# Thread deltas

## 2026/08/15

- [2026/08/15/13-11-19 by Yoichi NAKAYAMA via GitGitGadget <gitgitgadget@gmail.com>] Yoichi NAKAYAMA submitted a patch fixing worktree repair to correctly handle relative paths in .git files by adding a `bool *absolute` output parameter to `read_gitfile_gently()` and removing dead relative-to-absolute conversion code in `repair_gitfile()` and `repair_worktree_at_path()`, since `read_gitfile_gently()` always returns an absolute path.

## 2026/08/17

- [2026/08/17/17-21-21 by Junio C Hamano <gitster@pobox.com>] Junio C Hamano criticized the patch's commit message as hiding the details needed to evaluate the change, asking what problem is actually being fixed, what "dead code" exists and in which file/function, and why "repair" cares whether the path is absolute or relative; he proposed two alternative approaches: adding a new READ_GITFILE_ERR_RELATIVE_PATH constant treated as a non-fatal error by read_gitfile_error_die(), or introducing a separate read_raw_gitfile() that returns the path without conversion (with read_gitfile_gently() becoming a thin wrapper around it).
- [2026/08/17/21-27-01 by Yoichi Nakayama <yoichi.nakayama@gmail.com>] Yoichi Nakayama explained the concrete problem: when cross references are recorded as relative paths, setting worktree.useRelativePaths=false and running `git worktree repair` detects no "absolute/relative path mismatch" and leaves the references relative, because read_gitfile_gently() always returns an absolute path while repair_gitfile() and repair_worktree_at_path() treat the result as the raw .git file contents; he noted the issue dates to 717af916cd and is reproducible in v2.48.0, and agreed with Junio C Hamano's suggestion, saying he will revise the approach to introduce a read_raw_gitfile()-like function rather than changing read_gitfile_gently()'s signature.

## 2026/08/20

- [2026/08/20/15-46-00 by Yoichi NAKAYAMA via GitGitGadget <gitgitgadget@gmail.com>] Yoichi NAKAYAMA posted v2 of "worktree repair: detect relative path in .git file correctly", replacing the v1 approach of adding an `absolute` output parameter to read_gitfile_gently() with a new read_gitfile_raw() function that returns the unmodified path read from the .git file, and using it in repair_gitfile() so that 'git worktree repair' can correctly convert relative cross-references to absolute paths when worktree.useRelativePaths is false.
