This thread is about a 13-patch series from Johannes Schindelin (Dscho) that upstreamed Git for Windows-specific build and runtime adjustments into the main Git codebase. The series has already been merged to Junio’s `next` branch in its third iteration, and this fourth version is a polish release with minor mechanical improvements.

The latest email covers the fourth patch, which restricts the `-Wl,--large-address-aware` linker flag to 32-bit MinGW builds only, removing it from 64-bit and ARM64 configurations where it is either ignored or unsupported. This is a one-line build-system hygiene fix in `config.mak.uname` that aligns the build with modern toolchains like UCRT64, part of Git for Windows’ migration away from MINGW64. The change has no runtime impact on any platform and is uncontroversial.

The series as a whole addresses hard-coded assumptions, MSYS2 integration, linking behavior, deprecated build artifacts, a locale-handling regression, direct `git.exe` invocation, and build-system hygiene. Key participants include Dscho (author), Junio C Hamano (maintainer, who merged v3 to `next`), and Johannes Sixt (who provided substantive review and validation). One minor open question remains about a build-system guard for an edge case, but it is not blocking integration. If you’re not working on Windows compatibility, this series can safely be skimmed; if you are, the adjustments are now in `next` and will graduate to `master` in due course.
