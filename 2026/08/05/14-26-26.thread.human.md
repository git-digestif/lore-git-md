This thread is about a 12-patch series from Johannes Schindelin (Dscho) that upstream Git for Windows-specific build and runtime adjustments into the main Git codebase. The series aims to improve Windows compatibility—enabling Python support, allowing alternative compilers like Clang, removing deprecated build artifacts, fixing a locale-handling regression in MSYS2, and supporting direct `git.exe` invocation—without affecting non-Windows platforms.

The series is now at v3 and under active review. Patches 1 (removing `NO_PYTHON` for MINGW), 2 (removing hard-coded `CC = gcc`), 10 (simplifying `ETC_GITCONFIG`/`ETC_GITATTRIBUTES` path logic), and 11 (fixing the locale-handling regression) are uncontroversial and ready for integration, with no outstanding feedback. Johannes Sixt has been running a subset of these patches in his personal Windows builds since November 2025 without issues, and the full series passes GitHub CI on Windows, providing real-world validation. The main open discussion centers on Patch 12, where Junio C Hamano has suggested adding build-system guards to handle an edge case (empty `MSYSTEM` export), a point Dscho has not yet addressed in this iteration.

The series touches build configuration files (`config.mak.uname`, CMake/Meson files), `compat/mingw.c`, and one test (`t0060-path-utils.sh`), but introduces no new symbols or on-disk format changes. While the changes are Windows-specific, they are minimal and routine, positioning the series as a straightforward maintenance update rather than a major feature. The only forward-looking note is Junio’s suggestion that dashed-form executables (e.g., `git-commit`) could be removed entirely in Git 3.0, though this isn’t a request for changes to the current series.
