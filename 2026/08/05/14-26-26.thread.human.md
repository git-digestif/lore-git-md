This thread is about a 12-patch series from Johannes Schindelin (Dscho) that upstream Git for Windows-specific build and runtime adjustments into the main Git codebase. The series addresses hard-coded assumptions, MSYS2 integration, linking behavior, deprecated build artifacts, a locale-handling regression in the MSYS2 runtime, and direct `git.exe` invocation. All patches are uncontroversial and ready for integration, with no outstanding review feedback or open questions beyond minor nits.

The final patch (12/12) enables direct invocation of `git.exe` without the legacy Git wrapper, eliminating an extra process hop. This change is well-motivated, narrowly scoped, and thoroughly tested, addressing a long-standing Git for Windows quirk (GitHub issue #2283) without affecting non-Windows platforms. The implementation is defensive, with fallbacks for edge cases, and the test coverage is robust. The only unresolved discussion is a minor build-system nit about guarding against an empty `MSYSTEM` export, but this does not block integration.

Johannes Sixt has run a subset of these patches in personal Windows builds since November 2025 without issues, and the full series passes GitHub CI on Windows, providing real-world validation. Junio C Hamano has raised no objections to the current series, though he previously suggested the possibility of removing dashed-form executables entirely in Git 3.0—a forward-looking proposal unrelated to this series. The series is now in its third iteration, with mechanical adjustments made to address feedback about logical ordering and maintainability. If you care about Windows compatibility or build-system hygiene, this is a routine but important maintenance update.
