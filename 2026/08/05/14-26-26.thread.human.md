This patch series from Johannes Schindelin, now at its fourth iteration, continues to upstream Git for Windows-specific build and runtime adjustments into the main Git codebase. The latest update adds a small but meaningful step toward modernizing the Windows build process: patch 9/13 begins the phased deprecation of Git’s "dashed form" executables (like `git-commit`) by skipping their creation during Windows builds. This change, which adds a single line to `config.mak.uname`, eliminates unnecessary build overhead (~30 seconds per build), reduces confusion in Windows Explorer, and aligns with the long-term goal of removing these historical artifacts entirely—something Junio C Hamano has suggested for Git 3.0.

The series as a whole remains focused on improving Windows compatibility without affecting other platforms. Earlier patches in v4 addressed hard-coded assumptions, MSYS2 integration, linker behavior, and locale-handling regressions, with key changes like restricting the `-Wl,--large-address-aware` flag to 32-bit builds, removing redundant linker flags, and dynamically setting `prefix` and `HOST_CPU` based on MSYS2 environment variables. Junio has already merged v3 to `next` with minor editorial cleanup, and v4 is a polish iteration that splits a fly-by style fix into its own commit and adds `Helped-by` trailers. Johannes Sixt’s validation—personal builds since November 2025 and passing GitHub CI—continues to apply.

The only unresolved discussion is Junio’s suggestion to add a build-system guard for an edge case in patch 12, which Dscho declined to address, arguing the scenario is too unlikely. Otherwise, the series is uncontroversial and ready for integration, with no open technical objections. The broader deprecation of dashed-form executables will likely resurface in future discussions, but this patch is a straightforward and well-motivated step forward.
