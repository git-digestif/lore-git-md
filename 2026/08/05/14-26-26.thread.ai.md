Thread identity: patch series (13 patches), "[PATCH v4 0/13] MinGW/Windows build and runtime adjustments", originating author Johannes Schindelin (Dscho).
Core problem or goal: upstream Git for Windows-specific build and runtime adjustments into the main Git codebase, addressing hard-coded assumptions, MSYS2 integration, linking behavior, deprecated build artifacts, a locale-handling regression in the MSYS2 runtime, direct `git.exe` invocation, and build-system hygiene. The series aims to improve Windows compatibility without affecting non-Windows platforms and is urgently needed for Git for Windows' migration from MINGW64 to UCRT64.
Current status: **merged to `next` (Junio C Hamano confirmed v3 integration with minor editorial cleanup; v4 replaces v3 in `next` as of 2026-06-05)**. The series is on track for graduation to `master`; no further technical discussion or review is expected unless new issues surface during integration testing. Changes from v3 are mechanical: a fly-by style fix split into its own commit (13/13), `Helped-by` trailers added, a paragraph moved from patch 8/12’s commit message to 12/12, and **Patch 4/13 restricts the `-Wl,--large-address-aware` linker flag to 32-bit MinGW builds only** (removing it from 64-bit and ARM64 configurations where it is ignored or unsupported). **Patch 5/13 removes the redundant `-Wl,--pic-executable,-e,...` linker flag** (introduced in 2016 as a MinGW workaround but now obsolete; the default entry-point symbols are already correct in current MinGW toolchains). **Patch 6/13 dynamically sets `prefix` and `HOST_CPU` based on MSYS2 environment variables (`MINGW_PREFIX` and `MINGW_CHOST`)**, eliminating hard-coded values for each MSYS2 variant (MINGW32, MINGW64, CLANGARM64) and aligning the build system with MSYS2’s conventions. **Patch 7/13 restricts the `-DDETECT_MSYS_TTY` flag to builds where `MSYSTEM` is set**, moving it inside the `ifneq (,$(MSYSTEM))` conditional block in `config.mak.uname` and removing it from the unconditional `COMPAT_CFLAGS` line. The series explicitly notes that CMake and Meson do not automatically inherit the `MSYSTEM` setting from the build environment. **Patch 8/13 replaces hard-coded MinGW/MSYS2 paths and CPU identifiers in `config.mak.uname` with dynamic values derived from `MINGW_PREFIX` and `MINGW_CHOST`**, reducing conditional nesting and extending support to additional MSYS2 variants (e.g., `clang64`, `ucrt64`) without explicit per-variant logic. **Patch 9/13 begins the phased deprecation of Git’s "dashed form" executables (e.g., `git-commit`) by skipping their creation during the Windows build process**, adding `SKIP_DASHED_BUILT_INS = YabbaDabbaDoo` to `config.mak.uname` under the `Windows` and `MINGW` conditionals. **Patch 10/13 simplifies the logic for defining `ETC_GITCONFIG` and `ETC_GITATTRIBUTES` in MSYS2 environments by removing redundant special-casing for specific variants (e.g., `mingw64`, `clangarm64`) and consolidating the definitions under a single `MINGW_PREFIX`-based conditional**, further reducing conditional nesting in `config.mak.uname`. This change aligns the build system with MSYS2 conventions and supports newer variants like `ucrt64`. **Patch 11/13 fixes a locale-handling regression in the MSYS2 runtime (versions 2.4.1 to 2.6.0) by setting `LC_CTYPE=C.UTF-8` in the environment when no locale-related variables (`LC_ALL`, `LC_CTYPE`, or `LANG`) are present**, preventing non-ASCII characters in command-line arguments from being munged during subprocess invocation (e.g., `git-upload-pack`). The fix is minimal (three lines added to `compat/mingw.c`), Windows-specific, and resolves GitHub issue [git-for-windows/git#1036](https://github.com/git-for-windows/git/issues/1036). **Patch 12/13 enables direct invocation of `git.exe` by initializing the `MSYSTEM` environment variable and adjusting `PATH` when `MSYSTEM` is unset**, addressing GitHub issue [git-for-windows/git#2283](https://github.com/git-for-windows/git/issues/2283). The patch adds a new block in `compat/mingw.c`’s `setup_windows_environment()` to set `MSYSTEM` to the value of the `ENSURE_MSYSTEM_IS_SET` macro (defined in `config.mak.uname`) and prepends `$HOME/bin`, `/mingw64/bin`, and `/usr/bin` to `PATH`. The logic is guarded by `#ifdef ENSURE_MSYSTEM_IS_SET` and further protected by `#if !defined(RUNTIME_PREFIX) || !defined(HAVE_WPGMPTR) || !defined(MINGW_PREFIX)` to avoid compilation errors on non-Windows or non-Runtime-Prefix builds. The build system is updated to pass `ENSURE_MSYSTEM_IS_SET` and `MINGW_PREFIX` to the compiler via `COMPAT_CFLAGS` in `config.mak.uname`, with CMake and Meson updated to hard-code or expose these values per platform. The test `t0060-path-utils.sh` is extended to verify `MSYSTEM` and `PATH` adjustment when `git.exe` is invoked directly. Johannes Sixt’s validation (personal builds since November 2025, GitHub CI passes) still applies. **Patch 13/13 is a pure style fix to `t/t0060-path-utils.sh`**, reinstating a closing single quote accidentally dropped in an earlier version of the series. The change moves the quote from the end of the `test_cmp` line to its own line, aligning with the project’s test-script style conventions. No behavior is altered.
