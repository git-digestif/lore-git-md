Thread identity: patch series (12 patches), "[PATCH v3 0/12] MinGW/Windows build and runtime adjustments", originating author Johannes Schindelin (Dscho).
Core problem or goal: upstream Git for Windows-specific build and runtime adjustments into the main Git codebase, addressing hard-coded assumptions, MSYS2 integration, linking behavior, deprecated build artifacts, a locale-handling regression in the MSYS2 runtime, and direct `git.exe` invocation. The series aims to improve Windows compatibility without affecting non-Windows platforms.
Current status: v3 posted; under review. Patches 1 (removing `NO_PYTHON` for MINGW in `config.mak.uname`), 2 (removing hard-coded `CC = gcc` assignment in `config.mak.uname`’s MINGW section), 3 (removing `-D_USE_32BIT_TIME_T` compiler flag from the MinGW section of `config.mak.uname`), 4 (refining the `-Wl,--large-address-aware` linker flag to apply only to 32-bit builds (`MINGW32`)), 5 (removing redundant `-e` entry-point specifications from the `-Wl,--pic-executable` linker flag in `config.mak.uname`), 6 (replacing hard-coded `prefix` and `HOST_CPU` values in `config.mak.uname` with dynamic settings derived from MSYS2’s environment variables (`MINGW_PREFIX` and `MINGW_CHOST`), guarded by `ifneq (,$(MSYSTEM))`), and 7 (making the `-DDETECT_MSYS_TTY` compiler flag conditional on the presence of the `MSYSTEM` environment variable in `config.mak.uname`) are uncontroversial and ready for integration, with no review feedback or open questions. The unresolved discussion about guarding against an empty `MSYSTEM` export in Patch 12 continues, with Junio C Hamano reinforcing the precedent for defensive programming in the build system by pointing to existing `ifneq (,$(MSYSTEM))` guards in `config.mak.uname`.
Key technical details:
- Files touched: `compat/mingw.c`, `config.mak.uname`, CMake/Meson build files (`contrib/buildsystems/CMakeLists.txt`, `meson.build`, `meson_options.txt`), test `t0060-path-utils.sh`.
- New/renamed symbols: none.
- Behavior changes: none for non-Windows platforms. Windows-specific adjustments include:
  - Enabling Python buildability by removing `NO_PYTHON` for MINGW in `config.mak.uname` (Patch 1), allowing users to leverage MSYS2-provided Python interpreters in Git for Windows’ SDK environment.
  - Removing the hard-coded `CC = gcc` assignment in the MINGW section of `config.mak.uname` to allow alternative compilers (e.g., Clang) (Patch 2).
  - Removing the `-D_USE_32BIT_TIME_T` compiler flag from the MinGW section of `config.mak.uname` (Patch 3), as it is incompatible with the UCRT64 runtime and was only needed for the original MinGW runtime (deprecated since 2015).
  - Refining the linker flag `-Wl,--large-address-aware` to apply only to 32-bit builds (`MINGW32`), omitting it for 64-bit builds (`MINGW64` and `CLANGARM64`) where it is irrelevant or unsupported (Patch 4).
  - Removing redundant `-e` entry-point specifications from the `-Wl,--pic-executable` linker flag in `config.mak.uname` (Patch 5), as the specified entry points (`_mainCRTStartup` for 32-bit, `mainCRTStartup` for 64-bit) are already the default according to upstream binutils documentation.
  - Replacing hard-coded `prefix` and `HOST_CPU` values in `config.mak.uname` with dynamic settings derived from MSYS2’s environment variables (`MINGW_PREFIX` and `MINGW_CHOST`), guarded by `ifneq (,$(MSYSTEM))` (Patch 6).
  - Making the `-DDETECT_MSYS_TTY` compiler flag conditional on the presence of the `MSYSTEM` environment variable in `config.mak.uname` (Patch 7), ensuring it is only enabled when compiling in an MSYS2 environment.
  - Replacing hard-coded defaults for `MSYSTEM` and installation prefix in `config.mak.uname`, CMake, and Meson with values derived from MSYS2’s environment variables (`MINGW_PREFIX` and `MSYSTEM`), guarded by `ifneq (,$(MSYSTEM))` (Patch 8). The v2 iteration aligned Meson’s behavior with the Makefile’s by removing the leading slash from `MINGW_PREFIX`. The compiler-definition hunks (`ENSURE_MSYSTEM_IS_SET` and `MINGW_PREFIX`) are now in Patch 12, where they are consumed by the C code.
  - Disabling generation of hard-linked `git-<command>` executables (e.g., `git-commit`) in `libexec/git-core/` for Windows builds by setting `SKIP_DASHED_BUILT_INS = YabbaDabbaDoo` in `config.mak.uname` (Patch 9).
  - Simplifying the logic for setting `ETC_GITCONFIG` and `ETC_GITATTRIBUTES` paths by unconditionally defining them for all MSYS2 environments (Patch 10).
  - Fixing a locale-handling regression in the MSYS2 runtime (introduced between versions 2.4.1 and 2.6.0) that caused Git to mishandle command-line arguments containing non-ASCII characters when shelling out to subprocesses (Patch 11).
  - Allows `git.exe` to be called directly instead of through the "Git wrapper" (`C:\Program Files\Git\cmd\git.exe`), eliminating an extra process hop. The patch adds logic in `compat/mingw.c` to detect when `MSYSTEM` is unset (indicating the wrapper hasn’t run) and initializes it, along with `PLINK_PROTOCOL` and a carefully constructed `PATH` that prepends `$HOME/bin`, the MSYS2 system directories (`/mingw64/bin` and `/usr/bin`), and the original `PATH`. The build system (`config.mak.uname`) is updated to pass `MSYSTEM` and `MINGW_PREFIX` as compiler definitions. A new test in `t0060-path-utils.sh` verifies the environment setup (Patch 12).
