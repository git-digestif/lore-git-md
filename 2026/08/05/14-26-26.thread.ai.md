Thread identity: patch series (13 patches), "[PATCH v4 0/13] MinGW/Windows build and runtime adjustments", originating author Johannes Schindelin (Dscho).
Core problem or goal: upstream Git for Windows-specific build and runtime adjustments into the main Git codebase, addressing hard-coded assumptions, MSYS2 integration, linking behavior, deprecated build artifacts, a locale-handling regression in the MSYS2 runtime, direct `git.exe` invocation, and build-system hygiene. The series aims to improve Windows compatibility without affecting non-Windows platforms and is urgently needed for Git for Windows' migration from MINGW64 to UCRT64.
Current status: **merged to `next`** (Junio C Hamano confirmed integration of v3 with minor editorial cleanup; v4 is a polish iteration). Changes from v3 are mechanical: a fly-by style fix split into its own commit (13/13), `Helped-by` trailers added, a paragraph moved from patch 8/12’s commit message to 12/12, and **Patch 4/13 restricts the `-Wl,--large-address-aware` linker flag to 32-bit MinGW builds only** (removing it from 64-bit and ARM64 configurations where it is ignored or unsupported). **Patch 5/13 removes the redundant `-Wl,--pic-executable,-e,...` linker flag** (introduced in 2016 as a MinGW workaround but now obsolete; the default entry-point symbols are already correct in current MinGW toolchains). **Patch 6/13 dynamically sets `prefix` and `HOST_CPU` based on MSYS2 environment variables (`MINGW_PREFIX` and `MINGW_CHOST`)**, eliminating hard-coded values for each MSYS2 variant (MINGW32, MINGW64, CLANGARM64) and aligning the build system with MSYS2’s conventions. **Patch 7/13 restricts the `-DDETECT_MSYS_TTY` flag to builds where `MSYSTEM` is set**, moving it inside the `ifneq (,$(MSYSTEM))` conditional block in `config.mak.uname` and removing it from the unconditional `COMPAT_CFLAGS` line. The series explicitly notes that CMake and Meson do not automatically inherit the `MSYSTEM` setting from the build environment. **Patch 8/13 replaces hard-coded MinGW/MSYS2 paths and CPU identifiers in `config.mak.uname` with dynamic values derived from `MINGW_PREFIX` and `MINGW_CHOST`**, reducing conditional nesting and extending support to additional MSYS2 variants (e.g., `clang64`, `ucrt64`) without explicit per-variant logic. **Patch 9/13 begins the phased deprecation of Git’s "dashed form" executables (e.g., `git-commit`) by skipping their creation during the Windows build process**, adding `SKIP_DASHED_BUILT_INS = YabbaDabbaDoo` to `config.mak.uname` under the `Windows` and `MINGW` conditionals. This change is Windows-specific, reduces build time (~30 seconds per build), eliminates Explorer confusion, and aligns with the long-term goal of removing dashed-form executables entirely (a goal Junio has suggested for Git 3.0). Johannes Sixt’s validation (personal builds since November 2025, GitHub CI passes) still applies.
