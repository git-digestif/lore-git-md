This thread introduces a new `receive-report` hook for `git-receive-pack`, allowing server administrators to intercept and modify the status report sent to clients after ref updates are committed. The hook is motivated by GitLab’s need to implement multi-version concurrency control (MVCC), where the reported status must reflect the repository state *after* all server-side operations—even those beyond `ref_transaction_commit()`—are complete. Karthik Nayak is the author, and the series has evolved through nine iterations to address feedback from Junio C Hamano, Patrick Steinhardt, and others.

The hook acts as a bidirectional filter: it receives the pkt-line encoded status report on stdin, replaces it with its stdout, and forwards stderr to the client via sideband. A non-zero exit code rewrites all ref status lines to `"receive-report hook failed"`, while a zero exit uses the hook’s stdout as the report. This design intentionally decouples the reported status from the actual repository state—a departure from Git’s traditional consistency model, where remote-tracking branches reflect the server’s state. The commit message justifies this trade-off with GitLab’s use case, where conservative client-side behavior (not updating remote-tracking branches when the hook reports `ng`) is the desired outcome.
