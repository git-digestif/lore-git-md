This thread introduces a new `receive-report` hook for Git’s `receive-pack`, letting server administrators intercept and modify the status report sent to clients after ref updates. The hook is motivated by GitLab’s need for MVCC (multi-version concurrency control), where the server must report a state that may diverge from the actual repository—e.g., marking a push as failed (`ng`) while still committing the update. This breaks Git’s traditional consistency model, where remote-tracking branches always reflect the server’s state, but the trade-off is justified by GitLab’s use case.
