# Thread deltas

## 2026/08/18

- [2026/08/18/12-31-09 by Kristofer Karlsson <krka@spotify.com>] Kristofer Karlsson proposes an RFC to make `check_connected()` cost proportional to the incoming set rather than repository size, defining "trusted object" and "boundary commit" to frame the problem.
- [2026/08/18/12-31-09 by Kristofer Karlsson <krka@spotify.com>] He proposes two optimizations: (1) opportunistic trusted-tree discovery that caches verified objects and uses a parallel tree walk against trusted parent commits to prune verification to roughly changed entries, and (2) bounded boundary traversal seeded with old ref values and a walk budget, falling back to `--not --all` if the boundary is not closed.
- [2026/08/18/12-31-09 by Kristofer Karlsson <krka@spotify.com>] He reports preliminary prototype results on a large repository (3M commits, 200K refs) showing the connectivity check dropping from ~1s to ~0.03s for a 5-commit push and ~0.007s for a 1-commit push.
- [2026/08/18/12-31-09 by Kristofer Karlsson <krka@spotify.com>] He notes he explored using commit-graph membership as evidence of trust but abandoned the approach as hard to reason about, and describes appendix handling for non-commit tips, shallow clones, deepening fetches, promisor remotes, and replace objects (with fallbacks to the current rev-list path where needed).
