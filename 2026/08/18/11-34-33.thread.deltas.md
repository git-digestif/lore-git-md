## 2026/08/18

- [2026/08/18/11-34-33 by Artur Bieniek via GitGitGadget <gitgitgadget@gmail.com>] Artur Bieniek submitted a patch adding a `--hard` mode to `git pull` that, after fetching, requires a single integration candidate and resets the current branch, index, and working tree to it, while preserving quiet and submodule recursion behavior and rejecting options that cannot be honored by a hard reset.
- [2026/08/18/14-48-01 by Junio C Hamano <gitster@pobox.com>] Junio C Hamano expressed mild opposition to adding `--hard` to `git pull`, arguing that the behavior is already safely and explicitly achieved by `git fetch` followed by `git reset --hard @{u}`, that the core purpose of `git pull` is history integration, and that adding a destructive option makes it easier for users with uncommitted work to trigger data loss by accident.
