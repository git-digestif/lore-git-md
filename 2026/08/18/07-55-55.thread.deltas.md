# Thread deltas

## 2026/08/18

- [2026/08/18/07-55-55 by Karthik Nayak <karthik.188@gmail.com>] Karthik Nayak submitted a patch introducing a new 'report' hook for git-receive-pack(1) that receives the pkt-line encoded status report on stdin and whose stdout replaces the report sent to the client; a non-zero exit status causes receive-pack to die and the client to treat the push as failed. He explained the GitLab use case of a custom MVCC where the report needs to be modified based on the status of the MVCC commit phase after the reference transaction.
- [2026/08/18/20-54-02 by Junio C Hamano <gitster@pobox.com>] Junio C Hamano reviewed the patch, questioning how the client distinguishes between a hook that rewrites the report to indicate failures versus one that exits non-zero, and noting that when the hook aborts the client does not receive the report and interprets the lack of a success report as failure. He concluded the design is "ugly, but may work OK" but needs to be documented more clearly.
