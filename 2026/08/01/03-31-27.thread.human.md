This thread is about a bugfix for `git filter-branch` where the `--state-branch` option incorrectly inverts commit mappings, causing errors during incremental repository splitting. The issue was introduced in Git 2.50.0 during a Perl-removal refactor and affects users who rely on `--state-branch` with `--prune-empty`.

The patch, now in its second version (`v2`), has received strong support. Michele Locati and Patrick Steinhardt have both confirmed the bug and the fix, with Locati adding a critical test case that directly verifies the commit mapping inversion and `--prune-empty` behavior. The only remaining tasks are minor: Patrick Steinhardt requested a rewritten commit message (naming the regressing commit and using imperative mood) and a small test cleanup, while the typo in the patch subject ("fiter-branch") awaits a decision on whether to fix it via a new version or a maintainer edit.

The fix itself is minimal—just two lines in `git-filter-branch.sh`—and the test coverage is now comprehensive. The patch is ready to proceed once the commit message and test adjustments are addressed, with no open technical objections.
