This thread is about a bugfix for `git filter-branch` that corrects a commit mapping inversion regression introduced in Git 2.50.0. The issue occurs when using `--state-branch` with `--prune-empty`, causing the state branch file to be read backwards and leading to errors like "Is a directory" on subsequent runs. Grant Moyer posted the third version (`v3`) of the patch, which addresses all remaining review feedback from Junio C Hamano, Michele Locati, and Patrick Steinhardt.

The fix itself is a minimal two-line change in `git-filter-branch.sh` that ensures the state branch file is read in the correct "original:rewritten" format. The commit message now explicitly names the regressing commit (f6d855091e) and explains the test changes, while the test suite has been updated to include a new case that directly verifies the mapping correctness in incremental runs. The patch is self-contained, includes thorough test coverage, and has received substantive reviews confirming both the bug and the fix. All open questions from the previous version have been resolved, and the patch is now ready for merging.
