This thread is about a bugfix for `git filter-branch` where the `--state-branch` option incorrectly inverts commit mappings, causing issues with `--prune-empty` and leading to "Is a directory" errors. The bug was introduced in Git 2.50.0 during a Perl-removal refactor.

Grant Moyer posted a standalone patch that fixes the two-line mapping inversion in `git-filter-branch.sh` and updates the test to ensure the state branch is actually used. The patch has received substantive review from Michele Locati, who confirmed the bug and fix through testing with incremental runs using `--prune-empty` and `--subdirectory-filter`. Patrick Steinhardt reviewed the patch and raised two process concerns: the test doesn’t directly verify the mapping inversion, and the commit message should reference the regression-introducing commit (f6d855091e). While Patrick prefers a one-line fix for conciseness, he doesn’t object to Grant’s two-line version, which Grant argues is clearer and more consistent with the script’s style.

The thread is now waiting on Michele Locati to propose a more direct test case that exercises the broken scenarios. The subject-line typo ("fiter-branch") was noted, and Patrick advised Grant that it can be fixed either by the maintainer during merge or via a new patch version, depending on Junio’s preference. The patch is technically sound but needs the test improvement before it’s fully ready for merging.
