This thread is about a bugfix for `git filter-branch` where the `--state-branch` option incorrectly inverts commit mappings, causing errors during incremental runs with `--prune-empty`. The issue was introduced in Git 2.50.0 during a Perl-removal refactor and affects users splitting repositories incrementally.

Grant Moyer posted a v2 patch that fixes the two-line logic error and adds comprehensive test coverage, including a new test case from Michele Locati that directly verifies the mapping inversion and `--prune-empty` scenario. The patch has received substantive reviews from Michele Locati and Patrick Steinhardt, both confirming the bug and the fix. The only remaining loose end is a minor typo in the patch subject ("fiter-branch"), which Patrick suggests could be handled either by the maintainer during merge or via a new patch version.

The latest feedback from Patrick Steinhardt focuses on polishing the commit message and test scaffolding. He proposes a clearer, more conventional commit message that names the regressing commit and uses imperative mood, and suggests a small test cleanup. No technical concerns remain, and the patch is ready for merging once the commit message is adjusted. The fix is self-contained, touches only `git-filter-branch.sh` and its test file, and does not change the on-disk format.
