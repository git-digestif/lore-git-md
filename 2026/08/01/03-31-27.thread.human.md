This thread is about a bugfix for `git filter-branch` that corrects a commit mapping inversion regression introduced in Git 2.50.0. The issue occurs when using `--state-branch` with `--prune-empty`, causing the script to read commit mappings backwards ("to_commit:from_commit" instead of "from_commit:to_commit"). This leads to errors like "Is a directory" on subsequent runs, as the script attempts to create files with empty names.

Grant Moyer posted a minimal two-line fix in `git-filter-branch.sh` that resolves the inversion by properly splitting and assigning the commit mappings. The patch is now in its second version (`v2`), which includes expanded test coverage—most notably a new test case from Michele Locati that directly verifies the fix in incremental runs with `--prune-empty` and `--subdirectory-filter`. This test fails on current `master` without the fix and passes with it, confirming both the bug and the solution. The fix has received substantive, tested reviews from Michele Locati and Patrick Steinhardt, who confirmed the bug’s existence and the fix’s correctness.

The only remaining loose end is a typo in the patch subject ("fiter-branch"), which Patrick Steinhardt suggested could be handled either by the maintainer during merge or via a new patch version. The patch is self-contained, well-motivated, and now has comprehensive test coverage, making it ready for merging. No on-disk format changes or new symbols are introduced.
