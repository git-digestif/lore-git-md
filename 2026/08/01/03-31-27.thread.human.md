This thread is about a bugfix for `git filter-branch` where the `--state-branch` option incorrectly inverts commit mappings, causing issues with `--prune-empty` and incremental runs. The bug, introduced in Git 2.50.0 during the Perl-removal refactor, was reported and fixed by Grant Moyer in a standalone patch that includes a minimal test update.

The patch has received a substantive review from Michele Locati, who confirmed both the bug and the fix by testing the exact scenario the patch targets (incremental runs with `--state-branch`, `--prune-empty`, and `--subdirectory-filter`). Patrick Steinhardt has since reviewed the patch and raised two process-oriented concerns: the test coverage is indirect (it verifies the state branch is consulted but not that the mapping is correct), and the commit message lacks a reference to the regression's introduction (commit `f6d855091e`). Patrick suggests a slightly simpler one-line fix but does not object to the current version. He has asked Michele Locati to contribute a more direct test case to better exercise the bug and its fix.

The patch itself is technically sound and ready for integration, with no remaining technical objections. The only open question is whether the test suite should be expanded to catch similar bugs in the future. The fix touches `git-filter-branch.sh` and updates a test in `t/t7003-filter-branch.sh`.
