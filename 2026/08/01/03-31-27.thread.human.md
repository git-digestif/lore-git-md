This thread is about a bugfix for `git filter-branch` where the `--state-branch` option incorrectly inverts commit mappings, causing issues like empty commit files and "Is a directory" errors during incremental repository splitting. The bug, introduced in Git 2.50.0 during a Perl-removal refactor, affects users relying on `--state-branch` for operations like `--prune-empty`.

The patch, authored by Grant Moyer, is a simple two-line fix in `git-filter-branch.sh` that corrects how commit mappings are read from the state branch file. It includes a test update to ensure the state branch is properly consulted, though the test does not yet directly verify the mapping inversion itself. Michele Locati has confirmed the bug and fix through testing, while Patrick Steinhardt reviewed the patch and suggested a simpler one-line alternative but did not object to the current version. Patrick also raised two process concerns: the test could be more thorough in verifying mapping correctness, and the commit message should reference the regression-introducing commit (f6d855091e).

In the latest email, Grant responds to Patrick’s feedback, defending the two-line fix for clarity and consistency with the rest of the script. He also clarifies the test’s purpose—it now reliably fails if the tree-filter is incorrectly re-run—but acknowledges it doesn’t directly test the mapping inversion. Grant asks whether the typo in the patch subject ("fiter-branch") should be fixed in a new version or left to the maintainer. The patch is technically ready for integration, but the discussion leaves open whether the test suite should be expanded to catch similar bugs in the future.
