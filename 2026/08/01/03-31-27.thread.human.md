This thread is about a bugfix for `git filter-branch` that corrects a commit mapping inversion regression in the `--state-branch` feature, introduced in Git 2.50.0. The issue causes the state branch file to be read backwards, leading to errors like "Is a directory" when `--prune-empty` is used in incremental runs. Grant Moyer posted a v2 patch that fixes the bug with a minimal two-line change in `git-filter-branch.sh` and includes expanded test coverage.

The patch has received substantive reviews from Michele Locati and Patrick Steinhardt, both of whom confirmed the bug and the fix. Michele Locati contributed a new test case that directly verifies the commit mapping correctness in incremental runs with `--prune-empty` and `--subdirectory-filter`, ensuring the state branch file contains correctly ordered entries. Patrick Steinhardt requested adjustments to the commit message (to name the regressing commit and use imperative mood) and a small test cleanup. Junio C Hamano is now reviewing the patch and has asked for clarification on the test changes in the commit message, as well as a minor test hygiene question.

The patch is technically complete, with comprehensive test coverage that fails on current `master` without the fix and passes with it. The remaining tasks are minor: clarifying the commit message and addressing the typo in the patch subject ("fiter-branch"). Given the thorough review and the patch's self-contained nature, it is likely to be merged soon, pending these small adjustments.
