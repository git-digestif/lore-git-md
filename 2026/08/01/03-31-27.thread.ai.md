Subject: [PATCH] filter-branch: fix commit mapping inversion with --state-branch
Series version: standalone patch (no series)
Originating author: Grant Moyer
Thread type: bugfix

Core problem or goal
`git filter-branch` with `--state-branch` has long stored commit mappings in "from_commit:to_commit" format but read them back as "to_commit:from_commit", causing the map directory to be populated backwards. When `--prune-empty` is used, this leads to commits that map to nothing; on subsequent runs the script attempts to create files with empty names and emits "Is a directory" errors. The bug was introduced in Git 2.50.0 (commit f6d855091e) during the Perl-removal refactor and affects users who rely on `--state-branch` for incremental repository splitting.
