Subject: [PATCH] filter-branch: fix commit mapping inversion with --state-branch
Series version: standalone patch (no series)
Originating author: Grant Moyer
Thread type: bugfix

Core problem or goal
`git filter-branch` with `--state-branch` has long stored commit mappings in "from_commit:to_commit" format but read them back as "to_commit:from_commit", causing the map directory to be populated backwards. When `--prune-empty` is used, this leads to commits that map to nothing; on subsequent runs the script attempts to create files with empty names and emits "Is a directory" errors. The bug was introduced in Git 2.50.0 (commit f6d855091e, "filter-branch: stop depending on Perl") during the Perl-removal refactor and affects users who rely on `--state-branch` for incremental repository splitting.

Current status
Under review; no prior versions posted. The patch is self-contained, includes a test, and has received a substantive, tested review from Michele Locati confirming both the bug and the fix. Patrick Steinhardt has reviewed the patch and raised two process-oriented concerns: (1) the existing test only verifies that the state branch is consulted, not that the mapping is correct, and (2) the commit message does not reference the regression-introducing commit (f6d855091e). Grant Moyer prefers the current two-line fix over Patrick’s suggested one-line alternative (`echo "${line#*:}" >../map/"${line%:*}"`), citing clarity and consistency with how the state branch is constructed elsewhere in the script. The test update now ensures the test fails immediately if the tree-filter is incorrectly re-run, but Patrick’s request for a more direct test case exercising the swapped mapping entries and `--prune-empty` scenario remains open. The typo in the patch subject ("fiter-branch") is noted; Grant asks whether it should be fixed via a new patch version or handled by the maintainer during merge.

Key technical details
- Files touched: `git-filter-branch.sh` (two-line fix: split line on colon, write to-commit into file named by from-commit), `t/t7003-filter-branch.sh` (test update to verify state branch is actually used by forcing a tree-filter failure and checking HEAD remains unchanged).
- New/renamed symbols: none.
- On-disk format change: none; the state branch file format is unchanged, only the read logic is corrected.
- Test coverage: minimal test change directly tied to the bug—replaces a no-op tree filter with one that fails, ensuring the state branch is the only reason HEAD remains unchanged. Patrick Steinhardt requests a more direct test case that exercises the swapped mapping entries and the `--prune-empty` scenario to catch this class of bug in the future.
