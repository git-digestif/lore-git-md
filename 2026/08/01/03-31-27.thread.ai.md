Subject: [PATCH v2] filter-branch: fix commit mapping inversion with --state-branch
Series version: standalone patch, v2
Originating author: Grant Moyer
Thread type: bugfix

Core problem or goal
`git filter-branch` with `--state-branch` has long stored commit mappings in "from_commit:to_commit" format but read them back as "to_commit:from_commit", causing the map directory to be populated backwards. When `--prune-empty` is used, this leads to commits that map to nothing; on subsequent runs the script attempts to create files with empty names and emits "Is a directory" errors. The bug was introduced in Git 2.50.0 (commit f6d855091e, "filter-branch: stop depending on Perl") during the Perl-removal refactor and affects users who rely on `--state-branch` for incremental repository splitting.

Current status
Under review; second version (`v2`) posted. The patch is self-contained, includes expanded test coverage, and has received substantive, tested reviews from Michele Locati, Patrick Steinhardt, and Junio C Hamano confirming both the bug and the fix. The key blocker—test coverage for the commit mapping inversion—has been fully addressed by Michele Locati’s new test case, which directly exercises incremental runs with `--prune-empty` and `--subdirectory-filter`, ensuring the state branch file contains correctly ordered "original:rewritten" entries. The test fails on current `master` (a018953) without the fix, passes with the fix, and also passes on Git v2.49.1 (the last version before the regression). Junio’s latest review requests two clarifications: (1) an explanation in the commit message for the test change (replacing `touch file || :` with `exit 1` to force reliance on the state branch), and (2) a decision on test hygiene (`test_when_finished rm -rf incremental` or reuse the repository). The typo in the patch subject ("fiter-branch") remains; Junio has not yet indicated whether he will edit it during merge or request a v3.
