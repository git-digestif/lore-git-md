This thread is about Kristoffer Haugsbakk’s five-patch series adding `--abbrev`, `--color`, and `--date` formatting options to the experimental `git format-rev` command, bringing it closer to `git log`’s flexibility. The series is now at v2, posted on August 26, 2026, and incorporates all feedback from the first round—defensive code improvements, designated initializers, a memory leak fix, and two new refactoring patches for assertion placement and documentation reuse.

The patches refactor option handling and documentation (patches 1–4) and implement the new options (patch 5/5) by reusing existing `git log` logic. The series remains uncontroversial but has stalled due to lack of review. Junio C Hamano, the maintainer, has explicitly stated he’s not the best reviewer for this experimental command and has called for input from contributors more familiar with `git format-rev`. Ben Knoble acknowledged the series is on his review list but hasn’t provided substantive feedback yet. Without reviews in the next few weeks, Junio plans to drop the topic from his `seen` branch.

The changes touch `builtin/name-rev.c`, documentation, and tests, with no on-disk format changes. The new options behave identically to their `git log` counterparts, and test coverage has been expanded to verify this. The series is queued under the name `kh/format-rev-more-options` but isn’t in any integration branch yet. The main open question is whether the UI design for `--date` will attract further discussion, though no objections have been raised so far.
