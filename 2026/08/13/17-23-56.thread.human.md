This thread is about Kristoffer Haugsbakk’s five-patch series adding `--abbrev`, `--color`, and `--date` formatting options to `git format-rev`, a command introduced in Git 2.45. The series is now at v2, addressing all review feedback from v1, including a memory leak fix, defensive code improvements, and two new refactoring patches. The goal is to bring `git format-rev` closer to parity with `git log`’s formatting flexibility by reusing existing logic from `rev_info` and `pretty.c`.

The series remains under review, but its future is uncertain. Haugsbakk has raised doubts about whether `git format-rev` is needed at all, suggesting `git diff-tree` could be modified to replace it. However, this follow-up clarifies that `git diff-tree` cannot replicate `git format-rev --stdin-mode=text`’s core functionality—turning hashes into references—which remains a unique capability of the command. While the `--stdin-mode=revs` mode (formatting revision ranges) might be replaceable, the text-filtering mode still justifies `git format-rev`’s existence. Haugsbakk’s admission that modifying `git diff-tree` is "too difficult" for him suggests the alternative may not materialize soon, leaving the series’ fate dependent on whether reviewers see enough value in the text-mode functionality to justify the new options.

Junio C Hamano has reiterated that he is not the best reviewer for this experimental command and has invited input from others more familiar with `git format-rev`. Ben Knoble has engaged with the broader design question but has not yet provided technical feedback on the patches themselves. The series is currently queued in `seen` but risks being dropped if no substantive reviews are posted soon. All v1 feedback has been addressed, and the patches are uncontroversial, but the unresolved design question about the command’s necessity remains a hurdle.
