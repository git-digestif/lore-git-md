Thread identity: A five-patch series from Kristoffer Haugsbakk adding `--abbrev`, `--color`, and `--date` formatting options to the `git format-rev` command (introduced in Git 2.45). The series is now at v2, incorporating v1 review feedback, a memory leak fix, defensive code improvements, and two new refactoring patches (2/5 and 4/5) addressing assertion placement and documentation reuse.

Core problem or goal: Extend `git format-rev` with three new formatting options (`--abbrev`, `--color`, `--date`) to bring it closer to parity with `git log`'s formatting flexibility. The series refactors option handling and documentation (patches 1–4) and implements the new options (patch 5/5) by reusing existing `git log` logic (`rev_info` struct and `pretty.c` date formatting). The command's necessity has been debated, with the latest exchange clarifying that the `--stdin-mode=text` mode (turning hashes into references in arbitrary input text) remains a unique capability not replicated by `git diff-tree` or other commands. The `--stdin-mode=revs` mode (formatting revision ranges) could potentially be replaced by `git diff-tree`, but no concrete proposal or patch has been posted, and the author has admitted modifying `git diff-tree` is "too difficult." D. Ben Knoble has now proposed a UI/UX refinement: split `git format-rev` into two distinct commands or modes, moving the revs mode functionality into `git diff-tree` (which would need to learn NUL-terminated output) while retaining `git format-rev` exclusively for the text mode. This would simplify invocation (e.g., for editor integration) and reduce the command's scope, potentially addressing the author's earlier doubts about its necessity.
