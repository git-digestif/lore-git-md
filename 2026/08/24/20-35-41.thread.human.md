This thread is about a small but useful feature addition to `git format-patch`: the ability to control Git notes inclusion separately for the range-diff section and the patch output itself. Kristoffer Haugsbakk originally proposed the feature in v1, but Junio C Hamano raised usability concerns about the option semantics and toggle behavior. After redesigning the feature in v2, Kristoffer eliminated the problematic toggle mechanism and adopted Junio’s suggested rule, making the CLI behavior explicit and predictable.

The v2 series is now technically complete, with two patches: a preparatory refactoring and the new implementation. Junio reviewed the second patch and found it sound, noting only a minor redundancy in the test script (an extra `test_when_finished` call), which Kristoffer has acknowledged and will fix in the next version. The feature itself is uncontroversial and well-motivated, but the thread remains closed—no maintainer decision has been made on whether to revive and integrate the feature. If approved, the v2 redesign is ready for further review and integration.

The only remaining loose end is the minor test cleanup, which is purely mechanical and doesn’t affect functionality. The broader question of whether to accept the feature at all is still open, but the v2 proposal provides a viable path forward if the maintainer chooses to proceed.
