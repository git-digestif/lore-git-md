This thread is about a small but useful feature addition to `git format-patch`: the ability to control whether Git notes appear in the range-diff section independently of the patch output. Kristoffer Haugsbakk proposed the feature in a two-patch series, now at version 4, which adds `--range-diff-notes=<ref>` and `--no-range-diff-notes` options. The design has evolved significantly since the first version, adopting a simpler, more explicit approach suggested by Junio C Hamano that avoids confusing fallback behavior and toggle mechanisms.

The series is technically complete and ready for Junio’s final approval. All substantive feedback from earlier rounds has been addressed: the commit messages are now more concise, the documentation is clearer, and the option callback has been refactored for better maintainability. Junio’s latest review raises no technical concerns, only a minor editorial suggestion to further tighten the commit message’s explanation of why the new options don’t error out when used without `--range-diff`. The feature itself—allowing users to suppress notes in the range-diff while keeping them in the patch output—has no remaining open questions or objections.

The implementation touches `builtin/log.c`, updates the documentation, and includes thorough test coverage. The interaction between patch notes and range-diff notes is now explicit: if no range-diff notes options are given, the range-diff uses the same notes as the patches; otherwise, it uses only the explicitly specified notes (including none). The series builds on two recent commits (from September 2025) that introduced necessary infrastructure and fixed a related bug. No further changes are expected unless Junio requests additional editorial tweaks.
