This thread is about a two-patch series, now at version 4, that adds `--[no-]range-diff-notes` options to `git format-patch`. The goal is to let users control which Git notes (if any) appear in the range-diff section of the output, independently of the notes shown on the patches themselves. Kristoffer Haugsbakk is the author.

The series is technically complete and ready for the maintainer’s decision. Junio C Hamano reviewed earlier versions and raised usability concerns about the option semantics and toggle mechanism; the v4 redesign directly addresses these by simplifying the CLI behavior—`--no-range-diff-notes` means “no notes for range-diff” without fallback, and `--range-diff-notes=<ref>` requires an explicit ref argument. The preparatory patch (1/2) refactors `get_notes_args` to remove a redundant parameter, while the second patch (2/2) implements the new options, updates the documentation, and adds comprehensive tests. All of Junio’s remaining editorial and implementation feedback from v3 has been addressed in v4: commit messages are trimmed, the documentation is rewritten in a more concise style, and the option callback now wraps `parse_opt_string_list` instead of duplicating its logic.

No substantive technical concerns remain. The series touches `builtin/log.c`, updates `Documentation/git-format-patch.adoc`, and extends `t/t3206-range-diff.sh` with tests that verify suppression of range-diff notes, use of different notes refs for patches and range-diffs, and proper handling of the single-patch case. The interaction rule is straightforward: if no range-diff notes options are given, the range-diff uses the same notes as the patches; otherwise, it uses only the explicitly specified notes (including none). The feature is now awaiting maintainer approval for integration.
