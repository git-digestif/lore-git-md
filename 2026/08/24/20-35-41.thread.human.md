This thread is about a proposed feature for `git format-patch` that would let users control Git notes separately in the range-diff section and the patch output itself. The author, Kristoffer Haugsbakk, sent a second version of the patch series after the first version drew usability concerns from Junio C Hamano, the maintainer. The new design simplifies the command-line options: `--no-range-diff-notes` now means "no notes for the range-diff" without any fallback, and `--range-diff-notes=<ref>` requires an explicit reference argument, making the behavior clearer and more predictable.

The series is technically ready—Junio reviewed the second patch and found nothing questionable except a minor redundancy in the test script, which Haugsbakk has agreed to fix. The implementation touches several files in the codebase, including `builtin/log.c` and `revision.c`, and introduces a new `struct rdiff_notes` to track whether the user wants to override the default notes behavior for range-diffs. Tests cover edge cases like single-patch scenarios and explicit notes suppression. Despite the technical soundness, the thread remains in limbo: no decision has been made on whether to revive the feature, and the discussion is effectively closed unless Junio or another maintainer chooses to reopen it. For now, the series is a well-designed but stalled proposal.
