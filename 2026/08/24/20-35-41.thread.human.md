This thread began as a proposal to add `--[no-]range-diff-notes` options to `git format-patch`, allowing users to control whether Git notes appear in the range-diff section separately from the patches themselves. The feature aimed to address workflows where iteration notes (like "v3: [description]") were useful in patches but cluttered range-diffs. Kristoffer Haugsbakk implemented the feature in a three-patch series, but Junio C Hamano quickly identified a critical usability flaw: the interaction between the new options and the existing `--notes` was ambiguous and unintuitive, particularly with the toggle mechanism (`--no-range-diff-notes --range-diff-notes`) and edge cases like `--no-notes --range-diff-notes` suppressing notes in both contexts. Kristoffer acknowledged the issues and chose to abandon the feature rather than pursue a redesign.

In the final exchange, Kristoffer proposed a simplified redesign that directly addresses Junio’s concerns. The redesign eliminates the toggle mechanism and the arg-less `--range-diff-notes` variant, adopting Junio’s rule that `--no-range-diff-notes` means "no notes for range-diff" without fallback, while `--range-diff-notes=<ref>` requires an explicit ref. This removes the conceptual overhead of the toggle sequence and makes the behavior more predictable, though it sacrifices the niche ability to revert to patch notes for range-diff output. The thread remains closed, and no further action is expected, but if the feature is revived, this redesign would likely serve as the starting point. The core technical details—files touched, struct members, and prior commit dependencies—remain unchanged, but the option parsing and behavior rules would be streamlined. D. Ben Knoble’s minor documentation feedback and the tangential issue of `format-patch`’s default notes handling (suggesting `format.notes` over `notes.displayRef`) were noted but not pursued.
