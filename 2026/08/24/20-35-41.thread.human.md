This thread is about Kristoffer Haugsbakk’s patch series adding `--[no-]range-diff-notes` to `git format-patch`, now at its fifth iteration. The feature lets users control Git notes inclusion in the range-diff section independently of the patch output, addressing a long-standing usability gap. After Junio C Hamano’s feedback on earlier versions, the v5 redesign simplifies the CLI semantics: `--range-diff-notes=<ref>` requires an explicit ref argument, and `--no-range-diff-notes` suppresses notes in the range-diff without fallback. The preparatory refactoring (1/2) was merged earlier, leaving only the feature implementation (2/2) in this version.

The implementation touches `builtin/log.c`, the documentation, and the test suite, introducing a new `struct rdiff_notes` to track override behavior. Tests cover suppression, ref overrides, and edge cases like single-patch scenarios. Junio reviewed v2 through v5, finding no substantive issues beyond minor editorial tweaks, which Kristoffer addressed in v5 by condensing the commit message. The series is now technically complete and ready for integration, with no further changes expected unless Junio spots additional editorial concerns during final queueing. The next step is Junio’s review and inclusion in his integration branches.
