This thread is about a small but useful feature addition to `git format-patch`: the ability to control Git notes inclusion separately for the range-diff section and the patch output itself. Kristoffer Haugsbakk’s `[PATCH v3 0/2]` series implements `--[no-]range-diff-notes`, allowing users to suppress notes in range-diffs (which often inherit irrelevant iteration changelogs from patch notes) while keeping them in the patch output.

The series is now technically complete and ready for maintainer approval. After two iterations and feedback from Junio C Hamano, the v3 redesign adopts a cleaner, more predictable design: `--no-range-diff-notes` suppresses notes in the range-diff without fallback, and `--range-diff-notes=<ref>` requires an explicit ref argument, enforcing a clear separation between patch notes and range-diff notes. The implementation touches `builtin/log.c`, updates documentation, and includes thorough test coverage for edge cases like single-patch scenarios. Junio’s feedback on v3 was limited to editorial improvements—commit message phrasing, documentation clarity, and a minor refactoring of the option callback to avoid code duplication—none of which raised substantive concerns about the patch’s design or behavior.

The only remaining step is Junio’s final approval. The feature’s revival now hinges on whether the maintainer decides to accept it, as the v3 proposal addresses all prior usability concerns and is technically sound. If merged, this would give users finer control over `format-patch` output, particularly in workflows where range-diffs and patches serve different purposes. No related work or dependencies are blocking this series.
