This thread began as a proposal by Kristoffer Haugsbakk to add `--[no-]range-diff-notes` options to `git format-patch`, allowing users to control whether Git notes appear in the range-diff section separately from the patches themselves. The idea was to suppress iteration notes (like "v3: [description]") in range-diffs while keeping them in the patch output, but the implementation ran into usability problems that proved insurmountable.

Junio C Hamano, the maintainer, quickly flagged the core issue: the interaction between the new options and the existing `--notes` was ambiguous and unintuitive. The toggle mechanism (`--no-range-diff-notes --range-diff-notes`) intended to revert to the default state—where both patches and range-diffs use the same notes—turned out to be confusing in practice. Junio’s latest email dissects why the toggle sequence fails under both possible interpretations of `--no-range-diff-notes`, confirming that it cannot achieve its intended purpose without creating edge cases that would trip up users. Kristoffer acknowledged the problems, clarified that the implementation already followed a cleaner design (separate control for patch notes and range-diff notes), but ultimately chose to abandon the feature rather than pursue a redesign.

The thread is now closed with no further action expected. If someone revives this work, they’ll need to address Junio’s concerns—likely by adopting Kristoffer’s later proposal to drop the toggle mechanism, require an explicit ref argument for `--range-diff-notes`, and make `--no-range-diff-notes` mean "no notes for range-diff" without fallback. A tangential issue about whether `format-patch` should respect `format.notes` instead of `notes.displayRef` also surfaced but remains unaddressed.
