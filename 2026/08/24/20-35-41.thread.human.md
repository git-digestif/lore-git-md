This thread is about a proposed feature for `git format-patch` that would let users control whether Git notes appear in the range-diff section separately from the patch output. The original version had usability issues, but the author, Kristoffer Haugsbakk, sent a redesigned v2 series that simplifies the command-line options and removes confusing behavior. Junio C Hamano, the maintainer, reviewed the v2 patches and found them technically sound, with only a minor redundancy in the test script (a duplicate `test_when_finished` call) that Haugsbakk plans to fix.

The series is now complete and ready for integration if Junio decides to revive the feature, but no decision has been made yet. The v2 design addresses all the maintainer’s earlier concerns, making the behavior explicit and predictable. The only remaining open question is whether the feature itself will be accepted—it’s not currently under active review, but the implementation is uncontroversial. If revived, the next step would be a final cleanup of the test script and integration into Junio’s queue.
