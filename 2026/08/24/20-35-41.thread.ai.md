Thread identity: `[PATCH v3 0/2] format-patch: add --[no-]range-diff-notes` series. Originating author: Kristoffer Haugsbakk. Thread type: patch series (feature addition).

Core problem or goal: Enable independent control over Git notes inclusion in `git format-patch` output, specifically allowing users to suppress notes in the range-diff section while retaining them in the patch output. The v3 redesign adopts Junio C Hamano’s suggested rule: `--no-range-diff-notes` means "no notes for range-diff" without fallback, and `--range-diff-notes=<ref>` requires an explicit ref argument, enforcing explicit separation between patch notes and range-diff notes.

Junio C Hamano reviewed v2 and found nothing questionable beyond a minor redundancy in the test script (an extra `test_when_finished` call), which Kristoffer Haugsbakk has addressed in v3. No maintainer decision has been made on whether to accept the feature, but the series is now technically ready for integration if approved.

Key technical details:
- Files touched: `builtin/log.c` (refactoring and implementation), `Documentation/git-format-patch.adoc`, and tests in `t/t3206-range-diff.sh`.
- CLI options (v3): `--range-diff-notes=<ref>` (requires an explicit ref argument) and `--no-range-diff-notes` (means "no notes for range-diff" without fallback). The arg-less `--range-diff-notes` variant and the toggle mechanism are removed.
- New struct: `struct rdiff_notes` introduced to track whether the user wants to override the default notes behavior for range-diffs. The `rev_info` struct is simplified by removing the `rdiff_override_notes` flag and renaming `rdiff_notes_arg` to `rdiff_log_arg` for clarity.
- Refactoring: `get_notes_args` updated to take only `struct rev_info *` as a parameter, removing the redundant `struct strvec *arg` parameter. The function now directly accesses `rev->rdiff_log_arg` (introduced in commit 85bd88a7, 2025-09-25) instead of receiving it as a separate argument. The custom `revision.c` option handler is replaced with a standard `parse-options` callback (`rdiff_notes_cb`).
- Behavior (v3): The interaction rule between patch notes and range-diff notes remains unchanged: if no range-diff notes options are given, the range-diff uses the same notes as the patches; otherwise, it uses only the explicitly specified notes (including none, via `--no-range-diff-notes`). `--no-notes` no longer suppresses range-diff notes unless explicitly requested via `--no-range-diff-notes`. `--range-diff-notes` without `--range-diff` has no effect but does not error, avoiding silent failures.
- Test coverage: Comprehensive tests verify scenarios such as suppressing all range-diff notes, using different notes refs for patches and range-diffs, and ensuring `--range-diff-notes` requires a value. Two additional tests specifically address the single-patch case, serving as regression tests for a bug fixed in a prior commit (155986b4, 2025-09-25). Tests also confirm that `--range-diff-notes` has no effect when `--range-diff` is not used. The redundant `test_when_finished` call noted by Junio and acknowledged by Kristoffer Haugsbakk has been removed in v3.
- Prior commit dependencies: 85bd88a7 (2025-09-25) introduced `rdiff_log_arg` to `struct rev_info`; 155986b4 (2025-09-25) fixed a bug in the single-patch case.
- Documentation: Updated to reflect the simplified behavior, removing references to the toggle mechanism and clarifying the explicit separation between patch notes and range-diff notes.
