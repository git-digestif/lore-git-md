Core problem or goal: Enable independent control over Git notes inclusion in `git format-patch` output, specifically allowing users to suppress notes in the range-diff section while retaining them in the patch output. Key technical details:
- Files touched: `builtin/log.c` (implementation), `Documentation/git-format-patch.adoc`, and tests in `t/t3206-range-diff.sh`. The preparatory refactoring patch (1/2) simplified `get_notes_args` in `builtin/log.c` by removing an unnecessary parameter and directly using `rev->rdiff_log_arg` instead of passing it as an argument, aligning with Git’s coding style.
- CLI options (v5): `--range-diff-notes=<ref>` (requires an explicit ref argument) and `--no-range-diff-notes` (means "no notes for range-diff" without fallback). The arg-less `--range-diff-notes` variant and the toggle mechanism are removed.
- New struct: `struct rdiff_notes` introduced to track whether the user wants to override the default notes behavior for range-diffs. The `rev_info` struct is simplified by removing the `rdiff_override_notes` flag and renaming `rdiff_notes_arg` to `rdiff_log_arg` for clarity.
- Behavior (v5): The interaction rule between patch notes and range-diff notes remains unchanged: if no range-diff notes options are given, the range-diff uses the same notes as the patches; otherwise, it uses only the explicitly specified notes (including none, via `--no-range-diff-notes`). `--no-notes` no longer suppresses range-diff notes unless explicitly requested via `--no-range-diff-notes`. `--range-diff-notes` without `--range-diff` has no effect but does not error, avoiding silent failures. The commit message for patch 2/2 now uses Junio’s concise phrasing, explicitly stating that `--[no-]range-diff-notes` does not error out when used without `--range-diff` to accommodate workflows where users configure default options in aliases.
- Test coverage: Comprehensive tests verify scenarios such as suppressing all range-diff notes, using different notes refs for patches and range-diffs, and ensuring `--range-diff-notes` requires a value. Two additional tests specifically address the single-patch case, serving as regression tests for a bug fixed in a prior commit (155986b4, 2025-09-25). Tests also confirm that `--range-diff-notes` has no effect when `--range-diff` is not used.
- Prior commit dependencies: 85bd88a7 (2025-09-25) introduced `rdiff_log_arg` to `struct rev_info`; 155986b4 (2025-09-25) fixed a bug in the single-patch case. The preparatory refactoring patch (1/2) was merged prior to v5.

The `--range-diff-notes` documentation has been rewritten in a concise, direct style as requested by Junio, explicitly stating that the option specifies a *different* notes ref for the range diff (not additive to `--notes`).
