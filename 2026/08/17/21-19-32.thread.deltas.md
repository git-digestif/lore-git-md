# Thread deltas

## 2026/08/17

- [2026/08/17/21-19-32 by Kenneth Lorber <keni@his.com>] Kenneth Lorber submitted an RFC proposing that `git config -e` exit with a non-zero status when the invoked editor fails, noting this could be a breaking change for anyone relying on the command always succeeding.
- [2026/08/17/21-19-33 by Kenneth Lorber <keni@his.com>] Kenneth Lorber posted the patch implementing the proposal by modifying `show_editor()` in builtin/config.c to return the result of `launch_editor()` instead of unconditionally returning 0, and adding two tests to t/t1300-config.sh that verify the exit code with `GIT_EDITOR` set to `true` and `false`.
- [2026/08/17/22-39-21 by Junio C Hamano <gitster@pobox.com>] Junio C Hamano questioned whether the change has much value, observing that while a non-zero editor exit can stop `git commit` from creating a commit, with `git config -e` the damage to the file is already done and cannot be undone, concluding "I dunno".

## 2026/08/18

- [2026/08/18/08-26-36 by Karthik Nayak <karthik.188@gmail.com>] Karthik Nayak argued that git should notify the user when the editor fails rather than brushing it off, expressed support for the patch, and noted that a user's expectation would be a non-zero exit status (demonstrating that `GIT_EDITOR=false git config --edit` currently exits 0).
- [2026/08/18/08-42-59 by Karthik Nayak <karthik.188@gmail.com>] Karthik Nayak suggested a test-code nit: use `test_env GIT_EDITOR=true git -C repo config -e` (and the `false` equivalent) instead of the set/export/unset sequence, and said the patch otherwise looks good to him.
- [2026/08/18/14-31-05 by Junio C Hamano <gitster@pobox.com>] Junio C Hamano said that if `git config -e` were being added today it should absolutely signal failure, but the open question is whether the benefit outweighs the downside of changing behavior existing users are accustomed to; he noted the subcommand is relatively new (introduced in commit 3cbace5ee0, 2024-05-06), so the fallout might not be great, ending with "So, I dunno."
- [2026/08/18/22-12-59 by brian m. carlson <sandals@crustytoothpaste.net>] brian m. carlson argued the error code should be propagated: apart from ed(1) and POSIX vi(1), editors exit nonzero only on error, and scripting languages exit nonzero only when something seriously went wrong or the user requested it; he added that people may be ignoring errors under `set -e` that they intended to catch precisely because no nonzero status is returned.
