# Thread deltas

## 2026/08/17

- [2026/08/17/23-39-15 by friel@openai.com] Friel submitted a patch adding a `write_pack_file/wrote_bytes` Trace2 datum to `builtin/pack-objects.c` that reports the total bytes written for packs sent to stdout or disk (including each pack's header and trailing checksum, summed when `pack.packSizeLimit` splits the output) to enable measuring how compression settings affect push performance, along with two new tests in `t/t5300-pack-object.sh`.

## 2026/08/18

- [2026/08/18/01-08-24 by Junio C Hamano <gitster@pobox.com>] Junio C Hamano questioned the patch's use of separate `pack_bytes` and `bytes_written` variables, suggesting instead that `bytes_written` be incremented directly in the common code path (hunk 1389) via `bytes_written += hashfile_total(f) + the_hash_algo->rawsz;`, noting that non-stdout pack sizes are easily observed on disk and that counting in the common path would be cleaner.

## 2026/08/19

- [2026/08/19/23-28-10 by friel@openai.com] Friel posted [PATCH v2] "pack-objects: trace pack bytes written", adding a `write_pack_file/wrote_bytes` Trace2 datum to `builtin/pack-objects.c` that reports total pack bytes written (including each pack's header and trailing checksum, summed across split packs when `pack.packSizeLimit` is set), with new tests in `t/t5300-pack-object.sh`; after Junio had written that updating `bytes_written` before finalization is equivalent, the revision drops the intermediate `pack_bytes` variable and accumulates directly into `bytes_written`.
