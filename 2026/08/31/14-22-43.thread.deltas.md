## 2026/08/31

- [2026/08/31/19-59-56 by D. Ben Knoble <ben.knoble@gmail.com>] D. Ben Knoble clarified that the quoted single-character `@` rule applies to references generally, observed that the porcelain commands create ref `refs/heads/@` (confusing since `@` is shorthand for HEAD, though not against current documented rules), noted that `git switch @` fails as it resolves to HEAD while `git checkout @` succeeds but does not switch branches, and suggested that `--branch` mode could be stricter and perhaps should reject this case.

## 2026/09/02

- [2026/09/02/07-37-53 by Jeff King <peff@peff.net>] Jeff King explained that bare "@" is allowed in a ref component (but not "@{") due to strict backwards compatibility, so this is not a bug but the system working as designed; he noted that porcelain interfaces have previously been restricted to avoid footguns, with HEAD being the notable example where `check-ref-format --branch` rejects it while plain `check-ref-format` accepts `refs/heads/HEAD`.
- [2026/09/02/07-37-53 by Jeff King <peff@peff.net>] Jeff King suggested treating bare "@" the same as HEAD in porcelain commands to block the footgun, while cautioning against forbidding all "@" since names like foo@bar are legal.
- [2026/09/02/07-37-53 by Jeff King <peff@peff.net>] Jeff King stated that the porcelain-tightening rules are not documented anywhere, which is acceptable because `check-ref-format --branch` is intended for programmatic checking against those rules.
