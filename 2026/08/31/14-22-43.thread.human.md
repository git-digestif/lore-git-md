This thread is about an inconsistency in Git’s branch name validation: porcelain commands like `git checkout -b` and `git switch -c` allow creating a branch named `@`, even though `@` is rejected by `git check-ref-format` and cannot later be checked out via those same commands (because `@` is interpreted as `HEAD`). The discussion pits convenience—`@` is a useful shorthand for `HEAD` in complex expressions—against consistency and usability.

Junio C Hamano, the maintainer, has made his position clear: he opposes allowing `@` as a branch name, calling its use a "bad habit" that violates Git’s ref name rules. He dismisses workarounds and rejects the trade-off between convenience and consistency, leaving little room for debate. Jeff King (Peff) and others have proposed a targeted fix—rejecting bare `@` in `git check-ref-format --branch` while preserving compound names like `foo@bar`—but no patch has been submitted yet.

The thread is now waiting for someone to implement Junio’s preferred solution. Until then, the inconsistency remains a usability trap: users can create a branch named `@` but can’t check it out without manual workarounds. The broader question of whether to deprecate `@` as a synonym for `HEAD` has been set aside as unlikely to gain traction due to Git’s "heavy inertia."
