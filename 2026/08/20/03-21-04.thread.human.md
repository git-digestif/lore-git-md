This thread is about a bugfix patch that preserves `WWW-Authenticate` headers during HTTP redirects, preventing authentication failures when Git follows redirects to endpoints requiring credential helpers (like OAuth2 Bearer tokens). The patch, now in its second version (`v2`), was authored by Aaron Plattner and introduces a reusable `credential_update_url()` helper in `credential.c` to centralize the preservation logic. It also includes a test in `t/t5563-simple-http-auth.sh` to verify the fix.

Junio C Hamano, the maintainer, has twice requested broader review participation, framing the patch as uncontroversial and well-motivated. Despite this, no reviewers have yet engaged, and Junio has explicitly warned that the patch will be discarded from the `seen` branch if no one steps up in the coming weeks. The patch remains in `seen` (proposed updates) and has not advanced to `next` or `master`. The technical implementation is sound, and the only remaining hurdle is securing review validation from contributors familiar with Git’s HTTP or credential subsystems.
