Subject: [PATCH v2] http: preserve WWW-Authenticate headers on redirect
Series version: v2 (root email is v1)
Originating author: Aaron Plattner <aplattner@nvidia.com>
Thread type: bugfix patch series

Core problem or goal
Git's HTTP layer loses `WWW-Authenticate` headers from an HTTP redirect response when updating the credential struct for the new URL. This breaks authentication when the redirect target requires a credential helper (e.g., OAuth2 Bearer tokens) rather than URL-embedded credentials.

Key technical details
- New symbol: `credential_update_url()` in `credential.c` (wraps `credential_from_url()` but preserves `wwwauth_headers` via `SWAP()`).
- Modified subsystems: `http.c` (now uses `credential_update_url()` when recovering from redirects), `credential.c` (new helper).
- On-disk format: unchanged.
- Test coverage: new test in `t/t5563-simple-http-auth.sh` verifies `wwwauth_headers` preservation after redirect, using a custom Apache rewrite rule (`/custom_auth_redir/`) that redirects to a bearer-auth-protected endpoint.
- Security invariant: `wwwauth_headers` are server-provided and must never be populated by `credential_from_url()`. Peff suggests adding a `BUG()` check to enforce this and requests the commit message explicitly document this invariant. Matthew Cheetham confirms the patch correctly preserves headers from the *final* redirect target, not the original server, addressing the security concern.

Open questions and loose ends
- **Helper design**: whether to keep the new `credential_update_url()` helper (v2) or revert to the v1’s inline approach for clarity. Peff prefers the latter, arguing the helper’s reusability is speculative and not worth the abstraction cost. Matthew Cheetham does not explicitly endorse either option.
- **Commit message**: needs to explicitly state (1) why preserving `wwwauth_headers` is safe (headers are server-provided and scoped to the redirect target, not URL-derived) and (2) clarify that headers originate from the final redirect target, not the original server. Peff’s requested documentation is now partially addressed by Matthew’s reply, but the commit message itself remains unupdated.
- **Defensive programming**: Peff’s suggestion to add a `BUG()` check in `credential_update_url()` to enforce that `wwwauth_headers` are never URL-derived remains unresolved. Matthew’s reply does not address this.
