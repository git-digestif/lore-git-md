# Thread deltas

## 2026/08/14

- [2026/08/14/18-55-36 by Matthew Hughes <matthewhughes934@gmail.com>] Matthew Hughes reported that bash completion for `git add` (and other commands calling `git ls-files`) hangs for seconds in large repositories (367,628 files across 58,404 directories), tracing the slowdown to `git ls-files` iterating the filesystem via `_git_add->__git_complete_index_file->__git_index_files`, with strace showing approximately 100,000 `getdents64`, 75,000 `openat`, and 50,000 `fstat` calls per directory.
- [2026/08/14/18-55-36 by Matthew Hughes <matthewhughes934@gmail.com>] He proposed a workaround adding a `GIT_COMPLETION_NO_COMPLETE_INDEX` environment variable check to `__git_complete_index_file` in `contrib/completion/git-completion.bash` to skip index completion and fall back to default Bash file completion.

## 2026/08/15

- [2026/08/15/14-17-19 by D. Ben Knoble <ben.knoble@gmail.com>] D. Ben Knoble suggested turning on "feature.manyFiles" to enable optimizations such as fsmonitor that might help in large repositories.
- [2026/08/15/19-52-46 by Matthew Hughes <matthewhughes934@gmail.com>] Matthew Hughes noted that his repository is already configured via `git-scalar(1)`, which sets `feature.manyFiles=false`; an earlier message said this disables the "many files" optimizations because Scalar sets valuable optimizations explicitly.
- [2026/08/15/19-52-46 by Matthew Hughes <matthewhughes934@gmail.com>] Matthew Hughes reported that testing in a fresh repository with `feature.manyFiles` enabled showed no significant performance change.
- [2026/08/15/19-52-46 by Matthew Hughes <matthewhughes934@gmail.com>] Matthew Hughes was not sure whether `git ls-files --exclude-standard --others --directory` knows about fsmonitor or the untracked cache the way `git status` does, nor whether it could benefit from such things.

## 2026/08/19

- [2026/08/19/20-25-46 by Matthew Hughes <matthewhughes934@gmail.com>] Matthew Hughes shared a final workaround (described as a "filthy hack") for the slow bash completion: redefining `__git_complete_index_file` to return early when options that require inspecting files on disk (`--others`, `--modified`, `--deleted`, `--ignored`, `--killed`) are present, causing completion to fall back to default Bash file completion.
