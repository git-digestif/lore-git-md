## Long threads

### diff hunk provider interface rethought

*Long thread (root 2026/05/22/02-11-19): 25 replies so far from 4 participants over 94 days; 1 message that day.*

Michael Montalbo retracted the "diff provider" abstraction introduced in RFC PATCH v7 0/10, which had proposed a repository-owned chain of providers consulted before any blob is loaded -- with a diff-hunks store at `$GIT_DIR/objects/info/diff-hunks` and an oid-only external process provider -- saying it is not ultimately helpful and shoehorns several concepts together that should be addressed separately. He clarified that "chain order is authority" was an unclear way to describe earlier providers overriding xdiff's default, confirmed the original intent was to configure a provider for a file type via `.gitattributes` and `diff.<driver>.process` with xdiff used when no provider is configured, and confirmed the diff-hunks store stores `xdl_opts` directly so the in-memory representation cannot change without breaking the cache. He agreed "coordinates" was a term he invented for offsets and lengths in hunk headers and would replace it with more explicit, established terminology. He stated his goals: a "cousin" interface to xdiff-interface allowing users to configure their own alternative to xdiff that composes with surrounding diff functionality, with xdiff still rendering content; letting current xdiff-interface callers operate with OIDs only and no content loading when only hunk header info is needed; and a consistent pkt-line interface for plugging in xdiff alternatives. He decided to return to the v6 line for future re-rolls and to eject the diff-hunks patches to focus on the pkt-line xdiff-interface line.

## Notable threads

### git organize: record file placement and apply it
Michael Montalbo posted RFC PATCH 00/14 adding `git organize`, a builtin that records a project's file-placement guideline in a tracked `.gitorganize` file and moves files that are not in their recorded directories, repointing references and staging the result. It has `status` and `apply` subcommands, configurable `organize.labeler`/`organize.organizer` commands, and eight planned carves for odb, refs, pack, diff, revision, index, setup, and transport; the cover reports 495 in-scope files (113 in place, 303 to move, 79 backlog) before the carves and 380 in place, 36 to move, 79 backlog after them. Later patches move the C sources and headers for each component into its directory as renames, repointing includes, Makefile/meson entries, and tutorial examples.

### stash: configurable ref for the stash stack
Vladimir Sitnikov proposed a `stash.ref` configuration knob (defaulting to `refs/stash`) honored by stash commands, so a worktree can set it to `refs/worktree/stash` for an isolated stash stack; he cited that the shared `refs/stash` causes silent data movement between worktrees when multiple coding agents operate concurrently. He asked whether the knob should be restricted to `refs/`, whether `git stash list` should show other worktrees' stacks, and whether entries under `refs/worktree/*` are safe from gc. Kristoffer Haugsbakk agreed a configuration option makes the most sense given history, endorsed opting in to `refs/worktree/stash`, argued the shared stash can confuse users as inconsistent with modern worktree semantics, minimized the agent-automation concern by noting agents can be instructed not to use the stash, and answered that per gitdatamodel(7) no ref namespace is special with regard to reachability and GC.

### config: --global reads both home and XDG files
Delilah Ashley Wu posted v2 of a 3-patch series making `git config --global` read both `$HOME/.gitconfig` and `$XDG_CONFIG_HOME/git/config`, fixing the inconsistency where `--global` read only the former while plain `git config list` read both. The patches enforce forward slashes in `xdg_config_home_for()` on Windows, teach `do_git_config_sequence()` to optionally report an error when no files in the sequence were successfully processed, and make `--global` reuse that sequence with the other scopes ignored. Chris Torek asked which of the global configuration files `git config --global --edit` edits.

### reftable/stack: avoid reloading the stack when locked
Karthik Nayak's series avoids reloading the reftable stack within a reference transaction, where the stack is already locked and reloading is a no-op; earlier reporting showed most time in bulk ref creation was spent on fstat(). Today he acknowledged Junio C Hamano's concern that moving the list lock to `struct reftable_stack` breaks nested `reftable_addition` instances on the same stack, proposed each addition tracking its own bit indicating whether it acquired the lock, and said he would write a unit test to validate this. He defended keeping the lock check inside `stack_uptodate()` rather than forcing every caller to replicate it, and confirmed he could reproduce Jeff King's ~25% `update-ref` speedup, explaining his own smaller numbers came from benchmarking `refs/heads/*` where `should_write_log()` shortcuts log creation, while Jeff used `refs/tags/*`, which triggered a stack reload before the patches.

### repo structure: Unicode output under UTF-8 locales
K Jayatheerth's GSoC series makes `git repo structure` emit Unicode box-drawing characters and bullets under a UTF-8 locale, falling back to ASCII otherwise, with a gettext fix so `is_utf8_locale()` does not misreport a UTF-8 locale when the charset is unset. Oswald Buddenhagen countered terminal width-disagreement concerns by citing mutt and midnight commander and proposed an opt-out option; Junio C Hamano agreed an opt-out is needed, since his objection was to consulting only locale settings with no way to opt out without abandoning UTF-8; Tuomas Ahola noted mutt falls back to ACS characters when not in a UTF-8 locale.
