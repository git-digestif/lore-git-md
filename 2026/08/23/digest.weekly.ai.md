### Packfile loading performance with many packs
*Long thread: 22 replies so far from 5 participants over 6 days.*
Jeff King's patch adding a `skip_dup_check` parameter to `packfile_list_append()` to fix an O(N^2) regression when loading many packfiles drew attention to the same problem in `packfile_list_prepend()`. Patrick Steinhardt noted the prepend function has essentially the same duplicate-check issue, and Jeff King identified prepend calls in hot code paths including the MRU adjustment from `find_pack_entry()`. He supplied a synthetic test showing `git rev-list --count foo` growing from 18 ms with 500 packs to 6351 ms with 16000 packs, concluding that MRU updates should use constant-time movement within a doubly-linked list rather than explicit duplicate check and removal.

## The period in brief
The week of 2026/08/17 through 2026/08/23 saw heavy traffic across seven active days, with multiple long-running architectural series advancing alongside new proposals. The dominant themes were the continued refinement of the ODB abstraction -- including pluggable packfile writes and generation, eager alternates loading, and corrupt-object handling -- plus significant progress on `git history squash` and worktree usability fixes. ## Key developments

### Multi-pack-index race recovery after geometric repack
Elijah Newren posted a two-patch series addressing a race where geometric repacking creates a new multi-pack-index and removes the pack an older index named as owner, causing running processes to treat present objects as missing. The series makes `git replay` fail gracefully with an error message instead of SIGSEGV when a merge input is unreadable, and teaches `find_pack_entry()` to scan the multi-pack-index's covered packs directly for a surviving copy when the recorded owner is unavailable. Junio C Hamano confirmed the diagnosis on the replay fix, calling it "Well spotted and fixed," and Patrick Steinhardt noted the race also affects `OBJECT_INFO_QUICK` callers like upload-pack's existence checks.

### Backend-agnostic corrupt-object handling in the ODB
Patrick Steinhardt posted v2 of a seven-patch series moving `OBJECT_INFO_DIE_IF_CORRUPT` handling into `do_oid_object_info_extended()` generically, restructuring around `enum odb_read_status` with negative error codes and an `errmsg` parameter so object sources can bubble up human-readable corruption messages. This removes `has_packed_and_bad()` and the loose source's direct `die()`. Junio C Hamano accepted the explanation but noted the reasoning relies on the invariant that a single pack contains each object at most once, and suggested a named enum such as `ODB_ROI_MISSING = 1` for missing objects.

### Report hook for `git-receive-pack`
Karthik Nayak's patch introducing a `report` hook that receives the pkt-line encoded status report on stdin and whose stdout replaces the report sent to the client advanced through v2. Kristoffer Haugsbakk and Patrick Steinhardt suggested documenting the hook in `githooks(5)` and `git-receive-pack(1)`, adding the GitLab MVCC use case to the commit message, and explaining why existing hooks do not fit. Junio C Hamano called the design "ugly, but may work OK" pending clearer documentation and agreed that a failed report hook should explicitly tell the client the push was declined, modeled on pre-receive.

### Parallel packfile URI fetches
Patrick Steinhardt submitted a two-patch series letting `git-fetch` and `git-clone` fetch packfile URIs in parallel, refactoring `fetch-pack.c` into preparation, fetch and aggregation phases and adding the `fetch.packfileURIThreads` config (default 1, 0 for auto-detect). Benchmarks showed speedups up to 7.58x on a throttled connection, making this a significant performance improvement for large clones.

### AI-generated treewide migration declined on DCO grounds
A treewide series migrating from `utime.h` to `utimensat()` was declined for review by brian m. carlsson after its cover letter disclosed it was generated by Gemini Flash from Antigravity, arguing this cannot satisfy the Developer's Certificate of Origin requirement. Junio C Hamano endorsed the stance as prudent, explaining that a contributor's DCO cannot be treated as valid when an AI copy editor cannot know where code was copied from, and that the project bears the cost if DCO-covered work later proves legally unusable. The discussion distinguished honest disclosure of AI use from misleading the project about provenance.

### `git organize` RFC for file placement
Michael Montalbo posted a 14-patch RFC introducing `git organize`, a command that records a project's file-placement guideline in a tracked `.gitorganize` file and moves out-of-place files, repointing references and staging the result. It includes `status` and `apply` subcommands, configurable `organize.labeler`/`organize.organizer` commands, and eight planned carves for subsystems; the final patch moves 22 transport C sources and 21 headers into `transport/`.

### Shallow clone push optimization
Elijah Newren submitted a `send-pack` patch adding reachable shallow grafts as negative pack tips so pushing from a shallow clone no longer sends the entire toplevel tree, controlled by a new `push.shallowExcludeBoundary` config (default true). Patrick Steinhardt reviewed it with questions about graft amendment, tree negotiation and `push.negotiate` defaults, which Newren answered while agreeing to mark parameters `const` and combine ref loops.

### `git config --global` XDG consistency fix
Delilah Ashley Wu posted v2 of a three-patch series making `git config --global` read both `$HOME/.gitconfig` and `$XDG_CONFIG_HOME/git/config`, fixing the inconsistency where `--global` read only the former while plain `git config list` read both. The patches enforce forward slashes in XDG paths on Windows, let the config sequence optionally report an error when no files were read, and make `--global` reuse `do_git_config_sequence()`. Chris Torek asked which file `git config --global --edit` edits.
