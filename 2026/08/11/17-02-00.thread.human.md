This thread introduces a security feature to Git’s HTTPS certificate verification: a new `http.sslVerifyStatus` option (defaulting to `false`) that enables OCSP staple validation via libcurl. When enabled, Git will reject connections to servers that don’t provide a valid OCSP staple, closing a gap where revoked certificates are currently accepted—particularly relevant for government and FIPS-compliant users, such as US Department of Defense PKI deployments. The feature has been thoroughly reviewed and is now ready for merge.

The patch has evolved through seven iterations, with the latest version combining the author’s original tests (covering fail-closed behavior and per-URL scoping) with Patrick Steinhardt’s OCSP test harness, which exercises staple validation paths. The test infrastructure now includes a certificate authority, OCSP responder, and Apache configuration for stapling, ensuring robust coverage. Junio C Hamano and Patrick Steinhardt have both confirmed the patch is technically complete, with no remaining procedural or test-coverage concerns. The patch is currently in Junio’s `next` branch and awaits his merge action to graduate to `master`.

The design defaults to `false` to avoid breaking existing setups but adopts a fail-closed approach for security when enabled. Error messages include libcurl error strings to help users diagnose issues. While there’s some discussion about whether the default should eventually change to `true` or if users should be warned when staples are ignored, these are forward-looking questions that don’t block the current merge. The feature addresses a specific but critical use case for government and enterprise users while maintaining backward compatibility.
