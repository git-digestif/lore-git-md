This thread is about a security feature patch that adds `http.sslVerifyStatus` to Git, enabling OCSP staple validation for HTTPS connections. The patch was merged to `master` on June 12, 2025, but later reverted from `next` and ejected from `seen` due to test infrastructure issues and a CI timeout problem.

The feature itself is complete and addresses a security gap where Git's HTTPS certificate verification ignores OCSP staples, which are mandated by government customers like the US Department of Defense PKI. The new `http.sslVerifyStatus` config option (defaulting to `false`) enables staple validation via libcurl, causing connections to fail if the server doesn't provide a valid staple. All review feedback was addressed, and the test failures were traced to environmental issues (GnuTLS backend limitations) rather than flaws in the patch.

However, a new issue has emerged: the patch causes CI jobs to hang indefinitely when tested in isolation, confirming the timeout problem isn't due to interactions with other topics in `seen`. Junio C Hamano reports that Linux-based CI jobs (`linux-clang` and `linux-gcc`) spin for six hours before timing out, while unrelated failures on other platforms don't affect this diagnosis. The root cause remains unknown, and no new technical objections to the feature have been raised. The next step is debugging to identify what triggers the CI hang. The patch remains in `master` but is blocked from graduating until this issue is resolved.
