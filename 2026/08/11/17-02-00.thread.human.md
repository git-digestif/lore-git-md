This thread is about a security feature patch that adds `http.sslVerifyStatus` to Git, enabling OCSP staple validation for HTTPS connections. The patch was merged to `master` on June 12, 2025, but later reverted from `next` on June 18 due to test infrastructure issues identified by SZEDER Gábor. The core functionality remains intact, and the revert was procedural to allow test fixes before the feature graduates to the next release.

The feature introduces a boolean config option (defaulting to `false`) that makes Git fail HTTPS connections if the server doesn’t provide a valid OCSP staple. This addresses a security gap where Git currently accepts revoked certificates in deployments requiring OCSP stapling, such as government PKI environments. The patch includes thorough test coverage, though Gábor’s post-merge testing revealed two issues: (1) the test’s assumption that revoked certificates would be accepted without the feature was invalid on systems where libcurl checks CRLs by default, and (2) the `SSL_VERIFYSTATUS` prerequisite’s error-message check was misleading. Both issues were traced to using the GnuTLS backend for libcurl, which lacks full OCSP stapling support; switching to OpenSSL resolves them.

The author, graysongordon-gl, addressed all prior review feedback, including Junio’s documentation tweaks and Patrick Steinhardt’s test harness contributions. Junio and Gábor have since agreed on improvements to the prerequisite (tightening the error-message check and renaming it to `CURL_SSL_VERIFYSTATUS`), but no follow-up patch has been posted yet. The thread is now focused on post-merge test robustness, with no outstanding objections to the feature itself. Two minor code-quality nits in the test script remain open, and Junio has requested revisions to overly verbose commit-message paragraphs, though these are cosmetic. The feature’s maintenance burden and default value (`false`) may be revisited later, but for now, the focus is on finalizing the test infrastructure.
