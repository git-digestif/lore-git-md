This thread is about a security feature that adds OCSP staple validation to Git’s HTTPS certificate checks. The patch introduces `http.sslVerifyStatus`, a boolean option (defaulting to `false`) that enables staple validation via libcurl, making Git fail connections if the server doesn’t provide a valid staple. The feature was merged to `master` on June 12, 2025, but reverted from `next` on June 18 after test failures surfaced.

The core functionality remains intact, but the test suite needs fixes. SZEDER Gábor identified two issues: the `SSL_VERIFYSTATUS` prerequisite is too permissive, and the test incorrectly assumes revoked certificates are accepted without the feature enabled (libcurl’s CRL checks interfere). Junio reverted the topic from `next` to allow these test problems to be resolved before the feature graduates. The author, Grayson Gordon, has addressed all prior review feedback, and both Junio and Patrick Steinhardt consider the patch technically complete. The open work is purely about test robustness—no changes to the feature itself are needed.

The thread is now waiting for a follow-up patch to tighten the prerequisite and adjust the test environment. Minor code-quality nits (error message checks and shell portability) are also pending. The default value (`false`) and fail-closed behavior are uncontroversial, though there’s lingering discussion about whether the feature’s maintenance burden is justified given OCSP stapling’s declining relevance. For now, the focus is on getting the tests right so the feature can proceed toward release.
