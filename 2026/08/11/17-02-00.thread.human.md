The `http.sslVerifyStatus` patch has been merged into Git’s `master` branch. This feature adds a new boolean configuration option, `http.sslVerifyStatus` (defaulting to `false`), which enables OCSP staple validation for HTTPS connections when set to `true`. The change addresses a security gap where Git, when linked with OpenSSL, would accept revoked certificates if the server provided an OCSP staple—an issue particularly relevant for government and government-adjacent users (e.g., US Department of Defense PKI) who mandate stapling.

The patch underwent seven iterations, with the final version combining Grayson Gordon’s original tests (covering fail-closed behavior, per-URL scoping, and edge cases) and Patrick Steinhardt’s OCSP test harness. Junio C Hamano confirmed the patch’s readiness for merge after resolving the last procedural questions, including test coverage and documentation clarity. Patrick Steinhardt, initially skeptical about the feature’s maintenance burden, ultimately endorsed the final version after the author addressed his concerns about error messaging and test robustness. The feature is now available in `master`, though the default remains `false` to avoid breaking existing setups; future discussion may revisit whether to change this default or warn users when staples are ignored.
