This thread is about a security feature patch that adds `http.sslVerifyStatus`, a new Git configuration option enabling OCSP staple validation for HTTPS connections. The patch was authored by graysongordon-gl and recently merged to `master` on June 12, 2025.

The feature addresses a security gap where Git’s HTTPS certificate verification ignores OCSP staples, potentially accepting revoked certificates. This is particularly relevant for government and government-adjacent users (e.g., US Department of Defense PKI) who mandate OCSP stapling. The new `http.sslVerifyStatus` option (defaulting to `false` for backward compatibility) enables staple validation via libcurl’s `CURLOPT_SSL_VERIFYSTATUS`, causing connections to fail if the server does not provide a valid staple. The design is fail-closed for security but avoids breaking existing setups by defaulting to off.

Key participants include the author, who drove the feature with thorough testing and addressed all review feedback, and Junio C Hamano, who confirmed the patch’s technical completeness and merged it. Patrick Steinhardt initially questioned the feature’s maintenance burden but later provided a test harness and confirmed the patch’s readiness for graduation. His final review raised minor, non-blocking nits about the commit message’s verbosity but explicitly stated no further changes were needed. The patch is now in `master`, with no further changes expected. Open questions remain about whether the default should eventually change to `true` or if users should be warned when staples are ignored, but these are long-term considerations.
