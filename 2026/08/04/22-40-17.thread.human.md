This thread is about a bugfix for the `contrib/credential/libsecret` credential helper, which crashes and silently loses stored passwords when the GNOME keyring is locked or items are concurrently deleted. Daniel Martí posted a v2 patch that removes the problematic `SECRET_SEARCH_LOAD_SECRETS` flag, replacing it with explicit secret loading for each matched item. This ensures errors are properly reported rather than silently discarded, preventing assertion failures and data loss.

The patch is now self-contained, with a clear commit message explaining the design trade-off: Martí argues the flag isn’t a true optimization and its error-silencing behavior is harmful, while Junio C Hamano initially preferred preserving the batch-fetch path for the common case. The v2 update addresses Junio’s feedback on clarity and rationale, making the case for dropping the flag entirely. The fix is minimal, touching only the libsecret helper, and maintains the same number of D-Bus round-trips while ensuring all errors are surfaced.

The discussion is now focused on this design choice rather than technical correctness. Martí’s patch aligns with libsecret’s own `secret-tool` utility and ensures genuinely inaccessible items produce useful error messages, while Git can still fall back to password prompting. No test coverage is included due to reproducibility challenges, but the fix is well-motivated and ready for further review.
