This thread is about a bugfix for the `contrib/credential/libsecret` credential helper, which currently crashes and silently loses data when retrieving credentials from the GNOME keyring. The issue occurs because the `SECRET_SEARCH_LOAD_SECRETS` flag used in the current implementation silently discards failures (e.g., for locked or deleted items), leading to NULL secret values and assertion failures. Daniel Martí proposed a patch that replaces this flag with an explicit `secret_item_load_secret_sync()` call to surface all errors, while Junio C Hamano suggested an alternative that retains the flag and conditionally loads secrets only when NULL is returned.

The discussion has been substantive, with Martí defending his design as simpler and more reliable, and Junio prioritizing the batch-fetch optimization for the common case. The latest development is a question from M Hickford, who asks whether the silent discarding of failures is intended behavior in libsecret or an upstream bug. This shifts the discussion toward whether the fix should address Git’s usage of the library or if the issue lies in libsecret itself. No consensus has been reached on the design trade-off or the upstream status, but the procedural path forward is clear: Martí is expected to post a v2 patch addressing Junio’s feedback on clarity, while the upstream question may influence the final approach. The thread remains under active review.
