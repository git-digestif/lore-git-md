## 2026/08/22

- [2026/08/22/20-47-12 by Daniel Martí <mvdan@mvdan.cc>] Daniel Martí replied to Junio C Hamano's review of the libsecret credential patch, conceding that dropping SECRET_SEARCH_LOAD_SECRETS is not strictly necessary since checking secret_item_get_secret() for NULL would also avoid the assertion failures, but explaining that the flag is not a single call: libsecret implements it as SearchItems followed by GetSecrets with errors from the second step discarded, and it skips locked items client-side without asking the daemon.
- [2026/08/22/20-47-12 by Daniel Martí <mvdan@mvdan.cc>] He argued that his unconditional explicit load keeps the common case at the same two round trips (SearchItems plus one GetSecret for the used item), whereas a fallback version would add a third round trip in the rare race case, and that keeping the flag with a fallback would leave the explicit-load path essentially unexercised while still silently discarding load errors on the common path; with the unconditional load there is one code path taken on every run and any failure produces a real error message.
- [2026/08/22/20-47-12 by Daniel Martí <mvdan@mvdan.cc>] He agreed that the race condition requires a concurrently-racing process or a locked keyring to trigger and that he does not see a way to test it reliably.
