This thread is about a small but tidy patch from Sahitya Chandra that fixes a quirk in Git’s sparse-index handling. When `repo_index_has_changes()` is called on an unborn HEAD (a newly created orphan branch), it currently forces a full expansion of any sparse directory entries in the index, even though an unborn HEAD is logically equivalent to the empty tree. The patch replaces that fallback with a direct comparison against the empty tree, keeping the unborn-branch case on the same code path as normal tree comparisons and avoiding the unnecessary expansion.

Sahitya and Elijah Newren have already agreed that the patch is a code-hygiene improvement rather than a performance fix—there’s no realistic scenario where a user with an unborn HEAD would have a sparse index containing millions of uncommitted files. The patch removes a TODO, unifies the code path, and reduces the code footprint by 28 lines. The only loose end was a minor ambiguity in the test-helper output format, which Sahitya has now resolved by revising the output to handle multiple dirty paths unambiguously. A v2 patch is imminent, and once posted it should be ready for Junio’s queue.
