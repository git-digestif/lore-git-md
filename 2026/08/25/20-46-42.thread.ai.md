Thread identity: patch series extending `git var` to provide unified identity and signing configuration, replacing the earlier `git ident` proposal. Originating author: Andrew Pleeter (via GitGitGadget). Thread type: patch series (implementation of design consensus).

Core problem or goal: provide a unified, scriptable interface to Git’s identity (author/committer names/emails/dates) and signing configuration (GPG/SSH/X.509 keys, `commit.gpgsign` status) by extending the existing `git var` plumbing command. The solution must support both interactive use and scripting, with composable arguments and machine-readable output. **Note**: the `GIT_SIGNING_KEY` variable has been dropped from this iteration due to ambiguity in its interpretation across signing mechanisms (GPG/SSH/X.509).

Exit-code behavior is finalized: multi-variable queries exit 0 even if some requested variables are unset (omitting them from output), while non-zero codes are reserved for actual errors (unknown variables, etc.). Key technical details:
- **Files touched**: `builtin/var.c`, `Documentation/git-var.adoc`, `t/t0007-git-var.sh`.
- **New variables**: `GIT_AUTHOR_NAME`, `GIT_AUTHOR_EMAIL`, `GIT_AUTHOR_DATE`, `GIT_COMMITTER_NAME`, `GIT_COMMITTER_EMAIL`, `GIT_COMMITTER_DATE`. **`GIT_SIGNING_KEY` has been removed** due to ambiguity in its interpretation across signing mechanisms (GPG/SSH/X.509).
- **Behavior**: supports multiple variable arguments in a single invocation, `-z` for NUL-terminated output (aligned with `git config -z`: `key\nvalue\0` or `VARIABLE=value` pairs), and strict argument ordering (options precede variable names, enforced via `parse_options()` with `PARSE_OPT_STOP_AT_NON_OPTION`). Maintains backwards compatibility for single-variable queries (bare values) while introducing structured output for multi-variable queries.
- **Output format**: `-z` mode matches `git config -z` (`key\nvalue\0`), with multi-valued variables formatted as repeated `VARIABLE=value` entries (e.g., `GIT_CONFIG_GLOBAL=value1\nGIT_CONFIG_GLOBAL=value2\0`). Non-`-z` mode prints `VARIABLE=value` pairs, omitting unset variables. This design eliminates ambiguity for multi-valued variables. The patch adds `-z` mode, which prints bare values followed by NUL for single-variable queries and `VARIABLE\nvalue\0` for `-l` mode, identical to `git config -z`. Multi-valued variables are formatted as repeated `VARIABLE=value` entries, each terminated by NUL.
- **Error handling**: multi-variable queries exit 0 if *any* requested variable is set (omitting unset variables from output), while non-zero exit codes are reserved for actual errors (unknown variable names, invalid arguments, etc.). Empty variable lists exit with code 129 and print usage. This aligns with `GIT_CONFIG_NOSYSTEM` precedent.
- **Code structure**: uses `enum ident_part` for type safety, table-driven variable handling, and Git’s standard argument parsing infrastructure. Multi-valued variables are implemented via `string_list`-based callbacks, with explicit formatting as repeated `VARIABLE=value` entries in both `-z` and non-`-z` modes. **Patch 1 (v9)** refactors the internal representation of multi-valued variables to use a `string_list` instead of a newline-joined string, eliminating fragility where delimiters could appear in values. **Patch 2 (v9)** switches to `parse_options()` for argument parsing, enforcing strict ordering (options before variable names) and introducing the `-z` flag. **Patch 3 (v9)** implements multi-variable support, allowing `git var` to accept more than one variable argument in a single invocation, printing each as a `VARIABLE=value` pair (or `VARIABLE\nvalue\0` under `-z`), and omitting unset variables without error. **Patch 4 (v9)** adds the six new identity variables, each backed by a helper function that calls `split_ident_line()` on the corresponding ident string and returns the requested component. The implementation reuses Git’s existing ident-parsing logic, ensuring correct handling of awkward characters in names or emails. Documentation is updated to show both single-variable and multi-variable usage examples, and tests verify individual component queries, unset identities, and inclusion in `git var -l` output.
- **Argument parsing**: enforces strict ordering (options before variable names) and rejects ambiguous invocations (e.g., `git var GIT_AUTHOR_NAME -z`). `--` is not currently handled but could be added in a future iteration.
- **Test coverage**: comprehensive, including `-z` output format, multi-valued variables, argument ordering, unset variables, exit-code behavior, and individual identity component queries. Tests use Git’s `nul_to_q` helper to avoid binary comparison errors.
