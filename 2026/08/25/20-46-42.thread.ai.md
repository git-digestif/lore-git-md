Thread identity: patch series extending `git var` to provide unified identity and signing configuration, replacing the earlier `git ident` proposal. Originating author: Andrew Pleeter (via GitGitGadget). Thread type: patch series (implementation of design consensus).

Core problem or goal: provide a unified, scriptable interface to Git’s identity (author/committer names/emails/dates) and signing configuration (GPG/SSH/X.509 keys, `commit.gpgsign` status) by extending the existing `git var` plumbing command. The solution must support both interactive use and scripting, with composable arguments and machine-readable output.

Current status: **technically complete and ready for integration**. The v8 patch resolves the final two documentation-implementation discrepancies raised by Junio in the v7 review: (1) the output format now prints `VARIABLE=value` pairs (or `VARIABLE\nvalue\0` with `-z`), eliminating ambiguity for multi-valued variables, and (2) the exit code behavior is now accurately documented and aligned with the implementation (multi-variable queries exit with code 1 if *any* requested variable is unset). The series remains in `seen`; no maintainer has signaled graduation to `next`, but the patch is **ready for integration pending Junio’s final confirmation**.

Key technical details:
- **Files touched**: `builtin/var.c`, `Documentation/git-var.adoc`, `t/t0007-git-var.sh`.
- **New variables**: `GIT_AUTHOR_NAME`, `GIT_AUTHOR_EMAIL`, `GIT_AUTHOR_DATE`, `GIT_COMMITTER_NAME`, `GIT_COMMITTER_EMAIL`, `GIT_COMMITTER_DATE`, `GIT_SIGNING_KEY` (resolves the key that would be used for a commit, regardless of `commit.gpgsign` status).
- **Behavior**: supports multiple variable arguments in a single invocation, `-z` for NUL-terminated output (aligned with `git config -z`: `key\nvalue\0` or `VARIABLE=value` pairs), and strict argument ordering (options precede variable names, enforced via `parse_options()` with `PARSE_OPT_STOP_AT_NON_OPTION`). Maintains backwards compatibility for single-variable queries (bare values) while introducing structured output for multi-variable queries.
- **Output format**: `-z` mode matches `git config -z` (`key\nvalue\0`), with multi-valued variables formatted as repeated `VARIABLE=value` entries (e.g., `GIT_CONFIG_GLOBAL=value1\nGIT_CONFIG_GLOBAL=value2\0`). Non-`-z` mode prints `VARIABLE=value` pairs, omitting unset variables. This design eliminates the ambiguity Junio highlighted in v7, as scripts no longer need prior knowledge of which variables are multi-valued.
- **Error handling**: multi-variable queries exit with code 1 if *any* requested variable is unset (matching Phillip Wood’s recommendation), while single-variable queries exit with code 1 only if that specific variable is unset. Unset variables are omitted from the output in multi-variable queries. Empty variable lists (e.g., `git var` with no args) exit with code 129 and print usage.
- **Code structure**: uses `enum ident_part` for type safety, table-driven variable handling, and Git’s standard argument parsing infrastructure. The `GIT_SIGNING_KEY` variable uses Git’s standard `get_signing_key()` (from `gpg-interface.c`) for consistency with actual commit signing.
- **Multi-valued variables**: implemented via `string_list`-based callbacks, with explicit formatting as repeated `VARIABLE=value` entries in both `-z` and non-`-z` modes. The documentation now clearly labels multi-valued variables (e.g., `GIT_CONFIG_GLOBAL`).
- **Argument parsing**: enforces strict ordering (options before variable names) and rejects ambiguous invocations (e.g., `git var GIT_AUTHOR_NAME -z`). `--` is not currently handled but could be added in a future iteration.
- **Signing key resolution**: uses `get_signing_key()` to ensure consistency with actual commit signing. The unresolved question about whether `GIT_SIGNING_KEY` alone is sufficient for callers to determine the signing mechanism (GPG/SSH/X.509) remains, but this is not a blocker for integration.
- **Test coverage**: comprehensive, including `-z` output format, multi-valued variables, argument ordering, unset variables, and signing key resolution. Tests use Git’s `nul_to_q` helper to avoid binary comparison errors.
- **No on-disk format changes or new configuration options**; the patch extends an existing plumbing command predictably.

Open questions and loose ends:
- **`GIT_SIGNING_KEY` use case**: whether the key alone is sufficient for callers to determine the signing mechanism (GPG/SSH/X.509). Andrew has not replied to Phillip Wood’s prior question, but this is not a blocker for integration.
- **Usability**: whether to allow empty variable lists (e.g., `git var` with no args) remains deferred to Junio’s broader usability argument. `--` handling is not implemented but could be added later.
- **Long-term CLI rules**: whether Git 3.0 should enforce stricter flag/variable ordering across all commands, and whether `git var` should stop handling `git config -l` output. Neither is a blocker for the current patch.
