This thread is about a 9-patch series from Patrick Steinhardt that refactors how Git handles ODB alternates during repository creation. The goal is to simplify the ODB interface by removing the ability to write alternates after repository creation, making alternates an implementation detail of the ODB backend. The series is part of Patrick’s ongoing ODB abstraction effort and has now reached its fifth iteration (`v5`).

The key changes include splitting `init_db()` into focused functions (`create_repository()`, `create_reference_database()`, and `create_object_database()`), consolidating all alternates logic into a single code path (`collect_alternates()`), and writing alternates during ODB creation using Git’s lockfile API for atomicity. The series also fixes a latent bug in worktree alternates handling and removes the now-unused `write_alternate` callback and its supporting infrastructure. Feedback from reviewers like Karthik Nayak and Justin Tobler has been addressed, with minor adjustments to naming, documentation, and error handling. The most substantive discussion revolved around error-handling robustness in the alternates-writing loop, but Patrick declined to implement per-write `ferror()` checks, arguing that the current single check at the end is sufficient.

The series is now fully reviewed and ready for integration into Junio’s `next` branch. It introduces no user-visible changes but lays the groundwork for future ODB abstraction work by simplifying the interface and resolving long-standing correctness and concurrency concerns. Reviewers tracking the ODB effort may note the lockfile API adoption and the deferred discussion about backend error codes for future patches.
