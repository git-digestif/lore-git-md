This thread is about Patrick Steinhardt’s 9-patch series refactoring how Git handles ODB alternates during repository creation, part of the larger ODB abstraction effort. The goal is to simplify the ODB interface by removing the ability to write alternates after repository creation, consolidating all alternates logic into the ODB creation step. This prepares for alternates to become an implementation detail of the ODB backend, giving backends more control over their configuration.

The series is now at v4, with all patches posted and under review. The key changes since v3 are improved documentation for the new repository creation functions (`create_repository()`, `create_reference_database()`, and `create_object_database()`) and clarification of the `reinit_ok` parameter, addressing Justin Tobler’s feedback. The series also includes a critical correctness fix in patch 5 to ensure alternates are only added for shared local clones, resolving a latent bug in worktree alternates handling. Patch 7 adopts Git’s lockfile API for writing alternates, addressing Junio C Hamano’s and Toon Claes’s earlier concerns about race conditions and concurrent access.

The refactoring touches several subsystems, including ODB, alternates handling, repository creation, and worktree handling. No user-visible changes are introduced, but the series lays the groundwork for future ODB abstraction work. The patches have been well-received, with substantive reviews from Justin Tobler and surface-level feedback from Toon Claes. Junio’s primary concern about the lockfile API has been resolved, and the series is now a strong candidate for integration once remaining ODB-focused contributors (e.g., Karthik Nayak) have reviewed patches 7–9. The only open question is a forward-looking architectural discussion about whether user-facing options like `--shared` should be restricted to specific backends or left to backend discretion.
