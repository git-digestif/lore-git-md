This thread is Patrick Steinhardt’s nine-patch series refactoring how Git handles ODB alternates during repository creation, part of the larger ODB abstraction effort. The goal is to remove the ability to write alternates after repository creation, simplifying the ODB interface by making alternates an implementation detail of the backend. Currently, alternates can be added at any time, but Git only uses this during initial setup (e.g., `git clone --reference`). The series introduces a new option in `odb_source_create_on_disk()` to handle alternates at creation time, eliminating the need for a separate `write_alternates()` callback.

The v3 iteration refactored `init_db()` into `create_repository()`, which now only creates the repository skeleton without setting up the refdb or ODB, moving command-specific logic into the commands themselves. This addresses feedback about the growing complexity of `init_db()`’s skip flags. Patch 2 deferred ODB initialization in `git clone` until after the clone source URI is resolved, ensuring alternates paths are fully resolved before ODB setup. Patch 4 (previously summarized) renamed `setup_reference()` to `collect_alternates()` and refactored it to gather alternates paths into a `strvec` instead of immediately writing them to the ODB. The latest patch, 5/9, consolidates alternates logic for shared local clones (`git clone --shared`) into `collect_alternates()`, removing manual alternates updates in `clone_local()` and preparing for the lockfile API adoption in patch 6.

The series is under review, with all nine patches posted as v3. Junio C Hamano and Toon Claes raised concerns in earlier versions about TOCTOU races and concurrent access, which Patrick addressed by adopting the lockfile API for writing the `info/alternates` file. Justin Tobler’s feedback on the ODB interface’s flexibility—whether user-facing options like `--shared` should be backend-specific—remains unresolved but is not a blocker. The series is uncontroversial in its current form, with no major objections or open technical issues. The remaining patches (6-9) will remove the now-redundant `write_alternates()` infrastructure and finalize the alternates-as-backend-detail design. Reviewers may focus on edge cases in path resolution or error handling, but the series is expected to proceed to integration once the ODB-focused contributors (e.g., Karthik Nayak) have reviewed the later patches. No user-visible changes are introduced.
