This thread is about Patrick Steinhardt’s 9-patch series (`[PATCH v5 0/9]`) refactoring how Git handles ODB alternates during repository creation. The goal is to simplify the ODB interface by removing the ability to write alternates after repository creation, making alternates an implementation detail of the ODB backend. The series is part of the ongoing ODB abstraction effort and is now complete, with all substantive feedback addressed.

The key changes include splitting `init_db()` into focused helpers (`create_repository()`, `create_object_database()`, and `initialize_repository()`), consolidating alternates logic into a single code path (`collect_alternates()`), and adopting Git’s lockfile API for atomic alternates writes. The series also fixes a latent bug in worktree alternates handling and removes the now-unused `write_alternate` callback infrastructure. Karthik Nayak’s reviews have been largely surface-level, but his feedback on patch 7/9 raised a minor but important robustness concern: checking `ferror()` after each `fprintf()` call in the alternates-writing loop rather than once at the end. Patrick has acknowledged this as the sole remaining loose end, and the series is otherwise ready for integration.

The patches are built on `ps/odb-eagerly-load-alternates` and touch `builtin/clone.c`, `setup.c`, `odb/source-files.c`, and related files. No user-visible behavior changes are introduced, but the refactoring simplifies the codebase and prepares for future ODB abstraction work. The series is uncontroversial, with Justin Tobler and Karthik Nayak providing the most substantive feedback, and Junio’s earlier security concern about lockfile usage has been resolved. Once the error-handling detail in patch 7/9 is addressed, the series should graduate to `next`.
