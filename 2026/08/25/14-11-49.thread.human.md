This thread is about Patrick Steinhardt’s 8-patch series refactoring how Git handles ODB alternates during repository creation. The goal is to simplify the ODB interface by removing the ability to write alternates after repository creation, consolidating the logic into a single step during ODB setup. This change is part of the ongoing ODB abstraction effort, which aims to make alternates an implementation detail of the ODB backend.

The series is now in its second version (`v2`), addressing the primary blocker from `v1`: the adoption of Git’s standard lockfile API for writing the `info/alternates` file, which resolved TOCTOU race and concurrent access concerns raised by Junio C Hamano and Toon Claes. Patches 1-5 refactored reference handling in `git clone`, deferring ODB setup and consolidating alternates logic into a new `collect_alternates()` function. This fixed a latent bug in worktree alternates handling and ensured alternates are written with full context, including URI rewrites from template configurations. Patches 6-8 implemented the core design change: alternates are now written during ODB creation using a new `odb_create_on_disk_options` struct, and the unused `write_alternates()` infrastructure has been removed.

The series has received substantive reviews from Justin Tobler, who raised forward-looking questions about the growing complexity of `init_db()`’s interface and the flexibility of the ODB abstraction. Patrick Steinhardt addressed these concerns, clarifying that the `alternates` field in `odb_create_on_disk_options` is intentionally flexible to allow backends to define their own semantics for options like `--shared`. This aligns with the ODB abstraction’s goal of making alternates an implementation detail. No other reviewers have weighed in on the locking issue or the broader design, though the series is expected to proceed to integration once ODB-focused contributors like Karthik Nayak review patches 6-8. The discussion may also prompt broader conversations about safety, concurrency, and interface clarity in the ODB abstraction effort.
