This thread is about Patrick Steinhardt’s 9-patch series refactoring how Git handles ODB alternates during repository creation. The goal is to simplify the ODB interface by removing the ability to write alternates after repository creation, consolidating all alternates setup into a single code path during ODB initialization. This is part of the broader ODB abstraction effort, which aims to give backends more control over their configuration.

The series has evolved through three versions, with v3 incorporating feedback to refactor `init_db()` into `create_repository()`, eliminating skip flags and deferring ODB setup in `git clone` until after URI resolution. This ensures alternates are written with full context, addressing forward compatibility with alternate ODB backends. Patches 4–6 consolidate alternates logic into `collect_alternates()`, fixing a latent bug in worktree handling and ensuring all alternates paths flow through a single code path. Patch 7 implements the core change: alternates are now written during ODB creation using Git’s lockfile API, resolving security concerns about TOCTOU races. The final patches (8–9) remove the now-unused `write_alternates()` infrastructure, completing the refactoring.

Justin Tobler’s reviews have been substantive, focusing on interface clarity and correctness. His feedback on patch 5 identified a critical bug where alternates were incorrectly added for non-shared local clones, which Patrick addressed in v3. A recent follow-up from Justin retracted an earlier suggestion after realizing the issue was already handled in patch 6, confirming the series’ incremental approach. Junio C Hamano’s earlier concern about lockfile usage was resolved in v2, and Toon Claes’s surface-level approval in v2 carried little weight due to its lack of technical engagement. The series is now under final review, with no major open questions beyond potential scrutiny of the lockfile cleanup logic and the ODB interface’s long-term flexibility. The next steps are likely integration once remaining ODB-focused contributors (e.g., Karthik Nayak) review patches 7–9.
