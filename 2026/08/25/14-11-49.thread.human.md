Patrick Steinhardt’s nine-patch series to refactor ODB alternates handling has now concluded with the removal of the `write_alternate` callback and its supporting infrastructure. The series, part of the ongoing ODB abstraction effort, simplifies the ODB interface by eliminating the ability to write alternates after repository creation, consolidating all alternates logic into the ODB creation process.

The key changes include splitting `init_db()` into focused functions (`create_repository()`, `create_reference_database()`, and `create_object_database()`), deferring ODB setup in `git clone` until after URI resolution, and refactoring alternates handling to use a `strvec` of paths gathered during repository creation. Patches 4-6 consolidated alternates logic for both shared and non-shared local clones, fixing a latent bug in worktree alternates handling and ensuring alternates are only added when explicitly requested. Patch 7 introduced atomic writes via Git’s lockfile API, addressing security concerns raised by Junio C Hamano in earlier iterations. The final patch removes the now-unused `write_alternate` callback and its backend-specific implementations, completing the series.

Review feedback has been largely surface-level, with Karthik Nayak and Justin Tobler providing the most substantive input. Karthik’s feedback on patch 7 highlighted error-handling robustness and backend error reporting, though these points remain open but non-blocking. Justin’s reviews identified a critical correctness issue in patch 5 (ensuring alternates are only added for shared local clones) and improved documentation for the new helpers. The series is now ready for integration, with all patches posted as v5 and no outstanding technical objections. The refactoring paves the way for alternates to become an ODB backend implementation detail, aligning with the broader ODB abstraction goals.
