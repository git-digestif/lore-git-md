This 9-patch series by Patrick Steinhardt refactors how Git handles ODB alternates during repository creation, removing the ability to write alternates after repository setup. The goal is to simplify the ODB interface and prepare for alternates to become an implementation detail of the ODB backend. The series is now in its fifth iteration (v5) and has addressed all substantive review feedback, making it a strong candidate for integration.

The key changes include splitting `init_db()` into focused functions (`create_repository()`, `create_reference_database()`, and `create_object_database()`), consolidating all alternates logic into a single `collect_alternates()` function, and writing alternates atomically during ODB creation using Git's lockfile API. Patch 5/9, the latest update, moves the setup of alternates for shared local clones (`git clone --shared`) into `collect_alternates()`, fixing a latent bug where alternates were incorrectly added for non-shared local clones. The patch also includes a critical correctness fix to ensure alternates are only added when `--shared` is explicitly set, addressing feedback from Justin Tobler.

The series has received surface-level reviews from Karthik Nayak and Justin Tobler, with the latter providing substantive feedback on interface clarity and correctness. Karthik’s review of patch 7/9 raised technical concerns about error handling robustness and backend error reporting, which may prompt follow-up work. The lockfile API adoption in patch 7 resolves the primary security concern from earlier iterations, and the series is now complete with all patches posted as v5. No major open questions remain, though reviewers may focus on the error handling improvements suggested for patch 7/9. The series is built on `ps/odb-eagerly-load-alternates` and is part of Patrick Steinhardt’s broader ODB abstraction effort.
