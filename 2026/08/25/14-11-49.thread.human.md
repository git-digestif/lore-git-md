This thread is about Patrick Steinhardt’s 8-patch series refactoring how Git handles ODB alternates during repository creation, part of the larger ODB abstraction effort. The goal is to simplify the ODB interface by removing the ability to write alternates after repository creation, consolidating alternates setup into a single step during ODB creation. This prepares for alternates to become an implementation detail of the ODB backend, giving backends more control over their configuration.

The series is now in its second version, addressing the primary blocker from v1: adopting Git’s standard lockfile API for writing the `info/alternates` file in patch 6, which resolved TOCTOU race and concurrent access concerns raised by Junio C Hamano and Toon Claes. Patches 1-5 refactored reference handling in `git clone`, deferring ODB setup and consolidating alternates logic into a new `collect_alternates()` function. This fixed a latent bug in worktree alternates handling and ensured alternates are written with full context, including URI rewrites from template `.git/config` files. Patch 6 introduced the core design change, using `odb_create_on_disk_options` to write alternates during ODB creation with the lockfile API. Patch 7 wired up the new mechanism in `cmd_clone()`, and patch 8 removed the now-unused `write_alternates()` infrastructure.

The latest discussion between Patrick Steinhardt and Justin Tobler focuses on the architectural implications of the `init_db()` interface. Justin suggested eliminating "skip" flags in favor of explicit repository setup, and Patrick responded by proposing a more radical refactoring: lifting repository initialization messages out of `init_db()` entirely and renaming it to `create_repository()` to better reflect its narrowed scope. This would simplify the interface by moving command-specific logic to the commands themselves. Patrick also clarified that deferring `setup_reference()`—which configures alternates, not refs—is necessary because alternates can only be written after the ODB exists. The discussion is forward-looking and may influence future iterations of the series or broader refactoring of repository initialization.

The series is under review, with all substantive feedback addressed. Justin Tobler’s reviews have been substantive and forward-looking, focusing on interface clarity and extensibility. Toon Claes provided surface-level approval of the cover letter in v2, and Junio’s earlier concerns about locking have been resolved. The series is expected to proceed to integration once the remaining ODB-focused contributors (e.g., Karthik Nayak) have reviewed patches 6-8 and the new question about backend-specific options is discussed. No user-visible changes are introduced, but the refactoring is foundational for the ODB abstraction effort.
