This thread is about Patrick Steinhardt’s 9-patch series (`[PATCH v4 0/9]`) refactoring how Git handles ODB alternates during repository creation. The goal is to simplify the ODB interface by removing the ability to write alternates after repository creation, consolidating all alternates logic into the ODB creation process. This prepares the ground for alternates to become an implementation detail of the ODB backend, giving backends more control over their configuration.

The series has evolved through four iterations, with v4 addressing all substantive review feedback. Key changes include improved documentation for the new repository creation functions (`create_repository()`, `create_reference_database()`, and `create_object_database()`), a critical correctness fix in patch 5/9 to ensure alternates are only added for shared local clones (`git clone --shared`), and the adoption of Git’s lockfile API in patch 7/9 to ensure atomic writes and resolve security concerns raised by Junio C Hamano. Patches 5-6/9 also fixed a latent bug in worktree alternates handling, ensuring alternates are correctly resolved when cloning from a linked worktree. The series is now well-documented, uncontroversial, and appears ready for integration.

Reviewers Justin Tobler and Toon Claes have weighed in, with Justin’s feedback driving the most significant improvements. His review of v3 identified the correctness issue in patch 5/9, and his request for better documentation was addressed in v4. Toon’s earlier comments were mostly surface-level, though his concern about locking in patch 8/9 was resolved by the lockfile adoption in patch 7/9. Justin’s final reply to the v4 cover letter offers a surface-level approval, acknowledging the improved documentation but not engaging with the technical substance of the patches. No substantive objections remain, and the series is now awaiting Junio’s queueing. The patches touch the ODB subsystem, repository creation logic, and alternates handling, with no user-visible behavior changes.
