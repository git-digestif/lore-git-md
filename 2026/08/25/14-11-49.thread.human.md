Patrick Steinhardt’s nine-patch series to refactor ODB alternates handling during repository creation is now in its fourth iteration and nearing readiness for Junio’s queue. The goal is to remove the ability to write alternates after repository creation, simplifying the ODB interface by consolidating alternates logic into the ODB creation process. This change is part of the broader ODB abstraction effort, which aims to make alternates an implementation detail of the ODB backend.

The series has evolved through feedback, with the most significant change in v4 being improved documentation for the new repository creation functions (`create_repository()`, `create_reference_database()`, and `create_object_database()`) and the `reinit_ok` parameter, addressing Justin Tobler’s substantive review. The core design change—writing alternates during ODB creation via Git’s standard lockfile API—resolves earlier security concerns about TOCTOU races and concurrent access. Patches 1-6 consolidate alternates logic into a single code path, fixing a latent bug in worktree alternates handling and ensuring alternates are only added for shared local clones (`git clone --shared`). Patches 7-9 implement the lockfile-based alternates writes, wire the alternates `strvec` to the ODB creation process, and remove the now-unused `write_alternates()` infrastructure.

Review feedback has been largely surface-level, with Karthik Nayak’s recent comment on patch 5/9 suggesting a minor readability improvement to the conditional logic. This suggestion does not affect the patch’s correctness—the `option_shared` guard already ensures alternates are only added for shared clones, addressing Justin Tobler’s earlier feedback. No substantive objections remain, and the series appears ready for integration. The only open architectural question, raised by Justin Tobler, concerns the ODB interface’s long-term flexibility regarding user-facing options like `--shared`, but this does not block the current refactoring. The series is built on `ps/odb-eagerly-load-alternates` and represents a key step toward simplifying the ODB interface.
