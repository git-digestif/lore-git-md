This thread is about Patrick Steinhardt’s 9-patch series refactoring how Git handles ODB alternates during repository creation, part of the broader ODB abstraction effort. The goal is to simplify the ODB interface by removing the ability to write alternates after repository creation, consolidating all alternates logic into the ODB creation process. This prepares for alternates to become an implementation detail of the ODB backend, giving backends more control over their configuration.

The series is now complete and ready for integration. All substantive feedback has been addressed, including a critical correctness fix in patch 5/9 to ensure alternates are only added for shared local clones (`git clone --shared`), a latent bug fix in patch 6/9 for worktree alternates handling, and the adoption of Git’s lockfile API in patch 7/9 to resolve TOCTOU race concerns raised by Junio in v1. The final patch (9/9) removes the `write_alternate` callback and its supporting infrastructure, completing the refactoring. Karthik Nayak’s recent "otherwise looks good" confirms the series is ready for Junio to queue in `next`.

Key changes include splitting `init_db()` into focused helpers (`create_repository()`, `create_object_database()`, `initialize_repository()`), consolidating alternates logic into `collect_alternates()` (renamed from `setup_reference()`), and introducing `odb_create_on_disk_options` to pass alternates paths during ODB creation. The series touches `builtin/clone.c`, `setup.c`, and ODB backend files, with new tests verifying the worktree alternates bug fix. No user-visible behavior changes are introduced, but the refactoring simplifies the ODB interface and aligns with the ODB abstraction effort’s goals. The deferred question about backend error codes (distinguishing "alternates not supported" from other failures) may influence future ODB work but does not block this series.
