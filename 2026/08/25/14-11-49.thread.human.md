Patrick Steinhardt’s nine-patch series to refactor ODB alternates handling during repository creation is now in its fourth iteration and appears close to being queued. The goal is to simplify the ODB interface by removing the ability to write alternates after repository creation, consolidating all alternates logic into the ODB creation process. This change is part of the broader ODB abstraction effort, which aims to make alternates an implementation detail of the ODB backend.

The series has evolved significantly since v1, addressing Junio C Hamano’s security concern about TOCTOU races by adopting Git’s standard lockfile API for atomic alternates writes. Justin Tobler’s substantive feedback on v2 and v3 led to the refactoring of `init_db()` into `create_repository()`, eliminating skip flags and improving interface clarity, as well as a critical correctness fix in patch 5/9 to ensure alternates are only added for shared local clones. The v4 iteration adds documentation for the new repository creation functions and clarifies the `reinit_ok` parameter, addressing Justin’s request for better documentation. Karthik Nayak’s recent substantive review of patch 7/9 raises two technical points: tighter error handling for alternates writes (checking `ferror()` after each `fprintf()` rather than once at the end) and a forward-looking question about formalizing backend error codes. Neither issue challenges the series’ core design, and both are likely to be addressed with minor adjustments.

The series is now well-documented and uncontroversial, with all substantive feedback incorporated. Patches 1-6 consolidate alternates logic into a single code path, fix a latent bug in worktree alternates handling, and defer ODB setup until after URI resolution in `git clone`. Patches 7-9 implement the core design change: alternates are now written during ODB creation via `odb_create_on_disk_options`, using the lockfile API for atomicity, and the `write_alternates()` callback is removed. The only remaining loose end is Justin Tobler’s architectural question about whether user-facing options like `--shared` should be restricted to the "files" backend or left to backend discretion. Patrick Steinhardt’s response in v2 clarified that the `odb_create_on_disk_options` interface is intentionally flexible, allowing backends to define their own semantics, but this may prompt further discussion about interface clarity. The series is otherwise ready for Junio’s queueing.
