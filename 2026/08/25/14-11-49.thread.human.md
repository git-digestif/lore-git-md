This thread is Patrick Steinhardt’s nine-patch series refactoring how Git handles ODB alternates during repository creation. The goal is to simplify the ODB interface by removing the ability to write alternates after the repository is created, consolidating all alternates logic into the ODB creation phase. This change is part of the ongoing ODB abstraction effort, which aims to make alternates an implementation detail of the ODB backend rather than a public API.

The series has evolved through three versions, with v3 introducing a key refactoring of `init_db()` into `create_repository()`, which now only creates the repository skeleton without setting up the refdb or ODB. This eliminates the need for skip flags and moves command-specific logic (like initialization messages) into the commands themselves. Patches 2-6 consolidate alternates handling into a single code path, fixing a latent bug in worktree alternates handling and ensuring all alternates logic flows through `collect_alternates()`. Patch 7 implements the core design change: alternates are now written during ODB creation using Git’s standard lockfile API, ensuring atomic writes and resolving earlier concerns about TOCTOU races and concurrent access. Patch 8 wires up the new interface, and the final patch (just posted) removes the now-unused `write_alternates()` infrastructure.

Key participants include Junio C Hamano, who raised security concerns in v1 about the alternates writing mechanism, prompting Patrick to adopt the lockfile API in v2. Toon Claes provided surface-level reviews in v1 and v2, with his earlier feedback focusing on minor code structure observations. Justin Tobler’s substantive reviews engaged with the series’ technical rationale and design implications, particularly around the growing complexity of `init_db()`’s skip flags and the ODB interface’s long-term flexibility. Patrick has addressed all substantive feedback, and the series is now complete and ready for integration, pending final review from ODB-focused contributors like Karthik Nayak.

The changes are internal and have no user-visible impact. The series touches repository creation, alternates handling, and the ODB abstraction, with updates to `builtin/clone.c`, `setup.c`, `odb/source-files.c`, and related files. Tests in `t/t5604-clone-reference.sh` verify the new behavior, including edge cases for cloning from worktrees and resolving relative alternates paths. The only unresolved question is Justin Tobler’s forward-looking architectural concern about whether user-facing options like `--shared` should be restricted to the "files" backend or left to the backend’s discretion—a discussion that may continue as the ODB abstraction effort progresses.
