This thread is about Patrick Steinhardt’s 9-patch series (`[PATCH v3 0/9]`) refactoring how Git handles object database (ODB) alternates during repository creation. The goal is to simplify the ODB interface by removing the ability to write alternates after repository creation, making alternates an implementation detail of the ODB backend. This is part of the ongoing ODB abstraction effort, which aims to give backends more control over their configuration.

The key change in v3 is the refactoring of `init_db()` into `create_repository()`, which now only creates the initial repository skeleton without setting up the reference or object databases. This eliminates the need for skip flags like `INIT_DB_SKIP_ODB` and moves command-specific logic (such as printing initialization messages) into the commands themselves, resulting in a cleaner and more straightforward interface. The series also consolidates alternates handling into `odb_source_create_on_disk()`, ensuring alternates are written atomically during ODB creation using Git’s lockfile API, which resolves TOCTOU race and concurrent access concerns raised in earlier versions.

The patches touch several files, including `builtin/clone.c` (refactoring reference handling and deferring ODB setup), `setup.c`/`setup.h` (splitting `init_db()` and updating `create_object_database()`), and various ODB source files (removing unused `write_alternates()` infrastructure). The series introduces new symbols like `create_repository()` and `collect_alternates()`, while removing the `write_alternates()` callback. No user-visible changes are introduced, but the series fixes a latent bug in worktree alternates handling and consolidates alternates logic into a single code path. Test coverage in `t/t5604-clone-reference.sh` has been updated to verify the new behavior, including edge cases for worktree clones and relative path resolution.

The series addresses feedback from v2, particularly around the lockfile API adoption and the refactoring of `init_db()`. Reviewers like Junio C Hamano and Toon Claes had previously raised concerns about the locking mechanism, which have been resolved by using Git’s standard lockfile API. Justin Tobler’s feedback on the growing complexity of `init_db()`’s interface has also been addressed by splitting the function into `create_repository()`. The series is now ready for review, with patches 1-2 introducing the `create_repository()` refactoring and patches 3-9 largely unchanged from v2 (except for minor typo fixes). The most significant discussion point may be the architectural shift in repository initialization, though Patrick’s approach seems reasonable and aligns with the goal of simplifying the interface. The series is expected to proceed to integration once the remaining ODB-focused contributors (e.g., Karthik Nayak) have reviewed it.
