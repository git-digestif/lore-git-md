This thread is about extending Git’s `git var` plumbing command to provide a unified, scriptable interface for querying Git’s identity (author/committer names, emails, dates) and signing configuration (resolved signing key). The patch series, now at its fifth iteration (v5), is authored by Andrew Pleeter and implements the design consensus reached in earlier discussions, replacing the earlier `git ident` proposal.

The v5 patch addresses all remaining mechanical and polish-level feedback from Junio C Hamano and Phillip Wood. Key improvements include aligning the signing key resolution logic with Git’s standard `get_signing_key()` function, adopting script-friendly error handling (printing empty records for unset variables instead of exiting), and finalizing the `-z` output format for multi-valued variables. The patch also simplifies the code structure, removes redundant checks, and updates the documentation and test suite. The series remains under active review and is not yet merged, though it is approaching readiness for integration.

The implementation touches `builtin/var.c`, `Documentation/git-var.adoc`, and the test suite (`t/t0007-git-var.sh`). It introduces seven new variables (`GIT_AUTHOR_NAME`, `GIT_AUTHOR_EMAIL`, `GIT_AUTHOR_DATE`, `GIT_COMMITTER_NAME`, `GIT_COMMITTER_EMAIL`, `GIT_COMMITTER_DATE`, and `GIT_SIGNING_KEY`) and enforces strict argument ordering (options before variable names). The `-z` mode now matches `git config -z` behavior, and multi-valued variables are handled with internal NUL delimiters. The patch maintains backwards compatibility with existing `git var` usage while providing a more robust and scriptable interface.

Junio and Phillip Wood have not yet reviewed v5, but the changes align with their prior feedback and the established design consensus. The series is now focused on final polish, with no major open questions remaining. Once reviewed, it is expected to graduate to Junio’s integration branches.
