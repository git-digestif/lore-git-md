This thread implements a long-discussed extension to `git var` to provide a unified, scriptable interface for Git’s identity and signing configuration, replacing the earlier `git ident` proposal. The series, now at **v9**, is fully reviewed and ready for maintainer integration. Authored by Andrew Pleeter, it extends `git var` to support `-z` output (NUL-terminated, machine-readable), multi-variable queries in a single invocation, and six new identity variables (`GIT_AUTHOR_NAME`, `GIT_AUTHOR_EMAIL`, `GIT_AUTHOR_DATE`, `GIT_COMMITTER_NAME`, `GIT_COMMITTER_EMAIL`, `GIT_COMMITTER_DATE`). The earlier `GIT_SIGNING_KEY` variable was dropped due to ambiguity across signing mechanisms (GPG/SSH/X.509).

The series is split into four patches: (1) a refactor to use `string_list` for multi-valued variables, (2) the `-z` output mode, (3) multi-variable support, and (4) the new identity variables. All high-weight technical feedback from Junio Hamano, Phillip Wood, Jeff King, and brian m. carlson has been addressed. Phillip’s final review of v9 noted only **surface-level test style** (e.g., replacing `test_env()` with simpler shell constructs) and test organization, which Andrew acknowledged but deemed insufficient for a re-roll. The series remains in Junio’s `seen` branch, awaiting his decision on whether to graduate it to `next` or request minor test cleanups first.

Key technical details include strict argument ordering (options before variable names), exit-code behavior (0 if any requested variable is set, omitting unset ones), and output formats aligned with `git config -z`. The implementation touches `builtin/var.c`, `Documentation/git-var.adoc`, and `t/t0007-git-var.sh`, with no new configuration options or on-disk format changes. Open questions—such as a trailing delimiter in `-z` mode or future handling of `GIT_SIGNING_KEY`—are non-blocking. The thread has reached consensus on the implementation, and the only remaining step is Junio’s review of v9.
