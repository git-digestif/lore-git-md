This thread is about extending Git’s `git var` plumbing command to provide a unified, scriptable interface for identity and signing configuration, replacing an earlier `git ident` proposal. The series, now at version 5, was authored by Andrew Pleeter and has been under review since its inception.

The patch aims to expose Git’s author/committer names, emails, dates, and signing keys through `git var`, supporting multiple variables in a single call and machine-readable output via `-z`. All prior mechanical and polish-level feedback from Junio C Hamano and Phillip Wood was addressed in v5, including alignment of the signing key resolution with `get_signing_key()`, script-friendly error handling, and a finalized `-z` output format. The series was considered ready for integration, pending final review.

However, Junio’s latest review raises three substantive concerns that block integration. First, the documentation for identity variables is too sparse, lacking the clarity provided for `GIT_SIGNING_KEY`. Second, the output format for multi-valued variables introduces a potential backward-incompatibility by adding an extra delimiter after the last value when querying multiple variables, which could break existing scripts. Third, the error handling in `ident_part()` is overly permissive, masking programming errors that should trigger `BUG()` instead. Junio also critiques the multi-valued variable implementation for silently skipping valid values if an empty string is present and suggests a more robust `string_list`-based approach. The review concludes that the patch is not yet ready for integration and requires further revision. The thread remains in active review, with no merge in sight.
