This thread is about Andrew Pleeter’s patch series extending `git var` to provide a unified, scriptable interface for Git’s identity and signing configuration. The series, now at v4, implements the design consensus reached earlier, replacing the `git ident` proposal with a solution that exposes author/committer details (name, email, date) and a resolved signing key (`GIT_SIGNING_KEY`) via the existing `git var` plumbing command. The patch supports multiple variable arguments, NUL-terminated output (`-z`), and maintains backwards compatibility while addressing prior feedback on usability, output format, and argument parsing.

Key participants include Junio C Hamano and Phillip Wood, who provided substantive reviews of v3, focusing on documentation clarity, code structure, and edge cases like `-z` output format ambiguity and flag handling. Andrew’s v4 revision addresses all these points: it adopts `parse_options()` to enforce strict flag/variable ordering, aligns `-z` output with `git config -z` (key\nvalue\0), renames `GIT_DEFAULT_KEY` to `GIT_SIGNING_KEY` (dropping the alias), and improves type safety with an `enum` for variable handling. The documentation has been reworded to clarify variable descriptions, and tests now cover `-z` output and multi-valued variables.

The patch is now in a final polish phase, with no fundamental objections remaining. Junio and Phillip have endorsed the changes, and the series is likely to be merged once minor mechanical improvements (e.g., shorter lines, clarifying comments) are addressed. It remains in Junio’s `seen` branch, awaiting integration. The only open questions are minor: whether to allow empty variable lists (deferred to Junio’s broader usability argument) and whether the signing key resolution logic (now independent of `commit.gpgsign`) is sufficiently documented. The patch touches `builtin/var.c`, `Documentation/git-var.adoc`, and `t/t0007-git-var.sh`, with no new configuration options or on-disk format changes.
