This thread is about Andrew Pleeter’s patch series extending `git var` to provide a unified, scriptable interface for Git’s identity and signing configuration. The series, now at its sixth iteration, implements the design consensus reached in earlier discussions, replacing the earlier `git ident` proposal. The core goal is to allow scripts and users to query Git’s identity (author/committer names, emails, dates) and signing key configuration in a predictable, machine-readable way, supporting both interactive use and scripting.

The patch has undergone extensive review, with Junio C Hamano and Phillip Wood providing high-weight feedback on prior versions. The v6 patch addressed all substantive concerns from Junio’s review of v5, including multi-valued variable handling, error behavior, and documentation clarity. However, Phillip’s recent review of v6 identified remaining edge cases in error handling, documentation, and test robustness, while Junio’s latest feedback focuses on documentation conciseness and output format consistency. The series remains in Junio’s `seen` branch, with no maintainer signaling readiness to graduate it to `next`.

Key technical details include the addition of new variables like `GIT_AUTHOR_NAME`, `GIT_SIGNING_KEY`, and support for multiple variable arguments and NUL-terminated output (via `-z`). The patch maintains backward compatibility with existing `git var` usage but introduces stricter argument ordering and error handling. Junio’s latest review suggests streamlining the documentation to avoid repetition and rethinking the output format for multi-valued variables to make parsing more intuitive for scripts. Andrew’s next steps will likely involve addressing these polish items, with the series expected to be ready for integration once these final adjustments are made. No fundamental design objections remain, and the focus is now on usability and robustness.
