This thread is about extending `git var` to provide a unified, scriptable interface for Git’s identity and signing configuration, replacing an earlier `git ident` proposal. Andrew Pleeter is the author, and the series is now in its fourth iteration (v4), addressing all substantive feedback from Junio C Hamano and Phillip Wood.

The patch adds new variables like `GIT_AUTHOR_NAME`, `GIT_SIGNING_KEY`, and others, supports multiple arguments and NUL-terminated output (`-z`), and maintains backward compatibility. It’s under active review and approaching readiness for integration, though it remains in Junio’s `seen` branch. The latest version aligns with prior design consensus, including strict argument ordering and output format improvements.

Phillip Wood’s recent review of v4 focuses on polish rather than design changes. He raises concerns about the signing key resolution logic, multi-valued variable handling in `-z` mode (e.g., how to parse output when values contain newlines), and error behavior for unset variables. He suggests two approaches for multi-valued variables in `-z` mode—either printing the variable name before each value or adding an extra NUL terminator—and proposes more forgiving error handling for scripts. The feedback is constructive and likely to be addressed in the next iteration, with no major objections or controversies remaining. Junio and Phillip are aligned on the design, and the series is on track for integration once these mechanical improvements are finalized.
