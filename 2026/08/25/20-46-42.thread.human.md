This thread is about Andrew Pleeter’s patch series extending `git var` to provide a unified, scriptable interface for Git’s identity and signing configuration. The series, now at v7, implements the design consensus from earlier discussions, replacing the abandoned `git ident` proposal.

Andrew has addressed all substantive feedback from Junio’s and Phillip Wood’s high-weight reviews of v6. The latest version streamlines documentation to avoid repetition, adds `BUG()` checks for robustness, simplifies multi-valued variable handling, and relaxes error handling to avoid non-zero exit codes for unset variables in multi-variable queries. The test suite now uses Git’s `nul_to_q` helper to prevent false failures in `-z` mode tests. The implementation is clean, using Git’s standard argument parsing and a table-driven approach for the new variables (`GIT_AUTHOR_NAME`, `GIT_AUTHOR_EMAIL`, `GIT_AUTHOR_DATE`, `GIT_COMMITTER_NAME`, `GIT_COMMITTER_EMAIL`, `GIT_COMMITTER_DATE`, and `GIT_SIGNING_KEY`). The `-z` output format aligns with `git config -z`, and multi-variable queries include an extra delimiter after multi-valued variables for clarity.

The patch touches `builtin/var.c`, `Documentation/git-var.adoc`, and `t/t0007-git-var.sh`, with no on-disk format changes or new configuration options. Junio’s concerns about documentation and output format ambiguity are fully resolved, and Phillip’s feedback on error handling and test robustness is addressed. The only remaining loose end is whether `GIT_SIGNING_KEY` alone is sufficient for callers to determine the signing mechanism (GPG/SSH/X.509), but this isn’t a blocker. The series is in `seen` and appears ready for `next` once Junio confirms the final polish meets his expectations. Key participants—Junio, Phillip Wood, Jeff King, and brian m. carlson—have all weighed in, with no fundamental objections remaining.
