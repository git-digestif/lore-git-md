This thread implements a long-discussed extension to `git var` that provides a unified, scriptable interface for Git’s identity and signing configuration, replacing the earlier `git ident` proposal. Andrew Pleeter’s v9 series is now complete and ready for maintainer review after addressing all substantive feedback from prior iterations.

The series adds six new identity variables (`GIT_AUTHOR_NAME`, `GIT_AUTHOR_EMAIL`, `GIT_AUTHOR_DATE`, `GIT_COMMITTER_NAME`, `GIT_COMMITTER_EMAIL`, `GIT_COMMITTER_DATE`) and introduces multi-variable support with `-z` output mode for machine-readable results. The controversial `GIT_SIGNING_KEY` variable was removed due to ambiguity across signing mechanisms, and exit-code behavior is now finalized: multi-variable queries exit 0 even if some variables are unset, omitting them from output. The implementation maintains backward compatibility while enforcing strict argument ordering (options before variable names) and includes comprehensive test coverage.

Phillip Wood’s final review confirms the series is technically complete, with only minor test organization suggestions that don’t warrant a re-roll. The patches touch `builtin/var.c`, documentation, and tests, with no new configuration options or on-disk format changes. All prior high-weight reviewers (Junio, Phillip, Jeff King, brian m. carlson) have had their concerns addressed, and the series now awaits Junio’s review for graduation to `next`. The only open question—a trailing delimiter in `-z` mode—is not a blocker. This is a well-scoped, thoroughly reviewed effort that fills a clear gap in Git’s scripting interface.
