Thread identity: Refactoring ODB alternates handling during repository creation. 9-patch series (`[PATCH v3 0/9]`) by Patrick Steinhardt, part of the ongoing ODB abstraction effort. Thread type: patch series.

Core problem or goal: Remove the ability to write ODB alternates after repository creation, simplifying the ODB interface. Currently, alternates can be added at any time via `odb_source_write_alternate()`, but Git only uses this during initial setup (e.g., `git clone --reference`). The series introduces a new option in `odb_source_create_on_disk()` to handle alternates at creation time, eliminating the need for a separate `write_alternates()` callback. This change prepares for alternates to become an implementation detail of the ODB backend, giving backends more control over their configuration. The v3 iteration significantly refactors `init_db()` into `create_repository()`, which now only creates the repository skeleton without setting up the refdb or ODB, eliminating the need for skip flags and moving command-specific logic (e.g., initialization messages) into the commands themselves.

Current status: Under review. The series is built on `2c3adbb2c4` (The 18th batch, 2026-08-24) with `ps/odb-eagerly-load-alternates` merged in. All 9 patches have been posted as v3, incorporating feedback from v2: the primary change is the refactoring of `init_db()` into `create_repository()` (patches 1-2), which simplifies the interface by removing skip flags and moving command-specific logic out of the core initialization function. Patches 3-9 are largely unchanged from v2, except for minor typo fixes. The series retains the lockfile API adoption for writing the `info/alternates` file (patch 6), resolving TOCTOU race and concurrent access concerns raised by Junio C Hamano and Toon Claes in v1. The refactoring in patches 1-2 addresses Justin Tobler’s forward-looking architectural concern about the growing complexity of `init_db()`’s skip flags by replacing them with a cleaner separation of concerns: `create_repository()` handles skeleton creation, while `create_object_database()` and `initialize_repository()` (a new helper) handle ODB and refdb setup, respectively. This design avoids the awkwardness of accumulating skip flags and better reflects the narrowed scope of repository initialization in `git clone`.

Key technical details:

Patch 8 removes the unused `write_alternates()` infrastructure, which is now redundant due to the lockfile API adoption in patch 6.
