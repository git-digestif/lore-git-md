Thread identity: Refactoring ODB alternates handling during repository creation. 9-patch series (`[PATCH v3 0/9]`) by Patrick Steinhardt, part of the ongoing ODB abstraction effort. Thread type: patch series.

Core problem or goal: Remove the ability to write ODB alternates after repository creation, simplifying the ODB interface. Currently, alternates can be added at any time via `odb_source_write_alternate()`, but Git only uses this during initial setup (e.g., `git clone --reference`). The series introduces a new option in `odb_source_create_on_disk()` to handle alternates at creation time, eliminating the need for a separate `write_alternates()` callback. This change prepares for alternates to become an implementation detail of the ODB backend, giving backends more control over their configuration. The v3 iteration refactors `init_db()` into `create_repository()`, which now only creates the repository skeleton without setting up the refdb or ODB, eliminating the need for skip flags and moving command-specific logic (e.g., initialization messages) into the commands themselves. Patch 2 defers ODB initialization in `git clone` until after the clone source URI is resolved, addressing two key issues: forward compatibility with alternate ODB backends (which may require object hash information at creation time) and the need to resolve alternates paths before ODB setup. Patch 4/9 (updated) renames `setup_reference()` to `collect_alternates()` and refactors it to gather alternates paths into a `strvec` instead of immediately writing them to the ODB, preparing for later patches that consolidate alternates setup into `create_object_database()`. Patch 5/9 extends `collect_alternates()` to handle shared local clones (`git clone --shared`), consolidating all alternates logic into a single code path by moving the manual alternates setup from `clone_local()` into `collect_alternates()` and adding `src_repo` and `is_local` parameters to support this. Patch 6/9 (new email) completes the consolidation by moving the setup of alternates for non-shared local clones (`git clone --local --no-shared`) into `collect_alternates()`, fixing a latent bug where cloning from a worktree failed to resolve the source repository’s common directory. The patch reuses the already-resolved common directory path from `collect_alternates()` to handle this case correctly, and two new tests in `t/t5604-clone-reference.sh` verify the fix for cloning from a linked worktree and resolving relative alternates paths.
