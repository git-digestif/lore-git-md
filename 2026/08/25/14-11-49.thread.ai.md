Thread identity: Refactoring ODB alternates handling during repository creation. 9-patch series (`[PATCH v4 0/9]`) by Patrick Steinhardt, part of the ongoing ODB abstraction effort. Thread type: patch series.

Core problem or goal: Remove the ability to write ODB alternates after repository creation, simplifying the ODB interface. Currently, alternates can be added at any time via `odb_source_write_alternate()`, but Git only uses this during initial setup (e.g., `git clone --reference`). The series introduces a new option in `odb_source_create_on_disk()` to handle alternates at creation time, eliminating the need for a separate `write_alternates()` callback. This change prepares for alternates to become an implementation detail of the ODB backend, giving backends more control over their configuration. The v4 iteration adds documentation for the new repository creation functions (`create_repository()`, `create_reference_database()`, and `create_object_database()`) and clarifies the `reinit_ok` parameter, addressing Justin Tobler’s feedback from v3. The refactoring of `init_db()` into `create_repository()` (introduced in v3) continues to simplify the interface by removing skip flags and moving command-specific logic (e.g., initialization messages) into the commands themselves.

Patch 6/9 completes the consolidation of alternates logic by moving the setup of alternates for non-shared local clones (`git clone --local --no-shared`) into `collect_alternates()`. The patch fixes a latent bug in worktree alternates handling: previously, Git failed to resolve the common directory of the referenced repository when cloning from a worktree, causing alternates setup to break. The patch reuses the resolved common directory path from `collect_alternates()` (already computed for shared clones) to handle non-shared local clones, ensuring alternates are correctly resolved for worktrees. The `copy_alternates()` function is renamed to `read_alternates()` and refactored to gather alternates paths into a `strvec` instead of immediately writing them to the ODB, aligning with the series’ goal of deferring alternates writes until ODB creation. The feedback is purely observational and unlikely to require changes.

Patch 7/9 implements the core design change: alternates are now written during ODB creation via `odb_create_on_disk_options` using Git's standard lockfile API, ensuring atomic writes and resolving TOCTOU race and concurrent access concerns raised by Junio C Hamano in v1. The patch adds support for writing alternates to the "files" backend via the new `odb_create_on_disk_options` struct, which carries a `strvec` of alternates paths. The implementation reads any preexisting alternates (e.g., from templates), deduplicates them with the new entries using a `strset`, and writes the combined set atomically using `commit_lock_file()`. The ODB is then reprepared to activate the new alternates. Error handling is thorough, with rollback on failure and proper cleanup of resources. The patch touches `odb/source-files.c` (adding the alternates-writing logic), `odb/source.h` (introducing `odb_create_on_disk_options` and updating the `create_on_disk` callback signature), and `setup.c` (updating `create_object_database()` to pass the alternates `strvec` via the options struct). The lockfile adoption resolves the primary security concern from v1 and is uncontroversial. **Karthik Nayak’s substantive review of this patch in v4 raises two technical concerns about error handling and a forward-looking question about backend error reporting.** The review identifies a robustness issue: the code checks for `ferror()` only *after* writing all alternates, rather than after each `fprintf()` call. This could leave the alternates file in a partially written state if an error occurs mid-write, though the lockfile mechanism would prevent corruption. Karthik suggests checking `ferror()` inside the loop to fail fast and avoid writing partial data. The current implementation’s single check at the end is less precise but still safe due to the lockfile rollback. Karthik also asks whether backends should formalize error codes to distinguish "alternates not supported" from other failures, probing the ODB interface’s clarity and extensibility. The current design leaves backend-specific behavior (like alternates support) undocumented, which could lead to inconsistent error handling across backends. While not urgent, this feedback may influence future ODB abstraction work. The review is narrowly scoped to patch 7/9 and does not engage with the broader series goals or the lockfile adoption’s security implications. It is substantive but unlikely to require major changes—just tighter error handling and potential documentation improvements.

Patch 8/9 wires up the alternates `strvec` collected by `collect_alternates()` to the ODB creation process via the new `odb_create_on_disk_options` struct, eliminating the manual alternates loop in `cmd_clone()` and preparing for the removal of the `write_alternates()` callback in patch 9. The change is mechanical: `create_object_database()` now accepts a `strvec` of alternates paths (or `NULL` for no alternates, preserving existing behavior in `cmd_init_db()`), and `cmd_clone()` passes the alternates `strvec` directly to `create_object_database()` instead of manually writing each alternate via `odb_add_to_alternates_file()`. The patch touches `builtin/clone.c` (removing the manual alternates loop), `builtin/init-db.c` (updating `cmd_init_db()` to pass `NULL` for alternates), `setup.c` (extending `create_object_database()` to accept the alternates `strvec` via `odb_create_on_disk_options`), and `setup.h` (updating the function signature and documentation). No new symbols are introduced, and the patch preserves existing behavior while simplifying the code. This patch is a direct follow-up to patch 7/9 and is uncontroversial.

Patch 9/9 removes the `write_alternate` callback and its supporting infrastructure across all ODB backends, completing the series. The patch deletes 117 lines across seven files: `odb.c` (removing `odb_add_to_alternates_file()`), `odb.h` (removing the function declaration), `odb/source-files.c` (removing the "files" backend’s `write_alternate` implementation and its lockfile logic), and the "inmemory", "loose", and "packed" backends (removing their stub `write_alternate` implementations). The `write_alternate` field is also removed from the `odb_source` struct in `odb/source.h`, along with its inline helper function. This is a mechanical cleanup patch with no behavior changes. All alternates logic has already been moved into the ODB creation process in earlier patches (notably patch 7’s lockfile-based atomic writes and patch 8’s wiring of the alternates `strvec` to `create_object_database()`). The removal of `odb_add_to_alternates_file()` and its backend-specific implementations is uncontroversial, as the function has no remaining callers in the codebase. The patch aligns with the series’ design goal of making alternates an ODB backend implementation detail, simplifying the interface by eliminating the ability to write alternates after repository creation.
