# Thread deltas

## 2026/08/25

- [2026/08/25/08-55-16 by Nikita Leshenko <nikita@island.io>] Nikita Leshenko submitted a patch to make `git am --3way` record postimage blobs of cleanly applied patches by running `git apply --build-fake-ancestor` and an extra apply per clean patch, so that a later patch whose preimage is that postimage can be 3-way merged instead of failing with "could not build fake ancestor".
- [2026/08/25/17-14-34 by Junio C Hamano <gitster@pobox.com>] Junio C Hamano rejected the eager per-patch overhead (extra subprocesses, temporary index files, loose objects, and index load/unload for every clean patch in a series) and proposed instead reconstructing the missing preimage lazily inside `fall_back_threeway()` only when `build_fake_ancestor()` fails, by applying earlier patches in-core until the needed blob is produced.
- [2026/08/25/20-26-42 by Nikita Leshenko <nikita@island.io>] Nikita Leshenko agreed the eager approach was unacceptable but argued that Junio's surgical lazy reconstruction would require elaborate scanning logic for multiple missing blobs; he proposed a simpler lazy alternative that, when `build_fake_ancestor()` fails, applies all previous patches 1..(N-1) on their fake ancestors to build the missing blobs, records a "postimage-attempted" marker in `.git/rebase-apply` to avoid repeating work for later patches, and optionally bumps that marker when a patch succeeds on its fake ancestor.
