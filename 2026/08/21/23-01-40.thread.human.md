This thread is about a two-patch bugfix series from Volodymyr Vriukalo that fixes a crash and incorrect error handling in Git’s experimental `submodule.propagateBranches` feature. The issue occurs when `git branch --recurse-submodules` is used with a non-ref start point (like a raw object ID). In repositories without submodules, Git aborts with a BUG after partially completing the operation, while in repositories with submodules, the command fails earlier due to a truncated argument list passed to a helper.

The series has been under review for three days with no feedback. Junio Hamano, the maintainer, has nudged the list, noting that unless reviewers step up soon, he will drop the topic from his integration branches (`seen` is already crowded with neglected patches). The patches touch `branch.c` and `builtin/submodule--helper.c`, and add tests to `t/t3207-branch-submodule.sh`. They address the root cause—a missing tracking name when the start point isn’t a ref—by adding a guard in `create_branches_recursively()` and making the tracking name argument optional in the submodule helper. No technical objections have been raised, but there are minor open questions about test placement and whether to extend the fix to a similar unguarded call elsewhere. The series is based on `maint` and merges cleanly into `next` and `seen`.
