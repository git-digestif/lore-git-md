This thread is fixing a crash and error-handling bug in Git’s experimental `submodule.propagateBranches` feature when `git branch --recurse-submodules` is used with a non-ref start point (like a raw object ID). Volodymyr Vriukalo’s two-patch series addresses two scenarios: a BUG abort in repositories without submodules (leaving the operation partially completed) and an early failure in repositories with submodules due to a truncated argument list.

The series is under review, with Junio C Hamano queuing it in `seen` as `vv/branch-recurse-no-start-ref` but signaling intent to drop it unless reviewers step up. D. Ben Knoble recently provided a substantive review of the first patch, focusing on test clarity and commit message improvements. He confirmed the bug is reproducible and suggested simplifying the test case to directly create a branch at a non-ref start point (e.g., `git branch t @~3`), making the test shorter and more direct. Knoble’s feedback doesn’t challenge the fix itself but aims to improve its presentation. The series remains open for further review, with no maintainer intent expressed regarding graduation to `next` or `master`.
