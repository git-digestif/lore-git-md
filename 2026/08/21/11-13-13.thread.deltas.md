# Thread deltas

## 2026/08/21

- [2026/08/21/11-13-13 by Anselm Schüler <mail@anselmschueler.com>] Anselm Schüler questioned the purpose of `--ext-diff`, suggesting custom diff filters should always be executed, asking whether it is a security feature (noting that `git-diff` executes diff filters anyway), and asking what situation would require a diff filter to run under `git-diff` but not `git-show`.

## 2026/08/24

- [2026/08/24/18-23-02 by Jeff King <peff@peff.net>] Jeff King explained that an external diff can perform arbitrary actions such as opening GUI windows, making it surprising if git-log opened dozens of windows while walking history, and noted that git-show likely inherited the default to disallow external diffs because it is implemented as "git log --no-walk", though there is an argument it should use the same default as git-diff since both show about one commit's worth of diffs.
- [2026/08/24/18-23-02 by Jeff King <peff@peff.net>] Jeff King suggested that textconv is often a better experience than --ext-diff because, while less flexible in requiring binary-to-text transformation, it fits more neatly into existing commands, adding that he may be biased as textconv's author.
- [2026/08/24/20-25-36 by Junio C Hamano <gitster@pobox.com>] Junio C Hamano agreed with Jeff King, and as the author of ext-diff stated that the only use he finds for a custom --ext-diff program is the daily maintenance of "What's cooking" report drafts, though he suspects even that could be substituted with creative use of the textconv filter, diff hunk header patterns, and the -W option.
