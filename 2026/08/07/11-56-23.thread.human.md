**Human-readable summary**

This thread tracks a now-completed patch series that lets users toggle nanosecond precision at runtime via `core.useNanosec` instead of recompiling Git. The series, originally posted by D. Ben Knoble, has graduated to Junio’s `next` branch (integration testing) and is effectively finished.

The core change replaces the build-time `USE_NSEC` macro with a new config key that defaults to off. On filesystems that support nanosecond timestamps, users can now flip the switch without rebuilding, reducing “racy Git” false positives. Performance concerns raised in early versions were resolved by caching the config value, and backward compatibility is preserved: platforms lacking nanosecond support simply ignore the setting.

Two minor follow-ups were handled in the final version: a typo fix in the documentation (“comparisions” → “comparisons”) and a decision to retain the `#ifndef NO_NSEC` guard in the config handler. Jeff King (Peff) flagged a theoretical edge case—mixed builds on the same system could misinterpret timestamps—but the risk is low and no further changes were deemed necessary. The only remaining loose end is a latent bug in `is_racy_stat()` when operating on repositories other than `the_repository`; this is documented as a forward-looking constraint but does not block graduation. A routine textual conflict with another topic (`ty/repo-config-cleanups`) will be resolved if both advance.

The series touches a dozen files, including the Meson build system, core config documentation, and the racy-check logic. The first two patches—a build-system fix and a no-op refactor—are uncontroversial and could graduate independently. No further iterations are planned; the topic is now in a holding period awaiting final integration.
