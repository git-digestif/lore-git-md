This thread is about Harald Nordgren’s `git history squash` feature, which collapses a range of commits into a single commit while preserving descendant history. The series is now on its fifteenth iteration and is technically complete, addressing all prior feedback including strict autosquash marker resolution, shape-based validation, and protection for local branches that would be left dangling.

Harald has implemented the core logic in the latest patch (7/8), which adds the `--no-edit` workflow. This allows users to squash a range without opening an editor, handling autosquash markers (`fixup!`, `squash!`, `amend!`), preserving authorship and merge parents, and replaying descendants. The patch enforces strict case-sensitive matching for autosquash markers, rejecting uppercase OIDs, and incorporates `amend!` messages targeting the oldest commit into the squashed commit message. The test suite has been expanded to cover autosquash sequences, merge handling, ref protection, and edge cases like `--dry-run` and reflog accuracy.

Junio C Hamano has signaled intent to queue the series with a "Will replace" note in version 7, and all substantive review feedback has been addressed. The series is now cooking in Junio’s `seen` branch and is likely to graduate to `next` in the next "What’s cooking" report. The only remaining work is the `--edit` path, which will open an editor with an autosquash-style template, but this does not block integration. The feature is designed to complement `git rebase --autosquash` while enforcing stricter validation and ref protection.
