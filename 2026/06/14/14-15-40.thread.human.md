This thread is about fixing a memory leak in `git history reword`, part of Patrick Steinhardt’s `git history` command work, which revealed broader slab management gaps in Git. The original leak occurred because commits loaded from the commit-graph bypass raw object parsing, leaving dynamically allocated commit buffers uncached in Git’s slab system and thus unfreed. A v2 patch from Kaartic Sivaraam, now merge-ready, adds a single line in `builtin/history.c` to explicitly free the buffer using `repo_unuse_commit_buffer`. Junio C Hamano’s recent reply confirms the patch is ready for integration, with only minor editorial feedback on commit message formatting.

The fix resolves not only the `git history reword` leak but also related test failures (`t345x`), while a separate patch already addressed a distinct leak in the topological walk slab (`init_topo_walk`). The commit message is unusually thorough, including an ASAN leak report, root-cause analysis, and a minimal reproduction recipe (`SANITIZE=leak GIT_TEST_COMMIT_GRAPH=1 make test`). No technical objections or regressions remain, though there’s an open but tangential question about whether Git’s test suite should continue suppressing leak detection by default. The thread also highlights systemic slab management gaps, particularly around commit-graph interactions, though the current fixes are narrowly targeted.
