This thread is about a proposed feature to improve `git worktree` with two main enhancements: copy-on-write (reflink) worktree creation and automatic reaping of ephemeral branches. The series, now at version 3, is authored by Jason Newton and consists of four patches. The reflink feature is designed to speed up worktree creation on supported filesystems (Linux btrfs/XFS/bcachefs, macOS APFS) by avoiding full checkouts, but it remains controversial—particularly whether it should be opt-in or default for tracked files. Windows ReFS reflink support has been permanently disabled due to a known silent corruption bug, and the feature now emits a warning on Windows when enabled.

The second enhancement, ephemeral branch reaping, automatically deletes branches created by `git worktree add` when the worktree is removed. This is intended to address a long-standing cleanup nuisance, but it has faced strong opposition from Eric Sunshine, who argues it is redundant given the existing `--detach` flag and risks disrupting workflows. Jason maintains that ephemeral branches provide a more intuitive experience by preserving branch semantics during the worktree's lifetime, avoiding the "degraded halfway state" of detached HEADs. The reaping mechanism is narrowly scoped to auto-created branches and does not affect explicitly named branches or detached HEADs.

The thread has seen active debate, with Eric Sunshine raising substantive objections to both features. His latest email, however, shifts focus to a procedural concern: he criticizes Jason for relying on an AI-generated response to address review feedback rather than providing a direct, human-written explanation. While this doesn’t revisit the technical arguments, it signals frustration with the quality of engagement and could slow progress by making reviewers hesitant to invest time in a proposal that feels under-explained. The series remains under review, with key questions unresolved—particularly whether reflink should default to automatic for tracked files and whether ephemeral branch reaping should be opt-in or removed entirely.
