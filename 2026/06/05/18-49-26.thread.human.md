This thread proposes two worktree improvements by Jason Newton: copy-on-write (CoW) worktree creation via `--reflink` and automatic reaping of ephemeral branches. The series is now at v3 with four patches, though both features remain contentious.

The reflink support, which avoids full checkout overhead on supported filesystems (Linux btrfs/XFS/bcachefs, macOS APFS), is now permanently disabled on Windows ReFS due to a silent corruption bug (Git LFS #6312). While macOS clonefile() support is validated in CI, the reflink implementation is still disputed—Eric Sunshine argues it should default to automatic for tracked files rather than requiring opt-in via `--reflink` or config, as the untracked-file copying concern doesn’t apply there. Jason maintains the opt-in design is justified.

The ephemeral branch reaping feature, which automatically deletes auto-created branches when their worktree is removed, is also under fire. Eric Sunshine calls it redundant (since `--detach` already exists) and disruptive to workflows that rely on auto-created branches. Jason’s v3 patch adds `--keep-branch` to preserve branches during removal but doesn’t make reaping opt-in, leaving the debate unresolved. The feature remains unconditional, even for unmerged commits, as ephemeral branches are considered disposable by design.

The series is under active review, with no maintainer decision yet on whether either feature will be merged. Key open questions include whether reflink should default to automatic for tracked files and whether ephemeral branch reaping should be opt-in or scrapped entirely.
