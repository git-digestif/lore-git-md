This thread is about a two-part feature proposal from Jason Newton to improve `git worktree`: copy-on-write (CoW) worktree creation via `--reflink`, and automatic cleanup of ephemeral branches. The series is now at v2, having dropped a controversial shared-branch capability from v1.

The first patch adds `--reflink` support for CoW worktree creation on supported filesystems (btrfs, XFS, APFS, ReFS), avoiding full checkout overhead. This faces platform-specific concerns: Windows ReFS reflink is disabled in the next revision due to a silent corruption bug, and macOS’s `clonefile()` path needs CI validation. The second patch introduces automatic reaping of ephemeral branches created by `git worktree add`, addressing a long-standing cleanup nuisance. This part is now contested by Eric Sunshine, who argues the feature is unnecessary and disruptive, as `--detach` already serves the use case of throwaway worktrees. Eric’s review questions the motivation and highlights the unconditional nature of the branch reaping as a design flaw, suggesting it should be opt-in or scrapped entirely.

Key participants include Jason Newton (author), brian m. carlson (who raised concerns about Windows ReFS corruption and macOS CI testability), and Junio C Hamano (who questioned the opt-in CoW design). The reflink implementation is now cross-platform but faces maintenance challenges due to the Windows ReFS bug. The ephemeral branch reaping, while uncontested in v1, is now under scrutiny, with Eric’s feedback potentially leading to its rejection unless Jason can justify its advantages over `--detach`. The next steps will likely focus on whether the reaping feature can be redesigned to be less intrusive or if it should be abandoned.
