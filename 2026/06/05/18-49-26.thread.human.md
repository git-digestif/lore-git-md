This thread is about a proposed improvement to `git worktree` that adds two new features: copy-on-write (CoW) worktree creation and automatic cleanup of ephemeral branches. The original v1 proposal included a more ambitious (and controversial) shared-branch capability, but after feedback from Junio C Hamano and brian m. carlson, author Jason Newton has refocused the series on narrower, more immediately actionable changes.

The v2 series introduces `--reflink` support for `git worktree add`, allowing worktrees to be created using filesystem-level CoW on supported platforms (btrfs/Linux, APFS/macOS, ReFS/Windows). This avoids the overhead of a full checkout when the source and destination are on the same filesystem. The implementation is opt-in (via `worktree.reflink` config) rather than automatic, a deliberate choice to avoid silently copying untracked files from the source worktree. The series also adds automatic reaping of ephemeral branches—those auto-created by `git worktree add`—when the worktree is removed, addressing a long-standing cleanup annoyance.

Jason has addressed the v1 feedback thoroughly: the reflink implementation is now cross-platform (including Windows ReFS via Git LFS’s approach), handles edge cases like dirty worktrees and cluster alignment, and includes detailed documentation of safe usage patterns. The shared-branch capability, which raised safety concerns about concurrent commits, has been dropped entirely. Junio and brian’s concerns about opt-in vs. automatic CoW and the risks of shared branches are now moot for this version, though the opt-in nature of reflink may still spark discussion. The series is well-scoped, technically solid, and likely to be uncontroversial in its current form.
