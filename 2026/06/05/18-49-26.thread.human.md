This thread proposes two focused improvements to `git worktree`, now at version 2 after dropping a controversial shared-branch feature from the initial proposal. The first patch adds `--reflink` support for copy-on-write worktree creation on supported filesystems (btrfs, XFS, APFS, ReFS), reducing checkout overhead while handling edge cases like dirty worktrees and untracked files. The second patch, just posted, introduces automatic reaping of ephemeral branches—those auto-created by `git worktree add`—when the worktree is removed, solving a long-standing cleanup annoyance.

Jason Newton has refined the series in response to feedback, removing the shared-branch capability entirely and making the reflink feature opt-in via `worktree.reflink` (defaulting to "auto"). The reflink implementation is cross-platform, using Linux’s FICLONE, macOS’s clonefile(), and Windows’s FSCTL_DUPLICATE_EXTENTS_TO_FILE, with careful handling of edge cases like overlayfs (disabled) and cluster alignment. The ephemeral branch reaping is narrowly scoped: only branches created by DWIM auto-naming are marked as ephemeral and reaped, while explicitly named or pre-existing branches are preserved. A `--keep-branch` option allows opting out of reaping if needed.

The series is under active review, with no major objections raised so far. Junio questioned the opt-in nature of reflink in the first version, but the current approach remains configurable. The ephemeral branch reaping is likely to be merged as-is, though there may be minor discussion about whether `--keep-branch` should be the default or if the feature should be configurable. The implementation is backward-compatible, and the design choices—such as unconditional deletion of ephemeral branches—are well-justified in the documentation. The patches include thorough test coverage and clear documentation updates, making them ready for integration.
