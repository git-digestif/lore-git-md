Core problem or goal
Extend `git log -L` (line-log) to support range-scoped diff stat formats (`--stat`, `--numstat`, `--shortstat`), whitespace checking (`--check`), and the `-G` pickaxe. The goal is to make these common diff options work consistently with the line-range filter, so that only changes or errors within the tracked line ranges are reported.

Behavior changes:
- Patch 2 fixes a bug where deletions just outside the tracked range could leak into patch output by removing the `pending_rm` buffer and classifying removal lines immediately based on the post-image position of the following line. The symmetric leading-deletion case (removals just before the tracked range) is now correctly included if the following line is in-range. The fix defers calculation of old and new line counts for the hunk header until flush time, reducing state management complexity.
- Patch 3 ensures hunk headers emitted by `git log -L` match `git diff` exactly, including edge cases like pure insertions (`@@ -5,0 +6,3 @@`) and deletions (`@@ -5,3 +5,0 @@`). The new `xdiff_emit_hunk_header()` helper guarantees consistency by delegating to xdiff’s native `xdl_emit_hunk_hdr()`. The off-by-one correction ensures the begin line is the line *before* the change (for zero-line sides), and a count of 1 is omitted. Test fixtures are updated to reflect the corrected headers.
- Patch 4 centralizes line-range filter boilerplate without changing behavior. The helpers enforce invariants (one xdiff hunk per range, hunk headers always emitted) and handle `ctxlen` inflation, flag clearing, diff execution, and buffer cleanup.
- Patch 5 enables `--stat`, `--numstat`, and `--shortstat` to honor tracked line ranges by routing the line-range filter’s output through `diffstat_consume()`. The stat counters now reflect only in-range lines, and the documentation clarifies the exclusion of `--dirstat` (its default mode measures whole-file churn, making range-scoped counting misleading).
- Patch 6 enables `--check` to honor tracked line ranges by wrapping `checkdiff_consume()` with the line-range filter. The implementation adds an optional `orig_hunk_fn` callback to `line_range_filter` to route `checkdiff_consume_hunk()`, ensuring accurate file line numbers (counting from the start of the file rather than the range hunk). The trailing blank-at-eof check is gated on the tracked ranges, preventing false positives when the blank line lies outside the range. Documentation is updated to list `--check` among the supported formats.
- Patch 7 enables `-G` to honor tracked line ranges by exposing `diff_emit_line_ranges()` to wrap `xdi_diff_outf()`, forwarding only in-range lines to the caller’s callback. `-G` now scopes to ranges, but skips textconv (driver output lacks original line coordinates), falling back to whole-file search when a textconv driver is active. `-S` is explicitly excluded due to architectural constraints (whole-file search is inherent to its design).
