This thread is about a patch series by Paulius Zaleckas that adds a configurable error-handling mode for `git fetch --recurse-submodules`. The series, now at version 6, lets users choose whether submodule fetch errors should fail hard (the default, preserving backwards compatibility) or merely warn, which is useful when upstream topic branches are still in flux. It also fixes a pre-existing logic flaw where submodule fetch failures were recorded prematurely.

The series is technically complete, with all review feedback addressed, including Junio Hamano’s latest mechanical requests. It touches `submodule.c`, `builtin/fetch.c`, and related documentation and test files, introducing a new config key (`fetch.submoduleErrors`) and CLI option (`--submodule-errors`). The implementation centralizes error handling and ensures consistent error reporting, with test coverage for the new behavior and edge cases.
