Core problem or goal
Allow users to configure whether `git fetch --recurse-submodules` should fail hard or merely warn when a submodule’s gitlink points to an OID that is not reachable from the submodule’s remote. The default (`fail`) preserves backwards compatibility; the new `warn` mode enables workflows where upstream topic branches are still in flux without disrupting the entire fetch. The series also fixes a pre-existing logic flaw in submodule fetch error handling where phase-1 fetch failures were recorded prematurely, even when a subsequent phase-2 OID-based fetch could still succeed.

Key technical details
- Files touched: `submodule.c`, `submodule.h`, `builtin/fetch.c`, `Documentation/config/fetch.txt`, `Documentation/fetch-options.txt`, `t/t5526-fetch-submodules.sh`
- New config key: `fetch.submoduleErrors` (values: `fail`, `warn`; case-sensitive, parsed with `strcmp`)
- New CLI option: `--submodule-errors=(fail|warn)`
- New behavior: when set to `warn`, submodule fetch errors are reported but do not abort the parent fetch
- Forwarding: the resolved value (whether from CLI or config) is propagated to child fetches (`--all`, `--multiple`, nested recursion) when explicitly set, preserving user intent. The setting is explicitly forwarded to per-remote child processes to override any repository config.
- Error routing: all submodule fetch errors flow through `record_fetch_error()`, which defers error recording until all fetch phases (refs and OID-based retry) have failed, fixing a logic flaw where phase-1 failures could abort the fetch prematurely. The helper also ensures errors are consistently reported with the submodule name in the final summary. The patch restructures `fetch_finish()` to defer error recording until all retry attempts are exhausted, ensuring the overall fetch result accurately reflects whether the required commits were ultimately obtained.
- Implementation improvements: config value parsing and option formatting are now centralized in a shared name array (`submodule_error_name`), eliminating redundant conditional branches and aligning CLI/config logic. `strcasecmp()` replaced with `strcmp` for case-sensitive matching. Array indexing type changed from `size_t` to `unsigned` and array renamed to singular form (`submodule_error_name[]`) per Junio’s feedback.
- Test coverage: new tests for warn mode, error reporting, CLI override propagation, and edge cases, including tests verifying that a failed submodule fetch is still reported even when the gitlinked commits are present locally, and that the setting is forwarded correctly with `--all`. The test suite also covers the pre-existing logic flaw fix, ensuring phase-1 failures are only recorded after all retry attempts fail. Test hygiene: raw `grep` replaced with `test_grep` for portability.
