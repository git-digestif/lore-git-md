Thread identity: Patch series replacing the `GIT_NO_LAZY_FETCH=fromAccepted` proposal with `uploadpack.lazyFetchTrusted`, a server-side protected configuration variable to mark repositories as trusted for lazy fetching. Series version: v3 (v4 pending for 5/5). Originating author: Christian Couder.

Core problem or goal: Provide a server-side mechanism for operators to explicitly declare which repositories are safe to lazy-fetch from, addressing the security objection that untrusted repositories could trigger arbitrary code execution via lazy-fetch hooks or configuration. The new approach shifts trust decisions entirely to the server operator, modeled after Git’s `safe.directory` configuration, and replaces the earlier client-side `fromAccepted` proposal.

Current status: Under review, with all v2 concerns addressed. Junio suggests checking the environment first and only setting `GIT_NO_LAZY_FETCH` if it isn’t already set by the operator, preserving operator control. This change is expected in v4. - New or modified symbols: `lazy_fetch_objects()` (new helper in 1/5 consolidating lazy-fetching logic, modified in 4/5 to check recursion depth and simplified in v3 to use a single `return` statement with logical OR), `try_promisor_remotes()` (converted from `int` to `bool` in 1/5; documentation and parameter semantics now under review for clarity), `path_allowlist_apply()` and `path_allowlist_config_apply()` (new generic helpers in 2/5 for path validation, now flagged for silent-ignoring behavior on non-existent paths), `allow_safe_dir()` (new callback in 2/5 for `safe.directory` rules), `allow_trusted_path()` (new callback in 3/5 for `uploadpack.lazyFetchTrusted` validation, enforcing stricter path requirements than `safe.directory`), `upload_pack_lazy_fetch_trusted()` (new function in 3/5 to check configuration), `fetch_objects()` (modified in 4/5 to pass recursion depth to child processes). The `GIT_INTERNAL_LAZY_FETCH_DEPTH` environment variable (introduced in 4/5) limits recursion depth to `MAX_LAZY_FETCH_DEPTH` (5), chosen to balance safety and legitimate nesting (e.g., `git fetch` invoking `index-pack` to lazily fetch REF_DELTA bases). Junio’s review of 4/5 suggests changing the depth counter’s type from `unsigned long` to `int`. The final patch (5/5) activates the mechanism by setting `GIT_NO_LAZY_FETCH=0` in `builtin/upload-pack.c` when serving a trusted repository, but the environment-handling logic is now under review for a v4 tweak to preserve operator control.
- New behavior: `uploadpack.lazyFetchTrusted` (protected configuration variable) allows server operators to mark repositories as trusted for lazy fetching, with recursion safeguards preventing infinite loops when a repository is configured as its own promisor remote. The configuration is read from protected files only, and only absolute paths are accepted (rejecting `.` and relative paths). Non-bare repositories must be allowlisted by their `.git` directory (e.g., `/srv/repo/.git` for `/srv/repo`). The callback-based allowlist design enables caller-specific validation rules: `uploadpack.lazyFetchTrusted` requires absolute paths, while `safe.directory` retains its existing behavior. Documentation now explicitly states that the configuration is multi-valued, specifies repository paths as git directories, warns against self-referential promisor remotes, and supports `~` and `%(prefix)` expansions. Tests verify recursion limits, path validation, and the server-side trust model’s security properties.
