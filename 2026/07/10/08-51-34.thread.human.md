This thread is about a patch series (v5) by Christian Couder that replaces an earlier client-side proposal (`GIT_NO_LAZY_FETCH=fromAccepted`) with a server-side configuration variable, `uploadpack.lazyFetchTrusted`. The goal is to let server operators explicitly mark repositories as safe for lazy fetching, addressing security concerns about untrusted repositories triggering arbitrary code execution via hooks or configuration.

The series is now fully reviewed, with all feedback from Junio—including his final surface-level documentation tweaks—addressed in v5. No substantive objections remain, and the code is rebased on Git 2.56 with passing CI tests. The mechanism is activated by conditionally setting `GIT_NO_LAZY_FETCH=1` only for untrusted repositories, preserving operator control. Key technical details include recursion safeguards (depth limit of 5), strict path validation, and non-propagation of trust to promisor remotes. The series also refactors existing code to reduce duplication and improve clarity, though these changes are behaviorally equivalent.

Christian has flagged a latent design issue in Git’s `safe.directory` mechanism (silent ignoring of non-existent paths) for future work, but this doesn’t block the current series. The thread is now effectively closed, with the series awaiting Junio’s decision on integration.
