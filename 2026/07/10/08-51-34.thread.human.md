This thread is about a five-patch series by Christian Couder that introduces `uploadpack.lazyFetchTrusted`, a server-side configuration variable allowing operators to mark repositories as trusted for lazy fetching. The goal is to address security concerns around untrusted repositories triggering arbitrary code execution via lazy-fetch hooks or configuration, shifting trust decisions entirely to the server operator.

The series is now in its third version, with all of Junio’s v2 review concerns fully addressed: API rigidity resolved via a callback-based allowlist, stricter path validation, recursion safeguards, and clearer documentation. Junio’s latest review of the final patch (5/5) raises a minor design nit about the order of environment variable handling in `cmd_upload_pack()`, suggesting a cleaner approach to preserve operator control. The rest of the patch—documentation, tests, and core behavior—is uncontested. While Junio’s conceptual doubt about using a configuration variable for this purpose and brian m. carlson’s security objection remain unresolved, both are mitigated by the server-side trust model. The series is technically sound and ready for a v4 tweak to address Junio’s environment-handling feedback. No other substantive reviews have been posted since v3.
