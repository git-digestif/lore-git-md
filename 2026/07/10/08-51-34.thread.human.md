This thread is about a patch series (v5) by Christian Couder that introduces `uploadpack.lazyFetchTrusted`, a server-side configuration variable allowing operators to mark repositories as trusted for lazy fetching. The goal is to address security concerns around untrusted repositories triggering arbitrary code execution via lazy-fetch hooks or configuration, shifting trust decisions entirely to the server operator.

The series is now under review, with all feedback from v4 addressed in v5. Junio’s earlier critiques—API rigidity, path validation, recursion risks, and documentation ambiguities—have been resolved. His final v4 review was entirely surface-level, focusing on documentation wording and grammar. The series remains under review, not yet in `seen`, `next`, or `master`. The latest patch (3/5) wires up the path-allowlist helpers from earlier patches to the new configuration key, enforcing strict absolute-path validation and preparing the plumbing for the final activation in 5/5. No substantive concerns remain, though Junio’s scalability critique about memory overhead and conceptual doubts about using a configuration variable are still unresolved. A latent design issue in `safe.directory` (silent ignoring of non-existent paths) is now flagged for follow-up. Christian is the sole active participant, with no new reviews posted for v5.
