This thread is about a patch series introducing `uploadpack.lazyFetchTrusted`, a server-side configuration variable that lets operators mark repositories as trusted for lazy fetching—a security-conscious replacement for the earlier client-side `GIT_NO_LAZY_FETCH=fromAccepted` proposal. The series is now at v3, submitted by Christian Couder after addressing feedback from Junio C Hamano on the v2 design.

The key change in v3 is a major refactoring of the path allowlist machinery. Junio’s critique of the v2 API—where `path_allowlist_apply()` hardcoded path validation logic—has been resolved by introducing a callback-based design. The new implementation lets callers define their own validation rules via a function pointer, allowing the `uploadpack.lazyFetchTrusted` logic to reject relative paths (including `.`) while preserving the existing behavior for `safe.directory`. The series also adds a safeguard against infinite lazy-fetch recursion, a risk Junio identified in v2 where a repository configured as its own promisor remote could trigger nested `upload-pack` invocations. This is now prevented by a `GIT_INTERNAL_LAZY_FETCH_DEPTH` environment variable, with tests verifying the behavior. Documentation has been updated to clarify that repositories must be allowlisted by their `.git` directory (e.g., `/srv/repo/.git` for `/srv/repo`) and to warn against self-referential configurations.

The series remains under review, with no merge status reported. Junio’s feedback on v2—including stylistic suggestions, scalability concerns, and API design critiques—has been addressed, but the unresolved security objection from brian m. carlson (who argued that expanding lazy-fetching flexibility increases exposure to untrusted repositories) still lingers, though the server-side trust model directly mitigates it. The implementation touches the promisor-remote subsystem, `setup.c`, `upload-pack.c`, and adds a new test script covering edge cases like recursion and path validation. Christian has rebased the series on a recent `master` commit to avoid merge conflicts, and CI tests pass except for an unrelated Debian 11 environment issue. The next step is likely further review or a reroll if additional feedback emerges.
