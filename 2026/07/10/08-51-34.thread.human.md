This thread is about a patch series (v3) by Christian Couder that introduces `uploadpack.lazyFetchTrusted`, a server-side configuration variable allowing operators to mark repositories as trusted for lazy fetching. The goal is to address security concerns around arbitrary code execution via lazy-fetch hooks or configuration in untrusted repositories, shifting trust decisions to the server operator. The series replaces an earlier client-side proposal (`GIT_NO_LAZY_FETCH=fromAccepted`) and is modeled after Git’s `safe.directory` mechanism.

The v3 series is complete and under review, with all patches resent to fix a threading error. Junio’s earlier critiques from v2—design/scalability, API rigidity, recursion risks, and documentation ambiguities—have been fully addressed. The API rigidity concern was resolved with a callback-based allowlist (patches 2/5 and 3/5), recursion risks are mitigated via a depth-limited environment variable (patch 4/5), and documentation now clarifies multi-valued syntax and repository identification. Junio’s latest review of patch 1/5 focuses on improving documentation for `try_promisor_remotes()` and its parameters, while his review of patch 2/5 highlights a latent issue in `safe.directory` (silent-ignoring of non-existent paths) that could affect this series if unaddressed. His only feedback on patch 4/5 is a minor type nitpick (`unsigned long` vs. `int` for the recursion depth counter), which is easily fixed.

The series remains in review, not yet in `seen`, `next`, or `master`. The unresolved high-weight concerns are Junio’s scalability critique (memory overhead in `lazy_fetch_objects()`) and conceptual doubt about using a configuration variable for this purpose, along with brian m. carlson’s security objection—though both are mitigated by the server-side trust model. Patch 5/5 is documentation-ready, and patches 2/5 and 3/5 are clean refactorings that could be integrated early if the series stalls. The only open technical question is whether the recursion depth limit of 5 is sufficient, but this can be adjusted later. No substantive reviews beyond Junio’s have been posted for v3.
