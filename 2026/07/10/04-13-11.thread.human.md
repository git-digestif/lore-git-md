This thread is about a bugfix for `git rebase --autosquash` that handles an edge case where a `fixup!` or `squash!` commit cancels out its target, resulting in an empty commit. The issue has been a long-standing pain point: Git currently halts the rebase with an error instead of respecting the user's `--empty` option (`drop`, `keep`, or `stop`). Farid Zakaria, the author, has iterated through five versions of the patch, incorporating substantive feedback from Phillip Wood, the primary reviewer.

The fix introduces a new function, `is_amended_head_empty()`, to detect when applying a `fixup!` or `squash!` empties the target commit, ensuring `--empty` is honored for such cases. It also preserves existing behavior for commits that were picked empty to begin with, avoiding disruption to workflows that rely on empty commits as placeholders. The patch touches the sequencer subsystem, updates user-facing documentation, and adds comprehensive test coverage for all three `--empty` modes and edge cases like mid-chain fixups and conflict resolution.

As of `v5`, the patch is technically sound and ready for merging. Phillip Wood's latest review confirms it addresses all prior concerns, including correctness issues around `rewritten-pending` file handling and performance optimizations. The patch is motivated by a real-world workflow at Meta, where it enables automatic dropping of both a commit and its revert when `--empty=drop` is used. While the patch itself is uncontroversial, a follow-up discussion about introducing a `revert!` (or `drop!`) autosquash directive remains unresolved, with competing designs proposed by Phillip Wood and Yuxuan Chen. The series has not yet been merged to any integration branch.
