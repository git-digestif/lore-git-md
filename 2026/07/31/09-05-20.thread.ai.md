Core problem or goal
A regression in `git rebase` (and related operations like merge) causes fatal errors (`invalid commit position. commit-graph is likely corrupt`) when commit graphs are enabled and the operation involves submodule pointer changes. The root cause is that `lookup_commit_reference_gently()` and related reachability functions resolve object references across repository boundaries, treating a submodule commit OID as if it belonged to the main repository. This was introduced by commit `bb5da75d61` ("commit: use commit graph in `lookup_commit_reference_gently()`").

Current status
A fix has been posted by Orestis Floros, modifying `commit-reach.c` to propagate the `struct repository *` parameter through the reachability functions (`can_all_from_reach()`, `can_all_from_reach_with_flag()`) and their callers. The patch ensures commits are parsed in the correct repository, preventing cross-repository commit-graph lookups. The fix includes a new test case in `t/t6437-submodule-merge.sh` that verifies the regression is resolved. The patch is narrowly scoped, well-motivated, and aligns with the ongoing effort to eliminate implicit reliance on `the_repository`. No controversy is evident; the fix is expected to be uncontroversial for reviewers familiar with the commit-graph and submodule subsystems. Workaround remains: disable commit graphs (`core.commitGraph=false`).
