This thread is about a regression in `git rebase` (and related operations like merge and fetch) that caused fatal errors when commit graphs were enabled and submodule pointer changes were involved. The issue was introduced by commit `bb5da75d61` and manifests as an "invalid commit position" error when Git tries to resolve a submodule commit OID as if it belonged to the main repository.

A fix has been posted by Orestis Floros and is now queued for integration after receiving Junio C Hamano's approval. The patch modifies `commit-reach.c` to propagate the `struct repository *` parameter through reachability functions, ensuring commits are parsed in the correct repository. This resolves the cross-repository commit-graph lookup problem and aligns with the broader effort to eliminate implicit reliance on `the_repository`. The fix includes a new test case in `t/t6437-submodule-merge.sh` and has been confirmed to work by Kristofer Karlsson, who also noted it reduces reliance on `the_repository` in the affected file.

The patch is narrowly scoped, well-motivated, and uncontroversial. It touches several files (`commit-reach.c`, `commit-reach.h`, `fetch-pack.c`, `upload-pack.c`, and test infrastructure) but avoids broader architectural changes. The regression affects users with submodules and commit graphs enabled, and the fix should proceed smoothly toward `master`. No open questions remain, though backporting to maintenance tracks may be considered once the fix lands in `master`.
