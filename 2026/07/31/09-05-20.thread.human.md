This thread is about a regression in `git rebase` (and related operations like merge and fetch) that causes fatal errors when commit graphs are enabled and submodule pointer changes are involved. The issue was introduced by commit `bb5da75d61` and affects users with submodules, producing errors like `invalid commit position. commit-graph is likely corrupt`.

Florian Schmidt reported the bug and provided a bisect result, reproduction case, and workaround (disabling commit graphs). Orestis Floros authored a fix that propagates the `struct repository *` parameter through reachability functions to ensure commits are parsed in the correct repository, preventing cross-repository commit-graph lookups. The fix includes a new test case in `t/t6437-submodule-merge.sh` and aligns with the broader effort to eliminate implicit reliance on `the_repository`. Junio C Hamano and Patrick Steinhardt have both reviewed and approved the patch, calling it "reasonable" and technically sound. Patrick’s recent review confirmed the fix resolves the regression and the test coverage is effective.

The patch is now uncontroversial and ready for integration, likely to Junio’s `next` branch soon. The only remaining questions are whether the fix should be backported to the maintenance track and if there are performance implications of propagating the repository parameter, but these are minor and do not block integration. The regression is resolved, and the fix is well-tested.
