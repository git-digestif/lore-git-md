This thread is about a regression in `git rebase` and `git merge` that causes fatal errors when commit graphs are enabled and submodule pointers change. The issue, introduced by commit `bb5da75d61`, occurs because Git mistakenly treats a submodule commit OID as belonging to the main repository, leading to commit-graph corruption errors.

Orestis Floros posted a targeted fix that propagates the `struct repository *` parameter through reachability functions, ensuring commits are parsed in the correct repository. The patch includes a new test case that confirms the regression is resolved. Florian Schmidt reported the issue and provided a reproduction case, while Patrick Steinhardt noted that recent commit-graph fixes in `master` might already address the problem but acknowledged the patch as a valid solution. Kristofer Karlsson’s recent review adds weight to the fix: he tested the patch and confirmed it resolves the issue while also reducing reliance on the global `the_repository` variable, aligning with broader architectural goals. The feedback so far is uniformly positive, and the patch is expected to be uncontroversial among reviewers familiar with the commit-graph and submodule subsystems.

The fix is narrowly scoped and well-motivated, but a few questions remain open: whether other code paths might trigger similar cross-repository confusion, whether the fix should be backported to maintenance branches, and whether the test coverage is sufficient for edge cases like nested submodules or partial clones. For now, users can work around the issue by disabling commit graphs.
