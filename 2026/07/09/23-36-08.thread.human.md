Here’s the human-mode narrative summary for a developer catching up on the thread:

This thread is about Domen Kožar’s patch series introducing a unified `post-worktree` hook to notify tools about worktree lifecycle events (creation, removal, movement). The series is now at version 3, but it’s blocked by a `git send-email` misconfiguration that broke threading in the mailing-list archive, preventing Junio’s automation tools from processing it. Domen argues the hook is necessary for observability when worktrees are created or removed by uncontrolled callers (e.g., IDEs, manual deletions), while Kristoffer Haugsbakk has proposed an alternative `--id=<string>` option for ownership-based enforcement. Maciej Ciemborowicz provided a real-world use case showing that wrappers are insufficient for observability when tools like VS Code create worktrees directly, strengthening Domen’s argument.

The current status is a design stalemate. Junio hasn’t responded to Domen’s v3 series or the framing of hooks and IDs as complementary, while Phillip Wood’s review of the v3 1/2 patch raised significant design concerns about the hook’s interface, timing, and execution model. Domen hasn’t yet addressed Phillip’s feedback, and the series remains in `seen` (proposed updates) but unmerged due to the threading issue. Meanwhile, Anders Kaseorg posted a test fix for a fragile `sed` substitution in the pruning test that fails when worktree paths contain `w2`—a real-world bug already causing failures in Ubuntu’s Git package. The fix is uncontroversial and should be incorporated before the series can proceed.

The open questions remain whether Junio will accept the hook-based approach, how the design might evolve to address Phillip’s concerns, and whether hooks and IDs can be integrated. For now, the series is stuck on both technical (threading) and design (interface) hurdles.
