This thread is about a patch series by Domen Kožar that introduces a unified `post-worktree` hook to notify external tools (like IDEs or AI agents) about worktree lifecycle events—creation, removal, and movement. The latest version (v3) now covers `git worktree prune`, ensuring tools can observe removals even when triggered indirectly (e.g., manual deletion or IDE cleanup). Domen argues this is necessary because wrappers can’t catch uncontrolled callers, as demonstrated by Maciej Ciemborowicz’s real-world example: VS Code with Codex creates worktrees directly, leading to races between worktree creation/removal and agent startup.

The series is still under active design discussion, with two competing but potentially complementary approaches: Domen’s hooks for observability and Kristoffer Haugsbakk’s `--id=<string>` counterproposal for ownership-based enforcement. Domen’s v3 patches are technically sound, with thorough test coverage for edge cases like dry runs, damaged entries, and relative paths. However, Junio C Hamano’s fundamental objection to hooks remains unresolved—he hasn’t responded to Domen’s v3 series, the observability argument, or Maciej’s use case. The key open question is whether hooks and IDs can be integrated, or if one approach will prevail. For now, the series is in `seen` (proposed updates), but no maintainer decision has been made.
