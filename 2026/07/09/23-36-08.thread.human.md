This thread is about Domen Kožar’s proposal to add a unified `post-worktree` hook with subcommands (`add`, `remove`, `move`) to notify external tools (IDEs, AI agents, development environments) when worktrees are created, removed, or moved. The hook is intended to address a gap in observability: when worktree operations are triggered by uncontrolled callers (e.g., a user running `git worktree remove` directly or an IDE invoking `git worktree prune`), external tools have no reliable way to detect these events.

The discussion has been stalled on a design objection from Junio C Hamano, who questioned whether Git should provide hooks for this purpose at all, arguing that user-written wrappers could achieve the same functionality. Domen proposed a compromise—a single hook with subcommands—as a narrower interface that still meets the observability requirement, but Junio has not yet responded to this counterargument. The series remains in the `seen` branch (proposed updates) with no indication of merge status change.

Key participants include Domen (the author), Junio (the maintainer), Phillip Wood (who raised concerns about hook execution order and documentation), and Caleb White (who provided surface-level feedback on consistency). Domen’s latest email is a design checkpoint, restating the motivation and asking Junio whether the compromise meets his bar for acceptance before Domen invests in a v3 patch series. No new technical details or objections have emerged, and the thread is effectively waiting on Junio’s reply.
