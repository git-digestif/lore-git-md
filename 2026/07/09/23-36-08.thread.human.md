This thread is about Domen Kožar’s patch series proposing a unified `post-worktree` hook to notify external tools (like IDEs or AI agents) about worktree lifecycle events—creation, removal, and movement. The series is now at version 3, but the discussion has hit a snag unrelated to the design: Junio C Hamano, the Git maintainer, has flagged a technical issue with how the patches were sent. The cover letter and patches reference mismatched message-IDs, breaking the thread in the mailing-list archive and preventing Junio’s automation tools from processing the series. Until this is resolved, the patches themselves won’t be reviewed or merged.

The core debate remains unresolved. Domen argues that hooks are necessary for observability when worktrees are created or removed by uncontrolled callers (e.g., an IDE or a user running `git worktree prune` directly), while Kristoffer Haugsbakk’s counterproposal—an `--id=<string>` option for ownership enforcement—addresses a different but complementary need: preventing tools from interfering with each other’s worktrees. Maciej Ciemborowicz’s real-world report supports Domen’s case, showing that wrappers can’t solve the observability problem when the caller isn’t the user or their agent. Junio’s earlier objection—that user-written wrappers could achieve the same thing—hasn’t been revisited since Domen’s v3 compromise, which frames hooks and IDs as complementary rather than competing. For now, the thread is stalled on the threading issue, but the design questions—whether hooks are justified, how they might coexist with IDs, and whether the subcommand-style interface is the right approach—are still open.
