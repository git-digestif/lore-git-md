This thread is about a Google Summer of Code contributor’s final patch series (v9) adding four new path-related keys—`path.working_tree`, `path.superproject_working_tree`, `path.index`, and `path.prefix`—to `git repo info`. The series is now design-resolved, mechanically complete, and ready for merging after addressing all prior objections. The new keys expose filesystem locations of repository components in a scriptable format, with each key supporting absolute and relative path variants via suffix-based formatting (e.g., `path.working_tree.absolute`).

The series has undergone significant refinement: earlier versions included controversial keys (`path.hooks`, `path.cdup`) and naming inconsistencies, but v9 streamlines the scope to uncontroversial keys and enforces underscore-based naming (e.g., `path.superproject_working_tree`). Key technical changes include a critical fix to `get_superproject_working_tree()` (patch 2/5) to respect the `repo` parameter, ensuring correct behavior when `--git-dir` is used in submodules. Tests have been optimized to avoid redundant repository initialization, and all edge cases (bare repositories, subdirectory execution, path overrides) are covered.

All substantive objections have been resolved. Junio C Hamano, the maintainer, previously raised architectural concerns about shared logic between `git repo info` and `git rev-parse`, but the author proposed a two-phase plan (merge v9 as-is, then refactor shared logic in a follow-up series). Phillip Wood’s design objections—naming, necessity of `path.hooks`, and behavioral consistency of `path.cdup`—were addressed by dropping those keys entirely. Justin Tobler’s feedback on test correctness and usability (e.g., `/dev/null` handling) was incorporated in earlier versions. The series is now awaiting final review before being queued for merging. No further changes are expected unless new issues arise.
