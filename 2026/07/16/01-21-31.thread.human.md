This thread is about a Google Summer of Code contributor’s patch series adding four new path-related keys (`path.working_tree`, `path.superproject_working_tree`, `path.index`, and `path.prefix`) to the `git repo info` command. The series is now in its eighth iteration and is planned as the final version (v9) before merging.

The goal is to expose filesystem locations of repository components—such as the working tree, index file, superproject working tree, and the relative path from the top-level working tree to the current directory—in a scriptable format. After a design pivot in v8, the series has been streamlined to uncontroversial keys only, resolving all prior objections. The author has agreed to Junio’s requirement to use underscores in key names (e.g., `path.superproject_working_tree` instead of `path.superproject-working-tree`), which was the last mechanical blocker. The next version will also optimize tests to avoid initializing new repositories for each case, addressing a minor efficiency suggestion from Phillip Wood.

The series is now mechanically complete and design-resolved, with no remaining substantive objections. The implementation touches `builtin/repo.c`, `submodule.c`, and `builtin/rev-parse.c`, introducing eight new keys with suffix-based formatting (e.g., `.absolute` and `.relative`). The `path.prefix` key returns the relative path from the top-level working tree to the current directory, including a trailing slash. All keys are tested for edge cases, including bare repositories and submodule contexts. The only unresolved architectural concern—a proposal to refactor shared logic into a new helper library—has been deferred to a follow-up series, as the current patches are ready for merging. The author’s constructive responses to feedback have preserved momentum, reducing the risk of abandonment.
