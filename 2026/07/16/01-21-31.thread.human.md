The `[PATCH v7]` series adding eight new path-related keys to `git repo info` is now mechanically complete and awaiting substantive technical review. The latest update addresses Justin Tobler’s stylistic feedback on the `path.superproject-root` implementation, simplifying control flow without changing functionality. All high-weight issues from prior versions—including the bisectability break in patch 2/8 and the `path.cdup` edge-case discrepancy—have been resolved.

The series exposes filesystem locations of repository components (e.g., hooks directory, index file, superproject root) via scriptable keys like `path.toplevel.absolute` and `path.cdup`. While mechanically sound, three design questions remain unresolved: whether `path.hooks.relative` should return `/dev/null` verbatim when hooks are disabled, whether the deprecated `path.grafts` keys should be included at all, and how to handle the unwieldy test helper for absolute paths. Justin Tobler advocates for usability improvements in the hooks handling, while the current implementation follows `git rev-parse` precedent. The grafts inclusion debate pits the series’ goal of completeness against the project’s deprecation plans.

Despite Justin Tobler’s committed review, no substantive feedback beyond test hygiene and design questions has materialized since v7 was posted.
