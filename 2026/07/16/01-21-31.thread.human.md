This thread is the seventh iteration of a GSoC patch series by K Jayatheerth adding eight new path-related keys to `git repo info`, such as `path.toplevel`, `path.superproject-root`, `path.hooks`, and `path.cdup`. The goal is to expose filesystem locations of repository components (e.g., hooks directory, index file) in a scriptable format, mirroring internal Git struct fields. Version 7 is mechanically complete and fixes all prior correctness issues, but two design questions linger: whether to include `path.grafts` (given grafts are deprecated) and how to handle `/dev/null` for disabled hooks.

The latest update resolves the `/dev/null` debate. Justin Tobler and the author agreed to special-case both `path.hooks.absolute` and `path.hooks.relative` to return `/dev/null` verbatim when `core.hooksPath` is set to that value, improving usability for scripts. This diverges slightly from `git rev-parse --git-path` but aligns with the series’ focus on practicality. The `path.grafts` question remains open—Justin questions its long-term value, while the author defends it as part of the series’ completeness goal. Junio C Hamano has warned the series risks being dropped from `seen` unless reviewers engage soon, as no substantive technical feedback has materialized beyond these resolved issues.

Key changes in v7 include fixing a critical bug in `path.superproject-root` (where the function ignored the `repo` parameter), adding `path.cdup` to address Junio’s symmetry request, and splitting tests to avoid bisectability breaks. The series touches `builtin/repo.c`, `submodule.c`, and test files, with 24 new keys supporting suffix-based formatting (e.g., `.absolute`/`.relative`). While mechanically ready, the lack of reviewer bandwidth threatens its progress.
