This thread is about a Google Summer of Code contributor’s patch series, now at version 7, that adds eight new path-related keys (`path.toplevel`, `path.superproject-root`, `path.hooks`, `path.index`, `path.grafts`, `path.git-prefix`, and `path.cdup`) to the `git repo info` command. The goal is to expose filesystem locations of repository components in a scriptable format, avoiding direct access to Git’s internals. The series is mechanically complete, all prior correctness issues have been fixed, and the design has been endorsed by Junio C Hamano, but it has received no substantive technical review in the month since v7 was posted.

The series is now at imminent risk of being dropped from Junio’s integration branches unless reviewers step up within the next few weeks. Justin Tobler had previously committed to reviewing the series, but his review has not yet materialized. The patches touch `builtin/repo.c`, documentation, and tests, and introduce twenty-four new keys with suffix-based formatting support. The behavior aligns with `git rev-parse --git-path` precedent, returning paths unconditionally even in bare repositories or when the file does not exist. The only unresolved architectural question is whether to merge v7 as-is and later refactor shared logic into a new helper library, but this is not blocking immediate review.

The series is feature-complete, well-tested, and unlikely to be controversial—its primary obstacle is now reviewer bandwidth. If no reviewers engage soon, the topic will be abandoned, despite its readiness for integration.
