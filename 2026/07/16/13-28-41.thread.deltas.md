## 2026/09/03

- [2026/09/03/21-52-06 by Samuel Bronson <naesten@gmail.com>] Samuel Bronson reported testing the `--drop-filtered` feature on a real llvm-project clone not originally cloned with `--filter`, finding it seemed to work well and greatly reduced the object database size.
- [2026/09/03/21-52-06 by Samuel Bronson <naesten@gmail.com>] Samuel Bronson proposed an RFC change to `builtin/repack` so that instead of dying when a blob referenced by the current index would be dropped, the operation skips dropping it (retaining the message as a warning), arguing this is more convenient than canceling after the slow `enumerate_promisor_blobs()` step and allows `git repack -a --filter=blob:limit=0 --drop-filtered` to work in non-bare repositories with non-trivial files; he noted the RFC does not fix the tests to match or allow `--filter=blob:none`.

## 2026/09/04

- [2026/09/04/10-51-33 by Siddharth Shrimali <r.siddharth.shrimali@gmail.com>] Siddharth Shrimali agreed with Samuel Bronson that aborting the whole `--drop-filtered` operation because a single blob is referenced by the index is a poor trade-off, since that failure would occur only after the full `enumerate_promisor_blobs()` walk had already run.
- [2026/09/04/10-51-33 by Siddharth Shrimali <r.siddharth.shrimali@gmail.com>] He cautioned that `oidset_remove()` mutates `drop_oids` in place and the `--dry-run` printer iterates `drop_oids` afterwards, so simply skipping index-referenced blobs would make `--dry-run` stop listing them; instead he proposed collecting the index OIDs into a separate skip-set that both the dry-run output and the real drop consult.
- [2026/09/04/10-51-33 by Siddharth Shrimali <r.siddharth.shrimali@gmail.com>] He noted as a follow-up that the planned drop-log work must account for the fact that a blob skipped this way was never dropped, so it must not be recorded there.
