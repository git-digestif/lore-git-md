Originating author: K Jayatheerth (GSoC contributor). Thread type: feature patch series. Current version: 7 (mechanically complete, correctness-fixed, and ready for substantive technical review).

Core problem or goal: Expose filesystem locations of repository components (e.g., hooks directory, index file, grafts file, superproject root, and the relative path from the top-level working tree to the current directory *and its inverse*) in a user-facing, scriptable format via `git repo info`. The new keys mirror existing internal Git struct fields but avoid requiring direct access to Git’s internals. Each key supports suffix-based formatting (e.g., absolute vs. relative paths). The series includes `path.cdup` (the inverse of `path.git-prefix`) to complete the relative-path key set, as explicitly requested by Junio C Hamano to address prior design objections and achieve symmetry.

  - Patch 8/8 (v7): `path.cdup` uses a new `get_path_cdup()` function, returning the relative path from the current directory to the top-level working tree (e.g., `../../` in a subdirectory, empty string at the root, or the absolute path to the working tree root when outside the working tree). The implementation checks `is_inside_work_tree(repo)` and, if false, returns `repo_get_work_tree(repo)` as an absolute path. Tests cover the outside-working-tree scenario, including cases where `GIT_WORK_TREE` is set but the current directory is outside the working tree.
- Behavior: Keys return filesystem paths (absolute or relative) for repository components. In bare repositories or when not inside a submodule, the respective keys return an empty string, except for `path.index`, `path.grafts`, and `path.hooks`, which return paths unconditionally (even when the file or directory does not exist or the repository is bare), aligning with `git rev-parse --git-path` precedent. The `path.hooks` keys explicitly document that they return `/dev/null` verbatim when `core.hooksPath` is set to that value. The test suite includes coverage for `/dev/null` handling, bare-repository edge cases, `--git-dir` usage, and the new `path.cdup` and `path.git-prefix` behaviors.
