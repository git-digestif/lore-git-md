The `path.git-prefix` key returns the relative path from the top-level working tree to the current directory (e.g., `sub/dir/` in a subdirectory, empty string at the root), including a trailing slash. The `path.cdup` key returns the relative path from the current directory to the top-level working tree (e.g., `../../` in a subdirectory, empty string at the root).

  - Patch 3/7 (v6): `path.hooks.absolute` and `path.hooks.relative` use `repo_git_path_replace()` and `format_path()`, respecting `core.hooksPath` and documenting `/dev/null` handling.

  - Patch 7/7 (v6): `path.cdup` uses a new `get_path_cdup()` function, returning the relative path from the current directory to the top-level working tree (e.g., `../../` in a subdirectory, empty string at the root). The implementation counts slashes in the repository’s `prefix` field to generate `../` sequences.
- Behavior: Keys return filesystem paths (absolute or relative) for repository components. In bare repositories or when not inside a submodule, the respective keys return an empty string, except for `path.index`, `path.grafts`, and `path.hooks`, which return paths unconditionally (even when the file or directory does not exist or the repository is bare), aligning with `git rev-parse --git-path` precedent. The `path.hooks` keys explicitly document that they return `/dev/null` verbatim when `core.hooksPath` is set to that value. The test suite includes coverage for `/dev/null` handling, bare-repository edge cases, `--git-dir` usage, and the new `path.cdup` and `path.git-prefix` behaviors.
