Originating author: K Jayatheerth (GSoC contributor). Thread type: feature patch series. Current version: 7 (mechanically complete, correctness-fixed, and ready for substantive technical review).

Core problem or goal: Expose filesystem locations of repository components (e.g., hooks directory, index file, grafts file, superproject root, and the relative path from the top-level working tree to the current directory *and its inverse*) in a user-facing, scriptable format via `git repo info`. The new keys mirror existing internal Git struct fields but avoid requiring direct access to Git’s internals. Each key supports suffix-based formatting (e.g., absolute vs. relative paths). The series includes `path.cdup` (the inverse of `path.git-prefix`) to complete the relative-path key set, as explicitly requested by Junio C Hamano to address prior design objections and achieve symmetry.

Current status: Seventh submission (version 7) is **mechanically complete, correctness-fixed, and ready for substantive technical review**. All high-weight issues from prior versions are resolved:
1. **Patch 2/8 refactoring**: Split into two patches—patch 2/8 fixes `get_superproject_working_tree()` (respecting the `repo` parameter and using the repository’s working directory), and patch 3/8 introduces the `path.superproject-root` keys. 7. **Patch 7/8 (`path.git-prefix`)**: Returns the relative path from the top-level working tree to the current directory (e.g., `sub/dir/`), including a trailing slash. Tests cover root and subdirectory cases.

The implementation matches `git rev-parse --show-cdup` behavior exactly, resolving Junio’s edge-case discrepancy. Tests cover root, subdirectory, and outside-working-tree scenarios, including `GIT_WORK_TREE` overrides.
