The thread is a bug report from Toon Claes about `git history fixup` corrupting the index in other worktrees: when the command rewrites a commit on a branch that is checked out elsewhere, the other worktree is left with spurious staged changes. Phillip Wood diagnosed the root cause as the command rewriting branches without updating the corresponding index or working copy, and the discussion settled on a conservative fix -- `git history fixup` will refuse to rewrite any branch checked out in another worktree (or mid-rebase when the tree would change), mirroring the safety checks in `git rebase --update-refs`. Patrick Steinhardt endorsed this approach and opened GitLab issue #772, and Aniket Gupta volunteered to implement it.

Toon Claes has now confirmed that GitLab has no competing plan for the issue and formally invited Gupta to proceed with the patch, asking to be Cc'd on the eventual submission for review. The design remains finalized and unchanged, but no code has been posted yet; implementation is still pending in `builtin/history.c` and the worktree branch-detection code, with regression tests expected in both the `git history` and worktree test suites.
