## 2026/08/03

- [2026/08/03/09-05-15 by Phillip Wood <phillip.wood123@gmail.com>] Phillip Wood argued that "--reedit-message" is an unfortunate precedent for the "squash" subcommand (where a new message is constructed from several commits rather than re-editing an existing one), said he is tempted to add an "--edit" option and deprecate "--reedit-message", and proposed that when squashing, the default could inspect the commits being squashed before deciding whether to open the editor (skipping it for "fixup!"/"amend!" commits squashed into a single target, opening it otherwise) with a command-line override like "git commit", while acknowledging the danger of it becoming confusing. He also maintained that "amend!"/"squash!" messages signal user intent and should be dropped more carefully, and noted scripts could pass --edit/--no-edit.
- [2026/08/03/09-11-46 by Phillip Wood <phillip.wood123@gmail.com>] Phillip Wood reiterated that regardless of the default, the user should be able to override it on the command line, and repeated his objection that the rebase squash message template — designed for squashing fixups into a single target — is a poor fit for a command that squashes fixups into multiple targets, worrying about message fragments separated by screens of commented lines.
- [2026/08/03/16-02-45 by Junio C Hamano <gitster@pobox.com>] Junio C Hamano agreed that re-raising a dismissed point can lead to productive discussion but cautioned that "convincing" is not black and white; noted that since "git history" is experimental its UI can be tweaked; and responded to the proposed editor default that while a base commit with an "amend!" clearly needs no further editing, he is unsure when any "fixup!" or multiple "amend!" commits are involved and suspects the behavior would be confusing.

- [2026/11/02/16-34-23 by Phillip Wood <phillip.wood123@gmail.com>] Phillip Wood distinguishes the subject of this thread (which feels like a genuine question) from "Will merge to next?", which he reads as "I'm going to do that unless someone stops me"; he agrees with Patrick Steinhardt's points and suggests that making clear an ejected topic can be re-added if there is renewed interest would lessen worry about demotivating contributors.
