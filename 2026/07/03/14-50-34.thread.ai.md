Subject: [PATCH 0/3] teach `git history` to sign rewritten commits
Series version: v3 (v1 and v2 previously)
Originating author: Souma
Thread type: patch series

Core problem or goal
Teach `git history` to sign rewritten commits (`drop`, `fixup`, `reword`, `split`) using the same configuration (`commit.gpgsign`) and command-line options (`-S/--gpg-sign`, `--no-gpg-sign`) already supported by `git commit`.

Current status
Series is at v3; under maintainer consideration. All substantive review feedback from Patrick Steinhardt (v1 and v2) has been addressed: the replay API plumbing is split into a dedicated preparatory patch (1/3), documentation and tests are folded into the main feature patch (3/3), commit messages are trimmed, and the `OPT_HISTORY_GPG_SIGN` macro formatting is fixed. Patrick explicitly stated in his v3 review of patch 1/3 that the infrastructure is mechanically sound and ready for integration, and in his v2 review of patch 3/3 that he is happy with the series as-is and does not require a reroll. Junio C Hamano has now raised a procedural question about the author’s name under the Developer Certificate of Origin (DCO), which must be resolved before the series can proceed to `next`. No code changes are required; the series remains effectively ready for integration pending Souma’s response.

Key technical details
- Files touched: `builtin/history.c`, `replay.c`, `replay.h`, `Documentation/git-history.txt`, `t/t3451-history-reword.sh`, `t/t3452-history-split.sh`, `t/t3453-history-fixup.sh`, `t/t3454-history-drop.sh`
- New behavior: `drop`, `fixup`, `reword`, `split` now respect `commit.gpgsign`, `-S[=<key-id>]`, `--gpg-sign[=<key-id>]`, and `--no-gpg-sign`; command-line options override configuration, and the last option wins
- New symbols: `sign_commit` field in `replay_revisions_options` struct, plumbing through `pick_regular_commit`, `create_commit`, `commit_tree_ext`, `commit_tree_with_edited_message`, `split_commit`
- On-disk format: unchanged; only the commit object’s signature trailer is added when signing is enabled
- Test coverage: GPG-gated tests in `t3451`, `t3452`, `t3453`, `t3454` verify config-driven signing, command-line overrides, explicit key selection, and the no-new-commit case for `drop`; all flag/config combinations are covered
