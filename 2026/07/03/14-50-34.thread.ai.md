Thread identity
Subject: [PATCH 0/3] teach `git history` to sign rewritten commits
Series version: v4 (v1–v3 previously)
Originating author: Souma
Thread type: patch series

Core problem or goal
Teach `git history` to sign rewritten commits (`drop`, `fixup`, `reword`, `split`, `squash`) using the same configuration (`commit.gpgsign`) and command-line options (`-S/--gpg-sign`, `--no-gpg-sign`) already supported by `git commit`, `git rebase`, and `git cherry-pick`.

Current status
Series is at v4; **cooking in `seen`**. All substantive review feedback from Patrick Steinhardt (v1–v3) and Junio C Hamano’s DCO query have been addressed. The replay API plumbing (patch 1/3) is unchanged from v3; the main feature patch (2/3) covers all five subcommands with documentation, synopsis, and test coverage. Junio merged the series to `seen` for integration testing, where two new issues surfaced: (1) a mechanical regression in `t9902-completion.sh` (completion script does not handle the new `--gpg-sign`/`--no-gpg-sign` options for `git history`), and (2) a discrepancy in the `--git-completion-helper` output for `git history split` when conflicting options (`--gpg-sign --no-dry-run -- --no-gpg-sign`) are provided—the helper includes all options rather than respecting the last-option-wins precedence rule. Both issues must be resolved before the topic can graduate to `next`.

Key technical details
- Files touched: `builtin/history.c`, `replay.c`, `replay.h`, `Documentation/git-history.adoc`, `t/t3451-history-reword.sh`, `t/t3452-history-split.sh`, `t/t3453-history-fixup.sh`, `t/t3454-history-drop.sh`, `t/t3455-history-squash.sh`
- New behavior: all five subcommands respect `commit.gpgsign`, `-S[=<key-id>]`, `--gpg-sign[=<key-id>]`, and `--no-gpg-sign`; command-line options override configuration, and the last option wins
- New symbols: `sign_commit` field in `replay_revisions_options` struct, plumbing through `pick_regular_commit`, `create_commit`, `commit_tree_ext`, `commit_tree_with_edited_message`, `split_commit`; custom `history_config` callback to read `commit.gpgsign`; `OPT_HISTORY_GPG_SIGN` macro for command-line parsing
- On-disk format: unchanged; only the commit object’s signature trailer is added when signing is enabled
- Test coverage: GPG-gated tests in `t3451`–`t3455` verify config-driven signing, command-line overrides, explicit key selection, and the no-new-commit case for `drop`; all flag/config combinations are covered

Open questions and loose ends
- **Conceptual trade-off**: whether signing rewritten commits that were originally authored by someone else is desirable or misleading; documented in the commit message but unresolved.
- **Completion regression**: `t9902-completion.sh` fails in `seen` due to missing handling of `--gpg-sign`/`--no-gpg-sign` for `git history`.
- **Completion helper discrepancy**: `--git-completion-helper` for `git history split` does not respect the last-option-wins rule when conflicting options are provided, potentially misleading users.
