This thread teaches `git history` to sign rewritten commits (`drop`, `fixup`, `reword`, `split`) using the same GPG-signing configuration and command-line options already supported by `git commit`. The series, now at version 3, is authored by Souma and has been under review by Patrick Steinhardt.

All substantive feedback from earlier versions has been addressed: the replay API plumbing is split into a dedicated preparatory patch, documentation and tests are folded into the main feature patch, and commit messages are now concise. The latest review from Patrick is narrowly focused on minor improvements to the commit message—specifically, adding a brief explanation of the reordering of `repo_config()` calls—but he explicitly states the series is ready as-is and does not require a reroll. The only unresolved discussion is the conceptual trade-off of signing commits originally authored by someone else, which is acknowledged in the commit message but not blocking progress.

The series touches `builtin/history.c`, `replay.c`, and related test files, adding support for `commit.gpgsign`, `-S/--gpg-sign`, and `--no-gpg-sign` while preserving the existing behavior that command-line options override configuration. Test coverage verifies all flag/config combinations and the no-new-commit case for `drop`. With Patrick’s final feedback addressed (or optionally incorporated), the series is effectively ready for maintainer consideration.
