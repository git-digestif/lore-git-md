This thread is about teaching `git history` to sign rewritten commits (for subcommands like `drop`, `fixup`, and `squash`) using the same GPG-signing options already supported by other Git commands. The series, now at version 5, has addressed all substantive feedback from reviewers like Patrick Steinhardt and Junio C Hamano, including a follow-up to fix a completion test regression.

The implementation touches the `replay.c` API, adds command-line options (`-S/--gpg-sign`, `--no-gpg-sign`), respects the `commit.gpgsign` configuration, and includes thorough test coverage. Junio recently merged the series to his `seen` branch for integration testing, where a minor completion script issue was identified and resolved. The only remaining open question is a conceptual one—whether signing rewritten commits (which may have different authorship) is desirable—but this hasn’t blocked progress.

The latest email is a small clarification from Junio about the test script’s use of `--no-...` as a placeholder for dynamically generated negated options. This is a mechanical detail and unlikely to delay the series, which is otherwise unblocked and ready to move to `next` in Junio’s next "What’s cooking" report.
