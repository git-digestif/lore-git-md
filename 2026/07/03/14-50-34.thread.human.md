This thread is about teaching `git history` to sign rewritten commits (`drop`, `fixup`, `reword`, `split`) using the same GPG-signing configuration and command-line options already supported by `git commit`. The series, now at version 3, is authored by Souma and has been under active review.

The key change is that these `git history` subcommands now respect `commit.gpgsign`, `-S/--gpg-sign`, and `--no-gpg-sign`, with command-line options overriding configuration. The implementation touches `builtin/history.c` and the replay machinery in `replay.c`, and includes updated documentation and GPG-gated regression tests. All substantive feedback from Patrick Steinhardt—who reviewed earlier versions—has been addressed, including splitting the replay API plumbing into a preparatory patch and trimming commit messages. The series is now close to ready, with only minor cleanups expected.

One unresolved question remains: whether signing rewritten commits that were originally authored by someone else is desirable or potentially misleading. This trade-off is discussed in the commit message but hasn’t been settled. Otherwise, the technical implementation appears solid, with no major objections raised in the latest round of reviews.
