This thread is about teaching `git history` to sign rewritten commits (like `drop`, `fixup`, `reword`, `split`, and `squash`) using the same GPG-signing configuration and options already supported by other Git commands. The series, now at version 4, is ready for integration after addressing all substantive feedback from Patrick Steinhardt and a procedural DCO query from Junio C Hamano.

The core change refactors the replay API to expose a `sign_commit` field, which is then plumbed through the commit-creation logic. The main feature patch (2/2) now covers all history subcommands, including `squash`, and includes full documentation and test coverage. Junio is expected to queue the series for the `next` branch in the next "What's cooking" report.

The only unresolved discussion point is a conceptual trade-off: whether signing rewritten commits (which may have different authorship) is desirable or potentially misleading. This is documented in the commit message but remains an open question. Otherwise, all technical feedback has been addressed, and the series is mechanically sound and ready for integration.
