This thread is about teaching `git history` to sign rewritten commits—`drop`, `fixup`, `reword`, `split`, and `squash`—using the same GPG-signing options and configuration (`commit.gpgsign`, `-S`, `--gpg-sign`, `--no-gpg-sign`) already supported by other Git commands. The series, now at version 5, has addressed all substantive feedback from reviewers and is cooking in Junio’s `seen` branch for integration testing.

The implementation threads GPG-signing through the replay machinery, adding a `sign_commit` field to the `replay_revisions_options` struct and plumbing it through the commit-creation functions. Command-line options override the configuration, and the last option wins. Tests cover all five subcommands, verifying that signing works as expected with both config and command-line flags, including explicit key selection and the no-new-commit case for `drop`. The completion regression that surfaced during integration testing has been fixed in follow-up patches, and the series is now unblocked and ready to graduate to `next`.

The only unresolved question is conceptual: whether signing rewritten commits—especially those originally authored by someone else—is desirable or potentially misleading. This trade-off is documented in the commit message but remains an open discussion point. Patrick Steinhardt and Junio C Hamano have both reviewed the series, with Patrick confirming the infrastructure is mechanically sound and Junio merging it to `seen` after resolving a procedural DCO question. Souma has addressed all feedback, including splitting the replay API changes into a preparatory patch and clarifying the completion helper behavior.
