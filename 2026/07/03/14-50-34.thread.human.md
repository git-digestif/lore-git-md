The `git history` signing feature has been merged into Junio C Hamano’s `next` branch, meaning it is now integration-tested and on track for the next Git release. The series, originally posted by Souma as `[PATCH 0/3] teach `git history` to sign rewritten commits`, teaches the `git history` command to sign rewritten commits (`drop`, `fixup`, `reword`, `split`, `squash`) using the same GPG-signing configuration (`commit.gpgsign`) and command-line options (`-S/--gpg-sign`, `--no-gpg-sign`) already supported by `git commit`, `git rebase`, and `git cherry-pick`.

The final version (v5) addressed the last blocking issue—a regression in `t9902-completion.sh`—by adding completion coverage for `--gpg-sign` and `--no-gpg-sign` to `git history split`. The completion fix uses `--no-...` as a literal placeholder for dynamically generated `--no-gpg-sign` options, matching the behavior of `git rebase` and `git commit`. All substantive feedback from Patrick Steinhardt (mechanical cleanups and conceptual trade-off discussion) and Junio’s DCO query have been resolved. The replay API plumbing (patch 1/2) and main feature patch (patch 2/2) are unchanged from the version previously cooking in `seen`.

The only unresolved question is a conceptual trade-off: whether signing rewritten commits that were originally authored by someone else is desirable or misleading. This is documented in the commit message but remains an open discussion point. The series is now in `next` and will graduate to `master` unless new issues emerge during integration testing.
