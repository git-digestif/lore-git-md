This thread is about teaching `git history` to sign rewritten commits (like `drop`, `fixup`, `reword`, `split`, and `squash`) using the same GPG-signing options already supported by other Git commands. The series, now at version 4 by author Souma, has addressed all prior feedback from reviewers Patrick Steinhardt and Junio C Hamano, including mechanical cleanups, a conceptual discussion about signing rewritten commits, and a DCO clarification. The code is functionally complete, with full test coverage for all five subcommands and proper handling of configuration and command-line options.

However, Junio recently merged the series into the `seen` integration branch and discovered two new issues. First, the series breaks `t9902-completion.sh`, likely because the completion script doesn’t account for the new `--gpg-sign` and `--no-gpg-sign` options. Second, there’s an edge case in the command-line option parsing for `git history split`: when the `--git-completion-helper` is invoked with conflicting options (like `--gpg-sign --no-dry-run -- --no-gpg-sign`), it outputs all of them, which doesn’t match the command’s actual "last option wins" precedence rule. These issues will need to be fixed before the series can move to the `next` branch for further testing. No objections to the core functionality remain, and the series is otherwise ready for integration.
