This thread is about teaching `git history` to sign rewritten commits (`drop`, `fixup`, `reword`, `split`) using the same GPG-signing configuration and options already supported by `git commit`. The series, now at its third version, is authored by Souma and has been reviewed by Patrick Steinhardt, who has given it a green light.

The core change introduces a `sign_commit` field in the `replay_revisions_options` struct and plumbs it through the replay API, allowing the `history` command to respect `commit.gpgsign`, `-S[=<key-id>]`, `--gpg-sign[=<key-id>]`, and `--no-gpg-sign`. Command-line options override configuration, and the last option wins. The on-disk format remains unchanged—only the commit object’s signature trailer is added when signing is enabled. Tests in `t3451`, `t3452`, `t3453`, and `t3454` verify all flag/config combinations and the no-new-commit case for `drop`.

Patrick’s review in earlier versions requested mechanical cleanups (parameter ordering, config callback, preparatory split of `replay.c` changes) and a discussion of the conceptual trade-off around signing others’ commits. All feedback was addressed in v3, and Patrick explicitly stated he is happy with the series as-is, though he suggested a minor, optional addition to the commit message to explain the reordering of `repo_config()` calls. The series is effectively ready for maintainer consideration, with no outstanding technical concerns. The only open question remains whether signing rewritten commits—originally authored by someone else—is desirable or potentially misleading.
