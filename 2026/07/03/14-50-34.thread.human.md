This thread teaches `git history` to sign rewritten commits (`drop`, `fixup`, `reword`, `split`) using the same GPG-signing configuration and command-line options already supported by `git commit`. The series, now at version 2, is authored by Souma and remains under active review.

Souma has fully addressed Patrick Steinhardt’s earlier feedback from the first version, splitting the replay API plumbing into a dedicated preparatory patch and folding documentation and tests into the main feature patch. The current version respects `commit.gpgsign`, `-S/--gpg-sign`, and `--no-gpg-sign`, with command-line options overriding configuration. Tests cover all flag and config combinations, including edge cases like `drop` (which creates no new commit).

Patrick’s latest review is surface-level, focusing on minor documentation and style cleanups rather than technical concerns. He suggests trimming redundant sentences from the commit message and fixing a macro alignment nit in the code. The conceptual question—whether signing rewritten commits authored by others is desirable—remains unresolved but is now discussed in the commit message. The series is close to ready, pending these small adjustments.
