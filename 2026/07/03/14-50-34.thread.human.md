This thread is about teaching `git history` to sign rewritten commits (`drop`, `fixup`, `reword`, `split`) using the same GPG-signing configuration and command-line options already supported by `git commit`. The series, now at version 3, is authored by Souma and has been reviewed by Patrick Steinhardt, who has confirmed the infrastructure is mechanically sound and ready for integration.

The key change is that rewritten commits now respect `commit.gpgsign`, `-S[=<key-id>]`, `--gpg-sign[=<key-id>]`, and `--no-gpg-sign`, with command-line options overriding configuration. The series touches `builtin/history.c`, `replay.c`, and related documentation and test files, adding a `sign_commit` field to the `replay_revisions_options` struct and plumbing it through the relevant commit-creation functions. The on-disk format remains unchanged, as only the commit object’s signature trailer is added when signing is enabled.

All substantive feedback from Patrick has been addressed, including splitting the replay API plumbing into a preparatory patch, folding documentation and tests into the main feature patch, and trimming commit messages. The latest round of feedback from Patrick was surface-level, requesting only a minor addition to the commit message to explain the reordering of `repo_config()` calls. Junio C Hamano has now acknowledged the series and Patrick’s feedback, signaling it is under consideration for integration into `next`. The only remaining loose end is a conceptual trade-off about whether signing rewritten commits authored by others is desirable, which is discussed in the commit message but remains unresolved. Souma may choose to address the minor commit message request before the series is queued.
