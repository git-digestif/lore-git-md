This thread is about teaching `git history` to sign rewritten commits (`drop`, `fixup`, `reword`, `split`, and `squash`) using the same GPG-signing configuration and command-line options already supported by `git commit`, `git rebase`, and `git cherry-pick`. The series, now at version 4, is ready for integration after addressing all substantive feedback from Patrick Steinhardt and resolving a procedural DCO question from Junio C Hamano.

The implementation touches the replay machinery (`replay.c`, `replay.h`), the `git history` built-in, its documentation, and adds comprehensive test coverage for all five subcommands. Signing behavior follows the same rules as other Git commands: configuration (`commit.gpgsign`) is overridden by command-line options (`-S`, `--gpg-sign`, `--no-gpg-sign`), with the last option taking precedence. The on-disk format remains unchanged, as only the commit object’s signature trailer is added when signing is enabled.

The only unresolved question is a conceptual trade-off: whether signing rewritten commits that were originally authored by someone else is desirable or potentially misleading. This is documented in the commit message but remains an open discussion point. Junio is expected to queue the series for the `next` branch in the next "What's cooking" report.
