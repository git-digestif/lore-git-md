This Git mailing list thread is about an RFC patch series proposing a breaking change for Git 3.0: restricting hex object IDs to lowercase only. The series, authored by brian m. carlson, aims to address security vulnerabilities and compatibility issues caused by Git's current case-insensitive parsing of object IDs. The discussion has been ongoing, with the series now at its second version (v2), which is technically complete and addresses all feedback from the initial RFC.

The core of the proposal is to enforce lowercase-only parsing of object IDs, making Git's behavior consistent and predictable. The series introduces new infrastructure (like the `hex_kind` enum and updated hex-parsing functions) and refactors existing code to use these helpers without changing runtime behavior in the preparatory patches. The final patch activates the enforcement mechanism, documents the change, and adds test coverage to verify the new behavior. The breaking change is gated behind `WITH_BREAKING_CHANGES` and targets Git 3.0.

Key participants include brian m. carlson, who argues for the change on security and consistency grounds, and Junio C Hamano, the maintainer, who has engaged deeply with the implementation and philosophical aspects of the proposal. Junio's tentative "Will queue" signals movement toward integration, but the thread remains open pending broader community feedback. Jeff King (Peff) and Michael Montalbo have contributed technical reviews and demonstrations that strengthen the security rationale, while Phillip Wood has raised pivotal questions about the scope of the change, suggesting that forbidding ref names that look like object IDs might also be necessary. Elijah Newren provided substantive feedback on implementation details, which were addressed in v2.

The series is now complete, but the discussion around Phillip Wood's adjacent proposal could broaden the scope if others engage with it. The fate of the series depends on whether the project is willing to accept this breaking change for Git 3.0.
