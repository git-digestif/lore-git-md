This thread is about a proposed breaking change for Git 3.0: restricting hex object IDs to lowercase only. The series, now at v2, is authored by brian m. carlson and aims to address security and compatibility issues caused by Git's current case-insensitive parsing of object IDs. The seven-patch series introduces infrastructure for stricter hex parsing, preserves existing lowercase-forcing behavior in key code paths, adjusts a test to avoid false positives, and finally activates the enforcement, all gated behind `WITH_BREAKING_CHANGES`.

The core argument for the change is that Git's current behavior—emitting lowercase but accepting both cases—creates ambiguity and security risks for external tools that assume hex uniqueness. brian m. carlson has provided concrete evidence of real-world vulnerabilities, and Michael Montalbo demonstrated how mixed-case object IDs can produce inconsistent output, potentially confusing downstream tools. Junio C Hamano, the maintainer, has engaged deeply with the implementation and philosophical premise, raising technical questions but signaling readiness to mark the series for `next` if no new issues arise. His latest request for final review suggests he is inclined to proceed, pending community input.

Key participants include Jeff King, who focused on implementation details and edge cases (e.g., uppercase hex in object payloads creating parallel histories), and Phillip Wood, who expanded the discussion to adjacent policy questions, such as whether Git should also forbid ref names that *look like* object IDs. Elijah Newren provided narrowly scoped but critical feedback on correctness in earlier reviews, which was addressed in v2. Patrick Steinhardt’s recent email is a procedural update, committing to review the series within the week, but adds no new technical feedback.

The series remains under review, with open questions about whether the project will accept the breaking change, whether `HEX_KIND_OID` should cover derived hashes, and the unresolved edge case of uppercase hex in object payloads. Junio’s proposed compromise—normalizing mixed-case inputs to lowercase internally while accepting them externally—remains on the table but has not gained traction. The thread’s focus is still on the lowercase-only hex change, though Phillip Wood’s ref-name proposal could broaden the scope if others engage. For now, the series appears technically sound and aligned with prior discussion, but the final decision rests on community consensus.
