This Git mailing list thread is about an RFC patch series proposing a breaking change for Git 3.0: restricting hex object IDs to lowercase only. The series, authored by brian m. carlson, aims to address security and compatibility issues caused by Git's current acceptance of both uppercase and lowercase hex object IDs, which can confuse external tools and enable security bypasses.

Key participants include brian m. carlson, who argues for the change based on consistency, security, and ecosystem compatibility; Junio C Hamano, the maintainer, who has signaled tentative acceptance but remains ambivalent and has suggested a potential compromise of normalizing inputs internally; and Phillip Wood, who has raised important questions about the security rationale and scope of the change. Other contributors like Jeff King, Michael Montalbo, and Elijah Newren have provided substantive technical feedback on implementation details and edge cases.

The series is currently in the RFC stage, with no prior versions. The first five patches introduce infrastructure changes without altering runtime behavior, while the sixth patch activates the breaking change, gated behind `WITH_BREAKING_CHANGES`. Junio's reviews have identified technical omissions and behavioral subtleties that will be addressed in a `v2` update. The security rationale has been strengthened by brian's response to Phillip's questions, but it remains unclear whether this will be deemed sufficient to justify the change.

The latest email from Phillip Wood advances the discussion by probing the boundaries of the proposed change. He acknowledges brian's security examples but questions whether restricting hex case alone is sufficient, suggesting that ref names resembling object IDs could pose similar risks. This hints at a potential expansion of the discussion to broader input validation policies, though the thread's focus remains on the lowercase-only hex change for now. The thread is still open, with no final decision made on whether the project will accept this breaking change.
