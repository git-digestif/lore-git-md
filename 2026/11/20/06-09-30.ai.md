This is a **feature** patch adding a new `%(body:trailers=<bool>)` placeholder to Git's pretty-formatting engine. Andy Koppe proposes a `%(body)` atom that defaults to behaving exactly like the existing `%b` (raw body), but accepts a boolean `trailers` option; with `trailers=no` it strips the trailer block (as identified by the existing `%(trailers)` machinery) plus the blank line separating it from the preceding text, while preserving any content that follows the trailer block (such as `Conflicts:` sections or comment lines).

The implementation lives in `pretty.c` via a new `format_body_without_trailers()` helper that reuses the trailer-parsing infrastructure (`parse_trailers()`, `trailer_block_start/end()`) with `no_divider` set, then splices the body around the detected trailer range. A `parse_body_options()` function handles the `:trailers[=...]` argument syntax, mirroring the option style used by `%(trailers)` and `%(describe)`. Documentation is updated in `Documentation/pretty-formats.adoc`, and six new test cases in `t/t4205-log-pretty-formats.sh` cover equivalence with `%b`, unknown-option pass-through, trailer omission, `Conflicts:` handling, trailing content preservation, and the empty-body edge case.

The commit message is clear and well-motivated, listing four concrete use cases: hiding trailers in compact logs, reflowing the body with `%w` without disturbing trailers, coloring trailers separately, and scripting/UI access without post-processing `%b`. The author notes a related but independent patch ("pretty: fix lost and leaked colors at line breaks") that originally motivated this work, suggesting the two could be reviewed separately. The patch appears clean and self-contained, with thorough test coverage for the new placeholder's edge cases.
