This thread is a single-patch bugfix from Maik Riechert, sent via GitGitGadget, for an untracked-cache interaction with fsmonitor. He reports that after a failed fsmonitor query or a trivial response, normal-mode `git status` can list both an untracked directory and a nested directory beneath it, such as `?? three/` alongside `?? three/deep/`. The root cause is traced to commit 1cf98cb4d9, which added a stat check to invalidate stale cached directories but did not propagate that invalidation upward to parent directories.

The proposed fix changes `invalidate_stale_dirs()` in `dir.c` so that, when `DIR_SHOW_OTHER_DIRECTORIES` is set and at least one child is invalidated, it also calls `invalidate_one_directory()` on the immediate parent, mirroring `invalidate_one_component()`; the all-files mode is deliberately left unchanged to avoid extra stat calls during traversal. Regression coverage is added in `t/t7519-status-fsmonitor.sh` for both trivial and failed fsmonitor responses, using `test-tool chmtime` and `update-index --force-write-index` to force a stale cached state and verify that `git status --porcelain` does not report both parent and child. The patch is under review; no merge or integration status is stated.
