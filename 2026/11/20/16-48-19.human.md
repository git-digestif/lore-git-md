This is a refactoring patch, the sixth in an eight-part bugfix series that fixes the missing `promisor-remote` capability reply during protocol v2 `fetch` operations.

In this patch, Christian Couder finishes the consolidation of protocol v2 capability writing by updating `get_remote_bundle_uri()` in `connect.c` to use the unified `write_command_and_capabilities()` function instead of the old `send_capabilities()`. Since this was the last remaining caller, the patch deletes `send_capabilities()` entirely, eliminating the duplicated logic that previously existed across multiple functions. The bundle-uri request is now built the same way as fetch and ls-refs requests: by constructing a `struct strvec` of capabilities (here just the promisor-remote reply, no server-options) and passing it to the shared writer.

The commit notes a few wire-level differences that result from the unification: `command=bundle-uri` now appears first on the wire rather than last, the `promisor-remote` capability line precedes `object-format`, and the command line no longer carries a trailing newline. The author argues these are harmless because `serve.c` accepts capabilities in any order and servers strip trailing newlines.

This patch is purely preparatory -- it changes no user-visible behavior but sets up patch 7/8, where the actual bugfix lands by routing `fetch` through the same unified path so that the `promisor-remote=...` reply is sent with every pack-requesting command. The refactoring directly addresses the maintainer's earlier objection to v1 of this series, which had proposed a dedicated argument for the promisor-remote reply; v2 instead generalizes the capability list so all commands build their requests through the same helper.
