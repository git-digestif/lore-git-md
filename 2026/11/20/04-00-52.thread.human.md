Andrei Șova has sent a single patch fixing `git clone --revision` when cloning from a SHA-256 repository using a raw commit hash, a bug where the refspec is parsed with the wrong hash length because it is appended before the remote's hash algorithm is known. The patch records the refspec index and re-initializes it after `create_reference_database()` sets the correct algorithm, along with a regression test in `t/t5621-clone-revision.sh`. The series remains under review with no new version posted yet.

Junio C Hamano reviewed the patch substantively, questioning the design of appending the refspec early and re-parsing it later, and asked for commit message improvements describing the user-visible failures across protocol versions as well as test refinements. In his latest reply, Andrei explains that deferring refspec creation until after the handshake is impossible due to a circular dependency: `refspec_ref_prefixes()` must be initialized before `transport_get_remote_refs()` can fetch the remote refs that reveal the hash algorithm, but the prefixes require the refspec to exist first. He instead proposes skipping ref-prefix initialization when `--revision` is used, which also removes the need for the patch's extended guard; the implementation approach is still being negotiated.
