Andrei Șova has submitted a single-patch fix for a bug where `git clone --revision=<hash>` fails when cloning between repositories that use different hash algorithms -- specifically when a SHA-256 commit hash is misinterpreted as SHA-1 because the refspec is parsed in `builtin/clone.c` before the destination repository's hash algorithm is known. The patch records the refspec index early and re-initializes it via `refspec_item_init_fetch()` after `create_reference_database()` sets the correct algorithm, accompanied by a regression test in `t/t5621-clone-revision.sh`.

Junio C Hamano has provided the first substantive review, questioning the design of appending the refspec early and patching it later rather than deferring its creation until after the remote handshake when the hash algorithm is already determined. He requests commit message improvements to document the actual user-visible error messages for different protocol versions, note that the bug triggers in both directions, and explain the guard extension; he also asks for test refinements including separated assertions and additional unrelated refs to make the "no refs copied" verification meaningful. The patch remains under review with no integration branch assignment.
