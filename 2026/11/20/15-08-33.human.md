This is a bugfix for `git rev-parse` in repositories that use SHA-256 but are configured to be SHA-1 compatible via the `extensions.compatObjectFormat` setting.

The patch addresses a case where `git rev-parse --output-object-format=sha1 <oid>` would silently output the SHA-256 hash of an object instead of the requested SHA-1 hash. This happens when the object was created before the repository enabled SHA-1 compatibility, meaning it has no SHA-1 mapping. Rather than printing the wrong algorithm's hash, the command now dies with an error stating it cannot map the object to the requested format.

The change is small and surgical, modifying only `builtin/rev-parse.c` to check the return value of `repo_oid_to_algop()` and fail loudly when conversion is impossible. The commit message includes a clear reproduction sequence using `git init --object-format=sha256`, `git hash-object`, and `git config extensions.compatObjectFormat sha1`, which makes the edge case easy to verify. This looks like a solid, well-motivated fix for a real correctness issue in Git's hash-transition support.
