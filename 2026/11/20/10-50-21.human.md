This is a substantive review of Dominik Maier's bugfix for `git log --graph` rendering of left-skewed octopus merges. Caspar Duregger confirms the `idx < 0` guard is the correct fix but notes the commit message undersells it: the bug is reproducible with just three parents, not only four or more as originally stated. They supply a compact test case demonstrating the three-parent scenario, showing the edge being lost in the ASCII art.

Caspar also raises a policy question about the defensive `BUG()` added in `graph_draw_octopus_merge()`. While acknowledging it prevents out-of-bounds access, they note that without it the code would merely draw garbage rather than crash, leaving it to others to judge whether a hard crash is the appropriate behavior for a display routine. They conclude by observing that the commit message is dense and requires reading the code to fully grasp, though they do not push for changes there.

The review adds useful signal: it broadens the known trigger conditions and flags the `BUG()` choice as a potential point of contention for maintainers, while generally endorsing the technical approach.
