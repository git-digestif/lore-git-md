This is a preparatory refactoring patch, the third of eight in Christian Couder's v2 series that fixes the missing `promisor-remote` reply in protocol v2 `fetch` commands. The series expanded from three patches to eight specifically to address the maintainer's design objections to the first version, and patches like this one restructure the client-side capability-writing code before the actual bugfix lands in patch 7/8.

Specifically, this commit adds an optional `struct packet_reader *reader` parameter to `write_command_and_capabilities()` in `connect.c`. When that argument is NULL, the function behaves exactly as before, checking the server's advertised object-format against the global `the_hash_algo` and dying on mismatch. When a reader is provided, it instead sets `reader->hash_algo` directly from the server's advertisement, mirroring what `send_capabilities()` currently does for `ls-refs` and `bundle-uri` requests where the client may not yet know its own hash algorithm (such as during `git clone`).

The motivation is to prepare `write_command_and_capabilities()` to eventually absorb `send_capabilities()` in a following commit, unifying the two code paths that write protocol v2 command capabilities. All three current call sites -- in `send_object_info_request()`, `send_fetch_request()`, and `negotiate_using_fetch()` -- pass NULL, so this patch introduces no behavior change on its own.

The diff touches `connect.c`, `connect.h`, `fetch-pack.c`, and `fetch-object-info.c`, updating the function signature and its callers without altering wire behavior. It also handles the edge case where the server does not advertise an object-format by defaulting the reader to SHA-1.

As a purely mechanical preparation step with no user-visible effect, this patch looks straightforward and well-motivated; its value lies in enabling the unification that follows in the remaining refactoring patches of the series.
