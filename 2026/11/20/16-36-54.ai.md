This is a brief review acknowledgment in the ongoing `[PATCH v4 0/5]` utf8.c bounds-handling series. Junio C Hamano replies to Andy Koppe's argument that an optional `size_t *remainder` out-parameter on the ANSI escape scanning function is unnecessary: callers can pass `SIZE_MAX` as the length limit and derive any needed remainder by subtracting the returned consumed-byte count from their own known length. Junio explicitly endorses this simpler approach, confirming that the end-pointer API for `display_mode_esc_sequence_len()` should not grow a remainder parameter. The exchange is surface-level -- a short agreement with no new technical analysis -- but it closes the API design question raised in the parent email, settling on the cleaner signature where bounded scanning is achieved via the `end` pointer alone and unbounded scanning via `SIZE_MAX` rather than an additional out-parameter.
