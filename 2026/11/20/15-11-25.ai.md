This is a documentation patch, specifically the second of five in Dirk Gouders' v4 series addressing bounds handling in Git's UTF-8 display-width code. It corrects the comment block above `utf8_strnwidth()` in `utf8.c`, changing the description from "null-terminated string" to "string terminated by len" and fixing the claimed return value for invalid UTF-8 from `strlen()` to `len`, matching the function's actual signature and behavior.

Within the series, this comment fix complements the substantive code changes in later patches -- notably patch 4, which modifies `utf8_strnwidth()` to compute a `remainder` and pass it to `utf8_width()` to prevent reading past the buffer end, and patch 5, which introduces `display_mode_esc_sequence_len_all()` for greedily consuming ANSI SGR sequences. The broader v4 series (which reposts a retracted v3) fixes out-of-bounds reads in both `utf8_strnwidth()` and `utf8_width()`, adds end-pointer variants of ANSI escape scanning in patch 1, and includes unit tests in `t/unit-tests/u-utf8-ansi.c` and `t/unit-tests/u-utf8-width.c`. This particular patch touches only two lines of comments in `utf8.c` with no code or behavior change, and is straightforward and uncontroversial.
