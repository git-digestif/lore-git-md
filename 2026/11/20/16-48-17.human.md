This is a preparatory refactoring patch, the fourth in an eight-patch v2 series that fixes the missing `promisor-remote` reply in protocol v2 `fetch` commands.

Christian Couder reworks how the client builds `ls-refs` and `bundle-uri` requests so that they are accumulated in a `struct strbuf` and sent with a single `write_in_full()` call, matching the existing pattern used for `fetch` and `object-info` requests. To make this possible, `send_capabilities()` now writes into a `struct strbuf` instead of directly to a file descriptor, and both `get_remote_refs()` and `get_remote_bundle_uri()` construct their entire request -- command line, capabilities, delimiters, and flush -- in memory before sending.

The bytes sent on the wire are unchanged because `packet_buf_write()` and `packet_write_fmt()` format identically, but the error handling improves: a failed write now dies with "unable to write request to remote" rather than "packet write with format failed" or an unhandled SIGPIPE. This change sets up later patches in the series to route these requests through the unified `write_command_and_capabilities()` helper, which is the core of the refactoring that addresses the maintainer's objection to v1's dedicated `promisor_remote_reply` argument.
