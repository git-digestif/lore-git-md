This is a reply in Patrick Steinhardt's ongoing review thread for the first patch of his twelve-patch series introducing pluggable commit graphs as part of the ODB abstraction effort. The email responds to Junio C Hamano's substantive feedback on the simplification of commit-graph chain linking in `commit-graph.c`.

Patrick agrees with Junio that the switch from boolean returns to the standard "0 means success" error convention should be explicitly called out in the commit message for clarity. He then addresses the more substantive concern that removing the comparison against the `oids` array makes `struct commit_graph`'s `oid` field effectively write-only, since nothing else reads it for validation. Patrick proposes adding an `oidcmp(&oid, &g->oid)` check inside `load_commit_graph_chain_fd_st()` right before linking the base graph, which would validate each loaded layer against the hash recorded in the chain file.

He notes that this proposed check is actually stricter than the previous behavior: the old code skipped verification of both the base layer and the topmost layer, whereas the new check would validate every layer's trailer hash. While he views this as an improvement in both validation rigor and code clarity, he observes that it causes a test failure in `t5324` because that test implicitly depends on the base layer not being verified. Consequently, Patrick is considering adding a separate preparatory commit to address this validation gap, and he wonders aloud whether the series has grown long enough to warrant splitting into two smaller series for easier review.
