Andrei Șova has sent the second iteration of a bugfix for `git clone --revision` in `builtin/clone.c`. The bug: under protocol v2, cloning with `--revision=<hash>` fails with "fatal: Remote revision ... not found in upstream origin" when the given hash uses a different algorithm than the destination repository's default -- for example, a SHA-256 hash cloned into a SHA-1 repo -- even though the object exists on the remote. The root cause is that the `--revision` value was appended to the fetch refspec before the destination's hash algorithm was configured, so `parse_refspec` interpreted the hash under the wrong algorithm. The fix defers appending the refspec until after the hash algorithm is known, explicitly setting `remote->fetch.hash_algo`, and tracks the refspec item's index via a new `rev_refspec_idx` passed to `wanted_peer_refs`; the ref-prefix logic is also adjusted so that with `--revision` all advertised refs are requested rather than just HEAD. A regression test in `t/t5621-clone-revision.sh` covers the cross-algorithm case by cloning a SHA-256 source into a SHA-1 destination and verifying the clone succeeds with the expected HEAD and no stray refs. The thread currently consists of this single patch; no review feedback or merge status has been recorded yet.
