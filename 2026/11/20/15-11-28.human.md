This is a bugfix patch, specifically the fifth and final patch of Dirk Gouders's v4 series to fix bounds handling in Git's UTF-8 display-width code.

This patch introduces `display_mode_esc_sequence_len_all()`, a convenience wrapper around `display_mode_esc_sequence_len()` that greedily consumes all consecutive leading ANSI SGR escape sequences up to a given end pointer, rather than requiring callers to loop themselves. It updates the three call sites that previously looped manually -- in `utf8_strnwidth()`, `strbuf_add_wrapped_text()`, and `strbuf_utf8_replace()` -- to use the new helper, simplifying the code and reducing the chance of bounds-related mistakes. The patch also adds unit tests in `t/unit-tests/u-utf8-ansi.c` covering cases with no sequences, single sequences, multiple consecutive sequences, and truncated buffers.

Within the broader series, this sits at the end after the core bounds fixes and documentation corrections in patches 1 through 4; it is a cleanup that makes the earlier end-pointer API more ergonomic. The patch is small, well-scoped, and includes test coverage, which makes it a solid candidate for attention. No part of the v4 series has been queued in any integration branch yet; it remains under review.
