This is a refactoring patch, specifically patch 6 of 8 in Christian Couder's v2 series that fixes the missing `promisor-remote` reply in protocol v2 `fetch` commands. Having already unified `ls-refs` request construction in patch 5/8, this patch extends the same treatment to `get_remote_bundle_uri()` in `connect.c`, replacing its direct call to `send_capabilities()` with a call to the now-generic `write_command_and_capabilities()`. Because `send_capabilities()` no longer has any remaining callers after this change, the patch deletes that function entirely, removing 44 lines while adding only 5.

The new code path builds a `struct strvec capabilities` using the `add_promisor_remote_reply()` helper (introduced earlier in the series and declared in `connect.h`), then passes it along with the string `"bundle-uri"` to `write_command_and_capabilities()`, which now handles writing the command line, capability lines, and flush delimiter in one go. The function still assembles the request into a local `struct strbuf req_buf` before transmitting it with a single `write_in_full()`, preserving the error handling introduced in patch 4/8.

Several wire-level details change as a result. The `command=bundle-uri` line now appears first in the request instead of last, and the `promisor-remote` capability now precedes `object-format`; the author notes this is harmless because `serve.c` accepts capabilities in any order and JGit does not implement `bundle-uri`. Additionally, the `command=bundle-uri` line no longer ends with a newline, which the author describes as harmless because servers chomp newlines. As with the `ls-refs` changes in patch 5/8, no `server-option` capability is sent with the `bundle-uri` request.

This patch completes the client-side unification of protocol v2 capability writing across `ls-refs` and `bundle-uri`, leaving `write_command_and_capabilities()` as the single function responsible for emitting capability lines. That sets up patch 7/8, where the actual bugfix will route `fetch` requests through the same function to ensure the `promisor-remote=...` reply is sent with every pack-requesting command. The series applies on top of `maint` (v2.56.1) and currently has no Reviewed-by or Acked-by trailers.
