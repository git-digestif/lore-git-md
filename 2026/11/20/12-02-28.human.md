This is a small behavioral cleanup to `git fast-import`, the first patch in a six-part refactoring series from Patrick Steinhardt on the packfile lifecycle subsystem. The patch removes the `pack_report()` call from `git fast-import`'s default `--stats` output, deletes the `pack_report()` function itself along with its associated counters from `packfile.c` and `packfile.h`, and updates the man page to drop the mention of packfile statistics. The commit message argues that details like page size, `mmap` call counts, and pack window usage are internal implementation details that a user should not see by default, and that with pluggable object databases Git should not assume packfiles are even in use.

The change is part of Patrick Steinhardt's ongoing ODB abstraction and repack machinery overhaul. The cover letter for the series indicates that the later patches will continue polishing the packfile API and fix process-wide limit handling, so this first patch simply strips out user-visible reporting of packfile internals as a preparatory step. The diff is compact -- four files, three insertions and forty-four deletions -- and the commit message is clear about the motivation, making it easy to review. No one has replied yet, and the series is not queued in any integration branch.
