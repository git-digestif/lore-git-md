Patrick Steinhardt has posted a six-patch series refactoring the packfile lifecycle subsystem as part of his broader ODB abstraction and repack machinery overhaul. The series polishes the packfile API through five refactoring patches and includes one behavioral fix at its core: patch 1/6 removes developer-focused packfile statistics from `git fast-import` output, patches 2-4 perform mechanical renames and consolidation of lifecycle functions into a consistent `packfile_` prefix convention, patch 5/6 moves process-wide packfile limits from per-repository scope to a global `all_packfiles` list, and patch 6/6 fixes limit enforcement to explicitly honor the `do_not_close` flag.

Junio C Hamano has reviewed the first patch and provided substantive feedback. While agreeing with the premise that the removed metrics are aimed at Git developers rather than end users, he corrected a factual inaccuracy in the commit message: `pack_report()` did not report the number of packs opened, but rather printed page size, the `core.packedGitWindowSize` and `core.packedGitLimit` config values, the window-switch counter, mmap call counts, and current/peak window and mapped values. He also caught a user-visible string the patch missed -- the `--stats` option description in `cmd_fast_import()` still references packfiles and needs updating. No objections to the core removal were raised, but the feedback indicates the commit message needs revision for accuracy.

The series remains at v1 and under review, with no integration status claimed. A v2 is expected to incorporate Junio's corrections to the commit message description and the fix to the `--stats` help text before further review proceeds on the remaining patches.
