Patrick Steinhardt has posted a six-patch series refactoring Git's packfile lifecycle, aimed at polishing the internal packfile API ahead of pluggable object database backends. The first patch has now arrived: it removes the `pack_report()` function and strips packfile-internal statistics (mmap call counts, pack window usage, page size details) from `git fast-import --stats` output, on the grounds that these metrics expose implementation details that become meaningless once non-packfile storage is supported; he suggests such data could return later as trace2 output if needed. The remaining five patches, described in the cover letter, cover renaming `open_pack_index` to `packfile_open_index`, inlining `open_packed_git_1()`, adding a dedicated packfile-freeing function, and moving process-wide packfile limits to global scope.

So far Patrick is the only participant -- no reviews, acks, or objections have been recorded, and the series is not queued in any of Junio's integration branches. The work touches roughly 22 files, concentrated in `packfile.c` and `packfile.h` with call sites across `builtin/`, HTTP, and the test suite, and the author notes a minor semantic conflict with the `seen` branch in `odb/source-packed.c`. The thread remains open and awaiting substantive review.
