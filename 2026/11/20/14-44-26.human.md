This is a bugfix targeting the UTF-8 display width calculation in `utf8.c`, specifically patch 3 of a 4-patch series (v3) from Dirk Gouders. I have not seen the cover letter for this series, so I cannot relate it to the overall series goal beyond what the commit message states.

The patch addresses a corner case in `utf8_strnwidth()` when the `skip_ansi` parameter is set. The function skips over ANSI escape sequences (like color codes) to calculate the visible width of a string, but previously it did not check whether skipping such a sequence consumed the remainder of the input string. If an escape sequence ended exactly at the given length boundary, the function would proceed to call `utf8_width()` on a pointer at or past the end of the buffer. The fix adds a bounds check after the ANSI-skipping loop to break out early if the string pointer has reached the end.

The change is small and surgical: 10 lines modified in `utf8.c` plus 11 lines of new unit tests in `t/unit-tests/u-utf8-width.c` using the clar test framework. The tests cover three scenarios with the string `"\033[31mhello"`: where the ANSI sequence fits entirely within the length, where the length ends exactly at the end of the escape sequence, and where one character of visible text remains. This looks like a well-crafted fix with appropriate test coverage for the edge case it addresses.
