This is a cover letter for a five-patch bugfix series (v4) that Dirk Gouders is resending to replace the retracted v3. Four patches are his, and one is authored by Junio C Hamano; together they fix bounds handling in Git's UTF-8 display-width code and correct a misleading comment.

The series targets `utf8_strnwidth()` and `utf8_width()`, which could read past their length arguments or end-of-buffer boundaries -- a real risk when operating on mmapped regions where an out-of-bounds read can trigger SIGBUS. Junio's patch introduces an end-pointer variant of `display_mode_esc_sequence_len()` so ANSI escape sequences are scanned without reading at or beyond a supplied boundary, resolving an earlier performance objection about quadratic scanning. Dirk's patches then use that bounded helper inside `utf8_strnwidth()`, pass a remainder length to `utf8_width()` so multibyte characters chopped by the `len` argument are handled correctly, add a convenience wrapper `display_mode_esc_sequence_len_all()` for consuming consecutive SGR sequences, and fix the function's comment which incorrectly claimed it returns `strlen()` instead of `len` for invalid input.

The changes touch `utf8.c`, `utf8.h`, `pretty.c`, and the build files, and come with new clar unit tests in `t/unit-tests/u-utf8-ansi.c` and `t/unit-tests/u-utf8-width.c` covering chopped CJK sequences and greedy ANSI parsing. The range-diff confirms v4 is simply the un-squashed v3 content reposted after the previous version was withdrawn due to a malformed send.

No version of this series has been merged or queued in any integration branch; v4 is now the version under review. The work looks well-motivated and carefully tested, addressing genuine edge cases in display-width calculation rather than cosmetic issues.
