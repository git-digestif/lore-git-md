This is a documentation patch -- specifically a comment correction -- sitting as the second patch in Dirk Gouders' five-part v4 series fixing bounds handling in Git's UTF-8 display-width code.

The patch fixes the comment above `utf8_strnwidth()` in `utf8.c`, which had two inaccuracies. It described the input as a "null-terminated string" when the function actually takes an explicit `len` argument and operates on a bounded buffer, and it claimed the function returns `strlen()` for invalid UTF-8 when it actually returns the `len` argument itself. The fix rewords both points to match the real behavior.

Within the series, this lands right after Junio C Hamano's patch 1, which introduced the end-pointer variant of `display_mode_esc_sequence_len()`. While patch 1 changes code behavior to avoid reading past buffer ends, this patch simply makes the documentation honest about what the function already does. It is a small, well-motivated cleanup with a `Helped-by` from Andy Koppe, who had previously raised substantive objections to earlier versions of the series.

The series as a whole is under review and has not been queued in any integration branch. This particular patch is unlikely to generate controversy -- it corrects a misleading comment without touching any logic -- and serves as a clear statement that the surrounding documentation will be updated to match the new bounded-buffer semantics being introduced in the rest of the series.
