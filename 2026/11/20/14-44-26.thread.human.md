Dirk Gouders has posted the third patch in a v3 four-patch series fixing a potential out-of-bounds read in Git's UTF-8 display-width calculation. The bug lives in `utf8_strnwidth()` in `utf8.c`: when the function is asked to skip ANSI escape sequences and one of those sequences consumes bytes right up to (or beyond) the requested length boundary, the code previously proceeded to decode a glyph from a pointer that had already reached the end of the buffer. The fix adds a simple guard that breaks the loop early once the pointer hits the boundary, preventing phantom width counts or memory overruns. The patch also introduces unit tests in `t/unit-tests/u-utf8-width.c` covering the corner cases where an escape sequence ends exactly at the limit.

This is a small, targeted correction -- ten lines in `utf8.c` plus eleven lines of tests -- and represents the current state of the v3 series, though the cover letter and the other three patches are not part of this message. As yet there is no review feedback or maintainer decision recorded in the thread; the discussion so far consists solely of the technical description of the boundary-condition fix and its test coverage.
