This is a preparatory refactoring patch -- the first of eight in Christian Couder's v2 series fixing the missing `promisor-remote` reply in protocol v2 `fetch`. It does not change behavior; instead it restructures how the client builds protocol v2 capability lines so that later patches can inject the promisor-remote reply cleanly.

The patch changes `write_command_and_capabilities()` in `connect.c` to accept a `const struct strvec *capabilities` instead of a `const struct string_list *server_options`. Rather than the function internally iterating server options and emitting `server-option=...` lines, callers now build a complete list of capability lines (as `"key=value"` strings) and pass it in. A new helper `add_server_options()` in `connect.c` converts a `string_list` of server options into the corresponding `server-option=...` entries in a `strvec`, preserving the old behavior for existing callers.

Three call sites are updated to use the new API: `send_object_info_request()` in `fetch-object-info.c`, and both `send_fetch_request()` and `negotiate_using_fetch()` in `fetch-pack.c`. Each now initializes a local `struct strvec`, calls `add_server_options()` to populate it from the existing `server_options`, passes that strvec to `write_command_and_capabilities()`, and clears it afterward. The function itself now extracts the key portion of each capability line (up to the `=`) to call `ensure_server_supports_v2()` for validation before writing the full line to the request buffer.

Within the series, this patch and the next five establish the unified capability-writing path that patch 7/8 relies on to actually send `promisor-remote=...` with every pack-requesting `fetch`. The commit message explicitly states no behavior change is intended, and the diff confirms this is purely mechanical preparation: same wire output, different internal plumbing. Key identifiers for follow-up discussion: `write_command_and_capabilities()` signature change, `add_server_options()` helper, `struct strvec capabilities` locals in `fetch-pack.c` and `fetch-object-info.c`.
