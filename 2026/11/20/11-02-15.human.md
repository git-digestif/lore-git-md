This is a documentation patch -- specifically version 3 of a standalone proposal to codify line-wrapping and paragraph conventions for emailed contributions to the Git mailing list. Okhuomon Ajayi updates three contributor-facing documents (`Documentation/CodingGuidelines`, `Documentation/ReviewingGuidelines.adoc`, and `Documentation/SubmittingPatches`) to state that emailed prose, including patch commit messages and review replies, should be wrapped to a maximum of 72 columns so it remains readable on an 80-column terminal after a few levels of quoting, and that paragraphs -- including blocks of quoted text -- should be separated by blank lines.

The only change from v2 is the wording of the column limit: "near 70 columns" becomes "to a maximum of 72 columns", matching the existing commit-message convention and removing ambiguity, as Andy Koppe suggested during review of v2. The blank-line guidance, including the rule that a quoted block counts as a paragraph, carries over unchanged from v2, which had addressed Junio C Hamano's earlier scope question about inter-paragraph spacing. The patch is purely additive -- nineteen inserted lines across the three files -- with no code or behavior changes.

The patch sits under review with no integration-branch placement yet. It is a small, well-motivated piece of documentation housekeeping that formalizes long-standing informal list etiquette, and it has already absorbed feedback from both the maintainer and another reviewer, which suggests it is close to consensus.
