This is a **substantive review** of the first patch in Harald Nordgren's v9 series (the refactoring that extracts the `branch.<name>.deleteMerged` opt-out check into a reusable helper ahead of the new `--delete-integrated` flag). Junio C Hamano raises two design concerns rather than mechanical ones.

First, he objects to the helper's name `branch_opted_out()` as too generic: it implies the function applies to any future destructive operation, but the config key `branch.<name>.deleteMerged` is specific to the merge-deletion operation. He suggests either renaming the function to reflect its specific scope (deleteMerged) or generalizing both the function *and* the config key (for example to `branch.<name>.noClobber=true`) so that users are protected from future destructive commands by default.

Second, he questions the function's default behavior. As written, a missing key or an explicit `true` means the branch is *not* opted out, so the destructive operation proceeds. Junio argues this is a risky default -- if a user has not explicitly said "I am fine losing this branch," Git should treat it as precious and skip it. He frames this as a safety principle: absence of consent should mean protection, not permission.

The patch itself remains a behavior-neutral refactoring in `builtin/branch.c`, and the thread context indicates it was previously considered uncontroversial and ready for integration, but these two objections from the maintainer will need to be addressed before the series can advance.
