This is a refactoring patch, specifically the seventh and final patch of v2 part 1 in Patrick Steinhardt's series preparing commit-graph code for the ODB abstraction effort. It eliminates redundant bookkeeping arrays from `struct write_commit_graph_context` -- `base_graph_name`, `commit_graph_filenames_before`, `commit_graph_filenames_after`, and `commit_graph_hash_after` -- and instead derives all layer information directly from the passed-in commit-graph chain structure.

Inside `write_commit_graph_file()`, the patch introduces local `string_list` variables (`chain_hashes` and `kept`) to snapshot the hashes and filenames needed for chain-file writing and pruning before the existing chain is closed via `commit_graph_close()`. The base-layer rename logic now uses `base_rename_from`/`base_rename_to` derived from `ctx->new_base_graph`, and the split-graph chain file is written by iterating `chain_hashes` in reverse. The helpers `mark_commit_graphs()` and `expire_commit_graphs()` change signatures to accept the tip and base chain pointers and a `kept` string list respectively, rather than reading from the removed context arrays; `expire_commit_graphs()` now takes `dirpath` and `expire_time` directly. The caller `commit_graph_write()` drops all allocation and freeing of the removed arrays.

One behavioral change is introduced: `expire_commit_graphs()` is now called only after a successful write (after `commit_lock_file()`), whereas previously it ran unconditionally even if the graph write failed, which the commit message notes is arguably more correct. The patch touches only `commit-graph.c` with a net reduction of 33 lines, and serves to cleanly separate path-dependent logic from `write_commit_graph_file()` so it can be moved into the "files" backend in the deferred part 2 of the series.
