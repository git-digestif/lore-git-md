This is a review reply on a documentation patch. Andy Koppe responds to Okhuomon Ajayi's v2 proposal, which suggests telling contributors to wrap emailed text "near 70 columns" in three contributor-facing documents. Koppe counters with a more precise figure, recommending the documents instead state a "maximum of 72 columns."

His rationale is twofold. First, 72 columns matches the long-standing convention for commit messages, which are themselves quoted in email replies, so the same width limit applies to both contexts. Second, using a hard maximum rather than the softer "near 70" removes ambiguity about what is acceptable. This is a substantive review comment because it engages with the specific numeric choice and offers a concrete alternative grounded in existing project practice, rather than merely noting style preferences.

The suggestion arrives as the thread considers v2 of Ajayi's patch, which adds guidance to `Documentation/CodingGuidelines`, `Documentation/SubmittingPatches`, and `Documentation/ReviewingGuidelines.adoc`. If adopted, the change would replace the approximate 70-column target with the exact 72-column limit already used for commit messages, potentially making the guidance more consistent across Git's contributor documentation.
