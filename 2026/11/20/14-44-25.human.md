This is a documentation patch -- specifically a fix to an in-code comment -- and the second of four patches in a v3 series (the cover letter was not provided here, so the overall series goal is unclear from this email alone). Dirk Gouders corrects the comment above `utf8_strnwidth()` in `utf8.c`, which had two inaccuracies: it described the input as a NUL-terminated string when the function actually operates on a buffer bounded by the `len` parameter, and it claimed the function returns `strlen()` for invalid UTF-8 when it in fact returns the `len` argument itself. The diff is two lines, swapping those descriptions for the correct ones. It is a small, precise fix that removes misleading documentation without touching behavior, and the `Helped-by` trailer credits Andy Koppe for the review input.
