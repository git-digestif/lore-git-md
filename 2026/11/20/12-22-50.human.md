This is a refactoring patch, specifically the second of seven in Patrick Steinhardt's v2 series preparing commit-graph internals for the ODB abstraction effort. The patch simplifies how commit-graph chains are linked by removing a redundant parameter and tightening error conventions.

The core change renames the static helper `add_graph_to_chain()` to the now-public `commit_graph_link_base()` and drops its `oids` array argument. Previously, the function received both the chain being built and a parallel array of object IDs read from the chain file to verify trailer hashes. The patch recognizes that this array duplicates information already present in the linked base layers themselves: since each base graph stores its own `oid`, the function can walk the `base_graph` chain to derive the expected hashes ad-hoc. This makes the interface cleaner and self-contained.

Alongside the signature change, the function adopts the integer error convention of returning 0 on success and a negative code on failure, replacing the previous boolean-style returns. The caller in `load_commit_graph_chain_fd_st()` is updated accordingly, and the temporary `oids` array allocation is eliminated entirely.

The motivation is forward-looking: by making the linking logic depend only on the graph structures themselves rather than external arrays, the code becomes easier to move into the object database backend in a follow-up series. This patch is part of the broader pluggable commit-graph work, where part 2 will introduce `read_commit_graph` and `write_commit_graph` callbacks in `struct odb_source`.

The patch looks clean and well-scoped, touching only `commit-graph.c` and `commit-graph.h` without changing on-disk formats or user-visible behavior. It directly supports the series goal of decoupling chain management from the files backend.
