This is a refactoring patch, the fifth in an eight-patch v2 series that fixes a protocol v2 bug where the client omits the `promisor-remote=...` reply during `fetch` commands. The series, authored by Christian Couder, addresses failures with stateless servers (HTTP, JGit/Gerrit) that have existed since Git v2.49; earlier patches in the series generalized `write_command_and_capabilities()` to accept a `struct strvec` of capabilities and a packet reader, and this patch applies that unified function to the `ls-refs` code path.

The patch modifies `get_remote_refs()` in `connect.c` to build its capability list using the new `add_server_options()` and `add_promisor_remote_reply()` helpers, then pass that list to `write_command_and_capabilities()` instead of calling `send_capabilities()` directly and looping over server options manually. The new `add_promisor_remote_reply()` helper is declared in `connect.h` because it will also be needed in `fetch-pack.c` in a later patch of the series; for now it duplicates logic still present in `send_capabilities()`, which the author notes will be removed in a following commit.

Two wire-level changes occur in the `ls-refs` request. First, the order of capability lines after `command=ls-refs` changes from `object-format, promisor-remote, server-option*` to `server-option*, promisor-remote, object-format`; the commit message notes this is harmless because `serve.c` and JGit accept capabilities in any order. Second, the `command=ls-refs` line no longer ends with a newline, which the author describes as harmless because servers chomp newlines. These changes prepare for the eventual removal of `send_capabilities()` and the unification of all protocol v2 command writing through `write_command_and_capabilities()`.
