This is the third patch in Dirk Gouders' five-patch v4 bugfix series fixing bounds handling in Git's UTF-8 display-width code. Specifically, it patches `utf8_strnwidth()` in `utf8.c` to stop processing when skipping ANSI escape sequences consumes the entire remaining bounded string: after the loop that advances `string` past any leading SGR sequences via `display_mode_esc_sequence_len()`, the code now checks `if (string >= end) break;` before calling `utf8_width()`, preventing a read past the `end` boundary when the escape sequence ends exactly at or beyond the given length. The patch adds a unit test `test_utf8_width__strnwidth_ansi` in `t/unit-tests/u-utf8-width.c` covering corner cases such as `utf8_strnwidth("\033[31mhello", 4, 1)` returning 3, `len` 5 returning 0, and `len` 6 returning 1. This addresses the specific scenario where an ANSI sequence terminates the string within the provided boundary, complementing the `remainder`-based fixes in the later patch 4 of the same series.
