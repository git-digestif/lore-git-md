This is a refactoring patch, the fourth of six in Patrick Steinhardt's packfile lifecycle series. It introduces `packfile_free()` in `packfile.c` and `packfile.h` as a dedicated function that combines `packfile_close()` with `free(3p)`, replacing the repetitive two-step pattern currently scattered across nine call sites. The commit message notes this abstraction will be extended in a subsequent patch to maintain a list of all packs, foreshadowing the process-wide limit tracking that arrives in patch 6/6.

The patch mechanically converts manual cleanup sequences in `builtin/index-pack.c`, `commit-graph.c`, `connected.c`, `http-walker.c`, `http.c`, `midx-write.c`, and `odb/source-packed.c` to use the new helper. It also swaps bare `free(p)` calls for `packfile_free(p)` in the error paths of `parse_pack_index()` and `packfile_from_idx()` inside `packfile.c` itself, ensuring consistent resource handling even when the pack was not fully opened. No behavioral change is intended; this is pure API consolidation.

For follow-up context: the series base is f7de81456940dd6f3274e461149bba12965de609, and this patch builds directly on the renames from patch 2/6 (which established the `packfile_` prefix) and the inlining from patch 3/6. The next patch (5/6) is expected to move process-wide packfile limits to global scope, and patch 6/6 will both fix limit handling and honor the do-not-close flag during close operations, at which point `packfile_free()` will likely gain logic to unlink packs from that global list. The patch is cleanly motivated and touches only the expected files, with no test changes required since behavior is unchanged.
