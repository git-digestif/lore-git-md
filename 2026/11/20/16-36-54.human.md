This is a brief review reply in the ongoing `utf8.c` bounds-handling thread, specifically responding to the `[PATCH v2 1/4]` discussion about `display_mode_esc_sequence_len_counted()`. Junio C Hamano agrees with Andy Koppe that adding a `size_t *remainder` out-parameter to the function is unnecessary: callers who want unbounded, NUL-terminated-style scanning can simply pass `SIZE_MAX` as the length argument, and because the function already returns the number of bytes consumed, they can compute any remainder they need by subtracting that value from their own known length. Junio explicitly endorses this simpler approach, closing the design question without requiring the extra parameter.

The exchange settles a point of API minimalism in the series: the end-pointer variant needs only the `start` and `end` pointers, keeping the signature clean and avoiding the quadratic `strlen()` cost that had motivated the original objection to the wrapper. While this particular reply references the v2 iteration of the patch, the same end-pointer design carried forward into the later v4 series that Dirk Gouders subsequently reposted. No code changes are proposed in this email itself; it is purely an acknowledgment that the simpler formulation is preferable.
