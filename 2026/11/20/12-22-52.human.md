This is a **refactoring** patch -- the fourth of seven in Patrick Steinhardt's v2 preparatory series for pluggable commit graphs, part of the broader ODB abstraction effort.

The patch exposes a new public function, `commit_graph_validate_chain()`, which wraps the two existing static helpers that check whether a loaded commit-graph chain has mixed generation-data or Bloom-filter settings across its layers. Previously these validation calls lived inline at the end of `load_commit_graph_chain_fd_st()`; now they are callable from outside `commit-graph.c`, with the header updated to declare the new symbol and document its behavior.

The motivation is forward-looking: in the follow-up part 2 of this effort, loading of commit graphs will move into the object database backend, and the backend will need to perform this same validation itself. By promoting the validation into a shared public API now, the patch prepares the code for that move without changing any current behavior.

The diff is minimal and clean -- nine lines added in `commit-graph.c` plus the header declaration -- and fits squarely into the series' goal of making commit-graph internals ready for backend-specific control. As a standalone change it is uncontroversial; its value lies in enabling the larger refactoring that follows.
