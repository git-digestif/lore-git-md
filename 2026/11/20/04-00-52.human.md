This is a bugfix for `git clone --revision` when used with SHA-256 repositories.

The patch addresses a bug where cloning a repository that uses the SHA-256 object format with `--revision` set to a raw SHA-256 commit hash fails. The refspec item is appended to the remote's fetch list early in `cmd_clone`, before the destination repository's hash algorithm has been determined, so `parse_refspec` interprets the hash using the wrong algorithm and the clone does not work as intended.

The fix records the index of the `--revision` refspec when it is first appended, then re-initializes that specific refspec item after `create_reference_database` has set up the repository's hash algorithm. This ensures the hash is parsed under the correct algorithm. The patch also adjusts the condition guarding the call to `wanted_peer_refs` so that a raw SHA-256 hash is treated similarly to the existing SHA-1 exact-hash case.

The change is small and focused, touching only `builtin/clone.c`, and includes a new test in `t/t5621-clone-revision.sh` that verifies cloning a SHA-256 repository with a SHA-256 `--revision` value produces a detached HEAD at the correct commit with no refs and no configured fetch refspec. The commit message clearly explains the root cause, and the test coverage looks appropriate for the fix.
