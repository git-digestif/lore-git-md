This is a **substantive review reply** from Junio C Hamano on patch v9 1/4, which refactors the `branch.<name>.deleteMerged=false` opt-out check into a static helper named `branch_opted_out()` in `builtin/branch.c`.

Junio raises a design concern about the helper's name being "selfish" -- too generic, assuming that deleting merged branches will remain the only destructive operation needing an opt-out, while the configuration key `branch.<name>.deleteMerged` is specific to that single operation, creating an impedance mismatch. He offers three resolution paths: (1) rename the function to explicitly reference `deleteMerged`, (2) make the function truly generic for any destructive operation and rename the config key to something like `noClobber`, or (3) keep the generic name but pass the operation as a parameter (e.g., `branch_opted_out("main", "deleteMerged")`), with the function remaining a pure boolean check without operation-specific side effects. This feedback directly affects how patch 3/4 (`--delete-integrated`) will reuse the helper, and the naming question remains open in the thread.
