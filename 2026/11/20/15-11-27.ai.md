This is patch 4 of 5 in Dirk Gouders's v4 bugfix series targeting bounds handling in `utf8_strnwidth()` and `utf8_width()`.

The patch fixes `utf8_strnwidth()` in `utf8.c` so that it passes the remaining bounded length to `utf8_width()` rather than NULL, which previously allowed the width calculation to read past the `end` pointer when a multibyte UTF-8 sequence was truncated by the `len` argument. The change computes `remainder = end - string` before each call and passes `&remainder` as the optional boundary parameter, ensuring `utf8_width()` respects the same bound as the outer loop. This addresses the case where callers provide a length that cuts a CJK or other multibyte character in half; instead of reading beyond the buffer (which can trigger SIGBUS on mmapped regions), the function now treats the incomplete sequence as having the width specified by the remaining bytes.

The patch adds a new unit test `test_utf8_width__strnwidth_cjk_chopped` in `t/unit-tests/u-utf8-width.c` verifying that `utf8_strnwidth("三bytes long, 二columns wide", 1, 1)` returns 1 and that `utf8_strnwidth(..., 3, 1)` returns 2, confirming that chopped multibyte sequences no longer cause out-of-bounds reads. This is the fourth patch in the series; the preceding patches established the end-pointer API for ANSI escape scanning and corrected documentation, while the following patch (5/5) introduces the greedy `display_mode_esc_sequence_len_all()` helper. The series remains under review with no integration branch placement yet.
