This is a refactoring patch -- the seventh and final patch of v2 part 1 in Patrick Steinhardt's series preparing commit-graph internals for the ODB abstraction effort.

The patch removes redundant bookkeeping from `struct write_commit_graph_context` by deriving all layer information directly from the passed-in commit-graph chain. Previously, `write_commit_graph_file()` relied on parallel arrays tracking hashes, filenames, and the base graph name that the caller had to populate; now it walks the `base_graph` linked list and the new tip to build `chain_hashes` and `kept` string lists locally, eliminating four array fields from the context structure and shrinking the function by a net 33 lines. This makes the path-dependent logic cleanly separable from the generic write path, which is exactly what part 2 needs to move this code into the "files" backend in `odb/source-files.c`.

There is one deliberate behavior change: `expire_commit_graphs()` now runs only when writing the new graph succeeds, whereas previously it ran regardless of outcome. The commit message notes this is arguably an improvement, since expiring old graphs after a failed write was puzzling.

The patch is well-motivated and mechanically clean -- it touches only `commit-graph.c`, removes more code than it adds, and sets up the next series without introducing new behavior beyond the expiration timing fix. It remains under review with no merge status yet.
