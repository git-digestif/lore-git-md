This is the first patch of a five-patch bugfix series (v4 1/5) targeting out-of-bounds reads in Git's UTF-8 display-width handling. Authored by Junio C Hamano but sent by Dirk Gouders as part of his series, it introduces an optional end pointer to `display_mode_esc_sequence_len()` so the function can scan ANSI SGR sequences without reading at or beyond a caller-supplied buffer boundary. The signature changes from `display_mode_esc_sequence_len(const char *s)` to `display_mode_esc_sequence_len(const char *start, const char *end)`, where a NULL `end` preserves the old NUL-terminated behavior.

The patch updates all in-tree call sites to use explicit end pointers: `utf8_strnwidth()` now passes `string + len` as the end, `strbuf_add_wrapped_text()` computes `end = text + strlen(text)` upfront and passes it in its ANSI-skipping loop, `strbuf_utf8_replace()` passes its existing `end` variable, and `pretty.c` passes `ch + 1` in `format_and_pad_commit()`. This directly addresses the O(n²) performance objection Andy Koppe raised against a wrapper that would have called `strlen()` repeatedly; the end-pointer design avoids that cost.

The patch adds a new clar unit-test file `t/unit-tests/u-utf8-ansi.c` (wired into both `Makefile` and `t/meson.build` ahead of the existing `u-utf8-width.c`) with three test functions: `test_utf8_ansi__sgr_len_null` covering NUL-terminated strings, `test_utf8_ansi__sgr_len_end_ptr` covering bounded buffers including truncated sequences, and `test_utf8_ansi__sgr_len_start_end_swap` verifying that swapped start/end pointers return 0. Files touched are `utf8.c`, `utf8.h`, `pretty.c`, `Makefile`, `t/meson.build`, and the new test file.

This patch is the foundational piece of the v4 repost of the retracted v3 series; it establishes the end-pointer API that the subsequent patches build on to fix the actual bounds violations in `utf8_strnwidth()` and add the greedy `display_mode_esc_sequence_len_all()` helper. No part of this series has been merged or queued in any integration branch; it is under review awaiting substantive feedback on the v4 formulation.
