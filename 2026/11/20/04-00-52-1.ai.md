This is a bugfix for `git clone --revision` in `builtin/clone.c`, now in its second iteration (`[PATCH v2]`). Under protocol v2, the command fails with "fatal: Remote revision ... not found in upstream origin" when given a valid commit hash whose algorithm differs from the local default -- for example, a SHA-256 hash when the destination uses SHA-1 -- even though the object exists on the remote. Under protocol v1 the same situation produced a different error ("couldn't find remote ref"). The root cause is that the refspec item for `--revision` was appended to `remote->fetch` before the destination repository's hash algorithm was configured, so `parse_refspec` interpreted the hash under the wrong algorithm.

The fix delays appending the `--revision` value until after the remote's hash algorithm has been gathered and assigned to `the_repository->hash_algo`; the code now explicitly sets `remote->fetch.hash_algo = the_repository->hash_algo` before calling `refspec_append`. A new integer `rev_refspec_idx` tracks the index of this refspec item and is passed to `wanted_peer_refs`, which uses it to flag the revision refspec when calling `get_fetch_map`. The patch also adjusts the ref-prefix logic so that when `--revision` is used, "HEAD" is not added to `transport_ls_refs_options.ref_prefixes` and the prefix list is left empty, causing all advertised refs to be requested.

A regression test is added in `t/t5621-clone-revision.sh`: it initializes a SHA-256 source repo, then runs `GIT_DEFAULT_HASH=sha1 git clone --no-local --revision=$oid`, verifying that the clone succeeds, `HEAD` resolves to the provided OID, no refs are created in the destination, and `remote.origin.fetch` remains unset. The diff touches only `builtin/clone.c` (38 lines changed, including the `wanted_peer_refs` signature) and the test file.

This addresses a concrete user-facing failure with a targeted fix and clear commit message. The cross-algorithm scenario is covered by the new test, and the change introduces no apparent design controversy -- it simply defers refspec construction until the hash context is known.
