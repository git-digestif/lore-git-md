This is a maintainer review of patch 2/3 in Adrian Ratiu's v2 bugfix series for the `compatObjectFormat` interoperability layer. Junio C Hamano engages with the commit message wording and test design at a surface-to-substantive level: he accepts the explanation that range arguments like `A..B` do not use the desired output hash and are out of scope, but flags that describing the fix as covering "single revision" cases is slightly ambiguous because it excludes invocations like `git rev-parse --output-object-format=sha1 main next` where multiple single revisions are requested simultaneously. He otherwise approves the approach, calling the test "clever and clean."

The patch itself adds a `< 0` return check on `repo_oid_to_algop()` in `builtin/rev-parse.c` so that `git rev-parse --output-object-format` dies with "cannot map object %s to %s" instead of silently printing the storage OID when an object has no compat mapping -- aligning it with `git pack-objects` and other callers. The test in `t/t1500-rev-parse.sh` uses a `RUST` prerequisite, initializes a SHA-256 repository, writes an object before enabling `extensions.compatObjectFormat` (so it receives no compat mapping), then sets the config and verifies that requesting the SHA-256 ID succeeds while requesting the SHA-1 compat ID fails with the expected error. This approach avoids manual object-directory copying, which would be fragile under the upcoming ODB abstraction.
