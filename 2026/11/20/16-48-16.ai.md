This is a preparatory refactoring patch, the third of eight in Christian Couder's v2 series fixing the missing `promisor-remote` reply in protocol v2 `fetch` commands. It modifies `write_command_and_capabilities()` in `connect.c` to accept an additional `struct packet_reader *reader` parameter, preparing the function to eventually replace `send_capabilities()` for `ls-refs` and `bundle-uri` requests in a later commit. When the `reader` argument is non-NULL, the function sets `reader->hash_algo` to the object format advertised by the server (defaulting to SHA-1 if the server does not send an `object-format` capability), mirroring the behavior currently found in `send_capabilities()`; when `reader` is NULL, it retains the existing behavior of validating the server's `object-format` against `the_hash_algo` and dying on mismatch. All three current call sites -- `send_object_info_request()` in `fetch-object-info.c`, plus `send_fetch_request()` and `negotiate_using_fetch()` in `fetch-pack.c` -- are updated to pass NULL, so this patch introduces no behavior change. The change touches `connect.c`, `connect.h`, `fetch-object-info.c`, and `fetch-pack.c`, and updates the function signature documentation in `connect.h` to describe the dual mode of operation. This is purely mechanical groundwork for the unification of client-side capability writing that the series uses to address the maintainer's objection to the v1 approach.
