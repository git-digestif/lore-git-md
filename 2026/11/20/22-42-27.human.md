This is a documentation patch -- specifically version 4 of a standalone proposal from Okhuomon Ajayi that codifies line-wrapping and paragraph conventions for emailed contributions to the Git mailing list. The patch updates three contributor-facing documents: `Documentation/CodingGuidelines`, `Documentation/ReviewingGuidelines.adoc`, and `Documentation/SubmittingPatches`.

The core guidance added to each file states that emailed prose should be wrapped to a maximum of 72 columns, matching the existing commit message convention, so that text remains readable on an 80-column terminal after a few levels of quoting. It also instructs readers to leave a blank line between paragraphs, and clarifies that a block of quoted text counts as a paragraph and should therefore be surrounded by blank lines as well.

Version 4 incorporates all three revisions Okhuomon Ajayi accepted after Junio C Hamano's review of v3. The patch now uses the phrase "E-mailed text intended for human-to-human communication" rather than "patch message", avoiding any confusion that diff lines themselves should be wrapped. It also adopts the imperative form "Tell readers to leave a blank line..." with an explicit rationale, and retains the qualifier "before and after it, too" to make clear that quoted blocks need blank lines on both sides.

The change is purely additive, adding twenty lines across the three files with no code or behavior modifications. It is based on commit 7fb6055e678f800320d8ab8cd8f201d9493d1ba0 and remains under review, with no integration branch placement announced yet. The patch looks well-crafted and responsive to maintainer feedback, having already addressed both the scope and wording concerns raised in earlier iterations.
