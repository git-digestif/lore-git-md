This is a review clarification within the `[PATCH v4 0/5]` utf8.c bounds-handling series. Andy Koppe corrects his earlier suggestion that callers of `display_mode_esc_sequence_len()` could pass `SIZE_MAX` as the length to achieve unbounded scanning: he points out that computing the `end` pointer via `end = s + len` with `len` set to `SIZE_MAX` would be undefined behavior due to pointer arithmetic overflow, meaning callers must always pass a valid, bounded length. He concludes that no actual call sites lack knowledge of the remaining buffer length and would need to fall back to `strlen()`, which supports keeping the function signature as `(const char *start, const char *end)` without a `size_t *remainder` out-parameter, consistent with Junio C Hamano's endorsement in the parent email. The exchange closes the technical question of how length limits should be expressed in the API, but introduces no new substantive review of the v4 patches themselves; the series continues to await broader feedback on the split of the former patch 4 into v4 patches 4 and 5.
