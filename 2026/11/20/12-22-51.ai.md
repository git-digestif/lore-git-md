This is a refactoring patch, specifically the third of seven in Patrick Steinhardt's v2 series preparing commit-graph internals for the ODB (object database) abstraction. The patch simplifies the interface for reading a single commit-graph layer by removing the redundant `dir` parameter from the loading function and renaming `load_commit_graph_one_fd_st()` to `commit_graph_read()`. Instead of populating the graph's directory path inside the low-level loader, the path is now set in `load_commit_graph_one()`, which is the function slated to move into the "files" backend in the deferred part 2 of this series.

The motivation is preparatory: as the series progresses toward making commit-graph locations a backend responsibility, generic read/write functionality should not be exposed to directory paths. By consolidating path assignment into the single caller that already knows the directory, the code avoids populating paths in two different locations and better isolates the backend-agnostic reading logic. The diff touches `commit-graph.c`, `commit-graph.h`, and `builtin/commit-graph.c`, with the latter updating its call site in `cmd_commit_graph_verify()` to use the new name and signature.

No behavior changes or on-disk format modifications are introduced. The patch is a clean interface simplification that aligns with the series' broader goal of separating commit-graph I/O from path derivation, setting up the eventual introduction of `read_commit_graph` and `write_commit_graph` callbacks in `struct odb_source`. The series remains under review with no merge status reported.
