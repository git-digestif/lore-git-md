This is a maintainer review of patch 1/3 in Adrian Ratiu's v2 series fixing bugs in the `compatObjectFormat` SHA-1/SHA-256 interoperability layer. Junio C Hamano approves the patch, which adds a guard in `verify_repository_format()` in `setup.c` rejecting configurations where `extensions.compatObjectFormat` matches `objectFormat` (or the default hash when `objectFormat` is unset). The review is surface-level -- a brief endorsement without deep technical analysis -- but carries maintainer authority. Junio agrees the trigger condition represents an incorrectly configured repository rather than a `BUG()`, so returning a clear error message is more appropriate than aborting.

The patch prevents a crash where every Git command in Rust-enabled builds aborted with `BUG: repository.c:204: hash_algo and compat_hash_algo match`, including `git config`, which left the repository unreachable and unrecoverable through Git itself; non-Rust builds died separately because `compatObjectFormat` requires Rust. The new check runs before any Rust-only code paths, so both build types now receive the same diagnostic spelling the key as `extensions.compatObjectFormat`, and the test in `t/t1302-repo-version.sh` exercises both `sha1` and `sha256` without a `RUST` prerequisite, recovering the repository via `git config unset --file=...`.

This is the uncontroversial first of three fixes in the series; patches 2 and 3 address `git rev-parse --output-object-format` mapping failures and unknown commit header handling during conversion respectively. No objections are raised here, and the patch already incorporates Patrick Steinhardt's earlier cosmetic feedback on capitalization and test syntax. The maintainer's approval signals this patch will likely proceed without contention, unlike patch 3 which removes a deliberate 2023 safety check and remains under substantive discussion.
