This is a bugfix that tightens validation in Git's split commit-graph chain loading, and it serves as the first patch in a larger refactoring series toward pluggable commit graphs.

The commit fixes a long-standing gap in how Git verifies commit-graph layers: previously, each layer's trailer hash was only checked when the next layer was linked on top of it, meaning the topmost layer was never verified and a corrupted base layer would be silently used until a link attempt failed. Patrick Steinhardt moves the validation into the loading path itself, verifying each layer's trailer hash against the chain file immediately after it is read, so the chain is cut at the first mismatch rather than continuing with an invalid layer.

This is patch 1 of 7 in v2 part 1 of a series that prepares commit-graph internals for the ODB abstraction effort, deferring the actual pluggable backend hooks to a follow-up part 2. The series is built on `ps/commit-graph-write-refactor` and remains under review with no merge status yet.

The patch updates `t/t5324-split-commit-graph.sh` to expect the stricter behavior and adds two new tests confirming that corrupted trailer hashes are now detected in both the base and topmost layers.

The change is well-motivated and addresses a real correctness issue in chain validation, though it does alter behavior that two existing tests implicitly relied upon. No on-disk format changes are involved.
