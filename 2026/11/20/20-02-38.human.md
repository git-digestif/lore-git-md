This is a maintainer review from Junio C Hamano on the third patch of Harald Nordgren's v9 series, which adds the `git branch --delete-integrated` machinery for detecting rebase- and squash-merged branches. Although this particular patch has been treated as largely uncontroversial after earlier rounds, Junio uses this reply to raise several open questions about CLI wording, configuration semantics, and test coverage.

Junio suggests rewording the commit subject to "rebased or squash-merged branches" for grammatical consistency. More substantively, he questions whether the existing `branch.<name>.deleteMerged` config key should silently govern the new `--delete-integrated` flag, proposing instead a more generic `.deleteDone` variable that could anticipate future ways a branch becomes "done." He also flags three specific test gaps: the combination of `--dry-run` with `--delete-integrated`, the opt-out behavior when `deleteMerged` is set to `false`, and verification that `--quiet` actually suppresses output for the new flag.

On design, Junio pushes back against the requirement that `--dry-run` must be paired with either `--delete-merged` or `--delete-integrated`. He argues that a dry run of a plain deletion should report the same protective errors—such as refusing to delete the currently checked-out branch—without demanding a mode flag. He confirms the new mutual-exclusion check between the two deletion flags is correct and well-tested, but asks that `--quiet` coverage be added as well.

This is a substantive review rather than a surface-level one: it engages with configuration naming, default safety semantics, and the completeness of the test suite, though it does not block the patch outright. These points remain open as the v9 series continues under review.
