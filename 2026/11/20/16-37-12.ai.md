This is a volunteer commitment in the ongoing `git history fixup` worktree corruption bug thread. Aniket Gupta responds to Patrick Steinhardt's GitLab issue #772 by offering to send a patch implementing the thread's settled design: `git history` should refuse to update a branch that is checked out in another worktree, or that is currently being rebased when the update would change its tree. Gupta notes this should cover the original report (referred to in the email as "Nikita's report").

The proposed safety check mirrors the protection logic in `git rebase --update-refs` and would prevent the index corruption where staged changes leak into other worktrees sharing the repository. Implementation would touch `builtin/history.c` for the fixup command logic and worktree detection code to identify branches checked out elsewhere, with regression tests expected in both the `git history` and worktree test suites.

No patch has been posted yet; this email establishes intent to implement the conservative "refuse to rewrite" approach rather than attempting best-effort index updates in other worktrees. The thread remains open with the design decision finalized and implementation pending, leaving the exact mechanism for detecting an in-progress rebase and the precise test scenarios as open questions for the eventual patch.
