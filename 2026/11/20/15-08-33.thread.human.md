Ophir Bleicher has posted a single-patch bugfix for `git rev-parse` that corrects a silent wrong-answer case in SHA-256 repositories using SHA-1 compatibility. When a repository enables `extensions.compatObjectFormat` after objects were already written, those pre-compatibility objects have no SHA-1 mapping; previously, requesting `--output-object-format=sha1` for such an object would quietly print the SHA-256 hash instead of failing. The patch makes `cmd_rev_parse()` in `builtin/rev-parse.c` check the return value of `repo_oid_to_algop()` and `die()` with "cannot map object %s to %s" when the conversion is impossible, turning the misleading output into an explicit error.

The change is minimal—four lines in one file—and includes a clear commit message with a reproduction recipe: initialize a SHA-256 repository, write an object, then enable SHA-1 compatibility, and observe that `git rev-parse --output-object-format=sha1 <oid>` now errors instead of emitting the wrong hash. The thread is currently at the initial patch posting; no review feedback or test additions have been discussed yet, though the absence of regression tests in `t/t1006-*` is a likely point for reviewers to raise.
