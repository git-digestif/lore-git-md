This is a review reply in the ongoing discussion of Patrick Steinhardt's v5 series modernizing `git rerere` subcommand handling, specifically responding to Junio C Hamano's comments on patch 11/13 (the `OPT_SUBCOMMAND()` conversion). Patrick agrees with Junio's assessment that the loss of `--rerere-autoupdate` help text in `git rerere -h` is acceptable, and generalizes the observation into a design principle: a default (verb-less) subcommand pattern is tolerable only when the bare command accepts no flags at all; once non-default behavior is requested, the interface should demand an explicit subcommand (e.g., a hypothetical `git rerere perform --rerere-autoupdate`) rather than mixing flags with the implicit default. He notes that this particular ship has sailed for `git rerere` due to backwards-compatibility concerns, but records it as a personal takeaway for future command design. The email contains no code changes and introduces no new objections; it closes the substantive discussion of the help-text discoverability and shell-completion side effects that Junio had flagged for the `OPT_SUBCOMMAND()` conversion, leaving the series under review with no merge status claimed.
