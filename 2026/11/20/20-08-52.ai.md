This is a maintainer review reply to the fourth patch of Harald Nordgren's v9 series implementing `git branch --delete-integrated`, specifically commenting on the gitlink-to-blob crash fix.

Junio C Hamano acknowledges the new regression test for the submodule-to-file type-confusion case and asks whether this was the only corner case requiring a fix in v9. His tone suggests some mild disappointment that the author appears to be reacting to reviewer-discovered bugs rather than proactively hunting for additional edge cases, noting that reviewers have been doing significant work finding corner cases while the author should ideally be finding several times more.

The code change under discussion adds a `base_mode` field to `struct branch_change` in `builtin/branch.c`, populated from `p->one->mode` during `collect_branch_changes()`. The guard in `change_state_at()` is extended to return `CHANGE_MISSING` when `!S_ISREG(change->base_mode)`, which prevents `read_mmblob()` from attempting to read a gitlink (submodule commit) OID as if it were a blob when a path transitioned from submodule to regular file. This directly addresses the crash Jasper Mayone identified in v8 where `fatal: unable to read blob object` occurred on such type changes.

The accompanying test in `t/t3200-branch.sh` sets up a scenario where both a branch and upstream independently replace a submodule `lib` with a regular file containing different content, then verifies that `--delete-integrated origin/next` correctly keeps the `replaces-lib` branch rather than crashing or incorrectly deleting it. The test expects empty output and retention of both `main` and `replaces-lib`.

Within the broader thread context, this v9 iteration incorporates the confirmed crash fix and regression test requested by Jasper Mayone, while the series remains under review with no integration status announced. The patch continues to address the squash-merge detection logic using `ll_merge()` for upstream-modified files, with the `base_mode` guard ensuring type safety when the merge base contains gitlinks.
