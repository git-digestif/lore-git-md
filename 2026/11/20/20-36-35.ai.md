This is a design discussion reply in the review thread for the `git clone --revision` SHA-256 bugfix. Andrei Șova is responding to Junio C Hamano's suggestion to defer refspec creation until after the handshake by explaining a circular dependency that prevents that approach: `refspec_ref_prefixes()` must be initialized before `transport_get_remote_refs()` can fetch the remote refs (which is how the remote hash algorithm is discovered), but the refspec item must exist before the ref prefixes can be computed, so the refspec cannot simply be moved after the handshake.

Instead, Andrei proposes not initializing the ref prefixes when `--revision` is used, noting they serve only as an optimization. This also eliminates the need for the extended `if (refs || ...)` guard in the patch, since `refs` will now reliably be non-NULL after the fetch. No new patch version has been sent yet; the thread remains under review with the implementation approach still being negotiated.
