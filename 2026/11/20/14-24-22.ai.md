This is a refactoring patch -- specifically v9 2/4 in Harald Nordgren's four-patch series introducing `git branch --delete-integrated`.

The patch extends `delete_branches()` in `builtin/branch.c` with a new fourth parameter, `struct strmap *landed_commits`, which maps branch names to the upstream commit where their changes landed. When a branch being deleted appears in this map, the function skips the standard `check_branch_commit()` reachability check and instead reports the landing commit in its output, using the format `Deleted branch %s (was %s, landed as %s)` (and the corresponding `Would delete ...` variant for `--dry-run`), with the landing OID abbreviated via `repo_find_unique_abbrev()`. Both current call sites -- `delete_merged_branches()` and the direct deletion path in `cmd_branch()` -- pass `NULL` for the new argument, so existing behavior is unchanged; this purely prepares the plumbing for patch 3/4, which will populate the map when `--delete-integrated` detects branches whose changes landed upstream via squash or rebase merges. Per the thread context, this patch is considered uncontroversial and ready for integration.
