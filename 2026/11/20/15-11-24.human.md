This is the first patch of a five-patch bugfix series (v4) that fixes out-of-bounds reads in Git's UTF-8 display-width code. Authored by Junio C Hamano and submitted by Dirk Gouders as part of the reposted v4 series, it introduces an optional end-pointer parameter to `display_mode_esc_sequence_len()` so the function never scans at or beyond a given buffer limit. When the end pointer is NULL, the function behaves as before on NUL-terminated strings; otherwise it stops safely at the boundary, addressing both the memory-safety concern (particularly for mmapped regions where reading past the end could trigger SIGBUS) and Andy Koppe's performance objection that counted buffers might otherwise require quadratic scanning via `strlen()`.

The patch updates the three call sites in `utf8.c` -- `utf8_strnwidth()`, `strbuf_add_wrapped_text()`, and `strbuf_utf8_replace()` -- plus one in `pretty.c`, to pass explicit end pointers. It also adds a new unit test file `t/unit-tests/u-utf8-ansi.c` covering both the NUL-terminated and end-pointer forms, including edge cases like swapped start/end pointers. The commit message is clear and well-motivated, and the change is a prerequisite for the subsequent patches in the series that fix `utf8_strnwidth()`'s own bounds handling.
