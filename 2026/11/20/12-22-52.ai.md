This is a refactoring patch that is part of the ongoing ODB abstraction effort. Specifically, it is the fourth patch in the seven-patch v2 part 1 series authored by Patrick Steinhardt, which prepares commit-graph internals for pluggable backends.

The patch exposes a new public function `commit_graph_validate_chain()` in `commit-graph.h` and `commit-graph.c`. This function wraps two existing static validation helpers, `validate_mixed_generation_chain()` and `validate_mixed_bloom_settings()`, which check whether all layers in a commit graph chain were written with compatible generation-data and Bloom-filter settings. Previously these helpers were called directly at the end of `load_commit_graph_chain_fd_st()`; now that call site invokes the new public wrapper instead.

The motivation is forward-looking: in part 2 of this series, commit graph loading will move into the object database backend, and the backend will need to perform this chain validation itself. By making the validation logic publicly available now, the patch prepares the interface without changing current behavior. No on-disk format changes occur, and the internal call site in `load_commit_graph_chain_fd_st()` continues to validate the chain exactly as before, just through the new function.

Files touched are `commit-graph.c` and `commit-graph.h`. The only new symbol is `commit_graph_validate_chain()`, which takes a `struct commit_graph *` pointing at the head of the chain. The patch is small and mechanical, consisting of moving the two validation calls into a new public function and updating the internal caller. It remains under review with no merge status indicated.
