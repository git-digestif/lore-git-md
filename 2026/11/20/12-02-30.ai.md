This is a refactoring patch, the third in Patrick Steinhardt's six-part series polishing the packfile lifecycle API as part of his ongoing ODB abstraction and repack machinery overhaul. Patch 3/6 targets `packfile.c` only, eliminating the static helper `open_packed_git_1()` by inlining its logic into the former caller `open_packed_git()`, which is simultaneously renamed to `packfile_open_pack()` to match the `packfile_` prefix convention established in patch 2/6.

The core change fixes a design smell where the `_1()` sibling deferred error cleanup to its caller, risking a leaked file descriptor if the caller failed to close `pack_fd` on error paths. The patch introduces a common `out:` exit label that calls `packfile_close_fd()` whenever `ret < 0`, allowing all error returns inside the function to use `goto out` instead of returning directly. This consolidates the validation logic -- index opening, file descriptor acquisition, stat checks, pack header signature and version verification, object count validation, and trailing hash comparison -- into a single function with uniform cleanup.

Call sites in `use_pack()` and `is_pack_valid()` are updated to invoke `packfile_open_pack()` instead of the old `open_packed_git()`. No behavioral change is intended beyond the error-path fd cleanup, which should now be more robust. The patch touches 115 lines in `packfile.c` (70 insertions, 45 deletions) and represents a continuation of the incremental modernization strategy outlined in the cover letter, avoiding the churn of renaming `struct packed_git` itself.
