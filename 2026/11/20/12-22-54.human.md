This is a preparatory refactoring patch, part of Patrick Steinhardt's v2 series to make commit-graph storage pluggable within the ODB abstraction effort. It is the sixth of seven patches in this first half of the series.

The patch reworks `write_commit_graph_file()` in `commit-graph.c` to use a single `out:` exit label instead of returning early from multiple error paths. Each former `return -1` now assigns the error to a local `ret` and jumps to the common cleanup, which rolls back the lock file and returns. The successful path sets `ret = 0` before falling through to the same exit. This is explicitly preparation for the next patch, which will add more allocations inside the function that need consistent cleanup; the commit message says the change makes that upcoming diff easier to read.

There is no behavior change here. The function still performs the same split and non-split write logic, creates the same temporary files, and takes the same lock; it merely funnels all exits through one place. The patch is small (19 insertions, 15 deletions) and self-contained, touching only `commit-graph.c`.

As the sixth patch in the series, it sits alongside earlier refactoring that exposed `commit_graph_validate_chain()`, made the chain-linking logic public, and switched merge-strategy decisions from path-based to depth-based comparisons. Together these prepare the ground for part 2, where the actual backend callbacks will live in `odb/source-files.c`. The patch looks clean and deliberately scoped; it does exactly what it says and nothing more.
