This is a discussion reply in the ongoing bugfix thread for `git clone --revision` with SHA-256 repositories, not a new patch version. Andrei Șova responds to Junio C Hamano's suggestion that the refspec creation should be deferred until after the handshake when the hash algorithm is known. He explains that he initially tried this but hit a circular dependency: the ref prefixes must be initialized before fetching remote refs (which is how the remote hash algorithm is discovered), yet the refspec item needs to exist before that fetch can happen.

He now proposes a cleaner resolution: since `refspec_ref_prefixes` are apparently only an optimization, they can be skipped entirely when `--revision` is used. This avoids needing the refspec item during the initial handshake phase. As a side benefit, this change means the `refs` variable will reliably be non-NULL after the fetch, allowing the removal of the extra guard condition that was previously needed because the incorrectly parsed refspec could cause `transport_get_remote_refs` to falsely return nothing.

The email does not include an updated patch, so the thread remains under review with this design discussion now informing the next iteration.
