This is a preparatory refactoring patch (4/8) in Christian Couder's series to fix the missing `promisor-remote` reply in protocol v2 `fetch` commands. It changes how `ls-refs` and `bundle-uri` requests are constructed and sent, buffering them into a `struct strbuf` before a single `write_in_full()` call, rather than writing packets directly to the file descriptor.

The patch modifies `send_capabilities()` in `connect.c` to accept a `struct strbuf *req_buf` instead of an `int fd_out`, switching from `packet_write_fmt()`/`packet_delim()`/`packet_flush()` to their `packet_buf_*()` counterparts. Both `get_remote_refs()` and `get_remote_bundle_uri()` now build their entire request -- command line, capabilities, options, and flush delimiter -- into a local `struct strbuf`, then transmit it with one `write_in_full()`. Because `packet_buf_write()` formats packets identically to `packet_write_fmt()`, the bytes on the wire are unchanged. The error handling does change: write failures now die with "unable to write request to remote" (consistent with `fetch` and `object-info` paths) instead of "packet write with format failed" or a silent SIGPIPE on EPIPE.

This sets up later patches in the series (5/8 through 6/8) to route `ls-refs` and `bundle-uri` through the unified `write_command_and_capabilities()` function, which will ultimately allow the `promisor-remote=...` reply to be included in those requests as well. The patch touches only `connect.c` and introduces no behavior change for existing users.
