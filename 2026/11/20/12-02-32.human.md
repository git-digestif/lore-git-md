This is a refactoring patch, specifically the fifth in a six-patch series from Patrick Steinhardt that polishes the packfile lifecycle API as part of his broader ODB abstraction effort. The patch introduces a process-wide global list of all open packfiles (`all_packfiles`) and rewires the two existing resource limits -- `pack_max_fds` and `core.packedGitLimit` -- to consult that list instead of walking repository-specific structures.

The practical effect is that these limits now behave as their names suggest: they apply across all repositories in the process and are agnostic to the object database backend in use. Previously, both `unuse_one_window()` and `close_one_pack()` downcast the object database to the files backend and iterated only that repository's pack directories, which meant the limits could silently fail when multiple repositories were involved or when a non-files backend was active. By maintaining the list globally in `packfile_new()` and `packfile_free()`, the patch removes that backend assumption and makes the LRU eviction logic genuinely process-wide. The diff is compact -- 13 insertions and 16 deletions confined to `packfile.c` -- and introduces no new user-visible behavior beyond making the existing limits work correctly in more scenarios.
