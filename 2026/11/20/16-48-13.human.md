This is a v2 cover letter for a bugfix series that has grown from three to eight patches to address the maintainer's design feedback. The core problem remains the same: the Git client omits the `promisor-remote=...` reply during protocol v2 `fetch` commands, which breaks fetches against stateless servers (HTTP, JGit/Gerrit) or when only object IDs are requested. Since the capability was introduced in v2.49, the author hopes the fix can land in `maint`.

Where v1 added a dedicated argument to `write_command_and_capabilities()`, this version adopts the generalized approach Junio C Hamano pushed for: patches 1/8 through 6/8 refactor `connect.c` so that `write_command_and_capabilities()` becomes the single function that writes protocol v2 capability lines, while callers (`get_remote_refs()`, `get_remote_bundle_uri()`, `send_fetch_request()`) build a `strvec` of capabilities to pass in. This eliminates the duplication across `send_capabilities()`, `get_remote_refs()`, and `write_command_and_capabilities()` that Junio flagged. The refactoring introduces a few small wire changes -- `session-id` is now sent with `ls-refs` and `bundle-uri` when `transfer.advertiseSID` is set, error reporting for failed writes is unified, capability ordering is adjusted, and trailing newlines after `command=ls-refs`/`command=bundle-uri` are dropped.

Patch 7/8 is the actual fix: `do_fetch_pack_v2()` now builds a capability list that includes `add_promisor_remote_reply()` and passes it through, so the `promisor-remote` reply is always sent with `fetch` requests that ask for a pack. Patch 8/8 documents this requirement in `gitprotocol-v2.adoc`. Tests cover local and HTTP scenarios in `t5710` and a new `t5711`. The author notes that CI failures on his fork appear unrelated to the series.
