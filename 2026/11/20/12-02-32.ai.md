This is **patch 5/6 of a refactoring series** on the packfile lifecycle subsystem, part of Patrick Steinhardt's ongoing ODB abstraction effort. It moves process-wide packfile limits from per-repository scope to a global list, making the enforcement logic backend-agnostic.

The patch introduces a static global `struct packfile_list all_packfiles` in `packfile.c`. `packfile_new()` now appends every new `struct packed_git` to this list via `packfile_list_append()`, and `packfile_free()` removes it via `packfile_list_remove()` before closing and freeing the pack. This global list replaces the previous per-object-database iteration: `close_one_pack()` and `unuse_one_window()` no longer take a `struct repository *` or `struct object_database *` parameter, and they iterate over `all_packfiles` directly instead of walking `odb_source_files_downcast()` directories. This removes the hard assumption that the "files" ref backend is in use, which the commit message identifies as a prerequisite for pluggable object databases.

The change affects the enforcement of two limits: `pack_max_fds` (maximum open file descriptors for packfiles) and `core.packedGitLimit` (maximum mapped packfile data). Both now scan the global list to find least-recently-used packs or windows to close when limits are exceeded. The patch is behavior-preserving for single-repository use but enables true process-wide limits across multiple repositories and future non-files backends. It also sets up patch 6/6, which will fix limit-handling bugs and honor the `do-not-close` flag by operating on this same global list.
