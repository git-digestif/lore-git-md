This is the first patch of Patrick Steinhardt's six-patch packfile lifecycle refactoring series, removing internal packfile statistics from `git fast-import` output. The patch deletes the `pack_report()` function from `packfile.c` and `packfile.h`, strips its invocation from `builtin/fast-import.c` (along with now-unused statistics counters such as `pack_mmap_calls` and `peak_pack_open_windows`), and updates `Documentation/git-fast-import.adoc` to no longer mention packfile details in the `--stats` description. The motivation is that these metrics expose internal implementation details (page size, mmap call counts, pack window usage) that users should not need to see, and that such packfile-specific reporting becomes meaningless once pluggable object databases allow non-packfile storage. The author suggests that if anyone actually needs this data it could later be reintroduced as trace2 output, but for now the packfile subsystem statistics are dropped entirely. As patch 1/6, it precedes the larger API renaming and process-wide limit changes described in the cover letter; the series remains under review and is not queued in any integration branch.
