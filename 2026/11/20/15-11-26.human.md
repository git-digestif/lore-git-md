This is a bugfix, specifically the third patch in Dirk Gouders's five-patch v4 series hardening Git's UTF-8 display-width code against out-of-bounds reads. The patch addresses a corner case in `utf8_strnwidth()` where the ANSI escape sequence skipping logic could consume the entire remaining buffer up to the given length boundary, leaving the subsequent `utf8_width()` call to read past the valid data.

The fix adds a simple guard after the loop that skips SGR sequences: if the string pointer has advanced to or beyond the computed end pointer, the function breaks out early rather than attempting to measure a glyph that does not exist within the bounds. This prevents reading beyond the buffer when an escape sequence happens to end exactly at (or consume) the last bytes of the input range.

The patch also adds unit tests in `t/unit-tests/u-utf8-width.c` covering these boundary conditions, verifying that truncated ANSI sequences at the edge of the length argument return the expected widths without over-reading. Within the broader series, this sits between the documentation correction (patch 2) and the `remainder`-parameter rework (patch 4), and it builds directly on Junio C Hamano's end-pointer variant of `display_mode_esc_sequence_len()` introduced in patch 1. The series remains under review with no integration-branch status yet.
