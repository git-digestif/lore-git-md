Andy Koppe has proposed a new `%(body:trailers=<bool>)` placeholder for Git's pretty-formatting engine that strips the trailer block from commit messages while preserving any trailing content like `Conflicts:` sections. The patch adds a `format_body_without_trailers()` helper in `pretty.c` that reuses the existing trailer-parsing infrastructure, along with documentation and six test cases in `t/t4205-log-pretty-formats.sh`.

Junio C Hamano has reviewed the patch and approves the overall design, noting that having a built-in way to strip trailers without external post-processing complements the existing `%(trailers)` atom and simplifies use cases like `%w` rewrapping and separate coloring. While he raised a couple of implementation questions -- specifically about the `no_divider` flag in `parse_trailers()` and the safety of an `else` clause -- he traced the code paths himself and accepted the current approach as correct.

The review is largely positive, with Junio describing the patch as "nicely done" aside from minor test concerns. He flagged that the `test_when_finished "git reset --hard HEAD^"` cleanup is unsafe if a test fails early, recommending instead that the test capture the original HEAD and reset to that specific commit. He also suggested adding test coverage for repeated options like `trailers=no,trailers=yes` and invalid boolean values such as `trailers=bogus`. No maintainer decision on merging has been made yet; the series remains under review pending these test adjustments.
