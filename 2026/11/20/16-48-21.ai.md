This is the final documentation patch (8/8) in Christian Couder's v2 series fixing the missing `promisor-remote` capability reply in protocol v2 `fetch` commands. It updates `Documentation/gitprotocol-v2.adoc` to explicitly state that clients must send the `promisor-remote=...` reply with every `fetch` command request that asks for a pack, because protocol v2 is stateless and each command is handled independently. The patch adds seven lines clarifying that negotiation-only requests (such as those from `git fetch --negotiate-only`) do not require the reply since they do not request a pack, and notes that object-ID-only fetches may skip `ls-refs` entirely, making the per-command reply essential.

The documentation change accompanies the code fix in patch 7/8, which routes the `fetch` request through the unified `write_command_and_capabilities()` path to actually emit the `promisor-remote` line on the wire. Prior to this series, the client only sent this reply with `ls-refs` and `bundle-uri` commands, causing failures with stateless servers like HTTP-based Git or JGit/Gerrit when objects were only available via promisor remotes. The bug was introduced in Git v2.49 when the capability was first added.

The patch touches only `Documentation/gitprotocol-v2.adoc`, adding text after the existing explanation of when clients should or should not advertise the `promisor-remote` capability. It references the "Capabilities" section's discussion of statelessness and sits near documentation of server-side configuration options (`promisor.advertise`, `promisor.sendFields`) and client-side options (`promisor.acceptFromServer`). The commit is marked `Reported-by: Matt Cote <mcote@nvidia.com>`.

As the capstone of an eight-patch series that grew from an initial three-patch v1, this documentation update reflects the expanded scope that includes unifying client-side capability writing through `struct strvec` helpers (`add_server_options()`, `add_promisor_remote_reply()`) and deleting the now-redundant `send_capabilities()` function. The series remains under review with no maintainer feedback yet on whether the refactoring in patches 1-6 satisfies the objection raised against v1's approach.

Key technical reference for future discussion: the documented requirement that `promisor-remote` must accompany each pack-requesting `fetch` in protocol v2, contrasted with negotiation-only fetches which omit it, and the implication for stateless server implementations that cannot rely on state from previous `ls-refs` or `bundle-uri` commands within the same session.
