This is a review reply within Dirk Gouders's v2 bugfix series for UTF-8 display-width bounds handling, specifically discussing the API design of `display_mode_esc_sequence_len()` in patch 1. Andy Koppe responds to Dirk's proposal to add an optional `size_t *remainder` parameter -- modeled on `utf8_width()` -- to avoid the upfront `strlen()` cost of the NUL-terminated wrapper. Andy argues the extra parameter is unnecessary because callers wanting unbounded scanning can already pass `SIZE_MAX` as the length, and since the function returns the number of bytes consumed, a separate remainder output adds no value. Given that the series has already settled on removing the wrapper entirely and reverting to Junio C Hamano's counted-variant-only approach from v1, this design alternative was not adopted, but the exchange documents the reasoning behind preferring the simpler signature.
