This is a refactoring patch, specifically the fifth of seven in Patrick Steinhardt's v2 series preparing commit-graph internals for pluggable ODB backends. The commit changes how `split_graph_merge_strategy()` decides which existing layers to merge into a new split commit-graph layer and which layer the new one should chain upon. Previously these decisions relied on comparing on-disk directory paths (`g->dir` vs `ctx->dir`) and filenames to determine whether a layer was "local" or a split graph; this patch replaces those filesystem-dependent checks with simple depth counters.

The motivation is to make the merge strategy backend-agnostic. As the ODB abstraction progresses, the backend--not the generic commit-graph code--will control where commit graphs are stored, so path-based comparisons will no longer be reliable. To enable this, the patch adds `mergeable_layers` and `chainable_layers` fields to `struct write_commit_graph_context`. In `commit_graph_write()`, it walks the existing chain once, counting how many topmost layers are local (mergeable) and how many qualify as chainable (either split layers regardless of locality, or local non-split layers that can be converted), then passes these counts to the merge strategy.

Inside `split_graph_merge_strategy()`, the loop now compares a running `depth` against `ctx->mergeable_layers` rather than calling `strcmp()` on directories, and the check for whether the new base can be chained uses `ctx->chainable_layers`. The old logic that inspected `g->filename` against `get_commit_graph_filename(g->dir)` is removed in favor of the precomputed count. The commit message explains the two rules clearly, and the diff is focused and mechanical, touching only `commit-graph.c` with no on-disk format changes or behavior differences for the current files backend.

This is a clean, well-motivated preparatory step. By moving the locality and split-status determination into `commit_graph_write()`--where the backend context is already known--and reducing the merge strategy to simple arithmetic, the patch tees up part 2 of the series, where path derivation and these counts will presumably be supplied by the pluggable backend itself. The commit message is concise but sufficient, and the refactoring preserves existing behavior while removing a hard dependency on the filesystem layout.
