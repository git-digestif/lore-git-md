This is a volunteer offer in an ongoing bug report thread about `git history fixup` corrupting the index in other worktrees. Aniket Gupta is stepping forward to implement the fix the thread has already settled on: making `git history` refuse to rewrite a branch that is checked out in another worktree when the update would change its tree, mirroring the safety check used by `git rebase --update-refs`. This directly addresses Toon Claes's original report of spurious staged changes leaking across worktrees after running `fixup`.

The design decision was confirmed earlier when Patrick Steinhardt, the original author of `git history`, endorsed the conservative approach and opened GitLab issue #772 to track it for the next release cycle. Aniket's message signals that the issue remains open to community patches and that he intends to send one covering both the cross-worktree case and concurrent rebase scenarios. No code has been posted yet, so the bug is still live, but the implementation path is now clear and unopposed.
