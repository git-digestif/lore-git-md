Dirk Gouders has sent the second patch of a four-patch v3 series that corrects the doc comment for `utf8_strnwidth()` in `utf8.c`. The fix is purely documentary: the old comment described the input as a null-terminated string and claimed the function returns `strlen()` on invalid UTF-8, whereas the corrected text notes that the string is bounded by the `len` argument and that `len` is returned in the invalid case, matching the actual behavior of the API. The patch carries a `Helped-by` trailer from Andy Koppe and touches no code, making it a low-risk cleanup within the broader series.
