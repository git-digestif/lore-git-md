This is a **refactoring** patch, specifically the second of seven patches in v2 part 1 of Patrick Steinhardt's series preparing commit-graph internals for the ODB abstraction effort. It simplifies how commit graph chains are linked during loading and makes the linking logic reusable for a future object database backend.

The patch renames the static `add_graph_to_chain()` to the now-public `commit_graph_link_base()` and changes its signature to accept only the new tip layer `g` and the existing chain `base`, eliminating the redundant `struct object_id *oids` array parameter. Instead of comparing against a pre-read array of OIDs from the chain file, the function now walks the `base_graph` linked list to derive each base layer's hash directly from the already-loaded `struct commit_graph` instances. Error semantics shift from boolean (1 for success, 0 for failure) to the integer convention where 0 means success and negative values indicate errors. The caller `load_commit_graph_chain_fd_st()` is updated accordingly: it no longer allocates the `oids` array, uses a stack-allocated `struct object_id` for per-line parsing, and calls `commit_graph_link_base(g, graph_chain)` to attach each verified layer.

Files touched are `commit-graph.c` and `commit-graph.h`. The commit message notes this prepares for a subsequent change (deferred to part 2 of the series) that will move chain-creation logic into the object database backend. No on-disk format changes occur, and user-visible behavior remains unchanged apart from the internal error-code convention.
