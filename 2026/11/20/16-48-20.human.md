This is the seventh patch in Christian Couder's eight-part bugfix series, and it delivers the actual fix for the missing `promisor-remote` reply in protocol v2 `fetch` commands.

The bug is that when a client accepts promisor remotes during a fetch, the `promisor-remote=...` capability reply was only being sent with the `ls-refs` and `bundle-uri` commands, not with the `fetch` command itself. This works over `file://` or `ssh://` because the same upload-pack process handles both commands and remembers the acceptance, but it breaks over HTTP where each request runs in a fresh process, and it also breaks when fetching by object ID only (which skips `ls-refs` entirely). In those cases the server doesn't know the client accepted a promisor remote, so it rejects packs that reference missing objects with "could not fetch <oid> from promisor remote".

The fix moves capability construction up into `do_fetch_pack_v2()` in `fetch-pack.c`, which now builds a `struct strvec` once using `add_server_options()` and `add_promisor_remote_reply()` and passes it down to `send_fetch_request()`. That function hands the list to `write_command_and_capabilities()` (the unified writer established in earlier patches of this series), ensuring the reply goes out with every pack-requesting `fetch`. Negotiation-only requests from `negotiate_using_fetch()` don't ask for a pack, so they correctly skip the reply.

The patch adds tests in `t/t5710-promisor-remote-capability.sh` verifying the reply appears in the `fetch` request during clone and during object-ID-only fetches, plus a new `t/t5711-promisor-remote-capability-http.sh` that reproduces the HTTP stateless-server scenario and confirms the clone succeeds with the large object lazily fetched from the promisor remote.

This patch sits at the end of the refactoring sequence; patches 1/8 through 6/8 had reorganized `connect.c` to eliminate the duplicate capability-writing paths, and this patch applies that new structure to the `fetch` path. The series remains under review, with no maintainer response to v2 yet.
