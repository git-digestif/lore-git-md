This is patch 2/8 in Christian Couder's v2 series fixing the missing `promisor-remote` reply in protocol v2 fetch, specifically extending `session-id` advertisement beyond `fetch` to cover `ls-refs` and `bundle-uri` requests. The patch modifies `send_capabilities()` in `connect.c` to read `transfer.advertiseSID` and, when set and the server supports it, write `session-id=<trace2_session_id>` alongside the other capability lines. This changes behavior only for users who explicitly enable `transfer.advertiseSID`, since the default remains off; the commit message references 1e905bbc00 (2020) which originally added session-id only to fetch-pack without explaining the omission.

The patch sits within the preparatory refactoring block (patches 1/8 through 6/8) that unifies client-side capability writing before the actual bugfix lands in 7/8. It touches `connect.c` and adds two test cases to `t/t5705-session-id-in-capabilities.sh`: one verifying `git ls-remote` sends the client session ID when only `ls-refs` is requested, and another using `test-tool bundle-uri ls-remote` to confirm the ID appears when only `bundle-uri` is sent. The author notes that over `file://` and `ssh://` transports where one upload-pack process handles multiple commands, the server will now log the session-id twice per process, which is harmless.
