This is a refactoring patch, the third in a seven-patch series preparing commit-graph internals for the ODB abstraction effort. Patrick Steinhardt is splitting the work so that this v2 part 1 handles only internal cleanups, while the actual pluggable backend hooks come later in part 2.

The patch renames `load_commit_graph_one_fd_st()` to `commit_graph_read()` and removes its directory-path parameter. Previously, the directory was being recorded in two different places: inside the low-level loader and again in `load_commit_graph_one()`. The change consolidates this so that `load_commit_graph_one()` -- which will eventually move into the "files" backend -- is solely responsible for populating both the directory and filename fields. This keeps path-derivation logic out of the generic graph-reading code, setting up the later move where the ODB backend owns the locations from which commit graphs are read.

The diff is small and mechanical, touching `commit-graph.c`, `commit-graph.h`, and the `verify` subcommand in `builtin/commit-graph.c`. No behavior changes; it simply makes the function signature cleaner and moves path handling to the layer that will eventually own it. The commit message is clear about the motivation, tying the change directly to the upcoming backend split.
