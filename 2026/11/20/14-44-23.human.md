This is a bugfix patch series (v3, four patches) targeting the UTF-8 display-width code in `utf8.c`, fixing bounds handling in `utf8_strnwidth()` and `utf8_width()` so they no longer read past the end of the caller's buffer -- including the mmapped-region SIGBUS edge case -- along with a documentation correction.

The series is authored by Dirk Gouders, with the first patch contributed by Junio C Hamano. Patch 1 reworks `display_mode_esc_sequence_len()` to take an end pointer instead of relying on NUL-termination, eliminating a potential O(n²) degradation and a wrapper function; patches 2 through 4 then use that bounded scanner to keep `utf8_strnwidth()` and `utf8_width()` within their `len` arguments, plus new unit tests in `t/unit-tests/u-utf8-ansi.c` and `u-utf8-width.c`. The changes touch `utf8.c`, `utf8.h`, `pretty.c`, and the build files.

From the thread discussion, the technical direction is settled: the earlier debate over whether to keep a NUL-terminated wrapper has been resolved by adopting the end-pointer approach, and all substantive objections are closed. The remaining items that held up v2 -- meson test ordering, a "null-terminated" wording nit, and formatting -- are addressed in this v3. Patch 4 in particular earned an approving "Well spotted, and nicely done" from Junio.

The series looks well-crafted and ready for integration: the commit messages explain the motivation clearly, the fixes address a real correctness issue with out-of-bounds reads, and the test coverage includes edge cases like chopped CJK characters. It is currently under review with no outstanding technical concerns.
