Thread identity: v3 bugfix series (patch 1/4) from Dirk Gouders hardening the UTF-8/ANSI escape-sequence parser against buffer over-reads; co-signed by Junio C Hamano. Thread type: patch series.

Core problem or goal: `display_mode_esc_sequence_len()` in `utf8.c`/`utf8.h` previously relied on NUL termination and could read past the end of counted buffers. The fix adds an optional `const char *end` parameter: when NULL the function behaves as before (NUL-terminated input); when non-NULL it never dereferences `*end` or beyond, allowing safe use on `<string, len>` pairs.

Current status: v3, first patch of a four-part series; under review, not merged.

Key technical details: signature change to `display_mode_esc_sequence_len(const char *p, const char *end)`; callers updated -- `utf8_strnwidth()` computes `end = string + len`, `strbuf_add_wrapped_text()` sets `end = text + strlen(text)`, `strbuf_utf8_replace()` forwards its existing `end`, and `pretty.c:format_and_pad_commit()` passes `ch + 1`. New clar unit-test file `t/unit-tests/u-utf8-ansi.c` (wired into `Makefile` and `t/meson.build`) with three cases: NULL-end legacy path with SGR sequences, explicit end at exact sequence boundaries, and swapped start/end returning 0. Commit message notes the change avoids the O(n^2) degradation risk Andy Koppe previously flagged.
