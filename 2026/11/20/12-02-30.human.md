This is a refactoring patch, specifically the third of six in Patrick Steinhardt's packfile lifecycle series. It cleans up the internal logic of `packfile.c` by inlining the helper function `open_packed_git_1()` into its sole caller and renaming the result to `packfile_open_pack()`. The commit message explains that the split between the two functions existed only because error handling and closing the file descriptor on failure was considered too awkward; the patch fixes this by introducing a common `out:` exit path that closes the descriptor automatically when an error occurs, making the separate helper unnecessary.

The change is entirely contained in `packfile.c` and alters no external behavior. It does, however, rename the primary function used to open a packfile from `open_packed_git()` to `packfile_open_pack()`, which fits the naming convention established in the previous patch of the series (`open_pack_index` became `packfile_open_index`, and so on). The new name also clarifies that the function opens the pack file itself rather than the index or other associated files.

Within the broader series, this patch continues the incremental modernization of the packfile subsystem that Patrick has been driving as part of his ODB abstraction and repack machinery overhaul. While earlier patches handled mechanical renames across many files, this one addresses a deeper structural wart in a single file. The commit message is clear and well-motivated, identifying a real design smell rather than making a change for its own sake. It looks like a solid, low-risk cleanup that should be easy to review.
