Thread identity: Feature patch (v1, no prior versions) from Andy Koppe <andy.koppe@gmail.com> adding a new `%(body:trailers=<bool>)` placeholder to Git's pretty-formatting engine, now under substantive review by Junio C Hamano.

Core problem or goal: Provide a `%(body)` atom that behaves identically to the existing `%b` (raw body) by default, but accepts a boolean `trailers` option. With `trailers=no`, it strips the trailer block (as identified by the existing `%(trailers)` machinery) and the blank line separating it from preceding text, while preserving any content following the trailer block such as `Conflicts:` sections or comment lines.

Current status: Under review. Junio C Hamano has reviewed the patch and approved the overall design, noting that having a counterpart to `%(trailers)` that strips the trailer block without external post-processing makes `%w` rewrapping and separate coloring cleaner, and that modeling the syntax after `%(trailers)` and `%(describe)` fits existing conventions. No merge or integration decision has been announced.

Key technical details: Implementation in `pretty.c` via new `format_body_without_trailers()` helper that reuses trailer-parsing infrastructure (`parse_trailers()`, `trailer_block_start/end()`) with `no_divider` set, splicing the body around the detected trailer range. New `parse_body_options()` handles the `:trailers[=...]` argument syntax using `match_placeholder_bool_arg()`, which Junio praised for cleanly handling bare options, boolean values, repeated options, and unclosed placeholders. Documentation updated in `Documentation/pretty-formats.adoc`. Six new test cases in `t/t4205-log-pretty-formats.sh` cover equivalence with `%b`, unknown-option pass-through, trailer omission, `Conflicts:` handling, trailing content preservation, and empty-body edge case. Use cases listed: hiding trailers in compact logs, reflowing body with `%w` without disturbing trailers, coloring trailers separately, and scripting/UI access without post-processing `%b`. Junio observed that calling `parse_trailers()` with `no_divider` populates and immediately frees the trailer list because `trailer_block_get()` is file-local to `trailer.c`, accepting this trade-off. He also verified that omitting an `else` clause when `trailer_start` is not greater than `body` is safe because `find_trailer_block_start()` in `trailer.c` skips the first paragraph, tracing the caller in `format_commit_one()` where `msg` is set to `subject_off` and `body` to `body_off`.

Open questions and loose ends: Junio flagged that `test_when_finished "git reset --hard HEAD^"` in the tests is unsafe because if the test fails before creating the commit, subsequent tests run in a repository state with one commit fewer than expected; he suggests capturing `go_back_to=$(git rev-parse --verify HEAD)` first and resetting to that instead. He also recommends adding test cases for repeated options like `trailers=no,trailers=yes` and invalid boolean values such as `trailers=bogus`.

Participant positions: Andy Koppe proposed the feature with a clean, self-contained implementation and thorough test coverage. Junio C Hamano reviewed substantively, approved the design direction and implementation approach, and raised only minor test-safety and test-coverage nits, concluding the patch looks nicely done apart from those.
