Thread identity: Feature patch (v1, no prior versions) from Andy Koppe <andy.koppe@gmail.com> adding a new `%(body:trailers=<bool>)` placeholder to Git's pretty-formatting engine.

Core problem or goal: Provide a `%(body)` atom that behaves identically to the existing `%b` (raw body) by default, but accepts a boolean `trailers` option. With `trailers=no`, it strips the trailer block (as identified by the existing `%(trailers)` machinery) and the blank line separating it from preceding text, while preserving any content following the trailer block such as `Conflicts:` sections or comment lines.

Current status: New patch posted for review; no maintainer or reviewer response yet.

Key technical details: Implementation in `pretty.c` via new `format_body_without_trailers()` helper that reuses trailer-parsing infrastructure (`parse_trailers()`, `trailer_block_start/end()`) with `no_divider` set, splicing the body around the detected trailer range. New `parse_body_options()` handles the `:trailers[=...]` argument syntax, mirroring option style of `%(trailers)` and `%(describe)`. Documentation updated in `Documentation/pretty-formats.adoc`. Six new test cases in `t/t4205-log-pretty-formats.sh` cover equivalence with `%b`, unknown-option pass-through, trailer omission, `Conflicts:` handling, trailing content preservation, and empty-body edge case. Use cases listed: hiding trailers in compact logs, reflowing body with `%w` without disturbing trailers, coloring trailers separately, and scripting/UI access without post-processing `%b`.
