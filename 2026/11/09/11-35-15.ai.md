This is an Outreachy proposal draft for a feature that adds configurable fetch ordering to promisor remotes in partial clones. The author, Hussain Sitamouwala, is seeking feedback on their design before sending a formal patch series.

The proposal targets a long-standing limitation in Git's partial clone functionality: when multiple promisor remotes exist, the order in which they are tried for fetching missing objects is fixed and cannot be configured by users or servers. The planned implementation would add three components: (1) tests to lock in current behavior, (2) a local configuration setting (`remote.<name>.priority`) to control ordering, and (3) a server-advertised priority field with documented precedence rules.

The design is well-motivated and technically grounded. The author has already contributed two patches to Git (one documenting current promisor remote behavior, another converting `check-ref-format` to use `parse-options`), demonstrating familiarity with the codebase and review process. They propose a sensible config shape (`remote.<name>.priority` with lower values tried first) and a defensive protocol design that ignores malformed server input. The threat model section (section 8) is particularly thorough, identifying edge cases like integer overflow and duplicate fields that will need testing.

The proposal acknowledges a competing patch that implements an alternative config shape (`promisor.fetchOrder`) and includes contingency plans if that lands first. The timeline is realistic, with design review scheduled early (week 2) and implementation broken into small, testable patches. The author's plan to send a protocol RFC before coding is especially prudent given the cross-cutting nature of this change.

This looks like a serious, well-prepared proposal that addresses a real user need. The feature would benefit users with multiple promisor remotes (e.g., those using partial clones in large organizations with regional mirrors) by allowing them to prioritize cheaper or faster remotes. The implementation appears technically sound, with appropriate attention to backward compatibility and security.
