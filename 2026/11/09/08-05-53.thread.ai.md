Core problem or goal
The `--follow` option in `git log` suffers a severe performance regression (28 s → ~7 min for `git log --stat --follow` on a single file in linux.git) introduced by commit 304812ed33 (June 2026). That commit added a custom loop (`propagate_follow_pathspec_to_parent`) that runs full rename-detection diffs between every merge and each parent, even when the parent does not yet contain the followed path. The goal is to remove this loop and fold path propagation into the existing `log_tree_diff` parent loop, eliminating redundant diffs while preserving the same visible output.
