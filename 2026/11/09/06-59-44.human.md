This is the first patch in a two-part test infrastructure series that introduces `test-tool genbytes` to address a performance bottleneck in Git's test suite on macOS. The patch implements the new command, which writes arbitrary bytes (specified as two lowercase hexadecimal digits, e.g., `61` for 'a') and converts 14 existing test scripts to use it instead of the slower `genzeros | tr` pipeline. The series is functionally complete and under review, with the only remaining feedback being minor implementation details.

Patrick Steinhardt's review raises two points. First, he suggests replacing `strtoimax()` with `git_parse_signed()` for parsing the count argument, a straightforward improvement. Second, and more substantively, he questions the readability of the hexadecimal interface, noting that `test-tool genbytes 61 500` obscures the intent (writing 500 'a' characters) unless the reader knows ASCII values. He proposes extending the interface to accept escape sequences like `\NNN` or `\xNN` for clarity and future extensibility, such as supporting multi-byte strings.

The patch itself is well-motivated and addresses a real performance issue—macOS CI jobs improve by 70–79%—while maintaining backward compatibility. The implementation is clean, though the hexadecimal interface may be less intuitive than the original `tr`-based approach. Steinhardt's feedback is substantive but not blocking; the series is otherwise ready for integration. If the interface is revised, it would likely require a minor update to the second patch, which removes the now-obsolete `test-tool genzeros`.
