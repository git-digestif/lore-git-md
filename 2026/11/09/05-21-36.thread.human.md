This thread is Fien Dora's Outreachy internship proposal to convert the manual option-parsing loops in `git diff-index` and `git diff-tree` to the shared `parse_options()` API, with Christian Couder and Siddharth Asthana serving as mentors. The proposal is still in the discussion stage with no code posted yet; Fien's earlier microproject was accepted into `next`, so she is a known contributor. The main open questions are whether `parse_options()` can faithfully reproduce the current edge-case behavior -- the `diff_merges_suppress_m_parsing()` interaction with `-m`, the `--stdin`/`--merge-base` mutual exclusivity, abbreviated option names, and repeated options -- and how it will interact with `setup_revisions()`.

The only new development this round is a brief side exchange on mailing-list etiquette: Richard Kerry asked for guidance on breaking up long reply blocks, and Junio C Hamano confirmed that Git already asks contributors to wrap text to roughly 70 columns and said he would welcome a documentation patch formalizing a preference for blank lines between quoted blocks. That sub-thread is closed and has no bearing on the proposal itself, which remains under discussion with no reviews or objections so far.
