This is a test infrastructure patch discussion. Kristofer Karlsson responds to Johannes Sixt’s `printf`-based workaround for the macOS `tr(1)` performance bottleneck by confirming it works but noting two practical limitations: the macOS `/bin/sh` (bash 3.2) `printf` builtin silently fails for field widths exceeding `INT_MAX - 15`, and it consumes 2.1 GB of RSS to build each field in memory. He proposes a chunked version that writes 1 MiB blocks, achieving the same speed improvement (800–900 s → 170–280 s on macOS) without a new test-tool command. The helper function is already implemented locally as a single-patch alternative to the `genbytes` series, but Kristofer holds off sending it until more feedback arrives. The thread remains focused on choosing between the chunked-`printf` helper and the `test-tool genbytes` command; no new design questions or workflow changes are introduced.
