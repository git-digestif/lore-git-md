This is a follow-up in the RFC thread about adding `--verbose` support to `git history reword`. Phillip Wood weighs in on the opt-in vs. opt-out debate, siding with Karthik Nayak’s proposal to make diff display the default behavior for `git history reword`. He argues that the command’s experimental status provides flexibility to adjust the default later if it proves problematic, and notes that he would also favor making `commit.verbose` the default for `git commit` if starting from scratch. He adds a practical consideration: scripted editing becomes simpler if the diff is not present by default, but still endorses the opt-out approach for this feature. The thread now has three distinct positions—opt-in with a flag (Jelle van der Waa, D. Ben Knoble), opt-in with config support (Phillip Wood’s earlier feedback), and opt-out (Karthik Nayak, now supported by Phillip Wood)—with no clear consensus yet on either the interface or the default behavior. The discussion remains focused on user experience and Git’s conventions rather than implementation details.
