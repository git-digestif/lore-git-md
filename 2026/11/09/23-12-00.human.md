That gap allowed a memory leak (fixed in commit 6272f3bd17) to go unnoticed. The new tests verify core functionality: handling multiple trees in a batch, ignoring trailing blank lines, processing `-z` (NUL-terminated) input, and failing gracefully on missing objects. One test also documents the current (but potentially unintended) behavior when consecutive blank lines produce an empty tree.

Laveesh’s review goes beyond surface-level feedback. The review also endorses keeping the test for consecutive blank lines, while suggesting the documentation question belongs in the commit message’s "---" section rather than the main body.
