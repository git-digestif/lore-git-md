This is the fourth patch in Patrick Steinhardt’s v2 series optimizing GitLab CI speedups, focusing on a **performance improvement in the test suite**. The patch targets `t0027-auto-crlf.sh`, a test script that verifies Git’s CRLF conversion logic across 2,600 test cases—making it one of the slowest tests, particularly on Windows (over 10 minutes).

The bottleneck lies in `checkout_files()`, which repeatedly spawns separate `rm` and `git checkout` processes for each of five files during repository state resets. The patch consolidates these into a single `rm` and `git checkout` invocation, reducing process overhead and index rewrites. This yields a **20% runtime reduction across all platforms**, with Windows seeing a **~2.5-minute improvement** (from ~10 minutes to ~7.5 minutes). The change is mechanical and low-risk, replacing a loop of individual file operations with a batched approach.

This aligns with the series’ broader goal of CI speedups, where earlier patches addressed SDK installation and build optimizations.
