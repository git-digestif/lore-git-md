This is a refactoring patch converting the `git check-ref-format` built-in command to use Git’s `parse-options` API. The patch is part of the ongoing effort to standardize argument parsing across all built-in commands, though it is not explicitly tied to any larger in-flight series.

The change replaces the manual argument parsing loop in `cmd_check_ref_format()` with a declarative `struct option` array and a call to `parse_options()`. All existing options (`--normalize`, `--print`, `--allow-onelevel`, `--refspec-pattern`) are preserved with identical behavior, now expressed using the standard `OPT_BOOL_F`, `OPT_BIT`, and `OPT_BIT_F` macros. The patch also introduces a new `builtin_check_ref_format_usage_options` array to hold the two usage strings that were previously inlined in the `usage()` call.

The conversion is mechanical and follows the established pattern seen in other built-in commands. The patch touches only `builtin/check-ref-format.c`, adding the necessary `#include "parse-options.h"` header and no other files. No user-visible behavior changes are introduced, and the commit message does not claim any functional improvement.

This is the initial version (v1) of the patch, sent as part of an Outreachy contribution. The patch is under review but has not yet received any feedback. The conversion appears well-executed and aligns with the project’s preference for consistent argument parsing, so it is likely to be uncontroversial unless reviewers identify edge cases in the option handling.
