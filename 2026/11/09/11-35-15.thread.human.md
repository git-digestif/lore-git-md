This thread is an Outreachy proposal draft from Hussain Sitamouwala seeking feedback on a planned feature to add configurable fetch ordering to promisor remotes in partial clones. The proposal addresses a long-standing limitation where Git currently uses a fixed, unconfigurable order when fetching missing objects from multiple promisor remotes.

Hussain—a contributor with two prior Git patches—proposes adding a local configuration setting (`remote.<name>.priority`) to control fetch order, along with a server-advertised priority field. The design is well-considered, with thorough attention to edge cases (like integer overflow and duplicate fields) and a clear precedence model. The proposal also acknowledges a competing patch (`promisor.fetchOrder`) and includes contingency plans if that lands first. The timeline is realistic, with early design review and implementation broken into small, testable patches.

This feature would benefit users with multiple promisor remotes (e.g., large organizations with regional mirrors) by allowing them to prioritize faster or cheaper remotes. The proposal is technically grounded, with appropriate safeguards for backward compatibility and security. No feedback has been posted yet, so the design is still open for discussion.
