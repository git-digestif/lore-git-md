This is a performance-motivated refactoring patch in the `log` subsystem, specifically targeting the `--follow` option for rename detection in non-linear history. It is the fourth patch in a five-patch series (v5) by Miklos Vajna.

The patch removes a custom function (`propagate_follow_pathspec_to_parent`) and its associated loop that were introduced in an earlier commit (304812ed33, June 2026) to handle path propagation across merge parents. That implementation caused a severe performance regression—`git log --stat --follow` on a single file in linux.git ballooned from 28 seconds to nearly seven minutes—because it ran full rename-detection diffs between every merge and each of its parents, even when the parent did not yet contain the followed path. Instead of adding more special-case logic to fix the regression, this patch simplifies the code by moving the path-propagation logic directly into the existing `log_tree_diff` parent loop, right after the diff that detects the rename. Merge commits are now diffed once per parent (silently when only following paths), and the actual merge diff is shown only if explicitly requested (`-c`, `--cc`, or `--remerge-diff`).

The diff touches only `log-tree.c`, removing 55 lines and adding 41, resulting in a net reduction of 14 lines. The commit message is clear about the motivation, the regression, and the trade-off: no immediate performance gain, but a cleaner foundation for the follow-up patch that will address the slowdown. No new tests or documentation are introduced; the patch is purely internal plumbing.
