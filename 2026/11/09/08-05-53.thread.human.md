This thread is about a performance refactoring for `git log --follow`, which currently suffers a severe slowdown (from 28 seconds to ~7 minutes) when tracing file history across merges in large repositories like linux.git. The issue stems from a 2026 commit that added redundant rename-detection diffs for every merge parent, even when the parent doesn’t contain the followed path. Miklos Vajna’s patch (v5 4/5 in a five-patch series) removes this custom loop and integrates path propagation into the existing `log_tree_diff` parent loop, reducing redundant work while preserving the same output.

His rewrite separates the concerns of merge-diff display (triggered by `-c`, `--cc`, or `--remerge-diff`) from the silent path-propagation logic used when `--follow` is active, and he asks whether his version is functionally equivalent.
