This thread is about a performance regression in `git log --follow` that was introduced in June 2026 (commit 304812ed33). The regression made `git log --stat --follow` on a single file in linux.git nearly 15 times slower—from 28 seconds to nearly seven minutes—because the code was running full rename-detection diffs between every merge and each of its parents, even when the parent didn’t yet contain the followed path.

Miklos Vajna’s five-patch series (now at v5) addresses this by refactoring the internal plumbing in the `log` subsystem. The fourth patch, which just arrived, removes the custom function and loop that were added in the problematic commit and instead moves the path-propagation logic directly into the existing `log_tree_diff` parent loop. The result is a net reduction of 14 lines in `log-tree.c` and a cleaner foundation for the follow-up patch that will actually restore the lost performance. No new tests or documentation are included; this is purely internal code cleanup. The series is still under review, and no maintainer decision has been recorded yet.
