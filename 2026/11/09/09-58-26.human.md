This is the fifth patch in Patrick Steinhardt’s seven-part series to speed up GitLab CI. It targets the `t0027-auto-crlf.sh` test script, which has long been a bottleneck—especially on Windows, where it previously took 480 seconds to run.

The patch caches the expected output files that `compare_files()` and `compare_ws_file()` generate. These helper functions are called over a thousand times during the test, yet they repeatedly recompute the same expected output from a small set of input files. By writing the expected output to `.expect` and `.ws-expect` files on the first run and reusing them thereafter, the patch eliminates redundant `tr` and `sed` invocations. The result is a 20–25 % reduction in runtime: Windows drops from 480 to 380 seconds, macOS from 71 to 54 seconds, and similar gains are seen on other platforms.

The change is purely an optimization—no behavior is altered, and the test still cleans up its temporary files. The implementation is straightforward: a single `test -f` check guards each transformation, and the cached files are left in place for subsequent calls. This patch complements the earlier optimizations in the series (such as the single `rm`/`git checkout` reset in patch 4) and keeps the focus on reducing process overhead in the test suite.
