Subject: [PATCH 5/5] log: speed up --follow for merge-heavy histories
Series version: v1 (final patch in a 5-patch series)
Originating author: Miklos Vajna
Thread type: patch series (performance fix)

Core problem or goal
Restore performance of `git log --follow` in repositories with many merges, where a June 2026 regression (commit 304812ed33) caused a 14× slowdown (28 s → 6 min 43 s) on a linux.git test case. The regression stems from `log_tree_diff()` now diffing each merge against *every* parent with rename detection enabled, even when the path is unchanged relative to one parent.

Current status
Under review; this is the fifth and final patch in the series. No prior versions of this patch exist. The series has not been queued in any integration branch.

Key technical details
- Subsystem: log-tree (builtin/log.c → log-tree.c)
- New symbols: `tree_has_path`, `commit_has_path`, `follow_same_parent`, `follow_parent_changed_dropped_file`, `follow_has_rename_source`, `follow_needs_renames`
- Behavior change: two-phase diff strategy—first diff without rename detection to find a “same” parent, then skip further diffs against other parents unless renames are still needed
- Performance: linux.git test case now 42 s (vs 6 min 43 s pre-fix)
- Files touched: log-tree.c only (~140 lines added)
