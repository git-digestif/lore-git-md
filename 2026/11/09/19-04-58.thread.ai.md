Subject: [PATCH 0/2] archive: remove USE_THE_REPOSITORY_VARIABLE
Series version: v2
Originating author: Srujith A Poojary (Outreachy contributor via GitGitGadget)
Thread type: patch series (refactoring)

Core problem or goal
Remove the `USE_THE_REPOSITORY_VARIABLE` macro from Git’s archival modules (`archive-tar.c`, `archive-zip.c`, `archive.c`, `archive.h`) by replacing implicit use of the global `the_repository` with explicit `struct repository *repo` parameters. A supporting change in `submodule.c` ensures commit abbreviation uses the submodule’s repository context, fixing a correctness issue where submodule diffs could resolve commit abbreviations against the superproject’s object database instead of the submodule’s. The series is part of the ongoing `the_repository` removal effort led by René Scharfe and others.

Current status
Under review; v2 posted in response to Junio C Hamano’s feedback on v1. The v2 revision fully restructures repository parameter passing: `init_tar_archiver()` now calls `repo_config()` at its start and uses `args->repo->hash_algo` instead of `the_hash_algo`, while `builtin/archive.c` temporarily retains `USE_THE_REPOSITORY_VARIABLE` to bridge the transition until all archival modules are converted. The series touches nine files: `archive-tar.c`, `archive-zip.c`, `archive.c`, `archive.h`, `builtin/archive.c`, `builtin/upload-archive.c`, `diagnose.c`, `submodule.c`, and the new test `t/t4041-diff-submodule-option.sh`. No functional changes to user-visible behavior; the submodule fix remains a correctness improvement.

Key technical details
- Files/subsystems: archive subsystem (`git archive`, `git upload-archive`), submodule commit abbreviation in diff headers, diagnostic archive creation.
- New/renamed symbols: all archive-related functions (`init_tar_archiver`, `init_zip_archiver`, `init_archivers`) now take an explicit `struct repository *repo` parameter; `USE_THE_REPOSITORY_VARIABLE` macro removed from archive modules except as a temporary measure in `builtin/archive.c`. New helper variable `struct repository *repo` in `submodule.c` to select the correct repository context for commit abbreviation (submodule’s repository if available, otherwise the provided repository context). Updated call sites in `cmd_archive()`, `cmd_upload_archive_writer()`, and `diagnose.c` to pass the appropriate repository context.
- Old-vs-new behavior: no functional change for archive operations; submodule diffs now resolve commit abbreviations against the submodule’s object database (correctness fix). Diagnostic archives now use the correct repository context for ZIP initialization.
- On-disk format changes: none.
- Test coverage: new test in `t/t4041-diff-submodule-option.sh` verifies submodule commit abbreviation remains correct, including edge cases with colliding commit prefixes in superproject and submodule object databases. The test uses `test_oid_cache` to handle both SHA-1 and SHA-256 repositories.

Open questions and loose ends
The primary open question is whether the v2 revision fully addresses Junio’s concern about repository initialization in `cmd_archive()`. The revised approach moves `repo_config()` to the start of `init_tar_archiver()` and uses `args->repo->hash_algo`, but reviewers may verify edge case handling when `cmd_archive()` is invoked outside a valid repository context (due to `RUN_SETUP_GENTLY`). The temporary `USE_THE_REPOSITORY_VARIABLE` macro in `builtin/archive.c` is also a loose end, pending full conversion of all archival modules.
