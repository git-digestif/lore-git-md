This is a CI/build system patch, part of Patrick Steinhardt’s v2 series to speed up GitLab CI pipelines. This specific patch (2/7) targets Windows runners, which are the slowest part of the CI matrix.

The problem is straightforward: Windows test jobs currently spend 34 seconds downloading and extracting a build artifact that contains roughly 1,800 unnecessary intermediate `.obj` files. The fix is equally simple—add an `exclude` rule to the GitLab CI configuration so those files are not included in the artifact. The result is a 50 % reduction in artifact handling time (34 s → 17 s) for every Windows test job.

The change is minimal (two lines in `.gitlab-ci.yml`) and risk-free; it only affects the artifact packaging, not the build itself or any test logic. No new symbols or on-disk formats are introduced. The patch is already part of a series that Junio has called “interesting” and “fully made sense,” so unless someone spots an unintended side effect, it looks like a clear win.
