This is a follow-up in the RFC discussion about adding `--verbose` support to `git history reword`. Karthik Nayak proposes a more radical change: instead of adding a `--verbose` flag, he suggests making the diff display the *default behavior* for `git history reword`, removing the need for an option entirely.

His rationale is straightforward: showing the diff while editing the commit message is unambiguously useful, and he sees no downside to making it the default. This would simplify the interface by eliminating the need to debate flag names (`--verbose`, `--show-diff`, etc.) or whether to support `commit.verbose` config. The proposal is a clear departure from the current patch series, which follows the precedent of `git commit --amend --verbose` by making the diff opt-in.

The suggestion is likely to be controversial. While it aligns with the principle of "sensible defaults," it breaks consistency with `git commit --verbose`, which requires an explicit flag. The thread has not yet seen other participants weigh in on this idea, so its reception remains uncertain. If adopted, it would require a significant rework of the current patches.
