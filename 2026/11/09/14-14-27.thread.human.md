This thread is about a potential compatibility issue between Git and zlib 1.4, which changed how raw deflate operations report completion. Sven Strickroth initially raised the question, asking whether Git’s zlib usage might be affected by the new behavior—where `Z_STREAM_END` is returned instead of `Z_OK` when deflate completes exactly at the end of the output buffer.

Patrick Steinhardt has now audited the relevant code and concluded that Git is unaffected. His review focused on `archive-zip.c`, the only file in Git that uses raw deflate. He examined two key loops where `Z_FINISH` is passed to `git_deflate`: one that writes to an `xmalloc`-allocated buffer and another that streams output. Both loops already handle `Z_STREAM_END` correctly—the first loop’s exit condition (`while (result == Z_OK)`) naturally terminates on `Z_STREAM_END`, and the second loop explicitly checks for it. No changes to Git are needed.

The thread is effectively resolved, pending any further objections or additional audit findings from other contributors. No patch or follow-up discussion is expected unless someone identifies an edge case Patrick missed.
