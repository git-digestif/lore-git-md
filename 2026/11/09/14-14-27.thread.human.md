This thread is a heads-up about a potential compatibility issue with zlib 1.4. Sven Strickroth reports that zlib 1.4, released to address security concerns, now returns `Z_STREAM_END` instead of `Z_OK` when raw deflate completes exactly at the end of the output buffer. He’s asking whether this behavioral change affects Git’s zlib usage.

So far, this is just a question—no patches or decisions have been made. The thread is narrowly focused on the low-level compression layer, so if you’re not working on Git’s internals or platform compatibility, you can probably skip it for now. Maintainers or contributors familiar with Git’s zlib callsites may need to audit the code to ensure it handles the new return value correctly. No responses or reviews have been posted yet.
