This is the sixth patch in Patrick Steinhardt’s seven-patch CI/build system series (v2) targeting GitLab CI speedups. It refactors the `t1092-sparse-checkout-compatibility.sh` test script to reduce redundant repository setup overhead.

The patch addresses a performance bottleneck in `t1092`, where the `init_repos()` function recreates three test repositories (full checkout, sparse checkout, sparse index) from scratch over 100 times during test execution. On Windows, this overhead accumulates to over 10 minutes of runtime. The optimization introduces a one-time setup of template repositories (`full-checkout.template`, `sparse-checkout.template`, `sparse-index.template`) during the `setup template repositories` phase, then copies these templates into place for each test iteration. This change reduces Windows test runtime by approximately 3 minutes, with no impact on Linux performance (already ~30 seconds).

The implementation is straightforward: the patch adds a new `setup template repositories` test helper that initializes the sparse-checkout definitions once, then modifies `init_repos()` to copy these templates instead of recreating repositories from the `initial-repo` baseline. The diff shows a net reduction in process spawning (fewer `git sparse-checkout` and `git config` calls), which is the primary source of the speedup. No new symbols or on-disk format changes are introduced.

This is a targeted refactoring that preserves the test’s behavior while measurably improving CI performance. The approach aligns with the series’ broader goal of reducing process overhead in test scripts, and the patch is uncontroversial given its clear before/after metrics and lack of behavioral changes. It complements the other optimizations in the series (e.g., cached expected output in `t0027`, reftable backend in `t5551`) without introducing dependencies on them.
