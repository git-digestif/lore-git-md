This thread is a bug report from Harold Hunt about Git’s change detection failing on macOS/APFS when files are modified via `mmap` without an explicit `msync()`. The issue arises because APFS does not update `mtime` on `mmap` writes, causing Git to miss modifications until `munmap()` is called (which updates `ctime` but not `mtime`). Harold is exploring whether the project considers this edge case worth fixing and has floated the idea of checking APFS’s generation number or falling back to content examination as a potential solution.

Brian M. Carlson’s reply clarifies that Git’s own `mmap` usage is unaffected by this quirk, as it only maps immutable or atomically replaced files (like packs and indexes). He also notes that POSIX does not require `mtime` updates for `mmap` writes without `msync()`, meaning APFS’s behavior is technically compliant. While Brian dismisses the idea of an LLM-generated patch, he does not take a position on whether the project should address the issue for third-party tools that might `mmap` working-tree files. The discussion remains open, with no patch or concrete fix proposed yet. Key questions—such as the importance of this edge case and the performance tradeoffs of content examination—are still unresolved.
