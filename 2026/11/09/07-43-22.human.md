This is a **test infrastructure patch** revisiting the design of `test-tool genbytes` in response to Patrick Steinhardt’s review. The author, Kristofer Karlsson, proposes abandoning the hexadecimal interface (`61` for ASCII `'a'`) in favor of a simpler, more readable design: keeping the existing `test-tool genzeros` for NUL-byte generation and adding a new `test-tool genbytes <char> [<count>]` that accepts a literal character (e.g., `a`, ` `) for all other cases. This change would revert the series to a v1-like structure (without the final patch that removed `genzeros`) and eliminate the need for escape sequences or hexadecimal parsing.

The motivation is clarity: none of the 16 test scripts that currently use `tr(1)` or `genzeros` actually need a specific byte value beyond NUL, so a literal-character interface avoids the cognitive overhead of hexadecimal codes. The proposal also addresses Johannes Sixt’s concern about churn by leaving existing `genzeros` callers untouched. Kristofer asks Junio C Hamano whether this simpler approach would be acceptable, given Junio’s earlier suggestion to use hexadecimal for consistency.

If adopted, this would likely require a v3 of the series, with the first patch introducing `genbytes <char>` and converting the non-NUL callers, and the second patch remaining as a no-op (or dropped entirely). The buffer allocation issue raised by Junio (256 KB stack buffer) would still need resolution, but the interface debate would be settled. The patch looks well-motivated and responsive to review feedback, though the final decision rests with Junio.
