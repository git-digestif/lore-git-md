This is a surface-level review comment on the first patch of Kristofer Karlsson’s two-patch series introducing `test-tool genbytes` to replace slow `tr(1)` invocations in the Git test suite. Junio C Hamano points out that allocating a 256 KB buffer on the stack in `test-genbytes.c` is risky, as stack sizes are limited (8 MB on Linux and macOS, 1 MB on Windows by default). While the current implementation works for a short-lived test helper, he suggests declaring the buffer as `static` to avoid potential stack overflow, noting that the function is only called once per process and does not need reentrancy. The comment is purely about code hygiene and portability, with no bearing on the patch’s core functionality or the ongoing `printf` vs. `genbytes` debate. The series remains under review, and this is a minor, easily addressed nit.
