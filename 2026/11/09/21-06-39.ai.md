This is Junio C Hamano’s reply in the thread fixing the `git apply --check` crash. He clarifies a boundary condition: a `diff --git` line that appears *in the commit message body* (not in the actual diff) is not valid input from `git diff` or `git format-patch`, even if `git format-patch` accidentally emits it. The responsibility for filtering out such garbage lies with `git am`, not `git apply`. This reinforces the series’ strict-validation philosophy—`git apply` should reject anything that Git’s own tools would not generate as part of a real diff. The comment does not alter the patch’s direction but tightens the rationale for rejecting malformed headers.
