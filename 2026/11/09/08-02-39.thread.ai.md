Core problem or goal
Improve `git log --follow` for non-linear histories, specifically fixing a regression where `--follow` would miss renames in merges of unrelated histories (e.g., subtree merges). The regression was introduced in an earlier version of this series and causes `follow_needs_renames()` to incorrectly return `0` when no merge base exists, disabling rename detection.

Current status
Under review. This is the second iteration of a six-patch series. The series as a whole is a mix of performance improvements and correctness fixes for `--follow`. Patch 2/6 (this email) is a targeted bugfix addressing a review comment from Patrick Steinhardt on v1. The fix restores the intended behavior from commit `304812ed33d` (June 2026) and adds test coverage in patch 1/5.

Key technical details
- Subsystem: `log` (rename-following logic for `--follow`)
- Key function: `follow_needs_renames()`
- Behavior change: When no merge base exists (e.g., unrelated histories), the function now returns `1` (enabling rename detection) instead of `0`.
- Test coverage: Added in patch 1/5 of the series.
- On-disk format: No changes.
