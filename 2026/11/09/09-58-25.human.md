This is the fourth patch in Patrick Steinhardt’s seven-part series to speed up GitLab CI. It targets a specific bottleneck in the `t0027-auto-crlf.sh` test script, which verifies Git’s CRLF conversion logic across 2,600 test cases. On Windows, this test alone takes over ten minutes to run, making it a significant contributor to CI runtime.

The patch optimizes the `checkout_files()` helper function, which resets repository state between test cases. Previously, the function removed and checked out each of the five test files individually, spawning ten separate processes per invocation. The new version batches these operations into a single `rm` and a single `git checkout`, reducing process overhead and index rewrites. The change cuts runtime by about 20% across all platforms—roughly 2.5 minutes on Windows—and maintains the same test coverage without altering behavior.

The commit message is clear and well-motivated, explaining both the problem (excessive process spawning) and the solution (batching operations). The diff itself is minimal, touching only the test script’s setup logic, and the performance improvement is measurable and consistent. This patch is part of a broader effort to optimize CI bottlenecks, and its impact is already validated in the series’ GitLab merge request, where it contributes to a 29-minute to 18-minute reduction in macOS pipeline runtime.

No substantive objections were raised in the v1 review, and the v2 version incorporates Junio C Hamano’s stylistic feedback while preserving the performance gains. The patch is low-risk, focused, and directly addresses a known pain point in the test suite. It looks ready for `next` unless new concerns emerge.
