This thread is about a bugfix for `git log -m --follow` that corrects a regression in merge commit history tracking. Miklos Vajna identified that when using `-m --follow` on a file involved in a diamond-merge scenario (where two branches rename the same file differently before merging), the history from the second parent's side is incorrectly omitted. The issue stems from the parent loop in `log_tree_diff()` failing to restore the original path between parents, causing the diff to compare against the wrong file path.

The fix is small and targeted: it saves the merge's path before iterating over parents, restores it before each diff, and ensures the correct path is recorded for each parent. The patch includes a new test case that verifies the full history is now shown for the diamond-merge scenario. The change is confined to `log-tree.c` and the test suite, with no broader implications for other Git functionality. There’s been no review feedback yet, so the patch is still under initial consideration.
