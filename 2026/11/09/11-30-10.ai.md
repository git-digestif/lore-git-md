This is a documentation patch that completes the technical reference for Git's `parse-options` API. It adds missing documentation for two flags (`PARSE_OPT_ONE_SHOT` and `PARSE_OPT_SHELL_EVAL`) and nineteen macros (`OPT__SUPER_PREFIX`, `OPT__VERBOSITY`, `OPT_BITOP`, `OPT_STRVEC`, `OPT_UYN`, `OPT_NOOP_ARG`, `OPT_COLUMN`, `OPT_CONTAINS`, `OPT_NO_CONTAINS`, `OPT_WITH`, `OPT_WITHOUT`, `OPT_CLEANUP`, `OPT_PATHSPEC_FROM_FILE`, `OPT_PATHSPEC_FILE_NUL`, `OPT_AUTOSTASH`, `OPT_DIFF_UNIFIED`, `OPT_DIFF_INTERHUNK_CONTEXT`, `OPT_IPVERSION`, and `OPT_ALIAS`). The patch also corrects the signature of `OPT__FORCE` to include its `flags` argument.

The patch touches only `Documentation/technical/api-parse-options.adoc` and is purely additive, making no behavioral changes to the codebase. It brings the documentation into alignment with the current state of `parse-options.h`, filling gaps that have existed for years (notably `PARSE_OPT_ONE_SHOT`, which was introduced in 2019 and never documented). The commit message explains the rationale: comprehensive documentation makes it easier for contributors to choose the right API, and omissions can lead to confusion or misuse.

This is the third iteration of the patch. The previous version (v2) addressed all prior feedback, and v3 incorporates the final two surface-level copy-edits suggested by Cynthia Uche: changing "Introduced" to "Introduce" in the documentation and renaming `alias_source` to `source_long_name` in the `OPT_ALIAS` macro. The patch remains uncontroversial and is expected to be merged without further debate. No integration branch has been reported, but given the nature of the change, it is likely to be queued for `next` once Junio picks it up.

Key technical details include the behavior of the newly documented flags: `PARSE_OPT_ONE_SHOT` processes only the first option and leaves `argv[]` untouched, while `PARSE_OPT_SHELL_EVAL` wraps usage output in a shell-evaluable heredoc. The macros cover a range of use cases, from verbosity control (`OPT__VERBOSITY`) to pathspec handling (`OPT_PATHSPEC_FROM_FILE`) and diff context (`OPT_DIFF_INTERHUNK_CONTEXT`). The `OPT_ALIAS` macro, added in v2, allows defining aliases for existing options. The patch also clarifies the `flags` argument for `OPT__FORCE`, which was previously undocumented.

The patch is well-scoped and thorough, addressing all known omissions in the `parse-options` API documentation. It is a straightforward cleanup that improves the developer experience without introducing risk.
