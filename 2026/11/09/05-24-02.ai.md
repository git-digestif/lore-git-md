This patch is a **bugfix** for option parsing consistency in `` `git rev-parse` `` and `` `git shortlog` ``.

The issue: `` `git log --glob <pattern>` `` has long accepted the glob pattern as a separate word, but `` `git rev-parse` `` and `` `git shortlog` `` only recognised the ``--glob=<pattern>`` spelling.  When users tried ``--glob 'heads/*'`` as a separate argument, ``rev-parse`` treated ``--glob`` as a literal ref and ``shortlog`` rejected it as an unknown option.

The fix adds support for the detached ``--glob <pattern>`` form in both commands.  ``rev-parse`` now consumes the next argument when it sees ``--glob``, and ``shortlog`` (which uses the revision machinery’s ``parse_options`` callback) is taught to recognise the two-word sequence and overwrite the argument vector accordingly.  The four tests that were marked as known breakage in the original 2011 commit now pass and are flipped to regular tests.

The commit message is clear and cites the exact commit (0fc63ec4e7) that introduced the inconsistency.  The code changes are minimal and focused: two small additions in ``builtin/rev-parse.c`` and ``revision.c``, plus the test flips in ``t/t6018-rev-list-glob.sh``.  The author notes that ``--exclude`` and ``--exclude-hidden`` share the same gap and will be addressed separately, while ``--branches``, ``--tags``, and ``--remotes`` remain in the ``=`` form because they take optional arguments.
