This is a documentation patch that completes the technical reference for Git’s `parse-options` API. Karthik Nayak’s v3 patch adds missing documentation for two flags (`PARSE_OPT_ONE_SHOT` and `PARSE_OPT_SHELL_EVAL`) and nineteen macros (`OPT__SUPER_PREFIX`, `OPT__VERBOSITY`, `OPT_BITOP`, `OPT_STRVEC`, `OPT_UYN`, `OPT_NOOP_ARG`, `OPT_COLUMN`, `OPT_CONTAINS`, `OPT_NO_CONTAINS`, `OPT_WITH`, `OPT_WITHOUT`, `OPT_CLEANUP`, `OPT_PATHSPEC_FROM_FILE`, `OPT_PATHSPEC_FILE_NUL`, `OPT_AUTOSTASH`, `OPT_DIFF_UNIFIED`, `OPT_DIFF_INTERHUNK_CONTEXT`, `OPT_IPVERSION`, and `OPT_ALIAS`). It also corrects the signature of `OPT__FORCE` to include its `flags` argument. The patch touches only `Documentation/technical/api-parse-options.adoc` and is purely additive, making no behavioral changes.

The motivation is straightforward: the header file `parse-options.h` exposes these symbols, but the technical documentation had never been updated to match. Karthik discovered the gaps while reviewing another series and decided to fill them so that contributors can see the full API surface in one place. The commit message explains that `PARSE_OPT_ONE_SHOT` was originally meant to be temporary but has now been around for seven years, so documenting it is a pragmatic choice.

All prior review feedback has been addressed. The v3 iteration incorporates the last two surface-level nits—changing “Introduced” to “Introduce” in the commit message and renaming `alias_source` to `source_long_name`—and is expected to be the final version. The patch is uncontroversial and should merge without further debate.
