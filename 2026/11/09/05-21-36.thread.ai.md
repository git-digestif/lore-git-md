Core problem or goal
Improve maintainability and consistency of Git’s built-in command-line argument parsing by converting manual option-parsing loops in `git diff-index` and `git diff-tree` to the shared `parse_options()` API. The commands currently mix `setup_revisions()` (for common revision/diff arguments) with manual loops for command-specific options (`--cached`, `--merge-base`, `-m`, `--stdin`), leading to duplicated code and potential inconsistencies in option handling.

Current status
Proposal stage; no code changes yet. Fien’s prior microproject (a test patch for `git check-ref-format`) was accepted and integrated into Git’s `next` branch, demonstrating familiarity with the project’s review process.

Key technical details
- Files touched: `builtin/diff-index.c`, `builtin/diff-tree.c`
- Subsystems: command-line argument parsing, diff plumbing
- New/renamed symbols: none yet; conversion will use existing `parse_options()` infrastructure
- Old vs. new behavior: must preserve existing option semantics, including:
  - `diff_merges_suppress_m_parsing()` interaction (prevents `-m` from being misinterpreted by diff-merges parser)
  - Mutual exclusivity of `--stdin` and `--merge-base` in `git diff-tree`
  - Support for abbreviated option names (e.g., `--merg` for `--merge-base`)
  - Handling of repeated options (e.g., `git diff-index -m -m`)
- Test coverage: identified relevant tests (`t4068-diff-symmetric-merge-base.sh` for `--merge-base` behavior) and regression suites

Open questions and loose ends
- How to handle the interaction between `parse_options()` and `setup_revisions()` without breaking existing behavior
- Whether `parse_options()` can fully replicate the current manual parsing’s edge-case handling (e.g., abbreviated options, repeated options)
- Potential for unintended changes to option syntax or argument ordering
- Baseline behavior documentation: Fien plans to establish this before implementing changes
