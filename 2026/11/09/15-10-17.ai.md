This is a **clarification in a documentation thread** about Jasper Mayone’s patch adding a safety warning to `git-for-each-ref(1)` for the `%(worktreepath)` atom. Phillip Wood confirms D. Ben Knoble’s suspicion that while Git’s porcelain discourages checking out the same branch in multiple worktrees (due to race risks), it is technically possible using `--force` flags or low-level plumbing commands like `git symbolic-ref`. The documentation’s claim—that only one worktree is shown when a branch is checked out in multiple worktrees—is therefore correct, but the patch should not imply this scenario is impossible. The thread now has the factual basis it needs to resolve the blocker on patch 2/4; the documentation can proceed as written, though a follow-up patch might add a sentence clarifying how such worktrees can be created.
