This is a reply in the ongoing "bundle-uri: skip unresolvable relative URIs instead of dying" bugfix series. Patrick Steinhardt weighs in on the policy debate around patch 2/3 (credential anonymization in error messages) and clarifies a key technical point about error message usefulness.

Patrick does not object to the credential anonymization itself but defers to Derrick Stolee's judgment on whether it is necessary. His substantive contribution is emphasizing that the other half of patch 2 — trimming the error message to show the URL *after* `../` components have been stripped — is actively harmful. The current implementation prints a transformed URL that no longer matches the user's input, making it impossible to diagnose why resolution failed. This is a concrete usability issue that directly impacts the series' core goal of graceful error handling.

The email does not propose code changes but reinforces the need for patch 2 to be revised or split. The credential anonymization and URL-trimming logic are currently intertwined; Patrick's feedback suggests they should be separated so the useful part (preserving the original URL in error messages) can proceed independently. This aligns with Junio C Hamano's earlier critique and increases the likelihood that patch 2 will require a v4 revision.
