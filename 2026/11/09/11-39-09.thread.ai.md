Thread identity: Configurable fetch ordering for promisor remotes in partial clones (Outreachy proposal draft)
Core problem or goal: Allow users and servers to influence the order in which Git tries multiple promisor remotes when fetching missing objects in partial clones, replacing the current fixed order (accepted remotes first, then others in config order, with `extensions.partialClone` last).
