This is a **test infrastructure patch** revisiting the design of `test-tool genbytes` in response to Patrick Steinhardt’s review. The author, Kristofer Karlsson, proposes abandoning the v2 hexadecimal interface (`61` for ASCII `'a'`) and instead splitting the functionality into two commands: the existing `test-tool genzeros` (unchanged) for NUL-byte generation, and a new `test-tool genbytes <char> [<count>]` that accepts a literal character for all other cases. This change would revert to the v1 approach but omit the final patch that removed `genzeros`, leaving the 14 existing `genzeros` callers untouched. The motivation is readability: none of the current callers actually need a specific byte value beyond NUL, so a literal-character interface (`genbytes 'a'`) is more self-documenting than hexadecimal codes. The proposal also addresses Johannes Sixt’s concern about churn by preserving backward compatibility for `genzeros`. The author seeks Junio C Hamano’s approval for this direction, framing it as a compromise between the v1 literal-character design and the v2 hexadecimal design Junio previously suggested. No implementation is attached; this is a design discussion email. If accepted, the next version (v3) would likely consist of two patches: one adding `genbytes` with a literal-character interface, and one converting the 14 non-NUL callers. The buffer allocation issue (stack vs. static) remains unresolved but is orthogonal to the interface debate.
