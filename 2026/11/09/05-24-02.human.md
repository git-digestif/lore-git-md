This is a small but useful consistency fix for two Git commands. The patch makes `` `git rev-parse` `` and `` `git shortlog` `` accept the `--glob` option as a separate word (e.g., `--glob 'heads/*'`) instead of requiring the `--glob=<pattern>` form that they currently insist on. The change aligns them with `` `git log` ``, which already supports both spellings.

The root cause is a 2011 commit (0fc63ec4e7) that only wired up the `--glob=` form for commands using the modern `parse_options` API. `` `git rev-parse` `` parses its options by hand, so it missed the update, and `` `git shortlog` `` inherited the limitation. The patch adds the missing logic in both places and flips four tests from “known breakage” to “expected success.”

The commit message is clear and the code is minimal: a few lines in `builtin/rev-parse.c` and `revision.c`, plus the test updates. The author notes that `--exclude` and `--exclude-hidden` have the same gap and will be fixed separately, so this patch is intentionally narrow. No controversy is evident; it looks like a straightforward cleanup that should be uncontroversial.
