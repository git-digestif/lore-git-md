This is a CI performance patch, part of Patrick Steinhardt’s v2 series to speed up GitLab CI pipelines. It targets the `t1092-sparse-checkout-compatibility.sh` test script, which verifies sparse-checkout behavior across three repository configurations (full checkout, sparse checkout, sparse index).

The patch replaces the repeated, process-heavy initialization of these repositories with a one-time setup of template repositories. Instead of recreating each repository from scratch over 100 times (a process that takes more than 10 minutes on Windows), the test now copies pre-configured templates into place. This change reduces the test’s runtime on Windows by about 3 minutes, cutting the total from over 10 minutes to roughly 7 minutes. The optimization is straightforward and low-risk: it preserves the test’s logic while eliminating redundant work.

The implementation adds a new `setup template repositories` test helper that creates and configures the templates once, then modifies `init_repos()` to copy these templates instead of recreating the repositories. The diff is clean and focused, touching only the test script and introducing no new symbols or on-disk format changes. This aligns with the series’ broader goal of reducing CI bottlenecks without altering Git’s core behavior.

Junio has already signaled no technical objections to the series, and this patch—like the others—addresses a clear performance pain point with measurable improvements. The change is particularly valuable for Windows runners, which remain the slowest part of Git’s CI pipeline. If the rest of the series lands, this patch will contribute to a noticeable reduction in end-to-end CI runtime.
