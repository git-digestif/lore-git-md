This is a follow-up in the ongoing RFC discussion about adding `--verbose` support to `git history reword`. Karthik Nayak proposes a more radical change: making the diff display the default behavior for `git history reword` and omitting the option entirely. His rationale is that showing the diff is unambiguously useful and avoids the need for a flag whose name is already under debate (`--verbose`, `--show-diff`, etc.).

The suggestion shifts the discussion from interface design (what should the flag be called?) to user experience (should this be opt-in or opt-out?). Karthik does not address the earlier technical feedback about config support (`commit.verbose`) or diff-generation edge cases, nor does he engage with Phillip Wood’s or D. Ben Knoble’s concerns about consistency with `git commit --verbose`. His position is concise and principled but may face pushback from reviewers who value backward compatibility or alignment with existing Git conventions. The thread now has three distinct positions: (1) add `--verbose` now (author), (2) add `--verbose` with config support (Phillip Wood), and (3) make the diff display default (Karthik Nayak). No consensus has emerged yet.
