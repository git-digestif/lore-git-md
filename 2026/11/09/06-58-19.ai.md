This is a **CI/build system** follow-up in Patrick Steinhardt’s seven-patch series to speed up GitLab CI pipelines. The email is Patrick’s reply to Junio C Hamano’s surface-level review of the first patch, which optimizes Git for Windows SDK installation in the `build:mingw64` job.

Patrick clarifies two points raised by Junio. First, he acknowledges the surprising performance gap between `Expand-Archive` and `tar(1)` (3 minutes vs. 10 seconds) but does not dispute the measurement—this remains a well-documented win. Second, he agrees to drop the SDK cache in the next revision (`v2`), as it only saved a few seconds and introduced a potential staleness concern. This decision also removes the need for the PowerShell parameter capitalization cleanup (`-directory` → `-Directory`), which Junio questioned as non-essential. The core optimization—switching to `tar(1)`—remains intact, preserving the 3-minute speedup.

The patch is still **low-risk and well-motivated**, with no impact on Git’s core functionality. Junio’s questions were clarifying rather than critical, and Patrick’s adjustments address them without compromising the series’ goal. The thread continues to target measurable CI bottlenecks, and this patch remains a clear improvement for Windows build jobs. Expect `v2` to proceed with the `tar(1)` optimization and without the cache.
