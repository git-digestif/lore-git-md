This is a refactoring patch for the `git reflog expire` command, currently under review. The patch consolidates two separate loops (one for `--all`, one for named refs) into a single loop, addressing a maintainer suggestion from an earlier fix. The change is confined to `builtin/reflog.c` and is purely mechanical, preserving all existing behavior—error reporting, exit status, output order, and handling of dynamic refs like `@{-1}`.

Patrick Steinhardt’s review is substantive. He acknowledges the simplification but raises two points: first, the commit message should explain the *why* (not just the *what*) of the refactoring, and second, the new single-loop structure makes it easy to deduplicate refs—something the current patch does not do. He also notes that the patch retains the existing asymmetry in how per-reflog options are applied, which now stands out as potentially inconsistent.

The patch itself is clean and behavior-preserving, with the author reporting full test suite passes across reflog tests, reftable, SHA-256, and leak sanitization. However, Patrick’s feedback suggests the next iteration will likely address both the commit message and the deduplication opportunity, making this a small but worthwhile cleanup rather than a final version.
