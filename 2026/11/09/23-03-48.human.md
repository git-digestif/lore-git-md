This is the first patch in a two-part Outreachy series fixing a crash in `git apply --check` when processing malformed patch headers. The author, Tanga Joris, acknowledges Junio C Hamano’s clarification that `git apply` should not attempt to handle `diff --git` lines appearing in commit message bodies—those are considered invalid input, not real diff content. The patch will now focus strictly on rejecting corrupt headers (e.g., blank lines or misordered `---`/`+++` lines after `diff --git`), aligning with the maintainer’s guidance that `git apply` should only accept formats generated by `git diff` or `git format-patch`.

The series is under final review, with the stricter validation approach now uncontested. This patch specifically addresses stale `old_name`/`new_name` values in the `patch` struct caused by early parsing termination, while the second patch (already settled) rejects inconsistent header ordering. Both patches include thorough test coverage in `t/t4133-apply-filenames.sh` and target `maint` with clean merges to all integration branches. The only remaining discussion points are minor: error message clarity and whether to reject empty `diff --git` sections (currently accepted but flagged for potential re-evaluation). The fix is well-motivated, technically sound, and ready for integration.
