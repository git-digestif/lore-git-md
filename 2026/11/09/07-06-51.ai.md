This is a **documentation follow-up** in the now-merged `git rerere` subcommand modernization series. The thread focuses on a single, narrow gap in the `enum rerere_flags` documentation introduced by patch 2/12: the purpose of `RERERE_NOAUTOUPDATE` and how it differs from simply omitting `RERERE_AUTOUPDATE`.

Junio’s review notes that while the current comment describes what the flag *does* (updates the working tree but not the index), it fails to explain *why* it exists or when a caller would choose it over the absence of `RERERE_AUTOUPDATE`. The distinction is subtle but important: omitting `RERERE_AUTOUPDATE` means Git does nothing after recording the resolution, while `RERERE_NOAUTOUPDATE` actively updates the working tree (but not the index) and prints conflict-resolution messages to stderr. Patrick acknowledges the gap and proposes revised wording that clarifies the flag’s role as an explicit override for `rerere.autoUpdate`, though the discussion remains open on whether this fully addresses Junio’s concern.

The series itself is already merged to `master`, so this exchange is not a blocker but rather a minor documentation polish for future reference. The files involved are `rerere.h` (where the enum is defined) and `builtin/rerere.c` (where the flags are used). No behavior changes, new CLI options, or on-disk format changes are proposed here—only a tweak to the in-code documentation. The thread is unlikely to generate further discussion unless Junio signals dissatisfaction with Patrick’s proposed wording.
