This is a CI/build system patch, the first in Patrick Steinhardt’s v2 series to speed up GitLab CI pipelines. It targets the "build:mingw64" job, which currently downloads and extracts the Git for Windows SDK on every run using PowerShell’s `Expand-Archive`—a slow operation. The patch replaces it with `tar(1)`, a faster alternative, while also making the script more robust by enabling error-on-failure and suppressing noisy progress output.

The change is minimal (one line swapped, four lines added) and touches only `ci/install-sdk.ps1`. It directly addresses a known bottleneck: SDK extraction time drops from ~3 minutes to ~10 seconds. The patch also removes the SDK archive cache introduced in v1, which Junio flagged as a potential staleness risk. This adjustment aligns with the series’ goal of reducing CI runtime without introducing maintenance overhead.

The patch is well-motivated and uncontroversial. It’s a clear win for Windows runners, which remain the slowest part of GitLab’s CI despite this improvement. No new symbols or behavior changes are introduced—just a faster, quieter, and more reliable SDK setup. Given Junio’s earlier approval and the lack of substantive feedback on this part of the series, it looks ready for `next`.
