This is the final patch in Patrick Steinhardt’s seven-part CI speedup series, targeting GitLab pipeline performance. It addresses a specific bottleneck in the `t5551-http-fetch-smart.sh` test (and by extension `t5559`, which repeats it) by switching the test repositories from the traditional "files" ref backend to reftable. The change is surgical: two `git init` and `git clone` commands now include `--ref-format=reftable`, eliminating the need to create nearly 100,000 loose ref files.

The motivation is clear and well-quantified. On macOS, the test previously took almost 20 minutes; with reftable it completes in 2 minutes—a 10× speedup. Linux sees a more modest but still significant 2× improvement. The commit message explicitly notes that the HTTP negotiation logic under test is unaffected by the ref backend choice, making this a low-risk optimization. The patch itself is minimal (four lines changed in one file) and self-contained, with no new symbols or on-disk format changes.

This is a textbook example of a well-crafted performance patch: it targets a real, measurable bottleneck, provides concrete before/after metrics, and confines its changes to the narrowest possible scope. The series as a whole has already drawn positive feedback from Junio, and this patch in particular looks like a straightforward win. If you care about CI turnaround times, this is worth your attention.
