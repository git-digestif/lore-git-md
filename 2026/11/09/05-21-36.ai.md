This is an Outreachy internship proposal from Fien Dora, targeting the Git project's command-line argument parsing subsystem. The proposal outlines a three-month effort (December 2026–March 2027) to improve how Git built-ins scan and parse command-line options, with Christian Couder and Siddharth Asthana as mentors.

Fien’s background centers on C and systems programming, with prior experience contributing to Git during the Outreachy contribution period. Their microproject—a test patch for `git check-ref-format`—was accepted and integrated into Git’s `next` branch, demonstrating familiarity with the project’s review process and conventions. The proposal builds on this experience, focusing on converting manual argument-parsing loops in `git diff-index` and `git diff-tree` to Git’s shared `parse_options()` API.

The technical focus is on two commands that currently mix `setup_revisions()` (for common revision/diff arguments) with manual parsing for command-specific options. For `git diff-index`, the goal is to replace a small loop handling `--cached`, `--merge-base`, and `-m` with `parse_options()`, while preserving the existing behavior—particularly the interaction with `diff_merges_suppress_m_parsing()`, which prevents `-m` from being misinterpreted by the diff-merges parser. For `git diff-tree`, the challenge is similar: the command manually processes `--stdin` and `--merge-base` after `setup_revisions()`, and a conversion would need to maintain the existing restrictions (e.g., `--stdin` and `--merge-base` cannot be used together).

The proposal is thorough and well-researched, with detailed investigations into the current implementations, test coverage, and compatibility concerns. Fien has already identified relevant tests (e.g., `t4068-diff-symmetric-merge-base.sh` for `--merge-base` behavior) and noted edge cases, such as abbreviated option names or repeated options, that a shared parser might handle differently. The timeline is realistic, emphasizing incremental work, design discussions with mentors, and a focus on regression testing. Risks—such as unintended changes to option syntax or interactions with `setup_revisions()`—are acknowledged and addressed with a plan to establish baseline behavior before implementing changes.

This is a strong proposal for an Outreachy internship. The work is scoped appropriately for a three-month period, targets a real maintainability issue (manual parsing duplication), and aligns with ongoing efforts to standardize Git’s command-line handling. The proposal’s strength lies in its attention to detail and its emphasis on understanding *why* a change is needed—not just *what* to change. If executed as planned, the internship would deliver tangible improvements to Git’s codebase while providing Fien with valuable experience in large-scale C development and open-source collaboration.
