This is the first patch in a five-part series that expands test coverage for `git log --follow` across merge commits. The patch adds 214 new test cases to `t/t4219-log-follow-merge.sh`, covering scenarios that already work but lack explicit tests. These include subtree merges with file copies, forks with renames on both sides (tested with `-c`, `--cc`, and `--remerge-diff`), `--no-ff` merges taking renames from the second parent, merges where one side keeps the path while the other renames it, `--diff-merges=first-parent` behavior, and merges where one side edits the original path while the other keeps a renamed or copied version.

The tests are structured as setup-and-verify pairs, with helper functions like `setup_rename_on_second_parent` to generate consistent repository states. Each test verifies that `--follow` correctly traces file history through the specified merge topology. The commit message explicitly states these are regression tests for a future optimization, not fixes for existing bugs. The patch is authored by Miklos Vajna with help from Patrick Steinhardt and touches only the test file, making it a pure test addition with no production code changes.
