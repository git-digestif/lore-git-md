This thread is about expanding test coverage for `git log --follow` behavior across merge commits. Miklos Vajna has sent a five-part series, with this first patch adding 214 new test cases to `t/t4219-log-follow-merge.sh`. The tests cover a wide range of merge scenarios—subtree merges, renames on both sides of a fork, `--no-ff` merges, and different diff-merges options—that already work but lacked explicit verification. The tests are structured as setup-and-verify pairs and are intended as regression tests for a future optimization, not as fixes for existing bugs. So far, this is a pure test addition with no changes to production code, and the patch has received help from Patrick Steinhardt. No reviews or decisions have been made yet.
