This is the seventh and final patch in Patrick Steinhardt’s seven-part CI speedup series. It targets a specific performance bottleneck in the test suite: the `t5551` and `t5559` scripts, which create nearly 100,000 references to test HTTP negotiation.

The problem is the traditional "files" ref backend, which stores each reference as a separate loose file. On Linux this is tolerable (about two minutes per test), but on macOS the same test takes almost 20 minutes. Because the test’s goal is to verify HTTP negotiation—not ref backend performance—Patrick switches the test repositories to use the reftable backend, which writes all references in a single table. The result is dramatic: macOS runtime drops from 20 minutes to 2 minutes (a 10× speedup), and Linux still sees a 2× improvement.

The change is minimal: two lines in `t/t5551-http-fetch-smart.sh` add `--ref-format=reftable` to the `git init` and `git clone` commands. No new test code is introduced, and the patch carries no risk of breaking the actual HTTP negotiation logic being tested. This is a clean, low-risk optimization that directly addresses one of the slowest tests in the GitLab CI pipeline.
