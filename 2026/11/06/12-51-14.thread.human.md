This thread is a two-patch series from Kristofer Karlsson that fixes a subtle bug in Git’s `unpack-objects` plumbing and strengthens a test that was silently failing to do its job. The series targets `t5608-clone-2gb.sh`, a test meant to verify Git’s handling of very large packs, which was not actually creating packs larger than 2GB or 4GB as its name implied. The first patch corrects a type narrowing issue in `unpack-objects.c` where a blob’s size was incorrectly cast to `unsigned long`, causing failures on Windows when blobs exceeded 4GB. The second patch adds explicit assertions to the test script to ensure the packs are truly the sizes they claim, making the test more reliable and exposing the bug the first patch fixes.

The series is well-motivated and focused, touching only `builtin/unpack-objects.c` and the test script. The commit message clearly explains the problem—a test that doesn’t test what it claims—and the fix, which includes both the plumbing correction and the test improvements. The Windows-specific failure is a notable catch, as it highlights a portability issue that might otherwise go unnoticed. The fix itself is straightforward (changing a parameter type from `unsigned long` to `size_t`), though `unpack-objects` is a low-level command where even small changes can have broad implications.

The test script changes are more involved, expanding the setup to ensure the packs are genuinely large and adding assertions to verify their sizes. This makes the test more thorough but also more expensive to run, which could impact CI performance. The author acknowledges this trade-off in the cover letter, noting that the test was already slow and that the assertions are necessary for correctness. So far, there’s been no review feedback, so the series is still in its initial state—no objections, no approvals, and no requests for changes. If the patches hold up under review, they should be a straightforward improvement to both the plumbing and the test suite.
