This is the seventh and final patch in Patrick Steinhardt's seven-part CI/build system series targeting GitLab CI speedups. It addresses a specific performance bottleneck in the test suite by switching two high-ref-count repositories in `t5551-http-fetch-smart.sh` from the traditional "files" ref backend to the reftable backend.

The patch modifies `t/t5551-http-fetch-smart.sh` to initialize both the server-side and client-side repositories with `--ref-format=reftable`. This change is motivated by the test's creation of nearly 100,000 references, which is extremely slow with the files backend—particularly on macOS, where the test previously took almost 20 minutes. With reftable, the same test completes in just 2 minutes on macOS (a 10x speedup) and halves the runtime on Linux. The patch also updates the corresponding test in `t5559` via the series' earlier changes.

The modification is narrowly scoped: it only affects the test's repository initialization and clone commands, leaving the rest of the test logic untouched. Since the test's purpose is to verify HTTP negotiation rather than ref backend behavior, this change is low-risk and directly addresses the CI bottleneck without altering the system under test. The commit message provides clear before/after metrics and explains why reftable is a suitable optimization for this scenario. This patch, like the rest of the series, demonstrates a practical, well-measured approach to CI performance tuning.
