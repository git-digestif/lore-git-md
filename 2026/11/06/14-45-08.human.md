This is a follow-up in the ongoing feature request for `git ls-files` to add a file-type filter (e.g., `--type f` to exclude symlinks). Alejandro Colomar acknowledges D. Ben Knoble’s suggested workaround using `--format=%(objectmode)` and post-processing with `grep`/`sed`, but reiterates his preference for a built-in `--type` flag to simplify the workflow.

The email demonstrates the workaround in action, showing how to exclude symlinks (mode `120000`) and filter for `.c`/`.h` files before passing them to `grepc`. While functional, the approach is clunky—especially with `-z` for handling spaces—and underscores the ergonomic gap. Colomar’s proposed `--type f` syntax would make this a one-liner, aligning with tools like `find -type f`.

No new objections or design feedback have emerged; the thread remains in the proposal stage, awaiting broader input on whether the feature is worth implementing. The technical path is clear: Git already tracks file types via `%(objectmode)`, so adding a `--type` flag would be a straightforward plumbing tweak in `builtin/ls-files.c`. For now, users have a viable (if verbose) workaround, but the case for a built-in solution is growing stronger.
