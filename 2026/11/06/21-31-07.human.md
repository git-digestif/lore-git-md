This is the fourth patch in a five-part documentation and terminology cleanup series (v3) that aligns Git’s code comments and help text with the 2024 redefinition of "pseudoref" and "root ref." The series updates the glossary, man pages, tests, and now in-code comments to consistently distinguish *root refs* (refs outside `refs/`, like HEAD and ORIG_HEAD) from *pseudorefs* (only FETCH_HEAD and MERGE_HEAD, which store metadata and multiple object IDs).

This patch updates four files to replace outdated uses of "pseudoref" with "root ref" in code comments and help text. The changes are mechanical but important for consistency: `builtin/for-each-ref.c` updates the `--include-root-refs` option description to say "also include root refs" instead of "also include HEAD ref and pseudorefs"; `contrib/completion/git-completion.bash` clarifies that `__git_pseudoref_exists()` checks both root refs and pseudorefs (though the function name itself is left unchanged for compatibility); `refs.h` updates comments to reflect that root refs and pseudorefs share naming rules (all caps and underscores) and clarifies that pseudorefs cannot be stored in the ref backend; and `revision.c` removes the outdated "pseudorefs" label from the error message for `--merge`.

The patch is uncontroversial and well-motivated. The commit message is clear, and the changes are narrowly scoped to terminology updates without altering behavior. The only notable exception is the decision to leave `__git_pseudoref_exists()` named as-is, which the author justifies by noting that there’s no obvious term covering both root refs and pseudorefs, and third-party scripts might depend on the name. This is a pragmatic choice that avoids breaking compatibility for minimal gain.
