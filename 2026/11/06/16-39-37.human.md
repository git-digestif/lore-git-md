This is a review comment on the second patch in Patrick Steinhardt’s now-merged 12-patch series modernizing `git rerere`’s subcommand handling. The series converted `git rerere` to use Git’s standard `OPT_SUBCOMMAND()` mechanism, and this patch specifically replaced four `#define` flags with an `enum rerere_flags`.

Junio’s feedback is narrow and technical: while he accepts the updated documentation for `RERERE_NOAUTOUPDATE` (which clarifies that it updates the working tree but leaves the index untouched), he points out that neither the v2 nor v3 version explains *why* the flag exists at all. The question is not what the flag does, but why it is distinct from simply omitting `RERERE_AUTOUPDATE`. The implication is that the enum comment should briefly justify the flag’s necessity—likely because it controls whether conflict-resolution messages are printed to stderr, a behavioral difference that omitting the bit would not achieve.

The comment is otherwise uncontested; Junio explicitly states that the new wording is not wrong, merely not an improvement over v2. This is a surface-level review—it does not challenge the patch’s correctness or the series’ direction, only the clarity of a single documentation line. Since the series is already merged to `master`, this feedback is effectively retrospective, though it may inform future documentation patches in the same area.
