This is the sixth patch in Patrick Steinhardt’s 12-part refactoring series that modernizes `git rerere`’s subcommand handling by switching to Git’s standard `OPT_SUBCOMMAND()` mechanism. This patch extracts the "clear" action into a dedicated `cmd_rerere_clear()` function with proper `parse_options()` machinery, preserving the existing behavior: it calls `rerere_clear()` to remove all recorded conflict resolutions and clears the in-memory `merge_rr` string list. The change is purely mechanical—no new options, no behavior changes, and no on-disk format changes—just a preparatory step that aligns the code with the series’ goal of using Git’s built-in subcommand infrastructure.

The patch touches only `builtin/rerere.c`, adding a 22-line function that wraps the existing `rerere_clear()` call in a standard `parse_options()` skeleton. The function’s option table is empty (no flags are accepted), and it enforces the same argument-checking as the original code: if extra arguments are provided, it errors out with "too many arguments". The original hand-rolled `if (!strcmp(...))` ladder is updated to call the new function instead of invoking `rerere_clear()` directly, and the `merge_rr` string list is now managed inside `cmd_rerere_clear()` rather than at the top level.

This is a textbook refactoring patch: small, self-contained, and risk-free. It follows the same pattern established in the preceding patch (which extracted "forget") and sets the stage for the subsequent patches that will do the same for "status", "remaining", "diff", and "gc". The series as a whole is uncontested, well-reviewed, and ready for integration; this patch in particular has no open questions or feedback to address.
