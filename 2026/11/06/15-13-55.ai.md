This is the first patch in Patrick Steinhardt’s v3 series modernizing `git rerere`’s subcommand handling. It renames the function `repo_rerere()` to `rerere()` to align with the naming convention of other functions in `rerere.h` (all of which already use the `rerere_` prefix). The change is purely mechanical: the function’s signature, behavior, and call sites are unchanged. The commit message and updated documentation clarify that this function is the main entry point for recording and reusing conflict resolutions during merge operations.

The patch touches nine files: `apply.c`, `builtin/am.c`, `builtin/commit.c`, `builtin/merge.c`, `builtin/rerere.c`, `builtin/stash.c`, `rerere.c`, `rerere.h`, and `sequencer.c`. All callers are updated to use the new name. The documentation in `rerere.h` is expanded to better explain the function’s role, addressing a minor stylistic feedback point from Junio C Hamano in earlier rounds.

This is a low-risk, guideline-aligned refactoring that sets the stage for the rest of the series. The rename is uncontested and ready for integration. No new CLI options, config keys, or on-disk format changes are introduced. The patch is part of the ongoing effort to standardize Git’s built-in commands and eliminate inconsistencies in internal APIs.
