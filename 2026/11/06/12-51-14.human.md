This is a two-patch test and bugfix series targeting the `t5608-clone-2gb.sh` test script.

The author noticed that `t5608` (a test for cloning repositories with large packs) was unusually slow in CI, but profiling revealed the test wasn’t actually creating the >2GB or >4GB packs its name suggests. The first patch fixes a bug in `unpack-objects`: when streaming large blobs, it was truncating the size to `unsigned long`, which fails on Windows where `unsigned long` is 32-bit. The fix changes the parameter type to `size_t` to handle larger sizes. The second patch adds assertions to the test script to verify the packs are truly the expected size, ensuring the test does what it claims.

The series is well-motivated: it addresses a real performance anomaly in CI and fixes a platform-specific bug that would cause the test to fail on Windows once the assertions are in place. The commit messages are clear, and the changes are small and focused. This looks like a straightforward improvement that should attract little controversy.
