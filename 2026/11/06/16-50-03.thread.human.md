This thread is a compatibility inquiry about Git v3’s default object format. Adam Dinwoodie reports that when Git is built with `WITH_BREAKING_CHANGES=1`—the flag meant to enable Git v3 behavior—`git init` still creates repositories using SHA-1 instead of SHA-256 as the default. He provides a simple reproduction: build Git with the flag, run `git init`, and observe that `git rev-parse --show-object-format` returns `sha1`. The behavior is consistent across Git v2.56.0, the `next` branch, and `main`.

The question is whether this is intentional, as the thread doesn’t propose a fix or reference prior discussion. This appears to be part of broader Git v3 preparation work, particularly for Nixpkgs, where the default object format has compatibility implications.
