This thread began when Adam Dinwoodie asked whether `git init` correctly defaults to SHA-256 for new repositories when Git is built with `WITH_BREAKING_CHANGES=1`, the flag intended to enable Git v3 behavior. It did not -- a confirmed bug -- and brian m. carlson prepared a fix in `setup.c` ensuring `git init` respects the breaking-changes flag by defaulting new repositories to SHA-256, while refusing to silently reinitialize existing repositories with a different hash algorithm. The series went through three iterations: Junio C Hamano caught a latent bug in `read_repository_format()` and a reinitialization regression in the first version, which v2 addressed by restructuring `repository_format_configure()` so an explicit `--object-format` always wins and mismatched reinitialization dies with an error; v3 then removed a stale comment and switched the tests in `t/t0001-init.sh` to `$GIT_TEST_BUILTIN_HASH`, both suggestions from Patrick Steinhardt.

The series has been merged to `master` (date unknown), and Patrick Steinhardt's latest message -- a brief "Thanks, I'm happy with this version" -- closes out his involvement, since his only outstanding suggestions were the ones incorporated in v3. With that, the review is settled: Adam Dinwoodie raised the issue, brian m. carlson authored and refined the fix across v1 through v3, Junio C Hamano drove the substantive review and merged it, and no objections or alternative proposals remain open. The only loose ends noted are non-blocking future work, namely a possible "empty repository" feature that would require protocol changes and is not currently planned.
