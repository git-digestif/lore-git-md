This thread began when Adam Dinwoodie reported that `git init` was not defaulting to SHA-256 for new repositories when Git is built with `WITH_BREAKING_CHANGES=1`, a flag intended to enable Git v3 behavior. The issue was confirmed as a bug, and brian m. carlson provided a fix that ensures new repositories use SHA-256 under the breaking-changes flag while preventing silent reinitialization of existing repositories with an incompatible hash algorithm. Junio C Hamano merged the revised patch (`[PATCH v2] setup: fix hash algorithm detection`) to `master` after praising its simplified and safer logic.

The fix is now complete and merged, but Patrick Steinhardt’s recent review suggests two minor improvements to the already-merged patch: updating a stale comment in `setup.c` to reflect the new precedence rules, and replacing a custom test helper with the standard `GIT_TEST_BUILTIN_HASH` mechanism in the test suite. These tweaks are purely about consistency and maintainability and do not affect the patch’s correctness or safety. No further action is needed for integration, though the suggestions could be addressed in a follow-up if the maintainers choose to do so. The thread is effectively closed, with the core issue resolved.
