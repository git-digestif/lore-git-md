This thread began when Adam Dinwoodie reported that `git init` incorrectly defaults to SHA-1 even when Git is built with `WITH_BREAKING_CHANGES=1`, a flag intended to enable Git v3 behavior where SHA-256 should be the default. The issue was quickly confirmed as a bug, and brian m. carlson has now submitted a fix.

The patch is minimal and targeted: it ensures that `git init` respects the `GIT_HASH_DEFAULT` value, which is set to SHA-256 when `WITH_BREAKING_CHANGES=1` is enabled. The fix adds a single line in `setup.c` to set the repository's hash algorithm to `GIT_HASH_DEFAULT` when no other algorithm is specified, and includes a new test in `t/t0001-init.sh` to verify the behavior. The patch is undergoing CI testing and is expected to be sent soon. No objections or alternative approaches have been raised, and the fix is considered a straightforward correction.

The broader context is Git v3 preparation, particularly for compatibility with downstream consumers like Nixpkgs. The fix is self-contained and does not depend on other patches, though it aligns with the ongoing SHA-256 transition. The only remaining open question is whether additional safeguards or documentation updates will be included for downstream users, but the patch itself does not address this.
