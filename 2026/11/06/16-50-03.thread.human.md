The thread concerns whether `git init` correctly defaults to SHA-256 when Git is built with `WITH_BREAKING_CHANGES=1` for Git v3. Adam Dinwoodie reported that it did not, and brian m. carlstadt has submitted a three-iteration patch series fixing the default object format selection in `setup.c` to respect the breaking-changes flag for new repositories while preventing unsafe reinitialization of existing ones with a different hash. Patrick Steinhardt reviewed the refactoring and expressed satisfaction with v3, but Junio C Hamano is still interrogating details rather than approving.

Junio's latest review questions the commit message explanation for why the code does not default to `GIT_HASH_DEFAULT`, asks whether the "no detected hash algorithm" state is current or hypothetical future behavior, and argues that parts of the removed reinitialization-safety comment remain valuable. He also raises a semantic question about whether `init.defaultObjectFormat` in the user's global config counts as the user having "specified" an algorithm alongside command-line and environment options. Earlier he had flagged potential test isolation issues with `sane_unset GIT_DEFAULT_HASH` in the new test cases. The series remains under review with these documentation and logic questions open, and no merge to any integration branch has occurred.
