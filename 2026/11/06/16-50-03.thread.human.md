This thread began when Adam Dinwoodie asked whether `git init` correctly defaults to SHA-256 when Git is built with `WITH_BREAKING_CHANGES=1`, a flag meant to enable Git v3 behavior. The inquiry revealed a bug: even with the flag set, new repositories were still defaulting to SHA-1. brian m. carlson confirmed the issue and provided a fix that ensures `git init` respects the breaking-changes flag by defaulting to SHA-256 for new repositories.

However, Junio C Hamano identified two critical problems in the initial patch: a latent bug in `read_repository_format()` that forced SHA-1 when the repository version was unset, and a regression where reinitializing an existing repository could silently overwrite its object format. Junio proposed a refactor to guard the default-setting logic, ensuring it only applies to new repositories, while Patrick Steinhardt suggested an alternative restructuring for better readability and consistency with ref-storage handling. brian has now submitted a revised patch that addresses these concerns. The new version restructures `repository_format_configure()` to enforce safe reinitialization—refusing to change the hash algorithm for existing repositories—and includes comprehensive tests to verify the fix. The patch is technically sound, aligns with prior feedback, and is ready for integration, pending CI results. No open objections remain.
