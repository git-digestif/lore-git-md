This thread is about a Git v3 compatibility issue: when Git is built with `WITH_BREAKING_CHANGES=1` (the flag meant to enable Git v3 behavior), `git init` still defaults to SHA-1 instead of SHA-256 for new repositories. Adam Dinwoodie raised the question after confirming the behavior on Git v2.56.0 and the `next` and `main` branches.

Brian M. Carlson has confirmed this is a bug and reports having a fix ready. The patch will adjust `git init` to respect the `WITH_BREAKING_CHANGES=1` flag by defaulting to SHA-256, aligning with Git v3’s intended behavior. He plans to send the patch shortly after CI testing completes. The fix targets the repository initialization logic in `builtin/init-db.c` and is expected to be uncontroversial, as it directly addresses the documented purpose of the breaking-changes flag. No prior related work or follow-up changes are anticipated beyond this narrow correction. The thread is now waiting on the patch submission and any subsequent review or CI feedback.
