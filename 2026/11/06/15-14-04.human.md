This is the tenth patch in Patrick Steinhardt’s twelve-patch series modernizing `git rerere`’s subcommand handling. The patch extracts the "gc" action into a dedicated `cmd_rerere_gc()` function with standard `parse_options()` machinery, preserving the existing behavior while preparing for the upcoming `OPT_SUBCOMMAND()` conversion in patch 11.

The change is purely mechanical: the `cmd_rerere_gc()` function takes the standard `argc`, `argv`, `prefix`, and `repo` parameters, declares a hidden `--skip-locked` option (previously a global flag), and calls `parse_options()` to validate that no extra arguments are provided. If arguments are given, it errors out with a usage message; otherwise, it invokes `rerere_gc()` with the appropriate `RERERE_NOWAIT` flag and cleans up the `merge_rr` string list. The global `--skip-locked` flag is removed from the top-level parser, since it is now handled locally within `cmd_rerere_gc()`. The test suite loses one negative test (`--skip-locked` is only accepted by "gc"), as the flag is no longer recognized by the top-level command.

The patch is uncontested and aligns with the series’ goal of bringing `git rerere` in line with other multi-subcommand built-ins. Karthik Nayak’s review of this patch confirmed it is a mechanical refactoring with no behavioral changes. The only files touched are `builtin/rerere.c` (30 insertions, 18 deletions) and `t/t4200-rerere.sh` (5 deletions). The series remains ready for integration.
