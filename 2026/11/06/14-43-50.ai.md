This is the second patch in Aniket Gupta’s three-patch bugfix series for the bundle-uri subsystem, and it is now the subject of substantive review feedback from Derrick Stolee. The patch itself plugs a minor but real information-disclosure hole: when `relative_url_gently()` (introduced in patch 1) fails to resolve a relative URI, the error message it generates now anonymizes any credentials present in the original URL before printing it. The patch also improves diagnosability by showing the full, unmodified input URL rather than a partially-stripped version.

Derrick’s review is substantive but mixed. He questions the necessity of anonymizing URLs in error messages, arguing that the user already knows the problematic URL (since they provided it) and that environments storing logs should already be sanitizing command output. He also notes that bundle-uri lists containing credentialed URIs are inherently unsafe, so this patch does not meaningfully protect secrets in that context. However, he acknowledges that if the project decides to proceed with anonymization, the implementation is correct and the test coverage is appropriate.

The patch touches only `remote.c` and adds a single test in `t0060-path-utils.sh` that verifies the anonymization works when the helper fails. The implementation is straightforward: `transport_anonymize_url()` is called on the original URL, the anonymized string is used in the error message, and the temporary string is freed. The test explicitly covers the credential case, ensuring the fix is exercised.

This patch remains uncontroversial in its mechanics but now carries an open policy question: whether error messages should anonymize URLs at all. The decision on this point will likely influence whether the patch is merged as-is or revised. The series as a whole is still blocked on the larger policy question raised in patch 3 (whether to skip unresolvable URIs or halt), but this patch’s fate is now tied to a narrower, related discussion.
