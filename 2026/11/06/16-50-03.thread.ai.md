Thread identity: inquiry about Git v3 default object format for new repositories; thread root by Adam Dinwoodie. Series version: not applicable (self-contained bugfix).

Core problem or goal: determine whether the current behavior of `git init` defaulting to SHA-1 (instead of SHA-256) when Git is built with `WITH_BREAKING_CHANGES=1` is intentional, as this flag is meant to enable Git v3 behavior where SHA-256 is the expected default. The issue is confirmed as a bug, and a fix has been prepared by brian m. carlson to ensure `git init` respects `WITH_BREAKING_CHANGES=1` by defaulting to SHA-256 for new repositories.

Current status: bug confirmed and fix implemented. The patch adds a single line in `setup.c` to set the repository's hash algorithm to `GIT_HASH_DEFAULT` when no other algorithm is specified, ensuring `git init` uses SHA-256 in breaking-changes mode. The fix includes a new test in `t/t0001-init.sh` to verify the correct default object format is used, with and without the `WITH_BREAKING_CHANGES` prereq. CI testing is underway, and the patch is expected to be sent soon.

Key technical details:
- Build flag: `WITH_BREAKING_CHANGES=1` (intended to enable Git v3 behavior).
- Command: `git init` and `git rev-parse --show-object-format` (now correctly returns `sha256` under Git v3).
- Subsystem: repository initialization (`setup.c`).
- New symbol: `GIT_HASH_DEFAULT` (used to set the default object format).
- On-disk implication: default object format for new repositories now aligns with Git v3 expectations.
- Test coverage: new test in `t/t0001-init.sh` verifies the fix for both breaking-changes and non-breaking-changes scenarios.
