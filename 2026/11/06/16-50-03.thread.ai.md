Thread identity: inquiry about Git v3 default object format for new repositories; thread root by Adam Dinwoodie. Series version: not applicable (self-contained bugfix).

Core problem or goal: determine whether `git init` correctly defaults to SHA-256 (instead of SHA-1) when Git is built with `WITH_BREAKING_CHANGES=1`, as this flag is intended to enable Git v3 behavior. The issue was confirmed as a bug, and a revised fix by brian m. carlson ensures `git init` respects the breaking-changes flag by defaulting to SHA-256 for *new* repositories while preventing silent reinitialization of existing repositories with a different hash algorithm. The patch targets the default object format selection logic in `setup.c`.

Current status: bug confirmed and fix implemented. The revised patch restructures `repository_format_configure()` to enforce two key behaviors: (1) defaulting to `GIT_HASH_DEFAULT` only for *new* repositories (where `repo_fmt->version < 0` or the hash is explicitly unset), and (2) refusing to reinitialize an existing repository with a different hash algorithm. This resolves the latent bug in `read_repository_format()` (where `version == -1` forced SHA-1) and the regression where reinitialization silently clobbered the object format. The patch aligns with Junio C Hamano’s concerns about reinitialization safety and Patrick Steinhardt’s preference for consistent format-handling across hash, ref storage, and object storage. No open technical objections remain; CI results are pending. The patch is ready for integration.

Key technical details:
- Build flag: `WITH_BREAKING_CHANGES=1` (intended to enable Git v3 behavior).
- Command: `git init` and `git rev-parse --show-object-format` (now correctly returns `sha256` under Git v3 for *new* repositories).
- Subsystem: repository initialization (`setup.c`).
- New symbol: `GIT_HASH_DEFAULT` (used to set the default object format).
- Functions: `read_repository_format()` (latent bug resolved) and `repository_format_configure()` (restructured to guard default-setting logic and prevent silent reinitialization).
- On-disk implication: default object format for *new* repositories now aligns with Git v3 expectations, while *existing* repositories are preserved during reinitialization (or fail if an incompatible hash is specified).
- Test coverage: comprehensive tests in `t/t0001-init.sh` verify default object format selection, rejection of reinitialization with a different hash algorithm, and preservation of the existing hash algorithm when reinitializing with a config override.
