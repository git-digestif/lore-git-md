This is the final patch in Patrick Steinhardt’s 12-part refactoring series that modernizes `git rerere`’s subcommand handling by adopting Git’s standard `OPT_SUBCOMMAND()` mechanism. The series is purely internal—no behavior changes, no new CLI options, and no on-disk format changes—and this patch completes it by adding proper per-subcommand usage strings to both the man page (`Documentation/git-rerere.adoc`) and the C code (`builtin/rerere.c`).

The man page’s `SYNOPSIS` section now lists each subcommand ("clear", "diff", "forget", "gc", "remaining", "status") and the default `--[no-]rerere-autoupdate` mode on separate lines, matching the style of other multi-subcommand built-ins like `git notes`. In the C code, each subcommand’s `parse_options()` call now references its own usage array, defined via `N_()`-wrapped strings. The top-level `rerere_usage[]` array is extended to include all seven synopses, ensuring that `git rerere -h` and `git rerere <subcommand> -h` display the correct usage for each context.

This patch is a documentation-only change that aligns the help output with the refactoring done in earlier patches. The series as a whole is uncontested, addresses all prior feedback, and is ready for integration. The only files touched are `Documentation/git-rerere.adoc` and `builtin/rerere.c`, with no test or behavior changes.
