Thread type: patch series (bug fix + test modernization)

Core problem or goal
The test script `t5608-clone-2gb.sh` claims to verify Git’s handling of very large (>2 GB or >4 GB) packs, but it was not actually creating packs of those sizes. Additionally, `unpack-objects` incorrectly narrows the size of streamed blobs to `unsigned long`, which causes failures on Windows when blobs exceed 4 GB due to the platform’s 32-bit `unsigned long` type.

Current status
Under review (no prior versions). Two patches:
1. Fix the `unpack-objects` bug by changing a parameter type from `unsigned long` to `size_t`.
2. Add assertions to `t5608-clone-2gb.sh` to ensure the packs are truly the sizes they claim, making the test more reliable.

Key technical details
- Files touched: `builtin/unpack-objects.c` (plumbing fix), `t/t5608-clone-2gb.sh` (test assertions).
- New/renamed symbols: None.
- Behavior change: `unpack-objects` now correctly handles blob sizes >4 GB on Windows.
- On-disk format: Unchanged.
- Test coverage: Expanded assertions in `t5608-clone-2gb.sh` to verify pack sizes, increasing test runtime but improving reliability.
