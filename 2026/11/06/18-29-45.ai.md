This is a bugfix targeting the ignore-pattern parsing subsystem. The patch by Aniket Gupta directly addresses the issue reported by Mike Beaton: `git check-ignore -v` incorrectly matches paths ending in a trailing slash against blank lines in `.gitignore` when those lines use CRLF line endings or contain only whitespace. The fix is minimal and surgical—it modifies `add_patterns_from_buffer()` in `dir.c` to skip adding a pattern if the trimmed line is empty, ensuring blank lines (regardless of line endings or trailing spaces) never match any path.

The change is well-motivated and aligns with the documented semantics of `.gitignore` blank lines. The patch includes a new test in `t/t0008-ignores.sh` that verifies the fix works for both CRLF and mixed-whitespace blank lines, covering the edge cases Mike Beaton identified. The test is clear and reproduces the exact scenario described in the original report.

The root cause is now pinpointed: the ignore-pattern parser was treating any non-comment line as a potential pattern, even if it became empty after trimming carriage returns and spaces. The fix adds a single guard (`if (*entry)`) to prevent this, which is both correct and low-risk. No other `.gitignore` patterns (comments, negations, etc.) appear to be affected by this logic, so the scope of the fix is appropriately narrow.

This patch is ready for review by maintainers of the ignore subsystem. It is unlikely to be controversial, as it restores documented behavior without changing any on-disk formats or introducing new dependencies. The reproduction case is straightforward, and the fix is self-contained. The patch also credits Mike Beaton in the `Reported-by` trailer, acknowledging the original report.

Key technical details for follow-up discussion:
- **File modified**: `dir.c` (ignore-pattern parsing logic in `add_patterns_from_buffer()`)
- **Test added**: `t/t0008-ignores.sh` (new test case for blank lines with CRLF/whitespace)
- **Behavior change**: blank lines (after trimming) are now explicitly skipped, preventing them from matching paths ending in `/`
- **Related functions**: `trim_trailing_spaces()`, `add_pattern()`
- **Edge cases covered**: CRLF line endings, trailing spaces, mixed whitespace
- **Command affected**: `git check-ignore -v` (output correctness, not core ignore behavior)
