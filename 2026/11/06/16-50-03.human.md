This is a question about Git v3 preparation, specifically the default object format for new repositories.

Adam Dinwoodie reports that when building Git with `WITH_BREAKING_CHANGES=1` (the flag intended to enable Git v3 behavior), `git init` still creates repositories using SHA-1 instead of SHA-256. He provides a Nix-based test script and a simpler reproduction case: build Git with the breaking-changes flag, run `git init`, and check the object format with `git rev-parse --show-object-format`. The result is "sha1", but Adam expected "sha256".

The email is not a patch or a proposal, but a request for clarification. It is part of the broader Git v3 effort, which aims to make SHA-256 the default object format. Adam’s observation suggests that either the behavior is not yet implemented, or there is a misunderstanding about how the breaking-changes flag is supposed to work. No prior discussion or cover letter is referenced, so this appears to be the start of a new thread. The question is straightforward and well-supported with reproduction steps, making it easy for others to verify.
