This is a documentation and terminology cleanup patch in Andy Koppe’s v3 series, which aligns Git’s code and documentation with the 2024 distinction between *root refs* (refs outside `refs/`, like HEAD and ORIG_HEAD) and *pseudorefs* (only FETCH_HEAD and MERGE_HEAD). This specific patch updates in-code comments and help text to replace outdated references to "pseudorefs" with "root refs" where appropriate, while leaving the bash-completion function `__git_pseudoref_exists()` unchanged due to its ambiguous scope.

Junio C Hamano’s review of this patch is **surface-level**, focusing on two minor wording issues in the help text and error message. First, he notes that the updated `--include-root-refs` description ("also include root refs") is correct but could be more precise by mentioning that *all* root refs (e.g., ORIG_HEAD) are included, not just HEAD. Second, he flags the removal of the word "pseudorefs" from the `--merge` error message as potentially confusing for users. His concern is that dropping the label entirely might leave users unsure why `git log --merge MERGE_HEAD` fails when MERGE_HEAD doesn’t exist, whereas retaining "root refs" (or rewording the message to explain the operational context) would clarify that the option only works when those refs are present.

The patch itself is uncontroversial and nearly ready for merging. Junio’s feedback is editorial and doesn’t challenge the core goal of the series. The changes are mechanical and precise, touching only comments and help text in `builtin/for-each-ref.c`, `revision.c`, and related files. No behavioral changes are introduced, and all prior substantive review feedback has been addressed in earlier patches. The unresolved points here are minor and unlikely to delay the series.
