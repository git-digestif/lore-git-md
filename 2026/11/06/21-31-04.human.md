This is a documentation patch, the first in a five-part series (v3) that aligns Git’s terminology around "root refs" and "pseudorefs" with the 2024 redefinition. The series is uncontroversial and appears ready for merging.

This patch updates the glossary to formally introduce "root ref" (refs outside `refs/`, like HEAD and ORIG_HEAD) and clarify "pseudoref" (now strictly FETCH_HEAD and MERGE_HEAD). The "pseudoref" entry now explicitly states that pseudorefs are *not* refs, cannot be written by `git-update-ref` or listed by `git-for-each-ref`, and may contain multiple object IDs (e.g., FETCH_HEAD’s multi-object format with "not-for-merge" annotations). It also clarifies that MERGE_HEAD is written by `git-pull` (not just `git-merge`) and that commands like `git log` use the first object ID when multiple entries are present. The "ref" entry is cleaned up to remove naming rules and irregular root refs, which are now covered under "root ref".

The changes are thorough and well-motivated, addressing prior review feedback from Junio C Hamano and Patrick Steinhardt. The glossary now provides clear, example-driven distinctions between root refs and pseudorefs, improving consistency across Git’s documentation. No behavioral changes are introduced—this is purely a terminology cleanup. The patch touches only `Documentation/glossary-content.adoc` and is part of a larger effort to resolve long-standing inconsistencies in Git’s documentation.
