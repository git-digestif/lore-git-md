This is a bugfix for the `.gitignore` parsing logic. Aniket Gupta provides a minimal patch that addresses the issue Mike Beaton reported: `git check-ignore -v` incorrectly matches directory paths ending in a trailing slash (`foo/`) against blank lines in `.gitignore` when those lines use CRLF line endings or contain only spaces.

The fix is straightforward: in `add_patterns_from_buffer()`, the code now checks whether the trimmed line is empty (`*entry`) before adding it as a pattern. This ensures blank lines (including those with CRLF or spaces) are skipped entirely, matching the documented semantics that blank lines should never match any file or directory. The patch also adds a test case to `t/t0008-ignores.sh` that verifies blank lines with CRLF or spaces do not trigger matches.

The change is narrow and well-motivated, touching only the ignore-pattern parsing logic in `dir.c`. The test coverage is appropriate, and the commit message clearly explains the problem and solution. This looks like a clean, uncontroversial fix that should resolve the issue without side effects. The patch is ready for review by maintainers of the ignore subsystem.
