This is a bugfix patch targeting the `unpack-objects` command, part of a two-patch series. The issue is a type mismatch on 32-bit platforms (notably Windows): `unpack_one()` decodes a blob’s size into a `size_t`, but `stream_blob()` still expects it as an `unsigned long`. When a blob exceeds 4 GB, the size is truncated, causing a fatal write error (`write stream object 4294967304 != 8`). The fix is a one-line change that aligns the parameter type with the rest of the code path, which already uses `size_t`. The commit message is clear and cites the exact commit that introduced the inconsistency. This looks like a straightforward, well-motivated fix that should be uncontroversial.
