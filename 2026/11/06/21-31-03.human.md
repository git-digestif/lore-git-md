This is a documentation patch series that aligns Git’s terminology around "root refs" and "pseudorefs" with the 2024 redefinition (commit 993d57eded). The series now clearly distinguishes pseudorefs (FETCH_HEAD, MERGE_HEAD) from root refs (HEAD, ORIG_HEAD, etc.) by emphasizing semantic differences: pseudorefs can store multiple object IDs and metadata (e.g., FETCH_HEAD’s "not-for-merge" annotations), while root refs behave like normal refs except for their location outside `refs/`. The glossary’s "pseudoref" entry now includes a detailed FETCH_HEAD example (e.g., `d4c5f27105ee2e44366d718dbc5db95bbe99c714 not-for-merge branch 'example' of https://example.com/x/y`) and explicitly lists supported operations (`git log`, `git diff`) and limitations (`git-update-ref`, `git-for-each-ref`). The "root ref" entry is similarly fleshed out, and cross-references between the glossary and `gitdatamodel.adoc` improve navigability.
