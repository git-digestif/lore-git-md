This is the first patch in Patrick Steinhardt’s seven-part CI/build system series aimed at speeding up GitLab CI pipelines. It specifically targets the "build:mingw64" job, which currently downloads and extracts the Git for Windows SDK on every run using PowerShell’s `Expand-Archive`—a process that takes about three minutes.

The patch introduces two key improvements: caching the downloaded SDK archive and switching from `Expand-Archive` to `tar(1)` for extraction. The caching itself only saves a few seconds, but the switch to `tar` reduces extraction time from three minutes to around ten seconds. The changes are confined to `.gitlab-ci.yml` and `ci/install-sdk.ps1`, with no new symbols or behavior changes beyond the performance gain. The patch also ensures the SDK and download directories are excluded from Git via `.git/info/exclude`.

This looks like a well-motivated, low-risk optimization with clear measurable benefits. The commit message is concise and explains the rationale and impact effectively. No open questions or controversies are evident yet—this is a straightforward infrastructure tweak that should be uncontroversial.
