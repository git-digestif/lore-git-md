This is the first patch in Patrick Steinhardt’s seven-part CI/build system series aimed at speeding up GitLab CI pipelines. It specifically targets the "build:mingw64" job, which previously spent about three minutes extracting the Git for Windows SDK on every run using PowerShell’s `Expand-Archive` cmdlet.

The patch introduces two key optimizations: caching the downloaded SDK archive and switching from `Expand-Archive` to `tar(1)` for extraction. The caching itself only saves a few seconds, but the switch to `tar` reduces extraction time dramatically—from roughly three minutes down to ten seconds. The change touches `.gitlab-ci.yml` (adding a cache configuration) and `ci/install-sdk.ps1` (replacing the extraction logic and adding error handling). The script now downloads the SDK to a `.dependencies` directory, checks for an existing archive before downloading, and uses `tar -xf` for extraction, with proper error checking and cleanup.

This is a well-motivated, low-risk optimization that directly addresses a measurable bottleneck in the Windows CI pipeline. The commit message clearly states the problem, the solution, and the performance impact, making it easy to assess the value. No new symbols or on-disk formats are introduced, and the change is confined to CI infrastructure. The patch looks ready for review and is likely to be uncontroversial.
