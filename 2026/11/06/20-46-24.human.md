This is a **Git v3 compatibility bugfix** addressing the default object format for new repositories.

Brian M. Carlson confirms Adam Dinwoodie’s observation that `git init` incorrectly defaults to SHA-1 even when Git is built with `WITH_BREAKING_CHANGES=1`, the flag meant to enable Git v3 behavior. The expected behavior is that new repositories should use SHA-256 as the default object format under this build configuration. Carlson reports having a patch ready that fixes the issue, currently undergoing CI testing, and plans to send it shortly.

The thread remains unresolved but now has a clear path forward: a patch is imminent, and the bug itself is acknowledged. No controversy or alternative approaches have been raised yet. The fix will likely be small and targeted, touching only the repository initialization logic to respect the `WITH_BREAKING_CHANGES` flag. This is part of the broader Git v3 preparation effort, particularly relevant for downstream packagers like Nixpkgs.
