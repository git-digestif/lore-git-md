This is Junio’s "What’s cooking in git.git" report for November 2026, summarizing the state of 80+ in-flight topics.  It is not a single patch but a high-level snapshot of the entire integration queue, so the summary focuses on what a busy reader needs to know: which topics are graduating, which are newly cooking, which are stalled, and which look ready to advance soon.

The report shows three topics graduating to master: a typo fix in the config documentation (`hk/config-log-typofix`), a CI tweak to fail builds when optional dependencies like Perforce or Git-LFS fail to install (`hn/ci-fail-on-missing-deps`), and a pair of optimizations—one to reduce lock contention in `git status` (`mc/status-index-lock`) and another to clean up leftover rebase refs (`pw/sequencer-delete-rebase-head`).

New topics cooking in ‘next’ include a handful of small fixes and cleanups: better error handling in object-file writing (`jt/object-file-error-handling`), a Cirrus CI removal (`ta/ci-retire-cirrus-ci`), a parse-options API doc fix (`cu/doc-api-parse-options`), and a tweak to `git annotate` to fix shell completion (`tj/annotate-blame-args`).  Two larger efforts stand out: `ps/storage-format-improvements` (5 patches) extends the object and ref storage format machinery to support payloads and automatically create leading directories, and `ps/commit-graph-write-refactor` (10 patches) consolidates commit-graph writing parameters into a single options structure, paving the way for pluggable backends.

Stalled topics—those waiting for author response or rerolls—include `ap/http-preserve-wwwauth-redirect` (stalled since August), `vv/branch-recurse-no-start-ref` (a submodule crash fix), `kj/repo-info-more-path-keys` (8 patches adding new `git repo info` keys), and `ec/commit-fixup-options` (support for `-m/-F/-c/-C` with `--fixup`).  None of these have seen activity in the last two weeks, so they may be dropped unless interest revives.

Among the cooking topics, a few deserve special mention.  `ps/ci-speedups` (7 patches) optimizes GitLab CI by building optimized binaries with Meson and using reftables to speed up tests with many refs.  `rm/http-retry-improvements` (4 patches) adds exponential backoff and configurable retry status codes to HTTP operations.  `hn/reflog-operations` (2 patches) teaches `git reflog` and `git log -g` a new `%gb` placeholder that shows the branch name at the time of each reflog entry.  `ps/rerere-subcommands` (12 patches) converts `git rerere` to use the standard `OPT_SUBCOMMAND()` API, removing ad-hoc parsing.  `hn/fetch-refmap` (6 patches) changes the default refspec for remotes added in shallow repositories to pull only the remote branches tracked by local branches, avoiding an eager full fetch.

The report also lists a dozen discarded topics—patches that were picked up prematurely but proved unready.  Most are small or niche (e.g., `ds/fsmonitor-invalidate-untracked` was retracted in favor of `ik/fsmonitor-untracked-cache-trivial-response`), but a few represent larger efforts that stalled: `mm/diff-process-hunks` (11 patches) proposed a new `diff.<driver>.process` config to let external tools act as hunk providers, and `ij/subtree-reject-v2-config` (2 patches) tried to prevent users from accidentally running the old shell `git subtree` on repositories already managed by the new Rust implementation.

Overall, the queue is active but not overwhelming; the majority of topics are small fixes, doc updates, or mechanical refactorings.  The larger efforts (`ps/storage-format-improvements`, `ps/commit-graph-write-refactor`, `hn/fetch-refmap`, `ps/ci-speedups`) are the ones to watch—they are well-motivated, have seen recent discussion, and are likely to land in the next cycle.
