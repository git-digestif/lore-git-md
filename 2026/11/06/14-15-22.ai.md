This is a **surface-level review** of Alejandro Colomar’s feature request for a file-type filter in `git ls-files`. The reply from D. Ben Knoble suggests a workaround using the existing `--format` option to expose Git’s internal file-type tracking (via `%(objectmode)`), which could be post-processed to exclude symlinks. The proposal is technically lightweight—no new CLI flags or code changes are required, just a creative use of the existing plumbing.

The workaround is practical but shifts the filtering burden to the user (e.g., piping through `awk` or `grep` to exclude `120000` symlinks). This addresses the immediate use case but doesn’t solve the broader ergonomic issue: users still need to know Git’s internal mode values and write custom scripts. The thread remains in the proposal stage, with no patch yet, but Knoble’s suggestion provides a stopgap while the discussion evolves.

Key details for follow-up: the `%(objectmode)` field (e.g., `100644` for blobs, `120000` for symlinks) is the critical piece of plumbing here. If the feature request advances, it would likely involve adding a `--type` flag to `builtin/ls-files.c` to filter by these modes natively. No new subsystems or on-disk changes would be needed, as Git already tracks this metadata. The thread is still awaiting broader feedback on whether this is worth implementing as a built-in feature.
