This is the second patch in Aniket Gupta’s three-patch bugfix series for the bundle-uri subsystem, and the email is Derrick Stolee’s review of it. The patch itself plugs a minor but real information-disclosure hole: when `relative_url_gently()` (introduced in patch 1) fails to resolve a relative URI, the error message it generates now anonymizes any credentials that were present in the original URL before printing it. The patch also improves diagnosability by showing the full, unmodified input URL rather than a partially-stripped version.

Stolee’s review is substantive but cautious. He questions the necessity of anonymizing the URL in error messages, arguing that the user already knows the problematic string (since they provided it) and that environments storing logs should already be sanitizing command output. He also notes that bundle-uri lists containing credentialed URIs are inherently unsafe, so this patch doesn’t meaningfully protect secrets in that context. That said, he acknowledges the patch accomplishes its technical goal and approves the implementation if the anonymization policy is deemed desirable.

The review leaves the policy question open: whether error messages should sanitize credentials or show the raw input. This is a minor point compared to the larger behavioral choice in patch 3 (whether to skip unresolvable URIs), but it’s now a loose end in the series. The patch itself is small, well-tested, and uncontroversial in its mechanics—it just hinges on whether the project wants to adopt this level of caution in error reporting.
