This is a follow-up in the ongoing feature request for a file-type filter in `git ls-files`. Alejandro Colomar acknowledges D. Ben Knoble’s suggested workaround using `--format=%(objectmode)` and demonstrates how it can be post-processed to exclude symlinks (mode `120000`). He confirms the workaround is functional but reiterates his preference for a native `--type f` flag to simplify the workflow, arguing that `git ls-files` should handle the filtering internally rather than requiring users to chain `grep`, `sed`, and `xargs` commands.

The email advances the thread by showing concrete examples of both the workaround and the proposed native solution, making the ergonomic trade-off explicit. The workaround is viable but cumbersome, especially when dealing with filenames containing spaces (requiring `-z` and null-delimited processing). The proposed `--type f` flag would eliminate this friction, aligning `git ls-files` with tools like `find -type f`. No new technical objections or design questions are raised here; the discussion remains focused on whether the feature’s convenience justifies its implementation.

Key details for future reference: the `%(objectmode)` field remains central (e.g., `100644` for regular files, `120000` for symlinks), and the proposed `--type` flag would likely be implemented in `builtin/ls-files.c`. The thread is still in the proposal stage, with no patch yet, but Colomar’s examples provide a clear benchmark for what the feature should achieve.
