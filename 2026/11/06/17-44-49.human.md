This is a small refactoring proposal for `git fast-import`. Joy, an Outreachy applicant, suggests replacing manual packfile iteration in `fast-import.c` with the existing `repo_for_each_pack()` helper. The goal is to reduce direct access to the files backend while preserving the current behavior for packed-object lookups and duplicate checks.

The patch isn’t written yet—this is a pre-patch RFC asking Patrick Steinhardt (the ODB/refactoring lead) whether the change would fit into the ongoing object-database abstraction work. Joy’s question is narrowly scoped: two functions (`store_object()` and `stream_blob()`) would switch from walking `files->dirs` to using the iterator.

The motivation is plausible but light: avoiding backend internals is generally good hygiene, and `repo_for_each_pack()` is already used elsewhere in the codebase. No performance or correctness claims are made, so the value is purely code-cleanliness. If Patrick gives a green light, this would likely be a single, uncontroversial patch.
