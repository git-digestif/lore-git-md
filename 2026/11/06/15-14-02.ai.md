This is patch 8/12 in Patrick Steinhardt’s v3 series modernizing `git rerere`’s subcommand handling. The patch extracts the "remaining" action into a dedicated `cmd_rerere_remaining()` function with standard `parse_options()` machinery, preserving the existing logic: it calls `rerere_remaining()` to populate a string list of conflicted paths, prints the unresolved ones, and cleans up. The function takes the standard `argc`, `argv`, `prefix`, and `repo` parameters, declares an empty option table (since "remaining" accepts no flags), and calls `parse_options()` to validate that no extra arguments are provided. If arguments are given, it errors out with a usage message; otherwise, it iterates over the conflicted paths in `merge_rr`, prints those not marked `RERERE_RESOLVED`, and cleans up the string list. The existing hand-rolled `if (!strcmp(argv[0], "remaining"))` branch in `cmd_rerere()` is updated to delegate to the new function.

The change is purely mechanical: no behavior change, no new CLI options, and no on-disk format changes. It touches only `builtin/rerere.c` (31 insertions, 11 deletions) and is a preparatory step for patch 11, which will replace the hand-rolled subcommand ladder with `OPT_SUBCOMMAND()`. The patch follows the same pattern established in patches 5–7 for "forget", "clear", and "status", ensuring consistency across the series. The `repo` parameter is passed through to `rerere_remaining()` (which already received it in patch 3), maintaining the series’ goal of eliminating `the_repository` usage. The string-list cleanup logic is preserved verbatim from the original code.
