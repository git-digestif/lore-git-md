This is the third patch in Patrick Steinhardt’s seven-part CI/build system series aimed at speeding up GitLab CI pipelines. It addresses a specific bottleneck in the `fedora-breaking-changes-meson` job, which runs nearly twice as long as other Linux jobs due to unoptimized Meson builds.

The patch switches Meson’s build type from `debug` (which compiles with `-O0`) to `debugoptimized` (which uses `-O2`). This change cuts the Fedora job’s runtime from 35 minutes to 16 minutes—a 54% improvement—while also delivering a 10% speedup for other Linux and macOS jobs. The performance gain is most dramatic for SHA256 operations (9.6s → 1.5s for a 500MB blob), which are heavily impacted by the lack of optimizations in the current setup. SHA1 is less affected (0.9s → 2.1s with `-O0`), so the patch’s impact is more noticeable in jobs that enable breaking changes.

Windows builds see a mixed effect: compilation slows by about two minutes, but tests run 10% faster, leaving total runtime roughly unchanged. The patch itself is minimal—just two lines changed in `.gitlab-ci.yml` and `ci/run-build-and-tests.sh`—and carries low risk, as it only adjusts build flags without altering behavior or on-disk formats.

This is a well-motivated, data-driven optimization that directly targets a known CI pain point. The commit message clearly explains the problem, the solution, and the measured impact, making it easy for reviewers to assess. If the series lands, this patch alone would shave significant time off the Fedora job, which is currently the slowest Linux runner.
