This is a documentation patch, part of Andy Koppe’s v3 series (1/5) to align Git’s glossary and documentation with the 2024 terminology change that narrowed "pseudoref" to `FETCH_HEAD` and `MERGE_HEAD` while introducing "root ref" for refs outside `refs/` (e.g., `HEAD`, `ORIG_HEAD`). The series is uncontroversial and nearly ready for merging, with all substantive feedback incorporated.

Junio’s reply to this patch is a light review, focusing on two minor phrasing suggestions. He proposes removing the contrast between pseudorefs and root refs in the glossary entry ("In contrast to root refs, pseudorefs are not stored..."), arguing that pseudorefs are already established as *not* refs, so the comparison is unnecessary. He also questions whether the glossary should mention `refs/remotes/` and `refs/notes/` hierarchies alongside `refs/heads/` and `refs/tags/`, though he doesn’t insist on the change. Otherwise, he calls the patch "ready" and thanks the author.

The email also includes a tangential observation about code behavior: Git currently treats arbitrary files outside `refs/` (e.g., `.git/out/mister`) as if they were root refs, which Junio suggests should be tightened. He marks this as `#leftoverbits`, indicating it’s unrelated to the current patch and doesn’t block merging.

This patch is purely editorial, with no behavioral changes. It updates the glossary to define "root ref" and clarify "pseudoref" with precise, user-facing language. The remaining suggestions are surface-level and could be addressed in a follow-up if not incorporated now. The series as a whole is well-motivated and addresses a real documentation gap.
