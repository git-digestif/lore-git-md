This is a test optimization patch (part 5/7 of Patrick Steinhardt’s GitLab CI speedup series). It targets `t0027-auto-crlf.sh`, a test script that exercises Git’s CRLF conversion logic and is a known bottleneck in CI pipelines—especially on Windows, where it previously took 480 seconds to run.

The patch eliminates redundant process spawning in the `compare_files()` and `compare_ws_file()` helper functions. These functions are called over a thousand times during the test, but they recompute the same expected output from a small set of input files each time. The fix caches the expected output in `.expect` and `.ws-expect` files on first use, avoiding repeated `tr` and `sed` invocations. The result is a 20–25 % runtime reduction across platforms, with Windows improving from 480 to 380 seconds.

The change is confined to the test script itself (`t/t0027-auto-crlf.sh`); no new files or symbols are introduced. The implementation is straightforward: a one-time check (`test -f`) guards the expensive transformation, and the cached files are left in place rather than cleaned up after each call. This trades a small amount of disk space for a measurable speedup, a trade-off that aligns with the series’ goal of reducing CI wall-clock time.

The patch is part of a larger effort to optimize GitLab CI jobs, but it stands alone as a generic test-suite improvement.
