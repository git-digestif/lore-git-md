This is a review comment on the first patch in Patrick Steinhardt’s five-patch series preparing the Git test suite for ODB abstraction. The series aims to make the test suite backend-agnostic by allowing tests to specify alternative object storage formats via `GIT_TEST_DEFAULT_OBJECT_STORAGE_FORMAT`.

Karthik Nayak’s review is surface-level but constructive. He suggests a small improvement to the test script in `t/t1423-ref-backend.sh`, proposing to replace the explicit loop over `files` and `reftable` backends with a call to `test_detect_ref_format`. This would make the test automatically adapt to whichever ref backend is active in the current CI job, avoiding redundant test runs while still verifying both backends in their respective environments. The change is mechanical and does not affect the patch’s core functionality—it simply makes the test more maintainable and CI-friendly.

The patch itself is a minor but necessary refactoring: it ensures both the "files" and "reftable" ref backends create missing leading directories when initializing, improving usability for non-default ref locations. The review does not raise any substantive concerns about the patch’s logic or impact. If Patrick adopts the suggestion, it will likely be a straightforward adjustment in a future revision.
