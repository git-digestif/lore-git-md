This is a feature request for `git ls-files`.

Alejandro Colomar describes a common workflow where he pipes the output of
`git ls-files` into tools like `grep`, `sed`, or `grepc` to search or
transform source code. He notes that `git ls-files` currently lists all
tracked files, including symlinks, which can interfere with downstream
processing. The `find` command offers a `-type f` filter to exclude symlinks
and other non-regular files, but `git ls-files` lacks an equivalent option.

The request is straightforward: add a flag (e.g., `--type f`) to `git ls-files`
that restricts output to regular files, leveraging Git’s internal knowledge of
file types. Alejandro suggests this should be efficient since Git already tracks
file modes. The motivation is practical rather than theoretical -- he wants to
replace `find . -type f` with a faster, Git-native alternative for scripting.

No patch is attached; this is an RFC-style proposal. The tone is conversational
and the use case is clearly illustrated with examples. There is no indication
of prior discussion on the list about this specific feature, so the thread is
just beginning. If implemented, this would be a small but useful quality-of-life
improvement for developers who script against Git’s file listings.
