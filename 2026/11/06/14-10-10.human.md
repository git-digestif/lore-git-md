This is a **substantive review** of the second patch in Volodymyr Vriukalo’s two-patch bugfix series for the `submodule.propagateBranches` feature. The series targets a crash and incorrect error handling in `git branch --recurse-submodules` when the start point is not a ref name (e.g., a raw object ID).

D. Ben Knoble’s review confirms the patch’s technical soundness but suggests improvements to clarity and presentation. The core fix—making the tracking name argument optional in the `submodule--helper create-branch` command—is uncontroversial and addresses the root cause (a truncated argument list due to `strvec_pushl()` stopping at NULL). Knoble’s feedback focuses on three areas:

1. **Commit message**: He recommends simplifying it to focus on the behavioral change (omitting the tracking name when absent) rather than implementation details, and notes Git’s convention against hanging indents.
2. **Code comment**: While he acknowledges the value of explaining the intent behind pushing the tracking name separately, he suggests the comment could be more concise, as the log message already covers the rationale.
3. **Test design**: The new test verifies the fix by checking that branches are created in both the superproject and submodules, but Knoble notes the lack of explicit assertions (though the `rev-parse` calls implicitly fail if branches are missing).

The review is constructive and does not raise technical objections to the fix itself. The patch remains well-scoped, touching only the necessary code to resolve the crash without altering behavior for ref-based start points. The series is queued in `seen` as `vv/branch-recurse-no-start-ref` but risks being dropped unless further reviews materialize. For now, this patch appears to be a clean, targeted fix for a real bug in an experimental feature.
