This is a brief follow-up in the HTTP retry series, specifically addressing the unresolved default value for `http.retryAfter`. Ravi Mistry concedes to brian m. carlson’s argument that a 1-second initial delay is too short for Git’s computationally expensive requests and agrees to adopt a 10-second default (10s, 20s, 40s, ...). This resolves the primary blocker for the series, shifting the default from the previously proposed 1-second compromise to a value that better balances server protection and user experience. The change will appear in v3, which Mistry plans to send shortly. No other aspects of the series are affected; the rest of the implementation and design remain unchanged.
