This is the first patch in a v3 documentation series (1/5) that updates Git’s glossary to formally define "root ref" and clarify the "pseudoref" entry, aligning terminology with the 2024 redefinition (commit 993d57eded). The patch adds a new "root ref" entry, moves naming rules and irregular refs from the "ref" entry to this new section, and reworks the "pseudoref" definition to emphasize that pseudorefs are *not* refs (contrasting them with root refs). Key details include:

- The "root ref" entry now explicitly lists naming rules (upper-case/underscore names ending in `_HEAD` or `HEAD`) and the exhaustive set of irregular root refs (e.g., `AUTO_MERGE`, `NOTES_MERGE_PARTIAL`), with a note that this list must not be extended.
- The "pseudoref" entry is rewritten to state that pseudorefs have "additional semantics" (e.g., storing multiple object IDs and metadata like FETCH_HEAD’s "not-for-merge" annotations) and are *not* handled by the ref backend. It clarifies that commands like `git log` use the first object ID when a pseudoref contains multiple entries, and that MERGE_HEAD is written by both `git merge` and `git pull`.
- The "ref" entry is updated to remove root-ref-specific rules and now cross-references the new "root ref" entry.
- The patch incorporates prior feedback from Junio C Hamano and Patrick Steinhardt, including Junio’s suggested wording tweaks ("additional" instead of "different" semantics) to avoid implying incompatibility with normal ref operations.

This is a pure documentation change with no behavioral impact. The updated glossary entries provide clearer, more precise definitions and resolve inconsistencies in how root refs and pseudorefs are described across Git’s documentation. The patch is uncontroversial and ready for merging, pending minor editorial suggestions (e.g., cross-references in `gitdatamodel.adoc`) that do not affect this specific change.
