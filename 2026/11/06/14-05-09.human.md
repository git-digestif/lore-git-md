This is a **bugfix patch** for the submodule subsystem, specifically addressing a crash in the experimental `submodule.propagateBranches` feature. The review by D. Ben Knoble is **substantive**, engaging with the technical details of the crash and the test coverage.

The patch itself prevents `git branch --recurse-submodules` from attempting to set up tracking when the start point is not a ref name (e.g., a raw object ID or revision expression like `HEAD~0`). Without this fix, Git aborts with a BUG in `refspec_find_match()` after partially completing the operation, leaving scripts that check the exit status misled about whether the branch update succeeded. The fix aligns the recursive branch creation path with the non-recursive one, which already guards against this case.

D. Ben Knoble’s review focuses on two main points: clarifying the commit message and improving the test. He suggests rewriting the commit message to make the crash scenario easier to follow, proposing a more concise explanation of how the NULL `tracking_name` propagates through `setup_tracking()` and `remote_find_tracking()`. He also questions the test’s use of `HEAD~1` as the initial branch target, noting that the bug can be triggered even without forcing the branch (`-f`), and suggests simplifying the test to directly use a raw object ID. His feedback is constructive and technically grounded, though it does not identify any flaws in the fix itself.

The patch is well-motivated and narrowly scoped, touching only `branch.c` and adding a test in `t/t3207-branch-submodule.sh`. The crash is limited to a specific combination of conditions (submodule recursion enabled, `propagateBranches` set, a configured remote, and a non-ref start point), so the fix is unlikely to introduce regressions elsewhere.
