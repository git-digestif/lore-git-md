This is a documentation patch series (v3) that aligns Git’s terminology around "root refs" and "pseudorefs" with the 2024 redefinition (commit 993d57eded). The series updates the glossary, man pages, code comments, and tests to consistently distinguish between *root refs* (refs outside `refs/` like HEAD and ORIG_HEAD) and *pseudorefs* (only FETCH_HEAD and MERGE_HEAD, which store metadata and multiple object IDs). This v3 addresses all prior review feedback, including Junio C Hamano’s and Patrick Steinhardt’s suggestions to clarify pseudoref semantics (e.g., multi-object storage, metadata) and improve cross-referencing between `gitdatamodel.adoc` and the glossary.

Key changes in v3:
- The glossary’s "pseudoref" entry now explicitly contrasts pseudorefs with root refs, detailing their "additional semantics" (e.g., FETCH_HEAD’s multi-object format and "not-for-merge" annotations). It also clarifies that MERGE_HEAD is written by `git-pull` (not just `git-merge`).
- `gitdatamodel.adoc` now links to the glossary for definitions of root refs and pseudorefs, improving navigability.
- Commit messages for patches 1/5 and 2/5 were reworded for clarity, and the "per-worktree ref" glossary entry now uses itemized lists for better readability.

The series touches 22 files, including man pages (`git-update-ref`, `git-worktree`), the glossary, test scripts, and in-code comments. No behavioral changes are introduced—this is purely a terminology cleanup. The updates are thorough and uncontroversial, with all substantive review feedback incorporated. The only remaining loose ends are minor editorial tweaks (e.g., Patrick Steinhardt’s suggestion to drop "also" from `gitdatamodel.adoc`), which could be addressed in a follow-up if not resolved in v3.
