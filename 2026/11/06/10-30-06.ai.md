This is the sixth patch in Patrick Steinhardt's seven-patch series optimizing GitLab CI performance. It targets the `t1092-sparse-checkout-compatibility.sh` test script, which verifies sparse-checkout behavior across three repository configurations (full checkout, sparse checkout, sparse index). The patch replaces the current per-test repository initialization—where each of the 100+ test invocations recreates repositories from scratch—with a template-based approach. Instead of running dozens of processes to set up each repository, the test now copies pre-configured template repositories, reducing Windows test time by approximately 3 minutes (from over 10 minutes to around 7 minutes).

The change is straightforward: a new `setup template repositories` test helper creates and configures the three template repositories once, and `init_repos()` now copies these templates rather than recreating them. The patch touches only the test script, with no new symbols or on-disk format changes. While the optimization is most dramatic on Windows, it also benefits other platforms by eliminating redundant process overhead. This is a well-motivated, low-risk improvement that directly addresses a known CI bottleneck in the sparse-checkout test suite.
