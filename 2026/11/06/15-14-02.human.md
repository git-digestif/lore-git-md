This is the eighth patch in Patrick Steinhardt’s 12-part refactoring series that modernizes `git rerere`’s subcommand handling. The series is a well-executed internal restructuring with no behavior changes, and this patch extracts the "remaining" action into a dedicated function (`cmd_rerere_remaining()`) using Git’s standard `parse_options()` machinery.

The patch is a straightforward mechanical refactoring. It moves the existing logic for listing unresolved conflicts (previously a hardcoded `if (!strcmp(argv[0], "remaining"))` branch) into a new function with an empty option table, since "remaining" accepts no flags. The function validates that no extra arguments are provided, calls `rerere_remaining()` to populate the conflict list, prints unresolved paths, and cleans up. The change is purely preparatory for the later `OPT_SUBCOMMAND()` conversion (patch 11) and aligns with the series’ goal of consistency with other multi-subcommand built-ins like `git notes`.

No new behavior, CLI options, or on-disk format changes are introduced. The patch touches only `builtin/rerere.c` and is uncontested—Karthik Nayak’s review of earlier patches in the series focused on documentation and naming, neither of which apply here. This is a low-risk, guideline-aligned step in a larger effort that has already addressed all substantive feedback. The series as a whole is ready for integration, and this patch is a routine part of that progression.
