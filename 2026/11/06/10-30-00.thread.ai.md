Core problem or goal
Reduce end-to-end CI runtime in Git's GitLab pipelines by addressing specific bottlenecks in test execution, SDK installation, and build configuration. The series targets both GitLab-specific and generic CI environments, with measurable speedups demonstrated across macOS, Fedora, and Windows runners.

Key technical details
- Files touched: `.gitlab-ci.yml`, `ci/install-sdk.ps1`, `ci/run-build-and-tests.sh`, test scripts `t0027-auto-crlf.sh`, `t0027`, `t1092-sparse-checkout-compatibility.sh`, `t5551-http-fetch-smart.sh`, `t5559`
- Subsystems: CI infrastructure, test suite, build system (Meson)
- New/renamed symbols: None (CI configuration flags and test optimizations only)
- Behavior changes:
  - Git for Windows SDK installation now uses `tar(1)` instead of Extract-Archive (3m → 10s), with strict error handling and suppressed progress output (patch 1/7)
  - SDK archive cache removed in v2 (previously saved download time; cache key included SDK URL to prevent staleness, but Junio raised staleness concerns)
  - `t0027` repository reset logic optimized (Windows: >10m → 6m) via single `rm` + single `git checkout` for all five files (previously ten separate processes)
  - `t0027-auto-crlf.sh` now caches expected output in `.expect` and `.ws-expect` files, avoiding repeated `tr`/`sed` invocations (Windows: 480s → 380s; macOS: 71s → 54s (24% reduction); 20–25% reduction across platforms). Adopts Junio’s loop-based refactoring for readability while preserving performance.
  - `t5551-http-fetch-smart.sh` and `t5559` now use reftable backend (macOS: 20m → 2m per test; Linux: runtime halved)
  - `t1092-sparse-checkout-compatibility.sh` now uses template-based repository initialization (Windows: >10m → ~7m)
  - Meson builds now use `-Doptimize=debug` flag for faster compilation (Linux/macOS) and `--buildtype=debugoptimized` (Fedora: 2100s → 1000s; SHA256 hashing 500MB blob: 9.6s → 1.5s at `-O2`). The change aligns Meson flags with Git’s traditional Makefile defaults (`-g -O2`).
  - Windows build artifacts now exclude ~1,800 intermediate "*.obj" files (patch 2/7), cutting artifact download/extraction time from 34s to 17s per test job. The exclusion rule (`exclude: - build/**/*.obj`) is added to the `build:msvc-meson` job in `.gitlab-ci.yml`.
- On-disk format: No changes
- Test coverage: Directly modifies test scripts (`t0027-auto-crlf.sh`, `t0027`, `t1092-sparse-checkout-compatibility.sh`, `t5551-http-fetch-smart.sh`, `t5559`); no new test files added

Open questions and loose ends
- Windows runners remain the critical path despite improvements (author notes this as a remaining bottleneck).
- SHA256 performance with `-O0` optimization is flagged as poor but addressed in this series via `-O2` for Fedora jobs.
- No new substantive objections raised in v2; stylistic feedback from v1 (patch 4/7) resolved by adopting Junio’s loop-based refactoring.
