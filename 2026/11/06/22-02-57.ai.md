This is the fifth patch in Andy Koppe’s v3 series updating Git’s documentation to align with the 2024 terminology change that narrowed "pseudoref" to FETCH_HEAD and MERGE_HEAD while introducing "root ref" for refs outside the "refs/" hierarchy. The email is Andy’s reply to Julia Evans’s feedback on the glossary’s "pseudoref" entry, incorporating Junio C Hamano’s and Patrick Steinhardt’s suggestions while declining Julia’s proposal to include a concrete FETCH_HEAD file-format example.

Andy’s revised glossary entry for "pseudoref" now leads with the key behavioral distinction—pseudorefs can record multiple object IDs and carry metadata, unlike root refs—and explicitly states that pseudorefs are not handled by the ref backend. The entry clarifies that commands like `git log` use the first object ID when multiple entries are present, a point Junio emphasized in review. FETCH_HEAD and MERGE_HEAD are described in more accessible prose, specifying that FETCH_HEAD records fetched objects with their source ref and merge status, while MERGE_HEAD records commits during a merge (including via `git pull`). The phrasing avoids the cryptic example Julia suggested but still improves readability over the v2 version. This change is purely editorial and does not affect the series’ technical scope, which remains uncontroversial and ready for merging. The two minor editorial suggestions from Patrick Steinhardt (dropping "also" in `gitdatamodel.adoc` and adding glossary cross-references) are still pending but do not block progress.
