This thread is about a feature request from Alejandro Colomar to add a file-type filter option to `git ls-files`, specifically to exclude symlinks. The goal is to improve workflow efficiency when using downstream tools like `grep` or `sed` in large directories, such as a built Linux kernel tree, where `find . -type f` is slower than a Git-native solution.

So far, the only feedback has come from D. Ben Knoble, who suggested a workaround using the existing `--format` option with `%(objectmode)` to expose Git’s internal file-type tracking. This approach avoids new code but requires users to manually filter output (e.g., with `awk` or `grep`), which is less ergonomic than a built-in flag. The thread remains in the early proposal stage, with no patches or broader feedback yet. The next steps will likely depend on whether others see value in adding a native `--type` filter to `git ls-files`.
