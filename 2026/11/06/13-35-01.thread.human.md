This thread is about a feature request for `git ls-files` to add a `--type` filter option (e.g., `--type f` to exclude symlinks), proposed by Alejandro Colomar. The goal is to replace cumbersome workarounds—like piping `git ls-files --format=%(objectmode)` into `grep` or `awk`—with a native Git solution that simplifies workflows, especially in large directories like Linux kernel trees. The feature would leverage Git’s existing `%(objectmode)` tracking (e.g., `100644` for regular files, `120000` for symlinks) without requiring on-disk format changes.

Colomar has now explicitly volunteered to implement the feature if the community welcomes the idea, shifting the thread from a theoretical discussion to a potential contribution. While no maintainer or core contributor has yet weighed in on the proposal’s merit, the workaround’s limitations—such as handling filenames with spaces—highlight the ergonomic benefits of a native `--type` flag. D. Ben Knoble previously suggested the `--format=%(objectmode)` workaround but did not engage with the proposal’s design or necessity.

The thread remains in the proposal stage, with no patch submitted yet. The next step is likely a patch submission from Colomar, assuming no major objections arise. For now, the discussion hinges on whether the feature’s convenience justifies its inclusion in Git.
