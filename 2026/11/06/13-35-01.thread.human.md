This thread is a feature request from Alejandro Colomar proposing that `git ls-files` gain an option to filter its output by file type, specifically to exclude symlinks. The motivation is workflow-oriented: Alejandro frequently pipes `git ls-files` output into tools like `grep` or `grepc`, and symlinks in the output can interfere with these tools. He notes that `find . -type f` avoids this issue but is slower, especially in large directories like a built Linux kernel tree. Since Git already tracks file types internally, he suggests the feature should be straightforward to implement.

The request is framed as a practical improvement rather than a technical necessity, and the use case is clearly illustrated with concrete examples. No patch is attached—this is purely a discussion starter. So far, there are no replies or prior feedback to summarize, so the thread’s status is simply an open proposal awaiting community input.
