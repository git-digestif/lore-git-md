This thread is about a feature request from Alejandro Colomar to add a file-type filter option to `git ls-files`, specifically to exclude symlinks. The goal is to improve workflow efficiency when using downstream tools like `grep` or `sed` in large directories, such as a built Linux kernel tree. Currently, there’s no native way to filter by file type in `git ls-files`, and the workaround involves using `--format=%(objectmode)` to expose Git’s internal file-type tracking, then post-processing the output with tools like `awk` or `grep` to exclude symlinks (mode `120000`). While this workaround works, it’s cumbersome, especially for filenames with spaces, and Colomar argues that a native `--type f` flag would be more ergonomic.

The discussion remains in the proposal stage, with no patch yet submitted. D. Ben Knoble previously suggested the workaround, but the thread hasn’t yet addressed whether the feature is worth implementing as a built-in option. Colomar’s latest email provides concrete examples of both the workaround and the proposed native solution, highlighting the trade-offs. The proposed `--type` flag would leverage Git’s existing `%(objectmode)` tracking (e.g., `100644` for regular files, `120000` for symlinks) and would likely be implemented in `builtin/ls-files.c`. No design objections or requests for changes have been raised so far, but the thread is still awaiting broader feedback on whether the feature’s convenience justifies its inclusion.
