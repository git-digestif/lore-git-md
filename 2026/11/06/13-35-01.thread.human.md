This thread began as a feature request from Alejandro Colomar for `git ls-files` to add a `--type` filter (e.g., `--type f` to exclude symlinks), aiming to simplify workflows in large directories like built Linux kernel trees. The proposal sought to replace slower workarounds (e.g., `find` or post-processing Git’s output) with a Git-native solution, leveraging existing `%(objectmode)` tracking.

The maintainer, Junio C Hamano, rejected the idea, arguing that `git ls-files` is a plumbing command and should not grow arbitrary filtering options to avoid feature creep. Instead, he provided a pipeline-based workaround using `git ls-files -z -s | sed` and `xargs`, which Alejandro later adapted into a local wrapper script, `git-find`. The thread concluded amicably, with Alejandro conceding the maintainer’s point and implementing his own solution without further advocacy for the feature. A minor style debate over pipeline readability (ending vs. beginning lines with `|`) was noted but left unresolved.

The discussion is now closed, with no patches submitted or pending. The key takeaway is that Git’s plumbing commands are intentionally minimal, and users are encouraged to combine existing tools (e.g., `sed`, `xargs`) for filtering rather than adding new flags. Alejandro’s wrapper script demonstrates a practical alternative for those needing similar functionality.
