This thread is about Patrick Steinhardt’s seven-patch series (now at v3) to speed up Git’s GitLab CI pipelines. The series targets specific bottlenecks in test execution, SDK installation, and build configuration, with measurable improvements across macOS, Fedora, and Windows runners. Junio C Hamano has reviewed the series and stated he has no technical objections, calling the patches "interesting" and "fully made sense," which signals likely queuing for the `next` branch unless other reviewers raise substantive issues.

Key optimizations include replacing Extract-Archive with `tar` for Git for Windows SDK installation (reducing time from 3 minutes to 10 seconds), caching expected output files in `t0027-auto-crlf.sh` (cutting runtime by 20–25%), and switching two tests to the reftable backend (speeding up macOS tests tenfold). The series also consolidates process invocations in `t0027` and `t0027-auto-crlf.sh`, reduces artifact handling time on Windows, and optimizes Meson build flags for faster compilation. All changes are low-risk, with clear before/after metrics and no on-disk format or behavior changes.

Feedback from Junio and Torsten Bögershausen has been addressed in v3. Junio’s suggestions—such as documenting the `tar` portability assumption and clarifying variable initialization in `t0027-auto-crlf.sh`—were incorporated, while Torsten’s alternative implementation for patch 5/7 was benchmarked but not adopted due to negligible performance differences. The series is now under final review, with Windows runners remaining the critical path for further improvements. Patrick has also floated the idea of unifying GitHub Workflows with the GitLab CI script but deferred the decision to Johannes Schindelin.
