This patch series from Patrick Steinhardt aims to speed up Git's GitLab CI pipelines by addressing bottlenecks in test execution, SDK installation, and build configuration. The series is now in its third version, with Junio C Hamano having stated he has no technical objections and finds the changes sensible, making it likely to be queued for the `next` branch soon unless other reviewers raise substantive issues.

The optimizations are wide-ranging but focused. On Windows, SDK installation now uses `tar` instead of Extract-Archive (cutting time from 3 minutes to 10 seconds), and test scripts like `t0027-auto-crlf.sh` and `t1092-sparse-checkout-compatibility.sh` have been streamlined to reduce redundant operations. Meson builds now use `-Doptimize=debug` for faster compilation on Linux and macOS, while Windows builds exclude intermediate `.obj` files to halve artifact handling time. The most dramatic improvement comes from switching two HTTP-fetch tests to the reftable backend, which slashed macOS runtime from 20 minutes to 2 minutes. Collectively, these changes have reduced CI runtime by 30–50% across platforms, with Windows runners still remaining the critical path.

Feedback from Junio and Torsten Bögershausen has been addressed in this version. Junio’s concerns about portability and defensive programming were resolved with documentation and minor code tweaks, while Torsten’s alternative implementation for one optimization was benchmarked but not adopted due to negligible performance differences. The series is positioned as low-risk, with clear before-and-after metrics demonstrating its impact. No major open questions remain, and the changes are unlikely to face further pushback.
