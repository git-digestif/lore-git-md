This thread is about Patrick Steinhardt’s seven-patch series to speed up Git’s GitLab CI pipelines. The series targets specific bottlenecks in test execution, SDK installation, and build configuration, with measurable improvements across macOS, Fedora, and Windows runners. So far, the series is under review in its initial version (v1), with no prior iterations or merge status reported.

The first patch, which Junio C Hamano recently reviewed, optimizes the Git for Windows SDK installation in the `build:mingw64` job. It replaces `Expand-Archive` with `tar(1)` for extraction (reducing time from 3 minutes to 10 seconds) and caches the SDK archive between CI runs. Junio’s review was surface-level, raising minor questions about the performance gap between tools and whether the cached SDK might go stale, but he didn’t dispute the patch’s core improvements. His feedback is clarifying rather than critical, and the patch is likely to proceed with minimal changes.

Other patches in the series address bottlenecks like test repository reset logic, expected output caching in `t0027-auto-crlf.sh`, reftable backend usage in `t5551` and `t5559`, and Meson build optimizations. While Windows runners remain the critical path, the series demonstrates clear speedups—such as cutting Fedora job time from 2100s to 1000s and reducing artifact handling time from 34s to 17s. No substantive objections have been raised yet, and the series is positioned as a practical infrastructure improvement with low risk to Git’s core functionality.
