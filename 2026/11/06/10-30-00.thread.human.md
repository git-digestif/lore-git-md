This thread is about Patrick Steinhardt’s seven-patch series to speed up Git’s GitLab CI pipelines. The series, now in its second version, targets bottlenecks in test execution, SDK installation, and build configuration, with measurable improvements across macOS, Fedora, and Windows runners. Junio C Hamano has reviewed the series and stated he has no technical objections, calling it "interesting" and "fully made sense," which suggests it’s likely to be queued for the `next` branch unless other reviewers raise substantive issues.

The key optimizations include switching Git for Windows SDK installation to use `tar` instead of Extract-Archive (reducing installation time from 3 minutes to 10 seconds), optimizing test repository reset logic in `t0027` (cutting Windows runtime from over 10 minutes to 6 minutes), caching expected output in `t0027-auto-crlf.sh` (yielding a 20–25% reduction in runtime), and using template-based repository initialization in `t1092-sparse-checkout-compatibility.sh` (reducing Windows runtime from over 10 minutes to about 7 minutes). The latest patch, the seventh in the series, switches `t5551-http-fetch-smart.sh` to the reftable backend, achieving a 10x speedup on macOS (from 20 minutes to 2 minutes) and halving the runtime on Linux. Meson builds also benefit from debug optimization flags, cutting Fedora job times from 2100 seconds to 1000 seconds.

Feedback from Junio and Torsten Bögershausen was largely stylistic and has been addressed in this version. The series is positioned as low-risk, with clear before-and-after metrics demonstrating its impact. The main remaining bottleneck is Windows runners, though the improvements here still represent significant progress. No substantive objections have been raised, and the series appears on track for integration.
