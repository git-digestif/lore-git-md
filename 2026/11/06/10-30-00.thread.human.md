This thread is about Patrick Steinhardt’s seven-patch series to speed up Git’s GitLab CI pipelines by addressing bottlenecks in test execution, SDK installation, and build configuration. The series has shown measurable improvements across macOS, Fedora, and Windows runners, with notable reductions in runtime for specific tests and build jobs.

Junio C Hamano, the maintainer, has reviewed parts of the series and stated he has no technical objections, calling the patches "interesting" and "fully made sense." This suggests the series is likely to be queued for `next` unless other reviewers raise substantive issues. So far, the only adjustments requested are minor clarifications and a decision to drop the SDK cache in the next version (`v2`) to avoid potential staleness, which Patrick has agreed to. The core optimizations, such as switching to `tar(1)` for SDK extraction (reducing time from 3 minutes to 10 seconds), remain intact.

The series touches CI infrastructure, test scripts, and build system configurations, with no changes to Git’s core functionality or on-disk format. Key improvements include faster SDK installation, optimized test resets, cached test outputs, and reduced build times. Windows runners remain a bottleneck, but the series still delivers significant speedups overall. Torsten Bögershausen provided substantive feedback on one patch, confirming its performance gains and offering an alternative implementation, which Patrick incorporated in spirit by adopting Junio’s loop-based refactoring.

The next version (`v2`) will proceed with the `tar(1)` optimization and without the SDK cache, keeping the focus on practical, low-risk improvements to CI performance. No major open questions remain, and the series appears on track for integration.
