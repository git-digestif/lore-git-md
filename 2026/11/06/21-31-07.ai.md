This is the fourth patch in Andy Koppe’s v3 series (5/5) that aligns Git’s documentation and code with the 2024 terminology change distinguishing *root refs* (refs outside `refs/`, like HEAD and ORIG_HEAD) from *pseudorefs* (only FETCH_HEAD and MERGE_HEAD). This patch updates in-code comments and help text in four files to replace outdated uses of "pseudoref" with "root ref" where appropriate, while leaving the bash-completion function `__git_pseudoref_exists()` unchanged due to its ambiguous scope (covering both root refs and pseudorefs) and potential third-party dependencies.

The changes are mechanical but precise: the help text for `git for-each-ref --include-root-refs` now says "also include root refs" instead of "also include HEAD ref and pseudorefs"; the comment in `refs.h` for `REFS_FOR_EACH_INCLUDE_ROOT_REFS` clarifies that it includes root refs like HEAD and ORIG_HEAD (omitting pseudorefs); and the pseudoref definition in `refs.h` is reworded to emphasize that pseudorefs are names with "different semantics" (e.g., multi-object storage in FETCH_HEAD) that cannot be stored in the ref backend. The error message in `revision.c` for `--merge` drops the redundant "pseudorefs" label when listing MERGE_HEAD and similar refs. The bash-completion script’s comments are updated to reflect that `__git_pseudoref_exists()` checks both root refs and pseudorefs, though the function name itself remains unchanged.

No behavioral changes are introduced—this is purely a terminology cleanup. The patch is uncontroversial and ready for merging, as all prior review feedback (including Junio’s and Patrick Steinhardt’s suggestions) has been addressed in earlier patches. The only remaining loose ends are two minor editorial tweaks to `gitdatamodel.adoc` (not touched here), which do not block progress. The files modified are `builtin/for-each-ref.c`, `contrib/completion/git-completion.bash`, `refs.h`, and `revision.c`.
