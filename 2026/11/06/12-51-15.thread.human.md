This thread is about a small but important bugfix for the `git unpack-objects` command. Kristofer Karlsson identified a type mismatch on 32-bit platforms (like Windows) where blob sizes larger than 4GB get truncated because `unsigned long` is only 32 bits wide. The fix is simple: change one line in `builtin/unpack-objects.c` to use `size_t` instead of `unsigned long` for the blob size parameter in `stream_blob()`, matching the rest of the codebase which already uses `size_t` for object sizes after a prior change.

The issue causes a fatal write error when unpacking large blobs, and the patch aligns the type usage without changing behavior on 64-bit systems. This is a platform-compatibility fix that follows up on an earlier change from May 2026. The fix itself is uncontroversial—it’s a straightforward type correction that only affects the internal loose-object writing code. The test case that exposes this issue is in the second patch of the series, which is typical for bugfixes where the test depends on the fix.

So far, there’s been no review feedback on this patch, but given its narrow scope and clear problem statement, it’s likely to be merged quickly once the accompanying test is reviewed. The thread is currently just the patch submission, so the next step is for reviewers to weigh in on both the fix and the test.
