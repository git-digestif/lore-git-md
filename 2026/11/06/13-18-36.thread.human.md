This Outreachy internship thread is about Shashank S.'s proposal (now at v3) to add configurable ordering to Git's promisor remote fetching in partial clones. The goal is to let users prioritize which remotes Git tries first when fetching missing objects, which could improve performance and reliability in setups with multiple promisor remotes.

So far, the proposal has been refined through two earlier versions, and Shashank has already contributed four related patches—two test modernizations, a `the_repository` cleanup, and an option-parsing improvement—that have been merged or queued. No implementation work has started yet; the current focus is on planning, documentation, and test design before moving to RFC discussions. Key technical areas include `promisor-remote.c`, configuration parsing, and potential protocol changes for server-side preferences.

The main open questions revolve around how to structure the configuration (ordered list vs. numeric priorities), how servers might advertise preferences, and how local settings should interact with server hints. There’s also some uncertainty about how this work will mesh with Patrick Steinhardt’s ongoing ODB abstraction efforts. So far, feedback has been light—Kaartic Sivaraam’s recent reply was encouraging but didn’t engage with the technical details, so the proposal is still waiting for deeper review from mentors or maintainers.
