This is the sixth patch in Patrick Steinhardt’s seven-part series to speed up Git’s GitLab CI pipelines. It targets the `t1092-sparse-checkout-compatibility.sh` test script, which verifies sparse-checkout behavior across three repository configurations: full checkout, sparse checkout, and sparse index.

The patch replaces the current `init_repos()` function—which recreates each repository from scratch over 100 times during the test run—with a template-based approach. Instead of running dozens of Git processes to initialize sparse-checkout definitions and reset repositories each time, the test now creates three template repositories once during setup, then simply copies them into place for each test case. This change cuts the Windows test runtime from over 10 minutes to about 7 minutes, a meaningful improvement in a CI pipeline where Windows runners are the critical path.

The implementation is straightforward: a new `setup template repositories` test helper creates the three template directories (`full-checkout.template`, `sparse-checkout.template`, `sparse-index.template`) with all necessary sparse-checkout definitions pre-configured. The `init_repos()` function then becomes a simple `cp -r` for each template followed by a `git reset --hard`, eliminating the repeated `git sparse-checkout init`, `git sparse-checkout set`, and configuration commands.

This is a clean refactoring of test infrastructure rather than a behavior change; the test’s assertions remain identical. The patch is well-motivated by the performance data and fits neatly into the series’ overall goal of reducing CI overhead. No new configuration flags or user-facing changes are introduced.
