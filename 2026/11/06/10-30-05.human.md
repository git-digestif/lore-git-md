This is a test optimization patch, part of Patrick Steinhardt’s seven-patch series to speed up GitLab CI. It targets `t0027-auto-crlf.sh`, a test script that verifies Git’s CRLF conversion behavior across different line-ending configurations.

The patch eliminates redundant process spawning in the `compare_files()` and `compare_ws_file()` helper functions. These functions are called over a thousand times during the test run, but they repeatedly compute identical expected outputs from a small set of input files. The fix caches the expected output files on first use, avoiding unnecessary recomputation. On Linux, this reduces runtime by 20-25%; on Windows, the test now completes in 380 seconds instead of 480 seconds.

The implementation is straightforward: the patch wraps the output-generation logic in a conditional check (`test -f "$1".expect || ...`) and removes the explicit cleanup of temporary files, letting the test framework handle it. The change is contained to a single file and does not alter test behavior—only its efficiency.

This is a well-motivated, low-risk optimization that directly addresses a measurable bottleneck in CI. The commit message clearly states the problem, the solution, and the performance impact, making it easy to assess. If the series lands, this patch will contribute to faster feedback loops for developers, especially on Windows runners where the improvement is most pronounced.
