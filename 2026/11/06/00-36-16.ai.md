This is a **maintainer review** of the v4 patch that fixes `--grep` and related option parsing in `git rev-list`. Junio C Hamano raises a **substantive design concern**: the patch hardcodes an array of 19 option strings in `rev_list_option_takes_argument()`, duplicating parser logic and creating a maintenance hazard. He points out that the list is already incomplete—it omits options like `--diff-merges` (parsed in `diff-merges.c`) and `--src-prefix`/`--dst-prefix` (parsed in `diff.c`)—and asks whether the fix would correctly handle a command like `git rev-list --src-prefix --missing-only HEAD`.

The review does not reject the patch outright but signals that the current approach is fragile and unlikely to be merged as-is. No new tests or edge cases are suggested; the focus is entirely on the architectural flaw of duplicating option-parsing knowledge. The thread remains under review, with the ball in the author’s court to propose a more robust solution.
