This is a brief follow-up in the ongoing bugfix series to make `git clone` and `git fetch` skip unresolvable relative URIs in bundle lists instead of dying. Aniket Gupta acknowledges Derrick Stolee’s feedback on patch 2 (credential anonymization in error messages) and notes that the current implementation only covers one specific error message, not all cases where credentials might leak. He observes that Git already hides passwords in some contexts (e.g., the "From" line in fetch output) and suggests the patch could be dropped if Stolee and Patrick Steinhardt deem it unnecessary.

He also corrects a minor inaccuracy in the commit message for patch 3: the clone does not continue with *all* remaining bundles after an unresolvable URI, but rather stops processing the bundle list at the bad entry and falls back to fetching from the remote. He offers to send a v4 to fix this wording if the reviewers agree. The tone is collaborative and low-stakes; no technical changes are proposed, just a documentation tweak. The series remains ready for maintainer pickup.
