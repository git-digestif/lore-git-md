This is the first patch in Patrick Steinhardt’s 12-patch refactoring series that modernizes `git rerere`’s subcommand handling. The patch is a straightforward rename: it changes the function `repo_rerere()` to `rerere()` and updates its documentation to better explain its role as the main entry point for recording and reusing conflict resolutions.

The change is purely mechanical—no behavior or signature changes—and aligns the function name with the rest of the `rerere_*` family in `rerere.h`. The commit message notes that the `repo_` prefix was never a good fit, since the function’s purpose isn’t tied to the repository parameter in a way that justifies the prefix. All callers (in `apply.c`, `builtin/am.c`, `builtin/commit.c`, `builtin/merge.c`, `builtin/rerere.c`, `builtin/stash.c`, `rerere.c`, and `sequencer.c`) are updated to use the new name.

This patch is uncontested and ready for integration; it was already reviewed and accepted in earlier iterations of the series. The only feedback was stylistic (the rename itself), and that has been resolved. The patch is a low-risk, high-consistency refactoring that sets the stage for the rest of the series.
