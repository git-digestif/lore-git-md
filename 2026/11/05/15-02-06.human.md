This is the final patch in Patrick Steinhardt’s five-part series preparing the Git test suite for non-default object storage backends. It adds the `GIT_TEST_DEFAULT_OBJECT_STORAGE_FORMAT` environment variable, defaulting to the "files" backend, mirroring the existing mechanism for ref storage formats.

The patch itself is minimal—just four lines in `t/test-lib.sh`—but it unlocks the series’ core goal: exposing tests that hard-code assumptions about `.git/objects` by allowing them to run with a payload like `files://objdir`. The commit message notes that only ~1,100 of 35,000 tests fail under this regime, a surprisingly low number that suggests the test suite is already fairly backend-agnostic. Fixing those failures is deferred to follow-up work, as the series focuses on infrastructure rather than immediate compatibility.

This is a test infrastructure patch, not a user-facing change. It’s part of the ongoing ODB abstraction effort, and while the variable isn’t immediately useful (no alternative backend exists yet), it serves as a placeholder for future backends and a diagnostic tool for identifying brittle tests. The patch is well-motivated and clearly explained, though its impact will only become visible once alternative backends materialize. For now, it’s a sensible step toward making the test suite more flexible.
