This is a test-infrastructure patch from Junio C Hamano that responds to Kristofer Karlsson’s test-fix proposal for the `git describe` regression thread. The patch is not yet finalized but represents Junio’s preferred approach to resolving the test inconsistency introduced by Linus Torvalds’ generation-number-based fix.

Junio acknowledges the problem Kristofer identified: Linus’s patch causes `t6120.102` (the `--candidates=2` disjoint-history test) to pass when a commit-graph exists but still fail without one, breaking the test’s expected-failure state. Instead of Kristofer’s proposed workaround (forcing the test to run without a commit-graph), Junio suggests a more principled solution: **freeze the test to always run with `GIT_TEST_COMMIT_GRAPH=1` and flip the test from `expect_failure` to `expect_success`**. This aligns with the project’s default behavior (since mid-2019, `core.commitGraph` defaults to `true`) and avoids testing an artificially degraded mode. The change is minimal—just four lines in `t/t6120-describe.sh`—but shifts the test’s baseline to the modern, commit-graph-enabled world.

The patch is a surface-level review adjustment (test hygiene) rather than a substantive change to the algorithmic debate. It does not address the open question of whether to adopt Linus’s generation-number fix or Kristofer’s two-counter prototype, but it ensures the test suite remains reliable while that discussion continues. Junio’s preference for testing the "default" case (commit-graph enabled) reflects the project’s long-term direction, though he notes the ideal would be to test both modes—something this patch does not yet achieve. No objections or alternative approaches have been raised in this email, but the patch is still under discussion.
