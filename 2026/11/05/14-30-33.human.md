This is a review of Yopa Nelly’s promisor-remote ordering patch. Tanga Joris reports a crash when the new `promisor.fetchOrder` config is set: the process hits a BUG() in `string_list_split_in_place()` because the list was initialized with `STRING_LIST_INIT_DUP` but the code tries to split in-place. The reviewer also points out that the file-static `fetch_order` list is never cleared, so values from multiple config files accumulate, and that the list is shared across all repositories in the process (including submodules), while the rest of the promisor config is per-repository. Finally, Tanga notes two surface-level issues: the new config key is missing from `Documentation/config/promisor.adoc`, and one line uses spaces instead of a tab for indentation.

The review is substantive: it identifies a real crash, a design mismatch with the rest of the subsystem, and a documentation gap. The author will need to address the string-list misuse, decide whether the ordering should be per-repository or global, and add the missing documentation before the patch can move forward. The crash alone is a blocker; the other points are important but secondary.
