This is the third patch in Tanga Joris's v4 series fixing a Bash completion regression for four built-in commands (`patch-id`, `diff-pairs`, `fast-import`, `var`). The patch adds a defensive test in `t/t0012-help.sh` to catch future regressions where built-ins converted to `parse-options` retain the `NO_PARSEOPT` flag in `git.c`. The test runs `git <cmd> --git-completion-helper` for every built-in not listed in `git --list-cmds=parseopt` and fails if the command prints any long options (starting with `--`). It currently skips five diff-related commands (which print diff options) and `rev-parse` (which echoes arguments), and it does not catch `var` because that command only has short options.

The test is well-motivated and directly addresses Kaartic Sivaraam's suggestion to prevent future `NO_PARSEOPT` regressions. It already catches the three commands (`diff-pairs`, `fast-import`, `patch-id`) that were fixed in the previous patch, confirming the regression would have been detected. The limitation with `var` (short options only) is noted in the commit message, making it clear the test is not exhaustive. Tanga offers to squash this patch into the second one if Kaartic prefers, but the separation makes the test easier to review and modify independently. The test is a sensible addition to the series and does not introduce new dependencies or edge cases.
