This is Junio’s reply to the first patch in Tanga Joris’s v4 series, which centralizes `--git-completion-helper` handling in `parse-options.c` to fix a Bash completion regression for four built-in commands. Junio points out that the proposed comment in `parse-options.h` is misleading because it frames the function’s purpose around the unusual behavior of `fast-import` (waiting for input or leaving temporary files), which is not a general concern for most Git commands. Instead, he suggests the comment should clarify that the function is only needed when a command must handle help or completion flags *before* calling `parse_options()`, which is rare and typically only applies to commands with unusual initialization sequences like `fast-import`. The feedback is a documentation nit, not a technical objection, and does not block the patch’s correctness or the series’ overall goal. Tanga will likely revise the comment to match Junio’s guidance, but the core refactoring remains sound and ready for integration once the dependency on Christian Couder’s `cc/early-scan-options` series is resolved.
