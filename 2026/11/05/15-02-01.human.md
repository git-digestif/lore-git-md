This is a refactoring and test-infrastructure patch series from Patrick Steinhardt, part of the ongoing ODB (object database) abstraction effort. The goal is to improve how Git handles ref and object storage formats, specifically to prepare for alternative backends.

The series introduces a way to run the test suite with a non-default object storage format via `GIT_TEST_DEFAULT_OBJECT_STORAGE_FORMAT=`. Since no alternative backend exists yet, it also adds support for specifying a default format with a payload (e.g., `files://objdir`), which helps surface tests that hardcode assumptions about object storage paths (like `.git/objects`). Only about 3% of tests fail under this setup, suggesting the groundwork is solid. The fixes for those failing tests will come later, either by adapting them to use plumbing commands or tagging them with prerequisites.

Key changes include creating leading directories for ref and object storage, allowing payloads in default storage formats, and updating `git rev-parse` to print the payload for the ref storage format. The series also adds test infrastructure to support non-default object storage formats. It builds on Patrick’s earlier `ps/odb-object-storage-extension` work and is targeted at the `next` branch.

The patches look well-structured and address a real need for the ODB abstraction effort. The commit messages are clear, and the changes are incremental, making this a low-risk but important step toward pluggable backends. If you care about Git’s storage layer or future extensibility, this series is worth following.
