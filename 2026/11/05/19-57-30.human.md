This is an Outreachy proposal draft from Tanga Joris, an applicant for the December 2026 round. The project targets Git's command-line argument parsing: today, built-in commands handle early requests like `-h`, `--help-all`, and `--git-completion-helper` inconsistently, with some working outside a repository and others crashing or misbehaving. Tanga proposes to unify this behavior, add tests to guard it, and move the early option scanning toward the shared `parse-options` machinery.

Tanga has already contributed several patches to Git: a microproject converting plural messages to use `Q_()`, a four-iteration series removing `NO_PARSEOPT` from built-ins that use `parse-options` (which revealed and fixed a bash-completion edge case), and a one-patch simplification of `git annotate` that stopped it from rewriting its arguments before parsing. These patches are all on `master` or in flight, and the proposal builds directly on the lessons learned from them. The plan is concrete: first make the entry points behave consistently (weeks 1–4), then convert only those early scans that cause user-visible bugs (weeks 4–8), and finally explore a "dry-run" mode for `parse_options()` (weeks 8–13). Every change is tested first, and the timeline includes weekly blog posts and written updates to mentors.

The proposal is well-motivated, technically grounded in Tanga’s own contributions, and scoped realistically for a three-month internship. It addresses a real pain point (inconsistent early option handling) and aligns with the project’s long-term direction (moving ad-hoc parsers into `parse-options`). If accepted, this work would make Git’s command-line interface more predictable and maintainable.
