This is a **bugfix patch update** targeting the `bundle-uri` subsystem, now split into a three-patch series in response to Patrick Steinhardt’s review feedback. The goal remains the same: prevent `git bundle-uri` from crashing when encountering unresolvable relative URIs (e.g., `../../../../etc/passwd`) in bundle lists from untrusted servers. The v2 iteration addressed all substantive feedback, and this follow-up email confirms two final refinements.

The patch is now structured as three commits: (1) introducing `relative_url_gently()` (a non-dying variant of `relative_url()`), (2) adding credential redaction to its error messages via `transport_anonymize_url()`, and (3) using the new function in `bundle_list_update()` to skip malformed URIs gracefully. This split improves clarity and testability, though the core logic is unchanged. The commit message now explains backward compatibility more clearly, noting that `relative_url()` remains a dying wrapper for existing callers (e.g., submodules).

The test in `t0060-path-utils.sh` has been tightened to verify the full error message format, not just credential redaction. This addresses Patrick’s concern about test precision, though the earlier coverage gap for certain relative URIs (e.g., `../foo`) in `t5750` remains unaddressed. The patch is technically sound and ready for `next`, with no open technical objections. The remaining loose end—whether to restore the dropped test cases—is a minor detail rather than a blocker.
