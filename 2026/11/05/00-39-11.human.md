This is the first patch in Tanga Joris’s v4 series addressing a Bash completion regression for Git built-in commands. The patch centralizes handling of `--git-completion-helper` and `--git-completion-helper-all` in `parse-options.c`, ensuring these flags are processed before any command-specific initialization. This fixes a user-visible issue where `git fast-import --git-completion-helper` would block waiting for input and leave behind temporary pack files, and it restores expected completion behavior for `patch-id`, `diff-pairs`, and `var` as well.

The patch is a clean refactoring that extends `show_usage_with_options_if_asked()` to recognize the completion-helper flags, mirroring how it already handles `-h` and `--help-all`. This eliminates the need for per-command boilerplate and avoids side effects like temporary file creation. The commit message is clear and well-motivated, crediting prior feedback from René Scharfe, Junio Hamano, Kaartic Sivaraam, and Cynthia Uche. Changes since v3 include improved documentation (a comment in `parse-options.h`) and expanded test coverage for `--git-completion-helper-all`, addressing Cynthia Uche’s tested review.

The patch touches `parse-options.c`, `parse-options.h`, and adds two new tests in `t/t9300-fast-import.sh` to verify that neither completion-helper flag reads from stdin or creates temporary files. The tests are minimal but effective, checking for the absence of `tmp_pack_*` files and confirming the expected option lists are printed. While the patch does not explicitly test completion behavior for `patch-id`, `diff-pairs`, or `var`, the centralized approach ensures they benefit automatically.

This is a well-crafted fix for a real problem, with thorough test coverage and a maintainable design. It depends on Christian Couder’s `cc/early-scan-options` series but requires no changes to it. The only loose end is whether additional tests for the other three commands would be useful, but that’s not a blocker. The patch looks ready for `next` once its dependency is stable.
