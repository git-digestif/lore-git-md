This is a bugfix patch for the `git bundle-uri` command, now split into a three-patch series in response to review feedback. The core issue remains the same: Git crashes when a bundle list contains a relative URI with too many `../` components, because `relative_url()` calls `die()`. The fix introduces a non-dying variant, `relative_url_gently()`, to allow graceful error recovery when processing untrusted bundle lists.

The author has addressed Patrick Steinhardt’s two remaining suggestions from the v2 review. The commit message now clarifies that `relative_url()` remains a dying wrapper for backward compatibility, avoiding confusion about submodule callers. The new test in `t0060-path-utils.sh` now verifies the full error message format, not just credential redaction. The patch series is now structured as three logical commits: (1) the gentle variant, (2) credential redaction in its error messages, and (3) its use in `bundle-uri.c`.

The series looks ready for `next`. The design rationale (graceful handling of untrusted URIs) is sound, the test coverage is thorough, and the backward-compatibility story is clear. The only loose end from earlier discussion—the dropped test cases for certain relative URIs in `t5750`—remains unresolved, but this does not appear to be a blocker. The patch is well-motivated and well-executed.
