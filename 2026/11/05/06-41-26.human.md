This is a bug report about a regression in Git’s geometric maintenance strategy. The author, Christoph Weiss, reports that after upgrading Git from 2.52 to 2.54 (which changed the default maintenance strategy from `gc` to `geometric`), repositories started failing health checks. The issue appears to be that geometric maintenance prunes commits without updating the commit-graph, leaving it in an inconsistent state.

The report includes a minimal reproduction script that sets up a bare repository, creates a commit history with an obsolete branch, forces pruning by backdating objects, and then runs `git maintenance run --auto`. Before maintenance, `git fsck` passes, but afterward, it reports errors due to dangling commits—indicating that the commit-graph still references objects that have been pruned.

The problem is well-documented and reproducible, with clear steps and a focused test case. The regression is tied to a specific version upgrade and a deliberate change in default behavior (switching to geometric maintenance), which makes this a high-priority issue for anyone relying on commit-graphs or automated maintenance. The report does not yet include a proposed fix, but the reproduction script should make it straightforward for maintainers to investigate. If this affects your workflow, it’s worth following the thread for updates.
