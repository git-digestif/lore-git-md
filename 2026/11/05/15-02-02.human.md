This is the first patch in Patrick Steinhardt’s five-part series preparing Git’s test suite for ODB abstraction. It’s a small but necessary refactoring in the refs subsystem.

The patch makes both the files and reftable backends automatically create any missing leading directories when they initialize. Today, if you specify a custom refs directory via a payload (e.g., `files://refdir`), Git dies unless the directory already exists. After this change, Git will create it on the fly, which is friendlier for both users and the upcoming test infrastructure. The `noshare()` variant of `safe_create_leading_directories` is used to avoid accidentally changing permissions on directories outside the repository.

The change itself is tiny—one line added to each backend—but the test coverage is thorough: a new loop in `t1423-ref-backend.sh` verifies that both backends correctly create their expected directory structures when given a payload. The patch is clearly motivated, well-explained, and ready for review. It’s a straightforward improvement that removes a minor friction point before the larger ODB test-suite work lands.
