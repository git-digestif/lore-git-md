This is the third and final patch in Tanga Joris's v5 Outreachy series, adding a defensive test to catch future regressions where built-in commands are converted to use `parse-options` but retain the `NO_PARSEOPT` flag. The test runs `git <cmd> --git-completion-helper` for every built-in not listed in `git --list-cmds=parseopt` and checks that no long options (starting with `--`) are printed. Without the earlier patches in the series, this test would fail for `diff-pairs`, `fast-import`, and `patch-id`—the three commands with long options that were still marked `NO_PARSEOPT`.

The test skips five diff-related commands (`diff`, `diff-files`, `diff-index`, `diff-tree`, `rev-list`) because they print diff options, and `rev-parse` because it echoes arguments. It does not catch `var`, which only has short options (`-l`, etc.), so the test remains limited to long-option regressions. Kaartic Sivaraam originally suggested this test to prevent future oversights, and Tanga implemented it with clear skips and a straightforward grep check.

The patch is a small but useful safeguard for the completion system, complementing the earlier refactoring in `parse-options.c`. It is ready for review and depends on the same `cc/early-scan-options` series as the rest of the series. The test is lightweight and unlikely to be controversial, though its limitation to long options means it won't catch every possible `NO_PARSEOPT` regression.
