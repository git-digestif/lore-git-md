Christoph Weiss reported a regression in Git 2.54 where the new default `geometric` maintenance strategy corrupts the commit-graph by pruning unreachable commits without updating the graph, leaving `git fsck` reporting dangling commits and a broken commit-graph chain. The bug does not occur with the previous `gc` strategy default, and Weiss provided a self-contained reproduction script demonstrating the inconsistency after running `git maintenance run --auto`.

Patrick Steinhardt has acknowledged the report and outlined a concrete fix direction: moving commit-graph generation into `odb_optimize()` so the code can detect when objects were discarded during maintenance and conditionally rewrite the commit-graph only in those cases. This approach aligns with his ongoing ODB abstraction effort, which aims to make commit-graphs a pluggable implementation detail of the object database backend. Steinhardt notes the fix is currently blocked on that prerequisite series landing first to avoid merge conflicts, after which he intends to send a patch series addressing the corruption. Until that work lands, the issue remains open with no code changes yet proposed.
