This thread is a bug report from Christoph Weiss about a regression in Git 2.54’s new default `geometric` maintenance strategy. When `git maintenance run --auto` is invoked, the geometric strategy prunes unreachable commits but fails to update the commit-graph, leaving it inconsistent. The provided reproduction script shows that after maintenance, `git fsck` reports dangling commits and a corrupted commit-graph chain, whereas the old `gc` strategy does not exhibit this behavior.

The issue affects the commit-graph, refs, and object storage subsystems, specifically involving the `maintenance.strategy=geometric` configuration, `gc.writeCommitGraph`, and the `--split` commit-graph chain. Since the geometric strategy became the default in Git 2.54, this bug could impact any user upgrading to this version, potentially causing performance degradation or correctness issues in operations that rely on the commit-graph, such as `git log --graph` or reachability checks.

No prior discussion or patches are referenced, so this appears to be the first report of the problem. The reproduction is self-contained and does not require external tools beyond a POSIX shell and Git 2.54. As of now, there are no responses or proposed fixes, so the thread is still open and awaiting review or action from maintainers or contributors familiar with the maintenance subsystem.
