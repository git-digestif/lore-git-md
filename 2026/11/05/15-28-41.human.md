This is the second patch in Aniket Gupta’s three-part bugfix series for the bundle-uri subsystem. It plugs a minor but real information leak: when `relative_url()` fails to resolve a relative URI, the error message currently prints the full URL, including any embedded credentials (user:password). The patch anonymizes the URL before it reaches the error message, so only the hostname and path are shown. It also improves the message by naming the original URL rather than a partially stripped version, making it easier for users to recognize what went wrong.

The change is confined to `remote.c` and adds a single test in `t0060-path-utils.sh` that verifies the anonymization works. The patch is a clean follow-up to the first one, which introduced the non-dying `relative_url_gently()` helper; this one simply ensures that helper doesn’t leak sensitive data. The commit message is clear and the test is well-scoped. No controversy or open questions are evident; this looks like a straightforward, well-motivated fix that should be uncontroversial.
