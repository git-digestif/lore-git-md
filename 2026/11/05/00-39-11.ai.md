This is the first patch in Tanga Joris's v4 series, continuing the effort to fix a user-visible Bash completion regression for four built-in commands (`patch-id`, `diff-pairs`, `fast-import`, `var`). The patch centralizes `--git-completion-helper` and `--git-completion-helper-all` handling in `parse-options.c`, ensuring these flags are processed before any command-specific initialization. This prevents side effects like temporary file creation or blocking on input, which were particularly problematic for `fast-import`.

The patch adds a six-line block to `show_usage_with_options_if_asked()` in `parse-options.c` to handle the completion-helper flags generically, along with a clarifying comment in `parse-options.h` and two new tests in `t/t9300-fast-import.sh`. The tests verify that `git fast-import --git-completion-helper` and `--git-completion-helper-all` no longer create temporary pack files or read from stdin, addressing the edge case René Scharfe identified in earlier iterations. The commit message now explicitly notes that the next patch removes `NO_PARSEOPT` from `fast-import`, improving clarity.
