This is a review of a feature patch adding `--show-object-format` to `git ls-remote`. The patch itself is a clean, well-motivated addition that addresses a real interoperability gap for tools like Jujutsu, which need to know a remote repository's hash algorithm upfront to avoid silent mismatches—especially with empty repositories. The implementation is minimal, reusing existing transport APIs, and the test coverage is thorough.

Patrick Steinhardt's review is **substantive**, engaging with both the design and the implementation details. He raises two main points: first, suggesting the output format include a prefix (e.g., `object-format: sha1`) to make it more extensible and parser-friendly; second, questioning whether the hash algorithm is guaranteed to be populated in all cases, though he acknowledges the existing code likely handles this. He also offers **surface-level** nitpicks on wording consistency in the documentation and test structure, proposing minor improvements like deduplicating test cases.

The review is constructive and technical, but the core of the patch remains sound. The suggested changes are reasonable but not blocking—this is a small, self-contained feature that already works as intended. If the author incorporates the feedback, the patch will be even more robust, but even in its current form, it’s a clear win for interoperability. Worth tracking for anyone working with Git’s protocol or multi-hash setups.
