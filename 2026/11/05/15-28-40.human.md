This is the first patch in a three-part bugfix series targeting the bundle-uri subsystem. It introduces `relative_url_gently()`, a non-fatal variant of the existing `relative_url()` helper. The new function returns `NULL` and populates a `strbuf` with an error message instead of calling `die()` when it encounters an unresolvable relative URI (e.g., too many `../` components). The original `relative_url()` is now a thin wrapper that calls the gentle variant and dies if it fails, preserving backward compatibility for existing callers.

The change is clean and focused: the core logic is lifted from `relative_url()` with minimal modification, and the new function is exposed in `remote.h`. The commit message clearly explains the motivation—callers that want to handle errors gracefully rather than aborting—and the patch itself is well-structured, with the gentle variant handling the error case explicitly. The helper is immediately useful for the next patch in the series, which will use it to skip unresolvable URIs in bundle lists rather than failing the entire operation.

This patch looks solid and ready for review. It touches only `remote.c` and `remote.h`, with no cross-subsystem impact, and the test coverage for the new helper will be added in the third patch. The series as a whole is fixing a regression in the bundle-uri feature introduced in Git 2.41, so this is a targeted fix for a real problem in relatively new code.
