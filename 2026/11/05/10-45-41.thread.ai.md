Thread identity: Patch series introducing `--show-object-format` option to `git ls-remote` to query a remote repository's hash algorithm (SHA-1/SHA-256) without cloning. Originating author: Adrian Ratiu. Thread type: patch series (single patch).

Core problem or goal: Enable Git-based tools (notably Jujutsu) to detect a remote repository's object format upfront, preventing silent mismatches—especially critical with empty repositories where the format cannot be inferred from existing objects. The change addresses a concrete interoperability gap (JJ issue #3813) by exposing the hash algorithm via an existing transport API.

Current status: Under review. Version: initial submission (v1), with v2 planned to address feedback. No merge status change; remains in review.

Key technical details:
- New CLI option: `git ls-remote --show-object-format`
- Output: single line prefixed with `object-format:` (e.g., `object-format: sha1` or `object-format: sha256`) for future extensibility, as agreed with Patrick Steinhardt
- Implementation: reuses `transport_get_hash_algo()`; null-check on the returned pointer remains unresolved (Patrick flags it as a broader robustness concern, but Adrian notes it is unnecessary in this context)
- Files touched: `builtin/ls-remote.c`, `Documentation/git-ls-remote.txt`, `t/t5512-ls-remote.sh`
- Test coverage: SHA-1/SHA-256 repos (empty and non-empty), protocol v0/v2, nongit environment; test helper (`test_show_object_format`) will be parameterized to accept the expected format, reducing boilerplate
- On-disk format: unchanged; no new symbols or config keys

Open questions and loose ends:

- Test helper parameterization and deduplication of SHA-1/SHA-256 test cases (agreed to be addressed in v2).
