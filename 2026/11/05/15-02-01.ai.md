This is a cover letter for a five-patch series from Patrick Steinhardt targeting the object and ref storage subsystems. The series is part of the ongoing ODB abstraction effort, preparing the test suite to run with non-default storage backends.

The main goal is to allow tests to specify a different object storage format via the `GIT_TEST_DEFAULT_OBJECT_STORAGE_FORMAT` environment variable. Because no alternative backend exists yet, the series also introduces the ability to attach a payload (e.g., `files://objdir`) to the default format string, which surfaces tests that hard-code assumptions about `.git/objects`. Only ~1100 out of 35,000 tests currently fail under this regime; fixing those failures is explicitly deferred to follow-up work.

Key technical details: the series touches `refs/files-backend.c` and `refs/reftable-backend.c` to create leading directories, `odb/source-files.c` for the same purpose, `setup.c` to parse payloads in default format strings, and `builtin/rev-parse.c` to print the payload. The test scripts `t0001-init.sh`, `t1423-ref-backend.sh`, and `t1500-rev-parse.sh` are extended to exercise the new functionality, while `t/test-lib.sh` gains the environment-variable plumbing.

The series is based on `df904e7114c` (the 15th batch, 2026-11-04) with Patrick’s `ps/odb-object-storage-extension` branch merged in. No merge status is claimed; the patches are under review.
