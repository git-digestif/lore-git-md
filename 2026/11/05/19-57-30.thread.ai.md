Core problem or goal
Improve consistency and robustness in how Git built-in commands scan and parse command-line arguments and options, particularly for early requests like `-h`, `--help-all`, and `--git-completion-helper`. The current implementation exhibits inconsistencies across commands (e.g., some commands fail when `--git-completion-helper` is used outside a repository, while others do not) and requires manual handling of option parsing order in certain cases (e.g., `merge-index`). The goal is to unify behavior, eliminate edge-case failures, and lay groundwork for a more maintainable `parse_options()` API.

Current status
Proposal stage (not yet implemented). Tanga has contributed foundational patches to Git, including:
- A microproject (merged to `master`).
- A four-iteration series removing `NO_PARSEOPT` from built-ins (status unknown; not explicitly stated as merged).
- A fix for `git annotate` to prevent segfaults when `--git-completion-helper` is used outside a repository (merged to `master`).
The proposal builds on Christian Couder’s prior `early-scan-options` series and aligns with Junio’s long-term direction for `parse-options`.

Key technical details
- **Subsystems/files touched**: `parse-options.c`/`parse-options.h` (core API), built-in command entry points (e.g., `builtin/annotate.c`, `builtin/merge-index.c`), and test files (e.g., `t/t0040-parse-options.sh`).
- **New/renamed symbols**: Proposal does not yet introduce new symbols, but may involve refactoring `parse_options()` or adding a "dry run" mode for early scanning.
- **Behavior changes**: Targets include:
  - Ensuring `--git-completion-helper` works outside a repository for all commands.
  - Eliminating manual option-parsing order dependencies (e.g., in `merge-index`).
  - Unifying early option handling (e.g., `-h`, `--help-all`) across commands.
- **On-disk format**: No changes anticipated.
- **Test coverage**: Proposal emphasizes adding failing tests on `master` for each change to ensure regression safety.
