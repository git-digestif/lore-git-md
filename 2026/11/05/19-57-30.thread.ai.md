Core problem or goal
Improve consistency and robustness in how Git built-in commands scan and parse command-line arguments and options, particularly for early requests like `-h`, `--help-all`, and `--git-completion-helper`. The proposal targets three concrete, user-visible issues: (1) `git stash show` misinterpreting `-G`/`-S` values as stash references, (2) silent failure of numeric parsing in `git index-pack` and `git fetch-pack` on malformed inputs (e.g., "abc"), and (3) `--no-index` detection in `git diff` failing when preceded by short options like `-G`. The proposal now also includes `git daemon` as a conversion target, removing dependency on Christian Couder’s `early-scan-options` series. The goal is to unify behavior, eliminate edge-case failures, and lay groundwork for a more maintainable `parse_options()` API, with a focus on test-driven, incremental refactoring.

Current status
Proposal stage (not yet implemented), now in its third draft. Tanga has contributed foundational patches to Git, including:
- A microproject (merged to `master`).
- A four-iteration series removing `NO_PARSEOPT` from built-ins (status: under review; not explicitly stated as merged).
- A fix for `git annotate` to prevent segfaults when `--git-completion-helper` is used outside a repository (merged to `master`).
Tanga has experimented with applying `early_scan_options()` to `git diff`, documenting that while the approach shows promise, it currently breaks several existing cases (e.g., `git diff -p --no-index a b`), highlighting the need for additional work to handle short options. The plan is structured as three prioritized tasks with fallback options, and the timeline includes weekly updates and list-first design discussions.

Key technical details
- **Subsystems/files touched**: `parse-options.c`/`parse-options.h` (core API), built-in command entry points (e.g., `builtin/stash.c`, `builtin/index-pack.c`, `builtin/diff.c`, `builtin/fetch-pack.c`, `builtin/daemon.c`), and test files (e.g., `t/t0040-parse-options.sh`, `t/t3903-stash.sh`, `t/t5000-tar-tree.sh`).
- **New/renamed symbols**: Proposal may involve adapting or extending Christian Couder’s `early_scan_options()` framework, though the exact symbols are not yet finalized.
- **Behavior changes**:
  - `git stash show`: Ensure `-G`/`-S` options are parsed as revision arguments, not stash references.
  - `git index-pack`/`git fetch-pack`: Reject malformed numeric inputs (e.g., "abc") with clear error messages instead of silent failure.
  - `git diff`: Correct `--no-index` detection when preceded by short options (e.g., `git diff -G pattern --no-index`).
  - `git daemon`: Convert to use `parse_options()` for consistent argument handling.
- **On-disk format**: No changes anticipated.
- **Test coverage**: Proposal emphasizes adding failing tests on `master` for each change to ensure regression safety. Specific test files mentioned include `t/t3903-stash.sh` (for `stash show`), `t/t5000-tar-tree.sh` (for `index-pack`), and existing `parse-options` tests.

Open questions and loose ends
1. **Design direction for `git diff`**: Whether to adapt the `early_scan_options()` framework (which currently breaks existing cases like `git diff -p --no-index a b`) or pursue a smaller, targeted fix. This remains a key discussion point for mentor input.
2. **Scope boundaries**: Whether to expand the scope to other commands (e.g., revision options) after addressing the core tasks. The proposal prioritizes plumbing fixes first but leaves room for follow-up work.
3. **Backwards compatibility**: Ensuring changes do not break existing scripts or completion tools relying on current behavior, particularly for `git stash show` and numeric parsing in `index-pack`/`fetch-pack`.
4. **Implementation order**: The proposal suggests starting with `git stash show` and `index-pack`/`fetch-pack` fixes before tackling `git diff` and `git daemon`, but the order may shift based on feedback.
5. **Prior art integration**: While the proposal no longer depends on Christian Couder’s `early-scan-options` series, the status of that work remains unknown, and its potential reuse or adaptation is still under consideration.
