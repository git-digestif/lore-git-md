Core problem or goal
Improve consistency and robustness in how Git built-in commands scan and parse command-line arguments and options, particularly for early requests like `-h`, `--help-all`, and `--git-completion-helper`. The proposal now targets three concrete, user-visible issues: (1) `git stash show` misinterpreting `-G`/`-S` values as stash references, (2) silent failure of numeric parsing in `git index-pack` and `git fetch-pack` on malformed inputs (e.g., "abc"), and (3) `--no-index` detection in `git diff` failing when preceded by short options like `-G`. The goal remains to unify behavior, eliminate edge-case failures, and lay groundwork for a more maintainable `parse_options()` API, with a focus on test-driven, incremental refactoring.

Current status
Proposal stage (not yet implemented). Tanga has contributed foundational patches to Git, including:
- A microproject (merged to `master`).
- A four-iteration series removing `NO_PARSEOPT` from built-ins (status: under review; not explicitly stated as merged).
- A fix for `git annotate` to prevent segfaults when `--git-completion-helper` is used outside a repository (merged to `master`).
The revised proposal builds on Christian Couder’s prior `early-scan-options` series and aligns with Junio’s long-term direction for `parse-options`. The plan is structured as three prioritized tasks with fallback options, and the timeline includes weekly updates and list-first design discussions.

Key technical details
- **Subsystems/files touched**: `parse-options.c`/`parse-options.h` (core API), built-in command entry points (e.g., `builtin/stash.c`, `builtin/index-pack.c`, `builtin/diff.c`, `builtin/fetch-pack.c`), and test files (e.g., `t/t0040-parse-options.sh`, `t/t3903-stash.sh`, `t/t5000-tar-tree.sh`).
- **New/renamed symbols**: Proposal does not yet introduce new symbols, but may involve refactoring `parse_options()` or adapting Christian Couder’s `early-scan-options` framework (e.g., `parse_options_early()` or similar).
- **Behavior changes**:
  - `git stash show`: Ensure `-G`/`-S` options are parsed as revision arguments, not stash references.
  - `git index-pack`/`git fetch-pack`: Reject malformed numeric inputs (e.g., "abc") with clear error messages instead of silent failure.
  - `git diff`: Correct `--no-index` detection when preceded by short options (e.g., `git diff -G pattern --no-index`).
- **On-disk format**: No changes anticipated.
- **Test coverage**: Proposal emphasizes adding failing tests on `master` for each change to ensure regression safety. Specific test files mentioned include `t/t3903-stash.sh` (for `stash show`), `t/t5000-tar-tree.sh` (for `index-pack`), and existing `parse-options` tests.

Open questions and loose ends
1. **Design direction for `git diff`**: Whether to fix the existing option-parsing loop or adapt Christian Couder’s `early-scan-options` framework. This is flagged for mentor input, reflecting awareness of broader design tradeoffs.
2. **Prior art integration**: Status of Christian Couder’s `early-scan-options` series remains unknown (not merged). The proposal acknowledges this as a potential dependency or alternative approach.
3. **Scope boundaries**: Whether to expand the scope to other commands (e.g., `git daemon` port parsing, revision options) after addressing the core three tasks. The proposal prioritizes plumbing fixes first but leaves room for follow-up work.
4. **Backwards compatibility**: Ensuring changes do not break existing scripts or completion tools relying on current behavior, particularly for `git stash show` and numeric parsing in `index-pack`/`fetch-pack`.
5. **Implementation order**: The proposal suggests starting with `git stash show` and `index-pack`/`fetch-pack` fixes before tackling `git diff`, but the order may shift based on feedback.
