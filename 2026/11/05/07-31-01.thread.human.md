This thread is about a small but long-standing bug in Git's command-line completion for `git annotate`. Tanga Joris identified that `git annotate --<TAB>` was incorrectly offering options from `git diff` instead of `git annotate`'s own options. The root cause was a redundant `-c` flag being prepended to the argument list before calling `cmd_blame()`, which confused the completion helper. The fix is straightforward: remove the redundant `-c` prepend (since `cmd_blame()` already handles the distinction between `annotate` and `blame` internally) and pass the original arguments unchanged.

The patch is minimal—just 22 lines removed and 10 added—and touches only `builtin/annotate.c` and its test file. It’s well-tested: the author verified 45 argument combinations and added regression tests in `t8003-blame-corner-cases.sh` to ensure the completion helper works correctly. The commit message is thorough, explaining the problem, tracing the redundant code back to a 2008 commit, and noting that recent refactoring (1dd7c32daa, 2024-11-20) made the old workaround obsolete. There’s no discussion yet, but the patch depends on `tj/drop-no-parseopt` (not yet in `next`) for a planned follow-up. So far, this looks like a clean, uncontroversial fix.
