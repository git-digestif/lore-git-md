This thread is about a small but long-standing bug in Git’s command-line completion: when you type `git annotate --<TAB>`, the shell offers options from `git diff` instead of `git annotate`. Tanga Joris identified the root cause—a redundant `-c` argument being prepended in `builtin/annotate.c`—and sent a minimal patch (22 lines removed, 10 added) that removes the redundancy. The fix is accompanied by regression tests in `t/t8003-blame-corner-cases.sh` that verify the completion helper now lists the correct options.

Junio C Hamano reviewed the patch and gave it a clear thumbs-up, calling the change “a great goal” and confirming it aligns with how `git annotate` and `git blame` are documented to share options. The patch is now effectively ready to merge; the only loose end is its dependency on `tj/drop-no-parseopt`, which is not yet in `next` but does not block this fix. No objections or open questions remain.
