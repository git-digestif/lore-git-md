This is a **bugfix and performance patch** that addresses a long-standing inefficiency in Git’s object quarantine mechanism. During a push, Git’s connectivity check (`rev-list --alternate-refs`) unnecessarily loads *all* refs—including hidden ones—from the repository’s own object directory when it is passed as an alternate inside the quarantine environment. This creates a measurable performance regression, particularly in repositories with many hidden refs (e.g., 200,000), where the patch delivers a **65.5% speedup** for small pushes. Even without hidden refs, every ref is still listed twice, causing a **16.7% slowdown**.

The fix itself is **minimal and targeted**: it skips an alternate whose path matches the repository’s own `commondir` when listing alternate refs. This approach aligns with Git’s existing behavior of ignoring the object directory itself when loading alternates, and it avoids quarantine-specific logic entirely. The patch is **well-tested**, with a new perf test (`p5552-push-hidden-refs.sh`) demonstrating the performance impact and functional tests verifying that:
- The repository’s own refs are *not* listed as alternate refs during quarantine.
- Refs from *real* alternates (other repositories) are still listed correctly.
- The behavior holds for `rev-list` run from a pre-receive hook or with the object directory passed as an alternate manually.

The commit message is **clear and thorough**, explaining the problem, the fix, and the performance impact with concrete numbers. The patch also updates the documentation for `--alternate-refs` to clarify that the repository’s own object directory does not count as an alternate, even when passed as one (e.g., during quarantine).
