Thread identity: patch series titled "bundle-uri: skip unresolvable relative URIs instead of dying", v3, authored by Aniket Gupta. Thread type: bugfix series targeting a regression in the bundle-uri subsystem (introduced in Git 2.41).

Core problem or goal: fix a regression where `git clone` or `git fetch` dies when encountering a bundle list containing an unresolvable relative URI (e.g., too many `../` components). The goal is to refactor URI-handling code to skip problematic bundles with an error message (now including anonymized URLs for security) instead of failing the entire operation. A secondary goal is to prevent credential disclosure in error messages when URI resolution fails.

Current status: v3 posted, addressing feedback from v2 (patch split, commit message rewording, test tightening). Under review; no maintainer decisions or merge status reported. The series remains technically complete but carries two open policy questions: (1) whether skipping unresolvable URIs is the correct policy (raised in patch 3), and (2) whether error messages should anonymize URLs (raised in patch 2). Awaiting substantive review on patches 2 and 3, with patch 1 conditionally approved pending resolution of the broader policy concerns.

Key technical details:
- Files touched: `remote.c`, `remote.h`, `bundle-uri.c`, `t/t0060-path-utils.sh`, `t5750-bundle-uri-parse.sh`.
- New symbols: `relative_url_gently()` helper function (non-dying variant of `relative_url()`), which returns NULL and populates a `strbuf` error message on failure. The original `relative_url()` is now a thin wrapper that calls `relative_url_gently()` and dies if it fails.
- Internal changes: `chop_last_dir()` helper modified to signal failure (return -1) without dying, enabling graceful error propagation. `transport_anonymize_url()` is now used to sanitize error messages when `relative_url_gently()` fails, preventing credential disclosure. `bundle_list_update()` now logs errors and skips unresolvable URIs instead of dying.
- Behavior change: unresolvable relative URIs in bundle lists are now skipped with an error message that includes the anonymized problematic URL (full input URL shown for diagnosability), rather than causing the operation to die.
- Error message improvement: now includes the anonymized URL and the full input URL for clarity. Patch 2 specifically addresses credential anonymization in error messages, calling `transport_anonymize_url()` on the original URL before including it in the error output.
- Test coverage: expanded unit test in `t0060-path-utils.sh` (added tests for credential anonymization in error messages and URI resolution edge cases) and updated bundle-uri tests in `t5750` (now verifies non-fatal error reporting and continued parsing of the bundle list).
- On-disk format: no changes.
- Subsystem: bundle-uri (introduced in Git 2.41).

Open questions and loose ends:
- **Policy question (patch 3)**: Derrick Stolee has flagged the behavioral choice to skip unresolvable URIs (rather than halting) as a design decision that warrants further discussion. He deferred judgment until reviewing patch 3 but expressed a preference to revisit this policy. The question remains unresolved and is a blocker for approval.
- **Policy question (patch 2)**: Derrick Stolee has questioned the necessity of anonymizing URLs in error messages, arguing that the user already knows the problematic URL and that log sanitization should be handled by the environment. He acknowledges the implementation is correct but leaves the policy decision open.
