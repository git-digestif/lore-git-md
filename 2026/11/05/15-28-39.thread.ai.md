Thread identity: patch series titled "bundle-uri: skip unresolvable relative URIs instead of dying", v3 (likely to become v4), authored by Aniket Gupta. Thread type: bugfix series targeting a regression in the bundle-uri subsystem (introduced in Git 2.41).

Core problem or goal: fix a regression where `git clone` or `git fetch` dies when encountering a bundle list containing an unresolvable relative URI (e.g., too many `../` components). The goal is to refactor URI-handling code to skip problematic bundles with an error message (now including anonymized URLs for security) instead of failing the entire operation. A secondary goal is to prevent credential disclosure in error messages when URI resolution fails, though this aspect remains under active policy debate, with reviewers questioning its necessity and highlighting diagnosability trade-offs.

Current status: v3 posted, addressing all prior feedback. The core regression fix (skipping unresolvable URIs) is uncontested and technically complete. **Patch 2/3 (credential anonymization and URL-trimming in error messages) is now the sole point of contention** following critiques from Junio C Hamano and Patrick Steinhardt. Junio challenges the necessity of credential anonymization in error messages, arguing that the bundle-uri feature is inherently unsafe if the bundle list contains credentialed URIs and that existing uses of `transport_anonymize_url()` are limited to user-facing output, not error messages. Patrick Steinhardt highlights that the URL-trimming logic in patch 2 actively harms diagnosability by obscuring the original input URL. Aniket Gupta has clarified that he will retain the portion of patch 2 that preserves the original URL in error messages (addressing Patrick’s concern) while keeping the credential anonymization logic. This signals a likely v4 revision to split or refine patch 2, separating the harmful URL-trimming logic from the anonymization feature. The series awaits Aniket’s v4; merge status remains under review, not yet queued in `seen`.

Key technical details:
- Files touched: `remote.c`, `remote.h`, `bundle-uri.c`, `t/t0060-path-utils.sh`, `t5750-bundle-uri-parse.sh`.
- New symbols: `relative_url_gently()` helper function (non-dying variant of `relative_url()`), which returns NULL and populates a `strbuf` error message on failure. The original `relative_url()` is now a thin wrapper that calls `relative_url_gently()` and dies if it fails.
- Internal changes: `chop_last_dir()` helper modified to signal failure (return -1) without dying, enabling graceful error propagation. `transport_anonymize_url()` is used to sanitize error messages when `relative_url_gently()` fails, preventing credential disclosure. `bundle_list_update()` now logs errors and skips unresolvable URIs instead of dying.
- Behavior change: unresolvable relative URIs in bundle lists are now skipped with an error message that includes the anonymized problematic URL (original input URL preserved for diagnosability in the revised implementation), rather than causing the operation to die. The implementation stops parsing the bundle list at the bad entry (for lists provided via `--bundle-uri`) and falls back to fetching from the remote.
- Error message improvement: patch 2/3 adds credential anonymization to the new error message. The URL-trimming logic (which obscured the original input URL) will be removed in v4 to address diagnosability concerns. The anonymization is limited to the new error message; other parts of Git (e.g., "failed to download bundle from URI" warnings) still print raw URLs containing credentials.
- Test coverage: expanded unit test in `t0060-path-utils.sh` (added tests for credential anonymization in error messages and URI resolution edge cases) and updated bundle-uri tests in `t5750` (now verifies non-fatal error reporting and continued parsing of the bundle list).
- On-disk format: no changes.
- Subsystem: bundle-uri (introduced in Git 2.41).

Open questions and loose ends:
- **Policy debate on credential anonymization in error messages**: Junio C Hamano questions whether it is necessary, given that (1) the bundle-uri feature is unsafe if the bundle list contains credentialed URIs, and (2) existing uses of `transport_anonymize_url()` are limited to user-facing output, not error messages. Aniket Gupta and Patrick Steinhardt agree that the original URL must be preserved for diagnosability, but the anonymization itself remains contested. A v4 revision may retain anonymization while removing the URL-trimming logic, but Junio’s concerns may persist.
- The commit message in patch 3 inaccurately describes the bundle list processing behavior (claiming it continues processing after an unresolvable URI, when it actually stops). This is a minor documentation issue that could be fixed in v4.
- A potential follow-up enhancement is noted: adding a configuration toggle to let users opt back into the old behavior (dying on unresolvable URIs) for use cases where strict validation is preferred. This is framed as a `#leftoverbits` item (low-priority, non-blocking).
