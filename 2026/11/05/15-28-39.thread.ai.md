Thread identity: patch series titled "bundle-uri: skip unresolvable relative URIs instead of dying", v3, authored by Aniket Gupta. Thread type: bugfix series targeting a regression in the bundle-uri subsystem (introduced in Git 2.41).

Core problem or goal: fix a regression where `git clone` or `git fetch` dies when encountering a bundle list containing an unresolvable relative URI (e.g., too many `../` components). The goal is to refactor URI-handling code to skip problematic bundles with an error message (now including anonymized URLs for security) instead of failing the entire operation. A secondary goal is to prevent credential disclosure in error messages when URI resolution fails.

Current status: v3 posted, addressing all feedback from prior iterations. The series is **technically complete and ready for maintainer consideration** after Derrick Stolee's substantive review of all patches. All open policy questions have been resolved: (1) skipping unresolvable URIs is confirmed as the correct policy (aligning with the original intent of the bundle-uri feature, as evidenced by a TODO comment from Stolee), and (2) error message anonymization (introduced in patch 2) is accepted as implemented but now explicitly optional. The commit message inaccuracy in patch 3 (regarding bundle list processing behavior) is noted as a minor documentation issue that could be fixed in a v4 if reviewers agree. No code changes are required; the series awaits maintainer pickup (merge status: under review, not yet queued in `seen`).

Key technical details:
- Files touched: `remote.c`, `remote.h`, `bundle-uri.c`, `t/t0060-path-utils.sh`, `t5750-bundle-uri-parse.sh`.
- New symbols: `relative_url_gently()` helper function (non-dying variant of `relative_url()`), which returns NULL and populates a `strbuf` error message on failure. The original `relative_url()` is now a thin wrapper that calls `relative_url_gently()` and dies if it fails.
- Internal changes: `chop_last_dir()` helper modified to signal failure (return -1) without dying, enabling graceful error propagation. `transport_anonymize_url()` is used to sanitize error messages when `relative_url_gently()` fails, preventing credential disclosure. `bundle_list_update()` now logs errors and skips unresolvable URIs instead of dying.
- Behavior change: unresolvable relative URIs in bundle lists are now skipped with an error message that includes the anonymized problematic URL (full input URL shown for diagnosability), rather than causing the operation to die. The implementation stops parsing the bundle list at the bad entry (for lists provided via `--bundle-uri`) and falls back to fetching from the remote, contrary to the initial commit message claim that it continues processing.
- Error message improvement: now includes the anonymized URL and the full input URL for clarity. Patch 2 specifically addresses credential anonymization in error messages, calling `transport_anonymize_url()` on the original URL before including it in the error output. This anonymization is limited to the new error message added by this series; other parts of Git (e.g., "failed to download bundle from URI" warnings) still print raw URLs containing credentials.
- Test coverage: expanded unit test in `t0060-path-utils.sh` (added tests for credential anonymization in error messages and URI resolution edge cases) and updated bundle-uri tests in `t5750` (now verifies non-fatal error reporting and continued parsing of the bundle list).
- On-disk format: no changes.
- Subsystem: bundle-uri (introduced in Git 2.41).

Open questions and loose ends:
- The credential anonymization in patch 2 is now explicitly optional and could be dropped if reviewers deem it unnecessary. No action is required unless reviewers request its removal.
- The commit message in patch 3 inaccurately describes the bundle list processing behavior (claiming it continues processing after an unresolvable URI, when it actually stops). This is a minor documentation issue that could be fixed in a v4 if reviewers agree.
- A potential follow-up enhancement is noted: adding a configuration toggle to let users opt back into the old behavior (dying on unresolvable URIs) for use cases where strict validation is preferred over graceful continuation. This is framed as a `#leftoverbits` item (low-priority, non-blocking) and explicitly stated to not delay the current series.
