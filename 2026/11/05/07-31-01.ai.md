This is a bugfix patch targeting command-line completion for `git annotate`. The issue: `git annotate --<TAB>` currently offers `git diff` options instead of `git annotate`'s own, because `cmd_annotate()` prepends `"-c"` to the argument list before calling `cmd_blame()`, which confuses the completion helper. The fix removes the redundant `-c` prepending (since `cmd_blame()` already handles `annotate` vs `blame` internally) and passes the original arguments unchanged.

The patch is well-motivated: the commit message explains the problem clearly, traces the redundant code back to a 2008 commit, and notes that recent refactoring (1dd7c32daa, 2024-11-20) made the argument-copying workaround obsolete. The author tested 45 argument combinations to verify output consistency, and added regression tests in `t8003-blame-corner-cases.sh` to ensure completion helpers work correctly. The change is minimal (22 lines removed, 10 added) and touches only `builtin/annotate.c` and its test file.
