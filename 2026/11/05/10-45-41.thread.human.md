This thread is about a small but practical addition to `git ls-remote`: a `--show-object-format` option that lets tools like Jujutsu detect whether a remote repository uses SHA-1 or SHA-256 without cloning it. The feature is particularly useful for empty repositories, where the hash algorithm can't be inferred from existing objects. Adrian Ratiu sent the initial patch, and after incorporating feedback from Patrick Steinhardt, has now posted a v2 that addresses all review points.

The implementation is straightforward, reusing existing transport code to expose the hash algorithm in a single line prefixed with `object-format:` (e.g., `object-format: sha256`). The only technical disagreement—a null-check on the transport function—has been deferred as a broader robustness concern, with Adrian arguing it isn't needed here. Tests cover both hash algorithms, empty and non-empty repos, and both protocol versions, and the documentation now includes a clear example of why the feature matters. Patrick's feedback was thorough but constructive, and all his suggestions have been adopted.

The patch is uncontroversial and fills a real interoperability gap (tracked in Jujutsu as issue #3813). With no fundamental objections and all review points addressed, it seems likely to move toward Junio's `next` branch soon. The v2 changes are mostly ergonomic—output format tweaks, test helper improvements, and documentation clarifications—so unless new concerns arise, this should be ready to graduate.
