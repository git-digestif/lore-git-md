This thread is about a small but useful addition to `git ls-remote`: a `--show-object-format` option that lets tools like Jujutsu detect a remote repository’s hash algorithm (SHA-1 or SHA-256) without cloning. The feature addresses a real interoperability gap, especially for empty repositories where the format can’t be inferred from existing objects.

The patch, authored by Adrian Ratiu, is now in its second version (v2). It incorporates all feedback from the initial review, including changes to the output format (now prefixed with `object-format:` for future extensibility), improved test ergonomics, and minor documentation tweaks. Junio C Hamano’s review of v2 confirmed the safety of the underlying transport API call and signaled readiness for queueing, while Patrick Steinhardt’s latest email explicitly states he’s “happy with this version.” With both reviewers now satisfied, the patch is effectively approved and waiting for Junio to pick it up for integration.

The implementation is straightforward: it reuses existing transport logic, touches only `ls-remote.c` and its documentation, and includes thorough test coverage for SHA-1/SHA-256 repositories, protocol versions, and edge cases. There are no open questions or loose ends, and the series has no dependencies on other in-flight work. Unless new objections surface, this should land in `next` soon.
