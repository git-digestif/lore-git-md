This thread is about a patch series introducing a `--show-object-format` option to `git ls-remote`, allowing tools like Jujutsu to detect a remote repository's hash algorithm (SHA-1 or SHA-256) without cloning. The feature addresses a specific interoperability gap (JJ issue #3813), particularly for empty repositories where the format cannot be inferred from existing objects.

The patch, now in its second version (v2), has incorporated all feedback from the initial review. Key changes include adopting a future-proof output format (`object-format: <name>`), improving test ergonomics, and addressing minor documentation and typo fixes. The only unresolved discussion from v1—whether to add a null-check for `transport_get_hash_algo()`—has been rendered moot by Junio C Hamano's review, which confirms the call is always safe in this context. Junio's feedback is entirely positive, and he considers the patch ready to proceed.

The implementation is minimal, reusing existing transport infrastructure without touching on-disk formats or introducing new symbols. Test coverage is thorough, handling empty and non-empty repositories, both protocol versions (v0 and v2), and nongit environments. With Junio's explicit approval, the patch is likely to be queued for `next` soon, barring any last-minute objections. The series is authored by Adrian Ratiu, with Patrick Steinhardt providing the initial review.
