This thread introduces a small but useful feature: a `--show-object-format` option for `git ls-remote`, letting users check whether a remote repository uses SHA-1 or SHA-256 before cloning. Adrian Ratiu proposed it to solve a specific interoperability problem with Jujutsu (JJ), which relies on Git's networking layer and can silently fail when the object format doesn't match—particularly with empty repositories. The patch is minimal, reusing existing transport code, and comes with thorough tests covering SHA-1/SHA-256, empty/non-empty repos, and both protocol versions. The documentation update includes a clear example of why this matters.

So far, the patch appears uncontroversial. It addresses a real gap without adding complexity, and the use case (JJ issue #3813) gives it concrete motivation. No reviews or objections have surfaced yet, but given the scope—this is a straightforward addition with no behavioral changes to existing commands—it’s likely to be merged once it gets a look from a maintainer or a domain expert in the transport layer. If you’re tracking Git’s remote inspection tools or working with JJ, this is a small but handy improvement to watch.
