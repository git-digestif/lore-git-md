This is a **bugfix follow-up** in the config subsystem, part of Junio C Hamano’s ongoing effort to make Git respect file permissions when writing out-of-tree configuration files (e.g., `~/.gitconfig`). The patch itself is uncontroversial and nearly ready—this email is a minor exchange about polish, not substance.

Patrick Steinhardt raises two small points in response to Junio’s v2. First, he notes that the commit message could clarify *why* in-tree files (like `.git/config`) are excluded from permission checks, though he concedes the mutability of repository contents is probably "self-evident" to most readers. Second, he suggests quoting the filename in the new `error_errno()` message for consistency, pointing out that the function’s existing usage is already inconsistent (sometimes quoted, sometimes not). Junio pushes back on both: he sees no need to justify the exclusion of in-tree files further, and he’d rather defer a broader cleanup of error-message formatting to avoid test churn.

The exchange is collegial and low-stakes. Neither point blocks the patch, and Patrick explicitly calls them "nits" he doesn’t feel strongly about. The core fix—adding an `access(2)` check before writing out-of-tree config files and returning `CONFIG_NO_WRITE` if the file is read-only—remains unchanged and well-justified. The patch is likely to proceed to `next` soon, with or without these minor adjustments. If you care about config-file security or have opinions on error-message consistency, this thread is worth a quick skim; otherwise, it’s safe to skip.
