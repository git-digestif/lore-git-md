This is the third and final patch in Tanga Joris’s v4 series fixing a Bash completion regression for four Git built-in commands (`patch-id`, `diff-pairs`, `fast-import`, `var`). The patch adds a defensive test in `t/t0012-help.sh` to catch any future built-ins that retain the `NO_PARSEOPT` flag after being converted to use the `parse-options` API.

The test works by running `git <cmd> --git-completion-helper` for every built-in not listed in `git --list-cmds=parseopt` and checking that the output does not contain any long options (lines starting with `--`). This would fail for commands still marked `NO_PARSEOPT`, as they do not process the completion helper and thus do not list their options. The test already exposed the regression in the previous two patches, which removed the flag from the four affected commands. It skips five commands (`diff`, `diff-files`, `diff-index`, `diff-tree`, `rev-list`) because they print diff options, and `rev-parse` because it echoes unknown arguments. The test does not catch `var` because it only has short options (`-l`), which the completion helper does not list.

The patch is well-motivated and addresses Kaartic Sivaraam’s suggestion for a defensive test. It is technically sound but has a known limitation: it misses commands with only short options. The commit message clearly states this gap, and the test is still valuable as-is. The patch is ready for review and depends on the first two patches in the series, which have already addressed all prior feedback. No further changes to Christian Couder’s `cc/early-scan-options` series are needed.
