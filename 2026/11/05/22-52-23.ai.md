This is a **v2 feature patch** for the promisor-remote subsystem, addressing the `promisor.fetchOrder` configuration variable introduced in the initial submission. The patch now includes documentation in `Documentation/config/promisor.adoc` and restructures the implementation to avoid the file-static `fetch_order` list that caused architectural issues in v1. Instead, the parsed order is stored directly in `struct promisor_remote_config` and re-parsed on each config read, ensuring per-repository isolation.

The core behavior remains unchanged: users specify a comma-separated list of remote names, and Git tries those remotes first (in the listed order) before falling back to the remaining remotes in their original configuration order. The patch also preserves the existing "accepted before configured" pass structure in `lazy_fetch_objects()`. The crash from v1 (triggered by `string_list_split_in_place_f()` on a `STRING_LIST_INIT_DUP` list) is resolved by switching to `string_list_init_nodup()` and properly clearing the list during config reinitialization.

Key technical details:
- **Files touched**: `promisor-remote.c` (108 lines added, 12 removed) and `Documentation/config/promisor.adoc` (11 lines added).
- **New config key**: `promisor.fetchOrder`, documented with cross-references to `gitprotocol-v2` and the partial clone design notes.
- **Storage**: The parsed list is now stored in `struct promisor_remote_config` and cleared during `promisor_remote_clear()`.
- **Algorithm**: A two-pass approach in `try_promisor_remotes()`—first the explicitly ordered remotes, then the rest—replaces the v1 insertion-sort mechanism.
- **Validation**: Remote names in the list are still not validated; typos are silently treated as "not listed."
- **Test coverage**: Still absent, but the author has acknowledged this gap in prior discussion.

The patch directly addresses the architectural flaws and crash identified in v1 while maintaining the original feature goal. The commit message is now more concise and focused on the *what* and *why*, though it does not explicitly mention the v1 issues or their fixes. Documentation is included, but the lack of tests remains a notable omission.
