This is the second patch in Patrick Steinhardt’s five-part series preparing Git’s test suite for alternative object storage backends. It’s a small but necessary refactoring of the "files" object backend.

The patch ensures that when Git initializes a repository with a custom object directory path (e.g., `files:///some/absolute/path`), the leading directories are created if they don’t exist. This matches the behavior already implemented for ref backends in the previous patch and keeps the on-disk setup consistent. The change itself is a single line in `odb/source-files.c` that calls `safe_create_leading_directories_no_share()` before creating the object directory.

The test update in `t/t0001-init.sh` adjusts an existing test to verify that nested directories are handled correctly. The test now uses `files://$(pwd)/absolute/objdir` instead of a flat path, confirming that the backend properly creates intermediate directories.

This is a well-scoped, uncontroversial change that aligns the object backend’s directory creation logic with the ref backends. It’s clearly part of the larger ODB abstraction effort, but the patch itself is purely mechanical and doesn’t introduce new behavior—just ensures existing behavior works in more cases. No review feedback has appeared yet, but given the straightforward nature of the change, it’s likely to be accepted as-is.
