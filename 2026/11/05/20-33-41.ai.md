This is the third patch in Okhuomon Ajayi’s six-patch series refactoring the notes subsystem to eliminate implicit uses of `the_repository`. It updates `write_notes_tree()` and `prune_notes()`—two core functions in `notes.c`—to use the repository stored in `struct notes_tree` instead of the global `the_repository`.

The patch is mechanical and well-scoped: it adds a `struct repository *` field to the `write_each_note_data` and `prune_notes_data` helper structs, propagates the repository from the notes tree through the call chain, and updates all object database operations (`odb_write_object`, `odb_has_object`) to use the tree’s repository. The changes are confined to `notes.c` and touch no other files. No user-visible behavior changes, CLI options, or on-disk format changes are introduced.

The patch builds directly on the first two patches in the series, which added the `repo` field to `struct notes_tree` and updated five other core functions to use it. This incremental approach keeps each patch small and reviewable, and the commit message clearly explains the propagation path for the repository parameter. The only remaining uses of `the_repository` in `notes.c` after this patch are in `display_notes()`, `expand_loose_notes_ref()`, and `the_hash_algo` sizes—these are left for potential follow-up work.

The patch is part of the ongoing `the_repository` removal effort and directly addresses Patrick Steinhardt’s architectural concern by fixing the root cause of unsafe functions rather than guarding downstream callers. It is likely to attract review from René Scharfe (the primary driver of the `the_repository` removal) and Patrick Steinhardt, who will focus on whether the repository field is correctly propagated and used throughout the call chain.
