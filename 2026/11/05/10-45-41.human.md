This is a feature patch adding a `--show-object-format` option to `git ls-remote`. The patch comes from Adrian Ratiu and is motivated by work on Jujutsu (jj), which uses Git for networking but needs to determine a remote repository's object format (SHA-1 or SHA-256) without cloning it.

The problem the patch addresses is real: currently, there is no direct way to query a remote's object format. Users can sometimes infer it from the length of object IDs in `git ls-remote` output, but this fails for empty repositories, where `ls-remote` prints nothing and `git fetch` silently creates a local repository with the wrong format. The new option prints the object format (e.g., `sha1` or `sha256`) on its own line before listing references, working even for empty remotes.

The implementation is straightforward: the option is added to the command-line parser, and when enabled, the patch calls `transport_get_hash_algo(transport)->name` to print the format. The patch includes thorough tests covering both SHA-1 and SHA-256 repositories, empty and non-empty cases, and operation outside a Git repository. Documentation is updated to describe the new option.

The patch is well-motivated, clearly explained, and includes good test coverage. It touches a small, focused part of the codebase (just `ls-remote.c` and its documentation) and does not appear to introduce any edge cases or backwards-compatibility concerns. The feature seems uncontroversial and likely to be merged once reviewed.
