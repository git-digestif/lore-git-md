This is a test-fix patch discussion for the ongoing `git describe` regression fix. Junio C Hamano and Kristofer Karlsson agree that the current patch (lt/describe-commit-date-skew) causes an expected-failure test to pass when a commit-graph exists but still fail without one, creating inconsistency. The proposed fix—unsetting `GIT_TEST_COMMIT_GRAPH` for the specific test—restores consistent behavior by forcing the test to run without a commit-graph, preserving the expected failure until the underlying issue is resolved.

Junio suggests an alternative: testing only the "default" case (with `core.commitGraph=true`) and flipping the test to expect success, since the commit-graph is now enabled by default. However, he acknowledges this as a stop-gap and prefers testing both modes in the long term. The current patch is a pragmatic solution to keep the test suite stable while the broader algorithmic debate (Linus's generation-number fix vs. Kristofer's prototype) continues. No objections have been raised, and the change is minimal, touching only the test infrastructure.
