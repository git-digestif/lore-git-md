This thread is about a bugfix series from Aniket Gupta that prevents `git clone` or `git fetch` from dying when encountering unresolvable relative URIs in bundle lists—a regression introduced in Git 2.41. The series is now in its third version, with all technical feedback addressed and the core fix (skipping problematic URIs instead of failing) confirmed as the correct policy by reviewer Derrick Stolee. The series is ready for maintainer consideration, but a policy debate has emerged over one of its patches.

The debate centers on patch 2/3, which anonymizes credentials in error messages when URI resolution fails. Junio Hamano has raised substantive concerns, questioning whether this protection is necessary. He argues that if bundle lists themselves can contain credentialed URIs (making the feature inherently unsafe), anonymizing error messages is moot. He also notes that `transport_anonymize_url()` is currently used only for user-facing output like reflog entries, not error messages, suggesting the patch breaks precedent. While Junio hasn’t rejected the patch outright, his skepticism puts the burden on Aniket to justify it—or risk dropping it in a v4.

The rest of the series remains uncontested. Patch 1/3 (a refactored `relative_url_gently()` helper) and patch 3/3 (the core fix to skip unresolvable URIs) have Stolee’s unconditional approval. A minor commit message inaccuracy in patch 3 (about bundle list processing behavior) was clarified by Aniket but doesn’t require code changes. The series touches the bundle-uri subsystem, adding new helpers and tests, and is now awaiting Junio’s decision on whether to queue it or request further revisions.
