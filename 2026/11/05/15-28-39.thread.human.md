This thread is about a bugfix series from Aniket Gupta that addresses a regression in Git 2.41’s bundle-uri subsystem, where `git clone` or `git fetch` would die when encountering an unresolvable relative URI in a bundle list (e.g., too many `../` components). The series, now at v3, refactors the URI-handling code to skip problematic bundles with an error message instead of failing the entire operation. The core fix—skipping unresolvable URIs—is uncontested and technically complete, with Derrick Stolee’s approval.

However, patch 2/3, which adds credential anonymization and URL-trimming to error messages, has become the primary point of contention. Junio C Hamano questions the necessity of anonymizing credentials in error messages, arguing that the bundle-uri feature is inherently unsafe if the bundle list contains credentialed URIs. Patrick Steinhardt highlights that the URL-trimming logic harms diagnosability by obscuring the original input URL, making it impossible to debug resolution failures. Aniket has clarified in this follow-up that he will retain the original URL in error messages (addressing Patrick’s concern) while keeping the credential anonymization, likely splitting or refining patch 2 in a v4. The series remains under review, with no merge status change.
