This thread is about a three-patch bugfix series from Aniket Gupta that addresses a regression in Git 2.41's bundle-uri subsystem, where `git clone` or `git fetch` would die when encountering an unresolvable relative URI in a bundle list. The core fix—skipping problematic URIs instead of failing—is technically complete and uncontested, with Derrick Stolee's approval. However, the second patch, which anonymizes credentials in error messages, has sparked a policy debate.

Junio C Hamano questions whether credential anonymization is necessary in error messages, arguing that the bundle-uri feature itself is unsafe if credentialed URIs are present, and that existing uses of `transport_anonymize_url()` are limited to user-facing output, not errors. Patrick Steinhardt adds that the patch's URL-trimming logic harms diagnosability by obscuring the original input URL, making it harder to debug failures. Aniket has clarified that the anonymization is limited to this specific error message and offered to drop the patch if reviewers prefer, but the intertwined URL-trimming logic complicates the issue. A v4 may be needed to address these concerns, possibly splitting the patch into separate credential anonymization and URL-trimming changes.

The series is otherwise ready for maintainer consideration, with all prior feedback addressed. The regression fix aligns with the bundle-uri feature's intent, and the implementation is sound, but the open policy questions around patch 2 are holding up progress. No merge has occurred yet, and the series remains under review.
