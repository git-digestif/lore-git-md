This thread is a bugfix series by Aniket Gupta to address a regression in Git 2.41’s bundle-uri subsystem, where `git clone` or `git fetch` would die when encountering an unresolvable relative URI in a bundle list. The series, now at v3, refactors URI-handling code to skip problematic bundles with an error message (including anonymized URLs for security) instead of failing the entire operation. All feedback from prior iterations has been addressed, and the series is technically complete and ready for maintainer consideration.

Key participants include Aniket Gupta (author) and Derrick Stolee (reviewer). Stolee’s substantive reviews confirmed the correctness of the approach—skipping unresolvable URIs aligns with the feature’s original intent—and approved all patches. The series touches `remote.c`, `bundle-uri.c`, and related test files, introducing a new `relative_url_gently()` helper to avoid fatal errors and improving error messages to prevent credential disclosure. Tests now verify non-fatal error reporting and continued parsing of bundle lists.

In this final follow-up, Aniket clarifies two points: (1) the credential anonymization in patch 2 is limited to the new error message and doesn’t affect other parts of Git, and (2) the commit message for patch 3 inaccurately described the behavior—it stops parsing the bundle list at the bad entry rather than continuing. Neither issue requires code changes, though Aniket offers to send a v4 for the commit message fix if needed. The series remains ready for maintainer pickup, with no open technical or policy questions.
