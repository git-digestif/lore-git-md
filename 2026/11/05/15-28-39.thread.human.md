This thread is a three-patch bugfix series from Aniket Gupta addressing a regression in Git 2.41’s bundle-uri subsystem. The issue occurs when `git clone` or `git fetch` encounters a bundle list containing an unresolvable relative URI (e.g., too many `../` components), causing the operation to die. The fix refactors the URI-handling code to skip problematic bundles with an error message—now including anonymized URLs for security—rather than failing outright.

The series is now complete with v3, which splits the changes into logical patches, tightens tests, and improves error messages. The core change introduces `relative_url_gently()`, a non-fatal variant of `relative_url()` that returns `NULL` and populates an error message on failure. The original `relative_url()` is now a thin wrapper that calls this helper and dies if needed. The patch also modifies `chop_last_dir()` to signal failure without dying, enabling graceful error propagation, and uses `transport_anonymize_url()` to sanitize error messages. Tests in `t5750-bundle-uri-parse.sh` have been updated to verify the new behavior, including credential anonymization.

No substantive review has been posted yet, but the series addresses prior feedback and appears technically complete. The changes are confined to `bundle-uri.c` and its tests, with no on-disk format or cross-subsystem impact. The thread is now awaiting review from maintainers or domain experts.
