This thread is about a bugfix series, now at v3, that addresses a regression in Git 2.41’s bundle-uri subsystem: when `git clone` or `git fetch` encounters a bundle list containing an unresolvable relative URI (e.g., too many `../` components), the operation dies instead of skipping the problematic bundle. The series refactors URI-handling code to skip such bundles with an error message, now including anonymized URLs to prevent credential disclosure. Aniket Gupta is the author, and the series has been technically complete since Derrick Stolee’s substantive review.

The core regression fix—skipping unresolvable URIs—is uncontested and aligns with the bundle-uri feature’s intent. However, patch 2/3, which anonymizes credentials in error messages, has sparked a policy debate. Junio C Hamano questioned its necessity, noting that the bundle-uri feature is inherently unsafe if the bundle list contains credentialed URIs, and that existing uses of `transport_anonymize_url()` are limited to user-facing output, not error messages. Patrick Steinhardt’s recent reply reinforces this critique, highlighting a usability issue: the current implementation trims the error message to show the URL *after* `../` stripping, making it impossible to diagnose why resolution failed. This feedback suggests patch 2 may need to be split or revised in a v4.

The series is under review and not yet queued in Junio’s `seen` branch. The next steps hinge on Aniket’s response to the policy debate. If patch 2 is dropped or reworked, the rest of the series could proceed as-is, as the regression fix is independent of the anonymization logic. A minor documentation inaccuracy in patch 3 (about bundle list processing behavior) may also be corrected in a future revision.
