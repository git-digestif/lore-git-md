This is a **design discussion** in the HTTP retry series, specifically about the default value of `http.retryAfter`. Junio C Hamano briefly endorses Ravi Mistry’s compromise proposal to default `http.retryAfter` to **1 second**, matching curl’s `--retry` behavior (1s, 2s, 4s, ...). This aligns with Junio’s earlier feedback that `0` is incompatible with exponential backoff and avoids the aggressive 30-second initial delay suggested by brian m. carlson, which would escalate to 120 seconds over three retries. The email does not introduce new technical concerns or code changes; it simply signals maintainer approval for the compromise, leaving the final decision to Ravi and brian. Resolution of this open question will likely determine whether a v3 is needed.
