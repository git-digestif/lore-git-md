This is a **substantive review** from Jeff King (Peff) on the second patch of Patrick Steinhardt’s two-patch bugfix series for loose object database (ODB) cache invalidation during `git merge`. The series was previously approved for merging, but Peff’s email raises fundamental questions about the root cause and long-term correctness of the fix.

Peff acknowledges the immediate bug (newly written merged blobs are incorrectly reported as missing due to stale cache entries) and agrees the patch doesn’t make anything worse, but argues the fix is incomplete. He identifies the deeper issue: **any code path using `QUICK` object existence checks (like `prefetch_cache_entries()`) is vulnerable to false negatives**, not just the specific case of `git merge` writing loose objects. The `QUICK` flag is meant to tolerate false negatives, but the current design fails to handle them gracefully—when a promisor remote fetch fails for a local-only object, Git barfs instead of silently recovering.

Peff suggests two alternative approaches:
1. **Omit `QUICK` in prefetch paths** (e.g., `prefetch_cache_entries()`), forcing a full re-scan of the ODB. This would catch locally written objects (packed or loose) but could be expensive for large prefetches.
2. **Reconsider the cache-flushing logic removed in commit `5946a564cdd`**, which previously flushed caches on `SECOND_READ` (a fallback for missing objects). Peff argues this was a useful optimization signal, not just a correctness hack.

He also highlights a broader class of bugs: **racy cache staleness** where objects written by other processes (e.g., `git repack` or `git log`) or even helper processes in `git merge` could trigger the same issue. The current fix only addresses objects written by the same process, leaving other cases unhandled.

The email includes a detailed reproducer for a hypothetical race condition involving `git log` and `git repack`, and notes that false positives (objects cached as present but later pruned) are a separate, unsolved problem. Peff’s tone is collaborative but firm—he’s not rejecting the patch, but he’s making it clear this is a band-aid, not a cure.

**Key technical details for follow-up discussion:**
- **Files/subsystems:** `odb/source-loose.c`, `prefetch_cache_entries()`, promisor remote logic.
- **Flags:** `QUICK`, `OBJECT_INFO_FOR_PREFETCH`, `SECOND_READ`.
- **Prior work:** Commit `5946a564cdd` (removed cache flushing).
- **New symbols:** None introduced here, but `loose_cache_mark_seen()` (from the patch) is central to the debate.
- **Behavior change:** Peff’s proposed alternatives would affect performance trade-offs (e.g., re-scanning packs vs. tolerating stale caches).

**Likely points of contention:**
- Whether to prioritize correctness (Peff’s preference) or minimal disruption (the current patch).
- Whether to address racy staleness now or defer it.
- The performance impact of omitting `QUICK` in prefetch paths.

This review shifts the thread from "ready to merge" to an open design discussion, with Peff’s concerns likely to prompt further iteration or a follow-up series.
