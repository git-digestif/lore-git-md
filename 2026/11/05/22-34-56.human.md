This is the first patch in Tanga Joris’s v5 Outreachy series, fixing a Bash completion regression for Git’s built-in commands. The patch centralizes handling of `--git-completion-helper` and `--git-completion-helper-all` in `parse-options.c`, ensuring these flags are processed before any command-specific initialization. This prevents side effects like temporary file creation or blocking on input, which were particularly problematic for `git fast-import`.

The change is minimal and focused: it adds a six-line block to `show_usage_with_options_if_asked()` to handle the completion-helper flags generically, avoiding per-command boilerplate. The updated comment in `parse-options.h` now clearly explains the function’s purpose—answering help or completion requests before option parsing—without over-specifying the `fast-import` edge case. Two new tests in `t/t9300-fast-import.sh` verify that `git fast-import --git-completion-helper` and `--git-completion-helper-all` no longer create temporary pack files or read from stdin, addressing the issue René Scharfe identified in earlier iterations.
