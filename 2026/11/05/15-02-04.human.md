This is the third patch in Patrick Steinhardt’s five-part series preparing Git’s test suite for pluggable object storage backends. It extends the existing `init.defaultRefStorageFormat` and `init.defaultObjectStorageFormat` configuration knobs — and their environment-variable counterparts — to accept a payload (e.g., `files:///path/to/objdir`). The change is small but essential: without it, tests cannot specify where the backend should store its data, which is the whole point of the series.

The patch touches only `setup.c` and `t/t0001-init.sh`. In `setup.c`, the parsing logic is updated to split the format string into a backend name and an optional payload using the existing `*_by_uri()` helpers. The payload is then stored in the repository format structure and freed at the appropriate time. The test script adds four new cases: two for ref storage (via config and environment) and two for object storage (same), all verifying that the payload is correctly recorded and that the backend creates the expected directory structure.

The implementation is clean and well-contained; there are no behavioral changes outside the new payload support. The commit message is clear, and the tests cover the advertised functionality. This patch is a straightforward, uncontroversial step toward the larger ODB abstraction goal.
