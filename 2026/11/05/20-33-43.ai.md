This is the fifth patch in Okhuomon Ajayi’s six-patch series refactoring the notes subsystem to remove implicit uses of `the_repository`. The patch updates the `combine_notes` callbacks (`concatenate`, `overwrite`, `ignore`, and `cat_sort_uniq`) to accept an explicit `struct repository *` parameter, allowing them to operate on the correct repository when combining notes from different repositories. It also updates `copy_note()` to use the tree’s hash algorithm for its null object ID, ensuring consistency with the repository’s configuration.

The changes are mechanical: every `combine_notes` callback signature gains a `struct repository *` parameter, and all internal calls to `odb_read_object()` and `odb_write_object()` are updated to use the passed repository instead of `the_repository`. The `string_list_add_note_lines()` helper is similarly updated to take a repository parameter. The patch touches `notes.c` and `notes.h`, updating function signatures and call sites to propagate the repository through the call chain. No user-visible behavior changes are introduced, and the patch maintains backward compatibility by ensuring the callbacks work correctly regardless of which repository the notes tree belongs to.

This patch directly addresses the architectural concern raised by Patrick Steinhardt: the `combine_notes` callbacks were unsafe because they implicitly used `the_repository`, even when the notes tree belonged to a different repository. By passing the repository explicitly, the callbacks become repository-agnostic, eliminating the need for downstream guards. The patch is well-scoped and builds on the earlier patches in the series, which added the `repo` field to `struct notes_tree` and updated core functions to use it.

The patch is part of the ongoing `the_repository` removal effort, and its approach aligns with the project’s preference for fixing root causes rather than guarding downstream callers.
