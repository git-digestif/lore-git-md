This is a bugfix series targeting the bundle-uri subsystem. The problem: when `git clone --bundle-uri` encounters a relative URI in the bundle list that cannot be resolved (e.g., a path that does not exist on the server), the entire clone fails with a fatal error. The series changes the behavior so that Git reports the unresolvable URI and skips that bundle instead of dying.

The three patches are cleanly split: the first adds a new helper `relative_url_gently()` that does not die on errors, the second ensures that credential information is not leaked in error messages when `relative_url()` fails, and the third switches the bundle-uri code to use the gentle variant so that unresolvable URIs become skippable warnings rather than show-stoppers. The commit messages are clear and the test updates cover both the new helper and the end-to-end behavior change.

This is a sensible, well-scoped fix that addresses a real usability pain point without touching unrelated code. The series has already gone through two iterations and the changes since v2 are minor (better commit message wording, full error-message comparison in tests, and clearer URL reporting). It looks ready for review and likely to land soon.
