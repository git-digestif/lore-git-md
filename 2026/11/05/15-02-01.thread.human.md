This thread is preparing the Git test suite for the upcoming ODB (object database) abstraction work, led by Patrick Steinhardt. The five-patch series introduces infrastructure to let tests specify alternative object storage backends via `GIT_TEST_DEFAULT_OBJECT_STORAGE_FORMAT`, though no such backend exists yet. The current version (v1) focuses on exposing and fixing hard-coded assumptions about `.git/objects` in the test suite, with ~1,100 failing tests deferred to follow-up work.

The series has seen light but substantive review from Karthik Nayak, who suggested a mechanical improvement to one test script (`t1423-ref-backend.sh`) to avoid redundant CI execution. His latest feedback—a brief, positive note on the fourth patch—confirms the consistency fix for `git rev-parse --show-ref-storage-format` (adding payload output to match the object storage format behavior). This patch is uncontroversial and aligns with the series’ goal of symmetry between ref and object storage formats.

Key changes include directory-creation logic for ref backends and the "files" object backend, payload parsing in repository setup, and the new `GIT_TEST_DEFAULT_OBJECT_STORAGE_FORMAT` environment variable. The series is still under review, with no merge status claimed, and remains dependent on Patrick’s `ps/odb-object-storage-extension` branch. The only open technical question is Karthik’s untested suggestion for `t1423`, which Patrick may address in a future revision.
