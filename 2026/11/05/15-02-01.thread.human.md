This thread is about preparing Git’s test suite to support non-default object storage backends, a key step in Patrick Steinhardt’s ongoing ODB abstraction effort. The five-patch series introduces `GIT_TEST_DEFAULT_OBJECT_STORAGE_FORMAT`, an environment variable that lets tests specify an alternative object storage format (e.g., `files://objdir`), exposing hard-coded assumptions about `.git/objects` in the test suite. While ~1100 tests currently fail under this regime, fixing them is deferred to follow-up work.

The series is under review and remains at v1, with no merge status claimed. Key changes include plumbing for payload parsing in default format strings, directory creation in ref backends, and updates to `rev-parse` to print payloads for both object and ref storage formats. The only prior dispute—whether to retain a `for` loop in `t1423-ref-backend.sh`—was resolved in Patrick’s favor, as he argued it was necessary to directly test ref storage behavior. Karthik Nayak’s reviews were substantive but narrowly scoped, and his suggestion to simplify the test was declined. Junio’s latest feedback was purely mechanical (a typo and merge conflict), requiring no resend. The series is now technically uncontested, though the deferred test failures and lack of an alternative backend mean its immediate utility is limited to infrastructure.
