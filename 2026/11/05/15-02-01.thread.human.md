This thread is about preparing Git’s test suite to support alternative object storage backends, a key step in Patrick Steinhardt’s ongoing ODB abstraction effort. The five-patch series introduces `GIT_TEST_DEFAULT_OBJECT_STORAGE_FORMAT` to let tests specify non-default backends, though no such backend exists yet. Instead, the series focuses on exposing tests that hardcode assumptions about `.git/objects` by attaching payloads (e.g., `files://objdir`) to the default format string. About 1,100 tests currently fail under this regime, but fixing them is deferred.

The series is under review at v1, with no merge status claimed. Key changes include directory creation in ref backends (`refs/files-backend.c`, `refs/reftable-backend.c`), payload parsing in `setup.c`, and a 14-line addition to `builtin/rev-parse.c` to print payloads for both object and ref storage formats. Tests in `t0001-init.sh`, `t1423-ref-backend.sh`, and `t1500-rev-parse.sh` were updated to verify the new behavior. Karthik Nayak reviewed the series positively, calling it “a very easy read” and suggesting a mechanical improvement to `t1423-ref-backend.sh` to avoid redundant CI execution. No objections or broader changes were requested. The series remains focused on test infrastructure, with no on-disk format changes.
