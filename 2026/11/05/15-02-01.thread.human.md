This thread is about Patrick Steinhardt’s five-patch series that prepares Git’s test suite to run with alternative object-storage backends. The series is a step in the long-running ODB abstraction effort, letting tests specify a different storage format via the `GIT_TEST_DEFAULT_OBJECT_STORAGE_FORMAT` environment variable. Since no actual alternative backend exists yet, the patches also introduce a way to attach a payload (like `files://objdir`) to the default format string, which helps uncover tests that hard-code assumptions about `.git/objects`. About 1,100 of Git’s 35,000 tests currently fail under this setup, but fixing those is left for later.

The patches touch the ref backends (both files and reftable), the ODB source-files layer, and the setup and rev-parse built-ins to parse and display the payload. Three test scripts are extended to exercise the new functionality, and the test library gains the necessary environment-variable plumbing. The series is based on a recent integration batch and Patrick’s own `ps/odb-object-storage-extension` branch, and it’s currently under review with no merge status claimed yet.
