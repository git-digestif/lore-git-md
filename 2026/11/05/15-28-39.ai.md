This is a bugfix series targeting the bundle-uri subsystem. The problem: when `git clone` or `git fetch` encounters a bundle list containing a relative URI that cannot be resolved, the entire operation dies. The series refactors the URI-handling code to report the error and skip the problematic bundle instead.

The three patches are cleanly split: the first adds a new `relative_url_gently()` helper that does not die on failure; the second ensures that credentials are not leaked in error messages when the helper fails; the third changes the bundle-uri code to use the gentle variant and skip unresolvable URIs. The commit messages are clear, the test coverage is expanded (new unit test in `t0060-path-utils.sh` and updated bundle-uri tests in `t5750`), and the error messages now name the problematic URL rather than a stripped-down version.

The series is part of the bundle-uri feature introduced in Git 2.41, so it is fixing a regression in a relatively new code path. The changes are confined to `remote.c`, `remote.h`, and `bundle-uri.c`, with no cross-subsystem impact. The v3 iteration addresses feedback from v2 by splitting the patches, rewording the commit message, and tightening the test expectations. The code looks well-motivated and ready for review.
