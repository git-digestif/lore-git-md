This is the first patch in a three-part bugfix series for the bundle-uri subsystem. It introduces `relative_url_gently()`, a non-fatal variant of the existing `relative_url()` helper that resolves relative URIs against a base URL. The new function returns NULL and populates a `strbuf` error message instead of calling `die()` when the relative URI contains too many `../` components to resolve. The original `relative_url()` is now a thin wrapper that calls `relative_url_gently()` and dies if it fails, preserving backward compatibility for existing callers.

The patch touches `remote.c` and `remote.h`, adding the new function and updating the internal `chop_last_dir()` helper to signal failure without dying. The logic is straightforward: when `chop_last_dir()` cannot strip another directory component, it returns -1, triggering `relative_url_gently()` to clean up, set the error message, and return NULL. The error message now includes the problematic URL, improving diagnosability.

This is a refactoring patch with no behavior change for existing callers. The motivation is to enable the bundle-uri subsystem to skip unresolvable URIs rather than failing the entire operation, which the subsequent patches will implement. The code is clean, the commit message is clear, and the test coverage will be added in the third patch. No open questions or loose ends are apparent.
