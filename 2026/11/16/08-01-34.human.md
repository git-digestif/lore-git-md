This is the first patch in a two-patch performance series targeting the `git repo structure` command. It delays object parsing until it is actually needed, avoiding the current wasteful practice of reading and parsing every object—including blobs and tags—even when only basic metadata like object type is required. The change is confined to `builtin/repo.c` and introduces no new user-facing options or on-disk format changes.

The patch exploits the fact that commits encountered during the revision walk are already parsed, so it skips re-parsing them entirely, instead looking them up directly via `lookup_commit()`. For trees, it still parses the object but only when necessary (blobs and tags are now skipped). The updated code comment in this version clarifies that `repo_parse_commit()` is a failsafe, not a dependency, addressing the only feedback from the first iteration.

Benchmarking in `git.git` shows a 12% wall-time improvement and a 4% memory reduction, with larger gains expected in repositories with many blobs or tags. The patch is well-motivated, narrowly scoped, and uncontroversial; it is ready for maintainer pickup alongside its companion patch.
