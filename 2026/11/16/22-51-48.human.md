This is a bugfix patch targeting submodule handling in linked worktrees.

Andreas Wendleder reports a crash (a `BUG()` assertion) when switching branches in a superproject worktree if the submodule is itself a linked worktree and `submodule.recurse=true` is set. The crash occurs in `validate_submodule_legacy_git_dir()` because the function expects the submodule’s Git directory path to end with the submodule’s name, but a linked worktree’s path (`modules/<name>/worktrees/<id>`) does not satisfy this condition.

The reproduction script is thorough: it creates a superproject with a submodule, adds two linked worktrees to the submodule (one named `sub`, the other `sub1`), and then attempts a branch switch in a superproject worktree with recursion enabled. The script confirms the bug exists on `master`, `next`, and `seen`.

The patch does not include a fix, but the analysis is clear: the legacy validation path should return an error rather than calling `BUG()`, and the newer `extensions.submodulePathConfig` path already does so—but its error message incorrectly suggests enabling the extension even when it is already active. The author’s expectation is that linked worktrees of submodules should be accepted, or at least rejected gracefully. This looks like a real, reproducible issue that affects a non-exotic workflow; the fix will likely be small and targeted.
