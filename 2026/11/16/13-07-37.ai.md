This is the first patch in Patrick Steinhardt’s 12-patch series introducing **pluggable commit graphs** as part of the **ODB abstraction** effort. It simplifies the logic for linking commit-graph chains by removing redundant object ID tracking and making the linking function public.

The patch refactors `add_graph_to_chain()` into `commit_graph_link_base()`, which now derives base-layer hashes by walking the existing chain structure instead of requiring an explicit array of object IDs. This reduces memory overhead (no need to allocate an `oids` array) and prepares the code for later patches that will move chain-creation logic into the ODB backend. The new function returns an error code (`0` for success, `-1` for failure) rather than a boolean, and validation logic (e.g., checking chain depth and commit counts) is preserved but streamlined.

Key changes:
- **Files touched**: `commit-graph.c` (core refactoring) and `commit-graph.h` (new function declaration).
- **Behavior**: No user-facing changes, but the internal API is now more flexible for backend-specific implementations.
- **Performance**: Minor improvement from avoiding redundant allocations, though the primary goal is code clarity and pluggability.

The patch is a mechanical refactor with no new functionality, but it’s a critical step toward ODB abstraction. The commit message explains the motivation clearly, and the changes align with the series’ goal of making commit-graph storage backend-agnostic. No tests are added here, as this is infrastructure-only work. Future patches in the series will build on this foundation to move path logic into the ODB backend.
