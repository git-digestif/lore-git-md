Andreas Wendleder reported a crash where switching branches in a superproject with `submodule.recurse=true` triggers a `BUG()` abort if one of the submodules is itself a linked worktree of its repository. Adrian Ratiu traced the root cause to a 2024 change that made `submodule_move_head()` validate gitdir paths read from disk, turning a previously unreachable assertion into a live crash, and has posted a three-patch v1 series to fix it.

The series addresses three related problems. The first patch replaces the `BUG()` abort in `validate_submodule_legacy_git_dir()` with a proper error message so Git fails gracefully instead of crashing. The second fixes a misleading hint in the `extensions.submodulePathConfig` code path that suggested enabling the extension even when it was already on, by moving the advice into a separate `advise()` call that only fires when the extension is actually disabled. The third and final patch teaches `submodule_move_head()` to recognize linked-worktree gitdirs (paths like `.git/modules/sub/worktrees/sub1`) as valid, skipping the rewrite of the `.git` file and `core.worktree` in that case so recursive operations succeed without breaking the submodule. Each patch comes with test coverage in `t/t7450-bad-git-dotfiles.sh`, `t/t7425-submodule-gitdir-path-extension.sh`, and `t/t2405-worktree-submodule.sh`.

The series is currently under review as v1, based on commit `e1ec09b23c8e0deb21a0b95ac5996422277395d4`, and has not been merged to `master`, `next`, or `seen`. Whether linked worktrees of submodule repositories should be formally accepted as valid git directories is proposed but still awaiting maintainer and community feedback.
