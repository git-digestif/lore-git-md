The thread concerns a crash (`BUG()`) in Git when a submodule is itself a linked worktree of its repository and `submodule.recurse=true` is set during a recursive branch switch in the superproject. Andreas Wendleder reported the bug with a reproduction script; Adrian Ratiu traced the root cause to a security-fix commit that made `submodule_move_head()` validate on-disk gitdir paths, which made a previously unreachable `BUG()` triggerable, and posted a three-patch v1 series fixing the crash, a misleading `extensions.submodulePathConfig` hint in his own extension code, and acceptance of linked-worktree git dirs for submodules. The series is under review, with no part merged to `master`, `next`, or `seen`.

Junio C Hamano has now reviewed both `[PATCH 1/3]` and `[PATCH 2/3]`. On patch 1 he agrees the fix makes sense but asks that the explanatory comment state the actual invariant (why the git dir must end with the submodule name) rather than referencing the historical `BUG()`-to-`error()` conversion. On patch 2, which moves the extension hint out of the fatal `die()` into a conditional `advise()` gated on the extension being disabled, he finds the motivation sensible but suggests the simpler hedged wording already used by `submodule_name_to_gitdir()` ("might fix ... if it's not already enabled") instead of an explicit state check, and notes that `clone_submodule()` in `builtin/submodule--helper.c` carries the same unconditional hint and may need the same treatment. He also asks that the deeply nested non-dry-run block in `submodule_move_head()` be extracted into a helper function for readability.

Still open is review of `[PATCH 3/3]`, which teaches `submodule_move_head()` to accept a submodule `.git` file pointing at a linked-worktree git dir (via the new `validate_submodule_gitfile_dir()` helper, which rejects forged paths and skips rewriting the `.git` file and unsetting `core.worktree`), plus whether Adrian adopts Junio's suggested rewording, the hedged-message approach, and the nested-block refactor in a v2.
