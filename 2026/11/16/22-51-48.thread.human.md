Adrian Ratiu has posted version 2 of his five-patch series fixing a crash that occurs when a submodule is itself a linked worktree and `submodule.recurse=true` is set during branch switching in the superproject. The original bug report came from Andreas Wendleder, who provided a reproduction script for the `BUG()` abort in `validate_submodule_legacy_git_dir()`; the series also addresses a misleading error message that incorrectly suggests enabling `extensions.submodulePathConfig` when that extension is already active or irrelevant to the actual problem.

The v2 series, which applies on commit `e1ec09b23c8e`, restructures the fix across five commits. The first replaces the `BUG()` with a proper `error()` and adds a regression test; the second introduces a shared `die_refusing_submodule_git_dir()` helper to centralize the "refusing to create/use" message and conditionally advise about the extension only when it is not enabled; the third -- just posted -- is a cosmetic extraction of the git-directory setup logic from `submodule_move_head()` into a new `setup_submodule_git_dir()` helper to reduce nesting, with no functional change; the fourth adds validation immediately after `absorb_git_dir_into_superproject()` to handle nested-submodule edge cases; and the fifth accepts linked worktrees as valid submodule git dirs via a new `validate_submodule_worktree_dir()` helper, skipping the `.git` file rewrite when a worktree is detected. The series remains under review, with Junio C Hamano having provided detailed feedback on v1 that Ratiu incorporated into v2, but he has not yet responded to the new version.
