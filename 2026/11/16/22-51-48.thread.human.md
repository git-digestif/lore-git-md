This thread is about a **bugfix for a crash in Git's submodule subsystem**. Andreas Wendleder reports that when a submodule is itself a linked worktree of its repository and `submodule.recurse=true` is set, Git hits a `BUG()` assertion in `validate_submodule_legacy_git_dir()` during branch switching in the superproject. The issue stems from linked worktrees' git directories (e.g., `.git/modules/sub/worktrees/sub1`) not ending with the submodule name, violating the validation logic. With `extensions.submodulePathConfig` enabled, the same setup fails with a misleading error message instead of crashing.

The bug is reproducible with a minimal script and affects all integration branches (`master`, `next`, and `seen`), meaning it hasn’t been fixed yet. The patch argues that linked worktrees of submodule repositories should either be accepted as valid or rejected with a proper error—not crash or mislead users. This is a clear correctness issue, and the fix will likely involve relaxing the validation logic or improving error handling in the legacy code path.
