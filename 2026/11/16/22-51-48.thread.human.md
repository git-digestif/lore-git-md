The thread addresses a crash in Git when a submodule is itself a linked worktree of its repository and `submodule.recurse=true` is set during branch switching. Andreas Wendleder reported the bug, and Adrian Ratiu has posted a three-patch v1 series to fix both the crash and a misleading error message that incorrectly suggests enabling `extensions.submodulePathConfig`. Junio C Hamano has reviewed all three patches and agreed the fixes make sense, though no version has been merged to any integration branch yet.

The series remains under review with a v2 pending. Junio has approved several structural changes Adrian has agreed to implement: dropping a contested comment from patch 1, replacing hedged "might fix" wording in patch 2 with an explicit check of the extension state via a shared helper across all three call sites in `submodule_move_head()`, `submodule_name_to_gitdir()`, and `clone_submodule()` -- a direction Junio just endorsed as "super sensible" -- and restructuring patch 3 so that linked-worktree detection happens unconditionally after ensuring the `.git` file exists but before the forced-move check, which fixes a nested-submodule edge case Junio identified where recursive absorption could leave the worktree flag unset. Adrian reproduced that edge case and accepted the restructure. A v2 incorporating all of these changes has not yet been posted.
