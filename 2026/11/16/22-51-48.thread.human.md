This thread fixes a crash where Git aborts with a `BUG()` during recursive submodule checkout when a submodule is itself a linked worktree. Andreas Wendleder reported the issue with a reproduction script: when a submodule's git directory ends in a worktree id rather than the submodule name (for example `.git/modules/sub/worktrees/sub1`), the suffix assertion in `validate_submodule_legacy_git_dir()` fails. Adrian Ratiu diagnosed the root cause and developed a five-patch v2 series that addresses both the crash and a related misleading error that suggested enabling `extensions.submodulePathConfig` when the real problem was a worktree git dir.

The v2 series, now complete with all five patches posted by Ratiu on base `e1ec09b23c`, resolves every concern Junio C Hamano raised during the v1 review. It replaces the `BUG()` with a proper error message, introduces a shared `die_refusing_submodule_git_dir()` helper that only suggests the extension when appropriate, extracts `setup_submodule_git_dir()` to reduce nesting, adds validation after git-dir absorption to catch stale gitfiles, and -- in the final patch -- teaches Git to accept linked worktrees as valid submodule git dirs via `validate_submodule_worktree_dir()`, skipping the forced `.git` file rewrite and `core.worktree` unset that would otherwise corrupt the worktree. Tests across `t/t2405-worktree-submodule.sh`, `t/t7425-submodule-gitdir-path-extension.sh`, and `t/t7450-bad-git-dotfiles.sh` cover acceptance of worktree submodules, absorb-path handling, clean removal, and rejection of forged worktree dirs.

The series remains under review; no part has been merged to `master`, `next`, or `seen`, and Junio has not yet responded to v2. Once picked up, it will allow `checkout --recurse-submodules` to work correctly when submodules are linked worktrees instead of crashing.
