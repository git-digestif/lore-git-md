This thread began with Srujith A. Poojary’s patch to remove a single use of the global `the_repository` in `overlay_tree_on_index()` by switching to the repository associated with the provided `index_state`. The patch is part of the ongoing project-wide effort to eliminate implicit reliance on `the_repository` in favor of explicit repository parameters. Derrick Stolee initially gave it a surface-level LGTM, calling it a clean, mechanical change with no substantive concerns.

Junio C Hamano’s recent reply shifts the conversation from a narrow review to a broader architectural discussion. While he accepts the patch as-is—calling it a harmless step forward—he points out that other functions in `read-cache.c` (`add_to_index()`, `refresh_index()`) suffer from the same issue but are not addressed here. He suggests that future cleanups should tackle these together to reduce patch churn, though he cautions against attempting a wholesale removal of `USE_THE_REPOSITORY` from the file in one go. The deeper challenge, he notes, is that many lower-level functions in the file lack an `istate` or `repo` parameter, and fixing this would require design work that hasn’t been done yet. His feedback reframes the patch as a small part of a larger, still-unresolved refactoring plan, leaving the door open for further discussion on how to proceed. The patch itself remains uncontested and is likely to be merged as-is, but the thread now highlights the need for a more deliberate approach to the broader cleanup.
