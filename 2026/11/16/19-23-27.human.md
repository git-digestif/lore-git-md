This is the author’s response to the ongoing RFC thread about adding diff display to `git history reword`. The patch series, originally proposed as opt-in via `--verbose`, is now being revised to make diff display the **default behavior** for `git history reword`, `split`, and `fixup`, while respecting the existing `commit.verbose` configuration. The author acknowledges the feedback from Karthik Nayak, Phillip Wood, and D. Ben Knoble, who collectively favored default diff display—provided users can opt out via configuration. This shift resolves the opt-in vs. opt-out debate for now, though the unresolved question of **output format generalizability** (raised by Patrick Steinhardt) remains unaddressed. The author’s plan to tie the behavior to `commit.verbose` aligns with Phillip Wood’s earlier suggestion and avoids introducing a new config key, but it may still face scrutiny if reviewers feel the output format needs to be redesigned to support future `git history` subcommands. The next version of the patch will likely drop the `--verbose` flag entirely, simplifying the interface but deferring the scripted-editing concern (Phillip Wood’s point about automated edits) to a future opt-out mechanism.
