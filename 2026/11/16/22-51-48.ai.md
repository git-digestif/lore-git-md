This is a **bugfix** targeting the submodule subsystem. The patch reports a crash (BUG()) in `validate_submodule_legacy_git_dir()` when a submodule is itself a linked worktree of its repository and `submodule.recurse=true` is set. The issue surfaces during branch switching in the superproject worktree.

The reproduction script demonstrates the problem: when a submodule repository has multiple linked worktrees, their git directories (e.g., `.git/modules/sub/worktrees/sub1`) do not end with the submodule name, triggering the BUG() assertion. With `extensions.submodulePathConfig` enabled, the same setup fails with a misleading error message suggesting the extension is not enabled, even though it is.

The patch argues that linked worktrees of submodule repositories should either be accepted as valid git directories or rejected with a proper error (not a BUG()). The current behavior is clearly broken—crashing in one case and providing a confusing hint in the other. The issue affects all integration branches (`master`, `next`, and `seen`), indicating it has not been addressed yet.

This is a clear correctness bug with a minimal reproduction case, making it a strong candidate for attention. The fix will likely involve either relaxing the validation logic or improving error handling in the legacy path.
