This is a contributor housekeeping patch that aligns the naming of Git’s credential-store lock timeout configuration with the established convention used by other lock-timeout settings. The patch introduces `credentialStore.lockTimeout` as the preferred key while retaining `credentialStore.lockTimeoutMS` as a deprecated alias, ensuring backward compatibility.

The change is purely mechanical and follows directly from the recent `rerere.lockTimeout` patch, which established the convention that lock-timeout variables should omit the unit (milliseconds) from their names. The commit message now explicitly enumerates all existing lock-timeout variables (`rerere.lockTimeout`, `reftable.lockTimeout`, `core.filesRefLockTimeout`, etc.) to demonstrate the consistency of the convention, addressing Junio C Hamano’s substantive objection from the v2 review. The patch touches three files: `Documentation/config/credential.adoc` (updated description and deprecation notice), `builtin/credential-store.c` (config lookup falls back to the old key), and `t/t0302-credential-store.sh` (test coverage for the new key, old key compatibility, precedence, and zero timeout).

The v3 patch incorporates all feedback from Junio’s review of v2. The config lookup line in `builtin/credential-store.c` is now wrapped for readability, and the test cases are collapsed into a single loop over both config key names to reduce duplication. A comment clarifies that the "both are set" test verifies the new key takes precedence by checking for "in 0 ms" rather than "in 500 ms". The patch is uncontroversial and ready for integration, as it restores naming consistency without altering behavior. It is part of a broader effort to standardize timeout variable naming across Git’s configuration system.
