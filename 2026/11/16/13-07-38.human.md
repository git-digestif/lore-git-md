This is the second patch in Patrick Steinhardt’s 12-patch series introducing **pluggable commit graphs** as part of the **ODB abstraction** effort. It simplifies the logic for reading a single commit-graph layer by consolidating path handling and renaming a function to better reflect its new, narrower scope.

The patch removes the `dir` parameter from `load_commit_graph_one_fd_st()` (now renamed to `commit_graph_read()`), moving path population into `load_commit_graph_one()`. This change prepares for the upcoming shift of path-derivation logic into the ODB backend, where it will become backend-specific. The diff is small (13 insertions, 16 deletions) and touches only three files: `commit-graph.c`, `commit-graph.h`, and `builtin/commit-graph.c`.

The motivation is clear: the current design exposes backend-specific details (directory paths) to generic commit-graph code, which violates the separation of concerns the series aims to establish. By centralizing path handling in `load_commit_graph_one()`, the patch makes the codebase more modular and paves the way for future backend-specific implementations. The rename from `load_commit_graph_one_fd_st()` to `commit_graph_read()` also signals the function’s reduced responsibility—it now only reads a graph from a file descriptor, without worrying about where that file came from.

No user-facing behavior changes are introduced, and the patch is purely mechanical. The commit message is concise but sufficient, explaining both the "what" and the "why" without overloading the reader. Given the series’ broader goal of ODB abstraction, this patch looks like a well-justified refactor that should attract little controversy—though reviewers may check for edge cases in path handling or unintended side effects in the callers.
