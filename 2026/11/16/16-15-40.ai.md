This is a reply in the ongoing `git worktree list --merged` RFC thread, specifically addressing Junio’s forward-looking design feedback on the first patch (the safety check for `git worktree remove`). The patch itself is uncontroversial and ready for integration, but the discussion here focuses on future refactoring opportunities.

Jasper agrees with Junio’s suggestion to eventually consolidate the scattered worktree state checks into a reusable helper in `worktree.c`. Currently, three separate places (`branch.c`, `worktree.c`, and the new safety check) read rebase/bisect state, each with slightly different needs: `prepare_checked_out_branches()` only records branch names, while the new safety check also cares about detached HEADs and operations like `git am` or cherry-pick. A unified helper would report both the operation type and the branch (if any), making it reusable for all three call sites.

The tone is collaborative and pragmatic. Jasper proposes tackling this refactoring in a follow-up series rather than holding up the current patch, which Junio had already marked as `#leftoverbits` (future work). No objections are raised to the current patch, and the discussion remains focused on maintainability rather than immediate functionality. The key technical detail for future reference is the proposed helper’s interface: it would return an error code (not die) and report both the operation and the branch, if applicable.
