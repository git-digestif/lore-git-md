This is the third patch in Patrick Steinhardt’s 12-patch series introducing **pluggable commit graphs** for the ODB abstraction effort. It exposes the internal chain-validation logic (`validate_mixed_generation_chain` and `validate_mixed_bloom_settings`) as a public function, `commit_graph_validate_chain`, so the ODB backend can call it after loading a commit-graph chain. The change is minimal—just moving existing code into a header and renaming the call site—but it’s a necessary step for the backend-specific loading logic that follows in later patches.

The patch touches only `commit-graph.c` and `commit-graph.h`, adding the new function and updating the call site in `load_commit_graph_chain_fd_st`. No behavior changes are introduced; this is purely a refactoring to prepare for the backend’s future responsibility. The commit message is clear about the motivation: the ODB backend will soon handle commit-graph loading, and it needs access to this validation logic.

This patch is uncontroversial on its own—it’s a straightforward mechanical change—but it’s part of a larger refactor that’s likely to draw scrutiny. The key question for reviewers will be whether exposing this function is the right abstraction boundary, or if the validation logic should be redesigned to better suit backend-specific needs. The patch doesn’t address that directly, but it sets the stage for the discussion.
