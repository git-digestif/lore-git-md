This is a **substantive review reply** to the second patch in Adrian Ratiu’s three-patch bugfix series for the `compatObjectFormat` interoperability layer. The patch itself (already summarized in the parent email) fixes a silent failure in `git rev-parse --output-object-format` by making it die when `repo_oid_to_algop()` cannot map an object, aligning its behavior with other callers.

Patrick Steinhardt’s review is narrowly focused on the test design. He raises a forward-compatibility concern: the test manually copies a loose object into the repository, which could break if the object storage format changes (e.g., with the new ODB abstraction effort). He suggests an alternative approach—writing the object with `extensions.compatobjectformat` unset, then setting it afterward—to avoid direct manipulation of the object database. The suggestion is technically sound but does not question the patch’s core logic; it is a test-maintenance observation rather than a correctness critique. Adrian may choose to adjust the test in a follow-up or defend the current approach, but the fix itself remains uncontroversial and well-justified. No other feedback is provided on this patch.
