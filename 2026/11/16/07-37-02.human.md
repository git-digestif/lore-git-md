This is a review reply to the second patch in Adrian Ratiu’s three-patch series fixing bugs in Git’s `compatObjectFormat` interoperability layer. The patch itself is a straightforward bugfix: it makes `git rev-parse --output-object-format` die with an error when it cannot map an object to the requested compat format, instead of silently returning the wrong OID. The fix is uncontroversial and well-justified, and the test coverage is thorough.

Patrick Steinhardt’s review is surface-level. He agrees the current behavior is wrong and the fix is correct, but raises two minor points: (1) he finds the commit message’s explanation of the scope (“this only covers a single revision argument”) hard to parse and suggests a clearer rewrite, and (2) he questions the test’s manual object-copying approach, asking whether it could be done by writing the object with `extensions.compatobjectformat` unset and then setting it afterward. This avoids direct manipulation of the object database, which Patrick notes may break when the new object storage format extension lands. Neither point challenges the substance of the patch, and both are framed as suggestions rather than objections. The patch remains on track for merging once the minor wording and test adjustments are addressed.
