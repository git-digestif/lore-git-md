This is the sixth patch in Patrick Steinhardt’s 12-patch series introducing **pluggable commit graphs** as part of the **ODB abstraction** effort. The patch eliminates redundant bookkeeping in the split commit-graph write path by deriving layer information directly from the passed-in commit-graph chain instead of maintaining separate arrays for hashes, filenames, and merge targets. This refactoring prepares the codebase for backend-specific logic by isolating path-dependent operations, a key step toward making commit-graph storage pluggable.

The patch touches only `commit-graph.c` (227 lines changed, 97 additions, 130 deletions) and introduces no new user-facing behavior. It removes five fields from `struct write_commit_graph_context` (`base_graph_name`, `commit_graph_filenames_before`, `commit_graph_filenames_after`, `commit_graph_hash_after`) and replaces their use with local variables and string lists (`chain_hashes`, `kept`) that are populated by walking the commit-graph chain. The logic for renaming the base layer, updating mtimes, and expiring stale layers is now driven by the chain structure rather than caller-provided arrays. One behavioral change is noted: `expire_commit_graphs()` is now called only on success, whereas previously it ran unconditionally—this is framed as an improvement.

The patch is a mechanical refactor with no performance impact, but it simplifies the internal API by reducing the surface area of data the caller must provide. The new approach is more robust, as it avoids potential mismatches between the caller’s arrays and the actual chain state. The use of `string_list` for tracking kept filenames and chain hashes is a natural fit, though the patch does not yet move any logic into the "files" backend (that comes in later patches). The code is well-structured, with clear commit message explanations and no obvious regressions, though reviewers may question whether the new local variables (`base_rename_from`, `base_rename_to`) could be further encapsulated.

This patch is a prerequisite for the backend-specific work in later patches and aligns with the series’ goal of making commit-graph storage pluggable. It is unlikely to be controversial, but reviewers may ask for comments clarifying the new depth-based chain traversal or the rationale for deferring `expire_commit_graphs()` until success. The patch is authored by Patrick Steinhardt, a prolific contributor to the ODB abstraction effort, and builds on the prerequisite branch `ps/commit-graph-write-refactor`. No tests are added, as this is infrastructure-only.
