This is the seventh patch in Patrick Steinhardt’s 12-patch series introducing **pluggable commit graphs** as part of the **ODB abstraction** effort. It extracts the logic that checks whether writing a commit graph is allowed into a new helper function, `commit_graph_write_allowed()`, in preparation for moving the write logic into ODB backends in a later patch.

The change is a straightforward refactoring: the existing checks (for `core.commitGraph`, repository compatibility, and `commitGraph.changedPathsVersion`) are lifted out of `commit_graph_write()` and placed in the new function. The patch touches only `commit-graph.c` and `commit-graph.h`, adding the new function and updating the call site. No behavior changes are introduced—this is purely about code organization.

The motivation is clear: future ODB backends will need to perform the same checks, and duplicating this logic would be error-prone. The patch is well-motivated and aligns with the series’ goal of making commit-graph operations backend-agnostic. The commit message is concise but sufficient, and the code itself is clean and mechanical.

This is a minor but necessary step in the series. It doesn’t introduce new functionality or controversy, but it’s a prerequisite for the more invasive backend-splitting work that follows. Reviewers are unlikely to object to the change itself, though they may scrutinize how it’s used in later patches. The patch is part of a larger, well-structured effort, and its quality reflects that.
