This is a contributor housekeeping patch that aligns the naming of Git’s credential store lock timeout configuration with the established convention used by other lock-timeout settings. The patch introduces `credentialStore.lockTimeout` as the preferred key while keeping `credentialStore.lockTimeoutMS` as a deprecated alias for backward compatibility.

The change is purely mechanical and addresses Junio C Hamano’s earlier objection about inconsistent naming. The commit message now explicitly lists all existing lock-timeout variables (`rerere.lockTimeout`, `reftable.lockTimeout`, etc.) and confirms they are uniformly measured in milliseconds, resolving any ambiguity about unit conventions. The patch updates the documentation to reflect the new key and its deprecation notice, modifies the config lookup in `builtin/credential-store.c` to try the new key first, and adds comprehensive test coverage in `t/t0302-credential-store.sh`.

This v3 patch is ready for integration. It incorporates all prior feedback, including wrapping the config lookup line for readability and collapsing duplicated test cases into a single loop. The tests verify the new key works, the old key remains functional, precedence rules when both keys are set, and zero timeout behavior. The patch is uncontroversial and aligns with the project’s established patterns without altering behavior.
