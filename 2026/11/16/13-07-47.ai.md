This is the eleventh patch in Patrick Steinhardt’s 12-patch series introducing **pluggable commit graphs** for the ODB abstraction effort. It moves the logic that derives commit-graph paths from `commit-graph.c` into the "files" ODB backend (`odb/source-files.c`), a key step in decoupling commit-graph storage from the generic subsystem.

The patch is a **mechanical refactor**: 437 lines are removed from `commit-graph.c` and 428 are added to `odb/source-files.c`, with only minor adjustments (e.g., suppressing `-Wsign-compare` warnings). The moved functions include path helpers (`get_commit_graph_filename`, `get_split_graph_filename`, `get_commit_graph_chain_filename`), file operations (`open_commit_graph`, `open_commit_graph_chain`), and the core loading logic (`load_commit_graph_one`, `load_commit_graph_v1`, `load_commit_graph_chain`, `load_commit_graph_chain_fd_st`). The `read_commit_graph_one` function is also moved, though its declaration remains in `commit-graph.h` for now (to be removed in the next patch). The `commit_graph_write` function and its helpers (`mark_commit_graphs`, `expire_commit_graphs`) are relocated to the backend, completing the shift of all path-dependent logic.

No behavior changes are introduced; the patch is purely preparatory for the final patch in the series, which will refactor the moved code to use backend-specific paths. The diff is large but straightforward, with the author noting it is "mostly an exact move." The only functional difference is the suppression of sign-compare warnings, which does not affect runtime.

This patch is part of the **ODB abstraction** effort, specifically the goal of allowing alternative ODB backends to control commit-graph storage. By isolating path logic in the "files" backend, future backends (e.g., reftable) can implement their own storage schemes without being tied to filesystem conventions. The series is under review, with no merge status reported.

Key files touched: `commit-graph.c` (removals), `odb/source-files.c` (additions), and `commit-graph.h` (declarations retained temporarily). The next patch will clean up the remaining declarations and further refactor the moved code. The patch is well-motivated and aligns with the project’s long-term architectural goals, though its size may draw scrutiny during review.
