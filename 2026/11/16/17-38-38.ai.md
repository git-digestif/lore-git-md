This is a **bugfix** targeting the `index-pack` subsystem in partial clones. The author, לירון עדן, reports a regression in Git 2.56.0 where `git index-pack` incorrectly triggers a nested lazy fetch for `REF_DELTA` bases that are *already present* in the thin pack it is processing. The issue surfaces in blobless partial clones when the server does not support `OFS_DELTA` (simulated here by disabling `repack.useDeltaBaseOffset` on the client).

The bug is well-documented with a minimal reproduction script that sets up a server and client repository, forces `REF_DELTA` encoding, and demonstrates the redundant fetch via `GIT_TRACE2_EVENT` and `GIT_TRACE_PACKET` logs. The script shows that all 6 lazily fetched objects were already in the incoming pack, and the nested fetch spawns unnecessary processes (`fetch/index-pack/fetch/index-pack` etc.). In real-world scenarios (e.g., Azure DevOps), this can escalate to unbounded recursion, though commit `4360734e90` (merged October 2026) now caps nesting at 5 levels.

The root cause is identified in `fix_unresolved_deltas()` in `builtin/index-pack.c`: the prefetch loop iterates over *all* `REF_DELTA` entries, including those already resolved against in-pack bases, before checking their resolution status. The author suggests a fix (resolve locally available bases first, then prefetch only unresolved ones) but has not provided a patch. The issue affects `master`, `next`, and `seen` as of 2026-11-15.

Key technical details:
- **Files touched**: `builtin/index-pack.c` (specifically `fix_unresolved_deltas()`).
- **Subsystems**: `index-pack`, promisor-remote lazy fetching, partial clones.
- **Reproduction**: Requires blobless partial clone + thin pack + `REF_DELTA` (no `OFS_DELTA`).
- **Workaround**: Explicitly fetch the commit before checkout (avoids lazy fetch).
- **Related commit**: `4360734e90` (recursion cap, but doesn’t fix the redundant fetch).

The report is thorough, with clear steps, expected/actual behavior, and a real-world impact description. The issue is likely to affect users of partial clones with servers that don’t support `OFS_DELTA`. No prior discussion or patches are referenced in the email.
