This is a documentation patch that finalizes the standalone guide for Git’s detached HEAD state. The patch is the seventh iteration (v7) of a series that began with a rewrite of the explanation in `git-checkout.adoc` and has now evolved into a dedicated guide (`git help detached-head`) aimed at users who accidentally enter this state and feel confused.

The key change in v7 is the addition of a single sentence—**"You can also use this to make experimental commits without being on a branch."**—which explicitly highlights a practical use case for detached HEAD. This addresses Junio’s feedback that the guide should emphasize the "most important consequence" of this state, making it clear that detached HEAD isn’t just a source of confusion but also a useful tool for temporary work. The rest of the guide remains unchanged from v6, which was merged to `master` in July 2024.

The guide itself is well-structured and beginner-friendly, explaining what detached HEAD is, why it happens, how to avoid it accidentally (using `git switch` instead of `git checkout`), and how to recover from it. The framing that "Git considers commits that aren’t on a branch to be garbage" (borrowed from Steve Klabnik’s Jujutsu tutorial) is both memorable and technically accurate, helping users understand the risks without overcomplicating the explanation. The guide is dual-purpose: it serves as the DETACHED HEAD section in `git-checkout.adoc` while also functioning as a standalone reference (`gitdetached-head(7)`), accessible via `git help detached-head` or from Git’s advice messages when users detach accidentally.

The patch is purely organizational and clarifying, touching only documentation files (`detached-head.adoc`, `gitdetached-head.adoc`, `Makefile`, `meson.build`, and `advice.c`) and a test file (`t2020-checkout-detach.sh`) to verify the updated advice message. The changes are minimal and uncontroversial, reflecting the thread’s conclusion that the guide can now evolve independently as a "survival guide" for inexperienced users. No further revisions are expected, and the patch looks ready for merging. This is a thoughtful, user-centric improvement that directly addresses a common pain point for Git beginners.
