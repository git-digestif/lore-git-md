Subject: Regression in partial clones (blob:none) after ODB abstraction refactor
Series version: standalone bugfix (no versioning)
Originating author: Google (via Mergify, Remy Duthu)
Thread type: bug report with reproduction and proposed diagnostic, now with fix validation and confirmation

Core problem or goal
A regression in Git 2.54.0 causes partial clones with `blob:none` filters to attempt lazy-fetch of blobs that were just written locally during operations like cherry-pick or merge. The root cause is a visibility gap in the loose object cache introduced by commit `5946a564cd` ("odb/source: make `read_object_info()` function pluggable"), which stopped flushing the loose cache during lookups when `OBJECT_INFO_QUICK` is not set while continuing to flush the packfile store.

Current status
Fix validated and ready for review/merge. The proposed fix series (`20261104-pks-odb-loose-stale-cache-v1`)—specifically commit `a00d5cdb5e7d`—resolves the regression by adjusting loose cache flush logic in `odb/source-files.c`. The reporter (Google) confirmed the fix passes both the original reproduction script (cherry-pick in `elastic/fleet-server`) and an additional test case for merge operations. The regression bisects cleanly to `5946a564cd` (Git 2.54.0) and affects production workflows, making backporting to maintenance branches likely.

Key technical details
- **Files touched**: `odb/source-files.c` (`odb_source_files_read_object_info()`).
- **Symbols involved**: Existing flags (`OBJECT_INFO_QUICK`, `OBJECT_INFO_FOR_PREFETCH`) and functions (`odb_source_prepare()`, `ODB_PREPARE_FLUSH_CACHES`).
- **Subsystems**: ODB abstraction layer (Patrick Steinhardt’s series), partial clone (`blob:none` filter), promisor remote.
- **Behavior change**: Loose objects written after a directory scan (e.g., during merge/cherry-pick) are invisible to subsequent lookups without `OBJECT_INFO_QUICK`, causing Git to queue them for promisor fetch.
- **Test coverage**: Reproduction script provided; fix validated against cherry-pick and merge operations. No new test files added yet.

Open questions and loose ends
1. **Backporting**: The regression affects Git 2.54.0+; maintainers may need to backport the fix to `maint` branches once merged.
2. **ODB abstraction fallout**: This is the first reported bug from the ODB abstraction series; other edge cases may require review, though none are identified yet.
