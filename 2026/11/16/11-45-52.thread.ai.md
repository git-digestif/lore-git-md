Subject: Regression in partial clones (blob:none) after ODB abstraction refactor
Series version: standalone bugfix (no versioning)
Originating author: Google (via Mergify, Remy Duthu)
Thread type: bug report with reproduction and proposed diagnostic, now with fix validation

Core problem or goal
A regression in Git 2.54.0 causes partial clones with `blob:none` filters to attempt lazy-fetch of blobs that were just written locally during operations like cherry-pick. The root cause is a visibility gap in the loose object cache introduced by commit `5946a564cd` ("odb/source: make `read_object_info()` function pluggable"), which stopped flushing the loose cache during lookups when `OBJECT_INFO_QUICK` is not set while continuing to flush the packfile store.

Current status
Under review, with an in-flight fix series (`20261104-pks-odb-loose-stale-cache-v1`) targeting the regression. The fix (commit `a00d5cdb5e7d`) adjusts loose cache flush logic in `odb/source-files.c` and is awaiting validation from the reporter. The regression bisects cleanly to `5946a564cd` (Git 2.54.0) and affects production workflows (cherry-picks in partial clones). A reproduction script using GitHub’s `elastic/fleet-server` repo remains the primary test case.

Key technical details
- **Files touched**: `odb/source-files.c` (`odb_source_files_read_object_info()`).
- **New/renamed symbols**: None introduced; regression involves existing flags (`OBJECT_INFO_QUICK`, `OBJECT_INFO_FOR_PREFETCH`) and functions (`odb_source_prepare()`, `ODB_PREPARE_FLUSH_CACHES`).
- **Subsystems**: ODB abstraction layer (Patrick Steinhardt’s series), partial clone (`blob:none` filter), promisor remote.
- **Behavior change**: Loose objects written after a directory scan (e.g., during merge/cherry-pick) are invisible to subsequent `OBJECT_INFO_QUICK` lookups, causing Git to queue them for promisor fetch.
- **Test coverage**: Reproduction script provided; no new test files added yet. The fix series (`20261104-pks-odb-loose-stale-cache-v1`) is the reference for resolution.

Open questions and loose ends
1. **Fix validation**: Reporter (Google) needs to test the proposed fix (`a00d5cdb5e7d`) and confirm it resolves the cherry-pick failure in `blob:none` partial clones.
2. **Backporting**: The regression affects Git 2.54.0+; maintainers may need to backport the fix to `maint` branches once validated.
3. **ODB abstraction fallout**: This is the first reported bug from the ODB abstraction series; other edge cases may require review, though none are identified yet.
