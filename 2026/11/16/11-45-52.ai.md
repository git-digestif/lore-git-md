This is a **bugfix** targeting the object database (ODB) layer, specifically a regression in partial clones (`blob:none` filter) introduced by commit `5946a564cd` ("odb/source: make `read_object_info()` function pluggable") in Git 2.54.0. The issue causes Git to attempt a lazy-fetch for a blob that was just written locally during a cherry-pick, leading to a fatal error when the server (correctly) reports the object as unknown.

### Key details
The regression bisects cleanly to `5946a564cd`, which refactored `read_object_info()` to make it pluggable as part of Patrick Steinhardt’s ongoing ODB abstraction effort. The commit’s change inadvertently stopped flushing the *loose object cache* during lookups when `OBJECT_INFO_QUICK` is not set, while still flushing the packfile store. This creates a visibility gap: loose objects written after a directory scan (e.g., during a merge) remain invisible to subsequent `OBJECT_INFO_QUICK` lookups (like those in diff prefetch), causing Git to mistakenly treat them as missing and queue them for promisor fetch.

### Reproduction and impact
The provided reproduction script (using GitHub’s `elastic/fleet-server` repo) consistently triggers the bug on Git 2.54.0+ but succeeds on 2.53.0 and earlier. The failure occurs during commit summary printing after the cherry-pick completes, when Git tries to fetch a blob it just wrote locally. The author confirms this affects production workflows (cherry-picks in partial clones) across multiple repositories, forcing a rollback to Git 2.53.

### Technical context
- **Files touched**: The regression is in `odb/source-files.c`, specifically the `odb_source_files_read_object_info()` function.
- **Key names**: `OBJECT_INFO_QUICK`, `OBJECT_INFO_FOR_PREFETCH`, `odb_source_prepare()`, `ODB_PREPARE_FLUSH_CACHES`.
- **Related work**: This is part of the ODB abstraction series (Patrick Steinhardt), which aims to make object storage pluggable. The regression highlights a subtle interaction between loose object caching and the new pluggable read path.
- **Proposed fix direction**: The author’s diagnostic patch (not intended as a final fix) suggests flushing the loose cache alongside the packfile cache during retries, but notes that a better solution might involve updating the loose cache when objects are written.

### Likely discussion points
1. **Fix location**: Should the fix update the loose cache on write (more invasive) or flush it during lookups (simpler but potentially less efficient)?
2. **Backwards compatibility**: The regression affects partial clones, a feature increasingly used in large repositories. The fix may need to be backported to maintenance branches.
3. **ODB abstraction fallout**: This is the first reported bug from the ODB abstraction series, which has been in flight for months. It may prompt closer scrutiny of other edge cases in the new pluggable design.

The patch is well-motivated, with a clear reproduction case and a bisect pointing to the culprit commit. The author’s analysis is technically precise, and the issue is severe enough to block production use of Git 2.54+. Expect high-priority review from ODB maintainers (Patrick Steinhardt, Justin Tobler) and likely a quick fix.
