This is a **bugfix** for a long-standing segmentation fault in `for-each-ref` and `git refs list` when `--no-format` is used. The patch is now **reviewed and approved** by Patrick Steinhardt, a key contributor.

The fix moves the default format assignment to *after* command-line parsing, ensuring `--no-format` (which sets the format string to `NULL`) restores the default output instead of crashing. This aligns `for-each-ref` with `git branch` and `git tag`, which already behave this way. The change is minimal—just four lines of code in `builtin/for-each-ref.c`—and includes a new test in `t/for-each-ref-tests.sh` to verify the fix.

Patrick’s review confirms the approach is sound and consistent with the rest of Git’s ref-listing commands. The patch is effectively converged, with no open questions or objections. The crash has existed since 2007 (commit `c3428da87f`), and this fix resolves it cleanly. The only change in v2 was updating the Signed-off-by line to comply with the real-name policy.

Files touched: `builtin/for-each-ref.c` and `t/for-each-ref-tests.sh`. The patch is ready for integration.
