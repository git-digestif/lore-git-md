This is the eighth patch in Patrick Steinhardt’s 12-patch series introducing **pluggable commit graphs** as part of the **ODB abstraction** effort. The patch splits the monolithic `write_commit_graph_file()` function into two parts: `commit_graph_write_layer()`, which handles the generic task of writing a single commit-graph layer, and `commit_graph_write()`, which retains backend-specific responsibilities like file path management, locking, and cleanup.

The refactoring is mechanical but invasive: `write_commit_graph_file()` is reduced from ~200 lines to ~50, with the extracted `commit_graph_write_layer()` taking over the core writing logic (chunkfile setup, hash computation, and data serialization). The new `commit_graph_write()` function now orchestrates the backend-specific steps—creating temporary files, acquiring locks, and managing the commit-graph chain—while delegating the actual layer writing to `commit_graph_write_layer()`. The patch also introduces two new parameters to the layer-writing function: `mergeable_layers` and `chainable_layers`, which control how many topmost layers may be merged or used as a base, respectively. These counters were previously computed inside `write_commit_graph_file()` but are now passed in from the caller to decouple the generic writing logic from backend-specific layer selection.

Key technical details:
- **Files touched**: `commit-graph.c` (major refactoring) and `commit-graph.h` (new function declaration).
- **New symbols**: `commit_graph_write_layer()` (the extracted layer-writing function).
- **Behavior changes**: None; this is a pure refactoring. The split is designed to allow future ODB backends to reuse `commit_graph_write_layer()` while implementing their own file management logic in `commit_graph_write()`.
- **Structural changes**: The `write_commit_graph_context` struct loses its `dir` and `graph_name` fields, as these are now handled locally in `commit_graph_write()`. The context gains `mergeable_layers` and `chainable_layers` fields, which are populated by the caller and used to determine the base layer for the new graph.
- **Error handling**: The patch preserves the existing common exit path introduced in an earlier patch, ensuring that locks and temporary files are properly cleaned up on failure.

The patch is a clear step toward pluggability: by isolating the layer-writing logic, it enables alternative ODB backends to reuse the same serialization code while customizing how and where commit graphs are stored. The separation of concerns is clean, though the new `mergeable_layers` and `chainable_layers` parameters add some complexity to the interface. The patch does not introduce new tests, as it is part of an infrastructure-only series; testing will likely come in follow-up patches that exercise the pluggable backend hooks. The refactoring is well-motivated and aligns with the series’ goal of enabling backend-specific commit-graph storage.
