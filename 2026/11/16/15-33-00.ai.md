This is the final version of a documentation patch that introduces a new standalone guide (`git help detached-head`) explaining Git’s detached HEAD state. The patch is part of a long-running effort (v1–v7) to improve Git’s documentation for users who accidentally enter detached HEAD and are confused about their repository’s status. The v6 version was merged to `master` on 2024-07-10, and this v7 patch adds a single sentence—**"You can also use this to make experimental commits without being on a branch."**—to explicitly highlight the practical utility of detached HEAD for temporary work, addressing Junio’s feedback about the "most important consequence" of this state.

The guide is now dual-purpose: it serves as both a standalone survival guide for confused users (`git help detached-head`) and as the DETACHED HEAD section in `git-checkout.adoc`. The rewrite is concise, beginner-friendly, and avoids the overly technical diagrams of the original documentation. It explains what detached HEAD is, why it’s useful, how users might end up in this state (accidentally or intentionally), and how to return to a branch. The addition of the experimental-commits sentence makes the guide more actionable by showing users a concrete use case for detached HEAD.

The patch touches only documentation files (`detached-head.adoc`, `gitdetached-head.adoc`, `git-checkout.adoc`, and build system updates) and updates the advice message in `advice.c` to reference the new guide. The test suite is updated to reflect the new advice message. The changes are purely organizational and clarifying, with no impact on code behavior. The thread is conclusively closed, and this patch is ready for merging. It’s a well-motivated, user-centric improvement that directly addresses a common pain point for Git beginners.
