This is a performance and memory-usage improvement for the `git repo structure` command, now in its second iteration. The series targets the object-counting logic in `builtin/repo.c`, which previously parsed every object it encountered—an approach that becomes prohibitively expensive in repositories with tens of billions of tree entries. Patch 1 delays object parsing until it is actually needed, while patch 2 avoids full tree parsing when only the object type is required. The changes are confined to `builtin/repo.c` and introduce no new CLI options, config keys, or on-disk format changes.

The v2 update addresses the only substantive feedback from the initial review: a reworded comment in patch 1 now clarifies that `repo_parse_commit()` acts as a failsafe, framing it as a fallback rather than a dependency. The rest of the series remains unchanged. Benchmarking by both the author and Kristofer Karlsson confirms an 80% reduction in memory usage (5.1× less) and a 20% improvement in wall-clock time, though the command still cannot complete in the largest repositories due to the sheer volume of tree entries.

The series is now technically complete, with no open objections or unresolved feedback. It is ready for maintainer pickup and should be uncontroversial, given the clear performance gains and the absence of behavioral or interface changes. The only caveat is the inherent limitation of tree-walking in massive repositories, but that is acknowledged as a separate problem.
