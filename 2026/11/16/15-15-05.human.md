This is Junio’s biweekly "What’s cooking in git.git" report for November 2026, summarizing the current state of integration branches. It’s a high-level overview rather than a single patch, so the summary focuses on trends, notable graduations, and topics worth watching.

A steady stream of small fixes and cleanups graduated to `master` this cycle. Highlights include Christian Couder’s `cc/early-scan-options` series, which unified early command-line parsing across commands like `git fast-import`; Phillip Wood’s `pw/stash-change-check-only-once` optimization that eliminates redundant lstat calls in `git stash`; and Taylor Blau’s `tb/repack-cruft-less-midx-corner-cases` fixes for the cruft-less MIDX feature. These are all solid, well-tested improvements that address real performance or correctness issues—worth scanning if you maintain scripts or tools that interact with these commands.

On the documentation front, Jean-Noël Avila’s ongoing synopsis-style conversion continues to churn out small patches (`cu/doc-api-parse-options`, `dg/doc-gitcli-grammofix`), while Julia Evans’s rewrite of the `git diff` EXAMPLES section (`je/doc-git-diff-examples`) landed after several iterations. The latter is particularly useful for users; if you’ve ever struggled to remember the right incantation for comparing branches or commits, the new cheat-sheet format is a welcome change.

Several topics are cooking in `next` but not yet in `master`. The most substantial is Taylor Blau’s `tb/config-null-values` series (15 patches), which plugs NULL-pointer dereferences in config callbacks. It’s a cross-cutting fix that touches many commands, so if you’ve ever seen a segfault when a config key lacks an `=` sign, this is the fix. Another notable effort is Phillip Wood’s `ps/rerere-subcommands` refactor, which converts `git rerere` to use the standard `OPT_SUBCOMMAND()` API. This is a long-overdue cleanup that makes the command’s CLI behavior consistent with the rest of Git.

A few topics are still under active discussion and may need another iteration. Toon Claes’s `mv/log-follow-merge-opt-in` makes the expensive rename-following logic in `git log --follow` opt-in via `--follow=merges`, addressing a performance regression introduced by an earlier enhancement. The change is motivated by real-world slowdowns, but the configuration name and default behavior are still being debated. Similarly, Hariom Verma’s `hn/branch-delete-merged-squash` introduces `--delete-integrated` to find and remove branches whose work has been squash-merged, but the implementation’s reliance on blob comparison has raised questions about false positives.

The report also lists several topics marked as "Waiting for response" or "Needs review," such as Patrick Steinhardt’s `ps/repo-count-objects-speedup` and Christian Couder’s `cc/pack-index-v3` (part of the SHA-1/SHA-256 interoperability work). These are more specialized but could be worth tracking if you work with large repositories or care about hash migration.

Finally, Junio’s report includes a "Discarded" section with topics that were picked up prematurely or stalled. Most are niche or need significant rework, but `js/coverity-overflow-fixes` stands out—it addresses integer overflows reported by Coverity, and the feedback suggests it’s close to being ready. If you maintain a downstream fork, these fixes might be worth cherry-picking.

In short: this cycle is heavy on incremental improvements and cleanups, with a few larger efforts (like config NULL handling and `rerere` refactoring) nearing completion. The topics to watch are those addressing performance regressions (`log --follow`) and safety (`config-null-values`). If you’re a user, the `git diff` documentation rewrite is the most immediately useful change.
