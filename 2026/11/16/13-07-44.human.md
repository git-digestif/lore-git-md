This is the eighth patch in Patrick Steinhardt’s 12-patch series introducing **pluggable commit graphs** as part of the ongoing **ODB abstraction** effort. The patch splits the monolithic `write_commit_graph_file()` function into two distinct responsibilities: `commit_graph_write_layer()`, which writes the content of a new commit-graph layer, and `commit_graph_write()`, which handles backend-specific path management and file operations. This separation prepares the codebase for future backend-specific logic, where alternative ODB implementations will control where commit graphs are stored.

The refactoring is mechanical but invasive, touching only `commit-graph.c` and `commit-graph.h`. The new `commit_graph_write_layer()` function encapsulates the core logic for writing commit-graph data (fanout tables, commit data, bloom filters, etc.), while `commit_graph_write()` retains responsibility for file creation, locking, and cleanup. The patch also introduces a new public function signature for `commit_graph_write_layer()`, which takes explicit parameters for mergeable and chainable layers, a file descriptor, and a path, and returns the base layer and hash of the written graph. The `struct write_commit_graph_context` is slimmed down by removing fields (`dir`, `graph_name`) that are now handled locally in `commit_graph_write()`.

No user-facing behavior changes are introduced, and the on-disk format remains unchanged. The patch is well-motivated by the series’ goal of enabling pluggable ODB backends, and the separation of concerns is clean. The commit message clearly explains the rationale, and the code changes align with the broader ODB abstraction effort. This is a foundational refactor that will likely receive close scrutiny for correctness, but it looks like a necessary and well-structured step toward the series’ goals.
