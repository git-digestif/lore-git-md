This is a bugfix patch targeting the UTF-8 string width calculation in Git's display code.

The patch fixes a boundary-checking issue in `utf8_strnwidth()`, which currently can read past the specified length (`len`) when processing ANSI escape sequences. The function relies on `display_mode_esc_sequence_len()` to skip escape sequences, but that helper doesn't respect the caller's length constraint. The fix adds an explicit check after processing escape sequences to ensure the function stays within bounds.

The patch includes three new unit tests in `t/unit-tests/u-utf8-width.c` that verify corner cases with ANSI sequences and short length arguments. Two of these tests fail without the fix, demonstrating the bug's impact. The tests check scenarios where the requested length falls within an escape sequence, at its boundary, or just after it.

The change is minimal and focused: it modifies only the control flow in `utf8.c` to add the boundary check, without altering the core width calculation logic. The commit message clearly explains the problem and shows the test results before and after the fix.
