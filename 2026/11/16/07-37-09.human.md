This is the third patch in Adrian Ratiu’s three-part bugfix series for Git’s `compatObjectFormat` interoperability layer, and Patrick Steinhardt’s review here is substantive. The patch removes a 2023 safety check that rejected unknown commit headers during SHA-1 ↔ SHA-256 conversions, making Git copy them unchanged instead. This aligns the behavior of reading existing commits with that of creating new ones, fixing a real-world interoperability issue for tools like Jujutsu that rely on custom headers (e.g., `change-id`).

Patrick’s feedback focuses on two points. First, he notes that the patch now accepts malformed commit headers (e.g., `tree` without a trailing space or object ID), which Git previously rejected. While he acknowledges this is a minor edge case—since such commits are already corrupt—he suggests a stricter format check (e.g., requiring a space between header key and value) could prevent even more obviously invalid data from being copied. However, he concedes this might not be worth the added complexity. Second, he proposes a forward-looking idea: introducing a well-known header prefix (e.g., `x-obj-foobar`) to explicitly mark object IDs in custom headers, which would let Git convert them without needing to understand their purpose. This is framed as a separate effort, not a blocker for this patch.

The review is constructive and technical, but it does not challenge the core trade-off Adrian presents: consistency with external tools versus the safety of rejecting unrecognized headers. Patrick’s suggestions are refinements rather than objections, and he explicitly agrees with Adrian’s alternatives (e.g., rejecting unknown headers in both code paths or maintaining a allowlist) are impractical. The patch remains well-motivated and addresses a clear pain point, but the discussion around malformed headers and Patrick’s `x-obj-*` proposal could lead to follow-up work if reviewers push for stricter validation. For now, the patch looks like a reasonable fix, though its acceptance may hinge on whether the project is comfortable with the relaxed safety check.
