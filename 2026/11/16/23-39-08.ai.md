This is a contributor housekeeping patch that aligns the naming of Git’s credential-store lock timeout configuration with the established convention used by other lock-timeout settings. Junio C Hamano has now marked the patch as ready for the `next` branch after reviewing the v3 update, which addressed his earlier substantive objection by demonstrating that all existing lock-timeout variables are consistently measured in milliseconds and omit the unit from their names.

The patch introduces `credentialStore.lockTimeout` as the preferred key while retaining `credentialStore.lockTimeoutMS` as a deprecated alias for backward compatibility. The change is purely mechanical and does not alter behavior, touching only documentation, the credential-store builtin, and its test suite. The v3 update refined the commit message to explicitly enumerate the existing timeout variables (`rerere.lockTimeout`, `reftable.lockTimeout`, etc.) and clarify why the unit is omitted, resolving the ambiguity that previously blocked the patch.

With Junio’s explicit sign-off, the patch is now queued for integration testing in `next`. No substantive objections remain, and the patch is uncontroversial. It is part of a broader effort to standardize timeout variable naming across Git’s configuration system, following the precedent set by the recently merged `rerere.lockTimeout` patch.
