## 2026/11/17

- [2026/11/17/00-02-38 by Junio C Hamano <gitster@pobox.com>] Junio C Hamano argued that the blame in the utf8_strnwidth() bounds patch is slightly misplaced: the real defect is the missing guard before the utf8_width() call (the skip loop can consume the whole len region), not display_mode_esc_sequence_len() lacking an explicit boundary; he also noted that a boundary check after the skip loop is "too late" because reading string[len] at the end of an mmapped region could SIGBUS.

- [2026/11/17/16-18-56 by Junio C Hamano <gitster@pobox.com>] Junio C Hamano posted an illustration patch (not compile-tested) changing display_mode_esc_sequence_len() to take a length limit so it never reads s[len] or beyond, with fallout updates to callers in pretty.c, utf8.c (utf8_strnwidth, strbuf_add_wrapped_text, strbuf_utf8_replace) and utf8.h; he noted this does not make Dirk's guard-before-utf8_width() change unnecessary.
- [2026/11/17/17-57-08 by Dirk Gouders <dirk@gouders.net>] Dirk Gouders said his planned v2 would instead have introduced two new functions, ansi_sgr_nlen() and ansi_sgr_nlen_multi() (the latter eating all leading SGR sequences so callers need no loop), to replace display_mode_esc_sequence_len(), but accepted that Junio's posted patch is also fine.
- [2026/11/17/18-11-31 by Junio C Hamano <gitster@pobox.com>] Junio C Hamano endorsed the two-function arrangement for maintainability and proposed adding display_mode_esc_sequence_len_counted() with a counted-string API while keeping display_mode_esc_sequence_len() on the original NUL-terminated convention, since other proposed topics would add more callers to the function.
