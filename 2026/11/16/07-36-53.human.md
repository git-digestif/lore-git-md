This is a surface-level review of the first patch in Adrian Ratiu’s three-patch series fixing bugs in Git’s `compatObjectFormat` interoperability layer. The patch itself remains uncontroversial and well-justified—it prevents a crash when `extensions.compatObjectFormat` is set to the same hash algorithm as the repository’s `objectFormat`—but Patrick Steinhardt raises two minor, user-facing issues.

First, he points out that the error message should use the correct capitalization (`compatObjectFormat` instead of `compatobjectformat`) to match the config key users see. Second, he suggests modernizing the test script by replacing the older `git config --file=... --unset` syntax with the simpler `git config unset` command, and notes that if this change is made, the test should also update the earlier `git config set` calls for consistency. Neither comment questions the substance of the fix; both are purely about presentation and test hygiene. The patch is still on track to be accepted once these nits are addressed.
