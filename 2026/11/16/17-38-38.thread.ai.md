Subject: `index-pack` regression in Git 2.56.0: redundant lazy fetch for in-pack `REF_DELTA` bases
Series version: none (standalone bug report)
Originating author: לירון עדן
Thread type: bug report

Core problem or goal
A regression in Git 2.56.0 causes `git index-pack` to trigger unnecessary nested lazy fetches for `REF_DELTA` bases that are already present in the thin pack being processed. The bug affects blobless partial clones when the server does not support `OFS_DELTA`, leading to redundant network round-trips and, in extreme cases, unbounded recursion (mitigated by a 5-level cap introduced in commit `4360734e90`).

Current status
Under review. The issue is confirmed to exist in `master`, `next`, and `seen` as of 2026-11-15. No patch has been posted yet; the author has identified the root cause in `fix_unresolved_deltas()` in `builtin/index-pack.c` and proposed a conceptual fix (resolve locally available bases first, then prefetch only unresolved ones).

Key technical details
- **Files touched**: `builtin/index-pack.c` (function `fix_unresolved_deltas()`).
- **Subsystems**: `index-pack`, promisor-remote lazy fetching, partial clones.
- **New/renamed symbols**: none.
- **Behavior change**: `index-pack` now incorrectly prefetches `REF_DELTA` bases that are already in the incoming pack, causing redundant lazy fetches.
- **On-disk format**: unchanged.
- **Test coverage**: minimal reproduction script provided in the report; no formal test case yet.
- **Reproduction requirements**: blobless partial clone + thin pack + `REF_DELTA` (no `OFS_DELTA`).
- **Workaround**: explicitly fetch the commit before checkout to avoid lazy fetch.
- **Related commit**: `4360734e90` (merged October 2026) caps recursion at 5 levels but does not eliminate the redundant fetch.
