Thread identity: Subject: [PATCH 0/2] utf8.c: fix bounds handling and documentation in utf8_strnwidth(). Series version: v1 under review; v2 in preparation by author. Originating author: Dirk Gouders. Thread type: bugfix patch series.

Core problem or goal: Fix two distinct issues in Git's UTF-8 handling code in `utf8.c`: (1) `utf8_strnwidth()` ignores its `len` argument when processing valid UTF-8, potentially reading beyond the intended bounds, and (2) the function's documentation incorrectly claims it returns `strlen()` in certain cases, whereas the code actually returns the `len` argument.

Current status: Under review. v1 remains the current posted version. Dirk Gouders has conceded Junio C Hamano's substantive technical concerns and is preparing a v2 that addresses the bounds-handling fix and the mmapped-region memory-safety edge case. Junio C Hamano has now posted an illustrative patch demonstrating one approach to threading the length boundary through `display_mode_esc_sequence_len()`, though he notes it is not compile-tested.

Key technical details: Files touched: `utf8.c`, `utf8.h`, `pretty.c`, new unit test `t/unit-tests/u-utf8-width.c`. Symbols: `utf8_strnwidth()` (function behavior and documentation corrected), `display_mode_esc_sequence_len()` (signature gains `size_t len` parameter in Junio's illustrative patch), `utf8_width()`, `format_and_pad_commit()`, `strbuf_add_wrapped_text()`, `strbuf_utf8_replace()`. On-disk format: no changes. Test coverage: new unit test verifies bounds-respecting behavior. Memory-safety concern: if `string` points to the end of an mmapped region, reading beyond `len` could trigger a `SIGBUS` before the proposed check is reached; Gouders agrees this makes the v1 fix "too late" in that scenario and plans to address it in v2. Junio's illustrative patch inserts `end <= p` guards throughout the escape-sequence parser to prevent reads past `s + len`, updates four call sites to pass the remaining byte count, and explicitly does not eliminate the need for the separate guard after the ANSI-skipping loop inside `utf8_strnwidth()`.

Open questions and loose ends: v2 respin expected to address: (a) placing the boundary guard after the ANSI-escape-skipping loop rather than relying solely on `display_mode_esc_sequence_len()`, and (b) the SIGBUS risk when `string` points to the end of an mmapped region. Junio's illustrative patch offers one mechanism for (a) by making `display_mode_esc_sequence_len()` length-aware, but the separate post-loop guard remains necessary per Junio. No final decision on which approach v2 will take; thread awaits Dirk Gouders's v2.
