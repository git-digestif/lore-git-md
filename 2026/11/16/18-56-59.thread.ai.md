Thread identity: Subject: [PATCH v4 0/5] utf8.c: fix bounds handling and documentation in utf8_strnwidth() and utf8_width(). Series version: v4 (five patches), reposted by Dirk Gouders to replace the retracted v3. Originating author: Dirk Gouders, with patch 1 authored by Junio C Hamano. Thread type: bugfix patch series.

Core problem or goal: Fix bounds handling in Git's UTF-8 display-width code so that utf8_strnwidth() and utf8_width() respect their length arguments and do not read past the end of the input buffer, including the mmapped-region SIGBUS edge case; additionally correct the misleading documentation on utf8_strnwidth().

Current status: v4 has been posted as a corrected, un-squashed repost of the withdrawn v3. The end-pointer design settled in v3 is preserved, with v3's patch 4 split into v4 patch 4 (utf8_strnwidth() boundary fixes using a remainder parameter) and patch 5 (the new display_mode_esc_sequence_len_all() helper and call-site updates). The series is under review and now has a concrete blocker: as posted, patch 4/5 fails to build because the variable `skip` is undeclared. No version of the series has been merged or queued in any integration branch.

Key technical details: Files touched: utf8.c, utf8.h, pretty.c, Makefile, t/meson.build, new unit tests t/unit-tests/u-utf8-ansi.c and t/unit-tests/u-utf8-width.c (wired into both Makefile and t/meson.build, ordered u-utf8-ansi.c before u-utf8-width.c). Symbols: utf8_strnwidth(), utf8_width(), display_mode_esc_sequence_len(const char *start, const char *end) (patch 1, authored by Junio C Hamano), which scans for an SGR sequence without reading at or beyond end and returns 0 if the buffer ends before a complete sequence or if start/end are swapped; a NULL end preserves the old NUL-terminated behavior; and display_mode_esc_sequence_len_all(const char *start, const char *end) (patch 5), which greedily consumes all consecutive leading ANSI SGR sequences up to end by repeatedly calling display_mode_esc_sequence_len() until no further sequence is found, returning the total consumed length. The v2 display_mode_esc_sequence_len_counted() and the old NUL-terminated wrapper were both removed. The API design for bounded versus unbounded scanning has been settled with an important correction: callers use the end pointer for bounded scanning, but they must not construct end as s + SIZE_MAX, because that pointer arithmetic would overflow and be undefined behavior; every actual call site knows a valid remaining buffer length, so no call site needs a strlen()-based fallback, and display_mode_esc_sequence_len() keeps the signature (const char *start, const char *end) without a size_t *remainder out-parameter. Call sites in patch 1 use the end-pointer form: utf8_strnwidth() passes string + len, strbuf_utf8_replace() passes its existing end variable, strbuf_add_wrapped_text() computes end = text + strlen(text) upfront, and pretty.c passes ch + 1 in format_and_pad_commit(). Patch 3 modified utf8_strnwidth() to add if (string >= end) break; after the ANSI-skipping loop and before calling utf8_width(), preventing a read past the end boundary when an escape sequence ends exactly at or beyond the given length. Patch 4 modified utf8_strnwidth() to compute remainder = end - string before each utf8_width() call and pass &remainder instead of NULL, with a guard against advancing beyond orig + len in the ANSI-skipping loop, ensuring utf8_width() respects the same bound as the outer loop when a CJK or other multibyte character is chopped by the len argument; as posted, patch 4/5 does not compile because the variable `skip` is undeclared. Patch 5 switched the ANSI-skipping loops in utf8_strnwidth(), strbuf_add_wrapped_text(), and strbuf_utf8_replace() to use display_mode_esc_sequence_len_all(), replacing three manual while loops that previously called display_mode_esc_sequence_len() individually so that each call site now advances by the full greedy result in a single step. Patch 2 (v4 2/5) was a documentation-only correction to the comment above utf8_strnwidth() changing the description from "null-terminated string" to "string terminated by len" and fixing the claimed return value for invalid UTF-8 from strlen() to the len argument, matching the function's actual signature and behavior; it touches only comment lines with no code or behavior change. Patch 1 added unit tests in t/unit-tests/u-utf8-ansi.c: test_utf8_ansi__sgr_len_null (NUL-terminated strings), test_utf8_ansi__sgr_len_end_ptr (bounded buffers including truncated sequences), and test_utf8_ansi__sgr_len_start_end_swap (swapped pointers return 0). Patch 3 added unit test test_utf8_width__strnwidth_ansi in t/unit-tests/u-utf8-width.c covering cases such as utf8_strnwidth("\033[31mhello", 4, 1) returning 3, len 5 returning 0, and len 6 returning 1. Patch 4 added unit test test_utf8_width__strnwidth_cjk_chopped in t/unit-tests/u-utf8-width.c verifying that utf8_strnwidth("三bytes long, 二columns wide", 1, 1) returns 1 and that utf8_strnwidth(..., 3, 1) returns 2, confirming that chopped multibyte sequences no longer cause out-of-bounds reads. Patch 5 added unit test test_utf8_ansi__sgr_len_greedy in t/unit-tests/u-utf8-ansi.c covering cases with no sequences, single sequences, multiple consecutive sequences, and truncated buffers. Andy Koppe's review of patch v4 1/5 suggests simplifying the bounds checks in display_mode_esc_sequence_len() by collapsing the digit/semicolon scanning loop to `while (!(end && p >= end) && (isdigit(*p) || *p == ';'))` and the final check to `if ((end && p >= end) || *p++ != 'm')`, removing redundant end guards. On-disk format: no changes.

Open questions and loose ends: The v4 repost resolves the immediate question of how to re-present the series after the v3 retraction; the end-pointer design is carried forward unchanged in substance. The API design question of whether display_mode_esc_sequence_len() should grow a size_t *remainder out-parameter has been closed: Junio C Hamano endorsed Andy Koppe's argument against an unnecessary out-parameter, and Andy Koppe further clarified that unbounded scanning cannot be expressed by end = s + SIZE_MAX because that pointer arithmetic is undefined behavior; since no real call site lacks knowledge of the remaining buffer length, the function signature remains (const char *start, const char *end) without a remainder out-parameter. Andy Koppe's review raises two open items: (1) a build blocker -- patch 4/5 as posted fails to compile because the variable `skip` is undeclared, which must be fixed before the series can be considered; (2) a scope question -- whether the new display_mode_esc_sequence_len_all() helper (patch 5) is needed at all, with Koppe recommending the series concentrate on three items: the utf8_strnwidth() comment fix, the optional end pointer for display_mode_esc_sequence_len() with caller updates, and the end guard plus bounded utf8_width() call inside utf8_strnwidth(). Koppe also notes in his patch 1 review that while standard functions like strncmp() and strnlen() accept SIZE_MAX as a length bound, computing an end pointer as start + SIZE_MAX remains undefined behavior, and the correct alternative with a length parameter is bounds checking via subtraction (p - start < len) before dereferencing. The split of the former v3 patch 4 into v4 patches 4 and 5 also remains unreviewed on its merits. In his latest review of the patch 1 unit tests in t/unit-tests/u-utf8-ansi.c, Koppe identified two additional test-only correctness issues: passing two different string literals as start and end compares pointers to different objects (undefined behavior in C even if compilers often optimize them to the same address), and using sizeof(sgr_3) and sizeof(sgr_4) yields the pointer size (8 bytes on 64-bit) rather than the string length, making the computed end pointers incorrect and causing line-length violations; these are nits that do not affect the core logic but should be fixed before the series advances. No outstanding technical objections remain from prior versions other than the items above.
