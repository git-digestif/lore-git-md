Thread identity: Subject: [PATCH v2 0/4] utf8.c: fix bounds handling and documentation in utf8_strnwidth() and utf8_width(). Series version: v2 (four patches) under review; expanded from v1's two patches. Originating author: Dirk Gouders, with patch 1 authored by Junio C Hamano. Thread type: bugfix patch series.

Core problem or goal: Fix bounds handling in Git's UTF-8 display-width code so that `utf8_strnwidth()` and `utf8_width()` respect their length arguments and do not read past the end of the input buffer, including the mmapped-region SIGBUS edge case; additionally correct the misleading documentation on `utf8_strnwidth()`.

Current status: Under review. v2 is the current posted version. The technical direction for all four patches is settled: patch 1 will use the v1 form (counted variant only, no NUL-terminated wrapper), patch 2 is documentation-only, and patches 3 and 4 have no remaining technical objections. Dirk Gouders has confirmed that dropping the `display_mode_esc_sequence_len()` wrapper and switching its sole remaining caller in `pretty.c` to `display_mode_esc_sequence_len_counted()` directly is exactly what Junio C Hamano's v1 already contained, so patch 1 of v2 will effectively revert to that approach. No v3 has been posted yet; only surface-level items remain outstanding.

Key technical details: Files touched: `utf8.c`, `utf8.h`, `t/meson.build`, new unit tests `t/unit-tests/u-utf8-ansi.c` and `t/unit-tests/u-utf8-width.c` (wired into both `Makefile` and `t/meson.build`). Symbols: `utf8_strnwidth()`, `utf8_width()`, `display_mode_esc_sequence_len()` (NUL-terminated wrapper retained in v2 patch 1 but confirmed for removal in the next version, reverting to v1's approach where only the counted variant exists), new `display_mode_esc_sequence_len_counted(const char *s, size_t len)` (patch 1, authored by Junio C Hamano) which scans for an SGR sequence without reading at or beyond `s[len]` and returns 0 if the buffer ends before a complete sequence. Three call sites use the counted variant: `utf8_strnwidth()` passes remaining length (`orig + len - string`), `strbuf_utf8_replace()` uses `end - src`, and `strbuf_add_wrapped_text()` computes `end = text + strlen(text)` upfront and passes `end - text` per iteration; the remaining wrapper call site in `pretty.c` will switch to the counted variant. Patch 3 modifies `utf8_strnwidth()` to use the counted variant in its ANSI-skipping loop and adds a guard ensuring the pointer does not advance beyond `orig + len` before calling `utf8_width()`, addressing both the original bounds bug and the mmapped SIGBUS scenario. Patch 4 modifies `utf8_strnwidth()` to compute `remainder = orig + len - string` before each `utf8_width()` call and pass `&remainder` instead of NULL, ensuring the width calculation respects the caller-supplied length; patch 4 also adds unit test `test_utf8_width__strnwidth_cjk_chopped` in `t/unit-tests/u-utf8-width.c` verifying correct behavior when CJK characters are truncated by the `len` argument. Patch 2 is a documentation-only correction to the comment block above `utf8_strnwidth()` changing the invalid-UTF-8 return claim from `strlen()` to the `len` argument. On-disk format: no changes.

Open questions and loose ends: All substantive technical questions are resolved. The wrapper-removal design question is closed: Dirk Gouders has confirmed patch 1 will revert to Junio's v1 form (counted variant only, no wrapper). Dirk Gouders had proposed that `display_mode_esc_sequence_len_counted()` accept `size_t *len` rather than `size_t len` (NULL for NUL-terminated scanning, non-NULL for bounded scanning with remainder update), modeled on `utf8_width()`'s optional remainder parameter; Andy Koppe has now explicitly rejected this remainder-based compromise, arguing that callers wanting unbounded scanning can simply pass `SIZE_MAX` as the length, and since the function returns consumed bytes, callers can subtract that from their own known length to obtain the remainder without an out-parameter, keeping the API simpler and avoiding the `strlen()` quadratic cost. This rationale is now on record should future discussion reference the `SIZE_MAX` sentinel approach or the remainder-parameter alternative. Andy Koppe's postscript suggestion to drop the `_counted` suffix by folding `len` directly into `display_mode_esc_sequence_len()` is noted but not acted on. Outstanding items are surface-level only: (1) Junio C Hamano's two formatting nits on patch 3 (excess space in `if (skip_ansi )` and overlong while-loop condition line wrapping). (2) Andy Koppe's documentation nit on patch 2 that the comment still describes the input as "null-terminated" despite the explicit `len` parameter; Dirk Gouders has confirmed he will remove this phrasing. (3) The meson ordering nit on patch 1 (`u-utf8-ansi.c` listed after `u-utf8-width.c` in `t/meson.build`'s `clar_test_suites`), confirmed by Dirk Gouders as a v3 fixup. Patch 4 has been approved with no changes requested. The series awaits a possible v3 or integration.
