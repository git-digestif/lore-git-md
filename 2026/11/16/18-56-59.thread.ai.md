Thread identity: Subject: [PATCH v2 0/4] utf8.c: fix bounds handling and documentation in utf8_strnwidth() and utf8_width(). Series version: v2 (four patches) under review; expanded from v1's two patches. Originating author: Dirk Gouders, with patch 1 authored by Junio C Hamano. Thread type: bugfix patch series.

Core problem or goal: Fix bounds handling in Git's UTF-8 display-width code so that `utf8_strnwidth()` and `utf8_width()` respect their length arguments and do not read past the end of the input buffer, including the mmapped-region SIGBUS edge case; additionally correct the misleading documentation on `utf8_strnwidth()`.

Current status: Under review. v2 is now the current posted version. It incorporates Junio C Hamano's proposed `display_mode_esc_sequence_len_counted()` as patch 1, retains the v1 documentation fix as patch 2, applies the counted variant plus a post-loop guard inside `utf8_strnwidth()` as patch 3, and adds a new patch 4 extending the same boundary-respecting treatment to `utf8_width()`.

Key technical details: Files touched: `utf8.c`, `utf8.h`, new unit tests `t/unit-tests/u-utf8-ansi.c` and `t/unit-tests/u-utf8-width.c` (wired into both `Makefile` and `t/meson.build`). Symbols: `utf8_strnwidth()`, `utf8_width()`, `display_mode_esc_sequence_len()` (retained as NUL-terminated wrapper calling the counted variant with `strlen(s)`), new `display_mode_esc_sequence_len_counted(const char *s, size_t len)` (patch 1, authored by Junio C Hamano) which scans for an SGR sequence without reading at or beyond `s[len]` and returns 0 if the buffer ends before a complete sequence. Three call sites use the counted variant: `utf8_strnwidth()` passes remaining length (`orig + len - string`), `strbuf_utf8_replace()` uses `end - src`, and `strbuf_add_wrapped_text()` computes `end = text + strlen(text)` upfront and passes `end - text` per iteration. Patch 3 modifies `utf8_strnwidth()` to use the counted variant in its ANSI-skipping loop and adds a guard ensuring the pointer does not advance beyond `orig + len` before calling `utf8_width()`, addressing both the original bounds bug and the mmapped SIGBUS scenario. Patch 4 applies analogous boundary checks to `utf8_width()`. Patch 2 is a documentation-only correction to the comment block above `utf8_strnwidth()`: it changes the claim that the function returns `strlen()` when the input is not valid UTF-8 to correctly state that it returns the `len` argument; purely cosmetic, no behavior change. On-disk format: no changes. Test coverage: `u-utf8-ansi.c` tests the counted escape-sequence function including truncated sequences like `"\033[m"` with insufficient length; `u-utf8-width.c` tests `utf8_strnwidth()` and `utf8_width()` corner cases. One v2 test correction: the escape sequence `"\033"` has display width 0, so the expected sum for a truncated string is 3, not 4.

Open questions and loose ends: The previously open items -- post-loop guard placement and the mmapped-region SIGBUS risk -- are now addressed in v2 patch 3. The series awaits further review of v2.
