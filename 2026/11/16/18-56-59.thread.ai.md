Thread identity: Subject: [PATCH v3 0/4] utf8.c: fix bounds handling and documentation in utf8_strnwidth() and utf8_width(). Series version: v3 (four patches) under review; expanded from v2's counted-length API to an end-pointer design. Originating author: Dirk Gouders, with patch 1 authored by Junio C Hamano. Thread type: bugfix patch series.

Core problem or goal: Fix bounds handling in Git's UTF-8 display-width code so that `utf8_strnwidth()` and `utf8_width()` respect their length arguments and do not read past the end of the input buffer, including the mmapped-region SIGBUS edge case; additionally correct the misleading documentation on `utf8_strnwidth()`.

Current status: Under review. v3 is the current posted version. The technical direction for all four patches is settled on the end-pointer design: patch 1 replaces the v2 approach (`display_mode_esc_sequence_len_counted(const char *s, size_t len)` plus a retained NUL-terminated wrapper) with a single `display_mode_esc_sequence_len(const char *s, const char *end)` that takes an end pointer rather than a length, eliminating the `strlen()` call inside the old wrapper and avoiding the O(n^2) degradation Andy Koppe had flagged; the sole remaining caller in `pretty.c` switches to passing an explicit end pointer directly. v3 also addresses previously noted surface nits such as meson test-suite ordering, stray whitespace, and the "null-terminated" documentation wording. No v4 has been posted yet.

Key technical details: Files touched: `utf8.c`, `utf8.h`, `pretty.c`, `Makefile`, `t/meson.build`, new unit tests `t/unit-tests/u-utf8-ansi.c` and `t/unit-tests/u-utf8-width.c` (wired into both `Makefile` and `t/meson.build`, now ordered with `u-utf8-ansi.c` before `u-utf8-width.c`). Symbols: `utf8_strnwidth()`, `utf8_width()`, and `display_mode_esc_sequence_len(const char *s, const char *end)` (patch 1, authored by Junio C Hamano), which scans for an SGR sequence without reading at or beyond `end` and returns 0 if the buffer ends before a complete sequence; the v2 `display_mode_esc_sequence_len_counted()` and the old NUL-terminated wrapper are both removed in v3. Call sites use the end-pointer form: `utf8_strnwidth()` passes `orig + len`, `strbuf_utf8_replace()` passes `end`, `strbuf_add_wrapped_text()` computes `end = text + strlen(text)` upfront and passes `end`, and `pretty.c` passes an explicit end pointer. Patch 3 modifies `utf8_strnwidth()` to use the end-pointer variant in its ANSI-skipping loop and adds a guard ensuring the pointer does not advance beyond `orig + len` before calling `utf8_width()`, addressing both the original bounds bug and the mmapped SIGBUS scenario. Patch 4 modifies `utf8_strnwidth()` to compute `remainder = orig + len - string` before each `utf8_width()` call and pass `&remainder` instead of NULL, ensuring the width calculation respects the caller-supplied length; patch 4 also adds unit test `test_utf8_width__strnwidth_cjk_chopped` in `t/unit-tests/u-utf8-width.c` verifying correct behavior when CJK characters are truncated by the `len` argument. Patch 2 is a documentation-only correction to the comment block above `utf8_strnwidth()` changing the invalid-UTF-8 return claim from `strlen()` to the `len` argument and removing the "null-terminated" phrasing. On-disk format: no changes.

Open questions and loose ends: All substantive technical questions are resolved with the end-pointer API in v3; the earlier wrapper-removal and remainder-parameter debates are closed by this design. Previously noted surface nits -- meson test-suite ordering, excess whitespace in patch 3, and the "null-terminated" comment wording in patch 2 -- are addressed in v3.
