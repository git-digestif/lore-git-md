Core problem or goal: Fix bounds handling in Git's UTF-8 display-width code so that utf8_strnwidth() and utf8_width() respect their length arguments and do not read past the end of the input buffer, including the mmapped-region SIGBUS edge case; additionally correct the misleading documentation on utf8_strnwidth().

Key technical details: Files touched: utf8.c, utf8.h, pretty.c, Makefile, t/meson.build, new unit tests t/unit-tests/u-utf8-ansi.c and t/unit-tests/u-utf8-width.c wired into both Makefile and t/meson.build, ordered u-utf8-ansi.c before u-utf8-width.c. Symbols: utf8_strnwidth(), utf8_width(), display_mode_esc_sequence_len(const char *start, const char *end) (patch 1, authored by Junio C Hamano), which scans for an SGR sequence without reading at or beyond end and returns 0 if the buffer ends before a complete sequence or if start/end are swapped; a NULL end preserves the old NUL-terminated behavior; and display_mode_esc_sequence_len_all(const char *start, const char *end) (patch 5), which would greedily consume all consecutive leading ANSI SGR sequences up to end by repeatedly calling display_mode_esc_sequence_len(), but is now agreed to be dropped. The v2 display_mode_esc_sequence_len_counted() and the old NUL-terminated wrapper were both removed. The API design is settled: callers use the end pointer for bounded scanning, but must not construct end as s + SIZE_MAX because that pointer arithmetic would overflow and be undefined behavior; every actual call site knows a valid remaining buffer length, so no call site needs a strlen()-based fallback, and display_mode_esc_sequence_len() keeps the signature (const char *start, const char *end) without a size_t *remainder out-parameter. Andy Koppe's suggested simplification of the bounds checks in display_mode_esc_sequence_len(), now agreed to by Gouders, replaces the current loop and final check with `while (!(end && p >= end) && (isdigit(*p) || *p == ';'))` and `if ((end && p >= end) || *p++ != 'm')`. Call sites in patch 1 use the end-pointer form: utf8_strnwidth() passes string + len, strbuf_utf8_replace() passes its existing end variable, strbuf_add_wrapped_text() computes end = text + strlen(text) upfront, and pretty.c passes ch + 1 in format_and_pad_commit(). Patch 3 modified utf8_strnwidth() to add if (string >= end) break; after the ANSI-skipping loop and before calling utf8_width(), preventing a read past the end boundary when an escape sequence ends exactly at or beyond the given length. Patch 4 modified utf8_strnwidth() to compute remainder = end - string before each utf8_width() call and pass &remainder instead of NULL, with a guard against advancing beyond orig + len in the ANSI-skipping loop, ensuring utf8_width() respects the same bound when a CJK or other multibyte character is chopped by len; as posted, patch 4/5 does not compile because `skip` is undeclared, now acknowledged by Gouders as fixed in his working copy. Patch 5 would have switched the ANSI-skipping loops in utf8_strnwidth(), strbuf_add_wrapped_text(), and strbuf_utf8_replace() to display_mode_esc_sequence_len_all(), replacing three manual while loops; Gouders has now agreed to remove it. Patch 2 was documentation-only, changing the utf8_strnwidth() comment from null-terminated string to string terminated by len and fixing the claimed invalid-UTF-8 return from strlen() to len. Patch 1 added tests in t/unit-tests/u-utf8-ansi.c: test_utf8_ansi__sgr_len_null, test_utf8_ansi__sgr_len_end_ptr, and test_utf8_ansi__sgr_len_start_end_swap. Patch 3 added test_utf8_width__strnwidth_ansi in t/unit-tests/u-utf8-width.c covering bounded ANSI cases. Patch 4 added test_utf8_width__strnwidth_cjk_chopped verifying chopped multibyte sequences no longer cause out-of-bounds reads. Patch 5 would have added test_utf8_ansi__sgr_len_greedy, now moot if the helper is dropped. On-disk format: no changes.
