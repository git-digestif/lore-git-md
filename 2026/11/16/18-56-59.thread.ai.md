Core problem or goal: Fix bounds handling in Git's UTF-8 display-width code so that `utf8_strnwidth()` and `utf8_width()` respect their length arguments and do not read past the end of the input buffer, including the mmapped-region SIGBUS edge case; additionally correct the misleading documentation on `utf8_strnwidth()`.

Current status: v4 has been posted as a corrected, un-squashed repost of the withdrawn v3. The end-pointer design settled in v3 is preserved, with v3's patch 4 split into v4 patch 4 (`utf8_strnwidth()` boundary fixes using a `remainder` parameter) and patch 5 (the new `display_mode_esc_sequence_len_all()` helper and call-site updates). v4 2/5 is a documentation-only patch correcting the comment above `utf8_strnwidth()`. v4 3/5 adds a bounds check in `utf8_strnwidth()` to break out of the loop when ANSI escape skipping consumes the entire remaining bounded string. The series is under review awaiting substantive feedback on the v4 formulation. No version of the series has been merged or queued in any integration branch.

Key technical details: Files touched: `utf8.c`, `utf8.h`, `pretty.c`, `Makefile`, `t/meson.build`, new unit tests `t/unit-tests/u-utf8-ansi.c` and `t/unit-tests/u-utf8-width.c` (wired into both `Makefile` and `t/meson.build`, ordered `u-utf8-ansi.c` before `u-utf8-width.c`). Symbols: `utf8_strnwidth()`, `utf8_width()`, `display_mode_esc_sequence_len(const char *start, const char *end)` (patch 1, authored by Junio C Hamano), which scans for an SGR sequence without reading at or beyond `end` and returns 0 if the buffer ends before a complete sequence or if start/end are swapped; a NULL `end` preserves the old NUL-terminated behavior; and `display_mode_esc_sequence_len_all(const char *start, const char *end)` (patch 5), which greedily consumes all consecutive leading ANSI SGR sequences up to `end`. The v2 `display_mode_esc_sequence_len_counted()` and the old NUL-terminated wrapper were both removed. Call sites in patch 1 use the end-pointer form: `utf8_strnwidth()` passes `string + len`, `strbuf_utf8_replace()` passes its existing `end` variable, `strbuf_add_wrapped_text()` computes `end = text + strlen(text)` upfront, and `pretty.c` passes `ch + 1` in `format_and_pad_commit()`. Patch 3 modified `utf8_strnwidth()` to add `if (string >= end) break;` after the ANSI-skipping loop and before calling `utf8_width()`, preventing a read past the `end` boundary when an escape sequence ends exactly at or beyond the given length. Patch 4 modified `utf8_strnwidth()` to compute `remainder = orig + len - string` before each `utf8_width()` call and pass `&remainder` instead of NULL, with a guard against advancing beyond `orig + len` in the ANSI-skipping loop. Patch 5 switched the ANSI-skipping loops in `utf8_strnwidth()`, `strbuf_add_wrapped_text()`, and `strbuf_utf8_replace()` to use `display_mode_esc_sequence_len_all()`. Patch 2 (v4 2/5) was a documentation-only correction to the comment above `utf8_strnwidth()` changing the description from "null-terminated string" to "string terminated by len" and fixing the claimed return value for invalid UTF-8 from `strlen()` to the `len` argument, matching the function's actual signature and behavior; it touches only comment lines with no code or behavior change. Patch 1 added unit tests in `t/unit-tests/u-utf8-ansi.c`: `test_utf8_ansi__sgr_len_null` (NUL-terminated strings), `test_utf8_ansi__sgr_len_end_ptr` (bounded buffers including truncated sequences), and `test_utf8_ansi__sgr_len_start_end_swap` (swapped pointers return 0). Patch 3 added unit test `test_utf8_width__strnwidth_ansi` in `t/unit-tests/u-utf8-width.c` covering cases such as `utf8_strnwidth("\033[31mhello", 4, 1)` returning 3, `len` 5 returning 0, and `len` 6 returning 1. Patch 5 added unit tests `test_utf8_ansi__sgr_len_greedy` and `test_utf8_width__strnwidth_cjk_chopped` (e.g. `utf8_strnwidth("三bytes long...", 1, 1)` returns 1). On-disk format: no changes.
