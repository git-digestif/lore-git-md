Thread identity: Subject: [PATCH 0/2] utf8.c: fix bounds handling and documentation in utf8_strnwidth(). Series version: v1 under review; v2 in preparation by author. Originating author: Dirk Gouders. Thread type: bugfix patch series.

Core problem or goal: Fix two distinct issues in Git's UTF-8 handling code in `utf8.c`: (1) `utf8_strnwidth()` ignores its `len` argument when processing valid UTF-8, potentially reading beyond the intended bounds, and (2) the function's documentation incorrectly claims it returns `strlen()` in certain cases, whereas the code actually returns the `len` argument.

Current status: Under review. v1 remains the current posted version. Dirk Gouders has conceded Junio C Hamano's substantive technical concerns and is preparing a v2 that addresses the bounds-handling fix and the mmapped-region memory-safety edge case. Junio C Hamano has revised his API proposal: rather than changing `display_mode_esc_sequence_len()`'s signature for all callers, he now proposes keeping the original NUL-terminated function as a wrapper that computes `strlen()` and delegates to a new `display_mode_esc_sequence_len_counted()` accepting a `size_t len` boundary, to avoid disrupting other in-flight topics that add callers. Gouders has accepted this general direction over his own alternative plan.

Key technical details: Files touched: `utf8.c`, `utf8.h`, `pretty.c`, new unit test `t/unit-tests/u-utf8-width.c`. Symbols: `utf8_strnwidth()` (function behavior and documentation corrected), `display_mode_esc_sequence_len()` (retained as NUL-terminated wrapper), new `display_mode_esc_sequence_len_counted(const char *s, size_t len)` (proposed counted variant for bounds enforcement), `utf8_width()`, `format_and_pad_commit()`, `strbuf_add_wrapped_text()`, `strbuf_utf8_replace()`. On-disk format: no changes. Test coverage: new unit test verifies bounds-respecting behavior. Memory-safety concern: if `string` points to the end of an mmapped region, reading beyond `len` could trigger a `SIGBUS` before the proposed check is reached; Gouders agrees this makes the v1 fix "too late" in that scenario and plans to address it in v2. Junio's earlier illustrative patch inserted `end <= p` guards throughout the escape-sequence parser to prevent reads past `s + len` and updated four call sites; the revised proposal preserves existing call sites unchanged by adding the counted variant instead. The separate post-loop guard inside `utf8_strnwidth()` remains necessary regardless of which mechanism bounds the escape-sequence parser.

Open questions and loose ends: v2 respin expected to address: (a) placing the boundary guard after the ANSI-escape-skipping loop rather than relying solely on the escape-sequence parser bounds, and (b) the SIGBUS risk when `string` points to the end of an mmapped region. Goulders has abandoned his planned alternative of introducing `ansi_sgr_nlen()` and `ansi_sgr_nlen_multi()` helper functions in favor of Junio's approach of a counted variant `display_mode_esc_sequence_len_counted()`. The separate post-loop guard inside `utf8_strnwidth()` remains necessary regardless. Thread awaits Dirk Gouders's v2.
