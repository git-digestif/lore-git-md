Core problem or goal: Fix bounds handling in Git's UTF-8 display-width code so that utf8_strnwidth() and utf8_width() respect their length arguments and do not read past the end of the input buffer, including the mmapped-region SIGBUS edge case; additionally correct the misleading documentation on utf8_strnwidth().

Current status: v6 is the latest posted version and is under review; no version has been merged or queued in any integration branch. v6 incorporates all mechanical fixes requested in Junio C Hamano's v5 review: commit message trailers reordered to chronological custodial order, redundant `#include <strbuf.h>` removed from t/unit-tests/u-utf8-ansi.c, `cl_assert_equal_u()` substituted for `cl_assert_equal_i()` for size_t return values, comparisons in display_mode_esc_sequence_len_counted() rewritten as `len <= i`, and the `_counted` variant dropped from strbuf_add_wrapped_text() where NUL termination suffices. Commit messages for patches 2 through 4 are reworded per Junio's suggestions, including using "bounded" rather than "terminated" in patch 2, a concrete example in patch 3 showing how an escape sequence reaching orig + len causes utf8_width() to read past the limit, and a note in patch 4 explaining why the bounds check from 3/4 remains necessary even when utf8_width() receives a remainder argument. The API design remains the length-based `_counted` approach using array index/length rather than pointer arithmetic, explicitly to avoid both O(n^2) degradation on NUL-terminated strings and the undefined behavior of computing s + len when len is SIZE_MAX. Junio C Hamano had previously reviewed v5 and stated the series is in "a very good shape" and that "we are getting closer to the finish line"; v6 addresses the specific enumerated nits, signaling convergence toward merge readiness; the series remains unmerged and not yet in any integration branch.

Key technical details: Files touched: utf8.c, utf8.h, pretty.c, Makefile, t/meson.build, new unit tests t/unit-tests/u-utf8-ansi.c and t/unit-tests/u-utf8-width.c wired into both Makefile and t/meson.build. Symbols: utf8_strnwidth(), utf8_width(), and display_mode_esc_sequence_len_counted(const char *s, size_t len) (patch 1, authored by Junio C Hamano), which scans for an ANSI SGR sequence bounded by index/length using `len <= i` comparison style rather than an end pointer; the existing NUL-terminated display_mode_esc_sequence_len(const char *s) is retained as a thin wrapper that calls the counted variant with SIZE_MAX; the v4 end-pointer display_mode_esc_sequence_len(const char *start, const char *end) and the proposed display_mode_esc_sequence_len_all() are both absent. Patch 1 immediately adopts the counted variant at two bounded-buffer call sites: utf8_strnwidth() passes `orig + len - string` as the bound when skipping escape sequences, and strbuf_utf8_replace() passes `end - src`. Patch 2 is documentation-only, changing the utf8_strnwidth() comment to say the string is "bounded by len" (not NUL-terminated) and fixing the documented invalid-UTF-8 return from strlen() to len. Patch 3 ensures utf8_strnwidth() respects the len boundary after skipping ANSI escape sequences using the new _counted variant and checking against orig + len, breaking the loop when string >= orig + len; its commit message includes a concrete example with "\033[31mhello" showing that when len = 5 (the 5-byte escape sequence ending exactly at orig + len) the function previously returned width 1 instead of 0 because utf8_width() would read the byte at orig + len; the fix adds `if (string >= orig + len) break;` immediately after consuming escape sequences. Tests in patch 3 add test_utf8_width__strnwidth_ansi() to t/unit-tests/u-utf8-width.c covering "\033[31mhello" at lengths 4, 5, and 6 to verify widths of 3, 0, and 1 respectively. Patch 4 modifies the main loop to declare `size_t remainder`, compute it as `orig + len - string`, and pass `&remainder` to utf8_width(&string, &remainder) so multibyte characters chopped by len do not cause out-of-bounds reads; its commit message notes why the 3/4 bounds check remains necessary even with the remainder argument because utf8_width() would still read the byte at orig + len if called with zero remainder. Other call sites use the length-based form throughout; pretty.c passes ch + 1 in format_and_pad_commit() via the counted API; strbuf_add_wrapped_text() no longer uses the `_counted` variant since the string is NUL-terminated there. Tests in t/unit-tests/u-utf8-ansi.c cover the new counted function including wrapper tests with SIZE_MAX and truncated sequences at the boundary, using `cl_assert_equal_u()` for size_t values and arrays initialized with string constants so sizeof() yields buffer size without the redundant strbuf.h include; t/unit-tests/u-utf8-width.c covers bounded utf8_strnwidth() behavior including chopped CJK sequences via test_utf8_width__strnwidth_cjk_chopped() (verifying "三bytes..." with len 1 returns width 1 and len 3 returns width 2) and carries a TODO noting that cl_assert_equal_i() usage may need future updating to cl_assert_equal_u() if the width functions' return types change from int to size_t.
