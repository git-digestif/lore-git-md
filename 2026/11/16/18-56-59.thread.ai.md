Core problem or goal: Fix bounds handling in Git's UTF-8 display-width code so that utf8_strnwidth() and utf8_width() respect their length arguments and do not read past the end of the input buffer, including the mmapped-region SIGBUS edge case; additionally correct the misleading documentation on utf8_strnwidth().

Current status: v5 is the latest posted version and is under review; no version has been merged or queued in any integration branch. v5 drops the v4 patch 5 (display_mode_esc_sequence_len_all() helper) entirely as agreed, restores the undeclared `skip` variable that broke v4's compilation, fixes the two test-only nits in t/unit-tests/u-utf8-ansi.c by using arrays initialized with string constants so sizeof() yields buffer size, and incorporates Andy Koppe's simplified bounds checks. The API design has shifted from v4's end-pointer approach back to a length-based `_counted` API, but now uses an array index/length rather than pointer arithmetic, explicitly to avoid both O(n^2) degradation on NUL-terminated strings and the undefined behavior of computing s + len when len is SIZE_MAX. Junio C Hamano has now reviewed patch 1/4 and requested specific changes including trailer reordering, test assertion updates, and code style adjustments detailed below, and has also reviewed patch 2/4 (documentation-only) approving it with a minor wording suggestion to use "bounded" instead of "terminated" in the commit message.

Key technical details: Files touched: utf8.c, utf8.h, pretty.c, Makefile, t/meson.build, new unit tests t/unit-tests/u-utf8-ansi.c and t/unit-tests/u-utf8-width.c wired into both Makefile and t/meson.build. Symbols: utf8_strnwidth(), utf8_width(), and display_mode_esc_sequence_len_counted(const char *s, size_t len) (patch 1, authored by Junio C Hamano), which scans for an ANSI SGR sequence bounded by index/length rather than an end pointer; the v4 end-pointer display_mode_esc_sequence_len(const char *start, const char *end) and the proposed display_mode_esc_sequence_len_all() are both absent from v5. Patch 2 is documentation-only, changing the utf8_strnwidth() comment to say NUL-terminated and fixing the documented invalid-UTF-8 return from strlen() to len. Patch 3 ensures utf8_strnwidth() respects the len boundary after skipping ANSI escape sequences using the new _counted variant and checking against orig + len. Patch 4 modifies the main loop to compute remainder = end - string (or equivalent length-based remainder) and pass it to utf8_width(&string, &remainder) so multibyte characters chopped by len do not cause out-of-bounds reads; the `skip` variable is now declared. Call sites use the length-based form throughout; pretty.c passes ch + 1 in format_and_pad_commit() via the counted API. Tests in t/unit-tests/u-utf8-ansi.c cover the new counted function including wrapper tests, and t/unit-tests/u-utf8-width.c covers bounded utf8_strnwidth() behavior including chopped CJK sequences; test code uses arrays with sizeof() for correct buffer sizing. Junio's review of patch 1 specifies that in utf8.c the four comparisons between index `i` and `len` should be written as `len <= i` rather than `i >= len`; that in strbuf_add_wrapped_text() the unconditional `strlen(text)` call computing the `end` pointer is wasted when `width <= 0` diverts early and should be moved after that check; that t/unit-tests/u-utf8-ansi.c should drop the redundant `#include <strbuf.h>` (already provided by `<unit-test.h>`), change `cl_assert_equal_i()` to `cl_assert_equal_u()` for size_t return values per the precedent in t/unit-tests/u-odb-inmemory.c, and reword test comments from "end pointers" to "length limits"; and that patch 1's commit message trailers should be reordered to chronological custodial order (original author sign-off first, then Helped-by, then the relaying sign-off). Junio's review of patch 2/4 approves the documentation fix but suggests the commit message use "bounded" rather than "terminated" when describing the length limit. On-disk format: no changes.
