This thread reports a regression in Git 2.56.0 affecting `git index-pack` in partial clones. לירון עדן describes a bug where `index-pack` incorrectly triggers nested lazy fetches for `REF_DELTA` bases that are already present in the thin pack being processed. The issue occurs in blobless partial clones when the server doesn’t support `OFS_DELTA`, leading to redundant fetches and potential unbounded recursion (though a 2026 commit now caps nesting at 5 levels).

The root cause is in `fix_unresolved_deltas()` in `builtin/index-pack.c`: the prefetch loop processes all `REF_DELTA` entries before checking their resolution status, including those resolvable against in-pack bases. The author provides a minimal reproduction script and suggests a fix (resolve local bases first, then prefetch unresolved ones) but hasn’t submitted a patch. The bug affects `master`, `next`, and `seen` as of mid-November 2026, with a documented workaround of explicitly fetching the commit before checkout.

This is a well-documented regression with real-world impact, particularly for users of partial clones with servers lacking `OFS_DELTA` support. No prior discussion or patches are referenced, so the thread is currently just the initial report.
