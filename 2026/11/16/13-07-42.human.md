This is the sixth patch in Patrick Steinhardt’s 12-patch series introducing **pluggable commit graphs** as part of the **ODB abstraction** effort. The patch eliminates redundant bookkeeping in `write_commit_graph_file()` by deriving layer information directly from the passed-in commit-graph chain instead of relying on caller-provided arrays. This refactoring simplifies the code and prepares the ground for moving path-dependent logic into the "files" ODB backend in later patches.

The core change is mechanical: the patch removes the `commit_graph_filenames_before`, `commit_graph_filenames_after`, and `commit_graph_hash_after` arrays from `struct write_commit_graph_context` and replaces their use with direct traversal of the commit-graph chain. This reduces memory overhead and eliminates a source of potential inconsistency, as the caller no longer needs to maintain parallel arrays of filenames and hashes. The patch also introduces a new `string_list` to track kept filenames for expiration, which is populated by walking the chain.

A small but notable behavioral change: in the preimage, `expire_commit_graphs()` was called unconditionally, even if writing the new commit-graph failed. The new version only calls it on success, which is a logical improvement—expiring graphs when no new ones were written is counterintuitive.

The patch is well-motivated and aligns with the series’ goal of making commit-graph storage pluggable. The refactoring is clean and reduces complexity, though the new logic for tracking kept filenames (via `string_list`) adds a bit of cognitive overhead. The commit message clearly explains the rationale and the behavioral change, and the code itself is straightforward. This looks like a solid step toward the larger ODB abstraction goal.
