This is the first patch in a two-patch performance series targeting `git repo structure`. It delays object parsing until it is actually needed, eliminating unnecessary work for blobs and tags. The change is confined to `builtin/repo.c` and introduces no new user-facing behavior or on-disk format changes.

The patch rewrites the object-counting loop so that only trees and commits are parsed. Blobs and tags are now counted without parsing their content, and commits are looked up via `lookup_commit()` rather than being parsed from scratch—relying on the revision walk to have already parsed them. The commit message frames `repo_parse_commit()` as a failsafe, not a dependency, addressing the sole feedback from v1.

Benchmarking in `git.git` shows a 12% wall-time improvement and a 4% memory reduction. The larger gains (80% memory, 20% speed) reported in the cover letter come from the combined effect of both patches, so this patch’s contribution is the smaller slice. The code is clean, the rationale is clear, and the performance impact is measurable. No open questions remain; the patch is ready for maintainer pickup.
