This is the first patch in Patrick Steinhardt’s 12-part series introducing **pluggable commit graphs** as part of the **ODB abstraction** effort. It simplifies how commit-graph chains are linked by removing redundant data passing and making the logic self-contained within the commit-graph structure itself.

The patch refactors `add_graph_to_chain()` into a new public function, `commit_graph_link_base()`, which no longer requires an external array of object IDs. Instead, it walks the existing chain of base layers to validate hashes and compute commit counts. This change reduces coupling and prepares the code for the next step, where chain-creation logic will move into the ODB backend.

The diff is mechanical but invasive: it touches core commit-graph loading logic in `commit-graph.c` and exposes the new function in `commit-graph.h`. The behavior change is subtle—commit-graph chains are now validated by depth rather than by an external list—but the real purpose is infrastructure cleanup. No new tests are added, as this is purely internal refactoring.

This patch looks well-crafted and aligns with the series’ goal of making commit-graph storage pluggable. It’s a small but necessary step for the broader ODB abstraction effort, and the commit message clearly explains the motivation. Reviewers will likely focus on whether the new function’s interface is sufficiently flexible for future backends.
