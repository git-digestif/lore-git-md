# Thread deltas

## 2026/11/16

- [2026/11/16/17-38-38 by לירון עדן <lironeden@gmail.com>] Bug report filed: in a blobless partial clone fetching a thin pack whose in-pack delta bases arrive as REF_DELTA (no ofs-delta negotiated), index-pack starts a nested lazy fetch for delta bases that are already in the pack being indexed, causing a redundant round trip.
- [2026/11/16/17-38-38 by לירון עדן <lironeden@gmail.com>] Root cause identified as the prefetch loop in fix_unresolved_deltas() in builtin/index-pack.c, which iterates all REF_DELTA entries—including ones already resolved against in-pack bases—and requests them from the promisor remote because the incoming pack's objects are not yet in the object store.
- [2026/11/16/17-38-38 by לירון עדן <lironeden@gmail.com>] Suggested (but not written or tested) remedy: resolve deltas against locally available bases first and only then prefetch the bases of what remains unresolved, which would also cover delta chains whose base object ID is not yet known.
- [2026/11/16/17-38-38 by לירון עדן <lironeden@gmail.com>] Real-world impact reported against Azure DevOps Services (no ofs-delta advertised): checking out an unfetched commit triggered recursive nested lazy fetches—12 levels in about a minute and several hundred levels in an unattended job until it hit its memory limit, each level re-downloading about 14 MB; commit 4360734e90 caps nesting at 5 but the redundant requests still occur in v2.56.1, master, next and seen as of 2026-11-15.
- [2026/11/16/17-38-38 by לירון עדן <lironeden@gmail.com>] Workaround noted: running GIT_NO_LAZY_FETCH=1 git fetch --depth 1 origin <commit> before the checkout avoids the nested fetch.
