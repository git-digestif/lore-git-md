This is a cleanup patch in the HTTP backend, now approved by Patrick Steinhardt. The patch removes an unnecessary and incorrect pre-sizing step in `get_info_packs()` that was introduced in 2009. The function previously iterated over all packs twice—once to count local packs and pre-size a `strbuf`, and again to format the output—despite `strbuf_addf()` already handling dynamic growth efficiently. The pre-sizing logic was also flawed, underestimating line lengths for SHA-256 repositories and using unchecked arithmetic.

The author revised the commit message in v2 to address Patrick’s concern about the performance trade-off, explaining that `get_info_packs()` is a one-shot CGI handler where the overhead of dynamic `strbuf` growth (a few dozen reallocations even with thousands of packs) is negligible compared to CGI startup and I/O costs. Patrick accepted this rationale, noting that the memory savings from pre-sizing are irrelevant in practice and that repositories with enough packs to make this matter would have far bigger problems.

This is a well-motivated, low-risk cleanup that aligns with similar improvements elsewhere in the codebase. The patch touches only `http-backend.c`, requires no new tests, and has no behavior change. It’s now ready to merge to `next`.
