Subject: submodule: fix crash when submodule is a linked worktree
Series version: standalone patch (no version marker)
Originating author: Andreas Wendleder
Thread type: bug report / bugfix

Core problem or goal
A crash (BUG()) occurs in `validate_submodule_legacy_git_dir()` when a submodule is itself a linked worktree of its repository and `submodule.recurse=true` is set. The crash is triggered during branch switching in the superproject worktree. The root cause is that linked worktrees of submodule repositories have git directories (e.g., `.git/modules/sub/worktrees/sub1`) that do not end with the submodule name, violating an assertion in the validation logic. When `extensions.submodulePathConfig` is enabled, the same scenario fails with a misleading error message suggesting the extension is not enabled.

Current status
Under review. The issue is present in all integration branches (`master`, `next`, and `seen`), indicating no prior fix has been merged.

Key technical details
- Subsystem: submodule
- Function: `validate_submodule_legacy_git_dir()`
- Files likely touched: submodule.c or related validation logic
- Behavior change: The patch will either relax the validation logic to accept linked worktrees of submodule repositories as valid git directories or improve error handling to avoid the BUG() and misleading error message.
- Test coverage: A minimal reproduction script is provided in the email, demonstrating the crash and the misleading error message.
