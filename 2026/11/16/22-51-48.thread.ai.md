Thread identity: Subject "submodule: fix crash when submodule is a linked worktree", standalone patch (no version marker), originating author Andreas Wendleder, thread type bug report / bugfix.

Core problem or goal: A crash (BUG()) occurs in `validate_submodule_legacy_git_dir()` (submodule.c:2414) when a submodule is itself a linked worktree of its repository and `submodule.recurse=true` is set during branch switching in the superproject worktree. The root cause is that linked worktrees of submodule repositories have git directories (e.g., `.git/modules/sub/worktrees/sub1`) that do not end with the submodule name, violating the suffix assertion. When `extensions.submodulePathConfig` is enabled, the same scenario fails with a misleading error message suggesting the extension is not enabled.

Current status: Under review. The issue exists in all integration branches (`master`, `next`, `seen`); no fix has been merged. Adrian Ratiu has a local fix ready and intends to send the patch shortly.

Key technical details: The BUG() predates `extensions.submodulePathConfig` but only became reachable after commit 9cf8547320 ("clone: prevent clashing git dirs when cloning submodule in parallel", 2024-01-28), which caused `submodule_move_head()` to validate the gitdir path read from disk; a path read from disk should never trigger a BUG(). The reproducer requires a second linked worktree because the primary checkout's gitdir (`.../sub`) accidentally satisfies the suffix check. Test t2405 creates this exact layout but never exercises a recursive checkout. The misleading "refusing to create/use" hint when `extensions.submodulePathConfig` is already enabled is Adrian Ratiu's own error. Adrian's local fix allows the branch switch to succeed in both legacy and `submodulePathConfig` modes without touching the main submodule checkout.

Open questions and loose ends: Whether linked worktrees of submodule repositories should be accepted as valid git directories or rejected with a proper error message appears resolved in favor of acceptance, pending Adrian's patch. The misleading error message under `extensions.submodulePathConfig` is acknowledged as a bug in Adrian's own code and will be fixed.
