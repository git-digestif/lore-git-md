This is a brief follow-up in the ongoing review of Patrick Steinhardt’s two-patch series to improve the performance and memory usage of `git repo structure`. The series is already cooking in `seen` and has no open technical objections; the only remaining discussion is whether to add a `BUG()` assertion in patch 1/2.

Kristofer Karlsson, who previously reviewed the series and confirmed its 80 % memory reduction and 20 % speedup, now suggests that the code could defensively `BUG()` if `repo_parse_commit()` is ever called on an unparsed commit. The current code silently falls back to parsing, which might mask future regressions. Patrick had considered the same idea but hesitated to add the assertion; Kristofer leaves the choice to the author, noting that either way the updated comment makes the intended behavior clear. No code change has been made yet, and the series remains ready for maintainer pickup.
