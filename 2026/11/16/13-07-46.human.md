This is the tenth patch in Patrick Steinhardt’s 12-patch series making commit-graph storage **pluggable** as part of the **ODB abstraction** effort. It introduces the actual pluggability mechanism by adding ODB backend hooks for reading and writing commit graphs, then updates callers to use the new generic functions.

The patch adds two new callbacks to `struct odb_source`: `read_commit_graph()` and `write_commit_graph()`. The "files" backend (the only one implemented so far) wires these up to the existing `read_commit_graph_one()` and `commit_graph_write()` functions, but now the logic is invoked through the ODB interface rather than hard-coded paths. Callers in `builtin/fetch.c`, `builtin/gc.c`, and the test helper are updated to use `odb_write_commit_graph()` and `odb_source_read_commit_graph()`, removing direct references to the object directory. The `git commit-graph` built-in keeps its `--object-dir=` option, but now dispatches to either the files backend or the generic ODB interface depending on whether a custom directory was specified.

No on-disk format changes or user-visible behavior changes are introduced; this is pure infrastructure. The patch is cleanly split, touching only the plumbing layer and leaving the commit-graph data structure untouched. The commit message is clear about the current limitation—commit-graph *discovery* logic remains in `commit-graph.c`—and promises a follow-up patch to complete the abstraction. This is a well-crafted, incremental step in a long-running refactor, authored by the domain expert driving the ODB effort.
