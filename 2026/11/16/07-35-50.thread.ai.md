Originating author: Miklos Vajna <vmiklos@collabora.com>
Thread type: regression bugfix

Core problem or goal
The 2026-06-22 commit 304812ed33 ("diff: detect renames in merges") improved rename detection for merges but introduced a severe performance regression in `git log --stat --follow` on large repositories (e.g., linux.git: 28s → 6m43s). The regression occurs because the enhanced logic performs an expensive per-parent diffing step even when the path isn’t added relative to a parent. This patch restores the pre-304812ed33 behavior as an opt-in `--follow=merges` mode (and `log.follow=merges` config), allowing users to trade off merge rename detection for performance.
