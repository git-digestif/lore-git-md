This is Junio C Hamano marking the standalone toggle patch for `git log --follow` as ready for the `next` branch. The patch, which introduces the config `log.follow=merges` and flag `--follow=merges` to make rename-following in non-linear history optional (and disabled by default), has received Patrick Steinhardt’s explicit approval ("looks good to me") and addresses all prior feedback. This is the final step before the patch graduates to `next` and eventually `master`.

The toggle patch is the project’s settled resolution to the `--follow` performance regression introduced by commit 304812ed33 (June 2026), which made `git log --follow` ~14× slower when processing merges. The patch restores pre-regression performance for default users while preserving the correctness fixes from the v5 series (Miklos Vajna/Justin Tobler). It is fully decoupled from the v5 series and will land first to unblock GitLab’s deployment.
