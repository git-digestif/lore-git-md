This thread is about a regression in Git 2.54.0 that affects partial clones using `blob:none` filters. When operations like `cherry-pick` write new blobs locally, Git incorrectly attempts to lazy-fetch them from the promisor remote because the loose object cache isn’t being flushed properly after the ODB abstraction refactor. Google (via Remy Duthu) reported the issue with a clear reproduction case and a diagnostic patch suggesting a cache flush during retries.

Patrick Steinhardt, the ODB abstraction maintainer, has now linked an in-flight fix series (`20261104-pks-odb-loose-stale-cache-v1`) that directly addresses the loose cache visibility gap. He’s asked the reporter to test the fix against the failing cherry-pick scenario. The fix targets the same code path (`odb/source-files.c`) identified in the original report, so if testing confirms it works, this should resolve the regression. The thread is now focused on validating the fix rather than debating alternatives. If all goes well, the fix will likely be merged soon and may need backporting to `maint` branches.
