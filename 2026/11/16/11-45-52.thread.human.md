This thread is about a regression in Git 2.54.0 that broke partial clones with `blob:none` filters, causing Git to attempt lazy-fetching blobs that were just written locally during operations like cherry-pick. The issue was traced to a visibility gap in the loose object cache introduced by the ODB abstraction refactor (commit `5946a564cd`). Google reported the bug with a clear reproduction case, and Patrick Steinhardt proposed a fix series (`20261104-pks-odb-loose-stale-cache-v1`) targeting the loose cache flush logic in `odb/source-files.c`.

The fix has now been validated by the reporter, who confirmed it resolves the issue for both cherry-pick and merge operations in partial clones. The regression affects production workflows, so the fix is likely to be prioritized for merging and backporting to maintenance branches. The thread is now focused on reviewing the fix series itself, with no open technical questions remaining. Key participants include Google (who reported and validated the bug) and Patrick Steinhardt (who authored the fix). The reproduction script using GitHub’s `elastic/fleet-server` repo remains the primary test case.
