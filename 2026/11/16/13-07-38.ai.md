This is the second patch in Patrick Steinhardt’s 12-patch series introducing **pluggable commit graphs** for the ODB abstraction effort. It simplifies the internal API for reading a single commit-graph layer by removing redundant path handling and preparing the codebase for backend-specific logic.

The patch renames `load_commit_graph_one_fd_st()` to `commit_graph_read()` and stops passing the directory path as an argument. Instead, the path is now populated in `load_commit_graph_one()`, which will later move into the "files" ODB backend. This change aligns with the series’ goal of shifting path-derivation responsibility to the backend, though the backend-specific logic itself is introduced in later patches. The diff touches `commit-graph.c`, `commit-graph.h`, and a single call site in `builtin/commit-graph.c`.

The motivation is twofold: first, to eliminate duplicate path handling (the directory was already being set in `load_commit_graph_one()`), and second, to reduce exposure of backend-specific details (like paths) to generic commit-graph code. The patch is mechanical and introduces no user-facing changes, but it’s a critical preparatory step for the backend pluggability introduced later in the series. The commit message clearly explains the rationale, and the changes are narrowly scoped to the refactoring goal.

This patch is unlikely to be controversial, but it’s worth noting that the path-handling logic is now split between `load_commit_graph_one()` (which sets the path) and `commit_graph_read()` (which reads the data). Future reviewers may question whether this split is the cleanest design, especially if the backend-specific path logic grows more complex. The patch also doesn’t yet move the path-setting code into the backend—that happens in a later patch—but it lays the groundwork by removing the redundant directory argument.

Key technical details for follow-up discussion:
- **Files touched**: `commit-graph.c` (core logic), `commit-graph.h` (API change), `builtin/commit-graph.c` (call site update).
- **New symbol**: `commit_graph_read()` (replaces `load_commit_graph_one_fd_st()`).
- **Behavior**: No functional changes; the patch is purely a refactor to prepare for backend-specific path handling.
- **Related patches**: This is a prerequisite for later patches in the series that move path logic into the ODB backend.
