This is a bugfix patch targeting the UTF-8 string width calculation in Git's output formatting.

The patch fixes a boundary-checking issue in `utf8_strnwidth()`, which currently can read past the specified length (`len`) when processing ANSI escape sequences. The function relies on `display_mode_esc_sequence_len()` to skip escape sequences, but that helper doesn't respect the caller's length limit. The fix adds an explicit check to ensure the function stays within bounds.

The commit includes new unit tests that demonstrate the problem: two of the three test cases fail without the fix, confirming the bug affects real-world usage (e.g., truncating colored output). The tests verify that strings containing ANSI color codes (`\033[31m`) are correctly measured when the length limit falls within or exactly at the escape sequence.

The change is small and focused, touching only `utf8.c` and its unit test file. It's part of a two-patch series, though the second patch isn't shown here. The fix looks well-motivated and comes with clear test coverage, suggesting it's ready for serious review.
