This is a contributor housekeeping patch that aligns the naming of Git’s credential-store lock timeout configuration with the established convention used by other lock-timeout settings. The patch introduces `credentialStore.lockTimeout` as the preferred key while retaining `credentialStore.lockTimeoutMS` as a deprecated alias for backward compatibility. Junio C Hamano has now marked the patch as ready for the `next` branch, confirming it is technically complete and uncontroversial.

The change is purely mechanical and follows directly from the recent `rerere.lockTimeout` patch, which established the convention that lock-timeout variables should omit the unit (milliseconds) from their names. The commit message explicitly enumerates all existing lock-timeout variables to demonstrate consistency, addressing Junio’s earlier substantive objection. The patch touches documentation, the credential-store builtin, and test coverage, with all feedback from the v2 review now incorporated.

This patch is the final piece of a two-part effort to fix a long-standing race condition in the `rerere` subsystem, where concurrent writers contend for the shared `rr-cache` directory lock. The main series (already in `next`) introduced a configurable timeout and a `--skip-locked` mode for `git rerere gc`, while this follow-up ensures naming consistency across Git’s configuration system. The patch is ready for integration testing.
