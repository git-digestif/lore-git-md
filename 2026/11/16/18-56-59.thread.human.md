This v2 series from Dirk Gouders fixes out-of-bounds reads in Git's UTF-8 width functions (`utf8_strnwidth()` and `utf8_width()`), including the mmapped-region SIGBUS edge case, and corrects misleading documentation. The four patches introduce a bounds-aware `display_mode_esc_sequence_len_counted()` variant (authored by Junio C Hamano), apply it inside `utf8_strnwidth()` with a post-loop guard, extend the same treatment to `utf8_width()`, and fix the doc comment. New unit tests in `t/unit-tests/` cover truncated ANSI sequences and chopped CJK characters.

Junio C Hamano reviewed patches 3 and 4 favorably -- patch 4 got a "well spotted, and nicely done" with no technical objections, while patch 3 drew only surface-level style nits. Andy Koppe initially flagged a remaining documentation inaccuracy in patch 2 (the comment still calls the input "null-terminated" despite the explicit `len` parameter), but has now escalated to a substantive objection against patch 1's API design: retaining `display_mode_esc_sequence_len()` as a `strlen()`-based wrapper risks quadratic behavior when the function is called repeatedly across a string, and he recommends dropping the wrapper entirely so all callers pass an explicit length. This leaves the series with one open design question on the wrapper API, two minor wording/style nits, and no recorded objections to the core bounds-fixing logic; a v3 addressing these points appears likely.
