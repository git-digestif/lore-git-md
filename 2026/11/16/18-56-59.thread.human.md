Dirk Gouders has posted v5 of his UTF-8 bounds-handling series, now trimmed to four patches after dropping the `display_mode_esc_sequence_len_all()` helper that Andy Koppe had questioned. The series has also reversed course on the API design: instead of v4's end-pointer approach, v5 returns to a length-based `_counted` API, but expressed through an array index rather than pointer arithmetic, so it avoids both the O(n^2) degradation of scanning NUL-terminated strings and the undefined behavior of computing `s + SIZE_MAX`. Patch 1, authored by Junio C Hamano, introduces `display_mode_esc_sequence_len_counted(const char *s, size_t len)`; Gouders's patches 2 through 4 fix the misleading `utf8_strnwidth()` documentation, ensure the function respects its `len` boundary after skipping ANSI escape sequences, and pass a `remainder` to `utf8_width()` so multibyte characters chopped by `len` no longer read out of bounds. The `skip` variable that broke v4's compilation is restored, and the test nits Koppe flagged in `t/unit-tests/u-utf8-ansi.c` are addressed by initializing arrays from string constants so `sizeof` yields the buffer size. v5 is the latest posted version and remains under review, with no merge or integration-branch placement announced.
