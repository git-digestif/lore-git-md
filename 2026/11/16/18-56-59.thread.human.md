This thread is Dirk Gouders's four-patch v2 series fixing bounds handling in Git's UTF-8 display-width code (`utf8_strnwidth()` and `utf8_width()` in `utf8.c`), so the functions respect their length arguments and never read past the end of the buffer -- including the mmapped-region SIGBUS edge case -- plus a correction to the misleading documentation on `utf8_strnwidth()`. The series is under review; it grew from v1's two patches by adding Junio C Hamano's `display_mode_esc_sequence_len_counted()` as patch 1 and a new patch 4 extending the same boundary-respecting treatment to `utf8_width()`. Junio has effectively signed off on patches 3 and 4 -- patch 3 drew only two surface-level style nits, and patch 4 got a clean "well spotted, nicely done" with no requested changes.

The main open question has been patch 1's API design. Andy Koppe objected that keeping `display_mode_esc_sequence_len()` as a `strlen()`-based wrapper around the counted variant introduces a quadratic-time regression when the function is scanned repeatedly over a whole string, and recommended dropping the wrapper in favor of mandatory explicit lengths. In the latest email Dirk concedes this point: he confirms only one caller in `pretty.c` uses the wrapper, proposes switching that call site to the counted variant directly so the NUL-terminated wrapper can be removed entirely, and asks whether that approach -- which Junio's earlier v1 already contained -- would be acceptable.

Also still pending are two smaller items Dirk has already acknowledged: removing the inaccurate "null-terminated" phrasing from patch 2's comment block (flagged by Andy Koppe) and Junio's two formatting nits on patch 3. If the wrapper removal is accepted, the series would likely see a v3 incorporating it along with those fixes; otherwise the series is close to ready as it stands.
