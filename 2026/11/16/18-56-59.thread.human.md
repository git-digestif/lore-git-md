Dirk Gouders has posted version 6 of a four-patch series fixing out-of-bounds reads in Git's UTF-8 display-width code, with the first patch authored by maintainer Junio C Hamano. The series targets `utf8_strnwidth()` and `utf8_width()` in `utf8.c`, which could read past the end of bounded buffers -- a real risk when strings live in mmapped regions where such reads trigger SIGBUS. The core change introduces a length-bounded variant, `display_mode_esc_sequence_len_counted()`, that scans ANSI escape sequences using an explicit length rather than assuming NUL termination, avoiding undefined behavior when the bound is `SIZE_MAX`. This counted API is immediately adopted at the two call sites that already handle bounded buffers, preparing the ground for later patches that enforce bounds inside the width loops themselves.

Junio had reviewed the previous version as being in "a very good shape" and close to merge readiness, and v6 addresses his remaining mechanical nits: trailer ordering, test assertion types, and commit message wording. New unit tests in `t/unit-tests/u-utf8-ansi.c` and `u-utf8-width.c` cover truncated escape sequences and chopped multibyte characters at buffer boundaries. The series remains under review and has not been queued in any integration branch. Separately, contributor Andy Koppe plans to update his own `make_line_colors_self_contained()` work to the new counted API once this lands.
