Dirk Gouders has posted version 4 of a five-patch series fixing bounds handling in Git's UTF-8 display-width functions `utf8_strnwidth()` and `utf8_width()`, a corrected repost of the withdrawn v3. The series leads with a patch from Junio C Hamano introducing `display_mode_esc_sequence_len()` with an end-pointer API that avoids reading past buffer boundaries, followed by Dirk's patches that apply bounded scanning to the width functions, correct misleading documentation, and add a greedy `display_mode_esc_sequence_len_all()` helper for consuming consecutive ANSI sequences. The former patch 4 has been split into two patches (4 and 5) for clarity, and new unit tests cover truncated escape sequences and chopped CJK characters.

The core design question of how to express length limits has now been settled. Andy Koppe clarified that his earlier suggestion to pass `SIZE_MAX` for unbounded scanning is invalid because computing `end = s + len` with such a length would be undefined behavior; he confirmed that all actual call sites know their remaining buffer length, so the function signature `(const char *start, const char *end)` will remain unchanged without a `size_t *remainder` out-parameter, consistent with Junio's endorsement. No version of the series has been merged or queued in any integration branch.

The series now awaits substantive review of the v4 formulation itself, particularly whether splitting the former patch 4 into separate boundary-fix and helper-introduction patches is acceptable. No outstanding technical objections remain from prior versions.
