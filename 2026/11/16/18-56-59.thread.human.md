Dirk Gouders has posted the fifth version of a four-patch series fixing bounds handling in Git's UTF-8 display-width code, specifically making `utf8_strnwidth()` and `utf8_width()` respect their length arguments and avoid reading past the end of input buffers, including the mmapped-region SIGBUS edge case. The series, which also corrects misleading documentation and adds unit tests in `t/unit-tests/u-utf8-ansi.c` and `t/unit-tests/u-utf8-width.c`, adopts a length-based `_counted` API using array index rather than pointer arithmetic to avoid both undefined behavior and O(n^2) degradation.

Junio C Hamano has reviewed all four patches individually and pronounced the series in "a very good shape," stating "we are getting closer to the finish line," while enumerating a set of mechanical nits -- trailer reordering, test assertion changes, comparison style, and commit message wording -- that need addressing. Dirk Gouders has now confirmed he understood all the requests and will send a v6 shortly to incorporate them. The series remains under review and has not been merged or queued in any integration branch.
