This thread concerns Dirk Gouders's `[PATCH v4 0/5]` series fixing bounds handling in Git's UTF-8 display-width functions `utf8_strnwidth()` and `utf8_width()`, ensuring they respect length arguments and never read past buffer ends -- including the mmapped-region SIGBUS case. The series, which includes a patch authored by Junio C Hamano, remains at v4 and under review with no integration-branch status; v3 was previously retracted and v4 splits its final two patches apart. The core API design is settled: `display_mode_esc_sequence_len()` keeps the `(const char *start, const char *end)` signature with no `size_t *remainder` out-parameter, and callers pass concrete buffer ends like `string + len` rather than constructing invalid pointers.

Andy Koppe's review has narrowed the remaining scope considerably. Gouders has agreed to drop patch 5 and its `display_mode_esc_sequence_len_all()` helper entirely as unnecessary noise, acknowledged that patch 4/5 currently fails to compile due to an undeclared `skip` variable (attributed to a merge-conflict mistake) and says it is fixed in his working copy, accepted Koppe's simplified bounds-check formulation for `display_mode_esc_sequence_len()`, and confirmed that two test-only nits in `t/unit-tests/u-utf8-ansi.c` (pointer comparison across different objects and incorrect `sizeof` usage) will be fixed. In the latest exchange, Gouders also agreed with Koppe that forming `start + SIZE_MAX` is undefined behavior even without dereferencing, and confirmed he will audit the code for any `s + len` overflow patterns, ensuring the end-pointer API never constructs such invalid pointers.

What remains open is the expected v5 repost incorporating these agreed changes: the `skip` compilation fix, removal of patch 5, the simplified bounds checks, and the test corrections. Junio C Hamano authored patch 1 and endorsed the no-remainder signature; Koppe has committed to updating his own `make_line_colors_self_contained()` work to the new API once it lands.
