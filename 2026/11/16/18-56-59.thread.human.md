This thread concerns a four-patch v2 series from Dirk Gouders fixing bounds handling in Git's UTF-8 display-width functions so that `utf8_strnwidth()` and `utf8_width()` respect their length arguments and never read past the end of the input buffer -- including the mmapped-region SIGBUS edge case -- along with correcting misleading documentation. The series expands on v1 by incorporating Junio C Hamano's `display_mode_esc_sequence_len_counted()` as patch 1, keeping the documentation fix as patch 2, applying the counted variant plus a post-loop guard inside `utf8_strnwidth()` as patch 3, and extending the same treatment to `utf8_width()` in a new patch 4.

Review has been largely convergent. Junio approved patch 4 outright ("Well spotted, and nicely done") and offered only surface-level style nits on patch 3; Andy Koppe raised a substantive performance objection to patch 1's NUL-terminated wrapper, which Dirk has agreed to resolve by dropping the wrapper and switching its sole remaining caller in `pretty.c` to the counted variant directly, though that resolution is not yet confirmed by other reviewers. Andy also flagged that patch 2's corrected comment still describes the input as "null-terminated", which Dirk has acknowledged and will fix. The newest comment from Junio adds one more mechanical nit: in `t/meson.build` the new test file `u-utf8-ansi.c` was appended after `u-utf8-width.c`, violating the alphabetical ordering enforced by `make -C t check-meson`.

The series remains under review with no technical objections to the core bounds-handling approach in patches 3 and 4. A possible v3 would likely bundle the `pretty.c` wrapper removal, the "null-terminated" wording fix, the patch 3 style nits, and this meson ordering fix.
