This thread is a four-patch v2 series by Dirk Gouders that fixes bounds handling in Git's UTF-8 display-width code, `utf8_strnwidth()` and `utf8_width()`, so they stop reading past the end of the caller's buffer -- including the mmapped-region SIGBUS edge case -- along with a documentation correction and new clar unit tests in `t/unit-tests/u-utf8-ansi.c` and `u-utf8-width.c`. Patch 1 was authored by Junio C Hamano and introduces `display_mode_esc_sequence_len_counted()`, a bounded SGR-sequence scanner that never reads at or beyond the given length.

All substantive technical questions are now settled. The main design debate -- Andy Koppe's objection that the NUL-terminated wrapper `display_mode_esc_sequence_len()` turns repeated SGR scanning into quadratic time via upfront `strlen()` -- has been resolved by agreeing to drop the wrapper entirely and revert patch 1 to Junio's v1 form, where only the counted variant exists and the remaining caller in `pretty.c` passes an explicit length. Dirk Gouders's latest email proposed a third alternative, giving the counted variant an optional `size_t *remainder` parameter modeled on `utf8_width()`, but that compromise was not adopted given the settled wrapper-removal approach; it stands only as documentation of the API design space considered. Andy Koppe has concurred and said he will update his own `make_line_colors_self_contained()` to use the counted variant directly.

What remains is surface-level only: Junio's two formatting nits on patch 3, Andy's documentation nit on patch 2 (the comment still says "null-terminated" despite the `len` parameter, which Dirk has confirmed he will fix), and a meson test-suite ordering nit that Dirk will address in a v3. Patch 4 was approved by Junio with no changes requested. No v3 has been posted yet, and the series remains under review awaiting either the next version or integration.
