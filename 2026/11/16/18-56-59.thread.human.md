The thread concerns a four-patch v2 series from Dirk Gouders fixing bounds handling in Git's UTF-8 display-width functions (`utf8_strnwidth()` and `utf8_width()`), incorporating a patch from Junio C Hamano that adds `display_mode_esc_sequence_len_counted()` to avoid reading past buffer ends. All substantive technical questions are now resolved: the series will revert to Junio's v1 approach of removing the NUL-terminated wrapper entirely, leaving only the counted variant, and Dirk Gouders has confirmed this resolution along with fixes for remaining surface-level nits (formatting in patch 3, "null-terminated" wording in patch 2's docs, and meson test ordering) planned for a possible v3.

Andy Koppe, who originally raised the performance objection about quadratic `strlen()` scanning in the wrapper, has now formally rejected Dirk Gouders's alternative proposal to add an optional `size_t *len` remainder parameter to the counted function. Koppe points out that callers wanting unbounded scanning can simply pass `SIZE_MAX` as the length, then subtract the returned consumed-byte count from their own known length to derive the remainder themselves, keeping the API simpler without an out-parameter. This closes the last design alternative; the series awaits only cosmetic cleanups before integration.
