This thread covers Dirk Gouders' four-patch v2 series fixing bounds handling in Git's UTF-8 display-width functions, `utf8_strnwidth()` and `utf8_width()`. The core issue is that these functions could read past the end of their input buffer -- a real hazard when the string lives in an mmapped region, where an out-of-bounds access can trigger SIGBUS -- and the documentation for `utf8_strnwidth()` incorrectly described its fallback behavior on invalid UTF-8. The series is currently under review; no version has been merged.

The v2 series restructures the work around a new counted-length helper, `display_mode_esc_sequence_len_counted()`, proposed by Junio C Hamano and included as patch 1, with the original `display_mode_esc_sequence_len()` retained as a NUL-terminated wrapper. Patch 2 -- the patch just posted -- is a purely cosmetic correction to the `utf8_strnwidth()` comment, changing the claim that invalid UTF-8 yields `strlen()` to the correct statement that it yields the `len` argument. Patch 3 applies the counted variant inside `utf8_strnwidth()`'s ANSI-skipping loop and adds a guard so the pointer never advances past `orig + len` before calling `utf8_width()`. Patch 4 extends the same boundary-respecting treatment to `utf8_width()` itself. New unit tests in `t/unit-tests/u-utf8-ansi.c` and `u-utf8-width.c` cover truncated escape sequences and width corner cases.

Junio C Hamano drove the design toward the counted-variant API after reviewing v1; Dirk Gouders incorporated that feedback in v2 and dropped his earlier alternative helpers. The previously open concerns -- guard placement and the mmapped SIGBUS risk -- are addressed in the current patches. What remains open is simply further review of v2; no objections or requests for changes are outstanding.
