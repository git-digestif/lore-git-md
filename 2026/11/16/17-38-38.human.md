This is a **bugfix** targeting the `index-pack` subsystem in partial clones. The author, לירון עדן, reports that when Git receives a thin pack containing `REF_DELTA` objects whose bases are *already present in the same pack*, `index-pack` incorrectly triggers a redundant lazy fetch for those bases. The issue surfaces in blobless partial clones when the server does not support `ofs-delta` (or the client disables it), leading to unbounded recursion in real-world scenarios—though a recent commit (4360734e90) caps the recursion depth at 5, the redundant requests still occur.

The provided reproduction script demonstrates the problem clearly: with `repack.useDeltaBaseOffset=false` set, a single `git fetch` spawns a nested fetch process that requests six objects, all of which were already in the incoming pack. The root cause lies in `fix_unresolved_deltas()` in `builtin/index-pack.c`, where the prefetch loop fails to skip `REF_DELTA` entries that were resolved against in-pack bases. The author suggests resolving locally available bases first, then prefetching only the remaining unresolved ones, but notes they haven’t tested a patch.

The bug is well-documented, with a minimal reproducer, clear expected/actual behavior, and a real-world impact (observed against Azure DevOps Services). The fix appears straightforward and targeted, though the author’s caution about chained deltas hints at potential edge cases. The report is credible and actionable, making this a patch worth attention from anyone working on partial clones or pack handling.
