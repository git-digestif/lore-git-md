Series version: v2 part 1 of 2 (seven-patch preparatory refactoring; the original twelve-patch v1 has been split, with the pluggable backend hooks deferred to a follow-up part 2). Originating author: Patrick Steinhardt. Thread type: patch series (infrastructure refactor). Current focus: patch 7/7, the final patch of part 1.

Core problem or goal: The series refactors commit-graph internals in `commit-graph.c` to simplify chain management, unify error handling to the "0 means success" convention, and prepare for backend-specific control, as a foundational step in the ODB abstraction effort. This v2 part 1 contains only the preparatory refactoring of reading and writing logic; the introduction of pluggable `read_commit_graph` and `write_commit_graph` callbacks in `struct odb_source` and the move of path-derivation logic into `odb/source-files.c` are deferred to part 2.

Current status: Under review. v2 part 1 (seven patches) has been submitted, addressing Junio C Hamano's feedback on v1 patch 1. Patch 1 moves trailer-hash verification into the chain-loading loop itself, validating `oideq(&g->oid, &oids[i])` immediately after each layer is loaded from disk via `load_commit_graph_chain_fd_st()`, and truncating the chain at the first mismatch rather than using unverified layers. Patch 2 renames the static `add_graph_to_chain()` to the public `commit_graph_link_base()` and changes its signature to accept only the new tip layer `g` and the existing chain `base`, eliminating the redundant `struct object_id *oids` array parameter; instead of comparing against a pre-read array of OIDs from the chain file, the function now walks the `base_graph` linked list to derive each base layer's hash directly from the already-loaded `struct commit_graph` instances, and error semantics shift from boolean to the integer convention where 0 means success. The caller `load_commit_graph_chain_fd_st()` is updated to no longer allocate the `oids` array, using a stack-allocated `struct object_id` for per-line parsing instead. Patch 3 renames `load_commit_graph_one_fd_st()` to `commit_graph_read()` and removes the redundant `dir` parameter from the loading function, consolidating path assignment into `load_commit_graph_one()` (the function slated to move into the files backend in part 2) so that generic read logic is not exposed to directory paths. Patch 4 exposes a new public function `commit_graph_validate_chain()` that wraps the static helpers `validate_mixed_generation_chain()` and `validate_mixed_bloom_settings()`, replacing the direct calls at the end of `load_commit_graph_chain_fd_st()` so that the ODB backend in part 2 can invoke chain validation itself. Patch 5 replaces directory-path comparisons in `split_graph_merge_strategy()` with depth-based counters: `commit_graph_write()` now pre-computes `mergeable_layers` and `chainable_layers` (both `size_t`) in `struct write_commit_graph_context` by walking the existing chain once, using `get_commit_graph_filename()` to detect split vs. non-split layers and `strcmp(layer->dir, ctx.dir)` to detect locality, and `split_graph_merge_strategy()` uses a `depth` counter against these pre-computed values instead of inspecting paths directly, with the conversion logic for a local non-split base preserved as `if (ctx->new_base_graph && depth >= ctx->chainable_layers)`. Patch 6 modifies `write_commit_graph_file()` to establish a single common exit path using a `goto out` pattern: all early `return -1` error exits are converted to set a local `ret` variable and jump to the `out:` label, the success path sets `ret = 0` before falling through to the same label, and the `out:` label unconditionally calls `rollback_lock_file(&lk)` before returning, ensuring the lock file is always properly handled on every exit; this is purely preparatory for patch 7 which will introduce additional allocations in this function that need cleanup. Patch 7, the final patch of part 1, eliminates redundant bookkeeping arrays from `struct write_commit_graph_context` (`base_graph_name`, `commit_graph_filenames_before`, `commit_graph_filenames_after`, `commit_graph_hash_after`) and instead derives all layer information directly from the passed-in commit-graph chain structure; inside `write_commit_graph_file()` it introduces local `string_list` variables (`chain_hashes` and `kept`) to snapshot the hashes and filenames needed for chain-file writing and pruning before the existing chain is closed via `commit_graph_close()`, uses `base_rename_from`/`base_rename_to` derived from `ctx->new_base_graph` for the base-layer rename logic, writes the split-graph chain file by iterating `chain_hashes` in reverse, changes the signatures of `mark_commit_graphs()` and `expire_commit_graphs()` to accept the tip and base chain pointers and a `kept` string list respectively rather than reading from the removed context arrays, and has `expire_commit_graphs()` take `dirpath` and `expire_time` directly; the caller `commit_graph_write()` drops all allocation and freeing of the removed arrays. One behavioral change is introduced: `expire_commit_graphs()` is now called only after a successful write (after `commit_lock_file()`), whereas previously it ran unconditionally even if the graph write failed, which the commit message notes is arguably more correct. Patch 7 touches only `commit-graph.c` with a net reduction of 33 lines. No merge status reported; part 2 is expected to follow.

Key technical details: Files touched: `commit-graph.c`, `commit-graph.h`, `builtin/commit-graph.c`, `t/t5324-split-commit-graph.sh`. New or renamed symbols: `commit_graph_link_base()` (replaces `add_graph_to_chain()`, now public), `commit_graph_read()` (replaces `load_commit_graph_one_fd_st()`, now without `dir` parameter), `commit_graph_validate_chain()` (new public wrapper around mixed-generation and mixed-Bloom validation), `commit_graph_write_allowed()`, `commit_graph_write_layer()`. Patch 1 switches error returns from boolean to integer ("0 means success") and moves the trailer-hash comparison out of the chain-linking function into the loading loop, verifying every layer's trailer hash against the chain file record via `oideq(&g->oid, &oids[i])`; on mismatch the layer is freed and the chain truncated, making the `oid` field in `struct commit_graph` read-accessible. Patch 2 makes `commit_graph_link_base()` walk the `base_graph` linked list to derive base layer hashes directly from loaded `struct commit_graph` instances rather than from a pre-read OIDs array, and updates `load_commit_graph_chain_fd_st()` to use a stack-allocated `struct object_id` for parsing instead of allocating an `oids` array. Patch 3 removes the `dir` parameter from `commit_graph_read()` and sets the graph's directory path in `load_commit_graph_one()` instead, with `builtin/commit-graph.c` updating its call site in `cmd_commit_graph_verify()` to use the new name and signature. Patch 4 makes `commit_graph_validate_chain()` public so the future ODB backend can call it; it wraps `validate_mixed_generation_chain()` and `validate_mixed_bloom_settings()` and is called from `load_commit_graph_chain_fd_st()` with no behavior change. Patch 5 introduces the `mergeable_layers` and `chainable_layers` fields in `struct write_commit_graph_context` and a `depth` local in `split_graph_merge_strategy()`; the old behavior relied on `strcmp(g->dir, ctx->dir)` and `get_commit_graph_filename()` comparisons inside the merge strategy, while the new behavior moves those checks into `commit_graph_write()` so the strategy function itself becomes path-agnostic. Patch 6 restructures `write_commit_graph_file()` to use a `goto out` common exit path with a local `ret` variable, converting all early error returns and the success path to flow through the `out:` label where `rollback_lock_file(&lk)` is called unconditionally, making cleanup semantics uniform and preparing for patch 7 which adds allocations requiring cleanup. Patch 7 removes the `base_graph_name`, `commit_graph_filenames_before`, `commit_graph_filenames_after`, and `commit_graph_hash_after` fields from `struct write_commit_graph_context`, replacing them with local `string_list` variables (`chain_hashes`, `kept`) in `write_commit_graph_file()` that snapshot chain hashes and filenames before `commit_graph_close()`, changes `mark_commit_graphs()` and `expire_commit_graphs()` to accept chain pointers and the `kept` list directly instead of reading from context arrays, moves `expire_commit_graphs()` to take `dirpath` and `expire_time` parameters directly, and changes `expire_commit_graphs()` to run only after a successful `commit_lock_file()` rather than unconditionally. No on-disk format changes.

Open questions and loose ends: Whether the depth-based merge strategy sufficiently generalizes for future backends remains open. Patrick has questioned whether the series split improves reviewability. Whether the stricter trailer validation belongs in the generic chain loader or should be backend-specific remains a design consideration for part 2, which will move chain-creation logic into the object database backend and let the files backend in `odb/source-files.c` decide how many layers are mergeable or chainable rather than generic commit-graph code. With patch 7 submitted, part 1 of the series is now complete pending review.
