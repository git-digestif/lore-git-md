Thread identity: Subject: [PATCH v2 0/7] Introduce pluggable commit graphs for ODB abstraction (part 1). Series version: v2 part 1 of 2 (seven-patch preparatory refactoring; the original twelve-patch v1 has been split, with the pluggable backend hooks deferred to a follow-up part 2). Originating author: Patrick Steinhardt. Thread type: patch series (infrastructure refactor). Current focus: patch 4/7.

Core problem or goal: The series refactors commit-graph internals in `commit-graph.c` to simplify chain management, unify error handling to the "0 means success" convention, and prepare for backend-specific control, as a foundational step in the ODB abstraction effort. This v2 part 1 contains only the preparatory refactoring of reading and writing logic; the introduction of pluggable `read_commit_graph` and `write_commit_graph` callbacks in `struct odb_source` and the move of path-derivation logic into `odb/source-files.c` are deferred to part 2.

Current status: Under review. v2 part 1 (seven patches) has been submitted, addressing Junio C Hamano's feedback on v1 patch 1. Patch 1 moves trailer-hash verification into the chain-loading loop itself, validating `oideq(&g->oid, &oids[i])` immediately after each layer is loaded from disk via `load_commit_graph_chain_fd_st()`, and truncating the chain at the first mismatch rather than using unverified layers. Patch 2 renames the static `add_graph_to_chain()` to the public `commit_graph_link_base()` and changes its signature to accept only the new tip layer `g` and the existing chain `base`, eliminating the redundant `struct object_id *oids` array parameter; instead of comparing against a pre-read array of OIDs from the chain file, the function now walks the `base_graph` linked list to derive each base layer's hash directly from the already-loaded `struct commit_graph` instances, and error semantics shift from boolean to the integer convention where 0 means success. The caller `load_commit_graph_chain_fd_st()` is updated to no longer allocate the `oids` array, using a stack-allocated `struct object_id` for per-line parsing instead. Patch 3 renames `load_commit_graph_one_fd_st()` to `commit_graph_read()` and removes the redundant `dir` parameter from the loading function, consolidating path assignment into `load_commit_graph_one()` (the function slated to move into the files backend in part 2) so that generic read logic is not exposed to directory paths. Patch 4 exposes a new public function `commit_graph_validate_chain()` that wraps the static helpers `validate_mixed_generation_chain()` and `validate_mixed_bloom_settings()`, replacing the direct calls at the end of `load_commit_graph_chain_fd_st()` so that the ODB backend in part 2 can invoke chain validation itself. No merge status reported; part 2 is expected to follow.

Key technical details: Files touched: `commit-graph.c`, `commit-graph.h`, `builtin/commit-graph.c`, `t/t5324-split-commit-graph.sh`. New or renamed symbols: `commit_graph_link_base()` (replaces `add_graph_to_chain()`, now public), `commit_graph_read()` (replaces `load_commit_graph_one_fd_st()`, now without `dir` parameter), `commit_graph_validate_chain()` (new public wrapper around mixed-generation and mixed-Bloom validation), `commit_graph_write_allowed()`, `commit_graph_write_layer()`. Patch 1 switches error returns from boolean to integer ("0 means success") and moves the trailer-hash comparison out of the chain-linking function into the loading loop, verifying every layer's trailer hash against the chain file record via `oideq(&g->oid, &oids[i])`; on mismatch the layer is freed and the chain truncated, making the `oid` field in `struct commit_graph` read-accessible. Patch 2 makes `commit_graph_link_base()` walk the `base_graph` linked list to derive base layer hashes directly from loaded `struct commit_graph` instances rather than from a pre-read OIDs array, and updates `load_commit_graph_chain_fd_st()` to use a stack-allocated `struct object_id` for parsing instead of allocating an `oids` array. Patch 3 removes the `dir` parameter from `commit_graph_read()` and sets the graph's directory path in `load_commit_graph_one()` instead, with `builtin/commit-graph.c` updating its call site in `cmd_commit_graph_verify()` to use the new name and signature. Patch 4 makes `commit_graph_validate_chain()` public so the future ODB backend can call it; it wraps `validate_mixed_generation_chain()` and `validate_mixed_bloom_settings()` and is called from `load_commit_graph_chain_fd_st()` with no behavior change. Later patches switch layer mergeability from path-based to depth-based comparisons (`mergeable_layers`/`chainable_layers`), introduce a common exit path in `write_commit_graph_file()` that rolls back the lock file on every error, replace the `incomplete_chain` out-parameter with an `incomplete` field in `struct commit_graph`, and derive layer information directly from the chain structure rather than maintaining parallel state. No on-disk format changes.

Open questions and loose ends: Whether the depth-based merge strategy sufficiently generalizes for future backends remains open. Patrick has questioned whether the series split improves reviewability. Whether the stricter trailer validation belongs in the generic chain loader or should be backend-specific remains a design consideration for part 2, which will move chain-creation logic into the object database backend.
