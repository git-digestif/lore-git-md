This thread is Patrick Steinhardt’s 12-patch series introducing pluggable commit graphs as part of the broader ODB abstraction effort. The goal is to move commit-graph storage logic into the “files” ODB backend, allowing alternative backends to control where commit graphs are read and written. This is infrastructure work with no user-facing changes yet, but it’s a key step toward making Git’s object storage more modular.

The series is currently under review, with v1 posted on July 10, 2025. The first patch, which just arrived, refactors how commit-graph chains are linked by simplifying the logic and removing redundant object ID tracking. This prepares the code for later patches that will move chain-creation logic into the ODB backend. The changes are mechanical but necessary for the series’ goal of making commit-graph storage backend-agnostic.

So far, only Patrick has weighed in, framing the series as a necessary step for ODB abstraction. Open questions include whether the design is flexible enough for future backends to avoid the commit-graph data structure entirely, and whether moving path logic into the backend might complicate caching or introduce redundant I/O. The series depends on Patrick’s prerequisite branch `ps/commit-graph-write-refactor` and is part of the larger ODB abstraction effort led by him and Justin Tobler. No merge status has been reported yet.
