This thread covers Patrick Steinhardt's v2 part 1 of a seven-patch series that refactors commit-graph internals as groundwork for the ODB abstraction effort, deferring the actual pluggable backend hooks to a follow-up part 2. The series simplifies chain management, unifies error handling to the "0 means success" convention, and exposes interfaces the future backend will need. Patch 4, the latest in the thread, exposes `commit_graph_validate_chain()` as a public function wrapping the existing static checks for compatible generation-data and Bloom-filter settings across chain layers, so the ODB backend can invoke validation itself once loading moves there; current behavior is unchanged. Earlier patches in the series moved trailer-hash verification into the chain-loading loop, reworked `commit_graph_link_base()` to derive base hashes from the loaded chain rather than a separate OID array, and isolated path handling from the generic read function via `commit_graph_read()`. Junio C Hamano's review of v1 prompted several of these changes, including the trailer validation that made the `oid` field readable. The series remains under review with no merge status reported, and part 2 is expected to follow.
