This is the final patch in Patrick Steinhardt’s 12-part series introducing **pluggable commit graphs** for the ODB abstraction effort. It completes the isolation of commit-graph path logic by internalizing all remaining path-dependent code into the "files" ODB backend, leaving only backend-agnostic orchestration in the core subsystem.

The patch removes the last external caller (`git commit-graph verify`) that relied on hardcoded commit-graph paths, replacing it with backend-specific functions (`odb_source_files_read_commit_graph_dir` and `odb_source_files_write_commit_graph_dir`). These functions are exposed solely for the `git commit-graph` command’s `--object-dir` option, which is now explicitly rejected for non-"files" backends. The patch also privatizes all path-derivation helpers (e.g., `get_commit_graph_filename`, `open_commit_graph`) by making them `static` and removing their declarations from `commit-graph.h`.

The changes are mechanical but invasive: 123 lines added, 124 removed, with the bulk of the diff moving logic from `commit-graph.c` to `odb/source-files.c`. The new backend-specific functions wrap the existing loading/writing logic, now operating on `struct odb_files_dir` instead of raw paths. No behavior changes are introduced, but the patch enables future backends to implement their own storage logic without being constrained by the "files" backend’s assumptions.

This is a well-crafted infrastructure refactor. The commit message clearly explains the motivation (internalizing path logic for pluggability), and the patch itself is a clean mechanical transformation. The series as a whole is a critical step toward ODB abstraction, and this final patch ties off the loose ends left by the earlier refactors. Worth attention from anyone following the ODB effort, though it’s unlikely to spark controversy given its narrow scope.
