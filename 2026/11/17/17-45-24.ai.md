This is a substantive review reply confirming the root cause of the submodule linked-worktree crash. Adrian Ratiu acknowledges Andreas Wendleder's reproducer and explains that the `BUG()` in `validate_submodule_legacy_git_dir()` (submodule.c:2414) predates `extensions.submodulePathConfig` but only became reachable after commit 9cf8547320 ("clone: prevent clashing git dirs when cloning submodule in parallel", 2024-01-28), which caused `submodule_move_head()` to validate the gitdir path read from disk. He notes that a path read from disk should never trigger a `BUG()`, and explains that the reproducer requires a second linked worktree because the primary checkout's gitdir (`.../sub`) accidentally satisfies the suffix check. He confirms that test t2405 creates this exact layout but never exercises a recursive checkout. Adrian also admits the misleading "refusing to create/use" hint when `extensions.submodulePathConfig` is already enabled is his error. He reports having a local fix that allows the branch switch to succeed in both legacy and `submodulePathConfig` modes without touching the main submodule checkout, and says he will send the patch shortly with a `Reported-by` trailer for Andreas.
