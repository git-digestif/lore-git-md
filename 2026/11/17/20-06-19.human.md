This is a bounds-safety refactoring in the UTF-8 handling code, sent as a standalone v2 patch by Junio C Hamano and currently under review. It introduces a new helper, `display_mode_esc_sequence_len_counted()`, in `utf8.c` that scans for ANSI display mode escape sequences (such as `\033[1;31m`) at the start of a buffer while respecting an explicit length parameter, ensuring it never reads at or beyond `ptr[len]`.

The existing `display_mode_esc_sequence_len()` relied on NUL termination to bound its scan, which is unsafe for callers working with counted buffers like `utf8_strnwidth()`. The patch keeps the original function as a thin wrapper that calls the counted variant with `strlen(s)`, preserving the API for NUL-terminated strings while making the bounded version available where needed.

All internal callers are updated to use the counted form: `utf8_strnwidth()`, `strbuf_add_wrapped_text()`, and `strbuf_utf8_replace()` now pass the remaining byte count to the end of their respective buffers. As a small side optimization, `strbuf_add_wrapped_text()` computes the `end` pointer once upfront from `strlen(text)` instead of recalculating the remaining length in each loop iteration. The diff touches only `utf8.c` and `utf8.h` and looks clean and mechanical.

The commit message notes this prepares the way for new callers that need bounded scanning, suggesting the maintainer anticipates further patches in this area. With no objections recorded yet, this looks like a straightforward correctness improvement to the ANSI-sequence parsing logic that avoids potential out-of-bounds reads on non-NUL-terminated input.
