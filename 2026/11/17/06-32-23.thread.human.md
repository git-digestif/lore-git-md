Sami Jawhar has filed a bug report about `git diff-tree --cc` producing incorrect output for octopus merges with many parents: at 33 and 63 parents the hunk headers disagree with the hunk bodies, and at 64 parents no hunks are produced at all. He traced the root cause to `coalesce_lines()` in `combine-diff.c`, where `baseend->parent_map |= 1<<parent` shifts a plain `int` into an `unsigned long` field, overflowing beyond 32 parents on 64-bit systems and hitting undefined behavior at 64. The bug is confirmed present in both Git 2.43.0 and current master.

Aniket Gupta confirmed the diagnosis and volunteered to send a fix patch, asking whether he should also handle merges exceeding 64 parents; Sami Jawhar has now replied with a simple "Yes, please do," granting permission to proceed. Neighboring functions in the same file already use the correct `1UL<<num_parent` form, so the expected fix is straightforward. No patch has been posted yet, no test has been added, and no maintainer has weighed in, so the thread remains open awaiting Gupta's proposed fix.
