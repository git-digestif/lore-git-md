This is a substantive review reply confirming a submodule crash bug and promising a fix. Adrian Ratiu acknowledges Andreas Wendleder's report of a `BUG()` abort in `validate_submodule_legacy_git_dir()` when a superproject worktree has `submodule.recurse=true` and its submodule is itself a linked worktree of the submodule repository.

Ratiu traces the root cause to commit 9cf8547320 (January 2024), which made `submodule_move_head()` validate the gitfile path read from disk, meaning untrusted paths can now reach the assertion. He explains that the reproducer requires a second linked worktree because the primary gitdir path `.../sub` coincidentally ends with the submodule name, allowing the check to pass by accident. He also notes that test t2405 already creates this layout but never exercises a recursive checkout. Ratiu admits the misleading hint suggesting users enable `extensions.submodulePathConfig` when it is already enabled was his own mistake.

He states he has a local fix that makes the reproduction script switch branches cleanly in both legacy and `submodulePathConfig` modes without touching the main submodule checkout, and he will send it in the coming days with Wendleder credited as the reporter.
