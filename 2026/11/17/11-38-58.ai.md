This is the fifth and final patch of a five-patch bugfix series (v2) addressing loose object size handling and `long`-versus-`size_t` truncation bugs on LLP64 platforms such as 64-bit Windows. The patch fixes a heap overflow in `combine_notes_concatenate()` in `notes.c`, where concatenating two notes totaling 4 GiB or more caused the buffer length to be computed in a 32-bit `unsigned long`, truncating the allocation size while `memcpy()` still copied the full 64-bit lengths, writing far past the end of the buffer. The fix changes `buf_len` to `size_t` and computes it with `st_add3()` for overflow safety, then passes it through `cast_size_t_to_ulong()` only at the call to `odb_write_object()`, whose length parameter still requires `unsigned long`; on affected platforms this now dies cleanly instead of silently writing a truncated blob. The commit message notes the trigger can be as simple as displaying a notes tree containing multiple notes for the same object at different fanout levels, or fetching a notes ref, and that no automated test is included because reproducing it requires both a 32-bit `long` platform and notes exceeding 4 GiB. This patch complements patches 2/5 and 4/5 in the same series, which address similar truncation issues in the loose object reader and `cat-file --batch`, and it highlights the lingering API limitation that `odb_write_object()` has not yet been converted to `size_t`.
