This is the first patch in a three-part bugfix series targeting a memory leak in `apply.c`'s `parse_git_diff_header()` function. The leak occurs when processing patches containing multiple `diff --git` lines (e.g., an empty section followed by a valid diff), as the function overwrites `patch->def_name` without freeing the previous value. The fix is a one-line addition (`free(patch->def_name)`) before assigning the new name, which is safe because both callers initialize the `patch` struct to zero.

The patch includes a new test in `t/t4133-apply-filenames.sh` that verifies the fix by applying a patch with an empty `diff --git` line followed by a valid diff. Without the fix, this test fails under `SANITIZE=leak`. The test is minimal but sufficient to cover the leak scenario, and it aligns with the series' broader goal of enforcing stricter validation in the apply machinery.

This is a **well-scoped, uncontroversial fix** that addresses a minor but real issue identified during review of the larger crash bug. The memory leak is not user-visible (it only affects edge cases like test scripts with malformed patches), but fixing it enables the reinstatement of a previously dropped test case and ensures the codebase remains leak-free. The change is mechanical and low-risk, as the `free()` is guarded by the same logic that assigns the new value. No philosophical debate is expected, and the patch is ready for final review.
