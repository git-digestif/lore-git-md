This is an author reply within the `[PATCH 0/4] odb: eagerly create tmp-objdir at transaction start` thread, specifically addressing Karthik Nayak's open question on patch 4/4 about why large numbers of loose objects are not expected in ODB transactions.

Justin Tobler answers that loose objects enter a transaction only when an incoming packfile falls below the unpack limit (default 100 objects) or when objects are added directly, for example via `git add`. He acknowledges the edge case where a user adds a new tree containing many objects for the first time, but argues the eager-creation overhead is per-object and small relative to the cost of writing the object itself, so the 7% slowdown seen in the micro-benchmark should not be noticeable in typical workloads. He commits to clarifying this reasoning in the commit message of the next version.

This response closes the last unresolved technical question from the review of patch 4/4, which removes the lazy-creation logic (`odb_transaction_files_prepare()`) in `object-file.c` and makes temporary directory creation eager at transaction start.
