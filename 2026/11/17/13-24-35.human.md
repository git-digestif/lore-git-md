This is a **feature patch** -- the third of four in Harald Nordgren's v8 series adding change-based branch deletion to `git branch`. It introduces the new `--delete-integrated <pattern>` flag, which extends the existing `--delete-merged` behavior to also remove branches whose *changes* (but not their commit tips) have landed upstream via squash or rebase merges -- the workflows behind GitHub's "Squash and merge" and "Rebase and merge" buttons.

The patch implements the core machinery: for each candidate branch, it diffs the merge base against the branch tip to collect the changed paths and their blob OIDs, then walks upstream commits since the fork point looking for the first one whose tree contains matching blob OIDs and modes for every changed path. This tree-based comparison never reads file contents, keeping the check cheap even in partial clones. When a match is found, the branch is deleted and the output names the landing commit (e.g., `Deleted branch topic (was 1a2b3c4, landed as 9f8e7d6)`). The flag cannot be combined with `--delete-merged`, and the existing `branch.<name>.deleteMerged` config key applies to both.

Within the series, this patch provides the foundational plumbing and CLI surface; the fourth patch in the series layers on the more sophisticated `ll_merge()`-based handling for cases where upstream later modified the same files. The thread context indicates this specific patch has been explicitly reviewed and deemed uncontroversial by Junio, with earlier feedback (a variable rename) already addressed in previous versions. It touches `builtin/branch.c`, the branch documentation, and adds test coverage in `t/t3200-branch.sh` for rebase-merged, squash-merged, reverted, and partially-landed scenarios.
