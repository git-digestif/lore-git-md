This thread is a bug report from wheakerd about a runaway recursion in `git push` when a remote group contains a member with the same name as the group itself. The issue causes unbounded process spawning—over 5,000 processes in 12 seconds in the reporter’s test—because `push_multiple()` in `builtin/push.c` expands the group recursively without detecting cycles. The bug affects Git 2.56.0 and is present in `master`, `next`, and `seen` as of mid-November 2026.

The reporter provides a clear reproduction case and notes that the fetch side has a similar known issue (dating back to 2010 and 2013) that was never fixed. Jeff King previously suggested a solution—expanding groups in a single process with cycle detection—but no patch was ever submitted. The expected fix would likely involve preventing re-expansion of groups in child processes and detecting cycles during group resolution.

This is a serious correctness issue that could lead to resource exhaustion, and the reporter’s analysis is thorough. No responses or patches have been posted yet, so the thread is currently just the initial report. If you’re working on remote handling or process management, this is worth tracking.
