This is the **v3 cover letter** for a well-crafted **bugfix series** targeting a crash in `git apply --check` when processing malformed patch headers. The series is now **technically complete**, addressing all known edge cases, a memory leak, and improved error messages, with **maintainer endorsement** and **clean merges** across all integration branches (`maint`, `master`, `next`, `seen`).

The three-patch series fixes two distinct but related crash triggers in `apply.c`:
1. **Patch 1/3** plugs a memory leak in `parse_git_diff_header()` by freeing `patch->def_name` before overwriting it. This is a trivial but necessary fix to reinstate a previously dropped test case for empty `diff --git` sections.
2. **Patch 2/3** rejects patches with blank lines or non-header content (e.g., indented mode lines) after a `diff --git` line, aligning with Junio’s guidance to enforce strict parsing rules. This prevents stale `old_name`/`new_name` values from persisting in the `patch` struct.
3. **Patch 3/3** rejects patches where `---` appears before `new file mode` (for new files) or `+++` appears before `deleted file mode` (for deletions), fixing the assertion failure (`patch->is_new <= 0`) in `check_preimage()`. Error messages now reference the problematic header lines (e.g., `"---" before "new file mode"`) instead of stripped filenames, improving clarity.

The series includes **thorough test coverage** in `t/t4133-apply-filenames.sh`, verifying both `--check` and actual application (including reverse application with `-R`). Tests cover blank lines after `diff --git`, indented mode lines, and the new header-ordering edge cases. The stricter validation rejects previously accepted but corrupt patches, such as those with blank lines after `diff --git` (which Git would apply while silently ignoring mode changes).

This is a **low-risk, high-impact bugfix** for a deterministic crash in released versions (confirmed in Git 2.43 and 2.45.0). The stricter validation is a deliberate trade-off for robustness, and the series is ready for final review (likely by Eric Sunshine) to assess the memory leak fix and error message refinements. No further philosophical debate is expected, and the patches are **poised for merging** once the last technical loose ends are confirmed.
