This is a substantive review reply in the ongoing discussion of Harald Nordgren's v14 series introducing `remote.<name>.fetchRefmap`. Junio C Hamano responds to Phillip Wood's concession that `--refmap=""` could serve as an explicit opt-out, but first corrects a slip in Phillip's wording: `--refmap=""` would ignore the `.fetchRefmap` config, not the `.fetch` config, since `.fetch` provides the default refspecs rather than the dashed option.

More significantly, Junio then reverses his earlier position on override semantics. He now states that he is "completely fine" with Phillip's original proposal that any refspec carrying an explicit destination (`src:dst`) should simply ignore the refmap entirely, with the refmap applying only to refspec entries that lack their own destination. This effectively accepts Phillip's argument that command-line `src:dst` should override `fetchRefmap` configuration rather than add to it, resolving the main point of contention between them from the previous round.

The only constraint Junio insists on preserving is a clear one-to-one relationship between configuration and command line: the configuration sets the default, and the command-line option overrides it. With this concession, the dual-storage edge case that had divided the maintainer and reviewer appears settled in favor of the implicit-override behavior Phillip advocated, clearing a significant obstacle for the v14 series as it awaits final review for `master`.
