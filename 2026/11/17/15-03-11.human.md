This is a substantive review of the first patch in Harald Nordgren's five-patch v14 series introducing `remote.<name>.fetchRefmap`.

Phillip Wood replies to `[PATCH v14 1/5]`, raising a specific concern about how the new config key interacts with explicit command-line refspecs. He observes that when a user sets `fetchRefmap` and then passes a `src:dst` refspec on the command line, the current implementation stores the fetched ref in both the `fetchRefmap` destination and the command-line destination. Wood argues this dual storage is confusing because users expect a command-line `src:dst` to override configuration, not add to it -- consistent with how command-line refspecs already override `remote.<name>.fetch`. He proposes that `--refmap` and `fetchRefmap` be ignored whenever an explicit destination is given on the command line or in the `.fetch` config. The comment identifies a concrete edge case and offers a clear semantic fix, marking it as a substantive review rather than a surface-level nit.
