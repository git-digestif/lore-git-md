This is the third and final patch in a well-crafted bugfix series addressing a crash in `git apply --check` when processing malformed patch headers. The series targets the `apply.c` subsystem and is now technically complete, with all review feedback incorporated.

This patch specifically rejects patches where the `---` line appears before the `new file mode` line (for new files) or the `+++` line appears before the `deleted file mode` line (for deletions). These edge cases previously caused Git to crash with an assertion failure (`patch->is_new <= 0`) in `check_preimage()` because the `patch` struct ended up in an inconsistent state—both marking a file as "new" while also assigning it an `old_name`, or marking it as "deleted" while assigning it a `new_name`. The fix aligns with the stricter validation approach endorsed by Junio C Hamano and Phillip Wood, rejecting such patches outright with clear, actionable error messages that reference the problematic header lines (e.g., `"---" before "new file mode"`).

The patch adds two new checks in `parse_git_diff_header()` that return `-128` (a sentinel value for corrupt headers) when these invalid header orderings are detected. The error messages distinguish between file-based and line-based input sources, improving clarity for users. The accompanying test coverage in `t/t4133-apply-filenames.sh` verifies both the `--check` mode and reverse application (`-R`), ensuring the fix works in all scenarios. Notably, the tests confirm that patches generated by Git itself remain unaffected, as Git always writes the mode line before the `---`/`+++` lines.

This patch resolves the last of the root causes identified in the original bug report, completing the series. The stricter validation is a deliberate trade-off—rejecting previously accepted edge cases to enforce robustness—but this approach is now uncontroversial after maintainer and reviewer endorsement. The series is ready for final review (likely by Eric Sunshine) and is expected to graduate soon, as it merges cleanly with `maint`, `master`, `next`, and `seen`. The only remaining edge case (empty `diff --git` sections) is intentionally preserved for now, though Junio has hinted it may be revisited in the future.
