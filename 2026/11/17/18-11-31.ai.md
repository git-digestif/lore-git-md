This is a substantive review reply in the ongoing bugfix thread for `utf8_strnwidth()` bounds handling, part of Dirk Gouders's two-patch series under review. Junio C Hamano responds to Gouders's plan to replace `display_mode_esc_sequence_len()` with two new bounded helpers (`ansi_sgr_nlen()` and `ansi_sgr_nlen_multi()`), endorsing the two-function idea for maintainability but proposing a different API split: keep `display_mode_esc_sequence_len()` with its original NUL-terminated calling convention as a wrapper that computes `strlen()` and delegates to a new `display_mode_esc_sequence_len_counted()` that accepts a `size_t len` boundary. He notes that his earlier illustrative patch was lazy in changing the signature for all existing callers, and that since other in-flight topics would add more callers to this function, preserving the original API while adding the counted interface for callers that need bounds enforcement -- specifically the `utf8_strnwidth()` fix -- is the cleaner path. The thread remains open awaiting Gouders's v2 respin, which is still expected to address the mmapped-region `SIGBUS` edge case and the separate post-loop guard inside `utf8_strnwidth()` that both parties agree is necessary regardless of how the escape-sequence parser is bounded.
