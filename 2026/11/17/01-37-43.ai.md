This is the final reply in the now-closed `ps/rerere-subcommands` series, a refactoring that modernized `git rerere`'s subcommand handling by replacing its custom parsing logic with Git’s standard `OPT_SUBCOMMAND()` mechanism. The series was merged to `master` on 2025-06-25, and this email is a post-merge documentation nit from Junio C Hamano.

Junio points out a long-standing discrepancy between the man page and the actual behavior of `git rerere diff`. The documentation claims the subcommand accepts additional arguments and passes them to the system `diff` command, but the code has not done this since 2006 (commit 658f365027, "Make git-rerere a builtin"). The new per-subcommand usage strings added in patch 12/12 preserve this inaccuracy by omitting any mention of arguments, while the prose description still implies they are supported. The mismatch is purely documentary—no code changes are proposed or needed—but it is a real, if minor, issue: users who rely on the man page may be misled into expecting functionality that does not exist.

The observation is low-weight and does not affect the correctness or completeness of the refactoring series. It is a retrospective documentation cleanup opportunity rather than a blocker or regression. The thread is otherwise closed; no further discussion or patches are expected in this context.
