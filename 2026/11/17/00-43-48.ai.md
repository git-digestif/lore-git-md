This is the **third and final patch in a three-part bugfix series** addressing a crash in `git apply --check` when processing malformed patch headers. The series targets the `apply.c` subsystem and is now technically complete, with all review feedback incorporated.

This patch specifically **rejects patches where `---` appears before `new file mode` (for new files) or `+++` appears before `deleted file mode` (for deletions)**, a scenario that previously caused Git to crash with an assertion failure (`patch->is_new <= 0` in `check_preimage()`). The fix aligns with the stricter validation approach endorsed by Junio C Hamano and Phillip Wood, which treats such header ordering as corrupt input rather than attempting to normalize it. The error messages now explicitly reference the problematic header lines (e.g., `"---" before "new file mode"`), improving clarity for users. The patch includes **comprehensive test coverage** in `t/t4133-apply-filenames.sh`, verifying both forward and reverse application (`-R`) for the edge cases.

The change is minimal and surgical: it adds two validation checks in `parse_git_diff_header()` to detect and reject the inconsistent state before it propagates to `check_preimage()`. The logic is straightforward and mirrors the existing validation for other mutually exclusive header lines (e.g., `d70e9c5c8c`). The patch is **uncontroversial**—the stricter validation has already been agreed upon in prior discussion—and is expected to graduate soon. It merges cleanly with `maint`, `master`, `next`, and `seen`.

Key technical details:
- **Files touched**: `apply.c` (validation logic) and `t/t4133-apply-filenames.sh` (tests).
- **Error messages**: Now include the line number of the problematic header (e.g., `"has \"---\" before \"new file mode\" at old_before_new.diff:4"`), making them actionable.
- **Behavior change**: Patches with `+++ /dev/null` before `deleted file mode` are now rejected even without `-R`, as they were previously applied incorrectly.
- **Test coverage**: Covers both `/dev/null` and regular file paths, ensuring robustness across edge cases.

The series as a whole is ready for final review (likely by Eric Sunshine) to confirm the memory leak fix in 1/3 and the backwards-compatibility trade-offs. No further debate is expected.
