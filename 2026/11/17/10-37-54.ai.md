This is patch 2/4 of Elia Pinto's v2 bugfix series fixing integer truncation in large-file handling, specifically targeting the complete-rewrite code path in `git diff -B`. The patch widens line-count and size types from `int` to `size_t` throughout `diff.c` to prevent silent truncation when processing files of 2 GiB or more, a case that bypasses both `core.bigFileThreshold` and `MAX_XDIFF_SIZE` because `should_break()` in `diffcore-break.c` loads contents directly.

The commit rewrites several interconnected functions and struct fields: `count_lines()` now takes and returns `size_t`; `emit_rewrite_lines()` accepts `size_t` for the buffer size; `count_trailing_blank()` uses `size_t` for both its counter and the buffer size (the latter previously stored in `long`, which is 32-bit on LLP64 platforms like 64-bit Windows, causing pointer underflow for buffers over 2 GiB); and fields in `struct emit_callback` (`blank_at_eof_in_preimage`, `blank_at_eof_in_postimage`, `lno_in_preimage`, `lno_in_postimage`) are widened to `size_t` along with `add_line_count()`, `check_blank_at_eof()`, and `emit_rewrite_diff()`. Single line lengths remain `int` but are guarded by `cast_size_t_to_int()` to die rather than truncate if a line exceeds `INT_MAX`. The diffstat total accumulation uses `PRIuMAX` formatting for `uintmax_t` values.

This v2 patch directly addresses Phillip Wood's substantive review of v1, which had identified that merely widening the size parameter of `count_lines()` while keeping its `int` return type would allow the line counter itself to overflow past `INT_MAX`. The author adds two EXPENSIVE tests to `t/t4022-diff-rewrite.sh` gated on `SIZE_T_IS_64BIT` and `LONG_IS_64BIT` prerequisites: one verifies numstat and patch output for a 2 GiB file (expecting 536870912 lines), the other verifies numstat for a file with 2^31 lines. Both fail on master and with v1's partial fix. The `count_trailing_blank()` overflow is not covered by committed tests (it affects only whitespace highlighting); the author verified it via `SANITIZE=signed-integer-overflow` builds with 2200 MiB of newlines.

Potential points of contention for future discussion include whether the widened types introduce new edge cases in low-level I/O, the LLP64 `long`-vs-`size_t` issue in `count_trailing_blank()` which the author notes was found by inspection but not tested on such platforms, and whether the EXPENSIVE tests in `t4022` adequately exercise the complete-rewrite path given their disk-space and time requirements.
