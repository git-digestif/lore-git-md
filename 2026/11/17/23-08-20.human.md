This is a substantive review comment on the v2 patch, where Andy Koppe suggests extending the ANSI escape-sequence parameter scanner to accept colons in addition to digits and semicolons. The email quotes the specific loop in `display_mode_esc_sequence_len_counted()` that currently advances past `isdigit(*p) || *p == ';'` and asks Junio to add `':'` to that condition while he is touching the line.

Andy grounds the suggestion in both the specification and real-world behavior: ECMA-48 section 5.4.2 defines colons as sub-separators within control sequence parameters, and xterm (along with its compatible emulators) accepts colons in SGR sequences, treating them as the standard separator while still allowing semicolons for legacy compatibility. This is a concrete, spec-backed proposal to make the parser more permissive and more aligned with what terminals actually accept.

The comment lands in the context of Junio's bounds-safety refactoring, which introduced the counted variant to prevent out-of-bounds reads on non-NUL-terminated buffers while keeping the existing NUL-terminated API intact. Andy's suggestion would broaden which byte sequences are recognized as valid escape parameters without affecting the memory-safety guarantees of the new code. No response from Junio appears in this email, so the suggestion remains open for consideration in a potential v3.
