This is **patch 4/4 of v8** in Harald Nordgren's series adding `--delete-integrated` to `git branch`. It implements detection of squash-merged branches where upstream subsequently modified the same files, closing the gap where a squash commit contains neither the branch's version nor the fork point's version of those files.

The core addition is `merge_keeps_upstream()` in `builtin/branch.c`, which performs a path-by-path three-way merge via `ll_merge()` using the branch's blob, the upstream commit's blob, and the merge-base blob. A change counts as landed if this merge leaves the upstream version byte-identical (`result.size == upstream.size && !memcmp(...)`). This supports `.gitattributes` from the working tree/index (read once upfront via `repo_read_index()` in `find_landed_commits()` for performance), but may trigger blob downloads in partial clones. The `branch_change` struct gains `base_oid`, `upstream_oid`, and `state` fields, with a new `change_state` enum (`CHANGE_MISSING`, `CHANGE_LANDED`, `CHANGE_NEEDS_MERGE`). `changes_landed()` now runs in two passes: first checking for exact tree-entry matches via `change_state_at()`, then invoking `merge_keeps_upstream()` only for paths marked `CHANGE_NEEDS_MERGE`.

Documentation in `Documentation/git-branch.adoc` clarifies that a file counts as landed either when the upstream commit has the branch's exact blob or when merging the branch's version into the upstream version is a no-op, noting the partial-clone blob-fetch implication. Tests in `t/t3200-branch.sh` add coverage for squash merges onto upstream-modified files (expecting deletion with "landed as" attribution) and negative cases (unmerged, half-landed, conflicting branches retained).

Per the thread context, v8 contains only documentation rewording relative to v7; the code is considered technically complete and ready for integration. The known remaining gap -- not blocking -- is the "npm update" false-positive scenario where unrelated upstream changes coincidentally match a branch's diff, which would require author-check or patch-id mitigation not yet implemented.
