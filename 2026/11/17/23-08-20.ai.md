This is a substantive review reply suggesting a functional extension to Junio C Hamano's `[PATCH v2]` that introduces `display_mode_esc_sequence_len_counted()` in `utf8.c`. Andy Koppe focuses on the bounds-checked while loop inside the new counted scanner and asks whether colons should be accepted alongside digits and semicolons when parsing ANSI SGR (Select Graphic Rendition) parameter strings. He cites ECMA-48 section 5.4.2, which defines the colon (ASCII 0x3A, notation "3/10") as a sub-separator within control sequence parameters, and notes that xterm and compatible terminals treat colons as the standard separator (with semicolons as legacy), making sequences like `ESC[38:5:123m` common in practice. The concrete suggestion is to extend the loop condition from `p < end && (isdigit(*p) || *p == ';')` to also match `*p == ':'`.
