This is a substantive review containing a concrete illustrative patch. Junio C Hamano demonstrates how to add a `size_t len` parameter to `display_mode_esc_sequence_len()` so it respects the remaining-string boundary, inserting `end <= p` guards throughout the parser to prevent reads past `s + len`. The diff changes the function signature in `utf8.h`, rewrites the escape-sequence parser in `utf8.c` to stop at the supplied boundary, and updates four call sites: `format_and_pad_commit()` in `pretty.c`, plus `utf8_strnwidth()`, `strbuf_add_wrapped_text()`, and `strbuf_utf8_replace()` in `utf8.c`, each now passing the remaining byte count (`orig + len - string` or `end - text`). Junio explicitly states this change does not eliminate the need for the separate guard after the ANSI-skipping loop inside `utf8_strnwidth()` that Dirk Gouders had proposed in v1. The patch is marked as not compile-tested but sufficient to illustrate the approach of threading the `len` boundary through to `display_mode_esc_sequence_len()`, directly addressing the "contract mismatch" where the function previously lacked any length awareness.
