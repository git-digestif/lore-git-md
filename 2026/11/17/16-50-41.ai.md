This is a refactoring and bounds-safety fix to the UTF-8/ANSI handling code, sent by Junio C Hamano. The patch changes `display_mode_esc_sequence_len()` in `utf8.c` to accept an explicit buffer length (`size_t len`) rather than relying on NUL termination, ensuring it never reads at or beyond `s[len]` when scanning for ANSI display mode escape sequences (e.g., `\033[1;31m`). The function now returns the length of a complete sequence at the start of the buffer or 0 if the bytes do not form one.

All callers are updated to pass the remaining byte count: `format_and_pad_commit()` in `pretty.c` passes `ch + 1 - p`, while `utf8_strnwidth()`, `strbuf_add_wrapped_text()`, and `strbuf_utf8_replace()` in `utf8.c` pass the distance to the end of their respective buffers. Notably, `strbuf_add_wrapped_text()` now computes the `end` pointer once upfront from `strlen(text)` instead of repeatedly calling `strlen()` inside the loop. The patch touches `pretty.c`, `utf8.c`, and `utf8.h` with a clean, mechanical diff that looks well-crafted and ready for review.
