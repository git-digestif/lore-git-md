This is a substantive review reply from Junio C Hamano on the third patch of Elia Pinto's five-part v2 series fixing loose object size handling. The patch adds a post-inflation size check to the streaming loose object reader in `odb/source-loose.c`, but Junio questions the error-handling consistency: the new code emits a noisy `error()` message when the inflated byte count disagrees with the header, while an existing failure path just below silently returns -1. He argues the two should match, preferring that the low-level helper stay silent and set `st->z_state` so the caller up the chain reports the error instead, which would also make the newly added `oid` field in the stream struct unnecessary. He is not rejecting the patch but asking for a redesign of how the corruption is reported before he will approve it. The discussion sits within the broader series where patches 1/5 and 2/5 have already drawn positive maintainer attention, and this streaming-side fix is meant to mirror the validation patch 1/5 adds to the non-streaming path. No decision has been reached yet; the author is expected to respin with consistent, silent low-level error propagation.
