This three-patch series from Christian Couder tackles a latent class of bugs on LLP64 platforms like 64-bit Windows, where `long` is 32-bit but `size_t` is 64-bit. Several code paths narrowed `size_t` to `unsigned long` at API boundaries, which could silently truncate merge results or objects of 4 GiB or more. The series widens that path end to end: patch 1 changed `write_buf_to_worktree()` in `notes-merge.c` to take `size_t`, patch 2 widened the ODB write APIs (`odb_write_object()`, `odb_write_object_ext()`, `odb_source_write_object()`, `write_loose_object()`) across `odb.c`, `odb.h`, and the loose and in-memory sources, and this final patch removes the now-redundant `size > LONG_MAX` guard in `xdl_do_merge()` in `xdiff/xmerge.c` along with the LLP64-specific test restrictions in `t/t4300-merge-tree.sh`, so big-merge tests can run on 64-bit Windows. The work builds on the recently merged `jk/xdiff-size_t` and `kn/safer-mem-arithmetic-in-xdiff` efforts.

The series is at version 1 (patches 1 through 3 all posted in the initial submission); no revised version has been sent. As of the latest email, no reviews, acks, or objections have been recorded from anyone, so the series remains under review with no integration status -- it is not queued in `next`, `seen`, or `master`.

The main open item is verification on the platform the series targets: exercising the changed paths requires 64-bit Windows with `GIT_TEST_LONG=1` and enough memory and disk for a merge result just over 4 GiB, which Linux and macOS CI cannot cover. Until reviewers weigh in and Junio picks the series up, its fate is undecided.
