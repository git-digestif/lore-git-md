This is a bugfix, specifically patch 4/4 of Elia Pinto's v2 series addressing integer truncation in large-file handling. It targets two distinct overflow bugs in `git diff --stat` output: the summary totals and the graph scaling.

The patch widens the accumulation variables in `show_stats()` and `show_shortstats()` from `int` to `uintmax_t`, matching the type already used in `struct diffstat_file`. Previously, when a single file exceeded `INT_MAX` lines (possible after the complete-rewrite fix in patch 2/4) or when multiple files summed past that limit, the "insertions/deletions" summary would wrap around and display negative numbers. The prototype for `print_stat_summary()` in `diff.h` is updated accordingly, though `git apply --stat` still uses its own `int` totals and is left unchanged. Separately, `scale_linear()` now takes `uintmax_t` parameters so that the product `it * (width - 1)` is computed without overflow when rendering wide graphs for small files -- for example, a 50,000-line change with `--stat-graph-width=46000` previously printed no `+` characters at all because the intermediate calculation overflowed `int`. The result still fits in an `int` since it is capped at the graph width.

The patch adds a cheap, always-run test to `t/t4052-stat-output.sh` covering the wide-graph scaling case, which fails on master. The diffstat totals themselves are not covered by a committed test because exercising them requires multi-gigabyte inputs. This patch builds on the series' earlier work (particularly patch 2/4's widening of the complete-rewrite path) and remains under review with no merge status reported.
