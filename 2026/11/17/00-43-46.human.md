This is the first patch in a three-part bugfix series addressing a Git crash in `git apply --check` when processing malformed patch headers. Specifically, this patch fixes a memory leak in `parse_git_diff_header()` by freeing `patch->def_name` before overwriting it with a new value. The leak occurs when `find_header()` processes multiple `diff --git` lines (e.g., an empty section followed by a valid one), as the function reuses the same `patch` struct without cleaning up the previous allocation.

The fix is minimal and safe: a single `free()` call before assigning the new name. Both callers of `parse_git_diff_header()` already zero-initialize the `patch` struct, so the first assignment is guaranteed to be NULL. The accompanying test in `t/t4133-apply-filenames.sh` verifies that patches with empty `diff --git` sections still apply correctly, and the leak is now resolved (confirmed by passing under `SANITIZE=leak`).

This patch is a prerequisite for the rest of the series, as it enables the reinstatement of a previously dropped test case. The memory leak itself is minor, but fixing it ensures the series doesn’t introduce regressions in test coverage. The change aligns with Git’s coding practices and has no behavioral impact—it’s purely a correctness fix. The patch is uncontroversial and ready for integration.
