This is a substantive maintainer review containing an illustrative patch from Junio C Hamano on Dirk Gouders's two-patch bugfix series for `utf8_strnwidth()` bounds handling.

Junio provides a concrete diff showing how `display_mode_esc_sequence_len()` could be updated to accept a length limit parameter, ensuring the function never reads beyond the specified bound when parsing ANSI escape sequences. The patch touches `utf8.c`, `utf8.h`, and `pretty.c`, updating all three call sites to pass the remaining byte count. He notes explicitly that the change is not compile-tested but should suffice to illustrate the approach. Importantly, he states that this modification does not make Dirk's original fix unnecessary -- the guard after the ANSI-skipping loop in `utf8_strnwidth()` is still required to prevent `utf8_width()` from reading out of bounds.

The email follows Junio's earlier critique that the root cause is a missing boundary check after the escape-sequence loop rather than inside the sequence parser itself, though he concedes that adding the length parameter to `display_mode_esc_sequence_len()` is a good change regardless. The context remains the open concern about SIGBUS crashes when the input string points near the end of an mmapped region, which Dirk Gouders has acknowledged requires addressing in the upcoming v2.
