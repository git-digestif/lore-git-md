This is a reply in the review thread for the second patch of Adrian Ratiu's three-patch bugfix series on the `compatObjectFormat` interoperability layer, specifically addressing Patrick Steinhardt's feedback on `[PATCH 2/3]` ("rev-parse: die when --output-object-format cannot map an object").

Adrian Ratiu accepts both of Patrick's suggestions and commits to incorporating them in v2. First, he agrees to reword the hard-to-parse commit message paragraph about single-revision versus range arguments, adopting Patrick's clearer phrasing that explains only the single-revision case passes the desired output hash explicitly while ranges like `A..B` do not. Second, regarding the test in `t/t1500-rev-parse.sh`, he confirms he verified that the alternative approach works: instead of manually copying a loose object into the repository (which Patrick flagged as fragile under the upcoming ODB abstraction), the test will write the object with `extensions.compatobjectformat` unset and then set the config afterward, ensuring no compat mapping is created without direct object-database manipulation.

Adrian also notes that his real-world reproduction of the bug used JJ (Jujutsu), which he deliberately avoided adding as a test dependency, and mentions he will update JJ to reject repositories with `extensions.compatObjectFormat` since neither JJ nor Gitoxide support it. The patch's core fix -- making `git rev-parse --output-object-format` die on mapping failure rather than printing the storage OID -- remains unchanged and uncontroversial; only the commit message wording and test mechanics are being adjusted.
