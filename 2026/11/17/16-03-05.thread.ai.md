Thread identity: standalone single-patch bugfix to `git fast-import` authored by Kaartic Sivaraam, addressing error-message information disclosure in the `export-marks` feature check.

Core problem: since commit 68061e3470 (2019-08-29) made `feature export-marks=<path>` forbidden by default unless `--allow-unsafe-features` is passed, the diagnostic emitted when the feature is rejected leaks the full feature string -- including the user-supplied filesystem path -- into stderr. The `import-marks` variants do not leak because they pass only the bare feature name to `check_unsafe_feature()`.

Current status: patch submitted upstream as a standalone fix; the author notes they spotted the issue while backporting security fixes and deliberately held the cleanup until after the security release shipped. No review or integration status reported yet; under review.

Key technical details: one-line change in `builtin/fast-import.c` in `parse_one_feature()` at the `skip_prefix(feature, "export-marks=", &arg)` branch, passing the literal string `"export-marks"` instead of the full `feature` argument to `check_unsafe_feature()`. Test update in `t/t9300-fast-import.sh` strengthens the existing test `R: export-marks feature forbidden by default` to grep stderr for `feature .export-marks. forbidden` rather than only asserting command failure. Old behavior: stream with `feature export-marks=git.marks` and no `--allow-unsafe-features` dies with `feature 'export-marks=git.marks' forbidden in input without --allow-unsafe-features`. New behavior: same condition dies with `feature 'export-marks' forbidden in input without --allow-unsafe-features`, matching `import-marks` style. Enforcement logic unchanged; the feature remains forbidden under identical conditions.

Open questions and loose ends: none raised yet.

Participant positions: Kaartic Sivaraam is the sole participant so far, submitting the fix with a commit message explaining the disclosure issue and the deliberate timing relative to the security release.

Related work: references commit 68061e3470 (2019-08-29) which introduced the `--allow-unsafe-features` gating for `export-marks`; part of the broader `fast-import` unsafe-feature hardening effort.
