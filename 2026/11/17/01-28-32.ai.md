This is the maintainer's review of the penultimate patch in Patrick Steinhardt’s now-merged `git rerere` subcommand modernization series. The patch replaces the hand-rolled subcommand ladder with Git’s standard `OPT_SUBCOMMAND()` mechanism, introducing a fallback subcommand (`cmd_rerere_perform()`) for the default case.

Junio’s review focuses on a single technical point: the fallback logic’s memory handling. The code constructs a synthetic `"perform"` subcommand by pushing it into a `strvec` and then copying the array to avoid modification by `parse_options()`. Junio questions whether the `CALLOC_ARRAY()` and `COPY_ARRAY()` calls account for the terminating NULL pointer, noting that C’s `(ac, av)` convention requires `av[ac]` to be NULL. If the `strvec` does not include this NULL, the copied array would be unterminated, potentially causing issues in `cmd_rerere_perform()`. This is a substantive review concern, as it could lead to memory corruption or undefined behavior.

The rest of the patch—its core refactoring, the removal of misleading global flags, and the alignment with Git’s standard subcommand handling—is not contested. Junio’s earlier regression reports (option ordering and error reporting) have already been accepted as deliberate trade-offs, and this review does not reopen those discussions. The feedback is narrowly targeted at a latent safety issue in the fallback logic’s implementation.
