This is a follow-up in the `git history --verbose` RFC thread. D. Ben Knoble raises a practical concern about the author’s pivot to make diff display the default behavior for `git history reword` (and related subcommands) while relying solely on the `commit.verbose` configuration for control. He points out that even with a config setting, users and scripts need a **command-line option** to override the default behavior deterministically, especially in interactive or automated workflows. This echoes an earlier concern from Phillip Wood about scripted editing and reinforces the need for user control beyond configuration. The comment is brief but substantive, focusing on a real-world usability gap rather than implementation details. It does not engage with the unresolved output format debate (lightweight unified diff vs. structured multi-commit format) or the generalizability requirement, but it keeps the discussion grounded in practical workflow needs.
