This is a platform-compatibility patch, specifically the second of a three-patch series from Christian Couder targeting 64-bit Windows (LLP64) where `long` is 32-bit but `size_t` is 64-bit. The patch widens the length parameter of the object-database write APIs from `unsigned long` to `size_t` across five files: `odb.c`, `odb.h`, `odb/source.h`, `odb/source-loose.c`, and `odb/source-inmemory.c`. The functions affected are `odb_write_object()`, `odb_write_object_ext()`, the `odb_source_write_object()` wrapper, `write_loose_object()`, and the `size` field of `struct inmemory_object`.

The commit message explains that downstream consumers of these lengths already use `size_t` -- including `hash_object_file()`, `format_object_header()`, `git_zstream`, and the `write_object` callback -- so the narrowing at the API boundary risks silent truncation on LLP64 platforms when callers pass `size_t` values such as `strbuf.len`. The change also prepares for the third patch in the series, which plans to remove the `size > LONG_MAX` guard in `xdl_do_merge()` (added in 1c93cc03ea) now that the ll_merge() result flows through `size_t` all the way to the ODB layer.

The patch is small and mechanical, touching only signatures and one struct field with no logic changes. It builds directly on the recently merged `jk/xdiff-size_t` work (81db32ddce) and is clearly motivated by the LLP64 truncation hazard, though like the rest of the series it cannot be exercised by Linux or macOS CI and relies on 64-bit Windows testing with `GIT_TEST_LONG=1`.
