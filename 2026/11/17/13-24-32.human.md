This is a cover letter for the eighth iteration of a four-patch feature series from Harald Nordgren that extends `git branch` to detect squash-merged and rebase-merged branches. The series introduces a new `--delete-integrated <pattern>` option that deletes branches whose changes—but not necessarily their tips—have landed in an upstream branch, addressing a long-standing gap for users of GitHub-style "Squash and merge" workflows. The existing `--delete-merged` retains its strict tip-reachability semantics, while the new flag performs change-based detection using tree diffs and a three-way merge approximation to handle cases where upstream later modified the same files.

Version eight contains no code changes; the range-diff shows only commit-message rewording in the fourth patch to clarify how hosting services land pull requests and how partial clones may download blobs during the merge check. Earlier versions in this thread already addressed substantive review feedback, including performance optimizations (reading the index once before the walk), correct `.gitattributes` handling, and expanded test coverage for edge cases like partially landed or conflicting branches.

The series appears technically complete and ready for integration. The CLI design—splitting strict and change-based detection into separate flags—has been confirmed, and the preparatory patches are uncontroversial. The sole remaining open question is whether to add an author-check mitigation to reduce false positives in scenarios like "npm update" where different authors land identical changes, but this is not implemented and does not block the current patches.
