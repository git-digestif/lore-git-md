Junio C Hamano has sent a refactoring and bounds-safety patch to the UTF-8/ANSI handling code. The core change is to `display_mode_esc_sequence_len()` in `utf8.c`, which now takes an explicit buffer length (`size_t len`) instead of assuming NUL termination, so it can never read at or beyond `s[len]` while scanning for ANSI display mode escape sequences such as `\033[1;31m`. The function returns the length of a complete sequence at the start of the buffer, or 0 if the bytes do not form one.

All callers are updated to pass the remaining byte count: `format_and_pad_commit()` in `pretty.c` passes `ch + 1 - p`, while `utf8_strnwidth()`, `strbuf_add_wrapped_text()`, and `strbuf_utf8_replace()` in `utf8.c` each pass the distance to the end of their respective buffers. As a side improvement, `strbuf_add_wrapped_text()` now computes its `end` pointer once upfront from `strlen(text)` rather than recomputing it inside the loop. The diff touches `pretty.c`, `utf8.c`, and `utf8.h` and is described as clean and mechanical, ready for review.
