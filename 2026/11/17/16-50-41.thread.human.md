Junio C Hamano has posted version 2 of a standalone patch that fixes an out-of-bounds read risk when scanning for ANSI display mode escape sequences (such as `\033[1;31m`) in non-NUL-terminated buffers. The patch introduces `display_mode_esc_sequence_len_counted(const char *s, size_t len)` in `utf8.c`, which scans exactly `len` bytes and never reads at or beyond `s[len]`, while keeping the original `display_mode_esc_sequence_len()` as a thin wrapper for NUL-terminated callers. Three callers inside `utf8.c` (`utf8_strnwidth()`, `strbuf_add_wrapped_text()`, and `strbuf_utf8_replace()`) are switched to the counted variant; only `utf8.c` and `utf8.h` are touched, and the commit message notes the new function is partly preparatory for future external callers needing bounded scans. The patch is freshly posted and under review, with no integration branch status reported.

Dirk Gouders has replied with a substantive review offering two concrete suggestions. First, an early-return optimization (`if (len < 3) return 0;`) since the shortest valid SGR sequence `\033[m` is three bytes, which would avoid scanning in many cases. Second, he supplies a complete clar unit test suite for the new function in a new file `t/unit-tests/u-utf8-ansi.c` (registered in both the `Makefile` and `t/meson.build`), asserting specific length results for truncated and complete sequences -- notably that an untested variant he examined previously contained an off-by-one error, which is the motivation for the tests. No response from Junio has arrived yet, so the suggestions remain open and the patch stays under review.
