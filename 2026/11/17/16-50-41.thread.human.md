Junio C Hamano has posted version 2 of a standalone patch that fixes an out-of-bounds read when scanning for ANSI display-mode escape sequences in non-NUL-terminated buffers. The patch adds `display_mode_esc_sequence_len_counted(const char *s, size_t len)` in `utf8.c`, which scans exactly `len` bytes without ever reading past the buffer, and keeps the original `display_mode_esc_sequence_len()` as a thin wrapper for existing NUL-terminated callers. Three internal callers in `utf8.c` (`utf8_strnwidth()`, `strbuf_add_wrapped_text()`, and `strbuf_utf8_replace()`) switch to the counted variant. The change touches only `utf8.c` and `utf8.h` and is partly preparatory for future external callers that need bounded scans.

Dirk Gouders reviewed the patch and proposed two changes: an early-return optimization for very short strings, and a clar unit test suite for the new function. Junio rejected the early return, arguing the existing `"\033"` check already handles most short cases and that the micro-optimization was not worth the added complexity; Dirk has now conceded that point, agreeing that correctness outweighs the marginal performance gain. Junio agreed to incorporate Dirk's tests in a new file `t/unit-tests/u-utf8-ansi.c`, and Dirk has confirmed in his latest reply that Junio is welcome to use the test code as-is.

The tests verify boundary behavior of the counted variant, including that a truncated `"\033[m"` at `len=2` returns 0 while `len=3` returns 3, plus checks for `"\033[31m"` (5) and `"\033[0;31m"` (7), guarding against the off-by-one error Dirk spotted in an earlier untested variant. The patch remains under review with no integration branch status announced; a v3 folding in the agreed-upon test suite appears likely but has not yet been posted, and no Reviewed-by or Acked-by trailers have been recorded.
