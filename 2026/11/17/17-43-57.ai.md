This is the third and final patch of a three-part platform-compatibility series from Christian Couder targeting LLP64 systems such as 64-bit Windows, where `long` is 32-bit but `size_t` is 64-bit. It removes a now-redundant `size > LONG_MAX` guard in `xdl_do_merge()` (`xdiff/xmerge.c`) and relaxes the corresponding test prerequisites in `t/t4300-merge-tree.sh`.

The removed check was originally added by 288266c11d to prevent silent truncation when a merge result larger than 2 GiB was passed down to APIs that accepted `unsigned long`. That guard became unnecessary once 81db32ddce switched the merge buffer from `mmbuffer_t` (which used `long` for its size) to `mmfile_t` (which uses `size_t`), and once the downstream consumers -- `odb_write_object()` and `write_buf_to_worktree()` -- were widened to `size_t` in the first two patches of this series. With the entire path now carrying `size_t`, the `LONG_MAX` comparison no longer prevents any truncation, so the patch deletes it and allows merge results up to the full `size_t` range.

The test changes in `t/t4300-merge-tree.sh` reflect this: the two EXPENSIVE big-merge tests that previously required both `SIZE_T_IS_64BIT` and `LONG_IS_64BIT` now only require `SIZE_T_IS_64BIT`, meaning they will run on 64-bit Windows. The separate test that expected `git merge-tree` to die on LLP64 platforms (`!LONG_IS_64BIT`) is removed entirely, since merges over 2 GiB now succeed there. The test for `!SIZE_T_IS_64BIT` (32-bit `size_t` overflow) is retained because overflow in the size computation itself is still caught by the `st_add*()` checks introduced in b1313872ce.

This patch completes the series' goal of eliminating truncation points between `ll_merge()` and the object database on LLP64 platforms. It depends on the earlier patches in the series (widening `write_buf_to_worktree()` and the ODB write APIs) as well as the previously merged `jk/xdiff-size_t` work. No reviews or objections have been recorded yet. Testing the LLP64-specific path requires 64-bit Windows with `GIT_TEST_LONG=1` and enough memory/disk for a merge result just over 4 GiB; Linux and macOS CI cannot exercise the changed behavior.
