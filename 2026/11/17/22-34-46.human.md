This is a substantive review reply from Junio C Hamano on the second patch of Elia Pinto's five-part v2 series fixing loose object size handling on LLP64 platforms.

Junio approves the direction of patch 2/5 -- widening loose-object size variables from `unsigned long` to `size_t` throughout the reading path -- calling the changes "straightforward" and saying they "make sense" for preventing truncation on platforms like 64-bit Windows where `long` is 32-bit. However, he pushes back on one gap: switching to `size_t` addresses truncation but does not protect against unsigned arithmetic wrapping, and he asks whether there are spots in the touched code where the `st_add()` family of overflow-safe helpers should be used instead of plain addition. This is a genuine technical question about edge cases rather than a stylistic nit, suggesting he has read the patch closely and is probing whether the fix is complete against all overflow scenarios, not just the type-width mismatch. The series remains under review, with this patch now carrying an implicit open question about arithmetic safety before it can be considered fully addressed.
