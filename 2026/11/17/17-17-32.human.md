This is a **feature request** (RFC) proposing a new `-M` flag for `git grep` to support multi-line pattern matching, analogous to `pcre2grep -M`.

Alejandro Colomar suggests adding multi-line search capability to `git grep`, motivated by the need to search for multi-line C code constructs using the complex regexes generated by tools like `grepc(1)`. Currently, `git grep -P` can use these PCRE2 patterns but only matches within single lines; a `-M` flag would allow patterns to span line boundaries, enabling searches for function bodies, multi-line macros, and other structural code patterns across history. The email demonstrates the workflow with examples searching the Linux kernel tree for definitions like `ARRAY_END` and syscall macros, noting that while single-line matches work today, multi-line constructs currently require piping through external tools like `git show` plus `grepc`.

The proposal is conceptual rather than a patch -- it asks whether the feature makes sense without providing an implementation. It builds on existing `git grep -P` (PCRE2) support and would primarily benefit developers doing structural code search across repository history.
