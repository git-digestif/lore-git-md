This is a bugfix for the `pretty` subsystem, specifically the third iteration (`v3`) of a single-patch series by Andy Koppe that fixes ANSI color handling in custom `git log --format=...` output. The patch modifies `repo_format_commit_message()` in `pretty.c` to post-process formatted output when color is enabled, calling a new static helper `make_line_colors_self_contained()` that scans the strbuf for ANSI escape sequences, tracks active colors since the last reset, inserts a reset before any newline where colors are active, and replays those colors at the start of the next non-empty line unless that line begins with its own reset. A final reset is appended if colors remain active at the end of the buffer. The implementation avoids buffer copies unless necessary, using `memchr()` and `strcspn()` to skip through the text efficiently.

Version 3 contains no functional changes from v2; it is purely a code clarity refactoring of the new algorithm. The author combined the previously separate reset and replay conditionals into a single if-else chain, and renamed the local variables `is_reset` to `reset`, `is_reset_only` to `reset_only`, and `end` to `reset_end` for consistency with the `replay` flag. The range-diff shows only these renaming and control-flow simplifications within `make_line_colors_self_contained()`.

The patch touches `pretty.c` and adds seven new test cases to `t/t4205-log-pretty-formats.sh` covering colors carrying across explicit `%n` line breaks, wrapped lines via `%w()`, automatic reset at commit boundaries, empty lines, manual `%x1b` escape sequences, NUL byte handling, and integration with `--graph` output. The commit message explains that the runtime approach is necessary because placeholders like `%w` and `%b` cannot provide per-line color control through the existing API, and notes that formats relying on `--graph` or pagers to reset colors at line breaks will now need explicit resets.

Thread context indicates this builds on v1 and v2, which Junio C Hamano reviewed substantively and endorsed after acknowledging the API gap that prevents per-line color control in multi-line placeholders. No objections to the implementation or test coverage were raised, and the series remains under review with no merge status reported. The base commit is `03b41523c5` on `maint`.
