This is the **v3 cover letter** for a **three-patch bugfix series** targeting the `apply.c` subsystem, addressing a crash in `git apply --check` when processing malformed patch headers. The series is now **technically complete**, incorporating all review feedback: stricter validation, a memory leak fix, and improved error messages.

The core issue—a deterministic crash in released versions (confirmed in Git 2.43, 2.45.0, and `master`)—stems from inconsistent state in the `patch` struct when parsing corrupt headers. The series now **rejects such patches outright** with clear, actionable error messages, aligning with Junio C Hamano’s guidance to enforce strict parsing rules (only accepting formats generated by `git diff` or `git format-patch`). Key changes since v2:
- **Patch 1/3**: Fixes a memory leak in `parse_git_diff_header()` by freeing `patch->def_name` before overwriting it. This is a trivial but necessary fix to reinstate a previously dropped test case.
- **Patch 2/3**: Rejects patches with blank lines or non-header content after `diff --git` (e.g., indented mode lines), now treating them as errors rather than attempting to normalize them. This resolves the root cause of the crash (stale `old_name`/`new_name` values).
- **Patch 3/3**: Rejects patches where `---` appears before `new file mode` (for new files) or `+++` appears before `deleted file mode` (for deletions), with error messages referencing the problematic header lines (e.g., `"---" before "new file mode"`) instead of stripped filenames (e.g., `dev/null`).

The series includes **comprehensive test coverage** in `t/t4133-apply-filenames.sh`, verifying both `--check` and actual application (including reverse application with `-R`). Tests cover blank lines after `diff --git`, indented mode lines, empty diff sections, and the new header-ordering edge cases. The stricter validation is a deliberate trade-off: it rejects previously accepted edge cases (e.g., patches with blank lines after `diff --git`) to enforce robustness, but this is now uncontroversial after maintainer and reviewer endorsement.

**Status**: Ready for final review (likely by Eric Sunshine) to assess the memory leak fix and backwards-compatibility implications. The series merges cleanly with `maint`, `master`, `next`, and `seen`, and is expected to graduate soon. The only remaining edge case—empty `diff --git` sections followed by another `diff --git`—is intentionally preserved (per 206de27efa), though Junio has hinted this may be revisited in the future. No further philosophical debate is expected.
