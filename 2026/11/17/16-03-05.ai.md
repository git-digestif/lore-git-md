This is a small bugfix to `git fast-import`'s error reporting, submitted as a standalone patch by Kaartic Sivaraam. Since commit 68061e3470 (2019-08-29) made `feature export-marks=<path>` forbidden by default unless `--allow-unsafe-features` is given, the resulting error message has leaked the full feature string -- including the filesystem path supplied by the user -- into the diagnostic output. The `import-marks` variants do not have this problem because they pass only the bare feature name to `check_unsafe_feature()`, so the author makes `export-marks` behave consistently by passing the literal string `"export-marks"` instead of the full `feature` argument in `parse_one_feature()` in `builtin/fast-import.c`.

The patch touches two files: the one-line change in `builtin/fast-import.c` at the `skip_prefix(feature, "export-marks=", &arg)` branch, and a corresponding update to `t/t9300-fast-import.sh` where the existing test `R: export-marks feature forbidden by default` is strengthened to grep stderr for `feature .export-marks. forbidden` rather than merely asserting that the command fails. The commit message notes the author spotted this while backporting security fixes and deliberately waited for the security release to ship before sending the cleanup upstream.

Old behavior: a stream containing `feature export-marks=git.marks` without `--allow-unsafe-features` dies with `feature 'export-marks=git.marks' forbidden in input without --allow-unsafe-features`. New behavior: the message reads `feature 'export-marks' forbidden in input without --allow-unsafe-features`, matching the style of the `import-marks` messages and avoiding disclosure of the path in the error text. This is purely a message-consistency fix with no change to the actual enforcement logic; the feature remains forbidden under the same conditions.
