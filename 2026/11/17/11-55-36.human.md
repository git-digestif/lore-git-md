This is a review-response email in Adrian Ratiu's three-patch bugfix series for the `compatObjectFormat` interoperability layer. Adrian is replying to Patrick Steinhardt's feedback on the second patch, which fixes `git rev-parse --output-object-format` to die when it cannot map an object instead of silently printing the wrong OID.

Adrian acknowledges two points from the review. First, he agrees to reword a hard-to-parse paragraph in the commit message that explains the fix only covers single-revision arguments. Second, and more substantively, he accepts Patrick's suggestion to rewrite the test so it does not manually copy loose objects into the repository -- a technique that could break when the object database abstraction changes the on-disk storage format. Instead, the test will write the object with `extensions.compatobjectformat` unset and enable the extension afterward, which Adrian has verified achieves the same result without touching the object store directly.

He also adds a brief anecdote that he originally reproduced the bug in the wild using Jujutsu (jj), and notes he plans to make jj reject repositories with `extensions.compatobjectformat` set, since neither jj nor gitoxide supports the feature. Both changes are slated for v2 of the series; the underlying fix itself remains uncontroversial.
