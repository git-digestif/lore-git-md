This is a substantive design discussion within Harald Nordgren's v14 patch series introducing `remote.<name>.fetchRefmap`, specifically a reply from Phillip Wood to Junio C Hamano debating how command-line refspecs should interact with the new configuration.

Phillip Wood pushes back against Junio's symmetry argument by focusing on actual user mental models: most users, he contends, do not know `--refmap` exists and are accustomed to a command-line `src:dst` overriding their configured `.fetch` values, so they will be surprised if it does not also override `.fetchRefmap`, potentially causing refs to be stored in two places. Junio had argued that since command-line refspecs override `.fetch` (refspec defaults) while `.fetchRefmap` provides defaults for `--refmap`, it would be confusing for the former to also override the latter; Phillip counters that this distinction is too subtle for users who are unfamiliar with `--refmap`'s corner cases.

Phillip also identifies a documentation gap, noting that the current man page text about `--refmap` overriding `remote.<repository>.fetch` only applies when `.fetch` is acting as a mapping, and it is unclear whether the documented behavior of `--refmap` combined with an explicit command-line destination actually matches what the code does. This observation adds weight to his argument that the current behavior may already be surprising or undocumented in this specific scenario.

The discussion appears to converge on a practical resolution: Phillip accepts Junio's suggestion that `--refmap=""` could serve as an explicit opt-out mechanism, since `--refmap` overrides configuration and an empty value is already the documented way to ignore the `.fetch` config. This would let users who want to bypass `fetchRefmap` do so explicitly without changing the default override semantics that Phillip argues users expect.

For readers following the thread, this exchange leaves the override semantics question with a proposed compromise: maintain Phillip's position that command-line `src:dst` should override `fetchRefmap` by default, while using `--refmap=""` (or a future `--no-refmap`) as the escape hatch when users want to ignore that configuration entirely. The series remains under final review, with this design point now having a clearer path forward.
