This is a small hardening patch from Junio C Hamano that changes the internal helper `display_mode_esc_sequence_len()` to accept an explicit buffer length instead of relying on NUL termination. The function, which measures ANSI color escape sequences (like `ESC [ 1 ; 31 m`), previously scanned until it hit a NUL byte; now it takes a `<ptr, len>` pair and guarantees it never reads at or beyond `ptr[len]`. This closes the door on potential out-of-bounds reads when callers pass counted buffers or need to stop at a specific position.

The patch touches three files: `utf8.h` (the prototype), `utf8.c` (the implementation plus three call sites), and `pretty.c` (one call site in `format_and_pad_commit()`). All callers are updated to pass the remaining byte count. In `strbuf_add_wrapped_text()`, which receives a NUL-terminated string, the author computes the end pointer once up front rather than calling `strlen()` inside the loop, which is a minor efficiency improvement alongside the safety fix.

The change is mechanical and well-contained, typical of the maintainer's own clean-up work. It does not alter user-visible behavior but makes the internal API safer for future use with non-NUL-terminated buffers. Given the author and the tight scope, this looks like a straightforward fix that is likely to be picked up without controversy.
