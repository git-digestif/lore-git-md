This is a **cover letter for a feature patch series** (v8 of 4 patches) extending `git branch --delete-merged` with change-based detection of squash- and rebase-merged branches.

The series introduces a new opt-in flag `--delete-integrated <pattern>` alongside the existing `--delete-merged <pattern>` (which remains strictly tip-reachability based). `--delete-integrated` detects branches whose changes landed upstream via squash or rebase merges even when their tips are unreachable, including cases where upstream modified the same files before integration. The detection uses tree-based diffing for rebase detection (no blob fetches) and a path-by-path three-way merge approximation via `ll_merge()` for squash merges with upstream modifications (may download blobs in partial clones). The output format is extended to `Deleted branch topic (was 1a2b3c4, landed as 9f8e7d6)`.

Files touched: `builtin/branch.c`, `Documentation/git-branch.adoc`, `Documentation/config/branch.adoc`, `t/t3200-branch.sh`. Key symbols include `find_landed_commits()`, `merge_keeps_upstream()`, the `landing_search` struct, `DELETE_BRANCH_INTEGRATED` flag, and the `branch_opted_out()` helper. Config key `branch.<name>.deleteMerged` applies to both flags.

Compared to v7, **v8 contains only commit-message and documentation rewording in patch 4/4** -- specifically clarifying the explanation of GitHub's "Squash and merge" workflow and the partial-clone blob-download behavior. No code changes. The series remains technically complete and ready for integration per prior review; the sole outstanding technical gap (not blocking) is the author-check mitigation to prevent false positives where unrelated upstream changes coincidentally match a branch's diff.
