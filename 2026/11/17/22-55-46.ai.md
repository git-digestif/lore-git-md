This is a **substantive review** of patch 3/5 in Elia Pinto's five-patch v2 series on loose object size handling. Junio C Hamano is responding to the proposed addition of a post-inflation size check in `read_istream_loose()` that compares the streamed byte count against the header-declared size and emits a "corrupt loose object" error on mismatch.

Junio identifies a consistency problem in the patch's error-handling strategy. The new code calls `error()` unconditionally when the size check fails, yet the very next failure path in the same function (visible in the diff context) returns -1 silently. He argues that mixing noisy and silent error returns within one low-level helper is inconsistent. His preference is to keep the low-level function silent, set `st->z_state = ODB_LOOSE_READ_STREAM_ERROR`, and let a caller higher in the chain inspect that state to produce the error message.

As a direct consequence of choosing the silent approach, Junio notes that the patch's addition of an `oid` field to `struct odb_loose_read_stream` -- and the `oidcpy()` needed to populate it -- becomes unnecessary overhead, since the OID would only be used to format the error message locally. The review thus suggests simplifying the patch by removing both the noisy `error()` call and the new struct member, relying instead on the existing error-state mechanism to propagate failure upward.

This is patch 3/5 of the series, which complements patch 1/5 (already approved) by extending the same header-vs-inflated-size validation to the streaming path used by `git cat-file blob`. The feedback is design-level rather than cosmetic: it addresses how errors should be reported through the `odb_source_loose` streaming API. The patch remains under review with no maintainer decision recorded yet; Junio's comments here indicate the direction he would like the error handling to take, but the author has not yet responded to rework the patch accordingly.
