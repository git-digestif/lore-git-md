This is a review exchange on Junio C Hamano's bounds-safety patch (`[PATCH v2] utf8: add display_mode_esc_sequence_len_counted()`), which introduces a length-bounded variant of the ANSI escape-sequence scanner to prevent out-of-bounds reads on non-NUL-terminated buffers.

Andy Koppe has suggested extending the new parser to accept colons (`:`) as parameter separators in SGR sequences (e.g. `ESC[38:5:123m`), citing ECMA-48 and common xterm behavior where colons are the standard sub-separator. Junio responds by questioning whether this is necessary: he notes the function is not counting widths of end-user supplied strings, but rather of sequences Git itself paints into a buffer, and asks whether Git actually generates colon-separated sequences. The question remains open, with no response yet recorded from Andy.
