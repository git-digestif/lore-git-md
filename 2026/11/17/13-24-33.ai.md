This is a preparatory refactoring patch, specifically the first of four in version 8 of Harald Nordgren's series extending `git branch` deletion logic. The patch extracts the existing `branch.<name>.deleteMerged` opt-out check from `delete_merged_branches()` into a new static helper function named `branch_opted_out()` in `builtin/branch.c`. The helper takes a `struct strbuf *` for the config key, the branch name, and deletion flags, and returns true if the branch should be skipped because the config is set to false, printing the skip message unless quiet mode is active. No behavior changes; it is purely mechanical preparation for a later patch in the series.

Within the series context, this refactoring enables the upcoming `--delete-integrated` flag (introduced in patch 3/4) to honor the same `branch.<name>.deleteMerged=false` configuration that already applies to `--delete-merged`. By moving the check into a shared helper, both deletion paths can use identical opt-out logic without duplication. The thread context indicates this patch and the following one are explicitly uncontroversial and ready for integration, with no substantive objections raised by Junio or other reviewers.

Technically, the diff touches only `builtin/branch.c`, adding 19 lines and removing 13. The new `branch_opted_out()` function encapsulates the `repo_config_get_bool()` lookup for the `branch.%s.deletemerged` key and the conditional stderr message. The call site in `delete_merged_branches()` is simplified to use this helper, adding the branch to the deletable set only when `branch_opted_out()` returns false. Future follow-up discussion in this thread may reference this helper when discussing whether `--delete-integrated` should reuse the same config key or introduce a separate one.
