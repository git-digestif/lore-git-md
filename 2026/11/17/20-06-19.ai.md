This is a bounds-safety bugfix and refactoring in Git's UTF-8/ANSI escape-sequence handling, sent as `[PATCH v2]` by Junio C Hamano. It introduces a new counted-buffer variant of the ANSI escape-sequence scanner to prevent out-of-bounds reads on non-NUL-terminated buffers while preserving the existing API for NUL-terminated callers.

The patch adds `display_mode_esc_sequence_len_counted(const char *s, size_t len)` in `utf8.c` (declared in `utf8.h`), which scans for a complete ANSI display mode escape sequence (e.g., `ESC [ 1 ; 31 m`) at the start of exactly `len` bytes and guarantees it never reads at or beyond `s[len]`, returning the sequence length or 0. The original `display_mode_esc_sequence_len(const char *s)` is retained as a thin wrapper that calls the counted variant with `strlen(s)`, so existing NUL-terminated callers are unaffected. The commit message notes this is partly preparatory for new external callers that want to use the bounded scan.

Three callers inside `utf8.c` are switched to the counted variant: `utf8_strnwidth()` now passes `orig + len - string` as the remaining length; `strbuf_add_wrapped_text()` computes `end = text + strlen(text)` once upfront and passes `end - text` in its loop instead of relying on NUL termination; and `strbuf_utf8_replace()` passes `end - src`. The diff touches only `utf8.c` and `utf8.h` (27 insertions, 9 deletions); unlike the earlier thread context suggested, this v2 does not modify `pretty.c`. The patch is freshly posted and under review with no integration-branch status yet.
