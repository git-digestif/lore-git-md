This is a platform-compatibility patch -- specifically the second of three from Christian Couder addressing LLP64 systems like 64-bit Windows, where `long` is 32-bit but `size_t` is 64-bit. It widens the object-length parameters in Git's object-database write path from `unsigned long` to `size_t`, touching `odb_write_object()`, `odb_write_object_ext()`, the `odb_source_write_object()` wrapper, `write_loose_object()`, and the `size` field in `struct inmemory_object` across five files in the `odb/` directory.

The motivation is twofold. First, many callers already pass `size_t` values -- often `strbuf.len` -- that could silently truncate on Windows when narrowed to a 32-bit `unsigned long`. Second, the change prepares for the third patch in the series, which removes the `size > LONG_MAX` guard in `xdl_do_merge()`; once that guard is gone, merge results larger than 4 GiB can flow through, so the write APIs need to handle full `size_t` values without truncation. The commit message helpfully references the two recently merged series this builds on (`jk/xdiff-size_t` and `kn/safer-mem-arithmetic-in-xdiff`).

This patch sits in the middle of a broader effort to make Git's internals safe on platforms where `long` is narrower than `size_t`. Patch 1 fixed a similar truncation in `notes-merge.c`, and patch 3 will update the xdiff merge code and tests. The diff itself is purely mechanical -- six lines changed across five files -- and looks clean and well-motivated. It is under review and has not yet been queued in any integration branch.
