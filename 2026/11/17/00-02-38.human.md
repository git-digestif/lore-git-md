This is a bugfix patch in the UTF-8 handling code, specifically addressing a bounds-checking issue in `utf8_strnwidth()`. Junio’s reply to Dirk Gouders’ first patch surfaces a subtle but important point about the fix’s robustness.

The core issue is that `utf8_strnwidth()` can read past its `len` boundary when processing ANSI escape sequences, even though the function is explicitly designed to respect that limit. Dirk’s patch adds a boundary check after the ANSI-skipping loop to prevent this. Junio agrees the problem exists but questions whether the fix is sufficient: if the input string is at the end of an mmapped region, the `display_mode_esc_sequence_len()` call itself could already trigger a SIGBUS before the new check ever runs. This suggests the fix might be necessary but not fully sufficient for all edge cases.
