This thread is a standalone bugfix from Kaartic Sivaraam addressing an information disclosure in `git fast-import`: when the `export-marks=<path>` feature is forbidden because `--allow-unsafe-features` was not passed, the error message used to leak the full feature string -- including the user-supplied filesystem path -- into stderr. The fix is a one-line change in `parse_one_feature()` in `builtin/fast-import.c` that passes the literal `"export-marks"` to `check_unsafe_feature()` instead of the full argument, matching how the `import-marks` variants and all other features already behave, along with a strengthened test in `t/t9300-fast-import.sh` that now greps stderr for the sanitized message. The patch remains under review with no integration status reported.

Karthik Nayak has replied with a substantive review endorsing the change, confirming that passing a static string is consistent with the existing pattern across all features and that the fix is sensible. The only open item he raises is procedural rather than technical: the patch is likely to conflict with his own in-flight series refactoring `fast-import` tests (`20261112-kn-fast-import-tests-1-v2`), so one author will need to rebase onto the other's topic before either can advance. No objections or requests for changes have been raised, and the enforcement logic itself is unchanged -- the feature remains forbidden under the same conditions, only the diagnostic is cleaned up.
