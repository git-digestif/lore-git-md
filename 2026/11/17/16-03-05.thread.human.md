The thread concerns a small but real information-disclosure bug in `git fast-import`: when a stream uses `feature export-marks=<path>` without `--allow-unsafe-features`, the error message leaks the full feature string including the user-supplied filesystem path into stderr. Kaartic Sivaraam sent a one-line fix in `builtin/fast-import.c` that passes only the bare feature name `"export-marks"` to `check_unsafe_feature()`, matching how the `import-marks` variants already behave, and updated the corresponding test in `t/t9300-fast-import.sh` to assert the sanitized message. Karthik Nayak reviewed the patch, confirmed the reasoning, and endorsed it.

Junio C Hamano has now weighed in, calling the original fix "obviously correct" but proposing a slightly larger structural improvement to prevent this class of bug from recurring: a new `check_unsafe()` helper in `parse_one_feature()` that combines the `skip_prefix()` match with the safety check, so the feature name no longer has to be repeated in two places. He notes an edge case for argument-less unsafe features that would need handling if ever introduced. The patch remains under review, with no integration status reported yet, and the earlier note stands that it may conflict with Karthik Nayak's in-flight fast-import test refactoring series, so one topic will need rebasing before either can advance.
