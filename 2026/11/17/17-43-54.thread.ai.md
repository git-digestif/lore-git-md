Thread identity: `[PATCH 0/3]` through `[PATCH 3/3]` series from Christian Couder addressing 64-bit Windows (LLP64) compatibility and latent truncation bugs where `long` is 32-bit but `size_t` is 64-bit. Thread type: patch series, now complete at three patches.

Core problem or goal: On LLP64 platforms, several APIs narrow `size_t` to `unsigned long` at their boundaries, risking silent truncation for objects or merge results of 4 GiB or more. The series widens the path from `ll_merge()` through to the object database so that `size_t` flows unbroken end to end.

Current status: All three patches posted for review; neither merged nor queued in any integration branch. The series builds on recently merged efforts: `jk/xdiff-size_t` (commit 81db32ddce) and `kn/safer-mem-arithmetic-in-xdiff` (commit 1c93cc03ea), which added a `LONG_MAX` guard in `xdl_do_merge()`.

Key technical details: Patch 1 changes the signature of `write_buf_to_worktree()` in `notes-merge.c` from `unsigned long` to `size_t` to fix truncation from callers `write_note_to_worktree()` and `ll_merge_in_worktree()`. Patch 2 widens the length parameters of `odb_write_object()`, `odb_write_object_ext()`, `odb_source_write_object()`, and `write_loose_object()` from `unsigned long` to `size_t` across `odb.c`, `odb.h`, `odb/source.h`, `odb/source-loose.c`, and `odb/source-inmemory.c`, and changes the `size` field of `struct inmemory_object` to `size_t`. Downstream consumers (`hash_object_file()`, `format_object_header()`, `git_zstream`, the `write_object` callback) already use `size_t`. Patch 3 removes the now-redundant `size > LONG_MAX` check in `xdl_do_merge()` in `xdiff/xmerge.c` (originally added by 288266c11d) and updates `t/t4300-merge-tree.sh`: the two EXPENSIVE big-merge tests now require only `SIZE_T_IS_64BIT` instead of both `SIZE_T_IS_64BIT` and `LONG_IS_64BIT`, the test expecting `git merge-tree` to die on LLP64 (`!LONG_IS_64BIT`) is removed, and the `!SIZE_T_IS_64BIT` overflow test is retained since `st_add*()` checks from b1313872ce still catch size computation overflow.

Open questions and loose ends: Testing requires 64-bit Windows with `GIT_TEST_LONG=1` and sufficient memory/disk for a merge result just over 4 GiB; Linux and macOS CI cannot exercise the LLP64-specific paths. A linked CI run showed tests passed aside from macOS startup issues.

Participant positions: Christian Couder is the author; no reviews, acks, or objections recorded yet.

Related work: Depends on `jk/xdiff-size_t` (81db32ddce) and `kn/safer-mem-arithmetic-in-xdiff` (1c93cc03ea); part of the broader effort to make Git's internals safe on platforms where `long` is narrower than `size_t`.
