This is a cover letter for a three-patch platform-compatibility and bugfix series from Christian Couder aimed at 64-bit Windows (LLP64 platforms where `long` is 32-bit but `size_t` is 64-bit). The series builds on two recently merged efforts -- `jk/xdiff-size_t` (81db32ddce), which switched xdiff merge buffers from `mmbuffer_t` to `mmfile_t` with `size_t` sizes, and `kn/safer-mem-arithmetic-in-xdiff` (1c93cc03ea), which added overflow checks and a `LONG_MAX` guard in `xdl_do_merge()` for the `maint` branches. On `master` the `LONG_MAX` guard is no longer needed for `mmfile_t`, but several downstream functions still accept `unsigned long` lengths, which truncate large merge results on Windows.

Patch 1 changes the size parameter of `write_buf_to_worktree()` in `notes-merge.c` from `unsigned long` to `size_t`; the cover letter notes this independently fixes a latent bug introduced by c6a4629e32 where a delete/modify conflict in `git notes merge` on a note of 4 GiB or more silently writes a truncated note on LLP64 platforms. Patch 2 widens the length arguments of `odb_write_object()`, `odb_write_object_ext()`, the `odb_source_write_object()` wrapper, and `write_loose_object()` -- plus the size field in `struct inmemory_object` -- to `size_t` across `odb.c`, `odb.h`, `odb/source.h`, `odb/source-loose.c`, and `odb/source-inmemory.c`, ensuring object lengths are not truncated before reaching the already-`size_t` backends. Patch 3 removes the `size > LONG_MAX` check in `xdl_do_merge()` in `xdiff/xmerge.c` and updates `t/t4300-merge-tree.sh` to let the big-merge tests run successfully on LLP64 while removing the test that expected failure.

The behavioral difference only manifests on LLP64 systems, so Linux and macOS CI cannot exercise the changed paths; the author explicitly asks for testing on 64-bit Windows with `GIT_TEST_LONG=1`, noting the tests require enough memory and disk for a merge result just over 4 GiB. A CI run is linked showing tests passed aside from some macOS startup issues.
