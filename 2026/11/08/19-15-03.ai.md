This is the first patch in a two-patch test infrastructure series introducing `test-tool genbytes` to eliminate a performance bottleneck on macOS. The patch implements the new `genbytes` command, which writes arbitrary bytes directly (specified as two lowercase hexadecimal digits, e.g., `00` for NUL, `61` for 'a'), and converts 14 existing test scripts to use it instead of the slower `genzeros | tr` pipeline. The file `test-genzeros.c` is renamed to `test-genbytes.c` and repurposed as a thin wrapper around the new core logic, preserving backward compatibility for NUL-byte generation.

The implementation uses a 256 KB buffer for efficiency and enforces the hexadecimal interface via `hex2chr()` from `hex-ll.h`. Performance measurements in the commit message show dramatic improvements on macOS CI jobs (70–79% faster) while Linux jobs see modest gains (2–7%). The patch touches Makefile, meson.build, test-tool plumbing, and 11 test scripts, including `t4205-log-pretty-formats.sh` (the primary beneficiary) and `t5300-pack-object.sh`. No on-disk format changes are involved, and the design addresses all prior review feedback, including Junio C Hamano’s preference for a hexadecimal interface over literal-character input. The `printf` vs. `genbytes` debate is now closed, with Johannes Sixt conceding that `printf` is unreliable on macOS for large outputs and NUL bytes.
