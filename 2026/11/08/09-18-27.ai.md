This is a reply in the `test-tool genbytes` series, clarifying why the author prefers the new command over Johannes Sixt’s `printf` suggestion. Kristofer Karlsson acknowledges that `printf` is fast enough for the specific case in `t4205` (which only needs zeros) but rejects it as a general solution because it cannot generate arbitrary bytes (notably NUL) and because its behavior with extremely large padding values is inconsistent across implementations. He also notes the high memory usage of some `printf` variants, which could be problematic in constrained CI environments. The reply reinforces the original design choice: generalizing `test-tool genzeros` into `genbytes` is more maintainable and predictable than relying on shell workarounds. No new technical details or workflow changes are introduced; this is purely a rationale for sticking with the series’ approach.
