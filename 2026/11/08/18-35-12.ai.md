This is a workflow discussion in the ongoing `test-tool genbytes` series. Junio C Hamano replies to Kristofer Karlsson’s question about how to structure the first patch, which currently splits a file rename (`test-genzeros.c` → `test-genbytes.c`) from the functional changes. Junio states no preference on whether to keep both `genzeros()` and `genbytes()` or rewrite all callers at once, but he strongly prefers a single "rename-and-modify" commit over the current two-patch split. His rationale is that future readers of the Git history—who will use `git log` or `git show`—will find a single commit easier to understand than a mechanical rename followed by an in-place edit. The current split, he notes, optimizes for reviewers on the mailing list (and is partly driven by GitGitGadget’s limitations), but the long-term audience deserves priority. No new technical concerns are raised; this is purely about patch presentation.
