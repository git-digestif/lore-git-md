This is a refactoring patch for the `git reflog expire` command. It consolidates the two separate loops—one for `--all` and one for named refs—into a single loop, addressing a suggestion from Junio during the review of an earlier fix (d1536ac3e2).

The patch collects all refs (both from `--all` and command-line arguments) into a single `string_list`, then processes them together. This avoids duplicating the expiration logic while preserving the existing behavior: command-line refs are still looked up during the loop, so error reporting, exit status, and output remain unchanged. The commit message notes that deferring the lookup until the loop ensures errors (like unknown refs) appear in the expected order and that edge cases like `@{-1}` continue to work.

The change is confined to `builtin/reflog.c` and is mechanical: the core expiration logic (`refs_reflog_expire`) is unchanged, only the control flow around it is simplified. The author reports full test suite passes, including reflog tests with reftable, SHA-256, and leak sanitization, suggesting the refactoring is behavior-preserving.

Key technical details for follow-up discussion:
- The `collected.reflogs` list holds both worktree refs (from `--all`) and command-line arguments.
- `item->util` is used as a flag to mark refs that still need lookup (command-line arguments).
- The `repo_dwim_log` call remains in the loop to handle dynamic refs like `@{-1}`.
- The patch maintains backward compatibility for error messages and exit status.
