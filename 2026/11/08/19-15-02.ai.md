This is a test infrastructure patch series (v2) that introduces `test-tool genbytes` to eliminate a performance bottleneck in Git's test suite on macOS.

The series replaces slow `tr(1)` invocations with a new `test-tool genbytes` command that writes arbitrary bytes directly. The key change since v1 is the interface: `genbytes` now accepts the byte as two lowercase hexadecimal digits (e.g., `00` for NUL, `61` for 'a') instead of a literal character or "NUL" string. This addresses Junio C Hamano's design feedback and allows NUL bytes to be specified cleanly. The author has squashed the file rename (`test-genzeros.c` → `test-genbytes.c`) into the functional patch as requested.

Patch 1 implements `genbytes` and updates 14 test scripts that previously used `genzeros | tr` (e.g., `t4205-log-pretty-formats.sh`, `t5300-pack-object.sh`). Patch 2 removes the now-redundant `genzeros` command and converts its remaining callers to `genbytes 00`. The implementation uses a 256 KB buffer and preserves the existing silent handling of invalid counts. Performance measurements in the commit message show macOS CI jobs improving by 70–79% (from ~800–900 s to ~200 s), while Linux jobs improve by 2–7%.

The series touches 16 files, including Makefile, meson.build, and test-tool plumbing. No on-disk format changes are involved. The hexadecimal interface is a notable technical detail: it requires `hex2chr()` from `hex-ll.h` and enforces lowercase input. All review feedback from v1 has been addressed, and the `printf` vs. `genbytes` debate is now closed.
