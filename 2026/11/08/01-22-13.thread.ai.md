Core problem or goal
Refactor `git reflog expire` to consolidate two separate loops (one for `--all`, one for named refs) into a single loop, addressing a maintainer suggestion from an earlier fix (d1536ac3e2). The goal is to eliminate code duplication while preserving existing behavior: error reporting, exit status, output order, and handling of dynamic refs like `@{-1}`. The patch also presents an opportunity to deduplicate refs (e.g., if the same ref appears via `--all` and a command-line argument), which the maintainer now considers a bug fix rather than a behavioral change. The work will now be split into two patches: the first for the mechanical refactoring (no behavior change), and the second for deduplication as a deliberate improvement.

Author reports full test suite passes (including reflog tests with reftable, SHA-256, and leak sanitization). Junio C Hamano has endorsed Patrick Steinhardt’s suggestion to deduplicate refs in the unified loop, calling the current behavior (processing the same ref twice) a bug. - Files touched: `builtin/reflog.c` only.

Command-line refs are still looked up during the loop via `repo_dwim_log` to handle dynamic refs. Deduplication must avoid sorting to preserve order.
- On-disk format: no changes.
- Test coverage: existing reflog tests (`t/t1400-reflog.sh`, `t/t1419-reflog-expiry.sh`) plus reftable/SHA-256/leak sanitization runs.

Per-reflog options (e.g., `--expire`, `--expire-unreachable`) apply to all refs in the loop, but dynamic-ref resolution (`repo_dwim_log()`) is conditional on `item->util`. Deduplication will be implemented in the second patch by skipping duplicates during iteration.
