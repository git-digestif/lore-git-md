Subject: [PATCH] reflog: refactor expire cmd to use single loop for all refs

Originating author: Laveesh Bansal <laveeshb@laveeshbansal.com>
Thread type: patch (refactoring)

Core problem or goal
Refactor `git reflog expire` to consolidate two separate loops (one for `--all`, one for named refs) into a single loop, addressing a maintainer suggestion from an earlier fix (d1536ac3e2). The goal is to eliminate code duplication while preserving existing behavior: error reporting, exit status, output order, and handling of dynamic refs like `@{-1}`. The patch also presents an opportunity to deduplicate refs (e.g., if the same ref appears via `--all` and a command-line argument), which would simplify error handling and avoid redundant work, though this may alter `--verbose` output order and per-ref occurrence reporting.

Current status
Under review. No prior versions posted. Patch applies cleanly to `builtin/reflog.c`; core expiration logic (`refs_reflog_expire`) is unchanged. Author reports full test suite passes (including reflog tests with reftable, SHA-256, and leak sanitization). Patrick Steinhardt has raised two requests for improvement: (1) the commit message should better explain the *why* (not just the *what*), and (2) the new loop structure could deduplicate refs, though the author notes this would change `--verbose` output behavior. The author plans to send a v2 with an improved commit message but is awaiting further feedback on deduplication.

Key technical details
- Files touched: `builtin/reflog.c` only.
- New/renamed symbols: none (mechanical refactoring).
- Behavior: unchanged except for potential deduplication; command-line refs are still looked up during the loop via `repo_dwim_log` to handle dynamic refs.
- On-disk format: no changes.
- Test coverage: existing reflog tests (`t/t1400-reflog.sh`, `t/t1419-reflog-expiry.sh`) plus reftable/SHA-256/leak sanitization runs.
- Implementation: `collected.reflogs` string_list holds both worktree refs (from `--all`) and command-line arguments; `item->util` flags refs needing lookup. Per-reflog options (e.g., `--expire`, `--expire-unreachable`) apply to all refs in the loop, but dynamic-ref resolution (`repo_dwim_log()`) is conditional on `item->util`. Deduplication would require skipping duplicates during iteration (not sorting, to preserve order).

Open questions and loose ends

- Ref deduplication: Patrick suggests deduplicating refs in the unified loop to simplify error handling and avoid redundant work, but the author notes this would change `--verbose` output behavior (listing each occurrence of a ref vs. only once). The author proposes treating deduplication as a separate follow-up patch unless reviewers prefer it folded into this one.
