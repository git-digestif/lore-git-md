Thread type: patch (refactoring)

Core problem or goal
Refactor `git reflog expire` to consolidate two separate loops (one for `--all`, one for named refs) into a single loop, addressing a maintainer suggestion from an earlier fix (d1536ac3e2). The goal is to eliminate code duplication while preserving existing behavior: error reporting, exit status, output order, and handling of dynamic refs like `@{-1}`. The patch also presents an opportunity to deduplicate refs (e.g., if the same ref appears via `--all` and a command-line argument), which the maintainer now considers a bug fix rather than a behavioral change.

Current status
Under review. No prior versions posted. Patch applies cleanly to `builtin/reflog.c`; core expiration logic (`refs_reflog_expire`) is unchanged. Author reports full test suite passes (including reflog tests with reftable, SHA-256, and leak sanitization). Junio C Hamano has endorsed Patrick Steinhardt’s suggestion to deduplicate refs in the unified loop, calling the current behavior (processing the same ref twice) a bug. The author plans to send a v2 addressing both the commit message clarity and the deduplication logic.

Key technical details
- Files touched: `builtin/reflog.c` only.
- New/renamed symbols: none (mechanical refactoring).
- Behavior: unchanged except for deduplication; command-line refs are still looked up during the loop via `repo_dwim_log` to handle dynamic refs. Deduplication must preserve `--verbose` output order and per-ref occurrence reporting.
- On-disk format: no changes.
- Test coverage: existing reflog tests (`t/t1400-reflog.sh`, `t/t1419-reflog-expiry.sh`) plus reftable/SHA-256/leak sanitization runs.
- Implementation: `collected.reflogs` string_list holds both worktree refs (from `--all`) and command-line arguments; `item->util` flags refs needing lookup. Per-reflog options (e.g., `--expire`, `--expire-unreachable`) apply to all refs in the loop, but dynamic-ref resolution (`repo_dwim_log()`) is conditional on `item->util`. Deduplication will require skipping duplicates during iteration (not sorting, to preserve order).
