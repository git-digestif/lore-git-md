Core problem or goal
Clarify the undocumented behavior of Git’s promisor remote fetch ordering in partial clones. Specifically, explain that (1) promisor remotes advertised and accepted from a server are tried first, one after the other, and (2) if a fetch from one remote fails, Git falls back to the next remote for any remaining missing objects, though this fallback behavior is now considered redundant and may be removed in v3.
