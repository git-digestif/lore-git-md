This is a test infrastructure patch series that introduces `test-tool genbytes` to eliminate a performance bottleneck on macOS. The series is now in its second iteration (v2) and consists of two patches.

The core issue remains the same: the `EXPENSIVE` tests in `t4205-log-pretty-formats.sh` run several times slower on macOS than on Linux because they generate 2 GB of data and pipe it through `tr(1)`, which is unusually slow on that platform. The new `genbytes` command writes arbitrary bytes directly, bypassing `tr` entirely. The author has incorporated all review feedback from v1: the file rename (`test-genzeros.c` → `test-genbytes.c`) and functional changes are now combined into a single commit, and the interface now accepts bytes as two-digit lowercase hexadecimal values (e.g., `00` for NUL, `20` for space) instead of literal characters or the string "NUL".

Patch 1 implements `genbytes` and updates 14 test scripts that previously used `genzeros | tr` to use `genbytes` instead. The implementation uses a 256 KB buffer (matching the previous static buffer size) and preserves the existing silent handling of invalid counts. Patch 2 converts the remaining 10 callers of `genzeros` to use `genbytes 00` and removes the now-redundant `genzeros` command. The series touches 16 files in total, including the Makefile and Meson build files.

The performance improvements are substantial: macOS CI jobs improve by 70–79 % (from ~800–900 seconds to ~200 seconds), while Linux jobs improve by 2–7 %. The series is well-motivated, addresses a real cross-platform performance issue, and has already incorporated all review feedback. The author has clearly documented the changes and their rationale, making this a straightforward and uncontroversial improvement to the test suite.
