This is the second and final patch in a two-part test infrastructure series that removes the now-redundant `test-tool genzeros` command after introducing `test-tool genbytes` in the first patch.

The patch converts the remaining callers of `genzeros` to use `genbytes 00` (the hexadecimal representation of a NUL byte) and deletes the `genzeros` implementation. The changes touch seven test scripts (`t1007-hash-object.sh`, `t1051-large-conversion.sh`, `t1450-fsck.sh`, `t4141-apply-too-large.sh`, and `t5318-commit-graph.sh`) and the test-tool plumbing. Most of these callers only care about generating a specific number of bytes, but a few (like `t1007` and `t5318`) depend on the data being NUL bytes for correctness. The patch preserves that behavior by continuing to generate NUL bytes, ensuring no functional change in the tests.

The diff is straightforward: each `test-tool genzeros` invocation is replaced with `test-tool genbytes 00`, and the `genzeros` command is removed from `test-tool.c` and `test-tool.h`. The implementation in `test-genbytes.c` is also cleaned up by deleting the now-unused `cmd__genzeros` function. No new functionality is introduced; this is purely a cleanup step to consolidate the two commands into one.

The series as a whole is a well-motivated performance improvement for macOS CI jobs, with measurable speedups (70–79%) in the commit message. The author has addressed all prior review feedback, and the interface design (hexadecimal byte specification) is now settled. This patch completes the series and leaves the test suite with a single, flexible command for generating arbitrary bytes. The changes are confined to test infrastructure and do not affect Git's core functionality or on-disk formats.
