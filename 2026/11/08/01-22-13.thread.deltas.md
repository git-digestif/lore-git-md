## 2026/11/08

- [2026/11/08/01-22-13 by Laveesh Bansal <laveeshb@laveeshbansal.com>] Laveesh Bansal posted a patch to builtin/reflog that collects refs from both --all and named command-line arguments into a single list and expires them in one loop, replacing the previous two separate calls to refs_reflog_expire().

## 2026/11/09

- [2026/11/09/09-40-09 by Patrick Steinhardt <ps@pks.im>] Patrick Steinhardt reviewed the single-loop patch: he said the commit message should not cite a mailing-list suggestion but explain the underlying issue in its own words (the mail reference belongs after the "---" line), said it says what is done but not why, called the collect-then-expire-in-one-loop change a useful simplification, asked whether entries could also be sorted and deduplicated (e.g. a name given twice on the command line or via both a named argument and --all), and wondered whether applying per-reflog options only when the name was explicitly given (the only case calling repo_dwim_log()) is sensible.
- [2026/11/09/16-13-13 by Laveesh Bansal <laveeshb@laveeshbansal.com>] Laveesh Bansal rejected deduplication for this patch because it would change behavior: with --verbose a name given twice lists its entries twice today and sorting would reorder them, though skipping an already-seen name in the loop could be a separate change; he corrected Patrick's reading, stating reflog_expire_options_set_refname() is called for every loop entry as in both old loops so per-reflog options apply to --all entries too, with only repo_dwim_log() conditional since --all names come straight from the ref store; he said he will reword the commit message as suggested and send a v2 once others have had a chance to comment.
- [2026/11/09/20-04-29 by Junio C Hamano <gitster@pobox.com>] Junio C Hamano agreed with the deduplication point, calling it a bug that the current two-loop model processes and reports the same thing twice, and noted the collect-then-process model allows deduplication almost for free to address that bug.
