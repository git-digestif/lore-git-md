This is a **bugfix for Git v3 compatibility**, addressing the issue Adam Dinwoodie reported where `git init` incorrectly defaults to SHA-1 instead of SHA-256 when Git is built with `WITH_BREAKING_CHANGES=1`. The patch ensures new repositories use the expected default object format (`GIT_HASH_DEFAULT`), which resolves to SHA-256 in Git v3 mode.

The fix is minimal and targeted: it adds a single line in `setup.c` to set the repository’s hash algorithm to `GIT_HASH_DEFAULT` when no other algorithm is specified. This aligns with the intended behavior for Git v3, where SHA-256 should be the default. The accompanying test (`t/t0001-init.sh`) verifies the fix by checking that `git rev-parse --show-object-format` returns `sha256` under `WITH_BREAKING_CHANGES` and `sha1` otherwise.

The patch is well-motivated and clearly explained in the commit message, which references Adam’s report and explicitly states the goal of defaulting to SHA-256 in breaking-changes mode. The test coverage is thorough, using `test_have_prereq` to conditionally check the expected behavior based on the build flag. This makes the fix robust and easy to verify.
