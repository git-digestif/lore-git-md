This is a reply in the ongoing `test-tool genbytes` thread, clarifying why the author prefers the new command over Johannes Sixt’s `printf` suggestion. Kristofer Karlsson acknowledges that `printf` is fast enough for the specific case in `t4205` (which only needs zeros) but points out two practical drawbacks: high memory usage on some shells and inconsistent behavior across platforms for very large padding values. More fundamentally, `printf` cannot generate arbitrary bytes (such as NUL), so it would not replace the existing `genzeros` helper. The author stands by the decision to generalize `genzeros` into `genbytes` as a cleaner, more predictable solution that handles all use cases. The discussion remains focused on implementation trade-offs; no new design decisions or workflow changes are introduced.
