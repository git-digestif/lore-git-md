This thread is a documentation-only patch series clarifying how Git’s partial clones handle promisor remote fetch ordering. The author, Hussain Sitamouwala, posted a second version of the patch to explain that promisor remotes advertised by a server are tried sequentially, with fallback to the next remote if a fetch fails—though this fallback behavior is now considered redundant and may be removed in a future release.

Junio C Hamano initially raised procedural concerns (v2 was sent prematurely and not threaded as a reply to v1) and editorial feedback, first requesting a wording tweak and later proposing to remove the entire redundant sentence about fallback behavior. Hussain has now agreed to this change, resolving the last substantive open question. The patch remains under review, with no technical objections raised so far. The next step is for Hussain to post a properly threaded v3 incorporating the agreed-upon edits. No merge status has been reported.
