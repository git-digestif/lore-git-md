This thread is a documentation-only patch series from Hussain Sitamouwala that aims to clarify how Git handles promisor remote fetch ordering in partial clones. The patch explains that Git first tries promisor remotes advertised by the server, and if a fetch fails, it falls back to other promisor remotes for any remaining missing objects. The series is currently at v2, but Junio C Hamano raised procedural concerns—v2 was sent prematurely and wasn’t threaded as a reply to v1—and requested a wording change in the documentation ("other promisor remotes" instead of "next remote").

Hussain has since acknowledged Junio’s feedback, agreeing to follow proper mailing list etiquette in future iterations. No technical review of the content has taken place yet, and the patch remains under review. The next step is for Hussain to address Junio’s editorial request before sending a v3. The discussion so far has been entirely about process and phrasing, not the correctness of the documented behavior.
