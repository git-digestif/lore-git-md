This thread is a six-patch bugfix series from Junio C Hamano addressing a long-standing API contract violation in the `strbuf_getwholeline()` family in `strbuf.c`: when EOF is detected on the input stream, these functions return EOF without clearing the caller's output strbuf, leaving stale data from a previous read. That stale-buffer behavior has caused concrete bugs -- and in some cases infinite loops -- in several commands that reuse a strbuf across reads.

The series is deliberately structured so that patches 2 through 4 demonstrate the bugs with `test_expect_failure` cases in `git shortlog` (misattributed subjects from incomplete header lines at EOF), `git clean -id` (stale "y" answer causing mass deletion of untracked files), and `git fast-import` (a stale `deleteall` command corrupting the tree), while patch 5 delivers the actual root-cause fix by resetting the output strbuf on EOF, flipping those tests to passing. Patch 1 separately hardens `git mailinfo` against the new behavior, and patch 6 adds regression tests for two infinite-loop scenarios in `clean -id` and `fast-import` that could not be expressed as expected failures beforehand. In a follow-up email, Junio explained that he considered inserting local `strbuf_reset()` workarounds at the affected call sites in the early patches and reverting them in patch 5, but rejected that approach as awkward and wasteful, preferring to separate the bug demonstrations from the root-cause fix.

The series is newly posted and under review; no integration status has been reported and no reviews have been recorded yet. The central open question -- whether any other in-tree or out-of-tree callers implicitly rely on the old stale-preserving behavior after an EOF return -- remains the likely focus of future review, as Junio's patch 5 commit message asserts there are none but this has not yet been confirmed by other reviewers.
