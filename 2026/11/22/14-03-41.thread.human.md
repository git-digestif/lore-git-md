This thread is a six-patch bugfix series from Junio C Hamano addressing a long-standing contract violation in the `strbuf_getwholeline()` family in `strbuf.c`: when the input stream hits EOF, these functions return EOF without clearing the caller's output strbuf, so it retains stale data from a previous read. That stale-buffer behavior has caused real misbehavior -- in the worst cases infinite loops -- in several commands that reuse a strbuf across reads.

The first patch in the series makes `git mailinfo` robust against the problem: previously, a message containing only header lines and no terminating blank line caused the last header to leak into the commit log via `handle_body()`. The fix has `read_one_header_line()` return -1 on EOF, adjusts its callers accordingly, and adds a regression test in `t/t5100-mailinfo.sh`. Patches 2 through 4 add failing tests documenting the bugs in `git shortlog`, `git clean -i`, and `git fast-import`, and patch 5 implements the actual fix by clearing the strbuf on EOF. The series is newly posted and under review; no integration status has been reported.

The main open question for reviewers is whether clearing the strbuf on EOF breaks any other callers that implicitly relied on the old stale-preserving behavior. No reviews have been recorded yet.
