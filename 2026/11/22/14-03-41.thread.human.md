This thread is a six-patch bugfix series from Junio C Hamano addressing a long-standing API contract violation in the `strbuf_getwholeline()` family in `strbuf.c`: when EOF is detected, these functions return EOF without clearing the caller's output strbuf, leaving stale data from a previous read. That behavior has caused concrete misbehavior across several commands -- `git mailinfo` leaking a final header line into the body, `git shortlog` recording the wrong commit subject when stdin ends mid-header, `git clean -id` deleting every untracked file after a single "y" answer without a trailing newline, and `git fast-import` corrupting trees by re-parsing a stale `deleteall` line. The first five patches harden `mailinfo` against the stale-buffer behavior, add `test_expect_failure` cases demonstrating the shortlog, clean, and fast-import bugs, and land the core fix: `strbuf_getwholeline()` and `strbuf_getline()` now reset the strbuf when `feof()` is hit, flipping those expected failures to expected successes.

The sixth and final patch, just posted, adds regression tests for two additional infinite-loop bugs that the stale-buffer behavior had masked. In `git clean -id` filter-by-pattern mode, a pattern entered without a trailing newline left the reused `confirm` strbuf populated at EOF, so the pattern-reading loop never broke. In `git fast-import`, a final `merge :2` line without a trailing LF left `command_buf` holding that text at EOF, causing `parse_merge()` to loop until OOM. Both tests are written as `test_expect_success` because they hang without the patch 5 fix, and the commit message walks through both mechanisms step by step.

The series is newly posted and under review; no integration status has been reported and no reviewers have weighed in yet. The main open question for discussion is whether clearing the strbuf on EOF breaks any other callers that implicitly relied on the old stale-preserving contract -- Junio's commit message argues no reasonable caller would, and the one known in-tree dependent (`mailinfo`'s `handle_body()`) was already hardened in patch 1, but this has not yet been confirmed by other reviewers.
