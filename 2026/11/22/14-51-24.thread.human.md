Dirk Gouders has posted the first patch of a four-patch v5 series aimed at fixing a latent memory-safety issue in Git's UTF-8 handling code. The series introduces a counted-length variant of the ANSI escape sequence parser, `display_mode_esc_sequence_len_counted()`, which guarantees it will never read past the end of a bounded buffer. The existing NUL-terminated function becomes a thin wrapper that passes `SIZE_MAX`, preserving current behavior for callers with null-terminated strings while allowing safe operation on non-NUL-terminated data. Andy Koppe had previously suggested the `SIZE_MAX` approach to avoid quadratic performance degradation.

The patch updates three call sites to use the new counted variant: `utf8_strnwidth()`, `strbuf_utf8_replace()`, and `strbuf_add_wrapped_text()`. In each case, the code now computes the remaining length once and passes it on every iteration, closing a correctness gap where the old NUL-terminated scan could read beyond the logical end of a counted buffer. The change is accompanied by a new clar unit test suite at `t/unit-tests/u-utf8-ansi.c` that verifies the function respects explicit length limits and never reads out of bounds.

The series is at v5, patch 1 of 4, and has just been posted to the list. No review feedback has arrived yet, so the discussion is open; the remaining three patches in the series are expected to follow in the same thread.
