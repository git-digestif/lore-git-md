This is a feature patch -- specifically patch 5/7 of Harald Nordgren's v15 series on limiting fetches in shallow repositories. It introduces the `remote.<name>.fetchUpstreams` boolean configuration, which causes a refspec-less `git fetch <name>` to also download the upstream branches that local branches track on that remote, in addition to whatever `remote.<name>.fetch` requests.

The new setting deliberately separates what is fetched from where it is stored: combined with `remote.<name>.fetchRefmap` (established in patch 3/7) and an empty `remote.<name>.fetch`, a remote can be limited to exactly the branches currently in local use. Only the current branch's upstream is marked for merging, so `git pull` continues to integrate just that branch rather than every tracked branch. The patch also teaches `@{push}` to consult the refmap, so pushing to such a remote resolves to the correct remote-tracking branch instead of failing with "has no local tracking branch".

Implementation-wise, the patch builds directly on the refactoring from the previous patch: it adds `branches_tracking_remote()` in `remote.c` (which iterates over all local branches using the `collect_upstream_from_remote()` helper extracted in patch 4/7) and wires it into `get_ref_map()` in `builtin/fetch.c` via a new `add_branch_upstreams()` function. When `fetch_upstreams` is set, the fetch logic includes these tracked upstreams in the ref prefixes sent to the transport and in the ref map construction, while `do_fetch()` switches from collecting only the current branch's upstream to collecting all tracked branches.

The commit message is clear and motivating, explaining the shallow-repository use case where maintaining a hand-curated `remote.<name>.fetch` list becomes burdensome when branches are started or dropped. Test coverage is thorough, with a new dedicated test file `t/t5586-fetch-refmap.sh` covering baseline behavior, interaction with `remote.<name>.fetch`, prefetch behavior, `git pull` semantics, and the `@{push}` resolution fix. Overall this looks like a well-crafted, well-tested addition that delivers the core user-facing functionality of the series.
