This is a review reply from Junio C Hamano to Omri Sarig's documentation patch (v2 of a series fixing AsciiDoc markup in `Documentation/git-update-index.adoc`). Junio provides feedback on both the commit message and the patch content itself. On the commit message, he suggests downcasing "Format" to "format" in the subject line and prefers present tense ("has references to") over the past tense used in the draft, noting that early commit message text should describe the current state. He also reframes the motivation: the issue is not that the text fails to be "references" but that option names should be typeset in monospaced font per manual page conventions.

Substantively, Junio points out that while the patch adds backticks around option mentions like `--refresh` and `--remove`, it misses adjacent markup that should follow the same convention. Specifically, he notes that the enumeration header `-q`:: should become `` `-q`:: `` and that `'git update-index'` in single quotes should use backticks as well. He cites commit e9a99ef2da (doc: convert git-format-patch synopsis and options to new style, 2026-07-23) from Jean-Noel Avila's earlier series as the model for these comprehensive formatting fixes, where both option mentions and list markers were converted to backtick style.

Junio also expresses a mild preference against accumulating too many low-risk, low-value patches that address overly narrow issues, implying that this fix might be better bundled with other markup corrections in the same file. He advises Omri to imitate the commit message style used in Jean-Noel's series. The exchange leaves the patch under review with clear guidance on how to broaden the scope of the fix to match established documentation conventions.
