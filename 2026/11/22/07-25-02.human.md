This is a substantive review of the first patch in Dirk Gouders's v4 series, pointing out two concrete defects in the new unit tests for `display_mode_esc_sequence_len()`.

Andy Koppe identifies that the test assertion `display_mode_esc_sequence_len("", "")` invokes undefined behavior, because comparing pointers to different objects is not permitted in C even when a compiler might happen to use the same address for both empty string literals. He also catches that the lines using `sizeof(sgr_3)` and `sizeof(sgr_4)` are incorrect: since those variables are `char *` pointers, `sizeof` returns the size of the pointer (typically 8 bytes) rather than the length of the underlying string literal, which would make the expected return values wrong and the source lines excessively long.

This is a targeted code-level review rather than a surface nitpick -- it spots actual bugs in the test logic that would cause the new clar tests to either rely on undefined behavior or assert incorrect lengths. Within the broader v4 thread, it adds to Koppe's earlier feedback, which included flagging a build blocker in patch 4/5 and questioning the scope of the new `display_mode_esc_sequence_len_all()` helper, and it continues his detailed engagement with the end-pointer API for bounded ANSI sequence scanning.
