This is a bug report diagnostic for the Linux fsmonitor backend, adding a bisection result to an ongoing thread about test failures in `t7527-builtin-fsmonitor--daemon.sh`.

Dirk Gouders reports that a bisect identified commit `ce48de8b2c` ("fsmonitor: implement filesystem change listener for Linux", 2026-04-15) as the first bad commit introducing the defect. This confirms the crash he previously diagnosed: when the built-in fsmonitor daemon runs on Linux during the `move_directory_up` test scenarios (specifically `Matrix[uc:false][fsm:true]` and `Matrix[uc:true][fsm:true]`), `git fsmonitor--daemon run --detach -` aborts with `BUG("double remove of watch for '%s'", w->dir)` at `compat/fsmonitor/fsm-listen-linux.c:144`. The Linux inotify listener attempts to remove the same directory watch twice while handling upward directory moves.

The `core.*` files appearing in temporary test directories contain this fatal error message, which contaminates the `git status --porcelain=v1` output comparison and causes the two observed test failures. Gouders has Cc'd the authors of the introducing commit, signaling that a fix is expected to come from those involved in the original Linux fsmonitor implementation rather than from himself.

For future reference: the defect is isolated to the Linux inotify backend in `compat/fsmonitor/fsm-listen-linux.c`, triggered specifically by directory moves upward in the tree while fsmonitor is active, and regressed in `ce48de8b2c`. Any follow-up patches will likely target the watch removal logic around line 144 of that file.
