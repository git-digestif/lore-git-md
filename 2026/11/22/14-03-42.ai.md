This is a bugfix patch, specifically the first of a six-patch series from Junio C Hamano addressing stale-buffer behavior in the `strbuf_getline()` family. The patch targets `mailinfo.c` and makes `git mailinfo` robust against a long-standing API issue where `strbuf_getline_lf()` returns EOF upon detecting `feof()` without clearing the caller's output strbuf. Previously, when a mail message contained only header lines with no terminating blank line, `read_one_header_line()` would return 0 on EOF (indistinguishable from a blank line) while leaving the last header line in the buffer, causing `mailinfo()` to feed that stale header into `handle_body()` and leak headers such as `Content-Type` into the commit log. The fix changes `read_one_header_line()` to return -1 on EOF, updates its callers in `mailinfo()` and `handle_boundary()` to loop only while the return value is positive and to call `handle_body()` only when the return is exactly 0, and adds a defensive `len &&` guard in `handle_filter_flowed()`. A new test in `t/t5100-mailinfo.sh` verifies that a header-only message produces empty body and patch outputs. This patch prepares `mailinfo` for the underlying `strbuf` fix that arrives later in the series (patch 5), and the main open question for the thread remains whether clearing the strbuf on EOF in `strbuf_getwholeline()` will break other callers that implicitly relied on the stale-preserving contract.
