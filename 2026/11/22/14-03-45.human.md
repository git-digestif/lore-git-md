This is a test patch, the fourth in Junio C Hamano's six-part series addressing the `strbuf_getwholeline()` EOF bug. It adds a `test_expect_failure` case to `t/t9300-fast-import.sh` that demonstrates a concrete data-corruption bug in `git fast-import`.

The bug occurs when a commit message uses a heredoc delimiter that happens to match a file-change command -- in the test, the delimiter is `deleteall`. If the input stream ends immediately after the heredoc terminator line with no trailing blank line, `parse_data()` leaves the string `deleteall` sitting in `command_buf`. Because `strbuf_getline_lf()` returns EOF without clearing the buffer, the subsequent `read_next_command()` call in `parse_new_commit()` also hits EOF but leaves `command_buf` unchanged. The code then re-parses that stale `deleteall` as a file-modify command, causing `file_change_deleteall()` to discard every file inherited from the parent commit.

The commit message walks through this failure path step by step, making clear that the root cause is the same stale-strbuf contract violation documented in patches 2 and 3 for `git shortlog` and `git clean -i`. The test feeds a two-commit stream where the second commit's heredoc delimiter is `deleteall` and asserts that the first commit's file still exists in the tree afterwards -- an assertion that currently fails. It is marked `test_expect_failure` because the actual fix (clearing the strbuf on EOF inside `strbuf_getwholeline()`) arrives later in patch 5 of the series.
