This is a bugfix for `git archive` that corrects the interaction between the `--add-file` and `--add-virtual-file` options. Both options currently register their entries in the same internal string-list, which means the negative forms `--no-add-file` and `--no-add-virtual-file` each clear the entire list -- wiping out entries added by the other option. René Scharfe changes the behavior so that each negative form removes only the entries added by its corresponding positive form.

Rather than splitting the shared list into two separate lists (which would alter the ordering of files in generated archives), the patch filters the existing list in place. It introduces a new helper, `filter_string_list_func()`, in the string-list subsystem that applies a callback to decide which items to keep and calls a custom destructor on those that are removed. The archive code uses this to retain only regular files when `--no-add-file` is given, or only virtual files when `--no-add-virtual-file` is given, based on whether the entry has associated content.

The change is small and well-contained, touching `archive.c`, `string-list.c`, `string-list.h`, and adding two test cases to `t/t5000-tar-tree.sh` that verify each negative flag preserves the other flag's entries. The commit message clearly explains both the surprising current behavior and why the implementation avoids separate lists. This looks like a solid, low-risk fix that addresses a real usability wart without changing archive output ordering.
