This is a test patch -- specifically the second of six in Junio C Hamano's bugfix series documenting and fixing stale-buffer behavior in the `strbuf_getwholeline()` family. It adds two `test_expect_failure` cases to `t/t4201-shortlog.sh` that demonstrate how `git shortlog` produces wrong output when reading from stdin if the input ends on an incomplete line.

The patch targets `read_from_stdin()` in `builtin/shortlog.c`, which uses a strbuf named `oneline` across reads while scanning header lines. When `strbuf_getline_lf()` hits EOF mid-line, it returns EOF without clearing `oneline`, leaving the previous line's contents in place. The commit message walks through two concrete failure modes: an incomplete `Author:` line at EOF causes the previous commit's subject to be recorded for the second commit, and an incomplete `Date:` (or similar) header at EOF causes that discarded header text to be treated as the commit subject. Both tests expect the corrected output (empty subject in the first case, empty output in the second) but are marked as expected failures because the underlying `strbuf_getwholeline()` fix has not yet been applied -- that fix arrives in patch 5 of this series.

As the second patch in the series, this sits between the mailinfo robustness fix (patch 1) and the additional failing tests for `git clean -i` and `git fast-import` (patches 3 and 4). The author explicitly notes that the fix is deferred to avoid entangling this demonstration with the broader behavior change in `strbuf.c`, which will also affect other callers. The series remains under review with no integration status reported.
