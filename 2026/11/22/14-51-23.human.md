This is a bugfix patch series cover letter for UTF-8 display-width handling in `utf8.c`. Dirk Gouders submits `[PATCH v5 0/4]`, a four-patch series that fixes bounds handling in `utf8_strnwidth()` and `utf8_width()` so they respect their length arguments and avoid reading past buffer ends, plus a documentation correction for `utf8_strnwidth()`'s comment.

The series comprises one patch from Junio C Hamano adding `display_mode_esc_sequence_len_counted()`, which scans ANSI SGR escape sequences using a length bound rather than a NUL terminator, and three patches from Gouders that wire this into `utf8_strnwidth()`, fix the function's misleading comment about returning `strlen()`, and ensure the width calculation stops at the specified boundary even when ANSI sequences or multibyte characters are truncated. New unit tests in `t/unit-tests/u-utf8-ansi.c` and `u-utf8-width.c` cover the bounded behavior.

Version 5 marks a narrowing of scope compared to v4: Gouders dropped the fifth patch that introduced `display_mode_esc_sequence_len_all()` after Andy Koppe questioned its necessity, agreeing it was noise. He also reverted to Junio's preferred `display_mode_esc_sequence_len_counted()` API rather than the end-pointer design from v3/v4, but implemented it using an array index internally to avoid the O(n²) risk of calling `strlen()` on NUL-terminated strings and to avoid undefined pointer arithmetic like `s + SIZE_MAX`. The cover letter notes that test arrays are now initialized from string constants so `sizeof()` yields the correct buffer length, addressing Koppe's review nits about pointer decay.

The series touches `utf8.c`, `utf8.h`, `pretty.c` call sites, and the test infrastructure (`Makefile`, `t/meson.build`). It remains under review; no version has been queued in `next` or `master`. The approach looks well-crafted and responsive to review, with the immediate open question being whether this v5 addresses all of Koppe's technical concerns about bounds checking and pointer safety.
