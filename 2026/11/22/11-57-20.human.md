This is a feature patch, specifically the third of seven in Harald Nordgren's v15 series reworking fetch behavior for shallow repositories. It introduces a new per-remote configuration key, `remote.<name>.fetchRefmap`, which provides the default value for the `--refmap` option in the same way that `remote.<name>.fetch` already provides default refspecs. The command-line `--refmap` continues to override the configured value.

The new setting controls only where fetched refs are stored, not what is fetched. When `remote.<name>.fetch` is also configured, it remains the selector for which refs to fetch, but entries without an explicit destination are mapped through the refmap, while entries carrying their own destination (`src:dst`) are stored only at that destination and ignore the refmap entirely. This lets a user name specific branches in `remote.<name>.fetch` while storing them all under a single remote-tracking namespace via one refmap entry. Lookup of upstream branches for `@{upstream}` and `git branch --track` falls back to the refmap when `remote.<name>.fetch` has no match, and branches excluded by a negative refspec in `remote.<name>.fetch` remain excluded.

The patch touches `builtin/fetch.c`, `remote.c`, and `remote.h` to thread the new `refmap` field through the remote structure and the fetch ref-map logic, and adds extensive tests in `t/t5510-fetch.sh` covering the interaction between `fetchRefmap`, command-line refspecs, and upstream tracking. Documentation updates in `Documentation/config/remote.adoc` and `Documentation/fetch-options.adoc` explain the new precedence rules clearly.

This patch looks well-crafted and directly implements the override semantics that Junio C Hamano and Phillip Wood confirmed earlier in the thread: explicit destinations bypass the refmap, while destination-less selections flow through it. The commit message is precise about the separation between "what to fetch" and "where to store," and the test coverage appears thorough, exercising both the baseline behavior and edge cases like negative refspecs and command-line overrides.
