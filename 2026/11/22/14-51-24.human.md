This is a bugfix and performance patch for the UTF-8 handling subsystem, specifically the first of a four-patch series (v5). Dirk Gouders adds a length-aware variant of `display_mode_esc_sequence_len()`, called `display_mode_esc_sequence_len_counted()`, which takes an explicit length parameter and never reads at or beyond that boundary. The existing NUL-terminated wrapper now delegates to this new function with `SIZE_MAX`.

The motivation is twofold. First, correctness: `utf8_strnwidth()` takes a counted buffer but was calling the old function, which relied on NUL termination and could scan past the given length. Second, performance: `strbuf_utf8_replace()` and `strbuf_add_wrapped_text()` were repeatedly measuring the remaining text on each iteration, risking O(n²) degradation; the patch computes the end pointer once upfront and passes the remaining length into the counted function.

The change is well-tested, adding a new clar unit test file `t/unit-tests/u-utf8-ansi.c` with coverage for both the NUL-terminated and length-limited variants, including edge cases where the sequence is truncated. Junio C Hamano signed off, and the commit message credits Andy Koppe for the `SIZE_MAX` suggestion. Overall this looks like a clean, carefully constructed fix that addresses a real correctness issue while also removing a performance hazard.
