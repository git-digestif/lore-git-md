This is a behavior refinement for `git fetch --refmap`, forming the first patch of Harald Nordgren's seven-patch v15 series on limited fetch modes for shallow repositories. The patch changes how `--refmap` interacts with command-line refspecs: a refspec that carries its own explicit destination (`src:dst`) is now stored only at that destination and is no longer additionally mapped through `--refmap`. Previously, `git fetch --refmap=<map> <remote> main:tmp` would store the fetched ref both at `tmp` and wherever `<map>` sent it, which the commit message notes becomes problematic once a remote can configure a default refmap via `remote.<name>.fetchRefmap` (introduced in the following patch).

The change preserves the existing opportunistic update behavior for remote-tracking branches selected by `remote.<name>.fetch`, so `git fetch origin main:tmp` still updates `origin/main` as before; only the explicit refmap mapping is skipped for refspecs with destinations. The implementation adds a `map_refs_without_dst()` helper in `builtin/fetch.c` that filters out already-mapped refs before applying the refmap, updates the `fetch-options` documentation, and includes a test in `t/t5510-fetch.sh` verifying that `main:refs/remotes/custom/main` is stored only at the custom location while a destination-less refspec (`side`) still goes through the refmap.

Within the broader thread, this patch implements one half of the override semantics that Junio C Hamano and Phillip Wood confirmed during the v14 review: any refspec with an explicit `src:dst` form ignores both command-line `--refmap` and the config-based `fetchRefmap` entirely, preventing dual storage. The companion behavior -- that `--refmap` works even without command-line refspecs -- appears in the next patch of the series. As patch 1/7 of v15, it sits at the head of the series that remains under final review for `master`, still blocking Collin's `ch/remote-defer-follow-remote-head-validation` topic due to textual conflicts. The patch is well-crafted, with a clear commit message explaining the motivation, focused code changes, and test coverage.
