Thread identity: Single performance/correctness patch by Stepan Koltsov (sent via GitGitGadget) targeting the interaction between the untracked cache and the fsmonitor daemon in `git status`. Thread type: patch.

Core problem or goal: When fsmonitor is enabled, `valid_cached_dir()` in `dir.c` currently calls `prep_exclude()` on every check, which is redundant because fsmonitor already invalidates untracked-cache entries when any file in a directory changes, including `.gitignore` files. The patch skips the `prep_exclude()` call when fsmonitor is enabled and the untracked-cache entry is still marked valid. Additionally, it fixes an edge case in `invalidate_stale_dirs()`: after a trivial fsmonitor response (introduced in commit 1cf98cb4d9), cached directories are rechecked only against stat data, but editing a `.gitignore` in place does not change the directory's stat data. The fix invalidates any directory whose `exclude_oid` is non-null (indicating it contains a `.gitignore`), forcing a rescan on the next status call to catch edits made while the daemon was stopped and restarted.

Test additions cover two scenarios: a `.gitignore` edited while the daemon is stopped followed by a trivial fsmonitor response, and a `.gitignore` change reported normally by fsmonitor; both verify the untracked cache picks up new ignore rules.
