Stepan Koltsov has sent a patch that both speeds up `git status` and fixes a correctness edge case in how the untracked cache interacts with the fsmonitor daemon. The proposal skips the `prep_exclude()` call inside `valid_cached_dir()` in `dir.c` when fsmonitor is enabled and the cached directory entry is still valid, on the grounds that fsmonitor already invalidates cache entries whenever files change, including `.gitignore` files.

The patch also addresses a subtle bug in `invalidate_stale_dirs()`: after a trivial fsmonitor response, directories are rechecked only against stat data, but editing a `.gitignore` in place does not alter the directory's stat data. To catch this scenario -- particularly when the daemon was stopped and restarted, missing the edit -- the patch now invalidates any directory whose `exclude_oid` is non-null, forcing a rescan on the next status call. Tests in `t/t7527-builtin-fsmonitor.sh` cover both the daemon-restart case and the normal fsmonitor-reported change. On macOS with roughly 89,000 directories and a warm untracked cache, `git status --untracked-files=all` reportedly drops from about 310 ms to 65 ms. The series is at its initial version and is awaiting review.
