This is a feature patch, specifically v15 patch 5/7 of Harald Nordgren's seven-patch series introducing a matching-inspired fetch mode for shallow repositories. The patch adds the `remote.<name>.fetchUpstreams` boolean configuration key, which causes a refspec-less `git fetch <name>` to additionally fetch the upstream branches that local branches track on that remote, beyond whatever `remote.<name>.fetch` requests. The setting controls only what is fetched; storage location remains governed by `remote.<name>.fetch` and `remote.<name>.fetchRefmap`, so a remote with `fetchUpstreams` plus a `fetchRefmap` but no `fetch` refspec effectively limits fetching to locally-tracked branches.

Implementation centers on a new `bool fetch_upstreams` field in `struct remote` (remote.h), parsed in `handle_config()` via the `fetchupstreams` subkey. The patch introduces `branches_tracking_remote()` in remote.c, which iterates every local branch using `refs_for_each_branch_ref()` with the `add_if_tracking_remote()` callback; each invocation calls the `collect_upstream_from_remote()` helper (extracted in patch 4/7) with that branch's refname to collect its upstream source refs on the specified remote. In builtin/fetch.c, the new `add_branch_upstreams()` static function calls `branches_tracking_remote()` and converts each resulting upstream into a destination-less refspec item fed through `get_fetch_map()`, skipping any already present in the ref map. Both `get_ref_map()` and `do_fetch()` check `remote->fetch_upstreams` to decide whether to invoke this collection logic alongside the existing `remote->fetch` processing, ensuring the transport's ls-refs prefixes include these upstreams even when no explicit refspecs are given.

The patch also extends `tracking_for_push_dest()` in remote.c so that `@{push}` resolution consults `remote->refmap` (via `apply_refspecs()`) when `remote->fetch` yields no match, allowing a branch pushed to a refmap-only remote to resolve to the remote-tracking branch it updated rather than erroring. Test coverage lives in the new `t/t5586-fetch-refmap.sh` (182 lines), which exercises baseline fetch behavior with `fetchUpstreams` unset, tracking branches via one-time fetches, ensuring later plain fetches update tracked branches, verifying deduplication when multiple local branches track the same upstream, confirming branches tracking other remotes are excluded, demonstrating that `remote.<name>.fetch` entries combine with upstreams, checking `--prefetch` stores under `refs/prefetch/`, validating that `git pull` merges only the current branch's upstream, and testing `@{push}` resolution. Documentation appears in `Documentation/config/remote.adoc`. The series remains under review in `next`.
