This is a bug report providing specific technical details about test failures in the built-in fsmonitor daemon test suite. Dirk Gouders follows up on his initial inquiry with the exact failure mode: two tests in `t7527-builtin-fsmonitor--daemon.sh` -- test 43 (`Matrix[uc:false][fsm:true] move_directory_up`) and test 56 (`Matrix[uc:true][fsm:true] move_directory_up`) -- fail on `origin/master` because `git fsmonitor--daemon run --detach -` crashes with a `BUG("double remove of watch for '%s'", w->dir)` assertion at `compat/fsmonitor/fsm-listen-linux.c:144`.

Both failing cases exercise the `move_directory_up` operation with fsmonitor enabled, which points to the Linux fsmonitor listener attempting to remove a watch that has already been removed when handling directory-move events that propagate upward in the hierarchy. The report is specific and actionable, citing the exact file and line where the assertion fires, which gives future investigators a concrete starting point for debugging the daemon's watch management on Linux.
