René Scharfe has sent a bugfix for `git archive` addressing a flaw in how the negative forms of `--add-file` and `--add-virtual-file` are handled. Both options store their extra entries in the same `string_list`, but previously `--no-add-file` and `--no-add-virtual-file` would clear the entire list, inadvertently removing entries added by the other option. The patch introduces a `filter_string_list_func()` helper in `string-list.c` that removes only matching entries based on a predicate, preserving the original ordering of retained items. A `keep_file()` callback distinguishes between regular files (added via `--add-file`) and virtual files (added via `--add-virtual-file`) so each negative flag now removes only its own type of entry. Two new tests in `t/t5000-tar-tree.sh` verify that the flags no longer interfere with each other. The commit message explains that while separate lists would have been simpler, doing so would have altered the order of files in generated archives, which the filtering approach avoids. The patch is currently under review on the list.
