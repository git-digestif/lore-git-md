This is a documentation patch -- specifically a fix to an in-code comment -- and it is the second of four patches in a v5 series from Dirk Gouders.

The patch corrects the comment above `utf8_strnwidth()` in `utf8.c`. The old comment described the input as a NUL-terminated string and claimed the function returns `strlen()` when the input is not valid UTF-8. In reality the function takes an explicit `len` bound and returns that `len` value in the invalid-UTF-8 case. The diff changes only those two lines of the comment; no code behavior is altered.
