This is a review acknowledgment in the ongoing bugfix series for UTF-8 width calculation bounds handling.

Dirk Gouders replies to Andy Koppe's clarification about pointer arithmetic safety, accepting the point that computing an end pointer as `start + SIZE_MAX` is undefined behavior because it forms a pointer more than one past the end of the object, even without dereferencing it. Gouders commits to reviewing Junio C Hamano's `display_mode_esc_sequence_len()` implementation for any such `s + len` problems and confirms that the NUL-terminated wrapper will simply call the bounded function with `SIZE_MAX` as the length.

This exchange sits within the v4 series that fixes out-of-bounds reads in `utf8_strnwidth()` and `utf8_width()`, particularly the SIGBUS risk when scanning mmapped regions. The end-pointer API design remains settled, and Gouders's acceptance here reinforces that the series will avoid the undefined pointer arithmetic Koppe flagged while keeping the `(const char *start, const char *end)` signature.
