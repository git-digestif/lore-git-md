This is a bug report concerning a failure in the test suite, specifically test script `t7527-builtin-fsmonitor--daemon.sh` (the built-in fsmonitor daemon test). Dirk Gouders reports that on `origin/master`, two of the seventy tests fail: test 43 (`Matrix[uc:false][fsm:true] move_directory_up`) and test 56 (`Matrix[uc:true][fsm:true] move_directory_up`). Both failing cases involve the `move_directory_up` operation with fsmonitor enabled, suggesting a potential issue in how the fsmonitor daemon tracks or reports directory moves upward in the hierarchy.

The test uses a matrix approach to verify combinations of untracked cache (`uc`) and fsmonitor (`fsm`) settings, comparing expected versus actual `git status --porcelain=v1` output via `test_cmp`. Gouders notes that a `core.*` file appearing in the temporary directory appears to interfere with the comparison, causing the failures. The specific operation under test moves directory contents up one level, and the daemon seems to produce incorrect status output in this scenario when fsmonitor is active.

The email serves as an initial inquiry -- Gouders is asking whether this is a known issue before investigating further. No patch or fix is proposed, and no prior discussion context is provided. The failure pattern points to a possible bug in the fsmonitor daemon's handling of the `move_directory_up` filesystem event, or potentially in how the test harness isolates configuration files between matrix iterations.
