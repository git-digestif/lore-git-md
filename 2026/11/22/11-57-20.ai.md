This is a feature patch -- specifically the third of seven in Harald Nordgren's v15 series -- that introduces the new `remote.<name>.fetchRefmap` configuration key. The patch establishes `fetchRefmap` as the configured default for the `--refmap` command-line option, mirroring how `remote.<name>.fetch` already supplies default refspecs. It decouples "where fetched refs are stored" from "what is fetched": `remote.<name>.fetch` continues to select which refs to fetch, entries in it without an explicit destination are stored through the refmap, and entries carrying their own `src:dst` destination bypass the refmap entirely. Command-line `--refmap` overrides the config value.

Technically, the patch adds a `struct refspec refmap` field to `struct remote` in `remote.h`, parses the `fetchrefmap` config subkey in `remote.c`'s `handle_config()`, and initializes/clears it in `make_remote()`/`remote_clear()`. In `builtin/fetch.c`, `get_ref_map()` now computes an `effective_refmap` that prefers the command-line refmap but falls back to `remote->refmap`, and uses the `map_refs_without_dst()` helper (introduced in patch 1/7) to apply it only to destination-less entries. The `remote_find_tracking()` function in `remote.c` is extended to consult the refmap when `remote.<name>.fetch` has no match, so `@{upstream}` resolution and `git branch --track` work for branches stored via the refmap, while still honoring negative refspecs in `remote.<name>.fetch`. Documentation updates appear in `Documentation/config/remote.adoc` and `Documentation/fetch-options.adoc`, and extensive tests are added to `t/t5510-fetch.sh` covering baseline behavior, storage of named branches, command-line override, interaction with `src:dst` entries (both configured and command-line), tracking of branches outside the fetch refspec, and exclusion via negative refspecs.
