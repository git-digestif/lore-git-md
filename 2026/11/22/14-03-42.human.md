This is a bugfix for `git mailinfo`, and the first patch in a six-part series from Junio C Hamano addressing the stale-buffer behavior of `strbuf_getline_lf()` on EOF.

The patch fixes a concrete leak where `mailinfo` would feed a stale header line into the message body when an email consisted only of headers with no blank line separating them from the body. Because `strbuf_getline_lf()` returns EOF without clearing the output buffer when it hits end-of-file, `read_one_header_line()` was returning 0 (suggesting a blank line) while `line` still contained the last header seen. The main `mailinfo()` loop then passed that stale content to `handle_body()`, causing headers like `Content-Type` to appear in the commit log message.

The fix makes `read_one_header_line()` return -1 on EOF instead of 0, allowing callers to distinguish a true EOF from a properly terminated header section. The main loop now only calls `handle_body()` when the return value is exactly 0, meaning a real blank or non-header line was read. A small defensive `len &&` guard is also added in `handle_filter_flowed()` for symmetry with an existing CR check.

A regression test in `t/t5100-mailinfo.sh` verifies that a header-only message produces empty `msg` and `patch` outputs without leaking the `Content-Type` header. This patch serves as the first step in the broader series, making `mailinfo` robust against the underlying `strbuf` behavior before the actual fix lands later in the series.
