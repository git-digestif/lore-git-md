Dirk Gouders has sent the third patch of a four-patch v5 series addressing a bounds-checking bug in Git's UTF-8 display-width code. The patch fixes `utf8_strnwidth()` in `utf8.c`, which previously could read past the end of a string when an ANSI escape sequence ended at or beyond the specified length limit while `skip_ansi` was enabled. The fix adds a check after the ANSI-skipping loop to stop if the pointer has reached the string boundary, preventing out-of-bounds reads. It also includes a new unit test `test_utf8_width__strnwidth_ansi()` in `t/unit-tests/u-utf8-width.c` covering three corner cases involving the string `"\033[31mhello"`.

The series is at version 5, though the overall goal of the four-patch set is not stated in this email alone. So far only this single patch has been described; the status of the other patches and any review feedback remain unknown.
