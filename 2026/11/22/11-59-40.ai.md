This is a bugfix for `git archive` option handling, authored by René Scharfe. The options `--add-file` and `--add-virtual-file` both register extra entries in the same `string_list` (`args->extra_files` in `archive.c`), but their negative forms `--no-add-file` and `--no-add-virtual-file` previously cleared the entire shared list, wiping out entries added by the other option. The patch changes the unset path in `add_file_cb()` to filter the list rather than clear it, using a new helper `filter_string_list_func()` added to `string-list.c`/`string-list.h`. This helper takes a predicate callback and a destructor, preserving the original ordering of retained items. The predicate `keep_file()` distinguishes between regular files (where `extra_file_info->content` is NULL, added via `--add-file`) and virtual files (where content is set, added via `--add-virtual-file`), so that `--no-add-file` removes only regular-file entries and `--no-add-virtual-file` removes only virtual-file entries. Two tests in `t/t5000-tar-tree.sh` verify that each negative flag preserves entries added by the other positive flag when creating archives from the empty tree. The commit message notes that using separate lists would have been simpler but would change the order of files in generated archives, hence the filtering approach.
