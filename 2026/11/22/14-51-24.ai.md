This is a correctness refactoring in the UTF-8 handling subsystem, specifically patch 1 of a 4-patch v5 series. It introduces a counted-length variant of the ANSI escape sequence parser to prevent out-of-bounds reads in callers that operate on non-NUL-terminated buffers.

The patch adds `display_mode_esc_sequence_len_counted(const char *s, size_t len)` to `utf8.c` and `utf8.h`, which guarantees never to read at or beyond `s[len]`. The existing `display_mode_esc_sequence_len()` becomes a thin wrapper that calls the new function with `SIZE_MAX`, preserving the NUL-terminated behavior for existing callers while allowing the function to work safely with bounded buffers. The commit message notes that Andy Koppe suggested accepting `SIZE_MAX` for the NUL-terminated case to avoid O(n²) degradation.

Three call sites are updated to use the counted variant: `utf8_strnwidth()` now passes the remaining length (`orig + len - string`), and both `strbuf_utf8_replace()` and `strbuf_add_wrapped_text()` compute the end pointer once and pass the remaining distance on each iteration, fixing a latent correctness issue where the old NUL-terminated scan could read past the logical end of counted buffers.

The patch includes a new clar unit test suite at `t/unit-tests/u-utf8-ansi.c` (registered in both `Makefile` and `t/meson.build`) covering the counted function with `SIZE_MAX`, the wrapper, and explicitly limited lengths to verify it never reads beyond the specified bound. The commit appears well-crafted: it addresses a real memory-safety concern, includes thorough test coverage, and has a clear motivation.
