This is a feature patch -- specifically 6/7 in Harald Nordgren's v15 series on matching-inspired fetch modes -- that adds a `--limited-fetch` (and `--no-limited-fetch`) option to `git remote add`. Instead of writing the usual wildcard `remote.<name>.fetch` refspec that tracks every branch on the remote, the option configures `remote.<name>.fetchRefmap` to map fetched heads into `refs/remotes/<name>/*` and sets `remote.<name>.fetchUpstreams` to true. The result is that a plain `git fetch <name>` pulls only the upstream branches that local branches actually track, which is the behavior implemented in patch 5/7.

The patch makes the new mode explicit and opt-in at remote-creation time, rejecting `--limited-fetch` when combined with `-t/--track` or `--mirror` since those already specify what to fetch. It touches `builtin/remote.c`, the `git-remote` man page, and adds tests in `t/t5505-remote.sh` confirming the config keys are set correctly and that conflicting flags are rejected. The commit message clearly explains the motivation: avoiding wasteful history negotiation for branches nobody uses, a pain point especially in shallow clones of large repositories.

Within the series, this patch serves as the user-facing entry point for the machinery built in earlier patches -- particularly the `fetchUpstreams` behavior from 5/7 and the `fetchRefmap` infrastructure from 3/7. The series as a whole remains under review and is currently queued in `next` as an earlier iteration; this v15 version is the latest refinement awaiting final maintainer sign-off. The patch itself is clean, well-documented, and includes appropriate test coverage.
