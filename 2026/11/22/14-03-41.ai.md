This is a bugfix series from Junio C Hamano addressing a long-standing API contract issue in the `strbuf_getwholeline()` family of functions in `strbuf.c`. The core problem is that when these functions detect `feof()` on the input stream, they return EOF without clearing the caller's output `strbuf`, which has led to stale buffer reuse bugs in several commands. The series is structured unusually: patch 1 makes `mailinfo` robust against the behavior, patches 2 through 4 add failing tests that demonstrate concrete bugs in `git shortlog` (t4201), `git clean -i` (t7301), and `git fast-import` (t9300), patch 5 implements the actual fix by clearing the strbuf upon EOF in `strbuf_getwholeline()`, and patch 6 adds regression tests for two additional infinite-loop issues in `clean` and `fast-import` that cannot be safely demonstrated as `test_expect_failure` before the fix. Key files touched are `strbuf.c`, `mailinfo.c`, and the four test scripts t4201-shortlog.sh, t5100-mailinfo.sh, t7301-clean-interactive.sh, and t9300-fast-import.sh. The commit messages for patches 2-4 contain detailed walkthroughs of how the stale buffer causes misbehavior in each command, and future discussion will likely reference whether the buffer-clearing behavior breaks any other callers that implicitly relied on the old contract.
