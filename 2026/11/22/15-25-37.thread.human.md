Omri Sarig has submitted a second version of a small documentation patch fixing AsciiDoc markup in the `git-update-index` man page, adding backticks around option names like `--refresh` and `--remove` so they render as code literals. The v2 differs from v1 only in the commit message subject line, which now follows Git's convention of lowercasing the second word.

Junio C Hamano has reviewed the patch and offered feedback on both the commit message and the patch content itself. While he agrees with the subject line change, he suggests using present tense in the body and reframing the motivation to emphasize that option names should be typeset in monospaced font per manual page conventions. More substantively, Junio points out that the patch misses adjacent markup that should follow the same convention: the enumeration header `-q`:: should become `` `-q`:: `` and the command name in single quotes (`'git update-index'`) should also use backticks. He cites Jean-Noël Avila's recent commit e9a99ef2da as the model for these comprehensive formatting fixes and advises bundling related corrections rather than sending narrowly scoped patches. The patch remains under review pending these revisions.
