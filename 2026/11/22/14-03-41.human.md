This is a bugfix series from Junio C Hamano addressing a long-standing API issue in `strbuf_getwholeline()`. When the function hits EOF on its input stream, it returns EOF but leaves the output buffer unchanged, a contract that has led to subtle bugs in several commands. The six-patch series is deliberately structured to demonstrate the problems first and fix the root cause later.

Patches 2 through 4 add tests that expose existing bugs in `git shortlog`, `git clean -i`, and `git fast-import`, each caused by callers reusing stale buffer contents after EOF. The commit messages provide detailed walkthroughs of the failure modes: shortlog reusing a stale buffer, clean's ask mode deleting past EOF, and fast-import re-parsing a heredoc delimiter at EOF. Patch 5 then fixes the actual bug in `strbuf.c` by clearing the buffer when EOF is reached.

Patch 1 independently fixes `git mailinfo` so that it no longer relies on the current behavior, ensuring it works correctly whether or not the buffer is cleared on EOF. Patch 6 adds bonus tests for infinite-loop scenarios in clean and fast-import that could not be safely written as expected failures before the fix. The cover letter explains that separating the demonstrations from the fix makes the series easier to review, since forcing reviewers to absorb three unrelated commands and the central change at once would obscure the motivation.

This looks like a well-crafted, maintainer-quality contribution that addresses a real correctness issue affecting multiple subsystems. The unusual ordering -- bugs first, fix last -- is clearly motivated and should help reviewers understand the impact without getting lost in implementation details.
