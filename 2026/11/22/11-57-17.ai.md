This is a cover letter for a seven-patch feature series (v15) by Harald Nordgren that reworks how `git fetch` behaves in shallow repositories, introducing explicit configuration for limiting fetches to tracked branches.

The series splits fetch control into two settings: `remote.<name>.fetchRefmap` decides where fetched refs are stored (the default for `--refmap`), while a new `remote.<name>.fetchUpstreams` boolean decides whether a refspec-less fetch also pulls the upstream branches of local branches. `git remote add --limited-fetch` sets both, and in shallow repositories `--limited-fetch` becomes the default for `git remote add`, with `--no-limited-fetch` to override. This resolves the earlier architectural debate: instead of implicitly inferring what to fetch whenever only a refmap was configured (the v14 behavior), the author now requires explicit opt-in via `fetchUpstreams`, keeping `remote.<name>.fetch` as the primary selector when present.

Two new patches at the head of the series implement the override semantics that were confirmed in the v14 review: a refspec carrying its own destination (`src:dst`) now ignores both `--refmap` and `fetchRefmap` entirely, preventing dual storage, and `--refmap` on the command line now works even without command-line refspecs, applying to whatever `remote.<name>.fetch` selects. The series also fixes `git pull` so it merges only the current branch's upstream rather than every tracked branch.

The implementation touches `builtin/fetch.c`, `remote.c`/`remote.h`, and `builtin/remote.c`, introducing the `fetch_upstreams` field on `struct remote`, the `add_branch_upstreams()` helper, and the config keys `remote.<name>.fetchRefmap` and `remote.<name>.fetchUpstreams`. Tests live primarily in `t/t5586-fetch-refmap.sh` (new), with additions to `t5510-fetch.sh` and `t5505-remote.sh`.

As of this v15 iteration the series remains under review and still blocks `ch/remote-defer-follow-remote-head-validation` due to textual conflicts; the earlier proposal to merge only patches 1--3 to unblock that topic has not been acted on in this version.
