This is a **refactoring** patch, specifically v15 patch 4/7 in Harald Nordgren's series introducing matching-inspired fetch modes for shallow repositories.

The patch extracts logic that was previously inlined in `do_fetch()` (`builtin/fetch.c`) into a new reusable helper, `collect_upstream_from_remote()`, declared in `remote.h` and defined in `remote.c`. The extracted logic checks whether a given branch (or the current branch when `refname` is NULL) has merge configuration pointing at the specified remote, and if so, pushes the branch's upstream source refs (from `branch->merge[i]->src`) into a `strvec` of tracked refs. The call site in `do_fetch()` now invokes this helper with `NULL` to preserve the existing behavior of fetching the current branch's upstream when no explicit refspec is given, referencing commit 49ca2fba39 which established this default behavior in 2022.

The behavioral change is neutral for the current call site, but the new function signature accepts an arbitrary `refname` parameter, enabling future patches in the series to collect upstreams for branches other than just the current one. This prepares the groundwork for the `remote.<name>.fetchUpstreams` feature described in the series cover letter, where a refspec-less fetch would pull upstream branches of all local branches (or a selected set) rather than only the current branch's upstream.

Files touched are `builtin/fetch.c` (removing the inlined block and calling the helper), `remote.c` (adding the function definition), and `remote.h` (adding the declaration with a doc comment). The diff is small and mechanical: 32 insertions, 10 deletions, with no changes to control flow at the existing call site.

In the context of the v15 series, this patch follows 3/7 (which added the `remote.<name>.fetchRefmap` config key) and precedes the patches that will implement the `fetchUpstreams` boolean to actually enumerate and fetch non-current-branch upstreams. The series remains queued in `next` and blocks `ch/remote-defer-follow-remote-head-validation` due to textual conflicts in these files.
