Junio C Hamano has posted a bugfix for the `git mailinfo` plumbing command addressing a case where email headers leak into the generated commit message when the input contains only headers and no body. The issue resides in `mailinfo()` in `mailinfo.c`, where the header-parsing loop unconditionally passes the last-read line to `handle_body()` after `read_one_header_line()` returns 0; on header-only input, that return value actually signals EOF rather than a successful blank-line read, causing the final header (such as `Content-Type`) to be treated as body text.

The patch changes `read_one_header_line()` to return -1 on EOF or error instead of 0, updating both call sites so that `mailinfo()` invokes `handle_body()` only on a return value of exactly 0 and `handle_boundary()` continues only while the return is greater than 0. It also adds a defensive length guard in `handle_filter_flowed()` and includes a regression test in `t/t5100-mailinfo.sh` verifying that a header-only message produces empty output without header leakage. The change touches only `mailinfo.c` and the test script.

As a focused edge-case fix from the maintainer with a clear reproduction and test coverage, the patch appears well-crafted and is now awaiting review from other contributors.
