Dirk Gouders has sent the fourth and final patch of his v5 series, which fixes UTF-8 width calculation in `utf8.c`. This particular patch corrects `utf8_strnwidth()` so that it respects the caller-supplied length boundary when decoding multibyte characters; previously the function could read past the given boundary and count bytes from an incomplete multibyte sequence as a complete glyph. The fix computes the remaining buffer length and passes it as a boundary to `utf8_width()`, ensuring truncated sequences at the end of a string are not counted.

The change is small and well-targeted, adding two regression tests in `t/unit-tests/u-utf8-width.c` under `test_utf8_width__strnwidth_cjk_chopped()` that verify correct widths when a CJK character is chopped by the length limit. As the concluding patch of the four-patch v5 series, it presumably builds on earlier fixes in the thread that addressed related boundary handling or ANSI escape skipping logic.
