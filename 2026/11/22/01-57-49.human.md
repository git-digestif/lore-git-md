This is a bugfix to `git mailinfo` from Junio C Hamano, correcting a case where email headers leak into the commit message when the input ends immediately after the headers.

The bug occurs on header-only input: when `read_one_header_line()` hits EOF while looking ahead for header continuations, it returns 0 but leaves the previous header line sitting in the `line` buffer. `mailinfo()` then unconditionally passes that stale line to `handle_body()`, causing headers like `Content-Type` to appear in the generated commit log instead of being consumed as headers.

The fix makes `read_one_header_line()` return -1 on EOF, and `mailinfo()` now calls `handle_body()` only when the function returns 0 (meaning a genuine blank or non-header line was read). The commit message explains why simply checking `feof()` in `mailinfo()` would be incorrect: an incomplete non-header line at EOF also sets the EOF flag while still leaving valid data in the buffer. A small defensive `len &&` guard is also added in `handle_filter_flowed()` for symmetry with a nearby CR check.

The patch includes a regression test in `t/t5100-mailinfo.sh` that feeds a header-only message to `git mailinfo` and verifies the commit message is empty. This is a well-crafted, focused fix from the maintainer with a clear root-cause analysis and test coverage.
