Dirk Gouders reported two failing tests in `t7527-builtin-fsmonitor--daemon.sh` on `origin/master` -- specifically the `move_directory_up` cases in both the untracked-cache-off and untracked-cache-on matrix configurations with fsmonitor enabled. In a follow-up diagnostic, he traced the failures to a fatal crash in the built-in fsmonitor daemon's Linux backend: when handling an upward directory move, the inotify listener attempts to remove the same directory watch twice, triggering `BUG("double remove of watch for '%s'", w->dir)` at `compat/fsmonitor/fsm-listen-linux.c:144`. The stray `core.*` file that was polluting the test comparison is simply the daemon's crash log.

The thread remains an open bug report with the root cause now identified but no fix proposed yet. The issue is isolated to the Linux fsmonitor listener's handling of `move_directory_up` events, where the watch cleanup logic removes a watch that has already been removed.
