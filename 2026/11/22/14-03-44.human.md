This is a **test** patch -- the third in a six-part bugfix series from Junio C Hamano -- that documents a user-visible bug in `git clean -i` without fixing it yet. It adds a `test_expect_failure` case to `t/t7301-clean-interactive.sh` demonstrating that the interactive "ask each" mode can delete every remaining untracked file when the user's answer reaches EOF without a trailing newline.

The scenario is specific: after choosing `a` for ask mode, the user answers `y` (no Enter) for the first prompt. Because `strbuf_getline()` returns EOF on the next read without clearing the `confirm` strbuf, the stale `"y"` persists and the loop interprets it as a repeated "yes" for every subsequent item. The new test pipes `a\ny` into `git clean -id` and expects only the first item to be removed, but currently the command deletes everything.

The patch is deliberately marked as an expected failure because the root cause -- `strbuf_getwholeline()` leaving stale data in the output buffer when it hits `feof()` -- is fixed later in the series (patch 5). Once that fix lands, the EOF read will empty `confirm`, the `!confirm.len` check will short-circuit the loop, and only the first file will be deleted as the test expects.
