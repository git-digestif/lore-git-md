This is a test patch, specifically the third of six in Junio C Hamano's series addressing the `strbuf_getwholeline()` EOF behavior in `strbuf.c`. It adds a single `test_expect_failure` case to `t/t7301-clean-interactive.sh` that demonstrates a concrete bug in `git clean -id` (interactive ask mode): when the user selects "ask each" and answers "y" to the first prompt without a trailing newline, the command incorrectly deletes every remaining untracked file instead of stopping at EOF.

The commit message provides a detailed walkthrough of the failure mechanism in `builtin/clean.c`. The `ask_each_cmd()` function loops over deletion candidates, reading user input into a reused `strbuf` named `confirm` via `git_read_line_interactively()` (which calls `strbuf_getline()`). On the first item, the incomplete line "y" is read and matches a prefix of "yes", so the item is marked for removal. On the second item, `strbuf_getline()` detects `feof()` and returns EOF without clearing `confirm`, leaving it containing the stale "y". The code then treats this stale value as a fresh affirmative answer, causing all subsequent items to be deleted despite the user having signaled EOF.

The test feeds `printf "a\ny"` to `git clean -id` and asserts that only the first file (`a.out`) is removed while all others remain, which currently fails and is therefore marked as `test_expect_failure`. The author explicitly notes that this behavior will be corrected by patch 5 of the series, which modifies `strbuf_getwholeline()` to clear the output buffer before returning EOF; once that fix lands, the stale "y" will be wiped on the second read, `!confirm.len` will evaluate true, and the loop will correctly stop removing files.

This patch touches only the test script `t/t7301-clean-interactive.sh` and serves purely to document the bug ahead of the actual fix. It is part of a broader effort to identify all callers affected by the long-standing contract violation where `strbuf_getwholeline()` preserves stale data on EOF, with similar demonstrations already added for `git shortlog` (patch 2) and planned for `git fast-import` (patch 4). Reviewers should note that the open question for the series remains whether clearing the buffer on EOF in `strbuf.c` will break other callers that implicitly relied on the old stale-preserving behavior.
