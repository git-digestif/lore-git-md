Thread identity: standalone bugfix patch for `git archive` option handling, authored by René Scharfe (l.s.r@web.de), touching archive.c, string-list.c, string-list.h, and t/t5000-tar-tree.sh.

Core problem or goal: the negative forms of `git archive`'s extra-entry options incorrectly wipe unrelated entries. Both `--add-file` and `--add-virtual-file` register entries in the same `string_list` (`args->extra_files` in archive.c), but `--no-add-file` and `--no-add-virtual-file` previously cleared the entire shared list, deleting entries added by the other positive option.

Current status: new patch posted, under review; no integration branch status reported.

Key technical details: the fix changes the unset path in `add_file_cb()` to filter the list rather than clear it, introducing a new helper `filter_string_list_func()` in string-list.c/string-list.h that accepts a predicate callback and a destructor while preserving the original ordering of retained items. A predicate `keep_file()` distinguishes regular files (where `extra_file_info->content` is NULL, added via `--add-file`) from virtual files (where content is set, added via `--add-virtual-file`), so each negative flag removes only its own entry type. Two tests in t/t5000-tar-tree.sh verify that each negative flag preserves entries added by the other positive flag when archiving from the empty tree. The commit message notes that using separate lists would have been simpler but would change the order of files in generated archives, hence the filtering approach.
