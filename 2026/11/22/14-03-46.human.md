This is the core bugfix of a six-patch series from Junio C Hamano, addressing a long-standing API contract violation in `strbuf_getwholeline()` and its frontends like `strbuf_getline_lf()`.

The patch makes `strbuf_getwholeline()` call `strbuf_reset()` on the output buffer when it takes the early EOF return path, rather than leaving stale data from a previous read in place. This is the change that actually repairs the misbehavior demonstrated in the preceding patches: `git shortlog` recording the wrong subject for commits at EOF, `git clean -id` treating a stale "y" as confirmation and deleting all remaining files, and `git fast-import` re-parsing a heredoc terminator as a `deleteall` command and corrupting the tree.

As part of the fix, Junio flips the three `test_expect_failure` cases added earlier in the series (in `t/t4201-shortlog.sh`, `t/t7301-clean-interactive.sh`, and `t/t9300-fast-import.sh`) to `test_expect_success`, confirming that the strbuf change resolves the bugs those tests captured.

The commit message acknowledges the risk that some existing caller might have implicitly relied on the old behavior of preserving buffer contents across an EOF return, but argues this is unlikely and that the sensible contract is that a read into a strbuf replaces its previous contents regardless of whether the call succeeds. It also notes that the earlier `mailinfo` hardening (patch 1 of the series) is necessary to avoid an out-of-bounds read in `handle_filter_flowed()` that would otherwise be exposed once the buffer is cleared on EOF.

Overall this looks like a well-motivated, central fix: it changes a low-level primitive to match what callers reasonably expect, and it is backed by concrete regression tests that were demonstrated to fail before the change.
