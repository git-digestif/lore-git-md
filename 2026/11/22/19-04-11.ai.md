This is a maintainer procedural update in an RFC feature thread, signaling movement toward integration.

Junio C Hamano confirms he will keep the test renumbering fix (t7427 to t7428) as a separate commit rather than squashing it into the main patch, noting the fix will become moot once the series graduates from RFC status. Re-reading Jacob Keller's earlier review, which he characterizes as a strong endorsement that thought through the design issues, Junio states he is inclined to perform the proposed squash and mark the `^/` submodule URL topic as ready for `next`. He invites any heavy submodule users to object before he merges the topic down, indicating the feature is now moving from RFC discussion toward integration cooking.

The underlying patch by Stanislav Aleksandrov introduces a `^/` prefix syntax for submodule URLs in `.gitmodules` that resolves relative to the superproject remote's server root rather than its path. For example, with a superproject at `https://host/me/super.git`, a submodule URL of `^/org/lib.git` resolves to `https://host/org/lib.git`, preserving protocol, host, and credentials while replacing only the path portion. The implementation touches `builtin/submodule--helper.c`, `submodule-config.c`, and `remote.c`, introducing a `root_relative_url()` function that handles SCP-style URLs with IPv6 brackets via `skip_bracketed_host()` and rejects local paths, `file://` URLs, and helper transports. The syntax is explicitly designed for submodules remaining at their original server location, distinct from `../` relative paths intended for forked dependencies.

Behaviorally, the feature is opt-in and backwards-compatible; existing URLs are unchanged. Malformed `^/` URLs that would alter the URL type (e.g., changing protocol) are rejected. Test coverage resides in t7428 and includes cloning, syncing, HTTPS/SSH/local forks, nested submodules, remote URL changes, and error conditions including shell escaping concerns (since `^` is special in `cmd.exe` and Git Bash) and IPv6 handling. No explicit test was added for IPv6 in SCP-style URLs despite the code path handling it.

The thread has reached a state where no technical objections remain from the core reviewers. Jacob Keller's review, referenced by URL in Junio's email, engaged substantively with design trade-offs including syntax choice versus existing mechanisms like `url.<base>.insteadOf`, fork isolation semantics, and the superiority of `^/` over `../../` for arbitrary nesting depths. The remaining open questions concern ecosystem adoption (libgit2, JGit, forges would need to implement the syntax) and the practical shell-quoting requirement, but these are not blocking integration. The topic is now positioned to move from RFC status into Junio's `next` branch for integration testing, though it has not yet been merged to `master`.
