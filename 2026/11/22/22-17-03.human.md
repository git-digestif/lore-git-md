This is a bug report that pins down the origin of two failing tests in the built-in fsmonitor daemon suite.

Dirk Gouders follows up on his earlier diagnosis of test failures in `t7527-builtin-fsmonitor--daemon.sh` by reporting the results of a bisect. He identifies commit `ce48de8b2c` ("fsmonitor: implement filesystem change listener for Linux", 2026-04-15) as the first bad commit that introduced the crash. The failure manifests when the Linux inotify backend processes a `move_directory_up` operation with fsmonitor enabled: the daemon aborts with `BUG("double remove of watch for '%s'", w->dir)` at `compat/fsmonitor/fsm-listen-linux.c:144`, attempting to remove the same directory watch twice.

The two affected tests are `Matrix[uc:false][fsm:true] move_directory_up` and `Matrix[uc:true][fsm:true] move_directory_up`, both of which exercise the interaction between the untracked cache and the fsmonitor daemon. The `core.*` file that originally confused the test comparison is simply the daemon's crash log.

No fix is proposed in this email; it serves to establish the exact commit and code path responsible, inviting the authors of the Linux fsmonitor listener to address the double-remove of the inotify watch.
