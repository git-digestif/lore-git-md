This is a substantive review reply from Andy Koppe on the first patch of the v4 series, offering a code simplification for `display_mode_esc_sequence_len()` and clarifying pointer-arithmetic safety around length bounds. Koppe suggests collapsing the existing end-pointer checks in the digit/semicolon scanning loop and the final `'m'` check into a more compact form: `while (!(end && p >= end) && (isdigit(*p) || *p == ';'))` followed by `if ((end && p >= end) || *p++ != 'm')`, which removes the redundant `end &&` guards scattered through the original logic.

He also addresses the alternative of reverting to a length parameter instead of the optional end pointer, noting that standard functions like `strncmp()` and POSIX `strnlen()` accept `SIZE_MAX` as a length bound. However, he warns that this safety does not extend to computing an end pointer as `start + SIZE_MAX`, because forming a pointer more than one past the end of the underlying object is undefined behavior even without dereferencing it. The correct approach with a length parameter is to check bounds via subtraction, such as `p - start < len`, before reading `*p`.

This feedback directly concerns the new signature `display_mode_esc_sequence_len(const char *start, const char *end)` introduced in patch v4 1/5, which is the foundational API change that later patches use to prevent out-of-bounds reads in `utf8_strnwidth()` and other call sites. The series remains under review with no part merged or queued; Koppe's earlier substantive objections to the wrapper design have been resolved by this end-pointer approach, and his current note refines the implementation details without challenging the overall direction.
