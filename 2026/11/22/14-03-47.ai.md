This is a test patch -- the sixth and final patch in Junio C Hamano's series fixing the `strbuf_getwholeline()` EOF behavior in `strbuf.c`. It adds regression tests to `t/t7301-clean-interactive.sh` and `t/t9300-fast-import.sh` for two infinite-loop bugs that were previously masked by the stale-buffer behavior fixed in patch 5.

The first test exercises `git clean -id` in filter-by-pattern mode. When the user selects the `f` filter option and provides a pattern like `*.out` without a trailing newline, `filter_by_patterns_cmd()` in `builtin/clean.c` enters a `for (;;)` loop reading patterns via `git_read_line_interactively()` into the `confirm` strbuf. On the second iteration, `strbuf_getwholeline()` previously returned EOF without clearing `confirm`, leaving the stale `*.out` pattern in place so the `if (!confirm.len) break;` check never fired and the loop re-applied the filter forever. With patch 5's change, the strbuf is emptied on EOF, the loop breaks cleanly, and the test verifies that `git clean -id` exits successfully while preserving files that do not match the pattern.

The second test targets `git fast-import`. When a commit stream ends with a `merge :2` line lacking a trailing LF, `parse_merge()` in `builtin/fast-import.c` calls `read_next_command()`, which uses `strbuf_getline_lf()` on the static `command_buf`. Previously, the EOF return left `command_buf` populated with `merge :2`, so the `while (skip_prefix(...))` loop in `parse_merge()` never terminated, looping until OOM. Now that `strbuf_getwholeline()` resets the buffer on `feof()`, `command_buf` becomes empty, `skip_prefix()` fails, and the loop exits. The test constructs a fast-import stream with two parent commits and verifies that `git rev-parse a^2` succeeds while `a^3` does not exist, confirming the merge was parsed exactly once.

Both tests are written as `test_expect_success` because they only pass with patch 5 applied; reverting patch 5 causes them to hang. The commit message provides detailed step-by-step walkthroughs of both infinite-loop mechanisms, naming the specific functions (`filter_by_patterns_cmd()`, `parse_merge()`, `read_next_command()`) and the strbuf variables (`confirm`, `command_buf`) involved, which will help future reviewers trace discussions about whether clearing the buffer on EOF has any unintended consequences for other callers.
