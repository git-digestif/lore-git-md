This is a refactoring patch -- specifically 4/7 in Harald Nordgren's v15 series that reworks how `git fetch` behaves in shallow repositories by introducing explicit `remote.<name>.fetchRefmap` and `fetchUpstreams` configuration.

The patch extracts a block of inlined logic from `do_fetch()` in `builtin/fetch.c` into a new helper, `collect_upstream_from_remote()`, now living in `remote.c`. When a fetch has no explicit refspec, Git currently checks whether the *current* branch has an upstream on the remote being fetched, and if so adds that upstream's source ref to the list of refs to fetch (so that `git pull` can find something to merge). This patch moves that check into a reusable function that takes an optional `refname` parameter -- `NULL` meaning the current branch -- without changing any behavior.

The motivation is forward-looking: later patches in the series need to apply this same "does this branch build on this remote?" check to *all* local branches, not just the current one, in order to implement the `fetchUpstreams` opt-in. By parameterizing the helper now, the author avoids duplicating the logic later. The commit message helpfully references commit 49ca2fba39, which originally introduced the default ref-prefix extension for the current branch's upstream.

The change is purely mechanical: it touches `builtin/fetch.c`, `remote.c`, and `remote.h`, moving 18 lines and adding the new declaration. There is no behavior change and no controversy apparent; it is a clean preparatory step for the feature work in patches 5--7. As part of the broader v15 effort, the series remains under review in `next` and continues to block the dependent `ch/remote-defer-follow-remote-head-validation` topic due to textual conflicts.
