This is a test patch documenting a stale-buffer bug in `git shortlog`, and it is the second of six patches in Junio C Hamano's series addressing the `strbuf_getwholeline()` family in `strbuf.c`. The series aims to fix a long-standing contract violation where these functions return EOF on end-of-input without clearing the caller's output `strbuf`, leaving stale data from previous reads.

The commit message provides detailed step-by-step walkthroughs of two failure modes in `builtin/shortlog.c:read_from_stdin()`. In the first, an incomplete "Author:" line at EOF causes the previous commit's subject to leak into the current record because the `oneline` strbuf retains its old contents when `strbuf_getline_lf()` hits EOF. In the second, an incomplete header line such as "Date:" at EOF causes that discarded header text to be recorded as the commit's subject. Both cases produce incorrect `git shortlog` output when reading from standard input.

Rather than fixing the code here, the patch adds two `test_expect_failure` cases to `t/t4201-shortlog.sh` that capture these incorrect behaviors. This deliberate choice reflects the series' structure: the actual fix to `strbuf_getwholeline()` itself arrives in patch 5, and patch 6 adds regression tests for other affected commands. By marking these as expected failures now, the tests will automatically start passing once the strbuf is cleared on EOF, providing a clear before-and-after demonstration.

The contribution is well-crafted, with precise commit messages that trace the exact code path and buffer state at each step, making it easy for reviewers to verify the diagnosis. As patch 2 of 6, it fits into a larger narrative where patch 1 already hardened `mailinfo` against the same issue, and patches 3 and 4 similarly document bugs in `git clean -i` and `git fast-import` before the central fix lands.
