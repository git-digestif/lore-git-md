This is a cover letter for v5 of a four-patch bugfix series (down from five in v4) targeting UTF-8 bounds handling in `utf8.c`, posted by Dirk Gouders. The series reverts from v4's end-pointer design back to a length-based (`_counted`) API, but now uses an array index rather than pointer arithmetic to avoid both O(n²) degradation on NUL-terminated strings and the undefined behavior of computing `s + len` when `len` is `SIZE_MAX`.

Patch 1, authored by Junio C Hamano, introduces `display_mode_esc_sequence_len_counted(const char *s, size_t len)`, which scans for ANSI SGR sequences bounded by an index/length rather than an end pointer. Patches 2 through 4 by Gouders fix the `utf8_strnwidth()` comment to say "NUL-terminated" and correct the documented return value from `strlen()` to `len`; ensure `utf8_strnwidth()` respects the `len` boundary after skipping ANSI escape sequences (using the new `_counted` variant and checking against `orig + len`); and modify the main loop to compute a `remainder` and pass it to `utf8_width(&string, &remainder)` so multibyte characters chopped by `len` do not cause out-of-bounds reads. The undeclared `skip` variable that broke v4's compilation is restored, and the v4 patch 5 (`display_mode_esc_sequence_len_all()`) is dropped entirely as noise.

Tests are added in `t/unit-tests/u-utf8-ansi.c` (wired into both `Makefile` and `t/meson.build`) for the new counted function, including wrapper tests, and in `t/unit-tests/u-utf8-width.c` for bounded `utf8_strnwidth()` behavior including chopped CJK sequences. The test code now uses arrays initialized with string constants so that `sizeof()` yields the correct buffer size rather than pointer size, addressing earlier review nits. No on-disk format changes; base commit is `f7de81456940dd6f3274e461149bba12965de609`.
