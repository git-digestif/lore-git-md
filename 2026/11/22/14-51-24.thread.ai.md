Core problem or goal: prevent out-of-bounds reads when the ANSI escape sequence parser operates on non-NUL-terminated (counted-length) buffers, by introducing a bounded variant of the parser and migrating the unsafe call sites to it.

Current status: v5 posted; patch 1/4 introduces the new API and migrates three callers. No merge, graduation, or "What's cooking" status has been stated for this series; it is under review.

Key technical details: new function `display_mode_esc_sequence_len_counted(const char *s, size_t len)` added to `utf8.c` and declared in `utf8.h`, guaranteeing it never reads at or beyond `s[len]`. The existing `display_mode_esc_sequence_len()` is retained as a thin wrapper that calls the counted variant with `SIZE_MAX`, preserving NUL-terminated semantics for existing callers; the commit message credits Andy Koppe with suggesting the `SIZE_MAX` sentinel to avoid O(n^2) degradation. Three call sites now pass an explicit remaining length: `utf8_strnwidth()` passes `orig + len - string`; `strbuf_utf8_replace()` and `strbuf_add_wrapped_text()` compute the end pointer once and pass the remaining distance per iteration, fixing a latent over-read past the logical end of counted buffers. Tests: new clar unit suite `t/unit-tests/u-utf8-ansi.c`, registered in both `Makefile` and `t/meson.build`, covering the counted function with `SIZE_MAX`, the wrapper, and explicitly limited lengths to verify the bound is never exceeded.
