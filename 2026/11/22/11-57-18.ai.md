This is patch 1 of 7 in v15 of Harald Nordgren's "matching-inspired fetch" feature series, implementing the first half of the override semantics confirmed by Junio C Hamano and Phillip Wood: a refspec that carries its own destination (`src:dst`) now ignores `--refmap` entirely, so the fetched ref is stored only at the explicit destination and not duplicated through the refmap.

The patch modifies `builtin/fetch.c` to introduce a new helper `map_refs_without_dst()` that filters the ref map to only those entries lacking a `peer_ref` before applying the refmap, replacing the previous logic that applied `--refmap` indiscriminately to command-line refspecs. It updates `Documentation/fetch-options.adoc` to document that `<src>:<dst>` refspecs are stored only at `<dst>`, and adds a test case to `t/t5510-fetch.sh` verifying that `git fetch --refmap=... origin main:refs/remotes/custom/main side` stores `main` only at `custom/main` (not at the mapped location) while `side` (no destination) still goes through the refmap. Opportunistic updates via `remote.<name>.fetch` are explicitly left unchanged.

This patch is well-motivated and directly enables the next patch in the series (2/7), which introduces `remote.<name>.fetchRefmap` as a configured default for `--refmap`; without this change, a configured default would cause dual storage for any command-line refspec with an explicit destination. The commit message clearly explains the rationale, the change is minimal and focused, and it carries the maintainer's prior endorsement from the v14 review discussion.
