Core problem or goal: `utf8_strnwidth()` in `utf8.c` could read beyond the specified string boundary when `skip_ansi` was enabled and an ANSI escape sequence ended exactly at or beyond the given length limit (`orig + len`). The function would advance past the escape sequence without checking whether it had reached the end of the string, then call `utf8_width()` on an out-of-bounds position.

Current status: v5 of the series, patch 3/4 posted and under review; no merge or integration status stated.

Key technical details: The fix in `utf8.c` adds a bounds check immediately after the ANSI-skipping loop in `utf8_strnwidth()`: if the `string` pointer has reached or exceeded `orig + len`, the function breaks out and returns the accumulated width. A new unit test `test_utf8_width__strnwidth_ansi()` was added to `t/unit-tests/u-utf8-width.c`, exercising three cases with the string `"\033[31mhello"`: length ending inside the escape sequence (returns 3), length ending exactly at the sequence's end (returns 0), and length including the first character after the sequence (returns 1).
