This is a bug report about failing tests in the Git test suite. Dirk Gouders reports that `t7527` (the FSMonitor test script) is currently failing on `origin/master` with 2 of 70 tests not passing.

The two failures are both `move_directory_up` scenarios within the test matrix -- specifically tests 43 and 56, which run with fsmonitor enabled (once with untracked cache disabled and once with it enabled). Both fail at the `test_cmp` step that compares expected versus actual `git status --porcelain=v1` output after moving a directory up. The author notes seeing a `core.*` file appear in a temporary directory during the run, which he suspects is contaminating the comparison and causing the mismatch.

The email is a query to the list asking whether this is a known issue before he invests time debugging it further. At this point the report is observational only -- no patch or fix is proposed, just a signal that the test suite is currently red on master for this particular scenario involving directory moves under fsmonitor.
