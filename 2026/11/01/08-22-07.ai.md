This is the v6 iteration of Harald Nordgren’s four-patch series that extends `git branch --delete-merged` with a new `--delete-integrated` flag. The flag detects branches whose changes (but not their tips) have been integrated into an upstream branch via squash merges, rebases, or patch-based workflows, even when the upstream modified the same files before integration. The series is now under final review; the only substantive technical feedback from Junio on v5—an index-population issue affecting `.gitattributes`-driven merge behavior—has been fixed in v6 by calling `repo_read_index()` before the file merge. The remaining changes are stylistic: renaming `opt` to `diffopt` in the diff machinery and addressing two usability nits (help text and error message for combined flags).

The first two patches (preparatory refactoring and landing-message helper) remain uncontroversial and ready for integration. The third patch (core `--delete-integrated` flag) implements rebase detection via tree-based diffing and squash detection via a path-by-path three-way merge approximation using Git’s low-level `ll_merge()` machinery. The fourth patch extends squash detection to handle upstream modifications, now with correct `.gitattributes` support. The CLI design is finalized: `--delete-merged` retains its strict tip-reachability behavior, while `--delete-integrated` is opt-in and handles both rebase and squash merges by default. The series explicitly addresses the false-positive issue by splitting the behaviors into separate flags, ensuring `--delete-merged` never deletes branches whose changes were independently implemented by another author.

Key technical details: the series touches `builtin/branch.c`, updates `Documentation/git-branch.adoc` and `Documentation/config/branch.adoc`, and adds comprehensive tests in `t/t3200-branch.sh`. The new output format (`Deleted branch topic (was 1a2b3c4, landed as 9f8e7d6)`) clearly shows where each branch’s changes landed. Performance optimizations keep rebase detection tree-based (no blob fetches), while squash detection with upstream modifications may download blobs in partial clones. Edge cases handled include upstream modifications, reverted changes, partial landings, and mixed workflows. The author-check mitigation (Jasper’s proposal) remains the sole major technical gap but is not implemented in this series.

Open questions: whether to implement the author-check mitigation or patch IDs for rebase detection to address the "npm update" scenario and forge workflows, and whether to document the squash-detection algorithm’s limitations (e.g., lack of rename detection, blob-fetching behavior in partial clones) more explicitly. Jasper’s remaining usability nits (outdated cover letter flag names, silent skipping of checked-out worktrees) are still unaddressed. The series is now technically complete and awaiting Junio’s final review before integration.
