This is a small but useful diagnostic patch targeting the `git maintenance` subsystem.

The patch addresses a silent failure mode in `git maintenance run --auto`: when the command encounters an existing `maintenance.lock` file, it skips maintenance without any indication, making it hard for users to detect repeated skips (e.g., due to stale locks from interrupted processes). The fix adds a Trace2 data event that logs when this skip occurs, allowing users to track these events when Trace2 logging is enabled.

The change is minimal: two lines added to `builtin/gc.c` to emit the trace event when the lock exists and the `--auto` flag is set, plus a new test in `t/t7900-maintenance.sh` to verify the trace output. The commit message clearly explains the problem and solution, and the test coverage is appropriate.

This looks like a well-scoped, low-risk improvement that doesn’t change behavior but makes troubleshooting easier. It’s the kind of patch that’s easy to overlook but could save users time when debugging maintenance issues. No controversy or follow-up work is evident from the patch itself.
