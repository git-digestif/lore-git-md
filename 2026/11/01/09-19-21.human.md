This is a bugfix series addressing silent truncation of large files (4GiB or more) on 64-bit Windows, where `long` is 32 bits but `size_t` is 64 bits. The issue affects two commands: `` `git archive` `` (both tar and zip formats) and `` `git apply` ``, which write corrupt or truncated files without error.

The series consists of two patches. The first converts `` `git archive` `` to use `size_t` for archive entry sizes, fixing truncation in streaming writes. The second does the same for `` `git apply` ``, ensuring patched files are written fully. Both patches touch the core logic in `archive-tar.c`, `archive-zip.c`, and `apply.c`, with minimal changes to function signatures.

Elia notes the fixes were verified by simulating truncation at 16 bits, though no new tests were added. The existing `t5004` test for 4GB+ zip archives remains disabled on 32-bit `long` platforms, but Elia suggests it could now be enabled on 64-bit Windows (where `size_t` is 64 bits) as a follow-up. The series is self-contained and merges cleanly with current `master`.
