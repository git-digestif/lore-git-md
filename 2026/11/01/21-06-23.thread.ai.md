Thread identity: Outreachy proposal for *"Improve how command arguments and options are scanned and parsed"* by Cynthia Uche, targeting the December 2026 Outreachy round. Thread type: project proposal (RFC).

Core problem or goal: Extend the `early_scan_options()` API (introduced in Christian Couder’s `cc/early-scan-options` series, currently in `seen`) to additional Git commands that currently perform ad-hoc argument scanning before `parse_options()`. The goal is to eliminate discrepancies between early scanning and `parse_options()` by converting commands like `git column`, `git bisect`, and `git check-ref-format` to use the new API.

Current status: Proposal stage; no code has been posted yet. The `cc/early-scan-options` series is the dependency and is currently in `seen` (under review). Cynthia has contributed a microproject (merged to `master`) and reviewed the `early-scan-options` series, demonstrating engagement with the codebase.

Key technical details:
- **Files/subsystems**: `builtin/column.c`, `builtin/bisect.c`, `builtin/check-ref-format.c`, `parse-options.c`.
- **New/renamed symbols**: `early_scan_options()`, `PARSE_OPT_EARLY`, `parse_options_takes_argument()`, `lookup_long_opt()`.
- **Behavior changes**: Commands may start accepting option abbreviations, `--no-` forms, or `--` where they previously rejected them. Some (e.g., `git column`) may drop "must be first argument" restrictions if those are deemed unintentional.
- **On-disk format**: No changes.
- **Test coverage**: Existing tests (`t9002` for `column`, `t1402` for `check-ref-format`, `t6030` for `bisect`) will need updates to reflect new behavior. The proposal prioritizes test coverage and incremental conversion (e.g., `bisect_terms()` before `bisect_start()`).

Open questions and loose ends:
- Whether `git column`’s "must be first argument" rule is intentional or an artifact of hand-rolled parsing. This may require discussion on the list.
- Whether `git check-ref-format` should accept options after `<refname>` (currently rejected).
- The `cc/early-scan-options` series must graduate to `next` before conversions can proceed.

Participant positions: Cynthia Uche is the sole author of the proposal. No reviews or objections have been posted yet, but the proposal anticipates discussion around the "must be first" rule for `git column` and the behavior of `git check-ref-format`.

Related work: The `cc/early-scan-options` series (Christian Couder) is the direct dependency. The proposal builds on this work and targets commands that were not covered by the original series.
