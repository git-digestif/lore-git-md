This is a CI/build system patch, the first in a three-patch series restoring GitHub Actions CI jobs after Ubuntu 26.04 became the default runner image. The patch addresses a hygiene issue: the `linux32` job currently uses `apt` (meant for interactive use) instead of `apt-get` (intended for scripting), which triggers CLI interface warnings. The fix is a one-line change in `.github/workflows/main.yml`, replacing `apt` with `apt-get` to match the style already used in `ci/install-dependencies.sh`.

The motivation is straightforward: eliminate noisy warnings in CI logs without altering functionality. The change is conservative and aligns with existing practice elsewhere in the CI scripts. No substantive review has appeared yet, but the patch looks uncontroversial—it’s a clean, minimal fix that doesn’t introduce new behavior or dependencies.

This patch affects only the `linux32` job and doesn’t touch the other failing jobs (`documentation`, `fuzz-smoke`, `static-analysis`), which are addressed in the subsequent patches. The series as a whole is pragmatic, targeting immediate breakage rather than redesigning the CI infrastructure, and this patch is the simplest of the three.
