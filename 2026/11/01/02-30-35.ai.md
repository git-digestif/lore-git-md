This is Junio C Hamano's review of the v2 patch that adds a safeguard against operating on shallow boundary commits in `git revert`, `git cherry-pick`, and all `git rebase` backends. The review is substantive but focused on minor implementation details rather than the core design.

Junio acknowledges that all the changes since v1—extending the safeguard to all rebase backends, moving the check to the planning stage, supporting `--allow-shallow-boundary` across `--continue`, and omitting the option from the synopsis—are sensible improvements. He questions the necessity of the rebase onto current `master`, asking whether the previous version was outdated or if unrelated changes made the rebase unavoidable. This is a procedural check rather than a technical objection.

On the two uncovered cases (`git commit --amend` and manually edited rebase todo lists), Junio notes that starting small is acceptable but asks whether there is a vision for how these might be supported later. This suggests he expects the safeguard to eventually cover these cases, though not necessarily in this patch.

The only technical nit is about the use of `git_config_bool_or_int()` instead of `git_config_bool()` for the `allow-shallow-boundary` config key. Junio finds this inconsistent with the boolean nature of the setting and expects a justification beyond "other booleans use it." This is a surface-level review point, not a blocker.

Overall, the patch appears to be in good shape, with Junio's feedback limited to minor details. No merge decision has been made yet, but the review signals that the patch is close to being ready for integration.
