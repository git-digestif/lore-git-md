This is a v2 documentation and terminology cleanup series that aligns Git’s glossary, man pages, code comments, and tests with the 2024 redefinition of "pseudoref" (now limited to FETCH_HEAD and MERGE_HEAD) and the introduction of "root ref" for refs outside the "refs/" hierarchy (e.g., HEAD, ORIG_HEAD). The series touches 22 files, including the glossary, six man pages, built-in commands, refs internals, and test scripts.

v2 addresses feedback from Junio C Hamano and Patrick Steinhardt on the glossary’s "pseudoref" definition, now explicitly listing supported operations (direct reading via `git log`/`git diff`) and clarifying that pseudorefs cannot be written by `git update-ref` or listed by `git for-each-ref`. The "per-worktree ref" entry now uses itemized AsciiDoc lists for better readability, and the "worktree" entry has been simplified by removing explicit examples and cross-referencing the "per-worktree ref" section. Julia Evans’s proposal to expand `gitdatamodel.adoc` is also incorporated, adding dedicated sections for root refs and pseudorefs to the data-model guide.

Key changes in v2 include:
- Glossary tweaks: restored "different semantics" phrasing for pseudorefs, added prefix lists for per-worktree refs, and wrapped lists in `--` for AsciiDoc formatting.
- Documentation updates: `gitdatamodel.adoc` now explicitly covers root refs and pseudorefs, and `git-update-ref(1)`’s reflog documentation has been corrected to reflect that only HEAD (not ORIG_HEAD) gets a reflog by default.
- Commit message trimming for patches 3 and 4, focusing on the core terminology changes.

The series remains uncontroversial, with no behavioral changes or new test cases. Junio’s general approval ("a pleasant read") suggests it is on track for merging, though the glossary’s phrasing may still see minor refinements. The updates to `gitdatamodel.adoc` close a gap in the pedagogical documentation, making the series more comprehensive than initially proposed.
