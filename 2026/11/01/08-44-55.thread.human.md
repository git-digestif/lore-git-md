This thread is a two-patch bugfix series from Elia Pinto addressing a silent 4 GiB file size truncation issue on 64-bit Windows (and other platforms where `long` is 32 bits but `size_t` is 64 bits). The problem causes `git grep` to miss matches in large files and `git diff` to generate misleading patches that would truncate files when applied.

The first patch fixed the `grep` subsystem by widening buffer sizes to `size_t`, while the newly posted second patch makes `git diff` die with a clear error when encountering files of 4 GiB or larger in the working tree, textconv, `--no-index`, or combine-diff scenarios. This matches existing behavior for blobs and prevents silent corruption. The changes are mechanical and confined to size assignment points, using a new `cast_size_t_to_ulong()` helper that checks for truncation.

The series is under review with no prior versions or open objections. While the patches address the immediate correctness problems, the author acknowledges that widening `diff_filespec.size` to `size_t` for full 4+ GiB support remains a larger effort deferred to a future series. No tests are included due to the impracticality of generating 4 GiB inputs, but the author has verified the `grep` portion through simulated truncation testing. The patches merge cleanly with current `master`.
