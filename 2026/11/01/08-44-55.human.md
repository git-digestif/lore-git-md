This is a bugfix series targeting platforms where `long` is 32 bits but `size_t` is 64 bits (notably 64-bit Windows). The patches address silent truncation of file sizes at or above 4 GiB in `git grep` and `git diff`, which could lead to incorrect results or misleading patches without warning.

The first patch widens buffer sizes in `git grep` to `size_t`, ensuring it correctly handles large files in the working tree, blobs, and `--no-index` mode. The second patch makes `git diff` (including textconv, `--no-index`, and combine-diff) die with an error when encountering files too large to process safely, matching the existing behavior for blobs. The commit messages detail the specific failure modes and verification steps, though no tests are included due to the impracticality of generating 4 GiB inputs for CI.

The changes are narrowly scoped to the reachable truncation issues, leaving broader refactoring (like widening `diff_filespec.size` to `size_t`) for future work. The series is self-contained and merges cleanly with current `master`. This looks like a well-motivated, low-risk fix for a real edge case on affected platforms.
