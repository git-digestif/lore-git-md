This is a review reply in the ongoing `git describe` commit-distance bugfix thread. Junio C Hamano responds to Tuomas Ahola’s suggested rewrite of Linus Torvalds’ test case, raising two technical concerns.

First, Junio points out that Tuomas’s rewrite uses `test_config` inside a subshell, which may fail because the test framework’s cleanup actions cannot be registered from subshells. This is a correctness issue: the test might leave behind state or fail unpredictably.

Second, Junio argues that the rewrite sacrifices clarity for conciseness. The original test hard-codes explicit timestamps (e.g., "2020-01-01 17:01"), making it immediately obvious which commit is older or newer. Tuomas’s version manipulates `$test_tick` (a global test clock) to achieve the same skew, but the relative ordering is no longer visible in the source. Junio questions whether the trade-off is justified, especially in a test whose entire purpose is to verify behavior when timestamps are out of order.

The review is substantive but narrowly focused on test design. Junio does not engage with the core fix (prioritizing commit generation numbers over dates) or suggest changes to it. The thread remains open; no new objections to the patch itself have been raised.
