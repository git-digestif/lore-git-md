# Thread deltas

## 2026/11/01

- [2026/11/01/23-29-24 by Farid Zakaria <farid.m.zakaria@gmail.com>] Farid Zakaria posted a two-patch series describing races in credential-cache--daemon when two "git credential-cache store" commands run simultaneously and each tries to start a daemon: the second daemon unlinks the first's socket and binds its own, causing the first's stored credential to be lost, "git credential-cache exit" to stop only the second daemon, and the first daemon's tempfile handler to remove the second's socket when it exits; he found the issue using Rewind, a deterministic VM he is building.
- [2026/11/01/23-29-25 by Farid Zakaria <farid.m.zakaria@gmail.com>] In the first patch, Farid Zakaria fixes the concurrent socket-directory creation race by ignoring EEXIST from mkdir() and instead stat-ing the directory to verify its permissions the same way as for a pre-existing directory, preventing the second daemon from dying with "File exists" and its client from failing with "cache daemon did not start".
- [2026/11/01/23-29-26 by Farid Zakaria <farid.m.zakaria@gmail.com>] In the second patch, Farid Zakaria fixes the socket takeover race by using unix_ss_create() instead of unix_stream_listen(), which takes a lock and binds only if no other server is listening, so a second daemon prints "ok" and exits while its client talks to the running daemon; the socket is registered for removal only after binding succeeds, so a losing daemon never removes the running daemon's socket.

## 2026/11/03

- [2026/11/03/08-01-08 by Patrick Steinhardt <ps@pks.im>] Patrick Steinhardt, reviewing "credential-cache--daemon: allow a concurrently created socket dir", asked Farid Zakaria to fix in a preparatory commit the pre-existing use of `safe_create_leading_directories()` (which wrongly applies "core.sharedRepository" to the daemon's socket directory) by calling `safe_create_leading_directories_no_share_const()` instead; he agreed the EEXIST-tolerant mkdir change "makes sense", and noted the duplicated stat/permissions-check logic is a shame but he sees no obvious way to avoid it.
- [2026/11/03/08-01-14 by Patrick Steinhardt <ps@pks.im>] Patrick Steinhardt, reviewing "credential-cache--daemon: do not take over a running daemon's socket", asked that the commit message be rewritten in imperative style ("Fix that by using `unix_ss_create()` instead..."), called the new comment explaining the bind-only-if-no-daemon logic somewhat useless for lacking the "why", questioned why the daemon prints "ok" when it fails to start (asking why pretending everything was alright is right), and said the "Remove the socket at exit only now that it is ours" comment adds little value.
- [2026/11/03/17-24-13 by Junio C Hamano <gitster@pobox.com>] Junio C Hamano, on the same patch, questioned whether mixing the unix_ss_* API with tempfile is sane, arguing `register_tempfile()` is unnecessary and architecturally undesirable because `unix_ss_create()` already detects and safely unlinks stale sockets, and that `delete_tempfile()` (including in the signal handler) blindly unlinks the socket, bypassing the `unix_ss_was_stolen()` inode check that protects a taken-over socket.
