This is the first patch in the **v5 bugfix series for `git imap-send`**, addressing a long-standing tunnel-command lifecycle issue. The patch ensures that when `imap.tunnel` is configured, the tunnel process is properly waited for and cleaned up, fixing a memory leak in the argument list and process handle.

The change is straightforward: the `imap` struct now stores the tunnel as an allocated `child_process` pointer (rather than a stack-allocated local variable), and `imap_close_server()` calls `finish_command()` and `free()` to reap the process. This aligns with Git’s run-command API best practices and resolves feedback from Patrick Steinhardt in earlier iterations about defensive coding. The patch touches only `imap-send.c` and introduces no new behavior—just proper cleanup where none existed before.

This patch was previously merged to `next` in v4 (2025-06-10) and remains unchanged in v5. The tunnel fix is orthogonal to the CRLF header-parsing bug addressed in Patch 2/4, which is the sole reason for the v5 resend. The commit message clearly explains the leak’s origin (inherited from isync, carried over in 2009) and why it went unnoticed (no tests set `imap.tunnel`).

For a future AI summarizer, note the key symbols: `imap->tunnel` (now an allocated pointer), `finish_command()`, and the `imap_close_server()` cleanup hook. The patch is uncontroversial and well-motivated, with no open questions.
