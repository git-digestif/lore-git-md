Subject: CI: Fix Ubuntu 26.04 compatibility after GitHub Actions update
Series version: v1 (initial submission)
Originating author: Harald Nordgren (via GitGitGadget)
Thread type: patch series (build system / CI)

Core problem or goal
Restore four failing CI jobs on GitHub Actions after the `ubuntu-latest` runner image was updated to Ubuntu 26.04. The breakage is caused by (1) CLI interface warnings from `apt` vs `apt-get`, (2) a permission error when creating symlinks during dependency installation (specifically replacing `/usr/bin/dirname` with a GNU-compatible version), and (3) a temporary Docker networking issue (DNS resolution for `deb.debian.org`) in the `linux32` job due to Docker 29.4.2's seccomp profile blocking `socketcall` for 32-bit glibc containers. The series applies minimal, targeted fixes without redesigning the CI infrastructure.

Current status
Queued in `seen`; no prior versions. Junio’s “Will queue. Thanks” confirms the series is accepted for review and will appear in the next `seen` rebuild. The patches touch only `.github/workflows/main.yml` and `ci/install-dependencies.sh`. The fixes are based on prior work by Johannes Schindelin in Git for Windows, suggesting they have been tested in a similar environment.

Key technical details
- Files: `.github/workflows/main.yml`, `ci/install-dependencies.sh`
- Jobs affected: `linux32`, `documentation`, `fuzz-smoke`, `static-analysis`
- Changes:
  1. Switch from `apt` to `apt-get` in the `linux32` job’s `prepare libc6 for actions` step to silence CLI interface warnings (hygiene, no behavioral change).
  2. Run `ln` with `sudo` in `ci/install-dependencies.sh` to work around a permission issue when replacing `/usr/bin/dirname` with a GNU-compatible version (affects `documentation`, `fuzz-smoke`, `static-analysis`).
  3. Pin the `linux32` job to Ubuntu 24.04 via a conditional `runs-on` expression in `.github/workflows/main.yml` to bypass the Docker networking issue, leaving all other jobs on `ubuntu-latest`. The fix references GitHub Actions runner-images issue #14790, documenting the upstream regression.
- New or renamed symbols: none
- On-disk format changes: none
- Test coverage: CI jobs themselves; no new test files

Open questions and loose ends
- The `sudo` workaround may still draw scrutiny if reviewers prefer a more robust solution (e.g., adjusting file permissions or avoiding symlink replacement altogether).
- The networking fix for `linux32` is explicitly temporary; Junio notes it will need to be reverted once the upstream Docker issue is resolved.
