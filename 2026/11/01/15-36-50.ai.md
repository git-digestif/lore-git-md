This is the second patch in Elia Pinto’s three-patch bugfix series addressing integer truncation in large-file handling. It targets the `count_lines()` function in `diff.c`, which currently takes its size parameter as an `int` but is called with `unsigned long` or `size_t` values from elsewhere in the diff subsystem. When processing files of 2 GiB or larger, the `int` parameter truncates or wraps, causing `git diff -B --stat` to report incorrect line counts (e.g., zero changed lines instead of the actual value). The patch changes the parameter to `size_t`, matching the types used by callers and eliminating the truncation risk. The line counter itself remains an `int`, as line counts are not expected to exceed `INT_MAX` in practice. No test is included due to the impracticality of generating multi-gigabyte test files, but the issue was confirmed via a 16-bit truncation simulation. The change is minimal (one line) and self-contained, touching only `diff.c`. This patch is part of the same well-motivated effort as the rest of the series, which addresses real (if niche) corruption risks in packfile generation, diffstat output, and rename detection.
