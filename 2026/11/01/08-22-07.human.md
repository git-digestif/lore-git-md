This is a feature patch series that extends `git branch --delete-merged` to detect branches whose changes (but not their tips) have been integrated via squash merges, rebases, or patch-based workflows, even when upstream modified the same files. The series is now in its sixth iteration and consists of four patches: a preparatory refactoring, a helper to report where branches landed, the core `--delete-integrated` flag, and squash-detection that handles upstream modifications via a three-way merge approximation.

The key improvement in v6 is a fix for the correctness issue Junio identified in v5: the index is now read before calling `ll_merge()`, ensuring `.gitattributes`-driven merge behavior is honored. This resolves the latent bug where merge drivers were silently ignored. The series also incorporates earlier feedback by renaming `opt` to `diffopt` for clarity and addressing two usability nits (adding `--delete-integrated` to `git branch -h` and simplifying the error message for combined flags).

The CLI design is finalized and explicitly confirmed by Junio: `--delete-merged` retains its strict tip-reachability behavior, while `--delete-integrated` (opt-in) detects both rebased and squash-merged branches, including those with upstream modifications. The series is well-motivated, with clear user benefits for GitHub-style workflows and thorough test coverage in `t/t3200-branch.sh`. The first two patches remain uncontroversial and ready for integration, while the third and fourth patches now address all substantive technical feedback.

The remaining open question is whether to implement Jasper’s proposed author-check mitigation to reduce false positives in rebase detection (e.g., the "npm update" scenario), but this is not a blocker for the current functionality. The series looks mature and addresses a real pain point for users who rely on squash or rebase merges.
