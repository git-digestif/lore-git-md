This is the third patch in Harald Nordgren’s v6 series introducing `git branch --delete-integrated`. It implements the core flag that detects branches whose changes (but not their tips) have been integrated into an upstream branch via rebase or squash merges, even when the upstream later modified the same files. The patch is now technically complete: Junio’s only feedback on v5—a variable rename (`opt` → `diffopt`) for clarity in `find_landed_commits()`—has been addressed, and the CLI design is finalized.

The patch adds the `--delete-integrated` flag, which extends the existing `--delete-merged` logic to also delete branches when some upstream commit since the fork point contains their exact file versions. The output format (`Deleted branch topic (was 1a2b3c4, landed as 9f8e7d6)`) clearly shows where each branch’s changes landed. Rebase detection remains tree-based (no blob fetches), while squash detection is handled by the fourth patch via `ll_merge()`. The series explicitly splits the behaviors into separate flags to avoid false positives: `--delete-merged` retains its strict tip-reachability behavior, ensuring it never deletes branches whose changes were independently implemented by another author.

Key changes in this patch include the `DELETE_BRANCH_INTEGRATED` flag, the `landing_search` struct (tracking branch changes and upstream commits), and the `find_landed_commits()` helper (using diff machinery to identify the first upstream commit containing all branch changes). The test suite (`t/t3200-branch.sh`) now covers rebase-merged, squash-merged, and reverted branches, as well as mixed scenarios where some branches remain unmerged. The patch is uncontroversial beyond the stylistic rename and awaits Junio’s final review alongside the rest of the series.
