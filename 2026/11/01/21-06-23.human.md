This is an Outreachy proposal draft from Cynthia Uche for the project "Improve how command arguments and options are scanned and parsed." The proposal targets the December 2026 Outreachy round and is seeking feedback on its inventory of candidate commands and timeline.

The core problem Cynthia describes is that some Git commands perform an early, hand-rolled scan of command-line arguments to extract specific options before calling `parse_options()`, which can lead to inconsistencies. For example, `git fast-import` scans for `--allow-unsafe-features` early, but the hand-written loop may miss options that `parse_options()` would accept (e.g., abbreviations or space-separated values), causing the two parses to disagree. This can result in either overly strict behavior (safe but incorrect) or dangerous behavior (e.g., misinterpreting an option's value as a flag).

The solution, developed in Christian Couder's `cc/early-scan-options` series (currently in `seen`), introduces `early_scan_options()`, a helper that mimics `parse_options()`'s behavior but stops early for specific options marked with `PARSE_OPT_EARLY`. The series has evolved through three versions, with the latest (v3) addressing feedback and adding features like handling `LASTARG_DEFAULT` and stopping at more edge cases. The series is under review, with Kaartic Sivaraam providing feedback on implementation details (e.g., callback safety, documentation).

Cynthia's proposal focuses on extending this work to other commands with similar hand-rolled parsing logic. She has identified several candidates:
- **`git column`**: Already uses `parse_options()` but has an early scan for `--command=`, which could be replaced with `early_scan_options()`. The current behavior enforces that `--command` must be the first argument, but this rule isn't documented or tested, raising questions about whether it should be preserved.
- **`git bisect`**: Has multiple hand-written loops for options like `--no-checkout` and `--term-*`. Cynthia plans to convert these to `parse_options()` first, then use `early_scan_options()` for early parsing.
- **`git check-ref-format`**: Uses a hand-written loop for flags like `--normalize` and `--allow-onelevel`. Tests for this command are limited, and a recent patch by Fien Dora adds coverage for `--allow-onelevel` precedence.
- **`git unpack-objects`**: Lower priority, with risks around backward compatibility since it's invoked by other Git commands.

The timeline spans 13 weeks, starting with helping the `early-scan-options` series land in `next`, then tackling the conversions in order of complexity. Cynthia emphasizes testing current behavior before making changes and plans to drop lower-priority tasks if time runs short. She also commits to weekly blog posts and coordination with mentors.

The proposal is well-researched, with clear technical rationale and a realistic plan. The main risks are user-visible behavior changes (e.g., accepting previously rejected abbreviations or `--` in `check-ref-format`) and coordination with ongoing work (e.g., Patrick Steinhardt's `rerere` conversion).
