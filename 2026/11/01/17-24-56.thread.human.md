This thread is about a bugfix for the `git apply` command, submitted by Elia Pinto. The patch fixes an integer overflow risk in `parse_binary_hunk()` where a maliciously crafted binary patch could declare a size larger than `INT_MAX`, leading to an oversized memory allocation and potential crash or memory exhaustion. The fix adds a bounds check to reject such patches early, treating them as corrupt.

The change is small and targeted: a single check in `apply.c` and a new test case in `t/t4103-apply-binary.sh` that verifies the fix by attempting to apply a patch with an oversized hunk. The test uses `GIT_ALLOC_LIMIT=1m` to ensure the allocation fails fast, confirming the patch is rejected rather than causing an out-of-memory condition. The commit message is clear and explains both the problem and the test strategy.

So far, there’s been no review or discussion on the list, so the patch remains under initial consideration. If you’re tracking security or stability fixes, this is one to watch—it’s a straightforward but important edge-case fix.
