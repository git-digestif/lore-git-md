This is the second patch in a two-patch bugfix series addressing 4 GiB file size truncation on 64-bit Windows (and other platforms where `long` is 32 bits but `size_t` is 64 bits). It targets the `diff` subsystem, making `git diff` die with a clear error when encountering files of 4 GiB or larger in the working tree, textconv, `--no-index`, or combine-diff scenarios. This matches the existing behavior for blobs and prevents the generation of misleading patches that would truncate files when applied.

The patch modifies `combine-diff.c`, `diff-no-index.c`, and `diff.c`, replacing direct assignments of `size_t` values to `diff_filespec.size` (an `unsigned long`) with calls to `cast_size_t_to_ulong()`. This helper function checks for truncation and dies if the size exceeds `ULONG_MAX`, ensuring Git fails fast rather than producing incorrect results. The changes are mechanical and confined to size assignment points, with no alterations to the on-disk format or core diff algorithms.

No test is included due to the impracticality of generating 4 GiB inputs, but the commit message confirms the fix aligns with the existing behavior for blobs and prevents silent corruption. The patch is self-contained and merges cleanly with current `master`. The author acknowledges that widening `diff_filespec.size` to `size_t` for full 4+ GiB support is a larger effort deferred to a future series.

This patch complements the first in the series, which fixed the same truncation issue in `git grep` by widening buffer sizes to `size_t`. Together, they address the immediate correctness problems while leaving the broader type-system cleanup for later. The series is under review with no prior versions or open objections.
