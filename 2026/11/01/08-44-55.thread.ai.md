Thread identity: Subject "[PATCH 0/2] Fix 4 GiB truncation in grep and diff on 64-bit Windows", series version v1 (initial), originating author Elia Pinto, thread type bugfix patch series.

Core problem or goal: Fix silent truncation of file sizes at 4 GiB on platforms where `long` is 32 bits but `size_t` is 64 bits (notably 64-bit Windows). The truncation causes `git grep` to miss matches in large files and `git diff` to generate misleading patches that would truncate files when applied. Patch 1/2 addresses `grep`; patch 2/2 addresses `diff`.

Current status: Under review; v1 posted and unchanged. Author confirms the series still applies cleanly to current `master` (e1ec09b23c) and merges cleanly with `seen`. No merge status reported; no reviewer feedback received to date.

Key technical details: Files touched are `builtin/grep.c`, `grep.h`, `combine-diff.c`, `diff-no-index.c`, `diff.c`. Patch 1/2 widens `grep_source.size` from `unsigned long` to `size_t` and updates `grep_source_load`, `grep_source_1`, `end_of_line`, `look_ahead`, `grep_source_init_buf`, and `grep_buffer` to use `size_t` for buffer sizes. Patch 2/2 leaves `diff_filespec.size` as `unsigned long` but adds `cast_size_t_to_ulong()` checks in `diff_populate_filespec` and related helpers to detect truncation when assigning `size_t` values, causing Git to die with a clear error for files >= 4 GiB in the working tree, textconv, `--no-index`, and combine-diff paths (blobs already errored). Old behavior was silent truncation; new behavior is correct grep results for files > 4 GiB and a fatal error from `git diff` for files >= 4 GiB. On-disk format unchanged. No test coverage (impractical to generate 4 GiB inputs); grep fix verified via simulated truncation at 16 bits; diff fix aligned with existing blob behavior.

Open questions and loose ends: The author explicitly asks whether the "die early" strategy in patch 2/2 (erroring on >= 4 GiB files rather than widening `diff_filespec.size` to `size_t`) is acceptable as an intermediate step, or whether reviewers would insist on the full widening across `diff.c`, `combine-diff.c`, and `diff-no-index.c` despite the larger scope. Widening `diff_filespec.size` to `size_t` for full 4+ GiB support is acknowledged as a larger effort deferred to a future series. `-Wshorten-64-to-32` warnings remain in xdiff internals (input sizes capped at 1023 MiB) and unreachable code paths.
