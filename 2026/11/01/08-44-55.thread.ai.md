Thread identity
Subject: [PATCH 0/2] Fix 4 GiB truncation in grep and diff on 64-bit Windows
Series version: v1 (initial)
Originating author: Elia Pinto
Thread type: bugfix patch series

Core problem or goal
Fix silent truncation of file sizes at 4 GiB on platforms where `long` is 32 bits but `size_t` is 64 bits (notably 64-bit Windows). The truncation causes `git grep` to miss matches in large files and `git diff` to generate misleading patches that would truncate files when applied. The series targets the `grep` and `diff` subsystems, with patch 1/2 addressing `grep` and patch 2/2 addressing `diff`.

Current status
Under review; v1 posted. No prior versions. No merge status reported.

Key technical details
- Files touched: `builtin/grep.c`, `grep.h`, `combine-diff.c`, `diff-no-index.c`, `diff.c`
- Symbols changed:
  - `grep_source.size` widened from `unsigned long` to `size_t` (patch 1/2)
  - `grep_source_load` and related helpers (`grep_source_1`, `end_of_line`, `look_ahead`, `grep_source_init_buf`, `grep_buffer`) updated to use `size_t` for buffer sizes (patch 1/2)
  - `diff_populate_filespec` and related helpers now use `cast_size_t_to_ulong()` to check for truncation when assigning `size_t` values to `diff_filespec.size` (an `unsigned long`), causing Git to die with a clear error for files ≥ 4 GiB in the working tree, textconv, `--no-index`, and combine-diff (patch 2/2; blobs already errored)
- Old behavior: silent truncation of file sizes > 4 GiB → incorrect grep results and misleading diffs
- New behavior: `git grep` correctly searches files > 4 GiB; `git diff` dies with a clear error for files ≥ 4 GiB
- On-disk format: unchanged
- Test coverage: none (impractical to generate 4 GiB inputs); verification via simulated truncation at 16 bits (patch 1/2) and alignment with existing blob behavior (patch 2/2)

Open questions and loose ends
- No open design objections or requests for changes yet.
- Acknowledged that widening `diff_filespec.size` to `size_t` for full 4+ GiB support is a larger effort deferred to a future series.
- `-Wshorten-64-to-32` warnings remain in xdiff internals (input sizes already capped at 1023 MiB) and in unreachable code paths.
