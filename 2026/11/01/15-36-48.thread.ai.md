Subject: [PATCH 0/3] Fix integer truncation in large-file handling
Series version: v1 (initial submission)
Originating author: Elia Pinto
Thread type: bugfix patch series

Core problem or goal
Fix silent integer truncation in three Git subsystems when processing files or buffers larger than 2–4 GiB. The patches change function signatures from 32-bit types (`uint32_t`, `int`, `unsigned int`) to `size_t` to prevent corruption in `hashwrite()` (packfile generation), miscounts in `count_lines()` (`git diff -B --stat`), and rename detection failures in `hash_chars()` (diffcore-delta).

Current status
Under review; no prior versions. Series is based on master at 50fe5cc63f and has no external dependencies. No merge status reported; still awaiting substantive technical review.

Key technical details
Files touched: `csum-file.c`/`csum-file.h`, `diff.c`, `diffcore-delta.c`
Symbols modified: `hashwrite()` (signature changed from `uint32_t` to `size_t` for byte count), `count_lines()` (signature changed from `int` to `size_t` for buffer size), `hash_chars()` (signature changed from `unsigned int` to `size_t` for buffer size)
Behavior change: functions now handle buffer/file sizes up to `SIZE_MAX` without truncation; no on-disk format changes. Internal loops in `hashwrite()` and `count_lines()` already handle block-based or line-by-line processing, so no additional logic required. The `hash_chars()` fix ensures rename detection works correctly for files ≥4 GiB by preventing undervalued similarity scores.
Test coverage: none (impractical to generate multi-gigabyte test inputs); failure mode confirmed via 16-bit truncation simulation, which caused `git cat-file` and `git fsck` to fail with "offset beyond end of packfile" errors after repacking, `git diff -B --stat` to report incorrect line counts, and `git diff -M` to miss renames.
