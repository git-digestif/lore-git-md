This thread is about a patch series from Farid Zakaria that fixes a race condition in Git's credential-cache daemon, where concurrent commands could cause one daemon to unlink another’s socket, leading to lost credentials and orphaned processes. The series is now at version 2, with three patches: a preparatory fix for socket directory permissions, the core `mkdir()` race fix, and the socket hijacking fix. The preparatory patch (patch 1) is uncontroversial and ready to merge, while patches 2 and 3 are technically sound but blocked by an unresolved architectural concern from Junio Hamano about mixing `unix_ss_*` and `tempfile` APIs in patch 3.

The latest email from Patrick Steinhardt adds a documentation nit to patch 2, pointing out that the commit message misleadingly implies the patch changes the `mkdir()` mode to `0700` to avoid a race, when in fact it only adds an `EEXIST` check. The message doesn’t challenge the patch’s correctness but asks for clarification on why the two-step `mkdir(..., 0777) && chmod(...)` pattern was ever considered preferable. This is a minor issue compared to the architectural concern, which remains the main blocker: Junio has rejected Farid’s claim that the socket-stealing race might only occur during Git upgrades, arguing that any serious installation would have a babysitter process to respawn daemons, making the race a persistent concern. Farid’s latest reply did not engage with this concern, leaving the series in limbo until either a v3 is posted or Junio intervenes. Jeff King and Patrick Steinhardt have both confirmed the core logic of patches 2 and 3 as correct, but the architectural issue in patch 3 is still unresolved.
