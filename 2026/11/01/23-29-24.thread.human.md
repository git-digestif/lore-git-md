This thread is a two-patch bugfix series from Farid Zakaria addressing a race condition in Git’s credential-cache daemon. The issue occurs when two `git credential-cache store` commands run simultaneously, causing the second daemon to unlink the first one’s socket and lose stored credentials. The problem is real-world: it can surface during parallel submodule fetches over HTTPS, making it a practical concern for users with large repositories.

The patches modify `builtin/credential-cache--daemon.c` and add tests in `t/t0301-credential-cache.sh`. The first patch makes the daemon resilient to concurrent socket directory creation, while the second prevents it from hijacking an existing daemon’s socket. The fix is motivated by a 2021 observation from Jeff King about racy socket setup, though this series tackles a more severe edge case where credentials are actively lost. Farid discovered the issue using Rewind, a deterministic VM for uncovering race conditions, which suggests the patches are well-tested for the specific failure mode.
