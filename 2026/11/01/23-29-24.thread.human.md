This thread is about a bugfix series from Farid Zakaria that addresses a race condition in Git’s credential-cache daemon, where concurrent `git credential-cache store` commands can cause one daemon to unlink another’s socket, leading to lost credentials and orphaned processes. The issue is particularly problematic during parallel submodule fetches over HTTPS. The series also fixes a pre-existing permission-handling issue in socket directory creation.

The series is now at v2, incorporating feedback from v1. Key changes include a preparatory commit to fix the permission issue using `safe_create_leading_directories_no_share_const()`, splitting the original patch into two, and improving documentation in the final patch. While reviewers Jeff King and Patrick Steinhardt have confirmed the core fixes (ignoring `EEXIST` from `mkdir()` and using `unix_ss_create()`) as correct, Junio C Hamano has raised an unresolved architectural concern about mixing `unix_ss_*` and `tempfile` APIs in the socket-handling logic. Junio argues this could lead to unsafe socket cleanup, citing `fsmonitor--daemon.c` as a safer precedent. Farid’s latest reply does not engage with this concern, instead framing his contribution as a best-effort fix and closing the door on further discussion. This leaves the architectural issue unresolved, making a v3 or maintainer intervention likely before the series can be merged.

The series touches `builtin/credential-cache--daemon.c` and adds tests in `t/t0301-credential-cache.sh`. The new behavior ensures daemons ignore `EEXIST` from `mkdir()`, use `unix_ss_create()` for safe socket creation, and create the socket directory with mode `0700` regardless of `core.sharedRepository` settings. If a second daemon detects an existing socket, it exits with an "ok" response, allowing its client to communicate with the running daemon. The pre-existing permission issue, where `core.sharedRepository` settings were incorrectly applied to user-specific directories, is also fixed. However, the unresolved architectural concern and Farid’s reluctance to address it may delay progress.
