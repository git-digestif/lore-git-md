This thread is about fixing a race condition in Git’s credential-cache daemon that can cause credential loss during parallel submodule fetches. Farid Zakaria posted a v2 patch series addressing two issues: the race condition itself (where concurrent daemons can unlink each other’s sockets) and a pre-existing permission-handling bug in socket directory creation. The series is under review, with the core fixes—ignoring `EEXIST` from `mkdir()` and using `unix_ss_create()` for safe socket handling—confirmed as correct by Jeff King and Patrick Steinhardt.

Junio Hamano raised an architectural concern in v1 about mixing `unix_ss_*` and `tempfile` APIs in the socket cleanup logic, arguing it could bypass safety checks. Farid acknowledged the concern in the v2 cover letter but did not address it in the code or explain his reasoning. Junio’s latest reply presses for clarity: either a justification for the current approach or a revised implementation. Until this is resolved, the series cannot move forward. The preparatory commit (fixing socket directory permissions) and documentation improvements in v2 are uncontroversial, but the unresolved API mixing question remains the blocker. No maintainer decision has been recorded, and the series is still under active discussion.
