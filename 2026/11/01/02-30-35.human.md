This is a review reply from Junio C Hamano on Nakul V S’s v2 patch that prevents `git revert`, `git cherry-pick`, and all `git rebase` backends from operating on shallow boundary commits by default. The patch itself is a well-motivated bugfix with thorough test coverage and a clean implementation, and Junio’s feedback is now limited to minor details.

Junio acknowledges that all the v2 changes—extending the safeguard to cherry-pick and all rebase backends, moving the check to the planning stage, saving the `--allow-shallow-boundary` flag across `--continue`, and omitting the option from the synopsis—are sensible improvements. His only technical question is why the patch uses `git_config_bool_or_int()` instead of the simpler `git_config_bool()` for the new `allow-shallow-boundary` config key; he expects a boolean value and sees no need for an integer interpretation. The rebase question is procedural rather than technical: Junio asks whether the rebase onto current master was truly necessary, noting that unnecessary rebases can obscure the patch’s history.

On the two open questions from v1—whether the safeguard should extend to `git commit --amend` and how to handle manually edited rebase todo lists—Junio reiterates that incremental coverage is fine but asks whether Nakul has a vision for how these cases might be addressed in the future. His tone is constructive, and the overall impression is that the patch is nearly ready for integration, pending resolution of these small points. No fundamental objections remain.
