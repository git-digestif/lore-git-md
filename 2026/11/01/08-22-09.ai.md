This is the second patch in Harald Nordgren’s four-part series introducing `--delete-integrated` for `git branch`. The patch extends `delete_branches()` to report where a deleted branch’s changes landed, preparing for the upcoming `--delete-integrated` logic that will delete branches whose commits are not reachable from their upstream but whose changes are (e.g., after squash merges).

The change is straightforward: `delete_branches()` now accepts an optional `strmap` (`landed_commits`) mapping branch names to the upstream commit where their changes landed. When a branch is in the map, the merge check is skipped, and the deletion message is updated to show both the branch’s tip and the landing commit (e.g., `Deleted branch topic (was 1a2b3c4, landed as 9f8e7d6)`). No callers pass a map yet, so the patch is purely preparatory and makes no functional changes.

The implementation is clean and uncontroversial: it adds the `landed_commits` parameter, checks for the branch in the map before the merge check, and updates the output format in both dry-run and actual deletion paths. The patch touches only `builtin/branch.c` and is explicitly marked as ready for integration in the thread context. No review feedback has been raised on this patch in any iteration, and it remains a low-risk refactoring that enables the later `--delete-integrated` functionality.
