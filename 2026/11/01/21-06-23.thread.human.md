This thread is about Cynthia Uche’s Outreachy proposal to extend Git’s `early_scan_options()` API to more commands, improving consistency in how arguments and options are parsed. The proposal targets the December 2026 Outreachy round and builds on Christian Couder’s `cc/early-scan-options` series, which is currently in `seen` but expected to move to `next` soon.

Cynthia’s plan focuses on converting commands like `git column`, `git bisect`, `git check-ref-format`, and (as a stretch goal) `git unpack-objects` to use the new API. Key technical questions remain, such as whether `git column`’s "must be first argument" rule is intentional and whether `git check-ref-format` should accept options after the refname. The proposal emphasizes backward compatibility and test coverage, with no changes to on-disk formats. So far, no substantive reviews or objections have been posted, though the proposal anticipates discussion on these open points.

The only reply so far is a procedural note from Usman Akinyemi, reminding Cynthia to submit the formal application on the Outreachy website. The thread is still in the proposal stage, with no code posted yet.
