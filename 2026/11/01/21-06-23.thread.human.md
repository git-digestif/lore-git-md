This thread is about an Outreachy proposal by Cynthia Uche (also using the name Priestess) to improve how Git commands scan and parse arguments and options. The project aims to extend Christian Couder’s `early_scan_options()` API—currently in the `seen` branch—to additional commands like `git column`, `git bisect`, `git check-ref-format`, and possibly `git unpack-objects`. The goal is to replace ad-hoc argument scanning with a standardized approach, ensuring consistency with `parse_options()` while preserving backward compatibility.

The proposal is in its second draft, with no code posted yet. Cynthia has already contributed a microproject (merged to `master`) and reviewed the dependent `cc/early-scan-options` series, demonstrating readiness. The main technical challenges include determining whether `git column`’s "must be first argument" rule is intentional, whether `git check-ref-format` should accept options after `<refname>`, and how to handle `git unpack-objects` without breaking existing callers. The project also emphasizes test coverage, with plans to update existing test suites (`t9002`, `t1402`, `t6030`, `t5300`) to reflect new behavior.

So far, the discussion has been light on technical feedback, with only a procedural reminder from Usman Akinyemi and a confirmation from Cynthia that she’ll submit the formal Outreachy application. The proposal anticipates broader discussion on the design questions above, but no substantive reviews or objections have been raised yet. The `cc/early-scan-options` series remains the key dependency, currently in `seen` but expected to move to `next` soon.
