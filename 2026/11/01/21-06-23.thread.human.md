Cynthia Uche’s Outreachy proposal to extend the `early_scan_options()` API to more Git commands is taking shape, with Christian Couder’s recent feedback providing clarity on key design questions. The project aims to eliminate inconsistencies in how commands like `git column`, `git bisect`, and `git check-ref-format` handle arguments before `parse_options()` is called, building on Christian’s `cc/early-scan-options` series (currently in `seen`).

Christian’s reply settles one of the proposal’s open questions: the "must be first" rule for `git column --command` is intentional and should be preserved. He also confirms that `git bisect`’s subcommand functions (like `bisect_terms()`) are the right targets for conversion, as the command already uses `parse_options()` for dispatch. For `git check-ref-format`, Hussain Sitamouwala’s parallel work may simplify Cynthia’s task or offer a reference implementation. The stretch goal of converting `git unpack-objects` remains unaddressed, and the project’s progress still hinges on Christian’s series graduating to `next`.

Cynthia has demonstrated readiness through her merged microproject and active review of the dependency series, but no code for the Outreachy project has been posted yet. The proposal’s emphasis on test-first development and backward compatibility—particularly for `git bisect`’s `BISECT_LOG` replay functionality—positions it well for incremental progress.
