This thread is an Outreachy proposal draft from Cynthia Uche for the December 2026 round, focusing on the project *"Improve how command arguments and options are scanned and parsed"*. The proposal aims to extend the recently introduced `early_scan_options()` API (currently in Junio’s `seen` branch as `cc/early-scan-options`) to additional Git commands that still use ad-hoc argument parsing.

Cynthia’s proposal is technically grounded and well-structured. She identifies `git column`, `git bisect`, and `git check-ref-format` as primary targets for conversion, with `unpack-objects` as a stretch goal. Each candidate is analyzed for risks (e.g., backward compatibility, test coverage) and fit (e.g., whether the command already uses `parse_options()`). The timeline is realistic, prioritizing incremental conversion and test coverage, and acknowledges potential risks transparently—for example, questioning whether `git column`’s "must be first argument" rule is intentional or whether `check-ref-format`’s rejection of abbreviations is desirable. These are flagged as discussion points for the mailing list.

The proposal reflects a strong understanding of Git’s contribution process and community norms. Cynthia has already contributed a microproject (merged to `master`) and reviewed the `early-scan-options` series, demonstrating deep engagement with the codebase. Her communication plan (weekly blog posts, list-first questions) aligns with Outreachy expectations, and her post-internship goals suggest long-term commitment. The main open question is whether the community will agree with her assumptions about the intended behavior of the commands she plans to convert, particularly around edge cases like `git column`’s argument ordering. Feedback on the proposal is likely to be positive, though the "must be first" rule for `git column` may spark discussion.
