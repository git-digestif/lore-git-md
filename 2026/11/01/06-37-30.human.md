This is a bugfix patch addressing a data corruption issue in `git pack-objects` on platforms where `size_t` can represent values larger than `unsigned long` (e.g., 32-bit systems with large file support). The patch is a minor revision to v2, responding to Junio C Hamano’s feedback on the commit message wording.

The core problem remains the same: when blobs ≥4GiB are packed, their sizes are truncated due to a cast from `size_t` to `unsigned long`, causing the pack header to record incorrect sizes while the compressed data remains intact. This leads to corrupted objects during `git repack` or `git gc` when loose large blobs are pruned. The fix itself—changing variable types in `builtin/pack-objects.c` to use `size_t` and `off_t`—is unchanged from v2, but the commit message now clarifies the platform-specific conditions more precisely to avoid confusion.

Junio’s feedback is purely editorial, focusing on making the commit message unambiguous about the target platforms (those where `long` is 32-bit but `size_t` is larger, not all 32-bit systems). The patch is otherwise uncontroversial, well-motivated, and narrowly scoped to the large-blob streaming path. No code changes were requested, and the fix aligns with existing patterns in the codebase. It should be ready for merging once the updated commit message is submitted.
