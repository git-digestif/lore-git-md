Subject: [PATCH] maintenance: add Trace2 event for --auto skip due to lock
Series version: standalone patch (no series)
Originating author: Pushkar Singh <pushkarkumarsingh1970@gmail.com>
Thread type: patch submission

Core problem or goal
Add a Trace2 data event to `git maintenance run --auto` when execution is skipped due to the presence of a `maintenance.lock` file, improving observability of silent skips that can mask stale locks or interrupted processes. The patch also surfaces a latent design question about lock-handling consistency between `--auto` and non-`--auto` modes.

Current status
Under review; no prior versions. Patch remains uncontroversial and follows established Trace2 patterns. No maintainer decisions or merge status reported yet. Patrick Steinhardt’s review raises a potential follow-up topic but does not block this patch.

Key technical details
- File modified: `builtin/gc.c` (adds Trace2 event in the lock-checking conditional).
- New Trace2 event: `"lock/skip": "exists"` under the `"maintenance"` category.
- Test added: `t/t7900-maintenance.sh` (creates lock, runs `--auto`, verifies event emission and lock persistence).
- No functional behavior change; only adds diagnostic logging.
- Latent issue noted: lock-acquisition errors (other than `EEXIST` in `--auto` mode) are currently swallowed, creating inconsistency with `git gc`’s fail-fast behavior.

Open questions and loose ends
- Whether the lock-handling logic should distinguish between `--auto` (warn and succeed) and non-`--auto` (error out) when the lock cannot be acquired. Patrick Steinhardt suggests this as a follow-up, but no action is requested on the current patch.
