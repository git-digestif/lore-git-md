Core problem or goal
Improve observability and consistency of `git maintenance run` lock handling. The series adds a Trace2 data event for `--auto` skips due to lock existence and aligns manual invocations (`git maintenance run` without `--auto`) with `git gc`’s fail-fast behavior when the lock cannot be acquired. The latent design question about lock-handling consistency between `--auto` and non-`--auto` modes is explicitly addressed and resolved.

Current status
Under review; v2 posted in response to Patrick Steinhardt’s review of the initial standalone patch. No maintainer decisions or merge status reported. The series remains uncontroversial; Patrick Steinhardt’s latest review requests mechanical refinements (patch splitting, code deduplication, and Trace2 event format simplification) but does not challenge the core functionality or design.

Key technical details
- Files modified: `builtin/gc.c` (Trace2 event and lock-acquisition logic), `t/t7900-maintenance.sh` (updated test).
- New Trace2 event: `"lock/skip": {"reason": "exists", "errno": <code>}` under the `"maintenance"` category, now including the actual error code (e.g., `EEXIST`, `EPERM`, `EACCES`). Patrick Steinhardt suggests simplifying the `reason` field to use `strerror(err)` unconditionally, eliminating the ternary operator.
- Behavioral change: manual `git maintenance run` now fails with exit code 128 and an error message when the lock cannot be acquired, matching `git gc`’s behavior. `--auto` mode continues to skip silently but logs the Trace2 event. The `--quiet` flag is respected in both cases.
- Code organization: Patrick Steinhardt recommends splitting the patch into two—one for the behavioral change and one for the Trace2 event—to improve reviewability and bisectability. He also identifies duplicated error-message formatting that could be refactored into a shared helper.
- Test updates: verifies both the Trace2 event emission (including error code) and the new exit-code behavior for manual invocations. The lock file is preserved on failure, maintaining the existing design that stale locks require manual inspection.
- No on-disk format changes; purely behavioral and diagnostic.

Open questions and loose ends

- Whether to deduplicate error-message formatting between `--auto` and manual cases.
- Whether to simplify the Trace2 event’s `reason` field to use `strerror(err)` unconditionally.
