Core problem or goal
Improve observability and consistency of `git maintenance run` lock handling. The series adds a Trace2 data event for `--auto` skips due to lock existence and aligns manual invocations (`git maintenance run` without `--auto`) with `git gc`’s fail-fast behavior when the lock cannot be acquired. The latent design question about lock-handling consistency between `--auto` and non-`--auto` modes is explicitly addressed and resolved.

Current status
Under review; v2 posted, v3 anticipated after mechanical refinements. No maintainer decisions or merge status reported. The series remains uncontroversial; Patrick Steinhardt’s review requests (patch splitting, code deduplication, Trace2 event format simplification) are now explicitly accepted by the author.

Key technical details
- Files modified: `builtin/gc.c` (Trace2 event and lock-acquisition logic), `t/t7900-maintenance.sh` (updated test).
- New Trace2 event: `"lock/skip": {"reason": <strerror(err)>, "errno": <code>}` under the `"maintenance"` category, using `strerror(err)` unconditionally for the `reason` field.
- Behavioral change: manual `git maintenance run` now fails with exit code 128 and an error message when the lock cannot be acquired, matching `git gc`’s behavior. `--auto` mode continues to skip silently but logs the Trace2 event. The `--quiet` flag is respected in both cases.
- Code organization: the patch will be split into two—one for the behavioral change and one for the Trace2 event—to improve reviewability and bisectability. Duplicated error-message formatting will be refactored into a shared helper.
- Test updates: verifies both the Trace2 event emission (including error code and `strerror`-based `reason`) and the new exit-code behavior for manual invocations. The lock file is preserved on failure, maintaining the existing design that stale locks require manual inspection.
- No on-disk format changes; purely behavioral and diagnostic.
