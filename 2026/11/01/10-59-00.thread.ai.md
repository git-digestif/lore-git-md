Core problem or goal: Improve observability and consistency of `git maintenance run` lock handling. The series adds a Trace2 data event for lock-skips and aligns manual invocations with `git gc`'s fail-fast behavior, while explicitly resolving the three-way distinction between manual, `--auto`, and `--schedule` invocation modes so that background-scheduled maintenance does not regress.

Current status: Under review; v4 posted as a direct response to the v3 regression reported by Aniket Gupta. Patch 1/2 (this email) introduces an `opts->schedule` branch in `maintenance_run_tasks()` that returns 0 (silent skip) for scheduled runs instead of failing, and passes `--no-auto-maintenance` to child `git fetch` processes in `fetch_remote()` so the prefetch task neither triggers nested automatic maintenance nor emits spurious lock warnings. Whether this fully resolves the background-run regression and whether the extended Trace2 coverage for scheduled runs (patch 2/2) matches maintainer expectations remains to be confirmed by reviewers.

Key technical details:
- Files modified: `builtin/gc.c`, `t/t7900-maintenance.sh`.
- Three-mode lock behavior when the maintenance lock cannot be acquired: manual `git maintenance run` fails with exit code 128 and an error message via the shared `unable_to_lock_message()` helper (matching `git gc`), unless `--quiet` suppresses the diagnostic while still failing; `--auto` warns and exits 0; `--schedule` (background runs started via `git maintenance start`) stays silent and exits 0 via the new `opts->schedule` check in `maintenance_run_tasks()`.
- Prefetch fix: `--no-auto-maintenance` appended to the internal `git fetch` command line in `fetch_remote()` so child fetches neither trigger nested automatic maintenance nor emit spurious lock warnings while the parent holds the lock.
- Trace2 event `"lock/skip": {"reason": strerror(err), "errno": <code>}` under the `"maintenance"` category is introduced in patch 2/2 (not yet received), to be emitted for both `--auto` and `--schedule` modes; manual invocations suppress the event. Emitted even under `--quiet`.
- Lock file `objects/maintenance.lock` preserved on failure. Tests in `t/t7900-maintenance.sh` cover all four lock-failure scenarios (auto warning, manual failure, manual quiet suppression, scheduled silent skip with preserved lock), verification that child fetches receive the new flag, and that prefetch with `--no-quiet` produces no stderr output. No on-disk format changes.
