Core problem or goal: Improve observability and consistency of `git maintenance run` lock handling. The series aligns manual invocations with `git gc`'s fail-fast behavior, resolves the three-way distinction between manual, `--auto`, and `--schedule` invocation modes so background-scheduled maintenance does not regress, and adds a machine-readable Trace2 record for lock-skips.

Current status: Under review; v4 posted as a direct response to the v3 regression reported by Aniket Gupta. Patch 1/2 introduces an `opts->schedule` branch in `maintenance_run_tasks()` that returns 0 (silent skip) for scheduled runs instead of failing, and passes `--no-auto-maintenance` to child `git fetch` processes in `fetch_remote()`. Patch 2/2 (this email) adds a Trace2 data event emitted when the maintenance lock cannot be acquired under `--auto` or `--schedule`. Whether this fully resolves the background-run regression and whether the Trace2 coverage matches maintainer expectations remains to be confirmed by reviewers.

Key technical details:
- Files modified across the series: `builtin/gc.c`, `t/t7900-maintenance.sh`.
- Three-mode lock behavior when the maintenance lock cannot be acquired: manual `git maintenance run` fails with exit code 128 and an error message via the shared `unable_to_lock_message()` helper (matching `git gc`), unless `--quiet` suppresses the diagnostic while still failing; `--auto` warns and exits 0; `--schedule` (background runs started via `git maintenance start`) stays silent and exits 0 via the `opts->schedule` check in `maintenance_run_tasks()`.
- Prefetch fix: `--no-auto-maintenance` appended to the internal `git fetch` command line in `fetch_remote()` so child fetches neither trigger nested automatic maintenance nor emit spurious lock warnings while the parent holds the lock.
- Trace2 event (patch 2/2, now received): `trace2_data_string("maintenance", r, "lock/skip", strerror(err))` emitted in `maintenance_run_tasks()` under `if (opts->auto_flag || opts->schedule)`, i.e. category `"maintenance"`, key `"lock/skip"`, value the OS error string (e.g. "File exists"). Manual invocations suppress the event; it is emitted regardless of `--quiet`; requires `GIT_TRACE2_EVENT` to be active. The hook is a four-line addition placed immediately before the existing warning/error logic.
- Lock file `objects/maintenance.lock` preserved on failure. Tests in `t/t7900-maintenance.sh` cover all four lock-failure scenarios (auto warning, manual failure, manual quiet suppression, scheduled silent skip with preserved lock), verification that child fetches receive `--no-auto-maintenance`, that prefetch with `--no-quiet` produces no stderr output, and the three-way Trace2 distinction: `--auto` with existing lock emits the event, `--schedule=hourly` emits it silently (empty stderr), manual `--quiet` fails without the `"lock/skip"` event in the trace file. No on-disk format changes.
