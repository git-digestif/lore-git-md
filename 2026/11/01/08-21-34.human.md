This is the first patch in the **v5 bugfix series for `git imap-send`**, addressing a long-standing tunnel-command lifecycle issue. The patch ensures that when `imap.tunnel` is configured, the tunnel process is properly waited for and its resources are freed, plugging a memory leak that has existed since the feature was introduced in 2009.

The fix is straightforward: the `imap` struct now stores the tunnel as an allocated `child_process` pointer (rather than a stack variable), and `imap_close_server()` calls `finish_command()` and `free()` to reap the process. This aligns with Git’s run-command API best practices and resolves defensive coding feedback from Patrick Steinhardt in earlier iterations. The change touches only `imap-send.c` and is uncontroversial, with no test coverage gaps (though no existing tests exercise the tunnel feature).

This patch was previously merged to `next` in v4 and remains unchanged in v5. The rest of the series focuses on header-parsing fixes, but this patch stands alone as a clean, well-motivated improvement to process management. If you care about `imap-send` or tunnel-based workflows, this is a small but meaningful robustness fix.
