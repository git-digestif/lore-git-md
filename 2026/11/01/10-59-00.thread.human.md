This thread is about a small but practical improvement to Git’s maintenance subsystem. Pushkar Singh, a first-time contributor, has submitted a patch that adds a Trace2 data event when `git maintenance run --auto` skips execution due to an existing `maintenance.lock` file. The change is minimal—just two lines in `builtin/gc.c` to emit the trace event—and includes a new test in `t/t7900-maintenance.sh` to verify the event is logged correctly.

The motivation is straightforward: silent skips make it difficult to diagnose why automatic maintenance isn’t running, especially if a stale lock is left behind. The patch addresses this by making the skip visible in Trace2 logs, which are commonly enabled in production for observability. The implementation follows established patterns for Trace2 events in Git, and the test coverage is adequate, confirming both the event emission and the preservation of the skip behavior.

So far, there’s been no discussion or review on the list, but the patch is narrowly scoped and uncontroversial. It doesn’t touch any contentious areas and should integrate smoothly. The next step is likely review from maintainers or contributors familiar with the maintenance subsystem or Trace2 infrastructure. If you’ve been away from the list, this is a low-risk, high-utility change that won’t require much catching up.
