This thread is about a small but useful improvement to `git maintenance run`: making its lock-handling behavior more observable and consistent. Pushkar Singh’s two-patch series (now at v3) adds a Trace2 event when `--auto` mode skips maintenance due to an existing lock, and aligns manual invocations with `git gc`’s fail-fast behavior when the lock can’t be acquired.

The series is uncontroversial and mechanically complete. Patrick Steinhardt reviewed earlier versions, requesting patch splitting, code deduplication, and a simpler Trace2 event format—all of which have been addressed in v3. The implementation is narrow: it emits a Trace2 event with the error string and `errno` value, respects the `--quiet` flag for terminal output, and preserves the existing design that stale locks require manual inspection. Tests verify both the event emission and the new exit-code behavior.

No open questions remain, and the series is ready for final review. Pushkar has allowed time for additional feedback, but none has emerged. The patches touch only `builtin/gc.c` and the test suite, with no on-disk format changes or cross-subsystem interactions. If no further objections arise, this should be a straightforward merge.
