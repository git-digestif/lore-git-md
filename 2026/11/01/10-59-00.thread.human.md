This thread is about a two-patch series from Pushkar Singh that improves how `git maintenance` handles lock acquisition failures. The series adds Trace2 logging for `--auto` mode skips and aligns manual invocations with `git gc`'s behavior when the lock is held.

The v2 series, posted in response to Patrick Steinhardt’s review of the initial patch, now fully addresses the inconsistency between `--auto` and manual modes. When `git maintenance run --auto` can’t acquire the lock, it logs a structured Trace2 event (`"lock/skip"`) with the specific error code (e.g., `EEXIST`). Manual invocations (`git maintenance run` without `--auto`) now fail with exit code 128 and an error message, matching `git gc`. The lock file is preserved on failure, requiring manual inspection for stale locks. Tests verify both the Trace2 event and the new exit-code behavior.

Patrick Steinhardt’s feedback on the v1 patch flagged the lock-handling inconsistency, and his concerns are fully resolved in v2. No objections or alternative proposals have surfaced, and the series remains uncontroversial. The changes are narrowly scoped to `builtin/gc.c` and the test suite, with no on-disk format or subsystem impacts.
