This is a refactoring patch converting `git diff-files` to use Git’s `parse-options` API. It is the sixth iteration (`v6`) of a standalone patch, addressing the broken threading issues noted in prior versions (`v3` and `v4`). The patch remains purely mechanical, replacing ad-hoc option parsing in `cmd_diff_files()` with structured `OPT_*` macros while preserving existing behavior for `--base`, `--ours`, `--theirs`, and `-q`.

The change touches only `builtin/diff-files.c`, removing 19 lines of manual `strcmp()`-based parsing and adding 20 lines of `parse-options` boilerplate. The new implementation uses `OPT_SET_INT_F` for stage-selection options (`--base`, `--ours`, `--theirs`), marking them `PARSE_OPT_NONEG` to prevent negated forms (e.g., `--no-base`), consistent with similar options in `builtin/checkout.c`. The `-q` flag is handled via `OPT_BIT`, setting `DIFF_SILENT_ON_REMOVED` as before. The patch also updates the usage message to use `usage_with_options()`, enabling auto-generated help text and shell completion support.

No new symbols or on-disk format changes are introduced. The patch does not add test coverage, relying on existing `git diff-files` tests to verify behavior. The threading issue (missing `In-Reply-To`/`References` headers) has been resolved in this iteration, making it eligible for technical review.
