This thread is a three-patch series from Elia Pinto fixing silent integer truncation in Git when handling files larger than 2–4 GiB. The issue affects packfile generation, diffstat line counts, and rename detection, potentially causing corruption or misleading output in commands like `git cat-file`, `git diff -B --stat`, and `git diff -M`. The fixes are straightforward: changing function signatures from 32-bit types (`uint32_t`, `int`, `unsigned int`) to `size_t` to handle sizes up to `SIZE_MAX`.

The series is under review with no prior versions, and while the patches are technically sound—confirmed via truncation simulations—they haven’t yet received substantive technical feedback. The changes are minimal and self-contained, touching `csum-file.c`, `diff.c`, and `diffcore-delta.c`, with no on-disk format changes or test coverage (due to the impracticality of generating multi-gigabyte test files). The third patch, just summarized, addresses rename detection failures in `diffcore-delta.c`, where truncation caused similarity scores to be miscalculated, leading to missed renames in `git diff -M` and merges.

No maintainer decisions or merge status have been reported yet, and the series remains open for review. The main open question is whether the low-level I/O and diff logic might have edge cases not addressed by the type changes alone. If you work with large repositories or care about rename detection, this is worth watching—though the fixes are niche, they prevent subtle corruption in edge cases.
