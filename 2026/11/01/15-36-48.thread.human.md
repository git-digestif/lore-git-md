This thread is a bugfix series from Elia Pinto that fixes silent integer truncation in three Git subsystems when handling files larger than 2–4 GiB. The patches change function signatures from 32-bit types to `size_t` to prevent corruption in packfile generation, incorrect line counts in `git diff -B --stat`, and rename detection failures in `git diff -M`.

The series is still under review, with no prior versions or merge status reported. Phillip Wood has just submitted a substantive review of the second patch, identifying a critical flaw: while the `size` parameter was widened to `size_t`, the function’s return type and line counter remain `int`, creating a new overflow risk if a file contains more than `INT_MAX` lines. This feedback suggests the series may need rework to address edge cases more thoroughly, particularly the mismatch between widened input sizes and narrower return types. No other reviews have been posted yet, and the series remains self-contained with no external dependencies. The patches touch `csum-file.c`, `diff.c`, and `diffcore-delta.c`, with no on-disk format changes, but the lack of test coverage for multi-gigabyte inputs remains a loose end.
