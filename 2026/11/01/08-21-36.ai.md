This is the third patch in the v5 series fixing `git imap-send` to handle non-canonical email header order and case insensitivity. The patch removes a special-case exemption for `git send-email` copies that was introduced in commit `04133f5bc4` (2025-08-12). That exemption allowed messages starting with "From git-send-email" to be counted if they had only `From:` and `To:` headers, ignoring `Date:` and `Subject:`. Now that the header-parsing logic (introduced in Patch 2/4) accepts headers in any order, this exemption is redundant and can be removed.

The change simplifies the `count_messages()` function in `imap-send.c` by treating all messages uniformly: any message starting with "From " is counted if it has the required headers (`From:`, `Date:`, and `Subject:`), regardless of their order or case. The commit message explains that this makes the check stricter for non-`git-send-email` scripts that might write mboxes with a "From git-send-email" line, but notes that such scripts would already have been rejected if they lacked a `Subject:` header (as `imap-send` has always required one). The patch adds a test in `t/t9001-send-email.sh` to verify that the `--imap-sent-folder` workflow continues to work as expected, ensuring backward compatibility.

This is a **clean, well-justified refactoring** that aligns with the series' goal of RFC 5322 compliance and interoperability. The removal of the special case is uncontroversial, as the new header-parsing logic (Patch 2/4) already handles the edge case that the exemption was designed to address. The test coverage is thorough, and the commit message clearly documents the backward-compatibility implications. No new issues are introduced, and the patch is ready for integration.
