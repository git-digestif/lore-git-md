This is the fourth patch in a five-part documentation and terminology cleanup series. It updates in-code comments and help text to stop calling "root refs" (like HEAD and ORIG_HEAD) "pseudorefs," aligning the codebase with the glossary definitions introduced earlier in the series. The changes are mechanical and uncontroversial, touching four files: `builtin/for-each-ref.c`, `contrib/completion/git-completion.bash`, `refs.h`, and `revision.c`.

The patch addresses feedback from Patrick Steinhardt on the v1 commit message, tightening it to focus on the core terminology change. The only behavioral change is in `revision.c`, where the error message for `--merge` no longer labels MERGE_HEAD and friends as "pseudorefs," though the list of valid refs remains the same. The bash completion helper `__git_pseudoref_exists()` is left unchanged (except for its comment) because there’s no clear term that covers both root refs and pseudorefs, and third-party scripts might depend on the name.

The changes in `refs.h` are the most substantive: the comment for `REFS_FOR_EACH_INCLUDE_ROOT_REFS` now explicitly lists root refs (HEAD, ORIG_HEAD), and the pseudoref definition is updated to clarify that these names can be used like refs but have different semantics and cannot be stored in the ref backend. The help text for `git for-each-ref --include-root-refs` is also updated to say "root refs" instead of "HEAD ref and pseudorefs."

This patch looks ready for merging. It’s a straightforward cleanup with no functional impact, and the author has addressed all review feedback from v1. The only deliberate omission—the completion helper’s name—is well-justified. If the rest of the series is approved, this patch should go in as-is.
