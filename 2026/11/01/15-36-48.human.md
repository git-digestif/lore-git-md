This is a bugfix series from Elia Pinto addressing three distinct integer-truncation issues that can corrupt data or produce wrong results when Git processes files or buffers larger than 2 GiB or 4 GiB. The patches change function parameters from 32-bit types (`uint32_t`, `int`, `unsigned int`) to `size_t` to match the actual size of the data being handled.

The problems were discovered by scanning a 64-bit Linux build with `-Wshorten-64-to-32`, which catches implicit truncation of 64-bit values to 32 bits. Each patch fixes one specific overflow: `hashwrite()` in `csum-file.c` can corrupt a pack when `pack-objects` writes a compressed buffer of 4 GiB or more in a single call; `count_lines()` in `diff.c` gives wrong `--stat` output for files of 2 GiB or more under `git diff -B`; and `hash_chars()` in `diffcore-delta.c` fails to recognize renames of files 4 GiB or larger.

The commit message is clear and factual, naming the exact functions, files, and scenarios affected. No tests are included because reproducing the bugs requires multi-gigabyte inputs, but the author verified each fix by simulating the truncation at 16 bits. The series is self-contained, based on current `master`, and merges cleanly with other in-flight topics. It looks like a well-scoped, uncontroversial set of fixes that should be easy to review.
