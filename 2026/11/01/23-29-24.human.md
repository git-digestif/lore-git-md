This is a bugfix series targeting the credential-cache daemon. Farid Zakaria identifies two race conditions that occur when multiple Git commands attempt to start the credential-cache daemon simultaneously. The races can cause credential loss, daemon leaks, and socket corruption—particularly problematic in parallel operations like submodule fetches over HTTPS.

The series consists of two patches. The first allows the daemon to tolerate a concurrently created socket directory, while the second prevents a new daemon from hijacking an existing daemon’s socket. The changes are confined to `builtin/credential-cache--daemon.c` and add new tests in `t/t0301-credential-cache.sh`.

The commit message is unusually clear for a race-condition fix: it describes the symptoms (lost credentials, lingering daemons, socket removal), the trigger (parallel credential stores), and the tool used to find the bug (Rewind, a deterministic VM that replays thread schedules). The author also cites a 2021 discussion where Jeff King noted the socket setup was racy, though the worst-case scenario at the time was underestimated.

The patches look well-motivated and narrowly scoped. The added test coverage is a strong positive signal—race-condition fixes are notoriously hard to verify, and the new tests directly exercise the problematic scenarios. No controversy is evident in the cover letter, and the changes appear to be a straightforward hardening of the daemon startup logic.
