This is the third patch in Harald Nordgren’s four-patch **bugfix series for `git imap-send`**, now in its fifth iteration (`v5`). The series as a whole makes the header-parsing logic order-agnostic and case-insensitive, ensuring RFC 5322 compliance and interoperability with tools like `b4`. This specific patch removes a special-case exemption for messages starting with `From git-send-email`, treating them like any other message in the mbox.

The change is straightforward: the `count_messages()` function in `imap-send.c` previously had a dedicated branch for `From git-send-email` lines that only checked for `From:` and `To:` headers, ignoring `Date:` and `Subject:`. With the new order-agnostic logic (introduced in Patch 2/4), this exemption is redundant, as `git send-email`’s IMAP copies already include all required headers. The patch simplifies the code by consolidating the logic into a single check using `has_required_headers()`, which now handles any header order and case.

The commit message explains the backward-compatibility implications clearly: while the change could theoretically reject valid messages from other scripts that mimic `git send-email`’s `From` line but omit `Subject:`, such messages were already rejected in all other contexts, and the IMAP workflow would only fail if *no* messages in the mbox were counted. The risk is minimal, and the patch includes a new test in `t/t9001-send-email.sh` to verify that `--imap-sent-folder` continues to work as expected.

This patch was explicitly endorsed by Patrick Steinhardt in earlier reviews, and the `v5` iteration does not modify it—it remains identical to the version merged to `next` in `v4`. The only change in `v5` is the CRLF fix in Patch 2/4, which is unrelated to this one. The series is now ready for re-integration into `next`, and this patch is uncontroversial. It’s a clean refactoring that aligns the code with the series’ broader goal of treating all messages uniformly.
