This is the third patch in Harald Nordgren’s v6 series introducing `git branch --delete-integrated`. It implements the core flag that detects branches whose changes (but not their tips) have been integrated into an upstream branch via rebase or squash merges, even when the upstream later modified the same files. The patch adds the `DELETE_BRANCH_INTEGRATED` flag, the rebase-detection logic (tree-based diffing), and the squash-detection logic (three-way merge approximation via `ll_merge`). The CLI design is finalized: `--delete-integrated` is opt-in and handles both rebase and squash merges by default, while `--delete-merged` retains its strict tip-reachability behavior.

Key technical details: the patch touches `builtin/branch.c`, updates `Documentation/git-branch.adoc` and `Documentation/config/branch.adoc`, and adds comprehensive tests in `t/t3200-branch.sh`. The new output format (`Deleted branch topic (was 1a2b3c4, landed as 9f8e7d6)`) clearly shows where each branch’s changes landed. The rebase-detection logic is tree-based (no blob fetches), while squash-detection uses `ll_merge()` to handle upstream modifications. The patch introduces several new symbols: the `DELETE_BRANCH_INTEGRATED` flag, the `landing_search` struct (tracking branch name, rev, upstream, and changes), the `changed_paths` commit slab (caching diff results), and helper functions like `find_landed_commit()` and `find_landed_commits()`.

The patch is uncontroversial in its current form. Junio’s only feedback on the v5 iteration was a surface-level variable rename (`opt` → `diffopt` in `find_landed_commits()`), which Harald addressed in v6. The first two patches in the series (preparatory refactoring and landing-message helper) are also uncontroversial and ready for integration. The fourth patch (squash-detection with upstream modifications) fixed a latent correctness issue in v6 by ensuring `.gitattributes`-driven merge behavior is respected. The only remaining technical gap for the series is the author-check mitigation (Jasper’s proposal), which is not implemented in this patch.
