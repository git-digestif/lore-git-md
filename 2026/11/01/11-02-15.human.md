This is a CI/build system patch, the second in a three-patch series restoring Ubuntu 26.04 compatibility in GitHub Actions. It addresses a permission error when creating a symlink during dependency installation by running `ln` with `sudo`. The issue affects the `documentation`, `fuzz-smoke`, and `static-analysis` CI jobs.

The fix is minimal: a single-line change in `ci/install-dependencies.sh` that prepends `sudo` to the `ln` command. The error occurs because the symlink target (`/usr/bin/dirname`) already exists, and the CI environment lacks the necessary permissions to overwrite it without elevation. The patch is based on prior work by Johannes Schindelin in Git for Windows, suggesting it has been tested in a similar context.

This is a pragmatic workaround rather than a structural fix. It restores CI functionality without redesigning the dependency installation process, but the use of `sudo` might draw scrutiny from reviewers who prefer adjusting file permissions or avoiding symlinks altogether. The patch is unlikely to be controversial on technical grounds, but the approach may prompt discussion about long-term robustness.

The change is self-contained and does not affect core Git functionality. It is part of a broader effort to address CI breakage after GitHub Actions updated its `ubuntu-latest` runner image to Ubuntu 26.04. The series as a whole is under review, with no prior versions submitted.
