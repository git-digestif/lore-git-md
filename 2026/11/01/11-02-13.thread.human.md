This thread is about fixing four CI jobs that broke after GitHub Actions updated its `ubuntu-latest` runner to Ubuntu 26.04. Harald Nordgren sent a three-patch series to restore functionality with minimal changes. The issues are: (1) CLI warnings from `apt` vs `apt-get`, (2) a permission error when replacing `/usr/bin/dirname` with a GNU-compatible version, and (3) a temporary Docker networking issue in the `linux32` job.

The series is under review, with no prior versions. The fixes touch only `.github/workflows/main.yml` and `ci/install-dependencies.sh`. The third patch, just summarized, pins the `linux32` job to Ubuntu 24.04 to bypass a Docker networking regression (DNS resolution for `deb.debian.org`) caused by Docker 29.4.2's seccomp profile blocking `socketcall` for 32-bit glibc containers. This is a temporary workaround, expected to be resolved in future runner updates, and is based on prior work by Johannes Schindelin in Git for Windows.

So far, only the author has weighed in, presenting pragmatic fixes to unblock CI. The `sudo` workaround in the second patch might draw scrutiny, but the third patch is unlikely to be controversial. No substantive reviews have been posted yet. The series is focused on restoring CI functionality without redesigning the infrastructure.
