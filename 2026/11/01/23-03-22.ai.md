This is the fourth patch in a five-patch documentation and terminology cleanup series. It updates in-code comments and help text to replace outdated uses of "pseudoref" with "root ref," aligning with the 2024 terminology change that restricted "pseudoref" to mean only FETCH_HEAD and MERGE_HEAD.

The patch touches four files: `builtin/for-each-ref.c`, `contrib/completion/git-completion.bash`, `refs.h`, and `revision.c`. The changes are mechanical and clarify existing behavior rather than introducing new functionality. The help text for `git for-each-ref --include-root-refs` now says "root refs" instead of "HEAD ref and pseudorefs," and the bash-completion script’s comments clarify that `__git_pseudoref_exists()` covers both root refs and pseudorefs (though the function name itself is left unchanged for compatibility). In `refs.h`, the description of `REFS_FOR_EACH_INCLUDE_ROOT_REFS` now lists root refs explicitly, and the pseudoref definition is updated to match the glossary’s narrower scope. The only behavioral change is in `revision.c`, where the error message for `--merge` no longer calls MERGE_HEAD et al. "pseudorefs," though the list of valid refs remains the same.

The commit message is concise and focuses on the terminology change, noting the deliberate omission of renaming `__git_pseudoref_exists()` due to ambiguity about what term would cover both root refs and pseudorefs.
