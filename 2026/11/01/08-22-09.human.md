This is the second patch in Harald Nordgren’s four-part series extending `git branch --delete-merged` with a new `--delete-integrated` flag. The patch prepares the output machinery for the upcoming feature by letting `delete_branches()` report where a branch’s changes landed, even when the branch tip itself is not reachable from the upstream.

The change is straightforward: `delete_branches()` now accepts an optional `strmap` that maps branch names to the upstream commit where their changes were integrated. When a branch is found in the map, the merge check is skipped and the deletion message is extended to show both the branch tip and the landing commit (e.g., `Deleted branch topic (was 1a2b3c4, landed as 9f8e7d6)`). No callers pass a map yet, so the patch is purely preparatory and has no user-visible effect.

The patch is uncontroversial and ready for integration. Junio has not raised any concerns about it in any of the six iterations, and the thread summary confirms it is explicitly marked as uncontroversial. The implementation is clean, the commit message is clear, and the test coverage in the series already exercises the new output format. This is a safe, incremental step toward the larger goal of detecting squash-merged and rebase-merged branches.
