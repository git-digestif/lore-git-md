This thread covers Elia Pinto's two-patch series fixing silent truncation of files 4GiB or larger on platforms where `long` is 32-bit but `size_t` is 64-bit, notably 64-bit Windows. The first patch corrects `git archive` for tar and zip formats by switching file-size variables from `unsigned long` to `size_t` in `archive-tar.c`, `archive-zip.c`, and `archive.h`; the second applies the same fix to `git apply` in `apply.c`. Both target `master` and currently sit at v1 with no technical review feedback yet.

Patrick Steinhardt has now weighed in on the one structural question in the series: patch 2 leaves a gap because `add_index_file()` passes the file size to `odb_write_object()`, whose length parameter is still `unsigned long` until a separate size_t series lands, meaning `git apply --index` and `git am` would still truncate the indexed blob on affected platforms. Rather than casting the size through `cast_size_t_to_ulong()` to make those commands fail loudly, Patrick prefers holding back patch 2/2 entirely until the dependent series merges, and has asked Elia to rebase and resend once that happens.

Patch 1/2 stands alone and remains under review with no objections raised. The series is still at v1; no new version has been posted, and no integration status has changed. The existing `t5004` zip test remains disabled on 32-bit `long` platforms, with the author suggesting it could be relaxed to `SIZE_T_IS_64BIT` once the fixes land, though this has not been tested on 64-bit Windows.
