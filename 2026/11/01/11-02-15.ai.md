This is the second patch in a three-patch CI/build system series restoring Ubuntu 26.04 compatibility after GitHub Actions updated its `ubuntu-latest` runner. The patch works around a permission issue when creating a symlink during dependency installation by running `ln` with `sudo`.

The problem occurs in `ci/install-dependencies.sh` when the script attempts to replace the system `dirname` binary with a GNU-compatible version (`gnudirname`). On Ubuntu 26.04, the `/usr/bin/dirname` path is already occupied by a non-GNU binary, and the `ln` command fails with a "Permission denied" error unless run with elevated privileges. The fix is minimal: prepend `sudo` to the `ln` command, matching a solution previously implemented by Johannes Schindelin in Git for Windows.

This patch affects the `documentation`, `fuzz-smoke`, and `static-analysis` CI jobs, all of which rely on the dependency installation script. The change is pragmatic and restores functionality without redesigning the underlying mechanism, though it may draw scrutiny from reviewers who prefer avoiding `sudo` in CI scripts or addressing the root cause (e.g., adjusting file permissions or avoiding symlink replacement altogether). The commit message clearly explains the motivation and cites a specific GitHub Actions run where the failure was observed, providing concrete context for the fix.

No new symbols or on-disk formats are introduced, and the patch is self-contained to a single line in `ci/install-dependencies.sh`. The series as a whole is under review, and this patch is unlikely to be controversial on its own, though the `sudo` workaround might prompt discussion about long-term robustness. The fix is based on tested precedent (Git for Windows) and aligns with the series' goal of minimal, targeted changes to restore CI functionality.
