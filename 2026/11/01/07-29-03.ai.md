This is a bugfix patch targeting the `pack-objects` subsystem, addressing a data corruption issue when handling large blobs (≥4GiB) on platforms where `long` is 32 bits but `size_t` is 64 bits (e.g., 64-bit Windows). This is the third iteration of a standalone patch, incorporating feedback from Junio C Hamano to clarify the platform condition in the commit message.

The patch modifies `builtin/pack-objects.c` to prevent truncation of large blob sizes during pack creation. The fix changes the types of `size` (to `size_t`) and `datalen`/`olen` (to `off_t`) in the streaming path for large blobs, ensuring accurate size tracking for both the object and its compressed data. The return type of `write_no_reuse_object` and `write_large_blob_data` is also updated to `off_t` to match existing patterns in the codebase. These changes prevent the pack header from recording incorrect sizes while preserving full-length compressed data, which previously led to corrupted objects during `git repack` or `git gc` when loose large blobs were pruned.

The commit message now explicitly states the platform condition (32-bit `long` with 64-bit `size_t`), addressing Junio's feedback from v2. The patch remains narrowly scoped to the large-blob streaming path, with no impact on the on-disk format or other `pack-objects` functionality. The rationale for using `off_t` (alignment with `write_reuse_object()` and suitability for file offsets) is well-documented, and the commit message clarifies why other truncations in the codebase are unreachable (due to `core.bigFileThreshold` being `unsigned long`).

No test is included, as reproducing the bug requires ≥4GiB objects on affected platforms, but the edge cases and consequences are thoroughly explained. The patch is minimal (7 lines changed) and uncontroversial, focusing on a clear correctness issue with no behavioral side effects. All prior feedback has been addressed, and the patch appears ready for merging.

Key technical details for follow-up discussion:
- Files touched: `builtin/pack-objects.c`
- Symbols changed: `size` (to `size_t`), `datalen`/`olen` (to `off_t`), return types of `write_no_reuse_object` and `write_large_blob_data` (to `off_t`)
- Subsystem: `pack-objects` streaming path for large blobs
- Platform scope: affects only platforms where `sizeof(long) == 4` and `sizeof(size_t) > 4`
- Related prior work: none; this is a standalone fix for a specific edge case.
