This is the first patch in Harald Nordgren’s four-part series introducing `git branch --delete-integrated`. It is a **refactoring patch** that extracts the existing `branch.<name>.deleteMerged` opt-out check from `delete_merged_branches()` into a new helper function, `branch_opted_out()`. The helper is designed for reuse in the upcoming `--delete-integrated` logic, which will also respect the same configuration knob.

The patch touches only `builtin/branch.c` and makes no functional changes—it is purely a code reorganization. The extracted helper takes a `strbuf` for the config key, the branch name, and the `flags` bitmask, returning `true` if the branch should be processed (i.e., the config is unset or `true`) and `false` if the user has opted out. The helper also emits the existing informational message when skipping an opted-out branch in non-quiet mode.

This patch remains **explicitly uncontroversial** and is ready for integration. Junio has not raised any concerns about it in the v4, v5, or v6 iterations, and the series’ cover letter continues to mark it as such. The refactoring is a prerequisite for the third patch, which implements the core `--delete-integrated` flag.
