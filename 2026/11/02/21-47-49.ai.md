This is a **contributor housekeeping** patch updating the bash-completion script in `contrib/` to add missing shell completions for three `git log` options: `--graph-indent`, `--no-graph-indent`, and `--graph-lane-limit`. This is the second iteration of the patch, incorporating feedback from the first version.

The patch now adds all three options to the `__git_log_gitk_options` block (rather than `__git_log_common_options` as in v1), grouping them with `--graph` as suggested by Pablo Sabater. This change aligns the completion logic with the semantic relationship between the options: all three are graph-rendering modifiers that only make sense when `--graph` is present. The commit message cites the original commits that introduced the options, providing clear provenance.

This version addresses the two main review points from v1: (1) moving the options to the correct variable (`__git_log_gitk_options`), and (2) including `--graph-lane-limit` (which was not present in v1). The patch remains mechanical and low-risk, touching only the completion script and not affecting Git's core behavior. No test coverage is provided, but this is typical for completion script changes, which are validated manually.

The broader architectural discussion about conditional completion (e.g., suppressing `--graph`-dependent options unless `--graph` is present) and self-maintaining completion hints via `parse-options.h` remains open but is not addressed in this patch. Mirko has indicated this is forward-looking work, and the current patch is scoped to the immediate goal of adding missing completions.

Key technical details for follow-up: the patch adds `--graph-lane-limit=` (with an equals sign), indicating it expects a value, which matches the option's documented behavior. The options are added to the block used by both `git log` and `gitk`, though `--graph-indent` and `--graph-lane-limit` are only documented for `git log`. This is consistent with the existing pattern in the script, where options are grouped by relevance rather than strict command-specificity. If this becomes a point of contention, it would likely focus on whether the completion should be restricted to `git log` only.
