This is the first patch in Jasper Mayone’s four-part series (v4) that tightens safety around `git worktree remove`. It prevents the command from deleting a worktree that is in the middle of a rebase, `git am`, bisect, cherry-pick, or revert unless the user supplies `--force`. The patch treats these operations as “unclean” states, even when the worktree’s files are clean, because the operation’s state lives in the worktree’s own `$GIT_DIR` and would be lost if the worktree were removed. The documentation is updated to list the conditions requiring `--force` in a bulleted format for clarity, and the tests now cover every operation the patch protects, including edge cases like a single-commit cherry-pick that has been resolved to the current contents (leaving `CHERRY_PICK_HEAD` behind). The implementation is clean, well-tested, and directly addresses a real risk of data loss that was highlighted in earlier review discussion. It looks ready for integration.
