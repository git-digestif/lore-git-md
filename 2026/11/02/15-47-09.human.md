This is a bugfix patch that aligns the connectivity check in `git rev-list` with other Git operations like `fsck`, `prune`, and `pack-objects` by ignoring replacement objects.

The patch addresses a subtle inconsistency: while most Git operations that verify repository completeness ignore replacement refs (to work with the original objects), the connectivity check (`check_connected()`) currently follows them. This can lead to a mismatch where the connectivity check accepts a pack as complete even if downstream operations like `fsck` or `repack` would later fail because they ignore replacements. The issue is rare in practice but creates a logical inconsistency.

Kristofer Karlsson, the author, frames this as both a question and a proposed fix, asking whether the current behavior is intentional or if alignment is preferable. The patch modifies `rev-list` to disable replacement refs when the `--connectivity-check` option is used, matching the behavior of other commands. It also updates a test to reflect the new behavior, removing a redundant case.

The change is small and targeted, touching only the connectivity check logic and its documentation. The commit message is clear and provides historical context, making it easy to understand the motivation. This looks like a well-justified cleanup rather than a controversial change.
