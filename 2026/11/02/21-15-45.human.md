This is a **feature patch** for `git range-diff`, introducing the `--matched-only` option to filter output to show only commits present in both input ranges. The patch is now **ready for merging** and has been queued in `seen`, but is at risk of being dropped due to lack of review despite no remaining technical objections.

Harald Nordgren clarifies the feature’s motivation in this reply to Ben Knoble’s substantive review question. The use case is straightforward: when rebasing a long-lived branch against `master`, the default `git range-diff` output buries the few relevant changes (commits that survived the rebase) under hundreds of unrelated commits that were simply added or dropped. `--matched-only` eliminates this noise, letting users focus on how surviving commits changed without scrolling through irrelevant entries. Harald’s example—311 unrelated commits before reaching the actual changes—vividly illustrates the pain point.

The implementation is minimal and additive. It reuses existing suppression logic by internally setting both `--left-only` and `--right-only` when `--matched-only` is specified, avoiding new symbols beyond a single struct field. Mutual exclusion with other filtering options is enforced via a simple arithmetic check in the library layer, with the CLI front-end handling `die()` calls. The patch touches only presentation logic, with no on-disk format changes, and includes thorough test coverage.
