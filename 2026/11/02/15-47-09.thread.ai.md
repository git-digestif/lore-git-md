Thread identity
Subject: rev-list: ignore replacements during connectivity check
Series version: standalone patch (no version marker)
Originating author: Kristofer Karlsson
Thread type: bugfix

Core problem or goal
The connectivity check in `git rev-list` (used by `fetch`, `receive-pack`, and `index-pack`) currently follows replacement refs, while other commands (`fsck`, `prune`, `pack-objects`, `upload-pack`) ignore them. This inconsistency can cause a pack to pass the connectivity check (because replacements are visible) but later fail `fsck` (because replacements are ignored and the original objects are missing). The goal is to align `rev-list`'s connectivity check with the established behavior of the other commands by ignoring replacement objects.

Current status
Under review; no prior versions. The patch adds a `--connectivity-check` flag to `git rev-list` that ignores replacement refs, modifies `tree-verify.c` to drop the `OBJECT_INFO_LOOKUP_REPLACE` flag, and updates test `t5413` to expect rejection when replacements mask missing objects. The core design question—whether the connectivity check should ignore replacements (current patch) or verify both original *and* replacement objects—has converged on the original approach (ignoring replacements). Junio C Hamano endorsed the core idea ("absolutely the right thing to do") but initially raised the alternative; Patrick Steinhardt's reviews reinforce the current patch's design, noting that the connectivity check's scope is limited to validating transferred objects, not policing locally created refs. The patch now faces two technical concerns: (1) whether the test change in `t5413` was originally written to accommodate a real-world edge case, and (2) whether the removal of `OBJECT_INFO_LOOKUP_REPLACE` from `tree-verify.c` unintentionally affects other callers (e.g., `fsck`, `index-pack`).

Key technical details
- Files: `builtin/rev-list.c` (new `--connectivity-check` flag), `tree-verify.c` (drops `OBJECT_INFO_LOOKUP_REPLACE`), `t/t5413-rev-list-connectivity.sh` (updated test coverage), `Documentation/rev-list-options.adoc` (updated), `Documentation/git-replace.adoc` (needs update)
- New behavior: `git rev-list --connectivity-check` ignores replacement refs
- Old behavior: followed replacement refs, potentially masking missing objects
- On-disk format: unchanged
- Test coverage: `t5413` verifies the new behavior rejects packs where replacements mask missing objects
- Side effects: removal of `OBJECT_INFO_LOOKUP_REPLACE` in `tree-verify.c` may affect other callers (e.g., `fsck`, `index-pack`)

Open questions and loose ends
- Documentation inconsistency: `git-replace.adoc` still claims that *all* commands except reachability traversals (prune, pack transfer, fsck) use replacements by default, but `rev-list --connectivity-check` now ignores them. This needs updating to reflect the new exception.
- Test context: was the original expectation in `t5413` (accepting a commit with a missing original tree but a complete replacement) intentional, or was it an oversight? If intentional, the new behavior might break existing workflows.
- Caller audit: has the author audited all callers of `odb_read_object_info_extended()` to ensure consistency? Specifically, should other object verification sites (e.g., `fsck`, `index-pack`) also ignore replacements, or should this change be scoped more narrowly to the connectivity check?

Participant positions
- Kristofer Karlsson (author): proposes ignoring replacements for consistency with other commands (`fsck`, `prune`, etc.), citing established behavior since 2009. Argues that replacement objects are stored as regular refs, so their reachable objects are already covered by ordinary connectivity checks during fetch or push.
- Junio C Hamano (maintainer): endorses the core idea ("absolutely the right thing to do") but initially suggested an alternative approach (checking both originals and replacements). The question is now effectively resolved in favor of the original patch.
- Patrick Steinhardt: two substantive reviews reinforcing the current patch's design but raising technical concerns: (1) potential breakage of existing workflows due to the `t5413` test change, and (2) unintended side effects of removing `OBJECT_INFO_LOOKUP_REPLACE` from `tree-verify.c`. No objections to the core design.
- Karthik Nayak: surface-level review noting the documentation inconsistency between `rev-list-options.adoc` and `git-replace.adoc`. No technical objections.
