Thread identity
Subject: rev-list: ignore replacements during connectivity check
Series version: standalone patch (no version marker)
Originating author: Kristofer Karlsson
Thread type: bugfix

Core problem or goal
The connectivity check in `git rev-list` (used by `fetch`, `receive-pack`, and `index-pack`) currently follows replacement refs, while other commands (`fsck`, `prune`, `pack-objects`, `upload-pack`) ignore them. This inconsistency can cause a pack to pass the connectivity check (because replacements are visible) but later fail `fsck` (because replacements are ignored and the original objects are missing). The goal is to align `rev-list`'s connectivity check with the established behavior of the other commands by ignoring replacement objects.

Current status
Under review; no prior versions. The patch touches `builtin/rev-list.c` (adding `--connectivity-check` flag to ignore replacements), `tree-verify.c` (dropping `OBJECT_INFO_LOOKUP_REPLACE` flag), and updates test `t5413` to expect rejection when replacements mask missing objects. Junio C Hamano has endorsed the core idea but raised a conceptual question: whether the connectivity check should instead ensure *both* original *and* replacement objects exist, treating replacements as additional tips in the connectivity graph. This alternative approach is acknowledged as a separate issue but may influence the final design.

Key technical details
- Files: `builtin/rev-list.c`, `tree-verify.c`, `t/t5413-rev-list-connectivity.sh`
- New behavior: `git rev-list --connectivity-check` ignores replacement refs (current patch)
- Proposed alternative: check connectivity for both original *and* replacement objects (Junio's suggestion)
- Old behavior: followed replacement refs, potentially masking missing objects
- On-disk format: unchanged
- Test coverage: `t5413` updated to verify the new behavior

Open questions and loose ends
- Whether the connectivity check should ignore replacements (current patch) or verify both originals and replacements (Junio's alternative).
