Thread identity
Subject: rev-list: ignore replacements during connectivity check
Series version: standalone patch (no version marker)
Originating author: Kristofer Karlsson
Thread type: bugfix

Core problem or goal
The connectivity check in `git rev-list` (used by `fetch`, `receive-pack`, and `index-pack`) currently follows replacement refs, while other commands (`fsck`, `prune`, `pack-objects`, `upload-pack`) ignore them. This inconsistency can cause a pack to pass the connectivity check (because replacements are visible) but later fail `fsck` (because replacements are ignored and the original objects are missing). The goal is to align `git rev-list`'s connectivity check with the established behavior of the other commands by ignoring replacement objects.

Current status
Under review; no prior versions. The patch adds a `--connectivity-check` flag to `git rev-list` that ignores replacement refs, modifies `tree-verify.c` to drop the `OBJECT_INFO_LOOKUP_REPLACE` flag, and updates test `t5413` to expect rejection when replacements mask missing objects. Junio C Hamano has now fully endorsed the core design ("no need to do anything extra"), resolving the earlier ambiguity in favor of ignoring replacements. The patch remains unchanged, and the thread is now focused on two remaining technical concerns: (1) the test change in `t5413` was intentionally written to accommodate a real-world edge case (accepting a commit with a missing original tree if a replacement exists), meaning the new behavior could break existing workflows, and (2) the removal of `OBJECT_INFO_LOOKUP_REPLACE` from `tree-verify.c` is confirmed to be scoped correctly, as the global replacement mechanism is already disabled when this code path runs, and `tree-verify.c` is only used by `rev-list --connectivity-check=incremental`.

Key technical details
- Files: `builtin/rev-list.c` (new `--connectivity-check` flag), `tree-verify.c` (drops `OBJECT_INFO_LOOKUP_REPLACE`), `t/t5413-rev-list-connectivity.sh` (updated test coverage), `Documentation/rev-list-options.adoc` (updated), `Documentation/git-replace.adoc` (no update needed per author's clarification)
- New behavior: `git rev-list --connectivity-check` ignores replacement refs
- Old behavior: followed replacement refs, potentially masking missing objects
- On-disk format: unchanged
- Test coverage: `t5413` verifies the new behavior rejects packs where replacements mask missing objects
- Side effects: removal of `OBJECT_INFO_LOOKUP_REPLACE` in `tree-verify.c` affects only `rev-list --connectivity-check=incremental`; a separate, unrelated bug in `mktree` (follows replacements when checking object existence but writes the original OID into the tree) is noted but not addressed

Open questions and loose ends
- Workflow impact: the test change in `t5413` was intentional, meaning the new behavior (rejecting packs where replacements mask missing objects) could break existing workflows that rely on this edge case.
- Unrelated bug: `mktree` follows replacements when checking object existence but writes the original OID into the tree, which could allow missing objects to pass validation. Flagged as a potential bug but not addressed in this patch.

Participant positions
- Kristofer Karlsson (author): proposes ignoring replacements for consistency with other commands (`fsck`, `prune`, etc.), citing established behavior since 2009. Argues that replacement objects are stored as regular refs, so their reachable objects are already covered by ordinary connectivity checks during fetch or push. Confirms the test change in `t5413` was intentional and that the removal of `OBJECT_INFO_LOOKUP_REPLACE` from `tree-verify.c` is correctly scoped. Notes the unrelated `mktree` bug but does not address it in this patch. Defends the existing wording in `git-replace.adoc`, arguing that the patch improves accuracy: the connectivity check is part of pack transfer, so the text was already misleading (it claimed "pack transfer" ignores replacements, but the connectivity check did follow them). The list of commands ignoring replacements was never exhaustive, and the patch aligns behavior with the documented intent.
