Thread identity
Subject: [PATCH 0/6] odb: move loose object backend into its own source file
Series version: v1
Originating author: Patrick Steinhardt <ps@pks.im>
Thread type: patch series (refactoring)

Core problem or goal
Refactor the Git object database (ODB) to isolate the loose-object backend logic into a dedicated source file (`odb/source-loose.c`). This is part of the broader ODB abstraction effort to make backends (loose, packed, files) more modular, enabling easier audits of backend-agnostic code and identifying subsystems that still depend on backend internals.

Current status
Under review. This is the first version (v1) of the series. The series builds on recent `master` but conflicts with the in-flight topic `bc/restrict-hex-to-lowercase`; a resolution diff is provided in the cover letter. All patches in the series have now received at least surface-level review from Kaartic Sivaraam, with no substantive objections raised. The series is mechanically correct and ready for deeper technical review or integration, pending resolution of the merge conflict.

Key technical details
- **Files touched**: 20 files in total. Primary changes:
  - `object-file.c`: 419 lines removed (loose-object reading, path derivation, and iteration logic).
  - `odb/source-loose.c`: 429 lines added (consolidated loose-object backend logic, including mmap deduplication).
  - Header files: `object-file.h` and `odb/source-loose.h` (declarations moved to reflect new backend isolation).
- **Logic moved**: Loose-object reading (`read_loose_object()`, `unpack_loose_header()`, `unpack_loose_rest()`, `parse_loose_header()`, `map_fd()`), path derivation (`odb_loose_path()`, `fill_loose_path()`), and iteration logic (`for_each_loose_file_in_objdir()`, `for_each_file_in_obj_subdir()`) are relocated to `odb/source-loose.c`.
- **Deduplication**: mmap logic is consolidated in the new backend file by having `odb_source_loose_map_object()` reuse `map_fd()` (patch 4/6), removing 20 lines of duplicate code. Patrick Steinhardt declined Kaartic Sivaraam’s suggestion to adopt the `goto out` pattern in `map_fd()` for stylistic consistency, citing minimal churn as the reason; the suggestion remains valid for future cleanup.
- **Header changes**: Direct includes of `odb/source-loose.h` and `git-zlib.h` are removed from `object-file.h`. Patch 5/6 removes the blanket `#include "odb/source-loose.h"` from `object-file.h` and adds explicit includes in the seven compilation units that still need loose-backend internals (`builtin/pack-objects.c`, `http-walker.c`, `http.c`, `loose.c`, `object-file.c`, `setup.c`, and the header itself). Patch 6/6 removes the blanket `#include "git-zlib.h"` from `object-file.h` and adds explicit includes in the nine files that directly use zlib (`apply.c`, `builtin/fast-import.c`, `builtin/index-pack.c`, `builtin/pack-objects.c`, `diff.c`, `object-file.c`, `odb/source-loose.c`, `pack-check.c`, and `packfile.c`). These changes are purely mechanical and make backend dependencies visible for future abstraction work.
  - **Clarifications from follow-up**: `builtin/pack-objects.c` can drop its `#include "object-file.h"` directive, but only after patch 6/6 lands because it currently relies on an implicit dependency on `git-zlib.h`. `http-walker.c` should have its `#include "object-file.h"` removed in patch 5/6, not earlier. `object-file.h` still requires `#include "odb/streaming.h"` because it uses `struct odb_stream`, despite compiling without it by chance.
- **New symbols**: No new public API symbols are exposed. Backend-specific functions (e.g., `loose_object_path()`, `for_each_loose_file_in_objdir()`) are introduced in `odb/source-loose.c` but remain internal to the ODB layer.
- **Behavior**: No functional changes; the refactoring maintains existing behavior while reorganizing code structure. The only behavioral tweak is inlining `fill_loose_path()` in `odb_loose_path()`, which simplifies the call chain without altering functionality. The iteration function still accepts a generic `struct odb_source` rather than the loose-specific `struct odb_source_loose`, deferring that cleanup to future work.
- **Subsystems**: Primarily affects the ODB layer, with indirect impacts on subsystems currently relying on loose-backend internals (e.g., dumb transport, which still uses `odb_loose_path()` pending future abstraction).

Open questions and loose ends
- The series conflicts with `bc/restrict-hex-to-lowercase`; the resolution is provided in the cover letter, but integration timing remains unclear.
- **Documentation preservation**: Patrick Steinhardt has accepted Kaartic Sivaraam's suggestion to move documentation comments for relocated functions from `object-file.h` to `odb/source-loose.c` above the corresponding static functions. This feedback applies to all patches in the series and will be addressed in the next revision.
- **Header hygiene**: Kaartic Sivaraam identified five follow-up cleanup opportunities, now clarified by Patrick Steinhardt:
  - `http-walker.c` no longer needs to include `object-file.h` after patch 5/6 (the removal belongs in patch 5/6, not earlier).
  - The four callers updated in patch 3/6 (`builtin/count-objects.c`, `builtin/gc.c`, `builtin/prune.c`, and `prune-packed.c`) no longer need their existing `#include "object-file.h"` directives.
  - `builtin/pack-objects.c` and `loose.c` no longer need `#include "object-file.h"` after patch 6/6 (not patch 5/6, due to an implicit dependency on `git-zlib.h`).
  - `object-file.h` still requires `#include "odb/streaming.h"` despite compiling without it by chance.
  None of these cleanups block the series but are noted for future attention.
- **Stylistic consistency**: Kaartic Sivaraam suggested adopting the `goto out` pattern in `map_fd()` to match `odb_source_loose_map_object()`, but Patrick Steinhardt declined this change to minimize churn; the suggestion remains valid for future cleanup.
- No substantive review feedback has been received yet beyond surface-level observations on documentation, header hygiene, and stylistic consistency. The broader architectural implications of the ODB abstraction effort have not been discussed.
- The iteration function signature (`for_each_loose_file_in_source`) could be tightened in a later iteration to use the loose-specific `struct odb_source_loose`.
- Future abstraction is needed to fully hide backend internals from callers like the dumb transport, which still directly uses `odb_loose_path()`.
