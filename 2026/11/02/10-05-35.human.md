This is a feature patch adding the `--matched-only` option to `git range-diff`. The patch is part of a small, self-contained series (v3) that has been sitting in `seen` for over six weeks without further review. The goal is straightforward: let users filter `range-diff` output to show only commits present in both input ranges, making it easier to focus on how surviving commits changed during a rebase or other history rewrite, without distraction from added or dropped commits.

The implementation is minimal and uncontroversial. It adds the new option, enforces mutual exclusion with `--left-only` and `--right-only`, reuses existing suppression logic, and includes thorough test coverage. The only substantive discussion point—error-handling layering—was resolved in v3 by reverting to the original `error()` call in the library layer and letting the CLI front-end handle `die()`. Junio’s earlier objections have been fully addressed, and the patch is ready for merging.
