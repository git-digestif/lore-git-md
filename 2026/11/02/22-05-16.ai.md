This is a bugfix targeting the connectivity check in `git rev-list`. Junio C Hamano replies to Kristofer Karlsson's patch, endorsing the core idea—aligning `rev-list`'s connectivity check with other commands by ignoring replacement objects—but raises a conceptual question: instead of ignoring replacements entirely, should the check ensure that *both* the original *and* replacement objects exist? This would treat replacement objects as additional tips in the connectivity graph, guaranteeing that all objects reachable from replacements are present. Junio describes this as a separate issue to address later, but his framing suggests it may become a point of discussion.

The patch itself remains unchanged in this reply. It adds a `--connectivity-check` flag to `rev-list` that disables replacement refs (via `disable_replace_refs()`), updates `tree-verify.c` to drop the `OBJECT_INFO_LOOKUP_REPLACE` flag, and documents the new behavior. The implementation is straightforward and matches the established pattern used by `fsck`, `prune`, and other commands since 2009. Junio's review is brief but positive, calling the change "absolutely the right thing to do" and "straightforward."

The thread now has two clear positions: Kristofer's original proposal (ignore replacements for consistency) and Junio's alternative (check both originals and replacements). No other participants have weighed in yet, so the discussion is still open. The patch is small, well-motivated, and touches only three files (`builtin/rev-list.c`, `tree-verify.c`, and documentation), making it easy to iterate on if the design shifts.
