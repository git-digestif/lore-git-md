This is the second patch in the v7 series adding path-related keys to `git repo info`. It fixes a **substantive correctness bug** in the `get_superproject_working_tree()` function, which previously used the current working directory (`xgetcwd()`) to determine the repository whose superproject should be checked. This was incorrect when `--git-dir` pointed to a repository different from the one associated with the current working directory, potentially returning the wrong superproject or an empty result.

The patch updates the function to accept a `struct repository *` parameter and use the repository’s working directory (via `repo_get_work_tree()`) instead of the shell’s working directory. This ensures the function respects the repository being inspected, not the shell’s context. The change touches `submodule.c` (implementation), `submodule.h` (function signature), `builtin/rev-parse.c` (updated caller), and adds a new test in `t/t7400-submodule-basic.sh` to verify the fix works with `--git-dir`.

Justin Tobler’s review identifies a **test failure** in this patch: the new test exercises `path.superproject-root`, which isn’t introduced until the next patch (3/8). He suggests the test should instead verify the existing `git rev-parse --show-superproject-working-tree` behavior, which this patch already fixes. The fix itself is **mechanically sound and well-motivated**, but the test placement is problematic. This is a **surface-level issue** that doesn’t affect the patch’s correctness but could cause confusion during review or bisecting. The author will likely need to adjust the test to avoid referencing the not-yet-introduced key.

The patch is **ready for substantive review** and addresses a high-weight correctness concern raised by Junio in v6. The fix is minimal, focused, and well-explained in the commit message.
