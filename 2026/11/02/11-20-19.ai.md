This is a refactoring patch (3/6 in the series) targeting the object database (ODB) abstraction effort. It moves the loose-object iteration logic (`for_each_loose_file_in_source` and its helper `for_each_file_in_obj_subdir`) from `object-file.c` into the new backend file `odb/source-loose.c`, continuing the isolation of loose-backend internals.

The patch is mechanical: it relocates ~90 lines of code (including function declarations, typedefs, and implementations) from the core object-file layer to the backend-specific file. Callers in `builtin/count-objects.c`, `builtin/gc.c`, `builtin/prune.c`, and `prune-packed.c` are updated to include the new backend header (`odb/source-loose.h`) instead of `object-file.h`. The commit message notes a design quirk: the iteration function still accepts a generic `struct odb_source` rather than the loose-specific `struct odb_source_loose`, deferring that cleanup to future work.

This is a clean, focused step in the ODB abstraction series. The change maintains existing behavior while making the backend more self-contained, and the commit message clearly explains the rationale and limitations. No functional changes or new API symbols are introduced. The patch looks well-prepared for review, though the author acknowledges the function signature could be tightened in a later iteration.
