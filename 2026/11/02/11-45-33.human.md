This is a **bugfix and performance patch** targeting Git's object quarantine mechanism. The patch (v2) addresses a long-standing inefficiency where Git unnecessarily loads all hidden refs from the repository's own object directory during push connectivity checks, even though earlier work (`bcec6780b2`) explicitly excluded hidden refs from these checks.

The fix repurposes `GIT_QUARANTINE_ENVIRONMENT` to carry the parent repository's object directory path, avoiding fragile path comparisons and new APIs. This approach has been endorsed by Junio C Hamano and Jeff King as a pragmatic short-term solution, though both acknowledge the alternate object store interface's existing fragility. The patch is minimally invasive, touching only quarantine plumbing (`tmp-objdir.c`) and environment variable handling (`environment.c`), and includes thorough test coverage—both functional tests (verifying edge cases like quarantines outside the commondir) and a new perf test demonstrating a **67.7% speedup** in repositories with 200,000 hidden refs.

The patch is well-motivated, with clear performance data and a commit message that explains the root cause and design trade-offs. While the "parent-path deduction" assumption is described as "icky," it’s framed as a necessary stopgap pending a more robust ODB abstraction solution. Feedback from ODB maintainers (Patrick Steinhardt, Justin Tobler) is still pending, but the patch looks ready for `next` given the performance regression it fixes. Expect follow-up discussion about long-term ODB transaction callbacks, but this version is a solid incremental improvement.
