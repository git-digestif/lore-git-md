This is the first patch in Patrick Steinhardt’s v2 CI/build system cleanup series (now seven patches). It consolidates the setup of Git’s CI test environment variables by moving all environment variable assignments from `ci/run-build-and-tests.sh` into `ci/lib.sh`. The goal is to centralize configuration logic, making it easier to maintain and understand which variables apply to which CI jobs.

The patch is a pure refactoring: it moves 44 lines of environment variable assignments (spread across three `case` statements in `ci/run-build-and-tests.sh`) into `ci/lib.sh`, adding 43 lines there. This creates temporary duplication—both files now contain the same logic—but the commit message explains this as a deliberate stepping stone for later cleanup. The duplication will be resolved in subsequent patches, which will further consolidate and simplify the logic.

Key details include the variables being moved: `GIT_TEST_USE_SET_E` (set for Linux jobs), `WITH_BREAKING_CHANGES` (for breaking-changes jobs), `GIT_TEST_DEFAULT_HASH` (for SHA-256 jobs), `GIT_TEST_DEFAULT_REF_STORAGE_FORMAT` (for reftable jobs), and a long list of feature-testbed settings (e.g., `GIT_TEST_SPLIT_INDEX`, `GIT_TEST_COMMIT_GRAPH`). The patch also moves the `TEST_CONTRIB_TOO=yes` export into `ci/lib.sh`, ensuring it applies globally.

No behavior changes are introduced; this is purely a reorganization. The patch has already received positive feedback from reviewers (Jeff King, Phillip Wood, Toon Claes) as part of the broader series, and it is uncontroversial. The main value is in setting up the foundation for the rest of the series, which will eliminate redundancy and improve maintainability. Files touched: `ci/lib.sh` and `ci/run-build-and-tests.sh`.
