This is the **core API patch** in Christian Couder’s v4 series introducing `early_scan_options()`, a new `parse-options` sub-API for safely scanning command-line arguments early. The patch is part of a **bugfix and API refactoring** effort that is now **ready for `next`**, having addressed all substantive feedback from Junio, Kaartic Sivaraam, and Cynthia Uche.

The patch adds `early_scan_options()` to `parse-options.c`, allowing Git commands to scan their arguments for specific options before full parsing begins. This replaces fragile hand-rolled scans (like the one in `git fast-import` that previously ignored `--allow-unsafe-features` when preceded by `--depth 5`). The API reuses `parse-options` internals (`lookup_long_opt()` and `parse_options_takes_argument()`) to handle negated options, unambiguous abbreviations, and aliases consistently with `parse_options()`. It is deliberately conservative—stopping at short options, unknown options, ambiguous abbreviations, and low-level callbacks—to avoid misinterpreting option values.

Key technical details:
- **New flag**: `PARSE_OPT_EARLY` marks options to be reported during early scanning.
- **New function**: `early_scan_options()` scans `argv` for `PARSE_OPT_EARLY`-marked options, calling a callback for each match.
- **Validation**: The function now calls `parse_options_check()` to prevent invalid uses of `PARSE_OPT_EARLY` (e.g., short options or `OPTION_SUBCOMMAND`).
- **Behavior**: The scan stops at `--`, `--end-of-options`, non-options (if `EARLY_SCAN_STOP_AT_NON_OPTION` is set), short options, unknown/ambiguous options, and low-level callbacks. This ensures the scan never misinterprets an option value as an option.
- **Test coverage**: The patch adds 28 new tests in `t/t0040-parse-options.sh`, exercising edge cases like stuck/separate values, negated options, ambiguous abbreviations, and non-options. A new test helper (`test-parse-options --early-scan-options`) validates the API.

The implementation is **clean and well-documented**, with clear warnings about the ephemeral nature of the `option` pointer passed to callbacks. The v4 redesign addresses all prior concerns: usability (via improved validation and documentation), code clarity (replacing an `if`-statement chain with a `switch`), and correctness (handling negated options and abbreviations consistently with `parse_options()`). The patch is **uncontroversial** and **ready for integration**, with no unresolved technical issues. Future work may extend adoption to other commands (e.g., `git bisect`), but this is not a blocker.
