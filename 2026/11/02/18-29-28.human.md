This is a **documentation patch** that improves the `git-for-each-ref` man page by warning users about parsing risks with the `%(worktreepath)` atom. The patch addresses a real usability issue: worktree paths can contain newlines, which breaks scripts that assume one record per line. It explains two safe parsing strategies—using a quoting option like `--shell` or NUL-terminated output (`%00`)—and clarifies that only one worktree is shown when a branch is checked out in multiple worktrees.

The change is small but important for anyone scripting with `%(worktreepath)`. It directly responds to Phillip Wood’s review feedback in the thread, where he flagged the lack of guidance on handling paths with newlines. The wording is clear and actionable, and the patch is uncontroversial. If you use `git for-each-ref` in scripts, this update is worth noting.
