This is a **documentation patch** in the four-part series adding filtering capabilities to `git worktree list` via the `%(worktreepath)` atom in `git for-each-ref`. This specific patch updates the `git-for-each-ref(1)` man page to warn users about two safety-critical limitations of the `%(worktreepath)` atom: (1) worktree paths can contain newlines, which breaks scripts that assume one record per line, and (2) only one worktree is shown when a branch is checked out in multiple worktrees.

The patch adds clear guidance on how to handle newlines safely: use a quoting option like `--shell` or append `%00` to the format string and parse the output by looking for the NUL terminator before the LF that ends each record. This addresses Phillip Wood’s concern about parsing safety, which was raised in the thread as a potential footgun for scripts. The documentation change is minimal but precise, adding just six lines to the existing description of `%(worktreepath)`.

This patch is part of a well-motivated series that fixes a real usability gap (the `%(worktreepath)` atom not reporting worktree paths for rebasing/bisecting branches) while also addressing a pre-existing safety issue (`git worktree remove` allowing deletion of in-progress worktrees). The documentation update is a necessary complement to the functional changes, ensuring users are aware of the atom’s limitations and how to work around them. The patch is uncontroversial and ready for integration. It touches only the `Documentation/git-for-each-ref.adoc` file.
