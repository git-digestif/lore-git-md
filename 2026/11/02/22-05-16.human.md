This is a bugfix targeting the connectivity check in `git rev-list`. Junio C Hamano replies to Kristofer Karlsson’s patch, endorsing the core idea—aligning `rev-list`’ connectivity checks with other commands like `fsck` and `prune` by ignoring replacement objects—but floats an alternative design: instead of ignoring replacements entirely, the connectivity check could verify *both* the original objects *and* the objects reachable from the replacement chain. This would ensure that replacements themselves are backed by complete history, not just the original objects.

The patch itself is straightforward: it disables replacement refs during the connectivity check (via `disable_replace_refs()` in `builtin/rev-list.c`) and removes the `OBJECT_INFO_LOOKUP_REPLACE` flag from `tree-verify.c` to match. Junio’s feedback doesn’t block the current approach but suggests a follow-up discussion about whether the stricter check (verifying replacements too) would be preferable. The patch is small, well-motivated, and addresses a real inconsistency, so it looks like a solid fix even if the design question remains open. No objections or implementation concerns are raised in this reply.
