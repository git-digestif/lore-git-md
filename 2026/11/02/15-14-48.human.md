This is a **revised API refactoring and bugfix series** introducing `early_scan_options()`, a new `parse-options` sub-API for safely scanning command-line arguments early. The v4 series addresses all remaining feedback from Junio, Kaartic Sivaraam, and Cynthia Uche, making the API ready for wider adoption.

The series fixes a real bug in `git fast-import`: `--allow-unsafe-features` was silently ignored when preceded by `--depth 5`, causing the command to refuse unsafe features from the input stream. The new API ensures the early scan aligns with `parse_options()` behavior, handling negated options, unambiguous abbreviations, and aliases consistently. The implementation stops at short options, unknown options, ambiguous abbreviations, and low-level callbacks to avoid misinterpreting option values, erring on the side of caution.

Key improvements since v3 include:
- A `switch` statement in `parse_long_opt()` for cleaner code (addressing Kaartic’s feedback).
- Validation checks in `early_scan_options()` to catch invalid `PARSE_OPT_EARLY` usage early (another Kaartic suggestion).
- Clearer API documentation warning that the `option` pointer passed to callbacks is ephemeral (Kaartic’s concern).
- An improved comment in `fast-import.c` explaining why `EARLY_SCAN_STOP_AT_NON_OPTION` is passed, even though `parse_options()` isn’t called with `PARSE_OPT_STOP_AT_NON_OPTION` (Cynthia’s feedback).
- A new test confirming `--allow-unsafe-features` is rejected when it follows a non-option argument (addressing a gap in test coverage).

The series is now **well-tested and technically sound**, with 28 new tests in `t/t0040-parse-options.sh` and 2 in `t/t9300-fast-import.sh`. The `git fast-import` conversion (patch 4/4) is ready for `next`, and the preparatory refactorings (patches 1/4 and 2/4) are uncontroversial. The core API (patch 3/4) addresses all prior usability concerns, including the argument-skipping responsibility, which is now documented as a deliberate design choice.

This is a **worthwhile effort** for maintainers of commands with hand-rolled early scans (e.g., `git bisect`, `git rev-parse`). The API is minimal, reusable, and avoids the fragility of ad-hoc parsing. The series is **very close to being ready for `next`**, pending Junio’s final review.
