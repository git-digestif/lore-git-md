This is the first patch in Christian Couder’s **v4 series** introducing `early_scan_options()`, a new `parse-options` sub-API for early command-line argument scanning. The patch is a **refactoring** that extracts the logic for determining whether an option takes an argument into a reusable function, `parse_options_takes_argument()`.

The change is **preparatory work** for the core API (patch 3/4) and the `git fast-import` bugfix (patch 4/4). The extracted function will be used by `early_scan_options()` to decide which arguments to skip during early scanning, ensuring consistent behavior with `parse_options()`. The patch also updates `show_gitcomp()`—the function responsible for shell completion—to use the new helper, replacing its open-coded logic.

The implementation is **clean and well-motivated**: the commit message explains why `PARSE_OPT_LASTARG_DEFAULT` options are treated as taking an argument (even though they only consume the next argument when it isn’t the last one), and the code itself is straightforward. The patch touches only `parse-options.c` and `parse-options.h`, with no behavior changes—just a mechanical refactor. The test coverage for shell completion (`t9902-completion.sh`) will indirectly exercise this change, but the real validation comes in later patches where `early_scan_options()` uses the helper.

This patch is **uncontroversial and ready for integration**. It’s a small, focused step toward the larger goal of replacing hand-rolled early argument scans with a reusable API. The series as a whole is **ready for `next`**, and this patch is a safe, incremental part of that effort.
