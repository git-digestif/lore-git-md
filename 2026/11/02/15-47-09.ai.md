This patch is a bugfix targeting the connectivity check in `git rev-list`. Kristofer Karlsson identifies an inconsistency: while commands like `fsck`, `prune`, `pack-objects`, and `upload-pack` ignore replacement objects (as established in 2009), the connectivity check (`check_connected()`) still follows them. This can lead to a mismatch where the connectivity check accepts a pack as complete (because it sees replacement objects) while later operations like `fsck` fail (because they ignore replacements and see missing original objects).

The fix teaches `rev-list` to ignore replacements when run with `--connectivity-check`, aligning its behavior with the other commands. The change affects both the full and incremental connectivity checks, and updates the `tree-verify.c` helper to drop the `OBJECT_INFO_LOOKUP_REPLACE` flag for consistency. The patch also adjusts a test (`t5413`) that previously expected the connectivity check to accept incomplete objects when replacements were present—now it correctly expects rejection.

The commit message is thorough, explaining the rationale, the edge case (a replace ref pointing to an object not yet present locally), and why shallow boundaries are unaffected. The author frames this as both a question ("should the connectivity check ignore replacements?") and a proposed solution, inviting discussion rather than assuming consensus. The patch itself is small and focused, touching only the necessary files (`builtin/rev-list.c`, `tree-verify.c`, and a test). No prior discussion of this inconsistency is cited, suggesting this is a novel observation.
