This is the **core API patch** in Christian Couder’s `parse-options` early scanning series (v4, 3/4). It introduces `early_scan_options()`, a new sub-API that lets Git commands safely scan for specific options before full argument parsing begins. The patch is **ready for `next`**, with all prior feedback addressed in this version.

The implementation reuses existing `parse-options` internals (`lookup_long_opt()` and `parse_options_takes_argument()`) to handle negated options, unambiguous abbreviations, and aliases consistently with `parse_options()`. The scan stops at short options, unknown options, ambiguous abbreviations, and low-level callbacks to avoid misinterpreting option values—a deliberate design choice to err on the side of caution. A new `PARSE_OPT_EARLY` flag marks options to be reported during early scanning, and `early_scan_options()` validates these flags upfront to prevent invalid usage (e.g., short options or `OPTION_SUBCOMMAND`).

The patch adds **28 new tests** in `t/t0040-parse-options.sh`, covering edge cases like stuck/separate values, negated options, ambiguous abbreviations, and non-option arguments. The API is exercised by a new test helper (`test-parse-options --early-scan-options`), and the documentation in `api-parse-options.txt` clearly explains the differences from `parse_options()` (e.g., stopping at `--`, `--end-of-options`, and non-options when `EARLY_SCAN_STOP_AT_NON_OPTION` is set).

Key technical details:
- **New flags**: `PARSE_OPT_EARLY` (marks options for early scanning), `EARLY_SCAN_STOP_AT_NON_OPTION` (stops at non-options, matching `PARSE_OPT_STOP_AT_NON_OPTION`).
- **New functions**: `early_scan_options()` (core API), `find_early_scan_option()` (internal helper), and validation checks in `parse_options_check()`.
- **Files touched**: `parse-options.h`, `parse-options.c`, `t/helper/test-parse-options.c`, `t/helper/test-tool.{c,h}`, `t/t0040-parse-options.sh`, and `Documentation/technical/api-parse-options.txt`.
- **Behavior**: The scan stops at arguments it cannot reliably skip (e.g., short options, ambiguous abbreviations, low-level callbacks) to avoid misinterpreting values. This ensures the scan never reports an option that `parse_options()` would reject, though it may miss some valid options.

This patch is the linchpin of the series, enabling the `git fast-import` bugfix in 4/4 and future conversions of commands with hand-rolled early scans (e.g., `git bisect`). The API is now well-documented, validated, and thoroughly tested, with no unresolved technical concerns.
