This is a gentle nudge from Junio about the stalled review of Harald Nordgren’s **v3 patch** that adds advice for `<rev>~N` and `<rev>^N` failures in shallow clones. The patch itself is a well-scoped, uncontroversial bugfix that addresses a real usability pain point: when a user in a shallow clone tries to access an ancestor not present locally (e.g., `git show HEAD~20`), Git currently emits a generic “is not a commit” error with no hint that the repository is shallow or how to fetch more history.

The v3 iteration is clean: it drops the flawed `git log` integration from earlier versions, fixes a bug where chained carets (`<rev>^^^`) printed the advice twice, and includes thorough test coverage. Junio’s earlier review praised the technical implementation (auto-detection of remote/branch, context-aware `--deepen` values, suppression of double-printing), and all prior feedback has been addressed. The patch touches `object-name.c`, `shallow.c`, `advice.c`, and adds tests in `t/t1500-rev-parse.sh`—nothing invasive or risky.

The only reason this hasn’t moved forward is lack of review bandwidth. Junio is giving the list a few weeks to volunteer; if no one steps up, he’ll drop it from `seen` to make room for more active topics. For anyone who’s ever been frustrated by Git’s opaque shallow-clone errors, this is a low-effort, high-impact patch that’s ready for `next`.
