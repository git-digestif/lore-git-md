This thread is a refactoring series from Patrick Steinhardt that moves Git’s loose-object backend logic into its own source file (`odb/source-loose.c`) as part of the broader ODB abstraction effort. The goal is to make backends more modular, easing audits of backend-agnostic code and identifying subsystems still tied to backend internals. The series is at version 1 (v1) and is under review, with no substantive feedback yet.

The refactoring touches 19 files, primarily extracting loose-object reading, path derivation, and iteration logic from `object-file.c` into the new backend file. The series maintains existing behavior while reorganizing code structure, though it conflicts with the in-flight `bc/restrict-hex-to-lowercase` topic (resolution provided in the cover letter). The latest email covers patch 4/6, a small but focused cleanup that deduplicates mmap logic in the loose-object backend by reusing `map_fd()` instead of reimplementing it. This change is uncontroversial and aligns with the series’ goals.

Key participants so far are limited to Patrick, who authored the series and provided conflict resolution guidance. The broader ODB abstraction effort remains ongoing, with future work planned to isolate packed and files backends and fully abstract backend internals from callers like the dumb transport. The series is a stepping stone toward those goals, with no major open questions beyond integration timing.
