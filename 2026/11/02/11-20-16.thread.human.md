This thread is about Patrick Steinhardt’s six-patch series to refactor Git’s object database (ODB) by moving the loose-object backend logic into its own source file, `odb/source-loose.c`. The goal is to make the ODB more modular, which will help isolate backend-specific code and identify parts of Git that still depend on backend internals. The series is currently under review, with no substantive feedback yet on its functional or architectural aspects.

Kaartic Sivaraam has reviewed the first four patches, confirming their mechanical correctness and suggesting minor improvements. For patch 4/6, which deduplicates mmap logic, Kaartic proposed a stylistic tweak to align `map_fd()`’s error handling with the pattern used in `odb_source_loose_map_object()`. This suggestion is non-blocking and focuses on code hygiene rather than the broader refactoring. Earlier reviews also noted that documentation comments for relocated functions should be preserved in the new backend file and identified a couple of follow-up header hygiene cleanups, but these are not critical to the series.

The series builds on recent `master` but conflicts with the in-flight topic `bc/restrict-hex-to-lowercase`; Patrick provided a resolution diff in the cover letter. No functional changes are introduced—this is purely a refactoring—but it sets the stage for future work, including isolating other backends (packed, files) and fully abstracting backend internals from callers like the dumb transport. The next steps are to address Kaartic’s feedback and await further review, particularly on the architectural implications of the ODB abstraction effort.
