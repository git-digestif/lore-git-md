This is a **bugfix follow-up** to the earlier Trace2 diagnostic patch for `git maintenance`. The author, Pushkar Singh, has expanded the scope to address the latent lock-handling inconsistency Patrick Steinhardt flagged in review.

The patch now does two things: (1) retains the Trace2 event for `--auto` skips due to an existing lock, and (2) changes the behavior for **manual invocations** (`git maintenance run` without `--auto`) so they **fail fast** with an error when the lock cannot be acquired, matching the precedent set by `git gc`. The `--auto` mode still succeeds but prints a warning, preserving its intended non-blocking behavior.

The change is small (a few lines in `builtin/gc.c`) and comes with a test update in `t/t7900-maintenance.sh` that verifies both the Trace2 event and the new exit code. The commit message explains the motivation clearly: silent success on lock contention was inconsistent and potentially confusing. No controversy is expected; the patch aligns with established patterns and addresses feedback directly.
