This is a **bugfix and ref-filter enhancement** patch series (v4) targeting the worktree subsystem. The series consists of four patches that address two related safety issues: (1) `git worktree remove` currently allows deletion of worktrees in the middle of a rebase, bisect, cherry-pick, revert, or `git am` operation, risking data loss; and (2) `git for-each-ref`'s `%(worktreepath)` atom does not report the worktree path for branches being rebased or bisected, creating a mismatch with how `git worktree add` and `git branch -d` already treat those branches as "checked out."

The first patch makes `git worktree remove` refuse to delete a worktree that is in the middle of an operation unless `--force` is given, aligning with Git’s general principle of protecting uncommitted or in-progress work. This is a **safety fix** that closes a pre-existing bug made more urgent by the second patch. The implementation adds a new helper function, `worktree_is_in_progress()`, which checks for rebase, bisect, cherry-pick, revert, and `git am` state, and updates the `git worktree remove` logic to refuse deletion unless `--force` is provided. The patch now also checks for `CHERRY_PICK_HEAD` and `REVERT_HEAD` when a single-commit cherry-pick or revert has completed without conflicts, addressing an edge case Phillip Wood identified. The documentation for `git worktree remove` has been updated to list the conditions requiring `--force` in a bulleted format for clarity, and the tests use shared setup and subshells to improve organization.

The second patch is a **documentation update** that adds a warning to `git-for-each-ref(1)` about parsing `%(worktreepath)` safely. It notes that worktree paths can contain newlines and recommends using quoting options (e.g., `--shell`) or NUL-terminated output (`%00`) to handle such cases. The patch also clarifies that only one worktree is shown for a branch checked out in multiple worktrees, addressing a limitation of the atom.

The third patch extends `%(worktreepath)` in `ref-filter.c` to report the worktree path for branches being rebased or bisected, closing the gap Kristoffer Haugsbakk identified. The implementation avoids code duplication by exposing a shared helper, `branch_checked_out_worktree(const char *refname)`, in `branch.c` instead of copying logic from `prepare_checked_out_branches()`. The helper explicitly excludes branches that `rebase --update-refs` will move but are not currently checked out, ensuring consistency with `branch.c`'s logic. The patch also stops printing the `git_dir` of bare worktrees in `%(worktreepath)`, documenting this as a **breaking change** that aligns the atom’s behavior with its name and purpose. Tests verify the new behavior, including edge cases like rebasing, bisecting, and bare repositories.

The fourth patch removes the redundant `+` marker in `git branch` output for worktrees rebasing or bisecting a branch. Since the `(no branch, ...)` line already names the branch, the `+` marker is unnecessary and could be confusing. The documentation is updated to reflect this change, and tests verify the new output format.

The series is **backward-incompatible** for scripts relying on the current empty `%(worktreepath)` value for rebasing/bisecting branches, the `+` marker in `git branch` output, or the ability to delete in-progress worktrees without `--force`. The commit messages explicitly ask whether any such scripts exist, signaling awareness of the compatibility risk. The implementation is clean, well-tested, and addresses the design tensions identified in earlier RFC discussions. It avoids introducing new CLI options by leveraging `%(worktreepath)`, sidestepping the ordering invariant concern (main worktree appearing first) but leaving open the broader limitations of `for-each-ref` as a filtering mechanism (e.g., NUL-terminated output, main/linked worktree distinction). The series is ready for review and looks like a well-crafted fix for a real problem. Key files touched include `builtin/worktree.c`, `ref-filter.c`, `branch.c`, and their respective documentation and test files.
