This is a bugfix patch series (v4) targeting submodule diff header commit abbreviation, part of the Git libification effort. The series now consists of two patches: the original fix (unchanged from v3) and a new test patch that extends coverage to SHA-256 repositories.

The core issue remains the same: commit abbreviations in submodule diff headers were being checked against the superproject's object database, risking collisions where the same abbreviated ID could refer to different objects in the submodule. The fix ensures abbreviations use the submodule's repository when available, falling back to `o->repo` (from diff options) rather than the global `the_repository`.

The new second patch adds a test case for SHA-256 repositories, addressing Junio's earlier suggestion to make the test hash-agnostic. This is a direct response to feedback and improves the robustness of the test suite without altering the core fix. The test constructs a collision scenario using `test_oid_cache` to avoid hardcoded SHA-1 values, ensuring the test works across hash algorithms.

The series is now technically complete, with all prior feedback incorporated. Junio's "Will queue" indication from v3 still applies, and the addition of SHA-256 coverage makes this version more thorough than the already-accepted v3. The patches touch `submodule.c` and `t/t4041-diff-submodule-option.sh`, introducing no new symbols but reinforcing the use of `strbuf_repo_add_unique_abbrev()` for repository-aware abbreviation.

This looks like a well-crafted, low-risk fix with solid test coverage. The libification angle (reducing reliance on `the_repository`) is a bonus, though the patch stands alone as a correctness improvement for submodule diff display. The series is ready for integration.
