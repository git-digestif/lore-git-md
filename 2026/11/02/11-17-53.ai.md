This is the fifth patch in Patrick Steinhardt’s v2 CI/build system cleanup series (7 patches total). It aligns test behavior with Git’s compiled-in defaults for ref storage format, eliminating a redundant CI job in the process.

The patch addresses a gap in test coverage: when "breaking changes" (e.g., SHA-256) are enabled, tests now also use the compiled-in default ref storage backend (reftable) instead of hardcoding the "files" backend. This change ensures that the reftable backend is exercised in CI jobs that test breaking changes, making the explicit `linux-reftable-sha256` job obsolete. The patch removes this job from both GitHub Actions and GitLab CI workflows, reducing redundancy while preserving identical test coverage.

Key technical details: the patch updates `test_detect_ref_format()` in `t/test-lib-functions.sh` to fall back to `GIT_TEST_BUILTIN_REF_STORAGE_FORMAT` (queried from `git version --build-options`) when `GIT_TEST_DEFAULT_REF_STORAGE_FORMAT` is unset. It also updates `t/test-lib.sh` to export `GIT_DEFAULT_REF_STORAGE_FORMAT` with the same fallback logic. The changes are mechanical and affect only test infrastructure, with no on-disk format or user-visible behavior changes.

The patch is uncontroversial and part of a well-reviewed series. Earlier feedback from Phillip Wood and Jeff King endorsed the broader consolidation effort, and this patch specifically removes redundancy while improving test coverage consistency. The series is likely to be merged as-is, pending Junio C Hamano’s final confirmation.
