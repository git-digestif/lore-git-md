This is the sixth patch in Patrick Steinhardt’s seven-patch CI/build system cleanup series (v2). It restores test coverage for non-Rust builds by adding `NO_RUST=Yes` to the `linux-asan-ubsan` job in `ci/lib.sh`, targeting a glibc-based environment to complement the existing musl-based coverage on Alpine Linux. The change is a direct response to the April 2026 default-enable-Rust commit (32d5b90590), which removed non-Rust test coverage from all but the Alpine Linux job.

The patch is a one-line modification to `ci/lib.sh`, appending `NO_RUST=Yes` to the `MAKEFLAGS` assignment for the `linux-asan-ubsan` job. The rationale is twofold: (1) the job’s focus on memory safety makes it a logical place to test C code without Rust’s built-in memory safety guarantees, and (2) the job uses glibc, providing coverage on a different libc than the Alpine Linux job (musl). The change is uncontroversial and aligns with earlier reviewer feedback from Phillip Wood, who endorsed disabling Rust for the sanitizer job while acknowledging the balance might shift if Git’s Rust codebase grows more unsafe code in the future.

No new symbols or behavior changes are introduced beyond the `NO_RUST` flag. The patch is mechanical and self-contained, touching only `ci/lib.sh` and preserving the existing `NO_PYTHON` override. It is part of the broader effort to consolidate CI environment variables and ensure consistent test coverage across platforms. The series as a whole has received positive feedback from Jeff King ("obviously good"), Phillip Wood ("nice"), and Toon Claes ("noncontroversial and good"), and this patch is likely to be merged without further debate.

Key context for follow-up discussion: the patch addresses a gap created by the default-enable-Rust commit, and the choice of `linux-asan-ubsan` reflects both its glibc environment and its focus on memory safety. The patch does not resolve the broader tension between developer ergonomics (local re-testing) and CI reproducibility, but that discussion is closed for this series.
