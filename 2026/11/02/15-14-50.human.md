This is the second patch in Christian Couder’s **v4 series** introducing a new `parse-options` sub-API for early argument scanning. The patch **refactors `parse_long_opt()`** to extract a reusable `lookup_long_opt()` helper, which performs the lookup part of long-option parsing without side effects (no `get_value()`, `die()`, or `error()` calls). This prepares the ground for the core API (`early_scan_options()`) in patch 3/4, which will reuse this helper to scan arguments early while maintaining consistency with `parse_options()`.

The refactoring is **mechanical and behavior-preserving**: exact matches are still preferred, abbreviations are still rejected when disallowed, and the ambiguity error message is unchanged. The new `lookup_long_opt()` function returns an enum (`LONG_OPT_EXACT`, `LONG_OPT_ABBREV`, `LONG_OPT_AMBIGUOUS`, or `LONG_OPT_UNKNOWN`) and populates output parameters (`found`, `other`, `stuck`) to describe the match. The original `parse_long_opt()` is rewritten as a thin wrapper around `lookup_long_opt()`, using a `switch` statement for clarity (addressing Kaartic Sivaraam’s feedback from v3).

The patch touches only `parse-options.c` and adds no new functionality—it’s a pure refactoring. The extracted helper is **well-documented** with a detailed comment explaining its return values and output parameters. This is a **clean, uncontroversial change** that directly supports the series’ goal of replacing hand-rolled early scans with a reusable API. The series as a whole is **ready for `next`**, and this patch is a necessary stepping stone toward the bugfix in `git fast-import` (patch 4/4).
