The patch addressed a long-standing regression (since Git 2.31) where high-level commands like `` `git branch -d` `` and `` `git tag -d` `` reported all-zero OIDs in the reference-transaction hook, breaking external tools that rely on the hook to monitor ref changes. The v6 iteration moved the fix to the transaction hook layer, resolving architectural concerns raised in earlier versions while preserving the bulk-deletion performance optimization. Despite its readiness and alignment with prior feedback, the patch stalled due to lack of reviewer engagement, a common fate for patches that do not attract timely attention.

Key details for future reference:
- **Subsystems**: `refs`, reference-transaction hook.
- **Commands affected**: All ref-modifying commands (`` `git branch -d` ``, `` `git tag -d` ``, `` `git remote prune` ``, `` `git fetch --prune` ``, `` `git push` ``, etc.).
- **Backends**: files, reftable.
- **Introducing commit**: `8198907795` (Git 2.31).
- **New mechanism**: On-demand resolution of old OIDs in the transaction hook layer, stored in `hook_old_oid` and `hook_old_target` fields.
- **Test coverage**: Updated regression tests in `t/t1416-ref-transaction-hooks.sh` verify hook payloads for all ref-modifying commands, symbolic refs, concurrent updates, and UI behavior.
- **Performance trade-off**: Bulk-deletion optimization preserved, but on-demand resolution may add latency for large batches (accepted as a reasonable trade-off by Patrick Steinhardt).
- **Documentation**: Updated `githooks.adoc` to clarify hook behavior.
