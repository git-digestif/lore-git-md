This is a follow-up in the ongoing documentation series that aligns Git’s terminology around "root refs" (like `HEAD`, `ORIG_HEAD`) and "pseudorefs" (`FETCH_HEAD`, `MERGE_HEAD`). The series itself is uncontroversial and nearly ready for merging, but Julia Evans raises a natural question: if both `ORIG_HEAD` (a root ref) and `MERGE_HEAD` (a pseudoref) appear as plain files in `.git/`, what *is* the difference?

Andy Koppe’s reply clarifies the distinction in operational terms. Root refs can be stored in reftables, contain only a single hash or symbolic ref, and are writable via `git update-ref` and listable via `git for-each-ref`. Pseudorefs are always plain files, may contain multiple hashes (plus metadata in `FETCH_HEAD`), and are only modified by the commands that create them (`git fetch`, `git merge`). Both types can be used as arguments to commands like `git log` or `git diff`, which is why the distinction is subtle for users. The answer does not change the series’ content, but it highlights a gap in the documentation: the glossary and man pages could use a short note explaining the storage and operational differences to avoid confusing readers who inspect `.git/` directly.
