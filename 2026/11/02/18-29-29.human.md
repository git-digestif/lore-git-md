This is the third patch in Jasper Mayone’s four-patch series (v4) that extends Git’s `%(worktreepath)` atom to report the worktree path for branches being rebased or bisected. The patch directly addresses a long-standing inconsistency: while `git worktree add` and `git branch -d` already treat such branches as "checked out," `git for-each-ref --format='%(worktreepath)'` and `git worktree list` show them as detached, leaving users with no way to identify which worktree is actively working on the branch.

The implementation is clean and well-motivated. Instead of duplicating logic from `branch.c`, the patch exposes a new helper function, `branch_checked_out_worktree()`, which looks up the branch in the list of checked-out branches that `prepare_checked_out_branches()` already maintains. This avoids code duplication and ensures consistency with existing Git behavior. The helper explicitly excludes branches that `rebase --update-refs` will move but are not currently checked out, which is the correct behavior for `%(worktreepath)`—those branches are protected from deletion or checkout, but no worktree is actively working on them.

The patch also makes a **breaking change** that aligns `%(worktreepath)` with its name and purpose: it no longer prints the `git_dir` of bare repositories. This is documented in the commit message and the updated `git-for-each-ref(1)` man page, and the tests verify the new behavior. The change is justified—`%(worktreepath)` should only report paths to actual worktrees, not bare repositories—but scripts that relied on the old behavior will need to be updated.

The tests are thorough, covering rebasing, bisecting, interactive rebase with an edit stop, `rebase --update-refs`, and bare repositories. They verify both the new behavior (e.g., `%(worktreepath)` now returns the correct path for a rebasing branch) and backward-compatibility edge cases (e.g., branches that `rebase --update-refs` will move are excluded, and detached-HEAD rebases are ignored).

This patch is part of a larger effort to improve worktree safety and usability, and it looks ready for integration. The only open question is whether any scripts rely on the old behavior (empty `%(worktreepath)` for rebasing/bisecting branches or the bare-repository `git_dir` output), but the commit message explicitly asks about this, signaling awareness of the compatibility risk. The implementation is solid, the tests are comprehensive, and the change addresses a real gap in Git’s worktree handling.
