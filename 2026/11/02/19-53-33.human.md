This is a **contributor housekeeping** follow-up in the bash-completion script thread. Mirko Faina responds to Pablo Sabater’s review of his patch to add `--graph-indent` and `--no-graph-indent` to `git log`’s completion list. The patch itself is uncontroversial and will be updated to place the new options in the command-specific block (`__git_log_gitk_options`) alongside `--graph`, rather than in the shared `__git_log_common_options` list.

The discussion now centers on two broader questions. First, Mirko and Pablo agree that `--graph-lane-limit` (another `--graph`-dependent option) should also be added to the completion script. Second, they explore whether the completion system should suppress `--graph`-dependent options unless `--graph` is already on the command line. Mirko notes that the current `parse-options.h` machinery does not support such conditional logic, and suggests that implementing it in the bash-completion script might not be worthwhile unless the core Git code adopts a similar approach. This remains an open design question, but it does not block the current patch.

The reroll will include both `--graph-indent` and `--graph-lane-limit`, placed in the same command-specific block as `--graph`. The patch is small, well-motivated, and unlikely to be controversial.
