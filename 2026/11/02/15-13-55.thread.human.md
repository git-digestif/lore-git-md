This thread is about establishing a formal governance document for the Git project, making its long-standing but implicit rules and roles explicit for newcomers and future reference. Antonin Delpeuch posted the initial draft of `Documentation/Governance.adoc`, which describes the current governance structure—including the Project Leadership Committee (PLC), maintainer roles, and security processes—without proposing changes.

Junio C Hamano, the project’s maintainer, has now reviewed the draft and raised several substantive points. He suggests line-wrapping improvements to the AsciiDoc source for easier editing and discussion, questions whether the document’s scope should explicitly include community channels like Discord and IRC, and proposes referencing Git for Windows more formally. Junio also clarifies key governance details: the project’s relationship with the Software Freedom Conservancy is informal, there are no established processes for PLC membership changes or security list access, and role succession (such as for localization maintainers) happens organically. His feedback narrows some of the document’s open questions—such as how to handle PLC departures or security list invitations—by providing authoritative answers, though others, like the scope definition, remain unresolved. The document is still in its first iteration, and no decisions have been made about merging it. Further input, particularly from Johannes Schindelin regarding his role in the security team, is expected.
