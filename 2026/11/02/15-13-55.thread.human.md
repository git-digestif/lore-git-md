This thread is about documenting Git’s governance. Antonin Delpeuch has posted a draft `Documentation/Governance.adoc` file that lays out the project’s current roles (maintainer, Project Leadership Committee, security team, localization maintainers, website maintainers) and decision-making processes. The patch is explicitly a work in progress, with several open questions—marked as “admonitions”—about the project’s scope, how PLC members can step down, and access to the security mailing list. Antonin frames this as an effort to make long-standing but implicit conventions explicit for newcomers and to provide a foundation for future discussions about potential changes.

The draft avoids prescribing new rules and instead aims to reflect the status quo, drawing on past mailing list discussions and external policies. It also updates the build system to include the new file. Antonin notes that the unresolved questions must be addressed before the patch can be merged and invites feedback on both the content and the framing of the document. This patch is part of a larger conversation about governance that has included threads on voting processes and AI contribution policies. So far, the thread is just getting started, with no reviews or decisions yet.
