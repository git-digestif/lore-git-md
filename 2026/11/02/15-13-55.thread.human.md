This thread is about establishing a formal governance document for the Git project, making its long-standing but implicit rules and roles explicit for newcomers and future reference. Antonin Delpeuch posted an initial draft (`Documentation/Governance.adoc`) as an RFC, and the discussion has since focused on refining details without changing how the project actually operates.

Junio C Hamano, the project maintainer, provided substantive feedback that Antonin has largely addressed in preparation for a v2 patch. Key clarifications include the project’s relationship with the Software Freedom Conservancy (now described as "member project" and "fiscal sponsor"), the process for joining the security list ("ask for membership"), and the lack of a formal succession process for localization maintainers. Jiang Xin, the current localization maintainer, recently chimed in to confirm that Junio already has maintainer access to the `git-l10n` GitHub organization, making a handoff straightforward if needed. This resolves one of the open questions about how permissions would be transferred.

The remaining loose ends center on who moderates the project’s communication channels (Discord and IRC) and how the security list operates in practice—Johannes Schindelin has been asked for input on the latter. The document also leaves voting procedures and the PLC’s role in moderating communication channels unresolved. Antonin is actively engaging stakeholders to fill these gaps before sending a revised version. No code or merge decisions are involved; this is purely about documenting existing practices.
