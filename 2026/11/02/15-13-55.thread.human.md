This thread is about documenting Git’s governance structures in a new `Documentation/Governance.adoc` file. Antonin Delpeuch posted an initial RFC to make the project’s implicit governance conventions explicit, covering roles, decision processes, and security procedures. Junio C Hamano has provided detailed feedback, much of which Antonin has incorporated into a forthcoming v2 patch.

The discussion has clarified some key points: the Software Freedom Conservancy’s role as a fiscal sponsor, the informal process for security mailing list access, and the lack of formal procedures for localization maintainer transitions. However, several questions remain unresolved. Who moderates IRC and Discord channels—and should the PLC oversee them? How exactly are security list invitations managed? Johannes Schindelin has been looped in to clarify his role in the security team, which may help refine that section. Junio’s latest email leaves these operational details open, suggesting they may need input from other stakeholders before the next revision.

The document itself is shaping up as a reflection of current practice rather than a prescriptive change, though it has already surfaced ambiguities that the project may need to address. No merge timeline is in sight; the series is still in the RFC phase, with Antonin actively revising based on feedback. If you’re following this thread, the next version should include clearer language on the SFC’s role and possibly new sections on communication channels, but the unresolved questions about moderation and security mechanics will likely persist until more voices weigh in.
