This thread is about establishing a formal governance document for the Git project, making its long-standing but implicit rules and roles explicit for newcomers and future reference. Antonin Delpeuch posted the first version of `Documentation/Governance.adoc`, a draft that describes current governance structures—such as the Project Leadership Committee (PLC), maintainer roles, and security processes—without proposing changes.

Junio C Hamano provided detailed feedback, clarifying how the project actually operates: for example, that there’s no formal process for PLC membership changes, that the security mailing list is invitation-only, and that the Software Freedom Conservancy’s role is limited to financial oversight. Antonin has now responded, incorporating Junio’s corrections and refining the document’s scope. He’s added a section on communication channels (Discord, IRC) but kept Git for Windows out of scope, as it has its own governance. He’s also reached out to Johannes Schindelin to clarify his role in the security team, turning some of the abstract documentation into concrete operational details.

The document is still a draft, and several questions remain open: who controls the security mailing list, how localization maintainers manage permissions, and whether the PLC should moderate communication channels. Antonin plans to post a second version once these points are resolved, but further input from stakeholders like Johannes will be needed before the document can be finalized. The thread is collaborative, treating the governance document as a living reflection of how the project works rather than a prescriptive set of rules.
