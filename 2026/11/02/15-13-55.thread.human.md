This thread is about documenting Git’s governance processes in a new `Documentation/Governance.adoc` file. Antonin Delpeuch posted an initial RFC patch to make the project’s implicit governance conventions explicit, covering roles, decision procedures, and security processes. The document is intended to reflect the current status quo rather than introduce changes, but it has surfaced several ambiguities—particularly around communication channel moderation, security list mechanics, and voting procedures.

Junio C Hamano and Jiang Xin provided substantive feedback, which Antonin has largely addressed in preparation for a v2 patch. Key refinements include clarifying the Software Freedom Conservancy’s role as a “member project” and “fiscal sponsor,” formalizing the security list access process (“ask for membership”), and confirming that localization maintainer succession is technically straightforward (Junio already has access to the `git-l10n` GitHub organization). The unresolved questions remain: who moderates Discord/IRC channels, how the security team operates in practice (Johannes Schindelin’s input is still pending), and whether the Project Leadership Committee oversees communication channels or voting procedures.

The series is still in the RFC phase, with no merge status reported. Antonin is actively gathering input on the remaining open questions before sending the next revision. The document touches only the documentation subsystem, with no code or test changes involved.
