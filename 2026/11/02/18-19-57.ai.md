This is a documentation-focused follow-up in the ongoing terminology cleanup series that aligns Git’s glossary, man pages, and code comments with the 2024 distinction between "root refs" (HEAD, ORIG_HEAD, etc.) and "pseudorefs" (FETCH_HEAD, MERGE_HEAD). Julia Evans, the author of the pedagogical `gitdatamodel.adoc` guide, asks a clarifying question about the on-disk representation of these two categories: while both ORIG_HEAD (a root ref) and MERGE_HEAD (a pseudoref) appear as plain files in `.git/`, the glossary and documentation describe them as stored differently. The question is not a review objection but a request for deeper technical context to ensure the documentation remains accurate and pedagogically sound.

The thread remains uncontroversial; no behavioral changes are proposed, and the series is otherwise ready for merging. Julia’s question highlights a potential gap in the documentation’s explanation of the storage distinction, which could be addressed in a future patch or follow-up discussion. The series itself does not modify the on-disk format or behavior, so this inquiry does not block its progress.
