This is a **revised API refactoring and bugfix series** introducing `early_scan_options()`, a new `parse-options` sub-API for safely scanning command-line arguments early. The v4 series is a **streamlined version** of v3, now down to 4 patches (from 6), and addresses all remaining feedback from Junio, Kaartic Sivaraam, and Cynthia Uche. The series is **ready for `next`**, with the `git fast-import` bugfix (patch 4/4) and preparatory refactorings (1/4, 2/4) now uncontroversial. The core API (3/4) has been improved to include validation checks and clearer documentation, resolving the last substantive concerns.

The goal remains the same: replace fragile hand-rolled early argument scans in Git commands with a reusable, consistent API that handles negated options, unambiguous abbreviations, and aliases the same way `parse_options()` does. The series fixes a real bug in `git fast-import` where `--allow-unsafe-features` was silently ignored when preceded by `--depth 5`, causing the command to refuse unsafe features from the input stream. The API is designed to err on the side of caution—stopping at short options, unknown options, ambiguous abbreviations, and low-level callbacks—to avoid misinterpreting option values.

Key changes since v3:
- **Patch 2/4**: Replaced an `if`-statement chain with a `switch` in `parse_long_opt()` for better readability, addressing Kaartic’s code clarity suggestion.
- **Patch 3/4**: Added a `parse_options_check()` call inside `early_scan_options()` to validate options before scanning, preventing invalid uses of `PARSE_OPT_EARLY` (e.g., short options, `OPTION_SUBCOMMAND`). This resolves Kaartic’s validation concern.
- **Patch 3/4**: Improved API documentation to clarify that the `option` pointer passed to the callback is ephemeral and must not be retained, addressing Kaartic’s ephemeral pointer concern.
- **Patch 4/4**: Enhanced the comment above `early_scan_options()` in `fast-import.c` to explain why `EARLY_SCAN_STOP_AT_NON_OPTION` is passed, incorporating Cynthia Uche’s feedback. Added a new test to verify that unsafe features are refused when `--allow-unsafe-features` follows a non-option argument.

The series touches `parse-options.h`, `parse-options.c`, `fast-import.c`, and adds comprehensive test coverage in `t/t0040-parse-options.sh` and `t/t9300-fast-import.sh`. The new API is exercised by a test helper (`test-parse-options --early-scan-options`) and includes edge cases like stuck/separate values, negated options, and ambiguous abbreviations. The `git fast-import` conversion now aligns with `parse_options()` behavior in all cases, including abbreviations (e.g., `--allow-unsafe` is accepted unless `GIT_TEST_DISALLOW_ABBREVIATED_OPTIONS` is set).

The v4 redesign maintains the deliberate design choice of requiring callers to handle argument skipping (`--option value`), but the improved validation and documentation mitigate the usability concerns raised in v2. The series is **well-tested, documented, and ready for integration**, with no unresolved technical issues. Commands with hand-rolled early scans (e.g., `git bisect`, `git rev-parse`) may adopt this API in future work.
