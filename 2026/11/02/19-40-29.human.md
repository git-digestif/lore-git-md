This is a bugfix patch for submodule diff headers, part of the Git libification effort. The patch ensures commit abbreviations in submodule diffs are checked against the submodule's object database rather than the superproject's, preventing potential collisions where the same abbreviated ID could refer to different objects in the two repositories.

The fix itself is small and surgical: it replaces `strbuf_add_unique_abbrev()` with `strbuf_repo_add_unique_abbrev()` in `submodule.c`, using the submodule repository when available and falling back to `o->repo` (from diff options) otherwise. This reduces reliance on the global `the_repository` while fixing the correctness issue. The accompanying test constructs a scenario with colliding abbreviated commit IDs between superproject and submodule, verifying the output uses the correct (submodule) abbreviation.
