This is the **core API patch** in Christian Couder’s four-patch series introducing `early_scan_options()`, a new `parse-options` sub-API for early argument scanning. The patch is now in its **fourth iteration (v4)** and addresses all remaining feedback from Kaartic Sivaraam and others.

The patch adds `early_scan_options()`, a function that scans command-line arguments for options marked with `PARSE_OPT_EARLY` before the full `parse_options()` call. This replaces fragile hand-rolled scans in commands like `git fast-import`, fixing a real bug where `--allow-unsafe-features` was silently ignored when preceded by `--depth 5`. The API reuses `parse-options` internals (`lookup_long_opt()`) to handle negated options, unambiguous abbreviations, and aliases consistently with `parse_options()`. It stops at short options, unknown options, ambiguous abbreviations, low-level callbacks, `--`, and `--end-of-options` to avoid misinterpreting option values.

In this email, Christian confirms two key improvements in v4. First, he adds a `parse_options_check()` call inside `early_scan_options()` to validate options before scanning, preventing invalid uses of `PARSE_OPT_EARLY` (e.g., short options or `OPTION_SUBCOMMAND`) even if the caller invokes the function before `parse_options_start()`. This addresses Kaartic’s concern about silent misbehavior or crashes in edge cases. Second, he clarifies the API documentation to warn callers that the `option` pointer passed to the callback is ephemeral and must not be retained after the scan completes, mitigating the risk of use-after-free bugs.

The patch is **well-crafted, thoroughly tested, and uncontroversial**. It includes 28 new tests in `t/t0040-parse-options.sh` covering edge cases like stuck/separate values, negated options, ambiguous abbreviations, and non-options. The series as a whole is **ready for `next`**, with Junio and other reviewers signaling approval. The only remaining work is broader adoption in other commands (e.g., `git bisect`, `git rev-parse`), but that is explicitly out of scope for this series. If you care about command-line argument parsing or have encountered bugs in early option handling, this patch is worth reviewing—it’s a clean, reusable solution to a long-standing problem.
