This is a documentation-focused follow-up in the ongoing effort to clarify Git’s terminology around "root refs" and "pseudorefs." The email is a direct reply to Julia Evans’s questions about pseudoref behavior, specifically whether they may contain multiple hashes, how commands handle such cases, and whether `FETCH_HEAD` and `MERGE_HEAD` are the only pseudorefs. Andy Koppe responds by pointing to the updated glossary entry in the v2 series, which now explicitly addresses these points: it lists `FETCH_HEAD` and `MERGE_HEAD` as the only pseudorefs, notes that they may contain multiple object IDs (with metadata for `FETCH_HEAD`), and clarifies that commands like `git log` use the first object ID when multiple entries are present.

The exchange is narrow but substantive for documentation purposes. It does not introduce new code changes or challenge the series’ direction, but it directly informs how the glossary and pedagogical documentation (e.g., `gitdatamodel.adoc`) should explain pseudorefs to users. The updated glossary entry in v2 now provides the technical precision Julia requested, making the distinction between root refs (single object ID, ref-like storage) and pseudorefs (multiple object IDs, file-backed, metadata-rich) immediately clear. This refinement is likely to be incorporated into the final version of the series, improving clarity for users who encounter pseudorefs in practice.
