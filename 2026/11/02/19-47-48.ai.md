This is a reply in the ongoing documentation-terminology thread that clarifies the technical distinction between "root refs" and "pseudorefs" for a pedagogical audience. Andy Koppe responds to Julia Evans’s question about why the glossary and documentation describe root refs (e.g., ORIG_HEAD) and pseudorefs (e.g., MERGE_HEAD) as stored differently when both appear as plain files in `.git/`. The answer is substantive: root refs can be stored in reftables (not just files), contain only a single hash or symbolic ref, and are supported by `git update-ref` and `git for-each-ref`, whereas pseudorefs are always file-backed, may contain multiple hashes (with additional metadata in FETCH_HEAD), and are only modified by their respective commands (`git fetch`, `git merge`). Both can be used as arguments to commands like `git log` or `git diff`, which is their main commonality. This clarification fills a gap in the documentation and will help future readers understand the operational constraints and storage flexibility implied by the terminology. The reply does not propose code changes but provides the technical context needed to keep the documentation accurate and pedagogically sound.
