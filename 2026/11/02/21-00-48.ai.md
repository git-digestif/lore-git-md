This is a documentation-focused discussion in the ongoing series to align Git’s terminology around "root refs" and "pseudorefs." Julia Evans, a well-known technical writer, follows up on Andy Koppe’s earlier clarification about the technical distinctions between the two concepts. Her questions are aimed at refining the pedagogical documentation: she suggests adding "may contain multiple hashes" to the pseudoref definition to make the difference from root refs immediately clear to users, asks whether commands like `git log` use the first hash when a pseudoref contains multiple entries, and seeks confirmation that FETCH_HEAD and MERGE_HEAD are the only pseudorefs.

The exchange is substantive but narrow: it does not propose code changes or challenge the series’ direction, but it directly informs how the glossary and `gitdatamodel.adoc` should explain pseudorefs. Andy’s earlier reply already established that root refs (e.g., ORIG_HEAD) can be stored in reftables and contain only a single hash, while pseudorefs are always file-backed and may contain multiple hashes with additional metadata. Julia’s follow-up sharpens that distinction by highlighting FETCH_HEAD as a user-facing example and probing the behavior of commands when pseudorefs contain multiple hashes. The answers to these questions will likely be incorporated into the next revision of the documentation, making the series more accessible to users who encounter pseudorefs in practice. No controversy or technical disagreement is evident; this is a collaborative effort to improve clarity.
