This is the sixth patch in Patrick Steinhardt’s seven-patch CI/build system cleanup series. It restores test coverage for non-Rust builds by adding `NO_RUST=Yes` to the `linux-asan-ubsan` job in `ci/lib.sh`. The change is a direct response to the April 2026 default-enable-Rust commit (32d5b90590), which removed the last non-Rust CI job (Alpine Linux with musl libc).

The patch is a single-line tweak that disables Rust for the address/undefined sanitizer job. The rationale is pragmatic: since Rust is memory-safe by design, the sanitizer job is more valuable when testing C code. The choice of `linux-asan-ubsan` is deliberate—it uses glibc, avoiding the musl-specific issues that led to Rust being disabled on Alpine in the first place. The commit message is clear and well-motivated, and the change itself is uncontroversial, aligning with earlier reviewer feedback that endorsed restoring non-Rust coverage.

This patch is part of a broader effort to consolidate CI environment variables and improve maintainability. It follows the same pattern as earlier patches in the series: mechanical, targeted, and justified by a specific gap in test coverage. The series as a whole has received positive feedback, and this patch is likely to be merged without further discussion. If you care about CI hygiene or Rust-related test coverage, this is a small but meaningful improvement worth noting.
