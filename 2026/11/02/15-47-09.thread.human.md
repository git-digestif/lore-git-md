This thread is about a bugfix to `git rev-list`'s connectivity check, which currently follows replacement refs while other Git commands (`fsck`, `prune`, etc.) ignore them. This inconsistency can cause packs to pass connectivity checks but later fail `fsck` if the original objects are missing. Kristofer Karlsson proposed a patch to align `rev-list` with the established behavior by ignoring replacements during connectivity checks.

Junio C Hamano endorsed the core idea but raised a conceptual question: instead of ignoring replacements entirely, should the check ensure *both* the original *and* replacement objects exist? This would treat replacements as additional tips in the connectivity graph, ensuring all reachable objects are present. Junio described this as a separate issue for later but framed it as a potential point of discussion. The patch itself remains unchanged—it adds a `--connectivity-check` flag to `rev-list`, updates `tree-verify.c`, and adjusts the test suite to reflect the new behavior.

The thread is still open, with two clear positions: Kristofer’s original proposal (ignore replacements for consistency) and Junio’s alternative (check both originals and replacements). No other participants have weighed in yet. The patch is small, well-motivated, and touches only three files, making it easy to iterate on if the design shifts. The test coverage ensures regression protection.
