This thread is about a bugfix to make `git rev-list`'s connectivity check ignore replacement objects, aligning it with the behavior of other Git commands like `fsck` and `prune`. The inconsistency could cause packs to pass the connectivity check (because replacements were visible) but later fail `fsck` (because replacements are ignored and the original objects are missing). The patch, authored by Kristofer Karlsson, adds a `--connectivity-check` flag to `git rev-list` that ignores replacement refs and updates related code and tests.

The core design question—whether the connectivity check should ignore replacements or verify both original and replacement objects—has been resolved in favor of ignoring replacements. Junio C Hamano initially raised the alternative but has now endorsed the current approach, confirming that replacement objects are stored as regular refs, so their reachability is already covered by ordinary connectivity checks. Patrick Steinhardt's reviews reinforced the design, though he raised concerns about potential workflow breakage from a test change in `t5413` and the scoped removal of a flag in `tree-verify.c`. Kristofer clarified that the test change was intentional and the flag removal is correctly scoped.

The patch is now under review for these technical details rather than its design. The main open question is whether the test change in `t5413` could break existing workflows that rely on the edge case where replacements mask missing objects. An unrelated bug in `mktree` was also noted but is not addressed in this patch. The thread is nearing conclusion, with only implementation details remaining.
