This thread is about a bugfix to make `git rev-list`'s connectivity check ignore replacement refs, aligning it with other Git commands like `fsck` and `prune`. The patch, authored by Kristofer Karlsson, adds a `--connectivity-check` flag to `rev-list` and modifies `tree-verify.c` to drop the `OBJECT_INFO_LOOKUP_REPLACE` flag. The core design—ignoring replacements during connectivity checks—has broad support, including from Junio Hamano and Patrick Steinhardt, though Junio initially suggested an alternative approach.

The patch is now under review with two key technical concerns. First, the test change in `t5413` was intentional, meaning the new behavior could break workflows that rely on replacement objects masking missing objects. Second, the removal of `OBJECT_INFO_LOOKUP_REPLACE` in `tree-verify.c` is confirmed to be scoped correctly, as the file is only used by `rev-list --connectivity-check=incremental`. However, Kristofer notes an unrelated issue in `mktree` where replacements are followed during validation but original OIDs are written to the tree, potentially allowing missing objects to slip through. Documentation in `git-replace.adoc` also needs updating to reflect the new exception for `rev-list --connectivity-check`.

Patrick Steinhardt’s reviews raised these concerns, while Karthik Nayak pointed out the documentation inconsistency. The patch remains narrowly focused on the connectivity check, avoiding broader changes to the replacement mechanism. If merged, it will resolve a long-standing inconsistency but may disrupt edge-case workflows.
