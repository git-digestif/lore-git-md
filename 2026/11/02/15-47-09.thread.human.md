This thread is about a bugfix to make `git rev-list --connectivity-check` ignore replacement objects, aligning it with other Git commands like `fsck` and `prune`. The patch itself is under review and has converged on its core design, with Junio C Hamano and Patrick Steinhardt endorsing the approach after initial discussion.

The latest email clarifies a documentation point raised by Karthik Nayak. Kristofer Karlsson argues that the existing wording in `git-replace.adoc`—which claims "pack transfer" ignores replacements—was already inaccurate, since the connectivity check (part of pack transfer) previously *did* follow replacements. He defends the current text as illustrative rather than exhaustive, noting other commands (like `index-pack` and `commit-graph`) also ignore replacements but aren’t listed. No changes to the patch or documentation are proposed; the discussion is purely about whether the text needs updating to reflect the new behavior.

The patch remains technically sound, with two lingering concerns: (1) the test change in `t5413` could break workflows relying on the old edge case (accepting commits with missing original trees if replacements exist), and (2) `git-replace.adoc` still doesn’t explicitly mention `rev-list --connectivity-check` as an exception. The unrelated `mktree` bug (following replacements during validation but writing original OIDs) is noted but not addressed here. Key participants—Kristofer (author), Junio, and Patrick—agree on the fix’s direction, with only surface-level documentation questions remaining.
