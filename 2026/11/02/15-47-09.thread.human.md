This thread is about a bugfix patch from Kristofer Karlsson that makes `git rev-list --connectivity-check` ignore replacement objects, aligning its behavior with other Git commands like `fsck` and `prune`. The goal is to prevent a scenario where a pack passes the connectivity check (because replacements are visible) but later fails `fsck` (because replacements are ignored and the original objects are missing).

The patch is under review and has effectively converged on its design: the connectivity check should ignore replacements, as replacement objects are stored as regular refs and their reachability is already validated during fetch or push. Junio C Hamano endorsed the core idea, and Patrick Steinhardt’s earlier review reinforced the patch’s approach, noting that the connectivity check’s scope is limited to validating transferred objects, not policing locally created refs. The implementation adds a `--connectivity-check` flag to `git rev-list`, modifies `tree-verify.c` to drop the `OBJECT_INFO_LOOKUP_REPLACE` flag, and updates test `t5413` to expect rejection when replacements mask missing objects.

The latest email from Patrick Steinhardt raises two technical concerns. First, he questions whether the test change in `t5413`—which now expects the connectivity check to reject a commit with an incomplete original tree but a complete replacement—was originally written to accommodate a real-world edge case. If so, the new behavior might break existing workflows. Second, he notes that removing `OBJECT_INFO_LOOKUP_REPLACE` from `tree-verify.c` affects other code paths (e.g., `git fsck`, `git index-pack`) and asks whether the author audited all callers to ensure consistency. These concerns are diagnostic, not design-related, and focus on potential side effects rather than the patch’s core premise.

The thread is otherwise converged, with no further objections to the implementation or design. The only remaining loose end is a documentation inconsistency noted by Karthik Nayak: `git-replace.adoc` still claims that all commands except reachability traversals (prune, pack transfer, fsck) use replacements by default, but `rev-list --connectivity-check` now ignores them. This needs updating to reflect the new exception.
