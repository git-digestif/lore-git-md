This thread is about a bugfix to `git rev-list`'s connectivity check. Kristofer Karlsson noticed that while most Git commands ignore replacement objects (as decided in 2009), the connectivity check still follows them. This inconsistency can cause `rev-list --connectivity-check` to accept a pack as complete when later operations like `fsck` would reject it because they ignore replacements and see missing original objects.

The patch makes `rev-list` ignore replacements during connectivity checks, aligning it with the rest of Git. It updates both full and incremental checks, removes the `OBJECT_INFO_LOOKUP_REPLACE` flag from `tree-verify.c`, and fixes a test (`t5413`) that previously expected the wrong behavior. The commit message explains the edge case (a replace ref pointing to an object not yet local) and why shallow boundaries aren't affected. So far, this is a solo patch with no replies—it's framed as a question ("should connectivity checks ignore replacements?") rather than a settled decision, so discussion may still be coming.
