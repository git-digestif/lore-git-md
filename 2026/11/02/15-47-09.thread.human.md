This thread is about a bugfix patch from Kristofer Karlsson that makes `git rev-list --connectivity-check` ignore replacement refs, aligning its behavior with other Git commands like `fsck` and `prune`. The inconsistency being fixed could cause packs to pass connectivity checks while later failing `fsck` because replacements mask missing objects.

The patch itself is straightforward: it adds a `--connectivity-check` flag to `rev-list` that skips replacements, modifies `tree-verify.c` to drop the `OBJECT_INFO_LOOKUP_REPLACE` flag, and updates a test to verify the new behavior. Junio C Hamano endorsed the core idea but raised a design question: whether the connectivity check should instead verify *both* original and replacement objects, treating replacements as additional tips in the graph. Kristofer responded that replacements are stored as regular refs, so their reachable objects should already be covered by ordinary connectivity checks, but the question remains open.

Karthik Nayak’s recent review is a minor documentation nit: the patch updates `rev-list-options.adoc` to note the new behavior, but `git-replace.adoc` still claims all commands except reachability traversals use replacements by default. This should be updated to include `rev-list --connectivity-check` as an exception. The review doesn’t engage with the design discussion, so the open question about whether to ignore replacements or verify both remains unresolved. The patch is still under review, with no objections to the implementation itself.
