This is a bugfix patch series (v4) targeting submodule diff header correctness, part of the Git libification effort. The series now consists of two patches: the original fix (unchanged from v3) and a new test patch that makes the existing test hash-agnostic by using `test_oid_cache` instead of hardcoded SHA-1 commit IDs.

The core issue remains the same: commit abbreviations in submodule diff headers were checked against the superproject's object database, risking collisions where the same abbreviated ID could refer to different objects in the submodule and superproject. The fix ensures abbreviations use the submodule's object database when available, falling back to `o->repo` (from the diff options) rather than the global `the_repository`.

The new test patch addresses Junio's non-blocking suggestion from v3, replacing hardcoded SHA-1 values with `test_oid_cache` to ensure the test works with both SHA-1 and SHA-256 repositories. This is a clean follow-up that doesn’t alter the fix itself but improves test robustness. The series is now technically complete, with all feedback incorporated and no open questions.
