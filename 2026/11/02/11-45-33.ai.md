This is a **bugfix and performance patch** targeting the object quarantine mechanism in `receive-pack`. The v2 patch replaces the v1 proof-of-concept with a more robust solution that avoids fragile path comparisons by repurposing `GIT_QUARANTINE_ENVIRONMENT` to carry the parent repository’s object directory path. The change is endorsed by Junio C Hamano and Jeff King as a pragmatic short-term fix for a measurable performance regression.

The patch modifies the ODB layer (`odb/source-files.c`) to mark alternates as "borrowed" (from another repository) or not, using two heuristics: the alternate’s path is either the repository’s own `<commondir>/objects`, or the parent of `GIT_QUARANTINE_PATH` (since quarantines are created directly inside the object directory). Only borrowed alternates contribute refs to `--alternate-refs`. This prevents the connectivity check from redundantly listing the repository’s own refs—including hidden ones—during pushes, addressing the regression documented in the perf test (`p5552-push-hidden-refs.sh`).

Key files touched: `odb/source-files.c` (core logic), `odb/source-files.h` (new `borrowed` flag), `Documentation/rev-list-options.adoc` (updated docs), and test files (`t5547-push-quarantine.sh`, `t5618-alternate-refs.sh`, and the new `t/perf/p5552-push-hidden-refs.sh`). The perf test shows a **67.7% speedup** in repositories with 200,000 hidden refs and a **17.6% improvement** even without hidden refs, as the fix eliminates duplicate ref listings.

The patch is **well-tested**, covering edge cases like quarantines outside the commondir and pre-receive hooks. While the parent-path assumption is acknowledged as "icky" by Junio, it is framed as an acceptable trade-off given the existing fragility of the alternate interface. The solution aligns with maintainer preferences for minimal invasiveness, though Justin Tobler’s earlier proposal for an ODB transaction callback remains a potential long-term direction. No objections have been raised to the v2 approach, and the patch is likely to land in `next` pending final feedback from ODB maintainers (Patrick Steinhardt, Justin Tobler).
