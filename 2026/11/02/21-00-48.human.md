This is a documentation-focused discussion in the ongoing effort to clarify Git’s terminology around "root refs" and "pseudorefs." Julia Evans, a well-known technical writer, asks for further clarification on the practical differences between these two concepts after reviewing Andy Koppe’s patch series. Her questions—why root refs and pseudorefs appear similarly stored on disk, how commands handle pseudorefs with multiple hashes, and whether FETCH_HEAD and MERGE_HEAD are the only pseudorefs—highlight gaps in the current documentation that could confuse users.

Andy’s response provides the technical context: root refs (like ORIG_HEAD) can be stored in reftables, contain a single hash or symbolic ref, and are supported by `git update-ref` and `git for-each-ref`, while pseudorefs (like FETCH_HEAD and MERGE_HEAD) are always file-backed, may contain multiple hashes (with FETCH_HEAD including additional metadata), and are only modified by their respective commands. He also confirms that commands like `git log` or `git diff` use the *first* hash when a pseudoref contains multiple entries, and that FETCH_HEAD and MERGE_HEAD are indeed the only pseudorefs in Git.

Julia’s follow-up suggests this clarification—particularly the detail about multiple hashes in pseudorefs—would improve the glossary and pedagogical documentation (`gitdatamodel.adoc`). The discussion is purely about documentation accuracy and does not propose code changes, but it underscores the importance of Andy’s series in making Git’s terminology more accessible. The series itself remains uncontroversial and appears ready for merging, with only minor unresolved nits in one patch.
