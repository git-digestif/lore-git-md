This is a gentle but firm nudge from Junio C Hamano about the v2 patch that fixes a bug in Git’s HTTP authentication layer. The patch—*http: preserve WWW-Authenticate headers on redirect*—has been sitting in `seen` since early June without attracting reviewers, despite Junio’s explicit invitation for broader participation.

The bug itself is straightforward: when Git follows an HTTP redirect, it loses the `WWW-Authenticate` headers from the original response, which breaks authentication for redirect targets that rely on credential helpers (like OAuth2 Bearer tokens). The v2 patch addresses this by introducing a reusable helper, `credential_update_url()`, that preserves the headers across URL updates. The fix is well-motivated, includes a new test in `t/t5563-simple-http-auth.sh`, and touches only two files (`http.c` and `credential.c`). Junio has described it as uncontroversial and easy to review, but so far, no one has stepped up.

Now, Junio is setting a deadline: if no reviewers volunteer in the next few weeks, he will drop the topic from `seen`. This isn’t a rejection—just a pragmatic move to clear space for patches that are getting attention. For anyone casually following Git development, this is a low-effort opportunity to contribute meaningful feedback on a small, self-contained fix. If you’ve ever worked with Git’s HTTP layer or credential helpers, this is your cue.
