This is a reply in the ongoing documentation-terminology thread about "root refs" vs "pseudorefs". Junio C Hamano clarifies Julia Evans’s question about the on-disk representation difference between the two categories. The key technical distinction is that pseudorefs (FETCH_HEAD, MERGE_HEAD) can describe multiple objects and include metadata (e.g., branch names and "not-for-merge" flags), whereas root refs (HEAD, ORIG_HEAD) contain only a single object ID and behave like normal refs except for their location outside the `refs/` hierarchy. Junio illustrates this with an example of FETCH_HEAD’s multi-line format and explains that root refs are treated as real refs by Git’s internals, while pseudorefs are not. The reply also notes that the "root" terminology is a slight misnomer, as Git would technically accept any file under `.git/` as a ref if it contains a valid object ID, but only the project-sanctioned ones (HEAD, ORIG_HEAD, etc.) are officially supported.
