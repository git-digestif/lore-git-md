This is the first patch in Christian Couder’s **v4 series** introducing `early_scan_options()`, a new `parse-options` sub-API for early command-line argument scanning. The patch **refactors existing logic** by extracting the rule that determines whether an option takes an argument into a reusable function, `parse_options_takes_argument()`.

The change is **mechanical and preparatory**: it moves the logic currently open-coded in `show_gitcomp()` into a standalone function in `parse-options.h`/`parse-options.c`. The new function will be used in the next patch to implement `early_scan_options()`, and it also simplifies the completion logic in `show_gitcomp()` by replacing a 13-line `switch`/`if` chain with a single call. The behavior is unchanged—options with `PARSE_OPT_LASTARG_DEFAULT` are still treated as taking an argument (for early scanning purposes) but do not trigger an `=` suffix in completions, preserving the existing UX.

The patch is **uncontroversial** and **ready for integration**; it has no unresolved feedback and is part of a series that is now marked as **ready for `next`** after addressing all prior concerns. The commit message clearly explains the motivation (code reuse for early scanning) and the edge case (`PARSE_OPT_LASTARG_DEFAULT`). No new tests are added here, but the function will be exercised by the test helper introduced in patch 3/4. Files touched: `parse-options.c`, `parse-options.h`.
