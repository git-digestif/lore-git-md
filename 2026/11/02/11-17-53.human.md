This is the fifth patch in Patrick Steinhardt’s seven-patch CI/build system cleanup series. It aligns test behavior with Git’s compiled-in defaults by ensuring the default ref storage format (reftable) is used when breaking changes (e.g., SHA-256) are enabled, rather than hardcoding the "files" backend.

The patch removes the redundant `linux-reftable-sha256` CI job from both GitHub Actions and GitLab CI workflows, as the `linux-breaking-changes` job now automatically exercises reftable when SHA-256 is enabled. It also updates the `test_detect_ref_format()` helper in `t/test-lib-functions.sh` to fall back to the compiled-in default (`GIT_TEST_BUILTIN_REF_STORAGE_FORMAT`) when no explicit override is set, and adds logic in `t/test-lib.sh` to detect and export this default.

The change is small (4 insertions, 8 deletions) and uncontroversial, reflecting the broader series’ goal of reducing duplication and improving maintainability. Reviewers have already endorsed the series as "obviously good," and this patch fits cleanly into that consensus. No new technical concerns are introduced; the patch simply ensures test environments honor Git’s built-in defaults, eliminating an explicit test case that is now redundant.
