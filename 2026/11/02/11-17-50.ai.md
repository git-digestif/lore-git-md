This is the second patch in Patrick Steinhardt’s seven-patch CI/build system cleanup series (v2). It targets a small but concrete redundancy in Git’s CI infrastructure: the `GIT_TEST_USE_SET_E` environment variable, which enables `set -e` behavior in the test suite, is currently set individually for each Linux distribution job (e.g., `almalinux-*`, `debian-*`, `fedora-*`). This patch replaces those per-distribution assignments with a single platform-wide rule, ensuring the variable is set for *all* Linux jobs, including the previously missed `linux32` job.

The change is mechanical and low-risk: it moves the `GIT_TEST_USE_SET_E=yes` assignment from a job-name-based `case` block into a new `CI_OS_NAME`-based block, eliminating four lines of redundant configuration while adding six lines of consolidated logic. The rationale is straightforward: `set -e` works consistently across all supported Linux distributions, so the variable should be set uniformly rather than piecemeal. The patch also implicitly fixes an oversight by ensuring the `linux32` job (which runs 32-bit tests) inherits the setting, though this is not called out in the commit message.

This aligns with the series’ broader goal of reducing duplication and improving maintainability in CI configuration. The use of `CI_OS_NAME` as a proxy for platform-wide settings is a deliberate design choice, intended to make the configuration more resilient to future job additions or renames. Reviewers (Jeff King, Phillip Wood, Toon Claes) have already endorsed the series as uncontroversial, and this patch is no exception—it’s a clean, well-motivated refactoring with no behavioral changes or edge cases.

Files touched: only `ci/lib.sh`. Key symbols: `GIT_TEST_USE_SET_E`, `CI_OS_NAME`. No test coverage changes or on-disk format impacts. The patch is ready for merging as part of the larger series.
