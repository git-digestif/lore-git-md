This is a **feature patch** introducing the `--matched-only` option to `git range-diff`, currently stalled in `seen` due to lack of review rather than technical issues. Harald Nordgren responds to Ben Knoble’s substantive review question about the feature’s motivation by providing a concrete workflow example: when rebasing a long-lived branch against `master`, the default `git range-diff` output buries the few relevant changes (the commits that survived the rebase) under hundreds of unrelated commits that were simply added or dropped. The `--matched-only` flag filters the output to show only the commits present in both ranges, eliminating the need to scroll past irrelevant entries. This use case directly addresses the pain point described in the original commit message and clarifies the feature’s practical value for users reviewing rebases or other range-diff scenarios where the focus is on how surviving commits changed, not on which commits were added or removed. The response advances the thread by supplying the missing motivation, which may help attract further review and move the patch toward merging.
