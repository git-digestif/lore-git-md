This is a follow-up in the ongoing completion regression fix series. Tanga Joris responds to Kaartic Sivaraam’s suggestion to add a defensive test that would catch future commands adopting `parse-options` but forgetting to remove their `NO_PARSEOPT` flag. The test, as sketched, works for commands with long options (it catches the original regression for `diff-pairs`, `fast-import`, and `patch-id`) but misses `var`, which only has short options, because the `--git-completion-helper` output only lists long options. Tanga has prototyped the test and confirms it passes with the series applied, but is unsure how to extend it to cover short-only commands. The question of whether to fold the test into patch 2/2 or add it as a new 3/3 remains open. The series itself is otherwise ready and still blocked on Christian Couder’s `cc/early-scan-options` reaching `next`.
