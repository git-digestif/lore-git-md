This is the second patch in a two-patch bugfix series (v4) targeting submodule diff header commit abbreviation. The series is part of the Git libification effort and fixes a correctness issue where commit IDs in submodule diff headers were abbreviated using the superproject's object database, risking collisions where the same abbreviated ID could refer to different objects in the submodule and superproject.

This patch makes the existing test hash-agnostic by replacing hardcoded SHA-1 abbreviations with values provided via `test_oid_cache`. The test now runs under both SHA-1 and SHA-256, ensuring the fix works regardless of the hash algorithm in use. The change is minimal and surgical: it removes the `SHA1` prerequisite, defines expected abbreviations for both hash algorithms, and updates the test to use these values. All other aspects of the test remain unchanged, including the core scenario that verifies the submodule's object database is used for abbreviation.

The series is now technically complete. The first patch (unchanged in v4) was already marked "Will queue" by Junio, and this patch addresses his feedback about test hash-agnosticism. The fix is low-risk, well-tested, and ready for integration. The libification angle—reducing reliance on `the_repository`—is a secondary benefit but not a prerequisite for this correctness improvement. If you care about submodule diff display or hash-agnostic testing, this series is worth a quick look; otherwise, it’s safe to skip.
