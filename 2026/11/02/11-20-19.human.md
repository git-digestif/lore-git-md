This is the third patch in Patrick Steinhardt’s six-part refactoring series to isolate the loose-object backend into its own source file (`odb/source-loose.c`). The series is part of the ongoing ODB abstraction effort, which aims to make Git’s object storage layer more modular.

This patch moves the iteration logic for loose objects—specifically the `for_each_loose_file_in_source()` and `for_each_file_in_obj_subdir()` functions—from `object-file.c` into the new backend file. The change is mechanical: the code is lifted verbatim, with only the necessary `#include` directives adjusted (adding `dir.h` to the backend file and removing it from `object-file.c`). Four callers (`builtin/count-objects.c`, `builtin/gc.c`, `builtin/prune.c`, and `prune-packed.c`) now include `odb/source-loose.h` instead of `object-file.h`.

The commit message notes a quirk in the current design: the iteration function accepts a generic `struct odb_source` even though it only needs the `path` member, because it knows how to traverse the loose-object directory structure. The author acknowledges this is odd and suggests a future cleanup to use `struct odb_source_loose` instead, but defers that work to avoid churning callers prematurely.

No functional changes are introduced; the patch is purely a refactoring step that keeps the existing behavior intact while further isolating the loose backend. The series as a whole remains under review, with no substantive feedback yet.
