This is a cover letter for a two-patch bugfix series from Dominik Maier that addresses argument validation and a zip-formatting bug in `git archive`. The series is standalone, not part of a larger effort, and represents a second iteration responding to review feedback from René Scharfe.

The primary focus is patch 2/2, which reworks how `--add-file` is validated when `--remote` is used. In v1 the author rejected the combination inside the option callback before any filesystem access; following René Scharfe's suggestion, v2 instead defers the `stat()` call until after `parse_options()` completes. This preserves the security property of never probing the server filesystem for `--add-file` paths when `--remote` is set, but it also allows a later `--no-add-file` to cancel an earlier `--add-file`, and it permits `--add-virtual-file` to work over `--remote` since that option supplies content inline rather than reading from disk. The patch credits René Scharfe with a `Suggested-by` trailer and adds tests in `t/t5000-tar-tree.sh` covering the remote rejection, the `--no-add-file` cancellation case, and remote virtual files.

Patch 1/2 fixes a separate bug discovered while testing: an out-of-bounds pointer advance in `write_zip_entry()` in `archive-zip.c` that occurred when `--prefix` was longer than the path of an extra or virtual file. The fix adjusts the prefix-stripping logic, with a corresponding test added to `t/t5003-archive-zip.sh`.

The series looks well-crafted and responsive to review. The commit messages clearly explain the motivation, the range-diff shows a thoughtful adaptation to the suggested alternative approach, and test coverage addresses both the new behavior and the regression it prevents.
