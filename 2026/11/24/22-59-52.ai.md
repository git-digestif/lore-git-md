This is a **bugfix for Git v3 compatibility**, part of the `WITH_BREAKING_CHANGES=1` effort to make `git init` default to SHA-256 rather than SHA-1. The patch is v5 of a series by brian m. carlstadt, restructures the hash-algorithm selection logic in `repository_format_configure()` within `setup.c`, and fixes a test-isolation bug in `t/t0001-init.sh` that caused global config to leak between tests on bash systems.

The core change replaces the previous scattered assignments to `repo_fmt->hash_algo` with a single if-else chain that computes a local `hash` variable using strict priority: an explicit command-line `--object-format` always wins; otherwise, if the repository already exists (`repo_fmt->version >= 0`), its current `hash_algo` is reused; failing that, the `GIT_DEFAULT_HASH` environment variable is consulted, then the `init.defaultObjectFormat` config value (`cfg.hash`), and finally `GIT_HASH_DEFAULT` (which resolves to SHA-256 under breaking-changes builds and `SHA1_LEGACY` otherwise). After computing `hash`, the code assigns it to `repo_fmt->hash_algo` once at the end, and adds an explicit guard inside the existing `repo_fmt->version >= 0` block that calls `die(_("attempt to reinitialize repository with different hash"))` if the computed value disagrees with the repository's stored algorithm, preventing silent reinitialization with a different hash.

The test additions in `t/t0001-init.sh` cover three scenarios using `$GIT_TEST_BUILTIN_HASH`: a new repository picks up the build default; `git init --object-format=<other>` on an existing repository fails with the fatal error; and a global `init.defaultObjectFormat` does not alter the hash of an existing repository on reinit. The v5-specific changes address Junio C Hamano's review feedback: the redundant `repo_fmt->hash_algo != GIT_HASH_UNKNOWN` conjunct was removed from the reinitialization guard, and the test-isolation bug was fixed by moving the `test_when_finished "test_unconfig --global init.defaultObjectFormat"` registration outside the subshell and replacing the `test_config_global` call inside the subshell with a direct `git config --global` invocation, ensuring cleanup executes in the parent shell.

The series has been approved by the maintainer and is pending queueing in `next` or `seen`; it is not yet merged to `master`. The fix ensures `git rev-parse --show-object-format` returns `sha256` for new repositories under `WITH_BREAKING_CHANGES=1` while preserving existing repository hashes, and does not apply to `maint`. Future work on a hypothetical "empty repository" feature allowing hash-agnostic initialization remains out of scope.
