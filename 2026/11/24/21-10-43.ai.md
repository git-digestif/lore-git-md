This is a substantive review of Andy Koppe's feature patch adding the `%(body:trailers=<bool>)` placeholder to the pretty-formatting engine. Junio C Hamano approves the overall design, noting that having a counterpart to `%(trailers)` that strips the trailer block without external post-processing makes `%w` rewrapping and separate coloring cleaner, and that modeling the syntax after `%(trailers)` and `%(describe)` fits existing conventions.

On the implementation in `pretty.c`, Junio examines `format_body_without_trailers()` and questions why `parse_trailers()` is called with `no_divider` set when only `trailer_block_start()` and `trailer_block_end()` are used, observing that this populates and immediately frees the trailer list because `trailer_block_get()` is file-local to `trailer.c`. He accepts this trade-off for now. He also probes whether an `else` clause is needed when `trailer_start` is not greater than `body`, tracing the caller in `format_commit_one()` where `msg` is set to `subject_off` and `body` to `body_off`, and concluding it is safe because `find_trailer_block_start()` in `trailer.c` skips the first paragraph. He praises the use of `match_placeholder_bool_arg()` in `parse_body_options()` for cleanly handling bare options, boolean values, repeated options, and unclosed placeholders.

Regarding the tests in `t/t4205-log-pretty-formats.sh`, Junio flags that `test_when_finished "git reset --hard HEAD^"` is unsafe because if the test fails before creating the commit, subsequent tests run in a repository state with one commit fewer than expected; he suggests capturing `go_back_to=$(git rev-parse --verify HEAD)` first and resetting to that. He also recommends adding test cases for repeated options like `trailers=no,trailers=yes` and invalid boolean values such as `trailers=bogus`. He concludes that the patch looks nicely done apart from these minor test nits.
