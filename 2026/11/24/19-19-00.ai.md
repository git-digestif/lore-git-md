This is a substantive maintainer review from Junio C Hamano approving Dominik Maier's security patch for `git filter-branch --state-branch`. The email confirms the path-traversal vulnerability in `git-filter-branch.sh` when loading the `filter.map` blob from an untrusted state branch, specifically noting that an empty key like `:foo` causes redirection to `../map/` to fail with an "Is a directory" error inside the loop without invoking `die()`, while keys containing `../` can escape `$tempdir/map` into the surrounding working tree.

Junio validates the proposed validation logic requiring `$from_commit` to be non-empty lowercase hexadecimal and `$to_commit` to contain only lowercase hex digits and spaces (with empty permitted for pruned commits). He offers one minor documentation suggestion: the commit message should briefly explain why spaces are allowed in `$to_commit`, since the `map()` function that dumps `../map/$from_commit` is designed to be used unquoted in constructs like `for reparent in $(map "$parent")` to expand a single `from` commit into multiple `to` commits separated by spaces.

The review concludes with "Looks good. Thanks.", signaling maintainer approval of the approach. The patch modifies `git-filter-branch.sh` to read lines with `IFS= read -r` and enforce the hex validation before writing map entries, with corresponding tests in `t/t7003-filter-branch.sh` covering traversal attempts like `../../escaped:injected`. The work builds on commit 4811dabed7 which restored the `from:to` ordering in the state-branch map parsing. No objections are raised; the thread remains open pending any final tweaks to the commit message.
