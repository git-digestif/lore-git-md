This is a cover letter for a two-patch bugfix series (v2) targeting the archive subsystem, authored by Dominik Maier. The series evolves from a previous single-patch approach after substantive review feedback from René Scharfe, splitting the work into a zip prefix-handling fix and a reworked argument-validation change for `--remote` mode.

Patch 1/2 fixes an out-of-bounds pointer advance in `write_zip_entry()` in `archive-zip.c` that occurs when `--prefix` is longer than the path of an extra file (`--add-file`) or virtual file (`--add-virtual-file`). The cover letter notes this was discovered while testing `--remote --add-virtual-file` with `--format=zip`.

Patch 2/2 implements René Scharfe's suggested alternative to v1: instead of rejecting `--add-file` immediately inside the option callback, the `stat()` and regular-file checks are deferred to `parse_archive_args()` in `archive.c` after `parse_options()` completes. The callback now merely records the path with `info->content = NULL` (for `--add-file`) or inline content (for `--add-virtual-file`). After parsing, the code iterates `args->extra_files`, skipping entries with non-NULL `content` (virtual files), dying with the incompatibility error if `is_remote` is set and `content` is NULL, and only then performing `stat()` on the server filesystem. This allows a later `--no-add-file` to cancel an earlier `--add-file` even under `--remote`, and permits `--add-virtual-file` to work with `--remote` since no filesystem access is needed.

Tests are added in `t/t5000-tar-tree.sh` verifying that `--remote --add-file` fails with the incompatibility message rather than "File not found", that `--no-add-file` can cancel `--add-file` both locally and remotely, and that `--remote --add-virtual-file` succeeds. A test is also added in `t/t5003-archive-zip.sh` for the zip prefix fix. The series touches only `archive.c`, `archive-zip.c`, and the two test scripts, with no merge or integration status stated.
