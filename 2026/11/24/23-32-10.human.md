This is a feature patch -- specifically the second of three in Erik Cervin-Edin's v4 series that completes the matrix of message-specification options for `git commit --fixup`. While the first patch in the series restructured `prepare_to_commit()` to write the fixup subject line up front, this patch delivers the actual user-visible change: `-m` and `-F` now work with every `--fixup` variant, including `--fixup=amend:` and `--fixup=reword:`, where they previously errored out.

The motivation is to support non-interactive workflows, particularly for AI coding agents that cannot drive an editor. Previously, plain `--fixup` accepted `-m` but not `-F`, while the amend and reword variants only allowed message editing through an editor. This patch removes the `die()` check that blocked `-m` with `--fixup=amend:`, demotes the incompatible-option check from `die_for_incompatible_opt4` to `die_for_incompatible_opt3` (since `-F` is now permitted), and updates the documentation to describe the new behavior for both plain and amend-style fixups.

The changes touch `builtin/commit.c`, `Documentation/git-commit.adoc`, and `t/t7500-commit-template-squash-signoff.sh`. The tests replace the old "error out with -m option" cases with positive assertions that `--fixup=amend:` and `--fixup=reword:` now accept `-m`, add coverage for `-F` with both plain `--fixup` and `--fixup=reword:`, and verify that an empty `-m ""` still triggers the expected "empty commit message body" error for amend commits. The remaining `-c`/`-C` enablement is deferred to the third patch in the series.

The commit message traces the history of these restrictions back to the original `--fixup` introduction in 2010 and the 2017 addition of `-m`, noting that nothing inherent prevents the broader support. With all prior feedback from Phillip Wood and Junio Hamano addressed in earlier iterations, this v4 reroll appears production-ready and is awaiting final review.
