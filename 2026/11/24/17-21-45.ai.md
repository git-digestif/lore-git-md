This is a refactoring patch in the ongoing `the_repository` removal effort, specifically the fourth of five patches in Okhuomon Ajayi's v2 series targeting the notes subsystem. It modifies the ref glob helpers `string_list_add_refs_by_glob()` and `string_list_add_refs_from_colon_sep()` in `notes.c` and `notes.h` to accept an explicit `struct repository *` as their first parameter instead of implicitly using the global `the_repository`. The patch updates the function signatures, the internal calls to `refs_for_each_ref_ext()`, `repo_get_oid()`, and the recursive call between the two helpers, and adjusts all current call sites in `notes.c` and `notes-utils.c` to pass `the_repository` explicitly as a temporary measure.

The change touches three files: `notes.c` (where the functions are defined and most callers reside), `notes.h` (declarations), and `notes-utils.c` (two call sites in `notes_rewrite_config()` and `init_copy_notes_for_rewrite()`). The callers in `load_display_notes()`, `notes_display_config()`, and the notes rewrite path all currently pass `the_repository`, maintaining existing behavior while making the repository explicit. This prepares the API for future callers that may hold a different `struct repository *`.

Within the series context, this patch sits between the write/prune path conversions in patch 3/5 and the `combine_notes_fn` callback conversions planned for patch 5/5. The series as a whole stores a `struct repository *repo` field in `struct notes_tree` (patch 1/5) and progressively threads the repository through `notes.c` internals. This particular patch addresses the display and rewrite configuration paths that populate `string_list` structures with note refs.

The series remains under active review with no merge status; it is not in `seen`, `next`, or `master`. Patrick Steinhardt's confirmation on the scoping of the remaining `USE_THE_REPOSITORY_VARIABLE` guard in `notes.c` is the gating item for the next iteration. The `USE_THE_REPOSITORY_VARIABLE` guard remains in both `notes.c` and `notes-utils.[c,h]` because functions like `load_display_notes()` and the global `default_notes_tree` still rely on implicit global state.
