This is a review-discussion reply in the ongoing bugfix thread about `git cherry-pick` on unborn branches, not a new patch. Phillip Wood responds to Wonseok Oh's questions, confirming that the commit message will be reworded to cite commit `0f974e2124` as the origin of the uninitialized-variable use.

The email settles an open question about how the sequencer state files should represent an unborn branch. Wonseok had asked whether the patch should write an empty `.git/sequencer/head` file to match `update_abort_safety_file()`'s behavior, since an empty file arguably represents "no OID" more naturally than a null OID. Phillip initially floated that idea but then reversed course, deciding that older versions of Git expect to read a null OID in both state files, so the patch should standardize on the null OID rather than the empty file. This means the current approach in Wonseok's patch is correct as-is, and no change to the state-file representation is needed.

With that question resolved, the path is clear for a v2 of the patch containing only the commit-message rewording and the `oidclr()` fix itself. Phillip reiterates that the immediate fix for the uninitialized `oid` in `sequencer_pick_revisions()` looks good, while the broader behavioral inconsistencies he outlined earlier -- such as the inability to abort a multi-pick sequence on an orphan branch and the differing treatment of single versus multi-commit reverts on unborn branches -- remain open for separate follow-up work rather than this series.
