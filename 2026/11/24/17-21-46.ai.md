This is a refactoring patch and the final installment (`[PATCH v2 5/5]`) of a five-patch series that removes implicit uses of the global `the_repository` from the notes subsystem as part of the ongoing `the_repository` removal effort.

The patch updates the `combine_notes_fn` typedef in `notes.h` to accept a `struct repository *` as its first parameter, ahead of the two object IDs, and applies the same signature change to all four built-in combinators: `combine_notes_concatenate()`, `combine_notes_overwrite()`, `combine_notes_ignore()`, and `combine_notes_cat_sort_uniq()`. Inside `notes.c`, the static helper `string_list_add_note_lines()` also gains a repository parameter, and the single call site in `note_tree_insert()` now passes `t->repo` so that the callbacks read and write note blobs through the notes tree's own repository (`r->objects`) rather than `the_repository->objects`. The `UNUSED` markers on `combine_notes_overwrite()` and `combine_notes_ignore()` indicate they still ignore the repository for now, but the interface is consistent.

This completes the series' goal of making the core notes API repository-agnostic; with this patch, the read, write, prune, ref-glob, and combine paths in `notes.c` all use the repository stored in `struct notes_tree` or passed explicitly. The `USE_THE_REPOSITORY_VARIABLE` guard remains in `notes.c` and `notes-utils.[c,h]` for functions still tied to the global `default_notes_tree`, but the combine callbacks are now fully converted. The series remains under review with no merge status; Patrick Steinhardt's confirmation on the scoping of the remaining guard is still the gating item for any future iteration.
