Junio C Hamano replies to Wonseok Oh's v2 patch that fixes silent corruption when an inline `M` command appears at the end of the input stream without a following `data` command. While he confirms the commit message "describes the problem accurately," he questions whether this specific fix is the right approach, pointing instead to his own series at `https://lore.kernel.org/git/20261122140347.41990-1-gitster@pobox.com/` which he says would solve "this infinite loop, together with a few others." This suggests the maintainer sees Wonseok Oh's patch as potentially redundant if his more comprehensive series addresses the same EOF-handling weakness in `file_change_m()` along with other related issues. The v2 patch itself restructures the read loop to explicitly check for EOF and die with an error message rather than storing an uninitialized object ID, but Junio's response indicates he prefers tackling the root cause through his own broader cleanup.
