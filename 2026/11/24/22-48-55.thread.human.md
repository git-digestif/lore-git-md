Harald Nordgren posted a small follow-up patch to `imap-send.c` that rewrites the header-scanning loop in the static function `has_required_headers()`, which looks for the required `From:`, `Date:`, and `Subject:` headers up to the blank line that ends the header block. The change replaces the old inline pointer advancement with symmetric up-front checks for LF and CRLF empty-line terminators, making the loop condition easier to read; the commit message states there is no behavior change, and the idea originated from a suggestion Patrick Steinhardt made during review of an earlier imap-send series that has already reached `master`.

Junio C Hamano replied with a substantive review and acceptance. He traced the function's only caller, `count_messages()`, and verified that `starts_with()` cannot read past the terminating NUL of the strbuf holding the mbox input, and that the EOF behavior matches the old code exactly. Concluding the rewrite is behaviorally identical but clearer, he closed with "Will queue. Thanks.", so the patch is accepted for integration but not yet merged.
