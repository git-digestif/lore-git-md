This is a design discussion reply in the v10 patch series thread, not a patch itself. Junio C Hamano responds to Harald Nordgren's suggestion that making `--dry-run` a universal modifier across all `git branch` operations (including creation and renaming) might belong in a separate effort rather than this series. Junio clarifies that if `--dry-run` is introduced as part of this topic, users will expect individual operation modes to emit specific "not supported yet" messages -- such as "would avoid clobbering existing branch" for creation -- rather than generic incompatibility errors, though he concedes that leaving the broader redesign out of this series entirely is also acceptable.

The exchange centers on patch 3/5's relaxation of `--dry-run` to work with plain `-d`/`-D` deletion flags. Harald had argued that the universal `--dry-run` concept is sound but probably too large for this topic, asking whether Junio thinks it should be handled separately. Junio's reply delineates the scope boundary: either this series commits to the full per-operation dry-run model with tailored error messages for each unsupported operation, or it sticks to the current narrower scope where `--dry-run` only applies to deletion modes.

No code changes are proposed here; the email simply seeks consensus on how broadly to interpret `--dry-run` support before the series moves forward. The discussion leaves unresolved whether universal `--dry-run` should eventually extend to branch creation and renaming, with Junio signaling that inclusion in this series would require more than just allowing the flag with deletion operations.
