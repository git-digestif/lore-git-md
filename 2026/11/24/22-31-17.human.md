This is a maintainer review approving a security bugfix for the `contrib/git-cvsexportcommit.perl` script.

Junio C Hamano confirms that Dominik Maier's patch correctly addresses the command injection vulnerability in the `-W` (working-tree) mode. The review walks through each hunk of the diff, validating the conversion from single-argument `system()` calls -- which invoke `/bin/sh -c` and interpret shell metacharacters like `;` in branch names -- to the list form `system('git', 'checkout', ...)`, which execs git directly without shell interpretation. He notes that retiring the single-arg form is a good principle regardless of whether specific variables are currently safe, and specifically confirms that `$commit` is safe because it comes from `@ARGV` cleansed via `git rev-parse --verify`.

Junio briefly considers moving the `chomp $go_back_to` call closer to where the variable is used, but ultimately agrees with keeping it early, consistent with the principle of cleansing external data as soon as it is obtained. He validates the hardening of the final checkout with `--end-of-options` and `--` to prevent option injection from dash-prefixed refnames, and confirms the `git symbolic-ref` restoration is correctly converted. The review concludes with "Looks good. Thanks," signaling acceptance of the patch, which includes a regression test creating a branch literally named `topic;false` to verify HEAD is restored safely.
