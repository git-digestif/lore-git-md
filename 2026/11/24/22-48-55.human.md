This is a small refactoring patch touching `imap-send.c`, specifically the `has_required_headers()` function that scans an email message for required `From:`, `Date:`, and `Subject:` headers.

The patch rewrites the loop that detects the empty line marking the end of the headers. The old code advanced the pointer first and then checked separately for an LF or CRLF empty line, which made the control flow easy to misread. The new version checks for both `\n\n` and `\n\r\n` at the current position before moving to the next line, making it obvious that both line-ending styles are handled identically. The commit message is explicit that behavior does not change.

The change was suggested by Patrick Steinhardt during review of a series that has since landed in `master`, so this is a follow-up cleanup rather than new functionality. It is a standalone patch, not part of a larger series, and touches only four lines in a single file. The patch looks well-crafted and low-risk -- a clarity improvement in a network-facing code path that any reviewer can verify at a glance.
