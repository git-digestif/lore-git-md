This is a substantive review by Junio C Hamano of patch 2/7 in Harald Nordgren's v15 series on matching-inspired fetch behavior. The patch removes the error that aborted `git fetch --refmap` when no command-line refspecs were given, instead letting the option apply to configured `remote.<name>.fetch` refspecs by stripping their destinations and remapping them.

Junio raises three specific concerns about the implementation. First, with no configured fetch refspecs at all, `git fetch --refmap=... <URL>` would now silently ignore the refmap and just fetch HEAD into FETCH_HEAD rather than erroring out -- he is unsure whether that harmlessness is acceptable. Second, and more substantively, he points out that `*autotags` is computed earlier in the loop based on whether the original configured refspecs had destinations, but `drop_destinations()` subsequently clears those destinations, so the autotag logic no longer reflects the actual refmap state -- passing `--refmap=""` to suppress remote-tracking branches would still trigger tag auto-following, while destinationless configured entries combined with a `--refmap` that supplies destinations would not. Third, `prune_refs()` in `do_fetch()` still receives `remote->fetch` rather than the refmap when no command-line refspecs are present, so `git fetch --prune --refmap=...` would prune based on the original configuration rather than the remapped hierarchy, likely leaving the wrong refs in place.

The review is thorough and identifies real edge cases in how the refmap interacts with tag following and pruning, suggesting the patch needs refinement before it can graduate.
