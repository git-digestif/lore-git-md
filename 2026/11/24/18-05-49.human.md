This is the first patch of a two-patch bugfix series (v2) targeting `git archive`'s ZIP output, specifically an out-of-bounds pointer bug in `archive-zip.c`.

The patch fixes `write_zip_entry()`, which previously computed `path + args->baselen` unconditionally to strip the `--prefix` before checking whether an entry is binary. For entries added via `--add-file` or `--add-virtual-file`, the archive path can be shorter than a later `--prefix`, causing the pointer arithmetic to step past the end of the string. For virtual files it could even trigger a spurious worktree `gitattributes` lookup along an arbitrary path. The fix updates `args->base` and `args->baselen` to match each extra file's recorded prefix before writing, and clears them to `NULL` for virtual files so `entry_is_binary()` falls back to content inspection rather than path-based attribute lookup.

This patch complements the second patch in the series, which reworks `--remote` argument validation; the ZIP bug was discovered while testing `--remote --add-virtual-file` with `--format=zip`. A regression test in `t/t5003-archive-zip.sh` covers the case where `--prefix` is longer than a virtual file's path.

The change is small, well-targeted, and includes test coverage. It addresses a real memory-safety edge case rather than a cosmetic issue, and appears ready for review.
