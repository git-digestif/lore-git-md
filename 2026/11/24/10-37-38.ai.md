This is a feature patch that adds a new `GIT_COMMENT_STRING` variable to `git var`. Phillip Wood exposes the effective comment string used for template commit messages and rebase todo lists, which is currently determined by either `core.commentChar` or `core.commentString` but not directly queryable by scripts without parsing both config keys. The motivation, tied to commit 9ccf3e9b22 which introduced `core.commentString`, is that scripts previously had to run awkward shell pipelines to figure out which comment character Git would actually use; `git var GIT_COMMENT_STRING` now returns it directly.

The implementation adds a `comment_string()` helper in `builtin/var.c` that returns the global `comment_line_str`, registers it in the `git_vars[]` table under the name `GIT_COMMENT_STRING`, documents the new variable in `Documentation/git-var.adoc`, and adds test coverage in `t/t0007-git-var.sh` verifying both the default `#` and a custom `core.commentString` value. The patch is small and self-contained, touching only those three files with no behavioral changes to existing commands.

The patch looks clean and well-motivated: it solves a concrete scripting pain point with a minimal interface addition, includes tests, and follows the existing pattern of other `git var` variables like `GIT_EDITOR` and `GIT_DEFAULT_BRANCH`.
