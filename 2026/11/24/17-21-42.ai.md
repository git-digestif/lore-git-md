This is the first patch in a five-patch series (`[PATCH v2 1/5]`) that begins the `the_repository` removal effort in the notes subsystem by storing a repository pointer directly in `struct notes_tree`. The patch adds a `struct repository *repo` field to the `struct notes_tree` definition in `notes.h` and renames two public API functions to require an explicit repository argument: `init_notes()` becomes `notes_tree_init()` with the signature `notes_tree_init(struct notes_tree *t, struct repository *r, const char *notes_ref, combine_notes_fn combine_notes, int flags)`, while `load_notes_trees()` becomes `notes_tree_load(struct repository *r, struct string_list *refs, int flags)`. Inside `notes_tree_init()`, the repository is saved as `t->repo` and used in place of the global `the_repository` for calls to `default_notes_ref()`, `repo_get_oid_treeish()`, `refs_read_ref()`, `get_tree_entry()`, and the `oidclr()` on the root tree key.

The diff modifies `notes.c`, `notes.h`, `builtin/notes.c`, `notes-cache.c`, and `notes-utils.c`. Most callers pass `the_repository` temporarily, but `notes_cache_init()` threads its existing `struct repository *r` parameter through to `notes_tree_init()`, and `notes_tree_load()` forwards its repository argument to each `notes_tree_init()` call it makes when initializing multiple trees. Internal functions that still operate on the global `default_notes_tree` -- specifically `load_display_notes()` and the lazy-initialization path in `format_note()` -- continue to reference `the_repository` directly, as converting those is explicitly deferred to later work.

This patch establishes the structural foundation that patches 2/5 through 5/5 will build on, converting core operations like `note_tree_find()`, `add_non_note()`, `load_subtree()`, `remove_note()`, `format_note()`, `write_notes_tree()`, and `prune_notes()` to use `t->repo` instead of the global. The function renames and parameter ordering follow Patrick Steinhardt's interface feedback from the v1 iteration, and the deliberate retention of the `USE_THE_REPOSITORY_VARIABLE` guard for functions depending on `default_notes_tree` remains the key scoping question awaiting his confirmation before the next iteration.

Future discussion in this thread is likely to reference the exact parameter order of the renamed functions (`notes_tree_init()` takes tree first, repository second; `notes_tree_load()` takes repository first), the new `t->repo` field as the canonical repository pointer for initialized notes trees, and the distinction between converted code paths that now use `t->repo` versus unconverted paths in display-notes handling and hash-size helpers that still rely on `the_repository` and `the_hash_algo`.
