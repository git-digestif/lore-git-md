This is the second patch in a two-patch bugfix series (v2) targeting the `git archive` argument handling, specifically the interaction between `--remote`, `--add-file`, and `--add-virtual-file`. Authored by Dominik Maier, it implements a suggestion from René Scharfe to defer filesystem access until after option parsing completes.

The core change moves the `stat()` and regular-file checks for `--add-file` out of the option callback and into `parse_archive_args()` in `archive.c`. Previously, `add_file_cb()` called `stat()` immediately while `parse_options()` was still running, which meant that under `--remote` (handled by `git-upload-archive` on the server), a nonexistent file would trigger a "File not found" error before the code could check the `--remote` incompatibility. Now the callback simply records the path with a NULL content pointer, and after parsing finishes, the code iterates the recorded entries: virtual files (which have inline content) are skipped, `--add-file` entries under `--remote` are rejected with the proper "cannot be used together" message before touching the filesystem, and local `--add-file` entries undergo the `stat()` checks as before.

This restructuring also fixes a subtle behavior where `--no-add-file` could not properly cancel an earlier `--add-file` under `--remote`, and it enables `--remote --add-virtual-file` to work, since virtual files carry their content inline and require no server filesystem access. The patch includes tests in `t/t5000-tar-tree.sh` verifying that remote `--add-file` fails with the incompatibility message rather than "File not found", that `--no-add-file` cancellation works both locally and remotely, and that `--remote --add-virtual-file` succeeds. The commit message is clear, the change is well-scoped, and it directly incorporates the reviewer's feedback from v1.
