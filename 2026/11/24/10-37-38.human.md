This is a small feature patch that adds a new `GIT_COMMENT_STRING` variable to `git var`. Phillip Wood gives scripts a direct way to query the comment string Git uses in template commit messages and rebase todo lists, without having to manually reconcile `core.commentChar` and `core.commentString` from the config.

The motivation traces back to commit 9ccf3e9b22, which introduced `core.commentString` next to the older `core.commentChar`. When a multi-byte string is configured, it is often useful to keep `core.commentChar` set to a single character for compatibility with older Git versions, but that makes it awkward for scripts to figure out which value Git actually uses. Today a script has to run `git config --get-regex` and parse the output to pick the right key; `git var GIT_COMMENT_STRING` hides that logic.

The change itself is minimal: a new entry in the `git_vars` table in `builtin/var.c` that returns the existing `comment_line_str`, plus a line in `Documentation/git-var.adoc` and a test in `t/t0007-git-var.sh` covering both the default `#` and a custom value. The commit message is clear, cites the specific commit that created the problem, and shows the awkward shell snippet this replaces. It looks like a well-crafted, low-risk addition that should be straightforward to review.
