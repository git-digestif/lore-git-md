This is a v2 bugfix for the ASCII graph renderer in `graph.c`, fixing incorrect `git log --graph` output for left-skewed octopus merges. Author Dominik Maier addresses a flaw in `graph_insert_into_new_columns()` where a shortcut intended to let existing right-side columns fuse with a merge's last edge (`idx < 0`) also fired for left-skewed merges, whose first parent does not advance `graph->width`. With three parents this swallows an edge entirely; with four or more it shifts subsequent parents one slot left, leaving `-1` in `graph->mapping[]` and causing an out-of-bounds read at `graph->new_columns[-1]` in `graph_draw_octopus_merge()`.

The fix adds an `idx < 0` guard to the fusion condition so it only applies to existing non-merge columns. Compared to v1, this version drops the defensive `BUG()` that v1 had added in `graph_draw_octopus_merge()`, rewords the commit message to include ASCII-art examples of both the 3-parent missing-edge case and the 4+-parent crash, and expands testing. Two regression tests are added to `t/t4215-log-skewed-merges.sh`: one constructing a left-skewed 3-parent merge (`8_TOP` with parents `8_A`, `8_B`, `8_M`) and one with a 4-parent octopus (`8_TOP4` / `8_M4`), both verifying expected graph output via `lib_test_check_graph`.

Caspar Duregger is credited with `Helped-by` for supplying the simplified 3-parent reproduction and confirming the `idx < 0` guard approach; he had previously questioned whether the `BUG()` belonged in the code, which this v2 addresses by removing it. The patch touches only `graph.c` and the test file. It remains under review with no maintainer decision or integration-branch placement recorded.
