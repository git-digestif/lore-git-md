This is the second patch in the v5 three-patch series fixing the `git repack -d` concurrent-push data-loss race; it adds new plumbing to `git pack-objects` that the following patch will use. The new option `--ignore-pack-keep-from=<file>` reads a list of local pack names from a file (one per line, matched as for `--keep-pack`) and clears their `p->pack_keep` flag before any object-walking code runs, so those packs are treated as if they had no `.keep` file even if one appears mid-run. This covers every path that consults `pack_keep`, including `--honor-pack-keep`, `--unpack-unreachable`, `--keep-unreachable`, and `--cruft`.

The implementation lives in `ignore_pack_keep_from_file()` in `builtin/pack-objects.c`, which is called early in `cmd_pack_objects()` before `add_extra_kept_packs()`. It opens the named file, reads pack basenames into a sorted string list using `fspathcmp`, then iterates `repo_for_each_pack()` clearing `pack_keep` on matching local packs. The file-based interface exists because the list can exceed command-line length limits (notably the 32767-character limit on Windows) and stdin is already occupied in the modes `repack` uses. Names are matched against `pack_basename(p)` for local packs only.

The patch updates `Documentation/git-pack-objects.adoc` with the synopsis and a description explaining that callers like `git repack` which are about to delete the named packs use this to ensure a `.keep` file appearing after the deletion decision does not cause objects to be omitted. Tests in `t/t7700-repack.sh` verify two behaviors: a functional test confirming that naming one of two kept packs in the ignore file causes its reachable objects to be packed while unreachable ones are loosened (and the other kept pack is left alone), and a negative test confirming that a missing file produces a `could not open ... for reading` error.

This patch introduces no behavior change for existing callers; it only exposes the mechanism. Patch 3/3 of the series will have `builtin/repack.c` write the snapshot of non-kept packs observed at startup to a tempfile and pass it via this option, closing the race where `repack` decides to delete a pack but a concurrent push drops a `.keep` file on it before `pack-objects` scans the directory.
