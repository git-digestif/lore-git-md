This is a review reply on a test-infrastructure patch, where Kaartic Sivaraam responds to Junio C Hamano's correctness objections against the v2 mechanism for serializing `EXPENSIVE` tests in `t/test-lib.sh`.

Sivaraam first acknowledges two minor commit-message fixes Junio spotted -- a typo in a commit hash and an inconsistent comma. He then addresses the two serious concurrency flaws Junio identified. For the TOCTOU race where a waiter might delete a newly-acquired lock, he proposes adding a secondary `mkdir`-based "break lock" and re-verifying the PID file contents before removing a stale lock directory. For the more severe deadlock window where a signal could arrive after creating the lock directory but before setting the `have_expensive_lock_` flag, he suggests swapping the order so the flag is set before writing the PID, ensuring the `die()` EXIT trap always cleans up the directory.

Sivaraam candidly notes that these fixes do not make the mechanism completely foolproof: a `kill -9` landing in the microseconds between `mkdir` and writing the PID, or a signal arriving before the flag is set, would still leave a permanent stale lock. He proposes shipping with the two fixes in place rather than chasing those remaining edge cases, and asks for Junio's thoughts on that trade-off. Both agree that the deadlock scenario is the worse failure mode. The thread remains open, with the author awaiting feedback on whether to proceed with these partial fixes or attempt a more robust solution.
