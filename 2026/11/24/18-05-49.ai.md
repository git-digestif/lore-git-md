This is a bugfix patch, specifically the first of a two-patch series (v2 1/2) targeting the ZIP archive backend. It corrects an out-of-bounds pointer advance in `write_zip_entry()` in `archive-zip.c` that occurs when `--prefix` is longer than the archive path of an extra file (`--add-file`) or virtual file (`--add-virtual-file`).

The root cause is that `write_zip_entry()` unconditionally computes `path_without_prefix = path + args->baselen` before calling `entry_is_binary()`. For tracked tree entries this is correct because they always begin with the final `--prefix` stored in `args->base`. However, extra files use the per-entry prefix recorded at option-parse time (`info->base`), and virtual files carry no prefix at all. When a later `--prefix` exceeds the extra or virtual file's path length, the pointer arithmetic steps past the end of the path buffer; for virtual files this also causes `entry_is_binary()` to look up worktree gitattributes along an arbitrary virtual path.

The fix lives partly in `archive.c` and partly in `archive-zip.c`. In `write_archive_entries()` (`archive.c`), the code now updates `args->base` and `args->baselen` to each `--add-file` entry's recorded prefix before calling `write_entry()`, and sets `args->base = NULL` (with `baselen = 0`) for `--add-virtual-file` entries. In `archive-zip.c`, `write_zip_entry()` now guards the pointer arithmetic with `args->base ? path + args->baselen : NULL`, and `entry_is_binary()` skips the path-based `userdiff_find_by_path()` lookup when `path` is NULL, falling back to content inspection instead. A test in `t/t5003-archive-zip.sh` exercises `--format=zip --prefix=very-long-archive-prefix/ --add-virtual-file=a:hello` against the empty tree.

This patch complements the second patch in the series (v2 2/2), which reworks `--remote` argument validation in `archive.c` to defer `stat()` calls and properly handle `--no-add-file` cancellation; the two patches together address distinct defects in `git archive` discovered while testing `--remote --add-virtual-file` with ZIP output. The series is under review with no merge status stated, and incorporates prior feedback from René Scharfe on the v1 approach.
