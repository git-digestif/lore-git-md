This thread is Jean-Noël Avila's four-patch v1 series converting the `git-svn`, `git-fast-import`, and `git-fast-export` man pages to AsciiDoc synopsis style, with patch 2/4 extracting the `svn.*` configuration documentation into a new shared include file `Documentation/config/svn.adoc`. The series remains under review with no integration branch status; Junio C Hamano has now reviewed both patch 4/4 and patch 2/4, offering minor corrections and structural questions but no Reviewed-by or approval yet.

On patch 4/4 (`git-fast-export`), Junio's feedback is mostly surface-level: a double space, the phrase "in addition of," a stray tab, and a truncated sentence in the `--reencode` description, plus an open question about whether remaining single-quoted command names should become backticks. His review of patch 2/4 is more substantive. He notes the patch subject says "add missing config options" while the commit message describes relocating existing text, and asks that both aspects be acknowledged. He flags that grouping `svn.findcopiesharder` (boolean) with `svn.l` (integer) under one entry obscures their differing types in `git-config(1)`, and suggests trimming a pre-existing implementation-detail sentence from the `svn.useSvmProps` entry now that it appears in the central config reference. Most significantly, he lists roughly sixteen `svn.*` and `svn-remote.<name>.*` keys used in `git-svn.perl` and `perl/Git/SVN.pm` -- including `svn.username`, `svn.repack`, `svn-remote.<name>.url`, and `svn-remote.<name>.fetch` -- that are absent from the new file, and asks the author to clarify which subset the file intends to cover. He also challenges placing the included content under the "CONFIG FILE-ONLY OPTIONS" heading in `git-svn.adoc`, since many of these variables have corresponding command-line flags; he suggests a "CONFIGURATION" section using `cmd-config-section-all.adoc` would be more accurate if the file is meant to serve as the complete `git-config(1)` list.

No response from Jean-Noël Avila or a v2 has been posted yet, so all of Junio's points -- the missing keys, the section placement, and the wording fixes across patches 2 and 4 -- remain open.
