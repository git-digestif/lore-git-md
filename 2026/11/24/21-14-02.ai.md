This is a substantive review reply from Junio C Hamano to the sixth patch in Patrick Steinhardt's six-part packfile lifecycle series. The email responds to `[PATCH 6/6]`, which modifies `close_one_pack()` in `packfile.c` to skip packfiles whose `do_not_close` bit is set when selecting a victim to close under the process-wide open-pack limit. The patch adds a three-line check inside the loop over the global `all_packfiles` list (introduced in patch 5/6), testing `e->pack->do_not_close` alongside the existing `pack_fd == -1` condition.

Junio questions the premise of the fix: since the only code that sets the `do_not_close` bit is `git fast-import`, and fast-import allocates its packs manually without adding them to `all_packfiles`, the limit-enforcement code would never encounter such a pack anyway. He suggests that if the sole user of the bit does not rely on `close_one_pack()` honoring it, a simpler alternative would be to retire the `do_not_close` bit entirely rather than adding logic to respect it. This challenges the author's characterization of the current behavior as "fragile coincidence" and proposes removing the flag as dead weight instead.

The technical context involves the `struct packed_git` field `do_not_close` and the global `struct packfile_list all_packfiles` that tracks all open packs process-wide. Patch 5/6 moved limit enforcement (`pack_max_fds` and `core.packedGitLimit`) from per-repository ODB iteration to scanning this global list, making it possible for `close_one_pack()` to encounter packs it did not open. The series as a whole is part of Patrick Steinhardt's ongoing ODB abstraction effort and remains at v1 under review, with no integration branch status claimed.
