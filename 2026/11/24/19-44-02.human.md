This is a substantive review from Junio C Hamano on the first patch of Yoichi NAKAYAMA's v2 series, which aims to store `submodule.<name>.gitdir` as relative paths in linked worktrees so the setting survives worktree moves.

Junio first asks the author to clarify the status quo in the commit message -- that `repo_git_path_append()` currently produces absolute paths for linked worktrees unless relative paths are enabled, and noting the change also applies to the main worktree when `GIT_DIR` is absolute. He then praises the v2 fix that copies `worktree_git_path()`'s result into a local `strbuf` in the `else` branch, noting it avoids overwriting the static buffer and that converting early returns to `goto cleanup` plugs pre-existing leaks.

However, he identifies a remaining static-buffer hazard in the `if (is_absolute_path(modules_dir))` branch: `relative_path()` may return a pointer directly into `worktree_git_path()`'s four-slot ring buffer without using the provided `strbuf`. He warns that once patch 3 calls `worktree_git_path(wt, "config.worktree")` inside `validate_and_set_submodule_gitdir()`, four consecutive failures could wrap that ring buffer and overwrite `modules_dir` while `create_default_gitdir_config()` is still using it. He suggests unconditionally owning the copy with `xstrdup()` to close the hole cleanly.
