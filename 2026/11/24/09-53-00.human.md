This is a review reply in the ongoing bugfix series `[PATCH v5 0/4]` that fixes bounds handling in `utf8_strnwidth()` and `utf8_width()`. Dirk Gouders is responding to Junio C Hamano's feedback on patch 3/4, which adds a bounds check after skipping ANSI escape sequences so that `utf8_width()` does not read past the end of the input buffer. Junio had approved the code change as correct but asked for two clarifications: the commit message should describe the actual trigger (an escape sequence reaching `orig + len` causing an out-of-bounds read) rather than just the symptom, and the new test in `t/unit-tests/u-utf8-width.c` should carry a comment warning that the assertions may need updating when the existing TODO at the bottom of `utf8_strnwidth()` is addressed. Gouders agrees to both and notes that he had started documenting how callers use the return values but decided to leave that broader `int`-vs-`size_t` cleanup for another time. The patch remains under review, with these mechanical tweaks expected in a future version.
