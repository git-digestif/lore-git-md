This is a substantive maintainer review of Andy Koppe's feature patch adding a `%(body:trailers=<bool>)` placeholder to Git's pretty-formatting engine. Junio C Hamano confirms the design choices are sound -- modeling the syntax after `%(trailers)` and `%(describe)` fits well, and having a built-in way to strip the trailer block simplifies `%w` rewrapping and separate coloring. He engages deeply with the implementation: he notes that calling `parse_trailers()` with `no_divider` correctly mirrors the `%(trailers)` branch, questions whether the trailer start can precede the body offset (then confirms it cannot, since `find_trailer_block_start()` skips the first paragraph), and praises the reuse of `match_placeholder_bool_arg()` for handling the option syntax cleanly.

The review identifies one real fragility in the test setup: three new test cases use `test_when_finished "git reset --hard HEAD^"`, which assumes a commit was successfully created before any failure occurs; Junio suggests capturing the starting HEAD with `git rev-parse --verify HEAD` instead so cleanup returns to the exact original state. He also recommends adding tests for repeated options like `trailers=no,trailers=yes` and invalid values like `trailers=bogus` to exercise the option parser fully.

Overall Junio judges the patch "nicely done" apart from these minor test nits, signaling likely acceptance once the test robustness issues are addressed. The thread remains open for Andy Koppe to respond to the test feedback.
