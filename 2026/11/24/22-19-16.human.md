This is a substantive review reply on patch 1/6 of Patrick Steinhardt's six-patch packfile lifecycle series. brian m. carlson endorses the removal of packfile statistics from `git fast-import` output but argues for a broader change: disabling all statistics reporting by default, in line with the Unix philosophy of staying silent on success. They cite a concrete use case -- test suites that convert repositories from SHA-1 to SHA-256 -- where the default stats output creates noise on standard error that must currently be suppressed with `--quiet`, while still needing to see genuine errors.

The feedback pushes beyond Patrick Steinhardt's narrower scope (dropping only packfile metrics) toward making `--stats` an opt-in flag for all statistics. This aligns with and extends the discussion already opened by Junio C Hamano's review of the same patch, which focused on commit message accuracy and a missed option string. The email does not dispute the technical removal of `pack_report()`, but suggests the user-visible behavior could be improved further by rethinking when statistics are emitted at all.
