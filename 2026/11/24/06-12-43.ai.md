This is a **bugfix cover letter** for the fifth iteration (v5) of a three-patch series by Qin ShiCheng (qeesung) that fixes a data-loss race in `git repack -d`. The race occurs when a `.keep` file appears on a pack after `repack` has decided to delete it but before `pack-objects` scans the packs, causing `pack-objects` to skip the pack's objects while `repack` deletes the pack anyway, leaving refs dangling.

The v5 series is essentially v4 rebased onto current `master` (base-commit `77904e546de3bd940621092ecec47a88d0cede5d`) to resolve a test conflict in `t/t7700-repack.sh` with the `ds/path-walk-tagged-tree-revisit` topic; the only code change in the range-diff is sorting the `keep_pack_list` before collection. The series replaces the old `--honor-pack-keep` mechanism with an explicit snapshot approach: patch 1/3 fixes a stale kept-pack cache in the cruft walk by introducing `repo_invalidate_kept_pack_caches()` in `packfile.c`/`packfile.h`; patch 2/3 adds a new `git pack-objects` option `--ignore-pack-keep-from=<file>` that reads pack names from a file and treats those packs as if they had no `.keep` file; patch 3/3 makes `builtin/repack.c` write a snapshot of all non-kept, non-cruft packs observed at startup to a tempfile and pass it to `pack-objects` via `--ignore-pack-keep-from`, ensuring `.keep` files created mid-run cannot cause deletion of packs whose objects were not copied elsewhere.

Files touched include `builtin/pack-objects.c`, `builtin/repack.c`, `packfile.c`, `packfile.h`, `repack.c`, `repack.h`, `odb/source-packed.h`, `tempfile.h`, `Documentation/git-pack-objects.adoc`, and tests in `t/t5329-pack-objects-cruft.sh`, `t/t7700-repack.sh`, and `t/t7703-repack-geometric.sh`. The tests reproduce the race for `-a -d`, `-A -d`, `-k`, `--cruft`, `--geometric`, and `--filter` modes using a `git` wrapper to inject a `.keep` file mid-repack. A known trade-off is that the cruft walk now traverses alternate ODB packs (intentional for safety), which slows `repack -d -l --cruft` in `clone --shared` setups from ~2ms to ~3.3s on `git.git`. The author notes that Justin Tobler's separate `jt/odb-keep-lockfile-fix` series addresses the `receive-pack` side but leaves this race intact. The series has received Reviewed-by tags from Jeff King (patch 1/3) and Taylor Blau (patch 3/3) in prior iterations and is considered ready for integration.
