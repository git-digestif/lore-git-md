This is a refactoring patch, specifically patch 3 of 5 in Okhuomon Ajayi's series to remove `the_repository` from the notes subsystem as part of the ongoing `the_repository` removal effort. It converts the write and prune paths in `notes.c` to use the repository stored in `struct notes_tree` (`t->repo`) rather than the global.

The patch modifies `write_notes_tree()` to write the final root tree and all intermediate subtrees through `t->repo->objects` instead of `the_repository->objects`. To support this, `tree_write_stack_finish_subtree()` and `write_each_note_helper()` now take an explicit `struct repository *r` parameter that is threaded down from `write_notes_tree()`, and the callback struct `write_each_note_data` gains a `struct repository *repo` field to carry this through `for_each_note()`.

`prune_notes()` similarly switches from `the_repository` to `t->repo` for its object-existence checks. It introduces a new `struct prune_notes_data` that wraps both the repository and the delete-list pointer, so `prune_notes_helper()` can call `odb_has_object(d->repo->objects, ...)` without touching the global. Finally, `copy_note()` now uses `null_oid(t->repo->hash_algo)` instead of `null_oid(the_hash_algo)` for its null object ID, since it writes through the tree via `add_note()`.

This builds directly on patch 1/5 (which added the `repo` field to `struct notes_tree`) and patch 2/5 (which converted the read path functions `note_tree_find()`, `add_non_note()`, `load_subtree()`, `remove_note()`, and `format_note()`). Together these make the core notes API repository-agnostic for the converted paths. The `USE_THE_REPOSITORY_VARIABLE` guard remains in `notes.c` for functions still dependent on the global `default_notes_tree` or lacking repository propagation, and the series remains under review with Patrick Steinhardt's confirmation on that scoping still pending.
