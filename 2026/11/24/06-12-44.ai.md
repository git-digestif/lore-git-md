This is a bugfix, specifically patch 1/3 of the v5 series by Qin ShiCheng (qeesung) that fixes a data-loss race in `git repack -d` where concurrent pushes can cause packs to be deleted before their objects are copied elsewhere. This first patch addresses a latent bug in the cruft-pack walk that becomes critical once the `--honor-pack-keep` mechanism is removed in later patches: the kept-pack cache in `packfile.c` is built while unlisted packs are still marked as kept, and the subsequent reachability walk consults that stale cache, causing the traversal to stop at unlisted packs and miss expired objects beyond them. The fix introduces `repo_invalidate_kept_pack_caches()` in `packfile.c`/`packfile.h`, which drops the kept-pack cache for every object directory, and calls it from `enumerate_and_traverse_cruft_objects()` in `builtin/pack-objects.c` after unmarking the packs.

With the cache invalidated, the cruft walk now correctly traverses every pack except the explicitly fresh ones, including packs borrowed from alternates and packs specified via `--keep-pack`. The patch also adjusts `--keep-pack` handling by marking such packs as `pack_keep_in_core_open` (similar to `--stdin-packs=follow` "!" packs), so the walk passes through them to rescue reachable objects while still excluding the pack's own objects from the cruft pack. This ensures that objects in alternate ODBs (which may be needed when repositories borrow from each other or when `git repack --filter-to` has split objects across repos) are properly rescued, at the cost of potentially walking a much larger history than the local repository's own.

The code changes touch `builtin/pack-objects.c`, `packfile.c`, `packfile.h`, and `odb/source-packed.h`, with the new `repo_invalidate_kept_pack_caches()` function exposed for use by the repack machinery. Tests added in `t/t5329-pack-objects-cruft.sh` verify that the cruft traversal correctly goes through an unlisted pack, through a `--keep-pack` pack (excluding its objects while rescuing others), and through an alternate ODB's packs both with and without `--local`, using scenarios involving `git repack --filter-to` to set up split object storage.

Jeff King has provided a Reviewed-by for this patch in the thread, confirming the fix is correct and the performance trade-off of traversing alternates is acceptable. The patch is part of a series that has been rebased onto current `master` and is considered ready for integration.
