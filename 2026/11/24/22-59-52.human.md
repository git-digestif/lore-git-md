This is the fifth and final iteration of a bugfix patch series correcting how `git init` selects the default object format when Git is built with `WITH_BREAKING_CHANGES=1`. The series, authored by brian m. carlstadt, fixes a bug where new repositories incorrectly defaulted to SHA-1 instead of SHA-256 under Git v3 behavior, and adds safeguards against silently changing the hash algorithm of an existing repository during reinitialization.

The core change restructures `repository_format_configure()` in `setup.c` into a single if-else chain that computes a local `hash` variable with strict priority: an explicit `--object-format` on the command line always wins; otherwise an existing repository's detected algorithm is reused; failing that, the code falls back to `GIT_DEFAULT_HASH`, then `init.defaultObjectFormat`, and finally `GIT_HASH_DEFAULT` (which is SHA-256 in breaking-changes builds). A fatal check later in the function now refuses to reinitialize a repository with a mismatched hash algorithm. This v5 specifically incorporates the two cleanups Junio C Hamano requested after approving v4: dropping the redundant `GIT_HASH_UNKNOWN` check from the reinitialization guard, and fixing a test-isolation bug in `t/t0001-init.sh` where `test_when_finished` was registered inside a subshell, causing the global `init.defaultObjectFormat` config to leak into subsequent tests on bash systems.

The patch adds three tests to `t/t0001-init.sh` covering the default object format for new repositories, the fatal refusal to reinitialize with a conflicting `--object-format`, and confirmation that a global `init.defaultObjectFormat` does not alter the hash of an existing repository on reinit. The test fixes ensure cleanup happens at the top level rather than inside a subshell. The commit message is clear and the logic is now straightforward to follow, with the priority order made explicit rather than scattered across multiple conditional branches.

Junio C Hamano had already indicated that v4 "all looks good" and stated that if this v5 contains only the test fix, he has a ready fix-up commit on his topic branch and would squash it in. With the test-isolation bug resolved and the cosmetic cleanup applied, the series appears ready to be queued in `next` or `seen`; it is not yet recorded as merged to any integration branch. The fix is well-motivated, addresses a concrete gap in Git v3 preparation, and the tests provide good coverage of the edge cases.
