This is a substantive review of the fifth patch in Okhuomon Ajayi's six-patch series removing `the_repository` from the notes subsystem. Christian Couder points out that patch 5/6, titled "notes: pass the repository to the combine_notes callbacks," also modifies `copy_note()` to use the tree's hash algorithm for its null object ID, a change unrelated to the `combine_notes` callback signature updates. He suggests moving the `copy_note()` change into the second or third patch of the series so that the commit title and message better match the actual content. The review engages with the logical organization of the series rather than surface-level details, identifying a scope mismatch between the commit title and its contents without flagging bugs in the code itself. For future reference, the patch under review updates the `combine_notes_fn` typedef to `int (*)(struct repository *, struct object_id *, const struct object_id *)` and modifies the four callbacks (`concatenate_notes()`, `overwrite_notes()`, `ignore_notes()`, `cat_sort_uniq_notes()`) plus `copy_note()` in `notes.c`; the `copy_note()` change specifically switches from using the global hash algorithm to using `t->repo->hash_algo` for constructing the null object ID. The suggested reorganization would split these concerns, keeping the callback signature changes in patch 5/6 while relocating the `copy_note()` hash-algorithm fix to an earlier patch where the `struct notes_tree->repo` field is first introduced.
