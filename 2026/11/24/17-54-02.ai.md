This is a maintainer review approving the second patch in Johannes Schindelin's v2 series "[PATCH v2 0/5] Coverity-inspired integer-overflow fixes". Junio C Hamano confirms the one-line change in `http.c` that switches the local variable `posn` in `fwrite_sha1_file()` from `int` to `size_t` is correct, noting that `xwrite()` already clamps per-call I/O to `MAX_IO_SIZE` and that the `posn/eltsize` division avoids signed-to-unsigned promotion issues. He does, however, ask for the commit message to be reworded because the original text confusingly repeats "in practice" and could be misread as suggesting the overflow accumulates across multiple curl callback invocations; he clarifies that `posn` is reset to zero on every invocation, so the overflow can only occur if a single call passes more than `INT_MAX` bytes (`size = eltsize * nmemb`). The patch itself is unchanged from v1 and is now explicitly approved with "Looking good", leaving only the commit-message wording as an open nit.
