This is a maintainer's review of patch 6/6 in Patrick Steinhardt's six-part packfile lifecycle series. The patch itself adds a three-line check in `close_one_pack()` so that packfiles marked with the `do_not_close` bit are skipped when the code selects a pack to close under process-wide file descriptor limits.

Junio C Hamano engages substantively with the design rationale: since the only command that sets `do_not_close` -- `git fast-import` -- allocates its packs manually and never adds them to the global `all_packfiles` list anyway, he questions whether honoring the bit here is the right fix. He suggests a simpler alternative might be to retire the bit entirely if no one else depends on it being honored in this codepath. Patrick had characterized the current behavior as "fragile coincidence" rather than proper design, but Junio is probing whether the fragility is real enough to warrant the new check, or whether the dead flag should simply be removed. The series remains at v1 under review with no integration status claimed, and this exchange leaves the design question open for a potential v2.
