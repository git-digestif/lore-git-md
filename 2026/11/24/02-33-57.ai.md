This is a review-discussion reply in the ongoing bugfix thread about the sequencer's handling of unborn branches, not a new patch. Wonseok Oh responds to Phillip Wood's substantive review of his fix for the uninitialized `oid` in `sequencer_pick_revisions()` (sequencer.c), agreeing to reword the commit message to cite commit `0f974e2124` (cherry-pick: allow to pick to unborn branches, 2016) as the origin of the uninitialized-variable use.

The email surfaces an open design question about state representation: `rollback_is_safe()` expects a null OID in `.git/sequencer/head` for unborn branches, while `update_abort_safety_file()` writes an empty file in that case. Wonseok asks whether his updated patch should also write an empty `.git/sequencer/head` to align with the latter, and Phillip Wood's earlier suggestion that an empty file may be a better representation of an unborn branch (since no OID exists) is implicitly on the table. No decision is made in this email.

Wonseok also acknowledges Phillip Wood's broader observations about behavioral inconsistencies -- that `sequencer_rollback()` currently refuses to abort when HEAD is unborn yet leaves sequencer state intact (making multi-pick aborts on orphan branches impossible), that single-commit reverts on unborn branches are allowed via a separate path from `7acaaac275` while multi-commit reverts are not, and that the unborn-branch check dates to `04d3d3cfc4` (2011) -- and commits to following up on those separately rather than expanding this series.

For future thread context: the patch under discussion modifies `sequencer_pick_revisions()` in `sequencer.c` to call `oidclr(&oid, r->hash_algo)` when `repo_get_oid(r, "HEAD", &oid)` fails for a non-revert action, and adds a regression test to `t/t3510-cherry-pick-sequence.sh` verifying that `git cherry-pick --abort` on an orphan branch fails with "cannot abort from a branch yet to be born". The likely next step is a v2 of the patch with the reworded message and possibly the empty-file change, pending Phillip Wood's guidance on the state-representation question.
