This is a documentation patch acknowledging maintainer feedback on `Documentation/gitcli.adoc`. Dirk Gouders is replying to Junio C Hamano's review of the v4 iteration, conceding that he inadvertently regressed one wording change while trying to update the commit message and incorporate other fixes.

The dispute centers on the bullet describing how to disambiguate arguments that could be read as either revisions or paths. The v4 text says such arguments "can be disambiguated by placing `--` between them," but Junio points out this is less accurate than the earlier v3 phrasing "before or after it." He illustrates with `git log` examples: for a single ambiguous argument like `git log main` (where `main` is both a file and a branch), the separator can correctly go either before (`git log -- main`) or after (`git log main --`), but for multiple arguments like `git log main next`, simply placing `--` "between them" in typed order does not work -- the user must reorder to `git log next -- main`. The earlier wording captured both cases without misleading readers.

Dirk admits the error plainly, explaining he "failed in this detail" while migrating the topic to v4 and did not intend to revert to the v1 wording that Junio had previously found problematic. He confirms he understands the review comment and implies a corrected version will follow.

The topic remains under review with no merge to any integration branch. The other v4 changes -- grammatical fixes like "conventions" and "When arguments", and the imperative "Split short options into separate words" -- stand accepted; only the disambiguation bullet needs to return to the earlier phrasing before the patch can be queued.
