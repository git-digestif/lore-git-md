This is a feature patch for the `diff-highlight` contrib script, teaching it to highlight paired changes inside `git range-diff` output.

`git range-diff` produces a diff-of-diffs: each line carries an outer marker showing how the patch changed between versions plus an inner marker for the patch itself, and everything sits under a commit-pair header like `1: abc1234 ! 1: def5678` with a four-column indent. The current `diff-highlight` ignores that format entirely -- it fails to strip the indent, misses the `@@` hunk header because range-diff colors it differently, and rejects removed/added pairs because the two-character marker prefix breaks its matching logic. This patch fixes those gaps by detecting the range-diff header, stripping the four-column indent the same way it handles `--graph` prefixes, tolerating color codes inside the `@@` line, and treating either the outer or inner marker as the one that identifies a removed/added line. It also adds a fallback that pairs lines sharing the same outer marker but differing in the inner marker (e.g. `+-old` vs `++new`) when the outer hunk cannot be paired line-by-line.

The change is well-scoped and safe: all new behavior is guarded by having seen a range-diff header, so ordinary diffs are untouched. The commit message is clear about the motivation and the mechanics, and the patch includes three new tests in `t9400-diff-highlight.sh` covering cross-version pairs, within-version pairs, and colored input. This is a solid, self-contained improvement to a contrib tool that many developers pipe diffs through.
