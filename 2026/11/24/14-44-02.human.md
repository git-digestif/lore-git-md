This is a **substantive review** of patch 1/7 in Harald Nordgren's v15 matching-inspired fetch series, in which Junio C Hamano confirms the core logic is correct while flagging two wording issues.

Junio validates that `map_refs_without_dst()` correctly distinguishes between refspecs with an explicit destination and those without: he notes that `rm->peer_ref` is NULL for elements like `main:` (empty destination), so those still flow through `--refmap`, while `src:dst` with a non-empty destination bypasses it, which matches the intended semantics. He asks the author to tighten the documentation to say "non-empty `<dst>`" rather than simply "a destination of its own", since every refspec technically has a `<dst>` field even when empty. He also catches a minor commit-message error, noting that the `fetchRefmap` configuration arrives in 3/7, not 2/7.

The patch itself is well-motivated: it prevents dual storage when a command-line refspec carries its own destination and a configured refmap default is present, which is a prerequisite for the later patches in the series. With these small wording fixes, the change looks ready to proceed.
