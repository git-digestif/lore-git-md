This is a substantive review and approval from the maintainer of a security bugfix for the `git-cvsexportcommit.perl` contrib script.

Junio C Hamano confirms that the patch's conversion of single-argument `system()` calls to list form is both trivially correct and a necessary safety improvement, since `$go_back_to` -- captured via backticks from `git symbolic-ref HEAD` -- can contain shell metacharacters like `;` that are valid in Git refnames but dangerous when passed through `/bin/sh -c`. He validates that `$commit`, which originates from `@ARGV`, is safe because it is cleansed by `git rev-parse --verify`, but endorses retiring the single-arg form as a principle. Regarding the `chomp $go_back_to` placement, Junio notes it looks slightly out of place in the first hunk but ultimately agrees with the patch author's choice to cleanse externally-obtained data as early as possible rather than moving the `chomp` later. He also confirms the hardening of the final checkout with `--end-of-options` and `--` is appropriate to prevent option injection from dash-prefixed refnames. The review concludes with an explicit approval ("Looks good. Thanks.") of the changes to `contrib/git-cvsexportcommit.perl` and the regression test in `t/t9200-git-cvsexportcommit.sh`, which creates a branch named `topic;false` and asserts HEAD is correctly restored after `git cvsexportcommit -W -p -u -c HEAD`.
