This is a refactoring patch, part of the ongoing `the_repository` removal effort in the notes subsystem. It is the third of five patches in Okhuomon Ajayi's v2 series, which aims to make the notes API repository-agnostic by storing a `struct repository *` inside `struct notes_tree`.

The patch converts the write and prune paths in `notes.c` to use `t->repo` instead of the global `the_repository`. Specifically, `write_notes_tree()` now writes objects through `t->repo->objects`, threading the repository pointer through `tree_write_stack_finish_subtree()`, `write_each_note_helper()`, and the `write_each_note_data` callback struct. Similarly, `prune_notes()` checks for object existence via `d->repo->objects` by passing a new `prune_notes_data` struct to `prune_notes_helper()`. The commit also updates `copy_note()` to derive its null object ID from `t->repo->hash_algo` rather than the global `the_hash_algo`.

This follows patch 2/5, which converted the reading path, and precedes planned patches that will handle ref glob helpers and `combine_notes` callbacks. The series deliberately leaves the `USE_THE_REPOSITORY_VARIABLE` guard in place for functions that still depend on the global `default_notes_tree` or lack a repository parameter, a scoping decision that is awaiting Patrick Steinhardt's confirmation before the next iteration. No user-visible behavior changes; the series remains under review with no merge status.
