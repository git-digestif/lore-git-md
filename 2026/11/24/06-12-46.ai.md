This is patch 3/3 of a bugfix series (v5) that eliminates a data-loss race in `git repack -d` caused by `.keep` files appearing between repack's initial pack scan and pack-objects' own scan. The patch implements the snapshot mechanism described in the cover letter: when repack determines it may delete packs (under `-d` with `-a`, `-A`, `--cruft`, or `--geometric`), it writes the basenames of all non-kept and cruft packs to a temporary file in the object directory and passes that file to every spawned `git pack-objects` via the new `--ignore-pack-keep-from=<file>` option introduced in patch 2/3. This ensures pack-objects treats those specific packs as non-kept regardless of any `.keep` files that appear on disk during the run, so their reachable objects are copied into the new pack before the old pack is deleted.

The implementation touches `builtin/repack.c`, `repack.c`, and `repack.h`. In `builtin/repack.c`, after collecting existing packs and sorting the keep list, the code checks `existing_packs_has_non_kept()` and, if true, creates a tempfile named `tmp_non_kept_packs_XXXXXX` in the object directory, writes the pack names via the new `existing_packs_write_non_kept()` helper, and sets `po_args.ignore_pack_keep_from` to the tempfile path. The same path is also propagated to the cruft pack-objects invocation (`cruft_po_args.ignore_pack_keep_from`) so cruft repacks benefit from the same protection. In `repack.c`, `prepare_pack_objects()` appends `--ignore-pack-keep-from=%s` to the command line when the field is set, and `existing_packs_write_non_kept()` writes one `<name>.pack` per line for both non-kept and cruft packs.

Tests added in `t/t7700-repack.sh` and `t/t7703-repack-geometric.sh` reproduce the race by using a `git` wrapper shim placed in `--exec-path` that creates a `.keep` file on the target pack at the moment `pack-objects` starts. The tests cover `-a -d`, `-A -d`, `-a -k -d`, `--cruft -d` (with and without expiration), `--pack-kept-objects`, `--filter`, and `--geometric` modes, verifying with `git fsck` and `cat-file` that no objects are lost even when the `.keep` appears mid-run. The series has received Reviewed-by tags from Jeff King (patch 1/3) and Taylor Blau (patch 3/3) and is considered ready for integration.
