This is a documentation patch (v3) from brian m. carlson warning users against using `http.extraHeader` to pass authentication credentials. It updates three files: `Documentation/config/http.adoc` gains an explicit note that the option should not be used for credentials because doing so can expose them to every server Git contacts or to other users on the system, and because setting an `Authorization` header this way can break external tools like Git LFS that add their own header, resulting in duplicate `Authorization` headers; `Documentation/git.adoc` drops the specific example of `http.extraHeader` as a variable that might hold sensitive values; and `Documentation/gitfaq.adoc` adds a sentence to the existing password-in-URL advice stating that `http.extraHeader` is likewise not recommended for credentials.

The motivation is a recurring real-world misuse: people often use `http.extraHeader` for credentials without URL-qualifying it, leaking them broadly, or they place them where other users can read them. The commit message also highlights the Git LFS conflict, noting that credential helpers avoid this problem because Git LFS only calls them when it lacks credentials. The patch steers readers toward credential helpers, which support modern methods including Bearer tokens.

This third version incorporates the formatting feedback Junio C Hamano gave on v2: the config key is now written in camelCase as `http.extraHeader`, the `Authorization` header name appears in backticks, and a `linkgit:gitcredentials[7]` cross-reference has been added. No substantive objections have been raised, and the patch appears well-crafted and ready for consideration.
