This is the second patch (2/2) of a two-patch bugfix series targeting `git archive` argument handling, specifically the interaction between `--add-file`, `--add-virtual-file`, and `--remote`. It implements a suggestion from René Scharfe to defer filesystem validation until after option parsing completes.

The patch modifies `add_file_cb()` in `archive.c` so that `--add-file` no longer calls `stat()` during `parse_options()`; instead it merely records the path with `info->content = NULL` and a zeroed `struct stat`. The actual `stat()` call and `S_ISREG` check move into `parse_archive_args()`, which now iterates `args->extra_files` after parsing finishes. For each entry with `content == NULL` (i.e., a real `--add-file`), it dies with the "options '--add-file' and '--remote' cannot be used together" message when `is_remote` is set, and only otherwise performs the filesystem probe. Entries with non-NULL `content` (virtual files) are skipped, allowing `--remote --add-virtual-file` to work since no server-side filesystem access is needed. This also preserves the ability of a later `--no-add-file` to cancel an earlier `--add-file` even under `--remote`, because the remote incompatibility check now happens after all options have been processed.

Tests are added to `t/t5000-tar-tree.sh` covering three scenarios: `--remote --add-file` fails with the incompatibility message rather than "File not found", `--no-add-file` successfully cancels a nonexistent `--add-file` both locally and remotely, and `--remote --add-virtual-file` succeeds. The series touches only `archive.c` and `t/t5000-tar-tree.sh` in this patch; patch 1/2 (not shown here) addresses a separate out-of-bounds issue in `write_zip_entry()` in `archive-zip.c`. No merge or integration status is stated; the series is under review as v2.
