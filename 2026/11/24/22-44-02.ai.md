This is a maintainer review of patch v4 3/5 in Ravi Mistry's five-part series on HTTP transport retry handling. Junio C Hamano approves the documentation wording for the new `http.retryStatusCodes` config option, then offers two substantive observations about edge cases in the implementation: first, that setting the config to an empty string disables all retries rather than restoring the default 429-only behavior (a point he suggests documenting); second, that 401 and 404 responses will never be retried even if explicitly listed in the config, because `handle_curl_result()` checks `missing_target()` and 401 before consulting `is_retryable_http_code()`. The review is substantive despite its brevity -- it identifies a specific ordering constraint in the retry decision path that constrains which codes are actually retryable regardless of configuration. He closes with "Overall looking very good," indicating approval of the patch modulo the noted documentation suggestions.
