This is a bugfix for `git log --graph` ASCII rendering, specifically correcting output for left-skewed octopus merges with three or more parents. Dominik Maier's v2 patches `graph.c` to fix a case where the edge to a second parent disappears, and where four or more parents cause subsequent columns to shift one slot too far left, triggering an out-of-bounds read at `graph->new_columns[-1]` inside `graph_draw_octopus_merge()`.

The bug lives in `graph_insert_into_new_columns()`, where a shortcut meant to fuse a column to the right of a merge with the merge's last edge was incorrectly firing for left-skewed merges. Because a left-skewed merge's first parent does not advance `graph->width`, the "last edge" comparison ended up matching the column immediately to the left of the merge, swallowing the parent's own edge and corrupting the mapping for later parents.

The fix adds an `idx < 0` guard so the fusion shortcut applies only to existing non-merge columns, which is the case it was originally written for. The v2 revision also rewords the commit message to show the 3-parent missing-edge case with ASCII art alongside the 4-parent out-of-bounds scenario, adds a regression test for the simpler 3-parent case, and drops the defensive `BUG()` assertion from v1 after Caspar Duregger questioned whether a hard crash was preferable to graceful degradation. Two new tests in `t/t4215-log-skewed-merges.sh` cover both the 3-parent and 4-parent left-skewed octopus scenarios.

Caspar Duregger has reviewed the approach and confirmed the `idx < 0` guard is correct, supplying the simplified 3-parent reproduction now included in the patch. The contribution is well-scoped with targeted tests and a clear commit message; it remains under review and has not been queued in any integration branch yet.
