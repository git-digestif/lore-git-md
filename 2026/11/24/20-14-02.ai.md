This is a substantive review of patch 2/3 in Yoichi NAKAYAMA's v2 series on worktree-specific submodule configuration. Junio C Hamano examines the diff that routes submodule config writes into `config.worktree` and filters gitdir entries during `git worktree add`, raising two concrete correctness concerns and two process suggestions.

The first issue concerns `is_submodule_active()`, which expects a submodule path rather than its name. The patch calls this function with `sub->name` in both the initialization and deinitialization paths shown in the diff, which breaks when a submodule's name differs from its path (for example after moving the submodule within the superproject). Junio notes this would produce wrong behavior in exactly the scenario the worktree feature aims to support, and suggests adding test coverage for name/path divergence in `t/t2405-worktree-submodule.sh`.

The second issue targets `copy_filtered_worktree_config()` in `builtin/worktree.c`, which strips `submodule.<name>.gitdir` entries when creating a new linked worktree. The current loop uses `repo_config_set_in_file_gently()` to unset each matching key, but this fails to remove duplicate entries if the source config contains more than one `gitdir` line for the same submodule. Junio recommends switching to `repo_config_set_multivar_in_file_gently()` with `CONFIG_FLAGS_MULTI_REPLACE` so all duplicates are cleared.

Junio also asks whether `Documentation/config/submodule.adoc` should explain how the various `submodule.<name>.*` keys interact with `extensions.worktreeConfig`, since the patch touches several of those keys but the documentation update in this patch only mentions `gitdir`. This remains an open question alongside the earlier static-buffer lifetime hazard he flagged in patch 1/3's `create_default_gitdir_config()`. No other reviewers have weighed in on patch 2/3 yet, so these points are the current state of discussion.
