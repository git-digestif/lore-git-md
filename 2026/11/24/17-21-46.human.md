This is a refactoring patch, the fifth and final one in a five-patch series aimed at removing implicit uses of the global `the_repository` from Git's notes subsystem as part of the ongoing `the_repository` removal effort. Okhuomon Ajayi completes the series by converting the `combine_notes_fn` callback interface to accept an explicit `struct repository *` parameter, updating the typedef in `notes.h` and all four built-in combinators -- `combine_notes_concatenate()`, `combine_notes_overwrite()`, `combine_notes_ignore()`, and `combine_notes_cat_sort_uniq()` -- to read and write note blobs through the provided repository rather than `the_repository`. The static helper `string_list_add_note_lines()` is likewise updated to take the repository, and the sole call site in `note_tree_insert()` now passes `t->repo` to the callback, ensuring that note merging always operates on the repository that owns the notes tree.

The patch is purely internal and introduces no user-visible behavior changes, on-disk format differences, or new configuration options. It follows the structural groundwork laid in earlier patches of the series, which added a `struct repository *repo` field to `struct notes_tree` and converted the core read, write, and prune paths to use it. By threading the repository through the combine callbacks as well, this final patch closes the remaining gap in `notes.c` where the merge strategy functions still relied on the global repository, making those code paths fully repository-agnostic. The series remains under review with no merge status indicated.
