This is a review reply from Junio C Hamano on the first patch of Patrick Steinhardt's six-patch packfile lifecycle series, which removes packfile statistics from `git fast-import` output. The review is substantive rather than surface-level: beyond correcting typos in the commit message ("shoudln't" to "shouldn't", "kind of" to "kinds of"), Junio identifies a factual inaccuracy in the claim that `pack_report()` reports the number of packs opened, clarifying that it actually prints `getpagesize()`, the `core.packedGitWindowSize` and `core.packedGitLimit` config values, the `pack_used_ctr` window-switch counter, `pack_mmap_calls`, and current/peak values for `pack_open_windows` and `pack_mapped`. He nevertheless agrees with the patch's premise that these metrics are aimed at Git developers rather than end users.

Junio also catches a user-visible string that the patch missed: the `--stats` option description in `cmd_fast_import()`'s `fast_import_option[]` array still reads "display some basic statistics (objects, packfiles and memory)", which should be updated to drop the packfile reference now that the new design no longer reports them. He confirms that removing the `pack_report(repo)` call correctly allows the `repo` parameter of `cmd_fast_import()` to be marked `UNUSED`, and he notes that deleting the four counters that existed solely for that report (`pack_mmap_calls`, `pack_open_windows`, `peak_pack_open_windows`, and `peak_pack_mapped`) is clean.

The patch under review deletes `pack_report()` from `packfile.c` and `packfile.h`, removes its invocation and the now-unused counters from `builtin/fast-import.c`, and updates `Documentation/git-fast-import.adoc` to remove packfile details from the `--stats` description. For future sessions, the key technical takeaway is that Junio's feedback signals the commit message needs revision to accurately describe `pack_report()`'s actual output and that the option help text in `builtin/fast-import.c` requires a corresponding update to match.

No objections to the core change are raised; the feedback is constructive and focused on accuracy of description and completeness of the removal. The series remains under review with no merge status claimed. Future follow-ups in this thread should expect a v2 that incorporates the wording corrections, the accurate description of the removed statistics, and the fix to the `--stats` option string.
