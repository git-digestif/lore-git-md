This is a substantive review from Junio C Hamano on Wonseok Oh's bugfix for `git cherry-pick` on unborn branches. The patch itself fixes an uninitialized OID in `sequencer_pick_revisions()` that causes `--abort` to fail with "Could not parse object" or undefined behavior instead of the intended "cannot abort from a branch yet to be born" message; Phillip Wood has already endorsed the approach of saving the null OID for backwards compatibility.

Junio's feedback focuses on two things. First, he asks for commit-message tightening: the first paragraph should more clearly connect the `oidclr()` call to the `sequencer_rollback()` check, the second paragraph should describe the general undefined-behavior failure modes rather than anecdotal symptoms from specific builds, and the trailing "and add a test" should be dropped. Second, he questions the strength of the proposed regression test, noting that if the stack variable happened to be zero-initialized the test could pass by coincidence, or fail with the wrong error in `rollback_is_safe()`. He suggests the test should assert the specific "cannot abort" error message and verify that `.git/sequencer/head` actually contains `$ZERO_OID` to harden it against accidental passes.

The patch remains under review with no integration status; the author has already agreed to reword the commit message in a forthcoming v2.
