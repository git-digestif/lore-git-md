This is a process discussion within the `promisor.fetchOrder` RFC thread, not a technical patch.

Christian Couder replies to Junio C Hamano's proposal to restructure Outreachy projects into three tiers (microprojects for community engagement, mid-sized projects for capability demonstration, and full-scale projects for accepted interns). Couder agrees the tiered approach would be valuable but notes the difficulty lies in curating the project lists. He mentions developing an AI-based tool that automatically generates GitLab issues from mailing list discussions and classifies them with labels such as "microproject" or "middle size project", with hopes to make it available soon.

This email advances only the meta-discussion about Outreachy procedures; it does not address the unresolved design question about how client-side `promisor.fetchOrder` should interact with server-advertised promisor remote order in multi-remote scenarios. The RFC patch remains in its current state with no new technical progress, and the fundamental limitation identified earlier—that a static client-side order cannot handle divergent server-side advertisements across different remotes—remains the sole blocker for substantive review.
