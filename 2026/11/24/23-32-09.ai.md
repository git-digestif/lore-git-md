This is a refactoring patch, specifically the first of three in Erik Cervin-Edin's v4 series that enables all message-specification options (`-m`, `-F`, `-c`, `-C`) across every `--fixup` variant (`--fixup`, `--fixup=amend:`, `--fixup=reword:`). The series restructures how `git commit` composes messages for fixup commits; this particular patch prepares the ground by aligning `--fixup` with the existing `--squash` behavior.

The patch modifies `prepare_to_commit()` in `builtin/commit.c` to write the `fixup!` or `amend!` subject line in its own block at the top of the message-source chain, before the if/else-if arms that handle `-m`, `-F`, `-c`/`-C`, and the editor. Previously the fixup subject was written inside the fixup arm near the end of the chain; now it is written first, mirroring how `--squash` has always inserted its `squash!` subject before other message options contribute content. Because the `-m` arm now precedes the fixup arm in the chain, the error for combining `-m` with `--fixup=amend:` has been moved into the new subject block so it is still caught. The local variable previously named `commit` is renamed to `c` to match the style of the adjacent `--squash` block.

This is purely a structural change with no user-visible behavior difference yet; it removes the `!fixup_message` guards that previously prevented the `-m` arm from running when a fixup was requested. The follow-up patches in the series (2/3 and 3/3) will use this new structure to actually enable `-m`/`-F` and `-c`/`-C` for all fixup variants. The patch touches only `builtin/commit.c`, with the commit message providing clear historical references to the original `--fixup` (d71b8ba7c9) and `--squash` (89ac1223c0) introductions and the later `-m` support (30884c9afc).
