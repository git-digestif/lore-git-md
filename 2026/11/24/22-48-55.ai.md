This is a small refactoring patch to `imap-send.c` that improves the readability of the header-scanning loop without changing its behavior. The patch modifies `has_required_headers()`, a static function that iterates through message lines looking for required `From:`, `Date:`, and `Subject:` headers until it encounters the empty line that terminates the header block. The previous loop condition advanced the `line` pointer inline via `*++line` and then tested separately for LF and CRLF empty-line endings, which made the CRLF check implicitly dependent on the preceding LF advancement and easy to misread. The new code checks for both terminator styles symmetrically up front using `starts_with(line, "\n\n")` for LF and `starts_with(line, "\n\r\n")` for CRLF before executing a standalone `line++`, making the loop's control flow clearer.

The change was suggested by Patrick Steinhardt during review of an earlier imap-send series that has already reached `master`, as noted in the commit message's link to the lore.kernel.org thread. Harald Nordgren implemented this as a standalone follow-up cleanup. The diff is minimal -- three insertions and one deletion confined to the `while` loop condition in `imap-send.c`.

The commit message explicitly states that behavior does not change, which the code confirms: both versions detect the same header-terminating empty line regardless of whether the message uses LF or CRLF line endings. This is a low-risk, purely cosmetic cleanup typical of the ongoing polish applied to recently merged code.
