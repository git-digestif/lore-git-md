This is a documentation patch, now in its third iteration, from brian m. carlson warning users against using `http.extraHeader` for authentication credentials. It is a standalone patch, not part of a larger series.

The patch touches three files. In `Documentation/config/http.adoc`, it adds a note to the `http.extraHeader` entry explaining that the option should not be used to pass credentials because doing so can expose them to every server Git contacts or to other users on the system, and because setting an `Authorization` header this way can break external tools like Git LFS that add their own `Authorization` header, resulting in duplicate headers. It recommends credential helpers instead, noting that modern helpers support methods including Bearer tokens and linking to `linkgit:gitcredentials[7]`. In `Documentation/git.adoc`, the patch replaces a specific example naming `http.extraHeader` as a sensitive variable with a generic statement about variables where sensitive data appears in the value. In `Documentation/gitfaq.adoc`, it appends a sentence to the existing advice against putting passwords in URLs, adding that `http.extraHeader` is similarly not recommended for credentials.

Version 3 incorporates the formatting adjustments Junio C Hamano requested after v2: the config key is now written in camelCase as `http.extraHeader` throughout, the header name `Authorization` is wrapped in backticks, and the `gitcredentials(7)` cross-reference has been added. The substantive content remains unchanged from v2, which had already fixed a missing word ("used") that Junio noted in v1.

The commit message gives a clear motivation: users frequently misuse `http.extraHeader` for credentials despite the security risks and the known breakage with tools that manage their own auth headers. The change is documentation-only with no code or test modifications. As of this email, the patch is under review with no substantive objections raised, only the formatting polish that v3 now addresses.
