Phillip Wood has posted a small feature patch adding a new `GIT_COMMENT_STRING` variable to `git var`. The change exposes the effective comment string Git uses for template commit messages and rebase todo lists -- currently derived from either `core.commentChar` or `core.commentString` but not directly queryable -- so scripts no longer need to parse config keys or run shell pipelines to discover which character Git will actually use. The motivation traces back to commit 9ccf3e9b22, which introduced `core.commentString`.

The implementation is minimal and self-contained: a `comment_string()` helper in `builtin/var.c` returns the global `comment_line_str`, which is registered in the `git_vars[]` table alongside existing entries like `GIT_EDITOR` and `GIT_DEFAULT_BRANCH`. Documentation is added in `Documentation/git-var.adoc` and tests in `t/t0007-git-var.sh` cover both the default `#` and a custom `core.commentString` value. No existing command behavior changes.

As a standalone patch at the thread root, it is currently under review with no decisions or merge status recorded yet.
