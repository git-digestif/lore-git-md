Phillip Wood's patch to add a `GIT_COMMENT_STRING` variable to `git var` is under review on the mailing list. The change would let scripts query the effective comment character directly instead of parsing both `core.commentChar` and `core.commentString` config values through awkward shell pipelines. The patch touches `builtin/var.c`, the documentation, and adds test coverage in `t/t0007-git-var.sh`, with no changes to existing command behavior.

Junio C Hamano has reviewed the series and acknowledged that the motivation addresses a real scripting pain point, though he noted a pre-existing wrinkle: because the two comment-related config keys use last-one-wins semantics, scripts still cannot simply prefer one over the other when both are set. This observation flags an inconsistency for future discussion but does not block the patch. Kristoffer Haugsbakk also provided substantive feedback earlier, suggesting the commit message and man page use "comment string" consistently and cross-reference both config keys in `git-config(1)`.

The series remains under review with no merge decision indicated yet. The only open items are the non-blocking documentation and wording suggestions from reviewers.
