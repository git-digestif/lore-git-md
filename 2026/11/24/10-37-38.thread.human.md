This thread is a standalone patch from Phillip Wood adding a new `GIT_COMMENT_STRING` variable to `git var`, so scripts can query the effective comment string directly instead of parsing `core.commentChar` and `core.commentString` themselves. Junio C Hamano reviewed the motivation as sound, and Kristoffer Haugsbakk gave a substantive review confirming the test coverage in `t/t0007-git-var.sh` is adequate, including the empty-string edge case that causes a fatal abort. In his response, Wood agreed to reword the commit message from "comment character" to "comment string," but gently pushed back on fully documenting the config sources in `git-var.adoc`, proposing instead a brief "as set by `core.commentString`" mention and adding a cross-reference from `git-config(1)` back to the new variable. The patch touches only `builtin/var.c`, `Documentation/git-var.adoc`, and `t/t0007-git-var.sh`, remains under review with no blocking objections or merge decision indicated, while Junio separately flagged the pre-existing last-one-wins inconsistency between the two comment config keys as a possible future discussion.
