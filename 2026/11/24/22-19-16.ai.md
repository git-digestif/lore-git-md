This is a review reply supporting Patrick Steinhardt's patch 1/6 with a suggestion for a broader follow-up change. brian m. carlson agrees that packfile statistics should not be printed by default but argues that in a future series all `git fast-import` statistics should be disabled unless explicitly requested via `--stats`, aligning with the Unix philosophy of silence on success. They cite a concrete use case: automated tests that convert repositories from SHA-1 to SHA-256, where they monitor standard error for real errors but find the default statistics output clutters test logs, forcing them to pass `--quiet` to suppress the noise. The reply does not raise any technical objections to the patch itself, only advocating for extending the same principle to the remaining statistics.

For future thread context: this signals potential interest in a follow-up that changes the default behavior of `git fast-import` statistics from on-by-default to opt-in via `--stats`. The `fast_import_option[]` array in `builtin/fast-import.c` currently advertises `--stats` as displaying "basic statistics (objects, packfiles and memory)" -- patch 1/6 removes the packfile reference, and brian's comment suggests the entire option could eventually become the sole way to enable any stats output.
