This is a documentation patch for the reftable technical specification. Daniel Scherzer updates `Documentation/technical/reftable.adoc` to correct the "First ref block" section: the documentation previously stated that the file header is always 24 bytes and that the first ref block always begins at position 24, but following the introduction of version 2 headers (which are 28 bytes), the starting offset of the first ref block now depends on the file format version -- position 24 for version 1 headers and position 28 for version 2 headers. The patch touches only the AsciiDoc documentation, changing four lines to reflect this version-dependent offset in both the general description and the log-block-specific note. This is a small, well-scoped fix that keeps the reftable format documentation accurate as the format evolves, and it is part of the broader reftable backend integration effort.
