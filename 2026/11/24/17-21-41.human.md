This is a cover letter for a five-patch preparatory series that continues the ongoing `the_repository` removal effort in the notes subsystem. Okhuomon Ajayi reframes the work as a scoped first step: rather than converting the entire notes subsystem at once, the series stores a `struct repository *` inside `struct notes_tree` and updates the core functions in `notes.c` to use that stored repository instead of the global `the_repository`. The ref glob helpers and the `combine_notes` callbacks are also changed to accept an explicit repository parameter, and the direct callers in `builtin/notes.c`, `notes-cache.c`, and `notes-utils.c` are adjusted to pass it through.

Compared to the previous iteration, the author has dropped the final patch that would have removed the `USE_THE_REPOSITORY_VARIABLE` guard from `notes-utils.[c,h]`, deliberately keeping the series inside `notes.[c,h]` and its immediate callers. The `copy_note()` change to use the tree's hash algorithm has also been moved from the callbacks patch into the writing-and-pruning patch, where it logically belongs. The cover letter explicitly lists what remains for future work: the display-notes code that still relies on global state, the hash-size helpers still using the global `the_hash_algo`, `notes-utils.[c,h]`, and `notes-merge.[c,h]`.

The series is under active review with no merge status yet. It directly addresses Patrick Steinhardt's architectural concern by fixing the root cause in `notes.c` rather than papering over it with downstream guards, and it appears well-scoped and mechanically clean. Reviewers are likely to focus on whether the remaining `USE_THE_REPOSITORY_VARIABLE` guard in `notes.c` is correctly scoped to the functions that genuinely still need global state.
