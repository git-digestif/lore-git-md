This is a feature patch, specifically the second of three in Erik Cervin-Edin's v4 series that enables non-interactive message specification for all `git commit --fixup` variants. Patch 2/3 extends `-m` and `-F` support to `--fixup=amend:` and `--fixup=reword:` (previously only plain `--fixup` accepted `-m`, and no variant accepted `-F`), while `-c`/`-C` are deferred to the following patch.

The core change in `builtin/commit.c` removes the error that previously forbade combining `-m` with `--fixup=amend:` inside `prepare_to_commit()`, and drops `-F` from the `die_for_incompatible_opt` check that guarded `--fixup`. This builds directly on patch 1/3's refactoring, which moved the `--fixup` subject-line writing ahead of the message-source chain so the `-m`/`-F` arms no longer need `!fixup_message` guards. Behaviorally, when `--fixup=amend:` or `--fixup=reword:` is used with `-m` or `-F`, the supplied message replaces the log message that would otherwise be copied from the target commit, rather than triggering a fatal error.

Tests in `t/t7500-commit-template-squash-signoff.sh` are updated to assert the new behavior: `--fixup=reword:` and `--fixup=amend:` now succeed with `-m`, plain `--fixup` and `--fixup=reword:` succeed with `-F`, and an empty `-m ""` with `--fixup=amend:` still correctly fails. The documentation in `Documentation/git-commit.adoc` is updated to describe that `-m` or `-F` may supply the replacement message for amend/reword fixups, bypassing the editor. The patch touches only `builtin/commit.c`, the man page, and the test script, with no changes to on-disk formats. The series remains under review with no outstanding technical objections.
