This is a substantive code review by Junio C Hamano of patch 1/3 in Yoichi NAKAYAMA's v2 series on worktree-relative submodule gitdir paths. Junio identifies a static-buffer lifetime hazard in `create_default_gitdir_config()` where `modules_dir` may point into the four-slot ring buffer returned by `worktree_git_path()`, and notes that `relative_path()` can return a pointer directly into that buffer when the worktree path is a directory prefix of the modules path, without populating the temporary strbuf. He warns that patch 3's calls to `worktree_git_path(wt, "config.worktree")` inside `validate_and_set_submodule_gitdir()` could wrap that ring buffer across multiple failure cases and overwrite `modules_dir` while it is still in use. To close this hole, he suggests unconditionally copying the result with `xstrdup` (using either the relative or absolute form) and freeing it under the cleanup label, rather than conditionally relying on the strbuf. He also acknowledges that the v2 changes correctly fix the previous leak and buffer hazard in the else branch by copying into a local strbuf immediately, and that converting early returns to `goto cleanup` plugs pre-existing strbuf leaks. No merge status is mentioned; the series remains under review with this feedback outstanding.
