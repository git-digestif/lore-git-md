This is a **feature patch series cover letter** -- v4 of Erik Cervin-Edin's effort to let `git commit --fixup` accept every message-specification option (`-m`, `-F`, `-c`, `-C`) across all three `--fixup` variants (plain, `amend:`, and `reword:`).

The headline change in this iteration is a new first patch that refactors `prepare_to_commit()` in `builtin/commit.c` to write the generated `fixup!` subject line up front, the same way `--squash` already does. This restructure lets the `-m` and `-F` code paths serve every `--fixup` variant without the awkward `!fixup_message` guards that Phillip Wood flagged in v3, leaving the fixup-specific arm to handle only the `amend:` case. Patches 2/3 and 3/3 are rebuilt on top of this foundation, with 2/3 enabling `-m`/`-F` for all variants and 3/3 adding `-c`/`-C`, completing the matrix so that every message source behaves consistently whether the user is creating a plain fixup, an amend fixup, or a reword fixup.

Erik has also incorporated Phillip Wood's test-hygiene suggestions from the previous round: tests for `-C` now suppress the editor with `GIT_EDITOR=false`, and tests for `-c` verify the editor actually runs using `GIT_EDITOR="echo edited >>"`. The series touches only `builtin/commit.c`, `Documentation/git-commit.adoc`, and `t/t7500-commit-template-squash-signoff.sh`, with no changes to on-disk formats or core data structures. Backward compatibility is preserved -- when no message option is given, the editor still launches as before.

The commit messages have been reworded to better explain the history of why these options were previously rejected and to document the intentional behavior where `-c`/`-C` with an `amend:` fixup strips `amend!` lines from the source commit's message. Erik notes he has dogfooded the feature for months, and the thread summary indicates no outstanding technical objections remain from Junio Hamano or Phillip Wood. The series is currently under review, awaiting the v4 reroll to be picked up.
