This is a documentation patch for the reftable format specification. Daniel Scherzer updates `Documentation/technical/reftable.adoc` to correct the description of where the first ref block begins in a reftable file. The existing text assumed the file header was always 24 bytes, which was true for version 1 headers but not for the recently introduced version 2 headers, which are 28 bytes. The patch clarifies that the first ref block starts at offset 24 for version 1 files and offset 28 for version 2 files, and that the first block is correspondingly smaller than subsequent blocks by 24 or 28 bytes depending on the header version.

The change is small and focused, touching only the "First ref block" section of the technical documentation with four insertions and three deletions in a single AsciiDoc file. No code is modified. The commit message clearly states the motivation: the documentation had become stale after version 2 headers were introduced, leaving the byte offsets incorrect for the newer format version.

As a standalone documentation fix, this patch appears well-crafted and uncontroversial. It corrects a concrete factual error in the specification rather than making stylistic changes, which is exactly the kind of maintenance the reftable documentation needs as the format evolves. Anyone implementing or debugging the reftable backend from the spec will benefit from having the header-version distinction documented explicitly.
