This is a three-patch feature series introducing a configuration knob to disable orphaned commit warnings during `git checkout` and `git switch`, motivated by performance issues in large mono-repos.

The series adds `checkout.orphanedCommitWarning` (enabled by default) to skip the reachability check that currently runs when leaving a detached HEAD. The check can be expensive—Trace2 data from an internal Microsoft mono-repo showed it consuming 193 seconds out of a 205-second checkout. A new Trace2 region exposes the check’s duration, and when it exceeds two seconds, Git now advises users about the opt-out via `advice.checkoutOrphanedCommitWarning`. The third patch disables the check by default in Scalar, using its existing set-if-missing mechanism to preserve any explicit user setting.

Files touched include the checkout built-in, advice subsystem, Scalar integration, and new tests in `t2020-checkout-detach.sh`. The default behavior for ordinary Git users remains unchanged; only users who explicitly disable the setting (or use Scalar) lose the warning about commits left behind, though those commits remain recoverable via the HEAD reflog. The series is authored by Wyatt Holden, a Microsoft engineer collaborating with Derrick Stolee.
