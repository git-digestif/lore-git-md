This is a refactoring and correctness patch series targeting the object database (ODB) transaction machinery. It is part of the ongoing ODB abstraction effort led by Patrick Steinhardt.

The series changes how Git creates the temporary directory used during ODB transactions. Currently, the directory is created lazily on the first object write, but this series makes creation eager—happening as soon as the transaction begins. The motivation is to ensure that *all* transactional object writes go to the temporary directory, not just those with batched fsync enabled. The commit message frames this as a correctness fix: previously, some writes might bypass the temporary directory entirely, which could lead to subtle inconsistencies if the transaction later fails or is rolled back.

Four patches: the first three are small preparatory refactors (renaming a constant, cleaning up fsync logic, preserving `errno` in `tmp-objdir.c`), and the fourth implements the main change. The diff shows a net reduction in code (54 insertions, 82 deletions), mostly from removing the now-unused lazy-creation logic in `object-file.c` and `odb/source-loose.c`. The test `t0004-unwritable.sh` is updated to reflect the new behavior.

The series is based on `3c60ef1e38` (The 17th batch, 2026-11-08) with `jt/tmp-objdir-loose-idx-merge` merged in, situating it squarely in the ODB transaction workstream. No controversy is evident from the cover letter, and the changes appear mechanical and well-scoped. The author, Justin Tobler, is a regular contributor to the ODB abstraction effort, and his patches in this area are typically reviewed by Patrick Steinhardt and others working on the same subsystem.
