This is patch 13/15 in the v2 bugfix series addressing Git segfaults when config settings lack values. The patch prevents crashes in `includeIf` matching for `remote.*.url` by skipping valueless URLs in `add_remote_url()`. The fix is minimal: a single NULL check (`value`) before appending the URL to the list used for pattern matching. The test verifies that `includeIf.hasconfig:remote.*.url:foourl` does not match when another remote (`valueless`) has a URL key without a value, ensuring commands like `git log` no longer segfault. This aligns with the series' established pattern of graceful handling for edge cases (e.g., `fetch.bundleCreationToken` defaulting to 0) rather than rejecting them with `config_error_nonbool()`. The commit message clarifies that valueless URLs are already rejected elsewhere (e.g., `handle_config()` in `remote.c`), so skipping them here preserves consistency without introducing new behavior. No new symbols or API changes are introduced. The patch is well-motivated and directly addresses a crash site identified in the audit.
