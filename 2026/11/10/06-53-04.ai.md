This is a follow-up in the GitLab CI speedups thread, specifically addressing Junio C Hamano’s portability concern about the `tar -xf` command in `ci/install-sdk.ps1` (patch 1/7 of the series). Patrick Steinhardt responds to Junio’s suggestion to document the assumption that the environment provides a BSD-derived `tar` capable of handling ZIP archives.

Patrick argues that the assumption is already broadly valid: `bsdtar` (based on `libarchive`) is now distributed with Windows by default, so the command should work in most CI environments without issue. He acknowledges that the commit message could clarify this but sees no need for an in-code comment, as the behavior is expected to be portable. He also floats the idea of unifying GitHub Workflows with the GitLab CI script — a change he previously reverted due to performance issues — now that the slowness has been resolved. However, he defers this decision to Johannes Schindelin (Dscho), the maintainer of Git for Windows, and keeps it out of the current series.

The exchange is surface-level: no functional changes are proposed or required, and the discussion remains focused on documentation and future compatibility. The broader series (seven patches targeting CI bottlenecks) is still on track for queuing, with Junio having already stated no technical objections.
