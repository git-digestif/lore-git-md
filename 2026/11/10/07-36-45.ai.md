This is the final patch in Thomas Bachem’s 15-patch bugfix series, targeting a regression introduced in Git 2.54.0 (commits 2d4ab5a885 and 9cb4a5e1ba). The patch fixes a segfault in `git config list --type=color` and `--type=expiry-date` when encountering config keys without values (e.g., `git -c section.valueless`). The fix adds NULL checks in `format_config_color()` and `format_config_expiry_date()` to silently skip valueless keys, matching the existing behavior for unparseable values and aligning with `--type=int`. The test verifies that the commands no longer crash and omit the problematic key from output.

The change is minimal and surgical: two lines of code, each guarding a call to `color_parse_quietly()` or `parse_expiry_date()` with a `!value_` check. The test coverage is thorough, confirming both `--type=color` and `--type=expiry-date` handle valueless keys identically. This patch completes the series’ goal of eliminating segfaults from unvalued config keys, and its inclusion in v2 reflects the author’s attention to edge cases. The regression it fixes was introduced earlier this year, making this a timely and well-motivated fix. No further changes are expected; the patch is ready for merge once the series’ test conflicts in `seen` are resolved.
