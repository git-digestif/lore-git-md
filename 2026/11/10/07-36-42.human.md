This is the twelfth patch in Thomas Bachem’s v2 series fixing Git segfaults when config keys lack values. It targets the `scalar` subsystem, preventing a crash in `scalar reconfigure --all` when `scalar.repo` is given without a value. The fix is minimal: a NULL check in `get_scalar_repos()` rejects missing values with `config_error_nonbool()`, matching the series’ established pattern. The test verifies the error message is clear and the command fails gracefully.

The patch is well-motivated and safe. The commit message explains why this cannot break existing setups (`scalar register` always writes a path), and the test coverage is sufficient. Derrick Stolee’s earlier review of v1 endorsed this approach, and no further changes were requested. This is a straightforward bugfix that fits cleanly into the broader effort to harden Git against unvalued config keys.
