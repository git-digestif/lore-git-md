Thread identity: Subject "[PATCH 0/6] odb: eagerly create tmp-objdir at transaction start", series version v2, originating author Justin Tobler, thread type patch series (correctness/refactoring) within the ODB abstraction effort.

Core problem or goal: The series addresses a correctness gap in Git's ODB transaction machinery where the temporary directory is created lazily on first object write, causing some writes (those not using batched fsync) to bypass the temporary directory entirely. The goal is to make temporary-directory creation eager at transaction start so all transactional object writes go to the temporary directory immediately.

Current status: Under review; v2 complete with all six patches posted. Based on commit `3c60ef1e38` (The 17th batch, 2026-11-08) with `jt/tmp-objdir-loose-idx-merge` merged in. The v2 respin expands the series from 4 to 6 patches and incorporates all feedback from the v1 review cycle. Patch 1/6 renames the default temporary directory prefix from `"bulk-fsync"` to `"transaction"` in `odb_transaction_files_begin()` within `object-file.c`. Patch 2/6 extracts the batched-fsync flush logic from `odb_transaction_files_commit()` into a new static helper `flush_batched_fsync()` in `object-file.c`, guarded by `batch_fsync_enabled(FSYNC_COMPONENT_LOOSE_OBJECT)`. Patch 3/6 inlines the static helper `setup_tmp_objdir()` into its sole caller `tmp_objdir_create()` in `tmp-objdir.c`, moving the `mkdir` of the `pack` subdirectory directly into the creation function as preparatory cleanup for a subsequent patch that will make `tmp_objdir_create()` preserve `errno` on failure; this touches only `tmp-objdir.c` (13 deletions, 6 insertions, no behavior change). Patch 4/6 modifies `tmp-objdir.c` and `tmp-objdir.h` so that `tmp_objdir_create()` preserves `errno` across its internal cleanup when directory creation fails, introducing a local `saved_errno` variable, converting the two early-return failure paths (after `mkdtemp` and after `mkdir` of the `pack` subdirectory) to a single `error` label, and restoring `errno` from `saved_errno` before returning NULL; the header comment is updated to document that the function now sets `errno` on failure, serving as groundwork for patch 6/6. Patch 5/6 touches only `odb/transaction.h`, replacing the jargon term "ODB" with "object" in three user-facing `die()` messages emitted by the inline helpers `odb_transaction_begin_or_die()` and `odb_transaction_commit_and_finalize_or_die()`: "failed to start ODB transaction", "failed to commit ODB transaction", and "failed to finalize ODB transaction" become "failed to start object transaction", "failed to commit object transaction", and "failed to finalize object transaction" respectively; this is a purely cosmetic wording change with no behavioral impact. Patch 6/6 implements the core change by moving temporary directory creation from the lazy `odb_transaction_files_prepare()` called on first object write into `odb_transaction_files_begin()` itself, so every files-backend transaction creates its `tmp_objdir` up front using either the `"transaction"` or `"incoming"` prefix depending on the `ODB_TRANSACTION_RECEIVE` flag; it removes the now-unused `odb_transaction_files_prepare()` function, the `prefix` field from `struct odb_transaction_files`, and the conditional lazy-creation calls in `write_loose_object()` and `odb_source_loose_write_object_stream()` in `odb/source-loose.c`, ensuring all transactional loose object writes are staged in the temporary directory regardless of the configured `core.fsyncMethod`. All reviewer concerns from v1 are addressed in v2 pending further review, though no `Reviewed-by` or `Acked-by` trailers have been recorded yet.

Key technical details: Files touched: `object-file.c`, `object-file.h`, `tmp-objdir.c`, `tmp-objdir.h`, `odb/source-loose.c`, `odb/transaction.h`, and test `t/t0004-unwritable.sh`. Patch 1/6 renames the default `transaction->prefix` from `"bulk-fsync"` to `"transaction"` in `odb_transaction_files_begin()`, since the old name dates to commit `c0f4752ed2` (core.fsyncmethod: batched disk flushes for loose-objects, 2022-04-04). Patch 2/6 modifies only `object-file.c` to introduce `flush_batched_fsync()` which creates a temporary file named `bulk_fsync_XXXXXX` in the object directory and fsyncs it as a durability barrier, now guarded so it only executes when batched fsync is enabled. Patch 3/6 inlines `setup_tmp_objdir()` into `tmp_objdir_create()` with the explicit `xstrfmt`, `mkdir`, and `free` sequence replacing the helper call, so that `errno` preservation in a later patch only needs handling in one place. Patch 4/6 implements the `errno` preservation in `tmp_objdir_create()` via a `saved_errno` local and single `error` exit label, updating `tmp-objdir.h` to document the new `errno` guarantee. Patch 5/6 modifies three `die()` message strings in `odb/transaction.h` to use "object" instead of "ODB" for user-facing clarity. Patch 6/6 touches `object-file.c`, `object-file.h`, `odb/source-loose.c`, and `t/t0004-unwritable.sh` with a net reduction of 44 lines, moving tmp_objdir creation to `odb_transaction_files_begin()` and removing lazy creation from the write paths; the behavioral consequence is that committing a transaction now migrates every written object into the primary object directory even when batched fsync is disabled. Test `t/t0004-unwritable.sh` updated with new messages including `fatal: failed to start object transaction` and `error: unable to create temporary object directory in .git/objects: Permission denied`. On-disk format unchanged. Net code change across the series: 37 deletions net (63 insertions, 100 deletions). Micro-benchmark shows 7% slowdown for `git add` writing 10,000 loose objects (small 4 KiB files) under default fsync configuration, considered marginal by the author.
