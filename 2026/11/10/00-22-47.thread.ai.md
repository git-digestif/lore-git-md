Thread identity: Subject "[PATCH 0/4] odb: eagerly create tmp-objdir at transaction start", series version v1, originating author Justin Tobler, thread type patch series (correctness/refactoring) within the ODB abstraction effort.

Core problem or goal: The series addresses a correctness gap in Git's ODB transaction machinery where the temporary directory is created lazily on first object write, causing some writes (those not using batched fsync) to bypass the temporary directory entirely. The goal is to make temporary-directory creation eager at transaction start so all transactional object writes go to the temporary directory immediately.

Current status: Under review; no prior versions. Based on commit `3c60ef1e38` (The 17th batch, 2026-11-08) with `jt/tmp-objdir-loose-idx-merge` merged in. Justin Tobler has now responded to both Patrick Steinhardt's and Karthik Nayak's reviews of patch 2/4. He answered Karthik's fsync durability question by noting the behavior is platform-specific and citing commit `c0f4752ed2` (core.fsyncmethod: batched disk flushes for loose-objects, 2022-04-04) as the authoritative explanation of the batched-fsync barrier semantics, resolving the technical concern about `flush_batched_fsync()` without code changes. Key technical details: Files touched: `tmp-objdir.c`, `tmp-objdir.h`, `object-file.c`, `object-file.h`, `odb/source-loose.c`, and test `t0004-unwritable.sh`.
