This is a test patch, part of the ongoing effort to improve Git's test coverage. The v2 iteration adds basic tests for `git mktree --batch`, addressing a gap that previously allowed a memory leak (fixed in commit 6272f3bd17) to go unnoticed.

The patch adds seven new tests to `t/t1010-mktree.sh`, covering core functionality like multiple trees in a single batch, `-z` (NUL-terminated) input, and error conditions such as missing objects. It also verifies that blank lines are rejected without `--batch` and documents the current behavior with consecutive blank lines (producing an empty tree), though the commit message notes this may not be intentional. The v2 update incorporates feedback from Laveesh Bansal: it now checks the error message in the missing-object test and moves the question about blank-line behavior out of the commit message.

The tests are straightforward and well-scoped, touching only the test file. They pass under `SANITIZE=leak` and catch the memory leak when the fix is reverted, confirming their effectiveness. The patch is motivated by Jeff King’s suggestion, which lends credibility, and the changes are uncontroversial. The only open question is whether the behavior with consecutive blank lines should be preserved or rejected, but that’s a separate discussion. This looks like a solid, incremental improvement to test coverage.
