This is a brief follow-up in the long-running `[PATCH v8 0/7]` series that adds seven new path-related keys to the `git repo info` command. The thread is now focused on a **surface-level but blocking naming convention issue**.

Junio C Hamano recently clarified that Git configuration variables (and by extension, `git repo info` keys) should avoid hyphens in favor of underscores or dots. Phillip Wood confirms that while the new keys are not configuration variables, the existing `path.gitdir.*` and `path.commondir.*` keys already follow this convention, so the series should drop hyphens (e.g., `path.superproject_working_tree` instead of `path.superproject-working-tree`) for consistency.

This is a **mechanical, uncontroversial change** that the author must make before the series can proceed. The fix requires updates to the implementation, documentation, and tests, but no design or behavioral changes. The thread remains otherwise unresolved on two substantive points: the necessity of the `path.hooks` key and the usability of `path.cdup`. Without further reviewer engagement, the series risks being dropped from `seen`.
