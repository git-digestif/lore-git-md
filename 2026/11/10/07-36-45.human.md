This is the final patch in Thomas Bachem’s 15-part bugfix series that systematically eliminates Git segfaults when config keys are given without values. Patch 15/15 fixes a regression introduced in Git 2.54.0 (commits 2d4ab5a885 and 9cb4a5e1ba) where `git config list --type=color` and `--type=expiry-date` would crash if any key in the configuration lacked a value. The fix is minimal and surgical: it adds NULL checks in `format_config_color()` and `format_config_expiry_date()` to silently skip valueless keys, matching the existing behavior for unparseable values and aligning with how `--type=int` already handles missing values.

The patch touches only `builtin/config.c` and adds a new test in `t/t1300-config.sh` that verifies both `--type=color` and `--type=expiry-date` omit valueless keys without error. The change is uncontroversial and follows the established pattern in the series of graceful handling for edge cases. Derrick Stolee’s earlier review of the series endorsed the approach, and the v2 update (which adjusted only patch 1/15) left this patch unchanged. The series as a whole is effectively approved for merge, pending resolution of minor test conflicts with two other topics in `seen`. This patch is a clear, well-motivated fix for a user-facing crash and deserves attention from anyone tracking regressions in Git 2.54.0.
