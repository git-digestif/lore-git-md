This is the sixth patch in the v2 series fixing Git segfaults when config keys lack values. It targets the `remote.<name>.tagOpt` setting, which currently causes `git fetch`, `git remote`, and `git status` to crash when given without a value (e.g., `git -c remote.origin.tagOpt`). The fix adds a NULL check in `handle_config()` to reject missing values with `config_error_nonbool()`, matching the existing behavior for `remote.<name>.url` and `remote.<name>.pushurl`.

The patch touches `remote.c` and adds a test in `t/t5505-remote.sh` to verify the error message. The change is minimal and aligns with the series' consistent pattern of using `config_error_nonbool()` for unvalued config keys. The test confirms that Git now emits a clear error instead of segfaulting. This is one of the simpler fixes in the series, addressing a straightforward crash without introducing new edge cases or behavior changes. The fix is well-motivated and follows the established precedent (ba176db511). No controversy or open questions are associated with this patch.
