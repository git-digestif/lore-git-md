This is an RFC patch series from a new contributor, Azuama Odinaka Maximus, proposing improvements to Git’s early option scanning in `rev-list` and introducing a reusable API for it.

The series has two patches. The first modifies `rev-list` to better handle options that consume arguments during early scanning, addressing a current limitation where such options might be misparsed. The second introduces a generic early option-scanning API in `parse-options.c`, complete with tests, aiming to make this functionality reusable across Git commands. The author acknowledges that the current implementation still relies on a hardcoded option list, which they recognize as fragile, and are exploring ways to integrate revision-option parsing more robustly.

The motivation is clear: early option scanning in Git can be error-prone, especially for commands like `rev-list` that accept complex argument patterns. The proposed API could reduce duplication and improve consistency if done well. The series includes thorough test coverage, which is a positive sign, though the commit messages could be more explicit about the specific edge cases being fixed (e.g., examples of misparsed arguments).

This looks like a well-scoped, technically sound effort, though the RFC tag suggests the author is still refining the approach. The feedback requested—particularly on API design and integration with revision parsing—will likely shape the next iteration. For now, this is worth watching for anyone interested in Git’s command-line parsing or `rev-list` internals.
