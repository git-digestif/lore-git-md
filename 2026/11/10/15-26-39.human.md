This is a two-patch refactoring series for the `git reflog expire` command, addressing a maintainer suggestion from an earlier review. The goal is to simplify the code by merging two separate loops (one for `--all`, one for named refs) into a single loop, then deduplicate reflogs so each is expired only once.

The first patch is purely mechanical: it consolidates the loops without changing behavior, preserving error reporting, exit status, and output order. The second patch adds deduplication, treating repeated reflogs (e.g., from `--all` and a command-line argument) as a bug fix rather than a behavioral change. The author reports full test suite passes, including reflog tests with reftable, SHA-256, and leak sanitization, and the output differs from the base only where a reflog was previously processed twice.

The series is well-motivated and clearly split: the first patch is a straightforward refactor, while the second makes a deliberate improvement. The commit messages are now self-contained, addressing earlier feedback about clarity. Junio and Patrick Steinhardt have both endorsed the direction, and the author has incorporated their suggestions to split the work into two patches. This looks like a clean, uncontroversial cleanup that should be easy to review and merge.
