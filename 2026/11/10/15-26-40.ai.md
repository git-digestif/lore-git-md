This is the first patch in a two-patch refactoring series for `git reflog expire`. It mechanically consolidates the two separate loops (one for `--all`, one for named refs) into a single loop, addressing a maintainer suggestion from an earlier fix (d1536ac3e2). The goal is to eliminate code duplication while preserving all existing behavior: error reporting, exit status, output order, and handling of dynamic refs like `@{-1}`.

The patch collects all reflogs—both from `--all` and command-line arguments—into a single `string_list` (`collected.reflogs`). Command-line refs are flagged with `item->util` to indicate they still need lookup via `repo_dwim_log` during iteration. The core expiration logic (`refs_reflog_expire`) is unchanged, and the author confirms the refactor passes the full test suite, including reflog tests with reftable, SHA-256, and leak sanitization.
