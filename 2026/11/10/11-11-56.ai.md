This is a **substantive review** of patch 14/15 in the v2 segfault-fix series, focusing on the `bundle-uri` subsystem. Phillip Wood raises a **consistency concern**: the patch rejects NULL values for `bundle.heuristic` and `bundle.<id>.creationToken` with `config_error_nonbool()`, but the existing code silently ignores *invalid* (non-NULL) values for the same keys. For `bundle.heuristic`, unknown heuristics are explicitly ignored; for `bundle.<id>.creationToken`, parse errors trigger a warning but do not abort. Phillip questions whether NULL values should be treated more leniently—either ignored or warned about—rather than causing the entire bundle list to be rejected.

The review is **narrow but technical**: it targets a specific design choice in the patch’s error-handling logic, not the broader goal of preventing segfaults. Phillip defers to Derrick Stolee (the subsystem’s primary reviewer) on the "best behavior," but the observation is sharp: the patch introduces a stricter error path for NULL values than for invalid ones, which could surprise users or break workflows where malformed bundle lists are currently tolerated. The test coverage (added in the patch) verifies the new error messages but does not address this inconsistency.

This feedback does not block the patch—it’s a **design-level question** rather than a bug—but it may prompt a v3 update if Stolee or the author agree that NULL values should align with the existing handling of invalid values. The thread’s prior discussion (Derrick’s review) already noted that the error message for valueless keys could be clearer, so this adds another dimension to the UX tradeoff. No merge conflicts or test failures are introduced by this concern.
