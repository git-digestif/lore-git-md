This is the first patch in a 15-part bugfix series addressing Git segfaults when config keys are given without values. Specifically, it fixes a crash in `git rebase -i` when `rebase.missingCommitsCheck` is set without a value (e.g., `git -c rebase.missingCommitsCheck` or a bare `missingCommitsCheck` under `[rebase]`). The crash occurs because the code passes a NULL value to `strcasecmp()` when generating the todo list.

The fix treats missing values for `rebase.missingCommitsCheck` as invalid, issuing a warning and defaulting to `"ignore"`—the same behavior applied to explicitly invalid values (e.g., `"foo"`). This aligns with the design suggestion from Phillip Wood and Junio C Hamano during the v1 review, resolving the key open question from the series. The patch updates `get_missing_commit_check_level()` to check for NULL before calling `strcasecmp()` and adds a test confirming the warning is shown while ensuring the rebase completes without flagging dropped commits.

The change is minimal and targeted, touching only `rebase-interactive.c` and its test file. The commit message clearly explains the problem, the fix, and the rationale for the chosen behavior. This patch is now ready for merge, with no further changes expected. The rest of the series (patches 2–15) continues to use `config_error_nonbool()` for other unvalued config keys, but this one case was singled out for special handling due to its existing behavior for invalid values.
