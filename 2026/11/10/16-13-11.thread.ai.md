Thread identity: RFC patch series introducing a reusable early option-scanning API for Git's parse-options subsystem. Series version: RFC (no version number specified). Originating author: Azuama Odinaka Maximus. Thread type: RFC design discussion and patch series.

Core problem or goal: Improve Git's parse-options subsystem by introducing a reusable API for early option scanning, enabling commands to handle options that consume arguments without triggering unwanted side effects from full revision-option parsing. The current implementation in `rev-list` uses a hardcoded, fragile option list, which this series generalizes for broader use across Git commands.

Current status: Under initial review as an RFC. The series consists of two patches: the first modifies `rev-list` to use early option scanning, and the second introduces the generic API with tests. No prior versions or merge status reported. The author continues to invite feedback on API design, integration with revision parsing, and the trade-off between generality and complexity.

Key technical details:
- Files touched: `builtin/rev-list.c`, `parse-options.c`, `parse-options.h`, test helpers (`test-parse-options.c`), and new test scripts (`t/t0040-parse-options.sh`, `t/t6022-rev-list-missing.sh`).
- New API functions: `parse_options_early_scan()` (core function), `parse_options_takes_argument()` (helper), and supporting infrastructure (`lookup_long_opt()`, `find_early_scan_option()`, `early_scan_one_option()`). Patch 1 introduces `rev_list_option_takes_argument()` as a `rev-list`-specific helper.
- Symbols introduced: `rev_list_option_takes_argument()`, `parse_options_early_scan()`, `parse_options_takes_argument()`, `early_scan_fn` callback type, `enum early_scan_flags`, and internal helpers. The `PARSE_OPT_EARLY` flag marks options for early scanning.
- Test coverage: New tests in `t/t6022-rev-list-missing.sh` verify edge cases for `--grep` and `--author` arguments beginning with `--`, ensuring they are not misinterpreted as options. Tests also cover interactions with `--exclude-promisor-objects` and `--` (pathspec delimiter). Patch 2 adds unit tests in `test-parse-options.c` and a new test script (`t/t0040-parse-options.sh`) for the generic API, covering attached/separate arguments, `--` delimiters, default values, and early termination.
- Behavior changes: Early option scanning for `rev-list` avoids side effects from full revision parsing, particularly for options that consume arguments (e.g., `--grep <pattern>`). The API stops at `--`/`--end-of-options`, skips short options and unknown long options, and does not modify `argv`. No on-disk format changes.
- Subsystems affected: parse-options (primary), revision parsing, and command-line argument handling.

Open questions and loose ends:
- How to eliminate the hardcoded option list in `rev_list_option_takes_argument()` (acknowledged by the author as a temporary measure and future improvement).
- Whether the API's complexity is justified by its reusability (no concrete use cases beyond `rev-list` are provided, though the API is designed to be generic).
- Integration with revision parsing: how to avoid conflicts or redundancy with existing revision-option handling (e.g., `--` delimiter, options that overlap between parse-options and revision parsing).
- Feedback on API design: the author explicitly requests input on the `parse_options_early_scan()` function, the `PARSE_OPT_EARLY` flag, and whether the added complexity is warranted for the use case.
