This is a refactoring and correctness patch series targeting the object database (ODB) transaction machinery. It comes from Justin Tobler, who has been deeply involved in the ongoing ODB abstraction effort alongside Patrick Steinhardt.

The series changes how Git creates the temporary directory used during ODB transactions. Currently, the directory is created lazily on the first object write; after this series, it is created eagerly when the transaction begins. The motivation is to ensure that *all* transactional object writes go to the temporary directory, not just those with batched fsync enabled. The commit message frames this as a correctness fix, though it does not describe a specific bug that the current behavior causes.

Four patches: the first three are small preparatory cleanups (renaming a constant, adjusting fsync logic, preserving errno in a helper), and the fourth is the main change. The diffstat shows a net reduction of 28 lines, mostly from `object-file.c`. The series is based on a recent integration branch and includes a merge of another topic (`jt/tmp-objdir-loose-idx-merge`), suggesting it is part of a larger, coordinated effort.

The code touches core ODB internals (`object-file.c`, `tmp-objdir.c`) and updates a test script (`t0004-unwritable.sh`) to match the new behavior. No new user-visible options or commands are introduced; this is plumbing-only work. The commit messages are clear and the patches appear well-structured, though the series does not include a cover-letter-style motivation beyond the brief paragraph above.

If you care about ODB transactions or are following the ODB abstraction work, this is worth a closer look. If you are a casual reader, it is safe to skip unless you are debugging a transaction-related issue.
