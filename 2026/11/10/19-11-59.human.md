This is the second patch in Wyatt Holden’s three-part series introducing `checkout.orphanedCommitWarning`, a configuration knob to disable the expensive reachability check that warns users when leaving a detached HEAD. This patch specifically adds advice that triggers when the check takes more than two seconds, guiding users toward the new setting.

The change wires up a new advice key (`advice.checkoutOrphanedCommitWarning`) and measures the wall-clock time of the existing `orphaned_commit_warning()` function with a Trace2 region. When the check exceeds two seconds (or when the test hook `GIT_TEST_CHECKOUT_DELAY_WARNING` is set), Git prints a hint explaining how to disable the check and the trade-off involved—skipping the check silences the warning about commits left behind, but those commits remain recoverable via the HEAD reflog. The advice itself can be suppressed with the advice key, and the patch includes thorough tests that verify the hint appears, respects suppression, and does not fire when the check is skipped.

The implementation follows the pattern established by the 2019 slow-status advice, but instead of a command-line flag it recommends a configuration setting, keeping the interface consistent with the rest of Git. The patch is clean, well-tested, and directly addresses the performance pain point described in the cover letter. It looks ready for review and should not be controversial.
