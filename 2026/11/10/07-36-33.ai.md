This is the third patch in the v2 series fixing Git segfaults when config settings lack values. It targets the interactive patch subsystem (`git add -p`, `git add -i`), where unvalued color slots like `color.interactive.prompt` or `color.diff.frag` currently cause crashes. The fix replaces `repo_config_get_value()` with `repo_config_get_string_tmp()` in `add-patch.c`, aligning the error handling with `git diff`'s existing behavior for diff colors. When a value is missing, Git now rejects the config key with `config_error_nonbool()` instead of passing NULL to `color_parse()`.

The patch touches `add-patch.c` (one line changed) and adds a 12-line test to `t/t3701-add-interactive.sh`. The test verifies that `git -c color.interactive.prompt add -p` fails with a clear error message when the color slot lacks a value. This is a straightforward, well-motivated bugfix with no behavior changes beyond preventing the segfault. The commit message clearly explains the problem, the fix, and the precedent (matching `git diff`'s handling). The test coverage is thorough and follows the series' pattern of validating both the crash prevention and the error message. No controversy or open questions remain for this patch.
