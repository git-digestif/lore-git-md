This is patch 7/15 in the v2 series fixing Git segfaults when config keys lack values. It addresses a crash in `git blame` when `color.blame.repeatedLines` or `color.blame.highlightRecent` are set without values (e.g., `git -c color.blame.repeatedLines blame file.c`). The fix adds NULL checks in `git_blame_config()` to reject missing values with `config_error_nonbool()`, matching the existing pattern for other `blame.*` config keys like `blame.date` and `blame.coloring`.

The patch touches `builtin/blame.c` and adds a test in `t/t8012-blame-colors.sh` to verify that Git emits a clear error message instead of crashing. The change is minimal and consistent with the series' approach: unvalued config keys are treated as errors unless there is a specific reason to handle them gracefully. The test covers both affected keys and confirms the error message includes the problematic config key name.

This is a straightforward bugfix with no behavior changes beyond preventing a segfault.
