This is a **surface-level review** of the first patch in Jasper Mayone’s four-patch series (v4), which makes `git worktree remove` refuse to delete worktrees in the middle of a rebase, `git am`, bisect, cherry-pick, or revert unless `--force` is given. Phillip Wood’s feedback focuses on documentation formatting and minor stylistic improvements to the man page text.

The review suggests two small changes to the bulleted list in `Documentation/git-worktree.adoc`:
1. Each list item should be a self-contained sentence, so the trailing comma after "submodules" should be dropped, and the ", or" before the final item should be removed.
2. The rendering of `git am` in a different font from the other command names (rebase, bisect, cherry-pick, revert) looks odd; Phillip notes that splitting the list into separate items for each command might improve clarity, though he is unsure whether this would be an improvement.

No technical concerns are raised—the implementation (the new `check_no_operation_in_progress()` helper and its integration into `remove_worktree()`) is explicitly praised as "good." The review is purely editorial and does not affect the patch’s correctness or safety. Jasper has already accepted similar stylistic feedback in earlier iterations, so this is likely to be addressed in a reroll. The patch remains a clear, well-motivated **bugfix** that closes a real safety hole.
