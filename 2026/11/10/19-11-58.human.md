This is the first patch in a three-part feature series introducing `checkout.orphanedCommitWarning`, a new configuration option to disable the reachability check that warns users when leaving a detached HEAD. The motivation is performance: in large mono-repos, this check can dominate checkout time (193 seconds out of 205 in Microsoft’s internal repo), and the series aims to provide an opt-out while preserving the default safety behavior.

The patch adds the boolean config key (defaulting to `true`) and wires it into the checkout and switch built-ins. When disabled, the check is skipped entirely, and the code falls back to a simple detached-head description instead of the full reachability walk. A new Trace2 region (`orphaned_commit_warning`) exposes the check’s duration, helping users and tooling measure its impact. The tests verify that both commands respect the setting and that Trace2 events are emitted only when the check runs.

The implementation follows the pattern of `status.aheadbehind`, using a config-only toggle without a dedicated command-line flag. The commit message is thorough, explaining the observed bottleneck, the design choices, and the trade-offs (recoverability via reflog is preserved even when the warning is disabled). The patch looks well-crafted, with clear documentation and test coverage for both the happy path and invalid values. It’s a focused, practical change that addresses a real performance pain point without altering the default user experience.
