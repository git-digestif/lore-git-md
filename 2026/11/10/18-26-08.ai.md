This is a test infrastructure patch that introduces `test-tool genbytes` to eliminate a performance bottleneck in Git's test suite on macOS. The patch is the culmination of a three-iteration design process and is now ready for submission.

The core issue is that several tests generate large amounts of data by piping `test-tool genzeros` through `tr(1)`, which is unusually slow on macOS—spending up to two minutes of CPU time to generate 2 GB of data. The new `genbytes` command writes arbitrary bytes directly, bypassing `tr` entirely. Performance measurements show macOS CI jobs improving by 70–79%, while Linux jobs see modest gains of 2–7%.

The implementation adds `cmd__genbytes` alongside the existing `cmd__genzeros` in `test-genzeros.c`, sharing the same 256 KB static buffer and `generate_bytes` helper. The interface is `test-tool genbytes <char> [<count>]`, where `<char>` is a literal character (e.g., `test-tool genbytes a 500`). Callers needing NUL bytes continue using `genzeros`, avoiding churn in existing tests. The patch updates 16 test scripts, replacing `genzeros | tr` invocations with direct `genbytes` calls. Input validation is now stricter, using `git_parse_signed()` to reject invalid counts rather than silently treating them as zero.

Key design decisions—such as the two-command literal-character interface and the rejection of `printf`-based alternatives—were settled in earlier iterations after feedback from Junio C Hamano, Johannes Sixt, and Patrick Steinhardt. The buffer allocation detail (static vs. stack) was resolved in favor of a static buffer to avoid stack exhaustion, with Junio dismissing thread-safety concerns for this "run-once" helper. The patch is well-motivated, thoroughly tested, and addresses a real performance pain point without introducing behavioral changes. It touches only test infrastructure and is unlikely to be controversial.
