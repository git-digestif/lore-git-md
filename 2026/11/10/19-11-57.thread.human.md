This thread introduces a new configuration option, `checkout.orphanedCommitWarning`, to address a significant performance bottleneck in `git checkout` and `git switch` when leaving a detached HEAD. The change is motivated by Microsoft's internal data showing that the reachability check for orphaned commits can consume over 90% of checkout time in large mono-repos (193 seconds out of 205 in their case). The feature defaults to `true` to preserve the existing safety warning but allows users to opt out for performance-critical workflows.

The patch series is currently under review in its initial version (v1). Wyatt Holden, the author, has implemented the config key, integrated it with the checkout built-in, and added Trace2 telemetry to measure the check's duration. The series also includes Scalar integration, which disables the warning by default while respecting explicit user settings. Tests confirm the feature works as expected for both `git checkout` and `git switch`. No substantive reviews or objections have been raised yet, so the discussion is still in its early stages.
