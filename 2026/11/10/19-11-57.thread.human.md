This thread introduces a new configuration option, `checkout.orphanedCommitWarning`, to disable the performance-heavy reachability check that warns users about orphaned commits when leaving a detached HEAD. The feature is aimed at large mono-repos where this check can consume over 90% of checkout time, and it preserves the default safety behavior while allowing an opt-out for performance-critical workflows.

Wyatt Holden (Microsoft) posted the initial v1 series, which adds the boolean config key, integrates it with Scalar (disabling the warning by default for Scalar users), and includes Trace2 telemetry and advice messages to guide users toward the trade-off. Derrick Stolee, a key contributor with deep expertise in large-repo performance, has reviewed and endorsed the series, citing prior art like `status.aheadBehind` and confirming the Scalar integration follows established patterns. His only feedback was a minor cosmetic nit, which has already been addressed.

The series is now under broader review, with no substantive objections or open questions raised so far. If no further concerns emerge, it’s likely to proceed toward integration.
