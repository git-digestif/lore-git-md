This is the first patch in a 15-patch bugfix series addressing Git segfaults when config keys are given without values. Specifically, it fixes a crash in `git rebase -i` when `rebase.missingCommitsCheck` is set without a value (e.g., `git -c rebase.missingCommitsCheck` or a bare `missingCommitsCheck` under `[rebase]`). The crash occurs because `get_missing_commit_check_level()` passes a NULL value to `strcasecmp()`.

The fix treats missing values for `rebase.missingCommitsCheck` as invalid, issuing a warning and defaulting to `"ignore"`—matching the existing behavior for explicitly invalid values (e.g., `"foo"`). This resolves the design question raised in the v1 discussion by Phillip Wood and Junio C Hamano, who argued that missing values should not trigger `config_error_nonbool()` but instead follow the same fallback logic as unrecognized values. The patch updates `rebase-interactive.c` to check for NULL and adds a test in `t/t3404-rebase-interactive.sh` to verify the warning and fallback behavior.

The change is minimal and targeted, touching only the affected function and its test. The commit message clearly explains the problem, the fix, and the rationale for the chosen approach. The test coverage is thorough, ensuring the warning is displayed and the rebase completes without dropping commits. This patch is now aligned with the rest of the series, which consistently handles unvalued config keys either by rejecting them with `config_error_nonbool()` or gracefully defaulting where appropriate. No further changes are expected for this patch.
