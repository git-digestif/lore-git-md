This is the third and final patch in Wyatt Holden’s three-part series introducing `checkout.orphanedCommitWarning`, a configuration knob to disable the reachability check that warns about orphaned commits when leaving a detached HEAD. The series targets performance bottlenecks in large mono-repos, where the check can consume over 90% of checkout time.

This patch integrates the new setting into Scalar, Git’s high-performance wrapper for large repositories. It adds `checkout.orphanedCommitWarning=false` to Scalar’s recommended configuration, using the existing `scalar_config_set()` mechanism to preserve any explicit user choice. The change is documented in `Documentation/scalar.adoc`, explaining that disabling the check trades off the immediate warning for performance while preserving commit recoverability via the HEAD reflog. No new tests are added, as existing Scalar tests already verify configuration preservation.

The patch is narrowly scoped and uncontroversial: it simply opts Scalar users into the performance optimization introduced by the earlier patches, maintaining the series’ overall goal of preserving default safety while allowing opt-out for performance-critical workflows. The change aligns with Scalar’s purpose of tuning Git for large repositories and follows the established pattern of recommending settings without overriding user preferences.
