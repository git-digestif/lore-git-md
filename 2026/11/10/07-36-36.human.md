This is the sixth patch in Thomas Bachem’s 15-part bugfix series that plugs Git segfaults when config keys are given without values. It targets the `remote.<name>.tagOpt` setting: when someone writes `git -c remote.origin.tagOpt` (no value), the code used to pass NULL straight to `strcmp()`, crashing `git fetch`, `git remote`, and `git status`. The fix is a two-line guard in `remote.c` that rejects the missing value with `config_error_nonbool()`, matching the existing pattern for `remote.<name>.url` and `remote.<name>.pushurl`. A new test in `t/t5505-remote.sh` verifies the error message is clear and the command fails gracefully instead of crashing. The patch is minimal, well-motivated, and follows the series’ consistent approach.
