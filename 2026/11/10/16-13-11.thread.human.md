This thread is an RFC patch series by Azuama Odinaka Maximus proposing a reusable early option-scanning API for Git's parse-options subsystem. The goal is to replace the hardcoded, fragile option handling in `rev-list` with a generalized API that other Git commands can adopt. The series consists of two patches: the first modifies `rev-list` to use early option scanning, and the second introduces the generic API with thorough test coverage.

The new API, introduced in the second patch, centers on `parse_options_early_scan()`, a function designed to scan command-line arguments for specific options without triggering side effects from full revision parsing. The implementation handles edge cases like ambiguous abbreviations, `--end-of-options`, and missing arguments, and includes a new `PARSE_OPT_EARLY` flag to mark options for early processing. Tests verify the API's behavior across scenarios like attached vs. separate arguments, `--` delimiters, and early termination. While the patch is technically sound, the author acknowledges the hardcoded option list in `rev-list` as a temporary measure and invites feedback on the API's design and reusability.

So far, the thread has seen no substantive reviews or objections, leaving key questions open: whether the API's complexity is justified by its potential use beyond `rev-list`, how to eliminate the hardcoded option list, and whether the `PARSE_OPT_EARLY` flag is the most intuitive approach. The series is still under initial review as an RFC, with no merge status or prior versions reported.
