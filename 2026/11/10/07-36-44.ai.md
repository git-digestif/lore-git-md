This is patch 14/15 in the v2 bugfix series addressing Git segfaults when config settings lack values. The patch targets the `bundle-uri` subsystem, fixing crashes in `git clone --bundle-uri` and `git fetch` when a bundle list contains keys like `bundle.mode`, `bundle.heuristic`, `bundle.<id>.uri`, or `bundle.<id>.creationToken` without values. These crashes can be triggered by malformed server responses, making this a potential security-adjacent issue.

The fix adds NULL checks in `bundle_list_update()` for all four keys, rejecting missing values with `config_error_nonbool()`. This aligns with the series' established pattern and ensures the bundle list is treated as invalid, allowing the clone or fetch to proceed without the bundles. The test verifies that Git emits clear error messages for each valueless key, matching the behavior for other malformed bundle list entries (e.g., duplicate URIs).

This patch is part of a well-reviewed series that has already addressed 19 other crash sites across Git commands. Derrick Stolee's earlier review noted that while the fix prevents segfaults, the error message may not clearly indicate the issue stems from a malformed server response—this UX concern is deferred to a follow-up. The patch itself is straightforward and follows the series' consistent approach to handling unvalued config keys.
