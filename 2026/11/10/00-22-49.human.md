This is the second patch in Justin Tobler’s four-patch series that refactors Git’s ODB transaction machinery to create the temporary object directory eagerly at transaction start. The patch itself is a small, focused cleanup: it extracts the batched-fsync flush logic into a helper function (`flush_batched_fsync`) and makes the flush conditional on the `FSYNC_COMPONENT_LOOSE_OBJECT` batch-fsync setting. The net effect is that Git no longer issues an unnecessary hardware flush when batched fsync is disabled, which happens in `git-receive-pack` and other contexts where objects are synced individually or not at all.

The change is mechanical and well-motivated: the commit message clearly explains why the flush was previously unconditional and why it should now be guarded by the batch-fsync setting. The diff is clean, moving the flush logic into a helper without altering behavior when batch-fsync is enabled. This patch is a pure refactoring with no user-visible impact, setting the stage for the main behavioral change in patch 4/4. No controversy or open questions are evident; the patch looks like a straightforward improvement.
