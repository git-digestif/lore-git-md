This is the tenth patch in the v2 series fixing Git segfaults when config keys lack values. It addresses a crash in `safe.bareRepository` handling: when the key is set without a value (e.g., `git -c safe.bareRepository`), the `allowed_bare_repo_cb()` callback passes NULL to `strcmp()`, causing a segfault in any bare repository operation like `git -C repo.git log`.

The fix adds a NULL check in `allowed_bare_repo_cb()` and rejects missing values with `config_error_nonbool()`, consistent with the series' established pattern. The test verifies Git emits a clear error message instead of crashing. This aligns with the callback's existing behavior, which already rejects any value other than `"explicit"` or `"all"`.

The patch touches `setup.c` and adds a test case to `t/t0035-safe-bare-repository.sh`. It is a targeted bugfix with no behavior changes beyond preventing the crash.
