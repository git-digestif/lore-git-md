This is the fourth patch in a 15-patch bugfix series addressing Git segfaults when config settings lack values. It targets the `bundle-uri` subsystem, specifically the `fetch.bundleCreationToken` config key used by `git fetch` and `git clone --bundle-uri` when the bundle list employs the `creationToken` heuristic.

The patch fixes a crash in `fetch_bundles_by_token()` where a NULL value for `fetch.bundleCreationToken` (e.g., from `git -c fetch.bundleCreationToken`) was passed directly to `sscanf()`. The fix treats a missing value the same as an unparseable one—defaulting to 0, which triggers a fresh download of bundles and updates the stored token to 1. This aligns with the function’s existing behavior for malformed tokens and avoids introducing new error paths. The test verifies that `git fetch` succeeds and correctly updates the token to 1 after the operation.

The change is minimal and surgical: a single NULL check (`!creationTokenStr`) added to the existing `sscanf()` condition. The test coverage is thorough, setting up a bundle list with the `creationToken` heuristic and confirming the token is updated post-fetch. Derrick Stolee’s earlier review of v1 endorsed this approach, noting it as the correct fix for the crash. No design questions remain; the patch is ready for merge pending resolution of the series’ test conflicts in `seen`.
