This is the second patch in Justin Tobler’s four-patch series that refactors Git’s ODB transaction machinery to create the temporary object directory eagerly at transaction start. It is a targeted cleanup inside `object-file.c` that moves the batched-fsync flush logic into a helper function and makes the flush conditional on the `FSYNC_COMPONENT_LOOSE_OBJECT` batch-fsync setting.

The patch extracts the existing flush code into `flush_batched_fsync()`, then wraps the call in a check for `batch_fsync_enabled()`. The motivation is straightforward: the hardware flush is only needed when batched fsync is active; when objects are synced individually (or not at all), the flush is redundant and can be skipped. The change is purely internal—no user-visible behavior changes, no on-disk format changes, and no new test coverage.

The diff is small (25 insertions, 18 deletions) and mechanical: the extracted helper is identical to the original code except for the conditional guard. The patch is uncontroversial and appears ready for review; it is a natural follow-up to the first patch’s prefix rename and a prerequisite for the eager-creation change that follows in patch 4.
