This thread covers Justin Tobler's v2 patch series, now complete at six patches, which makes Git's object database transaction machinery create its temporary directory eagerly at transaction start rather than lazily on the first object write. The change ensures that all transactional loose-object writes are staged in a temporary directory and later migrated into the primary object store, regardless of whether batched fsync is enabled, fixing a correctness gap where some writes previously bypassed the temporary directory entirely. The final patch (6/6) moves the creation logic into `odb_transaction_files_begin()`, removes the now-unused lazy preparation function, and updates tests so that unwritable repositories fail immediately at transaction start rather than during object insertion.

Patrick Steinhardt has endorsed the direction and seen his earlier concerns about batched-fsync scope and error handling addressed in the earlier patches of the series, though no formal `Reviewed-by` or `Acked-by` trailers have been recorded yet. Karthik Nayak remains skeptical at the design level, questioning whether the shift from lazy to eager creation is architecturally justified, and that fundamental question is still unanswered. The series is based on a recently merged topic and remains under review; the author notes a micro-benchmark showing roughly a 7% slowdown when adding ten thousand small files, which he considers marginal for typical workloads.
