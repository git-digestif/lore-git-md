Justin Tobler’s four-patch series aims to close a correctness gap in Git’s object database (ODB) transaction machinery by making temporary-directory creation eager rather than lazy. The current lazy approach risks inconsistencies if a transaction fails after some objects have already been written directly to the main object store. The series, part of Patrick Steinhardt’s broader ODB abstraction effort, has drawn substantive review from both Patrick and Karthik Nayak, though key questions remain unresolved.

The technical changes are concentrated in `tmp-objdir.c`, `object-file.c`, and related headers, with the core shift moving temporary-directory creation to transaction start. Patch 1/4, which renames the default prefix from `"bulk-fsync"` to `"transaction"`, is effectively approved, but the remaining patches face open questions. Karthik has challenged the series’ fundamental motivation, questioning why eager creation is preferable to the existing lazy approach and pressing for a clearer technical justification. He’s also raised a correctness concern about the barrier logic in `flush_batched_fsync()` (patch 2/4) and proposed a refactoring for `tmp_objdir_create()` (patch 3/4) to improve maintainability. His review of the final patch (4/4) zeroes in on the performance claim—why large numbers of loose objects aren’t expected in ODB transactions—suggesting the 7% slowdown in the micro-benchmark might not be as negligible as the cover letter implies.

Patrick Steinhardt has been broadly supportive of the direction but has flagged user-facing jargon in the test (`t0004-unwritable.sh`) and noted a documentation gap in patch 2/4’s commit message about batched fsync’s scope. Neither reviewer has yet offered a Reviewed-by or Acked-by for the series as a whole. Justin has not responded to any of the feedback, leaving the design rationale, correctness questions, and performance assumptions unresolved. The series remains under active review, with no indication of when—or if—a v2 will address the open concerns.
