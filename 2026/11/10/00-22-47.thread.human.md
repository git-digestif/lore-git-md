This thread covers Justin Tobler's four-patch series to make temporary object directory creation eager at the start of ODB transactions rather than lazy on first write, fixing a correctness gap where writes not using batched fsync would bypass the temporary directory entirely. The series touches `tmp-objdir.c`, `object-file.c`, and the loose object source, renaming the default temporary directory prefix from "bulk-fsync" to "transaction" and removing the now-unnecessary `odb_transaction_files_prepare()` function. Patrick Steinhardt has reviewed substantively and endorsed the direction; his concerns about patch 2/4 are now resolved after Justin confirmed that batched fsync currently applies only to loose objects and agreed to document this in the v2 commit message.

Justin has just responded to Karthik Nayak's substantive correctness question about whether `fsync(fd)` guarantees durability of prior writes, pointing to commit `c0f4752ed2` (the 2022 batched-fsync introduction) as the authoritative explanation of the barrier semantics, which effectively closes that technical concern without code changes. Justin also agreed to convert an inline comment block in `flush_batched_fsync()` to a formal function comment in the next version. However, Karthik's broader design-level skepticism about the shift from lazy to eager creation remains unanswered, as does his challenge to the performance claim in patch 4/4 regarding large numbers of loose objects in transactions.

The series remains at v1 under review with no Reviewed-by or Acked-by trailers yet. A v2 is awaited that incorporates the promised commit message update about loose-objects-only batched fsync and the comment conversion, while the open design questions from Karthik Nayak about the architectural motivation and performance characteristics still need addressing before the series can converge.
