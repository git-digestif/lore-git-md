This thread is about a four-patch series from Justin Tobler that fixes a correctness gap in Git’s object database (ODB) transaction machinery. The series ensures the temporary directory used during ODB transactions is created at transaction start rather than lazily on the first object write, preventing inconsistencies if the transaction fails or is rolled back. The series is part of the ongoing ODB abstraction effort led by Patrick Steinhardt.

Key participants are Justin (the author), Patrick Steinhardt, and Karthik Nayak. Patrick has reviewed the series in detail, endorsing the direction but raising minor issues: he objects to a user-hostile error message in the test suite and questions whether the `"incoming"` prefix (used for `git-receive-pack`) should be unified with the new `"transaction"` prefix. Karthik initially challenged the series’ core premise—asking for a clearer justification for eager creation—but his latest reply is a surface-level sanity check on the first patch, confirming the new prefix behaves as expected. That patch is now effectively approved, though the series as a whole remains under review.

The most significant open question is still Karthik’s design-level skepticism about eager creation. Patrick also noted a commit-message gap in patch 2/4 (the assumption that batched fsync is only for loose objects) and minor stylistic points in patch 3/4, but neither requires code changes. The series touches `tmp-objdir.c`, `object-file.c`, and related headers, renaming the default temporary directory prefix and introducing a new helper function. A micro-benchmark shows a 7% slowdown for a synthetic workload, but the overhead is considered marginal for real-world use. No prior versions exist, and the series is based on recent ODB transaction work.
