This thread is about a four-patch series from Justin Tobler that fixes a correctness gap in Git’s object database (ODB) transaction machinery. The series ensures the temporary directory used during ODB transactions is created at transaction start rather than lazily on the first object write, preventing inconsistencies if the transaction fails or is rolled back. The series is part of the broader ODB abstraction effort led by Patrick Steinhardt.

The patches touch `tmp-objdir.c`, `object-file.c`, and related files, renaming the default temporary directory prefix from `"bulk-fsync"` to `"transaction"` and moving temporary directory creation to the start of the transaction. A micro-benchmark shows a minor 7% slowdown for a specific workload, but this is considered acceptable given the correctness gains. The series is under review, with no prior versions, and depends on the recently merged `jt/tmp-objdir-loose-idx-merge` branch.

Patrick Steinhardt has reviewed the series and endorsed its direction, though he raised two minor concerns: the use of the term "ODB" in an error message (which he finds user-hostile) and whether the `"incoming"` prefix (used for `git-receive-pack`) should be unified with the new `"transaction"` prefix. The first patch, which renames the prefix, has received explicit approval from Patrick, as he agrees the old name would become misleading. The remaining patches are still under discussion, but no major objections have been raised. The series is likely to move forward with minor tweaks to address Patrick’s feedback.
