This thread is about a four-patch series from Justin Tobler that fixes a correctness gap in Git’s object database (ODB) transaction machinery. The series ensures the temporary directory used during ODB transactions is created at the start of the transaction, rather than lazily on the first object write, preventing inconsistencies if the transaction fails or is rolled back. The series is part of the broader ODB abstraction effort led by Patrick Steinhardt.

The first patch, which renames the temporary directory prefix from `"bulk-fsync"` to `"transaction"`, is effectively approved. The second patch, which moves temporary directory creation to the start of the transaction, has drawn feedback from Patrick about a commit-message gap and performance rationale, but no code changes have been requested yet. The third patch, which preserves `errno` across cleanup in `tmp_objdir_create()`, received a substantive but surface-level review from Patrick, who endorsed the change while noting minor stylistic preferences. The fourth patch, which removes the now-redundant `odb_transaction_files_prepare()`, has not yet been reviewed.

The series is under active review, with one open question about error-message clarity in the test suite (`t0004-unwritable.sh`) and a potential future improvement around unifying temporary directory prefixes. Justin has not yet responded to Patrick’s feedback on the second patch. The net effect of the series is a small performance trade-off (a 7% slowdown in a micro-benchmark) for improved correctness, with no changes to the on-disk format. The series is based on recent ODB transaction work and is expected to move forward once the remaining feedback is addressed.
