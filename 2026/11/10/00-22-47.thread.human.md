This thread covers Justin Tobler's v2 six-patch series, "[PATCH 0/6] odb: eagerly create tmp-objdir at transaction start," which fixes a correctness gap in Git's object database transaction machinery: the temporary directory was created lazily on first object write, so some writes bypassed it entirely. The respun series moves tmp-objdir creation to transaction start so every transactional loose-object write is staged in the temporary directory regardless of the configured fsync method, along with preparatory cleanup (renaming the "bulk-fsync" prefix to "transaction", extracting a flush helper, making `tmp_objdir_create()` preserve `errno`, and rewording user-facing "ODB" messages to "object"). It is part of the broader ODB abstraction effort and sits on top of the already-merged `jt/tmp-objdir-loose-idx-merge` base.

Patrick Steinhardt, who reviewed v1 substantively, now says all changes in v2 look sensible and that he is happy with this version; his earlier concerns about batched-fsync scope documentation, prefix naming, and the `tmp_objdir_create()` restructuring are addressed. However, his reply carries no Reviewed-by trailer, so the series remains formally under review with no recorded Reviewed-by or Acked-by from anyone. Karthik Nayak's fundamental design question -- whether switching from lazy to eager tmp-objdir creation is architecturally justified -- remains unanswered, and he has not endorsed the series either.

Nothing has been queued or merged; the series is still awaiting review convergence. The author measured a marginal 7% slowdown for `git add` writing 10,000 small loose objects, which he considers acceptable. The main open item going forward is resolving Karthik's design-level objection and obtaining formal review trailers before Junio would pick the topic up.
