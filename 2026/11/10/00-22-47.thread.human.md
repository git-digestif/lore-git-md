This thread is about a four-patch series from Justin Tobler that fixes a correctness gap in Git’s object database (ODB) transaction machinery. The issue is that the temporary directory used during ODB transactions was created lazily—only when the first object was written—meaning some writes (those not using batched fsync) could bypass it entirely, risking inconsistencies if the transaction later failed or was rolled back. The series makes temporary-directory creation *eager*, ensuring all transactional object writes go through the temporary directory from the start.

The series is now complete with the fourth patch, which removes the now-unused lazy-creation logic, updates the transaction begin routine to create the directory immediately, and adjusts the test suite to match the new behavior. The change is a straightforward correctness fix, though it introduces a minor 7% slowdown in a synthetic benchmark (writing 10,000 loose objects), which the author notes is not representative of typical ODB transaction workloads. The series is part of the broader ODB abstraction effort led by Patrick Steinhardt and has no outstanding objections or open questions. No reviews have been posted yet, but the first three patches were pure refactorings with no behavior change, setting the stage for this final functional update. The series remains uncontroversial and well-scoped.
