This thread is about a four-patch series from Justin Tobler that fixes a correctness gap in Git’s object database (ODB) transaction machinery. The series ensures the temporary directory used during ODB transactions is created at transaction start rather than lazily on the first object write, preventing inconsistencies if the transaction fails or is rolled back. The series is part of Patrick Steinhardt’s ongoing ODB abstraction effort and is currently under review.

Key participants are Patrick Steinhardt, who endorses the direction but critiques error-message clarity and raises minor stylistic points, and Karthik Nayak, who has challenged the series’ core premise—questioning whether eager creation is justified—and now raises a fundamental correctness concern about the `fsync` barrier logic in the second patch. Justin has yet to respond to either reviewer’s latest feedback.

The series touches `tmp-objdir.c`, `object-file.c`, and related headers, renaming the temporary directory prefix from `"bulk-fsync"` to `"transaction"` and introducing a new helper function, `flush_batched_fsync()`. While the first patch is effectively approved, the second patch’s correctness hinges on resolving Karthik’s `fsync` question, and the third and fourth patches remain uncontroversial but unacknowledged. The most pressing open question is whether the barrier logic in `flush_batched_fsync()` is sound, as this could require a code change or at least a commit-message clarification.
