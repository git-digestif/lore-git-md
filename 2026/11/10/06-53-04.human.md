This is a follow-up in Patrick Steinhardt’s GitLab CI speedup series, specifically addressing Junio C Hamano’s portability concern about the `tar -xf` command in `ci/install-sdk.ps1` (patch 1/7). The discussion clarifies that the script relies on `bsdtar`, which is now distributed with Windows by default and can handle ZIP archives via `libarchive`. Patrick argues that this makes the command portable across CI environments, including GitHub Actions, and suggests that the commit message (rather than an in-code comment) is the appropriate place to document the dependency. He also floats the idea of unifying GitLab and GitHub CI workflows by adopting the same SDK installation script for both, noting that the performance bottleneck that previously led GitHub to revert to a custom action has now been resolved. However, he defers this change pending input from Johannes Schindelin, the Git for Windows maintainer.

The tone is collaborative and pragmatic, with Patrick acknowledging the broader context while keeping the focus on the immediate patch. No technical objections remain, and the portability assumption appears well-founded given Microsoft’s inclusion of `bsdtar` in Windows. The suggestion to unify CI workflows is a natural extension of the current work but is explicitly scoped out of this series, leaving it as a potential follow-up. For now, this exchange resolves the only open question on patch 1/7, clearing the way for the series to proceed.
