This is the **patch implementing the agreed reflog fix for symref updates in transactions**, targeting the reftable and files backends. It introduces `ref_transaction_resolve_new_oid()`, a helper in `refs.c` that resolves a ref’s new OID by walking the transaction’s updates (including symref chains) before falling back to `refs_resolve_ref_unsafe()`. Both backends now use this helper when writing reflog entries for symrefs, ensuring HEAD reflog entries record the correct OID regardless of update order or backend.

The patch touches `refs.c`, `refs-internal.h`, `refs/files-backend.c`, `refs/reftable-backend.c`, and adds a new test script (`t/t1400-update-ref.sh`) that exercises both update and create scenarios with varying update orders. The test coverage is thorough: it verifies both the reflog message and the recorded OID for HEAD when its target branch is updated in the same transaction.

The patch aligns with the broader architectural goal of moving reflog logic into the generic refs layer, though it leaves deeper refactoring for later.
