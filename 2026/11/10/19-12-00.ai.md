This is the third and final patch in Wyatt Holden’s three-part feature series introducing `checkout.orphanedCommitWarning`, a configuration knob to disable the expensive reachability check that warns about orphaned commits during `git checkout` or `git switch`. The series targets performance bottlenecks in large mono-repos, where the check can consume over 90% of checkout time.

This patch integrates the new setting into Scalar’s recommended configuration, setting `checkout.orphanedCommitWarning=false` by default. It uses Scalar’s existing `scalar_config_set()` mechanism, which only applies the setting if the user has not already configured it, preserving explicit user choices during `scalar clone`, `register`, and `reconfigure`. The patch also updates `Documentation/scalar.adoc` to document the trade-off: disabling the warning removes the immediate feedback about commits left behind, but those commits remain recoverable via the `HEAD` reflog until its entries expire.

The change is minimal and self-contained, touching only `scalar.c` and the Scalar documentation. No new tests are added, as existing Scalar tests already verify configuration preservation. This patch completes the series, which now provides a configurable opt-out for the orphaned commit warning while maintaining the default safety behavior for ordinary Git users. The integration with Scalar reflects the feature’s primary motivation—improving performance in large repositories where the reachability check is prohibitively expensive.
