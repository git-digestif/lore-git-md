This is the final patch in Jasper Mayone’s four-part series improving worktree safety and consistency. The patch removes the redundant `+` marker from `git branch` output when the current worktree is rebasing or bisecting a branch, since the `(no branch, ...)` line already names the branch.

Phillip Wood’s review raises two concerns. First, he questions the clarity of the commit message and code comments, particularly the ambiguous use of “it” in the comment describing `build_format()`. The intent is clear enough in context—omitting the `+` marker avoids duplicating the branch name—but the wording could be tightened. Second, and more substantively, he suggests an alternative approach: introducing a new `%(currentworktree)` format specifier that would let users construct their own output format (e.g., `%(if)%(worktreepath)%(then)%(if)%(currentworktree)%(then)%(else)+ %(else)%(end)%(end)`). This would be more flexible and avoid the need for the current patch’s conditional logic in `build_format()`.

Jasper’s implementation is clean and well-tested, but Phillip’s suggestion highlights a missed opportunity for extensibility. The current patch hardcodes the behavior, while a format specifier would let users customize output without further code changes. That said, the patch as written is a reasonable incremental improvement, and the series as a whole is ready for review. If the project prefers the more flexible approach, it could be implemented as a follow-up.
