This is a feature patch series introducing a new configuration option to disable orphaned commit warnings during `git checkout` and `git switch`. The series is motivated by performance issues observed in Microsoft's Office mono-repo, where the reachability check for orphaned commits can add nearly 200 seconds to checkout times. The patches add a new `checkout.orphanedCommitWarning` config setting (enabled by default), advice to suggest disabling it when the check is slow, and integration with Scalar to disable the check by default.

The cover letter clearly explains the problem: the `orphaned_commit_warning()` function, which warns about commits not reachable from any ref, performs expensive ref enumeration and commit history walks. In large repositories, this can turn a 12-second checkout into a 205-second operation, while `--quiet` (which also suppresses this check) reduces it to 14 seconds. The series targets automated environments where the warning's value may be outweighed by performance costs.

The implementation looks clean and well-scoped. Patch 1 adds the config option with Trace2 instrumentation to measure the check's duration. Patch 2 introduces advice that triggers after 2 seconds, pointing users to the opt-out. Patch 3 integrates this with Scalar, which already has mechanisms for preserving user settings. The documentation updates cover both the config option and the advice, and the tests verify the behavior without relying on wall-clock delays.

This appears to be a well-motivated and thoroughly implemented feature. The performance impact is significant enough to justify the change, and the design preserves existing behavior by default while providing a targeted opt-out. The integration with Scalar suggests this has been validated in production-scale environments. For users of large mono-repos, this could be a meaningful quality-of-life improvement.
