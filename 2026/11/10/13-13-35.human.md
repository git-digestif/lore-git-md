This is a follow-up in the now-concluded thread about rewriting Git’s detached HEAD documentation. The patch itself was merged to `master` in July 2024, but the thread continued as a meta-discussion about documentation philosophy and phrasing accuracy. Julia Evans responds to Junio C Hamano’s latest feedback, which objected to describing `HEAD` as *being* a branch or commit ID and instead proposed framing it as *recording* a reference.

Julia pushes back on Junio’s technical precision, arguing that the verb "records" is jargon that users won’t understand. She suggests an alternative explanation that leans on Git’s implementation (`.git/HEAD` as a file containing either a branch name or commit ID) but acknowledges this approach is fragile—it will break when the reftable backend becomes the default, since `.git/HEAD` won’t exist. Her proposed rewrite avoids the term "records" entirely, instead describing `HEAD` as "where Git stores the name of your current branch" and using plain language ("branch name" and "commit ID") to align with how users actually think about Git.

The exchange highlights a persistent tension: Junio prioritizes technical accuracy (e.g., `HEAD` is neither a branch nor a commit, but a pointer that *records* one), while Julia advocates for user-centric language that matches real-world mental models, even if imprecise. Neither side concedes, but the thread remains closed—no further patches or revisions are proposed. The discussion is now purely philosophical, with no actionable outcome beyond the already-merged documentation.
