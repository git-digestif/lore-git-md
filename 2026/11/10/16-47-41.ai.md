This is a **surface-level review** of the second patch in Jasper Mayone’s four-part series extending `%(worktreepath)` in `git for-each-ref`. The patch updates the `git-for-each-ref(1)` man page to warn users about two safety-critical limitations of the `%(worktreepath)` atom: worktree paths can contain newlines (breaking scripts that assume one record per line), and only one worktree is shown when a branch is checked out in multiple worktrees. The documentation now includes clear guidance on how to handle newlines safely—using a quoting option like `--shell` or appending `%00` to the format string and parsing for the NUL terminator before the LF that ends each record.
