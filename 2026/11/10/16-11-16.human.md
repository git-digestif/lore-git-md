This is a follow-up in the seven-patch series aimed at speeding up GitLab CI pipelines. The discussion here is surface-level and centers on a minor portability concern in the first patch, which replaces the slow `Extract-Archive` PowerShell cmdlet with `tar -xf` to unpack the Git for Windows SDK (reducing installation time from 3 minutes to 10 seconds).

Junio C Hamano notes that the script assumes a BSD-derived `tar` capable of handling ZIP archives and suggests adding a comment to document this assumption. Patrick Steinhardt responds that the assumption is already broadly valid, as `bsdtar` (based on `libarchive`) is now distributed with Windows by default, making the command portable across CI environments. He sees no need for an in-code comment but acknowledges the point could be clarified in the commit message. The exchange is amicable and does not block the series; Junio’s earlier review already stated no technical objections to the patches.

Patrick also floats the idea of reunifying GitHub Workflows with the GitLab CI script — a change he previously reverted due to performance issues — now that the slowness has been resolved. He defers this decision to Johannes Schindelin, the maintainer of Git for Windows, and keeps it out of the current series.

The series itself remains on track for queuing, with measurable speedups demonstrated across macOS (29m → 18m), Fedora (35m → 16m), and Windows runners. This particular email does not introduce new technical content but clarifies a minor implementation detail and hints at future CI unification work.
