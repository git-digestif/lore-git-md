This is the final patch in Justin Tobler’s four-patch series that shifts Git’s ODB transaction machinery to create its temporary object directory eagerly—at transaction start rather than lazily on first write. The patch removes the now-unused lazy-creation logic (`odb_transaction_files_prepare()` and its call sites), updates the transaction begin routine to create the directory immediately, and adjusts the test suite to match the new error messages. The diff shows a net reduction of 44 lines, mostly from deleting the conditional logic that previously governed when the directory was created.

The patch is a straightforward correctness fix: it ensures that every transactional object write goes through the temporary directory, eliminating a subtle inconsistency where some writes (those without batched fsync) could bypass it entirely. The commit message includes a micro-benchmark showing a 7 % slowdown for a `git add` workload that writes 10 000 loose objects, but notes that such workloads are not typical for ODB transactions and the overhead is marginal in practice.

Files touched: `object-file.c` (main logic), `object-file.h` (removed function declaration), `odb/source-loose.c` (removed lazy-creation calls), and `t/t0004-unwritable.sh` (updated error messages). Key symbols: `odb_transaction_files_begin()`, `tmp_objdir_create()`, and the `ODB_TRANSACTION_RECEIVE` flag. The patch is uncontroversial, well-scoped, and part of the ongoing ODB abstraction effort led by Patrick Steinhardt.
