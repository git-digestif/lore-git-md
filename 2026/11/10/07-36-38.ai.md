This is patch 8/15 in the v2 series fixing Git segfaults when config keys lack values. It addresses a crash in `git merge` when `branch.<name>.mergeOptions` is given without a value (e.g., `git -c branch.main.mergeOptions merge ...`). The fix adds a NULL check in `git_merge_config()` to reject missing values with `config_error_nonbool()`, matching the existing pattern for other string-valued config keys in the same function. The test verifies Git emits a clear error message instead of segfaulting.

The patch is minimal and follows the series' established pattern: it touches only the crash site (`builtin/merge.c`) and adds a targeted test (`t/t7600-merge.sh`). The change aligns with the broader goal of systematically eliminating unvalued config key crashes across Git commands. No new symbols or behavior changes are introduced beyond the crash fix. The commit message clearly explains the problem, the fix, and the rationale for using `config_error_nonbool()`. This is a well-scoped bugfix with no apparent downsides.
