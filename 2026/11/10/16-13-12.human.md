This is the first patch in an RFC series introducing a reusable early option-scanning API for Git's `parse-options` subsystem. It modifies `git rev-list` to handle arguments during early option scanning, addressing a long-standing fragility in how the command processes options that consume arguments (like `--grep` or `--author`) before full revision parsing begins.

The patch replaces a brittle manual loop in `cmd_rev_list()` with a new helper function, `rev_list_option_takes_argument()`, which uses `parse_long_opt()` to recognize options that require arguments. It also explicitly handles `-n` and `--default`, and stops scanning at `--` to avoid misinterpreting pathspecs as options. The tests verify that arguments like `--grep=--missing-only` or `--author --missing-only` are not mistaken for standalone options during early scanning.

The change is narrowly scoped to `rev-list` but lays the groundwork for the generic API introduced in the next patch. The hardcoded list of options in `rev_list_option_takes_argument()` is a notable limitation—acknowledged in the commit message—but the patch otherwise appears well-structured, with clear test coverage for edge cases. This looks like a sensible first step toward a more robust solution, though the series' broader reusability will depend on feedback about the API design in the follow-up patch.
