This is the second patch in Wyatt Holden’s three-patch series introducing `checkout.orphanedCommitWarning` to address performance bottlenecks in large mono-repos. It adds an advice message that triggers when the orphaned-commit reachability check takes more than two seconds, guiding users to the new configuration knob.

The patch wires up a new advice key (`advice.checkoutOrphanedCommitWarning`) and extends the existing `orphaned_commit_warning()` function in `builtin/checkout.c` to measure the check’s duration with Trace2. When the check exceeds two seconds (or when the test hook `GIT_TEST_CHECKOUT_DELAY_WARNING` is set), Git prints a hint suggesting `git config set checkout.orphanedCommitWarning false` and explains the trade-off: skipping the check means losing the warning about commits left behind. The advice itself can be suppressed via the advice key or the global `GIT_ADVICE=0` setting. Tests in `t2020-checkout-detach.sh` verify the advice appears, respects suppression, and does not fire when the check is disabled or when `--quiet` is used.

The implementation follows the pattern established by the 2019 slow-status advice (0a53561a622) but differs in recommending a config setting rather than a command-line option. The test hook avoids wall-clock delays while preserving the measured duration, ensuring reliable CI runs. This patch is a straightforward extension of the first patch’s infrastructure and is unlikely to be controversial.
