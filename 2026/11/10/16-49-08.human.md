This is a **performance-focused review** of the third patch in Jasper Mayone’s four-patch series that extends `%(worktreepath)` in `ref-filter.c` to report the worktree path for branches being rebased or bisected. The series as a whole is a well-motivated effort to close a gap in Git’s worktree safety and usability, and this patch is the technical centerpiece.

Phillip Wood’s review is **substantive and targeted**: he identifies a clear performance regression in the new implementation. The patch replaces the old hashmap-based O(1) lookup in `ref-filter.c` with a linear scan over all worktrees for every ref, resulting in O(N*M) complexity (where N is the number of refs and M is the number of worktrees). This is a real concern for repositories with many refs or worktrees, and the fix is straightforward: refactor `branch.c` to use a hashmap for worktree lookups, mirroring the old implementation, and then expose a function to retrieve the worktree path for a given branch. This would restore the original performance while maintaining the patch’s goal of avoiding code duplication.

The review is constructive and does not question the patch’s overall goal or correctness. The implementation is otherwise clean, well-tested, and addresses a real usability issue: `%(worktreepath)` now correctly reports the worktree path for branches being rebased or bisected, aligning with how `git worktree add` and `git branch -d` already treat those branches. The patch also removes ~50 lines of now-unused worktree-mapping machinery in `ref-filter.c` and introduces a breaking change (stopping the printing of the `git_dir` of bare worktrees) that is documented and justified.

Phillip’s suggestion is a clear improvement and should be addressed before the patch is merged. The rest of the series—including the safety fix for `git worktree remove`, the documentation update, and the cleanup of the redundant `+` marker in `git branch` output—is uncontroversial and ready for integration. The series as a whole looks like a thoughtful, well-crafted contribution that addresses a real problem.
