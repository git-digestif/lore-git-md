This is the fourth patch in Thomas Bachem’s 15-patch bugfix series that stops Git from crashing when config keys are given without values. It targets a specific segfault in `git fetch` and `git clone --bundle-uri` when the `fetch.bundleCreationToken` setting is present but empty (e.g., `git -c fetch.bundleCreationToken`). The crash happens because the code passes a NULL string to `sscanf()`; the fix treats a missing value the same way it already treats an unparseable one—defaulting to 0, which triggers a fresh download of the bundles and then stores the new token. The patch adds a concise test that verifies the token is correctly updated to 1 after the fetch. Derrick Stolee’s earlier review confirmed this approach is correct and safe.
