This is the third patch in Jasper Mayone’s four-patch series (v4), which extends Git’s `%(worktreepath)` atom to report the worktree path for branches being rebased or bisected. The patch replaces the old `ref-filter.c` logic—built from scanning each worktree’s `HEAD`—with a call to a new helper, `branch_checked_out_worktree()`, in `branch.c`. This avoids code duplication and aligns `%(worktreepath)` with how Git already treats such branches in other commands (e.g., `git worktree add` and `git branch -d`).

Phillip Wood’s review is substantive. He points out that the new helper iterates over all worktrees for every ref, which is inefficient compared to the existing hashmap-based lookup in `ref-filter.c`. He suggests refactoring `branch.c` to use a hashmap for O(1) lookups, mirroring the old implementation, and then exposing a function to retrieve the worktree path for a given branch. This would improve performance and maintain consistency with the existing codebase. The review is constructive and focuses on a clear technical improvement without questioning the patch’s overall goal. The patch is otherwise well-motivated, with thorough tests covering rebasing, bisecting, interactive rebase with an edit stop, `rebase --update-refs`, and bare repositories. Key files touched are `ref-filter.c`, `branch.c`, and their test files.
