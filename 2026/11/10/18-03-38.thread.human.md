Git has just released a critical security-focused maintenance update across seven maintenance tracks (from 2.56.1 down to `maint-2.43`), addressing six CVEs discovered by Luke Martin and pwn2addr. The vulnerabilities include remote code execution via malicious submodule gitfiles, path traversal in the files ref backend, stack corruption from multi-signature commits, out-of-bounds reads from oversized binary patches, heap corruption during large merges, and unsafe `fast-import` features. The fixes were implemented by a team including Toon Claes, Karthik Nayak, Kaartic Sivaraam, and others, with Junio C Hamano coordinating the release.

Key technical changes include size_t overflow checks in xdiff (Kaartic Sivaraam), improved multi-signature handling in `remove_signature()` (Karthik Nayak), and protocol v2 symref validation (Toon Claes). Jeff King contributed 30 patches, primarily addressing const-correctness warnings and HTTP header redaction, while Johannes Schindelin fixed CI issues, including macOS 15 and OpenSSL 4.0 compatibility. The release also includes defense-in-depth hardening, such as rejecting over-long cache entries, and updates to the build system to support newer platforms like Debian 12 and macOS 15.

This is a coordinated update for all users, particularly those using recursive clones, `git merge` with signed tags, or `fast-import`. The fixes are backported to all supported maintenance tracks, ensuring broad coverage. The announcement credits the collaborative effort across multiple contributors and highlights the project’s response to security disclosures. There are no unresolved discussions or controversial changes in this release.
