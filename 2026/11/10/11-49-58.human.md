This is a **test modernization** patch, the thirteenth in Karthik Nayak’s 20-patch series refactoring `t9300-fast-import.sh`. The patch makes the marks-related tests self-contained by removing their dependency on state left behind by earlier tests.

The core change introduces a new helper, `create_marks_file()`, that writes a fresh marks file with commits, tags, and blobs so each test can start from a clean repository. The patch also fixes a latent bug in the “feature import-marks-if-exists” test: the original relied on a blob that was never stored in the current test, so the patch now writes that blob explicitly. All marks tests are wrapped in `git init repo && (cd repo && …)` blocks to ensure isolation, and the legacy “series letter” naming (e.g., `R: …`) is kept for now but will be dropped in the final patch of the series.

The diff is large (322 insertions, 190 deletions) but mechanical: every test that once read or wrote marks now does so in its own repository. The commit message is clear and the rationale is sound—this is a well-scoped step in the broader effort to make `git fast-import` tests easier to debug and modify. No behavior changes are introduced, so the patch should be uncontroversial once reviewers confirm the new helpers work as intended.
