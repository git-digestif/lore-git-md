This is the second patch in the v2 series fixing Git segfaults when config settings lack values. It targets the ODB subsystem, specifically the alternate refs machinery used by `git fetch`, `git receive-pack`, and `git rev-list --alternate-refs`.

The patch addresses crashes in `fill_alternate_refs_command()` when `core.alternateRefsCommand` or `core.alternateRefsPrefixes` are set without values (e.g., `git -c core.alternateRefsCommand`). The current code passes NULL to `strvec_push()` or `strvec_split()`, causing segfaults. The fix replaces `repo_config_get_value()` with `repo_config_get_string_tmp()`, which rejects missing values with `config_error_nonbool()`, consistent with the series' overall approach. The test verifies that Git now emits a clear error message instead of crashing.

The change is minimal and surgical: two lines in `odb.c` and a new test case in `t/t5618-alternate-refs.sh`. The fix aligns with the precedent set by ba176db511 (2023-12-07) and follows the pattern established in patch 1/15 for `rebase.missingCommitsCheck`. Derrick Stolee’s review of v1 endorsed this approach, and the patch remains unchanged in v2. The test coverage is thorough, checking both config keys and confirming the error message format.

This is a well-motivated bugfix with no behavioral changes beyond preventing crashes. The patch is uncontroversial and ready for merge, pending resolution of the test conflicts noted in the cover letter.
