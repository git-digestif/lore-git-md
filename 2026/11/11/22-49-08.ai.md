This is the eighth patch in Thomas Bachem’s 15-patch v3 series fixing Git segfaults on unvalued config keys. It targets `branch.<name>.mergeOptions` in `git merge`: when the setting is given without a value (e.g., `branch.main.mergeOptions` in a config file or `-c branch.main.mergeOptions` on the command line), `git_merge_config()` passes the NULL value to `xstrdup()`, causing a crash. The fix adds a NULL check and rejects the missing value with `config_error_nonbool()`, matching the existing pattern for other string-valued settings in the same function. The patch includes a new test in `t/t7600-merge.sh` that verifies the error message and ensures the command fails cleanly.

The design is consistent with the series’ broader approach and with Git’s historical config semantics: missing values (no `=`) are treated as boolean `true`, while empty values (`=`) are treated as empty strings. Junio Hamano’s earlier reply in the thread cited the 2005 commit (17712991a5) that introduced this distinction, confirming that the asymmetry is intentional and too entrenched to change. This patch therefore rejects NULL values but allows empty strings, which are silently accepted and passed to `xstrdup()`. The behavior aligns with the rest of the series and with the project’s backward-compatibility requirements.

No new feedback or objections have emerged since the v3 update; the patch is uncontroversial and ready to merge once the test conflicts with `iw/connected-deepen-fetch-no-alternate-refs` and `kk/quarantine-alternate-refs` are resolved. The fix is minimal, well-tested, and addresses a clear crash.
