This is a brief but substantive reply in the ongoing RFC thread about adding `--verbose` support to `` `git history reword` ``. Patrick Steinhardt weighs in on the opt-in versus opt-out debate, aligning with D. Ben Knoble’s conditional acceptance of default diff display—provided it can be disabled via configuration. His comment introduces a new requirement: the chosen diff-display format must be reusable across all `` `git history` `` subcommands (e.g., `split`, `squash`, `fixup`) to avoid inconsistent editor behavior. This adds a design constraint that the author (Jelle van der Waa) will need to address if the series moves toward default behavior. The thread now has three reviewers (Karthik Nayak, Phillip Wood, Patrick Steinhardt) favoring opt-out with config support, one reviewer (D. Ben Knoble) conditionally accepting it, and the author still advocating for opt-in via a flag. The unresolved questions are whether config support should be added now and whether the diff format can scale to other subcommands.
