This is the fifth patch in Patrick Steinhardt’s seven-part series to speed up GitLab CI pipelines. It targets a specific bottleneck in the `t0027-auto-crlf.sh` test script, where the `compare_files()` and `compare_ws_file()` helper functions repeatedly recompute identical expected output files—over 1,000 times in a typical run. The fix caches these files on first use, cutting test runtime by 20–25% (Windows: 480s → 380s; macOS: 71s → 54s).

The patch is a straightforward optimization: it wraps the `tr`/`sed` pipelines in lazy-initialization blocks (`test -f "$1".expect || ...`) so the expected output is generated only once per input file. The diff is minimal—just nine lines changed in one file—and preserves the existing logic while eliminating redundant process spawning. Earlier discussion with Torsten Bögershausen explored an alternative that precomputed all expected files upfront, but Patrick’s benchmarks showed no meaningful performance difference, so the simpler incremental approach was retained.
