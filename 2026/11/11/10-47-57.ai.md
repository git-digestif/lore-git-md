This is the sixth patch in Patrick Steinhardt’s v3 series optimizing GitLab CI performance. It targets the `t1092-sparse-checkout-compatibility.sh` test script, which verifies sparse-checkout behavior across three repository configurations (full checkout, sparse checkout, sparse index). The patch replaces the current per-test repository initialization with a one-time template setup, reducing redundant `git sparse-checkout` and `git config` calls.

The optimization is straightforward: during the `setup template repositories` phase, the script creates three template repositories (`full-checkout.template`, `sparse-checkout.template`, `sparse-index.template`) with all necessary sparse-checkout configurations pre-applied. Each test iteration then copies these templates and performs a `git reset --hard`, eliminating the need to re-run `git sparse-checkout init` and `git sparse-checkout set` 100+ times. On Windows, this cuts test runtime from over 10 minutes to approximately 7 minutes—a meaningful improvement for a single test file.

The change is contained to the test script and introduces no new symbols or behavior changes. The template-based approach is a common pattern in test suites and carries minimal risk; the only potential concern would be stale template state, but the `git reset --hard` ensures each test starts from a clean slate. The patch aligns with the series’ broader goal of reducing CI bottlenecks by minimizing process overhead, particularly on slower platforms.
