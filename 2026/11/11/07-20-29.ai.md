This is a **platform compatibility discussion** continuing the APFS/mmap metadata quirk thread. Johannes Sixt (Hannes) adds a cross-platform perspective, noting that Git’s mmap emulation on Windows also exhibits delayed timestamp updates—similar to macOS/APFS—and cannot reliably emulate Linux’s timely `mtime` updates, even with `FlushViewOfFile`.

Hannes’s point broadens the scope of the issue: the APFS quirk is not unique to macOS. Git’s Windows mmap emulation, which is used for packfiles and indexes, also fails to update timestamps atomically, meaning the same change-detection problem could theoretically occur on Windows. However, like on macOS, Git’s own mmap usage on Windows is restricted to immutable or atomically-replaced files, so the practical impact is limited to third-party tools that mmap mutable working-tree files.

The key technical detail here is the Windows API limitation: `FlushViewOfFile` does not update file timestamps, making it impossible to emulate Linux’s behavior. This reinforces Brian M. Carlson’s earlier observation that POSIX compliance does not guarantee timely `mtime` updates for mmap writes, and that relying on such updates is inherently fragile across platforms.

Hannes does not propose a fix or take a position on whether the project should address the edge case. Instead, his comment serves as a cautionary note: any solution targeting macOS/APFS would need to account for Windows’s similar limitations, or risk creating inconsistent behavior across platforms. The discussion remains exploratory, with no patch or RFC yet in sight.
