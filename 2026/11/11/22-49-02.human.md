This is a bugfix patch from Thomas Bachem’s 15-part series that plugs a segfault in the object-database (ODB) layer when `core.alternateRefsCommand` or `core.alternateRefsPrefixes` is given without a value. The crash occurs in `fill_alternate_refs_command()` when the NULL value is passed to `strvec_push()` or `strvec_split()`. The fix replaces the unsafe `repo_config_get_value()` calls with `repo_config_get_string_tmp()`, which rejects missing values with `config_error_nonbool()`, matching the pattern established in the first patch of the series. A new test in `t/t5618-alternate-refs.sh` verifies that both settings now fail gracefully with a clear error message instead of crashing. The change is minimal, well-motivated, and uncontroversial; it should be ready to merge once the test conflicts with the `seen` branch are resolved.
