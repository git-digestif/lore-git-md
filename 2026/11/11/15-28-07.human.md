This is a **documentation patch** in Jasper Mayone’s five-part series adding filtering capabilities to `git worktree list` via `git for-each-ref`. It updates the `git-for-each-ref` man page to warn users that the `%(worktreepath)` atom can output paths containing newlines, which breaks scripts that read one record per line. The patch explains two safe parsing techniques: using a quoting option like `--shell`, or appending `%00` to the format string and splitting on NUL bytes. It also clarifies that when a branch is checked out in multiple worktrees, only one worktree path is shown.

The change is small (six lines added) and directly addresses a real usability pitfall. The commit message and diff are clear, and the advice matches established Git conventions for handling potentially unsafe output. This patch looks ready to integrate; it’s a straightforward improvement that doesn’t introduce controversy or technical debt.
