This is the second patch in Jasper Mayone’s five-part v5 series extending `git for-each-ref`’s `%(worktreepath)` atom and improving worktree safety. It updates the `git-for-each-ref` man page to document two edge cases: (1) the atom’s output can contain newlines, so scripts must use quoting options (`--shell`, `--perl`, etc.) or NUL-terminated output (`%00`) to parse it safely, and (2) when a branch is checked out in multiple worktrees, only one worktree path is shown. The patch is a straightforward documentation fix that addresses a real usability issue—scripts that read one record per line will break if a worktree path contains a newline. The warning is clear, actionable, and matches the guidance given elsewhere in Git’s documentation for similar parsing hazards. No code changes are involved; the patch touches only `Documentation/git-for-each-ref.adoc`. It is uncontroversial and ready for integration.
