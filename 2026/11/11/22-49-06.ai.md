This is patch 6/15 in the v3 series fixing Git segfaults when config settings lack values. It targets the `remote.<name>.tagOpt` setting, which controls whether `git fetch` fetches tags (`--tags`), suppresses them (`--no-tags`), or follows the default behavior. Previously, omitting the value (e.g., `git -c remote.origin.tagOpt`) caused a segfault because `handle_config()` passed the NULL value to `strcmp()`.

The fix aligns with the series' harmonized error handling for v3: missing values now trigger a warning (`"missing value for 'remote.origin.tagOpt'"`) and are ignored, matching the behavior for invalid values (e.g., `remote.origin.tagOpt=foo`). This change is consistent with patches 7/15 (blame colors) and reflects feedback from Phillip Wood, who raised consistency concerns in earlier versions. The patch adds a test in `t/t5505-remote.sh` verifying the warning and ensuring the command (`git remote`) succeeds.

The fix is minimal and uncontroversial, touching only `remote.c` and the test suite. No new symbols or API changes are introduced. The commit message clearly explains the crash scenario and the chosen resolution, and the test coverage is thorough. This patch is ready for merge alongside the rest of the series, pending resolution of the test conflicts in `seen`.
