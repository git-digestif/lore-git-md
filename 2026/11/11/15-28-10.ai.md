This is the fifth and final patch in Jasper Mayone’s v5 series introducing `%(currentworktree)` and refining `git branch` output. It uses the new ref-filter atom to clean up a visual redundancy: when you run `git branch` inside a worktree that is rebasing or bisecting a branch, the branch name appears twice—once in the `(no branch, rebasing topic)` header and again in the list with a `+` marker and the worktree path. The patch removes the `+` and path for the current worktree, leaving only the header line.

The change is small but well-motivated. It touches only `builtin/branch.c` and adds a single test in `t/t3203-branch-output.sh` that verifies the branch name no longer appears with a `+` or path when listed from its own worktree during a rebase. The test also confirms the `(no branch, ...)` header is still present, so the branch name remains visible. The implementation is straightforward: the default format string now checks `%(currentworktree)` before `%(worktreepath)`, so branches being rebased or bisected in the current worktree skip the `+` and path entirely.

This patch directly addresses Phillip Wood’s architectural suggestion from v4 and eliminates the need for the `here_format` logic that was previously used to suppress the `+` marker. The result is simpler, more maintainable code and a cleaner user experience. There are no backward-compatibility concerns here—users who customize `--format` strings will need to update them if they rely on the old behavior, but the default output is strictly improved. The patch is ready for integration.
