This is a **test fix** for Domen Kožar’s `post-worktree` hook series, specifically addressing a bug in the test suite for the pruning patch (v3 2/2). Anders Kaseorg identifies a fragile `sed` substitution in `t2401-worktree-prune.sh` that fails when the worktree path contains the substring `w2` (e.g., `/path/to/w20`). The fix replaces the `sed` command with a simple `cp` to avoid unintended replacements.

The issue is not in the hook implementation itself but in the test infrastructure, where the `sed` substitution was intended to simulate a damaged worktree entry by corrupting the `gitdir` file. Anders reports that this bug has already caused a test failure in Ubuntu’s Git package build, confirming it is a real-world problem. The fix is minimal and uncontroversial, but it highlights a recurring pattern of fragile string manipulation in Git’s test suite.

This patch does not advance the thread’s core design discussion about hooks vs. ownership IDs, but it is a necessary prerequisite for the series to be merged. The fix is straightforward and should be uncontroversial; the only question is whether Domen will incorporate it into a v4 or if Junio will apply it as a follow-up.
