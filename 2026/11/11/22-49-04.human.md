This is the fourth patch in Thomas Bachem’s 15-patch bugfix series that prevents Git from crashing when config keys are given without values. This specific patch addresses a segfault in `git fetch` and `git clone --bundle-uri` when `fetch.bundleCreationToken` is set without a value (e.g., `git -c fetch.bundleCreationToken`).

The fix is straightforward: the code now checks if `creationTokenStr` is NULL before passing it to `sscanf()`, treating a missing value the same way it treats an unparseable token—by defaulting to 0. This matches the existing behavior for invalid tokens and ensures the bundle list is downloaded as if no prior fetch had occurred. The patch includes a new test in `t/t5558-clone-bundle-uri.sh` that verifies the fix by cloning a repository with a malformed `fetch.bundleCreationToken` and confirming the token is correctly set to 1 after the fetch.

The change is minimal and well-motivated, with no controversy or design questions remaining. The test coverage is thorough, and the commit message clearly explains the problem and solution. This patch is part of a larger, effectively approved series that addresses a systemic issue; it should merge cleanly once the test conflicts with other topics in `seen` are resolved.
