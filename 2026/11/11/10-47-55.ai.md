This is the fourth patch in Patrick Steinhardt’s v3 series optimizing GitLab CI performance by speeding up slow tests. It targets `t0027-auto-crlf.sh`, a test script that verifies Git’s CRLF conversion logic across 2,600 test cases and is a known bottleneck on Windows, where it takes over 10 minutes to run.

The patch optimizes the `checkout_files()` helper function, which sets up the working directory for each test by removing old files and checking out fresh copies. The original implementation spawns ten separate processes—five `rm` and five `git checkout` invocations—per test setup. The new version consolidates these into a single `rm` and a single `git checkout` call, reducing process overhead and index rewrites. The change is minimal: it initializes an empty `paths` variable, builds a space-separated list of file paths in a loop, and then uses that list in a single `rm` and `git checkout` command. The patch also adopts Junio C Hamano’s defensive programming suggestion from the v2 review by explicitly initializing `paths=` to clarify its empty state.

Performance impact is measurable: the patch reduces runtime by about 20% across all platforms, cutting Windows execution time by roughly 2.5 minutes (from over 10 minutes to around 7.5 minutes). The optimization is uncontroversial—Junio’s feedback was purely stylistic, and the v3 revision incorporates it without altering the core logic. The patch touches only `t/t0027-auto-crlf.sh` and does not introduce new symbols or change on-disk formats. It is part of a broader CI speedup effort that has already demonstrated end-to-end pipeline improvements (e.g., macOS jobs from 29 to 18 minutes, Fedora from 35 to 16 minutes). This specific patch is low-risk, well-motivated by clear before/after metrics, and ready for integration.
