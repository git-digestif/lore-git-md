This is the fourth patch in Patrick Steinhardt’s v3 series to speed up GitLab CI. It targets the `t0027-auto-crlf.sh` test script, which verifies Git’s CRLF conversion logic across 2,600 test cases and is a notorious bottleneck—taking over ten minutes on Windows.

The patch optimizes the `checkout_files()` helper, which repeatedly resets the working directory by removing and re-checking out five specific files. The original implementation spawned ten separate processes (five `rm` and five `git checkout` calls) for each invocation. The new version consolidates these into a single `rm` and a single `git checkout`, reducing process overhead and index rewrites. The change is simple: build a space-separated list of file paths (`paths=`) and pass it to both commands in one go. A defensive programming tweak—explicitly initializing `paths`—addresses Junio’s feedback from v2.

Performance gains are consistent: a 20% runtime reduction across all platforms, with Windows seeing the biggest absolute improvement (~2.5 minutes shaved off). The patch is uncontroversial, well-motivated, and already reviewed; it’s a straightforward optimization with no behavioral changes or new dependencies. If the series lands, this will be one of the more impactful speedups for Windows CI.
