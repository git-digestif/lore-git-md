This is the fifth and final patch in Jasper Mayone’s v5 series introducing `%(currentworktree)` and refining `git branch` output. The patch stops `git branch` from redundantly marking a branch with `+` when the current worktree is in the middle of rebasing or bisecting it.

The change is small but well-motivated: when you run `git branch` inside a worktree that is rebasing `topic`, the output already starts with `* (no branch, rebasing topic)`, so showing `+ topic` on the next line is clutter. The patch uses the new `%(currentworktree)` atom to suppress the `+` marker and the worktree path for branches that the current worktree is actively rebasing or bisecting. Branches checked out normally (not in a transient operation) are unaffected, because `%(HEAD)` already marks them with `*`.

The implementation is clean: the default format string in `builtin/branch.c` is updated to nest `%(currentworktree)` inside the conditional logic, and the verbose-format path is similarly adjusted. The test in `t/t3203-branch-output.sh` verifies that the branch name appears without the `+` marker and that the worktree path is omitted, while still showing the expected `* (no branch, rebasing ...)` header.

This patch is a direct follow-up to Phillip Wood’s architectural suggestion in v4 and completes the series’ goal of making `git branch` output more composable and less noisy. It looks ready to integrate.
