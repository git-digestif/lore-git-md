This is a **clarification in the `git history --verbose` RFC thread**, specifically Patrick Steinhardt’s response to Phillip Wood’s request to define what "format" means in the context of generalizing diff display across all `git history` subcommands.

Patrick confirms that he is primarily concerned with the **output format**—how the diff (or other change summary) is presented in the editor template—rather than just the option name. He outlines four future use cases the format must accommodate: changes to commit layout (e.g., `git history split`), commit order (e.g., a future `git history move`), commit messages, and updates to multiple references. While he does not expect all of these to be implemented immediately, he insists the format must be flexible enough to support them. He suggests that `git range-diff`’s existing format could serve as a model, implying a structured, multi-commit summary rather than a simple unified diff.

This clarification shifts the discussion from user interface (flag naming, config keys) to **technical design**: the diff-generation logic must now be forward-compatible with a broader set of `git history` operations, not just `reword`. The thread’s unresolved debate over opt-in vs. opt-out remains, but Patrick’s answer adds a new constraint—any implementation must avoid painting itself into a corner for future subcommands.
