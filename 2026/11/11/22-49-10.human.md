This is the tenth patch in Thomas Bachem’s 15-patch bugfix series that plugs Git segfaults when config keys are given without values. It fixes a crash in the `safe.bareRepository` setting: if the key appears without a value (e.g., `safe.bareRepository` in a config file or `-c safe.bareRepository` on the command line), the callback `allowed_bare_repo_cb()` passes NULL to `strcmp()`, causing a segfault in any bare repository operation such as `git -C repo.git log`.

The fix is minimal: a NULL check is added in the callback, and the missing value is rejected with `config_error_nonbool()`. The existing logic already rejects any value other than `"explicit"` or `"all"`, so the patch simply extends that validation to cover the missing-value case. A new test in `t/t0035-safe-bare-repository.sh` verifies that the command fails cleanly and prints the expected error message.

The change is uncontroversial and follows the established pattern used throughout the series. No feedback or objections have been raised on this patch, and it is ready to merge once the series-wide test conflicts are resolved.
