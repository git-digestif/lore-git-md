This is a bugfix patch, part 5 of a 15-patch series that systematically eliminates Git segfaults when config settings are given without values. The series is effectively approved for merge pending resolution of minor test conflicts, and this patch addresses one of the 20 crash sites identified by the audit.

The patch fixes a segfault in `git grep`, `git log`, and `git show` when `grep.patternType` is specified without a value (e.g., `git -c grep.patternType`). The crash occurs because `grep_config()` passes the NULL value to `parse_pattern_type_arg()`, which then calls `strcmp()` on it. The fix adds a NULL check in `grep_config()` and rejects missing values with `config_error_nonbool()`, consistent with how the function already handles missing values for `color.grep.*` slots. The change is minimal and targeted, touching only `grep.c` and adding a test in `t/t7810-grep.sh` to verify the error message.

The fix aligns with the series' overall approach of rejecting unvalued config keys with `config_error_nonbool()` where appropriate, and the test coverage is thorough. No design questions or objections remain for this patch, and the commit message clearly explains the problem and solution. The patch is uncontroversial and ready for merge once the series' test conflicts are resolved.
