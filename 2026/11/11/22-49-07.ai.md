This is the seventh patch in Thomas Bachem’s 15-patch v3 series fixing Git segfaults when config keys are given without values. It targets the `color.blame.repeatedLines` and `color.blame.highlightRecent` settings in `git blame`, which previously crashed when passed a NULL value (e.g., `git -c color.blame.repeatedLines blame`).

The fix aligns error handling with the behavior for invalid values: missing `color.blame.repeatedLines` now triggers a warning and is ignored (matching how invalid values are handled), while missing `color.blame.highlightRecent` is rejected with `config_error_nonbool()` (consistent with existing behavior for `blame.date` and `blame.coloring`). This harmonization addresses Phillip Wood’s feedback from earlier versions, where he noted the inconsistency between rejecting missing values for some blame colors but not others. The patch includes two new tests in `t/t8012-blame-colors.sh` to verify the warning and error messages.

The change is minimal and targeted, touching only `builtin/blame.c` and its test file. No new symbols or API changes are introduced. The fix is uncontroversial and follows the series’ established pattern of preventing crashes while maintaining backward compatibility. The commit message clearly explains the rationale and edge cases, and the tests cover both the warning and error paths. This patch is ready for merge once the series’ test conflicts in `seen` are resolved.
