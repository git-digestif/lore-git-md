This is a test infrastructure patch that introduces `test-tool genbytes` to eliminate a performance bottleneck in Git's test suite on macOS. The patch is the fourth iteration of a series that has already received thorough review and is now ready for `next`.

The core issue is that several tests generate large amounts of data by piping `test-tool genzeros` through `tr(1)` to replace NUL bytes with another character. On macOS, `tr` processes each byte individually through `getwchar()` and `putwchar()`, making this operation extremely slow—especially in `t4205-log-pretty-formats.sh`, which generates over 2 GB of data. The new `genbytes` command writes arbitrary bytes directly, avoiding the need for `tr` entirely. Performance measurements show macOS CI jobs improving by 70–79%, while Linux jobs see smaller but still measurable gains.

The implementation is straightforward: `genbytes` shares code with the existing `genzeros` command, using a static 256 KB buffer to write bytes efficiently. The interface is simple—`test-tool genbytes <char> [<count>]`—and callers that need NUL bytes continue using `genzeros`. The patch updates 16 test scripts to use `genbytes` instead of `tr`, including a newly identified callsite in `t1600-index.sh` that was introduced in Git 2.50.2. Input validation is now stricter, using `git_parse_signed()` to reject invalid counts rather than silently treating them as zero.

Review feedback from Junio C Hamano and Patrick Steinhardt has been fully incorporated, including design choices like keeping `genzeros` for NUL bytes, using a static buffer to avoid stack exhaustion, and adopting a literal-character interface (`genbytes a`) for readability. The series is well-motivated, with clear performance benefits and no downsides for other platforms. The patch is mechanical and low-risk, touching only test infrastructure and leaving no loose ends. It looks ready for integration.
