This is a bugfix review targeting Domen Kožar’s v3 patch series introducing a unified `post-worktree` hook. Anders Kaseorg identifies a subtle but serious flaw in the test suite: the `sed` substitution that rewrites `.git/worktrees/w2/gitdir` to point to `w1` instead of `w2` will corrupt the file if the path contains another occurrence of `w2` (e.g., `/path/to/w20`). He proposes replacing the fragile `sed` command with a simple `cp` from the known-good `w1/gitdir`, which is both safer and clearer.

The issue affects both the new test in this patch and an existing one in `t2401-worktree-prune.sh`, and Anders reports it has already caused a test failure in Ubuntu’s Git package build. The fix is trivial but essential: the current code risks false positives in the test suite, undermining confidence in the hook’s correctness. This is a surface-level review (test-only, no behavioral change) but the bug is real and the remedy is straightforward. The patch series remains under active design discussion, but this feedback should be addressed before the next iteration.
