This is the third patch in Jasper Mayone’s five-patch v5 series that extends Git’s ref-filter to show which worktree is rebasing or bisecting a branch. The patch replaces the old O(N*M) lookup in `ref-filter.c` with a new O(1) helper, `branch_checked_out_worktree()`, that consults a hashmap populated during `prepare_checked_out_branches()`. It also stops printing the `git_dir` of bare repositories for `%(worktreepath)`, documenting this as a breaking change.

The motivation is clear: `%(worktreepath)` currently returns an empty string for branches being rebased or bisected, even though Git already treats those branches as “checked out” in other commands (`git worktree add`, `git branch -d`). The patch aligns the atom’s behavior with the rest of Git, so `git branch` and `git for-each-ref` now mark the branch with a `+` and show the correct worktree path. The implementation is clean—it removes ~50 lines of unused worktree-mapping machinery and adds comprehensive tests for rebasing, bisecting, and edge cases like `--update-refs` and bare repositories.

Performance is a key win: v4 introduced an O(N*M) regression that Phillip Wood identified; this patch restores O(1) lookups by reusing the existing `prepare_checked_out_branches()` infrastructure. The breaking change for bare repositories is small and well-documented, so it’s unlikely to break real-world scripts. The patch looks ready for integration.
