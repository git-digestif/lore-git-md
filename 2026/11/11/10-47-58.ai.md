This is the seventh and final patch in Patrick Steinhardt’s v3 series targeting GitLab CI speedups. It addresses a specific performance bottleneck in the test suite by switching two HTTP-fetch tests (`t5551-http-fetch-smart.sh`) from the traditional files-based ref backend to reftable.

The patch modifies only two lines in `t5551-http-fetch-smart.sh`, adding `--ref-format=reftable` to the `git init` and `git clone` commands that create and fetch from a repository with 2,000 tags. The change is surgical: the test’s logic remains unchanged, but the ref backend switch eliminates the need to create 2,000 loose files, reducing macOS test runtime from 20 minutes to 2 minutes (a 10x speedup) and halving Linux runtime. The commit message clarifies that the test’s focus is HTTP negotiation, not ref storage performance, making the backend choice irrelevant to the test’s validity.

This patch is a textbook example of a low-risk, high-impact optimization. It touches no production code, introduces no new dependencies, and preserves the test’s behavior while delivering measurable CI speedups. The reftable backend is already a mature part of Git, so the change carries minimal risk. The patch is part of a broader series that collectively reduces GitLab CI runtime by 30–50% across macOS, Fedora, and Windows runners, and this specific change is one of the most dramatic improvements in the series. Junio C Hamano has already signaled no technical objections to the series, and this patch in particular is unlikely to draw controversy.
