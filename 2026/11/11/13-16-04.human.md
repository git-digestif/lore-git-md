This is the second patch in Justin Tobler’s four-patch series refactoring Git’s ODB transaction machinery to create the temporary object directory eagerly at transaction start. The patch is a small, targeted performance optimization inside `object-file.c` that avoids an unnecessary hardware flush when batched fsync is disabled.

The change extracts the existing flush logic into a helper function, `flush_batched_fsync()`, and wraps the call in a check for `batch_fsync_enabled(FSYNC_COMPONENT_LOOSE_OBJECT)`. The motivation is straightforward: the flush is only needed when batched fsync is active; when objects are synced individually or not at all, the flush is redundant. The patch is uncontroversial and appears well-justified. Patrick Steinhardt’s review raises a minor documentation point—clarifying in the commit message that batched fsync currently only applies to loose objects—but otherwise accepts the change as correct. No code changes are requested, and the patch looks ready to proceed.
