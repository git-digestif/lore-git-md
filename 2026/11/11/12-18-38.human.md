This is the second patch in Patrick Steinhardt’s now-merged 12-patch series modernizing `git rerere`’s subcommand handling. It converts the legacy `#define` flags (`RERERE_AUTOUPDATE`, `RERERE_NOAUTOUPDATE`, `RERERE_READONLY`, `RERERE_NOWAIT`) into a proper `enum rerere_flags`, documents each value, and adds a `BUG()` check to catch the invalid case where both `RERERE_AUTOUPDATE` and `RERERE_NOAUTOUPDATE` are set simultaneously.

The change is purely internal: no new behavior, no CLI changes, and no on-disk format changes. The enum values are defined as bit shifts (`1 << 0`, `1 << 1`, etc.) to preserve the existing bitmask semantics, and the documentation now clearly explains the three-state system (follow the configured `rerere.autoUpdate` default, force `--autoupdate`, or force `--no-autoupdate`). The `BUG()` check in `rerere_cache_setup()` addresses a latent safety issue that was silently present in the old code: if both flags were set, `RERERE_AUTOUPDATE` took precedence without validation. The new check ensures this invalid state is caught immediately rather than silently ignored.

The patch touches only `rerere.c` and `rerere.h`, updating function signatures and the enum definition. The commit message is clear and concise, and the code follows Git’s modern coding guidelines.
