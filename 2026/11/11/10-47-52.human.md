This is the first patch in Patrick Steinhardt’s v3 series to speed up GitLab CI. It targets the slow installation of the Git for Windows SDK in the `build:mingw64` job, which previously took around three minutes per run due to the use of PowerShell’s `Expand-Archive` cmdlet.

The patch replaces `Expand-Archive` with `tar(1)`, cutting extraction time from roughly three minutes to ten seconds. The change relies on Windows shipping `bsdtar` (based on `libarchive`) by default, which can handle ZIP archives despite the command name. The patch also adds strict error handling (`$ErrorActionPreference = 'Stop'`) and suppresses progress output (`$ProgressPreference = 'SilentlyContinue'`) to avoid cluttering CI logs. A comment in the script now documents the `bsdtar` dependency, addressing Junio C Hamano’s earlier portability concern.

The diff is minimal—just five lines changed in `ci/install-sdk.ps1`—and the commit message clearly explains the rationale and the portability assumption. This is a well-motivated, low-risk optimization that directly addresses a known CI bottleneck. No behavioral changes or new symbols are introduced; the patch is purely about build-time performance. The series as a whole looks ready for `next`, and this patch in particular appears uncontroversial.
