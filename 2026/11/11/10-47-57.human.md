This is the sixth patch in Patrick Steinhardt’s seven-part series to speed up GitLab CI pipelines. It targets a specific bottleneck in `t1092-sparse-checkout-compatibility.sh`, a test script that verifies sparse-checkout behavior across three repository configurations (full checkout, sparse checkout, sparse index).

The patch replaces the existing `init_repos()` function, which recreates each test repository from scratch every time it is called (over 100 times in the test suite), with a template-based approach. A new `setup template repositories` phase creates one-time template repositories (`full-checkout.template`, `sparse-checkout.template`, `sparse-index.template`) during test initialization, and `init_repos()` now simply copies these templates and resets them to a clean state. This eliminates redundant `git sparse-checkout init`, `git sparse-checkout set`, and `git config` calls, reducing the Windows runtime from over 10 minutes to approximately 7 minutes—a roughly 30% improvement.

The change is contained to a single file (`t/t1092-sparse-checkout-compatibility.sh`) and introduces no new symbols or on-disk format changes. It is a pure test optimization, preserving the exact same test logic and assertions while reducing process overhead. The patch is well-motivated by the author’s CI metrics and aligns with the series’ overall goal of measurable runtime reductions. Junio C Hamano has already signaled no technical objections to the series, and this patch appears ready for integration.
