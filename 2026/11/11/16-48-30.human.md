This is the final patch in Justin Tobler’s four-patch series converting Git’s ODB transaction machinery to create its temporary object directory eagerly at transaction start. Karthik Nayak’s review is substantive but narrowly focused: he accepts the code changes as correct and well-structured, but presses for clarification on a key design assumption.

The patch itself removes the now-unused lazy-creation logic (`odb_transaction_files_prepare()`), updates the transaction begin routine to create the directory immediately, and adjusts the test suite to match the new error messages. Karthik’s only technical question is why large numbers of loose objects are not expected in ODB transactions—a point the commit message states but does not justify. This is not a correctness concern, but it does highlight a gap in the patch’s rationale that may need filling before the series lands. No other objections or requested changes are raised.
