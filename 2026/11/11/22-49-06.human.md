This is the sixth patch in Thomas Bachem’s 15-patch bugfix series that eliminates Git segfaults when config keys are given without values. It specifically addresses the `remote.<name>.tagOpt` setting, which controls whether `git fetch` fetches tags from a remote (`--tags`, `--no-tags`, or any other value, which is ignored). Previously, omitting the value (e.g., `git -c remote.origin.tagOpt`) caused a segfault because the code passed a NULL value to `strcmp()`.

The fix is minimal and consistent with the series’ broader approach: when the value is missing, the code now issues a warning (`"missing value for 'remote.origin.tagOpt'"`) and ignores the setting, matching the behavior for invalid values. This aligns with feedback from Phillip Wood, who raised consistency concerns in earlier versions of the series. The patch includes a new test in `t/t5505-remote.sh` that verifies the warning is emitted and the command (`git remote`) succeeds without crashing.

The change is uncontroversial and well-motivated, with no design questions remaining. The commit message clearly explains the problem and the chosen solution, and the test coverage is thorough. This patch is part of a larger effort to systematically audit and fix config-related segfaults, and it fits cleanly into the series’ goal of harmonizing error handling for missing values. The series as a whole is effectively approved for merge pending resolution of minor test conflicts.
