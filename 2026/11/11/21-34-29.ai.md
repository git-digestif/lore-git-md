This is a documentation patch, now at v5, that rewrites Git’s explanation of detached HEAD state. The patch is part of a concluded series (v4 was merged to `master` on 2024-07-10), but this revision incorporates final feedback from Junio C Hamano and D. Ben Knoble on phrasing and clarity.

The v5 patch refines the explanation of `HEAD` to make its role more uniform: it now opens by stating that `HEAD` always refers to the current commit, then clarifies that it stores either a branch name (indirectly pointing to a commit) or a commit ID (detached HEAD). This framing avoids anthropomorphism and aligns with Junio’s preference for technical precision while still prioritizing user accessibility. The patch also adds a note about the benefits of detaching HEAD (e.g., avoiding temporary branches) and tweaks the wording around how `HEAD` is stored internally ("branch name" instead of just "branch").

The implementation remains unchanged: the new content lives in `detached-head.adoc`, included by both `git-checkout.adoc` and the new `gitdetached-head(7)` man page, with updates to `advice.c` to reference the standalone guide. The range-diff shows only textual refinements—no structural or behavioral changes. The patch is well-motivated, addressing common user confusion about detached HEAD, and the v5 adjustments reflect a careful balance between accuracy and readability.
