This is the first patch in the v3 series fixing Git segfaults when config settings lack values. It targets the `rebase.missingCommitsCheck` option in `git rebase -i`, which crashes when given without a value (e.g., `git -c rebase.missingCommitsCheck` or a bare `missingCommitsCheck` in `.gitconfig`). The fix treats missing values the same as invalid ones: issuing a warning and defaulting to `"ignore"`, matching the existing behavior for unrecognized values.

The patch modifies `get_missing_commit_check_level()` in `rebase-interactive.c` to check for `NULL` after `repo_config_get_value()` and emit a warning before falling back to `MISSING_COMMIT_CHECK_IGNORE`. The test in `t/t3404-rebase-interactive.sh` verifies the warning is shown and that the rebase completes without dropping commits, using a simplified three-commit scenario and `test_commit_message` for clearer diagnostics. Phillip Wood’s feedback from v2 is incorporated here, settling the design question about whether missing values should be rejected or treated as invalid.

This is a well-scoped bugfix with thorough test coverage. The commit message clearly explains the crash scenario and the chosen resolution, and the code change is minimal and targeted. The patch is uncontroversial and effectively approved, pending resolution of the series’ test conflicts in `seen`. No new symbols or API changes are introduced.
