This is the third patch in Patrick Steinhardt’s v3 series targeting GitLab CI speedups, focusing on build optimization for Meson-based jobs. It addresses the disproportionately long runtime of the `fedora-breaking-changes-meson` job by switching Meson’s build type from `debug` (`-O0`) to `debugoptimized` (`-O2`), aligning it with Git’s traditional Makefile defaults (`-g -O2`). The change cuts the Fedora job’s runtime nearly in half (2100s → 1000s) by accelerating SHA256 hashing (500MB blob: 9.6s → 1.5s), while other Linux/macOS jobs see ~10% improvements. Windows builds paradoxically slow down by ~2 minutes, but test execution speeds up enough to offset the regression, leaving total runtime unchanged.

The patch is minimal—just two lines added to `.gitlab-ci.yml` and `ci/run-build-and-tests.sh`—and uncontroversial. Junio C Hamano’s prior feedback on v1 (noted in the thread summary) focused on build optimization trade-offs, but this version reflects no further objections. The commit message clearly explains the motivation (SHA256’s sensitivity to `-O0`), quantifies the performance impact, and acknowledges the Windows trade-off, making the rationale transparent. No new symbols or behavior changes are introduced; this is purely a build flag adjustment.

Key details for follow-up discussion: the patch targets the `fedora-breaking-changes-meson` job specifically, but the `debugoptimized` flag applies to all Meson builds in the CI pipeline. The Windows slowdown in the build step is noted but not addressed here, suggesting it may be revisited in future work. The change is part of a broader series that collectively reduces CI runtime by 30–50% across platforms, with this patch contributing the largest single improvement for Linux. No test coverage or on-disk format changes are involved.
