This is the **v5 cover letter for a four-patch `git imap-send` bugfix series**, now explicitly requesting re-integration into `next`. The goal is to make `git imap-send` fully RFC 5322-compliant by accepting any order and any case for `From:`, `Date:`, and `Subject:` headers, while fixing a tunnel-command memory leak and removing a `git-send-email`-specific exemption. The v5 update is minimal: Patch 2/4 now correctly handles both LF (`\n\n`) and CRLF (`\r\n`) line endings in the `has_required_headers()` helper, preventing false positives from body text. A new test verifies this edge case. Patch 1/4 (tunnel process lifecycle) was already merged to `next` on 2025-06-10 and remains unchanged; Patches 3/4 (removal of the `git-send-email` special case) and 4/4 (case-insensitive header matching) are also unchanged, with expanded test coverage added in v4.

The series touches only `imap-send.c` and `t/t9001-send-email.sh`, with no on-disk format changes. All prior feedback has been addressed, including defensive coding for the tunnel process (Patch 1/4), backward-compatibility documentation for the special-case removal (Patch 3/4), and test coverage for order-agnostic parsing (Patch 2/4) and mixed-case headers (Patch 4/4). The CRLF fix is targeted and uncontroversial, resolving the blocking issue without introducing new complexity.
