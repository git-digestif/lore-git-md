This is the fifth patch in Patrick Steinhardt’s v3 series optimizing GitLab CI performance by speeding up slow tests. It targets `t0027-auto-crlf.sh`, a test script notorious for its high process-spawning overhead on Windows.

The patch caches expected output files (`.expect` and `.ws-expect`) to avoid repeatedly regenerating them via `tr` and `sed` in the `compare_files()` and `compare_ws_file()` helper functions. These functions are called over a thousand times during the test, each time recomputing the same output from a small set of input files. By computing the expected output once and reusing it, the patch reduces the number of spawned processes and achieves a 20–25% runtime reduction: Windows execution time drops from 480 to 380 seconds, and macOS from 71 to 54 seconds.

The implementation is incremental and lazy: the expected files are generated only if they do not already exist (`test -f "$1".expect || ...`). This keeps the change minimal and avoids upfront computation overhead. The patch also removes the `rm` calls that previously deleted the temporary files, letting the test framework’s cleanup handle them instead. The diff touches only nine lines in `t/t0027-auto-crlf.sh`, making it a focused, low-risk optimization.

This patch was previously discussed in v1 and v2. Torsten Bögershausen proposed an alternative that precomputed all expected files upfront in a dedicated test phase, eliminating runtime `tr` calls entirely. Patrick benchmarked the alternative and found no meaningful performance difference, opting to retain the simpler incremental approach. The decision closes the discussion on this patch, leaving it unchanged in v3.

The change is uncontroversial and well-motivated, with clear before/after metrics and no behavior or on-disk format changes. It directly addresses a known bottleneck in Git’s test suite and complements the other optimizations in the series (e.g., SDK extraction speedups, reftable backend usage in other tests). The patch is ready for integration and should land in `next` unless new substantive concerns emerge.
