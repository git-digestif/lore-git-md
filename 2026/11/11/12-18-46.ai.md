This is patch 10/12 in the now-merged `ps/rerere-subcommands` series, a refactoring that modernizes `git rerere`'s subcommand handling by replacing its custom parsing logic with Git’s standard `OPT_SUBCOMMAND()` mechanism. The series is purely internal, with no behavior changes or new functionality.

This patch turns the "gc" subcommand into a proper subcommand by extracting its logic into a dedicated function, `cmd_rerere_gc()`. The function uses `parse_options()` to validate arguments and introduces a hidden `--skip-locked` option, preserving the existing behavior where `rerere_gc()` skips garbage collection if another process holds the lock. The global `--skip-locked` flag is removed from the top-level parser, as it is now handled locally within `cmd_rerere_gc()`. The patch also removes a test (`--skip-locked is only accepted by gc`) that is no longer needed, as the option is now scoped to the "gc" subcommand.

The change is mechanical and low-risk, following the established pattern from earlier patches in the series. The commit message is clear, and the diff is straightforward, showing the extraction of the "gc" logic into its own function and the removal of redundant code. This patch is a preparatory step for the final switch to `OPT_SUBCOMMAND()` in patch 11/12. No open questions or loose ends remain for this patch.
