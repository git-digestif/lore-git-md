This thread is a bug report from kongfankaikai about `git repack --drop-filtered` in partial clones. The issue is that the command currently fails entirely when it encounters a blob that is both eligible for dropping (due to the filter) and referenced by the current index. Instead of aborting, the author suggests Git should skip such blobs and continue processing the rest, optionally warning about the skipped objects. This would be especially useful in partial clones with large working trees, where the goal is to drop as many filtered objects as possible without disrupting the working state.

The report is well-documented and asks whether there’s a specific reason the condition is treated as fatal rather than recoverable. It touches on the repack machinery and partial clone support, areas actively developed by Patrick Steinhardt and Taylor Blau. The proposed change would affect the object-dropping logic in `builtin/repack.c` and likely require coordination with the index and object-filtering subsystems. So far, no patches or responses from maintainers or other contributors have been posted.
