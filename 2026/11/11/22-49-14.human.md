This is the fourteenth patch in Thomas Bachem’s fifteen-patch bugfix series that eliminates Git segfaults when config keys are given without values. This installment plugs a crash in the bundle-uri subsystem: when a bundle list contains `bundle.mode`, `bundle.heuristic`, `bundle.<id>.uri`, or `bundle.<id>.creationToken` without a value, `bundle_list_update()` passes the NULL pointer to `strcmp()`, `relative_url()`, or `sscanf()`, causing a segfault. The fix adds NULL checks at each site and rejects the malformed entry with `config_error_nonbool()`, making the list invalid so the clone or fetch proceeds without the bundles. The patch includes a new test in `t/t5750-bundle-uri-parse.sh` that verifies the error messages for every affected key.

The change is narrow and well-motivated: it follows the established pattern from earlier patches in the series, preserves the existing behavior for valid lists, and adds minimal overhead. The test coverage is thorough, exercising both top-level and per-bundle keys. No design questions remain; the only prior feedback (from Derrick Stolee) noted that the error message could be clearer but deferred improvement to a follow-up. This patch is ready to merge once the test conflicts with `iw/connected-deepen-fetch-no-alternate-refs` and `kk/quarantine-alternate-refs` are resolved.
