This is patch 12/15 in the v3 series fixing Git segfaults when config keys are given without values. It targets the `scalar` subsystem, specifically the `scalar reconfigure --all` command.

The patch addresses a crash in `get_scalar_repos()` where a NULL value for `scalar.repo` is passed to `string_list_append()`, which internally calls `xstrdup()` and thus dereferences NULL. The fix adds a NULL check and rejects missing values with `config_error_nonbool()`, consistent with the series' established pattern. The commit message explains this cannot break existing setups because `scalar register` always writes `scalar.repo` with a path, so the error case is purely defensive.

The change is minimal: one conditional in `scalar.c` and a new test in `t/t9210-scalar.sh` that verifies `scalar -c scalar.repo reconfigure -a` fails cleanly with an appropriate error message. The test follows the series' style of checking both the command's exit code and the error message content.

This patch is uncontroversial and aligns with the series' goal of systematically eliminating NULL-dereference crashes in config callbacks. No feedback was received on this specific patch in prior rounds, but the approach mirrors other fixes in the series (e.g., patches 10/15 and 11/15) that also use `config_error_nonbool()` for missing values. The fix is well-motivated and the test coverage is adequate.
