This is the fourth patch in Jasper Mayone’s five-patch v5 series extending Git’s ref-filter atoms to better handle worktree state. It introduces `%(currentworktree)`, a new atom that returns the absolute path of the current worktree if the ref is checked out there (or being rebased/bisected), and an empty string otherwise. The implementation is clean: it adds a second hashmap (`current_worktree_branches`) in `branch.c` that records only the branches checked out in the current worktree, mirroring the existing `checked_out_worktrees` map used by `%(worktreepath)`. Lookup is O(1), so there is no performance penalty. The patch touches `branch.c`, `ref-filter.c`, and `Documentation/git-for-each-ref.adoc`, and adds a test in `t/t6302-for-each-ref-filter.sh` that verifies the atom’s behavior in both the main and a linked worktree during a rebase. The atom is explicitly designed to be used with `%(if)` to treat the current worktree differently from others, which the next patch leverages to simplify the logic in `git branch`. This is a well-motivated addition that directly addresses Phillip Wood’s architectural suggestion from v4, and it looks ready for integration.
