This is the first patch in Patrick Steinhardt’s v3 series targeting GitLab CI speedups, focusing on the CI/build system. It replaces the slow `Expand-Archive` cmdlet in `ci/install-sdk.ps1` with `tar(1)` to extract the Git for Windows SDK, cutting installation time from ~3 minutes to ~10 seconds. The patch also adds strict error handling (`$ErrorActionPreference = 'Stop'`) and suppresses progress output (`$ProgressPreference = 'SilentlyContinue'`).

The key technical detail is the use of `tar -xf` to extract a ZIP archive, which works because Windows now ships `bsdtar` (based on `libarchive`) by default. This portability assumption is explicitly documented in the commit message and a comment in the script, addressing Junio C Hamano’s earlier concern about the tool’s availability. The change is minimal—just six lines modified—but delivers a dramatic performance improvement for Windows CI jobs.

This patch is part of a broader effort to reduce CI runtime bottlenecks, with measurable speedups demonstrated in the series’ GitLab merge request. The author positions it as low-risk, given the widespread availability of `bsdtar` on Windows and the lack of behavioral changes. No new symbols or on-disk formats are introduced, and the patch touches only the CI infrastructure.

The v3 revision adds the portability documentation that Junio requested in his review of v1, closing the only open question from prior feedback. The series as a whole has no outstanding technical objections from Junio, who called the patches "interesting" and "fully made sense." This patch is likely to proceed to `next` unless new concerns emerge.
