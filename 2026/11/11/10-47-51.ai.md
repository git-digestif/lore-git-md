This is a CI/build system patch series (v3) that targets GitLab CI speedups. The author, Patrick Steinhardt, addresses slow test execution in Git's continuous integration pipelines with a series of optimizations that collectively reduce end-to-end CI runtime. This revision incorporates feedback from Junio C Hamano and Torsten Bögershausen, adding documentation for the `tar` portability assumption and a defensive programming tweak in `t0027-auto-crlf.sh`.

The series consists of seven patches that touch `.gitlab-ci.yml`, `ci/install-sdk.ps1`, `ci/run-build-and-tests.sh`, and test scripts (`t0027-auto-crlf.sh`, `t1092-sparse-checkout-compatibility.sh`, `t5551-http-fetch-smart.sh`). Key optimizations include: replacing `Extract-Archive` with `tar(1)` to cut Git for Windows SDK installation from 3 minutes to 10 seconds (patch 1/7); optimizing repository reset logic in `t0027` to reduce Windows test time from over 10 minutes to 6 minutes (patch 4/7); and enabling reftable usage in `t5551`/`t5559` to achieve 10x speedups on macOS (from 20 minutes to 2 minutes per test, patch 7/7). The series also introduces Meson-optimized builds (`-Doptimize=debug`) and template-based repository setup in `t1092`, reducing redundant `git sparse-checkout` calls.

Changes in v3 are minimal but address prior feedback: patch 1/7 now documents why Windows' `tar` can extract ZIP archives (clarifying the `bsdtar`/`libarchive` dependency), and patch 4/7 explicitly initializes the `paths` variable in `checkout_files()` to avoid ambiguity. The author provides a GitLab merge request link demonstrating measurable speedups: macOS jobs improve from 29 to 18 minutes, Fedora jobs from 35 to 16 minutes, and Windows pipelines see a ~10-minute reduction. Windows runners remain the critical path, but the optimizations meaningfully accelerate feedback for other platforms.

Junio C Hamano has previously stated he has no technical objections to the series, calling the patches "interesting" and "fully made sense." The v3 changes are surface-level (documentation and defensive programming) and do not alter the core optimizations. The series appears ready for `next` unless new substantive concerns emerge. The author positions this as a low-risk, high-impact improvement to CI infrastructure, with clear before/after metrics and no on-disk format changes.
