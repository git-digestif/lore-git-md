This is a test infrastructure patch that introduces `test-tool genbytes` to eliminate a performance bottleneck in Git's test suite on macOS. The patch is the fourth iteration of a series that has been thoroughly reviewed and is now ready for `next`.

The core issue is that several tests generate large amounts of data by piping `test-tool genzeros` through `tr(1)`, which is unusually slow on macOS—taking up to two minutes of CPU time for 2 GB of data in `t4205-log-pretty-formats.sh`. The new `genbytes` command writes arbitrary bytes directly, avoiding the need for `tr`. Performance measurements show macOS CI jobs improving by 70–79%, while Linux jobs see smaller but still measurable gains (2–7%).

The implementation is straightforward: `test-tool genbytes <char> [<count>]` writes `<count>` copies of `<char>` to stdout, sharing code with the existing `genzeros` command (which remains unchanged for callers that need NUL bytes). The patch updates 16 test scripts to use `genbytes` instead of `tr`, including a newly identified callsite in `t1600-index.sh` that was introduced in Git 2.50.2. The buffer allocation uses a static 256 KB buffer to avoid stack exhaustion, and input validation is stricter thanks to `git_parse_signed()`.

All prior review feedback has been addressed. Junio C Hamano and Patrick Steinhardt have both signaled readiness for integration, and the author has committed to a trivial rebase to handle the remaining callsite. The series is well-motivated, thoroughly tested, and uncontroversial—it’s a clear win for test suite performance on macOS without any downsides for other platforms. The patch touches only test infrastructure and has no impact on Git's on-disk formats or user-facing behavior.
