This is the seventh and final patch in Patrick Steinhardt’s v3 series **GitLab CI speedups**, targeting a specific performance bottleneck in the test suite. The patch switches two test scripts (`t5551-http-fetch-smart.sh` and, by extension, `t5559`) to use the reftable backend for repositories that create nearly 100,000 refs, cutting test runtime on macOS from 20 minutes to 2 minutes—a 10× speedup. On Linux, the same tests run twice as fast.

The change is surgical: two lines in `t5551` add `--ref-format=reftable` to `git init` and `git clone` calls. The tests verify HTTP fetch negotiation, not ref backend behavior, so the switch is safe and does not alter the system under test. The patch is well-motivated by CI metrics and carries minimal risk; it simply leverages reftable’s strength (single-table writes for many refs) where the files backend struggles (thousands of loose files).

This is a **performance patch** for the test suite, not a user-facing feature or bugfix. It directly addresses the CI bottleneck identified in the series cover letter, and the before/after numbers make the benefit clear. No new symbols or on-disk formats are introduced, and the change is isolated to test setup.
