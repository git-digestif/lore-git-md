This is a bugfix patch (11/15) in a well-reviewed series that eliminates Git segfaults when config keys are given without values. The patch targets the `pseudo-merge` subsystem, specifically the `bitmapPseudoMerge.<name>.pattern` config key used by `git repack -adb` to generate pseudo-merge bitmaps. When this key is set without a value (e.g., `git -c bitmapPseudoMerge.test.pattern repack -adb`), the callback `pseudo_merge_config()` dereferences the NULL value while checking if the pattern starts with `^`, causing a segfault.

The fix is straightforward: the callback now checks for a missing value (`!value`) and rejects it with `config_error_nonbool()`, consistent with the series' established pattern and the callback's existing validation for threshold keys (which already uses `git_config_expiry_date()`). The patch includes a new test in `t/t5333-pseudo-merge-bitmaps.sh` that verifies the error message and ensures the command fails cleanly. The test follows the series' style of using `test_must_fail` and `test_grep` to confirm the expected error output.

This patch is uncontroversial and aligns with the series' goal of systematically addressing unvalued config keys. The fix is minimal, targeted, and well-motivated, with no behavior changes beyond preventing the crash. The test coverage is adequate, and the commit message clearly explains the problem and solution.
