This is the penultimate patch in Patrick Steinhardt’s now-merged 12-patch series modernizing `git rerere`’s subcommand handling. Patch 11/12 replaces the hand-rolled subcommand ladder with Git’s standard `OPT_SUBCOMMAND()` mechanism, completing the core refactoring goal.

The change is mechanical and well-contained: the custom string-matching logic in `cmd_rerere()` is removed, and each subcommand ("clear", "diff", "forget", "gc", "remaining", "status") is registered via `OPT_SUBCOMMAND()`. The fallback case—when no subcommand is given—is now handled by a new `cmd_rerere_perform()` function that parses the `--[no-]rerere-autoupdate` flags locally instead of globally. This fixes a long-standing inconsistency: the flags were previously accepted by all subcommands but only honored by the default (no-subcommand) case. The patch also removes the global `--[no-]rerere-autoupdate` options from the top-level parser, making the CLI interface more predictable.

The diff is clean and the commit message forthright about the backwards-incompatible change, framing it as a bug fix rather than a feature regression. The only minor quirk is the need to copy the argument array to avoid leaking strings when `parse_options()` modifies it; this is a necessary workaround for the current API. The patch is part of a series that has already been cooking in `next` and is now merged to `master`, so the risk is low and the benefit—consistency with other multi-subcommand built-ins—is clear. Reviewers who care about CLI parsing or the rerere subsystem will find this a satisfying conclusion to the series.
