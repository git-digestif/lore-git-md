This is a **platform compatibility discussion** continuing the thread about APFS, mmap, and Git's change detection. Johannes Sixt (Hannes) adds a cross-platform perspective, noting that Git's mmap emulation on Windows behaves similarly to macOS/APFS in not updating file timestamps promptly.

Hannes points out that Git's Windows mmap emulation cannot replicate Linux's behavior of updating `mtime`/`ctime` immediately after writes. Even Windows' `FlushViewOfFile` function does not update timestamps, making the emulation closer to macOS's delayed timestamp updates than to Linux's immediate ones. This observation broadens the scope of the discussion: the APFS quirk is not unique to macOS, and any fix would need to account for Windows as well.

The comment reinforces the earlier consensus that Git's own mmap usage is unaffected (since it only mmaps immutable or atomically replaced files), but it complicates the question of whether to address the edge case for third-party tools. If the behavior is shared across platforms, the project might need to decide whether to treat it as a general limitation or to implement platform-specific workarounds.

No patch or concrete proposal emerges from this reply, but it shifts the focus from "Apple's quirk" to a broader "mmap timestamp inconsistency" issue. The thread remains exploratory, with no clear direction yet on whether or how to proceed.
