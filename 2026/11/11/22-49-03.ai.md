This is a bugfix patch, part 3 of a 15-patch series that systematically eliminates Git segfaults triggered by config settings given without values. The series is effectively approved for merge pending resolution of test conflicts, and this patch addresses a crash in the interactive patch modes (`git add -p`, `git add -i`, etc.) when color slots like `color.interactive.prompt` or `color.diff.frag` are specified without values.

The fix replaces `repo_config_get_value()` with `repo_config_get_string_tmp()` in `add-patch.c`, ensuring that missing values are rejected with `config_error_nonbool()` rather than being passed as NULL to `color_parse()`, which would segfault. This aligns the behavior with how `git diff` already handles missing values for diff colors. The patch includes a new test in `t/t3701-add-interactive.sh` that verifies the error message when `color.interactive.prompt` is given without a value.

The change is minimal and targeted, touching only the `init_color()` function in `add-patch.c` and adding a test case. The commit message clearly explains the problem (segfault due to NULL value) and the solution (reject missing values with `config_error_nonbool()`). The test coverage is thorough, using `test_must_fail` and `test_grep` to confirm the expected error message. This patch is uncontroversial and follows the established pattern from earlier patches in the series. No further feedback or design questions are expected for this specific fix.
