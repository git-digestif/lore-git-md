This is a **worktree safety and usability feature** that builds on the earlier v4 series. The author, Jasper Mayone, has addressed the most significant review feedback from Phillip Wood and others, resulting in a cleaner, more performant, and more composable implementation.

The series now consists of five patches. The first two remain largely unchanged: patch 1 makes `git worktree remove` refuse to delete a worktree in the middle of a rebase, bisect, cherry-pick, revert, or `git am` operation unless `--force` is given, and patch 2 documents how to safely parse `%(worktreepath)` in `git for-each-ref`. The key improvements are in patches 3–5.

Patch 3, which extends `%(worktreepath)` to report the worktree path for branches being rebased or bisected, has been **completely rewritten** to address the performance regression Phillip Wood identified. Instead of iterating over all worktrees for every ref (O(N*M) complexity), the patch now uses a hashmap in `branch.c` for O(1) lookups, restoring the original performance while avoiding code duplication. This is a clear win: the implementation is both faster and cleaner.

Patch 4 is entirely new. It introduces `%(currentworktree)`, a ref-filter atom that returns the path of the current worktree if it has the branch checked out (or is rebasing/bisecting it), and an empty string otherwise. This atom is implemented using a second hashmap in `branch.c`, ensuring O(1) performance. The addition is well-motivated: it allows users to distinguish the current worktree from others in format strings, which was previously impossible without unsafe string comparisons. The documentation is clear, and the tests cover both the current and non-current worktree cases.

Patch 5 replaces the previous patch 4, which removed the redundant `+` marker in `git branch` output for worktrees rebasing or bisecting their own branch. The new implementation uses `%(currentworktree)` to achieve the same goal in a more elegant way: the default format now omits the `+` marker and worktree path for branches being operated on in the current worktree, while preserving the existing behavior for all other branches. This approach is more maintainable and composable, as it leverages the new atom rather than introducing special-case logic in `builtin/branch.c`.

The series is **backward-incompatible** for scripts that rely on the old behavior of `%(worktreepath)` (empty for rebasing/bisecting branches, printing the `git_dir` of bare worktrees), the `+` marker in `git branch` output, or the ability to delete in-progress worktrees without `--force`. The commit messages explicitly ask whether any such scripts exist, which is a responsible way to handle the compatibility risk. The implementation is well-tested, with thorough coverage of edge cases like rebasing, bisecting, and bare repositories.

The most significant open question is whether there are scripts that rely on the old behaviors. Beyond that, the series looks **ready for integration**. It addresses a real usability gap, fixes a safety issue, and does so with clean, performant code. The introduction of `%(currentworktree)` is particularly noteworthy, as it provides a general mechanism for distinguishing the current worktree in format strings, which could be useful for future enhancements. The author has clearly engaged thoughtfully with the review feedback, and the result is a stronger series.
