This is a platform compatibility follow-up. Patrick Steinhardt responds to Sven Strickroth’s inquiry about whether Git is affected by zlib 1.4’s behavioral change in raw deflate return values.

Patrick clarifies that the change only impacts raw deflate operations, which Git uses exclusively in `archive-zip.c`. He audits the two relevant code paths: one that compresses into a pre-allocated buffer and another that streams compressed output. Both loops already handle `Z_STREAM_END` correctly, so he concludes that Git is unaffected by the zlib 1.4 change. The response is concise, technically precise, and closes the inquiry without requiring further action. If you maintain a Git installation that uses zlib 1.4, this summary confirms no compatibility issues.
