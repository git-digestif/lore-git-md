This is the seventh patch in Thomas Bachem’s 15-patch bugfix series that systematically eliminates Git segfaults triggered by config settings given without values. This patch specifically addresses crashes in `git blame` when `color.blame.repeatedLines` or `color.blame.highlightRecent` are set without values (e.g., `git -c color.blame.repeatedLines blame hello.c`).

The fix aligns the handling of missing values with the existing behavior for invalid values: for `color.blame.repeatedLines`, a missing value now triggers a warning and is ignored (matching the behavior for invalid colors), while for `color.blame.highlightRecent`, a missing value is rejected with `config_error_nonbool()` (consistent with how `blame.date` and `blame.coloring` are handled). The patch includes two new tests in `t/t8012-blame-colors.sh` to verify the behavior: one checks that `color.blame.repeatedLines` without a value only warns and does not crash, and the other ensures `color.blame.highlightRecent` requires a value.

This patch is part of the v3 update, which harmonizes error handling for missing values across the series. The design for this patch was settled in earlier discussion, and the implementation is straightforward and well-tested. The fix is uncontroversial and directly addresses the segfault without introducing new behavior or API changes. The commit message clearly explains the rationale and the distinction between the two config keys.
