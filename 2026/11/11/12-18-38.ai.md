This is the second patch in the now-merged 12-patch series modernizing `git rerere`'s subcommand handling. It converts the legacy `#define` flags (`RERERE_AUTOUPDATE`, `RERERE_NOAUTOUPDATE`, `RERERE_READONLY`, `RERERE_NOWAIT`) into a proper `enum rerere_flags`, aligning with Git’s modern coding guidelines. The patch also adds a `BUG()` check in `rerere_cache_setup()` to catch the invalid state where both `RERERE_AUTOUPDATE` and `RERERE_NOAUTOUPDATE` are set simultaneously, addressing a latent safety concern identified in earlier versions of the series.

The change is mechanical and low-risk: the enum values are defined as bit shifts (`1 << 0`, `1 << 1`, etc.) to preserve the existing bitmask semantics, and all function signatures are updated to use the new type. The patch also expands the documentation for each flag, clarifying their purpose and the three-state system they form (follow default, force autoupdate, force no-autoupdate). Notably, the documentation for `RERERE_NOAUTOUPDATE` now explicitly states that it updates the working tree but leaves the index untouched while printing conflict-resolution messages to stderr.

Files touched are `rerere.c` and `rerere.h`, with no behavior changes or new functionality. The `BUG()` check is a defensive measure to ensure no silent precedence behavior (where `RERERE_AUTOUPDATE` would previously take precedence over `RERERE_NOAUTOUPDATE` without validation). This patch is a prerequisite for later patches in the series, which rely on the enum type for subcommand parsing.

The patch addresses feedback from Karthik Nayak (who suggested expanding the documentation for `RERERE_NOAUTOUPDATE`) and Junio C Hamano (who confirmed the correctness of the existing `RERERE_NOWAIT` comment). The `BUG()` check was added in response to a post-merge review of v3, where the latent issue was first identified. The patch is now part of `master` and is considered complete.
