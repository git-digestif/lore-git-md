This is a bugfix for `git ls-tree`, now in its second iteration as a standalone single-patch series. The patch corrects the handling of the `%(path)` placeholder when `-z` and `--format` are used together: since `--format` was introduced in 2022, `ls-tree` has always applied C-style quoting to paths even when `-z` requested verbatim null-terminated output, contradicting the documentation and diverging from `git ls-files --format`, which already emits paths unquoted under `-z`. The fix is a small branch in `show_tree_fmt()` within `builtin/ls-tree.c` that appends the raw path with `strbuf_addstr()` when `options->null_termination` is set, falling back to `quote_c_style()` otherwise.

Version two responds directly to maintainer feedback on the initial submission. Where v1 used a Hebrew filename to exercise the quoting path, v2 constructs the test tree with `git mktree` using a path containing a double quote, keeping the test entirely within US-ASCII and independent of filesystem capabilities, and it explicitly sets `core.quotePath=true` to ensure the quoting behavior is deterministic. The regression test in `t/t3104-ls-tree-format.sh` now verifies that `ls-tree -z --format="%(objecttype) %(path)"` emits the raw path followed by a NUL byte.

Junio C Hamano reviewed the v1 code change as "trivially correct" and accepted the approach, though he had suggested the test avoid non-ASCII bytes; v2 addresses that concern while preserving the test's ability to catch the regression. The patch appears well-motivated and ready for integration, with no objections raised to the fix itself, though no integration branch has yet been named.
