This is a bugfix for `git mv` that closes a hole in the symlink protection added by commit 062d90b2a8. That earlier commit taught `cmd_mv()` to reject destinations whose leading path contains a symbolic link, but its test only exercised a dangling symlink. Dominik Maier points out that when the target file actually exists on disk beyond a symlinked directory, `lstat()` succeeds, the `-f` flag clears the error state, and an unconditional `goto act_on_entry` skips the symlink and sparse-checkout checks entirely -- allowing `git mv -f` to overwrite the file through the symlink.

The fix is a one-line change in `builtin/mv.c`: the `goto act_on_entry` now only fires when `bad` is non-NULL, so forced overwrites still flow through the remaining destination validation including `has_symlink_leading_path()`. The patch also adds a regression test to `t/t7001-mv.sh` that creates a real file beyond a symlinked directory, confirms `git mv -f` refuses to overwrite it, and verifies the target remains intact.

The commit message clearly traces the regression to the specific commit and explains the exact code path that bypassed the check, and the included test covers the previously untested case where the destination exists. It looks like a solid, well-targeted fix that should be straightforward to review.
