# Thread deltas

## 2026/11/19

- [2026/11/19/19-23-11 by Dominik Maier <dmnk@google.com>] Dominik Maier posted a patch modifying `add_file_cb()` in `archive.c` to pass `is_remote` into the callback and reject `--add-file` and `--add-virtual-file` immediately before calling `stat()` on the server filesystem, fixing the issue where `git-upload-archive` would report "File not found" or succeed with `--no-add-file` before reaching the existing `--remote` incompatibility check in `parse_archive_args()`; the patch also adds test cases to `t/t5000-tar-tree.sh` verifying the rejection occurs before the filesystem is touched.

## 2026/11/21

- [2026/11/21/15-15-29 by René Scharfe <l.s.r@web.de>] René Scharfe acknowledged Dominik Maier's bug report as a "good find".
- [2026/11/21/15-15-29 by René Scharfe <l.s.r@web.de>] René Scharfe noted that the current code's rejection of --add-virtual-file combined with --remote is arguably also a bug, since the option's value brings file name and content to the remote end.
- [2026/11/21/15-15-29 by René Scharfe <l.s.r@web.de>] René Scharfe observed that the proposed patch would also reject --remote --add-file=foo --no-add-file, which could be allowed.
- [2026/11/21/15-15-29 by René Scharfe <l.s.r@web.de>] René Scharfe suggested moving the stat(2) call to after applying any --no-add-file but before writing archive content, refusing to perform it if is_remote is set, and noted that files added using --add-file have content == NULL.
