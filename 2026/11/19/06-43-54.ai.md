This is patch 2/4 of Elia Pinto's v3 series fixing silent 32-bit integer truncation in Git's large-file handling, specifically targeting the complete-rewrite diff path (`git diff -B`). The patch widens size and line-count types from `int` or `long` to `size_t` throughout `diff.c`, affecting `count_lines()`, `emit_rewrite_lines()`, `count_trailing_blank()`, `check_blank_at_eof()`, `add_line_count()`, `emit_rewrite_diff()`, and the `blank_at_eof_in_preimage`, `blank_at_eof_in_postimage`, `lno_in_preimage`, and `lno_in_postimage` fields of `struct emit_callback`. Previously, files of 2 GiB or more caused the size parameter to truncate to a negative value, making `git diff -B --stat` report zero changed lines and `git diff -B -p` emit an empty `@@ -0,0 +0,0 @@` hunk that `git apply` rejects while still exiting successfully. The patch also fixes a latent bug on LLP64 platforms like 64-bit Windows, where `count_trailing_blank()` previously stored the buffer size in a 32-bit `long`, potentially underflowing the pointer for buffers over 2 GiB. Single line lengths remain `int` but are now guarded by `cast_size_t_to_int()` before being passed to `emit_del_line()` and `emit_add_line()`.

The code is unchanged from v2, which had addressed Phillip Wood's review feedback on the `count_lines()` flaw, but the commit message has been shortened; the patch currently awaits re-review from Phillip Wood. Two EXPENSIVE tests are added to `t/t4022-diff-rewrite.sh`, both gated on `SIZE_T_IS_64BIT` and `LONG_IS_64BIT` prerequisites: one verifies numstat and patch output for a 2 GiB file (expecting 536,870,912 lines), and the other verifies numstat for a file with 2^31 lines. The commit message includes a reproduction recipe using approximately 2.2 GiB of data to demonstrate the pre-patch failure mode. This patch is part of a four-patch series that also touches `builtin/fast-import.c`, `builtin/pack-objects.c`, `diffcore-delta.c`, and `t/t4052-stat-output.sh` to fix similar truncation issues in packfile generation, rename detection, and diffstat scaling; coordination with a separate loose-object-size series means that series' patch 6/6 will be dropped to avoid conflicts with the `count_trailing_blank()` changes here.
