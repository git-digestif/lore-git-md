This is a follow-up ping on an under-review bugfix series, not a new patch. Elia Pinto is nudging the list for feedback on a two-patch series that fixes silent 4 GiB truncation in `git grep` and `git diff` on platforms where `long` is 32 bits but `size_t` is 64 bits (notably 64-bit Windows). The series has received no comments since posting, and the author confirms it still applies cleanly to current `master` (e1ec09b23c) and merges cleanly with `seen`.

The central question the author wants answered concerns the design of patch 2/2. Rather than widening `diff_filespec.size` from `unsigned long` to `size_t` -- a change that would touch significantly more code across `diff.c`, `combine-diff.c`, and `diff-no-index.c` -- the current approach makes `git diff` die with a clear error when encountering working-tree files, textconv output, or `--no-index` inputs of 4 GiB or larger. This matches the existing behavior for blobs, which already error out, and prevents the generation of misleading patches that would truncate files if applied. The author asks whether this "die early" strategy is acceptable as an intermediate step, or whether reviewers would insist on the full widening instead.

For context, patch 1/2 addresses `git grep` by widening `grep_source.size` and related buffer-size fields in `builtin/grep.c` and `grep.h` to `size_t`, allowing the command to correctly search files larger than 4 GiB. Patch 2/2 leaves the `diff_filespec.size` field as `unsigned long` but adds `cast_size_t_to_ulong()` checks in `diff_populate_filespec` and related paths to detect truncation and abort. No tests accompany either patch because generating 4 GiB inputs is impractical; the author instead verified the grep fix by simulating truncation at 16 bits.

The underlying issue is that on 64-bit Windows (and similar LP64-with-32-bit-long platforms), file sizes above 4 GiB were silently truncated when stored in `unsigned long` variables, causing `git grep` to miss matches and `git diff` to produce corrupt patches. The series is self-contained with no dependencies on other in-flight topics, and the remaining `-Wshorten-64-to-32` warnings are noted as either unreachable or confined to xdiff internals where input is already capped at 1023 MiB.
