# Thread deltas

## 2026/11/19

- [2026/11/19/19-23-07 by Dominik Maier <dmnk@google.com>] Dominik Maier submitted a patch fixing `repo_config_copy_or_rename_section_in_file()` in config.c so that remove-section and rename-section no longer stop early when a backslash-continued value contains a line beginning with '['; the patch adds `skip_section_header()` and `update_line_continuation()` to track continuation and quote state across lines (so '#' or ';' inside quotes are not treated as comments) and only treat '[' as a section header at the start of a logical line, along with tests in t/t1300-config.sh covering multiline values with smuggled brackets and quoted subsection names containing ']'.

## 2026/11/20

- [2026/11/20/00-44-52 by Junio C Hamano <gitster@pobox.com>] Junio C Hamano asked whether treating backslash-continued lines as part of the preceding value during section copy/rename would be a breaking change that could negatively affect existing configuration files, and noted that the patch's declaration of `was_continued` after statements triggers `-Wdeclaration-after-statement`.
- [2026/11/20/14-33-31 by Phillip Wood <phillip.wood123@gmail.com>] Phillip Wood argued that the patch aligns section copy/rename parsing with config-reading parsing without changing how settings are read, making it a bug fix for an unlikely corner case rather than a breaking change; noted that parsing is implemented twice instead of sharing a common code path; and reported that the patch does not handle carriage returns in values and subsection names correctly (treating `\r` like `\n`), giving the example that `printf '[a "b\rc"]\rkey=\rv\ralue'` creates a valid config where `git config get` returns "vQal" but the patch would misparse it.
