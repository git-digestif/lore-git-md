This is a refactoring patch, specifically the seventh of thirteen in Patrick Steinhardt's v5 series that modernizes `git rerere`'s subcommand handling by replacing custom string comparisons with the standard parse-options `OPT_SUBCOMMAND()` mechanism. The patch extracts the "status" subcommand logic from the monolithic `cmd_rerere()` into a dedicated static function `cmd_rerere_status()`, following the same pattern established in the preceding patches for "forget" and "clear".

The new handler runs `parse_options()` with an empty options array, rejects any extra arguments with `usage(_("too many arguments"))`, and sets up the rerere cache with `RERERE_READONLY` before printing the paths from the merge_rr string list. This flag choice aligns with the preparatory cleanup in patch 4/13, which established that read-only subcommands like "status" should pass only `RERERE_READONLY` rather than the full flags variable. The main `cmd_rerere()` now simply dispatches to this new function when `argv[0]` equals "status", shrinking the central dispatch chain.

The commit message notes this is a preparatory step toward the eventual `OPT_SUBCOMMAND()` conversion, with no intended behavior change beyond the possible tightening of argument validation -- the "too many arguments" check may reject command lines that previously passed extra arguments to "status" silently. As part of the broader series, this continues the incremental extraction of each subcommand into its own `cmd_rerere_*()` function ahead of the final switch to the parse-options subcommand mechanism.
