This is a maintainer-response reply within Patrick Steinhardt's four-patch performance series on auto-maintenance reflog expiration. Specifically, it answers Junio C Hamano's question on patch 1/4 about whether skipping the disk write during `git reflog expire --dry-run` is a correctness fix or merely a performance improvement.

Patrick confirms that the pre-patch code was already semantically correct: during a dry run the reftable backend did write a new table to disk, but it immediately called `reftable_addition_destroy()`, which in turn invokes `reftable_addition_close()` to unlink the table. Thus `--dry-run` never left observable on-disk changes, and the patch in `refs/reftable-backend.c` is purely an optimization that eliminates wasted I/O rather than fixing a bug. He says he will adapt the commit message to state this explicitly.

The clarification closes the main open question on patch 1/4, giving reviewers confidence that the change is low-risk.
