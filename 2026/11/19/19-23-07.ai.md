This is a bugfix targeting the config subsystem, specifically the section-removal and section-rename logic in `config.c`.

The patch fixes `repo_config_copy_or_rename_section_in_file()`, which scans config files line-by-line to copy or remove a section. The bug: when a value in the target section uses backslash line continuation and a continuation line happens to begin with `[something]`, the function mistakenly treats that `[something]` as a new section header. This causes `--remove-section` or `--rename-section` to stop early and leave fragments of the continued value behind as a spurious new section.

The fix introduces two helpers: `skip_section_header()` to parse past a valid section header (including quoted subsections), and `update_line_continuation()` which tracks two pieces of state across lines -- whether the current line is a continuation of a previous backslash-terminated value (`continued`) and whether the parser is currently inside a double-quoted string (`in_quote`). The main loop now calls `update_line_continuation()` before checking for `[`, and only treats the line as a section header if it is not a continuation of a previous value. Quote state is tracked so that `#` or `;` inside quotes on continued lines are not misinterpreted as comments.

Tests are added to `t/t1300-config.sh` covering removal and rename of a section whose value continues across lines containing a bracketed string, a quoted hash, and a subsection whose name contains brackets and escaped quotes. The patch is well-scoped, includes a clear reproduction scenario in the commit message, and appears solid.
