This is a bugfix for `git archive` that closes a window where the `--remote` and `--add-file` incompatibility check happened too late. Currently, when `git-upload-archive` parses client arguments, the `--add-file` callback runs `stat()` on the server filesystem before the post-parse validation rejects the combination, producing misleading "File not found" errors or even succeeding if `--no-add-file` appears later in the arguments.

Dominik Maier moves the check into `add_file_cb()` itself by passing the `is_remote` flag through a new `struct add_file_data`, so both `--add-file` and `--add-virtual-file` die immediately with a clear "cannot be used together" message before any filesystem access. The old post-`parse_options()` check in `parse_archive_args()` is removed.

The patch touches `archive.c` and adds a test in `t/t5000-tar-tree.sh` verifying that a nonexistent file triggers the incompatibility error rather than a stat failure, and that the `--no-add-file` workaround no longer masks the error. The commit message clearly explains the ordering bug and the fix is minimal and well-scoped, making this look like a straightforward, well-crafted correction worth a quick look.
