This is a review confirmation email within Harald Nordgren's v14 five-patch series introducing `remote.<name>.fetchRefmap`, specifically resolving the override-semantics disagreement on Patch 1/5. Phillip Wood confirms agreement with Junio C Hamano's reversed position: any refspec carrying an explicit destination (`src:dst`) -- whether passed on the command line or found in configuration -- ignores the refmap (and by extension `remote.<name>.fetchRefmap`) entirely, while destination-less refspecs remain subject to the refmap.

The email corrects a slip in which Phillip previously referred to ignoring `.fetch` instead of `.fetchRefmap`, confirming that `--refmap` on the command line overrides the `.fetchRefmap` configuration just as command-line refspecs override `.fetch` defaults. Both participants now endorse this implicit-override model because it maintains a clean one-to-one relationship between configuration (setting defaults) and command-line options (overriding them), avoiding special semantics for `--refmap=""`.

Phillip provides two concrete examples that should behave identically: `git config remote.cabal.fetch master` combined with `git fetch --refmap=refs/heads/*:refs/test/* cabal`, versus `git config remote.cabal.fetch master` plus `git config remote.cabal.fetchRefmap refs/heads/*:refs/test/*` followed by `git fetch`. In both cases, `master` should be fetched and stored under `refs/test/master`, demonstrating that command-line `--refmap` and config `fetchRefmap` are functionally equivalent when overriding destination-less refspecs.

Implementation-wise, Phillip suggests a preliminary patch to make command-line refspecs with destinations ignore `--refmap`, alongside tweaking Patch 1/5 so that `remote.<name>.fetchRefmap` applies only to refspec entries lacking their own destination. This closes the dual-storage concern and finalizes the precedence logic affecting `remote.c` and `builtin/fetch.c` involving `remote->fetchRefmap`.

With this exchange, the override-semantics question is fully resolved and endorsed by both the maintainer and the primary reviewer.
