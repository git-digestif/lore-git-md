This is a cover letter for the second iteration (v2) of a six-patch series by Justin Tobler that moves ODB transaction temporary directory creation from lazy to eager, part of the ongoing ODB abstraction effort. The series targets the "files" backend transaction machinery so that the temporary object directory is created at transaction start rather than on first write, ensuring all transactional writes (not just those using batched fsync) go through the temporary directory. The patches touch `object-file.c`, `tmp-objdir.c`, `odb/source-loose.c`, `odb/transaction.h`, and `t/t0004-unwritable.sh`, among others, with a net reduction of 37 lines (63 insertions, 100 deletions).

The v2 respin incorporates feedback from the v1 review cycle: it moves the `flush_batched_fsync()` comment above the function and documents that batched fsync applies only to loose objects (not packfiles); adds a new patch inlining `setup_tmp_objdir()` into `tmp_objdir_create()` with a single `goto error` exit path that preserves `errno`; adds a patch replacing "ODB" with "object" in user-facing error messages; and clarifies the final patch's commit message regarding the per-object overhead of eager creation, arguing it is minor compared to the cost of writing the object and typically affects only small numbers of loose objects unless below the unpack limit.

The final patch (6/6) implements the core change by creating the temporary directory eagerly in the transaction prepare path and removing the lazy creation logic from `object-file.c` and `odb/source-loose.c`. Patch 1/6 renames the default temporary directory prefix from `"bulk-fsync"` to `"transaction"`. Test expectations in `t/t0004-unwritable.sh` are updated to reflect new error messages such as `fatal: failed to start object transaction` and `error: unable to create temporary object directory`.

Review status remains open with no `Reviewed-by` or `Acked-by` trailers yet. While Justin Tobler has addressed specific technical concerns from Patrick Steinhardt and Karthik Nayak regarding batched fsync scope, errno handling, and error message wording, Karthik Nayak's fundamental design-level question about whether eager creation is architecturally justified over the previous lazy approach remains unanswered. The series is based on commit `3c60ef1e38` with `jt/tmp-objdir-loose-idx-merge` merged in, and aims to ensure consistent object visibility semantics at transaction commit regardless of the configured `core.fsyncMethod`.
