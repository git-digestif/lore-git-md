This is a review reply proposing an API design alternative within Dirk Gouders's v2 bugfix series for UTF-8 display-width bounds handling in `utf8.c`. Specifically, it responds to Andy Koppe's objection that the NUL-terminated wrapper `display_mode_esc_sequence_len(const char *s)` -- which calls `display_mode_esc_sequence_len_counted(s, strlen(s))` -- introduces a quadratic performance regression when scanning long strings for SGR escape sequences. Dirk Gouders suggests a third design option beyond keeping the wrapper or deleting it outright: give `display_mode_esc_sequence_len()` an optional `size_t *remainder` parameter modeled on `utf8_width()`. Passing NULL would preserve the current NUL-terminated behavior, while a non-NULL pointer would supply and update the remaining length, allowing bounded scanning without an upfront `strlen()`. The thread summary indicates the series has since settled on removing the wrapper entirely and reverting to Junio C Hamano's v1 approach (counted variant only), so this remainder-based compromise appears not to have been adopted, but it documents the design space considered for the `display_mode_esc_sequence_len()` / `display_mode_esc_sequence_len_counted()` API in `utf8.c` and `utf8.h`.
