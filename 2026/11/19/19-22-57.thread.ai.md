Thread identity: single-patch bugfix series (v1, no version marker) from Dominik Maier <dmnk@google.com>, subject concerning stale server capabilities in the protocol v2 handshake path. Thread type: patch under review on the Git mailing list.

Core problem or goal: the file-static `server_capabilities_v2` strvec in `connect.c` is never cleared between handshakes, so capability lines from an earlier remote persist in-process and are returned by `server_feature_v2()` and `server_supports_feature()` (both return the first matching entry) for subsequent connections to different remotes. Concrete failure modes: `git remote show r1 r2` with r1 on SHA-256 and r2 on SHA-1 aborts the second handshake with "mismatched object format" due to r1's stale `object-format=sha256` line; a stale `session-id` capability from r1 is logged for r2 even when r2 sets `transfer.advertiseSID=false`; the bug also affects v0/v1 handshakes that skip `process_capabilities_v2()` because callers like `get_bundle_uri()` may still query `server_supports_v2("bundle-uri")` afterwards.

Current status: under review on the mailing list; no maintainer decision recorded, not queued in any integration branch.

Key technical details: fix adds `strvec_clear(&server_capabilities_v2)` at the top of both `discover_version()` and `process_capabilities_v2()` in `connect.c`, so every new handshake starts from an empty vector. Regression test added in `t/t5702-protocol-v2.sh`: creates two remotes with differing object formats and SID settings, runs `git remote show r1 r2`, and inspects trace2 output to confirm the `server-sid` event appears only for the remote that advertised it. Affected surface: connection-handling code shared by fetch, push, and remote-inspection commands.

Open questions and loose ends: none raised yet; awaiting review feedback from other contributors.

Participant positions: Dominik Maier is the sole participant so far; no Reviewed-by, Acked-by, or objections recorded.

Related work: protocol v2 capability negotiation in `connect.c`, trace2 `server-sid` event logging, `transfer.advertiseSID` configuration, and the `bundle-uri` capability queried by `get_bundle_uri()`.
