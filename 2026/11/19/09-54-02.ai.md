This is a feature request proposing branch-aware `.gitignore` rules, sent as a standalone email rather than a patch.

Jordan Kadish describes a workplace scenario where a `settings.py` file is passed around manually because it intentionally differs from the version in the `main` branch, and asks Git to support ignoring files conditionally based on the current branch name. The proposal envisions two modes: a whitelist approach where a file is ignored in every branch except a named one, and a blacklist approach where the file is ignored only in a specifically named branch. The stated motivation covers common cases like Django migration files, local settings, and compiled binaries that must exist on main or staging branches but should stay out of local working trees.

The email does not include any implementation sketch, syntax proposal, or patch; it is purely a conceptual request for discussion. No prior art or related Git mechanisms (such as `.gitattributes` filters or hooks) are mentioned, leaving open how this would interact with existing ignore infrastructure. Likely points of contention for follow-up discussion include the performance cost of evaluating branch names during ignore-pattern matching, the parsing complexity of extending `.gitignore` syntax, and whether branch-conditional behavior belongs in core ignore handling or in an external mechanism.
