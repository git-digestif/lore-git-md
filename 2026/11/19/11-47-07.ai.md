This is a preparatory refactoring patch -- specifically patch 6 of 13 in Patrick Steinhardt's v5 series to modernize `git rerere`'s subcommand handling. The series replaces the command's custom string-comparison dispatch with the standard `OPT_SUBCOMMAND()` mechanism from the parse-options subsystem, and this particular commit extracts the "clear" subcommand into its own dedicated handler as an intermediate step.

The patch adds a new static function `cmd_rerere_clear()` in `builtin/rerere.c` that accepts the standard `(argc, argv, prefix, repo)` arguments, runs `parse_options()` with an empty options array and the existing `rerere_usage` string, rejects any extra arguments with `usage(_("too many arguments"))`, and then delegates to `rerere_clear(repo, &merge_rr)` followed by `string_list_clear(&merge_rr, 1)`. The main `cmd_rerere()` dispatch is updated to call this new function when `argv[0]` equals "clear", replacing the previous inline `if (!strcmp(argv[0], "clear"))` block. This mirrors the pattern established in the preceding patch 5, which performed the same extraction for the "forget" subcommand.

There is no behavior change -- the patch is purely structural, moving code into a standalone function and introducing a `parse_options()` call as scaffolding for the eventual `OPT_SUBCOMMAND()` conversion. The commit is well-motivated and consistent with the series' incremental approach; it touches only `builtin/rerere.c` and maintains the existing error-handling semantics. Future discussion in this thread is likely to reference whether the "too many arguments" check correctly preserves the old behavior of silently ignoring extra arguments to `clear`, or whether this tightening is intended.
