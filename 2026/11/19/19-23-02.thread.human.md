Dominik Maier has sent a bugfix for the attribute subsystem that closes a symlink-traversal gap left over from a 2021 fix. Commit 2ef579e261 taught Git to open in-tree `.gitattributes` files without following symlinks via `open_nofollow()`, but that only protects the final path component: when a user passes an explicit path like `symdir/file` to `git check-attr` and `symdir` is itself a directory symlink, Git still traversed the link to read `symdir/.gitattributes` (and `lstat()`'d across it in the object-mode path), allowing attribute lookups to escape the repository worktree.

The patch adds `has_symlink_leading_path()` guards in `attr.c` -- in `read_attr_from_file()` under the `READ_ATTR_NOFOLLOW` flag and at the top of `builtin_object_mode_attr()` for the check-in direction -- so that no leading path component may be a symlink, aligning worktree lookups with index lookups. Tests in `t/t0003-attributes.sh` verify that both `attr_check_basic` and `attr_check_object_mode` on `symdir/file` now return `unspecified` instead of reading through the link. The change is narrow and self-contained, hardening existing no-follow behavior rather than introducing new policy, and the thread is at its opening email with no review discussion or open questions yet.
