This is a cover letter for v3 of a five-patch bugfix series addressing loose object size validation and `long`-versus-`size_t` truncation bugs, primarily on LLP64 platforms such as 64-bit Windows. The series reworks v2 in response to maintainer and reviewer feedback: patch 1/5 now emits a specific size-mismatch error ("loose object '<oid>' has N bytes, but its header says M") and writes the check as `total_out != hdrlen + size`; patch 3/5 removes its direct `error()` call from `read_istream_loose()` in `odb/source-loose.c`, instead returning -1 silently with `z_state` set to `ODB_LOOSE_READ_STREAM_ERROR` so the caller reports the failure, which also eliminates the `oid` struct member added in v2; patch 2/5's commit message now explains why `st_add()` is unnecessary (the size is parsed with `st_mult()`/`st_add()` and allocated before further arithmetic); and patch 4/5 has a trimmed commit message. The `memchr()`-versus-`strlen()` suggestion for `unpack_loose_rest()` is deferred to a separate patch.

The five patches remain: 1/5 adds post-inflation size validation in `unpack_loose_rest()` (`object-file.c`) to catch streams shorter or longer than their header claims, preventing uninitialized memory exposure or silent truncation on all platforms, with tests in `t/t1060-object-corruption.sh`; 2/5 widens loose object size variables from `unsigned long` to `size_t` across `object-file.c`, `object-file.h`, and `odb/source-loose.c` (`map_fd()`, `unpack_loose_header()`, `unpack_loose_rest()`, `check_stream_oid()`, `odb_source_loose_map_object()`) to fix buffer overreads on Windows when headers claim sizes above 4 GiB; 3/5 adds the equivalent check to the streaming reader `read_istream_loose()` with tests in `t/t1006-cat-file.sh`; 4/5 changes `batch_write()` in `builtin/cat-file.c` to take `size_t` instead of `int` to fix a cross-platform buffer overread in `git cat-file --batch` for objects between 2 GiB and 4 GiB; and 5/5 fixes a heap overflow in `combine_notes_concatenate()` (`notes.c`) on 64-bit Windows by using `size_t` with `st_add3()` and passing the result through `cast_size_t_to_ulong()` only at the `odb_write_object()` call.

Only patches 1/5 and 3/5 have automated tests because the others require multi-gigabyte objects or a 32-bit `long` platform; their commit messages document manual reproduction steps. The series is based on `master` at e1ec09b23c and touches `builtin/cat-file.c`, `notes.c`, `object-file.c`, `object-file.h`, `odb/source-loose.c`, plus `t/lib-loose.sh`, `t/t1006-cat-file.sh`, and `t/t1060-object-corruption.sh`. The issues were reviewed on the git-security list and deemed non-security-sensitive.
