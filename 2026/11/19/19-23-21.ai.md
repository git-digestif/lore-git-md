This is a security bugfix for the `git-cvsexportcommit.perl` contrib script, addressing a command injection vulnerability in its `-W` (working-tree) mode.

When `-W` is enabled, the script captures the current HEAD reference into the Perl variable `$go_back_to` using backticks (`git symbolic-ref HEAD`), then later restores it with single-argument `system("git checkout $go_back_to")` and `system("git symbolic-ref HEAD $go_back_to")`. Because Perl's single-argument `system()` spawns `/bin/sh -c`, any shell metacharacters in the branch name -- such as the semicolon in `refs/heads/topic;false` -- are interpreted by the shell, allowing unintended command execution or incorrect HEAD restoration.

The patch converts all affected `system()` calls to the list form `system('git', 'checkout', ...)`, which execs git directly without shell interpretation. It adds `chomp $go_back_to` to strip the trailing newline from the backtick capture, and hardens the final checkout with `--end-of-options` and `--` to prevent option injection if a branch name begins with a dash. The same list-form conversion is applied to the intermediate `git checkout -q "$parent^0"` and `git checkout -q "$commit^0"` calls, as well as the `git symbolic-ref` restoration.

A regression test in `t/t9200-git-cvsexportcommit.sh` creates a branch literally named `topic;false`, runs `git cvsexportcommit -W -p -u -c HEAD`, and asserts that `git symbolic-ref HEAD` afterwards still equals `refs/heads/topic;false`, confirming the metacharacter is handled safely.

The patch is concise, well-motivated, and includes direct test coverage for the exploit scenario. It modifies only `git-cvsexportcommit.perl` and `t/t9200-git-cvsexportcommit.sh`.
