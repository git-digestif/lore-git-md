This is a refactoring patch, specifically the second of thirteen in Patrick Steinhardt's v5 series modernizing `git rerere`'s subcommand handling. It converts the rerere subsystem's flag constants from `#define` macros into a proper `enum rerere_flags` with explicit bit-shift values, and updates the signatures of `rerere_cache_setup()`, `rerere()`, and `rerere_gc()` in `rerere.c` and `rerere.h` to take the enum type instead of a bare `int`. This aligns the code with modern Git coding guidelines that favor enums for flag parameters, making it easier to see at a glance what flags a function expects.

Beyond the mechanical type change, the patch adds a defensive `BUG()` check in `rerere_cache_setup()` that fires if a caller passes both `RERERE_AUTOUPDATE` and `RERERE_NOAUTOUPDATE` simultaneously. The commit message notes that this combination is nonsensical--`RERERE_AUTOUPDATE` would take precedence, but the intent is ambiguous--and while all current callers already avoid it, the explicit check prevents future misuse rather than silently picking one behavior.

The patch touches only `rerere.c` and `rerere.h` and introduces no user-visible behavior change; it is purely internal cleanup that prepares the ground for the larger subcommand-parsing overhaul in the rest of the series. It looks well-crafted and consistent with the surrounding effort, carrying a clear commit message and a Signed-off-by trailer.
