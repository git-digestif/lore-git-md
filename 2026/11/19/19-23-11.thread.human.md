Dominik Maier has posted v2 of a two-patch series fixing two related bugs in `git archive`. The first patch corrects an out-of-bounds pointer advance in `write_zip_entry()` (`archive-zip.c`) that occurred when `--prefix` was longer than the path of a file added via `--add-file` or `--add-virtual-file`; the fix threads the per-entry prefix (or NULL for virtual files) through `args->base`/`args->baselen` so the pointer arithmetic and the `entry_is_binary()` gitattributes lookup are guarded. The second patch, following a suggestion from René Scharfe, defers filesystem validation of `--add-file` until after option parsing: the option callback now only records the path, and `parse_archive_args()` performs the `stat()` and regular-file check afterward, dying with the proper "--add-file and --remote cannot be used together" message when `--remote` is set. This preserves `--no-add-file` cancellation even under `--remote` and allows `--remote --add-virtual-file` to work, since virtual files need no server-side filesystem access. Tests in `t/t5000-tar-tree.sh` and `t/t5003-archive-zip.sh` cover all three scenarios.

René Scharfe reviewed v1 and proposed the deferred-stat design that v2 adopts; no Reviewed-by, Acked-by, or outstanding objection is recorded. The series remains under review as v2, with no merge or integration status stated.
