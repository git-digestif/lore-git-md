This thread is a single standalone bugfix from Dominik Maier addressing argument validation ordering in `git archive --remote`. Previously, the `--add-file` and `--add-virtual-file` options were processed -- including filesystem `stat()` calls -- before the check rejecting them in combination with `--remote`, which let confusing "File not found" errors surface ahead of the real incompatibility error, and allowed `--no-add-file` to suppress the check entirely.

The fix restructures `archive.c` so that a new `struct add_file_data` (bundling the archiver args, base pointer, and remote flag) is passed to the option callback, letting `add_file_cb()` reject the incompatible options immediately during parsing, before any filesystem access. The redundant late check in `parse_archive_args()` is removed. A new test in `t/t5000-tar-tree.sh` confirms both that `--remote=. --add-file=no-such-file` fails with the incompatibility message and that `--no-add-file` can no longer bypass it.

Nothing is open or contested; the patch is a small, self-contained change to the archive subsystem and its tar test script, and the thread consists of just this one email.
