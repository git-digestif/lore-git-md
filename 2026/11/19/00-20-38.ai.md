This is a refactoring patch, specifically the first of six in Justin Tobler's v2 series that shifts ODB transaction temporary-directory creation from lazy to eager as part of the ongoing ODB abstraction effort.

The patch makes a one-line change in `object-file.c` within `odb_transaction_files_begin()`, renaming the default `transaction->prefix` string from `"bulk-fsync"` to `"transaction"`. The old name dates to commit `c0f4752ed2` (core.fsyncmethod: batched disk flushes for loose-objects, 2022-04-04), when the temporary object directory existed solely to batch fsyncs of loose objects. As the commit message notes, ODB transactions have since become a more general object-writing interface, and the upcoming final patch in this series (6/6) will create the temporary directory eagerly for every transaction regardless of the configured `core.fsyncMethod`, making the "bulk-fsync" label misleading.

No behavior changes yet; this is purely preparatory renaming ahead of the eager-creation logic introduced later in the series. The change touches only `object-file.c` (one insertion, one deletion) and is based on commit `3c60ef1e38` with `jt/tmp-objdir-loose-idx-merge` merged in. The series remains under review with no `Reviewed-by` or `Acked-by` trailers recorded.
