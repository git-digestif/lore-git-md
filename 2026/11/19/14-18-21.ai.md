This is the second patch in Adrian Ratiu's three-patch v2 bugfix series for the `compatObjectFormat` interoperability layer. It fixes `git rev-parse --output-object-format` silently printing the storage OID instead of the compat OID when an object has no compat mapping, which happens for objects received via fetch through index-pack. The fix checks the return value of `repo_oid_to_algop()` in `builtin/rev-parse.c` and dies with "cannot map object %s to %s" on failure, matching the behavior of `git pack-objects` and other callers. The commit message notes that this only addresses the single-revision case where the desired output hash is passed explicitly; range arguments like `A..B` do not use the output hash and remain a future, larger change.

The test in `t/t1500-rev-parse.sh` creates a SHA-256 repo, writes an object before enabling `extensions.compatObjectFormat` (so it gets no compat mapping), then enables the config and verifies that asking for the SHA-1 compat ID fails with the expected error while asking for SHA-256 succeeds. This approach avoids manually copying object directories, which would be fragile under the upcoming ODB abstraction. The patch touches only `builtin/rev-parse.c` and the test file.
