This is patch 4/4 of a v3 bugfix series fixing silent integer truncation in large-file handling, specifically targeting diffstat output and graph scaling in `diff.c`. The patch widens accumulation variables in `show_stats()` and `show_shortstats()` from `int` to `uintmax_t`, and changes `print_stat_summary()` and `print_stat_summary_inserts_deletes()` to accept and format `uintmax_t` insertions/deletions using `PRIuMAX`, fixing the summary line overflow when a single file contributes more than `INT_MAX` lines (e.g., a 2 GiB complete rewrite). `scale_linear()` now takes `uintmax_t` parameters so the computation `it * (width - 1)` does not overflow for large change counts on LLP64 platforms, and the `graph_width` assignment in `show_stats()` now caps `max_change` at `width` when it would exceed available space rather than storing a potentially truncated value. A new test in `t/t4052-stat-output.sh` covers the `scale_linear()` overflow case using a 50,000-line file with `--stat=46100 --stat-graph-width=46000`; the totals themselves remain untested as they require multi-gigabyte inputs. The commit message addresses two prior review concerns from Junio C Hamano: it explains why a `uintmax_t` accumulator cannot overflow in practice (each line requires at least one byte of input), and documents the `graph_width` capping behavior. The patch carries a `Tested-by` trailer from Torsten Bögershausen and touches `diff.c`, `diff.h`, and `t/t4052-stat-output.sh`.
