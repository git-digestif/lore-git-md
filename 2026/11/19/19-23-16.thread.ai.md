Thread identity: security bugfix patch (thread root) from Dominik Maier <dmnk@google.com> fixing a path-traversal vulnerability in `git filter-branch --state-branch` handling. Single-patch thread, under review; not queued in any integration branch.

Core problem or goal: when `git filter-branch` resumes from a state branch and loads the `filter.map` blob, map entries were written to `../map/$from_commit` without validating commit identifiers, so a malicious or corrupted state branch could escape the temporary map directory via keys containing slashes, backslashes, or `..` segments. Junio C Hamano additionally confirmed that an empty key (e.g. `:foo`) causes redirection to `../map/` to fail with an "Is a directory" error inside the loop without invoking `die()`, while keys containing `../` can escape `$tempdir/map` into the surrounding working tree.

Key technical details: modifies `git-filter-branch.sh` to read lines with `IFS= read -r` and validate both sides of each `from:to` mapping before writing. `from_commit` must be non-empty lowercase hexadecimal; `to_commit` may contain only lowercase hex digits and spaces (empty permitted, representing pruned commits). Violations cause the command to die with "Unable to load state from $state_branch:filter.map". Tests added in `t/t7003-filter-branch.sh` covering rejection of entries like `../../escaped:injected` and backslash-containing keys, verifying both command failure and that no file escapes the map directory. Commit message references prior commit 4811dabed7 ("filter-branch: fix commit map init from state branch", 2026-10-02), which restored the `from:to` ordering and introduced the parsing logic now being hardened.

Current status: patch posted and under review; Junio C Hamano has reviewed and approved the approach ("Looks good. Thanks."); no integration branch assignment stated.

Open questions and loose ends: Junio suggested the commit message briefly explain why spaces are allowed in `$to_commit` -- the `map()` function output is designed to be used unquoted in constructs like `for reparent in $(map "$parent")` to expand a single `from` commit into multiple `to` commits separated by spaces. This documentation tweak is the only outstanding item.
