This is a refactoring patch, specifically patch 9/13 in Patrick Steinhardt's v5 series to modernize `git rerere` subcommand handling. The series aims to replace custom subcommand parsing with the standard `OPT_SUBCOMMAND()` mechanism; this particular patch continues the incremental extraction of individual subcommand handlers into dedicated functions.

The patch moves the "diff" subcommand logic out of the monolithic `cmd_rerere()` dispatch into a new static function `cmd_rerere_diff(int argc, const char **argv, const char *prefix, struct repository *repo)` in `builtin/rerere.c`. The new handler follows the exact pattern established by patches 5 through 8 for "forget", "clear", "status", and "remaining": it calls `parse_options()` with an empty options array and the shared `rerere_usage` string, rejects any extra arguments via `usage(_("too many arguments"))`, sets up the rerere cache with `RERERE_READONLY` only (consistent with patch 4's cleanup of read-only subcommands), iterates the merge_rr list calling `diff_two()` on each preimage, and cleans up resources. The main `cmd_rerere()` now dispatches to this function when `argv[0]` equals "diff".

No behavior change is intended for `git rerere diff` output, though like patches 6-8, the new "too many arguments" check tightens validation of extra arguments that were previously silently ignored. The patch touches only `builtin/rerere.c` and serves as preparatory restructuring toward the eventual switch to `OPT_SUBCOMMAND()` in a later patch.
