Thread identity: single-patch bugfix series (v1, no cover letter) from Dominik Maier <dmnk@google.com> targeting the attribute subsystem (`attr.c`), subject concerning symlink traversal in `git check-attr` / object-mode attribute lookups.

Core problem: commit 2ef579e261 (2021-02-16, "attr: do not respect symlinks for in-tree .gitattributes") taught `read_attr_from_file()` in `attr.c` to open `.gitattributes` with `open_nofollow()`, but `open_nofollow()` only guards the final path component. When a user passes an explicit path whose leading directory is a symlink (e.g. `symdir/file` where `symdir` is a symlink to a directory outside the worktree), `prepare_attr_stack()` still traversed the leading symlink to read `symdir/.gitattributes`, and `builtin_object_mode_attr()` called `lstat()` across the link, letting attribute lookups escape the repository worktree.

Current status: patch posted, under review; no maintainer decision, Reviewed-by, Acked-by, or integration-branch placement recorded. Not in `next`, `seen`, or `master`.

Key technical details: fix confined to `attr.c` plus test script `t/t0003-attributes.sh`. Two insertions: (1) in `read_attr_from_file()`, when the `READ_ATTR_NOFOLLOW` flag is set, return NULL if `has_symlink_leading_path()` detects a symlinked leading component; (2) at the top of `builtin_object_mode_attr()` for the `GIT_ATTR_CHECKIN` direction, return `ATTR__UNSET` under the same condition. New `SYMLINKS`-guarded test in `t/t0003-attributes.sh` creates an external directory containing a `.gitattributes`, symlinks it as `symdir`, and asserts both `attr_check_basic symdir/file` and `attr_check_object_mode symdir/file` return `unspecified`. Goal is parity between worktree and index attribute lookups: no part of an explicit path may traverse a symlink outside the repository.

Open questions and loose ends: none raised in this email; the change is described as narrow, self-contained hardening of existing no-follow behavior with no stated controversy.

Participant positions: only the author (Dominik Maier) so far; no reviews recorded. Correctness of the fix has not been independently verified.

Related work: builds directly on commit 2ef579e261 (2021-02-16) which introduced `open_nofollow()` for in-tree `.gitattributes`; relevant to any future work on path-safety of attribute lookups and symlink handling in the worktree.
