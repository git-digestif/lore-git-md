This is a substantive review by Junio C Hamano of brian m. carlstadt's v3 bugfix patch ensuring `git init` defaults to SHA-256 when built with `WITH_BREAKING_CHANGES=1`. The patch restructures `repository_format_configure()` in `setup.c` to give an explicit command-line `--object-format` precedence, while consulting the environment, config, and the build-time default only for brand-new repositories. Junio engages with both the commit message and the removed code comment, questioning whether the old comment is truly "now inaccurate" or merely partially so.

He argues that while the final sentence of the deleted comment is misleading -- because user intent can be expressed via environment variables or config, not just the command line -- the first two lines still serve as a valuable caution to future maintainers about the corruption risk of changing hash algorithms on existing repositories. The review culminates in a specific edge-case question: whether a global `init.defaultObjectFormat` setting in `~/.gitconfig` counts as "the user has specified" an algorithm, which would affect how the new precedence logic handles reinitialization when no command-line flag is given. This is a substantive review that probes the semantic boundaries of the fix rather than offering surface-level feedback.
