This is a substantive review from the maintainer concerning the naming and scope of a feature patch. Junio C Hamano is responding to the v5 series that adds a `--concern` option to `git repo structure`, and he raises a design objection: the name "structure" is misleading for what the command actually reports.

He argues that "structure" suggests information about how a repository is organized -- the depth and width of trees, the number and integration patterns of branches, how branch names are organized -- whereas the current command only provides counts and sizes of objects. He expects a command called "structure" to allow comparing those organizational characteristics across different repositories and projects.

Junio notes, however, that `git repo` is still marked experimental, so there is room to correct this. He suggests that once individual subfeatures prove useful, they could be given more appropriate names and user interfaces and eventually migrate out from under the experimental `git repo` umbrella. This is a significant naming concern from the maintainer but framed as a correctable issue given the experimental status of the command.
