This is a **substantive review** of the third iteration of a bugfix patch series that corrects how `git init` selects the default object hash algorithm when Git is built with `WITH_BREAKING_CHANGES=1`. Junio C Hamano is examining the test additions in `t/t0001-init.sh` from brian m. carlstadt's `[PATCH v3]` and raising a specific concern about test isolation.

The email walks through three new test cases added by the patch. The first verifies that `git init` uses `$GIT_TEST_BUILTIN_HASH` as the default object format when `GIT_DEFAULT_HASH` is unset. The second confirms that attempting to reinitialize an existing repository with a conflicting `--object-format` fails with "fatal: attempt to reinitialize repository with different hash". The third ensures that reinitializing a repository does not change its hash algorithm even when `init.defaultObjectFormat` specifies a different value. Junio approves of these test scenarios individually, noting they correctly exercise the restructured `repository_format_configure()` logic in `setup.c`.

The key point of contention is Junio's question about whether calling `sane_unset GIT_DEFAULT_HASH` in the second and third tests without saving and restoring the previous value could pollute the environment for subsequent tests. He specifically asks whether later tests -- such as the existing "extensions.objectFormat is not allowed with repo version 0" test that follows -- might break if they implicitly rely on `GIT_DEFAULT_HASH` being set by `t/test-lib.sh`. This identifies a potential test-ordering dependency that could cause flaky failures depending on which hash algorithm the binary was built with.

Contextually, this review is part of the broader effort to ensure `git init` defaults to SHA-256 (via `GIT_HASH_DEFAULT`) under Git v3 breaking-changes builds while preventing silent reinitialization of existing repositories with incompatible hash algorithms. The patch touches `setup.c` and `t/t0001-init.sh`, and addresses the original report that `git init` incorrectly defaulted to SHA-1 even in breaking-changes builds.
