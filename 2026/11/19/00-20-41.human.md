This is a refactoring patch -- specifically preparatory cleanup -- in the fourth position of Justin Tobler's six-patch v2 series that moves ODB transaction temporary-directory creation from lazy to eager, part of the broader ODB abstraction effort.

The patch modifies `tmp_objdir_create()` in `tmp-objdir.c` so that it preserves `errno` when directory creation fails. Currently, if `mkdtemp()` or the subsequent `mkdir()` of the `pack` subdirectory fails, the cleanup paths (`tmp_objdir_free()` or `tmp_objdir_destroy()`) can clobber `errno` before the function returns NULL, leaving callers unable to determine the actual failure reason. The fix saves `errno` into a local variable at each failure point and restores it via a single `error` exit path before returning NULL, and updates the header comment in `tmp-objdir.h` to document that the function now sets `errno` on failure.

This change is explicitly preparatory: a later patch in the same series (6/6) will create the temporary object directory eagerly at transaction start and will need to report specific error messages based on why creation failed. By ensuring `errno` survives the cleanup now, the author avoids having to handle errno preservation in multiple places later.

The patch is small, well-motivated, and directly implements the single-exit-path restructuring that Karthik Nayak had suggested during the v1 review cycle. It touches only `tmp-objdir.c` and `tmp-objdir.h` with no behavior change visible to end users yet, but it lays the groundwork for more informative error reporting when the eager-creation behavior lands.
