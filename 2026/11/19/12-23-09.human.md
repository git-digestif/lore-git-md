This is a brief reply in the review thread for Ravi Mistry's five-patch HTTP retry series, specifically addressing the documentation for patch 3/5, which adds the `http.retryStatusCodes` config option. Patrick Steinhardt had proposed that the documentation explicitly frame non-429 retry codes as a workaround for buggy providers rather than a standard feature, to encourage the ecosystem to converge on returning 429 when overloaded. Ravi Mistry agrees to this framing and commits to updating the `http.retryStatusCodes` docs in v4 to state that providers are expected to return 429 when overloaded and that configuring other codes should be viewed as a temporary fix while infrastructure is repaired.

The exchange partially resolves the architectural debate over whether Git should make arbitrary retry codes configurable at all. While the opt-in configuration mechanism itself remains unchanged, adopting Patrick's documentation language nudges the feature toward being positioned as an escape hatch for non-standard providers rather than a general-purpose setting. The technical implementation of patch 3/5 -- introducing `http.retryStatusCodes` with a default of "429" -- is not altered by this reply. The series remains under review awaiting a v4 that incorporates this and other committed fixes.
