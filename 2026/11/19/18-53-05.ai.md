This is a substantive review reply from Junio C Hamano on Kaartic Sivaraam's standalone bugfix for `git fast-import` error-message disclosure. While endorsing the original one-line fix as "obviously correct," Junio suggests a structural improvement to `parse_one_feature()` in `builtin/fast-import.c` to prevent similar bugs from recurring: replacing the current pattern of calling `skip_prefix()` followed by a separate `check_unsafe_feature()` with a new helper `check_unsafe()` that combines both operations. The proposed helper takes the full `feature` string, a `prefix` to match, and an output `arg` pointer; it uses `skip_prefix()` to verify the prefix and requires an `=` immediately after it, dies with only the bare feature name (not the full string with path) when the feature is unsafe and `--allow-unsafe-features` is absent, and otherwise sets `*arg` past the `=` and returns success. This eliminates the forced repetition of the feature name in both the prefix string and the safety-check argument that caused the original leak.

Junio explicitly notes an edge case for the proposed helper: if an argument-less unsafe feature is ever added in the future, the check for `*arg_ == '='` would need to be relaxed to accept NUL (or use a separate signal like `arg == NULL`) so that features without parameters are handled correctly. The included diff shows the refactoring touches only `builtin/fast-import.c`, replacing the existing `check_unsafe_feature()` function and updating the `export-marks` and `import-marks` branches in `parse_one_feature()` to use the new combined helper, reducing the file by a net of three lines while removing the duplication trap.

The email advances the thread from a simple bugfix toward a small refactoring, but does not reject the original approach; it offers an alternative implementation that the author may adopt. No integration status is reported -- the topic remains under review -- and the earlier endorsement from Karthik Nayak stands, though the potential conflict with his in-flight fast-import test refactoring series (`20261112-kn-fast-import-tests-1-v2`) remains an open logistical point for whoever advances the topic next.
