This is a refactoring patch, specifically the eighth of thirteen in Patrick Steinhardt's v5 series that modernizes `git rerere`'s subcommand handling by replacing custom parsing with the standard `OPT_SUBCOMMAND()` mechanism. It continues the incremental extraction pattern established by the preceding patches: just as patches 5, 6, and 7 moved "forget", "clear", and "status" into their own handler functions, this patch extracts the "remaining" subcommand into a new static function `cmd_rerere_remaining()` in `builtin/rerere.c`.

The new `cmd_rerere_remaining()` accepts `(argc, argv, prefix, repo)`, runs `parse_options()` with an empty options array and the existing `rerere_usage` string, and rejects any extra arguments via `usage(_("too many arguments"))` -- the same validation tightening introduced in patches 6 and 7. It then calls `rerere_remaining(repo, &merge_rr)`, iterates over the resulting string list to print each path whose `util` field is not `RERERE_RESOLVED` (nulling out resolved entries to prepare for cleanup), and frees the list with `string_list_clear()`. The main `cmd_rerere()` dispatch now routes `argv[0] == "remaining"` to this function instead of handling the logic inline. The patch touches only `builtin/rerere.c` and is explicitly preparatory, with no intended behavior change to `git rerere remaining` output.
