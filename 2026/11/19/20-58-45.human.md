This is a review reply in an ongoing bugfix series. Andy Koppe responds to Dirk Gouders's proposal to drop the NUL-terminated wrapper `display_mode_esc_sequence_len()` from the `[PATCH v2 0/4]` series on UTF-8 display-width bounds handling. The series, which fixes `utf8_strnwidth()` and `utf8_width()` to respect their length arguments and avoid reading past buffer ends, had included the wrapper as a convenience for existing callers. Andy had objected that the wrapper's `strlen()` call turns repeated scans into quadratic time, and Dirk now agrees to remove it entirely, switching the sole remaining caller in `pretty.c` to the explicit-length `display_mode_esc_sequence_len_counted()` variant instead.

Andy confirms he has no objection to this approach, noting that he would make the same change in his own separate patch introducing `make_line_colors_self_contained()` to avoid the same performance pitfall. This exchange effectively settles the API design question for patch 1: the counted variant becomes the only interface, eliminating the `strlen()` overhead and forcing callers to think about bounded input. The discussion is substantive rather than cosmetic, addressing a concrete algorithmic concern about repeated scanning in string-processing code.

With this agreement, the main outstanding technical objection to the series is resolved. Remaining items are minor: a documentation wording nit about "null-terminated" phrasing, two style nits from Junio C Hamano on patch 3, and a meson build ordering fix for the new unit test files. The series now appears poised for a v3 that incorporates the wrapper removal alongside those cleanups, or for direct integration if the maintainer is satisfied with the current direction.
