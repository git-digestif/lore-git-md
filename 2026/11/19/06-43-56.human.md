This is the fourth and final patch in Elia Pinto's v3 series fixing silent integer truncation in large-file handling, and it targets the diffstat output path in `diff.c`.

The patch fixes three related overflow bugs. First, `show_stats()` and `show_shortstats()` accumulated per-file line counts into `int` variables, so a single file with more than 2^31 lines (achievable via a complete rewrite, per the previous patch in the series) made the summary line print nonsensical values like "-2147483648 insertions(+)"; these accumulators are now `uintmax_t`, matching the per-file fields, and `print_stat_summary()` formats them with `PRIuMAX`. Second, `scale_linear()` computed `it * (width - 1)` in `int`, which overflowed even for modest files when the graph was wide -- a 50,000-line file with `--stat-graph-width=46000` printed no "+" characters at all; it now works in `uintmax_t`. Third, the local `graph_width` was assigned `max_change` without capping, which could itself overflow; it is now capped at `width`.

The commit message addresses two concerns raised in review: it explains why a `uintmax_t` total cannot overflow in practice (each line consumes at least one input byte), and it documents that capping `graph_width` only changes output where `max_change` previously did not fit anyway. A cheap regression test in `t/t4052-stat-output.sh` covers the `scale_linear()` case with a 50,000-line file and a 46,000-wide graph; the totals themselves are not tested because they require multi-gigabyte inputs. Torsten Bögershausen contributed a `Tested-by` trailer. The patch looks well-crafted and ready; with this, all four patches in the series have addressed the substantive review feedback from v2.
