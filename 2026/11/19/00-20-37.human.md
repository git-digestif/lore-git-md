This is a cover letter for the second iteration of a six-patch series (expanded from four) that refactors Git's object database transaction machinery to create the temporary object directory eagerly rather than lazily. Part of the ongoing ODB abstraction effort, the series aims to eliminate special cases where loose object writes had to know about transaction internals to trigger directory creation, and where object visibility at commit time depended on the configured fsync method.

The core behavioral change moves temporary directory creation from the first object write to transaction start, ensuring all transactional writes go through the temporary directory regardless of fsync configuration. The first five patches are preparatory refactors: renaming the default transaction prefix, gating batched-fsync flushes on the appropriate config, inlining `setup_tmp_objdir()` into `tmp_objdir_create()` with a single error exit path, preserving `errno` on failure, and replacing "ODB" with "object" in user-facing error messages. The final patch implements the eager creation itself and removes the lazy setup logic.

Version two directly addresses feedback from the first round of review. Justin Tobler moved the `flush_batched_fsync()` comment above the function and documented that batched fsync applies only to loose objects, added the two new patches requested by reviewers (the `setup_tmp_objdir()` inline and the error-message cleanup), and clarified commit messages regarding the performance characteristics of the change -- noting that the overhead is a small per-object migration cost that should be negligible except when adding many small files at once.

The series is based on `3c60ef1e38` and remains under review. While the author has incorporated the substantive suggestions from Patrick Steinhardt and Karthik Nayak regarding code structure, documentation, and error messaging, no `Reviewed-by` or `Acked-by` trailers have been recorded yet, and Karthik's earlier design-level question about the motivation for eager versus lazy creation appears to remain open.
