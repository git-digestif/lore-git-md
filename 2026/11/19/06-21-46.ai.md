This is patch 1/5 of a five-patch bugfix series (v3) addressing loose object size validation and LLP64 platform truncation issues. The patch fixes `unpack_loose_rest()` in `object-file.c` by adding a post-inflation validation that compares `stream->total_out` against `hdrlen + size`; on mismatch it emits the specific error "loose object '<oid>' has N bytes, but its header says M" and frees the allocated buffer, preventing both uninitialized heap memory exposure when the compressed stream ends early and silent truncation when the stream contains more data than the header claims. The check mirrors validation already present in `unpack_compressed_entry()` for packfiles. The patch extends the `loose_obj()` test helper in `t/lib-loose.sh` to accept an optional third argument that overrides the real content size with a bogus header value, and adds three automated tests to `t/t1060-object-corruption.sh` verifying that `git cat-file` fails with the expected byte-count error for both too-large and too-small header claims and that `git fsck` detects both cases. This patch is cross-platform and fully tested, unlike the LLP64-specific patches later in the series. Junio C Hamano approved the approach in v2 ("Looking good. Thanks."); v3 refines the error message per Patrick Steinhardt's suggestion to include the actual versus expected byte counts and adjusts the check to be written as `total_out != hdrlen + size`. The series is rebased on `master` at e1ec09b23c.
