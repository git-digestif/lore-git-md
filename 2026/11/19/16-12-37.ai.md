This is a maintainer approval of a bugfix for `git ls-tree`. Junio C Hamano reviewed the v2 patch from Noam Cohen and replied that everything looks as expected, calling it "nicely done" and stating he will queue it.

The patch itself corrects the `%(path)` placeholder in `git ls-tree --format` so that when `-z` is passed the path is emitted verbatim and NUL-terminated rather than C-style quoted. The code change is confined to `show_tree_fmt()` in `builtin/ls-tree.c`, where the logic now branches on `options->null_termination`: if true it appends the raw name with `strbuf_addstr()`, otherwise it falls back to the existing `quote_c_style()` call. This aligns `ls-tree` with its own documentation and with the behavior of `git ls-files --format`, which has handled `-z` correctly since commit ce74de931d.

The v2 revision addresses earlier review feedback by reworking the regression test in `t/t3104-ls-tree-format.sh`. Instead of writing a non-ASCII filename to the filesystem, the test synthesizes a tree entry containing a literal double quote using `git mktree`, forces `core.quotePath=true` to ensure the quoting path would otherwise trigger, and verifies that `git ls-tree -z --format="%(objecttype) %(path)"` outputs the raw path followed by a NUL byte. The test remains entirely within US-ASCII and self-contained.
