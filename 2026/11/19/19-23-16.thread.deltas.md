# Thread deltas

## 2026/11/19

- [2026/11/19/19-23-16 by Dominik Maier <dmnk@google.com>] Dominik Maier submitted a patch to git-filter-branch that validates each "from:to" line loaded from a --state-branch filter.map: it requires "$from_commit" to be non-empty lowercase hex and "$to_commit" to contain only lowercase hex digits and spaces (allowing an empty "$to_commit" for pruned commits) before writing "../map/$from_commit", so malformed entries with empty keys, slashes, backslashes, or ".." segments die with "Unable to load state from ...:filter.map" instead of writing outside "$tempdir/map"; the patch also adds t/t7003-filter-branch.sh tests for a "../.."-traversal entry and a backslash entry.

## 2026/11/24

- [2026/11/24/19-19-00 by Junio C Hamano <gitster@pobox.com>] Junio C Hamano confirmed the vulnerability: an empty key such as ":foo" makes redirection to "../map/" fail with an "Is a directory" error inside the loop without calling die(), and keys containing "../" can escape "$tempdir/map" into the surrounding working tree.
- [2026/11/24/19-19-00 by Junio C Hamano <gitster@pobox.com>] He suggested the patch also briefly explain why spaces are allowed in $to_commit, presuming that a single 'from' commit can map to multiple commits and that map() output is consumed unquoted in a for loop to replace $parent with each reparent commit.
- [2026/11/24/19-19-00 by Junio C Hamano <gitster@pobox.com>] He gave the review verdict "Looks good. Thanks." for the filter-branch hex-oid validation patch.
