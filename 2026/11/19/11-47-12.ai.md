This is the core refactoring patch (11/13) of Patrick Steinhardt's v5 series, converting `git rerere`'s custom subcommand dispatch in `builtin/rerere.c` to the standard `OPT_SUBCOMMAND()` mechanism. The patch introduces a table of `OPT_SUBCOMMAND()` entries mapping the names "clear", "diff", "forget", "gc", "remaining", and "status" to their respective `cmd_rerere_*()` handler functions extracted in preceding patches, and adds `PARSE_OPT_SUBCOMMAND_OPTIONAL` to the top-level `parse_options()` call so that the subcommand becomes optional.

When no subcommand is recognized, `cmd_rerere()` now falls back to a new `cmd_rerere_perform()` function that preserves the original default behavior of running `rerere()` with any `--rerere-autoupdate` or `--no-rerere-autoupdate` flags. This fallback path synthesizes an argv array by pushing "perform" plus the remaining arguments, and the patch fixes two issues in this path: it allocates the copied argv with `CALLOC_ARRAY(args_copy, args.nr + 1)` to guarantee NULL termination (correcting the prior `args.nr` allocation), and it calls `usage_with_options()` when the first remaining argument does not start with a dash, restoring the informative usage message for mistyped subcommand names.

The patch introduces one intentional backwards-incompatible change: the `--[no-]rerere-autoupdate` options are now only accepted for the implicit "perform" subcommand and are rejected when passed to named subcommands like `gc` or `status`, whereas previously they were silently accepted and ignored for all subcommands. The commit message frames this as fixing a misleading interface rather than a regression.

Within the broader v5 thread, this patch completes the `OPT_SUBCOMMAND()` conversion after the preparatory extractions in patches 5 through 10, and it implements the specific memory-safety and error-reporting corrections that were identified as follow-ups after v4 was merged to `master`.
