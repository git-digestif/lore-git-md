This is a bugfix targeting `git config` section removal and renaming.

The patch fixes `repo_config_copy_or_rename_section_in_file()` in `config.c`, which previously scanned config files line by line and treated any line beginning with `[` as a new section header. When a value inside the target section spanned multiple lines via backslash continuation and a continuation line happened to start with `[other]`, the function mistook it for a real section boundary, stopped processing early, and left behind a corrupted "unquoted" section containing the remainder of the continued value.

Dominik Maier adds tracking for backslash value continuations and quote state across lines, so that `[` is only recognized as a section header at the start of a logical line rather than inside a continued value. The fix carefully handles quoted subsections and ensures that `#` or `;` inside quotes are not mistaken for comments.

The patch includes thorough tests in `t/t1300-config.sh` covering multiline values with smuggled bracket text, quoted hash characters, and quoted subsection names containing brackets. The tests verify that `--remove-section` and `--rename-section` now correctly process the entire target section without being derailed by continuation lines.

This looks like a well-crafted fix: the commit message clearly explains the bug scenario, the code handles edge cases methodically, and the test coverage includes adversarial cases that verify the fix actually prevents the corruption described.
