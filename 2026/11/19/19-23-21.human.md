This is a security bugfix for `git-cvsexportcommit` that closes a shell injection hole in the `-W` (working-tree) mode. When `-W` is enabled, the Perl script reads the current HEAD via `git symbolic-ref` and later passes that value unquoted into single-string `system("git checkout $go_back_to")` calls. Because valid Git branch names can contain shell metacharacters such as `;`, Perl ends up invoking `/bin/sh -c`, allowing unintended command execution instead of a plain checkout.

The patch switches those calls to the list form -- `system('git', 'checkout', ...)` -- so the arguments are passed directly to `execve` without a shell. It also adds `--end-of-options` and `--` to the final checkout to guard against option injection, chomps the trailing newline from the symbolic-ref output, and converts the matching `git symbolic-ref HEAD` restoration call to list form as well.

A new test in `t/t9200-git-cvsexportcommit.sh` creates a branch literally named `topic;false` and verifies that `git cvsexportcommit -W` restores HEAD correctly without executing the injected command. The change is small, targeted, and clearly motivated; it fixes a genuine vulnerability in a contrib script with minimal risk of regression.
