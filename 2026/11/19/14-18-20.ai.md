This is a bugfix patch, specifically the first of three in Adrian Ratiu's v2 series addressing the `compatObjectFormat` interoperability layer (the SHA-1/SHA-256 object conversion machinery). The patch adds a guard in `verify_repository_format()` in `setup.c` that rejects a repository when `extensions.compatObjectFormat` is set to the same hash algorithm as `objectFormat` (or the default when `objectFormat` is unset). Previously, this configuration caused every Git command in Rust-enabled builds to abort with `BUG: repository.c:204: hash_algo and compat_hash_algo match`, including `git config`, making the repository unreachable and unrecoverable through Git itself; non-Rust builds also died, but for the separate reason that `compatObjectFormat` requires Rust. The new check runs before any Rust-only code paths, so both build types now receive the same clear error message spelling the key as `extensions.compatObjectFormat`, and the test in `t/t1302-repo-version.sh` exercises both SHA-1 and SHA-256 without requiring a `RUST` prerequisite, using modern `git config set` syntax and recovering the repository by unsetting the key via `git config unset --file=...`. This patch is uncontroversial and incorporates Patrick Steinhardt's cosmetic feedback from v1; patches 2 and 3 in the series address `git rev-parse --output-object-format` mapping failures and unknown commit header handling during conversion, respectively.
