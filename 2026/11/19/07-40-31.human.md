This is a test infrastructure patch that fixes CI hangs caused by memory exhaustion. When `GIT_TEST_LONG` is set and tests run in parallel via `prove --jobs`, multiple expensive tests (such as the multi-gigabyte cases in `t1007`, `t1600`, `t4300`, and `t4141`) can run simultaneously and exhaust the 16GB GitLab and GitHub CI runners, causing sanitizer jobs to hang until timeout or get OOM-killed.

The patch adds a cross-script lock in `t/test-lib.sh` so that any test carrying the `EXPENSIVE` prerequisite runs one at a time across all test scripts sharing the same `TEST_RESULTS_DIR`. The lock is implemented as a directory created with `mkdir(1)`, which records the holder's PID so that a stale lock left by a SIGKILLed script can be detected and taken over. It is released after the test and its cleanup finish, and also from the `EXIT` trap if the script dies while holding it, ensuring cheap tests in the same scripts continue to run in parallel while only the memory-hungry ones serialize.

The commit message is well-motivated, citing specific commits that introduced the expensive tests and providing links to CI pipeline runs on both GitHub and GitLab demonstrating that the fix resolves the hangs. The change is contained to `t/test-lib.sh` and `t/README`, with documentation updated to warn that long tests can use substantial memory and disk. It looks like a solid, targeted fix that should be uncontroversial.
