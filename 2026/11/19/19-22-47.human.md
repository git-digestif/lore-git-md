This is a bugfix for `git log --graph` rendering. Dominik Maier fixes a crash or corruption in the graph drawing code when displaying left-skewed octopus merges with four or more parents.

The bug occurs in `graph_insert_into_new_columns()` in `graph.c`. When a merge commit is skewed left (`merge_layout == 0`), its first parent does not advance the graph width, which causes the second parent of a 4+-parent merge to overwrite a column mapping without properly advancing the width. Subsequent parents are then placed one slot too far left, leaving the last dashed-parent slot in `graph->mapping[]` at -1 and causing `graph_draw_octopus_merge()` to index `graph->new_columns[-1]`.

The fix restricts the right-neighbor edge fusion logic to existing non-merge columns (`idx < 0`) and adds a defensive `BUG()` check in `graph_draw_octopus_merge()` to catch negative mapping indices. The patch includes a regression test in `t/t4215-log-skewed-merges.sh` that constructs a left-skewed 4-parent octopus merge and verifies the graph renders correctly.

The commit message clearly explains the root cause and the fix is minimal and targeted. This looks like a well-crafted fix for a real edge case in graph visualization.
