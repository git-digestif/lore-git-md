This is a maintainer review reply in the single-patch bugfix thread fixing `git ls-tree` `%(path)` quoting under `-z --format`. Junio C Hamano responds to Noam Cohen's defense of using a non-US-ASCII filename (נעם) in the regression test, acknowledging that synthesizing the tree with `git mktree` plus a forced `core.quotePath` setting was the alternative he had in mind, but stating explicitly that avoiding non-US-ASCII bytes is not a requirement -- tests using such bytes are preferable to having no test at all, provided one remains aware of platforms that cannot store them.

The technical substance confirms the thread's settled state: the code change in `show_tree_fmt()` within `builtin/ls-tree.c` (branching on `options->null_termination` to use `strbuf_addstr()` instead of `quote_c_style()`) remains assessed as "trivially correct," and the regression test in `t/t3104-ls-tree-format.sh` is accepted as written. The fix addresses the divergence from `git ls-files --format` (originating in commit ce74de931d) where `-z` already suppresses quoting, whereas `ls-tree --format` (introduced in 455923e0a1) had incorrectly applied C-style quoting even with `-z`.

No integration branch (master, next, seen) has been named for this topic, so it remains under review despite the maintainer's approval of both code and test. The two open questions Noam Cohen raised -- whether to set `core.quotePath` explicitly in the test rather than relying on its default, and whether to add a corresponding `-z` test for `git ls-files --format` -- remain unresolved, as does the broader question of whether other `ls-tree --format` placeholders require the same `-z` handling.
