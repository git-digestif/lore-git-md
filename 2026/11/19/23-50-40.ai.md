This is a **tested review** of the third patch in Christian Couder's LLP64 platform-compatibility series, confirming the removal of the `LONG_MAX` guard in `xdl_do_merge()` is safe and correct.

Tanga Joris reports actually running `t/t4300-merge-tree.sh` with `GIT_TEST_LONG=1` on two 64-bit Windows environments: a GitHub Actions Windows server runner (run 44423166965) and a native Windows laptop using the Git SDK. On the base commit `e1ec09b23c` the two EXPENSIVE big-merge tests were skipped because `long` is 32 bits there, while the "merge-tree dies when merge buffer size does not fit long" test passed; with Couder's series applied on top, both big merge tests now pass. Joris also audited all remaining callers of `ll_merge()` and `xdl_merge()` and confirmed they now terminate in `odb_write_object()`, `write_buf_to_worktree()`, `strbuf_attach()`, or `fwrite()`, all of which accept `size_t` once the series is applied, so the deleted check protects nothing. The review closes with "Looks good to me," providing concrete evidence that the patch achieves its goal on the target LLP64 platform.
