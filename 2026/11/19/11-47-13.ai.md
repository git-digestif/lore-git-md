This is a refactoring patch, specifically the twelfth of thirteen in Patrick Steinhardt's v5 series that converts `git rerere` to use the standard `OPT_SUBCOMMAND()` parsing mechanism. It improves the command's help and error output by giving each subcommand its own specific usage string instead of sharing a single generic one.

The patch touches `builtin/rerere.c` and `Documentation/git-rerere.adoc`. In the code, it replaces the single shared `rerere_usage[]` array with individual usage arrays for each subcommand handler (`cmd_rerere_clear`, `cmd_rerere_diff`, `cmd_rerere_forget`, `cmd_rerere_gc`, `cmd_rerere_perform`, `cmd_rerere_remaining`, `cmd_rerere_status`), defined via new `RERERE_*_USAGE` macros. Each `parse_options()` call in these handlers now receives its subcommand-specific usage string, so error messages like "too many arguments" display the correct syntax for that specific subcommand. The top-level `cmd_rerere()` now assembles a combined usage array listing all seven forms. The man page synopsis is updated to list each subcommand on its own line rather than as a bracketed alternation.

This builds directly on patch 11/13, which introduced the `OPT_SUBCOMMAND()` table and the `cmd_rerere_*()` handlers; this patch merely polishes the user-facing strings those handlers emit. No behavioral change to command execution occurs -- only the text shown in usage and error messages changes. The patch appears clean and well-scoped, completing the user-interface aspect of the subcommand modernization before the final documentation cleanup in 13/13.
