Dominik Maier has sent a single-patch bugfix for the protocol v2 handshake code in `connect.c`. The problem is that the file-static `server_capabilities_v2` vector is never cleared between handshakes, so capabilities advertised by one remote bleed into later connections to a different remote within the same process. Because `server_feature_v2()` and `server_supports_feature()` return the first matching entry, a stale `object-format=sha256` line from one remote can make a subsequent SHA-1 handshake abort with "mismatched object format", and a stale `session-id` can be logged for a remote that has `transfer.advertiseSID` disabled. The failure is reproducible with `git remote show r1 r2` when the two remotes use different object formats, and it can also surface on v0/v1 handshakes that skip `process_capabilities_v2()` entirely but still query capabilities afterwards.

The fix is minimal and defensive: a `strvec_clear(&server_capabilities_v2)` call is added at the top of both `discover_version()` and `process_capabilities_v2()` so every new handshake starts from an empty vector. The patch also includes a regression test in `t/t5702-protocol-v2.sh` that sets up two remotes with differing object formats and SID settings, runs `git remote show r1 r2`, and checks trace2 output to confirm the `server-sid` event appears only for the remote that actually advertised it. The change touches connection-handling code shared by fetch, push, and remote-inspection commands, and is currently under review on the mailing list.
