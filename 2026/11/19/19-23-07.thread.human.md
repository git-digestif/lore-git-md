This thread is a standalone bugfix from Dominik Maier targeting Git's config subsystem. The patch fixes `repo_config_copy_or_rename_section_in_file()` in `config.c`, which scans config files line-by-line when copying, removing, or renaming a section. The bug occurs when a value in the target section uses a backslash line continuation and the continuation line happens to begin with `[something]` -- the function mistakes that bracketed text for a new section header, causing `git config --remove-section` or `--rename-section` to stop early and leave fragments of the continued value behind as a spurious section.

The fix introduces two helpers: `skip_section_header()`, which parses past a valid section header including quoted subsections, and `update_line_continuation()`, which tracks two pieces of state across lines -- whether the current line continues a previous backslash-terminated value, and whether the parser is inside a double-quoted string. The main loop now updates this state before checking for `[`, so a bracketed string on a continuation line is no longer misread as a header, and `#` or `;` inside quotes on continued lines are not misinterpreted as comments. New tests in `t/t1300-config.sh` cover removal and rename of a section whose value continues across lines containing a bracketed string, a quoted hash, and a subsection name with brackets and escaped quotes.

As of this first email the patch is simply posted for review; no maintainer decision, Reviewed-by, or integration status has been announced yet, so the thread is open and awaiting substantive feedback.
