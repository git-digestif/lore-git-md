This is a bugfix for out-of-bounds and uninitialized reads when parsing delta headers in corrupt packfiles. Dominik Maier identifies two related defects: `get_size_from_delta()` in `packfile.c` inflates up to 20 bytes into a stack buffer but previously passed a fixed `delta_head + 20` bound to the header parser even when the stream ended earlier, causing it to read uninitialized stack memory; and the old `get_delta_hdr_size()` in `delta.h` used a do-while loop that dereferenced the buffer before checking bounds, allowing a read one byte past the buffer when a varint's continuation bit remained set at the boundary.

The patch replaces `get_delta_hdr_size()` with `decode_delta_hdr_size()`, which returns `-1` on truncated varints, unterminated sequences, or `size_t` shift overflow, and updates both `get_size_from_delta()` and `patch_delta()` to treat these error returns as failures rather than silently accepting partial sizes. The bound passed to the decoder is now `stream.total_out`, ensuring reads stay within the actually inflated data. The commit message clearly explains the attack surface -- a corrupt local packfile could trigger these reads -- and the fix appears well-targeted.

The patch includes a thorough test in `t/t5300-pack-object.sh` that constructs deliberately malformed packfiles with unterminated varints, out-of-bounds headers, and truncated streams, verifying that `git cat-file` rejects them rather than reading past buffers. Overall this looks like a solid, well-tested hardening fix for a real memory-safety issue in packfile parsing.
