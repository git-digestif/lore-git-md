This is a substantive review reply from Junio C Hamano on the eleventh patch of Patrick Steinhardt's v5 series, which converts `git rerere`'s custom subcommand dispatch in `builtin/rerere.c` to the standard `OPT_SUBCOMMAND()` mechanism with `PARSE_OPT_SUBCOMMAND_OPTIONAL` and a `cmd_rerere_perform()` fallback for the implicit default subcommand. Junio endorses the patch's intentional backwards-incompatible change: `--[no-]rerere-autoupdate` is now accepted only by the implicit "perform" path and rejected for named subcommands like `gc` or `status`, which he frames as fixing a previously misleading interface where the flag was silently ignored.

He identifies a usability side effect: because the primary subcommand has no explicit verb, `git rerere -h` now displays only the top-level usage listing all subcommands, hiding the descriptive help text for `--rerere-autoupdate` that previously appeared in the main help output. While awkward workarounds exist (e.g., `git rerere -- -h` or `git rerere --rerere-autoupdate -h`), he considers the current state acceptable, arguing that users familiar with the option already know it and others should use `git -c rerere.autoupdate=no rerere` instead.

Junio also flags a change in shell completion behavior: `git rerere --git-completion-helper` now emits the subcommand names (`clear diff forget gc remaining status`) rather than just the autoupdate flags. He notes this output is arguably better than the old sparse output but may affect the bash completion script, which might have carried workarounds for the previous behavior.

Within the series context, this reply addresses the core conversion patch (11/13) after the preparatory subcommand extractions in patches 5-10, and implicitly confirms the post-v4 follow-up fixes (NULL-terminated argv via `CALLOC_ARRAY(args.nr + 1)` and restored error reporting via `usage_with_options()`). No new objections are raised; the maintainer signals general acceptance of the approach modulo the noted discoverability caveat for the autoupdate option's help text.
