This is a **bugfix series cover letter** (v2) for the `compatObjectFormat` SHA-1/SHA-256 interoperability layer. Adrian Ratiu submits three patches: patch 1 adds a guard in `setup.c` to reject the nonsensical configuration where `extensions.compatObjectFormat` equals `extensions.objectFormat` (preventing a `BUG()` crash), patch 2 makes `git rev-parse --output-object-format` die with a clear error instead of silently printing the wrong OID when no compat mapping exists, and patch 3 makes `convert_commit_object()` copy unknown commit headers unchanged rather than rejecting them, unifying behavior with `convert_commit_extra_headers()` and removing a safety check deliberately added in commit 08a45903cb (2023).

The v2 iteration incorporates feedback from Patrick Steinhardt: error-message capitalization now uses `extensions.compatObjectFormat`, tests use modern `git config set/unset` syntax, the rev-parse test writes objects before enabling compat rather than manually copying loose objects (more robust under the upcoming ODB abstraction), and the header-matching logic in patch 3 now uses `<=` instead of `<` so that `tree `, `parent `, and `mergetag ` lines with empty values are still correctly classified and rejected rather than copied verbatim. A new test covers the empty-mergetag edge case.

The first two patches appear uncontroversial and well-justified. Patch 3 remains the focus of substantive discussion because it reverses a deliberate 2023 design decision; the author explicitly welcomes review from Eric Sunshine or brian m. carlson on this point, acknowledging the risk that unknown headers might contain unconverted object IDs. The series is cleanly written with good test coverage and directly addresses real bugs found while testing interop with Jujutsu and Gitoxide.
