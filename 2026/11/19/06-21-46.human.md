This is the first patch in a five-patch v3 series fixing loose object handling bugs, specifically adding missing size validation to the loose object reader. The patch fixes `unpack_loose_rest()` in `object-file.c`, which allocated a buffer based on the size claimed in the object header but never verified that the inflated stream actually produced that many bytes. This left two failure modes open: short streams would hand out uninitialized heap memory as object content, while streams that fit entirely within the initial header buffer would silently drop extra data. The fix adds a post-inflation check comparing `stream->total_out` against `hdrlen + size`, mirroring validation already present in the packfile path, and emits a specific error reporting the actual versus expected byte counts when they differ.

The patch also extends the `loose_obj()` helper in `t/lib-loose.sh` to accept an optional third argument for writing a bogus size into the object header, enabling three new tests in `t/t1060-object-corruption.sh` that verify reading objects with too-large or too-small header claims fails cleanly and that `git fsck` detects both cases. Unlike some other patches in this series that address LLP64-specific truncation issues, this fix is cross-platform and includes full automated test coverage.

The patch has already received maintainer approval from Junio C Hamano in the previous iteration, with v3 refining the error message per Patrick Steinhardt's suggestion to state the byte counts explicitly. It is based on current `master` and represents a well-crafted, targeted correctness fix that closes a real gap in loose object parsing without changing the on-disk format.
