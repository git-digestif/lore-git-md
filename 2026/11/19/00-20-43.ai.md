This is the final patch (6/6) of Justin Tobler's v2 series implementing eager creation of the ODB transaction temporary directory, part of the ongoing ODB abstraction effort. The patch moves temporary directory creation from a lazy `odb_transaction_files_prepare()` called on first object write into `odb_transaction_files_begin()` itself, so every files-backend transaction now creates its `tmp_objdir` up front using either the `"transaction"` or `"incoming"` prefix depending on the `ODB_TRANSACTION_RECEIVE` flag. It removes the now-unused `odb_transaction_files_prepare()` function, the `prefix` field from `struct odb_transaction_files`, and the conditional lazy-creation calls in `write_loose_object()` and `odb_source_loose_write_object_stream()` in `odb/source-loose.c`, ensuring all transactional loose object writes are staged in the temporary directory regardless of the configured `core.fsyncMethod`.

The behavioral consequence is that committing a transaction now migrates every written object into the primary object directory even when batched fsync is disabled, which adds a small per-object migration cost. The commit message includes a micro-benchmark showing roughly a 7% slowdown for `git add` of 10,000 small 4 KiB files under the default fsync configuration, but the author argues this overhead is minor compared to the cost of writing the object itself and is typically only visible when adding many small files at once; normal transactions writing few loose objects (e.g., unpacking small packs below the unpack limit) should not notice it. Tests in `t/t0004-unwritable.sh` are updated to expect the new failure mode: instead of late "insufficient permission" errors during object insertion, unwritable repositories now fail immediately at transaction start with `error: unable to create temporary object directory in .git/objects: Permission denied` followed by `fatal: failed to start object transaction`.

Files touched are `object-file.c`, `object-file.h`, `odb/source-loose.c`, and `t/t0004-unwritable.sh`, with a net reduction of 44 lines. The series remains under review with no `Reviewed-by` or `Acked-by` trailers yet; while Patrick Steinhardt has endorsed the direction and specific v1 concerns about batched-fsync scope and errno handling have been addressed in earlier patches of this v2, Karthik Nayak's fundamental design-level question about whether eager creation is architecturally justified over the previous lazy approach remains unanswered.
