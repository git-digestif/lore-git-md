This is a feature request proposing branch-aware `.gitignore` rules. Jordan Kadish describes a workplace scenario where a `settings.py` file is intentionally kept different from the version stored in `main`, and asks Git to support ignoring files based on the current branch -- either in all branches except a named one (whitelist mode) or only in a specific branch (blacklist mode). The motivation is concrete: local settings files, Django migrations, and compiled artifacts that must exist on staging or main but should be ignored locally. No patch or implementation is attached; this is a proposal seeking community feedback on whether such behavior is desirable and how it might be designed. As a standalone idea without code, there is nothing to review for correctness, though the use case is relatable to many developers who juggle environment-specific files across branches.
