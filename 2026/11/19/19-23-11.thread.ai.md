Thread identity: two-patch bugfix series v2 authored by Dominik Maier <dmnk@google.com>, evolving from the earlier standalone single-patch proposal after review by René Scharfe. The series targets the archive subsystem.

Core problem: two related defects in `git archive` argument handling and ZIP output. First, with `--remote`, `--add-file` and `--add-virtual-file` were processed during option parsing, including filesystem `stat()` calls, before the incompatibility check ran; a nonexistent file could therefore produce a confusing "File not found" error instead of "options '--add-file' and '--remote' cannot be used together", and `--no-add-file` after `--add-file` could suppress the check. Second, `write_zip_entry()` in `archive-zip.c` could advance a pointer out of bounds when `--prefix` was longer than the path of an extra or virtual file; this was found while testing `--remote --add-virtual-file` with `--format=zip`.

Current status: v2 is proposed and under review; no merge or integration status is stated. It supersedes the single-patch v1 approach.

Key technical details: patch 1/2 fixes the out-of-bounds pointer advance in `write_zip_entry()` in `archive-zip.c` for extra files (`--add-file`) and virtual files (`--add-virtual-file`) whose paths are shorter than `--prefix`. Patch 2/2 implements René Scharfe's alternative to rejecting options inside the callback: the option callback in `archive.c` now only records the entry, setting `info->content = NULL` for `--add-file` and inline content for `--add-virtual-file`. After `parse_options()` completes, `parse_archive_args()` iterates `args->extra_files`, skips entries with non-NULL `content`, dies with the `--remote` incompatibility error when `is_remote` is set and `content == NULL`, and only then performs `stat()` and the regular-file check. This preserves `--no-add-file` canceling an earlier `--add-file` even with `--remote`, prevents filesystem access on the server for `--add-file`, and allows `--remote --add-virtual-file` because virtual files require no filesystem access. The late `is_remote && args->extra_files.nr` validation from v1 is no longer used. Tests in `t/t5000-tar-tree.sh` cover `--remote --add-file` failing with the incompatibility message rather than "File not found", `--no-add-file` canceling `--add-file` locally and remotely, and `--remote --add-virtual-file` succeeding; `t/t5003-archive-zip.sh` covers the zip prefix fix. Files touched are `archive.c`, `archive-zip.c`, `t/t5000-tar-tree.sh`, and `t/t5003-archive-zip.sh`; relevant to server-side handling in `git-upload-archive`.

Open questions and loose ends: René Scharfe's v1 feedback has been incorporated in v2, including the deferred-stat design and support for `--no-add-file` cancellation; no unresolved objection or request for changes is recorded.
