Thread identity: standalone single-patch bugfix (not part of a series) authored by Dominik Maier <dmnk@google.com> fixing argument validation ordering in `git archive --remote`.

Core problem: with `--remote`, the `--add-file` and `--add-virtual-file` options were processed during option parsing -- including filesystem `stat()` calls -- before the existing incompatibility check ran, so a nonexistent file produced a confusing "File not found" error instead of the proper "options '--add-file' and '--remote' cannot be used together" message, and appending `--no-add-file` after `--add-file` could suppress the check entirely, letting the command succeed when it should have been rejected.

Current status: patch proposed and under review; no merge or integration status stated.

Key technical details: modifies `archive.c` by introducing a new `struct add_file_data` that bundles the `archiver_args`, the `base` pointer, and the `is_remote` flag, passed as the option callback value in place of the bare `archiver_args`. `add_file_cb()` now checks `data->is_remote` immediately and dies with the incompatibility error (for either `--add-file` or `--add-virtual-file`) before any filesystem access. The late validation in `parse_archive_args()` that checked `is_remote && args->extra_files.nr` after `parse_options()` returns is removed. Adds a test in `t/t5000-tar-tree.sh` verifying that `git archive --remote=. --add-file=no-such-file` fails with the incompatibility message rather than "File not found", and that `--add-file` followed by `--no-add-file` still errors. Touches only the archive subsystem and its tar test script; relevant to server-side argument handling in `git-upload-archive`.
