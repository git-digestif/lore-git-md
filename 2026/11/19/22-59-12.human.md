This is a design-discussion reply within the v2 bugfix series for UTF-8 display-width bounds handling in `utf8.c`. Dirk Gouders responds to Andy Koppe's performance objection that the NUL-terminated wrapper `display_mode_esc_sequence_len()` -- which calls `strlen()` before delegating to the counted variant -- turns repeated SGR scanning from linear into quadratic time. Rather than accepting the binary choice between keeping that wrapper or deleting it outright, Dirk proposes a third option: give the function an optional `size_t *remainder` parameter modeled on `utf8_width()`, where NULL preserves NUL-terminated behavior and a non-NULL pointer supplies and updates the remaining length, allowing bounded scanning without an upfront `strlen()`. He includes an untested diff sketch showing how the signature would change.

The email documents the API design space considered for `display_mode_esc_sequence_len()` and its `_counted` variant, but per the thread context this compromise was not adopted. The series has instead settled on removing the wrapper entirely and reverting to Junio C Hamano's v1 approach, where only the counted variant exists and callers like `pretty.c` pass the length explicitly. Andy Koppe has separately indicated he will update his own code to call the counted variant directly once the wrapper is gone.

For a reader tracking this thread, the key takeaway is that the substantive technical direction is now settled -- patch 1 of the next version will drop the wrapper -- and this email merely records an alternative that was considered and set aside. Only surface-level nits remain outstanding for a possible v3.
