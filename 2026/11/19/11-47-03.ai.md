This is a refactoring patch, the second of thirteen in Patrick Steinhardt's v5 series modernizing `git rerere`'s subcommand handling. It converts the rerere subsystem's flag constants from `#define` macros into a proper `enum rerere_flags` with explicit bit-shift values (`1 << 0` through `1 << 3`), updating the signatures of `rerere_cache_setup()`, `rerere()`, and `rerere_gc()` in `rerere.h` and `rerere.c` to accept the enum instead of a bare `int`. Each flag is now documented inline in the enum definition.

The patch also adds a defensive `BUG()` check in `rerere_cache_setup()` that fires if a caller passes both `RERERE_AUTOUPDATE` and `RERERE_NOAUTOUPDATE` simultaneously, since the precedence between these contradictory flags was previously implicit (autoupdate wins). The commit message notes that all current callers already avoid this combination, so this is purely a safety net rather than a bug fix.

Within the broader v5 series, this is preparatory cleanup that precedes the actual subcommand-parser rewrite: the series replaces custom parsing with `OPT_SUBCOMMAND()` and dedicated `cmd_rerere_*()` functions. This particular patch touches only `rerere.c` and `rerere.h` with no behavior change visible to users, though future patches in the series (notably patch 11) will address memory-safety and error-reporting fixes in the fallback `cmd_rerere_perform()` path.
