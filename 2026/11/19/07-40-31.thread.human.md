This thread concerns Kaartic Sivaraam's v2 patch to serialize EXPENSIVE tests in Git's shell test suite, a fix for CI runners being OOM-killed when memory-intensive tests (notably the multi-GB cases in t1007, t1600, t4300, and t4141) run concurrently under `GIT_TEST_LONG` with parallel execution. The patch adds `acquire_expensive_lock_()`/`release_expensive_lock_()` to t/test-lib.sh using a directory-based lock with stale-PID detection. Patrick Steinhardt reviewed substantively and approved the approach, and his requested refinements are incorporated in v2.

The series remains blocked on two correctness objections from Junio C Hamano: a TOCTOU race where a waiter could delete a newly-acquired lock, and a more serious signal-handling window where a process killed between `mkdir` and writing its PID leaves a permanently stuck lock, which Junio called "far worse" than the race. Sivaraam has replied with two incremental fixes -- a secondary `.break` lock plus PID re-verification for the race, and setting `have_expensive_lock_=t` before the PID write for the deadlock window -- while acknowledging that `kill -9` and microsecond-window edge cases remain unaddressed and proposing to defer them. No v3 has been posted, and the thread awaits Junio's response to these proposals.

Harald Nordgren added a brief supportive note hoping the patch can be merged soon to unbreak the GitHub CI pipeline, but it carries no technical feedback and does not change the assessment: v2 is still under review, not accepted, and not queued in any integration branch.
