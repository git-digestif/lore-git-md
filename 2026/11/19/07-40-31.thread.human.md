This thread concerns Kaartic Sivaraam’s v2 patch to serialize `EXPENSIVE` shell tests in `t/test-lib.sh`, so that memory-heavy tests such as parts of t1007, t1600, t4300, and t4141 do not run concurrently under `prove --jobs`, the Makefile, or Meson and OOM 16GB CI runners. Patrick Steinhardt reviewed the approach substantively and was fine with it, and v2 incorporates his refinements: `local` declarations inside `acquire_expensive_lock_()`, softer commit-message wording that does not single out `prove --jobs`, and a range-diff showing the feedback was addressed.

The picture changed with Junio C Hamano’s review, which identifies two serious flaws in v2’s `mkdir`-based lock at `$TEST_RESULTS_DIR/expensive.lock`. One is a TOCTOU race: a waiter can read the previous holder’s `pid` file just as that holder exits and another process acquires the lock, then delete the now-active lock and let two `EXPENSIVE` tests run together. The worse case is a signal delivered after `mkdir` succeeds but before the PID is written or `have_expensive_lock_=t` is set; the EXIT trap then skips release because the flag is unset, leaving an empty lock directory that waiters never clear and causing a permanent deadlock.

The series remains under review and is not accepted as-is: the approach has Steinhardt’s approval, but Junio’s correctness objections are now the open issue, with no integration-branch placement stated.
