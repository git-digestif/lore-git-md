This thread is a single test patch from Kaartic Sivaraam addressing a CI reliability problem in Git's shell test suite. When `GIT_TEST_LONG` is enabled and tests run under `prove --jobs`, several memory-intensive tests -- notably the 5GB filtered hash-object test in `t1007` and newer multi-GB tests in `t1600`, `t4300`, and `t4141` -- can execute simultaneously and exhaust the 16GB memory of GitLab and GitHub runners, causing OOM kills and timeouts. The patch serializes only tests carrying the `EXPENSIVE` prerequisite by adding `acquire_expensive_lock_()` and `release_expensive_lock_()` helpers to `t/test-lib.sh`, implemented as a `mkdir`-based lock directory at `$TEST_RESULTS_DIR/expensive.lock` with a `pid` file and stale-lock recovery, and wired into `test_run_()` plus the `die()` EXIT trap. Cheap tests in the same script still run in parallel. The patch also documents the behavior in `t/README`, and the commit message cites the specific commits that introduced the heavy tests along with reproduction steps and CI validation links. As a newly posted patch it is under review, with no maintainer decision recorded yet.
