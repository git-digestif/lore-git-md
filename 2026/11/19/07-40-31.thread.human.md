This thread addresses OOM kills on CI runners caused by multiple memory-intensive tests running concurrently when `GIT_TEST_LONG` is set. Kaartic Sivaraam posted a v2 patch that serializes tests marked with the `EXPENSIVE` prerequisite in `t/test-lib.sh` using a lock directory, and Patrick Steinhardt approved the approach after requesting refinements that were incorporated. The discussion then turned to correctness flaws identified by Junio C Hamano: a TOCTOU race where a waiter might delete a new lock holder's directory, and a more severe signal-handling window where a process killed between `mkdir` and setting the cleanup flag could leave a permanently stuck lock.

Sivaraam replied proposing two incremental fixes -- a secondary `.break` lock to close the TOCTOU race and reordering the code so `have_expensive_lock_=t` is set before the PID write to eliminate the deadlock. In his latest reply, Junio drew a sharp distinction between the two failure modes: a leaky lock that lets two EXPENSIVE tests overlap merely reproduces the status quo and is not a regression, but a permanent deadlock is a serious regression that must be eliminated. He stated that if the next version kills the deadlock scenario he will be satisfied, effectively greenlighting the flag-before-PID-write reordering while accepting the remaining `kill -9` and microsecond-window edge cases as deferrable residual risks.

The series remains under review with no v3 posted yet; the expected next step is a revised patch incorporating the approved fixes, after which the topic can move toward acceptance.
