This is a refactoring patch -- specifically the third of six in Justin Tobler's v2 series that moves ODB transaction temporary directory creation from lazy to eager, part of the ongoing ODB abstraction effort. The change inlines the static helper `setup_tmp_objdir()` into its sole caller, `tmp_objdir_create()`, in `tmp-objdir.c`, eliminating an intermediate function that merely created the `pack` subdirectory.

The commit message explains that this is preparatory work: a subsequent patch in the series needs `tmp_objdir_create()` to preserve `errno` when directory creation fails, and inlining the helper means `errno` only has to be saved in one place rather than across multiple functions. The diff itself is purely mechanical -- moving the `mkdir` call for the `pack` subdirectory directly into `tmp_objdir_create()` and deleting the now-unused `setup_tmp_objdir()` function -- with no behavior change (6 insertions, 13 deletions).

Within the broader series, this cleanup sets up the final patch that will create the temporary object directory eagerly at transaction start rather than on first write. The series as a whole addresses a correctness gap where some transactional object writes bypassed the temporary directory, and this particular patch is just tidying the code path that will soon be exercised much earlier in the transaction lifecycle.

The patch looks clean and well-scoped. It does exactly what it says, introduces no functional changes, and the commit message clearly states its role as preparation for the errno-preservation fix that follows.
