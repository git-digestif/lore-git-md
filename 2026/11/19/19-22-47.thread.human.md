Dominik Maier has sent a bugfix for the ASCII graph rendering code in `graph.c`, addressing incorrect output and an out-of-bounds crash when rendering left-skewed octopus merges with four or more parents under `git log --graph`. The bug was in `graph_insert_into_new_columns()`: with `merge_layout == 0`, a merge commit's first parent does not advance `graph->width`, so a fusion branch intended only for existing columns to the right of a merge also fired for a left-side column, shifting later parents one slot too far left and leaving a `-1` in `graph->mapping[]` that was dereferenced in `graph_draw_octopus_merge()`.

The fix is small and well-scoped: it adds an `idx < 0` guard so the fusion path only applies to existing non-merge columns, plus a defensive `BUG("octopus merge mapping uninitialized")` in `graph_draw_octopus_merge()`. It also includes a regression test in `t/t4215-log-skewed-merges.sh` that constructs a left-skewed 4-parent octopus merge joined to an adjacent left column and checks the expected output. The patch appears ready for review, with no reviewer feedback or merge status yet recorded.
