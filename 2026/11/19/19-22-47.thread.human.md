This thread is a small bugfix effort by Dominik Maier to correct the ASCII graph rendering in `git log --graph` for left-skewed octopus merges with three or more parents. The root cause lies in `graph_insert_into_new_columns()` in `graph.c`: a column-fusion shortcut meant for existing right-side columns also fired for left-skewed merges, whose first parent does not advance the graph width. With three parents this swallows a merge edge entirely; with four or more it shifts later parents one slot left, leaving a `-1` in `graph->mapping[]` and triggering an out-of-bounds access in `graph_draw_octopus_merge()`. The fix adds an `idx < 0` guard so the fusion path applies only to existing non-merge columns.

The series has now reached v2. The new version drops the defensive `BUG()` that v1 had placed in `graph_draw_octopus_merge()`, rewords the commit message with ASCII-art examples of both failure modes, and expands the regression tests in `t/t4215-log-skewed-merges.sh` to cover both a 3-parent and a 4-parent left-skewed merge. Caspar Duregger, who in review supplied the simpler 3-parent reproduction and confirmed the guard is the right approach, is credited with a `Helped-by` trailer; his earlier open question about whether the `BUG()` belonged in the code is thereby resolved by its removal. His remaining feedback was surface-level, noting the commit message is dense for casual readers.

The patch remains under review with no Reviewed-by, Acked-by, or maintainer feedback recorded, and it has not been queued in any of Junio's integration branches. Nothing is contested; the main open item is simply that the fix's correctness has not yet received independent verification beyond Duregger's confirmation, and a maintainer has not yet weighed in.
