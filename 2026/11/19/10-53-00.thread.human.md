This thread is a single documentation patch from Okhuomon Ajayi proposing to codify the informal line-wrapping and paragraph conventions for emailed Git contributions. The patch, currently at version 2, would add guidance to `Documentation/CodingGuidelines`, `Documentation/ReviewingGuidelines.adoc`, and `Documentation/SubmittingPatches` stating that emailed text -- including commit messages and review replies -- should be wrapped near 70 columns to stay readable on an 80-column terminal after quoting, and that paragraphs, including blocks of quoted text, should be separated by blank lines. Version 2 added the blank-line guidance in response to a scope concern Junio C Hamano raised on v1.

The main open point has been the exact column limit. Andy Koppe reviewed v2 and suggested replacing the vague "near 70 columns" with "to a maximum of 72 columns," matching the existing commit-message convention and removing ambiguity. Ajayi has now replied accepting that suggestion and says he will resend the patch, presumably as v3, with the 72-column wording; the blank-line guidance from v2 is unchanged.

The thread remains open with no Reviewed-by or Acked-by trailers recorded and no integration-branch placement announced, so the patch is still under review awaiting the next version and further feedback.
