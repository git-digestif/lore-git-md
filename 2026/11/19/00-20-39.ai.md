This is patch 2/6 in Justin Tobler's v2 series on eagerly creating the ODB transaction temporary directory, classified as a bugfix within the ODB abstraction effort. It modifies only `object-file.c` to avoid issuing an unnecessary hardware flush during transaction commit.

The patch extracts the batched-fsync flush logic from `odb_transaction_files_commit()` into a new static helper `flush_batched_fsync()`, which creates a temporary file named `bulk_fsync_XXXXXX` in the object directory and fsyncs it to act as a durability barrier. The behavioral change is that this flush is now guarded by `batch_fsync_enabled(FSYNC_COMPONENT_LOOSE_OBJECT)`, so it only executes when batched fsync is actually enabled. Previously, the flush ran whenever `transaction->objdir` was set, meaning transactions configured for `git-receive-pack` (which always create the temp directory) would perform the flush even when objects were synced individually or not synced at all, despite there being no pending writeout requests to flush.

The commit message notes that batched fsync applies only to loose objects; packfiles written during the transaction are fully synced (or not synced) at write time and do not rely on this barrier. This patch is preparatory to the series' core change in 6/6, where temporary directory creation becomes eager rather than lazy.
