This is a security hardening patch for `git filter-branch` that fixes a path traversal vulnerability when loading state from a `--state-branch`.

When `git filter-branch --state-branch` resumes from an existing state branch, it reads the `filter.map` blob and writes each entry to a file named after the source commit inside its temporary map directory. The existing code split each `from:to` line and wrote `../map/$from_commit` without checking that `$from_commit` or `$to_commit` were valid hexadecimal object IDs. A malformed or malicious state branch containing entries like `../../escaped:injected` or backslashes could therefore cause the script to write files outside the intended temp directory.

The patch validates both fields before writing: `$from_commit` must be non-empty lowercase hexadecimal, and `$to_commit` may contain only lowercase hex digits and spaces (allowing an empty value for pruned commits). It also switches the read loop to `IFS= read -r` to avoid mangling whitespace or backslashes, and uses `printf` instead of `echo` for the output. Both invalid cases now die with a clear error message.

The commit includes a test in `t/t7003-filter-branch.sh` that constructs a state branch with a path-traversing entry (`../../escaped`) and one with a backslash, verifying that `git filter-branch` fails cleanly and does not create the escaped file. The patch looks well-crafted: it addresses a concrete security issue with a targeted fix and adequate test coverage.
