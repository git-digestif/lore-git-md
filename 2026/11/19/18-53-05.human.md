This is a substantive review from Junio C Hamano responding to Kaartic Sivaraam's bugfix patch for `git fast-import`. While Junio agrees the one-line fix is "obviously correct," he argues that the underlying code structure is fragile and proposes a small refactoring to prevent similar bugs in the future.

The patch itself fixes an information disclosure where the `export-marks=<path>` feature leaked the user-supplied filesystem path into the error message when the feature was forbidden. Junio points out that the current if/else if/else cascade in `parse_one_feature()` forces the feature name to be repeated -- once in the `skip_prefix()` check and again in the `check_unsafe_feature()` call -- which is exactly what allowed this bug to slip in. He suggests introducing a combined helper, `check_unsafe()`, that performs both the prefix matching and the safety check in one place, passing only the bare feature name to the error message. This would eliminate the repetition for all unsafe features, not just `export-marks`.

Junio also notes a forward-looking consideration: if an argument-less unsafe feature is ever added, the helper would need to distinguish between `feature` and `feature=` terminators, but the core idea remains sound. The review is constructive and endorses the direction while improving the implementation, and there are no objections to the fix itself -- only a suggestion to make the code more robust against future mistakes.
