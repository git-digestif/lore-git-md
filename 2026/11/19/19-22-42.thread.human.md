Dominik Maier has sent a security-hardening patch that fixes two memory-safety defects in how Git parses delta object headers from packfiles. The first issue is in `get_size_from_delta()` in `packfile.c`, which inflates up to 20 bytes into a stack buffer but always passed the full buffer end as the decoder bound, causing reads of uninitialized stack memory when zlib produced fewer bytes. The second is in the old `get_delta_hdr_size()` in `delta.h`, whose loop dereferenced data before checking bounds and could return a bogus size for truncated varints, leading `patch_delta()` to misinterpret corrupt headers.

The patch replaces `get_delta_hdr_size()` with `decode_delta_hdr_size()`, which returns -1 on truncated varints, EOF, or shift overflow, and updates both `get_size_from_delta()` and `patch_delta()` in `patch-delta.c` to handle that error return. The `get_size_from_delta()` call site now bounds the decoder by `stream.total_out` instead of the fixed buffer end. An 86-line test in `t/t5300-pack-object.sh` constructs corrupted packfiles covering unterminated varints, out-of-bounds reads, and truncated headers to verify that `git cat-file` rejects them. The series is at its initial version and awaits review.
