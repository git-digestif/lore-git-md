This is a bugfix for `git mv` that closes a hole in symlink-leading-path protection introduced by commit 062d90b2a8. The patch targets `builtin/mv.c` in `cmd_mv()`: when `mv -f` is used and the destination path resolves through a symlinked directory to a file that already exists on disk, the previous code unconditionally jumped to `act_on_entry`, bypassing `has_symlink_leading_path()` and sparse-checkout checks. The fix changes the unconditional `goto act_on_entry` to `if (bad) goto act_on_entry`, ensuring that forced overwrites still run the remaining destination validation before proceeding. A regression test in `t/t7001-mv.sh` covers the case where `git mv -f` attempts to overwrite an existing file through a symlinked leading path and verifies the operation fails with "destination is beyond a symbolic link" while leaving the target intact.
