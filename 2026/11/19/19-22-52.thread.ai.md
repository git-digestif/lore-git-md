Thread identity: standalone bugfix patch from Dominik Maier <dmnk@google.com> to `git@vger.kernel.org` fixing a hole in `git mv`'s symlink-leading-path protection. Thread root; no prior emails.

Core problem: commit 062d90b2a8 introduced symlink-leading-path protection for `git mv`, but in `cmd_mv()` in `builtin/mv.c` the `mv -f` path unconditionally executed `goto act_on_entry` when the destination resolved through a symlinked directory to an existing file, bypassing both `has_symlink_leading_path()` and sparse-checkout checks. This allowed a forced overwrite to proceed where it should have been rejected.

Fix: the unconditional `goto act_on_entry` is changed to `if (bad) goto act_on_entry`, so forced overwrites still run the remaining destination validation. Regression test added in `t/t7001-mv.sh` covering `git mv -f` over an existing file through a symlinked leading path; it verifies the operation fails with "destination is beyond a symbolic link" and the target file is left intact.
