This is a review ping on an existing bugfix patch. Aniket Gupta is nudging Elijah Newren to review the standalone patch that fixes a `--no-overwrite-ignore` regression in the `merge-ort` strategy, where directory rename detection can silently overwrite ignored untracked files despite the option being set.

The underlying patch addresses a data-loss risk confirmed across Git versions 2.54.0 through 2.56.0.138: when `merge.directoryRenames` is enabled (in any mode) and a tracked file is moved via directory rename detection into a path containing an ignored file, Git overwrites the ignored file instead of aborting. The fix introduces a `preserve_ignored` bit in `struct merge_options` (in `merge-ort.h`), plumbs it through `merge-ort.c` to the checkout logic, and corrects the trivial-merge path in `builtin/merge.c` which previously ignored the option. Two new tests in `t/t7600-merge.sh` cover both direct collisions and the directory rename scenario, expecting an aborted merge with a clear error message.

The patch is currently v1 and awaiting technical review; no feedback has been received yet. Coy Geek originally reported the regression with a reproduction script. The issue is specific to `merge-ort` and does not affect other strategies like `recursive`.
