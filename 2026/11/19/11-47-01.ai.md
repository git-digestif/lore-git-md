This is the cover letter for version 5 of Patrick Steinhardt's 13-patch refactoring series that modernizes `git rerere`'s subcommand handling by replacing its custom parser with the standard `OPT_SUBCOMMAND()` mechanism. The series builds on the already-merged `ps/rerere-remove-global-state` topic (b948c10c8b3) and touches `builtin/rerere.c`, `rerere.h`, `rerere.c`, and several callers in `apply.c`, `builtin/am.c`, `builtin/commit.c`, `builtin/merge.c`, `builtin/stash.c`, and `sequencer.c`, plus `Documentation/git-rerere.adoc` and `t/t4200-rerere.sh`.

Version 5 directly addresses the follow-up items left open after the v4 discussion. Patch 10 now explicitly documents in its commit message that the `--skip-locked` flag is only accepted after the `gc` subcommand name (not before), acknowledging this as an intentional behavior change. Patch 11 fixes two issues: it corrects the NULL-termination of the synthetic `argv` array used in the fallback `cmd_rerere_perform()` path by allocating `args.nr + 1` elements with `CALLOC_ARRAY()` (previously `args.nr`), and it restores the usage synopsis for unknown subcommands by calling `usage_with_options()` when the first argument does not start with a dash. A new thirteenth patch removes the stale documentation claim that `git rerere diff` passes additional arguments to the system `diff` command -- a discrepancy that has existed since 2006.

The technical core remains the same as v4: flags converted to `enum rerere_flags`, removal of `the_repository` in favor of an explicit `repo` parameter, dedicated `cmd_rerere_*()` functions for each subcommand ("forget", "clear", "status", "remaining", "diff", "gc"), and the final switch to `OPT_SUBCOMMAND()` with `cmd_rerere_perform()` as the fallback. No new user-visible functionality is introduced; the only behavioral change is the documented `--skip-locked` option-ordering restriction.

For future thread summarization: watch for confirmation that the NULL-termination fix in patch 11 is correct and that the new documentation patch 13 accurately reflects that `git rerere diff` accepts no extra arguments. The option-ordering change for `--skip-locked` remains the only point where old command lines will fail, now explicitly called out as intentional.
