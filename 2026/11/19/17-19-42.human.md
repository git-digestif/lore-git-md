This is a bugfix thread -- specifically a polite ping on a standalone patch that fixes ignore-pattern parsing.

Aniket Gupta is following up on his earlier submission, which addresses a bug where `git check-ignore -v` incorrectly matches directory paths ending in a trailing slash against blank lines in `.gitignore` when those lines use CRLF endings or contain only whitespace. The fix is a one-line guard in `add_patterns_from_buffer()` in `dir.c` that skips empty lines after trimming, restoring the documented behavior that blank lines never match anything. A test in `t/t0008-ignores.sh` covers the CRLF and mixed-whitespace cases reported by Mike Beaton.

This email itself adds no new technical content -- it is simply a reminder that the patch is still awaiting review. The change is minimal, well-motivated, and aligns with documented semantics, but no maintainer has yet weighed in. It is currently under review with no indication of controversy.
