This is a bugfix, and specifically patch 4/5 in Elia Pinto's five-patch v3 series addressing loose object size validation and integer truncation on LLP64 platforms. While the series as a whole targets 64-bit Windows quirks, this particular patch fixes a cross-platform buffer overread in `git cat-file --batch`.

The bug is in `batch_write()` in `builtin/cat-file.c`, which takes the data length as an `int` even though its callers pass `size_t` object sizes. For any object between 2 GiB and 4 GiB, the length wraps negative, and when passed to `fwrite()` or `write_or_die()` it becomes an enormous `size_t`, causing Git to write past the end of the allocated buffer until it crashes with "write error: Bad address". Objects 4 GiB and larger are silently truncated, desynchronizing the batch output stream. The fix is a one-line type change from `int` to `size_t`, which both underlying write functions already accept.

The issue triggers when `git cat-file --batch` processes non-blob objects or blobs run through `--filters` or `--textconv`, since plain blobs are streamed rather than buffered. The commit message documents a manual reproduction using a 3 GiB zero-filled blob with `--filters`, but no automated test is included because it would require several GiB of memory and disk.

Junio C Hamano reviewed the patch and called it "trivially correct"; the v3 commit message was trimmed per his stylistic suggestion. It sits alongside the other patches in the series, which address LLP64-specific truncation in loose object reading, streaming, and notes concatenation, but unlike those this one affects all platforms.
