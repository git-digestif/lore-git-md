This is a design-discussion reply within the bugfix series fixing bounds handling in Git's UTF-8 width code. Dirk Gouders responds to Andy Koppe's performance objection to the NUL-terminated wrapper proposed in patch 1 of the v2 series (`display_mode_esc_sequence_len()` calling `strlen()` on its input). Koppe had argued that the wrapper turns repeated SGR scans from linear into quadratic time by forcing a full `strlen()` on every call.

Gouders proposes a middle-ground API for a future v3: give `display_mode_esc_sequence_len()` an optional remainder parameter modeled on `utf8_width()`. If the caller passes NULL the function assumes a NUL-terminated string; otherwise it reads the bound from `*remainder`, updates it, and returns the sequence length. This would avoid both the quadratic `strlen()` cost and the need to remove the wrapper entirely.

The email sits early in the patch-1 discussion of the four-patch series that also touches `utf8_strnwidth()`, `utf8_width()`, and their unit tests. At this point in the thread the API shape for the escape-sequence scanner is still open; Gouders is floating the remainder-argument design as a way to preserve a convenient NUL-terminated interface without the performance regression Koppe identified.
