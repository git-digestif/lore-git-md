This is patch 5/6 in Justin Tobler's v2 series on eagerly creating the temporary object directory at ODB transaction start, part of the ongoing ODB abstraction effort. The patch is a user-facing error message wording change that touches only `odb/transaction.h`, replacing the jargon term "ODB" with the more accessible "object" in three `die()` messages emitted by the inline helpers `odb_transaction_begin_or_die()` and `odb_transaction_commit_and_finalize_or_die()`. Specifically, the messages "failed to start ODB transaction", "failed to commit ODB transaction", and "failed to finalize ODB transaction" become "failed to start object transaction", "failed to commit object transaction", and "failed to finalize object transaction" respectively. The commit message notes that "ODB" is unlikely to be understood by average users, making "object transaction" the clearer phrasing.

The change is purely cosmetic with no behavioral impact, consisting of three line modifications in the header file. It sits near the end of the six-patch series, ahead of the final patch that implements the actual eager directory creation. Because these messages are user-visible, downstream test updates -- specifically in `t/t0004-unwritable.sh` as noted in the series cover letter -- will need to expect the new "object transaction" wording rather than the old "ODB transaction" phrasing. The patch is straightforward and uncontroversial, addressing a v1 review point about user-facing terminology without introducing any functional changes or dependencies on the other patches in the series.
