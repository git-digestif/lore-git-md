This is the final patch (6/6) of a bugfix series that makes ODB transaction temporary-directory creation eager rather than lazy, part of the ongoing ODB abstraction effort.

Currently, the "files" backend only creates the temporary object directory on the first loose-object write when batched fsync is enabled, meaning some transactional writes bypass the quarantine directory entirely depending on the configured `core.fsyncMethod`. This patch moves creation to `odb_transaction_files_begin()` so every transaction stages objects in the temporary directory immediately, guaranteeing consistent visibility semantics at commit time regardless of fsync settings. It removes the now-unnecessary `odb_transaction_files_prepare()` hook and the lazy-creation calls from `write_loose_object()` and the stream writer in `odb/source-loose.c`, and updates the unwritable-repository test expectations in `t/t0004-unwritable.sh` to match the new early failure messages.

The author includes a benchmark showing roughly a 7% slowdown for `git add` when writing 10,000 small loose objects, attributing it to the added migration cost of moving each object from the temporary directory into the primary object store at commit time; he argues this overhead is negligible in typical transactions that write only a few objects. The series remains under review, with Karthik Nayak's fundamental design question about whether eager creation is architecturally justified over the lazy approach still open, though all specific technical concerns from the v1 cycle appear addressed in this v2 respin.
