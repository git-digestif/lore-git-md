This is a **bugfix** (security hardening) for corrupt packfile handling, addressing out-of-bounds and uninitialized memory reads in delta header parsing.

The patch fixes two related defects in how Git reads delta object headers from packfiles. `get_size_from_delta()` in `packfile.c` inflates up to 20 bytes into a stack buffer `delta_head[]` but always passed `delta_head + sizeof(delta_head)` as the upper bound to the header decoder, even when zlib produced fewer bytes -- reading uninitialized stack memory. Meanwhile, the old `get_delta_hdr_size()` in `delta.h` used a do-while loop that dereferenced `*data` before checking bounds, and returned a partial size when a varint's continuation bit remained set at the boundary, which could cause `patch_delta()` to treat a truncated varint as a zero-byte size.

Dominik Maier replaces `get_delta_hdr_size()` with `decode_delta_hdr_size()`, which returns -1 on truncated varints, EOF, or `size_t` shift overflow, and updates both `get_size_from_delta()` and `patch_delta()` in `patch-delta.c` to check this return value. The `get_size_from_delta()` call site now bounds the decoder's `top` pointer by `stream.total_out` rather than the fixed 20-byte buffer end. The patch includes an 86-line test in `t/t5300-pack-object.sh` that constructs corrupted packfiles exercising three failure modes: unterminated varints, out-of-bounds reads (20 bytes all with the continuation bit set), and truncated headers, verifying that `git cat-file` rejects them.
