This is a refactoring series -- specifically the v5 cover letter for a 13-patch effort by Patrick Steinhardt to modernize `git rerere`'s subcommand parsing. The goal is to replace the hand-rolled subcommand ladder in `builtin/rerere.c` with the standard `OPT_SUBCOMMAND()` mechanism used by other multi-subcommand built-ins like `git notes` and `git maintenance`, bringing the command in line with the rest of the codebase. No new user-facing functionality is introduced; the series is purely internal restructuring that extracts each existing action ("forget", "clear", "status", "remaining", "diff", "gc") into a dedicated function with its own usage string.

Version 5 specifically addresses several regressions and loose ends identified during review of v4. It documents the intentional behavior change for `--skip-locked` (now only accepted after the `gc` subcommand name), fixes the error message so an unknown subcommand again prints the synopsis, NULL-terminates the synthetic argv array in the fallback logic to fix a latent memory-safety issue, and adds a final patch to remove the stale claim in the man page that `git rerere diff` passes arguments to the system `diff` command -- a discrepancy dating back to 2006.

The series touches `builtin/rerere.c` most heavily, along with `rerere.h`, `rerere.c`, several callers in `apply.c` and other builtins, the test suite, and `Documentation/git-rerere.adoc`. It builds on the already-merged `ps/rerere-remove-global-state` topic. The commit messages are clear and the changes appear mechanical, suggesting a low-risk cleanup that completes the `the_repository` removal for this command and standardizes its CLI handling.
