This is a review reply from Junio C Hamano on the core patch (11/13) of Patrick Steinhardt's v5 series refactoring `git rerere` to use `OPT_SUBCOMMAND()`. Junio confirms that the intentional backwards-incompatible change -- rejecting `--[no-]rerere-autoupdate` for named subcommands like `diff` or `gc` -- is a good fix for a previously misleading interface.

He raises one usability concern: the help text describing the `--rerere-autoupdate` option is now hard to reach because `git rerere -h` displays the top-level usage listing all subcommands rather than the implicit "perform" subcommand's options. Users would need awkward workarounds like `git rerere -- -h` to see that description. Junio decides this is acceptable to leave as-is, reasoning that existing users of the flag already know it and others can use `git -c rerere.autoupdate=no rerere` instead.

He also notes a side effect on `--git-completion-helper`: the output now lists subcommand names (`clear diff forget gc remaining status`) instead of the autoupdate flags. He thinks the new output is arguably better but is unsure whether the bash completion script has workarounds for the old behavior that are now unnecessary. The email closes with thanks, signaling acceptance of the patch.
