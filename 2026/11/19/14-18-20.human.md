This is a bugfix -- specifically the first of three patches in Adrian Ratiu's v2 series addressing bugs in the `compatObjectFormat` interoperability layer, which handles object conversion between SHA-1 and SHA-256 repositories.

The patch fixes a crash that makes a repository completely unusable: when `extensions.compatObjectFormat` is set to the same hash algorithm as the repository's `objectFormat`, every Git command in a Rust-enabled build aborts with `BUG: repository.c:204: hash_algo and compat_hash_algo match`. Because even `git config` triggers the crash, the bad value cannot be removed through Git itself, forcing manual editing of `.git/config`. The author adds a guard in `verify_repository_format()` in `setup.c` that returns a clear error message -- spelling the key as `extensions.compatObjectFormat` -- before any Rust-specific code runs, so the same protection applies to non-Rust builds as well.

The fix is accompanied by a test in `t/t1302-repo-version.sh` that runs for both `sha1` and `sha256`, verifying that the misconfiguration produces the expected error and that unsetting the extension via `--file` (since in-repo `git config` is unavailable) restores functionality. The test uses modern `git config set`/`unset` syntax, reflecting feedback from Patrick Steinhardt on the earlier version.

This patch appears uncontroversial and well-crafted: the commit message clearly explains the failure mode and why the check belongs in `setup.c`, and the test is thorough without introducing new dependencies. It addresses a concrete footgun in the SHA-1/SHA-256 interoperability work, though the broader questions around the series -- particularly the handling of unknown commit headers in patch 3 -- remain open for discussion.
