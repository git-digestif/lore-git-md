This is a performance patch (second iteration of a standalone contribution) targeting the interaction between `git diff` and the fsmonitor daemon. Maik Riechert modifies `check_removed()` in `diff-lib.c` so that cache entries marked `CE_FSMONITOR_VALID` return immediately after `fake_lstat()` fills in the stat data, skipping the subsequent `has_symlink_leading_path()` call and the `S_ISDIR()` check. The argument is that these checks are redundant for fsmonitor-valid entries: if a leading directory had been replaced by a symlink, fsmonitor would have reported the change and `refresh_fsmonitor()` would have cleared the valid bit for everything beneath it, and `preload_index()` already trusts the flag in exactly this way.

The change builds on commit `4f3d6d0261`, which previously eliminated the `lstat()` of the file itself for valid entries, leaving only the expensive leading-path `lstat()` calls as overhead. With this patch, `git diff HEAD` on a Linux repository with 100,000 files drops from 57ms to 26ms when using a hook that reports no changes and the cache is warm. Three new tests in `t/t7519-status-fsmonitor.sh` cover the shortcut behavior and confirm that deletions are still detected when fsmonitor does report the directory, with and without a trailing slash.

This v2 simply addresses the one piece of feedback from the previous round: it drops the now-unnecessary `stat_err` variable and inlines the `lstat()` call directly into the `if` condition, as suggested by Junio C Hamano. The patch remains under review with no integration branch assignment indicated.
