This is a discussion reply confirming the withdrawal of a patch from an ongoing feature series. Jasper Mayone responds to Phillip Wood's review of v5 patch 4/5, the `%(currentworktree)` atom for `git for-each-ref`, explaining that the patch has been dropped from the series because it existed solely to support patch 5/5 (a `git branch` output cleanup), which Junio C Hamano objected to on the grounds that the "+" marker for bisected branches in long branch lists is useful. The series now terminates at patch 3/5.

Jasper acknowledges Phillip's substantive design suggestions for potential future revival: making the atom boolean like `%(HEAD)` (printing "*" when the ref is checked out in the current worktree) or extending `%(HEAD)` itself to cover branches that are rebasing or bisecting. He also notes Phillip's implementation concerns -- that a hashmap for a single entry is inefficient and that the atom could report inconsistent results versus `%(worktreepath)` when a branch is checked out in multiple worktrees -- will be kept in mind if the feature is revisited. The thread context indicates the remaining three patches address `git worktree remove` safety checks, `%(worktreepath)` documentation, and O(1) performance for the worktree path atom in `ref-filter.c` and `branch.c`, with the series considered ready for integration pending minor editorial nits.
