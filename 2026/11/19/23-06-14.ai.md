This is a brief maintainer acknowledgment within the v3 review of a bugfix series correcting hash algorithm detection in `setup.c` for Git v3 (`WITH_BREAKING_CHANGES=1`).

Junio C Hamano accepts brian m. carlstadt's clarification of the reinitialization semantics: a command-line `--object-format` that mismatches an existing repository's hash causes a fatal "attempt to reinitialize repository with different hash" error, whereas the `GIT_DEFAULT_HASH` environment variable and `init.defaultObjectFormat` config are silently ignored when reinitializing an existing repository. This closes one of the five open questions Junio had raised about the v3 commit message and code.

The thread remains under review with no approval yet. A v4 is still anticipated to address the remaining concerns: expanding the commit message to explain that `GIT_HASH_DEFAULT` initializes to `SHA1_LEGACY` (and is therefore not treated as an "unspecified" sentinel), rewriting the removed reinitialization-safety comment to distinguish CLI from config/env precedence, and fixing potential test isolation issues caused by `sane_unset GIT_DEFAULT_HASH` in `t/t0001-init.sh` without restoring the prior value.
