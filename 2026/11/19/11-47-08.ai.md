This is a refactoring patch, specifically the seventh in Patrick Steinhardt's thirteen-patch v5 series that modernizes `git rerere`'s subcommand handling by moving toward the standard `OPT_SUBCOMMAND()` mechanism. The patch extracts the "status" subcommand from the monolithic `cmd_rerere()` dispatcher into a dedicated static function `cmd_rerere_status()` in `builtin/rerere.c`, following the same pattern established by the preceding patches for "forget" (patch 5) and "clear" (patch 6).

The new `cmd_rerere_status()` accepts the standard `(argc, argv, prefix, repo)` signature and invokes `parse_options()` with an empty options array and the shared `rerere_usage` string, then rejects any extra positional arguments via `usage(_("too many arguments"))` before proceeding. It sets up the rerere cache with `rerere_cache_setup(&cache, repo, &merge_rr, RERERE_READONLY)`, iterates over the merge_rr string list to print each path, and then releases the cache and string list. The main `cmd_rerere()` now simply dispatches to this function when `argv[0]` equals "status".

Technically, the patch preserves the existing read-only behavior by continuing to pass only `RERERE_READONLY` to `rerere_cache_setup()`, consistent with the preparatory cleanup in patch 4 that established read-only subcommands should not receive autoupdate flags. The extraction itself introduces no functional change to the `git rerere status` output, though the new "too many arguments" check technically tightens validation compared to the previous inline implementation which silently ignored extra arguments -- a pattern also seen in patch 6's "clear" handler and worth noting for future reviewers assessing whether this validation tightening is intentional and consistent across subcommands.

This patch advances the series' incremental goal of giving each rerere subcommand its own proper handler function ahead of the eventual `OPT_SUBCOMMAND()` conversion in later patches. The v5 series itself supersedes a v4 that was previously merged to `master`, and this particular patch sits within that broader effort alongside related preparatory work including the `repo_rerere()` rename, `enum rerere_flags` conversion, and `the_repository` removal visible in earlier patches of the series.
