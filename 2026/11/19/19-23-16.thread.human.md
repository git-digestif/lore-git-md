Dominik Maier posted a security fix for a path-traversal vulnerability in `git filter-branch --state-branch`, where a malicious or corrupted state branch could write map entries outside the temporary directory via keys containing slashes or `..` segments. The patch hardens `git-filter-branch.sh` by validating that `from_commit` is non-empty lowercase hex and that `to_commit` contains only hex digits and spaces before writing to `../map/$from_commit`, with tests in `t/t7003-filter-branch.sh` covering traversal attempts.

Junio C Hamano reviewed the patch and confirmed the vulnerability, noting that an empty key like `:foo` previously caused a confusing "Is a directory" error inside the loop rather than a clean `die()`, while `../` keys could escape into the working tree. He approved the proposed validation logic and concluded with "Looks good. Thanks.", offering only one minor suggestion: the commit message should briefly explain why spaces are allowed in `to_commit`, since the `map()` function is intentionally used unquoted in constructs like `for reparent in $(map "$parent")` to expand one commit into multiple space-separated values. The thread remains open pending that small commit-message tweak, with no objections raised.
