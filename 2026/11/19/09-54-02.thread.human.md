Jordan Kadish has sent a standalone feature request to the Git mailing list proposing branch-aware `.gitignore` rules. The motivation is a workplace scenario where a file like `settings.py` is passed around manually because it intentionally differs from the `main` branch, and Jordan asks whether Git could ignore files conditionally based on the current branch name -- either as a whitelist (ignored everywhere except a named branch) or a blacklist (ignored only in a named branch). Mentioned use cases include Django migration files, local settings, and compiled binaries that must exist on main or staging but should stay out of local working trees.

The email is purely conceptual: there is no patch, no proposed syntax, and no implementation sketch, and no prior art or interaction with existing mechanisms like `.gitattributes` filters or hooks is discussed. Nothing has been decided or agreed yet; the thread is open for discussion, with likely points of contention including the performance cost of evaluating branch names during ignore matching, the complexity of extending `.gitignore` syntax, and whether branch-conditional behavior belongs in core ignore handling at all.
