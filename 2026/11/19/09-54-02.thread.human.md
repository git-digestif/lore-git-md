Jordan Kadish asked on the Git mailing list whether `.gitignore` could support branch-aware rules, describing a workplace where a `settings.py` is passed around manually because it intentionally differs from `main`. Two substantive responses have reframed the request away from core changes. Hsieh Chin Fan argued that branch-conditional rules in the tracked `.gitignore` would propagate through merges and make behavior hard to reason about across branches, and instead demonstrated a working alternative using `includeIf "onbranch:..."` in `.git/config` to set `core.excludesFile` to a local ignore file, which achieves the desired whitelist/blacklist behavior without touching the ignore engine. Ben Knoble added a lighter note that many teams already handle similar problems with the tracked-template-plus-local-override convention, such as an `.env.example` copied to a locally ignored `.env`.

The thread remains a conceptual feature request with no patch, no maintainer response, and no decision on whether the configuration-based approach or existing conventions fully cover the use cases Kadish described.
