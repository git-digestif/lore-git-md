This is patch 4/5 of a five-patch bugfix series (v3) addressing loose object size validation and `long`-versus-`size_t` truncation issues on LLP64 platforms. The patch is a one-line fix in `builtin/cat-file.c`: it changes the `len` parameter of `batch_write()` from `int` to `size_t`. The bug it fixes is cross-platform: when `git cat-file --batch` processes an object between 2 GiB and 4 GiB, the `int` parameter wraps negative, causing `fwrite()` and `write_or_die()` to interpret it as an enormous `size_t` and write past the end of the allocated buffer until an unmapped page triggers "write error: Bad address"; objects of 4 GiB or larger are silently truncated, desynchronizing the batch output stream. The trigger applies to any non-blob object or to blobs processed via `--filters` or `--textconv` (plain blobs are streamed rather than buffered). Both callees already accept `size_t`, so the change is type-safe. There is no automated test because reproducing requires several GiB of memory and disk; the commit message documents a manual reproduction using a 3 GiB zero-filled blob piped through `git cat-file --batch --filters`. Junio C Hamano previously approved this patch as "trivially correct"; the v3 commit message has been trimmed per his stylistic suggestion. This patch has received maintainer approval with no outstanding objections.
