This thread is a standalone security fix from Dominik Maier for the `git-cvsexportcommit.perl` contrib script. When the `-W` option is used, the script captures HEAD into a variable and later restores it through single-argument `system()` calls, which go through `/bin/sh -c` -- so a branch name containing shell metacharacters (Git allows names like `refs/heads/topic;false`) could execute arbitrary commands or corrupt the HEAD restoration. The patch converts the affected `system()` calls to list form, adds a `chomp` on the backtick-captured value, and hardens the final checkout with `--end-of-options` and `--` against option injection. A regression test in `t/t9200-git-cvsexportcommit.sh` creates a branch literally named `topic;false` and verifies HEAD survives a `-W` export-commit run.

Junio C Hamano reviewed the patch and gave it an explicit approval ("Looks good. Thanks."). He confirmed the list-form conversion is trivially correct and the right principle, validated that the commit argument is already safe via `git rev-parse --verify`, agreed with placing the `chomp` early to cleanse externally-obtained data, and endorsed the `--end-of-options` hardening. With the maintainer's approval on record and no objections raised, the patch appears ready to be picked up, though no integration branch status has been announced yet.
