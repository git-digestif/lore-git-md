This is a **bugfix patch** addressing a misleading progress message in `git fsck --verbose`. The author, Aniket Gupta, acknowledges the feedback from Laveesh Bansal about the edge case in partial clones, where the reported object count includes blobs that were never downloaded (and thus not "checked" in the strict sense). While the patch itself remains unchanged, Aniket proposes refining the commit title to better reflect the behavior—suggesting "report the number of objects in the connectivity message" instead of "real object count" or "objects checked."

The discussion clarifies that the message reports the number of objects *referenced* during connectivity checks, not necessarily those present or verified. This distinction is subtle but important for users of partial clones, where the count may still feel misleading. Aniket is open to sending a v2 with an updated title if Junio requests it, but no code changes are planned. The patch itself is straightforward, well-tested, and addresses the core issue (replacing the hash bucket count with the actual object count). The edge case is noted but not considered a blocker.
