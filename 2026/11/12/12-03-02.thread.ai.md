This is Yoichi NAKAYAMA's v2 patch series, "[PATCH v2 0/3] worktree-specific submodule configuration", now complete with patches 1/3, 2/3, and 3/3 posted; it remains under review with no prior merged version and no graduation to any integration branch reported. The goal is to teach Git to store per-worktree submodule settings in the worktree-specific config file (`config.worktree`) when `extensions.worktreeConfig` is enabled, especially storing `submodule.<name>.gitdir` as a relative path such as `../.git/worktrees/wt/modules/sub1` in linked worktrees so the setting survives worktree moves. Patch 1/3 changes `create_default_gitdir_config()` in `builtin/submodule--helper.c` to make the gitdir relative, adds `get_current_worktree()`, updates the fallback error message to print `modules_dir` before the submodule name, and adds the `t/t2405-worktree-submodule.sh` case "git submodule init make gitdir relative" asserting `submodule.sub1.gitdir` and `submodule.sub2.gitdir` equal `../.git/worktrees/wt/modules/sub1` and `../.git/worktrees/wt/modules/sub2`. Patch 2/3 routes submodule config writes for `git submodule update --init`, `add`, `sync`, and `deinit` into `config.worktree`, has deinit set `active=false` there, and ensures `git worktree add` does not copy gitdir settings into the new worktree; tests verify `active`, `url`, and `gitdir` land in `config.worktree`. Patch 3/3 covers `git submodule init` via the renamed helper `submodule_git_dir_matches_current_worktree()` and the new warning string `submodule_mismatch_warning`; `t/t7425-submodule-gitdir-path-extension.sh` checks that in the main worktree enabling worktree config and running init copies existing repository-config gitdir values into `config.worktree`, while in a linked worktree init warns that the existing value does not point to a gitdir for the current worktree and writes the expected relative path, with extra coverage for absolute paths from older Git versions and custom gitdir names. Files touched are `builtin/submodule--helper.c`, `builtin/worktree.c`, and `Documentation/config/submodule.adoc`; behavior is gated by `the_repository->repository_format_worktree_config`, and there are no on-disk format changes.

Junio C Hamano has now reviewed all three patches substantively. On 1/3 he confirmed the v2 fixes for the else-branch leak and early-return strbuf leaks but asked that a static-buffer lifetime hazard in `create_default_gitdir_config()` be closed by unconditionally duplicating `worktree_git_path()` results with `xstrdup` and freeing them under the cleanup label, because `modules_dir` may point into the four-slot ring buffer and `relative_path()` may return a pointer directly into that buffer; he also noted patch 3's multiple calls to `worktree_git_path(wt, "config.worktree")` could wrap that ring buffer across failure cases. On 2/3 he identified that `is_submodule_active()` is called with `sub->name` instead of the submodule path in both initialization and deinitialization, which is wrong when name and path diverge and needs test coverage in `t/t2405-worktree-submodule.sh`, and that `copy_filtered_worktree_config()` in `builtin/worktree.c` uses `repo_config_set_in_file_gently()` when unsetting gitdir entries during `git worktree add`, which fails to remove duplicate entries; he recommends `repo_config_set_multivar_in_file_gently()` with `CONFIG_FLAGS_MULTI_REPLACE`. He also asked whether `Documentation/config/submodule.adoc` should explain how the various `submodule.<name>.*` keys interact with `extensions.worktreeConfig`, since the docs currently mention only `gitdir`.

In the new review of 3/3, Junio endorses the direction, saying the transition to `extensions.worktreeConfig` is safer with the new warning and that the main-worktree and linked-worktree migration test coverage looks solid, but flags a canonicalization mismatch in `submodule_git_dir_matches_current_worktree()`: `repo_worktree_path_append()` resolves `the_repository->worktree` through `real_pathdup()` during repository setup, while `absolute_pathdup(repo_get_git_dir(the_repository))` relies on `PWD`/`getcwd()` for a relative gitdir or copies an explicit absolute `GIT_DIR` verbatim, without resolving symlinks or normalizing `.`/`..`; examples such as `GIT_DIR=.git git submodule init` from a symlinked directory or `GIT_DIR=.git/../.git` can make the `super` and `submodule` buffers diverge, causing a false mismatch warning and regenerating a gitdir instead of copying a valid existing one. He suggests canonicalizing both sides with `real_pathdup(repo_get_git_dir(the_repository), 1)` for `super` and `strbuf_realpath_forgiving()` for `submodule`, accepting uglier absolute paths in exchange for a robust comparison.

Open items remain: close the static-buffer hazard in patch 1/3 as above; fix the `is_submodule_active()` name-versus-path bug in patch 2/3 and add name/path-divergence tests; switch `copy_filtered_worktree_config()` to the multivar replace API so duplicate gitdir entries are cleared; document the broader `submodule.<name>.*` interaction with `extensions.worktreeConfig`; and canonicalize both paths in `submodule_git_dir_matches_current_worktree()` per Junio's 3/3 suggestion. No other participants have weighed in, and interaction with existing submodule workflows across multiple worktrees, the exact warning behavior, and the error-message guidance are still not independently validated. Related work is the existing `extensions.worktreeConfig` mechanism plus worktree path utilities `worktree_git_path()` and `relative_path()`.
