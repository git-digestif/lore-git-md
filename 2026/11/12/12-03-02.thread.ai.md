Thread identity: Subject "[PATCH v2 0/3] worktree-specific submodule configuration", series version v2, originating author Yoichi NAKAYAMA, thread type patch series. All three patches have now been posted: 1/3 details the relative-gitdir-path change in `create_default_gitdir_config()`, 2/3 routes submodule config writes into the worktree-specific config file, and 3/3 covers `git submodule init` handling via `submodule_git_dir_matches_current_worktree()`.

Core problem or goal: Teach Git to store submodule settings that vary between worktrees in the worktree-specific config file (`config.worktree`) when `extensions.worktreeConfig` is enabled, and specifically to store `submodule.<name>.gitdir` as a relative path (e.g. `../.git/worktrees/wt/modules/sub1`) for linked worktrees so the setting survives worktree moves.

Current status: Under review; v2 complete with patches 1/3, 2/3, and 3/3 posted. No prior merged versions. Junio C Hamano has reviewed patches 1/3 and 2/3, raising substantive concerns in both: a static-buffer lifetime hazard in patch 1/3's `create_default_gitdir_config()` and, in patch 2/3, an incorrect call to `is_submodule_active()` with the submodule name instead of its path plus a failure to remove duplicate gitdir entries in `copy_filtered_worktree_config()`.

Key technical details: Files touched: `builtin/submodule--helper.c`, `builtin/worktree.c`, `Documentation/config/submodule.adoc`. New tests: `t/t2405-worktree-submodule.sh`, `t/t7425-submodule-gitdir-path-extension.sh`. Patch 1 adds test case "git submodule init make gitdir relative" asserting `submodule.sub1.gitdir` and `submodule.sub2.gitdir` equal `../.git/worktrees/wt/modules/sub1` and `../.git/worktrees/wt/modules/sub2`. Patch 2 tests verify that `submodule update --init`, `submodule add`, `submodule sync`, and `submodule deinit` write `active`, `url`, and `gitdir` to `config.worktree`, that deinit sets `active=false` there, and that `git worktree add` does not copy gitdir settings into the new worktree. Patch 3 tests in `t/t7425-submodule-gitdir-path-extension.sh` verify that in the main worktree, enabling worktree config and running `git submodule init` copies existing repository-config gitdir values into `config.worktree`, while in a linked worktree the command warns that the existing value does not point to a gitdir for the current worktree and instead writes the expected relative path; additional assertions cover absolute paths written by older Git versions and custom non-default gitdir names to ensure they are preserved when they match and regenerated when they do not. New helpers: `get_current_worktree()` (patch 1) and `submodule_git_dir_matches_current_worktree()` (patch 3, renamed from `validate_submodule_git_dir_with_worktree()` in v1). Warning string `submodule_mismatch_warning` fires in `git submodule init` when a repository-config gitdir belongs to a different worktree. Patch 1 updates the fallback error message to print `modules_dir` before the submodule name in the suggested `git config` command. Worktree-config behavior is gated by `the_repository->repository_format_worktree_config` checks. No on-disk format changes. Junio's patch 2/3 review identifies that `is_submodule_active()` expects a path but receives `sub->name`, and that `copy_filtered_worktree_config()` in `builtin/worktree.c` must use `repo_config_set_multivar_in_file_gently()` with `CONFIG_FLAGS_MULTI_REPLACE` rather than `repo_config_set_in_file_gently()` to clear all duplicate gitdir entries.

Open questions and loose ends: Junio C Hamano identified a static-buffer lifetime hazard in `create_default_gitdir_config()` where `modules_dir` may point into the four-slot ring buffer returned by `worktree_git_path()`, and `relative_path()` can return a pointer directly into that buffer when the worktree path is a directory prefix of the modules path without populating the temporary strbuf; he suggests unconditionally copying the result with `xstrdup` and freeing it under the cleanup label rather than conditionally relying on the strbuf, and notes that patch 3's calls to `worktree_git_path(wt, "config.worktree")` could wrap that ring buffer across multiple failure cases. In patch 2/3, `is_submodule_active()` is called with `sub->name` instead of the submodule path in both initialization and deinitialization paths, which produces wrong behavior when a submodule's name differs from its path; test coverage for this name/path divergence is suggested in `t/t2405-worktree-submodule.sh`. Also in patch 2/3, `copy_filtered_worktree_config()` uses `repo_config_set_in_file_gently()` to unset gitdir entries during `git worktree add`, which fails to remove duplicate entries when the source config contains multiple gitdir lines for the same submodule; switching to `repo_config_set_multivar_in_file_gently()` with `CONFIG_FLAGS_MULTI_REPLACE` is recommended. Junio also asks whether `Documentation/config/submodule.adoc` should explain how the various `submodule.<name>.*` keys interact with `extensions.worktreeConfig`, since the patch touches several keys but the documentation update only mentions `gitdir`. Interaction with existing submodule workflows (e.g. `git submodule update --init`) across multiple worktrees not yet reviewed; error message guidance and `submodule_mismatch_warning` behavior not yet validated by reviewers.
