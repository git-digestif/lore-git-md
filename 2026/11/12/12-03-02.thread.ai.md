Subject: [PATCH 0/3] worktree-specific submodule configuration

Originating author: Yoichi NAKAYAMA

Core problem or goal
Teach Git to store submodule settings that vary between worktrees in the worktree-specific config file when `extensions.worktreeConfig` is enabled. Currently, submodule paths and other settings are stored in the main repository config, forcing users with multiple worktrees to either accept a one-size-fits-all configuration or manually manage per-worktree overrides.

Current status
Under review; v1 posted. No prior versions. All three patches (submodule gitdir path relativization, core worktree-specific submodule config logic, and `git submodule init` adjustments) have received initial implementation feedback but no substantive review yet. No objections or requests for changes raised.

Key technical details
- Files touched: `builtin/submodule--helper.c`, `builtin/worktree.c`, `Documentation/config/submodule.adoc`
- New test files: `t/t2405-worktree-submodule.sh`, `t/t7425-submodule-gitdir-path-extension.sh`
- New behavior: when `extensions.worktreeConfig` is enabled, submodule settings (`submodule.<name>.active`, `submodule.<name>.url`, etc.) are written to the worktree config instead of the main repository config
- New helpers: `get_current_worktree()` in `builtin/submodule--helper.c` (Patch 1) and `validate_submodule_git_dir_with_worktree()` (Patch 3) to compute the current worktree path and validate gitdir relevance
- Edge case handling:
  - Patch 1 ensures `submodule.<name>.gitdir` remains relative for linked worktrees (using `worktree_git_path()` and `relative_path()`) to prevent absolute path leakage; error message updated to suggest the correct relative path format (`../.git/worktrees/wt/modules/sub1`)
  - Patch 2 modifies `repo_config_set_worktree_gently()` to store submodule settings in worktree config, updates `git submodule deinit` to set `submodule.<name>.active=false` in worktree config (preserving shared settings), and excludes `submodule.<name>.gitdir` from being copied to new worktrees via `copy_filtered_worktree_config()`
  - Patch 3 adjusts `git submodule init` to copy existing `submodule.<name>.gitdir` settings from the repository config to the worktree config only if they belong to the current worktree (checked via `validate_submodule_git_dir_with_worktree()`); otherwise, generates a new worktree-specific setting
- No on-disk format changes; the change is purely in config file selection logic, path relativization, and submodule initialization behavior
