Thread identity: Subject "[PATCH v2 0/3] worktree-specific submodule configuration", series version v2, originating author Yoichi NAKAYAMA, thread type patch series. Patches 1/3 and 2/3 have been posted individually; patch 1/3 details the relative-gitdir-path change in `create_default_gitdir_config()`, and patch 2/3 routes submodule config writes into the worktree-specific config file.

Core problem or goal: Teach Git to store submodule settings that vary between worktrees in the worktree-specific config file (`config.worktree`) when `extensions.worktreeConfig` is enabled, and specifically to store `submodule.<name>.gitdir` as a relative path (e.g. `../.git/worktrees/wt/modules/sub1`) for linked worktrees so the setting survives worktree moves.

Current status: Under review; v2 posted. No prior merged versions. Patch 1/3 modifies `builtin/submodule--helper.c` to use `get_current_worktree()` and `worktree_git_path()` + `relative_path()` for linked worktrees, with the v2 static-buffer lifetime fix (copying `worktree_git_path()` result into a local `strbuf` immediately). Patch 2/3 switches submodule config writes from `repo_config_set_gently()` to `repo_config_set_worktree_gently()` in `init_submodule()` (for `submodule.<name>.active`, `.url`, `.update`), `sync_submodule()` (for `.url`), `configure_added_submodule()` (for `.url`, `.active`), and `validate_and_set_submodule_gitdir()` (for `.gitdir`); `deinit_submodule()` targets `config.worktree` when worktree config is active (otherwise `config`) and sets `submodule.<name>.active` to `false` there; `copy_filtered_worktree_config()` in `builtin/worktree.c` strips `submodule.<name>.gitdir` entries when copying config to a new linked worktree. Patch 3/3 covers `git submodule init` handling via `submodule_git_dir_matches_current_worktree()`.

Key technical details: Files touched: `builtin/submodule--helper.c`, `builtin/worktree.c`, `Documentation/config/submodule.adoc`. New tests: `t/t2405-worktree-submodule.sh`, `t/t7425-submodule-gitdir-path-extension.sh`. Patch 1 adds test case "git submodule init make gitdir relative" asserting `submodule.sub1.gitdir` and `submodule.sub2.gitdir` equal `../.git/worktrees/wt/modules/sub1` and `../.git/worktrees/wt/modules/sub2`. Patch 2 tests verify that `submodule update --init`, `submodule add`, `submodule sync`, and `submodule deinit` write `active`, `url`, and `gitdir` to `config.worktree`, that deinit sets `active=false` there, and that `git worktree add` does not copy gitdir settings into the new worktree. New helpers: `get_current_worktree()` (patch 1) and `submodule_git_dir_matches_current_worktree()` (patch 3, renamed from `validate_submodule_git_dir_with_worktree()` in v1). Warning string `submodule_mismatch_warning` fires in `git submodule init` when a repository-config gitdir belongs to a different worktree.
