This is a **bugfix** for a performance regression in `` `git log --follow` ``. The patch introduces a new `--follow=merges` option (and matching `log.follow=merges` config) to restore the pre-regression behavior while keeping the improved rename-following logic opt-in.

The regression was introduced in 304812ed33 (June 2026), which made `` `git log --stat --follow` `` on a single file in linux.git take **6m43s** instead of the previous **28s**. The slowdown comes from diffing each merge against *all* parents with rename detection enabled, even when the path was only added relative to one parent. The new `--follow=merges` mode restores the old behavior by default and makes the expensive per-parent diffing opt-in.

The patch is **well-motivated and narrowly scoped**: it adds a single configuration knob, updates the documentation, and includes thorough test coverage for both the new option and its interaction with the existing `log.follow` config. The implementation is clean, with no obvious red flags in the diff. Junio and Patrick Steinhardt (who suggested the approach) are both supportive, so this looks likely to land soon. If you care about `` `git log --follow` `` performance, this is worth watching.
