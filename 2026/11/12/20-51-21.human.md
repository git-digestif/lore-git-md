This is a bugfix discussion targeting the diff subsystem, specifically the userdiff patterns that identify function names in context headers.

Junio C Hamano replies to Ulrich Windl’s report about `git diff` failing to show shell function names in multi-line definitions. The exchange clarifies that the issue is not a regression—Git 2.51.0 behaves the same as current versions—but rather a long-standing limitation in how Git’s diff algorithm determines function context. Junio explains that the line continuation (`\`) causes the diff engine to treat the `_COUNT=...` line as the start of a new context, overriding the earlier `run_query()` line. This happens because the default userdiff pattern for shell scripts (and unknown file types) simply looks for any non-whitespace line, without accounting for line continuations or multi-line function definitions.

The discussion is still in the diagnostic phase; no patch has been proposed yet. Junio’s analysis suggests the fix would involve updating the shell-script userdiff pattern to recognize multi-line function definitions, but he does not indicate whether this is a priority or how complex the change might be. The thread remains open, with the core question being whether Git should support this edge case at all. For now, this is a low-urgency but clearly reproducible issue that affects shell script diffs.
