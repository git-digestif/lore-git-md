This is a **bugfix** discussion targeting the diff subsystem's context header logic for shell scripts. Junio C Hamano replies to Ulrich Windl's bug report about `git diff` failing to correctly identify shell function names in multi-line definitions.

Junio confirms the issue is reproducible in current Git and explains the root cause: the diff algorithm's userdiff pattern for shell scripts does not look ahead to associate subsequent lines with the original function definition when a line continuation (`\`) splits the definition. Instead, the algorithm treats the continuation line (beginning with `_COUNT=`) as a new context header candidate, overriding the earlier `run_query()` line. This behavior stems from Git's default fallback pattern for unknown file types, which picks any non-whitespace line as a potential function header.

The discussion clarifies that the problem is not a regression—it has existed since at least Git 2.51—and is specific to shell scripts (or files without explicit language suffixes). No patch is proposed yet, but Junio's analysis identifies the userdiff pattern logic as the subsystem to modify.
