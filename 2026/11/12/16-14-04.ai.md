This is a performance patch targeting memory usage in the commit subsystem.

The patch removes padding from `struct commit` on 64-bit platforms by reordering its fields. Currently, the struct is 80 bytes with 8 bytes of padding (4 between `.object` and `.date`, and 4 tail padding). By moving the `index` field into the gap after `.object`, the struct shrinks to 72 bytes, eliminating all padding. This yields a 10% memory reduction per commit with no behavioral change. On platforms with 4-byte alignment for 8-byte members (e.g., i386), the size remains unchanged.

The author measured peak RSS for `git rev-list --all` on an internal monorepo with ~4.5 million commits, showing a ~32 MiB reduction (from ~849 MiB to ~817 MiB), closely matching the expected 8 bytes × 4.5M commits (~34 MiB). Runtime remained within noise.

The commit message notes this optimization was discovered via `gdb`'s `ptype /o` while investigating an unrelated commit-walk change. Historical context is provided: the struct's size and padding have fluctuated over time, sometimes undoing prior optimizations. The author prototyped a regression test to verify struct sizes but omitted it, questioning its maintainability and suitability for a unit test. They offer to submit it as a follow-up if there’s interest.

The patch itself is minimal: a single-line change in `commit.h`, moving `unsigned int index` from the end of the struct to immediately after `struct object`. The base commit is `1891de46f79dc444a47db1c87bd0c8c76b5463f2`.
