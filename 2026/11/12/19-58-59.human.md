This is a bugfix series targeting the promisor-remote protocol v2 capability. The issue is straightforward: when fetching objects, the Git client fails to send a `promisor-remote=...` reply to the server, which means servers that handle each request independently (like HTTP or JGit-based servers such as Gerrit) don’t know the client accepted a promisor remote. This causes the server to reject fetches where objects are missing from the main pack but available on the promisor remote, with an error like "could not fetch <oid> from promisor remote."

The bug has been present since the capability was introduced in Git v2.49, so the series is marked for `maint` as well as the next feature release. Christian Couder discovered the issue during a hackathon following the Gerrit User Summit 2026, and this is the most pressing of several related problems found there.

The series is small and focused: patch 1 prepares the plumbing by letting `write_command_and_capabilities()` send the promisor-remote reply without changing behavior; patch 2 is the actual fix, ensuring the reply is sent during fetch, and adds tests in both the existing `t5710` and a new `t5711` script for HTTP scenarios; patch 3 updates the protocol documentation to reflect the requirement. The tests look thorough, covering both direct and HTTP-based fetches, and the commit messages are clear about the motivation and scope.

CI failures are noted but appear unrelated to the patch itself, likely stemming from test infrastructure issues. The series is well-structured and addresses a real, user-facing problem that affects interoperability with Gerrit and other non-Git servers. It looks like a solid candidate for merging.
