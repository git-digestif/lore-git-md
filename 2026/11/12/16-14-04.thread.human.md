This thread is about a small but impactful performance optimization to reduce Git's memory usage. Kristofer Karlsson posted a patch (now at v2) that reorders fields in `struct commit` to eliminate padding on 64-bit platforms, shrinking the struct from 80 to 72 bytes—a 10% reduction with no behavioral change. The patch is minimal: it moves the `index` field after `struct object` in `commit.h` and adds explanatory comments for `index` and `date` to address maintainer feedback.

The patch has received positive reviews. Derrick Stolee called it "obviously correct" and confirmed the memory savings, while Junio C Hamano's feedback on code clarity has been incorporated in v2. The author has also explored ways to enforce awareness of struct bloat going forward, such as a compile-time assertion (`BUILD_ASSERT_OR_ZERO`) to ensure `struct object` remains first, though this isn't part of the current patch. The only open question is whether to add a regression test for struct size, but the author has deferred this to a follow-up if requested.

The patch is ready for maintainer pickup unless further discussion emerges on the proposed enforcement mechanisms. No technical objections remain, and the memory savings have been measured in practice: a 32 MiB reduction in peak RSS for `git rev-list --all` on a 4.5-million-commit repository.
