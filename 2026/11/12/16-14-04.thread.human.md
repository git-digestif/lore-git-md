This thread is about a small but impactful performance patch from Kristofer Karlsson that reduces memory usage in Git’s commit subsystem. The patch reorders fields in `struct commit` to eliminate padding on 64-bit platforms, shrinking the struct from 80 to 72 bytes—a 10% reduction—without changing behavior. The author measured a 32 MiB RSS reduction for `git rev-list --all` on a large repository, and Derrick Stolee reviewed it as "obviously correct."

Junio C Hamano, the maintainer, has now weighed in with cautious approval. While he endorses the memory savings, he raises two broader points: first, that the existing comment warning about struct bloat hasn’t been effective in preventing growth, and second, that reordering fields by size (rather than logical grouping) might obscure the design intent. He suggests adding comments to clarify the purpose of the `index` and `date` fields, whose roles aren’t immediately obvious. The patch itself remains uncontroversial and ready for integration, though the discussion about whether to add a regression test for struct size is still open. No objections have been raised, and the change is likely to be picked up soon.
