This thread is about a performance optimization to reduce memory usage in Git's commit subsystem. Kristofer Karlsson authored a patch that reorders fields in `struct commit` to eliminate padding on 64-bit platforms, shrinking the struct from 80 to 72 bytes—a 10% reduction—with no behavioral changes. The patch has evolved through three versions, with the latest refining comments to clarify safe casting directions, the purpose of the `index` field, and the source of the `date` field.

Key participants include Derrick Stolee, who endorsed the change as "obviously correct," and Junio C Hamano, the maintainer, who provided feedback on comment clarity and has signaled intent to merge the patch to the `next` branch. Oswald Buddenhagen contributed to a broader discussion about enforcing struct bloat awareness, suggesting architecture-specific dummy members as a pragmatic alternative to compile-time assertions. All prior feedback has been addressed, and the patch is now ready for integration, with measurements showing a ~32 MiB peak RSS reduction in a large repository.

The only remaining loose end is whether to include a regression test for struct size, which the author deferred to a follow-up if requested. The broader discussion about struct bloat enforcement remains open but doesn’t block this change.
