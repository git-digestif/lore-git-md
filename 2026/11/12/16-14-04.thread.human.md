This thread is about a performance optimization to reduce memory usage in Git’s commit subsystem. Kristofer Karlsson proposed reordering fields in `struct commit` to eliminate padding on 64-bit platforms, shrinking the struct from 80 to 72 bytes—a 10% reduction—without any behavioral change. The patch is now in its second version, addressing Junio C Hamano’s feedback by adding explanatory comments for the `index` and `date` fields.

The change is minimal: a one-line reordering in `commit.h` plus added comments. Derrick Stolee endorsed the patch as "obviously correct," and Junio’s feedback has been fully incorporated. The author measured a 32 MiB reduction in peak RSS for `git rev-list --all` on a 4.5-million-commit monorepo, matching the expected savings. No technical objections remain, and the patch is ready for maintainer pickup.

The only open discussion is about how to enforce awareness of struct bloat going forward. The author proposed a compile-time assertion (`BUILD_ASSERT_OR_ZERO`) to enforce the `struct object`-first invariant but noted its inflexibility. Alternatives like regression tests or scoped `-Wpadded` warnings were also mentioned, but no consensus has emerged. For now, the patch stands as a safe, self-contained improvement.
