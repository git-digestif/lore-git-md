This is the documentation patch (3/3) in Christian Couder’s three-part bugfix series for the promisor-remote protocol v2 capability. The series addresses a long-standing issue where the Git client fails to send the `promisor-remote=...` reply during `fetch` commands, breaking interactions with stateless servers like those using HTTP or JGit/Gerrit.

This patch updates `Documentation/gitprotocol-v2.adoc` to explicitly state that the client must send the `promisor-remote` reply with the `fetch` command, even if it was already sent with earlier commands like `ls-refs`. The change is motivated by the stateless nature of protocol v2, where servers may not retain information between requests. The commit message references the earlier patches in the series (1/3 and 2/3) that implement the actual behavior change, making this a straightforward documentation follow-up.

The patch is minimal and focused, touching only the protocol documentation. It adds six lines to clarify the expected behavior, including a note about scenarios where `ls-refs` might not be sent at all (e.g., when fetching only specific object IDs). The change aligns with the series’ goal of ensuring compatibility with servers that handle each request independently, and it reflects the technical fix already implemented in the earlier patches.
