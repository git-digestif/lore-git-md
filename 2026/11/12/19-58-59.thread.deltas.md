## 2026/11/12

- [2026/11/12/19-58-59 by Christian Couder <christian.couder@gmail.com>] Christian Couder posted a 3-patch series fixing the "promisor-remote" protocol v2 bug where the client omits the `promisor-remote=...` reply from `fetch` commands, causing failures with stateless servers (HTTP, JGit/Gerrit) and when fetching only object IDs.
- [2026/11/12/19-59-00 by Christian Couder <christian.couder@gmail.com>] Patch 1/3 adds a `promisor_remote_reply` parameter to `write_command_and_capabilities()` so it can write a `promisor-remote=...` capability when the argument is non-NULL; all current callers pass NULL, so there is no behavior change yet.
- [2026/11/12/19-59-01 by Christian Couder <christian.couder@gmail.com>] Patch 2/3 makes `do_fetch_pack_v2()` pass the accepted promisor remote to `send_fetch_request()` so `fetch` requests include the `promisor-remote=...` reply, and adds tests in t5710 plus a new t5711 HTTP test script.
- [2026/11/12/19-59-02 by Christian Couder <christian.couder@gmail.com>] Patch 3/3 updates `gitprotocol-v2.adoc` to document that clients must send the `promisor-remote` reply with the `fetch` command request because protocol v2 is stateless.
- [2026/11/12/22-18-07 by Junio C Hamano <gitster@pobox.com>] Junio C Hamano objected to Patch 1/3's API design, saying a dedicated `promisor_remote_reply` parameter contaminates the generic `write_command_and_capabilities()` interface and asking whether the `promisor-remote=...` string could instead be sent through the existing server_options list.
- [2026/11/12/22-34-38 by Junio C Hamano <gitster@pobox.com>] Junio C Hamano clarified that he suggests generalizing the server_options string list to hold elements with keys other than "server-option" (such as "promisor-remote") rather than using a separate hardcoded fourth parameter.

## 2026/11/13

- [2026/11/13/13-10-57 by Christian Couder <christian.couder@gmail.com>] Christian Couder explained that cleaning up the capability-sending API would need a significant refactor because three separate places in "connect.c" write the client's protocol v2 capabilities—send_capabilities() for `bundle-uri`, get_remote_refs() for `ls-refs`, and write_command_and_capabilities() for `fetch` and `object-info`—duplicating code for "server-option", "agent" and "object-format"; he noted the server side already has a generic capabilities table in "serve.c" and the client could have something similar, agreed to work on such a refactoring but proposed it as a separate series from this bug fix (which might go to maint), and offered to send a v2 with a NEEDSWORK comment on write_command_and_capabilities() proposing it be refactored with send_capabilities() and get_remote_refs() so callers build the full capability list, removing the `promisor_remote_reply` parameter.
- [2026/11/13/19-11-54 by Junio C Hamano <gitster@pobox.com>] Junio C Hamano replied that the duplicated code is all the more reason to clean it up before piling more on top, and questioned whether it deserved to be called "significant" refactoring, suggesting it would not take a large series.
