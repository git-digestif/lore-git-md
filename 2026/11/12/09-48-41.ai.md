This is a bugfix targeting the ref-filter subsystem, specifically addressing a double-free crash in `git for-each-ref` when processing refs pointing to missing objects.

The patch fixes a regression introduced in v2.53.0 by commit a29e2e8fe ("ref-filter: parse objects on demand", 2025-10-23) and later exacerbated by bea37f1d6 ("ref-filter: fix stale parsed objects", 2025-11-04). The issue occurs when `get_object()` frees `oi->content` but fails to reset the pointer, leaving it dangling. If a subsequent ref lookup fails before overwriting the pointer, the cleanup path attempts to free the already-freed buffer again, triggering a double-free abort. The fix is minimal: reset `oi->content` to `NULL` at the start of `get_object()`, mirroring the existing reset of `maybe_object`.

The commit message is clear and well-structured, explaining the bug's origin, reproduction scenario, and fix rationale. It includes a regression test that verifies the fix by creating a repository with an annotated tag followed by a ref pointing to a missing object—this ordering ensures the double-free condition is triggered. The test checks both the correct output (the annotated tag's object) and the proper error message for the missing object.

The patch is based on the `maint` branch, as the bug first appeared in v2.53.0 and affects production environments (GitLab.com encountered this issue in the wild). The change is isolated to `ref-filter.c` and the test suite, with no broader implications for other subsystems. The fix itself is straightforward and aligns with existing patterns in the codebase.
