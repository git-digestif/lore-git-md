Thread identity: Subject: [PATCH v2 0/8] promisor-remote: fix protocol v2 capability reply for fetch; Series version: v2 (8 patches, expanded from v1's 3); Originating author: Christian Couder; Thread type: bugfix patch series with preparatory refactoring.

Core problem or goal: The Git client omits the `promisor-remote=...` reply during `fetch` protocol v2 commands, breaking interactions with stateless servers (Git over HTTP, JGit/Gerrit) that handle each request independently. The bug has existed since the capability was introduced in Git v2.49 and causes fetch failures when objects are only available on promisor remotes. Reported-by: Matt Cote <mcote@nvidia.com>.

Current status: Under review; v2 submitted. The series has grown from 3 to 8 patches to address the maintainer's design objection to v1. Christian Couder has clarified in a follow-up reply that the refactoring Junio requested is already included in v2 itself, not deferred: patches 1-6 unify the client-side capability-writing path and delete `send_capabilities()`, rather than layering the fix on top of duplicated logic. Patch 6/8 completes the unification by routing `bundle-uri` requests through `write_command_and_capabilities()` and deleting the now-unused `send_capabilities()` function, leaving `write_command_and_capabilities()` as the single function responsible for emitting capability lines across `ls-refs`, `bundle-uri`, and `fetch`. Patch 8/8 updates `Documentation/gitprotocol-v2.adoc` to document that clients must send the `promisor-remote=...` reply with every pack-requesting `fetch` command (protocol v2 being stateless), while negotiation-only requests (e.g. `git fetch --negotiate-only`) and object-ID-only fetches that skip `ls-refs` have specific handling requirements.

Key technical details: Files touched: `connect.c`, `connect.h`, `fetch-pack.c`, `fetch-object-info.c`, `Documentation/gitprotocol-v2.adoc`, `t/meson.build`. New helpers introduced: `add_server_options()` and `add_promisor_remote_reply()` for building capability strvecs. `write_command_and_capabilities()` signature changed to accept `const struct strvec *capabilities` (patch 1/8) and subsequently a `struct packet_reader *reader` parameter (patch 3/8); it extracts the key portion (up to `=`) of each line to call `ensure_server_supports_v2()` before writing the full line, and when `reader` is non-NULL sets `reader->hash_algo` from the server's `object-format` capability (defaulting to SHA-1). Patch 6/8 specifics: `get_remote_bundle_uri()` in `connect.c` now builds a `struct strvec capabilities` using `add_promisor_remote_reply()` and passes it with `"bundle-uri"` to `write_command_and_capabilities()` instead of calling `send_capabilities()`; `send_capabilities()` is deleted entirely (44 lines removed, 5 added) as it has no remaining callers. Wire-level changes for `bundle-uri`: the `command=bundle-uri` line now appears first in the request instead of last, `promisor-remote` capability precedes `object-format`, and the command line no longer ends with a newline; no `server-option` capability is sent with the `bundle-uri` request. Patch 5/8 specifics: `get_remote_refs()` uses `write_command_and_capabilities()` with a strvec built by `add_server_options()` and `add_promisor_remote_reply()`; wire-level changes are reordered capability lines and removal of the trailing newline after `command=ls-refs`. Patch 4/8 specifics: `send_capabilities()` (now deleted in patch 6/8) previously took `struct strbuf *req_buf` instead of `int fd_out`. Patch 2/8 specifics: session-id advertisement extended to `ls-refs` and `bundle-uri` via `transfer.advertiseSID`. Patch 7/8 (the core bugfix): `do_fetch_pack_v2()` in `fetch-pack.c` now constructs a `struct strvec capabilities` once using `add_server_options()` and `add_promisor_remote_reply()`, then passes it to `send_fetch_request()`, whose signature gains a `const struct strvec *capabilities` parameter and forwards it to `write_command_and_capabilities()`; the previous call to `promisor_remote_reply()` in `do_fetch_pack_v2()` is removed, ensuring the `promisor-remote=...` reply is sent with every pack-requesting `fetch`. Patch 8/8 specifics: adds seven lines to `Documentation/gitprotocol-v2.adoc` clarifying that `promisor-remote` must accompany each pack-requesting `fetch` in protocol v2 due to statelessness, that negotiation-only requests do not require the reply, and that object-ID-only fetches may skip `ls-refs` entirely. Test scripts: `t/t5705-session-id-in-capabilities.sh`, `t/t5710-promisor-remote-capability.sh` (extended with `GIT_TRACE_PACKET` checks), and `t/t5711-promisor-remote-capability-http.sh` (new, registered in `t/meson.build`). On-disk format unchanged.
