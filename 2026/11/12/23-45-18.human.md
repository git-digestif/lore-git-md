This is Junio Hamano’s "What’s cooking in git.git" report for November 2026, summarizing the current state of topics in flight. The report is a snapshot of the integration branches (`next`, `seen`, and `master`) and highlights which topics have graduated, which are newly proposed, and which are still cooking.

### Graduated to `master`
Several patches have recently graduated to `master`, meaning they are now part of the upcoming release. These include:
- A fix for `git pack-objects` to correctly handle large blobs on 64-bit Windows by using `size_t` instead of `long`.
- An update to `git rev-parse @{push}` to mirror `git push` behavior when the push remote differs from the fetch remote.
- A test fix in `t5702` to avoid relying on `env` output formatting.
- A `range-diff` cleanup to stop using the global `the_repository`.
- CI script improvements to deduplicate test environment setup.
- A `merge-ort` fix to accept valueless rename settings (e.g., `diff.renames` without a value).
- A new `gitsecurityboundary(7)` man page clarifying Git’s security guarantees.

### New Topics
Several new topics have been proposed and are awaiting review or feedback:
- **`wh/checkout-orphaned-commit-warning`**: Introduces a configuration option to skip computing orphaned commits during `git checkout`, which can be slow in large repositories. The topic is waiting for feedback on the implementation.
- **`tb/config-null-values`**: A large series fixing NULL pointer dereferences in config callbacks when a key is provided without a value (e.g., `git config foo.bar`). This looks well-motivated and is likely to merge soon.
- **`mv/log-follow-merge-opt-in`**: Makes the expensive rename detection in `git log --follow` opt-in via `--follow=merges` or `log.follow=merges`, addressing a performance regression introduced by an earlier enhancement.
- **`jm/worktree-rebase-bisect-checked-out`**: Prevents `git worktree remove` from removing a worktree in the middle of a rebase or bisect unless `--force` is given. The series also improves `git branch` and `git for-each-ref` to correctly identify the worktree performing these operations.
- **`kk/commit-struct-padding`**: Rearranges `struct commit` to eliminate padding bytes, reducing its memory footprint by 8 bytes per commit on 64-bit platforms. This is a small but useful optimization.
- **`kn/fast-import-tests`**: A major refactor of `t9300-fast-import.sh` to split tests into self-contained units and improve parallel execution. This is part of ongoing test modernization efforts.

### Cooking Topics
Many topics are still cooking in `next` or `seen`, with varying degrees of progress:
- **`jc/unpack-trees-repo`**: Part of the `the_repository` removal effort, this updates `unpack-trees` to use the repository context from `index_state` instead of the global variable. It is ready to merge to `master`.
- **`ps/ci-speedups`**: Optimizes GitLab CI by building optimized binaries with Meson and using reftables to speed up tests with many refs. This is a practical improvement for CI performance.
- **`ps/rerere-subcommands`**: Converts `git rerere` subcommand parsing to use `OPT_SUBCOMMAND()`, aligning it with other Git commands. This is a cleanup with no behavior change.
- **`rm/http-retry-improvements`**: Enhances HTTP retry logic with exponential backoff and configurable status codes for retries. This is a useful robustness improvement for `git fetch` and `git push`.
- **`ps/odb-loose-stale-cache`**: Fixes a bug where the loose object cache could return stale entries for newly written objects, causing issues in partial clones. This is a targeted fix for a real problem.
- **`hn/reflog-operations`**: Adds a `%gb` format placeholder to `git reflog` and `git log -g` to show the branch name associated with each reflog entry, even during rebase operations. This is a user-facing enhancement.
- **`tb/sideband-skip-unrecognized-allow-control-characters`**: Fixes an infinite loop in the sideband configuration parser when encountering unrecognized control character keywords. This is a small but important fix.

### Stalled or Discarded Topics
Some topics have been marked as stalled or discarded due to lack of progress or unresolved issues:
- **`ap/http-preserve-wwwauth-redirect`**: A fix for preserving `WWW-Authenticate` headers across HTTP redirects. This has been waiting for feedback for too long.
- **`vv/branch-recurse-no-start-ref`**: A fix for `git branch --recurse-submodules` when the start point is not a reference. This has also stalled.
- **`mv/log-follow-speedup`**: A more ambitious version of `mv/log-follow-merge-opt-in` that was retracted to fast-track the opt-in behavior.

### Observations
- The `the_repository` removal effort continues to generate many small, mechanical patches, with several graduating to `master` this cycle.
- Performance and robustness improvements (e.g., CI speedups, HTTP retries, loose object cache fixes) are a recurring theme.
- Some topics, like `tb/config-null-values` and `ps/rerere-subcommands`, are well-scoped and likely to merge soon.
- The `wh/checkout-orphaned-commit-warning` topic is notable for addressing a real user pain point (slow `git checkout` in large repositories) but may need more discussion to finalize the design.

This report is a good way for a busy reader to quickly assess which topics are worth following up on. The most actionable items are likely the new topics (`tb/config-null-values`, `mv/log-follow-merge-opt-in`, `jm/worktree-rebase-bisect-checked-out`) and the cooking topics that are close to merging (`jc/unpack-trees-repo`, `ps/ci-speedups`).
