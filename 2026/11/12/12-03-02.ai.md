This is a feature patch series introducing worktree-specific submodule configuration. The series (3 patches) teaches Git to store submodule settings that can vary between worktrees in the worktree-specific config file when `extensions.worktreeConfig` is enabled.

The motivation is straightforward: when using multiple worktrees, submodule paths or other settings may need to differ between worktrees, but Git currently stores these settings in the main repository config, forcing users to either accept a one-size-fits-all configuration or manually manage per-worktree overrides. This series automates that management by leveraging the existing `extensions.worktreeConfig` mechanism.

Patch 1 ensures `submodule.<name>.gitdir` remains relative for linked worktrees, preventing absolute paths from leaking between worktrees. Patch 2 modifies the config storage logic to write submodule settings to the worktree config when `extensions.worktreeConfig` is enabled. Patch 3 adjusts `git submodule init` to copy an existing `gitdir` setting to the current worktree config only when that setting belongs to the current worktree.

The implementation touches `builtin/submodule--helper.c` (the core logic), `builtin/worktree.c` (worktree-specific handling), and adds two new test scripts (`t/t2405-worktree-submodule.sh` and `t/t7425-submodule-gitdir-path-extension.sh`) covering the new behavior. The documentation in `Documentation/config/submodule.adoc` is updated to reflect the change.

The series is well-scoped and addresses a clear gap in worktree support for submodules. The commit messages are detailed and the test coverage appears thorough. No controversial design choices are evident from the cover letter, though the interaction with existing submodule workflows (e.g., `git submodule update --init`) may draw scrutiny during review. The patches are part of a single logical change and should be evaluated together.
