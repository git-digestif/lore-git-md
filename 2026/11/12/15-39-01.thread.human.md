This thread is about a small but important fix to make Git's test suite work on Solaris when paths contain spaces. Jakub Kulik reported that the test script `t1017-cat-file-remote-object-info.sh` fails on Solaris because two shell variables (`$daemon_parent` and `$HTTPD_DOCUMENT_ROOT_PATH`) weren't quoted, causing "No such file or directory" errors during directory changes.

Junio C Hamano, the maintainer, reviewed the fix and agreed with the core issue—Git's coding guidelines require quoting variables for portability, even if POSIX shells don't strictly need it. He made one minor adjustment to the patch: removing the space between the redirection operator and the quoted path (changing `> "$daemon_parent/hello"` to `>"$daemon_parent/hello"`) to match the project's style. The fix is now ready to be formally submitted with a proper commit message and sign-off. No objections or further discussion points have been raised, so this should be a straightforward merge once Jakub sends the updated patch.
