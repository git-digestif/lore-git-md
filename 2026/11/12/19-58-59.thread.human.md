This thread is about a bugfix series from Christian Couder that ensures the Git client sends the `promisor-remote=...` reply during `fetch` protocol v2 commands—a capability that has been missing since Git v2.49, causing fetch failures with servers like JGit/Gerrit that handle each request independently. The series consists of three patches: a preparatory refactor, the core fix, and a documentation update.

The main point of contention is the design of the first patch, where Junio C Hamano raised a high-weight objection to the new `promisor_remote_reply` argument in `write_command_and_capabilities()`, arguing it bypasses the intended extensibility of the existing `server_options` string list. Junio proposed generalizing `server_options` to support arbitrary key-value pairs instead. Christian has now responded, acknowledging the technical debt in the client-side capability-writing code but arguing that a full refactor should be a separate follow-up. He proposes sending a v2 of the series with a `NEEDSWORK` comment documenting the need for future cleanup, prioritizing the bugfix for `maint` while leaving a clear path for later improvement.

The thread is now at a decision point: Junio must either accept the `NEEDSWORK` compromise or insist on the cleaner API before merging. The core goal—fixing the missing `promisor-remote` reply—remains uncontested, and the series includes thorough tests and documentation. No other reviewers have weighed in yet.
