This thread is a bugfix series from Christian Couder fixing a protocol v2 fetch regression that has existed since Git v2.49: the client was omitting the `promisor-remote=...` reply during pack-requesting `fetch` commands, which breaks stateless servers such as Git over HTTP and JGit/Gerrit when objects live only on promisor remotes. The original v1 was a compact 3-patch fix, but Junio C Hamano objected that it layered the fix on top of duplicated capability-sending logic in `connect.c` and asked for that duplication to be removed first. In response, Couder submitted v2 as an 8-patch series, dedicating the first six patches to exactly that refactoring: unifying the three client-side functions that emit capability lines into a single `write_command_and_capabilities()` path that takes a `struct strvec`, with new helpers `add_server_options()` and `add_promisor_remote_reply()`, and culminating in the outright deletion of `send_capabilities()`. Patch 7/8 then routes the fetch request through this unified path so the promisor-remote reply is sent with every fetch, and patch 8/8 documents the requirement in `gitprotocol-v2.adoc`.

The latest email in the thread is Couder pushing back gently on Junio's framing, pointing out that v2 already performs the requested refactoring rather than deferring it, and expanding test coverage with a new HTTP capability test plus `GIT_TRACE_PACKET` assertions on wire-level ordering. Nothing has been merged or approved yet: the series remains under review with no Reviewed-by or Acked-by trailers, and the open question is whether Junio accepts that the six-patch refactoring satisfies his prerequisite for taking the bugfix. Couder has advocated for inclusion in `maint` given the bug's age and impact on stateless-server setups.
