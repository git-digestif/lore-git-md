This thread is a three-patch bugfix series from Christian Couder addressing a long-standing issue in Git's protocol v2 `fetch` command: the client omits the `promisor-remote=...` reply, breaking interactions with stateless servers like those using HTTP or JGit/Gerrit. The bug has existed since the capability was introduced in Git v2.49 and causes fetch failures when objects are only available on promisor remotes.

The series is under review and targets the `maint` branch for its urgency. The first two patches implement the fix—refactoring to allow sending the reply and enabling it during `fetch`—while the third (this email) updates the protocol documentation to clarify the expected behavior. Tests cover both local and HTTP scenarios, and the changes are self-contained with no open questions. No reviews have been posted yet, but the series is well-motivated and includes thorough test coverage. The documentation patch itself is minimal, adding six lines to `gitprotocol-v2.adoc` to explicitly state that the client must send the `promisor-remote` reply during `fetch`, even if it was already sent in earlier commands like `ls-refs`. This aligns with the stateless nature of protocol v2, where servers may not retain information between requests.
