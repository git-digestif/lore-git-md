Christian Couder has submitted version 2 of an eight-patch series fixing a bug where Git's protocol v2 client omits the `promisor-remote=...` reply during `fetch` commands, breaking stateless HTTP servers and JGit/Gerrit when objects are only available on promisor remotes. The bug has existed since Git v2.49. After Junio C Hamano objected to v1's approach as introducing technical debt, Couder reworked the series to unify capability handling: patches 1 through 4 refactor `connect.c` so that `ls-refs`, `bundle-uri`, `fetch`, and `object-info` requests all build their capability lists into a `struct strvec` and buffer output through `struct strbuf` before a single write, paving the way for the actual fix in patch 7/8 where `promisor-remote` is included in every pack-requesting fetch. The wire protocol remains unchanged in these preparatory patches; the refactoring merely consolidates the client-side code paths.

The series is currently under review with no Reviewed-by or Acked-by tags yet. Junio has not responded to v2, so it remains unclear whether the extensive refactoring satisfies his earlier requirement to eliminate duplication before the bugfix can land. Couder notes the series applies cleanly on `maint` and advocates for inclusion there given the bug's impact, though no integration branch status has been reported.
