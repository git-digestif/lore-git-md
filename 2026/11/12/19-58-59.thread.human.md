Christian Couder has posted v2 of an eight-patch series (expanded from v1's three patches) fixing a bug where Git's protocol v2 client failed to send the `promisor-remote=...` reply with `fetch` commands, breaking fetches against stateless servers such as Git over HTTP and JGit/Gerrit when objects are only available on promisor remotes. The bug was introduced in Git v2.49. The final patch, 8/8, updates `Documentation/gitprotocol-v2.adoc` to state explicitly that clients must include the `promisor-remote` reply with every pack-requesting `fetch`, since protocol v2 is stateless and each command is handled independently; negotiation-only fetches (e.g. `git fetch --negotiate-only`) and object-ID-only fetches that skip `ls-refs` are called out as cases where the per-command reply is essential.

The bulk of the series is refactoring that addresses the maintainer's objection to v1: patches 1 through 6 unify client-side capability writing by routing `ls-refs`, `bundle-uri`, and `fetch` requests through a single `write_command_and_capabilities()` function that takes a `struct strvec` built by new helpers `add_server_options()` and `add_promisor_remote_reply()`, culminating in the deletion of the now-redundant `send_capabilities()`. Patch 7/8 applies this unified path to the actual fetch request in `do_fetch_pack_v2()` so the `promisor-remote` line is actually emitted on the wire, and tests in `t5710` and a new HTTP-based `t5711` script verify the behavior, including a scenario where the server lazily fetches a missing object from the promisor remote. The series touches `connect.c`, `connect.h`, `fetch-pack.c`, `fetch-object-info.c`, and the protocol documentation; no on-disk format changes.

The series remains under review. Junio C Hamano previously objected to v1's approach as technical debt and proposed generalizing `server_options`; whether the v2 refactoring satisfies that objection has not yet been stated, and there are no Reviewed-by or Acked-by trailers yet. Couder has advocated for inclusion in `maint` given the bug's age and impact, and noted that some CI failures on his fork appear unrelated to the series.
