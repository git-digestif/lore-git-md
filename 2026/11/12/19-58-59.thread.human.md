This thread is about a bugfix series from Christian Couder addressing a long-standing issue in Git's promisor-remote protocol v2 capability. The bug, present since Git v2.49, prevents the client from sending a required `promisor-remote=...` reply during `fetch` operations, causing failures when interacting with servers that handle requests independently—such as Git over HTTP or JGit/Gerrit. The problem is particularly disruptive because it breaks fetches when objects are only available on promisor remotes.

The series consists of three patches. The first lays the groundwork by enabling `write_command_and_capabilities()` to send the promisor-remote reply without altering behavior. The second patch implements the core fix, ensuring the client sends the reply during `fetch`, and adds comprehensive tests covering both local and HTTP scenarios. The third patch updates the documentation to reflect the change. The patches touch key files like `connect.c`, `fetch-pack.c`, and `Documentation/gitprotocol-v2.adoc`, and introduce new test scripts (`t5710` and `t5711`). Christian has explicitly requested this series for the `maint` branch, underscoring its urgency.

So far, the series appears uncontroversial and well-motivated, with clear commit messages and thorough test coverage. The CI failures mentioned seem unrelated to the patch itself, likely stemming from test infrastructure issues. No substantive reviews or objections have been raised yet, so the next steps will likely involve maintainer pickup or further testing feedback. If all goes smoothly, this should resolve a real-world annoyance for users relying on promisor remotes.
