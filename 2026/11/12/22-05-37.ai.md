This is the first patch in a five-part documentation series (v4) that aligns Git’s glossary and documentation with the 2024 terminology change distinguishing "pseudorefs" (now only `FETCH_HEAD` and `MERGE_HEAD`) from "root refs" (refs outside `refs/`, like `HEAD` and `ORIG_HEAD`). This patch introduces the "root ref" glossary entry and clarifies the "pseudoref" entry to reflect their distinct semantics and storage mechanisms.

The patch adds a new "root ref" definition, moving naming rules and the exhaustive list of irregular root refs (e.g., `AUTO_MERGE`, `NOTES_MERGE_PARTIAL`) from the existing "ref" entry. The "ref" entry is updated to explicitly mention remote-tracking branches alongside local branches and tags. The "pseudoref" entry is reworded to emphasize that pseudorefs are *not* handled by the ref backend, can record multiple object IDs, and carry metadata, setting them apart from both root refs and regular refs. It clarifies that commands like `git log` use the first object ID when multiple entries are present, and details what `FETCH_HEAD` and `MERGE_HEAD` record (e.g., fetch status annotations, merge commits).

The changes are purely terminological and uncontroversial, addressing prior review feedback from Junio C Hamano and Patrick Steinhardt. The patch touches only `Documentation/glossary-content.adoc`, with no behavioral or code changes. The updated glossary entries now provide clearer, more precise definitions that align with Git’s internal logic and user-facing documentation. This patch sets the foundation for the rest of the series, which propagates the terminology to man pages, code comments, and tests.
