This is the first patch in a three-part bugfix series for Git’s object-format interoperability layer. It addresses a crash that occurs when `extensions.compatObjectFormat` is set to the same hash algorithm as the repository’s `objectFormat`. Currently, this triggers a BUG() in `repository.c`, breaking even basic commands like `git config` and leaving users unable to recover without manually editing the config file.

The fix is straightforward: the patch adds a validation check in `verify_repository_format()` to reject this nonsensical configuration early, returning a clear error message instead of crashing. The change is minimal—just seven lines in `setup.c`—and includes a new test in `t1302-repo-version.sh` that verifies the error is triggered for both SHA-1 and SHA-256 repositories. The test also confirms that removing the bad config restores normal operation.

The patch is uncontroversial and well-justified. The crash is a clear bug, and the fix is defensive programming at its most basic: validate inputs before they cause problems. The test coverage is thorough, and the error message is user-friendly. This looks like a solid, low-risk fix that should be easy to merge.
