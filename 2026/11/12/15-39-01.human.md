This is a **platform compatibility** bugfix targeting the test suite. Jakub Kulik reports that several tests in `t1017-cat-file-remote-object-info.sh` fail on Solaris because shell variables containing paths with spaces are left unquoted. The failures manifest as "No such file or directory" errors when the shell splits the path at the space.

The patch itself is small and surgical: it adds quotes around two variable expansions (`$daemon_parent/hello` and `$HTTPD_DOCUMENT_ROOT_PATH/http_parent/hello`) in the test script. The change is clearly motivated by the observed failure and follows standard shell-scripting hygiene. No new functionality is introduced; this is purely a correctness fix for a platform where paths routinely contain spaces.

The patch looks well-targeted and uncontroversial. It touches only the test suite, so there is no risk of breaking production code. If you care about Solaris support or test suite robustness, this is worth a quick look.
