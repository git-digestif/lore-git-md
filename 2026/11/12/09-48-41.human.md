This is a bugfix patch targeting the `ref-filter` subsystem. Mustafa Bayar reports a double-free crash in `git for-each-ref` when a ref points to a missing object. The crash occurs because `get_object()` frees a buffer but leaves the pointer dangling, so a subsequent call can free the same memory again if the object lookup fails early.

The patch is minimal: it resets the `content` pointer to `NULL` at the start of `get_object()`, mirroring an earlier fix for a related stale-state bug. A new regression test verifies the fix by creating a repository with an annotated tag followed by a tag pointing to a missing object, which triggers the double-free path when refs are processed in sorted order.

The commit message is clear and well-motivated, citing the specific commits that introduced and later partially fixed the issue. The test is carefully constructed to reproduce the exact conditions that trigger the bug. This looks like a solid, well-crafted fix for a real problem encountered in production on GitLab.com.
