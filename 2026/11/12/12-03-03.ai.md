This is the first patch in a three-part feature series introducing worktree-specific submodule configuration. It ensures `submodule.<name>.gitdir` paths remain relative for linked worktrees, preventing absolute path leakage when worktrees are moved.

The patch modifies `builtin/submodule--helper.c` to compute the modules directory relative to the current worktree (using `worktree_git_path()` and `relative_path()`) rather than relying on the main repository path. This change only takes effect when `extensions.worktreeConfig` is enabled, preserving backward compatibility. The new test in `t/t7425-submodule-gitdir-path-extension.sh` verifies that `git submodule init` in a linked worktree produces relative paths like `../.git/worktrees/wt/modules/sub1`.

The implementation is clean and focused: it adds a single helper (`get_current_worktree()`) and systematically replaces hardcoded `repo_git_path_append()` calls with relative-path logic. The error message in the failure case is updated to suggest the correct relative path format. This patch lays the groundwork for the series by ensuring submodule gitdir paths are portable across worktree moves.
