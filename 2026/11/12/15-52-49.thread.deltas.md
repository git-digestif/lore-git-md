# Thread deltas

## 2026/11/12

- [2026/11/12/15-52-49 by Jakub Kulik <jakub.kulik@oracle.com>] Jakub Kulik reported that on Solaris the uname syscall returns a non-negative value on success (unlike other platforms that return 0), so the current `if (uname(&uname_info))` check in version.c incorrectly fails, and proposed changing it to `if (uname(&uname_info) < 0)`, which he thinks should work on other platforms as well but might be missing some where it would not.
- [2026/11/12/19-29-14 by Junio C Hamano <gitster@pobox.com>] Junio C Hamano confirmed that POSIX.1 specifies uname returns non-negative on success and -1 on failure, stated that erroring on any non-zero value is buggy and the proposed `< 0` check looks right, and asked Jakub Kulik to make the change into a real patch.

## 2026/11/18

- [2026/11/18/16-01-47 by Jakub Kulik <jakub.kulik@oracle.com>] Jakub Kulik posted the patch "version: accept positive uname(2) return values" to change the `get_uname_info()` check from `if (uname(&uname_info))` to `if (uname(&uname_info) < 0)` so that any non-negative `uname(2)` return value is accepted per POSIX.
- [2026/11/18/17-11-14 by Junio C Hamano <gitster@pobox.com>] Junio C Hamano approved the patch, replying "Perfect. Thanks."
