Subject: `git diff` context output fails to identify shell function names in multi-line definitions

Thread type: bug report / bugfix discussion

Core problem or goal
`git diff` omits shell function names from context headers when the function definition spans multiple lines due to a line continuation character (`\`). The issue is reproducible: a function `run_query()` defined across two lines (with `\` at the end of the first line) causes the second diff chunk to show only the line number and file name, not the function name, in its context header. The root cause is contested: Junio C Hamano initially traced it to the diff algorithm's shell script userdiff pattern in `userdiff.c` lacking lookahead for line continuations, but Johannes Sixt (Hannes) argues the issue may stem from **missing configuration**—Git does not auto-detect the shell script type (even with `.sh` extension or shebang) and falls back to the generic hunk header pattern unless `diff=bash` is explicitly set in `.gitattributes` or `.git/info/attributes`.

Current status
Under review. The issue is confirmed, but the diagnosis is now split between two explanations:
1. **Code fix**: Adjust the shell script regex in `userdiff.c` to handle line continuations (Junio's initial analysis).
2. **Configuration fix**: Document or tooling improvements to encourage users to set `diff=bash` explicitly (Hannes's alternative).
No patch has been proposed yet. The thread remains open, with the next step likely being a decision on which path to pursue.
