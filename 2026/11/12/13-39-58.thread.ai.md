Subject: `git diff` context output fails to identify shell function names in multi-line definitions
Series version: N/A (bug report, no patch series)
Originating author: Windl, Ulrich <u.windl@ukr.de>
Thread type: bug report

Core problem or goal
`git diff` incorrectly omits shell function names from context headers when the function definition spans multiple lines due to a line continuation character (`\`). The reporter demonstrates that a function `run_query()` defined across two lines (with `\` at the end of the first line) causes the second diff chunk to show only the line number and file name, not the function name, in its context header.

Current status
Under review. No patch proposed; the report is purely observational. The issue is reproducible with the provided shell script example.

Key technical details
- Subsystem: diff context detection (specifically, the logic that identifies function names for `@@ -l,n +m,n @@` headers)
- Language affected: shell scripts (and potentially other non-C languages where function definitions may span multiple lines)
- Trigger condition: line continuation (`\`) at the end of a line containing a function definition
- Files touched: none yet (this is a bug report, not a patch)
- Symbols: none introduced or renamed
- Behavior: context header for subsequent chunks omits the function name, showing only `filename:line_number` instead of `function_name (filename:line_number)`
- Test coverage: none yet; the reporter provides a minimal shell script example that reproduces the issue

Open questions and loose ends
- Whether this is considered a bug or an edge case that Git does not intend to support.
