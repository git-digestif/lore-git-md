Subject: `git diff` context output fails to identify shell function names in multi-line definitions
Series version: N/A (bug report, no patch series)
Originating author: Windl, Ulrich <u.windl@ukr.de>
Thread type: bug report / bugfix discussion

Core problem or goal
`git diff` omits shell function names from context headers when the function definition spans multiple lines due to a line continuation character (`\`). The issue is reproducible: a function `run_query()` defined across two lines (with `\` at the end of the first line) causes the second diff chunk to show only the line number and file name, not the function name, in its context header. Junio C Hamano confirms this is a long-standing behavior (present since at least Git 2.51) and traces it to the diff algorithm's userdiff pattern for shell scripts, which does not look ahead to associate continuation lines with the original function definition.

Current status
Under review. The issue is confirmed and diagnosed; no patch proposed yet. Junio's analysis identifies the root cause as the shell script userdiff pattern in `userdiff.c` lacking lookahead for line continuations. Windl's follow-up clarifies the file is a BASH script (`.sh` extension, shebang), reinforcing that the fix should target the shell-specific regex rather than the generic fallback pattern. The thread remains open, with the next step likely being a patch to adjust the shell script regex in `userdiff.c` to handle line continuations.

Key technical details
- **Subsystem**: diff context detection (userdiff patterns in `userdiff.c`)
- **Language affected**: shell scripts (BASH specifically, as clarified by Windl)
- **Trigger condition**: line continuation (`\`) at the end of a line containing a function definition
- **Files touched**: `userdiff.c` (where built-in patterns are defined)
- **Symbols**: none introduced or renamed; the fix will modify the shell script regex
- **Behavior**: context header for subsequent chunks omits the function name, showing only `filename:line_number` instead of `function_name (filename:line_number)`
- **Test coverage**: none yet; Windl's reproduction case provides a minimal shell script example for verification
- **Root cause**: the shell script userdiff pattern does not look ahead to associate continuation lines with the original function definition
