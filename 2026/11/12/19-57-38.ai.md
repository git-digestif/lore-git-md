This is the first patch in a three-patch bugfix series targeting Git’s object-format interoperability layer. It addresses a crash that occurs when `extensions.compatObjectFormat` is set to the same hash algorithm as the repository’s `objectFormat`. Currently, this configuration triggers a BUG() in `repository.c`, causing every Git command—including `git config`—to abort, which makes it impossible to remove the misconfiguration using Git itself. The patch moves the check into `verify_repository_format()` in `setup.c`, where it runs early enough to prevent the crash and return a clear error message instead. The fix is minimal and includes a new test in `t1302-repo-version.sh` that verifies the error is raised for both SHA-1 and SHA-256 repositories.

The change is uncontroversial and well-justified: it plugs a crash that can leave repositories in an unusable state, and the test coverage ensures the fix works for both hash algorithms. The commit message clearly explains the problem and the solution, and the patch itself is small and focused. There is no behavior change for valid configurations, only a more graceful failure for an invalid one. This patch is likely to be accepted as-is, with discussion in the thread expected to focus on the later patches in the series.
