This is a bugfix series targeting the promisor-remote protocol v2 capability. The issue is that the Git client fails to send a `promisor-remote=...` reply during `fetch` protocol commands, which breaks interactions with servers that handle each request independently (e.g., Git over HTTP or JGit/Gerrit). The bug has existed since the capability was introduced in Git v2.49 and is particularly annoying because it causes fetch failures when objects are only available on promisor remotes.

The series consists of three patches. Patch 1/3 prepares the groundwork by allowing `write_command_and_capabilities()` to send a promisor-remote reply without changing behavior. Patch 2/3 is the core fix, ensuring the client sends the reply during `fetch`, and includes new tests in `t5710` and a new HTTP-specific test script `t5711`. Patch 3/3 updates the documentation to reflect that the client should send the reply with `fetch`.

The commit messages are clear and well-motivated, and the tests cover both local and HTTP scenarios. The CI failures mentioned appear unrelated to the patch itself, likely stemming from test infrastructure issues. This looks like a well-crafted fix for a real problem, and the author explicitly requests it for the `maint` branch, indicating its urgency. Key files touched include `connect.c`, `fetch-pack.c`, and `Documentation/gitprotocol-v2.adoc`, with new test scripts added.
