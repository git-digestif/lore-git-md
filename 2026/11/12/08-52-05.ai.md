This is a feature patch, part of a small series introducing a `--show-object-format` option to `git ls-remote`. The v2 iteration incorporates all feedback from Patrick Steinhardt on the initial submission: the output now uses an extensible `object-format: <format>` prefix, the documentation is clearer, and the test helper is parameterized to reduce boilerplate. The patch remains focused on its original goal—allowing tools like Jujutsu to detect a remote repository’s hash algorithm (SHA-1 or SHA-256) without cloning—while addressing the edge case of empty repositories where the format cannot be inferred from existing objects.

The implementation is minimal and reuses existing transport infrastructure (`transport_get_hash_algo`). The only unresolved technical point from v1—the null-check on the returned pointer—has been deferred as a broader robustness concern, but Adrian argues it is unnecessary in this context. The test coverage is thorough, exercising both SHA-1 and SHA-256 repositories (empty and non-empty), protocol versions v0 and v2, and nongit environments. The documentation update includes a practical example of why the feature matters, making the motivation clear to users.

This version looks ready for further review. The changes since v1 are all surface-level or ergonomic (output format, test helper, documentation wording), and the core design—printing the format on its own line before references—remains unchanged. The patch is uncontroversial and fills a concrete interoperability gap (JJ issue #3813) without touching on-disk formats or introducing new symbols. If no new objections surface, it seems likely to proceed toward `next`.
