This is the core bugfix patch in Christian Couder’s three-part series to fix the promisor-remote protocol v2 capability. The issue is that Git’s client omits the `promisor-remote=...` reply during `fetch` commands, which breaks interactions with servers that handle each request independently—most notably Git over HTTP and JGit/Gerrit. The bug has existed since the capability was introduced in Git v2.49 and causes fetch failures when objects are only available on promisor remotes.

The patch modifies `do_fetch_pack_v2()` in `fetch-pack.c` to ensure the client sends the `promisor-remote` reply with every `fetch` request, not just with `ls-refs` or `bundle-uri`. The preparatory work in patch 1/3 (refactoring `write_command_and_capabilities()`) makes this possible without changing behavior elsewhere. The fix is minimal: it passes the accepted promisor remote string to `send_fetch_request()`, which then includes it in the protocol v2 `fetch` command.

The patch also adds thorough test coverage. The existing `t5710` script gains two new tests: one verifies the reply is sent during a full clone, and another confirms it works when fetching only an object ID (a scenario that skips `ls-refs` entirely). A new HTTP-specific test script, `t5711`, replicates the setup from `t5710` but exercises the HTTP transport, where each request runs in a separate upload-pack process and the bug is most acute.

This looks like a well-crafted fix for a real problem. The commit message clearly explains the edge cases (HTTP, JGit, object-ID-only fetches), the code changes are focused, and the tests cover both local and HTTP scenarios. The author explicitly requests this for the `maint` branch, signaling its urgency. If you work with promisor remotes or HTTP-backed Git servers, this patch is worth your attention.
