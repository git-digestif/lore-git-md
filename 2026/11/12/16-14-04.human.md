This is a performance patch that reduces memory usage for commits. Kristofer Karlsson identifies an 8-byte padding hole in `struct commit` on 64-bit platforms and rearranges the struct members to eliminate it. The change shrinks the struct from 80 to 72 bytes, saving about 10% memory per commit with no behavior change.

The patch is a single-line move of the `index` field from the end of the struct to between `object` and `date`, filling the 4-byte gap after `object` and removing the 4-byte tail padding. On 32-bit platforms where 8-byte alignment isn't required, the size remains unchanged.

Kristofer measures the impact on a 4.5-million-commit monorepo using `git rev-list --all`, showing a 32 MiB reduction in peak RSS (close to the expected 34 MiB) with no measurable runtime change. The commit message traces the history of struct layout changes and mentions a prototype regression test that was left out due to uncertainty about its maintainability.

The patch is clean, well-motivated, and touches only the struct definition in `commit.h`. It looks like a straightforward win for large repositories.
