This thread is about a long-standing bug in `git diff` where context headers fail to show shell function names when the function definition spans multiple lines due to a line continuation character (`\`). Ulrich Windl reported the issue, providing a minimal reproduction case: a BASH script where a function `run_query()` is defined across two lines (with `\` at the end of the first line) causes the second diff chunk to display only the filename and line number, omitting the function name.

Junio C Hamano confirmed the issue and traced it to the shell script userdiff pattern in `userdiff.c`, which doesn’t look ahead to associate continuation lines with the original function definition. Windl’s follow-up clarifies that the file is explicitly a BASH script (with a `.sh` extension and shebang), reinforcing that the fix should target the shell-specific regex rather than a generic fallback pattern. The discussion remains in the diagnostic phase, with no patch proposed yet, but the next step is likely a modification to the shell script userdiff pattern to handle line continuations, along with a test case. No other participants have weighed in with objections or additional feedback.
