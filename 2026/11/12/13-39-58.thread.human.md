This thread is about a bug in `git diff` where context headers fail to show shell function names when the function definition spans multiple lines due to a line continuation character (`\`). Ulrich Windl reported the issue, and Junio C Hamano confirmed it as a long-standing behavior caused by the shell script userdiff pattern not looking ahead to associate continuation lines with the original function definition.

The discussion took a turn when Johannes Sixt (Hannes) pointed out that the issue might not be a bug in the userdiff pattern itself, but rather a configuration problem. Git does not auto-detect file types for diff drivers, even with a `.sh` extension or shebang—users must explicitly configure the shell-specific pattern (`diff=bash`) via `.gitattributes` or `.git/info/attributes`. Without this, Git falls back to a generic hunk header pattern that fails to recognize multi-line function definitions. This reframes the problem: the fix could involve improving documentation or tooling to encourage proper configuration, rather than modifying the shell script regex in `userdiff.c`. The thread is now considering two paths forward, but no patch has been proposed yet.

Key participants include Windl, who reported the issue and provided a reproduction case, and Junio, who diagnosed the root cause. Hannes’s input has shifted the focus from a purely technical fix to a broader discussion about Git’s design and user expectations. The thread remains open, with the next steps likely involving either a patch to adjust the regex or documentation changes to clarify the need for explicit configuration.
