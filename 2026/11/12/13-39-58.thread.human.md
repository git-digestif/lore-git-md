This thread is a bug report from Ulrich Windl about a specific issue with `git diff`'s context output. When a shell function definition spans multiple lines using a line continuation (`\`), Git fails to correctly associate the function name with subsequent diff chunks. The reporter demonstrates this with a real-world example where the second chunk of a diff incorrectly omits the function name (`run_query()`) from its context header, making the output harder to read.

The issue appears to be in Git's diff algorithm's handling of function context detection for non-C languages, specifically shell scripts in this case. While the reporter acknowledges this line-breaking style is uncommon, they argue the diff output should still properly identify the function context. No patch or fix has been proposed yet—this is purely a problem report with reproduction details. The thread is currently just the initial report, so there are no responses or decisions yet.
