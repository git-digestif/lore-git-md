This is a bug report about `git diff` (specifically context diff output) not correctly identifying shell function names in its hunk headers.

The author, Ulrich Windl, reports that when a shell function definition spans multiple lines in an unusual way (here, a single `run_query()` line followed by an opening brace on the next line), `git diff` fails to include the function name in the hunk header. Instead of showing `@@ -201,10 +226,9 @@ run_query()` as expected, it omits the function name entirely (`@@ -201,10 +226,9 @@`). The issue appears to stem from how Git parses function definitions when the opening brace is not on the same line as the function name.

The report is clear and includes a minimal reproduction case: the original shell code snippet and the malformed diff output. No patch is provided—this is purely a problem description. The issue seems real but minor, affecting only the cosmetic quality of diff output rather than correctness. It may be worth attention from someone familiar with Git’s diff hunk header logic, but it does not look urgent or controversial.
