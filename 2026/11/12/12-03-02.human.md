This is a feature patch series introducing worktree-specific configuration for submodules. The author, Yoichi NAKAYAMA, proposes a three-patch series that allows submodule settings to be stored in the worktree config when `extensions.worktreeConfig` is enabled, addressing a long-standing limitation where submodule configurations could not vary between worktrees.

The series starts by ensuring `submodule.<name>.gitdir` remains relative for linked worktrees (patch 1/3), then implements the core functionality of storing submodule settings in the worktree config (patch 2/3), and finally modifies `git submodule init` to copy existing gitdir settings to the current worktree config only when appropriate (patch 3/3). The changes touch `builtin/submodule--helper.c` extensively, with additional modifications to `builtin/worktree.c` and new test files covering both worktree-submodule interactions and gitdir path extensions.

The motivation is clear: when working with multiple worktrees, users often need different submodule configurations for each worktree, but Git currently stores these settings globally. This series enables that flexibility while maintaining backward compatibility through the existing `extensions.worktreeConfig` mechanism. The implementation looks thorough, with 260 new lines of tests across two new test scripts, suggesting good coverage of edge cases.

This appears to be a well-crafted solution to a real problem that submodule users have likely encountered. The series is self-contained and doesn't appear to conflict with other ongoing efforts. If the implementation holds up under review, this could be a valuable addition to Git's worktree functionality.
