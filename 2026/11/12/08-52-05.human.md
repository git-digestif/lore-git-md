This is a feature patch introducing the `--show-object-format` option to `git ls-remote`. It’s the second iteration (v2) of a patch series that began as a single patch, addressing feedback from Patrick Steinhardt on the initial submission.

The patch lets users query a remote repository’s hash algorithm (SHA-1 or SHA-256) without cloning, which is especially useful for tools like Jujutsu that rely on Git’s networking layer. The motivation is concrete: empty repositories don’t expose their object format, leading to silent mismatches that only surface later. The implementation is minimal, reusing the existing `transport_get_hash_algo()` function and printing the format on its own line with an `object-format:` prefix for future extensibility.

All of Patrick’s feedback from v1 has been incorporated: the output now includes the prefix, the documentation wording is clearer, and the test helper is parameterized to reduce boilerplate. The test coverage is thorough, checking both SHA-1 and SHA-256 repositories (empty and non-empty), protocol versions (v0 and v2), and nongit environments. The only unresolved point is whether to add a null-check for `transport_get_hash_algo()`, which Patrick flagged as a broader robustness concern but Adrian considers unnecessary here.

This looks like a well-crafted, uncontroversial addition that fills a real gap. The commit message is clear, the code changes are straightforward, and the tests cover the edge cases. If the null-check debate doesn’t escalate, this is likely to land soon.
