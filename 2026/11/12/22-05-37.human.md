This is a documentation patch, the first in a five-part series that aligns Git’s glossary and documentation with the 2024 terminology change distinguishing "pseudorefs" (now only `FETCH_HEAD` and `MERGE_HEAD`) from "root refs" (refs outside the `refs/` hierarchy, like `HEAD` and `ORIG_HEAD`). The patch adds a new "root ref" glossary entry and substantially rewrites the existing "pseudoref" entry to clarify their distinct semantics and storage.

The new "root ref" entry formally defines the naming rules (upper-case/underscore names ending in `_HEAD` or `HEAD`), lists the exhaustive set of irregular root refs (including `AUTO_MERGE` and `NOTES_MERGE_PARTIAL`), and explicitly states that this list must not be extended. The "ref" entry is updated to mention remote-tracking branches alongside local branches and tags, and now refers to the new "root ref" entry for refs outside `refs/`.

The "pseudoref" entry is reworked to emphasize that pseudorefs are not handled by the ref backend and can record multiple object IDs with metadata. It clarifies that commands like `git log` use the first object ID when multiple entries are present, lists the two pseudorefs (`FETCH_HEAD`, `MERGE_HEAD`), their storage location (`.git` directory), supported operations (`git show`, `git log`), and limitations (`git-update-ref`, `git-for-each-ref`). The entry also explains what `FETCH_HEAD` records (fetched objects with their source ref and merge status) and that `MERGE_HEAD` is written by both `git merge` and `git pull`.

This patch is uncontroversial and ready for merging. It addresses all prior review feedback from Junio C Hamano and Patrick Steinhardt, and the series as a whole is a well-motivated cleanup that resolves long-standing inconsistencies in Git’s documentation. The changes are purely terminological and do not alter behavior.
