This is a three-patch bugfix series from Adrian Ratiu targeting Git’s `compatObjectFormat` handling, specifically around SHA-1/SHA-256 interoperability with Gitoxide and Jujutsu.

The first patch adds a sanity check in `setup.c` to reject the nonsensical case where `compatObjectFormat` and `objectFormat` are set to the same value. The second makes `git rev-parse --output-object-format` fail explicitly when it cannot map an object to the requested format, rather than silently producing a wrong object ID. Both are straightforward fixes with new tests.

The third patch is the most delicate: it changes `object-file-convert.c` to copy unknown commit headers unchanged, rather than rejecting them. This removes a check that was added intentionally in 2023 to prevent certain signed-tag edge cases. Adrian flags this as a potential behavior change and asks for careful review; the commit message explains the tension between Git’s current inconsistent behavior (copying unknown headers when creating commits but rejecting them when converting) and the proposed uniform approach.

The series touches low-level object-format plumbing, so it is likely to interest anyone working on SHA-256 interop or object-conversion code paths. The first two patches look uncontroversial; the third may spark discussion about whether the original safety check should be preserved.
