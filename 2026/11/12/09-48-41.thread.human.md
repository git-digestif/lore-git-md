This thread is about a critical bugfix for a double-free crash in `git for-each-ref` that was introduced in Git v2.53.0 and worsened by a follow-up commit. The issue affects production environments—GitLab.com encountered it in the wild—and occurs when processing refs pointing to missing objects. Mustafa Bayar authored the fix, which is minimal and targeted: it resets a dangling pointer in the `get_object()` function to prevent the cleanup path from freeing an already-freed buffer.

The patch includes a clear explanation of the bug’s origin, a reproduction scenario, and a regression test that verifies both the fix and the correct error handling for missing objects. The change is isolated to the ref-filter subsystem and the test suite, with no broader implications. Since the bug first appeared in a stable release, the patch is based on the `maint` branch, ensuring it will be backported to affected versions. There are no open questions or contested points in the thread so far—this appears to be a straightforward, uncontroversial fix.
