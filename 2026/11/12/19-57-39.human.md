This is the second patch in Adrian Ratiu’s three-part bugfix series for Git’s `compatObjectFormat` interoperability layer. It addresses a silent failure in `git rev-parse --output-object-format`: when the command cannot map an object to the requested format (e.g., because no compat ID exists for it), it currently returns the wrong OID without error. The patch makes it die with a clear error message instead, matching the behavior of `git pack-objects` in the same situation.

The fix is straightforward and well-motivated. The bug occurs because `rev-parse` ignores the return value of `repo_oid_to_algop()`, which leaves the OID unchanged when mapping fails. The patch adds a check and propagates the error with a descriptive message. The new test in `t1500-rev-parse.sh` verifies both the correct behavior for mapped objects and the new error path for unmapped ones, using a hand-copied loose object to avoid dependencies on fetch behavior.

This change is unlikely to be controversial. The commit message clearly explains the problem, the fix, and the scope (single revision arguments only, with other forms left for future work). The test coverage is thorough and self-contained. If the series as a whole gets attention, this patch should be an easy accept.
