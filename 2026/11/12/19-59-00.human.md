This is the first patch in a three-part bugfix series targeting the promisor-remote protocol v2 capability. The series addresses a long-standing issue where the Git client fails to send a `promisor-remote=...` reply during `fetch` protocol v2 commands, breaking interactions with servers that handle each request independently (e.g., Git over HTTP or JGit/Gerrit).

This patch is purely preparatory. It modifies `write_command_and_capabilities()` in `connect.c` to accept a new optional `promisor_remote_reply` argument. When this argument is non-NULL, the function includes a `promisor-remote=...` capability in the request. For now, all callers pass NULL, so there is no change in behavior. The patch touches `connect.c`, `connect.h`, `fetch-object-info.c`, and `fetch-pack.c`, updating function signatures and calls to match the new interface.

The commit message is clear and well-structured, explaining the motivation (preparing for a future fix) and the scope of the change. The patch itself is small and mechanical, focusing only on enabling the capability without actually using it yet. This is a sensible approach for a refactoring that sets the stage for the real fix in the next patch.

No reviews have been posted yet, but the patch looks clean and uncontroversial. It’s a necessary step for the series’ overall goal and doesn’t introduce any risk on its own. If the series is accepted, this patch will likely be merged as-is.
