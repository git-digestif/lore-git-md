Subject: [PATCH] log: make --follow per-parent diffing opt-in
Series version: single patch (no prior iterations)
Originating author: Miklos Vajna
Thread type: bugfix and feature patch

Core problem or goal
Restore the pre-304812ed33 (June 2026) performance of `git log --follow` on non-linear history (e.g., Linux kernel repository), which regressed from ~28 seconds to ~6m43s due to diffing each merge against all parents with rename detection enabled. The patch makes this expensive per-parent diffing opt-in via `--follow=merges` (or `log.follow=merges`), while restoring the original behavior for plain `--follow`.

Current status
Under review; no prior iterations. The patch is proposed as a ready-to-merge fix for a severe, measurable regression affecting a common workflow (`git log --stat --follow` on a single file in large repositories).

Key technical details
- Files touched: `builtin/log.c`, `diff.c`, `diff.h`, `log-tree.c`
- New symbols: `diff_options::follow_merges` flag, `--follow=merges` CLI syntax, `log.follow=merges` config key
- Behavior change: plain `--follow` now skips per-parent diffing (restores pre-304812ed33 performance); `--follow=merges` enables the thorough but slower logic
- On-disk format: unchanged
- Test coverage: new test file `t4219-log-follow-merge.sh` covering valid/invalid arguments, config overrides, and edge cases
