Subject: `git repack --drop-filtered` fatal error on blobs referenced by current index
Series version: none (bug report thread)
Originating author: kongfankaikai
Thread type: bug report

Core problem or goal
`git repack --drop-filtered` currently aborts with a fatal error when attempting to drop a blob that is referenced by the current index. This prevents the operation from dropping other eligible blobs, which is particularly problematic in partial clones with large working trees where the goal is to reduce storage footprint.

Current status
No patch has been posted yet. The issue is acknowledged as a known limitation by Siddharth Shrimali, who is working on a fix. The fix will replace the `die()` call with a warning, allowing the repack to continue and drop remaining eligible blobs. Siddharth references an earlier RFC patch by Samuel Bronson (September 2026) that proposed the same direction.

Key technical details
- Command: `git repack --drop-filtered`
- Error condition: blob referenced by current index
- Current behavior: `die()` aborts entire repack
- Proposed behavior: warning + continue dropping other blobs
- Affected use case: partial clones, large repositories
- Subsystem: repack machinery

Open questions and loose ends

- Are there edge cases (e.g., index corruption, concurrent operations) that could still cause issues?
