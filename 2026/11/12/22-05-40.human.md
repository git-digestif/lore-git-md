This is the fourth patch in a five-part documentation and terminology cleanup series (v4) that aligns Git’s code comments, help text, and error messages with the 2024 redefinition of "pseudoref" (now limited to `FETCH_HEAD` and `MERGE_HEAD`) and "root ref" (refs outside `refs/`, like `HEAD` and `ORIG_HEAD`). The series is uncontroversial and ready for merging, with all prior review feedback incorporated.

This patch updates in-code comments and error messages to stop using "pseudoref" for root refs. The most visible change is in `revision.c`, where the `--merge` error message is reworded from listing specific ref names (`MERGE_HEAD`, `CHERRY_PICK_HEAD`, etc.) to describing the required state ("an ongoing merge, cherry-pick, revert or rebase"). This avoids implying that users must supply one of those refs as an argument, addressing a long-standing usability nit. The change is purely editorial—no behavior is altered.

In `refs.h`, the comment for `REFS_FOR_EACH_INCLUDE_ROOT_REFS` now explicitly lists root refs (`HEAD`, `ORIG_HEAD`, etc.) instead of grouping them with pseudorefs. The pseudoref definition itself is reworded to emphasize their unique semantics (multi-object storage, metadata) and incompatibility with the ref backend. The help text for `git for-each-ref --include-root-refs` is updated to say "root refs" instead of "HEAD ref and pseudorefs".

The bash completion function `__git_pseudoref_exists()` is left unchanged (only its comment is updated) because there is no obvious term covering both root refs and pseudorefs, and third-party scripts might depend on the name. The function’s comment now clarifies that it checks both root refs and pseudorefs.

The patch touches four files: `builtin/for-each-ref.c`, `contrib/completion/git-completion.bash`, `refs.h`, and `revision.c`. The changes are mechanical and well-motivated, reflecting the project’s commitment to precise terminology. The series as a whole resolves inconsistencies that have lingered since the 2024 terminology change, making the documentation and codebase more approachable for users and contributors.
