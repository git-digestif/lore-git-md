This is a bugfix for the ref-filter subsystem, addressing a double-free crash in `git for-each-ref` when processing refs that point to missing objects. The issue is a regression introduced in Git v2.53.0 and later exacerbated by a follow-up fix, affecting production environments like GitLab.com.

The patch itself is minimal and well-targeted: it resets the `oi->content` pointer to `NULL` at the start of `get_object()`, mirroring an existing pattern for `maybe_object`. This prevents the cleanup path from attempting to free an already-freed buffer when a subsequent ref lookup fails. The fix is accompanied by a regression test in `t/t6302-for-each-ref-filter.sh` that verifies both the crash is resolved and the correct error message is shown for missing objects.

Karthik Nayak, a domain expert in ref backends, confirms this patch has already undergone internal review and iteration at GitLab, where the bug was encountered. His rubber-stamp here suggests the fix is solid and ready for upstream consideration. The patch is based on the `maint` branch, as it targets the v2.53.x stable series.
