This is the second patch in Adrian Ratiu’s three-patch bugfix series for the `compatObjectFormat` interoperability layer. It addresses a silent failure in `git rev-parse --output-object-format=<compat-format>`: when an object lacks a recorded compat ID (e.g., objects received via `index-pack` during a fetch), the command currently returns the storage ID instead of the requested compat ID, exiting successfully despite the mismatch. The patch makes the command die with an explicit error message when `repo_oid_to_algop()` fails to map the object, aligning its behavior with `git pack-objects` and other callers of the same function.

The change is confined to `builtin/rev-parse.c` and adds a new test in `t/t1500-rev-parse.sh`. The test manually copies a loose object into a SHA-256 repository configured with `extensions.compatobjectformat=sha1`, ensuring no compat mapping exists, then verifies that `--output-object-format=sha1` fails with the expected error while `--output-object-format=sha256` succeeds. The fix is narrow—it only handles single-revision arguments—and leaves other forms (e.g., `A..B`, `A^@`) unchanged, as those still return storage IDs regardless of `--output-object-format`.

The patch is well-motivated and uncontroversial: the current behavior is clearly incorrect, the fix is minimal, and the test coverage is thorough. No objections are expected, and the change should integrate smoothly with the rest of the series.
