This is the final patch in a three-part bugfix series targeting the promisor-remote protocol v2 capability. The series addresses a long-standing issue where the Git client fails to send the `promisor-remote=...` reply during `fetch` protocol v2 commands, breaking interactions with stateless servers like those used in Git over HTTP or JGit/Gerrit.

This patch updates the `gitprotocol-v2.adoc` documentation to explicitly state that the client should send the `promisor-remote` reply with the `fetch` command, not just with `ls-refs` and `bundle-uri`. The change is straightforward: it adds a six-line paragraph clarifying that, because protocol v2 is stateless, the client must send the reply with every `fetch` request, even if it has already sent it with an earlier command like `ls-refs`. It also notes that the client might skip the `ls-refs` command entirely when fetching only specific object IDs.

The documentation update is minimal and focused, directly addressing the gap that led to the bug. The commit message is clear and references the earlier patches in the series, making it easy to follow the context. This patch completes the series, which is well-motivated, thoroughly tested, and explicitly requested for the `maint` branch due to its urgency. The fix is uncontroversial and aligns with the stateless nature of protocol v2.
