This is the first patch in a three-part series introducing worktree-specific submodule configuration. It ensures that `submodule.<name>.gitdir` settings are stored as relative paths when working with linked worktrees, preventing absolute path leakage that would break the submodule if the worktree is moved.

The patch modifies `builtin/submodule--helper.c` to use worktree-relative paths for the modules directory, leveraging the existing `worktree_git_path()` helper. The change is mechanical but important: it replaces direct calls to `repo_git_path_append()` with logic that constructs paths relative to the current worktree, using `relative_path()` when the modules directory is an absolute path. This ensures that the `gitdir` setting remains valid even if the worktree is relocated, provided `worktree.useRelativePaths` is enabled.

The test coverage is solid: the new test in `t/t7425-submodule-gitdir-path-extension.sh` verifies that `git submodule init` produces relative paths in a linked worktree when the appropriate extensions are enabled. The test is clear and exercises the core functionality without overcomplicating the setup.
