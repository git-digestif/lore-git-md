This thread contains a v2 three-patch series from Yoichi NAKAYAMA that makes submodule configuration worktree-aware when `extensions.worktreeConfig` is enabled. The goal is to store worktree-specific submodule settings in `config.worktree` rather than the shared repository config, and to record `submodule.<name>.gitdir` as a relative path so it survives worktree moves. Patch 1 changes `create_default_gitdir_config()` in `builtin/submodule--helper.c` to generate relative paths for linked worktrees; patch 2 routes submodule config writes through `repo_config_set_worktree_gently()` in `init_submodule()`, `sync_submodule()`, `configure_added_submodule()`, and `validate_and_set_submodule_gitdir()`, while `deinit_submodule()` and `copy_filtered_worktree_config()` in `builtin/worktree.c` ensure gitdir entries are not inappropriately copied to new worktrees; patch 3 adds `submodule_git_dir_matches_current_worktree()` so that `git submodule init` copies an existing repository-config gitdir into `config.worktree` only when it actually belongs to the current worktree, emitting a new `submodule_mismatch_warning` and generating a fresh path otherwise.

The series adds tests in `t/t2405-worktree-submodule.sh` and `t/t7425-submodule-gitdir-path-extension.sh` covering relative-path assertions, config.worktree writes for `active`, `url`, and `gitdir`, and the init-time migration behavior in both main and linked worktrees. It remains under review with no substantive objections or reviewer feedback beyond the v2 static-buffer lifetime fix already incorporated.
