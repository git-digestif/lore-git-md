Yoichi NAKAYAMA's v2 series of three patches proposes teaching Git to keep worktree-specific submodule settings in the worktree-specific config file (`config.worktree`) when `extensions.worktreeConfig` is enabled, and in particular to store `submodule.<name>.gitdir` as a relative path for linked worktrees so the setting survives worktree moves. All three patches are now posted: 1/3 makes the default gitdir path relative in `create_default_gitdir_config()`, 2/3 routes submodule config writes into `config.worktree`, and 3/3 adjusts `git submodule init` handling. The series is under review and has not been queued or merged.

Junio C Hamano has now reviewed both patch 1/3 and patch 2/3 substantively. On patch 1/3 he flagged a static-buffer lifetime hazard in `create_default_gitdir_config()`, where `modules_dir` can point into the ring buffer returned by `worktree_git_path()` and be clobbered across calls, and asked for an unconditional `xstrdup` copy freed under the cleanup label. On patch 2/3 he raised two further correctness concerns: `is_submodule_active()` is being called with the submodule name rather than its path, which misbehaves when name and path diverge, and `copy_filtered_worktree_config()` in `builtin/worktree.c` uses single-value config unset, so duplicate `gitdir` entries in the source config would survive; he recommends `repo_config_set_multivar_in_file_gently()` with `CONFIG_FLAGS_MULTI_REPLACE`. He also asked whether the submodule config documentation should explain how the various `submodule.<name>.*` keys interact with `extensions.worktreeConfig`, since only `gitdir` is currently mentioned. No other reviewers have weighed in, and no decisions have been made beyond these open review points.
