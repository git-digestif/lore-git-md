Subject: [PATCH v2] commit: shrink struct commit by reordering fields
Series version: standalone patch, now v2
Originating author: Kristofer Karlsson
Thread type: performance optimization

Core problem or goal
Reduce memory usage in the commit subsystem by eliminating padding in `struct commit` on 64-bit platforms. The change reorders fields to move `unsigned int index` into the 4-byte gap after `struct object`, shrinking the struct from 80 to 72 bytes (10% reduction) with no behavioral change. The patch also addresses maintainability by adding explanatory comments for `index` and `date` and explores mechanisms to enforce awareness of struct size bloat going forward.

Key technical details
- Files touched: `commit.h`
- Symbols: `struct commit` (reordered fields: `index` moved after `object`; added comments for `index` and `date`), `BUILD_ASSERT_OR_ZERO`, `init_commit_node()`
- Old vs new: 80 bytes with 8-byte padding → 72 bytes with no padding on 64-bit; no change on 4-byte-aligned platforms (e.g., i386)
- On-disk format: unchanged
- Test coverage: none in patch; author measured peak RSS for `git rev-list --all` on a 4.5M-commit monorepo (32 MiB reduction, matching 8 bytes × 4.5M)
- Comments: Added to clarify `index` (unique in-memory identifier for commit-slab) and `date` (unadjusted committer date from commit object)
- Invariant enforcement: Author demonstrated that violating the `struct object`-first invariant causes runtime failures in `init_commit_node()` and proposed a compile-time assertion as a follow-up
