Subject: [PATCH] commit: shrink struct commit by reordering fields
Series version: standalone patch
Originating author: Kristofer Karlsson
Thread type: performance optimization

Core problem or goal
Reduce memory usage in the commit subsystem by eliminating padding in `struct commit` on 64-bit platforms. The change reorders fields to move `unsigned int index` into the 4-byte gap after `struct object`, shrinking the struct from 80 to 72 bytes (10% reduction) with no behavioral change. The patch also sparks discussion about how to enforce awareness of struct size bloat and maintain code clarity in performance-sensitive areas.

Current status

Derrick Stolee has reviewed the patch, calling it "obviously correct" and endorsing the memory savings. Junio C Hamano has provided feedback on code clarity and struct bloat awareness but has not raised technical objections. The patch remains ready for maintainer pickup unless further discussion emerges.

Key technical details
- Files touched: `commit.h`
- Symbols: `struct commit` (reordered fields: `index` moved after `object`)
- Old vs new: 80 bytes with 8-byte padding → 72 bytes with no padding on 64-bit; no change on 4-byte-aligned platforms (e.g., i386)
- On-disk format: unchanged
- Test coverage: none in patch; author measured peak RSS for `git rev-list --all` on a 4.5M-commit monorepo (32 MiB reduction, matching 8 bytes × 4.5M)
- Comments: Junio suggests adding explanatory comments for `index` (unique in-memory identifier for commit-slab) and `date` (unadjusted committer date from commit object) to clarify their purpose and mitigate readability concerns from reordering fields by size rather than logical grouping
