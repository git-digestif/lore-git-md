This is the core bugfix patch in Christian Couder’s three-part series addressing the promisor-remote protocol v2 capability regression. Patch 2/3 ensures the Git client sends a `promisor-remote=...` reply during `fetch` protocol v2 commands, fixing a long-standing issue where servers handling each request independently (e.g., HTTP or JGit) fail to recognize that the client accepts promisor remotes.

The patch modifies `fetch-pack.c` to pass the promisor-remote reply (constructed in `do_fetch_pack_v2`) to `write_command_and_capabilities`, ensuring the capability is included in the `fetch` request. Two new test scenarios in `t5710` verify the fix: one checks that the reply is sent during a full clone, and another confirms it works when fetching only an object ID (which skips `ls-refs`). A new HTTP-specific test script (`t5711`) validates the fix over HTTP, where the bug was most acute due to separate upload-pack processes per request.

The change is minimal and targeted, touching only the necessary plumbing to propagate the reply. The commit message clearly explains the bug’s root cause (a mistaken assumption in an earlier refactoring) and its impact (fetch failures when objects are only available on promisor remotes). The tests cover both local and HTTP scenarios, and the patch is explicitly marked for the `maint` branch, signaling its urgency. No open questions remain; this looks like a well-scoped, thoroughly tested fix for a real-world problem.
