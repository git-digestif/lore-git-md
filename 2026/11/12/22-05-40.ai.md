This is the fourth patch in a five-patch documentation and terminology cleanup series (v4) that aligns Git’s code comments and help text with the 2024 redefinition of "pseudoref" (now limited to `FETCH_HEAD` and `MERGE_HEAD`) and "root ref" (refs outside `refs/`, like `HEAD` and `ORIG_HEAD`). This patch updates in-code comments and error messages to stop using "pseudoref" for root refs, focusing on four files: `builtin/for-each-ref.c`, `contrib/completion/git-completion.bash`, `refs.h`, and `revision.c`.

The key change is the `--merge` error message in `revision.c`, which previously listed `MERGE_HEAD`, `CHERRY_PICK_HEAD`, `REVERT_HEAD`, and `REBASE_HEAD` as pseudorefs. This was misleading because only `MERGE_HEAD` is a true pseudoref, and the phrasing implied users should supply one of these refs as an argument. The new message clarifies that an *ongoing* merge, cherry-pick, revert, or rebase is required, avoiding the confusion. The `refs.h` header is updated to reword the pseudoref definition, emphasizing their unique semantics (multi-object storage, metadata) and incompatibility with the ref backend, while the comment for `REFS_FOR_EACH_INCLUDE_ROOT_REFS` now explicitly lists root refs (e.g., `HEAD`, `ORIG_HEAD`) and omits pseudorefs. The help text for `git for-each-ref --include-root-refs` is reworded to say "root refs" instead of "HEAD ref and pseudorefs".

The bash completion function `__git_pseudoref_exists()` is left unchanged (only its comment is updated) because there is no clear term covering both root refs and pseudorefs, and third-party scripts might depend on the name. The patch is uncontroversial and ready for merging, with all prior review feedback incorporated. It touches no test files or man pages—those updates are handled in other patches in the series. The changes are purely editorial, with no behavioral impact.
