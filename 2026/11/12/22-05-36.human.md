This is a documentation and terminology cleanup series, now in its fourth iteration (v4). The goal is to align Git’s documentation, glossary, man pages, and code comments with the 2024 terminology change that narrowed "pseudoref" to only `FETCH_HEAD` and `MERGE_HEAD`, while introducing "root ref" for refs outside the `refs/` hierarchy (e.g., `HEAD`, `ORIG_HEAD`). This v4 addresses all remaining editorial feedback from Junio C Hamano and Patrick Steinhardt, making the series effectively ready for merging.

The key updates in v4 focus on removing redundant contrasts between pseudorefs and root refs in the glossary, clarifying the exhaustive nature of the root ref list (and discouraging future extensions), and improving the precision of man page descriptions. For example, the glossary’s "pseudoref" entry no longer explicitly contrasts pseudorefs with root refs, avoiding potential confusion about whether pseudorefs might be a subset of refs. The "ref" entry now mentions remote-tracking branches alongside local branches and tags, and the "per-worktree ref" entry states that the list of root ref prefixes will not be extended. In `git-ls-remote(1)`, the default behavior is now described more clearly, and the `--refs` option is explained in terms of what it omits rather than pseudorefs. The error message for `git log --merge` is reworded to avoid implying that users must supply one of the listed refs as an argument, instead stating that an ongoing merge, cherry-pick, revert, or rebase is required.

The series touches 22 files, including the glossary, man pages (`git-update-ref`, `git-worktree`, `git-ls-remote`), pedagogical documentation (`gitdatamodel.adoc`), code comments (`refs.h`, `revision.c`), and test scripts. No behavioral changes are introduced—this is purely a terminology and documentation update. The changes are uncontroversial and appear well-motivated, with all substantive review feedback incorporated. The remaining tweaks are editorial and could be addressed in a follow-up if not resolved in this version. The series is a clear improvement to Git’s documentation consistency and clarity.
