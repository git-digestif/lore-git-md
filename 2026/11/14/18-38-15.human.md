This is the fourth patch in Harald Nordgren’s five-patch v14 series introducing a matching-inspired fetch mode for shallow repositories. The patch adds a `--limited-fetch` flag to `git remote add`, which configures the remote to fetch only the branches tracked by local branches (via `remote.<name>.fetchRefmap`) instead of every branch on the remote. The flag is rejected when combined with `-t/--track` or `--mirror`, since those options already specify what to fetch.

The implementation is straightforward: when `--limited-fetch` is passed, the patch sets `remote.<name>.fetchRefmap` to `+refs/heads/*:refs/remotes/<name>/*` (the same namespace mapping as the default `remote.<name>.fetch` refspec) and omits `remote.<name>.fetch` entirely. This ensures that a refspec-less `git fetch <name>` will use the dynamic branch enumeration logic introduced in Patch 3/5, fetching only the branches tracked by local branches. The documentation update clarifies the flag’s behavior and cross-references the `--refmap` entry in `git-fetch(1)`.

The patch is well-motivated and uncontroversial. It provides the user-facing ergonomic improvement promised by the series, allowing users to opt into the new fetch mode without manually editing their Git config. The test coverage is thorough, verifying both the config setup and the rejection of conflicting options.
