This is the second patch in the v9 series adding path-related keys to `git repo info`. It fixes a **critical correctness bug** in `get_superproject_working_tree()`: the function previously used `xgetcwd()` to determine which repository’s superproject to check, which fails when `--git-dir` points to a different repository than the current working directory. The patch updates the function to accept a `struct repository *` parameter and use `repo_get_work_tree()` instead, ensuring the superproject is determined from the correct repository.

The change touches `submodule.c` (implementation), `submodule.h` (function signature), `builtin/rev-parse.c` (updated caller), and `t/t1500-rev-parse.sh` (new test). The test verifies that `--show-superproject-working-tree` works correctly with `--git-dir` in a submodule context, addressing the edge case that motivated the fix. This patch is **uncontroversial** and has no remaining feedback; it was a blocker for the rest of the series and is now resolved. The implementation is clean, with no redundant checks or latent issues, and the test coverage is thorough.
