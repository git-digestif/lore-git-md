This is the fifth and final patch in Harald Nordgren’s v14 series introducing a matching-inspired fetch mode for shallow repositories. The patch makes `--limited-fetch` the default when adding a remote to a shallow repository, ensuring that `git fetch` does not negotiate history for every branch the remote has.

The change is small and targeted: it modifies `builtin/remote.c` to check `is_repository_shallow(the_repository)` when `limited_fetch` is unset (its default value, `-1`), turning on `--limited-fetch` automatically in shallow repositories unless the user explicitly passes `--no-limited-fetch`, `-t/--track`, or `--mirror`. The documentation (`git-remote.adoc`) is updated to reflect the new default, and the test suite (`t5505-remote.sh`) adds four new tests covering the shallow-repository default, the override with `--no-limited-fetch`, and edge cases with `-t` and full repositories.

The patch is well-motivated and uncontroversial. The default behavior aligns with the purpose of shallow clones (avoiding unnecessary history negotiation), and the override mechanism (`--no-limited-fetch`) preserves backwards compatibility for users who want the old behavior. The implementation is clean, with no new complexity beyond the shallow-repository check, and the tests thoroughly cover the new behavior. This patch is ready for merging as part of the full series, though the ongoing discussion about a partial merge (Patches 1–3 only) does not affect it directly.
