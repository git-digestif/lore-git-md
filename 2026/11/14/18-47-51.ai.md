This is the second patch in Wasswa Edson's three-part series converting `git credential` to use `OPT_SUBCOMMAND`. It refactors the existing `cmd_credential()` function by splitting each subcommand (`fill`, `approve`, `reject`, `capability`) into its own static function with the signature expected by the parse-options API. The patch is purely preparatory: it moves code without changing behavior, except for one small but intentional change—unknown subcommands are now rejected *before* reading a credential from stdin, rather than after. This makes the error path more consistent with the upcoming `OPT_SUBCOMMAND` conversion and avoids unnecessary I/O for invalid commands.

The patch touches only `builtin/credential.c` and is mechanical in nature: each new function (`cmd_credential_fill`, `cmd_credential_approve`, etc.) is a direct extraction of the corresponding block from the original `strcmp()` chain. The `argc` and `argv` adjustments (`argc - 1`, `argv + 1`) ensure the subcommand functions receive only their own arguments, not the command name or subcommand itself. The `prefix` and `repo` parameters are passed through unchanged, though they remain unused in this patch.

This refactoring is a textbook example of a safe, incremental step toward a larger goal. By isolating each subcommand into its own function, the patch makes the next step (switching to `OPT_SUBCOMMAND`) trivial and reviewable. The commit message clearly explains the motivation and the single behavioral change, and the code itself is clean and idiomatic. There are no obvious gotchas or edge cases introduced here—just a straightforward reorganization that aligns the code with Git's established patterns. The patch should be uncontroversial and ready for merging once any minor nits are addressed.
