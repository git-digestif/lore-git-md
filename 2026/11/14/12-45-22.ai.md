This is a maintainer query about a potential UI regression in the now-merged `ps/builtin-rerere-subcommands` series. Junio C Hamano reports that the new subcommand-based parser no longer accepts the `--skip-locked` option before the "gc" subcommand: `git rerere --skip-locked gc` (old syntax) now fails, while `git rerere gc --skip-locked` (new syntax) works. The change is subtle but real, and Junio is concerned it could break existing scripts or user habits, given Git’s large user base. He notes that while he personally prefers options after non-options, the enforced ordering is a departure from the previous behavior. The transcript shows the old syntax working on `master` and `next` but failing on `seen`, confirming the regression. No fix or workaround is proposed yet; this is an early heads-up rather than a demand for action.
