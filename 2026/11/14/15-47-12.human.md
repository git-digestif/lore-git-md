This is a bugfix for the first patch in Yoichi NAKAYAMA’s three-patch series introducing worktree-specific submodule configuration. The series aims to let users store submodule settings (like `submodule.<name>.url` or `submodule.<name>.active`) in worktree-specific config files when `extensions.worktreeConfig` is enabled, rather than forcing all worktrees to share the same settings from the main repository config.

The bug here is a classic C footgun: `worktree_git_path()` returns a pointer to a static buffer that can be overwritten by subsequent calls. The original patch used this pointer directly, risking corruption when other functions (like `relative_path()`) are invoked. Yoichi’s fix copies the result into a `strbuf` immediately, ensuring the path remains valid throughout the function’s lifetime. The corrected code now properly handles both absolute and relative paths, storing the result in the `strbuf` in either case.

This fix is minimal and surgical—it touches only the `create_default_gitdir_config()` helper in `builtin/submodule--helper.c` and preserves the patch’s original goal: keeping `submodule.<name>.gitdir` paths relative for linked worktrees. The test in `t/t7425-submodule-gitdir-path-extension.sh` remains valid, as the corrected code still produces the same relative paths (e.g., `../.git/worktrees/wt/modules/sub1`). The fix is necessary but doesn’t expand the patch’s scope or introduce new behavior.

The series as a whole is still under review, with this fix resolving the only technical concern raised so far. No other feedback has been posted, so the door remains open for substantive discussion about the feature’s design or edge cases. If you care about submodule workflows in multi-worktree setups, this is worth watching—it plugs a clear gap in Git’s worktree support.
