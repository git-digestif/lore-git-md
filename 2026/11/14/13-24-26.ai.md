This is the v7 iteration of Harald Nordgren’s four-patch series that teaches `git branch --delete-integrated` to detect branches whose changes were squash-merged or rebase-merged into an upstream branch, even when the upstream later modified the same files. The series is now technically complete: the two substantive review issues raised by Jasper Mayone in v6—redundant index reads and `.gitattributes` resolution from the wrong tree—are both fixed. A new test case verifies that branches whose changes never landed are not deleted, closing the last major correctness gap.

The first two patches remain uncontroversial: patch 1/4 is a pure refactoring that extracts `branch_opted_out()` for reuse, and patch 2/4 extends `delete_branches()` to report the landing commit in the deletion message. Patch 3/4, which implements the `--delete-integrated` flag, is also uncontroversial after Junio’s variable-rename feedback was addressed in v6. Patch 4/4—the core squash-detection logic—now reads the index once before the walk in `find_landed_commits()`, eliminating the performance bottleneck Jasper identified, and the commit message explicitly documents that the merge uses this repository’s attributes from the working tree and index, resolving the `.gitattributes` resolution ambiguity.

The new test case in patch 4/4 covers three edge cases: a branch whose changes never landed, a branch whose changes landed only partially, and a branch whose changes conflicted with upstream edits. These scenarios directly address Jasper’s robustness concerns from v6, and the test’s structure (setup in `upstream/`, execution in `repo/`) mirrors the existing test suite. The only remaining loose ends are minor usability nits: outdated flag names in the cover letter, silent skipping of checked-out worktrees, and Phillip Wood’s call for clearer documentation of the algorithm’s limitations. None of these block integration, and the series is now ready for Junio’s queue.
