This is a follow-up to the first patch in Yoichi NAKAYAMA’s three-patch series introducing worktree-specific submodule configuration. The email corrects a static-buffer handling issue in the original submission.

The problem is straightforward: `worktree_git_path()` returns a pointer to a static buffer, which can be overwritten by subsequent calls (e.g., to `relative_path()`). The original patch used this pointer directly, risking corruption. Yoichi’s fix copies the result into a `strbuf` immediately, ensuring the path remains valid. This is a classic C pitfall, and the correction is minimal and necessary—it adds no new behavior, only safety.

The change is confined to `builtin/submodule--helper.c` and affects only the `create_default_gitdir_config()` helper. The fix preserves the patch’s original goal: keeping `submodule.<name>.gitdir` paths relative for linked worktrees to prevent breakage when worktrees are moved. The test in `t/t7425-submodule-gitdir-path-extension.sh` remains valid, as the corrected code still produces the same relative paths (e.g., `../.git/worktrees/wt/modules/sub1`).

This is a surface-level but critical fix. The original patch was well-motivated, but this static-buffer issue could have caused subtle bugs.
