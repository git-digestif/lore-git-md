This is the third patch in Harald Nordgren’s v7 series implementing `git branch --delete-integrated`, a new flag that deletes branches whose changes (but not their tips) have been integrated into an upstream branch via rebase or squash merges. The patch adds the core `--delete-integrated` flag and the rebase-detection logic; squash-detection with upstream modifications is implemented in patch 4/4.

The patch introduces the `DELETE_BRANCH_INTEGRATED` flag and the `landing_search` struct, which tracks each branch’s name, tip commit, upstream, and the set of files it changed. The rebase-detection algorithm is tree-based: it collects the branch’s changes relative to the merge base, then walks the upstream history looking for a commit that contains the branch’s version of every changed file. This avoids reading file contents, so it stays cheap in partial clones. The commit message is updated to show where the work landed (`Deleted branch topic (was 1a2b3c4, landed as 9f8e7d6)`), and the config key `branch.<name>.deleteMerged` now applies to both `--delete-merged` and `--delete-integrated`.

The implementation is uncontroversial after Junio’s feedback on v5 (renaming `opt` to `diffopt` in `find_landed_commits()`) was addressed in v6. The patch adds new test coverage for rebase-merged branches, mixed workflows (a branch that was both merged and squash-merged), and edge cases where the branch’s changes were later reverted upstream. The CLI design is final: `--delete-merged` remains strict (tip-reachability only), while `--delete-integrated` is opt-in and detects both rebase and squash merges. The two flags cannot be combined, and `--dry-run` works with both.
