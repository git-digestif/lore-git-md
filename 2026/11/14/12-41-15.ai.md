This is the sixth patch in Harald Nordgren’s six-patch feature series improving how `git status` and `git push` handle rebased push branches. The patch teaches `git push` to detect when the remote branch carries no new work—only commits the local branch has rewritten via a clean rebase—and to suggest `--force-with-lease` instead of the generic `git pull` advice.

The implementation adds a new helper `branch_rebased_cleanly()` in `remote.c` that reuses the three-way `rev-list --cherry-mark` logic introduced earlier in the series to determine whether the non-upstream commits are identical on both sides. When they are, the push rejection message now explicitly states the branch was "rebased cleanly on 'upstream/main'" and offers only the force-push option. The new advice message (`message_advice_force_after_clean_rebase`) is opt-in and consistent with Git’s existing advice patterns. The test file (`t/t6040-tracking-info.sh`) adds a 25-line test case verifying the new rejection message and the subsequent `git status` output after a successful force push.

Harald’s follow-up email reports he is already using the feature via `seen` and shares a real-world example showing the new `git status` output: it now breaks down divergence into commits present in the branch-vs-push comparison but absent from upstream, and explicitly notes when the divergence is due to a clean rebase. The push rejection message in this scenario offers only `--force-with-lease`, which aligns with the user’s intent after a clean rebase. The series as a whole looks well-scoped and the commit message is clear, but the real test will be whether reviewers agree that `--force-with-lease` is always the right advice in these scenarios.
