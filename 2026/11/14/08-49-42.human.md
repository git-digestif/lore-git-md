This is a **substantive review** in the ongoing `git diff` shell function context header bugfix discussion. Johannes Sixt (Hannes) clarifies a critical point that was previously overlooked: Git does *not* automatically apply language-specific diff patterns (like the shell script regex in `userdiff.c`) based on file extensions or shebangs. Instead, users must explicitly configure a diff driver (e.g., `*.sh diff=bash`) in `.gitattributes` or `.git/info/attributes` for the shell-specific pattern to take effect.

Hannes’s observation reframes the thread’s focus. The issue Windl reported isn’t a bug in the shell script userdiff pattern itself—it’s that the pattern isn’t being *used* by default. Without a diff driver configured, Git falls back to a generic hunk header pattern that only matches lines starting with non-punctuation characters, which explains why multi-line function definitions (like `run_query() \`) fail to show the function name in context headers. This shifts the discussion from "how to fix the shell regex" to "how to ensure the shell regex is applied by default for `.sh` files."

The thread now has two open questions:
1. Should Git automatically enable the shell diff driver for `.sh` files (a behavior change that might affect existing workflows)?
2. If not, should the documentation (e.g., `gitattributes(5)`) be updated to highlight this requirement for shell scripts?

No patch has been proposed yet, but Hannes’s reply suggests the fix might involve either:
- Modifying Git’s default attributes to include `*.sh diff=bash`, or
- Improving the fallback pattern to better handle shell-like syntax (though this could introduce false positives).

The review is substantive because it identifies a systemic issue (diff driver activation) rather than a narrow regex bug. It also raises backward-compatibility concerns, as any change to default attributes could alter diff output for users who currently rely on the generic pattern. The thread remains under review, with the next step likely being a patch to address the driver activation gap.
