This is the first patch in Harald Nordgren’s v14 series introducing `remote.<name>.fetchRefmap`, a new configuration key that provides the default value for the `--refmap` option in `git fetch`. The patch adds the plumbing for the config key, updates the refspec precedence logic in `remote.c` and `builtin/fetch.c`, and includes comprehensive tests.

The patch implements the core separation of concerns that the series is built on: `remote.<name>.fetch` decides *what* to fetch, while `remote.<name>.fetchRefmap` decides *where* to store it. When both are configured, the fetch refspec takes precedence, and the refmap is used only for mapping the fetched refs. This design resolves the maintainer’s objection to overloading `remote.<name>.refmap` in earlier versions. The override semantics (command-line refspecs override `fetchRefmap` entirely) are already implemented here, aligning with the finalized v14 design.

The test coverage is thorough, verifying that `fetchRefmap` behaves like `--refmap` on the command line, that it correctly stores branches named in `remote.<name>.fetch`, that it tracks branches outside the fetch refspec, and that it respects negative refspecs. The patch is foundational and uncontroversial; it enables the rest of the series and is required to resolve the textual conflicts with Collin’s `ch/remote-defer-follow-remote-head-validation` topic. No behavioral changes are introduced beyond the new config key, and the implementation is clean and well-documented. This patch is ready for merging and is a strong candidate for a partial merge if the series is split.
