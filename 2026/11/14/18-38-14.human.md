This is the third patch in Harald Nordgren’s v14 series introducing `remote.<name>.fetchRefmap` for matching-inspired fetch mode. The patch implements the core dynamic branch enumeration logic: when a remote has only a `fetchRefmap` configured (no `fetch` refspec), a refspec-less `git fetch` now infers which branches to fetch from the local branches whose `@{upstream}` points to that remote. The patch also ensures `@{push}` resolution works correctly for such remotes by falling back to the refmap if the `fetch` refspec does not resolve the refname.

The implementation touches `builtin/fetch.c` (adding the inference logic in `get_ref_map()`), `remote.c` (adding the `branches_tracking_remote()` helper and the `@{push}` fallback), and `remote.h` (exporting the new helper). Documentation is updated to clarify the behavior, and a new test file (`t/t5586-fetch-refmap.sh`) thoroughly exercises the feature, including edge cases like prefetch, multiple branches tracking the same upstream, and `@{push}` resolution.

This patch is strategically critical: it resolves the textual conflicts with Collin’s `ch/remote-defer-follow-remote-head-validation` topic, making it a blocker for that work. The architectural objection raised by Phillip Wood (that dynamic branch enumeration violates the separation of concerns introduced in Patch 1/5) is weakened by this dependency, as the patch is required to unblock the other topic. The patch is well-tested, with no known issues beyond the ongoing strategic discussion about whether to merge it now or defer it as part of a partial merge. The implementation is clean, with the `@{push}` fix squashed in to avoid a bug-introduce-then-fix sequence, and the helper extraction in Patch 2/5 enabling reuse without adding complexity.
