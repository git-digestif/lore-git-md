This is the fourth patch in the **v9 series** adding path-related keys to `` `git repo info` ``. It introduces `path.index.absolute` and `path.index.relative`, exposing the repository’s index file location in a scriptable, config-like format. The implementation respects the `GIT_INDEX_FILE` environment override and returns the configured index path even if the file does not exist or the repository is bare, aligning with `` `git rev-parse --git-path` `` precedent.

The patch touches `builtin/repo.c` (adding two new getter functions, `get_path_index_absolute` and `get_path_index_relative`), `Documentation/git-repo.adoc` (documenting the new keys), and `t/t1900-repo-info.sh` (adding tests for standard paths, `GIT_INDEX_FILE` overrides, and bare-repository edge cases). The tests are thorough and cover both absolute and relative paths, including the expected behavior in bare repositories where the index file may not exist.

This patch is **uncontroversial and mechanically complete**. The only latent concern—a `BUG()` invocation in `repo_get_index_file(repo)`—was raised by Junio in earlier iterations but retained as-is by the author. The decision to keep the existing implementation is defensible given the series’ focus on exposing existing Git internals rather than refactoring them. The patch is ready for merging and fits cleanly into the broader effort to make repository paths accessible via `` `git repo info` ``.
