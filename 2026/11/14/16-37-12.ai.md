This is the second patch in the **v9 series** adding path-related keys to `` `git repo info` ``. It fixes a **critical correctness bug** in `` `get_superproject_working_tree()` ``: the function previously used `` `xgetcwd()` `` to determine which repository’s superproject to check, which fails when `` `--git-dir` `` points to a different repository than the current working directory. The patch updates the function to accept a `` `struct repository *` `` parameter and use `` `repo_get_work_tree(repo)` `` instead of `` `xgetcwd()` ``, ensuring the superproject is determined from the repository being inspected rather than the shell’s working directory.

The change touches `` `submodule.c` `` (implementation), `` `submodule.h` `` (function signature), `` `builtin/rev-parse.c` `` (updated caller), and adds a test in `` `t/t1500-rev-parse.sh` `` that verifies `` `--show-superproject-working-tree` `` works correctly with `` `--git-dir` `` in a submodule context. The test initializes a superproject and submodule, then uses `` `git --git-dir=<submodule-git-dir> rev-parse --show-superproject-working-tree` `` to confirm the correct superproject root is returned.

This patch is **uncontroversial and mechanically complete**. It was first introduced in v8 to address Junio’s high-weight correctness concern, and the v9 version incorporates no further changes. The test added here replaces the one that was previously in `` `t/t7400-submodule-basic.sh` `` (removed in v8 to avoid bisectability issues). The fix is a prerequisite for the `` `path.superproject_working_tree` `` keys introduced in patch 3/5, which rely on this corrected behavior.
