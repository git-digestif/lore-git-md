This is a follow-up to the first patch in Yoichi NAKAYAMA’s three-patch series introducing worktree-specific submodule configuration. The patch itself is a bugfix addressing a static-buffer issue in the original submission.

The problem is straightforward: `worktree_git_path()` returns a pointer to a static buffer managed by `get_pathname()`, which can be overwritten by subsequent calls. The original patch used this pointer directly, risking corruption when other functions (like `relative_path()`) are invoked. Yoichi’s fix copies the result into a `strbuf` immediately, ensuring the path remains valid throughout the function’s lifetime. This is a classic C footgun, and the correction is both necessary and minimal—it adds no new behavior, only safety.

The change is confined to `builtin/submodule--helper.c` and affects only the `create_default_gitdir_config()` helper introduced in the original patch. No other files or logic are touched. The fix preserves the patch’s original goal: keeping `submodule.<name>.gitdir` paths relative for linked worktrees to prevent breakage when worktrees are moved. The test in `t/t7425-submodule-gitdir-path-extension.sh` remains valid, as the corrected code still produces the same relative paths (e.g., `../.git/worktrees/wt/modules/sub1`).

This is a surface-level but critical fix. The original patch was well-motivated and cleanly implemented, but this static-buffer issue could have caused subtle bugs in edge cases.
