This is a v2 patch series converting `git credential` to use `OPT_SUBCOMMAND` from the parse-options API. The series is now split into three patches: (1) aligning the `-h` output with the SYNOPSIS, (2) refactoring each subcommand into its own function, and (3) switching to `OPT_SUBCOMMAND`. The author, Wasswa Edson, has addressed the two main issues raised in the v1 review by Tanga Joris: the code size claim is dropped, and a helper function (`parse_no_args`) is introduced to reduce repetitive boilerplate. The series also adds a test to verify that extra arguments are rejected, closing the missing test coverage gap.

Key technical details: the patch touches `builtin/credential.c`, `git.c`, `Documentation/git-credential.adoc`, and `t/t0300-credentials.sh`. The new helper function centralizes the argument parsing and rejection logic, making the code more maintainable. The `NO_PARSEOPT` flag is removed from `git.c`, exposing the command to `--list-cmds=parseopt`. Behavior changes are limited to error paths: clearer messages for missing/unknown subcommands, rejection of extra arguments, and subcommand-specific help output. The core credential operations (fill, approve, reject, capability) remain unchanged.

The series is a clean, incremental refactoring that aligns `git credential` with Git's established patterns. The split into three patches makes the changes easier to review, and the addressed feedback from v1 strengthens the implementation. The added test coverage for extra arguments is a welcome improvement. This looks like a well-scoped, uncontroversial effort that should be ready for merging once any remaining nits are addressed. The commit messages are thorough and clearly explain the motivation and changes.
