This is the second patch in Harald Nordgren’s four-part v7 series introducing `git branch --delete-integrated`. It extends the `delete_branches()` helper to report where a deleted branch’s changes landed, preparing for the squash-merge and rebase-merge detection logic that arrives in patch 4/4.

The patch is a straightforward plumbing change: `delete_branches()` now accepts an optional `strmap` (`landed_commits`) that maps branch names to the upstream commit where their changes were integrated. When a branch is in the map, the merge-reachability check is skipped and the deletion message is extended to show both the branch’s old tip and the landing commit (e.g., `Deleted branch topic (was 1a2b3c4, landed as 9f8e7d6)`). No callers pass a non-NULL map yet, so the patch is behavior-neutral.

The implementation is clean: the map lookup is guarded by a null check, the landing commit’s abbreviated OID is computed once, and the output strings are localized. The patch touches only `builtin/branch.c` and is explicitly uncontroversial—Junio and reviewers have already signed off on the design in earlier rounds. This is a pure refactoring that enables the user-visible change in patch 4/4.
