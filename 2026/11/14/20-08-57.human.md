This is Junio’s review of the first patch in Adithya Chakilam’s two-patch series that adds `--filter-to-loose=<dir>` to `git repack`. The feature lets users write filtered-out objects directly as loose objects into a specified directory, bypassing the intermediate packfile step—useful for systems like key-value stores that manage objects individually.

Junio’s feedback is **surface-level** but pointed. He hasn’t decided whether the feature itself makes sense, so his comments assume the design is acceptable and focus on correctness and edge cases. Key points: he wants tests to verify that the command errors out if the target directory doesn’t exist, and that relative paths work correctly when the command is run from a subdirectory. He also flags a potential double-close bug in the error path where `unpack.in` might be closed twice if `start_command()` fails. The review is concise and technical, but stops short of engaging with the broader design or performance implications. No approval or rejection is implied—just a request for fixes before deeper consideration.
