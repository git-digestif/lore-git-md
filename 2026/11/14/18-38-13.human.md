This is a refactoring patch in Harald Nordgren’s five-part series introducing `remote.<name>.fetchRefmap` and a matching-inspired fetch mode for shallow repositories. It is the second patch in the v14 iteration, which is now under final review for merging to `master`.

The patch extracts the logic that checks whether the current branch builds on a given remote and, if so, adds its upstream refs to the list of refs to fetch. This logic was previously inlined in `builtin/fetch.c` and only applied to the current branch. By moving it into a new helper function, `collect_upstream_from_remote()`, the patch enables the same logic to be reused for branches other than the current one. The helper is called unconditionally when no refspec is provided, ensuring that the current branch’s upstream is still fetched even if the remote’s configured refspec does not cover it.

The change is mechanical and uncontroversial: it does not alter behavior, only reorganizes existing code to support the dynamic branch enumeration logic introduced in Patch 3/5. The helper is well-named and clearly documented, and the commit message explains the motivation with a concrete example. This patch is foundational for the series, as it enables the later patches to implement the matching-inspired fetch mode without duplicating logic.

This patch, however, is not directly affected by either consideration, as it is purely preparatory plumbing. It looks ready to graduate as part of whichever subset of the series is ultimately merged.
