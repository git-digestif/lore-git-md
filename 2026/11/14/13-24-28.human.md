This is the second patch in Harald Nordgren’s four-part series introducing `git branch --delete-integrated`, which will let users delete branches whose changes (but not their tips) were squash-merged or rebase-merged into an upstream. This patch is a small, focused preparatory step: it extends the `delete_branches()` helper so it can report *where* a branch’s changes landed, even when the branch tip itself is not reachable from the upstream.

The change is straightforward. `delete_branches()` now takes an optional `strmap` that maps branch names to the upstream commit where their changes were integrated. If a branch is in the map, the merge check is skipped and the deletion message is extended to show both the old tip and the landing commit: `Deleted branch topic (was 1a2b3c4, landed as 9f8e7d6)`. No callers pass a map yet, so there is no behavior change in this patch—it simply wires up the plumbing for the next two patches.

The patch is uncontroversial. Junio has not raised any concerns about it, and the thread context confirms that the first two patches in the series are explicitly ready for integration. The commit message is clear, the code is clean, and the test coverage in the later patches will exercise the new output format. If you care about the `--delete-integrated` feature, this patch is worth noting only as a stepping stone; the real action is in patches 3 and 4.
