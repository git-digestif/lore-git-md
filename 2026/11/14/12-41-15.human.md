This is the final patch in Harald Nordgren’s six-patch feature series, now seeing real-world use after being picked up in `seen`. The series improves how `git status` and `git push` handle rebased branches by distinguishing between commits that originate from upstream and those that don’t, and by offering more actionable advice when divergence is due to a clean rebase.

The patch itself teaches `git push` to detect when the remote branch carries no new work—only commits the local branch has rewritten—and suggests `--force-with-lease` instead of the generic `git pull` advice. When the divergence is due to a clean rebase, the rejection message now explicitly says the branch was "rebased cleanly on 'upstream/main'" and offers only the force-push option. The logic reuses the `stat_outside_upstream()` helper introduced earlier in the series to determine whether non-upstream commits are identical on both sides. The new advice message (`message_advice_force_after_clean_rebase`) is opt-in and consistent with Git’s existing advice patterns.

Harald reports using the feature via `seen` and shares a real-world example of the new `git status` output, which clearly labels the divergence as a clean rebase and suggests `--force-with-lease`. The implementation touches `builtin/push.c` (adding the new advice message and adjusting the rejection logic), `remote.c` (adding the `branch_rebased_cleanly()` helper), and `remote.h` (exporting the helper). The test file (`t/t6040-tracking-info.sh`) adds a 25-line test case verifying the new rejection message and the subsequent `git status` output after a successful force push.

The patch is narrowly focused on the push rejection path and does not change core object storage or ref handling. The behavior is opt-in: only users who configure `status.compareBranches` to include `@{push}` will see the new advice. The series as a whole looks well-scoped and the commit message is clear, but the real test will be whether reviewers agree that `--force-with-lease` is always the right advice in these scenarios. Harald’s real-world usage suggests the feature is already proving useful, which may help build momentum for review.
