This is the third patch in the **final (v9)** series adding path-related keys to `git repo info`. It introduces `path.superprojectworkingtree.absolute` and `path.superprojectworkingtree.relative`, which expose the working tree root of the superproject when the current repository is a submodule. The patch is **uncontroversial, mechanically complete, and ready for merging**.

The implementation builds on the **critical correctness fix** in patch 2/5, which updated `get_superproject_working_tree()` to respect the `repo` parameter. Here, the new keys use that function to return the superproject’s working tree path in either absolute or relative format, or an empty string if not in a submodule. The patch touches `builtin/repo.c` (adding the new keys and their getter functions), `Documentation/git-repo.adoc` (documentation), and `t/t1900-repo-info.sh` (tests covering submodule contexts, `--git-dir` usage, and non-submodule edge cases).

The tests are thorough: they verify the keys return the correct paths when inside a submodule (including relative paths with `../`), and empty strings when not in a submodule. The naming convention (underscores, not hyphens) is settled, and all prior design objections—particularly around the necessity and behavior of these keys—have been resolved in earlier iterations. This patch is a straightforward extension of the series’ core goal: making repository component paths scriptable without requiring direct access to Git’s internals.
