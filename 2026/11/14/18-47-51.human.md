This is the second patch in Wasswa Edson’s three-part series converting `git credential` to use `OPT_SUBCOMMAND`. It refactors the existing `cmd_credential()` function by moving each of the four subcommands—`fill`, `approve`, `reject`, and `capability`—into its own static function. The new functions all follow the signature expected by the parse-options API, so the next patch can simply wire them up to `OPT_SUBCOMMAND` without further changes.

The patch is purely mechanical: the credential logic itself is untouched, and the only behavioral difference is that an unknown subcommand is now rejected *before* reading from stdin, rather than after. This is a minor UX improvement that avoids unnecessary I/O when the user mistypes a command. The commit message is clear, the diff is easy to follow, and the split keeps the series reviewable. No new issues are introduced, and the patch looks ready to proceed once any surface-level nits are addressed.
