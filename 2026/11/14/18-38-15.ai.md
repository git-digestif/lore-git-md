This is the fourth patch in Harald Nordgren’s five-patch v14 series introducing `remote.<name>.fetchRefmap` and a matching-inspired fetch mode. The patch adds a `--limited-fetch` flag to `git remote add`, which configures the remote to fetch only the branches tracked by local branches (via `remote.<name>.fetchRefmap = *@{upstream}`) instead of every branch on the remote. The flag is rejected when combined with `-t/--track` or `--mirror`, as those options already specify what to fetch.

The implementation is straightforward: when `--limited-fetch` is passed, `builtin/remote.c` sets `remote.<name>.fetchRefmap` to `+refs/heads/*:refs/remotes/<name>/*` (the same namespace mapping as the default `remote.<name>.fetch` refspec) and skips setting `remote.<name>.fetch`. The documentation (`git-remote.adoc`) is updated to describe the new flag, and a test in `t5505-remote.sh` verifies that `--limited-fetch` works in a full repository and conflicts with `-t` as expected.

This patch is part of the series’ ergonomic layer (Patches 4–5), which builds on the plumbing added in Patches 1–3. The flag is not required for the core functionality (dynamic branch enumeration via `fetchRefmap`), but it provides a user-friendly way to opt into the new mode without manually editing Git config. The patch is uncontroversial and well-tested, but its fate is tied to the ongoing strategic discussion about whether to merge Patches 1–3 now (to unblock the dependent topic) and defer Patches 4–5, or to insist on the full series. If the partial merge proposal is accepted, this patch would likely be deferred.
