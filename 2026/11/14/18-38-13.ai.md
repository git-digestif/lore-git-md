This is the second patch in Harald Nordgren’s five-patch v14 series introducing `remote.<name>.fetchRefmap` and a matching-inspired fetch mode for shallow repositories. The patch extracts a helper function, `collect_upstream_from_remote()`, from the existing logic in `builtin/fetch.c` that determines whether the current branch builds on a given remote and, if so, adds its upstream refs to the list of refs to fetch. The helper is now available for reuse in Patch 3/5, which implements dynamic branch enumeration for remotes configured with only a `fetchRefmap`.

The change is a pure refactoring with no behavior change. The extracted logic is identical to the inlined version it replaces, and the helper’s signature is designed to support both the current branch (passing `NULL` as `refname`) and arbitrary branches (passed by name). The patch touches only `builtin/fetch.c`, `remote.c`, and `remote.h`, and the diff is mechanical: the ten-line block in `do_fetch()` is replaced by a single call to the new helper, and the helper itself is a straightforward copy of the original logic with added parameterization.

This patch is uncontroversial and foundational. It enables Patch 3/5’s dynamic branch enumeration logic without introducing new complexity or edge cases, and it aligns with the series’ goal of decoupling the "what to fetch" logic from the "where to store it" logic. The helper’s name and signature are clear, and the commit message succinctly explains the motivation: reusing the same logic for branches other than the current one. No review feedback has targeted this patch in earlier iterations, and it is unlikely to attract substantive critique in v14.

The patch is part of the plumbing that Junio and Phillip Wood have already endorsed in principle. Its inclusion in a potential partial merge (Patches 1–3) is unproblematic, as it is a prerequisite for Patch 3/5’s dynamic branch enumeration. If the series is split, this patch will graduate with Patches 1 and 3, leaving the ergonomic additions (Patches 4–5) for later.
