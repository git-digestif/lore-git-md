This is the third and final patch in Wasswa Edson’s three-part series converting `git credential` to use `OPT_SUBCOMMAND` from the parse-options API. It completes the transition by replacing the manual `strcmp()`-based dispatch in `cmd_credential()` with `OPT_SUBCOMMAND`, which enables per-subcommand usage strings and shell completion support via `--git-completion-helper`. The patch also removes the `NO_PARSEOPT` flag from `git.c`, exposing the command to `--list-cmds=parseopt`.

The core change is in `builtin/credential.c`, where the main dispatch logic is rewritten to use `parse_options()` with `OPT_SUBCOMMAND` entries for each subcommand (`fill`, `approve`, `reject`, `capability`). Each subcommand now has its own usage string, so `git credential <subcommand> -h` shows help specific to that subcommand rather than the generic usage. The `parse_no_args()` helper introduced in the previous patch is reused to reject extra arguments consistently across all subcommands. Error messages for missing, unknown, or extra arguments are now clearer and appear before the usage text, improving usability.

Behavior changes are limited to error paths: missing or unknown subcommands now report specific errors ("need a subcommand" / "unknown subcommand"), extra arguments are rejected with "too many arguments", and `-h` for a subcommand exits successfully with the subcommand’s usage. The core credential operations (fill, approve, reject, capability) remain unchanged, ensuring backward compatibility. The patch also adds tests in `t/t0300-credentials.sh` to verify subcommand-specific help, error messages, and argument rejection.

This patch is a clean, mechanical conversion that aligns `git credential` with Git’s established patterns for subcommand dispatch. The changes are well-scoped, thoroughly tested, and address all feedback from the v1 review. The series as a whole is now ready for merging, pending any final nits. Key technical details to track in follow-up discussion: the `OPT_SUBCOMMAND` usage, the removal of `NO_PARSEOPT`, and the new per-subcommand help behavior.
