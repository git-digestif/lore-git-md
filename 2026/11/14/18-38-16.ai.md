This is the fifth and final patch in Harald Nordgren’s v14 series introducing `remote.<name>.fetchRefmap` and a matching-inspired fetch mode for shallow repositories. The patch makes `--limited-fetch` the default when adding a remote to a shallow repository, ensuring that `git fetch` on that remote only negotiates history for branches tracked by local branches rather than every branch the remote has.

The change is small and targeted: it modifies `builtin/remote.c` to check `is_repository_shallow(the_repository)` when `limited_fetch` is unset (its default value), turning on `--limited-fetch` automatically in shallow repositories unless the user explicitly passes `--no-limited-fetch`, `-t/--track`, or `--mirror`. The documentation (`git-remote.adoc`) is updated to reflect the new default, and the test suite (`t5505-remote.sh`) adds four new tests covering the shallow-repository default, the override with `--no-limited-fetch`, and edge cases with `-t` and full repositories.

This patch is uncontroversial and well-motivated: it directly addresses the performance problem that motivated the series (shallow clones fetching every branch from a new remote) and aligns with the user experience goal of making shallow clones behave as users expect. The implementation is clean, the tests are thorough, and the documentation clearly explains the new behavior. The patch is ready for review and has no known blockers beyond the ongoing strategic discussion about whether to merge the full series or only Patches 1–3. If the partial merge proposal is accepted, this patch would be deferred to a follow-up series.
