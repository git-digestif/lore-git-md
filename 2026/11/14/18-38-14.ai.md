This is the third patch in Harald Nordgren’s v14 series introducing `remote.<name>.fetchRefmap` and a matching-inspired fetch mode for shallow repositories. The patch implements the core dynamic branch enumeration logic: when a remote has only a `fetchRefmap` (no `fetch` refspec), a refspec-less `git fetch` infers which branches to fetch from the local branches whose `@{upstream}` is on that remote. It also ensures `@{push}` resolution works correctly for such remotes by falling back to the refmap if the `fetch` refspec does not resolve the refname.

The patch touches `remote.c` and `remote.h` to add the `branches_tracking_remote()` helper and its callback data struct, which iterates over all local branches and collects their upstream refs from the given remote. In `builtin/fetch.c`, `get_ref_map()` now checks whether the remote has only a `fetchRefmap` and no `fetch` refspec; if so, it uses the new helper to build an inferred refspec and passes it to `get_fetch_map()`. The `@{push}` resolution fix is integrated into `tracking_for_push_dest()` in `remote.c`, ensuring it falls back to the refmap if the `fetch` refspec does not resolve the refname. Documentation in `remote.adoc` and `fetch-options.adoc` is updated to describe the new behavior, and a new test file (`t/t5586-fetch-refmap.sh`) verifies the dynamic branch enumeration logic, `@{push}` resolution, and edge cases like prefetch and multiple branches tracking the same upstream.

This patch is now strategically critical: Matt Hunter’s clarification that Patches 1–3 are sufficient to resolve the textual conflicts with Collin’s `ch/remote-defer-follow-remote-head-validation` topic makes it a key enabler for unblocking that work. The architectural objection to this patch (Phillip Wood’s proposal to eliminate dynamic branch enumeration) is weakened by this context, as removing the patch would reintroduce the conflicts. The implementation is clean and well-tested, with no known issues beyond the ongoing strategic discussion about whether to merge Patches 1–3 now or insist on the full series. The `@{push}` resolution fix, previously a separate patch, is now squashed into this one, addressing D. Ben Knoble’s feedback about patch organization.
