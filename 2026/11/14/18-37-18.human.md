This is a bugfix patch for the `for-each-ref` and `git refs list` commands. It resolves a long-standing segmentation fault that occurs when `--no-format` is used, which has existed since 2007. The issue arises because `--no-format` sets the format string to `NULL`, leading to a crash when `verify_ref_format()` dereferences it. The fix moves the default format assignment after command-line parsing, ensuring `--no-format` restores the default output instead of causing a crash. This aligns `for-each-ref` with the behavior of `git branch` and `git tag`, which already handle `--no-format` correctly.

The patch is minimal and well-explained, touching just four lines of code in `builtin/for-each-ref.c` and adding a six-line test in `t/for-each-ref-tests.sh`. The test verifies that `--format=<fmt> --no-format` produces the same output as no format option at all. The commit message clearly justifies why `PARSE_OPT_NONEG` was not used, as it would break consistency with other ref-listing commands.

This is the second iteration of the patch, sent solely to update the `Signed-off-by` line to comply with the project's real-name policy. No code changes were made from v1, and the fix itself appears uncontroversial. Junio has already indicated support for the approach, and the patch is effectively ready for merging. If you care about command-line option consistency or have encountered this crash, this patch is worth noting.
