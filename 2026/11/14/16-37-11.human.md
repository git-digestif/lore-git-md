This is the first patch in the **final (v9)** series adding path-related keys to `` `git repo info` ``. It introduces ``path.workingtree.absolute`` and ``path.workingtree.relative``, which expose the top-level working tree directory in a scriptable, strictly formatted way—replacing the need for `` `git rev-parse --show-toplevel` `` in scripts.

The implementation is straightforward: the keys use ``repo_get_work_tree(repo)`` and ``format_path()`` to return canonical absolute or relative paths. In bare repositories, both keys return an empty string. Tests cover execution from subdirectories, edge cases, and bare-repository behavior. The patch touches ``builtin/repo.c`` (implementation), ``Documentation/git-repo.adoc`` (documentation), and ``t/t1900-repo-info.sh`` (tests).

This patch is **uncontroversial** and aligns with all prior feedback. It is part of a **design-resolved, mechanically complete** series that has dropped all previously objected keys (``path.hooks``, ``path.cdup``) and settled on underscore-based naming (``path.workingtree`` instead of ``path.working-tree``). The only remaining architectural concern—a deferred refactoring of shared logic into ``repo-info.c``—does not affect this patch and is now lower priority. Junio has not yet queued the series, but the risk of abandonment is effectively zero.
