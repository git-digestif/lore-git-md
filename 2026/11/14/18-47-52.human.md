This is the final patch in Wasswa Edson’s three-part series converting `git credential` to use `OPT_SUBCOMMAND`. It replaces the manual `strcmp()`-based dispatch with the standard parse-options mechanism, giving each subcommand (`fill`, `approve`, `reject`, `capability`) its own usage string and making the subcommand names available to shell completion.

The patch is a clean mechanical conversion that touches only `builtin/credential.c`, `git.c`, and the test suite. It removes the `NO_PARSEOPT` flag from the `git.c` entry, exposing the command to `--list-cmds=parseopt`. Behavior changes are limited to error paths: clearer messages for missing or unknown subcommands, rejection of extra arguments before reading stdin, and subcommand-specific `-h` output. The core credential operations remain unchanged.

The implementation is straightforward and well-tested; the added test cases verify subcommand-specific help, error messages, and argument rejection. This patch completes the series and looks ready for merging once any remaining nits are addressed. The commit message clearly explains the motivation and changes, and the series as a whole is a tidy, uncontroversial refactoring that aligns `git credential` with Git’s established patterns.
