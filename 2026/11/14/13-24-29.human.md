This is the third patch in Harald Nordgren’s v7 four-patch series that introduces `git branch --delete-integrated`, a new flag that deletes branches whose changes (but not their tips) have been integrated into an upstream branch via rebase or squash merges. This patch implements the core `--delete-integrated` logic, leaving the squash-detection details (including upstream modification handling) to the fourth patch.

The patch adds the new flag, extends the `delete_merged_branches()` helper to detect branches whose changes have landed upstream, and updates the documentation to describe the behavior. The implementation is tree-based for rebase detection (no blob fetches) and uses a commit slab to cache diff results, avoiding redundant work. The new flag cannot be combined with `--delete-merged`, ensuring the two behaviors remain distinct. Test coverage verifies that rebase-merged branches are deleted, squash-merged branches are handled in the next patch, and unrelated branches are preserved.

Junio’s feedback on the previous iteration (a variable rename in `find_landed_commits()`) has been addressed, and the patch is now explicitly uncontroversial. The only remaining work for the series is the squash-detection logic in patch 4/4, which has also been updated to address performance and correctness concerns raised in review. This patch is ready for integration.
