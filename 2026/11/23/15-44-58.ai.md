This is a **refactoring** patch -- specifically `[PATCH v2 3/5]` of Adrian Ratiu's five-commit series fixing crashes when a submodule is a linked worktree. It extracts the git-directory setup logic from `submodule_move_head()` in `submodule.c` into a new static helper `setup_submodule_git_dir()`, reducing four levels of nesting in the caller. The commit explicitly states this is cosmetic cleanup with no intended functional change, and credits Junio C Hamano with suggesting the extraction.

For future thread context: this patch sits between the bugfix in `1/5` (which replaces a `BUG()` abort in `validate_submodule_legacy_git_dir()` with a proper `error()`) and the shared-helper introduction in `2/5` (`die_refusing_submodule_git_dir()`), and it precedes `4/5` (post-absorb validation for nested submodules) and `5/5` (accepting linked worktrees as valid submodule git dirs). The moved code handles three cases: when `old_head` exists and the submodule already uses a gitfile, it validates the git dir via `validate_submodule_git_dir()` and dies via the new helper if invalid; when `old_head` exists but the git dir needs absorbing, it calls `absorb_git_dir_into_superproject()`; and when `old_head` is NULL (new submodule), it connects the work tree and resets the index. The forced-move reconnection via `connect_work_tree_and_git_dir()` with force flag `1` is also moved into the helper, preserving the exact same control flow that `submodule_move_head()` now delegates to when not in dry-run mode.

The patch touches only `submodule.c` (37 insertions, 35 deletions), moving the block that previously lived inside the `if (!(flags & SUBMODULE_MOVE_HEAD_DRY_RUN))` check in `submodule_move_head()`. Future discussion of patches `4/5` and `5/5` will modify this extracted helper -- patch 4 inserts validation immediately after `absorb_git_dir_into_superproject()`, and patch 5 alters the helper to detect and handle linked-worktree git dirs via `validate_submodule_worktree_dir()` -- so understanding that the git-dir setup logic now lives in `setup_submodule_git_dir()` rather than inline in `submodule_move_head()` is essential for following those later changes.
