This is patch 2/3 of a three-patch bugfix series (v4) by Aniket Gupta addressing a bundle-uri regression where unresolvable relative URIs cause `git clone` or `git fetch` to die. Specifically, this patch improves the diagnosability of the error message emitted by `relative_url_gently()`, a non-dying helper introduced in patch 1/3 of the same series.

The change is confined to `remote.c` within `relative_url_gently()`: when `chop_last_dir()` fails and returns -1, the error message now formats the original input parameter `remote_url` rather than the intermediate, partially-stripped `remoteurl` buffer. Previously, with a base URL like "./a/b" and excessive "../" components, the fatal message would confusingly report `cannot strip one component off url '.'`; it now correctly names the full original URL (e.g., `https://host.example/a`). A corresponding unit test added in `t/t0060-path-utils.sh` asserts that `test-tool submodule resolve-relative-url` produces the expected fatal message containing the unmodified input URL.

This patch builds directly on patch 1/3, which introduced `relative_url_gently()` as a non-fatal variant of `relative_url()` that populates a `strbuf` error instead of calling `die()`. By naming the original URL, the error output becomes actionable for users debugging bundle lists. Patch 3/3 of the series will use this gentle variant in `bundle_list_update()` to skip unresolvable bundle URIs with this improved error message rather than aborting the entire operation. The series remains under review; credential-anonymization logic from earlier iterations has been dropped per reviewer feedback, leaving this patch focused purely on error-message clarity.
