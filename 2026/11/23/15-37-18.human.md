This is a follow-up discussion in Junio C Hamano's bugfix series for `strbuf_getwholeline()`. He is explaining the rationale behind the series structure: rather than adding temporary `strbuf_reset()` calls in patches 2-4 to make the failing tests pass immediately (and then removing them in patch 5 when the root cause is fixed), he chose to leave patches 2-4 as `test_expect_failure` cases with detailed commit messages walking through how each bug manifests. He considered the alternative -- adding code in early patches only to delete it in a later one -- awkward and wasteful, so the long commit messages serve as the documentation of the bug mechanics instead.
