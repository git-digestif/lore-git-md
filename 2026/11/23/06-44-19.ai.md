This is a cover letter for the v4 iteration of a three-patch bugfix series targeting the bundle-uri subsystem. The series fixes a regression introduced in Git 2.41 where `git clone` or `git fetch` dies when a bundle list contains a relative URI that cannot be resolved (for example, too many `../` components). The goal is to log the error and skip the problematic bundle instead of aborting the entire operation.

Compared to v3, patch 2/3 has been retitled and simplified: the credential-anonymization logic has been dropped entirely at Derrick Stolee's suggestion, while the portion that names the original input URL in error messages is retained per Patrick Steinhardt's diagnosability concern. Patch 3/3 carries a corrected commit message clarifying that for a server-advertised bundle list, parsing stops at the bad entry and earlier bundles are still used, whereas a list passed via `--bundle-uri` is rejected as a whole; in both cases the clone falls back to fetching from the remote. The series was rebased onto current master without conflicts.

Technically, the series introduces `relative_url_gently()` in `remote.c` (declared in `remote.h`), a non-dying variant of `relative_url()` that returns NULL and populates a `strbuf` error message on failure, with the original `relative_url()` becoming a thin wrapper that dies on failure. `chop_last_dir()` was modified to return -1 without dying. Patch 3 updates `bundle_list_update()` in `bundle-uri.c` to use the gentle variant and skip unresolvable URIs. Tests were expanded in `t/t0060-path-utils.sh` and `t/t5750-bundle-uri-parse.sh`. No on-disk format changes.

The cover letter notes a minor textual conflict with `tb/config-null-values` currently in `next`, which adds a `!value` check in `bundle_list_update()` just above the line patch 3 modifies; the author confirmed the two coexist with the `!value` check placed first, and verified the merge with t0060, t5558, and t5750. The series remains under review and has not yet been queued in `seen`. A possible follow-up to add a configuration toggle restoring the old die-on-error behavior is explicitly deferred.
