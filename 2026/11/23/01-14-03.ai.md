This is a **bugfix for Git v3 hash-algorithm selection**, the fourth iteration of a patch series fixing `git init` behavior under `WITH_BREAKING_CHANGES=1`. brian m. carlstadt restructures `repository_format_configure()` in `setup.c` so that the hash algorithm is chosen in a strict priority order: an explicit command-line `--object-format` always wins; otherwise an existing repository's detected algorithm is reused; failing that, the `GIT_DEFAULT_HASH` environment variable is consulted, then `init.defaultObjectFormat` from config, and finally `GIT_HASH_DEFAULT` (which resolves to SHA-256 in breaking-changes builds). The patch also moves the reinitialization safety check so that if the finally-selected algorithm differs from an existing repository's `hash_algo`, `git init` dies with "attempt to reinitialize repository with different hash", preventing silent corruption while allowing config or environment values to be ignored on reinit.

The diff touches `setup.c` and `t/t0001-init.sh`. In `setup.c`, the logic previously scattered across `read_repository_format()` and early branches of `repository_format_configure()` is consolidated into a single if-else chain that computes a local `hash` variable, with the fatal mismatch check placed in the existing `repo_fmt->version >= 0` block alongside the ref-storage-format checks. `repo_fmt->hash_algo` is now assigned once at the end from the computed `hash`. The commit message explains that the old code never treated `GIT_HASH_DEFAULT` as a fallback and could silently change a repository's hash on reinit when `init.defaultObjectFormat` was set.

Three new tests are added to `t/t0001-init.sh`: one verifying that a fresh `git init` produces `$GIT_TEST_BUILTIN_HASH` (covering the default-selection path), one confirming that reinitializing with a conflicting `--object-format` fails fatally, and one ensuring that a global `init.defaultObjectFormat` does not alter the hash of an existing repository on reinit. The v3 concern about test isolation is addressed by wrapping each `sane_unset GIT_DEFAULT_HASH` in a subshell so the environment is restored for subsequent tests. Patrick Steinhardt has signalled satisfaction with the approach, and Junio C Hamano's outstanding questions from v3 (the `GIT_HASH_DEFAULT`/`SHA1_LEGACY` initialization rationale, the defensive "no detected hash" branch, and the test-environment hygiene) appear resolved by the updated commit message, the preserved defensive else-branch, and the subshell scoping. The series remains under review, with no approval recorded yet.
