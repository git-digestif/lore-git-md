This is a substantive review of Stanislav Aleksandrov's RFC patch proposing the `^/` syntax for root-relative submodule URLs. D. Ben Knoble engages deeply with the implementation, first clarifying his understanding of the fork-depth problem that motivates the feature, then raising specific technical concerns. He questions why the code suppresses a warning when `^/` URLs fall back to the current working directory, since the syntax would not resolve meaningfully there. He also expresses discomfort with the hand-rolled string parsing in `root_relative_url()` and asks whether an existing dependency could handle URL manipulation instead, or at least whether the code makes the supported input forms clear enough to spot the unsupported ones. On documentation, he suggests restructuring the `git-submodule` man page to list the three URL forms as a bulleted list rather than embedding the `^/` explanation mid-sentence, and proposes cross-referencing `gitmodules.adoc` back to `git-submodule.adoc` to avoid repetition. He asks whether the new check in `check_submodule_url()` guards against the same credential-injection vulnerability that `count_leading_dotdots()` protects against, and expresses confusion about why `^//evil.example.com` is rejected if it would simply resolve to a path on the same host. Finally, he suggests renaming the test case away from the GitLab-specific term "subgroup" to something more general. Overall the review is constructive and thorough, probing both the security implications and the documentation quality without blocking the proposal.
