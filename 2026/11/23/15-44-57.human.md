This is a bugfix, specifically the second patch in Adrian Ratiu's five-patch v2 series addressing crashes when a submodule is a linked worktree. It fixes a misleading error message: previously, when Git refused to use a submodule's git dir, it unconditionally suggested enabling `extensions.submodulePathConfig`, even when that extension was already enabled. The patch introduces a shared helper, `die_refusing_submodule_git_dir()`, which checks `the_repository->repository_format_submodule_path_cfg` and only advises enabling the extension when it is actually disabled.

The helper replaces the identical die-and-advise logic in three call sites: `submodule_move_head()` and `submodule_name_to_gitdir()` in `submodule.c`, and `clone_submodule()` in `builtin/submodule--helper.c`. This ensures consistent error output across all paths that reject a git dir. The commit message notes this behavior was reported by Andreas Wendleder alongside the original crash.

Test coverage is added in `t/t7425-submodule-gitdir-path-extension.sh`, verifying that when the extension is already enabled, the error message does not mention `extensions.submodulePathConfig`. Conversely, `t/t7450-bad-git-dotfiles.sh` is updated to expect the suggestion to appear when the extension is disabled, confirming the conditional logic works in both directions.

As part of the v2 series, this patch implements feedback from Junio C Hamano's review of v1, where he approved the shared-helper approach. The series remains under review, with no merge to `master`, `next`, or `seen` yet.
