This is a **review comment** on the fourth iteration of brian m. carlstadt's patch series fixing hash-algorithm selection for `git init` under `WITH_BREAKING_CHANGES=1`. Junio C Hamano identifies a test-isolation bug in `t/t0001-init.sh`: the test named 're-init does not modify hash from config' wraps its body in a subshell, but uses `test_when_finished` to register cleanup for the global config change made by `test_config_global`. Because `test_when_finished` registers cleanup in the current shell context and the subshell exits without triggering the parent's cleanup, the global `init.defaultObjectFormat` setting leaks into subsequent tests, causing failure ("not ok 62").

Junio proposes a two-line fix in `t/t0001-init.sh`: add `test_when_finished "test_unconfig --global init.defaultObjectFormat"` at the top level of the test (outside the subshell) so the cleanup runs reliably, and replace the `test_config_global` call inside the subshell with a plain `git config --global init.defaultObjectFormat "$other"`. This keeps the subshell environment isolated while ensuring the global config is removed when the test completes.

The email is a reply within the ongoing thread where v4 of the series has already received broad approval from Junio and Patrick Steinhardt, with only minor cosmetic suggestions outstanding. This particular comment is a substantive catch of a real test-hygiene issue rather than a stylistic nit -- it prevents cross-test contamination in the shell-based test suite. The fix is mechanical and does not alter the C logic in `setup.c` that the series restructures; it only corrects the test scaffolding so the new test cases verifying reinitialization safety actually pass cleanly.
