This is a bugfix -- specifically the third patch in Johannes Schindelin's five-part v2 series hardening Git against integer overflows flagged by Coverity. The patch redefines the contract of `write_in_full()` in `wrapper.c` so that it returns `int` (0 on success, -1 on error) rather than `ssize_t`, eliminating the need to accumulate a byte count that could overflow when the requested `size_t` exceeds `SSIZE_MAX`. Because the function loops until the entire buffer is written or an error occurs, callers already know how many bytes were requested, so returning a status code instead of a total is both simpler and safe by construction. The inline helper `write_str_in_full()` in `wrapper.h` is updated to match.

The change touches three callers to accommodate the new return type: `imap-send.c` now derives the byte count from the input length when the write succeeds, `notes-merge.c` collapses its manual write loop into a single call that only checks for errors (preserving the existing `EPIPE` special case), and the reftable unit test adjusts its assertion from comparing a byte count to checking for zero. The patch also introduces a new clar unit-test file, `t/unit-tests/u-wrapper.c`, covering successful writes, empty writes, and error paths, and wires it into both the Makefile and meson build.

Within the broader thread, this v2 revision replaces an earlier approach that relied on compiler-specific overflow-detection macros; the API redesign sidesteps portability concerns previously raised about `SSIZE_MAX` width mismatches on platforms like NonStop. The commit message credits Phillip Wood for assistance, and the change appears well-motivated and cleanly scoped. Combined with the accompanying tests and caller updates, this looks like a solid, low-risk hardening that is ready for integration once the series receives final acknowledgment.
