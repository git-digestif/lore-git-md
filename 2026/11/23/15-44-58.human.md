This is a **refactoring** patch, the third of five in Adrian Ratiu's v2 series fixing crashes when a submodule is itself a linked worktree. It extracts the git dir setup logic from `submodule_move_head()` in `submodule.c` into a new private helper called `setup_submodule_git_dir()`, suggested by Junio C Hamano to reduce the four-level nesting that made the original code hard to read and extend.

The moved code handles three cases: absorbing a `.git` directory into the superproject when the submodule does not use a gitfile, validating that an existing gitfile points to the correct git dir, and forcing a reconnection when the `SUBMODULE_MOVE_HEAD_FORCE` flag is set. The patch is purely mechanical -- the commit message explicitly states no functional change is intended, and the diff confirms this by moving the block verbatim into the new function.

This cleanup prepares the ground for the subsequent patches in the series, particularly patch 4 which adds validation after absorption and patch 5 which accepts linked worktrees as valid git dirs. By isolating the setup logic, those later changes can modify a single well-defined function rather than digging through nested conditionals. The patch looks clean and well-motivated; it does exactly what it claims without introducing risk.
