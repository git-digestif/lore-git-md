This is a maintainer review of a documentation patch, flagging one specific hunk as a regression while approving the rest.

Junio C Hamano accepts the v4 changes to the commit message formatting and the short-option bullet point (the "into separate words" wording suggested by Andy Koppe), but he objects to the rewording of the bullet about disambiguating revisions from paths. The v4 text currently says that when arguments can be misunderstood, "they can be disambiguated by placing `--` between them," which Junio argues is less clear than the earlier phrasing that mentioned placing `--` "before or after it." He explains with concrete examples that the correct position depends on intent: `git log -- main` traces a file's history, `git log main --` shows a branch's history, and `git log next -- main` is needed when you want a file's history up to a specific branch tip. Saying `--` goes "between" them suggests a single fixed solution that does not cover these cases. While he finds the other parts of v4 to be improvements over v3, he considers this particular change a regression that should be reverted before the patch can move forward.
