This is a documentation patch, the second version of a standalone change from brian m. carlson that warns users against using `http.extraheader` to pass authentication credentials. The patch updates three files: `Documentation/config/http.adoc`, `Documentation/git.adoc`, and `Documentation/gitfaq.adoc`. In `http.adoc`, it adds a note to the `http.extraHeader` config entry explaining that using it for credentials can expose them to every server Git contacts or to other users on the system, and that it can break external tools like Git LFS by creating duplicate `Authorization` headers; it recommends credential helpers instead, noting they support modern methods including Bearer tokens. The patch also generalizes a mention in `git.adoc` that previously singled out `http.extraHeader` as containing sensitive data, and appends a similar warning to the FAQ entry about passwords in URLs.

Version two addresses the only feedback received so far: Junio C Hamano had noted in the previous iteration that the proposed text was missing the word "used," and this version includes that fix. No substantive technical objections have been raised. The commit message provides a clear motivation -- users frequently misuse `http.extraheader` for credentials despite the security risks and the known incompatibility with tools that manage their own auth headers -- and the change is confined to documentation with no code or test modifications. The patch looks straightforward and well-targeted, steering users toward the credential helper mechanism that Git and Git LFS handle correctly.
