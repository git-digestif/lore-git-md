This is a **bugfix** cover letter for v2 of a five-patch series addressing crashes and broken behavior when a submodule is itself a linked worktree and the superproject performs a recursive checkout. Adrian Ratiu expands the original three-patch v1 into five commits, incorporating all of Junio C Hamano's review feedback from the previous round. The series still targets the bug reported by Andreas Wendleder where `validate_submodule_legacy_git_dir()` in `submodule.c` hits a `BUG()` because linked-worktree gitdirs such as `.git/modules/sub/worktrees/sub1` do not end with the submodule name.

The five patches restructure the fix substantially from v1. Patch 1 retains the change to return a proper `error()` instead of `BUG()` for an unexpected git dir path but drops the contested explanatory comment entirely. Patch 2 introduces a shared helper `die_refusing_submodule_git_dir()` in `submodule.c` (declared in `submodule.h`) that checks `the_repository->repository_format_submodule_path_cfg` and only advises enabling `extensions.submodulePathConfig` when the extension is actually disabled; this helper replaces the unconditional misleading hint in all three call sites: `submodule_move_head()`, `submodule_name_to_gitdir()`, and `clone_submodule()` in `builtin/submodule--helper.c`. Patch 3 extracts the git dir setup logic from `submodule_move_head()` into a new private function `setup_submodule_git_dir()` to reduce nesting. Patch 4 adds validation of the git dir immediately after `absorb_git_dir_into_superproject()` has run, closing the nested-submodule edge case Junio identified where recursive absorption could leave `is_worktree` unset and trigger an unwanted reconnection. Patch 5 accepts a linked worktree as a valid submodule git dir via a simplified `validate_submodule_worktree_dir()` helper that uses `get_common_dir_noenv()` to confirm the git dir lives under `<common-dir>/worktrees/<id>` and validates the common dir against the submodule name; when a worktree is detected, `submodule_move_head()` now skips rewriting the `.git` file and skips unsetting `core.worktree`.

For future thread summarization, the key control-flow change is that `submodule_move_head()` now calls `setup_submodule_git_dir()` (unless in dry-run mode), which returns an `is_worktree` flag. Inside that helper, after ensuring `path/.git` is a gitfile -- either because it already was one or because absorption just made it one -- the code unconditionally validates the resulting git dir and sets `is_worktree` before the forced-move block. The forced-move reconnection via `connect_work_tree_and_git_dir()` is now guarded by `!is_worktree`, preventing a linked worktree from being hijacked by the superproject's expected modules path. The series applies on base commit `e1ec09b23c8e0deb21a0b95ac5996422277395d4`.

Test coverage spans `t/t2405-worktree-submodule.sh`, `t/t7425-submodule-gitdir-path-extension.sh`, and `t/t7450-bad-git-dotfiles.sh`. New tests verify that recursive checkout accepts a submodule worktree in both legacy and `extensions.submodulePathConfig` modes, that a submodule worktree containing a nested `.git` directory (triggering the absorb path) is handled correctly, that removal of a submodule worktree works, and that forged worktree git dirs are rejected with a clear error rather than a `BUG()`.

The series remains under review with no merge to `master`, `next`, or `seen`. V2 resolves all outstanding design questions from v1 -- the shared-helper approach for the extension advice is settled, the nested-submodule absorb case is fixed by patch 4, and the worktree validation is simplified and integrated into the extracted setup function.
