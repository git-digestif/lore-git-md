This is a refactoring patch that lays the groundwork for a bundle-uri bugfix -- specifically, patch 1/3 of Aniket Gupta's v4 series "bundle-uri: skip unresolvable relative URIs instead of dying."

The patch introduces `relative_url_gently()` in `remote.c` (declared in `remote.h`), a non-dying variant of the existing `relative_url()` helper. Where `relative_url()` calls `die()` when a URL contains more `../` components than the base URL can absorb, the new gentle variant returns NULL and populates a `struct strbuf` with the error reason instead. The original `relative_url()` is reimplemented as a thin wrapper that calls the gentle version and dies on failure, preserving existing behavior for current callers. Internally, `chop_last_dir()` is modified to return -1 rather than dying when there is nothing left to strip.

As the first patch in the series, this is purely mechanical API preparation: it touches only `remote.c` and `remote.h`, changes no behavior for existing code paths, and introduces no tests of its own (those arrive with later patches in `t/t0060-path-utils.sh`). The commit message is clear and concise, and the change looks clean and well-scoped -- exactly the kind of foundational refactoring that makes the actual bundle-uri fix in patch 3/3 straightforward to implement.
