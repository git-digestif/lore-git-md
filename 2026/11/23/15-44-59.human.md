This is a **bugfix**, the fourth patch in Adrian Ratiu's five-part v2 series fixing crashes and misleading errors when a submodule is itself a linked worktree. Specifically, this patch closes a nested-submodule edge case that Junio C Hamano identified during the v1 review.

The problem is that `submodule_move_head()` absorbs a submodule's `.git` directory when one exists, but if the submodule already used a gitfile pointing elsewhere, the old code skipped validating that target after absorption. As a result, Git could silently replace a bad or unexpected git dir instead of rejecting it. Patch 4 restructures the logic inside the extracted `setup_submodule_git_dir()` helper so that validation runs unconditionally once `path/.git` is confirmed to be a gitfile -- whether it already was one or absorption just converted it. This ensures Git refuses a mismatched git dir with a clear error rather than proceeding with an invalid path.

The patch also adds a regression test in `t/t7450-bad-git-dotfiles.sh` that creates a nested `.git` directory to trigger the absorb path, then verifies that a gitfile pointing to a renamed git dir (`.git/modules/elephant` instead of `.git/modules/hippo`) is rejected with the expected "not a suffix of git dir" message and that the original `.git` file is left untouched.

The change is small and mechanical, crediting Junio C Hamano for suggesting the restructure. It fits cleanly into the series' overall goal of making submodule git-dir handling consistent and safe across legacy and `extensions.submodulePathConfig` modes. The series remains under review with no merge to `master`, `next`, or `seen` yet.
