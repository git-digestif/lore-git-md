This is a review-thread reply in Adrian Ratiu's three-patch bugfix series for the `compatObjectFormat` interoperability layer, specifically addressing patch 2/3 which makes `git rev-parse --output-object-format` die when an object cannot be mapped to the requested hash format instead of silently printing the wrong OID.

Adrian clarifies the scope of the fix in response to Junio C Hamano's concern that the commit message was ambiguous about "single revision": multiple single-revision arguments like `git rev-parse --output-object-format=sha1 main next` are indeed covered, while range arguments such as `A..B` or `A...B` that rev-parse expands internally are not. He commits to clarifying this wording in v3. He also acknowledges Junio's praise for the test design, crediting Patrick Steinhardt for the approach of writing an object before enabling `extensions.compatObjectFormat` so it receives no compat mapping.

The patch itself has maintainer approval; the only outstanding item is the commit-message wording tweak promised for the next iteration.
