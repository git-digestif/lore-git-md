This is a substantive review of a bugfix patch targeting the sequencer's handling of unborn branches. Phillip Wood responds to Wonseok Oh's fix for an uninitialized `oid` variable in `sequencer_pick_revisions()` when cherry-picking onto an orphan branch. While endorsing the immediate fix as correct for the uninitialized-variable problem, Phillip Wood traces the issue to commit `0f974e2124` (cherry-pick: allow to pick to unborn branches, 2016-06-06), which introduced the use of the uninitialized `head` variable by allowing picks onto unborn branches where `repo_get_oid()` fails.

The review highlights several behavioral inconsistencies in the current design: `sequencer_rollback()` refuses to abort when HEAD is unborn and leaves the sequencer state intact, making it impossible to abort a multi-pick sequence started on an orphan branch; single-commit reverts are allowed on unborn branches (a separate code path inserted by `7acaaac275` in 2011) while multi-commit reverts are not; and the unborn-branch check itself dates to `04d3d3cfc4` (2011) without documented rationale. Phillip Wood also notes an inconsistency in state representation: `rollback_is_safe()` expects a null OID for unborn branches, but `update_abort_safety_file()` writes an empty file in that case, suggesting these should be unified. He proposes that future work (separate from this series) could allow aborting cherry-picks on unborn branches, remove the unborn-branch check for multi-commit reverts, or move the check to cover single picks as well.
