This is a surface-level review reply from Junio C Hamano on patch 2/4 of Dirk Gouders's v5 series, which corrects the `utf8_strnwidth()` documentation comment. Junio approves the change but suggests replacing the word "terminated" with "bounded" in the proposed commit message wording, noting it reads less awkwardly. The patch itself fixes two documentation errors: the comment incorrectly claimed the function works on a NUL-terminated string when it is actually bounded by the `len` argument, and incorrectly stated it returns `strlen()` for invalid UTF-8 when it actually returns `len`. With this minor wording tweak, Junio considers the patch ready.
