This is a bugfix patch, specifically the second of five in Johannes Schindelin's v2 series addressing integer overflows flagged by Coverity. It targets `http.c`, changing the local variable `posn` in `fwrite_sha1_file()` from `int` to `size_t` to match the type of the total size parameter `size` (itself `size_t`). The mismatch meant that if the HTTP response body delivered to the curl write callback exceeded `INT_MAX` (approximately 2 GB), the `int` accumulator would overflow, causing a heap under-read when indexing into the buffer and potentially leaking adjacent heap memory to the temporary object file before the hash check rejected the corrupt object. While curl typically delivers data in small chunks (around 16 KB) making the overflow unlikely in practice, the function interface accepts arbitrary sizes and the accumulation occurs across the write loop within a single invocation, so the type mismatch is a genuine defect that Coverity flagged. The change is a one-line type fix with no behavioral change for normal inputs. The patch has been reviewed and accepted by Patrick Steinhardt and Junio C Hamano, with the latter confirming the change is correct after verifying that `xwrite()` clamps writes via `MAX_IO_SIZE`; a suggestion to use `off_t` instead was rejected on the grounds that `posn` indexes a contiguous in-core buffer sized in `size_t`. This patch remains unchanged from v1 of the series and is considered uncontroversial and ready for integration.
