This is a bugfix -- specifically the first patch of a five-patch v2 series (`[PATCH v2 1/5]`) from Adrian Ratiu addressing a crash when a submodule is a linked worktree.

The patch changes `validate_submodule_legacy_git_dir()` in `submodule.c` to return a normal `error()` instead of aborting with `BUG()` when the git dir path read from a submodule's `.git` file does not end with the submodule's name. The commit message traces the history carefully: the `BUG()` was added in 2019 when callers only passed Git-computed paths, but commit `9cf8547320` in 2024 introduced a caller that reads the path from disk, making the assertion reachable by user setup rather than by a Git bug. This turns a hard crash into a graceful "refusing to create/use ..." error consistent with the `extensions.submodulePathConfig` behavior.

This is the opening salvo of the series; the remaining four patches (not shown here) build the actual linked-worktree handling on top of this safer error path. The commit includes a regression test in `t/t7450-bad-git-dotfiles.sh` that renames a submodule's git dir and verifies the checkout now fails with the new error message rather than a `BUG` output.

The patch looks well-crafted: the commit message explains the root cause with specific commit references, and the change itself is minimal and targeted. The series remains under review with no merge to `master`, `next`, or `seen` yet.
