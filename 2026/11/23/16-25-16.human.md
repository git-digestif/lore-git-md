This is a **substantive review** of the v4 bugfix patch series fixing `git init` hash-algorithm detection under `WITH_BREAKING_CHANGES=1`. Junio C Hamano identifies a test-infrastructure bug in the newly added test "re-init does not modify hash from config": the helper `test_config_global` internally uses `test_when_finished` to clean up the global config, but because the test runs inside a subshell, that cleanup never executes, causing the global `init.defaultObjectFormat` setting to leak into subsequent tests.

Junio proposes a concrete fix that keeps the test logic inside the subshell (needed for the `sane_unset GIT_DEFAULT_HASH` scoping) while moving the cleanup responsibility outside: he suggests adding a `test_when_finished "test_unconfig --global init.defaultObjectFormat"` at the top level alongside the existing `rm -rf repo` cleanup, and replacing the `test_config_global` call inside the loop with a plain `git config --global` so the subshell no longer depends on the broken cleanup mechanism. This is a precise, well-placed correction that preserves the test's intent while fixing the environmental hygiene issue he had previously raised.

The review comes as the series has otherwise been approved -- Junio had already confirmed the v4 restructuring of `repository_format_configure()` "all looks good" -- so this represents a final polish rather than a substantive objection. The patch series itself fixes `git init` so that new repositories correctly default to SHA-256 when Git is built with `WITH_BREAKING_CHANGES=1`, while ensuring existing repositories are never silently reinitialized with a different hash. The topic remains under review and is expected to appear in an upcoming "What's cooking" report for `next` or `seen`; it has not yet been recorded as merged to any integration branch.
