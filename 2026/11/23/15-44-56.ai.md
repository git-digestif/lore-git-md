This is a **bugfix**, specifically patch 1 of 5 in Adrian Ratiu's v2 series (`[PATCH v2 1/5]`) addressing a crash when a submodule is a linked worktree. The series responds to a bug report from Andreas Wendleder and expands on a previous v1 iteration by incorporating Junio C Hamano's review feedback.

The patch modifies `validate_submodule_legacy_git_dir()` in `submodule.c` to return a proper `error()` instead of aborting via `BUG()` when the git dir path read from a submodule's `.git` file does not end with the submodule name. The commit message traces the root cause to commit `9cf8547320` (2024-01-28), which added a caller passing a path read from disk, making the `BUG()` -- originally added in `a8dee3ca61` (2019-10-01) when all callers passed Git-computed paths -- reachable. The fix ensures the command dies with the standard "refusing to create/use ..." error message rather than a `BUG` abort, matching the behavior when `extensions.submodulePathConfig` is enabled.

A new test in `t/t7450-bad-git-dotfiles.sh` verifies that `checkout -f --recurse-submodules` rejects a gitfile pointing to a renamed git dir (e.g., `.git/modules/elephant` instead of `.git/modules/hippo`) with the expected error message and without emitting "BUG".

The series applies on base commit `e1ec09b23c8e0deb21a0b95ac5996422277395d4` and remains under review with no merge to `master`, `next`, or `seen`.
