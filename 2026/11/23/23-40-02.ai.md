This is a maintainer reply in a concluded feature-request thread about adding safety mechanisms to `git reset --hard`. Junio C Hamano responds to Steven Rostedt's report that running `git reset` without `--hard` produced a massive diff (72,642 files) when trying to fast-forward a branch. Junio acknowledges the impracticality, noting that while simple cases can be recovered with `git diff | git apply -R`, recovery becomes messier when paths were added or removed between the index/working tree and the target state. He confirms that he personally never uses bare `git reset` (without `--hard`) for cleaning up working trees for exactly this reason. The email contains no patch and introduces no new technical proposal; it reinforces the maintainer's earlier position -- established earlier in the thread -- that `builtin/reset.c` will not gain config-based safety prompts, `--force` bypass flags, or pre-command hooks for `git reset --hard`, and that the original poster has accepted this by planning a personal wrapper script instead.
