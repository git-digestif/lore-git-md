This is a **bugfix cover letter** for the second iteration of a five-patch series fixing crashes in the submodule subsystem when a submodule is itself a linked worktree of its repository. Adrian Ratiu sends `[PATCH v2 0/5]` in response to review feedback from Junio C Hamano on the original three-patch version, expanding the series to address a nested-submodule edge case that could still trigger the crash via a different code path.

The core problem remains the one reported by Andreas Wendleder: when `submodule.recurse=true` and a submodule's `.git` file points to a linked-worktree git dir (such as `.git/modules/sub/worktrees/sub1`), recursive checkout either hits a `BUG()` abort or produces a misleading hint about `extensions.submodulePathConfig`. The v2 series converts the `BUG()` into a proper error, moves the `submodulePathConfig` suggestion into a shared helper that only fires when the extension is actually disabled, and accepts linked-worktree git dirs as valid after validating they sit under the expected `worktrees/` path.

Two new patches (3/5 and 4/5) restructure `submodule_move_head()` by extracting the git-dir setup into a `setup_submodule_git_dir()` helper and ensuring validation happens after a git dir is absorbed, which closes the nested-submodule hole Junio identified where `is_worktree` could remain unset and the code might still attempt to reconnect the worktree. The series touches `submodule.c`, `builtin/submodule--helper.c`, and three test scripts, and remains under review with no merge to `master`, `next`, or `seen` yet.
