This is a **bugfix for Git v3 compatibility**, specifically fixing how `git init` selects the default hash algorithm. The patch ensures that when Git is built with `WITH_BREAKING_CHANGES=1` (the Git v3 mode), new repositories default to SHA-256 via `GIT_HASH_DEFAULT` instead of incorrectly defaulting to SHA-1. It also prevents `git init` from silently changing the hash algorithm when reinitializing an existing repository with a conflicting `--object-format`, `GIT_DEFAULT_HASH`, or `init.defaultObjectFormat` setting.

The fix restructures `repository_format_configure()` in `setup.c` so that an explicit command-line `--object-format` always wins, followed by the existing repository's hash (if any), then the environment variable, then config, and finally the build-time default. If the chosen algorithm differs from an existing repository's algorithm, the command dies with "attempt to reinitialize repository with different hash" rather than corrupting the repository. The patch adds three tests to `t/t0001-init.sh` covering the default object format selection, refusal to reinitialize with a mismatched hash, and confirmation that reinitialization preserves the original hash even when config specifies otherwise.
