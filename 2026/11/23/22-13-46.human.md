This is the final patch in a five-part bugfix series addressing integer overflows flagged by Coverity, specifically targeting relative-date parsing in `date.c`. As `[PATCH v2 5/5]`, it completes Johannes Schindelin's v2 effort to harden `approxidate` against signed-overflow undefined behavior that could occur when multiplying a parsed quantity by a unit length (weeks, months, etc.) before converting to `time_t`.

The patch modifies `approxidate_alpha()` to perform the multiplication in `uintmax_t` using `unsigned_mult_overflows()` and `date_overflows()` checks, returning `NULL` (a parse error) if the product exceeds the range of `time_t` rather than silently wrapping. It also updates `approxidate_digit()` to reject any parsed integer greater than `INT_MAX` before narrowing to `int`, and adjusts `approxidate_str()` to propagate these new error returns. The commit message notes the inputs are non-negative, so unsigned checks suffice, and emphasizes that checking the converted value alone would be too late because signed overflow is undefined behavior.

Test coverage is added in `t/t0006-date.sh`, including a case parsing "4000 weeks ago" and a negative test verifying that an absurdly large quantity (near `UINT64_MAX`) is rejected as an invalid timestamp rather than causing undefined behavior. The patch touches only `date.c` and the test file, with no changes to on-disk formats or CLI surfaces.

Within the broader series, this patch follows four others addressing overflow risks in `archive-tar.c`, `http.c`, and the wrapper I/O functions (`wrapper.c`, `wrapper.h`); patches 1 and 2 are considered uncontroversial, while this fifth patch along with the revised wrapper changes await final acknowledgment.
