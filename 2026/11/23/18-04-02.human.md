This is a substantive review of the RFC patch proposing `^/` submodule URLs. Junio C Hamano engages directly with the implementation, raising two points: a terminology nit and a genuine parsing bug.

On terminology, he notes that calling `^/` an "absolute path" is misleading for scp-style URLs like `git@host:group/super.git`, which lack a leading slash after the colon; he suggests describing it instead as a path relative to the server root.

More importantly, he identifies a flaw in `skip_bracketed_host()`. The function scans for `@[` without stopping at the first path separator, so remote URLs containing literal `@[` in the path portion -- such as `host:dir/@[x]/repo.git` or `host:dir/@[x]:y/repo.git` -- can cause the parser to misidentify the host boundary. In the second example, this produces a corrupt URL like `host:dir/@[x]:org/lib.git` rather than the intended `host:org/lib.git`. He suggests the scan should stop at the first slash to avoid these cases.
