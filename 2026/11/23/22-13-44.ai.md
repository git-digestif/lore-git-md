This is a bugfix and API refactoring in the wrapper I/O layer, specifically patch 3 of 5 in Johannes Schindelin's v2 series hardening Git against Coverity-flagged integer overflows. The patch eliminates a potential `ssize_t` overflow in `write_in_full()` by changing its return type from `ssize_t` (total bytes written) to `int` (0 on success, -1 with `errno` set on failure), since callers already know the requested count on success and the accumulation itself could overflow for `size_t` inputs exceeding `SSIZE_MAX`. The companion inline `write_str_in_full()` in `wrapper.h` is updated to match, returning `int` instead of `ssize_t`.

The change touches `wrapper.c` and `wrapper.h` for the core implementation, and updates three call sites to accommodate the new contract: `imap-send.c` now maps a successful write to the requested length, `notes-merge.c` simplifies its write loop to a single call checking for error (while preserving `EPIPE` tolerance), and `t/unit-tests/u-reftable-stack.c` adjusts an assertion from expecting a byte count to expecting 0. A new clar unit-test file `t/unit-tests/u-wrapper.c` adds coverage for successful writes, empty writes, and error handling, registered in both the `Makefile` and `t/meson.build`.

Within the broader series, this patch represents the v2 approach to the wrapper subsystem: rather than adding overflow-checking macros (as attempted in v1 via withdrawn patch 4), the API is redesigned so the total byte count never needs to fit in a signed type. This contrasts with patch 2 (`http.c`), which changed `posn` from `int` to `size_t`, and patch 5 (`date.c`), which uses `uintmax_t` arithmetic with explicit overflow checks. The series as a whole targets latent undefined behavior across archive-tar, HTTP fetch, wrapper I/O, and date parsing, with patches 1 and 2 considered uncontroversial and this revised patch 3 awaiting final acknowledgment.

The commit message does not audit external callers of `write_in_full()` outside the Git tree, leaving the migration burden for downstream consumers unaddressed; within the codebase itself, all identified callers are updated.
