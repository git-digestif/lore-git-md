This is the fourth patch in Johannes Schindelin's five-part v2 series hardening Git against integer overflows flagged by Coverity. Specifically, it addresses the read-side counterpart to the write-side changes in patch 3: it introduces `read_in_full_or_error()`, a new wrapper function that returns 0 on success or -1 on error, for callers that need to read a complete buffer but do not care about the exact byte count. The existing `read_in_full()` is tightened to reject requested sizes exceeding `SSIZE_MAX` with a `BUG()` rather than risking undefined behavior in the return value.

The patch updates six call sites to use the new error-oriented API where appropriate: `builtin/blame.c`, `combine-diff.c`, `dir.c`, `grep.c`, and `refs/packed-backend.c` now call `read_in_full_or_error()` and check for a negative return, simplifying their error handling. `strbuf.c` is modified to clamp its internal read size to `SSIZE_MAX` before calling `read_in_full()`, preserving the byte-count semantics that function still provides for callers that need it. The implementation itself factors the read loop into a static helper `read_in_full_1()` that both public functions share.

Test coverage is added in the clar unit-test file `t/unit-tests/u-wrapper.c`, with new cases exercising `read_in_full_or_error()` for successful reads, empty reads, short reads (premature EOF), and bad file descriptors, plus complementary tests for the updated `read_in_full()`. This is part of a v2 revision where patches 1 and 2 are already considered uncontroversial and ready for integration, while this patch and the others await final acknowledgment.
