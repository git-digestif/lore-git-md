This is a maintainer reply in a concluded design discussion about `git reset --hard` safety mechanisms. Junio C Hamano responds to Steven Rostedt's report that running `git reset` without `--hard` produced a massive diff across 72,642 files, agreeing that while mixed-mode resets can sometimes be reversed with `git diff | git apply -R`, the recovery becomes messy when paths were added or removed between the index and working tree. He notes that he personally never uses `git reset` for cleanup purposes for exactly this reason. The email contains no patch and introduces no new proposal; it simply reinforces his earlier position in the thread rejecting any changes to `git reset --hard` semantics -- whether config-based defaults, `--force` bypass flags, or pre-command hooks -- and confirms that the feature request has been withdrawn in favor of client-side workarounds.
