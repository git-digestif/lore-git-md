This is a substantive review comment from Junio C Hamano on the v10 cover letter, specifically addressing the newly added support for `--dry-run` with plain `-d` and `-D` deletion modes (patch 3/5 of the series). Junio endorses the change as an improvement but uses it to push for a broader redesign of how `git branch` handles `--dry-run` across all operation modes. He argues the project should move away from the mindset that `--dry-run` is only compatible with `--delete-merged` toward a model where the option is universally accepted but may report that specific operations do not yet support it.

Junio provides concrete examples of the ideal future behavior he envisions: `git branch --dry-run test v1.5.0` should eventually report "fatal: would avoid clobbering existing branch 'test' by creating", and `git branch --dry-run -m foo bar` should report similar protective messages for renaming operations rather than rejecting the option outright. For the immediate term, however, he suggests that when `--dry-run` is combined with unsupported operations like branch creation or renaming, Git should emit specific error messages such as "fatal: --dry-run is not supported yet for branch creation" or "...for branch renaming" instead of the current generic incompatibility error. This preserves the assurance of harmlessness that `--dry-run` provides while acknowledging implementation gaps.

Within the thread context, this comment responds directly to Harald Nordgren's explanation that v10 inserted a new commit allowing `--dry-run` to work with `-d`/`-D` while still rejecting it with other non-deleting options. Junio confirms this is a step in the right direction but signals that the error handling for unsupported modes should be softened and made more descriptive to prepare for a future where `--dry-run` is a universal modifier. The remark touches on the series' broader CLI design discussion around `--delete-integrated` and `--delete-merged`, though it does not address the unresolved config-key question (`branch.<name>.deleteMerged` versus alternatives) or the "npm update" false-positive mitigation that remain open from earlier in the thread.
