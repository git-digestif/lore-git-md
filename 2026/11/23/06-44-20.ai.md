This is the first patch in v4 of Aniket Gupta's three-patch bugfix series "bundle-uri: skip unresolvable relative URIs instead of dying", which targets a Git 2.41 regression where `git clone` or `git fetch` aborts when a bundle list contains a relative URI with too many `../` components. This specific patch is a preparatory refactoring in the remote subsystem that introduces a non-fatal variant of URL resolution, enabling later patches in the series to skip bad bundle URIs gracefully instead of calling `die()`.

The patch modifies `remote.c` and `remote.h` to add `relative_url_gently()`, which resolves a relative URL against a base remote URL but returns NULL and writes a human-readable reason into a caller-provided `struct strbuf` when the relative path cannot be absorbed by the base. The existing `relative_url()` is reimplemented as a thin wrapper around the new function that preserves the old behavior by calling `die()` with the error message on failure. To support this, the internal helper `chop_last_dir()` is changed to return -1 instead of dying when there is nothing left to strip from the base URL.

Behaviorally, this splits the old monolithic `relative_url()` into a gentle core plus a dying wrapper, and changes `chop_last_dir()` from a fatal function to one that signals failure via return code. No existing callers change behavior yet; the new capability is inert until consumed. The series' third patch will use `relative_url_gently()` inside `bundle_list_update()` in `bundle-uri.c` to log the error and skip the offending bundle entry rather than aborting the entire operation.

Within the v4 series, this patch is 1/3 and provides the plumbing only; test updates for the new function appear in later patches of the series (including `t/t0060-path-utils.sh`). The series remains under review and has not been queued in `seen`. It is rebased onto current master with a noted minor textual conflict with the `tb/config-null-values` topic in `next`, which the author confirmed resolves cleanly with the `!value` check placed first.
