This is a bugfix for the experimental `git history` command that prevents it from rewriting branches checked out in other worktrees, which would otherwise leave those worktrees' index and working tree inconsistent with the moved branch.

The patch introduces a new static function `reject_checked_out_branches()` in `builtin/history.c`, invoked from `setup_revwalk()` when the ref update action is `branches` (the default). It resolves the current `HEAD` target with `refs_resolve_refdup()` to skip the branch belonging to the current worktree, then iterates over local branches containing the original commit using `filter_refs()` with `FILTER_REFS_BRANCHES`. For each candidate it calls `branch_checked_out()` from `branch.h`, which returns a path for any branch checked out in another linked worktree or currently undergoing rebase or bisect. If such a branch is found, the command errors with "cannot rewrite branch '%s' used by worktree at '%s'" and returns failure.

On refusal the patch emits the `advice.historyUpdateRefs` hint, suggesting `--update-refs=head` to rewrite only the current branch, and the check also applies during `--dry-run` so the preview reflects the real behavior. The advice text in `Documentation/config/advice.adoc` is extended to cover this worktree case alongside the existing squash-related case, and `Documentation/git-history.adoc` documents that branches used by other worktrees cannot be rewritten under the default `branches` mode.

Tests in `t/t3450-history.sh` add coverage for: refusal when another worktree has a descendant branch checked out, refusal under `--dry-run`, silencing the hint via `advice.historyUpdateRefs=false`, successful rewriting with `--update-refs=head` while leaving other branches untouched, normal rewriting of the current worktree's own branch, and refusal when the current branch is mid-rebase or when another worktree is bisecting.

This is a standalone patch based on master, reported by Toon Claes and Nikita Bobko and suggested by Patrick Steinhardt, aligning `git history` with the safety behavior of `git branch -f` and `git rebase --update-refs`.
