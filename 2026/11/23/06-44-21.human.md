This is a bugfix, specifically patch 2/3 of a three-patch series addressing a regression in the bundle-uri subsystem where `git clone` and `git fetch` die on unresolvable relative URIs.

This particular patch makes a one-line correction in `relative_url_gently()` (in `remote.c`) so that when URL resolution fails, the error message names the original input URL rather than the mangled remainder after `../` components have been stripped. Previously, a base URL like `"./a/b"` with too many `../` would produce the unhelpful message "cannot strip one component off url '.'"; now it correctly reports the full original URL. The patch includes a new test case in `t/t0060-path-utils.sh` verifying the improved message.

Within the larger series, this addresses a diagnosability concern raised by Patrick Steinhardt: while v4 dropped the credential-anonymization logic at Derrick Stolee's suggestion, retaining the original URL in error messages preserves enough context for users to understand what went wrong. The change is small, well-motivated, and directly improves the user experience when bundle URI resolution fails.
