This is a thread reply in an open bug report about `git history fixup` corrupting the index in other worktrees, where Toon Claes greenlights Aniket Gupta's offer to implement the agreed-upon fix.

Toon Claes responds to Aniket Gupta confirming that GitLab currently has no one planned to work on GitLab issue #772, so Aniket is welcome to pick up the task and send a patch. Toon asks to be copied on the eventual patch for review.

The thread has already settled on a conservative design: rather than trying to update branches checked out in other worktrees (which leaks staged changes and corrupts their index state), `git history fixup` should refuse to rewrite such branches, mirroring the safety behavior of `git rebase --update-refs`. The fix will also need to detect branches currently being rebased.

No patch has been posted yet; this email simply establishes that Aniket Gupta will implement the settled design and that Toon Claes will review it. When the patch arrives, it is expected to touch `builtin/history.c` and worktree detection logic, with regression tests planned for both the `git history` and worktree test suites.
