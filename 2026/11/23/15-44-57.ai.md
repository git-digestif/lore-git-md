This is patch 2 of 5 in Adrian Ratiu's v2 bugfix series fixing crashes when a submodule is a linked worktree. The patch introduces a shared error helper, `die_refusing_submodule_git_dir()` in `submodule.c` (declared in `submodule.h`), which centralizes the "refusing to create/use" error message and conditionally advises enabling `extensions.submodulePathConfig` only when `r->repository_format_submodule_path_cfg` is false. This replaces three previous call sites that unconditionally suggested the extension regardless of its state: `clone_submodule()` in `builtin/submodule--helper.c`, the validation block in `submodule_move_head()` in `submodule.c`, and `submodule_name_to_gitdir()` in `submodule.c`.

The old behavior embedded the extension hint directly in the `die()` message; the new behavior uses `advise()` for the hint only when the extension is disabled, and keeps the `die()` message clean. Tests in `t/t7425-submodule-gitdir-path-extension.sh` now assert that with the extension enabled the suggestion is absent from both the gitfile-rejection path and the config-gitdir path, while `t/t7450-bad-git-dotfiles.sh` gains an assertion that the hint *does* appear in the default (extension-disabled) case. This patch depends on patch 1's change to `validate_submodule_legacy_git_dir()` and is a prerequisite for patches 3-5, which restructure `submodule_move_head()` around the new helper.
