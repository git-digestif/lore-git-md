This is a **bugfix**, the fifth and final patch of Adrian Ratiu's v2 series fixing crashes when a submodule is itself a linked worktree during recursive checkout.

The patch introduces `validate_submodule_worktree_dir()` in `submodule.c` to verify that a git dir claiming to be a linked worktree actually resides at `<common-dir>/worktrees/<id>`, rejecting any path with a `commondir` file located elsewhere. It modifies `setup_submodule_git_dir()` (extracted in patch 3) to return an `is_worktree` flag: when `get_common_dir_noenv()` detects a worktree git dir, the function validates the common dir against the submodule name instead of the worktree id, which previously caused the suffix check in `validate_submodule_git_dir()` to fail unless the worktree id happened to match the submodule name.

The control flow in `submodule_move_head()` now uses this `is_worktree` flag to avoid two destructive actions on linked worktrees. The forced-move reconnection via `connect_work_tree_and_git_dir()` is skipped when `is_worktree` is set, preventing Git from rewriting the submodule's `.git` file to point at the non-existent `$GIT_DIR/modules/<name>` path of the superproject. Similarly, `submodule_unset_core_worktree()` is skipped during submodule removal to avoid errors when trying to modify `core.worktree` in a worktree git dir that belongs to another working tree.

Test coverage is added in `t/t2405-worktree-submodule.sh` using a new `test_submodule_worktree_is_kept` helper that verifies the `.git` file contents and HEAD remain unchanged after `checkout --recurse-submodules`. Tests cover acceptance of submodule worktrees in both legacy and `extensions.submodulePathConfig` modes, handling of a submodule worktree containing a nested `.git` directory (absorb path), and clean removal. `t/t7450-bad-git-dotfiles.sh` gains a test ensuring a forged worktree git dir (with `commondir` pointing to a wrong location) is rejected with the "is not a worktree of" error rather than triggering a `BUG()` or misleading extension advice.

This patch completes the series by addressing the original crash reported by Andreas Wendleder: recursive checkout no longer aborts when a submodule's git dir ends in a worktree id rather than the submodule name, and linked worktrees are preserved intact rather than being hijacked by the superproject's expected modules path.
