This is patch 4 of 5 in Johannes Schindelin's v2 series hardening Git against integer overflows flagged by Coverity, specifically targeting the wrapper I/O layer in `wrapper.c` and `wrapper.h`.

The patch introduces a new `read_in_full_or_error()` function that returns `int` (0 on complete read, -1 with `errno` set on error or premature EOF), for callers that do not need the byte count. The existing `read_in_full()` now calls a shared static helper `read_in_full_1()` and triggers a `BUG()` if the requested `count` exceeds the maximum value representable in `ssize_t`, preventing silent overflow of the return value. Six call sites (`builtin/blame.c`, `combine-diff.c`, `dir.c`, `grep.c`, `refs/packed-backend.c`, and `strbuf.c`) were migrated to `read_in_full_or_error()` where they previously compared the return value against the requested size, simplifying error handling. `strbuf.c` additionally clamps its internal `want` variable to `SSIZE_MAX` before calling `read_in_full()`. The patch adds clar unit tests in `t/unit-tests/u-wrapper.c` covering successful reads, empty reads, short reads (premature EOF), and bad file descriptors for both the new and existing functions.

This change complements patch 3 of the same series, which altered `write_in_full()` to return `int` instead of `ssize_t`; together they eliminate overflow risk in the wrapper API by design. The series remains under review with Junio's integration queue marked "Waiting for response."
