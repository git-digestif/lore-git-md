This is a substantive review reply from Junio C Hamano to Harald Nordgren's v10 series, commenting on the patch that allows `--dry-run` to work with plain `-d` and `-D` deletion modes.

Junio acknowledges that the change is "much better than before" but pushes for a broader design shift: rather than treating `--dry-run` as incompatible with anything except deletion operations, the validation logic should evolve toward supporting `--dry-run` across all `git branch` operation modes, with some modes simply reporting "not supported yet" until implemented. He illustrates the ideal future behavior with examples showing `--dry-run` catching clobbering during branch creation or renaming, contrasted with the current fallback messages that would say `--dry-run` is not supported for those operations. He explicitly says it is acceptable to leave creation and renaming as gaps for now, but the underlying mindset should change to assume all modes ought to support the flag eventually.

The feedback carries maintainer weight and will likely influence how Harald (or future contributors) frame the error handling and documentation for `--dry-run` in subsequent iterations, even though no code changes are demanded immediately.
