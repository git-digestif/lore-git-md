Aniket Gupta has sent a bugfix for the experimental `git history` command that prevents it from rewriting branches that are checked out in other worktrees, which would otherwise leave those worktrees with inconsistent index and working tree state. The patch adds a `reject_checked_out_branches()` check in `builtin/history.c` that runs during the default `branches` update mode, skipping the current worktree's own branch but refusing to move any other local branch that is checked out elsewhere or currently undergoing rebase or bisect. When such a conflict is detected, the command errors out and suggests using `--update-refs=head` instead, with the check applying even during `--dry-run` so previews match real behavior. Documentation and tests in `t/t3450-history.sh` cover the new safety behavior, including the advice hint that can be silenced via `advice.historyUpdateRefs=false`. The standalone patch, based on master, was reported by Toon Claes and Nikita Bobko and suggested by Patrick Steinhardt, bringing `git history` in line with the existing safety checks in `git branch -f` and `git rebase --update-refs`.
