This is the fifth and final patch in Johannes Schindelin's v2 series of Coverity-inspired integer-overflow hardening fixes, targeting the relative-date parser in `date.c`. Where the earlier patches in the series address `archive-tar.c`, `http.c`, and the wrapper I/O layer, this one focuses on `approxidate_str()` and its helpers, ensuring that multiplying a parsed quantity by a unit length (seconds, minutes, hours, days, weeks, etc.) cannot trigger signed integer overflow, which is undefined behavior in C.

The patch modifies `approxidate_alpha()` to perform the unit-length multiplication in `uintmax_t` using `unsigned_mult_overflows()` before checking whether the result fits the native `time_t` range via `date_overflows()`, returning `NULL` on either failure rather than wrapping. In `approxidate_digit()`, the parsed number is now rejected if it exceeds `INT_MAX` before being narrowed to `int`, and `approxidate_str()` is adjusted to propagate these `NULL` returns by setting `*error_ret` and returning zero, so callers like `git reflog expire` report an "invalid timestamp" error instead of computing a wrapped offset.

Tests are added in `t/t0006-date.sh`: one verifying that a large but valid quantity ("4000 weeks ago") parses correctly on 64-bit `time_t` platforms, and another confirming that an absurdly large number ("18446744073709551615 seconds ago") is rejected with a failure exit. The commit message notes the inputs are non-negative, so unsigned overflow checks suffice, and that Coverity flagged the original code.

Within the thread, this patch is part of the v2 revision where patches 3 through 5 were reworked to drop earlier proposals for generic overflow macros in favor of these direct, portable checks; patches 1 and 2 remained unchanged from v1.
