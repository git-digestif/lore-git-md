This is the **v3 security bugfix patch** for the SSH revocation file flaw, addressing Junio C Hamano’s substantive review feedback on error-handling consistency. The patch now folds the revocation-file check into the existing failure block so that signature information is displayed for both missing revocation files and unknown keys, aligning the `%G?` status code ("U") and user feedback. The commit message confirms the behavioral symmetry: "a known key gets the error and then its signature info, as an unknown key does."

The patch is part of the same security report thread as the earlier timestamp-confusion documentation fix (now finalized and endorsed by Patrick Steinhardt). Both patches are ready for integration and may be held together to avoid splitting security fixes across releases. Test coverage in `t/t7528-signed-commit-ssh.sh` has been expanded to verify the new error-handling flow and the `:(optional)` escape hatch. Files touched: `gpg-interface.c`; config key: `gpg.ssh.revocationFile`.
