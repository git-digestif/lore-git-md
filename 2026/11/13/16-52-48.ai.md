This is a performance optimization patch targeting memory usage in the commit subsystem. Junio C Hamano weighs in on the ongoing discussion about comment wording in Kristofer Karlsson’s v2 patch, which reorders fields in `struct commit` to eliminate padding and reduce its size from 80 to 72 bytes on 64-bit platforms. The patch itself is uncontroversial and ready for merging, but the thread has focused on refining the explanatory comments to accurately reflect Git’s casting patterns.

Junio corrects the direction of the cast in the comment for `struct object`, clarifying that the first-member invariant enables unconditional downcasting from `struct commit *` to `struct object *`, while upcasting (object to commit) requires external knowledge that the object is indeed a commit. This aligns with the "cheap C inheritance" pattern used throughout Git’s codebase. The proposed wording—"so that a 'struct commit *' can be cast to a 'struct object *'. The code casts in the other direction only when the object is known to be a commit"—is precise and avoids ambiguity about which direction is safe.
