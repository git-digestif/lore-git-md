This is a two-patch performance and memory-usage improvement for `git repo structure`, part of the `git repo` built-in command. The series targets the object-counting logic that currently parses every object it encounters, which becomes prohibitively expensive in repositories with tens of billions of tree entries. Patch 1 delays parsing until the object is actually needed; patch 2 skips full tree parsing altogether when only the object type is required. The result is a measurable reduction in memory footprint and wall-clock time, although the author notes that even with these changes the command still cannot complete in a repository of that scale due to the sheer volume of tree entries to traverse. The patches touch only `builtin/repo.c` and are motivated by a real-world OOM observed in production.
