This is the first patch in a four-part bugfix series addressing inconsistent error handling in `git cat-file --batch` when dealing with invalid references. Specifically, it fixes a parsing edge case in `get_oid_basic()` where a failed peel suffix (like `^{blob}`) could be misinterpreted as a reflog selector, causing Git to resolve the wrong object.

The bug occurs when a reference like `HEAD@{1}^{blob}` is processed. The code incorrectly treats `1}^{blob` as a reflog selector, which `approxidate_careful()` then interprets as "now," resolving to the current HEAD instead of failing. The patch adds a check to ensure the final `}` closes the `@{` selector, preventing this misinterpretation. The fix is minimal and targeted, touching only `object-name.c` and adding test cases to `t1508-at-combinations.sh`.

The commit message is clear and includes a reproduction example, making the problem easy to understand. The test coverage is appropriate for the scope of the fix. This patch is uncontroversial and aligns with the series' goal of making error handling more consistent.
