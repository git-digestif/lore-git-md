This is the second patch in a four-part bugfix series addressing inconsistent error handling in `git cat-file --batch` when dealing with invalid references. The series targets a regression introduced by commit 393bbb21 ("object-name: make get_oid quietly return an error", 2025-06-12), which added the `GET_OID_GENTLY` flag to allow graceful error returns instead of fatal errors—but applied it inconsistently.

This patch refines how `GET_OID_GENTLY` behaves in `get_oid_basic()`. The current implementation incorrectly turns *successful* lookups (like `ref@{<date>}` older than the reflog or `ref@{N}` beyond the reflog’s bounds) into errors when the flag is set. The fix moves the gentle-check into the failure branch of the lookup cascade, ensuring it only affects truly failing lookups. This restores the expected behavior: `ref@{<date>}` resolves to the oldest known value, and `ref@{N}` resolves to the "old" side of the oldest entry, matching the behavior without the flag.

The change is small but precise, touching only `object-name.c` and adding a test in `t/t3903-stash.sh` to verify that `git stash export` now handles reflog selectors like `stash@{1970-01-02}` consistently with `git stash show`. The test also confirms that out-of-bounds selectors (e.g., `stash@{2}` when only one entry exists) still fail gracefully. The commit message is clear and references prior review feedback, showing the author engaged with the discussion.

This patch looks well-crafted and uncontroversial. It directly addresses the regression while preserving the intended behavior of `GET_OID_GENTLY`.
