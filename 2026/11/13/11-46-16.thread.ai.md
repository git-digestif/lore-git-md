Core problem or goal
Improve performance and reduce memory usage of `git repo structure` (part of the `git repo` built-in) by optimizing its object-counting logic. The current implementation parses every object it encounters, which is prohibitively expensive in repositories with tens of billions of tree entries. The goal is to delay parsing until necessary (patch 1) and skip full tree parsing when only the object type is required (patch 2).

Key technical details
- Files touched: `builtin/repo.c` only.
- New behavior: objects are parsed only when needed (patch 1: blobs and tags are counted without parsing; commits are looked up via `lookup_commit()` and parsed only as a failsafe via `repo_parse_commit()`; patch 2: tree parsing is skipped when only object type is required).
- Old behavior: every object was parsed unconditionally.
- No on-disk format changes; no new CLI options or config keys.
- Performance impact: patch 1 alone yields 12% wall-time improvement and 4% memory reduction in `git.git`; combined effect of both patches is 80% memory reduction and 20% wall-time improvement, as benchmarked by the author and confirmed by Kristofer Karlsson.
- Code comment rewording in patch 1: the comment now states that commits *should* already be parsed by the revision walk, framing `repo_parse_commit()` as a failsafe rather than a dependency.
- Open design choice (resolved for integration): the fallback `repo_parse_commit()` call remains silent rather than triggering a `BUG()` assertion, aligning with the author's preference for fail-safe behavior.

Open questions and loose ends
None. The low-priority design choice about fail-fast behavior (silent fallback vs. `BUG()` assertion) was the only open item and has been resolved in favor of silent fallback, with no impact on integration status.
