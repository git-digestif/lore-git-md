Subject: [PATCH 0/2] repo structure: performance and memory-usage improvements
Series version: v2 (addresses minor feedback)
Originating author: Patrick Steinhardt <ps@pks.im>
Thread type: patch series

Core problem or goal
Improve performance and reduce memory usage of `git repo structure` (part of the `git repo` built-in) by optimizing its object-counting logic. The current implementation parses every object it encounters, which is prohibitively expensive in repositories with tens of billions of tree entries. The goal is to delay parsing until necessary (patch 1) and skip full tree parsing when only the object type is required (patch 2).

Current status
Under review; v2 posted. The update addresses the sole substantive feedback from v1: a reworded comment in patch 1 to clarify that `repo_parse_commit()` acts as a failsafe rather than a dependency. All other aspects of the series remain unchanged. The series is endorsed by Kristofer Karlsson, who confirmed the 80% memory reduction (5.1× less memory) and 20% wall-time improvement. No open technical concerns or objections remain; the series is ready for maintainer pickup.

Key technical details
- Files touched: `builtin/repo.c` only.
- New behavior: objects are parsed only when needed (patch 1); tree parsing is skipped when only object type is required (patch 2).
- Old behavior: every object was parsed unconditionally.
- No on-disk format changes; no new CLI options or config keys.
- Performance impact: 80% memory reduction and 20% wall-time improvement, as benchmarked by the author and confirmed by Kristofer Karlsson.
- Code comment rewording in patch 1: the comment now states that commits *should* already be parsed by the revision walk, framing `repo_parse_commit()` as a failsafe rather than a dependency.
