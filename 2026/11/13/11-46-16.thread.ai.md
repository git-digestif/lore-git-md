Core problem or goal
Improve performance and reduce memory usage of `git repo structure` (part of the `git repo` built-in) by optimizing its object-counting logic. The current implementation parses every object it encounters, which is prohibitively expensive in repositories with tens of billions of tree entries. The goal is to delay parsing until necessary (patch 1) and skip full tree parsing when only the object type is required (patch 2).

Current status
Under review; v1 posted. No prior versions.

Key technical details
- Files touched: `builtin/repo.c` only.
- New behavior: objects are parsed only when needed (patch 1); tree parsing is skipped when only object type is required (patch 2).
- Old behavior: every object was parsed unconditionally.
- No on-disk format changes; no new CLI options or config keys.
- Test coverage: not mentioned in the summary, but the motivation is a real-world OOM observed in production.
