Subject: [PATCH] promisor-remote: fix crash in `git ls-remote` outside repository
Series version: standalone patch
Originating author: Christian Couder
Thread type: bugfix

Core problem or goal
Fix a crash in `git ls-remote` when invoked outside any Git repository with promisor-remote configuration enabled. The crash occurs because `filter_promisor_remote()` dereferences `repo->gitdir` without checking for NULL. The regression was introduced by commits 3e20258d11 and 7a56394fc6 (2026).

Current status
Under review. Consensus is forming around Christian’s minimal fix (a NULL check in `filter_promisor_remote()`) as an acceptable short-term solution, while Junio’s alternative (making `promisor_remote_reply()` a no-op when no repository is present) remains the preferred long-term direction. Both maintainer and reviewer now agree that the minimal fix can proceed, with the understanding that future cleanup will address the broader design issue.

Key technical details
- Subsystem: promisor-remote
- Functions discussed: `filter_promisor_remote()` (Christian’s fix), `promisor_remote_reply()` (Junio’s alternative)
- Files touched: `promisor-remote.c`, `t/t5710-protocol-v2-http.sh` (tests already provided by Christian)
- New symbols: none
- Old-vs-new behavior: both approaches prevent the crash; Junio’s alternative avoids calling `filter_promisor_remote()` entirely when outside a repository
- Test coverage: two new test cases in `t5710` covering both crash scenarios (already present in Christian’s patch)

Open questions and loose ends
- Should the rationale for punting when `repo->gitdir` is NULL be documented in the code? Both Junio and Patrick have noted this as a requirement for either solution.
- Are there other callers of `promisor_remote_reply()` that might need similar adjustments if Junio’s approach is adopted in the future?
- Longer-term cleanup: the thread has established that the `!repo` case should be handled explicitly to align with Git’s modern practice of avoiding implicit repository assumptions. This will likely influence future refactoring of the promisor-remote subsystem.

Participant positions
- Christian Couder (author): provided problem description, regression timeline, fix (NULL check in `filter_promisor_remote()`), and tests. Argues the early return is safe because `git ls-remote` has no legitimate use for promisor remotes outside a repository.
- Junio C Hamano (maintainer): initially proposed an alternative fix (making `promisor_remote_reply()` a no-op when no repository is present) but now accepts Christian’s minimal fix as an acceptable short-term solution. Continues to prefer the no-op approach for long-term design consistency and alignment with Git’s broader effort to eliminate reliance on `the_repository`. Emphasizes the need for explicit documentation of the rationale in the code.
- Patrick Steinhardt: prefers Junio’s approach in principle, arguing that checking for `!repo` (rather than `!repo->gitdir`) is cleaner and aligns with Git’s modern practices. Open to Christian’s minimal fix as a short-term solution but reinforces the need to handle the `!repo` case explicitly for future-proofing.
