This thread introduces a two-patch performance optimization for `git repo structure`, a subcommand of the `git repo` built-in. Patrick Steinhardt addresses a scalability bottleneck in the object-counting logic, which previously parsed every object it encountered—an approach that becomes impractical in repositories with tens of billions of tree entries. The patches delay parsing until necessary (patch 1) and skip full tree parsing when only the object type is needed (patch 2), reducing both memory usage and execution time. While the changes improve performance, Patrick notes that the command still struggles to complete in such large repositories due to the sheer volume of tree entries.

The series is narrowly scoped to `builtin/repo.c` and is motivated by a real-world out-of-memory (OOM) issue observed in production. No reviews or objections have been posted yet, so the patches are still under initial consideration. If you’re working on large-repository tooling or the `git repo` command, these changes may be relevant to your workflow.
