This thread is about Patrick Steinhardt’s two-patch series to improve the performance and memory usage of `git repo structure`, a subcommand of the `git repo` built-in. The series targets a real-world issue where the current implementation parses every object it encounters, leading to out-of-memory errors in repositories with tens of billions of tree entries. Patch 1 delays object parsing until necessary, while patch 2 skips full tree parsing when only the object type is required.

The series is under active review, with the first patch receiving minor feedback on code comment wording from Kristofer Karlsson. The second patch has now been substantively reviewed by Karlsson, who endorses the approach based on his own work on incremental connectivity checks. He reports significant improvements: an 80% reduction in memory usage (5.1× less memory) and a 20% speedup in wall time. No objections or open questions have been raised, and the feedback so far is uniformly positive. The series touches only `builtin/repo.c` and introduces no on-disk format changes or new CLI options. If the current momentum holds, it’s likely to be queued for integration soon.
