This thread is about a two-patch series from Patrick Steinhardt that improves the performance and memory usage of `git repo structure`. The series optimizes the object-counting logic in `builtin/repo.c` by delaying object parsing until necessary and skipping full tree parsing when only the object type is needed. The changes are confined to that file and introduce no new CLI options, configuration keys, or on-disk format changes.

The initial version received substantive review from Kristofer Karlsson, who confirmed an 80% reduction in memory usage (5.1× less) and a 20% improvement in wall-clock time. The only feedback—a minor rewording of a code comment to clarify the failsafe role of `repo_parse_commit()`—was incorporated in the v2 update, which Patrick just posted. No technical objections remain, and the series is now ready for Junio to pick up. The performance gains are clear, and the changes are uncontroversial. The only acknowledged limitation is that the command still cannot complete in the very largest repositories due to the sheer volume of tree entries, but that is a separate issue.
