Adithya Chakilam has posted v2 of a two-patch series adding a `--filter-to-loose=<directory>` option to `git repack`, which writes objects excluded by a `--filter` directly as loose objects into a target directory rather than an intermediate pack. This supports workflows for key-value object stores and large-object promisors that do not speak the Git wire protocol. The first patch streams packed objects through `unpack-objects` into the destination, while the second patch -- detailed in the latest email -- extends the feature to loose objects already in the source repository.

The second patch introduces `move_loose_filtered_objects()` and `remove_moved_loose_objects()` in `repack-filtered.c` to collect loose object IDs, apply the filter, and copy excluded objects to the target using temporary files and `finalize_object_file()` for atomicity; when `-d` is given, the source copies are removed after `prune_packed_objects()` runs. V2 addresses three issues Junio C Hamano raised during v1 review: it errors early if the destination directory does not exist, uses `OPT_FILENAME` so relative paths resolve correctly from subdirectories, and fixes a double-close bug by removing a manual `close()`. Tests in `t/t7700-repack.sh` cover copying loose objects, `-d` removal, skipping objects already present in the destination (verified by inode comparison), and failure recovery that leaves no temporary files behind.

The series remains under review with no integration status reported; it is not queued in `pu`, `next`, or `master`.
