This thread introduces a new `--filter-to-loose=<dir>` option for `git repack`, allowing filtered-out objects to be written directly as loose objects into a specified directory. The feature is aimed at improving interoperability with systems like key-value stores that manage Git objects individually, avoiding the need to unpack a packfile.

Adithya Chakilam posted the initial v1 series, which consists of two patches. The first patch, now under review, implements the core functionality for objects already stored in packs. It adds the new option, updates the repack machinery (`builtin/repack.c`, `repack-filtered.c`, and `repack.h`), and includes test coverage and documentation updates. The patch is well-scoped and addresses a clear workflow need, though it hasn’t yet received any reviewer feedback. The design streams the filtered pack into `unpack-objects`, which writes the objects to the target directory in loose form, skipping any objects already present.

The series is still in its early stages, with no maintainer integration status reported. The second patch, which will extend the functionality to handle loose objects excluded by the filter, is yet to be posted. Open questions include edge cases like concurrent access to the target directory, permission issues, and performance implications of writing loose objects versus packfiles. For now, the thread is waiting for reviewer input to move forward.
