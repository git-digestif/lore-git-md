This thread introduces a new `--filter-to-loose=<dir>` option for `git repack`, allowing filtered-out objects to be written directly as loose objects into a specified directory. The feature is split into two patches: the first (already posted) handles objects already in packs, while the second (this email) extends the functionality to loose objects excluded by the filter.

Adithya Chakilam is the author, and the series is now complete with v1 of both patches posted. The implementation touches the repack machinery (`repack-filtered.c`, `repack.h`) and includes thorough test coverage in `t/t7700-repack.sh`. The new option is designed for workflows involving key-value object stores, enabling them to ingest objects in loose form without unpacking a packfile. The second patch ensures loose objects are also copied to the destination, with safeguards for edge cases like existing destination objects and failed operations.

No reviewer feedback has been posted yet, so the design and implementation remain unchallenged. The series is under review, with no maintainer integration status reported. Open questions include performance implications, handling of concurrent access to the destination directory, and scalability for large object sets. The feature appears production-ready, but its adoption will depend on the prevalence of key-value object stores in Git workflows.
