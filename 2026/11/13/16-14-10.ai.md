This is a bugfix patch targeting the `for-each-ref` and `git refs list` commands.

The patch addresses a segmentation fault that occurs when `--no-format` is passed to either command. The issue arises because the `--format` option is declared with `OPT_STRING()`, which allows `--no-format` to set the format string to `NULL`. Since the default format is assigned before command-line parsing, nothing restores it, leading to a `NULL` dereference in `verify_ref_format()`. The problem has existed since 2007 (commit `c3428da87f`).

The fix aligns `for-each-ref` with `git branch` and `git tag`, which already handle `--no-format` by falling back to their default formats. The solution moves the default format assignment *after* command-line parsing, so if `--no-format` is used, the default is applied. This also allows `--no-format` to cancel an earlier `--format` and restore the default output. The patch includes a new test in `t/for-each-ref-tests.sh` to verify the fix.

The change is minimal (4 lines of code, 6 lines of test) and well-motivated. The commit message clearly explains the problem, the fix, and why `PARSE_OPT_NONEG` was not used. The test coverage is appropriate for the scope of the bug. This looks like a straightforward, uncontroversial fix for a long-standing crash.
