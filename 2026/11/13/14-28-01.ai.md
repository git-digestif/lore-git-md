This is the first patch in a four-part bugfix series addressing inconsistent `git cat-file --batch` error handling for invalid references. Specifically, it fixes a parsing edge case in `get_oid_basic()` where a failed peel suffix (like `^{blob}`) could be misinterpreted as a reflog selector, causing Git to resolve the wrong object. For example, `HEAD@{1}^{/no-such-subject}` would incorrectly return the current HEAD instead of failing.

The patch adds a bounds check to ensure the final `}` in a reference closes the `@{` of the reflog selector, not a later peel suffix. This prevents the parser from treating strings like `1}^{blob}` as valid reflog timestamps (which `approxidate_careful()` would accept as "now"). The fix is minimal and targeted, touching only `object-name.c` and adding test cases to `t1508-at-combinations.sh` to verify the corrected behavior.

The change aligns with the series' broader goal of making error handling consistent across reference lookups. The commit message clearly explains the bug and its impact, and the test coverage ensures the fix works for both reflog and non-reflog cases. No controversial design decisions are involved—this is a straightforward correctness fix for a parsing ambiguity. The patch is uncontroversial and appears well-crafted, with no obvious gaps in the reasoning or implementation.
