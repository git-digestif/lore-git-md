This is a documentation patch in Jasper Mayone’s five-part series adding worktree filtering to `git for-each-ref`. The patch updates the `git-for-each-ref` man page to warn users that `%(worktreepath)` can output paths containing newlines, which breaks scripts that read one record per line. It advises using Git’s quoting options (`--shell`, `--perl`, etc.) or NUL-terminated output (`%00`) to parse the atom safely. The patch also clarifies that when a branch is checked out in multiple worktrees, only one path is shown.

Junio’s review is surface-level but constructive. He raises a broader question: should this guidance be centralized rather than repeated for each atom that can emit arbitrary bytes? He does not object to the patch itself, calling it “good enough” for now, but suggests that a future effort might consolidate parsing advice in one place. The patch is uncontroversial and ready to merge; the only open question is whether to defer this documentation style improvement until a later cleanup.
