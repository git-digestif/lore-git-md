This is a two-patch feature series for `git repack`, introducing a new `--filter-to-loose` option. The goal is to help users of key-value object stores that manage Git objects individually by writing filtered-out objects directly as loose objects, avoiding the need to unpack intermediate pack files.

The cover letter explains the motivation clearly: the existing `--filter-to` option writes filtered objects into packs, which requires an extra unpacking step for stores that retrieve objects individually. The new `--filter-to-loose=dir` option streams filtered objects into `unpack-objects`, writing them directly as loose objects into a specified directory. The first patch implements the option for objects already in packs, while the second extends it to include loose objects excluded by the filter, with the destination directory treated as a Git object directory.

The implementation touches `builtin/repack.c`, `repack-filtered.c`, and adds tests in `t/t7700-repack.sh`. The changes look focused and well-scoped, with a clean separation between the two patches. The commit messages and cover letter are thorough, making the purpose and behavior easy to understand. This appears to be a well-crafted, practical addition that addresses a real workflow need without introducing unnecessary complexity. If you work with object stores that prefer loose objects, this series is likely worth your attention.
