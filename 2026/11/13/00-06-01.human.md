This is a bugfix for the promisor-remote subsystem. Christian Couder fixes a crash that occurs when `git ls-remote` is run outside a Git repository with certain promisor-remote configuration options enabled. The crash happens because the code assumes a valid repository object with a non-NULL `gitdir`, but `git ls-remote` can operate without one.

The patch adds a simple NULL check at the start of `filter_promisor_remote()` to bail out early if `repo->gitdir` is NULL. This prevents the code from dereferencing a NULL pointer when trying to auto-create a remote or store fields from a promisor-remote advertisement. The fix is minimal and targeted, addressing only the immediate crash without changing the broader behavior of promisor remotes.

Two new tests in `t5710-promisor-remote-capability.sh` verify that `git ls-remote` no longer crashes in these edge cases. The commit message clearly explains the regression's origin (two specific commits from earlier in 2026) and why `git ls-remote` is the only command affected. The patch looks well-crafted, with a clear rationale and test coverage. It should be uncontroversial.
