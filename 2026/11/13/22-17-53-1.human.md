This is a **bugfix for Git v3 compatibility**, addressing two critical issues in the repository initialization logic: (1) `git init` now correctly defaults to SHA-256 when Git is built with `WITH_BREAKING_CHANGES=1`, and (2) reinitializing an existing repository no longer silently overwrites its object format. The patch is a revision of brian m. carlson’s earlier fix, incorporating feedback from Junio C Hamano and Patrick Steinhardt to handle edge cases safely.

The core problem was that the original code failed to respect `GIT_HASH_DEFAULT` (which should be SHA-256 in Git v3) and allowed reinitialization to clobber the repository’s hash algorithm. The new version restructures `repository_format_configure()` to prioritize command-line arguments, then fall back to environment variables, config settings, or the default algorithm—but *only* for new repositories (`repo_fmt->version < 0`). For existing repositories, it preserves the current format and fails loudly if an incompatible hash is specified, mirroring the behavior for ref-storage formats.

The patch includes thorough test coverage: a new test verifies the default object format under `WITH_BREAKING_CHANGES`, while additional tests ensure reinitialization refuses to change the hash algorithm and respects config settings.
