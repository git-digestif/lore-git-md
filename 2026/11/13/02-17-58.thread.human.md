This thread is a cleanup patch from Yusuke Hayashi that removes an unnecessary and incorrect pre-sizing step in `get_info_packs()`, a function in Git’s HTTP backend. The change targets a 2009-era optimization that iterated over all packs twice—once to count them and pre-size a `strbuf`, and again to format the output—despite `strbuf_addf()` already handling dynamic growth efficiently. The pre-sizing logic was also flawed for SHA-256 repositories and used unchecked arithmetic.

The patch is now in its second iteration (v2), with the only change being an updated commit message that addresses Patrick Steinhardt’s review concern about the performance trade-off. Yusuke provided a context-specific rationale: `get_info_packs()` is a one-shot CGI handler for dumb HTTP requests, where the overhead of dynamic `strbuf` growth (a few dozen reallocations even with thousands of packs) is negligible compared to the cost of CGI startup, scanning the pack directory, and writing the HTTP response. The patch itself is a pure cleanup with no behavior change and is covered by existing HTTP backend tests.
