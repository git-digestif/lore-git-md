This thread is about a small but well-justified cleanup in Git’s HTTP backend. Yusuke Hayashi proposed removing an unnecessary pre-sizing step in `get_info_packs()`—a function that generates the `objects/info/packs` response for dumb HTTP requests. The original code counted packs twice (once to pre-size a buffer, once to format output), despite `strbuf` already handling dynamic growth efficiently. The pre-sizing logic was also incorrect for SHA-256 repositories and used unchecked arithmetic.

The patch went through two iterations. In the first, Patrick Steinhardt challenged the justification, asking for either performance data or a stronger rationale. The author responded in v2 with a context-specific argument: `get_info_packs()` is a one-shot CGI handler where the cost of a few dozen `strbuf` reallocations is negligible compared to CGI startup, directory scanning, and HTTP response overhead. Patrick accepted this reasoning in his latest reply, signaling approval. The patch itself is unchanged from v1—it simply removes the counting loop and `strbuf_grow()` call, leaving the output identical. The change is covered by existing HTTP backend tests and aligns with prior similar cleanups (e.g., `add_rfc2047()`).

With no further objections and Patrick’s explicit approval, the thread is now converged. The patch is a low-risk cleanup that should be ready for Junio to pick up in his next integration cycle.
