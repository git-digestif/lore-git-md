This is the second patch in Adithya Chakilam’s two-part series introducing `--filter-to-loose=<dir>` for `git repack`. The first patch implemented the core functionality for objects already in packs; this one extends it to also copy loose objects that the filter excludes, ensuring the destination directory receives the complete set of filtered-out objects.

The patch adds a new function `move_loose_filtered_objects()` that scans the loose-object store, applies the same filter used on the pack, and copies any excluded loose objects to the destination directory. Objects already present in the destination are not rewritten, and with `-d`, the source copies are removed after successful copying. The implementation is careful to handle errors gracefully: if copying fails, the source repository remains intact, and no partial state is left behind. New tests verify that loose objects are copied correctly, that `-d` removes the source copies, and that existing destination objects are not overwritten.

The code touches `builtin/repack.c`, `repack-filtered.c`, and `repack.h`, and adds test coverage to `t/t7700-repack.sh`. The commit message is clear and the implementation looks solid, though the series as a whole has not yet received reviewer feedback. This patch completes the feature, making `--filter-to-loose` fully functional for both packed and loose objects. The design is pragmatic and addresses a real workflow need for systems that manage Git objects individually, such as key-value stores. Whether this will see widespread adoption depends on how common such use cases are, but the implementation itself is clean and well-scoped.
