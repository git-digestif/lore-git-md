This is a performance patch for the `git repo structure` command, part of the `git-repo` built-in. It optimizes object counting by avoiding unnecessary parsing of blobs and tags, and by reusing already-parsed commit objects from the revision walk.

The patch modifies `builtin/repo.c` to skip reading and parsing object content for types that don't need it. For commits, it leverages the fact that they're already parsed during the revision walk, using `lookup_commit()` instead of re-parsing. For trees, it still parses to count entries, while blobs and tags are now processed without parsing their content. The change reduces wall time by ~12% and memory usage by ~4% in benchmarks on git.git.

Key technical details: the patch introduces conditional object info reading (`oi.contentp` is only set for trees), uses `lookup_commit()` for already-parsed commits, and maintains the existing statistics collection. The optimization is specific to the object counting phase of `git repo structure`, which walks the object graph to gather repository metrics.

This is the first patch in a 2-patch series (v1). The commit message provides clear motivation and benchmark results, showing measurable improvement without behavior changes. The implementation appears clean and targeted, focusing only on the unnecessary work identified.
