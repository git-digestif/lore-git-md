This is a surface-level review of the memory-optimization patch that reorders `struct commit` to eliminate padding.

Derrick Stolee replies to Kristofer Karlsson’s v2 patch with two minor comment tweaks. First, he points out that the new comment describing `struct object` as the first member is misleading: the code actually casts a `struct commit *` to a `struct object *`, not the other way around, though the reverse could happen if the object type is verified first. Second, he suggests clarifying the `date` field’s comment to reflect that its value may come from the commit-graph file rather than the commit object itself. Both suggestions are framed as optional nitpicks rather than blockers, and Stolee reiterates his prior endorsement of the patch as “obviously correct.” No new technical concerns are raised; the patch remains ready for maintainer pickup.
