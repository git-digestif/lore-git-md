This is Junio’s reply to the first patch in Jasper Mayone’s v5 series, which adds a safety check to `git worktree remove` to prevent deletion of worktrees in the middle of a rebase, bisect, cherry-pick, revert, or `git am` operation. The patch itself is uncontroversial and well-motivated, but Junio raises two forward-looking design questions that do not block this patch but suggest future work.

First, he notes that the new `check_no_operation_in_progress()` helper is a good central place for extensibility and asks how it should interact with the existing protection against checking out the same branch in multiple worktrees. The question is purely hypothetical at this stage—there is no immediate conflict or missing integration—but it signals that Junio is thinking about how these safety checks might eventually be unified or coordinated.

Second, he sketches a longer-term refactoring idea: create a single helper function that returns an error code (rather than dying) to check whether a worktree is in a discardable state, then call it from both `git worktree remove` and any other commands that need to know whether a worktree is safe to delete or modify. This would move the safety logic into `worktree.c` and "libify" it, making it reusable across the codebase. He explicitly marks this as out of scope for the current patch, labeling it `#leftoverbits`—a tag Junio uses to note follow-up work that is not part of the immediate series.

The tone is constructive and forward-looking; there are no objections to the patch as written, and the feedback is aimed at future maintainability rather than current correctness. The patch remains ready for integration.
