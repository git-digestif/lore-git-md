This is the first patch in a two-patch feature series introducing `--filter-to-loose=<dir>` for `git repack`. The patch implements the core functionality for objects already stored in packs, allowing `git repack --filter` to write filtered-out objects directly as loose objects into a specified directory (`<dir>`) instead of creating an intermediate packfile. This is achieved by streaming the filtered pack into `unpack-objects`, which writes the objects to the target directory in loose form.

The implementation touches `builtin/repack.c`, `repack-filtered.c`, and `repack.h`, adding the new `--filter-to-loose` option and plumbing it through the repack machinery. The patch includes compatibility checks to ensure the option cannot be combined with `--filter-to` or `--max-pack-size`, and it updates the documentation in `Documentation/git-repack.adoc` to describe the new behavior. Test coverage is added in `t/t7700-repack.sh`, verifying that the option works as expected, handles edge cases (e.g., failure to write objects), and preserves the source repository's integrity.

The patch is well-scoped and addresses a clear workflow pain point for systems that manage Git objects individually (e.g., key-value stores). The design—streaming directly to `unpack-objects`—is pragmatic and avoids unnecessary intermediate steps.
