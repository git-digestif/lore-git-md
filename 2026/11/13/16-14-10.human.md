This is a bugfix patch targeting the `for-each-ref` command (and its alias `git refs list`). The issue is a segmentation fault when `--no-format` is passed, which the parse-options machinery allows despite the option not being explicitly designed to support negation. The crash occurs because the default format string is assigned before command-line parsing, and `--no-format` sets the format to NULL, which is later dereferenced.

The patch moves the default format assignment *after* parsing, so that if `--no-format` is used, the default is restored. This matches the behavior of `git branch` and `git tag`, which handle the same option gracefully. The fix is minimal: two lines of code moved, plus a new test case in `t/for-each-ref-tests.sh` that verifies `--no-format` restores the default output.

The commit message is clear and includes a reproduction recipe, the crash stack trace, and a reference to the commit that introduced the problem (c3428da87f, from 2007). The author also explains why `PARSE_OPT_NONEG` was not used: it would make `--no-format` an error, breaking consistency with other commands.

This looks like a well-crafted, low-risk fix for a real bug. The test coverage is appropriate, and the rationale is sound. Worth a quick review for anyone who uses `for-each-ref` or maintains its option parsing.
