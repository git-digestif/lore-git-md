This is the implementation patch for the opt-in toggle that Junio has already queued to resolve the `git log --follow` performance regression. The patch makes `--follow` in non-linear history optional by default, addressing GitLab’s deployment blocker while preserving the correctness fixes from the v5 series.

The patch introduces a new config value `log.follow=merges` (alongside the existing boolean `log.follow`) and a corresponding command-line option `--follow=merges`. By default, `--follow` will no longer track renames through merges unless explicitly enabled, mitigating the ~1.6× slowdown that remained after the v5 series. The implementation is straightforward: it adds a new enum-style config parser, updates the revision setup logic to respect the new flag, and disables the expensive rename-tracking logic in `log-tree.c` when `follow_merges` is off.

His feedback is purely mechanical—no objections to the design or default behavior. The patch is now queued and likely to land soon, decoupled from the v5 series to unblock GitLab’s deployment.
