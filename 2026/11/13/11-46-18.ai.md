This is a performance patch targeting the `git repo structure` command, part of a two-patch series by Patrick Steinhardt. The patch avoids fully parsing tree objects when only counting their entries, yielding a **20% speedup and 80% memory reduction** (5.1× less memory) in benchmarks on git.git.

The change is surgical: it replaces `parse_object_buffer()` with direct tree-desc traversal in `count_tree_entries()`, eliminating the need to allocate and retain parsed `struct tree` objects. The diff touches only `builtin/repo.c`, removing 12 lines and adding 7, with no behavior change—only resource usage. Benchmark numbers are provided in the commit message, showing clear wins on both wall time and peak memory.

This is the second patch in the series; the first (not shown here) likely laid groundwork. The motivation is clear: `git repo structure` was unnecessarily expensive, and this refactoring addresses that without altering functionality. The patch is well-motivated, well-measured, and looks ready for review.
