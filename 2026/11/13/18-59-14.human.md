This is a brief, surface-level review comment from Junio on the third patch in Jasper Mayone’s five-patch v5 series. The series extends Git’s ref-filter atoms to better handle worktrees, and this patch specifically replaces the old O(N*M) `%(worktreepath)` lookup with an O(1) hashmap-based implementation.

Junio’s comment is narrowly focused: he notes the "nice loss of duplicated logic" but questions whether the new `branch_checked_out_worktree()` function in `branch.c` overlaps with what `prepare_checked_out_branches()` already knows. He suggests the two might be redundant and hints that the new function should reuse the existing logic if possible. The comment is purely mechanical—no discussion of behavior, edge cases, or broader design—and does not indicate whether he sees this as a blocker or a minor nit.

The patch itself is well-motivated, thoroughly tested, and resolves a performance regression from v4. It also fixes a long-standing inconsistency where `%(worktreepath)` would report an empty string for rebasing or bisecting branches, even though those branches are treated as "checked out" by other Git commands. The breaking change for bare repositories (now returning an empty string instead of the bare repo’s path) is explicitly documented and tested. Unless the overlap Junio points out requires significant rework, this patch still looks like a clear improvement over the previous state.
