# Thread deltas

## 2026/11/13

- [2026/11/13/00-06-01 by Christian Couder <christian.couder@gmail.com>] Christian Couder submitted a patch fixing a crash when `git ls-remote` is run outside a repository with promisor remote config options that write to config (`promisor.acceptFromServerUrl` or `promisor.acceptFromServer` with `promisor.storeFields`), by returning early from `filter_promisor_remote()` when `repo->gitdir` is NULL, and added tests in t5710 for both crash cases.
- [2026/11/13/19-42-47 by Junio C Hamano <gitster@pobox.com>] Junio C Hamano suggested an alternative of making `promisor_remote_reply()` a NOOP outside a repository by adding a `repo` parameter (with an illustration patch updating its two callers), and noted that the code should comment on why punting when `.gitdir` is NULL is safe.

## 2026/11/16

- [2026/11/16/06-35-26 by Patrick Steinhardt <ps@pks.im>] Patrick Steinhardt proposed instead passing the repository down and detecting the no-repo case by checking `!repo`, calling a check of whether the passed repository is initialized a code smell (if not operating inside a repository, the caller shouldn't pass one); he said this may be a bigger refactoring, so depending on its scope he is happy to live with the easier fix for now, and added that the code should also detect `!repo` so it won't need adapting again once the call chains stop using `the_repository`.
- [2026/11/16/15-29-46 by Junio C Hamano <gitster@pobox.com>] Junio C Hamano agreed that passing the repository down and checking `!repo` would be the most sensible way forward, potentially helping more code paths become free of `the_repository`; he accepted the easier fix for now, and agreed the `!repo` case should also be detected, noting that with sufficient test coverage the `repo->gitdir` dereference would immediately segfault once a caller passes NULL instead of `the_repository`.
