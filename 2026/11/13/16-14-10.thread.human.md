This thread is about a long-standing bug in `for-each-ref` and `git refs list` that causes a segmentation fault when `--no-format` is used. The issue, present since 2007, arises because `--no-format` sets the format string to `NULL`, which isn’t handled properly before the code attempts to dereference it. Aeron-gh submitted a minimal fix that moves the default format assignment after command-line parsing, ensuring `--no-format` restores the default output instead of crashing. The patch includes a test to verify the fix and aligns `for-each-ref` with the behavior of `git branch` and `git tag`.

Junio’s review confirms the bug is real and raises a broader design question: should `--no-format` consistently restore the default format across all ref-listing commands, or should it be treated as an error? This could lead to a discussion about option consistency, but for now, the patch itself is uncontroversial and addresses the crash effectively. The only procedural note is that the author’s Signed-off-by line uses a pseudonym, which Junio flagged as needing alignment with the project’s real-name and DCO requirements. No objections to the fix have been raised, and the patch remains under review.
