This thread is about a long-standing bug in `git for-each-ref` (and `git refs list`) that causes a segmentation fault when `--no-format` is used. The crash occurs because the `--format` option is parsed in a way that allows `--no-format` to set the format string to `NULL`, which isn’t handled properly. The patch from aeron-gh fixes the crash by moving the default format assignment after command-line parsing, ensuring `--no-format` restores the default output instead of causing a crash. This aligns `for-each-ref` with how `git branch` and `git tag` already behave.

Junio, the maintainer, initially raised a design question about whether `--no-format` should consistently restore the default format across all ref-listing commands or be treated as an error. In this latest email, he now leans toward consistency, favoring the current patch’s approach. However, he hasn’t yet confirmed whether `git tag` behaves the same way as `git branch`, so the patch may need to be extended to ensure uniformity across all three commands. The real-name policy issue noted earlier hasn’t been revisited, but the technical resolution for the crash and `--no-format` behavior seems to be converging.

The patch itself is minimal and well-motivated, with a new test to verify the fix. The remaining open question is whether the patch should be updated to explicitly handle `git tag` or if that can be addressed in a follow-up. No other objections or loose ends have been raised.
