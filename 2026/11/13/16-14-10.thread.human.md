This thread is about a simple but long-standing bugfix for `git for-each-ref` and `git refs list`. When users ran either command with `--no-format`, they would get a segmentation fault because the code tried to use a `NULL` format string. The fix, now in its second version, moves the default format assignment after command-line parsing so that `--no-format` restores the default output instead of crashing. This matches how `git branch` and `git tag` already work.

Abhishek Agarwal sent the patch, and Junio Hamano (the maintainer) has confirmed both the bug and the fix. The only change from v1 to v2 was updating the Signed-off-by line to use a real name, as required by project policy. The patch touches just two files (`builtin/for-each-ref.c` and the test suite) and adds a test to ensure the fix works. There’s no controversy here—everyone agrees this is the right way to handle `--no-format`, and the patch is ready to be merged.
