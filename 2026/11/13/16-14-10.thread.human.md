This thread is about a long-standing bug in `git for-each-ref` (and possibly `git tag`) that causes a segmentation fault when `--no-format` is used. The issue arises because `--no-format` sets the format string to `NULL`, which isn't handled properly, leading to a crash. The fix, submitted by aeron-gh (now using the real name Abhishek Agarwal), moves the default format assignment after command-line parsing, ensuring `--no-format` restores the default output instead of causing a crash. This aligns `for-each-ref` with `git branch` and, as confirmed by Abhishek, `git tag`.

The patch is minimal and well-motivated, with a new test in `t/for-each-ref-tests.sh` to verify the fix. Junio Hamano, the maintainer, initially raised a design question about whether `--no-format` should consistently restore the default format across all ref-listing commands. That question is now resolved: Junio favors consistency, and Abhishek has confirmed the patch already implements this behavior. The only remaining loose end is the Signed-off-by line, which currently uses a pseudonym. Abhishek plans to send a v2 solely to fix this to comply with the project's real-name policy. Once that’s done, the patch should be ready for final review and merging. No code changes are expected beyond the sign-off update.
