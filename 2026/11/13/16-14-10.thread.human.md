This thread is about a simple but long-standing bugfix for a segmentation fault in `git for-each-ref` and `git refs list`. The issue occurs when `--no-format` is passed, which sets the format string to `NULL` due to how the `--format` option is declared. The fix, submitted by aeron-gh, moves the default format assignment after command-line parsing so that `--no-format` properly falls back to the default output, matching the behavior of `git branch` and `git tag`.

The patch is minimal—just four lines of code and six lines of test—and includes a new test in `t/for-each-ref-tests.sh` to verify the fix. The commit message clearly explains the problem, the solution, and why `PARSE_OPT_NONEG` wasn’t used. There’s been no discussion yet, but the change looks uncontroversial and well-motivated, addressing a crash that’s been present since 2007. If no objections arise, this should be a straightforward merge.
