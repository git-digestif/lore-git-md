This is a two-patch feature series introducing a new `--filter-to-loose` option for `git repack`. The goal is to improve interoperability with key-value object stores that manage Git objects individually by allowing filtered-out objects to be written directly as loose objects into a specified object directory, rather than as a packfile.

The series targets the repack machinery, adding a new `--filter-to-loose=<dir>` option. When used with `--filter`, `git repack` streams the filtered pack into `unpack-objects`, writing the excluded objects as loose objects in the specified directory. This avoids the need to unpack an intermediate packfile, simplifying workflows for systems that prefer loose object storage. The first patch implements the core functionality for objects already in packs, while the second extends it to include loose objects excluded by the filter, ensuring the destination directory receives all relevant objects. Objects already present in the destination are not rewritten, and with `-d`, the source copies of loose objects are removed after successful writing.

The implementation touches `builtin/repack.c`, `repack-filtered.c`, and `repack.h`, with new tests added to `t/t7700-repack.sh`. The documentation in `Documentation/git-repack.adoc` is updated to describe the new option. The commit messages are clear and the code changes appear focused, though the series does not yet include feedback from reviewers. The feature addresses a real workflow pain point for systems that rely on loose object storage, and the design—streaming directly to `unpack-objects`—seems pragmatic. Whether this will see adoption depends on how widely such key-value stores are used with Git, but the implementation itself looks clean and well-scoped.
