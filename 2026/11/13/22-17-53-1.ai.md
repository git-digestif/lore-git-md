This is a **revised bugfix for Git v3 compatibility**, addressing the issues identified in the previous iteration. The patch ensures `git init` correctly defaults to SHA-256 when Git is built with `WITH_BREAKING_CHANGES=1` (or in Git 3.0) while also preventing silent reinitialization of existing repositories with a different hash algorithm.

The core change restructures `repository_format_configure()` in `setup.c` to enforce two key behaviors: (1) defaulting to `GIT_HASH_DEFAULT` only for *new* repositories (where `repo_fmt->version < 0` or the hash is explicitly unset), and (2) refusing to reinitialize an existing repository with a different hash algorithm. The logic now prioritizes command-line arguments, then environment variables, then config, and finally the default—mirroring the approach used for ref-storage format handling. This resolves the latent bug in `read_repository_format()` (where `version == -1` forced SHA-1) and the regression where reinitialization silently clobbered the object format.

- Rejection of reinitialization with a different hash algorithm.
