This is a performance patch for the `git repo structure` command, part of the ongoing `git repo` built-in effort. Patrick Steinhardt identifies a clear inefficiency: the command currently reads and parses *every* object it encounters (blobs, tags, commits, trees) even though it only needs parsed data for commits and trees. The fix is surgical: skip parsing for blobs and tags entirely, and for commits, reuse the already-parsed object from the revision walk instead of re-reading it.

The patch touches only `builtin/repo.c` (16 insertions, 7 deletions) and is well-motivated with a before/after benchmark in git.git: wall-clock time drops by 12.1% (10.9 s → 9.6 s) and memory use by 4.1% (3.5 GiB → 3.4 GiB). The commit message is clear and the code changes are minimal and focused. No new tests are added, but the existing test suite should catch any regressions in the object-counting logic.

This is the first patch in a two-patch series; the cover letter is not provided here, so the second patch’s role is still unclear. The change looks uncontroversial and ready for review.
