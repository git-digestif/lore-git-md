This is the third patch in Caspar Duregger’s four-part bugfix series addressing inconsistent error handling in `git cat-file --batch` and related commands. The series targets a regression introduced in commit 393bbb21 (June 2025), where `GET_OID_GENTLY`—a flag meant to enable graceful error reporting—was not applied consistently across all lookup paths, causing fatal errors for invalid references like out-of-bounds reflog entries.

This patch specifically fixes how `read_ref_at()` handles empty reflogs. Previously, the function would die with "log for <ref> is empty" (or exit silently with `GET_OID_QUIETLY`) when asked for any reflog entry beyond the 0th in an empty log. Now, when `GET_OID_GENTLY` is set, it returns `-1` instead, allowing the caller (`get_oid_basic()`) to treat it as a failed lookup. The change ensures `git stash export` reports "unable to find stash entry" rather than silently exiting when processing an emptied stash reflog. The fix touches `refs.c`, `object-name.c`, and `refs.h`, with a new test in `t/t3903-stash.sh` verifying the behavior.
