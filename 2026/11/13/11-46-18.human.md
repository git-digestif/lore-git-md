This is a performance patch for the `git repo` command, specifically targeting the `structure` subcommand. It’s the second patch in a two-patch series by Patrick Steinhardt.

The patch avoids fully parsing tree objects when counting their entries during a revision walk. Instead of calling `parse_object_buffer()` and keeping the parsed tree in memory, it directly counts entries from the raw object buffer. This change reduces peak memory usage by 80% (from 3.4 GiB to 0.7 GiB) and speeds up execution by 20% in the benchmark on git.git.

The implementation is straightforward: the `count_tree_entries()` helper is refactored to accept the raw buffer and size instead of a parsed `struct object`, and the caller now frees the buffer immediately after counting rather than relying on the object parser’s ownership flag. The patch touches only `builtin/repo.c` and is well-motivated by the included benchmark data. It looks like a clean, uncontroversial optimization.
