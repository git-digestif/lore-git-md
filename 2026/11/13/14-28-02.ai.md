This is the second patch in a four-part bugfix series addressing inconsistent error handling in `git cat-file --batch` for invalid references. The series targets a regression introduced by commit 393bbb21 ("object-name: make get_oid quietly return an error", 2025-06-12), which added the `GET_OID_GENTLY` flag to allow graceful error returns instead of fatal errors but applied it inconsistently.

This patch refines how `GET_OID_GENTLY` behaves in `get_oid_basic()` by ensuring the flag *only* affects failing lookups, not successful ones. Previously, the flag incorrectly turned two valid cases—`ref@{<date>}` older than the reflog and `ref@{N}` for a reflog with N entries—into errors. The fix moves the `GET_OID_GENTLY` check into the failure branch of the lookup cascade, restoring the intended behavior: `ref@{<date>}` now resolves to the oldest known value, and `ref@{N}` resolves to the "old" side of the oldest entry, matching their behavior without the flag. The change is minimal (9 lines modified in `object-name.c`) and includes a new test in `t/t3903-stash.sh` to verify `git stash export` now handles `stash@{<date>}` gracefully, aligning with `git stash show`.

The patch is uncontroversial and directly addresses feedback from the original review of 393bbb21, which questioned the overbroad application of `GET_OID_GENTLY`. The commit message clearly explains the rationale and edge cases, and the test coverage confirms the fix works as intended. This is a targeted bugfix with no behavioral changes beyond correcting the regression, and it touches core object-name lookup machinery, so reviewers familiar with `GET_OID_GENTLY` or reflog parsing will likely focus on the logic in `get_oid_basic()`. The series remains under review, with no indication of merge to `master`.
