This is a performance-focused bugfix for the `git repo` command, specifically targeting the `structure` subcommand. Patrick Steinhardt reports that in very large repositories, the command can trigger an out-of-memory (OOM) error. The two-patch series aims to reduce memory usage and improve speed by avoiding unnecessary parsing of objects during the object-counting process.

The patches modify `builtin/repo.c` to change how trees are processed: instead of fully parsing every tree object, the code now parses objects only as needed. This is a targeted optimization for the `git repo structure` operation, which walks the repository's object graph to count objects. While the patches don't fully solve the performance issues in repositories with 33 billion tree entries (Patrick notes that tree-walking in such cases remains slow and "kinda broken"), they address the immediate OOM problem.

The series is well-motivated and appears to be a practical fix for a real-world issue. Patrick is a prolific contributor with deep expertise in Git's object storage layer, so the patches are likely to be technically sound. The commit messages and cover letter are clear about the scope and limitations of the changes. This looks like a straightforward improvement that should be uncontroversial and worth reviewing for anyone interested in large-repository performance.
