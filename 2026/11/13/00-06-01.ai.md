This is a bugfix targeting the promisor-remote subsystem. The patch prevents a crash in `git ls-remote` when run outside a repository with certain promisor-remote configuration options enabled (`promisor.acceptFromServerUrl` or `promisor.acceptFromServer` with `promisor.storeFields`). The crash occurs because the code attempts to access `repo->gitdir` when it is `NULL` in this context.

The fix is minimal: it adds a guard clause at the start of `filter_promisor_remote()` to return early if `repo->gitdir` is `NULL`. The commit message explains that this is safe because `git ls-remote` has no use for promisor remotes outside a repository. The regression was introduced in two earlier commits (3e20258d11 and 7a56394fc6), both from 2026, and the patch includes new tests in `t5710` to verify the fix for both crash scenarios.

The patch is well-motivated, with a clear explanation of the problem, the regression timeline, and the rationale for the fix. The added tests cover the edge cases explicitly. This looks like a straightforward and necessary fix for a real-world crash.
