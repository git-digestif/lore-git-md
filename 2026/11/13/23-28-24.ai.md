This is the **v3 security bugfix patch** that closes the second of two critical flaws in Git's SSH signing verification, completing the pair of fixes reported earlier in the thread. The patch makes Git fail closed when the `gpg.ssh.revocationFile` is configured but missing or unreadable, rather than warning and proceeding as if no revocation file existed. This aligns Git's behavior with OpenSSH's `sshd`, which refuses all public key authentication when its `RevokedKeys` file is unreadable.

The change is minimal and surgical: it removes the warning-and-continue logic in `gpg-interface.c` and replaces it with an early error return when the revocation file is missing. The error message is clear ("ssh signing revocation file configured but not found") and the signature information is still displayed, so users see why verification failed. The escape hatch is the existing Git `:(optional)` pathname prefix, which allows users to opt out of the new strictness by prefixing the revocation file path; this is documented in `Documentation/config/gpg.adoc`.

Test coverage is thorough: four new test cases in `t/t7528-signed-commit-ssh.sh` cover revoked keys, missing files, and the `:(optional)` override. The tests verify both the failure case and the escape hatch, and confirm that the `%G?` status code ("U") is consistent for both missing revocation files and unknown keys.

The patch is clean, well-motivated, and directly implements the design consensus reached in the thread. It carries `Suggested-by` and `Helped-by` trailers crediting Patrick Steinhardt and Phillip Wood, and the commit message clearly explains the security rationale, the escape hatch, and the existing behavior of `:(optional)`. Junio's feedback on error-handling flow has been incorporated, and the patch applies cleanly to current `master`. No open questions remain; this is ready for integration.
