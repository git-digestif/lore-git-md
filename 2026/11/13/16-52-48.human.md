This is a performance optimization patch that has already received positive review. Junio C Hamano weighs in on a minor but important detail in the patch's explanatory comments. The patch itself reorders fields in `struct commit` to eliminate padding on 64-bit platforms, reducing its size from 80 to 72 bytes (a 10% memory saving) with no behavioral change.

The discussion here focuses solely on the wording of a comment in `commit.h`. Kristofer Karlsson's v2 patch added a comment stating that `struct object` must be the first member of `struct commit` so that a "struct object *" can be cast to a "struct commit *". Both Derrick Stolee and Junio point out that this phrasing is backwards: the safe and common operation is casting a `struct commit *` to a `struct object *`, not the reverse. Junio suggests precise wording that clarifies the downcast (commit to object) is always safe, while the upcast (object to commit) requires external knowledge that the object is actually a commit.

The patch is otherwise ready for merging; this is a surface-level review comment about documentation clarity, not a technical objection. The broader conversation about how to enforce awareness of struct bloat (regression tests, compile-time assertions, or architecture-specific dummy members) continues separately and does not block this patch.
