This thread is about a bugfix for a crash in `git ls-remote` when run outside a Git repository with specific promisor-remote configuration options enabled. The issue was introduced in two commits from 2026 and causes a segmentation fault when the code tries to access `repo->gitdir` while it is `NULL`.

Christian Couder authored the fix, which adds a simple guard clause to `filter_promisor_remote()` to return early if `repo->gitdir` is `NULL`. The fix is minimal and well-justified, as `git ls-remote` has no need for promisor remotes outside a repository. The patch also includes new tests in `t5710` to verify the fix for both crash scenarios.

The fix is straightforward and addresses a real-world issue, making it a clear candidate for merging. No objections or alternative approaches have been raised so far, and the patch appears ready for integration.
