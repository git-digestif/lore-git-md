This thread is about a bugfix for a crash in `git ls-remote` when run outside a Git repository with promisor-remote configuration enabled. The crash occurs because `filter_promisor_remote()` dereferences `repo->gitdir` without checking for `NULL`. Christian Couder proposed a minimal fix by adding an early return in `filter_promisor_remote()` when `repo->gitdir` is `NULL`, along with new tests to cover the crash scenarios.

Junio C Hamano reviewed the patch and suggested an alternative approach: making `promisor_remote_reply()` a no-op when no repository is present, rather than guarding against `NULL` in `filter_promisor_remote()`. His reasoning is that `git ls-remote` has no legitimate use for promisor remotes outside a repository, so the higher-level function should handle the case. This would require updating the callers of `promisor_remote_reply()` but could avoid unnecessary work in `filter_promisor_remote()`. Junio also emphasized the need for clear documentation explaining why the function punts when `repo->gitdir` is `NULL`.

The discussion is now centered on which approach—Christian’s minimal fix or Junio’s higher-level solution—is more maintainable and less prone to future regressions. No additional edge cases or tests have been raised, and the outcome will likely depend on which design is deemed cleaner. The patch is still under review, with no decisions made yet.
