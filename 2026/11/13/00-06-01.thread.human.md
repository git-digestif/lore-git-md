This thread is about fixing a crash in `git ls-remote` when run outside a Git repository with promisor-remote configuration enabled. The bug, introduced in early 2026, occurs because `filter_promisor_remote()` dereferences `repo->gitdir` without checking for NULL.

Christian Couder proposed a minimal fix—adding a NULL check in `filter_promisor_remote()`—along with tests. Junio Hamano and Patrick Steinhardt, however, prefer a more principled approach: making `promisor_remote_reply()` a no-op when no repository is present by having it take a `struct repository *` parameter and early-return if `repo` is NULL. This aligns with Git’s broader effort to eliminate implicit reliance on `the_repository`. While Junio now accepts Christian’s fix as a short-term solution, both he and Patrick emphasize that the `!repo` case should be handled explicitly in future refactoring.

The discussion is settled on the immediate fix, but the thread has clarified expectations for longer-term cleanup in the promisor-remote subsystem. No further objections or open questions remain.
