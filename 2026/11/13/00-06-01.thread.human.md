This thread is about fixing a crash in `git ls-remote` when run outside a Git repository with promisor-remote configuration enabled. The crash occurs because `filter_promisor_remote()` dereferences `repo->gitdir` without checking for NULL, a regression introduced in early 2026.

Christian Couder proposed a minimal fix—adding a NULL check in `filter_promisor_remote()`—along with tests. Junio Hamano countered with an alternative: making `promisor_remote_reply()` a no-op when no repository is present, arguing this is cleaner and avoids unnecessary work. Patrick Steinhardt has now weighed in, favoring Junio’s approach in principle for its alignment with Git’s modern practices but acknowledging that Christian’s fix could serve as a short-term solution. The discussion remains focused on design trade-offs, with agreement that the rationale for punting in the no-repo case should be documented. No new edge cases or test gaps have emerged, and the series is still under review.
