Originating author: Yusuke Hayashi
Thread type: patch (cleanup)

Core problem or goal
Remove an unnecessary and incorrect pre-sizing step in `get_info_packs()` that was introduced in 2009. The function iterated over all packs twice—once to count local packs and pre-size a `strbuf`, and again to format the output—despite `strbuf_addf()` already handling dynamic growth. The pre-sizing logic was also incorrect for SHA-256 repositories (underestimating line length) and used unchecked arithmetic.

Current status
**Merged to 'next' (date unknown).** The patch is in its second iteration (v2), with the commit message updated to address the reviewer’s justification challenge. Both Patrick Steinhardt and Junio C Hamano have explicitly accepted the author’s rationale: `get_info_packs()` is a one-shot CGI handler for dumb HTTP requests (`GET /objects/info/packs`), where the overhead of dynamic `strbuf` growth (a few dozen reallocations even with thousands of packs) is negligible compared to the cost of CGI startup, scanning the pack directory, and writing the HTTP response. The thread is fully converged, and the patch is now queued for integration testing in Junio’s `next` branch.
