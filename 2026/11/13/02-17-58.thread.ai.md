Subject: [PATCH] http-backend: remove unnecessary pre-sizing in get_info_packs()
Series version: standalone patch (no series)
Originating author: Yusuke Hayashi
Thread type: patch (cleanup)

Core problem or goal
Remove an unnecessary and incorrect pre-sizing step in `get_info_packs()` that was introduced in 2009. The function iterated over all packs twice—once to count local packs and pre-size a `strbuf`, and again to format the output—despite `strbuf_addf()` already handling dynamic growth. The pre-sizing logic was also incorrect for SHA-256 repositories (underestimating line length) and used unchecked arithmetic.

Current status
Under review. No prior versions of this patch exist. The patch is contested on grounds of justification: while the pre-sizing logic is acknowledged as buggy, the reviewer (Patrick Steinhardt) questions whether removing it entirely is preferable to fixing it, given the implicit performance trade-off (dynamic `strbuf` growth vs. a second loop over packs). The author has not yet responded to the challenge.

Key technical details
- File touched: `http-backend.c`
- Function modified: `get_info_packs()`
- Symbols: none added or renamed; the patch removes the counting loop and `strbuf_grow()` call
- Behavior change: none (output remains identical); the patch is a pure cleanup
- On-disk format: unchanged
- Test coverage: none added; the patch is covered by existing HTTP backend tests

Open questions and loose ends
1. Justification for removal: The patch’s rationale (citing a similar cleanup in `add_rfc2047()`) is deemed insufficient by the reviewer. The author must either provide profiling data showing the performance impact is negligible or a clearer explanation of why the pre-sizing hint is unnecessary in this context (e.g., typical pack counts, call frequency).
2. Performance trade-off: The reviewer explicitly asks whether the overhead of dynamic `strbuf` growth outweighs the cost of a second loop over packs, leaving this unresolved.
