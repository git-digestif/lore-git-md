Core problem or goal
Remove an unnecessary and incorrect pre-sizing step in `get_info_packs()` that was introduced in 2009. The function iterated over all packs twice—once to count local packs and pre-size a `strbuf`, and again to format the output—despite `strbuf_addf()` already handling dynamic growth. The pre-sizing logic was also incorrect for SHA-256 repositories (underestimating line length) and used unchecked arithmetic.

Current status
Approved and poised for merging. The patch is in its second iteration (v2), with the commit message updated to address the reviewer’s justification challenge. Patrick Steinhardt has explicitly accepted the author’s rationale: `get_info_packs()` is a one-shot CGI handler for dumb HTTP requests (`GET /objects/info/packs`), where the overhead of dynamic `strbuf` growth (a few dozen reallocations even with thousands of packs) is negligible compared to the cost of CGI startup, scanning the pack directory, and writing the HTTP response. No further changes are requested, and the thread is converged pending Junio’s integration.
