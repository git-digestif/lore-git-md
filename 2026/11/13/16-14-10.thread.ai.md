Core problem or goal
The `for-each-ref` and `git refs list` commands crash with a segmentation fault when invoked with `--no-format` because the `--format` option is declared with `OPT_STRING()`, which allows `--no-format` to set the format string to `NULL`. The default format is assigned before command-line parsing, so nothing restores it, leading to a `NULL` dereference in `verify_ref_format()`. The bug has existed since 2007 (commit `c3428da87f`).

Current status
Under review. The patch is a minimal, well-motivated fix that aligns `for-each-ref` with `git branch` and `git tag` by moving the default format assignment *after* command-line parsing. This ensures `--no-format` restores the default output and can also cancel an earlier `--format`. The patch includes a new test in `t/for-each-ref-tests.sh` to verify the fix.

Key technical details
- Files touched: `builtin/for-each-ref.c`, `t/for-each-ref-tests.sh`
- Subsystems: ref listing, command-line option parsing
- New test: added to `t/for-each-ref-tests.sh` to cover `--no-format` behavior
- Behavior change: `--no-format` now restores the default format instead of causing a crash
- On-disk format: unchanged
- Test coverage: minimal but sufficient for the bug scope
