Subject: [PATCH] for-each-ref: fix segfault with --no-format
Series version: standalone patch (v2 expected for Signed-off-by only)
Originating author: Abhishek Agarwal (formerly aeron-gh)

Core problem or goal
The `for-each-ref` and `git refs list` commands crash with a segmentation fault when invoked with `--no-format` because the `--format` option is declared with `OPT_STRING()`, which allows `--no-format` to set the format string to `NULL`. The default format is assigned before command-line parsing, so nothing restores it, leading to a `NULL` dereference in `verify_ref_format()`. The bug has existed since 2007 (commit `c3428da87f`).

Current status
Under final review, effectively converged. The patch moves the default format assignment *after* command-line parsing, ensuring `--no-format` restores the default output and can cancel an earlier `--format`. This aligns `for-each-ref` with `git branch` and `git tag` (both confirmed to behave identically). Junio now favors making `--no-format` consistently restore the default format across all ref-listing commands. The patch includes a new test in `t/for-each-ref-tests.sh` to verify the fix. A v2 will be sent solely to update the Signed-off-by line to comply with the real-name policy; no code changes are expected.

Key technical details
- Files touched: `builtin/for-each-ref.c`, `t/for-each-ref-tests.sh`
- Subsystems: ref listing, command-line option parsing
- New test: added to `t/for-each-ref-tests.sh` to cover `--no-format` behavior, verifying that `--format=<fmt> --no-format` produces the same output as no format option
- Behavior change: `--no-format` now restores the default format instead of causing a crash; this behavior is confirmed consistent across `for-each-ref`, `branch`, and `tag`
- On-disk format: unchanged
- Test coverage: minimal but sufficient for the bug scope; no additional tests for `git tag` or `git branch` are needed as their behavior is already consistent
