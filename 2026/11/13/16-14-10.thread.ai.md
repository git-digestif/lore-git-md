Subject: [PATCH] for-each-ref: fix segfault with --no-format
Series version: standalone patch
Originating author: aeron-gh
Thread type: bugfix patch

Core problem or goal
The `for-each-ref` and `git refs list` commands crash with a segmentation fault when invoked with `--no-format` because the `--format` option is declared with `OPT_STRING()`, which allows `--no-format` to set the format string to `NULL`. The default format is assigned before command-line parsing, so nothing restores it, leading to a `NULL` dereference in `verify_ref_format()`. The bug has existed since 2007 (commit `c3428da87f`).

Current status
Under review, converging toward resolution. The patch remains a minimal, well-motivated fix that moves the default format assignment *after* command-line parsing, ensuring `--no-format` restores the default output and can cancel an earlier `--format`. This aligns `for-each-ref` with `git branch` (and, per Junio's latest note, likely `git tag`). Junio now favors making `--no-format` consistently restore the default format across all ref-listing commands, settling the design question raised in his earlier review. The patch includes a new test in `t/for-each-ref-tests.sh` to verify the fix. Implementation details for `git tag` remain unconfirmed but are expected to follow the same pattern.

Key technical details
- Files touched: `builtin/for-each-ref.c`, `t/for-each-ref-tests.sh`
- Subsystems: ref listing, command-line option parsing
- New test: added to `t/for-each-ref-tests.sh` to cover `--no-format` behavior
- Behavior change: `--no-format` now restores the default format instead of causing a crash; this behavior is intended to be consistent across `for-each-ref`, `branch`, and `tag`
- On-disk format: unchanged
- Test coverage: minimal but sufficient for the bug scope; no test for `git tag` behavior yet

Open questions and loose ends
