This is a **substantive review** of a bugfix targeting the promisor-remote subsystem. Junio C Hamano responds to Christian Couder’s patch that fixes a crash in `git ls-remote` when run outside a repository with promisor-remote configuration enabled. The crash occurs because `filter_promisor_remote()` dereferences `repo->gitdir` without checking for `NULL`.

Junio acknowledges the problem but proposes an alternative approach: instead of guarding against `NULL` in `filter_promisor_remote()`, he suggests making `promisor_remote_reply()` a no-op when no repository is present. His illustration patch modifies `promisor_remote_reply()` to take a `struct repository *` parameter and early-return if `repo->gitdir` is `NULL`. He notes that this would require updating the two callers of the function but argues it might be a cleaner solution since `git ls-remote` has no legitimate use for promisor remotes outside a repository.

The review is substantive because it engages with the design of the fix rather than just its implementation. Junio’s alternative addresses the same issue but at a higher level in the call chain, which could avoid unnecessary work in `filter_promisor_remote()` entirely. He also raises a documentation point: the rationale for punting when `repo->gitdir` is `NULL` should be explicitly commented in the code, though his illustration patch only partially addresses this.

The discussion is now focused on whether to fix the issue at the original site (Christian’s approach) or higher up (Junio’s suggestion). The outcome will likely hinge on which approach is deemed more maintainable and less prone to future regressions. No tests or further edge cases are raised, but the review implies that either solution would be acceptable if properly documented.
