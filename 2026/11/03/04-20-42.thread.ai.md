Core problem or goal
Fix a crash in Git’s Rust `hash` module when formatting an `ObjectID` whose `algo` field contains an unrecognized algorithm identifier. The panic occurs because the `Display` implementation calls `unwrap()` on a function that returns an error for invalid algorithms.

Current status
Under review; no prior versions. Patch is small, self-contained, and includes a regression test. Base commit is recent (`a0018953688f1b10bddf91bff87474068f5f4746a4`), targeting the current development cycle.

Key technical details
- File modified: `src/hash.rs`
- Function: `Display` impl for `ObjectID`
- New behavior: invalid algorithms are formatted as the raw hash storage followed by `:invalid-hash-algo-<id>` (e.g., `abc123:invalid-hash-algo-99`)
- Test added: `invalid_object_ids_format_without_panicking` in `src/hash.rs`
- Constants referenced: `GIT_MAX_RAWSZ`
- Subsystem: ODB (object database), though this is purely a formatting fix with no on-disk format change

Open questions and loose ends
None yet; the patch is complete and addresses the crash without altering behavior for valid algorithms.
