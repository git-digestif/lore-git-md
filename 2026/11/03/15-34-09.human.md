This is a feature proposal for `git branch`. Johannes Welsch suggests adding a `-s` (or `--switch`) option to `git branch` that would create a new branch and immediately switch to it, mirroring the behavior of `git switch -c <branch>`.

The motivation is ergonomic: users who think of the operation as "create a branch and then switch to it" may naturally reach for `git branch` first, rather than `git switch -c`. The proposal argues that switching is an ancillary action to branch creation, not the primary operation, so the option belongs on `git branch` rather than `git switch`.

The patch itself is not yet written—this is an RFC to gauge interest. The proposed behavior would match `git switch -c` exactly: create the branch, switch to it, and fail if the branch already exists. No edge cases or additional flags are discussed.

The idea is straightforward and targets a common workflow. Whether it gains traction will likely depend on how the community weighs consistency (keeping branch-switching logic on `git switch`) against discoverability (letting users start from `git branch`). For now, it’s a small, self-contained suggestion that busy readers can quickly assess as either a sensible convenience or unnecessary duplication.
