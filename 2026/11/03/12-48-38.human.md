This is the second patch in a two-patch refactoring series (v3) that moves the `pack.packsizelimit` configuration value from a global variable into the repository-scoped `repo_config_values` struct. The change is part of the ongoing effort to eliminate global state in Git, improving modularity and making the codebase more suitable for use as a library.

The patch itself is straightforward: it removes the standalone global `pack_size_limit_cfg` and adds a `pack_size_limit` field to `struct repo_config_values`. The configuration parser (`git_default_config`) and the pack-writing code (`builtin/pack-objects.c` and `object-file.c`) are updated to read the value from the repository’s configuration struct instead. The preparatory patch (1/2) already ensured the struct is zero-initialized with `memset`, so this patch only needs to add the new field and update the access sites.

The commit message clearly explains the motivation—removing global state—and the change is purely mechanical with no behavioral impact. Joy reports successful test runs (`t1300-config.sh` and `t5300-pack-object.sh`), and the patch has already received technical approval from Patrick Steinhardt, who reviewed the previous version and stated it "reads well" with no further feedback. The only remaining feedback (cosmetic nits on the preparatory patch) has been addressed in this v3.

This is a well-crafted, uncontroversial refactoring that aligns with Patrick Steinhardt’s broader goals for the codebase. It’s ready for integration and should be a low-risk addition to `next`. If you’re following the `the_repository` removal effort, this is a small but meaningful step forward.
