This is a reply from the author (Ravi Mistry) to Junio C Hamano’s review of patch 2/4 in the HTTP retry series. The patch adds exponential backoff for retries when servers return HTTP 429 without a Retry-After header.

Ravi acknowledges Junio’s observation that the default `http.retryAfter=0` (immediate retry) does not mesh well with exponential backoff, but explains that he kept the default to preserve existing behavior introduced in commit 640657ffd0 and its associated tests. He updated the documentation in v2 to make this behavior explicit. On the technical side, Ravi agrees with Junio’s suggestion to reuse the existing `rate_limit_retries` counter (passing `http_max_retries - rate_limit_retries` as the attempt count) instead of introducing a new `attempt` variable, and has incorporated this change into v2. The patch now avoids the extra variable and maintains cleaner state management.

The response is brief and focused, addressing both of Junio’s points without introducing new questions or design changes. The series remains well-motivated and technically sound, with v2 now incorporating all feedback from Junio’s review. The unresolved question about whether 5xx errors should be retryable by default remains open, but this reply does not revisit it.
