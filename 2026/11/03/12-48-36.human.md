This is a refactoring patch series from an Outreachy contributor, part of the ongoing effort to eliminate global state in Git. Joy Gundu’s v3 series moves the `pack.packsizelimit` configuration value from a standalone global variable into the repository-scoped `repo_config_values` struct, making Git’s internals more modular and library-friendly.

The series consists of two patches. The first is a preparatory cleanup that replaces manual zero-initialization of `repo_config_values` with a `memset()` call, reducing boilerplate for future additions. The second patch does the core work: migrating `pack.packsizelimit` into the struct and updating all code paths to read it from there instead of the global variable. Both patches are mechanical and preserve existing behavior.

Joy has incorporated all feedback from earlier rounds, including Patrick Steinhardt’s suggestion to split the `memset()` cleanup into its own patch and improve commit messages. Patrick’s final review of v2 confirmed the second patch was technically sound, and Joy has addressed the remaining cosmetic nits (commit message and comment tweaks) in this v3. The series is now effectively ready for integration, pending Junio’s queueing.

Testing looks solid: Joy reports successful builds and clean runs of `t1300-config.sh` and `t5300-pack-object.sh`, with only minor permission errors during test cleanup (unrelated to the changes). The patch touches four files (`builtin/pack-objects.c`, `environment.c`, `environment.h`, and `object-file.c`) and is well-contained, affecting only pack-object handling and object database configuration.

This is a textbook example of a well-executed refactoring: small, focused, and aligned with the project’s long-term goals. The series is uncontroversial and should be a straightforward merge once Junio picks it up.
