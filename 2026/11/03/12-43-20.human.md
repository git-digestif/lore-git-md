This is the first patch in a three-part bugfix series for `git grep --recurse-submodules`. It fixes a regression introduced in Git v2.56.0 (commit 93cd344e34f) that causes the command to fail when grepping nested submodule trees. The root cause is straightforward: while blobs in submodules are correctly read via the submodule’s repository, trees are still read from `the_repository`, leading to "unable to read tree" errors.

The fix itself is minimal—just one line in `builtin/grep.c`—changing `grep_tree()` to read trees via `repo->objects` instead of `the_repository->objects`. The patch also adds a new test in `t/t7814-grep-recurse-submodules.sh` that verifies the fix by grepping a submodule with nested directories. The test is well-constructed, setting up a fresh repository with a submodule containing both top-level and nested files, and confirming the expected output.

The commit message is clear and thorough, explaining the regression context, the two recursion paths in `grep_tree()`, and why the fix works. It also notes that the bug went unnoticed because existing tests only covered submodules with top-level files. The regression version is now explicitly stated (Git v2.56.0), which is helpful for downstream maintainers assessing backport urgency.

This patch is the core of the series and looks solid. The fix is targeted, the test coverage is appropriate, and the motivation is well-documented. The series as a whole is intended for stable branches, and this patch is the one that actually resolves the reported issue.
