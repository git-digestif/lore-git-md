This is the second patch in the v7 series adding eight new path-related keys to `` `git repo info` ``. The patch fixes a correctness bug in `` `get_superproject_working_tree()` ``: the function previously used `` `xgetcwd()` `` to determine which repository’s superproject to check, so it would return the wrong result (or none at all) when `` `--git-dir` `` pointed to a different repository than the current working directory. The fix is simple—pass the `` `repository` `` parameter through and use the repository’s working directory instead of the process’s cwd.

The patch itself is mechanically clean and the core change is correct. However, the new test in `` `t/t7400-submodule-basic.sh` `` accidentally exercises `` `path.superproject-root.absolute` ``, a key that is not introduced until the next patch (3/8). This breaks bisectability, so the test must be rewritten to use the existing `` `git rev-parse --show-superproject-working-tree` `` instead. The author has already acknowledged the issue and will send a trivial fix.

Once the test is adjusted, this patch is ready to move forward. It is a small, focused bugfix that does not touch any controversial areas and has no unresolved design questions.
