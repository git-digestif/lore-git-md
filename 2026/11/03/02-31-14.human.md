This is Junio’s "What’s cooking in git.git" report for early November 2026, summarizing the state of 100+ topics currently in flight.

The report is a snapshot of Junio’s integration branches: topics marked “+” are in ‘next’ (stable enough to be candidates for the next release), while those marked “-” are only in ‘seen’ (not yet accepted).  A handful of topics have already graduated to ‘master’ since the last report, and a few long-stalled topics are listed as likely to be discarded.

Highlights for a busy reader
• A steady stream of test modernizations (t5300, t0410, t5402, t7104, t0001, t0081, t1450, t2403) continues; these are small, safe, and ready to merge.
• Several subsystems are being libified to remove the global `the_repository` variable: `rerere`, `bundle-uri`, `diffcore-rename`, `merge-blobs`, `range-diff`, and `checkout` are all in progress.
• Two new user-facing features are cooking: `git branch --delete-integrated` (find and remove branches whose work was squash-merged) and `git status` now compares against both upstream and push branches by default.
• A regression in `git grep --recurse-submodules` (it failed to read nested trees) is fixed; the fix also removes latent bugs in `grep_cache()` and `grep_objects()`.
• The object storage format is now configurable via `extensions.objectStorage`, paving the way for pluggable backends.
• The pack index v3 format (part of the SHA-1/SHA-256 interoperability work) is ready for review.
• CI and build system improvements: GitHub Actions are pinned to full commit IDs, ccache is taught to cache precompiled headers, and the required Perl version is bumped to 5.26.0.

Nothing in the report looks sloppy or under-motivated; the topics are either small cleanups, well-explained fixes, or carefully staged parts of larger efforts.  The only likely controversy is the new `status.compareBranches` default, which changes long-standing behavior for triangular workflows—watch for discussion if you care about that.
