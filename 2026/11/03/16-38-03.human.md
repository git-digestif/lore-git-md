This is a substantive review of a bug in `git diff --word-diff`. Phillip Wood confirms the issue Jean Abou Samra reported and explains why it happens: Git’s word-diff logic splits hunks at context lines (like blank lines) before computing word-level differences, which can cause it to misalign or omit large unchanged sections when whitespace changes are present. The result is technically correct but practically useless for understanding word-level edits.

Phillip traces the root cause to the hunk-splitting behavior and suggests a fix: feed entire hunks from the line-level diff into the word-diff engine instead of breaking them at context lines. He also notes that a modified patience diff algorithm (which avoids falling back to Myers) produces a more sensible word-diff in this case, though that’s not the core issue.

The review is credible and well-informed, coming from a frequent contributor with deep knowledge of Git’s diff machinery. It advances the thread by diagnosing the problem and proposing a clear technical direction for a fix. No patches are attached yet, but the explanation gives maintainers a concrete starting point. This looks like a real bug worth attention from anyone working on the diff subsystem.
