This is a brief follow-up in the HTTP resilience series. Ravi Mistry confirms that the removal of the early-return guard clause in `http.c` (which Junio questioned in his review of patch 1/4) is intentional and correct. The guard is redundant because the retry loop condition now handles the same case, and moving the check after the loop also prevents a misleading "retries-exhausted" log message when an initial 401 (authentication failure) is followed by a 429 (rate limit) during re-authentication with `http.maxRetries=0`. Ravi has updated the commit message in v2 to clarify this reasoning.

The exchange is purely about code clarity and logging correctness; no functional behavior changes are at stake. The patch remains a well-scoped bugfix targeting the HTTP transport layer, and the v2 iteration is now clearer and more maintainable. No further discussion is needed on this point.
