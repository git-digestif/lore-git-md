This is a **bugfix discussion** about the quarantine alternate refs performance regression. Justin Tobler replies to Patrick Steinhardt’s proposal to rethink the fix, offering a concrete short-term alternative.

Justin agrees with Patrick that the current approach—swapping the "real" and quarantine object directories—is fragile. His preferred long-term solution is to stop modifying the primary object directory entirely and instead propagate transaction context via environment variables, allowing child processes to reconstruct the proper environment. This aligns with his ongoing ODB transaction work but is a larger change.

For a short-term fix, Justin suggests adapting `odb_transaction_env()` to include a "read-only" mode flag. This would leave the primary object directory untouched and append the quarantine directory as an alternate, which should resolve the performance issue without introducing heuristics. Since the connectivity check in `git-receive-pack` doesn’t write objects, this approach would be sufficient and cleaner than the current patch.

The discussion remains collaborative, and the v2 patch is still in `next`. Justin’s proposal gives the maintainers a clear, low-risk path forward if they prefer to avoid the current patch’s heuristics. No objections have been raised to either approach, so the decision now hinges on whether the project wants a quick fix or to invest in the longer-term ODB transaction redesign.
