This is the fourth patch in the v7 series adding path-related keys to `git repo info`, and this email captures the final design agreement on how to handle `/dev/null` for the new `path.hooks.absolute` and `path.hooks.relative` keys. The discussion between K Jayatheerth and Justin Tobler resolves the last open design question for this patch: when `core.hooksPath` is set to `/dev/null`, both keys will now return `/dev/null` verbatim, rather than formatting the relative path. This change makes it easier for scripts to detect disabled hooks and eliminates platform-specific edge cases (like Windows path resolution) that previously required manual test skipping.

The implementation will special-case `/dev/null` in the C code, diverging slightly from `git rev-parse --git-path hooks` behavior but aligning with the series' goal of usability. Both authors agree this divergence is acceptable and won't complicate the planned follow-up refactoring to share logic between `git repo info` and `git rev-parse`. The patch is now mechanically complete and uncontested, with only the implementation of this special case remaining before it's ready for final review.

This resolution also simplifies the test helper by removing the need for platform-specific logic, and the updated tests will cover the `/dev/null` edge case without skipping it on Windows. The agreement here removes the last substantive obstacle for patch 4/8, leaving only the broader `path.grafts` design question and the architectural duplication concern as open issues for the series as a whole.
