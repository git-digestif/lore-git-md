This is the second patch in a two-patch bugfix series that has already been marked "Will queue" by Junio. The series fixes a subtle correctness issue in submodule diff headers: commit abbreviations were being checked against the superproject's object database rather than the submodule's, creating a risk of collisions where the same abbreviated ID could refer to different objects in the two repositories.

This patch makes the existing test hash-agnostic by adding SHA-256 coverage. It replaces hardcoded SHA-1 abbreviations with values provided via `test_oid_cache`, a standard Git testing mechanism that supplies the correct expected value for each hash algorithm. The test now runs for both SHA-1 and SHA-256, removing the previous `SHA1` prerequisite. The core test logic remains unchanged—it still verifies that submodule commit abbreviations use the submodule's object database for uniqueness checks.

Junio’s reply is procedural rather than technical. He questions the split between the two patches, noting that the SHA-256 support could have been included in the first patch rather than added as an afterthought. However, he acknowledges that the change is clean and well-executed, thanks to Git’s existing `test_oid*` infrastructure. His comment does not block integration; the series is still on track for queuing.

The patch itself is small and focused, touching only the test file. It adds a `test_oid_cache` block to define the expected abbreviated commit ID for each hash algorithm and updates the `printf` statement to use the hash-agnostic value. This is a direct response to Junio’s earlier feedback on v3, where he suggested making the test hash-agnostic but did not require it for merging.

The series as a whole is a well-motivated bugfix with thorough test coverage. The first patch (unchanged from v3) introduced `strbuf_repo_add_unique_abbrev()` and refactored the code to use `o->repo` as the fallback repository, reducing reliance on the global `the_repository`. This second patch completes the work by ensuring the test suite is robust across hash algorithms. The fix is part of the broader Git libification effort, though it stands alone and does not depend on other in-flight work.
