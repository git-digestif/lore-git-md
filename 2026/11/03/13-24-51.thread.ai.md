Subject: Critical regression in promisor remote lazy-fetch (Git 2.54.0)
Series version: N/A (bug report)
Originating author: Patrick Ohly
Thread type: bug report

Core problem or goal
A critical regression in Git 2.54.0 breaks the promisor remote lazy-fetch mechanism in partial clones. When `git merge` attempts to lazily fetch missing objects, the server rejects the request with "not our ref", causing the merge to fail. The issue was introduced by commit `5946a564` ("odb/source: make `read_object_info()` pluggable") as part of the ODB abstraction effort. The regression blocks CI workflows for projects like Kubernetes that rely on blobless partial clones.

Current status
Under review. The regression is confirmed to affect Git 2.54.0 and `master`, with Git 2.52.0 and earlier unaffected. A minimal reproduction case is provided, and the bisect points to the ODB abstraction work. The Kubernetes project has already reverted to Git 2.52.0 as a workaround. No root cause analysis or proposed fix is yet available.

Key technical details
- **Affected commit**: `5946a564` ("odb/source: make `read_object_info()` pluggable")
- **Subsystems touched**: ODB abstraction layer, promisor remote lazy-fetch mechanism
- **Impacted workflow**: `git merge` in blobless partial clones
- **Error message**: "not our ref" during lazy fetch
- **Reproduction**: Blobless partial clone of Kubernetes repository followed by a merge of a second commit
- **Regression boundary**: Git 2.52.0 (works) → Git 2.54.0 (fails)
- **Test coverage**: None yet; reproduction case provided in the report

Open questions and loose ends
- Root cause of the regression: how the pluggable ODB layer alters lazy-fetch triggering, specifically the interaction between `read_object_info()`, the `OBJECT_INFO_SECOND_READ` flag, and reprepare paths.
- Whether the issue affects other operations beyond `git merge` (e.g., `git checkout`, `git rebase`).
- Potential fix strategies: reverting `5946a564`, patching the ODB abstraction layer, or adjusting the lazy-fetch logic to accommodate the new ODB behavior.
- Timeline for a fix: urgency is high due to the severity of the regression and its impact on CI workflows.
