Subject: Critical regression in promisor remote lazy-fetch (Git 2.54.0)
Series version: N/A (bug report, now with proposed fix series `20261104-pks-odb-loose-stale-cache-v1`)
Originating author: Patrick Ohly
Thread type: bug report and fix proposal

Core problem or goal
A critical regression in Git 2.54.0 breaks the promisor remote lazy-fetch mechanism in partial clones, causing `git merge` (and potentially other operations) to fail with "not our ref" errors during lazy fetches. The regression was introduced by the ODB abstraction effort, specifically commit `5946a564` ("odb/source: make `read_object_info()` pluggable"), which exposed a pre-existing stale loose object cache invariant violation. The issue blocks CI workflows for projects like Kubernetes that rely on blobless partial clones. The regression's delayed manifestation—appearing only after days of successful operation—is now explained: it triggers only when merging an object whose first two hex characters match those of a newly written object in the same subdirectory, a rare condition dependent on object ID layout.

Current status
Fix proposed. The regression is confirmed to affect Git 2.54.0 and `master`, with Git 2.52.0 and earlier unaffected. The root cause is a stale loose object cache's oidtree that fails to reflect newly written objects in subdirectories already listed by prefetch. The fix series (`20261104-pks-odb-loose-stale-cache-v1`) updates the oidtree after loose object writes in listed subdirectories, preserving cache consistency without full invalidation. Patrick Steinhardt endorses the approach as aligned with ODB design goals and has clarified the regression's trigger condition. The Kubernetes project remains on Git 2.52.0 as a workaround. Urgency is high due to CI blockage, and rapid integration is expected.

Key technical details
- **Affected commit**: `5946a564` ("odb/source: make `read_object_info()` pluggable") exposed the issue, but the root cause predates it (stale cache invariant violation).
- **Subsystems touched**: ODB abstraction layer, promisor remote lazy-fetch mechanism, loose object cache (oidtree).
- **Impacted workflow**: `git merge`, `git checkout`, `git rebase` in blobless partial clones; any operation writing loose objects after listing their subdirectory.
- **Error message**: "not our ref" during lazy fetch.
- **Root cause**: Loose object cache's oidtree does not reflect newly written objects in subdirectories already listed by prefetch, causing incorrect "missing object" conclusions and spurious lazy fetches.
- **Trigger condition**: The regression manifests only when merging an object whose first two hex characters match those of a newly written object in the same subdirectory (e.g., `ab/cdef...` and `ab/1234...`).
- **Fix mechanism**: Update oidtree after loose object writes in listed subdirectories (patch series `20261104-pks-odb-loose-stale-cache-v1`).
- **Regression boundary**: Git 2.52.0 (works) → Git 2.54.0 (fails).
- **Masking factor**: Prior to `5946a564`, `odb_reprepare()` discarded the entire loose cache, masking the stale invariant; ODB abstraction preserves the cache across reprepares.
- **Test coverage**: Unit test for loose source exists locally; end-to-end test deemed cumbersome due to need for merged blob with specific first-byte collision.

Open questions and loose ends
