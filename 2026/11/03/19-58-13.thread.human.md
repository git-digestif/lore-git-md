This thread began as a bug report by Kevin Lyles about an unexpected interaction between the pre-commit hook and `git commit <pathspec>`: when a pathspec is provided, index changes made by the hook are silently discarded, while they are preserved without a pathspec or with additional staged files. The discussion has now taken a decisive turn with Junio C Hamano’s response, which reframes the issue as a policy question rather than a technical bug.

Junio agrees with Kristoffer Haugsbakk that the pre-commit hook is intended for validation, not index mutation, and proposes two follow-up actions: clarifying the documentation to explicitly discourage such use, and potentially detecting and rejecting index mutations in the code. While enforcing this restriction may not be technically straightforward, the maintainer’s stance is clear—the observed inconsistency in pathspec behavior is now a non-issue because the underlying use case (a hook modifying the index) is unsupported. The thread has shifted from diagnosing a behavioral quirk to establishing a project-wide expectation: pre-commit hooks should not mutate the index, and any reliance on such behavior is discouraged.

No code changes have been proposed yet, but the next steps are likely to focus on documentation updates and possibly enforcement mechanisms. The original reproducer and technical details remain relevant only insofar as they illustrate why index mutation in hooks is problematic, not as a bug to be fixed. The discussion is now settled in principle, pending implementation.
