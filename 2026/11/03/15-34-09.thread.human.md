This thread is an RFC proposing a `--switch` (`-s`) option for `git branch` that would create and switch to a new branch in one step, mirroring the existing `git switch -c <branch>` behavior. The idea, suggested by Johannes Welsch, aims to reduce cognitive friction for users who think of the operation as "create a branch" rather than "switch to a new branch."

So far, the discussion has focused on whether the redundancy with `git switch -c` is justified. Pushkar Singh raised concerns that the feature might blur the intentional separation between `git branch` (creation) and `git switch` (navigation), arguing that the current documentation already points users to `git switch -c` for this use case. His feedback is surface-level, questioning the user-experience value without engaging deeply with the author’s rationale or proposing alternatives. No code has been posted, and the thread remains at the conceptual stage, with open questions about whether the new option would add confusion, whether `-s` should be reserved for other purposes (like `--set-upstream`), and how existing scripts parsing `git branch` output might be affected. The discussion is still early, and no consensus has emerged.
