This thread is an RFC from Johannes Welsch proposing a `--switch` (`-s`) option for `git branch` that would create and switch to a new branch in one step, mirroring the existing `git switch -c <branch>` behavior. The goal is to reduce cognitive friction for users who think of the operation as "create a branch" rather than "switch to a new branch."

So far, the proposal has met with skepticism. Pushkar Singh questioned the necessity of the feature, arguing that `git switch -c` already provides the same functionality and that the current separation between `git branch` and `git switch` is intentional. Junio C Hamano, the maintainer, echoed this concern more bluntly, pointing out that `git checkout -b` (and its modern equivalent, `git switch -c`) already accomplishes the same thing. His response frames the discussion around redundancy: if there’s already a way to do this, why add another? Neither reviewer engaged with the user-experience rationale behind the proposal, leaving the author to either defend the need for the feature or reconsider it. No code has been posted, and the thread remains open.
