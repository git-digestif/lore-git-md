This is a **critical bug report** affecting partial clones (blobless filters) when merging. The issue surfaced in Git 2.54.0 and persists through 2.56.0 and current `master`, breaking Kubernetes CI workflows that rely on lazy fetching.

The regression was introduced by commit `5946a564` ("odb/source: make `read_object_info()` pluggable"), which refactored object database access. The failure mode is a "not our ref" error from the promisor remote when Git attempts to lazily fetch missing objects during a merge. The reporter bisected the issue cleanly and confirmed it does not occur in versions prior to 2.54.0. While they speculate the new `OBJECT_INFO_SECOND_READ` flag or reprepare logic might be involved, no root cause analysis is provided yet.

The impact is severe: Kubernetes PR merges are completely blocked until the project reverts to Git 2.52.0. The reporter notes the failure is deterministic and reproducible with their provided steps (using the Kubernetes repo itself). No workaround is mentioned beyond downgrading.

This looks like a genuine, well-documented regression with production consequences. The commit in question is part of Patrick Steinhardt’s ODB abstraction work, so expect follow-up from that effort’s contributors. Given the urgency, this is likely to see rapid attention.
