This thread reports a bug in `git diff --word-diff` where the command produces incorrect output when comparing files that differ by both textual changes and whitespace additions (such as blank lines). Jean Abou Samra originally reported the issue with a clear reproduction case, demonstrating that the bug causes words to be matched out of context and large unchanged sections to be omitted.

Phillip Wood has since confirmed the bug and identified its root cause: the word-diff logic currently splits hunks at context lines (unchanged lines) before computing word-level differences. When a blank line is introduced, it is treated as context, which disrupts the diff’s ability to correctly align words. Phillip suggests a fix—feeding entire hunks from the line-level diff into the word-diff logic rather than splitting them at context lines—and notes that a local patch modifying the patience algorithm produces better results for the reported case. However, no formal patch has been proposed yet.

The discussion remains in the diagnostic phase, with the root cause now understood but no concrete solution submitted. The issue appears isolated to the word-diff implementation and does not affect other diff modes or subsystems. No other participants have weighed in, and the thread is still focused on understanding and resolving the bug.
