The critical regression in Git 2.54.0 that breaks promisor remote lazy-fetch in partial clones has taken a major step forward with a detailed root-cause analysis from Kristofer Karlsson. The issue, introduced by the ODB abstraction work in commit `5946a564`, causes `git merge` to fail with "not our ref" when attempting to lazily fetch objects in blobless partial clones—a workflow critical to projects like Kubernetes, which have already reverted to Git 2.52.0 as a workaround.

Kristofer’s analysis reveals that the regression stems from a stale loose object cache invariant violation, exposed by the ODB abstraction’s preservation of the cache across reprepares. When a merge writes a new loose object (e.g., a merged blob) into a subdirectory already listed by an earlier prefetch, the cache’s `oidtree` fails to reflect the new object, triggering an unnecessary lazy fetch for an object that exists only locally. The server rejects the request, causing the merge to fail. The fix he proposes—updating the `oidtree` after a successful loose object write—is targeted and maintains the cache’s intended behavior without requiring a full flush.

The urgency remains high, as the regression continues to block CI workflows, but the path to resolution is now clear. The next steps will likely involve Patrick Steinhardt and Justin Tobler, who may weigh in on whether the fix aligns with the ODB abstraction’s design goals. While the analysis confirms the issue affects `git merge`, it also suggests a broader risk for any operation that writes loose objects after listing their subdirectory, though no other commands have been reported as broken yet. A unit test for the loose source is ready, but an end-to-end test may be challenging to implement due to the specific conditions required to reproduce the bug.
