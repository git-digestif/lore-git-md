This thread tracks a critical regression in Git 2.54.0 that breaks promisor remote lazy-fetch in partial clones, blocking CI workflows for projects like Kubernetes. The issue was introduced by commit `5946a564` as part of the ODB abstraction effort and causes `git merge` to fail with "not our ref" errors during lazy fetches. The root cause is now understood: a stale loose object cache invariant violation, where the cache's oidtree doesn't reflect newly written objects in subdirectories already listed by prefetch.

The urgency remains high, but a new mystery has emerged. Patrick Ohly reports that the regression only surfaced after days of uneventful Git 2.54.0 usage in Kubernetes CI, despite the bug being present from the start. This suggests the trigger may be rare or environment-specific—perhaps tied to a particular object layout, merge conflict pattern, or server-side change. The proposed fix (updating oidtree after loose object writes) is still awaiting input from Patrick Steinhardt, who leads the ODB abstraction work. Meanwhile, Kubernetes continues to use Git 2.52.0 as a workaround. The thread is still under active review, with no resolution yet.
