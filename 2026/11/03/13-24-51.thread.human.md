This thread is about a critical regression in Git 2.54.0 that breaks promisor remote lazy-fetch in partial clones, causing operations like `git merge` to fail with "not our ref" errors. The issue was introduced by the ODB abstraction effort and affects projects like Kubernetes, which have reverted to Git 2.52.0 as a workaround.

The root cause is a stale loose object cache that fails to reflect newly written objects in subdirectories already listed by prefetch. A fix series (`20261104-pks-odb-loose-stale-cache-v1`) has been proposed and endorsed by Patrick Steinhardt, who confirmed the issue and traced it to a pre-existing invariant violation exposed by the ODB changes. The fix updates the cache's oidtree after loose object writes, preserving consistency without full invalidation.

The mystery of why the regression only appeared after days of successful CI operation has now been explained: it triggers only when merging an object whose first two hex characters collide with a newly written object in the same subdirectory. This rare condition depends on object ID layout, making the bug intermittent but no less critical. The fix remains unchanged, and urgency is high due to the CI blockage. No objections to the fix have been raised, and rapid integration is expected.
