This thread is a critical bug report about a regression in Git 2.54.0 that breaks `git merge` in blobless partial clones, a workflow relied on by projects like Kubernetes. The issue was introduced by commit `5946a564` as part of the ODB abstraction work, specifically changes to `read_object_info()` and its handling of the `OBJECT_INFO_SECOND_READ` flag. The failure is deterministic and blocks CI pipelines, with Kubernetes already reverting to Git 2.52.0 as a workaround.

Patrick Ohly’s report provides a clear reproduction case and bisect results, pinning the regression on the ODB refactoring. The problem appears to stem from how the new pluggable ODB layer interacts with lazy fetches, causing the client to request objects the server rejects as "not our ref." The thread is likely to draw urgent attention from Patrick Steinhardt and Justin Tobler, who authored the ODB changes, though no root-cause analysis or proposed fix has been shared yet. The severity of the issue—blocking production CI—means this will be a high-priority discussion.
