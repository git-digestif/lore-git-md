This is a follow-up to the `git log --graph` orphaned branch rendering bug, now with a minimal reproduction case.

The author provides a self-contained script that creates a repository with three branches: `main` (commit B), `topic` (commit T), and an orphaned branch `orphan` (commit R). When `git merge --allow-unrelated-histories` merges `main` into `orphan` (commit M), the resulting graph drawn by `git log --graph --all --oneline` incorrectly shows commit R (the orphaned branch head) with a spurious parent connection, causing the rightmost lane to extend into empty space. The issue manifests regardless of `--graph-indent` setting, confirming it is not a cosmetic indentation quirk but a fundamental miscalculation in the graph layout algorithm.

The reproduction script is concise and platform-agnostic, making it easy for other contributors to verify the issue on non-Windows systems and different Git versions. The author explicitly tested with Git 2.56.0.windows.3, but the script should work on any recent Git. The key technical detail is that the bug surfaces only when `--all` is used, suggesting the graph logic fails to handle the combination of orphaned commits and unrelated histories correctly.

This follow-up advances the thread by eliminating the dependency on the external `packagecontrol/thecrawl.git` repository and providing a clear, minimal test case. The root cause remains unidentified, but the reproduction script narrows the debugging scope to the graph-drawing logic in `graph.c`, specifically how it processes commits with no parents when unrelated histories are merged. The next likely steps are for a contributor to run the script, confirm the rendering error, and begin tracing the graph layout code to identify where the spurious parent connection is introduced.
