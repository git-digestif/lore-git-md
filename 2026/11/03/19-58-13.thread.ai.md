Subject: Unexpected interaction between pre-commit hook and `git commit <pathspec>`
Series version: none (standalone bug report)
Originating author: Kevin Lyles <klyles@epic.com>
Thread type: bug report / policy discussion

Core problem or goal
The thread investigates an inconsistency in `git commit <pathspec>` behavior when the pre-commit hook modifies the index: hook-induced changes are silently discarded if a pathspec is provided, but preserved otherwise. The discussion has expanded to question whether pre-commit hooks should mutate the index at all, regardless of pathspec handling.

Current status
Under review, with maintainer direction established. Junio C Hamano has reframed the issue as a policy matter: pre-commit hooks are for validation only, and index mutation is unsupported. Two follow-up actions are proposed: (1) clarify documentation to explicitly discourage mutation, and (2) explore code-level enforcement (e.g., rejecting index changes in hooks). The original pathspec inconsistency is now considered a non-issue because the underlying use case (hook modifying the index) is out of scope. No merge status or integration branch updates; the thread remains open for documentation or enforcement patches.

Open questions and loose ends
- **Documentation**: How should the `githooks` documentation be updated to reflect the project's stance against index mutation in pre-commit hooks? Should examples or warnings be added?
- **Enforcement feasibility**: Is it technically possible to detect and reject index mutations in pre-commit hooks without breaking legitimate use cases (e.g., hooks that stage untracked files via `git add`)?
- **Backward compatibility**: If enforcement is implemented, how will existing hooks that rely on index mutation be handled? Will there be a deprecation period or immediate rejection?
