This is the second patch in Patrick Steinhardt’s v2 bugfix series for `git grep --recurse-submodules`. It applies the same defensive pattern as patch 1/3 to sparse directory trees: when `grep_cache()` reads a tree object from a sparse directory entry, it now uses the repository instance (`repo->objects`) passed to it instead of the global `the_repository`. The change is a single-line replacement in `builtin/grep.c` (line 560).

The commit message explains why this is not currently triggerable—submodules always expand their sparse indices into full indices—but the fix is still necessary to prevent a future bug once submodules start handling sparse indices. No new test coverage is added here; the patch is purely precautionary. The series remains focused on eliminating implicit `the_repository` usage in `builtin/grep.c` and is explicitly intended for backporting to stable branches.
