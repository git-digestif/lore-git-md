This is the final patch in Ravi Mistry’s four-patch series improving Git’s HTTP transport resilience. Junio C Hamano’s review of this patch is brief and positive: he notes that the new `http_retry_wait()` helper is cleanly extracted from existing code in `http_request_recoverable()`, and the refactoring replaces a block of repetitive logic with a single function call. The change extends retry logic—previously limited to GET requests—to cover HTTP POST requests, which handle data transfer during fetch/clone and partial clone blob downloads.

The patch itself is straightforward: it moves the retry delay calculation and sleep logic into the new helper, then updates both `probe_rpc()` (GET) and `post_rpc()` (POST) to use it. The test suite expands to verify that POST requests now retry 429 and 502 errors, that partial-clone lazy blob fetches survive transient 502s, and that gzipped POST requests preserve the Content-Encoding header across retries. No on-disk format or public API changes are involved.

Junio’s feedback here is purely surface-level—he does not raise any technical concerns or open questions about this patch. The earlier patches in the series (1–3) received more substantive review, particularly around exponential backoff behavior and status code configuration, but those issues do not affect this final piece. The series as a whole is under active review, with the author yet to respond to Junio’s feedback on patches 2 and 3. This patch looks ready to proceed once the earlier ones are resolved.
