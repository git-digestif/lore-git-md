This is a v2 bugfix series targeting `git grep --recurse-submodules`. The core issue—a regression introduced in Git v2.56.0 (commit 93cd344e34f)—causes nested submodule trees to be read from `the_repository` instead of the submodule’s own repository, breaking the command. The series remains concise (three patches, 26 insertions, 3 deletions) and is explicitly intended for backporting to stable branches.

The technical approach is unchanged: the fix ensures `grep_tree()`, `grep_cache()`, and `grep_objects()` consistently use the repository parameter passed to them rather than defaulting to `the_repository`. The new test in `t/t7814-grep-recurse-submodules.sh` (added in patch 1/3) verifies the fix for nested submodule trees, while existing tests cover the `.gitmodules` code path. No new symbols or on-disk format changes are introduced.
