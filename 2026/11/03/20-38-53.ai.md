This is a maintainer response in the ongoing thread about the pre-commit hook's interaction with `git commit <pathspec>`. Junio C Hamano weighs in on the broader question of whether the pre-commit hook should be used for index mutation at all. He agrees with Kristoffer Haugsbakk that the hook's intended purpose is validation, not modification, and suggests two follow-up actions: clarifying the documentation to explicitly discourage mutation, and potentially detecting and rejecting such attempts in the code.

Junio acknowledges that enforcing this restriction (step 2) may not be technically feasible, but the proposal itself signals a clear project stance: index mutation in pre-commit hooks is unsupported and should not be relied upon. This effectively reframes the original bug report—Kevin Lyles' observed inconsistency between pathspec and non-pathspec commits may now be treated as a non-issue, since the underlying use case (a hook modifying the index) is itself out of scope.

The thread has shifted from a narrow technical question about pathspec behavior to a broader policy discussion about hook expectations. Future patches or documentation updates are likely to focus on the two proposed actions rather than fixing the pathspec inconsistency. No code changes are proposed in this email, but the maintainer's position sets the direction for how the project will handle this and similar cases going forward.
