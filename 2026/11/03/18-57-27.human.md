This is the fourth and final patch in a v2 series improving Git’s HTTP transport resilience. It extends retry logic to cover HTTP POST requests, which carry the actual data during fetch, clone, and partial-clone blob downloads. The patch extracts the retry-wait logic into a shared helper (`http_retry_wait()`), defers error reporting until retries are exhausted, and ensures the “Content-Encoding: gzip” header is re-attached on retry. Test coverage verifies that POST requests now survive 429 (rate-limiting) and 502 (bad gateway) errors, that partial-clone blob fetches can tolerate transient 502s, and that gzipped POST bodies preserve their encoding across retries. The changes are narrowly scoped to the retry machinery and do not alter the default set of retryable status codes. This looks like a well-tested, uncontroversial fix for a real gap in Git’s HTTP error handling.
