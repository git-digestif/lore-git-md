This is a bugfix series targeting `git grep --recurse-submodules`. The v2 update incorporates feedback from the v1 review: the commit message now explicitly states that the regression was introduced in Git v2.56.0, making it clear which stable branches need the fix. The series remains focused on the same three patches—fixing the immediate bug in submodule tree reading, then defensively applying the same pattern to sparse directory trees and `.gitmodules` file reading.

The changes are minimal (6 insertions, 3 deletions) and confined to `builtin/grep.c` and the test script. The new test in `t/t7814-grep-recurse-submodules.sh` verifies that nested submodule trees are now read correctly, which is a strong signal that the fix is well-tested. The defensive follow-ups in patches 2/3 and 3/3 are precautionary rather than addressing known bugs, but they align with the ongoing effort to eliminate implicit reliance on `the_repository`.

Patrick notes that fully removing `the_repository` from `cmd_grep()` would require handling the `--no-index` case, which is out of scope for this series. The patch is based on Git v2.56.0, indicating it’s intended for backporting. This looks like a solid, well-contained fix for a real regression, with clear motivation and thorough test coverage.
