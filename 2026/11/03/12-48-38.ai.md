This is the second patch in a two-patch refactoring series (v3) that moves the `pack.packsizelimit` configuration value from a global variable into the repository-scoped `repo_config_values` struct. The change is part of the ongoing `the_repository` removal effort to reduce global state and improve Git’s modularity.

The patch updates four files: `builtin/pack-objects.c`, `environment.c`, `environment.h`, and `object-file.c`. The global variable `pack_size_limit_cfg` is removed, and its value is now stored in `repo_config_values.pack_size_limit`. The configuration parser (`git_default_config`) and pack-writing code are updated to read the value from the repository’s configuration struct instead of the global variable. The change is purely mechanical and does not alter behavior, but it ensures the pack size limit is repository-specific rather than process-global.
