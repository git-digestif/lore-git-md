This is the fourth patch in the v7 series adding path-related keys to `git repo info`, now focusing on the `/dev/null` edge case for the `path.hooks.absolute` and `path.hooks.relative` keys. The email captures a design agreement between K Jayatheerth and Justin Tobler: when `core.hooksPath` is set to `/dev/null`, both keys should return `/dev/null` verbatim, even for the relative variant. This departs from the current `git rev-parse --git-path hooks` behavior (which returns a relative path like `../../../../dev/null`) but improves usability by making it easier for scripts to detect when hooks are disabled.

The discussion also clarifies that this divergence from `git rev-parse` will not block the planned follow-up series to extract shared path logic into a helper library. Justin suggests either avoiding a shared helper for this case or special-casing the behavior, leaving the door open for future refactoring. The patch is now uncontested on this point and ready for final review, with the only remaining work being a mechanical update to the test helper to simplify `/dev/null` handling and resolve Windows compatibility. This change aligns with the series’ broader goal of exposing repository component paths in a user-friendly way, even if it means slightly bending consistency with existing commands.
