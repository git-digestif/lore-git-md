This is a **substantive review** of the second patch in Harald Nordgren’s v3 series introducing the `%gb` format placeholder for `git log -g` and `git reflog`. Phillip Wood identifies a **regression in edge-case handling** when `GIT_REFLOG_ACTION` is set, causing the `%gb` placeholder to mislabel branch names during rebase operations.

The review demonstrates the bug with a concrete example: when `GIT_REFLOG_ACTION` is set (e.g., during `git rebase`), the `%gb` output incorrectly labels reflog entries with the value of `GIT_REFLOG_ACTION` (e.g., `sequencer-delete-REBASE_HEAD`) instead of the actual branch name. Phillip’s test output shows three specific mislabeled entries, including one where a rebase step should show `detached at <commit>` but instead shows the `GIT_REFLOG_ACTION` value. The bug stems from the `mark_branches()` function’s reliance on reflog message parsing, which fails to account for the synthetic messages generated when `GIT_REFLOG_ACTION` is active.

The patch otherwise looks well-crafted—Phillip’s earlier "Looks good" applies to the general design, and the test coverage is thorough—but this edge case undermines the feature’s correctness. The regression is likely to affect users who rely on `GIT_REFLOG_ACTION` for scripting or tooling, making it a blocker for merging. Harald will need to revise the branch-parsing logic to handle these synthetic messages before the series can proceed.
