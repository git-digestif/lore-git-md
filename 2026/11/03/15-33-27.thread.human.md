Julia Evans’s patch to rewrite the EXAMPLES section of `git-diff(1)` has hit a critical review from Junio C Hamano, shifting the thread from a straightforward documentation refresh to a design discussion about how examples should be presented and which command forms the project wants to promote. The patch reorganizes the examples into five subsections, replaces the confusing `...` syntax with `--merge-base`, and moves from a table format to AsciiDoc horizontal definition lists to avoid line-wrapping on 80-character terminals.

Junio’s review raises three substantive concerns. First, he objects to the table format itself because the line-wrapping makes the examples impossible to cut-and-paste, a concrete technical issue that overrides any stylistic preference. Second, he calls the replacement of `--cached` with `--staged` in one example a “severe regression,” noting that `--staged` is only documented as a synonym for `--cached` in the man page and not mentioned in the SYNOPSIS; if the project wants to promote `--staged`, it must be done consistently across the entire document. Third, he questions the omission of `git diff AUTO_MERGE`, which was present in the original EXAMPLES section, and asks for an explanation. The patch is now blocked until these points are addressed. No other reviews have appeared yet, so the thread’s next move rests with Julia.
