This is a bugfix patch, the first in a two-patch follow-up series to the recently merged `jt/odb-keep-lockfile-fix` topic. It targets the object-file subsystem, specifically the error paths in `object-file.c` where temporary packfiles and `.keep` lockfiles are cleaned up.

The patch addresses a silent failure mode: when an ODB transaction aborts, the code currently calls `unlink()` to remove temporary files, but if that unlink fails (e.g., due to permissions or filesystem issues), the error is ignored. This can leave behind `.keep` files that permanently block packfile housekeeping. The fix is mechanical: replace `unlink()` with `unlink_or_warn()` in three locations, ensuring failures are reported to the user.

The change is narrow and well-scoped: only `object-file.c` is touched, the new behavior is limited to warning on unlink failure, and there are no on-disk format changes or new symbols introduced. The commit message clearly states the problem (silent unlink failure) and the solution (warn instead), though it does not elaborate on the real-world impact beyond the `.keep` file issue.

This patch is already cooking in `next` as part of the follow-up series, meaning it is undergoing integration testing but is not yet final. It directly responds to post-merge review feedback on the earlier ODB lockfile fix, and its companion patch (2/2) addresses a related error-propagation issue in the same subsystem. No test coverage is added, which is consistent with the follow-up nature of the series.
