This email is part of the ongoing `[PATCH v7]` series adding path-related keys to `git repo info`, specifically patch 4/8 which introduces `path.hooks.absolute` and `path.hooks.relative`. The discussion here finalizes a design agreement to special-case `/dev/null` handling for both keys when `core.hooksPath` is set to that value, resolving a usability concern raised by Justin Tobler.

The key outcome is that both `path.hooks.absolute` and `path.hooks.relative` will now return `/dev/null` verbatim when hooks are disabled via `core.hooksPath=/dev/null`. This diverges from `git rev-parse --git-path hooks` behavior (where the relative key returns a relative path like `../../../../dev/null`) but improves scriptability by making it easier to detect disabled hooks. The change is uncontested and will simplify the test helper by removing platform-specific edge cases (e.g., Windows path resolution). K Jayatheerth plans to implement this by special-casing `/dev/null` in the C code, avoiding complications for the proposed follow-up refactoring series that would share logic between `git repo info` and `git rev-parse`.

This adjustment aligns with the series' goal of usability while maintaining consistency with Git's existing path-handling patterns. The patch is otherwise mechanically clean, with thorough test coverage for standard hooks paths, custom overrides, and the `/dev/null` edge case. The open design question about `/dev/null` handling is now resolved in principle, pending implementation. No other substantive feedback remains for this patch.
