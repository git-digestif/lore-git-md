This is Junio’s reply to Matt Hunter’s surface-level question about whether the existing three-rev form of `git range-diff` already solves the `--matched-only` use case.

Junio clarifies that the three-rev form (`git range-diff <base> <rev1> <rev2>`) compares `<base>..<rev1>` against `<base>..<rev2>`, which requires a single shared base. Harald’s workflow, however, involves rebasing a topic branch onto a new base (e.g., updated `origin/master`), so there is no single `<base>` that applies to both the old and new versions of the branch. The three-rev form cannot express this scenario, making `--matched-only` necessary to filter out commits that appear in only one of the two ranges. The reply effectively closes the redundancy question by explaining why the proposed alternative does not work for the intended use case.
