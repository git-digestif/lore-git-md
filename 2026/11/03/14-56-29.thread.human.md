This thread reports a regression in `git push` where the `--force-with-lease` option is silently ignored when pushing to a *remote group* (defined via `remotes.<group>`) unless an explicit `<refname>` is provided. Patrick Peroša, the reporter, has provided a minimal reproduction recipe showing that `git push --force-with-lease --dry-run <group> <branch>` fails to reject non-fast-forward pushes, while the same command with `--force-with-lease=<branch>` or `--force` works as expected. The issue affects both Windows and Linux builds across multiple integration branches (`master`, `next`), and stems from the bare `--force-with-lease` flag being dropped during the internal decomposition of a group push into individual remote pushes.

The regression was confirmed via `GIT_TRACE` output, which shows the flag is not forwarded to the child `git push` processes spawned for each remote in the group. The problem does not occur with `--force` or when an explicit ref is provided to `--force-with-lease`. No responses or proposed fixes have been posted yet, so the thread is currently just the initial report with reproduction steps. If you use remote groups and rely on `--force-with-lease`, this is a critical edge case to be aware of.
