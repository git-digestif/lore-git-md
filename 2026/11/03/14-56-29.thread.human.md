This thread is about a bug in `git push --force-with-lease` that causes the flag to be silently ignored when pushing to a remote group (defined via `remotes.<group>`) unless an explicit `<refname>` is provided. The issue was reported by Patrick Peroša, who confirmed it affects both Windows and Linux across multiple Git branches, including `master` and `next`.

Tyler Cipriani has submitted a fix in a separate thread (not as a reply here) targeting the argument forwarding logic in `git push`. The bug occurs because the bare `--force-with-lease` flag is dropped during the decomposition of group pushes into individual remote pushes, while `--force-with-lease=<refname>` and `--force` are forwarded correctly. The fix is expected to be small and focused, addressing this inconsistency. No review feedback has been posted yet, but the patch should be straightforward to evaluate given the clear reproduction steps in the original report.

The thread is still under review, with no decisions made about merging or further testing. The key open question remains whether this is a regression or long-standing behavior, and whether fixing it could break existing workflows. A regression test will likely be needed to prevent future regressions.
