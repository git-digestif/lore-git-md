Thread identity
Subject: [RFC] git branch --switch: create and switch in one step
Series version: RFC (no patch version)
Originating author: Johannes Welsch
Thread type: feature proposal (user-experience)

Core problem or goal
Add a `-s`/`--switch` option to `git branch` that creates a new branch and switches to it in a single command, duplicating the existing `git switch -c <branch>` (and `git checkout -b <branch>`) behavior. The goal is to reduce cognitive friction for users who think of the operation as “create a branch” rather than “switch to a new branch.”

Current status
No code posted; pure RFC soliciting feedback on the idea. No prior discussion recorded. Maintainer Junio C Hamano has raised a conceptual objection, questioning the necessity of the feature given that `git checkout -b` and `git switch -c` already provide the same functionality. The thread remains open, awaiting the author’s response.

Key technical details
- Command: `git branch -s <branch>`
- Behavior: identical to `git switch -c <branch>` and `git checkout -b <branch>`—fails if the branch already exists, otherwise creates and switches.
- Files touched: none yet; eventual implementation would modify `builtin/branch.c` and update the `git-branch` man page.
- New CLI option: `-s`/`--switch`
- No on-disk format or object changes.

Open questions and loose ends
- Is the redundancy with `git switch -c` and `git checkout -b` justified by user-experience gains?
- Would the new option add confusion rather than reduce it?
- Should the short form `-s` be reserved for something else (e.g., `--set-upstream`)?
- Are there backward-compatibility concerns with existing scripts that parse `git branch` output?
- Can the author demonstrate a clear gap in the current user experience that isn’t addressed by existing commands?

Participant positions
- Johannes Welsch (author): proposes the feature, arguing it aligns better with users who model the operation as branch creation first.
- Pushkar Singh: questions the necessity of the feature, noting that `git switch -c` already provides the same functionality and that the current separation between `git branch` and `git switch` is intentional. Argues the proposed change might muddy the distinction between the two commands and highlights that the `git branch` documentation already recommends `git switch -c` for this use case. Review is surface-level, focusing on conceptual clarity rather than technical implementation.
- Junio C Hamano (maintainer): raises a high-weight conceptual objection, framing the proposal as redundant given the existence of `git checkout -b`. The objection is purely about user-experience design and does not engage with the author’s stated rationale. The maintainer’s position suggests skepticism unless the author can justify why the existing commands are insufficient.

Related work
