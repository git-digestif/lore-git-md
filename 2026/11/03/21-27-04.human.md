This is a substantive review identifying the root cause of the `git log --graph` orphaned branch rendering bug.

Pablo Sabater pinpoints the issue in `graph.c`: the `GRAPH_PRE_ROOT` state is incorrectly triggered for commit R (the orphaned branch head), causing the graph logic to add a spurious row that connects R to a nonexistent parent. This miscalculation pushes all subsequent lanes to the right, creating the visual artifact where the rightmost lane extends into empty space. The bug surfaces regardless of `--graph-indent` setting, confirming it is not a cosmetic indentation issue but a fundamental flaw in how the graph layout algorithm handles root commits when unrelated histories are merged.

The review advances the thread significantly by moving from "here is a bug" to "here is exactly where and why it happens." Pablo’s analysis suggests the fix should ensure consistent rendering with or without indentation, since the orphaned commit’s lack of parents is unambiguous. While he does not yet provide a patch, his diagnosis narrows the scope to the `GRAPH_PRE_ROOT` state logic, making it straightforward for another contributor to implement the correction. The next likely step is a targeted patch to `graph.c` that prevents the spurious row insertion for orphaned commits.
