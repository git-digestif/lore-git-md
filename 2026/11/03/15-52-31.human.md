This is a bugfix patch for the bundle URI subsystem, addressing a crash in `git bundle-uri` when processing relative URIs with excessive `../` components. The v2 update responds directly to Patrick Steinhardt’s review of the initial version, making key improvements to the commit message, error reporting, and test coverage.

The patch now clearly explains that bundle lists can originate from untrusted sources (e.g., server advertisements or user-provided `--bundle-uri` arguments), justifying why the command should recover from malformed URIs rather than aborting. The error message has been enhanced to name the problematic URL while stripping credentials, making it more actionable for users. A new test in `t0060-path-utils.sh` verifies this credential-stripping behavior, while the existing bundle URI test (`t5750`) has been updated to expect graceful error handling instead of a crash.

The implementation remains clean: `relative_url_gently()` is introduced as a non-dying variant of `relative_url()`, preserving backward compatibility for existing callers like submodules. The bundle URI code path now uses the gentle variant, skipping invalid entries after logging an error. While Patrick had noted dropped test cases for certain relative URIs in v1, the v2 test suite still covers the core regression (excessive `../` traversal) and adds the new credential-stripping check.

This looks like a well-motivated fix that addresses both the technical issue (crash avoidance) and the usability concern (clearer error messages). The changes are narrowly scoped and unlikely to introduce regressions elsewhere. If the goal is to make `git bundle-uri` more resilient to malformed input, this patch delivers.
