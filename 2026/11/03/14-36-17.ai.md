This is a documentation refinement proposal targeting the glossary’s "pseudoref" entry in Andy Koppe’s v2 series. Julia Evans suggests replacing the current abstract description of `FETCH_HEAD`’s metadata with a concrete example that shows the actual file format (e.g., `d4c5f27105ee2e44366d718dbc5db95bbe99c714 not-for-merge branch 'example' of https://example.com/x/y`). Her proposed wording also explicitly lists the two pseudorefs (`FETCH_HEAD` and `MERGE_HEAD`), clarifies their storage location (`.git` directory), and reiterates their supported operations (`git show`, `git log`) and limitations (`git-update-ref`, `git-for-each-ref`). The change is purely editorial and does not alter the series’ technical scope, but it directly addresses a readability gap identified by a user who had to inspect `.git/FETCH_HEAD` manually to understand the current phrasing.

The proposal is well-motivated and aligns with the series’ goal of improving clarity. Julia’s example-driven approach would make the glossary more accessible to users who are not already familiar with Git’s internals, while preserving all the technical accuracy of the current definition. The suggested wording also tightens the contrast between pseudorefs and references by explicitly stating that references can only contain an object ID or symbolic ref name, a distinction that is currently implied but not spelled out. No objections or alternative suggestions have been raised in the thread so far, and Andy Koppe’s earlier responses indicate openness to incorporating user feedback on documentation clarity. If adopted, this change would likely be folded into Patch 1/5 of the series before merging.
