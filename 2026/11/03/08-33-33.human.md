This is a refactoring patch for the `git check-ref-format` built-in command, converting it from manual option parsing to Git’s standard `parse-options` API. The v2 revision addresses all the substantive issues Junio C Hamano raised in his review of v1: the confusing duplicate usage strings are consolidated into a single array, the deprecated `--print` option is now properly hidden (`PARSE_OPT_HIDDEN`), negated options (`--no-normalize`, `--no-refspec-pattern`) are explicitly rejected (`PARSE_OPT_NONEG`), and the early `show_usage_if_asked()` call is removed so that `-h` is handled by `parse_options()` as intended.

The patch remains small and self-contained, touching only `builtin/check-ref-format.c`. It preserves all existing behavior—normalization, branch-name support, and refname validation—while introducing two minor, documented differences: unambiguous long-option abbreviations (e.g., `--norm`) are now accepted, and `--` may precede the refname. The commit message is clear and thorough, explaining both the motivation and the changes.
