This is the fourth patch in the v7 series adding path-related keys to `git repo info`, specifically introducing `path.hooks.absolute` and `path.hooks.relative`. The email captures a design agreement between K Jayatheerth and Justin Tobler to special-case `/dev/null` handling for both keys when `core.hooksPath` is set to that value, improving usability for scripts that need to detect disabled hooks.

The current implementation follows `git rev-parse --git-path hooks` precedent, where `path.hooks.absolute` returns `/dev/null` verbatim but `path.hooks.relative` returns a relative path (e.g., `../../../../dev/null`). Justin argues this inconsistency makes it harder for scripts to detect disabled hooks, and K Jayatheerth agrees to special-case `/dev/null` in the C code so both keys return `/dev/null` verbatim. This change will also simplify the test helper by removing platform-specific edge cases (e.g., Windows path resolution) and eliminate the need for manual test skipping. The divergence from `git rev-parse` behavior is acknowledged but deemed acceptable, as the follow-up refactoring series can handle the special case without complicating shared helpers.

The patch is otherwise mechanically clean, with thorough test coverage for standard hooks paths, custom overrides, and the `/dev/null` edge case. The open design question is now resolved in principle, pending implementation. This adjustment aligns with the series' goal of usability while maintaining consistency with Git's existing path-handling patterns. The discussion also highlights the ongoing architectural concern about shared logic between `git repo info` and `git rev-parse`, though this specific change is unlikely to complicate that effort.
