This is a substantive review of the second patch in Farid Zakaria’s two-patch bugfix series for the credential-cache daemon race condition. The patch replaces `unix_stream_listen()` with `unix_ss_create()` to prevent a second daemon from hijacking the socket of an already-running daemon. Patrick Steinhardt’s feedback focuses on commit-message clarity and code comments rather than the core logic of the fix.

The review suggests two improvements to the commit message: rephrase the explanation to use imperative language (“Fix that by using…”) and explicitly justify why the daemon prints “ok” when it detects an existing socket. On the code side, Patrick finds the explanatory comment about concurrent daemon starts (“Two clients may each start a daemon…”) too vague and the cleanup comment (“Remove the socket at exit…”) redundant. The underlying technical approach—using `unix_ss_create()` to safely handle concurrent socket creation—is not questioned, and the test coverage (added in `t/t0301-credential-cache.sh`) is not mentioned in the review.

This feedback is surface-level in the sense that it targets wording and documentation rather than program behavior, but it is still substantive because it asks the author to clarify the rationale for a key design choice (the “ok” response). The review does not raise any new edge cases or technical objections, so the patch’s core correctness remains uncontested. Farid will likely address these points in v2 by tightening the commit message and either expanding or removing the comments.
