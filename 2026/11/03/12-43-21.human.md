This is the second patch in Patrick Steinhardt’s three-patch bugfix series for `git grep --recurse-submodules`. It applies the same defensive pattern as the first patch: when reading sparse directory trees from the index, the code now uses the repository instance (`repo->objects`) passed to `grep_cache()` instead of the global `the_repository`. The change is a single-line substitution in `builtin/grep.c`.

The commit message explains that the bug cannot currently be triggered because submodule indices are always expanded to full indices, but the fix preempts a future regression if sparse indices are ever enabled for submodules. This aligns with the series’ overall goal of eliminating implicit reliance on `the_repository` and future-proofing the code. No new tests are added here; the patch is purely a precautionary measure. The series remains focused and low-risk, with all patches targeting stable backporting.
