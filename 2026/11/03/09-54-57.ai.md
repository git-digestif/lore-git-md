This is a surface-level review of the ongoing bugfix patch that teaches `git rev-list --connectivity-check` to ignore replacement objects. Karthik Nayak points out a minor documentation inconsistency: the patch updates `Documentation/rev-list-options.adoc` to note that `--connectivity-check` ignores replacements, but the existing text in `Documentation/git-replace.adoc` still claims that *all* commands except reachability traversals (prune, pack transfer, fsck) use replacements by default. Since `rev-list --connectivity-check` is now explicitly one of those exceptions, the documentation in `git-replace.adoc` should be updated to include it.

The observation is purely editorial and does not engage with the core design question Junio raised—whether the connectivity check should ignore replacements or verify both original and replacement objects. The patch itself remains unchanged; this is a suggestion to improve cross-referencing between the two documentation files. No technical objections or alternative approaches are offered.
