Core problem or goal
Rewrite the EXAMPLES section of the `git diff` man page to modernize usage patterns, improve readability, and replace outdated syntax. The revised version organizes common `git diff` invocations into five subsections, replaces the `...` syntax with `--merge-base`, and adds cross-references to option definitions. The presentation format (AsciiDoc horizontal definition lists vs. tables) and AsciiDoc processor compatibility remain contested, but all mechanical inconsistencies in `--staged`/`--cached` usage have been resolved.

Current status
Under review. Second iteration (v2) posted, incorporating Junio’s squashable fix-up that resolves the last four mechanical oversights: (1) the `-h` help output now uses `(--cached|--staged)` syntax, (2) the synopsis line matches, (3) the explanatory text correctly states “`--staged` is a synonym of `--cached`”, and (4) the range-diff directionality is fixed. The patch passes the previously failing test (`t4500.218`). No maintainer decision on merge status; the thread remains stalled on three disputes: the presentation format (horizontal definition lists vs. tables), a build toolchain compatibility issue (the `[[name_only]]` anchor syntax works in Asciidoctor but fails in Python AsciiDoc, causing xmlto validation errors), and a broader policy question about whether to drop Python AsciiDoc support entirely. Jeff King now proposes `--name-only[[name_only]]::` as a temporary workaround for the anchor syntax issue, framing it as a build-time hassle for packagers rather than a user-facing breakage. Junio’s objection to horizontal definition lists (cut-and-paste issues) and the broader toolchain policy question remain unaddressed. The patch is technically ready for queuing once these disputes are settled.
