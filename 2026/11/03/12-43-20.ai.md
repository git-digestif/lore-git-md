This is the first patch in a v2 bugfix series for `git grep --recurse-submodules`. It fixes a regression introduced in Git v2.56.0 (commit 93cd344e34f) where nested submodule trees are incorrectly read from `the_repository` instead of the submodule’s own repository, causing the command to fail with "unable to read tree". The patch updates `grep_tree()` to use `repo->objects` (passed via `opt->repo`) instead of `the_repository->objects` when reading tree objects in submodules.

The change is minimal: a single-line modification in `builtin/grep.c` that replaces `the_repository->objects` with `repo->objects`. The patch also adds a new test in `t/t7814-grep-recurse-submodules.sh` that verifies the fix by grepping a nested directory structure inside a submodule. The test sets up a two-level repository hierarchy (a superproject with a submodule containing both top-level and nested files) and confirms that `git grep --recurse-submodules` correctly finds matches in both locations.

The commit message is thorough, explaining the regression’s origin, the broken code path, and why the issue went unnoticed (lack of test coverage for nested submodules). It also explicitly states that the regression shipped in Git v2.56.0, which is critical context for downstream maintainers considering backports. The patch is part of a three-patch series that also includes defensive follow-ups for sparse directory trees and `.gitmodules` file reading, though those are addressed in subsequent patches.

This patch is well-motivated, narrowly scoped, and directly addresses the reported bug. The test coverage is appropriate and fills a clear gap in the existing test suite. The series is intended for stable branches, and this patch is the linchpin of the fix. No unresolved concerns remain from the v1 review.
