This is a bugfix patch targeting the `graph.c` graph-drawing logic. It addresses the previously reported issue where `git log --graph --all --oneline` incorrectly renders an orphaned branch (e.g., commit R in the test case) with a spurious parent connection, causing the rightmost lane to extend into empty space.

The patch modifies `graph_is_visual_root()` in `graph.c` to avoid indenting a commit when there are columns to its right. The rationale is that such indentation is unnecessary—columns to the right collapse into the root's column once rendered, leaving no possibility for a commit to appear vertically adjacent to it. The fix also prevents a layout bug where columns to the right are incorrectly offset, causing misaligned collapsing lines. The change is minimal and surgical: it adds a single condition (`graph->commit_index + 1 >= graph->num_columns`) to the existing logic, ensuring orphaned commits with right-side columns are not treated as visual roots requiring indentation.

The patch includes a new test case in `t/t4218-log-graph-indentation.sh` that verifies the corrected behavior. The test creates a repository with an orphaned branch, a parallel branch, and a merge commit, then checks that the graph output matches the expected ASCII-art layout (orphaned commit R rendered as a standalone node without spurious indentation). The test is self-contained and uses the existing `lib_test_check_graph` helper.

The commit message is clear and well-structured, referencing the problematic commit (a34c00d96, "graph: indent visual root in graph", 2026-07-14) and explaining both the root cause (misalignment between `graph_output_pre_root_line()` and `graph_output_commit_line()`) and the solution.
