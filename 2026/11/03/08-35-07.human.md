This is a bugfix targeting the connectivity check in `git rev-list`. The author, Kristofer Karlsson, responds to Junio C Hamano’s conceptual question about whether the connectivity check should ignore replacement objects (the current patch) or verify *both* original *and* replacement objects (Junio’s alternative). Kristofer acknowledges the possibility of a gap but suggests that replacement objects—being regular refs—are already covered by ordinary connectivity checks during fetch or push. The discussion remains open, but the patch itself is small, well-motivated, and aligns with established behavior in other commands like `fsck` and `prune`.

The patch touches `builtin/rev-list.c`, `tree-verify.c`, and updates test `t5413` to reject packs where replacements mask missing objects. No code changes are proposed in this reply; the focus is on design intent. The implementation is straightforward and matches the pattern used by other commands since 2009. Junio’s earlier endorsement ("absolutely the right thing to do") still stands, but the thread now has two clear positions: consistency with existing commands (Kristofer) versus treating replacements as additional connectivity tips (Junio). The outcome may influence future iterations, but the current patch is uncontroversial and ready for review.
