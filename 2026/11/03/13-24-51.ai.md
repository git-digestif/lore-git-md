This is a **critical bug report** targeting the promisor remote lazy-fetch mechanism in partial clones. The regression was introduced in commit `5946a564` ("odb/source: make `read_object_info()` pluggable") and first appears in Git 2.54.0. The issue causes `git merge` to fail with "not our ref" when attempting to lazily fetch missing objects, breaking CI workflows for projects like Kubernetes that rely on blobless partial clones.

The report provides a minimal reproduction case: a blobless partial clone of the Kubernetes repository followed by a merge of a second commit. The failure is deterministic and does not occur in Git 2.52.0 or earlier. The bisect points squarely at the ODB abstraction work, specifically the changes to `read_object_info()` and its interaction with the `OBJECT_INFO_SECOND_READ` flag and reprepare paths. The author hypothesizes that the new pluggable ODB layer alters how lazy fetches are triggered, causing the client to request objects the server rejects as "not our ref."

The impact is severe: Kubernetes CI is completely blocked, and the workaround (reverting to Git 2.52.0) is already in place. The report includes a clear version matrix showing the regression boundary and confirms the issue persists on `master`. No analysis of the root cause is provided, but the commit message and context strongly suggest the ODB abstraction effort is the culprit. The thread is likely to attract immediate attention from Patrick Steinhardt and Justin Tobler, given their involvement in the ODB refactoring.
