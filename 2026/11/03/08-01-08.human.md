This is a review exchange on the first patch of Farid Zakaria’s two-patch bugfix series for the credential-cache daemon. The patch itself is a well-motivated fix for a race condition in socket directory creation, and Patrick Steinhardt’s feedback is substantive but non-blocking.

Patrick identifies a latent issue in the existing code: the use of `safe_create_leading_directories()` is inappropriate for the credential-cache daemon’s socket directory because it applies `core.sharedRepository` permissions, which could lead to unintended access control. He suggests switching to `safe_create_leading_directories_no_share_const()` in a preparatory commit. While this is not part of Farid’s original patch, it is a sensible cleanup that would improve the code’s correctness and clarity.

The rest of Patrick’s review is positive. He agrees with the core fix—ignoring `EEXIST` from `mkdir()` and treating the directory as if it already existed—and notes that the duplicated permission-checking logic is unfortunate but unavoidable without larger refactoring. His feedback does not raise any correctness concerns about the race condition fix itself, and the patch remains uncontroversial.
