This is the second patch in a two-patch follow-up series to `jt/odb-keep-lockfile-fix`, which is already cooking in `next`. It targets the object-file subsystem, specifically tightening error propagation when `git index-pack` exits abnormally.

The patch modifies `odb_transaction_files_write_pack()` in `object-file.c` to return an error (instead of success) when `index-pack` fails after reporting the packfile name. Currently, the function records an error message in `err_msg` but still returns success, which is misleading even though callers currently discard the return value. The change is mechanical: it consolidates error handling by ensuring the function returns `-1` in all failure cases, including abnormal `index-pack` exit. The diff also simplifies how child process exit statuses are checked, replacing `status` variables with direct `run_command()`/`finish_command()` checks.

This is a follow-up to address post-merge review feedback, not new functionality. The commit message is clear but minimal, stating the problem ("return value should reflect the failure") and the fix without elaborating on broader implications. No test coverage is added, consistent with the series' focus on tightening existing error paths rather than introducing new behavior. The patch is small (10 insertions, 10 deletions) and touches only `object-file.c`.

The series as a whole (both patches) is already cooking in `next`, meaning it is undergoing integration testing but not yet final. This patch depends on the first patch in the series, which added warnings for unlink failures. The changes are uncontroversial and align with the project's preference for explicit error handling.
