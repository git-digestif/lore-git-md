This thread is a two-patch follow-up to Justin Tobler’s recently merged `jt/odb-keep-lockfile-fix` series, which fixed a bug in the object-file subsystem where `.keep` files could be left behind after failed operations. The follow-up tightens error handling in the same area: the first patch added warnings when unlink operations fail, and this second patch ensures that `git index-pack` failures are properly propagated as errors rather than silently ignored.

The change is mechanical and uncontroversial—it consolidates error handling in `odb_transaction_files_write_pack()` so that abnormal `index-pack` exits now return `-1` instead of success, even though current callers don’t check the return value. The patch is small (10 lines changed) and touches only `object-file.c`, with no new test coverage or on-disk format changes. Both patches in the series are already cooking in Junio’s `next` branch, meaning they’re undergoing integration testing but haven’t graduated to `master` yet. There’s been no review feedback on this second patch, but the series as a whole addresses post-merge review comments and aligns with Git’s preference for explicit error reporting.
