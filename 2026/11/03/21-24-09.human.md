This is a bugfix patch, the first in a two-patch follow-up series to the recently merged `jt/odb-keep-lockfile-fix`. It targets the object-file subsystem, specifically tightening error handling in the "files" ODB transaction cleanup path.

The patch addresses a silent failure mode: when Git cleans up a temporary packfile or ".keep" lockfile on an error path, any failure to unlink the file is currently ignored. This can leave behind ".keep" files that prevent their packfiles from being removed by later housekeeping. The fix is mechanical—replacing `unlink()` with `unlink_or_warn()` in three locations in `object-file.c`—so that failures are at least reported to the user.

The change is small (three insertions, three deletions) and well-scoped. It doesn’t alter core logic or introduce new behavior beyond surfacing existing failures. The commit message clearly states the problem and the solution, though it doesn’t elaborate on how often this failure might occur in practice or what the user impact is. No tests are added, which is consistent with the follow-up nature of the series—this is a direct response to post-merge review feedback on code that already landed in `next`.

The patch is already cooking in `next` alongside its parent series, meaning it’s undergoing integration testing but isn’t yet final. If you’re tracking the ODB abstraction effort or care about error reporting in low-level storage operations, this is worth noting; otherwise, it’s a quiet but sensible cleanup.
