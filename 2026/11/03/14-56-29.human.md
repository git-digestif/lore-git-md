This is a bug report about `git push` with the `--force-with-lease` option. The author, Patrick Peroša, describes a scenario where the option is silently ignored when pushing to a remote *group* (a configured alias for multiple remotes) unless an explicit `<refname>` is provided. The report includes a minimal reproduction case, GIT_TRACE logs showing the flag is not forwarded to child push processes, and confirms the issue exists across multiple Git versions (including `next`).

The bug is well-documented: the `--force-with-lease` flag works as expected when pushing to individual remotes or when the refname is explicitly specified, but fails when using a bare `--force-with-lease` with a remote group. The `--force` flag, by contrast, works correctly in all cases. This suggests a parsing or forwarding logic error in the push machinery when handling remote groups.

The report is credible and actionable. The reproduction steps are clear, the behavior is consistent across platforms, and the author has ruled out unrelated factors (like `--dry-run`). No prior discussion or patch is mentioned, so this appears to be a new discovery. If fixed, it would resolve a subtle but real usability issue for users who rely on remote groups and `--force-with-lease` for safer forced pushes.
