This is a maintainer response to an RFC proposing a `--switch` (`-s`) option for `git branch`. Junio C Hamano questions the necessity of the feature by pointing out that `git checkout -b` already provides the same functionality (create and switch to a new branch in one step). His reply is brief and direct, challenging the author to justify why the existing `git checkout -b` (or its modern equivalent, `git switch -c`) is insufficient for users who want this workflow.

The response does not engage with the user-experience rationale presented in the RFC (e.g., whether users think of the operation as "creating a branch" vs. "switching to a new branch"). Instead, it frames the discussion around redundancy: if `git checkout -b` already exists, why add another way to do the same thing? This suggests the proposal may face skepticism unless the author can demonstrate a clear gap in the current user experience that isn’t addressed by existing commands.

No technical concerns are raised—this is purely a conceptual objection. The thread remains open, with the ball now in the author’s court to either defend the proposal or reconsider it.
