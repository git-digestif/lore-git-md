This thread is about a Rust bugfix that prevents a panic when formatting an `ObjectID` with an invalid hash algorithm. The patch, submitted by shrimech, replaces an unchecked `unwrap()` in the `Display` implementation for `ObjectID` with a fallback that renders invalid algorithms as `<raw-bytes>:invalid-hash-algo-<id>` instead of crashing. A regression test was added to verify the fix.

The key discussion point was whether the Rust implementation should align with the C code, which silently falls back to the default algorithm for algorithm ID 0. brian m. carlson, the original author of the Rust `hash` module, weighed in to clarify that algorithm ID 0 is not a valid configuration and should not occur in practice. They endorsed the Rust implementation’s current behavior (marking invalid algorithms as invalid) as safer than the C code’s fallback, which they described as prone to subtle bugs. brian also noted that their `sha256-interop` branch includes changes to make the `algo` field non-public, preventing invalid states from being constructed in the first place. This effectively resolves the open question, leaving the Rust behavior unchanged.

Tanga Joris provided a substantive review, confirming the patch works as intended and raising the inconsistency with the C code as a potential issue. The patch is now under review, with no further technical objections or requests for changes. The next step is likely maintainer action, unless shrimech opts to incorporate brian’s referenced patch to further harden the Rust implementation.
