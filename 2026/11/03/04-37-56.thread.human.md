This thread is about a Rust bugfix patch that prevents a panic in Git's `hash` module when formatting an `ObjectID` with an unrecognized algorithm identifier. The patch, submitted by shrimech, replaces an unchecked `unwrap()` with a fallback that displays raw hash bytes and appends an `:invalid-hash-algo-<id>` marker instead of crashing. The fix includes a regression test and touches only `src/hash.rs`.

Tanga Joris reviewed the patch and confirmed it works: the new test passes, and the fix resolves the panic. However, the review surfaced a potential inconsistency with the C codebase. In Rust, algorithm ID 0 is treated as invalid (appending `:invalid-hash-algo-0`), while the C code silently falls back to the default hash algorithm for the same input. This discrepancy could cause divergent behavior between the two implementations. The reviewer cc’d brian m. carlson, the original author of `src/hash.rs`, to weigh in on whether this needs alignment before the patch can proceed. The patch remains under review, with no maintainer decision yet.
