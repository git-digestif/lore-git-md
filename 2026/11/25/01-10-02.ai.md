This is a **bugfix** targeting the `git apply` machinery -- specifically patch 2/2 of Tanga Joris's v4 two-patch series that fixes a deterministic crash in `git apply --check` when processing malformed patch headers. The series addresses the assertion failure `patch->is_new <= 0` in `check_preimage()` that occurs when a patch creates a new file but also carries an old name, or deletes a file but also carries a new name.

The patch adds two validation checks at the end of `parse_git_diff_header()` in `apply.c`: if `patch->is_new` is set but `patch->old_name` is also present, it rejects the patch with an error indicating `"---" before "new file mode"` at the recorded line number; likewise if `patch->is_delete` is set but `patch->new_name` is present, it rejects with `"+++" before "deleted file mode"`. This catches the inconsistent state where a `--- /dev/null` line appears before `new file mode` (causing `gitdiff_verify_name()` to populate `old_name` with `dev/null` before `is_new` is set), or where `+++ /dev/null` appears before `deleted file mode`. The error messages reference the offending `---` or `+++` header line and its line number rather than printing the stripped name, and the check returns `-128` to abort parsing. The commit message notes this mirrors the approach of commit `d70e9c5c8c` (2017), which added similar early rejection for other mutually exclusive header lines.

The behavioral change affects patches that previously applied: a patch with `+++ /dev/null` before `deleted file mode` that used to apply without `-R` is now rejected outright, and the analogous new-file case now fails `--check` instead of hitting the assertion. Git-generated patches are unaffected because Git always emits the mode line before the `---`/`+++` lines.

Tests are added to the new file `t/t4133-apply-filenames.sh`, covering both header-ordering violations with `--- /dev/null` and `--- a/f` before `new file mode`, and `+++ /dev/null` before `deleted file mode`, verifying that `git apply --check` fails with the expected error message referencing the correct file and line number, and that `git apply --check -R` also rejects the deletion case.

This patch is the second half of a series based on commit `77904e546de3bd940621092ecec47a88d0cede5d` targeting `maint`, which merges cleanly with `master`, `next`, and `seen`. It follows v4 patch 1/2 (which rejects empty `diff --git` sections in `find_header()`) and carries a `Helped-by` trailer from Siddharth Asthana. The fix addresses the crash originally reported by Gingrspacecadet and has received endorsement from Junio C Hamano and substantive review from Phillip Wood.
