This is the **v4 cover letter** for a **two-patch bugfix series** targeting `apply.c`, fixing a deterministic crash in `git apply --check` where the assertion `patch->is_new <= 0` in `check_preimage()` fires on malformed patch headers. The series is now reduced from three patches to two: v4 drops the v3 patch 1/3 (a memory leak fix in `parse_git_diff_header()` freeing `patch->def_name`) because the stricter validation in the new 1/2 makes that leak unreachable.

The key change in v4 is that patch 1/2 now rejects an empty `diff --git` header immediately inside `find_header()`, rather than waiting to see if a valid patch follows it. When `find_header()` encounters a `diff --git` line followed by another line that is not a git header line (including another `diff --git` line), it now emits `error(_("corrupt patch: empty \"diff --git\" header at %s:%d"), state->patch_input_file, linenr)` and returns `-128`. This implements Junio C Hamano's guidance that modern Git never generates bare `diff --git` lines (historically only in 2005 before commit `ec1fcc16af` added the `index` line), so any empty section indicates a corrupt patch. Text between complete patches continues to be ignored unless a line starts with `diff --git `.

Patch 2/2 is unchanged from v3 and modifies `parse_git_diff_header()` to reject new files where a `---` line appears before `new file mode`, and deleted files where a `+++` line appears before `deleted file mode`, producing error messages that reference the offending header lines with line numbers (e.g., `"---" before "new file mode" at file.diff:4`). Both patches add comprehensive tests to the new file `t/t4133-apply-filenames.sh`, covering empty headers followed by another `diff --git`, blank lines after `diff --git`, and the header-ordering violations, verifying behavior under both `--check` and actual application including `-R`.

The series is based on commit `77904e546de3bd940621092ecec47a88d0cede5d` and targets `maint`, merging cleanly with `master`, `next`, and `seen`. Junio C Hamano has explicitly endorsed the stricter approach, and Phillip Wood provided substantive review supporting the rejection of previously-accepted edge cases. The thread has converged on this v4 iteration, with the empty-section handling now resolved by immediate rejection in `find_header()` rather than the previous skip-and-continue behavior.
