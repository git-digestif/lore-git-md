This is a documentation patch fixing an inaccurate in-code comment.

Dirk Gouders sends the second patch in a four-part v6 series (no cover letter was provided with this email) that corrects the comment above `utf8_strnwidth()` in `utf8.c`. The existing comment describes the function as operating on a NUL-terminated string and returning `strlen()` when the input is not valid UTF-8, but the function actually accepts a `len`-bounded string and returns that `len` in the fallback case. The patch simply swaps those two phrases so the comment matches the real signature and behavior.

The change is two lines long, touches no executable code, and carries a Helped-by trailer from Andy Koppe. It is a straightforward, low-risk cleanup that clearly improves the accuracy of the source documentation.
