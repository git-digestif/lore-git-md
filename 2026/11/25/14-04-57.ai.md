This is a brief response in the review thread for patch 2/5 of Johannes Schindelin's v2 series "[PATCH v2 0/5] Coverity-inspired integer-overflow fixes". Johannes Schindelin accepts Junio C Hamano's suggested rewording of the commit message for the `http.c` patch and confirms he will use it. The code change itself -- switching the local variable `posn` in `fwrite_sha1_file()` from `int` to `size_t` -- is already approved by Junio with "Looking good" and remains unchanged from v1. The only remaining action on this patch is the commit-message rewording to clarify that `posn` is reset to zero on every curl callback invocation, so an overflow could only occur if a single call passed more than `INT_MAX` bytes (`size = eltsize * nmemb`), not through accumulation across multiple callbacks.
