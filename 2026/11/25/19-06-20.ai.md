This is a feature patch, specifically the third of seven in Harald Nordgren's v16 series implementing a limited-fetch mode for shallow repositories. It introduces the `remote.<name>.fetchRefmap` configuration variable, which provides a persistent default for the `--refmap` command-line option, decoupling which refs are fetched from where they are stored locally.

The implementation adds a `struct refspec refmap` field to `struct remote` in `remote.h`, initialized and cleared in `make_remote()` and `remote_clear()` within `remote.c`. The config parser in `handle_config()` recognizes the `fetchrefmap` subkey and appends it to this refspec. In `builtin/fetch.c`, `get_ref_map()` now computes an `effective_refmap` that prefers the command-line `--refmap` if given, falling back to `remote->refmap` otherwise, and applies it via `map_refs_without_dst()` to any destination-less refspecs. The function `remote_find_tracking()` in `remote.c` is also modified to consult the refmap when `remote.<name>.fetch` yields no match, so that `@{upstream}` and `git branch --track` resolve correctly for branches stored via the refmap, while still respecting negative refspec exclusions.

Behaviorally, configuring `remote.<name>.fetchRefmap` does not change what is fetched; `remote.<name>.fetch` still controls the source refs. Entries in `remote.<name>.fetch` without an explicit destination are stored through the refmap, while entries with their own non-empty destination bypass the refmap entirely. Tags are followed for refs stored through the refmap just as they are for refs stored through the fetch refspec. The command-line `--refmap` overrides the configured value when both are present.

Tests in `t/t5510-fetch.sh` cover the baseline behavior where nothing is fetched without tracked branches, storage of named branches through the refmap, CLI override of the config, exemption of destination-bearing refspecs (both configured and command-line), upstream tracking for branches outside the fetch refspec, and exclusion of branches matched by negative refspecs. Documentation updates appear in `Documentation/config/remote.adoc` and `Documentation/fetch-options.adoc`. As part of v16, this patch builds on patches 1-2 which established the `map_refs_without_dst()` helper and override semantics, and precedes patches 4-7 which implement `fetchUpstreams` and the `git remote add` changes; the series remains under review, having superseded v15 which was previously queued in `next`.
