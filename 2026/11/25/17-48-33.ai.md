This is the fifth and final patch in Ravi Mistry's v5 series hardening Git's HTTP transport retry logic; it changes the default for `http.retryAfter` and refines how an explicit `Retry-After: 0` is handled.

The patch flips the default value of `http.retryAfter` from 0 to 10 seconds in `http.c`, so that when `http.maxRetries` is enabled and a server returns a retryable status (429 by default, or codes listed in `http.retryStatusCodes`) without a `Retry-After` header, Git now waits 10 seconds before the first retry and doubles the delay on each subsequent attempt (10s, 20s, 40s, capped at `http.maxRetryTime`) instead of hammering the server in a tight loop. Users who need immediate retries can still set `http.retryAfter=0` explicitly.

Because libcurl's `CURLINFO_RETRY_AFTER` returns 0 both when the header is absent and when the server sends `Retry-After: 0` (or a past HTTP-date), the patch adds `has_zero_or_past_retry_after()` in `http.c`, guarded by the new `GIT_CURL_HAVE_CURL_EASY_HEADER` macro in `git-curl-compat.h` (defined for libcurl >= 7.84.0). When `CURLINFO_RETRY_AFTER` is <= 0, `finish_active_slot()` now inspects the raw response header via `curl_easy_header()`; if the server explicitly requested an immediate retry, `slot->results->retry_after` is set to 0 so the request retries without waiting, preserving the old behavior for that specific case while applying the new 10-second default only when the header is missing or malformed.

The patch also drops the word "configured" from the error message emitted when `http.retryAfter` exceeds `http.maxRetryTime`, since the value may now be the default rather than an explicit user setting. Tests in `t/t5584-http-429-retry.sh` are updated accordingly: existing tests that relied on immediate retries now set `http.retryAfter 0` explicitly, a new test verifies the 10-second default by setting `http.maxRetryTime 9` and confirming the fail-fast error mentions "10 > 9 seconds", and a `CURL_EASY_HEADER`-gated test confirms that `Retry-After: 0` still triggers an immediate retry on libcurl >= 7.84.0.

With patches 1-4 already approved by Junio C Hamano, this final patch completes the v5 series and awaits his review of the default-change proposal and the integration decision.
