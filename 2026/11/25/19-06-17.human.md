This is a cover letter for v16 of a seven-patch feature series by Harald Nordgren that introduces a "limited fetch" mode to stop shallow repositories from downloading every branch when a new remote is added.

The series addresses a specific pain point: in a shallow clone, running `git remote add` followed by `git fetch` currently pulls all remote branches because the default refspec is `+refs/heads/*:refs/remotes/<name>/*`, which defeats the purpose of the shallow clone. The proposed solution splits "what to fetch" from "where to store it" using two new configuration knobs -- `remote.<name>.fetchUpstreams` (to fetch only branches that local branches track) and `remote.<name>.fetchRefmap` (to control where fetched refs are stored, acting as a configured default for `--refmap`). A new `git remote add --limited-fetch` option sets both, and in shallow repositories this limited-fetch behavior becomes the default for `git remote add` unless `-t` or `--mirror` is specified.

Version 16 refines the semantics established in v15. It now follows tags when a fetch stores refs through `--refmap` or `fetchRefmap` (but not when `--refmap=""` stores nothing), rejects `--refmap` without command-line refspecs when the remote has nothing configured to fetch, and adjusts `--prune` so that it leaves configured destinations alone when `--refmap` redirects storage elsewhere. The range-diff shows these changes touch `builtin/fetch.c`, `remote.c`, and `remote.h`, with tests added to `t/t5510-fetch.sh`, `t/t5586-fetch-refmap.sh`, and `t/t5505-remote.sh`.

The series was previously queued in `next` as v11, but has since evolved significantly through multiple iterations addressing maintainer feedback.
