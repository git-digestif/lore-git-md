This is a substantive review from Junio C Hamano on the first patch of Dominik Maier's two-patch v2 series, which fixes out-of-bounds pointer arithmetic in `write_zip_entry()` within the ZIP archive backend when `--prefix` is longer than an extra or virtual file's path.

Junio engages with three specific aspects of the change. He first offers a minor wording correction: attribute lookups default to the index unless `--worktree-attributes` is given, so "gitattributes" is more accurate than "worktree gitattributes" in the commit message. On the `entry_is_binary()` NULL guard, he notes that `userdiff_find_by_path()` already handles NULL paths, so the new check mainly avoids initializing a static `attr_check` when only virtual files are present, and he suggests the optimization might belong inside `userdiff_find_by_path()` instead. Finally, he observes that the loop in `write_archive_entries()` mutates `args->base` and `args->baselen`, leaving them set to the last extra file's values on return; while current callers do not inspect them afterward, saving and restoring the original values around the loop would be safer for future callers.

The review closes approvingly with "Overall, nicely done," indicating no blocking objections. This email advances the discussion of patch v2 1/2, which pairs with a second patch reworking `--remote` argument validation, and the series remains under review with no merge status stated.
