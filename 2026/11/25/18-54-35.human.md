This is a small bugfix improving the error hint that `git config` prints when a user passes `key=value` as a single argument. When the value contains spaces, the suggested `git config set` command previously was not shell-safe -- pasting it back into a terminal would fail because the shell splits the unquoted value into separate arguments. The patch quotes the value when necessary and places the suggested command on its own line, matching the formatting of other Git hints so it can be copied and pasted directly.

The change modifies `builtin/config.c`, adding a helper function that wraps arguments in single quotes when they contain shell-significant characters, and updates `die_missing_set_value()` to use this when constructing the "did you mean" suggestion. Tests in `t/t1300-config.sh` are updated to expect the new multi-line output format and include cases for values with spaces and for shell alias syntax (such as `!git status`) to verify the quoting behaves correctly.
