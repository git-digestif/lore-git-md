This is patch 3/5 of Harald Nordgren's v11 series introducing `--delete-integrated` to `git branch`, though the patch itself is a standalone usability improvement to `--dry-run`. It extends `--dry-run` so that it works with plain `-d` and `-D` deletion flags, not just `--delete-merged`, letting users preview which branches `git branch -d topic` would remove without touching any refs. The output mirrors the actual deletion message (`Would delete branch topic (was 1a2b3c4).`), and branches that cannot be deleted still produce the same errors they would without the flag.

The v11 iteration refines the error handling when `--dry-run` is combined with unsupported operations. Instead of the generic `--dry-run requires --delete-merged`, the code now names the specific operation being attempted -- `--dry-run is not supported for branch renaming` for `-m`, copying for `-c`, creation for a bare `git branch --dry-run new-branch`, and a catch-all for other cases. This directly addresses Junio's request for operation-specific messaging, though the philosophical question of whether these errors should hint at future support remains open in the thread.

Within the broader series, this patch lays groundwork for the upcoming `--delete-integrated` mode (patches 4/5 and 5/5) by generalizing the `--dry-run` plumbing in `delete_branches()` via a new `DELETE_BRANCH_DRY_RUN` flag, but it delivers immediate value on its own. The change touches `builtin/branch.c`, the `git-branch` man page, and `t/t3200-branch.sh` with 54 lines of new tests covering dry-run deletion, remote-tracking branches, error cases, and the new operation-specific messages.

The patch looks well-crafted and responsive to maintainer feedback: it includes documentation updates clarifying that creating, renaming, and copying do not support `--dry-run` while deletion modes do, and the test coverage exercises both the successful preview paths and the rejection of unsupported operations. It remains under review with no integration status announced.
