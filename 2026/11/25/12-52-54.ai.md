This is patch 4/5 in version 11 of Harald Nordgren's series, implementing the tree-based rebase-detection half of the new `--delete-integrated` flag for `git branch`. The patch introduces the `DELETE_BRANCH_INTEGRATED` flag bit and a `delete_integrated` strvec parsed from the command line; when active, `delete_merged_branches()` in `builtin/branch.c` collects candidate branches that fail the usual `check_branch_commit()` reachability test into a `landing_search` array, then calls `find_landed_commits()` to scan the upstream history. For each candidate, `collect_branch_changes()` diffs the merge base against the branch tip to record every changed path with its blob OID and mode in a `branch_change` array. `find_landed_commit()` then walks upstream commits in reverse order using a `changed_paths` commit slab to skip commits that do not touch any of the branch's changed paths, checking whether any single upstream commit's tree contains the exact branch version (OID and mode) of every changed file via `changes_landed()` and `change_landed()`. The first matching commit is stored in a strmap keyed by branch name, which `delete_branches()` consults to skip the reachability check and print `Deleted branch %s (was %s, landed as %s)`. Because this comparison is purely tree-based and never reads blob contents, it remains cheap in partial clones and blobless checkouts. The patch adds 249 lines to `builtin/branch.c`, updates documentation for the new flag and the extended `--dry-run` support, and adds 263 lines of tests to `t/t3200-branch.sh` covering rebase-merged deletion, reverted squash merges, file-to-directory conversions, `--dry-run`/`--quiet` combinations, `branch.<name>.deleteMerged=false` opt-out, and mutual exclusion with `--delete-merged`. Note that patch 5/5 in the same series will layer squash-merge detection on top of this infrastructure using actual blob content comparison via `xdl_merge()`, whereas this patch handles only the tree-identical rebase case. Open questions from the thread remain unresolved: whether `branch.<name>.deleteMerged` is the right config key for the new mode or whether a separate key should be introduced, and the lack of author-check or patch-id mitigation for the "npm update" false-positive scenario where another author independently makes identical changes.
