This is a substantive review of the second patch (2/2) in Dominik Maier's v2 bugfix series for `git archive`, specifically the change that defers `--add-file` `stat()` calls until after option parsing. Junio C Hamano confirms the implementation cleanly follows René Scharfe's suggested deferred-validation approach and resolves all three targeted issues -- rejecting `--remote --add-file` before any filesystem access, preserving `--no-add-file` cancellation semantics, and enabling `--remote --add-virtual-file` -- without touching the server filesystem when unnecessary.

Junio validates the technical soundness of keeping `prefix_filename()` inside `add_file_cb()` during `parse_options()`, which preserves relative-path resolution when the command runs from a subdirectory. He notes that because `setup_git_directory()` is only invoked later in `write_archive()` after `parse_archive_args()` returns, the working directory remains unchanged between the callback and the deferred validation loop, so the stored path remains correct for the later `stat()` call.

He further confirms that entries added by `--add-virtual-file` always carry non-NULL `content` from `xstrdup()`, so the new loop in `parse_archive_args()` correctly skips them, allowing `--remote` archives to include virtual files without requiring server-side filesystem probes. The review touches `archive.c` and the new tests in `t/t5000-tar-tree.sh`, and concludes with "Looking good," indicating no outstanding objections to the patch as written.
