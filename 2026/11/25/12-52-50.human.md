This is a feature patch series -- specifically the cover letter for **v11** of Harald Nordgren's five-patch effort to add `git branch --delete-integrated <pattern>`, which extends branch deletion to catch branches whose changes were squash-merged or rebased into an upstream without their tips being reachable.

The v11 iteration is a small refinement on top of v10: when `--dry-run` is combined with a non-deletion operation (creating, renaming, or copying a branch), the error message now names that specific operation -- e.g. `fatal: --dry-run is not supported for branch renaming` -- rather than the previous generic "can only be used when deleting branches." The documentation is updated to state plainly that other operations do not support `--dry-run`.

The series itself remains substantial and under review. Patches 4 and 5 implement the core detection: patch 4 finds rebase-merged branches via pure tree comparison (cheap, no blob fetches), while patch 5 finds squash-merged branches -- including cases where upstream later modified the same files -- by performing a three-way text merge with `xdl_merge()` and requiring the result to match upstream byte-for-byte. The implementation deliberately ignores `.gitattributes` merge drivers to avoid false positives. Output names the landing commit: `Deleted branch topic (was 1a2b3c4, landed as 9f8e7d6)`.

The contribution looks well-crafted and thoroughly tested (nearly 500 lines of new tests in `t/t3200-branch.sh`), though reviewers have flagged open questions about false positives when another author independently makes identical changes, and Junio has questioned whether the `branch.<name>.deleteMerged` config opt-out should apply to the new change-based mode or remain specific to strict tip-reachability. No integration branch status has been announced.
