This is a feature patch for the new `git history` command, making the `squash` subcommand's revision range argument optional. When run without arguments, `git history squash` now defaults to folding the commits on the current branch that are not in its upstream (equivalent to `@{upstream}..HEAD`), matching the familiar behavior of `git rebase`. Previously the command refused to run without an explicit range.

The change restores a default that existed in an earlier incarnation of this feature when it was proposed as `git rebase --squash`; the behavior was lost when the functionality moved into the new `git history` command. The patch adds a `default_squash_range()` helper in `builtin/history.c` that resolves `@{upstream}` and HEAD, computes their merge base, and constructs the equivalent revision range automatically, erroring cleanly if no upstream is configured.

The patch updates the documentation in `Documentation/git-history.adoc` to show the argument as optional and describe the default, and adds tests in `t/t3455-history-squash.sh` covering both the new default behavior (using a clone with a diverged upstream) and the error case when no upstream exists. The commit message clearly explains the motivation and references the prior commit that introduced the squash skeleton, making this a well-motivated and complete contribution to the ongoing `git history` development effort.
