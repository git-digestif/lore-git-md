Thread identity: single bugfix patch to the `git config` builtin, authored by Harald Nordgren via GitGitGadget. Thread type: standalone patch, currently under review with no prior versions.

Core problem: when a user runs `git config <key>=<value>` as a single argument and the value contains spaces, the shell splits the argument and the command fails. The existing error hint suggested a `git config set` command that was itself unsafe to paste back into a shell because the value was not quoted.

Current status: initial patch version posted; not yet merged or queued in any integration branch.

Key technical details: the fix is implemented in `builtin/config.c`. A new static helper `add_suggested_arg` takes a `struct strbuf` and an argument string, applies `sq_quote_buf_pretty` to produce a shell-quoted form, and falls back to wrapping in single quotes if the argument already contains a single quote. `die_missing_set_value` now builds the suggestion into a `struct strbuf` by calling `add_suggested_arg` for both the key prefix and value, then emits it via `advise` in a multi-line format: `did you mean:` followed by a blank hint line and an indented tab-prefixed `git config set ...` line. Old single-line output like `hint: did you mean "git config set status.comparebranches @{upstream} @{push}"?` is replaced by `hint: did you mean:` / `hint:` / `hint: \tgit config set status.comparebranches '@{upstream} @{push}'`. Tests in `t/t1300-config.sh` are converted from `test_grep` to exact `test_cmp` matching, with new cases covering a value with spaces (`status.comparebranches="@{upstream} @{push}"`) and a shell alias (`alias.st="!git status"`).
