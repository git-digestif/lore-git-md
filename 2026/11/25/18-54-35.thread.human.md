Harald Nordgren has sent a small bugfix for the `git config` builtin that fixes an unsafe error hint. When a user runs `git config <key>=<value>` as a single argument and the value contains spaces, the shell splits the argument and the command fails; the old hint suggested a `git config set` command that was itself broken when pasted back into a shell because the value was left unquoted. The patch makes the suggestion shell-safe by quoting the value when necessary and printing the command on its own indented line.

The change is confined to `builtin/config.c` and `t/t1300-config.sh`. A new static helper `add_suggested_arg` uses `sq_quote_buf_pretty` to produce a shell-quoted form (falling back to single quotes if the value already contains one), and `die_missing_set_value` now builds the multi-line hint into a `struct strbuf` and emits it via `advise`. Tests in `t/t1300-config.sh` were switched from `test_grep` to exact `test_cmp` matching, with new cases covering a value with spaces and a shell alias to verify quoting is preserved.

Since this is the opening email of the thread, no review feedback or maintainer decision has been recorded yet; the patch is currently under review.
