This is a **feature** patch -- specifically the fourth of five in Harald Nordgren's v11 series adding a new `--delete-integrated` option to `git branch`. It implements the tree-based half of the change-detection logic: when a branch's tip is not reachable from upstream (as after a rebase-merge or squash-merge on GitHub), the code scans upstream history for a commit whose tree contains the branch's exact version of every file the branch touched, comparing blob OIDs and modes without ever reading file contents. That keeps the check cheap in partial clones. When a match is found, the branch is deleted and the output names where the work landed, e.g. `Deleted branch topic (was 1a2b3c4, landed as 9f8e7d6)`.

The patch wires up the new CLI flag `--delete-integrated <pattern>`, mutually exclusive with the existing `--delete-merged`, and reuses the `branch.<name>.deleteMerged=false` config opt-out (prepared in patch 1/5). It also carries the v11-specific refinement to `--dry-run`: combining `--dry-run` with a non-deletion operation now dies with an operation-specific message (`--dry-run is not supported for branch renaming`, etc.) rather than a generic error, while `--dry-run` itself now works with `--delete-integrated` to preview deletions. Tests in `t/t3200-branch.sh` cover rebase-merged deletion, squash-merged deletion (including reverted squash merges), file-to-directory changes, dry-run previews, quiet mode, the config opt-out, and the mutual-exclusion error.

The approach is deliberately conservative: because it compares trees rather than content, it cannot detect cases where upstream modified the same files before integrating the branch -- that harder squash-merge case is deferred to patch 5/5, which will add a three-way text-merge fallback. A known gap remains in both halves: the "npm update" scenario, where another author independently makes identical changes, will still trigger deletion; author checks or patch-ids would be needed to prevent that and are not implemented here. The series remains under review with no integration branch announced.
