This is the fourth patch in a six-patch `the_repository` removal series (v5) for the notes subsystem, refactoring the write, prune, and copy paths in `notes.c` to use the repository stored in `struct notes_tree` rather than the global.

The patch converts `write_notes_tree()` to pass `t->repo` down through the tree-writing helpers: `tree_write_stack_finish_subtree()` and `write_each_note_helper()` now take an explicit `struct repository *` first parameter, and `struct write_each_note_data` gains a `repo` field that `write_notes_tree()` populates with `t->repo`. Object writes that previously called `odb_write_object(the_repository->objects, ...)` now use `r->objects` or `t->repo->objects`. Similarly, `prune_notes()` introduces a new `struct prune_notes_data` carrying both the repository pointer and the delete-list head; its callback `prune_notes_helper()` receives this struct and checks `odb_has_object(d->repo->objects, ...)` instead of the global.

The patch also fixes the `copy_note()` NULL-dereference identified in earlier iterations: the function now begins with `t = notes_tree_or_default(t);` before calling `get_note()`, and when adding a null note it uses `null_oid(t->repo->hash_algo)` rather than the global `the_hash_algo`. This makes `copy_note()` consistent with the other public entry points (`add_note()`, `remove_note()`, etc.) that already routed through the `notes_tree_or_default()` helper introduced in patch 1/6.

Within the series, this patch builds on patch 2/6 (which added `struct repository *repo` to `struct notes_tree`) and patch 3/6 (which converted the read-path helpers). It leaves `USE_THE_REPOSITORY_VARIABLE` in place in `notes.c` for the remaining unconverted functions, including display-notes code and hash-size helpers, which the cover letter identifies as future work alongside `notes-cache.c` and `notes-merge.[c,h]`. The series remains under review with no merge status; Patrick Steinhardt's confirmation on the scoping of the remaining guard is still pending.
