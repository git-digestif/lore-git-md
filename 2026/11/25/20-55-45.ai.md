This is a bugfix, the first patch (v3 1/5) in Johannes Schindelin's five-patch series addressing Coverity-flagged integer overflows across `archive-tar.c`, `http.c`, `wrapper.c`, and `date.c`.

The patch hardens `get_path_prefix()` in `archive-tar.c`, which previously used a `do...while` loop that decremented a `size_t` index unconditionally. When the index was zero on entry, the decrement wrapped to `SIZE_MAX`, causing an out-of-bounds read at `path[SIZE_MAX]`. The fix adds an early `return 0` when the computed index `i` is zero, preventing the wrap. The commit message notes the bug is currently latent because the sole caller `write_tar_entry()` only invokes the function with `pathlen` of at least 100, but the interface accepts arbitrary values, so the guard protects against future callers or a `maxlen` of zero. No test is added in this patch.
