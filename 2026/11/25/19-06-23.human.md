This is a feature patch -- specifically the sixth of seven in Harald Nordgren's v16 series introducing a limited-fetch mode for shallow repositories. It adds a `--limited-fetch` flag to `git remote add` so users can explicitly request the new behavior instead of getting the default wildcard refspec.

When `--limited-fetch` is supplied, `git remote add` skips writing the usual `remote.<name>.fetch` wildcard and instead sets `remote.<name>.fetchRefmap` to `+refs/heads/*:refs/remotes/<name>/*` and `remote.<name>.fetchUpstreams` to `true`. A later refspec-less `git fetch <name>` therefore retrieves only the branches that local branches actually track, rather than every branch on the remote. The option dies if combined with `-t`/`--track` or `--mirror`, since those already state explicitly what to fetch.

The patch sits near the end of the series: earlier patches built the `fetchRefmap` and `fetchUpstreams` machinery in `remote.c` and `builtin/fetch.c`, and patch 7/7 will make limited-fetch the automatic default for `git remote add` in shallow repositories. This patch provides the explicit switch for users who want the behavior in any repository. Tests in `t/t5505-remote.sh` verify that the flag works in a full clone as well as a shallow one, writes the expected configuration, and rejects combination with `-t`.
