This is patch 1/4 of v6 of a bugfix series fixing out-of-bounds reads in Git's UTF-8 display-width code, authored by Junio C Hamano and sent by Dirk Gouders. It introduces `display_mode_esc_sequence_len_counted(const char *s, size_t len)` in `utf8.c` and `utf8.h`, a length-bounded scanner for ANSI SGR escape sequences that uses an array index `i` with explicit `len <= i` checks rather than pointer arithmetic, ensuring it never reads at or beyond `s[len]` and avoiding undefined behavior when `len` is `SIZE_MAX`. The existing NUL-terminated `display_mode_esc_sequence_len(const char *s)` is retained as a thin wrapper that calls the counted variant with `SIZE_MAX`.

The patch immediately adopts the counted variant at two call sites that operate on bounded buffers: `utf8_strnwidth()` in `utf8.c` passes `orig + len - string` as the bound when skipping escape sequences, and `strbuf_utf8_replace()` passes `end - src`. These updates prepare the infrastructure for patches 3 and 4 of the series, which enforce the actual bounds inside the width-computation loops themselves.

A new unit test file `t/unit-tests/u-utf8-ansi.c` is added and wired into both `Makefile` and `t/meson.build`, exercising the counted function with explicit length limits (including truncated sequences at the boundary) and the wrapper with `SIZE_MAX`, using `cl_assert_equal_u()` for size_t return values.

This is a foundational refactoring within the series: it changes no user-visible behavior for existing NUL-terminated callers but enables the subsequent patches to safely handle counted buffers, addressing the risk of reading past the end of mmapped regions when ANSI sequences or multibyte characters fall at the buffer boundary.
