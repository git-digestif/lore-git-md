This is a substantive review comment from Junio C Hamano on the second iteration of Adithya Chakilam's `--filter-to-loose` patch series.

Junio points out a correctness gap in the second patch: the loose-object handling only activates for `blob:limit` filters and silently skips objects when other filters such as `blob:none` are used. This means the behavior described in the cover letter -- where the destination receives all filter-excluded loose objects -- does not hold for all filter types, contradicting the documentation and commit message implications. The comment arrives while the series remains under review, following Junio's earlier identification of several other issues in both patches of v2, including a potential data-loss scenario when the destination directory equals the source object directory.
