This is a refactoring patch, the fourth of seven in Harald Nordgren's v16 series introducing limited-fetch semantics for shallow repositories. It extracts the existing logic that checks whether the current branch tracks a given remote into a new reusable helper, `collect_upstream_from_remote()`, moving it from `builtin/fetch.c` into `remote.c` and `remote.h`. The function takes an optional branch name (NULL meaning the current branch) and, if that branch's upstream lives on the specified remote, pushes the upstream source refs into a provided strvec.

The commit message explains that this inlined check currently ensures a refspec-less `git fetch origin` still retrieves the current branch's upstream into FETCH_HEAD even when the configured refspec does not cover it (as introduced in 49ca2fba39, 2022). By generalizing the helper to accept any branch name rather than just the current one, the patch prepares the ground for patch 5/7, which will iterate over all local branches to implement the `remote.<name>.fetchUpstreams` behavior. There is no behavior change in this patch alone; it is a clean, well-scoped extraction with a clear commit message and no test changes needed.
