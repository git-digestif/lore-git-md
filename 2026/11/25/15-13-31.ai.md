This is a review acknowledgment within Ravi Mistry's `[PATCH v4 4/5]` thread on retrying transient HTTP errors in `post_rpc()`. Ravi confirms Junio C Hamano's observation that the `struct slot_results results` variable in `post_rpc()` retains stale values when `run_one_slot()` returns `HTTP_START_FAILED` without calling `finish_active_slot()`, since the struct is initialized once at function entry and not reset before the `goto retry` loop. He notes this does not affect retry behavior because `HTTP_START_FAILED` is never retried, but `report_rpc_error()` would print the previous attempt's `http_code` and `curl_result` instead of the current failure. Ravi commits to clearing `results` before each `run_one_slot()` call in both `post_rpc()` and `probe_rpc()` in a forthcoming v5. This exchange resolves the last open code-level question on patch 4/5; combined with the author's earlier commitment to document the empty-string and 401/404 edge cases in patch 3/5, the series now awaits only a v5 respin before Junio's final integration decision.
