Thread identity: single-patch bugfix submitted by Alessio Attilio via GitGitGadget, currently at version 2 (v2), fixing a crash in `git pack-objects` under partial clone (promisor) conditions. Thread type: standalone patch, not part of a visible series.

Core problem: `is_not_in_promisor_pack_obj()` in `builtin/pack-objects.c` invoked `BUG()` when `odb_read_object_info_extended()` failed to read an object's info. In a partial clone, objects absent from the local promisor pack are expected to be missing, so the `BUG()` was incorrect and could crash the process. This code path is only reachable when pack-objects is invoked with the undocumented `--exclude-promisor-objects-best-effort` option (introduced by commit c08589efdc, "index-pack: repack local links into promisor packs", dated 2024-11-01), which is passed only when index-pack itself runs with `--promisor`; therefore the issue surfaces only in lazy-clone (partial clone) repositories and cannot affect ordinary clones.

Current status: v2 posted and under review; applies on top of commit 1630431f326e15fcde608827b5ff38422528eb59. Changes from v1: adds `OBJECT_INFO_SKIP_FETCH_OBJECT` to the `odb_read_object_info_extended()` call so the lookup does not trigger a lazy fetch of the missing object.

Key technical details: one-line change replacing the `BUG()` macro with `return 0`, causing the object to be treated as not belonging to a promisor pack and skipped during pack creation. Test coverage moved from `t/t0410-partial-clone.sh` to `t/t5616-partial-clone.sh` and expanded to cover both `--unshallow` and `--deepen=1` filtered fetches of a moved ref, plus a scenario where a subsequent fetch repacks links to promisor commits whose trees are missing -- exercising conditions where index-pack repacks local links into a promisor pack while walking into promisor commits with absent trees.

Open questions and loose ends: Junio C Hamano requests that the commit message describe the end-user scenario that triggers the code path (e.g., running `git repack` in a partial clone, which may attempt to fetch objects from the promisor remote) and explain why it is safe to treat an unreadable object as a promisor object without validating that assumption first. He also suggests documenting in the commit log that the change is scoped to partial clones via the `--exclude-promisor-objects-best-effort` / `--promisor` linkage. He reminds the author that any in-code comment stating "assume X" must explain why the assumption is safe and what the consequences would be if incorrect.
