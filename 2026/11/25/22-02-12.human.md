This is a refactoring patch -- specifically the fourth of six in a v5 series removing the `the_repository` global from the notes subsystem.

Patch 4/6 converts the write and prune paths in `notes.c` to use the repository stored in `struct notes_tree` (added in patch 2/6) rather than reading the global directly. `write_notes_tree()` now passes `t->repo` down through `tree_write_stack_finish_subtree()` and `write_each_note_helper()`, which previously reached for `the_repository->objects` to write tree objects. `prune_notes()` similarly bundles the repository into a new `prune_notes_data` struct handed to its callback, replacing direct `the_repository` lookups when checking whether noted objects still exist.

The patch also fixes the `copy_note()` NULL-dereference bug identified in earlier iterations. That function now routes through `notes_tree_or_default()` -- the helper introduced in patch 1/6 -- so a NULL tree pointer is substituted with the default notes tree before `t->repo->hash_algo` is read for the null object ID. This closes the safety gap that previously allowed `copy_note()` to dereference an uninitialized tree.

The change is mechanical but careful: helper functions gain explicit `struct repository *` parameters, and the commit message explains that both entry points already hold the notes tree, so threading its repository is the natural next step. No user-visible behavior changes; this is purely internal plumbing toward eliminating the global.

Within the broader series, this patch completes the conversion of the core mutation paths alongside the read-path conversions in patch 3/6. The series remains under review, with Patrick Steinhardt's confirmation on the remaining `USE_THE_REPOSITORY_VARIABLE` scoping still pending before follow-up work on `notes-cache.c` and display code can proceed.
