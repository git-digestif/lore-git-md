Feature patch, fifth of seven in Harald Nordgren's v16 series on limited-fetch mode for shallow repositories.

This patch adds the `remote.<name>.fetchUpstreams` boolean configuration, parsed via the `fetchupstreams` subkey in `remote.c:handle_config()` and stored as `fetch_upstreams` in `struct remote`. When set, a refspec-less `git fetch <name>` expands the fetch set to include the upstream branches of every local branch tracking that remote, rather than only the current branch. The new `branches_tracking_remote()` function in `remote.c` (declared in `remote.h`) iterates all local branches via `refs_for_each_branch_ref()` and calls the `collect_upstream_from_remote()` helper extracted in patch 4/7 for each branch. In `builtin/fetch.c`, `add_branch_upstreams()` converts those upstream source refs into destination-less refspec items fed through `get_fetch_map()`, so the refs are stored according to `remote.<name>.fetch` or `remote.<name>.fetchRefmap` rather than FETCH_HEAD. Both `get_ref_map()` and `do_fetch()` now branch on `remote->fetch_upstreams` to include these extra upstreams in the transport ls-refs prefix list. The patch also extends `tracking_for_push_dest()` in `remote.c` to fall back to `apply_refspecs(&remote->refmap, ...)` when the fetch refspec yields no match, allowing `@{push}` to resolve to the correct remote-tracking branch on a refmap-only remote. Tests are added in the new `t/t5586-fetch-refmap.sh`, covering shallow-clone setup, tracking multiple branches, de-duplication of shared upstreams, isolation from other remotes, combination with explicit `remote.<name>.fetch`, `--prefetch`, `git pull` merging only the current branch's upstream, and `@{push}` resolution after pushing to a refmap-only remote.
