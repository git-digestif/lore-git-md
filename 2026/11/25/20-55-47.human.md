This is a bugfix patch, the third in Johannes Schindelin's five-part v3 series addressing integer overflows flagged by Coverity. It changes the return type of `write_in_full()` in `wrapper.c` from `ssize_t` to `int` -- returning 0 on complete success or -1 with `errno` set on failure -- so the function no longer accumulates a running byte total that could overflow `ssize_t` when passed a very large `size_t` count. The companion inline `write_str_in_full()` in `wrapper.h` is updated to match.

Callers are adjusted to the new contract across `config.c`, `entry.c`, `imap-send.c`, `notes-merge.c`, `odb/streaming.c`, and `parallel-checkout.c`, with local variables changed from `ssize_t` to `int` where they now store the status return. Notably, Phillip Wood previously traced that several hook-feeding paths (`refs.c`, `sequencer.c`, `transport.c`) had been storing the old `ssize_t` return into an `int` and testing for negative values, meaning the old accumulation semantics could mask failures; the new API fixes those latent bugs by making the success/failure distinction explicit. The patch also adds a new clar unit-test file `t/unit-tests/u-wrapper.c` covering successful writes, empty writes, and error returns, and updates an assertion in `t/unit-tests/u-reftable-stack.c`.

The series remains under review; Junio C Hamano approved this direction in v2 and Phillip Wood helped refine the caller changes, but v3 is awaiting final sign-off before queuing.
