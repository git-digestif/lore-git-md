This is a substantive review by Junio C Hamano of the second patch in Adithya Chakilam's v2 series adding `--filter-to-loose` to `git repack`. Junio identifies several correctness and robustness issues in the new `move_loose_filtered_objects()` and `remove_moved_loose_objects()` functions in `repack-filtered.c`, as well as problems in the accompanying tests and documentation.

The most significant concern is that the current implementation enumerates all loose objects on disk and filters purely by size, ignoring reachability, pack membership, and the index. Junio outlines three concrete failure scenarios: with `--cruft -a -d`, unreachable loose blobs destined for the cruft pack get copied to the destination before `prune_packed_objects()` runs; with plain `-a -d`, unreachable loose blobs bypass normal prune expiration and pollute the destination; and staged blobs in the index are kept in the main pack by `pack-objects --indexed-objects` yet still get copied to the destination. He suggests the code should instead walk reachable objects from refs or filter after packs are installed, excluding objects that ended up in kept packs or the index. He also notes the function silently no-ops for any filter other than `blob:limit`, contradicting the commit message and documentation, and suggests supporting `LOFC_BLOB_NONE` at minimum while rejecting unsupported filters.

Junio repeats the data-loss guard concern from his review of patch 1: if `dest_objdir` equals the source repository's own object directory, `access(dst, F_OK)` succeeds because src and dst are the same file, and `remove_moved_loose_objects()` would then unlink the only copy of the object. He identifies additional implementation details: `copy_file()` maps mode 0444 to 0666 (masked by umask) rather than preserving read-only permissions, and the temporary file naming scheme `<oid>.tmp-<pid>` does not use the `tmp_obj_` prefix that `git fsck` ignores, so crashed runs leave files that trigger "bad sha1 file" warnings. He recommends using `git_mkstemp_mode(..., 0444)` with `copy_fd()` and the `tmp_obj_XXXXXX` template. In `remove_moved_loose_objects()`, he notes that unlike `prune_packed_objects()` which uses `unlink_or_warn()`, the current code silently ignores `unlink()` errors and leaves empty fan-out subdirectories behind.

On the test side, Junio questions whether the new test using `ls -i` to compare inodes actually exercises the new `move_loose_filtered_objects()` code path or merely the `unpack-objects` path from patch 1, and notes that `ls -i` is not portable across all platforms supported by the test suite. He also flags a documentation formatting issue in `Documentation/git-repack.adoc`, where the new paragraph needs a lone `+` continuation line to match AsciiDoc list formatting used by adjacent entries like `--drop-filtered`.
