This is the first patch of a two-patch v2 feature series introducing a new `--filter-to-loose=<directory>` option for `git repack`. Adithya Chakilam's patch teaches `git repack` to write objects excluded by `--filter` directly as loose objects into a specified object directory rather than into an intermediate packfile, streaming the filtered pack through `unpack-objects` with `GIT_OBJECT_DIRECTORY` pointed at the target. This patch implements the core path for objects already stored in packs; the companion second patch extends the behavior to source-repository loose objects. The option is incompatible with `--filter-to` and `--max-pack-size`, requires the destination directory to pre-exist, and skips objects already present in the target.

The implementation touches `builtin/repack.c`, `repack-filtered.c`, `repack.h`, `Documentation/git-repack.adoc`, and `t/t7700-repack.sh`. In `builtin/repack.c`, the new option is parsed with `OPT_FILENAME` (so relative paths resolve correctly from subdirectories), validated up front with `is_directory()`, and wired into `struct write_pack_opts` via a new `bool loose` field. In `repack-filtered.c`, `write_filtered_pack()` now branches on `opts->loose`: when true, it starts a `unpack-objects` child process with `GIT_OBJECT_DIRECTORY` set to the destination, pipes the `--stdin-packs` output of `pack-objects --stdout` into that child, and manages `SIGPIPE` via `sigchain_push`. This v2 iteration incorporates three fixes from Junio C Hamano's review of v1: the early `is_directory()` check, the `OPT_FILENAME` parsing, and removal of a manual `close()` that caused a double-close of `unpack.in` (since `start_command()` already closes descriptors on failure).

Tests in `t/t7700-repack.sh` cover writing filtered objects as loose files, skipping objects already present in the destination, erroring on a non-existent directory, failure recovery that leaves source packs intact and no `.tmp-*` leftovers, relative-path resolution from a subdirectory, not moving objects from kept packs, leaving unreachable objects in cruft packs alone, survival of `gc`/`prune` in the source once the destination is added as an alternate, and option incompatibility checks. The commit message notes that loose objects in the source repository are left untouched by this patch and will be handled by patch 2. The series remains under review with no integration status reported.
