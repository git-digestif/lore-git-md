This is a substantive maintainer review in an ongoing test-infrastructure thread. Junio C Hamano is responding to Kaartic Sivaraam's proposal to defer fixes for certain edge cases in the `[PATCH v2]` that serializes `EXPENSIVE` tests in `t/test-lib.sh` to prevent CI runners from being OOM-killed.

Junio draws a sharp line between the two classes of concurrency flaws previously identified. A leaky lock that occasionally lets two memory-heavy tests run at once is no worse than the current status quo, so he can live with that. A deadlock, however -- where a killed process leaves an unremovable lock directory that blocks all future `EXPENSIVE` tests forever -- would be a serious regression. He states plainly that as long as the updated version eliminates that deadlock window, he will be happy, implicitly rejecting Sivaraam's suggestion to ship now and patch the remaining `kill -9` and microsecond-window holes later.

The email effectively sets the acceptance criteria for a v3: the TOCTOU race may be tolerable, but the signal-handling deadlock must be closed. The thread remains open with the patch still under review; no integration branch placement has been announced.
