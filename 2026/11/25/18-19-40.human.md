This is the cover letter for v6 of a four-patch bugfix and documentation series fixing bounds handling in Git's UTF-8 display-width code. The series ensures that `utf8_strnwidth()` and `utf8_width()` respect their length arguments and never read past the end of the input buffer -- including the SIGBUS edge case when the buffer ends at a page boundary -- while also correcting the misleading comment on `utf8_strnwidth()`.

Compared to v5, this version incorporates the mechanical review feedback from Junio C Hamano: commit trailers are reordered, the redundant `#include <strbuf.h>` is dropped from the new unit tests, test assertions use `cl_assert_equal_u()` for `size_t` values, comparisons are rewritten as `len <= i`, and `strbuf_add_wrapped_text()` no longer uses the `_counted` variant since it already knows the string is NUL-terminated. Patch 3's commit message now includes a concrete example of how an ANSI escape sequence reaching the length boundary caused an out-of-bounds read, and patch 4 explains why the bounds check in patch 3 remains necessary even with the new `remainder` argument passed to `utf8_width()`.

Junio had previously described v5 as being in "a very good shape" and close to the finish line; v6 addresses those remaining nits without changing the core length-based `_counted` API design. The series remains under review and has not yet been queued in any integration branch.
