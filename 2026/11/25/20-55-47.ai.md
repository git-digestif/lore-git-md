This is the third patch in Johannes Schindelin's five-patch v3 series addressing Coverity-flagged integer overflows across Git's I/O wrappers and related subsystems. The patch changes `write_in_full()` in `wrapper.c` to return `int` (0 on success, -1 with `errno` set on failure) instead of `ssize_t`, eliminating the accumulator variable that could overflow when summing bytes for large `size_t` inputs. The companion inline `write_str_in_full()` in `wrapper.h` is updated to match the new signature.

Callers throughout the tree are adjusted to handle the status-only return: `config.c` changes `write_section()` and `write_pair()` to return `int` and store the result in `int` locals; `entry.c` and `parallel-checkout.c` change `ssize_t wrote` to `int wrote`; `odb/streaming.c` removes the now-unneeded `wrote` variable and tests the return directly; `imap-send.c` maps success to the requested length (`n = write_in_full(...) < 0 ? -1 : len`) to preserve its existing error-checking logic; `notes-merge.c` simplifies its write loop to a single call that dies on error unless `errno` is `EPIPE`; and `t/unit-tests/u-reftable-stack.c` updates its assertion to expect 0 instead of the byte count.

The patch adds a new clar unit-test file `t/unit-tests/u-wrapper.c` (registered in both `Makefile` and `t/meson.build`) covering successful writes, empty writes, and error cases with bad file descriptors. Phillip Wood's earlier review noted that several hook-feeding paths (`refs.c:transaction_hook_feed_stdin()`, `sequencer.c:pipe_from_strbuf()`, `transport.c:pre_push_hook_feed_stdin()`) previously stored the `ssize_t` return in an `int` and tested `result < 0`, meaning the old accumulation semantics could produce false negatives; this patch fixes those latent bugs by making the status explicit.

The commit message explains that since `write_in_full()` either completes the requested count or fails, callers already know the full size was written on success, so returning only status avoids needing the total to fit in `ssize_t`. The series remains under review, with Junio C Hamano having previously approved the direction and individual patches; this v3 iteration incorporates commit-message refinements requested for earlier patches in the series.
