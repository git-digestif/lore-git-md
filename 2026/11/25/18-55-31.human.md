This is a cover letter for a three-patch bugfix series that tightens input validation in `git remote`. Harald Nordgren proposes rejecting invalid branch names in `git remote add -t`, `git remote add -m`, and `git remote set-branches` before any configuration is written, rather than letting them through and silently breaking every future fetch on that remote.

The series modifies `builtin/remote.c` to add the validation checks and extends `t/t5505-remote.sh` with test coverage for the new behavior. The patches are small and focused, adding roughly 55 lines total across the two files.

The change addresses a real footgun: today a typo or malformed branch name in these commands gets stored in the remote's configuration without complaint, only to cause failures later during fetch. Catching the problem at configuration time gives the user immediate feedback and prevents a broken remote state.

The commit message clearly states the motivation and the series includes tests, which suggests a well-crafted contribution. It does not appear to be tied to a larger ongoing effort mentioned in the cover letter, standing instead as a self-contained fix for the `remote` builtin.
