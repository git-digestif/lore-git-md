This is a bugfix for the partial-clone (promisor) subsystem, updating a previous version of the same patch. Alessio Attilio addresses a crash in `git pack-objects` where `is_not_in_promisor_pack_obj()` in `builtin/pack-objects.c` invoked `BUG()` when `odb_read_object_info_extended()` failed to read an object. In a partial clone, missing objects are expected to be absent from the local promisor pack, so the fix replaces the `BUG()` with `return 0`, causing the object to be treated as not belonging to a promisor pack and skipped during pack creation.

The v2 iteration adds `OBJECT_INFO_SKIP_FETCH_OBJECT` to the `odb_read_object_info_extended()` call so the lookup does not trigger a lazy fetch of the missing object. The test coverage has also moved from `t/t0410-partial-clone.sh` to `t/t5616-partial-clone.sh` and expanded to cover both `--unshallow` and `--deepen=1` filtered fetches of a moved ref, as well as a scenario where a subsequent fetch repacks links to promisor commits whose trees are missing. These tests exercise the exact conditions that previously hit the `BUG()` when index-pack repacks local links into a promisor pack while walking into promisor commits with absent trees.

The patch is a standalone single-patch submission (not part of a larger visible series) applying on top of commit `1630431f326e15fcde608827b5ff38422528eb59`. It is currently under review with no recorded feedback yet.
