This is patch 5/6 of a six-patch series continuing the ongoing `the_repository` removal effort in the notes subsystem. Okhuomon Ajayi's series aims to store a `struct repository *` inside `struct notes_tree` so that notes code stops relying on the global repository variable; this particular patch takes another incremental step by giving `string_list_add_refs_by_glob()` and `string_list_add_refs_from_colon_sep()` an explicit `struct repository *` first parameter. Both helpers previously walked refs in `the_repository` implicitly, and now receive the repository explicitly from their callers.

The diff touches `notes.c`, `notes.h`, and `notes-utils.c`, updating the two function signatures and threading the new parameter through their internal call chain -- `string_list_add_refs_from_colon_sep()` passes its repository down to `string_list_add_refs_by_glob()`. All current call sites in `notes_display_config()`, `load_display_notes()`, and `init_copy_notes_for_rewrite()` pass `the_repository` for now, which is expected at this stage of the series since the surrounding display-notes code has not yet been converted to carry a repository pointer.

This is a clean, mechanical refactoring with no behavior change. It sets up the next patch (6/6), which converts the `combine_notes_fn` typedef and its built-in combinators to take a repository parameter as well.
