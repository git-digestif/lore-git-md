Harald Nordgren has posted a three-patch series hardening `git remote` against invalid branch names, now complete with the arrival of patch 3/3. The problem being fixed is that `git remote add -t`, `git remote add -m`, and `git remote set-branches` previously accepted malformed branch names like `@{u}`, persisting broken refspecs to the remote's configuration that would break every subsequent fetch -- and in the case of `set-branches` without `--add`, a typo could wipe the existing fetch refspecs before writing the bad one. All three subcommands now validate branch names up front using a shared `validate_tracked_branchname()` helper in `builtin/remote.c` that checks the candidate ref against `check_refname_format()` and dies before any configuration is written; patch 3/3 extends this to the `-m` option of `git remote add`, which previously only validated after the remote had already been created and a fetch attempted. Tests in `t/t5505-remote.sh` cover all three paths, each verifying that a fatal error is produced and no remote configuration is persisted.

The series is posted as v1 and remains under review; no maintainer or reviewer feedback has been posted yet, so nothing is agreed or queued beyond the author's own submission. The base commit is 6de20f6092dcf9bdb1c8efe03db4b70c82b423dd.
