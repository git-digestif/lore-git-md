Harald Nordgren has opened a new three-patch bugfix series aimed at hardening `git remote` against invalid branch names being written to configuration. Currently, commands like `git remote add -t`, `git remote add -m`, and `git remote set-branches` silently accept malformed refspecs, which then break every subsequent fetch on that remote. The series proposes validating branch names up front so the command rejects the bad name before any configuration is persisted. The patches touch `builtin/remote.c` for the validation logic and `t/t5505-remote.sh` for test coverage, with each patch addressing one of the three subcommands in turn. This is the thread root, so review and any decision on the series are still ahead.
