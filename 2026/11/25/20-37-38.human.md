This is a maintainer review from Junio C Hamano approving Abhishek Agarwal's bugfix for `git submodule update --jobs`.

Junio confirms the bug report and the archeology: the `--jobs=0` crash and the confusing negative-value error stem from commit 51243f9f0f moving the `online_cpus()` fallback out of `run_processes_parallel()` and into individual parsers, which `module_update()` never adopted for its `--jobs` option. He walks through the code to verify that the config-based paths already validate via `parse_submodule_fetchjobs()` before the command-line option is parsed, leaving the `--jobs` value unchecked. He endorses the proposed fix -- dying on negatives and substituting `online_cpus()` for zero -- as well as the documentation wording "A value of 0 will use some reasonable default," noting it matches `git fetch --jobs`.

He raises one adjacent observation as a `#leftoverbits`: `git clone --recurse-submodules --jobs=-1` silently ignores the value (since `-1` signals "unset" in `cmd_clone()`), while `--jobs=-2` would propagate down and hit the new validation. He suggests this could be addressed later if anyone cares.

Overall assessment is positive ("Looking good. Thanks."), signaling the patch is ready from the maintainer's perspective, though no integration branch status is mentioned.
