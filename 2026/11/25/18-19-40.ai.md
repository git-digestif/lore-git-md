This is a cover letter for version 6 of a four-patch bugfix series targeting UTF-8 bounds handling in `utf8.c`, posted by Dirk Gouders with patch 1 authored by Junio C Hamano. The series fixes out-of-bounds reads in `utf8_strnwidth()` and `utf8_width()` when given a length argument, particularly when ANSI escape sequences or chopped multibyte characters fall at the boundary.

Version 6 incorporates the mechanical fixes requested in Junio C Hamano's review of v5: commit message trailers are reordered chronologically, the redundant `strbuf.h` include is removed from `t/unit-tests/u-utf8-ansi.c`, size_t return values are now asserted with `cl_assert_equal_u()` instead of `cl_assert_equal_i()`, comparisons in `display_mode_esc_sequence_len_counted()` use the `len <= i` style, and the `_counted` variant is no longer used in `strbuf_add_wrapped_text()` where NUL termination suffices. Commit messages for patches 2 through 4 are reworded, including a concrete example in 3/4 showing how an escape sequence reaching `orig + len` causes `utf8_width()` to read past the limit, and a note in 4/4 explaining why the bounds check from 3/4 remains necessary even when `utf8_width()` receives a remainder argument.

Technically, patch 1 introduces `display_mode_esc_sequence_len_counted(const char *s, size_t len)`, which scans ANSI SGR sequences using an array index `i` kept within `len` to avoid the undefined behavior of computing `s + len` when `len` is `SIZE_MAX`. Patch 2 corrects the `utf8_strnwidth()` comment to describe the string as "bounded by len" rather than NUL-terminated and fixes the documented invalid-UTF-8 return from `strlen()` to `len`. Patch 3 ensures `utf8_strnwidth()` breaks its loop when the string pointer reaches `orig + len` after skipping escape sequences. Patch 4 modifies the main loop to compute a `size_t remainder` as `orig + len - string` and pass it to `utf8_width(&string, &remainder)`, preventing reads beyond the buffer when a multibyte character is truncated by `len`.

The series remains under review and has not been merged or queued in any integration branch. Junio previously described v5 as being in "a very good shape" and "closer to the finish line"; v6 addresses the specific mechanical nits he enumerated, signaling convergence toward merge readiness. Tests are added in `t/unit-tests/u-utf8-ansi.c` and `t/unit-tests/u-utf8-width.c`, wired into both `Makefile` and `t/meson.build`, covering the counted ANSI scanner and bounded width calculations including chopped CJK sequences.

Open items include whether v6 satisfies all reviewers, and Andy Koppe's intention to update his separately proposed `make_line_colors_self_contained()` (commit `e9f88b533d`) to the new counted API. The test file carries a TODO noting that `cl_assert_equal_i()` usage should switch to `cl_assert_equal_u()` if the width functions' return types change from `int` to `size_t` in the future.
