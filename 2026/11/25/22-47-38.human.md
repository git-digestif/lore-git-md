This is a substantive review by Junio C Hamano of Alessio Attilio's v2 bugfix for `git pack-objects` crashing on missing promisor objects in partial clones. Junio is not disputing the fix itself -- replacing the `BUG()` with `return 0` and adding `OBJECT_INFO_SKIP_FETCH_OBJECT` -- but he is pushing back on the commit message, which he says fails to explain when this code path is actually triggered and why it is safe to treat an unreadable object as a promisor object without validation.

Junio points out that `is_not_in_promisor_pack_obj()` is only called when `pack-objects` runs with the undocumented `--exclude-promisor-objects-best-effort` option (introduced by c08589efdc in 2024) and only when `index-pack` is running with `--promisor`. In a non-partial-clone repository this path never activates, which is what makes the "loose assumption" relatively low-risk, but that reasoning belongs in the commit log. He also reminds the author that any in-code comment saying "assume X" should explain why the assumption is safe and what happens if it is wrong.

The underlying patch replaces a `BUG()` crash with a graceful skip when `odb_read_object_info_extended()` fails to read an object's info, which in a partial clone simply means the object is missing from the local promisor pack. The v2 iteration adds `OBJECT_INFO_SKIP_FETCH_OBJECT` to prevent the lookup from triggering a lazy fetch. Test coverage in `t/t5616-partial-clone.sh` exercises `--unshallow`, `--deepen=1`, and scenarios where subsequent fetches repack links into promisor packs while walking into commits with missing trees. No merge status is indicated; the topic remains under review.
