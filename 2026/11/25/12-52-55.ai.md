This is the final patch (5/5) of a feature series adding `--delete-integrated` to `git branch`, implementing squash-merge detection on top of the tree-based rebase detection from patch 4/5.

The patch addresses the case where upstream squash-merged a branch after also modifying the same files, so no single upstream commit contains the branch's exact tree. For each changed file, it performs a three-way text merge via `xdl_merge()` with `XDL_MERGE_ZEALOUS` between the merge-base, upstream, and branch versions; the change counts as landed only when the merge result is byte-identical to the upstream version. This deliberately ignores `.gitattributes` merge drivers (like `union`) to avoid both false positives and arbitrary command execution during cleanup. Because this reads blob contents, partial clones may download objects, unlike the blob-free rebase detection in patch 4/5.

Key symbols introduced include `enum change_state` (`CHANGE_MISSING`, `CHANGE_LANDED`, `CHANGE_NEEDS_MERGE`), the expanded `struct branch_change` now carrying `base_oid`, `upstream_oid`, and `base_mode`, and the helpers `change_state_at()`, `merge_keeps_upstream()`, and `mergeable_as_text()`. `changes_landed()` now runs in two passes: first classifying each path by exact tree-entry comparison, then invoking `merge_keeps_upstream()` for paths needing a merge check. Tests in `t/t3200-branch.sh` cover squash merges onto upstream-modified files, submodule-to-file replacements, conflicting changes, and verification that `merge=union` drivers are ignored. The commit message and documentation note this completes the series' goal of recognizing change-based integration, though rename detection and author-check mitigation (to prevent false positives when another author independently makes identical changes) remain unimplemented.
