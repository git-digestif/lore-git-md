This is patch 3/5 of Harald Nordgren's v11 series, a feature patch that extends `git branch --dry-run` to work with plain `-d` and `-D` deletion modes, not just `--delete-merged`. The patch changes the validation logic in `builtin/branch.c` from `if (dry_run && !delete_merged.nr)` to `if (dry_run && !delete && !delete_merged.nr)`, and when `--dry-run` is combined with an unsupported operation it now dies with an operation-specific message -- `--dry-run is not supported for branch renaming`, `...for branch copying`, `...for branch creation`, or a generic `...for this operation` -- rather than the previous blanket `--dry-run requires --delete-merged`. When deletion is actually requested, the code passes the new `DELETE_BRANCH_DRY_RUN` flag bit into `delete_branches()`, which prints `Would delete branch %s (was %s).` for deletable branches and reports the same errors for undeletable ones (checked-out, not fully merged) that would appear without `--dry-run`, leaving all refs untouched.

Within the broader v11 series, this patch is groundwork for the upcoming `--delete-integrated` mode introduced in patches 4/5 and 5/5. The series adds change-based detection of squash-merged and rebased branches; patch 3/5 ensures that once those modes are available, users can preview deletions with `--dry-run` across all deletion variants (`-d`, `-D`, `--delete-merged`, and later `--delete-integrated`). The v11 delta specifically addresses Junio C Hamano's request for operation-specific error messages when `--dry-run` meets non-deletion operations, replacing the generic error from v10.

Technically, the patch touches `builtin/branch.c` (17 lines changed), `Documentation/git-branch.adoc` (synopsis and `--dry-run` description updated to mention `-d`, `-D`, and `--delete-merged`), and `t/t3200-branch.sh` (54 lines of new tests). The new tests verify that `--dry-run` with `-d`/`-D` prints the correct "Would delete" output for merged and force-deletable branches, reports worktree and merge-status errors identically to non-dry-run mode, preserves all refs after running, and that creation, rename, copy, and bare `--dry-run` invocations each fail with their specific error strings.

An open philosophical point from the thread remains unresolved in this patch: Junio has argued that for a mature command like `git branch`, the error messages should signal future support (e.g., "not supported yet"), while Harald prefers neutral wording and has tagged universal `--dry-run` support for create/rename as a future `#leftoverbits` series. The code currently uses neutral "is not supported" phrasing. Additionally, the series continues to grapple with whether `branch.<name>.deleteMerged` should govern `--delete-integrated` or a separate config key, and how to mitigate "npm update" false positives where another author independently makes identical changes -- neither of which is addressed by this particular patch.
