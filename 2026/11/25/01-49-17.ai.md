This is a maintainer review and acceptance of a small refactoring patch to `imap-send.c`. Junio C Hamano replies to Harald Nordgren's patch that rewrites the header-scanning loop in the static function `has_required_headers()` -- which iterates mbox lines looking for `From:`, `Date:`, and `Subject:` headers until the empty line terminating the header block -- to make the termination condition symmetric and easier to read.

The patch changes the `while` loop condition from the old form, which advanced the `line` pointer inline via `*++line` and then checked separately for LF (`*++line != '\n'`) and CRLF (`!starts_with(line, "\r\n")`), to a new form that checks `!starts_with(line, "\n\n")` for LF and `!starts_with(line, "\n\r\n")` for CRLF up front before executing a standalone `line++` in the loop body. The diff is three insertions and one deletion confined to the loop condition.

Junio performs a substantive correctness analysis, noting that `has_required_headers()` is only called by `count_messages()` on a NUL-terminated `strbuf` holding the mbox input. He verifies that `starts_with()` cannot read past the terminating NUL because it stops at the first mismatching byte, and confirms that at EOF after a single trailing LF both checks pass and the loop body runs on the empty string, matching the old behavior before `strchr()` returns NULL and exits. He concludes the rewrite has identical behavior but is easier to reason about, states "Will queue. Thanks.", indicating acceptance for integration though not yet merged.

Key names for future reference: `imap-send.c`, `has_required_headers()` (static), `count_messages()`, `strbuf`. The change touches only the `while` loop condition in `has_required_headers()`. No behavior change; purely readability. Originated from a suggestion by Patrick Steinhardt during review of an earlier imap-send series already in `master`.
