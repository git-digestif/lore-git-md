This is the final patch (5/5) in Harald Nordgren's v11 series adding `--delete-integrated` to `git branch`, and it implements the squash-merge detection half of the feature. While patch 4/5 handled rebase-style integration using pure tree comparisons, this patch tackles the common GitHub "Squash and merge" scenario where upstream has modified the same files the branch touched before landing the changes. For each file the branch modified, the code performs a three-way `xdl_merge()` (with `XDL_MERGE_ZEALOUS`) between the merge base, the upstream version, and the branch version, treating the change as landed only when the merge result is byte-identical to the upstream version. This necessarily reads blob contents, so partial clones may download objects, unlike the blob-free rebase detection in the previous patch.

The implementation deliberately uses the built-in text merge and ignores `.gitattributes` merge drivers, both to prevent false positives from drivers like `union` that could leave the upstream version unchanged despite the branch's changes being absent, and to avoid executing arbitrary custom merge commands during branch cleanup. The patch adds `merge_keeps_upstream()`, `change_state_at()`, and a two-pass `changes_landed()` that first checks for exact tree-entry matches and then falls back to the merge check for paths that differ. Tests cover the squash-onto-modified-files case, branches whose changes did not land, submodule-to-file replacements, and confirmation that `merge=union` drivers are ignored.

This completes the v11 series, which splits strict tip-reachability (`--delete-merged`) from change-based detection (`--delete-integrated`) and extends `--dry-run` to plain `-d`/`-D` with operation-specific error messages. The series remains under review with no integration status announced. Known gaps carried over from the thread include the "npm update" false-positive scenario -- where another author independently makes identical changes -- which would require author checks or patch-ids that have not been implemented, and the lack of rename detection. The patch itself appears well-crafted with thorough test coverage and clear documentation of the limitations.
