This is a review response within the ongoing `the_repository` removal series for the notes subsystem. Okhuomon Ajayi replies to Junio C Hamano's concern that converting `note_tree_find()` to read `t->repo` might introduce a NULL-dereference where none existed before. She argues the concern does not apply: `note_tree_find()` has only one caller, `get_note()`, which replaces a NULL `t` with `&default_notes_tree` and asserts `t->initialized` before proceeding, so by the time `note_tree_find()` runs, `t` is guaranteed non-NULL and initialized. She similarly defends the other four converted functions -- `remove_note()` and `format_note()` guard NULL themselves, while `add_non_note()` and `load_subtree()` are only reached during initialization where `t` is never NULL. The exchange addresses a substantive correctness question about the safety invariants of the notes API in patch v2 2/5; the series remains under active review with the next iteration expected as v5.
