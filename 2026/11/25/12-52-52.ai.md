This is a preparatory refactoring patch (v11 2/5) in Harald Nordgren's five-patch series adding `--delete-integrated` to `git branch`. It modifies `delete_branches()` in `builtin/branch.c` to accept a new `struct strmap *landed_commits` parameter mapping branch names to the upstream commit where their changes were detected. When a branch appears in this map, `delete_branches()` skips the usual `check_branch_commit()` reachability test and reports the deletion with an extended message: `Deleted branch %s (was %s, landed as %s)` (or the `Would delete` variant under `--dry-run`). The patch introduces a static `msg_templates[2][3]` array holding the three message variants (landed, remote-tracking, local) for both dry-run and actual deletion modes. Both existing call sites currently pass `NULL` for the new parameter, so there is no behavior change yet; patches 4/5 and 5/5 of the same series will populate the map when implementing rebase-based and squash-merge-based detection. The patch is clean and well-scoped, serving purely as plumbing for the later change-detection logic.
