This is the second patch in a five-part v3 series hardening Git against Coverity-flagged integer overflows, specifically a one-line type change in the HTTP fetch path.

Patch v3 2/5 modifies `http.c` to change the local variable `posn` in `fwrite_sha1_file()` from `int` to `size_t`. The function already computes `size = eltsize * nmemb` as a `size_t`, so tracking the write position in a narrower `int` risks signed overflow and subsequent buffer under-reads if a single curl callback ever delivers more than `INT_MAX` bytes. While curl currently sends data in smaller chunks making the bug latent, aligning the accumulator type with the buffer length eliminates the theoretical defect. The commit message incorporates Junio C Hamano's rewritten explanation clarifying that `posn` resets to zero on every callback invocation, meaning overflow would require a single call exceeding `INT_MAX` bytes.

The thread context shows this patch was previously approved by Junio in v2 ("Looking good") and confirmed correct by Patrick Steinhardt. An alternative suggestion from Simon Richter to use `off_t` instead of `size_t` was rejected in favor of matching the existing `size_t` type of the `size` parameter. The series remains under review awaiting Junio's final assessment of v3 before queuing.
