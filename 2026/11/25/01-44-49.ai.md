This is a cover letter for the second iteration of a feature patch series. Adithya Chakilam sends `[PATCH v2 0/2]` introducing a new `--filter-to-loose=<directory>` option for `git repack`, which writes objects excluded by `--filter` directly as loose objects into a specified object directory instead of into an intermediate packfile.

The series addresses interoperability with key-value object stores that manage Git objects individually, avoiding the need to unpack a packfile after using `--filter-to`. When `--filter-to-loose` is given, `git repack` streams the filtered pack through `unpack-objects`, writing excluded objects as loose files in the target directory. The first patch implements this for objects already stored in packs, while the second extends it to also copy loose objects that the filter excludes, removing the source copies when `-d` is specified. The option cannot be combined with `--filter-to` or `--max-pack-size`, and the destination directory must already exist.

Version 2 incorporates fixes for three issues raised by Junio C Hamano during review of v1: the code now dies early if the target directory does not exist rather than failing later, the option parsing uses `OPT_FILENAME` instead of `OPT_STRING` so relative paths resolve correctly when `git repack` runs from a subdirectory, and a double-close bug in `repack-filtered.c` is fixed by removing a manual `close()` call since `start_command()` already handles cleanup on failure. The range-diff shows these changes alongside expanded test coverage in `t/t7700-repack.sh`, including tests for the non-existent directory error, subdirectory relative path resolution, and failure recovery that leaves source packs intact.

The implementation touches `builtin/repack.c`, `repack-filtered.c`, `repack.h`, `Documentation/git-repack.adoc`, and `t/t7700-repack.sh`. Tests verify that objects already present in the destination are not rewritten, that all objects are written before any existing pack is removed, and that failure to write leaves the source repository unmodified. The commit messages are clear and the motivation is well-stated, though the series remains under review with no maintainer integration status reported.
