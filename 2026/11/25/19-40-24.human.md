This is a bugfix for `git pack-objects` in partial-clone scenarios.

The patch changes `is_not_in_promisor_pack_obj()` in `builtin/pack-objects.c` so that when `odb_read_object_info_extended()` fails to read an object's info, the function returns 0 (skip) instead of hitting a `BUG()`. In a partial clone, objects missing from the promisor pack are expected to be absent, and since such an object cannot be included in the pack being written, skipping it is the correct behavior rather than crashing.

The commit adds a regression test to `t/t0410-partial-clone.sh` that reproduces the crash scenario: a client with a shallow, tree-filtered fetch attempts `git fetch --unshallow --filter=tree:0` after the remote has advanced with new commits. This exercises the code path where `pack-objects` encounters objects that are referenced but not locally present.

The change is small and focused, with a clear commit message explaining why missing promisor objects should be tolerated rather than treated as an internal error. The inclusion of a targeted test case suggests the author verified the fix against the reported failure mode, making this look like a well-crafted, ready-to-review bugfix.
