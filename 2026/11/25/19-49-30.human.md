This is a bugfix for `git pack-objects` in the partial-clone subsystem, now in its second iteration. Alessio Attilio addresses a crash where `is_not_in_promisor_pack_obj()` in `builtin/pack-objects.c` invoked `BUG()` when `odb_read_object_info_extended()` failed to read an object. In a partial clone, objects absent from the local promisor pack are expected to be missing, so treating this as a fatal error was incorrect.

The fix replaces the `BUG()` with a `return 0`, causing the object to be skipped during pack creation rather than aborting the process. The v2 revision also passes `OBJECT_INFO_SKIP_FETCH_OBJECT` explicitly to the object-info lookup, preventing the check from triggering an unintended lazy fetch of the missing object.

The accompanying tests have moved from `t/t0410-partial-clone.sh` to `t/t5616-partial-clone.sh` and now cover a broader set of scenarios: filtered `--unshallow` and `--deepen=1` fetches where the remote has advanced, plus a subsequent fetch that causes index-pack to repack local links into a promisor pack while walking into promisor commits whose trees are missing. Each test verifies the ref resolves correctly and `git fsck` passes.

The patch applies cleanly on top of commit 1630431f326e and appears well-motivated, with the commit message clearly explaining why a missing object should not be fatal in this context. The test coverage looks thorough for the specific crash scenario described, though no review feedback has been recorded yet.
