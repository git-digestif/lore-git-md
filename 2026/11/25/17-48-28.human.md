This is the cover letter for v5 of a five-patch series that hardens Git's HTTP transport against transient server failures. Ravi Mistry tackles four specific gaps: an off-by-one error in the retry counter, the absence of exponential backoff when a server omits the `Retry-After` header, the inability to retry transient 5xx errors such as 502, 503, and 504, and the lack of retry support for HTTP POST requests used during fetch, clone, and partial-clone blob downloads. The series modifies `http.c`, `remote-curl.c`, documentation, and the test suite to introduce configurable retry status codes, backoff delays that double on each attempt, and safe retries for read-only POST operations.

Compared to v4, this iteration is a targeted refinement. Patches 1, 2, and 5 are unchanged, while patch 3 now explicitly documents that an empty `http.retryStatusCodes` disables all retries rather than restoring the default, and that listing 401 or 404 has no effect because those codes are handled earlier in the code path; a new test covers the empty-string case. Patch 4 clears the slot results structure before each retry attempt in `post_rpc()` and `probe_rpc()`, ensuring that a request which fails to start does not cause error messages to report a stale HTTP status from the previous attempt. These changes directly address the edge-case questions Junio C Hamano raised during his review of v4.

The series has received strong maintainer endorsement and appears well-crafted. Junio approved the first four patches individually in v4 and described the overall cover letter as showing little left to fix, noting that substantive feedback from Patrick Steinhardt had already been incorporated. The design keeps 429 as the default retryable code while allowing environments to opt into 5xx retries via `http.retryStatusCodes`, and it restricts POST retries to read-only services like `git-upload-pack` and `git-upload-archive` while deliberately excluding `git-receive-pack` (push) to avoid the risk of duplicate processing on the remote. With the remaining review comments now addressed here, the series looks ready for integration pending Junio's final decision on the complete v5 set.
