This is a substantive review from Junio C Hamano on the v2 bugfix from Alessio Attilio that prevents `git pack-objects` from crashing via `BUG()` when it encounters missing objects in a partial clone. Junio's feedback centers on the commit message: he asks the author to step back and describe the end-user scenario that triggers the code path -- for example, running `git repack` in a partial clone, which may attempt to fetch objects from the promisor remote while checking if they need packing -- and to explain why it is safe to treat an unreadable object as a promisor object without validating that assumption first.

Junio provides important technical context that should anchor future discussion: `is_not_in_promisor_pack_obj()` in `builtin/pack-objects.c` is only reached when pack-objects is invoked with the undocumented `--exclude-promisor-objects-best-effort` option, which was introduced by commit `c08589efdc` ("index-pack: repack local links into promisor packs", 2024-11-01). That option is only passed when index-pack itself runs with `--promisor`, meaning the loose assumption only surfaces in lazy-clone (partial clone) repositories and cannot affect ordinary clones, which is what makes the change lower-risk. He suggests documenting this scoping in the commit log.

The actual code change under review replaces the `BUG("should_include_obj should only be called on existing objects")` with a `return 0` when `odb_read_object_info_extended()` fails, and adds the `OBJECT_INFO_SKIP_FETCH_OBJECT` flag to that call so the lookup does not trigger a lazy fetch of the missing object. The effect is that objects absent from the local promisor pack are silently skipped rather than crashing the process. Junio also reminds the author that whenever an in-code comment says "assume X", it must explain why the assumption is safe and what the consequences would be if it proved incorrect.

The patch remains under review with no recorded Acked-by or Reviewed-by trailers yet. Test coverage lives in `t/t5616-partial-clone.sh` and exercises filtered `--unshallow` and `--deepen=1` fetches plus a subsequent fetch that repacks links to promisor commits whose trees are missing.
