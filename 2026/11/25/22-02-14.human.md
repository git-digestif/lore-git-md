This is the sixth and final patch in the fifth iteration of a series refactoring the notes subsystem as part of the ongoing `the_repository` removal effort. Okhuomon Ajayi updates the `combine_notes_fn` callback type and all four built-in combinators -- `combine_notes_concatenate()`, `combine_notes_overwrite()`, `combine_notes_ignore()`, and `combine_notes_cat_sort_uniq()` -- to accept an explicit `struct repository *` as their first parameter. The sole caller, `note_tree_insert()`, now passes `t->repo` instead of letting the callbacks fall back to the global `the_repository`, which matters when a notes tree belongs to a repository other than the default one. The helper `string_list_add_note_lines()` is updated accordingly, and all object reads and writes in these functions now use the passed repository's object database.

Within the broader v5 series, this patch closes out the conversion of the combine-notes path: earlier patches in the series added the `repo` field to `struct notes_tree`, introduced the `notes_tree_or_default()` helper to fix a NULL-dereference in `copy_note()`, and threaded the repository through the read, write, prune, and ref-glob helpers. With this final piece, every combine callback operates on the correct repository instance. The change is purely mechanical plumbing with no user-visible behavior change, and it looks cleanly executed -- the commit message is concise and the diff is tight, touching only `notes.c` and `notes.h`.
