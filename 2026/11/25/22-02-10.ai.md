This is patch 2/6 of a six-patch series in the ongoing `the_repository` removal effort, specifically refactoring the notes subsystem to eliminate implicit reliance on the global repository. The patch adds a `struct repository *repo` field to `struct notes_tree` in `notes.h` and stores the repository pointer during initialization, establishing the foundation that later patches in the series use to replace `the_repository` references with `t->repo`.

The patch renames two public API functions because all call sites change anyway. `init_notes()` becomes `notes_tree_init(struct notes_tree *t, struct repository *r, const char *notes_ref, combine_notes_fn combine_notes, int flags)`, now taking the tree first and the repository second, and saves `r` into `t->repo` before proceeding with initialization. Similarly, `load_notes_trees()` becomes `notes_tree_load(struct repository *r, struct string_list *refs, int flags)`, taking the repository as its first parameter. The commit also adds doc comments for the `r` and `flags` parameters of `notes_tree_init()` that were missing in earlier iterations.

Call sites updated include `builtin/notes.c` (three locations passing `the_repository` for now), `notes-cache.c` where `notes_cache_init()` passes the repository it was given, `notes-utils.c` where `init_copy_notes_for_rewrite()` passes `the_repository`, and `notes.c` itself where `load_display_notes()` and the lazy-init path in `format_note()` pass `the_repository`. The diff touches `notes.c`, `notes.h`, `notes-cache.c`, `notes-utils.c`, and `builtin/notes.c`.

This patch is the structural prerequisite for patches 3/6 through 6/6 in the same series, which convert internal helpers like `note_tree_find()`, `load_subtree()`, `write_notes_tree()`, and the combine-notes functions to dereference `t->repo` instead of using `the_repository` or `the_hash_algo`. By storing the repository on the tree at init time, the series removes the root cause that previously required `USE_THE_REPOSITORY_VARIABLE` guards in the notes code. The series remains under active review with no merge status indicated.
