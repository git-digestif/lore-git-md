This is a **refactoring** patch, the fourth of seven in Harald Nordgren's v16 series on matching-inspired fetch mode. It extracts the logic that decides whether the current branch's upstream lives on a given remote into a reusable helper, `collect_upstream_from_remote()`, placed in `remote.c` and declared in `remote.h`. The new function takes a `struct repository *`, a `const struct remote *`, a `const char *refname` (where NULL means the current branch), and a `struct strvec *tracked` to append matching upstream source refs to. It checks `branch_has_merge_config()` and that `branch->remote_name` matches the remote's name, then pushes each `branch->merge[i]->src` into the vector.

In `builtin/fetch.c`, the inline block in `do_fetch()` that performed this check for the current branch only is replaced by a call to the new helper with `refname = NULL`, preserving existing behavior while referencing commit 49ca2fba39 (2022) for the original "fetch the current branch's upstream even when the configured refspec does not cover it" logic. The extraction prepares for patch 5/7, which will need to call this helper for every local branch (not just the current one) to implement `remote.<name>.fetchUpstreams`. Files touched: `builtin/fetch.c`, `remote.c`, `remote.h`.
