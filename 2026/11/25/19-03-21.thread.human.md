Harald Nordgren has sent a patch proposing that the revision range argument for `git history squash` become optional, defaulting to the range from the merge base of `HEAD` and `@{upstream}` up to `HEAD` when no range is given. This restores a default that existed when the functionality lived in `git rebase --squash` but was lost when it moved into the new `git history` command. The implementation adds a `default_squash_range()` helper in `builtin/history.c`, refactors the command-line parsing to use a `strvec`, and updates both the usage string and `Documentation/git-history.adoc` to show `[<revision-range>]` as optional; if no upstream is configured the command errors out. Tests in `t/t3455-history-squash.sh` were adjusted to expect failure only when no upstream exists and to verify that, with an upstream set, running `git history squash --no-edit` without arguments correctly folds the local commits. The patch is presented as well-scoped and ready for review, with no decisions or merge status yet recorded.
