This is a hardening patch, specifically the fourth of five in Johannes Schindelin's v3 series addressing integer overflows flagged by Coverity across Git's I/O wrapper layer. The patch introduces a new `read_in_full_or_error()` function that returns an `int` (0 on success, -1 with `errno` set on failure) for callers that only need a success or failure signal rather than the byte count, sidestepping the `ssize_t` range limitation that occurs when files exceed what that signed type can represent. Internally, both the new function and the existing `read_in_full()` now share a static helper `read_in_full_1()`, with `read_in_full()` adding a `BUG()` guard that aborts if the requested `count` exceeds the maximum `ssize_t` value, treating such requests as programming errors rather than silent failures.

The patch migrates six call sites to `read_in_full_or_error()`: `builtin/blame.c`, `combine-diff.c`, `dir.c`, `grep.c`, `refs/packed-backend.c`, and `strbuf.c`. In `strbuf.c`, the read loop now clamps `want` to `SSIZE_MAX` before calling `read_in_full()`, ensuring the byte-count-returning variant is only used when the size is representable. The remaining callers of `read_in_full()` that still need the actual byte count are left unchanged but are now protected by the `BUG()` assertion against oversized requests.

Test coverage expands in `t/unit-tests/u-wrapper.c` with new clar-based tests for both functions: `read_in_full_or_error()` is tested for successful reads, empty reads, short reads (premature EOF mapping to `EIO`), and bad file descriptors, while `read_in_full()` gets corresponding tests verifying it returns the short count on premature EOF, handles empty reads, and returns -1 on error.

Within the broader series context, this patch resolves the read-side counterpart to the write-side changes in patch 3/5. Johannes Schindelin has incorporated Junio C Hamano's earlier request to document in the commit message that an oversized `count` triggers a `BUG()` abort, and Phillip Wood's review had previously identified that hook-feeding paths in `refs.c`, `sequencer.c`, and `transport.c` stored the old `ssize_t` return in `int` locals, meaning this type change also fixes latent overflow bugs in those paths. The series remains under review pending Junio's final assessment of v3.
