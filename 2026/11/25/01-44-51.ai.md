This is the second patch in a two-patch feature series (v2) that adds a `--filter-to-loose=<directory>` option to `git repack`. While the first patch handles objects already stored in packfiles by streaming them through `unpack-objects`, this patch extends the feature to loose objects in the source repository that the filter excludes. It introduces two new functions in `repack-filtered.c`: `move_loose_filtered_objects()`, which collects all loose object IDs via `for_each_loose_file_in_source`, applies the filter using `list_objects_filter__filter_oidset`, and copies each excluded object to the destination directory using a temporary file and `finalize_object_file()` for atomicity, and `remove_moved_loose_objects()`, which deletes the source copies when `-d` is specified. The implementation only activates for the `blob:limit` filter choice and skips objects already present in the destination to avoid rewriting.

The patch wires these functions into `builtin/repack.c`: after `write_filtered_pack()` completes, `move_loose_filtered_objects()` runs if `--filter-to-loose` is set, populating a `struct oidset moved_loose` that tracks which objects were successfully copied. Later, after `prune_packed_objects()` runs, `remove_moved_loose_objects()` unlinks the source copies of those tracked objects. Safety measures include checking `access(dst, F_OK)` before copying, creating leading directories with `safe_create_leading_directories()`, and using a `.tmp-<pid>` file that is unlinked on failure to prevent corruption. The header `repack.h` declares both functions, and `Documentation/git-repack.adoc` notes that loose objects excluded by the filter are also copied, with source removal under `-d`.

Tests in `t/t7700-repack.sh` verify that loose filtered blobs are copied to the destination, that `-d` removes the source copy while leaving the destination intact (verified via alternates), that an identical existing object in the destination is left untouched (confirmed by comparing inodes before and after), and that failure to copy a loose object leaves the source repository's packs and loose objects intact with no temporary file leftovers. The patch remains under review with no integration status reported.
