This is a refactoring patch -- specifically patch 2/6 in Okhuomon Ajayi's v5 series to remove implicit uses of the `the_repository` global from the notes subsystem. The series relabels itself v5 to correct a versioning collision flagged by Junio C Hamano, and this patch lays the structural foundation that later patches build on.

The patch adds a `struct repository *repo` field to `struct notes_tree` and renames two core initialization functions: `init_notes()` becomes `notes_tree_init()`, now taking the tree first and the repository second, while `load_notes_trees()` becomes `notes_tree_load()`, taking the repository as its first parameter. `notes_tree_init()` saves the repository pointer into `t->repo`, and all call sites in `builtin/notes.c`, `notes-cache.c`, and `notes-utils.c` are updated to pass either an explicit repository or `the_repository` temporarily. The patch also adds doc comments for the `r` and `flags` parameters that earlier iterations missed.

This change is the linchpin of the series: by storing the repository on the tree itself, later patches can thread `t->repo` through the read, write, prune, and combine paths instead of falling back to the global. The commit message is matter-of-fact and the diff is mechanical but careful, touching five files with 38 insertions and 21 deletions. It directly addresses Patrick Steinhardt's architectural concern about removing the root cause of `the_repository` dependency rather than papering over it with `USE_THE_REPOSITORY_VARIABLE` guards.

The patch fits squarely within the ongoing `the_repository` removal effort and follows the pattern established in patch 1/6, which introduced the `notes_tree_or_default()` helper that this and later patches rely on for NULL-safe entry points. The work is clearly well-structured and the commit message explains the renames as justified because every caller changes anyway.
