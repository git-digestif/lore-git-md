This is a bugfix for the sequencer subsystem, specifically the first patch of a two-patch v2 series (1/2) from Wonseok Oh addressing `git cherry-pick` behavior on unborn (orphan) branches.

The patch fixes `sequencer_pick_revisions()` in `sequencer.c`, where a failure to resolve HEAD via `repo_get_oid()` on an unborn branch previously left the local `oid` variable uninitialized; this garbage value was then passed to `save_head()` and written to `.git/sequencer/head`, causing `git cherry-pick --abort` to fail with "Could not parse object" or potentially move the branch to an arbitrary commit instead of producing the intended "cannot abort from a branch yet to be born" error from `sequencer_rollback()`. The fix restructures the error handling so that when `repo_get_oid()` fails, the code either returns the existing "can't revert as initial commit" error for `REPLAY_REVERT` actions or clears `oid` to the null OID via `oidclr(&oid, r->hash_algo)` for cherry-pick, ensuring the null OID (`$ZERO_OID`) is stored and the unborn-branch case is correctly detected later. The commit message traces the regression to commit `0f974e2124` (2016), which first allowed picking onto unborn branches.

The patch also adds a regression test to `t/t3510-cherry-pick-sequence.sh` that creates an orphan branch, attempts to cherry-pick two commits (where the first succeeds and births HEAD but the second fails), then verifies that `.git/sequencer/head` contains `$ZERO_OID`, that `git cherry-pick --abort` fails with the exact message "cannot abort from a branch yet to be born", and that HEAD remains unchanged. This is v2 of the series, incorporating prior review feedback from Phillip Wood and Junio C Hamano regarding commit message wording and test robustness; the companion patch 2/2 (not included here) addresses the related `.git/sequencer/abort-safety` file to store the null OID there as well for consistency.
