This is a reply in the review thread for patch 3/5 of Johannes Schindelin's v2 series hardening Git against Coverity-flagged integer overflows. The email itself is a brief acknowledgment: Schindelin confirms he has adjusted the callers of `write_in_full()` in response to Phillip Wood's detailed review.

The patch changes `write_in_full()` (and `write_str_in_full()`) to return `int` -- 0 on success, -1 with `errno` set on failure -- instead of returning the accumulated byte count as `ssize_t`. This eliminates the risk of the byte counter itself overflowing when writing very large buffers. Wood's review traced the impact across multiple call sites and found that three hook-feeding paths (`refs.c`, `sequencer.c`, `transport.c`) had been storing the old `ssize_t` return in an `int` and checking for negative values, meaning the patch fixes latent bugs there, not just a type mismatch. Other callers needed only minor type adjustments. The series as a whole has received maintainer approval from Junio C Hamano as a clear improvement over v1, and this particular patch now appears settled pending only commit-message polish.
