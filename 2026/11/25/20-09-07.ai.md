This is a review-discussion email in the ongoing `GIT_COMMENT_STRING` feature thread, where Kristoffer Haugsbakk and Phillip Wood converge on documentation wording for the new `git var` variable.

The exchange resolves an earlier disagreement over whether `Documentation/git-var.adoc` should cross-reference both `core.commentChar` and `core.commentString` in `git-config(1)`. Haugsbakk initially argued the concrete config names link the concepts unambiguously, but after Wood noted that the config docs would not add useful information, Haugsbakk conceded the link is not worth the space. They settle on the compromise phrasing "as set by `core.commentString`" for the `GIT_COMMENT_STRING` entry, which Wood notes is more accurate than promising readers additional detail in the config documentation. Haugsbakk also expresses a preference for the verbose style used by `GIT_EDITOR` and `GIT_PAGER` over the terse style of `GIT_DEFAULT_BRANCH`, and approves of Wood's decision to instead add a note to the `core.commentString` documentation in `Documentation/git-config.adoc` pointing readers to `git var GIT_COMMENT_STRING`.

For future reference, the patch touches `builtin/var.c` (registering `GIT_COMMENT_STRING` in the `git_vars[]` table via a `comment_string()` helper returning `xstrdup(comment_line_str)`), `Documentation/git-var.adoc`, `Documentation/git-config.adoc`, and `t/t0007-git-var.sh`. The discussion indicates no blocking objections; the topic remains under review with the documentation wording now agreed upon.
