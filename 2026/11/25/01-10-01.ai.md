This is **bugfix patch v4 1/2** in a two-patch series targeting `apply.c`, fixing a deterministic crash in `git apply --check` where the assertion `patch->is_new <= 0` in `check_preimage()` fires on malformed patch headers. The series is based on commit `77904e546de3bd940621092ecec47a88d0cede5d`, targets `maint`, and merges cleanly with `master`, `next`, and `seen`.

This first patch changes `find_header()` in `apply.c` to reject an empty `diff --git` header immediately rather than skipping it. When a `diff --git` line is followed by any line that is not a git extended header (including a blank line, indented header, another `diff --git`, or arbitrary text), the function now emits `error(_("corrupt patch: empty \"diff --git\" header at %s:%d"), state->patch_input_file, linenr)` and returns `-128`. This addresses the root cause where `parse_git_diff_header()` would set `patch->old_name` and `patch->new_name` from the `diff --git` line but then return early on the next non-header line, leaving stale state that caused the assertion failure downstream when `parse_traditional_patch()` later set `is_new` for `--- /dev/null` without clearing `old_name`.

The change also rejects `diff --git` lines followed directly by another `diff --git` line, which were previously skipped, and sections followed by non-git patch text that previously applied. Text between complete patches continues to be ignored unless a line starts with `diff --git `. The rationale, endorsed by Junio C Hamano, is that modern Git never generates bare `diff --git` lines (historically only in 2005 before commit `ec1fcc16af` added the `index` line), so an empty section indicates a corrupt patch.

The patch adds comprehensive tests to the new file `t/t4133-apply-filenames.sh`, covering blank lines after `diff --git`, indented `new file mode` lines, deletions with blank lines, modifications with blank lines, text before and after the empty header, and consecutive `diff --git` lines. Tests verify rejection under both `git apply --check` and actual application, including `git apply -R`, and confirm the error message references the correct file and line number.

The companion patch v4 2/2 (not shown here but part of the same series) modifies `parse_git_diff_header()` to reject new files where a `---` line appears before `new file mode`, and deleted files where a `+++` line appears before `deleted file mode`. Both patches were reviewed substantively by Phillip Wood and endorsed by Junio C Hamano, with the series converging on this stricter validation approach.
