This is patch 3/6 in Okhuomon Ajayi's v5 series refactoring the notes subsystem as part of the ongoing `the_repository` removal effort. The patch converts five functions in `notes.c` -- `note_tree_find()`, `add_non_note()`, `load_subtree()`, `remove_note()`, and `format_note()` -- to read the hash algorithm and object database from `t->repo` instead of the global `the_repository` and `the_hash_algo`.

The commit message carefully explains why this is safe even though some of these helpers do not check for a NULL tree pointer themselves: the public entry points like `add_note()`, `remove_note()`, and `get_note()` substitute the default notes tree and assert initialization before calling these internals, and `format_note()` performs its own NULL swap and lazy initialization. The author notes that `copy_note()` is the one public function missing this guard, which the following patch addresses.

This patch builds directly on patch 2/6, which added the `repo` field to `struct notes_tree` and renamed the initialization functions. By threading the repository through these read paths, the series eliminates implicit global state from the core notes-reading machinery while leaving `USE_THE_REPOSITORY_VARIABLE` in place only for functions still tied to the global default tree. The series remains under review, with Patrick Steinhardt's confirmation on the remaining guard scope still pending.
