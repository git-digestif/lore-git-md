This is a feature patch, specifically the sixth of seven in Harald Nordgren's v16 series introducing limited-fetch semantics for shallow repositories. It adds a `--limited-fetch` / `--no-limited-fetch` option to `git remote add` in `builtin/remote.c`. When `--limited-fetch` is given (and neither `-t`/`--track` nor `--mirror` is present), the command skips writing the traditional wildcard `remote.<name>.fetch` refspec and instead sets `remote.<name>.fetchRefmap` to `+refs/heads/*:refs/remotes/<name>/*` and `remote.<name>.fetchUpstreams` to `true`, relying on the machinery introduced in patches 3/7 and 5/7 to make refspec-less `git fetch <name>` pull only locally tracked upstream branches. The patch enforces mutual exclusion with `-t`/`--track` and `--mirror` via explicit `die()` checks, and the unspecified case defaults to `-1` so patch 7/7 can later decide shallow-repository defaults. Tests in `t/t5505-remote.sh` confirm the new config keys are written correctly in a full (non-shallow) clone and that `--limited-fetch -t` is rejected. Documentation in `Documentation/git-remote.adoc` describes the new flag and its effect.
