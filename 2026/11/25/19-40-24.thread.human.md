Alessio Attilio has posted version 2 of a single-patch fix for a crash in `git pack-objects` that occurs in partial clones when the code hits a `BUG()` while checking whether an object belongs to a promisor pack. The fix replaces the crash with a `return 0` and adds `OBJECT_INFO_SKIP_FETCH_OBJECT` to avoid triggering a lazy fetch of missing objects, and the accompanying test in `t/t5616-partial-clone.sh` now covers `--unshallow`, `--deepen=1`, and a subsequent fetch that repacks links to promisor commits with missing trees.

Junio C Hamano has reviewed v2 and focused his feedback on the commit message rather than the code itself. He asks the author to describe the end-user scenario that triggers the path -- for example, running `git repack` in a partial clone where the check might otherwise trigger a fetch from the promisor remote -- and to justify why it is safe to treat an unreadable object as a promisor object without further validation. Junio also clarified that the affected function is only reachable when pack-objects runs with the undocumented `--exclude-promisor-objects-best-effort` option, which was introduced by commit `c08589efdc` and is passed only when index-pack runs with `--promisor`; this means the change only affects lazy-clone repositories and cannot impact ordinary clones, a scoping that should be documented in the commit log. He additionally reminded the author that any in-code comment stating an assumption must explain why that assumption is safe and what would happen if it proved wrong.

The patch remains under review with no recorded Reviewed-by or Acked-by trailers yet; Alessio Attilio is expected to address Junio's commit-message feedback in a potential v3.
