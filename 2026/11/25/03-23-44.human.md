This is the second patch in a two-part bugfix series addressing `git cherry-pick` behavior on unborn (orphan) branches. While the first patch ensures `.git/sequencer/head` records the null OID when HEAD does not exist, this patch fixes the companion `.git/sequencer/abort-safety` file to do the same rather than writing an empty file.

The change modifies `update_abort_safety_file()` in `sequencer.c` so that when resolving HEAD fails, the code clears the OID to the null value before writing it, instead of writing an empty string. This keeps both sequencer state files representing an unborn branch consistently and maintains backwards compatibility with older Git versions that expect the null OID format in these files.

The patch adds a regression test in `t/t3510-cherry-pick-sequence.sh` that verifies both `.git/sequencer/head` and `.git/sequencer/abort-safety` contain `$ZERO_OID` after a failed cherry-pick sequence on an orphan branch. The contribution looks tidy and focused, with the commit message crediting Phillip Wood for the suggestion and the test directly exercising the new behavior.
