This is a feature patch series (v2, cover letter for two patches) adding a new `--filter-to-loose=<directory>` option to `git repack`.

The series introduces a way to write objects excluded by `--filter` directly as loose objects into a specified object directory, rather than packing them into an intermediate packfile. This targets workflows where a key-value object store or similar system needs individual loose objects, avoiding the extra unpack step that `--filter-to` requires. The author, Adithya Chakilam, is responding to review feedback from v1: the directory now must already exist (erroring early otherwise), the option uses `OPT_FILENAME` so relative paths resolve correctly when run from subdirectories, and a double-close bug in `repack-filtered.c` has been fixed.

The first patch implements the core mechanism for objects already in packs, streaming the filtered pack into `unpack-objects` to write loose objects directly to the target directory, skipping any that already exist there. The second patch extends this to loose objects in the source repository that the filter excludes, copying them to the destination and removing the source copies when `-d` is given. The option cannot be combined with `--filter-to` or `--max-pack-size`.

Test coverage in `t/t7700-repack.sh` is extensive, including the new error cases (non-existent directory, incompatible options), relative path resolution from a subdirectory, failure recovery that leaves source packs intact, and handling of loose objects. Documentation in `Documentation/git-repack.adoc` is updated accordingly.
