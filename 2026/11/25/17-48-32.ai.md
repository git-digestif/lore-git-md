This is patch 4/5 in Ravi Mistry's five-part v5 series hardening Git's HTTP transport error handling, specifically extending retry logic to cover HTTP POST requests used by the smart protocol. The patch modifies `remote-curl.c` to add a retry loop in `post_rpc()` (and the probe path for large requests) that consults the new `http_retry_wait()` helper extracted into `http.c` and declared in `http.h`, allowing read-only RPC services to sleep and retry transient failures using the same exponential backoff previously available only to GET requests.

The retry behavior is deliberately restricted: the new `can_retry_rpc()` function whitelists only `git-upload-pack` and `git-upload-archive` (covering fetch, clone, and partial-clone promisor blob fetches) and explicitly excludes `git-receive-pack` to avoid the risk of duplicate processing when retrying a non-idempotent push after a 502 or 504. Error reporting is deferred via the new `report_rpc_error()` function, which emits the "RPC failed; HTTP <code>" message only after retries are exhausted or for non-retryable failures, rather than immediately inside the slot runner. Two correctness fixes accompany the feature: the `struct slot_results results` variable is now cleared with `memset` before each `run_one_slot()` call in both `post_rpc()` and `probe_rpc()` to prevent stale HTTP status or Retry-After values from a failed previous attempt leaking into error reporting, and the `Content-Encoding: gzip` header is re-appended when retrying a compressed request body.

Test coverage in `t/t5584-http-429-retry.sh` verifies that protocol v2 `git-upload-pack` POSTs retry on 429 and configured 502s with correct warning messages, that partial-clone lazy blob fetches retry transient 502s, that gzipped POSTs preserve the `Content-Encoding: gzip` header across retries (checked via `GIT_TRACE_CURL`), and that `git push` (`git-receive-pack`) is never retried on 429 or 502. The test helper `t/lib-httpd/http-429.sh` gains `*-post-only*` URL patterns that fail only on POST requests and drains request bodies before returning synthetic errors to avoid Apache connection resets. Documentation in `Documentation/config/http.adoc` updates `http.maxRetries` to note that retries now apply to read-only smart-HTTP POST requests in addition to GETs.
