This is a feature patch -- the third of five in Ravi Mistry's v5 series hardening Git's HTTP transport against transient failures. It introduces the `http.retryStatusCodes` configuration key (and matching `GIT_HTTP_RETRY_STATUS_CODES` environment variable), allowing users to list HTTP status codes beyond the default 429 that should trigger retries up to `http.maxRetries` times. The patch replaces the hardcoded 429 check in `handle_curl_result()` with a new `is_retryable_http_code()` helper that parses the comma- or whitespace-separated list, constraining codes to the 400..599 range.

The commit message and documentation frame non-429 codes (such as 502, 503, and 504) as temporary workarounds for misbehaving proxies or overloaded providers, since well-behaved services should return 429 when rate-limiting. The docs explicitly note that an empty `http.retryStatusCodes` value disables all retries rather than restoring the default, and that 401 and 404 can never be retried because `handle_curl_result()` handles them before consulting the retryable list -- two edge cases Junio C Hamano raised during review that this v5 iteration addresses. When a non-429 code is retried, the warning message now shows the numeric status (e.g., "HTTP 502, waiting N seconds before retry") instead of the generic "rate limited" wording, and exhausted retries on non-429 codes return `HTTP_ERROR` rather than `HTTP_RATE_LIMITED`.

The patch extends `struct http_get_options` with an `http_code` field so the retry loop can distinguish the specific status, and updates the `http.retryAfter`, `http.maxRetries`, and `http.maxRetryTime` documentation to reference the new option. Test coverage in `t/t5584-http-429-retry.sh` verifies that 502/503/504 are not retried by default, that configured codes are retried with appropriate messages, that `Retry-After` headers are honored for non-429 codes, that exhausted retries report the actual error code, and that both the environment variable and `http.<url>.retryStatusCodes` urlmatch work correctly; a new test also confirms the empty-string configuration disables retries. The test helper `t/lib-httpd/http-429.sh` gains URL patterns to emit 502/503/504 status lines.

Patches 1/5, 2/5, and 5/5 are unchanged from v4; this patch and patch 4/5 contain the only v5-specific updates, resolving the last open code-level questions. Junio has previously approved patches 1-4 with "Looking good" or "Overall looking very good", noting that his sign-off is procedural given the substantive technical review from Patrick Steinhardt was incorporated earlier. The series remains under review awaiting a final integration decision.
