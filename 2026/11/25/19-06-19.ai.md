This is patch 2/7 of Harald Nordgren's v16 series implementing a matching-inspired fetch mode for shallow repositories. The patch modifies `builtin/fetch.c` so that `--refmap` applies to the configured `remote.<name>.fetch` refspecs when no refspecs are given on the command line, rather than dying with an error. Previously, `git fetch --refmap=<map> <remote>` without command-line refspecs was rejected; now the configured refspecs still determine what is fetched, but the results are stored through the `--refmap` mapping instead of at the destinations specified in `remote.<name>.fetch`.

The implementation introduces a new helper `drop_destinations()` in `builtin/fetch.c` that clears `peer_ref` (the destination) on each ref in the ref map, making them destination-less before applying the refmap via `map_refs_without_dst()`. In `get_ref_map()`, the fatal error for `--refmap` without command-line refspecs is removed and replaced with logic that calls `drop_destinations()` and `map_refs_without_dst()` when `refmap.nr` is non-zero, setting `*autotags = 1` if any refs result from the mapping. The error is preserved only for the case where there are no refspecs to fetch at all, such as fetching from a bare URL with no configured `remote.<name>.fetch` entries.

Behavioral semantics are carefully defined around tags and pruning. Tags are followed when fetched refs end up stored somewhere through the refmap, but `--refmap=""` stores nothing and follows no tags. When `--prune` is used with `--refmap` and no command-line refspecs, `do_fetch()` skips pruning the configured `remote.<name>.fetch` destinations since the fetch does not store there; destinations created by the refmap itself are also not pruned, matching the behavior of command-line refspecs.

Tests in `t/t5510-fetch.sh` cover four scenarios: that `--refmap` without command-line refspecs stores at the refmap destination while leaving the original `refs/remotes/origin/main` untouched; that destination-less configured refspecs store through the refmap and follow tags; that `--refmap=""` does not follow tags; and that `--prune` with `--refmap` leaves configured destinations intact. A fifth test confirms `--refmap` is still rejected when fetching from a URL with no refspecs configured. Documentation in `Documentation/fetch-options.adoc` clarifies that command-line refspecs with non-empty destinations bypass the refmap, while without command-line refspecs the configured refspecs decide what is fetched but the refmap decides where it is stored.

This patch addresses three concerns Junio C Hamano raised during the v15 review: the silent ignoring of `--refmap` with URL fetches (now explicitly rejected), the `*autotags` computation timing (now set correctly when refs are stored through the refmap), and the `prune_refs()` refspec source issue (configured destinations are no longer pruned when not used for storage).
