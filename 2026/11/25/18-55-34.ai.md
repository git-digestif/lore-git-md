This is the third and final patch of a three-patch bugfix series hardening `git remote` against invalid branch names. Harald Nordgren closes out the series by addressing `git remote add -m`, which previously validated its `-m` argument only after the remote had been created and a network fetch attempted, leaving a half-configured remote behind when given a bad name like `@{u}`.

The patch adds an up-front check in the `add()` function in `builtin/remote.c`: when the `master` variable is set (from the `-m` option), it constructs `refs/heads/<name>` in a `strbuf` and calls `check_refname_format()` on it; on failure it `die()`s with "'%s' is not a valid branch name" before any remote configuration is written. A corresponding test in `t/t5505-remote.sh` runs `git remote add -m "@{u}" badmaster bar`, expects the fatal error, and verifies via `test_must_fail git config get remote.badmaster.url` that no remote was persisted. This completes the series' goal of validating branch names in `git remote add -t`, `git remote set-branches`, and `git remote add -m` before any configuration changes take effect, all built on the shared `validate_tracked_branchname()` helper introduced in patch 1/3 and reused in patch 2/3.
