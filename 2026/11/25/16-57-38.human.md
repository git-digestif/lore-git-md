This is a substantive review from Junio C Hamano endorsing the first patch of Wonseok Oh's two-patch v2 series, which fixes `git cherry-pick` behavior on unborn (orphan) branches. The patch under review modifies `sequencer_pick_revisions()` in `sequencer.c` to explicitly clear the local `oid` to the null OID via `oidclr()` when `repo_get_oid()` fails to resolve HEAD, rather than leaving the variable uninitialized.

Junio traces the fix through the code path to confirm it works correctly: calling `oidclr(&oid, r->hash_algo)` initializes both the hash and algo members, so `save_head()` writes the proper null OID for the repository's hash algorithm to `.git/sequencer/head`. Later, `sequencer_rollback()` parses that file, hits its `is_null_oid()` check, and correctly rejects `--abort` with "cannot abort from a branch yet to be born" before touching HEAD. He notes that without this fix, the outer `oid` could hold stack garbage or retain a stale value from an earlier loop, leading to undefined behavior.

He also validates the regression test added to `t/t3510-cherry-pick-sequence.sh`, which creates an orphan branch, attempts to cherry-pick two commits (so the first succeeds and births HEAD while the second fails), then verifies that `.git/sequencer/head` contains `$ZERO_OID`, that `--abort` fails with the expected error message, and that HEAD remains unchanged. Junio observes that this closes the gaps from v1 by directly checking the state file contents and confirming HEAD stays put.

With "Looking good," Junio signals approval of the approach with no further changes requested for this patch. The series remains under review with no integration status reported yet, and the companion patch 2/2 addresses the related `.git/sequencer/abort-safety` file for consistency.
