This is the first patch of a seven-patch feature series (v16) from Harald Nordgren that changes how `--refmap` interacts with explicit refspec destinations, part of a larger effort to add a limited-fetch mode for shallow repositories.

The patch modifies `get_ref_map()` in `builtin/fetch.c` to introduce a new helper, `map_refs_without_dst()`, which applies the refmap only to refspecs whose `peer_ref` is NULL -- that is, refspecs with an empty destination (`<src>` or `<src>:`) -- while refspecs with a non-empty destination (`<src>:<dst>`) are stored only at their explicit `<dst>` and bypass the refmap entirely. Previously, `git fetch --refmap=<map> origin main:refs/remotes/custom/main` would store `main` both at `refs/remotes/custom/main` and wherever `<map>` sent it; now it stores it only at the explicit destination. The opportunistic update of remote-tracking branches through `remote.<name>.fetch` is left intact, so `git fetch origin main:tmp` still updates `origin/main` as before. A test in `t/t5510-fetch.sh` verifies that `main:refs/remotes/custom/main` lands only at the custom location while a destination-less `side` is still mapped, and `Documentation/fetch-options.adoc` documents the new exemption.

Within the v16 series, this patch establishes the foundational semantics that later patches build upon: patch 2/7 will extend this to configured `remote.<name>.fetch` entries when `--refmap` is given without command-line refspecs, and patch 3/7 adds the `remote.<name>.fetchRefmap` config that supplies a default refmap. The series as a whole implements `remote.<name>.fetchUpstreams` and `remote.<name>.fetchRefmap` to let shallow clones fetch only locally tracked upstream branches instead of every remote branch, with `git remote add` defaulting to this mode in shallow repositories. This v16 iteration supersedes v15 (which was queued in `next`) and addresses three concerns Junio C Hamano raised on the earlier version, including ensuring `--refmap` is rejected when the remote has nothing configured to fetch.

The change is small, well-tested, and clearly motivated by the upcoming config-driven refmap feature; it correctly preserves existing opportunistic-update behavior while giving explicit-destination refspecs a way to opt out of refmap application.
