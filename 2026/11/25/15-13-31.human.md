This is a review acknowledgment within Ravi Mistry's v4 patch series on HTTP retry logic, specifically responding to Junio C Hamano's question about patch 4/5. Ravi confirms Junio's edge-case observation: when `start_active_slot()` fails inside `run_one_slot()`, the function returns `HTTP_START_FAILED` without calling `finish_active_slot()`, so the `struct slot_results results` variable retains stale `http_code` and `curl_result` values from the previous attempt. While this does not affect the retry logic itself since `HTTP_START_FAILED` is never retried, the stale data would cause `report_rpc_error()` to print incorrect values. Ravi commits to fixing this in a future v5 by clearing the results struct before each `run_one_slot()` call in both `post_rpc()` and `probe_rpc()`.
