This is a cover letter for a three-patch bugfix series that hardens `git remote` against invalid branch names being written to configuration. Harald Nordgren proposes validating branch names up front in `git remote add -t`, `git remote add -m`, and `git remote set-branches`, so that instead of silently accepting a malformed refspec that breaks every subsequent fetch on that remote, the command rejects the name before any configuration is persisted.

The series touches `builtin/remote.c` (adding the validation logic) and `t/t5505-remote.sh` (adding test coverage for the three subcommands). Each patch addresses one subcommand in turn: first `add -t` for tracking branches, then `set-branches`, then `add -m` for the default fetch refspec.
