This is a feature patch -- specifically patch 3 of 7 in Harald Nordgren's v16 series introducing a limited-fetch mode for shallow repositories. It adds the new per-remote configuration key `remote.<name>.fetchRefmap`, which acts as the default value for `git fetch --refmap` in the same way that `remote.<name>.fetch` provides default refspecs. A command-line `--refmap` still overrides the configured value.

The refmap only controls where fetched refs are stored, not what is fetched. When `remote.<name>.fetch` contains destination-less entries, those refs are stored through the refmap; entries with their own explicit destination bypass the refmap and are stored only at that destination. This lets a user name specific branches in `remote.<name>.fetch` while mapping all of them into a single namespace via one `fetchRefmap` line. Tags are followed for refs stored through the refmap, matching the behavior of refs stored through the regular fetch refspecs.

The patch also extends `remote_find_tracking()` in `remote.c` so that lookups used by `@{upstream}` and `git branch --track` fall back to the refmap when `remote.<name>.fetch` yields no match, allowing tracking to work for branches that are only reachable via the refmap. Branches excluded by a negative refspec in `remote.<name>.fetch` remain excluded. Implementation-wise, it adds a `struct refspec refmap` field to `struct remote` in `remote.h`, parses the `fetchrefmap` subkey in `remote.c`, and threads an `effective_refmap` pointer through `get_ref_map()` in `builtin/fetch.c` so that either the command-line option or the config is applied via `map_refs_without_dst()`.

Tests in `t/t5510-fetch.sh` cover the baseline behavior, storage of named branches through the refmap, command-line override, exemption of refspecs with destinations, tracking of out-of-fetch branches, and exclusion via negative refspecs. Documentation updates in `Documentation/config/remote.adoc` and `Documentation/fetch-options.adoc` describe the new key and its relationship to `--refmap`. The patch looks well-crafted, with clear commit message, focused scope, and thorough test coverage.
