This is a documentation patch -- specifically an in-code comment fix in `utf8.c`, arriving as patch 2/4 of a v6 series from Dirk Gouders.

The patch corrects the comment above `utf8_strnwidth()` (in `utf8.c`, near line 217). The old comment claimed the function operates on a NUL-terminated string and returns `strlen()` when the input is not valid UTF-8; the corrected comment states that the string is bounded by the `len` parameter and that `len` itself is returned in the invalid-UTF-8 case. The function signature is `int utf8_strnwidth(const char *string, size_t len, int skip_ansi)`. No code behavior changes -- only the two-line comment is updated.
