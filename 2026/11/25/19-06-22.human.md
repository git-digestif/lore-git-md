This is patch 5 of 7 in Harald Nordgren's v16 series introducing a limited-fetch mode for shallow repositories -- specifically a feature patch that adds the `remote.<name>.fetchUpstreams` configuration option. When this boolean is set to true, a plain `git fetch <name>` with no command-line refspecs fetches not only what `remote.<name>.fetch` requests, but also the upstream branches that local branches currently track on that remote. This is the core "matching" behavior that lets a shallow clone stay narrow without hand-maintaining a list of branches.

The implementation builds directly on the previous patches in the series. It adds `branches_tracking_remote()` in `remote.c`, which iterates every local branch via `refs_for_each_branch_ref()` and uses the `collect_upstream_from_remote()` helper extracted in patch 4 to gather each branch's upstream source ref. In `builtin/fetch.c`, `get_ref_map()` calls a new `add_branch_upstreams()` helper to turn those upstreams into destination-less refspec items when `fetch_upstreams` is enabled, so they flow through the refmap machinery established in patches 1-3 and land wherever `remote.<name>.fetchRefmap` (or the default refmap) directs them. The patch also updates `do_fetch()` to include these tracked upstreams in the ls-refs request, and extends `tracking_for_push_dest()` in `remote.c` so that `@{push}` consults the refmap -- fixing a case where pushing to a refmap-only remote would fail with "has no local tracking branch".

Testing is thorough: the patch creates a new 183-line test script `t/t5586-fetch-refmap.sh` covering shallow clones with multiple tracked branches, one-time fetches that establish tracking, `git pull` merging only the current branch's upstream, `--prefetch` behavior, and `@{push}` resolution. The tests confirm that upstreams are only fetched when `fetchUpstreams` is true, that multiple local branches tracking the same upstream do not cause duplicate fetches, and that `remote.<name>.fetch` entries add to (rather than replace) the tracked upstreams.

Documentation for the new `remote.<name>.fetchUpstreams` key is added to `Documentation/config/remote.adoc`, clarifying that it only controls what is fetched while storage remains governed by the fetch refspec and refmap. This patch sets up the final two patches in the series, which wire this behavior into `git remote add` via a `--limited-fetch` flag and make it the default for shallow repositories. The series remains under review; v15 was previously cooking in `next`, and v16 supersedes it.
