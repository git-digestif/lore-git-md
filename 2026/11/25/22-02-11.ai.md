This is patch 3/6 of a `the_repository` removal series in the notes subsystem, converting internal read-path helpers to use the repository pointer stored on `struct notes_tree`.

The patch modifies five functions in `notes.c` -- `note_tree_find()`, `add_non_note()`, `load_subtree()`, `remove_note()`, and `format_note()` -- replacing reads of `the_repository->hash_algo`, `the_hash_algo`, and `the_repository->objects` with `t->repo->hash_algo` and `t->repo->objects`. This depends on patch 2/6, which added the `struct repository *repo` field to `struct notes_tree` and populated it during `notes_tree_init()`.

The commit message includes a call-path safety argument explaining why these helpers can dereference `t->repo` without a NULL check: public entry points (`add_note()`, `remove_note()`, `get_note()`, `format_note()`) substitute `&default_notes_tree` for a NULL `t` and assert initialization via `notes_tree_or_default()` (introduced in patch 1/6) before calling these internal functions. `load_subtree()` is additionally reached only after a lookup has already passed through such a guard. The author notes that `copy_note()` is the exception -- it is a public function that does not currently perform the NULL swap, which patch 4/6 will address.

No behavior change is intended; this is purely mechanical substitution of the global repository with the tree's stored repository. The `USE_THE_REPOSITORY_VARIABLE` guard remains in `notes.c` for the remaining unconverted code paths.
