This is the second patch of a two-patch bugfix series (v2) targeting the sequencer subsystem, specifically the handling of unborn (orphan) branches during `git cherry-pick` sequences. Authored by Wonseok Oh and suggested by Phillip Wood, it complements the first patch by ensuring that the `.git/sequencer/abort-safety` state file stores the null OID (`$ZERO_OID`) rather than an empty string when HEAD does not yet exist, matching the representation already used in `.git/sequencer/head`.

The change modifies `update_abort_safety_file()` in `sequencer.c`: instead of writing an empty file when `repo_get_oid(the_repository, "HEAD", &head)` fails, the code now calls `oidclr(&head, the_repository->hash_algo)` to explicitly set the null OID before writing `oid_to_hex(&head)` to the abort-safety file. This ensures both sequencer state files consistently represent an unborn branch with the null OID, which older Git versions expect when interpreting the abort-safety state.

A new regression test in `t/t3510-cherry-pick-sequence.sh` verifies the behavior by starting a cherry-pick sequence on an orphan branch, confirming the pick fails as expected, and then asserting that both `.git/sequencer/head` and `.git/sequencer/abort-safety` contain `$ZERO_OID`. The test sits alongside the existing "cannot abort a cherry-pick sequence started on an unborn branch" test added in patch 1 of this series.

This patch is part of a v2 series under review with no integration status reported; it addresses consistency feedback from Phillip Wood regarding the state-file representation on unborn branches, following the root-cause fix for the uninitialized `oid` variable in the companion patch.
