This is a bugfix patch, specifically the first of four in version 6 of Dirk Gouders's series fixing bounds handling in Git's UTF-8 display-width code. Authored by Junio C Hamano, the patch introduces `display_mode_esc_sequence_len_counted()`, a length-bounded variant of the existing `display_mode_esc_sequence_len()` function that scans for ANSI SGR escape sequences.

The new function takes a pointer and length rather than relying on NUL termination, ensuring it never reads at or beyond `ptr[len]`. This matters because callers like `utf8_strnwidth()` operate on counted buffers that may not be NUL-terminated, and computing an end pointer as `s + len` would be undefined behavior when `len` is `SIZE_MAX`. The original `display_mode_esc_sequence_len()` is retained as a thin wrapper that passes `SIZE_MAX`, preserving the NUL-terminated interface for existing callers.

The patch updates two call sites to use the counted variant: `utf8_strnwidth()` passes `orig + len - string` as the remaining length when skipping ANSI sequences, and `strbuf_utf8_replace()` passes `end - src`. Both changes prevent the scanner from reading past the buffer boundary when an escape sequence appears at the very end of the input.

Unit tests in the new `t/unit-tests/u-utf8-ansi.c` file cover both the counted function and its NUL-terminated wrapper, including cases with explicit length limits. The test suite is wired into both the `Makefile` and `t/meson.build`. The commit message credits Andy Koppe with warning against O(n^2) degradation and suggesting the use of `SIZE_MAX`.

This patch establishes the counted-scanning infrastructure that patches 2 through 4 of the series build upon to fix the actual out-of-bounds reads in `utf8_strnwidth()` and `utf8_width()`. The series remains under review and has not yet been queued in any integration branch.
