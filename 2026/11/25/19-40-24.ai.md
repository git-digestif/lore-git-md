This is a bugfix for `git pack-objects` in the partial-clone (promisor) subsystem. The patch addresses a crash in `is_not_in_promisor_pack_obj()` in `builtin/pack-objects.c`, where the code previously called `BUG()` when `odb_read_object_info_extended()` failed to read an object's info. In a partial clone, objects missing from the local promisor pack are expected to be absent, so triggering a BUG() here is incorrect; the fix changes the failure path to simply return 0, meaning the object is treated as not belonging to a promisor pack and skipped during pack creation.

The change is minimal -- a single line replacing the `BUG()` macro with `return 0` -- and is accompanied by a new test in `t/t0410-partial-clone.sh`. The test exercises a scenario where a client performs a shallow fetch followed by `fetch --unshallow` with `--filter=tree:0` while the remote has advanced with new commits, which previously could hit the BUG() condition. The patch applies cleanly on top of commit 1630431f326e15fcde608827b5ff38422528eb59 and is a standalone single-patch submission (not part of a larger series visible here).
