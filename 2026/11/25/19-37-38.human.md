This is a substantive review reply from the maintainer identifying a correctness gap in the patch series. Junio C Hamano responds to Adithya Chakilam's v2 cover letter for the `--filter-to-loose=<directory>` option and points out that the second patch, which handles copying loose objects excluded by the filter, only activates for `blob:limit` filters. As implemented, it silently skips loose objects under other filter specifications such as `blob:none`, which means the documented behavior does not match the actual functionality for those cases. This is part of the ongoing v2 review; the author has not yet responded with a v3 addressing this and other concerns raised about data-loss guards, reachability handling, and temporary file naming.
