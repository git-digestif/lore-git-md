This is a cleanup patch in the HTTP backend, targeting the `get_info_packs()` function in `http-backend.c`. The patch removes an unnecessary and incorrect pre-sizing step that was introduced in 2009. The function previously iterated over all packs twice—once to count local packs and pre-size a `strbuf`, and again to format the output—despite `strbuf_addf()` already handling dynamic growth efficiently. The pre-sizing logic was also flawed: it assumed SHA-1 line lengths (underestimating SHA-256 repositories) and used unchecked arithmetic.

The author has revised the commit message in this v2 to address the reviewer’s concern about the performance trade-off. The updated rationale explains that `get_info_packs()` is a one-shot CGI handler for dumb HTTP requests (`GET /objects/info/packs`), where the overhead of dynamic `strbuf` growth (a few dozen reallocations even with thousands of packs) is negligible compared to the cost of CGI startup, scanning the pack directory, and writing the HTTP response. The patch itself is unchanged from v1 and remains a pure cleanup with no behavior change.

This is a well-motivated, low-risk improvement that aligns with similar cleanups elsewhere in the codebase (e.g., `add_rfc2047()` in commit a9ce8526dc). The patch touches only `http-backend.c` and is covered by existing HTTP backend tests.
