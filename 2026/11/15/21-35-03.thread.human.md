This thread is about a bugfix for Git’s `pretty` subsystem, addressing a long-standing annoyance with ANSI color handling in custom log formats. Andy Koppe identified two related problems: colors that span line breaks get lost when tools like `--graph` or color-aware pagers reset at line boundaries, and active colors at the end of a line can leak into subsequent content. The fix modifies `repo_format_commit_message()` to post-process formatted output, ensuring each line is self-contained by inserting resets before breaks and replaying active colors at the start of the next line. The patch is clean, well-tested (with new coverage in `t/t4205`), and aligns with how default formats already manage colors.

So far, the thread is straightforward—no objections or alternative proposals have surfaced. The fix targets a real usability issue without introducing controversy, and the implementation is efficient and edge-case-aware. If this holds, it’s likely to be merged soon.
