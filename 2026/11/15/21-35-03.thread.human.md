This thread is a straightforward bugfix for ANSI color handling in `git log --format=...` output, authored by Andy Koppe. The issue causes color escape sequences to either vanish across line breaks (e.g., bold text only applying to the first line of a wrapped subject) or leak into unrelated content (e.g., graph markers inheriting colors from prior lines). The fix, now at version 2, uses runtime tracking of active colors to ensure each line is self-contained, resetting and replaying colors as needed without requiring buffer copies. The approach was chosen because the `pretty` subsystem’s `%w` and `%b` formatting options lack per-line color control, leaving runtime detection as the only viable solution.

Junio C Hamano reviewed the initial patch and endorsed the design after Andy clarified the API gap. The updated version (`v2`) addresses all feedback: the commit message now better justifies the runtime approach, drops non-essential references to grepping, and clarifies how color leakage affects graph markers. The patch also adds a test for NUL handling, optimizes line-break logic, and rebases onto the `maint` branch. Test coverage is thorough, including line breaks, wrapped lines, empty lines, manual escapes, NULs, and `--graph` integration.

The fix touches only `pretty.c` and its test file, with no changes to on-disk formats, CLI options, or public symbols. There are no open questions or objections, and the patch is ready for integration. The thread is uncontroversial, with both author and maintainer aligned on the solution.
