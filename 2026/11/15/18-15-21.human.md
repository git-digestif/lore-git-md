This is a test modernization patch. Hardik Kumar replaces the `!` operator with `test_must_fail` in four test scripts (`t5564-http-proxy.sh`, `t6030-bisect-porcelain.sh`, `t7400-submodule-basic.sh`, and `t9001-send-email.sh`). The change is mechanical and touches seven instances where a Git command is expected to fail.

The motivation is sound: `test_must_fail` is the project's preferred helper for asserting that a command fails, because it explicitly checks for non-zero exit codes and rejects crashes (e.g., segfaults) that the `!` operator would silently accept as "failure." The commit message explains this clearly, and the patch itself is small and focused.

No controversy is expected; this is a routine cleanup that aligns with the ongoing test modernization effort. The patch is well-scoped and unlikely to break anything. If you care about test robustness, it’s worth a quick skim.
