This is a small but well-motivated cleanup in the HTTP backend. The patch removes an unnecessary and now-incorrect pre-sizing step in `get_info_packs()` that was introduced in 2009. The function previously iterated over all packs twice—once to count local packs and pre-size a `strbuf`, and again to format the output—despite `strbuf_addf()` already handling dynamic growth efficiently. The pre-sizing logic was also flawed: it hardcoded the length of SHA-1 pack lines (53 bytes), undercounting the longer lines in SHA-256 repositories, and used unchecked arithmetic.

The change is straightforward and risk-free: it drops the counting loop and the `strbuf_grow()` call, leaving only the formatting loop. The commit message now provides a clear, context-specific rationale for why the pre-sizing is unnecessary in this case. `get_info_packs()` is a one-shot CGI handler for dumb HTTP requests (`GET /objects/info/packs`), where the overhead of a few dozen `strbuf` reallocations (even with thousands of packs) is negligible compared to the cost of CGI startup, scanning the pack directory, and writing the HTTP response. This justification addresses the reviewer’s earlier concern about the performance trade-off.

The patch touches only `http-backend.c` and is inspired by a similar cleanup in `add_rfc2047()` (commit a9ce8526dc). No behavior changes, no new symbols, and no test coverage gaps—the existing HTTP backend tests already cover this code path.
