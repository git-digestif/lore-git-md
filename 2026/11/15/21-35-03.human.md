This is a bugfix patch targeting the pretty-printing subsystem. Andy Koppe
identifies two related problems in custom log formats when colors are enabled:
colors that should persist across line breaks get lost (e.g., only the first
line of a wrapped subject is bold), and colors that are still active at the
end of a line leak into the next line (e.g., coloring a commit marker or graph
edges unintentionally). The patch fixes both by making each line’s coloring
self-contained: it scans the formatted output for color escapes, resets colors
before every newline, and replays them at the start of the next non-empty line
unless that line begins with a reset. The logic lives in
`repo_format_commit_message()` so it covers all sources of color sequences and
line breaks.

The commit message is clear and thorough, walking through the symptoms,
explaining why the default formats already avoid the issue, and detailing the
implementation. The code itself is careful: it minimizes overhead by using
`memchr()` and `strcspn()` to skip quickly over non-escape text, and it only
copies the buffer when a line break actually needs adjustment. The test file
`t4205-log-pretty-formats.sh` gains seven new tests that cover wrapped lines,
empty lines, manual escape sequences, and `--graph` interaction, giving good
confidence the fix is robust.

This looks like a well-crafted, low-risk fix for a real annoyance. It should
be uncontroversial and is likely to graduate quickly.
