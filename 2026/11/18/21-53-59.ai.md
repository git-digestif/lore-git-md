This is a review acknowledgment in the v3 patch series thread, where Ravi Mistry accepts Patrick Steinhardt's correctness objection to patch 4/5. Patrick had pointed out that `post_rpc()` handles both read and write operations, and that blindly retrying POST requests is unsafe for `push_git()` calls to `git-receive-pack(1)`, since a retried push could duplicate or corrupt pack data if the server already processed the initial request. Ravi agrees this is a valid concern and commits to restricting retries in the next iteration to read-only services only -- specifically `git-upload-pack` (fetch/clone) and `git-upload-archive` -- while explicitly excluding `git-receive-pack` (push). He also promises to add a test case covering the push scenario to ensure it is not retried. This resolves the open correctness question about whether patch 4/5 can safely apply retry logic uniformly across all `post_rpc()` call sites, and establishes the whitelist approach (by service name) that v4 will implement.
