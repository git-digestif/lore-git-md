This is a substantive review reply in the ongoing bounds-safety refactoring of ANSI escape sequence handling in `utf8.c`. Dirk Gouders is pushing back on Andy Koppe's suggestion to extend the SGR parameter parser to accept colon sub-separators (as in `ESC[38:5:123m`) by widening the loop condition to `*p >= '0' && *p <= ';'`.

This leaves Andy's question about whether user-supplied text containing colon-separated SGR sequences (reaching the code via `pretty.c` wrapping or `git-column` stdin) should have their display width ignored still unresolved.
