This is a **bugfix series** (v2) addressing object-size truncation on platforms where `unsigned long` is 32 bits -- notably 64-bit Windows -- when Git handles objects of 4 GiB or more. Elia Pinto sends four patches that convert key size parameters in the pack-receiving and verification pipeline from `unsigned long` to `size_t`, fixing a crash in `git unpack-objects`, a "serious inflate inconsistency" in `git index-pack --fix-thin`, false "SHA1 COLLISION FOUND" reports in `git index-pack`, and incomplete object checks in `git fsck`.

The v2 is rebased onto current master and adjusts patch 1/4 after a recent commit (e07ac16d1c) already fixed the streamed-blob path; the remaining `unsigned long` uses in non-streamed objects, deltas, and `--strict` buffers are converted here. Rather than dropping a size cast entirely, the patch moves it to `write_object()` so that downstream functions (`odb_write_object()`, `parse_object_buffer()`, `fsck_object()`) -- which still take `unsigned long` until separate series land -- receive a safely truncated value and `git unpack-objects` dies with a clear error instead of writing corrupt data. Patches 2/4 through 4/4 are unchanged in code from v1, with commit messages clarified to note the 32-bit `long` versus 64-bit `size_t` mismatch.

The series touches `builtin/unpack-objects.c`, `builtin/index-pack.c`, `builtin/fsck.c`, `odb.h`, and `pack.h`. No tests are included because generating 4 GiB objects is impractical, but the commit messages describe 16-bit truncation simulations used to verify the fixes. Full correctness for non-streamed writes still depends on two other in-flight series that convert `odb_write_object()`, `parse_object_buffer()`, and `fsck_object()` to `size_t`; the separate `pack-objects` streamed-blob fix has already been merged. The changes are mechanical but address real correctness and crash issues on affected platforms, and the series appears well-scoped and ready for review.
