This is a reply in the `ls-tree` `-z` `--format` bugfix thread, where Noam Cohen responds to Junio C Hamano's question about the regression test's use of a non-US-ASCII filename. The patch under review fixes `show_tree_fmt()` in `builtin/ls-tree.c` to emit the raw path via `strbuf_addstr()` when `options->null_termination` is set, instead of applying `quote_c_style()`; the regression test lives in `t/t3104-ls-tree-format.sh` and uses `test_commit` with a Hebrew filename (נעם) to verify that `git ls-tree -z --format="%(objecttype) %(path)"` outputs the verbatim UTF-8 path followed by NUL. Junio has already assessed the code change as "trivially correct" and accepted the test after initially questioning the non-ASCII characters ("OK, perhaps").

Noam defends the non-ASCII filename by noting that the only US-ASCII bytes `quote_c_style()` quotes are control characters, DEL, double-quote, and backslash -- none of which Windows permits in filenames except DEL, which he considered too obscure. He considered synthesizing the tree with `git mktree` instead of touching the filesystem, but found that made the test noticeably more complicated than a simple `test_commit` in the setup. He points out that existing tests such as `t3902` and `t4012` already use non-ASCII paths. He then asks two open questions: whether the test should set `core.quotePath` explicitly rather than relying on its default, and whether he should drop the test entirely or instead add a similar `-z` test for `git ls-files --format` (whose `--format` support originated in commit `ce74de931d`, 2022-07-23, while `ls-tree --format` came from `455923e0a1`).

The thread remains in a settled state on the code fix itself, with no objections raised and maintainer approval implied, though no integration branch has been named. Future discussion is likely to center on the two questions Noam poses -- explicit `core.quotePath` configuration in the test and whether to extend coverage to `ls-files` -- as well as the broader open question of whether other `ls-tree --format` placeholders need the same `-z` treatment.
