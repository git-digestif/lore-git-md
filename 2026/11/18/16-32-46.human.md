This is a **bugfix series** (cover letter for three patches) targeting the submodule subsystem, fixing the crash and broken behavior that Andreas Wendleder reported when a submodule is itself a linked worktree.

Adrian Ratiu sends the actual fix he promised earlier in the thread, addressing the scenario where a submodule repository has linked worktrees and `submodule.recurse=true` triggers a recursive checkout from the superproject. The series touches `submodule.c` plus three test scripts (`t2405`, `t7425`, `t7450`) with a net addition of 148 lines.

The three patches work together to resolve the issues identified in the discussion: the first converts the `BUG()` in `validate_submodule_legacy_git_dir()` into a proper error return for unexpected git directory paths; the second corrects the misleading hint about `extensions.submodulePathConfig` so it only appears when the extension is actually disabled; and the third explicitly accepts a linked worktree as a valid git dir for the submodule, allowing the recursive branch switch to succeed in both legacy and `submodulePathConfig` modes.

The commit message references the original report and credits Andreas with `Reported-by` trailers. With tests covering the worktree-submodule layout, the path extension, and bad git-dotfiles cases, this looks like a well-scoped fix ready for review.
