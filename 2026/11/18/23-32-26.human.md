This is a review reply advancing Tanga Joris's three-part bugfix series for the `git apply --check` crash. Responding to Junio C Hamano's critique that the test in patch 1/3 only passes due to coincidental filename matching, Tanga agrees the corrupt input should be rejected outright rather than tolerated. He proposes a cleaner approach: have `find_header()` stop and report an error immediately when a `diff --git` line is followed by no header content, rather than continuing to search. This would make the memory-leak fix in 1/3 unnecessary and simplify 2/3. Tanga notes that modern Git never generates such empty `diff --git` sections (verified with various diff options), and that the apply and am test suites pass with this stricter check apart from his own test case. He is asking for confirmation that this aligns with the maintainer's intent before preparing a v4.
