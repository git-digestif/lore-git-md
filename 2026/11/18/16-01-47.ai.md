This is a **platform compatibility bugfix** in `version.c`, submitted by Jakub Kulik as a standalone patch. The change fixes `get_uname_info()` to correctly handle POSIX.1-compliant `uname(2)` behavior, where the system call may return any non-negative value on success rather than strictly zero. The patch replaces the error check `if (uname(&uname_info))` with `if (uname(&uname_info) < 0)`, so only a negative return value is treated as failure. This matters on Solaris, where `uname()` returns a positive value on success, causing the old code to incorrectly report an error.

The technical scope is minimal: a single-line change in `version.c` affecting only the error path of `get_uname_info()`, with no impact on successful invocations, no new symbols, and no changes to CLI behavior or on-disk formats. The commit message explicitly cites POSIX.1 as the authority for the corrected condition.
