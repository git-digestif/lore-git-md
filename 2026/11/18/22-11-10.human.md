This is a substantive review reply from Junio C Hamano on the v8 feature patch adding revision filtering to `git repo structure`. While the patch itself is otherwise considered ready for integration, Junio flags a new concern: the tests hardcode specific `.disk_size` values (e.g., `objects.commits.disk_size=163722`), which makes them brittle across different zlib implementations that may produce different compressed sizes for the same objects. This suggests the tests may fail on systems with alternative compression libraries, a portability issue not addressed by the v8 changes that only added `SHA1` prerequisites for hash-algorithm compatibility.
