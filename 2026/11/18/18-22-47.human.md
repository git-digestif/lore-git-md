This is a performance optimization for the fsmonitor integration in `git diff-index`, tightening an existing shortcut in `diff-lib.c`.

The patch addresses an oversight in `check_removed()`: since commit 4f3d6d0261 (2021), entries marked `CE_FSMONITOR_VALID` skip the `lstat()` of the file itself, but the code still calls `has_symlink_leading_path()`, which `lstat()`s every parent directory in the path. The author argues this is redundant because fsmonitor would have detected a parent directory replaced by a symlink and cleared the valid flag for all entries beneath it, so those entries would not reach this code path. The fix restructures the function to return immediately after `fake_lstat()` fills in the stat data for fsmonitor-valid entries, skipping the leading-path check entirely.

Three new tests in `t/t7519-status-fsmonitor.sh` cover the change: one verifies that an unreported symlinked parent directory is not detected (confirming the shortcut works), and two verify that when fsmonitor does report the directory change, `diff-index` still notices it whether reported with or without a trailing slash.

The commit message includes a concrete benchmark: with 100,000 files in a warm cache on Linux, `git diff HEAD` drops from 57ms to 26ms. The patch is well-motivated, references the specific prior commit that introduced the inconsistency, includes targeted regression tests, and quantifies the improvement, so it looks like a solid, low-risk optimization worth a reviewer's time.
