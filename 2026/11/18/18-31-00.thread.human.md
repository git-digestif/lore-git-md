This thread concerns a small documentation patch from Junio C Hamano proposing to delete a four-line clause from `Documentation/CodingGuidelines` that warned contributors against "clever tricks," specifically citing the `!!` operator in arithmetic constructs as confusing. Junio's commit message argues that `!!value` is a standard idiom for normalizing a value to a 0/1 boolean rather than an exotic trick, and notes the removal had been floated in a recent review thread without being acted on. The patch touches documentation only, remains under review, and has drawn no objections.

Kristoffer Haugsbakk replied with historical context that strengthens the case for removal: the clause dates back to the original CodingGuidelines commit 6d0618a8 from November 2007, and Junio himself objected to the `!!` prohibition in that very first review, pointing out the idiom was already established in the codebase. Haugsbakk also surfaced Andreas Ericsson's original clarification that the concern was aimed at arithmetic expressions like `(!!a + !!b + !!c)`, where summing multiple normalized values obscures intent, rather than at plain `!!value` normalization. Phillip Wood had earlier sent a brief acknowledgment confirming the discussion had recurred in recent reviews.

Nothing remains open on the thread; it is a single-patch documentation change awaiting maintainer pickup, with the only feedback so far being supportive context rather than technical critique.
