This is a maintainer-feedback reply in the bugfix thread for `git ls-tree` `%(path)` quoting under `-z --format`. Noam Cohen responds to Junio C Hamano's question about whether the regression test really needs non-US-ASCII characters, explaining that the only US-ASCII bytes `quote_c_style()` escapes are control characters, DEL, double-quote, and backslash -- none of which are practical for a portable filesystem test since Windows disallows them, and DEL is too obscure to rely on. He notes he considered synthesizing the tree with `git mktree` to avoid the filesystem entirely but found `test_commit` simpler, and points out that other tests like t3902 and t4012 already use non-ASCII paths.

Cohen then raises two open questions for the maintainer: whether the test should set `core.quotePath` explicitly rather than relying on its default, and whether he should drop the test entirely or add a parallel one covering `git ls-files --format`. The email does not change the patch itself but clarifies the rationale behind the Hebrew filename used to verify that `-z` emits the path verbatim, and keeps the discussion about test scope open.
