This is a platform compatibility bugfix for Solaris. Jakub Kulik sends a one-line patch correcting the error check around `uname(2)` in `get_uname_info()` within `version.c`. The current code treats any non-zero return as failure (`if (uname(&uname_info))`), but POSIX.1 allows `uname()` to return any non-negative value on success, which Solaris does. The patch changes the condition to `if (uname(&uname_info) < 0)`, so only a negative return triggers the error path.

The change is minimal and confined to build-time system information collection. On successful invocations behavior is unchanged; only the failure-detection logic is tightened to match the standard. The commit message is brief but states the motivation clearly, citing the POSIX specification directly.
