This is a **documentation** fix -- specifically a one-line comment correction -- sitting as patch 2 of 4 in Dirk Gouders's v2 series on UTF-8 bounds handling.

The patch corrects the comment above `utf8_strnwidth()` in `utf8.c`, which previously claimed the function returns `strlen()` when the input does not look like valid UTF-8. In reality it returns the `len` argument supplied by the caller, so the comment now says "Returns len instead." It is a pure comment change with no code or behavior impact, carried over unchanged from v1 of the series.
