This is a substantive maintainer review of the first patch in Adrian Ratiu's three-patch bugfix series for the submodule linked-worktree crash. Junio C Hamano replies to `[PATCH 1/3]`, which modifies `validate_submodule_legacy_git_dir()` in `submodule.c` to return `error()` instead of aborting with `BUG()` when the submodule name is not a suffix of the git dir path. Junio agrees the fix "Makes sense" and calls the cited archaeology illuminating -- specifically that commit `9cf8547320` (2024-01-28, "clone: prevent clashing git dirs when cloning submodule in parallel") made the `BUG()` reachable by passing a gitfile path read from disk, and he notes this commit landed without the usual on-list review as part of the Git 2.39.4/2.45.1 security updates. He pushes back on the proposed code comment "is not necessarily a bug in the caller," arguing that phrasing only makes sense in the historical context of converting `BUG()` to `error()`; instead, the comment should state the actual invariant -- why the git dir is expected to end with the submodule name, or why a mismatch constitutes an error condition. The review targets the diff hunk around line 2410 in `submodule.c` replacing `BUG("submodule name '%s' not a suffix of git dir '%s'", ...)` with `return error(...)` and the adjacent explanatory comment. The series remains under review with no merge decision yet.
