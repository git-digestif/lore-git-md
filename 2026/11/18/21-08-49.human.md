This is a **bugfix** series -- specifically the v2 respin of a four-patch effort to fix bounds handling in Git's UTF-8 display-width code in `utf8.c`.

Dirk Gouders has expanded the original two-patch v1 into four patches, incorporating Junio C Hamano's proposed approach. The new first patch (authored by Junio) introduces `display_mode_esc_sequence_len_counted()`, a bounded variant of the existing escape-sequence parser that accepts an explicit `size_t len` limit, leaving the original NUL-terminated `display_mode_esc_sequence_len()` intact as a wrapper for other callers. Patch 3/4 now uses this counted function inside `utf8_strnwidth()` and adds a post-loop guard so the function never reads past the supplied boundary -- addressing the memory-safety concern (including the potential `SIGBUS` when reading near the end of an mmapped region) that was raised during v1 review. Patch 4/4 applies a similar bounds fix to `utf8_width()`, which previously could violate boundaries when called without its optional length argument. Tests live in the new `t/unit-tests/u-utf8-ansi.c` and `u-utf8-width.c` clar unit tests.

The series looks well-crafted: it directly addresses the substantive review feedback from v1, keeps existing call sites stable by adding a counted variant rather than changing signatures, and includes targeted unit tests for the corner cases. It is under review and awaiting further comment.
