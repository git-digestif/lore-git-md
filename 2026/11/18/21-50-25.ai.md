This is a **surface-level review** of the fourth patch in Dirk Gouders' four-patch v2 series fixing bounds handling in the UTF-8 display-width code. Junio C Hamano replies to patch 4/4 with a brief approval -- "Well spotted, and nicely done" -- offering no technical objections or requested changes.

The patch itself modifies `utf8_strnwidth()` in `utf8.c` to stop calling `utf8_width()` with a NULL boundary argument. Instead, it now computes `remainder = orig + len - string` before each call and passes `&remainder` to `utf8_width()`, ensuring the width calculation respects the caller-supplied length even when the loop pointer approaches the end of the buffer. The patch also adds a unit test in `t/unit-tests/u-utf8-width.c` named `test_utf8_width__strnwidth_cjk_chopped` that verifies correct behavior when CJK characters are truncated by the `len` argument (e.g., expecting width 1 for the first byte of a three-byte character and width 2 for a complete three-byte character within bounds).

Junio's response signals acceptance of the approach; the series now awaits either integration or a v3 if any other reviewers raise points.
