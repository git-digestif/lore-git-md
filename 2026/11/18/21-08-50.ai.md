This is a **bugfix** patch, specifically the first of four in Dirk Gouders's v2 series fixing bounds handling in Git's UTF-8 display-width code. Although submitted by Dirk Gouders, the patch itself is authored by Junio C Hamano and introduces a length-bounded variant of the ANSI escape-sequence scanner.

The core change adds `display_mode_esc_sequence_len_counted(const char *s, size_t len)` in `utf8.c`, which scans for an SGR sequence (e.g. `ESC [ 31 m`) without ever reading at or beyond `s[len]`, returning 0 if the buffer ends before a complete sequence is found. The existing NUL-terminated `display_mode_esc_sequence_len()` is retained as a thin wrapper that calls the counted variant with `strlen(s)`, preserving compatibility for current callers. The declaration is added to `utf8.h`.

Three call sites are updated to use the counted variant: `utf8_strnwidth()` passes the remaining length (`orig + len - string`) so the ANSI-skipping loop cannot scan past the caller-supplied boundary; `strbuf_utf8_replace()` uses `end - src`; and `strbuf_add_wrapped_text()` computes `end = text + strlen(text)` once upfront and passes `end - text` in each iteration. These changes prevent over-reads on counted buffers, addressing the mmapped-region SIGBUS risk discussed earlier in the thread. New unit tests in `t/unit-tests/u-utf8-ansi.c` (wired into both `Makefile` and `t/meson.build`) verify the counted function returns correct lengths for truncated sequences like `"\033[m"` with insufficient length.
