This is a feature patch (v8 of a single-patch series) adding revision-based filtering to the `git repo structure` command. The only change from v7 is the addition of `SHA1` test prerequisites to the newly added tests in `t/t1901-repo-structure.sh`, resolving the SHA-256 compatibility concern raised by Junio C Hamano regarding hardcoded 40-character object IDs in the "filter by object type" test.

The patch modifies `builtin/repo.c`, `Documentation/git-repo.adoc`, and `t/t1901-repo-structure.sh` (197 lines of tests). It introduces the ability to pass revision specifications (e.g., `git repo structure <revision>... [--not <revision>...]`) to limit the object graph analysis to specific subsets, using Git's standard `setup_revisions()` machinery with `struct rev_info`. When revisions are specified, the command processes objects reachable from included revisions unless they are exclusively reachable via excluded revisions; with no arguments it processes all objects as before. The implementation retains `.def = "HEAD"` and `.revarg_opt = REVARG_COMMITTISH` in `setup_revision_opt`, and performs a secondary ref-walk in `count_references()` to count references by type since `setup_revisions()` lacks a custom callback hook.

The series is now considered ready for integration, with Patrick Steinhardt having previously signaled satisfaction and the author having addressed all critical feedback across iterations. The accepted trade-offs remain: the double ref-walk inefficiency is tolerated for a diagnostic tool, the revision-parsing defaults remain potentially restrictive for tree/blob filtering (Patrick's suggestion to pass `NULL` to `setup_revisions()` was not adopted), and the `ref^{tree}` test case remains absent. The author has committed to a long-term cleanup to make all tests in `t/t1901-repo-structure.sh` hash-agnostic before Git 3.0, though the short-term `SHA1` prerequisite guards are now in place.

Future discussion in this thread is likely to focus on whether the patch has been queued by the maintainer, or potentially on the long-term test modernization commitment. No technical objections remain open.
