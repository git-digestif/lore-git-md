This is the fourth and final patch in Elia Pinto's v2 bugfix series targeting object-size truncation on 32-bit-`long` platforms (notably 64-bit Windows). It changes the `verify_fn` callback signature in `pack.h`, the `object_cb` field in `struct odb_fsck_options` in `odb.h`, and the `fsck_obj_buffer()` implementation in `builtin/fsck.c` from `unsigned long` to `size_t` for the object-size parameter. On platforms where `long` is 32 bits but `size_t` is 64, `git fsck` previously passed a truncated size to the verification callback when inspecting pack objects of 4 GiB or more, causing `parse_object_buffer()` and `fsck_object()` to check only a prefix of the object rather than the whole thing.

The diff itself is minimal -- three lines across three files -- but it closes the loop on the fsck path so that at least the size reaching the callback is correct. The commit message is candid about a remaining limitation: `parse_object_buffer()` and `fsck_object()` themselves still accept `unsigned long`, so until those are converted in a follow-up series, fsck will continue to inspect only a prefix of very large objects even though the size passed in is no longer truncated. No test is included because reproducing the bug requires generating objects larger than 4 GiB on a platform with 32-bit `long`.
