This is a **bugfix** patch, specifically the first of four in v2 of a series hardening Git's UTF-8 display-width code against out-of-bounds reads. The patch introduces a new bounds-aware helper, `display_mode_esc_sequence_len_counted(const char *s, size_t len)`, which scans for ANSI escape sequences without ever reading at or beyond the given length, and converts the existing NUL-terminated `display_mode_esc_sequence_len()` into a thin wrapper that calls the counted variant with `strlen()`. Although Dirk Gouders sends the email, the commit message credits Junio C Hamano as the original author.

The change touches `utf8.c` and `utf8.h`, and updates three call sites to use the new counted function: `utf8_strnwidth()` now passes the remaining buffer length when skipping ANSI sequences, while `strbuf_add_wrapped_text()` and `strbuf_utf8_replace()` compute the end pointer once and pass the remaining distance on each iteration. This directly addresses the concern that the old NUL-reliant scanning could read past the end of a counted buffer -- including the mmapped-region SIGBUS scenario discussed earlier in the thread. A new unit test file, `t/unit-tests/u-utf8-ansi.c`, verifies the counted function against truncated inputs.

Within the larger v2 series, this patch establishes the primitive that patches 3 and 4 rely on to enforce strict boundary discipline in `utf8_strnwidth()` and `utf8_width()`. The series expands v1's two patches into four by separating the API introduction, the documentation fix, and the two width functions. The patch looks well-crafted: it includes tests, preserves backward compatibility via the wrapper, and the commit message clearly explains both the immediate correctness issue and the performance benefit of avoiding repeated length measurements in the strbuf callers.
