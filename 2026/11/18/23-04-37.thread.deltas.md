- [2026/11/18/23-04-37 by Noam Cohen via B4 Relay <devnull+noam.noam.me@kernel.org>] Noam Cohen posted a patch making `git ls-tree -z --format` output the `%(path)` placeholder verbatim instead of C-quoting it, matching `git ls-files -z --format`, with a test using a non-ASCII path.
- [2026/11/18/23-20-39 by Junio C Hamano <gitster@pobox.com>] Junio C Hamano reviewed the patch, noting that ce74de931d (ls-files: introduce "--format" option, 2022-07-23) was the commit that added --format and that its documentation covers -z but adds no test combining --format="%(path)" with -z; he called the code change trivially correct, questioned whether the test really needs characters outside US-ASCII, and conceded "OK, perhaps" to the added test.
- [2026/11/18/23-45-42 by Noam Cohen <noam@noam.me>] Noam Cohen replied that the only US-ASCII bytes `quote_c_style()` quotes are control characters, DEL, '"' and '\', which Windows disallows in filenames except DEL (too obscure to rely on); he said a `git mktree`-based test was tried first but was noticeably more complicated than `test_commit`, and that existing tests (t3902, t4012, others) already use non-ASCII paths. He asked whether the test should set `core.quotePath` explicitly rather than rely on its default, and whether to drop the test or add a similar one for `ls-files --format`.
