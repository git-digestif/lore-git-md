This is a performance patch, specifically the first of four in Patrick Steinhardt's series addressing slow reflog expiration during auto-maintenance. The patch targets the reftable ref backend: when `git reflog expire` runs with the `--dry-run` flag, the backend previously wrote a new reftable to disk even though no actual changes were being made, since the dry-run only prints what would be pruned. The fix adds an early return when `EXPIRE_REFLOGS_DRY_RUN` is set, skipping the unnecessary `reftable_addition_commit()` call entirely.

The broader series addresses a more significant problem where `git maintenance run --auto` spawned `git reflog expire` on every invocation because the auto-condition in `builtin/gc.c` failed to evaluate reachability correctly, treating every reflog entry as unreachable. While this first patch provides a modest optimization for dry-run scenarios (roughly 11 percent faster wall time according to the included benchmarks), the cover letter for the series cites a 45.8x speedup for auto-maintenance on git.git once all four patches are applied.

The change itself is minimal and well-contained, touching only `refs/reftable-backend.c` with a small guard around the commit call. It comes with benchmark numbers showing consistent improvements, which suggests careful measurement rather than speculative tuning. As part of the ongoing reftable backend effort, this fits a pattern of eliminating wasted work in common code paths.
