This is a **platform compatibility** patch fixing the test suite. Jakub Kulik submits a minimal fix to `t/t1017-cat-file-remote-object-info.sh` that quotes two shell variables used as redirection targets, resolving test failures on Solaris when the temporary directory path contains spaces.

The diff wraps `$daemon_parent` and `$HTTPD_DOCUMENT_ROOT_PATH` in double quotes within two `echo` redirections, changing lines like `> $daemon_parent/hello` to `>"$daemon_parent/hello"`. This aligns with `Documentation/CodingGuidelines`, which require quoting variables even in contexts where POSIX shells do not strictly mandate it. The failures on Solaris manifested as "No such file or directory" errors during `cd` operations in the test harness.

The patch incorporates feedback from Junio C Hamano, who previously noted that while POSIX-compliant shells pass without the quotes, Git's style guide requires them for consistency. Junio also clarified that the redirection operator should immediately precede the quoted path without an intervening space, which this submission adopts. The change is signed off and self-contained.

The fix is narrowly scoped to shell portability in the test scripts and touches no production code. It appears ready for integration, with no outstanding technical objections.
