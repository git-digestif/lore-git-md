This is a bugfix patch, the third of four in a v2 series from Dirk Gouders, correcting a boundary-handling bug in `utf8_strnwidth()` within `utf8.c`. The function takes a `skip_ansi` flag that makes it skip ANSI escape sequences (such as SGR color codes) while computing display width, but the previous logic did not check whether consuming those sequences had already advanced the string pointer to the end of the allowed `len` boundary. If an escape sequence ended exactly at `orig + len`, the code would fall through and call `utf8_width()` on a position past the boundary, risking an out-of-bounds read.

The fix wraps the ANSI-skipping `while` loop and adds an explicit check `if (string >= orig + len) break;` immediately after it, ensuring the function stops when the escape sequences have consumed the entire remaining input up to the specified length. The change is confined to `utf8.c`, with accompanying unit tests added to `t/unit-tests/u-utf8-width.c`.

The new test `test_utf8_width__strnwidth_ansi()` covers the corner case using the string `"\033[31mhello"` (a 5-byte red SGR sequence followed by "hello") with length arguments of 4, 5, and 6, expecting widths of 3, 0, and 1 respectively. The length-5 case is the critical regression test: the ANSI sequence consumes exactly the full allowed length, which previously could trigger the boundary violation before the fix.
