This is a documentation patch from Junio C Hamano that removes a prohibition against "clever tricks" from `Documentation/CodingGuidelines`. Specifically, it deletes the clause warning that using the `!!` operator with arithmetic constructs can be confusing, on the grounds that double negation is actually a standard C idiom for normalizing a value to a 0/1 boolean rather than an exotic trick worth banning.

The commit message notes that the idea surfaced during a recent review thread where `!!` was used appropriately, but nobody followed through on removing the rule at the time. The change is minimal -- just four lines deleted -- and reflects a pragmatic reassessment of what constitutes readable versus confusing C code. Since this comes directly from the maintainer and touches only contributor-facing guidelines rather than code behavior, it is essentially a housekeeping change that formalizes a consensus which had already emerged informally in review discussions.
