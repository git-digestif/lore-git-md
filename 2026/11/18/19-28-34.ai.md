This is a **substantive review reply** from Junio C Hamano to `[PATCH 2/3]` of Adrian Ratiu's three-patch series fixing the submodule-linked-worktree crash. Junio agrees the motivation is sensible but offers two substantive observations. First, he notes that the existing `submodule_name_to_gitdir()` function already handles the same situation with a hedged message ("might fix ... if it's not already enabled") rather than checking the extension state, suggesting that simpler approach could be used here too; he also points out that `builtin/submodule--helper.c:clone_submodule()`, another caller of `validate_submodule_git_dir()`, has the same unconditional "Enabling ... should fix this" message and may need similar treatment. Second, he observes that the proposed change makes an already deeply nested block in `submodule_move_head()` (submodule.c, around line 2171) even harder to read, and suggests extracting the entire "if not dry-run" block into a private helper function to improve readability. For future thread context: the patch under review moves the `extensions.submodulePathConfig` suggestion from the fatal `die()` message into a conditional `advise()` call gated on `!the_repository->repository_format_submodule_path_cfg`; reviewers should watch for whether Junio's suggestion to use hedged wording instead of the explicit state check is adopted, and whether the nested-block refactor is requested in a future version.
