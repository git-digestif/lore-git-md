This is a review reply from the maintainer on the first patch of a three-patch bugfix series. Junio C Hamano responds to Adrian Ratiu's `[PATCH 1/3]`, which changes `validate_submodule_legacy_git_dir()` in `submodule.c` to return a regular `error()` instead of aborting with `BUG()` when the submodule name is not a suffix of the git dir path.

Junio agrees with the change ("Makes sense") and finds the archaeology in the commit message illuminating, noting that the commit which made the `BUG()` reachable -- `9cf8547320` (2024-01-28) -- apparently arrived without the usual on-list review as part of the Git 2.39.4/2.45.1 security updates. He then offers one piece of feedback on the new comment added above the check: he suggests that saying a mismatch "is not necessarily a bug" is only meaningful in the context of converting the `BUG()` to an error, and that the comment would be better if it explained why the submodule name is expected to be a suffix of the git dir, or why a mismatch constitutes an error condition.

The exchange shows the maintainer endorsing the direction of the patch while asking for a clearer explanation in the code comment. This is patch 1 of 3 in Adrian Ratiu's series addressing a crash that occurs when a submodule is itself a linked worktree of its repository and `submodule.recurse=true` is set; the series as a whole proposes to return proper errors instead of `BUG()`, fix a misleading `extensions.submodulePathConfig` hint, and accept linked worktrees as valid submodule git directories.
