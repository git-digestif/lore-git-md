The underlying patch (quoted in the reply) makes a single-line change in `version.c` inside `get_uname_info()`: it replaces the error check `if (uname(&uname_info))` with `if (uname(&uname_info) < 0)`. The old code treated any non-zero return as failure, but POSIX.1 allows `uname(2)` to return any non-negative value on success; on Solaris it returns a positive value, causing a spurious error report. The new condition treats only negative returns as errors, matching the standard. Behavior on successful invocations is unchanged, and no new symbols, config keys, or on-disk formats are introduced. The patch touches only the error path of build-time system information collection and ships without explicit test coverage.
