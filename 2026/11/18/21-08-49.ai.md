This is a **bugfix** patch series (v2, now four patches) targeting bounds handling in Git's UTF-8 display-width code in `utf8.c`. Dirk Gouders expanded his original two-patch v1 into a four-patch v2 that incorporates a patch by Junio C Hamano and extends the same bounds discipline to `utf8_width()`.

The series is structured as follows. Patch 1 (authored by Junio C Hamano) introduces a new bounded helper, `display_mode_esc_sequence_len_counted(const char *s, size_t len)`, which accepts an explicit length boundary, while retaining the original NUL-terminated `display_mode_esc_sequence_len()` as a wrapper to avoid disrupting other callers. Patch 2 fixes the incorrect comment on `utf8_strnwidth()` (unchanged from v1). Patch 3, now titled "respect string boundaries after skipping ANSI escape sequences," modifies `utf8_strnwidth()` to use the new counted variant in its ANSI-skipping loop and adds a guard ensuring the pointer does not advance beyond `orig + len` before calling `utf8_width()`; this directly addresses the v1 concern that the loop could read past the caller-supplied `len`, including the mmapped-region SIGBUS edge case discussed earlier. Patch 4 is new in v2 and applies the same boundary-respecting treatment to `utf8_width()` when called without its optional bounds argument.

The changes touch `utf8.c`, `utf8.h`, and add unit tests in `t/unit-tests/u-utf8-ansi.c` (for the counted escape-sequence function) and `t/unit-tests/u-utf8-width.c` (for `utf8_strnwidth()` and `utf8_width()` corner cases). One test expectation was corrected in v2: the escape sequence `"\033"` has display width 0, so the expected sum for a truncated string is 3, not 4. The series remains under review on the mailing list.
