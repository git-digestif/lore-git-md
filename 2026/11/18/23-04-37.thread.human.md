This thread is a single-patch bugfix from Noam Cohen correcting `git ls-tree --format` so that paths are emitted verbatim under `-z` instead of being C-style quoted, matching the documented null-terminated output and the behavior of `git ls-files --format`. The fix itself is a small change in `show_tree_fmt()` in `builtin/ls-tree.c`, and Junio C Hamano has already reviewed it, calling the code change "trivially correct" with no objections raised from anyone else; no integration branch has been named yet.

The remaining discussion is about the regression test in `t/t3104-ls-tree-format.sh`, which uses a Hebrew filename (נעם). After initially questioning whether non-US-ASCII characters were needed ("OK, perhaps"), Junio accepted the test as written, and Noam has now defended the choice: the only US-ASCII bytes `quote_c_style()` quotes are control characters, DEL, double-quote, and backslash, none of which are practical filename characters on Windows, while existing tests like t3902 and t4012 already use non-ASCII paths. He considered synthesizing the tree with `git mktree` but found `test_commit` simpler.

Two open questions remain from Noam's latest message: whether the test should set `core.quotePath` explicitly rather than rely on its default, and whether to drop the test or additionally add a `-z` test for `git ls-files --format`. The broader loose end -- whether other `ls-tree --format` placeholders need the same `-z` treatment -- is also still unresolved.
