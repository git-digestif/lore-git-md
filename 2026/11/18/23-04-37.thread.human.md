Noam Cohen has posted version 2 of a single-patch fix for `git ls-tree`, which since 2022 has applied C-style quoting to the `%(path)` placeholder in `--format` output even when `-z` was requested -- contradicting the documented verbatim, null-terminated behavior and diverging from `git ls-files --format`, which handles `-z` correctly. The code change itself is a one-line branch in `show_tree_fmt()` in `builtin/ls-tree.c` on `options->null_termination`, and Junio C Hamano has already reviewed v1 and called it "trivially correct", so the logic appears settled.

The v2 revision addresses the only open point from the v1 discussion: the regression test. Instead of creating a commit with a non-ASCII (Hebrew) filename on disk, the new test in `t/t3104-ls-tree-format.sh` synthesizes a tree entry containing a double quote via `git mktree`, keeps everything within US-ASCII, and forces `core.quotePath=true` so the quoting path would otherwise be triggered -- making the test self-contained and platform-independent while still proving `-z` suppresses quoting.

The series remains under review with no integration branch assigned yet, but with maintainer approval on the fix and the test concern resolved, it looks ready for Junio to pick up.
