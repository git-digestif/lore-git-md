This thread is a small, maintainer-approved bugfix to `git ls-tree`. Noam Cohen's patch fixes the `%(path)` placeholder in `git ls-tree --format` so that when `-z` is passed, paths are emitted verbatim and NUL-terminated instead of being C-style quoted -- matching both the documented behavior and how `git ls-files --format` has handled `-z` since 2022. The change is confined to `show_tree_fmt()` in `builtin/ls-tree.c`, branching on the null-termination option, and the v2 regression test in `t/t3104-ls-tree-format.sh` synthesizes a tree entry containing a double quote via `git mktree` with `core.quotePath=true` forced on, keeping the test self-contained in US-ASCII.
