This thread is a single-patch bugfix from Noam Cohen addressing a regression in `git ls-tree --format`: since the `--format` option was introduced, paths were C-style quoted even when `-z` was passed, contradicting the documented null-terminated verbatim output and diverging from `git ls-files --format`, which handles `-z` correctly. The fix is a small change in `show_tree_fmt()` in `builtin/ls-tree.c` that emits the raw path when `-z` is set, plus a regression test in `t/t3104-ls-tree-format.sh` using a non-ASCII (Hebrew) filename to confirm verbatim output.

Junio C Hamano has now reviewed the patch and responded favorably. He corrected the author's attribution -- the `--format` option for `ls-files` actually came from commit `ce74de931d` (2022-07-23), not `455923e0a1` -- and noted that while that commit documented `-z`, it lacked a test covering `%(path)` with `-z`. He called the proposed code change "trivially correct." On the test, he initially questioned whether non-US-ASCII characters were necessary, but after the author's reply settled on "OK, perhaps," effectively accepting the test as written.

The patch remains at v1 and under review with no objections raised; it appears to have maintainer approval pending integration, though no integration branch has been assigned. The only open question is whether other `ls-tree --format` placeholders need the same `-z` treatment, and whether `ls-files` is the right behavioral reference point.
