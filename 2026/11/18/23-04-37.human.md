This is a bugfix for `git ls-tree` that corrects how the `%(path)` placeholder behaves with `-z`.

The patch addresses an inconsistency introduced in commit 455923e0a1 (March 2022), which added the `--format` option. While the documentation states that `-z` causes filenames to be output verbatim, the `%(path)` placeholder in a custom format string was always C-quoted regardless of `-z`. This makes `git ls-tree -z --format="%(path)"` behave differently from the default output mode and from `git ls-files -z --format`, which already outputs paths verbatim under `-z`.

The fix is small and targeted: in `builtin/ls-tree.c`, the `show_tree_fmt` function now checks `options->null_termination` and skips the `quote_c_style` call when `-z` is active, appending the raw path instead. The accompanying test in `t/t3104-ls-tree-format.sh` creates a file with a non-ASCII name (נעם) and verifies that `ls-tree -z --format="%(objecttype) %(path)"` produces the expected null-terminated, unquoted output.

The commit message clearly states the motivation -- aligning `ls-tree` with the existing `ls-files` behavior -- and cites the specific commit that introduced the regression. The patch looks well-crafted and ready for review.
