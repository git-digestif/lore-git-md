Thread identity: standalone single-patch bugfix series (v2, 1/1, no cover letter) from Noam Cohen titled as a fix for `git ls-tree` `%(path)` quoting under `-z --format`; based on commit 03b41523c576f26ad34085378717a0c1b287470f.

Core problem or goal: since commit 455923e0a1 introduced `--format` for `ls-tree` in 2022, `git ls-tree --format` has applied C-style quoting to paths via `quote_c_style()` even when `-z` was requested, contradicting the documented verbatim null-terminated output and diverging from `git ls-files --format` (introduced in ce74de931d, 2022-07-23) which already handles `-z` correctly. The patch makes `ls-tree` emit the path verbatim when `-z` is set.

Current status: v2 posted and under review; Junio C Hamano reviewed v1 and called the code change "trivially correct" and accepted the approach. No objections to the fix itself have been raised and the patch appears to have maintainer approval pending integration, though no branch assignment (master/next/seen) has been stated.

Key technical details: change is confined to `show_tree_fmt()` in `builtin/ls-tree.c`, branching on `options->null_termination` -- if true the raw path is appended with `strbuf_addstr()`, otherwise the existing `quote_c_style()` path is used. The v2 regression test in `t/t3104-ls-tree-format.sh` now synthesizes a tree entry containing a double quote using `git mktree` rather than writing a non-ASCII filename to the filesystem, keeps the test content within US-ASCII, and forces `core.quotePath=true` to ensure the quoting path would otherwise be triggered, verifying that `git ls-tree -z --format="%(objecttype) %(path)"` emits the raw path followed by NUL.

Open questions and loose ends: whether other `ls-tree --format` placeholders need the same `-z` treatment; whether `ls-files` behavior is the correct reference point. The earlier open question about whether to avoid non-US-ASCII bytes in tests is resolved in v2 by switching to the `git mktree` approach with a double-quote character.

Participant positions: Junio C Hamano reviewed v1, corrected the historical attribution by noting that `--format` for `ls-files` originated in ce74de931d (2022-07-23) rather than 455923e0a1, and observed that while ce74de931d's documentation mentioned `-z` it lacked a test exercising `%(path)` with `-z`. He assessed the proposed code change as "trivially correct" and initially suggested the `git mktree` plus forced `core.quotePath` approach for the test while accepting the Hebrew-filename test as written ("OK, perhaps"), noting that non-US-ASCII bytes are acceptable and preferable to no test. No formal Reviewed-by trailer has been recorded yet. Noam Cohen defended the v1 non-ASCII filename choice but has now adopted the `mktree` approach in v2, keeping the test within US-ASCII and self-contained.

Related work: `git ls-files --format` `-z` handling is cited as the correct reference behavior; commit ce74de931d (2022-07-23) is the origin of the `ls-files --format` feature, while commit 455923e0a1 introduced `--format` for `ls-tree`.
