Thread identity: standalone single-patch bugfix series (v2, 1/1, no cover letter) from Noam Cohen titled as a fix for `git ls-tree` `%(path)` quoting under `-z --format`; based on commit 03b41523c576f26ad34085378717a0c1b287470f.

Core problem or goal: since commit 455923e0a1 introduced `--format` for `ls-tree` in 2022, `git ls-tree --format` has applied C-style quoting to paths via `quote_c_style()` even when `-z` was requested, contradicting the documented verbatim null-terminated output and diverging from `git ls-files --format` (introduced in ce74de931d, 2022-07-23) which already handles `-z` correctly. The patch makes `ls-tree` emit the path verbatim when `-z` is set.

Current status: v2 posted, reviewed, and approved by Junio C Hamano, who called it "nicely done" and stated he will queue it. No specific integration branch (master/next/seen) has been named; the series remains pending integration until a "What's cooking" report assigns it.

Key technical details: change is confined to `show_tree_fmt()` in `builtin/ls-tree.c`, branching on `options->null_termination` -- if true the raw path is appended with `strbuf_addstr()`, otherwise the existing `quote_c_style()` path is used. The v2 regression test in `t/t3104-ls-tree-format.sh` synthesizes a tree entry containing a double quote using `git mktree` rather than writing a non-ASCII filename to the filesystem, keeps the test content within US-ASCII, forces `core.quotePath=true` to ensure the quoting path would otherwise be triggered, and verifies that `git ls-tree -z --format="%(objecttype) %(path)"` emits the raw path followed by NUL.

Open questions and loose ends: whether other `ls-tree --format` placeholders need the same `-z` treatment; whether `ls-files` behavior is the correct reference point.

Participant positions: Junio C Hamano reviewed v1, corrected the historical attribution by noting that `--format` for `ls-files` originated in ce74de931d (2022-07-23) rather than 455923e0a1, assessed the code change as "trivially correct", and suggested the `git mktree` plus forced `core.quotePath` approach for the test. He subsequently reviewed v2, confirmed the test rework with "nicely done", and stated "Will queue", giving maintainer approval without naming a branch. No formal Reviewed-by trailer has been recorded. Noam Cohen defended the v1 non-ASCII filename choice but adopted the `mktree` approach in v2, keeping the test within US-ASCII and self-contained.

Related work: `git ls-files --format` `-z` handling is cited as the correct reference behavior; commit ce74de931d (2022-07-23) is the origin of the `ls-files --format` feature, while commit 455923e0a1 introduced `--format` for `ls-tree`.
