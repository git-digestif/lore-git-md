Thread identity: standalone single-patch bugfix series (v1, 1/1, no cover letter) from Noam Cohen titled as a fix for `git ls-tree` `%(path)` quoting under `-z --format`; based on commit 03b41523c576f26ad34085378717a0c1b287470f.

Core problem or goal: since commit 455923e0a1 introduced `--format` for `ls-tree` in 2022, `git ls-tree --format` has applied C-style quoting to paths via `quote_c_style()` even when `-z` was requested, contradicting the documented verbatim null-terminated output and diverging from `git ls-files --format` (introduced in ce74de931d, 2022-07-23) which already handles `-z` correctly. The patch makes `ls-tree` emit the path verbatim when `-z` is set.

Current status: v1 posted and under review; Junio C Hamano has reviewed and called the code change "trivially correct" and accepted the regression test after initially questioning whether non-US-ASCII characters were necessary ("OK, perhaps"). No objections to the fix itself have been raised and the patch appears to have maintainer approval pending integration, though no branch assignment (master/next/seen) has been stated.

Key technical details: change is confined to `show_tree_fmt()` in `builtin/ls-tree.c`, branching on `options->null_termination` -- if true the raw path is appended with `strbuf_addstr()`, otherwise the existing `quote_c_style()` path is used. Regression test added in `t/t3104-ls-tree-format.sh` using a commit containing a non-ASCII filename (נעם) and verifying `git ls-tree -z --format="%(objecttype) %(path)"` emits the raw UTF-8 path followed by NUL.

Open questions and loose ends: whether other `ls-tree --format` placeholders need the same `-z` treatment, and whether `ls-files` behavior is the correct reference point.

Participant positions: Junio C Hamano reviewed the patch, corrected the historical attribution by noting that `--format` for `ls-files` originated in ce74de931d (2022-07-23) rather than 455923e0a1, and observed that while ce74de931d's documentation mentioned `-z` it lacked a test exercising `%(path)` with `-z`. He assessed the proposed code change as "trivially correct" and, after questioning the necessity of non-US-ASCII characters in the test, accepted the Hebrew-filename regression test as written ("OK, perhaps"). No formal Reviewed-by trailer has been recorded yet.

Related work: `git ls-files --format` `-z` handling is cited as the correct reference behavior; commit ce74de931d (2022-07-23) is the origin of the `ls-files --format` feature, while commit 455923e0a1 introduced `--format` for `ls-tree`.
