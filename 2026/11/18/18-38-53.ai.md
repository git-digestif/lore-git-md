This is a substantive review reply within the ongoing `[PATCH v2]` thread for the bounds-safety refactoring of ANSI escape sequence handling in `utf8.c`. Dirk Gouders responds to Andy Koppe's grammar-based argument that ECMA-48 colon sub-separators can be accepted with a simple character-class expansion rather than a finite state machine.

Dirk concedes that his earlier claim was misleading: the existing `display_mode_esc_sequence_len()` already functions as a finite state machine accepting the regular language `"\033\[[0-9;]+m"`. His refined concern is narrower -- whether merely adding `:` to the accepted alphabet and to the existing "parameter" state (without introducing new states) would still restrict acceptance to only valid SGR sequences. To probe this, he asks whether `"\033[:;m"` constitutes a valid SGR sequence, noting that such discussion is difficult without first defining the exact language the parser intends to accept.

The exchange sits within the broader context of the v2 patch that adds `display_mode_esc_sequence_len_counted(const char *s, size_t len)` in `utf8.c` to prevent out-of-bounds reads on non-NUL-terminated buffers, with the original `display_mode_esc_sequence_len(const char *s)` retained as a wrapper.
