This is a substantive review reply from Junio C Hamano to Mark C. Chu-Carroll's v8 patch adding revision filtering to `git repo structure`. Building on the prior discussion where the SHA-256 test compatibility issue was resolved, Junio now identifies three specific implementation concerns in the option parsing and resource management. First, the current `parse_options()` call uses `PARSE_OPT_KEEP_UNKNOWN_OPT` but omits `PARSE_OPT_KEEP_DASHDASH`, which means the `--` separator is discarded; this prevents users from disambiguating pathspecs from revisions when a filename matches a refname (e.g., `git repo structure master..grobble -- t/`). Second, the condition `argc > 1` incorrectly causes `setup_revisions()` to be invoked for non-revision flags like `--objects`, `--stdin`, or `--end-of-options`; Junio suggests `included_revision_args` should instead be initialized based on `revs.rev_input_given` to accurately reflect whether any actual revision arguments were provided. Third, the error path that handles unrecognized arguments after `setup_revisions()` returns without calling `release_revisions()` on the `revs` struct, leaking resources held by the revision machinery. These are precise, code-level observations targeting `builtin/repo.c`, indicating a deep engagement with the patch's parsing logic and memory management.
