This is a feature patch for the `git repo structure` command, now in its eighth iteration. Mark C. Chu-Carroll adds revision-based filtering so users can pass revision arguments (e.g. `git repo structure main ^old-topic`) to limit the report to objects reachable from specific commits, rather than always scanning the entire repository. The goal is to help diagnose performance problems in large repos by letting users focus on the subset of the object graph that is actually misbehaving.

The v8 change is minimal: it adds a `SHA1` prerequisite to the new tests that hardcode 40-character object IDs, resolving the SHA-256 compatibility concern Junio C Hamano raised on v7. This matches the existing pattern in `t/t1901-repo-structure.sh` and is accepted as the short-term fix while the author commits to a longer-term hash-agnostic rewrite of the whole test file.

The patch touches `builtin/repo.c` to wire in `setup_revisions()`, updates `Documentation/git-repo.adoc` with the new syntax and clarified terminology, and expands `t/t1901-repo-structure.sh` to 197 lines covering edge cases like overlapping includes/excludes and different output formats. Patrick Steinhardt has already signed off on the technical approach, and the remaining trade-offs -- such as the default of `HEAD` when no revisions are given and a double ref-walk in `count_references()` -- are explicitly accepted as tolerable for a diagnostic tool.

With all substantive feedback from prior rounds incorporated and the final editorial and compatibility nits addressed, this version looks ready for integration.
