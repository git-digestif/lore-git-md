This is a cover letter for a four-patch performance series addressing slow reflog expiration during auto-maintenance. Patrick Steinhardt reports that commands were hanging for nearly a second after completion because the `reflog-expire` auto-condition in `builtin/gc.c` failed to properly evaluate reachability of reflog entries. As a result, every entry was treated as unreachable and evaluated against `gc.reflogExpireUnreachable` instead of `gc.reflogExpire`, causing `git maintenance run --auto` to spawn `git reflog expire` unnecessarily on every run. The third patch fixes this logic so only genuinely unreachable entries trigger expiration. The first two patches optimize the reftable backend (`refs/reftable-backend.c`) to skip writing a new table when expire is a dry-run or a no-op. The series also includes a documentation typo fix in `Documentation/config/maintenance.adoc` and new tests in `t/t0610-reftable-basics.sh`. Benchmark results on git.git show wall time dropping from 853 ms to 18.6 ms (45.8x faster) with memory usage reduced by about 31 percent. The series applies on base commit `e1ec09b23c8e0deb21a0b95ac5996422277395d4`.
