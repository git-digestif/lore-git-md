This is a feature patch (v8 of a single-patch series) adding revision-based filtering to `git repo structure`. The only delta from v7 is the addition of `SHA1` test prerequisites to the new tests in `t/t1901-repo-structure.sh`, resolving the SHA-256 compatibility issue raised by Junio C Hamano regarding hardcoded 40-character object IDs.

The patch modifies `builtin/repo.c`, `Documentation/git-repo.adoc`, and `t/t1901-repo-structure.sh`. It extends `cmd_repo_structure()` to accept revision arguments (`[<revs>...]`) parsed via `setup_revisions()` into a `struct rev_info`, allowing users to specify inclusion/exclusion sets (e.g., `git repo structure grobble ^master`). When revisions are provided, `setup_revisions()` populates the pending object list; when absent, the command falls back to walking all references. A new `bool add_to_pending` field in `struct count_references_data` and a corresponding parameter on `structure_count_references()` distinguish whether `count_references()` must also seed the pending list or merely count refs by type, working around `setup_revisions()`'s lack of a custom ref-walk callback (resulting in a double ref-walk when revisions are specified).

The series is considered ready for integration: Patrick Steinhardt previously signed off ("this version looks good to me"), and all critical feedback across iterations has been addressed. Accepted non-blocking trade-offs remain: the double ref-walk inefficiency is tolerated for a diagnostic tool; `setup_revision_opt` retains `.def = "HEAD"` and `.revarg_opt = REVARG_COMMITTISH` (Patrick's suggestion to pass `NULL` for broader tree/blob filtering was not adopted); and the `ref^{tree}` test case remains absent. The author retains a long-term commitment to rewrite all tests in `t/t1901-repo-structure.sh` to be hash-agnostic before Git 3.0, though the short-term `SHA1` prerequisite guards are now in place. Future discussion will likely track whether the maintainer queues the patch or revisits the hash-agnostic test modernization commitment.
