This is a substantive review reply on a feature patch (HTTP transport resilience). Patrick Steinhardt responds to Ravi Mistry's `[PATCH v3 2/5]` introducing exponential backoff for HTTP 429 retries when no Retry-After header is present.

Patrick endorses the exponential backoff approach and notes it is properly clamped by `http.maxRetryTime`, but suggests that adding jitter would also be sensible, though not required for this series. He raises two technical nits on the implementation in `handle_rate_limit_retry()` in `http.c`: first, that the new `attempt` parameter is typed as signed `int` when an unsigned type would be more appropriate for a counter; second, that the doubling logic implemented as a `for` loop could be expressed more directly as a single `MIN(http_max_retry_time, delay * (2 << (attempt - 1)))` calculation rather than an iterative loop. The review is concise but engages with the actual algorithm and types, indicating the reviewer examined the code closely. No response from the author is included in this email.
