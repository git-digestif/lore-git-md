This is a review-discussion reply within Patrick Steinhardt's four-patch performance series on reflog expiration during auto-maintenance. Specifically, it is Patrick responding to Karthik Nayak's observation on patch 1/4 that a "Future improvement" comment in `refs/reftable-backend.c` about skipping unchanged records was not removed by the subsequent patch 2/4.

Patrick clarifies that he deliberately left the comment in place because patch 2/4 does not fully address it. While patch 2/4 skips writing a new reftable entirely when no reflog entries changed, the comment refers to a more granular optimization: dropping only the individual entries that were not rewritten while still writing the ones that were. The distinction matters because patch 2/4 optimizes the no-op case, whereas the comment envisions finer-grained per-entry filtering during actual rewrites.

The exchange is a substantive clarification rather than a disagreement about correctness; Karthik had already endorsed the technical approach of the dry-run early return in patch 1/4. This reply simply narrows the scope of what the follow-up patch claims to have achieved, leaving the door open for the more fine-grained optimization to be implemented later.
