Maik Riechert proposed a standalone performance patch that shortens the hot path in `check_removed()` within `diff-lib.c`: when an index entry carries the `CE_FSMONITOR_VALID` bit, the function now returns immediately after `fake_lstat()` instead of also calling `has_symlink_leading_path()`, which performs an `lstat()` on every leading directory component. The motivation is a measured drop in `git diff HEAD` time from 57ms to 26ms on a 100,000-file Linux repository with a warm cache, and the correctness argument rests on `refresh_fsmonitor()` clearing the valid bit for all entries beneath a directory that gets replaced by a symlink.

Junio C Hamano has now reviewed the patch and offered conditional approval, stating that "assuming that the CE_FSMONITOR_VALID bit is trustworthy, the change looks OK." He pointed to existing precedent for trusting the flag in `read-cache.c:refresh_cache_ent()` and `preload-index.c:preload_thread()`, and suggested a minor cleanup to inline the `lstat()` call and drop the now-single-use `stat_err` variable. The series remains under review with no integration-branch status indicated; the only outstanding item is the theoretical question of whether the fsmonitor invalidation invariant covers every leading-path symlink edge case, though Junio's endorsement suggests he finds the reasoning sound.
