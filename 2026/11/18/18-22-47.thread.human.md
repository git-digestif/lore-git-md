Maik Riechert's v2 patch optimizing `git diff` performance with fsmonitor has now been accepted by Junio C Hamano, who announced "Will queue. Thanks." after reviewing the changes. The patch modifies `check_removed()` in `diff-lib.c` to return early for entries marked `CE_FSMONITOR_VALID`, skipping the expensive `has_symlink_leading_path()` check that lstats each leading directory component. This builds on prior work in commit `4f3d6d0261` that eliminated lstat on the file itself, and reports `git diff HEAD` time dropping from 57ms to 26ms on a 100,000-file Linux repository.

Junio's review included one technical correction to the commit message: he noted that the `S_ISDIR()` check does in fact trigger for gitlinks because `fake_lstat()` assigns them `S_IFDIR | 0755` mode, but the code remains safe due to an additional `S_ISGITLINK()` guard. With this clarification noted, Junio moved the patch from "under review" to queued, maintaining his earlier conditional approval that the approach is sound assuming the `CE_FSMONITOR_VALID` bit is trustworthy. The v2 version addressed his stylistic feedback by inlining the `stat_err` variable, and includes three new tests in `t/t7519-status-fsmonitor.sh` covering symlink replacement and deletion detection scenarios.

The thread is now converged with maintainer approval, though the underlying correctness assumption -- that fsmonitor invalidation reliably covers all cases where a leading directory is replaced by a symlink -- remains the load-bearing claim for future scrutiny. No objections or Reviewed-by trailers were recorded beyond Junio's endorsement.
