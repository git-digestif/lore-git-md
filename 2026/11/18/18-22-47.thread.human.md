Maik Riechert has posted v2 of a standalone performance patch that speeds up `git diff` when the fsmonitor daemon is active. The change modifies `check_removed()` in `diff-lib.c` so that index entries marked `CE_FSMONITOR_VALID` return immediately after `fake_lstat()` fills in stat data, skipping the expensive `has_symlink_leading_path()` call (which lstat()s every leading directory component) and the subsequent `S_ISDIR()` check. The argument is that these checks are unreachable for valid entries: if a leading directory were replaced by a symlink, fsmonitor would have reported it and `refresh_fsmonitor()` would have cleared the flag, and gitlinks are never marked valid. The patch cites a reported improvement of `git diff HEAD` dropping from 57ms to 26ms on a Linux tree with 100,000 files and a warm cache.

Junio C Hamano reviewed v1 substantively and conditionally endorsed the approach -- "assuming that the CE_FSMONITOR_VALID bit is trustworthy, the change looks OK" -- while noting that skipping `has_symlink_leading_path()` is a significant win. He also requested a minor cleanup: eliminating the now-single-use `stat_err` variable and inlining the `lstat()` call. V2 incorporates exactly that cleanup but leaves the central correctness assumption unchanged, so the thread remains open on whether fsmonitor invalidation reliably covers every leading-path symlink replacement edge case.
