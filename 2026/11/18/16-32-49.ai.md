This is a **bugfix**, the third and final patch (`[PATCH 3/3]`) in Adrian Ratiu's three-patch series fixing crashes when a submodule is a linked worktree of its repository during recursive operations (`--recurse-submodules` or `submodule.recurse=true`).

The patch modifies `submodule_move_head()` in `submodule.c` to handle the case where a submodule's `.git` file points to a linked worktree git dir (e.g., `.git/modules/sub/worktrees/sub1`) rather than the main submodule git dir. It introduces a new helper `validate_submodule_gitfile_dir()` that uses `get_common_dir_noenv()` to detect linked worktrees, verifies the git dir is located at `<common-dir>/worktrees/<id>` (rejecting forged paths elsewhere with a "is not a worktree of" error), and validates the common dir against the submodule name. When a linked worktree is detected, `submodule_move_head()` skips rewriting the `.git` file to point to the superproject's expected modules path and skips unsetting `core.worktree`, preventing the submodule from being left broken.

The patch adds test coverage in `t/t2405-worktree-submodule.sh` (recursive checkout accepting a submodule worktree in both legacy and `extensions.submodulePathConfig` modes, plus removal behavior) and `t/t7450-bad-git-dotfiles.sh` (rejecting a forged worktree git dir with a commondir file). This completes the series that also replaced a `BUG()` abort with a proper error (patch 1) and fixed a misleading `submodulePathConfig` hint (patch 2). Root cause traces to commit `9cf8547320` which made the previously unreachable validation triggerable. Reported-by: Andreas Wendleder.
