This is a substantive review comment from Junio C Hamano on the v8 feature patch adding revision filtering to `git repo structure`. The email is a reply in the ongoing single-patch thread authored by Mark C. Chu-Carroll.

Junio flags that the newly added tests in `t/t1901-repo-structure.sh` hardcode specific `.disk_size` byte values (e.g., `objects.commits.disk_size=163722`) in their expected output. He notes this makes the tests unnecessarily brittle across different zlib implementations, since compression ratios and resulting on-disk sizes can vary between zlib versions and platforms. This is a legitimate portability concern for the test suite, distinct from the SHA-256 compatibility issue addressed in v8 via `SHA1` prerequisites.

The comment suggests the test expectations should avoid depending on exact compressed sizes, perhaps by using pattern matching or by focusing on structural properties rather than byte counts. No alternative implementation is prescribed, but the observation implies the tests need adjustment to be robust across build environments. This appears to be a new issue not previously raised in earlier versions of the series, or at least one that remains unresolved in v8.
