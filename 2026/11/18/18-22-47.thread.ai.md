Thread identity: single standalone performance patch (not part of a series) authored by Maik Riechert via GitGitGadget, currently under review on the mailing list with no integration branch status indicated.

Core problem or goal: optimize the interaction between `diff-lib` and the fsmonitor daemon by modifying `check_removed()` in `diff-lib.c` so that entries marked `CE_FSMONITOR_VALID` return immediately after `fake_lstat()` fills in stat data, thereby skipping the subsequent `has_symlink_leading_path()` call (which `lstat()`s each leading directory component) and the `S_ISDIR()` check.

Current status: under review; no version iteration yet; maintainer Junio C Hamano has provided conditional approval, stating "assuming that the CE_FSMONITOR_VALID bit is trustworthy, the change looks OK," while noting that avoiding `has_symlink_leading_path()` is a significant win since that function is expensive; no merge or integration branch assignment recorded.

Key technical details: the change touches `diff-lib.c` (`check_removed()`); it relies on the invariant that if a leading directory were replaced by a symlink, fsmonitor would have reported the change and `refresh_fsmonitor()` would have cleared `CE_FSMONITOR_VALID` for all entries beneath it, making the skipped checks unreachable for valid entries; `preload_index()` already trusts the flag by skipping these entries entirely; gitlinks are never marked valid so the `S_ISDIR()` check cannot trigger for them; the patch cites commit `4f3d6d0261` (fsmonitor: skip lstat deletion check during git diff-index, 2021-03-17) as the prior change that eliminated `lstat()` on the file itself for valid entries, leaving only leading-path `lstat()` calls as overhead; reported performance improvement is `git diff HEAD` on Linux with 100,000 files dropping from 57ms to 26ms with a hook reporting no changes and warm cache; three new tests added to `t/t7519-status-fsmonitor.sh` verifying the shortcut behavior when a parent directory is replaced by a symlink without fsmonitor notification, and verifying deletion detection still works when fsmonitor reports the directory (with and without trailing slash); Junio points to precedent for trusting the flag in `read-cache.c:refresh_cache_ent()` and `preload-index.c:preload_thread()`.

Open questions and loose ends: the correctness of assuming fsmonitor invalidation covers all leading-path symlink replacement cases remains the central claim; Junio's acceptance is explicitly conditional on the `CE_FSMONITOR_VALID` bit being trustworthy in all edge cases; he suggests a minor code cleanup -- eliminating the `stat_err` variable (now assigned only once) and inlining the `lstat()` call directly into the `if` condition.

Participant positions: Maik Riechert proposed the optimization; Junio C Hamano reviewed substantively, conditionally endorsing the approach while requesting the `stat_err` variable be inlined; no Reviewed-by, Acked-by, or objections recorded.
