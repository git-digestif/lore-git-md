Thread identity: single standalone performance patch (not part of a series) authored by Maik Riechert via GitGitGadget, currently under review on the mailing list with no integration branch status indicated.

Core problem or goal: optimize the interaction between `diff-lib` and the fsmonitor daemon by modifying `check_removed()` in `diff-lib.c` so that entries marked `CE_FSMONITOR_VALID` return immediately after `fake_lstat()` fills in stat data, thereby skipping the subsequent `has_symlink_leading_path()` call (which `lstat()`s each leading directory component) and the `S_ISDIR()` check.

Current status: under review; no version iteration yet; no maintainer decision recorded.

Key technical details: the change touches `diff-lib.c` (`check_removed()`); it relies on the invariant that if a leading directory were replaced by a symlink, fsmonitor would have reported the change and `refresh_fsmonitor()` would have cleared `CE_FSMONITOR_VALID` for all entries beneath it, making the skipped checks unreachable for valid entries; `preload_index()` already trusts the flag by skipping these entries entirely; gitlinks are never marked valid so the `S_ISDIR()` check cannot trigger for them; the patch cites commit `4f3d6d0261` (fsmonitor: skip lstat deletion check during git diff-index, 2021-03-17) as the prior change that eliminated `lstat()` on the file itself for valid entries, leaving only leading-path `lstat()` calls as overhead; reported performance improvement is `git diff HEAD` on Linux with 100,000 files dropping from 57ms to 26ms with a hook reporting no changes and warm cache; three new tests added to `t/t7519-status-fsmonitor.sh` verifying the shortcut behavior when a parent directory is replaced by a symlink without fsmonitor notification, and verifying deletion detection still works when fsmonitor reports the directory (with and without trailing slash).

Open questions and loose ends: the correctness of assuming fsmonitor invalidation covers all leading-path symlink replacement cases is the central claim awaiting review; no reviewer feedback recorded yet.

Participant positions: Maik Riechert is the sole participant to date, proposing the optimization; no Reviewed-by, Acked-by, or objections recorded.
