Core problem or goal: optimize the interaction between `diff-lib` and the fsmonitor daemon by modifying `check_removed()` in `diff-lib.c` so that entries marked `CE_FSMONITOR_VALID` return immediately after `fake_lstat()` fills in stat data, thereby skipping the subsequent `has_symlink_leading_path()` call (which `lstat()`s each leading directory component) and the `S_ISDIR()` check.

No merge to `master` or graduation to `next` has been recorded.

Key technical details: the change touches `diff-lib.c` (`check_removed()`); it relies on the invariant that if a leading directory were replaced by a symlink, fsmonitor would have reported the change and `refresh_fsmonitor()` would have cleared `CE_FSMONITOR_VALID` for all entries beneath it, making the skipped checks unreachable for valid entries; `preload_index()` already trusts the flag by skipping these entries entirely. Junio corrected the commit message's claim about gitlinks: `fake_lstat()` calls `st_mode_from_ce()`, which assigns `S_IFGITLINK` entries the mode `S_IFDIR | 0755`, so the `S_ISDIR()` check does in fact trigger for gitlinks, but the check is safe because an additional `S_ISGITLINK()` guard prevents `repo_resolve_gitlink_ref()` from being called. The patch cites commit `4f3d6d0261` (fsmonitor: skip lstat deletion check during git diff-index, 2021-03-17) as the prior change that eliminated `lstat()` on the file itself for valid entries, leaving only leading-path `lstat()` calls as overhead; v2 removes the `stat_err` variable and inlines the `lstat()` call directly into the `if` condition as Junio requested; reported performance improvement is `git diff HEAD` on Linux with 100,000 files dropping from 57ms to 26ms with a hook reporting no changes and warm cache; three new tests added to `t/t7519-status-fsmonitor.sh` verifying the shortcut behavior when a parent directory is replaced by a symlink without fsmonitor notification, and verifying deletion detection still works when fsmonitor reports the directory (with and without trailing slash); Junio points to precedent for trusting the flag in `read-cache.c:refresh_cache_ent()` and `preload-index.c:preload_thread()`.

Open questions and loose ends: the correctness of assuming fsmonitor invalidation covers all leading-path symlink replacement cases remains the central unresolved claim; Junio's acceptance is explicitly conditional on the `CE_FSMONITOR_VALID` bit being trustworthy in all edge cases; v2 addressed only the stylistic cleanup and the gitlink mode clarification, leaving the substantive correctness assumption unchanged for future reviewers to scrutinize.
