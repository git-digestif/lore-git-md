This is a performance patch, specifically the first of four in Patrick Steinhardt's series addressing slow reflog expiration during auto-maintenance. It targets the reftable ref backend to avoid writing a new table to disk when `git reflog expire` is invoked with `--dry-run`. In `refs/reftable-backend.c`, the function `reftable_be_reflog_expire` previously called `reftable_addition_commit` unconditionally, meaning even a dry-run that only prints entries would commit a new reftable to disk. The patch adds an early return when the `EXPIRE_REFLOGS_DRY_RUN` flag is set, skipping the `reftable_addition_commit` call and the subsequent write, since the on-disk state is not supposed to change. Benchmarks on git.git show this yields roughly an 11 percent wall-time reduction for `git reflog expire --all --dry-run` (from about 414 ms to 369 ms) with negligible memory change. This patch is a prerequisite optimization for the series' main goal: patch 3/4 fixes the reachability logic in `builtin/gc.c` that was causing `git maintenance run --auto` to spawn unnecessary `git reflog expire` processes, while patch 2/4 applies the same skip-write logic for no-op expirations. Reviewers should note the changed control flow in `reftable_be_reflog_expire` where the dry-run check now precedes the `reftable_addition_commit` invocation.
