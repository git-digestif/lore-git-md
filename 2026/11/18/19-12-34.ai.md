This is a substantive technical reply in the ongoing review thread for the bounds-safety patch that adds `display_mode_esc_sequence_len_counted(const char *s, size_t len)` to `utf8.c`. Andy Koppe responds to Dirk Gouders's refined question about whether the parser can safely accept colon-separated subparameters without a finite state machine.

Koppe confirms that the complete regular expression for SGR (Select Graphic Rendition) sequences is `"\033\[[0-9:;]*m"`, noting that Git does not need to parse the individual parameter values, only to recognize valid sequence boundaries. He directly answers Gouders's probe: `"\033[:;m"` is indeed a valid SGR sequence, comprising two parameters where the first contains two empty subparameters and the second is an empty parameter. This supports his earlier argument that a simple character-class expansion from `[0-9;]` to `[0-9:;]` suffices without introducing new parser states.

Koppe also clarifies the ECMA-48 notation referenced in the discussion, explaining that `3/0` denotes byte `0x30` (the character `'0'`) and `3/11` denotes `0x3B` (`';'`), which makes the standard's parameter syntax more legible once decoded.

The exchange leaves the colon-separator question unresolved. While Koppe establishes that `"\033\[[0-9:;]*m"` captures the full syntactic range of ECMA-48 SGR sequences, no decision has been recorded on whether the patch should extend the accepted alphabet to include colons.
