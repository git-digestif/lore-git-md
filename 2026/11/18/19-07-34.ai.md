This is the first patch of a two-patch v4 series (cover letter not shown here) fixing `git maintenance run` lock acquisition handling in `builtin/gc.c`, with corresponding tests in `t/t7900-maintenance.sh`. It responds directly to a regression in v3 where background scheduled maintenance runs were incorrectly failing when the lock was held.

The patch establishes three distinct behaviors in `maintenance_run_tasks()` when `repo_hold_lock_file_for_update()` fails to acquire `objects/maintenance.lock`. Manual invocations now return -1 (non-zero exit) and emit an error via the shared `unable_to_lock_message()` helper, matching `git gc`'s fail-fast behavior, unless `--quiet` suppresses the diagnostic while still failing. Automatic mode (`--auto`) warns and exits 0, while the new v4 addition is a check for `opts->schedule` that keeps scheduled background runs completely silent and exiting 0, preventing the v3 regression where `git maintenance start`-initiated runs would fail when another maintenance process held the lock.

Additionally, `fetch_remote()` now appends `--no-auto-maintenance` to the internal `git fetch` command line so the prefetch task does not trigger nested automatic maintenance or emit spurious lock warnings while the parent process holds the lock. The tests cover all four lock-failure scenarios -- auto warning, manual failure, manual quiet suppression, and scheduled silent skip -- plus verification that child fetches receive the new flag and that prefetch with `--no-quiet` produces no stderr output.

Key names and symbols a follow-up summarizer should recognize: `maintenance_run_tasks()`, `fetch_remote()`, `unable_to_lock_message()`, `opts->schedule`, `opts->auto_flag`, `opts->quiet`, the lock path `objects/maintenance.lock`, and the test file `t/t7900-maintenance.sh`. The likely points of contention remain whether the `opts->schedule` branch fully resolves the background-run regression Aniket Gupta reported, and whether the Trace2 `"lock/skip"` event coverage (introduced in patch 2 of this series, not shown here) for scheduled runs meets maintainer expectations.
