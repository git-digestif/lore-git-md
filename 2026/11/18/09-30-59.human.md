This is a cover letter for a four-patch performance series that also fixes a bug in auto-maintenance. Patrick Steinhardt identified that several commands were hanging for nearly a second after completing because `git maintenance run --auto` was needlessly spawning `git reflog expire`. The root cause lies in how the auto-condition for reflog expiration evaluates reachability: it incorrectly treated every reflog entry as pointing to an unreachable commit, causing all entries to be counted against `gc.reflogExpireUnreachable` instead of `gc.reflogExpire`. This overcounting made the auto-condition trigger expiration on every maintenance run.

The series addresses this in two layers. The final patch fixes the actual logic in `builtin/gc.c` so that the `--auto` condition only considers `gc.reflogExpire` for reachable entries, which eliminates the spurious expiration entirely. The first two patches separately optimize the reftable backend so that a dry-run or no-op `git reflog expire` does not write a new table, and the fourth patch corrects a typo in the documentation for `maintenance.reflog-expire.auto`.

Benchmark results on the git.git repository show the impact clearly: `git maintenance run --auto` dropped from a mean of 853 ms to 18.6 ms, a 45.8x speedup, with memory usage also falling by about 31%. The commit message is thorough, includes concrete before-and-after measurements, and clearly separates the root-cause fix from the backend optimizations, making this a well-crafted contribution that directly addresses a user-visible performance problem.
