This is a **documentation** patch -- specifically a comment correction -- and it is patch 2 of 4 in Dirk Gouders' v2 series fixing bounds handling in `utf8_strnwidth()` and `utf8_width()`.

The patch changes a single line in the comment block above `utf8_strnwidth()` in `utf8.c` (around line 218): where the comment previously claimed the function returns `strlen()` when the input is not valid UTF-8, it now correctly states that it returns the `len` argument. This is a carry-over from v1 and is purely cosmetic; it does not alter behavior. The surrounding series (patches 1, 3, and 4) introduces `display_mode_esc_sequence_len_counted()` and adds boundary guards to prevent reads past the end of the buffer in both `utf8_strnwidth()` and `utf8_width()`, but this particular patch only fixes the misleading doc comment.
