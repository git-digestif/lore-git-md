This is a **bugfix** to the utf8 display-width code, specifically patch 3 of 4 in a v2 series (the cover letter was not provided, so the broader series goal is unclear from this email alone).

The patch fixes `utf8_strnwidth()` in `utf8.c` for the case where ANSI escape sequences (like SGR color codes) consume the entire remaining string within the given length boundary. Previously, the function would skip escape sequences but could proceed to call `utf8_width()` even when the skip had advanced the pointer past the end of the string, potentially reading out of bounds or computing a nonsense width. The fix adds a bounds check after skipping ANSI sequences and breaks out of the loop if the string boundary has been reached.

The change is small and targeted, and the author includes new clar unit tests in `t/unit-tests/u-utf8-width.c` that exercise exactly these corner cases -- verifying that a string consisting of an SGR sequence followed by text returns the correct visible width when the length limit falls inside the escape sequence, at its end, or just after it. The patch looks clean and well-tested for a narrow edge case in terminal-width calculation.
