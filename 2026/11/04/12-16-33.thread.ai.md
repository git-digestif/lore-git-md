Thread identity: Bugfix series for loose object database (ODB) cache invalidation during `git merge`. Two-patch series (`[PATCH v1 1/2]` and `[PATCH v1 2/2]`), initial submission by Patrick Steinhardt.

Core problem or goal: Fix a bug where newly written merged blobs in `git merge` cannot be read back due to stale loose object cache entries, causing Git to incorrectly assume the objects are missing locally and triggering unnecessary, failing backfill fetches from promisor remotes. The fix targets incomplete cache invalidation logic for loose objects, specifically the subdirectory bitmap handling in `odb/source-loose.c`.

Current status: Approved for merging. The series consists of a preparatory refactoring (patch 1/2) and the actual bugfix (patch 2/2). The refactoring extracts the subdirectory bitmap retrieval logic into a reusable function, `subdir_seen_bitmap()`, to avoid code duplication in the subsequent fix. Patch 2/2 implements the core fix by introducing `loose_cache_mark_seen()`, which updates the loose object cache after writing new objects, ensuring subsequent existence checks reflect the current state of the object store. Junio C Hamano’s acknowledgment confirms the series is ready for integration, with no further technical concerns or open questions.
