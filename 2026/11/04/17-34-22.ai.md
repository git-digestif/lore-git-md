This is the second patch in a two-patch series (v3 2/2) that adds Trace2 event logging for `git maintenance run --auto` when it skips maintenance due to an existing lock. The patch is narrowly scoped to diagnostic observability and complements the behavioral change introduced in the first patch (v3 1/2), which aligned manual `git maintenance run` lock failures with `git gc`'s fail-fast behavior.

The implementation emits a Trace2 data event under the `"maintenance"` category with the event name `"lock/skip"`. The event payload includes the error string (`strerror(err)`) and the raw `errno` value, allowing administrators to distinguish between different failure modes (e.g., "File exists" vs. "Permission denied"). The event is emitted unconditionally in `--auto` mode, even when `--quiet` is specified, ensuring that diagnostic data is always available for monitoring tools while respecting the user's preference for suppressing terminal output.

The test coverage verifies both the event emission and the preservation of the lock file (maintaining the existing design that stale locks require manual intervention). The test uses `GIT_TRACE2_EVENT` to capture the event and checks for the expected `"File exists"` reason when the lock file is present. The test infrastructure is minimal and focused, avoiding unnecessary complexity.

This patch is uncontroversial and ready for integration. It addresses the last remaining piece of feedback from Patrick Steinhardt's v2 review—ensuring the Trace2 event format is consistent and useful—without introducing new behavioral changes or cross-subsystem interactions. The series as a whole is now mechanically complete and awaits final review.
