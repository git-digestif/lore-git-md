This is a brief follow-up in the ongoing bugfix thread targeting Git’s object quarantine performance regression. The patch, already cooking in `next`, aims to prevent Git from listing its own refs as alternate refs during quarantine, which currently causes a measurable slowdown—especially in repositories with many hidden refs.

Junio chimes in to approve Kristofer Karlsson’s plan to reword the commit message. The current phrasing overgeneralizes how alternate refs are used (focusing narrowly on the connectivity check’s "negative tips" behavior), but the `rev-list` option is more general. Kristofer’s proposed adjustment aligns the patch with Git’s existing behavior of ignoring the object directory itself when loading alternates, ensuring the fix doesn’t inadvertently break other use cases. This is a minor but important clarification, not a technical change to the patch itself.

The thread has already converged on Jeff King’s commondir comparison approach as the definitive short-term fix—a minimal, 10-line change that directly compares the alternate’s path against the repository’s commondir in `refs_from_alternate_cb()`. This supersedes Kristofer’s v2 patch (which is already in `next`) and avoids quarantine-specific logic entirely. Junio’s approval here is procedural, signaling that the reworded commit message will satisfy his earlier concerns about overgeneralization. The patch’s core logic remains unchanged, and its performance benefits (a 67.7% speedup in repositories with 200,000 hidden refs) are well-documented.

No new technical objections or alternatives are raised in this email. The discussion is now focused on finalizing the commit message before the commondir comparison implementation lands. The patch is compatible with Patrick Steinhardt’s concurrent ODB abstraction work and has received explicit endorsements from both Justin Tobler (ODB maintainer) and Jeff King.
