This is the first patch in the v4 series introducing the `%gb` format placeholder for `git log -g` and `git reflog`. It is a refactoring patch that names the hard-coded strings used in reflog messages for branch switches, renames, and rebase steps, consolidating them into `#define` constants in `reflog.h`.

The patch touches seven files (`builtin/branch.c`, `builtin/checkout.c`, `builtin/rebase.c`, `object-name.c`, `reflog.h`, `sequencer.c`, and `wt-status.c`), replacing literal strings like `"checkout: moving from "` and `"Branch: renamed "` with named constants (`REFLOG_SWITCH_PREFIX`, `REFLOG_RENAME_PREFIX`, etc.). This preparatory work is explicitly tied to the upcoming `%gb` feature, which will parse these messages to determine the branch context for each reflog entry. The refactoring does not change behavior but makes the code more maintainable and reduces the risk of future desynchronization when the `%gb` logic is added.

The constants introduced in `reflog.h` cover all reflog message patterns used by branch switches (`checkout: moving from ...`), branch renames (`Branch: renamed ...`), and rebase steps (`start`, `finish`, `abort`, `returning to ...`, and `checkout ...`). The patch also updates `object-name.c` and `wt-status.c`, which previously hard-coded the switch prefix for parsing reflog messages, to use the new constants. This ensures consistency across the codebase when reading or writing reflog messages.

The motivation for this refactoring is clear: the `%gb` feature will need to parse these messages, and having them defined in one place avoids duplicating the strings and reduces the risk of errors when the format changes. The patch addresses Junio C Hamano’s earlier concern about alignment with future directions (e.g., translatable reflog messages) by making the strings easier to refactor later, though it does not split them into human-readable and machine-readable parts as Junio suggested.

This patch is well-scoped and uncontroversial, serving as a necessary foundation for the `%gb` feature in the next patch. The changes are mechanical and thoroughly tested, with no behavioral impact. The series as a whole remains under review, with Junio yet to weigh in on v4.
