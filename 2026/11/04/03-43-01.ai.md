This is the v5 iteration of a bugfix patch that ensures commit abbreviations in submodule diff headers are checked against the submodule's object database rather than the superproject's. The patch is part of the Git libification effort and addresses a correctness issue where the same abbreviated commit ID could refer to different objects in the two repositories.

The core change remains unchanged from v4: it introduces `strbuf_repo_add_unique_abbrev()` to replace `strbuf_add_unique_abbrev()` in `submodule.c`, using the submodule repository (`sub`) when available and falling back to `o->repo` from the diff options. This eliminates reliance on the global `the_repository`. The code is refactored to select the repository once at the start of the function and reuse it, avoiding duplicated `if/else` logic.

The test coverage is now fully hash-agnostic, using `test_oid_cache` to provide expected abbreviated commit IDs for both SHA-1 and SHA-256. This addresses Junio's feedback from v4 about the unnatural split between SHA-1 and SHA-256 test coverage, merging the previously separate second patch into the first. The test constructs a collision scenario between superproject and submodule commit IDs and verifies the output uses the correct (submodule) abbreviation.
