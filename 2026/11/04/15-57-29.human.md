This is a bugfix patch in Patrick Steinhardt’s ongoing commit-graph refactoring series, which is part of the larger ODB abstraction effort. It addresses a latent issue where the `verify_commit_graph()` function incorrectly reused the `COMMIT_GRAPH_WRITE_PROGRESS` flag from the write path, creating a potential collision if future verify-specific flags happen to share the same bit value.

The patch introduces a new `COMMIT_GRAPH_VERIFY_PROGRESS` flag and converts the verify flags into a proper enum for type safety. The change is confined to three files: `commit-graph.h` (where the enum is defined), `commit-graph.c` (where the verify function is updated to use the new enum), and `builtin/commit-graph.c` (where the `git commit-graph verify` command’s flag handling is adjusted). The diff is small (11 insertions, 6 deletions) and mechanical, replacing the old integer-based flags with the new enum.

This is clearly a correctness fix—preventing a future footgun—rather than a feature or refactoring. The commit message is concise and explains the risk (flag value collision) and the solution (dedicated verify flags). No new behavior is introduced, and the change is unlikely to be controversial. If the series as a whole is deemed worthwhile, this patch should be uncontroversial.
