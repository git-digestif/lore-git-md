This is a bugfix patch targeting the fsmonitor subsystem, specifically addressing a long-standing integration issue between fsmonitor and the untracked cache.

The problem occurs when fsmonitor fails or returns a trivial response, causing Git to disable fsmonitor for the untracked cache but leaving existing untracked cache entries marked as valid. This creates a situation where new untracked files can remain invisible to commands like `git status` because the cache isn't properly invalidated. The bug has existed since fsmonitor was introduced in 2017.

Derrick Stolee's fix adds a new `untracked_cache_invalidate_all()` function that recursively invalidates all untracked cache directories when fsmonitor fails, ensuring the index is properly updated. The patch includes two new tests that validate this behavior using the fsmonitor hook implementation, though the fix applies to both hook and builtin versions.

Performance testing shows no degradation under normal conditions, though Stolee notes that initial testing on Linux revealed a regression when the system's `max_user_watches` was too low - this was resolved by increasing the watch limit. The commit message provides clear reproduction steps and acknowledges AI assistance in developing the test cases, though Stolee emphasizes his significant human editing and validation.

The patch touches core fsmonitor logic in `fsmonitor.c`, adds the new invalidation function in `dir.c`, and extends the test suite. It appears well-motivated and thoroughly tested, addressing what seems to be a real-world issue in large repositories.
