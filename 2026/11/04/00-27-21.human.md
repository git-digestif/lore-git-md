This is a bugfix patch for `git push`. It addresses two related issues with `--force-with-lease` when pushing to a remote *group* (a feature introduced in Git 2.56.0 that allows pushing to multiple remotes at once).

The first bug is straightforward: a bare `--force-with-lease` (with no refspec) was silently ignored when pushing to a remote group, causing the push to fail as if `--force` had never been specified. The second bug is subtler: when using `--force-with-lease=<ref>:`, which is meant to protect against overwriting a branch that *doesn’t exist* on the remote, the check was incorrectly using the local remote-tracking branch’s state, which is almost always up-to-date with the remote after a fetch. This could allow an unintended overwrite.

The patch fixes both issues by properly forwarding the `--force-with-lease` options in `push_multiple()`. The first case now correctly passes the bare option, and the second case now explicitly appends a colon to the refspec to preserve the “expect absent” semantics. The commit includes thorough test coverage for both scenarios, using a setup with two bare remotes to verify the behavior across all members of the remote group.

The motivation is clear, the reproduction case was provided by a reporter, and the fix is minimal and targeted. The patch is based on `maint`, indicating it’s intended for backporting to the current stable release. This looks like a well-crafted, uncontroversial bugfix that addresses a real-world footgun.
