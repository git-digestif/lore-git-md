This is an Outreachy internship proposal for a project targeting Git's ongoing effort to reduce global state, specifically focusing on pathspec code as part of the broader libification goal.

The proposal comes from Srujith Poojary, a BCA graduate with some prior contributions to Git (test script modernization, safe integer arithmetic in diff-delta, and submodule-related changes). The work centers on refactoring `find_pathspecs_matching_skip_worktree()` in `pathspec.c`, which currently accesses the index via the global `the_repository->index` instead of receiving it as an explicit parameter. The author identifies four call sites (in `pathspec.c`, `builtin/add.c`, and `builtin/rm.c`) that would need updating and proposes two API approaches: either adding an explicit `struct index_state *istate` parameter to the helper, or extending the existing `find_pathspecs_matching_against_index()` API with a new `ps_skip_worktree_action` option.

The 13-week plan is detailed and incremental, starting with design confirmation, then implementation, regression testing, compatibility validation, and potential follow-up work on other pathspec functions like `init_pathspec_item()`. The author acknowledges risks around edge cases (sparse-checkout/sparse-index compatibility), API changes affecting multiple callers, and the possibility that the proposed scope might overlap with existing upstream work. A key technical challenge is designing a regression test that verifies the helper uses the caller-provided index rather than the global one, though the author notes this depends on Git's test infrastructure feasibility.

The proposal is well-researched, with clear boundaries (no promise to rewrite the entire pathspec subsystem or remove all global state) and a focus on preserving existing behavior. It directly aligns with the `the_repository` removal effort led by René Scharfe and others, though the author emphasizes this is a focused contribution rather than a comprehensive solution. The tone is appropriately cautious, emphasizing discussion with mentors and maintainers before expanding scope.
