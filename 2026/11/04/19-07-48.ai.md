This is a bugfix targeting the pack-objects/path-walk subsystem. Derrick Stolee identifies a regression introduced in Git 2.55.0 by commit 5111520e2a1 ("path-walk: support `tree:0` filter", 2026-05-22). The bug causes missing objects when a tagged tree contains a blob at a path already visited by a prior tree batch, because the path-walk machinery refuses to revisit paths already recorded in `path_stack_pushed`.

The fix is minimal: in `path-walk.c`, the code now removes a path from `path_stack_pushed` when consuming its queue entry, allowing new objects to be discovered at that path later. The commit message explains that this preserves the existing visit priorities (tagged trees still expand after commit root trees) while fixing the object-dropping regression. A new test in `t/t7700-repack.sh` creates a commit and an annotated tree tag with distinct blobs at the same path, repacks with `--path-walk`, and runs `git fsck --connectivity-only` to verify no objects are lost.

The patch is well-motivated, cites the exact commit that introduced the regression, and includes a clear reproduction case. The change itself is a single line in the core logic plus a comment update, making it easy to review. The test is thorough and directly exercises the edge case. This looks like a serious, well-crafted fix for a real-world issue (the torvalds/linux repository triggered it).
