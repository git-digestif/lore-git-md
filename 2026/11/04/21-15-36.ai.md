This is a feature patch (v4) that adds the `%gb` format placeholder to `git log -g` and `git reflog`, allowing users to see which branch each reflog entry was recorded on. The series is part of an ongoing effort to improve reflog usability, replacing earlier proposals for dedicated flags (`--operations` and `--historical-branch`) with a composable format specifier that aligns with Git’s decoration system.

The v4 iteration fixes a regression in branch-name detection when `GIT_REFLOG_ACTION` is set, which previously caused `%gb` to misinterpret reflog messages during rebase operations (e.g., labeling entries as `"sequencer-delete-REBASE_HEAD"` instead of the correct branch). The fix introduces a new helper function, `skip_rebase_checkout()`, to handle non-standard reflog messages (e.g., `"sync switch: checkout ..."`). The commit message for the `%gb` patch has also been reworded for clarity, though the core functionality remains unchanged from v3.

The series touches 12 files, including core reflog-walking logic (`reflog-walk.c`, `revision.c`), built-in commands (`builtin/rebase.c`, `builtin/checkout.c`), and documentation. The preparatory patch (1/2) refactors hard-coded reflog message strings into `#define` constants in `reflog.h`, explicitly tying the refactoring to the `%gb` feature. The test suite (`t/t1414-reflog-walk.sh`) has been expanded to cover the `GIT_REFLOG_ACTION` regression, adding 137 lines of new tests. No on-disk format changes are introduced, and the feature is additive—users must opt in via `--format='%h %gb %gd %s'`.

The series addresses all prior feedback, including Phillip Wood’s review identifying the `GIT_REFLOG_ACTION` regression and Junio C Hamano’s concern about alignment with future directions (e.g., translatable reflog messages). The broader architectural debate—whether to refactor multi-step commands to work on detached HEAD by default or change `git reflog`’s default behavior—remains unresolved, but this series does not engage with it. Harald Nordgren’s separate proposal to make `git reflog @{0}` the default output is also untouched.

The implementation appears well-scoped and thoroughly tested, with clear motivation tied to real-world pain points (e.g., tracking branch history across renames, obscured reset points during rebasing). The `%gb` placeholder is a targeted improvement that avoids altering default behavior, reducing regression risk. The series is ready for maintainer review, though Junio has not yet weighed in on v4.
