This is a **substantive review** of Aaron Plattner’s bugfix patch that preserves `WWW-Authenticate` headers across HTTP redirects. Jeff King (Peff) engages deeply with the security implications and design choices, offering a nuanced assessment that both validates the fix and raises minor concerns about its implementation.

The core issue remains clear: Git loses authentication challenges when following redirects, breaking OAuth2 and other bearer-token flows. Peff confirms the problem is real and the fix directionally correct, but questions whether `wwwauth_headers` belong in the credential struct at all. He suggests an alternative—pulling them out entirely—but acknowledges the patch’s approach is the "path of least resistance" and unlikely to introduce security risks, since the headers already come from the server Git is redirecting to.

On implementation, Peff mildly prefers the v1’s inline logic over v2’s new `credential_update_url()` helper, arguing the helper’s safety depends on context only the HTTP layer currently understands. He also spots a defensive coding opportunity: the `strvec_clear()` at the end of the helper is redundant (since `credential_from_url()` always blanks the field) and could mask bugs; he suggests replacing it with a `BUG()` check to enforce that assumption.

The review is **tested in spirit**—Peff doesn’t claim to have run the code, but his analysis of the HTTP flow and credential lifecycle is thorough. Matthew Cheetham, the original author of the `wwwauth` feature, is cc’d for additional perspective. No merge status change yet; the patch remains in `seen` pending further review.
