This is an Outreachy applicant's RFC for the promisor remote fetch ordering project.

Yopa Nelly, working with mentor Kaartic Sivaraam, is exploring how to let users control the order in which Git tries promisor remotes when fetching missing objects. Currently, remotes are tried in config-file order, with the `extensions.partialClone` remote always moved to the end, and there is no way to override this.

She proposes two config shapes: a numeric priority per remote (`remote.<name>.promisorPriority`) or a global ordered list (`promisor.fetchOrder`). She leans toward the list because it is easier to read, easier to override in layered config files, and avoids the ambiguity of how to handle unset priorities. The list also maps naturally to the existing linked-list structure in `promisor-remote.c`.

Three open questions she flags: (1) whether to error, warn, or silently ignore a non-promisor remote listed in the order; (2) whether an explicit entry in the list should override the automatic move of `extensions.partialClone` to the end; and (3) whether different fetch orders might be needed depending on which remote is being fetched from. She is looking for feedback before writing code.
