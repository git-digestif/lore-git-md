This thread is about a regression fix in Git 2.55.0 that causes objects to be lost when a tagged tree revisits a path already processed by the pack-objects/path-walk machinery. The issue was introduced by commit 5111520e2a1 ("path-walk: support `tree:0` filter") in May 2026. Derrick Stolee authored a minimal patch that removes paths from the `path_stack_pushed` set when their queue entries are consumed, allowing later objects at the same path to be discovered. The fix includes a new test in `t/t7700-repack.sh` to verify the fix.

The patch has received a surface-level "LGTM" from Taylor Blau but has not yet been scrutinized by reviewers familiar with the path-walk subsystem. Junio C Hamano acknowledged the patch and its review but did not provide additional feedback or indicate a merge decision. The patch remains under review, and while it is well-motivated and self-contained, it lacks substantive technical review. No open questions or loose ends have been identified, and the fix is targeted and minimal, touching only `path-walk.c` and the test suite.
