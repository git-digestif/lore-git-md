This thread is about a proposed feature to let users control the order in which Git tries multiple promisor remotes during lazy fetches. The patch, now at v2, was submitted by Yopa Nelly, an Outreachy contributor, and addresses earlier feedback about crashes and architectural issues. However, the discussion has hit two roadblocks: a key design question about how the new client-side configuration should interact with server-side promisor remote advertisements, and process concerns related to Outreachy.

The technical core of the patch is sound—it adds a `promisor.fetchOrder` config key that lets users specify a preferred order for promisor remotes, replacing the current implicit order. The v2 patch fixes earlier crashes and includes documentation, but Junio C Hamano has raised a high-priority question about whether this client-side setting should override, merge with, or ignore server-side suggestions. Christian Couder, the promisor-remote maintainer, hasn’t yet weighed in, leaving this unresolved. Meanwhile, Kaartic Sivaraam suggested treating the current patch as an RFC to discuss the design more broadly, and Yopa Nelly has agreed to pause work until Outreachy selections are finalized. This means the thread is effectively on hold, with the design question still open and no immediate path forward.
