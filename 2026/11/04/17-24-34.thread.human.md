This thread is about a new feature allowing users to specify the order in which Git tries multiple promisor remotes during lazy fetches. Yopa Nelly, an Outreachy contributor, proposed the patch to replace the current implicit ordering (based on configuration file order) with an explicit, user-configurable list via the `promisor.fetchOrder` config key.

The patch is under review and has hit a critical issue: Tanga Joris reported a crash (`BUG: string-list.c`) caused by a mismatch in `string_list` initialization and usage. Beyond the crash, the review also highlights architectural concerns—the file-static `fetch_order` list accumulates values across config files and is shared across all repositories in the process, which conflicts with the per-repository nature of the rest of the promisor config. Additionally, the documentation in `Documentation/config/promisor.adoc` is missing, and there’s a minor indentation nit. Tanga suggests reusing the existing `t0410-partial-clone.sh` test file for coverage, which already exercises multiple promisor remotes.

The patch is not yet ready for merging. The crash is the most urgent blocker, but the architectural issues and missing documentation will also need to be addressed before the feature can proceed. Yopa Nelly has not yet responded to the feedback, so the next steps depend on how they incorporate these changes.
