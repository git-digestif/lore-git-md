This thread is about Yopa Nelly’s Outreachy patch adding a `promisor.fetchOrder` configuration option, which lets users explicitly specify the order in which Git tries multiple promisor remotes during lazy fetches. The v2 patch addressed earlier feedback—fixing a crash, avoiding a shared global state, and adding documentation—but still lacks test coverage and leaves some design questions open.

The key development is Junio’s query to Christian Couder about how this client-side configuration interacts with the server-side mechanism that advertises preferred promisor remotes. Currently, the patch treats the two as independent, but Junio flags this as a potential conflict or gap that needs resolution before the feature can be merged. Christian’s response will likely determine whether the patch needs further changes or if the two mechanisms can coexist as-is.

The patch itself is technically sound for its immediate goal, but the server-side interaction question adds a new dimension to the review. Yopa has addressed prior feedback on process (commit message style) and implementation (crash fixes, per-repository isolation), but the Outreachy process question—whether an RFC was required—remains unresolved. Kaartic’s concern about skipping the RFC phase is still open, though the patch is now effectively serving as a prototype for that discussion. No other reviewers have weighed in on v2 yet.
