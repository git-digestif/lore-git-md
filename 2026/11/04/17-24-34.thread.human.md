This thread is about a feature patch from Outreachy contributor Yopa Nelly that adds a `promisor.fetchOrder` configuration option, letting users specify the order in which Git tries multiple promisor remotes during lazy fetches. The initial version had critical flaws—a crash in `string-list.c` and a file-static list that broke per-repository isolation—but the just-posted v2 fixes these issues. The new version stores the parsed order in `struct promisor_remote_config` and re-parses it on each config read, ensuring proper isolation. Documentation has been added, but test coverage is still missing.

The core behavior remains the same: users provide a comma-separated list of remote names, and Git tries those first (in the specified order) before falling back to the remaining remotes in their original configuration order. The patch now avoids the v1 crash by using `string_list_init_nodup()` and properly clearing the list during config reinitialization. Reviewer Tanga Joris had identified the architectural and crash issues in v1, and those concerns are now addressed. However, Kaartic Sivaraam’s process-related questions—whether the patch bypassed the expected RFC phase for Outreachy microprojects and whether the commit message complies with project guidelines—remain unresolved. The patch is now technically sound enough for substantive review, but the lack of tests and lingering process questions could still hold it up.
