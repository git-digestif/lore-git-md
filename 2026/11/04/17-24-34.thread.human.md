This thread is about a patch from Outreachy contributor Yopa Nelly that adds a `promisor.fetchOrder` configuration option, letting users specify the order in which Git tries multiple promisor remotes during lazy fetches. The patch is currently under review and has not been revised yet.

The implementation has two serious issues: it crashes due to a mismatch in string-list handling, and it uses a file-static list that violates per-repository config semantics, causing the order to leak across repositories and config files. There’s also no test coverage or documentation for the new config key. Tanga Joris provided a substantive review identifying these problems and the missing pieces; the author acknowledged the test gap and offered to address it later.

Kaartic Sivaraam’s recent review focuses on the commit message and process, not the code. He notes the message mixes technical detail with conversational language, violating project guidelines, and questions whether the patch should have gone through an RFC phase for the microproject. The review doesn’t engage with the technical issues or the feature’s merit, leaving the patch’s readiness unchanged. The author hasn’t yet responded to this feedback.
