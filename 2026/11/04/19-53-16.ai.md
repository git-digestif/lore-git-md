This is the third patch in Farid Zakaria’s v2 series fixing a race condition in the credential-cache daemon. It prevents a second daemon from hijacking the socket of an already-running daemon by switching from `unix_stream_listen()` to `unix_ss_create()`, the same safe socket-creation helper used by the simple-ipc subsystem. If another daemon is already listening, the new daemon prints "ok" and exits, allowing its client to communicate with the existing daemon instead of unlinking the socket and stranding credentials.

The patch touches `builtin/credential-cache--daemon.c` and adds a new test in `t/t0301-credential-cache.sh` that verifies the "ok" response and confirms credentials are preserved across concurrent daemon starts. The implementation registers the socket with the `tempfile` API, which Junio has flagged as architecturally unsafe because it bypasses `unix_ss_was_stolen()` and risks socket removal by a dying daemon that no longer owns it. The author has not yet addressed this concern in v2, but the core logic—using `unix_ss_create()` to safely handle concurrent socket creation—is confirmed correct by both Jeff King and Patrick Steinhardt.

The commit message is now written in the imperative mood, and the code includes a comment explaining the "ok" response as part of the client-daemon protocol. Redundant cleanup comments have been removed, and `exit(0)` is used for clarity. The patch is narrowly scoped, well-tested, and addresses a real, user-visible bug that surfaces during parallel submodule fetches. The only open question is the architectural soundness of mixing `unix_ss_*` and `tempfile` APIs, which the author has indicated willingness to revisit if required.
