This patch converts the `git credential` builtin to use `OPT_SUBCOMMAND` from the parse-options API, replacing its manual `strcmp()`-based subcommand dispatch. The change makes the code more idiomatic and consistent with other Git builtins, and it enables per-subcommand usage strings and shell completion support. The patch also fixes two minor documentation inconsistencies: the usage string now includes the "capability" subcommand, and the man page synopsis is marked as `[verse]` to allow extraction by the test suite. Behavior changes are limited to error reporting (clearer messages for missing or unknown subcommands) and help output (subcommand-specific usage). The patch touches `builtin/credential.c`, `git.c`, `Documentation/git-credential.adoc`, and adds tests in `t/t0300-credentials.sh`.

Key technical details: the patch introduces four new static functions (`cmd_credential_fill`, `cmd_credential_approve`, `cmd_credential_reject`, and `cmd_credential_capability`), each handling one subcommand with its own usage string. The main `cmd_credential` function now uses `OPT_SUBCOMMAND` to dispatch to these functions. The `NO_PARSEOPT` flag is removed from the `git.c` entry, making the command visible to `--list-cmds=parseopt`. Tests verify that subcommand-specific help works and that error messages for missing or unknown subcommands are clear.

The patch is a clean refactoring with no functional changes to the core credential operations (fill, approve, reject, capability). It addresses a long-standing inconsistency in how `git credential` handles subcommands compared to other builtins. The commit message is thorough and explains both the motivation and the mechanical changes. The test coverage is adequate, though it does not attempt to verify the shell completion improvements (which would require more complex test infrastructure). This is a well-scoped, uncontroversial improvement that aligns the command with Git's established patterns.
