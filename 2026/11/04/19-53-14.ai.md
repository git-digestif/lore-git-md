This is the first patch in Farid Zakaria’s v2 three-patch bugfix series for the credential-cache daemon. It is a **bugfix** that addresses a pre-existing permission-handling issue identified during review of the race-condition fixes.

The patch replaces `safe_create_leading_directories_const()` with `safe_create_leading_directories_no_share_const()` in `init_socket_directory()`. The socket directory (e.g., `~/.cache/git/credential`) is user-specific and should not be subject to `core.sharedRepository` settings from any repository the daemon happens to be started from. The current code incorrectly applies those permissions, which could lead to unintended access controls. The new helper ignores `core.sharedRepository`, ensuring the socket directory is created with the correct mode (`0700`) regardless of repository configuration.

The change is minimal—one line in `builtin/credential-cache--daemon.c`—and uncontroversial. It was suggested by Patrick Steinhardt during v1 review as a preparatory step before addressing the race conditions in patches 2 and 3. The commit message clearly explains the rationale and the security reasoning behind the directory creation logic (avoiding a race where an attacker could `chdir` into the directory before permissions are set). No test changes are needed, as the fix is purely about permission correctness. This patch is likely to be merged as-is, pending resolution of the architectural concern in patch 3.
