This is a **critical bugfix analysis** for the promisor remote lazy-fetch regression in Git 2.54.0. Kristofer Karlsson (Spotify) has identified the root cause and proposed a fix for the "not our ref" failure that blocks Kubernetes CI.

The issue stems from a broken invariant in Git's loose object cache. The cache is supposed to record all loose objects in a subdirectory once it has been listed, but writing a new loose object (like a merged blob during `git merge`) does not update the cache. This causes the checkout phase of the merge to incorrectly believe the object is missing and attempt to lazily fetch it from the server—even though the object exists locally. The server rejects the request with "not our ref," and the merge fails.

The regression was exposed by commit `5946a564` ("odb/source: make `read_object_info()` pluggable"), which stopped repreparing the loose object cache during retries. Previously, `odb_reprepare()` would discard the entire cache, masking the stale-cache bug. Now, the cache persists, and the stale entry causes the lazy-fetch misfire.

Kristofer reproduces the issue with Patrick Ohly's test case and confirms the fix: updating the loose object cache after writing a new object, ensuring the invariant holds. He has a working local patch with a unit test for the loose source backend, though an end-to-end test is tricky due to the need for a merged blob whose OID prefix collides with a prefetched object.

The patch targets the `odb/source` subsystem and should be straightforward—maintaining the cache invariant is a clear correctness fix. The urgency is high, as the regression completely breaks partial-clone workflows in production. Kristofer is deferring to Patrick Steinhardt for feedback on the approach, given Steinhardt's ongoing ODB refactoring work. Expect a formal patch submission soon.
