This is the first patch in the v3 series improving `git maintenance` lock handling. It aligns manual invocations (`git maintenance run` without `--auto`) with `git gc`'s behavior by making them fail with exit code 128 when the maintenance lock cannot be acquired, while preserving the silent skip for `--auto` mode but now emitting a warning. The `--quiet` flag is respected in both cases.

The patch modifies `builtin/gc.c` to check the `auto_flag` and report failures differently: manual runs now return `-1` (which propagates to exit code 128) and print an error, while `--auto` runs continue to return `0` but emit a warning. Error messages are formatted consistently using the existing `unable_to_lock_message()` helper, avoiding duplication. The test suite (`t/t7900-maintenance.sh`) is updated to verify both the new exit code behavior and the warning emission, including edge cases like `--quiet`.
