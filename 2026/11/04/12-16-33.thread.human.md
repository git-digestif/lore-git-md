This thread is about a bugfix series for the loose object database (ODB) cache invalidation during `git merge`, where stale cache entries cause Git to incorrectly assume locally written merged blobs are missing, triggering unnecessary and failing backfill fetches from promisor remotes. The series, authored by Patrick Steinhardt, consists of two patches: the first refactors code without changing behavior, while the second fixes the bug by ensuring the cache is properly invalidated after writing merged blobs.

The maintainer, Junio C Hamano, has approved landing the second patch as a targeted regression fix, while documenting the broader limitations of the `QUICK` flag in `odb.h` via a `NEEDSWORK` comment. The patch is expected to proceed to the `next` branch once the comment is added. Key participants include Kristofer Karlsson, who provided a substantive review and testing, and Derrick Stolee, who endorsed the fix without deep technical engagement. Jeff King (Peff) raised fundamental concerns about the fix’s completeness, arguing it leaves other vulnerable code paths unaddressed and highlighting the performance trade-offs of removing the `QUICK` flag entirely. Peff’s recent email quantified the flag’s performance impact, showing a 1320% slowdown in a pathological case when omitted, and clarified its usage patterns, grounding the discussion in measurable data.

The thread remains open on several fronts: whether the `QUICK` flag should be removed or modified, how to handle racy staleness and false positives, and the performance impact of omitting `QUICK` in prefetch paths. The `NEEDSWORK` comment will ensure these issues remain visible for future work, but no consensus has been reached on next steps. The series is otherwise ready to proceed, pending the addition of the documentation caveat.
