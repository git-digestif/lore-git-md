This thread is about a two-patch bugfix series from Patrick Steinhardt that addresses a regression in Git's loose object database (ODB) cache invalidation during `git merge`. The bug causes newly written merged blobs to be incorrectly treated as missing, triggering unnecessary and failing backfill fetches from promisor remotes. The root issue is broader: the `QUICK` flag used in object existence checks (e.g., `prefetch_cache_entries()`) is designed to tolerate false negatives but fails to handle them gracefully, leading to errors when promisor remote fetches fail for local-only objects.

The maintainer, Junio C Hamano, has approved landing the current patch (2/2) as a targeted regression fix while documenting the `QUICK` flag's limitations in `odb.h` via a `NEEDSWORK` comment. The series is expected to proceed to the `next` branch once the comment is added, with no substantive objections remaining. The fix ensures the loose object cache is properly invalidated after writing merged blobs, preventing false "object missing" errors. However, it does not address objects written by other processes (e.g., `git repack` or helper processes in `git merge`), false positives (objects cached as present but later pruned), or the performance trade-offs of omitting `QUICK` in prefetch paths.

Key participants include Patrick Steinhardt (author and ODB domain expert), Kristofer Karlsson (who provided a substantive, tested review), Derrick Stolee (who offered a surface-level endorsement), and Jeff King (Peff), who raised fundamental concerns about the fix's completeness and the `QUICK` flag's safety. Peff provided benchmark data showing a 1320% slowdown when `QUICK` is omitted in tag-following logic, highlighting the performance costs of broader fixes. The latest email is a minor, surface-level review from Toon Claes, who pointed out a type inconsistency in the extracted helper function `subdir_seen_bitmap()`. This is a cosmetic issue unlikely to impact the patch's progress. The series remains on track for `next`, with the `NEEDSWORK` comment serving as a placeholder for future work on the `QUICK` flag and cache staleness.
