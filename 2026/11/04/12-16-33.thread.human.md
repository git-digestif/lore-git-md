This thread fixes a bug in Git's loose object database (ODB) cache that caused `git merge` to fail when working with partial clones. The issue arose when newly written merged blobs couldn't be read back due to stale cache entries, leading Git to incorrectly assume the objects were missing and attempt unnecessary fetches from promisor remotes. The root problem is broader: any code using `QUICK` object existence checks (like `prefetch_cache_entries()`) can produce false negatives, and the current design doesn't handle these gracefully.

The two-patch series from Patrick Steinhardt has been approved for inclusion in `next` with one addition: a `NEEDSWORK` comment in `odb.h` documenting the known limitations of the `QUICK` flag. This reflects a pragmatic compromise—fixing the immediate regression while deferring a deeper audit of `QUICK` usage. The maintainer, Junio Hamano, and Patrick agreed on this approach, though Patrick remains skeptical about the `QUICK` flag's safety, calling it a "foot gun." The final placement of the comment (whether on `OBJECT_INFO_QUICK` or `OBJECT_INFO_FOR_PREFETCH`) is a minor detail still under discussion, but the patch itself is ready to proceed.

Key reviewers include Kristofer Karlsson, who tested the fix and confirmed it resolves the issue, and Jeff King, who raised concerns about the fix's completeness. Peff argues the current patch is a band-aid, leaving other `QUICK`-dependent code paths and racy staleness unaddressed. Derrick Stolee also reviewed the series but focused on surface-level validation. The broader `QUICK` flag discussion will continue in a follow-up thread, with the `NEEDSWORK` comment serving as a reminder to revisit the design. For now, the fix ensures the loose object cache reflects the process's own writes, preventing the immediate bug without introducing new risks.
