This thread is about a two-patch bugfix series from Patrick Steinhardt that addresses a loose object database (ODB) cache invalidation bug during `git merge`. The issue causes Git to incorrectly assume newly written merged blobs are missing, triggering unnecessary and failing backfill fetches from promisor remotes. The fix targets the subdirectory bitmap handling in `odb/source-loose.c`, with the first patch refactoring the code to avoid duplication and the second patch introducing `loose_cache_mark_seen()` to properly update the cache after writing objects.

The series is under review in its first version. Patrick’s commit messages and design rationale are thorough, explaining why the chosen approach (updating the cache on write) is preferable to alternatives. Kristofer Karlsson provided a substantive review, confirming the fix works as intended and adding both `Tested-by` and `Reviewed-by` trailers. Derrick Stolee’s recent follow-up is supportive but surface-level, offering no new technical feedback. The series is self-contained, includes a new test in `t/t5616-partial-clone.sh`, and has no open questions or loose ends. It’s ready for maintainer attention.
