This thread began as a straightforward bugfix for loose object database (ODB) cache invalidation during `git merge`, where newly written merged blobs were incorrectly reported as missing due to stale cache entries. Patrick Steinhardt’s two-patch series—approved for merging after substantive review from Kristofer Karlsson and maintainer acknowledgment from Junio Hamano—refactored the cache logic and introduced `loose_cache_mark_seen()` to update the cache after writing objects. The fix was well-tested and narrowly targeted, addressing the immediate issue without broader changes.

However, Jeff King (Peff) has now raised fundamental concerns about the fix’s long-term correctness. While he acknowledges the patch resolves the specific `git merge` bug, he argues it’s incomplete: the deeper problem is that *any* code path using `QUICK` object existence checks (like `prefetch_cache_entries()`) can produce false negatives, and the current design fails to handle them gracefully. Peff highlights that the `QUICK` flag is meant to tolerate false negatives, but when a promisor remote fetch fails for a local-only object, Git errors out instead of recovering. He proposes two alternatives: omitting `QUICK` in prefetch paths (forcing a full ODB re-scan) or revisiting cache-flushing logic removed in an earlier commit. He also warns of racy staleness—objects written by other processes (e.g., `git repack` or `git log`) could trigger the same bug, which the current fix doesn’t address.

The thread is now an open design discussion. Patrick and Junio will need to weigh Peff’s concerns—prioritizing correctness over minimal disruption—against the risk of introducing performance regressions or scope creep. A follow-up series seems likely, either to implement Peff’s suggestions or to document the limitations of the current fix. For now, the series is no longer "ready to merge" until these questions are resolved.
