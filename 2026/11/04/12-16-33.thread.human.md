This thread is about a bugfix series for Git’s loose object database (ODB) cache invalidation during `git merge`, where stale cache entries caused Git to incorrectly assume locally written merged blobs were missing, triggering unnecessary and failing backfill fetches from promisor remotes. The series, authored by Patrick Steinhardt, consists of two patches: the first refactors code without changing behavior, while the second fixes the bug by ensuring the cache is properly invalidated after writing merged blobs. The maintainer, Junio C Hamano, has approved the series for the `next` branch with a caveat—a `NEEDSWORK` comment in `odb.h` documenting the broader limitations of the `QUICK` flag, which tolerates false negatives but fails to handle them gracefully in promisor remote workflows.

The key debate now centers on the future of the `QUICK` flag. Patrick initially favored removing it entirely but has since acknowledged its performance benefits, as demonstrated by Jeff King’s (Peff) benchmark data showing a **1320% slowdown** in the `p5550.4: fetch` test when `QUICK` is omitted. However, Patrick argues that correctness must take precedence: if the flag cannot reliably handle concurrent repository maintenance or promisor remotes, its performance gains are moot. The discussion has shifted toward whether `QUICK` can be made safe (e.g., via improved cache invalidation) or if it should be phased out in favor of alternatives like the `RECHECK_PACKED` flag, which forces full rescans. Other unresolved issues include racy staleness from objects written by other processes and false positives from pruned objects, though these remain unaddressed for now.

The series itself is ready to proceed to `next` once the `NEEDSWORK` comment is added to `odb.h`, with no substantive objections blocking its progress. Reviews have been mixed: Kristofer Karlsson provided a substantive, tested review with `Tested-by` and `Reviewed-by` trailers, while Derrick Stolee and Toon Claes offered surface-level feedback. Jeff King remains the most vocal critic, raising concerns about the fix’s completeness and the `QUICK` flag’s safety, but his objections are not blocking the immediate regression fix. The thread’s next steps may involve auditing other `QUICK` users or revisiting commit `5946a564cdd`, which removed cache-flushing logic. For now, the focus is on landing the targeted fix while keeping the broader design questions open.
