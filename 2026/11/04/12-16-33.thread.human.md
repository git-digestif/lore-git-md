This thread is about a bugfix series for the loose object database (ODB) cache invalidation during `git merge`. The two-patch series, initially submitted by Patrick Steinhardt, addresses a bug where newly written merged blobs cannot be read back due to stale cache entries, causing Git to incorrectly assume the objects are missing and triggering unnecessary, failing backfill fetches from promisor remotes.

The series was previously approved for merging, but Jeff King's recent review raised fundamental concerns about the root cause and long-term correctness of the fix. Patrick now proposes landing the current patch as a targeted regression fix while deferring broader work on the `QUICK` flag and cache staleness to a follow-up effort. Junio C Hamano has endorsed this approach, suggesting a `NEEDSWORK` comment be added to `odb.h` to document the known limitations of the `OBJECT_INFO_FOR_PREFETCH` flag and ensure the larger issue is not forgotten. This pragmatic compromise allows the regression fix to proceed to Junio's `next` branch with minimal disruption while keeping the broader design discussion alive for future work.

Key participants include Patrick Steinhardt (author and ODB expert), Kristofer Karlsson (who provided a substantive, tested review), Derrick Stolee (who offered a surface-level endorsement), Junio C Hamano (maintainer), and Jeff King (who raised deeper concerns about the `QUICK` flag and cache staleness). The current patch touches `odb/source-loose.c` and adds test coverage in `t/t5616-partial-clone.sh`, but it does not address objects written by other processes or false positives in the cache. The open questions revolve around the scope of the immediate fix, the future of the `QUICK` flag, and how to handle racy staleness and performance trade-offs.
