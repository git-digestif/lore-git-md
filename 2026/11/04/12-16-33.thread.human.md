This thread is a two-patch bugfix series from Patrick Steinhardt addressing a subtle but impactful issue in Git's loose object database (ODB) cache invalidation during `git merge`. The bug causes Git to incorrectly treat newly written merged blobs as missing, triggering unnecessary and failing backfill fetches from promisor remotes. The series is now complete with the second patch, which implements the actual fix after a preparatory refactoring in the first patch.

The fix targets `odb/source-loose.c`, the core component handling loose object storage, and introduces a new helper function, `loose_cache_mark_seen()`, to ensure the cache is updated after writing new objects. The patch includes a thorough test in `t/t5616-partial-clone.sh` that validates the fix under realistic conditions, using a partial clone setup with 50 mergeable files. The commit message provides a detailed explanation of the bug's root cause—stale cache entries for sharding directories—and why the chosen fix is preferable to alternatives like flushing the cache on non-QUICK reads.

So far, the series has not received any review feedback, but it appears uncontroversial given its narrow scope and Patrick Steinhardt's domain expertise in ODB abstraction. The fix is self-contained, with no on-disk format changes or ties to other in-flight efforts. If reviews remain positive, this series is likely to be merged soon, resolving a long-standing edge case in promisor remote interactions.
