This thread is about a bug in Git’s loose object database (ODB) cache that causes `git merge` to fail when it tries to read back newly written merged blobs. The issue surfaces in partial clones, where Git incorrectly assumes the objects are missing locally and attempts unnecessary, failing backfill fetches from promisor remotes. Patrick Steinhardt initially proposed a two-patch fix to update the cache after writing new objects, which Junio Hamano and reviewers approved for merging.

However, Jeff King (Peff) raised deeper concerns: the bug isn’t limited to `git merge` but affects any code path using `QUICK` object existence checks, and the fix doesn’t address objects written by other processes or racy staleness. In response, Patrick acknowledged the broader problem but argued the current patch should proceed as a targeted regression fix, deferring the larger `QUICK`-related work to a follow-up series. He also suggested removing the `QUICK` flag entirely, while Peff proposed omitting it only in prefetch paths to avoid performance penalties.

The thread remains open, with no new patch version posted yet. The current fix is likely to land in `next` as a regression fix, but the discussion about the `QUICK` flag and cache staleness will continue, potentially leading to further changes in the ODB layer. Key participants include Patrick (author), Peff (reviewer), and Junio (maintainer), with possible input from other ODB experts like Christian Couder or Justin Tobler.
