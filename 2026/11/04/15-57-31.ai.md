This is the ninth patch in Patrick Steinhardt’s ten-patch series refactoring commit-graph write code as part of the ODB abstraction effort. It moves commit-graph verification from `builtin/fsck.c` into the pluggable object database backend (`odb/source-files.c`), aligning it with how multi-pack indices, bitmaps, and other auxiliary data structures are already verified.

The patch removes the hard-coded `git commit-graph verify` subprocess invocation from `cmd_fsck()` and replaces it with a new `fsck_commit_graph()` helper inside `odb_source_files_fsck()`. This helper respects the same pluggability rules as the rest of the ODB fsck machinery: commit graphs in alternates are only checked when `ODB_FSCK_FULL` is set (the default for `git fsck`), and verification is skipped entirely with `--connectivity-only`. Failures are now reported via the generic `ERROR_OBJECT` bit rather than the now-removed `ERROR_COMMIT_GRAPH` exit code, matching the pattern used for other auxiliary data structures.

The change is mechanical and consistent with the broader ODB abstraction goals. It touches only two files (`builtin/fsck.c` and `odb/source-files.c`) and introduces no new user-visible behavior. The diffstat shows a net reduction of 15 lines, reflecting the consolidation of verification logic into the pluggable backend. This patch is a prerequisite for the upcoming commit-graph pluggability work, which will allow backends to choose where commit graphs are stored.
