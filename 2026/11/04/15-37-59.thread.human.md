This thread is about a bugfix patch from Derrick Stolee that addresses a long-standing issue where the untracked cache incorrectly remains valid after fsmonitor fails or returns a trivial response, causing new untracked files to be missed by `git status`. The patch, which introduces a new `untracked_cache_invalidate_all()` function, has been accepted by Junio C Hamano and is queued for integration in `seen`, with plans to graduate to `next` and eventually `master`.

The only recent development is a procedural question from Junio about whether this patch should supersede an older, unreviewed patch (`ik/fsmonitor-untracked-cache-trivial-response`) targeting the same bug. There’s no technical disagreement or new feedback—just a logistical decision about which patch to prioritize. The fix itself is uncontested, well-tested, and includes performance considerations. No further action or discussion is needed beyond resolving the patch supersession question.
