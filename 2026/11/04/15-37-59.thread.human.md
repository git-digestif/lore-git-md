This thread is about a bugfix patch from Derrick Stolee that addresses a long-standing (since 2017) integration bug between fsmonitor and the untracked cache. The bug causes new untracked files to become invisible to `git status` when fsmonitor fails or returns a trivial response, leaving the untracked cache incorrectly marked as valid. Stolee’s patch introduces a new function, `untracked_cache_invalidate_all()`, to recursively invalidate the untracked cache in these scenarios, ensuring the index is properly updated. The fix includes two new tests in `t/t7519-status-fsmonitor.sh` to validate the behavior, and performance tests show no degradation when `max_user_watches` is sufficiently high.

The patch has now been accepted by Junio C Hamano, who acknowledged that while the fix is somewhat heavy-handed, correctness is the priority here. It is now queued for integration and will appear in the next `seen` rebuild, with plans to graduate to `next` and eventually `master`. No further review feedback or discussion has emerged yet, and there are no outstanding questions or objections. The patch touches `dir.c`, `dir.h`, `fsmonitor.c`, and the test suite, and it resolves a long-standing issue without introducing new complications.
