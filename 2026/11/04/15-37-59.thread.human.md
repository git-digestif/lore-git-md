This thread is about a bugfix patch from Derrick Stolee that addresses a long-standing integration issue between Git's fsmonitor and untracked cache subsystems. The bug, present since fsmonitor was introduced in 2017, could cause new untracked files to remain invisible to `git status` when fsmonitor fails or returns a trivial response, leaving the untracked cache incorrectly marked as valid.

The fix introduces a new function `untracked_cache_invalidate_all()` in `dir.c` that recursively invalidates all untracked cache directories and ensures the index is written even when no tracked entries change. The change is triggered in `fsmonitor.c` when fsmonitor use is disabled for the untracked cache. Two new tests in `t/t7519-status-fsmonitor.sh` validate the fix, covering both "trivial" and "failure" response scenarios. Performance tests show no degradation with the fix, provided the system's `max_user_watches` is sufficiently high.

The patch touches `dir.c`, `dir.h`, `fsmonitor.c`, and the test script, adding about 60 lines total. The commit message provides a clear explanation of the bug's history, the fix's mechanism, and the testing approach. There are no open questions or review comments yet, as this is the initial patch submission.
