Subject: [PATCH] path-walk: fix object loss when tagged tree revisits path
Series version: standalone patch
Originating author: Derrick Stolee
Thread type: bugfix

Core problem or goal
A regression in Git 2.55.0 (commit 5111520e2a1, "path-walk: support `tree:0` filter", 2026-05-22) causes the pack-objects/path-walk machinery to drop objects when a tagged tree contains a blob at a path already visited by a prior tree batch. The bug stems from `path_stack_pushed` refusing to revisit paths, which prevents new objects at those paths from being discovered.

Current status
Under review. The patch is a minimal, targeted fix: in `path-walk.c`, the code now removes a path from `path_stack_pushed` when consuming its queue entry, allowing later objects at the same path to be discovered. A new test in `t/t7700-repack.sh` verifies the fix by creating a commit and an annotated tree tag with distinct blobs at the same path, repacking with `--path-walk`, and running `git fsck --connectivity-only` to confirm no objects are lost.

Key technical details
- Files touched: `path-walk.c` (single-line change plus comment), `t/t7700-repack.sh` (new test case)
- Subsystem: pack-objects/path-walk
- New symbols: none
- Old-vs-new behavior: previously, objects at paths already in `path_stack_pushed` were silently dropped; now, those paths are removed from the set when consumed, allowing new objects at the same path to be discovered
- On-disk format: unchanged
- Test coverage: new test exercises the exact edge case (tagged tree revisiting a path already visited by a commit root tree)
