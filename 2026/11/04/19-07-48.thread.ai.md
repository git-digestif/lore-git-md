Subject: [PATCH] path-walk: fix object loss when tagged tree revisits path
Series version: standalone patch
Originating author: Derrick Stolee
Thread type: bugfix

Core problem or goal
A regression in Git 2.55.0 (commit 5111520e2a1, "path-walk: support `tree:0` filter", 2026-05-22) causes the pack-objects/path-walk machinery to drop objects when a tagged tree contains a blob at a path already visited by a prior tree batch. The bug stems from `path_stack_pushed` refusing to revisit paths, which prevents new objects at those paths from being discovered.

Current status
Under review. The patch remains unchanged: in `path-walk.c`, the code removes a path from `path_stack_pushed` when consuming its queue entry, allowing later objects at the same path to be discovered. A new test in `t/t7700-repack.sh` verifies the fix. Junio C Hamano has acknowledged Taylor Blau's "LGTM" but has not stated a merge decision; the patch still lacks substantive technical review from domain experts.
