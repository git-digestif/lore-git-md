This is a progress update from Srujith A Poojary on the submodule diff header commit abbreviation bugfix, now at v5. The patch is part of the Git libification effort and addresses a collision risk where the same abbreviated commit ID could refer to different objects in the superproject and submodule repositories.

The v5 patch consolidates the fix and its test coverage into a single commit, making the test fully hash-agnostic by using `test_oid_cache` to provide expected abbreviated commit IDs for both SHA-1 and SHA-256. This directly addresses Junio C Hamano’s feedback about the unnatural split between SHA-1 and SHA-256 coverage in earlier versions. The core fix—introducing `strbuf_repo_add_unique_abbrev()` and using `o->repo` as the fallback repository—remains unchanged from v4, but the test now verages both hash algorithms in one go.

The patch touches `submodule.c` and `t/t4041-diff-submodule-option.sh`, and the test suite passes all 48 tests in the targeted file. Junio has marked the series as "Will queue," indicating it is ready for integration with no open technical or procedural concerns. The update is purely informational; no new feedback or changes are requested. For readers tracking libification progress, this is a small but complete step toward reducing reliance on the global `the_repository`.
