This is a refactoring patch for the `git credential` command. The author, Wasswa Edson, converts the subcommand dispatch mechanism from a manual `strcmp()` chain to Git's standard `parse-options` API with `OPT_SUBCOMMAND`. The change makes the code more idiomatic and consistent with other built-ins, while also improving usability: each subcommand (`fill`, `approve`, `reject`, `capability`) now has its own targeted help text, and command-line completion via `--git-completion-helper` works automatically.

The patch touches `builtin/credential.c` (the main conversion), `Documentation/git-credential.adoc` (to fix a synopsis formatting issue so the test suite can extract it), `git.c` (to drop the `NO_PARSEOPT` flag), and adds new tests in `t/t0300-credentials.sh` to verify the new help and error behavior. Two minor pre-existing inconsistencies are fixed along the way: the usage string now lists all four subcommands (including `capability`, which was previously omitted), and the documentation synopsis is marked as `[verse]` so the test suite can parse it.

The patch is well-motivated, clearly explained, and includes thorough test coverage. It looks like a clean, uncontroversial improvement that aligns `git credential` with the rest of the codebase. No substantive objections are apparent from the patch itself.
