This is a performance optimization for `git send-pack`, specifically targeting the common workflow of force-pushing a rebased feature branch. The author, Marc Strapetz, is revisiting the series after Junio C Hamano raised concerns about its redundancy with existing push negotiation mechanisms. The key argument here is that this series optimizes the *default* packing path without introducing additional negotiation rounds, making it a lighter-weight alternative for a narrow but frequent use case.

The patch series introduces a new `--inspect-have` option in `pack-objects` that allows `send-pack` to mark the old branch tip’s root tree as "have" without walking its commit history. This enables the packer to exclude objects the receiver already has, reducing redundant transfers for forced non-fast-forward updates. The optimization is opt-in and restricted to existing branches (`refs/heads/`) where the old tip is locally available, avoiding regressions in shallow repositories, partial clones, or bitmap enumeration. The author emphasizes that this approach avoids the latency of negotiation while still improving performance for small rewrites.

Marc provides micro-benchmarks showing substantial improvements in pack size and wall-clock time for small changes (e.g., a single-file reword drops from 2.776 ms to 1.338 ms). However, he also transparently acknowledges a worst-case 8% packing-time overhead for widespread changes, inviting feedback on the trade-off. The series includes thorough test coverage, adding 19 new tests to `t5322-pack-objects-sparse.sh` and 43 to `t5516-fetch-push.sh`, covering edge cases like identical trees, shared blobs, and replacement refs.

The unresolved question from Junio—whether this series is sufficiently distinct from existing push negotiation—remains open. Marc argues that the series targets a narrower scope (the default packing path) and avoids negotiation latency, but it’s unclear whether this justification will sway reviewers. The author has explicitly called out Taylor Blau and Derrick Stolee for feedback on the pack generation and revision traversal aspects, suggesting this is still a work in progress.
