This thread is an Outreachy applicant's RFC for improving how Git controls the order in which promisor remotes are tried when fetching missing objects. Yopa Nelly, working with mentor Kaartic Sivaraam, proposes two configuration designs—numeric priorities per remote or a global ordered list—and seeks early feedback before implementation.

The current behavior tries remotes in config-file order, always moving the `extensions.partialClone` remote to the end, with no user override. Nelly favors the list-based approach (`promisor.fetchOrder`) for its readability and alignment with Git’s linked-list internals, though the numeric option (`remote.<name>.promisorPriority`) might better support source-dependent ordering. Three open questions remain: how to handle non-promisor remotes named in the list, whether the list should override the automatic `extensions.partialClone` move, and whether fetch order should vary by source remote.

The discussion is at the design stage, with no implementation yet. Key participants are Nelly and Kaartic, but broader input from maintainers or promisor-remote experts (e.g., Christian Couder or Patrick Steinhardt) would help resolve the open questions. The thread is a good example of Git’s mentorship culture, balancing applicant initiative with community guidance.
