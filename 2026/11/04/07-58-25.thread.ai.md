Core problem or goal
The thread reports a severe performance regression in `git log --follow` when tracking a single file through non-linear history (e.g., forward merges of maintenance branches into main). The command now takes ~10 minutes in Git 2.56 vs. ~1 second in Git 2.43, bisected to commit 304812ed33 ("log: improve --follow following renames for non-linear history"). The regression stems from the new logic running a full diff against *every* parent of a merge commit, even when the tracked file is absent in that parent, causing the cost to scale with the number of such merges and tree size.
