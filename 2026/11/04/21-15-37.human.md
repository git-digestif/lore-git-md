This is the first patch in a two-part series (v4) that refactors hard-coded reflog message strings into named constants in `reflog.h`. The change is explicitly preparatory for the next patch, which introduces the `%gb` format placeholder to show which branch `HEAD` was on for each reflog entry.

The patch replaces string literals like `"checkout: moving from "` and `"Branch: renamed "` with `#define` constants (`REFLOG_SWITCH_PREFIX`, `REFLOG_RENAME_PREFIX`, etc.) across seven files: `builtin/branch.c`, `builtin/checkout.c`, `builtin/rebase.c`, `object-name.c`, `reflog.h`, `sequencer.c`, and `wt-status.c`. It also standardizes rebase step labels (`"start"`, `"finish"`, `"abort"`) and prefixes like `"returning to "` and `"checkout "` in the same way. No behavior changes are introduced—this is purely a refactoring to avoid duplicating these strings in the upcoming `%gb` implementation.

The motivation is clear: the `%gb` feature will parse reflog messages to extract branch context, and centralizing these strings in `reflog.h` prevents future drift between the messages written by commands and the code that reads them. The patch also addresses Junio C Hamano’s earlier concern about making reflog messages easier to refactor later, though it stops short of splitting them into human-readable and machine-readable parts (a potential future direction).
