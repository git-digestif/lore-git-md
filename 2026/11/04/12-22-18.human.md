This is a bugfix follow-up in the ongoing critical regression thread about promisor remote lazy-fetch failures in Git 2.54.0. Patrick Steinhardt provides the missing piece to the timing mystery: the regression only manifests when merging an object whose first two hex characters match those of a newly written object in the same subdirectory. This explains why Kubernetes CI ran successfully for days before encountering the failure—it required a specific object layout collision that did not occur earlier.

The root cause is now fully explained: the ODB abstraction work exposed a pre-existing stale loose object cache invariant, and the regression triggers only when object IDs collide in their first two hex characters. Steinhardt has already sent a fix series (`20261104-pks-odb-loose-stale-cache-v1`) that updates the oidtree after loose object writes, preserving cache consistency. The fix is endorsed by him and aligns with the ODB design goals, making rapid integration likely. The urgency remains high due to the CI blockage, but the technical path forward is now clear.
