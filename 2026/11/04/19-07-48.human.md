This is a bugfix for the path-walking repack machinery. Derrick Stolee identifies a regression introduced in Git 2.55.0 (commit 5111520e2a1) where blobs from tagged trees could be silently dropped if they shared a path with an earlier object. The fix is small and surgical: when consuming a path from the priority queue, the code now removes that path from the "already pushed" set, allowing a later tagged tree to revisit the same path and include its blob. A new test in `t/t7700-repack.sh` creates a commit and an annotated tree tag that both contain distinct blobs at the same path, then verifies that `git repack --path-walk` followed by `git fsck` does not report missing objects.

The commit message is clear and well-structured: it names the regressing commit, describes the scenario (tagged trees expanded after commit root trees), explains why the old logic failed (path_stack_pushed refused to queue a path twice), and shows how the fix preserves the intended visit priorities. The test case is minimal and directly exercises the bug. This looks like a solid, well-motivated fix that addresses a real-world issue in the torvalds/linux repository.
