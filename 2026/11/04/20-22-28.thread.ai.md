Thread identity: patch series converting `git credential` to use `OPT_SUBCOMMAND` from the parse-options API. Originating author: Wasswa Edson. Thread type: patch series (three patches in v2).

Core problem or goal: replace the manual `strcmp()`-based subcommand dispatch in `git credential` with the standard `OPT_SUBCOMMAND` mechanism used by other Git builtins. This change makes the code more idiomatic, enables per-subcommand usage strings and shell completion support, and fixes minor documentation inconsistencies (missing "capability" subcommand in usage, `[verse]` markup in man page synopsis).

Current status: v2 posted and complete. The series is split into three incremental patches: (1) align `-h` output with SYNOPSIS, (2) refactor each subcommand into its own function, (3) switch to `OPT_SUBCOMMAND`. All feedback from v1 has been addressed. Patch 3 has received substantive reviewer approval from Tanga Joris pending one minor documentation tweak, and the v2 cover letter has received a blanket `Reviewed-by` from Laveesh Bansal following local test verification. No merge status reported; still under review.

Key technical details:
- Files touched: `builtin/credential.c`, `git.c`, `Documentation/git-credential.adoc`, `t/t0300-credentials.sh`, `t/t0450/adoc-help-mismatches`.
- New static functions: `cmd_credential_fill`, `cmd_credential_approve`, `cmd_credential_reject`, `cmd_credential_capability` (one per subcommand), plus helper `parse_no_args` to centralize argument parsing and rejection logic.
- `NO_PARSEOPT` flag removed from `git.c` entry, making the command visible to `--list-cmds=parseopt`.
- Behavior changes: clearer error messages for missing/unknown subcommands (now rejected *before* reading stdin, avoiding unnecessary I/O), subcommand-specific usage, rejection of extra arguments for each subcommand, improved `-h` output alignment with SYNOPSIS, and a newly noted change where `git credential <subcommand> --` (end-of-options marker after subcommand) now succeeds instead of producing a usage error. Core credential operations (fill, approve, reject, capability) remain unchanged. The third patch completes the transition by rewriting the main dispatch logic to use `parse_options()` with `OPT_SUBCOMMAND` entries, enabling per-subcommand help via `git credential <subcommand> -h` and shell completion support.
- Tests verify subcommand-specific help, error messages, and rejection of extra arguments. The first patch also adds coverage for the `capability` subcommand in `t/t0450/adoc-help-mismatches`.

Open questions and loose ends: Tanga Joris requests that the commit message for patch 3 document the behavior change regarding the `--` end-of-options marker after a subcommand (previously a usage error, now accepted). Laveesh Bansal has since confirmed that the long option `--end-of-options` behaves identically to `--` when placed after a subcommand (demonstrated with `git credential capability --end-of-options` succeeding and printing the capability list). Bansal also raises whether a dedicated `_git_credential` bash completion script is intended as a follow-up, noting that while `git credential --git-completion-helper` exposes subcommand names, bash completion currently offers no suggestions for `git credential <TAB>` (the same gap seen with `git hook`). The thread is otherwise converged with multiple reviewer approvals pending only the commit message clarification and the open completion question.
