This is the second patch in a two-patch bugfix series targeting a loose object database (ODB) cache invalidation bug during `git merge`. The issue causes Git to incorrectly report newly written merged blobs as missing, triggering unnecessary and failing backfill fetches from promisor remotes. This patch implements the actual fix by updating the loose object cache whenever a new loose object is written, ensuring subsequent existence checks reflect the current state of the object store.

The patch touches `odb/source-loose.c`, the core component handling loose object storage, and adds a new test in `t/t5616-partial-clone.sh` to verify the fix. The commit message provides a detailed reproducer and explains why the bug occurs: the loose object cache is not updated after writing new objects, leading to stale cache entries for sharding directories that were previously populated. The fix introduces a new helper function, `loose_cache_mark_seen()`, which marks newly written objects as present in the cache if their subdirectory has already been scanned.

The test coverage is thorough, using a partial clone setup with 50 mergeable files to ensure the fix works under realistic conditions. The test verifies that `git merge` correctly handles locally written objects without attempting to fetch them from the promisor remote. The patch is well-motivated, with a clear explanation of the bug's root cause and why the chosen fix is preferable to alternatives (e.g., flushing the cache on non-QUICK reads).

This patch is the culmination of the series, following a preparatory refactoring in patch 1/2 that extracted the subdirectory bitmap logic. The fix is narrowly scoped to the loose object cache and does not affect other subsystems or on-disk formats. Given Patrick Steinhardt's domain expertise in ODB abstraction and the series' clear focus, this patch is likely to be uncontroversial and a strong candidate for merging. The test coverage and detailed commit message further strengthen its case.
