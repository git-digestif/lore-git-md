This is the v3 cover letter for a two-patch series improving `git maintenance` lock acquisition failure handling. The series is now split into two focused patches: the first aligns manual invocation behavior with `git gc` (failing with exit code 128 when the lock cannot be acquired), and the second adds a Trace2 data event (`"lock/skip"`) for `--auto` skips, including the specific error code and `strerror`-based reason.

The v3 revision incorporates all feedback from Patrick Steinhardt’s v2 review: the patches are now split for better reviewability and bisectability, error-message formatting is deduplicated into a shared helper, and the Trace2 event uses `strerror(err)` consistently for the `reason` field. The author waited a day after v2 to post v3, allowing time for additional review, but no new objections or alternative proposals have emerged. The series remains uncontroversial and narrowly scoped to lock-handling logic in `builtin/gc.c` and its test coverage in `t/t7900-maintenance.sh`.

Key technical details for follow-up discussion include the new Trace2 event format (`"lock/skip": {"reason": <strerror(err)>, "errno": <code>}`), the exit code change for manual invocations (now matching `git gc`), and the test cases verifying both `--auto` and manual modes. The lock file is preserved on failure, maintaining the existing design that stale locks require manual inspection. No on-disk format changes or cross-subsystem interactions are introduced. The series is ready for final review and integration.
