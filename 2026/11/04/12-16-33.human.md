This is a bugfix targeting the object database (ODB) layer, specifically the loose-object cache in promisor-remote workflows. Patrick Steinhardt reports that when `git merge` writes merged blobs, the loose-object cache can become stale, causing Git to incorrectly conclude that the objects don’t exist locally. This leads to a failed backfill fetch from a promisor remote, which doesn’t have the objects either.

The series consists of two patches. The first refactors the logic for retrieving the subdirectory bitmap in `odb/source-loose.c` to make the code more maintainable. The second patch fixes the core issue by ensuring the loose-object cache is updated when new objects are written, preventing the false-negative existence checks. The fix is tested in `t/t5616-partial-clone.sh`, which now includes a new test case covering this scenario.

The commit message is clear and well-motivated, linking to the original bug report and explaining the problem in straightforward terms. The patches touch a critical part of Git’s storage layer, so the fix is likely to be uncontroversial—stale caches are a classic bug pattern, and the solution (updating the cache on write) is the obvious remedy. The test coverage is thorough, which should give reviewers confidence.
