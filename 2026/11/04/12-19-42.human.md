This is a **critical bugfix** addressing a regression in Git 2.54.0 that breaks lazy-fetching in partial clones, blocking CI workflows like Kubernetes. The issue stems from a stale loose object cache in the ODB abstraction layer, introduced by the broader effort to make `read_object_info()` pluggable.

Patrick Steinhardt confirms the bug and traces the root cause to a long-standing flaw: the loose object cache was never updated when new objects were written, but this only became visible after commit `5946a564` stopped flushing the cache during object lookups. The fix, sent as a separate patch series, updates the cache after loose object writes to maintain consistency. This is a targeted, well-motivated correction that aligns with the ODB abstraction’s design goals.

The regression is severe but narrow: it affects operations like `git merge` in blobless partial clones when a newly written object (e.g., a merged blob) lands in a directory already listed by prefetch. The fix is straightforward and unlikely to be controversial, though the timing mystery—why Kubernetes CI ran successfully for days before failing—remains unresolved. Patrick Steinhardt’s involvement and prompt response suggest this will be prioritized for merging.
