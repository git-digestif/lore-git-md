This is a **substantive review** of Aaron Plattner’s `[PATCH v2]` bugfix for preserving `WWW-Authenticate` headers across HTTP redirects. Jeff King (Peff) engages deeply with the security implications and design trade-offs of the patch, raising a key concern: whether the fix could inadvertently reuse authentication headers from the original server with the redirected-to server, which would be a security risk. He concludes that the patch is safe because the headers are already scoped to the redirect target, but questions the necessity of the new `credential_update_url()` helper, preferring the v1’s inline approach for clarity. Peff also suggests a defensive `BUG()` check to ensure `credential_from_url()` never populates `wwwauth_headers`, reinforcing the invariant that these headers are server-provided, not URL-derived.
