This thread is an Outreachy project proposal by Shashank S Mogaveera to make the fetch order of promisor remotes configurable in partial clones. The idea is to replace Git’s current hardcoded fallback order with a user-configurable list (`promisor.fetchOrder`) and optionally allow servers to advertise preferred priorities via a Protocol v2 extension. No code has been written yet; the proposal lays out the design, edge cases, and a client-first upstreaming plan.

Shashank has already traced the existing behavior with GIT_TRACE2 and has four prior microprojects merged, demonstrating familiarity with the mailing-list workflow. The thread is still in the proposal stage, with open questions about whether server-side advertisement should be opt-in, how to handle unlisted remotes, and whether to cache failed remotes dynamically. This follow-up email is purely administrative—fixing a typo and broken links—so the original proposal remains the substantive document for review.
