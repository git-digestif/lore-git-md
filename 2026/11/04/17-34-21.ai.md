This is the first patch in the v3 series improving `git maintenance` lock acquisition failure handling. It aligns manual invocation behavior (`git maintenance run` without `--auto`) with `git gc` by making it fail with exit code 128 when the lock cannot be acquired, while preserving the silent skip behavior for `--auto` mode but now emitting a warning (unless `--quiet` is specified). The patch touches `builtin/gc.c` and adds three new tests in `t/t7900-maintenance.sh` to verify the new behavior for both `--auto` and manual modes, including `--quiet` suppression.

The implementation refactors the lock-acquisition error path to use the existing `unable_to_lock_message()` helper (shared with `git gc`), ensuring consistent error formatting. The exit status logic now distinguishes between `--auto` (returns 0) and manual (returns -1, which propagates as 128) invocations. The lock file is preserved on failure, maintaining the existing design that stale locks require manual inspection. Test coverage confirms the warning/error messages include the lock path and system error, and that `--quiet` suppresses all output while still failing for manual invocations.

This patch directly addresses the lock-handling inconsistency flagged in Patrick Steinhardt’s review of v1, and incorporates all mechanical refinements requested in v2 (code deduplication, patch splitting). The behavioral change is narrowly scoped to `git maintenance run` and does not affect other commands or on-disk formats. The series remains uncontroversial and ready for final review.
