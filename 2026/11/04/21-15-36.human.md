This is a feature patch (v4) that introduces the `%gb` format placeholder to `git log -g` and `git reflog`, allowing users to see which branch each reflog entry was recorded on. The series is a ground-up redesign of earlier attempts (`--operations` and `--historical-branch` flags) in response to review feedback, now offering a composable format specifier that aligns with Git’s decoration system.

The core change adds `%gb` to `pretty.c`, which parses reflog messages left by branch switches, renames, and rebases to name the branch for each entry. For example, `git log -g --format='%h %gd: (%gb) %gs'` now shows output like `9c8d7e6 HEAD@{0}: (topic) rebase (finish): returning to refs/heads/topic`. The placeholder handles edge cases like `git rebase <upstream> <branch>`, detached HEAD states, and branch renames, and outputs "detached at <commit>" when HEAD was detached. For reflogs of other refs (not `HEAD`), `%gb` shows the shortened refname.

This version (v4) fixes a regression identified in v3 where `%gb` misinterpreted reflog messages altered by `GIT_REFLOG_ACTION` (e.g., during rebase operations), causing incorrect branch labels. The fix adds a helper function `skip_rebase_checkout()` to handle non-standard reflog messages, ensuring `%gb` names the correct branch even when `GIT_REFLOG_ACTION` is set. The series also includes a new test case (`t/t1414-reflog-walk.sh`) to validate this edge case. The preparatory patch (1/2) refactors hard-coded reflog message strings into `#define` constants in `reflog.h`, making future changes easier.
