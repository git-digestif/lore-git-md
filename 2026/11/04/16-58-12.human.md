This is a brief follow-up in the ongoing discussion about fixing a performance regression in Git’s object quarantine mechanism. The patch in question (now in `next` as v2) prevents `rev-list --alternate-refs` from listing the repository’s own refs twice during connectivity checks, which was causing measurable slowdowns—especially in repositories with many hidden refs.

Kristofer Karlsson, the original author, had asked Justin Tobler for guidance on the short-term path forward, presenting four options: adopt Jeff King’s minimal **commondir comparison** approach, implement Justin’s proposed **read-only transaction environment**, add a regression test, or defer the fix entirely. Justin replies here that he considers Jeff King’s approach a reasonable short-term solution. He also notes that he plans to revisit how the "files" ODB backend manages the object directory later, but that this will wait until other transaction-related work lands.

The discussion is now effectively settled on Jeff King’s commondir comparison as the immediate fix. This aligns with the project’s preference for small, self-contained patches and avoids the complexity of broader ODB abstraction changes for now. The v2 patch remains in `next`, and unless new objections arise, this thread is likely to conclude with Jeff’s approach being adopted.
