This is a refactoring series targeting the commit-graph writing code, part of Patrick Steinhardt’s ongoing effort to make the object database (ODB) pluggable. The series consists of ten patches that clean up interfaces, consolidate options into a single `struct commit_graph_write_options`, and modernize function names. It touches `commit-graph.c`, `builtin/commit-graph.c`, and a handful of callers (`fetch.c`, `gc.c`, `fsck.c`), plus a small addition to `odb/source-files.c` to verify commit-graphs during fsck.

The motivation is explicitly preparatory: these changes are split out from a larger patch series that will make commit-graph reading and writing pluggable via the ODB backend. By moving all write options into a single structure and removing redundant flags, the code becomes more consistent and easier to extend. The series also merges two separate commit-graph writer implementations into one, which should reduce duplication and simplify future maintenance.

Patch-by-patch, the changes are mechanical and focused: renaming structures, passing flags through options rather than as separate parameters, dropping redundant checks, and aligning function names with modern conventions. The only behavioral change is that commit-graph verification is now performed as part of `odb/source-files.c`’s fsck routine, which is a logical extension of existing checks.

The series is based on `master` (750f5de7dfe) with Patrick’s earlier `ps/commit-graph-cleanups` branch merged in. Given the author and the clear tie-in to the ODB abstraction work, this looks like a well-crafted, incremental step toward a larger goal. There’s no controversy apparent in the cover letter, and the changes are narrowly scoped enough that they should be straightforward to review. If you care about the ODB backend effort or the commit-graph subsystem, this series is worth a look.
