This thread reports a severe performance regression in `git log --follow` that emerged in Git 2.56, slowing the command from about a second to ten minutes when tracking files through non-linear history (such as forward merges of maintenance branches). The issue was bisected to commit 304812ed33, which introduced logic that runs a full diff against every parent of a merge commit—even when the tracked file is absent in that parent—causing the cost to balloon with the number of merges and tree size. The regression affects real-world tools like VS Code’s Timeline view and has no known workarounds.

Patrick Steinhardt recently acknowledged the report but noted that the issue is already being addressed in an earlier thread, which contains patches under active review. That thread is now the primary venue for discussion and proposed fixes, so anyone following this regression should refer there for updates on the solution. No new technical details or objections were raised in this message; the focus remains on the existing patch series as the way forward. The core question—whether the new logic can be optimized to skip unnecessary diffs without regressing the original fix—remains open and is being worked on in the linked thread.
