This thread is about Patrick Steinhardt’s ten-patch series refactoring Git’s commit-graph write code to consolidate scattered flags and global variables into a single `struct commit_graph_write_options`. The goal is to clean up the internal interface as preparatory work for making commit-graph reading and writing pluggable via the object database backend. The series is part of Steinhardt’s broader ODB abstraction effort.

The first two patches have been posted (v1), with no review feedback yet. The second patch moves the `enum commit_graph_write_flags` parameter into the new options struct, making the struct mandatory for all callers. This affects core commit-graph writing functions and built-in commands like `git commit-graph`, `git fetch`, and `git gc`. The change is mechanical—flags like `COMMIT_GRAPH_WRITE_APPEND` are now set via the struct rather than as separate parameters—and reduces code slightly while improving interface hygiene. No user-visible behavior changes are introduced.

The series touches `commit-graph.c`, `commit-graph.h`, and several built-in commands, with no on-disk format changes or new test files. While the refactoring is unlikely to be controversial, reviewers may weigh in on naming or edge cases in later iterations.
