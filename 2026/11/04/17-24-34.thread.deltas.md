## 2026/11/04

- [2026/11/04/17-24-34 by Yopa Nelly <yopatatchou@gmail.com>] Yopa Nelly submitted a patch adding a `promisor.fetchOrder` config variable (comma-separated remote names) so that listed promisor remotes are tried first in the specified order when fetching missing objects, with unlisted remotes following in original config order and the `extensions.partialClone` remote still last unless explicitly listed; the ordering is applied via a stable insertion sort in `promisor_remote_sort()` called at the start of each pass in `try_promisor_remotes()`, preserving the existing accepted-remotes-first behavior. The patch does not validate `fetchOrder` entries against configured remotes (typos keep default position) and includes no test because the t5710 fixture never triggers a lazy fetch, with the author offering to write a follow-up test using a fixture with two client promisor remotes.
