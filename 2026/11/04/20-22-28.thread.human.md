This thread is about converting `git credential` to use Git’s standard `OPT_SUBCOMMAND` mechanism, making the command more idiomatic and improving its help output and shell completion support. The series, authored by Wasswa Edson, is now complete with the third and final patch in its second version (v2).

The work replaces the manual `strcmp()`-based subcommand dispatch with `OPT_SUBCOMMAND`, which enables per-subcommand usage strings and better error handling. The changes are split into three incremental patches: the first aligned the `-h` output with the man page synopsis, the second refactored each subcommand into its own function, and the third (just posted) completes the transition by switching to `OPT_SUBCOMMAND`. The series also removes the `NO_PARSEOPT` flag, making the command visible to `--list-cmds=parseopt`.

Key improvements include clearer error messages (e.g., "need a subcommand" or "too many arguments"), subcommand-specific help via `git credential <subcommand> -h`, and consistent rejection of extra arguments. The core credential operations remain unchanged, ensuring backward compatibility. Tests verify the new behavior, including subcommand-specific help and error handling.
