This thread is about a patch from Wasswa Edson that modernizes the `git credential` builtin by switching its subcommand dispatch from manual `strcmp()` checks to Git’s standard `OPT_SUBCOMMAND` mechanism. The change makes the command’s behavior more consistent with other Git builtins—adding per-subcommand usage strings and shell completion support—while fixing minor documentation quirks (adding the missing "capability" subcommand to the usage string and marking the man page synopsis as `[verse]` for test extraction).

The patch is a clean refactoring with no functional changes to the core credential operations (fill, approve, reject, or capability). It replaces the old dispatch logic with four new static functions, one per subcommand, and removes the `NO_PARSEOPT` flag so the command now appears in `--list-cmds=parseopt`. Tests confirm the new help output and clearer error messages for missing or unknown subcommands, though shell completion improvements aren’t directly tested. So far, the patch has drawn no review feedback, but it’s a straightforward, uncontroversial improvement that aligns `git credential` with Git’s established patterns.
