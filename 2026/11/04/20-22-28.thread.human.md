This thread tracks Wasswa Edson's three-patch v2 series that converts `git credential` to use the standard `OPT_SUBCOMMAND` parse-options mechanism instead of manual `strcmp()` dispatch. The series splits the work into incremental steps: aligning `-h` output with the documentation, refactoring each subcommand into its own function, and finally switching the main dispatch to `OPT_SUBCOMMAND`, which enables per-subcommand help and shell completion support. All v1 feedback has been addressed, and the series is now functionally complete and uncontroversial.

Two reviewers have provided substantive approval. Tanga Joris confirmed patch 3 works correctly and approved it, pending only a commit message tweak to document a subtle behavior change: `git credential <subcommand> --` now consumes the end-of-options marker instead of erroring. Laveesh Bansal delivered an exceptionally thorough tested review of the cover letter, building each commit individually, running the relevant test suites under both SHA-1 and SHA-256, and performing differential testing across roughly fifty command lines to confirm identical output for valid input. Junio C Hamano replied to Bansal's write-up to endorse his detailed old-versus-new reasoning as the model for future reviews, noting that one-line approvals make it hard for bystanders to gauge review depth.

The series remains under review with no merge status reported. The only open item is the author updating patch 3's commit message to document the `--` handling change that Tanga Joris flagged. A secondary question raised by Bansal -- whether a dedicated bash completion script for `git credential` will follow -- also remains unanswered.
