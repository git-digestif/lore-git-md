This is the first patch in a two-patch bugfix series targeting a loose object database (ODB) cache invalidation bug during `git merge`. The series addresses a scenario where newly written merged blobs cannot be read back due to stale cache entries, causing Git to incorrectly assume the objects are missing and triggering unnecessary backfill fetches from promisor remotes.

This patch is a preparatory refactoring. It extracts the logic for retrieving the subdirectory bitmap (used to track which sharding directories have been scanned) into a separate helper function, `subdir_seen_bitmap()`. The change is mechanical and does not alter behavior—it simply moves existing code into a reusable function to avoid duplication in the next patch. The commit message explains the motivation clearly: the extracted logic will be needed by a second function that invalidates the cache after writing new objects.

The patch touches only `odb/source-loose.c`, a core ODB component, and is small (17 insertions, 7 deletions). It is authored by Patrick Steinhardt, a domain expert in Git’s ODB abstraction, which lends credibility to the approach. The refactoring looks clean and uncontroversial, setting the stage for the actual fix in the next patch. No review feedback has appeared yet, but this patch is unlikely to draw objections given its straightforward nature.
