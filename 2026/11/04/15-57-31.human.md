This is the ninth patch in Patrick Steinhardt’s ten-patch series refactoring the commit-graph write code as part of the ODB abstraction effort. The patch moves commit-graph verification from `git fsck`’s main command into the pluggable `odb_source_files_fsck()` callback, aligning it with how multi-pack indices, bitmaps, and other auxiliary data structures are already handled.

The change removes the hard-coded `ERROR_COMMIT_GRAPH` exit code and the manual `child_process` spawning in `builtin/fsck.c`, replacing it with a new `fsck_commit_graph()` helper inside `odb/source-files.c`. The helper respects the same rules as the rest of the ODB fsck callbacks: commit graphs in alternates are only verified when `ODB_FSCK_FULL` is set, and `--connectivity-only` skips verification entirely. Failures are now reported via the generic `ERROR_OBJECT` bit rather than a dedicated error code, matching the pattern used for MIDX and bitmaps.

The diff is clean and mechanical: twenty lines removed from `cmd_fsck()` and twenty-five added to `odb_source_files_fsck()`. No new user-visible behavior is introduced, but the patch paves the way for pluggable commit-graph backends by making verification a first-class ODB operation. The commit message clearly explains the consequences of the change and ties it back to the broader ODB abstraction goal.
