This thread introduces an Outreachy internship proposal by Srujith Poojary to refactor Git's pathspec code as part of the broader effort to eliminate global state. The project targets `find_pathspecs_matching_skip_worktree()` in `pathspec.c`, which currently relies on the global `the_repository->index` instead of accepting an explicit `struct index_state *` parameter. Srujith, who has prior contributions to Git (test modernization, diff-delta safety, and submodule changes), outlines a 13-week plan to update the function and its four call sites in `pathspec.c`, `builtin/add.c`, and `builtin/rm.c`.

The proposal explores two API approaches—adding an explicit `istate` parameter or extending an existing helper with a new option—and emphasizes incremental progress, regression testing, and compatibility validation. Key challenges include ensuring sparse-checkout/sparse-index compatibility and designing tests to verify the helper uses the caller-provided index. While the scope is intentionally narrow (focusing only on this function rather than the entire pathspec subsystem), it aligns with René Scharfe’s ongoing `the_repository` removal effort. The tone is cautious, prioritizing maintainer feedback before expanding the work. No decisions or reviews have been posted yet; the thread is currently just the proposal itself.
