This is a bugfix patch targeting the fsmonitor and untracked cache subsystems. The patch addresses a long-standing integration bug (present since fsmonitor was introduced in 2017) where the untracked cache could remain incorrectly marked as valid after fsmonitor fails or returns a trivial response, causing new untracked files to remain invisible to `git status`.

The fix adds a new function `untracked_cache_invalidate_all()` in `dir.c` that recursively invalidates all untracked cache directories and marks the untracked extension as changed, ensuring the index is written even when no tracked entries change. The change is triggered in `fsmonitor.c` when fsmonitor use is disabled for the untracked cache. Two new tests in `t/t7519-status-fsmonitor.sh` validate the fix using the fsmonitor hook implementation, covering both "trivial" and "failure" response scenarios.

Derrick Stolee reports that performance tests show no degradation with the fix, provided the system's `max_user_watches` is sufficiently high (a regression appeared in initial Linux testing due to insufficient watches, but disappeared after increasing the limit). The patch touches `dir.c`, `dir.h`, `fsmonitor.c`, and the test script, adding about 60 lines total. The commit message clearly explains the bug's history, the fix's mechanism, and the testing approach.
