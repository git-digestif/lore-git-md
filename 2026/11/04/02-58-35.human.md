This is a review reply from Jeff King to the first patch in Farid Zakaria’s two-patch series fixing a race condition in the Git credential-cache daemon. The patch makes the daemon ignore `EEXIST` from `mkdir()` when creating the socket directory, preventing a second daemon from failing unnecessarily when the directory already exists.

Jeff’s feedback is brief but substantive: he agrees the fix makes sense and explains why the existing code handles the last path component separately (to avoid a race where an attacker could chdir into the directory before permissions are set). He notes that if the directory already exists, the daemon is still subject to the same race, but it is reasonable to assume the creator set permissions correctly. This observation reinforces the patch’s logic and provides useful context about the security model. The review is positive and uncontroversial, with no objections or requests for changes. The patch remains well-motivated and technically sound.
