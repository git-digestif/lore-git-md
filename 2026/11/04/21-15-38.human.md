This is a feature patch (v4 2/2) that implements the `%gb` format placeholder for `git log -g` and `git reflog`, allowing users to see which branch each reflog entry was recorded on. The patch is part of a two-patch series (plus a preparatory refactoring patch) that replaces earlier proposals for dedicated flags (`--operations` and `--historical-branch`) with a composable format specifier.

The `%gb` placeholder parses reflog messages to determine the branch context for each entry, handling edge cases like rebases (`git rebase <upstream> <branch>`), detached HEAD states, and branch renames. For example, `git log -g --format='%h %gd: (%gb) %gs'` will now show output like `(topic) rebase (finish): returning to refs/heads/topic`. When HEAD was detached, `%gb` outputs "detached at <commit>". For reflogs of other refs (not HEAD), it shows the shortened refname. The implementation is additive and does not alter default behavior—users must opt in via custom format strings.

This patch fixes a regression in branch-name detection when `GIT_REFLOG_ACTION` is set (e.g., during rebase operations), which previously caused `%gb` to mislabel entries. The fix introduces a new helper function, `skip_rebase_checkout()`, to handle non-standard reflog messages (e.g., `"sync switch: checkout ..."`). The test suite (`t/t1414-reflog-walk.sh`) has been expanded by 137 lines to cover this regression, including edge cases like `GIT_REFLOG_ACTION`-modified messages, rebases, branch renames, and detached HEAD states.

The patch touches core reflog-walking logic (`reflog-walk.c`, `revision.c`), built-in commands (`builtin/rebase.c`, `builtin/checkout.c`), and documentation. It introduces new functions (`mark_branches()`, `skip_rebase_checkout()`) and a `branches_marked` flag in `struct complete_reflogs` to track whether branch context has been determined. The preparatory patch (1/2) refactored hard-coded reflog message strings into `#define` constants in `reflog.h`, explicitly tying the refactoring to the `%gb` feature.

The implementation appears well-scoped and thoroughly tested, addressing all prior feedback from reviewers like Phillip Wood (who identified the `GIT_REFLOG_ACTION` regression) and Junio C Hamano (who raised concerns about alignment with future directions, such as translatable reflog messages). The series is ready for maintainer review, though Junio has not yet weighed in on v4. The broader architectural debate—whether to refactor multi-step commands to work on detached HEAD by default or change `git reflog`'s default behavior—remains unresolved, but this patch does not engage with it.
