This is the v3 cover letter for a two-patch series improving `git maintenance` lock handling. The series is now split into two focused patches: the first aligns manual invocation behavior with `git gc` (failing with exit code 128 when the lock is held), and the second adds a Trace2 event to log `--auto` skips with the specific error reason.

The v3 revision incorporates all feedback from Patrick Steinhardt’s substantive review of v2: the patches are now separated for better bisectability, the Trace2 event uses `strerror(err)` consistently for the `reason` field, and duplicated error-message formatting is refactored into a shared helper. The author has explicitly accepted Patrick’s suggestions and waited a day before posting v3 to allow additional review.

The series remains uncontroversial and narrowly scoped to lock-handling logic in `builtin/gc.c` and its test coverage in `t/t7900-maintenance.sh`. It introduces no on-disk format changes and preserves the existing design where stale locks require manual inspection. The Trace2 event (`"lock/skip": {"reason": <strerror(err)>, "errno": <code>}`) provides structured observability for production diagnostics, while the behavioral change ensures consistency between `git maintenance` and `git gc`.
