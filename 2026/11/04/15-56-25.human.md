This is a **performance regression bugfix follow-up** for `git log --follow`.

Patrick Steinhardt acknowledges the severe slowdown in `git log --follow` when tracking files through non-linear history (e.g., forward merges of maintenance branches into main). He confirms this is a known issue and points to an existing thread with patches already under review. The regression, introduced in commit 304812ed33 ("log: improve --follow following renames for non-linear history"), causes the command to run a full diff against every parent of a merge commit, even when the tracked file is absent in that parent, leading to a 600x slowdown in large repositories.

The thread Patrick links to appears to contain proposed fixes, though no details about their approach or status are included in this email. The original report remains valid: the regression affects real-world tools like VS Code’s Timeline view and is not mitigated by shallow clones, commit-graph, or configuration. If the patches in the linked thread address the root cause (O(N*M) cost scaling with merge commits and tree size), they could restore the expected performance while preserving the original fix’s goal of better rename following for non-linear history. The issue is under active review.
