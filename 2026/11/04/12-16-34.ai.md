This is the first patch in a two-patch bugfix series targeting the loose object database (ODB) cache invalidation logic during `git merge`. The series addresses a bug where newly written merged blobs cannot be read back due to stale cache entries, causing Git to incorrectly trigger backfill fetches from promisor remotes.

This patch is a preparatory refactoring. It extracts the logic for retrieving the subdirectory bitmap (used to track which sharding directories have been scanned) into a separate function, `subdir_seen_bitmap()`. The extracted logic is currently inlined in `odb_source_loose_cache()`, but the next patch will reuse it to fix the cache invalidation bug. The change is mechanical and does not alter behavior; it simply moves code to improve readability and reusability.

The patch touches only `odb/source-loose.c`, a core ODB component, and is authored by Patrick Steinhardt, a domain expert in Git’s object storage layer. The commit message is concise but clear about the motivation: avoiding code duplication in the upcoming fix. The diff is small (17 insertions, 7 deletions) and focused, making it easy to review. No new symbols are introduced, and the on-disk format remains unchanged.

This patch is uncontroversial and appears well-crafted. It sets the stage for the actual bugfix in the next patch, which will address the stale cache issue by ensuring proper invalidation after writing merged blobs. Reviewers familiar with the ODB subsystem will likely find this change straightforward.
