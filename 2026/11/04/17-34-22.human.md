This is the second patch in a two-patch series (v3 2/2) that adds Trace2 observability to `git maintenance run --auto` when it skips maintenance due to an existing lock. The series as a whole addresses a long-standing inconsistency: manual `git maintenance run` now fails fast (like `git gc`) when the lock is held, while `--auto` mode logs a Trace2 event instead of silently skipping.

This patch introduces a new Trace2 data event under the `"maintenance"` category: `"lock/skip"` with fields `"reason"` (the `strerror` message) and `"errno"` (the numeric error code). The event is emitted only in `--auto` mode, preserving the silent-skip behavior but making it visible to monitoring tools. The test verifies that the event contains the expected error string ("File exists") and that the lock file remains in place after the skip.

The implementation is minimal and focused: a single `trace2_data_string()` call in `builtin/gc.c` and a new test case in `t/t7900-maintenance.sh`. The event format is consistent with existing Trace2 conventions, and the patch respects the `--quiet` flag (no console output, only the Trace2 event). No behavior changes beyond the new diagnostic; the lock file is still preserved for manual inspection.

The series has been through two rounds of review with Patrick Steinhardt, who requested mechanical refinements (patch splitting, code deduplication) that are now incorporated. This patch is uncontroversial and ready for final review. If the first patch in the series lands, this one should follow immediately.
