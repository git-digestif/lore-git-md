This thread is an RFC patch series from Jelle van der Waa proposing to add `--verbose` support to `git history reword`, mirroring `git commit --amend --verbose` by showing the commit diff in the editor during message editing. The series also includes a minor cleanup patch removing a redundant `strbuf_stripspace()` call.

The discussion has centered on whether the diff display should be opt-in (via a flag) or opt-out (default behavior). Jelle initially proposed an opt-in `--verbose` flag, while Karthik Nayak argued for making diff display the default, eliminating the need for a flag entirely. Phillip Wood and D. Ben Knoble both favor opt-in but differ on details: Phillip wants immediate support for the `commit.verbose` config (consistent with `git commit --verbose`) and suggests `--show-diff` as a clearer flag name, while D. Ben Knoble prefers names like `--diff-in-editor` to avoid ambiguity with other potential "verbose" behaviors in `git history`. D. Ben Knoble also pushed back on Karthik’s opt-out proposal, citing practical concerns about long diffs and editor startup time.

The implementation itself is uncontroversial—Phillip praised the feature as useful and the code as clean—but open questions remain about the user interface, config support, and edge cases in diff generation (e.g., binary files, submodules, and status-related settings). The thread has not yet converged on a preferred approach, and no maintainer decisions have been made. The author has not responded to the naming or config debates, leaving the discussion in a holding pattern.
