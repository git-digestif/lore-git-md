This thread is about adding diff display to `git history reword` so users can see the full patch while editing the commit message, similar to `git commit --amend --verbose`. The author, Jelle van der Waa, proposed this as an opt-in feature via a `--verbose` flag in an RFC patch series, along with a small cleanup to remove a redundant `strbuf_stripspace()` call.

The discussion has centered on whether the diff should be opt-in (via a flag) or opt-out (default behavior). Three positions have emerged: the author’s opt-in approach, Phillip Wood’s suggestion to add `commit.verbose` config support now, and Karthik Nayak’s proposal to make diff display the default. Phillip Wood’s latest reply adds a new argument—scripted editing could be disrupted by the diff—and expresses a personal preference for making diff display the default for `git history reword`, citing Git’s experimental status as justification. D. Ben Knoble has also weighed in, questioning the `--verbose` flag name and advocating for alternatives like `--diff-in-editor` to avoid ambiguity with potential future "verbose" behaviors in `git history`.

The implementation itself is straightforward, with test coverage for edge cases like bare repositories and merge commits. However, open questions remain about config support, flag naming, and whether the feature should be opt-in or opt-out. No maintainer decisions have been made yet, and the thread is still in the RFC phase.
