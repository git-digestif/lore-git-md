The thread is an RFC patch series proposing to add diff display to `git history reword`, mirroring `git commit --verbose`. The author, Jelle van der Waa, implemented this as an opt-in `--verbose` flag, along with a minor cleanup patch. The discussion has since focused on whether the diff should be opt-in (via a flag) or opt-out (default behavior), with no consensus yet.

Four distinct positions have emerged: the author prefers opt-in via `--verbose`; D. Ben Knoble supports opt-in but would accept opt-out if configurable; Phillip Wood initially favored opt-in with config support but now leans toward opt-out, citing the command’s experimental status; and Karthik Nayak argues for opt-out without any flag, deferring opt-out mechanisms to a future patch. The debate also touches on flag naming (`--verbose` vs. alternatives like `--show-diff`), scripted editing concerns, and whether `commit.verbose` config support should be added now or later.

The series is still under review, with no maintainer decisions. Key technical details include a new `print_verbose_diff()` helper, test coverage for edge cases like merge commits, and a proposed cleanup of redundant `strbuf_stripspace()` usage. The discussion remains open on whether to reuse more of `wt-status.c`’s diff logic and how to handle future expansion to other `git history` subcommands.
