This thread is an RFC patch series from Jelle van der Waa proposing `--verbose` support for `git history reword`, mirroring `git commit --amend --verbose` by showing the full diff while editing the commit message. The series also includes a small cleanup removing a redundant `strbuf_stripspace()` call in `builtin/history.c`.

The patches are under review, with no maintainer decisions yet. The implementation touches `builtin/history.c`, adds a new test file (`t/t3451-history-reword.sh`), and introduces a `COMMIT_TREE_VERBOSE` flag to trigger diff display. The diff logic is well-tested, including edge cases like bare repositories and merge commits (where the diff is generated against the first parent). The author omitted `commit.verbose` config support for now but left the door open for future expansion to other subcommands like `split`, `squash`, and `fixup`.

D. Ben Knoble’s recent review raises a conceptual concern: whether "verbose" is the right term for this behavior in `git history`. He suggests the flag name might be better reserved for showing a summary of rewritten commits after execution, and proposes alternatives like `--commit-verbose` or `--diff-in-editor` to avoid ambiguity. While Knoble acknowledges the value of consistency with `git commit`, his feedback highlights a potential usability issue before the feature solidifies. The author hasn’t yet responded to this specific point, so the naming question remains open. Other open questions include whether `commit.verbose` config support should be added now and whether the merge-commit diff behavior (first-parent only) is the correct default.
