This thread is an RFC patch series from Jelle van der Waa proposing `--verbose` support for `git history reword`, allowing users to see the full diff while editing the commit message, similar to `git commit --amend --verbose`. The series also includes a preliminary cleanup patch removing a redundant `strbuf_stripspace()` call.

The discussion has centered on two key points: the choice of the `--verbose` flag name and whether to support the `commit.verbose` configuration option now or later. D. Ben Knoble raised concerns that "verbose" could be ambiguous in the context of `git history`, suggesting alternatives like `--commit-verbose` or `--diff-in-editor`. Phillip Wood agreed that the name could be clearer and proposed `--show-diff` as another option, though no decision has been made yet. On the configuration front, Phillip has consistently argued for including `commit.verbose` support immediately to maintain consistency with `git commit --verbose`, while the author has preferred deferring it.

The series is still under review, with no maintainer decisions yet. The implementation itself is praised as a useful improvement, but there are open questions about edge cases in diff display (e.g., binary files, submodules) and whether the merge-commit diff behavior (first-parent only) is the correct default. Phillip has also suggested code cleanups, such as reusing `wt-status.c`'s diff logic and consolidating config callbacks across `git history` subcommands. The author has indicated openness to expanding `--verbose` to other subcommands like `split`, `squash`, and `fixup` in the future. The thread remains collaborative, with participants focused on refining the user interface and ensuring the feature aligns with Git’s existing conventions.
