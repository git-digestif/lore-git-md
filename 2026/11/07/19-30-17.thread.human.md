The `git history reword --verbose` RFC is shaping up as a small but surprisingly contentious feature. Jelle van der Waa wants to add diff display to the reword editor, mirroring `git commit --amend --verbose`, and started with a two-patch series: a cleanup of redundant whitespace stripping, then the diff logic itself. The implementation is clean and well-tested, but the discussion has quickly expanded beyond the immediate feature.

The central debate is whether the diff should be opt-in (via a `--verbose` flag) or opt-out (default behavior). Six distinct positions have emerged: Jelle’s original opt-in, opt-in with immediate config support (Phillip Wood), opt-out (Karthik Nayak and Phillip Wood), opt-in with a preference for future opt-out (Phillip Wood), conditionally accepting opt-out only if it’s configurable (D. Ben Knoble and Patrick Steinhardt), and opt-out with opt-out deferred to a future patch (Karthik Nayak). The debate remains unresolved, with no clear consensus on the path forward.

Patrick Steinhardt’s latest clarification adds a new constraint: the diff format must be generalizable to all `git history` subcommands (`split`, `squash`, `fixup`, etc.), not just `reword`. He’s not just concerned with the option name (e.g., `--verbose`, `--show-diff`) but with the **output format**—how the diff (or other change summary) is presented in the editor. He suggests `git range-diff`’s format as a model, implying a structured, multi-commit summary rather than a simple unified diff. This shifts the discussion from user interface to technical design, ensuring the implementation doesn’t paint itself into a corner for future subcommands.

The thread is still under review, with no maintainer decisions yet. Key open questions include whether `commit.verbose` config support should be added now, how to handle edge cases in diff display (binary files, submodules, etc.), and whether the test suite should be refactored to reduce redundancy. The author hasn’t yet weighed in on the flag naming debate or the generalizability requirement, so the next iteration of the series will likely need to address these points.
