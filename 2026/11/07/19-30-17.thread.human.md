Here’s the updated **human-mode** summary for a developer catching up:

This thread is an RFC patch series from Jelle van der Waa proposing to add `--verbose` support to `git history reword`, so users see the full diff while editing the commit message—mirroring `git commit --amend --verbose`. The series also cleans up a redundant `strbuf_stripspace()` call in `builtin/history.c`. Two patches are under review: the cleanup and the diff-display implementation with tests.

The main debate is whether the diff should be opt-in (via `--verbose`) or opt-out (default behavior). The author and D. Ben Knoble favor opt-in, arguing for user control and avoiding ambiguity in the `--verbose` flag name (D. Ben suggests alternatives like `--diff-in-editor`). Phillip Wood and Karthik Nayak now advocate for default diff display, citing Git’s experimental status and better user experience, though Phillip raises concerns about scripted editing (where the diff could interfere with automation). No consensus has emerged, and the discussion has expanded to include config support (`commit.verbose`), edge cases in diff generation, and whether the feature should extend to other `git history` subcommands like `split` or `squash`.

The implementation is technically sound, reusing Git’s diff machinery and testing edge cases like merge commits (showing diffs against the first parent). Phillip Wood suggests reusing more of `wt-status.c`’s logic for consistency with Git’s status settings, and both he and D. Ben Knoble critique the test suite’s redundancy. The thread remains open, with key questions unresolved: flag naming, default behavior, and whether to add config support now or later.
