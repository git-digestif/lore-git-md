This is the **seventh and final patch in the v8 series** adding path-related keys to `git repo info`. It introduces the `path.cdup` key, which returns the relative path from the current working directory to the repository’s working tree root (e.g., `../../` in a subdirectory, empty string at the root, or the absolute path when outside the working tree). The patch is **mechanically clean, well-tested, and uncontroversial**, resolving the last open design question from earlier versions by providing symmetry with `git rev-parse --show-cdup`.

The implementation adds a new getter function, `get_path_cdup()`, in `builtin/repo.c`. The function checks `is_inside_work_tree(repo)` and, if false, returns the absolute path to the working tree via `repo_get_work_tree(repo)`. When inside the working tree, it constructs the relative path by counting slashes in the repository’s `prefix` field. The control flow is streamlined to return early when outside the working tree, improving readability. Tests in `t/t1900-repo-info.sh` cover the root directory (empty string), subdirectory (e.g., `../../`), and outside-working-tree (absolute path) scenarios.

This patch directly addresses Junio C Hamano’s prior design objection by completing the relative-path key set (`path.git-prefix` and `path.cdup`). The behavior now strictly mirrors `git rev-parse --show-cdup`, including the edge case where the current directory is outside the working tree. The documentation in `Documentation/git-repo.adoc` is minimal but clear, and the tests are thorough, including a subshell-wrapped test for the outside-working-tree case to avoid environment leakage.
