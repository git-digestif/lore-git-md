This thread is about clarifying and implementing fetch ordering for promisor remotes in Git's partial-clone subsystem. The effort began with a documentation patch by Hussain Sitamouwala, an Outreachy contributor, which has been queued in Junio’s topic `hs/doc-promisor-fetch-order` and is currently cooking in `next`. The patch updates `Documentation/technical/partial-clone.adoc` to clarify the existing fetch ordering behavior introduced by commit `8808e61fd3`.

The broader Outreachy project is now moving into the implementation phase, starting with client-side configuration of fetch ordering (no protocol changes). The server-advertised preferences phase, which will require protocol changes, is deferred until later. Kaartic Sivaraam, the Outreachy mentor, has confirmed this phased approach and expressed support for Hussain’s plan to begin with the client-side work. The project remains uncontested technically, with Junio and Christian Couder (a domain expert) implicitly endorsing the direction. The next steps depend on the Outreachy contributor selection results, but the implementation work is expected to proceed smoothly once underway. Open questions include how the client-side configuration will interact with the documented baseline behavior and the timeline for the server-side phase.
