This is the sixth patch in Thomas Bachem’s 15-patch bugfix series addressing Git segfaults when config settings lack values. It targets a crash in `remote.c` when `remote.<name>.tagOpt` is specified without a value (e.g., `git -c remote.origin.tagOpt`), which causes `handle_config()` to pass `NULL` to `strcmp()`. The fix adds a `NULL` check and rejects the missing value with `config_error_nonbool()`, consistent with how `remote.<name>.url` and `remote.<name>.pushurl` are already handled. The patch also adds a test in `t/t5505-remote.sh` to verify the error message.

The change is minimal and surgical: two lines added to `remote.c` and a five-line test case. It follows the series’ established pattern of using `config_error_nonbool()` for unvalued config keys, making it uncontroversial and likely to be accepted as-is. No new edge cases or design questions are introduced; this is a straightforward application of the series’ core fix strategy. The test coverage is adequate, though it only checks the error message and not the absence of a crash (which would require a more involved test setup).
