This is a **substantive review and proposed fix** for the critical index corruption bug in `split-index.c` when both `core.splitIndex` and `index.skipHash` are enabled. Tanga Joris identifies the root cause: `write_shared_index()` names the shared index file after its trailing checksum, which is written as zeros when `index.skipHash` is enabled, resulting in a filename of all zeros. The split index then records a null base OID, and `read_index_from()` treats this as "no shared index," causing the entries in the shared index to be silently discarded. This explains the null OIDs, missing entries, and crashes observed in the original report.
