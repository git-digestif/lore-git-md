This is the eighth patch in Thomas Bachem’s 15-patch series fixing Git segfaults when config settings are given without values. It targets a crash in `git merge` when `branch.<name>.mergeOptions` is specified without a value (e.g., `git -c branch.main.mergeOptions merge ...`). The fix is straightforward: the config callback now checks for a NULL value and rejects it with `config_error_nonbool()`, matching the existing pattern used elsewhere in the same function for other string-valued config keys.

The patch touches `builtin/merge.c` and adds a test in `t/t7600-merge.sh` to verify the error message. The change is minimal and aligns with the series’ consistent approach to handling unvalued config keys. Like the other patches in this series, it looks well-crafted and uncontroversial, addressing a clear bug with a targeted fix and test coverage. No new edge cases or design questions are introduced here.
