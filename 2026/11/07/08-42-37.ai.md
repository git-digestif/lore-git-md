This is the fifth patch in Thomas Bachem’s 15-patch bugfix series addressing Git segfaults when config settings lack values. It fixes a crash in `git grep`, `git log`, and `git show` when `grep.patternType` is given without a value (e.g., `git -c grep.patternType`). The fix adds a NULL check in `grep_config()` to reject the missing value with `config_error_nonbool()`, aligning with the series’ consistent error-handling pattern. The patch touches `grep.c` and adds a test in `t/t7810-grep.sh` to verify the rejection message.

The change is narrow and uncontroversial: it plugs a NULL-dereference in `parse_pattern_type_arg()` by following the same approach already used for `color.grep.*` slots in the same function. No new symbols or behavior changes are introduced beyond the crash prevention. The test coverage is minimal but sufficient, checking only that the error message appears. This patch is one of the simpler fixes in the series, with no edge cases or special handling required.
