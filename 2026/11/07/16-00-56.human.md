This is the third patch in the v8 series adding new path-related keys to `git repo info`. It introduces `path.superproject-root.absolute` and `path.superproject-root.relative` to expose the superproject’s working tree root when the current repository is a submodule.

The implementation is straightforward: the new keys use the `get_superproject_working_tree()` helper (fixed in patch 2/7 to respect the `repo` parameter) and the existing `format_path()` utility to produce absolute or relative paths. The getter functions are clean and free of redundant early returns, addressing feedback from Justin Tobler on v7. Tests cover both submodule and non-submodule cases, including edge cases like `--git-dir` usage and empty-string returns when not in a submodule.

This patch is uncontroversial and mechanically complete. It depends on the correctness fix in patch 2/7 but otherwise stands alone. The design—returning an empty string when not in a submodule—aligns with the behavior of other path keys in the series and matches the precedent set by `git rev-parse --show-superproject-working-tree`. No substantive feedback remains, and the patch is ready for merging.
