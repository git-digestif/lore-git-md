This is patch 6/7 of the v8 series adding path-related keys to `git repo info`. It introduces the `path.git-prefix` key, which returns the relative path from the working tree root to the current directory (e.g., `sub/dir/`), including a trailing slash. The implementation is straightforward: it reads the repository’s `prefix` field (which is `NULL` at the root) and formats it into the output buffer.

The patch touches three files:
- `Documentation/git-repo.adoc` adds a brief description of the new key.
- `builtin/repo.c` implements the getter function (`get_path_git_prefix`) and registers the key in the `repo_info_field` table.
- `t/t1900-repo-info.sh` adds two tests: one for the root directory (expecting an empty string) and one for a subdirectory (expecting `sub/dir/`).

The implementation is clean and uncontroversial. The getter function is minimal, and the tests cover the two primary cases (root vs. subdirectory). This key was explicitly requested by Junio C Hamano in earlier rounds to provide symmetry with `path.cdup` (added in patch 7/7), and its inclusion is now settled. No substantive feedback remains on this patch.
