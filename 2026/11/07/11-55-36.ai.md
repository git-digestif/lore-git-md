This is the second patch in the v5 series introducing the `%gb` format placeholder for `git log -g` and `git reflog`. It implements the core functionality: parsing reflog messages to determine which branch `HEAD` was on when each entry was recorded, handling edge cases like detached HEAD states, rebases, branch renames, and custom `GIT_REFLOG_ACTION` values.

The patch adds the `%gb` placeholder to `pretty.c` and implements its logic in `reflog-walk.c`. Key components include:
- A new `get_reflog_branch()` function that returns the branch name (or "detached at <commit>") for each reflog entry.
- A `mark_branches()` helper that walks the reflog backward to assign branch context to each entry, using `#define` constants from `reflog.h` (introduced in patch 1/3) to parse reflog messages.
- Robust handling of edge cases: `git rebase <upstream> <branch>` (previously a correctness gap), detached HEAD labeling (now correctly showing the commit where HEAD was originally detached), and rebase checkout parsing (ignoring commit subjects starting with "checkout").
- A `branches_marked` flag in `struct complete_reflogs` to avoid redundant computation.
- For reflogs of non-`HEAD` refs, `%gb` simply shows the shortened refname.

The test coverage in `t/t1414-reflog-walk.sh` is thorough, validating scenarios like:
- Rebases of detached HEADs (including fast-forward and aborted rebases).
- Branch renames and custom `GIT_REFLOG_ACTION` values (e.g., `"sync switch: checkout ..."`).
- Interaction with `--decorate` and complex workflows (e.g., `git pull -r`, `git rebase -i`).
- Correct labeling of detached HEAD entries (e.g., "detached at <commit>").

The implementation is additive and does not alter default behavior. Users can include `%gb` in custom formats (e.g., `git reflog --format='%h %gb %gd %s'`) without losing other decorations. The patch addresses all prior feedback, including Phillip Wood’s failing test case from v4, and is ready for maintainer review.

The broader architectural debate about reflog message design (e.g., translatability) remains unresolved, but this patch does not engage with it, focusing instead on a targeted improvement.
