This is the fourth patch in Thomas Bachem’s 15-patch bugfix series addressing Git segfaults when config settings lack values. It fixes a crash in the bundle URI subsystem when `fetch.bundleCreationToken` is set without a value (e.g., `git -c fetch.bundleCreationToken fetch`). The crash occurs in `fetch_bundles_by_token()` when the NULL value is passed to `sscanf()`. The fix aligns with the series’ pattern of graceful handling: it treats a missing value the same as an unparseable one (defaulting to 0), ensuring the bundle list is downloaded and the new token stored. The patch touches `bundle-uri.c` and adds a dedicated test in `t/t5558-clone-bundle-uri.sh` to verify the behavior.

The change is minimal and targeted, adding only a NULL check before `sscanf()` and reusing the existing fallback logic. The test exercises the edge case by cloning with an unvalued `fetch.bundleCreationToken` and confirming the token is correctly updated to 1. This patch is uncontroversial and follows the series’ established error-handling precedent. No new symbols or APIs are introduced, and the fix is consistent with the series’ goal of eliminating segfaults without altering Git’s intended behavior. The bundle URI subsystem is the sole focus here, with no cross-subsystem implications.
