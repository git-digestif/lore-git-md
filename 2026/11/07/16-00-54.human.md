This is the first patch in the eighth version of a seven-patch series adding new path-related keys to the `git repo info` command. The series is part of a Google Summer of Code project and is now mechanically complete and ready for final review.

This patch introduces `path.toplevel.absolute` and `path.toplevel.relative` keys, which expose the root directory of the repository’s working tree in a scriptable format. The absolute key returns the canonical path, while the relative key returns the path relative to the current working directory. In bare repositories, both keys return an empty string, matching the behavior of `git rev-parse --show-toplevel`. The implementation uses `repo_get_work_tree()` and `format_path()` to ensure consistent formatting, and the patch includes thorough tests covering subdirectory execution and bare-repository edge cases.

The patch is well-structured, with clear documentation and test coverage. It addresses a real scripting need by providing a predictable alternative to `git rev-parse --show-toplevel`, avoiding the need for scripts to parse command output. The commit message is concise and explains the motivation and behavior clearly. There are no unresolved mechanical or design issues in this patch, and it aligns with the series’ overall goal of making repository paths more accessible to scripts.
