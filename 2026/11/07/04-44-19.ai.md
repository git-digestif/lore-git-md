This is a **bugfix** for the `merge-ort` strategy, addressing the regression in `--no-overwrite-ignore` where ignored files were being overwritten during directory rename detection. The patch by Aniket Gupta directly resolves the issue reported by Coy Geek by plumbing the `--no-overwrite-ignore` option through the merge machinery.

The fix introduces a new `preserve_ignored` bit in `struct merge_options` and propagates it from the command-line option to the merge-ort checkout logic. It also corrects the trivial-merge path in `builtin/merge.c`, which previously ignored the option. The patch touches `merge-ort.c`, `merge-ort.h`, `builtin/merge.c`, and adds two comprehensive tests to `t/t7600-merge.sh`: one for direct collisions and one for directory renames.

The implementation is clean and minimal, addressing the FIXME comments left in the code. The tests cover both the original regression case (directory rename) and a simpler direct collision, ensuring the option works as documented. This patch is well-motivated, clearly explained, and ready for review—it should resolve the data-loss risk for users relying on `--no-overwrite-ignore`. No new symbols or on-disk format changes are introduced.
