This is the first patch in a 15-part bugfix series addressing Git segfaults when config settings are given without values. It fixes a crash in `git rebase -i` when `rebase.missingCommitsCheck` is set without a value (e.g., `git -c rebase.missingCommitsCheck` or a bare entry in `.gitconfig`). The crash occurs because the code passes a `NULL` value to `strcasecmp()` when reading the config.

The fix replaces `repo_config_get_value()` with `repo_config_get_string_tmp()`, which properly rejects missing values with `config_error_nonbool()`, following the established pattern from ba176db511 (2023-12-07). The patch also adds a test to verify the error message is shown when the config is malformed. This is a clean, targeted fix that aligns with the project’s existing error-handling conventions.

The change is minimal—just one line in `rebase-interactive.c` and a new test case—and doesn’t introduce any new behavior beyond preventing the segfault. The commit message clearly explains the problem, the solution, and the precedent. This looks like a well-crafted fix for a real issue, and the approach is uncontroversial.
