## 2026/11/09

- [2026/11/09/10-17-47 by Phillip Wood <phillip.wood123@gmail.com>] Phillip Wood reviewed the reword --verbose patch: he supports the feature and argues "commit.verbose" should also be supported since it is easy to do; he noted the usage lines are getting long (not a new problem), suggested making the `verbose` parameter a bool to drop the `!!()` in the caller, asked how hard it would be to have the wt-status code generate the diff as "git commit" does and whether status.relativePaths, status.renames and status.renameLimit should be respected, and said he is in two minds about sharing one config callback across subcommands. On tests he suggested building the expected diff with `git diff HEAD~^-` instead of `git show --format= HEAD~`, questioned the value of the scissors-line grep, the separate no-diff test, and the bare-repository test, and asked that the merge-commit verbose case extend the existing merge reword test because the history tests are slow.
- [2026/11/09/10-18-07 by Phillip Wood <phillip.wood123@gmail.com>] Phillip Wood agreed with D. Ben Knoble's earlier point that "verbose" is ambiguous, offered "--show-diff" as a possible alternative name (hedging that he is not sure it is any better), and agreed that supporting "commit.verbose" and extending --verbose to other subcommands is a good idea.
