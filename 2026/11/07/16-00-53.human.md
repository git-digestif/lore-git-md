This is a **feature patch series** (v8) from a Google Summer of Code contributor, adding seven new path-related keys to the `git repo info` command. The series is now **mechanically complete and ready for substantive technical review**, having addressed all prior feedback and dropped the controversial `path.grafts` keys.

The new keys expose filesystem locations of repository components in a scriptable, user-facing format: `path.toplevel.absolute`/`relative` (working tree root), `path.superproject-root.absolute`/`relative` (superproject root for submodules), `path.hooks.absolute`/`relative` (hooks directory, now handling `/dev/null` consistently), `path.index.absolute`/`relative` (index file), `path.git-prefix` (relative path from worktree root to current directory), and `path.cdup` (relative path from current directory to worktree root). Each key supports suffix-based formatting (absolute or relative paths) and follows Git’s established conventions for path handling.

Key improvements since v7 include dropping `path.grafts` (resolving the deprecation debate), simplifying the `path.superproject-root` implementation, and ensuring `/dev/null` is returned verbatim for both `path.hooks.absolute` and `path.hooks.relative` when `core.hooksPath` is set to that value. The series also fixes a test isolation issue in patch 2/7 by moving the `--git-dir` test to `t/t1500-rev-parse.sh` (exercising `rev-parse --show-superproject-working-tree` instead of the new `path.superproject-root` key), and improves portability by avoiding `git config` for `/dev/null` settings on Windows.

The implementation touches `builtin/repo.c` (adding the new keys), `submodule.c`/`submodule.h` (refactoring `get_superproject_working_tree` to use `struct repository *`), `Documentation/git-repo.adoc` (documenting the keys), and the test suite (`t/t1900-repo-info.sh` and `t/t1500-rev-parse.sh`). The commit messages are clear, and the tests cover edge cases like bare repositories, submodules, and `/dev/null` handling.
