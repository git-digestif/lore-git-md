This is a feature patch series that adds the `%gb` format placeholder to `git log -g` and `git reflog`, allowing users to see which branch each reflog entry was recorded on. The series is now in its fifth iteration (v5) and has been significantly refined based on prior review feedback.

The `%gb` placeholder addresses a long-standing usability issue: reflog output currently mixes entries from all branches without indicating which branch each entry belongs to. This makes it difficult to track branch history, especially during complex operations like rebases or branch renames. The new placeholder shows the branch name for each entry, or "detached at <commit>" when HEAD was detached. For example, `git log -g --format='%h %gd: (%gb) %gs'` now produces output like `9c8d7e6 HEAD@{0}: (topic) rebase (finish): returning to refs/heads/topic`.

The v5 series consists of two patches. The first renames hard-coded reflog message strings (like "checkout: moving from") to named constants in `reflog.h`, making the code more maintainable. The second implements the `%gb` placeholder itself, including logic to parse reflog messages and determine the correct branch name for each entry. The implementation handles edge cases like rebases of detached HEADs, branch renames, and custom `GIT_REFLOG_ACTION` values (e.g., during `git pull --rebase`). The test suite (`t/t1414-reflog-walk.sh`) has grown to 229 lines, covering these edge cases and validating the fixes for issues identified in earlier versions.

Key improvements in v5 include: (1) correctly labeling detached HEAD entries with the commit where HEAD was originally detached (rather than the commit before switching away), (2) properly handling `git rebase <upstream> <rev>` by only treating `<rev>` as a branch if `refs/heads/<rev>` exists, (3) ignoring commit subjects that start with "checkout" to avoid misinterpreting them as rebase checkouts, and (4) adding comprehensive tests for detached rebases (both fast-forwarded and aborted). The series also includes a new helper function `is_commit_subject()` to distinguish between actual rebase checkouts and commit messages that happen to start with "checkout".

The implementation is additive and does not change default behavior, reducing the risk of regressions. The series has addressed all prior review feedback, including the critical correctness issues raised by Phillip Wood in v4. The changes are well-scoped, focusing on the reflog-walking logic without broad refactoring. This looks like a solid, user-facing improvement that should be of interest to anyone who relies on reflogs for debugging or auditing workflows. The series is now ready for maintainer review.
