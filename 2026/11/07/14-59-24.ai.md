This is the second patch in Kristofer Karlsson’s three-patch series introducing `test-tool genbytes` to eliminate the macOS test-suite bottleneck caused by slow `tr(1)` invocations. It implements the new command and updates all existing test scripts that previously used `genzeros | tr` to use `genbytes` instead.

The patch adds `test-tool genbytes <byte> [<count>]`, which writes the requested byte directly to stdout. The existing `genzeros` command is turned into a thin wrapper around the same code, preserving its interface. The implementation uses a 256 KB buffer (matching the previous static buffer size) and silently handles invalid counts as before. Sixteen test scripts are updated to use `genbytes` instead of `genzeros | tr`, covering everything from reftable write options (`t0613`) to pack-object tests (`t5300`) and the expensive `t4205-log-pretty-formats.sh` that originally motivated the series.

Performance measurements in the commit message show dramatic improvements on macOS CI runners: the `osx-gcc` job drops from 821 s to 243 s (–70 %), and the `osx-reftable` job from 911 s to 194 s (–79 %). Linux jobs see only minor improvements (–2 % to –7 %), reflecting the already-efficient GNU `tr(1)`. The patch touches eight files: the core implementation in `test-genbytes.c`, test-tool plumbing, and six test scripts. No on-disk formats or test expectations change; the series remains a pure test-infrastructure optimization.
