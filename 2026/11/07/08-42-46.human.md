This is the fourteenth patch in Thomas Bachem’s 15-patch series fixing Git segfaults when config keys are given without values. It targets the bundle-uri subsystem, where a malformed bundle list (either local or advertised by a server) containing keys like `bundle.mode`, `bundle.heuristic`, `bundle.<id>.uri`, or `bundle.<id>.creationToken` without values would cause `git clone --bundle-uri` or `git fetch` to crash. The fix adds NULL checks in `bundle_list_update()` and rejects missing values with `config_error_nonbool()`, making the list invalid and allowing the operation to proceed without the bundles. The patch includes a new test in `t/t5750-bundle-uri-parse.sh` that verifies the error handling for each affected key.

The change is narrowly scoped and follows the series’ established pattern: it aligns with the precedent set by ba176db511 (2023-12-07) and matches the error-handling approach used in the other 13 patches. The test coverage is thorough, exercising both top-level (`mode`, `heuristic`) and per-bundle (`uri`, `creationtoken`) keys. This is a clear bugfix with no design controversy, and the patch looks well-crafted. The only potential wrinkle is the series’ merge conflict with two topics in `seen`, but that doesn’t affect this patch’s correctness.
