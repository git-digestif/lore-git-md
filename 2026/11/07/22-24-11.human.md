This is a brief follow-up in the ongoing **critical index corruption bug** thread. Tanga Joris, who previously identified the root cause, confirms they are actively working on a fix and will keep Andy Koppe (the original reporter) updated. No new technical details or code changes are introduced here—this is purely a progress update.

The bug remains high-severity: when both `core.splitIndex` and `index.skipHash` are enabled, Git silently corrupts the index (null OIDs, missing entries) and crashes with `BUG: wt-status.c:585`. The root cause—`write_shared_index()` generating a shared index filename from a zeroed checksum when `index.skipHash` is enabled—has not been disputed, and no other contributors have weighed in yet. The next expected step is Tanga’s patch, which will likely address the filename generation logic in `split-index.c` to ensure the shared index is correctly identified even when the checksum is skipped.

No maintainer feedback or test coverage has been added since the last update. The thread is still focused on resolving the issue, with Tanga as the sole author expected to submit a fix.
