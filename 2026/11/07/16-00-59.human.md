This is the sixth patch in the v8 series adding new path-related keys to `git repo info`. It introduces `path.git-prefix`, which exposes the relative path from the working tree root to the current directory (e.g., `sub/dir/`), including a trailing slash. The key returns an empty string when invoked from the working tree root.

The implementation is straightforward: it reads the repository’s `prefix` field (which is `NULL` at the root) and formats it into the output buffer. Tests cover both the root case and a subdirectory case, verifying the trailing slash is included. The documentation update is minimal but clear.

This patch is uncontroversial and mechanically clean. It addresses a long-standing gap in `git repo info`’s scripting interface by mirroring the behavior of `git rev-parse --show-prefix` in a structured, scriptable format. The trailing slash convention aligns with Git’s existing output for similar keys (e.g., `git rev-parse --show-cdup` omits it, but `path.cdup` in patch 7/7 includes it for symmetry). No substantive feedback remains, and the patch is ready for merging as part of the series.
