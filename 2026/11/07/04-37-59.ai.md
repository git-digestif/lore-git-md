This is Junio C Hamano’s reply to the v3 cover letter of Ravi Mistry’s five-patch series improving Git’s HTTP transport resilience. The series itself is technically complete and addresses all prior feedback, but Junio raises a procedural concern about how the default value for `http.retryAfter` is introduced.

The core issue is structural: the first four patches implement the feature under the assumption that `http.retryAfter` defaults to 0 (no initial delay), while the fifth patch retroactively changes that default to 10 seconds. Junio questions whether this two-phase approach is the right way to structure a topic, noting that it might make future adjustments (e.g., to 30 seconds) easier by isolating the default value change, but also risks giving the impression that the initial design was incomplete. He explicitly asks brian m. carlson for input, framing it as a question about maintainability rather than a technical objection to the 10-second compromise itself.

The email does not reopen the substantive debate over the 10-second default—both Junio and brian have already accepted that value—but focuses on how the change is presented in the patch series. This is a surface-level review concern, not a blocker, and the series remains ready for integration once this minor structural question is resolved. The thread context confirms that all technical feedback has been addressed, and the only remaining discussion is about patch organization.
