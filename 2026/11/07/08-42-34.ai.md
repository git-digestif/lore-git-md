This is the second patch in Thomas Bachem’s 15-patch bugfix series that eliminates Git segfaults when config keys are given without values. It targets the `core.alternateRefsCommand` and `core.alternateRefsPrefixes` settings in the object database (ODB) subsystem. When either key is set without a value (e.g., `git -c core.alternateRefsCommand`), the code previously passed NULL to `strvec_push()` or `strvec_split()`, causing a crash in commands like `git fetch`, `git receive-pack`, and `git rev-list --alternate-refs` when the repository uses alternates.

The fix replaces `repo_config_get_value()` with `repo_config_get_string_tmp()`, which explicitly rejects missing values by calling `config_error_nonbool()`. This aligns with the series’ consistent error-handling pattern and the precedent set by ba176db511 (2023-12-07). The patch also adds a dedicated test in `t/t5618-alternate-refs.sh` that verifies both settings now fail with a clear error message rather than crashing.

The change is minimal and surgical: only two lines in `odb.c` are modified, and the test is straightforward. No new symbols or APIs are introduced. The fix is uncontroversial and directly addresses the crash without altering the intended behavior of the config keys. This patch is a textbook example of the series’ broader goal—systematically hardening config parsing across Git’s subsystems.
