This is a test infrastructure patch series aimed at speeding up Git's test suite on macOS. The author, Kristofer Karlsson, identifies that the `tr(1)` command—used in some tests to generate large amounts of data—is disproportionately slow on macOS, causing a specific test (`t4205`) to run several times longer than on Linux. The series introduces a new `test-tool genbytes` command to replace the slow `genzeros | tr` pipeline, with the goal of improving CI performance on macOS.

The series is structured as three patches. The first renames `test-genzeros.c` to `test-genbytes.c` to set up the refactoring cleanly. The second adds the new `genbytes` command, which can generate arbitrary byte patterns (not just zeros) and replaces the `tr`-based pipeline in the tests. The third patch is optional: it folds the existing `genzeros` functionality into `genbytes` (using `NUL` as the byte specifier) and updates the 10 call sites that currently use `genzeros`. The author leaves it to the list to decide whether this consolidation is worth the churn.

The implementation is straightforward and well-motivated. The new `genbytes` command avoids the macOS `tr` bottleneck by generating the desired byte pattern directly in C, using a 256KB buffer (unchanged from `genzeros`). The author notes that smaller buffers didn’t improve performance, and the buffer is no longer static to avoid shared state. Invalid counts are still treated as zero, matching the existing behavior of `genzeros`.

This is a targeted, platform-specific performance improvement for the test suite. The patches are small, focused, and unlikely to be controversial, though the optional third patch may spark discussion about whether the consolidation is worth the effort. The series is clearly well-tested (the author mentions CI experiments) and addresses a real pain point for macOS users. If you care about test performance or CI reliability, this is worth a look.
