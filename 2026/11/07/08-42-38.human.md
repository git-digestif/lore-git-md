This is the sixth patch in Thomas Bachem’s 15-patch series fixing Git segfaults when config keys are given without values. It targets a crash in `git fetch`, `git remote`, and `git status` when `remote.<name>.tagOpt` lacks a value—`handle_config()` passes the NULL value straight to `strcmp()`, causing a segfault. The fix is simple and consistent with the series’ pattern: reject the missing value with `config_error_nonbool()`, just as `remote.<name>.url` and `remote.<name>.pushurl` already do. The patch touches `remote.c` and adds a test in `t/t5505-remote.sh` to verify the error message.

The change is uncontroversial and well-scoped. It follows the established error-handling precedent (ba176db511) and aligns with the rest of the series. The test is minimal but sufficient, checking that the command fails and emits the expected error. No new edge cases or design questions are introduced here—this is a straightforward bugfix that plugs one of the 17 identified crash sites. If the series as a whole is deemed sound, this patch is likely to be merged without further discussion.
