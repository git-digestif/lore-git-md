This is a **bugfix patch** (14/15 in a 15-patch series) addressing a segfault in `git clone --bundle-uri` and `git fetch` when bundle lists contain keys like `bundle.mode`, `bundle.heuristic`, `bundle.<id>.uri`, or `bundle.<id>.creationToken` without values. The crash occurs because `bundle_list_update()` passes NULL values to `strcmp()`, `relative_url()`, or `sscanf()`. The fix adds NULL checks for these keys and rejects missing values with `config_error_nonbool()`, making the bundle list invalid (consistent with how unknown modes or duplicate URIs are already handled). This allows the operation to proceed without the bundles rather than crashing.

The patch touches `bundle-uri.c` (adding four NULL checks in `bundle_list_update()`) and `t/t5750-bundle-uri-parse.sh` (adding a test that verifies the error messages for valueless keys). The test covers both top-level keys (`mode`, `heuristic`) and per-bundle keys (`uri`, `creationtoken`). This is a server-triggered crash: a malicious or misconfigured server could advertise a bundle URI containing such a list, causing clients to segfault.

The fix aligns with the series' overarching goal of systematically eliminating crashes from unvalued config keys. It follows the established pattern of using `config_error_nonbool()` for rejection, except where graceful handling (like default values) is more appropriate. The commit message clearly explains the attack vector (server-advertised bundle lists) and the chosen mitigation (treating valueless keys as invalid). No controversial design choices are evident; the approach is consistent with prior patches in the series. The test coverage is thorough, exercising all four affected keys with clear error-message expectations.
