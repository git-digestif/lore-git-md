This is the tenth patch in Thomas Bachem’s 15-patch bugfix series addressing Git segfaults when config keys are given without values. It fixes a crash in the `safe.bareRepository` config callback (`allowed_bare_repo_cb()` in `setup.c`), which previously passed a NULL value to `strcmp()` when the key was unvalued (e.g., `git -c safe.bareRepository`). The fix adds a NULL check and rejects the missing value with `config_error_nonbool()`, aligning with the series’ established pattern. The patch also adds a test in `t/t0035-safe-bare-repository.sh` to verify the error message.

The change is minimal and targeted, touching only `setup.c` and its corresponding test file. The crash site is high-impact: any bare repository operation (e.g., `git -C repo.git log`) would trigger it. The fix is uncontroversial and consistent with the series’ goal of systematically hardening config callbacks against unvalued keys. No new edge cases or design questions are introduced; this is a straightforward application of the series’ error-handling template. The patch merges cleanly and does not conflict with other topics.
