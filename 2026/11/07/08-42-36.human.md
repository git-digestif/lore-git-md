This is the fourth patch in Thomas Bachem’s 15-patch series fixing Git segfaults when config settings are given without values. It targets the `fetch.bundleCreationToken` config key in the bundle-URI subsystem, where a missing value (e.g., `git -c fetch.bundleCreationToken`) previously caused a crash when the bundle list used the creationToken heuristic. The fix treats a NULL value the same as a non-parsable token—defaulting to 0—which aligns with the existing behavior and prevents the segfault without changing the user-facing outcome.

The patch is minimal and focused: it adds a single NULL check in `fetch_bundles_by_token()` before calling `sscanf()`, and includes a thorough test in `t/t5558-clone-bundle-uri.sh` that verifies the fix works for both `git fetch` and `git clone --bundle-uri`. The test sets up a bundle list with the creationToken heuristic, clones a repository with an unvalued `fetch.bundleCreationToken`, and confirms the token is correctly stored as 1 after the fetch.

This is a clear, uncontroversial bugfix that fits neatly into the series’ overall pattern of hardening config parsing. The commit message is concise and explains both the problem and the solution well. No design questions or edge cases are left open; the patch is ready for review. If the rest of the series holds up similarly, this looks like a straightforward win for stability.
