This is a bugfix patch that is now ready for integration. It fixes an infinite loop in Git’s sideband protocol configuration parser, which was introduced in March 2026 and breaks core commands like `git fetch`, `git push`, `git clone`, and `git ls-remote` for users with malformed `sideband.allowControlCharacters` settings.

The issue occurs when the parser encounters an unrecognized keyword (e.g., a typo like "colour", a space-separated list like "color, cursor", or a keyword only supported in newer Git versions). Instead of skipping the problematic entry, the parser would repeatedly warn about it, causing an infinite loop. The fix ensures the parser advances to the next comma-separated entry after issuing a warning, and the warning message now shows only the unrecognized keyword rather than the entire remaining string.

Junio C Hamano, the maintainer, reviewed the patch and declared it ready for `next`. The only prior discussion—a style nit about the use of the `!!` operator—was resolved in favor of the author’s approach, with Junio calling it "compelling" and easier to read. A follow-up patch to update the `CodingGuidelines` regarding `!!` is planned but does not affect this bugfix.

The patch includes a well-designed test that verifies the parser skips unrecognized keywords (e.g., "bogus") while still processing valid ones that follow. The change is minimal, touching only `sideband.c` and its test file, and addresses a real usability issue without introducing new complexity. This looks like a clean, uncontroversial fix that should be merged soon.
