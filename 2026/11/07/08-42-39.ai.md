This is the seventh patch in Thomas Bachem’s 15-patch bugfix series that systematically eliminates Git segfaults triggered by unvalued config keys. It targets the `blame` subsystem, where `color.blame.repeatedLines` and `color.blame.highlightRecent` settings without values currently cause `git blame` to crash by passing NULL to `strlen()` or `parse_color_fields()`. The fix adds NULL checks in `git_blame_config()` and rejects missing values with `config_error_nonbool()`, aligning with the existing error handling for `blame.date` and `blame.coloring`. The patch also adds a dedicated test (`t/t8012-blame-colors.sh`) that verifies both settings reject unvalued keys with an appropriate error message.

The change is narrow and uncontroversial: it follows the series’ established pattern of rejecting unvalued config keys with `config_error_nonbool()` and includes test coverage for the specific crash site. The fix is consistent with the project’s precedent (ba176db511, 2023-12-07) and does not introduce new behavior beyond preventing the segfault. No merge conflicts or design questions are raised by this patch; it is a straightforward application of the series’ audit methodology to the `blame` command. The patch is based on `master` and touches only `builtin/blame.c` and its corresponding test file.
