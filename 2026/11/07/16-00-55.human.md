This is the second patch in the v8 series adding path-related keys to `git repo info`. It fixes a **critical correctness bug** in `get_superproject_working_tree()` that could cause the function to return the wrong superproject (or none at all) when `--git-dir` points to a repository different from the current working directory.

The bug occurs because the function previously used `xgetcwd()` to determine the repository context, which fails when inspecting a repository via `--git-dir` (e.g., `git --git-dir=/path/to/repo.git rev-parse --show-superproject-working-tree`). The fix updates the function to accept a `struct repository *` parameter and use `repo_get_work_tree(repo)` instead of `xgetcwd()`, ensuring the superproject is determined from the repository being inspected rather than the current working directory. The function signature is updated in both `submodule.h` and `builtin/rev-parse.c`, and the implementation is refactored to use the repository’s working tree path consistently.

The patch also adds a test in `t/t1500-rev-parse.sh` to verify the fix works with `--git-dir`, covering the edge case where the current working directory and the repository being inspected differ. This test was moved from `t/t7400-submodule-basic.sh` in v8 to avoid bisectability issues, as the original test exercised `path.superproject-root.absolute`, a key introduced in a later patch.

This is a **well-motivated, narrowly scoped bugfix** that addresses a high-weight correctness issue identified by Junio C Hamano in earlier versions. The refactoring is clean, the test coverage is appropriate, and the patch is uncontroversial. It’s a critical prerequisite for the later patches in the series, particularly those introducing `path.superproject-root.absolute` and `path.superproject-root.relative`. The only remaining question is whether other callers of `get_superproject_working_tree()` (e.g., in scripts or other built-ins) need similar updates, but that’s a low-priority concern given the current focus on final review.
