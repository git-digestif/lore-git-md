This is the second patch in an RFC series adding `--verbose` support to `git history reword`. It implements the core feature: when `--verbose` is passed, the editor opened during `git history reword` will show the diff of the commit being reworded below the commit message template, matching the behavior of `git commit --amend --verbose`. The diff is displayed without `#` line prefixes and is not included in the final commit message.

The patch touches three files: `builtin/history.c` (adding the diff-generation logic and command-line option), `Documentation/git-history.adoc` (documenting the new `--verbose` flag), and `t/t3451-history-reword.sh` (adding 97 lines of test coverage). The implementation introduces a new `print_verbose_diff()` helper that uses Git’s diff machinery to generate a patch-formatted diff between the old and new trees, and integrates it into the existing `fill_commit_message()` flow. The diff is triggered by a new `COMMIT_TREE_VERBOSE` flag passed through the commit-tree machinery.

The tests cover the basic happy path (diff is shown with `--verbose`, omitted without it), edge cases (bare repositories, merge commits), and config interaction (explicitly confirming that `commit.verbose` config is *not* honored, as stated in the cover letter). The merge-commit test verifies that the diff is generated against the first parent, which is the expected behavior.

This is a user-facing feature addition to the `git history` subsystem, which is still relatively new and evolving. The implementation is clean and follows established Git conventions (e.g., `git commit --verbose`). The omission of `commit.verbose` config support is intentional and documented, though it may draw discussion. The patch is well-tested and appears ready for review beyond the RFC stage.
