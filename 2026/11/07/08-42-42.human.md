This is the tenth patch in Thomas Bachem’s 15-patch series fixing Git segfaults when config keys are given without values. It plugs a crash in the `safe.bareRepository` setting: if you run any Git command inside a bare repository with `safe.bareRepository` set but no value (e.g., `git -C repo.git -c safe.bareRepository log`), the callback `allowed_bare_repo_cb()` passes NULL to `strcmp()`, triggering a segfault. The fix is a simple NULL check that rejects the missing value with `config_error_nonbool()`, matching the series’ established pattern. The patch also adds a test in `t/t0035-safe-bare-repository.sh` to verify the error message.

The change is small, targeted, and uncontroversial. It follows the same error-handling approach used in the rest of the series and aligns with the precedent set by ba176db511. The test coverage is minimal but sufficient for the narrow scope. This patch is unlikely to draw debate; it’s a straightforward bugfix that fits neatly into the larger effort.
