This is the second patch in Thomas Bachem’s 15-patch series fixing Git segfaults when config settings are given without values. It targets the `core.alternateRefsCommand` and `core.alternateRefsPrefixes` settings in the object database (ODB) subsystem, which currently crash `git fetch`, `git receive-pack`, and `git rev-list --alternate-refs` when left unvalued in repositories using alternates.

The fix replaces `repo_config_get_value()` with `repo_config_get_string_tmp()` in `odb.c`, ensuring missing values are rejected with `config_error_nonbool()` rather than being passed as `NULL` to `strvec_push()` or `strvec_split()`. The change is minimal and follows the established pattern from the first patch in the series. A new test in `t/t5618-alternate-refs.sh` verifies the error message for both settings.

This patch is straightforward and uncontroversial: it plugs a clear crash site with a well-understood mechanism. The test coverage is appropriate, and the fix aligns with the series’ goal of consistent error handling for unvalued config keys. No design questions or edge cases are introduced here—just a targeted bugfix.
