Subject: [PATCH] split-index: fix corruption with skipHash and splitIndex enabled
Series version: standalone patch (v1)
Originating author: Andy Koppe (reporter), Tanga Joris (patch author)
Thread type: bug report / bugfix

Core problem or goal
A critical bug in Git’s index subsystem causes silent corruption (null OIDs, missing entries) and crashes (`BUG: wt-status.c:585`) when both `core.splitIndex` and `index.skipHash` are enabled. The root cause is that `write_shared_index()` names the shared index file after its trailing checksum, which is written as zeros when `index.skipHash` is enabled, resulting in a filename of all zeros. The split index then records a null base OID, and `read_index_from()` treats this as "no shared index," causing the entries in the shared index to be silently discarded.

Current status
Patch v1 posted by Tanga Joris; under review. Severity remains high: index corruption and crashes block users of split-index or skipHash optimizations (e.g., large repos with `feature.manyFiles`). No maintainer response or integration branch (`pu`/`seen`/`next`/`master`) yet.

- **On-disk format**: shared index filename derived from trailing checksum (zeros when `index.skipHash` is enabled); fix ensures shared index always includes its hash.
