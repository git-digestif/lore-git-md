Thread identity: Subject "[PATCH] split-index: fix corruption with skipHash and splitIndex enabled", standalone patch v1, originating from bug report by Andy Koppe with patch authored by Tanga Joris; thread type bug report / bugfix.

Core problem or goal: A critical bug in Git's index subsystem causes silent corruption (null OIDs, missing entries) and crashes (`BUG: wt-status.c:585`) when both `core.splitIndex` and `index.skipHash` are enabled. The root cause is that `write_shared_index()` names the shared index file after its trailing checksum, which is written as zeros when `index.skipHash` is enabled, resulting in a filename of all zeros. The split index then records a null base OID, and `read_index_from()` treats this as "no shared index," causing the entries in the shared index to be silently discarded.

Functions modified are `do_write_index()` and `write_shared_index()` (now takes `skip_hash` parameter). New symbol is the `skip_hash` parameter in `do_write_index()`.
