This is the first patch in the v5 series introducing the `%gb` format placeholder for `git log -g` and `git reflog`. It refactors hard-coded reflog message strings into `#define` constants in `reflog.h`, explicitly tying the refactoring to the upcoming `%gb` feature.

The patch touches seven files (`builtin/branch.c`, `builtin/checkout.c`, `builtin/rebase.c`, `object-name.c`, `reflog.h`, `sequencer.c`, and `wt-status.c`), replacing literal strings like `"checkout: moving from "` and `"Branch: renamed "` with named constants (`REFLOG_SWITCH_PREFIX`, `REFLOG_RENAME_PREFIX`, etc.). This ensures consistency across the codebase and simplifies the implementation of the `%gb` placeholder in the next patch, which will parse these messages to determine branch context for each reflog entry.

The refactoring is mechanical and does not alter behavior. It includes constants for all reflog messages written by branch switches, renames, and rebase operations, such as `REFLOG_STEP_START`, `REFLOG_STEP_FINISH`, `REFLOG_RETURNING_TO`, and `REFLOG_CHECKOUT`. The constants are documented by their usage in the code, making the purpose of each clear.

This patch addresses Junio C Hamano’s earlier concern about maintaining synchronization between the strings used to write reflog messages and those used to parse them. By centralizing the strings in `reflog.h`, future changes (e.g., for translatability or machine-readability) will only need to be made in one place. The refactoring does not split the messages into human-readable and machine-readable parts as Junio suggested, but it lays the groundwork for such a change if the project decides to pursue it.

The patch is well-structured and thoroughly covers all relevant code paths. It is a prerequisite for the `%gb` implementation and does not introduce any new functionality on its own. The commit message clearly explains the motivation and scope, and the changes are minimal and focused. No test failures or regressions are expected.
