This is the fifth patch in the v8 series adding path-related keys to `git repo info`. It introduces `path.index.absolute` and `path.index.relative`, exposing the repository’s current index file location in both absolute and relative formats. The implementation uses `repo_get_index_file(repo)` and the existing `format_path()` helper, respecting the `GIT_INDEX_FILE` environment override. Tests cover standard paths, overrides, and bare-repository edge cases.

The patch is uncontroversial and mechanically clean. The commit message clearly motivates the addition: scripts currently retrieve the index location via `git rev-parse --git-path index`, and this patch provides a consistent, scriptable interface through `git repo info`. Documentation is thorough, explicitly noting that the keys return the configured path even if the file does not exist or the repository is bare, aligning with `git rev-parse --git-path` precedent.

One latent issue remains: `repo_get_index_file(repo)` invokes `BUG("")` if the repository is not ready to return the index file path. The author retained this behavior rather than replacing it with direct access to `repo->index_file` and a null check, as suggested by Junio. This is a minor correctness concern but does not block merging, as the existing implementation is consistent with Git’s current behavior.

The patch is ready for merging as part of the v8 series, which is now technically complete and awaiting final review. The only remaining risk is lack of reviewer engagement, as Junio has warned the series may be dropped from `seen` unless reviewers step in soon.
