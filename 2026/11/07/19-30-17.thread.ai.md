Subject: [RFC PATCH 0/2] git history: add --verbose support for reword
Series version: v1 (RFC)
Originating author: Jelle van der Waa
Thread type: patch series (RFC)

Core problem or goal
Add diff display support to `git history reword` to show the full diff while editing the commit message, mirroring the behavior of `git commit --amend --verbose`. The series also removes a redundant `strbuf_stripspace()` call in `builtin/history.c` as preliminary cleanup. The design must now be generalizable to all `git history` subcommands (`split`, `squash`, `fixup`, etc.) to avoid inconsistent editor templates.

Current status
Under review (RFC). Two-patch series: (1) cleanup of redundant `strbuf_stripspace()` in `fill_commit_message()`, (2) implementation of diff display for `reword` with test coverage. No prior versions. No maintainer decisions yet. The discussion has expanded to include a new constraint: the diff format must be reusable across all `git history` subcommands. Six distinct positions on opt-in vs. opt-out are now established: (1) opt-in via `--verbose` (author), (2) opt-in via `--verbose` with immediate `commit.verbose` config support (Phillip Wood, previously), (3) opt-out (default behavior, no flag) (Karthik Nayak, Phillip Wood), (4) opt-in by default but with a preference for making diff display the default in the future (Phillip Wood), (5) conditionally accept default diff display only if it can be disabled via configuration (D. Ben Knoble, Patrick Steinhardt), (6) default diff display with opt-out deferred to a future patch (Karthik Nayak). Patrick Steinhardt’s latest reply reinforces the need for configurability and generalizability, aligning with D. Ben Knoble’s emphasis on user control. Karthik Nayak’s latest reply continues to argue for default diff display, citing the command’s experimental status and deferring opt-out mechanisms. The debate remains unresolved, with no clear consensus on the path forward.

- Redundancy removed: `strbuf_stripspace()` call in `fill_commit_message()` (patch 1/2)
- Config: `commit.verbose` intentionally omitted in this version; Phillip Wood argues it should be added now for consistency with `git commit --verbose` and expresses a broader preference for making `commit.verbose` the default for `git commit` itself

- New flag: `COMMIT_TREE_VERBOSE` passed through commit-tree machinery to trigger diff display

- Scripted editing: Phillip Wood raises a new concern about diff display interfering with automated edits in scripted workflows; Karthik Nayak acknowledges this but defers any opt-out mechanism to a future patch

Participant positions
- Jelle van der Waa (author): proposes the feature as opt-in via `--verbose`, omits `commit.verbose` config for now, open to adding it later. Suggests future expansion to other subcommands (`split`, `squash`, `fixup`). Implementation follows `git commit --verbose` precedent; diff logic is clean and well-tested.
- D. Ben Knoble: **substantive review** questioning the choice of `--verbose` as the flag name and advocating for user control. Argues that "verbose" in `git history` could imply a broader range of behaviors (e.g., post-execution summary of rewritten commits) and suggests alternative names like `--commit-verbose` or `--diff-in-editor` to avoid ambiguity and improve long-term clarity. Raises practical concerns about long diffs and editor startup time, pushing back against opt-out proposals. In his latest reply, he conditionally accepts default diff display only if it can be disabled via configuration, ensuring that scripted workflows are not disrupted. Does not object to the implementation but emphasizes user interface design and the need for configurability.
- Phillip Wood: **substantive review** of patch 2/2. Initially praised the feature as "a really useful improvement" but argued for immediate `commit.verbose` config support to maintain consistency with `git commit --verbose`. Suggested reusing `wt-status.c`’s diff logic to handle `status.relativePaths`, `status.renames`, and `status.renameLimit` settings, and proposed code cleanups (consolidate config callbacks, use `bool` for `verbose` flag). Critiqued test redundancy and suggested tighter assertions by comparing full editor output against expectations. Initially agreed with D. Ben Knoble that `--verbose` is ambiguous and proposed `--show-diff` as an alternative. In his latest reply, he shifts to a preference for making diff display the default behavior for `git history reword`, citing Git's experimental status as justification for potential future adjustments. He also reveals a broader bias toward making `commit.verbose` the default for `git commit` itself, framing the current discussion as part of a larger question about Git's defaults. Raises a new concern about scripted editing, where the diff could interfere with automated edits.
- Karthik Nayak: **substantive review** proposing a more radical change: make diff display the default behavior for `git history reword` and omit the option entirely. Argues that showing the diff is unambiguously useful and avoids the need for a flag whose name is already under debate. In his latest reply, he reinforces this position, citing the command’s experimental status and the principle of better defaults for users. Acknowledges Phillip Wood’s scripted-editing concern but defers any opt-out mechanism to a future patch. Does not address earlier technical feedback about config support or diff-generation edge cases, nor does he engage with D. Ben Knoble’s naming or opt-in arguments.
- Patrick Steinhardt: **substantive review** aligning with D. Ben Knoble’s conditional acceptance of default diff display—provided it can be disabled via configuration. Introduces a new requirement: the diff format must be generalizable to all `git history` subcommands (`split`, `squash`, `fixup`, etc.) to avoid inconsistent editor templates. This adds a forward-looking constraint on the design, ensuring that the mechanism is not `reword`-specific.
