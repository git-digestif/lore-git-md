Subject: [RFC PATCH 0/2] git history: add --verbose support for reword
Series version: v1 (RFC)
Originating author: Jelle van der Waa
Thread type: patch series (RFC)

Core problem or goal
Add diff display support to `git history reword` to show the full diff while editing the commit message, mirroring the behavior of `git commit --amend --verbose`. The series also removes a redundant `strbuf_stripspace()` call in `builtin/history.c` as preliminary cleanup.

Current status
Under review (RFC). Two-patch series: (1) cleanup of redundant `strbuf_stripspace()` in `fill_commit_message()`, (2) implementation of diff display for `reword` with test coverage. No prior versions. No maintainer decisions yet. The discussion remains centered on whether the diff display should be opt-in (via a flag) or opt-out (default behavior), with three distinct positions now clearly established: (1) opt-in via `--verbose` (author), (2) opt-in via `--verbose` with immediate `commit.verbose` config support (Phillip Wood), (3) opt-out (default behavior, no flag) (Karthik Nayak). The debate has expanded to include practical concerns about editor startup time and user control, but no consensus has emerged.

Key technical details
- Files touched: `builtin/history.c`, `Documentation/git-history.adoc`, `t/t3451-history-reword.sh`
- New CLI option: proposed `--verbose` for `git history reword` (alternatives proposed: `--show-diff` (Phillip Wood), `--commit-verbose` (D. Ben Knoble), `--diff-in-editor` (D. Ben Knoble)); Karthik Nayak proposes omitting the option entirely and making diff display the default
- New test file: `t/t3451-history-reword.sh` (97 lines)
- Subsystem: `git history` (new built-in command)
- Behavior: shows diff in editor during reword, matching `git commit --verbose`; diff is generated via new `print_verbose_diff()` helper using Git’s diff machinery, displayed without `#` line prefixes, and excluded from final commit message
- Redundancy removed: `strbuf_stripspace()` call in `fill_commit_message()` (patch 1/2)
- Config: `commit.verbose` intentionally omitted in this version; Phillip Wood argues it should be added now for consistency with `git commit --verbose`
- Edge cases tested: bare repositories, merge commits (diff generated against first parent)
- New flag: `COMMIT_TREE_VERBOSE` passed through commit-tree machinery to trigger diff display
- Diff generation: Phillip Wood suggests reusing more of `wt-status.c`’s existing logic (handles `status.relativePaths`, `status.renames`, `status.renameLimit`) rather than a custom helper
- Code organization: Phillip Wood proposes consolidating config callbacks across `git history` subcommands and using a `bool` for the `verbose` flag to avoid double-negation
- Future scope: `--verbose` could be extended to `split`, `squash`, `fixup` (with constraints); Karthik Nayak’s proposal would make this moot for `reword`

Participant positions
- Jelle van der Waa (author): proposes the feature as opt-in via `--verbose`, omits `commit.verbose` config for now, open to adding it later. Suggests future expansion to other subcommands (`split`, `squash`, `fixup`). Implementation follows `git commit --verbose` precedent; diff logic is clean and well-tested.
- D. Ben Knoble: **substantive review** questioning the choice of `--verbose` as the flag name and advocating for opt-in behavior. Argues that "verbose" in `git history` could imply a broader range of behaviors (e.g., post-execution summary of rewritten commits) and suggests alternative names like `--commit-verbose` or `--diff-in-editor` to avoid ambiguity and improve long-term clarity. Raises practical concerns about long diffs and editor startup time, pushing back against Karthik Nayak’s opt-out proposal. Does not object to the implementation but emphasizes user interface design and user control.
- Phillip Wood: **substantive review** of patch 2/2. Praises the feature as "a really useful improvement" but argues for immediate `commit.verbose` config support to maintain consistency with `git commit --verbose`. Suggests reusing `wt-status.c`’s diff logic to handle `status.relativePaths`, `status.renames`, and `status.renameLimit` settings, and proposes code cleanups (consolidate config callbacks, use `bool` for `verbose` flag). Critiques test redundancy and suggests tighter assertions by comparing full editor output against expectations. Agrees with D. Ben Knoble that `--verbose` is ambiguous and proposes `--show-diff` as an alternative, though without strong attachment to the name. Tone is collaborative and actionable.
- Karthik Nayak: **substantive review** proposing a more radical change: make diff display the default behavior for `git history reword` and omit the option entirely. Argues that showing the diff is unambiguously useful and avoids the need for a flag whose name is already under debate. Does not address earlier technical feedback about config support or diff-generation edge cases, nor does he engage with Phillip Wood’s or D. Ben Knoble’s concerns about consistency with `git commit --verbose` or practical concerns about long diffs and editor startup time. Position is principled but may face pushback from reviewers who value backward compatibility or alignment with existing Git conventions.
