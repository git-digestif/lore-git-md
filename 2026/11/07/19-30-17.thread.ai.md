Thread identity
Subject: [RFC PATCH 0/2] git history: add --verbose support for reword
Series version: v1 (RFC)
Originating author: Jelle van der Waa
Thread type: patch series (RFC)

Core problem or goal
Add `--verbose` support to `git history reword` to show the full diff while editing the commit message, mirroring the behavior of `git commit --amend --verbose`. The series also removes a redundant `strbuf_stripspace()` call in `builtin/history.c` as preliminary cleanup.

Current status
Under review (RFC). Two-patch series: (1) cleanup of redundant `strbuf_stripspace()` in `fill_commit_message()`, (2) implementation of `--verbose` for `reword` with test coverage. No prior versions. No maintainer decisions yet.

Key technical details
- Files touched: `builtin/history.c`, `Documentation/git-history.adoc`, `t/t3451-history-reword.sh`
- New CLI option: `--verbose` for `git history reword`
- New test file: `t/t3451-history-reword.sh` (97 lines)
- Subsystem: `git history` (new built-in command)
- Behavior: shows diff in editor during reword, matching `git commit --verbose`; diff is generated via new `print_verbose_diff()` helper using Git’s diff machinery, displayed without `#` line prefixes, and excluded from final commit message
- Redundancy removed: `strbuf_stripspace()` call in `fill_commit_message()` (patch 1/2)
- Config: `commit.verbose` intentionally omitted in this version; may be added later
- Edge cases tested: bare repositories, merge commits (diff generated against first parent)
- New flag: `COMMIT_TREE_VERBOSE` passed through commit-tree machinery to trigger diff display
- Future scope: `--verbose` could be extended to `split`, `squash`, `fixup` (with constraints)

Open questions and loose ends
- Should `commit.verbose` config support be added now or later?
- Are there additional edge cases in the diff display that need handling (e.g., binary files, submodules)?
- Is the omission of config support likely to be controversial?
- Will the author follow up with patches for other subcommands (`split`, `squash`, `fixup`)?
- Is the merge-commit diff behavior (first-parent only) the correct default?
- **New**: Is `--verbose` the most intuitive and future-proof name for this functionality, or would alternatives like `--commit-verbose` or `--diff-in-editor` better clarify the behavior and avoid overloading the term in the context of `git history`?

Participant positions
- Jelle van der Waa (author): proposes the feature, omits `commit.verbose` config for now, open to adding it later. Suggests future expansion to other subcommands (`split`, `squash`, `fixup`). Implementation follows `git commit --verbose` precedent; diff logic is clean and well-tested.
- D. Ben Knoble: **substantive review** questioning the choice of `--verbose` as the flag name. Argues that "verbose" in `git history` could imply a broader range of behaviors (e.g., post-execution summary of rewritten commits) and suggests alternative names like `--commit-verbose` or `--diff-in-editor` to avoid ambiguity and improve long-term clarity. Does not object to the implementation but raises a conceptual concern about user interface design.

Related work
