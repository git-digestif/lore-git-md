This thread addresses a serious corruption bug in Git's index subsystem: when both `core.splitIndex` and `index.skipHash` are enabled, the shared index file ends up named with an all-zeros checksum, causing the split index to record a null base OID. The result is silent data loss (null OIDs, missing entries) and crashes like `BUG: wt-status.c:585` during `git status`. Andy Koppe reported the issue with reproduction steps on Git v2.56.0, and Tanga Joris diagnosed the root cause in `write_shared_index()` and posted a standalone v1 patch that forces the shared index to always compute its trailing checksum while letting the main index keep the skipHash optimization, along with two new tests in `t/t1700-split-index.sh`.

The patch remains under review with no maintainer response yet -- it has not been queued in `pu`/`seen`, `next`, or `master`. Tanga Joris's latest email is simply a ping asking others to verify the fix resolves the reported problem. The thread is otherwise quiet: no design objections, no requests for changes, and no indication of when or whether the fix will be picked up.
