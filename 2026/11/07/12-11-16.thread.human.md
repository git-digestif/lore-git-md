This thread reports a critical bug in Git’s index subsystem that causes silent corruption and crashes when both `core.splitIndex` and `index.skipHash` are enabled. Andy Koppe discovered the issue, which manifests as null OIDs or missing entries in the shared index, leading to a BUG crash in `wt-status.c` during `git status`. The bug is reproducible in Git v2.56.0 on Linux with minimal steps: enabling both config options in a new repository and performing file operations.

The severity is high, as the corruption affects users relying on split-index or skipHash optimizations (common in large repositories with `feature.manyFiles`). The patch targets `split-index.c` and index file handling, with no prior discussion or related patches mentioned—this appears to be a newly identified issue. No reviews or maintainer responses have been posted yet, so the thread is currently focused on the bug report itself. If you use split-index or skipHash, this is a blocker until resolved.
