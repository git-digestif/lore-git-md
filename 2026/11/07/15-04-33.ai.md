This is a documentation patch for the partial-clone subsystem. It clarifies the fetch ordering behavior for promisor remotes in `Documentation/technical/partial-clone.adoc`.

The patch updates the existing paragraph about promisor remote fetching to specify two key behaviors: (1) remotes explicitly accepted from a server are tried before other promisor remotes, and (2) Git falls back to the next remote in the list if a fetch fails. The change is minimal—three lines added, one line modified—and directly addresses a previously ambiguous aspect of the partial clone design.

The commit message is concise and accurately describes the change. No test or code changes are involved, as this is purely documentation. The patch appears well-motivated: the current text ("tried one after the other") does not distinguish between accepted and other promisor remotes, nor does it explain what happens on fetch failure. These details are likely to matter to users debugging partial clone setups or designing promisor remote configurations.
