This is the second patch in a three-part test infrastructure series that introduces `test-tool genbytes` to eliminate a performance bottleneck on macOS. The patch implements the new command and converts all existing `test-tool genzeros | tr '\000' <char>` invocations to use `genbytes` directly.

The core change is in `t/helper/test-genbytes.c`, where the renamed file now exposes a `generate_bytes()` helper that writes a specified byte (not just NUL) to stdout. The existing `genzeros` command becomes a thin wrapper around this helper. The patch updates the test-tool plumbing (`test-tool.c`, `test-tool.h`) and modifies six test scripts to use `genbytes` instead of piping `genzeros` through `tr(1)`. The implementation preserves the original 256 KB buffer size and silent handling of invalid counts.

The performance impact is dramatic on macOS: the `EXPENSIVE` tests in `t4205-log-pretty-formats.sh` (which generate 2 GB of data) now run 70-78% faster in CI, dropping from ~800-900 seconds to ~200 seconds. Linux jobs see only minor improvements, as GNU `tr(1)` was already efficient. The commit message includes a clear before/after benchmark table.

This patch is well-motivated and addresses a real, measurable problem. The implementation is straightforward and maintains backward compatibility by keeping `genzeros` as a wrapper. The only open question is whether the third patch (which proposes folding `genzeros` into `genbytes` entirely) will be accepted, but that doesn’t affect the value of this change. The patch looks ready for serious review.
