This is the first patch in Harald Nordgren’s v5 series introducing the `%gb` format placeholder for `git log -g` and `git reflog`. The patch refactors hard-coded reflog message strings into `#define` constants in `reflog.h`, explicitly tying the refactoring to the upcoming `%gb` feature.

The changes are mechanical: strings like `"checkout: moving from "` (used by `git checkout`), `"Branch: renamed "` (used by `git branch -m`), and rebase step markers (`"start"`, `"finish"`, `"abort"`, `"returning to "`, `"checkout "`, `"fast-forward"`) are replaced with named constants (`REFLOG_SWITCH_PREFIX`, `REFLOG_RENAME_PREFIX`, `REFLOG_STEP_START`, etc.). The patch touches seven files—`builtin/branch.c`, `builtin/checkout.c`, `builtin/rebase.c`, `object-name.c`, `reflog.h`, `sequencer.c`, and `wt-status.c`—and makes no behavior changes.

This refactoring directly addresses Junio C Hamano’s earlier concern about keeping reflog message strings in sync across the codebase. By centralizing the strings in `reflog.h`, the patch ensures that the `%gb` implementation (in patch 2/2) can reliably parse reflog messages without introducing yet another copy of the same strings. The commit message is clear and ties the refactoring explicitly to the `%gb` feature, avoiding the ambiguity that Junio flagged in v2.

The patch is well-structured and ready for review. It does not engage with the broader architectural debate about reflog message design (e.g., translatability) but provides a solid foundation for the `%gb` feature. No regressions or correctness issues are introduced. The next patch in the series will implement the `%gb` placeholder itself.
