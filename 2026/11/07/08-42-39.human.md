This is the seventh patch in Thomas Bachem’s 15-patch series fixing Git segfaults when config settings are given without values. It targets `git blame` and specifically the `color.blame.repeatedLines` and `color.blame.highlightRecent` settings, which currently crash when passed a NULL value. The fix is straightforward: add NULL checks in `git_blame_config()` and reject missing values with `config_error_nonbool()`, following the same pattern already used for `blame.date` and `blame.coloring` in the same function.

The patch touches `builtin/blame.c` and adds a test in `t/t8012-blame-colors.sh` that verifies both settings now properly error out when given without values. The fix is uncontroversial and aligns with the series’ overall approach of systematically hardening config callbacks against NULL values. No new symbols or behavior changes are introduced beyond the crash prevention. The test coverage is minimal but sufficient for the narrow scope of the patch. This is a clean, well-scoped bugfix that fits neatly into the larger series.
