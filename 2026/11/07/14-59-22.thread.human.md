This thread is about a patch series that introduces `test-tool genbytes` to replace slow `tr(1)` invocations in Git’s test suite, particularly on macOS where they create a significant performance bottleneck. The series, authored by Kristofer Karlsson, aims to speed up `EXPENSIVE` tests like `t4205-log-pretty-formats.sh` by replacing `tr` with a new command that writes arbitrary bytes directly.

The current status is that the first version of the series is under review, with a second version planned. Junio Hamano has already weighed in with design feedback, proposing a change to the interface—using two-digit lowercase hexadecimal values (e.g., `00` for NUL) instead of literal characters or the string "NUL"—which the author has accepted. The workflow for presenting the changes (whether to combine the file rename and functional changes into a single patch) is still under discussion. Performance improvements are substantial on macOS (70–79% faster) and modest on Linux (2–7%).

The main open questions are whether to keep `genzeros` as a thin wrapper or fold it into `genbytes`, and how to structure the initial patch submission. So far, only Junio has provided substantive feedback, with Johannes Sixt suggesting `printf` as an alternative, but the author has rejected that approach due to its limitations in generating arbitrary bytes and inconsistent behavior across platforms. No other reviewers have weighed in yet, so the series is still awaiting broader input.
