This thread is about a test infrastructure improvement to address a performance bottleneck in Git's test suite on macOS. Kristofer Karlsson proposed a new `test-tool` command, `genbytes`, to replace slow `tr(1)` invocations when generating large amounts of data (up to 2 GB) in tests like `t4205-log-pretty-formats.sh`. The series is now in its third version and ready for submission, with all design and implementation details resolved.

The core issue was that macOS's `tr` and `printf` implementations are significantly slower than their Linux counterparts, causing some tests to run up to 79% slower on macOS. The solution settled on is a two-command design: `test-tool genzeros [<count>]` for NUL bytes and `test-tool genbytes <char> [<count>]` for arbitrary bytes. This approach avoids the unreliability and performance pitfalls of shell-based alternatives like `printf`, which can truncate output or consume excessive memory when handling large padding values. The series updates 16 test scripts and removes the now-obsolete `test-tool genzeros`.

Key participants include Junio C Hamano, who provided early feedback and resolved the last open implementation detail (buffer allocation), and Johannes Sixt and Patrick Steinhardt, who reviewed the design and implementation. Collin Funk, a coreutils contributor, recently chimed in to explain why `printf` behaves inconsistently across platforms, reinforcing the decision to avoid shell-based workarounds. The series is now technically complete, with no remaining open questions or blockers.
