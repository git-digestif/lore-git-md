This thread is about speeding up Git’s test suite on macOS by replacing slow `tr(1)` invocations that generate large test files. Kristofer Karlsson originally proposed a new `test-tool genbytes` command (v2 used a two-digit hex interface, v3 is now discussing a literal-character interface) to eliminate a 70–79 % slowdown in macOS CI jobs. After review feedback, he’s now also offering a simpler alternative: a shell helper that uses chunked `printf` calls to write 1 MiB blocks at a time. This achieves the same speedup without adding a new test-tool command, but consumes more memory (2.1 GB RSS) and still relies on `printf`, which can’t generate NUL bytes and silently fails on macOS for very large field widths. The thread is now deciding between the chunked-`printf` helper and the `test-tool genbytes` command; the interface design for `genbytes` (literal character vs. hex) is still under discussion, but no new objections or workflow changes have been raised.
