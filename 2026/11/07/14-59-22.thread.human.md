This thread is about speeding up Git’s test suite on macOS by replacing slow `tr(1)` invocations with a new `test-tool genbytes` command. Kristofer Karlsson sent a v2 series that introduced a two-digit hexadecimal interface (`00` for NUL, `20` for space) and converted all callers, but Patrick Steinhardt and Junio C Hamano raised concerns about readability and stack allocation.

In the latest email, Kristofer proposes a simpler path: keep the existing `test-tool genzeros` for NUL-byte generation and add a new `test-tool genbytes <char> [<count>]` that takes a literal character (e.g., `genbytes 'a'`). This preserves backward compatibility for the 14 `genzeros` callers while offering a more readable interface for future use. The change would revert the v2 hexadecimal design in favor of the v1 literal-character approach, but without removing `genzeros`. No implementation is attached yet; this is a design discussion seeking Junio’s approval before v3 is sent. The buffer allocation question (stack vs. static) remains open but is separate from the interface debate.
