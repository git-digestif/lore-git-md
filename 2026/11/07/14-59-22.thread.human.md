The `test-tool genbytes` patch series is addressing a performance bottleneck in Git’s test suite on macOS, where `tr(1)` invocations in `EXPENSIVE` tests like `t4205-log-pretty-formats.sh` run significantly slower than on Linux. The solution—a new `test-tool genbytes` command—has now settled on its design and workflow after feedback from Junio C Hamano and Johannes Sixt. The series is currently at v1, with v2 planned to incorporate the agreed-upon changes.

The core of the series replaces slow `tr(1)` calls with a direct byte-generation tool, `genbytes`, which will accept two-digit lowercase hexadecimal values (e.g., `00` for NUL, `20` for space) instead of literal characters or the string "NUL". This change will update 26 test scripts, and the author has confirmed he’ll combine the file rename (`test-genzeros.c` → `test-genbytes.c`) and functional changes into a single commit for v2, as Junio requested. The optional third patch, which consolidates `genzeros` into `genbytes`, will remain separate for now. Performance gains are substantial on macOS (70–79% improvement) and modest on Linux (2–7%).

The debate over alternatives—like using `printf`—is now closed. Johannes Sixt initially proposed `printf` as a simpler fix, but conceded it’s unreliable on macOS (truncating large padding values and unable to generate NUL bytes). Junio’s feedback has been fully addressed, and no further objections are expected. The author is preparing v2 with the hexadecimal interface and squashed workflow, leaving only the optional consolidation patch as a loose end.
