This thread is about speeding up Git’s test suite on macOS by replacing slow `tr(1)` invocations with a new `test-tool genbytes` command. Kristofer Karlsson sent a v2 series that uses a two-digit hexadecimal interface (e.g., `00` for NUL, `20` for space) and has already addressed all review feedback from v1, including Junio C Hamano’s design suggestion. The series is now under review, but the author has since proposed a v3 design that splits functionality into two commands—`genzeros` for NUL bytes and `genbytes <char>` for literal characters—arguing this is more readable and avoids churn.

Johannes Sixt (Hannes) had earlier suggested using `printf` instead of a new command, but in this latest email he concedes that `printf` is unreliable on macOS: when given an extremely large padding value, it silently truncates output to nine zeros rather than generating the expected 2 GB of data. He shares a workaround that splits the padding into smaller chunks, but the thread remains settled on `test-tool genbytes` with the hexadecimal interface. The only unresolved questions are whether to adopt the v3 literal-character design (which would preserve `genzeros` and leave its callers untouched) and minor implementation details like buffer allocation. Junio’s approval is still needed for the new direction, but no other participants have weighed in on it yet.
