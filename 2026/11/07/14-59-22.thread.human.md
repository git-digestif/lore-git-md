This thread is about a test infrastructure improvement to address a performance bottleneck in Git’s test suite on macOS. The series, now at version 3 and ready for submission, introduces `test-tool genbytes` to replace slow `tr(1)` invocations when generating large amounts of test data. Kristofer Karlsson, the author, has settled on a two-command design: `test-tool genzeros [<count>]` for NUL bytes and `test-tool genbytes <char> [<count>]` for arbitrary bytes, after ruling out alternatives like `printf`-based approaches due to reliability and performance issues on macOS.

The series has addressed all prior feedback, including interface design and buffer allocation details, with key input from Junio C Hamano, Johannes Sixt, and Patrick Steinhardt. The latest update confirms why shell-based workarounds remain impractical—macOS’s `tr` lacks a fast path for single-byte operations, even in `C` locale, and tools like `yes` require additional filtering. The performance gains are substantial: macOS CI jobs now run 70–79% faster, while Linux jobs see modest improvements. No open questions remain, and the series is poised for submission.
