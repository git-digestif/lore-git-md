This thread is about speeding up Git’s test suite on macOS by replacing slow `tr(1)` invocations that generate large test files. Kristofer Karlsson originally proposed a new `test-tool genbytes` command; after review feedback, he refined it to a two-digit hexadecimal interface in v2, then floated a literal-character interface and a chunked-`printf` helper as alternatives for v3. Johannes Sixt has now weighed in, dismissing the chunked-`printf` idea as impractical (too many process spawns) and endorsing the two-command design—`test-tool genzeros` for NUL bytes and `test-tool genbytes <char>` for everything else—as the cleanest path forward. The v2 series is still under review, but the design direction for v3 is settled: two commands, no `printf` helper, and the author is expected to post v3 shortly. Junio C Hamano’s only remaining concern is a low-weight implementation detail about buffer allocation; everything else is resolved.
