This thread is about a small but impactful test-infrastructure improvement: replacing slow `tr(1)` invocations in the Git test suite with a new `test-tool genbytes` command. The series, posted by Kristofer Karlsson, aims to eliminate a performance bottleneck that makes `EXPENSIVE` tests run several times slower on macOS than on Linux.

The v1 series is complete and under review. The first patch renames `test-genzeros.c` to `test-genbytes.c` without changing functionality; the second implements the new `genbytes` command and updates 16 test scripts; the third consolidates `genzeros` into `genbytes` by allowing "NUL" as a byte specifier and updates the remaining call sites. Junio C Hamano initially raised concerns about intermediate breakage but has since confirmed that the rename doesn’t actually break anything—the dispatcher in the renamed binary still recognizes the old `genzeros` command. He continues to suggest a workflow tweak: applying the first two patches together as a single commit to avoid an unnecessary intermediate state.

The main open question is whether to adopt Junio’s proposed design change: replacing the current byte-specification interface (literal characters or "NUL") with a two-digit lowercase hexadecimal input (e.g., `00` for NUL). This would simplify the parser but require updating all call sites. The author has flagged the consolidation in the third patch as optional, inviting feedback on whether to merge the commands or keep `genzeros` as a thin wrapper. No substantive review has been posted yet, so the code’s correctness hasn’t been independently verified.
