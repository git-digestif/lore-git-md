This thread is about a performance bottleneck in Git’s test suite on macOS, where `tr(1)` invocations in `EXPENSIVE` tests (notably `t4205-log-pretty-formats.sh`) run up to 70–79% slower than on Linux. Kristofer Karlsson proposed a new `test-tool genbytes` command to replace `tr` with a direct byte-generation utility, avoiding the slowdown while maintaining backward compatibility for NUL-byte generation. The series is currently at v1, with v2 planned to address feedback.

The key debate revolves around whether to adopt the generalized `genbytes` tool or pivot to a narrower `printf`-based fix targeting only the problematic test. Johannes Sixt (Hannes) has argued for the latter, suggesting `printf` with zero-padding as a simpler alternative. However, Kristofer demonstrated that `printf` fails on macOS when given extremely large padding values, truncating output and making it unreliable across platforms. This inconsistency, along with `printf`’s inability to generate NUL bytes or handle large inputs efficiently in CI environments, solidifies the case for `genbytes` as the more robust solution.

Junio C Hamano’s feedback has shaped the series’ direction: he proposed switching the `genbytes` interface from literal characters or "NUL" to two-digit lowercase hexadecimal values (e.g., `00` for NUL, `20` for space), which Kristofer has accepted and will implement in v2. Junio also suggested workflow adjustments to avoid intermediate breakage, though the exact approach (combined patch or squashed submission) remains unresolved. The series touches 26 test scripts and introduces a 256 KB buffer in the implementation, with no on-disk format changes. Performance gains are significant on macOS (70–79% improvement) and modest on Linux (2–7%).

Open questions include whether to fold `genzeros` into `genbytes` (flagged as optional by the author) and how to structure the initial patch submission. No new integration status has been reported, and the series remains under review. The thread has so far seen no additional substantive feedback beyond the `printf` vs. `genbytes` debate.
