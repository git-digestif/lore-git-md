This thread is about a small but impactful test-suite performance improvement for macOS. Kristofer Karlsson proposed a new `test-tool genbytes` command to replace slow `tr(1)` invocations that were causing some `EXPENSIVE` tests to run up to 79% slower on macOS than on Linux. The series is now at v2, with all prior design feedback addressed—most notably adopting Junio’s suggestion for a two-digit hexadecimal interface (e.g., `00` for NUL, `20` for space) instead of literal characters.

The v2 series is functionally complete and under final review. It consists of two patches: the first implements `genbytes` and converts 14 test scripts, while the second removes the now-obsolete `genzeros` tool and updates its remaining callers. The only remaining discussion is a surface-level implementation note from Junio about stack allocation of a 256 KB buffer in the new command; he suggests making it static instead, as the function is only called once per process. No one has objected to the core approach, and the earlier debate over alternatives (`printf` vs. `genbytes`) is now settled—Johannes Sixt conceded that `printf` is unreliable on macOS for large padding values and cannot generate NUL bytes. The series is ready to merge once the buffer allocation detail is resolved.
