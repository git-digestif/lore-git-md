This thread is about a performance improvement to Git’s test suite. Kristofer Karlsson has sent the third version of a patch series introducing `test-tool genbytes`, a new helper command designed to replace slow `tr(1)` invocations in macOS tests. The issue is that generating large amounts of data—such as the 2 GB needed in some `EXPENSIVE` tests—takes minutes on macOS due to inefficiencies in its `tr` implementation, while the same tests run quickly on Linux. The new `genbytes` command writes arbitrary bytes directly, bypassing `tr` entirely, and delivers a 70–79% speedup on macOS CI jobs with no behavioral changes.

The series is now ready for submission. It consists of two patches: the first implements `genbytes` and updates 14 test scripts to use it, and the second removes the now-obsolete `test-tool genzeros` and converts its remaining callers to `genbytes 00`. The interface is simple: `test-tool genzeros [<count>]` for NUL bytes and `test-tool genbytes <char> [<count>]` for any other byte. All design questions—including the choice between a single command with escape sequences or two separate commands, and whether to use a static or stack-allocated buffer—have been resolved through feedback from Junio C Hamano, Johannes Sixt, and Patrick Steinhardt. The series has no remaining open questions and is expected to be uncontroversial.

Key participants have all signed off on the approach. Junio initially raised concerns about intermediate breakage and interface design but later retracted them after the author demonstrated backward compatibility and settled on the two-command literal-character design. Johannes Sixt, who had proposed a `printf`-based alternative, conceded that it was unreliable on macOS and endorsed the current design. Patrick Steinhardt suggested idiomatic improvements like using `git_parse_signed()` for input validation, which the author adopted. The patch is well-tested, touches only test infrastructure, and addresses a real pain point without affecting Git’s core functionality.
