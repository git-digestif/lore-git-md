This thread is about a small but impactful test-infrastructure improvement: replacing slow `tr(1)` invocations in Git’s test suite with a new `test-tool genbytes` helper. The series, now at v3, originated from Kristofer Karlsson and targets a measurable performance bottleneck on macOS, where `EXPENSIVE` tests in `t4205-log-pretty-formats.sh` run up to 79% slower due to inefficient `tr` behavior when generating large byte streams.

The solution is a two-command design: `test-tool genzeros [<count>]` for NUL bytes and `test-tool genbytes <char> [<count>]` for arbitrary bytes. This approach was chosen after extensive discussion ruled out alternatives like `printf`-based helpers (unreliable for NUL bytes and large fields) and shell workarounds (lacking control over newlines). The implementation uses a static 256 KB buffer and `git_parse_signed()` for input validation, with no on-disk format changes. Sixteen test scripts have been updated to use the new helper, and the obsolete `test-tool genzeros` has been removed.

Key participants—Junio C Hamano, Johannes Sixt, and Patrick Steinhardt—have reviewed the series across three iterations, addressing interface design, buffer allocation, and parsing details. Junio’s latest email signals the series is ready for integration into `next`, with no remaining open questions. The patch is uncontroversial and focuses solely on test infrastructure, making it a straightforward win for CI performance.
