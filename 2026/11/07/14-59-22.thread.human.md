This thread introduces a small but effective performance improvement for Git's test suite, specifically targeting a slowdown on macOS. Kristofer Karlsson identified that `tr(1)` invocations in tests generating large amounts of data—particularly in `t4205-log-pretty-formats.sh`—were causing `EXPENSIVE` tests to run up to 79% slower on macOS compared to Linux. The solution is a new `test-tool genbytes` command that writes arbitrary bytes directly, bypassing `tr`.

The series is now complete with three patches. The first was a no-op rename of `test-genzeros.c` to `test-genbytes.c`. The second implemented `genbytes` and updated 16 test scripts to use it instead of `genzeros | tr`. This third patch proposes folding the existing `genzeros` command into `genbytes` by allowing "NUL" as a byte specifier, which would replace the remaining 10 `genzeros` call sites and remove the redundant command. The author has made it clear this last step is optional—if reviewers prefer, `genzeros` can remain as a thin wrapper around `genbytes`.

Performance gains are significant on macOS (70–79% improvement in CI jobs) while Linux sees modest but measurable speedups (2–7%). The changes are confined to test infrastructure, with no impact on core Git functionality or on-disk formats. No substantive reviews have arrived yet, so the main open question is whether the project will accept the optional third patch or keep `genzeros` as a wrapper. The series is ready for review and addresses a real, measurable bottleneck.
