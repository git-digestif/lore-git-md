This thread is about a small but impactful test-suite performance improvement for Git on macOS. Kristofer Karlsson has sent a two-patch series (now at v2) that replaces slow `tr(1)` invocations with a new `test-tool genbytes` command, eliminating a bottleneck that made certain `EXPENSIVE` tests run up to 79% slower on macOS than on Linux.

The core idea is simple: instead of relying on external tools like `tr` or `printf`—which behave inconsistently across platforms, especially when generating NUL bytes or large files—Git now has its own built-in command to write arbitrary bytes directly. The interface is clean: `test-tool genbytes <byte> [<count>]`, where `<byte>` is a two-digit lowercase hexadecimal value (e.g., `00` for NUL, `20` for space). The first patch implements this and converts 14 test scripts; the second (just summarized) removes the now-obsolete `test-tool genzeros` and updates the remaining callers.

All prior feedback has been addressed. Junio Hamano initially suggested tweaking the patch workflow and proposed the hexadecimal interface, both of which are now implemented. Johannes Sixt had argued for using `printf` instead, but conceded after seeing that it can’t reliably generate NUL bytes or handle extremely large padding values on macOS. The series is now functionally complete, with no open questions, and is awaiting final review. If accepted, it should land in Junio’s `next` branch soon.
