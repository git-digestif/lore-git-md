This thread is about a small but impactful test-infrastructure improvement: replacing slow `tr(1)` invocations in the Git test suite with a new `test-tool genbytes` command. The series, now at **v3**, is ready for integration into Junio’s `next` branch.

The bottleneck was most acute on macOS, where generating 2 GB of NUL bytes in `EXPENSIVE` tests like `t4205-log-pretty-formats.sh` took nearly two minutes—far slower than on Linux. The solution is a pair of simple commands: `test-tool genzeros [<count>]` for NUL bytes and `test-tool genbytes <char> [<count>]` for any other byte. The design was shaped by feedback from Junio C Hamano, Patrick Steinhardt, and Johannes Sixt, who helped rule out alternatives like `printf`-based helpers (unreliable across platforms) and shell workarounds (impractical for large data). The implementation is straightforward, using a static 256 KB buffer and idiomatic Git parsing, and has been tested across 16 scripts.

All review feedback has been addressed, and Patrick Steinhardt’s latest review confirms the series is ready. The macOS CI jobs now run 70–79% faster, while Linux jobs see modest improvements. No design questions remain, and Junio has already signaled the series is fit for `next`.
