This thread is about a small but practical performance improvement for Git’s test suite on macOS. Kristofer Karlsson has sent a three-patch series that introduces a new `test-tool genbytes` command to replace slow `tr(1)` invocations in the `EXPENSIVE` tests. The bottleneck is most noticeable in `t4205-log-pretty-formats.sh`, where generating 2 GB of data through `tr` is significantly slower on macOS than on Linux.

The first patch is purely mechanical, renaming `test-genzeros.c` to `test-genbytes.c` as a preparatory step. The second patch implements the new `genbytes` command, updates the build system (both Makefile and Meson), and wires it into the test-tool plumbing. The third patch is optional: it folds the existing `genzeros` functionality into `genbytes` by allowing the byte to be specified as "NUL", which would replace the 10 current call sites of `genzeros` with a single command. The author has kept this separate to make it easy to drop if the project prefers to keep `genzeros` as a thin wrapper.

So far, there’s been no review feedback, so the series is still under initial consideration. The main open question is whether the project wants to adopt the optional third patch or keep `genzeros` as a separate command. The series touches 16 files, mostly test scripts that previously used `genzeros | tr`, and the implementation preserves the existing behavior (including silent handling of invalid counts) while using a 256 KB local buffer.
