This is a review reply in the ongoing test infrastructure thread about introducing `test-tool genbytes` to replace slow `tr(1)` invocations on macOS. Junio C Hamano responds to the author’s open question about whether to fold the existing `genzeros` command into `genbytes` (patch 3) and to two other implementation details.

Junio suggests a different design for the byte specification: instead of accepting a single character or the string "NUL", `genbytes` should take the byte value as two hexadecimal digits (e.g., `00` for NUL, `20` for space). This would eliminate the need for special-casing NUL and simplify the interface, trading ergonomics for consistency and simplicity in a test helper. He also confirms that the buffer size and silent handling of invalid counts are not worth changing.

The review is substantive but narrowly focused on interface design; it does not engage with the broader performance motivation or test coverage. No tested feedback is provided. The author’s open question about patch 3 remains unresolved, now with an alternative proposal for how the command should work.
