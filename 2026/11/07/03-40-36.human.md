This is the final patch in a well-crafted five-part series improving Git’s HTTP transport resilience. It sets the default `http.retryAfter` to 10 seconds, formalizing the compromise reached in earlier discussion between server protection (brian m. carlson’s concern) and interactive usability (Ravi Mistry’s concern).

The patch updates documentation to reflect the new default, removes a misleading "configured" qualifier from an error message (since the default can now exceed `http.maxRetryTime` even when unset), and adjusts a test to account for libcurl’s behavior with past Retry-After HTTP-date values—these now fall back to the 10-second default instead of retrying immediately. The test suite gains a new check verifying the default behavior when `http.maxRetryTime` is set below 10 seconds.

This is a small but essential piece of the series, ensuring the exponential backoff (10s, 20s, 40s, ...) works as intended out of the box. The change is well-motivated, thoroughly tested, and resolves the last open design question from the review process. The series as a whole looks ready for integration.
