Thread identity: Bugfix series (15 patches) fixing Git segfaults when config settings are given without values (e.g., `git -c foo.bar` or bare `bar` under `[foo]`). Originating author: Thomas Bachem (via GitGitGadget). Thread type: patch series (bugfix). Current version: v3 (submitted).

Core problem or goal: Systematically eliminate crashes triggered by unvalued config keys across 21 distinct sites in Git commands (`git rebase -i`, `git fetch`, `git add -p`, `git add -i`, `git grep`, `git blame`, `git clone --bundle-uri`, `git merge`, `git fetch` with remote groups, `git -C repo.git log` in bare repositories, `git repack -adb` for pseudo-merge bitmaps, `scalar reconfigure --all`, `includeIf` matching for `remote.*.url`, server-advertised bundle lists, `git config list --type=color/expiry-date`, and interactive color slots like `color.interactive.prompt`/`color.diff.frag`). The series audits config callbacks and `repo_config_get_value()` callers, rejecting missing values with `config_error_nonbool()` (per ba176db511, 2023-12-07) or gracefully handling them (e.g., default values, omission, silent skipping, or skipping during `includeIf` matching) except for three cases: `fetch.bundleCreationToken` (defaults to 0), remote URLs (skip `includeIf` matching), and `git config list` (omits key). One patch (15/15) fixes a regression introduced in Git 2.54.0 (commits 2d4ab5a885 and 9cb4a5e1ba); the rest address latent crashes.

Current status: Under review (no merge status reported). Series is based on `master` (3c60ef1e38) and merges cleanly into `next` and `seen`, but conflicts with two topics in `seen` (`iw/connected-deepen-fetch-no-alternate-refs` and `kk/quarantine-alternate-refs`) due to overlapping test additions. Version: v3 (submitted). The v3 update **harmonizes error handling** for patches 6/15 (`remote.<name>.tagOpt`) and 7/15 (`color.blame.repeatedLines`/`color.blame.highlightRecent`) to **warn about missing values (NULL) and ignore them**, aligning with the behavior for invalid values. Patches 8/15 (`branch.<name>.mergeOptions`) and 14/15 (bundle list keys) retain `config_error_nonbool()` for missing values, justified by Git's config semantics (missing values = boolean `true`, empty values = empty strings) since 2005 (commit 17712991a5). The v3 update also incorporates Phillip Wood's test improvements for patch 1/15 (`rebase.missingCommitsCheck`), simplifying the rebase scenario to three commits and using `test_commit_message` for better diagnostics. The series is **effectively approved for merge** pending resolution of the test conflicts. No further design questions or objections remain.
