Thread identity: Bugfix series (15 patches) fixing Git segfaults when config settings are given without values (e.g., `git -c foo.bar` or bare `bar` under `[foo]`). Originating author: Thomas Bachem (via GitGitGadget). Thread type: patch series (bugfix). Current version: v2.

Core problem or goal: Systematically eliminate crashes triggered by unvalued config keys across 20 distinct sites in Git commands (`git rebase -i`, `git fetch`, `git add -p`, `git grep`, `git blame`, `git clone --bundle-uri`, `git merge`, `git fetch` with remote groups, `git -C repo.git log` in bare repositories, `git repack -adb` for pseudo-merge bitmaps, `scalar reconfigure --all`, `includeIf` matching for `remote.*.url`, server-advertised bundle lists, and `git config list --type=color/expiry-date`). The series audits config callbacks and `repo_config_get_value()` callers, rejecting missing values with `config_error_nonbool()` (per ba176db511, 2023-12-07) except for five cases: `fetch.bundleCreationToken` (defaults to 0), remote URLs (skip `includeIf` matching), `git config list` (omits key), `remote.*.url` (skipped during `includeIf` matching), and `rebase.missingCommitsCheck` (now treats missing values as invalid, defaulting to `"ignore"`). One patch (15/15) fixes a regression introduced in Git 2.54.0 (commits 2d4ab5a885 and 9cb4a5e1ba); the rest address latent crashes.
