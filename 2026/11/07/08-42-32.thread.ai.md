Thread identity: Bugfix series (15 patches) fixing Git segfaults when config settings are given without values (e.g., `git -c foo.bar` or bare `bar` under `[foo]`). Originating author: Thomas Bachem (via GitGitGadget). Thread type: patch series (bugfix). Current version: v3 (submitted).

Core problem or goal: Systematically eliminate crashes triggered by unvalued config keys across 23 distinct sites in Git commands (`git rebase -i`, `git fetch`, `git add -p`, `git add -i`, `git grep`, `git blame`, `git clone --bundle-uri`, `git merge`, `git fetch` with remote groups, `git -C repo.git log` in bare repositories, `git repack -adb` for pseudo-merge bitmaps, `scalar reconfigure --all`, `includeIf` matching for `remote.*.url`, server-advertised bundle lists, `git config list --type=color/expiry-date`, interactive color slots like `color.interactive.prompt`/`color.diff.frag`, `safe.bareRepository` in bare repositories, and `bitmapPseudoMerge.<name>.pattern` in `git repack -adb`). The series audits config callbacks and `repo_config_get_value()` callers, rejecting missing values with `config_error_nonbool()` (per ba176db511, 2023-12-07) or gracefully handling them (e.g., default values, omission, silent skipping, or skipping during `includeIf` matching) except for four cases: `fetch.bundleCreationToken` (defaults to 0), remote URLs (skip `includeIf` matching), `git config list` (omits key), and `remote.<name>.tagOpt`/`color.blame.repeatedLines` (warn and ignore). One patch (15/15) fixes a regression introduced in Git 2.54.0 (commits 2d4ab5a885 and 9cb4a5e1ba); the rest address latent crashes.
