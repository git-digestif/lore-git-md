This is a **bugfix series** (15 patches) targeting a systemic issue: Git segfaults when config settings are given without values (e.g., `git -c foo.bar` or a bare `bar` under `[foo]`). The series systematically audits config callbacks and `repo_config_get_value()` callers, identifying 17 distinct crash sites across commands like `git rebase -i`, `git fetch`, `git add -p`, `git grep`, `git blame`, and `git clone --bundle-uri`. Most fixes reject the missing value with `config_error_nonbool()`, following the precedent set by ba176db511 (2023-12-07). Three exceptions handle the absence gracefully: `fetch.bundleCreationToken` defaults to 0, remote URLs without values skip `includeIf` matching, and `git config list` omits the key entirely.

The audit methodology combined static analysis (checking every config callback) with dynamic testing (running common commands with unvalued keys from `git help --config`). The series is based on `master` and merges cleanly, though it conflicts with two topics in `seen` (`iw/connected-deepen-fetch-no-alternate-refs` and `kk/quarantine-alternate-refs`) due to overlapping test additions. Only one patch (15/15) fixes a regression introduced in Git 2.54.0; the rest address latent crashes.

Key technical details include:
- **Files touched**: 12 source files (e.g., `add-patch.c`, `bundle-uri.c`, `grep.c`) and 15 test files (e.g., `t/t5558-clone-bundle-uri.sh`, `t/t7810-grep.sh`).
- **Subsystems affected**: rebase, ODB, interactive add, bundle URIs, grep, remote handling, blame, merge, pseudo-merges, scalar, config parsing, and setup.
- **Edge case**: Patch 14/15 fixes a server-triggered crash via bundle lists advertised to clients.
- **Test coverage**: Each crash site gets a dedicated test (e.g., `t/t5618-alternate-refs.sh` for `core.alternateRefs*`).

The series is well-motivated and thorough, with clear commit messages and targeted fixes. The audit’s completeness suggests it’s likely to catch most (if not all) remaining instances of this bug class. No controversial design choices are evident; the approach aligns with existing error-handling patterns. The only unresolved case (`remote.*.followRemoteHEAD`) is intentionally left to a separate topic (`ch/remote-defer-follow-remote-head-validation`) already in `seen`.
