This is a **bugfix patch** (3/15 in the series) targeting a segfault in `git add -p` and other interactive patch modes when color slots (e.g., `color.interactive.prompt` or `color.diff.frag`) are configured without values. The crash occurs because `init_color()` passes a `NULL` value to `color_parse()`. The fix replaces `repo_config_get_value()` with `repo_config_get_string_tmp()`, which rejects missing values with `config_error_nonbool()`, matching the behavior already used for diff colors in `git diff`.

The patch is narrow and well-scoped: it touches only `add-patch.c` and adds a test in `t/t3701-add-interactive.sh` to verify the error message. The change aligns with the series' consistent pattern of rejecting unvalued config keys, and the test explicitly checks for the expected error ("missing value for .color.interactive.prompt"). This is a clear, uncontroversial fix for a latent crash, and the test coverage ensures the behavior won’t regress. No design questions or edge cases are introduced here—just a straightforward application of the series' established error-handling approach.
