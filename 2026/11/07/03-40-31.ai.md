This is the v3 cover letter for a five-patch series targeting Git’s HTTP transport layer, addressing gaps in error handling and retry logic. The series is now technically complete, incorporating all substantive feedback from Junio C Hamano and brian m. carlson, and awaits final review before integration.

The core goal remains improving resilience when Git interacts with hosting backends and reverse proxies under high concurrency. The series fixes an off-by-one retry count bug, introduces exponential backoff (10s, 20s, 40s, ...) when Retry-After headers are absent, makes retryable status codes configurable (defaulting to 429), and extends retries to HTTP POST requests—critical for fetch/clone data transfers and partial clone operations. The new patch (5/5) sets the default `http.retryAfter` to 10 seconds, resolving the earlier debate between server protection (brian m. carlson’s priority) and interactive usability (Ravi Mistry’s concern).

Key files touched include `http.c`, `remote-curl.c`, documentation (`git-config.txt`, `Documentation/config/http.adoc`), and tests (`t/t5584-http-429-retry.sh`, `t/lib-httpd/http-429.sh`). New symbols include `http.retryStatusCodes` (configurable list of 400–599 codes) and `http_retry_wait()` (shared retry timing logic). The test suite now covers exponential backoff, 5xx retries, POST retries, and gzipped POST header preservation, with 15 new tests in `t5584-http-429-retry.sh`.

The series is well-motivated, with clear real-world use cases (e.g., transient 5xx errors from load balancers, rate-limiting under high concurrency). The opt-in design for 5xx retries avoids default-behavior controversy, and the 10-second default strikes a balance between server protection and usability. The only remaining loose end is minor documentation formatting, which is cosmetic and unrelated to functionality.

Prior work (2020 and 2024 proposals) addressed subsets of these issues but did not land; this series builds on commit 640657ffd0 (2026-03-17), which introduced the original 429 retry logic. The exponential backoff behavior aligns with curl’s `--retry` semantics, though with a longer initial delay (10s vs. curl’s 1s). The series appears ready for integration, with no unresolved technical feedback.
