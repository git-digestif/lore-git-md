This is a small RFC feature patch series proposing to add `--verbose` support to `git history reword`.

The author, Jelle van der Waa, notes that the new `git history` subcommands (like `reword`) currently lack the ability to show the full diff while editing the commit message, a feature that `git commit --amend --verbose` already provides. The series adds a `--verbose` flag to `git history reword`, making it behave similarly to `git commit --amend --verbose`, but intentionally omits support for the `commit.verbose` configuration option for now. The author expresses interest in eventually supporting the config option and extending `--verbose` to other `git history` subcommands like `split`, `squash`, and `fixup`, but wants to start with `reword` as the initial step.

The series consists of two patches. The first removes a redundant `strbuf_stripspace()` call, a minor cleanup. The second implements the `--verbose` option for `reword`, including documentation updates and a new test file (`t/t3451-history-reword.sh`) with 97 lines of test coverage. The implementation looks straightforward, and the test coverage appears thorough. The RFC status suggests the author is seeking early feedback on the approach before expanding the feature further. This seems like a sensible, incremental improvement to the `git history` command.
