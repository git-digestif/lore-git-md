This is the first patch in Thomas Bachem’s 15-patch bugfix series addressing Git segfaults when config settings are given without values. It fixes a crash in `git rebase -i` when `rebase.missingCommitsCheck` is specified without a value (e.g., `git -c rebase.missingCommitsCheck` or a bare `missingCommitsCheck` under `[rebase]`). The crash occurs because `get_missing_commit_check_level()` passes a NULL value to `strcasecmp()`; the fix replaces `repo_config_get_value()` with `repo_config_get_string_tmp()`, which rejects missing values with `config_error_nonbool()`, following the precedent set by ba176db511 (2023-12-07).

The patch touches `rebase-interactive.c` (one line changed) and adds a test in `t/t3404-rebase-interactive.sh` to verify the error message. The fix is narrow and aligns with the series’ overall approach: enforce non-NULL values for non-boolean config keys. No new symbols or behavior changes are introduced beyond the error handling. The test coverage is minimal but sufficient for the specific crash site.

This patch is uncontroversial and well-motivated, addressing a clear bug with a targeted fix. It’s part of a larger audit of config callbacks, so its value is amplified by the series’ completeness. The only potential friction is the merge conflict with `seen` topics (`iw/connected-deepen-fetch-no-alternate-refs` and `kk/quarantine-alternate-refs`), but that’s a mechanical issue unrelated to the patch itself. Future discussion is likely to focus on the series as a whole rather than this individual fix.
