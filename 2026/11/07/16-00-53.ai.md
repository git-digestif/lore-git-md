This is the **eighth version (v8) of a feature patch series** adding seven new path-related keys to the `git repo info` command. The series is part of a Google Summer of Code (GSoC) project and is now **mechanically complete, design-resolved, and ready for final review**. The author, K Jayatheerth, has addressed all outstanding feedback from v7, including the controversial `path.grafts` keys, test hygiene, and edge-case handling.

The new keys expose filesystem locations of repository components in a scriptable, structured format:
- `path.toplevel.absolute` / `path.toplevel.relative`: The working tree root (empty in bare repositories).
- `path.superproject-root.absolute` / `path.superproject-root.relative`: The superproject root when inside a submodule.
- `path.hooks.absolute` / `path.hooks.relative`: The hooks directory, respecting `core.hooksPath` (now returns `/dev/null` verbatim when configured as such).
- `path.index.absolute` / `path.index.relative`: The active index file.
- `path.git-prefix`: The relative path from the working tree root to the current directory (e.g., `sub/dir/`).
- `path.cdup`: The relative path from the current directory to the working tree root (e.g., `../../`), or the absolute path when outside the working tree.

**Key changes since v7**:
1. **Dropped `path.grafts`**: The grafts keys were removed in response to Justin Tobler’s design concern about maintaining deprecated functionality. This resolves the last major open question from v7.
2. **Test hygiene improvements**: Tests for `path.superproject-root` were moved to `t/t1500-rev-parse.sh` to avoid bisectability issues, and the `/dev/null` handling for `path.hooks` now uses direct config file manipulation to avoid MSYS2 path mangling on Windows.
3. **Simplified control flow**: The getter functions for `path.superproject-root` and `path.cdup` were streamlined to eliminate redundant early returns.
4. **Edge-case handling**: `path.cdup` now returns early when invoked outside a working tree, and the `path.hooks` keys consistently return `/dev/null` verbatim for both absolute and relative paths.

**Files touched**:
- `builtin/repo.c`: Implementation of the new keys and their formatting logic.
- `Documentation/git-repo.adoc`: Documentation for the new keys.
- `t/t1900-repo-info.sh`: Tests for the new functionality.
- `t/t1500-rev-parse.sh`: Tests for the `get_superproject_working_tree()` refactoring.
- `submodule.c`/`submodule.h`: Refactored `get_superproject_working_tree()` to respect the `repo` parameter.
- `builtin/rev-parse.c`: Updated caller of `get_superproject_working_tree()`.

**Behavior**:
- Keys return filesystem paths (absolute or relative) for repository components.
- In bare repositories, `path.toplevel` returns an empty string, while other keys (e.g., `path.index`, `path.hooks`) return paths unconditionally, aligning with `git rev-parse --git-path` precedent.
- `path.hooks` now returns `/dev/null` verbatim when `core.hooksPath` is set to that value, improving usability for scripts.

**Open questions**:
- The series is now **technically complete** and has no unresolved design or mechanical issues. The only remaining risk is **lack of reviewer engagement**, as Junio C Hamano has warned the series may be dropped from `seen` unless reviewers step in soon.
- The **architectural duplication** concern (shared logic between `git repo info` and `git rev-parse`) remains unaddressed, but the author has proposed a follow-up series to refactor this into a new helper library (`repo-info.c`).
