This thread is a 15-patch bugfix series from Thomas Bachem that systematically eliminates Git segfaults triggered by unvalued config keys (e.g., `git -c foo.bar` or bare `bar` under `[foo]`). The series has been under review since its initial submission and now stands at version 1, with no merge status reported yet.

The fixes span 18 distinct crash sites across Git commands like `git rebase -i`, `git fetch`, `git add -p`, `git grep`, `git blame`, `git clone --bundle-uri`, `git merge`, and now `scalar reconfigure --all`. The approach is consistent: audit config callbacks and `repo_config_get_value()` callers to reject missing values with `config_error_nonbool()` (per project precedent from December 2023), except for three cases where graceful handling is appropriate. The series also fixes a regression introduced in Git 2.54.0 and includes dedicated tests for each crash site.

The latest patch (12/15) addresses a segfault in `scalar reconfigure --all` when `scalar.repo` is unvalued, adding a NULL check in the config callback and a new test. Like the rest of the series, this patch is uncontroversial and aligns with established error-handling patterns. The series merges cleanly on `master` but conflicts with two topics in `seen` due to overlapping test additions. No reviews have been recorded yet, and one related config key (`remote.*.followRemoteHEAD`) was intentionally deferred to a separate topic already in `seen`.
