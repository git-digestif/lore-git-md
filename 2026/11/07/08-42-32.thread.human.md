This thread is a 15-patch bugfix series by Thomas Bachem that prevents Git from segfaulting when config settings are given without values (e.g., `git -c foo.bar` or `bar` under `[foo]`). The series has been through two iterations and is now effectively approved for merge, with a planned v3 update to address minor feedback and test conflicts.

The fixes touch 20 distinct crash sites across Git commands, from `git rebase -i` to `git config list --type=color`. Most patches now consistently handle unvalued keys by either rejecting them with `config_error_nonbool()`, warning and ignoring them, or applying graceful fallbacks. Two patches (6/15 and 7/15) will be adjusted in v3 to warn about missing values and ignore them, aligning with how invalid values are handled. The series also includes a regression fix for a crash introduced in Git 2.54.0.

Key reviewers—Derrick Stolee, Phillip Wood, and Junio Hamano—have all weighed in, with no remaining design objections. The main blockers are test conflicts with two other topics in Junio’s `seen` branch, which must be resolved before the series can graduate to `next`. Ben Knoble’s recent reply merely endorses the now-settled design decision about Git’s config parser behavior and floats a future idea for stricter config validation, but adds no new requirements for this series.
