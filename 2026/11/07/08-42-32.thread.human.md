This thread is a 15-patch bugfix series from Thomas Bachem that systematically fixes Git segfaults when config settings are given without values (e.g., `git -c foo.bar` or `bar` under `[foo]`). The series targets 17 crash sites across commands like `git rebase -i`, `git fetch`, `git add -p`, `git grep`, `git blame`, and `git clone --bundle-uri`. The fixes follow a consistent pattern: rejecting missing values with `config_error_nonbool()` (per the 2023 precedent ba176db511) or gracefully handling them with defaults or skips, except for three special cases.

The series is under review and based on `master`, but conflicts with two topics in `seen` due to overlapping test additions. So far, patches 1–7 (covering rebase, interactive add, bundle URIs, grep, remote handling, and blame) have been posted, all following the same uncontroversial error-handling approach. Each patch includes dedicated tests for its crash site. The only unresolved case is `remote.*.followRemoteHEAD`, which the author deferred to a separate topic already in `seen`. No reviews have been recorded yet, but the patches align with the project’s established config-parsing conventions and include thorough test coverage. The series also fixes a regression introduced in Git 2.54.0.
