This thread is a 15-patch series from Thomas Bachem that fixes Git segfaults when config settings are given without values (e.g., `git -c foo.bar` or `bar` under `[foo]`). The series systematically addresses crashes across 23 distinct sites in Git commands, including `git rebase -i`, `git fetch`, `git add -p`, `git grep`, and others. One patch fixes a regression introduced in Git 2.54.0, while the rest address latent crashes.

The series is now in its third version (v3), which harmonizes error handling for two patches where missing values now warn and are ignored, aligning with behavior for invalid values. The rest of the series rejects missing values with `config_error_nonbool()` or handles them gracefully (e.g., default values, omission, or silent skipping). The v3 update also incorporates test improvements suggested by Phillip Wood. The series is effectively approved for merge, with no remaining design questions or objections, but it conflicts with two other topics in Junio’s `seen` branch due to overlapping test additions. These conflicts must be resolved before the series can graduate to `next`.

Key reviewers—Derrick Stolee, Phillip Wood, and Junio C Hamano—have provided substantive feedback, with Junio settling a design question by citing Git’s long-standing config semantics (missing values are treated as boolean `true`, empty values as empty strings). The series touches 30 source files and 30 test files, covering subsystems like rebase, ODB, interactive add, bundle URIs, grep, remote handling, blame, merge, and config parsing. No new symbols or API changes are introduced.

The only loose ends are the test conflicts and a deferred UX improvement for error messages in bundle list parsing. D.
