This thread is a 15-patch series from Thomas Bachem that systematically fixes Git segfaults triggered when config settings are given without values—such as `git -c foo.bar` or a bare `bar` under `[foo]`. The series covers 19 distinct crash sites across commands like `git rebase -i`, `git fetch`, `git add -p`, `git grep`, `git blame`, and others. All but the final patch address latent bugs; the last one fixes a regression introduced in Git 2.54.0 where `git config list --type=color` or `--type=expiry-date` would crash on valueless keys.

The approach is consistent: config callbacks and `repo_config_get_value()` callers now reject missing values with `config_error_nonbool()` (following the precedent set in late 2023) or handle them gracefully—defaulting, omitting, or skipping—depending on context.
