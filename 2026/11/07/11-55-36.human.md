This is the second patch in the v5 series introducing the `%gb` format placeholder for `git log -g` and `git reflog`. The patch implements the core functionality, allowing users to see which branch each reflog entry was recorded on by parsing reflog messages left by branch switches, renames, and rebases.

The implementation adds the `%gb` placeholder to `pretty.c` and documents it in `Documentation/pretty-formats.adoc`. The core logic lives in `reflog-walk.c`, where the `mark_branches()` function walks the reflog backward to determine the branch context for each entry. Key improvements in this version include correctly labeling detached HEAD entries (e.g., "detached at <commit>") and robustly handling rebase checkouts, including edge cases like `git rebase <upstream> <branch>` and custom `GIT_REFLOG_ACTION` values. The patch also introduces helper functions like `skip_rebase_checkout()` to avoid mislabeling remote branches or commit subjects starting with "checkout".

The test coverage in `t/t1414-reflog-walk.sh` is thorough, now spanning 229 lines and validating edge cases such as rebases of detached HEADs, fast-forward and aborted rebases, branch renames, and interaction with `--decorate`. The tests confirm that `%gb` correctly handles all scenarios without altering default behavior. The patch is additive and does not change existing output formats, reducing regression risk.
