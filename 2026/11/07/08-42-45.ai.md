This is the **thirteenth patch in a 15-patch bugfix series** addressing Git segfaults when config settings lack values. This patch specifically handles a crash in `includeIf` matching for `remote.*.url` patterns: when a remote URL is configured without a value (e.g., `url` under `[remote "valueless"]`), `add_remote_url()` passes `NULL` to `string_list_append()`, which then tries to `xstrdup()` it, causing a segfault. The fix skips such URLs during `includeIf` matching, as they cannot match any pattern and are already rejected by `handle_config()` in `remote.c` when Git reads remotes.

The change is minimal: a single `value` check in `add_remote_url()` (in `config.c`) ensures `NULL` values are excluded from the list of remote URLs used for `includeIf` matching. The accompanying test (`t/t1300-config.sh`) verifies that a valueless `remote.*.url` does not trigger `includeIf` rules, while valid URLs still do. This aligns with the series' broader pattern of rejecting or gracefully handling unvalued config keys, though here the handling is implicit (omission) rather than an explicit error.

The patch touches a core config subsystem (`config.c`) and adds test coverage for a previously untested edge case in `includeIf` logic. The fix is uncontroversial and consistent with the series' goal of eliminating crashes without changing behavior for valid configurations. No new symbols or APIs are introduced. The only potential interaction is with other `includeIf` patterns, but the change is narrowly scoped to `remote.*.url`.
