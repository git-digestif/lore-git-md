This is a **bugfix series** targeting a class of NULL-dereference segfaults that occur when Git config settings are given without values (e.g., `git -c foo.bar` or a bare `bar` under `[foo]`). The series consists of 15 patches, each addressing a specific crash site identified through a systematic audit of config callbacks and common Git commands.

The problem is widespread: the cover letter lists over a dozen subsystems affected, from interactive rebase and fetch to blame, grep, and bundle URIs. Most patches reject the missing value with `config_error_nonbool()`, following the precedent set by ba176db511 (2023). Three exceptions handle the NULL case gracefully: `fetch.bundleCreationToken` defaults to 0, a missing remote URL skips includeIf matching, and `git config list --type=color/expiry-date` omits the key entirely. Only one patch fixes a regression introduced in Git 2.54.0.

The series is well-motivated and thorough. The author explicitly states they checked every config callback and ran common commands with every key from `git help --config` set without a value. Test coverage is comprehensive, with new tests added for each crash site. The patches merge cleanly on `master` and only minor conflicts are noted with topics in `next` and `seen`.

This looks like a serious, well-crafted contribution that addresses a real and pervasive issue. The segfaults are easy to trigger (any user can hit them with a misconfigured setting), and the fixes are narrowly scoped to the crash sites without changing behavior for valid configurations. For anyone running recent Git versions, this series is likely worth attention.
