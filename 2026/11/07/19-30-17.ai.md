This is an RFC patch series proposing a feature addition to `git history`. The author, Jelle van der Waa, introduces `--verbose` support for the `git history reword` subcommand, aiming to make it behave similarly to `git commit --amend --verbose` by showing the full diff when editing the commit message. The series consists of two patches: the first removes a redundant `strbuf_stripspace()` call, and the second implements the `--verbose` option for `reword`.

The motivation is clear: users of `git history reword` currently lack the ability to see the diff while editing the commit message, which is a feature available in `git commit --amend`. The author explicitly chooses not to support the `commit.verbose` configuration option in this initial implementation but expresses openness to adding it later. They also suggest that `--verbose` could be extended to other `git history` subcommands like `split`, `squash`, and `fixup` in future patches, though with some constraints (e.g., only with `--reedit-message` for `fixup`).

The patch touches `builtin/history.c`, updates the documentation in `Documentation/git-history.adoc`, and adds a new test file `t/t3451-history-reword.sh` with 97 lines of test coverage. The implementation appears thorough, with test cases covering the new functionality. The author’s goal is to start with `reword` and then expand support to other subcommands, which seems like a pragmatic approach.

This is part of the `git history` subsystem, which is a relatively new and still-evolving built-in command. The feature itself is user-facing and aligns with existing Git conventions (e.g., `git commit --verbose`), so it is likely to be uncontroversial in principle. However, the omission of `commit.verbose` config support might draw discussion, as users may expect consistency with `git commit`. The author’s rationale for this omission is not stated, so it could become a point of debate. The series is marked as RFC, indicating it is seeking feedback before being finalized.
