This is the eighth patch in Thomas Bachem’s 15-patch bugfix series addressing Git segfaults when config settings lack values. It fixes a crash in `git merge` when `branch.<name>.mergeOptions` is specified without a value (e.g., `git -c branch.main.mergeOptions merge ...`). The fix adds a NULL check in `git_merge_config()` to reject the missing value with `config_error_nonbool()`, aligning with how other string-valued config keys in the same function are handled. The patch includes a new test in `t/t7600-merge.sh` that verifies the error message when the config key is unvalued.

The change is minimal and targeted: two lines added to `builtin/merge.c` and a six-line test case. It follows the series’ established pattern of rejecting unvalued config keys with `config_error_nonbool()`, making the behavior consistent across the codebase. No new symbols or APIs are introduced, and the fix is uncontroversial — it simply prevents a NULL pointer from being passed to `xstrdup()`. The test coverage is thorough, ensuring the error message is user-facing and actionable. This patch is a clear example of the series’ systematic approach to eliminating a class of latent crashes.
