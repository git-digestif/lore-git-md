This is a bugfix patch targeting the sideband protocol, now marked ready for integration.

Junio C Hamano has reviewed the patch and declared it ready for the `next` branch. The patch fixes an infinite loop in the configuration parser for `sideband.allowControlCharacters`, which was introduced in March 2026 (commit 128914438a). The loop occurred when the parser encountered an unrecognized keyword (e.g., typos like "colour", space-separated lists like "color, cursor", or keywords only supported in newer Git versions), causing `git fetch`, `git push`, `git clone`, and `git ls-remote` to hang indefinitely for users with malformed configurations.

The fix advances the parser to the next comma-separated entry after warning about an unrecognized keyword, rather than staying on the problematic entry. The warning message has also been tightened to show only the unrecognized keyword. The patch includes a new test in `t/t5409-colorize-remote-messages.sh` that verifies the parser skips unrecognized keywords (e.g., "bogus") and still processes valid keywords that follow, ensuring the fix works as intended.

Junio noted that the change is minimal and focused, avoiding unnecessary enhancements like allowing whitespace after commas. The test case is well-designed, capping output to prevent infinite warnings during testing. The patch touches only `sideband.c` and its test file, with no cross-subsystem impact. The earlier style discussion about the `!!` operator has been resolved in favor of the author's approach, and a follow-up patch to update `CodingGuidelines` is planned but unrelated to this bugfix.
