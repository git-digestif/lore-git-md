This is the second patch in an RFC series adding `--verbose` support to `git history reword`. The feature mirrors `git commit --amend --verbose`: when editing the commit message, the user sees the full diff of the commit being reworded, which helps provide context for the change.

The implementation touches `builtin/history.c`, updates the command’s documentation, and adds a new test file (`t/t3451-history-reword.sh`) with 97 lines of coverage. The diff display is intentionally not prefixed with `#` so it won’t become part of the commit message. The patch also ensures the diff works in bare repositories and correctly handles merge commits by diffing against the first parent.

Notably, this version omits support for the `commit.verbose` configuration option, which the author suggests could be added later. The test suite covers the core functionality, including edge cases like unstaged changes and merge commits, and verifies that `--no-verbose` and the absence of `--verbose` both suppress the diff.

The patch is well-structured and aligns with existing Git conventions. The omission of config support might draw discussion, but the feature itself is uncontroversial in principle. This is a user-facing improvement to the still-evolving `git history` command, and the implementation looks solid. If you care about interactive rebase workflows, this is worth a quick look.
