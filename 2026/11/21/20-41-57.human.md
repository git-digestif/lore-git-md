This is a feature patch series cover letter -- specifically v10 of Harald Nordgren's effort to teach `git branch` about branches that were integrated upstream via squash or rebase merges rather than tip-reachable merges.

The series introduces `--delete-integrated <pattern>`, which works like `--delete-merged` but also deletes branches whose changes appear in an upstream commit even when the branch tip itself is not an ancestor. When such a branch is removed, the output names the landing commit: `Deleted branch topic (was 1a2b3c4, landed as 9f8e7d6)`.

V10 folds in several fixes and responses to the maintainer's v9 review. Most notably, the file-merge logic in patch 5/5 now uses a plain text merge via `xdl_merge()` and explicitly ignores merge drivers configured in `.gitattributes`; this prevents a scenario where a custom or union merge driver could leave the upstream file unchanged despite the branch's change being absent upstream, causing a false deletion. It also fixes a case where a branch replacing a file or submodule with a directory was never detected as landed. A new patch 3/5 extends `--dry-run` so it previews `-d` and `-D` deletions, not just the `--delete-merged` and `--delete-integrated` modes. The series also adds the test coverage Junio asked for regarding `--dry-run`, `--quiet`, and `branch.<name>.deleteMerged=false` interactions with the new flag, and refactors the deletion messages into a single two-dimensional template table.

The series remains under review with no integration status announced, but v10 appears to address the outstanding correctness and test-coverage concerns raised in the previous iteration.
