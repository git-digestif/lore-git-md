This is the final patch (5/5) of a feature series that implements change-based deletion detection for `git branch --delete-integrated`, specifically adding the squash-merge half via three-way text comparison.

Patch 5/5 extends the tree-based rebase detection from patch 4/5 to handle branches whose changes were integrated upstream after upstream had also modified the same files. When an upstream commit does not contain the branch's exact blob OID for a changed path but instead has those changes merged into a different version of the file, this patch detects the landing. It introduces an `enum change_state` with values `CHANGE_MISSING`, `CHANGE_LANDED`, and `CHANGE_NEEDS_MERGE`, and expands `struct branch_change` to carry `base_oid`, `base_mode`, `upstream_oid`, and a mutable `state` field. The `changes_landed()` function now operates in two passes: first, `change_state_at()` classifies each changed path by comparing tree entries (exact OID and mode match yields `CHANGE_LANDED`, path absence yields `CHANGE_MISSING`, and a differing regular file yields `CHANGE_NEEDS_MERGE`); second, for any path marked `CHANGE_NEEDS_MERGE`, `merge_keeps_upstream()` performs a three-way merge using `xdl_merge()` with `XDL_MERGE_ZEALOUS` between the merge-base, upstream, and branch versions, treating the change as landed only when the merge result is byte-identical to the upstream version.

The merge is deliberately a plain text merge that ignores merge drivers configured in `.gitattributes`. The `mergeable_as_text()` guard rejects files exceeding `MAX_XDIFF_SIZE` or containing binary content, and the code never consults custom merge drivers, which prevents both false positives (a `union` driver would leave upstream unchanged even when the branch's changes are absent) and arbitrary command execution during branch cleanup. Because this reads blob contents, the documentation notes that partial clones may download objects when evaluating `--delete-integrated`.

The patch adds 180 lines of tests to `t/t3200-branch.sh` covering squash merges onto files that upstream had modified, branches with partially landed or conflicting changes, submodule-to-file replacements (handled by `S_ISDIR` checks in `change_state_at()`), and verification that `union` merge drivers do not cause false deletions. Documentation in `Documentation/git-branch.adoc` is updated to describe the plain-text merge semantics and partial-clone implications.

This completes the v10 series, which remains under review with no integration status announced. It fills the gap left by patch 4/5, which only detected rebase merges via exact tree comparisons. Open questions from the thread, including whether `branch.<name>.deleteMerged` is the appropriate config key for the new flag and how to mitigate "npm update" false positives where another author independently makes identical changes, remain unresolved.
