This is the final patch (5/5) of Harald Nordgren's v10 series, completing the `--delete-integrated` feature by adding squash-merge detection for branches whose changes landed in upstream commits that also touched the same files. While the previous patch (4/5) handled rebase-merged branches using purely tree-based comparisons, this patch handles the common GitHub-style "Squash and merge" workflow where upstream modified files before integrating the branch, requiring actual file-content comparison.

The core mechanism introduces a three-way merge approximation per changed path. For each file the branch modified relative to the merge base, the code now records base, branch, and upstream OIDs and modes in an extended `branch_change` struct. When an upstream commit does not exactly match the branch's version of a file, `change_state_at()` marks it `CHANGE_NEEDS_MERGE`, and `merge_keeps_upstream()` reads the three blob versions and runs `xdl_merge()` to check whether merging the branch's changes into the upstream version leaves the upstream text unchanged. The merge deliberately uses the built-in text merge via `xdl_merge()` guarded by `mergeable_as_text()`, ignoring any merge drivers configured in `.gitattributes` -- a safety choice to prevent a driver like `union` from leaving the upstream version unchanged while the branch's actual edits are absent, which would cause a false-positive deletion.

Because this path reads blob contents, the documentation now notes that `--delete-integrated` may download objects in a partial clone, unlike the tree-only rebase detection. The patch adds 180 lines of tests to `t/t3200-branch.sh` covering squash merges onto upstream-modified files, branches whose changes did not land, submodule-to-file replacements, and explicit verification that merge drivers are ignored. The series remains under review; the "npm update" false-positive scenario -- where another author independently made identical changes -- is still unmitigated, and Junio's question about whether `branch.<name>.deleteMerged` is the right config key for this new flag remains open.
