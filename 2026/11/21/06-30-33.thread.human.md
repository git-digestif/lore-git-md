Wonseok Oh has posted the second iteration of a two-patch series fixing how `git cherry-pick` handles sequences on an unborn (orphan) branch. The bug occurs in `sequencer_pick_revisions()` in `sequencer.c`: when HEAD does not yet exist, `repo_get_oid()` fails and leaves a local `oid` variable uninitialized, and that garbage value was previously written to `.git/sequencer/head`, causing `git cherry-pick --abort` to fail with "Could not parse object" instead of the intended "cannot abort from a branch yet to be born" error. The first patch clears `oid` to the null OID when HEAD cannot be resolved, while the second patch applies the same null-OID convention to `.git/sequencer/abort-safety` for consistency and backwards compatibility. A regression test in `t/t3510-cherry-pick-sequence.sh` verifies that the state file contains `$ZERO_OID` and that abort produces the correct error message while leaving HEAD untouched.

The series is currently at v2 and under review. Phillip Wood and Junio C Hamano provided substantive reviews of v1, requesting tighter commit-message wording (citing the 2016 commit `0f974e2124` that introduced the regression) and a more robust test; Wonseok Oh incorporated these changes in v2. Phillip Wood confirmed the null-OID representation for both state files, closing that design question. No Reviewed-by or Acked-by trailers have been recorded yet, and broader behavioral inconsistencies -- such as the inability to abort a multi-pick sequence started on an orphan branch -- remain deferred to separate follow-up work by the author.
