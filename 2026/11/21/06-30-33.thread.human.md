This thread is a single-patch bugfix by Wonseok Oh for the sequencer: when cherry-picking a sequence onto an unborn/orphan branch, `sequencer_pick_revisions()` in `sequencer.c` could leave `oid` uninitialized after `repo_get_oid(r, "HEAD", &oid)` fails, and that garbage value could be saved into `.git/sequencer/head`, making `git cherry-pick --abort` fail with “Could not parse object” instead of the intended “cannot abort from a branch yet to be born.” The proposed fix clears `oid` with `oidclr(&oid, r->hash_algo)` for non-revert actions and adds a regression test in `t/t3510-cherry-pick-sequence.sh`; the series is still under review with no integration status reported.

Phillip Wood gave a substantive review, endorsing the immediate fix while tracing the uninitialized use back to `0f974e2124` and discussing related inconsistencies around reverts on unborn branches and the older unborn-branch check from `04d3d3cfc4`. Wonseok Oh has now replied agreeing to reword the commit message to cite `0f974e2124`, and he raised one open design point: `rollback_is_safe()` expects a null OID for an unborn branch while `update_abort_safety_file()` writes an empty `.git/sequencer/head`, and it is undecided whether the patch should also write the empty file to match that representation. No decision has been made, and the broader behavioral questions about aborting multi-pick sequences on orphan branches are explicitly deferred to separate future work. The likely next step is a v2 with the reworded message and possibly the empty-file alignment, pending guidance on that state-representation question.
