A new bugfix from Wonseok Oh addresses a broken error path in `git cherry-pick` when running on an unborn (orphan) branch. When cherry-picking a sequence of commits where HEAD does not yet exist, `sequencer_pick_revisions()` in `sequencer.c` calls `repo_get_oid()` for HEAD, which fails and leaves the local `oid` struct uninitialized; that garbage value was then written to `.git/sequencer/head` by `save_head()`. As a result, `git cherry-pick --abort` would fail with a misleading "Could not parse object" error instead of the intended "cannot abort from a branch yet to be born", and in some builds the branch pointer could even be moved incorrectly.

The patch fixes this by explicitly clearing `oid` to the null OID with `oidclr()` when the HEAD lookup fails, except for the `REPLAY_REVERT` case which keeps its own "can't revert as initial commit" error. This lets `sequencer_rollback()` correctly detect the unborn-branch situation during `--abort`. The change is confined to `sequencer.c`, with a regression test added to `t/t3510-cherry-pick-sequence.sh` that verifies the abort message and that HEAD remains unborn. The series is newly posted and under review; no maintainer feedback or merge status has been reported yet.
