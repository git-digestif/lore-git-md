Wonseok Oh has proposed a fix for a bug where cherry-picking a sequence of commits onto an orphan branch leaves an uninitialized `oid` variable that gets written to `.git/sequencer/head`, causing `git cherry-pick --abort` to fail with "Could not parse object" instead of the intended "cannot abort from a branch yet to be born" error. The patch clears the OID to the null value when `repo_get_oid()` fails for HEAD, and adds a regression test in `t/t3510-cherry-pick-sequence.sh`. The series is currently under review with no integration status reported.

Phillip Wood has provided a substantive review that endorses the immediate fix while tracing the root cause to commit `0f974e2124` from 2016, which allowed picks onto unborn branches and introduced the use of the uninitialized variable. He highlights several related behavioral inconsistencies in the sequencer: `sequencer_rollback()` currently refuses to abort when HEAD is unborn, making it impossible to abort a multi-pick sequence started on an orphan branch; single-commit reverts are allowed on unborn branches while multi-commit reverts are not; and there is an inconsistency in how unborn branch state is represented between `rollback_is_safe()` (which expects a null OID) and `update_abort_safety_file()` (which writes an empty file). Wood suggests these issues could be addressed in future work separate from this series, such as allowing aborts on unborn branches or unifying the unborn-branch checks across single and multi-commit operations.
