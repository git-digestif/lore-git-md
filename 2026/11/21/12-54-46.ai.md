This is a **feature** patch adding bash shell completion for the `--filter=` option of `git clone`. It modifies `contrib/completion/git-completion.bash` inside the `_git_clone()` function, inserting a `--filter=*)` case that calls `__gitcomp` with the literal values `blob:none blob:limit= sparse:oid=` before the generic `--*` fallback. This mirrors the completion behavior that `git fetch` already provides for the same option.

The commit message explains that `git clone` and `git fetch` share the `--filter` argument but clone previously lacked completion support, so the patch brings parity between the two commands. The change is four lines against base commit `0ffa3e35c7c82ab8d0de226149fb03b3f7674d05` and touches only the completion script; no test updates accompany it, which is typical for manual-verification tooling in `contrib/`.

The patch is small, well-motivated, and unlikely to generate controversy. The specific filter specifiers listed are the standard partial-clone filters (`blob:none`, `blob:limit=<n>`, `sparse:oid=<oid>`), so future reviewers may ask whether additional filters such as `tree:0` should be included or whether the completion should dynamically generate `blob:limit=` values.
