This is a feature patch, the third of five in Harald Nordgren's v10 series on branch deletion detection. It extends `git branch --dry-run` so it now works with plain `-d` and `-D`, not just `--delete-merged`. Previously, asking "what would `git branch -d topic` do?" was impossible without actually running it; now `git branch -d --dry-run topic` prints `Would delete branch topic (was 1a2b3c4).` and leaves the ref untouched, while branches that cannot be deleted -- because they are checked out in a worktree or not fully merged -- still produce the same error they would without the flag. The option remains rejected when no deletion is happening at all.

The change is small and surgical: it relaxes the argument validation in `cmd_branch()`, threads the `DELETE_BRANCH_DRY_RUN` flag into the existing `delete_branches()` call path, and updates the man page and tests in `t/t3200-branch.sh` to cover `-d`, `-D`, remote-tracking branches, and the error cases. This directly addresses one of Junio C Hamano's open questions from the v9 review about `--dry-run` semantics, and the test coverage looks thorough for the behavior change.
