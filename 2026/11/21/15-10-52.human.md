This is a **feature patch** -- specifically the second of three patches in Yoichi NAKAYAMA's v2 series making submodule configuration worktree-aware when `extensions.worktreeConfig` is enabled.

The patch reroutes most submodule settings (`submodule.<name>.active`, `.url`, `.update`, and `.gitdir`) from the shared repository config to the worktree-specific config file by switching calls in `builtin/submodule--helper.c` from `repo_config_set_gently()` to `repo_config_set_worktree_gently()`. It also teaches `git worktree add` to explicitly strip any `submodule.*.gitdir` entries when copying the base config into a new worktree's `config.worktree`, since each worktree needs its own gitdir path. For `git submodule deinit`, it adjusts the cleanup logic so that when worktree config is enabled, the submodule section is removed from the worktree config and `submodule.<name>.active` is set to `false` there to unregister the submodule cleanly.

Within the series, this patch handles the storage routing while patch 1 (already posted) ensures `gitdir` paths are stored relative so they survive worktree moves; patch 3 will address how `git submodule init` reconciles gitdir values already present in the repository config. The change removes two long-standing `NEEDSWORK` comments about multi-worktree support and includes thorough tests in `t/t2405-worktree-submodule.sh` and `t/t7425-submodule-gitdir-path-extension.sh` covering init, add, sync, deinit, and worktree creation across both main and linked worktrees. The motivation is clearly stated -- allowing different branches checked out in separate worktrees to point the same submodule name at different URLs or commits -- and the patch looks well-crafted with no obvious gaps.
