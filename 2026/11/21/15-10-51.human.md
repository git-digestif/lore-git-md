This is the first patch in a three-part feature series aimed at worktree-specific submodule configuration, specifically fixing how `submodule.<name>.gitdir` paths are stored for linked worktrees. Authored by Yoichi NAKAYAMA as `[PATCH v2 1/3]`, it ensures that when Git writes the default gitdir for a submodule inside a linked worktree, the path is stored relative to that worktree rather than as an absolute path. This keeps the configuration valid if the worktree directory is later moved, provided `worktree.useRelativePaths` is enabled.

The change centers on `create_default_gitdir_config()` in `builtin/submodule--helper.c`, which now uses `get_current_worktree()` and `worktree_git_path()` to compute the `modules/` directory, then converts it to a relative path via `relative_path()` when it is absolute. The v2 revision also fixes a static-buffer lifetime issue by copying the result of `worktree_git_path()` into a `strbuf` immediately, preventing corruption from later calls. The error message suggesting a manual `git config` fix now includes the correct relative path format (e.g., `../.git/worktrees/wt/modules/sub1`).

Tests in `t/t7425-submodule-gitdir-path-extension.sh` verify that `git submodule init` in a linked worktree writes the expected relative gitdir values into the config. The patch is well-scoped and addresses a concrete edge case in worktree mobility; as part of the larger series, it lays groundwork for storing submodule settings in the worktree-specific config file when `extensions.worktreeConfig` is active. No objections have been raised yet, and the series remains under review.
