This is the second patch in a two-part bugfix series correcting combined-diff output for merges with many parents. Aniket Gupta's series targets a long-standing bug reported by Sami Jawhar where `git log --cc` misplaces columns or drops hunks entirely once a merge exceeds roughly 32 parents.

Where the first patch fixed the underlying bit-shift bug, this patch handles merges that exceed the mask capacity altogether. The combined-diff masks use one bit per parent, leaving room for 62 parents on platforms where `long` is 64 bits, or 30 where it is 32 bits (notably Windows). When a merge has more parents than that, the patch now prints an error to stderr and skips the patch output for that single merge, but deliberately does not abort the whole command, so `git log --cc` continues through histories containing huge octopus merges. The raw format output, which does not rely on these masks, is still shown as before.

The patch introduces a `MAX_PATCH_PARENTS` macro in `combine-diff.c` and gates the patch-format output on a new `show_patch` flag. Tests in `t/t4038-diff-combined.sh` cover both sides of the limit: one test confirms a 62-parent merge still renders correctly (skipped where `long` is not 64 bits), and another verifies that a 63-parent merge produces the error message while still emitting the raw combined output.

The contribution looks well-crafted: the commit message clearly states the problem and the platform-dependent limit, the tests exercise both the success and failure paths, and the change is minimal and focused.
