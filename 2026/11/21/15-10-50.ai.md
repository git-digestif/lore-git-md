This is a **feature patch series** -- specifically the v2 cover letter for a three-patch series that teaches Git to store submodule settings in the worktree-specific config file when `extensions.worktreeConfig` is enabled. The series is authored by Yoichi NAKAYAMA and addresses the problem that submodule configuration like `submodule.<name>.gitdir` is currently shared across all linked worktrees, causing different superproject worktrees to incorrectly share the same submodule HEAD and index.

Compared to v1, this revision primarily polishes commit messages and fixes a static-buffer lifetime issue in patch 1 by copying the result of `worktree_git_path()` into a `strbuf` immediately. Patch 1 ensures `submodule.<name>.gitdir` stays relative for linked worktrees (using `relative_path()` against the worktree path) so the setting remains valid if the worktree is moved. Patch 2 modifies `repo_config_set_worktree_gently()` and `copy_filtered_worktree_config()` in `builtin/worktree.c` to route submodule settings to the worktree config and explicitly exclude `submodule.<name>.gitdir` from being copied when adding new worktrees. Patch 3 adjusts `git submodule init` to copy an existing `gitdir` from the main repository config into the worktree config only when it belongs to the current worktree.

For follow-up discussion, the key technical landmarks are the new helper `submodule_git_dir_matches_current_worktree()` in `builtin/submodule--helper.c` (replacing the earlier `validate_submodule_git_dir_with_worktree()`), which checks whether a gitdir path resolves under the current worktree's `modules/` directory, and the new warning string `submodule_mismatch_warning` that fires when `git submodule init` encounters a repository-config gitdir belonging to a different worktree and declines to copy it. Tests in `t/t7425-submodule-gitdir-path-extension.sh` expect relative paths like `../.git/worktrees/wt/modules/sub1` in the worktree config and assert the warning appears on stderr when a mismatch is detected. The series touches `builtin/submodule--helper.c`, `builtin/worktree.c`, `Documentation/config/submodule.adoc`, and adds `t/t2405-worktree-submodule.sh`.

The series remains under review with no substantive objections yet; the main open question is how this interacts with existing `git submodule update --init` workflows across worktrees.
