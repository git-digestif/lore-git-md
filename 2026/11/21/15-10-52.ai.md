This is the second patch in Yoichi NAKAYAMA's v2 series (`[PATCH v2 2/3]`) implementing worktree-specific submodule configuration. It is a feature patch that routes submodule settings into the per-worktree config file (`config.worktree`) whenever `extensions.worktreeConfig` is enabled, rather than writing them to the shared repository config. In `builtin/submodule--helper.c`, the patch switches calls from `repo_config_set_gently()` to `repo_config_set_worktree_gently()` across several code paths: `init_submodule()` (for `submodule.<name>.active`, `.url`, and `.update`), `sync_submodule()` (for `.url`), `configure_added_submodule()` (for `.url` and `.active`), and `validate_and_set_submodule_gitdir()` (for `.gitdir`). The `deinit_submodule()` function is also updated to target the correct config file -- `config.worktree` when worktree config is active, otherwise `config` -- and, when worktree config is enabled, to explicitly set `submodule.<name>.active` to `false` in that file to mark the submodule as unregistered for the current worktree.

In `builtin/worktree.c`, the patch modifies `copy_filtered_worktree_config()` so that when a new linked worktree is created, any `submodule.<name>.gitdir` entries are stripped from the copied config. This exclusion is necessary because the gitdir path is inherently worktree-specific -- sharing it would cause different superproject worktrees to point at the same submodule HEAD and index. The implementation parses the source config for keys matching `submodule.<name>.gitdir` and unsets them in the destination file.

The patch also updates `Documentation/config/submodule.adoc` to note that `submodule.<name>.gitdir` is stored in each worktree's config when `extensions.worktreeConfig` is enabled. Test coverage is added in `t/t2405-worktree-submodule.sh` and `t/t7425-submodule-gitdir-path-extension.sh`: the former verifies that `submodule update --init`, `submodule add`, `submodule sync`, and `submodule deinit` write `active`, `url`, and `gitdir` to the worktree config and that deinit sets `active=false` there; the latter confirms that gitdir values land in `config.worktree` for both main and linked worktrees, and that `git worktree add` does not copy gitdir settings into the new worktree.

Within the series context, this patch builds directly on patch 1/3 (which made gitdir paths relative for linked worktrees) and sets up patch 3/3 (which adjusts `git submodule init` to copy an existing gitdir from the main config only when it belongs to the current worktree via the helper `submodule_git_dir_matches_current_worktree()`). Key technical landmarks for follow-up discussion include the pervasive use of `repo_config_set_worktree_gently()`, the `the_repository->repository_format_worktree_config` checks that gate worktree-config behavior, and the string-list-based filtering of `submodule.*.gitdir` keys in `copy_filtered_worktree_config()`. No reviewer objections have been raised yet; the open question remains how these changes interact with existing `git submodule update --init` workflows across multiple worktrees.
