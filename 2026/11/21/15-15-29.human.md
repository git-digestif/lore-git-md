This is a substantive review reply to Dominik Maier's bugfix for `git archive --remote` argument validation. René Scharfe confirms the original problem is real ("good find") but raises two concerns about the proposed fix: first, that rejecting `--add-virtual-file` together with `--remote` is arguably wrong since the option carries its own content and never touches the server filesystem; second, that the patch would also reject the sequence `--remote --add-file=foo --no-add-file`, which could legitimately be allowed since the `--no-add-file` cancels the earlier request.

Rather than rejecting inside the callback, René suggests moving the `stat()` call later so it happens after any `--no-add-file` has been applied, and simply refusing to stat when `is_remote` is set. He notes that files added via `--add-file` have `content == NULL`, which distinguishes them from `--add-virtual-file` and could be used to permit the latter combination. The review is engaged and identifies concrete edge cases the current patch would mishandle, offering an alternative implementation that preserves more permissive behavior while still avoiding the filesystem access.
