# Thread deltas

## 2026/11/21

- [2026/11/21/07-40-45 by Wonseok Oh via GitGitGadget <gitgitgadget@gmail.com>] Wonseok Oh posted a patch changing file_change_m() to replace the `while (read_next_command(state) != EOF)` loop with a `for (;;)` loop that calls read_next_command() at the top, and adding a test verifying that fast-import fails when inline data is cut off at end of input.
- [2026/11/21/20-03-58 by Junio C Hamano <gitster@pobox.com>] Junio C Hamano objected that the reasoning is wrong because note_change_n() can call parse_and_store_blob() at EOF only since it does not loop, and warned that the proposed change would loop forever if a `cat-blob` command appears on an incomplete final line without a trailing LF, since the updated code ignores the return value of read_next_command().

## 2026/11/22

- [2026/11/22/04-01-15 by Wonseok Oh <wonseok_oh@korea.ac.kr>] Wonseok Oh agreed with the earlier critique that ignoring read_next_command()'s return value could cause an infinite loop, and proposed a revised fix: replacing the while loop with a for(;;) loop that dies with "expected 'data n' command, found end of input" when read_next_command() returns EOF, which he stated fixes both the original uninitialized object ID bug and the infinite loop; he noted the error message was chosen arbitrarily and is open to changing it.
