This is a documentation patch from brian m. carlson that warns users against using `http.extraheader` for authentication credentials.

The patch updates three documentation files: `Documentation/config/http.adoc`, `Documentation/git.adoc`, and `Documentation/gitfaq.adoc`. In `http.adoc`, it adds a note to the `http.extraHeader` config entry explicitly stating that the option should not be used to pass credentials, explaining that doing so can expose credentials to every server Git contacts (when the URL-qualified variant is not used) or to other users (when set globally or on the command line). It also notes that using `http.extraheader` for the `Authorization` header can break external tools like Git LFS, which may add their own `Authorization` header and end up sending duplicate headers; credential helpers do not have this problem because Git LFS only invokes them when credentials are absent. The patch recommends credential helpers as the secure alternative, noting they support modern methods including Bearer tokens.

In `git.adoc`, the patch removes a sentence that specifically called out `http.extraHeader` as an example of a variable that might contain sensitive information in its value, replacing it with a more generic statement about variables where sensitive data appears in the value rather than the key. In `gitfaq.adoc`, it appends a sentence to the existing advice about not putting passwords in URLs, adding that `http.extraheader` is similarly not recommended for credentials.

The commit message provides clear motivation: users frequently misuse `http.extraheader` for credentials despite it being insecure and prone to causing breakage with tools that manage their own auth headers. The change is documentation-only, with no code or test modifications.
