This is a preparatory refactoring patch, the second of five in Harald Nordgren's v10 series. It modifies `delete_branches()` in `builtin/branch.c` to accept a new `struct strmap *landed_commits` parameter that maps branch names to the upstream commits where their changes landed. When a branch appears in this map, the function skips the usual `check_branch_commit()` merge-reachability test and instead reports the deletion with a "landed as %s" suffix showing the abbreviated OID of the landing commit. Both existing call sites (`delete_merged_branches()` and the main `cmd_branch()` delete path) currently pass NULL, so this patch introduces no user-visible behavior change yet; it merely sets up the plumbing for patches 3/5 through 5/5 which implement the `--delete-integrated` flag.

The patch also flattens the message-printing logic by replacing nested conditionals with a static `msg_templates[2][3]` array indexed by dry-run state, as Junio had suggested in earlier review. The three message variants cover the landed case, remote-tracking branches, and regular branches, each with dry-run and real-delete forms. When `landed_commits` is non-NULL and contains the branch name, the code uses `strmap_get()` to retrieve the landing commit and `repo_find_unique_abbrev()` to format its OID for the "landed as" output.

Files touched are limited to `builtin/branch.c` (39 insertions, 19 deletions). Key symbols introduced or modified include the `landed_commits` parameter on `delete_branches()`, the `msg_templates` array, and the `landed` local variable used to conditionally select the message format. The check to skip `check_branch_commit()` is guarded by `landed_commits && strmap_contains(landed_commits, bname.buf)`, ensuring existing behavior is unchanged when no map is supplied.

This patch relates directly to the series goal of letting `git branch --delete-integrated` attribute deletions to specific upstream commits. Future patches will populate the `landed_commits` map via `find_landed_commits()` and pass it to `delete_branches()`, enabling output like `Deleted branch topic (was 1a2b3c4, landed as 9f8e7d6)`. No open questions are raised by this specific patch; it is a straightforward mechanical preparation. The series remains under review with no integration status announced.
