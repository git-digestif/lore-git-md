Thread identity: Documentation patch (v2) from brian m. carlson warning users against using `http.extraheader` for authentication credentials. Thread type: standalone documentation patch (not part of a series).

Core problem or goal: The patch addresses the recurring misuse of `http.extraheader` for passing credentials, which is insecure (exposing credentials to every server contacted or to other users on the system) and can break external tools like Git LFS that add their own `Authorization` headers, resulting in duplicate headers. The goal is to document that credential helpers are the secure, recommended alternative.

Current status: v2 posted to the mailing list; under review. v2 incorporates the grammatical fix requested by Junio C Hamano in review of v1: the text now reads "should not be used to pass credentials" (adding the missing word "used"). No substantive technical objections raised; no Reviewed-by or Acked-by trailers recorded yet.

Key technical details: Documentation-only change touching three files. `Documentation/config/http.adoc` gains a note on the `http.extraHeader` entry explaining the credential exposure risks (global scope vs URL-qualified) and the Git LFS conflict, recommending credential helpers instead (which support Bearer tokens and are only invoked by Git LFS when credentials are absent). `Documentation/git.adoc` replaces a specific mention of `http.extraHeader` with a generic statement about variables containing sensitive values. `Documentation/gitfaq.adoc` appends a sentence to the existing "do not put passwords in URLs" advice noting that `http.extraheader` is similarly not recommended for credentials. No code or test changes.

Open questions and loose ends: None outstanding. Junio C Hamano's request for the grammatical fix ("should not be used to pass credentials") has been addressed in v2.
