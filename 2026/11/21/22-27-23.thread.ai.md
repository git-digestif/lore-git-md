Thread identity: Documentation patch (v3) from brian m. carlson warning users against using `http.extraHeader` for authentication credentials. Thread type: standalone documentation patch (not part of a series).

Core problem or goal: The patch addresses the recurring misuse of `http.extraheader` for passing credentials, which is insecure (exposing credentials to every server contacted or to other users on the system) and can break external tools like Git LFS that add their own `Authorization` headers, resulting in duplicate headers. The goal is to document that credential helpers are the secure, recommended alternative.

Current status: v3 posted to the mailing list; under review. v3 incorporates all three formatting adjustments requested by Junio C Hamano in review of v2: the config key is written in camelCase as `http.extraHeader` throughout (including `Documentation/gitfaq.adoc`), the header name `Authorization` is wrapped in monospaced backquotes, and a `linkgit:gitcredentials[7]` cross-reference has been added. v2 had incorporated the grammatical fix from v1 ("should not be used to pass credentials"). No substantive technical objections raised; no Reviewed-by or Acked-by trailers recorded yet.

Key technical details: Documentation-only change touching three files. `Documentation/config/http.adoc` gains a note on the `http.extraHeader` entry explaining the credential exposure risks (global scope vs URL-qualified) and the Git LFS conflict, recommending credential helpers instead (which support Bearer tokens) with a `linkgit:gitcredentials[7]` cross-reference. `Documentation/git.adoc` replaces a specific mention of `http.extraHeader` with a generic statement about variables containing sensitive values. `Documentation/gitfaq.adoc` appends a sentence to the existing "do not put passwords in URLs" advice noting that `http.extraHeader` is similarly not recommended for credentials. No code or test changes.
