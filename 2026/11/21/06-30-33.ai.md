This is a bugfix targeting the sequencer subsystem, specifically `git cherry-pick` behavior on an unborn branch. When cherry-picking a sequence of commits onto an orphan branch where HEAD does not yet exist, `sequencer_pick_revisions()` in `sequencer.c` calls `repo_get_oid(r, "HEAD", &oid)` which fails and leaves the `oid` struct uninitialized. The code previously passed this uninitialized value directly to `save_head()`, which writes it to `.git/sequencer/head`. Later, `git cherry-pick --abort` calls `sequencer_rollback()`, which checks for a null OID to produce the error "cannot abort from a branch yet to be born"; instead, the garbage OID causes a "Could not parse object" error, or in some builds undefined behavior where the branch pointer accidentally moves to the last picked commit.

The patch modifies the error handling in `sequencer_pick_revisions()` so that when `repo_get_oid()` fails for HEAD and the action is not `REPLAY_REVERT` (which retains its own "can't revert as initial commit" error), the `oid` is explicitly cleared to the null OID via `oidclr(&oid, r->hash_algo)` before being saved. This ensures `sequencer_rollback()` correctly detects the unborn-branch case during `--abort`. The fix touches only `sequencer.c` and adds a regression test to `t/t3510-cherry-pick-sequence.sh` that creates an orphan branch, attempts a cherry-pick sequence, and verifies that `--abort` fails with the expected "cannot abort from a branch yet to be born" message while leaving HEAD unborn.
