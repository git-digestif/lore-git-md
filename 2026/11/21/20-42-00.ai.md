This is patch 3/5 of v10 of Harald Nordgren's series introducing `git branch --delete-integrated`; it is a small user-visible CLI feature change that relaxes `git branch --dry-run` so it works with plain `-d` and `-D` deletion modes, not only with `--delete-merged`. Previously the option died with "--dry-run requires --delete-merged" unless a `--delete-merged` pattern was given; now `cmd_branch()` in `builtin/branch.c` validates with `if (dry_run && !delete && !delete_merged.nr)` and dies only when no deletion mode is active, and the delete path passes the `DELETE_BRANCH_DRY_RUN` flag into `delete_branches()` alongside the existing force and quiet flags. The documentation in `Documentation/git-branch.adoc` is updated to show `--dry-run` on the `(-d|-D)` synopsis line and to describe that it prints "Would delete branch ..." messages while leaving refs untouched, with unmergeable or worktree-checked-out branches still producing the same errors as a real delete. Tests in `t/t3200-branch.sh` cover `-d --dry-run` on a merged branch, `-D --dry-run` on an unmerged branch, `-d -r --dry-run` on a remote-tracking ref, confirmation that no refs are actually removed, and the rejection of `--dry-run` when no deletion is requested.

This patch directly addresses one of Junio C Hamano's open v9 review items about `--dry-run` semantics, and it is a prerequisite for the series' new `--delete-integrated` flow because users will want to preview `-d`/`-D` deletions of integrated branches before committing. It touches only `builtin/branch.c`, `Documentation/git-branch.adoc`, and `t/t3200-branch.sh`, and introduces no new config keys or data structures; the only new internal symbol is the `DELETE_BRANCH_DRY_RUN` flag bit consumed by `delete_branches()`, which was already prepared by patch 2/5's `msg_templates[2][3]` refactoring. The series remains under review with no integration branch announced, and the broader open questions from the thread -- whether `branch.<name>.deleteMerged` is the right config key for `--delete-integrated`, and how to mitigate "npm update" false positives via author checks or patch IDs -- are unaffected by this particular change.
