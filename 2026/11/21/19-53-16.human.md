This is a refactoring patch for `git reflog expire`, specifically the first of two patches in v3 of Laveesh Bansal's series. It consolidates the two separate code paths in `builtin/reflog.c` -- one that expires reflogs for `--all` and one that handles explicitly named refs -- into a single unified loop. Both sources of ref names are now collected into one `string_list` first, then processed in one pass with the callback setup happening in a single place.

The motivation is to prevent the kind of drift that already occurred once: commit d1536ac3e2 had to fix the named-refs copy of the loop because it was missing the `dry_run` flag that the `--all` loop had. By merging the loops, future changes to the expiration setup only need to happen in one location. The patch is purely mechanical; the commit message emphasizes that output and exit status remain unchanged, and command-line arguments are still resolved via `repo_dwim_log` inside the loop so dynamic refs like `@{-1}` keep working.

This is patch 1/2 in the v3 series. Patch 2 (not shown here) will build on this refactor to deduplicate refs that appear both via `--all` and on the command line, using a `strset` to track what has already been processed. The series has drawn positive attention from Junio C Hamano, who originally suggested the refactor, and Patrick Steinhardt, who reviewed earlier versions. The patch itself is small, clean, and well-justified, touching only `builtin/reflog.c` with a net reduction of two lines.
