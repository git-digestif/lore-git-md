This is the third and final patch in Yoichi NAKAYAMA's v2 series making submodule configuration worktree-aware when `extensions.worktreeConfig` is enabled. The patch modifies `builtin/submodule--helper.c` so that `git submodule init` copies an existing `submodule.<name>.gitdir` value from the repository config into `config.worktree` only when that path actually belongs to the current worktree, and otherwise generates a fresh worktree-specific path.

The core addition is the helper `submodule_git_dir_matches_current_worktree()`, which normalizes a gitdir path (absolute or relative to the worktree) and checks whether it resolves under the current worktree's `modules/` directory by comparing it against the superproject's git dir using `relative_path()`. A new warning string `submodule_mismatch_warning` fires when an existing repository-config value does not match the current worktree and is therefore not copied. `validate_and_set_submodule_gitdir()` now takes a `struct worktree *wt` parameter and, when `repository_format_worktree_config` is set, first checks the worktree config directly via a temporary config set; if the key is absent there, it inspects the effective value from lower-priority scopes and copies it to the worktree config only if it passes the new match check and validation, otherwise emitting the warning and falling through to generate a new gitdir path.

The test suite in `t/t7425-submodule-gitdir-path-extension.sh` gains cases verifying that in the main worktree, enabling worktree config and running `git submodule init` copies existing repository-config gitdir values into `config.worktree`, while in a linked worktree the same command warns that the existing value does not point to a gitdir for the current worktree and instead writes the expected relative path (e.g. `../.git/worktrees/wt/modules/sub1`). Additional assertions cover absolute paths written by older Git versions and custom non-default gitdir names to ensure they are preserved when they match and regenerated when they do not.

This patch completes the series' goal of preventing linked worktrees from sharing submodule gitdirs: patch 1 established relative-path generation for new worktrees, patch 2 routed submodule config writes into `config.worktree`, and this patch ensures `git submodule init` safely migrates or rejects pre-existing repository-level gitdir settings based on worktree ownership. The series remains under review with no substantive objections noted yet.
