This is a documentation patch that warns users against using `http.extraheader` to pass authentication credentials. brian m. carlsson updates three man pages to clarify that the option is not designed for credentials and to steer users toward credential helpers instead.

The commit message lays out the concrete risks of the current misuse: people frequently set the header globally rather than URL-qualified, which leaks credentials to every server Git talks to, or they place it on the command line or in a config file where other users or anyone with repo access can read it. The patch also notes that injecting an Authorization header via `http.extraheader` breaks Git LFS, since that tool can end up sending duplicate Authorization headers and failing authentication, whereas a credential helper works correctly.

The diff adds an explicit warning to the `http.extraheader` entry in `Documentation/config/http.adoc`, recommending credential helpers -- which can implement any reasonable auth method including Bearer tokens -- as the safer choice. It removes now-misleading text from `Documentation/git.adoc` that had cited `http.extraheader` as an example of a variable carrying sensitive data, and adds a similar caution to the FAQ entry about embedding passwords in URLs in `Documentation/gitfaq.adoc`.

This is a small, well-motivated clarification that addresses a recurring security footgun without changing any code. The patch touches only documentation files and is signed off by the author, so it appears ready for review.
