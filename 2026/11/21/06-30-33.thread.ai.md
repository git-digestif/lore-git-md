Thread identity: single-patch bugfix series authored by Wonseok Oh (sent via GitGitGadget) targeting the sequencer subsystem, specifically `git cherry-pick` behavior on an unborn (orphan) branch.

Core problem or goal: when cherry-picking a sequence of commits onto an orphan branch where HEAD does not yet exist, `sequencer_pick_revisions()` in `sequencer.c` calls `repo_get_oid(r, "HEAD", &oid)`, which fails and leaves `oid` uninitialized; this garbage value was previously passed to `save_head()` and written to `.git/sequencer/head`, causing `git cherry-pick --abort` to fail with "Could not parse object" (or undefined behavior moving the branch pointer) instead of the intended "cannot abort from a branch yet to be born" error from `sequencer_rollback()`.

Current status: patch proposed and under review; no integration status reported. Author has agreed to reword the commit message in a forthcoming v2 to cite commit `0f974e2124` as the origin of the uninitialized-variable use. Phillip Wood confirmed the null OID will be used for `.git/sequencer/head` on unborn branches (rather than an empty file) for backwards compatibility with older Git versions. Junio C Hamano has now also endorsed the commit-message tightening: the first paragraph should clarify the relationship between `oidclr()` and `sequencer_rollback()`'s null-OID check, the second paragraph should describe general undefined-behavior failure modes rather than anecdotal builds ("my master build", "Debian's 2.47.3"), and the trailing ", and add a test" filler should be removed.

Key technical details: the fix modifies `sequencer_pick_revisions()` in `sequencer.c` to explicitly clear `oid` to the null OID via `oidclr(&oid, r->hash_algo)` when `repo_get_oid()` fails for HEAD and the action is not `REPLAY_REVERT` (which keeps its own "can't revert as initial commit" error), ensuring `sequencer_rollback()` correctly detects the unborn-branch case. A regression test is added to `t/t3510-cherry-pick-sequence.sh` that creates an orphan branch, attempts a cherry-pick sequence, and verifies that `--abort` fails with "cannot abort from a branch yet to be born" while leaving HEAD unborn. Phillip Wood's review traces the uninitialized-variable introduction to commit `0f974e2124` (cherry-pick: allow to pick to unborn branches, 2016-06-06), notes that single-commit reverts on unborn branches are allowed via a separate code path from `7acaaac275` (2011) while multi-commit reverts are not, and observes that the unborn-branch check in `sequencer_rollback()` dates to `04d3d3cfc4` (2011) without documented rationale. Junio C Hamano raises a robustness concern about the proposed test: because the cherry-pick fails at the first step leaving HEAD unborn with an empty abort-safety file, the test might pass coincidentally if stack variables are zero-initialized, or fail in `rollback_is_safe()` with "could not parse abort-safety" instead of the intended error; he suggests the test verify the specific error message via `test_grep "cannot abort from a branch yet to be born"` and additionally validate that `.git/sequencer/head` stores `$ZERO_OID` to harden against coincidental passes.

Open questions and loose ends: the state-representation question for `.git/sequencer/head` on unborn branches is closed -- null OID approach confirmed by Phillip Wood for backwards compatibility, rejecting the empty-file alternative. Commit-message rewording is now endorsed by both Phillip Wood and Junio C Hamano (cite `0f974e2124`, clarify `oidclr()`/rollback relationship, generalize failure modes, remove filler). Test hardening is requested by Junio: grep for the specific "cannot abort from a branch yet to be born" message and check `.git/sequencer/head` contains `$ZERO_OID`. Broader behavioral inconsistencies remain deferred to separate follow-up work by Wonseok Oh: `sequencer_rollback()` currently refuses to abort when HEAD is unborn and leaves sequencer state intact, making it impossible to abort a multi-pick sequence started on an orphan branch; future work could allow aborting cherry-picks on unborn branches, remove the unborn-branch check for multi-commit reverts, unify the null-OID vs empty-file state representation across both state files, or move the unborn-branch check to cover single picks as well.
