Thread identity: two-patch bugfix series (v2) authored by Wonseok Oh (sent via GitGitGadget) targeting the sequencer subsystem, specifically `git cherry-pick` behavior on an unborn (orphan) branch.

Core problem or goal: when cherry-picking a sequence of commits onto an orphan branch where HEAD does not yet exist, `sequencer_pick_revisions()` in `sequencer.c` calls `repo_get_oid(r, "HEAD", &oid)`, which fails and leaves `oid` uninitialized; this garbage value was previously passed to `save_head()` and written to `.git/sequencer/head`, causing `git cherry-pick --abort` to fail with "Could not parse object" (or undefined behavior moving the branch pointer) instead of the intended "cannot abort from a branch yet to be born" error from `sequencer_rollback()`.

Current status: v2 posted and under review; no integration status reported. The author has incorporated the requested changes from v1: the commit message now cites commit `0f974e2124` as the origin of the uninitialized-variable use, describes general undefined-behavior failure modes rather than anecdotal builds, and removes filler text, per feedback from Phillip Wood and Junio C Hamano.

Key technical details: patch 1 modifies `sequencer_pick_revisions()` in `sequencer.c` to explicitly clear `oid` to the null OID via `oidclr(&oid, r->hash_algo)` when `repo_get_oid()` fails for HEAD and the action is not `REPLAY_REVERT` (which keeps its own "can't revert as initial commit" error), ensuring `sequencer_rollback()` correctly detects the unborn-branch case. Patch 2 (new in v2) addresses `.git/sequencer/abort-safety`: on an unborn branch it now stores the null OID instead of leaving the file empty, for consistency with the `.git/sequencer/head` representation and backwards compatibility with older Git versions. The regression test in `t/t3510-cherry-pick-sequence.sh` has been reworked per Junio C Hamano's suggestion: it attempts to cherry-pick `initial picked` (where the first commit succeeds, birthing HEAD, and the second fails), then verifies that `.git/sequencer/head` contains `$ZERO_OID`, that `git cherry-pick --abort` fails with the exact message "cannot abort from a branch yet to be born" (checked via `test_grep`), and that HEAD remains where it was; the cover letter notes the test could still pass coincidentally if stack memory happens to be zeroed.

Open questions and loose ends: the state-representation question for both `.git/sequencer/head` and `.git/sequencer/abort-safety` on unborn branches is closed -- null OID approach confirmed by Phillip Wood for backwards compatibility. Commit-message rewording and test hardening requests from Phillip Wood and Junio C Hamano have been addressed in v2. Broader behavioral inconsistencies remain deferred to separate follow-up work by Wonseok Oh: `sequencer_rollback()` currently refuses to abort when HEAD is unborn and leaves sequencer state intact, making it impossible to abort a multi-pick sequence started on an orphan branch; future work could allow aborting cherry-picks on unborn branches, remove the unborn-branch check for multi-commit reverts, or move the unborn-branch check to cover single picks as well.
