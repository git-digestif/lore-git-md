Thread identity: two-patch bugfix series (v2) authored by Wonseok Oh (sent via GitGitGadget) targeting the sequencer subsystem, specifically `git cherry-pick` behavior on an unborn (orphan) branch. The current email is Junio C Hamano's review of the v2 cover letter.

Core problem or goal: when cherry-picking a sequence of commits onto an orphan branch where HEAD does not yet exist, `sequencer_pick_revisions()` in `sequencer.c` calls `repo_get_oid(r, "HEAD", &oid)`, which fails and leaves `oid` uninitialized; this garbage value was previously passed to `save_head()` and written to `.git/sequencer/head`, causing `git cherry-pick --abort` to fail with "Could not parse object" (or undefined behavior moving the branch pointer) instead of the intended "cannot abort from a branch yet to be born" error from `sequencer_rollback()`. Patch 2 addresses the related `.git/sequencer/abort-safety` file: `update_abort_safety_file()` previously wrote an empty file when HEAD was unborn, which caused `rollback_is_safe()` to die with "could not parse" via `get_oid_hex()` during `git cherry-pick --skip` after a failed multi-commit pick on an unborn branch.

Current status: v2 posted and under review; Junio C Hamano has endorsed both patches with "Looking good" -- patch 1/2 for the commit message accuracy and test robustness, and patch 2/2 as "trivially correct" while noting the commit message could additionally mention the `rollback_is_safe()` failure mode during `--skip`; in his review of the v2 cover letter Junio additionally endorsed the restructuring that separates the `.git/sequencer/head` fix from the `.git/sequencer/abort-safety` update, noting it makes both changes straightforward to verify individually, and specifically approved the test adjustments in patch 1 as matching the scenario described in the commit log; no integration status reported. The author has incorporated the requested changes from v1: the commit message now cites commit `0f974e2124` as the origin of the uninitialized-variable use, describes general undefined-behavior failure modes rather than anecdotal builds, and removes filler text, per feedback from Phillip Wood and Junio C Hamano.

Key technical details: patch 1 modifies `sequencer_pick_revisions()` in `sequencer.c` to explicitly clear `oid` to the null OID via `oidclr(&oid, r->hash_algo)` when `repo_get_oid()` fails for HEAD and the action is not `REPLAY_REVERT` (which keeps its own "can't revert as initial commit" error), ensuring `sequencer_rollback()` correctly detects the unborn-branch case. Junio C Hamano adds that `oidclr()` properly initializes both the hash and `.algo` member fields of the outer `oid` variable, which could otherwise carry arbitrary stack garbage or retain a stale value from an earlier loop over `opts->revs->pending`, ensuring `save_head(oid_to_hex(&oid))` writes the correct null OID for the repository's hash algorithm into `.git/sequencer/head`, which `sequencer_rollback()` later parses and detects via its `is_null_oid()` check to reject `--abort` before touching HEAD. Patch 2 modifies `update_abort_safety_file()` in `sequencer.c`: instead of writing an empty file when `repo_get_oid(the_repository, "HEAD", &head)` fails, the code now calls `oidclr(&head, the_repository->hash_algo)` to explicitly set the null OID before writing `oid_to_hex(&head)` to `.git/sequencer/abort-safety`, ensuring both sequencer state files consistently represent an unborn branch with the null OID for backwards compatibility with older Git versions. The regression test in `t/t3510-cherry-pick-sequence.sh` has been reworked per Junio C Hamano's suggestion: it attempts to cherry-pick `initial picked` (where the first commit succeeds, birthing HEAD, and the second fails), then verifies that `.git/sequencer/head` contains `$ZERO_OID`, that `git cherry-pick --abort` fails with the exact message "cannot abort from a branch yet to be born" (checked via `test_grep`), and that HEAD remains where it was; patch 2's test additionally asserts that `.git/sequencer/abort-safety` also contains `$ZERO_OID`; the cover letter notes the test could still pass coincidentally if stack memory happens to be zeroed. Junio notes that while checking the state files directly verifies the change, a follow-up test exercising `git reset --merge` followed by `git cherry-pick --skip` would additionally cover the `rollback_is_safe()` code path.

Open questions and loose ends: the state-representation question for both `.git/sequencer/head` and `.git/sequencer/abort-safety` on unborn branches is closed -- null OID approach confirmed by Phillip Wood for backwards compatibility. Commit-message rewording and test hardening requests from Phillip Wood and Junio C Hamano have been addressed in v2, and Junio has confirmed the test closes the robustness gaps present in v1. Junio suggests the commit message for patch 2 could mention that `rollback_is_safe()` dies with "could not parse" on an empty abort-safety file during `git cherry-pick --skip`, and suggests a potential follow-up test covering `git reset --merge` then `git cherry-pick --skip` to exercise that path, but endorses the patch as-is.
