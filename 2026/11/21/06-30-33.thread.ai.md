Thread identity: single-patch bugfix series authored by Wonseok Oh (sent via GitGitGadget) targeting the sequencer subsystem, specifically `git cherry-pick` behavior on an unborn (orphan) branch.

Core problem or goal: when cherry-picking a sequence of commits onto an orphan branch where HEAD does not yet exist, `sequencer_pick_revisions()` in `sequencer.c` calls `repo_get_oid(r, "HEAD", &oid)`, which fails and leaves `oid` uninitialized; this garbage value was previously passed to `save_head()` and written to `.git/sequencer/head`, causing `git cherry-pick --abort` to fail with "Could not parse object" (or undefined behavior moving the branch pointer) instead of the intended "cannot abort from a branch yet to be born" error from `sequencer_rollback()`.

Current status: patch proposed and under review; no integration status reported.

Key technical details: the fix modifies `sequencer_pick_revisions()` in `sequencer.c` to explicitly clear `oid` to the null OID via `oidclr(&oid, r->hash_algo)` when `repo_get_oid()` fails for HEAD and the action is not `REPLAY_REVERT` (which keeps its own "can't revert as initial commit" error), ensuring `sequencer_rollback()` correctly detects the unborn-branch case. A regression test is added to `t/t3510-cherry-pick-sequence.sh` that creates an orphan branch, attempts a cherry-pick sequence, and verifies that `--abort` fails with "cannot abort from a branch yet to be born" while leaving HEAD unborn. Phillip Wood's review traces the uninitialized-variable introduction to commit `0f974e2124` (cherry-pick: allow to pick to unborn branches, 2016-06-06), notes that single-commit reverts on unborn branches are allowed via a separate code path from `7acaaac275` (2011) while multi-commit reverts are not, and observes that the unborn-branch check in `sequencer_rollback()` dates to `04d3d3cfc4` (2011) without documented rationale. He also identifies a state-representation inconsistency: `rollback_is_safe()` expects a null OID for unborn branches, but `update_abort_safety_file()` writes an empty file in that case.

Open questions and loose ends: Phillip Wood endorses the immediate fix as correct for the uninitialized-variable problem but flags several behavioral inconsistencies for future work (separate from this series): `sequencer_rollback()` currently refuses to abort when HEAD is unborn and leaves sequencer state intact, making it impossible to abort a multi-pick sequence started on an orphan branch; he proposes that future work could allow aborting cherry-picks on unborn branches, remove the unborn-branch check for multi-commit reverts, unify the null-OID vs empty-file state representation, or move the unborn-branch check to cover single picks as well.

Participant positions: Wonseok Oh is the author. Phillip Wood provided a substantive review endorsing the fix while tracing the root cause to historical commits and proposing future directions; no Reviewed-by, Acked-by, or objections recorded yet.
