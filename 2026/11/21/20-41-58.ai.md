This is a behavior-neutral refactoring patch, the first of five in v10 of Harald Nordgren's series that introduces `git branch --delete-integrated` to detect squash-merged and rebase-merged branches. It extracts the existing `branch.<name>.deleteMerged=false` opt-out check from `delete_merged_branches()` in `builtin/branch.c` into a new static helper named `opted_out_of_delete_merged()`, which accepts a `struct strbuf *` for the config key, the branch name, and the deletion flags. The helper performs the `repo_config_get_bool()` lookup for `branch.<name>.deletemerged`, prints the "Skipping" message to stderr unless `DELETE_BRANCH_QUIET` is set, and returns true when the branch is opted out. The call site in `delete_merged_branches()` now simply invokes this helper and adds the branch to the deletable set only when the helper returns false.

The motivation is purely preparatory: the upcoming `--delete-integrated` implementation in patches 3/5 through 5/5 will call the same `opted_out_of_delete_merged()` helper so that the new flag honors the same per-branch opt-out without duplicating the config-lookup and message-printing logic. The diff touches only `builtin/branch.c` with 20 insertions and 13 deletions, and the commit message explicitly states there is no change in behavior. Downstream discussion of this series should treat `opted_out_of_delete_merged()` as the single point where the `deleteMerged` config key is consulted for both `--delete-merged` and `--delete-integrated`, which is relevant to the still-open question about whether `branch.<name>.deleteMerged` is the right config key for the new flag or whether a more generic `deleteDone` key would be preferable.
