This is a **refactoring** patch -- the first of five in v10 of Harald Nordgren's series adding `git branch --delete-integrated`. It extracts the existing `branch.<name>.deleteMerged=false` opt-out check from `delete_merged_branches()` into a new static helper called `opted_out_of_delete_merged()` in `builtin/branch.c`, with no change in behavior. The purpose is to make that config lookup reusable when the later patches introduce `--delete-integrated`, which must honor the same opt-out.

The change is mechanical and clean: the helper takes a `strbuf` for the config key, the branch name, and the flags, performs the `repo_config_get_bool()` lookup, prints the "Skipping" message unless `DELETE_BRANCH_QUIET` is set, and returns whether the branch opted out. The original call site in `delete_merged_branches()` now simply calls this helper instead of inlining the logic.

Within the broader thread, this patch lays groundwork for the change-based deletion detection that dominates the series. As the cover letter and thread context note, v10 expands the series to detect branches whose changes -- but not tips -- have landed upstream via squash or rebase merges, and those new code paths will need the same `deleteMerged` opt-out protection that this refactoring now centralizes. The series remains under review with no integration status announced, and Junio has not yet weighed in on whether `deleteMerged` is the right config key for the new integrated-deletion mode.
