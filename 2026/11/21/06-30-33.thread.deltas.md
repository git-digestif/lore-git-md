# Thread deltas

## 2026/11/21

- [2026/11/21/06-30-33 by Wonseok Oh via GitGitGadget <gitgitgadget@gmail.com>] Wonseok Oh submitted a patch that clears the saved HEAD object ID to the null OID in `sequencer_pick_revisions()` when `repo_get_oid()` fails on an unborn branch, so that `git cherry-pick --abort` reports "cannot abort from a branch yet to be born" instead of erroring with "Could not parse object"; the patch also adds a test in `t/t3510-cherry-pick-sequence.sh` verifying this behavior.

## 2026/11/23

- [2026/11/23/14-32-38 by Phillip Wood <phillip.wood123@gmail.com>] Phillip Wood reviewed the patch and said it looks good as an immediate fix for the use of an uninitialized variable, while noting that the behavior of cherry-pick and revert onto an unborn branch does not make much sense.
- [2026/11/23/14-32-38 by Phillip Wood <phillip.wood123@gmail.com>] Phillip Wood traced the use of the uninitialized 'head' variable to commit 0f974e2124 (cherry-pick: allow to pick to unborn branches, 2016-06-06), noting that before that commit Git refused to cherry-pick onto an unborn branch and so did not use 'head' unless it was initialized.
- [2026/11/23/14-32-38 by Phillip Wood <phillip.wood123@gmail.com>] Phillip Wood observed that when sequencer_rollback() rejects an unborn branch it refuses to remove the sequencer state, making it impossible to abort a multi-pick cherry-pick started on an unborn branch, and that it is strange that Git tries to revert a single commit onto an unborn branch but not multiple commits because 7acaaac275 (revert: allow single-pick in the middle of cherry-pick sequence, 2011-12-10) inserted a separate code path for single picks before the unborn-branch check.
- [2026/11/23/14-32-38 by Phillip Wood <phillip.wood123@gmail.com>] Phillip Wood noted that the check for an unborn branch was introduced by 04d3d3cfc4 (revert: Save data for continuing after conflict resolution, 2011-08-04), whose commit message does not mention a reason, though he assumes it was to avoid having to support aborting to an unborn branch.
- [2026/11/23/14-32-38 by Phillip Wood <phillip.wood123@gmail.com>] Phillip Wood suggested that future changes could either remove the unborn-branch check when reverting multiple commits or move the check to cover single picks as well, and could allow the user to abort when cherry-picking onto an unborn branch, stating those changes do not need to be part of this series.
- [2026/11/23/14-32-38 by Phillip Wood <phillip.wood123@gmail.com>] Phillip Wood pointed out an inconsistency where rollback_is_safe() expects a null OID when picking onto an unborn branch but update_abort_safety_file() writes an empty file in that case, suggesting that an empty file is arguably a better representation because there is no OID.
