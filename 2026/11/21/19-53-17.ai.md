This is the second patch in a v3 two-patch refactoring series by Laveesh Bansal targeting `builtin/reflog.c`, specifically addressing duplicate processing in `git reflog expire`. While patch 1 mechanically unified the `--all` and named-ref loops into a single pass, this patch adds deduplication logic so that each reflog is expired at most once per invocation, fixing both cosmetic duplicate output and a potential data-loss edge case with `--updateref`.

The implementation introduces a `struct strset seen` (from `strmap.h`) in `cmd_reflog_expire()`. Before calling `refs_reflog_expire()` for any refname, the code checks `strset_add(&seen, refname)`; if the refname was already processed in this run, the iteration skips it. This ensures that invocations like `--all main refs/heads/main main` behave identically to `--all` alone, eliminating repeated "would prune" lines in `--verbose --dry-run` output. It also prevents the `--updateref` scenario where processing the same ref twice could move the ref tip after the first pass and then prune entries in the second pass that reference commits the new tip no longer reaches.

The author deliberately chose a `strset` over sorting the reflog names to preserve the existing expiration order, which matters because `--updateref` can move branch tips and "HEAD" is checked against every ref tip, meaning order-dependent pruning outcomes. The patch documents this as an intentional behavior change rather than a bug fix. Known limitations noted in the commit message: the deduplication does not catch names that resolve to the same reflog through worktree prefixes (e.g., "HEAD" vs "main-worktree/HEAD") or names that do not exist, which may still be processed or reported twice.

Tests are added to `t/t1410-reflog.sh`: one verifying that `--all` with redundant explicit names produces output identical to `--all` alone, and another constructing a `topic` branch scenario where `--updateref` with a duplicated ref name previously could lose reflog entries, now confirming the reflog remains intact and the ref points to the expected commit.

Within the thread, this v3 iteration resolves Patrick Steinhardt's v2 performance concern by using hash-based `strset` lookups instead of a sorted `string_list`, while maintaining output order. Junio C Hamano and Patrick Steinhardt have endorsed the general approach. The philosophical question of whether the `--updateref` behavior change constitutes a bug fix or a deliberate improvement remains unsettled in the visible discussion, though the commit message frames it as intentional and covers it with tests.
