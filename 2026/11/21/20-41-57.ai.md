This is a cover letter for v10 of a five-patch series adding a new `git branch --delete-integrated <pattern>` flag that detects branches whose changes were integrated upstream via squash or rebase merges, even when their tips are not reachable. Harald Nordgren expanded the series from four to five patches in this iteration, inserting a new commit that allows `--dry-run` to work with plain `-d` and `-D` deletion modes, addressing one of Junio C Hamano's open questions from the v9 review.

The most significant technical change in v10 is the replacement of `ll_merge()` with a direct call to `xdl_merge()` guarded by a new `mergeable_as_text()` helper, effectively making the squash-detection merge a plain text merge that ignores merge drivers set in `.gitattributes`. This prevents a malicious or misconfigured driver like `union` from leaving the upstream version unchanged while the branch's actual changes are nowhere present, which would have caused false-positive deletions. The change also eliminates the `repo_read_index()` call added in v6, since the index is no longer consulted for attribute resolution. Additionally, v10 fixes a bug where a branch that replaced a file or submodule with a directory was never found as landed, by adding `S_ISDIR(mode)` checks in `change_state_at()` and related path comparisons.

Internally, the series touches `builtin/branch.c`, `Documentation/git-branch.adoc`, `Documentation/config/branch.adoc`, and `t/t3200-branch.sh`. Key symbols include the `DELETE_BRANCH_INTEGRATED` flag, the `delete_integrated` strvec, the `landing_search` struct, and `find_landed_commits()` which walks upstream commits to match branch changes. The message-printing logic in `delete_branches()` has been refactored into a static `msg_templates[2][3]` array indexed by dry-run state, flattening the previous nested conditionals as Junio had suggested. The opt-out helper is now named `opted_out_of_delete_merged()`, and `branch_change` structs carry `base_oid`, `base_mode`, `upstream_oid`, and `state` fields to track whether each changed path is `CHANGE_MISSING`, `CHANGE_LANDED`, or `CHANGE_NEEDS_MERGE`. New tests cover `--dry-run` and `--quiet` behavior with `--delete-integrated`, the `branch.<name>.deleteMerged=false` opt-out for the new flag, the file-to-directory conversion case, and the merge-driver-ignoring behavior.

Relative to the thread state, v10 addresses several specific points Junio raised in his v9 review: the test coverage gaps for `--dry-run` combined with `--delete-integrated`, the `deleteMerged=false` opt-out interaction, and `--quiet` behavior are now tested in `t/t3200-branch.sh`; the `--dry-run` requirement has been relaxed to accept `-d`/`-D`; and the message template refactoring has been implemented. However, Junio's question about whether `branch.<name>.deleteMerged` is the right config key for `--delete-integrated` (versus a more generic `deleteDone`) remains unanswered in the cover letter, and the "npm update" false-positive mitigation via author checks or patch IDs is still not implemented. The series remains under review with no integration status announced.
