This thread is a standalone documentation patch from brian m. carlson warning users against using `http.extraHeader` to pass authentication credentials. The concern is that this approach exposes credentials to every server Git contacts or to other users on the system, and can break external tools like Git LFS that set their own `Authorization` headers, causing duplicate header conflicts. The patch instead recommends credential helpers as the secure alternative. The change touches three documentation files: `Documentation/config/http.adoc` (adding the warning and recommendation to the `http.extraHeader` entry), `Documentation/git.adoc` (replacing a specific mention with generic wording about sensitive variables), and `Documentation/gitfaq.adoc` (extending the existing advice against passwords in URLs).

The series has now reached v3. Version 2 had fixed a grammatical error from v1 that Junio C Hamano noted, and v3 incorporates his subsequent formatting requests: writing the config key as camelCase `http.extraHeader` throughout, wrapping the header name `Authorization` in backquotes, and adding a `linkgit:gitcredentials[7]` cross-reference. The substantive content remains unchanged from v2.
