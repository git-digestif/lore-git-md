This thread concerns a documentation patch from brian m. carlson (now at v2) warning users against using `http.extraheader` to pass authentication credentials, since doing so can leak credentials to every server contacted and conflict with external tools like Git LFS that add their own `Authorization` headers. The patch edits three files -- `Documentation/config/http.adoc`, `Documentation/git.adoc`, and `Documentation/gitfaq.adoc` -- to steer users toward credential helpers as the secure alternative.

Junio C Hamano has reviewed both v1 and v2. His v1 feedback was a single grammatical fix ("should not be used to pass credentials"), which brian incorporated in v2. In his review of v2, Junio offers only surface-level consistency suggestions: spell the config key consistently as camelCase `http.extraHeader`, consider wrapping the `Authorization` header name in monospaced backquotes, and add a `linkgit:gitcredentials[7]` cross-reference so readers can jump directly to the credential-helper documentation. None of these object to the substance of the security warning.

The patch remains under review with no Reviewed-by or Acked-by recorded yet. No substantive technical objections have been raised; the only open items are Junio's formatting and cross-reference suggestions, which brian may address in a v3.
