brian m. carlson has posted a standalone documentation patch warning users against using `http.extraheader` to pass authentication credentials, now at version 2 and under review on the mailing list. The patch edits three documentation files -- `Documentation/config/http.adoc`, `Documentation/git.adoc`, and `Documentation/gitfaq.adoc` -- to explain that the non-URL-qualified form of `http.extraheader` leaks credentials to every server Git contacts, that global or command-line usage exposes them to other users on the system, and that setting the `Authorization` header this way can break external tools like Git LFS by producing duplicate headers. It recommends credential helpers instead, noting they are "almost always more secure" and support Bearer tokens.

Junio C Hamano reviewed the initial version and requested a single grammatical fix -- changing "should not be to pass credentials" to "should not be used to pass credentials" -- which v2 incorporates. No substantive technical objections have been raised, and no Reviewed-by or Acked-by trailers have been added yet, so the patch remains open and awaiting further review or maintainer pickup.
