This is a test patch, the first of two in Orgad Shaneh's v2 series aligning `git fetch --prune-tags` with its documentation. It touches only `t/t5516-fetch-push.sh` and adds no production code; the behavioral change comes in the second patch of the series.

The patch strengthens the existing `test_force_fetch_tag` test, which previously only exercised a forced fetch via an explicit "+" refspec (`'+refs/tags/*:refs/tags/*'`). It now also covers `git fetch --force`, which was documented to clobber a changed tag but lacked test coverage. Both the lightweight-tag and annotated-tag variants run through the new sequence.

A new helper function `check_child1_tag` is introduced to verify not just that the fetch command exits successfully, but that the local tag object in the child repository was actually updated to match the remote. It does this by comparing `git rev-parse testTag` output between the parent and `../child1`. The test now moves the tag to `HEAD^` after the first successful forced fetch, confirms that a non-forced fetch fails as expected, then confirms that `--force` succeeds and updates the tag content.

From a thread-continuity perspective, this patch establishes the test infrastructure that patch 2 will rely on to verify the `--prune-tags` fix. The series remains open pending Junio C Hamano's ruling on whether the historical no-force behavior was intentional; this test-only change does not address that question directly but ensures the behavior is verifiable once the implementation lands.
