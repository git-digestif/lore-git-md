This is the implementation patch (2/2) of a v2 bugfix series aligning `git fetch --prune-tags` with its documentation. Orgad Shaneh modifies `builtin/fetch.c` to prepend a "+" force prefix to the implied `refs/tags/*:refs/tags/*` refspec whenever `--prune-tags` (or `fetch.pruneTags`) is active, so changed tags are clobbered rather than rejected with "would clobber existing tag". The change touches two `refspec_append` call sites: one for the remote-configured path and one for the command-line or non-config path, ensuring the force flag applies only to the auto-following tag refspec and not to explicit refspecs passed on the command line.

The patch updates `Documentation/git-fetch.adoc` and `Documentation/config/fetch.adoc` to quote the refspec as `+refs/tags/*:refs/tags/*`, reflecting the new behavior. Tests in `t/t5516-fetch-push.sh` add a case inside `test_force_fetch_tag` that creates a changed tag on the remote, confirms a plain `git fetch origin tag testTag` fails, then verifies `git fetch --prune --prune-tags origin` succeeds and updates the local tag object (checked via `check_child1_tag`), and finally confirms that with `fetch.pruneTags=true` configured, an explicit tag fetch still fails while a prune-tags fetch succeeds.

Old behavior: `--prune-tags` pruned missing tags but rejected changed tags because the implied refspec lacked the force flag. New behavior: the implied refspec carries "+", so changed tags are force-updated while missing tags are still pruned. Fetching a tag by name via explicit refspec remains unaffected and still requires `--force`.

The commit message traces the regression to commit 0bc8d71b99 (Git 2.20), which added tag-clobbering protection requiring "+" or `--force` but did not update the `--prune-tags` code path added earlier in 97716d21; Orgad Shaneh argues this was an oversight since 0bc8d71b99 does not mention `--prune-tags`. This v2 approach differs from v1 by scoping the force behavior to the auto-appended refspec only, avoiding the v1 bug where explicit refspecs were inadvertently forced when `fetch.pruneTags` was set. The series remains under review; Junio C Hamano has questioned historical intent and test sufficiency but has not yet ruled, and Ævar Arnfjörð Bjarmason (the original implementer of `--prune-tags`) has not yet weighed in.
