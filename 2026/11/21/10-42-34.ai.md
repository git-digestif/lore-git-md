This is the second patch in a two-part bugfix series from Aniket Gupta targeting the combined-diff machinery in `combine-diff.c`, based on `maint`. While the first patch fixed an `int` shift bug in `coalesce_lines()`, this patch handles merges that exceed the bit-mask capacity entirely: with `unsigned long` masks holding one bit per parent plus two marker bits, the practical limit is 62 parents on platforms where `long` is 64 bits, or 30 parents where `long` is 32 bits (notably Windows). Previously such merges produced undefined behavior -- missing hunks or wrong columns -- with no indication to the user.

The patch introduces a new `MAX_PATCH_PARENTS` macro defined as `bitsizeof(unsigned long) - 2` and modifies `diff_tree_combined()` to check the parent count when the output format includes `DIFF_FORMAT_PATCH`. If the number of parents exceeds this limit, the code calls `error()` with the message "cannot show a combined diff patch with more than %d parents" and sets a local `show_patch` flag to zero, which suppresses only the patch output for that specific merge while allowing the rest of the `git log --cc` run to continue. The raw format (`DIFF_FORMAT_RAW`), which does not use these masks, remains unaffected and is still shown. This deliberately avoids using `die()` so that a single huge octopus merge does not abort the entire history traversal.

Test coverage is added in `t/t4038-diff-combined.sh`. One test constructs a 63-parent merge setup and verifies that a 62-parent `git diff --cc` succeeds and marks the correct columns (guarded by the `LONG_IS_64BIT` prerequisite). Another test runs `git diff --cc --patch-with-raw` on a 63-parent merge and asserts that stderr contains the new error message, that the raw output (with 63 colons) is still present, and that no `diff --cc` patch header appears. The series has no recorded reviewer feedback yet and remains under review.
