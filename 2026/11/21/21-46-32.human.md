This is a test patch -- the first of two in Orgad Shaneh's v2 series addressing the `git fetch --prune-tags` inconsistency. While the series overall aims to change fetch behavior so that `--prune-tags` force-updates changed tags as the documentation promises, this particular commit only touches `t/t5516-fetch-push.sh` to strengthen the test coverage.

The patch adds a `check_child1_tag` helper that compares `git rev-parse` output between the parent and child repositories, ensuring that a forced fetch actually updates the local tag object rather than merely exiting successfully. It then extends the existing `test_force_fetch_tag` function to cover the `--force` flag in addition to the "+" refspec prefix, and re-tags between fetches to verify the content actually changes. This closes a gap where previous tests only checked that `git fetch` succeeded, not that the tag was updated.

Within the thread context, this patch sits alongside the behavioral change in patch 2/2 and reflects the series' broader goal of making `--prune-tags` reliably clobber changed tags. The strengthened tests are particularly relevant given Junio C Hamano's earlier concern about test sufficiency -- by verifying tag content rather than just exit status, this patch directly addresses that criticism. The work looks focused and well-motivated, though the series as a whole remains pending a substantive ruling from the maintainer on whether the current no-force behavior was an intentional design choice or an oversight.
