This is patch 1/3 of a feature series (v2) by Yoichi NAKAYAMA that makes `submodule.<name>.gitdir` paths relative for linked worktrees. The patch modifies `create_default_gitdir_config()` in `builtin/submodule--helper.c` to detect when the current repository is a linked worktree (via the new `get_current_worktree()` helper) and, if so, compute the `modules/` directory using `worktree_git_path()` followed by `relative_path()` against the worktree's path. This ensures the stored gitdir config value is a relative path like `../.git/worktrees/wt/modules/sub1` rather than an absolute path, so the setting remains valid if the worktree is moved (provided `worktree.useRelativePaths` is enabled). The v2 revision fixes a static-buffer lifetime issue by copying the result of `worktree_git_path()` into a local `strbuf` immediately.

The patch also updates the error message in the fallback case to suggest the correct relative path format, now printing `modules_dir` before the submodule name in the suggested `git config` command. A new test case in `t/t7425-submodule-gitdir-path-extension.sh` (titled "git submodule init make gitdir relative") creates a linked worktree, runs `git submodule init`, and asserts that `submodule.sub1.gitdir` and `submodule.sub2.gitdir` are set to the expected relative paths `../.git/worktrees/wt/modules/sub1` and `../.git/worktrees/wt/modules/sub2`.

For follow-up discussion, the key landmarks are the modified `create_default_gitdir_config()` function which now branches on `get_current_worktree()` and uses `worktree_git_path(wt, "modules/")` with `relative_path()` when the path is absolute, and the new test expectations in `t/t7425-submodule-gitdir-path-extension.sh` that verify relative gitdir storage. This patch is the first of three; patches 2 and 3 (not shown here) modify `repo_config_set_worktree_gently()` in `builtin/worktree.c` to route submodule settings to the worktree config when `extensions.worktreeConfig` is enabled, and adjust `git submodule init` via a helper called `submodule_git_dir_matches_current_worktree()` to handle pre-existing gitdir settings from the main repository config.
