This is the second patch in a v3 two-patch refactoring series for `git reflog expire`, adding deduplication so that each reflog is processed only once per run even when named multiple times. Building on patch 1 (which consolidated the `--all` and named-ref loops into a single pass), this patch introduces a `strset` called `seen` in `builtin/reflog.c` to track which refnames have already been expired; if a ref appears again -- whether as a literal duplicate like `main main`, via two spellings such as `main` and `refs/heads/main`, or covered by both `--all` and an explicit argument -- the second occurrence is skipped.

The change fixes two concrete problems: duplicate verbose output when a ref is named repeatedly, and a data-loss edge case with `--updateref` where processing the same reflog twice could prune entries that the first pass's ref update made unreachable. The author preserves the existing expiration order (important for `--updateref` interactions with `HEAD`) by using a hash-based `strset` rather than sorting, and documents that worktree-prefixed names like `main-worktree/HEAD` are not deduplicated against their unprefixed counterparts.

Tests in `t/t1410-reflog.sh` cover both the duplicate-output scenario and the `--updateref` case. The series remains under review with endorsements from Junio C Hamano and Patrick Steinhardt; the earlier philosophical question about whether the `--updateref` behavior is a bug or a deliberate improvement is documented as intentional in the commit message.
