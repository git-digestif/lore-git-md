Thread identity: cover letter for a two-patch bugfix series from Aniket Gupta <aniketgupta3001@gmail.com>, based on `maint`, addressing incorrect combined-diff output for merges with many parents. Thread type: patch series (bugfix).

Core problem or goal: `git log --cc` (and related combined-diff output) produces wrong results for merges with many parents, a long-standing bug reported by Sami Jawhar. With more than 32 parents, lines appear in the wrong columns and hunk headers disagree with their contents; with 64 parents, no hunks are shown at all.

Current status: series under review; no integration status claimed. Test suite passes and CI is green on Windows, macOS, and Linux per the author.

Key technical details: patch 1 fixes the root cause in `coalesce_lines()` in `combine-diff.c`, where the lost-line mask is recorded by setting a bit in the `parent_map` field of an `lline`. The bit was computed with `1 << parent`, an `int` shift that is undefined for shift counts of 32 or more; in practice the 33rd parent and beyond collided with another parent's bit. The fix changes the expression to `1UL << parent`, matching the `unsigned long` type of `parent_map` and consistent with the other masks in the file. Patch 2 introduces a `MAX_PATCH_PARENTS` macro defined as `bitsizeof(unsigned long) - 2` and modifies `diff_tree_combined()` to check the parent count when the output format includes `DIFF_FORMAT_PATCH`; if the number of parents exceeds this limit (62 parents on 64-bit `long` platforms, 30 on Windows where `long` is 32 bits), it calls `error()` with the message "cannot show a combined diff patch with more than %d parents" and sets a local `show_patch` flag to zero, suppressing only the patch output for that specific merge while allowing the rest of the `git log --cc` run to continue. The raw format (`DIFF_FORMAT_RAW`), which does not use these masks, remains unaffected and is still shown. This deliberately avoids using `die()` so that a single huge octopus merge does not abort the entire history traversal. Both patches touch `combine-diff.c` and add tests in `t/t4038-diff-combined.sh`. Tests for patch 1 construct a merge with forty parents where the second and the fortieth lose the same line, verifying the combined diff output marks exactly those two columns (guarded by the `LONG_IS_64BIT` prerequisite, skipped on platforms where `long` is not 64 bits). Tests for patch 2 construct a 63-parent merge setup and verify that a 62-parent `git diff --cc` succeeds and marks the correct columns (also `LONG_IS_64BIT`-guarded), and run `git diff --cc --patch-with-raw` on a 63-parent merge asserting that stderr contains the new error message, that the raw output (with 63 colons) is still present, and that no `diff --cc` patch header appears.
