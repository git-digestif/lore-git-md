A4-Tacks has sent a small feature patch adding bash shell completion for the `--filter=` option of `git clone`. The change touches only `contrib/completion/git-completion.bash`, adding a `--filter=*)` case inside `_git_clone()` that offers the standard partial-clone filter values `blob:none`, `blob:limit=`, and `sparse:oid=`, bringing `git clone` to parity with the completion `git fetch` already provides for the same option. The patch is four lines against base commit `0ffa3e35c7c82ab8d0de226149fb03b3f7674d05` and includes no test updates, which is typical for manually verified tooling under `contrib/`. The only open question the patch leaves for reviewers is whether the fixed list of filter specifiers is sufficient, or whether additional filters such as `tree:0` should be included and whether `blob:limit=` values should be generated dynamically.
