This is the first patch of a two-patch bugfix series correcting combined-diff output for merges with many parents. Aniket Gupta fixes a long-standing bug reported by Sami Jawhar where `git log --cc` and related combined-diff output produce wrong results once a merge has 33 or more parents: lines appear in the wrong columns and hunk headers disagree with their contents.

The root cause is in `coalesce_lines()` in `combine-diff.c`, where the code sets a bit in the `parent_map` mask using `1<<parent`. Because this is an `int` shift, shifting by 32 or more is undefined behavior, and in practice the bit for `parent - 32` gets set instead, causing the 33rd and later parents to collide with earlier ones. The fix changes this to `1UL << parent`, matching how the other masks in the file are computed, since `parent_map` is an `unsigned long`.

The patch adds a regression test in `t/t4038-diff-combined.sh` that constructs a merge with forty parents where the second and fortieth parents both lose the same line, then verifies that the combined diff correctly marks exactly those two columns. The test is skipped on platforms where `long` is not 64 bits, as the masks cannot represent that many parents there.

The series is based on `maint` because the bug is old, and this patch addresses the core shifting logic while the follow-up patch (2/2) handles merges that exceed the mask capacity entirely. The change is small and targeted -- one line of code plus test coverage -- and the author reports green CI across Windows, macOS, and Linux.
