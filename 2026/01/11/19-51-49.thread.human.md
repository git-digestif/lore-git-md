This thread tackles two related macOS compatibility issues, both now technically resolved but with one still facing architectural debate. The first, a two-patch series fixing an ISO-2022-JP iconv bug in utf8.c, is complete and ready for merging—it preserves conversion state during buffer growth and automatically detects Homebrew/MacPorts/Fink libiconv at build time.

The second, Curtis Allen Smith’s five-iteration patch series for a CRLF conversion size-trusting bug in read-cache.c, has reached a stable implementation that addresses prior feedback on test design and performance. The patch unconditionally checks for CRLF conversion when file sizes change during index refresh, preventing false positives in commands like `git status` or `git rebase` when external tools rewrite files with CRLF line endings. Benchmarks show negligible overhead in typical use, though Junio C Hamano’s latest review flags concerns about interference with Git’s racy Git logic and potential disruption of other performance trade-offs. Torsten Bögershausen’s recent suggestion to move the conversion check from `ie_modified()` to `ie_match_stat()`—while avoiding racy Git pitfalls—could reignite debate over where the fix belongs. Johannes Sixt’s fundamental objection remains unresolved: he argues the index’s recorded size is merely a stat cache and should be corrected during `git add`, not in refresh operations. Curtis has incorporated feedback from Phillip Wood, Junio, and others, but must now address Junio’s racy Git concerns and either justify the unconditional approach or revise the patch to be conditional. The series is technically sound and well-tested, but its architectural direction is still contested.
