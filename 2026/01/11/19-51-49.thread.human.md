This thread tackles two macOS-specific compatibility issues in Git, both now at different stages. The first, a two-patch series fixing an ISO-2022-JP iconv bug in `utf8.c`, is technically complete and ready for merging. It works around a buffer-state loss during conversion by detecting and handling libiconv variants on macOS.

The second, more contentious effort addresses a CRLF conversion bug in `read-cache.c` that causes `git status` to falsely report modifications when tools rewrite files with CRLF line endings after Git checks them out with LF endings. Curtis Smith has taken back ownership of this series after Torsten Bögershausen posted an independent v3, and plans to send a v4 that inlines the conversion-check logic directly into `ie_modified()`. His recent email clarifies that the index's recorded size is indeed a stat cache, but argues the real issue is `ie_modified()`'s assumption that size changes always mean content changes—a premise that fails when CRLF conversion is active. Benchmarks show the fix adds negligible overhead (~20ms per `git status` run on 10,000 files), but Johannes Sixt remains unconvinced, insisting the root cause lies in `git add` recording incorrect sizes rather than `git status` misinterpreting them. This architectural debate is the main blocker, with no resolution in sight yet. Junio Hamano has raised concerns about performance and clarity, but the collaboration process itself is now settled.
