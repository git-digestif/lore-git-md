This thread is about two related macOS compatibility fixes. The first, a two-patch series for an ISO-2022-JP iconv bug in utf8.c, is complete and ready for merging—it preserves internal state during buffer growth and automatically detects libiconv variants on macOS.

The second, an RFC patch from Torsten Bögershausen refining Curtis Allen Smith’s work, addresses a CRLF conversion bug in read-cache.c. This bug causes Git to misreport file modifications when tools rewrite files with CRLF line endings. The patch adds a `size_change_is_conclusive()` helper to verify conversion success, but Junio has raised concerns about its performance impact—specifically, the overhead of unconditional `would_convert_to_git()` calls in repositories without clean filters.

The utf8.c series is technically settled, but the read-cache.c patch is still under active discussion. Junio’s latest email shifts focus to process: he asks whether Torsten has taken over the series solo or is collaborating with Curtis, suggesting a `Co-authored-by` trailer if the latter. This procedural question must be resolved before the RFC can move forward. No technical changes have been requested in this update, but the performance trade-off and collaboration model remain open.
