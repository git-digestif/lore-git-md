This thread tackles two related but distinct macOS compatibility issues in Git’s character encoding and line-ending handling.

The first, a completed two-patch series, fixed a state-loss bug in ISO-2022-JP to UTF-8 conversion (utf8.c) by preserving iconv state during buffer growth. It’s technically ready for merging, with build-system detection for Homebrew/MacPorts/Fink libiconv already implemented.

The second, an RFC patch from Torsten Bögershausen, refines earlier work by Curtis Allen Smith to address a long-standing flaw in Git’s index comparison logic. The patch stops Git from blindly trusting file-size changes after CRLF conversion, which can falsely report modifications when tools rewrite files with CRLF line endings. Instead, Git now verifies content conversion when size changes occur, adding a 25-line helper function in read-cache.c and 45 lines of new tests. The change is unconditional and shifts some work from `git add` to `git status`, with a measured ~20ms overhead per file. While still in RFC form, it’s actively seeking feedback on commit-message clarity and the exact conditions for bypassing the size check. No reviews have landed yet, but the patch builds on established patterns for platform-specific fixes and complements the utf8.c series.
