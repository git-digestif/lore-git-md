This thread tackles two related macOS compatibility issues in Git, both now technically resolved but with one still facing architectural debate.

The first, a two-patch series fixing an ISO-2022-JP iconv bug in utf8.c, is complete and ready for merging. It implements a state-preserving workaround for buffer growth during conversion, with automatic build system detection for different libiconv variants.

The second, Curtis Allen Smith's patch addressing CRLF conversion size-trusting in read-cache.c, has reached its fourth iteration. This version inlines the fix directly into `ie_modified()`, removing the helper function from v3 while maintaining the same core logic: when file size changes and conversion is active, Git now verifies actual modification rather than trusting size differences alone. Curtis's benchmarks show negligible performance impact in most cases, with overhead becoming noticeable only when conversion is active and files are genuinely modified. The patch includes new tests covering CRLF rewrites and lone-CR edge cases.

The architectural debate remains the sticking point. Johannes Sixt continues to argue the fix should target `git add` to ensure correct size recording during index updates, while Curtis maintains the issue is a false positive in `git status`'s detection logic that should be corrected there. This fundamental disagreement about where the fix belongs could significantly alter the series' direction if the community sides with Sixt's view. Until that's resolved, the patch remains in RFC status despite being technically clean and ready for review.
