This thread tackles two related macOS compatibility issues: a fixed ISO-2022-JP iconv bug in utf8.c and an ongoing debate over a CRLF conversion bug in read-cache.c that causes Git to misreport file modifications. The utf8.c series is complete and ready for merging, while Curtis Allen Smith's read-cache.c series is now at v5, addressing feedback from Phillip Wood, Junio Hamano, Torsten Bögershausen, and Johannes Sixt.

The core dispute centers on where to place a conversion check to handle cases where clean filters or CRLF conversion alter file size without changing content. Curtis's v5 places the check in `ie_modified()`, targeting index-refresh commands like `git status`. Torsten now proposes moving it to `ie_match_stat()` to avoid interfering with Git's racy Git logic, which would affect a broader set of commands but reintroduces performance overhead. Junio has raised concerns about regressing the lstat() optimization that avoids unnecessary content comparisons, while Johannes Sixt argues the fix should target `git add` instead. Curtis's benchmarks show negligible overhead in realistic scenarios, but Junio's review suggests the optimization's removal is a non-starter.

The thread remains at an impasse, with three competing approaches and no clear consensus on balancing correctness, performance, and architectural purity. Torsten's proposal simplifies the code but doesn't resolve Sixt's objection or Junio's performance concerns, leaving the series' future direction uncertain.
