Core problem: macOS's ecosystem exhibits two distinct flaws during file processing:
1. In ISO-2022-JP to UTF-8 conversion (utf8.c), buffer growth during conversion loses internal state, corrupting output.
2. In CRLF conversion (read-cache.c), Git blindly trusts the reported post-conversion file size without verifying conversion success, causing commands that refresh the index (e.g., `git status`, `git rebase`, `git pull --rebase`, `git update-index --refresh`) to incorrectly report modifications when clean filters or CRLF conversion alter file size without changing content. The architectural debate now revolves around reconciling correctness, performance, racy Git avoidance, and the fundamental question of whether the index's recorded size should reflect the blob's size or serve as a stat information cache.
