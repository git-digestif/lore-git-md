This thread is about fixing a discrepancy between the documented and actual behavior of `git fetch --prune-tags`. The flag is supposed to both prune local tags that no longer exist on the remote *and* force-update tags that differ between local and remote, but the current implementation only does the former. Orgad Shaneh, the author of the two-patch series, argues this is likely an unintentional oversight from when the flag was introduced in 2018, before tag clobbering protection was added.

The series is currently stalled. Junio C Hamano, the maintainer, has raised questions about the original design intent and whether the test coverage is sufficient, but hasn’t revisited the thread since acknowledging he needed to refresh his memory. Orgad has responded to the test coverage feedback and maintains that the behavior was unintentional, but the next step depends on either Junio’s review or input from Ævar Arnfjörð Bjarmason, who originally implemented the flag. The patches themselves are straightforward: one adds test coverage (currently only checking exit status, not tag content), and the other modifies `builtin/fetch.c` to pass the `--force` flag when `--prune-tags` is active. The open question remains whether the code should be changed to match the docs or vice versa.
