This thread is about a bugfix for `git fetch --prune-tags`, which currently doesn’t match its documentation. The flag is supposed to both prune local tags not present on the remote *and* force-update tags that differ between local and remote, but the implementation only does the former. Orgad Shaneh proposed a two-patch series to align the code with the docs, adding test coverage and a one-line change to pass the `--force` flag when `--prune-tags` is used.

The discussion is stuck on whether the current behavior is intentional. Junio C Hamano, the maintainer, has raised concerns about historical intent and test coverage but hasn’t ruled on the substance yet. Orgad argues the mismatch was likely an oversight, pointing to the timing of the flag’s introduction and later tag clobbering protections. The original implementer, Ævar Arnfjörð Bjarmason, hasn’t weighed in, and Junio’s latest email just acknowledges the ping without advancing the discussion. The series remains at v1, awaiting either Junio’s refreshed perspective or input from Ævar to clarify the original design intent. No decisions have been made, and the open questions—whether to change the code, the docs, or both—remain unresolved.
