This thread is about a two-patch bugfix series from Orgad Shaneh that addresses an inconsistency between the documented and actual behavior of `git fetch --prune-tags`. The documentation claims the flag both prunes local tags not present on the remote *and* force-updates tags that differ between local and remote, but the current implementation only does the former. Orgad’s patches add test coverage and modify `builtin/fetch.c` to pass the `--force` flag to tag-fetching logic when `--prune-tags` is active, aligning the code with the docs.

The discussion has stalled on whether the current behavior (no force-update) is intentional or an oversight. Orgad argues it’s likely the latter, pointing to the timing of the flag’s introduction relative to tag clobbering protection. Junio C Hamano, the maintainer, has raised concerns about historical intent and test coverage but hasn’t yet ruled on the substance. The latest email is a gentle ping from Orgad, clarifying that the new test checks tag *replacement* (not just deletion) and offering to expand it if needed. The patch itself is minimal, but the thread awaits input from Ævar Arnfjörð Bjarmason, who originally implemented `--prune-tags`, to resolve the design intent question. No other participants have weighed in.
