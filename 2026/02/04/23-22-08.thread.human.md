This thread is about Mike Hommey’s patch series (now at v5) that moves Git’s Rust code from `src/` into a dedicated `rust/` subdirectory. The patch itself is technically complete—it applies cleanly, builds correctly, and addresses all prior feedback—but its future is now in question.

Junio, who had previously queued the patch for `next`, has stepped back to ask whether the project actually wants this reorganization at all. The patch has sat idle for over a month with no new comments, and aside from Mike, no one has shown strong enthusiasm for it. Junio ties this lack of momentum to the unresolved discussion about how Git 3.0’s mandatory Rust components will affect downstream projects that vendor Git’s C code while excluding its Rust components. Mike’s proposed solution—publishing the `gitcore` crate to crates.io—remains on the table, but the broader uncertainty seems to be dampening interest in the reorganization itself.

The patch is still in `next` for now, but Junio’s latest email suggests he may drop it unless someone steps forward to advocate for it. There are no remaining technical issues; this is purely a question of whether the project sees enough value in the change to proceed.
