This thread is about reorganizing Git’s Rust code into a dedicated `rust/` subdirectory. Mike Hommey has driven the effort through five patch versions, addressing all mechanical feedback—including a build-breaking meson.build error in v3 and a CI script path issue in v4. The latest version (v5) updates `ci/run-rust-checks.sh` to look for Rust files in their new location, resolving the last technical blocker. The reorganization itself is uncontroversial; it improves project structure by preventing Cargo from treating the entire Git repository as a single crate, which helps downstream projects that vendor Git’s C code while excluding its Rust components.

Junio C Hamano and Tuomas Ahola provided surface-level reviews on earlier versions, flagging presentational and mechanical issues (commit message style, duplicate entries, and the meson.build error) that Mike has since fixed. The only remaining discussion is forward-looking: how to handle downstream compatibility when Git 3.0 makes Rust components mandatory. Mike proposes publishing the `gitcore` crate to crates.io under the Git project’s namespace, but this is a separate conversation from the patch itself. With the CI fix now in place, the series appears ready for integration.
