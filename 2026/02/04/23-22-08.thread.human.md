This thread is about Mike Hommey’s patch series (now at v3) that moves Git’s experimental Rust code from `src/` to a dedicated `rust/` subdirectory. The goal is to clean up the project structure by separating C and Rust components, which previously shared the top-level directory and caused confusion with tools like Cargo.

The series has reached its third version, addressing mechanical path updates and build system integration. Junio C Hamano’s recent review flagged four surface-level issues—commit message phrasing, duplicate `.gitignore` entries, redundant `RUST_SOURCES` in the Makefile, and a mismatch between `.gitignore` and the `clean` target—that need fixing before the patch can proceed. These are minor corrections and don’t challenge the technical direction.

However, brian m. carlson’s latest email raises a forward-compatibility concern: the current reorganization helps downstream projects like git-cinnabar exclude Git’s Rust code when vendoring its C code as a submodule, but this workaround may break when Git 3.0 makes Rust components mandatory. The question is whether this is a temporary fix or if there’s a longer-term plan for handling mixed C/Rust dependencies. This isn’t a blocker for the current patch but could become a pain point for external consumers.

Mike is driving the implementation, Junio’s feedback is purely mechanical, and brian’s concern is substantive but not an objection—just a heads-up about future friction. The series itself is uncontroversial, but the broader Rustification effort may need to revisit this issue down the road.
