This thread is about Mike Hommey’s fourth iteration of a patch series that moves Git’s experimental Rust code from `src/` to a dedicated `rust/` subdirectory. The goal is to improve project structure in Git’s mixed C/Rust codebase while keeping the build working and supporting downstream projects that vendor Git’s C code but exclude its Rust components.

The series has addressed all prior mechanical feedback, including a build-breaking `meson.build` error that led Junio to temporarily drop the topic from the `seen` integration branch. With v4, the reorganization itself is technically sound, but Junio now reports a CI breakage: the `ci/run-rust-checks.sh` script still expects Rust files in their original `src/` location, causing the checks to fail. This is a substantive issue that must be fixed before the series can proceed, though it doesn’t challenge the reorganization’s merits. The long-term question of how to handle downstream projects once Git 3.0 makes Rust components mandatory remains unresolved, but Mike has proposed publishing the `gitcore` crate to crates.io as a potential solution.

Key participants include Mike (driving the implementation), Junio (maintainer, who flagged the CI issue), brian m. carlson (who raised forward-compatibility concerns), and Tuomas Ahola (who previously caught a build-breaking error). The series is now waiting on Mike to address the CI breakage, after which it should be ready for re-integration into `seen`.
