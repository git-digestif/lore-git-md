This thread is about reorganizing Git’s Rust infrastructure, moving all Rust code from the top-level `src/` directory into a dedicated `rust/` subdirectory. Mike Hommey has driven the effort through five patch versions, addressing all mechanical, CI, and integration feedback along the way. The latest version (v5) applies cleanly on Git 2.56-rc1, updates the build system (Makefile, meson.build, and CI scripts) to reference the new paths, and preserves all Rust functionality while improving project structure clarity.

Junio reviewed the patch and confirmed it is ready for integration, queuing it for the `next` branch. The only remaining stylistic question—whether to use `CARGO_MANIFEST_DIR` or `--manifest-path`—was left unresolved but is not a blocker. The reorganization also supports downstream projects that vendor Git’s C code while excluding its Rust components, a key concern for Git 3.0’s mandatory Rust components. Mike has proposed publishing the `gitcore` crate to crates.io as a long-term solution for handling mixed C/Rust dependencies, but that discussion remains separate from this patch.

No substantive objections remain, and the patch is effectively complete. The thread now awaits graduation from `next` to `master`.
