This thread is about reorganizing Git’s experimental Rust code, moving it from `src/` to a dedicated `rust/` subdirectory to improve project structure. Mike Hommey has posted the fourth version of the patch series, which now addresses all mechanical feedback from earlier rounds—fixing duplicate entries, updating the `Makefile` clean target, and correcting the `meson.build` path that previously broke the build.

The series itself is technically ready; no substantive objections to the reorganization remain. The only open question is how to handle long-term forward-compatibility for downstream projects that vendor Git’s C code but exclude its Rust components, especially once Git 3.0 makes Rust mandatory. Mike has proposed publishing the `gitcore` crate to crates.io as a solution, but this hasn’t been settled yet.

Junio temporarily pulled the series from the `seen` integration branch after CI builds started failing due to the `meson.build` error, but that’s now resolved in v4. The series is back on track for review, with no further technical blockers in sight.
