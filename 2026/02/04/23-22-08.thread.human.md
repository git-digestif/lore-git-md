This thread is about reorganizing Git's experimental Rust code into a dedicated `rust/` subdirectory. Mike Hommey has posted the third version of a patch that moves all Rust-related files (Cargo.toml, build scripts, and source files) from `src/` to `rust/` and updates the build system accordingly. The patch is now focused on project hygiene—cleaning up the mixed-language structure—rather than addressing earlier technical constraints like mrustc compatibility, which have since been resolved.

The implementation is straightforward: the patch updates the Makefile and meson.build to reference the new locations, adjusts `.gitignore` for Rust build artifacts, and fixes a minor duplicate entry in `RUST_SOURCES`. The changes are mechanical but thorough, ensuring all existing functionality is preserved while establishing a clearer structure for future Rust development. The git-cinnabar build issues, which were a concern in earlier discussions, are explicitly deferred for separate resolution.

The patch has evolved from an RFC to a concrete implementation, with the earlier mrustc compatibility questions now settled. The main open question is whether the community will accept the move based on project hygiene merits alone. So far, Mike has driven the effort forward, and the patch appears ready for review, though broader feedback on the reorganization itself may still emerge.
