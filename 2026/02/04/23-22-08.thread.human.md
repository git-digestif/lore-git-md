This thread is about reorganizing Git's Rust infrastructure into a dedicated `rust/` subdirectory. Mike Hommey has posted the third version of the patch series, which moves all Rust files (including `Cargo.toml`, `lib.rs`, and build scripts) from the top level to `rust/` while updating the build system to match. The series has evolved from an RFC discussion to a concrete implementation, with earlier technical concerns—like mrustc compatibility and git-cinnabar build issues—either resolved or deferred.

Junio C Hamano recently reviewed v3 and provided feedback focused entirely on mechanical and presentational issues: the commit message should use imperative mood, `.gitignore` entries for `/target/` and `/Cargo.lock` should be cleaned up rather than duplicated, and the Makefile contains redundant entries for `lib.rs` and `varint.rs`. He also noted a contradiction between the `clean` target (which still references `Cargo.lock` at the top level) and the new `.gitignore` rules (which expect it in `rust/`). These are all straightforward fixes that don’t challenge the patch’s direction. No substantive technical objections have been raised in this version, and the patch is now primarily about project hygiene rather than technical constraints.

The series is at v3, with the current version addressing a duplicate `RUST_SOURCES` entry introduced in v2. The build system updates (Makefile, meson.build, and `.gitignore`) are complete and functional, and the patch preserves all Rust functionality while improving codebase organization. The main open question is whether the community will accept the move based on its merits now that technical blockers are resolved. No new reviewer positions have emerged yet, but earlier concerns from brian m. carlson appear to be addressed. Follow-up work, such as Rust-specific CI or documentation updates, may be needed but is separate from this patch.
