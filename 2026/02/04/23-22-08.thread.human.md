This thread is about Mike Hommey’s patch series (now at v5) to reorganize Git’s Rust infrastructure by moving files from `src/` to a dedicated `rust/` subdirectory. The goal is to improve project structure clarity in Git’s mixed C/Rust codebase while ensuring build functionality remains intact and supporting downstream projects that vendor Git’s C code but exclude its Rust components.

The patch itself is technically complete, applies cleanly on Git 2.56-rc1, and addresses all prior feedback, including mechanical and CI-related issues. Junio reviewed it, queued it for `next`, and even raised a minor stylistic question about build mechanics, but he has since expressed doubt about whether the project wants the change at all. The primary obstacle now is a lack of broader enthusiasm, compounded by unresolved questions about how to handle Git 3.0’s mandatory Rust components and their impact on downstream projects. Mike has proposed publishing the `gitcore` crate to crates.io as a long-term solution, but this discussion remains separate from the reorganization patch.

Mike’s latest reply reaffirms his personal interest in the reorganization, stating he’d prefer not to maintain a fork just to move the Rust files. However, no other participants have stepped forward to advocate for the patch, and Junio’s tone suggests it may be dropped unless someone else voices support. The patch’s future is now uncertain, despite its technical readiness.
