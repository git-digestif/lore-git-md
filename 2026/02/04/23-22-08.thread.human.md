This thread is about Mike Hommey’s patch series (now at v5) that reorganizes Git’s Rust infrastructure by moving all Rust code from `src/` to a dedicated `rust/` subdirectory. The goal is to improve project structure clarity in Git’s mixed C/Rust codebase while ensuring build functionality remains intact and supporting downstream projects that vendor Git’s C code but exclude its Rust components.

The patch has progressed through five iterations, addressing all prior feedback, including a CI breakage in v4. Junio C Hamano’s latest review confirms the patch is technically complete and ready for integration. He verified the mechanical changes—updates to the Makefile, meson.build, and CI script—and noted only a minor stylistic question about `CARGO_MANIFEST_DIR` usage, which is not a blocker. The patch is now queued for `next` unless a last-minute technical concern arises.

The only remaining discussion is about long-term forward-compatibility for downstream projects when Git 3.0 makes Rust components mandatory. Mike proposes publishing the `gitcore` crate to crates.io as a solution, but this is orthogonal to the reorganization patch itself. No substantive objections to the patch remain, and the series is effectively ready to merge.
