This is a brief update in the ongoing bug report about the `git apply --check` crash. The author (Tanga Joris) confirms that the crash is reproducible on the current `master` branch and has identified the root cause: a blank line after the `diff --git` line in the new-file section of the patch. The original patch that triggered the issue was generated by an LLM, which explains the unusual formatting that exposed the bug.

Tanga Joris is actively working on a fix, which suggests this is a serious and well-understood issue. The bug remains tied to the `apply.c` subsystem and the `check_preimage` function, where the assertion failure (`patch->is_new <= 0`) occurs. The blank line in the patch header appears to be the specific trigger, though earlier discussion suggested the issue was sensitive to the ordering of `--- /dev/null` and `new file mode` lines. This new detail narrows the scope further and may help in crafting a targeted fix.

The thread is now focused on resolution rather than diagnosis. No patch has been posted yet, but the author’s statement indicates one is forthcoming. The issue is worth attention for anyone relying on `git apply --check` workflows, as the crash is deterministic and affects core functionality.
