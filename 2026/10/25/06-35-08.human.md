This is the final patch in Tyler Cipriani’s four-part series to fix the performance regression in Git’s `test-lint` target. The patch teaches `t/chainlint.pl` to run greplint checks during its own tokenization pass, eliminating duplicate file I/O and parsing work. By adding a `--greplint` option to `chainlint.pl`, the patch consolidates the two lint checks into a single invocation, leveraging parallel execution to cut `test-lint` runtime from ~25 seconds to ~6 seconds for five consecutive runs on a 16-core machine.

The changes are confined to `t/Makefile` and `t/chainlint.pl`. The Makefile is updated to introduce a new `test-chainlint-greplint` target that replaces the standalone `test-greplint` when `GIT_TEST_CHAIN_LINT` is enabled, while preserving the old behavior for users who disable chainlint. The `chainlint.pl` script is modified to load the shared `lib-greplint.pl` library (introduced in patch 3/4) and invoke `GrepLintParser::check_tokens()` during its parsing pass. The patch also ensures both lint checks operate on the same set of test files, expanding coverage for both tools.

Performance data in the commit message confirms the impact: a single `test-lint` run drops from ~4.5 seconds to under 1 second on the author’s 16-core laptop. The patch is well-motivated, addressing a workflow bottleneck reported by Junio and incorporating an optimization suggested by Peff. No behavior changes to Git itself are introduced, and the series has been tested without regressions. This looks like a clean, uncontroversial fix that should land quickly if no edge cases emerge.
