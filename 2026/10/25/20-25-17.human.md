This is the first patch in Harald Nordgren’s v11 series introducing `remote.<name>.refmap` for a matching-inspired fetch mode. It adds the configuration knob itself, mirroring `remote.<name>.fetch` but only providing a default for `--refmap` when there is something explicit to fetch (command-line refspecs or `remote.<name>.fetch`). The patch also updates `remote_find_tracking()` to fall back to `remote->refmap` when `remote->fetch` is either empty or contains no matching refspec for the given query, ensuring that refs fetched via refmap are correctly tracked for `@{upstream}` and similar operations. Two new tests verify that negative refspecs in `remote.<name>.fetch` continue to exclude refs as expected.

The implementation is clean and uncontroversial: it reuses existing refspec machinery, introduces no new technical debt, and preserves backward compatibility. When both `remote.<name>.fetch` and `remote.<name>.refmap` are configured, the former takes precedence, avoiding any ambiguity. The documentation updates are precise and include concrete examples. This patch is ready for `next` and is part of a series that has already addressed all prior feedback.
