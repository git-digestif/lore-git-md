This is a feature patch series (v11 of 5 patches) implementing a "matching-inspired" fetch mode for Git. The series introduces `remote.<name>.refmap` configuration and a `--limited-fetch` flag for `git remote add`, with the goal of making `git fetch` operations faster and more targeted in shallow repositories by dynamically fetching only branches tracked by local branches at the remote being fetched.

The v11 revision addresses all prior feedback and is ready for merging to `next`. Key improvements in this version include: (1) `remote_find_tracking()` now correctly falls back to `remote.<name>.refmap` when `remote.<name>.fetch` doesn't match, with tests for negative refspec exclusion; (2) the helper functions now use `strvec` instead of `string_list` for efficiency, take the output parameter last, and treat the `remote` parameter as `const`; (3) the `followRemoteHEAD` lookup is deduplicated; (4) commit messages and documentation are clearer, with concrete examples and precise behavior descriptions; and (5) `use_limited_fetch` is now a `bool` instead of an `int`.

The series touches `remote.c`/`remote.h` (refmap parsing, dynamic branch enumeration, and fallback logic), `builtin/fetch.c` (refmap integration and dynamic branch inference), `builtin/remote.c` (`--limited-fetch` flag and shallow-repository default), documentation (configuration and behavior updates), and tests (14 new tests covering edge cases and backward compatibility). The implementation reuses existing logic and configuration machinery, introduces no new technical debt, and resolves the merge conflict with Junio’s `ch/fetch-followremotehead-lazy-validation` topic.

The new behavior is opt-in via `--limited-fetch` and automatically enabled for shallow repositories, avoiding surprises for users who rely on the current behavior.
