This is the fourth patch in Harald Nordgren’s v11 series introducing a "matching-inspired" fetch mode for Git. The patch adds a `--limited-fetch` flag to `git remote add`, which configures the remote to use `remote.<name>.refmap` instead of the traditional wildcard `remote.<name>.fetch` refspec. This enables the dynamic branch inference logic introduced earlier in the series, ensuring that `git fetch` only retrieves branches already tracked by local branches at the remote.

The implementation updates `builtin/remote.c` to add the new flag, which is rejected when combined with `-t/--track` or `--mirror` (since those options already specify explicit fetch behavior). The flag sets `remote.<name>.refmap` to `+refs/heads/*:refs/remotes/<name>/*` via `repo_config_set()`, while leaving `remote.<name>.fetch` unset. Documentation in `git-remote.adoc` is updated to explain the new option, and four new tests in `t/t5505-remote.sh` verify the flag’s behavior, conflict with `-t`, and absence of interference with existing functionality.

The patch is uncontroversial and integrates cleanly with the rest of the series. It reuses the existing configuration machinery and avoids introducing new technical debt. The only edge case—rejecting the flag when combined with conflicting options—is handled explicitly. This patch, along with the rest of the v11 series, is queued in `next` and ready for merging.
