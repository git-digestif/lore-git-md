This is the second patch in Tyler Cipriani’s four-patch series addressing the `test-grep-lint` performance regression. It incorporates Jeff King’s optimization into the series by adding an early exit in `t/greplint.pl` for test bodies that do not contain the word "grep". The change is simple: before parsing the test body, the script checks for the presence of "grep" and skips further processing if none is found. The commit message reports this cuts the runtime of `make test-grep-lint` by roughly half, a meaningful improvement for a developer workflow bottleneck.

The patch itself is minimal and self-contained, touching only `t/greplint.pl`. The rationale is clearly explained in the code comment: while it is technically possible to split "grep" across lines in a way that would evade the check, the scenario is deemed too unlikely to justify the cost of full parsing. This aligns with the series’ overall goal of eliminating redundant work without disrupting functionality.

This is a straightforward performance win with no behavioral changes. The patch is uncontroversial and likely to be merged as part of the series.
