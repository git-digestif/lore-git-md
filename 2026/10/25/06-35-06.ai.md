This is the second patch in Tyler Cipriani’s four-patch series optimizing Git’s `test-lint` infrastructure. It incorporates Jeff King’s (Peff) earlier optimization into the series, adding an early exit in `t/greplint.pl` to skip parsing test bodies that do not contain the word "grep". The change is a targeted performance tweak: by avoiding unnecessary parsing of files that cannot possibly trigger the lint check, it cuts the runtime of `make test-grep-lint` by roughly half (from ~6.5 s to ~3.2 s per run on the author’s machine).

The implementation is straightforward and conservative. The new check is a simple regex match (`$body =~ /grep/`) inserted before the full parse, with a comment acknowledging the theoretical edge case of split-string "grep" (e.g., `gr\nep`) but dismissing it as too obscure to warrant handling. This aligns with Peff’s original suggestion and the series’ goal of eliminating redundant work without over-engineering. The patch touches only `t/greplint.pl`, adding nine lines of code, and does not alter behavior—it merely short-circuits the parsing loop when no "grep" is present.

This patch is a prerequisite for the later restructuring in the series, which consolidates parsing effort between `chainlint.pl` and `greplint.pl`. By reducing the cost of standalone `greplint.pl` runs, it ensures the tool remains viable for workflows that disable `chainlint` (via `GIT_TEST_CHAIN_LINT=0`), while also paving the way for the shared parsing logic introduced in patch 3/4. The performance data in the commit message is clear and reproducible, and the optimization is uncontroversial—no objections or edge cases have been raised in the thread so far.

The patch is part of a well-motivated effort to address a real developer workflow bottleneck reported by Junio. It is narrowly scoped, thoroughly tested, and unlikely to introduce regressions. The series as a whole is shaping up to be a clean, incremental improvement to Git’s test infrastructure.
