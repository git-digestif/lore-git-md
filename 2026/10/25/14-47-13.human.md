This is a **substantive review** of Jasper Mayone’s `--branch` filtering patch for `git worktree list`. Phillip Wood engages deeply with the implementation, identifying both design-level concerns and code-level duplication.

The review centers on two main points. First, Phillip observes that the new `checked_out_branch()` helper largely duplicates logic already present in `branch.c:prepare_checked_out_branches()`. He suggests refactoring that function to expose a reusable `branch_find_checkout(const char *branch)` API, which would let `git worktree list --branch` simply look up the branch in a shared hashmap instead of reimplementing the rebase/bisect detection. This would clean up the code and avoid subtle divergence between the two code paths.

Second, Phillip raises a UX issue: when filtering worktrees, the output no longer indicates which one is the main worktree. Since `git worktree remove` refuses to delete the main worktree, scripts that want to prune merged worktrees need a way to skip it. He proposes adding an `is-main-worktree true` field to the porcelain output when the main worktree is included in the filtered list.

The review also questions the current error handling: syntactically invalid branch names are rejected, but non-existent branches are silently ignored. Phillip asks whether this asymmetry is intentional.

Overall, the feedback is constructive and technical, targeting both code hygiene and scriptability. The patch is not yet in any integration branch, and these suggestions would likely need to be addressed before it moves forward.
