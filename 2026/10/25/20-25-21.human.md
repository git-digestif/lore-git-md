This is the final patch in the v11 series introducing a "matching-inspired" fetch mode for Git. It makes `--limited-fetch` the default when adding a remote in a shallow repository, ensuring that `git fetch` operations remain fast and targeted by avoiding the negotiation of history for all remote branches.

The patch updates `builtin/remote.c` to check whether the repository is shallow (using the existing `is_repository_shallow()` helper) when the `limited_fetch` flag is unset, defaulting to `--limited-fetch` unless explicitly disabled with `--no-limited-fetch`. The documentation in `git-remote.adoc` is updated to explain the new default behavior, clarifying that it applies to all shallow repositories, not just single-branch clones. Four new tests in `t/t5505-remote.sh` verify that the default works as intended: `-t/--track` still sets an explicit refspec, full repositories retain the wildcard refspec, shallow repositories default to `--limited-fetch`, and `--no-limited-fetch` overrides the default.

The implementation is uncontroversial and reuses existing logic without introducing new technical debt. The series as a whole is queued in `next` and ready for merging, with all prior feedback addressed and no open technical or procedural blockers. This patch completes the feature by ensuring shallow repositories automatically benefit from the performance improvements without requiring manual configuration.
