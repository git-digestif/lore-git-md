This is the third patch in the v11 series introducing "matching-inspired" fetch mode for Git. It implements the core dynamic branch inference logic: when a remote has a `remote.<name>.refmap` configured but no `remote.<name>.fetch` refspec, `git fetch` now infers which branches to fetch by enumerating local branches whose `@{upstream}` points to that remote.

The patch adds the `branches_tracking_remote()` helper in `remote.c`, which iterates over all local branches and collects the source refs of those tracking the target remote. This logic is integrated into `get_ref_map()` in `builtin/fetch.c`, where it constructs a dynamic refspec from the inferred branches. The `do_fetch()` function is updated to populate `transport_ls_refs_options.ref_prefixes` with these inferred branches, ensuring the transport layer only requests the necessary refs. The control flow in `do_fetch()` is reorganized to handle the new case where neither command-line refspecs nor `remote.<name>.fetch` are present, but a refmap is configured.

The implementation is clean and efficient: it reuses the existing `collect_upstream_from_remote()` helper (introduced in Patch 2/5) to avoid code duplication, and the new `branches_tracking_remote()` helper is designed for reuse in other contexts. The patch includes 119 lines of new tests in `t/t5586-fetch-refmap.sh`, covering edge cases like bare fetches (which fetch nothing until a branch is tracked), multiple branches tracking the same upstream (which avoids duplicate fetches), and branches tracking different remotes (which are correctly excluded). The documentation in `config/remote.adoc` and `fetch-options.adoc` is updated to explain the new behavior with concrete examples.

This patch is uncontroversial and addresses all prior feedback. The dynamic branch inference logic is well-motivated and integrates smoothly with the existing refmap machinery. The tests are thorough and lock down the expected behavior, including backward compatibility. The series as a whole is queued in `next` and ready for merging.
