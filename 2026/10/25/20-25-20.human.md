This is the fourth patch in Harald Nordgren’s v11 series introducing a "matching-inspired" fetch mode for Git. The patch adds a `--limited-fetch` flag to `git remote add`, which configures the remote to use `remote.<name>.refmap` instead of the traditional wildcard `remote.<name>.fetch` refspec. This ensures that `git fetch <name>` only fetches branches already tracked by local branches at the remote, avoiding the overhead of negotiating history for all remote branches.

The implementation is straightforward: the flag is rejected when combined with `-t/--track` or `--mirror` (since those options already specify explicit fetch behavior), and it sets up `remote.<name>.refmap` with a wildcard mapping (e.g., `+refs/heads/*:refs/remotes/<name>/*`) when no branches are explicitly tracked. The patch updates `builtin/remote.c` to handle the new flag, adds documentation to `git-remote.adoc`, and includes two new tests in `t/t5505-remote.sh` to verify the flag’s behavior and conflict with `-t`.

This patch is uncontroversial and well-motivated. The `--limited-fetch` flag provides a clear, opt-in way to enable the new fetch mode, complementing the automatic default for shallow repositories introduced in the final patch of the series. The implementation reuses existing configuration machinery and avoids introducing new technical debt. The tests cover the key edge cases, and the documentation is clear and concise. The patch is part of a series that is already queued in `next`, with all prior feedback addressed.
