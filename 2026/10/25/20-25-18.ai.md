This is the second patch in the v11 series introducing a "matching-inspired" fetch mode for Git. It extracts the existing logic that checks whether the current branch builds on a remote and fetches its upstream into a reusable helper function, `collect_upstream_from_remote()`, in preparation for reusing the same logic for branches other than the current one in later patches.

The patch moves the inlined code from `do_fetch()` in `builtin/fetch.c` into a new function in `remote.c` and declares it in `remote.h`. The helper takes a `struct repository *`, a `const struct remote *`, an optional branch name (NULL means the current branch), and a `strvec *` to populate with upstream refs. The function checks if the branch has an upstream configured on the given remote and, if so, adds the upstream refs to the provided `strvec`. The NULL-check for the branch is preserved via `repo_branch_get(repo, refname)`, addressing Junio’s earlier review requirement.

The change is purely refactoring and introduces no behavior changes. The extracted logic is identical to the original, and the helper is immediately used in `do_fetch()` to replace the inlined code. The commit message explains the motivation clearly: the helper will be reused in Patch 3/5 to implement dynamic branch enumeration for the new "matching-inspired" fetch mode. The patch is uncontroversial and aligns with D. Ben Knoble’s accepted suggestions for `strvec` usage, `const` correctness, and output parameters last.

Files touched: `builtin/fetch.c`, `remote.c`, and `remote.h`. The patch is part of a series that is ready for merging to `next`, with all prior feedback addressed and no remaining technical or procedural blockers. The new helper function, `collect_upstream_from_remote()`, will be a key building block for the dynamic branch inference logic introduced in the next patch.
