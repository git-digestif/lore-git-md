This is the final patch in Tyler Cipriani’s four-patch series optimizing Git’s `test-lint` infrastructure. It teaches `t/chainlint.pl` to run greplint checks during its own tokenization pass by adding a `--greplint` option, eliminating duplicate file I/O and parsing work. The patch updates `t/Makefile` to introduce a new `test-chainlint-greplint` target that becomes the default for `test-lint` when `GIT_TEST_CHAIN_LINT` is enabled, while preserving the standalone `test-greplint` target for cases where chainlint is disabled.

The key change is in `chainlint.pl`, which now loads `lib-greplint.pl` and invokes `GrepLintParser::check_tokens()` on each test body after parsing. The Makefile is updated to ensure both lint checks run on the same expanded set of test files (including interop tests), and the new target uses `--jobs=1` to avoid interleaved output from parallel workers. Performance data in the commit message shows `test-lint` runtime dropping from ~4.5 seconds to under 1 second on a 16-core machine, confirming the series’ goal of addressing Junio’s reported workflow bottleneck.

This patch completes the architectural refactoring introduced in patch 3/4, delivering the ~4x speedup by leveraging chainlint’s existing parallel execution. The implementation is conservative: it preserves standalone greplint functionality, respects the `GIT_TEST_CHAIN_LINT` environment variable, and maintains backward compatibility with existing test scripts. No behavior changes to Git itself are introduced, and the only test modification (in patch 3/4) ensures compatibility with the lint check.
