This is the second patch in Harald Nordgren’s v11 series implementing a "matching-inspired" fetch mode for Git. The series is queued in `next` and ready for merging.

This patch extracts the logic that determines which branches to fetch when no explicit refspec is given. Currently, Git checks whether the current branch’s upstream lives on the remote being fetched and, if so, adds that upstream to the list of refs to fetch. Harald moves this check into a new helper function, `collect_upstream_from_remote()`, so the same logic can be reused for *all* local branches that track the remote, not just the current one. The helper takes a repository pointer, a remote, an optional branch name (NULL means the current branch), and a `strvec` to populate with the upstream refs.

The change is a pure refactoring: no behavior is altered. The extracted logic is identical to what was previously inlined in `do_fetch()`, including the NULL-check for the branch via `repo_branch_get()`. The patch also updates the call site in `builtin/fetch.c` to use the new helper, replacing the old inlined code with a single function call. The commit message explains the motivation clearly and gives a concrete example of how the logic is used today.

This is a well-crafted, uncontroversial refactoring that prepares the ground for the dynamic branch enumeration introduced in later patches. The code is clean, the commit message is clear, and the patch is part of a series that has already addressed all prior feedback.
