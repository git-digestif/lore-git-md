This is a performance-focused refactoring of Git’s test-lint infrastructure. Tyler Cipriani proposes a four-patch series that eliminates redundant file parsing by running the `greplint` checks inside `chainlint.pl` instead of as a separate, serial pass. The result is a dramatic speed-up: five consecutive `make test-lint` runs drop from ~25 s to ~6 s on a 16-core machine.

The series adopts Jeff King’s earlier optimization (skipping files that don’t contain the word “grep”) and extends it by moving the core greplint logic into a shared library (`lib-greplint.pl`). `chainlint.pl` gains a `--greplint` flag so that `make test-lint` can invoke both linters in a single, parallel pass. The standalone `greplint.pl` is kept for users who disable chainlint via `GIT_TEST_CHAIN_LINT=0`.

The patches touch only the test infrastructure (`t/Makefile`, `t/chainlint.pl`, `t/greplint.pl`, and a small fix in an interop test), so there is no change to Git’s runtime behavior. The commit messages are clear, the before/after timings are compelling, and the design aligns with the architectural goal of shared parsing effort that was raised in the original thread. If the patches apply cleanly and pass CI, they look like a straightforward win.
