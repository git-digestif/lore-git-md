This is a performance optimization for Git's test-lint infrastructure, specifically targeting the slowdown in `test-grep-lint` reported by Junio. The series consolidates the work done by `t/chainlint.pl` and `t/greplint.pl`, which currently parse the same ~1100 test files independently and serially. By teaching `chainlint.pl` to run greplint checks during its own tokenization pass, the series reduces redundant parsing and leverages parallel execution, cutting total `test-lint` runtime from ~25 seconds to ~6 seconds for five consecutive runs on a 16-core machine.

The approach is pragmatic: it preserves `greplint.pl` as a standalone tool (for use when `GIT_TEST_CHAIN_LINT=0`) while moving the core parsing and token-checking logic into a shared library (`lib-greplint.pl`). The first patch (by Peff) adds an early return in `greplint.pl` to skip files that don’t contain the word "grep", halving its standalone runtime. The remaining patches restructure the code to allow `chainlint.pl` to invoke greplint checks directly, eliminating the duplicate file I/O and parsing overhead.

The commit message provides clear before/after performance data and credits Peff’s earlier optimization, which is incorporated here. The series touches `t/Makefile`, `t/chainlint.pl`, `t/greplint.pl`, and introduces `lib-greplint.pl`, with minimal changes to test scripts (only one interop test is updated to use `test_grep` instead of bare `grep`). The motivation is explicitly framed as addressing Junio’s workflow bottleneck, and the solution aligns with Peff’s suggestion to share parsing effort between lint checks.

This looks like a well-motivated, tested fix for a real developer experience issue. The architectural trade-off (immediate speedup vs. future linting system improvements) is acknowledged but not overstated, and the implementation avoids disrupting existing workflows. The series is likely to be uncontroversial and could land quickly if no edge cases are uncovered.
