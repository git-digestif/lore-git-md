This is the third patch in Tyler Cipriani’s four-patch series addressing the `test-lint` performance regression caused by `test-grep-lint`. The patch restructures the greplint code by moving the core parsing and token-checking logic from `t/greplint.pl` into a new shared library, `lib-greplint.pl`. This refactoring is a prerequisite for the next patch, which will allow `chainlint.pl` to invoke greplint checks during its own tokenization pass, eliminating redundant file I/O and parsing overhead.

The changes are mechanical but substantial: `t/greplint.pl` is reduced from 257 to 22 lines, while `lib-greplint.pl` (copied from the original script) is trimmed and refactored to expose a `check_tokens()` subroutine that returns error messages instead of printing them directly. The new library preserves all the original logic for detecting bare `grep` assertions and `! test_grep` anti-patterns, including the `is_command_word()`, `is_filter()`, and `lint_ok()` helper functions. The main script now delegates parsing and error collection to the library, which stores results in the parser object for later output.

This patch is a clean refactoring with no behavior changes—standalone `greplint.pl` remains fully functional, and the lint checks themselves are unchanged. The motivation is purely performance: by sharing the parsing effort between `chainlint` and `greplint`, the series aims to cut `test-lint` runtime from ~25 seconds to ~6 seconds for five consecutive runs. The patch is well-scoped and uncontroversial, assuming the follow-up integration in patch 4/4 works as intended. No objections or edge cases have been raised so far.
