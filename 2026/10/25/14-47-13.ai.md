This is a **substantive review** of Jasper Mayone’s `--branch=<branch>` filtering patch for `` `git worktree list` ``. Phillip Wood engages deeply with the implementation, identifying code duplication, proposing architectural improvements, and raising user-experience concerns.

The review centers on three main points. First, Phillip notes that the patch duplicates much of the branch-checking logic already present in `branch.c:prepare_checked_out_branches()`. He suggests refactoring that function to expose a reusable `branch_find_checkout()` helper that both `git branch` and `git worktree list` could call, avoiding redundancy and ensuring consistent behavior. This would require adding a `struct worktree` pointer to the `struct checked_out_branch` structure and converting the existing list to a hashmap indexed by branch name.

Second, Phillip raises a usability issue: when filtering worktrees, the output no longer indicates which one is the main worktree. Since deleting the main worktree is forbidden, scripts that might call `git worktree remove` on the filtered list could fail unnecessarily. He proposes adding an `is-main-worktree` annotation to the porcelain output so scripts can skip the main worktree preemptively.

Finally, Phillip questions the validation logic: the patch rejects syntactically invalid branch names but accepts names of branches that do not exist. He asks whether this asymmetry is intentional, though he does not press for a specific change.

The review is constructive and technically precise, focusing on maintainability and scriptability rather than the feature’s core value. It does not block the patch but suggests follow-up work that would improve its integration with the rest of the codebase.
