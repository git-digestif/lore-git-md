This is the final patch in the v11 series introducing a "matching-inspired" fetch mode for Git. It makes `--limited-fetch` the default when adding a remote in a shallow repository, ensuring that `git fetch` operations remain fast and targeted by avoiding the negotiation of history for all remote branches.

The patch updates `builtin/remote.c` to check `is_repository_shallow(the_repository)` when `limited_fetch` is unset, defaulting to `--limited-fetch` unless explicitly disabled with `--no-limited-fetch`. The logic reuses existing machinery and introduces no new technical debt. Documentation in `git-remote.adoc` is updated to explain the new default behavior, clarifying that it applies to all shallow repositories, not just single-branch clones. Four new tests in `t/t5505-remote.sh` verify the default behavior, its override with `--no-limited-fetch`, and that explicit `-t` refspecs are preserved in shallow repositories.

The change is uncontroversial and aligns with the series' goal of improving performance in shallow repositories. The implementation is minimal, leveraging the existing `limited_fetch` flag and shallow-repository detection. No edge cases or open questions remain for this patch; it completes the series by ensuring the new mode is automatically enabled where it is most beneficial.
