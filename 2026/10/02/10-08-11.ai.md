This is a major refactoring patch series (13 patches) from Patrick Steinhardt targeting the object database (ODB) subsystem, specifically the handling of alternates. The series moves alternates into the "files" backend, simplifying the architecture to address conceptual mismatches between pluggable ODBs and alternates.

The motivation is clear: the current design, where alternates are managed at the ODB source level, creates performance regressions, complicates data structures like bitmaps and commit graphs, and makes it difficult to extend `GIT_OBJECT_DIRECTORY` or `GIT_ALTERNATE_OBJECT_DIRECTORIES` in a backend-agnostic way. Alternates also make assumptions about backend implementations (e.g., filesystem paths) that don’t hold for all backends. This series doesn’t fix those problems directly but lays the groundwork for future fixes by consolidating alternates into the files backend.

Key changes include:
- Introducing `struct odb_files_dir` to manage multiple object directories.
- Refactoring `odb_for_each_alternate()` and `odb_find_source()` to work with directories instead of sources.
- Absorbing quarantine logic into `tmp-objdir` and managing it as an object directory.
- Dropping the `read_alternates` callback and moving alternates into the files backend.
- Touching 52 files, with significant changes to `odb/source-files.c` (482 lines added) and `odb.c` (439 lines removed).

The series is built on `c46c1e3772` (start of the Git 2.98 cycle) and has minor merge conflicts with `seen`, which are documented in the cover letter. The changes are mechanical but far-reaching, affecting core commands like `git commit-graph`, `git pack-objects`, `git repack`, and `git multi-pack-index`.

This is a prerequisite for future work, so expect follow-up series to build on it. The patch count and scope suggest it’s a well-considered effort, though the size may make review challenging. The commit messages and cover letter are thorough, which helps. If you care about ODB internals or alternates, this series is worth tracking.
