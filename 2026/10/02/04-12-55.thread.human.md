This thread is about a bug in Git’s reference-transaction hook that fails to fire during branch copy and rename operations. Никита Поникаров reports that commands like `git branch -C` (copy branch, overwriting an existing destination), `git branch -c` (copy branch, creating a new destination), `git branch -m/-M` (rename branch), and `git reflog delete --updateref --rewrite` do not trigger the hook as documented in `githooks(5)`. The issue affects both the files and reftable backends, though the exact behavior differs slightly between them.

The report includes a minimal reproduction script showing that the hook remains silent when `git branch -C` overwrites an existing branch, while it correctly fires for `git branch -f`. This gap prevents tools that rely on the hook—such as branch-protection systems—from enforcing policies for these operations. The problem appears to stem from missing hook invocations in Git’s ref-update plumbing rather than a documentation error.

So far, the thread is just the initial bug report; no patches or responses have been posted yet. The issue is well-documented, with clear reproduction steps and a real-world use case, so it’s likely to attract attention from maintainers or contributors familiar with the refs subsystem. If you’re working on branch protection or hook-based tooling, this is a critical gap to watch.
