This is the second patch in Patrick Steinhardt’s 13-patch series refactoring the object database (ODB) to move alternates into the "files" backend. It specifically decouples the commit-graph subsystem from `struct odb_source`, replacing it with explicit repository and object directory path arguments.

The patch is a mechanical but important step toward the series’ goal. Currently, commit-graph functions take a `struct odb_source`, which bundles both the repository and the object directory path. This design assumes the source has an on-disk layout (e.g., `.git/objects/info/commit-graph`), an assumption that doesn’t hold for non-files backends. By switching to explicit repository and path arguments, the commit-graph code becomes more backend-agnostic, aligning with the series’ broader aim of consolidating alternates into the files backend.

Key changes include:
- Replacing `struct odb_source *` with `struct repository *` and `const char *dir` in all commit-graph functions.
- Canonicalizing object directory paths to absolute paths to ensure robust comparisons (e.g., when checking if two graphs are in the same directory).
- Updating callers in `builtin/commit-graph.c`, `builtin/commit.c`, `builtin/fetch.c`, and other built-ins to pass the repository and path instead of the source.
- Modifying `struct commit_graph` to store the repository and directory path directly, rather than a pointer to the source.

The commit message is clear and explains both the immediate change and the long-term architectural benefit. No behavior changes are introduced—this is purely internal refactoring.
