Thread identity: `[PATCH v2] branch --delete-merged: default to all upstreams when no pattern given` (feature patch), originating author Harald Nordgren.

Core problem or goal: Simplify the `git branch --delete-merged` workflow by making the branch pattern optional. The patch changes the command to default to considering every upstream branch (via an implicit `**` pattern) when no pattern is provided, replacing the previous requirement to specify a pattern like `*/*`. The stated goal is to make the command more ergonomic for cleaning up branches whose work has landed upstream, though multiple reviewers have questioned whether the implementation (defaulting to *all* upstreams) aligns with this intent or introduces usability risks.

Current status: Under review (second version posted). The v2 iteration renames the default pattern from `*/*` to `**` and drops the `--merged` reference in the commit message, but the core design questions remain unresolved: whether defaulting to *every* upstream is the correct abstraction, and whether the use of `PARSE_OPT_LASTARG_DEFAULT` creates a usability trap. The author has acknowledged process-related feedback but has not yet engaged with the substantive design objections.

He contrasts this with other Git commands (e.g., `--merged`, `--contains`) that default to the *current* branch, suggesting the latter may be more intuitive. The thread has not resolved whether the default should be narrower (e.g., only branches merged into the current branch) or if `**` is the correct abstraction.

He suggests using a `--` separator to explicitly mark the end of upstream patterns (e.g., `git branch --delete-merged [<upstream>...] -- [<branch>...]`), a pattern already used elsewhere in Git.
