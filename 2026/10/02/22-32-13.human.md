This is a follow-up in the `git bisect` plumbing discussion.

Junio C Hamano confirms Jeff King’s earlier suggestion that the commit identified by `git bisect` as the culprit is reliably stored in the `refs/bisect/bad` ref. The confirmation comes from a close reading of the bisect code: when the bisect session concludes, `refs/bisect/bad` points to the first bad commit, and this ref is used internally to generate the "is the first bad commit" message. Junio also clarifies a minor optimization in the bisect logic—when the final step would not change `HEAD` (e.g., if the current commit is already the culprit), the code skips the checkout but still updates `refs/bisect/bad` to the correct commit. This means the ref is always accurate, regardless of whether `HEAD` moves during the final step.

The exchange reinforces that `git show bisect/bad` or `git rev-parse bisect/bad` are the correct plumbing-level ways to retrieve the culprit commit programmatically. No changes to Git are needed; the existing mechanism fully satisfies the original question. The discussion is now technically settled.
