This is the second patch in Kristoffer Haugsbakk’s v3 series introducing `--[no-]range-diff-notes` options to `git format-patch`. The patch implements the new functionality, allowing users to control Git notes inclusion in the range-diff section independently of the patch output.

The core change adds two CLI options: `--range-diff-notes=<ref>` (which requires an explicit ref argument) and `--no-range-diff-notes` (which suppresses notes in the range-diff without fallback). The implementation introduces a new `struct rdiff_notes` to track whether the user wants to override the default notes behavior for range-diffs, replacing the previous `rdiff_override_notes` flag in `struct rev_info` with a more flexible structure. The `get_notes_args` function is updated to take this new structure, and a parse-options callback (`rdiff_notes_cb`) is added to handle the new options.

Key behavior rules: if no range-diff notes options are given, the range-diff uses the same notes as the patches; otherwise, it uses only the explicitly specified notes (including none). The patch preserves the interaction between patch notes and range-diff notes while allowing independent control. The implementation avoids erroring out when `--range-diff-notes` is used without `--range-diff`, treating it as a no-op to avoid inconveniencing users with aliases or scripts.

Test coverage is thorough, verifying scenarios like suppressing all range-diff notes, using different notes refs for patches and range-diffs, and ensuring `--range-diff-notes` requires a value. Two additional tests specifically address the single-patch case, serving as regression tests for a bug fixed in commit 155986b4 (2025-09-25). The documentation is updated to reflect the new options and their behavior.

This patch is technically sound and addresses all feedback from v2, including removing a redundant `test_when_finished` call.
