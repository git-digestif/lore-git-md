This is a reply in the ongoing CI/build system thread improving GitHub Actions failure reporting. Harald Nordgren responds to Phillip Wood’s feedback about escaping percent signs (`%`) in GitHub annotations.

Harald now proposes to **drop the escaping logic entirely**, arguing that the only problematic case (`%25`, representing a literal percent sign) does not appear in any Git test. He links to two CI runs demonstrating that unescaped percent signs in test descriptions (e.g., from `for-each-ref` format atoms like `%(raw)`) do not break GitHub’s annotation parser in practice. The decision is pragmatic: rather than extend escaping to all existing annotations (which Phillip Wood flagged as inconsistent), Harald prefers to remove the escaping helper altogether, deferring any future fixes to a separate topic.

The change is narrow and does not affect the patch’s core functionality—precise, clickable failure annotations still work for static test descriptions. However, it leaves the escaping inconsistency unresolved: if a future test *does* include a literal `%25`, GitHub may misparse the annotation. This is a calculated trade-off; Harald judges the risk low enough to proceed without escaping.
