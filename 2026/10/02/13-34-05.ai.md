This is a **test improvement patch** for the ongoing **packfile corruption bugfix series** (Patrick Steinhardt’s v1). It proposes a **deterministic, platform-independent test** to replace the existing glibc-dependent regression test in `t/t6437-submodule-merge.sh`.

The patch adds a new test helper, `test-delta-base-cache`, that **forces memory reuse** of a `packed_git` struct by closing one pack and manually copying another into its memory address. This simulates the exact scenario that triggers the bug—stale delta base cache entries colliding with new packs at the same offset—without relying on allocator behavior. The test creates two packs (`A-B.pack` and `B-C.pack`) where the delta base for `B` in the first pack and `C` in the second pack share the same offset, then verifies that unpacking `C` after closing the first pack does not incorrectly use `A` as the delta base.

The implementation touches nine files, including:
- A new test helper (`t/helper/test-delta-base-cache.c`) that orchestrates the memory reuse and object reconstruction.
- A small enhancement to `test-pack-deltas` to support writing full objects (needed to generate the test packs).
- A new test script (`t/t5336-pack-delta-base-cache.sh`) that exercises the helper with a minimal reproduction case.

The patch is **well-motivated** and addresses the only loose end in the original series: the non-portability of the regression test. It is **narrowly scoped** and does not alter the core fix (which remains in `packfile.c`). The test design is clever and directly targets the bug’s root cause, making it a strong candidate for inclusion. No substantive review has been posted yet, but the approach looks sound and aligns with the project’s preference for deterministic tests.
