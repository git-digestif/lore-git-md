This is a performance optimization for the packed-refs backend, now in its second version. The patch speeds up operations that rewrite the packed-refs file (such as deleting references) by avoiding redundant formatting of unchanged refs. Instead of using `fprintf()` for every entry, it tracks the raw byte positions of unchanged refs in the snapshot iterator and writes them directly with `fwrite()`.

The key change in v2 is structural: the author split the write logic into two functions—`write_packed_entry()` for formatted writes and a new `write_packed_entry_raw()` for raw writes—addressing feedback from Toon Claes. This separation makes the code clearer and explicitly documents the side effects of bypassing `fprintf()`: original formatting (including case, whitespace, and malformed refnames) is preserved, and peeled OIDs for broken refs are carried forward unchanged. The commit message now acknowledges these trade-offs, which were not mentioned in v1.

The patch touches only `refs/packed-backend.c` and introduces a `record_start` field in `struct packed_ref_iterator` to track the start of each ref record. Benchmarks show a consistent ~20% improvement when deleting 100,000 packed refs, reducing runtime from ~28.7 ms to ~23.8 ms. The on-disk format remains backward-compatible, though tools parsing packed-refs files may observe subtle formatting differences.

This is part of the packed-refs subsystem maintained by Karthik Nayak and Patrick Steinhardt. The optimization is narrow and well-motivated, with clear performance gains and minimal risk of regression. The main open question is whether the formatting changes could affect external tools (e.g., JGit, libgit2), though no specific compatibility issues have been raised yet. The patch is ready for further review, with no unresolved technical concerns.
