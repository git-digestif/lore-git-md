This is the v6 cover letter for a three-patch bugfix series targeting the `rerere` subsystem. The series addresses a long-standing race condition where concurrent `rerere` operations (e.g., a rebase and background maintenance) contend for the shared `MERGE_RR.lock`, leading to crashes or deadlocks. The geometric maintenance strategy introduced in Git 2.54 exacerbated the issue by triggering `git rerere gc` more aggressively, but the race is a general robustness flaw in `rerere` locking.

The v6 updates incorporate feedback from Patrick Steinhardt and refine the approach introduced in v5. Key changes include:
- Patch 2 now introduces `--skip-locked` (hidden/undocumented) instead of `--auto` for `git rerere gc`, clarifying that the flag is for internal use by `git maintenance run --auto` and `git gc --auto`. The documentation is moved to `Documentation/config/rerere.adoc` and explicitly names the callers.
- The `RERERE_SKIP_LOCKED` flag in patch 3 is renamed to `RERERE_WARN_LOCKED` to avoid confusion with the new `RERERE_NOWAIT` flag.
- Patch 3 adds test coverage for the merge recreated by `git rebase -r`, the only call site previously missing a test.
- Commit messages are corrected to clarify that not all `rerere` commands take the lock (e.g., `status`, `diff`, and `remaining` do not).

The series remains a pragmatic, well-motivated fix for a real-world problem. The patches are cleanly structured, with thorough test coverage and clear documentation updates. The trade-offs (e.g., warning at conflict stops but failing post-resolution recording) are settled, and the implementation aligns with established Git patterns (e.g., configurable timeouts, hidden flags for internal use). The series is ready for final review, with no unresolved technical concerns. Files touched include `rerere.c`, `rerere.h`, `apply.c`, `builtin/am.c`, `builtin/gc.c`, `builtin/merge.c`, `builtin/rerere.c`, `builtin/stash.c`, `sequencer.c`, `Documentation/config/rerere.adoc`, `t/t4200-rerere.sh`, and `t/t7900-maintenance.sh`.
