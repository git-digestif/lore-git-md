This is the fourth patch in Christian Couder’s v5 series introducing `uploadpack.lazyFetchTrusted`, a server-side mechanism to mark repositories as trusted for lazy fetching. This patch specifically addresses the risk of infinite recursion when a repository and its promisor remote are configured to lazy-fetch from each other.

The patch adds a recursion depth counter via the new `GIT_INTERNAL_LAZY_FETCH_DEPTH` environment variable, which is incremented each time `fetch_objects()` spawns a child process. If the depth exceeds `MAX_LAZY_FETCH_DEPTH` (set to 5), the code emits a warning and aborts further lazy fetching. The limit is chosen to allow legitimate nesting (e.g., `index-pack` fetching REF_DELTA bases) while preventing infinite loops. The recursion safeguard is implemented in `promisor-remote.c`, with the depth check added to `lazy_fetch_objects()` and propagated through `try_promisor_remotes()` and `fetch_objects()`.

The test in `t/t0410-partial-clone.sh` verifies the safeguard by configuring two partial clones as each other’s promisor remotes and confirming that lazy fetching fails with the expected warning after exactly 5 nested fetches. The test also checks that the recursion is bounded by counting the number of `git fetch` subprocesses spawned.

This patch is a targeted bugfix that complements the broader trust model introduced in the series. It is well-motivated, with clear documentation of the recursion risk and a conservative depth limit. The implementation is clean, with no behavioral changes outside the pathological case. Junio’s earlier type nit (using `int` instead of `unsigned long` for the depth counter) is resolved by casting from `git_env_ulong()`. The patch is ready for integration if the series as a whole is accepted.
