This is the third patch in the v5 series implementing a "matching-inspired" fetch mode for shallow repositories. It adds a `--limited-fetch` flag to `git remote add` that explicitly opts a remote into the new mode by setting `remote.<name>.refmap` instead of the traditional wildcard `remote.<name>.fetch` refspec.

The patch updates `builtin/remote.c` to parse the new flag, validate that it is not used with incompatible options (`-t/--track` or `--mirror`), and write the refmap configuration (`+refs/heads/*:refs/remotes/<name>/*`) when the flag is specified. Documentation in `git-remote.adoc` is extended to describe the flag's behavior: a refspec-less `git fetch <name>` will now fetch only the branches tracked by local branches at the remote, rather than all remote branches. Tests in `t/t5505-remote.sh` verify the flag works in non-shallow repositories and correctly rejects incompatible combinations.

This is a straightforward plumbing change that complements the refmap configuration and dynamic branch enumeration logic introduced in Patches 1/4 and 2/4. The implementation is clean and well-tested, with no substantive objections raised in prior iterations. The flag is a user-facing opt-in for the new fetch mode, though Patch 4/4 will make it the default in shallow repositories. The patch preserves backward compatibility by only changing behavior when the flag is explicitly specified.
