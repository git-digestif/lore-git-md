This is the fourth and final patch in Harald Nordgren’s v5 series introducing a "matching-inspired" fetch mode for shallow repositories. It makes `--limited-fetch` the default when adding a remote in a shallow repository, unless the user explicitly opts out with `--no-limited-fetch` or specifies `-t/--track` or `--mirror`.

The patch is small and surgical: it modifies `builtin/remote.c` to check `is_repository_shallow()` and enable `--limited-fetch` by default in shallow repos, updates `Documentation/git-remote.adoc` to document the new behavior, and adds four new tests in `t/t5505-remote.sh` covering edge cases (explicit `-t` in shallow repos, wildcard refspecs in full repos, the shallow default, and `--no-limited-fetch` override). The implementation is clean and preserves backward compatibility for non-shallow repositories.

This patch directly addresses the core problem motivating the series: shallow clones with many remote branches experience slow or hanging `git fetch` operations because a refspec-less fetch negotiates history for all remote branches. By defaulting to `--limited-fetch` in shallow repositories, the patch ensures that `git remote add` does not commit the repository to following every branch the remote has, significantly improving performance in shallow clones. The design is opt-out rather than opt-in, which aligns with the user experience goal of not surprising users with unexpected full-fetch behavior in shallow repos.

The patch is well-tested and addresses prior feedback comprehensively. The only minor edge case noted in the series (a bare `git fetch` against a refmap-only remote fetches no branches) is unrelated to this patch and was acknowledged by the author as a small quibble, not a blocker. Junio C Hamano has stated he will queue the series ("Will replace") once he performs his own re-review, and no substantive objections remain. This patch is ready for integration.
