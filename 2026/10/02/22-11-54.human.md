This is a user-support reply about `git bisect` plumbing.

Jeff King (Peff) responds to Alejandro Colomar’s question about retrieving the bisect culprit commit programmatically. He suggests using `` `git show bisect/bad` `` as a plumbing-friendly way to obtain the commit hash after a successful bisect session. The rationale is that `git bisect` advances the `refs/bisect/bad` ref to point to the blamed commit, making it accessible without parsing porcelain output.

The suggestion is technically sound and aligns with Git’s ref-based state management. It avoids the need for parsing `git bisect log` or other user-facing commands, which is exactly what Alejandro was looking for. No new feature or patch is proposed—this is a direct answer to the original inquiry. If Alejandro or others confirm this works, it could become a recommended practice for scripting bisect workflows.
