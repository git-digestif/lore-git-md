This is a feature patch (v4 of a series) that extends `git history` to sign rewritten commits, now including the `squash` subcommand. The series teaches `git history` to respect the `commit.gpgsign` configuration and the `-S/--gpg-sign` and `--no-gpg-sign` command-line options for all rewriting operations (`drop`, `fixup`, `reword`, `split`, and now `squash`). The implementation follows the same precedence rules as `git commit`, `git rebase`, and `git cherry-pick`: configuration supplies the default, command-line options override it, and the last option wins.

The v4 update adds signing support to `git history squash`, including its synopsis, documentation, and test coverage. The new `t/t3455-history-squash.sh` test script verifies that squash respects configuration, command-line overrides, explicit key selection, and that replayed descendants are signed consistently. The replay infrastructure plumbing (patch 1/2) remains unchanged from v3, while the main feature patch (2/2) now handles squash alongside the other subcommands. The commit messages have been clarified to explain the configuration-loading order and the relationship between the replay infrastructure and the history commands.

Files touched include `builtin/history.c`, `replay.c`, `replay.h`, `Documentation/git-history.adoc`, and the test scripts `t/t3451-history-reword.sh`, `t/t3452-history-split.sh`, `t/t3453-history-fixup.sh`, `t/t3454-history-drop.sh`, and the new `t/t3455-history-squash.sh`. The on-disk format is unchanged; only the commit object’s signature trailer is added when signing is enabled. The series is now complete, addressing all previously reviewed subcommands and adding comprehensive test coverage for squash.

The conceptual trade-off around signing rewritten commits (whether it is desirable or misleading to sign commits authored by someone else) remains unresolved but is documented in the commit message. The series is ready for integration, with all substantive review feedback addressed and the last procedural blocker (DCO compliance) resolved in v3.
