This is the sixth patch in Patrick Steinhardt’s 13-patch series refactoring the object database (ODB) to move alternates handling into the "files" backend. The patch introduces the ability for the files backend to manage multiple object directories by adding a `next` pointer to `struct odb_files_dir` and updating all relevant ODB operations to loop through the list of directories.

The core change is mechanical: every function in `odb/source-files.c` that previously operated on a single `files->dirs` now iterates over the linked list of directories (`files->dirs` and its `next` pointers). For read operations (e.g., `read_object_info`, `read_object_stream`, `for_each_object`), the backend checks each directory in sequence until it finds the object. For write operations (e.g., `freshen_object`), it writes only to the first directory in the list. The patch also updates cleanup logic in `odb_source_files_free` and `odb_source_files_close` to handle the linked list properly.

No behavior changes are visible yet—this is purely preparatory work for later patches that will populate the `next` list with alternates. The patch touches only `odb/source-files.c` and `odb/source-files.h`, adding 100 lines and removing 56. The commit message is clear about the intent and the loop-based design, and the code is well-structured for the upcoming alternates migration. If you’re tracking the ODB refactoring effort, this is a foundational step worth noting.
