This is the second patch in Thomas Bachem’s three-part bugfix series addressing the `rerere` lock contention race. It introduces `--skip-locked` mode for `git rerere gc`, a hidden flag designed exclusively for auto-maintenance (`git maintenance run --auto` and `git gc --auto`). The patch ensures background maintenance skips silently when the `MERGE_RR.lock` is held, avoiding disruptions to concurrent operations like rebase or merge.

The implementation is clean and narrowly scoped. The flag is hidden (`OPT_HIDDEN_BOOL`) and explicitly restricted to the `gc` subcommand, preventing misuse. Documentation in `Documentation/config/rerere.adoc` clarifies the flag’s purpose and callers, while the test suite (`t/t4200-rerere.sh` and `t/t7900-maintenance.sh`) verifies both the silent skip behavior and the distinction between auto and manual maintenance. The patch also updates `builtin/gc.c` to pass `--skip-locked` when running in auto mode, aligning with the established pattern for other maintenance tasks (e.g., `--skip-foreground-tasks` in `git gc`).

Key technical details include the new `RERERE_NOWAIT` flag (value `010`), which forces a zero timeout when passed to `rerere_gc()`, and the validation logic in `builtin/rerere.c` to reject `--skip-locked` for non-`gc` subcommands. The patch maintains backward compatibility: manual `git rerere gc` invocations still wait and fail if the lock is held, preserving user expectations.

This patch directly addresses Patrick Steinhardt’s feedback from earlier iterations, replacing the ambiguous `--auto` flag with `--skip-locked` and moving caller-specific documentation to the config file. The change is well-motivated and uncontroversial, with no unresolved technical concerns. It’s a targeted, pragmatic fix that fits neatly into the series’ broader goal of making `rerere` locking more resilient.
