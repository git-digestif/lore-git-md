This is the first patch in Patrick Steinhardt’s v2 series introducing subcommand grouping to Git’s parse-options API. It fixes a minor but visible bug in the `--git-completion-helper` output: when the first option is skipped (e.g., because it is a group or hidden), the completion helper still prints a leading space, producing malformed output like `" --foo"` instead of `"--foo"`.

The fix is straightforward: replace the `opts == original_opts` check with a local boolean (`shown`) that tracks whether anything has been printed yet. The change is confined to `parse-options.c` and adds a single line to the test helper to exercise the new logic. No behavior changes beyond the formatting fix; the patch is purely a correctness improvement for shell completion scripts.

This is a well-scoped bugfix with clear test coverage. It addresses a nit Junio raised in the v1 review and is uncontroversial. The patch is part of the preparatory work for the larger subcommand grouping effort, but it stands alone as a small, self-contained improvement. No new reviews have been posted yet.
