This is the second patch in Christian Couder’s five-part v5 series introducing `uploadpack.lazyFetchTrusted`, a server-side protected configuration for marking repositories as trusted for lazy fetching. This patch is a pure refactoring with no behavioral changes: it extracts reusable path-allowlist logic from the existing `safe.directory` mechanism into two new generic helpers, `path_allowlist_apply()` and `path_allowlist_config_apply()`, and flags a latent design issue in `safe.directory` with a `NEEDSWORK` comment.

The refactoring targets `setup.c` and `setup.h`, introducing 143 lines of new code (including documentation) while removing 49 lines of duplicated logic. The new `path_allowlist_apply()` helper consolidates the path-matching logic previously hard-coded in `safe_directory_cb()`, making it reusable for the upcoming `uploadpack.lazyFetchTrusted` configuration. The helper takes a callback (`allow_path`) that lets callers enforce their own path-acceptance rules—here, `allow_safe_dir()` ensures only absolute paths or "." are allowed, mirroring the existing `safe.directory` behavior. The companion `path_allowlist_config_apply()` helper handles config-value expansion via `git_config_pathname()`, simplifying future callers.

A key addition is the `NEEDSWORK` comment in `path_allowlist_apply()`, which explicitly calls out the silent ignoring of non-existent paths—a behavior inherited from `safe.directory` that could mask misspelled or stale entries. Christian proposes addressing this in a follow-up patch, possibly by adopting an `:(optional)` prefix syntax for paths that are allowed to be missing. The patch also changes the `is_safe` field in `struct safe_directory_data` from `int` to `bool` to align with the new helpers’ interface, a mechanical change with no runtime impact.

The refactoring is observably equivalent to the original code: the `safe.directory` callback now delegates to the new helpers, preserving all existing behavior. Junio’s v4 feedback on this patch was limited to the `NEEDSWORK` comment, which is now included. The patch is a clean candidate for early integration if the series stalls, as it introduces no new dependencies and its helpers are immediately reusable by the next patch in the series.
