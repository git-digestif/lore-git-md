This is a **bugfix targeting the delta-base cache in the packfile subsystem**, resolving a regression that causes submodule merges to either fail with "repository corrupt" or misread commits due to stale cache data. The issue is now confirmed and fixed: Patrick Steinhardt has posted a patch that invalidates delta-base cache entries when packs are closed, preventing cross-submodule object misreads.

The fix is a targeted, low-risk change confined to `packfile.c`, addressing the root cause identified in the thread—a stale cache entry lingering after a pack is closed, which could then be incorrectly reused if another pack reuses the same memory address and base offset. The patch itself is straightforward: a one-line addition to `close_pack()` that clears the cache, ensuring no stale data remains. No on-disk format changes or new user-visible behavior are introduced, and the performance impact is expected to be negligible since pack closure is rare compared to object lookups.
