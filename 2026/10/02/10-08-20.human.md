This is the ninth patch in Patrick Steinhardt’s 13-patch series refactoring the object database (ODB) to move alternates handling into the files backend. This patch simplifies the temporary object directory ("quarantine") setup by merging the logic for replacing the primary ODB source into `tmp_objdir_create()`.

Previously, callers had to perform a two-step dance: create the quarantine directory with `tmp_objdir_create()`, then activate it as the primary ODB source with `tmp_objdir_replace_primary_odb()`. This patch eliminates the second step by moving the replacement logic into `tmp_objdir_create()`, reducing boilerplate for all users of temporary object directories. The change affects `log-tree.c` and `object-file.c`, where the now-redundant `tmp_objdir_replace_primary_odb()` calls are removed.

The patch also updates the `tmp_objdir` struct to track whether the quarantine directory will be destroyed (`will_destroy`), ensuring proper cleanup. Since the quarantine directory is now installed at creation time, `tmp_objdir_create()` gains a `will_destroy` parameter, and the `tmp_objdir_replace_primary_odb()` function is removed entirely. The diff shows a net reduction of 22 lines, with the most significant changes in `tmp-objdir.c` and its header.

This is a clean refactoring that aligns with the series’ goal of simplifying ODB internals. The change is mechanical and well-motivated, though it subtly alters the behavior of `odb_transaction_files_prepare()` in `object-file.c`—instead of repreparing only the quarantine directory, it now reprepares the entire ODB source, which is safe but slightly broader than before. If you’re tracking the ODB refactoring effort, this patch is a straightforward but important step in reducing API complexity.
