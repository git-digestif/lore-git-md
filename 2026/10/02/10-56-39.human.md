This is the second patch in Kristoffer Haugsbakk’s v3 series introducing `--[no-]range-diff-notes` to `git format-patch`. The feature is now technically complete and ready for maintainer approval after addressing all feedback from v2.

The patch adds fine-grained control over Git notes in the range-diff section of `git format-patch` output. Users can now suppress notes in the range-diff (with `--no-range-diff-notes`) or specify a different notes ref for the range-diff (with `--range-diff-notes=<ref>`), while keeping the patch output’s notes behavior unchanged. This solves a real annoyance: when documenting patch series iterations in notes, those notes clutter the range-diff with redundant information. The v3 design enforces explicit separation between patch notes and range-diff notes, eliminating the toggle mechanism and arg-less variant that caused usability concerns in v1.

The implementation is clean and well-motivated. It introduces a new `struct rdiff_notes` to track range-diff notes preferences, replaces a custom revision option handler with a standard `parse-options` callback, and updates `get_notes_args` to handle the new override logic. The interaction rule is straightforward: if no range-diff notes options are given, the range-diff uses the same notes as the patches; otherwise, it uses only the explicitly specified notes (including none). Documentation and tests are thorough, covering all key scenarios—suppressing all range-diff notes, using different notes refs for patches and range-diffs, and ensuring `--range-diff-notes` requires a value. Two additional tests specifically address the single-patch case, serving as regression tests for a prior bug fix.

The patch touches `builtin/log.c`, `Documentation/git-format-patch.adoc`, and `t/t3206-range-diff.sh`. The changes are minimal and focused, with no unnecessary complexity. The only substantive feedback from Junio (a redundant `test_when_finished` call) has been addressed in v3. The series is uncontroversial and appears ready for integration if the maintainer approves the feature. Key names introduced: `--range-diff-notes`, `--no-range-diff-notes`, `struct rdiff_notes`.
