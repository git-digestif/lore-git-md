This is a user-support reply about `git bisect` plumbing.

Jeff King (Peff) responds to Alejandro Colomar’s inquiry by suggesting a workaround: after a successful `git bisect` run, the commit identified as the culprit is recorded in the `refs/bisect/bad` ref, which can be retrieved programmatically using `git show bisect/bad`. This avoids parsing porcelain output and provides the exact commit hash the bisect session determined.

The suggestion is technically sound and directly addresses the original question. It leverages Git’s internal ref mechanism, which is stable and scriptable, making it a practical solution for automation. No new command or feature is proposed; instead, Peff identifies an existing plumbing-compatible way to access the information. The reply is concise, authoritative, and grounded in Git’s low-level behavior. If this approach works as described, it fully resolves the user’s need without requiring any changes to Git itself.
