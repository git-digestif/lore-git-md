This thread is about a proposed change to `git branch --delete-merged` to make it more ergonomic by defaulting to all upstream branches when no pattern is given. The patch, now in its second version, has sparked debate over whether the implementation aligns with the intended workflow and whether it introduces usability risks.

The key participants are Harald Nordgren (the author), Junio C Hamano (the maintainer), and Phillip Wood. Junio has questioned whether defaulting to *all* upstreams (via an implicit `**` pattern) matches the stated goal of cleaning up branches whose work has landed upstream, noting that other Git commands default to the current branch instead. Phillip has raised a design-level objection to the use of `PARSE_OPT_LASTARG_DEFAULT`, arguing it creates inconsistent behavior if future options are added, and has proposed a `--` separator as a more robust alternative. He has also emphasized that design flaws could be avoided with more upfront discussion rather than rapid patch iterations.

The latest exchange between Harald and Phillip clarifies that the process-related feedback was not intended as blame but as a collective reflection on improving design conversations. While the tone remains constructive, the core design questions—whether the current interface is sound or needs a redesign—remain unresolved. The patch is still under review, with no changes yet to address the substantive objections.
