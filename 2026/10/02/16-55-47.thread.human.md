This thread is about a proposed change to `git branch --delete-merged` to make the branch pattern optional, defaulting to all upstream branches when none is given. The patch, now in its second version by Harald Nordgren, aims to simplify branch cleanup but has faced substantive design objections from Junio Hamano and Phillip Wood.

Junio questions whether defaulting to *all* upstreams (via an implicit `**` pattern) aligns with the stated goal of cleaning up branches whose work has landed upstream, suggesting a narrower default (e.g., only branches merged into the current branch) might be more intuitive. Phillip raises a separate concern: the use of `PARSE_OPT_LASTARG_DEFAULT` creates a usability trap by making behavior depend on option order, which could break if future options are added. He advocates for a `--` separator to explicitly mark the end of upstream patterns, following existing Git conventions.

Harald revised the patch to address minor feedback (renaming the default pattern and updating the commit message) but has not engaged with the core design questions. Phillip’s latest email softens the tone of his earlier critique, emphasizing that design flaws are a collective responsibility and urging more upfront discussion to avoid such issues. The thread remains unresolved, with the key questions unanswered: whether the current interface is defensible or if a redesign is needed. No prior user requests or discussion motivated this change, and edge cases (e.g., multiple `--delete-merged` options) remain untested. The patch touches `builtin/branch.c`, its documentation, and tests, but the technical direction is still contested.
