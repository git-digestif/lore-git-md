This thread is about a proposed change to `git branch --delete-merged` to make the branch pattern optional, defaulting to all upstream branches (`**`) when none is provided. The goal is to simplify cleaning up branches whose work has landed upstream, but reviewers have raised concerns about whether the implementation aligns with this intent.

The patch is now in its second version, with the default pattern renamed from `*/*` to `**` and minor commit message tweaks, but the core design questions remain unresolved. Junio C Hamano and Phillip Wood have both raised substantive objections: Junio questions whether defaulting to *all* upstreams (rather than, say, the current branch) is the right abstraction, while Phillip critiques the use of `PARSE_OPT_LASTARG_DEFAULT` as a usability trap that could create inconsistent behavior if future options are added. Phillip also proposed an alternative using a `--` separator to explicitly mark the end of upstream patterns, following existing Git conventions.

The latest exchange shifts the discussion toward process rather than design. Both Junio and Phillip now emphasize the value of more upfront discussion to avoid design mistakes, with the author acknowledging this feedback constructively. However, the thread has not yet returned to the technical debate, leaving the key questions—whether `**` is the correct default and whether the interface is robust—still open. No prior user requests or discussion motivated this change, and edge cases (like multiple `--delete-merged` options or `--dry-run` in non-last positions) remain unaddressed. The patch touches `builtin/branch.c`, its documentation, and tests, but no new symbols are introduced.
