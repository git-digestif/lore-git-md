This thread proposes a small but user-visible change to `git branch --delete-merged`: when no branch pattern is given, the command will now default to deleting all merged branches from *all* upstreams, rather than requiring an explicit pattern like `*/*`. The patch, from Harald Nordgren, touches the documentation, implementation, and tests, and is currently under review.

Junio C Hamano has raised the first substantive feedback, questioning whether the default behavior is too broad. The commit message frames the goal as "cleaning up every branch whose work has landed upstream," but the implementation defaults to `**`—a pattern that matches *all* upstreams, not just those whose changes are merged. Junio contrasts this with other branch-listing options (e.g., `--merged`, `--contains`) that default to the *current* branch, calling that behavior "very natural" in Git’s design. His review leaves open whether the feature should default to a narrower set of branches (e.g., only those merged into the current branch) or if `**` is the right abstraction.

No other reviewers have weighed in yet, and the patch remains in early discussion. The thread is now focused on the design of the default behavior, not its implementation or edge cases. If the discussion converges on a narrower default, the patch may need a second version to address Junio’s concern. For now, the feature is still under review with no merge status.
