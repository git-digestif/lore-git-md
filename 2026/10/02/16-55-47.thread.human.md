This thread introduces a small but user-facing change to `git branch --delete-merged`: when no branch pattern is given, the command will now default to considering *all* upstream branches for deletion, rather than requiring an explicit pattern like `*/*`. The patch comes from Harald Nordgren and is a single-commit feature addition.

The implementation is straightforward: it uses Git’s `PARSE_OPT_LASTARG_DEFAULT` to make `--delete-merged` accept an implicit default pattern (`**`) when it appears as the last argument, matching the existing behavior of the `--merged` option. The documentation and help text are updated to reflect that the pattern is now optional, and a new test verifies that the command works as intended—including with `--dry-run`.

There’s been no discussion yet, so the change is uncontroversial at this stage. The patch is backward-compatible: existing invocations with explicit patterns continue to work unchanged. If reviewers engage, the most likely points of feedback will be around edge cases (e.g., multiple `--delete-merged` options or interactions with other flags) and whether the default pattern (`**`) is the most intuitive choice.
