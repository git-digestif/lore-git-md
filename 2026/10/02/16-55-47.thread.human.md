This thread is about a patch by Harald Nordgren that proposes to simplify `git branch --delete-merged` by making the branch pattern optional, defaulting to all upstream branches when none is given. The goal is to make it easier to clean up branches whose work has already landed upstream. Junio C Hamano raised concerns in review about whether defaulting to *all* upstreams (via an implicit `**` pattern) aligns with the stated intent, noting that other Git commands like `--merged` default to the current branch instead.

The patch is now in its second version, with minor adjustments to the default pattern and commit message, but the core design question remains unresolved. Phillip Wood’s recent review adds a significant new objection: the use of `PARSE_OPT_LASTARG_DEFAULT` creates a usability trap. He argues that the command’s behavior would become inconsistent if future options are added, as the default pattern would only trigger if `--delete-merged` is the last option. He suggests a more robust design using a `--` separator to explicitly mark the end of upstream patterns, a pattern already used elsewhere in Git. Phillip also critiques the patch’s development process, implying that more upfront discussion with reviewers could have avoided this design flaw.

The thread is still under review, with two substantive objections on the table: Junio’s concern about the default pattern’s scope and Phillip’s critique of the command-line interface design. No other reviewers have weighed in yet, and the author has not yet responded to Phillip’s feedback. The next steps will likely involve either revisiting the design to address these concerns or justifying the current approach despite the risks.
