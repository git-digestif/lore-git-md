This thread is about a proposed change to `git branch --delete-merged` to make the branch pattern optional, defaulting to all upstream branches when none is given. The patch, now in its second version, aims to simplify branch cleanup but has sparked debate about whether the design aligns with user expectations and Git’s interface conventions.

The key disagreement centers on two points: first, whether defaulting to *all* upstreams (via an implicit `**` pattern) is the right abstraction for cleaning up merged branches, or if it should instead default to the current branch (as other Git commands do); and second, whether the implementation’s use of `PARSE_OPT_LASTARG_DEFAULT` creates a usability trap by making behavior depend on option order. Junio Hamano and Phillip Wood have both raised substantive objections—Junio questioning the conceptual design, Phillip critiquing the interface mechanics—while the author, Harald Nordgren, has revised the patch to address surface-level feedback but not yet engaged with these deeper concerns.

The discussion briefly detoured into a meta-debate about development process after Phillip suggested the design flaw could have been avoided with more upfront discussion, but Harald pushed back on the framing, steering the thread back toward technical issues. The unresolved questions remain: whether the default should be narrower, whether the current implementation is intuitive, and how to handle future option additions without breaking consistency. The next steps will likely hinge on whether Harald or others propose a revised design that addresses these points.
