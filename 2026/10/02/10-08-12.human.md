This is the first patch in Patrick Steinhardt’s 13-patch series refactoring the object database (ODB) to move alternates handling into the files backend. It targets the `git commit-graph` command, specifically the `--stdin-packs` option.

The patch shifts responsibility for resolving packfile paths from the `fill_oids_from_packs()` function in `commit-graph.c` to the caller in `builtin/commit-graph.c`. Previously, users passed relative packfile paths via `--stdin-packs`, and the code internally resolved them to full paths by prepending the ODB source’s path. Now, the caller constructs the full path before passing it to the lower-level function. This untangles the commit-graph logic from ODB source internals, aligning with the series’ broader goal of consolidating alternates into the files backend.

The change is mechanical and small (19 insertions, 13 deletions), touching only two files. It doesn’t alter behavior or on-disk formats, but it does tighten the interface: `fill_oids_from_packs()` now expects resolved paths, which could break external callers if any exist (though none are mentioned in the commit message). The patch is well-motivated as a preparatory step for the larger refactoring, and the commit message clearly explains the rationale.

If you’re tracking the ODB refactoring effort, this patch is worth noting as a foundational change, but it’s unlikely to be controversial on its own. The real discussion will likely focus on later patches in the series where the architectural shifts become more pronounced.
