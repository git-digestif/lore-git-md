This is the pivotal patch in Patrick Steinhardt’s 13-part ODB refactoring series. It moves alternates handling from the generic ODB layer into the files backend, eliminating the conceptual mismatch that has caused performance regressions and blocked backend-agnostic extensions.

The patch is large (35 files changed, 441 insertions, 549 deletions) but mechanical: almost every loop over `odb->sources` is rewritten to loop over `files->dirs` instead. The core change is that alternates are now managed as linked-list entries in `struct odb_files_dir`, making them an implementation detail of the files backend rather than a cross-cutting concern. The commit also absorbs the alternates-parsing logic (`parse_alternates`, `odb_add_alternate_recursively`) into `odb/source-files.c` and drops the `read_alternates` callback entirely.

Commands that previously assumed pluggable ODBs (e.g., `git fsck`, `git gc`, `git repack`) are updated to work with the new directory-based iteration. The quarantine logic in `tmp-objdir.c` is adapted to insert the temporary directory at the head of the linked list, preserving the expected lookup order.

The patch is well-motivated and the conversion is thorough, but the size and scope mean review will need to focus on edge cases like promisor remotes, partial clones, and path canonicalization. The series is still in its first iteration, so expect a reroll once feedback arrives. If you care about ODB internals or alternates, this is the patch to watch.
