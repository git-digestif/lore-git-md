This is the first patch in a well-reviewed four-part feature series that introduces `remote.<name>.refmap` configuration to enable a "matching-inspired" fetch mode for shallow repositories. The patch adds a per-remote config variable that provides the default value for the `--refmap` command-line option, mirroring how `remote.<name>.fetch` already supplies default refspecs. The implementation is clean: it extends `remote.c` to parse the new configuration, updates `builtin/fetch.c` to use the configured refmap as the default `--refmap` value, and documents the feature in `config/remote.adoc` and `fetch-options.adoc`. Tests in `t/t5510-fetch.sh` verify the configuration behaves identically to the `--refmap` command-line option.

The patch is part of a larger effort to solve a real performance issue: shallow repositories with many remote branches experience slow or hanging `git fetch` operations because a refspec-less fetch negotiates history for all remote branches. The new `remote.<name>.refmap` configuration separates namespace mapping from fetch selection, allowing later patches to dynamically fetch only the branches tracked by local branches at the remote. This patch itself is purely plumbing and does not change user-visible behavior; it simply makes the `--refmap` option configurable per-remote.

The design is settled and addresses all prior feedback. Junio C Hamano proposed the `remote.<name>.refmap` approach and confirmed it resolves backward compatibility concerns, and the documentation wording in this patch precisely defines the configuration's purpose as "used to map remote refs being fetched to remote-tracking refs to store," addressing Junio’s review request from v3. The implementation is minimal and focused, touching only the necessary files (`remote.c`, `remote.h`, `builtin/fetch.c`, and documentation) and adding thorough tests. No substantive objections remain, and the patch is ready for integration. The series as a whole is marked "Will replace" by Junio but is still under active review and not yet in `seen`.
