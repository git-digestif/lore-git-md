This is the v2 revision of Patrick Steinhardt’s patch series introducing subcommand grouping to Git’s parse-options API and applying it to `git refs`. The series now consists of four patches instead of three, reflecting the incorporation of Junio C Hamano’s feedback from v1.

The core goal remains unchanged: refactor the parse-options subsystem to support grouped subcommands, then use this to organize `git refs`’ many subcommands into logical categories (database operations, reading, writing). The v2 changes address the structural and API consistency concerns raised in the first round. Specifically, the series now includes a preliminary refactoring of `usage_with_options_internal()` to extract option-formatting logic into a helper function, reducing nesting and improving readability. The API has also been simplified by extending `OPT_SUBCOMMAND_F()` to accept help text directly, eliminating the need for a separate `OPT_SUBCOMMAND_H()` variant. The variable `first` in the completion logic has been renamed to `shown` for clarity, as suggested.

The updated implementation touches the same key files: `parse-options.{c,h}`, `builtin/refs.c`, documentation, and tests. The new helper function (not yet named in the diff, but likely something like `print_option_usage()`) will be introduced in patch 2/4, while patch 3/4 implements the core subcommand grouping logic.
