This is a **brief follow-up discussion** in the **packfile corruption bugfix thread**, specifically about the **test improvement proposal** for the delta base cache bug.

Patrick Steinhardt responds to Guillaume Chauvel’s suggestion to **force memory reuse of `packed_git` structs** in the test to make it deterministic. While Patrick acknowledges the idea is technically feasible, he **rejects it as disproportionate**, arguing that the added infrastructure (a new test helper, build system updates, and test script) would be excessive for testing a single edge case. The original regression test in `t/t6437-submodule-merge.sh` (which relies on glibc’s allocator behavior) remains the only coverage for now, despite its platform dependency.

The exchange highlights a **trade-off between test determinism and maintenance cost**. Guillaume’s proposal (detailed in the parent email) would eliminate the test’s reliance on allocator quirks, but Patrick’s reply suggests the project may prefer to accept the existing test’s limitations rather than introduce new complexity. No alternative solutions are proposed, and the thread appears to have reached an impasse on this point. The core fix (evicting stale delta base cache entries in `close_pack()`) is unaffected by this discussion.
