This is a minor follow-up to the first patch in Patrick Steinhardt’s three-part series introducing subcommand grouping to Git’s parse-options API. The patch itself is a straightforward bugfix: it corrects a formatting issue in `--git-completion-helper` output where a leading space appears when the first option is skipped (e.g., because it is a group or hidden). Junio’s review was positive but suggested a clearer variable name (`shown` instead of `first`), and Patrick has now accepted that suggestion.

The change is uncontroversial and well-motivated. The bug is easy to reproduce (the test case in `t/helper/test-parse-options.c` demonstrates it), and the fix is minimal—adding a boolean flag to track whether anything has been printed yet. This patch is a prerequisite for the rest of the series, which builds on the parse-options API to enable grouped subcommands in `git refs`. No further discussion is expected, as the fix is both correct and narrowly scoped.
