This is the eleventh patch in Patrick Steinhardt’s 13-patch series refactoring the Git object database (ODB) to move alternates handling into the files backend. The series is a foundational refactoring aimed at simplifying the ODB architecture and enabling future backend-agnostic work.

This specific patch extracts the logic for reading alternates from `odb_source_files_read_alternates()` into a new helper function, `read_alternates()`. The new function takes only an object directory path and a `strvec` output buffer, removing the dependency on a full `struct odb_source`. The change is preparatory: the next patch in the series will introduce a new callsite that needs to read alternates without having an ODB source available. The extraction is mechanical and does not alter behavior, but it’s a necessary step for the broader architectural shift.

The patch touches only `odb/source-files.c`, moving 14 lines of code into a new 19-line helper. The diff is clean and self-contained, with no functional changes. The commit message is concise and clearly explains the motivation: enabling future code that lacks an ODB source but still needs to read alternates.

This is a small but important piece of the larger refactoring. If you’re following the series, this patch is worth noting as it sets up the next step, but on its own it’s a straightforward code movement. The series as a whole is well-motivated and looks like a serious effort to clean up a long-standing architectural mismatch in the ODB subsystem.
