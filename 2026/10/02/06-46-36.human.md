This is a follow-up in the ongoing discussion about whether Git should include a helper script for incremental rebase conflict resolution in its `contrib/` area. Patrick Steinhardt responds to Alejandro Colomar’s query about distributing `git-rebase-walk` separately under the `git-` namespace.

Patrick’s position is pragmatic: he acknowledges that the existence of multiple tools (like `git-imerge` and Colomar’s script) suggests the workflow is broadly useful, but he believes the functionality would be better integrated directly into `git rebase` itself rather than as a standalone script. He does not outright reject the idea of a `contrib/` helper but implies that a built-in solution would be preferable. On the namespace question, he confirms that the `git-` prefix is the standard way to extend Git and that Colomar does not need explicit permission to use it. However, he sidesteps the question of whether distributing the script as part of `manpages-utils` is appropriate, framing it as a decision for downstream distributors rather than the Git project itself.

The exchange leaves the core question unresolved: whether Git will accept *any* helper for this workflow, and if so, whether it should be a standalone script or integrated into `git rebase`. Patrick’s preference for a built-in solution suggests that the bar for `contrib/` inclusion may be high, but his tone is not dismissive. The thread remains open, with no maintainer decision yet. For now, Colomar’s script is a working tool with real-world use, but its future in Git’s ecosystem is still uncertain.
