This is the second patch in Patrick Steinhardt’s 13-patch series refactoring the object database (ODB) to move alternates into the files backend. It specifically decouples the commit-graph subsystem from `struct odb_source`, replacing it with explicit repository and object-directory path arguments.

The patch is a mechanical but consequential change: every function that previously took a `struct odb_source *` now takes a `struct repository *` and a `const char *dir` instead. The commit-graph data structure itself gains a `char *dir` field (canonicalized to an absolute path) and drops its `struct odb_source *odb_source` pointer. This ensures that two commit graphs loaded from the same directory compare equal regardless of how the caller spelled the path (relative, absolute, or via symlink). The patch touches nine files, with the bulk of the churn in `commit-graph.c` (115 lines changed) and `commit-graph.h` (31 lines).

The motivation is twofold: first, it unblocks the series’ goal of moving alternates into the files backend by removing the assumption that commit graphs live in `.git/objects/info`; second, it is a step toward making the commit-graph subsystem backend-agnostic, so that future backends can decide where to store their graphs. No on-disk format changes are introduced, and existing tests (including `t4216-log-bloom.sh`) are expected to cover the new path-resolution logic.

Key symbols introduced or modified:
- `struct commit_graph` gains `repo` and `dir` fields; drops `odb_source`.
- `write_commit_graph_reachable()` and `write_commit_graph()` now take `(repo, dir)` instead of `source`.
- `load_commit_graph_one_fd_st()`, `read_commit_graph_one()`, and related helpers now take explicit `repo` and `dir` arguments.
- All filename helpers (`get_commit_graph_filename()`, `get_commit_graph_chain_filename()`, etc.) now take a `const char *dir` instead of `struct odb_source *`.

The patch is well-motivated and the commit message clearly explains the architectural rationale. The changes are mechanical but far-reaching, so reviewers will likely focus on edge cases (e.g., promisor remotes, partial clones, or non-files backends) and path canonicalization robustness.
