This is a feature patch series that teaches `git format-patch` the `--[no-]range-diff-notes` options, allowing users to control whether notes appear in the range-diff section independently of the patch notes. This is the third iteration (v3) of Kristoffer Haugsbakk’s series, which now consists of two patches after incorporating feedback from Junio C Hamano.

The series is technically complete and addresses all prior usability concerns. The v3 update removes a redundant `test_when_finished` call in the test script, as noted by Junio in his review of v2. The core functionality remains unchanged: `--range-diff-notes=<ref>` lets users specify a notes ref for the range-diff, while `--no-range-diff-notes` suppresses notes in the range-diff entirely. The interaction between patch notes and range-diff notes is now explicit and predictable—if no range-diff notes options are given, the range-diff uses the same notes as the patches; otherwise, it uses only the explicitly specified notes.

The implementation touches `builtin/log.c`, `Documentation/git-format-patch.adoc`, and adds comprehensive tests in `t/t3206-range-diff.sh`. The first patch is a preparatory refactoring that simplifies parameter handling in `get_notes_arg`, while the second patch introduces the new options and updates the documentation. The test coverage verifies edge cases, including suppressing all range-diff notes, using different notes refs for patches and range-diffs, and ensuring `--range-diff-notes` requires a value.

This series is ready for maintainer consideration. The v2 redesign resolved the usability issues raised in v1, and the v3 update addresses the only remaining nit. The feature itself is well-motivated—Kristoffer notes he has used it privately for months—and the implementation is clean and uncontroversial. If revived, this would be a useful addition for users who want fine-grained control over notes display in `format-patch` output.
