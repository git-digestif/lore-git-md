This is a **bugfix** targeting the reference-transaction hook.

Nikita Ponikarov reports that several branch copy and rename operations update refs without triggering Git’s `reference-transaction` hook, violating the documented guarantee that the hook runs for *any* reference update. The issue affects both the traditional files backend and the newer reftable backend, and spans multiple commands: `git branch -C` (copy), `git branch -c` (create copy), `git branch -m/-M` (rename), and `git reflog delete --updateref --rewrite`. In some cases the hook sees only partial updates (e.g., a deletion but no creation), while in others it sees nothing at all.

The reproduction is straightforward: set up a logging hook, run one of the affected commands, and observe that the hook log remains empty. The gap is limited to branches that are not checked out in any worktree, since Git already blocks copy/rename onto checked-out branches. The report includes a minimal shell script that demonstrates the problem on both backends.

This is a clear correctness issue for tools that rely on the hook to enforce branch protection or audit ref changes. The patch will likely touch the ref-updating logic in `builtin/branch.c` and possibly the reflog code, but the email does not include a proposed fix—only the bug report. If the fix is small and well-scoped, it could be a strong candidate for `maint`.
