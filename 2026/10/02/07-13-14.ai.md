This is the v5 cover letter for a four-patch feature series that implements a "matching-inspired" fetch mode for shallow repositories. The series introduces `remote.<name>.refmap` configuration to separate namespace mapping from fetch selection, dynamically infers which branches to fetch based on local tracking branches, and adds a `--limited-fetch` flag to `git remote add` that defaults on in shallow repositories.

The v5 update is purely mechanical: the test file `t/t5585-fetch-refmap.sh` is renumbered to `t/t5586-fetch-refmap.sh` to avoid a conflict with another in-flight topic. No code or documentation changes were made; the series remains technically identical to v4, which already addressed all substantive review feedback.

The design is now settled. Junio C Hamano has stated he will queue the series ("Will replace") once he performs his own re-review, but has not yet done so. The series is still under active review and not yet in `seen` or any integration branch. All four patches are ready: Patch 1/4 adds `remote.<name>.refmap` parsing and documentation, Patch 2/4 implements dynamic branch enumeration (fetching only branches tracked by local branches at the remote), Patch 3/4 adds the `--limited-fetch` flag to `git remote add`, and Patch 4/4 makes `--limited-fetch` the default in shallow repositories.

Key files touched include `remote.c`/`remote.h` (refmap parsing and branch enumeration logic), `builtin/fetch.c` (refmap integration and dynamic branch selection), `builtin/remote.c` (`--limited-fetch` flag and shallow default), and documentation (`config/remote.adoc`, `fetch-options.adoc`, `git-remote.adoc`). Tests cover configuration behavior (`t/t5510-fetch.sh`), dynamic branch selection (`t/t5586-fetch-refmap.sh`), and the `--limited-fetch` flag (`t/t5505-remote.sh`). The implementation preserves backward compatibility for non-shallow repositories and avoids on-disk format changes beyond the new configuration entry.

The series targets a real performance issue: shallow repositories with many remote branches experience slow or hanging `git fetch` operations because a refspec-less fetch negotiates history for all remote branches. The new mode dynamically fetches only the branches tracked by local branches at the remote, significantly improving performance in shallow clones. The design uses Git’s existing `--refmap` mechanism and avoids inventing new refspec syntax, aligning with Junio’s preference. The forced inclusion of the remote’s default branch (present in v3) is removed, resolving Junio’s substantive objection.

One minor edge case remains: a bare `git fetch` against a refmap-only remote (no `remote.<name>.fetch` refspec) fetches no branches, leaving no remote-tracking refs for `git branch --set-upstream-to` to use. Harald Nordgren acknowledges this as a small quibble and not a blocker, but it may warrant future discussion. No other open questions or objections remain. The series is well-motivated, thoroughly tested, and addresses prior feedback comprehensively.
