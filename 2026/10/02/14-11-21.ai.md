This is the final patch in Andrew Pleeter’s four-part v9 series extending `git var` to expose Git’s identity configuration as individual, scriptable variables. The patch adds the six new variables (`GIT_AUTHOR_NAME`, `GIT_AUTHOR_EMAIL`, `GIT_AUTHOR_DATE`, `GIT_COMMITTER_NAME`, `GIT_COMMITTER_EMAIL`, `GIT_COMMITTER_DATE`) that scripts can query without parsing the monolithic `GIT_AUTHOR_IDENT` or `GIT_COMMITTER_IDENT` strings. The implementation is clean, type-safe, and reuses Git’s existing ident-parsing logic, ensuring correct handling of awkward characters in names or emails.

Phillip Wood’s review is **surface-level**, focusing solely on test organization. He notes that the separate tests for each identity component could have been combined into a single test but acknowledges the patch is otherwise complete and not worth a re-roll. The broader series (v9) is technically finalized, with all prior feedback incorporated, and remains in `seen` pending Junio’s review. The only unresolved suggestion—a trailing delimiter in `-z` mode—is not a blocker and can be addressed later if needed.

The patch itself is straightforward: each new variable is backed by a helper function that calls `split_ident_line()` on the corresponding ident string. Documentation and tests cover single-variable queries, multi-variable invocations, unset identities, and inclusion in `git var -l` output. The series as a whole delivers a robust, scriptable interface to Git’s identity configuration, replacing the earlier `git ident` proposal with a design that aligns with `git config -z` output and supports composable arguments. No open technical questions remain for this patch.
