This is the first patch in Scott Chacon’s RFC series proposing a new SHA-256-based signing mechanism for Git commits and tags. It introduces the core hashing logic: a function `tree_sha256_hex()` that computes a SHA-256 digest over the entire tree contents (including submodules) in a reproducible, object-format-agnostic way.

The digest is built from a sorted list of `<sha256(content)> SP <path> NUL` records for every file, symlink, and submodule in the tree. Submodules are handled recursively: their own tree digests are computed and included as `<digest> SP <path>/ NUL`. The implementation detects cycles (submodules that reference commits already being hashed) and treats them as "cycle:<commit>" to avoid infinite recursion. If a submodule is unavailable or missing the pinned commit, the function reports every problem and returns an error.

The patch adds a new file `tree-sha256.c` (238 lines), a test helper `test-tree-sha256.c` (31 lines), and a comprehensive test script `t/t1018-tree-sha256.sh` (123 lines). The test script validates the digest computation by recomputing it manually with `git ls-tree`, `git cat-file`, and `sha256sum`, and checks edge cases such as file mode changes, path renames, submodule updates, and missing submodules. The test coverage is thorough and confirms that the digest is stable across commits, tags, and trees, and that it correctly reflects content and path changes.

This patch is the foundation for the rest of the series: the following patches will embed the digest in signed objects via a new `--hash=sha256` option and a `gpg.treeHash=sha256` config key. The implementation is self-contained and does not change the object format itself, preserving backwards compatibility. The author’s commit message and test script are clear and well-documented, making the design easy to evaluate.
