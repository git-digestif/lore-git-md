This is a feature patch series that extends `remote.pushDefault` to accept a space-separated list of remote names. The goal is to let users set a single global configuration (e.g., `fork origin`) that works across all repositories, with Git pushing to the first remote in the list that exists locally.

The series consists of two patches. The first refactors `remote.c` to extract the logic for looking up a remote by name into a helper function, making the code more modular. The second patch modifies `remote_pushdefault()` to split the `remote.pushDefault` value on whitespace, iterate through the list, and return the first remote that exists in the repository. The documentation is updated to reflect the new behavior, and a new test in `t/t5516-fetch-push.sh` verifies that the feature works as expected.

The motivation is straightforward: users with multiple remotes (e.g., a fork and an upstream) often want to set a default push target that varies by repository. Currently, `remote.pushDefault` only accepts a single remote name, forcing users to configure it per-repository or rely on workarounds. This change eliminates that friction by allowing a fallback chain of remotes.
