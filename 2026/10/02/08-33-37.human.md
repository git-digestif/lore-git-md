This is the first patch in a two-part performance optimization for the commit-graph subsystem. It adds a new `commit-info` subcommand to `test-tool read-graph`, allowing tests to verify whether specific commits are present in the commit-graph and to inspect their generation numbers. The change is small and focused, touching only `t/helper/test-read-graph.c` to implement the new functionality.

The motivation is clear: the test infrastructure currently lacks a way to check commit-graph contents, which makes it difficult to verify the state of the graph after operations like `git fetch`. This helper will be used in the second patch to test the incremental commit-graph write strategy introduced there. The implementation is straightforward, parsing commit OIDs from the command line, looking them up in the graph, and printing their generation numbers or reporting if they are missing.

The patch is well-scoped and appears to be a necessary prerequisite for the series' main optimization. It introduces no behavioral changes to Git itself, only extending the test tooling. The commit message is concise and explains the purpose effectively. This looks like a clean, uncontroversial addition that enables better test coverage for the follow-up patch.
