This is a follow-up from Junio C Hamano in the RFC thread proposing a new signing mechanism that embeds SHA-256 digests of tree contents in signed commits and tags. Junio has reviewed the series but has not yet decided whether the overall direction is sound. His earlier review of patch 2 praised the refactoring of tag header construction but raised substantive design questions about the digest algorithm—specifically, whether it should distinguish between file modes or symlinks pointing to the same content, and whether it should reflect the internal structure of the tree object to detect corruption. Those questions remain unanswered.

In this email, Junio acknowledges Scott Chacon’s concern about the ecosystem impact of switching Git’s default object format to SHA-256 in Git 3.0 and notes that the implementation comments he offered are contingent on the assumption that the approach is worthwhile. He does not object to the goal but implies that the current design may need rethinking before proceeding. No new technical points are raised; this is primarily a status update indicating that the maintainer is still evaluating the proposal. The thread remains in the design-discussion phase, with no decisions or merge status recorded.
