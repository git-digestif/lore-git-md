This is a brief follow-up in the ongoing CI/build system series to improve GitHub Actions failure reporting. The patch in question (v4 2/2) aims to make test failures and fixed breakages point directly to their exact file and line in the test script.

Harald Nordgren responds to Phillip Wood’s latest feedback about escaping percent signs (`%`) in GitHub Actions annotations. Phillip had pointed out that while the patch escapes new annotations, it doesn’t apply the same escaping to existing ones, creating an inconsistency that could cause GitHub to misparse annotations. Harald now proposes dropping the escaping logic entirely, arguing that the only problematic case—literal `%25`—doesn’t appear in any Git tests, as confirmed by two CI runs. He suggests deferring the issue to a future topic if it becomes necessary.

This is a pragmatic retreat rather than a technical fix, and it leaves the escaping inconsistency unresolved. The decision simplifies the patch but may reintroduce parsing issues if test descriptions ever include unescaped percent signs. The series remains cooking in `next`, and this change is unlikely to derail it, though Phillip or others may revisit the escaping question later. For now, the patch’s core functionality—precise, clickable failure annotations—remains intact.
