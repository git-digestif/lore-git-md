This is the eighth patch in Patrick Steinhardt’s 13-patch series refactoring Git’s object database (ODB) to move alternates handling into the "files" backend. This specific patch adapts the quarantine logic in the `tmp-objdir` subsystem to treat the quarantine directory as an object directory rather than a separate ODB source.

The change is a direct follow-up to earlier patches in the series, particularly the introduction of `struct odb_files_dir` (patch 3/13) and its extension to support multiple directories via a linked list (patch 6/13). Here, the quarantine directory—previously managed as a standalone "files" source—is now integrated into the files backend’s linked list of object directories. The patch replaces `struct odb_source *quarantine` with `struct odb_files_dir *quarantine` in `struct odb_transaction_files` and updates `tmp_objdir_replace_primary_odb()` to create and insert a `struct odb_files_dir` instead of a new source. The `tmp_objdir_restore_source()` helper is similarly refactored to manipulate the linked list directly, removing the temporary directory and restoring the original primary directory.

The patch is mechanical and well-scoped, touching only `object-file.c`, `tmp-objdir.c`, and `tmp-objdir.h`. It removes the now-unused `odb_set_temporary_primary_source()` and `odb_restore_primary_source()` functions from the public ODB API, absorbing their functionality into `tmp-objdir.c` as static helpers. The changes are internal to the quarantine logic and do not affect other subsystems, though they pave the way for the next patch (9/13), which will fully migrate alternates into the files backend.

The commit message is clear and concise, explaining the motivation (preparing for alternates migration) and the technical approach (using the new linked-list infrastructure). The patch looks solid and aligns with the series’ broader goal of simplifying ODB architecture. If you’re following the ODB refactoring effort, this is a key step in the transition, but it’s unlikely to be controversial on its own.
