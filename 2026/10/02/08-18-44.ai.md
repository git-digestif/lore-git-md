This is the second patch in Scott Chacon’s four-part RFC series proposing a new signing mechanism that embeds SHA-256 digests of tree contents in signed commits and tags. This patch specifically teaches `git tag -s` and `git tag -u` a `--hash=sha256` option that adds a `tree-sha256` header to the tag object, making the signature cover the actual file contents rather than just the SHA-1 object names.

The implementation is straightforward: the new option is parsed in `builtin/tag.c`, the digest is computed by the existing `tree_sha256_hex()` helper (introduced in patch 1), and the header is inserted between the `tagger` line and the blank line that precedes the message. The patch enforces that `--hash=sha256` can only be used with signing (`-s` or `-u`), and it rejects unknown algorithms (`--hash=md5`). A new test script (`t/t7032-tree-sha256-signed.sh`) verifies that the header is present, correctly formatted, and covered by the signature, and that older Git versions can still verify the tag.

This patch is a clean, incremental step in the series: it reuses the digest computation from patch 1, adds minimal new code (29 lines in `builtin/tag.c`), and preserves backwards compatibility. The only open question it touches is naming (`--hash=sha256` vs. something else), which the author has already flagged for feedback in the cover letter. The patch itself looks well-crafted and ready for technical review.
