This is the fourth and final patch in Scott Chacon’s RFC series introducing a new signing mechanism that embeds SHA-256 digests of tree contents in signed commits and tags. It adds a `gpg.treeHash` configuration key to make the `--hash=sha256` behavior the default for all signed objects, eliminating the need to specify the option manually.

The patch touches seven files: it documents the new config key in `Documentation/config/gpg.adoc`, updates the `--hash` option descriptions in `git-commit.adoc` and `git-tag.adoc` to mention the override behavior, adds config parsing in `builtin/commit.c` and `builtin/tag.c`, and extends the test script `t/t7032-tree-sha256-signed.sh` with four new test cases. The tests verify that `gpg.treeHash=sha256` automatically adds the `tree-sha256` header to signed commits and tags, leaves unsigned objects untouched, allows `--hash=none` to override the config, and rejects invalid values like `md5`.

The implementation is careful to preserve backwards compatibility: unsigned commits and tags are created exactly as before, and the config only applies when signing is requested. The patch is small (75 lines added) and self-contained, completing the series without introducing new dependencies or behavioral changes beyond what was already established in the earlier patches. The author’s design choice to use a single config key for both commands (`git commit` and `git tag`) is consistent with the shared motivation for the feature.
