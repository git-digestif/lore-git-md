This is the second patch in Scott Chacon’s four-part RFC series proposing a new signing mechanism that embeds SHA-256 digests of tree contents in signed commits and tags. This patch specifically teaches `git tag -s` and `git tag -u` a `--hash=sha256` option that adds a `tree-sha256` header to the tag object, making the signature cover the actual file contents rather than just their SHA-1 object names.

The implementation is straightforward: the new option is parsed in `builtin/tag.c`, the digest is computed by the existing `tree_sha256_hex()` helper (introduced in patch 1), and the header is inserted between the `tagger` line and the blank line that precedes the message. The patch also adds a new test script (`t/t7032-tree-sha256-signed.sh`) that verifies the header is present, correctly formatted, and covered by the signature, and that the option rejects unknown algorithms, unsigned tags, and non-tree objects. Backwards compatibility is preserved: older Git versions simply ignore the extra header.

This patch is well-crafted and clearly motivated. The commit message and code are concise, the test coverage is thorough, and the design fits cleanly into the existing signing machinery. The only open question it touches is naming (`--hash=sha256` vs. something else), which the author has already flagged for discussion. If the overall approach gains traction, this patch looks ready to merge as-is.
