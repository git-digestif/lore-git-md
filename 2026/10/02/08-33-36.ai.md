This is a two-patch performance optimization for the `fetch.writeCommitGraph` feature. The series targets the commit-graph subsystem and introduces a new incremental write strategy that avoids scanning all refs after every fetch.

The cover letter explains the problem clearly: when `fetch.writeCommitGraph` is enabled, Git currently rebuilds the commit-graph from all reachable refs after each fetch, which is inefficient for repositories with many refs. The solution introduces a three-mode enum (`REACHABLE`, `TIPS`, `SKIP`) to control commit-graph writes: skip entirely for no-op fetches, write incrementally from updated refs only when possible, and fall back to a full scan when no existing graph exists or when fetching from multiple remotes.

Patch 1 adds a `commit-info` subcommand to `test-tool read-graph`, enabling tests to verify graph contents. Patch 2 implements the optimization in `builtin/fetch.c` and includes four tests covering incremental writes, unrelated commits, no-op fetches, and fallback cases. The changes touch `commit-graph.c` and `commit-graph.h` for the new enum, and add test coverage in `t/t5510-fetch.sh`.
