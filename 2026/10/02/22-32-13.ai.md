This is a maintainer clarification in the `git bisect` plumbing thread.

Junio C Hamano confirms Jeff King’s earlier suggestion that `refs/bisect/bad` reliably holds the commit hash identified as the bisect culprit. He traces the relevant code path in `bisect.c`, showing that the final "first bad commit" message is printed only when `bisect_rev` matches `current_bad_oid`, which is read directly from `refs/bisect/bad`. Junio also explains a minor optimization: when the bisect algorithm determines that the current `HEAD` is already the culprit, it skips moving `HEAD` but still updates `refs/bisect/bad` to point to that commit. This ensures the ref always reflects the correct result, even when `HEAD` itself does not change. No new behavior or patch is introduced; the email simply reinforces the stability of the existing plumbing mechanism.
