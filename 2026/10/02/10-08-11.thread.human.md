This thread is Patrick Steinhardt’s 13-patch series refactoring Git’s object database (ODB) to move alternates handling into the files backend, eliminating a long-standing architectural mismatch. The goal is to simplify the ODB subsystem, improve performance, and enable future work like pluggable backends. The series is under initial review, with no prior versions, and targets the start of the Git 2.98 cycle.

Karthik Nayak has raised two review comments so far. The first, on patch 1/13, was a surface-level critique of the commit message’s lack of motivation, though the patch itself was deemed correct. The second, on patch 2/13, is more substantive: he identified a potential issue in the test helper `git_test_write_commit_graph_or_die()`, where the function assumes the primary ODB source’s path instead of using the explicit path argument now passed to it. This could break tests targeting non-default object directories, such as alternates or quarantine directories. The rest of the patch appears uncontroversial, but this change—though small—highlights a recurring challenge in the series: ensuring that the shift from implicit ODB sources to explicit repository and path arguments doesn’t introduce edge-case regressions.

The series is large (13 patches, ~500 lines added/removed) and touches core ODB logic, commit-graph handling, and quarantine directories, so further review may surface additional concerns. No maintainer decisions or merge signals have been made yet, and the series remains in the early review phase. Patrick has not yet responded to Karthik’s feedback.
