This thread is about Patrick Steinhardt’s 13-patch series to refactor Git’s object database (ODB) subsystem, moving alternates handling into the "files" backend. The goal is to eliminate a long-standing architectural mismatch where alternates were managed at the ODB source level, causing performance regressions and blocking future work like pluggable backends. The series is now in its second version (v2), which is documentation-only—no code changes were made since v1, only clarifications to the commit messages.

The refactoring is complete and ready for integration, with all review feedback addressed. The key technical change is relocating alternates into the files backend, making them a backend-specific detail rather than a core ODB concern. This involved significant restructuring: introducing a linked list of object directories (`struct odb_files_dir`), removing the `read_alternates` callback from the ODB source interface, and adapting quarantine logic to work with the new structure. The series touches 52 files, with the bulk of changes in `odb.c` and `odb/source-files.c`. No on-disk format changes are introduced, but the internal behavior shifts—alternates are now identified by canonicalized absolute paths, and writes target only the first directory in the linked list.

Karthik Nayak reviewed most of the series, raising a few technical concerns that Patrick resolved. The only unresolved loose end is a minor inconsistency in the test helper `git_test_write_commit_graph_or_die()`, which assumes the primary ODB source’s path. Patrick dismissed this as a test-suite quirk, and Karthik accepted the response. The series has minor merge conflicts with the `seen` branch, but these are documented and should be straightforward to resolve. The main open question is whether the linked-list traversal order for alternates (quarantine directory at the head) could break assumptions in `git gc` or `git repack`, though no issues have been reported yet. The series is now waiting for Junio to pick it up for integration.
