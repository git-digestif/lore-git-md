This thread is Patrick Steinhardt’s 13-patch series refactoring Git’s object database (ODB) to move alternates handling into the files backend, eliminating a long-standing mismatch where alternates were managed at the ODB source level. The goal is to simplify the architecture, improve performance, and enable future ODB work like pluggable backends. The series is still in its initial review phase (v1), with no substantive feedback yet, though its size and potential edge cases (e.g., promisor remotes, partial clones) may pose challenges.

The latest update (patch 9/13) streamlines the `tmp-objdir` API by merging the two-step quarantine setup into a single call. This reduces boilerplate for callers and clarifies the lifecycle of quarantine directories, which are now inserted at the head of the files backend’s linked list immediately upon creation. The change is mechanical and aligns with the series’ broader consolidation effort, though the linked-list design’s implications for alternates ordering (e.g., promisor remotes) remain an open question.

Key technical details include the introduction of `struct odb_files_dir` to manage object directories, the decoupling of the commit-graph subsystem from `struct odb_source`, and the absorption of quarantine logic into `tmp-objdir.c`. The series touches 75 files but makes no on-disk format changes. Merge conflicts with Junio’s `seen` branch are documented but unresolved, so a reroll may be needed. No objections or requests for changes have been raised yet, but the architectural shift warrants scrutiny for edge cases like path canonicalization or backend-agnostic assumptions.
