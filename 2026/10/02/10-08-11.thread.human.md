This 13-patch series from Patrick Steinhardt completes a major refactoring of Git's object database (ODB) subsystem, moving alternates handling into the "files" backend. The work eliminates a long-standing architectural mismatch where alternates were managed at the ODB source level, which caused performance regressions and complicated data structures like bitmaps and commit graphs. The series is now fully reviewed and ready for integration, with all feedback addressed in this documentation-only v2 reroll.

The key achievement is making alternates a backend-specific implementation detail, which paves the way for future ODB work like pluggable backends. The final patch (13/13) removes the now-unused `read_alternates` callback from all ODB backends, completing the shift. While the series touches 52 files and makes significant internal changes—including introducing a linked list of object directories in the files backend—it maintains backward compatibility with no on-disk format changes.

Karthik Nayak provided thorough review across most patches, raising one critical technical concern about a removed NULL check that Patrick successfully resolved. The only remaining hurdle is minor merge conflicts with Junio's `seen` branch, which may require a rebased reroll. If you're tracking Git's ODB evolution, this series is a foundational step toward more flexible storage backends.
