This thread is about Patrick Steinhardt’s 13-patch series refactoring Git’s object database (ODB) to move alternates handling into the "files" backend. The goal is to eliminate a long-standing architectural mismatch where alternates were managed at the ODB source level, causing performance regressions and blocking future work like pluggable backends. The series is now in its second version (v2), which is documentation-only—no code changes were made since v1, only clarifications to the commit messages.

The refactoring is complete and ready for integration, though it has minor merge conflicts with the `seen` branch. Key changes include consolidating alternates into the files backend, removing the `read_alternates` callback, and introducing a linked list of `struct odb_files_dir` to manage multiple object directories. The series touches 52 files, with the bulk of changes in `odb.c` (439 lines removed) and `odb/source-files.c` (482 lines added). No on-disk format changes are made, but the internal behavior shifts subtly—for example, alternates are now identified by their canonicalized absolute paths, which could affect edge cases involving symlinks or relative paths.

Karthik Nayak reviewed several patches, raising one critical technical concern (a potential NULL-dereference regression in `clear_midx_file()`) that Patrick resolved by demonstrating redundancy. Karthik’s other feedback was largely surface-level, focusing on mechanical correctness rather than deeper edge cases like promisor remotes or linked-list invariants. The only unresolved loose end is a minor inconsistency in the test helper `git_test_write_commit_graph_or_die()`, which Patrick dismissed as a test-suite hack. The series is now technically complete, with all review feedback addressed, and awaits integration.
