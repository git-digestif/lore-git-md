This thread is about Patrick Steinhardt’s 13-patch series refactoring Git’s object database (ODB) to move alternates handling into the "files" backend. The goal is to eliminate a long-standing architectural mismatch where alternates were managed at the ODB source level, which caused performance regressions and blocked future work like pluggable backends. The series is now in its second version (v2), which is documentation-only—no code changes were made, but the commit messages were clarified to better explain the motivation.

The series has completed review, with all feedback addressed. Karthik Nayak was the primary reviewer, raising a few technical concerns—most notably about a potential NULL-dereference regression in patch 12/13, which Patrick resolved by demonstrating the check was redundant. Karthik also questioned a test helper’s assumptions in patch 2/13, but Patrick dismissed the concern, and Karthik accepted the response. The series is now ready for integration, though it has minor merge conflicts with the `seen` branch that may require a reroll.

The refactoring touches core ODB code (`odb.c`, `odb/source-files.c`), the commit-graph subsystem, and quarantine logic, among others. Key changes include introducing a new `struct odb_files_dir` to manage object directories, removing the `read_alternates` callback from the ODB source interface, and consolidating alternates into the files backend. The series is purely internal—no on-disk format changes—but its size (13 patches, ~1,000 lines of churn) and architectural implications (e.g., linked-list traversal of alternates) may introduce edge cases, particularly for promisor remotes or partial clones. No deeper review of these risks has emerged yet.

If you’re tracking Git’s ODB work, this series is a prerequisite for future efforts like pluggable backends. It’s now in Junio’s court for integration, pending resolution of the merge conflicts.
