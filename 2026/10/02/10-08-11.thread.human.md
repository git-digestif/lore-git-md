This thread is about a 13-patch refactoring series by Patrick Steinhardt that moves alternates handling into Git’s "files" object database (ODB) backend. The goal is to eliminate a long-standing mismatch where alternates were managed at the ODB source level, which caused performance issues and blocked future work like pluggable backends. The series is under review in its first version (v1), with no prior iterations.

Key changes include consolidating alternates into the files backend, introducing a new `struct odb_files_dir` to manage multiple object directories, and removing the `read_alternates` callback from the ODB interface. The series touches core ODB code, the commit-graph subsystem, and quarantine logic, with no on-disk format changes. Karthik Nayak has reviewed several patches, raising concerns about test helpers and a conceptual question about the architectural decision to eliminate multiple sources per ODB. The latter was resolved when Karthik retracted his question after Patrick clarified that alternates would be managed as a linked list within the files backend.

The series is uncontested in its design direction, but Karthik’s reviews have been surface-level, focusing on mechanical correctness rather than edge cases like linked-list traversal order or promisor remote interactions. The only remaining loose end is a dismissed inconsistency in a test helper, which Patrick argued was acceptable. The series is a prerequisite for future ODB work and has minor merge conflicts with the `seen` branch.
