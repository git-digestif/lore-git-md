This thread is Patrick Steinhardt’s 13-patch series refactoring Git’s object database (ODB) to move alternates handling into the "files" backend. The goal is to eliminate a long-standing architectural mismatch where alternates are managed at the ODB source level, which has caused performance regressions and complicated data structures like bitmaps and commit graphs. The series also decouples the commit-graph subsystem from `struct odb_source`, making it backend-agnostic and paving the way for future ODB work, such as pluggable backends.

The series is currently under review in its initial (v1) form. It builds on the start of the Git 2.98 cycle and has minor merge conflicts with the `seen` branch, which may require a reroll. The refactoring is substantial: 63 files are touched, with nearly 500 lines added to `odb/source-files.c` and a similar number removed from `odb.c`. Key changes include introducing `struct odb_files_dir` to manage object directories, refactoring `odb_for_each_alternate()` to operate on directories instead of sources, and updating commit-graph helpers to use repository and directory paths instead of `odb_source`. The fourth patch, just posted, mechanically adapts `odb_for_each_alternate()` to iterate over `struct odb_files_dir`, updating callers to use the new `abspath` field and ensuring repository context is passed explicitly.

No substantive objections or requests for changes have been raised yet, but the series’ size and architectural implications may pose review challenges. Edge cases like promisor remotes, partial clones, or non-files backends could need closer scrutiny, particularly around path canonicalization and backend-agnostic assumptions. So far, only Patrick has weighed in, framing the series as a necessary step for future ODB improvements. The work stands alone, with no dependencies on other in-flight topics.
