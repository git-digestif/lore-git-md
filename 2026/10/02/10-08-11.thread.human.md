This thread is a 13-patch series by Patrick Steinhardt refactoring Git’s object database (ODB) to move alternates handling into the "files" backend. The goal is to eliminate a long-standing architectural mismatch where alternates were managed at the ODB source level, which caused performance regressions and blocked future work like pluggable backends. The series is now complete with the posting of patch 13/13, which removes the now-unused `read_alternates` callback from the ODB source interface—a cleanup step that follows from the earlier relocation of alternates logic into the files backend.

The refactoring touches nearly every part of the ODB subsystem, including core ODB code, the files backend, quarantine logic, and the commit-graph subsystem. Key changes include replacing `struct odb_source` with `struct odb_files_dir` (a linked list of object directories), decoupling the commit-graph subsystem from `odb_source`, and absorbing quarantine logic into `tmp-objdir.c`. The series is under initial review, with no substantive objections yet, but reviewers are encouraged to focus on edge cases like promisor remotes, partial clones, and path canonicalization robustness. The series is built on the start of the Git 2.98 cycle and has minor merge conflicts with the `seen` branch, which may require a reroll.

The final patch is purely mechanical and uncontroversial if the rest of the series is accepted. It removes the `read_alternates` callback from all ODB backends, reflecting the fact that alternates are now an internal implementation detail of the files backend. No behavior changes or new logic are introduced. The series is a prerequisite for future ODB work, including pluggable backends and alternates-related fixes.
