Subject: [PATCH 0/2] fetch: optimize commit-graph write strategy for large repos

Core problem or goal
When `fetch.writeCommitGraph` is enabled, Git currently rebuilds the commit-graph from all reachable refs after every fetch, which is inefficient for repositories with many refs. The goal is to introduce an incremental write strategy that avoids scanning all refs after every fetch by writing only the newly fetched commits when possible, falling back to full scans only when necessary (e.g., no existing graph or multi-remote fetches).

Key technical details
- Subsystem: commit-graph
- Files touched: `builtin/fetch.c`, `commit-graph.c`, `commit-graph.h`, `t/helper/test-read-graph.c`, `t/t5510-fetch.sh`, `t/t5537-fetch-shallow.sh`
- New enum: `enum commit_graph_write_strategy { COMMIT_GRAPH_WRITE_REACHABLE, COMMIT_GRAPH_WRITE_TIPS, COMMIT_GRAPH_WRITE_SKIP }`
- New data structure: `oidset` in `builtin/fetch.c` to track updated refs during `do_fetch()`
- New APIs: `lookup_commit_in_graph()` and `commit_graph_generation()` (exposed for test helper and fetch logic); `prepare_commit_graph()` made non-static to allow fetch command to check for existing graph
- New test helper: `test-tool read-graph commit-info` (22 lines in `t/helper/test-read-graph.c`), used to verify commit presence and generation numbers in the commit-graph. Exits with status 1 if any queried commit is missing.
- Behavior: incremental writes from updated refs only when possible; fallback to `COMMIT_GRAPH_WRITE_REACHABLE` when no existing graph exists or when fetching from multiple remotes. No-op fetches (`COMMIT_GRAPH_WRITE_SKIP`) avoid unnecessary writes. The seeds passed to `write_commit_graph()` are **additive**, extending the existing graph (relying on split mode, `COMMIT_GRAPH_WRITE_SPLIT`). Non-split mode is not used by fetch, but if it were, the incremental path would require `COMMIT_GRAPH_WRITE_APPEND` or a fallback to the full reachable scan to avoid coverage loss.
- Performance: In a synthetic setup (git.git with 200K extra packed refs), incremental write reduces `fetch/write-commit-graph` time from ~357ms to ~9.3ms for a single ref update; no-op fetches are skipped entirely.
- Test coverage: six new tests in `t/t5510-fetch.sh` and `t/t5537-fetch-shallow.sh` covering incremental writes, exclusion of unrelated commits, no-op fetches, fallback cases, no coverage loss after incremental writes, and correct handling of shallow refs.
