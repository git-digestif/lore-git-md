Subject: [PATCH 0/2] fetch: optimize commit-graph write strategy for large repos

Core problem or goal
When `fetch.writeCommitGraph` is enabled, Git currently rebuilds the commit-graph from all reachable refs after every fetch, which is inefficient for repositories with many refs. The goal is to introduce an incremental write strategy that avoids scanning all refs after every fetch by writing only the newly fetched commits when possible, falling back to full scans only when necessary (e.g., no existing graph or multi-remote fetches).

- New test helper: `test-tool read-graph commit-info` (22 lines in `t/helper/test-read-graph.c`)
- Behavior: incremental writes from updated refs only when possible; fallback to `COMMIT_GRAPH_WRITE_REACHABLE` when no existing graph exists or when fetching from multiple remotes. No-op fetches (`COMMIT_GRAPH_WRITE_SKIP`) avoid unnecessary writes. The patch’s fallback logic implies seeds are additive (extending the existing graph), but this is not explicitly stated in the commit message.
- Test coverage: four new tests in `t/t5510-fetch.sh` covering incremental writes, exclusion of unrelated commits, no-op fetches, and fallback cases
