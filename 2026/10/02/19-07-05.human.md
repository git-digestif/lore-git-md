This is the second half of a two-patch series adding `--[no-]range-diff-notes` to `git format-patch`. The author, Kristoffer Haugsbakk, has revised the commit message and documentation in response to Junio C Hamano’s feedback on the first version of this patch. Junio suggested making the commit message more concise and the documentation more direct, and Kristoffer has adopted those changes here.

The patch itself remains functionally unchanged from v2. It introduces two new command-line options: `--range-diff-notes=<ref>` (which requires an explicit ref argument) and `--no-range-diff-notes` (which suppresses notes in the range-diff section). The implementation is clean, using a new `struct rdiff_notes` to track whether the user wants to override the default notes behavior for range-diffs, and simplifying the `rev_info` struct by removing a now-redundant flag. The option callback has also been refactored to wrap `parse_opt_string_list` rather than duplicating its logic, as Junio recommended.

Test coverage is thorough, verifying scenarios like suppressing all range-diff notes, using different notes refs for patches and range-diffs, and ensuring `--range-diff-notes` requires a value. The patch also includes regression tests for a single-patch case bug fixed in an earlier commit. Documentation has been updated to reflect the simplified behavior, removing references to the toggle mechanism and clarifying the explicit separation between patch notes and range-diff notes.

This patch is technically complete and addresses all of Junio’s feedback from v2. The series as a whole is now ready for maintainer approval, with no substantive concerns remaining. If accepted, it will allow users to control notes in the range-diff section independently of the patch output, a feature that has been requested and refined over multiple iterations.
