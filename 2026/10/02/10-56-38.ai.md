This is the first patch in Kristoffer Haugsbakk’s v3 series introducing `--[no-]range-diff-notes` to `git format-patch`. It is a refactoring patch that simplifies the `get_notes_args` function by removing a redundant parameter.

The patch builds on prior commit 85bd88a7 (2025-09-25), which added `rdiff_log_arg` to `struct rev_info`. The current implementation passes both `rev->rdiff_log_arg` and `rev` to `get_notes_args`, even though the function can access `rdiff_log_arg` directly through the `rev` pointer. This patch removes the redundant first parameter, making the function signature cleaner and more consistent. The change is mechanical and does not alter behavior; it only touches `builtin/log.c` and updates the function’s call site.

The commit message is clear and well-motivated, explaining the redundancy and the rationale for the change. The patch itself is small (7 insertions, 5 deletions) and focused, with no functional impact. The only additional change is reformatting a long `for_each_string_list` line for readability. The patch is compile-tested and uncontroversial, serving as a preparatory step for the new functionality introduced in patch 2/2.

Key technical details: the function `get_notes_args` now takes only `struct rev_info *` as a parameter, and the call site in `cmd_format_patch` is updated accordingly. The patch does not introduce new names or options, but it is a necessary precursor to the next patch, which implements the `--[no-]range-diff-notes` feature.
