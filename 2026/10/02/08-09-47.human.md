This is the second patch in Patrick Steinhardt’s v2 series introducing subcommand grouping to Git’s parse-options API. It is a pure refactoring patch that extracts the logic for printing a single option into two new helper functions: `usage_print_flag()` (which formats the option’s flags and arguments) and `usage_print_option()` (which handles the full output, including help text and aliases).

The patch touches only `parse-options.c` and is motivated by the need to reduce nesting and improve readability in `usage_with_options_internal()` before adding the new subcommand grouping logic in the next patch. The extracted functions are cleanly separated: `usage_print_flag()` returns the number of characters printed, while `usage_print_option()` manages the surrounding formatting (newlines, indentation, and help text wrapping). The diff is mechanical and well-contained, with no behavior changes.

This refactoring directly addresses Junio C Hamano’s feedback from v1, which called for reducing nesting and improving the structure of the option-printing logic. The patch is clearly well-crafted and uncontroversial; it is a necessary preparatory step for the core API changes that follow. No new reviews have been posted yet, but the patch looks ready for further scrutiny. The next patch in the series will build on this foundation to introduce the actual subcommand grouping API.
