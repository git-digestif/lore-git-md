This is the eighth patch in Patrick Steinhardt’s 13-patch series refactoring the object database (ODB) to move alternates handling into the files backend. This specific patch adapts the quarantine logic in `tmp-objdir.c` to manage the temporary object directory as a `struct odb_files_dir` instead of a standalone `struct odb_source`.

The patch is a mechanical but important step in the series’ broader goal of consolidating alternates into the files backend. Previously, `tmp_objdir_replace_primary_odb()` created a new "files" source for the quarantine directory, which would conflict with the upcoming changes to handle alternates as part of the files backend’s linked list of directories (introduced in patch 6/13). Here, the quarantine directory is now represented as a `struct odb_files_dir`, which includes both loose and packed sources and integrates cleanly with the linked-list design.

Key changes:
- The `tmp_objdir` struct replaces its `prev_source` field with `temp_dir` (the new quarantine directory) and `orig_dir` (the original primary directory).
- `tmp_objdir_replace_primary_odb()` now returns a `struct odb_files_dir` instead of a `struct odb_source`, and the quarantine directory is inserted at the head of the files backend’s linked list.
- The `will_destroy` flag is propagated to both the loose and packed sources within the quarantine directory.
- `tmp_objdir_restore_source()` is updated to handle the linked-list structure, ensuring the original primary directory is restored correctly.

The patch touches only three files (`object-file.c`, `tmp-objdir.c`, and `tmp-objdir.h`) and maintains backward compatibility with the rest of the codebase. The changes are internal to the quarantine logic and do not affect user-visible behavior. The commit message clearly explains the motivation: preparing for the upcoming alternates refactoring while leveraging the linked-list infrastructure already introduced in the series.

This patch is a clean, focused refactoring with no obvious red flags. It aligns with the series’ architectural direction and sets the stage for patch 9/13, which will further integrate alternates into the files backend. If you’re following the ODB refactoring effort, this is a logical and necessary step.
