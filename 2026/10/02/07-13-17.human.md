This is the third patch in Harald Nordgren’s four-patch series introducing a "matching-inspired" fetch mode for shallow repositories. It adds a `--limited-fetch` flag to `git remote add` that explicitly opts a remote into the new mode by writing a `remote.<name>.refmap` entry instead of the usual wildcard `remote.<name>.fetch` refspec.

The patch is small and focused: it updates `builtin/remote.c` to parse the new flag, rejects it when combined with `-t/--track` or `--mirror` (since those already specify what to fetch), and writes the refmap configuration (`+refs/heads/*:refs/remotes/<name>/*`) when the flag is used. Documentation in `git-remote.adoc` explains the flag’s purpose and links to `git-fetch(1)` for details on `--refmap`. Tests in `t/t5505-remote.sh` verify the flag works in non-shallow repositories and correctly rejects incompatible combinations.

This patch is uncontroversial and well-motivated. The `--limited-fetch` flag provides a clean way for users to opt into the new fetch mode, and the implementation is straightforward. The only edge case noted in the series (a bare `git fetch` against a refmap-only remote fetches no branches) is unrelated to this patch and already acknowledged by the author as a minor quibble. The patch is ready for integration and should land as part of the series once Junio completes his re-review.
