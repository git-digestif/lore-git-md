This is a minor follow-up to the first patch in Patrick Steinhardt’s three-patch series introducing subcommand grouping to Git’s parse-options API. The patch itself is a bugfix for `--git-completion-helper` output formatting: when the first option is skipped (e.g., because it is a group or hidden), the helper incorrectly prints a leading space. The fix adds a boolean flag to track whether anything has already been printed, ensuring no leading space is emitted.

Junio’s review of the original patch was positive, with only a stylistic preference for the variable name `shown` over `first`. Patrick accepts this suggestion, noting that `shown` better reflects the intent—tracking whether any output has been printed, not just whether the first option was processed. This change is uncontroversial and aligns with the series’ broader goal of improving the parse-options API for grouped subcommands. The fix is now effectively settled, pending any further feedback on the rest of the series. No code changes are needed beyond the variable rename.
