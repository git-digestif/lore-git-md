This is the first patch in Christian Couder’s five-part v5 series introducing `uploadpack.lazyFetchTrusted`, a server-side mechanism for marking repositories as trusted for lazy fetching. This patch is a pure refactoring with no intended behavior change, extracting the lazy-fetch logic from `fetch_objects()` and `promisor_remote_get_direct()` into a new `lazy_fetch_objects()` helper.

The refactoring consolidates the `GIT_NO_LAZY_FETCH` environment variable check into a single up-front call, avoiding redundant checks across multiple promisor remotes. It also moves the `promisor_remote_init()` call into the new helper, aligning with the convention that initialization should happen where the data is needed. The patch adds clear documentation for both `try_promisor_remotes()` and the new `lazy_fetch_objects()`, explicitly stating ownership rules for the `to_free` argument to prevent misuse.

This patch is well-motivated and cleanly executed. The commit message explains the rationale thoroughly, and the code changes are minimal and focused. Since it’s a refactoring with no behavioral impact, it could be merged early if the rest of the series stalls.
