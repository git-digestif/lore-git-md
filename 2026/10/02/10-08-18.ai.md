This is the seventh patch in Patrick Steinhardt’s 13-patch series refactoring the object database (ODB) to move alternates handling into the files backend. It absorbs the temporary-primary-source logic from the generic ODB layer (`odb.c`) into the `tmp-objdir` subsystem, which is now the sole user of that functionality.

The patch removes `odb_set_temporary_primary_source()` and `odb_restore_primary_source()` from `odb.h` and `odb.c` (45 lines deleted) and reimplements their core logic as static helpers inside `tmp-objdir.c` (34 lines added, net -11). The new helpers—`tmp_objdir_restore_source()` and the updated `tmp_objdir_replace_primary_odb()`—directly manipulate the ODB’s source list and `disable_ref_updates` flag, mirroring the old generic functions but now scoped to the quarantine use case. The change is purely internal: no behavior or API changes are visible outside `tmp-objdir.c`.

This is a clean, well-motivated refactoring that aligns with the series’ goal of making alternates an implementation detail of the files backend. The commit message clearly explains why the move is safe (only `tmp-objdir` uses the functionality) and how it prepares for the architectural shift. The diff is straightforward and the patch is small enough to review in isolation, though it depends on the earlier patches that introduced `struct odb_files_dir` and refactored alternates iteration. If you’re tracking the ODB refactoring effort, this patch is a logical next step and unlikely to be controversial.
