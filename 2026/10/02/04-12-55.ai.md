This is a **bugfix** targeting the reference-transaction hook, specifically in branch copy/rename operations.

The email reports that several Git commands update references without triggering the `reference-transaction` hook as documented in `githooks(5)`. The affected operations include `git branch -C` (copy branch, overwriting an existing destination), `git branch -c` (copy branch, creating a new destination), `git branch -m/-M` (rename branch), and `git reflog delete --updateref --rewrite`. The issue occurs on both the files and reftable backends, though the exact behavior differs slightly between them.

The author provides a minimal reproduction script demonstrating the problem: a hook configured to log all reference-transaction events remains silent when `git branch -C` overwrites an existing branch, while the same hook correctly fires for `git branch -f`. The gap prevents tools relying on this hook from enforcing branch protection policies for these operations.

It originates from work on a branch-protection tool, suggesting a real-world use case is affected. No patch is included, so this is currently a bug report rather than a fix. The issue appears to be a missing hook invocation in the ref-update plumbing rather than a documentation error.
