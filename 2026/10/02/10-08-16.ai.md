This is the fifth patch in Patrick Steinhardt’s 13-patch series refactoring the Git object database (ODB) to move alternates handling into the "files" backend. The patch refactors `odb_find_source()`—a core ODB function that locates an object directory by path—to operate on the new `struct odb_files_dir` instead of the generic `struct odb_source`. This change is a key step in the series’ goal of making alternates an implementation detail of the files backend.

The patch is mechanical but consequential. It removes the generic `odb_find_source()` and `odb_find_source_or_die()` functions from `odb.c` and `odb.h`, replacing them with a files-backend-specific `odb_source_files_find_dir()` in `odb/source-files.c`. Callers in `builtin/commit-graph.c`, `builtin/multi-pack-index.c`, and `t/helper/test-read-midx.c` are updated to use the new function, which returns a `struct odb_files_dir` (introduced in patch 3/13) instead of a generic `struct odb_source`. The changes are straightforward: replace `source->path` with `dir->abspath`, and use `odb_source_files_downcast()` where needed to access the files-specific fields.

The patch touches 7 files and 143 lines, with most of the churn in `builtin/multi-pack-index.c` (42 lines changed) due to the shift from `struct odb_source_files` to `struct odb_source_packed` in the `handle_object_dir_option()` helper. The commit message is clear and concise, framing the change as a natural follow-up to the preceding patch (which refactored `odb_for_each_alternate()` similarly).

This is a well-scoped refactoring that aligns with the series’ architectural direction. The new `odb_files_dir` abstraction is now used consistently for both iterating over alternates (patch 4/13) and finding a specific directory (this patch), setting the stage for the later patches that will fully absorb alternates into the files backend. No behavioral changes are introduced, and the patch is unlikely to be controversial—though reviewers may scrutinize the path canonicalization logic (e.g., `real_pathdup()` and `strbuf_realpath()`) for edge cases like symlinks or relative paths. The series’ size and scope suggest this is a carefully considered effort, and this patch is a logical step in the progression.
