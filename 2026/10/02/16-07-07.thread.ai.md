Originating author: Julia Evans

Core problem or goal
Remove redundant empty SYNOPSIS blocks from Git’s section 7 man pages (conceptual guides and tutorials) and update the `lint-man-section-order.perl` script to exempt section 7 documents from requiring a SYNOPSIS, as these pages are descriptive rather than command-oriented. The implementation must now also preserve the script’s ability to process multiple input files without misclassifying or skipping sections in files after the first.

Current status
Under review; awaiting maintainer decision on implementation approach. The patch is self-contained, touches only documentation files (`Documentation/*.adoc` and `lint-man-section-order.perl`), and has passed local testing (`make lint-docs` and manual inspection) for single-file cases. Junio C Hamano provided a substantive review identifying a maintainability issue in the linter script, proposed an alternative loop-based implementation, and later corrected a one-line bug in that proposal (replacing `<>` with `$line` in the section-detection block). Julia Evans has now identified a functional regression in her original patch: it reads only the first line of the first input file, breaking multi-file processing. She remains open to Junio’s corrected loop-based version or an alternative using Perl’s `Tie::File` module, which would treat the input file as an array and eliminate manual line-by-line reading.

Key technical details
- Files touched: `lint-man-section-order.perl` (modified to skip SYNOPSIS check for section 7; Junio’s feedback restructures the loop logic to keep all input processing inside the main loop, with the follow-up fix ensuring the first line is not skipped), plus 11 `.adoc` files in `Documentation/` (empty SYNOPSIS blocks removed).
- No new symbols, CLI options, or on-disk format changes.
- Test coverage: `make lint-docs` verifies the linter change for single-file cases; manual inspection confirmed the rendered output of affected files. Multi-file processing remains untested due to the regression.
- Junio’s review and follow-up add 15 lines to the linter script, focusing on loop structure, future customizability for other man sections, and correctness of input handling. The regression affects the script’s core functionality (processing multiple files sequentially via `<>`).
- Julia’s `Tie::File` suggestion is a core Perl module, so no external dependency would be introduced. This approach would abstract file handling entirely, potentially resolving the multi-file issue by treating each file as a separate array.

Open questions and loose ends
- Implementation choice: Junio must decide between his corrected loop-based implementation (which may still need refinement for multi-file handling) and Julia’s `Tie::File` alternative. The core goal (exempting section 7 man pages from SYNOPSIS requirements) remains uncontested, but the regression must be fixed before merging.
- Multi-file correctness: The linter’s ability to process multiple input files without misclassifying sections is now a blocker. Neither Junio’s loop-based proposal nor Julia’s original patch addresses this fully; the `Tie::File` approach may offer a cleaner solution but has not been prototyped.
