Core problem or goal
Remove redundant empty SYNOPSIS blocks from Git’s section 7 man pages (conceptual guides and tutorials) and update the `lint-man-section-order.perl` script to exempt section 7 documents from requiring a SYNOPSIS, as these pages are descriptive rather than command-oriented. The implementation must correctly handle multiple input files without misclassifying or skipping sections in files after the first.

Current status
Merged to `master` (date unknown). The patch is procedurally complete, uncontested, and self-contained. Junio’s post-merge feedback suggests minor robustness improvements to the Perl script (initializing `$man_section_number` to `"0"` and avoiding autovivification of `optional_in_man_sections`), while Julia Evans proposes an alternative approach: explicitly reporting an error if the first line of a file does not match the expected `gitglossary(7)` pattern, rather than silently defaulting. Neither approach affects the patch’s core correctness or merge status; both are optional refinements.

Key technical details
- Files touched: `lint-man-section-order.perl` (modified to add `optional_in_man_sections` to `%SECTIONS`, move man section detection into the main loop, and reset section tracking at file boundaries using `$.`), plus 11 `.adoc` files in `Documentation/` (empty SYNOPSIS blocks removed).
- No new CLI options, symbols, or on-disk format changes.
- Test coverage: `make lint-docs` verifies the linter change for single-file and multi-file cases; manual inspection confirmed rendered output of affected files.
- Implementation preserves the script’s ability to process multiple files sequentially via `<>`, using `$.` to reset the man section number at each file boundary. Junio’s feedback highlights two edge cases: (1) undefined `$man_section_number` if the first line of a file does not match the expected pattern, and (2) potential autovivification of `optional_in_man_sections` for sections without optional blocks. Julia’s alternative prioritizes explicit error reporting over silent fallback for the first edge case.
- Earlier approaches (Julia’s `Tie::File` suggestion, Junio’s `eof`-based solution) are superseded by Tuomas’s declarative design.
