This is the third patch in Scott Chacon’s four-patch RFC series proposing a new signing mechanism that embeds SHA-256 digests of tree contents in signed commits and tags. The series aims to provide a migration path away from SHA-1 without requiring Git 3.0 to switch the default object format to SHA-256.

This patch teaches `git commit -S` the `--hash=sha256` option, mirroring the functionality already added to `git tag` in patch 2. When used, it computes a SHA-256 digest over every file in the commit’s tree (including submodules) and embeds it as a `tree-sha256` header in the commit object, immediately before the GPG signature. The signature therefore covers both the commit metadata and the tree digest, while older Git versions simply ignore the extra header. The implementation handles amending correctly: it drops any existing `tree-sha256` header (since the tree has changed) and recomputes it only if the amended commit is signed with `--hash=sha256`.

The patch is small and focused: 38 lines added to `builtin/commit.c`, 11 lines to the documentation, and 49 lines to the new test script `t/t7032-tree-sha256-signed.sh`. The tests verify that the header is added only when requested, that signing is required, that unsupported algorithms are rejected, and that amending recomputes or drops the header as appropriate. The code is clean and the commit message is clear, though the series remains explicitly experimental and the author is soliciting feedback on whether this approach is viable as an alternative to switching the default hash in Git 3.0.
