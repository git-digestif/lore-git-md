This is the v5 cover letter for Christian Couder’s five-patch series introducing `uploadpack.lazyFetchTrusted`, a server-side protected configuration variable that lets operators explicitly mark repositories as trusted for lazy fetching. The series is now in its fifth iteration, with no functional code changes since v4—only improvements to code comments, documentation, tests, and commit messages.

The core goal remains unchanged: replacing the earlier client-side `GIT_NO_LAZY_FETCH=fromAccepted` proposal with a server-controlled trust model to address security concerns about untrusted repositories triggering arbitrary code execution via lazy-fetch hooks or configuration. The new approach shifts trust decisions entirely to the server operator, modeled after Git’s `safe.directory` mechanism.

Key refinements in v5 focus on clarity and edge-case handling. Patch 2/5 now includes a `NEEDSWORK` comment flagging the latent design issue in `safe.directory` (silent ignoring of non-existent paths), which could propagate to `uploadpack.lazyFetchTrusted`. The documentation in patch 5/5 has been expanded to clarify how repositories are identified—particularly when using `--separate-git-dir` or linked worktrees—and to emphasize that trust does *not* propagate to promisor remotes (unlike `GIT_NO_LAZY_FETCH=0`). New tests verify these behaviors, including a case where a repository’s `.git` file points to a separate git directory and another where a trusted repository’s promisor remote is *not* automatically trusted.

The series touches the promisor-remote subsystem (`promisor-remote.c`), `setup.c` (for path allowlist logic), `upload-pack.c`, and adds new tests in `t/t5710-promisor-remote-capability.sh` and `t/t0410-partial-clone.sh`. Key symbols include `upload_pack_lazy_fetch_trusted()` (checks if a repository is trusted), `GIT_INTERNAL_LAZY_FETCH_DEPTH` (limits recursion depth to 5), and `path_allowlist_config_apply()` (a generic helper for path validation). The final patch (5/5) activates the mechanism by conditionally *not* setting `GIT_NO_LAZY_FETCH=1` for trusted repositories, preserving operator control over the environment variable.

Junio’s feedback from v4 is fully addressed, including grammar fixes in the documentation ("each of which" → "each value of which", commas after "i.e." and "e.g.") and a more precise explanation of how repositories are identified. The unresolved high-weight concerns from earlier iterations—Junio’s scalability critique about memory overhead in `lazy_fetch_objects()` and conceptual doubt about using a configuration variable—remain but are mitigated by the server-side design. CI tests pass, and the series is rebased on Git 2.56 (a018953688). No new substantive reviews have been posted since v4.
