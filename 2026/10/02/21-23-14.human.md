This is the second patch in a two-patch series adding GPG commit signing support to `git replay` via a new `-S` option. Junio C Hamano replies to the author, Patrick Monette, to point out a striking similarity between this work and an in-flight series from Tian Yuchen that adds signing support to `git history`. The two efforts touch nearly identical code paths in the commit-creation logic, and Junio explicitly asks Monette to review Tian’s series instead of duplicating effort. He suggests that Monette’s work should be rebased on top of Tian’s once it stabilizes, salvaging any `git replay`-specific differences afterward.

The patch itself is well-structured: it introduces `-S`/`--gpg-sign` and `--no-gpg-sign` options, updates the man page, and adds a thorough test script covering signing behavior, key selection, and error cases. The implementation ignores `commit.gpgSign` for plumbing command consistency, a design choice that Patrick Steinhardt previously questioned but that remains unresolved. The test coverage is particularly strong, verifying edge cases like missing keys and ref rollback on failure.

Junio’s response effectively blocks this series until Tian’s `git history` signing work lands. The conflict is not technical but rather a matter of reviewer bandwidth and avoiding duplicated effort. No substantive changes to the patch are required—only a rebase once the dependency is resolved. The author has not yet acknowledged the merge order requirement, so the series remains in limbo until that happens. For now, this is a clean, well-tested feature addition that is ready for review but cannot proceed further until the `git history` series is merged.
