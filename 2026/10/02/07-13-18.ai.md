This is the fourth and final patch in Harald Nordgren’s v5 series introducing a "matching-inspired" fetch mode for shallow repositories. It makes `--limited-fetch` the default behavior when adding a remote in a shallow repository, unless the user explicitly opts out with `--no-limited-fetch` or specifies `-t/--track` or `--mirror`.

The patch modifies `builtin/remote.c` to check `is_repository_shallow()` and enable `--limited-fetch` by default in shallow repositories. The logic is clean: it preserves backward compatibility for full repositories (which continue using wildcard refspecs) and respects explicit user overrides (`--no-limited-fetch`, `-t`, or `--mirror`). Documentation in `git-remote.adoc` is updated to explain the new default and how to opt out. Tests in `t/t5505-remote.sh` cover the shallow-repository default, explicit `-t` in shallow repos, wildcard refspecs in full repos, and `--no-limited-fetch` override.

This patch directly addresses the performance issue motivating the series: shallow repositories with many remote branches no longer negotiate history for all branches when fetching. The implementation is well-scoped, with no on-disk format changes beyond the new configuration entry introduced in Patch 1/4. The edge case noted in the cover letter (a bare `git fetch` against a refmap-only remote fetches no branches) does not affect this patch, as it only changes `git remote add` behavior.
