This is the v6 cover letter for a three-patch bugfix series targeting the `rerere` subsystem. The series addresses a long-standing race condition where background maintenance tasks (like `git rerere gc`) can deadlock or kill an in-progress rebase when both try to acquire the `MERGE_RR.lock` simultaneously. The issue became more pronounced after Git 2.54 introduced a geometric maintenance strategy that triggers `rerere gc` more aggressively.

The series is now in its final form, with all prior feedback incorporated. Patch 1 makes all `rerere` writers wait for the lock with a configurable timeout (`rerere.lockTimeout`, defaulting to 1000 ms). Patch 2 introduces a hidden `--skip-locked` mode for `git rerere gc` (renamed from `--auto` in v5), which allows background maintenance tasks to skip silently if the lock is held, matching the behavior of other auto-maintenance tasks. Patch 3 allows conflict-stopping commands (e.g., `git rebase`, `git merge`, `git am --3way`) to proceed with a warning if the lock remains held after the timeout, while post-resolution recording (e.g., `git rebase --continue`, `git commit`) and explicit `git rerere` commands still fail immediately.

The v6 changes are minor but important: the `--auto` flag was renamed to `--skip-locked` (hidden and undocumented) to clarify its purpose, and the `RERERE_SKIP_LOCKED` flag in patch 3 was renamed to `RERERE_WARN_LOCKED` to avoid confusion with the new `RERERE_NOWAIT` flag. The documentation was also updated to reflect these changes, and a new test was added to cover the merge case in `git rebase -r`. The series is well-motivated, with clear test coverage and a pragmatic trade-off between resilience (allowing conflict stops to proceed) and correctness (failing post-resolution recording).

This is a clean, targeted fix for a real-world problem that has caused frustration for users since Git 2.54. The solution preserves backward compatibility and follows established patterns from other lock-timeout mechanisms in Git. The series looks ready for merging, with no outstanding technical concerns.
