This is the **reply to a substantive review** of the second patch in Kristofer Karlsson’s two-patch series optimizing `fetch.writeCommitGraph` for large repositories. The series aims to replace the current full-reachability scan after every fetch with an incremental write using only the newly updated refs as seeds.

Kristofer **clarifies the core design question** raised by Patrick Steinhardt: the seeds passed to `write_commit_graph()` are **additive**, extending the existing graph rather than replacing it. This relies on fetch always using split mode (`COMMIT_GRAPH_WRITE_SPLIT`), where new commits are written as a new layer on top of the existing chain. He acknowledges the need to document this behavior more explicitly and plans to extend the test to verify that pre-existing commits remain in the graph after a fetch.

On **non-split mode**, Kristofer confirms that the fetch path never uses it, but notes that if it ever did, the incremental path would need `COMMIT_GRAPH_WRITE_APPEND` or a fallback to the full reachable scan to avoid losing coverage. This addresses Patrick’s concern about edge-case behavior.

The **ref status filtering** question is resolved: `collect_updated_tips()` only needs to skip `REF_STATUS_REJECT_SHALLOW` because other `REF_STATUS_*` values (like `REF_STATUS_OK`) are push-side only. During fetch, refs remain at `REF_STATUS_NONE` unless rejected for shallow reasons, so filtering for `REF_STATUS_OK` would skip all refs. Kristofer suggests using `status != REF_STATUS_NONE` as a future-proof alternative.

The **`old_oid` vs. `new_oid` confusion** is explained: in the fetch `ref_map`, `rm->old_oid` holds the remote’s advertised value (the new tip being fetched), while `rm->peer_ref->old_oid` holds the local ref’s current value. The code uses `rm->old_oid` to collect the new tips and skips refs where the local and remote values match. `rm->new_oid` is unused during fetch; it’s populated later during `store_updated_refs()`.

Kristofer **provides benchmark numbers** for the first time, showing dramatic improvements in synthetic tests: a no-op fetch goes from 380ms to being skipped entirely, while fetches updating 1 or 10 refs drop from ~360ms to ~9ms. These numbers will be included in the reroll’s cover letter.

The **`GRAPH_WRITE_SKIP` redundancy** is justified: the explicit mode is needed to distinguish between a no-op fetch (where skipping is correct) and the multi-remote path (where a full reachable scan is required). Deriving the mode from `oidset_size()` alone would incorrectly skip writes for `fetch --all`.

The reroll will update the commit message to clarify these points, extend test coverage, and include performance data. The series remains **under review**, but the exchange resolves the key correctness questions and strengthens the patch’s rationale.
