This is a usability bugfix discussion targeting the configuration subsystem. Brian M. Carlson joins the thread to weigh in on the `git config --list --show-origin` inconsistency, where `.git/config` is displayed as a relative path (`file:.git/config`) while all other configuration sources show full paths.

Carlson supports switching to an absolute, canonicalized (symlink-free) path for `.git/config`, aligning with how other paths in the output are already handled. He acknowledges the potential for script breakage but considers it low-risk, noting that users can already determine the local config file’s absolute path using `git rev-parse --path-format=absolute --git-path config`. His position reinforces the argument for consistency over backward compatibility in this case, though the thread remains open to further input on the trade-offs.

The discussion is still exploratory, with no patch proposed yet. The key technical detail here is the preference for canonicalized absolute paths, which would require a display-layer change in the configuration subsystem and a new test in `t/t1300-config.sh`. The thread’s focus is now on whether to adopt absolute paths or Patrick Steinhardt’s intermediate proposal (relative to the current working directory when outside the repository root).
