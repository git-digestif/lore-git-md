Thread identity
Subject: [PATCH 0/13] Move alternates into the files ODB backend
Series version: v1 (initial submission)
Originating author: Patrick Steinhardt
Thread type: patch series (refactoring)

Core problem or goal
Refactor the Git object database (ODB) subsystem to move alternates handling into the "files" backend, eliminating a conceptual mismatch where alternates are currently managed at the ODB source level. This mismatch causes performance regressions, complicates data structures (bitmaps, commit graphs), and prevents backend-agnostic extensions to `GIT_OBJECT_DIRECTORY` and `GIT_ALTERNATE_OBJECT_DIRECTORIES`. The series lays the groundwork for future ODB work by consolidating alternates into the files backend, where they belong, and making the commit-graph subsystem backend-agnostic.

Current status
Under review (initial submission, v1). The series is built on commit `c46c1e3772` (start of the Git 2.98 cycle) and has minor merge conflicts with the `seen` branch, as documented in the cover letter. No prior versions exist.

Key technical details
- **Subsystems/files touched**: ODB core (`odb.c`, `odb.h`), files backend (`odb/source-files.c`, `odb/source-files.h`), quarantine logic (`tmp-objdir.c`, `tmp-objdir.h`, `object-file.c`), `builtin/commit-graph.c`, `commit-graph.c`, `commit-graph.h`, `builtin/count-objects.c`, `builtin/submodule--helper.c`, `diagnose.c`, `builtin/multi-pack-index.c`, `t/helper/test-read-midx.c`, and 75 files total.
- **New/renamed symbols**:
  - `struct odb_files_dir` (manages multiple object directories, introduced in patch 3/13; encapsulates `loose`, `packed`, absolute path, `local` flag, and now a `next` pointer for linked-list traversal of multiple directories, added in patch 6/13)
  - `odb_source_files_find_dir()` (files-backend-specific replacement for `odb_find_source()`, introduced in patch 5/13)
  - Refactored `odb_for_each_alternate()` and `odb_find_source()` (now operate on directories, not sources)
  - Absorbed quarantine logic into `tmp-objdir` as an object directory (patch 7/13 and 8/13: removed `odb_set_temporary_primary_source()` and `odb_restore_primary_source()` from `odb.h`/`odb.c`; reimplemented as static helpers `tmp_objdir_restore_source()` and `tmp_objdir_replace_primary_odb()` in `tmp-objdir.c`, directly manipulating the ODB’s source list and `disable_ref_updates` flag. Patch 8/13 further adapts these helpers to use `struct odb_files_dir` instead of `struct odb_source`, inserting the quarantine directory at the head of the files backend’s linked list. Patch 9/13 merges `tmp_objdir_replace_primary_odb` into `tmp_objdir_create`, which now takes a `will_destroy` flag and inserts the quarantine directory at the head of the linked list immediately on creation. The `tmp_objdir` struct replaces `prev_source` with `orig_dir` (original primary directory) and `temp_dir` (quarantine directory).)
  - `struct commit_graph` now stores `repo` and `dir` (canonicalized absolute path) instead of `odb_source`; all commit-graph filename helpers (`get_commit_graph_filename()`, etc.) now take `const char *dir` instead of `struct odb_source *`.
  - `write_commit_graph_reachable()` and `write_commit_graph()` now take `(repo, dir)` instead of `source`.
  - `odb_for_each_alternate_fn` (callback type) now takes `struct odb_files_dir *` instead of `struct odb_source *`.
  - `struct alternate_refs_data` gains a `repo` field to compensate for the removed `odb_source->odb->repo` access.
  - `odb_source_files_downcast()` helper for accessing `dirs` field of files-backed sources.
- **Behavior changes**:
  - Alternates are now managed exclusively by the files backend; the `read_alternates` callback is dropped.
  - Patch 1/13 shifts packfile path resolution responsibility from `fill_oids_from_packs()` to its caller (`builtin/commit-graph.c`), requiring fully resolved paths for `--stdin-packs`.
  - Patch 2/13 decouples the commit-graph subsystem from `struct odb_source`, replacing it with explicit repository and object-directory path arguments. This ensures commit graphs loaded from the same directory compare equal regardless of path spelling (relative, absolute, or symlink).
  - Patch 3/13 introduces `struct odb_files_dir` as a foundational step for later patches that will enable multiple directories per backend. The change is mechanical: every `struct odb_source_files` now contains a single `struct odb_files_dir` (accessed via `files->dirs`) instead of separate `loose` and `packed` fields. The new structure also stores the absolute path to the object directory and a `local` flag indicating whether it is the primary repository directory.
  - Patch 4/13 adapts `odb_for_each_alternate()` to iterate over `struct odb_files_dir` instead of `struct odb_source`, updating callers in `builtin/count-objects.c`, `builtin/submodule--helper.c`, and `diagnose.c` to use the `abspath` field. The `refs_from_alternate_cb()` helper is refactored to pass the repository context explicitly.
  - Patch 5/13 removes the generic `odb_find_source()` and `odb_find_source_or_die()` functions, replacing them with `odb_source_files_find_dir()`, a files-backend-specific function that returns `struct odb_files_dir`. Callers in `builtin/commit-graph.c`, `builtin/multi-pack-index.c`, and `t/helper/test-read-midx.c` are updated to use the new function, replacing `source->path` with `dir->abspath` and using `odb_source_files_downcast()` where needed. The change in `builtin/multi-pack-index.c` involves shifting from `struct odb_source_files` to `struct odb_source_packed` in `handle_object_dir_option()`.
  - Patch 6/13 extends `struct odb_files_dir` with a `next` pointer to form a linked list of object directories, enabling the files backend to manage multiple directories. All ODB operations in `odb/source-files.c` are updated to loop through the list: read operations check each directory in sequence until the object is found, while write operations target only the first directory. The patch is purely preparatory, with no visible behavior changes yet.
  - Patch 7/13 absorbs the temporary-primary-source logic into `tmp-objdir.c`, removing `odb_set_temporary_primary_source()` and `odb_restore_primary_source()` from the public ODB API. The functionality is reimplemented as static helpers in `tmp-objdir.c`, which now directly manipulates the ODB’s source list and `disable_ref_updates` flag.
  - Patch 8/13 adapts the quarantine logic in `tmp-objdir.c` to manage the temporary object directory as a `struct odb_files_dir` instead of a standalone `struct odb_source`. The `tmp_objdir` struct replaces its `prev_source` field with `temp_dir` (the new quarantine directory) and `orig_dir` (the original primary directory). `tmp_objdir_replace_primary_odb()` now returns a `struct odb_files_dir` and inserts the quarantine directory at the head of the files backend’s linked list. The `will_destroy` flag is propagated to both the loose and packed sources within the quarantine directory. `tmp_objdir_restore_source()` is updated to handle the linked-list structure, ensuring the original primary directory is restored correctly.
  - Patch 9/13 merges `tmp_objdir_replace_primary_odb` into `tmp_objdir_create`, which now takes a `will_destroy` flag and inserts the quarantine directory at the head of the linked list immediately on creation. Callers in `log-tree.c` and `object-file.c` are updated to pass the flag at creation time. The change reduces boilerplate and clarifies the lifecycle: the quarantine directory is active as soon as `tmp_objdir_create` returns, and the `will_destroy` flag is set once at creation.
- **On-disk format**: No changes (internal refactoring only).
- **Test coverage**: Existing tests for `--stdin-packs` (`t5318-commit-graph.sh`), core ODB commands (`git commit-graph`, `git pack-objects`, `git repack`, `git multi-pack-index`), and log-bloom (`t4216-log-bloom.sh`) are expected to cover the changes. Explicit test coverage for the new path resolution logic, linked-list traversal, or quarantine logic absorption is not mentioned.

Open questions and loose ends
- No substantive objections or requests for changes have been raised yet (initial submission).
- The series’ size (13 patches, 482 lines added to `odb/source-files.c`, 439 lines removed from `odb.c`) may pose review challenges, particularly for edge cases like promisor remotes, partial clones, or non-files backends.
- Merge conflicts with `seen` are documented but unresolved; a reroll may be required.
- The architectural shift (moving alternates into the files backend and decoupling commit-graph from `odb_source`) is well-motivated but may need additional scrutiny for unintended side effects, such as path canonicalization robustness (e.g., symlink resolution consistency, `real_pathdup()`/`strbuf_realpath()` edge cases) or backend-agnostic assumptions.
- The linked-list design introduced in patch 6/13 (multiple directories per backend) raises questions about future behavior: will alternates be appended to the list, prepended, or managed in a specific order? How will this interact with promisor remotes or partial clones, where object lookup order may affect performance or correctness? Patch 8/13 and 9/13 clarify that the quarantine directory is inserted at the head of the list, but the broader question of alternates ordering remains open.
