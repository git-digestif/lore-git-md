Thread identity
Subject: [PATCH 0/13] Move alternates into the files ODB backend
Series version: v1 (initial submission)
Originating author: Patrick Steinhardt
Thread type: patch series (refactoring)

Core problem or goal
Refactor the Git object database (ODB) subsystem to move alternates handling into the "files" backend, eliminating a conceptual mismatch where alternates were previously managed at the ODB source level. This mismatch caused performance regressions, complicated data structures (bitmaps, commit graphs), and blocked backend-agnostic extensions to `GIT_OBJECT_DIRECTORY` and `GIT_ALTERNATE_OBJECT_DIRECTORIES`. The series consolidates alternates into the files backend, making them a backend-specific implementation detail and enabling future ODB work such as pluggable backends.

Current status
Under review (initial submission, v1). The series is built on commit `c46c1e3772` (start of the Git 2.98 cycle) and has minor merge conflicts with the `seen` branch, as documented in the cover letter. No prior versions exist. Patch 13/13, the final cleanup step, has been posted, removing the now-unused `read_alternates` callback from the ODB source interface and completing the series.

Key technical details
- **Subsystems/files touched**: ODB core (`odb.c`, `odb.h`), files backend (`odb/source-files.c`, `odb/source-files.h`), loose-object backend (`odb/source-loose.h`), quarantine logic (`tmp-objdir.c`), commit-graph subsystem (`commit-graph.c`, `commit-graph.h`), and 75 files total across the series. Patch 12/13 specifically touches 35 files, with the bulk of changes in `odb.c` (354 lines removed) and `odb/source-files.c` (260 lines added). Patch 13/13 removes the `read_alternates` callback from all ODB backends (`files`, `inmemory`, `loose`, and `packed`), deleting 55 lines across 5 files.
- **New/renamed symbols**:
  - **Series-wide**:
    - `struct odb_files_dir` (manages multiple object directories, introduced in patch 3/13; encapsulates `loose`, `packed`, absolute path, `local` flag, and a `next` pointer for linked-list traversal of multiple directories, added in patch 6/13)
    - `odb_source_files_find_dir()` (files-backend-specific replacement for `odb_find_source()`, introduced in patch 5/13)
    - `read_alternates()` (new helper function in patch 11/13, extracted from `odb_source_files_read_alternates()` to operate on an object directory path instead of an `odb_source` struct; enables future use cases where an `odb_source` is unavailable)
    - Refactored `odb_for_each_alternate()` and `odb_find_source()` (now operate on directories, not sources)
    - Absorbed quarantine logic into `tmp-objdir` as an object directory (patch 7/13 and 8/13: removed `odb_set_temporary_primary_source()` and `odb_restore_primary_source()` from `odb.h`/`odb.c`; reimplemented as static helpers in `tmp-objdir.c`, directly manipulating the ODB’s source list and `disable_ref_updates` flag. Patch 8/13 further adapts these helpers to use `struct odb_files_dir` instead of `struct odb_source`, inserting the quarantine directory at the head of the files backend’s linked list. Patch 9/13 merges `tmp_objdir_replace_primary_odb` into `tmp_objdir_create`, which now takes a `will_destroy` flag and inserts the quarantine directory at the head of the linked list immediately on creation. The `tmp_objdir` struct replaces `prev_source` with `orig_dir` (original primary directory) and `temp_dir` (quarantine directory). Patch 10/13 moves the `will_destroy` flag from `struct odb_source` to `struct odb_source_loose`, where it is actually used, removing it from the generic ODB source structure.)
    - `struct commit_graph` now stores `repo` and `dir` (canonicalized absolute path) instead of `odb_source`; all commit-graph filename helpers (`get_commit_graph_filename()`, etc.) now take `const char *dir` instead of `struct odb_source *`.
    - `write_commit_graph_reachable()` and `write_commit_graph()` now take `(repo, dir)` instead of `source`.
    - `odb_for_each_alternate_fn` (callback type) now takes `struct odb_files_dir *` instead of `struct odb_source *`.
    - `struct alternate_refs_data` gains a `repo` field to compensate for the removed `odb_source->odb->repo` access.
    - `odb_source_files_downcast()` helper for accessing `dirs` field of files-backed sources.
  - **Patch 12/13-specific**:
    - `odb_files_dir_is_usable()` (files-backend-specific helper to check if a directory is usable)
    - `odb_add_alternate_recursively()` (files-backend-specific helper to recursively add alternates)
    - `odb_prepare_alternates()` (files-backend-specific helper to prepare alternates for use)
    - `dirs_by_path` hashmap and `dirs_paths_icase` field added to `struct odb_source_files` to track directories by path
    - Dropped `read_alternates` callback from `struct odb_source` (alternates are now a files-backend-specific concern)
    - Removed `next` pointer and `by_path_entry` field from `struct odb_source` (sources no longer form a linked list)
  - **Patch 13/13-specific**:
    - Removed `read_alternates` callback from `struct odb_source` and all backend implementations (`files`, `inmemory`, `loose`, `packed`).
- **Behavior changes**:
  - **Series-wide**:
    - Alternates are now managed exclusively by the files backend; the `read_alternates` callback is dropped.
    - Patch 1/13 shifts packfile path resolution responsibility from `fill_oids_from_packs()` to its caller (`builtin/commit-graph.c`), requiring fully resolved paths for `--stdin-packs`. The commit message for this patch was criticized by Karthik Nayak for lacking motivation; while the technical change is correct, it does not explain how this step advances the series’ broader architectural goals.
    - Patch 2/13 decouples the commit-graph subsystem from `struct odb_source`, replacing it with explicit repository and object-directory path arguments. This ensures commit graphs loaded from the same directory compare equal regardless of path spelling (relative, absolute, or symlink). The test helper `git_test_write_commit_graph_or_die()` now takes only a `struct repository *` but internally hard-codes the object directory path from `repo->objects->sources->path`, which Karthik Nayak flags as a potential inconsistency: the function should forward an explicit path argument to align with the series’ shift toward explicit repository and path arguments, avoiding assumptions about the primary ODB source’s path.
    - Patch 3/13 introduces `struct odb_files_dir` as a foundational step for later patches that will enable multiple directories per backend. The change is mechanical: every `struct odb_source_files` now contains a single `struct odb_files_dir` (accessed via `files->dirs`) instead of separate `loose` and `packed` fields. The new structure also stores the absolute path to the object directory and a `local` flag indicating whether it is the primary repository directory.
    - Patch 4/13 adapts `odb_for_each_alternate()` to iterate over `struct odb_files_dir` instead of `struct odb_source`, updating callers in `builtin/count-objects.c`, `builtin/submodule--helper.c`, and `diagnose.c` to use the `abspath` field. The `refs_from_alternate_cb()` helper is refactored to pass the repository context explicitly.
    - Patch 5/13 removes the generic `odb_find_source()` and `odb_find_source_or_die()` functions, replacing them with `odb_source_files_find_dir()`, a files-backend-specific function that returns `struct odb_files_dir`. Callers in `builtin/commit-graph.c`, `builtin/multi-pack-index.c`, and `t/helper/test-read-midx.c` are updated to use the new function, replacing `source->path` with `dir->abspath` and using `odb_source_files_downcast()` where needed.
    - Patch 6/13 extends `struct odb_files_dir` with a `next` pointer to form a linked list of object directories, enabling the files backend to manage multiple directories. All ODB operations in `odb/source-files.c` are updated to loop through the list: read operations check each directory in sequence until the object is found, while write operations target only the first directory. The patch is purely preparatory, with no visible behavior changes yet.
    - Patch 7/13 absorbs the temporary-primary-source logic into `tmp-objdir.c`, removing `odb_set_temporary_primary_source()` and `odb_restore_primary_source()` from the public ODB API. The functionality is reimplemented as static helpers in `tmp-objdir.c`, which now directly manipulates the ODB’s source list and `disable_ref_updates` flag.
    - Patch 8/13 adapts the quarantine logic in `tmp-objdir.c` to manage the temporary object directory as a `struct odb_files_dir` instead of a standalone `struct odb_source`. The `tmp_objdir` struct replaces its `prev_source` field with `temp_dir` (the new quarantine directory) and `orig_dir` (the original primary directory). `tmp_objdir_replace_primary_odb()` now returns a `struct odb_files_dir` and inserts the quarantine directory at the head of the files backend’s linked list. The `will_destroy` flag is propagated to both the loose and packed sources within the quarantine directory.
    - Patch 9/13 merges `tmp_objdir_replace_primary_odb` into `tmp_objdir_create`, which now takes a `will_destroy` flag and inserts the quarantine directory at the head of the linked list immediately on creation. Callers in `log-tree.c` and `object-file.c` are updated to pass the flag at creation time.
    - Patch 10/13 moves the `will_destroy` flag from the generic `struct odb_source` to `struct odb_source_loose`, where it is actually used. The flag was previously defined in the generic ODB source structure but only checked by the loose-object backend to skip fsync when the source is ephemeral.
    - Patch 11/13 extracts the alternates-reading logic from `odb_source_files_read_alternates()` into a new helper function, `read_alternates()`, which operates on an object directory path instead of an `odb_source` struct. The change is preparatory for patch 12/13, which will add a new callsite lacking an `odb_source` for the alternate directory.
    - Patch 12/13 relocates alternates handling into the files backend, making it a backend-specific implementation detail. The `read_alternates` callback is dropped, and alternates are read only by the files backend. The alternates infrastructure (path parsing, deduplication, recursive addition) is moved from `odb.c` to `odb/source-files.c`. The `odb_source` struct loses its `next` pointer and `by_path_entry` field, as sources no longer form a linked list. Alternates are managed as a linked list of `struct odb_files_dir` within the files backend. All ODB operations are updated to loop through this list: reads check each directory in sequence; writes target only the first directory. Commands like `git fsck`, `git gc`, and `git pack-objects` are updated to iterate over directories instead of sources.
  - **Patch 13/13-specific**:
    - Removes the now-unused `read_alternates` callback from the ODB source interface and all backend implementations, completing the architectural shift.

Open questions and loose ends
- No substantive objections or requests for changes have been raised yet (initial submission), but two review comments from Karthik Nayak identify areas for improvement:
  - **Patch 1/13**: The commit message lacks motivation, failing to explain how the patch advances the series’ broader architectural goals. While the technical change is correct, the omission makes it harder for reviewers to contextualize the patch within the series.
  - **Patch 2/13**: The test helper `git_test_write_commit_graph_or_die()` now takes only a `struct repository *` but internally hard-codes the object directory path from `repo->objects->sources->path`. This could break test cases that need to write commit graphs to non-default object directories (e.g., alternates, quarantine directories, or custom test setups). The function should forward an explicit path argument to align with the series’ shift toward explicit repository and path arguments.
- The series’ size (13 patches, 482 lines added to `odb/source-files.c`, 439 lines removed from `odb.c`) may pose review challenges, particularly for edge cases like promisor remotes, partial clones, or non-files backends.
- Merge conflicts with `seen` are documented but unresolved; a reroll may be required.
- The linked-list traversal order for alternates (e.g., whether they are appended, prepended, or managed in a specific order) remains an open question. Patches 8/13 and 9/13 clarify that the quarantine directory is inserted at the head of the list, but the broader alternates ordering is not yet addressed.
