Thread identity
Subject: [PATCH 0/13] Move alternates into the files ODB backend
Series version: v1 (initial submission)
Originating author: Patrick Steinhardt
Thread type: patch series (refactoring)

Core problem or goal
Refactor the Git object database (ODB) subsystem to move alternates handling into the "files" backend, eliminating a conceptual mismatch where alternates are currently managed at the ODB source level. This mismatch causes performance regressions, complicates data structures (bitmaps, commit graphs), and prevents backend-agnostic extensions to `GIT_OBJECT_DIRECTORY` and `GIT_ALTERNATE_OBJECT_DIRECTORIES`. The series lays the groundwork for future ODB work by consolidating alternates into the files backend, where they belong, and making the commit-graph subsystem backend-agnostic.

Current status
Under review (initial submission, v1). The series is built on commit `c46c1e3772` (start of the Git 2.98 cycle) and has minor merge conflicts with the `seen` branch, as documented in the cover letter. No prior versions exist.

Key technical details
- **Subsystems/files touched**: ODB core (`odb.c`, `odb.h`), files backend (`odb/source-files.c`), quarantine logic (`tmp-objdir.c`), `builtin/commit-graph.c`, `commit-graph.c`, `commit-graph.h`, `builtin/count-objects.c`, `builtin/submodule--helper.c`, `diagnose.c`, and 68 files total.
- **New/renamed symbols**:
  - `struct odb_files_dir` (manages multiple object directories, introduced in patch 3/13; encapsulates `loose`, `packed`, absolute path, and `local` flag)
  - Refactored `odb_for_each_alternate()` and `odb_find_source()` (now operate on directories, not sources)
  - Absorbed quarantine logic into `tmp-objdir` as an object directory
  - `struct commit_graph` now stores `repo` and `dir` (canonicalized absolute path) instead of `odb_source`; all commit-graph filename helpers (`get_commit_graph_filename()`, etc.) now take `const char *dir` instead of `struct odb_source *`.
  - `write_commit_graph_reachable()` and `write_commit_graph()` now take `(repo, dir)` instead of `source`.
  - `odb_for_each_alternate_fn` (callback type) now takes `struct odb_files_dir *` instead of `struct odb_source *`.
  - `struct alternate_refs_data` gains a `repo` field to compensate for the removed `odb_source->odb->repo` access.
  - `odb_source_files_downcast()` helper for accessing `dirs` field of files-backed sources.
- **Behavior changes**:
  - Alternates are now managed exclusively by the files backend; the `read_alternates` callback is dropped.
  - Patch 1/13 shifts packfile path resolution responsibility from `fill_oids_from_packs()` to its caller (`builtin/commit-graph.c`), requiring fully resolved paths for `--stdin-packs`.
  - Patch 2/13 decouples the commit-graph subsystem from `struct odb_source`, replacing it with explicit repository and object-directory path arguments. This ensures commit graphs loaded from the same directory compare equal regardless of path spelling (relative, absolute, or symlink).
  - Patch 3/13 introduces `struct odb_files_dir` as a foundational step for later patches that will enable multiple directories per backend. The change is mechanical: every `struct odb_source_files` now contains a single `struct odb_files_dir` (accessed via `files->dirs`) instead of separate `loose` and `packed` fields. The new structure also stores the absolute path to the object directory and a `local` flag indicating whether it is the primary repository directory.
  - Patch 4/13 adapts `odb_for_each_alternate()` to iterate over `struct odb_files_dir` instead of `struct odb_source`, updating callers in `builtin/count-objects.c`, `builtin/submodule--helper.c`, and `diagnose.c` to use the `abspath` field. The `refs_from_alternate_cb()` helper is refactored to pass the repository context explicitly.
- **On-disk format**: No changes (internal refactoring only).
- **Test coverage**: Existing tests for `--stdin-packs` (`t5318-commit-graph.sh`), core ODB commands (`git commit-graph`, `git pack-objects`, `git repack`, `git multi-pack-index`), and log-bloom (`t4216-log-bloom.sh`) are expected to cover the changes. Explicit test coverage for the new path resolution logic is not mentioned.

Open questions and loose ends
- No substantive objections or requests for changes have been raised yet (initial submission).
- The series’ size (13 patches, 482 lines added to `odb/source-files.c`, 439 lines removed from `odb.c`) may pose review challenges, particularly for edge cases like promisor remotes, partial clones, or non-files backends.
- Merge conflicts with `seen` are documented but unresolved; a reroll may be required.
- The architectural shift (moving alternates into the files backend and decoupling commit-graph from `odb_source`) is well-motivated but may need additional scrutiny for unintended side effects, such as path canonicalization robustness (e.g., symlink resolution consistency) or backend-agnostic assumptions.
