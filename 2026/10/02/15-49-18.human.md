This is a brief, surface-level review from Junio C Hamano on the second patch in Scott Chacon’s RFC series introducing a new signing mechanism that embeds SHA-256 digests of tree contents in signed commits and tags.

Junio’s comment is narrowly focused on the code’s structure: he approves the refactoring that moves the double newline (`\n\n`) from a hardcoded position to a conditional one, allowing the new `tree-sha256` header to be inserted cleanly. This is a mechanical improvement that makes the code more extensible, and Junio’s feedback is positive but limited to that single point. He does not engage with the broader design questions raised in the cover letter (digest algorithm, submodule handling, performance, or whether this mechanism is a viable alternative to switching the default object format to SHA-256 in Git 3.0). The review is purely about code organization, not functionality or design.
