This is a **review and proposed improvement** to Patrick Steinhardt’s bugfix series for stale delta base cache entries. Guillaume Chauvel responds to Patrick’s observation that the existing regression test (`t/t6437-submodule-merge.sh`) is platform-dependent (it relies on glibc’s allocation behavior) by proposing a **deterministic test helper** that forces the exact memory reuse scenario the bug depends on.

The patch adds a new test tool (`test-delta-base-cache`) that:
1. Creates two packs (`A-B.pack` and `B-C.pack`) where the delta base offsets for `B` and `C` are identical.
2. Unpacks `B` from the first pack, then closes it.
3. **Simulates memory reuse** by copying the `packed_git` struct from the second pack into the memory of the first (using `memcpy`), then frees the second pack.
4. Attempts to unpack `C` from the reused struct. If the delta base cache still contains stale entries from the first pack, the reconstruction will fail (producing the wrong object ID).

The test is **self-contained and portable**, avoiding the glibc dependency of the original test. It also adds a small helper (`write_full`) to `test-pack-deltas` to support generating the test packs.

This is a **substantive review contribution**: it directly addresses a weakness in the original series (platform-specific test behavior) with a well-engineered alternative. The implementation is clean, the commit message is clear, and the test logic is sound. The patch is **ready for review** and looks like a strong candidate for inclusion alongside Patrick’s fix. If accepted, it would replace or supplement the existing test, making the regression test suite more robust.
