This is a feature patch series (now 2 patches) that extends `git history` to sign rewritten commits, including the newly supported `squash` subcommand. The v4 update adds signing support for `squash`, updates its documentation and usage synopsis, and introduces GPG-gated tests covering configuration, command-line option precedence, explicit key selection, the squashed commit itself, and replayed descendants. The series is now complete: all history subcommands (`drop`, `fixup`, `reword`, `split`, and `squash`) respect `commit.gpgsign` and the standard `-S/--gpg-sign`/`--no-gpg-sign` options, with command-line options overriding configuration and the last option winning.

The changes are mechanical and well-tested: the replay API plumbing (patch 1/2) remains unchanged from v3, while the main feature patch (2/2) adds the squash subcommand’s signing logic, updates its usage string, and folds in the new tests. The commit messages have been clarified to explain the configuration-loading order and the replay infrastructure’s role. All prior review feedback—including Patrick Steinhardt’s request for squash support and Junio C Hamano’s DCO clarification—has been addressed.
