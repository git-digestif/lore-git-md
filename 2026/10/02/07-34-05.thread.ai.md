Subject: [PATCH 0/2] packfile: fix corruption from stale delta base cache entries
Series version: v1 (initial submission)
Originating author: Patrick Steinhardt
Thread type: bugfix patch series

Core problem or goal
Fix a subtle packfile corruption bug caused by stale delta base cache entries. When Git reuses memory addresses for new `packed_git` structs after closing packs, the delta base cache may retain entries from the old pack, leading to incorrect object reconstruction if the new pack has entries at the same offsets. The bug is reliably reproducible via recursive submodule merges.

Current status
Under review. Two-patch series: (1) preparatory refactoring of `close_pack()` to avoid forward declarations, (2) core fix evicting stale delta base cache entries when closing a pack. No prior versions.

Key technical details
- Files touched: `packfile.c` (core fix), `t/t6437-submodule-merge.sh` (new regression test).
- Subsystems: packfile management, delta base cache, submodule handling.
- New behavior: Delta base cache entries are evicted when their owning pack is closed.
- On-disk format: unchanged.
- Test coverage: new test in `t/t6437-submodule-merge.sh` verifies the fix via recursive submodule merges.
