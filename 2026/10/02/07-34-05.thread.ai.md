Subject: [PATCH 0/2] packfile: fix corruption from stale delta base cache entries
Series version: v1 (initial submission, follow-up discussion on test design and platform dependency)
Originating author: Patrick Steinhardt
Thread type: bugfix patch series

Core problem or goal
Fix a subtle packfile corruption bug caused by stale delta base cache entries. When Git reuses memory addresses for new `packed_git` structs after closing packs, the delta base cache may retain entries from the old pack, leading to incorrect object reconstruction if the new pack has entries at the same offsets. The bug is reliably reproducible via recursive submodule merges and became exposed after commit 6f1e9394e2 (2024-08-08) stopped leaking packfiles.

Current status
Under review. Two-patch series: (1) preparatory refactoring of `close_pack()` to avoid forward declarations, (2) core fix evicting stale delta base cache entries when closing a pack. The core fix remains uncontested. Discussion has clarified the original regression test’s platform dependency (glibc-specific memory allocation patterns) and its intentional design trade-off: simplicity over determinism. Patrick Steinhardt’s recent reply explicitly confirms the refactoring’s rationale (avoiding forward declarations for delta base cache declarations) in response to Mark C. Chu-Carroll’s procedural question. No new patch versions or alternative test proposals have emerged; the thread has reached a stable state on test coverage. No merge status reported; series remains under review.

Key technical details
- Files touched: `packfile.c` (refactoring in patch 1, core fix in patch 2), `t/t6437-submodule-merge.sh` (regression test in patch 2). The follow-up test improvement (Guillaume Chauvel’s deterministic proposal) was rejected and is not part of the series.
- Subsystems: packfile management, delta base cache, submodule handling, test infrastructure.
- New behavior: Delta base cache entries are evicted when their owning pack is closed (patch 2).
- New functions: `delta_base_cache_evict_entry()` (patch 2) evicts cache entries for a given pack.
- On-disk format: unchanged.
- Test coverage: The regression test in `t/t6437-submodule-merge.sh` (patch 2) verifies the fix via recursive submodule merges with 16 similarly structured submodules. The test relies on glibc’s allocator to reuse memory addresses and is platform-dependent; it did not reproduce on Philippe Blain’s WSL setup. The test’s behavior varies with the test directory’s path length (fewer submodules suffice in `/tmp/` but not in deeper paths). Guillaume Chauvel’s proposed deterministic test (not adopted) would have created two packs with overlapping delta base offsets to trigger the bug without relying on memory reuse patterns.
- Refactoring details: Patch 1 moves `close_pack()` later in `packfile.c` to ensure delta base cache declarations are in scope for patch 2; the refactoring’s rationale (avoiding forward declarations) is now explicitly confirmed in the thread.
