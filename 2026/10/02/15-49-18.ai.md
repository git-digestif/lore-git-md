This is a review reply from Junio C Hamano to Scott Chacon’s second patch in the four-part RFC series proposing a new signing mechanism that embeds SHA-256 digests of tree contents in signed commits and tags. The patch teaches `git tag -s` and `git tag -u` a `--hash=sha256` option that adds a `tree-sha256` header to tag objects.

Junio’s reply is **surface-level** but constructive: he praises the refactoring of the tag header construction in `builtin/tag.c` to make it extensible. The original code hardcoded a double newline after the `tagger` line, which made it difficult to add optional headers later. Scott’s patch replaces this with a single newline, allowing the `tree-sha256` header to be inserted conditionally before the final blank line. Junio calls this reorganization "very nice" and notes that it removes an artificial barrier to future extensibility.

The review does not engage with the broader design questions raised in the cover letter (e.g., digest algorithm, submodule handling, or performance), nor does it comment on the correctness or completeness of the implementation. It is narrowly focused on the mechanical improvement to the tag header construction. No objections or requests for changes are raised; the tone is positive but limited in scope.
