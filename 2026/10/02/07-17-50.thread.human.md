This thread introduces a small but useful quality-of-life improvement: allowing `remote.pushDefault` to accept a space-separated list of remote names (e.g., `fork origin`). The feature lets users set a global fallback chain so that `git push` automatically tries the first available remote in the list, eliminating the need to configure `remote.pushDefault` separately for each repository when working with multiple remotes like a fork and an upstream.

Harald Nordgren’s two-patch series is under initial review. The first patch refactors remote lookup into a helper function, and the second implements the core feature: Git now iterates through the list of remotes in `remote.pushDefault` and pushes to the first one that exists. If none exist, it falls back to the branch’s configured remote as if `remote.pushDefault` were unset. The implementation is confined to `remote.c`, with updated documentation and thorough test coverage for both happy paths and edge cases. Backward compatibility is preserved—single remote names continue to work as before, and repository-local settings still override global ones.

No maintainer or reviewer feedback has arrived yet, so the series remains in its initial state. The main open questions are whether the implementation handles whitespace in config values robustly (e.g., leading/trailing spaces, multiple consecutive spaces) and how the feature interacts with other push-related settings like `push.default` and `push.autoSetupRemote`. The patches are ready for review and should integrate cleanly with the existing codebase.
