## 2026/10/05

- [2026/10/05/05-32-18 by Patrick Steinhardt <ps@pks.im>] Patrick Steinhardt corrected Jeff King's earlier suggestion that the stale delta base cache bug was a user-after-free that ASan would reliably find, explaining that the cache key stores the freed `packed_git` pointer's address but never dereferences it (the cached value remains a live object), and that ASan cannot reproduce the bug because it hands out unique addresses.

## 2026/10/06

- [2026/10/06/10-20-13 by Patrick Steinhardt <ps@pks.im>] Patrick Steinhardt posted the v2 cover letter for "packfile: fix corruption due to stale delta base cache entries", summarizing that the two-patch series fixes corruption caused by stale delta base cache entries that are not evicted when closing a pack, which can be triggered by recursive merges with submodules that have similar packfiles.
- [2026/10/06/10-20-14 by Patrick Steinhardt <ps@pks.im>] Patrick Steinhardt posted [PATCH v2 1/2] "packfile: move around `close_pack()`", moving the function after the delta base cache declaration so the next commit can access the cache without a forward declaration.
- [2026/10/06/10-20-15 by Patrick Steinhardt <ps@pks.im>] Patrick Steinhardt posted [PATCH v2 2/2] "packfile: fix corruption due to stale delta base cache entries", adding `delta_base_cache_evict_entry()` called from `close_pack()` to evict cache entries belonging to the closed pack, plus a test in t/t6437-submodule-merge.sh that creates 16 packed submodules to reproduce the bug; the test reliably reproduces on glibc 2.44-25 but may not work on other platforms due to reliance on specific allocation behavior.
- [2026/10/06/19-57-41 by Junio C Hamano <gitster@pobox.com>] Junio C Hamano reviewed the fix, observing that the test will not detect the bug when the fix is reverted unless the glibc allocator is used, stating that an unreliable reproducer for an already-fixed bug may be of dubious value though potentially acceptable if it catches the bug on widely used configurations without false positives, and noting that custom low-level code to simulate colliding allocation addresses would be a maintenance burden.
