This is the fifth iteration of a feature series that introduces a "matching-inspired" fetch mode to solve a performance problem in shallow repositories. When a shallow clone (`git clone --depth=...`) fetches from a remote with many branches, a plain `git fetch` or `git pull` can be slow or hang because it negotiates history for every remote branch. The series now implements the consensus design: it uses `remote.<name>.refmap` to define namespace mappings and dynamically fetches only the branches tracked by local branches at the remote.

The v5 update is purely mechanical: the test file `t/t5585-fetch-refmap.sh` is renumbered to `t/t5586-fetch-refmap.sh` to avoid a conflict with another in-flight topic. No code or documentation changes were made; the series remains technically complete and addresses all prior feedback. Junio C Hamano has stated he will queue the series ("Will replace") but has not yet performed his own re-review, so it is still under active review and not yet in any integration branch.

The four patches are well-structured and cover the full scope: Patch 1/4 adds `remote.<name>.refmap` configuration, Patch 2/4 implements dynamic branch enumeration, Patch 3/4 adds `git remote add --limited-fetch` to explicitly opt into the new mode, and Patch 4/4 makes `--limited-fetch` the default in shallow repositories. The implementation touches `remote.c`, `builtin/fetch.c`, and `builtin/remote.c`, and includes thorough test coverage in `t/t5586-fetch-refmap.sh`, `t/t5510-fetch.sh`, and `t/t5505-remote.sh`.

The series is clearly motivated by a real user pain point and is now technically sound. The design avoids backward compatibility issues by keeping the new behavior opt-in (via `--limited-fetch` or shallow repositories) and preserves existing workflows for non-shallow clones. The only remaining loose end is a minor edge case where a bare `git fetch` against a refmap-only remote fetches no branches, leaving no remote-tracking refs for `git branch --set-upstream-to` to use, but this is acknowledged as a small quibble and not a blocker. The series looks ready for merging once Junio completes his re-review.
