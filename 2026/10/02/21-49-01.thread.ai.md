Core problem or goal
Alejandro Colomar sought a plumbing-compatible way to retrieve the commit hash identified by `git bisect` as the culprit after the bisect session completes but before resetting it, without parsing porcelain output.

Current status
The inquiry is resolved: the culprit commit is recorded in the `refs/bisect/bad` ref, which can be retrieved via plumbing commands such as `git rev-parse bisect/bad`, `git rev-list -1 bisect/bad`, or `git show bisect/bad`. Jeff King and Junio C Hamano confirmed that this mechanism is stable, intended for script use, and reliably updated in all cases, including when `HEAD` does not move. No patch or feature request is needed. Alejandro Colomar has adopted `git rev-parse bisect/bad` in his scripts, marking the practical end of the thread.

Key technical details
- Subsystem: `git bisect` plumbing
- No new symbols, files, or on-disk format changes
- Old behavior: `git bisect next` does not position `HEAD` at the found commit; the culprit hash is stored in `refs/bisect/bad` and can be accessed via plumbing commands (`git rev-parse`, `git rev-list`, `git show`, etc.)
- The ref is updated even when the bisect algorithm determines that the current `HEAD` is already the culprit, ensuring the ref always reflects the correct result
- User feedback confirms `git show bisect/bad`, `git rev-list -1 bisect/bad`, and `git rev-parse bisect/bad` all work as expected in practice
