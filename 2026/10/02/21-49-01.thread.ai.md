Subject: Is there a plumbing command to retrieve the bisect culprit?
Series version: N/A (user inquiry, not a patch series)
Originating author: Alejandro Colomar <alx@kernel.org>
Thread type: user question about Git’s command-line interface

Core problem or goal
Alejandro Colomar wants to know if Git provides a plumbing command that returns the commit hash identified by `git bisect` as the culprit, after the bisect session has completed but before resetting it. The goal is to obtain this information programmatically without parsing porcelain output (e.g., `git bisect log`).

Current status
The inquiry is resolved: the culprit commit is recorded in the `refs/bisect/bad` ref, which can be retrieved via plumbing commands such as `git rev-parse bisect/bad` or `git show bisect/bad`. Both Jeff King and Junio C Hamano have confirmed that this mechanism is stable and intended for script use. No patch or feature request is needed.

Key technical details
- Subsystem: `git bisect` plumbing
- No new symbols, files, or on-disk format changes
- Old behavior: `git bisect next` does not position `HEAD` at the found commit; the culprit hash is stored in `refs/bisect/bad` and can be accessed via plumbing commands (`git rev-parse`, `git show`, etc.)
- The ref is updated even when the bisect algorithm determines that the current `HEAD` is already the culprit, ensuring the ref always reflects the correct result regardless of whether `HEAD` moves
