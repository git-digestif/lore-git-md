This patch modifies the `git branch --delete-merged` command to default to considering *every* upstream branch when no explicit pattern is provided. Previously, users had to specify a pattern like `*/*` to clean up all merged branches, which the author describes as cumbersome. The change affects the command-line interface, documentation, and adds a new test case to verify the behavior.

The implementation uses `PARSE_OPT_LASTARG_DEFAULT` to make the `--delete-merged` option accept an implicit default value (`**`) when it appears as the last argument. This aligns with the existing behavior of `--merged` (without a commit), which also defaults when placed last. The documentation is updated to reflect that the pattern is now optional, and the help text in `builtin/branch.c` is adjusted to match.

The patch includes a new test (`--delete-merged without a pattern matches every upstream`) that verifies the default behavior by creating a repository with merged branches and confirming that `git branch --delete-merged` (without arguments) removes only the expected branches. The test also checks that `--dry-run` works as intended.

This is a **feature** patch that simplifies a common workflow (cleaning up merged branches) by making the command more ergonomic. The change is backward-compatible: existing invocations with explicit patterns continue to work as before. The use of `**` as the default pattern is a technical detail not exposed to users, but it effectively matches all upstreams.

The patch touches three files: `Documentation/git-branch.adoc` (documentation), `builtin/branch.c` (command implementation), and `t/t3200-branch.sh` (tests). The commit message is clear and concise, though it does not cite prior discussion or user requests motivating the change. The test coverage is thorough for the new behavior but does not explicitly test edge cases like multiple `--delete-merged` options or interactions with `--dry-run` in non-last positions.
