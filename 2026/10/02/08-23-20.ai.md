This is the third patch in Christian Couder’s five-part v5 series introducing `uploadpack.lazyFetchTrusted`, a server-side protected configuration variable that lets operators mark repositories as trusted for lazy fetching. The patch wires up the generic path-allowlist helpers (introduced in 2/5) to the new `uploadpack.lazyFetchTrusted` config key and exposes the result through `upload_pack_lazy_fetch_trusted()`.

The code adds 62 lines to `upload-pack.c` and 3 lines to `upload-pack.h`. It registers a new protected-config callback (`upload_pack_protected_lazy_fetch_config`) that invokes `path_allowlist_config_apply()` with a custom `allow_trusted_path()` validator. The validator enforces absolute paths—rejecting the `.` shorthand that `safe.directory` accepts—because `upload-pack` always serves repositories by absolute git-dir path. The public `upload_pack_lazy_fetch_trusted()` function resolves the repository’s real git-dir, consults the allowlist, and returns a boolean. Memory management is clean: `real_pathdup()` is paired with a `free()` in the same function.

No behavioral change is visible yet; the new function is a pure predicate that will be consumed in patch 5/5. The patch is a straightforward plumbing layer that reuses the refactored helpers from 2/5, keeping the series’ refactoring-then-feature pattern intact. Junio’s earlier feedback on path validation and documentation clarity is fully addressed: the commit message now explicitly states that non-bare repositories must be allowlisted by their `.git` directory (or the directory a `.git` file points to), and the code itself warns when a non-absolute path is encountered.
