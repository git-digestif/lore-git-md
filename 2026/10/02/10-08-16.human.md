This is the fifth patch in Patrick Steinhardt’s 13-patch series refactoring the Git object database (ODB) to move alternates handling into the "files" backend. The patch refactors `odb_find_source()`—a core ODB function that locates an object directory by path—to operate on the new `struct odb_files_dir` instead of the generic `struct odb_source`.

The change is mechanical but foundational: `odb_find_source()` is renamed to `odb_source_files_find_dir()` and moved into `odb/source-files.c`, where it now returns a `struct odb_files_dir` (introduced in patch 3/13) rather than a generic `odb_source`. Callers in `builtin/commit-graph.c`, `builtin/multi-pack-index.c`, and `t/helper/test-read-midx.c` are updated to use the new function and type, replacing direct access to `source->path` with `dir->abspath`. The patch also drops the now-unused `odb_find_source_or_die()` helper, inlining its logic where needed.

This is a clean, well-scoped refactoring that aligns with the series’ goal of making alternates an implementation detail of the files backend. The commit message is clear, and the diff is straightforward—no behavior changes, just type and function renames. If you’re following the ODB refactoring effort, this patch is worth noting as it establishes the pattern for how object directories will be handled going forward. The series is still under review, but this step looks solid.
