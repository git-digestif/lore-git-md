This is a bugfix patch in Patrick Steinhardt’s v2 series introducing subcommand grouping to Git’s parse-options API. It fixes a formatting glitch in the `--git-completion-helper` output: when the first option is skipped (for example, because it is a group or hidden), the helper still prints a leading space, producing malformed completion output. The fix is small and surgical—adding a local `shown` flag to track whether anything has been printed yet, replacing the problematic `opts == original_opts` check.

The patch touches only `parse-options.c` and the test helper, with a minimal test addition that verifies the fix by introducing an `OPT_GROUP` as the first option. The change is clearly motivated and well-contained; it addresses a real, if minor, usability issue in shell completion. This is the first of four patches in the series, laying the groundwork for the larger API refactoring that follows. No controversy is expected here—it is a straightforward correctness fix.
