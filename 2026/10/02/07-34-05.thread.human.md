This thread is about a two-patch bugfix series from Patrick Steinhardt that addresses a subtle packfile corruption bug caused by stale delta base cache entries. The bug, which became exposed after a 2024 commit stopped leaking packfiles, can lead to incorrect object reconstruction when Git reuses memory addresses for `packed_git` structs after closing packs. The series includes a preparatory refactoring of `close_pack()` and the core fix, which evicts stale cache entries when a pack is closed. The fix itself is uncontested, but the original regression test’s reliance on glibc-specific memory allocation patterns has sparked discussion about its portability and determinism.

The thread has reached a stable state on the core fix, with no substantive objections or requests for changes. However, Jeff King (Peff) recently reframed the bug as a user-after-free issue and proposed an alternative test strategy using AddressSanitizer (ASan) to detect the invalid memory access directly. This approach would make the test deterministic and portable, addressing the earlier trade-off between simplicity and reliability. Peff’s review is technically precise and collaborative, offering a concrete improvement without questioning the fix’s correctness. The existing test, which relies on recursive submodule merges with 16 similarly structured submodules, remains in place for now, though its limitations are acknowledged.

Key participants include Patrick Steinhardt (author), who has clarified the test’s design trade-offs and the refactoring’s rationale, and Philippe Blain and Guillaume Chauvel, who raised questions about the test’s portability and proposed a deterministic alternative (later rejected). The series remains under review, with no merge status reported. The open question is whether the test should be augmented or replaced with an ASan-based check, though no new patch version has been demanded.
