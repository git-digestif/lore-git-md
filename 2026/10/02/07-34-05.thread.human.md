This thread is about a bugfix series from Patrick Steinhardt that addresses a subtle packfile corruption issue caused by stale delta base cache entries. The bug, which became exposed after a 2024 change stopped leaking packfiles, leads to logical corruption when Git reuses memory addresses for `packed_git` structs after closing packs. The series is now in its second version, with only minor commit message improvements since v1.

The fix itself—evicting stale delta base cache entries when a pack is closed—has been uncontested throughout the discussion. The main debate centered on the regression test’s design, which relies on platform-specific memory allocation patterns (glibc and musl libc) and is not deterministic. Junio Hamano accepted the test’s limitations as a pragmatic trade-off, preferring its simplicity over a more complex but deterministic alternative. The test’s behavior is now confirmed to work on at least two libc implementations, though it may still fail on others like macOS or Windows.

The series is effectively ready for Junio’s `next` branch, with no outstanding objections to the core fix. The only loose end is whether to document the test’s platform dependency more prominently, but this is unlikely to block progress. Key participants—including Junio, Jeff King, and Philippe Blain—have all engaged substantively, and the thread has converged on the current approach.
