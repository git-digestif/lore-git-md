This thread is about a memory-safety bug in Git’s packfile handling, where stale delta base cache entries referencing freed `packed_git` structs can corrupt object reconstruction. The issue surfaced after a 2024 change stopped leaking packfiles, altering memory reuse patterns. Patrick Steinhardt’s two-patch series—one refactoring `close_pack()` and the other evicting stale cache entries—fixes the core problem and has seen no substantive objections.

The discussion has since shifted to test design. The original regression test relies on glibc’s allocator reusing memory addresses, making it platform-dependent (it didn’t reproduce on WSL). Jeff King (Peff) proposed using AddressSanitizer (ASan) to detect the bug as a user-after-free, but Patrick clarified that ASan’s behavior—allocating unique addresses for freed memory—actually *prevents* the bug from manifesting. The corruption stems from pointer reuse in the cache’s hashmap, not a direct memory-safety violation, so ASan can’t catch it. The thread now centers on whether the current test’s limitations are acceptable or if a more deterministic approach (e.g., mocking allocator behavior) is needed. No new patch versions have been posted, and the fix itself remains uncontested. Key participants include Patrick (author), Peff (reviewer), and Philippe Blain (who raised portability concerns).
