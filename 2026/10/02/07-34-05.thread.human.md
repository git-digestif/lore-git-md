This thread is about fixing a subtle packfile corruption bug caused by stale delta base cache entries, which can lead to incorrect object reconstruction when Git reuses memory addresses for `packed_git` structs after closing packs. The issue was exposed after a commit in August 2024 stopped leaking packfiles, altering memory reuse patterns.

Patrick Steinhardt submitted a two-patch series to address the bug: the first patch refactors `close_pack()` to avoid forward declarations, and the second introduces the core fix by evicting stale delta base cache entries when a pack is closed. The series includes a regression test, though it relies on glibc-specific allocation behavior, making it non-portable.

Guillaume Chauvel has now proposed a test improvement to replace the glibc-dependent test with a deterministic, platform-independent alternative. His patch introduces a new test helper (`test-delta-base-cache`) that forces memory reuse of a `packed_git` struct by manually copying one pack into the memory address of another, simulating the exact scenario that triggers the bug. This approach directly targets the root cause and avoids relying on allocator behavior. The new test is narrowly scoped, touching nine files but leaving the core fix in `packfile.c` untouched. While no substantive review has been posted yet, the design aligns well with the project’s preference for deterministic tests and addresses the only loose end in the original series. The series remains under review, with no major objections or open questions raised so far.
