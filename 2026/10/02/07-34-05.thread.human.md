Patrick Steinhardt sent a two-patch series to fix a subtle packfile corruption bug caused by stale delta base cache entries. The issue arises when Git reuses memory addresses for `packed_git` structs after closing packs, leading to incorrect object reconstruction if the new pack has entries at the same offsets. The bug became reproducible after a prior commit stopped leaking packfiles, altering memory reuse patterns.

The series is under review and consists of a preparatory refactoring (patch 1) and the core fix (patch 2), which evicts stale delta base cache entries when a pack is closed. Guillaume Chauvel later proposed a follow-up to replace the original glibc-dependent regression test with a deterministic, platform-independent version. Philippe Blain reviewed the series, raising minor questions about the original test’s design and portability but not contesting the fix’s correctness. Chu-Carroll about why the refactoring in patch 1 moves `close_pack()` later in the file—this is a procedural clarification with no bearing on the fix itself.
