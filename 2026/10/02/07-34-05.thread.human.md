This thread is about a two-patch series from Patrick Steinhardt that fixes a subtle packfile corruption bug caused by stale delta base cache entries referencing freed memory. The bug, which emerged after a 2024 change stopped leaking packfiles, leads to logical corruption when Git reuses memory addresses for new pack structures, causing incorrect object reconstruction. The fix itself—evicting stale cache entries when closing a pack—is uncontested and technically sound, with no substantive objections raised during review.

The discussion has largely focused on the regression test’s design. The test relies on glibc-specific memory allocation patterns and is platform-dependent, failing to reproduce the bug on systems like WSL or when AddressSanitizer is enabled. While this limitation was initially questioned, the thread has converged on accepting it as a pragmatic trade-off: the test is simple, won’t produce false positives, and its constraints are clearly documented. Junio Hamano, the maintainer, recently weighed in to endorse this approach, noting that while the test is an unreliable reproducer, its simplicity outweighs the complexity of alternatives like a deterministic allocator simulation. No further changes to the test are expected unless someone proposes a clearly superior solution.

The series is now effectively ready for integration. The core fix has no outstanding technical concerns, and the test’s limitations are understood and accepted. The only minor loose end is whether to document the test’s platform dependency more prominently, but this is unlikely to block progress. The patches are strong candidates for Junio’s `next` branch once the thread settles. Key participants—Patrick Steinhardt (author), Jeff King (reviewer), and Philippe Blain (reviewer)—have all engaged constructively, and the maintainer’s feedback aligns with the existing consensus.
