This thread is about a critical bugfix for a subtle packfile corruption issue discovered by Patrick Steinhardt. The bug occurs when Git reuses memory addresses for `packed_git` structs after closing packs, causing the delta base cache to retain stale entries that can lead to incorrect object reconstruction. The issue is reliably reproducible through recursive submodule merges.

Patrick has submitted a two-patch series to fix this. The first patch, already posted, refactored `close_pack()` to avoid forward declarations without changing behavior. The second patch, now available, implements the core fix: when a pack is closed, Git now evicts all delta base cache entries associated with that pack. This prevents stale cache entries from colliding with new packs allocated at the same memory address. The fix is minimal, surgical, and thoroughly tested with a new regression test in `t/t6437-submodule-merge.sh` that verifies the fix by creating 16 submodules with divergent branches.

The commit message is exceptionally clear, explaining the root cause, reproduction scenario, and potential consequences, including silent repository corruption. While the test is platform-dependent (relying on glibc’s allocation behavior), the fix itself is portable and addresses a long-standing assumption about packfile memory reuse. There are no open questions or contention points yet, and the series is under active review. This is a high-priority fix for a serious bug that could silently corrupt repositories in edge cases.
