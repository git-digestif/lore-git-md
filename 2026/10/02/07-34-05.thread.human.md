This thread is about a critical bugfix for a packfile corruption issue in Git, authored by Patrick Steinhardt. The bug occurs when stale delta base cache entries reference freed `packed_git` structs, leading to logical corruption if Git reuses the same memory addresses for new packs. This became a problem after a 2024 change stopped leaking packfiles, altering memory reuse patterns.

The fix is a two-patch series, now at v2, which remains unchanged in its core solution. The first patch refactors `close_pack()` to avoid forward declarations, while the second introduces a new function, `delta_base_cache_evict_entry()`, to evict stale cache entries when a pack is closed. The fix is minimal and uncontested, with no objections raised to its correctness. The accompanying regression test, though platform-dependent (relying on glibc’s allocator behavior), is accepted as a reasonable trade-off for simplicity.

Key participants include Patrick Steinhardt (author), Jeff King (who initially framed the bug as a user-after-free but later acknowledged it as a logical corruption from pointer reuse), and Philippe Blain (who raised questions about the test’s design and portability). The discussion has converged on the fix’s correctness and the test’s limitations, with no substantive technical feedback remaining.
