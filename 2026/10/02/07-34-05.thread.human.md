This thread is about a bugfix series from Patrick Steinhardt that addresses a subtle packfile corruption issue caused by stale delta base cache entries referencing freed `packed_git` structs. The bug, which became exposed after a 2024 change stopped leaking packfiles, leads to logical corruption when memory addresses are reused—though it doesn’t trigger AddressSanitizer (ASan) because it’s not a traditional use-after-free.

The series is now in its second version, with only minor commit message improvements since v1. The core fix (evicting stale cache entries when closing packs) and its regression test remain unchanged and uncontested. The test’s platform dependency—it relies on glibc or musl memory allocation patterns—was initially debated but accepted as a pragmatic trade-off, with Junio Hamano explicitly endorsing its simplicity over a more complex deterministic alternative. The only lingering discussion is whether to document the test’s limitations more prominently, but this is unlikely to block the series.

Jeff King (Peff) recently weighed in with a substantive follow-up, proposing an alternative fix that would convert the bug into a detectable memory-safety violation. However, he ultimately rejected his own idea, concluding that Patrick’s original approach is correct. This closes the last open technical question, leaving the series ready for Junio’s `next` branch. The thread has fully converged, with no remaining objections or requests for changes.
