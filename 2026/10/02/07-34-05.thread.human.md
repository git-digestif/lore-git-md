This thread is about a bugfix for a subtle packfile corruption issue caused by stale delta base cache entries. The bug occurs when Git reuses memory addresses for `packed_git` structs after closing packs, leading to incorrect object reconstruction if the new pack has entries at the same offsets. The issue became exposed after a 2024 commit stopped leaking packfiles.

Patrick Steinhardt submitted a two-patch series to fix the problem: the first patch refactors `close_pack()` to avoid forward declarations, and the second evicts stale delta base cache entries when closing a pack. The series includes a regression test in `t/t6437-submodule-merge.sh` that reproduces the bug via recursive submodule merges. Guillaume Chauvel later proposed a follow-up patch to replace the original test with a deterministic, platform-independent version that directly targets the bug’s root cause.

Philippe Blain recently reviewed the series, offering constructive feedback. He corrected a minor inaccuracy in the commit message (clarifying that `git merge` does not have a `--recurse-submodules` flag) and questioned the complexity of the test, noting that the original reproducer used only two submodules while the patch’s test merges more. He also reported that the bug did not reproduce on his WSL setup, suggesting platform-specific memory allocation behavior might explain the discrepancy. His review is collaborative and focuses on test design rather than the fix’s correctness, leaving the thread uncontroversial. The main open question is whether the test can be simplified or made more portable—though Guillaume’s follow-up already addresses this with a deterministic alternative. No substantive objections have been raised, and the series remains under review.
