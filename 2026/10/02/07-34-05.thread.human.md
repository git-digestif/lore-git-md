This thread is about a two-patch bugfix series from Patrick Steinhardt that fixes a subtle packfile corruption bug caused by stale delta base cache entries. The bug surfaces when Git reuses memory addresses for `packed_git` structs after closing packs, leading to incorrect object reconstruction if the new pack has entries at the same offsets. The fix evicts stale cache entries when a pack is closed.

The series is under review and remains uncontested. The first patch refactors `close_pack()` to avoid forward declarations, while the second introduces the core fix. The regression test, which relies on glibc-specific memory allocation patterns, has been acknowledged as platform-dependent but intentionally simple. Philippe Blain raised minor questions about the test’s design and portability, which Patrick clarified, and Guillaume Chauvel proposed an alternative deterministic test that was ultimately rejected as too complex.

Patrick has now addressed Mark C. Chu-Carroll’s procedural question about the refactoring in patch 1, confirming its purpose was to avoid forward declarations. No substantive objections or requests for changes have been raised, and the thread appears stable with no further action expected unless new feedback emerges.
