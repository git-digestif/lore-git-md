This is a refactoring and usability improvement series that extends Git’s parse-options API to support grouped subcommands, then applies it to `git refs`. The v2 iteration addresses all feedback from Junio C Hamano on the initial submission: it refactors the option-formatting logic to reduce nesting, extends `OPT_SUBCOMMAND_F` to accept help text (eliminating the need for a separate `OPT_SUBCOMMAND_H`), and renames the internal `first` flag to `shown` for clarity.

The series now consists of four patches instead of three. The new second patch extracts the option-formatting logic into a helper function, making the subsequent API changes cleaner and easier to review. The core functionality remains the same: `git refs -h` now displays subcommands grouped under “Reference database”, “Reading references”, and “Writing references”, making the help output far more scannable. The parse-options changes are mechanical and well-tested, with new coverage in `t/t0040-parse-options.sh` and a fix for a spurious leading space in completion output.

This is foundational work for Patrick Steinhardt’s ongoing effort to create focused, high-level commands like `git objects`. The API changes are unlikely to be controversial, and the `git refs` grouping is a natural and useful application of the new capability. The series looks ready for further review, with no open technical questions remaining from the v1 discussion.
