This is a **refactoring and API design patch** in Patrick Steinhardt’s series to add subcommand grouping to Git’s parse-options API. The email is a reply to Junio C Hamano’s review of patch 2/3, where Patrick accepts both of Junio’s suggestions.

Patrick agrees to refactor the option-formatting logic in `usage_with_options_internal()` into a helper function to reduce nesting and improve readability. He also accepts Junio’s API design critique: instead of introducing a new `OPT_SUBCOMMAND_H` macro (which would have been incomplete because it couldn’t accept flags), he will extend the existing `OPT_SUBCOMMAND_F` macro to support help text directly. This keeps the API consistent and avoids proliferation of similar-but-incomplete variants.

The changes are mechanical and non-controversial, addressing Junio’s feedback directly. No new technical concerns are raised, and the discussion is now focused on implementation details rather than the feature’s overall merit. A v2 of this patch is likely, incorporating these adjustments before the series moves forward. The broader goal—improving `git refs` usability by grouping subcommands—remains unchanged.
