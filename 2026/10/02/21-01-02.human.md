This is a usability bugfix discussion targeting the configuration subsystem. Brian M. Carlson chimes in on the ongoing thread about `git config --list --show-origin` displaying `.git/config` as a relative path (`file:.git/config`), which can mislead users about the repository's actual location.

Carlson supports showing the full, canonicalized (symlink-free) absolute path for `.git/config`, matching how other configuration sources are already displayed. He notes that callers already handle absolute paths elsewhere in the output, so the change would not introduce a new format. While he acknowledges the potential for script breakage, he agrees with Patrick Steinhardt that the risk is low. He also points out that users can already determine the absolute path to the local config file using `git rev-parse --path-format=absolute --git-path config`, reinforcing that the information is available and the proposed change would merely make it more visible.

The discussion remains focused on the trade-off between usability and backward compatibility, with no patch yet proposed. This is a minor but actionable issue that could be resolved with a small display-layer change and a new test in `t/t1300-config.sh`.
