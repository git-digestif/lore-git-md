This thread is an RFC discussion about a new signing mechanism that embeds SHA-256 digests of tree contents (including submodules) in signed commits and tags. The proposal, authored by Scott Chacon, aims to provide a migration path away from SHA-1 for commit/tag signing without requiring a disruptive switch to SHA-256 as Git’s default object format in Git 3.0. The series introduces a `--hash=sha256` option for `git commit -S` and `git tag -s`, along with a `gpg.treeHash=sha256` config key to make this behavior the default for all signed objects.

Junio C Hamano, the maintainer, has raised substantive design questions about the digest algorithm, particularly whether it should distinguish between file modes or symlinks pointing to the same content and whether it should reflect the internal structure of the tree object to detect corruption. While he praised the refactoring of tag header construction in one of the patches, he has not yet endorsed the overall direction and implies the current design may need rethinking. Scott Chacon has acknowledged concerns about the ecosystem impact of switching to SHA-256 as the default object format but has not yet addressed Junio’s technical questions.

The series is complete with four patches, covering the new CLI option, config key, and test coverage for edge cases like submodule cycles and missing commits. The implementation is object-format-agnostic, allowing it to work with both SHA-1 and SHA-256 repositories. No decisions have been made about merging, and the thread remains in the design-discussion phase. Key open questions include the viability of the digest algorithm, whether submodules should be excludable from the digest, and performance optimizations like streaming blob hashing. The proposal is positioned as an experimental alternative to the broader SHA-256 migration effort.
