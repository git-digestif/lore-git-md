This thread is an RFC discussion about a new signing mechanism proposed by Scott Chacon that embeds SHA-256 digests of tree contents (including submodules) in signed commits and tags. The goal is to provide a migration path away from SHA-1 for commit/tag signing without requiring a disruptive switch to SHA-256 as the default object format in Git 3.0. The series introduces a `--hash=sha256` option for `git commit -S` and `git tag -s`, along with a `gpg.treeHash=sha256` config key to make this behavior the default.

The proposal has faced early design scrutiny from Junio C Hamano, who raised questions about whether the digest algorithm should distinguish between file modes or symlinks pointing to the same content and whether it should reflect the internal structure of the tree object to detect corruption. The thread took a significant turn with a critique from brian m. carlson, who argues that the mechanism fails to address the core problem of SHA-1's collision resistance weaknesses and is misaligned with the project's long-standing plan to transition to SHA-256 as the default object format in Git 3.0. Carlson emphasizes that the Git project is already committed to this transition, with major forges already supporting SHA-256, and that the proposed tree digest approach does not enable the storage of colliding blobs—a key requirement for security researchers and users facing regulatory deadlines (e.g., the U.S. government's ban on SHA-1 by 2030). He suggests that the real solution lies in the interoperability work (rewriting repositories between hash algorithms during clone/fetch), which is not yet upstream but may be contributed by another company.

The series remains in the design-discussion phase, with no decisions or merge status recorded. Key open questions include the viability of the tree digest approach as an alternative to SHA-256 object format migration, the design of the digest algorithm, and whether the Git 3.0 timeline is truly immutable. The thread is now likely to pivot toward whether the interoperability work can address the same concerns or if the project needs to reconsider its strategy. Scott Chacon has not yet responded to Carlson's critique.
