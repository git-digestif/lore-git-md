This is patch 12/13 in Patrick Steinhardt’s ODB alternates refactoring series (v1). The patch moves alternates handling into the "files" backend, completing the architectural shift begun in earlier patches. It eliminates the conceptual mismatch where alternates were managed at the ODB source level, which caused performance regressions and blocked backend-agnostic extensions to `GIT_OBJECT_DIRECTORY` and `GIT_ALTERNATE_OBJECT_DIRECTORIES`.

Key changes in this patch:
- **Alternates as backend detail**: Alternates are now an implementation detail of the files backend, not a cross-source concept. The `read_alternates` callback is dropped, and alternates are read only by the files backend.
- **Environment variables**: `GIT_OBJECT_DIRECTORY` and `GIT_ALTERNATE_OBJECT_DIRECTORIES` are now handled by the files backend, as they are filesystem-specific concepts.
- **Code movement**: The alternates infrastructure (path parsing, deduplication, recursive addition) is moved from `odb.c` to `odb/source-files.c`. The `odb_source` struct loses its `next` pointer and `by_path_entry` field, as sources no longer form a linked list.
- **New symbols**: `odb_files_dir_is_usable()`, `odb_add_alternate_recursively()`, and `odb_prepare_alternates()` are introduced as files-backend-specific helpers. The `dirs_by_path` hashmap and `dirs_paths_icase` field are added to `struct odb_source_files` to track directories by path.
- **Behavior**: Alternates are now managed as a linked list of `struct odb_files_dir` within the files backend. The patch updates all ODB operations to loop through this list (reads check each directory in sequence; writes target only the first). Commands like `git fsck`, `git gc`, and `git pack-objects` are updated to iterate over directories instead of sources.

The patch touches 35 files, with the bulk of the changes in `odb.c` (354 lines removed) and `odb/source-files.c` (260 lines added). The diff is mechanical but invasive, converting loops over `odb->sources` to loops over `files->dirs`. The most complex part is the alternates infrastructure relocation, which includes path canonicalization, deduplication, and recursive alternate resolution.

This patch is the linchpin of the series, enabling future ODB work by making alternates a backend-specific concern. The changes are well-motivated and align with the series’ goal of simplifying the ODB architecture. Reviewers should focus on the alternates logic relocation and the linked-list traversal updates, particularly for edge cases like promisor remotes or partial clones. The patch is large but cohesive, and the commit message provides clear context for the architectural trade-offs.
