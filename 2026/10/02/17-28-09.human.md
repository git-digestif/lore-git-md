This is a review by Junio C Hamano of the second patch in Kristoffer Haugsbakk’s `[PATCH v3 2/2]` series, which adds `--[no-]range-diff-notes` options to `git format-patch`. The patch is part of a feature that allows users to control Git notes inclusion in the range-diff section independently of the patch output.

Junio’s feedback is surface-level, focusing on documentation and code style rather than the patch’s technical substance. He suggests two improvements: first, he asks for the commit message to be stripped of its conversational narrative and condensed into a concise technical explanation of the problem (range-diff notes inheriting patch notes, which may contain irrelevant iteration changelogs) and the solution (the new options and the `.override` flag). Second, he proposes rewriting the documentation for the new options to be more direct and less colloquial, offering a condensed version as an example.

In the code itself, Junio questions whether the `rdiff_notes_cb` callback should wrap the existing `parse_opt_string_list` function rather than duplicating its logic, to avoid future drift. This is a minor stylistic point and does not affect the patch’s correctness or functionality.

The patch itself remains technically sound and ready for integration. Junio’s feedback does not raise any substantive concerns about the implementation, and the requested changes are straightforward to address. The series as a whole is now waiting for a maintainer decision on whether to accept the feature.
