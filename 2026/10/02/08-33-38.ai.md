This is the second patch in a two-patch performance optimization series targeting the commit-graph subsystem. It implements the core logic for incremental commit-graph writes after fetches, using only the newly updated refs as seeds instead of scanning all refs.

The patch modifies `builtin/fetch.c` to collect updated refs into an `oidset` during `do_fetch()`, then passes them to `write_commit_graph()` when `fetch.writeCommitGraph` is enabled. The write strategy is controlled by a local enum with three modes: `REACHABLE` (fallback to full scan), `TIPS` (incremental write from updated refs), and `SKIP` (no-op fetches). The fallback to full scans occurs when no commit-graph exists or when fetching from multiple remotes, ensuring correctness is preserved. The `prepare_commit_graph()` function is made non-static to allow the fetch command to check for an existing graph.

Test coverage in `t/t5510-fetch.sh` verifies four key behaviors: incremental writes after fetches, exclusion of unrelated commits, skipping writes on no-op fetches, and fallback to full scans when no graph exists. The patch also touches `commit-graph.c` and `commit-graph.h` to expose the `prepare_commit_graph()` function.

The implementation is clean and well-scoped, with clear policy modes and thorough test coverage.
