This is the first patch in Christian Couder’s five-part v5 series introducing `uploadpack.lazyFetchTrusted`, a server-side mechanism for marking repositories as trusted for lazy fetching. This patch is a pure refactoring of the promisor-remote subsystem, extracting the lazy-fetch logic from `fetch_objects()` and `promisor_remote_get_direct()` into a new `lazy_fetch_objects()` helper.

The patch consolidates the `GIT_NO_LAZY_FETCH` environment check into a single up-front call, eliminating redundant checks (one per promisor remote in the old code). It also moves `promisor_remote_init()` into the new helper, aligning with the convention that initialization should happen where the data is needed. The refactoring is observably equivalent: the only behavioral differences are the reduced number of environment checks and the deferred initialization, neither of which changes the outcome.

Documentation for `try_promisor_remotes()` and the new `lazy_fetch_objects()` is added, clarifying ownership rules for the `remaining_oids` and `to_free` arguments—critical for avoiding memory leaks. The commit message explicitly calls out the two observable shifts (single environment check, deferred initialization) and explains why they are safe.

This patch is a prerequisite for the later ones in the series, which build on the refactored `lazy_fetch_objects()` to implement the server-side trust model. It has no functional impact on its own and could be merged independently if the series stalls. Junio’s earlier feedback on this patch (documentation wording, logical simplification) is fully addressed in v5. The patch touches only `promisor-remote.c` and is cleanly isolated from the rest of the series.
