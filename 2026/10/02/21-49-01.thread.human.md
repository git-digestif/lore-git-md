This thread began when Alejandro Colomar asked whether Git provides a plumbing command to retrieve the commit identified by `git bisect` as the culprit, without parsing porcelain output. The question is now fully resolved: Jeff King (Peff) and Junio C Hamano have confirmed that the culprit commit is reliably stored in the `refs/bisect/bad` ref, which can be accessed via standard plumbing commands like `git rev-parse bisect/bad` or `git show bisect/bad`. Junio’s follow-up traced the code path in `bisect.c`, demonstrating that the ref is updated even when the bisect algorithm determines the current `HEAD` is already the culprit, ensuring the result is always available. No patches or further discussion are needed; the existing mechanism meets the requirement.
