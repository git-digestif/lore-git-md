This is a small refactoring patch in Kristoffer Haugsbakk’s two-part series adding `--[no-]range-diff-notes` to `git format-patch`. The patch simplifies the `get_notes_args` function by removing a redundant parameter: the function previously took both a `struct strvec *` and a `struct rev_info *`, even though the `strvec` could be accessed directly through the `rev_info` struct. Now it takes only the `rev_info` pointer, making the calling convention cleaner and more consistent.

Junio C Hamano, the maintainer, reviewed the patch and suggested a small improvement to the commit message, replacing the first-person narrative with a more objective description. The code change itself is uncontroversial and well-motivated, touching only `builtin/log.c` and reformatting a long line for readability. The patch is compile-tested and serves as a preparatory step for the new functionality introduced in the second patch of the series.

This patch is part of the ongoing effort to allow independent control over Git notes in `git format-patch` output, specifically enabling users to suppress notes in the range-diff section while retaining them in the patch output. The refactoring builds on prior commit 85bd88a7 (2025-09-25), which added `rdiff_log_arg` to `struct rev_info`. The change is mechanical and does not alter behavior, but it is necessary for the next patch, which implements the new `--[no-]range-diff-notes` options.

The patch looks solid and ready for integration. It is a minor but useful cleanup that simplifies the codebase without introducing risk. If the feature series is accepted, this patch will be a straightforward inclusion.
