This is the fourth and final patch in Scott Chacon’s RFC series proposing a new signing mechanism that embeds SHA-256 digests of tree contents in signed commits and tags. This patch adds a `gpg.treeHash` configuration key so users can set `--hash=sha256` as the default for all signed objects without having to remember the flag each time.

The change is small and self-contained: it adds the config variable, updates the documentation to mention it, and teaches both `git commit` and `git tag` to read it. The implementation is careful to preserve backwards compatibility—unsigned objects are created exactly as before, and `--hash=none` overrides the config. New tests verify that the config works for both commands, that it leaves unsigned objects alone, and that invalid values are rejected with clear error messages.

This patch completes the series: the mechanism is now fully usable either via the command-line flag or the config key. The author’s stated goal is to offer a migration path away from SHA-1 signing without requiring a disruptive switch to SHA-256 as the default object format in Git 3.0. Whether that goal is met will be the focus of the upcoming discussion, but the implementation itself is clean, well-tested, and ready for review.
