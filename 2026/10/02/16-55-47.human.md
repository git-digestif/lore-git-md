This is a small but user-facing feature patch for the `git branch` command. The change makes `git branch --delete-merged` (with no additional arguments) default to deleting every local branch whose tip is reachable from its configured upstream. Previously, users had to specify a pattern like `*/*` to achieve the same effect.

The motivation is straightforward: cleaning up branches that have already been merged upstream is a common workflow, and the new default spares users from remembering or typing the glob pattern. The patch updates the documentation, the command-line help text, and the option parser to treat a bare `--delete-merged` as if the user had supplied `**` (every upstream). It also adds a test that verifies the new behavior works as intended and leaves the existing `--delete-merged <pattern>` syntax unchanged.

The implementation is clean and conservative: the option parser uses `PARSE_OPT_LASTARG_DEFAULT` so that `--delete-merged` only takes the default when it is the last argument, preserving the ability to preview deletions with `--dry-run --delete-merged`. The test coverage is adequate, exercising both the dry-run and actual deletion paths.

Overall, this looks like a well-considered usability improvement that should be uncontroversial. It doesn’t touch any sensitive internals, and the backward-compatibility story is clear.
