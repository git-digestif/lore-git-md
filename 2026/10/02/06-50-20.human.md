This is a small but useful feature patch for `git-contacts`, a contrib script that helps identify potential reviewers for patches. The patch allows the script to read patch content from stdin when the user passes `-` as an argument, following the conventional UNIX idiom. This enables mixed file/stdin usage (e.g., `git contacts patch1 - patch3 <patch2`) and improves interoperability with external tools like `b4`.

The implementation is straightforward: the script now checks for `-` in its arguments and sets a flag to read from stdin if present, replacing an earlier implicit stdin detection mechanism. The patch also updates the script’s internal usage comment and adds clear documentation in `git-contacts.adoc`, explaining that a single dash reads patch file(s) from stdin. The documentation includes an example (`git contacts - <feature.patch`) and clarifies that stdin can be combined with other input types.

This is the sixth iteration of the patch, incorporating feedback from Junio and others. The feature itself was merged in an earlier version, and this update consolidates the documentation and usage comment changes into a single commit, addressing minor procedural feedback about keeping these elements in sync. The patch is uncontroversial, well-explained, and ready to apply. It’s a nice quality-of-life improvement for users of `git-contacts`, especially those integrating it into toolchains.
