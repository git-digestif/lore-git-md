This thread is about a patch series (v2) by Kristofer Karlsson that optimizes Git's `fetch.writeCommitGraph` feature for large repositories. The goal is to avoid the current inefficiency of rebuilding the commit-graph from all reachable refs after every fetch by instead writing only the newly fetched commits when possible.

The series is now technically uncontested after Patrick Steinhardt's thorough review of the first version. Kristofer addressed all feedback in v2, including questions about edge cases like shallow refs, benchmarking, and fallback behavior. The implementation introduces an incremental write strategy that tracks updated refs during fetch and uses them as seeds for commit-graph updates, falling back to full scans only when necessary (e.g., no existing graph or multi-remote fetches). Performance improvements are significant - in a synthetic test with 200K refs, the time for a single ref update dropped from 357ms to 9.3ms.

The patch touches the commit-graph subsystem and includes new test coverage verifying correct behavior in various scenarios. No open questions remain, and the series appears ready for final review and potential merging. The changes are self-contained and don't interact with other in-flight Git efforts.
