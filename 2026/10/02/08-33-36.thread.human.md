This thread introduces a performance optimization for Git's commit-graph subsystem, aiming to reduce the overhead of `fetch.writeCommitGraph` in large repositories. Currently, Git rebuilds the commit-graph from all reachable refs after every fetch, which is inefficient when only a few refs have changed. Kristofer Karlsson's two-patch series proposes an incremental write strategy that updates the commit-graph using only the newly fetched commits when possible, falling back to a full scan only when necessary (e.g., no existing graph or multi-remote fetches).

The implementation touches `builtin/fetch.c`, `commit-graph.c`, and related files, introducing a new enum to control the write strategy (`REACHABLE`, `TIPS`, or `SKIP`) and an `oidset` to track updated refs during fetches. The series includes thorough test coverage in `t/t5510-fetch.sh`, verifying incremental writes, exclusion of unrelated commits, and fallback behavior. No reviews or objections have been posted yet, so the series is awaiting substantive feedback. If accepted, this change could significantly improve fetch performance in repositories with many refs.
