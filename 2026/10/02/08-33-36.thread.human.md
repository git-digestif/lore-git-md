This thread is about a two-patch series from Kristofer Karlsson that optimizes Git’s `fetch.writeCommitGraph` behavior for large repositories. The goal is to avoid the current inefficiency of rebuilding the commit-graph from all reachable refs after every fetch by introducing an incremental write strategy that only processes newly fetched commits when possible. The series is now at version 2, with a version 3 planned solely to address minor stylistic feedback.

The core design is uncontested after Patrick Steinhardt’s thorough review of the first version, which raised questions about edge cases like additive seeds, split-mode behavior, and shallow ref handling—all of which were clarified and addressed in the reroll. Version 2 added synthetic benchmark numbers (showing a reduction from 357ms to 9.3ms for a single ref update), a code comment explaining ref status filtering, and expanded test coverage. The only remaining feedback is surface-level: commit message formatting and test script style, which Kristofer has agreed to fix in the upcoming v3. No technical objections or open questions remain, and the series is effectively ready for final review. The first patch (a test helper) has no outstanding concerns, while the second (the fetch logic) is now just waiting for the stylistic tweaks. No merge status has been reported yet.
