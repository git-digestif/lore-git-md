This thread is about a two-patch series from Kristofer Karlsson that optimizes Git's `fetch.writeCommitGraph` behavior for large repositories. The goal is to avoid the current inefficiency of rebuilding the commit-graph from all reachable refs after every fetch by introducing an incremental write strategy that only processes newly fetched commits when possible.

The series is now technically uncontested after Patrick Steinhardt's thorough review, which raised questions about edge cases like additive seeds, split-mode reliance, and ref status filtering. Kristofer addressed all concerns in his replies, and the upcoming reroll will include clearer commit messages, benchmark numbers (showing a reduction from 360ms to 9ms for single-ref updates), a code comment explaining the ref status filtering logic, and an additional test for shallow ref handling. The series touches the commit-graph subsystem, adding new APIs and an enum to control write strategy, and has demonstrated significant performance improvements in synthetic testing.

No merge status has been reported yet, but the series is now in its final review phase with only documentation and test-coverage improvements planned before it can be considered for merging.
