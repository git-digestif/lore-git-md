This thread is about a two-patch series from Kristofer Karlsson that optimizes Git's `fetch.writeCommitGraph` feature for large repositories. The goal is to avoid the current inefficiency of rebuilding the commit-graph from all reachable refs after every fetch by introducing an incremental write strategy that only processes newly fetched commits when possible.

The series is now at version 2, which addresses all feedback from Patrick Steinhardt's substantive review of the first version. Key improvements include updated commit messages with benchmark numbers showing a significant speedup (from 357ms to 9.3ms for a single ref update), a code comment explaining the ref status filtering logic, and expanded test coverage. The series touches the commit-graph subsystem, adding new APIs and a test helper to verify the incremental write strategy works correctly without losing commit coverage or mishandling shallow refs.

Patrick Steinhardt's thorough review raised important questions about edge cases, which Kristofer addressed in this reroll. The series appears technically uncontested and is ready for merging, though no merge status has been reported yet. The first patch in this v2 series adds a test helper to verify commit-graph contents, which is a prerequisite for the new tests but doesn't change Git's runtime behavior.
