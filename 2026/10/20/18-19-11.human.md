This is a two-patch bugfix series targeting Git's hook configuration system. The author, Thomas Bachem, addresses two small but clear discrepancies between documented behavior and actual implementation.

The first patch ensures that `hook.pre-commit.enabled=false` actually disables the pre-commit hook in the hooks directory, aligning behavior with the documentation. Currently, the config setting is ignored for hooks in the traditional hooks directory, which contradicts the manual's claim that it applies universally.

The second patch makes the boolean configuration options `hook.*.enabled` and `hook.*.parallel` accept empty values (treated as `true`), matching Git's standard behavior for other boolean config keys. This is a minor consistency fix that removes a potential source of user confusion.

The patches touch `builtin/hook.c`, `hook.c`, and `hook.h`, and include a substantial test expansion in `t/t1800-hook.sh` that covers both the new behavior and edge cases. The commit messages are clear and the changes appear narrowly scoped to the stated problems.

This looks like a well-crafted, uncontroversial fix for two long-standing but low-severity bugs in the hook subsystem. The series is ready for review and likely to be merged once any minor feedback is addressed.
