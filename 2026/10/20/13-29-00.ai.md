This is the final patch in a four-patch bugfix series targeting the object database (ODB) transaction machinery. It implements the core fix for a race condition where concurrent `git-receive-pack` processes could delete each other’s `.keep` lockfiles, leaving newly written packfiles vulnerable to deletion by housekeeping processes.

The patch moves `.keep` lockfile creation from the quarantine phase (`odb_transaction_files_write_pack()`) to the transaction commit phase (`odb_transaction_files_commit()`). Instead of writing lockfiles immediately during quarantine, packfile names are stored in a `strvec` and batch-written as lockfiles only if the transaction commits successfully. This ensures lockfiles are never left in an inconsistent state and prevents the `atexit` handler from deleting lockfiles belonging to other processes. The change touches `object-file.c` and extends the test script `t/t5547-push-quarantine.sh` to verify the fix: the test now confirms that a manually created `.keep` file (simulating a concurrent process) is not deleted by the transaction cleanup, and that no corresponding `.pack` file exists alongside it.

Key symbols introduced or modified include `write_pack_lockfiles()` (a new helper that batch-creates lockfiles during commit) and the `pack_names` field added to `struct odb_transaction_files` to track packfile names during quarantine. The patch also removes the now-unused `final_path` and `keep_msg` strbufs from `odb_transaction_files_write_pack()`, consolidating lockfile creation logic in the new helper. Error handling is preserved, with lockfile creation failures propagated as transaction commit errors.

The series has Patrick Steinhardt’s explicit approval, and this patch incorporates all prior feedback, including the final stylistic tweaks (explicit error return assignment and newline removal) requested in the v3 iteration. The only lingering concern—whether leading directories for lockfiles are guaranteed to exist during quarantine—was flagged by Patrick but not addressed here; the author considers the assumption safe, and Patrick did not revisit it in his final review. The patch is technically complete and ready for integration.
