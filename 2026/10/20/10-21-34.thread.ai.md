Thread identity: Bugfix patch series (single patch) from GSoC contributor Aniket Gupta, correcting a misleading progress message in `git fsck --verbose` that reports hash bucket count instead of actual object count.

Core problem or goal: Replace the incorrect object count displayed during `git fsck --verbose` (which shows the number of hash buckets rather than the true number of objects) with the actual object count, improving clarity for users. The message is intended to reflect the number of objects *checked* during fsck, but in partial clones this may include objects not locally present or even downloaded, creating a potential disconnect between the reported count and the user's expectations.

Current status: Under review. This is the first iteration of the patch (no prior versions posted). The patch introduces a new helper function `get_object_count()` in `object.c`, updates the connectivity message in `builtin/fsck.c`, and adds tests in `t/t1450-fsck.sh` to verify both singular and plural message forms. The implementation is straightforward and builds on a prior queued patch ("fsck: use Q_() for the verbose connectivity message"). Discussion has converged on the commit message wording, with Laveesh Bansal adding a `Reviewed-by` trailer and accepting the reworded title "report the number of objects in the connectivity message"; Junio C Hamano has yet to make a final call on the exact phrasing.

- Files touched: `object.c`, `object.h`, `builtin/fsck.c`, `t/t1450-fsck.sh`.
