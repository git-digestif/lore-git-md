This is the fifth patch in Phillip Wood’s seven-patch refactoring series (`pw/stash-optimize-check_changes-calls/v3`), which targets redundant index operations in `git stash push` and `git stash create`. The patch replaces `reset_tree()` with `create_index_from_tree()` in `stash_working_tree()` to create the temporary index file used for stashing uncommitted working tree changes. The change eliminates reliance on the global `set_alternate_index_output()` mechanism, avoids overwriting the in-memory index, and removes an unnecessary `repo_read_index_preload()` call, saving one `lstat()` per changed path. A new `reset` boolean parameter is added to `create_index_from_tree()` to control whether the index is reset or merged into, preserving intent-to-add entries. The patch is confined to `builtin/stash.c` and introduces no user-visible behavior changes, focusing solely on code hygiene and performance. The refactoring aligns the implementation with the existing pattern used for `git stash push -p` and simplifies reasoning about index state by avoiding side effects on the in-memory index.
