This is the fourth patch in a five-patch feature series introducing a "matching-inspired" fetch mode for shallow repositories. The patch adds a `--limited-fetch` flag to `git remote add`, which configures the remote to use the new `remote.<name>.refmap` setting instead of the traditional wildcard `remote.<name>.fetch` refspec. This is a straightforward plumbing addition with no behavioral changes to Git itself—it merely provides a user-facing way to opt into the dynamic branch-fetching logic introduced earlier in the series.

The implementation is clean and uncontroversial. The flag is rejected when combined with `-t/--track` or `--mirror`, since those options already specify explicit fetch behavior. The patch updates `builtin/remote.c` to set the refmap configuration via `repo_config_set()` and adds documentation to `git-remote.adoc`. Four new tests in `t/t5505-remote.sh` verify that the flag works as expected, conflicts appropriately with `-t`, and does not interfere with existing functionality. The logic reuses the existing `limited_fetch` machinery and does not introduce new technical debt.

This patch is ready for review and has no unresolved technical concerns. It is a pure plumbing change that enables the user-facing opt-in for the new fetch mode, and its design aligns with the series' overall goal of reducing unnecessary history negotiation in shallow repositories. The only open question is whether the `--limited-fetch` flag should be the default for *all* repositories (not just shallow ones), but that is a design choice for the series as a whole and not a blocker for this patch. The patch itself is well-scoped and self-contained.
