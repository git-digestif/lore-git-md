This is a small i18n patch targeting the ZIP archive backend, ready for inclusion. The patch replaces a hardcoded singular/plural error message in `archive-zip.c` with Git’s `Q_()` macro to support proper pluralization in all languages, not just English. This is the fourth iteration of a standalone patch, incorporating all prior feedback from Phillip Wood and Junio C Hamano.

The change is mechanical and low-risk: it splits an existing error message in `write_zip_entry()` into singular and plural variants without adding new strings to the translation catalog. The error is triggered when a path exceeds the ZIP format’s 65,535-byte limit, so the English singular case (`pathlen == 1`) is unreachable, but `Q_()` is still valuable for languages with more complex plural rules (e.g., Polish). The commit message clearly explains this context and the broader i18n motivation.

This version addresses the last remaining feedback: indentation is now done with tabs, `Q_()` arguments are aligned, and lines are wrapped to stay under 80 characters. No logic, test, or documentation changes are required. Both reviewers have already endorsed the approach, and the patch is uncontroversial. Junio is expected to pick it up for `next` shortly. The file touched is `archive-zip.c`; the key macro introduced is `Q_()`.
