This is the third patch in Justin Tobler’s four-patch v3 series fixing a race condition in the ODB transaction machinery. It refactors `odb_transaction_files_write_pack()` to stop relying on `git-index-pack --keep` for `.keep` lockfile creation and instead write the lockfile explicitly in-process. The helper `write_pack_lockfile()` is introduced to construct the lockfile path, write the keep message (`"receive-pack <pid> on <hostname>"`), and register it as a tempfile. Error messages now include `errno` context and the lockfile path for diagnostic clarity. The patch also renames the internal `write_pack_lock()` to `write_pack_lockfile()` for consistency with existing naming conventions, addressing Patrick Steinhardt’s feedback from earlier rounds. All stylistic tweaks requested by Patrick—explicitly assigning the error return value and removing an extraneous newline—are incorporated. The only remaining loose end, whether leading directories for lockfiles are guaranteed to exist during quarantine, was flagged by Patrick but not revisited; the author justifies the assumption as safe without adding explicit directory creation. The series as a whole is technically complete and has Patrick’s explicit approval.
