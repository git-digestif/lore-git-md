This is the cover letter for the v10 iteration of Harald Nordgren’s five-patch series that introduces a “matching-inspired” fetch mode for shallow repositories. The goal is to stop a plain `git fetch` from negotiating history for every remote branch when the local repository is shallow (`git clone --depth=…`), which can hang or take minutes on large remotes.

The series is now technically complete: all substantive review points from Junio and others have been addressed, the code is cleanly split into five focused commits, and the test coverage is thorough (119 lines in a new `t/t5586-fetch-refmap.sh` plus additions to `t5505` and `t5510`). The only change in v10 is a trivial merge conflict resolution after Junio integrated Collin’s `ch/fetch-followremotehead-lazy-validation` topic into `master`.

Key moving parts:

- A new `remote.<name>.refmap` configuration key (Patch 1) that defines namespace mappings without specifying what to fetch.
- A helper function `collect_upstream_from_remote()` (Patch 2) extracted to reduce duplication.
- Dynamic branch inference (Patch 3): when no explicit refspec is given and the remote has a refmap but no `remote.<name>.fetch`, the fetch enumerates only the branches tracked by local branches at that remote.
- A `--limited-fetch` flag for `git remote add` (Patch 4) that configures the refmap instead of the traditional wildcard `remote.<name>.fetch`.
- Shallow-repository default (Patch 5): `git remote add` now defaults to `--limited-fetch` when the repository is shallow, so new remotes automatically use the narrow fetch mode.

The design is uncontroversial: `remote.<name>.fetch` still takes precedence if both are configured, the remote’s default branch is no longer fetched by default, and non-shallow repositories continue using wildcard refspecs. The implementation reuses existing machinery and introduces no new technical debt. Junio’s two review points from v8 (control-flow reorganization and NULL-check restoration) are fully resolved, and the series is ready for final maintainer feedback before graduating to `next`.
