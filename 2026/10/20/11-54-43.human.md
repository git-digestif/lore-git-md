This is a test patch adding basic coverage for `git mktree --batch`. The existing test suite had only one test for the batch mode (checking that it survives a concurrent repack), which left a leak (fixed in commit 6272f3bd17) unnoticed until recently. Roger Koranteng adds seven new tests that exercise core batch-mode behavior: verifying that multiple trees in one batch produce the same IDs as running `mktree` individually, that trailing blank lines are ignored, that `-z` input works, and that a missing object causes `mktree` to die after printing the trees it already processed. One test also documents the current (but possibly unintended) behavior of accepting two blank lines in a row and producing an empty tree between them.

The patch is well-motivated, clearly explained, and touches only the test file `t/t1010-mktree.sh`. It follows the project’s test style and includes a Suggested-by trailer crediting Jeff King. No controversy is evident; this looks like a straightforward, uncontroversial addition that fills an obvious gap in test coverage.
