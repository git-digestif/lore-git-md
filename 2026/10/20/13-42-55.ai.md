This is Patch 2/5 of the v10 series introducing a "matching-inspired" fetch mode for shallow repositories. The patch extracts the existing logic for fetching the current branch's upstream into a reusable helper, `collect_upstream_from_remote()`, so it can later be applied to *all* branches tracked at a remote, not just the current one.

The change is a pure refactoring with no behavior differences. The helper is introduced in `remote.c`/`remote.h` and takes a `struct repository *` parameter to avoid hardcoding `the_repository`, aligning with the ongoing `the_repository` removal effort. The `do_fetch()` function in `builtin/fetch.c` is updated to use the new helper, replacing the inlined logic that previously only handled the current branch. The helper itself is straightforward: it checks whether a given branch (or the current branch if `refname` is NULL) has an upstream on the specified remote, and if so, adds its source ref to the provided `string_list`.

This patch directly addresses Junio’s review feedback from v8, which requested moving the control-flow reorganization to Patch 3/5 and restoring the NULL-check for `branch` in the helper. Both points are now resolved: the helper is a clean extraction, and the NULL-check is preserved via `repo_branch_get(repo, refname)`. The patch is uncontroversial and ready for review, with no design decisions embedded. It lays the groundwork for Patch 3/5, which will use this helper to implement dynamic branch enumeration.
