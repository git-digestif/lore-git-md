This is the second patch in Jason Newton’s v2 series introducing worktree improvements. It implements **automatic reaping of ephemeral branches**—branches that `git worktree add` auto-creates when no branch is specified (e.g., `git worktree add ../hotfix` creates branch `hotfix`). These branches are now treated as owned by the worktree and are deleted when the worktree is removed, eliminating a long-standing cleanup nuisance.

The patch is clean and well-scoped. It records ownership by writing the branch name to a new administrative file (`worktrees/<id>/owned-branch`) at creation time, ensuring the branch is only reaped if it was auto-created (not pre-existing or named explicitly with `-b/-B`). The `git worktree remove` command now deletes the owned branch unless `--keep-branch` is passed, and `git branch -m` updates the marker so ownership follows a rename. The implementation is backward-compatible: older Git versions simply ignore the marker and keep the branch on removal, as before.

Test coverage is thorough, verifying edge cases like branch renames, pre-existing branches, and `--keep-branch`. The documentation updates clearly explain the behavior and tradeoffs (e.g., unmerged commits are deleted by default, but can be preserved by anchoring them with an ordinary branch). This addresses a real usability pain point without introducing complexity, and the design—treating auto-created branches as disposable by default—feels like a natural fit for the worktree model. The patch is likely to be uncontroversial.
