Subject: [PATCH] init: restore absolute path output in "Initialized empty Git repository" message
Series version: standalone patch (v3 posted)
Originating author: Matt Hunter <m@lfurio.us>
Thread type: bugfix patch

Core problem or goal
Restore the pre-20e38cba3926 behavior of `git init` and `git init --reinit` to print the absolute path of the initialized repository (e.g., `/home/user/repo/.git`) instead of the relative `.git/` path. The regression was introduced unintentionally in 20e38cba3926 (setup: split up concerns of `init_db()`, 2026-09-10) during the current development cycle (Git 2.56), making the fix urgent to avoid shipping the behavior change in the upcoming release.

Current status
Ready for integration. The author has posted v3 incorporating all feedback, including Patrick Steinhardt’s requested test refinements. Patrick Steinhardt’s explicit approval ("Thanks, I'm happy with this version") confirms the patch is complete and uncontroversial. The regression’s introduction in the current cycle (Git 2.56) continues to give the patch urgency.

Key technical details
- Files touched: `builtin/init-db.c`, `t/t0001-init.sh`
- New symbols: none (local variable `full_git_dir` added, but not exposed)
- Old behavior: printed relative `.git/` path
- New behavior (post-patch): prints absolute path (e.g., `/home/user/repo/.git`)
- On-disk format: unchanged
- Test coverage: added in v2 and refined in v3; the test in `t/t0001-init.sh` verifies the full output message for the default case (non-shared, empty repository initialization) by directly comparing the expected output (`echo "Initialized empty Git repository in $(pwd)/init-path/.git/" >expect`) against the actual command output. The unnecessary intermediate variable from v2 has been removed, and the test uses a temporary file for the expected output.

None. All feedback has been addressed, and the patch is ready for integration.
