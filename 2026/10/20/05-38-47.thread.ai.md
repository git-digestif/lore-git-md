Subject: [PATCH] init: restore absolute path output in "Initialized empty Git repository" message
Series version: standalone patch (v3 imminent)
Originating author: Matt Hunter <m@lfurio.us>
Thread type: bugfix patch

Core problem or goal
Restore the pre-20e38cba3926 behavior of `git init` and `git init --reinit` to print the absolute path of the initialized repository (e.g., `/home/user/repo/.git`) instead of the relative `.git/` path. The regression was introduced unintentionally in 20e38cba3926 (setup: split up concerns of `init_db()`, 2026-09-10) during the current development cycle (Git 2.56), making the fix urgent to avoid shipping the behavior change in the upcoming release.

Current status
Under review; the author has posted a v2 incorporating all feedback and adding a regression test. Patrick Steinhardt has suggested two minor test improvements (removing an unnecessary intermediate variable and testing the full output message rather than a substring) in his review of v2. The author has now proposed a refined test assertion that checks the full output message for the default case (non-shared, empty repository initialization), addressing Patrick’s feedback while acknowledging the complexity of covering all four possible output variants. The patch remains a minimal, narrowly scoped fix targeting a single user-visible regression. All substantive concerns have been addressed, and the patch is ready for integration once the test tweaks are finalized. The regression's introduction in the current cycle (Git 2.56) continues to give the patch urgency.
