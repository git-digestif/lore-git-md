This is a **bugfix** for the `status` and `checkout` commands, clarifying the message shown when a local branch tracks a remote branch that does not exist (whether never created or deleted). The patch is in its final stages of review, with Junio C Hamano and the author (Elia Pinto) now fine-tuning edge cases and compatibility concerns.

The core change—rewording the message from "upstream is gone" to "does not exist"—has been agreed upon and is effectively settled. Junio praised the neutral phrasing as covering both "never created" and "deleted" cases cleanly. The conditional advice logic (suggesting `git push` only when it would actually create the missing branch, otherwise recommending `git branch --unset-upstream`) is also approved, though Elia is refining the `push.default` edge-case handling in the upcoming v2.

A key discussion point in this email is the `[gone]` indicator in short formats like `git status -sb` and `git branch -vv`. Junio suggested replacing it with `[missing]`, but Elia argues for leaving it unchanged in this patch to avoid breaking scripts that rely on `git branch -vv | grep ': gone]'`. The porcelain formats (`--porcelain`, `--porcelain=v2`, and `for-each-ref`) are confirmed to be script-critical and will retain `[gone]` regardless. The human-readable formats (`git status -sb` and `git branch -vv`) could theoretically be updated later, but Elia proposes handling that in a separate follow-up to keep this patch focused.

The patch touches `remote.c` and adds comprehensive tests in `t/t6040-tracking-info.sh`. No on-disk format changes are involved, and the commit message already provides excellent context. With Junio’s substantive engagement and no unresolved technical objections, this is likely to graduate to `next` soon, pending the v2 update.
