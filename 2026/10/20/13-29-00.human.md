This is the final patch in a four-part bugfix series targeting a race condition in Git’s object database (ODB) transaction machinery. The series, authored by Justin Tobler and approved by Patrick Steinhardt, is technically complete and ready for integration.

This patch moves the creation of `.keep` lockfiles from the quarantine phase to the transaction commit phase. Previously, temporary lockfiles were registered in the object quarantine *before* being written to the primary ODB, which created a race: if the transaction exited early (e.g., due to an error), the `atexit` handler would still attempt to clean up the lockfile at its final location, potentially deleting a lockfile belonging to another process. This left newly written packfiles vulnerable to deletion by housekeeping processes. The fix ensures lockfiles are only written after the transaction is guaranteed to succeed, eliminating the race.

The patch touches `object-file.c` and extends the test script `t/t5547-push-quarantine.sh`. In `object-file.c`, it introduces a new helper function, `write_pack_lockfiles()`, which batch-creates lockfiles during transaction commit. The patch also modifies `odb_transaction_files_write_pack()` to store packfile names in a `strvec` during quarantine, deferring lockfile creation until commit. The test now verifies that no `.keep` lockfile exists in the quarantine directory during the pre-receive phase and that a manually created `.keep` file (simulating a concurrent process) is not deleted by the transaction cleanup. It also confirms no corresponding `.pack` file exists alongside the `.keep` file, addressing Patrick Steinhardt’s request for additional coverage.

The change is well-motivated and addresses all prior feedback. The only lingering concern—whether leading directories for lockfiles are guaranteed to exist during quarantine—was flagged by Patrick but not revisited in his final review, and the author has not provided further justification or directory-creation logic. This is unlikely to block integration, as the series is otherwise considered complete and technically sound. The patches are part of the ongoing ODB abstraction effort led by Patrick Steinhardt.
