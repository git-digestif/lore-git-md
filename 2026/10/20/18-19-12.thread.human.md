This thread is about a bugfix to Git's hook subsystem, part of Adrian Ratiu’s broader effort to make hooks configurable via Git configuration. The patch, authored by Thomas Bachem, addresses an inconsistency where `hook.<event>.enabled=false` only disabled hooks defined in Git configuration (`hook.<name>.command`) but not traditional hooks in `.git/hooks/`. The documentation claims that no hooks fire for that event when the setting is false, but in practice, traditional hooks still ran.

The fix moves the `event_disabled` flag out of the `u.configured` union so it applies to all hook types, ensuring both configured and traditional hooks respect the setting. The change touches `builtin/hook.c`, `hook.c`, and `hook.h`, and adds test coverage in `t/t1800-hook.sh` to verify that disabled hooks are not executed and are correctly marked as "event-disabled" in `git hook list`. The patch also fixes a latent test issue where the existing test for `hook.<event>.enabled=false` only checked standard output, not standard error, so it passed even when disabled hooks ran.

So far, the patch appears uncontroversial—it’s a straightforward correctness fix that aligns behavior with documentation, and the test additions are thorough.
