This is a v2 cover letter for a two-patch series that refines the worktree copy-on-write (CoW) feature proposal, now focusing solely on reflink-based worktree creation and ephemeral branch cleanup. The series drops the controversial shared-branch functionality in response to feedback from Junio C Hamano and brian m. carlson.

The first patch adds `--reflink` support to `git worktree add`, enabling CoW worktree creation on supported filesystems (btrfs/XFS/bcachefs on Linux, APFS on macOS, ReFS on Windows). The implementation now includes Windows ReFS block cloning (via `FSCTL_DUPLICATE_EXTENTS_TO_FILE`, matching Git LFS's approach) and clarifies that overlayfs is supported when its lower filesystem supports reflinks. The patch maintains the opt-in design (`worktree.reflink` config) but adds detailed documentation about edge cases: dirty worktrees, untracked file handling, and the recommended pattern for creating multiple worktrees at the same commit (using a single `update-ref` transaction with per-worktree refs or detached HEADs).

The second patch introduces automatic cleanup of ephemeral branches—those auto-created by `git worktree add` without `-b`—when the worktree is removed. This addresses the "left-behind branches" problem mentioned in the cover letter while avoiding the safety concerns raised about shared-branch checkouts.

Key improvements since v1 include: explicit Windows ReFS support, better documentation of reflink limitations (e.g., untracked files are copied), and a more robust explanation of how dirty worktrees are handled (via `update-index --refresh`). The series remains well-motivated by real-world scaling needs (e.g., CI agents) and includes measurable performance benefits, though the opt-in design may limit adoption until users explicitly enable it. The patches look technically sound, with thorough test coverage and attention to cross-platform details.
