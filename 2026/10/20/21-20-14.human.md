This is a substantive review comment on the first patch of Jason Newton’s two-patch v2 series that adds `--reflink` support to `git worktree add`. Brian m. Carlson flags a critical flaw in the Windows ReFS reflink implementation: Git LFS has an open, unresolved bug (issue #6312) where ReFS block cloning can corrupt files by silently dropping extents when the source file is modified during the clone. Because there is no fixed Windows version available, Brian argues the Windows reflink path should be disabled entirely until the underlying OS bug is resolved. He also questions whether the macOS CI probe will work as intended, since the macOS `cp` binary may not support `--reflink=always`, meaning the test would silently pass without actually exercising the APFS reflink code. The review is narrowly focused on correctness and test coverage, not on the broader design or the rest of the series.
