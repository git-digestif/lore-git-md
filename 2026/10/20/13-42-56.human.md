This is the core implementation patch (3/5) in Harald Nordgren’s v10 series introducing a "matching-inspired" fetch mode for shallow repositories. The patch enables `git fetch` to dynamically infer which branches to fetch when a remote is configured with `remote.<name>.refmap` but no `remote.<name>.fetch` refspec.

The key change is in `builtin/fetch.c`: when no explicit refspec is given and the remote has a refmap but no fetch refspec, the code now enumerates all local branches whose `@{upstream}` points to that remote, constructs a dynamic refspec from those branches, and fetches only them. This avoids the performance penalty of negotiating history for all remote branches in shallow repositories. The patch also updates the transport layer’s `ref_prefixes` to limit the refs requested from the remote, ensuring the optimization propagates through the entire fetch pipeline.

The implementation is clean: it reuses the existing `collect_upstream_from_remote` helper (refactored in Patch 2/5) and introduces a new `branches_tracking_remote` helper in `remote.c` to iterate over all local branches and collect their upstream refs. The control flow in `do_fetch` is reorganized to accommodate the new logic, and the documentation is updated to reflect the new behavior. The test coverage in the new `t/t5586-fetch-refmap.sh` script verifies edge cases like duplicate branch tracking, cross-remote tracking, and compatibility with `git remote show`.

This patch is technically solid and addresses all prior review feedback. The series as a whole is ready for merging to `next` pending any final maintainer feedback. If you work with shallow repositories, this is a meaningful quality-of-life improvement.
