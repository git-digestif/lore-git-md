This thread is a courtesy heads-up from Steven Rostedt, a Linux kernel developer, about a real-world dependency on Git's output formatting. He reports that `ktest.pl`—a testing tool in the Linux kernel—relies on parsing the output of `git bisect` to identify the first bad commit during automated bisection. A recent Git commit (0c0f93e7fa64, "bisect: print bisect terms in single quotes") changed the output format by adding quotes around bisect terms, breaking `ktest.pl`'s parsing logic. The issue is being fixed in the kernel tooling (with a patch already submitted), but Rostedt wanted to flag this to the Git project as an example of how Git's user-visible messages can become de facto stable interfaces for downstream tools, even when no formal stability guarantees exist.

The thread is purely informational—no action is requested from the Git side—but it serves as a concrete case study for future discussions about whether (or how) to version or stabilize certain Git messages. The commit in question was a minor UX improvement, but it had unintended consequences for a tool that depended on the exact string format. No controversy or debate has emerged yet; this is just a notification.
