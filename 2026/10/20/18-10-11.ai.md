This is a heads-up about a real-world dependency on Git's output formatting. Steven Rostedt (a Linux kernel developer) reports that `ktest.pl`—a testing tool in the Linux kernel tree—relies on parsing the output of `git bisect` to identify the first bad commit during automated bisection. A recent Git commit (0c0f93e7fa64, "bisect: print bisect terms in single quotes") altered the output format, breaking `ktest.pl`'s parsing logic. The breakage is being fixed in the kernel tooling (see the linked patch), but Rostedt wanted to flag this dependency to the Git project.

The email does not request any action from the Git side—it is purely informational. However, it highlights a risk: Git's user-visible messages are sometimes treated as stable interfaces by downstream tooling, even though they are not formally guaranteed to be stable. The commit in question was a minor UX improvement (adding quotes around bisect terms), but it had unintended consequences for a tool that depends on the exact string format.

Key details for follow-up discussion:
- The breaking commit: 0c0f93e7fa64 ("bisect: print bisect terms in single quotes").
- The affected tool: `ktest.pl` in the Linux kernel (`tools/testing/ktest/`).
- The symptom: failure to parse the "first bad commit" line from `git bisect`.
- The fix: a patch in the kernel tree (linked in the email) to update the regex used by `ktest.pl`.

This is a concrete example of how Git's output can become a de facto API, and it may come up in future discussions about whether (or how) to version or stabilize certain messages. No controversy or debate is present in this email—just a courtesy notice.
