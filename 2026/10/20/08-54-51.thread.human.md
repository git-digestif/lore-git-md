This thread is about a bugfix series that restores Git’s ability to dynamically reload alternate object databases when an object lookup fails. The regression was introduced in March 2026 during the ODB abstraction effort and has since been observed in production systems where the alternates file may be modified while Git is running. The series also fixes a related behavioral regression in `git receive-pack` when a temporary quarantine directory is used as the primary ODB.

Patrick Steinhardt authored the six-patch series, now at version 3, which Junio C Hamano has reviewed and declared ready for integration. Junio will merge the series to `next` after fixing a minor typo in one commit message locally, avoiding a full resend. The fix is narrowly scoped to the files-based ODB backend and does not attempt to handle recursive alternates, an edge case the commit messages acknowledge was never supported. Performance benchmarks show the final version nearly matches the pre-regression baseline, with lookup time for 20,000 missing objects improving from 310ms in the unoptimized fix to 199.5ms—just 14ms slower than the original 185.3ms.

Christian Couder contributed substantive feedback early in the thread, identifying the `receive-pack` regression and proposing the design change that became patch 2. Junio’s final review flagged a potential correctness issue with the `core.ignoreCase` deduplication mechanism in patch 4, but did not request changes, noting the series as “pretty much done.” All open questions—including the deduplication concern, the race condition in patch 6, and the suppression of error messages in patch 5—have been addressed in the final version. The series is now complete and awaiting integration.
