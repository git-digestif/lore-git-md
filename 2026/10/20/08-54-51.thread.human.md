This six-patch bugfix series from Patrick Steinhardt restores Git’s ability to dynamically reload alternate object databases when an object lookup fails—a behavior accidentally broken in March 2026 during the ODB abstraction effort. The regression, though rare, has been observed in production systems where the alternates file is modified while Git is running. The series also fixes a related behavioral regression in `git receive-pack` when a quarantine directory is used as the temporary primary ODB, ensuring objects moved to an alternate since the quarantine was created are still found.

All technical and editorial feedback has been addressed in the latest version (v3), including a design change proposed by Christian Couder to always reload the repository’s real alternates (resolving the `receive-pack` issue) and performance optimizations that nearly restore pre-regression lookup speeds. Junio Hamano has not yet reviewed the final version, but the series is now complete and ready for integration. The only remaining action is a trivial typo fix in patch 4’s commit message (`dir_paths_iscase` → `dir_paths_icase`), which Patrick has queued locally but won’t trigger a full resend for. The fix is narrowly scoped to the files-based ODB backend and doesn’t attempt to handle recursive alternates, an edge case the commit messages acknowledge was never supported.
