This thread is a bugfix series from Patrick Steinhardt to restore dynamic reloading of alternate object databases in Git’s files-based ODB backend, a feature accidentally broken during the ODB abstraction effort in March 2026. The regression is rare but has been observed in production, where the alternates file may be modified while Git is running. The series also fixes a behavioral regression in `git receive-pack` when a quarantine directory is used as the primary ODB, ensuring objects moved to an alternate since the quarantine was created can still be found.

The six-patch v2 series is under review, with all patches now submitted. The core fix (patch 3) and performance optimizations (patches 4–6) are largely settled, but a race condition in patch 6—identified by Christian Couder—remains unresolved. The race occurs if the alternates file is rewritten in-place while Git is reading it, potentially causing Git to miss new alternates indefinitely. Christian proposed a mechanical fix (reordering a `stat_validity_update()` call) that aligns with existing patterns in the codebase, but Patrick has not yet implemented it. The series touches `odb/source-files.c` and adds a test in `t/t1006-cat-file.sh`, with performance measurements showing the optimizations nearly restore pre-regression lookup times.

Christian’s latest review focuses on the fourth patch, which replaces a `hashmap` with a `strset` for tracking alternate directories. While the patch simplifies the code, Christian notes the commit message omits the removal of a `NEEDSWORK` comment about deduplication reliability (symlinks, mount points, and `core.ignoreCase`), which remains unaddressed. He also flags minor cosmetic issues: a lingering reference to “map” in a comment and a variable rename that could have been documented. These are surface-level critiques and do not affect the patch’s correctness or design. The series is otherwise ready for a follow-up to address the race condition in patch 6.
