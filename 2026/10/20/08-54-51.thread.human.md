This thread is a six-patch bugfix series by Patrick Steinhardt that restores dynamic reloading of alternate object databases in Git’s files-based ODB backend. The regression was accidentally introduced in March 2026 during the ODB abstraction effort, breaking a rare but production-observed scenario where the alternates file is modified while Git is running. The series also fixes a behavioral regression in `git receive-pack` when a quarantine directory is used as the primary ODB, ensuring objects moved to an alternate since the quarantine was created are still found.

The series is now complete with the sixth patch, which adds a `stat_validity` field to track the alternates file’s mtime and inode, avoiding unnecessary re-reads when the file hasn’t changed. This optimization nearly restores pre-regression performance, reducing lookup time for 20k missing objects from 262.7ms to 199.5ms (just 7.7% above the original 185.3ms baseline). Earlier patches refactored internal functions, introduced a `tail` pointer to track newly added directories, replaced a `hashmap` with a `strset` for deduplication (improving lookup overhead by 7.8%), and avoided redundant `stat()` calls for known alternates. The design change in patch 2—always reloading alternates from the repository’s real object directory—resolved the `receive-pack` regression and was agreed upon after Christian Couder’s review.

The series is uncontroversial and ready for merging. Junio Hamano provided a minor review comment on an earlier patch, which Patrick addressed, and no further objections or edge cases have been raised. The fix is narrowly scoped to the files-based ODB backend and includes a new test in `t/t1006-cat-file.sh` to verify the dynamic reload behavior. Memory usage increases slightly (4.3% over the broken state) but remains acceptable. The regression was introduced during Patrick’s ongoing ODB abstraction effort, and this series is based on his earlier ODB cleanup branch.
