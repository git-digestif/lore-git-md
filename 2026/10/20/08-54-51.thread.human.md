This thread is a six-patch bugfix series (v3) by Patrick Steinhardt that restores Git’s ability to dynamically reload alternate object databases when an object lookup fails—a behavior accidentally broken in March 2026 during the ODB abstraction effort. The regression, though rare, has been observed in production systems where the alternates file is modified while Git is running. The series also fixes a related behavioral regression in `git receive-pack` when a quarantine directory is used: objects that moved to an alternate after the quarantine was created were not found, even if the alternates file was updated.

All technical and editorial feedback has been addressed in this latest version. Key changes include resolving a race condition in the final patch, restoring a previously undocumented `NEEDSWORK` comment, and explicitly documenting the suppression of a user-facing error message in the commit message for patch 5. The series is now complete and under final review. Junio Hamano and Christian Couder have reviewed the patches, with Christian identifying both the `receive-pack` regression and a race condition in the stat-tracking logic. Performance has been carefully optimized: the final version nearly matches the pre-regression baseline, with lookup times for missing objects reduced from 310ms (unoptimized) to 199.5ms (a 35% improvement).

The fix is narrowly scoped to the files-based ODB backend and does not attempt to handle recursive alternates, an edge case the commit message acknowledges was never supported. New tests in `t/t1006-cat-file.sh` verify the fix by simulating concurrent alternates updates and the quarantine scenario. The series is ready for integration and is based on Patrick’s earlier ODB cleanup branch, part of the ongoing ODB abstraction effort.
