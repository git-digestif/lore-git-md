This thread is a bugfix series from Patrick Steinhardt to restore dynamic reloading of alternate object databases in Git’s files-based ODB backend, a feature accidentally broken during the ODB abstraction effort in March 2026. The regression is rare but has been observed in production, where the alternates file may be modified while Git is running. The series is now at v2 with six patches, addressing both the core regression and a behavioral issue in `git receive-pack` when a quarantine directory is used as the primary ODB.

The key technical challenge was balancing correctness with performance. The unoptimized fix initially slowed lookups for missing objects, but later patches (4–6) restored near-baseline performance by using a `strset` for deduplication, reordering checks to avoid redundant syscalls, and tracking the alternates file’s mtime/inode to skip unnecessary re-reads. The only remaining technical issue is a race condition in patch 6, where rewriting the alternates file in-place during a read could cause Git to miss updates indefinitely. Christian Couder proposed a fix (reordering `stat_validity_update()`), which Patrick accepted in principle and will adapt for the next revision.

Most feedback has been resolved, but a few loose ends remain. Christian flagged that patch 5 suppresses a user-facing error message for disappearing alternates—a trade-off Patrick considers acceptable but which Christian suggests should be documented in the commit message. Other minor issues include outdated references in the cover letter and an undocumented removal of a `NEEDSWORK` comment in patch 4, both of which Patrick plans to address. Junio Hamano’s earlier review focused on a correctness edge case in patch 4, which was fixed in v2. The series is under active review, with the race condition and documentation tweaks as the final hurdles before it can be queued.
