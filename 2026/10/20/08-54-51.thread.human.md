This thread is a bugfix series from Patrick Steinhardt aimed at restoring dynamic reloading of alternate object databases in Git’s files-based ODB backend. The regression, introduced during the ODB abstraction effort in March 2026, broke the ability to reload alternates when an object lookup fails, a rare but observed issue in production systems where the alternates file may be modified while Git is running. The series initially proposed a four-patch fix, but Christian Couder’s review identified a critical behavioral regression in `git receive-pack` when a temporary primary ODB (like the quarantine directory) is in use: objects moved to an alternate since the quarantine was created are not found, even if the alternates file is updated.

Patrick has now agreed with Christian’s proposed design change—to always reload the repository’s real alternates rather than the current primary ODB’s alternates—which resolves the `receive-pack` issue and restores pre-regression behavior. The fix is minimal (a one-line adjustment in `odb/source-files.c`) and aligns with the series’ goal without impacting performance. The thread is now likely headed for a v2 of the series, with the remaining patches (performance optimizations) possibly needing reordering or minor adjustments. The discussion remains narrowly focused on the files-based ODB backend and does not revisit broader ODB abstraction design questions. Key participants include Patrick (author), Junio (maintainer, who provided minor feedback on an edge case), and Christian (who identified the correctness gap and proposed the solution).
