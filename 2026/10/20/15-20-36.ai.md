This is the first patch in Phillip Wood’s seven-part refactoring series (`pw/stash-optimize-check_changes-calls/v3`) targeting redundant index operations in `git stash push` and `git stash create`. It introduces an `enum create_result` to replace the integer return type of `do_create_stash()`, distinguishing between success (`CREATE_SUCCESS`), errors (`CREATE_ERROR`), and cases where no changes were stashed (`CREATE_EMPTY`). The patch also fixes a long-standing behavioral anomaly: `create_stash()` previously exited with status 1 when `do_create_stash()` returned 1 (indicating no changes), even though `create_stash()` had already determined no changes existed via `check_changes()`. With this patch, `create_stash()` now exits 0 when there are no changes to stash, aligning with its documented behavior.

The changes are confined to `builtin/stash.c` and modify `do_create_stash()`, `stash_staged()`, `stash_patch()`, and `create_stash()`. The new enum (`CREATE_NO_CHANGES` is not yet used; it will be introduced in a later patch) improves code clarity and prepares the ground for eliminating redundant `check_changes()` calls in subsequent patches. The patch is uncontroversial and well-motivated, with no user-visible behavior changes beyond the exit-status correction. Phillip Wood, an established contributor with deep expertise in the stash subsystem, authored the patch, and Junio C Hamano’s feedback from earlier iterations has been fully incorporated. The series is part of an ongoing effort to reduce `lstat()` overhead and improve code hygiene in the stash machinery.
