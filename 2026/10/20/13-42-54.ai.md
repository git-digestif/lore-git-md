This is the first patch in the v10 series introducing a "matching-inspired" fetch mode for shallow repositories. It adds the `remote.<name>.refmap` configuration variable, which provides a default value for the `--refmap` option in `git fetch`, mirroring how `remote.<name>.fetch` provides default refspecs.

The patch implements the core configuration plumbing: it extends the `struct remote` to include a `refmap` field, updates the remote configuration parser to recognize `remote.<name>.refmap`, and modifies `builtin/fetch.c` to use the remote’s refmap as the default when no explicit `--refmap` is given on the command line. The precedence rule is clear: an explicit `--refmap` on the command line overrides the remote’s refmap, and `remote.<name>.fetch` (if configured) overrides both. When neither is present, the refmap acts as a namespace mapping for refs that are explicitly fetched (via command-line refspecs or `remote.<name>.fetch`).

The implementation is minimal and focused. It reuses the existing refspec machinery, so there is no new technical debt. The patch includes documentation updates for `remote.adoc` and `fetch-options.adoc`, and adds three new tests in `t/t5510-fetch.sh` to verify that the refmap behaves like `--refmap` on the command line, does nothing when nothing is being fetched, and correctly yields to `remote.<name>.fetch` when both are configured.

This patch is uncontroversial and ready for review. It lays the groundwork for the dynamic branch enumeration logic in Patch 3/5 by providing the configuration knob that enables the new fetch mode. The only behavior change is the introduction of the `remote.<name>.refmap` configuration, which has no effect unless explicitly set. The patch is a clean, mechanical addition that integrates smoothly with the existing codebase.
