This is the fifth patch in Phillip Wood’s seven-part refactoring series (`pw/stash-optimize-check_changes-calls/v3`), which targets redundant index operations in `git stash push` and `git stash create`. This patch reworks how the temporary index file is created when stashing uncommitted working tree changes, replacing `reset_tree()` with `create_index_from_tree()`.

The key improvement here is eliminating reliance on `set_alternate_index_output()`, a global-variable-dependent helper that overwrites the in-memory index and updates its timestamp unnecessarily. By switching to `create_index_from_tree()`, the patch avoids modifying the in-memory index entirely, making the code easier to reason about and removing a redundant `repo_read_index_preload()` call. This saves one `lstat()` per changed path and aligns the implementation with the approach already used for `git stash push -p`. The patch also adds a `reset` boolean parameter to `create_index_from_tree()` to preserve intent-to-add entries, which would otherwise be lost if the index were reset.

The change is confined to `builtin/stash.c` and introduces no user-visible behavior changes. The diff is clean and focused, removing 11 lines while adding just 4. This is a well-motivated refactoring that improves code hygiene and performance, and it fits neatly into the series’ broader goal of reducing redundant index operations.
