This thread is about a long-standing edge case in `git switch` and `git checkout` where creating a new branch fails midway—after updating the worktree and index but before moving HEAD—leaving the repository in a confusing state. The issue was reported by 井上司 (Tsukasa Inoue), who also proposed an incremental fix: making `setup_tracking()` return an error instead of calling `exit(1)`, which would prevent the halfway state but not achieve full atomicity. Junio C Hamano has argued for a more complete solution that ensures all-or-none behavior, but the discussion is now focused on whether the incremental approach is an acceptable compromise.

D. Ben Knoble’s recent review adds a new layer to the discussion by questioning the current control flow. He points out that worktree and index updates happen *before* both branch creation and HEAD movement, which he finds counterintuitive. His observation suggests that the problem may be deeper than just `setup_tracking()`—the entire sequence of updates (worktree, index, HEAD) might need reordering or refactoring to ensure consistency. This raises the stakes for the eventual fix, as a full solution could require more extensive changes than initially proposed.

The thread remains in the design phase, with no patches yet. The key open question is whether to accept the incremental fix now or hold out for a more robust refactoring.
