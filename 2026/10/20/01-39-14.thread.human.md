This thread is about a long-standing edge case in `git switch` and `git checkout` where the commands leave the repository in an inconsistent state if they fail to set up tracking configuration after updating the worktree and index but before moving HEAD. The issue affects branch-creation variants like `git switch -c` and `git checkout -b`, and was introduced in 2016 by a commit that made `setup_tracking()` call `exit(1)` on failure.

井上司 (Tsukasa Inoue) reported the bug and proposed an incremental fix: making `setup_tracking()` return an error instead of exiting, which would prevent the halfway state. Junio C Hamano initially preferred a fully atomic solution but has now endorsed the incremental approach, removing the main obstacle to a near-term fix. The broader control flow issues—such as worktree and index updates occurring before HEAD movement—remain unaddressed, but the discussion has clarified that reordering steps would not achieve true atomicity and could introduce new edge cases.

The thread is now focused on implementing the incremental fix, with no patch posted yet. Open questions include how to structure the error return and whether the change might break existing scripts. D. Ben Knoble has contributed technical analysis, confirming the root cause and raising concerns about the current control flow sequence. The fix will touch `branch.c` and `checkout.c`, but no on-disk format changes are involved.
