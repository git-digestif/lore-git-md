This is a bugfix patch targeting the hook subsystem, part of Adrian Ratiu’s ongoing effort to make hooks configurable via Git configuration rather than fixed filesystem paths.

The patch fixes an inconsistency in how `hook.<event>.enabled=false` is handled. Currently, this setting only disables hooks defined in Git configuration (`hook.<name>.command`), but not traditional hooks in `.git/hooks/`. The documentation claims that "no hooks fire for that event" when the setting is false, but in reality, traditional hooks still run. This patch moves the `event_disabled` flag out of the `u.configured` union and applies it to all hook types, ensuring that both configured and traditional hooks respect the setting.

The change touches `builtin/hook.c`, `hook.c`, and `hook.h`, and adds test coverage in `t/t1800-hook.sh` to verify that disabled hooks are not executed and are correctly marked as "event-disabled" in `git hook list`. The test also fixes a latent issue where the existing test for `hook.<event>.enabled=false` only checked standard output, not standard error, so it passed even when disabled hooks ran.

The patch is well-motivated, with a clear problem statement and a mechanical fix that aligns behavior with documentation. The test additions are thorough and cover both the execution and listing paths. This looks like a straightforward correctness fix that should be uncontroversial.
