This is the third patch in Justin Tobler’s four-patch bugfix series that fixes a race condition in Git’s object database (ODB) transaction machinery. The series is part of the ongoing ODB abstraction effort led by Patrick Steinhardt.

This patch prepares for the core fix (in patch 4) by refactoring how `.keep` lockfiles are created. Currently, `git-index-pack` writes the lockfile during the quarantine phase, which can lead to race conditions if the transaction fails or is interrupted. This patch updates `odb_transaction_files_write_pack()` to explicitly generate the `.keep` lockfile itself, rather than relying on `git-index-pack`. The lockfile is still written during quarantine for now, but the logic is restructured to pave the way for deferring lockfile creation to the transaction commit phase in the next patch.

The patch introduces a new helper function, `write_pack_lockfile()`, which constructs the lockfile path, writes the keep message (e.g., `"receive-pack <pid> on <hostname>"`), and registers it as a tempfile. The function includes robust error handling, with `errno` context and lockfile paths included in error messages. The patch also replaces the internal `index_pack_lockfile()` logic with a call to the newly exposed `read_index_pack_report()` helper (introduced in patch 2) to parse the packfile name from `git-index-pack`’s output.

The refactoring is clean and well-motivated, with clear test coverage in the series’ final patch. All feedback from Patrick Steinhardt has been addressed, and the patch is explicitly approved by him. The only minor concern—whether leading directories for lockfiles are guaranteed to exist during quarantine—was flagged by Patrick but not addressed in this patch, as the author argues the assumption is safe. This is unlikely to block integration, as the series is otherwise considered complete and technically sound.
