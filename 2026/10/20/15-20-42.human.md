This is the final patch in Phillip Wood’s seven-part refactoring series (`pw/stash-optimize-check_changes-calls/v3`) that targets redundant index operations in `git stash`. The series as a whole is a well-motivated cleanup that reduces `lstat()` calls and eliminates duplicate work in `git stash push` and `git stash create` without changing user-visible behavior.

This specific patch simplifies the `reset_tree()` helper in `builtin/stash.c` by removing two unused boolean parameters (`update` and `reset`). The function is now a focused utility that merges a tree into the index without touching the worktree or resetting the index state. The only caller, `do_apply_stash()`, never wanted these features, so the change is purely mechanical and improves code clarity. The diff is small (8 lines changed) and uncontroversial; Junio’s earlier review of the series called similar redundancies “embarrassingly stupid,” signaling strong support for this kind of cleanup.

The patch is part of a larger effort that has already addressed redundant `check_changes()` calls, duplicate index loads, and unnecessary refreshes. Earlier patches in the series introduced an `enum create_result` to clarify return values and fixed a minor exit-status anomaly in `create_stash()`. This final patch tidies up the last loose end, leaving `reset_tree()` with a single responsibility. The series is now complete, with all feedback from Junio incorporated, and looks ready to proceed to `next`.
