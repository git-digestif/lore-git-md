This is a **feature patch** revisiting the default behavior of `git status` in triangular workflows. The author, Harald Nordgren, responds to Junio C Hamano’s **substantive review** of the initial submission, which proposed defaulting `status.compareBranches` to `@{upstream},@{push}` so that `git status` shows divergence from both the upstream and push destinations.

Harald accepts Junio’s feedback on the commit message, agreeing to first establish the historical context (when `status.compareBranches` was introduced) before explaining the default change. On test coverage, he acknowledges that the initial patch mechanically updated existing tests rather than adding explicit coverage for both triangular and common-case scenarios. He now plans to restore some of the deleted test cases and add new ones to demonstrate the new default’s behavior when `@{upstream}` and `@{push}` resolve to the same branch, as well as when they differ. The discussion remains focused on justification and thoroughness; no technical objections to the code itself have been raised.

The patch touches `remote.c` (appending `@{push}` to the default comparison list), updates `Documentation/config/status.adoc`, and will revise tests in `t/t6040-tracking-info.sh` and `t/t5505-remote.sh`. There are no on-disk format changes, new CLI options, or new symbols introduced.
