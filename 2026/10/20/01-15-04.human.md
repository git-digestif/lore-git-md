This is a bugfix patch that corrects a misleading error hint in `git branch --set-upstream-to`.

When Git fails to write the upstream tracking configuration (for example, because `.git/config.lock` exists), it prints a recovery hint that includes the full ref name (e.g., `origin/refs/heads/feat`). However, the correct command should use the short branch name (`origin/feat`). Running the hinted command as printed fails because Git rejects the full ref name as invalid for this purpose. The patch strips the `refs/heads/` prefix from the hint, matching the behavior already used in the success message for the same operation.

The issue has been present since commit a3f40ec4b0 (2021-12-20), which introduced support for multiple upstream branches. The fix is minimal: it modifies only the hint text, leaving the actual configuration logic unchanged. The patch includes a new test in `t/t3200-branch.sh` that verifies the hint now uses the short branch name and excludes the `refs/heads/` prefix.

This is a clear, well-motivated fix for a user-facing annoyance. The commit message explains the problem, the regression origin, and the solution concisely. The test coverage is appropriate. No controversy is expected.
