This is a bugfix for the files ref backend, part of the ongoing discussion around how root refs (like `HEAD` or `ORIG_HEAD`) are handled in the loose ref cache. The patch itself—now in its third iteration (v3)—is ready for integration, with Patrick Steinhardt giving it a clear "looks good to me" after earlier substantive feedback was addressed.

The core issue is an inconsistency in the loose ref cache: root refs are included only if the `REFS_FOR_EACH_INCLUDE_ROOT_REFS` flag is passed during the *first* iteration that creates the cache, but subsequent iterations include them regardless of the flag, while earlier ones omit them even if the flag is set. The v3 patch resolves this by excluding root refs from the shared loose ref cache entirely and instead creating a temporary ref cache when the flag is passed, overlaying its iterator on the loose ref iterator. This approach is simple, performant (since the flag is used in only two places and invoked just once per command), and avoids the inconsistency without introducing significant overhead.

The patch touches `files-backend.c` and adds a test in `t/t6302-for-each-ref-filter.sh` to verify that `--include-root-refs` works correctly with `--merged`. The implementation is unchanged from v2, but the commit message has been expanded to discuss alternatives (such as always including root refs in the cache or using persistent dual caches) and justify the chosen design. Documentation corrections—such as fixing mislabeling of root refs as pseudorefs—have been deferred to a separate patch, as requested by Patrick.

The only remaining open question is architectural: whether to adopt Andy Koppe’s temporary cache approach (implemented here) or Junio C Hamano’s proposed persistent dual-cache design (not yet implemented). Patrick’s approval suggests the temporary cache approach is acceptable, but Junio’s alternative could still shift the direction. For now, the patch is technically unblocked and looks like a clean, well-motivated fix for a real bug. If the current approach is merged, the deferred documentation patch will likely follow soon after.
