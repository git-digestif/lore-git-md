This thread is about adding test coverage for `git mktree --batch`, a mode that previously had only one test (focusing on repack resilience) and allowed a memory leak to go unnoticed. Roger Koranteng sent a v2 patch that adds seven new tests to `t/t1010-mktree.sh`, covering basic functionality, edge cases, and error conditions for `--batch` and its `-z` (NUL-terminated) input mode. The tests verify multiple trees in a single batch, handling of trailing blank lines, NUL-terminated input, graceful failure on missing objects (with `stderr` verification), and rejection of blank lines without `--batch`. One test documents an ambiguous behavior—consecutive blank lines producing an empty tree—which remains noted as potentially unintentional but unchanged.

Laveesh Bansal provided a thorough review of v1, confirming the tests pass under `SANITIZE=leak` and catch the memory leak fixed in commit 6272f3bd17 when reverted. He also suggested improvements to `stderr` verification and the commit message, both of which were addressed in v2. Jeff King initially suggested the tests but hasn’t explicitly reviewed this version. Junio C Hamano has now queued the patch, indicating it’s in the integration pipeline and likely headed for `next` before graduating to `master`. The patch is purely additive to the test suite, with no new symbols or behavior changes. The only loose end is the ambiguous consecutive blank lines behavior, which remains unresolved.
