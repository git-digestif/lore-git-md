This is a bugfix series targeting the object database (ODB) subsystem, specifically the files-based backend. The series restores a previously working behavior: reloading the list of alternate object databases when an object lookup fails, which can happen if the alternates file is modified while Git is running. The regression was introduced in commit 5946a564cd (March 2026) during the ODB abstraction effort.

The cover letter explains that the regression is rare but has been observed in production systems. The fix itself is contained in the second patch, while the remaining two patches optimize performance to mitigate the overhead of reloading alternates. The series touches `odb/source-files.c`, adds a small helper in `odb/source-files.h`, and extends the test suite with a new scenario in `t/t1006-cat-file.sh`.

Performance is a key concern here: the unoptimized fix regressed lookup time for 20k missing objects from 180ms to 309ms, but the optimizations in patches 3 and 4 bring it down to 197ms. The series is based on the current `master` (as of 2026-10-19) with Patrick’s earlier ODB cleanup branch merged in.

The commit messages and cover letter are clear and well-motivated, and the test coverage is a strong positive signal. The regression is real, the fix is targeted, and the performance work is justified. This looks like a solid, uncontroversial bugfix that should be straightforward to review and merge.
