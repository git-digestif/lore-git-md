This is a build system patch addressing Rust integration in Git. Andy Koppe replies to Junio C Hamano in the ongoing discussion about how to fix a Makefile bug that causes the Git build to fail when users have a custom Cargo target directory (set via `~/.cargo/config.toml` or `CARGO_TARGET_DIR`). The patch itself is minimal—just two lines in the Makefile—but the debate centers on the best way to implement the fix.

Andy reiterates his concern that `CARGO_ARGS` appears designed for user-configurable build preferences (like `CFLAGS` or `LDFLAGS`), and modifying it to hardcode `--target-dir target` could interfere with legitimate overrides. He contrasts this with the existing `+=` modifications (e.g., `--quiet` and `--release`), which are optional and harmless to override. The `--target-dir`, however, is a hard requirement for the subsequent link step, and silently ignoring a user’s override could break the build in subtle ways. His argument hinges on maintainability and avoiding a "trap" where future modifications to `CARGO_ARGS` without `override` would be ignored.

The patch remains uncontroversial in terms of correctness—Patrick Steinhardt’s earlier review confirmed the issue and the fix—but the discussion is now focused on implementation trade-offs. Junio’s suggestion (adding `--target-dir target` to `CARGO_ARGS` once) is simpler but risks conflicting with user expectations, while Andy’s approach (modifying the two `cargo build` recipes individually) is more explicit but slightly more verbose. No consensus has been reached, and the thread may continue if others weigh in on the balance between maintainability and user flexibility. The fix aligns with Meson’s existing behavior and has no impact on user-facing functionality or on-disk formats.
