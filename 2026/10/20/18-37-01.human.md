This is a brief follow-up in the thread about downstream tooling relying on Git's output formatting. Junio C Hamano responds to Steven Rostedt's heads-up about `ktest.pl` breaking due to a recent change in `git bisect` output. Junio suggests an alternative approach: rather than parsing the human-readable output of `git bisect`, the script could inspect the `bisect/bad` ref directly using `git show bisect/bad`. This would avoid dependency on the exact formatting of `git bisect`'s messages, which are not guaranteed to be stable.

The suggestion is practical and aligns with Git's design philosophy—plumbing commands (like `git show`) are intended to be machine-readable and stable, while porcelain commands (like `git bisect`) are meant for human interaction and may change for UX improvements. Junio does not criticize the kernel tooling or the original Git commit; he simply offers a more robust way to achieve the same goal. This reply may prompt further discussion about best practices for tooling that integrates with Git, but it does not request any changes to Git itself. The thread remains low-stakes but serves as a useful reference for future conversations about output stability.
