This is a revised bugfix patch targeting the `upload-pack` subsystem, addressing a severe performance regression in shallow fetches over protocol v2. The patch is now in its second version, incorporating feedback from Junio C Hamano to correct a protocol-layer API misuse while preserving the intended performance optimization.

The core issue remains: fetching from a shallow repository with a long history (e.g., 900k commits) can take minutes over protocol v2 due to redundant history traversal, whereas protocol v0 handles this efficiently by directly advertising shallow grafts. Harald Nordgren’s solution aligns v2 behavior with v0 when no specific depth is requested, avoiding the expensive traversal. The v2 update fixes a critical flaw in the initial implementation—misuse of `packet_write_fmt`—by switching to the `packet_writer` API to ensure sideband multiplexing works correctly. A new test case verifies this fix by cloning from a shallow repository with `uploadpack.allowSidebandAll` enabled.

The patch touches three files: `shallow.c` (adjusting depth comparison logic to handle infinite depth), `upload-pack.c` (replacing the `deepen` call with a direct graft advertisement via `for_each_commit_graft`), and `t/t5537-fetch-shallow.sh` (adding the sideband-all test). The changes are minimal but address both the performance regression and the protocol correctness issue. The commit message now explicitly notes the v2 changes, including the API correction and test addition.

This version appears to resolve the technical concerns raised in review while maintaining the original goal. The failing test case from Junio’s feedback is now included, serving as a regression guard. No substantive objections remain, and the patch is likely ready for further review or integration once the API usage is confirmed correct.
