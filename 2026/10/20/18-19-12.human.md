This is a bugfix patch for the hook subsystem, part of a two-patch series. It addresses an inconsistency in how Git handles the `hook.<event>.enabled` configuration: the setting was documented to disable *all* hooks for the event, but in practice it only disabled hooks defined in Git configuration, not traditional hooks in `.git/hooks/`.

The patch moves the `event_disabled` flag out of the `u.configured` union in the `struct hook` so it applies to both configured and traditional hooks. It also fixes a test that was silently passing because it only checked standard output, not standard error where hook output actually appears. The updated test now verifies that disabled hooks truly don’t run.

The change is small but important for users who rely on `hook.<event>.enabled` to disable hooks globally. The commit message is clear and the code changes are straightforward, touching only the hook internals (`hook.c`, `hook.h`) and the `git hook` builtin. The test coverage is expanded to catch the previously missed case. This looks like a well-motivated fix that aligns behavior with documentation.
