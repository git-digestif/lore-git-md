This is the first patch in Patrick Steinhardt’s four-patch bugfix series that restores dynamic reloading of alternate object databases in the files-based ODB backend. It is a pure refactoring: the commit renames two internal functions (`odb_prepare_alternates` → `prepare_alternates` and `odb_add_alternate_recursively` → `add_alternate_recursively`) to drop the now-misleading `odb_` prefix. The functions were originally part of the object database layer but have since moved into the files-specific backend (`odb/source-files.c`), so the old prefix no longer reflects their location. The patch touches only `odb/source-files.c` and makes no behavioral changes. It is a preparatory step for the actual fix in patch 2, setting up clearer naming for the reload logic that follows.
