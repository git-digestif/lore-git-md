This is the first patch in Phillip Wood’s seven-part refactoring series (`pw/stash-optimize-check_changes-calls/v3`) targeting redundant index operations in `git stash push` and `git stash create`. The patch introduces an `enum create_result` to replace the integer return type of `do_create_stash()`, distinguishing between success (`CREATE_SUCCESS`), errors (`CREATE_ERROR`), and cases where there are no changes to stash (`CREATE_EMPTY`). This is a preparatory step for later patches that will use the enum to avoid redundant `check_changes()` calls and index refreshes.

The patch also fixes a minor behavioral anomaly: `create_stash()` previously exited with status 1 when `do_create_stash()` returned 1 (indicating no changes), even though `create_stash()` had already determined there were no changes via its own `check_changes()` call. With the enum, `create_stash()` now exits 0 when there are no changes to stash, aligning with its documented behavior. The change is confined to `builtin/stash.c` and introduces no new user-visible behavior beyond the exit-status correction.
