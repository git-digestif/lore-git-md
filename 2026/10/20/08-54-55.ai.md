This is the fourth and final patch in Patrick Steinhardt’s four-patch bugfix series restoring dynamic reload of alternate object databases in the files-based ODB backend. The patch addresses the performance regression introduced by the core fix (patch 2) by avoiding unnecessary re-reads of the alternates file when it hasn’t changed.

The optimization uses `struct stat_validity` to track the mtime and inode of the alternates file, allowing the code to short-circuit the read-and-parse step if the file is unchanged. Benchmark results show this reduces lookup time for 20k missing objects from 257ms (unoptimized fix) to 197ms, nearly matching the pre-regression baseline of 180ms. The patch touches only `odb/source-files.c` and `odb/source-files.h`, adding the `stat_validity` field to the `odb_source_files` struct and updating the `read_alternates()` helper to conditionally skip parsing.

The change is narrowly scoped, well-explained, and backed by concrete performance data. It completes the series’ goal of restoring the lost functionality without sacrificing performance, making the fix production-ready. No open questions or loose ends remain; this patch is a straightforward optimization that should be uncontroversial. The series as a whole now looks like a clean, well-motivated bugfix with strong test coverage and performance awareness.
