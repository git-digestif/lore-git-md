Subject: [PATCH v3] environment: move `pack.packsizelimit` into `repo_config_values`

Thread type: refactoring patch (part of the global-state-removal effort)

Core problem or goal
Migrate the `pack.packsizelimit` configuration value from a standalone global variable (`pack_size_limit_cfg`) into the repository-scoped `repo_config_values` struct. The v3 series retains the preparatory patch that uses `memset()` in `repo_config_values_init()` to reduce boilerplate and standardize initialization. This is a pure refactoring with no behavioral change, intended to reduce global state and improve Git’s modularity as a library component.

Current status
Under review; blocked by Junio’s `jc/freeze-repo-config-values` topic in `seen`, which prohibits adding new members to `struct repo_config_values` until it can operate on repositories other than `the_repository`. The preparatory `memset` cleanup (patch 1/2) remains viable and could proceed independently. The core refactoring (patch 2/2) must be reworked to avoid violating the freeze. No merge status reported for either patch.
