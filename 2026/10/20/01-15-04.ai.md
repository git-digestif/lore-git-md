This is a bugfix patch targeting the branch subsystem. It corrects a misleading hint message that appears when `git switch` or `git branch --set-upstream-to` fails to write tracking configuration due to a locked config file. Currently, the hint includes the full ref name (e.g., `origin/refs/heads/feat`), which is invalid as a remote-tracking branch name; the patch strips the `refs/heads/` prefix to match the short name users actually need (e.g., `origin/feat`).

The issue has been present since commit a3f40ec4b0 (2021-12-20), which introduced support for multiple upstream branches. The fix is minimal: it modifies the hint-printing logic in `branch.c` to call `skip_prefix()` on the remote branch name, aligning it with the success message behavior in the same function. The patch also adds a new test in `t/t3200-branch.sh` to verify the hint now omits the `refs/heads/` prefix.

The change is narrowly scoped to the hint text and does not affect the underlying config-writing logic or the handling of multiple upstreams (which still requires full ref names). The commit message clearly explains the problem, the regression origin, and the rationale for the fix. The test coverage is thorough, using `test_grep` to confirm both the presence of the correct short name and the absence of the unwanted prefix.

This looks like a well-crafted, low-risk fix for a real usability papercut. The patch is self-contained, touches only one file outside the test suite, and includes a regression test. It should be uncontroversial and ready for review.
