This thread is about a small but urgent bugfix to restore the pre-2.56 behavior of `git init`, which used to print the absolute path of the initialized repository (e.g., `/home/user/repo/.git`) instead of the relative `.git/` path. The regression was introduced in the current development cycle and risks shipping in the upcoming Git 2.56 release unless fixed.

The author, Matt Hunter, identified the issue and proposed a minimal patch that restores the absolute path output. After two rounds of review, all substantive feedback has been addressed. Patrick Steinhardt, the primary reviewer, initially suggested minor test improvements, which Matt incorporated in a refined test assertion that checks the full output message for the default case. Harald Nordgren and Junio C Hamano also chimed in, with Junio noting the practical utility of the absolute path in command transcripts.

The patch is now complete and uncontroversial. Matt is expected to post a final version (v3) with the polished test, after which Junio can merge it before the 2.56 release. The fix touches `builtin/init-db.c` and adds a regression test in `t/t0001-init.sh`, ensuring the absolute path appears in the output without changing any on-disk formats. No open questions remain.
