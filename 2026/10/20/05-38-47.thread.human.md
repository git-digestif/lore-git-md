This thread is about a small but urgent fix to restore the absolute path output in the "Initialized empty Git repository" message after a regression introduced in the current development cycle (Git 2.56). The patch, authored by Matt Hunter, reverts the unintended behavior change from commit 20e38cba3926, which caused `git init` to print a relative `.git/` path instead of the full path (e.g., `/home/user/repo/.git`).

The fix itself is uncontroversial and narrowly scoped, touching only `builtin/init-db.c`. Patrick Steinhardt reviewed it favorably, calling the changes "obviously good" and agreeing the regression should be addressed before the upcoming release. Matt has agreed to post a v2 incorporating minor feedback: dropping a redundant sentence in the commit message and changing a variable type from `int` to `size_t`. The urgency is now clearer, as the regression was confirmed to have been introduced in the current cycle, not a prior release.

The only open question is whether to add a regression test. Patrick and Matt are ambivalent, leaning toward omitting it unless further feedback suggests otherwise. Harald Nordgren chimed in to advocate for a test, arguing it would have prevented the regression and would guard against future ones, but the comment was brief and didn’t engage with the trade-offs Patrick mentioned (e.g., the effort of testing a specific user-facing output). No other objections or concerns have been raised, and the patch is likely to be merged once the v2 is posted.
