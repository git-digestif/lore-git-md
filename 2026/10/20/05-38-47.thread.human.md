This thread is about a small but user-visible regression in `git init`: since a recent refactoring, the command no longer prints the absolute path of the new repository (e.g., `/home/user/repo/.git`) but instead shows the relative `.git/` path. Matt Hunter posted a minimal patch to restore the old behavior, which Patrick Steinhardt reviewed favorably, calling it "obviously good" and agreeing the change was unintentional. The fix is urgent because the regression was introduced in the current development cycle (Git 2.56) and would otherwise ship in the upcoming release.

The patch itself is uncontroversial and nearly ready—Matt has agreed to two minor tweaks suggested by Patrick (dropping a redundant commit message sentence and changing a variable type for correctness). The only remaining discussion is whether to add a regression test. Patrick has pushed back gently, arguing that while the output change is noticeable, it isn’t *incorrect* in a functional sense, making a dedicated test less compelling. Harald Nordgren had previously advocated for a test on principle, but Patrick’s latest reply reframes the debate: this is about preserving a specific user-facing detail, not preventing a bug. No objections to merging remain, and the patch is expected to land soon unless further feedback emerges.
