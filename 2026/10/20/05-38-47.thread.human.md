This thread is about a small but user-visible regression in `git init` that was introduced in commit 20e38cba3926. Before that change, running `git init` or `git init --reinit` would print the absolute path of the new repository (e.g., `/home/user/project/.git`); afterward, it printed only the relative path (`.git/`). Matt Hunter’s patch restores the old behavior by ensuring the output message uses the repository’s full git directory path instead of a local variable that holds owned memory.

The fix itself is straightforward—just a few lines in `builtin/init-db.c`—and doesn’t touch any core logic, only the output formatting. The commit message makes it clear this was an unintended side effect of the earlier refactoring, and the patch is narrowly scoped to address just that. There’s no indication yet of review feedback or objections, so this looks like a uncontroversial bugfix that should land once it’s been looked at by a few more eyes.
