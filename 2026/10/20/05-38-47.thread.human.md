This thread is about a small but urgent fix to restore the absolute-path output in `git init`'s "Initialized empty Git repository" message, which was unintentionally changed to a relative path in the current development cycle (Git 2.56). The regression was introduced by commit 20e38cba3926 during a refactoring of `init_db()`, and the fix is time-sensitive to avoid shipping the behavior change in the upcoming release.

Matt Hunter posted the patch, which modifies `builtin/init-db.c` to print the absolute path (e.g., `/home/user/repo/.git`) instead of `.git/`. After review feedback from Patrick Steinhardt—who called the changes "obviously good"—and a broader discussion about the practical utility of absolute paths (noted by Junio C Hamano), the author posted a v2 that incorporates all requested tweaks and adds a regression test. The test, now included, verifies the absolute path appears in the output, resolving the earlier debate about whether such coverage was necessary.

The patch is now complete: it’s minimal, narrowly scoped, and addresses the regression without touching core logic. The urgency comes from the regression’s introduction in the current cycle, and the fix’s simplicity reduces the risk of side effects. No objections remain, and the patch appears ready for merging.
