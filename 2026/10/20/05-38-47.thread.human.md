This thread is about a regression in `git init` where the command stopped printing the absolute path of the initialized repository (e.g., `/home/user/repo/.git`) and instead shows the relative `.git/` path. The change was unintentionally introduced in the current development cycle (Git 2.56), making the fix urgent to avoid shipping the behavior change in the upcoming release.

Matt Hunter proposed a minimal patch to restore the absolute path output, which Patrick Steinhardt reviewed favorably, calling the changes "obviously good." The author has agreed to post a v2 incorporating minor feedback: dropping a redundant sentence in the commit message and changing a variable type from `int` to `size_t`. The patch itself is uncontroversial and narrowly scoped to the regression.

The only open question is whether to add a regression test. Patrick Steinhardt argued that the current output isn’t *incorrect*, just different, which weakens the case for a test. Harald Nordgren has repeatedly advocated for a test on principle but hasn’t addressed the technical or practical trade-offs. The discussion remains unresolved, but the patch itself is ready to merge once the v2 is posted.
