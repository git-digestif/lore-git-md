This thread is about a small but urgent bugfix to restore the pre-2.56 behavior of `git init`, which used to print the absolute path of the new repository (e.g., `/home/user/repo/.git`) but was accidentally changed to show only `.git/` in the current development cycle. The regression was introduced in commit 20e38cba3926 and needs to be fixed before the upcoming release.

Matt Hunter, the patch author, has posted a v2 that includes the fix, addresses all review feedback, and adds a regression test. The patch is now complete except for minor test improvements suggested by Patrick Steinhardt, who reviewed the v2 and proposed tightening the test by removing an intermediate variable and matching the full output message. Matt has responded with a refined test assertion that checks the full output for the default case, keeping the discussion narrowly focused on test design rather than the fix itself.

The patch is uncontroversial and ready for integration once the test tweaks are finalized. Junio Hamano and Harald Nordgren have also weighed in, with Junio noting the practical utility of the absolute path in command transcripts and Harald advocating for a regression test (which is now included). The urgency of merging the patch before the Git 2.56 release remains high.
