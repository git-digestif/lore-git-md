This is a bugfix for Git’s ZIP archive generation, specifically addressing the extended timestamp (UT) field overflow issue that caused silent data corruption in tools like UnZip. The patch is now ready for integration after incorporating a test infrastructure fix to handle 32-bit platforms correctly.

Matthew E. Luallen’s reply confirms the v2 patch resolves the original 2106 timestamp wrap bug, where UnZip’s update mode (`unzip -u`) would incorrectly retain outdated files instead of replacing them with newer ones. The fix omits the UT field entirely when the commit time exceeds the 32-bit signed integer range (`> 0x7fffffff`), preventing the silent wrap to 1970 that caused the issue. This approach is clean and avoids repeating conditional logic, using a `strbuf` to prepare the field upfront.

The patch also includes robust test coverage in `t/t5004-archive-corner-cases.sh`, with prerequisites (`TIME_T_IS_64BIT` and `ZIPINFO_UT_EXTRA`) ensuring tests pass on 64-bit platforms and are skipped on 32-bit systems where `zipinfo(1)` lacks UT field support. Junio C Hamano has already confirmed the test fix is sound, resolving earlier CI failures on 32-bit platforms.

Matthew’s follow-up notes a separate time-zone issue with post-2038 dates in `unzip -u`, but this is explicitly scoped out of the current fix. The patch is narrowly targeted and does not address the unrelated ZIP legacy DOS date overflow bug or the `fast-import` negative timestamp validation gap, both of which remain open for future discussion.

This is a well-tested, low-risk fix for a real-world compatibility issue. The implementation is straightforward, and the test infrastructure improvements make it robust across platforms. If you care about ZIP archive correctness or tool interoperability, this patch is worth reviewing or tracking for integration.
