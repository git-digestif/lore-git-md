This is the third patch in Patrick Steinhardt’s four-patch bugfix series restoring dynamic reload of alternate object databases in the files-based ODB backend. It targets a specific performance regression introduced by the core fix (patch 2) and optimizes the `odb_files_dir_is_usable()` function to avoid redundant filesystem checks when an alternate is already known.

The patch reorders the logic in `odb_files_dir_is_usable()` to perform the hashmap lookup first, before hitting the filesystem. This is a straightforward optimization: the hashmap lookup is cheap, and if the alternate is already known, the function can exit early without calling `strbuf_realpath()` or `is_directory()`. The commit message includes benchmark results showing that this change reduces the lookup time for 20k missing objects from 309ms (unoptimized fix) to 263ms, bringing performance closer to the pre-regression baseline (181ms) but still leaving room for further improvement in the next patch.

The change is narrowly scoped to `odb/source-files.c` and is purely a refactoring of control flow within a single function. The commit message is clear and includes concrete performance data, which helps reviewers assess the impact. This patch is uncontroversial and looks like a solid, well-justified optimization. It doesn’t introduce new behavior or edge cases, and the test coverage from the earlier patches should continue to apply. The next patch in the series will address the remaining performance gap.
