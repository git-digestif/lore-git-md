This is the final patch in Patrick Steinhardt’s four-part bugfix series restoring dynamic reload of alternate object databases in Git’s files-based ODB backend. The patch addresses the performance regression introduced by the earlier fix (patch 2) by avoiding unnecessary re-reads of the alternates file when it hasn’t changed.

The optimization uses `struct stat_validity` to track the alternates file’s modification time, allowing the code to short-circuit the expensive read-and-parse operation if the file is unchanged. Benchmark results show this brings lookup time for 20k missing objects down to 197ms—nearly matching the pre-regression performance of 180ms and significantly better than the 309ms introduced by the unoptimized fix. The patch touches only `odb/source-files.c` and `odb/source-files.h`, adding the `stat_validity` machinery and updating the `read_alternates()` function to conditionally skip parsing.

This is a clean, well-motivated optimization that directly addresses the performance concern raised in the cover letter. The commit message includes concrete benchmark data, and the implementation is narrowly scoped to the alternates-reloading logic. There’s no reason to expect controversy here—this looks like a straightforward improvement that should land alongside the rest of the series.
