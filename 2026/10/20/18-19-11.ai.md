This is a two-patch bugfix series targeting Git's hook configuration system. The patches address two specific issues:

1. **`hook.<event>.enabled` now correctly disables hooks in the hooks directory** (not just config-defined hooks). The commit message notes this aligns behavior with the existing documentation, which implied the setting should apply universally. The fix touches `builtin/hook.c` and `hook.c`, adjusting how the enabled flag is checked during hook execution.

2. **Boolean config values `hook.*.enabled` and `hook.*.parallel` now accept empty values** (treated as `true`), matching Git's standard behavior for other boolean config keys. This is a consistency fix in `hook.c` that simplifies configuration syntax.

The series includes a new test file (`t/t1800-hook.sh`) with 51 lines of tests covering both fixes, including edge cases like empty config values and interaction between config and hookdir hooks. The changes are narrowly scoped to hook execution logic and config parsing, with no cross-subsystem impact.

The motivation is clear: these are longstanding paper-cuts in the hook system that create user confusion. The implementation looks straightforward (config flag propagation and boolean parsing), but the test coverage suggests the author took care to verify edge cases. No controversy is evident from the patch itself, though the hook subsystem has historically been a source of subtle bugs.
