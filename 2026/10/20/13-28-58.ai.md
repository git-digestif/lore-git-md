This is the second patch in Justin Tobler’s four-patch bugfix series (v3) targeting the ODB transaction race condition. It extracts the parsing logic for `git-index-pack`’s stdout report into a new public helper, `read_index_pack_report()`, in preparation for the later patch that defers `.keep` lockfile creation to the transaction commit phase.

The patch lifts the core parsing logic from `index_pack_lockfile()`—which currently reads the `"pack\t<name>\n"` or `"keep\t<name>\n"` line, extracts the packfile name, and determines whether a `.keep` file was created—into a standalone function in `pack-write.c` and exposes it via `pack.h`. The new helper is hash-algo-agnostic (using `repo->hash_algo->hexsz` to size the read buffer) and unconditionally uses the `is_keep` pointer, simplifying the caller’s logic. The original `index_pack_lockfile()` is refactored to use the new helper, reducing code duplication and making the packfile-name extraction reusable for the upcoming transaction-phase lockfile creation.

No behavior changes are introduced; this is purely a refactoring to enable the later fix. The commit message explicitly notes the assumption that `git-index-pack` output follows the expected format, which is now documented in the code. Patrick Steinhardt has already approved this patch as part of his substantive review of the series.
