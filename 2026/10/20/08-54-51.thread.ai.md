Thread identity: Bugfix series restoring dynamic reload of alternate object databases in the files-based ODB backend. Series version: v2 (six patches). Originating author: Patrick Steinhardt. Thread type: patch series (bugfix).

Core problem or goal: Restore the ability to reload the list of alternate object databases when an object lookup fails, a behavior accidentally broken in commit 5946a564cd (March 2026) during the ODB abstraction effort. The regression is rare but has been observed in production systems, where the alternates file may be modified while Git is running. The fix must also address a behavioral regression in `git receive-pack` when a temporary primary ODB (such as the quarantine directory) is in use: objects that have moved to an alternate since the quarantine was created are not found, even if the alternates file was updated.

Current status: Under review. The series is now complete with all six patches submitted, but a race condition in the alternates file reloading logic (patch 6) has been identified by Christian Couder. The race occurs if the alternates file is rewritten in-place while Git is reading it, causing the `stat_validity` tracking to be updated with the file descriptor’s metadata *after* the old content has already been parsed. This could lead to Git missing new alternates indefinitely. The issue is reproducible in the test added in patch 3, which explicitly uses an in-place rewrite. Christian has proposed a fix: move the `stat_validity_update()` call *before* reading from the file descriptor, matching the pattern used in `refs/packed-backend.c` and `shallow.c`. He also suggests clearing the validity only when reading fails, which would address Junio’s earlier feedback on patch 4 without reintroducing the race. The proposed reordering is mechanical and preserves the patch’s performance benefits. No alternative approaches or objections have been raised yet.
