Core problem or goal: Restore the ability to reload the list of alternate object databases when an object lookup fails, a behavior accidentally broken in commit 5946a564cd (March 2026) during the ODB abstraction effort. The regression is rare but has been observed in production systems, where the alternates file may be modified while Git is running. The fix must also address a behavioral regression in `git receive-pack` when a temporary primary ODB (such as the quarantine directory) is in use: objects that have moved to an alternate since the quarantine was created are not found, even if the alternates file was updated.

Current status: Under review. The series is now complete with all six patches submitted, but the race condition in patch 6 and the documentation of the error suppression in patch 5 remain the sole unresolved issues. The race occurs if the alternates file is rewritten in-place while Git is reading it, causing the `stat_validity` tracking to be updated with the file descriptor’s metadata *after* the old content has already been parsed. This could lead to Git missing new alternates indefinitely. Patrick Steinhardt has accepted Christian Couder’s proposed fix in principle: move the `stat_validity_update()` call *before* reading from the file descriptor, matching the pattern used in `refs/packed-backend.c` and `shallow.c`.
