This is a bugfix patch restoring the pre-20e38cba3926 behavior of `git init` and `git init --reinit` to print the absolute path of the initialized repository instead of the relative `.git/` path.

The patch targets the regression introduced in 20e38cba3926 (setup: split up concerns of `init_db()`, 2026-09-10), which moved the code that prints the "Initialized empty Git repository" message but did not update it to use the repository's full git directory path. The commit message explicitly states that the change was unintentional, citing the lack of discussion around this behavior change in the original thread.

The fix is straightforward: in `builtin/init-db.c`, the code now calls `repo_get_git_dir(the_repository)` to obtain the absolute path and uses that in the printf statements instead of the local `git_dir` variable, which holds owned memory that is later freed. The patch adds a new `full_git_dir` variable to hold the string and updates the formatting logic to match the original behavior.

The change is minimal (4 insertions, 3 deletions) and touches only the output message, not any core logic.
