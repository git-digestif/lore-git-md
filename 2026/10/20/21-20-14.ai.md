This is a **substantive review** of the reflink worktree patch, focusing on **platform-specific correctness risks** on Windows and macOS.

The review from brian m. carlson raises two critical concerns about the cross-platform reflink implementation in patch 1/2 of the v2 series. First, on Windows, the proposed `FSCTL_DUPLICATE_EXTENTS_TO_FILE` (ReFS block cloning) is flagged as **known to be defective** due to a long-standing Git LFS bug (issue #6312) that can cause silent corruption when cloning extents. The reviewer argues that until Microsoft provides a fixed Windows version, reflinking should be **disabled entirely on Windows** to avoid data integrity issues. Second, on macOS, the test prereq (`test_lazy_prereq REFLINK`) relies on `cp --reflink=always`, which may not be supported by the macOS `cp` binary, potentially leaving the APFS reflink path **untested in CI**. The reviewer suggests ensuring the macOS CI environment can actually exercise the clonefile() path before merging.

The feedback is narrowly scoped to the reflink implementation’s **safety and testability** on non-Linux platforms, leaving the rest of the patch (e.g., Linux FICLONE, ephemeral branch reaping) untouched. The tone is technical and cautionary, emphasizing the need for guarantees on correctness rather than feature completeness. This is likely to prompt a v3 revision to either disable Windows reflink or add platform-specific safeguards.
