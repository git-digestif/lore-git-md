Thread identity: bugfix patch series (three patches), originating author tsukasa-ino via GitGitGadget, thread type bug report and fix. Series version v2, now proposed as two separate topics: (1) hint message fix (patch 1/3), (2) "finish the switch" behavioral change (patches 2/3 and 3/3).

Core problem or goal: correct two related usability issues in `git switch` and `git branch --set-upstream-to` (and `git checkout -b`): (1) a misleading hint message when tracking configuration fails due to a locked config file, which incorrectly includes the full ref name (e.g., `origin/refs/heads/feat`) instead of the short name (e.g., `origin/feat`), and (2) an incomplete state left behind when `git switch -c` or `git checkout -b` fails to write tracking configuration, leaving HEAD on the old branch while updating the worktree, index, and new branch ref.

- Files touched: `branch.c`, `branch.h`, `builtin/branch.c`, `builtin/checkout.c`, and three test files (`t/t2027-checkout-track.sh`, `t/t2060-switch.sh`, `t/t3200-branch.sh`).
- Subsystems: branch (tracking configuration hints and error handling), checkout/switch (worktree and HEAD updates).
