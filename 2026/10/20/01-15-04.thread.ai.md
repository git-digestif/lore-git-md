Thread identity: bugfix patch series (three patches), originating author tsukasa-ino via GitGitGadget, thread type bug report and fix. Series version v2.

Core problem or goal: correct two related usability issues in `git switch` and `git branch --set-upstream-to` (and `git checkout -b`): (1) a misleading hint message when tracking configuration fails due to a locked config file, which incorrectly includes the full ref name (e.g., `origin/refs/heads/feat`) instead of the short name (e.g., `origin/feat`), and (2) an incomplete state left behind when `git switch -c` or `git checkout -b` fails to write tracking configuration, leaving HEAD on the old branch while updating the worktree, index, and new branch ref.

Current status: patch series v2 posted, under review. The series is complete and addresses all feedback from v1. The author has explicitly scoped the series to avoid making the switch fully atomic (undoing all changes on failure), which Junio acknowledges as sensible. The thread is now waiting for input on integration strategy.

Key technical details:
- Files touched: `branch.c`, `branch.h`, `builtin/branch.c`, `builtin/checkout.c`, and three test files (`t/t2027-checkout-track.sh`, `t/t2060-switch.sh`, `t/t3200-branch.sh`).
- Subsystems: branch (tracking configuration hints and error handling), checkout/switch (worktree and HEAD updates).

The hint message is still shown.
- Old behavior: (1) hint messages included the invalid `refs/heads/` prefix, and (2) the command would stop halfway, leaving HEAD on the old branch while updating the worktree, index, and new branch ref.
- Test coverage: the series adds comprehensive tests for both the hint message and the new "finish the switch" behavior. The hint message test now includes the enhancements suggested in v1 review: (1) verifying the entire multiline hint message (not just individual lines) to catch formatting or wording regressions, and (2) confirming the suggested command works once the lock is removed. The new behavior is tested in both `git switch` and `git checkout` scenarios, verifying that HEAD is updated, the worktree is clean, and the tracking config is not written.
- On-disk format: no changes.
