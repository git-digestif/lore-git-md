This is a design discussion about a bug in `git switch` and `git checkout` where the commands leave the repository in an inconsistent state if tracking setup fails.

Junio C Hamano responds to 井上司’s RFC, agreeing that the current behavior—where the worktree and index are updated but HEAD is not—is problematic. He expresses a preference for an "all-or-none" approach: if tracking setup fails, the command should fail cleanly without making any changes to the repository state. This would avoid the confusing mismatch between the worktree and HEAD that users currently encounter.

The thread remains in the design phase; no patch has been proposed yet. The key question is now settled in favor of atomicity, but the implementation details (how to roll back worktree and index changes if tracking setup fails) are still open. This is a well-motivated bugfix targeting a long-standing edge case, and Junio’s preference suggests it is likely to be accepted once a patch is submitted.
