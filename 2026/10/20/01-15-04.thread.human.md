This thread is about a three-patch bugfix series from tsukasa-ino that addresses two related usability issues in `git switch` and `git branch --set-upstream-to`. The first issue was a misleading hint message when tracking configuration fails due to a locked config file, which incorrectly included the full ref name (e.g., `origin/refs/heads/feat`) instead of the short name (e.g., `origin/feat`). The second issue was an incomplete state left behind when `git switch -c` or `git checkout -b` fails to write tracking configuration, leaving HEAD on the old branch while updating the worktree and index.

The series is now in its second version, posted after incorporating feedback on the initial patch that only addressed the hint message. The new version retains the hint fix (with enhanced test coverage) and adds two patches to refactor `setup_tracking()` to return an error code instead of calling `exit()`, and to modify `git switch` and `git checkout` to complete the switch and exit successfully even if tracking config cannot be written. This aligns with the behavior of `git push -u`, `git clone`, and `git fetch`. The series touches only the relevant subsystems (branch, checkout/switch) and includes comprehensive tests for both the hint message and the new "finish the switch" behavior.

Junio C Hamano, the maintainer, reviewed the first version favorably, calling the observation "good" and suggesting a test enhancement to verify the corrected hint command works when run. Harald Nordgren also reviewed the first version, agreeing the fix was valuable and suggesting the test validate the entire multiline hint message. The author incorporated all feedback into the second version, which has not drawn any objections to its core approach or implementation. The series is self-contained, low-risk, and appears ready for final review. The only open question is whether the "finish the switch" behavior should be extended to `git branch`, but the series explicitly leaves this unchanged to preserve current behavior.
