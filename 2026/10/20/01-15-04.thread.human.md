This thread began as a simple bugfix for a misleading hint message in `git switch` and `git branch --set-upstream-to` when tracking configuration fails due to a locked config file. The initial patch (v1) corrected the hint to show the short branch name (e.g., `origin/feat`) instead of the invalid full ref name (e.g., `origin/refs/heads/feat`), and was well-received by Junio C Hamano and Harald Nordgren, who suggested minor test enhancements.

The discussion quickly expanded to address a deeper issue: when `git switch -c` or `git checkout -b` fails to write tracking configuration, it leaves the worktree, index, and new branch ref updated while HEAD remains on the old branch—an incomplete and confusing state. The new three-patch series (v2) now fixes both problems. Patch 1/3 carries over the hint fix from v1 (with the requested test improvements), while patches 2/3 and 3/3 refactor `setup_tracking()` to return an error instead of calling `exit()`, and modify `git switch` and `git checkout` to complete the switch and exit successfully even if tracking config cannot be written. This matches the behavior of `git push -u`, `git clone`, and `git fetch`, and resolves the usability issue thoroughly.

The series touches `branch.c`, `branch.h`, `builtin/branch.c`, and `builtin/checkout.c`, and includes comprehensive tests in `t/t2027-checkout-track.sh`, `t/t2060-switch.sh`, and `t/t3200-branch.sh`. The changes are minimal, focused, and self-contained, with no on-disk format changes. The only open question is whether `git branch` should also adopt the "finish the switch" behavior (the series leaves it failing, as it does today). No objections to the core approach have been raised, and the series appears ready for review.
