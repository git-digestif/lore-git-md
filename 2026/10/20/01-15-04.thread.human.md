This thread is about a three-patch series from tsukasa-ino that fixes two related usability issues in `git switch` and `git branch --set-upstream-to`. The first patch corrects a misleading hint message that incorrectly displays full ref names (e.g., `origin/refs/heads/feat`) instead of short names (e.g., `origin/feat`) when tracking configuration fails due to a locked config file. The remaining two patches refactor `setup_tracking()` to return an error code instead of calling `exit()`, and modify `git switch` and `git checkout` to complete the branch switch (updating HEAD, worktree, and index) even if tracking config cannot be written, aligning their behavior with `git push -u`, `git clone`, and `git fetch`.

The series is now in its second version, incorporating all feedback from the initial review. Junio C Hamano, the maintainer, has raised a procedural question about whether the patches should be split into two topics—one for the uncontroversial hint fix and another for the more significant behavioral change—or merged as a single series. The author has already clarified that making the switch fully atomic (undoing all changes on failure) is out of scope, which Junio acknowledges as reasonable. No technical objections have been raised, and the series is well-tested, with enhanced test coverage for both the hint message and the new "finish the switch" behavior. The thread is now awaiting input on the integration strategy. Key participants include Junio, the author tsukasa-ino, and Harald Nordgren, who provided surface-level feedback on the first version.
