This is the first patch in Jason Newton’s v2 series introducing copy-on-write worktree creation via `--reflink`. It adds the core reflink machinery to `git worktree add`, enabling much faster worktree creation on supported filesystems (btrfs, XFS, bcachefs on Linux; APFS on macOS; ReFS on Windows) by cloning files rather than writing them out from the object store.

The patch is substantial and well-executed. It introduces a new `reflink_file()` helper in `copy.c` with cross-platform support (Linux FICLONE, macOS clonefile(), Windows FSCTL_DUPLICATE_EXTENTS_TO_FILE), filesystem capability probing, and careful handling of edge cases: dirty worktrees (via index refresh before reset), untracked files (cloned but not tracked), and small-file performance (no size cutoff). The implementation is opt-in via `--reflink` or the `worktree.reflink` config (true/false/auto), and degrades gracefully on unsupported filesystems. Documentation is thorough, covering both the command-line option and the safe pattern for multiple worktrees at the same commit (one ref per worktree, created in a single `update-ref` transaction). Tests in `t2400-worktree-add.sh` cover reflink behavior, edge cases, and config interaction.

This is a clear performance win for users managing many worktrees from the same base, and the implementation looks solid. The cross-platform support (including Windows ReFS via the same mechanism Git LFS uses) and careful handling of edge cases suggest this is ready for serious review. The only likely point of discussion is whether reflink should be opt-in or automatic when available; the current opt-in approach is a deliberate choice to avoid silently copying untracked files.
