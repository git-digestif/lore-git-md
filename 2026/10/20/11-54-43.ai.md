This is a test patch adding basic coverage for `git mktree --batch`.

The patch introduces seven new tests in `t/t1010-mktree.sh`, exercising the `--batch` mode of `git mktree`. The tests verify that the command correctly handles multiple trees in a single batch, ignores trailing blank lines, processes `-z` (NUL-terminated) input, and fails gracefully when encountering a missing object. One test also confirms that blank lines are rejected without `--batch`, and another documents the current behavior when two blank lines appear consecutively (producing an empty tree, though the documentation suggests this may not be intentional).

The motivation is clear: the only existing test for `--batch` mode checks resilience to concurrent repacks, leaving basic functionality untested. This gap allowed a memory leak (fixed in commit 6272f3bd17) to go unnoticed. The tests are straightforward and cover the core behaviors described in the commit message, including edge cases like empty input blocks and error conditions. The patch is well-scoped, touching only the test file, and the commit message explicitly notes a potential ambiguity in the expected behavior for consecutive blank lines. Jeff King (Peff) suggested the tests, which lends credibility to the approach.
