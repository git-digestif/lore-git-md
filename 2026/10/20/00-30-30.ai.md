This is a CI/build system discussion follow-up. Brian M. Carlson responds to Todd Zullinger’s procedural question about whether to use `macos-latest` (a floating tag) or `macos-26` (an explicit version) for the `osx-reftable` and `osx-gcc` jobs in the v2 patch updating GitHub Actions macOS runners.

Carlson notes that macOS releases annually, so GitHub Actions’ `macos-latest` tag will likely update once per year, with older versions being deprecated. He observes that macOS has historically adhered closely to POSIX standards (until recently being UNIX-certified), so divergence in core functionality is unlikely to be a major concern. While he acknowledges that `macos-latest` would simplify maintenance by automatically tracking the current default image, he expresses no strong preference between the two options. His primary concern would be testing across different Linux versions, C libraries, and compilers—areas with greater potential for breaking changes and longer OS lifespans—rather than macOS versions.

The response is substantive but non-prescriptive: it provides context about macOS release cadence and POSIX compliance without endorsing either approach. The thread remains focused on the narrow trade-off between maintainability (`macos-latest`) and stability (explicit version pinning), with no new technical objections or alternative proposals introduced.
