This is a **bugfix patch** targeting a user-visible regression in `git init`. Junio C Hamano weighs in on the ongoing discussion about whether to add a regression test, siding with the practical value of the absolute path output. He acknowledges Patrick Steinhardt’s point that the current behavior isn’t *wrong* but argues it is "much less useful" for users reviewing command transcripts, where the absolute path helps contextualize where the repository was created. His comment shifts the focus from correctness to usability, reinforcing the case for restoring the pre-regression behavior.

The patch itself is a minimal, well-scoped fix to `builtin/init-db.c` that restores the absolute path output in the "Initialized empty Git repository" message. The regression was introduced in the current development cycle (Git 2.56) by commit 20e38cba3926, making this a time-sensitive fix to avoid shipping the behavior change in the upcoming release. The author, Matt Hunter, has already agreed to incorporate minor feedback (dropping a redundant commit message sentence and adjusting a variable type) and is preparing a v2.

The only open question remains whether to add a regression test. Junio’s input leans toward testing, not because the output is incorrect, but because users rely on the absolute path for clarity in transcripts. This aligns with Harald Nordgren’s earlier advocacy for a test, though Patrick Steinhardt had previously argued the case was weaker since the output isn’t technically wrong. The discussion now centers on user expectations rather than strict correctness.

The patch is under active review and looks likely to be merged once the v2 is posted. The urgency is heightened by the regression’s introduction in the current cycle, and the feedback so far—from both Patrick Steinhardt and Junio—suggests the fix is uncontroversial. The test question, while still unresolved, doesn’t appear to block the patch’s progress.
