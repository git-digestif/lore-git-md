This is the second patch in Phillip Wood’s seven-patch refactoring series (`pw/stash-optimize-check_changes-calls/v3`) targeting redundant change-detection logic in `git stash`. The patch removes a long-standing duplicate call to `check_changes_tracked_files()` in `create_stash()`, eliminating an unnecessary change check that has been present since ef0f0b4509 (2019). The commit message explains that the double check was never an optimization—it was unreliable because it ran before the index was refreshed—and that removing it simplifies the code without altering behavior. The patch also cleans up `check_changes_tracked_files()` by removing its redundant `repo_read_index()` call, since all remaining callers now refresh the index before invoking it.

The change is confined to `builtin/stash.c` and touches only `create_stash()` and `check_changes_tracked_files()`. It is a straightforward refactoring with no user-visible impact, addressing a minor inefficiency that has persisted for over seven years. The patch is well-motivated and uncontroversial, fitting neatly into the series’ broader goal of consolidating redundant index operations and change checks. No edge cases or objections have been raised in prior iterations, and the patch aligns with Junio’s feedback on avoiding unnecessary work. This is a clean, incremental step toward the series’ performance and code hygiene improvements.
