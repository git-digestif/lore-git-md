This is the core bugfix patch in Patrick Steinhardt’s four-patch series restoring dynamic reload of alternate object databases in the files-based ODB backend. It directly addresses the regression introduced in commit 5946a564cd (March 2026), which broke the ability to reload alternates when an object lookup fails.

The patch modifies `odb/source-files.c` to re-prepare alternates and retry the read when an object is not found. The key change is in `odb_source_files_read_object_info()`, where a new `tail` pointer tracks newly added directories so that only those are rescanned on retry, avoiding redundant work. The test in `t/t1006-cat-file.sh` verifies the fix by simulating a concurrent alternates update: an object initially missing becomes available after the alternates file is rewritten.

Performance is explicitly called out in the commit message. The unoptimized fix regresses lookup time for 20k missing objects from 180ms to 309ms, but the author notes this is unavoidable—restoring the broken behavior inherently requires more work. The next two patches in the series will address this overhead.

The patch is narrowly scoped, well-explained, and includes a clear test case. It touches only the files-based ODB backend and does not attempt to handle recursive alternates (an edge case the commit message acknowledges was never supported). The regression is real, the fix is targeted, and the performance trade-off is justified. This is a solid, uncontroversial bugfix that should merge cleanly once the follow-up optimizations land.
