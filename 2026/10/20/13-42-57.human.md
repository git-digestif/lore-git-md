This is the fourth patch in Harald Nordgren’s v10 series introducing a "matching-inspired" fetch mode for shallow repositories. It adds a `--limited-fetch` flag to `git remote add`, which configures the remote to use `remote.<name>.refmap` instead of the traditional wildcard `remote.<name>.fetch` refspec.

The patch is straightforward and uncontroversial. When `--limited-fetch` is given, `git remote add` sets up `remote.<name>.refmap` (e.g., `+refs/heads/*:refs/remotes/<name>/*`) so that a refspec-less `git fetch <name>` only fetches branches already tracked by local branches at that remote. The flag is rejected when combined with `-t/--track` or `--mirror`, since those options already specify explicit fetch behavior. The implementation updates `builtin/remote.c` to set the refmap configuration via `repo_config_set()` and adds documentation to `git-remote.adoc`. Four new tests in `t/t5505-remote.sh` verify the flag’s behavior, including edge cases like rejecting it with `-t` and ensuring it works in non-shallow repositories.

This patch is a pure feature addition with no behavior changes for existing workflows. It complements the core logic introduced in earlier patches and is ready for review. The series as a whole is technically complete and awaiting final maintainer feedback before merging to `next`.
