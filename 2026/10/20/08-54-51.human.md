This is a bugfix series targeting the object database (ODB) subsystem, specifically the files-based backend. The series restores functionality that was accidentally broken in March 2026: reloading the list of alternate object directories when an object lookup fails. Without this, Git processes that run for a long time (such as daemons) can miss updates to the alternates file, leading to spurious "object not found" errors even when the object exists in a newly added alternate.

The series is authored by Patrick Steinhardt, the primary driver of Git's ongoing ODB abstraction effort. The regression was introduced by commit 5946a564cd, which made the `read_object_info()` function pluggable. The fix itself is contained in the second patch, while the remaining two patches optimize performance to mitigate the overhead of reloading alternates. The commit message reports that the fix initially slowed down lookups for 20,000 missing objects from 180ms to 309ms, but the optimizations bring it down to 197ms, nearly restoring the original performance.

The series is small (four patches) and touches only `odb/source-files.c`, `odb/source-files.h`, and adds tests in `t/t1006-cat-file.sh`. It is based on the current tip of Junio's tree with Patrick's recent ODB cleanups merged in. The motivation is clear: production systems have encountered this edge case, and the fix is straightforward. The performance measurements suggest the optimizations are effective, making the fix practical for real-world use.

This looks like a well-crafted, narrowly scoped bugfix that addresses a real problem without introducing unnecessary complexity. The regression is identified by commit hash, the performance impact is quantified, and the series includes new tests to prevent future breakage. For anyone running long-lived Git processes that rely on alternates, this is likely worth attention.
