This is the third patch in Harald Nordgren’s v10 series introducing a "matching-inspired" fetch mode for shallow repositories. The patch implements the core logic: when a remote has `remote.<name>.refmap` configured but no `remote.<name>.fetch`, a refspec-less `git fetch` now infers which branches to fetch by enumerating the local branches whose `@{upstream}` points to that remote.

The change is focused on `builtin/fetch.c` and `remote.c`. In `get_ref_map()`, if no refspec is given and the remote has a refmap but no fetch refspec, the code calls the new `branches_tracking_remote()` helper (added in `remote.c`). This helper iterates over all local branches, collects the source ref for each branch whose `remote_name` matches the target remote, and constructs a dynamic refspec from the inferred branches. The `do_fetch()` function then populates `transport_ls_refs_options.ref_prefixes` with these inferred branches to limit the transport layer’s ref requests.

The patch also reorganizes the control flow in `do_fetch()` to accommodate the new logic, ensuring that the current branch’s `@{upstream}` is still fetched even if it is not covered by the inferred branches (e.g., when a narrowed `-t` refspec is configured). The existing "fetch branches merged into the current branch" logic is reused via the `collect_upstream_from_remote()` helper, which was extracted in Patch 2/5.

Test coverage is thorough: the new `t/t5586-fetch-refmap.sh` script (119 lines) verifies edge cases such as bare fetches, explicit one-time fetches, duplicate branch tracking, cross-remote tracking, and compatibility with `git remote show`. The tests confirm that the inferred fetch behavior works as expected and does not fetch branches tracked by other remotes.

This patch is the technical centerpiece of the series and is now ready for final maintainer review. All substantive feedback from Junio and other reviewers has been addressed in prior versions, and the v10 rebase resolves the only remaining conflict with a recently merged topic. The implementation reuses existing logic and configuration machinery, introducing no new technical debt.
