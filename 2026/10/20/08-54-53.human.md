This is the core bugfix patch in Patrick Steinhardt’s four-part series restoring dynamic reload of alternate object databases in Git’s files-based ODB backend. The patch directly addresses the regression introduced in commit 5946a564cd (March 2026), which broke the ability to reload alternates when an object lookup fails — a scenario that can occur in production when long-lived `git cat-file` processes run while the repository’s alternates file is modified (e.g., during repository forking or object pool updates).

The fix itself is straightforward: when an object isn’t found, the code now calls `prepare_alternates()` to reload the alternates list and retries the lookup. The patch also adjusts the retry logic to only re-scan newly added loose object directories, avoiding unnecessary work. The test added to `t/t1006-cat-file.sh` demonstrates the fix by simulating a concurrent alternates update during a `git cat-file --batch-check` session, verifying that the object becomes visible after the alternates file is written.

Performance is a key concern here. The unoptimized fix introduces a measurable regression (20k missing object lookups jump from 180ms to 309ms), but the commit message acknowledges this and notes that the next two patches in the series will mitigate it. The regression is framed as unavoidable — restoring the correct behavior inherently requires more work than the broken state, and the numbers align with pre-regression performance.

The patch is well-motivated and narrowly scoped. It touches only `odb/source-files.c` and adds a single test scenario, with no changes to public APIs or on-disk formats. The commit message clearly explains the regression, the fix, and the performance trade-offs, making it easy for reviewers to assess. This looks like a clean, uncontroversial bugfix that should merge smoothly once the follow-up optimizations land.
