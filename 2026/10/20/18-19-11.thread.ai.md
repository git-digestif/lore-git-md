Core problem or goal
Fix two inconsistencies in Git’s hook configuration system:
1. The `hook.<event>.enabled` setting should (per documentation) disable *all* hooks for the event, but currently only disables config-defined hooks, leaving hooks in the hooks directory unaffected. **Design resolution**: Adrian Ratiu (original author of `hook.<event>.enabled`) confirms the current behavior was intentional; the documentation’s broader wording is misleading. The thread now centers on whether to accept the patch (prioritizing consistency with documentation) or reject it (prioritizing backward compatibility). Adrian suggests a middle ground: accept the patch *and* update the documentation to explicitly state that `hook.<event>.enabled` disables both config-defined hooks and hooks in the hooks directory.
2. Boolean config values `hook.<event>.enabled` and `hook.<event>.parallel` now accept empty values (treated as `true`), matching Git’s standard boolean config behavior.

The thread remains open for broader community input on the trade-off between consistency and backward compatibility, but no technical objections or alternatives have been raised.
