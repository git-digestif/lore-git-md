Core problem or goal
Fix two inconsistencies in Git’s hook configuration system:
1. The `hook.<event>.enabled` setting should (per documentation) disable *all* hooks for the event, but currently only disables config-defined hooks, leaving hooks in the hooks directory unaffected. **Design resolution**: Adrian Ratiu (original author of `hook.<event>.enabled`) confirms the current behavior was intentional; the feature was scoped to config-defined hooks only. The documentation is therefore too broad.
2. Boolean config values `hook.<event>.enabled` and `hook.<event>.parallel` now accept empty values (treated as `true`), matching Git’s standard boolean config behavior.

Current status
Under review; v1 posted 2025-07-10. No prior versions. The design ambiguity is now resolved, but the thread remains open for broader community input on whether to accept the patch (prioritizing consistency) or reject it (prioritizing backward compatibility).
