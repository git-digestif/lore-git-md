Core problem or goal
Fix two inconsistencies in Git’s hook configuration system:
1. The `hook.<event>.enabled` setting now correctly disables hooks located in the hooks directory (not just config-defined hooks), aligning behavior with documentation.
2. Boolean config values `hook.<event>.enabled` and `hook.<event>.parallel` now accept empty values (treated as `true`), matching Git’s standard boolean config behavior.
**Design ambiguity**: Junio C Hamano notes that the current behavior (where `hook.<event>.enabled=false` only disables config-defined hooks) may have been intentional, not a bug, suggesting the documentation was written too narrowly and the feature’s original scope was limited to config-defined hooks.
