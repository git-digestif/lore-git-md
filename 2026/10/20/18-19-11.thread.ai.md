Core problem or goal
Fix two inconsistencies in Git’s hook configuration system, now explicitly framed as a **behavior change** rather than a bugfix:
1. The `hook.<event>.enabled` setting now disables *both* config-defined hooks and the traditional hook in the hooks directory, aligning behavior with the updated documentation. This resolves the ambiguity noted in v1, where the documentation’s broader wording conflicted with the original implementation’s narrower scope (disabling only config-defined hooks). Adrian Ratiu (original author of `hook.<event>.enabled`) proposed this middle ground—accepting the patch while updating the documentation to remove ambiguity.
2. Boolean config values `hook.<event>.enabled` and `hook.<event>.parallel` now accept empty values (treated as `true`), matching Git’s standard boolean config behavior.

Current status
Under review; v2 posted 2025-07-15. The series acknowledges the backward-compatibility trade-off: users who relied on the old behavior (where `hook.<event>.enabled=false` left the hookdir hook untouched) will see a change. The second patch (empty-value handling) is uncontroversial and mechanically consistent with Git’s config standards. No technical objections or alternatives have been raised for either patch, but the thread remains open for broader community input on the compatibility implications of the first patch. Junio’s earlier hesitation about classifying this as a breaking change is addressed by the updated framing, though no explicit maintainer position has been stated since v2.

- Documentation change: `hook.adoc` now explicitly states that `hook.<event>.enabled` applies to both config and hookdir hooks.
