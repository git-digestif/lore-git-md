This is the first patch in a two-patch v2 series introducing copy-on-write worktree creation via `--reflink` to the worktree subsystem. The patch implements the core reflink functionality, adding a new `--reflink` option to `git worktree add` that, on supported filesystems (btrfs/XFS/bcachefs on Linux, APFS on macOS, ReFS on Windows), populates the new worktree by reflinking the current worktree's files and index instead of writing every file out from the object store. The subsequent `git reset --hard` then only rewrites paths that differ between the source and the target commit, leaving everything else sharing storage with the source until modified.

The implementation is cross-platform, with new copy-on-write primitives in `copy.c` (`reflink_file()`) that abstract the platform-specific reflink mechanisms: Linux's `FICLONE` ioctl, macOS's `clonefile()`, and Windows's `FSCTL_DUPLICATE_EXTENTS_TO_FILE` (matching Git LFS's approach). Filesystem capability is probed up front by attempting to clone a one-byte file; where reflinks are unavailable, the option falls back to a regular checkout. The patch handles edge cases carefully: dirty worktrees are reconciled via an `update-index --refresh` before reset, untracked files are carried over (documented as a deliberate tradeoff), and the reflink behavior is configurable via `worktree.reflink` (true/false/auto) with command-line overrides (`--reflink`/`--no-reflink`).

The patch touches `builtin/worktree.c`, `copy.c`, and `copy.h`, adding the reflink logic and new helper functions, and updates documentation in `git-worktree.adoc` and `config/worktree.adoc` to explain the feature, its limitations (e.g., overlayfs incompatibility), and safe usage patterns (e.g., one ref per worktree for parallel agents). Test coverage in `t2400-worktree-add.sh` verifies the reflink functionality, including edge cases like untracked file handling and option compatibility. The implementation is opt-in (configurable rather than automatic) and degrades gracefully in modes that cannot reflink (`--orphan`, `--no-checkout`), ensuring it never breaks existing workflows.
