This thread is about a patch series from Thomas Bachem that fixes two edge cases in Git’s hook configuration system: making `hook.<event>.enabled` also disable hooks in the hooks directory (not just config-defined hooks), and allowing empty values for boolean config settings like `hook.<event>.enabled` and `hook.<event>.parallel`. The series was initially submitted as a straightforward bugfix, but Junio C Hamano raised a design question—whether the current behavior (where `hook.<event>.enabled=false` only disables config-defined hooks) was intentional rather than a bug.

The key development is Adrian Ratiu’s reply, confirming that the current behavior was deliberate. Adrian, who originally implemented the `hook.<event>.enabled` feature, clarified that the configuration was designed to affect only config-defined hooks, not traditional hooks in the hooks directory. While he acknowledges the documentation could be clearer, he leaves the decision to the community: either accept the patch to align behavior with the documentation (disabling all hooks) or update the documentation to reflect the original intent (preserving backward compatibility). The thread is now focused on this trade-off between consistency and backward compatibility, with no technical objections raised so far. The series remains under review, and broader input is expected before a decision is made.
