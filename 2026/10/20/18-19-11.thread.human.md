This thread is a two-patch bugfix series from Thomas Bachem that addresses inconsistencies in Git’s hook configuration system. The series, posted on July 10, 2025, fixes two longstanding issues: first, ensuring the `hook.<event>.enabled` setting correctly disables hooks in the hooks directory (not just config-defined hooks), and second, making boolean config values `hook.<event>.enabled` and `hook.<event>.parallel` accept empty values (treated as `true`), aligning with Git’s standard boolean config behavior.

The patches touch only `builtin/hook.c`, `hook.c`, and a new test file `t/t1800-hook.sh`, with no changes to on-disk formats or new symbols. The second patch, summarized here, is a minimal change in `hook.c` that relaxes value-checking logic for the two boolean keys, delegating parsing to `git_parse_maybe_bool()`. The tests verify edge cases, including interaction with the `hook.jobs` setting for parallel execution.

So far, the series has seen no review or discussion, but it is self-contained and addresses the stated problems without introducing new design questions. The hook subsystem has historically been prone to subtle bugs, but this series appears straightforward and well-tested. No objections or open questions have been raised yet.
