This thread is a two-patch bugfix series from Thomas Bachem that addresses two longstanding issues in Git's hook configuration system. The patches fix inconsistencies in how hook disabling and boolean config values are handled.

The first patch ensures that `hook.<event>.enabled` now correctly disables hooks in the hooks directory, not just those defined in configuration. This aligns the behavior with existing documentation. The second patch makes boolean config values like `hook.*.enabled` and `hook.*.parallel` accept empty values (treated as `true`), matching Git's standard behavior for other boolean config keys.

The changes are narrowly scoped to hook execution logic and config parsing, touching `builtin/hook.c`, `hook.c`, and `hook.h`. The series includes a new test file (`t/t1800-hook.sh`) with comprehensive coverage of both fixes, including edge cases. While the implementation appears straightforward, the thorough test coverage suggests careful attention to detail. There's no indication of controversy so far, though the hook subsystem has historically been prone to subtle bugs. The series is currently at its initial version (v1).
