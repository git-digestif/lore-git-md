This thread is about a two-patch series from Thomas Bachem that fixes edge cases in Git’s hook configuration system. The series, now at version 2, is explicitly framed as a behavior change rather than a bugfix. The first patch ensures `hook.<event>.enabled` disables both config-defined hooks and traditional hooks in the hooks directory, aligning behavior with the documentation and resolving an earlier ambiguity. The second patch makes `hook.<event>.enabled` and `hook.<event>.parallel` accept empty values (treated as `true`), matching Git’s standard boolean config behavior.

Junio C Hamano has queued the series for integration, noting no remaining objections. The patches touch `builtin/hook.c`, `hook.c`, `hook.h`, and `Documentation/config/hook.adoc`, with expanded test coverage in `t/t1800-hook.sh`. While the implementation is uncontroversial, the first patch introduces a backward-compatibility trade-off: users who relied on the old behavior (where `hook.<event>.enabled=false` left the hookdir hook untouched) will see a change. The updated documentation and commit messages now clearly reflect this as a deliberate design choice, addressing earlier feedback from Adrian Ratiu and Junio’s hesitation about classifying it as a breaking change. The series is now under review in Junio’s integration branches.
