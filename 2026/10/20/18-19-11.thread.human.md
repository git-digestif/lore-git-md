This thread is about a patch series from Thomas Bachem that fixes two edge cases in Git’s hook configuration system. The first patch addresses a discrepancy where `hook.<event>.enabled` (per documentation) should disable *all* hooks for an event, but currently only disables config-defined hooks, leaving hooks in the hooks directory active. Adrian Ratiu, the original author of this feature, clarified that the current behavior was intentional, meaning the documentation is overly broad. The second patch aligns boolean config values (`hook.<event>.enabled` and `hook.<event>.parallel`) with Git’s standard behavior by accepting empty values as `true`.

The series is under review, with the key question now being whether to accept the patch (prioritizing consistency with the documentation) or reject it (prioritizing backward compatibility). Junio C Hamano, the maintainer, has re-examined the documentation and concluded that the current behavior was likely intentional, making the proposed change a backward-incompatible breakage rather than a bugfix. However, he acknowledges that end users may not parse the documentation’s fine print, leaving the decision to the broader community. The thread is now awaiting further input, with no technical objections or alternatives raised so far. The patches touch `builtin/hook.c`, `hook.c`, and `hook.h`, and expand test coverage in `t/t1800-hook.sh` to verify the fixes.
