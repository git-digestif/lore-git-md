This thread is about a patch series from Thomas Bachem that fixes two edge cases in Git’s hook configuration system. The first patch addresses a discrepancy between the documentation and behavior: the `hook.<event>.enabled` setting is documented to disable *all* hooks for an event, but currently only disables config-defined hooks, leaving hooks in the hooks directory active. The second patch ensures that empty values for `hook.<event>.enabled` and `hook.<event>.parallel` are treated as `true`, aligning with Git’s standard boolean config behavior.

The series is under review, with the design intent now clarified. Adrian Ratiu, the original author of `hook.<event>.enabled`, confirmed that the current behavior was intentional but is open to accepting the patch if the documentation is updated to explicitly state that `hook.<event>.enabled` disables both config-defined hooks and hooks in the hooks directory. Junio C Hamano initially flagged the ambiguity and leaned toward treating the change as backward-incompatible but left the decision to the community. Thomas Bachem argues for consistency with the documentation and has provided test coverage for the edge cases.

The thread is now waiting for broader community input or for Thomas to submit a v2 with the requested documentation updates. No technical objections have been raised, and the key question remains whether to prioritize consistency with the documentation or preserve backward compatibility. The series touches `builtin/hook.c`, `hook.c`, and `t/t1800-hook.sh`, with no changes to on-disk formats or new symbols.
