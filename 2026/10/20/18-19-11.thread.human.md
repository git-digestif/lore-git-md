This thread is about a two-patch series from Thomas Bachem that fixes edge cases in Git’s hook configuration system. The series is now at version 2, posted on July 15, 2025, and is under review.

The first patch resolves an inconsistency where the `hook.<event>.enabled` setting only disabled hooks defined in Git’s configuration but left traditional hooks in the hooks directory untouched. This created a mismatch with the documentation, which suggested the setting applied to all hooks. The patch aligns the behavior with the documentation by making `hook.<event>.enabled` disable both config-defined and hookdir hooks. Adrian Ratiu, who originally implemented the `hook.<event>.enabled` feature, supported this change as a middle ground, and the documentation has been updated to remove ambiguity. The patch touches `builtin/hook.c`, `hook.c`, and `hook.h`, and expands test coverage in `t/t1800-hook.sh`.

The second patch, summarized in the new email, ensures that boolean config values like `hook.<event>.enabled` and `hook.<event>.parallel` accept empty values (treated as `true`), matching Git’s standard boolean config behavior. This is a mechanical change to `hook.c` and adds further test coverage. There are no backward-compatibility concerns here, as this is a straightforward consistency fix.

The series is framed as a deliberate behavior change rather than a bugfix, acknowledging that users who relied on the old behavior (where `hook.<event>.enabled=false` left hookdir hooks untouched) will see a change. No technical objections have been raised, but the thread remains open for broader community input on the compatibility implications. Junio Hamano, the maintainer, previously leaned toward treating this as a backward-incompatible change but hasn’t commented on the updated v2. The series is still under review, with no explicit approvals recorded yet.
