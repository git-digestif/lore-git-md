This is Junio’s review of the fourth patch in Patrick Steinhardt’s four-patch bugfix series restoring dynamic reload of alternate object databases. The series as a whole is a well-motivated, narrowly scoped fix for a regression introduced during the ODB abstraction effort, with strong test coverage and incremental performance optimizations.

Junio’s comment is a narrow technical point about the placement of the `stat_validity_update()` call in the alternates file parsing logic. Currently, the code updates the `stat_validity` struct *before* attempting to read the file, meaning that if the read fails (e.g., due to a transient I/O error or a concurrent modification), the validity timestamp will still reflect the failed attempt. Junio suggests moving the update *after* a successful read, which would make the optimization more conservative: if the read fails, the next attempt will still re-read the file rather than assuming it hasn’t changed. He frames this as a safety question rather than a correctness issue, asking whether the extra caution is worth the minor code restructuring.

The review is substantive but low-stakes: it does not challenge the patch’s core design or performance claims, and the change being proposed is small and mechanical. The question is whether to prioritize strict correctness (re-read on any failure) or simplicity (update validity unconditionally). No other concerns are raised, and the patch remains uncontroversial.
