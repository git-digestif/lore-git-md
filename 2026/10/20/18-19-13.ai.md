This is the second patch in a two-patch bugfix series targeting Git's hook configuration system. It addresses a longstanding inconsistency where boolean config keys `hook.<name>.enabled` and `hook.<name>.parallel` rejected empty values, unlike Git's standard boolean config behavior (where an empty value is treated as `true`). The fix is a small, targeted change in `hook.c` that relaxes the value-checking logic for these two keys, allowing them to accept empty values as `true`.

The patch touches only `hook.c` and the new test file `t/t1800-hook.sh`, adding 24 lines of code and tests. The implementation is straightforward: it modifies `hook_config_lookup_all()` to skip the "missing value" error for `.enabled` and `.parallel` keys, delegating the parsing to `git_parse_maybe_bool()`, which already handles empty values correctly. The new tests verify that both keys work as expected when given without a value, including interaction with the `hook.jobs` setting for parallel execution.
