This thread is a single-patch bugfix from GSoC contributor Aniket Gupta correcting the progress message printed by `git fsck --verbose`. The verbose connectivity message was reporting the number of hash buckets rather than the actual number of objects, which is misleading. The patch adds a small `get_object_count()` helper in `object.c` (returning `repo->parsed_objects->nr_objs`), switches `builtin/fsck.c` to use it, and adds singular/plural message tests in `t/t1450-fsck.sh`.

Review converged quickly. Laveesh Bansal gave a substantive review, tested the patch, added a `Reviewed-by` trailer, and worked with the author on the commit message title, settling on "report the number of objects in the connectivity message" -- phrasing that accurately describes the count without falsely implying every counted object was verified. One edge case was identified and accepted as non-blocking: in partial clones, the reported count can include objects that are not locally present or even downloaded. Aniket's latest email is simply a thank-you closing the loop; there are no new code changes or open technical questions.

The patch remains under review as its first iteration, awaiting Junio C Hamano's final call on the exact commit message wording before it can move toward integration.
