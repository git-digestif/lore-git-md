This is a performance bugfix for `upload-pack`, addressing a severe regression in shallow fetches over protocol v2. The v2 patch from Harald Nordgren fixes the core issue—where fetches from shallow repositories with long histories could take minutes instead of seconds—while also correcting a protocol-layer mistake identified in review.

The problem occurs because protocol v2 inefficiently traverses the entire commit history to determine which shallow commits to advertise, repeatedly visiting the same commits in merge-heavy histories. The fix aligns v2 behavior with protocol v0 by directly advertising all shallow grafts when no specific depth is requested, avoiding redundant traversal. For operations like `git fetch --unshallow` that still require history traversal, the patch optimizes the walk to visit each commit only once.

This version (v2) addresses Junio C Hamano’s review feedback by using the `packet_writer` API instead of `packet_write_fmt`, ensuring sideband multiplexing works correctly. The patch also adds a test case to verify shallow fetches work with `uploadpack.allowSidebandAll` enabled, guarding against the protocol violation that broke v1.

The changes are minimal and focused: three lines modified in `shallow.c` to adjust depth comparison logic, a new helper function in `upload-pack.c` to advertise grafts via the packet writer, and a test in `t/t5537-fetch-shallow.sh`. The fix is well-motivated, with clear before/after measurements (7 minutes → 1 second in the homebrew-core example) and no apparent downsides for edge cases like `--reject-shallow` or `--unshallow`.

The patch is now technically sound and ready for further review, though it remains marked as part of a pull request rather than a direct mailing list submission. No substantive objections remain, and the author has addressed the only correctness issue raised so far. This looks like a straightforward win for users of shallow repositories.
