This is the first patch in a five-part feature series that introduces a "matching-inspired" fetch mode for shallow repositories. The patch adds a new configuration variable, `remote.<name>.refmap`, which provides the default value for the `--refmap` option in `git fetch`. This is the foundational change that enables the rest of the series by separating namespace mappings from fetch selection logic.

The implementation is straightforward and well-contained. The patch adds the new configuration to `remote.c` and `remote.h`, updates `builtin/fetch.c` to use the remote's refmap when no explicit `--refmap` is given, and documents the new setting in `Documentation/config/remote.adoc` and `Documentation/fetch-options.adoc`. The precedence rule is clear: an explicit `--refmap` on the command line overrides `remote.<name>.refmap`, and `remote.<name>.fetch` (if configured) overrides both. This resolves the fatal error seen in earlier versions when `--refmap` was used without command-line refspecs.

The test coverage in `t/t5510-fetch.sh` is thorough, verifying that `remote.<name>.refmap` behaves like `--refmap` on the command line, does nothing when there is nothing to fetch, and correctly yields to `remote.<name>.fetch` when both are present. The tests are well-structured and cover edge cases like bare fetches and explicit command-line refspecs.

This patch is a clean, uncontroversial addition that reuses existing refspec machinery. It introduces no new technical debt and aligns with the series' goal of improving fetch performance for shallow repositories. The implementation is ready for merging, and the only remaining work is in later patches, which build on this foundation to implement the dynamic branch selection logic.
