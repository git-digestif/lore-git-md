This is the first patch in Patrick Steinhardt’s six-patch v3 series refactoring and optimizing alternates handling in the Git object database’s "files" backend. It directly addresses a performance regression introduced when alternates handling was reorganized for pluggable ODB support.

The patch reorders the object lookup logic in `odb_source_files_read_object_info()` to check all packfiles across alternates before checking any loose objects. This avoids unnecessary `stat()` syscalls when objects exist in alternate packfiles, which are cheaper to access due to cached pack indices. The change is motivated by benchmark data showing a 1.89x speedup for `git cat-file --batch-check` when reading objects primarily stored in alternate packfiles.

The patch also introduces a new regression test (`t/t5615-alternate-env.sh`) that verifies the optimization works as intended. The test creates an alternate repository with a deltified object, writes a loose copy of the same object in the main repository, and confirms `git cat-file --batch-check="%(deltabase)"` resolves to the alternate’s packfile rather than the loose copy. The test is portable, validated on both SHA-1 and SHA-256 repositories, and already integrated into Microsoft Git to fix the same performance issue.

The implementation is clean and minimal: it splits the existing loop into two sequential loops (packfiles first, then loose objects) without introducing new flags or complexity. The patch touches only `odb/source-files.c` and the new test file, with no behavior changes or on-disk format modifications. Reviewer feedback from v2 (notably Johannes Schindelin’s request for test coverage) is fully addressed, and the patch has received substantive, tested review from Justin Tobler. This is a well-motivated, thoroughly vetted performance fix that fits neatly into the broader ODB abstraction effort.
