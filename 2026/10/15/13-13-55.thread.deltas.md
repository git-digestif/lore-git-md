## 2026/10/24

- [2026/10/24/13-51-13 by Phillip Wood <phillip.wood123@gmail.com>] Phillip Wood is skeptical of `--operations` in its current form: not all working-tree-modifying commands update the reflog, and commands like `git cherry-pick A B C` create multiple reflog entries indistinguishable from multiple invocations of a single command, so the option should not pretend to show one entry per command; he is not opposed to filtering/simplification for HEAD, noting most of it can be achieved by looking at the branch reflog. He likes `--historical-branch` but would prefer it implemented as a format specifier (`%gb`) usable in custom formats, and would be happy to change the default HEAD format to include the branch name. He adds that accurate branch names require supporting `git rebase <upstream> <branch>`, which is involved because the branch being rebased (in the "(finish)" message) must be compared to the previously checked-out branch, with extra cases for detached-HEAD and up-to-date rebases; he has a patch fixing this for `@{-N}` that he thinks works but needs more tests.
- [2026/10/24/15-22-28 by D. Ben Knoble <ben.knoble@gmail.com>] D. Ben Knoble agrees with Phillip Wood that parsing existing reflogs is inherently heuristic and that the series is not a true operations log; he concurs on not pretending `--operations` shows one entry per command. He is more positive on `--historical-branch` and likes the composability of a format specifier, and suggests that a structured event/ops log might be simpler than investing in reflog parsing for this purpose.
- [2026/10/24/16-40-05 by Junio C Hamano <gitster@pobox.com>] Junio C Hamano likes the direction of making the default `git reflog` output on a single branch easier to understand without extra filtering, and discusses teaching multi-step commands like `git am` (and multiple `git cherry-pick`) to work on a detached HEAD like `git rebase` does, so branch reflogs record one iteration per entry; he also notes that using `@{0}`/`@{now}` refers to the current branch, which resolved his old annoyance at `git reflog` defaulting to HEAD.
- [2026/10/24/18-46-28 by Harald Nordgren <haraldnordgren@gmail.com>] Harald Nordgren says he had not realized `git reflog` could operate on a single branch, thinks that should be the default, and observes that the branch-reflog format is heavy with full-name references (showing example output) that could be cleaned up.
