This is a test fix targeting the SHA-256 transition effort. The patch repairs a test in `t5004-archive-corner-cases.sh` that verifies Git can handle ZIP archives containing objects larger than 4GB. The test was silently broken in Fedora CI jobs because it assumed a SHA-1 repository but ran in SHA-256 mode once a typo in the job configuration was fixed. Patrick Steinhardt makes the test explicitly create a SHA-1 repository to match the SHA-1 objects in the test archive.

The change is straightforward: the test now runs in a temporary SHA-1 repository instead of the default repository, ensuring the object format matches the test data. The patch is part of a larger CI housekeeping series (this is the first of eight patches in v4) and carries a "Suggested-by" from Jeff King, signaling it has already seen some review. The fix looks well-motivated and uncontroversial; it simply prevents a test failure that would otherwise surface once the CI configuration typo is corrected in the next patch.
