This is a **bugfix patch** targeting the severe performance regression in `git log --stat --follow` that was introduced in Git 2.56 by commit 304813ed33. The patch comes from Miklos Vajna, the original author of the problematic commit, and directly addresses the bottleneck identified in the thread: the quadratic behavior of `propagate_follow_pathspec_to_parent()` when processing merge commits.

The patch introduces two key optimizations. First, it skips expensive rename detection when the followed path is not newly added relative to a parent. Second, if the path exists unchanged in any parent, it follows that parent’s history without further diffing. These changes restore performance to near pre-regression levels (29 seconds versus the original 28 seconds in the Linux kernel test case) while preserving all existing test coverage in `t4219-log-follow-merge.sh`.

The implementation is clean and focused: it adds a new helper function `get_follow_path_change()` to classify how the followed path differs between a commit and its parent, and refactors the parent-traversal logic into `propagate_follow_pathspec_to_parents()` to apply the shortcuts. The patch touches only `log-tree.c` and does not change any on-disk formats or public interfaces.

Miklos frames this as a targeted fix rather than a fundamental redesign, and the benchmarks provided in the commit message suggest the optimizations are effective. The patch is still under review by SZEDER Gábor and Patrick Steinhardt, but if no issues surface it is likely to be sent to Junio soon. For anyone affected by the regression, this looks like a promising resolution.
