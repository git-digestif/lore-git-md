This is the second patch in Patrick Steinhardt’s six-patch v3 series refactoring and optimizing alternates handling in Git’s object database (ODB) "files" backend. It applies the same performance optimization introduced in patch 1/6 to the object streaming code path.

The patch modifies `odb_source_files_read_object_stream()` in `odb/source-files.c` to check all packfiles across alternates before checking any loose objects, mirroring the change in `odb_source_files_read_object_info()`. The rationale is consistency: both functions now follow the same order of operations, avoiding unnecessary `stat()` syscalls when objects exist in alternate packfiles. While the performance impact for streaming is expected to be smaller (since large object reads likely dominate `stat()` overhead), the change ensures uniform behavior across the ODB’s read and stream interfaces.

The diff is minimal: four lines changed, two lines added. It splits the original loop into two separate loops—one for packfiles, one for loose objects—with an early return if a packfile match is found. This matches the structure introduced in patch 1/6 and aligns with the series’ broader goal of simplifying the ODB source API.

No new test coverage is added here; the existing regression test (`t/t5615-alternate-env.sh`) introduced in patch 1/6 indirectly verifies this change by ensuring objects in alternate packfiles are prioritized. The patch is part of the ODB abstraction effort and builds on the alternates migration work in Patrick’s `ps/odb-files-alternates` branch.
