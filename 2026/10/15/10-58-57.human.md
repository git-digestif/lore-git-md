This is the first patch in Isabella Caselli’s three-part series implementing `includeIf.hostname:<pattern>` in Git’s configuration system. It adds a new `git var GIT_HOSTNAME` command, which lets users see the hostname Git detects—critical for debugging and writing correct `includeIf.hostname` rules later in the series.

The patch is small and focused: it extends `builtin/var.c` to call `xgethostname()`, adds a minimal test in `t/t0007-git-var.sh` that verifies the output is non-empty, and documents the new variable in `git-var.adoc`. The implementation handles errors gracefully—if the hostname can’t be determined, `git var GIT_HOSTNAME` exits non-zero and `git var -l` omits the variable rather than failing.

This directly addresses feedback from Eric Sunshine and Jeff King during the RFC phase, who both suggested exposing the hostname via `git var` rather than a config-specific command. The choice keeps the interface general and avoids tying the hostname to configuration logic. The test is intentionally minimal because the expected value is system-dependent; later patches in the series will verify that the hostname matches what the configuration code actually uses.

The patch is uncontroversial and well-motivated. It’s a necessary building block for the rest of the series, and the implementation is clean and follows established patterns. No substantive objections are expected.
