This thread introduces two new options to `git reflog` and `git log -g` to improve usability: `--operations` and `--historical-branch`. The series, now complete with its third patch, is authored by Harald Nordgren and is under review as version 1.

The `--operations` option (added in patch 2) collapses intermediate reflog entries from multi-step operations like rebase or checkout into single entries representing the actual commands executed. The newly added `--historical-branch` option decorates each reflog entry with the branch HEAD was on when the entry was recorded, addressing a long-standing pain point where users had to manually trace back through "checkout: moving from" entries to determine branch context. Both options require `--walk-reflogs` to be set and are designed to work together.

The implementation touches core reflog-walking logic, output formatting, and documentation, with thorough test coverage for edge cases like detached HEAD, branch renames, and interaction with existing options. The series is well-motivated by prior mailing-list discussion and appears technically sound, though the UX trade-offs of replacing standard decorations with historical branch names may spark discussion. No reviews have been posted yet, so the series is awaiting initial feedback.
