This thread is about a patch series from Harald Nordgren that adds two new options to `git reflog` and `git log -g`: `--operations` (collapsing multi-step operations like rebase into single entries) and `--historical-branch` (showing which branch HEAD was on when each reflog entry was recorded). The series is now at v2, addressing prior feedback on commit message clarity and output formatting.

The key debate centers on the first patch, a preparatory refactoring that replaces hard-coded reflog message strings with `#define` constants. Junio C Hamano raised an architectural concern: this refactoring touches the same code paths that would need to emit machine-readable markers in a future structured reflog format, potentially complicating that work. Harald pushed back lightly, arguing existing tests would catch any breakage, but Junio’s broader concern remains unresolved. Junio later accepted Harald’s position on test coverage, but the architectural question lingers.

Other participants have weighed in on the user-facing value. Kristoffer Haugsbakk endorsed the problem statement, describing real-world pain points like tracking reset points during rebasing, though he also noted `tig reflog` as an alternative. D. Ben Knoble suggested `git log -g -p` as another way to track reset points and provided feedback on output formatting, which Harald incorporated in v2. The series touches 23 files, including `reflog-walk.c`, `revision.c`, and a new 293-line test script, with no on-disk format changes. The options are additive and require `--walk-reflogs`.

The series is still under review, with the architectural debate unresolved. The user-facing improvements are compelling, but the long-term implications of the refactoring remain a sticking point. No maintainer decisions or merge status have been reported.
