This thread is about a patch series by Harald Nordgren that adds a `%gb` format placeholder to `git log -g` and `git reflog`, allowing users to see branch context in reflog output. The series has evolved through three versions, with v3 replacing earlier dedicated flags (`--operations` and `--historical-branch`) with a composable format specifier, addressing prior feedback about correctness and usability.

Key participants include Harald (the author), Junio C Hamano (the maintainer), Phillip Wood (who raised critical correctness concerns in v2), and D. Ben Knoble and Kristoffer Haugsbakk (who provided substantive reviews). The v3 series is now split into two patches: a preparatory refactoring of reflog message strings and the `%gb` implementation itself. It handles edge cases like rebases, branch renames, and detached HEAD states, and is additive—users must opt into the new format to see branch context.

The series is under review, with all prior technical feedback addressed, but broader architectural questions remain unresolved. Junio proposed two major changes in v2—refactoring multi-step commands to work on detached HEAD by default and changing `git reflog`’s default behavior—but the v3 series does not engage with these. D. Ben Knoble’s recent reply observes that users already tolerate detached HEAD during rebase without significant confusion, suggesting similar changes for commands like `git cherry-pick` might be less disruptive than feared. However, no consensus has emerged, and Junio has not yet reviewed v3. The series is ready for maintainer feedback, but its long-term viability depends on whether Junio accepts the narrower `%gb` approach or pushes for broader changes.
