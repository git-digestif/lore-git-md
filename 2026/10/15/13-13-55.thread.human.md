Harald Nordgren’s patch series adding `--operations` and `--historical-branch` options to `git reflog` and `git log -g` is still under review, now at version 2. The series aims to address long-standing usability pain points: `--operations` collapses intermediate reflog entries from multi-step operations like rebase or checkout into single entries showing the actual commands executed, while `--historical-branch` decorates each reflog entry with the branch HEAD was on when it was recorded, making it easier to trace branch context without manually parsing "checkout: moving from" messages.

The v2 update incorporated feedback on commit message clarity and output formatting—branch names now appear in parentheses after the operation description, preserving column alignment. The series touches core reflog-walking code, adds new flags and fields to internal structs, and includes thorough test coverage for edge cases like branch renames and detached HEAD. However, the architectural debate continues: reviewers Kristoffer Haugsbakk and D. Ben Knoble have pointed out that tools like `tig reflog` and `git log -g -p` already mitigate some of these pain points, raising questions about whether the reflog subsystem is the right place for this functionality. The UX trade-off of replacing standard commit decorations with historical branch names also remains unresolved.

Harald has framed the series as complementary to third-party tools, but so far this hasn’t settled the discussion. The thread is still waiting for broader review or a maintainer decision—no merge status has been reported, and the open questions about scope and design trade-offs are still on the table.
