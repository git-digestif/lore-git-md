This thread began as a patch series to improve `git reflog` usability by adding a `%gb` format placeholder to show branch context in reflog output, replacing earlier proposals for dedicated `--operations` and `--historical-branch` flags. The v3 series, now under review, implements `%gb` as a composable format specifier that handles edge cases like rebases, branch renames, and detached HEAD states without altering default behavior. Harald Nordgren addressed all prior feedback, including Phillip Wood’s correctness concerns about `git rebase <upstream> <branch>` and UX trade-offs around composability with decorations.

The discussion has since expanded to broader architectural questions raised by Junio C Hamano: whether multi-step commands like `git rebase` should default to detached HEAD, and whether `git reflog` should operate on the current branch by default. Junio reasserted his preference for Git’s current design, dismissing observations that even his own workflow (e.g., detaching HEAD during `git am`) relies on workarounds. D. Ben Knoble countered that users may already tolerate detached HEAD during rebases without significant confusion, and Harald Nordgren’s latest reply endorses this view, pivoting to a narrower proposal: making `git reflog @{0}` (the most recent reflog entry) the default output to address obscurity. This suggestion is additive and untriaged, with no patches or maintainer feedback yet. The v3 series remains ready for review, but Junio has not engaged with the `%gb` feature or the broader debate, leaving both the targeted improvement and architectural questions unresolved.
