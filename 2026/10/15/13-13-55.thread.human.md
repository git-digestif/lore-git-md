This thread introduces two new options to `git reflog` and `git log -g`—`--operations` and `--historical-branch`—aimed at improving usability by collapsing multi-step operations into single entries and showing the branch context for each reflog entry. The series, now at v1, is under review and addresses long-standing pain points where users must manually trace reflog entries to understand branch history or operation boundaries.

Harald Nordgren, the author, has structured the series into three patches: a preparatory refactoring (patch 1/3), the `--operations` implementation (patch 2/3), and the `--historical-branch` feature (patch 3/3). The changes touch 23 files, including core reflog-walking logic, documentation, and a new 293-line test script. The options are additive and require `--walk-reflogs` to function, with no on-disk format changes. Kristoffer Haugsbakk, the primary reviewer, has raised two key points: a substantive request to revise the commit message of patch 1/3 to better explain its motivation, and a broader architectural question about whether Git’s core commands should replicate functionality already available in tools like `tig`. Harald has acknowledged the commit message feedback but has not yet posted a v2 or addressed the scope debate.

The thread remains open, with the next step likely being a revised v2 incorporating the commit message improvements. The architectural question—whether these features belong in Git’s core or should be left to external tools—has not been resolved, and broader community feedback is still limited. For now, the series is stalled on the commit message rewrite, but the proposed features address real usability challenges described by both the author and reviewer.
