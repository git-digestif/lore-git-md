This thread is about a patch series (v3) by Harald Nordgren that adds a `%gb` format placeholder to `git log -g` and `git reflog`, allowing users to see which branch `HEAD` was on for each reflog entry. The series is a redesign of earlier versions that proposed dedicated `--operations` and `--historical-branch` flags, addressing prior feedback by adopting a composable format specifier that aligns with Git’s decoration system.

The v3 series is now split into two patches: the first refactors hard-coded reflog message strings into `#define` constants to support future changes (e.g., translatable messages), while the second implements the `%gb` placeholder itself. The new functionality handles edge cases like rebases, branch renames, and detached HEAD states, and includes thorough test coverage. Key reviewers—Phillip Wood, D. Ben Knoble, and Kristoffer Haugsbakk—had raised concerns in earlier versions about correctness (e.g., `git rebase <upstream> <branch>`) and UX trade-offs; these are now addressed by the `%gb` implementation. Junio C Hamano, the maintainer, had also questioned the alignment of the earlier refactoring with potential future directions (e.g., machine-readable reflog messages), but the v3 refactoring explicitly ties the changes to the `%gb` feature, making the strings easier to modify later.

The series is under review and does not alter default behavior, reducing regression risk. However, broader architectural questions remain unresolved, such as Junio’s proposals to refactor multi-step commands to work on detached HEAD by default or change `git reflog`’s default behavior to operate on the current branch. Harald has not engaged with these proposals in v3, focusing instead on the targeted improvement. The feature’s long-term viability may depend on maintainer approval, but the current implementation is ready for review.
