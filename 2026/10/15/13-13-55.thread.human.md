This thread introduces two new options for `git reflog` and `git log -g`—`--operations` and `--historical-branch`—aimed at improving usability by collapsing multi-step operations into single entries and showing the branch context for each reflog entry. The series, authored by Harald Nordgren, is currently under review in its first version, with no maintainer decisions yet.

The patches touch 23 files, including core reflog-walking logic, revision handling, and documentation, while adding new test coverage for edge cases like rebases, branch renames, and detached HEAD states. The `--operations` option simplifies sequences like rebases into single entries, and `--historical-branch` replaces standard commit decorations with the branch name at the time of the entry, addressing a long-standing pain point for users tracing branch history.

Feedback has highlighted a few open issues. Kristoffer Haugsbakk raised a substantive concern about the commit message for the preparatory refactoring (patch 1/3), arguing it lacks clear motivation upfront—a blocker for maintainer acceptance. Ben Knoble later pointed out a formatting issue with `--historical-branch`, where the branch name decoration disrupts the fixed-width alignment of the `HEAD@{n}` column, suggesting alternative placements. The thread has also debated whether these features belong in Git’s core or overlap with existing tools like `tig` and `git log -g -p`, though Harald has positioned them as complementary. No revised version has been posted yet, leaving these points unresolved.
