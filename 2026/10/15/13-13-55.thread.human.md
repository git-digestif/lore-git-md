This thread is about a patch series by Harald Nordgren that adds a `%gb` format placeholder to `git log -g` and `git reflog`, allowing users to see branch context in reflog output. The series is now at version 4, which fixes a regression in branch-name detection when `GIT_REFLOG_ACTION` is set and refactors hard-coded reflog message strings into named constants for better maintainability.

The core idea is to replace earlier proposals for dedicated flags (`--operations` and `--historical-branch`) with a composable format specifier that aligns with Git’s decoration system. The `%gb` placeholder names the branch for each reflog entry, handling edge cases like rebases, detached HEAD states, and branch renames. The series is additive and does not alter default behavior—users can include `%gb` in custom formats without losing other decorations.

Key participants include Harald Nordgren (the author), Junio C Hamano (the maintainer), Phillip Wood (who identified the regression fixed in v4), and D. Ben Knoble (who engaged with Junio’s broader architectural proposals). Phillip’s feedback was particularly actionable, leading to the regression fix in v4. Junio has not yet reviewed v4, and the broader architectural debate—whether to refactor multi-step commands to work on detached HEAD by default or change `git reflog`’s default behavior—remains unresolved. Harald also proposed making `git reflog @{0}` the default output, but this idea is untriaged and separate from the `%gb` series.

The series is under review, with no maintainer decisions or merge status reported. The expanded test suite now covers the regression fix, and the refactoring in patch 1/2 addresses Junio’s earlier concern about future translatability of reflog messages. The next step is likely Junio’s review of v4.
