This thread introduces a new feature for `git reflog` and `git log -g` to improve usability by making reflog output more readable. Harald Nordgren has proposed two new options: `--operations`, which collapses intermediate reflog entries from multi-step operations like rebases into single entries showing the actual commands executed, and `--historical-branch`, which shows which branch HEAD was on when each entry was recorded.

The series is currently under review as version 1, with no prior iterations. The second patch, implementing `--operations`, has just been posted. It refactors reflog-walking logic to identify and mark entries that should be shown or hidden, such as collapsing rebase sequences into a single "rebase (finish)" entry while omitting intermediate steps. The implementation is additive, requiring `--walk-reflogs` to be set, which prevents accidental misuse and avoids changing default behavior. The patch includes thorough test coverage for edge cases like stopped or aborted rebases, `git stash`, and `git pull --rebase`.

So far, no review feedback has been posted, so the series is still awaiting input from the community. The feature addresses a well-documented usability pain point, making reflogs more useful for debugging or auditing workflows by reducing noise and surfacing the actual commands executed. If the implementation holds up under review, this could be a welcome addition for users who rely on reflogs.
