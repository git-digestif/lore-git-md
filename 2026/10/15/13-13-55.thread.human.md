This thread is about improving `git reflog` usability by adding options to expose branch context and operation boundaries in its output. Harald Nordgren initially proposed dedicated flags (`--operations` and `--historical-branch`), but the discussion has shifted toward using format specifiers (e.g., `%gb`) for better composability with Git’s existing decoration system. The series is now at a crossroads due to substantive critiques from Phillip Wood, who identified fundamental flaws in both flags, including incomplete reflog coverage and correctness gaps in handling rebases.

The latest exchange centers on Junio C Hamano’s broader architectural proposal: refactoring multi-step commands like `git cherry-pick` and `git am` to work on detached HEAD by default, which would naturally produce cleaner reflog entries. Phillip Wood responded pragmatically, acknowledging the potential benefits but flagging user confusion as a concern, particularly for `git cherry-pick`. He suggests updating `git status` to clarify detached HEAD states if this change is adopted. Meanwhile, the original series remains under review, with no maintainer decisions or merge status reported. The community now favors replacing the dedicated flags with format specifiers, but no alternative patches have been posted yet.
