This thread is about a patch series by Harald Nordgren that adds a `%gb` format placeholder to `git log -g` and `git reflog`, letting users see which branch each reflog entry belongs to. The goal is to make it easier to track branch history, especially after resets or rebases, without changing the default output. The series is now at version 4, which fixes a regression in branch-name detection when `GIT_REFLOG_ACTION` is set and refactors hard-coded reflog message strings into named constants.

The latest update is a brief acknowledgment from Harald of Phillip Wood’s detailed review, which identified two remaining correctness issues: detached HEAD entries are mislabeled with the wrong commit, and the rebase checkout parsing logic is fragile, mistaking remote branches for local ones and getting confused by commit subjects that start with "checkout". Phillip also provided a failing test case that covers these issues and a `GIT_REFLOG_ACTION` edge case. Harald hasn’t yet addressed these problems, so the series isn’t ready to merge. Junio Hamano, the maintainer, hasn’t reviewed version 4, and the broader architectural questions he raised earlier—like whether multi-step commands should work on detached HEAD by default—remain unresolved. Harald’s separate proposal to make `git reflog @{0}` the default output is also still untouched.

The series is additive and doesn’t change existing behavior, but it needs to fix the correctness issues Phillip pointed out before it can move forward. The expanded test suite now covers the regression fix and edge cases, but the two remaining problems must be resolved in a future version. No other reviewers have weighed in on this latest exchange.
