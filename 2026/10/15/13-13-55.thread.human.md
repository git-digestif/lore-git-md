This thread introduces two new options to `git reflog` and `git log -g`—`--operations` and `--historical-branch`—aimed at improving usability by collapsing multi-step operations into single entries and showing the branch context for each reflog entry. The series, authored by Harald Nordgren, is currently at v1 and under review, with no maintainer decisions yet.

The patches touch 23 files, including core reflog-walking logic, revision handling, and new test coverage. The `--operations` option simplifies sequences like rebases or checkouts into single entries, while `--historical-branch` decorates entries with the branch name at the time of recording, addressing a long-standing pain point where users must manually trace branch context. The implementation avoids on-disk format changes but introduces new internal flags and constants to track operations and branch history.

Feedback has focused on two key areas: the clarity of the commit message for the preparatory refactoring (patch 1/3), which Kristoffer Haugsbakk flagged as needing a clearer motivation, and broader questions about whether the reflog subsystem is the right place for this functionality. Haugsbakk also noted that tools like `tig reflog` already mitigate some of these usability issues, raising architectural concerns about duplicating functionality. Harald has acknowledged the commit message feedback and intends to revise it, but no v2 has been posted yet. D. Ben Knoble’s recent reply suggested that `git log -g -p` might already address some of the pain points, though this was framed as a friendly observation rather than a critique.

The thread remains open, with the main unresolved questions being the commit message revision, the trade-off between usability and backward compatibility (e.g., `--historical-branch` replacing standard decorations), and whether the proposed features overlap with existing tooling. No maintainer signals or merge status updates have been reported.
