This thread is about a patch series by Harald Nordgren that adds a `%gb` format placeholder to `git log -g` and `git reflog`, allowing users to see branch context in reflog output. The series has evolved through three versions, with v3 abandoning earlier dedicated flags (`--operations` and `--historical-branch`) in favor of a composable format specifier that aligns with Git’s decoration system. The goal is to address usability pain points like tracking branch history across renames or obscured reset points during rebasing, without changing default behavior.

Key participants include Harald Nordgren (the author), Junio C Hamano (the maintainer), Phillip Wood, D. Ben Knoble, and Kristoffer Haugsbakk. Phillip Wood’s review of v2 raised critical concerns about correctness and UX, particularly around handling edge cases like `git rebase <upstream> <branch>` and the limitations of dedicated flags. The v3 series addresses these by implementing `%gb`, which parses reflog messages to show the branch name for each entry, including edge cases and detached HEAD states. Junio’s feedback on v2 focused on broader architectural questions—like refactoring multi-step commands to work on detached HEAD by default and changing `git reflog`’s default behavior—but the v3 series does not engage with these, instead offering a targeted improvement.

The series is currently under review, with v3 posted as a two-patch redesign: one refactoring hard-coded reflog message strings into `#define` constants (to support future changes like translatable messages), and another implementing `%gb`. No maintainer decision has been made, and Junio’s latest reply to D. Ben Knoble reasserts his preference for Git’s current design without addressing the v3 series. The broader architectural debate remains unresolved, though the v3 implementation is ready for review and addresses all prior technical feedback. Real-world validation from the broader community is still pending.
