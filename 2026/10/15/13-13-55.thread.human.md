This thread is about a patch series (v4) by Harald Nordgren that adds a `%gb` format placeholder to `git log -g` and `git reflog`, allowing users to see the branch context for each reflog entry. The series aims to solve usability pain points like tracking reset points during rebasing or branch history across renames, without changing default behavior. After earlier proposals for dedicated flags (`--operations` and `--historical-branch`) were critiqued, the series now uses a composable format specifier (`%gb`) that aligns with Git’s decoration system.

The v4 update fixes a regression in branch-name detection when `GIT_REFLOG_ACTION` is set and consolidates hard-coded reflog message strings into named constants. However, Phillip Wood’s latest review identifies two remaining correctness issues: (1) detached HEAD entries are mislabeled, showing the commit *before* switching away rather than where HEAD was originally detached, and (2) the rebase checkout parsing logic is fragile, mistaking remote branch names or commit subjects for local branches. Phillip provides a failing test case to validate these issues, which the series will need to address.

Key participants include Harald (the author), Junio C Hamano (the maintainer, who has not yet reviewed v4 but raised architectural concerns in v2), Phillip Wood (who identified the regression fixed in v4 and now these new issues), and D. Ben Knoble (who engaged with Junio’s broader proposals about detached HEAD behavior). The series is under active review, with no merge decisions yet. A separate, untriaged proposal by Harald—to make `git reflog @{0}` the default output—remains unaddressed. The thread’s focus is now on fixing the correctness issues Phillip raised before further maintainer feedback.
