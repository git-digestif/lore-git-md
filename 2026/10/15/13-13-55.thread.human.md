Harald Nordgren’s patch series adding `--operations` and `--historical-branch` options to `git reflog` and `git log -g` is now in its second iteration, with v2 addressing prior feedback on commit message clarity and output formatting. The series aims to simplify tracking multi-step operations (like rebases) and show which branch HEAD was on when each reflog entry was recorded—two common pain points for users who currently rely on manual inspection or external tools.

The v2 patches are functionally complete, touching over 20 files across the reflog, revision, and built-in command subsystems, and include a 293-line test script covering edge cases like branch renames and detached HEAD. While the implementation is ready for review, the thread’s broader question remains unresolved: whether this functionality belongs in Git’s core or is better left to tools like `tig` or `git log -g -p`. Kristoffer Haugsbakk and D. Ben Knoble have raised this architectural concern, though their feedback so far has focused on usability trade-offs rather than technical objections. Harald’s latest email is a simple nudge for review, leaving the design debate open for now. No maintainer decisions or merge status have been reported.
