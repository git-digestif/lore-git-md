This thread introduces two new options for `git reflog` and `git log -g`—`--operations` and `--historical-branch`—aimed at improving usability by collapsing multi-step operations into single entries and showing the branch context for each reflog entry. The series, now at v1, is under review with no maintainer decisions yet.

Harald Nordgren has acknowledged feedback from Kristoffer Haugsbakk on the commit message for the preparatory refactoring (patch 1/3) and from D. Ben Knoble on the output formatting of `--historical-branch`. In his latest reply, Nordgren agrees to Knoble’s suggestion to place the branch name in parentheses immediately after the operation description (e.g., `(topic) commit: add tests`), preserving alignment of the `HEAD@{n}` column while keeping the branch context visually integrated. This resolves one of the two open usability concerns, though the broader architectural question—whether this functionality belongs in Git’s core or overlaps with external tools like `tig`—remains unaddressed.

The series touches 23 files, including `reflog-walk.c`, `revision.c`, and a new 293-line test script, with no on-disk format changes. Key internal changes include refactoring reflog entry markers into constants and adding flags to track user operations and historical branch context. While the feature has been validated by Nordgren and Haugsbakk as addressing real-world pain points (e.g., tracking reset points during rebasing), the discussion has also highlighted alternatives like `tig reflog` and `git log -g -p`, which may influence the maintainer’s view on the feature’s scope. No v2 has been posted yet.
