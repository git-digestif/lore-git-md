This thread is about a patch series (v4) by Harald Nordgren that adds a `%gb` format placeholder to `git log -g` and `git reflog`, letting users see which branch each reflog entry belongs to. The goal is to make it easier to track branch history across renames or rebases without changing default behavior. The series has evolved from earlier proposals for dedicated flags (`--operations` and `--historical-branch`) to this more flexible format specifier, addressing prior critiques about correctness and usability.

The v4 series is now split into three patches: one refactors hard-coded reflog message strings into named constants, another implements the `%gb` placeholder (including a fix for a regression where `GIT_REFLOG_ACTION` broke branch detection), and the third consolidates the refactoring. The test suite has grown significantly to cover edge cases like rebases, branch renames, and detached HEAD states. All prior feedback has been addressed, including Phillip Wood’s review identifying the regression, and the series is ready for maintainer review. Junio C Hamano has not yet commented on v4, though his earlier reviews raised broader architectural questions—like whether reflog messages should be translatable or if `git reflog` should default to the current branch—which remain unresolved.

Key participants include Harald (the author), Phillip Wood (who provided substantive reviews and identified the regression), and D. Ben Knoble (who endorsed the format-specifier approach). Kristoffer Haugsbakk and Patrick Steinhardt have also weighed in on the real-world value of the feature. While the `%gb` implementation is now technically sound, the thread also touches on two untriaged proposals: Harald’s suggestion to make `git reflog @{0}` the default output (citing usability concerns) and Junio’s broader ideas about refactoring multi-step commands to work on detached HEAD by default. Neither has gained traction, and the current series focuses solely on the `%gb` placeholder.
