This is the second patch in Harald Nordgren’s three-patch series introducing `--operations` and `--historical-branch` options to `git reflog` and `git log -g`. It implements the `--operations` option, which collapses multi-step operations like rebases into single reflog entries representing the actual commands executed, while omitting entries that don’t change the branch (e.g., branch switches or the "reset: moving to HEAD" left by `git stash`).

The patch touches seven files: `reflog-walk.c` (core logic), `revision.c`/`revision.h` (option plumbing), documentation updates, and a new test script (`t/t1414-reflog-walk.sh`) with 105 lines of test coverage for the new behavior. The implementation adds a `user_operation` flag to reflog entries and a `mark_operations()` function that scans the reflog to identify and mark entries that should be shown (e.g., rebase finish/abort steps) or hidden (e.g., intermediate rebase steps or branch switches). The option is additive and requires `--walk-reflogs` to be set, preventing accidental misuse.

The motivation is clear: reflogs currently show every intermediate step of operations like rebases, making it difficult to see the actual commands executed. The patch addresses this by collapsing sequences into single entries (e.g., "rebase (finish): returning to refs/heads/topic") while preserving the original `HEAD@{<n>}` numbering, so users can still use `git reset --hard HEAD@{7}` to undo the operation. The test coverage is thorough, validating edge cases like stopped rebases, aborted rebases, `git stash`, and `git pull --rebase`.

The implementation looks well-scoped and avoids broad refactoring, focusing instead on the reflog-walking logic. The new option doesn’t change default behavior, reducing regression risk. The patch is part of a v1 series, so review feedback may still shape the final form, but the foundation appears solid. This is likely to be of interest to users who rely on reflogs for debugging or auditing workflows, as it directly addresses a long-standing usability pain point.
