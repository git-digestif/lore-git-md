This is the v7 iteration of a feature patch adding revision-based filtering to the `git repo structure` command. The patch is now procedurally clean and ready for merging to `next`, with no substantive changes since v6—only a one-word commit message fix ("standard the standard" → "the standard") addressing the final nit from Kristoffer Haugsbakk.

The feature allows users to analyze specific subsets of the repository object graph by specifying revisions (commits, refs, or ranges) to include or exclude, improving diagnostic capabilities for large repositories. For example, `git repo structure --branches --not --tags` processes only objects reachable from branches but not from tags. The implementation uses Git’s standard `setup_revisions()` machinery, replacing the earlier `--no-<reftype>` approach with a design consistent with Git’s revision-parsing idioms. The patch touches `builtin/repo.c`, updates `Documentation/git-repo.adoc` to clarify terminology and examples, and expands test coverage in `t/t1901-repo-structure.sh` to 197 lines, validating edge cases like overlapping includes/excludes and output formats.

The author acknowledges an awkward trade-off in the implementation: due to `setup_revisions()`’s lack of a custom ref-walk callback, the patch performs a second ref-walk in `count_references()` to count references by type. This inefficiency is considered tolerable for a diagnostic tool, and the workaround is clearly documented in the commit message. The revision-parsing defaults (`.def = "HEAD"` and `.revarg_opt = REVARG_COMMITTISH`) are retained to avoid breakage in empty repositories, though Patrick Steinhardt’s proposal to pass `NULL` to `setup_revisions()` for broader filtering remains unaddressed.
