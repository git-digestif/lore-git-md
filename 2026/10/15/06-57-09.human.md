This is a CI/build system patch series from Patrick Steinhardt, now in its fourth iteration. The series modernizes Git's CI configurations by updating EOL Docker images, removing obsolete jobs, and simplifying supporting scripts. All substantive technical concerns from earlier versions have been resolved, and the series is now uncontested and ready for integration.

The most notable change in v4 is a rewrite of the first patch, which now makes the test in `t/t5004-archive-corner-cases.sh` work with both SHA-1 and SHA-256 repositories by explicitly forcing the test repository to use SHA-1. This replaces the v3 approach of skipping the test in SHA-256 repositories and addresses Jeff King's feedback about making the test self-contained. The new implementation is cleaner and more robust, though it still requires the `SHA1` prerequisite to run in CI.

Other changes from v3 are purely mechanical: the `linux-TEST-vars` job is renamed to `linux-feature-testbed` (resolving a naming dispute), the `linux-reftable-leaks` job is repurposed as `linux-reftable-sha256` to test reftable with SHA-256, and the 32-bit job now uses `i386/debian:latest` instead of the unsupported `i386/ubuntu:20.04` image. Python 2 coverage is removed entirely, and the `linux-feature-testbed` job now uses `ubuntu:latest` with the system-provided GCC version.

The series touches CI configurations (GitHub Actions and GitLab CI), supporting scripts (`ci/install-dependencies.sh`, `ci/lib.sh`, `ci/run-build-and-tests.sh`), and one test file (`t/t5004-archive-corner-cases.sh`). Key symbols include job names (`linux-feature-testbed`, `linux-reftable-sha256`), Docker images (`i386/debian:latest`, `ubuntu:latest`), and the `WITH_BREAKING_CHANGES` flag in `ci/run-build-and-tests.sh`. The net effect is a reduction in CI complexity (43 insertions, 56 deletions) while maintaining or improving test coverage.
