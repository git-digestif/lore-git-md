This is a documentation patch that rewrites Git’s explanation of detached HEAD state. The author, Julia Evans, has posted the third version of a standalone patch that addresses all feedback from earlier rounds. The new text is shorter, more practical, and moves the explanation into a dedicated guide (`gitdetached-head(7)`) so it can be referenced directly from Git’s advice messages.

The rewrite focuses on four key improvements: explaining *why* detached HEAD is useful (e.g., for testing commits or browsing history), defining the concept upfront, clarifying how users might end up in this state accidentally, and removing overly complex diagrams. The new framing—borrowed from Steve Klabnik’s Jujutsu tutorial—describes detached HEAD commits as "garbage" that Git may eventually delete, which helps users understand why recovery is important. It also highlights the 2019 UI improvement in `git switch` that makes accidental detachment harder, a detail previously missing from the docs.

Changes in this version are minor but precise: the reflog expiry period is now correctly stated as 30 days (the default for `gc.reflogExpireUnreachable`), the help command uses hyphenated `git help detached-head`, and the text avoids implying that detached HEAD is the *only* way to view old commits. The patch is self-contained, touching only documentation files (`git-checkout.adoc`, `detached-head.adoc`, `gitdetached-head.adoc`), build system files (`Makefile`, `meson.build`), and the advice message in `advice.c`. No tests are added, as this is documentation-only.

The patch has addressed all review feedback from Junio C Hamano and Kristoffer Haugsbakk, including build system omissions, textual refinements, and naming conventions. The broader usability concern about Git’s help system (the mismatch between internal man page cross-references like `git-config(1)` and the `git help config` command) remains noted but is not a blocker. Julia Evans plans to follow up with a separate patch to hyphenate `gitmergeconflicts` for consistency.

This looks like a well-crafted, user-centric improvement. The new explanation is clearer and more actionable, and the standalone guide makes the information easier to find. The patch is ready for merging unless new substantive feedback emerges.
