This is a **bugfix patch review** targeting the severe performance regression in `git log --follow` introduced by commit 304813ed33. Junio C Hamano, the maintainer, responds to Miklos Vajna’s proposed fix with a detailed technical critique and an alternative architectural suggestion.

Junio identifies the root issue: the current implementation calls `propagate_follow_pathspec_to_parent()` *after* `log_tree_diff()` has already flushed its output, losing the critical information about whether the followed path existed in the parent. This forces the code to re-run expensive rename detection unconditionally for every parent of a merge commit. His proposed solution is to move the rename-following logic *inside* `log_tree_diff_flush()`, where the diff queue is still available, allowing the code to check whether the path appeared anew without redundant diffing.

The review is **substantive**: Junio questions whether the patch’s approach—adding optimizations on top of the existing structure—is the right long-term fix. He suggests that a cleaner solution might involve reverting the original regression-causing commit (304813ed33) entirely and rethinking the rename-following logic from scratch. This reflects a preference for architectural clarity over incremental patching, though he does not outright reject Miklos’s fix.

Key technical details for follow-up discussion include the timing of `propagate_follow_pathspec_to_parent()` (currently too late in the diff pipeline), the potential to leverage the diff queue in `log_tree_diff_flush()`, and the trade-offs between Miklos’s incremental optimizations and a full rewrite. The patch’s current approach—using `get_follow_path_change()` to classify path differences—is not directly criticized, but Junio’s feedback implies it may be solving the wrong problem if the underlying data flow is flawed.

The patch is not yet in any integration branch, and Junio’s response suggests it will need revision before being queued. The thread remains open, with the next steps likely involving Miklos addressing Junio’s architectural concerns or defending the current approach’s correctness and maintainability. For now, the regression is acknowledged, but the fix is not yet settled.
