This thread is about a bugfix that prevents `git rebase` and related commands from crashing when another process (like `git status` or Magit) holds the index lock. The crash leaves rebases in a half-picked state, requiring manual recovery. The patch, now in its second version, has been thoroughly reviewed and is ready for Junio to merge.

Szymon Wilczek authored the fix, which modifies `write_index_as_tree()` in the cache-tree subsystem to avoid blocking on the index lock. Instead, it skips writing the updated cache-tree back to the index but still computes and returns the tree object. The patch includes a test to verify the fix works when `.git/index.lock` exists. Patrick Steinhardt provided a substantive review of the first version, endorsing the technical approach and requesting only minor adjustments to the commit message and a stylistic tweak to the lock-check condition. Those changes were made in v2, and Patrick has now explicitly approved the patch as ready for Junio. No further changes or objections are expected.
