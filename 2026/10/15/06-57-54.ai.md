This is a **substantive review** by Jeff King (Peff) on the second patch of Igor Wiedler’s v2 series, which addresses the root cause of the performance regression in connectivity checks for deepening fetches. Peff engages deeply with the technical rationale and edge cases, endorsing the approach while clarifying some design nuances.

The review focuses on the patch’s handling of alternate refs from shallow or grafted repositories. Peff notes that the patch correctly ignores refs from such alternates (which may lack history behind their refs) but raises a tangential point about **replace refs**, observing that Git generally insists on full connectivity of original objects (e.g., `fsck` ignores replace refs). He doesn’t object to the current implementation but flags this as a conceptual distinction. The discussion of **partial clones** (promisor remotes) is similarly framed as a "weird setup" where punting is reasonable, given the complexity of detecting them via alternate config.

Peff praises the patch’s low-level fix in `odb.c`, which checks for `shallow` or `info/grafts` files in alternates, calling it "a little gross" but necessary due to the lack of a proper repository object for alternates. He confirms the fix works for both connectivity checks *and* advertising alternates for transfer, resolving the issue at its source. The test coverage is deemed sufficient, though Peff muses about constructing a more elaborate test case (e.g., a fetch that corrupts a recipient repo due to shallow alternate refs) but ultimately finds the current test reasonable.

The review is **supportive in principle** and **technically thorough**, though it stops short of an explicit "Reviewed-by" or "Acked-by". Peff’s feedback is more about clarifying design boundaries (e.g., replace refs, partial clones) than requesting changes. The patch remains well-motivated and addresses Junio’s earlier design concern, but the procedural pause (Junio’s reminder about workflow) still blocks progress until Igor responds. No new objections or merge blockers are introduced here.
