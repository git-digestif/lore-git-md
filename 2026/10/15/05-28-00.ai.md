This is the sixth and final patch in Patrick Steinhardt’s v3 series refactoring and optimizing alternates handling in the Git object database’s "files" backend. The patch removes the `local` flag from the generic `struct odb_source` and moves it into the packed source (`struct odb_source_packed`), where it is still needed.

The change is a cleanup that aligns with the series’ broader goal of simplifying the ODB source API after alternates were migrated into the "files" backend. The `local` flag’s original purpose — distinguishing the primary object directory from alternates — no longer makes sense at the generic source level, as alternates are now handled within the "files" backend itself. The patch updates all callers to use the packed source’s `local` field instead, including `midx.c` and `repack.c`, and removes the flag from the generic `odb_source_init()` function.

The diff touches ten files, with most changes being mechanical updates to pass the `local` flag through the packed source rather than the generic one. The in-memory source’s `for_each_object` callback is also updated to reflect that in-memory objects are neither local nor promisor objects, so it returns early when either flag is set. The commit message confirms that the `ODB_FOR_EACH_OBJECT_LOCAL_ONLY` flag’s behavior is preserved, as the "files" backend already handles it by skipping non-local object directories.

This patch is part of a well-reviewed series that has already addressed all substantive feedback, including Justin Tobler’s endorsement of the design and implementation. The unresolved question about the `ODB_FOR_EACH_OBJECT_LOCAL_ONLY` flag’s long-term viability remains, but Patrick has deferred its removal to a follow-up series. The patch itself is uncontroversial and completes the series’ cleanup goals.
