This is a bugfix patch targeting the refs subsystem, specifically the loose-ref iterator logic.

The patch fixes a subtle but real correctness issue in `cache_ref_iterator_seek()`. When seeking through loose refs, the iterator can misposition itself when a directory name shares a prefix with a ref name. For example, given refs `refs/tags/releases-z` and `refs/tags/releases/v1`, seeking after `v1` could incorrectly land on `releases-z` instead of descending into the `releases/` directory, causing `v1` to be returned again when it should not be. The fix ensures directory components are compared with their trailing slash included, preventing this confusion.

The patch also addresses two related positioning edge cases: stopping the search when all entries in a directory precede the cursor, and correctly positioning the iterator when a leaf ref sorts after the cursor even if the cursor has remaining path components.

The patch adds thorough regression tests covering loose, packed, and mixed ref storage backends, testing shared-prefix names, missing nested markers, and markers beyond the end of the ref listing.
