This thread is about a bug in Git's help system where `git help user-manual` fails on Git for Windows because it looks for the wrong filename (`gituser-manual.html` instead of `user-manual.html`). The issue was reported by John Wilson and confirmed to be in upstream Git's help subsystem, not a Git for Windows packaging problem.

The root cause has been identified: the `user-manual` documentation target is missing from the `CAT_guide` category in `command-list.h`, and the `cmd_to_page()` function in `help.c` unconditionally prepends `"git"` to page names that don't already start with it. D. Ben Knoble provided a substantive technical review, proposing two potential fixes: either add `user-manual` to `CAT_guide` or modify `cmd_to_page()` to avoid prefixing `"git"` for known non-command documentation targets.

Junio C Hamano has now weighed in, confirming the issue is reproducible upstream and framing the fix as a straightforward documentation plumbing task. He specifies two necessary changes: (1) add `user-manual` (and any other missing documents) to the list of guides in `command-list.h` so they appear in `git help --guides`, and (2) ensure the installed filenames match what Git expects, possibly retaining old paths for backward compatibility. No patch has been posted yet, but the path forward is clear and uncontroversial. The next step is likely a patch implementing these adjustments.
