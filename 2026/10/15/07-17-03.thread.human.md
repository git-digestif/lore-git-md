This thread is about a bug in Git for Windows where `git help user-manual` fails because the code incorrectly looks for `gituser-manual.html` instead of `user-manual.html`. John Wilson reported the issue, confirming it’s an upstream problem in Git’s help subsystem rather than a Git for Windows packaging error.

D. Ben Knoble has now provided a detailed analysis of the root cause. The issue stems from `cmd_to_page()` in the help code, which prepends `"git"` to documentation page names as a fallback. Since `user-manual` isn’t listed in the `CAT_guide` category in `command-list.h`, the fallback logic kicks in, producing the wrong filename. Knoble suggests two potential fixes: either update the generator to include `user-manual` in `CAT_guide`, or modify `cmd_to_page()` to avoid prefixing `"git"` for known non-command documentation targets. His review is substantive, pinpointing the exact functions and logic involved.

No patch has been posted yet, and it’s still unclear whether other documentation targets (like `git help git` or `git help tutorial`) might be affected by similar issues. The fix will also need to ensure it doesn’t break documentation lookup on non-Windows platforms. So far, only Wilson and Knoble have engaged with the thread.
