This is a feature patch series introducing two new options for `git reflog` and `git log -g`: `--operations` and `--historical-branch`. The goal is to make reflog output more useful by collapsing sequences like rebases into single entries and showing which branch each reflog entry belonged to at the time it was recorded.

The series is motivated by a long-standing pain point: the current reflog output is noisy, listing every intermediate step of operations like rebases or branch switches, which makes it hard to see the actual commands that were run. The new `--operations` option addresses this by showing only the "final" entry of each command (e.g., the commit that finished or aborted a rebase), while `--historical-branch` adds decorations to show the branch name for each entry, even if the branch no longer exists.

The implementation touches 15 files, including core reflog-walking logic (`reflog-walk.c`), documentation, and several built-in commands that generate reflog entries (e.g., `rebase`, `checkout`, `branch`). The changes are focused on plumbing the new options through the revision machinery and ensuring reflog entries are properly annotated with metadata about the operation and branch context. Tests are included in `t/t1414-reflog-walk.sh`.
