This is the third and final patch in Isabella Caselli’s three-patch v2 series implementing `includeIf.hostname:<pattern>` in Git’s configuration system. The patch adds the core logic, documentation, and test coverage for the new `hostname:` condition, completing the feature.

The implementation extends Git’s existing `includeIf` mechanism by introducing a new `hostname:` condition that matches the machine’s hostname against a glob pattern. The hostname is obtained via `xgethostname()` (the same function used by `git var GIT_HOSTNAME`, added in patch 1/3), ensuring consistency across the codebase. Matching is case-sensitive and supports standard glob wildcards, aligning with the behavior of `includeIf.onbranch:`. The commit message and documentation explicitly note that the hostname may be a short name or a fully qualified domain name, depending on system configuration, and that no normalization or DNS lookups are performed. This design choice reflects the 2024 consensus confirmed by Junio and Ignacio Encinas, and the documentation points users to `git var GIT_HOSTNAME` for debugging.

The patch touches `config.c` (adding the `include_by_hostname()` function and condition parsing), `Documentation/config.adoc` (documenting the new condition with examples and caveats), `Documentation/git-var.adoc` (cross-referencing the new condition), and `t/t1305-config-include.sh` (adding two test cases: exact hostname matching and wildcard matching). The tests use `git var GIT_HOSTNAME` to obtain the hostname, ensuring the test and production code agree on the value and avoiding silent failures. The implementation is uncontroversial and directly addresses the use case of sharing dotfiles across multiple machines, where per-host configuration is needed.

Junio’s earlier review described the implementation approach as “neat” and “quite nice,” and Peff’s recent surface-level review confirmed he found no issues. The only remaining technical question is whether hostname matching should be case-sensitive (current behavior), case-insensitive, or support a `hostname/i:` variant, but no proposals or objections have been raised about the matching semantics themselves. The series is now ready for final review, with all prior feedback incorporated and no substantive objections outstanding.
