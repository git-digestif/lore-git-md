This is the v7 cover letter for the single-patch series adding revision filtering to `` `git repo structure` ``. The patch itself is unchanged from v6 except for a one-word fix in the commit message ("standard the standard" → "the standard"), addressing the final nit raised by Kristoffer Haugsbakk. The series remains procedurally clean, technically sound, and ready for merging; Junio or Patrick Steinhardt could pick it up as-is.

The feature allows users to restrict the repository-structure report to objects reachable from specified revisions (e.g., `` `git repo structure main --not tags/v1.0` ``), which is particularly useful for diagnosing performance issues in large repositories without having to analyze the entire object graph. The implementation uses Git’s standard ``setup_revisions()`` machinery, so the syntax and semantics match familiar Git revision-parsing idioms. Three files are touched: ``builtin/repo.c`` (core logic), ``Documentation/git-repo.adoc`` (user-facing documentation), and ``t/t1901-repo-structure.sh`` (197 lines of test coverage for edge cases like overlapping includes/excludes and output formats). The only known inefficiency—a second ref-walk in ``count_references()``—is considered tolerable for a diagnostic command. All substantive feedback from prior rounds has been incorporated, and the remaining open questions (revision-parsing defaults, test coverage for trees/blobs) are now explicitly non-blocking.
