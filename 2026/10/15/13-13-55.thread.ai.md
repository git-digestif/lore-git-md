Subject: [PATCH 0/3] reflog: add --operations and --historical-branch options
Series version: v3 (v1, v2 previously)
Originating author: Harald Nordgren (via GitGitGadget)
Thread type: patch series

Core problem or goal
Add a `%gb` format placeholder to `git log -g` and `git reflog` to expose branch context in reflog output, replacing the earlier `--operations` and `--historical-branch` flags with a composable format specifier that aligns with Git’s decoration system. The goal is to address usability pain points (e.g., obscured reset points during rebasing, tracking branch history across renames) without altering default behavior. The series abandons the dedicated flags in favor of format specifiers, addressing prior critiques about correctness (e.g., `git rebase <upstream> <branch>` edge case) and UX trade-offs (e.g., replacing commit decorations). Junio C Hamano’s broader architectural proposals—(a) refactoring multi-step commands to work on detached HEAD by default and (b) changing `git reflog`’s default behavior to operate on the current branch—remain unresolved, but this series does not engage with them, focusing instead on a targeted improvement.

Current status
Under review; v3 posted as a ground-up redesign replacing v2’s dedicated flags with the `%gb` format specifier. The series is now split into two patches: (1) a preparatory refactoring of hard-coded reflog message strings into `#define` constants in `reflog.h`, explicitly tied to the `%gb` feature, and (2) the implementation of the `%gb` placeholder itself. The refactoring patch (1/2) addresses Junio’s earlier concern about alignment with future directions (e.g., translatable or machine-readable reflog messages) by making the strings easier to refactor later. The series addresses all prior feedback: Phillip Wood’s correctness concerns (e.g., `git rebase <upstream> <branch>`), UX trade-offs (composability with decorations), and commit message clarity. Key technical details
- **New format placeholder**: `%gb` (reflog branch), added to `pretty.c` and documented in `Documentation/pretty-formats.adoc`. The placeholder names the branch for each reflog entry by parsing messages left by branch switches, renames, and rebases, handling edge cases like `git rebase <upstream> <branch>`, detached HEAD states, and branch renames. Outputs "detached at <commit>" when `HEAD` was detached. For reflogs of other refs (not `HEAD`), `%gb` shows the shortened refname.
- **Files touched**: 12 files across the series, including core reflog-walking logic (`reflog-walk.c`, `revision.c`), built-in commands (`builtin/rebase.c`, `builtin/checkout.c`), documentation, and test script `t/t1414-reflog-walk.sh` (122 lines). Patch 1/2 refactors hard-coded reflog message strings into `#define` constants (`REFLOG_SWITCH_PREFIX`, `REFLOG_RETURNING_TO`, `REFLOG_CHECKOUT`, `REFLOG_RENAME_PREFIX`, etc.) in `reflog.h`, explicitly tying the refactoring to the `%gb` feature. Patch 2/2 implements the `%gb` placeholder and adds a `branches_marked` flag to `complete_reflogs` to track whether branch context has been determined.
- **New symbols**: `#define` constants in `reflog.h` (`REFLOG_SWITCH_PREFIX`, `REFLOG_RETURNING_TO`, `REFLOG_CHECKOUT`, `REFLOG_RENAME_PREFIX`); `branches_marked` flag in `struct complete_reflogs`; `mark_branches()` function in `reflog-walk.c`.
- **Test coverage**: 122-line test script (`t/t1414-reflog-walk.sh`) validates edge cases: rebases (including `git rebase <upstream> <branch>`), branch renames, detached HEAD states, and interaction with `--decorate`. No gaps identified in prior reviews.
- **No on-disk format changes**.
- **Behavior**: The `%gb` placeholder is additive and does not alter default output. Users can include it in custom formats (e.g., `git reflog --format='%h %gb %gd %s'`) without losing other decorations.
