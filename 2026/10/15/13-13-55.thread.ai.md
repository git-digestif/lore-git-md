Subject: [PATCH 0/3] reflog: add --operations and --historical-branch options
Series version: v4 (v1, v2, v3 previously)
Originating author: Harald Nordgren (via GitGitGadget)
Thread type: patch series

Core problem or goal
Add a `%gb` format placeholder to `git log -g` and `git reflog` to expose branch context in reflog output, replacing earlier proposals for dedicated flags (`--operations` and `--historical-branch`) with a composable format specifier that aligns with Git’s decoration system. The goal is to address usability pain points (e.g., obscured reset points during rebasing, tracking branch history across renames) without altering default behavior. The series abandons the dedicated flags in favor of format specifiers, addressing prior critiques about correctness (e.g., `git rebase <upstream> <branch>` edge case) and UX trade-offs (e.g., replacing commit decorations). Junio C Hamano’s broader architectural proposals—(a) refactoring multi-step commands to work on detached HEAD by default and (b) changing `git reflog`’s default behavior to operate on the current branch—remain unresolved, but this series does not engage with them, focusing instead on a targeted improvement. Harald Nordgren’s latest reply in v3 introduced a narrower proposal: making `git reflog @{0}` the default output for `git reflog`, citing obscurity of the notation as a usability barrier. This proposal remains untriaged and does not interact with the `%gb` series or Junio’s broader architectural debate.

Key technical details
- **New format placeholder**: `%gb` (reflog branch), added to `pretty.c` and documented in `Documentation/pretty-formats.adoc`. The placeholder names the branch for each reflog entry by parsing messages left by branch switches, renames, and rebases, handling edge cases like `git rebase <upstream> <branch>`, detached HEAD states, and branch renames. Outputs "detached at <commit>" when `HEAD` was detached. For reflogs of other refs (not `HEAD`), `%gb` shows the shortened refname.
- **Regression fix**: v4 introduces `skip_rebase_checkout()` in `reflog-walk.c` to handle reflog messages altered by `GIT_REFLOG_ACTION` (e.g., `"sync switch: checkout ..."`), ensuring `%gb` correctly interprets branch context during rebase operations. The fix addresses Phillip Wood’s review, preventing mislabeled entries (e.g., `"sequencer-delete-REBASE_HEAD"` instead of the correct branch name).
- **Files touched**: 13 files across the series, including core reflog-walking logic (`reflog-walk.c`, `revision.c`), built-in commands (`builtin/rebase.c`, `builtin/checkout.c`, `builtin/branch.c`), documentation, and test script `t/t1414-reflog-walk.sh` (now 259 lines, up from 122 in v3). Patch 1/3 refactors hard-coded reflog message strings into `#define` constants (`REFLOG_SWITCH_PREFIX`, `REFLOG_RETURNING_TO`, `REFLOG_CHECKOUT`, `REFLOG_RENAME_PREFIX`, etc.) in `reflog.h`, explicitly tying the refactoring to the `%gb` feature. Patch 2/3 implements the `%gb` placeholder, adds the `skip_rebase_checkout()` helper, and includes a `branches_marked` flag in `struct complete_reflogs` to track whether branch context has been determined. Patch 3/3 (new in v4) consolidates hard-coded reflog message strings into named constants in `reflog.h`, updating `builtin/branch.c`, `builtin/checkout.c`, `builtin/rebase.c`, `object-name.c`, `sequencer.c`, and `wt-status.c` to use these constants.
- **New symbols**: `#define` constants in `reflog.h` (`REFLOG_SWITCH_PREFIX`, `REFLOG_RETURNING_TO`, `REFLOG_CHECKOUT`, `REFLOG_RENAME_PREFIX`, `REFLOG_REBASE_START`, `REFLOG_REBASE_FINISH`, `REFLOG_REBASE_ABORT`, `REFLOG_REBASE_RETURNING_TO`, `REFLOG_REBASE_CHECKOUT`); `branches_marked` flag in `struct complete_reflogs`; `mark_branches()` and `skip_rebase_checkout()` functions in `reflog-walk.c`.
- **Test coverage**: Expanded test script (`t/t1414-reflog-walk.sh`) now covers `GIT_REFLOG_ACTION`-modified reflog messages, validating the regression fix. Tests include edge cases: rebases (including `git rebase <upstream> <branch>`), branch renames, detached HEAD states, interaction with `--decorate`, and custom `GIT_REFLOG_ACTION` values.
- **No on-disk format changes**.
- **Behavior**: The `%gb` placeholder is additive and does not alter default output. Users can include it in custom formats (e.g., `git reflog --format='%h %gb %gd %s'`) without losing other decorations.
- **New proposal**: Harald Nordgren’s v3 reply suggests making `git reflog @{0}` the default output for `git reflog`, citing obscurity of the notation as a usability barrier. This proposal remains untriaged, with no technical implementation or prior discussion in the thread. It does not interact with the `%gb` series or Junio’s broader architectural proposals.
