This is the second patch in Harald Nordgren’s three-part feature series adding `--operations` and `--historical-branch` options to `git reflog` and `git log -g`. It implements the `--operations` flag, which collapses multi-step operations like rebases into single entries representing the actual commands executed, while omitting entries that don’t change the branch (e.g., branch switches or the "reset: moving to HEAD" left by `git stash`).

The patch touches seven files, including core reflog-walking logic (`reflog-walk.c`, `revision.c`), documentation, and a new test script. The implementation introduces a `user_operation` flag in the reflog entry structure and a `mark_operations()` function that scans the reflog to identify and mark entries that should be displayed. The logic correctly handles edge cases like stopped rebases (folding in amendments) and aborted operations. The test coverage is thorough, with 105 lines of new tests validating behavior across rebases, stashes, and pull operations.

The motivation is clear: reflogs currently show every intermediate step, making it difficult to see the actual commands executed. This patch directly addresses that pain point without changing default behavior, reducing the risk of regression. The code is well-structured and the commit message provides helpful examples of the new output format. This looks like a well-crafted, user-focused improvement that should appeal to anyone who uses reflogs for debugging or auditing workflows.
