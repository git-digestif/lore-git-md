This is the third and final patch in Harald Nordgren’s three-part series adding new usability features to `git reflog` and `git log -g`. It introduces `--historical-branch`, an option that decorates each reflog entry with the branch HEAD was on when the entry was recorded, addressing a long-standing pain point where users have to manually trace back through "checkout: moving from" entries to determine which branch a given reflog action affected.

The implementation is clean and well-scoped: it adds a new `historical_branch` flag to the `rev_info` struct, extends the `reflog_walk_mark()` function to scan the reflog and annotate each entry with the branch name (or "detached at <commit>" for detached HEAD states), and modifies the decoration logic in `log-tree.c` to show the historical branch name in place of current ref decorations. The patch also handles edge cases like branch renames and detached HEAD states, and includes thorough test coverage in the new `t/t1414-reflog-walk.sh` script (adding 95 lines of tests in this patch alone).

The feature is additive and does not change default behavior, so there’s no risk of regression. Combined with the `--operations` option from patch 2/3, this gives users a powerful way to audit what was done to each branch without wading through intermediate steps. The documentation updates are clear and concise, and the commit message does a good job explaining the motivation and behavior.

This looks like a well-crafted, user-focused improvement that directly addresses a real usability issue. The series as a whole is likely to be of interest to anyone who uses reflogs for debugging or auditing workflows.
