This is a **bugfix patch** targeting the `git log --follow` performance regression introduced in Git 2.56 by commit 304813ed33. The patch is authored by Miklos Vajna, the original implementer of the regression-causing change, and proposes two optimizations to restore near-original performance while preserving the corrected rename-following behavior for non-linear history.

The patch introduces two shortcuts in the `propagate_follow_pathspec_to_parent()` logic: (1) it only performs expensive rename detection when the followed path is *added* relative to a parent, and (2) if the path is unchanged in any parent, it follows that parent’s history without further diffing. These changes reduce the runtime of `git log --stat --follow include/linux/rsc_table.h` in the Linux kernel repository from 6m43s back to 29s—almost matching the pre-regression time of 28s—while maintaining all existing test cases in `t4211-log-follow-merge.sh`.

The implementation adds a new helper function, `get_follow_path_change()`, which classifies how the followed path differs between a commit and its parent (unchanged, added, or other). This classification drives the optimization logic in `propagate_follow_pathspec_to_parents()`, which replaces the previous loop that unconditionally called the expensive rename-detection routine for every parent of a merge commit. The patch touches only `log-tree.c` and does not alter any on-disk formats or public interfaces.

Miklos frames the optimizations as safe because they preserve the correctness fixes introduced by 304813ed33, and he invites review from SZEDER Gábor and Patrick Steinhardt before sending it to Junio. The patch directly addresses the quadratic scaling issue identified in the thread: by avoiding full rename detection when the path is unchanged in a parent, it eliminates the worst-case behavior for merge commits with many parents.

Key technical details for follow-up discussion: the new `enum follow_path_change` and its classification logic, the `has_same` flag that short-circuits further diffing once an unchanged parent is found, and the unchanged test coverage in `t4211`. The patch does not adopt the `git log -L` strategy of skipping non-first parents entirely, but it achieves similar performance gains by avoiding redundant diffs.
