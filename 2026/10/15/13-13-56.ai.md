This is the first patch in Harald Nordgren’s three-part series adding `--operations` and `--historical-branch` options to `git reflog` and `git log -g`. It is a refactoring patch that centralizes the hard-coded strings used to mark branch switches, renames, and rebase steps in reflog messages.

The patch introduces five new `#define` constants in `reflog.h` (`REFLOG_SWITCH_PREFIX`, `REFLOG_RENAME_PREFIX`, `REFLOG_STEP_START`, `REFLOG_STEP_FINISH`, `REFLOG_STEP_ABORT`) and updates seven files (`builtin/branch.c`, `builtin/checkout.c`, `builtin/rebase.c`, `object-name.c`, `sequencer.c`, `wt-status.c`, and `reflog.h`) to use these constants instead of hard-coded strings. The changes are purely mechanical: no behavior is altered, and no new functionality is introduced. The goal is to prevent future drift between the strings used when writing reflog entries and those used when parsing them.

This patch is a prerequisite for the next two patches in the series, which will rely on these constants to implement the new `--operations` and `--historical-branch` options. The refactoring is well-scoped and uncontroversial, touching only the reflog message formatting and parsing code. The commit message clearly explains the motivation and the files involved, making it easy for reviewers to verify that the changes are safe and complete.
