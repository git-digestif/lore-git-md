This is a follow-up in the ongoing discussion about deprecating the experimental `git format-rev` command. Kristoffer Haugsbakk clarifies a technical detail about the proposed replacement pipeline using `git diff-tree --stdin --format=medium`.

The key point here is about handling multiline pretty-formatted output. While `git diff-tree` supports `-z` for NUL-terminated output, this option only applies to primitive diff formats (like `--raw`, `--numstat`, etc.) and not to the `--format=medium` pretty-printing mode. This means the earlier claim that `git cat-file` and `git diff-tree` together could fully replicate `git format-rev`'s functionality was incorrect—specifically, the NUL-terminated input/output for multiline revision expressions isn't supported in the same way.

Kristoffer acknowledges this limitation and retracts the footnote in his original proposal that suggested the two commands were "equally expressive." The discussion remains open on whether this gap (or other conveniences like direct revision expressions) justifies keeping `git format-rev` despite its overlap with existing tools. No new alternatives are proposed in this email, so the core question—whether to deprecate the command—is still unresolved.
