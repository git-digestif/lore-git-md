This is the third and final patch in Harald Nordgren's v1 series adding `--operations` and `--historical-branch` options to `git reflog` and `git log -g`. This patch implements `--historical-branch`, which decorates each reflog entry with the branch HEAD was on when the entry was recorded, addressing a long-standing usability pain point where users must manually trace back through "checkout: moving from" entries to determine which branch a reflog entry belongs to.

The implementation adds a new `historical_branch` flag to `struct rev_info`, extends `reflog_walk_mark()` to accept this flag, and introduces a `mark_branches()` function that scans the reflog to determine the branch for each entry. The branch name is then displayed in place of standard commit decorations, colored like a local branch ref. The patch handles edge cases such as detached HEAD (showing "detached at <commit>"), branch renames (showing the name at the time of the entry), and reflogs for non-HEAD refs (showing the ref name itself). The new option is additive and requires `--walk-reflogs` to be set, matching the behavior of `--operations`.

The patch touches 8 files, including core reflog-walking logic (`reflog-walk.c`, `revision.c`), output formatting (`log-tree.c`), and documentation. It also extends the test script `t/t1414-reflog-walk.sh` with 95 new lines of test coverage, validating behavior for branch renames, detached HEAD, non-HEAD reflogs, and interaction with `--decorate`. The implementation is careful to avoid on-disk format changes and reuses existing reflog parsing logic from the earlier patches in the series.
