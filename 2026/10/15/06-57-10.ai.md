This is a test fix targeting the SHA-256 transition effort. The patch repairs `t5004-archive-corner-cases.sh`, which verifies Git’s ability to handle ZIP archives containing objects larger than 4GB. The test was silently broken in SHA-256 repositories because it extracts SHA-1 objects from a pre-generated packfile (`big-pack.zip`) without ensuring the receiving repository uses the same object format. The fix creates a dedicated SHA-1 repository for the test, preventing format mismatches when the Fedora CI job (which runs with breaking changes enabled) exercises the test.

The patch is part of Patrick Steinhardt’s eight-commit series `[PATCH v4 1/8]` titled “ci: housekeeping”. This is the first patch in the series; the cover letter is not provided here, so the broader goal is unclear, but the immediate context is a CI-related cleanup that will expose the test breakage. Jeff King (Peff) suggested the SHA-1 repository workaround.

The change is mechanical: the test logic is moved into a subshell inside a newly initialized `--object-format=sha1` repository, and a `test_when_finished` guard cleans up the temporary directory. The prerequisites (`EXPENSIVE`, `LONG_IS_64BIT`, `UNZIP`, `UNZIP_ZIP64_SUPPORT`, `ZIPINFO`) remain unchanged. No new test cases or behaviors are introduced; this is purely a correctness fix for an edge case that only surfaces in SHA-256 CI environments.
