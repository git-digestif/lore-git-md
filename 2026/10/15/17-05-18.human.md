This is the seventh iteration of a feature patch adding revision-based filtering to `` `git repo structure` ``. The patch is now procedurally clean and ready for merging.

The goal is straightforward: users can now limit the repository-structure report to objects reachable from specific revisions (commits, refs, or ranges) by passing standard Git revision syntax, for example `` `git repo structure --branches --not --tags` ``. This makes the command far more useful for diagnosing performance issues in large repositories, where analyzing the entire object graph is impractical.

The implementation uses Git’s standard ``setup_revisions()`` machinery, replacing the earlier enum-based flag system with a design that aligns with Git’s established revision-parsing idioms. The patch touches three files: ``builtin/repo.c`` (core logic), ``Documentation/git-repo.adoc`` (user-facing documentation), and ``t/t1901-repo-structure.sh`` (197 lines of new tests covering edge cases like overlapping includes/excludes and output formats).

All substantive feedback from prior rounds has been addressed.
