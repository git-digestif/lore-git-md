This is the fourth patch in Patrick Steinhardt’s six-patch series refactoring and optimizing alternates handling in Git’s object database (ODB) "files" backend. The patch removes a redundant read loop in `do_oid_object_info_extended()` by replacing it with a single explicit re-read after fetching objects from a promisor remote.

The change simplifies the control flow in `odb.c` by eliminating the `while (1)` loop and the `already_retried` flag, which were artifacts of the pre-refactoring alternates logic. Now that alternates handling is confined to the "files" backend, the function can directly attempt a re-read after a promisor fetch, making the code easier to follow. The patch preserves the existing behavior: if an object is missing and the repository has a promisor remote, Git will fetch it and then re-attempt the read exactly once.

This is a clean refactoring with no user-visible behavior changes. The patch is well-motivated by the earlier work in the series (particularly patch 3/6, which moved the retry logic into the "files" backend) and has already been reviewed and endorsed by Justin Tobler, who confirmed the design and implementation. The simplification here is a natural follow-up to the architectural changes in the rest of the series, and the patch itself is small and focused, touching only 46 lines in a single file. It looks ready to merge as part of the larger ODB abstraction effort.
