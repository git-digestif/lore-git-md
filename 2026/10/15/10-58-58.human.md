This is the second patch in Isabella Caselli’s three-patch v2 series implementing `includeIf.hostname:<pattern>` for Git’s configuration system. It fixes a subtle test reliability issue in `t/t6500-gc.sh` by ensuring the test and the `git gc` command agree on the hostname value.

The problem: the test simulates a concurrent `git gc` by writing a `gc.pid` file containing the shell’s PID and hostname (obtained via the external `hostname` command). However, `git gc` itself determines the hostname using Git’s internal `xgethostname()` function. If these two methods return different values—e.g., one returns a short name (`myhost`) and the other a fully qualified domain name (`myhost.example.com`)—the test’s `gc.pid` file will contain a hostname that `git gc` does not recognize as its own. This causes `git gc` to skip the PID check entirely (assuming the lock belongs to another machine), and the test passes without verifying the intended behavior: that `git gc` detects a running process on the same machine.

The fix is simple and surgical: replace the external `hostname` command with `git var GIT_HOSTNAME`, which calls the same `xgethostname()` function used by `git gc`. The fallback to `unknown` is preserved, matching `git gc`’s behavior when the hostname cannot be determined.
