This is the first patch in Patrick Steinhardt’s six-patch v3 series refactoring and optimizing alternates handling in Git’s object database (ODB) "files" backend. The patch directly addresses a performance regression introduced when alternates handling was reorganized for pluggable ODBs: previously, Git scanned all alternate packfiles before loose objects, but the new architecture checked each alternate’s packfiles and loose objects sequentially, leading to unnecessary `stat()` calls when objects were packed in alternates.

The fix is simple and effective: the patch reorders the loops in `odb_source_files_read_object_info()` to check all packfiles across alternates first, then all loose objects. This restores the original performance behavior without changing user-visible functionality or on-disk formats. The commit message includes a clear benchmark showing a 1.89x speedup in `git cat-file --batch-check` when reading objects from an alternate packfile, and the patch adds a new regression test (`t/t5615-alternate-env.sh`) that verifies the optimization works as intended. The test creates an alternate repository with a deltified object, writes a loose copy of the same object in the main repository, and confirms `git cat-file` resolves to the alternate’s packfile, not the loose copy.

The patch is well-motivated, thoroughly tested, and already validated on both SHA-1 and SHA-256 repositories. It addresses Johannes Schindelin’s request for test coverage and incorporates a test authored by Tyrie Vella that was previously used in Microsoft Git to fix the same issue. The change is confined to the "files" backend and does not introduce new ODB flags or complexity, aligning with the series’ goal of simplifying the ODB source API. This patch is a clear win: it fixes a measurable performance regression with minimal risk and strong reviewer endorsement. If you care about large-repository performance or the ODB abstraction effort, this is worth reviewing.
