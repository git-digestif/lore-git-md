This is a follow-up in the `git format-rev` deprecation proposal thread. Kristoffer Haugsbakk clarifies a technical detail about the proposed replacement pipeline for `git format-rev`. The earlier suggestion that `git diff-tree --stdin --format=medium` could fully replace `git format-rev` was incomplete: while `git diff-tree` supports NUL-terminated output for certain diff formats (like `--raw` or `--name-only`), it does **not** support NUL termination for the `--format=medium` pretty-printing mode. This means the pipeline `git rev-list HEAD | git diff-tree --stdin --format=medium -z` would not work as intended for multiline commit messages or revision expressions, since `-z` only applies to primitive diff formats.

The email corrects the earlier claim that `git cat-file` and `git diff-tree` together could match `git format-rev`'s expressiveness for NUL-terminated input. While `git cat-file -Z` can handle NUL-terminated input and output, `git diff-tree` cannot propagate that termination through its pretty-printing machinery. This limitation weakens the argument for deprecating `git format-rev`, as the proposed replacement pipeline cannot handle multiline revision expressions or commit messages without mangling pathnames or losing formatting. The thread’s core question—whether `git format-rev`’s convenience features justify its continued existence—remains open, but this clarification highlights a functional gap in the alternative.
