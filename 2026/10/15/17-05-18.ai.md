This is the v7 iteration of a feature patch adding revision-based filtering to the `git repo structure` command. The patch is now procedurally clean and technically complete, addressing all prior feedback including the final editorial nit ("standard the standard" → "the standard") flagged by Kristoffer Haugsbakk. No substantive changes were made since v6; this version is identical except for the commit message fix.

The feature allows users to analyze specific subsets of the repository object graph by specifying revisions (commits, refs, or ranges) to include or exclude, improving diagnostic capabilities for large repositories. For example, `git repo structure --branches --not --tags` processes only objects reachable from branches but not from tags. The implementation uses Git’s standard `setup_revisions()` machinery, replacing the earlier `--no-<reftype>` approach with a design consistent with Git’s revision-parsing idioms. The patch touches `builtin/repo.c`, `Documentation/git-repo.adoc`, and `t/t1901-repo-structure.sh`, expanding test coverage to 197 lines and validating edge cases like overlapping includes/excludes and output formats.

All critical feedback from prior rounds has been incorporated. The author’s rationale for retaining the current defaults—avoiding breakage in empty repositories—was accepted as sufficient for a diagnostic tool.
