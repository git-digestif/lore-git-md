This is the third patch in Patrick Steinhardt’s six-patch v3 series refactoring alternates handling in the Git object database’s "files" backend. The patch moves the second-read logic — previously a generic ODB mechanism — into the "files" source itself, eliminating the `OBJECT_INFO_SECOND_READ` flag and simplifying the ODB source API.

The change confines the retry loop to `odb/source-files.c`, where a new `retry` boolean replaces the generic flag. The "loose" source no longer needs to handle `OBJECT_INFO_SECOND_READ` at all, and the "packed" source now uses `OBJECT_INFO_QUICK` to decide whether to scan MIDX-covered packfiles. The patch removes 56 lines across six files while preserving the existing behavior: objects are still re-checked after a first failure, but the mechanism is now an implementation detail of the "files" backend rather than a generic ODB concern.

Justin Tobler’s substantive review confirmed the design and implementation, and the patch is part of a series that has already addressed all substantive feedback from earlier iterations. The only open question — the long-term viability of the `ODB_FOR_EACH_OBJECT_LOCAL_ONLY` flag — is explicitly deferred to a follow-up series. This patch is a clean refactoring that aligns with the broader ODB abstraction effort.
