This thread is about a small but important fix to a test script (`t5004-archive-corner-cases.sh`) that verifies Git’s handling of large ZIP archives. The test was silently failing in SHA-256 repositories because it relied on a pre-generated packfile containing SHA-1 objects, creating a format mismatch. Patrick Steinhardt’s patch resolves this by running the test inside a dedicated SHA-1 repository, ensuring consistency regardless of the host repository’s object format. The fix is part of a larger CI cleanup series (`[PATCH v4 1/8]`), though the broader goals of that series aren’t detailed here.

The change itself is straightforward: the test logic is wrapped in a subshell within a temporary SHA-1 repository, with cleanup handled by `test_when_finished`. Jeff King (Peff) suggested this approach, and the patch doesn’t introduce new behaviors or test cases—it just ensures the existing test works correctly in SHA-256 environments, particularly in Fedora CI jobs where breaking changes are enabled. No objections or alternative proposals have surfaced yet, and the fix appears uncontroversial. The series is at version 4, but this is the first mention of it in the thread, so earlier feedback isn’t covered here.
