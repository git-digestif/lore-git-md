This is the third patch in Patrick Steinhardt’s six-patch series refactoring and optimizing alternates handling in Git’s object database (ODB) "files" backend. The series is now in its third iteration, with all substantive review feedback addressed and a new regression test added in patch 1/6.

This patch moves the "second read" logic — previously a generic ODB mechanism — into the "files" backend, making it an implementation detail of that source. The `OBJECT_INFO_SECOND_READ` flag is removed entirely, simplifying the ODB source API. The change is motivated by the recent migration of alternates handling into the files backend, which makes the second-read logic specific to that backend rather than a cross-cutting concern. The patch also adapts the "packed" source to use `OBJECT_INFO_QUICK` instead of `OBJECT_INFO_SECOND_READ` to determine when to scan multi-pack-index-covered packfiles, accepting a minor performance trade-off in rare race conditions for cleaner abstraction.

The patch touches six files, removing 56 lines and adding 16, for a net reduction of 40 lines. The core logic is now confined to `odb/source-files.c`, where a `retry` loop replaces the generic flag. The "loose" source no longer needs to handle the second-read flag, and the "packed" source’s behavior is adjusted to use `OBJECT_INFO_QUICK` for its fallback logic. The change is well-motivated and aligns with the series’ broader goal of simplifying the ODB source API while maintaining performance.

Justin Tobler’s review confirmed the design and implementation, tracing the control flow to verify correctness. The only open question — whether the `OBJECT_INFO_QUICK` phrasing and early loop termination structure are optimal — was discussed but left unchanged, as Patrick explained the current structure accommodates a planned follow-up series on alternates reloading. The patch is uncontroversial and looks ready for integration.
