This is the first patch in Isabella Caselli’s three-patch v2 series implementing `includeIf.hostname:<pattern>` in Git’s configuration system. It introduces `git var GIT_HOSTNAME` as a debugging aid, directly addressing feedback from Eric Sunshine and Jeff King during the RFC phase.

The patch adds a new `GIT_HOSTNAME` variable to `git var`, which exposes the hostname Git sees internally (via `xgethostname()`). This is critical for users to debug `includeIf.hostname` conditions, since the hostname may be a short name or FQDN depending on system configuration. The implementation is minimal: if the hostname cannot be determined, `git var GIT_HOSTNAME` exits non-zero, and `git var -l` omits the variable rather than failing. The test in `t/t0007-git-var.sh` only verifies the output is non-empty, as the expected value is system-dependent and may not match the external `hostname` command.

The patch touches `builtin/var.c` (adding the `hostname()` function), `Documentation/git-var.adoc` (documentation), and `t/t0007-git-var.sh` (a minimal test). No substantive objections remain; Peff’s recent review confirmed he has read the series and found no issues. This patch is uncontroversial and ready for integration, serving as a foundation for the core `includeIf.hostname` logic in patch 3/3. The unresolved case-sensitivity question (whether hostname matching should be case-sensitive) does not affect this patch.
