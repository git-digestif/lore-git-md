This is a bugfix patch addressing a performance regression in shallow fetches when backfilling tags. Karthik Nayak responds to Junio C Hamano's review of v2, clarifying edge cases and planning adjustments for a v3.

The patch splits the reference transaction into two parts—fetched references and backfilled tags—to restore correct negotiation behavior while preserving most of the performance gains from batched updates. Karthik confirms the regression only occurs when the main fetch updates on-disk state, not when the transaction is empty. He also acknowledges that `--atomic` fetches will continue to suffer from the same issue, as there’s no straightforward fix for that case, and plans to document this limitation in the commit message.

A control-flow issue in the cleanup path is addressed: the current patch jumps to `cleanup` if the tag backfill transaction fails, skipping post-fetch steps like writing `FETCH_HEAD` and setting upstream configuration. Karthik agrees this is incorrect and will introduce a separate `backfill_retcode` to distinguish between primary fetch failures and tag backfill failures. Additionally, he notes the new test doesn’t reliably catch the regression and will revert to an earlier version.

The patch is well-motivated and has strong test coverage, but Junio’s review raises valid concerns about edge cases and cleanup logic. A v3 is likely needed before this can progress to `next`. If you care about shallow fetch performance or reference transaction correctness, this is worth following.
