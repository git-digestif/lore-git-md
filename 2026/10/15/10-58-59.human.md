This is the third and final patch in Isabella Caselli’s three-patch series implementing `includeIf.hostname:<pattern>` for Git’s configuration system. The patch adds the core logic, documentation, and test coverage for the new `hostname:` condition, completing the feature.

The implementation extends Git’s existing `includeIf` mechanism with a new `hostname:` condition that matches the machine’s hostname against a glob pattern. The hostname resolution is system-dependent (short name or FQDN), documented as such, and matches exactly (case-sensitive) with standard glob wildcards. The patch touches `config.c` (adding the `include_by_hostname()` function and condition parsing), `Documentation/config.adoc` (documentation with examples and caveats), `Documentation/git-var.adoc` (cross-reference to `git var GIT_HOSTNAME`), and `t/t1305-config-include.sh` (tests for exact and wildcard hostname matching).

The commit message clearly explains the motivation (dotfile sharing across multiple machines), the design choices (system-dependent hostname matching without DNS lookups), and the testing strategy (using `git var GIT_HOSTNAME` to ensure test reliability). Junio C Hamano reviewed this patch and described the implementation approach as “neat” and “quite nice,” indicating no substantive objections. The series as a whole addresses all prior feedback, including Peff’s suggestion for `git var GIT_HOSTNAME` (implemented in patch 1/3) and Junio’s request to clarify the test reliability issue (addressed in patch 2/3).

The only remaining open question is whether hostname matching should be case-sensitive (current behavior), case-insensitive, or support a `hostname/i:` variant. Isabella has noted this but not yet proposed a specific change. Otherwise, the patch is well-crafted, thoroughly tested, and ready for final review. If you care about conditional configuration or dotfile management, this is a small but useful feature worth paying attention to.
