This is a review of Harald Nordgren’s three-patch series that adds `--operations` and `--historical-branch` options to `git reflog` and `git log -g`. Kristoffer Haugsbakk’s reply is enthusiastic and user-focused: he describes the pain point the series addresses (rebase steps cluttering the reflog and obscuring reset points) and confirms it is a common issue, citing his own workarounds (`ORIG_HEAD` or backup refs). His feedback is not a technical review but a clear endorsement of the feature’s value, which suggests the series is solving a real problem rather than introducing speculative functionality.

The series itself remains under review with no maintainer decisions yet. The preparatory refactoring in patch 1/3 has already drawn a substantive review comment from Kristoffer about commit-message clarity, but the code itself was not objected to. Patches 2/3 and 3/3 introduce the new options with thorough test coverage and careful attention to edge cases (detached HEAD, branch renames, non-HEAD reflogs), so the implementation looks well-scoped and ready for deeper technical scrutiny.

For anyone who uses reflogs for debugging or auditing, these options promise to make the output far more usable by collapsing multi-step operations into single entries and showing the branch context at the time of each entry. The series is additive (no default behavior changes) and touches only the reflog-walking logic, so regression risk appears low. If the remaining patches hold up to review as well as the first one did, this looks like a straightforward improvement worth following.
