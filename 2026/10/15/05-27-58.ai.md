This is the fourth patch in Patrick Steinhardt’s six-patch v3 series refactoring and optimizing alternates handling in Git’s object database (ODB) "files" backend. The patch removes the redundant read loop in `do_oid_object_info_extended()` by replacing it with a single explicit re-read after fetching objects from a promisor remote.

The change simplifies the control flow in `odb.c` by eliminating the `while (1)` loop and `already_retried` flag, which were artifacts of the pre-refactoring alternates handling logic. Now that the "files" backend manages alternates internally, the function can directly re-read the object once after a promisor fetch, making the code easier to reason about. The patch preserves the existing behavior: if an object is found but corrupt, the function still returns `ODB_READ_ERROR`; if the object is missing, it returns `ODB_READ_NOT_FOUND`. The error-handling logic for `OBJECT_INFO_DIE_IF_CORRUPT` remains unchanged.

The diff is confined to `odb.c` and removes 23 lines while adding 23, resulting in no net change in line count but a clearer structure. This patch depends on the earlier refactoring in the series (particularly patch 3/6, which moved the retry logic into the "files" backend) and is a prerequisite for the subsequent cleanup in patch 5/6, which tightens error semantics. Reviewer Justin Tobler has already endorsed the design and implementation, confirming the control flow works as intended. The patch is part of the broader ODB abstraction effort and aligns with the series’ goal of simplifying the ODB source API.
