This is a feature patch adding revision-based filtering to `` `git repo structure` ``. The v7 patch is procedurally clean and ready for merging—it differs from v6 only by a one-word commit message fix ("standard the standard" → "the standard") to address the final nit from Kristoffer Haugsbakk.

The feature allows users to restrict the repository-structure report to objects reachable from specified revisions, using Git’s standard revision-parsing syntax (e.g., `` `git repo structure main --not tags/v1.0` ``). This is particularly useful for diagnosing performance issues in large repositories, as it avoids analyzing the entire object graph. The implementation integrates with Git’s existing ``setup_revisions()`` machinery, ensuring consistency with commands like `` `git log` ``. Three files are modified: ``builtin/repo.c`` (core logic), ``Documentation/git-repo.adoc`` (updated usage examples and terminology), and ``t/t1901-repo-structure.sh`` (197 lines of new tests covering edge cases like overlapping includes/excludes and output formats).

The patch addresses all substantive feedback from prior rounds, including improved commit message motivation, fixed empty repository handling, and corrected error messages. The only known inefficiency—a second ref-walk in ``count_references()`` due to ``setup_revisions()``’s lack of a custom callback—is considered tolerable for a diagnostic tool. Open questions about revision-parsing defaults (e.g., allowing trees/blobs) and test coverage gaps (e.g., ``--filter=object:type=blob``) are now explicitly non-blocking. Patrick Steinhardt’s latest review confirms the patch is procedurally clean, and Junio’s earlier procedural blocker (accidental corruption in v3) is resolved. The patch meets Git’s standards for integration.
