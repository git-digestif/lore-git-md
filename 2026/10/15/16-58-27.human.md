This is a **bugfix** and **documentation** discussion targeting **platform compatibility** (Windows). D. Ben Knoble replies to John Wilson’s bug report about `` `git help user-manual` `` failing on Git for Windows due to a filename mismatch (`gituser-manual.html` vs. `user-manual.html`). Knoble clarifies that the issue stems from Git’s help subsystem logic: `` `git help` `` automatically prefixes requested documentation targets with `git` unless they are explicitly listed in the built-in command list (`command-list.h`) as guides. Since `user-manual` is not included in that list, the fallback logic incorrectly constructs the filename by prepending `git`, causing the lookup to fail.

Knoble’s analysis is substantive and well-informed, tracing the problem to `cmd_to_page()` in the help subsystem and noting that the workaround (manually opening the HTML file via `` `git --html-path` ``) is cumbersome. He suggests two potential fixes: either add `user-manual` to the `command-list.h` generator as a `CAT_guide` entry, or modify the fallback logic in `cmd_to_page()` to avoid prepending `git` for non-command documentation. The discussion remains open-ended, with no patch yet proposed, but Knoble’s explanation provides a clear path forward for anyone looking to address the issue. The thread is now focused on design rather than reproduction, making it more relevant to contributors familiar with Git’s help system or build-time tooling.
