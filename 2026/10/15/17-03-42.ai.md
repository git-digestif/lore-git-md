The feature allows users to restrict the repository-structure report to objects reachable from specified revisions (e.g., `` `git repo structure main --not tags/v1.0` ``). This is particularly useful for diagnosing performance issues in large repositories without analyzing the entire object graph. The implementation uses Git’s standard ``setup_revisions()`` machinery, ensuring syntax and semantics match familiar Git revision-parsing idioms (e.g., ``--all``, ``^ref``, and range expressions).

Three files are modified:
- ``builtin/repo.c``: Core logic adds revision parsing via ``setup_revisions()`` and a parameter to ``count_references()`` to avoid redundant ref-walks when revisions are specified. The workaround for ``setup_revisions()``’s lack of a custom ref-walk callback (a second ref-walk in ``count_references()``) is retained but considered tolerable for a diagnostic tool.
- ``Documentation/git-repo.adoc``: Updates the synopsis and adds examples demonstrating revision filtering (e.g., ``git repo structure x y ^xchild``).
- ``t/t1901-repo-structure.sh``: Expands test coverage to 197 lines, validating edge cases like overlapping includes/excludes, output formats (table/lines/nul), and filtering by object type (e.g., ``--filter=object:type=blob``).
