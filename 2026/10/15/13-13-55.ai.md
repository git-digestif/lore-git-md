This is a feature patch series introducing two new options to `git reflog` and `git log -g`: `--operations` and `--historical-branch`. The series addresses a long-standing usability issue with reflogs—namely, that they currently show every intermediate step of operations like rebase or branch switching, making it difficult to see the actual commands executed and which branch they affected.

The first patch renames internal strings that mark reflog entries for branch switches, renames, and rebase steps to make the code more readable. The second patch adds `--operations`, which collapses sequences like rebases into a single entry representing the command that finished or aborted them, and omits entries that don’t change the branch. The third patch adds `--historical-branch`, which decorates each reflog entry with the branch HEAD was on when the entry was recorded.

The series touches 15 files, including core reflog-walking logic (`reflog-walk.c`, `revision.c`), built-in commands (`builtin/rebase.c`, `builtin/checkout.c`), and documentation. It also adds a new test script (`t/t1414-reflog-walk.sh`) with 198 lines of test coverage, suggesting thorough validation of the new behavior. The motivation is clearly tied to an earlier discussion on the mailing list, indicating this is a response to real user pain points rather than a speculative feature.

The implementation looks well-scoped and targeted, avoiding broad refactoring in favor of focused changes to the reflog subsystem. The new options are additive and don’t change default behavior, reducing risk of regression. The series appears to be a v1, so review feedback may still shape the final form, but the foundation seems solid. This is likely to be of interest to users who rely on reflogs for debugging or auditing workflows.
