This is a **bugfix** targeting the help subsystem and platform compatibility (Windows). Junio C Hamano confirms the issue reported by John Wilson is not specific to Git for Windows but affects upstream Git: `` `git help user-manual` `` fails because `user-manual` is not listed in the `CAT_guide` category of `command-list.h`, causing the help system to incorrectly prepend `"git"` to the filename and look for `gituser-manual.html` instead of `user-manual.html`.

Junio’s reply shifts the focus from a Windows packaging problem to a broader documentation infrastructure issue. He observes that `` `git help --guides` `` does not list `user-manual` at all, meaning the problem is not just a filename mismatch but also a discoverability gap. His proposed solution involves two steps: adding `user-manual` (and any other missing guides) to the `--guides` list in `command-list.h`, and ensuring the installed filenames match what the help system expects—either by adjusting the install paths or retaining backward compatibility for old paths.

The email is concise and authoritative, framing the issue as a straightforward documentation plumbing fix rather than a deep architectural problem. No patch is included yet, but the next step is clear: a patch to update `command-list.h` and possibly the build system to ensure the correct filenames are installed and discoverable.
