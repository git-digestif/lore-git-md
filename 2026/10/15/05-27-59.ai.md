This is the fifth patch in Patrick Steinhardt’s six-patch v3 series refactoring and optimizing alternates handling in the Git object database’s "files" backend. It addresses a specific edge case in error handling: when an object is found but corrupt, the code previously attempted to fetch it from a promisor remote, effectively masking the corruption. The patch tightens the logic to only trigger promisor fetches for missing objects (`ODB_READ_NOT_FOUND`), not for corrupt ones (`ODB_READ_ERROR`), aligning with the principle that corruption should not be silently papered over.

The change is confined to `odb.c` and removes 12 lines of redundant error-handling logic in `do_oid_object_info_extended()`. The function now fails immediately with `ODB_READ_ERROR` when corruption is detected, rather than proceeding to fetch the object from a promisor remote. The `corrupt` boolean is eliminated, and the control flow is simplified: the promisor fetch block is now guarded by an explicit `ret == ODB_READ_NOT_FOUND` check, and the `OBJECT_INFO_DIE_IF_CORRUPT` logic is updated to reflect the new semantics. The patch preserves the existing behavior for missing objects and for the `OBJECT_INFO_DIE_IF_CORRUPT` flag, which still dies with an appropriate error message when corruption is encountered.

This patch directly addresses feedback from Justin Tobler on the v1 series, where he raised the concern that the original behavior was overly permissive. Patrick incorporated the suggestion in v2, and Justin has since explicitly endorsed the design and implementation, tracing the control flow to confirm the logic now only triggers promisor fetches for missing objects. The change is part of the broader ODB abstraction effort and is built on top of Patrick’s `ps/odb-files-alternates` branch, but it stands alone as a correctness improvement with no dependencies on the other patches in the series.

The patch is well-motivated and clearly explained in the commit message, which cites the dubiousness of silently proceeding after corruption. The diff is minimal and focused, touching only the error-handling logic in `do_oid_object_info_extended()`. There are no user-visible behavior changes, and the patch does not affect the on-disk format or any public APIs. The change is consistent with the series’ overall goal of simplifying the ODB source API and removing redundant code.
