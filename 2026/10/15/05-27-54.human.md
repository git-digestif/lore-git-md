This is the third iteration of a six-patch series from Patrick Steinhardt that refactors and optimizes alternates handling in Git’s object database (ODB) "files" backend. The series is part of the ongoing ODB abstraction effort and builds directly on Patrick’s earlier work migrating alternates into the files backend.

The patches address two performance regressions when reading or streaming objects from repositories with alternates, then clean up internal ODB APIs by removing redundant code and simplifying control flow. The first two patches reorder loops to check packfiles before loose objects, avoiding unnecessary `stat()` calls. The third patch moves the "second read" logic into the files backend, making it an implementation detail rather than a generic ODB concern. The fourth patch removes a redundant read loop in `do_oid_object_info_extended()`, and the fifth tightens error handling by failing immediately when an object is found but corrupt, rather than attempting to fetch it from a promisor remote. The final patch removes the `local` flag from the generic ODB source struct, retaining it only in the packed source where it is still needed.

The series now includes a regression test (`t/t5615-alternate-env.sh`) contributed by Tyrie Vella, which verifies that objects in alternate packfiles are checked before loose objects in the main repository. This test was requested by Johannes Schindelin in the previous round and is already in use at Microsoft Git to address the same performance issue. The test is portable and works with both SHA-1 and SHA-256 repositories.

Justin Tobler provided substantive, tested reviews for all six patches, confirming the design and implementation. His feedback on error handling in `do_oid_object_info_extended()` was incorporated as patch 5/6, and he explicitly agreed with the early-failure semantics for corrupt objects. The only unresolved concern is the long-term viability of the `ODB_FOR_EACH_OBJECT_LOCAL_ONLY` flag, which Patrick identified as potentially redundant but deferred removal to a follow-up series.

The changes are internal to the ODB subsystem and do not affect user-visible behavior or on-disk formats. The series looks well-crafted, with clear commit messages, thorough test coverage, and a net reduction of 11 lines across 13 files. The patches are uncontroversial and appear ready for integration.
