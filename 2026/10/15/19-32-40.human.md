This is the first patch in Isabella Caselli’s three-part series implementing `includeIf.hostname:<pattern>` in Git’s configuration system. Junio C Hamano has just reviewed this patch and given it a clear thumbs-up, calling the implementation "sensible" and the commit message "nicely written."

The patch adds a new `git var GIT_HOSTNAME` command that exposes the hostname Git sees internally (via `xgethostname()`). This is a debugging aid that directly addresses feedback from Eric Sunshine and Jeff King during the RFC phase, and it is critical for users to debug `includeIf.hostname` conditions, since the hostname may be a short name or FQDN depending on system configuration. The implementation is minimal: if the hostname cannot be determined, `git var GIT_HOSTNAME` exits non-zero, and `git var -l` omits the variable rather than failing. The test in `t/t0007-git-var.sh` only verifies the output is non-empty, as the expected value is system-dependent.

This patch is uncontroversial and ready for integration. It touches only `builtin/var.c`, `Documentation/git-var.adoc`, and `t/t0007-git-var.sh`, and serves as a foundation for the core `includeIf.hostname` logic in the third patch. The unresolved case-sensitivity question (whether hostname matching should be case-sensitive) does not affect this patch.
