This is the fifth patch in Patrick Steinhardt’s six-patch series refactoring and optimizing alternates handling in Git’s object database (ODB) "files" backend. It addresses a subtle but important correctness issue in error handling.

The patch changes `do_oid_object_info_extended()` to stop attempting to fetch corrupt objects from promisor remotes. Currently, when Git encounters a corrupt object, it tries to fetch it from a promisor remote and re-read it — effectively masking corruption by silently replacing it with a fresh copy. This patch makes the function fail immediately with `ODB_READ_ERROR` when an object is found but corrupt, rather than proceeding to fetch it. The change removes 20 lines of redundant error-handling logic and tightens the function’s error semantics.

The motivation is straightforward: corruption should not be silently papered over. If an object is corrupt, the user should be made aware of it rather than having Git quietly fetch a replacement. The patch only triggers promisor fetches for missing objects (`ODB_READ_NOT_FOUND`), not for corruption (`ODB_READ_ERROR`). This aligns with the principle that Git should fail fast and visibly when something is wrong, rather than silently proceeding with potentially incorrect data.

The change was suggested by Justin Tobler, who reviewed the control flow and explicitly agreed with the early-failure semantics. His feedback was incorporated in v2 of the series, and this patch is now part of v3. The patch is small (28 lines changed, 20 removed) and focused, touching only `odb.c`. It preserves the existing behavior for `OBJECT_INFO_DIE_IF_CORRUPT`, so user-visible error messages remain unchanged.

This is a well-motivated bugfix with clear reviewer endorsement. It’s part of a larger refactoring effort, but the change itself is self-contained and addresses a real correctness issue. The patch looks ready for merging.
