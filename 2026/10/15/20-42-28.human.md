This is a review of a bugfix patch for the pretty-printing subsystem, specifically the `%w()` format specifier in `git log` and related commands.

René Scharfe provides a substantive review of Andy Koppe’s patch, which fixes a long-standing indentation loss after newlines in wrapped text. The bug, present since 2007, causes misaligned output when a newline (e.g., `%n`) is followed by whitespace, such as in `git log --format="%w(11) This is%n  the %s"`. René traces the issue back to the original commit (ae0b270230) that introduced hard line break handling, noting that the current behavior—where whitespace after a newline is incorrectly skipped—was likely unintended.

The review is thorough and technical, breaking down the old and new behaviors with clear examples. René acknowledges the fix is correct but raises a minor concern about backward compatibility: the behavior has existed for 18 years, and some users (or tests) might rely on it. He suggests the change is reasonable, provided the documentation gap around hard newlines is addressed. The review is constructive and balanced, weighing the fix’s correctness against potential disruption.

The patch itself is small and well-motivated, with test coverage for both the regression and an edge case involving `%+d`. René’s feedback doesn’t block the fix but highlights a documentation opportunity. The discussion is unlikely to derail the patch, though it may prompt a follow-up to clarify the `%w()` behavior in the docs. For now, this looks like a straightforward bugfix with minimal risk.
