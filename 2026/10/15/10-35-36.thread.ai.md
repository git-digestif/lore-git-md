Subject: Proposal to deprecate `git format-rev`
Series version: N/A (standalone RFC)
Originating author: Kristoffer Haugsbakk
Thread type: feature deprecation proposal

Core problem or goal
The thread proposes deprecating the experimental `git format-rev` command on the grounds that its core functionality—pretty-formatting one revision at a time from stdin—is already provided by `git diff-tree --stdin --format=medium`. The existing pipeline additionally supports `--notes` (absent in `git format-rev`) and integrates with the full `rev-list` machinery (merge display, log-tree features). While `git format-rev` offers minor conveniences (direct revision expressions, object-name annotation in running text), these can be replicated by prepending `git cat-file --batch-command='%(objectname)'` to the pipeline.

Current status
Under discussion; no maintainer decision recorded. No prior version of this proposal exists.

Key technical details
- Command under discussion: `git format-rev` (experimental)
- Replacement pipeline: `git diff-tree --stdin --format=medium`
- Missing feature parity: `--notes` support in `git diff-tree` vs. none in `git format-rev`
- Workaround for object-name annotation: `git cat-file --batch-command='%(objectname)'`
- Subsystems touched: log-tree machinery, pretty-printing

Open questions and loose ends
- Whether the convenience of direct revision expressions and inline object-name annotation justifies keeping `git format-rev` despite the functional overlap.
- Whether any users or scripts rely on `git format-rev` in ways that cannot be replicated by the proposed pipeline.
- Whether the project is willing to deprecate an experimental command that has never graduated to stable status.

Participant positions
- Kristoffer Haugsbakk (author): argues the command’s raison d’être has been superseded and proposes deprecation.
