This is the first patch in the v3 series adding incremental connectivity checking for Git fetches and pushes. It introduces a new technical document (`Documentation/technical/connectivity-check.adoc`) that explains the connectivity invariant and the mechanics of the full connectivity check.

The patch is purely documentation and has already addressed all prior feedback about precision and maintainability. Patrick Steinhardt’s review here is surface-level, focusing on two minor points: adding the new document to the build system (Makefile and Meson) so it gets rendered in the HTML documentation, and clarifying a single awkward phrasing ("verified against these marks"). He also suggests documenting the promisor-remote fast path, though this is more of a suggestion than a blocker.

The document itself is thorough and well-structured, with a clear example graph that illustrates the trust boundary between incoming and already-connected commits. It stands alone as a reference for future contributors, so including it in the build system makes sense. The requested changes are small and unlikely to delay the series. This patch looks ready to land once the build system entries are added.
