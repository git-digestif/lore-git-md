Thread identity
Subject: `git help user-manual` fails on Git for Windows due to incorrect filename lookup
Series version: none (standalone bug report)
Originating author: John Wilson
Thread type: bug report

Core problem or goal
On Git for Windows, the command `git help user-manual` attempts to open `gituser-manual.html` instead of the correct filename `user-manual.html`, causing a "documentation file not found" error. The issue stems from a fallback logic in `cmd_to_page()` that prepends `"git"` to any page name not already starting with it, combined with `user-manual` not being listed in the `CAT_guide` category of `command-list.h`.

Current status
Reported; root cause identified. The issue is confirmed to be in the upstream Git help subsystem (`help.c` and `command-list.h` generator) rather than a Git for Windows packaging problem. No patch yet.

Key technical details
- Subsystem: help (`help.c`, `command-list.h` generator)
- Platform: Windows-specific (Git for Windows), but the bug is in upstream code
- Function: `cmd_to_page()` in `help.c`
- Header: `command-list.h` (generated during build)
- Category: `CAT_guide` (missing entry for `user-manual`)
- Expected filename: `user-manual.html`
- Actual filename attempted: `gituser-manual.html`
- Installed location: `C:\Program Files\Git\mingw64\share\doc\git-doc\`
- No new symbols, CLI options, or on-disk format changes
- Related commands: `git help --guides` (does not list `user-manual` due to missing `CAT_guide` entry)

Open questions and loose ends
- Whether to fix the issue by (a) adding `user-manual` to `CAT_guide` in `command-list.h`, or (b) modifying `cmd_to_page()` to avoid prefixing `"git"` for known non-command documentation targets
- Whether other documentation targets (e.g., `git help git`, `git help tutorial`) are affected by similar issues
- Confirmation that the fix does not break documentation lookup on non-Windows platforms
- Whether the `command-list.h` generator needs adjustment to handle similar cases in the future
