This is the first patch in the v12 series introducing `remote.<name>.fetchRefmap`, the new configuration key that decouples "what to fetch" from "where to store it" in Git's fetch machinery. The patch is part of a well-motivated, long-running effort to improve `git fetch` performance in shallow repositories by avoiding unnecessary history negotiation for untracked branches.

The patch adds the `remote.<name>.fetchRefmap` config variable, which provides the default value for the `--refmap` command-line option. Unlike `--refmap`, configuring `fetchRefmap` alone does not change what a refspec-less fetch does; it only specifies how fetched refs are mapped into the local namespace. When `remote.<name>.fetch` is also configured, it still determines what to fetch, and `fetchRefmap` only handles the mapping. This design cleanly resolves the earlier objection to overloading `remote.<name>.refmap` in v11, and the precedence rules are now settled: `remote.<name>.fetch` takes priority over `fetchRefmap`, which in turn takes priority over dynamic branch enumeration.

The implementation is thorough and well-tested. The patch updates `remote.c` and `remote.h` to parse and store the new config key, modifies `builtin/fetch.c` to use `fetchRefmap` as the default `--refmap` value when no command-line refmap is given, and updates `remote_find_tracking()` to fall back to `fetchRefmap` when `remote.<name>.fetch` has no match. The test coverage in `t/t5510-fetch.sh` is comprehensive, covering edge cases like negative refspecs, branches outside `remote.<name>.fetch`, and the interaction between `fetch` and `fetchRefmap`. The documentation updates are clear and precise, explaining the new config key's role and its relationship to existing configuration.

This is a high-quality, focused patch that implements a key piece of the v12 design. The series is now finalized in design, endorsed by Junio C Hamano and Phillip Wood, and under active review for merging. The only remaining work is addressing any minor nits from review, and the series is likely to graduate to `master` soon. If you care about fetch performance in shallow repositories or the design of Git's refspec machinery, this patch is worth reviewing.
