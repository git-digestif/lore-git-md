This is a brief, substantive review comment on the fifth patch in Patrick Steinhardt’s six-patch v2 series restoring dynamic reloading of alternate object databases. Christian Couder raises a potential edge case: if an alternate directory is removed after being added to the tracked set, the reordered logic in `odb_files_dir_is_usable()` will skip the `stat()` call and thus suppress the "object directory does not exist" error message. The question is whether this behavioral change is intentional or an unintended side effect of the performance optimization.

The patch itself is a clean, well-motivated reordering that eliminates redundant syscalls, and the benchmark data confirms a measurable speedup. However, Christian’s observation highlights a subtle trade-off between performance and user feedback. The commit message does not address this, so the intent is unclear. The answer will determine whether the patch needs adjustment or if the error suppression is an acceptable cost of the optimization. No other concerns are raised.
