This is the penultimate patch in Patrick Steinhardt’s 12-patch series modernizing `git rerere`’s subcommand handling. It replaces the custom string-based dispatch logic with Git’s standard `OPT_SUBCOMMAND()` mechanism, completing the conversion begun in earlier patches.

The patch touches only `builtin/rerere.c` and is purely mechanical: it adds the six subcommand entries to the option table, removes the old `if (!strcmp(...))` ladder, and introduces a fallback that invokes the new `cmd_rerere_record()` function when no subcommand is given. The commit message candidly notes a minor backwards-incompatible change—dropping the misleading `--[no-]rerere-autoupdate` flag from subcommands that never honored it—but frames it as a bug fix rather than a breaking change.

The implementation is clean and idiomatic, using `PARSE_OPT_SUBCOMMAND_OPTIONAL` so that `git rerere` without arguments still defaults to the “record” action. Memory management is handled correctly (the `args_copy` dance prevents leaks), and the patch preserves the existing usage strings and error messages.

This is a textbook refactoring: no new behavior, no new tests needed, and the risk is minimal. The series as a whole is now one patch away from being ready for `next`.
