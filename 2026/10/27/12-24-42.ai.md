This is the **core implementation patch (3/5)** in the **v12 "matching-inspired fetch mode" series**, which is **finalized in design** and **under active review for merging**. The patch enables `remote.<name>.fetchRefmap` to work **on its own** (without `remote.<name>.fetch`), dynamically inferring which branches to fetch from local branches whose `@{upstream}` points to the remote. The refmap itself still only controls **where** the fetched refs land, not **which** branches are selected.

The patch touches `builtin/fetch.c`, `remote.c`, and `remote.h`, adding the `branches_tracking_remote()` helper (which iterates over all local branches and collects those tracking the remote) and integrating it into `get_ref_map()`. When neither `remote.<name>.fetch` nor command-line refspecs are given, but `remote.<name>.fetchRefmap` is configured, the code now infers the refspecs from the local branches tracking the remote. The patch also updates the `ls-refs` prefix logic to handle the new dynamic branch selection, ensuring the server is asked for the correct refs.

The **documentation** (`remote.adoc` and `fetch-options.adoc`) is updated to explain the new behavior: when a refmap is active but no explicit refspec is given, `git fetch` infers what to fetch from local branches built on the remote. The **test coverage** (`t/t5586-fetch-refmap.sh`) is thorough, covering edge cases such as multiple local branches tracking the same remote branch (no duplicate fetches), branches tracking a different remote (not fetched), and prefetch behavior.
