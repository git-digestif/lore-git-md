This is a brief follow-up in the alternates reloading bugfix series. Patrick Steinhardt acknowledges Christian Couder’s identification of a race condition in patch 6/6: if the alternates file is rewritten in-place while Git is reading it, the `stat_validity` tracking could be updated with the new file metadata *after* the old content has already been parsed, causing Git to miss the new alternates indefinitely. The race is reproducible with the test added in patch 3, which explicitly uses an in-place rewrite.

Patrick accepts Christian’s proposed fix in principle: move the `stat_validity_update()` call *before* reading from the file descriptor, matching the pattern used in `refs/packed-backend.c` and `shallow.c`. He notes that the variant Christian pasted is subtly broken because it does not clear the stat cache when `open()` fails, but says he will adapt it for the next revision. The fix is mechanical and preserves the patch’s performance benefits while eliminating the edge case. No alternative approaches or objections have been raised. The series remains under review, with this race condition now the only unresolved technical issue in patch 6.
