This is the fourth patch in Jeff King's 8-patch series refactoring Git's unit test infrastructure to integrate `clar`-based unit tests with the shell test suite. The patch enables `test-lib.sh` to act as a thin wrapper for external programs that generate their own TAP output, addressing a key limitation that previously prevented unit tests from benefiting from `test-lib.sh`'s environment setup, logging, and leak detection.

The change is minimal and surgical: it modifies `test-lib.sh` to skip emitting the TAP header and plan count when `test_external` is set, while preserving the count for skipped tests (e.g., when `GIT_SKIP_TESTS` is active). This allows external TAP producers (like the `clar` unit tests in the next patch) to supply their own output without conflicts. The patch touches only `t/test-lib.sh`, adding a new case branch in `test_done()` and adjusting the TAP header logic to respect `test_external`.

The motivation is clear: the previous `test_external` interface was removed in 2022 for being overly complex, but its absence left a gap where external TAP generators couldn't leverage `test-lib.sh`'s infrastructure. This patch reintroduces a simpler variant of that functionality, paving the way for the next patch's integration of unit tests. The commit message explicitly ties this to the series' goal of improving debuggability in CI, where unit test failures currently lack the verbose logging available to shell tests.

The patch is uncontroversial and appears ready for integration. It builds directly on the earlier patches in the series (which fixed bugs in unit test error reporting and JUnit XML handling) and sets up the core integration in patch 5. No objections or requests for changes have been raised in the thread so far. The change is backward-compatible and doesn't affect existing shell tests. Key symbols introduced: `test_external` (a new variable controlling the wrapper behavior).
