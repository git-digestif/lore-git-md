This is the second patch in the v3 series introducing the `%gb` format placeholder to `git log -g` and `git reflog`. It implements the core functionality: the `%gb` placeholder itself, which names the branch `HEAD` was on when each reflog entry was recorded.

The patch adds the `%gb` placeholder to `pretty.c` and implements the branch-naming logic in `reflog-walk.c`. The new code parses reflog messages to determine the branch for each entry, handling edge cases like `git rebase <upstream> <branch>`, detached HEAD states, and branch renames. When `HEAD` was detached, the placeholder shows "detached at <commit>". For reflogs of other refs (not `HEAD`), `%gb` simply shows the shortened refname.

The implementation introduces a new `branches_marked` flag in `struct complete_reflogs` to track whether branch context has been determined, and a `mark_branches()` function that walks the reflog backward to assign branch names to each entry. The test script (`t/t1414-reflog-walk.sh`) adds 122 lines of coverage, validating edge cases like rebases, branch renames, detached HEAD states, and interaction with `--decorate`.
