This is a bugfix targeting the pack-objects subsystem in partial clones. The patch addresses a `BUG()` crash in `git pack-objects --exclude-promisor-objects-best-effort` when the revision walk encounters missing objects—specifically, trees of promisor commits that were filtered out (e.g., with `tree:0`) or lie beyond a shallow boundary. The crash occurs because the callback `is_not_in_promisor_pack_obj()` assumes all objects it sees exist, but in partial clones, missing objects are a normal condition.

The fix is minimal: instead of calling `BUG()` when `odb_read_object_info_extended()` fails, the callback now treats missing objects as promisor objects and skips them. This aligns with the existing behavior in `repack_local_links()`, which already handles missing objects gracefully. The commit message traces the regression to two sources: the original logic introduced in c08589efdc5 (2024-11-01) and a more recent change in d43b9acb05b (2026-07-07) that propagates `--shallow-file` to child processes, exposing the bug in new scenarios.

The patch includes two new test cases in `t/t5616-partial-clone.sh`. One exercises `--unshallow` and `--deepen=1` with a `tree:0` filter, verifying that the fetch succeeds and the repository remains consistent. The other explicitly tests the missing-tree scenario by unshallowing a repository with a filter that omits trees, then fetching a descendant of a local non-promisor commit. Both tests confirm that `git fsck` passes after the operation.

The change is narrowly scoped to the callback function and does not alter the broader promisor-object handling logic. The rationale—that a missing object cannot be a local non-promisor object—is sound and matches the project’s existing assumptions. The patch is authored by Patrick Steinhardt, the primary maintainer of the promisor/partial-clone subsystem, and includes a `Reported-by` trailer crediting the issue’s discoverer. The test coverage is thorough and reproduces the exact conditions that trigger the crash.
