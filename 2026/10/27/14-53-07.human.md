This is the eighth and final patch in Patrick Steinhardt’s CI/build system series, which consolidates test environment variables across GitHub Actions and GitLab CI. The patch introduces a `--feature-testbed` flag for the test suite, making it easier for developers to reproduce the CI’s "feature-testbed" job locally by setting the same `GIT_TEST_*` environment variables used in CI. The change replaces hardcoded variable exports in `ci/lib.sh` with a single flag, centralizing the configuration in `t/test-lib.sh` and ensuring it works for both shell and unit tests.

Phillip Wood’s review is substantive but narrowly focused. He notes that the commit message could clarify that the "feature-testbed" job also sets `OPENSSL_SHA1_UNSAFE`, which the new `--feature-testbed` flag does *not* replicate—this is intentional, as the flag only handles `GIT_TEST_*` variables. He also flags the `set_default_env()` helper’s use of `eval` as initially confusing but ultimately correct, confirming that the logic properly checks whether a variable is unset before assigning it. The review is thorough but does not raise functional concerns; the feedback is about clarity rather than correctness.

The patch itself is well-motivated and mechanical, completing the series’ goal of reducing CI redundancy while improving developer ergonomics. The new flag is a sensible addition, and the helper function’s design (preserving existing overrides) avoids breaking existing workflows. This is unlikely to be controversial, but Phillip’s observation about `OPENSSL_SHA1_UNSAFE` might prompt a minor commit message tweak. Worth a quick review for CI maintainers, but no major red flags.
