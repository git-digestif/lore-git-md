This is the sixth and final patch in Patrick Steinhardt’s v2 series fixing a regression in Git’s ability to dynamically reload alternate object databases. The patch introduces `stat_validity` tracking to avoid unnecessary re-reads of the alternates file when it hasn’t changed, but Christian Couder identified a race condition: if the file is rewritten in-place while Git is reading it, the `stat_validity` update could happen *after* the old content is parsed, causing Git to miss new alternates indefinitely. The test added in patch 3 explicitly uses an in-place rewrite, making the race reproducible.

Patrick acknowledges the issue and agrees to adopt Christian’s proposed fix: moving `stat_validity_update()` *before* reading the file (matching the pattern in `refs/packed-backend.c` and `shallow.c`) and clearing the validity only on read failure. The change is mechanical and preserves the patch’s performance benefits. The fix will appear in the next revision of the series, which is otherwise complete and addresses all known functional regressions. This patch is part of a well-motivated bugfix effort with thorough test coverage and clear performance measurements; it looks ready for `next` once the race is resolved.
