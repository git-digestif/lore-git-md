This is the fourth iteration of a four-patch bugfix series for `git imap-send`, addressing interoperability issues with tools like `b4` that produce non-canonical email header order (e.g., `Subject` before `Date`) and case variations (e.g., `FROM:`). The series is now nearly ready for integration, with only minor follow-up tweaks expected.

The core problem is that `git imap-send` previously rejected patches where headers appeared in an unexpected order or case, breaking workflows that rely on `b4` to fetch patches from lore.kernel.org. The fix makes the header-parsing logic order-agnostic and case-insensitive, ensuring RFC 5322 compliance while maintaining backward compatibility. It also plugs a tunnel-command memory leak and removes a special-case exemption for `git send-email` messages, treating all messages uniformly.

Key changes in this version (`v4`) include converting `imap->tunnel` to an allocated pointer to ensure `finish_command()` is only called on initialized instances (addressing Patrick Steinhardt’s defensive coding feedback), adding a test for lowercase headers to explicitly verify case insensitivity, and expanding the commit message for Patch 3/4 to clarify why dropping the `git-send-email` special case is safe. The series touches only `imap-send.c` and adds tests in `t/t9001-send-email.sh`.

Patch 1/4 (tunnel process lifecycle) was merged to `next` in `v3` but received follow-up feedback; the `v4` update resolves this by making `imap->tunnel` a pointer and simplifying the code. Patches 2/4 (order-agnostic parsing) and 4/4 (case-insensitive matching) are uncontroversial and ready for integration. Patch 3/4 (removal of the `git-send-email` special case) now includes a clearer backward-compatibility rationale, addressing Patrick’s earlier documentation concern.

The series is well-motivated, with thorough test coverage and minimal risk of regression. The remaining patches are queued in `seen` and should graduate to `next` soon.
