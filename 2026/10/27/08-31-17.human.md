This is the second patch in Harald Nordgren’s four-part bugfix series for `git imap-send`, addressing a long-standing interoperability issue with tools like `b4`. The patch makes `git imap-send` accept email messages where the `Subject` header appears before the `Date` header, a valid but non-canonical order that `git send-email` and other tools produce. Previously, `imap-send` would silently skip such messages, causing workflows like `b4 mbox --single-message | git imap-send` to fail with “no messages found to send.”

The fix replaces the brittle, order-dependent parsing logic with a new helper function `has_required_headers()` that scans the header block for `From:`, `Date:`, and `Subject:` in any order. The change is minimal and focused: it touches only the message-counting logic in `imap-send.c` and adds a single test in `t/t9001-send-email.sh` that verifies the new behavior by feeding a real patch through a fake IMAP server. The test is realistic and exercises the exact workflow that previously failed.

This patch is uncontroversial and ready for integration. The problem is real (interoperability with `b4`/`lore.kernel.org`), the solution is clean, and the test coverage is thorough. The commit message clearly explains the motivation and the change, and the code itself is straightforward. There are no open questions or blocking feedback; the only prior concern (case sensitivity) is addressed in a later patch in the series. The patch is part of a larger effort to make `git imap-send` fully RFC 5322-compliant, but it stands on its own as a well-motivated bugfix.
