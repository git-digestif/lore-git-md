This is the v4 cover letter for a two-patch CI/build system series that makes Perforce, Git LFS, and JGit installation failures fatal on the platforms that require them, while cleaning up redundant or ineffective steps. The series is now focused and ready for final review.

The core goal remains unchanged: reduce CI log noise by ensuring warnings and failures for these tools occur only on platforms where they are actually needed. The v4 iteration addresses the last technical nit from earlier rounds—removing redundant `&&` chains in the installation steps, which could silently allow failures to slip through despite `set -e` being active. This change makes the script’s error handling consistent and reliable, matching how every other install step in the file already works.

Patch 1/2 drops the macOS quarantine-removal step for Perforce binaries, which has been a no-op since 2022 when the install method switched from Homebrew to direct downloads. The commit message now clearly explains why the call is unnecessary (wget downloads never set the quarantine attribute) and confirms this holds on both GitHub Actions and GitLab CI. Patch 2/2 implements the stricter behavior: installation failures for Perforce, Git LFS, or JGit now immediately fail the build on ubuntu-* and macos-* platforms, with version output printed right after successful installation for confirmation.

The series has converged on a design that both Junio C Hamano and Patrick Steinhardt have accepted in principle, though neither has yet provided a formal Reviewed-by. The changes are confined to `ci/install-dependencies.sh` and do not affect Git’s functionality—only CI behavior. The patches are small, well-explained, and address a real annoyance for anyone reading CI logs. This looks like a straightforward improvement that should land soon.
