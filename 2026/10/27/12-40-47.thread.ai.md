Subject: [PATCH v2] Makefile: enable ccache sloppiness for precompiled header
Series version: standalone patch, v2 (now effectively superseded by upstream Meson change)
Originating author: Harald Nordgren
Thread type: build system patch

Core problem or goal
Enable ccache to cache objects built with Git’s precompiled header (introduced in 8d3a673147) by setting ccache “sloppiness” flags (`pch_defines`, `time_macros`). Without these flags ccache refuses to cache such objects, causing a performance regression on rebuilds and branch switches.

Current status
Resolved. The original Makefile patch (v2) is no longer needed because the same ccache sloppiness settings have been merged upstream in Meson (PR #16317). Both build systems now automatically enable the required ccache flags when precompiled headers are used, eliminating the cross-build-system inconsistency. No further Git-side changes are required.

Key technical details
- Files touched: `Makefile` (v2 patch was minimal, but now moot)
- New/changed variables: `CCACHE_SLOPPINESS` (appended `pch_defines,time_macros` in v2; now handled upstream in Meson)
- Related commit: 8d3a673147 (“Makefile: precompile 'git-compat-util.h'”)
- On-disk format: unchanged
- Test coverage: none (build system changes rarely have dedicated tests)
- Performance: 3× warm-cache rebuild speedup, 6× branch-switching speedup; first build of each branch ~25 % slower while ccache fills cache
- Edge case: Clang still misses cache when switching branches that modify headers included by the precompiled header, due to mtime recording in the PCH

Open questions and loose ends
None. The cross-build-system consistency question raised in earlier messages is now resolved by the upstream Meson change.
