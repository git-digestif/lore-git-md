Subject: [PATCH] Makefile: enable ccache sloppiness for precompiled header
Series version: standalone patch (no series)
Originating author: Harald Nordgren
Thread type: build system patch

Core problem or goal
Enable ccache to cache objects built with Git’s precompiled header (introduced in 8d3a673147) by setting two ccache “sloppiness” flags (`pch_defines`, `time_macros`). Without these flags ccache refuses to cache such objects, causing a performance regression on rebuilds and branch switches.

Current status
Under review; no prior versions posted. Patch is minimal (two-line Makefile change) and targets only the ccache/PCH interaction. Implementation questions about Makefile semantics (target-specific export propagation) and cross-build-system consistency (Meson unmodified) remain unresolved, but the patch’s core premise is uncontested.

Key technical details
- Files touched: `Makefile` (Meson build system remains unmodified)
- New/changed variables: `CCACHE_SLOPPINESS` (appends `pch_defines,time_macros`)
- Related commit: 8d3a673147 (“Makefile: precompile 'git-compat-util.h'”)
- On-disk format: unchanged
- Test coverage: none (build system changes rarely have dedicated tests)
- Performance: 3× warm-cache rebuild speedup, 6× branch-switching speedup; first build of each branch ~25 % slower while ccache fills cache
- Edge case: Clang still misses cache when switching branches that modify headers included by the precompiled header, due to mtime recording in the PCH

Open questions and loose ends
1. Does `export CCACHE_SLOPPINESS` attached to a target-specific rule in GNU Make propagate to recipe processes as intended? (Ben Knoble questions semantics; Harald acknowledges but does not resolve)
2. Should the variable be set directly in the two precompiled header recipes instead of using target-specific export? (Harald agrees this could be a good idea but does not provide a revised patch)
3. The Meson build system is not modified, creating potential inconsistency for ccache users depending on build tool. (Harald frames this as out of scope for the patch)

Participant positions
