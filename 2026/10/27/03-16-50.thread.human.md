This thread is an RFC patch series by Pablo Sabater that introduces batching to `git cat-file --remote-object-info` to remove the current 10k OID limit. The goal is to improve performance for large metadata queries—testing shows a 400k OID query now completes in 1.82s instead of 5.86s—while also addressing server-side resource exhaustion risks by proposing a server-advertised OID limit via a new capability.

The series remains under review as an RFC, with no code updates yet. Junio C Hamano has reviewed the first patch and the cover letter, engaging in a substantive discussion with Pablo about error message wording and design trade-offs. A key recent development is Pablo’s proposal to remove the early `smart_options` check in patch 1, instead relying on the existing `transport_fetch_object_info()` check later in the code path. This resolves Junio’s forward-compatibility concern and simplifies the error message to something like "object-info is not supported by <remote>", which is both accurate and user-friendly. The broader design questions—whether to implement the server-side OID limit, how to handle client/server mismatches, and the appropriateness of the 50k default batch size—remain open. Pablo plans to send a v2 later this week to incorporate this change and any further feedback. The series touches only the client side and transport layer, with no on-disk format changes.
