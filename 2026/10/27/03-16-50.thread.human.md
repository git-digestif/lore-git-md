This thread is an RFC patch series by Pablo Sabater that introduces batching to `git cat-file --remote-object-info`, removing the current 10k OID limit. The series is now complete with three patches: refactoring transport ownership, implementing internal batching, and adding a `--remote-max-batch` option (default: 50k OIDs). Performance gains are significant—400k OIDs now complete in 1.82s versus 5.86s under the old limit.

Junio C Hamano has reviewed the first patch, endorsing the refactoring but requesting a clearer error message for the "smart options required" condition. The latest feedback from Junio raises two key points: first, a minor suggestion to align the 50k default batch size with `git backfill`'s default for documentation simplicity, and second, a more critical question about backwards compatibility. Junio wants to know whether updated clients will break when talking to older servers, or vice versa, signaling that this needs explicit testing and documentation before the series can move forward. The series remains under review, with GitHub CI passing all patches, but no merge status reported yet. Open questions include whether the server should enforce its own OID limit and whether the 50k default is appropriate for all use cases.
