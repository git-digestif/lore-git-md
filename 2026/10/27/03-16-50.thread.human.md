This thread is an RFC patch series by Pablo Sabater proposing `git cat-file --remote-object-info` batching to remove the current 10k OID limit. The series, now complete with three patches, refactors transport ownership, implements internal batching (defaulting to 50k OID chunks), and adds a `--remote-max-batch` option. The goal is to improve performance for large metadata queries—benchmarks show a 3x speedup for 400k OIDs.

Junio C Hamano has reviewed the first patch, focusing on code clarity. He supports the refactoring and variable rename but flags the error message `"smart options required"` as confusing for users. This feedback will likely require a revision before the series moves forward. No other reviews have been posted yet, and the series remains under review with no merge status. Open questions include whether the server should enforce its own OID limit and whether the 50k default batch size is universally appropriate. The implementation touches transport and cat-file internals but makes no on-disk format changes.
