This thread is an RFC patch series by Pablo Sabater that introduces batching to `git cat-file --remote-object-info`, removing the current 10k OID limit. The goal is to improve performance for large metadata queries—400k OIDs now complete in 1.82s instead of 5.86s—while addressing server resource risks via a proposed server-advertised OID limit.

The series remains under review at version 1, with three patches covering transport refactoring, internal batching, and a new `--remote-max-batch` option (default: 50k OIDs). Junio C Hamano has reviewed the cover letter and first patch, and the latest exchange resolves his earlier concern about error message clarity: Pablo’s proposal to remove the early `smart_options` check in favor of the more robust `transport_fetch_object_info()` check was endorsed. This change also allows dynamic inclusion of the remote’s URL in error messages. Broader design questions—such as whether to implement the server-side OID limit and how to handle client-server mismatches—remain open, but Pablo plans to send a v2 soon incorporating this and other feedback. The thread is still in the design phase, with no merge status reported.
