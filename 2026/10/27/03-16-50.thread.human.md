This thread is an RFC patch series by Pablo Sabater that removes the 10,000-OID limit in `git cat-file --remote-object-info` by implementing internal batching. The series is now complete with all three patches posted: (1) a preparatory refactor to extract transport ownership, (2) the core batching logic, and (3) the new `--remote-max-batch` option (default: 50,000 OIDs) to let users tune the batch size.

The change is motivated by performance: a test with 400,000 OIDs now finishes in 1.82 seconds instead of 5.86 seconds under the old limit. The implementation reuses connections between batches and performs the handshake only once per command. Tests cover edge cases (invalid values, batch boundaries) across all transport protocols. No review feedback has arrived yet, but the code is clean and the test coverage looks thorough.

Two open questions remain: whether the server should enforce its own OID limit for object-info requests, and whether the 50k default batch size is appropriate for all use cases. The series is still marked as an RFC, so these questions—and any review comments—will likely shape the next iteration.
