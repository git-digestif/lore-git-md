This thread is an RFC patch series by Pablo Sabater introducing `git cat-file --remote-object-info` batching to remove the current 10k OID limit. The goal is to improve performance for large metadata queries by internally batching requests, with Pablo reporting a 3x speedup (1.82s vs. 5.86s) for 400k OIDs. The series also proposes a server-advertised OID limit via a new capability to mitigate resource exhaustion risks.

The series remains under review as an RFC, with no merge status reported. It consists of three patches: (1) refactoring to extract transport ownership, (2) implementing internal batching, and (3) adding the `--remote-max-batch` CLI option (default: 50k OIDs). Junio C Hamano has reviewed the cover letter and patch 1, and the only remaining critique—a request for a clearer error message—has now been addressed through discussion. Pablo proposed "object-info is not supported on bundles," but Junio raised a forward-compatibility concern, suggesting a more generic message like "object-info is not supported by this remote" or a dynamic version if the remote’s identity is available. This exchange resolves the last concrete feedback on patch 1, leaving the broader design questions—such as whether to implement the server-side OID limit, how to advertise it, and the default batch size—as the main open items.

Key technical details include the new `--remote-max-batch` option, internal batching logic (50k-OID chunks by default), and connection reuse between batches. The series touches `builtin/cat-file.c`, `transport-helper.c`, and related files, with new test coverage in `t/t1017-cat-file-remote-object-info.sh`. No on-disk format changes are involved, and backwards compatibility is preserved, though the server-side limit proposal introduces a new capability negotiation mechanism. Pablo and Junio are the primary participants, with Pablo driving the implementation and Junio providing substantive review feedback. The thread is still in the design phase, with no code updates yet.
