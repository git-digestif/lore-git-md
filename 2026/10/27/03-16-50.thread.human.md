This thread is an RFC patch series by Pablo Sabater that removes the 10,000-OID limit in `git cat-file --remote-object-info` by introducing internal batching. The goal is to improve performance for large metadata queries—testing shows a 3× speedup (1.82s vs. 5.86s) when querying 400,000 OIDs.

The series is now two-thirds posted. The first patch (already sent) refactored transport ownership, while this second patch implements the core batching logic. It splits OIDs into 50,000-OID chunks, reuses the same transport connection, and converts the fetch-object-info API to die on failure (matching `git ls-remote`). The third patch, not yet sent, will add the `--remote-max-batch` option to let users adjust the chunk size. No reviews have been posted yet, and the series remains under initial discussion. Open questions include whether the server should enforce its own OID limit and how to benchmark the change effectively.
