This is a refactoring and test infrastructure patch series from Jeff King (Peff) that overhauls how Git's unit tests (written with the `clar` framework) are executed and reported. The series addresses a long-standing pain point: unit test failures in CI are hard to debug because their TAP output is swallowed by `prove`, unlike the shell-based test suite which dumps verbose logs. The core change (patch 5) wraps the unit test binary in a standard `test-lib.sh` script, ensuring it benefits from the same environment setup, leak detection, and logging as the rest of the test suite.

The first three patches fix bugs uncovered during the refactoring: patch 1 corrects argument reporting in unit tests, patch 2 removes an unused variable in `test-lib.sh`, and patch 3 stops generating misleading JUnit XML for empty test suites. Patch 4 extends `test-lib.sh` to accept TAP output from external programs, enabling the integration in patch 5. The remaining patches clean up redundant test invocations (patch 6), remove a deprecated `test-tool run-command` mode (patch 7), and eliminate the now-unused shell-based JUnit XML reporting code (patch 8), yielding a net deletion of ~400 lines.

The series is well-motivated and technically sound, with clear commit messages and a logical progression. Peff explicitly marks the last two patches as RFC, suggesting they may need further discussion, but the rest appear ready. The cleanup is substantial, removing obsolete infrastructure while improving debuggability. Key files touched include `t/test-lib.sh`, `t/Makefile`, and the new `t/t0011-unit-tests.sh` wrapper script. The series also obviates recent workarounds for ignored test-lib options in unit tests, though it doesn’t address those directly.
