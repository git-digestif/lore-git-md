This is the first patch in a two-part feature series that introduces a `%gb` format placeholder for `git log -g` and `git reflog`, showing which branch `HEAD` was on for each reflog entry. This patch is a preparatory refactoring that names the hard-coded strings used in reflog messages for branch switches, renames, and rebase steps.

The change is mechanical: it moves seven string constants (`REFLOG_SWITCH_PREFIX`, `REFLOG_RENAME_PREFIX`, `REFLOG_STEP_START`, `REFLOG_STEP_FINISH`, `REFLOG_STEP_ABORT`, `REFLOG_RETURNING_TO`, and `REFLOG_CHECKOUT`) into `reflog.h` and updates all call sites in `builtin/branch.c`, `builtin/checkout.c`, `builtin/rebase.c`, `object-name.c`, `sequencer.c`, and `wt-status.c` to use these constants. The patch touches 33 lines across 7 files, with no behavior changes.

This refactoring is explicitly tied to the upcoming `%gb` feature in patch 2/2, replacing the earlier motivation of supporting the now-abandoned `--operations` flag. The constants will be used by the `%gb` implementation to parse reflog messages and determine branch context for each entry. The patch is well-scoped and uncontroversial, serving as a clean foundation for the feature. No test changes are included, as the behavior remains unchanged.
