This is the fourth patch in Jeff King’s (Peff) 8-patch series refactoring Git’s unit test infrastructure to integrate `clar`-based unit tests with the shell test suite. The patch enables `test-lib.sh` to act as a thin wrapper for external programs that generate their own TAP output, a prerequisite for the next patch (5/8) which will wrap the `clar` unit tests.

The change is minimal and surgical: `test-lib.sh` now checks for the new `test_external` variable before emitting its own TAP header and plan count. If `test_external` is set, the script skips these outputs entirely, letting the external program’s TAP stand alone. The only exception is when the entire script is skipped via `GIT_SKIP_TESTS`—in that case, `test-lib.sh` still emits a count (since the external program wouldn’t run at all). The patch touches only `t/test-lib.sh`, adding 6 lines and removing 3.

This is a well-motivated refactoring with no behavioral side effects. The commit message clearly explains the rationale (restoring a simpler version of the `test_external` functionality removed in 2022) and the real-world benefit (enabling the next patch’s integration of `clar` unit tests). The change is uncontroversial and appears ready for integration. If you’re following the series, this patch is a straightforward but necessary step toward the larger goal of unifying test execution environments.
