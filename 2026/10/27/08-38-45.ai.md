This is a feature patch series (v3) that introduces a `%gb` format placeholder to `git log -g` and `git reflog`, allowing users to see which branch `HEAD` was on when each reflog entry was recorded. The series is a major redesign of the earlier `--operations` and `--historical-branch` flags, now replaced by a single composable format specifier that aligns with Git’s existing decoration system.

The core change is in patch 2/2, which adds the `%gb` placeholder. This placeholder names the branch for each reflog entry by parsing messages left by branch switches, renames, and rebases. It handles edge cases like `git rebase <upstream> <branch>`, detached HEAD states, and branch renames, showing "detached at <commit>" when `HEAD` was detached. The implementation touches 12 files, including core reflog-walking logic (`reflog-walk.c`, `revision.c`), built-in commands (`builtin/rebase.c`, `builtin/checkout.c`), and documentation. The test script (`t/t1414-reflog-walk.sh`) has grown to 122 lines, covering scenarios like rebases, branch renames, and detached HEAD states.

Patch 1/2 is a preparatory refactoring that names the strings marking reflog entries for switches, renames, and rebase steps (e.g., `REFLOG_SWITCH_PREFIX`, `REFLOG_RETURNING_TO`). This refactoring is now explicitly tied to the `%gb` feature, replacing the earlier motivation of supporting `--operations`. The changes are mechanical and do not alter behavior.

The series addresses the thread’s earlier critiques by abandoning the dedicated flags in favor of format specifiers, which are more flexible and composable. The `%gb` placeholder also avoids the UX trade-off of replacing commit decorations, as users can now include branch names in custom formats without losing other decorations.
