This is a CI/build system patch, part of Patrick Steinhardt’s ongoing effort to consolidate Git’s CI test environments. It aligns test behavior with the project’s default ref storage backend (reftable) when breaking changes are enabled, mirroring how SHA-256 is already handled.

The patch removes the now-redundant `linux-reftable-sha256` CI job from both GitHub Actions and GitLab CI workflows, since the default ref storage format will automatically be used in breaking-change jobs. It also updates the test infrastructure (`t/test-lib-functions.sh` and `t/test-lib.sh`) to respect the compiled-in default ref storage format (`GIT_TEST_BUILTIN_REF_STORAGE_FORMAT`) instead of hardcoding "files" as the fallback. This ensures tests exercise the reftable backend when appropriate, improving coverage for the project’s future default.

The change is small but meaningful: it eliminates 8 lines of redundant CI configuration while adding 4 lines of logic to centralize the ref storage format selection. The motivation is clear—reducing drift between CI and production defaults—but the commit message doesn’t detail specific bugs or inconsistencies this fixes, leaving the urgency slightly understated. The patch is well-targeted and mechanically sound, fitting neatly into the broader CI cleanup series.

No objections or feedback have surfaced yet, but reviewers may question whether the removal of the explicit `linux-reftable-sha256` job could mask regressions if the default ref storage format isn’t properly detected in all environments. The patch assumes the `version --build-options` output is reliable, which seems reasonable but could be worth verifying in follow-up discussion.
