This thread is about Patrick Steinhardt’s seven-patch series cleaning up Git’s CI infrastructure by consolidating test environment variables across GitHub Actions and GitLab CI. The goal is to reduce duplication, improve maintainability, and ensure consistent test environments—such as default ref storage formats—across platforms. The series introduces a new `NO_RUST` build variant using glibc, centralizes environment variable overrides in `ci/lib.sh`, replaces per-distribution variable assignments with platform-wide rules, and aligns test behavior with Git’s compiled-in defaults. The eighth patch, which proposed a `--feature-testbed` flag, was dropped after reviewers (including Junio C Hamano, Jeff King, and Phillip Wood) preferred a simpler `FEATURE_TESTBED=1` environment variable approach, though that alternative was ultimately abandoned.

The series is now ready for Junio’s `next` branch, following explicit endorsements from Jeff King, Phillip Wood, and Toon Claes. Junio’s latest email confirms the procedural sign-off, marking the end of the review cycle. Key changes include consolidating redundant CI job configurations (e.g., removing the `linux-reftable-sha256` job by relying on compiled-in defaults), restoring non-Rust test coverage lost after the April 2026 default-enable-Rust commit, and improving documentation for the "feature-testbed" job. The patches touch CI workflow files (`.github/workflows/main.yml`, `.gitlab-ci.yml`), `ci/lib.sh`, and test infrastructure (`t/test-lib.sh`, `t/test-lib-functions.sh`), but introduce no on-disk format changes. Open questions about the urgency of the cleanup and the unresolved tension between developer ergonomics and CI reproducibility remain, but the series itself is uncontroversial and procedurally unblocked.
