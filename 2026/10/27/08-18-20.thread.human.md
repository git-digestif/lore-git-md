This thread is about Patrick Steinhardt’s v2 patch series (seven patches) to clean up Git’s CI infrastructure by consolidating test environment variables across GitHub Actions and GitLab CI. The goal is to reduce duplication, improve maintainability, and ensure consistent test environments—such as default ref storage formats—across platforms. The series introduces a new `NO_RUST` build variant, improves documentation for the "feature-testbed" job, replaces per-distribution variable assignments with platform-wide rules, and aligns test behavior with Git’s compiled-in defaults.

The series is under review and largely uncontroversial. Patches 1–7 have received positive feedback from Jeff King ("obviously good"), Phillip Wood ("nice"), and Toon Claes ("noncontroversial and good"). The latest email covers the fifth patch, which removes a redundant CI job (`linux-reftable-sha256`) by ensuring tests use the compiled-in default ref storage format when "breaking changes" (e.g., SHA-256) are enabled. This change preserves test coverage while eliminating redundancy. The series is expected to be merged as-is, pending Junio C Hamano’s final confirmation.

The only prior point of contention—patch 8/8, which proposed a `--feature-testbed` flag—was dropped entirely after reviewers (including Junio and Jeff King) favored a simpler `FEATURE_TESTBED=1` environment variable. Patrick Steinhardt abandoned the patch, leaving the broader CI consolidation effort unaffected. The series addresses a gap in test coverage for non-Rust builds created by the April 2026 default-enable-Rust commit.
