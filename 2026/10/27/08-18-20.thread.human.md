This thread is a cleanup of Git’s CI infrastructure, consolidating test environment variables across GitHub Actions and GitLab CI to reduce duplication and improve maintainability. The series, authored by Patrick Steinhardt, introduces a new `NO_RUST` build variant, centralizes environment variable overrides, and aligns test behavior with Git’s compiled-in defaults for ref storage. Patches 1–7 are uncontroversial and widely endorsed—Jeff King called them "obviously good," and Toon Claes recently echoed that assessment, describing them as straightforward and well-motivated. These patches are likely to be merged as-is once the series is rerolled.

The sticking point has been patch 8/8, which initially proposed a `--feature-testbed` command-line flag to toggle build and test settings. Jeff King, Junio C Hamano, and Phillip Wood all raised concerns about its inconsistency (e.g., omitting `OPENSSL_SHA1_UNSAFE`) and complexity, instead endorsing a simpler `FEATURE_TESTBED=1` environment variable. Patrick has confirmed he will reroll the patch to adopt this design, incorporating Junio’s shell quoting fix for portability. Toon Claes’s recent reply acknowledges the trade-offs but doesn’t challenge the consensus, leaving the environment variable approach as the clear path forward. The series is now awaiting a reroll of patch 8/8 before it can proceed to integration.
