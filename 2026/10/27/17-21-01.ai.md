This is a **design clarification** in the ongoing `fetch: introduce +: refspec for matching-inspired fetch mode` series (v12). The email exchanges a key technical point about **backwards compatibility** and **refspec interpretation** in older Git versions, confirming that the v12 design (using `remote.<name>.fetchRefmap`) is sound.

Junio C Hamano clarifies how older Git versions interpret `remote.<name>.fetch` when it is used to list source refs (e.g., `refs/heads/master`, `refs/heads/next`). Without a `refmap` (or the new `fetchRefmap`), older versions treat these entries as **fetch-only refspecs**—they fetch the refs but store them only in `FETCH_HEAD`, not in the local ref namespace. This means `git pull` still works (via `FETCH_HEAD`), but the refs are not stored in `refs/remotes/`. This behavior is **safe** (no silent corruption of local branches) but **incomplete** (no persistent tracking refs). The v12 design avoids this ambiguity by using `remote.<name>.fetchRefmap` for the "what to fetch" logic, ensuring older Git versions either ignore the new key or fail cleanly.

The discussion also confirms the **placement of forced updates (`+`)**. Junio’s example (`fetch = master`, `fetch = next`, `refmap = +refs/heads/*:refs/remotes/cabal/*`) shows that `+` belongs on the **refmap side** (the "where"), not the `fetch` side (the "what"). This aligns with the v12 design but introduces a **minor user-facing inconvenience**: users who want to reject non-fast-forward updates for some branches while mapping all refs the same way must now use **two separate refspecs** (one with `+` and one without). This is **not a blocker** for graduation but may require documentation clarification.

**Key takeaways for the series**:
- The v12 design (`remote.<name>.fetchRefmap`) is **backwards-compatible** and **avoids the pitfall** Phillip Wood raised (older Git versions misinterpreting `remote.<name>.fetch` as a refspec with an implicit destination).
- The **precedence rule** (`remote.<name>.fetch` > `remote.<name>.fetchRefmap` > dynamic branch enumeration) and **forced update placement** (`+` on the refmap side) are **finalized**.
