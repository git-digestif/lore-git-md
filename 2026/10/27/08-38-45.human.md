This is a feature patch that adds a `%gb` format placeholder to `git log -g` and `git reflog`, letting users see which branch `HEAD` was on when each reflog entry was recorded. The v3 series drops the earlier `--operations` and `--historical-branch` flags in favor of the more composable format specifier, addressing reviewer feedback that the original approach was too rigid and had correctness gaps.

The implementation touches 12 files, primarily `reflog-walk.c` (156 new lines) and a new 122-line test script (`t/t1414-reflog-walk.sh`). The core logic walks the reflog backward, parsing messages left by branch switches, renames, and rebases to determine the branch context for each entry. The patch handles edge cases like `git rebase <upstream> <branch>`, detached HEAD, and branch renames, and includes thorough test coverage for these scenarios.

The motivation is clear: reflog output currently mixes work from all branches, making it hard to track which changes belong to which branch. The `%gb` placeholder addresses this by decorating each entry with its branch context, e.g., `(topic) rebase (finish): returning to refs/heads/topic`. This is a targeted improvement to the reflog subsystem, avoiding broad refactoring while adding useful functionality for debugging and auditing workflows.

The series looks well-crafted and responsive to review feedback. The shift to a format specifier aligns with Git’s existing decoration system and avoids the UX trade-offs of dedicated flags. The test coverage is robust, and the implementation appears to handle the edge cases raised in earlier reviews. This is likely to be of interest to users who rely on reflogs for understanding branch history.
