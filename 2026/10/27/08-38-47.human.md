This is the second patch in a two-part feature series (v3) that adds a `%gb` format placeholder to `git log -g` and `git reflog`, allowing users to see which branch `HEAD` was on when each reflog entry was recorded. The series replaces the earlier `--operations` and `--historical-branch` flags with a composable format specifier that aligns with Git’s decoration system.

The patch implements the `%gb` placeholder by parsing reflog messages left by branch switches, renames, and rebases. It handles edge cases like `git rebase <upstream> <branch>`, detached HEAD states, and branch renames, showing "detached at <commit>" when `HEAD` was detached. The implementation walks the reflog backward to determine the correct branch, addressing Phillip Wood’s earlier correctness concerns. For non-`HEAD` reflogs (e.g., `git log -g main`), `%gb` simply shows the shortened refname.

The code touches `reflog-walk.c`, `pretty.c`, and `reflog-walk.h`, adding a `branches_marked` flag to track whether branch context has been determined and a `get_reflog_branch()` function to populate the `%gb` output. The test script (`t/t1414-reflog-walk.sh`) grows by 122 lines, validating edge cases like rebases, branch renames, and detached HEAD states. The implementation is additive and does not alter default behavior, reducing regression risk.
