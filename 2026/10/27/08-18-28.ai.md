This is the eighth and final patch in Patrick Steinhardt’s CI/build system series consolidating test environment variables across GitHub Actions and GitLab CI. It makes the "feature-testbed" job more accessible to developers by introducing a `--feature-testbed` flag for the test suite, which sets the same `GIT_TEST_*` environment variables used in CI. The patch replaces 11 lines of hardcoded variable exports in `ci/lib.sh` with a single flag assignment, documents the new option in `t/README`, and adds the flag to `t/test-lib.sh` and `t/unit-tests/unit-test.c` to ensure it’s recognized by both shell and unit tests.

The change is mechanical and well-motivated: it eliminates redundancy by centralizing the feature-testbed configuration in `t/test-lib.sh`, making it easier for developers to reproduce CI test environments locally. The new `set_default_env()` helper ensures existing variable overrides aren’t clobbered, preserving flexibility. The patch completes the series’ goal of consolidating CI logic while improving developer ergonomics—no functional changes to test behavior, just cleaner infrastructure. Worth a quick review for anyone maintaining CI or test scripts, but unlikely to be controversial.
