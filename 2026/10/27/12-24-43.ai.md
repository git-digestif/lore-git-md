This is the fourth patch in the v12 series introducing `remote.<name>.fetchRefmap` for matching-inspired fetch mode. The patch adds a `--limited-fetch` flag to `git remote add`, which configures `remote.<name>.fetchRefmap` (e.g., `*@{upstream}`) instead of the traditional `remote.<name>.fetch` wildcard refspec. This ensures that a refspec-less `git fetch <name>` only fetches branches tracked by local branches at the remote, addressing the original motivation: slow or hanging fetches in shallow repositories with many remote branches.

The implementation is clean and well-scoped. The flag is rejected when combined with `-t/--track` or `--mirror`, as those options already specify what to fetch. The patch updates `builtin/remote.c` to set `remote.<name>.fetchRefmap` (with a namespace mapping like `+refs/heads/*:refs/remotes/<name>/*`) when `--limited-fetch` is used, while leaving `remote.<name>.fetch` unset. Documentation (`git-remote.adoc`) and tests (`t/t5505-remote.sh`) are updated to reflect the new behavior, including edge cases like full repositories and flag conflicts.

The patch is part of a **finalized design** (v12) that resolves the maintainer and key reviewer’s objection to overloading `remote.<name>.refmap` in earlier versions. The series is **under active review for merging to `master`**, with no remaining design or implementation questions. This patch is a straightforward extension of the core logic introduced in earlier patches, and its behavior aligns with the settled precedence rules (`remote.<name>.fetch` > `remote.<name>.fetchRefmap` > dynamic branch enumeration). The test coverage is thorough, and the commit message clearly explains the motivation and implementation.
