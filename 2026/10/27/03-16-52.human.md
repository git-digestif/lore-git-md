This is the second patch in Pablo Sabater’s RFC series lifting the 10k OID limit for `git cat-file --remote-object-info`. It implements the core batching logic: instead of rejecting queries over 10k OIDs, the command now splits them into 50k-OID chunks (the new default) and reuses the same transport connection for all chunks. The patch touches `builtin/cat-file.c`, `transport-helper.c`, `transport.c`, and their headers, converting several functions from returning error codes to dying on failure and keeping the connection open between batches. Benchmarking in the cover letter shows the change cuts 400k-OID query time from 5.86 s to 1.82 s. No new options are introduced here—those come in patch 3—but the preparatory refactoring from patch 1 is now put to use. The code is clean and the motivation is clear: users no longer need to manually split large queries.
