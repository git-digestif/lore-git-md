This is the final patch in Jeff King’s (Peff) 8-part series refactoring Git’s unit test infrastructure. It removes the shell-based JUnit XML reporting code, which has been unused since Azure Pipelines was dropped in early 2025. The patch deletes the `test-lib-junit.sh` script and the `test-xml-encode` helper, along with their build system entries, trimming 213 lines of code.

The rationale is straightforward: GitLab CI now relies on Meson’s built-in JUnit output, and there’s no evidence of in-tree or external users invoking `--write-junit-xml` directly. Peff notes that a prior bug in the shell-based reporting (fixed earlier in the series) likely would have caused test failures for anyone still using it, making it unlikely that this removal will break real workflows. The patch leaves the `start_test_case_output` and `finalize_test_output` hooks in `test-lib.sh` intact, as they’re still used for GitHub workflow annotations and carry minimal overhead.

This is a clean cleanup with no behavioral impact. The series as a whole has already improved unit test debuggability by unifying execution under `test-lib.sh`, and this patch simply removes dead code. Peff marks it as RFC, inviting feedback on whether the JUnit XML option is still needed, but the commit message makes a strong case that it isn’t. The patch is ready for integration unless someone surfaces a concrete use case.
