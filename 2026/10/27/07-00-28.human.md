This is a bugfix for `git pack-objects` targeting partial clones. The patch addresses a crash (`BUG()`) that occurs when `git index-pack` tries to repack local links into promisor packs in repositories with shallow or filtered clones. The issue arises when the revision walk encounters missing objects (e.g., trees omitted by a `tree:0` filter) while excluding promisor objects, triggering an assertion failure.

The fix is straightforward: instead of crashing when an object cannot be read, the callback now assumes the missing object is a promisor object and skips it. This aligns with the existing behavior in `repack_local_links()` and resolves two scenarios where the bug manifests: (1) shallow clones combined with partial clones, and (2) recent changes to shallow file propagation (introduced in `d43b9acb05b`) that inadvertently exposed the issue during unshallowing or deepening operations.

Patrick Steinhardt authored the patch, which includes a detailed commit message explaining the root cause and two new test cases in `t/t5616-partial-clone.sh` to verify the fix. The tests cover both `--unshallow` and `--deepen` operations with filtered fetches, ensuring the repack process tolerates missing trees of promisor commits. The patch is well-motivated and addresses a real-world edge case in partial clone workflows. It looks ready for review and likely to be uncontroversial.
