This is a performance-focused RFC patch series targeting the `git cat-file --remote-object-info` command. The author, Pablo Sabater, proposes removing the hard-coded 10k OID limit for remote object info queries and instead batching requests internally to allow arbitrarily large queries. The series introduces a new `--remote-max-batch` option (defaulting to 50k OIDs) and includes benchmarking data showing significant speedups—e.g., a 400k OID query drops from 5.86s to 1.82s when increasing the batch size from 10k to 400k.

The motivation is clear: the current 10k limit is arbitrary and forces users to manually split large queries, while metadata-only requests (unlike `git backfill`) should theoretically scale better. The author’s benchmarks (simulated 47ms RTT) demonstrate diminishing returns beyond 50k batches, justifying the proposed default. The series touches the transport layer (`transport-helper.c`, `transport.c`) and adds a new test script (`t/t1017-cat-file-remote-object-info.sh`).

Key technical details:
- **Files modified**: `builtin/cat-file.c`, `transport-helper.c`, `transport.c`, and related headers.
- **New behavior**: The command now accepts unlimited OIDs and batches them internally.
- **New option**: `--remote-max-batch` to override the 50k default.
- **Open question**: Whether the server should enforce its own OID limit for object-info requests.

The series is well-structured, with a cover letter explaining the rationale, benchmarks, and open questions. The GitHub CI passed, and the code appears to be a clean refactoring (patch 1 extracts transport ownership, patch 2 implements batching, patch 3 adds the CLI option).
