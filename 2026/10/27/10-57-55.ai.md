This is the first patch in a three-patch bugfix series targeting the sequencer subsystem. It improves the `test_ref_missing()` helper in `t/test-lib-functions.sh` by making its error messages more informative. Currently, if the helper fails because a ref unexpectedly exists, it doesn’t specify which ref caused the failure—this patch fixes that by including the ref name in the error output. The change is small (4 insertions, 2 deletions) and purely diagnostic, with no functional impact on the test suite itself.

The motivation here is practical: when multiple `test_ref_missing()` calls appear in a single test, a failure leaves the user guessing which ref was the culprit. This patch eliminates that ambiguity by printing the ref name in both the "reference exists" and "generic error" cases. The implementation is straightforward, using `eval` to extract the last argument (the ref name) from the function’s arguments.

This patch is a precursor to the actual bugfix in the series, which will use `test_ref_missing()` to verify that `REBASE_HEAD` and `AUTO_MERGE` refs are properly cleaned up after rebase operations. The improved error messages will make it easier to debug test failures in those scenarios. Phillip Wood, the author, is a well-known contributor with deep expertise in the sequencer and test infrastructure, so the change is likely to be uncontroversial.

The patch touches only `t/test-lib-functions.sh` and doesn’t introduce or modify any Git behavior. It’s a minor but useful quality-of-life improvement for test authors and reviewers. No further discussion or follow-up is expected beyond routine review.
