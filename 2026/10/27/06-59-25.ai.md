This is a cleanup patch that removes dead code from the loose object storage subsystem. It is the first patch in Patrick Steinhardt’s seven-part series introducing the object storage extension (`extensions.objectStorage`), which aims to make Git’s object database pluggable.

The patch deletes `repo_write_loose_object_map()`, a function introduced in 2023 to write a mapping between SHA-1 and SHA-256 for loose objects. The function was never called—loose object maps are instead written incrementally via `repo_add_loose_object_map()`—and its hardcoded path (`$GIT_COMMON_DIR/objects/loose-object-idx`) conflicts with the loose source’s actual location when the object directory is relocated. The removal is a straightforward cleanup with no behavior changes; it simply excises 46 lines of unused code from `loose.c` and its declaration from `loose.h`.

The patch is uncontroversial and mechanically sound. It aligns with the series’ broader goal of refactoring the object storage layer, though it stands alone as a pure cleanup. No objections or review comments are expected, and the change is unlikely to affect future discussion in the thread, which centers on the architectural implications of the object storage extension rather than low-level loose object handling. The commit message clearly explains the rationale and the inconsistency that motivated the removal.
