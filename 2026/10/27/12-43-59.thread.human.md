This thread is a two-patch bugfix series from Harald Nordgren that fixes an inconsistency in Git’s triangular workflows when `push.default=simple`. The issue: `@{push}` fails to resolve when the push remote differs from the branch’s upstream, even though `git push` correctly pushes to the same-named branch on the push remote. This causes `git status` to omit the push-branch comparison and show misleading hints.

The first patch refactored the code for readability, splitting the logic for `PUSH_DEFAULT_SIMPLE` into a new helper function, `branch_get_push_simple()`. Junio’s feedback on this refactoring has been fully addressed, and the second patch—just posted—implements the actual fix. The change is minimal: it skips the upstream-name check in `branch_get_push_simple()` when the push remote differs from the branch’s remote, allowing `@{push}` to resolve to the same-named branch on the push remote, matching `git push`’s behavior.

Tests have been updated to cover the new behavior, including a regression test in `t/for-each-ref-tests.sh` and a new test case in `t/t1514-rev-parse-push.sh` for triangular workflows. Error-path coverage is preserved by adjusting an existing test to use a differently named upstream branch on the same remote. The series is now functionally complete, with no open objections, and awaits Junio’s final review before being queued for `next`. D. Ben Knoble’s earlier endorsement of the fix remains valid, and the commit message clearly explains the user-visible impact.
