This is a substantive review comment on the sixth patch in Patrick Steinhardt’s v2 series restoring dynamic reloading of alternate object databases. Christian Couder identifies a race condition in the alternates file reloading logic: if the file is rewritten in-place while Git is reading it, the `stat_validity` tracking could be updated with the file descriptor’s metadata *after* the old content has already been parsed, causing Git to miss the new alternates indefinitely. The race does not occur if the file is replaced atomically (e.g., via a lock file and rename), but the test added in patch 3 explicitly uses an in-place rewrite, making the issue reproducible.

Christian proposes a simple fix: move the `stat_validity_update()` call *before* reading from the file descriptor, matching the pattern used in `refs/packed-backend.c` and `shallow.c`. He also suggests clearing the validity only when reading fails, which would address Junio’s earlier feedback on patch 4 without reintroducing the race. The proposed reordering is mechanical and preserves the patch’s performance benefits while eliminating the edge case. No alternative approaches or objections have been raised in the thread so far.
