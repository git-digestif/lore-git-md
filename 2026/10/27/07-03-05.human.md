This is a **bugfix** for a regression in Git 2.56.0 that causes a `BUG()` abort during fetches combining `--filter=tree:0` with `--unshallow` (or `--deepen`) when the fetched ref has moved past the local shallow tip. The issue was introduced by commit d43b9acb05 ("setup: unify setup of shallow file"), which switched shallow file handling to environment-based propagation, but Patrick Steinhardt demonstrates the underlying problem predates this change and is reproducible on Git 2.55.0 under a two-step fetch sequence.

Patrick’s fix is now formally submitted as a patch. It replaces the `BUG()` assertion in `is_not_in_promisor_pack_obj()` with a graceful return (`return 0`), treating missing promisor objects as non-promisor objects. This aligns with partial clone expectations, where not all objects are locally available, and addresses the immediate symptom without reverting the environment-based shallow file propagation. The change is minimal (a single line in `builtin/pack-objects.c`) and well-motivated, with no open questions about the root cause or fix direction.

The regression affects shallow clones using tree filters during unshallow operations, a severe but narrowly scoped failure mode. The fix is unlikely to be controversial, as it replaces an assertion with behavior consistent with partial clone semantics. The reproduction case provided by Daniel Zoghalchali is clear and reliable, and Patrick’s analysis confirms the issue is not solely tied to the environment change but reflects a broader incorrect assumption in `is_not_in_promisor_pack_obj()`.

This patch is ready for review and should be a straightforward merge. It resolves a critical regression with a targeted, low-risk change. If you work with shallow clones or partial clones, this fix is worth paying attention to.
