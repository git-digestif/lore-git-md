Thread identity
Subject: [PATCH 0/8] ci: consolidate test environment variables
Series version: v2 (seven patches; patch 8/8 dropped)
Originating author: Patrick Steinhardt
Thread type: patch series (CI/build system cleanup)

Core problem or goal
Clean up Git’s CI infrastructure by consolidating test environment variables across GitHub Actions and GitLab CI workflows. The goal is to reduce duplication, improve maintainability, and ensure consistent test environments (e.g., default ref storage format) across CI platforms. The series introduces a new `NO_RUST` build variant using glibc, improves documentation for the "feature-testbed" job, replaces per-distribution variable assignments with platform-wide rules (e.g., `GIT_TEST_USE_SET_E` for Linux jobs), and aligns test behavior with Git’s compiled-in defaults for ref storage. The refactoring prioritizes resilience to future job additions by using pattern-matching case statements instead of explicit job-name lists. The design discussion for the eighth patch is closed: Patrick Steinhardt has dropped the patch entirely, abandoning both the `--feature-testbed` command-line flag and the maintainer-backed `FEATURE_TESTBED=1` environment variable alternative. The series addresses a gap created by the April 2026 default-enable-Rust commit (32d5b90590) by restoring test coverage for non-Rust builds.

Current status
**In `next`** following explicit approvals from Jeff King, Phillip Wood, and Toon Claes, and Junio C Hamano’s procedural confirmation. The series is procedurally unblocked, carries sufficient reviewer endorsements, and has been queued for integration testing.

Key technical details
- Files touched: `.github/workflows/main.yml`, `.gitlab-ci.yml`, `ci/lib.sh`, `ci/run-build-and-tests.sh`, `t/README`, `t/test-lib.sh`, `t/test-lib-functions.sh`, `t/unit-tests/unit-test.c`.
- New symbols: `NO_RUST` build variant (glibc-based); centralized environment variable overrides in `ci/lib.sh` (e.g., `GIT_TEST_DEFAULT_REF_STORAGE_FORMAT`, `GIT_TEST_DEFAULT_HASH`, `MESONFLAGS`, `TEST_CONTRIB_TOO`, `GIT_TEST_USE_SET_E`); `GIT_TEST_BUILTIN_REF_STORAGE_FORMAT` (compiled-in default for ref storage).
- Behavior changes: Centralizes hardcoded variable overrides in `ci/lib.sh` using pattern matching (e.g., `*breaking-changes*`, `*reftable*`, `*sha256*`); ensures test environment honors default ref storage format (reftable) when "breaking changes" (SHA-256) are enabled. Patch 1/8 moves 44 lines of environment variable assignments from `ci/run-build-and-tests.sh` into `ci/lib.sh`, creating temporary duplication (43 lines added, 44 lines removed) as a deliberate stepping stone for later consolidation. Patch 2/8 replaces per-distribution assignments of `GIT_TEST_USE_SET_E` with a single Linux-wide rule, eliminating redundancy and ensuring the `linux32` job (previously missed) inherits the setting. Patch 3/8 mechanically deduplicates 14 lines of redundant configuration by replacing explicit job-name lists with glob patterns (`*breaking-changes*`, `*reftable*`, `*sha256*`), eliminating redundancy while preserving identical behavior. Patch 4/8 merges three separate `case` statements over `$jobname` into one, eliminating 25 lines of redundant code while adding 16 lines of consolidated logic (e.g., moving `linux-musl-meson` and `linux-feature-testbed` into the primary block, with `linux-musl-meson` now disabling Rust support via `-Drust=disabled`). Patch 5/8 removes the redundant `linux-reftable-sha256` CI job by ensuring the `linux-breaking-changes` job uses the compiled-in default ref storage format (`GIT_TEST_BUILTIN_REF_STORAGE_FORMAT`) instead of hardcoding "files". The helper function `test_detect_ref_format()` in `t/test-lib-functions.sh` is updated to match this logic, and `t/test-lib.sh` is updated to export `GIT_DEFAULT_REF_STORAGE_FORMAT` with the same fallback logic. Patch 6/8 adds `NO_RUST=Yes` to the `linux-asan-ubsan` job in `ci/lib.sh`, restoring test coverage for non-Rust builds lost after the April 2026 default-enable-Rust commit (32d5b90590). The change targets a glibc-based environment to complement the existing musl-based coverage on Alpine Linux, and aligns with the job’s focus on memory safety. Patch 7/8 removes a redundant override of `GIT_TEST_DEFAULT_INITIAL_BRANCH_NAME` in the `linux-feature-testbed` job, as the initial branch name is already set via the `WITH_BREAKING_CHANGES` toggle.
- On-disk format: No changes.
- Test coverage: Adjusts test infrastructure (`t/README`, `t/test-lib.sh`) to support the "feature-testbed" job and align with compiled-in defaults.

In patch 4/8, further consolidates `case` statements to reduce redundancy and improve maintainability. In patch 5/8, removes the redundant `linux-reftable-sha256` job by aligning test behavior with compiled-in defaults, eliminating a now-unnecessary explicit test case. In patch 6/8, restores non-Rust test coverage by targeting the `linux-asan-ubsan` job, chosen for its memory-safety focus and glibc compatibility. Earlier review of patch 8/8 confirmed the correctness of the shell idiom (`eval "test -z \"\${$1+set}\""`) used to preserve existing variable overrides and identified the omission of `OPENSSL_SHA1_UNSAFE` in the `--feature-testbed` flag, suggesting it be documented in the commit message. In his latest reply, **endorsed Jeff King’s alternative design** (a `FEATURE_TESTBED=1` environment variable or Makefile flag) as more consistent and better aligned with existing tooling (e.g., Ævar Arnfjörð Bjarmason’s prior work on Makefile targets for CI jobs). Framed the choice as one of local reproducibility, reinforcing the maintainer-backed consensus. **Explicitly states the series is "ready for `next`" in his earlier email; this position is now reinforced by Junio’s procedural confirmation.**
- Junio C Hamano (maintainer): Provides **surface-level but technically precise** review of patch 8/8, suggesting a quoting fix to the `set_default_env()` helper in `t/test-lib.sh` for shell portability (`eval "$1=\"\$2\""` instead of `eval "$1=\$2"`). The change aligns with Git’s `CodingGuidelines` and addresses potential edge cases in non-POSIX shells. No functional impact; this is a defensive coding tweak. In his latest reply, Junio **endorsed Jeff King’s alternative design** for patch 8/8, agreeing that a `FEATURE_TESTBED=1` environment variable is "simple" and conceptually coherent, shifting the discussion from a reviewer preference to a maintainer-backed direction. **Confirms the series (patches 1–7) is cleared for integration into `next`.**

His proposal was endorsed by Junio C Hamano and Phillip Wood. **Explicitly endorses patches 1–7 as "obviously good" and "ready for `next`" in the new email, adding his procedural sign-off to Phillip Wood’s earlier assessment.**

He suggests the cleanest solution would be to split build and test flags entirely, but acknowledges this likely exceeds the series’ scope. No new technical feedback is introduced.
