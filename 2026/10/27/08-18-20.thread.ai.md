Subject: [PATCH 0/8] ci: consolidate test environment variables
Series version: v1 (initial submission, 8 patches; v2 confirmed for patch 8/8)
Originating author: Patrick Steinhardt
Thread type: patch series (CI/build system cleanup)

Core problem or goal
Clean up Git’s CI infrastructure by consolidating test environment variables across GitHub Actions and GitLab CI workflows. The goal is to reduce duplication, improve maintainability, and ensure consistent test environments (e.g., default ref storage format) across CI platforms. The series introduces a new `NO_RUST` build variant using glibc, improves documentation for the "feature-testbed" job, replaces per-distribution variable assignments with platform-wide rules (e.g., `GIT_TEST_USE_SET_E` for Linux jobs), and aligns test behavior with Git’s compiled-in defaults for ref storage. The refactoring prioritizes resilience to future job additions by using pattern-matching case statements instead of explicit job-name lists. The eighth patch’s design is **resolved**: a `FEATURE_TESTBED=1` environment variable will replace the `--feature-testbed` flag, toggling both build knobs and test environment variables (including `OPENSSL_SHA1_UNSAFE`) in a single, consistent interface. The series addresses a gap created by the April 2026 default-enable-Rust commit (32d5b90590) by restoring test coverage for non-Rust builds.

Current status
Under review (initial v1 submission; v2 confirmed for patch 8/8). Patches 1–7 are uncontroversial following Jeff King’s endorsement ("obviously good") and are likely to be merged without further debate. Patch 8/8’s design is **resolved**: the maintainer-backed consensus is to adopt Jeff King’s proposal of a `FEATURE_TESTBED=1` environment variable, replacing the `--feature-testbed` command-line flag. Junio C Hamano and Phillip Wood have both endorsed this approach as simpler and more consistent, shifting the discussion from reviewer preference to a clear direction. Key technical details
- Files touched: `.github/workflows/main.yml`, `.gitlab-ci.yml`, `ci/lib.sh`, `ci/run-build-and-tests.sh`, `t/README`, `t/test-lib.sh`, `t/test-lib-functions.sh`, `t/unit-tests/unit-test.c`.
- New symbols: `NO_RUST` build variant (glibc-based); centralized environment variable overrides in `ci/lib.sh` (e.g., `GIT_TEST_DEFAULT_REF_STORAGE_FORMAT`, `GIT_TEST_DEFAULT_HASH`, `MESONFLAGS`, `TEST_CONTRIB_TOO`, `GIT_TEST_USE_SET_E`); `GIT_TEST_BUILTIN_REF_STORAGE_FORMAT` (compiled-in default for ref storage); `FEATURE_TESTBED=1` environment variable (replaces `--feature-testbed` flag); `set_default_env()` helper in `t/test-lib.sh`.
- Behavior changes: Centralizes hardcoded variable overrides in `ci/lib.sh` using pattern matching (e.g., `*breaking-changes*`, `*reftable*`, `*sha256*`); ensures test environment honors default ref storage format (reftable) when "breaking changes" (SHA-256) are enabled. Patch 2/8 replaces per-distribution assignments of `GIT_TEST_USE_SET_E` with a single Linux-wide rule, eliminating redundancy and ensuring the `linux32` job (previously missed) inherits the setting. Patch 3/8 mechanically deduplicates 14 lines of redundant configuration by replacing explicit job-name lists with glob patterns. Patch 4/8 merges three separate `case` statements over `$jobname` into one, eliminating 25 lines of redundant code while adding 16 lines of consolidated logic (e.g., moving `linux-musl-meson` and `linux-feature-testbed` into the primary block, with `linux-musl-meson` now disabling Rust support via `-Drust=disabled`). Patch 5/8 removes the redundant `linux-reftable-sha256` CI job by ensuring the `linux-breaking-changes` job uses the compiled-in default ref storage format (`GIT_TEST_BUILTIN_REF_STORAGE_FORMAT`) instead of hardcoding "files". The helper function `test_detect_ref_format()` in `t/test-lib-functions.sh` is updated to match this logic. Patch 6/8 removes a redundant override of `GIT_TEST_DEFAULT_INITIAL_BRANCH_NAME` in the `linux-feature-testbed` job, as the initial branch name is already set via the `WITH_BREAKING_CHANGES` toggle. Patch 7/8 adds `NO_RUST=Yes` to the `linux-asan-ubsan` job in `ci/lib.sh`, restoring test coverage for non-Rust builds lost after the April 2026 default-enable-Rust commit (32d5b90590). The `FEATURE_TESTBED=1` environment variable will be recognized by both shell and unit tests, toggling all relevant settings (including `OPENSSL_SHA1_UNSAFE`) in a single interface.
- On-disk format: No changes.
- Test coverage: Adjusts test infrastructure (`t/README`, `t/test-lib.sh`) to support the "feature-testbed" job and align with compiled-in defaults. The `FEATURE_TESTBED=1` environment variable will be honored by both shell and unit tests.

Justifies temporary duplication as a stepping stone for full consolidation. In patch 2/8, argues that platform-wide rules (e.g., `GIT_TEST_USE_SET_E` for Linux) are more maintainable than per-distribution lists, citing stability of `CI_OS_NAME` as a proxy. In patch 3/8, shifts to pattern matching to future-proof the configuration against job renames or additions. In patch 4/8, further consolidates `case` statements to reduce redundancy and improve maintainability. In patch 5/8, removes the redundant `linux-reftable-sha256` job by aligning test behavior with compiled-in defaults, eliminating a now-unnecessary explicit test case. In patch 6/8, removes a redundant override of `GIT_TEST_DEFAULT_INITIAL_BRANCH_NAME` in the `linux-feature-testbed` job, as the initial branch name is already controlled by `WITH_BREAKING_CHANGES`. In patch 7/8, restores non-Rust test coverage by targeting the `linux-asan-ubsan` job, chosen for its memory-safety focus and glibc compatibility. In patch 8/8, initially introduced the `--feature-testbed` flag to improve developer ergonomics but has now **confirmed intent to reroll** the patch to adopt the `FEATURE_TESTBED=1` environment variable design, folding in Junio’s shell quoting fix. His latest reply frames the trade-off as one of developer ergonomics versus architectural consistency, but the maintainer’s endorsement of Jeff’s proposal makes a reroll highly likely.
- Phillip Wood (reviewer): Provides **substantive review** of the entire series, calling the changes "nice" and highlighting two improvements as "very welcome": moving job-dependent variable assignments into `ci/lib.sh` and removing the redundant `linux-reftable-sha256` job while preserving test coverage. Endorses disabling Rust for the sanitizer job (`linux-asan-ubsan`), noting its purpose is to check C code, though leaving open the possibility that this balance might shift if Git’s Rust codebase grows more unsafe code in the future. Earlier review of patch 8/8 confirmed the correctness of the shell idiom (`eval "test -z \"\${$1+set}\""`) used to preserve existing variable overrides and identified the omission of `OPENSSL_SHA1_UNSAFE` in the `--feature-testbed` flag, suggesting it be documented in the commit message. In his latest reply, **endorses Jeff King’s alternative design** (a `FEATURE_TESTBED=1` environment variable or Makefile flag) as more consistent and better aligned with existing tooling (e.g., Ævar Arnfjörð Bjarmason’s prior work on Makefile targets for CI jobs). Frames the choice as one of local reproducibility, reinforcing the maintainer-backed consensus.
- Junio C Hamano (maintainer): Provides **surface-level but technically precise** review of patch 8/8, suggesting a quoting fix to the `set_default_env()` helper in `t/test-lib.sh` for shell portability (`eval "$1=\"\$2\""` instead of `eval "$1=\$2"`). The change aligns with Git’s `CodingGuidelines` and addresses potential edge cases in non-POSIX shells. No functional impact; this is a defensive coding tweak. In his latest reply, Junio **endorses Jeff King’s alternative design** for patch 8/8, agreeing that a `FEATURE_TESTBED=1` environment variable is "simple" and conceptually coherent, shifting the discussion from a reviewer preference to a maintainer-backed direction.
- Jeff King (Peff) (reviewer): Provides **substantive review** of patch 8/8, initially questioning its design as overly complex and inconsistent due to the omission of `OPENSSL_SHA1_UNSAFE`. He argued that the flag "half-works" and proposed an alternative: a `FEATURE_TESTBED=1` environment variable to control both build knobs and test environment variables, avoiding the need for a command-line flag. His proposal is now endorsed by Junio C Hamano and Phillip Wood, making a reroll highly likely. He endorses patches 1–7 as "obviously good," indicating they are uncontroversial and likely to be merged without further debate.
