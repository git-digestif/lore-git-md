Subject: [PATCH 0/8] ci: consolidate test environment variables
Series version: v1 (initial submission, 8 patches)
Originating author: Patrick Steinhardt
Thread type: patch series (CI/build system cleanup)

Core problem or goal
Clean up Git’s CI infrastructure by consolidating test environment variables across GitHub Actions and GitLab CI workflows. The goal is to reduce duplication, improve maintainability, and ensure consistent test environments (e.g., default ref storage format) across CI platforms. The series introduces a new `NO_RUST` build variant using glibc, improves documentation for the "feature-testbed" job, replaces per-distribution variable assignments with platform-wide rules (e.g., `GIT_TEST_USE_SET_E` for Linux jobs), and aligns test behavior with Git’s compiled-in defaults for ref storage. The refactoring prioritizes resilience to future job additions by using pattern-matching case statements instead of explicit job-name lists. The eighth patch adds a `--feature-testbed` flag to the test suite, centralizing the feature-testbed configuration and making it accessible to developers for local reproduction of CI environments. The series addresses a gap created by the April 2026 default-enable-Rust commit (32d5b90590) by restoring test coverage for non-Rust builds.

Current status
Under review (initial v1 submission). No prior versions or merge status reported. Junio C Hamano has not signaled intent to merge; the series remains in the review phase. Phillip Wood reviewed the entire series, calling the changes "nice" and highlighting two improvements as "very welcome": moving job-dependent variable assignments into `ci/lib.sh` and removing the redundant `linux-reftable-sha256` job while preserving test coverage. He also endorsed disabling Rust for the sanitizer job (`linux-asan-ubsan`), noting its purpose is to check C code, though he left open the possibility that this balance might shift if Git’s Rust codebase grows more unsafe code in the future. Junio C Hamano reviewed patch 8/8, suggesting a **surface-level but technically precise** quoting fix to the `set_default_env()` helper in `t/test-lib.sh` for shell portability (`eval "$1=\"\$2\""` instead of `eval "$1=\$2"`), aligning with Git’s `CodingGuidelines`. Phillip’s earlier review of patch 8/8 noted a minor omission (`OPENSSL_SHA1_UNSAFE` not set by the new `--feature-testbed` flag) and confirmed the correctness of the shell idiom used to preserve existing variable overrides. Jeff King (Peff) reviewed patch 8/8, questioning the design of the `--feature-testbed` flag as overly complex and inconsistent due to its omission of `OPENSSL_SHA1_UNSAFE` (a build flag). He proposed an alternative: a `FEATURE_TESTBED=1` environment variable that would control both build knobs and test environment variables, avoiding the need for a command-line flag and ensuring all relevant settings are toggled together. Peff’s critique is **substantive**, challenging the architectural choice rather than implementation details. Junio’s latest reply is a procedural acknowledgment of Phillip’s review, adding no new technical feedback. The feedback is constructive and may prompt a reroll, particularly for patch 8/8, to address the design concerns raised by Peff and the omission noted by Phillip.

Key technical details
- Files touched: `.github/workflows/main.yml`, `.gitlab-ci.yml`, `ci/lib.sh`, `ci/run-build-and-tests.sh`, `t/README`, `t/test-lib.sh`, `t/test-lib-functions.sh`, `t/unit-tests/unit-test.c`.
- New symbols: `NO_RUST` build variant (glibc-based); centralized environment variable overrides in `ci/lib.sh` (e.g., `GIT_TEST_DEFAULT_REF_STORAGE_FORMAT`, `GIT_TEST_DEFAULT_HASH`, `MESONFLAGS`, `TEST_CONTRIB_TOO`, `GIT_TEST_USE_SET_E`); `GIT_TEST_BUILTIN_REF_STORAGE_FORMAT` (compiled-in default for ref storage); `--feature-testbed` flag for the test suite; `set_default_env()` helper in `t/test-lib.sh`.
- Behavior changes: Centralizes hardcoded variable overrides in `ci/lib.sh` using pattern matching (e.g., `*breaking-changes*`, `*reftable*`, `*sha256*`); ensures test environment honors default ref storage format (reftable) when "breaking changes" (SHA-256) are enabled. Patch 2/8 replaces per-distribution assignments of `GIT_TEST_USE_SET_E` with a single Linux-wide rule, eliminating redundancy and ensuring the `linux32` job (previously missed) inherits the setting. Patch 3/8 mechanically deduplicates 14 lines of redundant configuration by replacing explicit job-name lists with glob patterns. Patch 4/8 merges three separate `case` statements over `$jobname` into one, eliminating 25 lines of redundant code while adding 16 lines of consolidated logic (e.g., moving `linux-musl-meson` and `linux-feature-testbed` into the primary block, with `linux-musl-meson` now disabling Rust support via `-Drust=disabled`). Patch 5/8 removes the redundant `linux-reftable-sha256` CI job by ensuring the `linux-breaking-changes` job uses the compiled-in default ref storage format (`GIT_TEST_BUILTIN_REF_STORAGE_FORMAT`) instead of hardcoding "files". The helper function `test_detect_ref_format()` in `t/test-lib-functions.sh` is updated to match this logic. Patch 6/8 removes a redundant override of `GIT_TEST_DEFAULT_INITIAL_BRANCH_NAME` in the `linux-feature-testbed` job, as the initial branch name is already set via the `WITH_BREAKING_CHANGES` toggle. Patch 7/8 adds `NO_RUST=Yes` to the `linux-asan-ubsan` job in `ci/lib.sh`, restoring test coverage for non-Rust builds lost after the April 2026 default-enable-Rust commit (32d5b90590). Patch 8/8 introduces the `--feature-testbed` flag to the test suite, replacing 11 lines of hardcoded variable exports in `ci/lib.sh` with a single flag assignment. The `set_default_env()` helper ensures existing variable overrides aren’t clobbered by checking `eval "test -z \"\${$1+set}\""` before assignment. The flag omits `OPENSSL_SHA1_UNSAFE` (set only by the CI job, not the flag). Junio’s feedback refines the assignment step in `set_default_env()` to use `eval "$1=\"\$2\""` for shell portability. No functional changes to test logic or behavior.

- Test coverage: Adjusts test infrastructure (`t/README`, `t/test-lib.sh`) to support the "feature-testbed" job and align with compiled-in defaults. The `--feature-testbed` flag is recognized by both shell and unit tests.
