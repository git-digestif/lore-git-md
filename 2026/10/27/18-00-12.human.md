He suggests that while Git's internal terminology doesn't have to match external usage, aligning with user expectations could make the documentation more intuitive. For example, he finds it counterintuitive to call a branch name like `main` an "object ID," even if Git eventually resolves it to a hash.

The email doesn't propose a new patch or compromise but instead highlights the tension between historical precedent and usability. Ben's position is that Julia Evans's original patch (which proposed making "object ID" canonical) was a reasonable attempt to clarify terminology, even if it conflicted with the glossary's current definition. He doesn't directly challenge Junio's authority as maintainer but implies that the barrier to revisiting this decision might be too high.

This reply doesn't resolve the impasse but reinforces the divide: Junio sees the glossary as authoritative and any deviations as bugs to fix, while Ben (and likely Julia) view the current terminology as confusing and worth revisiting.
