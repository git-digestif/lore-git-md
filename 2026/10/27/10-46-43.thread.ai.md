Thread identity
Subject: [PATCH 0/12] Modernize git-rerere's subcommand handling
Series version: v1 (initial submission)
Originating author: Patrick Steinhardt
Thread type: patch series (refactoring)

Core problem or goal
Replace the custom subcommand-parsing logic in `git rerere` with Git’s standard `OPT_SUBCOMMAND()` mechanism, bringing the command in line with other multi-subcommand built-ins like `git notes` and `git maintenance`. The series is purely internal restructuring: no new functionality, no behavior changes, and no on-disk format changes.

Current status
Under review; v1 posted 2025-06-17. Depends on the already-merged `ps/rerere-remove-global-state` topic (b948c10c8b3), which eliminated the global rerere cache state and made this refactoring possible. The series is now complete with the addition of per-subcommand usage strings in the final patch.

Key technical details
- Files: `builtin/rerere.c` (primary), `rerere.h`, `Documentation/git-rerere.adoc`, plus callers in `apply.c`, `builtin/am.c`, `builtin/commit.c`, `builtin/merge.c`, `builtin/stash.c`, `rerere.c`, `sequencer.c`.
- Symbols: functions renamed to follow subcommand naming (`rerere_record()` replaces `repo_rerere()`; patches 5–10 introduce `cmd_rerere_forget()`, `cmd_rerere_clear()`, `cmd_rerere_status()`, `cmd_rerere_remaining()`, `cmd_rerere_diff()`, and `cmd_rerere_gc()`); flags converted to enums (`enum rerere_flags` replaces `#define RERERE_AUTOUPDATE`, `RERERE_NOAUTOUPDATE`, `RERERE_READONLY`, `RERERE_NOWAIT`). Mark C. Chu-Carroll suggests adding an explicit `RERE_MERGE_LOCK_TOKEN` enum value to represent the `MERGE_RR.lock` case, rather than documenting it only in a comment, for improved clarity. `the_repository` usage fully removed as of patch 3.
- Subcommands: "forget", "clear", "status", "remaining", "diff", and "gc" now have dedicated usage strings. Patch 4 removes the unused `--[no-]rerere-autoupdate` flag from the "status" and "diff" subcommands, hard-coding `RERERE_READONLY` in their call sites. Patches 5–10 extract the "forget", "clear", "status", "remaining", "diff", and "gc" actions into `cmd_rerere_forget()`, `cmd_rerere_clear()`, `cmd_rerere_status()`, `cmd_rerere_remaining()`, `cmd_rerere_diff()`, and `cmd_rerere_gc()` with standard `parse_options()` machinery. Patch 11 replaces the hand-rolled `if (!strcmp(...))` ladder with an `OPT_SUBCOMMAND()` table for the six subcommands, introducing a fallback `cmd_rerere_record()` that mimics the old default behavior when no subcommand is given. The "gc" subcommand (patch 10) adds a hidden `--skip-locked` option to its option table and removes the now-redundant global `--skip-locked` flag from the top-level parser. Patch 12 adds per-subcommand usage strings to the man page and to each subcommand function, completing the series.
- Documentation: `Documentation/git-rerere.adoc` updated for new interface (SYNOPSIS now lists one line per subcommand); test suite (`t/t4200-rerere.sh`) receives minor updates (patch 10 drops one negative test for the old global-flag behavior).
- No new CLI options, config keys, or test files.

Open questions and loose ends
Mark C. Chu-Carroll raised a minor stylistic point in patch 2: whether to add an explicit `RERE_MERGE_LOCK_TOKEN` enum value for the `MERGE_RR.lock` case, rather than documenting it only in a comment. This is a cosmetic suggestion with no functional impact and does not block the series.
