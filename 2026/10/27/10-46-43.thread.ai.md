Core problem or goal
Replace the custom subcommand-parsing logic in `git rerere` with Git’s standard `OPT_SUBCOMMAND()` mechanism, bringing the command in line with other multi-subcommand built-ins like `git notes` and `git maintenance`. The series is purely internal restructuring: no new functionality, no behavior changes, and no on-disk format changes.

Open questions and loose ends
**One remaining documentation concern**: Junio’s latest feedback notes that the `enum rerere_flags` documentation for `RERERE_NOAUTOUPDATE` (introduced in patch 2) does not adequately explain *why* the flag exists or how it differs from simply omitting `RERERE_AUTOUPDATE`. The current wording describes what the flag *does* (updates the working tree but not the index) but not *why* a caller would choose it over the absence of `RERERE_AUTOUPDATE`. The distinction is subtle but important: omitting `RERERE_AUTOUPDATE` means Git does nothing after recording the resolution, while `RERERE_NOAUTOUPDATE` actively updates the working tree (but not the index) and prints conflict-resolution messages to stderr. Junio suggests the enum documentation should make this clearer, ideally with a brief example or rationale. Since the series is already merged, this feedback is likely intended for future reference or as a minor follow-up, rather than as a blocker.
