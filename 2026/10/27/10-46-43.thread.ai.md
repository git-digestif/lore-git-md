Thread identity: Subject "[PATCH 0/13] Modernize git-rerere's subcommand handling", series version v5 (superseding v4 which was reported merged to 'master' as of 2025-06-25), originating author Patrick Steinhardt, thread type patch series (refactoring).

Core problem or goal: Replace custom subcommand-parsing logic in `git rerere` with standard `OPT_SUBCOMMAND()` mechanism; purely internal restructuring with no new functionality or on-disk format changes, except for the intentional `--skip-locked` option-ordering restriction now scoped to the `gc` subcommand.

Current status: v4 was previously recorded as merged to 'master' per Junio's "What's cooking" report. v5 has now been posted as a 13-patch series that directly addresses the post-merge follow-up items: patch 10 now documents in its commit message that `--skip-locked` is intentionally accepted only after the `gc` subcommand name; patch 11 fixes the NULL-termination of the synthetic `argv` array in `cmd_rerere_perform()` by allocating `args.nr + 1` elements with `CALLOC_ARRAY()` (correcting the prior `args.nr` allocation) and restores the usage synopsis listing valid subcommands when an unknown subcommand is given (fixing the error-reporting regression); new patch 13 removes the stale prose in `Documentation/git-rerere.adoc` claiming `git rerere diff` passes additional arguments to the system `diff` command. v5 is under review; no merge status for v5 is claimed.

Key technical details: Files touched include `builtin/rerere.c`, `rerere.h`, `rerere.c`, `apply.c`, `builtin/am.c`, `builtin/commit.c`, `builtin/merge.c`, `builtin/stash.c`, `sequencer.c`, `Documentation/git-rerere.adoc`, and `t/t4200-rerere.sh`. Technical core unchanged from v4: dedicated `cmd_rerere_*()` functions for "forget", "clear", "status", "remaining", "diff", "gc", and `cmd_rerere_perform()` as fallback subcommand via `OPT_SUBCOMMAND()`. Patch 1/13 renames `repo_rerere()` to `rerere()` (removing the misleading `repo_` prefix that suggested a repository-method rather than a rerere-specific operation), mechanically updating all call sites across `apply.c`, `builtin/am.c`, `builtin/commit.c`, `builtin/merge.c`, `builtin/rerere.c`, `builtin/stash.c`, and `sequencer.c`, while moving and expanding the function's documentation into `rerere.h`; no behavior change, purely preparatory naming cleanup. Patch 2/13 converts the rerere subsystem's flag constants from `#define` macros into a proper `enum rerere_flags` with explicit bit-shift values (`1 << 0` through `1 << 3`), updating the signatures of `rerere_cache_setup()`, `rerere()`, and `rerere_gc()` in `rerere.h` and `rerere.c` to accept the enum instead of a bare `int`, with each flag documented inline in the enum definition; it also adds a defensive `BUG()` check in `rerere_cache_setup()` that fires if a caller passes both `RERERE_AUTOUPDATE` and `RERERE_NOAUTOUPDATE` simultaneously, since the precedence between these contradictory flags was previously implicit (autoupdate wins), though all current callers already avoid this combination. Patch 3/13 removes the `#define USE_THE_REPOSITORY_VARIABLE` from `builtin/rerere.c` and replaces all eight references to the `the_repository` global with the explicit `repo` parameter already passed into `cmd_rerere()`, changing that parameter from `UNUSED` to used; this covers calls to `repo_config()`, `rerere()`, `rerere_forget()`, `rerere_clear()`, `rerere_gc()`, `rerere_cache_setup()`, `rerere_remaining()`, and `rerere_path()`, and the commit message notes there is no NULL-dereference risk during `-h` handling because no code references the repo before `parse_options()`. Patch 4/13 modifies only `builtin/rerere.c` and changes the `status` and `diff` subcommand handlers to pass only `RERERE_READONLY` to `rerere_cache_setup()` instead of `flags | RERERE_READONLY`, dropping the autoupdate flags variable that read-only subcommands ignore anyway; this is preparatory cleanup establishing the pattern that read-only subcommands receive only `RERERE_READONLY` while the default no-subcommand path retains user-supplied autoupdate flags, with no behavior change. Patch 5/13 extracts the "forget" subcommand logic from the monolithic `cmd_rerere()` into a dedicated `cmd_rerere_forget()` handler in `builtin/rerere.c`; the new function sets up its own `parse_options()` call with an empty options array and the existing `rerere_usage` string, preserving the deprecation warning when no paths are given, then delegates to `rerere_forget()`, while the main `cmd_rerere()` dispatches to this new function when `argv[0]` equals "forget"; this is preparatory restructuring toward the eventual `OPT_SUBCOMMAND()` switch with no behavior change. Patch 11 v5 specifically corrects the fallback logic memory handling by ensuring the copied `argv` array is NULL-terminated with `CALLOC_ARRAY(args_copy, args.nr + 1)` while `COPY_ARRAY(args_copy, args.v, args.nr)` copies the argument elements, and calls `usage_with_options()` for unknown subcommands to restore the informative error message. Patch 13 removes the 2006-era stale documentation about `git rerere diff` accepting extra arguments. The three-state autoupdate system (`RERERE_AUTOUPDATE`/`RERERE_NOAUTOUPDATE` with `BUG()` check in `rerere_cache_setup()`) remains as in v4.
