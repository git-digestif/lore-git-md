Thread identity
Subject: [PATCH 0/12] Modernize git-rerere's subcommand handling
Series version: v2 (addresses Junio’s feedback)
Originating author: Patrick Steinhardt
Thread type: patch series (refactoring)

Core problem or goal
Replace the custom subcommand-parsing logic in `git rerere` with Git’s standard `OPT_SUBCOMMAND()` mechanism, bringing the command in line with other multi-subcommand built-ins like `git notes` and `git maintenance`. The series is purely internal restructuring: no new functionality, no behavior changes, and no on-disk format changes.

Current status
Under review; v2 posted 2025-06-17 (date carried over from v1; exact v2 date not specified). Depends on the already-merged `ps/rerere-remove-global-state` topic (b948c10c8b3), which eliminated the global rerere cache state and made this refactoring possible. All open items from v1 are now resolved: the fallback subcommand has been renamed to `rerere()` as Junio C Hamano requested, the enum documentation in patch 2 has been extended to cover all four flags (`RERERE_AUTOUPDATE`, `RERERE_NOAUTOUPDATE`, `RERERE_READONLY`, `RERERE_NOWAIT`), and patch 1 (the rename from `repo_rerere()` to `rerere()`) is now also aligned with Junio’s feedback. Junio has accepted Patrick’s proposed cosmetic follow-up for patch 2. Patch 3 (the subject of this email) removes all remaining `the_repository` usage from `builtin/rerere.c`, completing the repository-parameter conversion for the file. No substantive objections remain; the series is ready for integration once Junio picks it up.

Key technical details
- Files: `builtin/rerere.c` (primary), `rerere.h`, `Documentation/git-rerere.adoc`, plus callers in `apply.c`, `builtin/am.c`, `builtin/commit.c`, `builtin/merge.c`, `builtin/stash.c`, `rerere.c`, `sequencer.c`.
- Symbols: functions renamed to follow subcommand naming (`rerere()` replaces `repo_rerere()` in patch 1; the function’s signature and behavior are unchanged, but its documentation in `rerere.h` is expanded to clarify its role as the main entry point for recording and reusing conflict resolutions); flags converted to enums (`enum rerere_flags` replaces `#define RERERE_AUTOUPDATE`, `RERERE_NOAUTOUPDATE`, `RERERE_READONLY`, `RERERE_NOWAIT`). The comment on `RERERE_NOWAIT` (immediate failure when `MERGE_RR.lock` is taken) is confirmed correct; the enum now documents all four flags for clarity. `the_repository` usage fully removed as of patch 3: every rerere helper (`rerere()`, `rerere_forget()`, `rerere_clear()`, `rerere_gc()`, `rerere_cache_setup()`, `rerere_remaining()`, `rerere_path()`) now receives an explicit `repo` parameter instead of relying on the global. The `USE_THE_REPOSITORY_VARIABLE` macro is dropped, and the `UNUSED` annotation on the `repo` parameter is removed.
- Subcommands: "forget", "clear", "status", "remaining", "diff", and "gc" now have dedicated usage strings. Patch 4 removes the unused `--[no-]rerere-autoupdate` flag from the "status" and "diff" subcommands, hard-coding `RERERE_READONLY` in their call sites. Patches 5–10 extract the "forget", "clear", "status", "remaining", "diff", and "gc" actions into `cmd_rerere_forget()`, `cmd_rerere_clear()`, `cmd_rerere_status()`, `cmd_rerere_remaining()`, `cmd_rerere_diff()`, and `cmd_rerere_gc()` with standard `parse_options()` machinery. Patch 11 replaces the hand-rolled `if (!strcmp(...))` ladder with an `OPT_SUBCOMMAND()` table for the six subcommands, introducing a fallback `cmd_rerere()` that mimics the old default behavior when no subcommand is given. The "gc" subcommand (patch 10) adds a hidden `--skip-locked` option to its option table and removes the now-redundant global `--skip-locked` flag from the top-level parser. Patch 12 adds per-subcommand usage strings to the man page and to each subcommand function, completing the series.
- Documentation: `Documentation/git-rerere.adoc` updated for new interface (SYNOPSIS now lists one line per subcommand); test suite (`t/t4200-rerere.sh`) receives minor updates (patch 10 drops one negative test for the old global-flag behavior).
- No new CLI options, config keys, or test files.
