Thread identity
Subject: [PATCH 0/12] Modernize git-rerere's subcommand handling
Series version: v2 (addresses Junio’s feedback)
Originating author: Patrick Steinhardt
Thread type: patch series (refactoring)

Core problem or goal
Replace the custom subcommand-parsing logic in `git rerere` with Git’s standard `OPT_SUBCOMMAND()` mechanism, bringing the command in line with other multi-subcommand built-ins like `git notes` and `git maintenance`. The series is purely internal restructuring: no new functionality, no behavior changes, and no on-disk format changes.

Current status
Under review; v2 posted 2025-06-17 (date carried over from v1; exact v2 date not specified). Depends on the already-merged `ps/rerere-remove-global-state` topic (b944c10c8b3), which eliminated the global rerere cache state and made this refactoring possible. All open items from v1 are now resolved: the fallback subcommand has been renamed to `rerere()` as Junio C Hamano requested, the enum documentation in patch 2 has been extended to cover all four flags (`RERERE_AUTOUPDATE`, `RERERE_NOAUTOUPDATE`, `RERERE_READONLY`, `RERERE_NOWAIT`), and patch 1 (the rename from `repo_rerere()` to `rerere()`) is now also aligned with Junio’s feedback. Patch 3 removed all remaining `the_repository` usage from `builtin/rerere.c`, completing the repository-parameter conversion for the file. Patch 4 removed the unused `--[no-]rerere-autoupdate` flag from the "status" and "diff" subcommands, hard-coding `RERERE_READONLY` in their call sites. Patch 5 extracted the "forget" action into a dedicated `cmd_rerere_forget()` function with standard `parse_options()` machinery, preserving the existing logic and behavior. Patch 6 extracted the "clear" action into a dedicated `cmd_rerere_clear()` function with an empty option table, preserving the existing `rerere_clear()` call and behavior. Patch 7 extracted the "status" action into a dedicated `cmd_rerere_status()` function with an empty option table, preserving the existing logic: it lists conflicted paths by reading the `MERGE_RR` file and printing each entry. Patch 8 extracted the "remaining" action into a dedicated `cmd_rerere_remaining()` function with an empty option table, preserving the existing logic: it calls `rerere_remaining()` to populate a string list of conflicted paths, prints the unresolved ones, and cleans up. Patch 9 extracted the "diff" action into a dedicated `cmd_rerere_diff()` function with an empty option table, preserving the existing logic: it calls `rerere_cache_setup()` with `RERERE_READONLY`, iterates over the conflicted paths in `MERGE_RR`, and invokes `diff_two()` on each preimage. Patch 10 extracted the "gc" action into a dedicated `cmd_rerere_gc()` function with a hidden `--skip-locked` option in its option table, removing the now-redundant global `--skip-locked` flag from the top-level parser and dropping the corresponding negative test from `t/t4200-rerere.sh`. Patch 11 replaced the hand-rolled `if (!strcmp(...))` ladder with an `OPT_SUBCOMMAND()` table for the six subcommands, introduces `cmd_rerere_perform()` as the fallback subcommand (renamed from the prior `rerere()` to clarify its role), and removes the global `--[no-]rerere-autoupdate` flag from the top-level parser, parsing it locally in `cmd_rerere_perform()` instead. This is framed as a bug fix, since the flag was previously accepted but ignored for all subcommands except the default. The `PARSE_OPT_SUBCOMMAND_OPTIONAL` flag ensures backward compatibility: if no subcommand is given, the parser invokes `cmd_rerere_perform()` instead of erroring out. Patch 12 adds per-subcommand usage strings to the man page (`Documentation/git-rerere.adoc`) and to each subcommand function in `builtin/rerere.c`, completing the series. No substantive objections remain; the series is ready for integration once Junio picks it up.

Key technical details
- Files: `builtin/rerere.c` (primary), `rerere.h`, `Documentation/git-rerere.adoc`, plus callers in `apply.c`, `builtin/am.c`, `builtin/commit.c`, `builtin/merge.c`, `builtin/stash.c`, `rerere.c`, `sequencer.c`.
- Symbols: functions renamed to follow subcommand naming (`rerere()` replaces `repo_rerere()` in patch 1; the function’s signature and behavior are unchanged, but its documentation in `rerere.h` is expanded to clarify its role as the main entry point for recording and reusing conflict resolutions; `cmd_rerere_perform()` introduced in patch 11 as the fallback subcommand); flags converted to enums (`enum rerere_flags` replaces `#define RERERE_AUTOUPDATE`, `RERERE_NOAUTOUPDATE`, `RERERE_READONLY`, `RERERE_NOWAIT`). The comment on `RERERE_NOWAIT` (immediate failure when `MERGE_RR.lock` is taken) is confirmed correct; the enum now documents all four flags for clarity. `the_repository` usage fully removed as of patch 3: every rerere helper (`rerere()`, `rerere_forget()`, `rerere_clear()`, `rerere_gc()`, `rerere_cache_setup()`, `rerere_remaining()`, `rerere_path()`) now receives an explicit `repo` parameter instead of relying on the global. The `USE_THE_REPOSITORY_VARIABLE` macro is dropped, and the `UNUSED` annotation on the `repo` parameter is removed.
- Subcommands: "forget", "clear", "status", "remaining", "diff", and "gc" now have dedicated functions (`cmd_rerere_forget()`, `cmd_rerere_clear()`, `cmd_rerere_status()`, `cmd_rerere_remaining()`, `cmd_rerere_diff()`, `cmd_rerere_gc()`) with standard `parse_options()` machinery. The fallback subcommand is `cmd_rerere_perform()`, introduced in patch 11. Patch 4 removed the unused `--[no-]rerere-autoupdate` flag from the "status" and "diff" subcommands, hard-coding `RERERE_READONLY` in their call sites. Patch 11 removes the global `--[no-]rerere-autoupdate` flag from the top-level parser, parsing it locally in `cmd_rerere_perform()` instead, framed as a bug fix since the flag was previously accepted but ignored for all subcommands except the default. Patch 10 introduces a hidden `--skip-locked` option in `cmd_rerere_gc()`'s option table, preserving the existing `rerere_gc()` call and behavior, and removes the now-redundant global `--skip-locked` flag from the top-level parser.
- Documentation: `Documentation/git-rerere.adoc` updated in patch 12 to include per-subcommand usage strings in the `SYNOPSIS` section, matching the style of other multi-subcommand built-ins (e.g., `git notes`). Each subcommand ("clear", "diff", "forget", "gc", "remaining", "status", and the default `--[no-]rerere-autoupdate` mode) now has its own line in the synopsis. The C code (`builtin/rerere.c`) defines seven `N_()`-wrapped usage strings (one per subcommand), and each subcommand’s `parse_options()` call references its own usage array. The top-level `rerere_usage[]` array is extended to list all seven synopses.
- No new CLI options, config keys, test files, or on-disk format changes.
