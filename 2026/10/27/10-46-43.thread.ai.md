Core problem or goal
Replace the custom subcommand-parsing logic in `git rerere` with Git’s standard `OPT_SUBCOMMAND()` mechanism, bringing the command in line with other multi-subcommand built-ins like `git notes` and `git maintenance`. The series is purely internal restructuring: no new functionality, no behavior changes, and no on-disk format changes.

Key technical details
- Files: `builtin/rerere.c` (primary), `rerere.h`, `Documentation/git-rerere.adoc`, plus callers in `apply.c`, `builtin/am.c`, `builtin/commit.c`, `builtin/merge.c`, `builtin/stash.c`, `rerere.c`, `sequencer.c`.
- Symbols: functions renamed to follow subcommand naming (`rerere()` replaces `repo_rerere()` in patch 1; the function’s signature and behavior are unchanged, but its documentation in `rerere.h` is expanded to clarify its role as the main entry point for recording and reusing conflict resolutions; `cmd_rerere_perform()` introduced in patch 11 as the fallback subcommand; `cmd_rerere_clear()`, `cmd_rerere_status()`, `cmd_rerere_forget()`, `cmd_rerere_remaining()`, `cmd_rerere_diff()`, and `cmd_rerere_gc()` introduced as dedicated functions for their respective subcommands). Patch 10 specifically introduces `cmd_rerere_gc()` with a hidden `--skip-locked` option, preserving the existing behavior where `rerere_gc()` skips garbage collection if another process holds the lock. The global `--skip-locked` flag is removed from the top-level parser, as it is now scoped to the "gc" subcommand. Flags converted to enums (`enum rerere_flags` replaces `#define RERERE_AUTOUPDATE`, `RERERE_NOAUTOUPDATE`, `RERERE_READONLY`, `RERERE_NOWAIT` in patch 2). The enum values are defined as bit shifts (`1 << 0`, `1 << 1`, etc.) to preserve the existing bitmask semantics. The comment on `RERERE_NOWAIT` (immediate failure when `MERGE_RR.lock` is taken) is confirmed correct. The enum now documents all four flags for clarity, with `RERERE_NOAUTOUPDATE` explicitly clarified to update the working tree but leave the index untouched while still printing conflict-resolution messages to stderr.
- **Three-state flag system**: The `RERERE_AUTOUPDATE` and `RERERE_NOAUTOUPDATE` flags form a three-state system: (0) follow the configured `rerere.autoUpdate` default, (1) force `--autoupdate`, or (2) force `--no-autoupdate`. The CLI parser (`parse_opt_tertiary()`) prevents both bits from being set simultaneously, but the consuming code (`rerere_cache_setup()`) now explicitly validates the state with a `BUG()` check added in v4. In the invalid case (both bits on), the `BUG()` triggers, ensuring no silent precedence behavior. This is not a regression—it predates the series—but the refactoring made it newly visible and actionable.
- Subcommands: "forget", "clear", "status", "remaining", "diff", and "gc" now have dedicated functions (`cmd_rerere_forget()`, `cmd_rerere_clear()`, `cmd_rerere_status()`, `cmd_rerere_remaining()`, `cmd_rerere_diff()`, `cmd_rerere_gc()`) with standard `parse_options()` machinery. The fallback subcommand is `cmd_rerere_perform()`, introduced in patch 11. Patch 3 removes the last references to the global `the_repository` variable in `builtin/rerere.c`, replacing all 13 uses with the `repo` parameter passed to `cmd_rerere()`. The change is safe because `git rerere` cannot run outside a repository, and the `parse_options()` call happens before any repository access, so the `repo` pointer is guaranteed to be valid even when `-h` is used. Patch 4 removes the unused `--[no-]rerere-autoupdate` flag from the "status" and "diff" subcommands, hard-coding `RERERE_READONLY` in their call sites. The change is purely internal: no behavior change, no new CLI options, and no on-disk format changes. The motivation is to simplify subsequent refactorings by eliminating dead flag-passing. Patch 5 introduces `cmd_rerere_forget()` with an empty option table, preserving the existing warning about deprecated usage (`'git rerere forget' without paths`) and pathspec handling. Patch 6 introduces `cmd_rerere_clear()` with an empty option table, preserving the existing `rerere_clear()` call and behavior, including the handling of the `merge_rr` string list. Patch 7 introduces `cmd_rerere_status()` with an empty option table, preserving the existing logic, including the `RERERE_READONLY` flag, the `merge_rr` string list, and the loop that prints each conflicted path. Patch 8 introduces `cmd_rerere_remaining()` with an empty option table, preserving the existing logic (11 lines of code moved verbatim from the hand-rolled subcommand ladder in `cmd_rerere()` into a new 31-line function). The function follows the established pattern from earlier patches, using an empty `struct option` array and a `parse_options()` call to validate arguments before invoking the core `rerere_remaining()` logic. The `string_list_clear()` cleanup and the loop that prints unresolved conflicts are preserved verbatim. The only difference is the addition of a usage check (`if (argc) usage(...)`), previously handled by the top-level `cmd_rerere()` function. Patch 9 introduces `cmd_rerere_diff()` with an empty option table, preserving the existing logic: it iterates over conflicted paths in `merge_rr`, generates diffs between the stored preimage and the working tree, and dies on failure. The only difference is the addition of a usage check (`if (argc) usage(...)`), previously handled by the top-level function. Patch 10 introduces `cmd_rerere_gc()` with a hidden `--skip-locked` option in its option table, preserving the existing `rerere_gc()` call and behavior, and removes the now-redundant global `--skip-locked` flag from the top-level parser. The patch also removes a test (`--skip-locked is only accepted by gc`) that is no longer needed, as the option is now scoped to the "gc" subcommand. Patch 11 replaces the hand-rolled subcommand ladder with an `OPT_SUBCOMMAND()` table, introduces `cmd_rerere_perform()` as the fallback subcommand, and removes the global `--[no-]rerere-autoupdate` flag from the top-level parser, parsing it locally in `cmd_rerere_perform()` instead. The fallback logic constructs a synthetic `"perform"` subcommand name and re-parses the arguments to ensure consistent behavior. The patch preserves all existing functionality, including the three-state autoupdate system and the `PARSE_OPT_KEEP_UNKNOWN_OPT` flag for forwards compatibility. The synthetic `"perform"` subcommand name is an internal placeholder and is not exposed to users. Patch 12 adds per-subcommand usage strings to the man page and C code, completing the series. Seven `N_()`-wrapped usage strings are defined (one per subcommand), each subcommand’s `parse_options()` call references its own usage array, and the man page’s `SYNOPSIS` section is updated to list each subcommand on its own line.
- Documentation: `Documentation/git-rerere.adoc` updated in patch 12 to include per-subcommand usage strings in the `SYNOPSIS` section. The documentation for `enum rerere_flags` has been further polished in v4 to clarify the three-state system (follow default, force autoupdate, force no-autoupdate) and the purpose of each flag.

Open questions and loose ends
1. **Documentation gap in `enum rerere_flags`**: While the documentation now clearly describes the three-state system and the behavior of each flag, the *rationale* for the three-state system (overriding the configured `rerere.autoUpdate` default) is still not explicitly captured in the enum’s documentation. A brief example or explanation of why this system exists (e.g., "to allow callers to override the configured default without modifying the configuration") could further improve clarity. This is a minor, non-blocking gap.
