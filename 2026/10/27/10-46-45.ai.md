This is the second patch in Patrick Steinhardt’s 12-patch refactoring series modernizing `git rerere`’s subcommand handling. It mechanically converts the existing integer bit-flags (`RERERE_AUTOUPDATE`, `RERERE_NOAUTOUPDATE`, `RERERE_READONLY`, `RERERE_NOWAIT`) into a proper C `enum rerere_flags`. The change touches only two files: `rerere.h` (where the enum is defined and the old `#define` constants are removed) and `rerere.c` (where function signatures are updated to use the new enum type). No callers outside these files are modified yet; those updates appear in later patches.

The patch is a textbook example of a low-risk, guideline-aligned refactoring. Git’s coding guidelines recommend enums for flag parameters, and the conversion here is purely syntactic: the numeric values remain identical, so behavior is unchanged. The commit message is concise but sufficient, and the diff is small and focused. There are no open questions or edge cases mentioned, and the patch does not introduce any new symbols or test failures.

This step is a prerequisite for the later patches that will switch `git rerere` to the standard `OPT_SUBCOMMAND()` mechanism. Reviewers familiar with Git’s internal APIs or the rerere subsystem may want to verify that the enum values match the original bitmasks, but the patch itself is unlikely to be controversial.
