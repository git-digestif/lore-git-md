This is the third patch in Harald Nordgren’s four-patch bugfix series for `git imap-send`, now in its fourth iteration (`v4`). The patch removes a special-case exemption that previously allowed messages starting with `From git-send-email` to bypass the normal header-checking logic. The exemption was introduced in commit `04133f5bc4` (2025-08-12) to work around `git send-email`’s non-canonical header order (writing `Subject` before `Date`), but is now redundant because earlier patches in the series (`2/4` and `4/4`) make the header-parsing logic accept any order and any case for `From:`, `Date:`, and `Subject:` headers.

The change is minimal: it replaces a 19-line conditional block with a single line that applies the same `has_required_headers()` check to all messages, regardless of their `From` line. The commit message explicitly addresses backward-compatibility concerns, noting that RFC 5322 requires `Date` and recommends `Subject`, so any valid message from a third-party script would already include these headers. The test added in `t/t9001-send-email.sh` verifies that `--imap-sent-folder` continues to work as expected, storing a copy of the sent patch in the specified IMAP folder.

This patch is uncontroversial and ready for integration. The prior feedback (Patrick Steinhardt’s request for clearer documentation of the backward-compatibility implications) has been fully addressed by the expanded commit message. The change is low-risk: it tightens the header-checking logic without breaking any existing workflows, and the test coverage confirms that `--imap-sent-folder` remains functional. The patch touches only `imap-send.c` and the test suite, with no new symbols or on-disk format changes. It is part of a well-motivated series that fixes real interoperability issues with tools like `b4` and `lore.kernel.org`.
