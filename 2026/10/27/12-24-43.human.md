This is the fourth patch in Harald Nordgren’s v12 series introducing `remote.<name>.fetchRefmap` for matching-inspired fetch mode. The patch adds a `--limited-fetch` option to `git remote add` that configures `remote.<name>.fetchRefmap` (e.g., `*@{upstream}`) instead of the traditional wildcard `remote.<name>.fetch` refspec. This ensures that a refspec-less `git fetch <name>` only fetches the branches already tracked by local branches, avoiding the slow or hanging behavior in shallow repositories with many remote branches.

The implementation is straightforward and well-tested. The option is rejected when combined with `-t/--track` or `--mirror`, since those already specify what to fetch. The patch updates `builtin/remote.c` to set `remote.<name>.fetchRefmap` (with a wildcard refmap for namespace mapping) when `--limited-fetch` is used, and adds two new tests in `t/t5505-remote.sh` to verify the behavior and conflict detection. Documentation in `git-remote.adoc` is updated to explain the new option and its effect.
