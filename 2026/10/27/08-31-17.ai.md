This is the second patch in Harald Nordgren’s four-patch bugfix series for `git imap-send`, addressing RFC 5322 compliance by making the header-parsing logic order-agnostic. The patch replaces the rigid three-header sequence check (`From:`, `Date:`, `Subject:`) with a flexible scan that accepts the three required headers in any order within each message’s header block. The change is motivated by interoperability with tools like `b4`, which emit patches with `Subject` before `Date`—a valid but non-canonical order that previously caused `git imap-send` to silently drop the message.

The implementation introduces a helper function `has_required_headers()` that scans the header block line-by-line, setting flags for each required header (`From:`, `Date:`, `Subject:`) regardless of order. The existing `count_messages()` logic is simplified to use this helper, eliminating the brittle `strstr()` chain that enforced the fixed order. The patch also adds a new test in `t/t9001-send-email.sh` that verifies the fix: it sends a patch with `git send-email`, captures the output in an mbox file (simulating a mailing-list archive), and confirms `git imap-send` can now process it without error.

The change is minimal and focused, touching only `imap-send.c` and the test suite. No new symbols are introduced, and the on-disk format is unaffected. The test coverage is thorough, exercising the exact workflow that previously failed (fetching a patch from an archive and feeding it back into `imap-send`). This patch is uncontroversial and ready for integration; all prior feedback on the series has been addressed in `v4`, and the remaining patches (3/4 and 4/4) build on this foundation to handle case insensitivity and remove a special-case exemption. The series as a whole is queued in `seen` and likely to graduate to `next` soon.
