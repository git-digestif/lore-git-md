This is the third and final patch in Pablo Sabater’s RFC series lifting the 10k OID limit for `git cat-file --remote-object-info`. It adds the `--remote-max-batch=<n>` option, letting users override the default 50k batch size. The patch is cleanly split: documentation updates, CLI plumbing in `builtin/cat-file.c`, and a new test script (`t/t1017-cat-file-remote-object-info.sh`) that verifies the option rejects invalid values and works across batch boundaries for all transport protocols (git://, file://, http://).

The implementation is straightforward: the option is parsed early, stored in the `batch_options` struct, and used to chunk OIDs in the existing batching loop. The only constraint is that `--remote-max-batch` requires `--batch-command`, enforced at option-parsing time. Tests cover edge cases (zero, non-numbers, wrong mode) and confirm that objects spanning multiple batches are still handled correctly. No new transport-layer code is introduced; this is purely a user-facing knob on top of the refactoring and batching logic already landed in patches 1 and 2.
