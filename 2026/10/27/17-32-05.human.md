This is a test infrastructure cleanup series from Jeff King (Peff) that overhauls how Git's unit tests are run. The core issue: unit tests currently bypass the standard `test-lib.sh` harness, making failures hard to debug in CI because their TAP output is swallowed by `prove`. The series fixes this by wrapping unit tests in a proper test script (`t0011-unit-tests.sh`), which also ensures they benefit from the same environment setup (e.g., LSAN_OPTIONS) as regular tests.

The first three patches are small bugfixes: correcting argument reporting in unit tests, removing unused variables in `test-lib.sh`, and stopping the generation of misleading JUnit XML for empty test suites. Patch 4 extends `test-lib.sh` to accept TAP output from external programs, and patch 5 implements the core change—running unit tests through `test-lib.sh`. The remaining patches (6–8) clean up redundant invocations and remove now-obsolete code, including the JUnit XML reporting machinery and a deprecated `test-run-command` mode.

The diffstat is striking: 433 lines deleted across 14 files, with only 33 added. The final two patches are marked RFC, suggesting they might need further discussion, but the rest look like straightforward improvements. The series directly addresses a real pain point (debugging unit test failures) and aligns the testing infrastructure with Git's established patterns. Well-motivated and clearly explained.
