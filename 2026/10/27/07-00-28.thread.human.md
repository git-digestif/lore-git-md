This thread is about a single-patch bugfix from Patrick Steinhardt that prevents a `BUG()` crash in `git pack-objects --exclude-promisor-objects-best-effort` when handling partial clones. The crash happens when the revision walk encounters missing objects—like trees filtered out by `tree:0` or beyond shallow boundaries—because the callback `is_not_in_promisor_pack_obj()` assumes all objects exist. The fix replaces the crash with a graceful skip, treating missing objects as promisor objects, aligning with existing logic elsewhere in the codebase. The regression was introduced by two earlier commits, with the second one exposing the bug in new scenarios.

The patch itself is narrowly focused on the callback function and includes two new test cases in `t/t5616-partial-clone.sh` to verify the fix works with `--unshallow`/`--deepen=1` and missing-tree scenarios. Junio C Hamano has reviewed the patch and suggested a small but important improvement: explicitly passing `OBJECT_INFO_SKIP_FETCH_OBJECT` to `odb_read_object_info_extended()` to make the code’s intent clearer, even though the current behavior is technically correct. This feedback doesn’t challenge the core logic but aims to improve maintainability. The patch is still under review, with no indication of merge status yet. The only other participant so far is Mark C. Chu-Carroll, who provided a surface-level review on commit message wording.
