This is a documentation terminology discussion in the ongoing Git glossary thread. Junio C Hamano replies to D. Ben Knoble’s defense of Julia Evans’s proposed clarification, reinforcing his position that "object name" must remain the canonical term for the hash identifier (SHA-1 or SHA-256).

Junio dismisses the argument that Git should align its terminology with user expectations, framing the issue as a matter of consistency with the project’s 20-year-old glossary definition. He clarifies that terms like `main` (a branch name) are *not* object names or object IDs but merely notations that can be used *in place of* an object name to refer to an object. This distinction is central to his rejection of Julia’s patch: the glossary’s definition of "object name" as the unique hash identifier is correct, and any documentation suggesting otherwise (e.g., `gitrevisions(1)`) should be fixed, not the glossary.

The email does not propose a new solution or compromise. Instead, it doubles down on the status quo, leaving the thread at an impasse. The maintainer’s stance remains unchanged: the glossary is authoritative, and the burden is on others to audit and correct inconsistent documentation elsewhere. No technical changes are proposed, and the discussion remains purely about terminology. For readers following the thread, this email confirms that the patch is blocked unless someone undertakes the broader documentation cleanup Junio demands.
