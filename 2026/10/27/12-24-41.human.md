This is the second patch in Harald Nordgren’s v12 series introducing `remote.<name>.fetchRefmap` for matching-inspired fetch mode. It is a pure refactoring patch that extracts the logic for collecting upstream refs from a remote into a reusable helper, `collect_upstream_from_remote()`.

The patch moves the existing inlined code that checks whether the current branch builds on a given remote and, if so, adds its upstream refs to the list of prefixes to fetch. This logic is currently used only for the current branch, but the new helper is designed to work for any branch (or the current branch if `refname` is `NULL`). The helper is added to `remote.c` and declared in `remote.h`, making it available for reuse in the next patch, which extends the logic to all local branches.

The change is mechanical and well-contained: it touches only `builtin/fetch.c`, `remote.c`, and `remote.h`, and the diff is straightforward. The commit message clearly explains the motivation (reusing the logic for branches other than the current one) and provides a concrete example of the behavior being preserved. There are no behavior changes, and the patch includes no new tests, as it is purely preparatory.

This is a clean, focused refactoring that sets up the next patch in the series. It is ready for review and has no known issues.
