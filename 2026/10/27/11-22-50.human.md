This is a substantive review comment on the sixth patch in Patrick Steinhardt’s v2 series, which restores dynamic reloading of alternate object databases in Git’s files-based ODB backend. Christian Couder identifies a race condition in the alternates file reloading logic: if the file is rewritten in-place while Git is reading it, the `stat_validity` tracking could be updated with stale content, causing Git to miss the new alternates indefinitely. The issue is specific to in-place rewrites (e.g., `echo >alternates`) and does not affect atomic replacements via rename.

Christian’s proposed fix reorders the logic to update the `stat_validity` struct *before* reading the file, matching the pattern used in `refs/packed-backend.c` and `shallow.c`. This ensures that if the file changes during the read, the next attempt will detect the change and re-read it. The fix is mechanical, preserves correctness, and addresses Junio’s earlier feedback about error handling. The review is thorough, citing specific code paths and edge cases, and includes a concrete reproduction scenario from the test suite. No objections or alternative approaches have been raised; the issue appears uncontroversial and ready to be addressed in a v3.
