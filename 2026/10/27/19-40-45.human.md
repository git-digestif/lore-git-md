This is a brief follow-up in the `git rerere` subcommand modernization thread. Junio C Hamano replies to Mark C. Chu-Carroll’s suggestion about the `enum rerere_flags` definition in the second patch of Patrick Steinhardt’s 12-patch series.

Junio clarifies that the comment on `RERERE_NOWAIT` is not describing an undocumented enum value, but rather explaining the intended behavior of the `RERERE_NOWAIT` flag itself: when the `MERGE_RR.lock` file is already held, passing `RERERE_NOWAIT` causes the function to return `-1` immediately, as if rerere were disabled. The comment is therefore not a placeholder for a missing enum value, but a behavioral note about an existing one. Junio’s response effectively closes the stylistic question Mark raised, leaving the patch as-is. No further changes to the enum definition are expected.
