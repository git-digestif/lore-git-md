This is a refactoring patch targeting the `the_repository` removal effort. It updates `prune_packed_objects()` in `prune-packed.c` to accept an explicit `struct repository *` parameter instead of relying on the global `the_repository` variable, addressing the last remaining feedback from the v3 review.

The patch introduces a new `struct prune_data` to bundle the repository pointer and `opts` integer for compatibility with the single-`void *data` callback interface of `for_each_loose_file_in_source()`. The commit message now explicitly explains why dereferencing `repo` is safe even when it could theoretically be `NULL` (due to `RUN_SETUP` and `parse_options()` handling `-h` early). The three lines in `prune-packed.c` that previously used spaces instead of tabs for indentation have also been corrected.

Files touched remain the same as in v3: `builtin/prune-packed.c`, `builtin/prune.c`, `builtin/repack.c`, `prune-packed.c`, and `prune-packed.h`. The changes are mechanical and do not alter behavior, only internal API structure. The patch is part of an Outreachy contribution and is now functionally complete, with all prior feedback incorporated. No test failures or edge cases are expected, as this is purely a plumbing adjustment to support better modularity and libification. The patch is uncontroversial and appears ready for merging.
