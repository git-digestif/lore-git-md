This thread is about Jeff King’s (Peff) eight-patch series refactoring Git’s unit test infrastructure to improve debuggability and remove obsolete code. The goal is to unify unit tests with the shell test suite by wrapping them in `test-lib.sh`, enabling better logging, leak detection, and CI integration. The series also fixes minor bugs, such as incorrect error messages in the unit test driver and empty test suite handling in JUnit XML reporting.

Patches 1–6 are uncontroversial and ready for integration, addressing core integration, cleanup, and redundant infrastructure removal. Patch 7 (released earlier) removed the legacy `test-tool run-command testsuite` mode, which Peff marked as RFC to solicit feedback on whether it’s still needed for tools like Visual Studio. Patch 8, the latest update, removes the shell-based JUnit XML reporting code—including the `test-xml-encode` helper and `test-lib-junit.sh` script—since Azure Pipelines support was dropped in early 2025, and GitLab CI now relies on Meson’s built-in reporting. This patch is also marked as RFC, with Peff inviting input on whether the removed functionality is still useful for out-of-tree users.

The series has seen no objections or requests for changes so far, but the RFC status on the final two patches suggests they may need further discussion. The rest of the series is poised for merging, with no maintainer decision yet reported. Key outcomes include improved debuggability for unit test failures, elimination of redundant test runs, and removal of ~614 lines of obsolete code.
