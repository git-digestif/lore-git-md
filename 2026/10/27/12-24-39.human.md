This is the v12 cover letter for Harald Nordgren’s long-running series that introduces a new `remote.<name>.fetchRefmap` configuration key to solve a performance problem in shallow repositories. The series is now feature-complete and ready for final review.

The core idea is simple: when you clone a large repository with `--depth`, a plain `git fetch` or `git pull` can hang or take minutes because it negotiates history for every remote branch. The new `fetchRefmap` key lets users configure a remote so that a refspec-less fetch only brings in the branches that local branches already track at that remote, avoiding the unnecessary work.

v12 is a pure rename-and-polish release. The controversial `remote.<name>.refmap` key from v11 has been renamed to `remote.<name>.fetchRefmap` to make it unambiguously clear that it only controls the mapping of refs that are already being fetched, not the selection of what to fetch. The commit message and documentation have been tightened to spell out the interaction with `remote.<name>.fetch`: when both are configured, `fetch` still decides what is fetched, and `fetchRefmap` only remaps it. A new test verifies that a remote configured with three named branches and a wildcard refmap stores all three under the same namespace.

The series is now five patches long. Patch 1 adds the new config key and its parsing; patch 2 extracts a helper that will be reused in patch 3, which implements the dynamic branch inference when `fetchRefmap` is configured but `fetch` is not; patch 4 adds the `--limited-fetch` flag to `git remote add`; and patch 5 makes `--limited-fetch` the default in shallow repositories. The test coverage is thorough, with new tests in `t/t5510-fetch.sh` and a dedicated `t/t5586-fetch-refmap.sh` that exercises the new mode.

The design direction was finalized in the v11 thread, and Junio and Phillip Wood have already signed off on the conceptual approach. This version addresses the last remaining mechanical concerns: the rename from `refmap` to `fetchRefmap`, a missing code path in `get_ref_map()` that ensures branches named in `remote.<name>.fetch` are also stored through `fetchRefmap`, and clearer documentation. The implementation looks clean, the tests are comprehensive, and the motivation is compelling. This is a well-crafted solution to a real problem, and it should be uncontroversial at this point.
