This is a CI/build system patch (5/8 in the series) that aligns test behavior with Git’s compiled-in defaults for ref storage. The patch ensures that when "breaking changes" are enabled—meaning tests run with SHA-256 by default—they also use the default ref storage backend (reftable) instead of hardcoding the "files" backend. This change removes the now-redundant `linux-reftable-sha256` CI job, which previously existed to explicitly test that combination.

The patch touches `.github/workflows/main.yml`, `.gitlab-ci.yml`, `t/test-lib-functions.sh`, and `t/test-lib.sh`. The key change is in `test-lib.sh`, where `GIT_DEFAULT_REF_STORAGE_FORMAT` now falls back to the built-in default (`GIT_TEST_BUILTIN_REF_STORAGE_FORMAT`) rather than hardcoding "files". The helper function `test_detect_ref_format()` in `t/test-lib-functions.sh` is updated to match this logic. The CI workflows drop the explicit `linux-reftable-sha256` job since the `linux-breaking-changes` job will now cover that case automatically.

This is a small but meaningful cleanup: it eliminates a redundant CI job and ensures tests exercise the same ref backend that users will get by default. The change is mechanical and well-motivated, though the commit message could have been clearer about why the `linux-reftable-sha256` job was originally needed and what problem its removal solves. The patch is part of Patrick Steinhardt’s broader CI consolidation series, which aims to reduce duplication and improve maintainability across GitHub Actions and GitLab CI workflows. No functional changes to test logic are introduced—just alignment with existing defaults.
