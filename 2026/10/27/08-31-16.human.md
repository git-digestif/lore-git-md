This is the first patch in Harald Nordgren’s four-part bugfix series for `git imap-send`, now in its fourth iteration (`v4`). The patch plugs a long-standing process lifecycle leak: when `imap.tunnel` is configured, `git imap-send` starts the tunnel command but never waits for it to exit, leaking both the process and its argument list. The fix is straightforward: store the tunnel as an allocated `struct child_process` pointer in the `imap` struct, then reap it with `finish_command()` and free the memory when the connection closes. The change is defensive—it avoids edge cases around `finish_command()` on uninitialized `struct child_process`—and aligns with the run-command API’s expectations. No test sets `imap.tunnel`, so the leak was previously invisible to the test suite.

The patch was previously merged to `next` but has been revised in `v4` to address Patrick Steinhardt’s feedback about defensive coding. The revision replaces the stack-allocated `struct child_process` with a heap-allocated one, eliminating any risk of `finish_command()` operating on uninitialized memory. The change is minimal, focused, and uncontroversial, with no behavioral impact beyond fixing the leak. The rest of the series (patches 2–4/4) is ready for integration and addresses header-parsing interoperability with tools like `b4`. This patch should graduate to `master` alongside them.
