This is the first patch in Patrick Steinhardt’s 12-patch series modernizing `git rerere`’s subcommand handling. It performs a single, mechanical rename: the function `repo_rerere()` becomes `rerere_record()` to align with the naming convention used by every other function in `rerere.h`. The change is purely internal; no behavior or interface changes occur.

The patch touches nine files: `apply.c`, `builtin/am.c`, `builtin/commit.c`, `builtin/merge.c`, `builtin/rerere.c`, `builtin/stash.c`, `rerere.c`, `rerere.h`, and `sequencer.c`. Each call site is updated to use the new name, and the function signature in the header and implementation files is adjusted accordingly. The commit message explains the rationale clearly: the `repo_` prefix was inconsistent with the rest of the rerere API, and the new name better reflects the function’s purpose.

This is a straightforward, uncontroversial refactoring step that sets the stage for the rest of the series. The patch is well-scoped and appears to be a clean, low-risk change. No review feedback has been posted yet.
