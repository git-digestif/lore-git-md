This is the first patch in Patrick Steinhardt’s seven-part series introducing the object storage extension (`extensions.objectStorage`). It is a **cleanup patch** that removes a dead function, `repo_write_loose_object_map()`, from the loose object backend.

The function was introduced in 2023 to write a mapping between SHA-1 and SHA-256 for loose objects, but it was never called. Instead, the codebase uses `repo_add_loose_object_map()` to update the mapping incrementally when new loose objects are created. Beyond being unused, the function hardcodes the location of the loose-object index file, which conflicts with the rest of the code that derives the path from the loose source’s configured directory. Removing it eliminates 46 lines of dead code and avoids a potential inconsistency.

The change is straightforward and uncontroversial: it deletes the function from `loose.c` and its declaration from `loose.h`. No behavior changes are introduced, and the commit message clearly explains why the function is safe to remove. This patch is a prerequisite for the rest of the series, which builds on the loose object backend’s existing structure. Karthik Nayak has already approved the entire series, and this patch in particular has no open questions. It is ready for integration.
