This thread is about a small but practical build-system tweak: enabling ccache to cache objects built with Git’s precompiled header (introduced in commit 8d3a673147). Without the patch, ccache refuses to cache these objects, causing noticeable slowdowns on rebuilds and branch switches—Harald Nordgren reports a 3× speedup for warm-cache rebuilds and 6× for branch switches after applying it.

The patch itself is minimal: it adds two ccache “sloppiness” flags (`pch_defines`, `time_macros`) to the Makefile. The change is uncontroversial in principle, but two implementation questions remain open. First, Ben Knoble raised concerns about whether the target-specific `export` in GNU Make will propagate correctly to recipe processes; Harald acknowledged the issue but hasn’t revised the patch. Second, the Meson build system is left unmodified, creating a potential inconsistency for users who switch between build tools. Patrick Steinhardt suggested the feature should be handled upstream in Meson, and Harald now plans to explore that route, leaving the Git-side change as-is for now.

No objections to the patch’s goals or safety have been raised, and the discussion has quieted down. The patch is still under review, with no prior versions posted. If you’re using ccache and Git’s precompiled headers, this change is worth watching—it’s a straightforward performance win once the Makefile semantics are confirmed.
