This thread is about a small but impactful build system patch that makes ccache work properly with Git’s precompiled header feature. Harald Nordgren originally proposed a two-line Makefile change to set ccache “sloppiness” flags (`pch_defines`, `time_macros`) so ccache would cache objects built with the precompiled header, fixing a performance regression on rebuilds and branch switches. After feedback from Ben Knoble questioning the Makefile semantics, Harald revised the patch (v2) to move the variable export out of target-specific rules and into the global precompiled-header block, ensuring the setting applies to all compilations that use the header.

The patch is now uncontested on its core goal and implementation, though it leaves the Meson build system unmodified—creating a temporary inconsistency for ccache users depending on the build tool. Harald and Patrick Steinhardt agree that ccache sloppiness for precompiled headers should ideally be handled upstream in Meson, and Harald may open a pull request there. Performance gains are substantial: warm-cache rebuilds are 3× faster, and branch switching is 6× faster, though the first build of each branch is about 25 % slower while ccache fills its cache. A known edge case with Clang (cache misses when switching branches that modify headers included by the precompiled header) remains unresolved but is acknowledged as a compiler limitation. The patch is ready for maintainer pickup, with the only loose end being the eventual Meson integration.
