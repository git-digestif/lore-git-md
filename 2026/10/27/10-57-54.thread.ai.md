Subject: [PATCH 0/3] sequencer: cleanup REBASE_HEAD and AUTO_MERGE refs
Series version: v1 (initial)
Originating author: Phillip Wood
Thread type: patch series (bugfix)

Core problem or goal
Fix a bug in the sequencer subsystem where `REBASE_HEAD` and `AUTO_MERGE` refs are not cleaned up after `git rebase --continue`, leaving stale refs that can confuse users or tools. The improved `test_ref_missing()` helper (patch 1) provides better diagnostics for the test suite, supporting the verification of the actual bugfix (patches 2-3).

Current status
Under review (v1 posted). Junio C Hamano has reviewed all three patches and explicitly approved the series with no requests for changes. The series remains narrowly scoped and uncontroversial; no merge status reported yet.

Key technical details
- Files touched: `sequencer.c`, `t/test-lib-functions.sh`, `t/t3403-rebase-skip.sh`, `t/t3407-rebase-abort.sh`, `t/t3418-rebase-continue.sh`
- New/renamed symbols: none
- Behavior change: `REBASE_HEAD` and `AUTO_MERGE` are now deleted during `git rebase --continue`, `--skip`, and `--abort` in two code paths: (1) in `do_commit()` after a successful commit (for `REBASE_HEAD` only), and (2) at the start of `pick_commits()` before the loop begins, ensuring cleanup even when continuing after conflicts or when the todo list is exhausted. The `test_ref_missing()` helper now includes the ref name in error messages for easier debugging.
- On-disk format: no changes
- Test coverage: added tests for cleanup in `--continue`, `--skip`, and `--abort` scenarios; existing test scripts updated to verify `REBASE_HEAD` and `AUTO_MERGE` presence during conflicts and absence after rebase completion.
