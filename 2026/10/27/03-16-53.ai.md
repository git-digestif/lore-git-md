This is the third and final patch in Pablo Sabater’s RFC series lifting the 10k OID limit for `git cat-file --remote-object-info` by introducing internal batching. It adds the `--remote-max-batch=<n>` option, letting users override the default 50k OID batch size. The patch touches `Documentation/git-cat-file.adoc`, `builtin/cat-file.c`, and introduces a new test script (`t/t1017-cat-file-remote-object-info.sh`) that verifies the option rejects invalid values (zero, non-numbers) and enforces the `--batch-command` requirement.

The implementation is straightforward: the option is parsed into a `batch_options` field, validated as a positive integer, and used to chunk OID lists in `parse_cmd_remote_object_info()`. Tests cover edge cases (batch boundaries, multiples of the batch size) across all transport protocols (git://, file://, http://). The commit message is minimal, but the series’ cover letter already provided benchmarks and rationale, so this patch focuses on the mechanics of exposing the knob to users. No substantive review feedback has appeared yet, but the code is clean, well-tested, and ready for scrutiny.
