This is a review reply from Junio C Hamano on the first patch of Pablo Sabater’s RFC series lifting the 10k OID limit for `` `git cat-file --remote-object-info` ``. The series aims to enable internal batching of large OID queries by refactoring transport ownership.

Junio’s feedback is brief but substantive. He agrees with the core refactoring goal—moving transport creation and cleanup from `get_remote_info()` to its caller—and endorses the variable rename from `gtransport` to `transport` as a clarity improvement. However, he flags the new error message “smart options required” as potentially confusing for end users, questioning whether it provides enough context for troubleshooting. The message appears when the transport lacks smart protocol options, but the phrasing assumes familiarity with Git’s internal transport layer.

The patch itself is a prerequisite for the batching logic in patch 2, touching only `builtin/cat-file.c`. No merge status is implied; this is still an RFC under review.
