This is the second patch in Pablo Sabater’s RFC series lifting the 10k OID limit for `git cat-file --remote-object-info`. It implements the core batching logic: the command now accepts an arbitrary number of OIDs and splits them into 50k-OID chunks internally, reusing the same transport connection for all chunks. The patch touches `builtin/cat-file.c`, `transport-helper.c`, `transport.c`, and their headers, converting the fetch-object-info API from returning an error code to dying on failure (matching the behavior of `git ls-remote`). The connection is kept open between batches, and the handshake is performed only once. No new user-facing options are introduced here; the 50k default is hard-coded until patch 3 adds `--remote-max-batch`. The change is purely behavioral: users can now pass 400k OIDs in a single command and see the 3× speedup shown in the cover letter.
