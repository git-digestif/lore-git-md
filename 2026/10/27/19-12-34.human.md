This is a brief follow-up in the ongoing RFC thread about `git cat-file --remote-object-info` batching. Junio C Hamano responds to Pablo Sabater’s cover letter, focusing on two points.

First, he notes that while the proposed default batch size of 50k OIDs is unrelated to `git backfill`’s 50k default, using the same number could simplify documentation. This is a minor observation, not a request for change, but it suggests Junio sees the choice as reasonable.

Second, he shifts attention to compatibility: how the new batching logic will interact with existing servers and clients. This is the first time backward and forward compatibility have been raised in the thread. Junio does not express a position yet, only curiosity, but the question itself signals that compatibility will be a key consideration before this series can move forward. No new code or benchmarks are introduced; the email is purely discussion.
