Thread identity: Refactoring of Git's unit test infrastructure to integrate `clar`-based unit tests with the shell test suite, improving debuggability and removing obsolete code. Series authored by Jeff King (Peff), currently at version 1.

Core problem or goal: Unit test failures in CI are difficult to debug because their TAP output is suppressed by `prove`, unlike the shell-based test suite which provides verbose logs. The series aims to unify the execution environment, leak detection, and logging for unit tests by wrapping them in `test-lib.sh`, while also cleaning up redundant or deprecated test infrastructure. A minor usability bug in the `unit-test.c` driver (incorrect error message for unexpected arguments) was fixed in the first patch.

Current status: Under review. The series consists of 8 patches. Patches 1-6 are ready for integration, with patches 1-5 previously noted as ready and patch 6 (the prior update) removing redundant unit test invocations and obsolete infrastructure. Patch 7 (this update) removes the `test-tool run-command testsuite` mode, a legacy helper used to run unit tests before the unified wrapper script (`t/t0011-unit-tests.sh`) was introduced. Patch 8 remains marked as RFC by the author. No maintainer decision or merge status has been reported.

Key technical details:
- **Files touched**: `t/test-lib.sh` (core integration logic, cleanup, and new `test_external` wrapper behavior), `t/Makefile` (build rules), `t/meson.build` (new dependency to ensure unit test binary is built before wrapper script), `t/t0011-unit-tests.sh` (new wrapper script for unit tests), `t/unit-tests/unit-test.c` (bugfix in error message handling), `t/test-lib-junit.sh` (bugfix for empty test suites), `ci/run-test-slice.sh` (CI test slice logic), `t/run-test.sh` (removed wrapper script), and **`t/helper/test-run-command.c`** (removed `testsuite` subcommand and supporting infrastructure).
- **New behavior**: Unit tests now run under `test-lib.sh` via the wrapper script `t/t0011-unit-tests.sh`, inheriting its environment setup, leak detection (e.g., `LSAN_OPTIONS`), and logging capabilities. The wrapper forwards relevant options like `--immediate` to the unit test binary but intentionally omits support for `--run` (due to syntax differences) and `--write-junit-xml` (unsupported by unit tests). TAP output from external programs (e.g., `clar` unit tests) is accepted by `test-lib.sh` via the `test_external` variable, which suppresses the TAP header and plan count while preserving skipped-test accounting. The `unit-test.c` driver correctly reports unexpected arguments in error messages. Empty test suites no longer trigger shell errors in JUnit XML reporting. The CI and build systems now invoke unit tests only once, via the wrapper script, eliminating redundant runs.
- **Removed infrastructure**: Shell-based JUnit XML reporting code (obsolete, removed in patch 8), deprecated `test-tool run-command testsuite` mode (removed in patch 7), redundant test invocations (removed in patch 6), the `run-test.sh` wrapper script (removed in patch 6), the `UNIT_TESTS_NO_DIR` variable (removed in patch 6), the `unit-tests-test-tool` target (removed in patch 6), and the now-unused variable `test_external_has_tap` (removed in patch 2). Patch 3 removes the problematic fallback logic for empty JUnit XML suites.
- **Net effect**: ~614 lines of code deleted (173 added in patch 7), improved debuggability for unit test failures in CI, a minor usability fix in the unit test driver, elimination of redundant test runs, and removal of a CI annoyance (empty test suites causing misleading errors).
- **Symbols**: New wrapper script `t/t0011-unit-tests.sh`; new binary path variable `UNIT_TESTS`; modified functions in `test-lib.sh` to handle TAP output from external programs (via `test_external`); corrected error message in `unit-test.c`; removed variables `test_external_has_tap` and `UNIT_TESTS_NO_DIR`; removed targets `unit-tests-test-tool`, `run-test.sh`, and `test-tool run-command testsuite`; removed redundant Meson test entry for unit tests; updated `prove` invocation in CI to use `TEST_SHELL_PATH` directly and pass `GIT_TEST_OPTS` via `prove`’s `::` separator.
