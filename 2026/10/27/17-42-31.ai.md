This is the final patch (8/8) in Jeff King’s test infrastructure refactoring series, removing the shell-based JUnit XML reporting code. The patch deletes the `test-xml-encode` helper binary and the `test-lib-junit.sh` script, which were previously used to generate JUnit XML output for Azure Pipelines. Since Azure Pipelines support was removed in early 2025 and GitLab CI now relies on Meson’s built-in JUnit reporting, this code is no longer needed. The patch also removes the `--write-junit-xml` option from `test-lib.sh`, simplifying the test harness.

The removal is clean: no in-tree consumers remain, and the commit message notes that out-of-tree users (if any) would need to revert this patch. The patch deletes ~213 lines across 7 files, including the entire `test-xml-encode.c` and `test-lib-junit.sh` files. The `start_test_case_output` and `finalize_test_output` hooks in `test-lib.sh` are left intact for potential future use, but the JUnit-specific logic is gone.

This patch is marked as RFC by Peff, who invites feedback on whether the removed `test-tool xml-encode` functionality is still needed (e.g., for Visual Studio users). No objections have been raised yet, but the RFC status suggests the patch may need further discussion before merging. The rest of the series (patches 1–7) is uncontroversial and ready for integration. Key symbols removed: `test-xml-encode` binary, `test-lib-junit.sh`, `--write-junit-xml` option, and the `xml-encode` subcommand in `test-tool`.
