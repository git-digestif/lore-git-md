This is a refactoring patch in the ongoing `the_repository` removal effort. The author, Shashank Srikumar, has posted v4 of a standalone patch that removes the implicit dependency on the global `the_repository` variable in `prune_packed_objects()` by converting it to accept an explicit `struct repository *` parameter. The patch touches five files in the object storage subsystem (`builtin/prune-packed.c`, `builtin/prune.c`, `builtin/repack.c`, `prune-packed.c`, and `prune-packed.h`) and introduces a small `prune_data` struct to wrap the repository pointer and options for callback compatibility.

The patch is functionally complete and addresses all prior feedback. In v3, Patrick Steinhardt raised two minor stylistic issues: the commit message needed clearer wording about why dereferencing the repository pointer is safe even when it could theoretically be `NULL` (e.g., when invoked with `-h`), and three lines in `prune-packed.c` used spaces instead of tabs for indentation. Both issues are now fixed in v4. Junio C Hamano also weighed in on the `-h` edge case, confirming the patch is safe as written because `parse_options()` ensures `RUN_SETUP` has succeeded before the repository pointer is dereferenced.

The patch is uncontroversial and appears ready for merging. It includes no behavior changes, no new CLI options, and no test coverage modifications.
