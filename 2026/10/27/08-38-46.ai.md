This is the first patch in a two-patch series introducing the `%gb` format placeholder for `git log -g` and `git reflog`. It is a refactoring patch that names the hard-coded strings used in reflog messages for branch switches, renames, and rebase steps, replacing them with `#define` constants in `reflog.h`.

The patch mechanically replaces string literals like `"checkout: moving from "` and `"Branch: renamed "` with named constants (`REFLOG_SWITCH_PREFIX`, `REFLOG_RENAME_PREFIX`, etc.) across seven files: `builtin/branch.c`, `builtin/checkout.c`, `builtin/rebase.c`, `object-name.c`, `reflog.h`, `sequencer.c`, and `wt-status.c`. The changes are purely preparatory for the next patch, which will use these constants to implement the `%gb` placeholder. There is no behavior change in this patch.

The motivation for this refactoring is to avoid adding yet another copy of these strings when the `%gb` placeholder is implemented. The constants are now explicitly tied to the `%gb` feature, replacing the earlier justification (supporting the `--operations` flag) that was abandoned in v3. The patch is clean and focused, touching only the code paths that write or read these reflog messages.

This patch addresses Junio C Hamano’s earlier concern about the refactoring’s alignment with future directions (e.g., making reflog messages translatable or machine-readable). By naming the strings in `reflog.h`, the patch makes it easier to refactor them later if needed, though it does not itself split them into human-readable and machine-readable parts. The constants are a step toward better maintainability, even if the broader architectural question remains unresolved.

The patch is well-scoped and ready for review. It is a prerequisite for the `%gb` implementation in the next patch, and the changes are straightforward and mechanical. No test coverage is added here, as the behavior is unchanged. The next patch will introduce the new functionality and its tests.
