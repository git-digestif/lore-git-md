Core problem or goal
The `@{push}` revision suffix and `git push` behave inconsistently in triangular workflows when `push.default=simple` and `remote.pushDefault` points to a different remote than the branch’s upstream. `git push` correctly pushes to the same-named branch on the push remote, but `@{push}` fails to resolve, causing `git status` to omit the push-branch comparison and display misleading hints. The patch aligns `@{push}`’s behavior with `git push` by making it resolve to the same-named branch on the push remote in this scenario.

Current status
Under review. No prior versions of this patch have been posted. The patch is a minimal four-line addition in `remote.c` that checks if the push remote differs from the branch’s remote and, if so, delegates resolution to `tracking_for_push_dest()`. The test updates verify the fix and preserve error-path coverage by adjusting an existing test to use a differently named upstream branch on the same remote instead of an invalid push remote.
