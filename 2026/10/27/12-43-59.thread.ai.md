Core problem or goal
The `@{push}` revision suffix and `git push` behave inconsistently in triangular workflows when `push.default=simple` and `remote.pushDefault` points to a different remote than the branch’s upstream. `git push` correctly pushes to the same-named branch on the push remote, but `@{push}` fails to resolve, causing `git status` to omit the push-branch comparison and display misleading hints. The patch aims to align `@{push}`’s behavior with `git push` by making it resolve to the same-named branch on the push remote in this scenario.

Behavior change: `@{push}` now resolves to the same-named branch on the push remote when `push.default=simple` and the push remote differs from the upstream remote, matching `git push`’s behavior. The existing `PUSH_DEFAULT_SIMPLE` case and the new logic both use `tracking_for_push_dest()` but differ in an upstream-name check that `git push` enforces.
