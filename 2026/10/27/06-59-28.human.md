This is the fourth patch in Patrick Steinhardt’s seven-patch series introducing the `extensions.objectStorage` mechanism for pluggable object database backends. It adds user-facing tools to inspect the object storage format of a repository, mirroring the existing functionality for ref storage.

The patch exposes the object storage format through two commands: `` `git rev-parse --show-object-storage-format` `` and `` `git repo objects.storageFormat` ``. Both return the configured backend type (e.g., `files`), and the former also includes the payload if set (e.g., `files://objs`). The implementation is straightforward: it adds a helper function (`object_storage_format_to_name`) to convert the internal enum to a string, updates `` `git repo` `` to include the new field in its output, and extends `` `git rev-parse` `` with the new option. Documentation is updated to cross-reference `object-storage-format.adoc`, and tests verify the output matches the configured format.

This is a small, well-contained patch that completes the user-facing half of the object storage extension. It follows the established pattern for ref storage inspection and requires no new design decisions. The only subtlety is that `` `git repo` `` omits the payload (for consistency with ref storage), while `` `git rev-parse` `` includes it. This matches the behavior of the analogous ref storage commands and is documented in the commit message. The patch is ready for integration and unlikely to attract controversy.
