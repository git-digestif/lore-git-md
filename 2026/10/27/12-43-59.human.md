This is a bugfix patch targeting the remote-handling subsystem, specifically the `@{push}` notation when used with `push.default=simple` in a triangular workflow.

The patch addresses a long-standing inconsistency: when `push.default` is set to `simple` and `remote.pushDefault` points to a different remote than the branch's upstream, `git push` correctly pushes to the branch of the same name on the push remote, but `@{push}` fails to resolve, causing `git status` to omit the push-branch comparison and show misleading hints. The fix makes `@{push}` resolve to the same destination that `git push` would use, aligning the two behaviors.

The commit message is clear and well-motivated, citing the relevant prior commits (ed2b18292b and e291c75a95) that introduced the divergence. The code change itself is small and targeted: a four-line addition in `remote.c` that checks whether the push remote differs from the branch's remote and, if so, delegates to the existing `tracking_for_push_dest` helper. The test updates are minimal and preserve the original error-path coverage while exercising the new triangular case.

This looks like a clean, well-scoped fix for a real user-facing annoyance. The patch is standalone and does not appear to be part of a larger series.
