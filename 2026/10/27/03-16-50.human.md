This is an RFC patch series proposing a performance improvement for `git cat-file --remote-object-info`. The author, Pablo Sabater, observes that the current implementation has a hard limit of 10,000 OIDs per request, which forces users to run the command multiple times for large batches. Since `git backfill` (which fetches full objects) defaults to 50,000 objects, the author argues that `remote-object-info` (which only requests metadata) should handle at least as many.

The series introduces internal batching to allow arbitrary numbers of OIDs, with a proposed default batch size of 50,000. Benchmarking shows significant speedups: a 100,000-object request drops from 1.691s to 0.981s when increasing the batch size from 10k to 50k, with diminishing returns beyond that. The author includes a new `--remote-max-batch` option to let users override the default and asks for feedback on both the benchmarking methodology and whether the server should enforce its own OID limit.

The patches touch `builtin/cat-file.c`, transport helpers, and add a new test script. The implementation looks clean, with a clear separation of concerns (e.g., extracting transport ownership in patch 1). The motivation is well-explained, and the benchmark data is presented transparently. This appears to address a real pain point for users working with large repositories, though the RFC tag suggests the author is still seeking input on design choices like the default batch size and server-side limits. The series is self-contained and doesn’t depend on other ongoing efforts.
