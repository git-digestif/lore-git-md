This is the third patch in Patrick Steinhardt’s seven-patch **v4** series introducing the **object storage extension** (`extensions.objectStorage`), a foundational step toward pluggable object database backends in Git. The patch adds support for overriding the object storage format via the `GIT_OBJECT_STORAGE_FORMAT` environment variable, mirroring the existing behavior for the ref storage format (`GIT_REF_STORAGE_FORMAT`).

The change is **mechanical and narrowly scoped**: it introduces the new environment variable, updates `setup.c` to parse it during repository discovery, and adds a test to verify that the variable overrides the `extensions.objectStorage` configuration. The implementation follows the established pattern for ref storage, ensuring consistency in precedence rules (environment variables override repository configuration). The patch touches four files:
- `Documentation/git.adoc`: Documents the new `GIT_OBJECT_STORAGE_FORMAT` variable.
- `environment.h`: Defines the `GIT_OBJECT_STORAGE_FORMAT_ENVIRONMENT` macro.
- `setup.c`: Extends `setup_git_directory_gently()` to parse the environment variable and override the repository’s `extensions.objectStorage` setting.
- `t/t0001-init.sh`: Adds a test verifying that `GIT_OBJECT_STORAGE_FORMAT` overrides the configuration, handles valid and invalid formats, and correctly relocates objects when the payload changes.

The test covers edge cases: it confirms that objects are written to the new location specified by the environment variable, that invalid formats are rejected, and that the override works as expected. The patch does not introduce new behavior beyond what was already established in earlier patches (e.g., the `(type, payload)` split, repository format version bumps, or local clone restrictions).

**Context in the series**: This patch is part of the **precedence and propagation** layer, which also includes command-line options (`--object-storage-format=`) and submodule handling. The environment variable is the second-highest precedence mechanism (after CLI options) and is critical for testing and scripting. The patch is **uncontroversial**—it aligns with the ref storage extension’s design and has not attracted review feedback beyond minor stylistic nits in earlier versions.
