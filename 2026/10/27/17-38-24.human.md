This is the fifth patch in Jeff King’s (Peff) eight-patch series refactoring Git’s unit test infrastructure. It is the core change of the series, integrating `clar`-based unit tests into the standard `test-lib.sh` framework so they inherit the same environment setup, leak detection, and logging as the shell test suite.

The patch creates a new wrapper script, `t/t0011-unit-tests.sh`, that runs the unit test binary through `test-lib.sh`. This immediately fixes two practical problems: unit test failures in CI are now visible (previously their TAP output was swallowed by `prove`), and sanitizer options like `LSAN_OPTIONS` are applied, producing useful stack traces for memory leaks. The wrapper also forwards the `--immediate` option to the unit test binary, though other options (like `--run`) are not yet supported due to syntax differences between the two test systems.

The implementation is straightforward: the wrapper locates the unit test binary (handling both Make and Meson build layouts) and invokes it with any relevant options. The patch also updates `t/meson.build` to declare the dependency, ensuring `meson test t0011-unit-tests` works correctly. This change is well-motivated and uncontroversial, addressing a long-standing pain point with minimal risk. The commit message clearly explains the rationale, limitations, and trade-offs, making it easy for reviewers to assess. No objections or requests for changes have been raised so far.
