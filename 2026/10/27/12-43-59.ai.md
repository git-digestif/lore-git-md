This patch is a **bugfix** targeting the `@{push}` revision suffix and the `push.default=simple` configuration. It addresses an inconsistency in triangular workflows where `git push` and `@{push}` resolve differently when the push remote differs from the upstream remote.

The issue: when `push.default=simple` and `remote.pushDefault` points to a different remote than the branch’s upstream, `git push` correctly pushes to the branch of the same name on the push remote, but `@{push}` fails to resolve, causing `git status` to omit the push-branch comparison and show misleading hints. The patch aligns `@{push}`’s behavior with `git push` by making it resolve to the same-named branch on the push remote in this scenario.

The change is minimal: a four-line addition in `remote.c` checks if the push remote differs from the branch’s remote, and if so, delegates resolution to `tracking_for_push_dest()` (which already handles the "current" case). The test updates ensure the fix works and preserve error-path coverage by tweaking an existing test to use a differently named upstream branch on the same remote instead of an invalid push remote.
