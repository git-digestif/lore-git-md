This thread is about Patrick Steinhardt’s 12-patch series modernizing `git rerere`’s subcommand handling, which has already been merged to Git’s `master` branch as of June 25, 2025. The series refactored the command’s internal logic to use Git’s standard `OPT_SUBCOMMAND()` mechanism, aligning it with other multi-subcommand built-ins like `git notes` and `git maintenance`. No new functionality or behavior changes were introduced—it was purely a code cleanup effort.

The key participants were Patrick (the author), Junio C Hamano (the maintainer), Karthik Nayak, and Mark C. Chu-Carroll. All feedback from earlier versions was addressed, and the series was deemed ready for merging. However, Junio’s latest email flags a lingering documentation issue in the second patch, which introduced an `enum rerere_flags`. While the updated documentation correctly describes what the `RERERE_NOAUTOUPDATE` flag *does*, it doesn’t explain *why* it exists or how it differs from simply omitting `RERERE_AUTOUPDATE`. This is a subtle but meaningful distinction: omitting the flag means Git does nothing after recording a resolution, while `RERERE_NOAUTOUPDATE` actively updates the working tree (but not the index) and prints messages to stderr. Junio’s feedback is likely intended as a minor follow-up rather than a blocker, given the series is already merged. No other open questions remain.
