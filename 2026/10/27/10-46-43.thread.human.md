This thread covers Patrick Steinhardt's v4 series to modernize `git rerere`'s subcommand handling by replacing its hand-rolled parser with Git's standard `OPT_SUBCOMMAND()` machinery. The series was merged to `master` on 2025-06-25 and is purely internal restructuring with no behavior changes intended, though it did introduce two accepted UI regressions: `git rerere --skip-locked gc` (old option ordering) is now rejected, and `git rerere unknown` no longer lists valid subcommands in its error message. Junio accepted both as deliberate trade-offs, and Patrick has committed to fixing the error-reporting regression and a stale documentation claim about `git rerere diff` accepting extra arguments.

The most recent exchange addresses a memory-safety issue in the fallback logic of patch 11, where a synthetic `"perform"` subcommand is constructed by copying a `strvec` into a raw `argv` array. Junio points out the specific correction needed: while `COPY_ARRAY` can copy `args.nr` elements as-is, `CALLOC_ARRAY` must allocate `args.nr + 1` elements so the array is properly NULL-terminated per C's `(ac, av)` convention. Patrick had already acknowledged the issue and agreed to adapt the code; this email provides the exact fix. These post-merge follow-ups -- the NULL-termination fix, the error-message regression, and the documentation discrepancy -- remain the only open items on an otherwise completed series.
