This thread is about Patrick Steinhardt’s 12-patch series to modernize `git rerere`’s subcommand handling by replacing its custom parsing logic with Git’s standard `OPT_SUBCOMMAND()` mechanism. The goal is purely internal refactoring—no new features, behavior changes, or on-disk format modifications—bringing `git rerere` in line with other multi-subcommand built-ins like `git notes` and `git maintenance`. The series builds on Patrick’s earlier work to remove global state in `git rerere`, which has already been merged.

The patches touch `builtin/rerere.c`, `rerere.h`, and documentation, along with callers in several other files. Key changes include renaming functions to follow subcommand naming conventions (e.g., `rerere_record()` replacing `repo_rerere()`), converting flags to enums, removing `the_repository` usage, and adding per-subcommand usage strings. The series also removes unused flags and consolidates option handling, such as dropping the global `--skip-locked` flag in favor of a hidden option for the "gc" subcommand.

The only substantive discussion so far has been Junio C Hamano’s concern about the `rerere_record()` name, which he argued was too narrow because the function also resolves conflicts when a recorded resolution exists. However, in this latest email, Junio calls the series “well done” and praises the incidental removal of `USE_THE_REPOSITORY_VARIABLE` as a clean win. His feedback is unqualified and effectively signals approval, leaving no open technical objections. The series is now poised to move forward toward integration.
