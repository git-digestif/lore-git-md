This thread tracks Patrick Steinhardt's effort to modernize `git rerere`'s subcommand handling, replacing its hand-rolled parser with Git's standard `OPT_SUBCOMMAND()` machinery. The v4 series was merged to `master` on 2025-06-25, and the discussion has since shifted to a post-merge follow-up phase. Version 5, a 13-patch series, has now been posted to close out the loose ends from that discussion: patch 11 fixes the NULL-termination bug in the synthetic `argv` array used by the fallback `cmd_rerere_perform()` path (allocating `args.nr + 1` elements as Junio specified), and also restores proper usage output for unknown subcommands; patch 10's commit message now explicitly documents that `--skip-locked` is only accepted after the `gc` subcommand as an intentional behavior change; and a new thirteenth patch removes the stale man-page claim that `git rerere diff` forwards extra arguments to the system `diff` command, a discrepancy dating back to 2006.

Junio C Hamano reviewed the earlier versions thoroughly, accepting two minor UI regressions as deliberate trade-offs -- the option-ordering restriction on `--skip-locked` and a generic error message for unknown subcommands -- while flagging the memory-safety issue and the documentation gap, both of which v5 now addresses. Other participants played smaller roles: Karthik Nayak suggested documentation clarifications and gave a blanket approval, while post-merge chatter from Phillip Wood, Tuomas Ahola, and Patrick touched on rebase workflow tips and the experimental `git history fixup` command, none of which reopens the series itself.

The series remains a purely internal refactoring with no new functionality or on-disk changes: flags became an `enum rerere_flags`, each subcommand got a dedicated `cmd_rerere_*()` function, and `the_repository` was removed from `builtin/rerere.c`. With v5 posted, the remaining open items are simply review confirmation of the NULL-termination fix and the new documentation patch; no substantive objections are outstanding.
