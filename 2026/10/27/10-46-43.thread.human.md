This thread tracks Patrick Steinhardt's v5 series, "[PATCH 0/13] Modernize git-rerere's subcommand handling," which refactors `git rerere` to use the standard `OPT_SUBCOMMAND()` mechanism instead of custom parsing. The series supersedes v4, which was previously merged to `master`, and directly addresses post-merge follow-ups: fixing a NULL-termination bug in the fallback argv handling, restoring usage output for unknown subcommands, documenting the intentional `--skip-locked` ordering restriction, and removing stale documentation about `git rerere diff`. The current email covers patch 5/13, which extracts the "forget" subcommand into its own `cmd_rerere_forget()` handler as part of the incremental move toward full subcommand dispatch.

The thirteen patches also include broader cleanup: renaming `repo_rerere()` to `rerere()`, converting flag macros to a documented `enum rerere_flags` with a `BUG()` guard against contradictory autoupdate flags, removing the `the_repository` global from `builtin/rerere.c`, and separating read-only flag handling for subcommands like `status` and `diff`. All changes are internal with no new features or on-disk format changes, aside from the scoped `--skip-locked` restriction. Patrick Steinhardt authored the series, implementing corrections previously suggested by Junio C Hamano, who had accepted the earlier trade-offs in v4. Karthik Nayak had previously approved v4. The series remains under review with no merge status claimed for v5; the remaining work is simply completing review of these follow-up fixes.
