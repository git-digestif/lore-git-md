This thread covers Patrick Steinhardt's v4 patch series modernizing `git rerere`'s subcommand handling by replacing its custom parsing with the standard `OPT_SUBCOMMAND()` mechanism. The series is purely internal refactoring with no behavior changes or on-disk format modifications, and Junio C Hamano merged it to `master` on 2025-06-25. The main change moves each subcommand (`forget`, `clear`, `status`, `remaining`, `diff`, `gc`) into its own dedicated function and removes the global `the_repository` references, while introducing a three-state flag system for autoupdate handling.

Junio accepted two minor UI regressions as deliberate trade-offs: the new parser enforces option ordering (rejecting `git rerere --skip-locked gc` in favor of `git rerere gc --skip-locked`), and invalid subcommands now yield a generic error message rather than listing valid options. Patrick Steinhardt has acknowledged both, arguing the old behaviors were design flaws, and confirmed the option-ordering change stays as-is.

Several follow-up items remain open. Patrick has committed to fixing the error-reporting regression so unknown subcommands again list valid choices, correcting a latent memory-safety issue in the fallback logic where the synthetic argument array must be properly NULL-terminated, and updating the stale documentation for `git rerere diff` which incorrectly claims it accepts additional arguments passed to the system diff command. These are documentation and safety fixes rather than blockers for the merged series.
