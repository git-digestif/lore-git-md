Patrick Steinhardt’s 12-patch series to modernize `git rerere`’s subcommand handling is now complete. The goal was to replace the command’s custom subcommand-parsing logic with Git’s standard `OPT_SUBCOMMAND()` mechanism, aligning it with other multi-subcommand built-ins like `git notes` and `git maintenance`. The series is purely internal refactoring—no new functionality, behavior changes, or on-disk format modifications were introduced.

All feedback from the initial version has been addressed. Junio C Hamano’s requests—renaming the fallback subcommand to `rerere()`, expanding enum documentation, and ensuring consistency with Git’s coding guidelines—were implemented in earlier patches. The final patch, just posted, adds per-subcommand usage strings to the man page and C code, completing the series. The work is uncontested and ready for Junio to pick up for integration. Key changes include removing global state dependencies (like `the_repository`), extracting dedicated functions for each subcommand, and fixing a long-standing bug where the `--[no-]rerere-autoupdate` flag was accepted but ignored for all subcommands except the default. The series builds on the already-merged `ps/rerere-remove-global-state` topic, which made this refactoring possible.
