This thread is about Patrick Steinhardt’s twelve-patch series modernizing `git rerere`’s subcommand handling by replacing its custom parsing logic with Git’s standard `OPT_SUBCOMMAND()` mechanism. The goal is purely internal refactoring—no new features, no behavior changes, and no on-disk format modifications—bringing `git rerere` in line with other multi-subcommand built-ins like `git notes` and `git maintenance`.

The series is now at version 2, posted on June 17, 2025, and addresses all feedback from Junio C Hamano on the initial version. Key changes include renaming the fallback subcommand to `rerere()`, expanding enum documentation to cover all four flags (`RERERE_AUTOUPDATE`, `RERERE_NOAUTOUPDATE`, `RERERE_READONLY`, `RERERE_NOWAIT`), and fully removing `the_repository` usage from `builtin/rerere.c`. Earlier patches in the series extracted the "forget", "clear", and "status" subcommands into dedicated functions, and this latest patch (8/12) does the same for the "remaining" subcommand, preserving its existing logic. The remaining patches will similarly extract "diff" and "gc", then replace the hand-rolled subcommand dispatch with an `OPT_SUBCOMMAND()` table.

The series is uncontested and ready for integration. Junio has reviewed the stylistic and naming concerns, and all substantive feedback has been addressed. The changes are mechanical, touching only `builtin/rerere.c`, `rerere.h`, and documentation, with no new CLI options or test files introduced. The work depends on the already-merged `ps/rerere-remove-global-state` topic, which eliminated the global rerere cache state and made this refactoring possible.
