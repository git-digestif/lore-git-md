Patrick Steinhardt has posted version 5 of his thirteen-patch series to modernize `git rerere`'s subcommand handling, replacing the custom dispatch logic in `builtin/rerere.c` with the standard `OPT_SUBCOMMAND()` mechanism. This iteration directly addresses follow-up items from the previously merged v4: it fixes a NULL-termination memory safety issue in the fallback handler via `CALLOC_ARRAY(args.nr + 1)`, restores informative error messages for unknown subcommands using `usage_with_options()`, and removes stale documentation about `git rerere diff` argument forwarding. The series also introduces an intentional backwards-incompatible change, restricting `--[no-]rerere-autoupdate` to the implicit "perform" subcommand only, and gives each subcommand its own specific usage strings for clearer error output.

Junio C Hamano has now reviewed the core conversion patch (11/13) and signals general acceptance of the approach. He endorses the autoupdate flag restriction as fixing a previously misleading interface where the option was silently ignored by named subcommands. However, he notes two side effects worth watching: `git rerere -h` now displays only the top-level usage listing subcommands, hiding the descriptive help text for `--rerere-autoupdate`, and the shell completion helper now emits subcommand names rather than just the autoupdate flags, which may require adjustments to the bash completion script. He considers the current help output acceptable despite the discoverability caveat, suggesting users unfamiliar with the option can use `git -c rerere.autoupdate=no rerere` instead.

The series remains under review with no merge status claimed for v5. All previously identified post-v4 follow-ups appear addressed, and no new objections have been raised.
