This thread began as a refactoring series by Patrick Steinhardt to modernize `git rerere`'s subcommand handling, replacing its custom parsing logic with Git's standard `OPT_SUBCOMMAND()` mechanism. The series was merged to `master` on June 25, 2025, after four iterations that addressed maintainer feedback, removed global state, and clarified flag documentation. While the refactoring introduced a deliberate UI regression—enforcing option ordering and rejecting previously accepted syntax like `git rerere --skip-locked gc`—Junio Hamano and Patrick agreed to accept it as a trade-off to fix what they considered a design flaw.

The merged code is now in `master`, but Junio recently noted a minor regression in error reporting: when an unknown subcommand is provided (e.g., `git rerere unknown`), the new parser on the `seen` branch shows a generic "too many arguments" message, whereas the old parser on `master` correctly listed valid subcommands. This is a cosmetic issue that doesn’t affect functionality, and Junio hasn’t proposed reopening the series for a fix. The thread is effectively closed, with no further code changes expected. Post-merge discussion has shifted to workflow tooling, including Junio’s wish for a hypothetical `git fixup` command and lighthearted suggestions from other contributors, but these don’t impact the `rerere` series itself.
