This is the final patch in Patrick Steinhardt’s 12-patch series modernizing `git rerere`’s subcommand handling. It updates the man page (`Documentation/git-rerere.adoc`) and the C code (`builtin/rerere.c`) to give each subcommand its own proper usage string, completing the shift from a single monolithic usage line to individual, context-sensitive help text.

The patch is purely mechanical: it defines six new `RERERE_*_USAGE` macros, wires them into the `parse_options()` calls for each subcommand, and assembles them into a unified `rerere_usage[]` array that `OPT_SUBCOMMAND()` will display. No behavior changes, no new flags, and no test updates beyond what earlier patches already covered. The result is a cleaner, more conventional interface that matches the style of other multi-subcommand built-ins like `git notes` or `git maintenance`.

This is a small but necessary capstone to the series. The earlier patches extracted the subcommand logic and switched to `OPT_SUBCOMMAND()`; this one simply makes the help output match the new structure. The patch is uncontroversial and should be a quick review for anyone familiar with Git’s command-line parsing conventions.
