This is a **substantive review** of the fourth patch in Patrick Steinhardt’s seven-patch series introducing the `extensions.objectStorage` mechanism for pluggable object database backends. The patch adds user-facing inspection tools (`` `git rev-parse --show-object-storage-format` `` and `` `git repo objects.storageFormat` ``) to query the configured object storage backend.

Karthik Nayak’s review focuses on two technical points, both of which question the design rather than the correctness of the implementation. First, he notes that the naming distinction between `object.format` (hash algorithm) and `objects.storageFormat` (storage backend) in `` `git repo` ``’s output is too subtle and likely to cause confusion. This is a UX concern, not a bug, and Karthik acknowledges there is no obvious fix without breaking consistency with other fields.

The more significant feedback is a design-level question about the hard-coded default (`files`) in the inspection tools. Karthik asks why the `object_storage_format` field in `struct repository` might be unset, and expresses discomfort with exposing the default outside the repository and ODB subsystems. This suggests a preference for encapsulating the default within the ODB layer rather than duplicating it in the CLI tools. The concern is architectural: if the default ever changes, the inspection tools would need to be updated to match, creating a maintenance burden. This is not a blocking issue, but it is a valid point about long-term maintainability.

The review is **not tested** (no mention of running the code) and does not identify any functional bugs. It is narrowly scoped to the patch’s design choices, making it a substantive but non-blocking critique. No other participants have weighed in on this patch yet. The feedback is actionable but unlikely to require a major rewrite; a follow-up patch could address the default encapsulation if the author agrees.
