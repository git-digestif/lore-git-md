This is a bugfix patch that rewords the confusing message shown by `git status` (and `git checkout`) when a branch is set to track a remote branch that does not exist. The current message says the upstream is "gone," which is misleading when cloning an empty repository — the upstream was never created, not deleted. The new wording clarifies that the upstream "does not exist" and offers more accurate advice: "git push" to create it (when appropriate) or "git branch --unset-upstream" to stop tracking.

The patch is well-motivated: the current message has confused users for years, as evidenced by StackOverflow questions and the commit message's clear explanation of the problem. It includes thorough test coverage, verifying the new message in multiple scenarios (empty clone, deleted upstream, different push configurations) and ensuring backward compatibility with script-dependent short formats like `git status -sb` and `git branch -vv`. The implementation is careful to only suggest "git push" when it would actually create the missing branch, avoiding misleading advice in edge cases like `push.default=nothing`.

The change is small but user-facing, and the new phrasing feels like a clear improvement over the current one. Worth a look for anyone who has ever been confused by the "upstream is gone" message.
