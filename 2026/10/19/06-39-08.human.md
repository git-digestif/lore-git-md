This is a **substantive review** from Patrick Steinhardt on the second patch of Beat Bolli’s v3 series for `git imap-send`. The series aims to replace Git’s manual TLS hostname verification with OpenSSL’s built-in `SSL_set1_host()` API, but the patch introduces two critical regressions: a **security regression** (certificate stripping) and an **error reporting regression** (loss of hostname-specific error messages).

Patrick’s review raises two key points. First, he suggests splitting the patch into two parts—a preparatory refactoring to move code into the new `verify_peer()` function without changing behavior, followed by a separate patch to introduce the semantic changes. This would make the diff easier to review and reduce the risk of introducing regressions. Second, he questions the new logic that calls `verify_peer()` when `SSL_connect()` fails, noting that the old code did not perform verification in this case. This change appears to be a behavioral regression, as it introduces a new verification step that wasn’t present before, potentially altering error handling in unexpected ways.

The review is **high-weight** and engages deeply with the patch’s correctness and reviewability. Patrick’s feedback highlights a process issue (the large, hard-to-review diff) and a potential behavioral inconsistency (the new verification step on connection failure). Neither issue has been addressed in the v3 series yet, and both should be resolved before the patch can move forward. If you’re following the `imap-send` OpenSSL compatibility effort, this review is worth tracking, as it identifies concrete problems that will need to be fixed in the next iteration.
