Core problem or goal: Enable alternative object storage backends (e.g., cloud storage, databases) by making Git’s object database pluggable. This series defines the configuration mechanism (`extensions.objectStorage`), modeled after the existing ref storage extension, and implements the baseline `files` backend with support for relocating the `.git/objects` directory via a payload (e.g., `files://objs` moves objects to `.git/objs`). The v3/v4 refactoring splits the storage format URI into separate `(type, payload)` components (e.g., `("files", "objs")` instead of `"files://objs"`), mirroring the ref storage backend’s design. The series also introduces environment variable support (`GIT_OBJECT_STORAGE_FORMAT` and `GIT_DEFAULT_OBJECT_STORAGE_FORMAT`), user-facing configuration (`init.defaultObjectStorageFormat`), inspection tools (`git rev-parse --show-object-storage-format` and `git repo objects.storageFormat`), submodule propagation, and CLI support for `git init`, `git clone`, `git submodule add`, and `git submodule update`.
