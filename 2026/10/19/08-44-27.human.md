This is a small i18n (internationalization) patch targeting the ZIP archive backend. The change replaces a hardcoded singular/plural error message in `archive-zip.c` with Git's `Q_()` macro, which automatically selects the correct singular or plural form based on the value of `pathlen`. The patch is trivial—one line changed—and fixes a minor grammatical inconsistency where the message always used "chars" even when the path length was 1.

The motivation is clear: improve the user experience for non-English speakers by ensuring proper pluralization in translated messages. The commit message is concise and to the point, though it doesn’t explain why this particular error message was chosen (it’s the only one in the file that could benefit from pluralization). The patch itself is well-scoped and unlikely to be controversial.

This isn’t part of a larger series, and the change is isolated to the ZIP archive code path. If you care about i18n polish or work on the archive subsystem, this is worth a quick glance; otherwise, it’s a safe "looks good" candidate for anyone reviewing.
