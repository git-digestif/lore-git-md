This is the first patch in Patrick Steinhardt’s seven-part series introducing the **object storage extension** mechanism. It is a clean-up patch that removes the unused function `repo_write_loose_object_map()`.

The function was introduced in 2023 to write a mapping between SHA-1 and SHA-256 for loose objects, but it was never called. Instead, the mapping is updated incrementally via `repo_add_loose_object_map()` whenever a new loose object is created. The function also hardcodes the location of the loose-object index file, which conflicts with how other parts of the codebase derive the path from the loose source’s location. The patch deletes the function and its declaration, removing 46 lines of dead code.

This is a straightforward refactoring with no behavior change. The patch is well-motivated and uncontroversial, serving as a low-risk first step in the series. It touches only the loose object subsystem and does not interact with the broader object storage extension work introduced later in the series. If the series as a whole gains traction, this patch is likely to be merged without discussion.
