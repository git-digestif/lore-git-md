This is a bugfix patch for the config subsystem, now with Junio’s explicit approval. The issue is a long-standing (since 2013) platform-dependent bug: on architectures where `char` is signed (e.g., x86), `git config --blob` and other in-memory config readers misinterpret bytes with the high bit set (0x80–0xff). A 0xff byte is treated as EOF, truncating the config blob, and UTF-8 byte order marks trigger spurious "bad config line" errors. The fix is minimal—casting the byte to `unsigned char` in `config_buf_fgetc()` and updating the ungetc check to match—aligning in-memory behavior with file-based config reading.

The patch includes three new tests in `t/t1307-config-blob.sh` that verify the fix handles 0xff bytes (both standalone and after CR) and UTF-8 BOMs. Junio’s reply is brief but decisive: "Very nice.
