Thread identity: Bugfix series for `git imap-send` to handle non-canonical email header order (e.g., `Subject` before `Date`) and case-insensitive header names (e.g., `FROM:`), while fixing tunnel-command lifecycle and memory leaks. Four-patch series (`v4`) authored by Harald Nordgren via GitGitGadget, addressing RFC 5322 compliance, interoperability with tools like `b4`, and proper process management. The series was **merged to `next` on 2025-06-18**, but a latent bug in Patch 2/4 (CRLF line-ending mismatch) has since been identified, requiring a new iteration (`v5`).

Core problem or goal: `git imap-send` fails when processing patches where the `Subject` header precedes the `Date` header (a valid but non-canonical order produced by tools like `b4`) or when header field names are not lowercase (e.g., `FROM:`, `DATE:`). The series fixes the header-parsing logic to accept any order and any case for `From:`, `Date:`, and `Subject:` headers, ensuring RFC 5322 compliance. It also plugs a tunnel-command memory leak by properly reaping the tunnel process via `finish_command()` (defensively coded to store `imap->tunnel` as an allocated pointer), and removes the `git-send-email` special case (which previously ignored `Subject` headers for messages starting with `From git-send-email`). The goal is to ensure interoperability with `b4` and other tools while maintaining backward compatibility. **A latent bug in Patch 2/4** (the `has_required_headers()` helper function) assumes LF line endings (`\n\n`) but IMAP messages use CRLF (`\r\n`), risking false positives/negatives in header detection.

Current status: **Merged to `next` on 2025-06-18, but blocked by a latent bug in Patch 2/4**. Patch 1/4 (tunnel process lifecycle fix) was previously merged to `next` on 2025-06-10 and further revised in `v4` to address Patrick Steinhardt’s defensive coding feedback by converting `imap->tunnel` to an allocated pointer. Patches 2/4 (order-agnostic header parsing), 3/4 (removal of the `git-send-email` special case), and 4/4 (case-insensitive header matching) were explicitly endorsed by Patrick Steinhardt and integrated into `next`. However, Junio C Hamano’s review identified a **blocking issue** in Patch 2/4: the `has_required_headers()` helper function does not account for CRLF line endings, which are mandatory in IMAP (RFC 2060). This mismatch could cause the function to scan past the header block into the message body, misclassifying messages with body text resembling headers. The series is **no longer technically complete**; a `v5` is required to address this issue. Graduation to `master` is on hold pending resolution.

Key technical details:
- Files touched: `imap-send.c` (header-parsing logic for case insensitivity and order agnosticism; removal of special-case logic for `git-send-email`; tunnel process management, including the `v4` revision to store `imap->tunnel` as an allocated pointer; **latent bug in `has_required_headers()` for CRLF line endings**), `t/t9001-send-email.sh` (tests verifying `--imap-sent-folder` workflow without the special case, order-agnostic header parsing, and case-insensitive header matching with mixed-case headers).
- New behavior: All messages are now treated uniformly by the header-parsing logic, accepting any order and any case for `From:`, `Date:`, and `Subject:` headers. The `--imap-sent-folder` workflow continues to work as before, but without relying on the `git-send-email` exemption. Tunnel processes are now properly reaped via `finish_command()` and `free()`.
- **Latent bug**: The `has_required_headers()` helper function (Patch 2/4) assumes LF line endings (`\n\n`) to detect the end of headers, but IMAP messages use CRLF (`\r\n`). This could cause the function to scan past the header block into the message body, leading to false positives (e.g., treating a `Subject:` line in the body as a valid header) or false negatives (e.g., failing to detect headers if the message uses mixed line endings).
- On-disk format: No changes.
- New symbols: `has_required_headers()` (Patch 2/4, helper function for order-agnostic header scanning; **requires CRLF fix**), reuses `istarts_with()` from Git’s string utilities.
- Test coverage: Expanded in `v4` to include mixed-case headers (Patch 4/4), order-agnostic header parsing (Patch 2/4), and explicitly verify the `--imap-sent-folder` workflow (Patch 3/4). The existing suite exercises the header-parsing logic comprehensively, but **does not currently test CRLF line endings in the `has_required_headers()` function**.
