Thread identity: Bugfix series for `git imap-send` to handle non-canonical email header order (Subject before Date) and fix a minor memory leak. Two-patch series (`v2`) authored by Harald Nordgren via GitGitGadget, addressing RFC 5322 compliance (case-insensitive header name matching) as requested in review.

Core problem or goal: `git imap-send` fails when processing patches where the `Subject` header precedes the `Date` header, a valid but non-canonical order produced by tools like `b4` (used to fetch patches from lore.kernel.org). The series fixes the header-parsing logic to accept either order, plugs a minor memory leak in tunnel-command handling, and ensures RFC 5322 compliance (case-insensitive header name matching). The goal is to ensure interoperability with `b4` and other tools while maintaining backward compatibility. **New clarification**: The series also removes a special-case logic that previously ignored `Subject` headers for messages starting with `From git-send-email`, a change whose safety and rationale require explanation.

Current status: **Under review**. `v2` incorporates Junio’s feedback (case-insensitive header matching via `istarts_with()` and memory leak fix via `child_process_clear(&tunnel)`). Patrick Steinhardt’s reviews raise two unresolved technical questions: (1) the tunnel-command lifecycle (omission of `finish_command()` in Patch 1/2), and (2) the removal of the `git-send-email` special case in Patch 2/2, which may affect backward compatibility. The test suite’s prerequisite handling (`$PREREQ` guards in every test) is also flagged as a potential refactoring target. No merge status recorded; series remains in `seen` or earlier.

Key technical details:
- Files touched: `imap-send.c` (header-parsing logic rewrite, memory leak fix via `child_process_clear(&tunnel)` in Patch 1/2; `istarts_with()` replacement and removal of `git-send-email` special case in Patch 2/2), `t/t9001-send-email.sh` (new test, `$PREREQ` guard handling).
- New behavior: Accepts `Subject` before `Date` in email headers, matching behavior of other email tools. Parsing logic is now order-agnostic for `From`, `Date`, and `Subject` headers and uses case-insensitive matching. **New detail**: The special-case logic for messages starting with `From git-send-email` (which previously ignored `Subject` headers) is removed.
- On-disk format: No changes.
- New symbols: `has_required_headers()` helper function in `imap-send.c` (now uses `istarts_with()` for case-insensitive header name matching).
- Test coverage: New test verifies the fix by sending a patch with `Subject` before `Date` and confirming acceptance; also checks for regressions in existing code paths, including the `--imap-sent-folder` workflow. The memory leak in `imap.tunnel` handling and tunnel process lifecycle (reaping via `finish_command()`) are not covered by tests. **New detail**: The test suite’s use of `$PREREQ` guards in every test is noted as a potential inefficiency.
