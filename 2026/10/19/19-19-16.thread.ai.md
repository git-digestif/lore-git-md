Thread identity: Bugfix series for `git imap-send` to handle non-canonical email header order (e.g., `Subject` before `Date`) and case-insensitive header names (e.g., `FROM:`), while fixing tunnel-command lifecycle and memory leaks. Four-patch series (`v4`) authored by Harald Nordgren via GitGitGadget, addressing RFC 5322 compliance, interoperability with tools like `b4`, and proper process management. The series is now technically complete, with all prior feedback resolved: (1) tunnel process lifecycle fix (revised in `v4` to store `imap->tunnel` as an allocated pointer, merged to `next` on 2025-06-10), (2) order-agnostic header parsing (ready for integration), (3) removal of the `git-send-email` special case (commit message now explicitly addresses backward-compatibility implications, ready for integration), and (4) case-insensitive header matching (test coverage expanded to include mixed-case headers, ready for integration).

Core problem or goal: `git imap-send` fails when processing patches where the `Subject` header precedes the `Date` header (a valid but non-canonical order produced by tools like `b4`) or when header field names are not lowercase (e.g., `FROM:`, `DATE:`). The series fixes the header-parsing logic to accept any order and any case for `From:`, `Date:`, and `Subject:` headers, ensuring RFC 5322 compliance. It also plugs a tunnel-command memory leak by properly reaping the tunnel process via `finish_command()` (now defensively coded to avoid edge cases by storing `imap->tunnel` as an allocated pointer), and removes the `git-send-email` special case (which previously ignored `Subject` headers for messages starting with `From git-send-email`). The goal is to ensure interoperability with `b4` and other tools while maintaining backward compatibility.
