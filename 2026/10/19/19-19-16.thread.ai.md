Thread identity: Bugfix series for `git imap-send` to handle non-canonical email header order (e.g., `Subject` before `Date`) and case-insensitive header names (e.g., `FROM:`), while fixing tunnel-command lifecycle and memory leaks. Four-patch series (`v4`) authored by Harald Nordgren via GitGitGadget, addressing RFC 5322 compliance, interoperability with tools like `b4`, and proper process management. The series is now **merged to `next`** as of 2025-06-18, with all patches integrated.

Core problem or goal: `git imap-send` fails when processing patches where the `Subject` header precedes the `Date` header (a valid but non-canonical order produced by tools like `b4`) or when header field names are not lowercase (e.g., `FROM:`, `DATE:`). The series fixes the header-parsing logic to accept any order and any case for `From:`, `Date:`, and `Subject:` headers, ensuring RFC 5322 compliance. It also plugs a tunnel-command memory leak by properly reaping the tunnel process via `finish_command()` (defensively coded to store `imap->tunnel` as an allocated pointer), and removes the `git-send-email` special case (which previously ignored `Subject` headers for messages starting with `From git-send-email`). The goal is to ensure interoperability with `b4` and other tools while maintaining backward compatibility.

Current status: **Merged to `next` on 2025-06-18**. Patch 1/4 (tunnel process lifecycle fix) was previously merged to `next` on 2025-06-10 and further revised in `v4` to address Patrick Steinhardt’s defensive coding feedback by converting `imap->tunnel` to an allocated pointer.
