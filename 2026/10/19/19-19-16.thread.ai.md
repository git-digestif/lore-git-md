Thread identity: Bugfix series for `git imap-send` to handle non-canonical email header order (Subject before Date) and fix tunnel-command lifecycle and memory leaks. Four-patch series (`v3`) authored by Harald Nordgren via GitGitGadget, addressing RFC 5322 compliance (case-insensitive header name matching), interoperability with tools like `b4`, and proper process management. The series splits the original two-patch `v2` into focused commits: (1) tunnel process lifecycle fix (merged to `next` on 2025-06-10), (2) order-agnostic header parsing (ready for integration), (3) removal of the `git-send-email` special case (under review in `seen`), and (4) case-insensitive header matching (ready for integration).

Core problem or goal: `git imap-send` fails when processing patches where the `Subject` header precedes the `Date` header (a valid but non-canonical order produced by tools like `b4`) or when header field names are not lowercase (e.g., `FROM:`, `DATE:`). The series fixes the header-parsing logic to accept any order and any case for `From:`, `Date:`, and `Subject:` headers, ensuring RFC 5322 compliance. It also plugs a tunnel-command memory leak, properly reaps the tunnel process via `finish_command()`, and removes the `git-send-email` special case (which previously ignored `Subject` headers for messages starting with `From git-send-email`). The goal is to ensure interoperability with `b4` and other tools while maintaining backward compatibility.

Current status: **Nearly complete**. Patch 1/4 (tunnel process lifecycle fix) was merged to `next` on 2025-06-10 but has received **minor technical feedback** from Patrick Steinhardt regarding defensive coding practices (safety of `finish_command()` on uninitialized `struct child_process` and code clarity). The patch remains merged, but the feedback may prompt a follow-up tweak. Patches 2/4 (order-agnostic header parsing) and 4/4 (case-insensitive header matching) are ready for integration. Patch 3/4 (removal of the `git-send-email` special case) is under review in `seen` and remains uncontroversial, though Patrick Steinhardt raised a **documentation edge case**: the commit message should explicitly address backward-compatibility implications of dropping the special case, as RFC 5322 only *requires* `Date` (`SHOULD` for `Subject`), and rejecting messages without `Subject` could theoretically break interoperability with minimal mboxes. No alternative implementation is proposed; the feedback is non-blocking. The entire series is queued in `seen` and likely to graduate to `next` once Junio processes the remaining patches.
