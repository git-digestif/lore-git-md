Thread identity: Bugfix series for `git imap-send` to handle non-canonical email header order (e.g., `Subject` before `Date`) and case-insensitive header names (e.g., `FROM:`), while fixing tunnel-command lifecycle and memory leaks. Five-patch series (`v5`) authored by Harald Nordgren via GitGitGadget, addressing RFC 5322 compliance, interoperability with tools like `b4`, and proper process management. The series was **merged to `next` on 2025-06-18 (v4)**, but a latent CRLF line-ending bug in Patch 2/4 (the `has_required_headers()` helper function) was identified by Junio C Hamano, requiring this new iteration (`v5`). **Patch 1/4 (tunnel process lifecycle fix) was previously merged to `next` on 2025-06-10 and remains unchanged in `v5`.**

Core problem or goal: `git imap-send` fails when processing patches where the `Subject` header precedes the `Date` header (a valid but non-canonical order produced by tools like `b4`) or when header field names are not lowercase (e.g., `FROM:`, `DATE:`). The series fixes the header-parsing logic to accept any order and any case for `From:`, `Date:`, and `Subject:` headers, ensuring RFC 5322 compliance. It also plugs a tunnel-command memory leak by properly reaping the tunnel process via `finish_command()` (defensively coded to store `imap->tunnel` as an allocated pointer), and removes the `git-send-email` special case (which previously ignored `Subject` headers for messages starting with `From git-send-email`). The goal is to ensure interoperability with `b4` and other tools while maintaining backward compatibility. **The latent CRLF bug in Patch 2/4** (the `has_required_headers()` helper function) has been fixed in `v5` by adjusting the line-iteration logic to handle both LF (`\n\n`) and CRLF (`\r\n`) line endings, aligning with IMAP’s RFC 2060 requirements.
