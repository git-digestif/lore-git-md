Subject: [PATCH 0/2] MyFirstContribution: reorder tutorial to emphasize review discussion before v2
Series version: v2 (2 patches)
Originating author: Junio C Hamano
Thread type: documentation patch series

Core problem or goal
Clarify the intended contribution workflow in `MyFirstContribution.adoc` by moving the "Sending v2" instructions after the "Responding to Reviews" section and strengthening the language to discourage sending updated patch versions before engaging with review feedback. The goal is to reduce premature v2 submissions from new contributors.

Current status
Under review; v2 posted addressing Patrick Steinhardt’s editorial feedback. Junio has proposed a minor wording tweak in response to Patrick’s latest comment, inserting *"so that both sides know what to expect in the next round"* to clarify the meaning of "finished discussing." Patch 1/2 (structural reordering) remains uncontroversial and ready for integration. Patch 2/2 (wording improvements) retains its stricter language but now includes the additional clarification. No merge event to `master` or any integration branch has been reported.

Key technical details
- File touched: `Documentation/MyFirstContribution.adoc`
- No new symbols, CLI options, or on-disk format changes
- No test coverage changes
- Patch 1/2: pure structural reordering—"Sending v2" sections moved from immediately after "Sending v1" to after "Responding to Reviews"; no text changes, only block relocation. Confirmed by Patrick Steinhardt as trivial and easy to follow with `git diff --color-moved`.
- Patch 2/2: wording improvements—strengthened cautionary language ("It is good manners to do so" → "Do not send v2 before you are done discussing the current iteration with reviewers"), typo corrections (`interations` → `iterations`), redundant newlines removed, subject-verb agreement (`do` → `does`), removal of duplicated cautionary content from the "Reviewing" section, removal of the sentence *"After a few days, you will hopefully receive a reply to your patchset with some comments. Woohoo! Now you can get back to work."*, and new phrasing: *"Do not start coding, let alone send the next version of your patch, until you have finished discussing the current one so both sides know what to expect."*

Open questions and loose ends
- **Phrasing refinement**: Patrick Steinhardt’s latest feedback suggests retaining the removed sentence (*"After a few days..."*) for stylistic context, while Junio’s proposed tweak addresses the same concern by clarifying the communication expectations. No substantive objections exist; this remains a surface-level preference.
- **Tone balance**: Patrick Steinhardt mildly objects to the blanket advice *"Do not start coding"* in patch 2/2, noting that exploratory coding during discussion can sometimes be productive. Junio retained the stricter language, arguing it reflects observed contributor behavior, and the new phrasing does not soften this stance.
