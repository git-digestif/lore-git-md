This is a small bugfix patch for `imap-send.c`. It plugs a memory leak in the IMAP tunnel code path: when `imap.tunnel` is configured, Git starts an external command but never releases the `child_process` structure that holds its argument list. The fix is a one-line call to `child_process_clear()` after the tunnel is running, freeing the now-unneeded resources. The commit message notes that no existing test exercises this code path, so the leak went unnoticed by the leak checker. This is the first patch in a two-patch series; the second patch is not shown here. The change is straightforward and appears to address a real, if obscure, issue.
