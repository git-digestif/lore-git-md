This is a user report and review of Harald Nordgren’s `--delete-merged` series, specifically the v2 iteration that adds squash-merge detection. Jasper Mayone, a contributor who works in repositories where GitHub’s “Squash and merge” is the norm, built and tested the patch on synthetic repositories with 3000+ commits and 80 branches.

The results are mixed. The patch correctly identifies squash-merged, rebase-merged, and renamed branches, and it skips branches whose changes only partly landed. However, it also deletes a branch whose changes were independently implemented by someone else—exactly the “irrelevant” case Junio Hamano warned about. Jasper agrees that the strict, tip-reachability-only meaning of `--delete-merged` should remain the default, and he endorses D. Ben Knoble’s earlier suggestion of a granular `--landed=<kind>` option (e.g., `--landed=squash`) instead of the current `--no-squashed` flag. He also proposes a config variable so users can set their preferred default once per repository.

Performance is acceptable: the feature adds ~50 ms overhead on a full clone (0.078 s vs. 0.030 s baseline), and the `--no-squashed` flag restores baseline speed. In a blobless clone the first run fetches 13 blobs and takes 0.42 s; subsequent runs are faster.

Jasper also notes two usability nits: (1) checked-out branches in worktrees are skipped silently, while branches with `deleteMerged=false` print “Skipping”, and (2) he plans a separate RFC for `git worktree list --merged`, so he’d like the “has this branch landed?” logic to be factored into a reusable helper. He signs off with a Tested-by trailer.
