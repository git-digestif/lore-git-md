This is a two-patch bugfix series for `git imap-send`. The issue: when `git imap-send` processes patches that were originally sent with `git send-email` (for example, patches fetched from lore.kernel.org using `b4`), it fails if the email headers are in an order it does not expect—specifically, if the `Subject` header appears before the `Date` header. The series makes `imap-send` accept such messages and also plugs a small memory leak in the tunnel-command handling.

The patches touch `imap-send.c` (the core logic) and add a new test in `t/t9001-send-email.sh` that verifies the fix works with reordered headers. The commit messages are clear and the code changes look straightforward: the first patch is a one-line leak fix, the second is a refactoring of the header-parsing loop to stop assuming a fixed order.

This is a real, user-facing bug that affects a common workflow (fetching patches from lore and pushing them to an IMAP folder), so it is worth attention. The fix is small, well-contained, and comes with a test, which suggests it is ready for review.
