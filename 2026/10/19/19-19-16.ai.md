This is a two-patch bugfix series for `git imap-send`. The issue: `git imap-send` fails when processing patches that have the `Subject` header before the `Date` header, which is a valid but non-canonical order that tools like `b4` (used to fetch patches from lore.kernel.org) produce. The series fixes the header-parsing logic to accept either order and plugs a minor memory leak in the tunnel-command handling.

Patch 1/2 (`imap-send: avoid leaking the tunnel command`) is a small cleanup that frees the tunnel command string after use, preventing a leak that valgrind would flag.

Patch 2/2 (`imap-send: accept messages with Subject before Date`) is the main fix. It rewrites the header-parsing loop in `imap-send.c` to scan all headers first, then process them in the required order (`Date` before `Subject`), rather than assuming the headers appear in a fixed sequence. The commit message notes that this matches the behavior of other email tools and is necessary for interoperability with `b4`-fetched patches.

The series touches only `imap-send.c` and adds a new test in `t/t9001-send-email.sh` that verifies the fix by sending a patch with `Subject` before `Date` and confirming it is accepted. The test coverage looks thorough: it exercises the new code path and checks for regressions in the existing one.

This is a clear, well-motivated bugfix with a minimal footprint. The problem is real (interoperability with `b4`/`lore`), the solution is straightforward, and the test ensures it won’t regress. No controversy is evident; the series should be uncontroversial.
