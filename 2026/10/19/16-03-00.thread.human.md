This thread is about a small but important documentation fix for Git’s partial-clone subsystem. Aleksei Sviridkin has posted a patch that corrects inaccuracies in `partial-clone.adoc`, clarifying that only one of the eleven call sites of `promisor_remote_get_direct()` still performs "one-at-a-time" fetches—the rest batch missing objects into a single request. The patch also updates outdated references to `fetch-pack` to reflect the current "git fetch" subprocess implementation introduced in 2020.

The patch itself is uncontroversial: it’s a minimal, surgical change to the design document, with a well-motivated commit message that explains both the technical context and historical background. This is a repost of a September 3 patch with an improved commit message, suggesting the technical content has already been reviewed. There are no open questions or objections, and the patch applies cleanly to `master`. It’s ready for integration and should be a straightforward improvement to the accuracy of the documentation.

Separately, the author included a concerning note about an unacknowledged security report sent to `git-security@` and GitHub’s private vulnerability reporting system, with no response after 46 days. This isn’t part of the patch but may need attention from maintainers. The patch, however, is unrelated to that issue and stands on its own.
