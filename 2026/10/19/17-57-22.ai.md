This patch is a **bugfix** targeting the `status` and `checkout` commands. It rewords the message shown when a local branch is configured to track a remote branch that does not exist, correcting a long-standing confusion where Git claimed the upstream was "gone" even when it had never been created (e.g., after cloning an empty repository).

The current message ("Your branch is based on 'origin/master', but the upstream is gone") is misleading because Git cannot distinguish between a deleted upstream and one that was never created. The patch replaces it with a neutral phrasing ("Your branch is set up to track 'origin/master', which does not exist") and tailors the advice: it suggests `git push` only when that command would actually create the missing branch (e.g., when `@{push}` resolves to the upstream), otherwise falling back to `git branch --unset-upstream`. The change affects both `git status` and `git checkout`, but preserves the `[gone]` indicator in short formats (e.g., `git status -sb`, `git branch -vv`) to avoid breaking scripts.

The commit message is thorough, explaining the problem, the fix, and the edge cases (e.g., `push.default=nothing`). The patch includes extensive tests covering empty-clone scenarios, deleted upstreams, and various `push.default` configurations.
