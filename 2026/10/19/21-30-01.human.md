This is a brief follow-up in the ongoing bugfix thread for the loose ref cache inconsistency in the files backend. Andy Koppe posts **v3 of the patch**, incorporating Patrick Steinhardt’s feedback from the v2 review.

The core implementation remains unchanged: root refs (like `HEAD` and `ORIG_HEAD`) are excluded from the shared loose ref cache, and a temporary cache is created for them only when the `REFS_FOR_EACH_INCLUDE_ROOT_REFS` flag is passed. What’s new in v3 is a **range-diff against v1**, making it easier for reviewers to see the evolution of the patch. The documentation corrections (fixing outdated references to “pseudorefs”) have been split out into a separate commit, as Patrick requested, and will be submitted later.

The patch is now technically unblocked and ready for further review. The architectural discussion—whether to use a temporary cache or Junio C Hamano’s proposed persistent dual-cache design—remains open, but v3 does not attempt to resolve it. The expanded commit message in v3 already discusses these trade-offs, so this email itself adds little new substance beyond confirming the procedural updates.
