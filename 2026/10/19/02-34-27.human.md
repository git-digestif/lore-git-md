This is a gentle nudge for a **bugfix** to the `git-contacts` contrib script that has been sitting unreviewed since early September. The patch itself is well-crafted and addresses a clear, long-standing issue: boundary commits (where `git blame` stops traversal, such as the initial commit or shallow clone cut-offs) are currently misclassified as legitimate contributors, leading to false positives in reviewer suggestions.

The fix is minimal and targeted—it modifies the blame parser to explicitly track and exclude boundary commits, and adds the `--root` flag to `git blame` to prevent the initial commit from being marked as a boundary. The commit message includes quantitative evidence showing the fix improves accuracy: 27 reviewer lists corrected, 9 now correctly empty, and 3 improved by removing noise. The patch also updates the man page to document the boundary commit exception.

No controversy is expected here; the change aligns with the script’s intended purpose and has been stable in testing. It applies cleanly to `master` and `maint`, and the issue has existed since the script was introduced in 2013, so the fix is relevant to all supported releases. The author is simply asking whether this is still wanted or if a resend would help. Given the clarity of the problem and the low-risk nature of the fix, this seems like an easy win for anyone looking to improve contrib tooling.
