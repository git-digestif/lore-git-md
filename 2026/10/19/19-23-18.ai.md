This is a **feature patch** that changes the default behavior of `git status` in triangular workflows.

The patch makes `git status` compare the current branch against *both* its upstream (`@{upstream}`) and push (`@{push}`) destinations by default, rather than only the upstream. When the two destinations resolve to the same branch (the common case), only one comparison is shown, so most users will see no change in output. Users who want the old behavior can restore it by setting `status.compareBranches` to `@{upstream}`.

The change touches `remote.c` to append `@{push}` to the default comparison list, updates the `Documentation/config/status.adoc` man page to reflect the new default, and adjusts tests in `t/t6040-tracking-info.sh` and `t/t5505-remote.sh` to match. The test updates are mechanical: removing explicit `status.compareBranches` settings that are now redundant, and reordering or rewording tests to reflect the new default.

The commit message is clear and concise, explaining the motivation (triangular workflows), the behavior change, and the backward-compatibility escape hatch. The patch itself is small and focused, with no obvious red flags in the diff. It looks like a well-considered, user-facing improvement that should not break existing workflows.
