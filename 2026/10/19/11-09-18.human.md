This is the second patch in Igor Wiedler’s two-patch bugfix series that resolves a performance regression in shallow fetches by tightening the trust boundary around alternate refs. The patch teaches `odb_for_each_alternate_ref()` to skip refs from any alternate that is itself shallow or grafted, preventing fetch-pack and receive-pack from treating those refs as valid “have”s. The change is backward-compatible: alternates without a `shallow` or `info/grafts` file continue to work exactly as before.

The motivation is straightforward: a shallow or grafted alternate cannot guarantee the full history behind its refs, so any repository that borrows from it risks silent corruption if those refs are used as connectivity boundaries. The patch mirrors the existing safety check in `git clone --reference`, extending it to alternates added via `objects/info/alternates` or `GIT_ALTERNATE_OBJECT_DIRECTORIES`. The commit message explicitly defers the partial-clone (promisor remote) edge case, noting that detecting it would require reading the alternate’s config.

Code changes are minimal: eleven lines in `odb.c` that check for the presence of `shallow` and `info/grafts` files before calling `read_alternate_refs()`, plus a small documentation update in `rev-list-options.adoc` and a new test in `t/t5618-alternate-refs.sh` that verifies shallow alternates are ignored. The test uses `GIT_TRACE2_EVENT` to confirm the refs are excluded, and the Windows portability fix from v2 (replacing `$TRASH_DIRECTORY` with `$(pwd)`) is already incorporated.

Review context is strong: Junio and Peff both helped shape the design, and Peff’s earlier review of patch 1 confirmed the overall approach is sound. The only loose end is the deferred partial-clone case, which the commit message frames as a reasonable trade-off given the complexity. This patch looks ready for integration alongside its companion.
