This is a bugfix patch for the `imap-send` subsystem, part of a two-patch series. The patch plugs a memory leak in `imap_open_store()` when the `imap.tunnel` configuration is used. The leak occurs because the `child_process` struct (`tunnel`) is never released after the tunnel is started, even though only its pipes are needed. The fix adds a call to `child_process_clear(&tunnel)` immediately after the tunnel is running, freeing the argument list and other resources. The commit message notes that no existing test covers this code path, so the leak went undetected by the leak checker.

The change is minimal—one line added to `imap-send.c`—and targets a specific, narrow edge case (IMAP tunneling). The patch is well-motivated: it identifies a clear resource leak and provides a straightforward fix. The absence of test coverage for this code path is mentioned, but the fix itself is uncontroversial and aligns with Git’s general practice of cleaning up process resources. The patch is likely to be accepted as-is, assuming the second patch in the series doesn’t introduce complications.

Key technical details for follow-up discussion: the patch touches `imap-send.c`, specifically the `imap_open_store()` function, and introduces a call to `child_process_clear()` on the `tunnel` struct. The leak is tied to the `imap.tunnel` config option, which is not exercised by the current test suite. No behavior change is expected for users, only a reduction in memory usage for those using IMAP tunneling.
