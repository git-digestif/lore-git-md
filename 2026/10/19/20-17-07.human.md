This is a bugfix patch targeting the skipping negotiator in Git's fetch machinery.

Taylor Blau identifies a subtle ordering bug in the skipping negotiator's queue management. The negotiator sorts commits by date to prioritize recent work, but when a parent commit is added to the queue via `push_parent()`, its date isn't parsed yet, so it defaults to zero. This can cause old ref tips to jump ahead of recent common ancestors in the queue, potentially ending negotiation prematurely before the client and server find a shared commit.

The fix is straightforward: parse each unseen parent commit before adding it to the queue, ensuring the queue uses the actual commit date. If parsing fails, the parent is left out of the queue. The patch includes a new test that demonstrates the issue by creating a topic branch with 32 old ref tips; without the fix, the recent common ancestor is delayed past the first batch of "have" messages.

The commit message is clear and the test coverage looks thorough. This is a well-motivated fix for a real edge case in the skipping negotiator.
