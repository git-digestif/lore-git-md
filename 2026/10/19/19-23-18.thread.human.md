This thread is about a proposed change to `git status` that would make it more useful in triangular workflows (where you push to a different branch than you pull from) by defaulting to comparing against both `@{upstream}` and `@{push}` instead of just `@{upstream}`. The patch is from Harald Nordgren and is currently at version 1, with a v2 planned to address feedback.

The key discussion so far has been about whether this change is justified. Junio C Hamano and Phillip Wood both raised substantive questions about the patch’s motivation and historical context for the current default behavior. Harald has accepted this feedback and plans to expand the commit message in v2 to better explain why the current default (`@{upstream}`) exists and why the proposed change makes sense. He’ll also add more test coverage to explicitly handle both triangular and common-case scenarios.

The technical implementation touches `remote.c`, documentation, and tests, but doesn’t change any on-disk formats or introduce new CLI options. The change is backward-compatible—users can restore the old behavior by setting `status.compareBranches` to `@{upstream}`. The patch is still under review, with no merge status recorded yet. The latest email in the thread is just a side discussion about mailing-list reply etiquette and doesn’t move the technical discussion forward.
