This thread proposes changing the default behavior of `git status` to compare the current branch against both `@{upstream}` and `@{push}` by default, making it more useful in triangular workflows where the push destination differs from the upstream. The patch, authored by Harald Nordgren, is the first version and touches `remote.c`, documentation, and tests to implement this change without altering on-disk formats or introducing new CLI options.

Junio C Hamano has raised substantive questions about the patch’s justification and test coverage. He suggests the commit message should better explain the historical context of `status.compareBranches` and asks whether the tests adequately cover both triangular workflows and cases where `@{upstream}` and `@{push}` resolve to the same branch. While the code itself has no technical objections yet, the discussion now focuses on whether the change is well-motivated and thoroughly tested. The patch remains under review, with the author expected to address Junio’s feedback in a follow-up version. No other participants have weighed in yet.
