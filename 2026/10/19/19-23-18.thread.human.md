This thread proposes changing `git status` to compare the current branch against both `@{upstream}` and `@{push}` by default, making it more useful in triangular workflows where the push destination differs from the upstream. The patch, authored by Harald Nordgren, is currently under review after its initial submission.

Junio C Hamano and Phillip Wood have raised substantive questions about the patch’s justification and historical context for the current default (`@{upstream}`). Harald has accepted this feedback and plans to address it in a v2 by expanding the commit message to clarify the historical rationale for `status.compareBranches` and adding explicit test cases for both triangular and common-case scenarios. The code itself has not faced technical objections, but the patch’s foundational premise remains under discussion until the v2 is posted.

No merge decisions have been made yet, and the series is still in the review phase. The next iteration is expected to resolve the remaining open questions about justification and test coverage.
