This thread is about a proposed change to `git status` that would make it compare the current branch against both `@{upstream}` and `@{push}` by default, rather than just `@{upstream}`. The patch, now in its second version, aims to improve usability in triangular workflows where the push destination differs from the upstream branch. Harald Nordgren, the author, argues that this change would help less experienced users transition smoothly into triangular workflows by making both comparisons visible by default, while preserving the current experience for most users (where `@{upstream}` and `@{push}` resolve to the same branch).

The patch itself is technically sound: it modifies `remote.c` and updates documentation and tests to support the new default behavior, with an escape hatch for users who prefer the old behavior. However, the core debate has shifted from implementation to justification. Junio C Hamano, the maintainer, has reopened the discussion by challenging the patch’s underlying assumption—that comparing against both branches by default is universally beneficial. He argues that `@{push}` is typically under the user’s control and thus less likely to introduce "surprises," making the default change unnecessary. Harald has pushed back, citing real-world experience where users often don’t realize they’re missing upstream information until they explicitly reconfigure their workflow, which can feel disruptive.

The thread is now at a crossroads. Junio’s objection remains unresolved, and the patch’s readiness for merging hinges on whether Harald can provide a stronger argument for the default change—perhaps through additional evidence like user surveys or anecdotes from other maintainers. Without further input or a shift in maintainer consensus, the discussion may stall. For now, the patch remains under review, with no clear path forward.
