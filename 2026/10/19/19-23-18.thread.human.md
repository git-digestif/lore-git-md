This thread proposes changing the default behavior of `git status` to compare the current branch against both its upstream and push destinations, making it more useful in triangular workflows. The patch, now in its second version (v2), comes from Harald Nordgren and addresses earlier feedback from Junio C Hamano and Phillip Wood.

The key change is that `status.compareBranches` now defaults to `@{upstream},@{push}` instead of just `@{upstream}`. When the two destinations are the same (the common case), only one comparison is shown, so most users won’t see any difference. The patch is backward-compatible—users can restore the old behavior by setting `status.compareBranches` to `@{upstream}`—and includes thorough test coverage for both triangular and common-case scenarios. The expanded commit message in v2 provides historical context, explaining why the feature was originally made opt-in and why the default is now being revisited.

Junio and Phillip had raised substantive questions about the patch’s justification and test coverage in v1, but those concerns have been addressed in this update. No technical objections remain, and the patch is now ready for further review or integration. The changes are confined to `remote.c`, the status configuration documentation, and the test suite, with no on-disk format or CLI changes.
