This thread introduces a small but user-visible change to `git status` behavior in triangular workflows. Harald Nordgren proposes that, by default, `git status` should compare the current branch against *both* its upstream (`@{upstream}`) and push (`@{push}`) destinations, rather than only the upstream. When the two destinations are the same (the common case), the output remains unchanged, so most users won’t notice any difference. Those who prefer the old behavior can restore it by setting `status.compareBranches` to `@{upstream}`.

The patch itself is straightforward: it modifies `remote.c` to append `@{push}` to the default comparison list, updates the documentation to reflect the new default, and adjusts a few tests to match the new behavior. The commit message clearly explains the motivation (better support for triangular workflows) and the backward-compatibility escape hatch. So far, there’s been no review feedback, so the patch is still in its initial proposal stage. If you use triangular workflows, this change might make `git status` more informative without requiring any configuration.
