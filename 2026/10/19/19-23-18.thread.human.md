This thread is about Harald Nordgren’s patch to make `git status` default to comparing against both `@{upstream}` and `@{push}` in triangular workflows, rather than just `@{upstream}`. The goal is to make the command more useful when the push destination differs from the upstream branch, while preserving the existing experience when they’re the same.

The patch is still under review after its initial v1 submission. Junio C Hamano and Phillip Wood raised substantive questions about the patch’s justification and historical context for the current default behavior. Harald has accepted this feedback and plans to address it in a v2, which will expand the commit message to clarify the rationale and add explicit test cases for both triangular and common-case scenarios. The code itself—modifying `remote.c`, documentation, and tests—hasn’t drawn technical objections, but the foundational premise of the change remains open until the v2 lands.

Kristoffer Haugsbakk’s recent reply is a low-weight comment on mailing-list etiquette, endorsing Harald’s observation about trimming quoted material in replies. It doesn’t engage with the patch’s design or code, so it doesn’t move the discussion forward. The thread is still focused on preparing the v2, with no merge status or new technical concerns raised.
