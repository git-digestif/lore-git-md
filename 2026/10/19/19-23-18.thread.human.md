This thread proposes making `git status` more useful in triangular workflows by defaulting to comparing the current branch against both `@{upstream}` and `@{push}` instead of just `@{upstream}`. The change would show both comparisons when the push destination differs from the upstream, while preserving the single-comparison experience when they match.

The patch is under active review. Junio C Hamano initially raised substantive questions about the patch’s justification and test coverage, which the author, Harald Nordgren, has accepted and plans to address in a v2. Phillip Wood’s recent review reinforces the need for clearer historical context in the commit message—specifically, why the current default (`@{upstream}`) was originally chosen and what discussions surrounded its introduction. This feedback is shaping the next iteration, which will also restore and expand test coverage for both triangular and common-case scenarios.

No technical objections to the code itself have been raised, and the patch remains in the review phase with no merge status recorded. The key files touched are `remote.c`, `Documentation/config/status.adoc`, and two test scripts. Users can revert to the old behavior by setting `status.compareBranches` to `@{upstream}`.
