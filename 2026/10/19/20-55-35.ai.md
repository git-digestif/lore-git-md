This is a bugfix for the config subsystem, now approved and queued by Junio. The patch fixes a long-standing (since 2013) platform-dependent bug where in-memory config readers (e.g., `git config --blob`) misinterpret bytes with the high bit set (0x80–0xff) when `char` is signed (as on x86). The issue causes two symptoms: a 0xff byte is treated as EOF, truncating the config blob, and UTF-8 byte order marks trigger spurious "bad config line" errors. The fix casts the byte to `unsigned char` in `config_buf_fgetc()` and updates the ungetc check to match, aligning behavior with file-based config reading.

The patch touches only `config.c` (specifically `config_buf_fgetc()` and its ungetc check) and adds three new tests in `t/t1307-config-blob.sh` to verify the fix handles 0xff bytes (both standalone and after CR) and UTF-8 BOMs. Junio’s reply is brief but positive, indicating he will queue the patch as-is.
