This is a **documentation** patch series (v2) replacing the outdated `gittutorial` man page with a new beginner-focused guide. The series is authored by Julia Evans, based on extensive user testing with 112 participants, and aims to provide a modern, practical introduction to Git that reflects current workflows.

The new tutorial is split into two parts: local repository creation and commits (Steps 1–7), and pushing to a remote host like GitHub or GitLab (Steps 8–14). Key design choices include starting with `git init` (to avoid forge-specific confusion), using SSH for authentication (with disclaimers about security policies), and omitting branching/collaboration to keep the tutorial focused and digestible. The author has incorporated minor feedback from D. Ben Knoble, addressing platform assumptions (e.g., *nix/Git for Windows), accessibility (e.g., `+`/`-` sigils in `git diff` for colorblind users), and clarifying the `-u` flag in `git push`.

Notable changes from v1 include removing a redundant Python file example, adding more detailed explanations of `git status` output (e.g., "untracked files"), and replacing `git push -u` with `git push --set-upstream` for clarity. The tutorial also includes a troubleshooting section for common issues (e.g., SSH host verification, branch name mismatches) and a disclaimer about simplified SSH key setup. The author explicitly frames the tutorial as "good enough" for merging, with plans for iterative improvements based on user feedback post-merge, particularly around branching and collaboration.

The series touches only `Documentation/gittutorial.adoc`, replacing its content entirely. While the tutorial is well-tested and addresses real user pain points, two open questions remain: whether to start with `git init` or `git clone` (the author defends the former as more consistent for beginners), and how to handle authentication generically without tying instructions to specific forges. The author’s urgency to merge stems from funding constraints, but the patch is unlikely to be controversial—its focus on documentation and user-tested design makes it a strong candidate for `next`.
