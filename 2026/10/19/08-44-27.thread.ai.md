Subject: [PATCH v3] archive-zip: use Q_() for singular/plural error message
Series version: standalone (single patch, v3)
Originating author: kerylefondji7@gmail.com
Thread type: patch submission

Core problem or goal
Replace a hardcoded singular/plural error message in the ZIP archive backend (`archive-zip.c`) with Git’s `Q_()` macro to support proper pluralization in all languages, not just the English singular case (`pathlen == 1`). The error message is triggered when a path exceeds the ZIP format’s 65,535-byte limit.

Current status
Ready for inclusion pending a resend with corrected formatting. This is the third iteration of the patch, incorporating all prior feedback: the commit message now clearly states the broader i18n motivation (support for languages with complex plural rules) and clarifies that the English singular case (`pathlen == 1`) is impossible in this context (since the error only triggers for `pathlen > 65535`). The only remaining issue is mechanical: the `Q_()` macro call is misaligned (spaces instead of tabs) and the line exceeds 80 characters. No code logic, test, or documentation changes are required. Both Phillip Wood and Junio C Hamano have reviewed prior versions and endorsed the approach; Phillip’s latest feedback is purely cosmetic.

Key technical details
- File: `archive-zip.c`
- Function: `write_zip_entry()`
- Macro introduced: `Q_()`
- Trigger condition: `pathlen > 65535` (ZIP format limit)
- Error message components: path length, object SHA-1, path itself
- No new strings added to the translation catalog; existing string split into singular and plural variants
- No logic, test, or documentation changes
- Pluralization context: The error is only reachable for `pathlen > 65535`, so the English singular case (`pathlen == 1`) is unreachable, but `Q_()` is still valuable for languages with more complex plural rules (e.g., Polish).
