Subject: [PATCH v4] archive-zip: use Q_() for singular/plural error message
Series version: standalone (single patch, v4)
Originating author: kerylefondji7@gmail.com
Thread type: patch submission

Core problem or goal
Replace a hardcoded singular/plural error message in the ZIP archive backend (`archive-zip.c`) with Git’s `Q_()` macro to support proper pluralization in all languages, not just the English singular case (`pathlen == 1`). The error message is triggered when a path exceeds the ZIP format’s 65,535-byte limit.

Current status
Ready for inclusion after one final mechanical fix. This is the fourth iteration of the patch, incorporating all prior feedback: the commit message clearly states the broader i18n motivation (support for languages with complex plural rules) and clarifies that the English singular case (`pathlen == 1`) is impossible in this context (since the error only triggers for `pathlen > 65535`). The mechanical issues (indentation with tabs, line wrapping under 80 characters, `Q_()` argument alignment) have been addressed except for one remaining nit: the indentation inside the `if` block is incorrect, and the function arguments no longer align with the opening parenthesis of `error()`. The fix is trivial and does not affect the patch’s logic or i18n value. Both Phillip Wood and Junio C Hamano have reviewed prior versions and endorsed the approach; the latest version addresses their final cosmetic feedback. The author has explicitly pinged Junio to pick it up for `next`; no further revisions are expected unless this final nit is addressed.

Key technical details
- File: `archive-zip.c`
- Function: `write_zip_entry()`
- Macro introduced: `Q_()`
- Trigger condition: `pathlen > 65535` (ZIP format limit)
- Error message components: path length, object SHA-1, path itself
- No new strings added to the translation catalog; existing string split into singular and plural variants
- No logic, test, or documentation changes
- Pluralization context: The error is only reachable for `pathlen > 65535`, so the English singular case (`pathlen == 1`) is unreachable, but `Q_()` is still valuable for languages with more complex plural rules (e.g., Polish).

Open questions and loose ends
One remaining mechanical nit: the indentation inside the `if` block is incorrect, and the function arguments no longer align with the opening parenthesis of `error()`. This violates Git’s coding style (hard tabs for indentation, aligned function arguments). The fix is trivial and does not affect the patch’s logic or i18n value.
