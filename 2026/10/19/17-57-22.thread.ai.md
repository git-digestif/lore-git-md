Thread identity: Subject "[PATCH] status,checkout: clarify tracking branch does-not-exist message"; standalone bugfix patch now at v3, originally authored by Elia Pinto; v3 is based on commit 47fdf2208c and remains queued in `seen` as `ep/status-missing-upstream` under review, with no evidence of graduation to `next` or `master`.

Core problem or goal: `git status` and `git checkout` previously printed "the upstream is gone" when a local branch tracks a remote branch that is absent, which is misleading when the upstream was never created, such as after cloning an empty repository. The patch changes the wording to a neutral "does not exist" form and replaces the unconditional `git branch --unset-upstream` advice with conditional guidance: suggest `git push` only when a plain push would actually create the missing upstream, otherwise suggest unsetting the upstream. The short-format `[gone]` indicator in `git status -sb`, `git branch -vv`, and `%(upstream:track)` of `git for-each-ref` is intentionally unchanged to avoid breaking scripts.

Current status and version changes: v3 has been posted and the maintainer review discussion is now closed. v3 moves the `push_creates()` call inside `format_missing_upstream()` so the computation is skipped when `advice.statusHints` is disabled, expands the comment above `push_creates()` to explain the `@{push}`-based reasoning, and adds roughly 150 lines to `t/t6040-tracking-info.sh`. Key technical details: Files touched are `remote.c` and `t/t6040-tracking-info.sh`; no on-disk format change. Implementation centers on a new `push_creates()` helper called from `format_missing_upstream()`, which is called from `format_tracking_info()`. The helper checks whether `@{push}` resolves to the tracked upstream, thereby excluding `push.default=nothing`, narrow explicit `remote.<name>.push` refspecs that do not cover the current branch, mirror remotes that would push to a different name, and `pushRemote` configurations pointing elsewhere, while retaining the existing special case for `push.default=matching` unless explicit refspecs or mirroring override it. Tests cover empty clones, deleted upstreams, all `push.default` values, explicit push refspecs including narrow and mirror-mismatch cases, `branch.<name>.pushRemote` to a different remote, and `advice.statusHints=false`.
