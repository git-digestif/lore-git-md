This is a bugfix for the files ref backend, updating the patch to its third iteration (v3). The patch resolves an inconsistency in how root refs (like `HEAD` or `ORIG_HEAD`) are handled in the loose ref cache. Previously, root refs were only included if the `REFS_FOR_EACH_INCLUDE_ROOT_REFS` flag was passed during the *first* iteration that created the cache; subsequent iterations included them regardless of the flag, while earlier iterations omitted them even if the flag was set. The reftable backend is unaffected.

The v3 patch keeps root refs out of the shared loose ref cache entirely. Instead, when an iterator requests root refs, it creates a separate temporary ref cache for them, overlays its iterator on the loose ref iterator, and frees the cache when done. This approach avoids the inconsistency while minimizing overhead, since the flag is used in only two places and invoked just once per command. The core implementation remains unchanged from v2, but the commit message has been expanded to discuss alternatives (such as always including root refs in the cache or using persistent dual caches) and justify the chosen design. The documentation corrections from v2 have been dropped and will be addressed in a separate patch, as requested by Patrick Steinhardt.

The patch touches `files-backend.c` and adds a test in `t/t6302-for-each-ref-filter.sh` to verify that `--include-root-refs` works correctly with `--merged`. The test coverage is minimal but sufficient to demonstrate the fix. The change is localized to the refs subsystem and does not affect user-facing behavior beyond fixing the inconsistency. The range-diff against v1 shows improvements to the commit message and code organization, such as moving the `create_root_ref_cache()` function below `get_loose_ref_cache()` for clarity.
