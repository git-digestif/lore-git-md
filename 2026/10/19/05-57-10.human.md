This is a cleanliness concern: the patch series would be easier to review and revert if the behavioral change and the documentation update were distinct commits.

The patch itself remains technically sound and unblocked. The core fix—excluding root refs from the shared loose ref cache and creating a temporary cache for them when requested—has not been challenged, and Patrick’s earlier performance concerns were resolved in the v1 discussion. The only open question is whether the documentation tweaks should be split out, which is a matter of project convention rather than correctness. The patch is still a well-scoped bugfix targeting `files-backend.c` with minimal test coverage, and the reftable backend is unaffected.
