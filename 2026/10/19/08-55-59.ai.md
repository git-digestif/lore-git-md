This is the fourth patch in Patrick Steinhardt’s seven-patch series introducing the **object storage extension**, a foundational step toward pluggable object database backends in Git. This patch adds user-facing inspection tools for the object storage format, mirroring the existing ref storage inspection commands.

The patch exposes the configured object storage format via two commands:
- `` `git rev-parse --show-object-storage-format` ``, which prints the value of `extensions.objectStorage` (or `files` if unset).
- `` `git repo` ``’s `objects.storageFormat` field, which returns the same value in a structured format.

The implementation is straightforward: it adds a new helper function (`get_object_storage_format`) to `builtin/repo.c` and a new option to `builtin/rev-parse.c`, both of which query the `object_storage_format` field in `struct repository`. The patch also updates documentation (`git-repo.adoc`, `git-rev-parse.adoc`) and adds tests in `t0001-init.sh` and `t1900-repo-info.sh` to verify the output matches the configured backend.

This is a small but necessary piece of the larger series. It ensures users and scripts can inspect the object storage configuration, which will be critical once multiple backends are available. The patch is uncontroversial and follows the established pattern for ref storage inspection, suggesting it will likely be accepted without significant pushback. The only minor quirk is the hard-coded default (`files`) in the output, which could theoretically diverge from the actual backend if future patches introduce dynamic defaults, but this is a nit at best.
