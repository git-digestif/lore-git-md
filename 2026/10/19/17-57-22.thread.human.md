Elia Pinto has posted v3 of a standalone patch clarifying the "tracking branch does not exist" message that `git status` and `git checkout` print. Where the old wording said "the upstream is gone" -- which is wrong when the upstream was never created, as after cloning an empty repository -- the new message says the upstream "does not exist," and the advice is now conditional: `git push` is suggested only when a plain push would actually create the missing branch, otherwise `git branch --unset-upstream` is recommended. The short-format `[gone]` indicator is deliberately left unchanged so scripts that grep for it keep working.

The v3 incorporates the structural change Junio C Hamano requested: the `push_creates()` call now lives inside `format_missing_upstream()` in `remote.c`, so the `@{push}` resolution work is skipped when `advice.statusHints` is disabled, and the comment above the helper now spells out the reasoning. Elia also answered all three of Junio's edge-case questions -- mirror remotes pushing to a different name, narrow explicit push refspecs, and `push.default=nothing` vs `matching` -- with explanations grounded in how `branch_get_push_1()` resolves. Test coverage in `t/t6040-tracking-info.sh` grew to roughly 150 new lines covering empty clones, deleted upstreams, all `push.default` values, explicit and narrow push refspecs, mirror remotes, `pushRemote`, and the `advice.statusHints=false` case.

The series remains queued in `seen` as `ep/status-missing-upstream` and under review; there is no announced merge to `next` or `master`. The only outside review so far is Harald Nordgren's bare "v2 looks good to me," a surface-level sign-off with no technical elaboration, so the patch's correctness has not been independently verified beyond Junio's engaged review of the logic.
