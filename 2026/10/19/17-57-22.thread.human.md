This thread is about a small but user-facing bugfix to Git’s `status` and `checkout` commands. When a local branch tracks a remote branch that was never created (for example, after cloning an empty repository), Git currently says the “upstream is gone” and suggests running `git branch --unset-upstream`. The patch from Elia Pinto rewords the message to “does not exist” and tailors the advice: `git push` is now suggested only when it would actually create the missing branch, otherwise the old advice (`--unset-upstream`) is kept.

Junio C Hamano, the maintainer, has already reviewed the change in detail. He approved the neutral phrasing, the conditional advice logic, and confirmed that the `[gone]` indicator in short formats (`git status -sb`, `git branch -vv`) is preserved for script compatibility. The implementation is complete, the tests cover all the edge cases (empty clones, deleted upstreams, `push.default` settings, mirror remotes), and the patch is queued in Junio’s `seen` branch under the topic `ep/status-missing-upstream`. It has been marked “Needs review” in the last three “What’s cooking” reports, so it is simply waiting for any final feedback before moving to `next`. If nothing new comes up, it should graduate soon.
