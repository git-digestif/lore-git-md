This thread concerns Elia Pinto's standalone patch (v2) rewording Git's message when a branch tracks a non-existent remote branch. The patch changes "the upstream is gone" to "does not exist" in `git status` and `git checkout`, and makes the advice conditional: suggesting `git push` only when it would actually create the missing branch (based on `@{push}` resolution and explicit push refspecs), otherwise recommending `git branch --unset-upstream`. The series is queued in `seen` as `ep/status-missing-upstream` and has been marked "Needs review" in recent "What's cooking" reports; it has not graduated to `next` or `master`.

Junio C Hamano has now provided a substantive review that engages deeply with the implementation, particularly the `push_creates()` logic in `remote.c`. He raises three specific edge cases for consideration: whether a `--mirror` remote where the local branch tracks a different remote branch would incorrectly suggest push, whether narrow explicit push refspecs that exclude the current branch would falsely trigger the push suggestion, and whether `push.default=nothing` should be explicitly handled alongside `PUSH_DEFAULT_MATCHING`. He also suggests a structural cleanup to move the `push_creates()` call inside `format_missing_upstream()` so the computation is skipped when `advice.statusHints` is disabled. Meanwhile, Harald Nordgren replied to the author's review ping with a bare "v2 looks good to me," which Junio explicitly characterized as a surface-level sign-off that carries limited technical weight for gauging how thoroughly the code was examined.

The patch remains under review with these new technical questions now open. The author has confirmed the patch merges cleanly against both `master` and `seen`, and has offered to send a v3 addressing feedback or to withdraw the patch if the list decides it is not worth keeping. The short-format `[gone]` indicator in `git status -sb` and `git branch -vv` is deliberately preserved for script compatibility, with any change to `[missing]` deferred to a follow-up.
