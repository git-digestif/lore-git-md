This thread is a bugfix from Elia Pinto clarifying the message Git's `status` and `checkout` commands print when a local branch tracks a remote branch that was never created -- for example, after cloning an empty repository. The current wording ("the upstream is gone") is misleading because it suggests the branch was deleted, so the v2 patch rewords it to a neutral "does not exist" and tailors the suggested fix: `git push` is recommended only when it would actually create the missing branch (checked via `@{push}` resolution and explicit `remote.<name>.push` refspecs), and `git branch --unset-upstream` otherwise. The short-format `[gone]` indicator in `git status -sb` and `git branch -vv` is deliberately preserved for script compatibility, with any relabeling deferred to a follow-up.

The patch touches `remote.c` and `t/t6040-tracking-info.sh`, with roughly 120 new test lines covering empty clones, deleted upstreams, various `push.default` settings, explicit push refspecs, and mirror remotes. It is queued in Junio C Hamano's `seen` branch as `ep/status-missing-upstream` and has been listed as "Needs review" in recent "What's cooking" reports. Junio has reviewed it substantively: he confirmed the neutral phrasing covers both the never-created and deleted cases, approved the conditional advice logic, and verified the `[gone]` label is preserved, so his position is effectively an approval pending any final wording tweaks.
