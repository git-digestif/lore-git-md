Elia Pinto has been shepherding a small bugfix that rewords Git's misleading "the upstream is gone" message shown by `status` and `checkout` when a local branch tracks a remote branch that was never created -- for example, after cloning an empty repository. The v2 resubmission changes the wording to a neutral "does not exist" and tailors the suggested fix: `git push` is recommended only when it would actually create the missing branch, otherwise `git branch --unset-upstream` is suggested. The short-format `[gone]` indicator is deliberately preserved so existing scripts keep working.

The patch is queued in `seen` as `ep/status-missing-upstream` and has been marked "Needs review" in recent "What's cooking" reports. Junio C Hamano gave it a substantive review, walking through the problem space and approving the conditional advice logic while confirming the neutral phrasing. After Elia pinged the list asking for final sign-off -- specifically requesting that Harald Nordgren review v2 -- Harald replied that "v2 looks good to me," providing the requested lightweight approval.
