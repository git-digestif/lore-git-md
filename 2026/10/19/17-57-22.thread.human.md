This thread is about a small but long-standing usability bug in Git’s `status` and `checkout` commands. When a local branch tracks a remote branch that was never created (for example, after cloning an empty repository), Git currently emits a misleading message saying “the upstream is gone.” Elia Pinto’s patch rewords this to the neutral “does not exist” and tailors the advice: `git push` is suggested only when it would actually create the missing branch, otherwise `git branch --unset-upstream` is recommended.

The patch has reached a key milestone: Junio C Hamano, the maintainer, has reviewed it substantively and appears satisfied with the technical approach. He confirmed that the neutral phrasing covers both the “never created” and “deleted” cases, probed edge cases around `push.default` configurations, and approved the conditional advice logic. The implementation touches `remote.c` and adds comprehensive tests in `t/t6040-tracking-info.sh`, covering empty clones, deleted upstreams, and various `push.default` edge cases. The `[gone]` indicator in short formats (`git status -sb`, `git branch -vv`) is preserved to avoid breaking scripts, though Junio noted that the translated string could still be tweaked if needed.

Elia originally submitted this as v2 after v1 did not appear in Junio’s integration branches. Harald Nordgren raised a procedural question about whether this was a duplicate of an earlier v2 submission, but Junio’s engagement confirms this is the active version. The patch is now effectively ready for integration, pending any final wording or test adjustments. Given Junio’s positive reaction, it is likely to graduate to `next` soon unless broader testing surfaces new edge cases.
