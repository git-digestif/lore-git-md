This is the cover letter for a seven-patch series introducing the **object storage extension**, a major architectural effort led by Patrick Steinhardt to make Git’s object database pluggable. The series lays the groundwork for alternative object backends by defining a configuration mechanism (`extensions.objectStorage`) modeled after the existing ref storage extension. For now, only the `files` backend is implemented, but it already allows users to relocate the `.git/objects` directory via a payload (e.g., `files://objs` moves objects to `.git/objs`).

The series builds on two prerequisite topics (`ps/odb-files-alternates` and `ps/setup-enforce-repo-passed-to-create-repository-has-no-state`), both of which are already merged into the base commit. The patches touch core subsystems (`odb/`, `setup.c`, `repository.c`) and add new command-line options (`--object-storage-format=` for `git clone` and `git init`), environment variable support (`GIT_OBJECT_STORAGE_FORMAT`), and submodule propagation. Documentation is updated across `git-{clone,init,submodule}.adoc` and new files like `object-storage-format.adoc`. Tests cover initialization, cloning, and submodule scenarios.

The motivation is clear: this is the first step toward pluggable object storage, a long-term goal that would enable backends like cloud storage or databases. The design mirrors the ref storage extension, suggesting a deliberate consistency with existing patterns. The implementation appears thorough, with careful attention to environment variable precedence, submodule handling, and backward compatibility (the default remains `files` with no payload). The series is likely to be a focal point for discussion, particularly around the API design and potential future backends.
