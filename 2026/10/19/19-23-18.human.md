This is a **feature patch** that changes the default behavior of `git status` in triangular workflows. Currently, `git status` only shows how your branch compares to its upstream (where you pull from), ignoring the push destination (where you push to). Harald Nordgren proposes that by default it should show both comparisons—upstream and push—unless they resolve to the same branch, in which case only one is shown (so most users see no change). Users who prefer the old behavior can set `status.compareBranches` to `@{upstream}`.

The patch touches `remote.c` to change the default value of `status.compareBranches` from `@{upstream}` to `@{upstream} @{push}`, updates the documentation to reflect the new default, and adjusts tests to match. The test changes are mechanical: some tests that previously set the config explicitly are simplified, and one test is reordered to reflect the new default.

The motivation is clear: triangular workflows (pull from one remote, push to another) are common, and users often want to know both "am I behind where I pull from?" and "am I ahead of where I push to?" without having to configure anything. The patch is small, well-scoped, and includes tests that verify the new behavior. It looks like a sensible usability improvement that should not break existing workflows.
