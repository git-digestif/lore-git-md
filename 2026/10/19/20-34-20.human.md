This is a bugfix for the files ref backend, now in its third iteration. The patch fixes an inconsistency in how root refs (like `HEAD` or `ORIG_HEAD`) are handled in the loose ref cache. Previously, root refs were only included if the `REFS_FOR_EACH_INCLUDE_ROOT_REFS` flag was passed during the *first* iteration that created the cache; later iterations would include them regardless of the flag, while earlier ones would omit them even if the flag was set. The reftable backend is unaffected.

The solution keeps root refs out of the shared loose ref cache entirely. When an iterator requests root refs, it creates a separate temporary ref cache for them, overlays its iterator on the loose ref iterator, and frees the cache when done. This approach is simple and efficient, since only two call sites actually use the flag, and they do so just once per command. The patch updates `files-backend.c` to implement this logic and adds a test in `t/t6302-for-each-ref-filter.sh` to verify that `--include-root-refs` works correctly with `--merged`.

The v3 iteration drops the documentation corrections that were included in v2, as Patrick Steinhardt suggested splitting them into a separate patch. The core implementation remains unchanged from v1, but the commit message has been expanded to discuss alternatives and clarify the reasoning behind the chosen approach.
