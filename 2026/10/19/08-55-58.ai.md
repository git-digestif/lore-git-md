This is the third patch in Patrick Steinhardt’s seven-patch series introducing the **object storage extension**, a major architectural effort to make Git’s object database pluggable. This patch adds support for overriding the object storage format via the `GIT_OBJECT_STORAGE_FORMAT` environment variable, mirroring the existing behavior for ref storage (`GIT_REF_STORAGE_FORMAT`).

The change is straightforward: it extends the repository setup logic in `setup.c` to check for the environment variable and override the `extensions.objectStorage` configuration if present. The patch also updates documentation (`git.adoc`) to document the new variable and adds a test in `t0001-init.sh` that verifies the override works as expected (e.g., switching from `files://objs` to `files://other` relocates objects) and rejects unknown schemas. The implementation follows Git’s standard precedence rules (config < environment < default) and reuses the existing `odb_source_type_by_uri()` helper for schema validation.

This patch is uncontroversial in isolation—it’s a mechanical extension of an existing pattern—but it’s a key piece of the series’ overall goal. The environment variable is likely to be used in testing and deployment scenarios, so its inclusion here is practical. The test coverage is thorough, covering both happy paths and error cases. No substantive review feedback has appeared yet, but this patch is unlikely to attract much debate given its consistency with the ref storage precedent. The main discussion points for the series will probably center on the broader API design (e.g., how future backends will integrate) rather than this specific feature.
