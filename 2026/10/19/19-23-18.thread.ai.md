Subject: [PATCH] status: default to comparing against both @{upstream} and @{push}
Series version: v1 (initial submission)
Originating author: Harald Nordgren
Thread type: feature patch

Core problem or goal
Make `git status` more useful in triangular workflows (where the push destination differs from the upstream) by defaulting to comparing the current branch against *both* `@{upstream}` and `@{push}` instead of only `@{upstream}`. When the two destinations resolve to the same branch, only one comparison is shown, so most users see no change.

Current status
Under review; no prior versions. Patch touches `remote.c` (appends `@{push}` to the default comparison list), updates `Documentation/config/status.adoc`, and adjusts tests in `t/t6040-tracking-info.sh` and `t/t5505-remote.sh` (mechanical updates to reflect the new default).

Key technical details
- Files: `remote.c`, `Documentation/config/status.adoc`, `t/t6040-tracking-info.sh`, `t/t5505-remote.sh`
- New default: `status.compareBranches` now defaults to `@{upstream},@{push}`
- Backward compatibility: users can restore the old behavior by setting `status.compareBranches` to `@{upstream}`
- No on-disk format changes; no new CLI options; no new symbols
- Test coverage: existing tests updated to match new default
