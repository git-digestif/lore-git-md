This is patch 5/7 in Patrick Steinhardt’s seven-patch series introducing the **object storage extension** (`extensions.objectStorage`). The series aims to make Git’s object database pluggable, and this patch adds user-facing configuration options for the object storage format to `git init` and `git clone`.

The patch introduces the `--object-storage-format=<format>` command-line option for `git init` (and implicitly for `git clone`), mirroring the existing `--ref-storage-format` option. It also adds support for the `GIT_DEFAULT_OBJECT_STORAGE_FORMAT` environment variable and the `init.defaultObjectStorageFormat` configuration key, following Git’s standard precedence rules (command line > environment > config > default). The `files` backend is the default, and the patch includes thorough validation to reject unknown formats.

Tests cover initialization, environment variable overrides, payload handling (e.g., `files://objs` relocates objects to `.git/objs`), and error cases like invalid formats or reinitialization with a different storage format. The patch is well-tested and aligns with the established pattern for ref storage, suggesting it will integrate smoothly. No substantive review feedback has been recorded yet, but the implementation looks solid and uncontroversial. This is a foundational piece of the series, enabling users to configure object storage at repository creation time.
