This thread is a straightforward bugfix for a memory leak in Git’s `imap-send` subsystem, specifically when using the `imap.tunnel` configuration. Harald Nordgren identified the issue: the `child_process` struct used to start an IMAP tunnel is never freed after the tunnel is running, even though only its pipes are needed. The fix is a single line in `imap-send.c` that calls `child_process_clear()` to release the struct’s resources.

The patch is narrow in scope, targeting only the tunneling code path, which isn’t covered by existing tests. While the leak checker missed this because of the lack of test coverage, the fix itself is uncontroversial—it aligns with Git’s standard practice of cleaning up process resources. There’s no expected behavior change for users, just a reduction in memory usage for those using IMAP tunneling. Assuming the second patch in the series doesn’t introduce complications, this one is likely to be accepted as-is. No objections or requests for changes have been raised so far.
