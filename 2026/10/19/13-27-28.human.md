This is a review of Harald Nordgren’s RFC patch that fixes a performance regression in `upload-pack` for shallow fetches over protocol v2. Junio C Hamano identifies a critical flaw in the proposed solution: the patch incorrectly uses `advertise_shallow_grafts()`, a function designed for protocol v0, in a protocol v2 context. In protocol v2, shallow information must be sent via the `packet_writer` API to ensure proper sideband multiplexing, but the patch bypasses this requirement, causing the client to misinterpret the data and fail with a protocol violation.

Junio demonstrates the issue with a new test case in `t/t5702-protocol-v2.sh` that reproduces the failure when `uploadpack.allowsidebandall` is enabled. The test confirms that the patch, as written, breaks protocol v2 compatibility. While the core idea—avoiding redundant history traversal—remains valid, the implementation needs reworking to use the correct API for protocol v2.

The review is substantive and tested, as Junio both explains the technical problem and provides a failing test case. This feedback suggests the patch will require a non-trivial rewrite to address the protocol layer mismatch, making it unlikely to be merged in its current form. The thread is now at a decision point: Harald will need to either revise the approach or abandon it if the fix proves too invasive for the performance gain.
