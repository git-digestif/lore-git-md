This is Junio’s "What’s cooking" report for October 2026 (#07), summarizing the state of Git’s integration branches. Below is a high-level digest of the most notable topics, grouped by their status and significance.

---

### **New Topics (Needs Review)**
These patches are fresh and waiting for community feedback. Most are small, focused fixes or cleanups:

- **ODB lockfile race fix (jt/odb-keep-lockfile-fix)**: A four-patch series from Justin Tobler that defers `.keep` lockfile creation to commit time in the object database, preventing race conditions where concurrent processes could delete each other’s lockfiles. This is a subtle but important correctness fix for the files backend.
- **`the_repository` removal in merge-blobs (oa/merge-blobs-stop-using-the-repository)**: A single patch from Oluwademilade Ajayi that threads repository context through the merge-blobs subsystem, part of the ongoing effort to eliminate global state. Small but well-scoped.
- **Test modernization (ss/t2403-modernize-test-d)**: Siddharth Shrimali replaces a raw `test -d` with `test_path_is_dir` in `t2403-worktree-move.sh`. A minor but welcome cleanup.
- **Sideband config parsing fix (tb/sideband-skip-unrecognized-allow-control-characters)**: Taylor Blau fixes an infinite loop in the sideband configuration parser when encountering unrecognized control character keywords. A small but critical fix for a potential DoS vector.
- **Loose refs cache fix (ak/refs-files-root-refs-cache)**: Andy Koppe prevents root refs (like `HEAD`) from being cached in the loose refs cache, which could cause them to be omitted from subsequent iterators. Another small but important correctness fix.
- **CI update to macOS 15 (jc/ci-update-macos-15)**: Junio updates GitHub CI jobs to use `macos-15` (the new default) instead of the deprecated `macos-14`. A routine maintenance update.

### **Stalled Topics**
These patches have been waiting for author responses or have unresolved issues:

- **OpenBSD runtime prefix (bs/runtime-prefix-obsd-getexecpath)**: Uses OpenBSD 8.0’s `getexecpath(3)` for proper `RUNTIME_PREFIX` resolution. Stalled due to lack of response.
- **HTTP OCSP stapling (gg/http-ssl-verify-status)**: Adds `http.sslVerifyStatus` to check stapled OCSP responses during TLS handshake. CI times out after 6 hours, suggesting a potential performance or deadlock issue.
- **`git last-modified` Bloom filter optimization (tc/last-modified-bloom)**: Uses Bloom filters to speed up `git last-modified` for wildcard pathspecs. Stalled due to unresolved feedback about correctness and edge cases.

### **Cooking in `next` (Likely to Graduate)**
These topics are in `next` and appear ready for `master` unless last-minute issues arise:

- **Pretty format wrap fix (ak/pretty-wrap-fix)**: Fixes a bug where `%w()` lost indentation after a newline. Small but user-visible.
- **Sequencer HEAD ref safety (ak/sequencer-head-refdup)**: Prevents the sequencer from clobbering the HEAD ref name during worktree lookups. A subtle but important correctness fix.
- **Coverity overflow fixes (js/coverity-overflow-fixes)**: A five-patch series from Jonathan Simons fixing integer overflows in date parsing, wrapper functions, and archive code. Includes new compile-time overflow detection macros.
- **Pack check bigfile threshold fix (ps/pack-check-bigfile-threshold)**: Patrick Steinhardt fixes a boundary condition in `git fsck` where objects exactly matching `core.bigFileThreshold` were incorrectly flagged as corrupt.
- **Fast-import OID resolution (mb/fast-import-reference-pending)**: Michael Blume allows `git fast-import`’s `from` command to reference newly created commits and tags by OID, fixing a crash. A small but important usability fix.
- **Incremental commit-graph writes (kk/fetch-write-commit-graph-incremental)**: Kristoffer Haugsbakk optimizes `fetch.writeCommitGraph` to update the commit-graph incrementally using only newly fetched commits, drastically reducing post-fetch update times.
- **Blame ignore-revs by default (rm/blame-default-ignore-revs)**: René Scharfe makes `git blame` and `git annotate` automatically use `.git-blame-ignore-revs` as the default ignore list if it exists. A user-friendly change with minimal risk.
- **Delta-islands pluralization (oa/delta-islands-i18n-use-q)**: Oluwademilade Ajayi fixes a translation issue in delta-islands progress messages by using `Q_()` for plural forms.
- **GPG test flakiness fix (hn/t7004-flaky-gpg-test-fix)**: SZEDER Gábor works around a flaky `rm` failure in `t7004` by pointing `GNUPGHOME` to an unused directory instead of deleting the active one.
- **CI housekeeping (ps/ci-housekeeping-and-modernizations)**: Patrick Steinhardt modernizes Git’s CI jobs, dropping Python 2 support, updating OS images, and improving reftable test coverage. A large but uncontroversial cleanup.
- **ODB alternates refactoring (ps/odb-files-alternates)**: A 13-patch series from Patrick Steinhardt that moves alternates handling into the files backend, improving performance and simplifying the API. This is a significant architectural cleanup with no behavior changes.
- **Packfile delta base cache fix (ps/packfile-stale-delta-base-cache-fix)**: Fixes a corruption bug where closing a packfile didn’t evict its entries from the delta base cache, leading to stale entries being reused. A critical correctness fix.
- **`git history` signing (ss/history-sign-rewrites)**: Siddharth Shrimali teaches `git history` to sign rewritten commits and their descendants, ensuring cryptographic integrity. A small but important feature for security-conscious workflows.
- **Packed-refs verbatim write (kn/packed-refs-verbatim-write)**: Karthik Nayak optimizes packed-refs rewrites by using `fwrite()` for unmodified records, avoiding redundant `fprintf()` calls. A small performance win.
- **Repository initialization safety (ps/setup-enforce-repo-passed-to-create-repository-has-no-state)**: Patrick Steinhardt enforces that the repository object passed to `create_repository()` is stateless, preventing subtle bugs in `git clone` and `git init`. A foundational cleanup.
- **Rerere lock contention fix (tb/rerere-wait-for-merge-rr-lock)**: Taylor Blau makes `git rerere` wait for the `MERGE_RR.lock` instead of failing immediately, improving usability in concurrent workflows.

### **Notable Topics Under Active Discussion**
These patches are generating discussion or need further refinement:

- **Incremental connectivity check (kk/connectivity-check-incremental)**: Kristoffer Haugsbakk proposes an incremental mode for connectivity checks during fetches, which could significantly improve performance for large repositories. The series is awaiting a reroll to address feedback about edge cases.
- **Worktree repair fixes (yn/worktree-repair-fix)**: Yuchen Ning fixes several edge cases in `git worktree repair`, including a bug where it could corrupt unrelated `.git` files. The series is well-motivated but needs review.
- **Refspec matching speedup (js/push-refspec-match-speedup)**: Jonathan Simons optimizes `git push` refspec matching by replacing linear traversals with string maps, improving performance for large refspecs. The series is large (12 patches) and needs thorough review.
- **Merge conflict labels (pw/checkout-m-conflict-labels)**: Phillip Wood teaches `git checkout -m` to remember and restore original conflict labels (e.g., branch names) from `.git/MERGE_LABELS`. A user-friendly improvement that’s close to merging.
- **Fetch refmap (hn/fetch-refmap)**: Hariom Verma changes the default refspec for remotes added in shallow repositories to rely on `remote.<name>.refmap`, pulling only tracked branches. This is a significant behavior change that needs careful review.
- **Rust crate reorganization (mh/rust-crate-subdir)**: Mike Hommey moves Rust code into a dedicated `rust/` subdirectory to avoid confusing Cargo. This is a prerequisite for further Rust integration and is uncontroversial but needs review.
