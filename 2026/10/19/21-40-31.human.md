This is a **substantive review** of the fourth patch in Patrick Steinhardt’s seven-patch series introducing the object storage extension. The patch adds inspection tools for the object storage format (`` `git rev-parse --show-object-storage-format` `` and `` `git repo objects.storageFormat` ``), mirroring the existing ref storage inspection commands.

Karthik Nayak’s review focuses on two design-level concerns. First, he notes that the naming inconsistency between `object.format` (singular) and `objects.storageFormat` (plural) in `` `git repo` ``’s output is subtle and could confuse users, though he acknowledges there’s no obvious fix. Second, and more significantly, he questions why the default object storage format (`files`) is hard-coded in both the `` `git repo` `` and `` `git rev-parse` `` implementations rather than being derived from the repository’s configuration or the ODB subsystem. This exposes implementation details outside their intended scope and could lead to inconsistencies if the default backend changes in the future. The feedback is technical and actionable, suggesting the patch may need revision to centralize the default value within the repository or ODB layer.

The review is narrowly scoped to this patch and does not address the broader series, but the concerns raised are valid and likely to be addressed before the patch is merged. No other objections or conditional approvals are present in the thread so far. This is a well-crafted, uncontroversial addition to the series, but Karthik’s points highlight a minor but important design refinement.
