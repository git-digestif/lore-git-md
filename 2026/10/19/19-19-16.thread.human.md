This thread is a targeted bugfix series for `git imap-send`, addressing two key interoperability issues: non-canonical email header order (e.g., `Subject` before `Date`) and case-insensitive header parsing, along with a tunnel-command memory leak. The four-patch series (`v3`) by Harald Nordgren, submitted via GitGitGadget, is nearly complete. The first patch (tunnel process lifecycle fix) was merged to `next` on June 10, while the remaining three—order-agnostic header parsing, removal of a `git-send-email` special case, and case-insensitive header matching—are ready for integration, with only minor documentation or test-coverage nits outstanding.

The core problem is that `git imap-send` previously failed to handle RFC 5322-compliant emails where headers like `Subject` appear before `Date` or use mixed case (e.g., `FROM:`). This broke interoperability with tools like `b4`, which generate such headers. The series fixes this by making the header-parsing logic order- and case-agnostic, while also plugging a memory leak in the tunnel-command process management. The changes are minimal and focused, with test coverage confirming backward compatibility.

The only open discussion revolves around the already-merged Patch 1/4, where Patrick Steinhardt suggested minor defensive coding improvements (e.g., making `imap->tunnel` a pointer to avoid edge cases with `finish_command()`). Harald has agreed to these tweaks, which may result in a follow-up patch but won’t block the series. The remaining patches are uncontroversial, with Patrick’s feedback on Patch 3/4 (removal of the `git-send-email` special case) highlighting a theoretical backward-compatibility edge case—though no practical issues are expected. Junio has not yet weighed in on Patches 2–4/4, but they are likely to graduate to `next` soon. The series is on track for `master` once these final details are resolved.
