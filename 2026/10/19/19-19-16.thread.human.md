This thread is about a bugfix series for `git imap-send` that addresses interoperability issues with tools like `b4` by making the header-parsing logic more flexible. The series, now at version 3 (`v3`), fixes a long-standing problem where `git imap-send` fails when processing patches with the `Subject` header before the `Date` header—a valid but non-canonical order. Harald Nordgren is the author, and the series has evolved through feedback from Junio C Hamano and Patrick Steinhardt.

The latest version (`v3`) splits the original two-patch series into four focused commits, each addressing a specific concern. The key improvements include fixing the tunnel process lifecycle (ensuring the tunnel command is properly reaped), removing a special-case logic for `git send-email` copies, and enforcing case-insensitive header name matching for RFC 5322 compliance. All previously open technical questions—such as the tunnel process lifecycle, the removal of the `git-send-email` special case, and test suite prerequisite handling—have been resolved or clarified. The series is now well-structured, with clear commit messages and thorough test coverage, making it easier to review and integrate.

Patrick Steinhardt’s feedback has been instrumental in shaping the series, particularly in addressing the tunnel process lifecycle and isolating the removal of the `git-send-email` special case into its own patch. Junio’s earlier review validated the design and flagged the case-sensitivity issue, which has since been fixed.
