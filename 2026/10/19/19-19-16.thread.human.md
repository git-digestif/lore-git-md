This thread is a four-patch bugfix series for `git imap-send`, authored by Harald Nordgren, that addresses interoperability issues with tools like `b4` by making email header parsing more flexible. The series fixes three key problems: (1) a tunnel-command memory leak and process lifecycle issue (already merged to `next`), (2) rigid header order requirements (Subject must not precede Date), (3) a special-case exemption for `git send-email` messages, and (4) case-sensitive header matching that violates RFC 5322.

The first patch, which fixed the tunnel process management, was merged to `next` on June 10, 2025. The second patch, making header order agnostic, is ready for integration. The third patch, removing the `git-send-email` special case, is under review and uncontroversial, with tests confirming backward compatibility. The fourth and final patch, just posted, makes header name matching case-insensitive (e.g., accepting `FROM:` or `date:`), aligning with RFC 5322. This change is minimal and mechanical, touching only three lines in the existing `has_required_headers()` helper.

Junio C Hamano and Patrick Steinhardt have reviewed earlier versions, raising technical questions that Harald addressed by splitting the series into focused patches. Junio flagged case sensitivity as a correctness concern, which this final patch resolves. The series is now structurally complete, with each patch addressing a distinct issue, and is queued in `seen`. No open questions remain, and the changes are expected to be merged once the preceding patches are integrated. The goal—ensuring `git imap-send` works reliably with `b4` and other tools—is fully met.
