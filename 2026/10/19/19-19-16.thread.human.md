This thread is a straightforward bugfix for `git imap-send`. Harald Nordgren identified a real-world interoperability issue: `git imap-send` fails when processing patches where the `Subject` header appears before the `Date` header, a valid but non-canonical order produced by tools like `b4` (used to fetch patches from lore.kernel.org). The two-patch series fixes the header-parsing logic to accept either order and plugs a minor memory leak in the tunnel-command handling.

The first patch is a small cleanup that frees the tunnel command string after use, preventing a leak detectable by valgrind. The second patch is the main fix, rewriting the header-parsing loop in `imap-send.c` to scan all headers first, then process them in the required order (`Date` before `Subject`), rather than assuming a fixed sequence. The series touches only `imap-send.c` and adds a new test in `t/t9001-send-email.sh` to verify the fix by sending a patch with `Subject` before `Date` and confirming it is accepted.

The problem is well-motivated, the solution is minimal and straightforward, and the test coverage is thorough. There’s no evident controversy; this should be an uncontroversial fix. The series is ready for review and should be a quick merge once any feedback is addressed.
