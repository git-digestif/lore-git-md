This thread is about a four-patch bugfix series for `git imap-send`, now in its fourth iteration (`v4`), authored by Harald Nordgren. The series addresses two main problems: (1) `git imap-send` fails when processing patches with non-canonical email header order (e.g., `Subject` before `Date`) or mixed-case header names (e.g., `FROM:`), breaking interoperability with tools like `b4`, and (2) a tunnel-command lifecycle issue that could leak memory. The series also removes a special-case exemption for `git-send-email` messages, which previously ignored `Subject` headers for messages starting with `From git-send-email`.

The latest version (`v4`) resolves all prior feedback. Patch 1/4, which fixes the tunnel process lifecycle, was previously merged to `next` but has been revised to address Patrick Steinhardt’s concerns about defensive coding by converting `imap->tunnel` to an allocated pointer. Patch 3/4, which removes the `git-send-email` special case, now includes an expanded commit message justifying the backward-compatibility implications, citing RFC 5322’s `SHOULD` for `Subject`. Patch 4/4 adds a test verifying case-insensitive header matching with lowercase headers, addressing a minor gap noted by Patrick. The remaining patches (2/4 and 4/4) are uncontroversial and ready for integration. The series is queued in `seen` and likely to graduate to `next` soon.

Key participants include Harald Nordgren (author), who addressed all feedback in `v4`, Junio C Hamano (maintainer), who merged Patch 1/4 to `next` and is expected to integrate the remaining patches, and Patrick Steinhardt, who provided substantive reviews highlighting defensive coding and documentation gaps, all of which have now been resolved. The changes are minimal, focused, and thoroughly tested, ensuring backward compatibility while aligning with RFC 5322 compliance. No open technical concerns remain, and the series should proceed smoothly to `master`.
