This thread is a two-patch bugfix series for `git imap-send`, authored by Harald Nordgren, that ensures compatibility with tools like `b4` which generate patches with `Subject` headers before `Date` headers—a valid but non-canonical order. The series also fixes a minor memory leak in tunnel-command handling.

The core issue is that `git imap-send` previously failed when processing patches with this header order, breaking interoperability with `b4` and similar tools. The fix rewrites the header-parsing logic in `imap-send.c` to accept the three required headers (`From`, `Date`, `Subject`) in any order and with case-insensitive names, as required by RFC 5322. The second patch in the series, which just arrived, implements this change using `istarts_with()` for case-insensitive matching and removes a now-redundant workaround for `git send-email --imap-sent-folder`. The first patch plugs a memory leak in tunnel-command handling.

The series is now complete and ready for integration. Junio Hamano reviewed the initial version (`v1`), validating the design (cursor logic, order-agnostic parsing) and flagging the case-sensitivity issue as a correctness concern. Harald incorporated this feedback in `v2`, and the series has no remaining open questions. The test coverage includes a new test for `b4`-style patches and regression checks for the `--imap-sent-folder` workflow. The changes are minimal, well-motivated, and uncontroversial, touching only `imap-send.c` and the test suite.
