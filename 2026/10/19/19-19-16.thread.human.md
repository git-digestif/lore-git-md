This thread is a straightforward bugfix series for `git imap-send`, addressing a real-world interoperability issue with tools like `b4` that fetch patches from lore.kernel.org. The problem is simple: `git imap-send` currently fails when processing patches where the `Subject` header appears before the `Date` header, a valid but non-canonical order. Harald Nordgren’s two-patch series fixes this by rewriting the header-parsing logic in `imap-send.c` to accept headers in any order, rather than requiring a fixed sequence.

The first patch is a minor cleanup that plugs a memory leak in tunnel-command handling, while the second patch is the core fix. The new logic scans all headers first, checks for the presence of `From`, `Date`, and `Subject` regardless of order, and removes a now-redundant special-case workaround for `git send-email --imap-sent-folder`. The series includes a new test in `t/t9001-send-email.sh` to verify the fix and ensure no regressions in existing workflows.

So far, the series has not attracted any review comments or objections, and it appears uncontroversial. The problem is well-motivated (interoperability with `b4`/`lore`), the solution is minimal and backward-compatible, and the test coverage is thorough.
