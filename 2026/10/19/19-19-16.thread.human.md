This thread is about a two-patch bugfix series for `git imap-send`, authored by Harald Nordgren, which addresses an interoperability issue with tools like `b4` that emit patches with non-canonical email header order (e.g., `Subject` before `Date`). The series also fixes a minor memory leak in tunnel-command handling. The first patch is a cleanup, while the second rewrites the header-parsing logic in `imap-send.c` to accept headers in any order, removing a redundant workaround for `git send-email --imap-sent-folder`.

The series is under review and has been well-received so far, with thorough test coverage added to `t/t9001-send-email.sh` to verify the fix and prevent regressions. However, Junio C Hamano recently identified a substantive issue in the second patch: the new `has_required_headers()` helper uses case-sensitive string matching (`starts_with()`), while RFC 5322 requires header names to be treated as case-insensitive. This will need to be fixed before merging, but the overall design and test coverage remain uncontroversial. No other objections or requests for changes have been raised yet. The series is minimal, well-motivated, and ready for review once the case-sensitivity issue is addressed.
