This is the second patch in Patrick Steinhardt’s seven-patch series introducing the **object storage extension** (`extensions.objectStorage`), a foundational step toward pluggable object database backends in Git. This patch implements the core configuration mechanism, allowing users to specify an object storage backend via a URI-style format (`<schema>[://<payload>]`), modeled after the existing ref storage extension.

The patch adds the `extensions.objectStorage` config key, which is parsed during repository setup and stored in the `repository` struct. For now, only the `files` backend is supported, but the infrastructure is designed to be extensible. The `files` backend can optionally take a payload to relocate the `.git/objects` directory (e.g., `files://objs` moves objects to `.git/objs`). The patch updates `setup.c` to handle the new extension, adds documentation in `extensions.adoc` and a new `object-storage-format.adoc`, and introduces helper functions in `odb/source.c` to parse URIs and instantiate the appropriate backend. Tests in `t0001-init.sh` verify that the extension works with the `files` backend and rejects unknown schemas.

The implementation is clean and follows established patterns (e.g., mirroring `extensions.refStorage`), with careful attention to environment variable precedence and error handling. The patch is uncontroversial in isolation but is part of a larger architectural effort; future discussion is likely to focus on API design and how new backends will integrate. No substantive review feedback has been recorded yet. Key symbols introduced include `repo_set_object_storage_format()`, `odb_source_type_by_uri()`, and the `object_storage_format` field in `struct repository`.
