Thread identity: bugfix patch series (single patch) addressing a correctness issue in Git's skipping negotiator during fetch negotiation. Originating author: Taylor Blau. Thread type: bugfix.

Core problem or goal: fix a subtle ordering bug in the skipping negotiator's queue management where parent commits were added to the queue before their date fields were parsed, causing recent common ancestors to be incorrectly prioritized behind older ref tips. This could lead to premature termination of negotiation without discovering the most recent common commit.

Current status: initial patch posted; under review with consensus forming around a broader refactoring. Junio C Hamano has endorsed Patrick Steinhardt’s proposal to move commit parsing from `push_parent()` to `rev_list_push()` to cover all callsites, align with the default negotiator, and eliminate a redundant `repo_parse_commit()` call in `get_rev()`. The original targeted fix is likely to be superseded by this more comprehensive change.

Key technical details:
- Files touched: `negotiator/skipping.c` (main fix and refactoring), `t/t5552-skipping-fetch-negotiator.sh` (new test case).
- Subsystem: fetch negotiation machinery, specifically the skipping negotiator.
- New behavior: parent commits are parsed (and thus have their correct date set) before being added to the queue, ensuring proper prioritization by date.
- Refactoring impact: moving commit parsing to `rev_list_push()` will cover all callsites, align the skipping negotiator with the default negotiator, and allow removal of the existing `repo_parse_commit()` call in `get_rev()`.
- Test coverage: new test case creates a scenario with 32 old ref tips and verifies that the two most recent commits (HEAD and its grandparent) are offered in the first two "have" lines during negotiation.

Open questions and loose ends:
- Implementation of the agreed refactoring (moving commit parsing to `rev_list_push()`) remains to be done.
- Minor test script nit noted by Patrick Steinhardt (`sed -n "1,2p"` could be `head -n2`) is still open.
