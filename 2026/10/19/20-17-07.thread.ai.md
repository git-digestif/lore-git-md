Thread identity: bugfix patch series (single patch) addressing a correctness issue in Git's skipping negotiator during fetch negotiation. Originating author: Taylor Blau. Thread type: bugfix.

Core problem or goal: fix a subtle ordering bug in the skipping negotiator's queue management where parent commits were added to the queue before their date fields were parsed, causing recent common ancestors to be incorrectly prioritized behind older ref tips. This could lead to premature termination of negotiation without discovering the most recent common commit.

Current status: patch v2 posted and ready for integration. The patch implements the agreed refactoring to move commit parsing from `push_parent()` to `rev_list_push()`, ensuring all commits are parsed (and thus have their correct date set) before being added to the queue. This broader change supersedes the original targeted fix, covers all callsites, aligns the skipping negotiator with the default negotiator, eliminates a redundant `repo_parse_commit()` call in `get_rev()`, and includes a NULL-return check in `push_parent()` as required by the skipping negotiator's `rev_list_push()` signature. No open questions remain.

Key technical details:
- Files touched: `negotiator/skipping.c` (refactoring to move commit parsing to `rev_list_push()`, adding NULL check in `push_parent()`), `t/t5552-skipping-fetch-negotiator.sh` (test case updated to use `head -n2` instead of `sed -n "1,2p"` for robustness).
- Subsystem: fetch negotiation machinery, specifically the skipping negotiator.
- New behavior: all commits are parsed (and thus have their correct date set) before being added to the queue, ensuring proper prioritization by date across all callsites.
- Refactoring impact: the change guarantees that the commit queue contains only parsed commits, simplifying the code and removing a potential source of future bugs. The redundant `repo_parse_commit()` call in `get_rev()` is now removed. The NULL-return check in `push_parent()` handles the skipping negotiator's `rev_list_push()` signature requirement.
- Test coverage: test case creates 32 old ref tips to demonstrate the bug and verifies that the two most recent commits (HEAD and its grandparent) are offered in the first two "have" lines during negotiation, confirming correct prioritization by date.
