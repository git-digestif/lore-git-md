This is a **build system** patch addressing a Rust integration issue in Git's Makefile. Patrick Steinhardt reviews Andy Koppe's fix for a build failure that occurs when users have a custom Cargo target directory (via `~/.cargo/config.toml` or `CARGO_TARGET_DIR`). The patch explicitly sets `--target-dir target` for Cargo commands in the Makefile, ensuring the `gitcore` library is found during linking—aligning with the existing Meson build behavior.

The review is **substantive and tested**: Patrick confirms the issue is real and the fix is correct, though he notes a minor stylistic preference (using `--target-dir=target` instead of `--target-dir target`) that he does not consider worth a reroll. The patch is minimal (two lines), narrowly scoped to the Rust build rules, and uncontroversial. No test coverage is mentioned, but this is a build-system fix rather than user-facing behavior.

Key technical details for follow-up: the `--target-dir` flag, the `RUST_LIB` and `RUST_MEMBER_LIBS` targets, and the `CARGO_ARGS` variable. The patch does not touch `contrib/libgit-{sys,rs}` targets, as their output location is not critical. Patrick also hints at a potential future discussion about merging the `contrib` Rust libraries into the main `gitcore` library, but this is unrelated to the current fix.

This patch is ready for integration and should resolve the build failure for users with custom Cargo configurations. No further changes are expected.
