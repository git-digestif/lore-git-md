This is the fourth patch in Patrick Steinhardt’s seven-part series introducing the **object storage extension**, a major architectural change to make Git’s object database pluggable. This patch adds user-facing ways to inspect the object storage format of a repository, mirroring the existing functionality for ref storage.

The patch exposes the object storage format through two commands: `` `git rev-parse --show-object-storage-format` `` (a new option) and `` `git repo` `` (via the new `objects.storageFormat` field). These additions are straightforward and consistent with the project’s existing patterns. The implementation is clean, touching only the necessary files (`builtin/repo.c`, `builtin/rev-parse.c`, and documentation) and adding minimal new code. Tests verify that the output matches the configured format, including the default `files` backend.

This is a small but necessary piece of the larger series. It doesn’t introduce new behavior or backends but ensures users and scripts can query the object storage configuration, which will be important as alternative backends are added. The patch is uncontroversial and well-motivated, fitting neatly into the series’ goal of making the object database extensible. If the broader series gains traction, this patch will be a routine but essential part of it.
