This is a **substantive review** of the second patch in Beat Bolli’s v3 series for `git imap-send`, which replaces Git’s manual TLS hostname verification with OpenSSL’s `SSL_set1_host()`. Patrick Steinhardt raises two technical concerns that engage deeply with the patch’s correctness and design:

1. **Diff readability**: The patch’s diff is hard to follow because it simultaneously introduces a new `verify_peer()` function and changes its semantics. Patrick suggests splitting the patch into two: a preparatory refactoring to move code into `verify_peer()` without changing behavior, followed by a second patch to modify the logic. This is a **structural critique** that targets the patch’s reviewability rather than its correctness, but it’s a common and reasonable request for complex changes.

2. **Behavioral regression**: The patch adds a call to `verify_peer()` when `SSL_connect()` fails under `SSL_VERIFY_PEER`, which was not present in the original code. Patrick questions the necessity of this change, noting that it introduces new behavior (verifying a certificate after a failed connection) that wasn’t there before. This is a **substantive correctness concern**—the new logic may be redundant or misleading, as `SSL_connect()` already fails on verification errors under `SSL_VERIFY_PEER`, making the `verify_peer()` call unreachable in practice.

The review does not address the **security regression** (certificate stripping) or the **error reporting regression** (loss of hostname-specific error messages) identified in earlier feedback, but it adds a new layer of scrutiny to the patch’s design. The behavioral regression is particularly important because it suggests the patch may be introducing dead code or unnecessary complexity.

If you’re tracking this series, this review is worth noting—it highlights a design flaw that could lead to confusion or maintenance burden. The patch is already blocked by more critical issues (the security regression and lack of test coverage), but Patrick’s feedback adds another reason to revisit the implementation.
