This is the cover letter for a seven-patch series introducing the **object storage extension** to Git, a major architectural effort led by Patrick Steinhardt. The series lays the groundwork for pluggable object database (ODB) backends by mirroring the design of the existing ref storage extension: users can configure the backend via `extensions.objectStorage`, environment variables, or command-line flags like `--object-storage-format=`. Currently, only the traditional "files" backend is supported, but the payload syntax already allows relocating the `.git/objects` directory (e.g., `files://objs` would store objects in `.git/objs`).

The series builds on two prerequisite topics (`ps/odb-files-alternates` and a long-named setup series) that have already been merged into Patrick’s integration branch. The patches touch core subsystems—setup, repository initialization, clone, submodule, and loose object handling—adding new config keys (`init.defaultObjectStorageFormat`), command-line options (`--object-storage-format=`), and environment variable support (`GIT_OBJECT_STORAGE_FORMAT`). Tests are thorough, covering init, clone, submodule propagation, and rev-parse introspection.

This is the first step in Patrick’s long-running ODB abstraction effort, which aims to make Git’s object storage layer modular. While the immediate user impact is minimal (only the "files" backend exists), the infrastructure is now in place for future backends. The series is well-scoped, clearly motivated, and includes comprehensive documentation and test coverage—it looks like a serious, well-crafted contribution that will likely land in `next` soon.
