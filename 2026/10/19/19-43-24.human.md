This is a build system patch addressing Rust integration in Git. Andy Koppe replies to Junio C Hamano’s suggestion about how to implement a fix for a Makefile bug that causes build failures when users have a custom Cargo target directory. The patch itself is uncontroversial—Patrick Steinhardt already confirmed the issue and the fix—but the discussion now centers on the best way to apply the change.

Andy argues that modifying `CARGO_ARGS` once (as Junio suggested) could be problematic because `CARGO_ARGS` is meant for user-overridable build preferences, while the target directory is a hard requirement for linking. He proposes `override CARGO_ARGS += --target-dir target` as a possible alternative but notes it could create confusion if later modifications to `CARGO_ARGS` don’t use `override`. He also mentions a stalled in-flight topic (`mh/rust-crate-subdir`) that touches the same lines, suggesting coordination might be needed if that series moves forward.

The patch is small and well-motivated, but the implementation choice now hinges on maintainability and future-proofing. No reroll is posted yet, and the thread remains open for further input on the best approach. If you care about Rust integration or Makefile hygiene, this is worth following.
