This is the fifth patch in Patrick Steinhardt’s seven-patch series introducing the **object storage extension**, a foundational step toward pluggable object database backends in Git. This patch adds user-facing controls for the object storage format to `git init` and `git clone`, mirroring the existing ref storage extension’s interface.

The patch introduces the `--object-storage-format=<format>` command-line option for both commands, along with support for the `GIT_DEFAULT_OBJECT_STORAGE_FORMAT` environment variable and the `init.defaultObjectStorageFormat` configuration key. The precedence rules follow Git’s standard pattern: command-line overrides environment, which overrides config, which overrides the default (`files`). The implementation is careful to avoid writing the extension when the format is the default (`files` with no payload), preserving backward compatibility.

Tests cover initialization, schema validation, environment variable precedence, and reinitialization edge cases. The patch is uncontroversial in isolation—it simply exposes the configuration mechanism defined in earlier patches—but it is a critical piece of the larger effort to make Git’s object storage pluggable. The thorough test coverage and clear documentation suggest this is a well-prepared step in the series.
