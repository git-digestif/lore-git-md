This thread is about a bugfix for Git's skipping negotiator, which had a subtle ordering bug causing recent common ancestors to be incorrectly prioritized during fetch negotiation. Taylor Blau originally posted a single-patch fix that ensures parent commits are parsed before being added to the queue, preventing premature negotiation termination.

The discussion has now settled on a broader architectural change. Patrick Steinhardt suggested moving commit parsing from `push_parent()` to `rev_list_push()` to cover all callsites and align with the default negotiator, a proposal Junio C Hamano has endorsed. This refactoring would also allow removing a redundant commit-parsing call elsewhere in the code. The patch touches `negotiator/skipping.c` and includes a new test case in `t/t5552-skipping-fetch-negotiator.sh`. With the maintainer's agreement on the design direction, the next step is likely implementing this more comprehensive fix. No objections remain, and the original motivation—correcting the queue prioritization—remains valid.
