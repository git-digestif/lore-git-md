This thread began as a bugfix for a subtle ordering issue in Git’s skipping negotiator, where commits were incorrectly prioritized during fetch negotiation due to parent commits being added to the queue before their date fields were parsed. Taylor Blau’s patch v2 refactored the code to parse commits before queueing them, fixing the immediate bug and aligning the skipping negotiator with the default negotiator’s behavior. The patch was merged to `master`, and the test case was updated for robustness.

During review, a latent edge-case bug was identified: `rev_list_push()` marks commits as `SEEN` before parsing succeeds, which can trigger a `BUG()` if an unparsable commit is revisited. This issue exists in both the skipping and default negotiators, making it a broader problem in the negotiation machinery. Junio C Hamano pushed back on replicating this pattern in new code, advocating instead for a hybrid approach—avoiding the mistake in future work while documenting the discrepancy as `#leftoverbits`. Taylor Blau agreed, clarifying that his original intent was consistency with the "battle-tested" default negotiator, not deliberate breakage. He proposed either the hybrid approach or a broader fix addressing both negotiators but deferred to Junio’s preference. No follow-up patch has been proposed, and the thread is now closed with the latent bug unresolved but recognized as a deferred `#leftoverbits` item. The discussion serves as design-level guidance for future work on the negotiation machinery.
