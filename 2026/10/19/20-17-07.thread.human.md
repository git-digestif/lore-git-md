This thread is about a bugfix patch from Taylor Blau that corrects a subtle ordering bug in Git's skipping negotiator during fetch negotiation. The issue causes parent commits to be added to the negotiation queue before their date fields are parsed, leading to incorrect prioritization of recent common ancestors behind older ref tips. The patch touches `negotiator/skipping.c` and adds a test case in `t/t5552-skipping-fetch-negotiator.sh`.

Patrick Steinhardt has reviewed the patch and raised a substantive design question: why the commit parsing is done in `push_parent()` rather than `rev_list_push()`, which would cover all callsites and align the skipping negotiator with the default negotiator. This refactoring could simplify the code by removing an existing `repo_parse_commit()` call in `get_rev()`. The review is technical and focuses on improving the architectural consistency of the fix, though it doesn’t include testing or benchmarking. The thread is now awaiting Taylor’s response to this design suggestion. No other reviews or decisions have been made yet.
