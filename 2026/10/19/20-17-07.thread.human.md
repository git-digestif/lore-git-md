This thread began as a bugfix for a subtle ordering issue in Git’s skipping negotiator, where parent commits were added to the negotiation queue before their date fields were parsed, leading to incorrect prioritization. Taylor Blau’s patch v2 refactored the code to parse commits before queueing them, fixing the immediate bug and aligning the skipping negotiator with the default negotiator’s behavior. That patch was merged to `master`.

The discussion later uncovered a latent edge-case bug in the broader negotiation machinery: `rev_list_push()` marks commits as `SEEN` before parsing succeeds, which can trigger a `BUG()` if an unparsable commit is revisited. This issue exists in both the skipping and default negotiators, suggesting it’s a systemic pattern rather than an isolated flaw. While the merged patch didn’t address this latent bug, Junio C Hamano’s recent follow-up pushes back on the justification that "existing code does it too." He advocates for avoiding the mistake in new code (e.g., by deferring the `SEEN` flag until after parsing in the skipping negotiator) while documenting the discrepancy and deferring a broader fix as `#leftoverbits`. No new patch has been proposed, and the thread remains closed unless someone picks up the deferred work. The key takeaway is that the latent bug is now recognized as a broader architectural issue, but it’s not blocking the merged fix.
