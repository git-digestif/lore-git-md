This is the **second patch in a v2 documentation series** replacing Git’s outdated `gittutorial` man page with a new beginner-focused guide. The patch introduces the full content of the new tutorial, which is split into two parts: local repository creation and commits (Steps 1–7), and pushing to a remote host like GitHub or GitLab (Steps 8–14). The tutorial is based on user testing with 112 participants and incorporates feedback from v1, including expanded explanations of `git status` output, a troubleshooting section for common issues (e.g., SSH host verification), and platform-specific clarifications.

The new tutorial makes deliberate pedagogical choices: it starts with `git init` (to avoid forge-specific confusion), uses SSH for authentication (with security disclaimers), and omits branching/collaboration to keep the scope manageable. Key commands covered include `git init`, `git add`, `git commit`, `git status`, `git diff`, `git restore`, and `git push`. The tutorial also addresses accessibility (e.g., `+`/`-` sigils in `git diff` for colorblind users) and simplifies setup (e.g., `git config --global init.defaultBranch main` to avoid `master`/`main` conflicts).

The patch is **documentation-only**, touching only `Documentation/gittutorial.adoc`. While the tutorial is well-tested and addresses real user pain points, two open questions remain: whether to start with `git init` or `git clone`, and how to handle authentication generically without tying instructions to specific forges. The author frames the tutorial as "good enough" for merging, with plans for post-merge improvements based on user feedback. Given its focus on documentation and user-tested design, this patch is a strong candidate for `next`.
