## 2026/10/19

## 2026/10/20

- [2026/10/20/07-29-24 by Elia Pinto <gitter.spiros@gmail.com>] Elia Pinto agrees that "missing" sounds good for the short bracketed form but prefers to keep it out of this patch.
- [2026/10/20/07-29-24 by Elia Pinto <gitter.spiros@gmail.com>] Pinto answers that the "git push" hint is not unconditional: it is given only when @{push} resolves to the upstream itself and push.default is not "matching", and notes the check errs toward not giving the hint (e.g., with push.default=matching plus an explicit remote push refspec, the hint is withheld even though "git push" would create the upstream); he plans to fix this in v2 by checking push.default only when the remote has no push refspec and is not a mirror.
- [2026/10/20/07-29-24 by Elia Pinto <gitter.spiros@gmail.com>] Pinto corrects the log message's justification about which commands emit a translated "gone": "git status -sb" uses the translated label, "git status --porcelain -b" always prints "[gone]" due to no_gettext, "git status --porcelain=v2" never prints "gone", "%(upstream:track)" in for-each-ref uses the documented untranslated "gone", and "git branch -vv" shows the translated label; therefore "scripts may depend on it" holds only for --porcelain and for-each-ref.
- [2026/10/20/07-29-24 by Elia Pinto <gitter.spiros@gmail.com>] Pinto remains hesitant to change the bracketed label in "git branch -vv" in this patch because under LC_ALL=C it says "gone" and "git branch -vv | grep ': gone]'" is a common recipe, and keeping porcelain output as "gone" while changing human output would require wt_shortstatus_print_tracking() to stop using a single LABEL() msgid; for v2 he plans to leave the bracketed label alone and correct the log message, treating any "[missing]" change for "git status -sb" and "git branch -vv" as a separate follow-up patch.
