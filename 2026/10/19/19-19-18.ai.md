This is the second patch in a two-patch bugfix series for `git imap-send`. The series addresses a real interoperability issue: `git imap-send` currently fails when processing patches where the `Subject` header precedes the `Date` header, a valid but non-canonical order produced by tools like `b4` (used to fetch patches from lore.kernel.org). This patch is the core fix, rewriting the header-parsing logic in `imap-send.c` to accept headers in any order rather than requiring a fixed sequence (`From`, `Date`, `Subject`).

The change replaces the brittle, order-dependent parsing in `count_messages()` with a new helper function `has_required_headers()`, which scans all headers first and checks for the presence of `From`, `Date`, and `Subject` regardless of their order. This matches the behavior of other email tools and ensures compatibility with `b4`-fetched patches. The patch also removes a special-case workaround for `git send-email --imap-sent-folder` (added in commit `04133f5bc4`), as the new logic makes it redundant.

The test coverage is thorough: a new test in `t/t9001-send-email.sh` verifies that `git imap-send` now accepts a patch with `Subject` before `Date` and confirms the fix doesn’t break existing functionality. The test exercises both the new code path and the `--imap-sent-folder` workflow to ensure no regressions.

This is a clean, well-motivated bugfix with a minimal footprint. The problem is concrete (interoperability with `b4`/`lore`), the solution is straightforward, and the test ensures robustness. The series looks uncontroversial and ready for review.
