This is a bugfix patch targeting the skipping negotiator in Git's fetch machinery.

The patch addresses a subtle ordering bug in the skipping negotiator's queue management. The negotiator sorts commits by date to prioritize recent work, but the `push_parent()` function was adding parent commits to the queue *before* parsing them, leaving their date fields unset (zero). This could cause recent common ancestors to be delayed behind older ref tips, potentially causing negotiation to terminate prematurely without discovering the most recent common commit.

Taylor Blau provides a clear example: if a topic branch is one commit ahead of `master`, the negotiator might skip `master`'s tip but then queue `master`'s parent with a zero date, causing it to appear older than unrelated refs. With enough old refs, the recent ancestor might never be offered at all. The fix ensures each parent is parsed (and thus has its correct date) before being added to the queue.

The patch touches `negotiator/skipping.c` and adds a new test case to `t/t5552-skipping-fetch-negotiator.sh`. The test creates a scenario with 32 old ref tips and verifies that the two most recent commits (the current HEAD and its grandparent) are offered in the first two "have" lines during negotiation, confirming the fix works.

The commit message is well-structured, explaining both the problem and the solution concisely. The test coverage is thorough, demonstrating the bug and verifying the fix with a realistic edge case. This appears to be a targeted, well-motivated fix for a real correctness issue in the fetch negotiation logic.
