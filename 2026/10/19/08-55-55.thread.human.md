This thread introduces a new mechanism for pluggable object database backends in Git, proposed by Patrick Steinhardt in a seven-patch series now at version 2. The series defines `extensions.objectStorage`, modeled after the existing ref storage extension, and implements a baseline `files` backend that allows relocating the `.git/objects` directory via a URI payload (e.g., `files://objs`). It also adds user-facing configuration (`init.defaultObjectStorageFormat`), environment variable overrides (`GIT_OBJECT_STORAGE_FORMAT`), and inspection tools (`git rev-parse --show-object-storage-format` and `git repo objects.storageFormat`) to query the configured backend.

The implementation is functionally complete, with all patches now implemented and submodule support added in v2. The series has been reviewed by Karthik Nayak, who raised minor concerns in earlier versions—such as path normalization, naming subtleties, and test coverage—but has now signaled conditional approval. His only remaining feedback is a non-blocking cleanup suggestion in patch 5/7 (a redundant `else if` block in `setup.c`). The series is rebased on the latest integration branch, and its prerequisite topics have already merged. While the local clone restriction (disabling local clones for non-default backends) and the repository format version bump may attract further discussion, neither has been flagged as a blocker.

Key participants include Patrick Steinhardt (author) and Karthik Nayak (reviewer), with Junio C Hamano providing advisory input on a minor implementation detail. The series remains architecturally uncontroversial, following established patterns for ref storage and addressing core functionality like configuration, inspection, cloning, and submodule propagation. No merge status has been reported yet, but the series appears ready for deeper review or integration.
