This thread introduces a new **object storage extension** mechanism for Git, allowing pluggable backends for object storage (e.g., cloud storage or databases). The series, authored by Patrick Steinhardt, is now complete with its seventh and final patch, which integrates the feature into `git submodule`.

The core idea is to make Git’s object database pluggable via a new configuration key, `extensions.objectStorage`, modeled after the existing ref storage extension. The initial implementation includes a `files` backend (the default) that supports relocating the `.git/objects` directory via a payload (e.g., `files://objs` moves objects to `.git/objs`). The series also adds environment variables (`GIT_OBJECT_STORAGE_FORMAT` and `GIT_DEFAULT_OBJECT_STORAGE_FORMAT`), user-facing configuration (`init.defaultObjectStorageFormat`), and inspection tools (`git rev-parse --show-object-storage-format` and `git repo objects.storageFormat`) to query the configured backend.

Key technical details include updates to `git clone`, `git init`, and now `git submodule` to accept the `--object-storage-format=` option, along with validation and propagation logic. The series avoids on-disk format changes, maintaining compatibility with the default `.git/objects` layout. One notable limitation is that local clones (hardlinking or copying objects) are disabled when either the source or destination uses a non-default object storage format, falling back to non-local transport or failing if `--local` is explicitly requested.

The series is under review, with no substantive feedback yet. The first six patches (covering refactoring, core configuration, environment variables, inspection tools, and `git clone` integration) appear uncontroversial, following established patterns for ref storage. The final patch, which propagates the option through `git submodule`, is a straightforward extension with thorough test coverage, completing the baseline functionality. Open questions may focus on API extensibility for future backends and whether the local clone restriction is too conservative. The series builds on two prerequisite topics (`ps/odb-files-alternates` and `ps/setup-enforce-repo-passed-to-create-repository-has-no-state`), both already merged.
