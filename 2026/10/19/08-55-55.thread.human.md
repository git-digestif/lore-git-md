This thread is about Patrick Steinhardt’s patch series introducing a pluggable object database backend for Git, now at version 3. The series defines `extensions.objectStorage` to allow alternative backends (like cloud storage) and implements a baseline `files` backend that can relocate the `.git/objects` directory. The latest iteration refactored the storage format URI into separate `(type, payload)` components for consistency with Git’s ref storage design, addressing earlier feedback from Karthik Nayak.

The series is functionally complete, with all planned features—configuration, environment variables, CLI options, inspection tools, and submodule support—implemented. Karthik Nayak conditionally approved v2, and the v3 refactoring doesn’t introduce new design questions, so his approval likely still stands. Junio Hamano’s earlier feedback was minor and advisory. The only open questions are non-blocking: path normalization, naming clarity in `git repo` output, and whether the repository format version bump is overly conservative for the `files` backend with a payload.

The newest email is a cleanup patch removing a dead function, `repo_write_loose_object_map()`, which was added in 2023 but never used. The function’s hardcoded path handling would have conflicted with the rest of the codebase, so its removal is uncontroversial and simplifies future backend work. No review feedback has arrived yet, but the patch is a straightforward deletion with no behavior changes. The series remains under review, with no merge status reported.
