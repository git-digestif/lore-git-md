This thread introduces Patrick Steinhardt’s patch series to make Git’s object database pluggable via a new `extensions.objectStorage` configuration, modeled after the existing ref storage extension. The series defines the baseline `files` backend (which supports relocating the `.git/objects` directory) and adds user-facing tools like `git rev-parse --show-object-storage-format` to inspect the active backend. It also enforces a pragmatic restriction: local clones (hardlinking or copying objects) are disabled when either the source or destination uses a non-default object storage format, falling back to non-local transport or failing if `--local` is explicitly requested.

The series is now complete at v1, with all seven patches posted. Karthik Nayak’s review of the first patch—removing dead code in `loose.c`—was purely supportive, noting the change as obviously correct without raising any technical concerns. No other feedback has arrived yet, so the series remains uncontroversial in its current form. The main open questions are likely to center on the local clone restriction (whether it’s too conservative) and how future backends will integrate with the API. The series builds on two prerequisite topics that are already merged, and no merge status has been reported for this one.
