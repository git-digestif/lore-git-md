This thread introduces the **object storage extension** (`extensions.objectStorage`), a pluggable backend mechanism for Git’s object database. The series, now at **v4**, is a seven-patch effort by Patrick Steinhardt to enable alternative object storage backends (e.g., cloud storage) while implementing the baseline `files` backend with support for relocating the `.git/objects` directory. The v4 iteration is **functionally complete**, addressing all prior feedback and expanding the architectural justification in response to SZEDER Gábor’s critique of the payload’s utility.

The series has **unconditional approval** from Karthik Nayak, who confirmed its technical readiness after reviewing the latest iteration. Key features include:
- A configuration mechanism (`extensions.objectStorage`) modeled after the ref storage extension, with environment variables (`GIT_OBJECT_STORAGE_FORMAT`, `GIT_DEFAULT_OBJECT_STORAGE_FORMAT`) and user-facing tools (`git rev-parse --show-object-storage-format`, `git repo objects.storageFormat`).
- CLI support for `git init`, `git clone`, `git submodule add`, and `git submodule update`, with precedence rules (CLI > environment > repository config > defaults).
- Submodule propagation that strips payloads (e.g., `files://objs` becomes `files`), mirroring the ref storage backend’s behavior.
- A **temporary local clone restriction** for non-default backends, documented as a safeguard.

The **sole remaining hurdle** is an unresolved architectural debate: SZEDER Gábor questioned whether `extensions.objectStorage` should exist as a public API, given that the `files` backend’s payload only relocates `.git/objects`. Patrick’s v4 response justified the payload’s utility (testing, consistency with ref storage, and internal use cases) but did not address the broader skepticism. Junio’s eventual decision may hinge on this point.

The implementation is robust, touching 35 files across core subsystems (`odb/`, `setup.c`, `repository.c`), built-ins, documentation, and tests. No merge status has been reported, but the series is otherwise ready for integration.
