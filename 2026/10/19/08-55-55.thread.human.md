This thread is about Patrick Steinhardt’s seven-part patch series introducing the **object storage extension** (`extensions.objectStorage`), which lays the groundwork for pluggable object database backends in Git. The series defines a configuration mechanism modeled after the existing ref storage extension, implements the baseline `files` backend (with support for relocating the `.git/objects` directory), and adds user-facing tools to inspect and configure the backend. The latest update, the seventh patch, completes the series by ensuring submodules inherit the parent repository’s object storage configuration via `--object-storage-format=` in `git submodule add` and `update`.

The series is now functionally complete, with all key components in place: configuration (`extensions.objectStorage`, `init.defaultObjectStorageFormat`), environment variable overrides (`GIT_OBJECT_STORAGE_FORMAT`, `GIT_DEFAULT_OBJECT_STORAGE_FORMAT`), inspection tools (`git rev-parse --show-object-storage-format`, `git repo objects.storageFormat`), and integration with `git clone`, `git init`, and submodules. The implementation is uncontroversial, reusing established patterns from the ref storage extension and addressing prior feedback, such as ensuring the `object_storage_format` field is always initialized. The only notable limitation is a documented restriction on local clones when using non-default backends, justified as a temporary measure.
