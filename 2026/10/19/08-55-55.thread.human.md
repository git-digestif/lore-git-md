This thread introduces a major architectural change: the **object storage extension**, a seven-patch series by Patrick Steinhardt that makes Git’s object database pluggable. The goal is to allow alternative backends (like cloud storage or databases) in the future, though for now only the default `files` backend is implemented. Users can already relocate the `.git/objects` directory via a payload (e.g., `files://objs` moves objects to `.git/objs`), and the series adds new configuration (`extensions.objectStorage`), CLI options (`--object-storage-format=` for `git clone` and `git init`), and environment variable support (`GIT_OBJECT_STORAGE_FORMAT`).

The series builds on two prerequisite topics already merged into the base commit, and it touches core subsystems like `odb/`, `setup.c`, and `repository.c`. Documentation and tests are updated to cover initialization, cloning, and submodule scenarios. The design mirrors the existing ref storage extension, suggesting a deliberate effort to maintain consistency with Git’s established patterns. While the immediate impact is limited to the `files` backend, the groundwork is laid for more ambitious backends down the line.

Key participants so far are Patrick Steinhardt as the author, and the thread is likely to attract attention from maintainers and contributors with an interest in Git’s storage architecture. No reviews or objections have been posted yet, so the discussion is just beginning. The series is currently at its first version (`v1`), and the next steps will likely involve feedback on the API design and potential edge cases.
