This thread introduces a new **object storage extension** mechanism for Git, allowing pluggable backends for the object database. The series, authored by Patrick Steinhardt, defines the `extensions.objectStorage` configuration (modeled after the existing ref storage extension) and implements a baseline `files` backend that supports relocating the `.git/objects` directory via a payload (e.g., `files://objs`). It also adds user-facing tools to inspect the configured backend, environment variable overrides, and submodule integration.

The initial version (v1) is under review and remains uncontroversial in its core design, following established patterns for ref storage. Key participants include Patrick Steinhardt and Karthik Nayak, who has provided substantive feedback on design consistency (e.g., path normalization, naming subtleties) and test coverage. Junio C Hamano has weighed in on minor implementation details but raised no objections. The series is complete, with all seven patches now available, and prerequisite topics merged.

Open questions center on design refinements—such as whether the `files` backend should normalize paths to absolute paths (deferred to avoid breaking tests) and the naming distinction between `object.format` (hash algorithm) and `objects.storageFormat` (storage backend) in `git repo` output. A pragmatic restriction disables local clones when either the source or destination uses a non-default object storage format, which may attract further discussion. No substantive review feedback has emerged for the later patches (5/7–7/7), and the series has not yet been queued for integration.
