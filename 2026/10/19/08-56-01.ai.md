This is the sixth patch in Patrick Steinhardt’s seven-patch series introducing the **object storage extension**, a major architectural effort to make Git’s object database pluggable. This patch wires up the new `--object-storage-format=` option in `git clone`, mirroring the functionality already added to `git init` in the previous patch.

The implementation follows the established pattern for the ref storage extension: users can specify the object storage format (e.g., `--object-storage-format=files://objs`) to relocate the object directory. The patch handles schema validation, environment variable precedence, and submodule propagation, but it explicitly disables local clones (hardlinking or copying objects) when either the source or destination repository uses a non-default object storage format. In such cases, the clone either falls back to a non-local transport (with a warning) or fails outright if `--local` was explicitly requested. The patch also includes thorough test coverage for initialization, payload handling, and error cases.

The limitation around local clones is a pragmatic choice: hardlinking or copying objects between repositories with different storage backends (or even the same backend with different payloads) is not straightforward, and the patch defers that complexity to future work. This is a reasonable trade-off for an initial implementation, though it may attract discussion about whether the restriction is too conservative. The patch is otherwise uncontroversial, building on the foundation laid by earlier patches in the series.
