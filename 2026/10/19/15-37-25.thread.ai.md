Subject: [PATCH] fsck: use Q_() for count-dependent pluralization
Series version: standalone patch (no series)
Originating author: Aniket Gupta <aniketgupta3001@gmail.com>
Thread type: patch (i18n improvement)

Core problem or goal
Replace a hardcoded plural form in `git fsck`'s verbose "Checking connectivity" message with the `Q_()` macro to allow translators to provide correct singular/plural forms for languages with more complex pluralization rules than English.

Current status
**Queued for integration.** Junio C Hamano has approved the patch ("Will queue") and it will enter his integration branches, starting with `seen` and progressing to `next` and eventually `master`. No prior versions.

Key technical details
- File touched: `builtin/fsck.c`
- Symbols: `Q_()` macro (existing Git i18n helper)
- Behavior: English output unchanged; enables correct pluralization in translations. The displayed count (from `get_max_object_index()`) is not an accurate object count, but this inaccuracy is left as a separate concern.
- On-disk format: no change
- Test coverage: none required (message formatting only)

Open questions and loose ends
None. Junio agrees with the author's decision to leave the count's inaccuracy as a separate concern, though he notes a `NEEDSWORK` comment could be added in the future if desired.

Participant positions
- **Junio C Hamano (maintainer)**: Approved and queued the patch. Explicitly endorses the use of `Q_()` for i18n support despite the count's inaccuracy, which he considers a separate issue.

Related work
Part of a broader GSoC effort to improve Git's translation support. No external dependencies.
