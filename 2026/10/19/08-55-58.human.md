This is the third patch in Patrick Steinhardt’s seven-patch series introducing the **object storage extension**, a major architectural effort to make Git’s object database pluggable. This patch adds support for overriding the object storage format via the `GIT_OBJECT_STORAGE_FORMAT` environment variable, mirroring the existing behavior for ref storage (`GIT_REF_STORAGE_FORMAT`).

The change is straightforward and consistent with Git’s established patterns. It adds the environment variable to `environment.h`, updates `setup.c` to check for it during repository setup, and documents it in `git.adoc`. The test in `t0001-init.sh` verifies that the environment variable takes precedence over the config setting (`extensions.objectStorage`), that the payload is respected (e.g., `files://objs` moves objects to `.git/objs`), and that invalid schemas are rejected. The implementation is clean and aligns with the series’ goal of providing a flexible, extensible configuration mechanism.

This patch is uncontroversial in isolation, but it’s part of a larger architectural discussion about pluggable object storage. The environment variable support is a logical and necessary piece of the puzzle, enabling users to experiment with backends without modifying config files. The patch is well-tested and follows Git’s conventions, so it’s likely to be accepted as-is. The real debate will center on the broader design of the object storage extension, particularly how future backends will integrate and whether the API is sufficiently flexible. For now, this patch is a solid incremental step.
