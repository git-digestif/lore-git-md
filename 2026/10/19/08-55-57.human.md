This is the second patch in Patrick Steinhardt’s seven-patch series introducing the **object storage extension**, a major architectural change that makes Git’s object database pluggable. This patch implements the core configuration mechanism (`extensions.objectStorage`) and integrates it into the repository setup code.

The patch adds the new `extensions.objectStorage` config key, modeled after the existing `extensions.refStorage`. The value is a URI in the format `<schema>[://<payload>]`, where the schema identifies the backend (currently only `files` is supported) and the payload provides backend-specific configuration. For the `files` backend, the payload specifies an alternative location for the `.git/objects` directory, allowing users to relocate object storage (e.g., `files://objs` moves objects to `.git/objs`). The patch updates `setup.c` to parse the extension, adds new fields to `struct repository` to store the object storage format and payload, and introduces helper functions like `repo_set_object_storage_format()` and `odb_source_type_by_uri()`.

Tests cover initialization with the new extension, including error cases for invalid backends and compatibility checks with repository format versions. The patch is well-scoped and appears technically sound, with clear documentation updates and careful handling of environment variable precedence (e.g., `GIT_OBJECT_DIRECTORY` takes precedence over the payload). This is a foundational piece of the series, enabling future backends while maintaining backward compatibility with the default `files` backend. The implementation is consistent with the ref storage extension, suggesting a deliberate design choice to reuse established patterns. No substantive review feedback has been recorded yet, but this patch is unlikely to be controversial given its mechanical nature and alignment with existing conventions.
