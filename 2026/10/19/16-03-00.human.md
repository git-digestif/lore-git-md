This is a documentation patch that corrects and clarifies the technical design document for partial clones. The patch narrows the scope of the "one-at-a-time fetch" limitation described in `Documentation/technical/partial-clone.adoc`. The author, Aleksei Sviridkin, points out that the current text misleadingly implies all dynamic object fetching is slow due to fetching objects individually, when in fact only the object lookup fallback in `odb.c` behaves this way. The other ten call sites of `promisor_remote_get_direct()` batch missing objects and fetch them in a single subprocess per promisor remote.

The commit message is now clear and well-motivated, explaining both the inaccuracy in the existing documentation and the specific code paths involved. The patch itself is small and surgical, replacing vague generalizations with precise descriptions of when and why the one-at-a-time behavior occurs. It also updates outdated references to `fetch-pack` (replaced by `git fetch` in 2020) and removes redundant phrasing.

This is a repost of a patch originally sent on September 3, with only the commit message revised. The diff remains unchanged and still applies cleanly to `master`. The patch looks like a straightforward improvement to the documentation’s accuracy and should be uncontroversial.

Separately, the author raises a concern in the cover text about an unacknowledged security report sent to `git-security@` and other channels over the past 46 days. That issue is unrelated to this patch but may warrant attention from the project’s maintainers.
