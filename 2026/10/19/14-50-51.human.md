This is a brief follow-up in the ongoing effort to fix a severe performance regression in `git fetch` from shallow repositories over protocol v2. The original RFC patch proposed a straightforward optimization—directly advertising shallow grafts instead of traversing history—but Junio C Hamano’s review identified a critical flaw: the patch misused the protocol API, causing client-side crashes when sideband multiplexing was enabled.

Harald Nordgren acknowledges the issue and signals intent to revise the patch. The technical direction is now clear: the fix must use the `packet_writer` API to preserve sideband multiplexing while retaining the performance benefit. Junio’s review included a failing test case that explicitly guards against the protocol violation, so the next iteration will need to pass that test.

The thread remains in a "needs revision" state, but the underlying goal—aligning protocol v2’s shallow advertisement behavior with v0 to avoid redundant traversal—is still valid. The regression (7-minute fetches reduced to 1 second) is well-documented, and the fix touches only `shallow.c` and `upload-pack.c`. No other objections have been raised, so once the API misuse is corrected, this patch should be ready for further review. For now, it’s not worth deeper attention until the revised version arrives.
