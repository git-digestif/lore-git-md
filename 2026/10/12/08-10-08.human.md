This is the **core API patch** in Christian Couder’s v3 series introducing `early_scan_options()`, a new `parse-options` sub-API for early argument scanning. The email is a reply to Kaartic Sivaraam’s v2 review, summarizing how v3 addresses the feedback.

The v3 redesign is a **major improvement** over v2, directly incorporating Sivaraam’s key concerns. The API now reuses `parse-options` internals (`lookup_long_opt()`) to handle negated options, unambiguous abbreviations, and aliases **consistently with `parse_options()`**, eliminating the risk of misalignment that Sivaraam flagged. For example, `git fast-import --export-pack --allow-unsafe-features` (where `--export-pack` is an abbreviation of `--export-pack-edges`) now correctly treats `--allow-unsafe-features` as a value for `--export-pack-edges`, matching `parse_options()` behavior. The scan also **stops at ambiguous abbreviations, short options, unknown options, and low-level callbacks**, erring on the side of caution to avoid misinterpreting values. This is a deliberate trade-off: the API may miss some options but will never report false positives.

The patch also addresses several edge-case refinements from the review. The return index now consistently points to the first argument *not* consumed by the scan (e.g., the value’s position after `--option value`), improving clarity for callers. A new `--stop-at-found` test helper option verifies this behavior. The API’s handling of missing values (e.g., `--wanted-value` with no argument) now mirrors `parse_options()`: the scan stops unless the option has `PARSE_OPT_LASTARG_DEFAULT`, in which case it reports the option with a `NULL` value (indicating the default). The test suite has been expanded to cover stuck optional values (e.g., `--optarg=5`), closing a gap in v2 coverage.

The commit message and `parse-options.h` documentation clearly explain the API’s limitations (e.g., ignoring short options, ambiguous abbreviations) and design rationale. The series is **well-tested**, with 28 new tests in `t/t0040-parse-options.sh` covering stuck/separate values, negated options, ambiguous abbreviations, non-options, and low-level callbacks. The preparatory refactorings (patches 1/6 and 2/6) and the `git fast-import` bugfix (patch 4/6) are **ready for `next`**, but the core API (this patch) remains under review due to lingering usability concerns—specifically, the caller’s responsibility for skipping argument values (e.g., `--option value`). This was a **substantive point of v2 feedback from Junio**, and while Christian defends the current design as simpler and faster, it may require further iteration before the series is ready for `next`.

The patch is **technically sound** and addresses all of Sivaraam’s v2 feedback, but the argument-skipping question is a **key unresolved issue** that could affect adoption. The API’s cautious approach (stopping at ambiguous cases) and reuse of `parse-options` internals make it a **strong foundation** for replacing hand-rolled early scans, but its practical utility will depend on how easily commands can integrate it. The series is worth watching for anyone interested in Git’s CLI infrastructure.
