This thread is about a patch series from D. Ben Knoble that improves shell completion for `git stash`, including refactoring, a Zsh bug fix, and the removal of completion support for the long-deprecated `git stash save` subcommand. The series is now under review, with version 1 posted and a v2 expected to address feedback.

The most recent discussion centers on the final patch (5/5), which removes `git stash save` from Bash completion. Patrick Steinhardt raised a design question: while it makes sense to stop suggesting `save` as a completion candidate, the patch also disables option autocompletion when a user manually types `save`. He notes that the subcommand has been deprecated for nearly a decade but questions whether this change might frustrate users who still rely on it, especially since the command remains completable if `GIT_COMPLETION_SHOW_ALL` is set. The thread is now waiting for the author to clarify whether this behavior is intentional or if the patch should be adjusted to preserve option completion for manually typed `save`.

Other parts of the series have seen progress. Patch 4/5, which removes `save` from the man page synopsis, is uncontroversial and endorsed by Patrick. Patch 3/5, which fixes a Zsh-specific bug with stash name completion (e.g., `stash@{0}`), is under discussion about whether a unified Bash/Zsh solution is possible. Patch 1/5, a refactoring to add the missing `store` subcommand to completion, awaits a v2 to address minor feedback. The series touches completion scripts, documentation, and built-in code but introduces no on-disk format changes or new tests. The broader question of how aggressively to remove completion for deprecated features remains open.
