The thread is a v2 patch series from D. Ben Knoble improving `git stash` shell completion, with five patches covering refactoring, a Zsh-specific bug fix, and the removal of completion and documentation for the deprecated `git stash save` subcommand. The series addresses feedback from Patrick Steinhardt on the initial version and is now under review.

The key changes include refactoring Bash completion logic to reduce duplication and add the previously omitted `store` subcommand, fixing a Zsh bug where stash names like `stash@{0}` were mishandled due to brace expansion, and removing `save` from the man page synopsis, `-h` usage text, and Bash completion candidates. The `save` subcommand is still documented in detail and remains completable if `GIT_COMPLETION_SHOW_ALL=1` is set, and option autocompletion for manually typed `save` (e.g., `git stash save --<TAB>`) continues to work regardless of this setting. The Zsh fix is Zsh-specific and displays stash names with escaped braces (e.g., `stash@\{0\}`), which is a side effect of the fix but preferable to the current broken behavior.

Patrick Steinhardt reviewed the first version, endorsing the man page cleanup but raising questions about the Zsh fix’s portability and the design of preserving option autocompletion for `save`. The author addressed these in v2, clarifying the scope of changes and confirming that no portable solution exists for the Zsh bug. The removal of `save` from completion and prominent help contexts is framed as a cleanup but may still draw feedback, as it accelerates the deprecation timeline for a subcommand that has been deprecated since 2018 but is still in use. The series is otherwise uncontroversial, with no objections raised so far.
