The `git stash` shell completion series from D. Ben Knoble is refining how Git’s command-line completion works for the `stash` subcommands. The series refactors existing logic to reduce duplication, fixes a Zsh-specific bug where stash names like `stash@{0}` weren’t handled correctly, and removes completion support for the long-deprecated `git stash save` subcommand. The series is currently at version 1, with a second version expected soon to address feedback.

The most active discussion centers on the fifth patch, which removes Bash completion for `git stash save`. Patrick Steinhardt raised a usability question: should option autocompletion (like `--keep-index`) still work if a user manually types `save`? The author is testing this behavior and expects that the existing `GIT_COMPLETION_SHOW_ALL` setting might already preserve this functionality, which could resolve the concern. The third patch, which fixes the Zsh bug, also drew attention for its Zsh-specific approach, though the author confirmed no portable solution exists and Bash isn’t affected.

The series touches completion scripts, documentation, and the stash built-in, but doesn’t change on-disk formats or add new tests. The main open questions are whether the `save` completion removal goes too far and whether the Zsh fix could be made more portable—though the latter seems unlikely given the constraints. A second version of the series should clarify these points.
