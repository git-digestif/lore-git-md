This thread is about a patch series from D. Ben Knoble that improves shell completion for `git stash`. The series refactors existing logic to reduce duplication, adds the missing `store` subcommand to completions, fixes a Zsh-specific bug where stash names like `stash@{0}` weren’t handled correctly, and removes completion and documentation support for the long-deprecated `git stash save` subcommand. The series is now at version 2, addressing feedback from Patrick Steinhardt on the first version.

The key changes include making Zsh completion work properly with stash names (though this introduces a minor display quirk where braces are escaped), removing `save` from the man page synopsis and Bash completion (unless a special environment variable is set), and preserving option completion for manually typed `save` commands. Patrick’s review was substantive, particularly on the Zsh fix and the `save` removal, but he endorsed the documentation cleanup. The author has been open to feedback and is willing to drop the more controversial `save` removal patches if they prove too contentious.

The only new development in this latest exchange is a minor workflow discussion: Kristoffer Haugsbakk endorsed the author’s idea of leaving the exact `git format-patch` command in future cover letters as a learning aid for new contributors. This doesn’t affect the technical content of the series, which remains under review with no major objections raised so far. The main open questions are whether the Zsh fix could be made more portable and whether removing `save` from completions and documentation will draw pushback.
