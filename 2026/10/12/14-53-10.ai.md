This is the first patch in the v3 series introducing `gitmergeconflicts(7)`, a new man page consolidating Git’s merge conflict resolution guidance. The patch creates the new guide (`Documentation/gitmergeconflicts.adoc`) and updates the build system (`Makefile`, `meson.build`, `.gitattributes`, and `command-list.txt`) to integrate it into the documentation suite.

The new guide is a comprehensive, user-focused resource that addresses long-standing documentation gaps: scattered advice across multiple man pages, inconsistent terminology ("ours" vs. "theirs"), unclear explanations of merge conflict markers, and missing practical examples. It covers foundational concepts (e.g., "WHAT IS A MERGE CONFLICT?"), step-by-step resolution workflows, tools for handling conflicts (`git diff AUTO_MERGE`, `git log --merge -p <filename>`, `merge.conflictstyle=diff3`), and command-specific nuances (e.g., "ours" and "theirs" during rebases). The guide explicitly deprecates `zdiff3` and promotes `diff3` as a best practice, while retaining backward compatibility.

This patch is purely additive—no existing behavior or on-disk formats are changed. The series has already incorporated all feedback from Junio’s v2 and v3 reviews, including the exhaustive list of commands that can cause conflicts (`git merge`, `git rebase`, `git cherry-pick`, `git pull`, `git am -3`, `git checkout -m`, `git stash pop`, `git revert`) and formal tone adjustments. Junio’s `Reviewed-by:` can be added once the final refinements are applied. The guide’s structure (e.g., `<<resolve>>`, `<<ours>>`, `<<diff3>>` sections) and use of `linkgit:` macros align with the project’s recent documentation improvements, such as Jean-Noël Avila’s synopsis-style conversion.
