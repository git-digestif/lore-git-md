This is the final patch in Isabella Caselli’s three-patch series implementing the `includeIf.hostname:<pattern>` condition for Git’s configuration system. It adds the core logic, documentation, and test coverage for hostname-based conditional includes, completing the feature introduced in the earlier patches.

The patch teaches Git to recognize `includeIf.hostname:<pattern>` in `.gitconfig` files, where `<pattern>` supports standard glob wildcards. The hostname used for matching is exactly what the system reports—short name or FQDN—without normalization or DNS lookups, aligning with the 2024 consensus established in Ignacio Encinas’ earlier work. If the hostname cannot be determined, the condition evaluates to false. The implementation is modeled after `includeIf.onbranch:` and uses the same exact-matching semantics (case-sensitive, no globbing beyond standard wildcards).

Key files touched: `config.c` (the new `include_by_hostname()` function and condition parsing), `Documentation/config.adoc` (man page update with examples and caveats about system-dependent hostname reporting), `Documentation/git-var.adoc` (cross-reference to `git var GIT_HOSTNAME`), and `t/t1305-config-include.sh` (two new test cases: exact hostname matching and wildcard matching). The tests use `git var GIT_HOSTNAME` to obtain the hostname, ensuring consistency with the production code path and failing visibly if the hostname cannot be retrieved.

The commit message clearly states the motivation (dotfile sharing across machines), the design choices (system-dependent hostname, no DNS lookups), and the relationship to prior work (Ignacio Encinas’ 2024 series). The implementation is straightforward and well-scoped, with no new CLI options, config keys, or on-disk format changes. The only remaining open question—whether hostname matching should be case-sensitive—is noted in the commit message but does not block the current implementation. The patch appears ready for review and addresses all prior feedback from the RFC phase.
