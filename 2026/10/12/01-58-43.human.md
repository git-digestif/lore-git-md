This is the first implementation of the `includeIf.hostname:<pattern>` feature, a new condition for Git’s configuration system that lets users include config files only on machines whose hostname matches a given pattern. The series also adds `git var GIT_HOSTNAME` as a debugging aid so users can see exactly which hostname Git is using for matching.

Isabella Caselli has taken over the effort from Ignacio Encinas’s stalled 2024 series, incorporating feedback from Jeff King, Eric Sunshine, and Junio C Hamano. The implementation is clean and conservative: it reuses the existing `includeIf` machinery, adds the new condition without changing the on-disk format, and documents the behavior clearly. The hostname resolution is intentionally system-dependent—Git uses whatever the system reports, short name or FQDN, and leaves normalization to the user. The only open question is case sensitivity; the patch keeps matching case-sensitive, matching the behavior of `includeIf.onbranch:`.

The series touches `config.c` for the core logic, `t1305-config-include.sh` for tests, and `Documentation/config.adoc` for documentation. It also updates `builtin/var.c` and `Documentation/git-var.adoc` to add the `GIT_HOSTNAME` variable, and tweaks `t6500-gc.sh` to use the new variable instead of a hard-coded hostname. The test coverage is thorough, exercising the new condition with exact matches and verifying that the variable behaves as expected when the hostname cannot be determined.

This looks like a well-scoped, well-motivated feature that addresses a real user need without introducing complexity or controversy. The implementation is straightforward, the commit messages are clear, and the feedback from prior rounds has been incorporated. If the case-sensitivity question is resolved (or left as-is), this series is likely to be uncontroversial and ready for `next`.
