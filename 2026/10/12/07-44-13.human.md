This is the **bugfix patch** in Christian Couder’s v3 series introducing the `early_scan_options()` API. It converts `git fast-import` to use the new API, fixing a real bug where `--allow-unsafe-features` was silently ignored when preceded by an option with a separate value (e.g., `--depth 5 --allow-unsafe-features`).

The patch is **well-motivated and thoroughly tested**. The commit message clearly explains the problem (a hand-rolled early argument scan that disagrees with `parse_options()` on value consumption) and how the new API resolves it. The fix now aligns with `parse_options()` behavior, including support for unambiguous abbreviations (e.g., `--allow-unsafe`) and proper handling of options that take values. The documentation is updated to remove outdated notes about spelling the option in full, and the NEEDSWORK comment is dropped.

The implementation is clean: it marks `--allow-unsafe-features` with `PARSE_OPT_EARLY`, replaces the fragile manual scan with `early_scan_options()`, and adds a callback (`option_parse_early_allow_unsafe`) to set the flag. The new tests cover the bugfix (options after a value), abbreviations, and edge cases where `--allow-unsafe-features` is misinterpreted as a value for another option. The patch is **ready for `next`** and should proceed independently of further API iteration.

This is a **clear improvement** over the status quo and a strong demonstration of the new API’s value. Maintainers of other commands with hand-rolled early scans (e.g., `git bisect`, `git rev-parse`) may want to watch this conversion as a template.
