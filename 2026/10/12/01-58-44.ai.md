This is the first patch in Isabella Caselli’s three-patch series implementing `includeIf.hostname:<pattern>` for Git’s configuration system. It adds a `GIT_HOSTNAME` variable to `git var`, exposing the hostname Git sees when querying the system. The implementation is straightforward: it calls `xgethostname()` (the same function Git already uses internally) and returns the result via `git var GIT_HOSTNAME`. If the hostname cannot be determined, the command exits non-zero, and `git var -l` omits the variable rather than failing.

The patch touches `builtin/var.c` (adding the new variable), `Documentation/git-var.adoc` (documenting it), and `t/t0007-git-var.sh` (adding a minimal test that checks the output is non-empty). The test is intentionally simple—it cannot know the expected hostname in advance, since Git’s interpretation may differ from the system `hostname` command on some platforms. Later patches in the series use this variable in `includeIf` tests to verify consistency with the configuration code.

This is a well-scoped, uncontroversial change that directly addresses feedback from the RFC phase (Peff and Eric Sunshine suggested exposing the hostname via `git var`). The implementation is clean, the commit message is clear, and the test coverage is appropriate for the scope. No open questions or edge cases are introduced here; the patch is ready for review and unlikely to generate debate. The only remaining technical question in the series—whether hostname matching should be case-sensitive—is deferred to the third patch.
