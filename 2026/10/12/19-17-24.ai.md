This is the **second patch in the v4 series** that implements the default `HEAD:.git-blame-ignore-revs` behavior for `git blame` and `git annotate`. The patch is **approved for integration** into `next` and addresses all prior feedback, including the **100MB size cap** on ignore-revs blobs to prevent memory exhaustion.

The patch teaches `git blame` to automatically use the `HEAD:.git-blame-ignore-revs` blob as the default ignore-revs file when no explicit ignore file is configured. This aligns local behavior with hosting platforms (GitHub, GitLab) that already respect this file by default. The implementation reads the *committed* blob from `HEAD` (not the working-tree file) to ensure consistency with hosting platforms, even when uncommitted changes exist. This design choice remains a **user-experience trade-off**: while it matches hosting platform behavior, it may surprise users who expect uncommitted changes to take effect.

Key technical details:
- **Files touched**: `builtin/blame.c`, `oidset.c`, `oidset.h`, `Documentation/blame-options.adoc`, `Documentation/config/blame.adoc`, and `t/t8013-blame-ignore-revs.sh`.
- **Default file lookup**: The `HEAD:.git-blame-ignore-revs` blob is resolved via `get_oid_with_context()` and checked for regular-file status (`S_ISREG()`) to skip non-regular tree entries (e.g., symlinks, subdirectories). The blob’s size is capped at **100MB** (`IGNORE_REVS_MAX_FILE_SIZE`) via `odb_read_object_info()` before loading, preventing memory exhaustion from maliciously large blobs.
- **In-memory parsing**: The blob is parsed via `oidset_parse_buffer_carefully()`, a new helper that shares line-parsing logic with the existing file-based parser (`parse_oidset_line()`). This ensures consistent handling of comments, whitespace, and malformed input (e.g., NUL bytes, invalid OIDs).
- **Precedence**: The default blob is added *before* user-configured ignore files, ensuring user overrides take precedence. Empty `blame.ignoreRevsFile` or `--ignore-revs-file ""` bypasses the default entirely.
- **Edge cases**: The patch handles subdirectory invocations (limited to the repository root), bare repositories, uncommitted working-tree changes (ignored), committed symlinks (skipped), and oversized blobs (skipped with a warning). Tests cover all these scenarios, including an `EXPENSIVE` test for the 100MB size cap.

The patch is **feature-complete** and resolves all prior technical objections. The only remaining open question is whether to adjust the uncommitted-changes handling (currently ignored), but this is a **user-experience trade-off** rather than a blocker. The size cap and security hardening (NUL-byte rejection, promisor fetch prevention, tag type verification) are robust and unlikely to require further changes. Junio’s approval and the lack of new objections suggest this is ready for `next`.
