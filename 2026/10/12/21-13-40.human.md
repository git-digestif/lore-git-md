This is a brief maintainer reply in the ongoing `git blame` default ignore-revs file thread. Junio C Hamano responds to Ravi Mistry’s note that v4 retains the current behavior of reading the ignore-revs list from the committed `HEAD:.git-blame-ignore-revs` blob rather than the working-tree file. Junio suggests that while matching hosting platforms (GitHub, GitLab) is not a sufficient justification, consulting the working-tree file in non-bare repositories would be "more ergonomic" for users. He leaves the decision open but signals a preference for the more intuitive behavior.

The comment is low-weight in terms of immediate action—v4 remains queued for `next` and is otherwise feature-complete—but it reopens the uncommitted-changes handling as a potential follow-up refinement. No technical objections are raised; this is purely a user-experience consideration. Authors and reviewers now have a clear signal that Junio would accept a future patch adjusting this behavior if someone (possibly Ravi, possibly another contributor) chooses to implement it.
