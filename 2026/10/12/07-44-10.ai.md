This is the **first patch in the v3 series** introducing `early_scan_options()`, a new `parse-options` sub-API for early command-line argument scanning. This patch is a **preparatory refactoring** that extracts the logic for determining whether an option takes an argument into a reusable function, `parse_options_takes_argument()`.

The patch moves the existing open-coded logic from `show_gitcomp()` (used for shell completion) into a new function in `parse-options.h`/`parse-options.c`. The logic is unchanged: an option takes an argument if its type is `OPTION_STRING`, `OPTION_FILENAME`, `OPTION_INTEGER`, `OPTION_UNSIGNED`, or `OPTION_CALLBACK`, and it does not have the `PARSE_OPT_NOARG` or `PARSE_OPT_OPTARG` flags. The new function also treats `PARSE_OPT_LASTARG_DEFAULT` options as taking an argument, even though they only consume the next argument when it isn’t the last one. This is a deliberate choice to simplify early scanning, where callers can easily check for a next argument.

The patch is **clean and uncontroversial**, with no behavior changes. It is a necessary foundation for the core API patch (2/4), which will use `parse_options_takes_argument()` to determine whether to skip the next argument when scanning for early options. The commit message clearly explains the motivation and the edge case (`PARSE_OPT_LASTARG_DEFAULT`), and the code is well-tested (the existing `show_gitcomp()` logic is preserved). This patch is **ready for `next`** and should proceed independently of any further iteration on the broader API.
