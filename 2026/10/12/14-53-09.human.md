This is a documentation patch series introducing `gitmergeconflicts(7)`, a new man page that consolidates Git’s scattered merge-conflict resolution guidance into a single, user-focused guide. The series is now in its third iteration (v3) and is ready for merging after addressing all feedback from Junio’s reviews.

The motivation is clear and well-documented: Git’s current documentation repeats or omits key details about merge conflicts across multiple command man pages, leaving users confused about terminology (e.g., "ours" vs. "theirs"), workflows, and tools. The new guide centralizes this information with practical examples, a foundational explanation of what merge conflicts are, and explicit advice on best practices (e.g., promoting `merge.conflictstyle=diff3` while deprecating `zdiff3`). Julia Evans cites direct user feedback (via Mastodon and other channels) as the driving force behind the design, which prioritizes clarity over technical minutiae.

The series touches 10 files, including a new `Documentation/gitmergeconflicts.adoc` (330 lines) and surgical updates to existing man pages (`git-merge`, `git-rebase`, `git-revert`, `git-cherry-pick`, and `git-pull`) to replace redundant sections with cross-references. The commit messages are detailed and transparent about open questions (e.g., whether to cover `git am -3` or `git checkout -m`), though these are now resolved in v3. The new guide is purely additive—no behavior changes—and integrates cleanly into the documentation build system (`make check-docs` passes).

Junio’s v2 and v3 reviews confirm that patches 2/6, 3/6, and 6/6 are approved for merging if unchanged, while patches 4/6 and 5/6 require only minor wording tweaks (e.g., moving the `gitmergeconflicts(7)` reference in `git-cherry-pick.adoc` to the `SEE ALSO` section). The final patch (updating `git-pull.adoc`) received unconditional approval. Julia has addressed all remaining feedback, including Junio’s latest requests: an exhaustive list of commands that can cause merge conflicts (`git merge`, `git rebase`, `git cherry-pick`, `git pull`, `git am -3`, `git checkout -m`, `git stash pop`, `git revert`) and formal phrasing (replacing contractions like "Here's" with "Here is").

The guide’s structure is now polished, with sections covering:
- A foundational "WHAT IS A MERGE CONFLICT?" explanation (including semantic conflicts).
- An exhaustive list of commands that trigger merge conflicts.
- Clear resolution paths (fix, abort, or skip).
- Merge conflict markers (`<<<<<<<`, `=======`, `>>>>>>>`, and `|||||||` in `diff3`).
- Tools for handling conflicts (grouped by static vs. dynamic views, with `diff3` actively promoted and `zdiff3` deprecated).
- A rewritten "OURS" AND "THEIRS" section that explicitly ties the terms to `HEAD` and the other commit.
- Practical examples, including `git diff AUTO_MERGE` and `git status` output.

The series also fixes a 16-year-old bug in `git-merge.adoc` (references to non-existent steps "2" and "3"). Reviewers—including Junio, Jeff King, D. Ben Knoble, and Patrick Steinhardt—have provided substantive feedback, and the author has been responsive to all suggestions. The only loose ends are potential follow-up patches (e.g., Patrick’s proposed conflict-marker enhancements or Junio’s `git status` wording tweaks), but these do not block merging.

This is a well-crafted, user-focused effort that addresses a long-standing gap in Git’s documentation. The series is ready for `next` and likely `master` in the near term.
