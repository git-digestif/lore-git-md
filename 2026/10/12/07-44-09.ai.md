This is a **revised API refactoring and bugfix series** introducing `early_scan_options()`, a new `parse-options` sub-API for safely scanning command-line arguments early. The v3 series addresses feedback from Junio and Kaartic Sivaraam by reusing `parse-options` internals (notably `lookup_long_opt()`) to handle negated options, unambiguous abbreviations, and aliases consistently with `parse_options()`. The implementation now stops at short options, unknown options, ambiguous abbreviations, and low-level callbacks to avoid misinterpreting option values, and it properly handles `PARSE_OPT_LASTARG_DEFAULT` options.

Key technical details:
- **New API**: `early_scan_options()` scans arguments using the same `struct option` array as `parse_options()`, ensuring consistency in option recognition and value consumption.
- **Behavior**: The scan stops at arguments it cannot reliably skip (e.g., short options, ambiguous abbreviations, low-level callbacks) to avoid misinterpreting values. This errs on the side of caution, potentially missing options but never reporting false positives.
- **Flags**: `PARSE_OPT_EARLY` marks options to report during early scanning; `EARLY_SCAN_STOP_AT_NON_OPTION` stops at non-options (matching `PARSE_OPT_STOP_AT_NON_OPTION`).
- **Bugfix**: Converts `git fast-import` to use the API, fixing a bug where `--allow-unsafe-features` was ignored when preceded by `--depth 5`. The fix now aligns with `parse_options()` behavior, including abbreviations (e.g., `--allow-unsafe` is accepted unless `GIT_TEST_DISALLOW_ABBREVIATED_OPTIONS` is set).
- **Tests**: Comprehensive coverage in `t/t0040-parse-options.sh` and `t/t9300-fast-import.sh`, including edge cases like stuck values, negated options, and ambiguous abbreviations.

The series is **well-structured and thoroughly tested**, with clear commit messages explaining design trade-offs. The v3 redesign resolves the major v2 concerns (e.g., handling abbreviations, negated options) while maintaining simplicity. The `git fast-import` conversion is ready for `next`, but the broader API may need further iteration to address usability (e.g., caller responsibility for argument skipping) before wider adoption. The series is **worth attention** from maintainers of commands with hand-rolled early scans (e.g., `git bisect`, `git rev-parse`).
