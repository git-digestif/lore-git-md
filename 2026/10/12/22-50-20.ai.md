This is a bugfix for `git fast-import` addressing a crash when resolving commits or tags created earlier in the same session but not yet written to the object database (ODB). The v2 patch incorporates feedback from the initial review: it improves the commit message, adheres to line-length conventions, and adds a comprehensive test case in `t/t9300-fast-import.sh` that covers both SHA-1 and SHA-256 repositories. The test verifies that references to pending commits and tags (including tag-of-tag scenarios) are resolved correctly without crashing.

The fix remains minimal and targeted, modifying only the `parse_from_existing` function in `builtin/fast-import.c`. It introduces a cache lookup for `OBJ_COMMIT` and `OBJ_TAG` objects before falling back to the ODB, ensuring that in-session objects are resolved via the fast-import object cache. The patch handles tag dereferencing through the existing `dereference` helper, preserving the expected behavior for nested tags. No new symbols or on-disk format changes are introduced.

The added test case is robust, using separate input files for SHA-1 and SHA-256 to avoid platform-specific issues (e.g., named pipes or coprocess limitations in shell scripts). It exercises four scenarios: referencing a pending commit via `reset`, referencing a pending commit via `from` in a new commit, referencing a pending tag, and referencing a tag-of-a-tag. The test confirms that existing objects (commits, tags, blobs) continue to work as before, while the crash is resolved for in-session objects.
