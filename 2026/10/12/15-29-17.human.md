This is a bugfix patch targeting the fetch subsystem, specifically addressing a regression in shallow fetches when backfilling tags. It’s the second iteration (v2) of a patch that fixes a performance issue introduced by commit 0e358de64a ("fetch: use batched reference updates", 2025-05-19).

The problem occurs because batched updates delay committing references to disk until after tag backfilling begins. During shallow fetches, this means the client has no references to report in the 'have' section of negotiation, causing the server to send all objects in the repository since backfilling lacks a depth limit. Karthik’s solution splits the reference transaction into two: one for fetched references and another for backfilling tags. This restores correct negotiation behavior while preserving most of the performance benefits of batched updates.

The patch touches `builtin/fetch.c` and adds a test in `t/t5510-fetch.sh` that directly verifies shallow fetches don’t refetch objects during tag backfilling by checking repository state with `git cat-file`. The test was revised from v1 to avoid indirect packet-trace counting, addressing Patrick Steinhardt’s feedback. Benchmark results show the fix runs 17.38±0.61 times faster than the pre-batched-update behavior, and while it’s slightly slower than the single-transaction approach (1.01x), it remains significantly faster than not using batched updates at all.
