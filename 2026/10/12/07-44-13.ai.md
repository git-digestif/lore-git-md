This is the **bugfix patch** in Christian Couder’s v3 series introducing the `early_scan_options()` API. It converts `git fast-import` to use the new API, fixing a real bug where `--allow-unsafe-features` was silently ignored when preceded by an option with a separate value (e.g., `--depth 5 --allow-unsafe-features`). The patch also aligns the command’s behavior with `parse_options()` for abbreviations and negated options, removing a long-standing NEEDSWORK comment and outdated documentation.

The implementation is clean and well-tested. The new `option_parse_early_allow_unsafe()` callback is minimal, and the early scan now reuses the same `struct option` array as `parse_options()`, ensuring consistency. Two new tests in `t/t9300-fast-import.sh` verify the bugfix: one confirms `--allow-unsafe-features` is recognized after a value (e.g., `--depth 5`), and another checks that ambiguous abbreviations (e.g., `--allow-unsafe`) are rejected when `GIT_TEST_DISALLOW_ABBREVIATED_OPTIONS` is set. The patch also removes a misleading note from the documentation that previously claimed the option had to be spelled in full.

This patch is **ready for `next`** and should proceed independently of further API iteration. The broader series remains under review due to lingering usability concerns (e.g., caller responsibility for argument skipping), but this conversion is a clear improvement over the hand-rolled scan it replaces. The fix is narrow, well-motivated, and thoroughly tested, making it a low-risk candidate for merging. Maintainers of other commands with hand-rolled early scans (e.g., `git bisect`) may want to watch this patch as a reference for future conversions.
