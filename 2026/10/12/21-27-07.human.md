This is a platform compatibility bugfix targeting the Windows credential helper in `contrib/credential/wincred`. The patch (v3) is the culmination of a short review cycle that addressed feedback from Junio C Hamano on earlier versions. It fixes a long-standing parsing bug where multi-line secret blobs—such as credentials containing both a password and an OAuth refresh token—were misinterpreted due to unsafe string operations (`wcsncpy_s` with incorrect size, `wcstok_s` misuse) that could cause buffer overreads, memory corruption, or incorrect line splitting.

The new implementation is a thorough refactor that replaces the problematic string-splitting logic with a cleaner, immutable approach. It uses `wmemchr` to scan for newlines directly in the original credential blob, correctly handles both `\r\n` and `\n` line endings, and avoids modifying the input buffer. The code is now split into two helper functions—`write_credential_item` and `write_credential`—which reduce nesting, improve readability, and make the logic easier to audit. Wide-character handling is now consistent, using character counts rather than bytes for sizes and pointer arithmetic.

This is a well-motivated fix for a real edge case that users have occasionally reported. The patch is confined to the Windows-specific credential helper and does not affect other platforms. While there are no tests (typical for `contrib/` code), the changes are straightforward and address the root causes of the parsing failures. The author has fully addressed Junio’s feedback on commit message clarity, code structure, and wide-character correctness, and the patch now looks ready for inclusion in `next`. If you work with Git on Windows or care about credential helper robustness, this is worth a quick look.
