This is a follow-up to Junio’s performance optimization patch for Phillip Wood’s `git checkout -m` conflict label preservation series. The patch implements Junio’s suggestion to cache per-invocation constants (like `merge.renormalize` and conflict style) in a new `struct checkout_merged_data`, avoiding redundant config reads and file I/O for `.git/MERGE_LABELS` during a single `git checkout -m` invocation.

Phillip Wood incorporates Junio’s diff verbatim, adding the new structure and helper functions (`checkout_merged_prepare()` and `checkout_merged_release()`) to `builtin/checkout.c`. The core logic in `checkout_merged()` now uses the precomputed values from the data structure instead of repeatedly querying the configuration or reading the labels file. The patch is a pure refactoring with no user-visible behavior change, touching only `builtin/checkout.c` and maintaining the same API surface.

The implementation is straightforward and aligns with Git’s existing patterns for caching per-invocation state (e.g., in-core configset cache). The new `checkout_merged_data` structure is initialized once at the start of `checkout_worktree()` and released at the end, ensuring cleanup. The patch is uncontroversial and ready for integration, though the question of whether it should be squashed into Phillip’s original patch 2/2 or kept as a separate "PATCH 1.5/2" remains open. Phillip’s response indicates he is happy to proceed with Junio’s sign-off, suggesting this version is final.

Key technical details include the new `struct checkout_merged_data` (which currently holds `conflict_style` and `renormalize` but is designed for future expansion), the `checkout_merged_prepare()` and `checkout_merged_release()` functions, and the updated `checkout_merged()` signature to accept the data structure. The patch does not introduce new edge cases or compatibility concerns, and the performance benefit—while small—is measurable, especially in repositories with many conflicts. The only unresolved question is the patch’s placement in the series, but this is a minor procedural detail rather than a technical issue.
