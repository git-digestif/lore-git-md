This is a bugfix for `git fast-import`, addressing a crash when the command tries to resolve commits or tags created earlier in the same session but not yet written to the object database. The v2 patch incorporates feedback from the initial review: it improves the commit message, adheres to line length conventions, and—most importantly—adds a comprehensive test case in `t9300-fast-import.sh` that covers both SHA-1 and SHA-256 repositories.

The fix itself remains minimal and targeted. It modifies `parse_from_existing` in `builtin/fast-import.c` to check the fast-import object cache for `OBJ_COMMIT` objects before falling back to the ODB. This preserves existing behavior for objects not in the cache while resolving the crash for in-session commits and tags. The test case exercises four scenarios: referencing a new commit via `reset`, referencing it via `from` in a subsequent commit, referencing a tag created in the same session, and referencing a tag-of-a-tag. The test is written to work across both hash algorithms and avoids platform-specific constructs like named pipes.
