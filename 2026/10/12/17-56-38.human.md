This is a platform-agnostic bugfix patch that addresses a long-standing inconsistency in how Git detects file modifications when clean filters or CRLF conversion are active. The issue manifests when tools or editors rewrite files with different line endings (e.g., converting LF to CRLF) without changing the actual content—`git status` incorrectly reports these files as modified, while `git diff` and `git add` correctly recognize them as unchanged.

The patch introduces a new helper function `size_change_is_conclusive()` in `read-cache.c` that checks whether a file’s size change is truly indicative of modification by running the content through Git’s conversion pipeline (`would_convert_to_git()`). If conversion is active, the function forces a full content comparison rather than trusting the size difference. This change affects only the modification-detection logic in `ie_modified()` and adds two new tests in `t/t0020-crlf.sh` to verify the fix handles both CRLF rewrites and lone CR cases correctly.

The commit message is unusually detailed, documenting real-world scenarios (Javadoc, code generators, editors) where this inconsistency causes confusion. Performance is addressed head-on: the patch shifts work from `git add` to `git status`, with the author noting a 20ms per-file overhead in the latter. This trade-off is justified by the elimination of the "status reports modified, diff shows nothing" inconsistency, which has been a recurring source of user confusion.
