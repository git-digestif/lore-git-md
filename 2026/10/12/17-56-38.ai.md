This is a platform compatibility bugfix targeting macOS and other environments where tools rewrite files with CRLF line endings, causing `git status` to incorrectly report modifications. The patch refines and simplifies earlier work by Curtis Allen Smith to address a long-standing flaw in Git's index comparison logic: `ie_modified()` in `read-cache.c` has historically treated any size change as conclusive evidence of modification, even when clean filters or CRLF conversion could legitimately alter file size without changing content.

The fix introduces `size_change_is_conclusive()`, a helper function that checks whether a file path would undergo conversion (`would_convert_to_git()`). When conversion is active, Git now reads and converts the file content to verify whether the size change reflects actual modification, rather than trusting the size difference alone. This change is unconditional (removing the earlier configuration switch) and adds 25 lines to `read-cache.c`, plus 45 lines of new tests in `t/t0020-crlf.sh` that cover both CRLF rewrites and lone-CR edge cases.

The patch is marked RFC, indicating it is still under active development. Torsten Bögershausen has taken ownership of the work, properly attributing it to Curtis Allen Smith via DCO sign-offs. The commit message is functional but the author notes it could be smoother ("bumpy"). Performance impact is acknowledged: the change shifts work from `git add` to `git status`, with measurements showing ~20ms overhead per file in the latter command.

This effort complements the recently completed utf8.c iconv series (also macOS-specific) but has broader scope: while the utf8.c fix addressed a narrow encoding conversion bug, this patch corrects a fundamental assumption in Git's index comparison logic that has been problematic since clean filters and CRLF conversion were introduced. The two patches share a platform-specific motivation but are otherwise independent. No review feedback has appeared yet on this RFC version.
