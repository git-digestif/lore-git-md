This is the v3 submission of a documentation patch series introducing `gitmergeconflicts(7)`, a new man page consolidating Git’s merge conflict resolution guidance. The series is now ready for merging after addressing all feedback from Junio’s v2 and v3 reviews, including final refinements to the new guide and updates to existing man pages.

The core goal remains unchanged: replacing scattered, duplicative conflict-resolution advice across multiple command man pages (`git merge`, `git rebase`, `git revert`, `git cherry-pick`, and `git pull`) with a single, comprehensive guide. The new `gitmergeconflicts(7)` page (330 lines) explains foundational concepts (e.g., "ours" vs. "theirs," semantic conflicts), provides practical examples (e.g., interpreting `diff3` markers, using `AUTO_MERGE`), and promotes best practices like `merge.conflictstyle=diff3`. Junio’s latest review requested two final adjustments—making the list of commands that can cause conflicts exhaustive (now including `git am -3`, `git checkout -m`, `git stash pop`, and `git revert`) and replacing contractions ("Here's" → "Here is")—both of which Julia Evans has agreed to incorporate.

The series touches 10 files, including mechanical updates to `Makefile`, `meson.build`, and `.gitattributes` to integrate the new page into the documentation build system. Existing man pages are surgically edited to replace redundant sections with cross-references to the new guide while preserving command-specific details (e.g., `CHERRY_PICK_HEAD` in `git-cherry-pick.adoc`). Junio’s `Reviewed-by:` can be added to patches 2/6, 3/6, and 6/6 as they are unchanged from v2; patches 4/6 and 5/6 will also be merge-ready once his wording suggestions are applied verbatim.

This is a well-crafted, user-focused effort that addresses a long-standing documentation gap. The new guide’s structure—prioritizing clarity and practical workflows—aligns with the project’s recent documentation improvements (e.g., Jean-Noël Avila’s synopsis-style conversion). The series has no behavioral or on-disk changes and is purely additive. Key technical details include the explicit deprecation of `zdiff3` (noted as ambiguous) and the retention of `git log --merge -p <filename>` as a tool for debugging conflicts. Open questions from earlier iterations (e.g., whether to cover `git apply` conflicts or update `git status` wording) remain deferred to future patches.
