This is a bugfix patch (v2) targeting the fetch subsystem, specifically addressing a regression in shallow fetches when backfilling tags. The patch splits reference transactions into two phases—committing fetched references before backfilling tags—to restore correct negotiation behavior while preserving most of the performance gains from batched updates.

The regression was introduced in commit 0e358de64a ("fetch: use batched reference updates", 2025-05-19), where batched updates delayed committing references until after tag backfilling. In shallow fetches, this caused the client to report no 'have' references during negotiation, forcing the server to send all objects since backfilling lacks a depth limit. The fix ensures the client can report its shallow boundary correctly by committing references before tag backfilling begins.

The patch touches `builtin/fetch.c` and adds a test in `t/t5510-fetch.sh` that directly verifies no objects are refetched beyond the shallow depth. The test was revised from v1 to avoid indirect packet-trace checks, instead using `git cat-file` to inspect repository state. Benchmark results show the fix is 17.38±0.61 times faster than the pre-batched-update behavior, with only a minor slowdown (1.01×) compared to the single-transaction approach.

Review feedback from Patrick Steinhardt and Justin Tobler has been addressed, including adding benchmark comparisons and clarifying the test. The two-transaction approach was confirmed as the correct fix after ruling out simpler alternatives due to protocol constraints requiring negotiation for nested annotated tags. This patch is ready for integration and should resolve the reported regression without introducing new edge cases.
