This is a review comment on Beat Bolli’s second patch in the v2 series for `imap-send`. The patch replaces Git’s manual hostname verification with OpenSSL’s built-in `SSL_set1_host()` API, a cleanup that directly addresses earlier feedback from brian m. carlson about RFC 6125 compliance and maintenance burden.

Aniket Gupta points out a subtle but real user-experience regression: the new code loses the hostname-specific error message that the old manual verification provided. Under the old regime, a hostname mismatch would produce something like “certificate owner does not match hostname ‘imap.example.com’”; the new code, relying on OpenSSL’s `SSL_connect()` failure, only says “certificate verify failed.” While the patch is technically correct and improves RFC compliance, the error message is now less actionable for users debugging connection issues.

The suggestion is straightforward: when `SSL_connect()` fails, the code should still fetch and print the detailed OpenSSL verification result (`SSL_get_verify_result()`) so that users see the same level of detail they did before. This is a small, targeted fix that preserves the patch’s correctness while restoring the lost clarity. No new tests are needed, and the change is uncontroversial in principle. If you care about `imap-send` usability, this is a minor but worthwhile tweak to watch.
