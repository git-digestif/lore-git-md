This is a maintainer's reply to the v3 patch that fixes multi-line secret parsing in the Windows credential helper (`contrib/credential/wincred`). Junio C Hamano, the Git maintainer, is stepping back from reviewing this patch himself, citing confusion over a specific sentence in the commit message: *"Invalid target size check (bytes instead of characters) for `wcsncpy_s` already led to memory corruption; d22a4884 just hid the error by making sure the target is always big enough."*

The sentence is grammatically clear but fails to explain *how* the size check was wrong, *what* memory corruption it caused, or *why* commit d22a4884 (which is not part of this thread) is relevant. Junio describes it as "clear language, obscure meaning" and declines to review further, explicitly deferring to Windows-focused contributors.

The patch itself remains unchanged in v3; only the commit message was updated in response to earlier feedback. Junio’s earlier reviews (on v1 and v2) focused on code readability, wide-character correctness, and minor stylistic issues, all of which the author addressed. However, this final sentence in the commit message appears to have been overlooked or misunderstood during those revisions.

The patch is now effectively blocked until someone with Windows expertise can clarify the commit message or confirm the technical claim. While the code changes are well-structured and address a real bug, the lack of clarity in the commit message risks leaving reviewers uncertain about the patch’s safety and scope. If the sentence is reworded to explain the issue concretely — e.g., "The original code used byte counts instead of character counts when calling `wcsncpy_s`, leading to buffer overreads when parsing multi-line secrets; commit d22a4884 mitigated the symptom but did not fix the root cause" — the patch would likely proceed to `next`. Until then, it remains under review, awaiting input from Windows contributors.
