This is the third patch in Kristofer Karlsson’s four-patch series introducing an incremental connectivity check for Git fetches and pushes. It adds the plumbing for the new `transfer.connectivityCheck` configuration option and wires up the `--verify-trees-incremental` flag in `git rev-list`.

The patch is straightforward: it extends `Documentation/config/transfer.adoc` with a 20-line description of the new `transfer.connectivityCheck` option (accepting `full` or `incremental`), documents the internal `--verify-trees-incremental` flag in `rev-list-options.adoc`, and teaches `builtin/rev-list.c` and `connected.c` to recognize the flag and pass it to the rev-list subprocess when the config is set to `incremental`. The implementation is minimal—`--verify-trees-incremental` currently has no effect, deferring the actual incremental verification logic to the next patch.

The config plumbing is clean and follows established patterns: the option is opt-in, defaults to `full`, and falls back to the full check for deepening fetches (a limitation documented in patch 1/4). The rev-list flag is explicitly marked “for internal use only,” which is appropriate since it is only meant to be used by `check_connected()`. The patch also disables `fetch_if_missing` when the flag is set, preventing lazy fetches during connectivity checks—a safeguard that addresses Junio’s earlier concern about promisor objects.

This patch is a pure plumbing change with no behavior impact; the incremental mode will only become functional once patch 4/4 lands. It is well-scoped, addresses all prior feedback on the config interface, and is ready for review. Given the series’ history and the author’s thorough response to earlier comments, this piece is likely to land as-is.
