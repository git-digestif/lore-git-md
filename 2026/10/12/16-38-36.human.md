This is a maintainer response to Phillip Wood’s review of the `git blame` default ignore-revs file series (v3). Junio acknowledges Phillip’s two concerns: the decision to ignore uncommitted changes to `.git-blame-ignore-revs` and the lack of a size limit in the `oidset` parser.

On the uncommitted changes issue, Junio is neutral. He notes that the current behavior (reading only the committed `HEAD` blob) aligns with how hosting platforms like GitHub and GitLab operate, but he also concedes that consulting the working-tree file might feel more intuitive to users. This leaves the door open for the author (Ravi Mistry) to adjust the implementation if they choose, though Junio does not explicitly request a change.

On the size limit concern, Junio agrees this is worth addressing. The `oidset` parser’s lack of an explicit cap could theoretically allow memory exhaustion from maliciously large blobs, even if the 32-bit entry count in `khash` makes this unlikely in practice. This is a **security and robustness improvement** that should be straightforward to implement.

The response is brief but carries weight: Junio’s agreement on the size limit suggests it will likely be addressed before the series graduates to `master`. The uncommitted changes issue remains unresolved but is now framed as a usability trade-off rather than a technical flaw. No new objections or technical concerns are raised.
