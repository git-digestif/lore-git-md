This is a follow-up to the `git checkout -m` conflict label preservation series, specifically addressing Junio’s performance optimization suggestion. Phillip Wood incorporates Junio’s proposed refactoring patch into his v3 series, introducing a `struct checkout_merged_data` to cache per-invocation constants like `merge.renormalize` and `conflict_style`. The change eliminates redundant config reads and file I/O for `.git/MERGE_LABELS` during a single `git checkout -m` invocation, which is a measurable improvement when many conflicted paths exist.

The patch is a pure refactoring with no user-visible behavior change. It touches only `builtin/checkout.c`, adding `checkout_merged_prepare()` and `checkout_merged_release()` functions to initialize and clean up the cached data. The core logic in `checkout_merged()` is updated to use the precomputed values instead of repeatedly querying the configuration or reading the labels file. Phillip’s implementation follows Junio’s diff closely, with minor adjustments (e.g., initializing `checkout_merged_data` to zero and setting `conflict_style` after preparation).
