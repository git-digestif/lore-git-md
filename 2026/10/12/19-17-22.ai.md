This is the **v4 revision of a feature patch series** that makes `git blame` and `git annotate` automatically use `HEAD:.git-blame-ignore-revs` as the default ignore-revs file when no explicit ignore file is configured. The series is now **approved for integration** into `next` and addresses all prior feedback, including a new **100MB size cap** on the ignore-revs blob to prevent memory exhaustion from maliciously large files.

The core change remains the same: aligning local `git blame` behavior with hosting platforms (GitHub, GitLab) that already respect `.git-blame-ignore-revs` by default. The v4 revision adds a **security-hardened size limit** (matching Git’s existing `ATTR_MAX_FILE_SIZE` for `.gitattributes`) via `odb_read_object_info()` before loading the blob into memory. This ensures oversized blobs are skipped with a warning, addressing Junio’s earlier scalability concern without requiring a separate parser pass. The implementation still reads the *committed* `HEAD` blob (not the working-tree file), which matches hosting platform behavior but may surprise users who expect uncommitted changes to take effect.

Key technical details:
- **Files touched**: `builtin/blame.c`, `oidset.c`, `oidset.h`, `Documentation/blame-options.adoc`, `Documentation/config/blame.adoc`, and `t/t8013-blame-ignore-revs.sh`.
- **New hardening**: The size cap (`IGNORE_REVS_MAX_FILE_SIZE = 100MB`) is enforced via `odb_read_object_info()`, preventing memory exhaustion from maliciously large blobs. The check is performed before loading the blob, avoiding unnecessary I/O.
- **Behavior**: The default blob is parsed in-memory via `oidset_parse_buffer_carefully()`, which shares line-parsing logic with the existing file-based parser. Non-regular tree entries (e.g., symlinks, subdirectories) are skipped via `S_ISREG()`.
- **Precedence**: The default blob is added *before* user-configured ignore files, ensuring user overrides take precedence. Empty `blame.ignoreRevsFile` or `--ignore-revs-file ""` bypasses the default entirely.
- **Tests**: New coverage for oversized blobs (via `EXPENSIVE`), subdirectory invocations, bare repositories, and CLI/config overrides. The test for oversized blobs uses `dd` to generate a 101MB zero-filled blob, verifying the warning and skip behavior.

The series is **feature-complete** and resolves all prior technical objections. The only remaining open question is whether to adjust the uncommitted-changes handling (currently ignored for consistency with hosting platforms), but this is a **user-experience trade-off** rather than a blocker. The size cap and security hardening (NUL-byte rejection, promisor fetch prevention, tag type verification) are now robust and unlikely to require further changes. Junio’s approval and the lack of new objections suggest this is ready for `next`.
