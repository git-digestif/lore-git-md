This is the **core API patch** in Christian Couder’s v3 series introducing `early_scan_options()`, a new `parse-options` sub-API for safely scanning command-line arguments early. The patch is part of a well-structured, thoroughly tested series that addresses a real bug in `git fast-import` (where `--allow-unsafe-features` was ignored when preceded by `--depth 5`) while providing a reusable solution for other commands with similar needs.

The implementation reuses `parse-options` internals (`lookup_long_opt()`) to handle negated options, unambiguous abbreviations, and aliases consistently with `parse_options()`. The scan is deliberately cautious: it stops at short options, unknown options, ambiguous abbreviations, and low-level callbacks to avoid misinterpreting option values, ensuring it never reports false positives. This trade-off prioritizes correctness over completeness and is clearly documented in the API limitations. The patch includes comprehensive test coverage for edge cases (stuck values, negated options, ambiguous abbreviations) and integrates with the existing test suite via a new `test-parse-options --early-scan-options` helper.

The API is designed for simplicity and safety, avoiding the complexity of a full "dry-run" mode in `parse_options()`. While this means callers must handle argument skipping themselves (a usability concern noted in Junio’s v2 feedback), the current design is a deliberate choice to keep the API fast and predictable. The patch is **ready for `next`** from a technical standpoint, though the broader API design may require further iteration to address lingering usability questions before wider adoption. Maintainers of commands with hand-rolled early scans (e.g., `git bisect`, `git rev-parse`) should take note—this series offers a cleaner, safer alternative.
