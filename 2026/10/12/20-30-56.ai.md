This is a small, targeted patch that updates `git imap-send` to use the modern OpenSSL API. It replaces the deprecated `SSLv23_method()` with `TLS_method()`, which has been the recommended function since OpenSSL 1.1.0. The change is purely mechanical—two lines swapped, one error message updated—and touches only `imap-send.c`.

The motivation is straightforward: OpenSSL has been deprecating older TLS initialization functions for years, and this patch keeps Git from relying on APIs that may disappear in future OpenSSL releases. The commit message is concise but sufficient; it cites the deprecation timeline and the replacement function without over-explaining.

This is the first patch in a two-patch v2 series (the cover letter is not included here). The earlier three-patch v1 series addressed OpenSSL 4.1 compatibility, ASN1_STRING safety, and RFC 6125 compliance; this v2 appears to be a narrower follow-up, possibly splitting off the uncontroversial TLS_method change from the more debated parts of the original series.

No test failures or regressions are expected—this is a compile-time API swap that should not alter runtime behavior. If you care about OpenSSL compatibility or `git imap-send`, this patch is a safe, incremental step forward.
