This is a platform compatibility bugfix targeting a macOS-specific issue in Git's CRLF conversion handling. The patch picks up work originally started by Curtis Allen Smith and refines it into a minimal, focused fix for a subtle edge case: when a file's size changes during content conversion (e.g., CRLF normalization), Git should not trust the new size if conversion is still active, as this can lead to incorrect buffer handling.

The core problem occurs in `read-cache.c` when Git processes index entries. If a file's size changes mid-conversion (for example, due to CRLF expansion or contraction), the code currently updates its internal tracking of the file's size. On macOS, this can cause issues with character encoding conversions (particularly ISO-2022-JP, as seen in the earlier thread), but the patch here addresses a more general concern: size changes during conversion should not be trusted until conversion completes. The fix adds a 25-line change to `read-cache.c` that prevents updating the cached file size while conversion is in progress, along with a new test in `t/t0020-crlf.sh` that exercises the edge case.

This is a follow-up to the earlier two-patch series that addressed a macOS iconv bug in ISO-2022-JP conversion, but it tackles a different (though related) issue. The earlier series introduced a workaround for macOS's iconv implementation losing state during buffer resizing; this patch instead prevents Git from acting on size changes that occur *during* conversion, which could trigger similar issues. The commit message is still rough ("bumpy" in the author's own words), and the author invites suggestions for improvement, but the technical approach is clear: avoid trusting size changes until conversion finishes.

The patch removes the configuration switch from the original proposal, opting for a simpler, always-on fix. This aligns with Git's historical approach to platform-specific workarounds (e.g., the earlier iconv fix), where the workaround is enabled automatically when needed rather than requiring user configuration. The author has taken ownership of the patch and added Curtis Allen Smith's `Signed-off-by`, which is procedurally correct for incorporating prior work.

Testing appears solid: all tests pass, and the new test in `t0020-crlf.sh` is thorough, covering the edge case with 45 lines of new test code. The patch is narrowly scoped to `read-cache.c` and the test suite, avoiding broader changes to the conversion infrastructure. While the commit message could be clearer, the code itself is straightforward and well-documented. This looks like a sensible, low-risk fix for a real (if niche) issue, and it advances the earlier discussion about macOS-specific conversion quirks.
