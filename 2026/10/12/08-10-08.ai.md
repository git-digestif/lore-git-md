This is the **core API patch (3/6)** in Christian Couder’s `early_scan_options()` series, now in its **v3 iteration**. The email is a **substantive reply** to Kaartic Sivaraam’s v2 review, detailing how the v3 redesign addresses the feedback by reusing `parse-options` internals (`lookup_long_opt()`) to handle negated options, unambiguous abbreviations, and aliases consistently with `parse_options()`. The scan now **stops at ambiguous abbreviations, short options, unknown options, and low-level callbacks** to avoid misinterpreting values, erring on the side of caution. The API’s behavior is now **fully aligned with `parse_options()`** for the cases it handles, and the changes are **well-tested** (28 new tests in `t/t0040-parse-options.sh`).

Key improvements in v3:
- **Abbreviations and negated options**: The scan now uses `lookup_long_opt()` to handle unambiguous abbreviations (e.g., `--export-pack` for `--export-pack-edges`) and negated options (`--no-<name>`), matching `parse_options()` behavior. Ambiguous abbreviations cause the scan to stop.
- **Safety**: The scan stops at unrecognized arguments, short options, and low-level callbacks, avoiding misinterpretation of option values. This addresses Kaartic’s concern about commands like `git fast-import --quiet --export-pack --allow-unsafe-features`, where `--allow-unsafe-features` could previously be misread as an option instead of a value for `--export-pack-edges`.
- **Edge-case handling**: The API now correctly handles `PARSE_OPT_LASTARG_DEFAULT` options (using the default value when the option is the last argument) and stops at missing values for required arguments (e.g., `test-tool early-scan-options --wanted-value`). The return index is now consistent, always pointing to the first unconsumed argument.
- **Test coverage**: Expanded tests cover stuck/separate values, negated options, ambiguous abbreviations, non-options, and low-level callbacks. A new `--stop-at-found` flag in the test helper verifies the return index behavior.

The API remains **deliberately simple**—it does not resolve aliases or handle subcommands—but its cautious approach (stopping at ambiguity) ensures correctness. The **usability concern** raised by Junio in v2 (caller responsibility for argument skipping) is unchanged in v3, but the API’s limitations are now **clearly documented** in `parse-options.h` and `api-parse-options.adoc`. The preparatory refactorings (patches 1/6 and 2/6) and the `git fast-import` bugfix (patch 4/6) are **ready for `next`**, but the core API (this patch) may need further iteration to resolve the argument-skipping question before proceeding.

This patch is **technically sound** and addresses all of Kaartic’s v2 feedback. The changes are **mechanical and well-motivated**, with thorough test coverage. The remaining open question (caller vs. callee responsibility for argument skipping) is the **primary blocker** for merging the API to `next`. The series as a whole is **closer to readiness**, but this patch is not yet ready for `next` without further discussion.
