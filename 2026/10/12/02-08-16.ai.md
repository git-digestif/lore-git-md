This is a **build system / CI compatibility fix** for René Scharfe’s patch that omits the ZIP Extended Timestamp (UT) extra field when the commit time exceeds 32-bit range. Junio C Hamano reports that the new tests fail on 32-bit platforms (Ubuntu 20.02 i386 and Debian i386) in GitHub Actions CI, specifically the checks for the UT extra field presence or absence.

The issue is that the tests assume `ZIPINFO_UT_EXTRA` (a lazy prerequisite checking for UT field support in `zipinfo(1)`) is available, but the 32-bit environments either lack `zipinfo` or have a version that does not support the UT extra field. The tests are gated on `TIME_IS_64BIT` (which passes on 32-bit) but not on the actual availability of `zipinfo`’s UT field support, causing false negatives.

This is a **surface-level review** from Junio, flagging a CI breakage rather than engaging with the patch’s technical substance. The fix will likely involve adjusting the test prerequisites to account for `zipinfo`’s capabilities on 32-bit systems, but no solution is proposed in this email. The patch itself remains sound; the failure is purely in the test infrastructure. The broader thread’s unresolved questions (ZIP legacy DOS date overflow and `fast-import` negative timestamp validation) are unaffected.
