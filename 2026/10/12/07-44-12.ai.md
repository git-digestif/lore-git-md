This is the **core API patch (3/6)** in Christian Couder’s `parse-options` early-scanning series. It introduces `early_scan_options()`, a new helper designed to replace hand-rolled early argument scans in Git commands. The patch is part of a **bugfix and API refactoring** effort targeting the argument-parsing subsystem.

The implementation reuses `parse-options` internals (`lookup_long_opt()` and `parse_options_takes_argument()`) to handle negated options, unambiguous abbreviations, and aliases consistently with `parse_options()`. The scan stops at arguments it cannot reliably skip—short options, unknown options, ambiguous abbreviations, low-level callbacks—to avoid misinterpreting option values. This cautious approach ensures the scan never reports false positives, though it may miss some options that `parse_options()` would accept. The behavior is documented in `parse-options.h` and `api-parse-options.adoc`, and the API is exercised by comprehensive tests in `t/t0040-parse-options.sh`.

Key technical details:
- **New flag**: `PARSE_OPT_EARLY` marks options to be reported during early scanning.
- **New function**: `early_scan_options()` scans arguments using the same `struct option` array as `parse_options()`, ensuring consistency in option recognition and value consumption.
- **Behavior**: The scan stops at `--`, `--end-of-options`, short options, unknown options, ambiguous abbreviations, and low-level callbacks. It also stops at non-options if `EARLY_SCAN_STOP_AT_NON_OPTION` is set (matching `PARSE_OPT_STOP_AT_NON_OPTION`).
- **Edge cases**: The scan handles stuck values (`--option=value`), negated options (`--no-option`), and `PARSE_OPT_LASTARG_DEFAULT` options. It does not skip optional values (`PARSE_OPT_OPTARG`) unless they are stuck to the option.
- **Tests**: The patch adds 28 new tests covering stuck/separate values, negated options, ambiguous abbreviations, non-options, and low-level callbacks. The test helper `test-parse-options --early-scan-options` exercises the API with these edge cases.

The patch is **well-structured and thoroughly tested**, with clear commit messages explaining design trade-offs. The v3 redesign addresses v2 feedback by reusing `parse-options` internals and stopping at ambiguous abbreviations, short options, and unknown options to avoid misinterpreting values. The API’s cautious approach prioritizes correctness over completeness, and its limitations are documented.

The patch is **ready for review** but not yet ready for `next` due to lingering usability concerns (e.g., caller responsibility for argument skipping). The preparatory refactorings (patches 1/6 and 2/6) are uncontroversial and could proceed independently. The series as a whole is worth attention from maintainers of commands with hand-rolled early scans (e.g., `git bisect`, `git rev-parse`).
