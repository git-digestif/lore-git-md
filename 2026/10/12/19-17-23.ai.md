This is the first patch in the **v4 series** that hardens the ignore-revs parser and tag-peeling logic in `git blame` before enabling the default `HEAD:.git-blame-ignore-revs` lookup. The changes address security concerns raised in prior reviews, particularly around **NUL-byte injection** and **promisor fetches in partial clones**, while adding test coverage for edge cases.

The patch modifies `oidset_parse_file_carefully()` in `oidset.c` to reject any line containing an embedded NUL byte using `memchr()`, preventing silent truncation of object names (e.g., `<oid>\0garbage`). In `builtin/blame.c`, `peel_to_commit_oid()` is hardened to avoid triggering promisor fetches for missing tag targets by using `odb_read_object_info_extended()` with `OBJECT_INFO_SKIP_FETCH_OBJECT` and `OBJECT_INFO_QUICK`. The function now also verifies each tag’s declared type before parsing, preventing type confusion attacks.

Test coverage is expanded in `t/t8013-blame-ignore-revs.sh` to verify:
1. Rejection of lines with NUL bytes (both mid-line and in comments).
2. Correct peeling of chained tags (e.g., `D_TAG2 -> D_TAG1 -> D`).
3. Graceful handling of missing tag targets in partial clones, ensuring no network requests are triggered.

The hardening is **necessary** for the upcoming default blob lookup (patch 2/2), as `HEAD:.git-blame-ignore-revs` could be attacker-controlled in shared repositories. The changes are **minimal and targeted**, avoiding behavior changes for existing users while closing security gaps. No new symbols are introduced, and the modifications align with Git’s existing security practices (e.g., `ATTR_MAX_FILE_SIZE` for `.gitattributes`). The patch is **well-tested** and addresses all prior feedback, including Junio’s scalability concerns about large blobs (handled in patch 2/2).
