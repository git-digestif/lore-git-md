This is the second patch in Beat Bolli’s v2 series for `imap-send`, targeting OpenSSL compatibility. It replaces Git’s manual hostname verification logic with OpenSSL’s built-in `SSL_set1_host()` API, available since OpenSSL 1.1.0. The change removes 72 lines of custom code (including the `host_matches()` and `verify_hostname()` helpers) and replaces them with a handful of OpenSSL-native calls.

The patch directly addresses brian m. carlson’s two concerns from the v1 series: (1) the manual verification code was incomplete (it did not handle IP-type SANs), and (2) it was suboptimal compared to OpenSSL’s native function. By switching to `SSL_set1_host()`, Git now automatically supports all SAN types (DNS, IP, email, etc.) and benefits from future OpenSSL improvements without further maintenance burden. The error reporting is also improved: OpenSSL’s `X509_verify_cert_error_string()` provides more detailed failure messages than the previous generic "certificate owner does not match hostname" output.

The patch is narrowly scoped to `imap-send.c` and does not affect any other part of Git. It is uncontroversial in principle—brian m. carlson explicitly suggested this approach in the v1 thread—but the implementation details (e.g., the `X509_CHECK_FLAG_NO_PARTIAL_WILDCARDS` flag) may still draw review scrutiny. No new tests are introduced, as the existing test suite does not exercise the edge cases this patch fixes; the change is effectively a compile-time swap with no expected runtime behavior change beyond stricter RFC 6125 compliance.

This patch is ready to proceed independently of the rest of the v1 series, which remains blocked on memory-safety and OpenSSL 4.1 compatibility issues. If you care about `imap-send` or OpenSSL integration, this is a clean, well-motivated cleanup that removes technical debt while improving correctness. The commit message clearly explains the rationale and cites the OpenSSL Wiki, making it easy to assess without digging into the code.
