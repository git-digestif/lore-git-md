This is the first patch in a now-ready-to-merge documentation series introducing `gitmergeconflicts(7)`, a new man page that consolidates Git’s scattered merge-conflict guidance into a single, user-friendly guide. The patch creates the new page (330 lines) and wires it into the build system (`Makefile`, `meson.build`, `.gitattributes`, `command-list.txt`).

The new guide is structured as a practical walkthrough: it starts with a clear definition of what a merge conflict is, lists every command that can trigger one (`git merge`, `git rebase`, `git cherry-pick`, `git pull`, `git revert`, `git am -3`, `git checkout -m`, `git stash pop`), and then walks through resolution step-by-step—identifying markers, editing files, staging changes, and continuing the operation. Key improvements over the current scattered documentation include consistent terminology (“ours” vs. “theirs” tied explicitly to `HEAD` and the other commit), side-by-side examples of `diff3` vs. `zdiff3` (with `zdiff3` explicitly deprecated), and a dedicated section on tools like `git diff AUTO_MERGE` and `git log --merge -p <filename>`. The guide also standardizes the modern `--abort`/`--continue` workflow across commands, replacing older phrasing like “reverse 2. and clean up 3.” that has confused users for years.

This patch is purely additive—no behavior or on-disk changes—and is the centerpiece of a six-patch series that surgically replaces duplicated conflict-resolution sections in existing man pages with cross-references to the new guide. Junio’s final review requested only two refinements (an exhaustive command list and formal tone), both of which are now incorporated. The series has broad support, with substantive reviews from D. Ben Knoble, Patrick Steinhardt, and Jeff King, and all mechanical blockers (e.g., `make check-docs`) resolved. The new guide’s clarity and completeness make it a standout documentation improvement that should benefit users immediately.
