This is the second patch in a two-patch feature series that makes `git blame` and `git annotate` automatically use `HEAD:.git-blame-ignore-revs` as the default ignore-revs file when no explicit ignore file is configured. The series is now approved for integration into `next` and addresses all prior feedback, including a 100MB size cap on the ignore-revs blob to prevent memory exhaustion.

The patch implements the core behavior: when no ignore-revs file is specified via `--ignore-revs-file` or `blame.ignoreRevsFile`, Git now checks for a `.git-blame-ignore-revs` blob in the `HEAD` tree. If the blob exists and is a regular file (not a symlink or subdirectory), its contents are parsed in-memory and added to the ignore list before any user-configured files. This ensures local `git blame` behavior matches hosting platforms like GitHub and GitLab, which already respect this file by default. The implementation is careful to skip non-regular tree entries, enforce the 100MB size limit, and handle edge cases like malformed input or uncommitted working-tree changes.

The commit message provides a clear rationale: the feature was originally deferred to avoid unexpected behavior, but `.git-blame-ignore-revs` has since become an ecosystem standard, making the mismatch between local and hosted blame results a frequent pain point. The patch is well-motivated and aligns with real-world usage. The security hardening (size cap, NUL-byte rejection, promisor fetch prevention) and thorough test coverage (subdirectory invocations, bare repositories, CLI/config overrides, oversized blobs) suggest this is a robust, production-ready change.

The only remaining open question is whether to adjust the uncommitted-changes handling. Currently, the patch always reads the *committed* `HEAD` blob, ignoring uncommitted changes to `.git-blame-ignore-revs` in the working tree. Junio justifies this as matching hosting platform behavior, but Phillip Wood considers it a user-experience regression. This is a minor trade-off rather than a technical blocker, and the patch’s approval status indicates the current approach is acceptable.

For developers, this means `git blame` will now "just work" with ignore-revs files without manual configuration, reducing friction for projects that already use `.git-blame-ignore-revs`. The change is backward-compatible: users can still override the default with `--ignore-revs-file ""` or `blame.ignoreRevsFile=""`. The patch is worth watching if you work on large projects with formatting commits or rely on blame attribution.
