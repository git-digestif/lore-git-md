This is the **performance test patch** (2/4) in Kristofer Karlsson’s four-part series introducing an incremental connectivity check for Git fetches and pushes. The patch adds benchmarks to measure the existing `rev-list` connectivity check across three dimensions: total repository size, number of incoming commits, and files changed per commit.

The new test script (`t/perf/p5413-connectivity-check.sh`) and its companion Perl generator create synthetic repositories with flat directory structures (e.g., 8,000 directories × 100 files each) and varying commit histories (from 1 to 10,000 commits). Each test fixture isolates one variable—such as repository size or commit count—while holding the others constant, allowing clear measurement of how the connectivity check scales. The generator uses `git fast-import` to build the repositories efficiently, and the test script runs `git rev-list --objects --stdin --not --all` to simulate the connectivity check without pack transfer overhead.

This patch directly supports the series’ goal by establishing baseline performance metrics for the current full connectivity check. The benchmarks will later be used to compare against the new incremental mode (introduced in patch 4/4), demonstrating its speedup for small pushes to large repositories and identifying edge cases where the incremental mode falls back to the full check. The test design is thorough, covering a wide range of repository sizes (5,000 to 800,000 files) and commit counts (1 to 10,000), which should help reviewers assess the incremental mode’s tradeoffs.
