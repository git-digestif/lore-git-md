This is a **feature patch** that makes `git blame` and `git annotate` automatically use `HEAD:.git-blame-ignore-revs` as the default ignore-revs file when no explicit ignore file is configured. The v4 revision of this two-patch series is now **approved for integration** and addresses all remaining feedback from the maintainer and reviewers.

The core change aligns local `git blame` behavior with hosting platforms like GitHub and GitLab, which already respect this file by default. This eliminates the need for users to manually configure `blame.ignoreRevsFile` in every clone, reducing friction for a widely adopted ecosystem convention. The implementation is careful: it reads the *committed* blob (not the working-tree file), skips non-regular tree entries (e.g., symlinks), and ensures user-configured ignore files take precedence. The default blob is added to the ignore-revs list *before* any user-specified files, so an empty `blame.ignoreRevsFile` or `--ignore-revs-file ""` will bypass it entirely.

The v4 revision adds a critical **security safeguard**: the default ignore-revs blob is now capped at 100MB (matching Git’s existing limit for `.gitattributes` files) to prevent memory exhaustion from maliciously large blobs. The patch uses `odb_read_object_info()` to check the blob size *before* loading it into memory, issuing a warning and skipping oversized blobs without parsing them. This addresses Junio’s earlier concern about scalability while maintaining the feature’s usability.

The series also includes **hardening** for the ignore-revs parser and tag-peeling logic (patch 1/2). The parser now rejects lines containing NUL bytes (via `memchr()`), and the tag-peeling code prevents promisor fetches in partial clones by using `OBJECT_INFO_SKIP_FETCH_OBJECT` and `OBJECT_INFO_QUICK`. It also verifies each tag’s declared type before parsing to avoid type confusion. These changes were prerequisites for exposing the parser to upstream-controlled content at a well-known path.

Test coverage is thorough, including edge cases like subdirectory invocations, bare repositories, uncommitted working-tree files, CLI/config overrides, and committed symlinks. The new test for oversized blobs (marked `EXPENSIVE`) ensures the size cap works as intended. Documentation updates clarify the new behavior and override semantics.

The only **remaining loose end** is the handling of uncommitted changes to `.git-blame-ignore-revs`. The current implementation always reads the committed `HEAD` blob, ignoring uncommitted changes in non-bare repositories. Junio justifies this as matching hosting platform behavior, but Phillip Wood has noted it as a **user-experience regression** compared to `.gitattributes`. No explicit request for change has been made, but the door remains open for future adjustment.

This is a **well-crafted, feature-complete** change that addresses a real usability gap. The security hardening, size cap, and careful precedence rules make it safe for integration. If you use `git blame` and collaborate on platforms like GitHub or GitLab, this patch will make your local workflow more consistent with what you see on the web.
