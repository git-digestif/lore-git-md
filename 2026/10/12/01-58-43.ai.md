This is the implementation series for the `includeIf.hostname:<pattern>` feature, following up on the earlier RFC discussion. Isabella Caselli has sent a three-patch series that adds the new condition and a `git var GIT_HOSTNAME` debugging aid, building directly on Ignacio Encinas’s stalled 2024 v3 work with his explicit permission.

The patches touch `config.c` (core logic), `t1305-config-include.sh` (tests), and documentation (`config.adoc`, `git-var.adoc`). The implementation adopts the 2024 consensus that hostname matching is system-dependent—Git uses whatever the system reports, whether short name or FQDN, and documents this behavior rather than enforcing normalization. The new `git var GIT_HOSTNAME` command exposes Git’s interpretation to users, replacing the dropped `test-tool xgethostname` helper. Tests now use `git var GIT_HOSTNAME || echo unknown` to avoid silent failures when the hostname cannot be determined.

One open question remains: whether hostname matching should be case-sensitive. The current implementation matches exactly, like `includeIf.onbranch:`, but Isabella notes that DNS names are case-insensitive and asks whether to retain the current behavior, ignore case, or add a `hostname/i:` variant. No other loose ends are apparent; the series appears ready for review and addresses all prior feedback from Peff, Junio, and Eric Sunshine.
