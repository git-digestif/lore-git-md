This is a documentation patch updating the `SubmittingPatches` guidelines. The author, Jon Simons, has accepted Junio C Hamano’s suggested revision to the proposed text, replacing the original two-line explanation with a single, more direct sentence: *"A bugfix patch should include tests in `test_expect_success()` blocks that demonstrate the breakage when the code change that implements the fix is omitted."*

The change formalizes an existing reviewer preference—avoiding the anti-pattern of splitting a test and its corresponding fix into separate commits (e.g., one introducing a `test_expect_failure` and a later commit converting it to `test_expect_success`). Junio’s feedback was substantive, focusing on clarity and removing ambiguity that could imply endorsement of `test_expect_failure` as a submission tool. The revised phrasing aligns with the project’s emphasis on self-contained, reviewable commits where the test and fix are presented together in the diff context.

No technical objections or edge cases were raised; the discussion remains narrowly scoped to wording. The patch is now likely to proceed as a v2 with the updated text. Key terms for future reference include `test_expect_success`, "diff context," and the concept of self-contained bugfix commits.
