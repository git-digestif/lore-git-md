This is a documentation patch to the contribution guidelines, specifically updating the `SubmittingPatches` file to discourage the anti-pattern of splitting a test and its corresponding bugfix into separate commits. Junio C Hamano, the maintainer, has just replied to Jon Simons' v2 patch with a final review comment.

Junio suggests condensing the first two sentences of the new guideline text, which currently read: *"A bugfix patch should include tests in `test_expect_success()` blocks that demonstrate the breakage when the code change that implements the fix is omitted. Submit tests as `test_expect_success` in the same commit as your code change that fixes the bug."* He proposes a more concise alternative: *"A bugfix patch should add, in the same commit, code change and `test_expect_success()` blocks that demonstrate the breakage when the fix is omitted."* Junio also notes that the latter half of the paragraph—explaining why this approach is preferable—might be unnecessary, as the guideline is meant to be prescriptive rather than pedagogical. However, he acknowledges that the discussion is reaching "diminishing returns" and will queue the patch as-is.

The patch remains uncontroversial and aligns with the project’s established preference for self-contained, reviewable commits. Junio’s feedback is surface-level, focusing on wording clarity rather than the substance of the guideline. The change is now effectively ready to proceed, pending Junio’s final integration. No further discussion or objections are expected.
