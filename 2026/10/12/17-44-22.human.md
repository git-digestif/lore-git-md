This is a brief follow-up in the ongoing discussion about extending `git branch --delete-merged` to detect squash-merged and rebase-merged branches. The author, Harald Nordgren, acknowledges Junio C Hamano’s suggestion to reuse the commit-matching logic from `git range-diff`—specifically its use of log-message similarity and authorship information—to improve rebase detection. Harald agrees that authorship could serve as a useful filter to quickly rule out mismatches, which would help performance. This reply is purely procedural; it does not address the larger architectural questions Junio raised (splitting the series, CLI scalability, or whether squash detection should be implemented at all) or the algorithmic trade-offs Phillip Wood and D. Ben Knoble have highlighted. The thread remains focused on refining the rebase-detection approach before any code changes are made.
