This is the second patch in Christian Couder’s v3 series introducing a new `parse-options` sub-API for early argument scanning. It extracts `lookup_long_opt()` from the existing `parse_long_opt()` function to enable safe, side-effect-free lookups of long options, including unambiguous abbreviations and negated forms.

The patch is a clean refactoring with no intended behavior change. It splits `parse_long_opt()` into two parts: `lookup_long_opt()` performs the lookup and returns an enum indicating whether the match was exact, an unambiguous abbreviation, ambiguous, or unknown, while `parse_long_opt()` now calls `lookup_long_opt()` and acts on the result (e.g., calling `get_value()`, `die()`, or `error()`). The new helper is designed to be reused by the upcoming `early_scan_options()` API, which needs to scan arguments without modifying state or calling `die()`.

The implementation is straightforward and well-documented, with clear commit messages explaining the design. The patch touches only `parse-options.c` and adds a new enum (`long_opt_lookup`) and struct (`parsed_option`) to pass lookup results back to the caller. The changes are mechanical and preserve the existing logic for handling exact matches, abbreviations, and negated options.

This patch is uncontroversial and ready for `next`. It lays the groundwork for the core API patch (3/6) and should proceed independently of any further iteration on the broader series. The refactoring is a necessary step to address v2 feedback about handling abbreviations and negated options consistently with `parse_options()`.
