This is the **plumbing patch** in the four-part series introducing incremental connectivity checks for Git fetches and pushes. It adds the `transfer.connectivityCheck` configuration option (accepting `full` or `incremental`) and wires up the `--verify-trees-incremental` flag in `git rev-list`, though the flag has no effect yet—the actual incremental verification logic will arrive in the next patch (4/4).

The patch touches four files: `Documentation/config/transfer.adoc` (20 lines of new documentation), `Documentation/rev-list-options.adoc` (6 lines marking the flag as internal), `builtin/rev-list.c` (4 lines to parse the flag and disable `fetch_if_missing`), and `connected.c` (24 lines to read the config and conditionally enable the flag). The config plumbing is straightforward: `check_connected()` now checks `transfer.connectivityCheck` and, if set to `incremental` and not a deepening fetch, passes the new flag to its `rev-list` subprocess. The flag is explicitly marked for internal use only, preventing accidental exposure to end users.

This patch is a pure setup step—no behavior changes yet—but it is critical for the series’ architecture. The config key (`transfer.connectivityCheck=incremental`) is the user-facing toggle, while the `rev-list` flag (`--verify-trees-incremental`) is the internal hook for the incremental verifier. The patch also disables `fetch_if_missing` when the flag is used, ensuring the subprocess does not trigger lazy fetches in partial clones, which would violate the connectivity check’s assumptions.
