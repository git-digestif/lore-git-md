This is a performance optimization for `git pack-objects` that reduces the number of objects sent during a push or fetch by inspecting receiver-known commits without walking their full history.

The patch introduces a new `--inspect-have <commit>` option for `git pack-objects`. When supplied, Git compares the root trees of the receiver-known commits with the outgoing commits' trees using sparse tree marking. This lets Git identify shared objects (blobs or subtrees) that the receiver already has, so they can be excluded from the pack without traversing the entire commit history of those receiver-known commits. The optimization is skipped in partial clones to avoid fetching missing trees.

The implementation adds plumbing to carry the selected commit tips through the object database pack-generation options, resolves the commits in `pack-objects` (where replacement refs are already disabled), and uses the existing `mark_trees_uninteresting_sparse()` machinery to prune identical or receiver-only subtrees. The patch includes thorough test coverage for edge cases: identical root trees, shared blobs under different roots, retained changed objects, subtree pruning, non-commit input rejection, partial clone fallback, and shared objects in earlier outgoing commits.

This is part 2 of a 3-patch series. The commit message and tests suggest the optimization is well-motivated and carefully implemented, with clear attention to correctness and edge cases. The change is narrowly scoped to the pack-objects enumeration path and does not affect bitmap-based enumeration, so it should not introduce regressions in existing workflows.
