This thread is about a documentation patch from Edson that aims to clarify how partial clone handles promisor remotes—specifically, the two-pass fetch order (server-advertised remotes first, then configured ones) and the security model for accepting untrusted remotes via `promisor.acceptFromServer` and `promisor.acceptFromServerUrl`. The patch currently touches only `Documentation/technical/partial-clone.adoc` and doesn’t change any code or on-disk formats.

The patch hit a procedural snag: it doesn’t apply cleanly to either the latest release (Git 2.56.0) or the current `master` branch. Junio, the maintainer, noted that while the commit message describes the two-pass fetch order, the diff itself only adds the security model section—the fetch order lines appear as context (already present in the author’s base tree), meaning the patch was built against a non-standard branch. Junio asked Edson to rebase the patch onto a published tree (like Git 2.56.0 or `master`) and, if the base is unusual, to explicitly state its dependencies, following Patrick Steinhardt’s recent ODB series as an example. No technical objections have been raised; this is purely about submission mechanics. The patch remains under review, with no merge status or further feedback yet.
