This thread is a two-patch series from Kaartic Sivaraam aimed at fixing a compatibility issue in Git's `clar`-based unit test framework. The problem occurs when `meson test` passes the `-l` (long tests) flag to the test runner, which doesn't recognize it, causing failures. The series prepares for this fix by first reorganizing existing NOOP arguments in alphabetical order (patch 1) before adding the new `-l`/`--long-tests` argument (patch 2).

The first patch is a minor but deliberate refactoring of `t/unit-tests/unit-test.c`, moving `--with-dashes` to maintain alphabetical order—a convention established by an earlier commit (9faf3963b6). This sets the stage for the second patch, which will add the new argument to resolve the `meson test` compatibility issue. The series is still under review, with no feedback yet, but the changes are self-contained and verified in CI. The goal is to ensure the test runner gracefully ignores unrecognized flags without breaking existing workflows.
