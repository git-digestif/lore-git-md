This is the second patch in a two-patch test infrastructure series from Kaartic Sivaraam. It adds support for ignoring the `-l`/`--long-tests` argument in the `clar`-based unit test framework, following the pattern established by an earlier commit (9faf3963b6). The issue arises when users run `meson test -v --test-args='-ilx'`, where the `-l` flag (intended for `meson` to run long tests) is incorrectly passed to the `unit-test` binary, causing it to fail with "unknown switch `l'".

The fix is minimal—just one line added to the `noop_args` array in `t/unit-tests/unit-test.c`—and aligns with the project’s established approach for handling compatibility arguments. The commit message clearly explains why this doesn’t affect CI (which uses `GIT_TEST_LONG` instead of the command-line flag) and confirms the change has been tested in GitHub and GitLab CI pipelines without issues. The patch is well-motivated and uncontroversial, addressing a usability hiccup without introducing new complexity. If you care about smooth test infrastructure, this is a small but worthwhile fix.
