This is a "What's cooking" report excerpt from Junio C Hamano, summarizing topics that have graduated to the `master` branch since the last report. Here’s what made it into the upcoming release:

The sequencer no longer clobbers the HEAD reference name when evaluating branches in worktrees (ak/sequencer-head-refdup). This small but important fix prevents a buffer corruption issue that could arise when multiple worktrees are in use.

Git’s configuration system gains a new `includeIf` condition: `hostname:` (ic/includeif-hostname). This allows conditional inclusion of config files based on the machine’s hostname, and users can now query the system’s hostname as seen by Git with `git var GIT_HOSTNAME`. The feature is accompanied by a test helper to fetch the hostname reliably.

The `git` man page now promotes `git help` more prominently in its opening section (je/doc-promote-git-help), guiding new users toward the built-in help system rather than leaving them to navigate the documentation unaided.

`git fast-import` can now reference newly created commits and tags by OID in its `from` command (mb/fast-import-reference-pending). This prevents a crash when the referenced objects aren’t yet in the object database, making the import process more robust.

Patrick Steinhardt’s CI housekeeping series (ps/ci-housekeeping-and-modernizations) modernizes the project’s CI infrastructure. It drops Python 2 coverage, switches to supported OS images, removes redundant jobs, and improves reftable test coverage. The series also fixes a test that was creating overly large archives under SHA-256.

The object database’s "files" backend (ps/odb-files-alternates-cleanups) has been optimized to check packfiles across all alternate object directories before falling back to loose objects, reducing system calls. The series also refactors the ODB source interface, removing the generic `local` flag in favor of backend-specific fields.

A boundary check in `git fsck` has been fixed to avoid false corruption reports on packed objects whose size exactly matches `core.bigFileThreshold` (ps/pack-check-bigfile-threshold). This is a small but important correctness fix.

The repository initialization sequence (ps/setup-enforce-repo-passed-to-create-repository-has-no-state) now treats the repository object passed to `create_repository()` as a pure out-parameter, ensuring it carries no pre-existing state. This refactoring also moves shared-repository handling into `setup.c` and improves the creation of leading directories.

Finally, `git blame` and `git annotate` now automatically use `.git-blame-ignore-revs` (or `HEAD:.git-blame-ignore-revs` in bare repos) as the default ignore list if the file exists (rm/blame-default-ignore-revs). The parser has also been hardened to handle malformed input more gracefully.

All of these changes are now in `master` and will be part of the next Git release. The topics are well-motivated, thoroughly reviewed, and address real-world issues without introducing controversy. If you’re tracking Git’s evolution, these are the highlights to watch.
