This thread is a documentation terminology debate about whether Git’s glossary should clarify the distinction between "object name" and "object ID." Julia Evans proposed updating the glossary to make "object ID" the canonical term for the hash (SHA-1/SHA-256) and define "object name" as context-dependent (e.g., refs, branch names, or other notations). The maintainer, Junio C Hamano, rejected this outright, insisting that "object name" *must* remain the canonical term for the hash, citing a 2005 standardization (`f1671ecbfa`) and arguing that any documentation using the term otherwise is incorrect and needs fixing.

The discussion has reached an impasse. Junio’s latest reply doubles down on the status quo, dismissing alternative phrasing (like "notation" for shorthand identifiers) as unnecessary and framing the issue as a wording problem in `gitrevisions(1)` rather than a terminology flaw. D. Ben Knoble’s recent email reinforces Julia’s position, questioning whether historical precedent should block improvements, especially when it conflicts with user intuition. He argues that calling a branch name like `main` an "object name" is misleading, and the glossary’s claim that "object name" is a *unique* identifier is undermined by the existence of multiple notations (refs, unique prefixes) that resolve to the same hash. However, he doesn’t propose a new patch or compromise, leaving the thread blocked unless someone undertakes the broader documentation audit Junio demands or finds a way to reconcile the two perspectives. No technical changes are on the table—this remains a purely philosophical debate about terminology.
