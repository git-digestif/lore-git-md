This thread began when Julia Evans proposed a small but important documentation cleanup: updating Git’s glossary to clarify the distinction between "object name" (the canonical term for an object’s SHA-1/SHA-256 hash) and "object ID" (a term used ambiguously elsewhere in Git’s documentation). The goal was to resolve an inconsistency where some man pages (like `gitrevisions(1)`) use "object name" to mean any name for an object—branch names, refs, or human-readable labels—while the glossary defines it strictly as the hash itself.

The maintainer, Junio C Hamano, rejected the patch outright, insisting that "object name" must remain the canonical term for the hash and that any documentation using it otherwise is incorrect and needs fixing. His position is uncompromising: a branch name like `main` is not an "object name" or "object ID" but merely a notation that can be used *in place of* the object identifier. The thread reached an impasse, with no clear path forward—Junio’s stance leaves no room for the glossary to change unless someone undertakes a broader audit of Git’s documentation to align it with the glossary’s definition.

In her latest email, Julia Evans concedes the impasse and formally withdraws the patch. The thread is now effectively closed, with the glossary’s definition unchanged and the broader inconsistency unresolved. For anyone following this discussion, the key takeaway is that the project’s terminology will not shift: "object name" remains the canonical term for the hash, and future efforts to harmonize Git’s documentation will need to focus on correcting other man pages rather than revisiting the glossary. No one has volunteered for that larger task, so the status quo prevails.
