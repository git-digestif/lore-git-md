This thread is about a proposed update to Git’s glossary to clarify the distinction between "object name" and "object ID." Julia Evans suggested making "object ID" the canonical term for an object’s hash (SHA-1/SHA-256) and refining "object name" to be context-dependent, arguing that current documentation uses the terms inconsistently. The maintainer, Junio C Hamano, rejected this outright, insisting that "object name" must remain the sole canonical term for the hash, while other identifiers (like branch names or refs) are merely notations that can *stand in* for the object name—not synonyms for it. Junio’s position is that any documentation deviating from this definition is incorrect and must be fixed, but he has not volunteered to undertake the broader audit required to align all man pages with the glossary.

The thread has reached an impasse. D. Ben Knoble, while sympathetic to Julia’s goal of improving clarity for users, acknowledges the deadlock in his latest reply. He notes that Junio’s latest clarification—emphasizing that a branch name like `main` is neither an "object name" nor an "object ID" but a notation—may align with some of his own concerns, but no compromise or path forward has emerged. The original patch remains blocked, and the discussion has shifted from refining terminology to defending the status quo. Without someone stepping up to audit and correct the broader documentation, the issue is unlikely to progress. For now, the glossary’s 2005 definition stands, despite its inconsistencies with newer documentation.
