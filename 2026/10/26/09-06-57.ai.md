This is the **v4 of a bugfix series** addressing a data-loss race in `git repack -d` where concurrent pushes can cause objects to be deleted despite being referenced by a `.keep` file that appears mid-repack. The series is now **production-ready** and **blocked only on prior stabilization** of `ps/odb-files-alternates` (which has since merged into `master`). The v4 redesign simplifies the approach by introducing `--ignore-pack-keep-from` to explicitly tell `pack-objects` which packs it may delete, eliminating the need for `--honor-pack-keep` entirely.

### Key changes since v3
1. **Redesigned approach**: Instead of passing a snapshot of *kept* packs (v3), v4 passes a snapshot of *non-kept* packs to `pack-objects` via `--ignore-pack-keep-from`. This ensures `pack-objects` never treats these packs as kept, regardless of `.keep` files that appear later. The change reduces complexity and avoids the need for `--honor-pack-keep`.
2. **Dropped patches**: v3’s patches 1/5 (traversal logic), 3/5 (performance optimization), and 4/5 (`--keep-pack-from-file`) are removed, as the new design no longer relies on `--keep-pack`.
3. **New plumbing**:
   - **Patch 1/3** fixes a stale kept-pack cache in the cruft walk (reproduces on `master` but was masked by `--honor-pack-keep`). The fix ensures the walk correctly traverses packs marked with `--keep-pack` and alternates, even when their objects are excluded.
   - **Patch 2/3** adds `--ignore-pack-keep-from=<file>`, which reads pack names from a file and treats them as if they had no `.keep` file. This is critical for scalability (avoids command-line length limits) and safety (prevents mid-repack `.keep` files from causing data loss).
   - **Patch 3/3** modifies `repack` to write the list of non-kept/cruft packs to a file and pass it to `pack-objects` via `--ignore-pack-keep-from`. The file is written only when there are packs to delete, matching the behavior of `--honor-pack-keep` when no `.keep` files exist.

### Behavior changes
- **Cruft walk**: Now correctly traverses alternates and `--keep-pack` packs, even when their objects are excluded (fixes a latent bug exposed by removing `--honor-pack-keep`).
- **Alternate ODB packs**: No longer skipped; their objects are packed to avoid data loss, trading disk space for safety.
- **Command-line limits**: `--ignore-pack-keep-from` avoids `ARG_MAX` and Windows command-line length caps by reading pack names from a file.

### Test coverage
- **Patch 1/3**: Tests verify the cruft walk rescues objects through untold packs, `--keep-pack` packs, and alternates (with/without `--local`).
- **Patch 2/3**: Tests confirm `--ignore-pack-keep-from` behaves identically to `--keep-pack` and fails cleanly on missing files.
- **Patch 3/3**: Tests reproduce the race (a `.keep` appearing mid-repack) for `-a -d`, `-A -d`, `-k`, `--cruft`, `--geometric`, and `--filter`, ensuring no objects are lost.

### Open questions
- **Performance impact**: The cruft walk now traverses alternates, which can slow down `repack -d -l --cruft` in shared clones (e.g., 2ms → 3.3s in a `clone --shared` of `git.git`). This is intentional (safety over speed) but may prompt discussion.
- **Edge cases**: Pack names with newlines are refused to prevent splitting, but this is unlikely to affect real-world use.
