This is a **follow-up to a substantive review** of Jasper Mayone’s `--branch=<branch>` filtering patch for `` `git worktree list` ``. Phillip Wood suggests a small but practical improvement to the composability story.

The email proposes using `%(refname:lstrip=2)` in `` `git branch --format` `` instead of `%(refname)` to strip the `refs/heads/` prefix consistently. This would let users write simpler commands like `git worktree list $(git branch --format='--branch=%(refname:lstrip=2)' --merged origin/main)` without needing to handle full ref names in the worktree filter. The change would also allow the worktree implementation to accept only branch names (e.g., `topic` instead of `refs/heads/topic`), simplifying its parsing logic.

The suggestion is narrowly scoped and does not reopen larger design questions. It looks like a straightforward usability win that could be adopted without disrupting the rest of the patch.
