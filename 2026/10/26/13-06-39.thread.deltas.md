# Thread deltas

## 2026/10/26

- [2026/10/26/13-06-39 by Julia Evans via GitGitGadget <gitgitgadget@gmail.com>] Julia Evans submitted a patch (pr-2282) proposing to update the glossary to use "object ID" as the canonical term for an object's SHA-1/SHA-256 identifier, warning that "object name" is used inconsistently across the documentation and does not always have the same meaning.
- [2026/10/26/17-08-00 by Junio C Hamano <gitster@pobox.com>] Junio C Hamano rejected the patch, stating that the other documentation places using "object name" should be fixed instead, and that <refname>, HEAD, etc. can be used where commands take object names because "object name" exactly refers to the 40 hexadecimal digits identifying objects.

## 2026/10/27

- [2026/10/27/12-15-42 by Ben Knoble <ben.knoble@gmail.com>] Ben Knoble suggested "notation" as a better word than "object name" in gitrevisions.adoc, argued that "object ID" should mean only the 40-digit (or other-length) hash while other spellings are notations that resolve to it, asked whether the glossary's "object name" entry should instead say "object ID" and mention SHA-256/other lengths, and proposed defining "object name" as any notation in gitrevisions(1) that resolves to an object ID.
- [2026/10/27/17-47-43 by Junio C Hamano <gitster@pobox.com>] Junio C Hamano defended "object name" as the canonical glossary term established by f1671ecbfa in 2005, argued that the real problem in "various ways to spell object names" is that the sentence omits "things that can be used in place of" rather than the choice of "name" vs "identifier", and said he would prefer fixing documentation that misuses "hash" to mean an object's name rather than changing the canonical term.
- [2026/10/27/18-00-12 by D. Ben Knoble <ben.knoble@gmail.com>] D. Ben Knoble agreed with Junio's explanation of object names and shorthands, but maintained his view that "ID" means only the cryptographic hash of contents; he accepted the 2005 historical context as useful while questioning whether it should be a barrier to improvement, endorsed Julia Evans' attempt to align with common "ID" vs "name" usage, and reiterated that calling "main" an object ID still seems strange to him.
- [2026/10/27/18-03-34 by D. Ben Knoble <ben.knoble@gmail.com>] D. Ben Knoble rephrased his position: he is not sure it is good to expect newcomers to use what he views as idiosyncratic definitions of "ID" and "name", noting Git already has enough jargon.
- [2026/10/27/19-18-17 by Junio C Hamano <gitster@pobox.com>] Junio C Hamano countered that the "goes both ways" point applies to those subverting terminology documented for 20 years, and stated that "main" is NOT an object ID or object name, though it can be used where an object name is called for to uniquely specify an object.
- [2026/10/27/19-24-23 by D. Ben Knoble <ben.knoble@gmail.com>] D. Ben Knoble accepted Junio's point ("Fair enough") and concluded that they may be saying some of the same things.
- [2026/10/27/22-34-54 by Julia Evans <julia@jvns.ca>] Julia Evans said she had genuinely thought the change might be uncontroversial, acknowledged she was wrong, and announced she would drop the patch.
