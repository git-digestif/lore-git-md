This is a CI/build system patch that pins all GitHub Actions in Git’s main workflow file to full commit SHAs instead of version tags or branches. The v2 revision strengthens the security rationale in the commit message, explicitly calling out the risk of supply-chain attacks: if an attacker compromises an action’s repository, they could move a tag to a malicious revision, and Git’s CI would automatically pick it up. By pinning to commit IDs, any update—including security fixes—requires an explicit workflow change, reducing the attack surface.

The patch touches only `.github/workflows/main.yml`, replacing 32 action references (e.g., `actions/checkout@v6` → `actions/checkout@d23441a48e516b6c34aea4fa41551a30e30af803`) while retaining the original version tags in comments for readability. Affected actions include `actions/checkout`, `actions/github-script`, `actions/upload-artifact`, `actions/download-artifact`, `actions/setup-python`, and several Git for Windows and Microsoft actions. The change is purely infrastructural—no functional impact on Git itself—and is part of broader CI modernization efforts (`ps/ci-housekeeping-and-modernizations` and `jk/http-curl-strip-creds`).

Junio’s earlier policy concern—that this change addresses a downstream constraint rather than an upstream need—has been addressed by the revised commit message, which now clearly documents the security trade-offs. The "last one wins" precedent worry (that accommodating one organization’s policy invites conflicting requests) remains noted but is no longer a blocker. The patch is conditionally accepted pending this v2, with no technical objections outstanding.

The maintenance overhead (updating SHAs for security fixes) is acknowledged but framed as justified by the security benefits. Future requests for similar changes may need to address the precedent concern more directly, but for now, the patch is on track for inclusion. The change is low-risk, mechanical, and aligns with GitHub’s own security recommendations for Actions.
