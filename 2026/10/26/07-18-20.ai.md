This is a small test infrastructure patch series (2 patches) targeting the `clar`-based unit test framework. The goal is to make the unit tests ignore the `-l`/`--long-tests` argument passed by `meson test`, which currently causes the test runner to fail with "unknown switch `l'".

The problem surfaced when running `meson test -v --test-args='-ilx'`: the `-l` flag (intended for `meson` to run long tests) was being passed through to the `unit-test` binary, which doesn’t recognize it. The series fixes this by adding `-l`/`--long-tests` as NOOP arguments to `t/unit-tests/unit-test.c`, following the precedent set by commit 9faf3963b6 ("t: introduce compatibility options to clar-based tests", 2024-12-13). The first patch reshuffles existing NOOP arguments to maintain order, and the second adds the new NOOP for `-l`.

The change is minimal (3 lines total) and well-motivated by the error scenario. The commit message clearly explains the issue and why it doesn’t affect CI (which uses `GIT_TEST_LONG` instead of the command-line flag). The series has been tested in CI (GitHub and GitLab pipelines), with no failures reported. This is a straightforward fix for a usability hiccup in the test infrastructure.
