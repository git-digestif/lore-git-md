This is a documentation patch for the partial-clone subsystem. It updates the technical design notes to clarify how Git handles promisor remotes when multiple sources are available.

The patch documents a previously undocumented two-pass fetch order: Git first tries promisor remotes advertised by the server (if accepted by the client), then falls back to configured promisor remotes. This behavior exists in the implementation but wasn't explained in the docs.

It also adds important security context about how clients handle server-advertised remotes. By default, clients reject all such remotes unless the user explicitly configures acceptance policies via `promisor.acceptFromServer` or `promisor.acceptFromServerUrl`. This prevents servers from injecting untrusted remote configurations.

The change is small (four lines added) but well-motivated, addressing both a documentation gap and a potential security concern. The commit message clearly explains the technical rationale and security model. This looks like a straightforward improvement that should be uncontroversial.
