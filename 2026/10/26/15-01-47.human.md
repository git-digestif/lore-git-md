This is a bugfix patch targeting the config subsystem, now in its second iteration (v2). The patch makes Git respect filesystem write permissions when modifying out-of-tree configuration files like `$HOME/.gitconfig` or XDG config files. If a user marks these files as read-only (e.g., `chmod a-w .gitconfig`), Git will now return a `CONFIG_NO_WRITE` error instead of silently overwriting them. The change is narrowly scoped to out-of-tree files, excluding in-tree files like `.git/config`, as the author argues these are uniquely vulnerable because they reside outside the repository and lack the same protections as in-tree files.

The patch touches `config.c` and adds test coverage in `t/t1300-config.sh`, introducing a new error code and modifying `repo_config_set_multivar_in_file_gently()` to check file permissions with `access(2)` before creating a lockfile. The implementation avoids modifying the broader lockfile API (`lockfile.c`) to sidestep a time-consuming audit of all lockfile users, a decision now explicitly justified in the commit message after Patrick Steinhardt’s review. The patch is well-motivated and addresses a real usability gap, though it leaves unresolved questions about edge cases like race conditions, symbolic links, and network filesystems.
