This is the v4 iteration of Harald Nordgren’s series that extends `git branch --delete-merged` to detect branches whose changes (but not their tips) have been integrated via squash or rebase merges. The series now introduces a new top-level flag `--delete-integrated` that unifies both rebase and squash detection under a single, opt-in interface, while preserving the original `--delete-merged` behavior (strict tip-reachability only). The four patches are:

1. A preparatory refactoring that moves the `deleteMerged` opt-out check into a helper.
2. A new commit that lets `delete_branches()` report where a branch “landed” in the output message.
3. The core patch that adds `--delete-integrated` to detect rebase-merged and squash-merged branches whose changes are fully contained in an upstream commit.
4. The final patch that extends `--delete-integrated` to handle cases where upstream modified the same files before the squash, using a three-way merge to determine if the branch’s changes are still present.

Key technical details:
- Files touched: `builtin/branch.c`, `Documentation/git-branch.adoc`, `Documentation/config/branch.adoc`, and `t/t3200-branch.sh`.
- New CLI: `--delete-integrated <pattern>` (opt-in, enables both rebase and squash detection by default; cannot be combined with `--delete-merged`).
- Performance: The rebase detection remains tree-based (fast, no blob fetches), while squash detection on modified upstream files may download blobs in partial clones.
- Safety: The series now includes Junio’s false-positive test case (an unrelated upstream commit adding an identical file) to ensure `--delete-merged` never deletes such branches.
- Output format: `Deleted branch topic (was 1a2b3c4, landed as 9f8e7d6)`.
- Config: `branch.<name>.deleteMerged` now applies to both `--delete-merged` and `--delete-integrated`.

The series is explicitly confirmed by Junio and addresses the safety concerns raised in v3 by splitting the strict and change-based behaviors into separate flags. The author-check mitigation (Jasper Mayone’s proposal) is not yet implemented, but the CLI design is finalized and ready for review.
