This is a **substantive review follow-up** in the ongoing bugfix thread about preventing `git revert` and `git cherry-pick` from operating on shallow boundary commits by default.

Phillip Wood responds to Junio C Hamano’s design question by proposing a more user-friendly approach: instead of checking for shallow boundary commits inside `do_pick_commit()` (which runs after the user has already started the operation), the check should happen earlier, when the todo list is being built. This would mean refusing to add a shallow commit to the todo list in the first place, improving the user experience by failing fast. To achieve this, Phillip suggests introducing a helper function that would be called from `sequencer_make_script()`, `make_script_with_merges()`, `single_pick()`, and `sequencer_pick_revisions()`—covering `git revert`, `git cherry-pick`, and `git rebase` in one go.

The proposal is a refinement of the original patch’s architecture, not a rejection of its core goal. It addresses Junio’s concern about where the safeguard should live while also improving usability. The thread remains under active design discussion; no merge decision has been made, and a follow-up patch from Nakul V S is likely.
