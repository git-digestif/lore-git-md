This is a performance optimization for the recently discussed CRLF conversion bugfix in `read-cache.c`. Torsten Bögershausen proposes an RFC patch that refactors Curtis Allen Smith’s v5 fix to eliminate redundant attribute lookups and streamline the logic in `ie_modified()`.

The patch removes the explicit `would_convert_to_git()` call added in v5, relying instead on the existing check in `ce_compare_data()` (called by `ce_modified_check_fs()`). This reduces the code footprint by 3 lines (8 insertions, 11 deletions) and avoids a double attribute lookup for files that trigger the size-mismatch path. The change is narrowly scoped to `read-cache.c` and preserves the fix’s correctness: it still handles CRLF rewrites, clean filters, and lone-CR edge cases, but does so more efficiently.

Torsten reports the patch passes all existing tests and works correctly with a real-world clean filter (tabs-to-spaces). However, it does not address the unresolved architectural debate: Johannes Sixt’s objection to the fix’s premise (that the index’s recorded size should reflect the blob’s size) or Junio C Hamano’s concern about preserving the lstat()-based optimization that avoids content comparisons for files whose sizes haven’t changed. The patch is an optimization, not a redesign, and the core trade-off—shifting work from `git add` to index refresh operations—remains unchanged.

This is a follow-up to a long-running thread, and the patch is clearly marked as RFC. It’s a well-motivated refinement, but the larger questions about where the conversion check belongs (and whether it belongs at all) are still open. For now, this patch is worth watching as a potential incremental improvement, but it won’t resolve the thread’s central tension.
