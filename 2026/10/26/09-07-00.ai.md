This is the **final patch (3/3) of a v4 bugfix series** that eliminates a data-loss race in `git repack -d` by replacing the `--honor-pack-keep` mechanism with a snapshot-based approach. The patch is **production-ready**, thoroughly tested, and addresses all prior review feedback.

The core change: when `repack` may delete packs (with `-d` and either `-a`, `-A`, `--cruft`, or `--geometric`), it now writes the names of non-kept and cruft packs to a temporary file and passes it to `pack-objects` via `--ignore-pack-keep-from`. This ensures `pack-objects` never treats these packs as kept, regardless of `.keep` files that appear mid-repack. The file format is one pack name per line, with newlines in names refused to prevent splitting. The snapshot is written only when there are packs to delete, matching the behavior of `--honor-pack-keep` when no `.keep` files exist.

The patch touches `builtin/repack.c` (to write the snapshot and pass it to `pack-objects`), `repack.c` (to add the plumbing for `--ignore-pack-keep-from`), and `repack.h` (to expose the new field and helper). Tests in `t/t7700-repack.sh` and `t/t7703-repack-geometric.sh` reproduce the race for all affected repack modes (`-a -d`, `-A -d`, `-k`, `--cruft`, `--geometric`, and `--filter`), verifying no objects are lost. The tests use a `git` wrapper to create a `.keep` file on the pack about to be deleted as `pack-objects` starts, simulating the race condition.

This patch is the culmination of the v4 redesign, which simplifies the approach by eliminating the need for `--honor-pack-keep` entirely.
