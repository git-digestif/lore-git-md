This is the second patch in Harald Nordgren’s four-part series introducing `--delete-integrated` to `git branch`. The series extends `git branch --delete-merged` to detect branches whose changes (but not their tips) have been integrated via squash or rebase merges.

This patch prepares the output machinery for the new behavior. It modifies `delete_branches()` to accept a `strmap` that maps branch names to the upstream commit where their changes landed. When a branch is in the map, the function skips the usual merge check and reports the deletion with an extra “landed as” clause: `Deleted branch topic (was 1a2b3c4, landed as 9f8e7d6)`. No caller passes a non-NULL map yet, so the patch is purely preparatory and changes no user-visible behavior.

The change is small (25 lines added, 5 removed) and touches only `builtin/branch.c`. It is uncontroversial and ready for integration; the author explicitly marked it as such in the cover letter. The patch is a necessary building block for the later patches that implement the actual detection logic.
