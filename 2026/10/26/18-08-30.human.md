This is a CI/build system patch that pins all GitHub Actions in Git’s main workflow file to full commit SHAs instead of version tags or branches. The v2 revision strengthens the security rationale in the commit message, explicitly calling out the risk of supply-chain attacks: if an attacker compromises an action’s repository, they could move a tag to a malicious revision, and Git’s CI would automatically pick it up. By pinning to commit IDs, any update—including security fixes—requires an explicit change to the workflow file.

The patch is purely mechanical, touching only `.github/workflows/main.yml` and replacing 32 action references (e.g., `actions/checkout@v6` → `actions/checkout@d23441a48e516b6c34aea4fa41551a30e30af803`). Each replacement keeps the original version tag in a trailing comment for readability. No functional changes to Git itself are introduced; this is purely about CI infrastructure hardening.

Junio’s earlier policy concern—that this change addresses a downstream constraint rather than an upstream need—has been addressed by the revised commit message, which now clearly articulates the security benefits and trade-offs. The patch is conditionally accepted pending this v2, and no technical objections remain. It’s part of broader CI modernization efforts (branches `ps/ci-housekeeping-and-modernizations` and `jk/http-curl-strip-creds`) and looks ready to proceed once the commit message is finalized. For anyone tracking Git’s CI security practices, this is a straightforward but meaningful improvement.
