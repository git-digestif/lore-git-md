This is the third patch in Harald Nordgren’s v4 series introducing `git branch --delete-integrated`, which extends `git branch --delete-merged` to detect branches whose changes (but not their tips) have been integrated via rebase or squash merges. The patch adds the core `--delete-integrated` flag and implements the change-based detection logic for both rebase-merged and squash-merged branches.

The patch touches `builtin/branch.c`, `Documentation/git-branch.adoc`, `Documentation/config/branch.adoc`, and `t/t3200-branch.sh`. It introduces the `DELETE_BRANCH_INTEGRATED` flag and extends `delete_merged_branches()` to detect when a branch’s changes are fully contained in an upstream commit since the fork point, even if the branch’s tip is not reachable. The detection logic is tree-based (no blob fetches) and uses a three-way merge approximation to handle upstream modifications to squashed files. The output format is updated to show the landing commit (e.g., `Deleted branch topic (was 1a2b3c4, landed as 9f8e7d6)`).

The test suite (`t/t3200-branch.sh`) includes coverage for rebase-merged branches, squash-merged branches (including those later reverted), partial landings, and mixed workflows. The patch also enforces that `--delete-integrated` cannot be combined with `--delete-merged`.

The implementation is now split into four patches: the first two (preparatory refactoring and landing-message helper) are uncontroversial and ready for integration, while this patch and the fourth (squash-detection with upstream modifications) remain under review. The CLI design is finalized, and the series addresses the false-positive safety concern by splitting the strict and change-based behaviors into separate flags. The author-check mitigation (Jasper Mayone’s proposal) is still required but not yet implemented.
