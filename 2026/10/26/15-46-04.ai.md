This is the second patch in a three-part series introducing a performance optimization for `git pack-objects`. The patch adds a new `--inspect-have <commit>` option that lets the sender inspect root trees of receiver-known commits to identify shared objects without walking their commit histories. This avoids packing objects the receiver already has, even when those commits are excluded from the revision walk as boundary commits.

The core idea is to compare root trees of outgoing tips with those of receiver-known commits using the existing sparse tree marking machinery. If a subtree is identical or exists only on the receiver side, it is skipped. The patch updates `builtin/pack-objects.c` to parse `--inspect-have` lines, resolve the commits, and mark their trees as uninteresting before the main revision walk. It also extends the `odb_generate_pack_options` struct to carry these commits through the ODB pack-generation pipeline, and updates the source-files backend to emit the new option when generating pack input.

The implementation is careful to avoid regressions: it disables the optimization in partial clones (where missing trees would trigger fetches), skips it when bitmaps are used (to preserve the fast path), and rejects non-commit inputs. The test coverage is thorough, exercising identical root trees, shared blobs under different roots, retained changed objects, subtree pruning, partial clone fallback, and shared objects in earlier outgoing commits.

The patch is well-motivated and technically sound. The commit message clearly explains the problem (receiver-known commits excluded as boundaries still force inspection of their trees) and the solution (sparse tree comparison without history traversal). The code is clean, the tests are comprehensive, and the edge cases are handled. This looks like a genuine performance win for clients pushing to servers that already know some of the history.
