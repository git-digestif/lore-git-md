This is a CI/build system patch series (v3) that makes two changes to GitHub Actions CI behavior.

The series now consists of two patches. The first is a preparatory cleanup: it removes the macOS-specific `xattr -d com.apple.quarantine` step for Perforce binaries, which has been a silent no-op since Perforce installation moved off Homebrew in 2022. The second patch implements the stricter behavior agreed in the thread: if Perforce, Git LFS, or JGit fail to install on a platform that requires them (ubuntu-* for all three, macos-* for Perforce), the build now fails immediately rather than allowing silent skips or warnings. The patch also removes the now-dead presence checks and warnings at the end of the script, and moves version output (`p4d -V`, `git-lfs version`, `jgit version`) inline right after each successful install for confirmation.

The series touches only `ci/install-dependencies.sh` and does not alter Git's functionality. The v3 iteration drops the explicit `echo "error: ..." / exit 1` blocks for Perforce, Git LFS, and JGit, relying instead on the `set -e` already active via `ci/lib.sh` to abort on the first failed install. This matches how every other install step in the file already works and simplifies the code. The range-diff shows the removal of redundant error handling and the dropped macOS `xattr` step.

The motivation is clear: reduce CI log noise by ensuring warnings or failures only occur on platforms that actually attempt to install these tools, and fail fast if installation fails. The thread has already resolved the fundamental question in favor of strictness, and the v3 series now implements that consensus cleanly. The preparatory cleanup (patch 1) is low-risk and aligns with Patrick Steinhardt’s earlier suggestion. The main change (patch 2) is ready for final review and a formal positive sign-off (Reviewed-by or Acked-by) from a contributor other than Junio C Hamano or Patrick Steinhardt.
