This is a **bugfix** targeting the shallow clone and pack-objects subsystems. Patrick Steinhardt replies to Daniel Zoghalchali’s regression report with a proposed fix for the BUG() in `should_include_obj()` that aborts a `--filter=tree:0` + `--unshallow` fetch when the fetched ref has moved past the local shallow tip.

The root cause is now clearer: the BUG() assertion in `is_not_in_promisor_pack_obj()` is overly strict. When walking past the shallow boundary into promisor objects whose trees were never fetched, `odb_read_object_info_extended()` fails, but the code incorrectly treats this as a fatal error. This issue predates the environment-based shallow file propagation introduced in Git 2.56.0 (commit d43b9acb05), though that change exposed it more frequently. Patrick’s proposed fix replaces the BUG() with a graceful return of 0, allowing the walk to continue without aborting.

The fix is small and targeted, touching only `builtin/pack-objects.c`. It addresses both the regression in 2.56.0 and the pre-existing edge case on 2.55.0, making it a clean solution to a well-understood problem. The reproduction script provided in the original report confirms the issue and will likely serve as a test case for the fix. This patch looks like a strong candidate for merging, as it resolves a severe failure mode (BUG() abort) with minimal risk. Expect it to land soon, possibly in `next` for the next release cycle.
