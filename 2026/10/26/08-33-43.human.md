This is a feature patch series that extends `git branch --delete-merged` to handle squash-merged and rebase-merged branches. The v4 iteration finalizes the CLI design after extensive discussion: the original `--delete-merged` behavior (strict tip-reachability) is preserved, and a new `--delete-integrated <pattern>` flag is added to detect branches whose changes (but not their tips) have been integrated into an upstream branch via squash merges, rebases, or patch-based workflows.

The series is now split into four patches: a preparatory refactoring, a helper to track where branches landed, the core `--delete-integrated` implementation (which handles both rebase and squash merges), and an extension to the squash detection logic to work even when upstream has modified the same files. The new flag is well-motivated by real-world workflows (GitHub's "Squash and merge" and "Rebase and merge" buttons) and addresses a long-standing pain point for users who want to clean up branches after their changes have been integrated but their tips are not reachable.

The implementation is careful: it avoids false positives by requiring that every change from the branch be present in the upstream commit, and it names the first such commit in the deletion message (`Deleted branch topic (was 1a2b3c4, landed as 9f8e7d6)`). Performance is preserved for `--delete-merged` by using fast tree-based diffing, while `--delete-integrated` may download blobs in partial clones when necessary. The test coverage is thorough, including edge cases like reverted squash merges, partial landings, and the false-positive scenario raised by Junio (a branch incorrectly deleted because another author independently made the same change).

The CLI design is now settled: `--delete-merged` remains unchanged, and `--delete-integrated` is a separate, opt-in flag that enables both rebase and squash detection by default. The series is ready for review, with the first two patches (refactoring and helper) uncontroversial and the last two requiring close attention to the correctness of the detection logic and the performance trade-offs of the squash-merge handling. The author has addressed the safety concerns raised in earlier iterations by splitting the flags and adding clear documentation of the algorithm's behavior.
