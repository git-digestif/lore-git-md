This is a documentation patch that proposes a terminology cleanup in Git's glossary. Julia Evans (a well-known technical writer and educator) argues that the glossary currently defines "object name" as the canonical term for an object's hash identifier, but in practice, the documentation uses "object name" inconsistently—sometimes meaning the hash, other times meaning a human-readable reference like a branch name. To resolve this ambiguity, she updates the glossary to use "object ID" (already widely used elsewhere in the docs) as the canonical term for the hash, while clarifying that "object name" is context-dependent and not always reliable. The patch also adjusts cross-references in the glossary to point to the new "object ID" definition.

The change is motivated by a 2020 suggestion from Junio Hamano (Git's maintainer) and aligns with broader industry conventions where "ID" refers to machine-readable identifiers and "name" to human-readable ones. The patch itself is small (11 lines added, 7 removed) and touches only the glossary file, making it a low-risk, high-clarity improvement. The commit message is thorough, explaining the problem, the solution, and even acknowledging a minor downside (losing a term for "a name for an object"), but concludes the trade-off is worth it.

This looks like a well-considered, uncontroversial patch that addresses a real documentation pain point. It’s likely to be merged once any minor wording tweaks are settled.
