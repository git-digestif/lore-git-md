This is a **substantive review** of the first patch in Harald Nordgren’s `git imap-send` bugfix series (v3 1/4). The patch, already merged to `next`, fixes a tunnel-command process leak by ensuring the child process is properly reaped via `finish_command()`. Patrick Steinhardt’s reply raises two technical concerns about the implementation:

1. **Safety of `finish_command()` on uninitialized `struct child_process`** – Patrick questions whether `imap_close_server()` might be called before `imap->tunnel` is initialized, risking undefined behavior. He suggests making `imap->tunnel` a pointer (allocated only when needed) to avoid this edge case.
2. **Code clarity** – He notes that the local variable `tunnel` (introduced to shrink the diff) is unnecessary and could be removed for cleaner code.

The review is narrowly focused on the patch’s robustness and style, not its overall correctness. The concerns are valid but minor: the current implementation is safe in practice (the tunnel is only used when `srvc->tunnel` is set, and `imap_close_server()` is called after initialization), but Patrick’s suggestion would make the code more defensive. No alternative implementation is proposed, and the patch remains ready for integration as-is. The discussion is unlikely to block the series, but may prompt a follow-up tweak if Harald chooses to address it. Key files: `imap-send.c` (tunnel process management).
