This is a test patch, part of a three-patch series. It extends the existing `t5516-fetch-push.sh` test script to cover a specific edge case in Git's push behavior: when a branch is rebased and force-pushed, unchanged blobs that the receiver already has (via the old tip) should still be resent rather than omitted.

The patch adds new test cases for three forms of forced push: `--force`, `--force-with-lease`, and a forced refspec (`+topic`). Each test creates a scenario where a commit is rebased onto a new base, but the blob content remains identical. The test verifies that the push sends exactly three objects (the new commit, its tree, and the unchanged blob) by inspecting the Git trace2 event log. It also disables push bitmaps to ensure the test exercises normal object enumeration rather than bitmap-based optimization.

A second test case checks that local replacement refs (created with `git replace`) do not cause objects missing from the receiver to be incorrectly omitted during a forced push. This ensures that replacement refs, which are purely local, do not interfere with the object negotiation logic.

The tests are well-scoped and clearly motivated by a real-world scenario: a forced push after a rebase should not silently drop objects that the receiver might still need. The commit message is concise but sufficient, and the test code is clean and idiomatic. No substantive review has appeared yet, but the patch looks like a solid addition to the test suite.
