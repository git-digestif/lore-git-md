This is the first patch in a two-part bugfix series that has now been merged to `master`. It addresses a latent correctness issue in Git's fetch negotiation machinery, specifically in the default negotiator.

The problem is that `rev_list_push()` marks commits as `SEEN` before attempting to parse them. If parsing fails (e.g., due to a missing object), the commit is left marked as `SEEN` but never added to the queue. This can cause `mark_common()` to incorrectly subtract the commit from `non_common_revs`, potentially stopping negotiation prematurely while other non-common commits remain queued. The fix defers setting the `SEEN` flag until after parsing succeeds, ensuring the flag accurately reflects whether the commit was actually queued.

The patch touches `negotiator/default.c` to move the `SEEN` flag assignment after the `repo_parse_commit()` call. It also adds a new test case in `t/t5702-protocol-v2.sh` that verifies negotiation continues correctly when a missing parent commit is encountered. The test creates a scenario where the first batch of commits includes a branch with a missing ancestor, and confirms that negotiation does not terminate before sending an unrelated tip.

This is a well-targeted fix for a subtle but real correctness issue. The commit message clearly explains the problem, the solution, and the edge case being addressed. The test coverage is thorough and demonstrates the bug's impact. The patch is part of a broader effort (the second patch in the series) to ensure consistent behavior across both the default and skipping negotiators. All review feedback has been incorporated, and the series is now closed.
