This is an **announcement email** for **Git for Windows 2.56.0(4)**, a security-focused bugfix release from Johannes Schindelin.

The update addresses two critical issues: corrupt code-signatures in the 32-bit MinGit executables and a vulnerability in the included brotli component (CVE-2026-111497), which has been patched by upgrading brotli to v1.2.1. This is the fourth build in the 2.56.0 series, following a rapid succession of releases (the previous version, 2.56.0(3), was released just four days earlier). The urgency suggests the security fix was deemed high-priority.

All standard distribution formats are provided (installers, portable builds, MinGit variants, and tarballs), with checksums for verification. Notably, the announcement targets both the Git mailing list (`git@vger.kernel.org`) and the Git packagers group, indicating this is relevant for downstream redistributors as well as end users.

This is **not** an upstream Git release—it is a Git for Windows-specific update. The version numbering (2.56.0.4) mirrors the upstream Git 2.56.0 release but includes Windows-specific fixes. No changes to Git’s core behavior or APIs are implied; the focus is solely on Windows packaging and security hardening. The brotli vulnerability is likely in a compression library used by Git for Windows, not in Git’s own codebase.
