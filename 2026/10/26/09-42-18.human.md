This is a **substantive review** of the third patch in Harald Nordgren’s four-patch series fixing `git imap-send` interoperability with tools like `b4`. The patch removes a special-case exemption for messages starting with `From git-send-email`, which was originally introduced to work around `git imap-send`’s earlier requirement that `Date` appear before `Subject`. Now that the parsing logic accepts headers in any order (Patch 2/4), the exemption is redundant, and the patch treats all messages uniformly.

Patrick Steinhardt’s review raises a **clarification question** about edge cases: while `Date` is mandatory per RFC 5322, `Subject` is only a "SHOULD," so messages without it are technically valid. The patch tightens the rules by requiring `Subject` (via the existing `has_required_headers()` helper), but the commit message does not explicitly address whether this change could break workflows that omit `Subject`. The author’s argument—that `git send-email` always includes `Subject`—is correct for that tool, but the patch’s broader impact on other scripts or tools generating mboxes is not discussed. This is not a blocking issue (the series is otherwise uncontroversial and ready for integration), but it may prompt a follow-up clarification in the commit message or a note in the documentation if the stricter requirement is intentional. The review is substantive but not critical; it highlights a potential edge case rather than identifying a flaw.
