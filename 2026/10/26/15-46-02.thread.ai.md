Subject: [PATCH 0/3] send-pack: optimize force-push of rebased feature branches
Series version: v1 (initial submission)
Originating author: Marc Strapetz (via GitGitGadget)
Thread type: patch series

Core problem or goal
Teach `git send-pack` to avoid re-uploading large unchanged blobs when force-pushing a rebased feature branch. The optimization is opt-in, enabled only for forced non-fast-forward updates where the old branch tip is locally available, and requires no server or protocol changes.

Current status
Under review; v1 posted 2025-07-10 (date from email headers). No prior versions. No maintainer decision recorded.

Key technical details
- New `--inspect-have` option in `pack-objects` that accepts an old tip commit and marks its root tree as “have” without walking the commit’s history.
- `odb_has_object_file()` helper added to check object existence without loading the object.
- Conditional logic in `send-pack.c` restricts inspection to forced non-fast-forward updates of existing branches (`refs/heads/`); shallow repositories, partial clones, and bitmap enumeration remain unchanged.
- Replacement refs are disabled during inspection to prevent object substitution.
- Files touched: `builtin/pack-objects.c`, `odb.c`, `odb.h`, `odb/source-files.c`, `send-pack.c`, `t5322-pack-objects-sparse.sh` (19 new tests), `t5516-fetch-push.sh` (43 new tests).
- New symbols: `--inspect-have` CLI option, `odb_has_object_file()` function.

Open questions and loose ends
- Cost/benefit trade-off: worst-case 8 % packing-time overhead for widespread-change cases; author invites feedback on whether this is acceptable.
