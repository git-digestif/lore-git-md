Subject: [PATCH] glossary: clarify "object name" vs "object ID"
Series version: standalone patch (no series)
Originating author: Julia Evans
Thread type: documentation cleanup

Core problem or goal
The Git glossary currently defines "object name" as the canonical term for an object's SHA-1/SHA-256 identifier, but the documentation elsewhere uses "object name" ambiguously to mean *any* name for an object (branch names, refs, human-readable labels) while using "object ID" specifically for the hash. The patch proposed to resolve this inconsistency by making "object ID" the canonical term for the hash and explicitly marking "object name" as context-dependent. The maintainer has now rejected this approach, insisting that "object name" *must* remain the canonical term for the hash and that any documentation using it otherwise is incorrect and should be fixed instead.

Current status
Rejected by the maintainer; no prior versions. The patch is blocked unless someone undertakes a broader documentation audit to align all man pages with the glossary's definition of "object name" as the hash identifier. No alternative solution has been proposed yet.
