Subject: [PATCH] glossary: clarify "object name" vs "object ID"
Series version: standalone patch (no series)
Originating author: Julia Evans
Thread type: documentation cleanup

Core problem or goal
The Git glossary currently defines "object name" as the canonical term for an object's SHA-1/SHA-256 identifier, but the documentation elsewhere uses "object name" ambiguously to mean *any* name for an object (branch names, refs, human-readable labels) while using "object ID" specifically for the hash. The patch proposed to resolve this inconsistency by making "object ID" the canonical term for the hash and explicitly marking "object name" as context-dependent. The maintainer has rejected this approach, insisting that "object name" *must* remain the canonical term for the hash and that any documentation using it otherwise is incorrect and should be fixed instead.

Open questions and loose ends
- Whether anyone will undertake the larger task of auditing and updating the broader documentation to align with the glossary's definition of "object name" as the hash identifier.
- No objections or requests for changes to the patch itself were raised before the maintainer's rejection; the thread is now focused on the fundamental disagreement over terminology.
- Ben Knoble's proposal to refine the wording by using "notation" for ways to spell an object identifier (e.g., refs, HEAD, or the hex string) and to define "object name" more precisely as "any notation in `gitrevisions(1)` that resolves to an object ID" remains unresolved.

Maintainer's position: "object name" is and should remain the canonical term for the 40- or 64-character hexadecimal identifier (SHA-1 or SHA-256); any documentation using it more broadly (e.g., for refs or branch names) is incorrect and must be fixed.
Ben Knoble's suggestions: Use "notation" instead of "name" for ways to spell an object identifier; explicitly mention SHA-256 alongside SHA-1 in the glossary definition of "object ID"; define "object name" as "any notation in `gitrevisions(1)` that resolves to an object ID."
