Subject: [PATCH] glossary: clarify "object name" vs "object ID"
Series version: standalone patch (no series)
Originating author: Julia Evans
Thread type: documentation cleanup

Core problem or goal
The Git glossary defines "object name" as the canonical term for an object's SHA-1/SHA-256 hash, but documentation elsewhere (e.g., `gitrevisions(1)`, `gitdatamodel`) uses "object name" ambiguously to mean any name for an object (branch names, refs, human-readable labels) while reserving "object ID" for the hash. Julia Evans proposed resolving this inconsistency by making "object ID" the canonical term for the hash and clarifying "object name" as context-dependent. The maintainer (Junio C Hamano) rejected this approach, insisting "object name" must remain the canonical term for the hash and that any documentation using it otherwise is incorrect and must be fixed. Junio’s position is that "object name" is the invariant identifier (the hash), while other terms (refs, branch names, unique prefixes) are mere notations or shorthand for it, not synonyms.

Current status
Rejected by the maintainer; no prior versions. The patch is blocked unless someone undertakes a broader documentation audit to align all man pages with the glossary’s definition of "object name" as the hash identifier. Junio’s latest emails reinforce the status quo, dismissing alternative phrasing (e.g., "notation") as unnecessary and framing the issue as a wording problem in `gitrevisions(1)` rather than a terminology flaw. No alternative solution or compromise has been proposed. The thread remains at an impasse, with no clear path forward. Ben Knoble’s latest email acknowledges the impasse and the maintainer’s clarification but does not propose a new solution or technical path forward.

Maintainer’s position: "object name" is and must remain the canonical term for the 40- or 64-character hexadecimal identifier (SHA-1 or SHA-256). Other documentation using "object name" more broadly (e.g., for refs or branch names) is incorrect and must be fixed. The term "object ID" is not canonical and should not replace "object name" in the glossary. The phrasing in `gitrevisions(1)` ("Here are various ways to spell object names") should be revised to "Here are various things that can be used in place of [object names]" to avoid implying that shorthand notations *are* object names. Historical context: The glossary’s definition was standardized in 2005 (`f1671ecbfa`) and is cited as authoritative. Junio notes that newer documentation (e.g., `gitdatamodel`) has reintroduced inconsistencies and should be corrected. Junio’s latest email clarifies that a branch name like `main` is not an "object name" or "object ID" but merely a notation that can be used *in place of* an object identifier to specify an object.
