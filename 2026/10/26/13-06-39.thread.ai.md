Subject: [PATCH] glossary: clarify "object name" vs "object ID"
Series version: standalone patch (no series)
Originating author: Julia Evans
Thread type: documentation cleanup

Core problem or goal
The Git glossary currently defines "object name" as the canonical term for an object's SHA-1/SHA-256 identifier, but the documentation elsewhere uses "object name" ambiguously to mean *any* name for an object (branch names, refs, human-readable labels) while using "object ID" specifically for the hash. The patch resolves this inconsistency by making "object ID" the canonical term for the hash and explicitly marking "object name" as context-dependent.

Current status
Under review; no prior versions. The patch updates only `Documentation/glossary-content.adoc`, revising the definitions of "hash", "object identifier", "object name", "ref", and "SHA-1" to consistently refer to "object ID" for the hash. The new "object name" definition warns readers that the term may denote either an object ID or a human-readable name, depending on context. The commit message cites a 2020 suggestion from Junio Hamano for a similar change.
