This is the second patch in Harald Nordgren’s v3 series targeting **CI/build system** improvements. The patch implements the agreed stricter behavior: failing the build immediately if Perforce, Git LFS, or JGit fail to install on platforms that require them (ubuntu-* for all three, macos-* for Perforce). The thread has already settled on this direction, and the patch itself is uncontroversial.

The email captures a minor follow-up discussion about error-handling style. Patrick Steinhardt points out that the `&&` chains in the installation steps are now redundant because `set -e` (already active via `ci/lib.sh`) will abort the script on the first failure. Harald Nordgren agrees, acknowledging that dropping the `&&` chains would simplify the script further. This is a **surface-level** stylistic observation, not a substantive critique—the patch’s core functionality is unaffected, and the change would be purely cosmetic.

The series is otherwise ready for final review and a formal positive sign-off (Reviewed-by or Acked-by) from a contributor other than Junio C Hamano or Patrick Steinhardt. The preparatory cleanup patch (1/2) is still awaiting GitLab CI results to confirm it doesn’t break anything there, but this second patch is not blocked by that. If you’re tracking CI noise reduction, this patch delivers the agreed solution cleanly.
