This is the **final patch in a v4 bugfix series** that closes a data-loss race in `git repack -d`. The series is now **production-ready** and targets the pack subsystem.

This patch (3/3) replaces the `--honor-pack-keep` mechanism with a snapshot-based approach: when `repack` starts, it writes the names of all non-kept and cruft packs to a temporary file and passes that file to `pack-objects` via the new `--ignore-pack-keep-from` option. `pack-objects` then treats those packs as if they had no `.keep` file, regardless of what appears on disk later. The result is that a `.keep` file that appears mid-repack cannot cause objects to be deleted, eliminating the race.

The implementation is minimal and focused. The snapshot file is written only when there are packs to delete, matching the behavior of `--honor-pack-keep` when no `.keep` files exist. Pack names with newlines are refused to prevent splitting, and alternates are traversed to ensure safety (trading disk space for correctness). The patch includes thorough test coverage for `-a -d`, `-A -d`, `-k`, `--cruft`, `--geometric`, and `--filter`, all of which now survive a mid-repack `.keep` without losing objects.

The series as a whole is well-motivated, thoroughly tested, and addresses all prior review feedback. Junio’s ack for the cruft-walk fix (v3 patch 2/5) remains valid, and the v4 redesign simplifies the approach by removing the need for `--honor-pack-keep` entirely.
