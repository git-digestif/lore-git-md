This is a two-patch bugfix series targeting Git's fetch negotiation machinery, specifically the default and skipping negotiators. The series resolves a correctness issue in commit queue ordering and a latent edge-case bug in the negotiation logic that could trigger a `BUG()` when unparsable commits are revisited.

The core problem is that commits were being marked as `SEEN` before their date fields were parsed, causing two distinct bugs. First, in the skipping negotiator, unparsed parent commits (with zero dates) could be incorrectly prioritized behind older ref tips, potentially causing negotiation to terminate prematurely without discovering the most recent common ancestor. Second, in both negotiators, marking commits as `SEEN` before parsing could trigger a `BUG()` if an unparsable commit was revisited by another child commit. The fix moves commit parsing into `rev_list_push()` and defers the `SEEN` flag until after parsing succeeds, ensuring the queue contains only parsed commits with valid dates.

The series touches `negotiator/default.c` and `negotiator/skipping.c`, with test coverage added to `t/t5552-skipping-fetch-negotiator.sh` and `t/t5702-protocol-v2.sh`. The first patch fixes the latent bug in the default negotiator, while the second patch applies the same fix to the skipping negotiator and adds a new test case demonstrating the missing-parent edge case. The test suite now verifies both the original ordering bug and the robustness against unparsable commits.
