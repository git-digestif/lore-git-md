This is the second patch in the v3 series targeting CI/build system behavior. It implements the stricter consensus reached in the thread: if Perforce, Git LFS, or JGit fail to install on platforms that require them (ubuntu-* for all three, macos-* for Perforce), the build now fails immediately rather than allowing silent skips or warnings. The patch removes the now-dead presence checks and warnings at the end of `ci/install-dependencies.sh`, moves version output (`p4d -V`, `git-lfs version`, `jgit version`) inline right after each successful install for confirmation, and relies on `set -e` (already active via `ci/lib.sh`) to abort on the first failed install. This matches how every other install step in the file already works and simplifies the code by 19 lines.

The change is confined to `ci/install-dependencies.sh` and does not alter Git's functionality. The motivation is clear: reduce CI log noise and fail fast if required tools are missing, making broken downloads immediately visible rather than silently tolerated. The thread has already resolved the fundamental question in favor of strictness, and this patch cleanly implements that consensus. The preparatory cleanup (patch 1/2) removed the macOS `xattr` step, which was a no-op, and this patch removes the redundant error-handling logic, making the script more consistent.
