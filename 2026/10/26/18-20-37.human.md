This is a CI/build system patch that has been accepted for inclusion. Junio C Hamano has queued the v2 revision of Taylor Blau’s patch to pin GitHub Actions in Git’s main workflow file to full commit SHAs instead of version tags or branches. The change is now unblocked after the commit message was strengthened to clearly articulate the security rationale—specifically, the risk of supply-chain attacks if an action’s repository is compromised and a tag is moved to a malicious revision.

The patch touches only `.github/workflows/main.yml`, replacing 32 action references (e.g., `actions/checkout@v6` → `actions/checkout@d23441a48e516b6c34aea4fa41551a30e30af803`) while retaining the original version tags in comments for readability. No functional changes to Git itself are introduced; this is purely a CI infrastructure update. The change aligns with GitHub’s security recommendations and is part of broader CI modernization efforts (`ps/ci-housekeeping-and-modernizations` and `jk/http-curl-strip-creds`).

Junio’s earlier policy concern—that the change addressed a downstream constraint rather than an upstream need—has been resolved by the revised commit message, which now explicitly documents the security trade-offs and frames the maintenance overhead (updating SHAs for security fixes) as justified. The "last one wins" precedent worry (that accommodating one organization’s policy could invite conflicting requests) remains noted but is no longer a blocker. The patch is low-risk, mechanical, and on track for `next`.
