This is a **CI/build system** patch, now in its second iteration, that makes the GitHub Actions CI build fail immediately if Perforce, Git LFS, or JGit fail to install on platforms where they are required. The patch is a direct implementation of the stricter approach agreed in the thread: tools that are necessary for a platform must be present, and the build should not proceed if they cannot be installed.

Patrick Steinhardt’s review here is **substantive and tested**: he confirms the patch correctly implements the agreed behavior, checks that the version output commands (`p4d -V`, `git-lfs version`, etc.) will work as written (they will, because `CUSTOM_PATH` is already set up in `ci/lib.sh`), and notes minor stylistic inconsistencies (the `rm` placement for Git LFS vs. Perforce on macOS). His only open question is whether the macOS `xattr` step should also be made mandatory, but he leaves that decision to the author, who has chosen to keep it optional (`|| true`) as a deliberate simplification.

The patch itself is **ready for final review**: it is small, focused, and uncontroversial. It touches only `ci/install-dependencies.sh`, adds clear error messages, and prints version output immediately after successful installation for confirmation.
