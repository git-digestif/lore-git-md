This is the first patch in a now-merged documentation series introducing `gitmergeconflicts(7)`, a new man page that consolidates Git’s scattered merge-conflict guidance into a single, example-driven guide. The patch creates the new `Documentation/gitmergeconflicts.adoc` file (339 lines) and updates the build system (`.gitattributes`, `Makefile`, `meson.build`, `command-list.txt`) to integrate it.

The new guide is organized as a practical walkthrough, covering foundational concepts (what a merge conflict is, when it occurs), an exhaustive list of commands that can trigger conflicts (`git merge`, `git rebase`, `git cherry-pick`, `git revert`, and others), resolution workflows (edit, stage, continue), and tools for handling conflicts (e.g., `git diff AUTO_MERGE`, `git log --merge --patch`). It clarifies terminology like "ours" and "theirs," explains merge conflict markers, and demonstrates the benefits of `merge.conflictstyle=diff3` with side-by-side examples. The guide also addresses long-standing pain points in the existing documentation, such as references to non-existent steps in `git-merge.adoc` and inconsistent use of "ours/theirs."

The patch is purely additive—no behavior changes—and is part of a six-patch series that surgically updates existing man pages to replace redundant conflict-resolution sections with cross-references to the new guide. The series has Junio’s `Reviewed-by:` and is now cooking in `next`. This patch specifically lays the groundwork for the new guide, while follow-up patches (2/6–6/6) handle the cross-references and cleanup in other man pages. The guide’s structure and content reflect extensive feedback from prior iterations, including input from D. Ben Knoble, Patrick Steinhardt, and Marie Claire LeBlanc Flanagan.
