This is the second patch in the v4 series fixing a data-loss race in `git repack`. It introduces `--ignore-pack-keep-from=<file>` to `git pack-objects`, a new option that reads a file containing pack names and treats those packs as if they had no `.keep` file. This is a **scalable, race-free alternative** to the existing `--keep-pack` mechanism, designed specifically for `git repack` to avoid command-line length limits and ensure `.keep` files that appear mid-repack cannot cause objects to be omitted from the new pack.

The implementation reuses the existing `--keep-pack` logic (now repurposed for exclusion) and adds two tests in `t/t7700-repack.sh`: one verifies functional equivalence with `--keep-pack` (packing reachable objects from the named pack while loosening unreachable ones), and another ensures the command fails cleanly when the input file is missing. The file format (one pack name per line, relative paths resolved against the working directory) matches existing Git tools like `git multi-pack-index write --refs-snapshot`, and the option is documented in `git-pack-objects.adoc` with a clear rationale: it is for callers like `repack` that are about to delete the named packs and must not be surprised by late-arriving `.keep` files.

This patch is **well-motivated and production-ready**. It addresses the scalability limitation of `--keep-pack` (which cannot handle many packs due to command-line length limits) and the race condition described in the series cover letter. The implementation is minimal, focused, and thoroughly tested, and it reuses existing code paths to minimize risk. No edge cases beyond the documented refusal of pack names containing newlines are known, and the performance impact is negligible (the file is read once at startup).
