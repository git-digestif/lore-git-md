This is the second patch in a two-part CI/build system series (v3) that tightens GitHub Actions CI behavior. The patch makes Perforce, Git LFS, and JGit installation mandatory on platforms that require them (ubuntu-* for all three, macos-* for Perforce), causing the build to fail immediately if installation fails rather than allowing silent skips or warnings. The change removes the now-dead presence checks and warnings at the end of `ci/install-dependencies.sh` and moves version output (`p4d -V`, `git-lfs version`, `jgit version`) inline right after each successful install for confirmation.

The motivation is clear: broken tool downloads can go unnoticed indefinitely when tests silently skip, so failing fast on installation failure reduces CI log noise and catches problems earlier. The thread has already resolved the fundamental question in favor of strictness, and this patch implements that consensus cleanly. The preparatory cleanup (patch 1) removed a macOS-specific `xattr` step that had been a silent no-op since 2022, and this patch simplifies error handling by relying on the `set -e` already active via `ci/lib.sh` to abort on the first failed install, matching how every other install step in the file already works.

The patch is well-motivated and uncontroversial. It touches only `ci/install-dependencies.sh` and does not alter Git's functionality. The range-diff shows the removal of redundant error handling and the dropped macOS `xattr` step, making the code simpler and more consistent.
