This thread explores a proposal by Massimiliano Cialdi to address a significant pain point in embedded development workflows: the redundant storage of Git objects across many clones and submodules. With 250 repositories on a single machine consuming 17.9 GiB in `.git` directories, Cialdi outlines a set of requirements (R1–R11) for a shared object store that would deduplicate objects while preserving local work and offline functionality. The inquiry is grounded in real-world testing, including two scripts that demonstrate critical flaws in Git’s current alternate mechanism—namely, that garbage collection (GC) in either the shared store or borrowers can inadvertently delete objects still in use.

Cialdi’s proposal is pragmatic and open-ended, exploring multiple technical approaches without committing to a specific implementation. These include using a remote helper to dynamically add alternates, enhancing `repack -l` to preserve local copies of objects reachable from selected refs, and integrating with sparse-checkout for versioned rules. The inquiry explicitly seeks upstream feedback on whether changes to Git itself—such as borrower-aware GC or repack-local improvements—would be welcome, suggesting the author is prepared to invest in a full implementation if the community sees value in the direction.

The thread is still in its early stages, with no responses yet from maintainers or other contributors. Key technical details likely to drive discussion include how the shared store would track borrowers’ reachability roots (O13) and how `repack -l` could be modified to avoid dropping objects still needed by borrowers (O14). The proposal also touches on broader workflow concerns, such as CI compatibility (R10) and sparse-checkout versioning (R9), indicating this is part of a larger effort to optimize embedded development. Prior art like Scalar’s shared object cache and depot_tools’ caches is mentioned, but the inquiry focuses on a solution that could be integrated into Git itself. For now, the thread remains a design exploration, awaiting input from the community on feasibility and direction.
