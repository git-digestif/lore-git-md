This is the final patch in a three-part performance optimization for `git send-pack`, targeting the common workflow of force-pushing rebased feature branches. The series as a whole teaches Git to avoid re-uploading large unchanged blobs when the old branch tip is locally available, without requiring server or protocol changes.

This patch implements the core logic in `send-pack.c` that enables the optimization. It modifies the ref-walking loop to inspect the old tip's tree for forced non-fast-forward updates of existing branches, using the new `--inspect-have` machinery introduced in earlier patches. The change is carefully scoped: it only applies to branches (not tags or other refs), skips shallow repositories (which already use a similar mechanism), and excludes fast-forward updates and rejected refs. The patch also updates the test expectations to reflect the reduced object count—expecting two packed objects (commit and tree) instead of three (commit, tree, and unchanged blob) after a rebase.

The implementation looks clean and well-considered. The conditional logic is precise, avoiding regressions in edge cases like shallow pushes or partial clones. The test adjustment is minimal and directly verifies the optimization's effect. This patch ties together the series' goal: making force-pushes of rebased branches more efficient by leveraging local knowledge of the receiver's state.
