This is a **substantive review** of the third patch in Harald Nordgren’s four-patch `v3` series for `git imap-send`. The patch removes a special-case exemption for messages starting with `From git-send-email`, which was originally introduced to work around `git imap-send`’s earlier requirement that `Date` appear before `Subject`. With the new order-agnostic parsing (Patch 2/4), the exemption is redundant, and the patch simplifies the code by treating all messages uniformly.

Patrick Steinhardt’s review raises a **technical edge case**: while the patch assumes all messages will have `Date` and `Subject` headers (since `git send-email` always includes them), RFC 5322 only *requires* `Date` (`SHOULD` for `Subject`). He questions whether tightening the rules to reject messages without `Subject` could break interoperability with other tools that generate valid but minimal mboxes. The review is not a rejection—Patrick acknowledges the edge case is likely unimportant—but he wants the commit message to explicitly address the backward-compatibility implications of dropping the special case. No alternative implementation is proposed; the feedback is purely about documentation clarity.

The patch itself remains uncontroversial. It deletes 13 lines of special-case logic, reuses the `has_required_headers()` helper from Patch 2/4, and includes a test confirming the `--imap-sent-folder` workflow still works. The series is otherwise ready for integration (Patches 2/4 and 4/4 are marked as such, and Patch 1/4 is already in `next`). This review does not block progress but may prompt a minor commit message tweak in a future iteration. Key files: `imap-send.c` (header-counting logic) and `t/t9001-send-email.sh` (test).
