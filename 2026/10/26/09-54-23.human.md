This is a CI/build system patch series (v3) that tightens GitHub Actions CI behavior by failing the build if Perforce, Git LFS, or JGit fail to install—rather than silently skipping them or emitting warnings on irrelevant platforms.

The series now consists of two patches. The first is a preparatory cleanup: it removes the macOS-specific `xattr -d com.apple.quarantine` step for Perforce binaries, which has been a no-op since Perforce’s install method switched from Homebrew to direct downloads in 2022. The second patch implements the stricter behavior agreed in the thread: installation failures for these tools now abort the build immediately, and version output is printed right after successful installation for confirmation. The series also drops redundant error-handling blocks, relying instead on `set -e` (already active via `ci/lib.sh`) to abort on the first failure.

The motivation is clear: reduce CI log noise while ensuring that tools required for a platform are actually present. The v3 iteration addresses Patrick Steinhardt’s feedback by removing the unnecessary macOS quarantine step and simplifying error handling. The changes are confined to `ci/install-dependencies.sh` and do not affect Git’s core functionality. The series looks well-crafted, with a concise range-diff showing the evolution from v2, and the commit messages explain the rationale and changes clearly.

This is a low-risk, high-signal improvement for CI reliability. The preparatory cleanup in the first patch is particularly welcome, as it removes dead code. The series is ready for final review and should be uncontroversial.
