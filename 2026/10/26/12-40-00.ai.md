This is the first patch in the now-merged `gitmergeconflicts(7)` documentation series. It introduces the new `gitmergeconflicts.adoc` man page (339 lines), which consolidates Git’s scattered merge-conflict resolution guidance into a single, example-driven guide. The patch also updates `.gitattributes`, `Documentation/Makefile`, `Documentation/meson.build`, and `command-list.txt` to integrate the new page into the documentation build system.

The new guide is organized as a practical walkthrough, covering foundational concepts (what a merge conflict is, when it occurs), an exhaustive list of commands that can trigger conflicts (`git merge`, `git rebase`, `git cherry-pick`, `git pull`, `git revert`, etc.), resolution workflows (edit, stage, continue), and tools for handling conflicts (e.g., `git diff AUTO_MERGE`, `git log --merge --patch`). Key improvements over existing documentation include consistent terminology ("ours" vs. "theirs"), removal of RCS analogies, and a side-by-side `diff3` example demonstrating how the common ancestor reveals intent (e.g., both sides removing a fruit from the original list). The guide actively promotes `merge.conflictstyle=diff3` as a best practice but omits `zdiff3` entirely, deferring its explanation to future work.
