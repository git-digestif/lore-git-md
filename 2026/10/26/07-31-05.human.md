This is the second patch in a two-part test infrastructure series targeting Meson compatibility for Git’s `clar`-based unit tests. The patch adds `-l`/`--long-tests` as a NOOP argument to the unit test runner, allowing it to silently ignore the flag when passed via `meson test --test-args='-ilx'`. This restores compatibility with common Meson test invocations without altering test behavior.

The change is minimal—just one line added to `t/unit-tests/unit-test.c`—and follows the established pattern introduced in commit 9faf3963b6 for handling unrecognized flags. The motivation is practical: users running the Meson command currently encounter a hard failure because the test binary rejects `-l`, even though the flag is irrelevant to unit tests (the `GIT_TEST_LONG` environment variable is used in CI to enable expensive tests). The patch is uncontroversial, with no substantive objections raised in review.

This patch depends on the first patch in the series, which reorders existing NOOP arguments alphabetically to maintain consistency. The series as a whole is ready for integration, with CI pipelines confirming no regressions. The only feedback so far has been surface-level (a commit message typo fix and approval of the alphabetical ordering), but the technical approach is sound and aligns with prior work in this area.

The patch is part of the ongoing test modernization effort, specifically the adoption of the `clar` unit test framework. It’s a small but useful step toward making Git’s test infrastructure more flexible and user-friendly, particularly for developers working with Meson. If you’re following the `clar` unit test rollout or Meson integration, this is worth noting—but otherwise, it’s a low-impact, incremental improvement.
