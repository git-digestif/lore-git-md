## 2026/11/04

- [2026/11/04/17-13-55 by Marc Strapetz <marc.strapetz@syntevo.com>] Marc Strapetz revived the series, arguing that the default push path still misses a worthwhile optimization for common rebase-and-force-update workflows; he distinguished the approach from push negotiation by noting it targets the non-negotiated default path using the already advertised old destination tip with no additional round trip, server change, or protocol change, and can avoid resending objects already present at the destination for qualifying non-fast-forward branch updates, reducing pack size, network transfer, and client- and server-side work while leaving ordinary fast-forward pushes unaffected. He reported that current measurements show small cases improve while a low-benefit worst-case fixture adds about 8% packing time for negligible size reduction, noting these cover only local pack generation and not the expected network and server-side benefits, and asked Taylor Blau and Derrick Stolee (added to the thread for their pack-generation and revision-traversal work) whether the targeted optimization is a reasonable tradeoff on the default path or whether a simpler approach exists.
