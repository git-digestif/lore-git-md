This is a test infrastructure patch, part of the ongoing `clar`-based unit test modernization effort. The series makes Git’s unit test runner silently ignore the `-l`/`--long-tests` flag when passed via `meson test --test-args='-ilx'`, restoring compatibility with common Meson test invocations without altering test behavior.

The v2 submission is a resend to correct the thread linkage (v1 was sent as a new thread) and fix a commit message typo (`prerequiiste` → `prerequisite`). No code changes were made; the two patches remain identical to v1. Patch 1/2 reorders existing NOOP arguments alphabetically, and patch 2/2 adds `-l`/`--long-tests` as a new NOOP argument, following the established pattern from commit 9faf3963b6 (t: introduce compatibility options to clar-based tests, 2024-12-13).

The motivation is practical: users running `meson test -v --test-args='-ilx'` currently encounter a hard failure because the unit test binary rejects the unrecognized `-l` flag. The fix is minimal (two lines modified in `t/unit-tests/unit-test.c`) and uncontroversial, with CI pipelines (GitHub, GitLab) confirming no regressions. Some macOS runners did not execute, but this is unrelated to the patch.
