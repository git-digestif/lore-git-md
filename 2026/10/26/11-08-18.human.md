This is the second patch in the two-part v3 series that tightens GitHub Actions CI behavior. The patch implements the agreed consensus: if Perforce, Git LFS, or JGit fail to install on platforms that require them (ubuntu-* for all three, macos-* for Perforce), the build now fails immediately rather than allowing silent skips or warnings. The change removes redundant error-handling blocks and moves version output inline for confirmation, relying on `set -e` (already active via `ci/lib.sh`) to abort on the first failed install.

Patrick Steinhardt’s reply points out a minor inconsistency: the patch removes explicit error handling for the Perforce, Git LFS, and JGit installation blocks but leaves the `&&` chains intact. Since `set -e` is already active, these `&&` chains are now redundant—they no longer serve any purpose because the script will abort on the first failure regardless. This is a surface-level nit: the patch still works as intended, but the leftover `&&` chains make the code slightly less clean. The observation is valid and worth addressing in a follow-up, though it does not affect functionality.

The thread has already resolved the core question in favor of strictness, and this patch cleanly implements that decision. The preparatory cleanup (patch 1/2) removed a no-op macOS `xattr` step, and this patch removes the now-unnecessary warnings and error-handling logic. The series is ready for final review and a formal positive sign-off from a contributor other than Junio C Hamano or Patrick Steinhardt. The remaining loose end is purely stylistic and does not block progress.
