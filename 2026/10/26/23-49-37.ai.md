This is the first patch in a two-patch bugfix series targeting Git's fetch negotiation machinery, specifically the default negotiator. The patch addresses a latent edge-case bug where `rev_list_push()` marked commits as `SEEN` before parsing succeeded, which could lead to incorrect negotiation termination or trigger a `BUG()` if an unparsable commit was revisited.

The fix defers setting the `SEEN` flag until after `repo_parse_commit()` succeeds, ensuring that only successfully parsed commits are marked as queued. This change aligns the default negotiator's behavior with the broader goal of ensuring all commits in the queue have valid dates before being prioritized. The patch also adds a new test case in `t/t5702-protocol-v2.sh` that verifies negotiation continues correctly even when a missing ancestor (unparsable commit) is encountered, preventing premature termination.

The diff is minimal and focused: it moves the `SEEN` flag assignment after the parsing check in `negotiator/default.c` and introduces a 31-line test case. The test constructs a scenario where the first batch of commits includes a missing parent, ensuring the negotiation logic does not incorrectly count the unparsable commit as queued and continues to process unrelated tips. This is a well-targeted fix for a subtle correctness issue, with clear test coverage demonstrating the problem and the solution. The patch is part of a resolved series that has already merged to `master`.
