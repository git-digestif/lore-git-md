Hi Julia, Team,

There was a request earlier for notes from Windows Git users, so as I am one I thought I might respond a little.

I use Git mostly via a GUI app.  I do understand that documentation for Git proper needs to treat it as command-line as all the GUIs are a bit different.  I think they all work via the CLI version and all that I use do always show the commands, so I quite understand that documentation needs to be done like that.

However....

Windows users don't use vim (or  vi).
Windows users don't use ssh.

I'm sure neither of those are completely true, so please no-one write in and say that I'm wrong, but I think a lot of Windows Git users won't do so, and will feel such mentions are not aimed at them and may take it that the whole document isn't either.

I'm sure I've read somewhere that ssh is a nightmare to set up on Windows, so a first-class mention of it may put off Windows users.  It might perhaps get a note that it's for Linux/Unix/etc users only (or only-ish).  Anyway, I've been developing on Windows for about 30 years and using Git for about eight, and never needed ssh for anything.  Https is all that I've used for GitHub and BitBucket, which you might consider likely to be the most common servers users might see.  And bearing in mind that GitHub has on-prem versions that may be found in corporate settings.  I'm not sure how easy it is to set up a local Git server by other means as I've never really tried.

Vim I think is very uncommon on Windows.  The only editor that is universal is NotePad, but I don't think that would be used much for serious development.  I use versions of Visual Studio but Visual Studio Code (no relation) may be more common nowadays.  For general editing I may use emacs for historical reasons, but I suspect that's nearly as rare on Windows as vim.  Something like NotePad++ would be better.  But then again, it isn't universal.

In short, if it mentions of someone using ssh and vim, I immediately think they are a Linux user, and I may tend to skip those parts of an article, or even assume the whole thing is not aimed at me.
