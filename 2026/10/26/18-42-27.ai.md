This is a small feature patch for `gitk`, the graphical commit history browser.

The patch adds a new context-menu item labeled "Cherry-pick with cross-reference" that invokes `git cherry-pick -x` instead of the plain `cherry-pick` action. The `-x` flag appends a line to the commit message recording the original commit hash, which is useful for traceability in workflows like backporting. The change is confined to the Tcl/Tk code in `gitk-git/gitk`: it inserts the new menu item, adjusts the indices of the following items, and modifies the `cherrypick` procedure to accept an optional `-x` (or any other) flag.

The motivation is clearly stated: it closes a gap in `gitk`’s GUI workflow for projects that need backported commits to remain traceable to their originals. The patch is self-contained, touches only one file, and includes no new dependencies or tests. It looks like a well-scoped, uncontroversial addition that should integrate cleanly into the existing code.
