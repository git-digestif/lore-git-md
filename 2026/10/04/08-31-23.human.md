This is the third patch in Harald Nordgren’s four-patch v6 series introducing a "matching-inspired" fetch mode for shallow repositories. It adds a `--limited-fetch` flag to `git remote add` that configures the remote to use the new `remote.<name>.refmap` instead of the traditional wildcard `remote.<name>.fetch` refspec. The flag is rejected if combined with `-t/--track` or `--mirror`, since those options already specify what to fetch.

The patch is small and focused: it updates `builtin/remote.c` to parse the new flag, sets up the refmap configuration when the flag is given, and adds two tests in `t/t5505-remote.sh` to verify the flag works and conflicts with `-t` as expected. The documentation in `git-remote.adoc` is updated to describe the new option and link to `git-fetch` for details on the refmap behavior.

This is a straightforward feature addition with no behavioral surprises. The implementation is clean, the tests cover the happy path and error cases, and the documentation is clear. The patch is ready to queue alongside the rest of the series.
