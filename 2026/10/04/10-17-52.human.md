This is a feature patch series adding `--[no-]range-diff-notes` options to `git format-patch`. The v4 iteration is a minor update to the already technically complete v3, addressing final editorial feedback from Junio C Hamano.

The series introduces two new command-line options: `--range-diff-notes=<ref>` (to specify which notes refs to show in the range-diff section) and `--no-range-diff-notes` (to suppress notes in the range-diff entirely). This gives users fine-grained control over notes display, allowing them to include notes in the patch output while omitting them from the range-diff, or vice versa. The implementation is clean and well-structured, with the first patch simplifying parameter handling in `get_notes_args` and the second patch adding the new functionality.

The v4 changes are minimal and cosmetic: trimming verbose explanations from the commit messages and documentation, and refactoring the option callback to reuse existing `parse_opt_string_list` logic rather than duplicating it. These adjustments address Junio’s final feedback from v3, leaving no substantive concerns unaddressed. The documentation is now concise and direct, clearly explaining the behavior without unnecessary examples.

Test coverage is thorough, including edge cases like single-patch range-diffs (which previously had a bug fixed in commit 155986b4). The tests also verify that `--range-diff-notes` has no effect when `--range-diff` is not used, avoiding silent failures. The series touches only `builtin/log.c`, `Documentation/git-format-patch.adoc`, and the test suite, with no changes to core Git internals.

This is a well-crafted feature that addresses a real workflow need. The implementation is technically sound, the documentation is clear, and the test coverage is comprehensive. The series is now ready for maintainer approval and integration. If you use `git format-patch --notes` and have ever wanted to suppress notes in the range-diff section, this feature will be useful.
