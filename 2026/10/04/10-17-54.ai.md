This is the second patch in Kristoffer Haugsbakk’s v4 series introducing `--[no-]range-diff-notes` to `git format-patch`. The patch implements the core functionality: two new CLI options (`--range-diff-notes=<ref>` and `--no-range-diff-notes`) that let users control which Git notes (if any) appear in the range-diff section of the output, independently of the notes shown on the patches themselves.

The patch touches `builtin/log.c`, `Documentation/git-format-patch.adoc`, and adds comprehensive tests to `t/t3206-range-diff.sh`. A new `struct rdiff_notes` tracks whether the user wants to override the default notes behavior for range-diffs, and a parse-options callback (`rdiff_notes_cb`) wraps `parse_opt_string_list` to avoid code duplication. The interaction rule is simple: if no range-diff notes options are given, the range-diff uses the same notes as the patches; otherwise, it uses only the explicitly specified notes (including none). The documentation has been rewritten in a concise, direct style as requested by Junio C Hamano, explicitly stating that `--range-diff-notes=<ref>` specifies a *different* notes ref for the range diff.

Test coverage is thorough, verifying suppression of range-diff notes, use of different notes refs for patches and range-diffs, and the requirement that `--range-diff-notes` takes a value. Two additional tests address the single-patch case as regression tests for a prior bug fix (155986b4, 2025-09-25). The patch also confirms that `--range-diff-notes` has no effect when `--range-diff` is not used, avoiding silent failures.

The v4 iteration addresses all remaining feedback from Junio: the commit message has been trimmed, the documentation rewritten, and the option callback refactored to wrap `parse_opt_string_list` rather than duplicating its logic. No substantive technical concerns remain; the series is now technically complete and awaits maintainer approval. Key names introduced are `--range-diff-notes`, `--no-range-diff-notes`, `struct rdiff_notes`, and `rdiff_notes_cb`.
