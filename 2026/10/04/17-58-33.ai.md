This is the v5 iteration of Kristoffer Haugsbakk’s feature series adding `--[no-]range-diff-notes` options to `git format-patch`. The series is now down to two patches after the preparatory refactoring was merged in v4. This version addresses Junio C Hamano’s final editorial feedback on the commit message for patch 2/2: the explanation of why `--[no-]range-diff-notes` does not error out when used without `--range-diff` has been condensed from a meandering multi-paragraph digression into a concise three-line rationale, and the thematic breaks (`***`) have been removed. The interdiff shows only this textual change; the code, tests, and documentation remain identical to v4.

The series is technically complete and ready for integration. It introduces two new CLI options: `--range-diff-notes=<ref>` (which requires an explicit ref argument) and `--no-range-diff-notes` (which means “no notes for range-diff” without fallback). The implementation touches `builtin/log.c`, updates `Documentation/git-format-patch.adoc`, and adds comprehensive tests in `t/t3206-range-diff.sh`. The interaction rule between patch notes and range-diff notes is unchanged from v4: if no range-diff notes options are given, the range-diff uses the same notes as the patches; otherwise, it uses only the explicitly specified notes (including none). The commit message now explicitly states that `--[no-]range-diff-notes` does not error out when used without `--range-diff` to accommodate workflows where users configure default options in aliases.

Key names introduced in this series are `--range-diff-notes`, `--no-range-diff-notes`, the `struct rdiff_notes` configuration struct, and the `rdiff_notes_cb` option callback. The series depends on two prior commits (85bd88a7 and 155986b4, both from 2025-09-25) that introduced the `rdiff_log_arg` field and fixed a single-patch bug, respectively. All maintainer feedback from v1 through v4 has been addressed, and the series is now in its final form. Junio’s queue is the next step.
