Thread identity
Subject: `git repack --dry-run --drop-filtered` violates dry-run contract
Series version: standalone bugfix (no series)
Originating author: Coy Geek
Thread type: bug report

Core problem or goal
The `--dry-run` option of `git repack`, when used together with `--drop-filtered`, incorrectly mutates repository storage by writing new promisor packs and (with `-d`) deleting old packs, despite the manual’s guarantee that it will only list candidate objects without making any changes.

Current status
Under review; no prior discussion of this specific regression is recorded. The bug is confirmed in Git 2.56.0; presence on `master` is unknown.

Key technical details
- Command: `git repack -a --filter=blob:limit=1m --drop-filtered --dry-run`
- Files touched: `.pack`, `.idx`, `.promisor`, `.rev` (newly written); original pack files (deleted when `-d` is added)
- Subsystem: `builtin/repack.c`, specifically the `delete_redundant` logic that is guarded by `!dry_run` but execution continues past the candidate-printing block
- On-disk format: new promisor packs are created; no data loss observed (blob remains accessible)
- Test coverage: reproduction script provided (Python, self-contained, portable)

Open questions and loose ends
- Whether the bug exists on `master` (author did not test)
- Whether a fix should also address the analogous `--geometric` code path (not mentioned in the report)
- Whether the manual’s wording should be tightened to clarify that `--dry-run` applies to *all* side effects, not just pack rebuilding

Participant positions
