This is the final patch in Harald Nordgren’s four-part series introducing a "matching-inspired" fetch mode for shallow repositories. It makes `--limited-fetch` the default when adding a remote to a shallow repository, ensuring that `git remote add` does not set up a wildcard refspec that would cause `git fetch` to negotiate history for every branch the remote has.

The patch modifies `builtin/remote.c` to check whether the repository is shallow (using `is_repository_shallow()`) and, if so, defaults to `--limited-fetch` unless `--no-limited-fetch`, `-t/--track`, or `--mirror` is given. The documentation in `git-remote.adoc` is updated to explain the new default behavior and how to override it. The test suite (`t/t5505-remote.sh`) adds four new tests: one verifying that `-t` still sets an explicit refspec in a shallow repository, one confirming that full repositories retain the wildcard refspec, one demonstrating the new default in a shallow repository, and one showing that `--no-limited-fetch` overrides the default.

This is a well-motivated change that directly addresses the problem described in the cover letter: shallow clones with many-branch remotes can experience slow or hanging fetches, and this patch prevents that by default. The implementation is clean, the tests are thorough, and the documentation is clear. No substantive objections remain, and Junio has already stated he will queue the series. The patch is ready for integration.
