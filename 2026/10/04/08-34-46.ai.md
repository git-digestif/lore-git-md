This is a **feature patch** revising the behavior of `git branch --delete-merged` to default to considering *every* upstream branch when no explicit pattern is provided. It is the second iteration (`v2`) of a patch originally posted by Harald Nordgren, responding to Junio C Hamano’s review of the first version.

The patch changes the command-line interface so that `git branch --delete-merged` (when placed last) now implicitly uses `**` as the default pattern, matching all upstreams. This replaces the previous requirement to specify a pattern like `*/*` or `origin/*`. The change is backward-compatible: existing invocations with explicit patterns remain unchanged. Documentation and help text are updated to reflect that the pattern is now optional, and a new test case verifies the default behavior, including interaction with `--dry-run`.

Key technical details: the implementation uses `PARSE_OPT_LASTARG_DEFAULT` to supply the default value (`**`) when `--delete-merged` appears as the last argument. The `**` pattern is not user-facing but effectively matches every configured upstream. The patch touches three files: `Documentation/git-branch.adoc`, `builtin/branch.c`, and `t/t3200-branch.sh`.

The v2 iteration addresses Junio’s review by renaming the default pattern from `*/*` to `**` and dropping the reference to `--merged` in the commit message. However, the core design question raised in the review remains open: whether defaulting to *every* upstream aligns with the stated goal of cleaning up branches whose work has landed upstream. Junio contrasted this with other Git commands (e.g., `--merged`, `--contains`) that default to the *current* branch, suggesting the latter may be more intuitive. The thread has not yet resolved whether the default should be narrower (e.g., only branches merged into the current branch) or if `**` is the correct abstraction.

The patch is well-structured and includes thorough test coverage for the new behavior, though edge cases (e.g., multiple `--delete-merged` options, `--dry-run` in non-last positions) remain untested. No additional reviewer feedback beyond Junio’s review has been recorded. The change is motivated by ergonomics but lacks citation of prior user requests or discussion. The next steps in the thread are likely to focus on the design question of what the default should match.
