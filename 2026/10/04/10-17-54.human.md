This is the second patch in a two-part feature series adding `--[no-]range-diff-notes` options to `git format-patch`. The series is now technically complete and ready for maintainer approval.

The patch implements independent control over Git notes in the range-diff section of `git format-patch` output. Users can now suppress notes in the range-diff (e.g., version-iteration notes that clutter the diff) while keeping them in the patch output, or specify a different notes ref for the range-diff. The v4 design adopts Junio C Hamano’s suggested rule: `--no-range-diff-notes` means "no notes for range-diff" without fallback, and `--range-diff-notes=<ref>` requires an explicit ref argument, enforcing clean separation between patch notes and range-diff notes.

The implementation touches `builtin/log.c` and updates the documentation in `git-format-patch.adoc`. A new `struct rdiff_notes` tracks whether the user wants to override the default notes behavior for range-diffs, and the option callback (`rdiff_notes_cb`) now wraps `parse_opt_string_list` rather than duplicating its logic. The patch also adds comprehensive tests in `t/t3206-range-diff.sh`, including two regression tests for the single-patch case (where the range-diff appears in the patch rather than the cover letter).

The commit message is concise and direct, reflecting Junio’s feedback to trim expository detail. The documentation is similarly streamlined, clearly stating that `--range-diff-notes=<ref>` specifies a *different* notes ref for the range-diff (not additive to `--notes`). The patch is well-tested and addresses all prior feedback; no substantive concerns remain. The series is now awaiting Junio’s decision on whether to accept the feature.
