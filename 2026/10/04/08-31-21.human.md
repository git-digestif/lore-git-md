This is the first patch in a four-part series introducing a "matching-inspired" fetch mode for shallow repositories. The patch adds a new per-remote configuration variable, `remote.<name>.refmap`, which provides the default value for the `--refmap` command-line option in `git fetch`. This is a foundational change that enables the later patches to implement dynamic branch selection without breaking backward compatibility.

The implementation is straightforward: `remote.c` is updated to parse the new configuration, `builtin/fetch.c` uses the configured refmap as the default `--refmap` value when no explicit refspec is given, and the documentation (`config/remote.adoc` and `fetch-options.adoc`) is extended to describe the new setting. The tests in `t/t5510-fetch.sh` verify that the configuration behaves identically to the `--refmap` command-line option.

The commit message and documentation are clear and precise, defining `remote.<name>.refmap` as "used to map remote refs being fetched to remote-tracking refs to store" — a wording that directly addresses Junio C Hamano’s earlier review request. The patch itself is well-crafted, with no substantive objections remaining from prior iterations. It is a clean, mechanical addition that lays the groundwork for the more complex logic in the subsequent patches. If the series as a whole is queued, this patch is ready to go.
