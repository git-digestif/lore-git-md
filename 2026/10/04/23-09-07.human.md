This is a feature patch introducing a unified `post-worktree` hook for Git's worktree subsystem. It is the first patch in Domen Kožar's v3 series, replacing the earlier v2 proposal for three separate hooks (`post-worktree-add`, `post-worktree-remove`, `post-worktree-move`) with a single hook that handles all three events via a subcommand-style interface.

The patch adds a new `post-worktree` hook that runs after worktree creation, movement, or removal. The hook receives four arguments: the event type (`add`, `move`, or `remove`), the worktree identifier, the old absolute path, and the new absolute path (empty strings are passed for paths that don't apply). This design lets a single configured command handle all three lifecycle events without relying on argument count to distinguish them. The hook runs in the repository where the command was invoked, not in the affected worktree, and its exit status is reflected in the command's exit status but does not undo the operation.

The implementation touches `builtin/worktree.c` (hook invocation points), and adds comprehensive test coverage in `t/t2400-worktree-add.sh` and `t/t2403-worktree-move.sh`. The hook is documented in `Documentation/githooks.adoc` and registered in `hook-list.h` via `Documentation/config/hook.adoc`. The tests cover ordinary, bare, and linked callers, no-checkout and orphan worktrees, relative paths, paths with spaces, configured hooks, and hook failures.

This v3 iteration is a direct response to Junio C Hamano's fundamental objection to the v2 series: the unified hook narrows the interface and makes the design more palatable for a native Git hook. Domen explicitly positions this as a compromise, seeking clarity from Junio on whether it meets the bar for acceptance before further iteration. The patch is well-motivated and addresses a real gap in Git's automation story, particularly for tooling that manages ephemeral worktrees. The commit message and documentation clearly explain the design choices, including edge cases like hook ordering and path resolution during pruning.
