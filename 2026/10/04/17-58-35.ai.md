This is the final patch (2/2) in Kristoffer Haugsbakk’s **`--[no-]range-diff-notes` feature series**, now at v5. The patch teaches `git format-patch` to accept `--range-diff-notes=<ref>` and `--no-range-diff-notes` options, allowing users to control Git notes inclusion in the range-diff section independently of the patch output. This version addresses Junio C Hamano’s last editorial feedback from v4 by condensing the commit message’s explanation of why `--[no-]range-diff-notes` does not error out when used without `--range-diff` into a concise three-line rationale.

The implementation touches `builtin/log.c` (adding a new `struct rdiff_notes` to track override behavior and notes refs, plus a parse-options callback), updates `Documentation/git-format-patch.adoc` to document the new options, and extends `t/t3206-range-diff.sh` with comprehensive tests covering suppression, ref overrides, and single-patch edge cases. The interaction rule remains unchanged: if no range-diff notes options are given, the range-diff uses the same notes as the patches; otherwise, it uses only the explicitly specified notes (including none). The preparatory refactoring (1/2) was merged prior to v5, simplifying `get_notes_args` by removing an unnecessary parameter and directly using `rev->rdiff_log_arg`.

Key names introduced are `--range-diff-notes`, `--no-range-diff-notes`, `struct rdiff_notes`, and `rdiff_notes_cb`. The series depends on two prior commits (85bd88a7 and 155986b4, both from 2025-09-25) that introduced the `rdiff_log_arg` field and fixed a single-patch bug. All maintainer feedback from v1 through v4 has been addressed, and the series is now technically complete and ready for integration into Junio’s queue. The next step is Junio’s final review and queueing.
