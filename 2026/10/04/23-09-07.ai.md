This is a feature patch introducing a unified `post-worktree` hook for Git's worktree subsystem. It is the first patch in Domen Kožar's v3 series, replacing the earlier v2 proposal for three separate hooks (`post-worktree-add`, `post-worktree-remove`, `post-worktree-move`) with a single hook that uses a subcommand-style interface. The patch directly addresses the thread's core goal: providing reliable observability for worktree lifecycle events (creation, movement, removal) even when the caller is uncontrolled (e.g., an IDE or manual `rm -rf`).

The hook takes four arguments: the event name (`add`, `move`, or `remove`), the worktree identifier (its administrative directory name), the old absolute path, and the new absolute path. Empty strings are used for paths that do not apply (e.g., `""` for the new path in a `remove` event). This design allows a single configured command to handle all three events without relying on argument count to distinguish them. The hook runs in the repository where the command was invoked, not the affected worktree, and its exit status is reflected in the command's exit status but does not undo the operation. The `add` event runs after `post-checkout`, even if the latter fails, because the worktree remains present.

The implementation touches `builtin/worktree.c` (hook invocation points), and adds comprehensive test coverage in `t/t2400-worktree-add.sh` and `t/t2403-worktree-move.sh`. The hook is documented in `Documentation/githooks.adoc` and registered in `hook-list.h` via `Documentation/config/hook.adoc`. The patch addresses all prior feedback from Phillip Wood's substantive review of v1 and v2: the hook runs unconditionally after `post-checkout`, handles all three lifecycle events, and uses a consistent interface. The commit message and documentation clearly explain the design choices, including edge cases like relative paths, paths with spaces, and hook failures.

This patch is a significant improvement over the v2 series. The unified hook is simpler to configure and more flexible for external tools, while the subcommand-style interface avoids the need for separate hooks. The test coverage is thorough, covering ordinary, bare, and linked worktrees, `--no-checkout` and `--orphan` options, relative paths, and configured hooks. The patch looks technically sound and is likely to be of interest to anyone building tooling around Git worktrees, particularly AI-driven development environments that manage ephemeral worktrees.

The series remains in `seen` pending resolution of Junio C Hamano's fundamental objection to hooks. Domen's compromise argues that hooks are necessary for observability when the caller is uncontrolled (e.g., Maciej Ciemborowicz's use case with VS Code and Codex), but Junio has not yet responded to this framing or the v3 series. The patch does not address Kristoffer Haugsbakk's `--id=<string>` counterproposal, which remains positioned as potentially complementary but not integrated.
