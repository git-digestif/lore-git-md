# Thread deltas

## 2026/10/04

- [2026/10/04/23-47-37 by Coy Geek <coygeek@gmail.com>] Coy Geek reported that on Git 2.56.0, `git repack -a --filter=blob:limit=1m --drop-filtered --dry-run` writes four new files (`.pack`, `.idx`, `.promisor`, `.rev`) to the pack directory and, when explicit `-d` is added, also deletes 12 existing pack and sidecar files, contradicting the manual's promise that `--dry-run` lists candidates without rebuilding packs or deleting anything; both variants exit 0, print the candidate blob ID, and leave the tested blob available.

## 2026/10/08

- [2026/10/08/02-25-34 by Siddharth Shrimali <r.siddharth.shrimali@gmail.com>] Siddharth Shrimali identified the cause of the bug: the `--dry-run` block in `cmd_repack()` prints candidates but does not stop, falling through to `repack_promisor_objects()` (which writes the new promisor pack) and, with explicit `-d`, to `existing_packs_remove_redundant()` (which deletes old packs), because the earlier `if (!dry_run) delete_redundant = 1` only stops `-d` from being implied, not from being given explicitly.
- [2026/10/08/02-25-34 by Siddharth Shrimali <r.siddharth.shrimali@gmail.com>] He proposed a two-line fix in `builtin/repack.c`: adding `ret = 0; goto cleanup;` at the end of the `if (dry_run)` block, right after the loop that prints candidate object IDs, so a dry run returns before any pack is rebuilt or deleted.
- [2026/10/08/02-25-34 by Siddharth Shrimali <r.siddharth.shrimali@gmail.com>] He stated he will add a test to `t/t7706-repack-drop-filtered.sh` that runs the dry run both without and with `-d` and checks that the pack directory is unchanged, the candidate is still printed, and the blob is still present, and that he will send the patch shortly.
