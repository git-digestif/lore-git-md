This is the second patch in Domen Kožar’s v3 series introducing a unified `post-worktree` hook for worktree lifecycle events. It specifically adds hook notifications when worktrees are pruned by `git worktree prune`, covering cases where worktrees disappear outside Git’s control (e.g., manual directory deletion).

The patch addresses a key gap in the observability story: tools maintaining per-worktree state (like IDEs or AI agents) need to know when a worktree is deregistered, even if it was removed by an uncontrolled caller. The hook runs once per pruned entry, passing the worktree ID and its former absolute path (or an empty string if the path cannot be determined). The implementation handles edge cases like duplicate entries, relative paths, and damaged administrative files, and ensures that hook failures do not suppress notifications for other worktrees. Tests cover all these scenarios, including dry runs (which skip the hook) and absolute path resolution for relative worktrees.

This is a well-crafted, thoroughly tested feature patch that directly responds to real-world tooling needs documented in the thread. The changes since v2 are minimal but important: the hook now receives the `.git` path from `should_prune_worktree()` even when the worktree is damaged, ensuring the former path is available to the hook. The test coverage is comprehensive, and the commit message clearly explains the design choices. If the unified hook approach is accepted, this patch will be essential for making the feature usable in practice.
