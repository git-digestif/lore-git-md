This is the v6 cover letter for the four-patch series introducing a "matching-inspired" fetch mode for shallow repositories, aimed at avoiding slow or hanging `git fetch` operations when the remote has many branches. The series is now technically complete and ready for queuing, with only a trivial documentation fix since v5.

The core idea remains unchanged: when a shallow repository is cloned with `--depth`, a plain `git fetch` (no refspec given) should not negotiate history for every remote branch. Instead, it should dynamically fetch only the branches tracked by local branches at the remote being fetched. The implementation achieves this by introducing `remote.<name>.refmap` configuration (Patch 1/4), using it to infer which branches to fetch (Patch 2/4), adding a `--limited-fetch` flag to `git remote add` (Patch 3/4), and making that flag the default in shallow repositories (Patch 4/4).

The v6 update is purely editorial: Patch 3/4’s commit message no longer references the "remote’s default branch" (a behavior removed in v4), resolving the last documentation inconsistency noted by Junio C Hamano. The code and tests are identical to v5, which itself was identical to v4 except for the mechanical renumbering of `t/t5585-fetch-refmap.sh` to `t/t5586-fetch-refmap.sh` to avoid a conflict. Junio has already stated he will queue the series ("Will replace"), but it remains under active review and is not yet in `seen`.

Key technical details for follow-up discussion: the series introduces `remote.<name>.refmap` (a namespace mapping without fetch selection logic), dynamic branch enumeration via `branches_tracking_remote()` in `remote.c`, and a new `--limited-fetch` flag for `git remote add`. The shallow-repository default is opt-out via `--no-limited-fetch`. Files touched include `remote.c`, `builtin/fetch.c`, `builtin/remote.c`, and documentation in `config/remote.adoc`, `fetch-options.adoc`, and `git-remote.adoc`. Tests cover configuration parsing, dynamic branch selection, edge cases (empty repositories, duplicate branches), and shallow-repository defaults.

Open questions from earlier iterations remain unresolved but are not blocking: whether the matching-inspired mode should be available outside shallow repositories, how to handle remotes with no default branch, and whether existing shallow repositories should be migrated automatically. The series preserves backward compatibility for non-shallow repositories. The only acknowledged edge case is that a bare `git fetch` against a refmap-only remote fetches no branches, leaving no remote-tracking refs for `git branch --set-upstream-to` to use—Harald Nordgren considers this a minor quibble.
