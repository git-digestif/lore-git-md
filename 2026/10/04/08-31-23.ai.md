This is the third patch in the v6 series introducing a "matching-inspired" fetch mode for shallow repositories. It adds a `--limited-fetch` flag to `git remote add`, allowing users to explicitly opt into the new behavior where `git fetch` dynamically fetches only the branches tracked by local branches at the remote, rather than all remote branches.

The patch modifies `builtin/remote.c` to introduce the `--limited-fetch` option, which sets up `remote.<name>.refmap` (a namespace mapping without fetch selection logic) instead of the traditional `remote.<name>.fetch` wildcard refspec. This enables the dynamic branch enumeration logic implemented in Patch 2/4. The flag is rejected if used with `-t/--track` or `--mirror`, as those options already specify explicit fetch behavior. The implementation is straightforward: when `--limited-fetch` is provided and no branches are tracked, the code writes `remote.<name>.refmap` with a wildcard mapping (e.g., `+refs/heads/*:refs/remotes/<name>/*`) instead of `remote.<name>.fetch`.

Documentation in `git-remote.adoc` is updated to describe the new flag, explaining that it configures the remote to fetch only the branches local branches are built on, and cross-referencing the `--refmap` entry in `git-fetch(1)`. The tests in `t/t5505-remote.sh` verify that `--limited-fetch` works in non-shallow repositories (setting `remote.<name>.refmap` and not `remote.<name>.fetch`) and that it conflicts with `-t` as expected.

The patch is well-motivated and technically sound. It addresses the series' core goal of reducing unnecessary history negotiation in shallow repositories while preserving backward compatibility for non-shallow repositories. The implementation is clean, the documentation is clear, and the tests cover the key behaviors. No substantive objections remain, and Junio C Hamano has already indicated he will queue the series. The only change since v5 is a trivial editorial fix to the commit message, removing an outdated reference to fetching the remote's default branch. This patch is ready for integration.
