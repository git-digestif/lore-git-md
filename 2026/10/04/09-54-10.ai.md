This is a **substantive review** of Harald Nordgren’s patch to extend `` `git branch --delete-merged` `` to detect squash-merged and rebase-merged branches. Phillip Wood engages deeply with the implementation’s efficiency and correctness, building on D. Ben Knoble’s earlier technical observations.

Phillip’s review centers on performance: he notes that the current patch recalculates upstream diffs for each branch, which is less efficient than the approach used by `` `git cherry` ``. That command precomputes patch-ids from the smaller side of the merge base, batches blob fetches in partial clones, and skips commits that cannot match due to disjoint changed paths. He suggests that adopting a similar strategy could significantly improve scalability, especially in large repositories or blobless clones. For squash merges, he proposes a lightweight optimization: if an upstream commit’s second parent tree exactly matches the branch tip, and the merge base and commit count conditions hold, the branch can be considered squash-merged without running the full patch-id check. This would be particularly useful in repositories that exclusively use squash merges and do not rebase them.

Phillip also acknowledges the inherent limitations of detecting rebased branches: if a branch is rebased before being merged, minor differences (such as an upstream commit with an identical change) can prevent detection. He does not object to the patch’s uniform treatment of squash and rebase cases but emphasizes that the algorithm must be efficient enough to be practical. While he finds the feature useful, he cautions that a careful implementation is needed to avoid performance pitfalls and notes that he is unlikely to have time for a detailed review.

The review advances the discussion by identifying concrete optimizations and trade-offs, shifting the focus from conceptual design to implementation quality. It does not resolve the CLI option debate (config flag vs. CLI option vs. unified behavior) but provides a clear path for improving the patch’s efficiency before that question is settled.
