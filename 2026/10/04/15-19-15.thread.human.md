This thread is about a bugfix patch from Ilia (via GitGitGadget) that addresses a subtle issue in Git's fsmonitor and untracked cache interaction. When the fsmonitor daemon sends a trivial response (typically after a restart or event loss), Git marks all index entries as dirty but fails to invalidate stale untracked cache entries. This causes two problems: untracked files may persist in `git status` output even after their directories are removed, and Git may emit spurious warnings about missing directories.

The patch introduces a new function, `untracked_cache_invalidate_stale_dirs()`, which recursively checks each cached directory against its on-disk stat data when the fsmonitor extension is written and the untracked cache is no longer trusted. Derrick Stolee reviewed the patch, confirmed its performance advantage over a broader "clear everything" approach, and endorsed the design. Junio C Hamano, the maintainer, has now resolved the last open implementation questions—agreeing that the recursive traversal is safe and that error handling should invalidate the entire cache rather than fail. With these details settled, the patch is ready for integration. The fix is narrowly scoped, well-tested, and introduces minimal overhead, making it a clean solution to the edge case.
