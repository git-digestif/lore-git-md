This thread is about a small but important bugfix for Git's fsmonitor feature. When the fsmonitor daemon restarts or loses events, it sends a trivial response (`"/"`), which tells Git to mark all index entries as dirty—but until now, it didn't invalidate stale untracked cache entries. This could cause `git status` to show phantom untracked files or emit spurious warnings about missing directories.

The patch, now in its final form (v2), fixes this by adding a new function, `untracked_cache_invalidate_stale_dirs()`, which runs after `refresh_fsmonitor()` and before the index is written. It ensures stale untracked cache entries are cleared when the daemon sends a trivial response, with minimal overhead (just one `lstat()` per cached directory). Derrick Stolee measured the performance impact and confirmed the design is sound, while Junio C Hamano reviewed the implementation details, including how to handle edge cases like `repo_get_work_tree()` failures. All review feedback has been addressed, including test cleanup and Trace2 instrumentation for debugging.

The patch is ready for integration, with no open questions or loose ends. The only recent discussion was a minor reminder from Stolee about rebasing etiquette—contributors should avoid unnecessary rebases onto the latest `master` unless resolving conflicts with recently merged changes, since Junio’s workflow handles most integration conflicts automatically. Otherwise, the patch remains unchanged and is awaiting merge.
