This thread reports a bug in `git repack --dry-run --drop-filtered`: despite the `--dry-run` promise to only list candidate objects without making changes, the command incorrectly writes new promisor packs and deletes old packs when `-d` is used. Coy Geek originally reported the issue with a reproduction script, confirming the bug in Git 2.56.0 but unsure about `master`.

D. Ben Knoble has now confirmed the bug exists on `master` (commit `6a2b3c4d`) and pinpointed the root cause in `builtin/repack.c`. The `dry_run` flag guards the `delete_redundant` logic but fails to prevent the subsequent `finish_repack` call, which writes promisor packs and deletes old ones unconditionally. Knoble proposes a minimal fix—returning early after printing candidates when `dry_run` is set—and verified it restores the expected behavior. He also suggests the fix should apply to the analogous `--geometric` code path, though this remains untested. The thread is now focused on implementing the fix, with no objections or alternative proposals raised so far.
