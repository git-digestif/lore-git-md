This thread is about a bug in `git repack --dry-run --drop-filtered` where the `--dry-run` option fails to prevent repository mutations—specifically, it writes new promisor packs and deletes old packs despite the manual’s promise that it will only list candidate objects without making changes. The issue was reported by Coy Geek and confirmed by D. Ben Knoble, who identified the root cause in `builtin/repack.c`: the `dry_run` flag guards only part of the logic, allowing unconditional execution of pack-writing and deletion steps later in the code path.

Siddharth Shrimali, the original author of the `--drop-filtered` feature, has now weighed in with a fix. The solution is minimal: after printing candidate objects in the `dry_run` block, the code will return early to avoid side effects. Shrimali also plans to add a test to verify that the pack directory remains unchanged while still printing the expected output. The fix targets the `finish_repack` function and is uncontroversial, aligning with the behavior of `--dry-run` in other Git commands. With confirmation from the feature’s author and a clear reproduction case, this bugfix is likely to be merged quickly. The only remaining question is whether the analogous `--geometric` code path should be addressed in the same patch or as a follow-up.
