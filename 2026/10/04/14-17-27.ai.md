This is a follow-up in the `git history` signing series, now at v5. Junio C Hamano asks a clarification question about the completion test in Souma’s follow-up patch. The test adds `--gpg-sign` and `--no-...` to the expected completion output for `git history split`, but Junio is unsure whether the three periods (`...`) are literal or a placeholder.

The question is purely mechanical: the test script uses `--no-...` as a stand-in for the dynamically generated negated option (`--no-gpg-sign`), which the completion helper emits after the `--` separator. This matches the established pattern for `git rebase` and `git commit`, where the helper lists all options before `--` and generated negated options after it. The clarification is unlikely to block the series, but it may prompt a small adjustment to the test wording for clarity. The series itself remains unblocked and ready to graduate to `next` once this minor detail is resolved.
