This is the v4 iteration of Kristoffer Haugsbakk’s feature series adding `--[no-]range-diff-notes` options to `git format-patch`. The series remains a two-patch set: the first refactors `get_notes_arg` to simplify its parameters, and the second implements the new functionality.

The v4 changes are editorial and mechanical. The commit messages have been trimmed to remove expository detail, and the documentation for `--range-diff-notes` has been rewritten in a more concise, direct style. The option callback (`rdiff_notes_cb`) has been refactored to wrap `parse_opt_string_list` rather than duplicating its logic, addressing Junio C Hamano’s feedback from v3. No substantive technical concerns remain; the series is now technically complete and awaits maintainer approval.

Key technical details carried over from v3:
- Files touched: `builtin/log.c`, `Documentation/git-format-patch.adoc`, and tests in `t/t3206-range-diff.sh`.
- CLI options: `--range-diff-notes=<ref>` (requires an explicit ref argument) and `--no-range-diff-notes` (suppresses notes in the range-diff without fallback).
- New struct: `struct rdiff_notes` tracks whether the user wants to override the default notes behavior for range-diffs.
- Behavior: If no range-diff notes options are given, the range-diff uses the same notes as the patches; otherwise, it uses only the explicitly specified notes (including none). `--no-notes` no longer suppresses range-diff notes unless explicitly requested via `--no-range-diff-notes`.
- Test coverage: Comprehensive tests verify suppression of range-diff notes, use of different notes refs for patches and range-diffs, and the requirement that `--range-diff-notes` takes a value. Two additional tests address the single-patch case as regression tests for a prior bug fix.
- Prior commit dependencies: 85bd88a7 (2025-09-25) introduced `rdiff_log_arg` to `struct rev_info`; 155986b4 (2025-09-25) fixed a bug in the single-patch case.
