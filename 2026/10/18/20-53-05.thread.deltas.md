# Thread deltas

## 2026/10/18

- [2026/10/18/20-53-05 by Andy Koppe <andy.koppe@gmail.com>] Andy Koppe submitted a patch to the Makefile that passes `--target-dir target` directly in the cargo build recipes for gitcore (both the default and per-target variants), rather than via `CARGO_ARGS`, so the build does not break with a link error when a user has a custom target directory configured via `~/.cargo/config.toml` or `CARGO_TARGET_DIR`; the `contrib/libgit-{sys,rs}` targets are left unchanged, and the Meson build already passes `--target-dir` explicitly.

## 2026/10/19

- [2026/10/19/06-45-54 by Patrick Steinhardt <ps@pks.im>] Patrick Steinhardt reviewed Andy Koppe's Makefile patch pinning cargo `--target-dir` to `./target` and said it "looks good to me", noting only a nit that he would have preferred the `--target-dir=target` form but that it does not warrant a reroll; he also mused that merging this into the main Rust library might be a topic for another day.
- [2026/10/19/16-07-30 by Junio C Hamano <gitster@pobox.com>] Junio C Hamano said the change might make sense but noted these Makefile areas are touched by other topics in flight, and wondered whether a single early `CARGO_ARGS += --target-dir target` unrelated to the individual rules would be preferable.
- [2026/10/19/19-43-24 by Andy Koppe <andy.koppe@gmail.com>] Andy Koppe argued against that approach because CARGO_ARGS appears intended for overridable build preferences like CFLAGS/LDFLAGS whereas the target dir is a hard requirement of the subsequent link step, noted that `override CARGO_ARGS += --target-dir target` would avoid that but set a trap for later non-override modifications, identified the conflicting topic as mh/rust-crate-subdir by Mike Hommey (moving things into a 'rust' subdirectory, apparently somewhat stalled), and offered to reapply the `--target-dir` tweak on top of that topic if it goes ahead or for Mike Hommey to add it there.

## 2026/10/20
