Subject: [PATCH] prune-packed: remove implicit dependency on the_repository
Series version: standalone patch (part of the_repository removal effort)
Originating author: Shashank S (via GitGitGadget)
Thread type: patch (refactoring)

Core problem or goal
Eliminate the implicit use of the global `the_repository` variable in `prune_packed_objects()` by converting it to accept an explicit `struct repository *` parameter. This is a step in the ongoing project-wide effort to remove all uses of `the_repository` for better modularity and libification.

Current status
Under review; no prior versions of this patch have been posted. The patch is mechanically sound and uncontroversial in its API adjustment, but Patrick Steinhardt has raised a substantive question about whether the updated code safely handles cases where the `repo` parameter might be `NULL`—specifically, whether the commands calling `prune_packed_objects()` (`git prune-packed`, `git prune`, and `git repack`) can ever be invoked outside a repository.

Key technical details
- Files touched: `builtin/prune-packed.c`, `builtin/prune.c`, `builtin/repack.c`, `prune-packed.c`, `prune-packed.h`
- New struct: `prune_data` (wraps `struct repository *` and `opts` integer for callback compatibility)
- Symbols: `prune_packed_objects()` now takes `struct repository *`; `USE_THE_REPOSITORY_VARIABLE` macro removed
- Subsystem: object storage (prune-packed)
- No on-disk format changes, no new CLI options, no test coverage changes

Open questions and loose ends
Patrick Steinhardt has asked whether the updated code safely handles `NULL` `repo` parameters, i.e., whether the calling commands can ever be invoked outside a repository. This question remains unresolved.
