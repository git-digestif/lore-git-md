Subject: [PATCH v4] prune-packed: remove implicit dependency on the_repository
Series version: standalone patch (v4), part of the_repository removal effort
Originating author: Shashank Srikumar (via GitGitGadget)
Thread type: patch (refactoring)

Core problem or goal
Eliminate the implicit use of the global `the_repository` variable in `prune_packed_objects()` by converting it to accept an explicit `struct repository *` parameter. This is a step in the ongoing project-wide effort to remove all uses of `the_repository` for better modularity and libification.

Current status
Under review; v4 posted. This version addresses all prior feedback, including the two minor stylistic nits raised by Patrick Steinhardt: (1) the commit message now clearly explains why dereferencing `repo` is safe when it could be `NULL` (invoking with `-h`), and (2) the three lines in `prune-packed.c` that previously used spaces instead of tabs for indentation have been corrected. The patch is functionally complete, uncontroversial, and appears ready for merging.

Key technical details
- Files touched: `builtin/prune-packed.c`, `builtin/prune.c`, `builtin/repack.c`, `prune-packed.c`, `prune-packed.h`
- New struct: `prune_data` (wraps `struct repository *` and `opts` integer for callback compatibility)
- Symbols: `prune_packed_objects()` now takes `struct repository *`; `USE_THE_REPOSITORY_VARIABLE` macro removed
- Subsystem: object storage (prune-packed)
- No on-disk format changes, no new CLI options, no test coverage changes
- Edge case: `repo` could theoretically be `NULL` if the command is invoked with `-h` outside a repository, but the patch is safe because `repo` is only dereferenced after `parse_options()` (which ensures `RUN_SETUP` has succeeded)

Open questions and loose ends
None. All prior feedback has been addressed.
