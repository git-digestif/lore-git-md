Subject: [PATCH v3] prune-packed: remove implicit dependency on the_repository
Series version: standalone patch (v3), part of the_repository removal effort
Originating author: Shashank Srikumar (via GitGitGadget)
Thread type: patch (refactoring)

Core problem or goal
Eliminate the implicit use of the global `the_repository` variable in `prune_packed_objects()` by converting it to accept an explicit `struct repository *` parameter. This is a step in the ongoing project-wide effort to remove all uses of `the_repository` for better modularity and libification.

Current status
Under review; v3 posted. This version addresses all prior feedback: removed the `[Outreachy Patch]` prefix from the subject line, omitted the explicit listing of the three builtin files (`builtin/prune-packed.c`, `builtin/prune.c`, `builtin/repack.c`) from the commit message, and clarified that the `repo` pointer *can* be `NULL` when the command is invoked with `-h` (though the patch remains safe because `repo` is only dereferenced after `parse_options()`). No functional changes from v2; the patch is now considered complete by the author and reviewers.

Key technical details
- Files touched: `builtin/prune-packed.c`, `builtin/prune.c`, `builtin/repack.c`, `prune-packed.c`, `prune-packed.h`
- New struct: `prune_data` (wraps `struct repository *` and `opts` integer for callback compatibility)
- Symbols: `prune_packed_objects()` now takes `struct repository *`; `USE_THE_REPOSITORY_VARIABLE` macro removed
- Subsystem: object storage (prune-packed)
- No on-disk format changes, no new CLI options, no test coverage changes
- Edge case: `repo` could theoretically be `NULL` if the command is invoked with `-h` outside a repository, but the patch is safe because `repo` is only dereferenced after `parse_options()`

Open questions and loose ends
None. All substantive and stylistic feedback has been addressed. The patch is ready for maintainer consideration.
