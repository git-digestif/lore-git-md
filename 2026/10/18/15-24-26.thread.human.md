This thread is about a bugfix patch from Olof Fairbrook that addresses a long-standing (since 2013) issue in Git's config subsystem. The bug occurs when reading in-memory config blobs (like `.gitmodules` from commits) on platforms where `char` is signed (e.g., x86): bytes with the high bit set (0x80–0xff) are misinterpreted, causing either premature EOF (for 0xff) or spurious "bad config line" errors (for UTF-8 BOMs). The fix is minimal—casting the byte to `unsigned char` in `config_buf_fgetc()` and updating the ungetc check—and includes three new tests to verify the behavior.

The patch targets a real, if niche, bug that affects any code path reading config from memory, not just `git config --blob`. It’s platform-dependent but the fix is portable, with no backward compatibility concerns. The commit message is clear and includes a minimal reproduction case. So far, there’s no review feedback, but the patch appears well-crafted and focused. If you’ve encountered mysterious config parsing failures on x86, this might be the culprit.
