This thread is about a long-standing bug in Git's config subsystem, present since 2013, where in-memory config readers (like `git config --blob`) misinterpret bytes with the high bit set (0x80–0xff) on platforms where `char` is signed (e.g., x86). The bug causes two issues: a 0xff byte is incorrectly treated as EOF, truncating the config blob, and UTF-8 byte order marks trigger spurious "bad config line" errors. Olof Fairbrook identified the problem, provided a minimal reproduction case, and submitted a well-crafted fix with tests.

The patch is minimal, touching only `config.c` to ensure consistent behavior between in-memory and file-based config reading. It adds three new tests in `t/t1307-config-blob.sh` to verify the fix handles 0xff bytes and UTF-8 BOMs correctly. The change affects any code path that reads config from memory, such as `.gitmodules` from commits, but does not alter the on-disk format. Junio C Hamano has reviewed and approved the patch, indicating he will queue it for integration. No objections or requests for changes have been raised, and the thread is now effectively resolved.
