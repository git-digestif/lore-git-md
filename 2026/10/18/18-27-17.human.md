This is the third and final patch in Harald Nordgren’s v2 series introducing `--historical-branch` to `git reflog` and `git log -g`. It implements the feature that shows which branch HEAD was on when each reflog entry was recorded, addressing a long-standing usability pain point where users must manually trace back through "checkout: moving from" entries to determine branch context.

The patch adds a `historical_branch` flag to `struct rev_info` and extends `reflog_walk_mark()` to accept this flag. A new `mark_branches()` function scans the reflog to determine the branch context for each entry, handling edge cases like detached HEAD, branch renames, and non-HEAD refs. The output format places the branch name in parentheses immediately after the `HEAD@{n}` selector (e.g., `HEAD@{0}: (topic) commit: add tests`), preserving column alignment and coloring the branch name like a standard decoration. The implementation is additive and requires `--walk-reflogs` to be set, avoiding changes to default behavior.

Test coverage is thorough, with 95 new lines in `t/t1414-reflog-walk.sh` validating edge cases like detached HEAD, branch renames, and non-HEAD reflogs. The patch also ensures `--historical-branch` replaces standard commit decorations when both are specified, preventing visual clutter. The implementation appears clean and well-motivated, with clear attention to backward compatibility and usability trade-offs.

This patch completes the series, which now includes preparatory refactoring (patch 1/3), `--operations` (patch 2/3), and `--historical-branch` (this patch).
