This patch is a bugfix and refactoring targeting the remote configuration subsystem. It defers validation of `remote.<name>.followRemoteHEAD` until it is actually needed (during `git fetch`), mirroring an earlier change (86129fd) that did the same for `fetch.followRemoteHEAD`. The patch eliminates spurious warnings emitted by commands like `git push` or `git remote -v` that load remote configuration but never use this setting. It also unifies the parsing logic for both settings, allowing `fetch.followRemoteHEAD` to accept the "warn-if-not-<branch>" syntax previously exclusive to the remote-level setting, and updates documentation and tests accordingly.

The change touches `remote.c`, `builtin/fetch.c`, `builtin/remote.c`, and the `fetch` and `remote` documentation files. It replaces the parsed `follow_remote_head` and `no_warn_branch` members in `struct remote` with a raw string (`follow_remote_head_raw`) and a seen flag, deferring parsing to the `get_follow_remote_head()` helper in `fetch.c`. The `set_head()` function is updated to accept the parsed `no_warn_branch` value as a parameter. Tests in `t5510-fetch.sh` verify the new behavior for both the remote and fetch-level settings.

The patch is well-motivated: the commit message clearly explains the problem (unnecessary warnings) and the solution (lazy validation). The implementation is clean, removing a NEEDSWORK comment and consolidating duplicate logic. The test coverage is thorough, adding cases for the newly supported syntax. This looks like a straightforward improvement that aligns the two settings' behavior and eliminates a minor but persistent annoyance.
