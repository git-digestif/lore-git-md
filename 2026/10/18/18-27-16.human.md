This is the second patch in Harald Nordgren’s v2 series introducing `--operations` and `--historical-branch` options to `git reflog` and `git log -g`. This patch implements the `--operations` option, which collapses multi-step operations like rebase, checkout, and stash into single entries representing the actual commands executed, making it easier to trace branch history without wading through intermediate steps.

The patch is well-structured and clearly motivated. It adds a `user_operation` flag to reflog entries and introduces a `mark_operations()` function that scans the reflog to identify which entries should be shown (e.g., rebase finish/abort) or hidden (e.g., intermediate rebase steps or branch switches). The implementation is careful to preserve the original `HEAD@{n}` numbering, so users can still use `git reset --hard HEAD@{n}` to undo operations. The test coverage is thorough, including edge cases like stopped/aborted rebases, `git stash`, and `git pull --rebase`.

The patch touches seven files, including `reflog-walk.c`, `revision.c`, and `revision.h`, and adds 105 lines of new test coverage in `t/t1414-reflog-walk.sh`. The documentation updates are minimal but clear, explaining the new option’s behavior in both `git-reflog.adoc` and `rev-list-options.adoc`. The commit message does a good job of explaining the problem (reflog clutter from multi-step operations) and the solution (collapsing them into single entries).

This patch addresses the core usability pain point described in the series: reducing reflog noise from operations like rebase, which currently generate one entry per commit replayed. The implementation looks solid, with no obvious regressions or missing edge cases. The only open question remains the broader architectural one raised in the thread—whether Git’s core should replicate functionality already available in tools like `tig`—but that doesn’t detract from the quality of this specific patch. For now, this is a well-crafted feature that directly improves the reflog experience.
