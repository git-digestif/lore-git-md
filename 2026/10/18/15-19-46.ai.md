This is a **design discussion reply** in the ongoing `branch.autoSetupMerge=inherit` thread, focusing on user workflows and potential alternative approaches to tracking setup.

Harald Nordgren responds to Phillip Wood’s user-centric feedback by exploring a new direction: prioritizing inheritance from the *current* branch’s tracking configuration (rather than the starting point’s) when creating a new branch. He suggests that if the current branch already tracks a remote (e.g., `origin/master`), the new branch should inherit *that* tracking relationship by default—aligning with Phillip’s described workflow where users often want new branches to track the same upstream as their parent branch. This would address the scenario where a user creates a branch from a pushed-but-not-tracked branch (e.g., `origin/another_branch`) but prefers to track `origin/master` instead.

As a fallback, Harald proposes retaining his original patch’s behavior (tracking the starting point directly) *only* if the current branch has no tracking configuration. This hybrid approach attempts to reconcile the two workflows Phillip described: it would automatically track `origin/master` in the first case (where the current branch already tracks it) but still track `origin/another_branch` in the second case (where the current branch has no tracking). Harald expresses uncertainty about whether this fallback is desirable, leaving it as an open question.

The reply does not include code or test updates, nor does it address Junio C Hamano’s earlier concerns about non-tracking starting points (tags, commit hashes). Instead, it shifts the discussion toward a more radical reframing of `inherit`’s logic—one that could supersede both the original patch and Junio’s proposed modes (`inherit-or-fail`, `inherit-or-direct`). This suggestion is still conceptual and lacks implementation details, but it introduces a new axis of debate: whether tracking inheritance should flow from the *current* branch or the *starting point*. The idea may appeal to users who frequently adjust tracking post-creation (e.g., via `git branch --set-upstream-to=origin`), but it risks complicating the mental model for others.
