Subject: [PATCH] remote: defer validation of remote.<name>.followRemoteHEAD
Series version: single patch (no cover letter)
Originating author: Colin Hinton
Thread type: bugfix/refactoring

Core problem or goal
The remote configuration subsystem emits spurious warnings when `remote.<name>.followRemoteHEAD` is loaded by commands (e.g., `git push`, `git remote -v`) that never use the setting. The patch defers validation until the setting is actually needed (during `git fetch`), aligning it with an earlier change (86129fd) for `fetch.followRemoteHEAD`. It also unifies parsing logic, allowing `fetch.followRemoteHEAD` to accept the "warn-if-not-<branch>" syntax previously exclusive to the remote-level setting.

Current status
Under review. Junio C Hamano has identified a critical issue: error messages in `get_follow_remote_head()` no longer distinguish between `fetch.followRemoteHEAD` and `remote.<name>.followRemoteHEAD`, which could confuse users. He requests passing the variable prefix (e.g., `"fetch."` or `"remote.<name>."`) from the caller to clarify error messages. A minor style nit (long line in `builtin/remote.c`) is also noted, but the error message clarity is the substantive blocker.
