Subject: [PATCH] remote: defer validation of remote.<name>.followRemoteHEAD
Series version: single patch (v2 forthcoming)
Originating author: Colin Hinton
Thread type: bugfix/refactoring

Core problem or goal
The remote configuration subsystem emits spurious warnings when `remote.<name>.followRemoteHEAD` is loaded by commands (e.g., `git push`, `git remote -v`) that never use the setting. The patch defers validation until the setting is actually needed (during `git fetch`), aligning it with an earlier change (86129fd) for `fetch.followRemoteHEAD`. The goal is now narrower: only the lazy validation of `remote.<name>.followRemoteHEAD` is retained; syntax unification between the two settings has been dropped in response to review feedback.

Current status
Under review; v2 expected. The substantive blockers from v1 have been addressed: (1) error messages in `get_follow_remote_head()` will now distinguish between `fetch.followRemoteHEAD` and `remote.<name>.followRemoteHEAD` by passing the variable prefix from the caller, and (2) the controversial unification of syntax (allowing `fetch.followRemoteHEAD` to accept the "warn-if-not-<branch>" value) has been abandoned. A minor style nit (long line in `builtin/remote.c`) and a refactoring suggestion (moving the `enum follow_remote_head_settings` definition to `fetch.c`) will also be incorporated.

Key technical details
- Files touched: `remote.c`, `builtin/fetch.c`, `builtin/remote.c`, `Documentation/fetch-options.txt`, `Documentation/git-remote.txt`
- Subsystem: remote configuration
- New/renamed symbols: `follow_remote_head_raw` (replaces `follow_remote_head` and `no_warn_branch` in `struct remote`), `get_follow_remote_head()` helper (in `fetch.c`)
- Behavior change: lazy validation of `remote.<name>.followRemoteHEAD`; syntax support remains split (`fetch.followRemoteHEAD` does not accept "warn-if-not-<branch>")
- On-disk format: unchanged
- Test coverage: `t5510-fetch.sh` (updated to reflect the narrower scope)

Open questions and loose ends
1. **Documentation synopsis style**: The v1 patch updated the synopsis in `Documentation/fetch-options.txt` and `Documentation/git-remote.txt` to use `<branch>` instead of `$branch`. Colin notes this change may be reverted if the `warn-if-not-<branch>` syntax is dropped, but the current plan is to retain it as a minor improvement.
2. **Style nit**: Long line in `builtin/remote.c` (minor, will be fixed in v2).
3. **Refactoring**: The `enum follow_remote_head_settings` definition will be moved to `fetch.c` since it is no longer used in `remote.c`.
