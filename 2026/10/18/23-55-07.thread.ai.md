Subject: [PATCH] remote: defer validation of remote.<name>.followRemoteHEAD
Series version: v4 (two-patch series, per Junio’s refactoring suggestion)
Originating author: Colin Hinton
Thread type: bugfix/refactoring

Core problem or goal
The remote configuration subsystem emits spurious warnings when `remote.<name>.followRemoteHEAD` is loaded by commands (e.g., `git push`, `git remote -v`) that never use the setting. The patch defers validation until the setting is actually needed (during `git fetch`), aligning it with an earlier change (86129fd) for `fetch.followRemoteHEAD`. The goal is to eliminate unnecessary warnings while maintaining backward compatibility.

Key technical details
- **Files touched**: `remote.c`, `builtin/fetch.c`, `builtin/remote.c`, `Documentation/fetch-options.txt`, `Documentation/git-remote.txt`, `t5510-fetch.sh` (tests).
- **New/renamed symbols**:
  - `struct remote`: Removed `follow_remote_head` and `no_warn_branch`; added `follow_remote_head_raw` (string) and `follow_remote_head_seen` (flag).
  - `get_follow_remote_head()`: Now accepts `const char *var_prefix`, `const struct transport *transport`, and `const struct config_set *config` parameters. The function dynamically constructs the configuration key and handles `no_warn_branch` internally, eliminating the need for a separate helper. This is the **final design**, replacing the standalone `determine_follow_remote_head()` function from v4.
  - `enum follow_remote_head_settings`: Moved from `remote.c` to `fetch.c`.
- **Behavior change**: Validation of `remote.<name>.followRemoteHEAD` is deferred until `git fetch`, eliminating spurious warnings in other commands.
- **On-disk format**: No changes; backward compatibility maintained.
- **Test coverage**: Added in `t5510-fetch.sh` to verify lazy validation and error message clarity.
- **Conflict details**: Mechanical overlap with `hn/fetch-refmap` in `fetch.c` is fully mitigated by the folded-in helper design, which clarifies the main flow and avoids duplication. The dependency on `hn/fetch-refmap` remains the sole blocker to integration.
