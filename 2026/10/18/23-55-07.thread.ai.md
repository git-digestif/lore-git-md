Subject: [PATCH] remote: defer validation of remote.<name>.followRemoteHEAD
Series version: single patch (no cover letter)
Originating author: Colin Hinton
Thread type: bugfix/refactoring

Core problem or goal
The remote configuration subsystem emits spurious warnings when `remote.<name>.followRemoteHEAD` is loaded by commands (e.g., `git push`, `git remote -v`) that never use the setting. The patch defers validation until the setting is actually needed (during `git fetch`), aligning it with an earlier change (86129fd) for `fetch.followRemoteHEAD`. It also unifies parsing logic, allowing `fetch.followRemoteHEAD` to accept the "warn-if-not-<branch>" syntax previously exclusive to the remote-level setting.

Current status
Under review. Junio C Hamano and Matt Hunter have identified two substantive issues: (1) error messages in `get_follow_remote_head()` no longer distinguish between `fetch.followRemoteHEAD` and `remote.<name>.followRemoteHEAD`, which could confuse users, and (2) the justification for unifying the syntax of the two settings is unclear, with Hunter arguing that `fetch.followRemoteHEAD` may not need the "warn-if-not-<branch>" syntax and that this change could complicate future reverts. Junio suggests passing the variable prefix (e.g., `"fetch."` or `"remote.<name>."`) from the caller to clarify error messages. A minor style nit (long line in `builtin/remote.c`) is also noted, but the error message clarity and syntax unification are the substantive blockers.

Open questions and loose ends
1. **Error message clarity**: How to fix the ambiguity in `get_follow_remote_head()` error messages to distinguish between `fetch.followRemoteHEAD` and `remote.<name>.followRemoteHEAD`. Junio suggests passing the variable prefix from the caller.
2. **Syntax unification justification**: Whether `fetch.followRemoteHEAD` should support the "warn-if-not-<branch>" syntax, as this may not be meaningful in the fetch-level context and could complicate future changes. Hunter cites prior discussion (Peff’s and Szeder’s emails from June 2026) raising this concern.
3. **Style nit**: Long line in `builtin/remote.c` (minor).
4. **Refactoring suggestion**: Hunter suggests moving the `enum follow_remote_head_settings` definition to `fetch.c`, since it is now only used there after the refactoring.
