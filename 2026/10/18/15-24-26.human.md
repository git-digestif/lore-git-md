This is a bugfix patch targeting the config subsystem.

Olof Fairbrook fixes a long-standing bug in how Git reads configuration from in-memory blobs (e.g., via `git config --blob`). The issue is that `config_buf_fgetc()` returns bytes as plain `char`, which is signed on x86. This causes bytes with the high bit set (0x80–0xff) to be interpreted as negative numbers, leading to two concrete problems: a byte 0xff is treated as EOF (silently truncating the rest of the blob), and UTF-8 byte order marks trigger "bad config line" errors. The fix is simple: cast the byte to `unsigned char` before returning it, matching the behavior of `getc()` when reading from files.

The patch includes three new tests in `t/t1307-config-blob.sh` that verify the fix handles 0xff bytes, 0xff after a CR, and UTF-8 BOMs correctly. The commit message is clear and cites the original introduction of the bug in 2013 (1bc888193e). This is a well-motivated, narrowly scoped fix with good test coverage.
