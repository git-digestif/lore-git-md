This is a bugfix patch targeting the config subsystem. It addresses a long-standing issue (since 2013) where `git config --blob` and other in-memory config readers misinterpret bytes with the high bit set (0x80–0xff) when `char` is signed (as on x86). The problem manifests in two ways: a 0xff byte is treated as EOF, truncating the config blob, and UTF-8 byte order marks trigger spurious "bad config line" errors. The fix casts the byte to `unsigned char` in `config_buf_fgetc()` and updates the ungetc check to match, aligning behavior with file-based config reading.

The patch includes three new tests in `t/t1307-config-blob.sh` that verify the fix handles 0xff bytes (both standalone and after CR) and UTF-8 BOMs. The commit message is clear and demonstrates the bug with a minimal reproduction case. The change is minimal and focused, touching only the two functions that read bytes from the config buffer.

This affects any code path that reads config from memory (e.g., `.gitmodules` from commits), not just `git config --blob`. The issue is platform-dependent (only surfaces on architectures where `char` is signed) but the fix is portable. No backward compatibility concerns are apparent. The patch appears well-crafted and addresses a real, if niche, bug.
