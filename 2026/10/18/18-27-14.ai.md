This is a v2 feature patch series for `git reflog` and `git log -g`, introducing `--operations` and `--historical-branch` options. The series now has 15 files changed (up from 13 in v1) and includes a 198-line test script (`t/t1414-reflog-walk.sh`) covering both new options.

The key change in v2 is the output format for `--historical-branch`: branch names now appear in parentheses *after* the operation description (e.g., `HEAD@{0}: (topic) commit: add tests`) rather than before it, preserving alignment of the `HEAD@{n}` column. This addresses D. Ben Knoble’s feedback about misaligned output in v1. The commit messages have also been improved, particularly for patch 1/3, which now clearly states the motivation (preventing drift between writing and parsing reflog strings) upfront.

The implementation remains focused on the reflog subsystem, with no on-disk format changes. New `#define` constants in `reflog.h` standardize reflog message prefixes, and the `historical_branch` flag in `struct rev_info` enables the new behavior. The series is additive and requires `--walk-reflogs` to be set, avoiding changes to default behavior.

The v2 patches appear to address the major review feedback from v1, particularly around commit message clarity and output formatting. The test coverage is thorough, including edge cases like detached HEAD, branch renames, and non-HEAD reflogs. The series is now ready for deeper technical review, though the broader architectural question—whether Git’s core should replicate functionality already available in tools like `tig`—remains unresolved.
