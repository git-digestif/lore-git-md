This thread is about a bugfix and refactoring patch from Colin Hinton that defers validation of the `remote.<name>.followRemoteHEAD` configuration setting until it’s actually needed (during `git fetch`), eliminating spurious warnings in commands like `git push` or `git remote -v`. The patch aligns this setting’s behavior with an earlier fix for `fetch.followRemoteHEAD` (commit 86129fd) and unifies their parsing logic, allowing both to accept the `"warn-if-not-<branch>"` syntax.

Junio C Hamano reviewed the patch and identified a critical issue: the error messages in the new `get_follow_remote_head()` helper no longer distinguish between the `fetch.followRemoteHEAD` and `remote.<name>.followRemoteHEAD` settings, which could confuse users. He suggested passing the variable prefix (e.g., `"fetch."` or `"remote.<name>."`) from the caller to clarify the error messages. The patch also has a minor style nit (an overly long line), but the error message clarity is the main blocker for merging. The rest of the patch—including the refactoring of `struct remote` to use a raw string (`follow_remote_head_raw`) and defer parsing, and the updated documentation and tests—is uncontroversial and well-motivated.

The patch touches `remote.c`, `builtin/fetch.c`, `builtin/remote.c`, and the relevant documentation files, with new test coverage in `t5510-fetch.sh`. There are no open questions beyond addressing Junio’s feedback, and the patch has no external dependencies or on-disk format changes.
