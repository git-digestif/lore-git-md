This is the second patch in Harald Nordgren’s v2 series introducing `--operations` to `git reflog` and `git log -g`. It implements the core functionality of collapsing multi-step operations (like rebase, stash, or pull --rebase) into single entries, addressing a long-standing usability pain point where users must manually skip past intermediate reflog entries to find the actual command that changed the branch.

The patch adds a `user_operation` flag to reflog entries and introduces a `mark_operations()` function that scans the reflog to identify which entries should be shown (e.g., rebase finish/abort) or hidden (e.g., intermediate rebase steps or branch switches). The logic is careful to handle edge cases: stopped rebases (showing the rebase start until it finishes or aborts), `git stash` (hiding the "reset: moving to HEAD" entry), and `git pull --rebase` (collapsing the entire operation into one entry). The implementation is additive and requires `--walk-reflogs` to be set, avoiding changes to default behavior.

Files touched include `reflog-walk.c` (core logic), `revision.c`/`revision.h` (CLI option plumbing), documentation updates, and a new 105-line test block in `t/t1414-reflog-walk.sh` covering rebase (normal, stopped, aborted), `git stash`, and `git pull --rebase`. The test coverage is thorough, validating both the presence of expected entries and the absence of intermediate steps.

The patch appears well-crafted: the commit message clearly explains the motivation and behavior, the code is cleanly structured, and the test cases cover realistic workflows. The only unresolved question is the broader architectural one raised in the thread—whether Git’s core should replicate functionality already available in tools like `tig`—but this patch itself is narrowly focused on the reflog subsystem and does not attempt to address that debate. For now, the implementation looks ready for deeper technical review.
