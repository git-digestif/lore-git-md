This is a documentation patch proposal targeting the `git remote add` help text.

The author, a self-described Git user, suggests clarifying the role of the `<name>` argument in `git remote add --help`. Currently, the usage line (`git remote add [<options>] <name> <url>`) does not explain what `<name>` represents or why "origin" is commonly used. The proposal adds a two-line explanation noting that "origin" is the default name assigned by `git clone` but that any valid name can be used. The change is purely additive and does not alter command behavior.

The motivation is to reduce confusion for new users who may not understand whether "origin" is a Git-enforced default, a required convention, or simply a user choice. The patch touches only the help text for `git remote add`, leaving other documentation and code paths unchanged. No tests or code modifications are involved.

The contribution is small, well-motivated, and uncontroversial. It addresses a real usability gap without introducing new concepts or changing existing functionality. The proposed wording is clear and concise. This is likely to be accepted as-is or with minor wording tweaks.
