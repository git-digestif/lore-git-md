This patch is part of the ongoing `the_repository` removal effort. It converts the `prune_packed_objects()` function in `prune-packed.c` to accept an explicit `struct repository *` parameter instead of relying on the global `the_repository` variable. The change is mechanical but requires introducing a new `struct prune_data` to pass both the repository pointer and the `opts` integer through the callback interface of `for_each_loose_file_in_source()`, which only accepts a single `void *data` pointer.

The patch updates three built-in commands (`git prune-packed`, `git prune`, and `git repack`) to pass their local `repo` variables to the now-parameterized function, removing the `UNUSED` macro from their signatures. The `USE_THE_REPOSITORY_VARIABLE` macro is also dropped from `prune-packed.c` as it is no longer needed. The diff touches five files: `builtin/prune-packed.c`, `builtin/prune.c`, `builtin/repack.c`, `prune-packed.c`, and `prune-packed.h`.

This is a clean, well-scoped refactoring that aligns with the project's long-term goal of eliminating implicit global state. The commit message clearly explains the motivation (libification) and the technical workaround (the new `prune_data` struct). The changes are minimal and focused, with no behavior changes—just plumbing adjustments to make the code more modular.
