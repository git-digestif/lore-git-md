This is a bugfix patch from Olof Fairbrook that plugs a memory-safety hole in `git bundle create`.

The bug surfaces when the command is given an unrecognized argument (e.g., `git bundle create private.bundle main --no-such-option`). Since a 2024 cleanup commit, the error path jumps to cleanup code that tries to free `revs_copy.pending`, but `revs_copy` itself is only initialized later in the function. The result is a read of uninitialized stack memory, which valgrind flags and which can crash depending on what happens to be on the stack.

The fix is a one-line change: initialize `revs_copy` to zero at declaration. A new test in `t/t5607-clone-bundle.sh` verifies that an unknown argument after the revision list is properly rejected and does not leave behind a bundle file. The test is designed to fail under valgrind if the bug is present.

The patch is small, self-contained, and clearly motivated. It touches only the bundle code and its test suite, so it should not affect other parts of Git. The regression is recent (introduced in June 2024) and the fix is minimal, so it looks like a safe candidate for `maint`.
