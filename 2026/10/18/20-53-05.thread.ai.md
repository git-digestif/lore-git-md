Thread identity: Rust integration in Git – Makefile fix for Cargo target directory handling
Series version: standalone patch (no versioned series)
Originating author: Andy Koppe

Core problem or goal: Fix a Makefile bug where the Git build fails if the user has a custom Cargo target directory (via `~/.cargo/config.toml` or `CARGO_TARGET_DIR`). The patch ensures the `gitcore` Rust library is found during linking by explicitly setting `--target-dir target` for Cargo commands, aligning the Make build with Meson’s behavior.

Current status: Under review; patch is minimal (two-line Makefile change) and targets only the Rust build rules (`RUST_LIB`, `RUST_MEMBER_LIBS`, `CARGO_ARGS`). The discussion has shifted to implementation mechanism: whether to modify the two `cargo build` recipes individually (current patch) or add `--target-dir target` to `CARGO_ARGS` once early in the Makefile (Junio’s suggestion). No changes have been posted yet, and the patch remains uncontroversial in terms of correctness.

Key technical details:
- Files touched: `Makefile` (Rust build rules only)
- New/renamed symbols: none
- Behavior change: Build now succeeds with custom Cargo target directories; output is written to `./target` instead of the user’s configured directory
- On-disk format: none
- Test coverage: none (build-system fix, not user-facing)

Open questions and loose ends:
- **Implementation mechanism**: Junio C Hamano suggested adding `--target-dir target` to `CARGO_ARGS` once early in the Makefile to avoid redundancy and improve maintainability. Andy Koppe raised concerns about this approach:
  - `CARGO_ARGS` appears intended for user-configurable build preferences (like `CFLAGS` or `LDFLAGS`), and overriding it could interfere with legitimate use cases.
  - Using `override CARGO_ARGS += --target-dir target` would create a subtle trap where subsequent modifications to `CARGO_ARGS` without `override` would be silently ignored.
  - Potential conflict with Mike Hommey’s stalled `mh/rust-crate-subdir` topic, which moves Rust code into a subdirectory. The fix could be reapplied there if that series progresses.
- No reroll is imminent, but the discussion may continue if others weigh in on the trade-offs.
