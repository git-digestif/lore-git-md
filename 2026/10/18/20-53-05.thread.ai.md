Thread identity: Rust integration in Git – Makefile fix for Cargo target directory handling
Series version: standalone patch (no versioned series)
Originating author: Andy Koppe

Core problem or goal: Fix a Makefile bug where the Git build fails if the user has a custom Cargo target directory (via `~/.cargo/config.toml` or `CARGO_TARGET_DIR`). The patch ensures the `gitcore` Rust library is found during linking by explicitly setting `--target-dir target` for Cargo commands, aligning the Make build with Meson’s behavior.

Current status: Under review; patch is minimal (two-line Makefile change) and targets only the Rust build rules. The discussion has shifted to the implementation mechanism: whether to modify the two `cargo build` recipes individually (current patch) or add `--target-dir target` to `CARGO_ARGS` once early in the Makefile (Junio’s suggestion). Junio’s observation that `CARGO_ARGS` is already modified with `+=` for other purposes (e.g., `--quiet` and `--release`) weakens Andy’s earlier concerns about it being reserved for user overrides, but Andy now argues that the distinction lies between build *preferences* (like `--quiet`, which can be overridden) and build *requirements* (like `--target-dir`, which must always be passed). Andy warns that adding `--target-dir` to `CARGO_ARGS` without the `override` keyword would create a maintainability trap: future modifications to `CARGO_ARGS` could silently ignore the requirement, breaking the build. The potential conflict with Mike Hommey’s stalled `mh/rust-crate-subdir` topic (which moves Rust code into a subdirectory) remains unresolved. No reroll has been posted, and the patch remains uncontroversial in terms of correctness, but the implementation debate is still active.
