Thread identity: Rust integration in Git – Makefile fix for Cargo target directory handling
Series version: standalone patch (no versioned series)
Originating author: Andy Koppe

Core problem or goal: Fix a Makefile bug where the Git build fails if the user has a custom Cargo target directory (via `~/.cargo/config.toml` or `CARGO_TARGET_DIR`). The patch ensures the `gitcore` Rust library is found during linking by explicitly setting `--target-dir target` for Cargo commands, aligning the Make build with Meson’s behavior.

Current status: Under review; patch is minimal (two-line Makefile change) and targets only the Rust build rules. The discussion has shifted to the implementation mechanism: whether to modify the two `cargo build` recipes individually (Andy’s approach) or refactor `CARGO_ARGS` to better distinguish between build *preferences* (e.g., `--quiet`, `--release`) and build *requirements* (e.g., `--target-dir`). Junio acknowledges Andy’s argument that `--target-dir` is a hard requirement and suggests introducing a companion variable (e.g., `CARGO_REQUIRED_ARGS`) for clarity, though he reiterates this is not an objection to the original patch. The potential conflict with Mike Hommey’s stalled `mh/rust-crate-subdir` topic remains unresolved. No reroll has been posted, and the patch remains uncontroversial in terms of correctness, but the implementation debate is still active.
