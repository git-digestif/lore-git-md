This is the third and final patch in Harald Nordgren’s v2 series introducing `--historical-branch` to `git reflog` and `git log -g`. It implements the core functionality: decorating each reflog entry with the branch name that was current when the entry was recorded, replacing the standard commit decorations. The patch touches eight files, adding 124 lines to `reflog-walk.c` (the bulk of the logic), 28 to `log-tree.c` (formatting), and 95 to the test script `t/t1414-reflog-walk.sh` for comprehensive coverage of edge cases.

The implementation adds a `branch` field to the `reflog_info` struct and introduces `mark_branches()`, which walks the reflog backward to determine the branch context for each entry. It handles branch renames, detached HEAD states (showing “detached at <commit>”), and non-HEAD reflogs (showing the ref’s own name). The branch name is formatted in parentheses after the `HEAD@{n}` selector and colored like a local branch decoration, preserving column alignment. The option is additive and requires `--walk-reflogs`; it is an error to use it without.

Test coverage is thorough: 95 new lines in `t/t1414-reflog-walk.sh` validate the output format, interaction with `--decorate`, branch renames, detached HEAD, non-HEAD reflogs, and the requirement for `--walk-reflogs`. The patch appears technically sound and addresses the v1 feedback on output formatting (branch names now appear after the operation description, not before). The architectural question—whether Git’s core should replicate functionality already available in tools like `tig`—remains unresolved, but the implementation itself is ready for deeper technical review.
