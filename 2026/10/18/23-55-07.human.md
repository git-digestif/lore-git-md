This is a bugfix and refactoring patch that aligns the handling of `remote.<name>.followRemoteHEAD` with an earlier change to `fetch.followRemoteHEAD`. The patch defers validation of the remote-level setting until it is actually needed (during `git fetch`), rather than validating it whenever any command loads remote configuration (e.g., `git push` or `git remote -v`). This eliminates spurious warnings and makes the two settings consistent in behavior and syntax.

The patch replaces the parsed `follow_remote_head` and `no_warn_branch` fields in `struct remote` with a raw string (`follow_remote_head_raw`) that is parsed lazily in `do_fetch()`. It also unifies the parser for both settings, so `fetch.followRemoteHEAD` now accepts the `warn-if-not-<branch>` syntax that was previously only available for the remote-level setting. Documentation is updated to reflect this, and new tests verify the new behavior.
