This thread is about a small but important fix to Git’s Rust build system. Andy Koppe submitted a patch to fix a Makefile bug that causes the build to fail when users have a custom Cargo target directory set in their environment. The patch ensures the `gitcore` Rust library is found during linking by explicitly setting `--target-dir target` for Cargo commands, matching the behavior of Git’s Meson build.

The patch itself is uncontroversial—Patrick Steinhardt reviewed it substantively, confirmed the issue and the fix, and considers it ready for integration. However, Junio C Hamano recently suggested a minor refinement to the implementation: instead of modifying the two `cargo build` recipes individually, he proposes adding `--target-dir target` to `CARGO_ARGS` once early in the Makefile. This would avoid redundancy and ensure the flag is consistently applied, even if `CARGO_ARGS` is overridden later. The discussion is now focused on this stylistic point rather than the correctness of the fix, though no reroll is imminent.

The patch touches only the Rust build rules in the `Makefile` and has no impact on user-facing behavior or on-disk format. There are no open technical questions, though Junio’s suggestion could influence how future patches interact with the Rust build rules. The fix is minimal and aligns with existing Meson behavior, making it a straightforward improvement for Rust integration.
