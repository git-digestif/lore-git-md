This thread is about a small but important fix to Git’s Rust build system. Andy Koppe identified a bug in the Makefile where builds fail if the user has a custom Cargo target directory (set via `~/.cargo/config.toml` or `CARGO_TARGET_DIR`). His patch ensures the `gitcore` Rust library is found during linking by explicitly setting `--target-dir target` for Cargo commands, matching the Meson build’s behavior.

The patch itself is uncontroversial and ready for integration—it’s a two-line change to the Makefile that fixes the build failure without affecting user-facing behavior. However, the discussion has shifted to *how* the fix should be implemented. Junio suggested a more maintainable approach: adding `--target-dir target` to `CARGO_ARGS` once early in the Makefile, rather than modifying the two `cargo build` recipes individually. Andy prefers the latter, arguing that `CARGO_ARGS` should be reserved for user-configurable build *preferences* (like `--quiet` or `--release`), while `--target-dir` is a build *requirement* that must always be passed. He also warns that modifying `CARGO_ARGS` without the `override` keyword could create a subtle trap: future changes might silently break the build if they omit it.

The debate remains unresolved, with no clear consensus on which approach is better. Patrick Steinhardt reviewed the patch and considers it ready, while Junio’s alternative remains on the table. The thread may continue if others weigh in on the trade-offs, particularly around maintainability and potential conflicts with Mike Hommey’s stalled `mh/rust-crate-subdir` series. For now, the patch is correct and could be merged as-is, but the implementation discussion is still active.
