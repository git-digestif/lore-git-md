This thread is about a small but important fix to Git’s Makefile to handle Rust builds when users have a custom Cargo target directory. Andy Koppe identified the issue: if you set `CARGO_TARGET_DIR` or configure it in `~/.cargo/config.toml`, the Git build fails because the `gitcore` Rust library can’t be found during linking. The fix is simple—explicitly setting `--target-dir target` for Cargo commands in the Makefile—bringing the Make build in line with Meson’s behavior.

Patrick Steinhardt reviewed the patch and confirmed it works as intended. He tested it and found no issues, though he noted a minor stylistic preference (using `--target-dir=target` instead of `--target-dir target`) that he didn’t think warranted a reroll. The patch is narrowly scoped, touching only the Rust build rules in the Makefile, and doesn’t affect the `contrib/libgit-{sys,rs}` targets. While Patrick mentioned a potential future discussion about merging those contrib libraries into `gitcore`, that’s unrelated to this fix.

The patch is ready to go and should resolve the build failure for users with custom Cargo configurations. No further changes are expected, and the fix is uncontroversial. If you’ve been hitting this issue, this patch should make it a thing of the past.
