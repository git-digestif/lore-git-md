This thread is about a small but important fix to Git’s Makefile to ensure the Rust build works correctly when users have custom Cargo target directories. Andy Koppe identified the issue—where the build fails if `~/.cargo/config.toml` or `CARGO_TARGET_DIR` specifies a non-default target directory—and proposed a two-line patch to explicitly set `--target-dir target` for Cargo commands. The fix aligns the Make build with Meson’s behavior and is uncontroversial in terms of correctness: Patrick Steinhardt reviewed it substantively, confirmed the problem, and deemed it ready for integration.

The discussion has since shifted to implementation details. Junio C Hamano suggested an alternative approach—adding `--target-dir target` to `CARGO_ARGS` once early in the Makefile—to avoid redundancy and improve maintainability. Andy responded with concerns about this approach: `CARGO_ARGS` is intended for user-configurable build preferences (like `CFLAGS`), and overriding it could interfere with legitimate use cases. He also noted a potential conflict with Mike Hommey’s stalled `mh/rust-crate-subdir` topic, which moves Rust code into a subdirectory, and suggested the fix could be reapplied there if that series progresses. No reroll has been posted yet, and the thread may continue if others weigh in on the trade-offs.

The patch itself is minimal, touching only the Rust build rules in the `Makefile`, and introduces no new symbols or on-disk format changes. It’s a build-system fix, so there’s no test coverage, but it resolves a real-world issue for users with custom Cargo configurations. The open question is purely about maintainability: whether to modify the two `cargo build` recipes individually or centralize the change in `CARGO_ARGS`. For now, the patch remains ready for integration, pending resolution of this implementation detail.
