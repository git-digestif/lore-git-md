This thread is about a small but important fix to Git’s Makefile to handle custom Cargo target directories when building the Rust components. Andy Koppe reported that the build fails if a user has configured a non-default target directory via `~/.cargo/config.toml` or `CARGO_TARGET_DIR`, and submitted a two-line patch to explicitly set `--target-dir target` for Cargo commands, matching Meson’s behavior.

The patch itself is uncontroversial—Patrick Steinhardt confirmed the issue and the fix, and Junio C Hamano has not objected to the correctness of the change. The discussion has instead focused on the best way to implement it: Andy’s original approach modifies the two `cargo build` recipes individually, while Junio suggested adding `--target-dir target` to `CARGO_ARGS` once early in the Makefile for better maintainability. Andy raised concerns about this approach, arguing that `CARGO_ARGS` is meant for user-configurable flags and that overriding it could interfere with legitimate use cases or create subtle traps for future modifications. Junio countered that the Makefile already modifies `CARGO_ARGS` for other purposes, weakening the argument that it should be reserved for user overrides.

No reroll has been posted yet, and the thread is now waiting for further input on the trade-offs between the two approaches. The patch touches only the Rust build rules in the `Makefile`, changes no user-facing behavior beyond making the build succeed with custom Cargo target directories, and introduces no new symbols or on-disk format changes. There’s no test coverage, as this is a build-system fix. The outcome may also depend on whether Mike Hommey’s stalled `mh/rust-crate-subdir` topic (which moves Rust code into a subdirectory) progresses, as the fix might need to be reapplied there. For now, the patch remains under review, with no clear consensus on the implementation mechanism.
