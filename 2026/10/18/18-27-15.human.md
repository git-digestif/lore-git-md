This is the first patch in a v2 feature series for `git reflog`, introducing `--operations` and `--historical-branch` options. This patch is a preparatory refactoring with no behavior change: it replaces hard-coded strings in reflog messages (used by `git checkout`, `git branch -m`, and `git rebase`) with `#define` constants in `reflog.h`. The goal is to prevent drift between the strings written to the reflog and those parsed by tools like `@{-<n>}` and `git status`.

The patch touches seven files, mostly in the `builtin/` and core subsystems. The new constants (`REFLOG_SWITCH_PREFIX`, `REFLOG_RENAME_PREFIX`, `REFLOG_STEP_START`, `REFLOG_STEP_FINISH`, `REFLOG_STEP_ABORT`) are straightforward and well-named. The commit message now clearly states the motivation upfront, addressing feedback from v1 about clarity. No test coverage is needed here since this is purely internal plumbing.

This is a clean, mechanical change that lays the groundwork for the next two patches. It looks well-crafted and uncontroversial, and the v2 improvements (better commit message, settled output format for `--historical-branch`) suggest the author is responsive to feedback. The patch is ready for deeper review, though the broader architectural question—whether Git’s core should replicate functionality already available in tools like `tig`—remains unresolved for the series as a whole.
