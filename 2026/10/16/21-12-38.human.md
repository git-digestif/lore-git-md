This is a documentation patch that has now been merged to `master`. Junio C Hamano’s email confirms the final version (v3) of Julia Evans’s rewrite of the introductory section of the `git(1)` man page is queued for integration.

The patch replaces outdated references to standalone guides (`gittutorial`, `giteveryday`, `user-manual`, `datamodel`, and `cli`) with direct, actionable instructions for accessing Git’s help system. New users are now pointed to `` `git push -h` `` for quick help, `` `git push --help` `` or `` `git help push` `` for full documentation, and `` `git help --guides` `` or `` `git help --user-interfaces` `` to discover concept guides. The patch also drops the link to `git.github.io/htmldocs/git.html` in favor of `git-scm.com/docs`, which tracks the latest *released* version of Git rather than the tip of `master`.

The commit message now fully explains the rationale for removing outdated guides: `cli` is developer-focused and not useful for interactive users, `user-manual` is outdated (e.g., still recommending `` `git format-patch` `` for collaboration), and `datamodel` feels orphaned once the other guides are removed. The patch adopts an "every page is page one" model, where documentation is self-contained and does not assume prior reading of other guides. All prior feedback—including Junio’s request for a clearer design philosophy and mechanical corrections—has been incorporated.

The patch touches only `Documentation/git.adoc` and has no on-disk format or test coverage changes. It is uncontroversial and ready for the next release. If you’ve been following the thread, this is the final step: the change is now in `master` and will appear in the next Git release.
