This is a review of the second patch in Johannes Schindelin’s five-part series fixing integer overflows flagged by Coverity. The patch changes the `posn` variable in `http.c` from `int` to `size_t` to match the type of the total size parameter, eliminating a latent heap under-read risk when HTTP response bodies exceed `INT_MAX` (~2 GB).

Patrick Steinhardt’s review confirms the change is correct: `posn` is only ever incremented by positive values, so a signed type is unnecessary. The patch is minimal—one line—and aligns with the series’ defensive hardening goal. No controversy here; the fix is straightforward and uncontroversial. The new `size_t` type may see future reuse in similar HTTP-related code paths, but this patch itself is self-contained.

The series as a whole remains under review, with open questions about platform-specific risks (NonStop’s `ssize_t` vs. `size_t` width mismatch) and the portability of the new overflow-checking macros. This particular patch, however, looks ready to proceed.
