This is a review comment on Igor Wiedler’s second patch in the v2 series fixing the performance regression in connectivity checks for deepening fetches. Jeff King (Peff) identifies a Windows CI failure in the new test case and proposes two alternative fixes to address the path normalization issue. The problem stems from using `$TRASH_DIRECTORY` in the alternates file, which Windows cannot normalize correctly. Peff suggests either using `$(pwd)` for relative paths or restructuring the test to use `--reference` or `--shared` cloning to let Git handle the alternates file itself.

Peff’s feedback is surface-level but practical: it focuses on test portability and style rather than the patch’s core logic. The proposed changes are mechanical and do not question the patch’s design or correctness. The review is thorough in addressing the immediate issue (Windows CI failure) and includes a minor style suggestion about using environment variables instead of temporary files. While the patch itself is well-motivated and addresses a real performance problem, this review highlights a test robustness issue that will need to be resolved before the series can proceed. No objections to the patch’s substance were raised.
