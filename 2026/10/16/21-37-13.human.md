This is the first patch in Justin Tobler’s v2 series fixing a race condition in Git’s ODB transaction machinery. It is a **refactoring** that makes a code comment hash-algorithm-agnostic by removing an explicit reference to SHA-1.

The patch updates a comment in `index_pack_lockfile()` to clarify that the output from `git-index-pack` uses a hexadecimal name (not specifically a SHA-1 hash) and that the line format is five bytes of prefix (`pack\t` or `keep\t`), followed by `hexsz` bytes of name, and a trailing newline. The change is purely documentary and does not alter behavior or touch any logic. The commit message explains the motivation clearly: the existing comment incorrectly implied that the parsing was SHA-1-specific, when in fact it already supports SHA-256.

This patch was split from the original v1 series at Patrick Steinhardt’s request to keep preparatory refactoring separate from the core fix. The change is small, well-explained, and uncontroversial. It prepares the ground for the next patch, which exposes the parsing logic as a public helper. No test changes are needed, and the patch looks ready to merge.
