This is the second patch in Justin Tobler’s three-patch bugfix series targeting the ODB transaction machinery. It refactors `odb_transaction_files_write_pack()` in `object-file.c` to stop relying on `git-index-pack --keep` to generate the `.keep` lockfile and instead write it explicitly inside the function itself.

The change is preparatory for patch 3/3, which will move lockfile creation to the transaction commit phase to fix the race condition where concurrent `git-receive-pack` processes can delete each other’s `.keep` files. The new `write_pack_lock()` helper constructs the lockfile path, writes the keep message (still formatted as `"receive-pack <pid> on <hostname>"`), and registers it as a tempfile. The patch also uses the exposed `read_index_pack_report()` (introduced in patch 1/3) to extract the pack name from `git-index-pack`’s output instead of calling the now-removed `index_pack_lockfile()` helper.

The diff is confined to `object-file.c` and replaces 20 lines of child-process plumbing with 79 lines of direct lockfile logic. No behavior change is intended; the patch is purely refactoring to enable the later transaction-phase lockfile creation. The commit message is clear about the motivation and the role this patch plays in the series.
