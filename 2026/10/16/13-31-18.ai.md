This is the v7 iteration of a feature patch adding revision-based filtering to the `git repo structure` command. The patch is now procedurally clean and ready for merging to `next`, with no substantive changes from v6—only a one-word commit message fix to address the final nit.

The feature allows users to analyze specific subsets of the repository object graph by specifying revisions (commits, refs, or ranges) to include or exclude, improving diagnostic capabilities for large repositories. The implementation uses Git’s standard `setup_revisions()` machinery, replacing an earlier enum-based flag system with a design consistent with Git’s revision-parsing idioms. This approach avoids the transitive dependency omission issues of earlier versions and aligns with established patterns in the codebase, though it introduces a known inefficiency: a second ref-walk in `count_references()` due to `setup_revisions()`’s lack of a custom ref-walk callback. This trade-off is explicitly accepted as tolerable for a diagnostic tool.

The patch touches `builtin/repo.c` (core implementation), `Documentation/git-repo.adoc` (user-facing documentation), and `t/t1901-repo-structure.sh` (test coverage). The test suite has grown significantly, now spanning 197 lines and validating edge cases like overlapping includes/excludes, output formats (table/lines/nul), and empty repository handling. The "empty repository" test, which was accidentally dropped in v4, has been reinstated to ensure predictable behavior. Documentation updates clarify terminology (e.g., "reachable") and correct misleading examples (e.g., `^foo`), while error messages now follow Git’s established pattern for unrecognized arguments.
