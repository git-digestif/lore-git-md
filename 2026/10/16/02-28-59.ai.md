This is the first patch in a three-part bugfix series targeting the ODB transaction machinery. It refactors the parsing logic for `git-index-pack` output to make it reusable, preparing the ground for the actual race condition fix in later patches.

The patch lifts the parsing of `git-index-pack`'s stdout report (which indicates whether a `.keep` lockfile was created alongside a packfile) from `index_pack_lockfile()` into a new helper function, `read_index_pack_report()`. The new function is exposed in `pack.h` and takes a `struct strbuf` to store the packfile name, along with an optional `is_keep` flag to indicate whether a `.keep` file was created. The original `index_pack_lockfile()` is updated to use this helper, making the code more modular and paving the way for the transaction machinery to read the packfile name without creating a `.keep` file prematurely.

The changes are confined to `pack-write.c` and `pack.h`, with no behavior changes in this patch—it’s purely preparatory refactoring. The diff is clean and focused, splitting out the parsing logic without altering its functionality. This patch is necessary for the subsequent fix, which will move `.keep` lockfile creation into the transaction commit phase to avoid the race condition described in the cover letter.

Key technical details for follow-up discussion:
- **New function**: `read_index_pack_report()` (exposed in `pack.h`), which parses `git-index-pack` output and stores the packfile name in a `struct strbuf`.
- **Refactored function**: `index_pack_lockfile()` now uses the new helper, reducing code duplication.
- **Files touched**: `pack-write.c`, `pack.h`.
- **No behavior change**: This patch is purely structural, setting up the next two patches in the series.
