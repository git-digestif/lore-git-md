This is the fourth and final patch in a v2 bugfix series targeting a race condition in Git’s object database (ODB) transaction machinery. The patch moves `.keep` lockfile creation from the quarantine phase to the transaction commit phase, ensuring lockfiles are only written after the transaction is guaranteed to succeed. This directly addresses the reported bug where concurrent `git-receive-pack` processes could delete each other’s lockfiles, leaving newly written packfiles vulnerable to housekeeping deletion.

The patch touches `object-file.c` and extends the test in `t/t5547-push-quarantine.sh` to verify the fix. Key changes include:
- Introducing a new `strvec pack_names` field in `struct odb_transaction_files` to store packfile names during quarantine.
- Adding a `write_pack_lockfiles()` helper that batch-creates lockfiles during transaction commit, using the stored packfile names.
- Removing the lockfile creation logic from `odb_transaction_files_write_pack()`, deferring it to commit time.
- Updating the test to confirm no `.keep` lockfile exists in the quarantine directory during the pre-receive phase and that manually created lockfiles (simulating concurrent processes) are preserved.

The commit message clearly explains the motivation and behavior change, and the test coverage is thorough, including checks for missing `.pack` files alongside `.keep` files. The patch is part of the ongoing ODB abstraction effort and follows all feedback from Patrick Steinhardt’s substantive reviews. The only remaining loose end is the unaddressed assumption about leading directories existing during quarantine, but this does not affect the correctness of the fix. The series is now technically complete and ready for final polish.
