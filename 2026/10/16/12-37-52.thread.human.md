This thread is about fixing a race condition in Git’s signal-handling (`sigchain`) subsystem that can cause infinite CPU loops during operations like `git clone --depth 1` over SSH. The issue arises when concurrent signal deliveries to different threads corrupt the internal handler chain.

The original patch by Ian Hu, currently in Junio’s `seen` branch, takes a minimal "repair after corruption" approach. However, the review discussion has shifted toward a more comprehensive thread-level fix: blocking signals during thread creation and using `sigaction()` to mask signals during handler execution. This approach is now the leading candidate, with Ian indicating willingness to implement it. Phillip Wood, a key reviewer, has refined the proposal with optimizations for thread-creation loops and clarified signal-masking behavior, reinforcing his preference for dropping the current patch entirely.

The thread is still under review, awaiting input from Jeff King (Peff), the original `sigchain` author, before Ian proceeds with a v2 series. Open questions include whether a regression test will be required and how to handle signal masking consistently across the codebase. The discussion remains focused on correctness and architectural safety rather than minimalism.
