This is a review follow-up in the `imap-send` OpenSSL hostname verification thread. Xiangfei Ding proposes a concrete fix for the error-reporting regression Aniket Gupta identified in Beat Bolli’s v2 patch 2/2. The patch currently loses the hostname-specific error message when certificate verification fails because `SSL_connect()` fails early under `SSL_VERIFY_PEER`. Xiangfei suggests installing an OpenSSL verification callback (`SSL_set_verify`) to capture the bad hostname in a "mailbox" variable, then printing it if `SSL_connect()` fails. This would restore the lost context without changing the patch’s core approach of using OpenSSL’s built-in `SSL_set1_host()`.

The proposal is narrowly scoped to error reporting and does not address the more serious security regression Patrick Steinhardt flagged (certificate stripping). It is a substantive, actionable suggestion that engages with OpenSSL’s callback mechanism, and Xiangfei volunteers to implement it as a follow-up patch. If accepted, this would unblock the error-reporting concern while leaving the security issue for Beat to resolve separately. No tests or new symbols are involved; the focus is purely on user-facing diagnostics.
