This thread is about a regression in Git’s HTTP transport layer caused by a security fix in libcurl 8.23.0 (CVE-2026-94266), which strips credentials from URLs during redirects. The issue affects pushes (but not fetches or clones) when the URL contains only a token as the username (e.g., `https://<token>@forge.example/owner/repo.git`), leading to 401 errors. Dan proposed a patch to fix this by modifying `http.c:update_url_from_redirect()` to strip userinfo from URLs before comparison.

However, Tuomas Ahola’s review reveals that this issue was already fixed in Git’s `master` branch by commit `76524c2604` ("http: handle curl stripping creds from effective url", 2026-09-28), which is included in the upcoming Git 2.55.0 release. The fix addresses the same problem and code path, meaning the regression is resolved for users of Git 2.55.0 or later. No further action is needed for the reported scenario, though there may be discussion about backporting the fix to older stable branches (e.g., `maint` for Git 2.54.x) if users are still affected. The thread is effectively closed unless gaps in the existing fix are identified.
