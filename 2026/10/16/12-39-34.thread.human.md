This thread is about a bugfix for a recently introduced regression in Git's sideband protocol handling. Thomas Bachem identified and fixed an infinite loop in the configuration parser for `sideband.allowControlCharacters`, which was introduced in March 2026. The bug occurs when users have malformed configurations (like typos or unsupported keywords) and breaks core Git operations like `fetch`, `push`, `clone`, and `ls-remote`.

The fix itself is simple: after warning about an unrecognized keyword, the parser now properly advances to the next entry rather than getting stuck. The patch also improves the warning message and adds a test case to verify the fix works for both invalid and valid keywords that follow. The change is contained to `sideband.c` and its test file, with no broader impact on other subsystems.

This appears to be a straightforward bugfix with no controversy or open questions - it addresses a clear usability issue that would affect any user with a malformed configuration, and the solution is well-scoped and tested. The patch should be ready for review and merging.
