Subject: [PATCH] branch: fix branch.autoSetupMerge=inherit with remote-tracking starting point
Series version: standalone patch (no series)
Originating author: Harald Nordgren
Thread type: bugfix patch → design discussion

Core problem or goal
Fix an inconsistency in `branch.autoSetupMerge=inherit` where it fails to set up tracking when the starting point is a remote-tracking branch (e.g., `origin/main`), unlike the default (`true`) behavior which does set up tracking. The discussion has expanded to define the intended behavior of `inherit` for *all* starting points (tags, commit hashes, local branches without tracking), but the author now explicitly limits the scope to remote-tracking branches only. The goal is to clarify whether the patch should:
1. Fix only remote-tracking branches (author's position), or
2. Also define behavior for non-tracking starting points (maintainer's concern).

Current status
Under review; no prior versions. The patch is self-contained but contested. Junio C Hamano’s review raises design questions about non-tracking starting points, while the author insists the patch should focus solely on remote-tracking branches. No consensus yet; the discussion is at an impasse pending clarification from the original `inherit` author or additional input.

Key technical details
- Files touched: `branch.c`, `Documentation/git-branch.adoc`, `Documentation/branch.adoc`, `t/t2060-switch.sh`
- Subsystem: branch creation and tracking logic
- New behavior (proposed): `branch.autoSetupMerge=inherit` sets up tracking for remote-tracking starting points (e.g., `origin/main`), matching the default (`true`) behavior
- Old behavior: `inherit` does not set up tracking for remote-tracking starting points, issuing a warning instead; does nothing for non-tracking starting points (tags, commit hashes, local branches without tracking)
- Test coverage: added test case in `t/t2060-switch.sh` to verify the fix for remote-tracking starting points; no changes for non-tracking starting points
- Potential new config values: `inherit-or-fail`, `inherit-or-direct` (suggested by Junio, not implemented or tested in this patch)
- Original commit: d3115660b4 (2021-12-20) introduced `inherit` mode; its behavior for non-tracking starting points was likely intentional but undocumented

Open questions and loose ends
1. Is the patch acceptable as a minimal fix for remote-tracking branches only, or must it also define behavior for non-tracking starting points (tags, commit hashes, local branches without tracking)?
2. Is the original behavior of `inherit` (doing nothing for non-tracking starting points) intentional, or was it an oversight? The original author (CC’ed) has not yet responded.
3. Documentation: `branch.adoc` update is flagged as misleadingly abbreviated; needs clarification for all starting point types, even if the patch does not address them.
4. Should Junio’s proposed modes (`inherit-or-fail`, `inherit-or-direct`) be pursued as a separate effort, or are they unnecessary complexity?

Participant positions

Rejects expanding scope to non-tracking starting points, calling Junio’s proposed new modes "overkill." No changes to existing behavior for non-tracking starting points.

- Original author of `inherit` (CC’ed): not yet responded; may clarify the original intent for non-tracking starting points.
