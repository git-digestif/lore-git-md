Subject: [PATCH] branch: fix branch.autoSetupMerge=inherit with remote-tracking starting point
Series version: standalone patch (no series)
Originating author: Harald Nordgren
Thread type: bugfix patch → design discussion

Core problem or goal
Fix an inconsistency in `branch.autoSetupMerge=inherit` where it fails to set up tracking when the starting point is a remote-tracking branch (e.g., `origin/main`), unlike the default (`true`) behavior which does set up tracking. The discussion has expanded to define the intended behavior of `inherit` for *all* starting points (tags, commit hashes, local branches without tracking), not just remote-tracking branches. The goal is now to clarify whether `inherit` should:
1. Copy tracking if it exists, otherwise do nothing (current behavior),
2. Track the starting point directly (proposed in the patch), or
3. Fail outright for non-tracking starting points.

Current status
Under review; no prior versions. The patch is self-contained but now contested. Junio C Hamano’s review raises design questions that may require a revised or expanded patch. The discussion is active, with no consensus yet on the correct behavior for non-tracking starting points.

Key technical details
- Files touched: `branch.c`, `Documentation/git-branch.adoc`, `Documentation/branch.adoc`, `t/t2060-switch.sh`
- Subsystem: branch creation and tracking logic
- New behavior (proposed): `branch.autoSetupMerge=inherit` sets up tracking for remote-tracking starting points (e.g., `origin/main`), matching the default (`true`) behavior
- Old behavior: `inherit` does not set up tracking for remote-tracking starting points, issuing a warning instead; does nothing for non-tracking starting points (tags, commit hashes, local branches without tracking)
- Test coverage: added test case in `t/t2060-switch.sh` to verify the fix for remote-tracking starting points; may need expansion to cover non-tracking starting points
- Potential new config values: `inherit-or-fail`, `inherit-or-direct` (suggested by Junio)
- Original commit: d3115660b4 (2021-12-20) introduced `inherit` mode; its behavior for non-tracking starting points was likely intentional but undocumented

Open questions and loose ends
1. What should `inherit` do for non-tracking starting points (tags, commit hashes, local branches without tracking)?
   - Current behavior: do nothing
   - Patch proposal: track the starting point directly
   - Junio’s suggestion: preserve current behavior or introduce new modes (`inherit-or-fail`, `inherit-or-direct`)
2. Should the patch be revised to address all starting points, or should it focus only on remote-tracking branches (as originally proposed)?
3. Is the original behavior of `inherit` (doing nothing for non-tracking starting points) intentional, or was it an oversight? The original author (CC’ed) may clarify.
4. Documentation: `branch.adoc` update is flagged as misleadingly abbreviated; needs clarification for all starting point types.
