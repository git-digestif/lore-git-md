This is a small but user-visible behavior change to the branch-tracking logic in Git. The patch addresses an inconsistency in how `branch.autoSetupMerge=inherit` handles remote-tracking branches as starting points.

Currently, when you create a new branch from a remote-tracking branch (like `origin/main`) with `inherit` mode, Git warns that no upstream is set—even though the remote branch would be a perfectly valid upstream. The patch makes `inherit` behave like the default `true` mode in this case: it directly uses the remote-tracking branch as the upstream, eliminating the warning and setting up tracking automatically.

The change is straightforward: a three-line code tweak in `branch.c` that detects when the starting point isn’t a local branch and switches the tracking mode to `BRANCH_TRACK_REMOTE`. The documentation is updated to clarify this behavior, and a new test case verifies that `git switch -c new_branch origin/main` now reports the branch as "up to date with 'origin/main'" when `inherit` is configured.
