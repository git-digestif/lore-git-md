This is a bugfix series targeting the object database (ODB) transaction machinery, now in its second iteration (v2). It fixes a race condition where concurrent `git-receive-pack` processes can delete each other’s `.keep` lockfiles, leaving newly written packfiles vulnerable to deletion by housekeeping processes. The series is part of the ongoing ODB abstraction effort led by Patrick Steinhardt.

The v2 update expands the series from three to four patches, splitting out a preparatory change (making index-pack output parsing hash-agnostic) into its own commit as requested in review. The core fix—moving `.keep` lockfile creation to the transaction commit phase—remains intact, but the implementation now includes improved error handling, better error messages (with `errno` context and lockfile paths), and a renamed helper (`write_pack_lockfile()`) for consistency. The test coverage in `t/t5547-push-quarantine.sh` has been strengthened to verify that no corresponding `.pack` file exists alongside the `.keep` file in the concurrent-process scenario, addressing a review request from Patrick Steinhardt.

All three original patches have been revised to incorporate Patrick’s feedback: unconditional use of the `is_keep` pointer in `read_index_pack_report()`, consolidated error paths, and clearer commit messages. The author declined to move the `safe_create_file_with_leading_directories()` call to the final patch, arguing that keeping it in the second patch is more defensive, though the assumption that leading directories exist during quarantine remains unaddressed. The series is now complete and ready for final polish, with no open technical objections from reviewers. The changes touch `object-file.c`, `pack-write.c`, `pack.h`, and the test suite.
