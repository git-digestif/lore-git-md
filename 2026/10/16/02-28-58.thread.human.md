This thread is a three-patch bugfix series from Justin Tobler that fixes a race condition in Git’s object database (ODB) transaction machinery. The issue occurs when concurrent `git-receive-pack` processes delete each other’s `.keep` lockfiles, leaving newly written packfiles vulnerable to deletion by housekeeping processes. The root cause is that temporary `.keep` lockfiles were registered in the object quarantine *before* being written to the primary ODB, allowing an early-exit `atexit` handler to delete lockfiles belonging to other processes.

The series is now complete with the third patch, which implements the core fix by moving `.keep` lockfile creation from the quarantine phase to the transaction commit phase. This ensures lockfiles are only written after the transaction is guaranteed to succeed, eliminating the race. The preparatory refactoring in patches 1 and 2 (already reviewed) made this change straightforward. The test coverage in `t/t5547-push-quarantine.sh` has been extended to verify lockfile ownership under concurrent operations, directly addressing the reported bug.

The fix is technically sound, well-motivated, and part of the broader ODB abstraction effort led by Patrick Steinhardt, though it stands alone as a correctness fix. No on-disk format changes or backwards-compatibility concerns are introduced. The series is ready for substantive review, with the only minor open question being whether the `atexit` cleanup should be made more defensive (e.g., checking file ownership before deletion). So far, only Justin has weighed in, and the patches remain unreviewed.
