This thread is a three-patch bugfix series from Justin Tobler that fixes a race condition in Git’s object database (ODB) transaction machinery. The issue occurs when concurrent `git-receive-pack` processes delete each other’s `.keep` lockfiles, leaving newly written packfiles vulnerable to deletion by housekeeping processes. The root cause is that temporary `.keep` lockfiles were registered in the object quarantine before being written to the primary ODB, allowing early transaction exits to trigger cleanup that could delete files belonging to other processes.

The fix moves lockfile creation to the transaction commit phase, ensuring lockfiles are only written after the transaction is guaranteed to succeed. All three patches have received substantive technical reviews from Patrick Steinhardt, who supports the direction and has provided detailed feedback on code clarity, style, error handling, and test coverage. The first two patches have been revised to address Patrick’s suggestions, including improvements to error paths, naming consistency, and docstring clarity. The third patch, which implements the core fix, has now been updated to incorporate Patrick’s feedback: the commit message will better explain the prevention of partial transaction commits, error messages will include `errno` context, and test coverage will explicitly verify that no corresponding `.pack` file exists alongside the `.keep` file in concurrent scenarios.

The series is now complete and ready for final polish. The only remaining open question is whether the `atexit` cleanup should be made more defensive, but this is minor compared to the fix’s overall robustness. The patches touch `object-file.c`, `pack-write.c`, and the test suite, introducing new helpers like `write_pack_locks()` to batch-create lockfiles during transaction commit. No on-disk format changes or backwards-compatibility concerns are introduced. The fix is part of the broader ODB abstraction effort led by Patrick Steinhardt.
