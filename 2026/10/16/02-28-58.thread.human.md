This thread is a four-patch bugfix series from Justin Tobler that fixes a race condition in Git’s object database (ODB) transaction machinery. The issue occurs when concurrent `git-receive-pack` processes delete each other’s `.keep` lockfiles, leaving newly written packfiles vulnerable to deletion by housekeeping processes. The root cause was that temporary `.keep` lockfiles were registered in the object quarantine *before* being written to the primary ODB, meaning that if the transaction exited early (e.g., due to an error), the `atexit` handler would still try to clean up the lockfile at its final location, potentially deleting a file belonging to another process.

The fix moves lockfile creation to the transaction commit phase, ensuring lockfiles are only written after the transaction is guaranteed to succeed. This eliminates the race condition by preventing lockfiles from being left in an inconsistent state. The series has been through four iterations, with all patches now incorporating feedback from Patrick Steinhardt, who has explicitly approved the series as technically sound and well-structured. The test in `t/t5547-push-quarantine.sh` verifies the fix by confirming that no `.keep` lockfile exists in the quarantine directory during the pre-receive phase and that a manually created `.keep` file (simulating a concurrent process) is not deleted by the transaction cleanup. The only remaining loose end is an unaddressed assumption that leading directories for lockfiles exist during quarantine, which Patrick Steinhardt flagged but did not revisit in his final review. This is not considered a blocker, and Junio C Hamano has signaled readiness to merge the series once the v4 reroll was submitted. The series is now ready for integration.
