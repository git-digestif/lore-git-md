This is a v2 bugfix series targeting the object database (ODB) transaction machinery, addressing a race condition where concurrent `git-receive-pack` processes can delete each other’s `.keep` lockfiles. The series is now expanded to four patches (up from three in v1) and incorporates all feedback from Patrick Steinhardt’s **substantive technical reviews**.

The core fix remains unchanged: `.keep` lockfiles are now created *only* during transaction commit (`odb_transaction_files_commit()`), not during quarantine, ensuring they are written only after the transaction is guaranteed to succeed. This eliminates the race condition where early-exit cleanup could delete lockfiles belonging to other processes. The v2 changes focus on code clarity, error handling, and test robustness:

- **Patch 1 (new)**: Makes the `git-index-pack` output parser hash-algorithm-agnostic by removing a hardcoded SHA-1 assumption. This was split from the original patch 1 as a separate cleanup, addressing Patrick’s request for clearer commit boundaries.
- **Patch 2**: Lifts and exposes `read_index_pack_report()` (renamed from internal logic in `index_pack_lockfile()`) to parse `git-index-pack` output. The helper now unconditionally uses the `is_keep` pointer (as requested by Patrick) and consolidates error paths.
- **Patch 3**: Refactors `object-file.c` to explicitly write `.keep` lockfiles via a new `write_pack_lockfile()` helper (renamed from `write_pack_lock()` for consistency). Error messages now include `errno` context and the lockfile path, and error paths are consolidated to avoid leaks.
- **Patch 4**: Moves lockfile creation to the transaction commit phase. The commit message now clarifies that this prevents partial transaction commits by acquiring all lockfiles before migrating data. The test in `t/t5547-push-quarantine.sh` now verifies that no corresponding `.pack` file exists alongside the `.keep` file in the concurrent-process scenario.

**Key technical details**:
- **Files touched**: `object-file.c`, `pack-write.c`, `pack.h`, `t/t5547-push-quarantine.sh`.
- **New/renamed symbols**:
  - `read_index_pack_report()` (exposed in `pack.h`): Parses `git-index-pack` output to extract packfile names and `.keep` status.
  - `write_pack_lockfile()` (renamed from `write_pack_lock()`): Writes the `.keep` lockfile with improved error handling.
  - `write_pack_lockfiles()` (new): Batch-creates lockfiles during transaction commit.
- **Behavior change**: Lockfiles are now created atomically during commit, not quarantine.
- **Test coverage**: Extends `t/t5547` to verify lockfile ownership under concurrent `git-receive-pack` operations, including checks for missing `.pack` files.

**Open questions**:
- The assumption that leading directories for lockfiles exist during quarantine remains unaddressed (Patrick requested explicit directory creation or a rationale, but the author declined to move the `safe_create_file_with_leading_directories()` call to the final patch).
- The `atexit` cleanup could still be made more defensive (e.g., checking file ownership before deletion), though this is not part of the current series.

The series is part of the ongoing ODB abstraction effort led by Patrick Steinhardt and is ready for final polish. All feedback from v1 has been addressed, and the patches look technically sound. The expanded test coverage and improved error handling strengthen the fix.
