This is the final patch in Justin Tobler’s three-part bugfix series targeting a race condition in Git’s object database (ODB) transaction machinery. It implements the core fix by moving `.keep` lockfile creation from the quarantine phase to the transaction commit phase, ensuring that lockfiles are only written after the transaction is guaranteed to succeed and that concurrent processes cannot interfere with each other’s lockfiles.

The patch touches `object-file.c` and extends the test coverage in `t/t5547-push-quarantine.sh`. The key change is in `odb_transaction_files_write_pack()`, where the lockfile creation logic is removed and replaced with a deferred approach: packfile names are stored in a `strvec` during quarantine, and the actual lockfiles are written in `odb_transaction_files_commit()` via the new `write_pack_locks()` helper. This ensures that lockfiles are only created if the transaction commits successfully, eliminating the race where an early-exit `atexit` handler could delete another process’s lockfile.

The test updates verify two critical behaviors: first, that no `.keep` lockfile exists in the quarantine directory during the pre-receive phase (confirming the lockfile is deferred), and second, that a manually created `.keep` file (simulating a concurrent process) is not deleted by the transaction cleanup. The latter test directly addresses the reported bug, where concurrent `git-receive-pack` processes could delete each other’s lockfiles, leaving packfiles vulnerable to housekeeping.

This patch is technically sound and well-motivated, addressing a real correctness issue with clear test coverage. The preparatory refactoring in patches 1–2 (already summarized) makes this change straightforward, and the commit message effectively explains the problem and solution. The only open question is whether the `atexit` cleanup should be made more defensive (e.g., checking file ownership), but that’s a minor concern given the fix’s robustness.

Key technical details for follow-up discussion:
- **Files touched**: `object-file.c`, `t/t5547-push-quarantine.sh`.
- **New functions**: `write_pack_locks()` (helper to batch-create lockfiles during commit).
- **Behavior change**: `.keep` lockfiles are now created *only* during transaction commit, not quarantine.
- **Test coverage**: Adds a test for concurrent lockfile safety, complementing the existing quarantine validation.
- **Related subsystems**: ODB transactions, packfile handling, quarantine mechanism.
