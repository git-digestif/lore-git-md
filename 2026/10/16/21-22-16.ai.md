This is a contributor housekeeping patch that aligns the naming of Git’s timeout configuration variables for the credential store subsystem. The patch introduces `credentialStore.lockTimeout` as the preferred setting while retaining `credentialStore.lockTimeoutMS` as a deprecated alias, matching the convention established by the recent `rerere.lockTimeout` patch.

The change is purely mechanical and touches three files. In `Documentation/config/credential.adoc`, it updates the description of the timeout setting to use the new name and adds a deprecation notice for the old one. In `builtin/credential-store.c`, the config lookup now tries the new key first, falling back to the old one if the new key is unset. The test suite (`t/t0302-credential-store.sh`) adds coverage for the new key, verifying it works as expected, that the old key still works, that the new key takes precedence when both are set, and that a zero timeout behaves correctly.

This v2 patch addresses all feedback from Junio C Hamano’s review of v1. The config lookup line in `builtin/credential-store.c` is now wrapped for readability, and the duplicated test cases for zero timeout are collapsed into a single loop over both config key names. A redundant test that did not exercise the timeout logic has been dropped, and a comment clarifies that the "both are set" test checks for "in 0 ms" rather than "in 500 ms". The patch is uncontroversial and ready for integration, as it aligns with established project conventions without altering behavior.
