Core problem or goal
Fix an infinite loop in the `sideband.allowControlCharacters` configuration parser introduced in March 2026 (commit 128914438a). The parser gets stuck on any unrecognized keyword (e.g., typos like "colour", space-separated lists like "color, cursor", or keywords only supported in newer Git versions), repeatedly warning about the same invalid entry. Because the setting is read during every transport setup, this bug breaks `git fetch`, `git push`, `git clone`, and `git ls-remote` for users with malformed configurations.

Current status
Under review. The patch is a standalone bugfix with no prior versions. It has not been queued in any integration branch.

Key technical details
- Files touched: `sideband.c`, `t/t5409-colorize-remote-messages.sh`
- New test: verifies the parser skips unrecognized keywords (e.g., "bogus") and still processes valid keywords that follow
- Behavior change: parser now advances to the next comma-separated entry after warning about an unrecognized keyword (previously, it would loop indefinitely on the problematic entry)
- Warning message: tightened to show only the unrecognized keyword rather than the entire remaining string
- Subsystems: sideband protocol (no cross-subsystem impact)
- Regression commit: 128914438a (March 2026)
- Style nit: the `!!` operator used to convert a character to a boolean for pointer arithmetic is discouraged by `CodingGuidelines` as an unnecessary "clever trick"
