This is a bugfix patch addressing a regression in `git fetch --all --depth=<n>` and `git fetch --all --unshallow` introduced in Git 2.56.0. The patch is under active revision following Junio C Hamano’s substantive review, which identified two key concerns: the same propagation issue may exist for submodule fetches, and the patch only handles `--depth` while ignoring other deepening options like `--deepen-since` and `--shallow-exclude`.

Rong Bao acknowledges the review feedback and plans a v2 that will explicitly handle `--depth` and `--deepen-since` but exclude `--shallow-exclude` to avoid propagating unrelated history constraints to submodules. The author argues that propagating `--depth` to submodules aligns with existing behavior for other fetch options like `--tags` and matches user expectations for commands like `git fetch --unshallow --recurse-submodules`. This position is likely to spark further discussion about whether submodule depth should be controlled independently.

The patch touches `builtin/fetch.c` and adds tests in `t/t5514-fetch-multiple.sh`. The core fix—forwarding deepening flags to subprocesses—is uncontroversial for `--all`, but the broader implications for submodule fetches remain unresolved. The v2 will clarify the scope and correctness of the propagation logic, making this a thread to watch for anyone interested in fetch behavior or submodule handling.
