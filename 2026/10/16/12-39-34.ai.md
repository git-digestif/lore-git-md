This is a bugfix patch targeting the sideband protocol's control-character handling.

The patch fixes an infinite loop in the configuration parser for `sideband.allowControlCharacters`. Since the feature was introduced in March 2026, the parser would get stuck on any unrecognized keyword (e.g., a typo like "colour", a space-separated list like "color, cursor", or a keyword only supported in newer Git versions), repeatedly warning about the same invalid entry. Because the setting is read during every transport setup, this bug effectively breaks `git fetch`, `git push`, `git clone`, and `git ls-remote` for users with malformed configurations.

The fix is straightforward: after warning about an unrecognized keyword, the parser now advances to the next comma-separated entry instead of staying on the problematic one. The warning message is also tightened to show only the unrecognized keyword rather than the entire remaining string. The patch includes a new test in `t/t5409-colorize-remote-messages.sh` that verifies the parser skips "bogus" and still processes valid keywords that follow it, ensuring both the warning and the intended functionality work as expected.

The change touches only `sideband.c` and its test file, with no cross-subsystem impact. The commit message clearly identifies the regression commit (128914438a) and provides concrete examples of how users might trigger the bug. The patch looks well-scoped and motivated, addressing a real usability issue without introducing new complexity.
