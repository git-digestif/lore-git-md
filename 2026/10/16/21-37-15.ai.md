This is the third patch in Justin Tobler’s four-patch v2 series fixing a race condition in Git’s ODB transaction machinery. It refactors `object-file.c` to explicitly write `.keep` lockfiles during the quarantine phase, preparing for the final patch (4/4) that defers lockfile creation to the transaction commit phase.

The patch introduces a new helper, `write_pack_lockfile()`, which constructs the lockfile path, writes the keep message (`"receive-pack <pid> on <hostname>"`), and registers it as a tempfile. The existing `odb_transaction_files_write_pack()` function is updated to use this helper instead of relying on `git-index-pack --keep` to create the lockfile. Key changes include:
- **New symbols**: `write_pack_lockfile()` (renamed from the earlier `write_pack_lock()` in the series for consistency).
- **Behavior**: Lockfiles are now written directly by Git rather than delegated to `git-index-pack`, with improved error handling (including `errno` context and lockfile paths in error messages).
- **Error paths**: Consolidated to avoid resource leaks, with explicit cleanup on failure.
- **Assumptions**: The patch assumes leading directories for lockfiles exist during quarantine (a point Patrick Steinhardt flagged as potentially unsafe, though the author justifies it as defensive).

The patch is technically sound and directly enables the race-condition fix in patch 4. It addresses all of Patrick Steinhardt’s v1 feedback: renaming the helper for consistency, adding `errno` context to error messages, and clarifying the lockfile path construction. The only remaining loose end is the unaddressed assumption about directory existence, but this does not block the patch’s readiness. The refactoring is clean and well-motivated, with no behavior change in this patch—only preparation for the final fix.
