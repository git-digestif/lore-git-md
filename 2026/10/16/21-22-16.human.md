This is a contributor housekeeping patch that aligns the naming of Git’s timeout configuration variables. It introduces `credentialStore.lockTimeout` as the preferred setting for credential lock retries, while keeping `credentialStore.lockTimeoutMS` as a deprecated alias for backward compatibility. The change is purely mechanical—no behavior is altered, only the config key name and its documentation.

The patch updates three files. In `Documentation/config/credential.adoc`, it adds the new key and marks the old one as deprecated. In `builtin/credential-store.c`, it modifies the config lookup to try the new key first, falling back to the old one if the new key is unset. The test suite (`t/t0302-credential-store.sh`) adds coverage for the new key, the old key, precedence when both are set, and zero timeout behavior.

This is a direct follow-up to Junio C Hamano’s observation in the `rerere` race-fix thread that most timeout variables in Git use milliseconds without an explicit unit suffix. The v2 patch incorporates all of Junio’s feedback: the config lookup line is now wrapped for readability, the duplicated test cases are collapsed into a loop, and a redundant test has been dropped. The remaining tests are thorough, covering edge cases like zero timeout and key precedence. The commit message is clear and concise, explaining the motivation without overstating the change.

The patch is uncontroversial and ready for integration. It aligns with established project conventions and maintains backward compatibility, so no substantive objections are expected. This is a clean, well-tested follow-up that tidies up a minor inconsistency in Git’s configuration naming.
