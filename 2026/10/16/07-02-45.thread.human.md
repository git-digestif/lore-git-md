This thread is about a bugfix for Git’s branch creation and tracking logic. Harald Nordgren identified an inconsistency in how `branch.autoSetupMerge=inherit` behaves when creating a new branch from a remote-tracking branch (like `origin/main`). Currently, Git warns that no remote is configured and skips tracking setup, even though the default (`true`) behavior *does* set up tracking in this case. The patch makes `inherit` match the default behavior, ensuring consistent tracking setup regardless of the `autoSetupMerge` setting.

The fix is small and targeted: it modifies `branch.c` to detect when the starting point isn’t a local branch (i.e., doesn’t begin with `refs/heads/`) and treats it as a direct tracking target. The patch also updates the documentation and adds a test case in `t/t2060-switch.sh` to verify the fix. The change is uncontroversial—it aligns behavior with user expectations without introducing new edge cases—and the code change is minimal, reducing the risk of regressions. No objections or alternative approaches have been raised so far, and the patch appears ready for integration.
