This thread began with Harald Nordgren’s patch to fix an inconsistency in `branch.autoSetupMerge=inherit`: when creating a branch from a remote-tracking starting point like `origin/main`, the `inherit` setting failed to set up tracking, unlike the default `true` behavior. What started as a straightforward bugfix has become a design discussion about the intended behavior of `inherit` for *all* starting points—not just remote-tracking branches, but also tags, commit hashes, and local branches without tracking.

Harald’s position is now clear: he wants `inherit` to set up tracking *only* for remote-tracking branches, matching the behavior of `true`, and considers the patch a narrow, well-scoped fix. He rejects Junio C Hamano’s suggestion that the patch should also define behavior for non-tracking starting points, calling proposed new modes like `inherit-or-fail` or `inherit-or-direct` unnecessary complexity. Junio, however, views the patch as incomplete because it doesn’t address what `inherit` should do when the starting point has no tracking information to inherit. The original author of the `inherit` mode (introduced in 2021) has not yet weighed in, leaving the original intent for non-tracking starting points unresolved.

The discussion is at an impasse. The patch itself is self-contained, touching `branch.c` and updating documentation to treat remote-tracking branches as direct tracking targets, but Junio’s review flags the documentation as misleading and the design as potentially ambiguous. Until the original author clarifies whether the current behavior (doing nothing for non-tracking starting points) was intentional, or until another contributor offers a decisive opinion, the thread is unlikely to move forward. For now, the patch remains under review, with no consensus on whether it should proceed as-is or be expanded to address the broader design questions.
