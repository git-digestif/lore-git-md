This thread began with Harald Nordgren’s patch to fix an inconsistency in `branch.autoSetupMerge=inherit`: when creating a branch from a remote-tracking starting point (like `origin/main`), the `inherit` setting failed to set up tracking, unlike the default (`true`) behavior. What started as a narrow bugfix has grown into a broader design discussion about how tracking should work in Git.

The patch itself is contested. Junio C Hamano, the maintainer, argues that the current behavior for non-tracking starting points (tags, commit hashes, local branches without tracking) was intentional and that the patch is incomplete without addressing them. He suggests new modes like `inherit-or-fail` or `inherit-or-direct` as opt-in alternatives. Phillip Wood, meanwhile, describes user workflows where the current behavior—doing nothing for non-tracking starting points—may actually be preferable, shifting the focus to user expectations.

Harald’s latest reply takes the discussion in a new direction. Instead of inheriting tracking from the starting point, he proposes inheriting it from the *current* branch: if you’re on a branch that already tracks `origin/master`, any new branch you create would automatically track the same remote. This would address Phillip’s scenario where users want new branches to track the same upstream as their parent branch. Harald suggests keeping his original patch’s behavior as a fallback (tracking the starting point directly) only if the current branch has no tracking configuration. This hybrid approach is still conceptual, with no code or tests, but it introduces a fundamental question: should tracking inheritance flow from the current branch or the starting point?

The thread remains at an impasse. The original author of the `inherit` mode hasn’t responded to clarify the intent behind the current behavior, and no consensus has emerged on whether to proceed with Harald’s minimal fix, Junio’s proposed modes, or this new hybrid approach. The outcome could influence how Git handles tracking setup in the future, but for now, the discussion is stuck between competing visions of what users expect.
