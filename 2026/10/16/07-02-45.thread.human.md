This thread is about a bugfix patch from Harald Nordgren that addresses an inconsistency in Git’s `branch.autoSetupMerge=inherit` behavior. The patch ensures that when a new branch is created from a remote-tracking starting point (like `origin/main`), tracking is set up just as it would be with the default `true` setting. The fix touches `branch.c`, updates documentation, and adds test coverage.

Junio C Hamano’s recent review has turned this from a straightforward bugfix into a design discussion. He questions whether the patch’s change—applying tracking only to remote-tracking starting points—is sufficient or if the `inherit` mode should also define behavior for other starting points (tags, commit hashes, or local branches without tracking). Junio suggests preserving backward compatibility by either keeping the current behavior (do nothing for non-tracking starting points) or introducing new modes like `inherit-or-fail` or `inherit-or-direct` to avoid surprising users. His preference leans toward the former, citing the original 2021 commit as evidence that the current behavior was intentional, even if undocumented.

The thread is now waiting for input from the original author of the `inherit` feature to clarify intent, but no substantive reviews or alternative implementations have been posted yet. The outcome will determine whether the patch needs revision, expansion, or a split into multiple configuration modes.
