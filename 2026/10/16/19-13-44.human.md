This is the third iteration of a bugfix for `git repack` that completes the work begun in v2. The patch addresses a long-standing regression where `git repack --drop-filtered --dry-run` incorrectly rebuilds packs and deletes old ones despite the `--dry-run` flag, violating its documented behavior. The v3 patch is a cleanup follow-up to the already-queued v2 fix, removing redundant `(!dry_run)` checks that became unreachable after the early `return` was added in v2.

The change is minimal and surgical: it drops two `!dry_run` guards in `repack_promisor_objects()` and `existing_packs_remove_redundant()` that are no longer needed because the early `return` in `cmd_repack()` now prevents a dry run from ever reaching those code paths. The test coverage remains unchanged from v2, which already verified that the pack directory is left untouched under `--dry-run`. This patch is purely about code hygiene and does not alter behavior or on-disk format.

The patch is well-motivated and uncontroversial. The redundant checks were noted by Patrick Steinhardt during the v2 review, and Siddharth Shrimali has addressed them as promised. The commit message clearly explains why the checks are now unnecessary, and the diff is small and easy to review. Since the v2 patch is already cooking in `next` and expected to graduate to `master` soon, this v3 cleanup can be queued independently without blocking the main fix.

No new symbols or files are introduced, and the patch touches only `builtin/repack.c`. The test script (`t/t7706-repack-drop-filtered.sh`) remains unchanged because the v2 test already covers the relevant behavior. This looks like a tidy, low-risk follow-up that aligns the codebase with the logical flow established in v2. The regression’s origin (commit `1e746b00aa`, 2025) and the fix’s rationale are well-documented, making the patch easy to understand in context.
