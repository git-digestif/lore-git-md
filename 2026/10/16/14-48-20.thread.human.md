This thread is about a small but practical fix to GitLab CI configuration. Patrick Steinhardt identified that the "check-whitespace" and "check-style" jobs in GitLab CI were failing for merge requests with more than 50 commits because GitLab's default shallow clone (depth=50) prevented the jobs from accessing the base commit they need to compare against. The fix is simple: force a full clone by setting `GIT_DEPTH: 0` for both jobs in `.gitlab-ci.yml`.

The change is minimal—just three lines—and mirrors a similar fix already in place for GitHub CI. While this issue rarely affects upstream patch series (which tend to be shorter), it does cause problems in GitLab's internal development branches. Patrick's patch is well-motivated, includes a link to a pipeline run demonstrating the fix, and is uncontroversial given his expertise in GitLab CI infrastructure. No objections or further discussion have emerged so far, so this looks like a straightforward improvement that should land without fuss.
