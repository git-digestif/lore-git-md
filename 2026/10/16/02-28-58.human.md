This is a bugfix series targeting the object database (ODB) transaction machinery. Justin Tobler addresses a race condition in `git-receive-pack` where concurrent processes receiving identical packfiles can delete each other’s `.keep` lockfiles, leaving newly written packfiles vulnerable to deletion by housekeeping processes.

The problem stems from how temporary `.keep` lockfiles are registered in the object quarantine *before* being written to the primary ODB. If an ODB transaction exits early (e.g., due to an error), the `atexit` handler still tries to clean up the lockfile at its expected final location, blindly deleting any matching file regardless of ownership. The series fixes this by deferring lockfile creation until the ODB transaction commits, ensuring the file exists before registration.

Patches 1 and 2 are preparatory: they lift and expose index-pack report parsing from `pack-write.c` so the ODB transaction code can handle lockfile creation directly. Patch 3 migrates lockfile generation into the transaction commit phase, eliminating the race. The changes touch `object-file.c`, `pack-write.c`, and `pack.h`, with a new test case in `t/t5547-push-quarantine.sh` to verify the fix.

The commit message clearly explains the bug and the solution, and the patch series is well-structured. The fix is narrowly scoped to the ODB transaction logic, avoiding broader changes that might introduce regressions. Given the potential for data loss (packfile deletion), this looks like a serious issue worth attention. The series is under review and not yet merged.
