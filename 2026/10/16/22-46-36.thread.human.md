This thread is about a routine maintenance update to Git's GitHub Actions CI workflows. GitHub is deprecating the `macos-14` runner image, so Junio C Hamano posted a patch to split the macOS CI jobs between `macos-15` (the oldest supported version) and `macos-latest` (currently `macos-26`). The goal is to keep the CI jobs (`osx-clang`, `osx-reftable`, `osx-gcc`, and `osx-meson`) operational while improving cross-version test coverage.

The latest version of the patch (v3) assigns `osx-clang` and `osx-meson` to `macos-15`, and `osx-reftable` and `osx-gcc` to `macos-latest`. This aligns with GitLab CI’s configuration and addresses the maintainability concern raised by Todd Zullinger, who advocated for using `macos-latest` to avoid manual updates. Junio initially leaned toward explicit versions (`macos-15`/`macos-26`) for consistency but ultimately chose `macos-latest` for the newer jobs to provide rolling coverage of newer macOS releases. The patch modifies only `.github/workflows/main.yml` and introduces no functional changes to Git’s codebase.

The thread has converged on this approach, with no technical objections or platform-specific concerns raised. The patch remains untested but is considered low-risk. The open question about whether to use `macos-26` or `macos-latest` has been resolved in favor of `macos-latest`, though Junio notes that the oldest supported version (`macos-15`) still requires manual updates due to the lack of a symbolic name for it. Key participants include Patrick Steinhardt (who proposed the job-splitting approach), Todd Zullinger (who advocated for `macos-latest`), and Brian m. Carlson (who provided context on macOS release cadence). The patch is now ready for integration.
