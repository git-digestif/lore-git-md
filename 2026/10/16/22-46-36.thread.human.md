This thread is about updating Git’s GitHub Actions CI workflow to replace the deprecated `macos-14` runner image with a split between `macos-15` and either `macos-26` or `macos-latest`. The change is purely infrastructural, ensuring CI jobs (`osx-clang`, `osx-reftable`, `osx-gcc`, `osx-meson`) remain functional while improving cross-version macOS coverage.

Junio C Hamano posted a v2 patch implementing Patrick Steinhardt’s proposal to split jobs: `osx-clang` and `osx-meson` run on `macos-15`, while `osx-reftable` and `osx-gcc` would run on either `macos-26` or `macos-latest`. The patch itself is uncontroversial, but the choice of runner tag for the latter two jobs remains open. Todd Zullinger advocated for `macos-latest` to automatically track GitHub’s default image, citing maintainability and rolling coverage of newer macOS releases, while Junio now leans toward explicit versions (`macos-15`/`macos-26`) for consistency with GitLab CI’s configuration. Brian m. Carlson provided context on macOS release cadence but deferred to the group’s preference.

The thread is converged on the v2 structure, with no objections to the job-splitting approach. The remaining question is whether to prioritize consistency with GitLab CI (explicit versions) or maintainability (floating tag). No technical risks or implementation issues have been raised, and the patch is not yet queued for integration.
