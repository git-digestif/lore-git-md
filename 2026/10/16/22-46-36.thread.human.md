This thread is about a routine maintenance update to Git's GitHub Actions CI workflows. Junio C Hamano posted a patch to split the macOS runner images between two explicit versions, `macos-15` and `macos-26`, replacing the deprecated `macos-14` image. The goal is to ensure CI jobs remain operational while improving cross-version compatibility coverage and aligning with GitLab CI, which lacks a `latest` tag.

The discussion initially explored using `macos-latest` for maintainability, but Patrick Steinhardt successfully argued for explicit versions to ensure consistency across CI systems. Junio withdrew his v3 patch (which favored `macos-latest`) and reverted to the v2 approach, now finalized in this v4 patch. The jobs are distributed as `macos-15` (for `osx-clang` and `osx-meson`) and `macos-26` (for `osx-reftable` and `osx-gcc`), balancing backward compatibility with the latest explicit version. The patch is purely mechanical, touching only the `.github/workflows/main.yml` file, and poses minimal risk as it only changes the runner image without altering job logic.

The thread has converged on the explicit versioning approach, resolving the earlier debate. The patch is uncontroversial, well-motivated, and ready for integration, with no open questions or loose ends remaining.
