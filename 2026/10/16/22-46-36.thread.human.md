The GitHub Actions CI maintenance thread has concluded its discussion on how to split macOS runner versions in `.github/workflows/main.yml`. The patch, originally posted by Junio C Hamano, updates the workflow to replace the deprecated `macos-14` image with two versions: `macos-15` (oldest supported) and `macos-26` (latest explicit version). This ensures backward compatibility and cross-version testing while aligning with GitLab CI, which lacks a floating `latest` tag.

The key participants were Junio, who initially favored `macos-latest` for maintainability, and Patrick Steinhardt, who argued for explicit versions (`macos-15` and `macos-26`) to ensure consistency across CI systems. Junio ultimately conceded to Patrick’s preference, reverting to the v2 patch’s approach. The final patch assigns `osx-clang` and `osx-meson` to `macos-15`, and `osx-reftable` and `osx-gcc` to `macos-26`. This resolves the thread’s only open question—versioning—with a trade-off: manual annual updates for explicit versions versus automatic updates for floating tags.

The patch touches only CI infrastructure, with no changes to Git’s codebase or test coverage. It is now finalized and awaits integration into Junio’s branches. The thread’s earlier consensus on splitting jobs between two macOS versions remains intact, ensuring broader compatibility coverage.
