This thread is a routine CI maintenance update to split GitHub Actions macOS runners between `macos-15` and `macos-26`, replacing the deprecated `macos-14` image. Junio C Hamano posted v2 of the patch, implementing Patrick Steinhardt’s proposal to distribute jobs across the two runner versions for broader test coverage. The patch assigns `osx-clang` and `osx-meson` to `macos-15`, and `osx-reftable` and `osx-gcc` to `macos-26` (currently equivalent to `macos-latest`).

The thread had converged on this approach until Todd Zullinger raised a procedural question: whether the two jobs on `macos-26` should instead use the floating `macos-latest` tag to avoid manual updates when GitHub releases new macOS versions. His question is narrowly scoped to those two jobs and does not challenge the job-splitting approach or the use of `macos-15` for the others. No objections or alternative proposals have been raised, and the patch remains unmerged.

The open question is now whether the project prefers explicit version pinning (for stability) or floating tags (for convenience). The answer will likely be a matter of policy rather than technical necessity, as both approaches are functionally valid. The patch itself is otherwise uncontroversial and ready for integration once this detail is resolved.
