This thread is about updating Git’s GitHub Actions CI workflow to replace the deprecated `macos-14` runner with a split between `macos-15` (for backward compatibility) and either `macos-26` or `macos-latest` (for newer releases). Junio C Hamano posted a v3 patch that assigns `osx-clang` and `osx-meson` to `macos-15`, and `osx-reftable` and `osx-gcc` to `macos-latest`, resolving an earlier open question in favor of maintainability.

The discussion has now converged on a practical choice: whether to use explicit macOS versions (`macos-15` and `macos-26`) or a floating tag (`macos-latest`) for the newer jobs. Patrick Steinhardt argues for explicit versions to keep GitHub Actions and GitLab CI in sync, since GitLab lacks a `latest` tag. This would require annual manual updates but ensures consistency between the two CI systems. Junio’s v3 patch opted for `macos-latest` to avoid manual updates, but Patrick’s latest email reopens the question, framing it as a trade-off between maintenance burden and predictable behavior. No technical objections or edge cases have been raised, and the patch remains under review with no integration branch yet queuing it.
