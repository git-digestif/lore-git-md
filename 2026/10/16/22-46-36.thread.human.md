This thread updates Git's GitHub Actions CI configuration to handle GitHub's deprecation of the `macos-14` runner image. Junio C Hamano posted a corrected v5 patch after retracting a mechanically flawed v4 iteration. The patch splits the four macOS CI jobs between two explicit runner versions: `macos-15` (oldest supported) for backward compatibility, and `macos-26` (latest explicit) to align with GitLab CI and enable cross-CI comparisons. The design—agreed earlier in the thread—assigns `osx-clang` and `osx-meson` to `macos-15`, and `osx-reftable` and `osx-gcc` to `macos-26`.

The patch itself is uncontested and touches only `.github/workflows/main.yml`, with no changes to Git's functionality. Earlier discussion settled the versioning debate in favor of explicit versions over floating tags like `macos-latest`, driven by Patrick Steinhardt's preference for predictable behavior across CI systems. Todd Zullinger had argued for `macos-latest` to avoid manual updates, but the thread converged on explicit versions. Brian m. carlson provided context on macOS release cadence but deferred to the group's consensus.

With the mechanical issue resolved, the patch is now ready for Junio to queue. The only remaining uncertainty is whether the new macOS versions will expose platform-specific quirks in the CI jobs, but that would surface during runtime rather than as a patch flaw. The thread is effectively complete.
