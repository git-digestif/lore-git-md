This is a documentation patch, now at v4, that rewrites Git’s explanation of detached HEAD state. The patch is complete and ready for merging after incorporating Junio C Hamano’s final textual refinements. It replaces the existing verbose, diagram-heavy section in `git-checkout.adoc` with a concise, practical explanation and moves it to a new standalone guide (`gitdetached-head(7)`), which can be referenced from Git’s advice messages.

The new text frames detached HEAD as useful for experimentation (e.g., testing old commits, browsing history, or working directly on remote-tracking branches) and removes the word “unintentionally” from accidental-detachment scenarios. It also highlights the 2019 UI improvement in `git switch` that makes accidental detachment harder. The reflog expiry period is specified as 30 days (the default for `gc.reflogExpireUnreachable`), and the advice message in `advice.c` now points to the new guide using `git help detached-head`. The patch touches `Documentation/git-checkout.adoc`, `Documentation/detached-head.adoc` (new), `Documentation/gitdetached-head.adoc` (new man page), `advice.c`, `Documentation/Makefile`, `meson.build`, and `command-list.txt`.

Junio’s latest feedback focused on incremental improvements: fixing a commit message example (“fix bug” instead of “3”), rephrasing “the commit for that tag” to “the tagged commit”, moving explicit `git checkout COMMIT_ID` and `git switch --detach COMMIT_ID` commands into the list of detachment methods to reduce duplication, and adding concrete examples of how detached HEAD can be used (e.g., data science pipelines, bug hunting). The author, Julia Evans, has addressed all feedback and signaled no further revisions, leaving the patch in Junio’s hands for a merge decision. The broader help-system usability concern (internal cross-references vs. `git help`) remains noted as a potential future improvement but is not a blocker.
