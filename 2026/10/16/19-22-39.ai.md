This is the third patch in Justin Tobler’s three-part bugfix series targeting a race condition in Git’s object database (ODB) transaction machinery. The patch moves `.keep` lockfile creation from the quarantine phase to the transaction commit phase, ensuring lockfiles are only written after the transaction is guaranteed to succeed. This change directly addresses the reported bug: concurrent `git-receive-pack` processes can no longer delete each other’s lockfiles, leaving packfiles vulnerable to housekeeping.

The test coverage in `t/t5547-push-quarantine.sh` will be extended to explicitly verify that no corresponding `.pack` file exists alongside the `.keep` file in the concurrent-process scenario, ensuring the test fully captures the race condition’s resolution.

The patch touches `object-file.c` and the test suite, introducing the new `write_pack_locks()` helper to batch-create lockfiles during transaction commit. No on-disk format changes or backwards-compatibility concerns are introduced.
