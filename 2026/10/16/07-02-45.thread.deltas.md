# Thread deltas

## 2026/10/16

- [2026/10/16/07-02-45 by Harald Nordgren via GitGitGadget <gitgitgadget@gmail.com>] Harald Nordgren submitted a patch to make `branch.autoSetupMerge=inherit` use a remote-tracking start point directly as the upstream (as `true` does), so that `git switch -c new_branch origin/main` and similar commands set the remote branch as upstream without a warning.
- [2026/10/16/16-55-05 by Junio C Hamano <gitster@pobox.com>] Junio C Hamano corrected the proposed documentation wording to "A remote-tracking branch given as a starting point" rather than "A remote-tracking starting point".
- [2026/10/16/16-55-05 by Junio C Hamano <gitster@pobox.com>] Junio C Hamano questioned whether the same direct-tracking behavior should apply when the starting point is not a remote-tracking branch, proposing alternative text where the new branch tracks the starting point itself if it has no tracking configuration.
- [2026/10/16/16-55-05 by Junio C Hamano <gitster@pobox.com>] Junio C Hamano said he is not sure users want a new branch forked from a non-tracking starting point to suddenly track that point, noting the original commit d3115660b4 only specified behavior for tracking start points and the previous "do nothing" behavior may be the right thing.
- [2026/10/16/16-55-05 by Junio C Hamano <gitster@pobox.com>] Junio C Hamano suggested that if the behavior change proves undesirable, `inherit` could gain synonyms such as `inherit-or-ignore` (preserving the current behavior), `inherit-or-fail` (die if the starting point has nothing to inherit), and `inherit-or-direct` (use the fallback direct tracking).

## 2026/10/17

- [2026/10/17/09-54-15 by Harald Nordgren <haraldnordgren@gmail.com>] Harald Nordgren stated that tracking should occur only when the starting point is a remote branch.
- [2026/10/17/09-54-15 by Harald Nordgren <haraldnordgren@gmail.com>] Harald Nordgren called Junio C Hamano's suggestion to add `inherit-or-ignore`, `inherit-or-fail`, and `inherit-or-direct` synonyms overkill for the problem, while noting it would be interesting to hear the original author's point of view.

## 2026/10/18

- [2026/10/18/09-59-57 by Phillip Wood <phillip.wood123@gmail.com>] Phillip Wood, responding to whether non-remote-tracking start points should also be tracked directly, said it depends on what he is forking from: branching from a pushed local branch he wants the new branch to track something like origin/master rather than the starting point, while branching from origin/master he does want to track the starting point; he judged the proposed behavior not clearly better than the current one but not worse either, said a way to "set up tracking when the starting point matches one of these patterns" might be useful, and noted he normally just runs `git branch --set-upstream-to` afterwards because the tracking options of `git switch -c` are confusing to him.
- [2026/10/18/15-19-46 by Harald Nordgren <haraldnordgren@gmail.com>] Harald Nordgren proposed going the other way: make the new branch first inherit the upstream of the branch being forked from (so `git checkout -b new_branch origin/another_branch` run while on a first_branch tracking origin/master would give new_branch tracking origin/master), with the v1 behavior of tracking the remote-tracking start point itself as a fallback when the current branch has no upstream, and asked whether that fallback is just bad.
