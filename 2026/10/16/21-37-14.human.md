This is the second patch in Justin Tobler’s four-patch v2 series fixing a race condition in Git’s ODB transaction machinery. The series is part of the ongoing ODB abstraction effort led by Patrick Steinhardt.

This patch lifts the parsing logic for `git-index-pack`’s output out of `index_pack_lockfile()` and exposes it as a new public helper, `read_index_pack_report()`. The helper extracts the packfile name and whether a `.keep` file was created, storing the name in a `strbuf` and setting an `is_keep` flag. The original `index_pack_lockfile()` is refactored to use this helper, making the code more modular and preparing for the later patches that defer `.keep` lockfile creation to the transaction commit phase.

The changes are clean and well-motivated: the new helper consolidates error handling, removes redundant parsing logic, and makes the `is_keep` flag unconditional (addressing Patrick Steinhardt’s feedback from v1). The commit message clearly explains the purpose and the preparatory nature of the patch. No behavior changes are introduced—this is purely refactoring to enable the later fix. The patch looks technically sound and ready for integration.
