This is a CI/build system patch that has just been queued by Junio. The patch itself is a minimal fix from Patrick Steinhardt to address GitLab CI job failures in merge requests with more than 50 commits. The root issue is GitLab's default shallow clone (depth=50), which prevents the "check-whitespace" and "check-style" jobs from accessing the base commit they need to compare against. Patrick's fix—adding `GIT_DEPTH: 0` to force full clones for both jobs—mirrors an existing solution already in place for GitHub CI.

Junio's reply is brief but revealing. He acknowledges the annoyance and notes that while the ideal fix would fetch only the necessary history (the base commit), GitLab doesn't offer that option. More interestingly, he questions the value of these jobs altogether, asking whether disabling them would lead to an influx of poorly formatted patches. This isn't a rejection—Junio explicitly says he'll queue the patch—but it does signal skepticism about the long-term utility of these checks. The implication is that the jobs might be more trouble than they're worth, even if the immediate fix is reasonable.

The patch itself is trivial (three lines added to `.gitlab-ci.yml`) and directly addresses the observed failure. Patrick includes a link to a pipeline run demonstrating the fix, which is a nice touch for reviewers. While the issue rarely affects upstream patches (which tend to be shorter), it does crop up in GitLab's internal development branches, so the fix has practical value for their workflow.

No controversy here—just a small, targeted improvement with a side of philosophical questioning from Junio about whether these checks are even necessary.
