This is a **bugfix** targeting the HTTP transport layer, specifically a regression in `git push` over smart HTTP when using token-only URLs (e.g., `https://<token>@forge.example/repo.git`) after a security change in libcurl 8.23.0.

The issue arises because libcurl now strips credentials from `CURLINFO_EFFECTIVE_URL` (CVE-2026-94266), causing Git to misinterpret a successful 200 response as a redirect. This triggers a rewrite of the base URL to exclude credentials, clearing the `http_auth` struct and leaving the subsequent `POST git-receive-pack` request unauthenticated. The result is a fatal error: `could not read Username for 'https://forge.example'`. Fetch/clone operations remain unaffected because they don’t rely on the same redirect logic.

The report includes a clear reproduction case (empty commit + `GIT_TERMINAL_PROMPT=0 git push`), version details (Git 2.55.0 + libcurl 8.5.0-2ubuntu10.16), and a detailed analysis of the code path in `http.c` (`http_request_reauth()` and `update_url_from_redirect()`). A workaround is provided (using `user:token@` syntax or a credential helper), but the underlying issue is a real regression affecting CI tools like Renovate that rely on token-only URLs.
