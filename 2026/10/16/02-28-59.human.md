This is the first patch in a three-part bugfix series targeting a race condition in Git’s object database (ODB) transaction machinery. The series addresses a real correctness issue where concurrent `git-receive-pack` processes can delete each other’s `.keep` lockfiles, leaving newly written packfiles vulnerable to deletion by housekeeping processes.

This patch lifts and exposes the parsing logic for `git-index-pack`’s output, which reports the hexadecimal name of a newly written packfile and whether a `.keep` file was created alongside it. The existing `index_pack_lockfile()` function is refactored to use the new `read_index_pack_report()` helper, which is now exposed in `pack.h` for reuse in later patches. The change is preparatory: the next patch will use this helper to avoid eagerly creating `.keep` files during quarantine registration, which is the root cause of the race condition.

The patch is clean and well-structured, with a clear commit message explaining the motivation and the mechanical changes. It touches `pack-write.c` and `pack.h`, introducing no behavior changes—just moving code to make it reusable. The new `read_index_pack_report()` function is straightforward and maintains the same error-handling semantics as the original code.

This is a refactoring patch that sets the stage for the actual fix in patch 3. It’s part of the broader ODB abstraction effort led by Patrick Steinhardt, though the series itself is a standalone correctness fix.
