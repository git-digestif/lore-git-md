This is the v7 iteration of a feature patch adding revision-based filtering to the `git repo structure` command. The patch is now procedurally clean and ready for merging to `next`, with no substantive changes from v6—only a one-word commit message fix ("standard the standard" → "the standard") to address the final nit raised by Kristoffer Haugsbakk.

The feature allows users to analyze specific subsets of the repository object graph by specifying revisions (commits, refs, or ranges) to include or exclude, improving diagnostic capabilities for large repositories. For example, `git repo structure --branches --not --tags` will process objects reachable from branches but not from tags. The implementation uses Git’s standard `setup_revisions()` machinery, replacing an earlier enum-based flag system with a design consistent with Git’s revision-parsing idioms. This approach avoids the transitive dependency omission issues of earlier versions and aligns with established patterns in the codebase.

The patch touches three files: `builtin/repo.c` (core implementation), `Documentation/git-repo.adoc` (user-facing documentation), and `t/t1901-repo-structure.sh` (test coverage). The test suite has grown to 197 lines, validating edge cases like overlapping includes/excludes, output formats (table/lines/nul), and empty repository handling. The "empty repository" test, which was accidentally dropped in v4, has been reinstated to ensure predictable behavior. The implementation retains a known inefficiency—a second ref-walk in `count_references()` due to `setup_revisions()`’s lack of a custom ref-walk callback—but this is considered tolerable for a diagnostic tool.

All substantive technical feedback from prior rounds has been addressed. The remaining open questions—revision-parsing defaults (`.def = "HEAD"` and `.revarg_opt = REVARG_COMMITTISH`), test coverage gaps (e.g., filtering by trees/blobs), and the double ref-walk inefficiency—are now explicitly accepted as non-blocking.
