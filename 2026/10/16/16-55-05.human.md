This is a **review feedback** email from Junio C Hamano on Harald Nordgren’s bugfix patch for `branch.autoSetupMerge=inherit`. The patch aims to make `inherit` behave like the default (`true`) when the starting point is a remote-tracking branch (e.g., `origin/main`), but Junio raises a broader question about the intended behavior when the starting point *isn’t* tracking anything.

Junio’s feedback is **substantive**: he points out that the documentation wording is ambiguous ("remote-tracking starting point" should be "remote-tracking branch given as a starting point") and, more importantly, questions whether the patch’s logic is too narrow. He suggests that if the starting point isn’t a local branch *or* a remote-tracking branch (e.g., a tag or arbitrary commit), the current behavior—doing nothing—might actually be correct, and that the patch’s change could introduce unintended tracking in cases where users don’t expect it.

He references the original commit (d3115660b4) that introduced `inherit` in 2021, noting it only specified behavior for starting points *with* tracking configurations, leaving the "no tracking" case undefined. Junio floats the idea of adding new config values (`inherit-or-fail`, `inherit-or-direct`) to clarify intent, though this would expand the scope of the fix.

The email doesn’t reject the patch outright but signals that the current approach may need rethinking. No other reviews have been posted yet, so the discussion is still open. If the author (or others) can justify why tracking *should* be set up for non-branch starting points, the patch might proceed; otherwise, it could require a more nuanced solution. For now, this is a **design-level concern** rather than a nitpick.
