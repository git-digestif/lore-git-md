This is a bugfix for the sideband subsystem. The patch addresses an infinite warning loop that occurs when Git encounters an unrecognized keyword in the `sideband.allowControlCharacters` configuration. The issue was introduced in March 2026 (commit 128914438a) and affects every fetch, push, clone, or ls-remote operation when the config contains a typo, extra space, or version-incompatible keyword.

The fix is straightforward: instead of repeatedly warning about the same unrecognized keyword, the parser now skips past it and continues processing the rest of the list. The warning message is also made more precise by showing only the problematic keyword rather than the entire remaining string. The patch includes a new test case that verifies the fix works for both the warning path and the actual control-character filtering.

The commit message is clear and well-motivated, and the code change is minimal and focused. The test coverage is thorough, adding a new scenario that exercises both the warning and the functional behavior. This looks like a solid, uncontroversial fix for a real annoyance.
