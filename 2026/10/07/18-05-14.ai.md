The flag is checked in `run_transaction_hook()` to suppress hook invocations for nested transactions, ensuring hooks only see the outer logical update (e.g., the rename itself, not the backend’s internal steps like packed-refs updates). The change is minimal—just six lines—but critical for the series’ architecture, as later patches will use this flag to avoid duplicate hook events during copy/rename operations. No public API is exposed, and the flag is explicitly documented as internal-only. The patch is a refactoring prerequisite with no behavior change on its own, but it lays the groundwork for the unified reflog replacement logic in subsequent patches.
