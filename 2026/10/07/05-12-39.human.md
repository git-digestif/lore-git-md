This is a brief follow-up in the review of Karthik Nayak’s performance patch for the packed-refs backend. The patch, now in its fourth iteration, aims to speed up packed-refs file rewrites by writing unchanged refs as raw bytes instead of reformatting them with `fprintf()`.

Patrick Steinhardt clarifies a documentation nit in the `record_start` field comment. The current wording ("set when advancing `pos`") could be misread as implying `record_start` is always updated whenever `pos` moves, which isn’t true—`pos` sometimes advances independently. This is a surface-level issue, not a technical flaw, and Karthik has already agreed to reword the comment in the next version. The exchange doesn’t challenge the patch’s core approach or performance claims, and the discussion remains constructive and focused on clarity. The patch is still under review, with no maintainer decision yet.
