## 2026/10/07

- [2026/10/07/13-21-11 by Daniel Gullberg <daniel.gullberg@mmm.com>] Daniel Gullberg reported that on Windows, an unreachable UNC path in safe.directory (e.g., '//192.168.1.190/dummy-test/repo.git') causes git commands in a repo failing the ownership check to stall ~25 s on first run (29 s total vs ~2 s without the entry), impacting tools like TortoiseGit, and reproduced it with Git for Windows 2.56.0.windows.2 and 2.46.1.windows.1.
- [2026/10/07/13-21-11 by Daniel Gullberg <daniel.gullberg@mmm.com>] He provided GIT_TRACE2_PERF output showing ~26 s spent before worktree setup with no git work in between, and noted a plain PowerShell Test-Path to the dead host also takes ~25 s, attributing the wait to the Windows network connect timeout.
- [2026/10/07/13-21-11 by Daniel Gullberg <daniel.gullberg@mmm.com>] He hypothesized (not verified in source) that safe.directory values are normalized to real paths when checked, causing Windows to contact the unreachable host, and suggested comparing the entry against the repository path first and only resolving entries that could match.
