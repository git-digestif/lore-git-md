This is the second patch in Phillip Wood’s two-patch refactoring series targeting redundant change-detection logic in `git stash push` and `git stash create`. The series aims to consolidate duplicate `check_changes()` calls into a single call for cleaner code, with no intended behavior change. This patch removes the redundant `check_changes()` call in `do_push_stash()` and adjusts the return-value convention of `do_create_stash()` so that 2 now signals "no changes to stash" (previously conflated with 1, which continues to mean "nothing was stashed").

Junio C Hamano’s review identified a new inefficiency: after the patch, `do_push_stash()` calls `repo_refresh_and_write_index()` unconditionally, then invokes `do_create_stash()`, which refreshes the index again. This results in a redundant double refresh during `git stash push`. Phillip acknowledges the issue and agrees to add a follow-up patch to avoid the unnecessary refresh. The discussion also touches on introducing symbolic constants for the return values, now that there are three distinct outcomes.

The patch itself is a straightforward cleanup, touching only `builtin/stash.c` and modifying `do_create_stash()` and `do_push_stash()`. No new functions or options are introduced, and there are no on-disk format changes or test coverage updates. The series is under review, with Junio’s feedback addressing both commit message typos (in the first patch) and this technical inefficiency. Phillip’s response suggests the series will likely proceed with a minor follow-up to address the double refresh.
