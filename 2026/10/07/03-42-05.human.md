This is a bugfix patch targeting test infrastructure. A new contributor, Muhammed Dilshad A, plugs two memory leaks in the `sort_stdin()` helper inside `test-mergesort.c`: the function allocates a memory pool and a `strbuf` but never frees them. The patch adds the missing cleanup calls (`mem_pool_discard` and `strbuf_release`) after the sorted lines are printed.

To catch such leaks in the future, the patch also extends the test coverage in `t/t0071-sort.sh` by adding a new test case that exercises the `sort` subcommand. Previously, the test suite only ran the `test` subcommand, so these leaks went unnoticed even in leak-sanitized runs.

The change is small and self-contained: two lines of cleanup in the C helper and seven lines of new test code. The commit message clearly explains the problem and the fix. This looks like a well-scoped, well-motivated contribution that addresses a real issue without introducing complexity. Worth a quick review for anyone familiar with the test helpers.
