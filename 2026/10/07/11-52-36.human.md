This is a performance optimization patch for the packed-refs backend, now at its fifth iteration (v5). The patch speeds up operations that rewrite the packed-refs file—such as deleting references—by avoiding redundant formatting of unchanged refs. Instead of using `fprintf()` for every entry, it tracks the raw byte positions of unchanged refs and writes them directly with `fwrite()`, preserving original formatting like case, whitespace, and even malformed refnames. The change is confined to `refs/packed-backend.c` and introduces a `record_start` field in `struct packed_ref_iterator` to mark the start of each ref record.

The patch has evolved through several rounds of review, with v4 addressing Patrick Steinhardt’s feedback on commit message clarity, `record_start` documentation, and wrapper inlining. The final tweak in v5—clarifying that `record_start` is updated only when a new record begins, not on every position advancement—resolves the last ambiguity. The performance improvement is consistent: deleting 100,000 packed refs now takes ~23.8 ms, down from ~28.7 ms (~20% faster), a gain Patrick describes as "significant."

The implementation is clean and well-documented, with side effects (like preserving original formatting) explicitly noted in the commit message. Toon Claes’s substantive review in earlier versions surfaced concerns about correctness and structure, which were fully addressed by splitting the write logic into separate functions and documenting the trade-offs. Junio C Hamano’s only feedback—a terminology nit ("sanitization" over "sanitation")—was adopted in v3, and he hasn’t weighed in on the technical merits since.

This patch looks ready for maintainer pickup. It’s narrowly scoped, thoroughly reviewed, and delivers a measurable speedup without breaking backward compatibility. The only lingering question is whether the subtle formatting changes (e.g., uppercase OIDs, tabs) might affect tools parsing packed-refs files, but no specific compatibility issues have been raised, and the documentation should mitigate any surprises. If you care about packed-refs performance, this is worth watching.
