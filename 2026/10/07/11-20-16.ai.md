This is a performance optimization patch targeting the packed-refs backend, now at v4. The patch speeds up operations that rewrite the packed-refs file (such as deleting references) by avoiding redundant formatting of unchanged refs. Instead of using `fprintf()` for every entry, it tracks the raw byte positions of unchanged refs in the snapshot iterator and writes them directly with `fwrite()`. This change is confined to `refs/packed-backend.c` and introduces a `record_start` field in `struct packed_ref_iterator` to mark the start of each ref record.

The patch addresses feedback from v3, which included clarifying the commit message, improving the `record_start` documentation to remove ambiguity about when it is updated, and inlining the `fwrite()` call instead of using a separate `write_packed_entry_raw()` function. The performance improvement is consistent and measurable: deleting 100,000 packed refs now takes ~23.8 ms, down from ~28.7 ms (~20% faster). The benchmark is well-documented and reproducible.

The implementation is clean and focused, touching only the necessary code paths. The patch preserves the on-disk format but may introduce subtle formatting differences (e.g., case, whitespace, malformed refnames) due to bypassing `fprintf()` sanitization. These side effects are explicitly documented in the commit message, and the patch does not introduce new dependencies or platform-specific code. The risk of regression appears low given the narrow scope.

Key technical details for follow-up discussion include the `record_start` field in `struct packed_ref_iterator`, the direct use of `fwrite()` for unchanged refs, and the performance benchmark demonstrating the improvement. The patch is part of the packed-refs subsystem, actively maintained by Karthik Nayak and Patrick Steinhardt, and has received substantive review from both Toon Claes and Patrick Steinhardt. Junio C Hamano’s feedback was limited to a terminology nit, which was addressed in v3.

The patch is ready for maintainer pickup and appears uncontroversial. The only open question is whether the subtle formatting changes could affect tools parsing packed-refs files (e.g., JGit, libgit2), though no specific compatibility issues have been raised. The documentation in the commit message should mitigate this concern.
