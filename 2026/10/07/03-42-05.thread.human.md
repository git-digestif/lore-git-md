This thread is about cleaning up and modernizing the test infrastructure for Git’s mergesort functionality. Muhammed Dilshad A sent a four-patch series (v3) that migrates the mergesort tests from the shell-based test suite to the Clar unit-test framework, removes unused subcommands (`generate` and `test`), retires an obsolete performance benchmark (`p0071-sort.sh`), and deletes the `test-mergesort.c` helper. The goal is to reduce code size (a net 307 lines removed), maintain test coverage, and adopt a more maintainable test design.

The series is under review and is effectively complete. Junio C Hamano and Patrick Steinhardt have both endorsed the cleanup direction. All prior feedback has been addressed: the leak-fix patch was dropped, the Clar migration was split into focused commits, and the test design was simplified by replacing a 1,680-case grid with direct tests for key scenarios (sorted, reversed, equal-value, and repeatable random inputs). The final patch (4/4) removes the obsolete benchmark and helper, completing the series. Junio’s latest feedback was purely stylistic—a request to reword the commit message in patch 1/4 to clarify the rationale—and the author has agreed to make this change. No technical or design questions remain unresolved.

The series touches test infrastructure files (`t/unit-tests/u-mergesort.c`, `t/helper/test-mergesort.c`, `t/perf/p0071-sort.sh`, and build-system updates) and introduces no user-facing changes. Test coverage is preserved and enhanced with new edge cases (empty lists, single-item lists, reversed and equal pairs, small lists with duplicates, and debug hook behavior). The cleanup is part of an ongoing effort to adopt the Clar unit-test framework, championed by Patrick Steinhardt. With the author’s response to Junio’s feedback, the series is on track for acceptance.
