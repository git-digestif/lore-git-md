This is a review reply in the `pw/stash-optimize-check_changes-calls/v1` refactoring series. The thread is focused on eliminating redundant `check_changes()` calls in `git stash push` and `git stash create`, but Junio C Hamano’s review of the second patch has surfaced a new inefficiency: the patch now causes `git stash push` to refresh the index twice in the common case where there *are* changes to stash.

Junio’s reply is substantive. He confirms Phillip Wood’s observation that the double refresh is a regression for the “nothing to stash” case (previously only one refresh, now two) and agrees with Phillip’s proposed follow-up direction: make callers of `do_create_stash()` responsible for refreshing the index. This would eliminate both the double refresh and redundant `preload_index()` calls. The exchange is brief and constructive, with no disagreement on the technical direction—just a shared recognition that the current patch, while correct, is not yet optimal.

The series remains under review; this is still the first iteration (`v1`). No other reviewers have weighed in on the inefficiency, and no test failures or edge cases have been raised. The next step is likely a follow-up patch from Phillip to address the index-refresh issue.
