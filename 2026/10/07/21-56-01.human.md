This is the first patch in Harald Nordgren’s v7 series introducing a "matching-inspired" fetch mode for shallow repositories. It adds the `remote.<name>.refmap` configuration variable, which provides the default value for the `--refmap` option in `git fetch`, mirroring how `remote.<name>.fetch` supplies default refspecs.

The patch is well-structured and clearly motivated. It extends the `struct remote` to include a `refmap` field, parses the new configuration key in `remote.c`, and updates `builtin/fetch.c` to use the configured refmap when no explicit `--refmap` is given. The documentation is thorough, explaining the purpose and behavior of the new setting, and the tests cover both the basic functionality and edge cases—such as the precedence rule where `remote.<name>.fetch` takes precedence when both it and `remote.<name>.refmap` are configured.

The implementation is clean and follows established patterns in the codebase. The commit message is clear, and the code changes are minimal and focused. The test coverage is particularly strong, verifying that the refmap behaves as expected when used alone, in combination with fetch refspecs, and when no branches are tracked. This patch is a solid foundation for the rest of the series and addresses the core design requirement of separating namespace mapping from fetch selection logic. It looks ready for integration once the remaining design decision about precedence is settled.
