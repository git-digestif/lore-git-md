This is the second patch in a two-patch performance optimization series targeting the commit-graph subsystem. It implements the core logic for an incremental write strategy in `git fetch` when `fetch.writeCommitGraph` is enabled, avoiding the current full reachable scan after every fetch.

The patch introduces a three-mode enum (`GRAPH_WRITE_REACHABLE`, `GRAPH_WRITE_TIPS`, `GRAPH_WRITE_SKIP`) to control the commit-graph write policy. After each fetch, Git checks whether a commit-graph exists: if not, it falls back to the full reachable scan; if the fetch updated at least one ref, it writes incrementally using only the new refs as seeds; if the fetch was a no-op, it skips the write entirely. Multi-remote fetches (e.g., `git fetch --all`) still use the full scan, as propagating the set of updated refs across process boundaries would complicate the implementation.

The changes touch `builtin/fetch.c` (adding the new logic and an `oidset` to track updated refs), `commit-graph.c`/`commit-graph.h` (exposing `prepare_commit_graph()` for fetch to check graph existence), and the test suite (adding coverage for incremental writes, no-op fetches, fallback cases, and shallow ref handling). The patch relies on the commit-graph write being additive (split mode), which fetch already uses, ensuring incremental updates extend rather than replace existing coverage.

Performance gains are substantial: in a synthetic benchmark (git.git with 200K packed refs), incremental writes reduce `fetch/write-commit-graph` time from ~357ms to ~9.3ms for a single ref update, and no-op fetches are skipped entirely. The implementation handles edge cases like shallow-rejected refs and ensures no coverage loss after incremental writes. All prior technical feedback has been addressed, and this version incorporates only surface-level improvements (commit message clarity, test script style, and the test helper added in patch 1).

This is a well-scoped, uncontroversial optimization that should benefit large repositories without introducing regressions. The series appears ready for final review, with no open technical questions.
