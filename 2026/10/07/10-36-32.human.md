This is a substantive review reply in the ongoing RFC thread about adding porcelain commands to share Git stashes through remotes. Johannes Sixt (Hannes) directly counters Hanan Arshad’s workflow justification by demonstrating how the same goal—applying temporary configurations across multiple branches—can be achieved using existing Git commands without introducing new porcelain. His example shows that a single branch can serve as a transport mechanism for the configuration, which is then applied once via `git show` and `git apply -3`, after which the local stash can handle further transfers. Hannes’s position remains firm: the existing workflow is sufficient, and the proposed feature is unnecessary. This reply reinforces the philosophical objection that stashes are inherently personal and ephemeral, while branches already provide a robust, well-understood solution for shareable work. The thread’s outcome now hinges on whether Hanan can provide a compelling counterexample that the existing workflow is genuinely cumbersome or error-prone for the Perforce-shelf-like use case.
