Key technical details
No new technical changes or revisions to the merged patch. The discussion continues to reference:
- Julia Evans’s March 2024 user research, which revealed that even experienced Git users often operate with imprecise mental models (e.g., confusion around HEAD, detached HEAD, and the distinction between HEAD and lowercase "head"). The research informed her phrasing choices in the merged patch, prioritizing alignment with user language over technical precision.
- Julia’s clarification that the "wrong" user quotes came from experienced users, not novices, underscoring that imprecise mental models are widespread even among proficient practitioners. The XKCD comic (2501) is cited as a humorous but apt illustration of the broader challenge.
- Junio’s latest feedback on phrasing, which distinguishes between `HEAD` *recording* a reference (branch or commit) and *being* a branch or commit. His proposed rewrite describes `HEAD`’s role in terms of direct vs. indirect references to commits, structured as:
  - `HEAD` records the name of the current branch (e.g., `main`), which in turn refers to a commit. New commits advance the branch, and `HEAD` indirectly refers to the new commit.
  - `HEAD` can also record a commit object name (e.g., `abc123`). New commits are created without advancing a branch, and `HEAD` directly refers to the new commit.
- Julia’s counterproposal: "HEAD is where Git stores the name of your current branch. For example, `.git/HEAD` might contain `ref: refs/heads/main` (meaning you’re on the `main` branch) or `abc123` (meaning you’re in detached HEAD state)." She dismisses `git symbolic-ref HEAD` as overly technical and rejects "records" as Git-specific jargon with no clear meaning outside the project. Her phrasing avoids implementation details that may become outdated with the reftable backend.
- Julia’s earlier proposed rewrite: "HEAD always refers to the current commit. Usually, it does this by pointing to a branch name (like `main`), which in turn points to a commit. But in detached HEAD state, HEAD points directly to a commit (like `abc123`)."
- The persistent difference in assumptions between Julia and Junio about documentation goals: Julia advocates for meeting users where they are, while Junio probes whether Git’s documentation should aim to educate users toward more accurate terminology. The thread frames this as a recurring challenge but does not resolve it.
