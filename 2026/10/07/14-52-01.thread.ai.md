Thread identity
Subject: [PATCH v3] doc: rewrite explanation of detached HEAD state
Series version: standalone patch, v3 (final polish, now complete)
Originating author: Julia Evans
Thread type: documentation improvement

Core problem or goal
Improve the clarity and usefulness of Git’s documentation for detached HEAD state by addressing four specific shortcomings: (1) the current text does not explain *why* detached HEAD is useful, (2) it takes too long to define the concept, (3) it does not clarify how users might end up in this state accidentally, and (4) it includes overly complex diagrams. The patch replaces the existing section in `git-checkout.adoc` with a concise, practical explanation and moves it to a new standalone guide (`gitdetached-head(7)`) that can be referenced from Git’s advice messages. Additionally, the thread has surfaced a broader usability concern about Git’s help system: the inconsistency between internal man page cross-references (e.g., `git-config(1)`) and the recommended `git help` command, which may confuse users who are unaware of the mapping.

Current status
Merging-ready; v3 is now complete after incorporating Junio C Hamano’s final textual refinements. All prior feedback from Junio, Kristoffer Haugsbakk, and Marie Claire LeBlanc Flanagan has been fully addressed: (1) the HEAD definition now emphasizes it records the starting point for current changes, whether a branch or a commit, and clarifies that changes made while on a branch grow that branch, whereas changes in detached HEAD are temporary and do not affect any branch; (2) the explanation of detached HEAD’s advantages is strengthened with concrete examples from programming, writing, game design, and data science, using the verb “check out” and the term “project” to broaden scope; (3) the list of ways to enter detached HEAD now includes explicit `git checkout <COMMIT>` and `git switch --detach <COMMIT>` commands alongside tag and remote-tracking branch checkouts; (4) phrasing in the warning output is improved (e.g., “the tagged commit” instead of “the commit for that tag”); (5) the help command in advice messages and documentation uses `git help detached-head` (hyphenated); (6) Marie Claire LeBlanc Flanagan’s sign-off is present; (7) the reflog expiry period is specified as 30 days (the default for `gc.reflogExpireUnreachable`); (8) whitespace alignment in `command-list.txt` is fixed; and (9) build system files (`meson.build`, `Makefile`) are updated. The patch remains self-contained and does not depend on other in-flight work. The broader help-system usability concern (internal cross-references vs. `git help`) remains noted as a potential future improvement but is not a blocker.

Key technical details
- Files touched: `Documentation/git-checkout.adoc`, `Documentation/detached-head.adoc` (new), `Documentation/gitdetached-head.txt` (new man page), `advice.c` (update advice message to reference `git help detached-head`), `Documentation/Makefile`, `meson.build`, `command-list.txt` (whitespace alignment fix).
- New symbols: `gitdetached-head(7)` man page (hyphenated per existing guide conventions).
- Behavior change: advice messages about detached HEAD now point to the new standalone guide using `git help detached-head` (hyphenated). The new text frames detached HEAD as advantageous for experimentation (e.g., testing commits, browsing history, or working directly on remote-tracking branches) and removes the word “unintentionally” from accidental-detachment scenarios. It also highlights the 2019 UI improvement in `git switch` that makes accidental detachment harder. The reflog expiry period is specified as 30 days (default for `gc.reflogExpireUnreachable`).
- On-disk format: no changes.
- Test coverage: none added; this is documentation-only.
- Help-system usability: internal man page cross-references (e.g., `git-config(1)`) do not align with the recommended `git help config` command, which may confuse users. The `git-help` man page does not explain how to map these references to `git help` commands. Julia Evans plans to add a cross-reference to `git help datamodel` for deeper context in this version.
