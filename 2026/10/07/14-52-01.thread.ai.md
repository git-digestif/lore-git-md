Subject: [PATCH] doc: rewrite explanation of detached HEAD state
Series version: standalone patch (no series)
Originating author: Julia Evans
Thread type: documentation improvement

Core problem or goal
Improve the clarity and usefulness of Git’s documentation for detached HEAD state by addressing four specific shortcomings: (1) the current text does not explain *why* detached HEAD is useful, (2) it takes too long to define the concept, (3) it does not clarify how users might end up in this state accidentally, and (4) it includes overly complex diagrams. The patch replaces the existing section in `git-checkout.adoc` with a concise, practical explanation and moves it to a new standalone guide (`gitdetachedhead(7)`) that can be referenced from Git’s advice messages.

Current status
Under review; no prior versions. The patch is self-contained and does not depend on other in-flight work. Junio C Hamano and Kristoffer Haugsbakk have provided substantive feedback, focusing on rewording the opening definition of HEAD, clarifying the advantages of detached HEAD for experimentation, adding a concrete recovery example (quoting the exact warning message Git emits when commits are left behind), and addressing build-system omissions (missing meson/Makefile changes to generate the new man page). No objections to the standalone man page or the advice-message pointer change; the discussion remains documentation-only.

Key technical details
- Files touched: `Documentation/git-checkout.adoc`, `Documentation/detached-head.adoc` (new), `Documentation/gitdetachedhead.txt` (new man page), `advice.c` (update advice message to reference the new guide), `Documentation/Makefile` and `meson.build` (to be added for man page generation).
- New symbols: `gitdetachedhead(7)` man page (hyphenation in name remains unresolved; Haugsbakk suggests `gitdetached-head(7)` for consistency with existing guides like `git-data-model(7)`, but the patch currently uses the unhyphenated form).
- Behavior change: advice messages about detached HEAD now point to the new standalone guide instead of the `git-checkout` man page.
- On-disk format: no changes.
- Test coverage: none added; this is documentation-only.

Open questions and loose ends
- Rewording the opening definition of HEAD to avoid circular phrasing and clarify that HEAD always points to a commit (not a branch), with branches as an additional layer of indirection.
- Framing detached HEAD as advantageous for experimentation (e.g., testing commits, browsing history, or working directly on remote-tracking branches) rather than as a "problem."
- Using "unknowingly" vs. "unintentionally" for the tag/checkout case (minor wording preference).
- Adding a concrete recovery example (quoting the exact warning message Git emits when commits are left behind).
- Whether to relocate diagrams from `git-checkout(1)` to `gitdetachedhead(7)` if they are missed.
- Build-system omissions: missing meson/Makefile changes to generate the new man page (critical for integration).
- Hyphenation of the man page name (`gitdetachedhead(7)` vs. `gitdetached-head(7)`).

Participant positions
- Julia Evans (author): proposes the rewrite as a user-centric improvement, citing clarity and accessibility as primary goals. The new text frames detached HEAD commits as "garbage" (borrowed from Steve Klabnik’s Jujutsu tutorial) to explain why they might disappear, and highlights the UI improvement in `git switch` that makes accidental detachment less likely.
- Junio C Hamano (maintainer): provides substantive review focused on precision and usability. Suggests rewording for clarity, emphasizes the advantages of detached HEAD, and requests a concrete recovery example. Neutral on structural changes (standalone man page, diagram relocation) but does not oppose them. No objections to the advice-message pointer change. Review is medium-weight (engages with text and structure, not just style).
- Kristoffer Haugsbakk: substantive review identifying build-system omissions (meson/Makefile changes) and proposing textual refinements. Argues the current HEAD definition ("`HEAD` is where Git stores your current branch") could mislead users into thinking HEAD is empty when no branch exists, and suggests an alternative framing emphasizing HEAD always points to a commit. Advocates for earlier mention of `git reflog` to reassure users about "garbage" commits and for replacing "main ways" with "typical ways" in accidental detachment scenarios. Praises the tag/checkout explanation but suggests `git log` as a more intuitive recovery tool than `git reflog`. Feedback is constructive and technically grounded, with no objections to the patch’s core goals.
