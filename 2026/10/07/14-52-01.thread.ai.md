Current status
The v4 patch was merged to `master` on 2024-07-10, including a follow-up bugfix for test breakage. The v5 patch is a follow-up that incorporates final phrasing feedback, refining the explanation of `HEAD` to state that it always refers to the current commit, then clarifying that it stores either a branch name (indirectly pointing to a commit) or a commit ID (detached HEAD). This framing avoids anthropomorphism and aligns with Junio’s preference for technical precision while still prioritizing user accessibility. The patch also adds a note about the benefits of detaching HEAD (e.g., avoiding temporary branches) and tweaks the wording around how `HEAD` is stored internally ("branch name" instead of just "branch"). The implementation remains unchanged: the new content lives in `detached-head.adoc`, included by both `git-checkout.adoc` and the new `gitdetached-head(7)` man page, with updates to `advice.c` to reference the standalone guide. Junio’s latest review raises two surface-level style nits: (1) rephrasing a sentence in `detached-head.adoc` to clarify that `HEAD` *stores* a reference (either a branch name or commit object name) rather than *being stored as* one, and (2) correcting the use of a backtick (`` ` ``) to quote a command in `advice.c` to match the file’s existing style of either unquoted commands or single quotes (`'`). Neither point affects the substance of the documentation or its accuracy, and the patch remains ready for merging as-is.
