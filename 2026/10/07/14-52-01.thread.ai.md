Subject: [PATCH] doc: rewrite explanation of detached HEAD state
Series version: standalone patch (no series)
Originating author: Julia Evans
Thread type: documentation improvement

Core problem or goal
Improve the clarity and usefulness of Git’s documentation for detached HEAD state by addressing four specific shortcomings: (1) the current text does not explain *why* detached HEAD is useful, (2) it takes too long to define the concept, (3) it does not clarify how users might end up in this state accidentally, and (4) it includes overly complex diagrams. The patch replaces the existing section in `git-checkout.adoc` with a concise, practical explanation and moves it to a new standalone guide (`gitdetachedhead(7)`) that can be referenced from Git’s advice messages.

Current status
Under review; no prior versions. The patch is self-contained and does not depend on other in-flight work. Junio C Hamano has provided line-by-line feedback on the proposed text, focusing on rewording the opening definition of HEAD, clarifying the advantages of detached HEAD for experimentation, and adding a concrete recovery example (quoting the exact warning message Git emits when commits are left behind). No objections to the standalone man page or the advice-message pointer change; the discussion remains documentation-only.

Key technical details
- Files touched: `Documentation/git-checkout.adoc`, `Documentation/detached-head.adoc` (new), `Documentation/gitdetachedhead.txt` (new man page), `advice.c` (update advice message to reference the new guide).
- New symbols: `gitdetachedhead(7)` man page.
- Behavior change: advice messages about detached HEAD now point to the new standalone guide instead of the `git-checkout` man page.
- On-disk format: no changes.
- Test coverage: none added; this is documentation-only.

Open questions and loose ends
- Rewording the opening definition of HEAD to avoid circular phrasing.
- Framing detached HEAD as advantageous for experimentation rather than as a "problem."
- Using "unknowingly" instead of "unintentionally" for the tag/checkout case.
- Adding a concrete recovery example (quoting the exact warning message Git emits when commits are left behind).
- Potential relocation of diagrams from `git-checkout(1)` to `gitdetachedhead(7)` if they are missed.

Participant positions

The new text frames detached HEAD commits as "garbage" (a concept borrowed from Steve Klabnik’s Jujutsu tutorial) to explain why they might disappear, and highlights the UI improvement in `git switch` that makes accidental detachment less likely.
