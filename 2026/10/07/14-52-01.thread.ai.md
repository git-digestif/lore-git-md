Subject: [PATCH] doc: rewrite explanation of detached HEAD state
Series version: standalone patch (no series)
Originating author: Julia Evans
Thread type: documentation improvement

Core problem or goal
Improve the clarity and usefulness of Git’s documentation for detached HEAD state by addressing four specific shortcomings: (1) the current text does not explain *why* detached HEAD is useful, (2) it takes too long to define the concept, (3) it does not clarify how users might end up in this state accidentally, and (4) it includes overly complex diagrams. The patch replaces the existing section in `git-checkout.adoc` with a concise, practical explanation and moves it to a new standalone guide (`gitdetached-head(7)`) that can be referenced from Git’s advice messages. Additionally, the thread has surfaced a broader usability concern about Git’s help system: the inconsistency between internal man page cross-references (e.g., `git-config(1)`) and the recommended `git help` command, which may confuse users who are unaware of the mapping.

Current status
Under review; no prior versions. The patch is self-contained and does not depend on other in-flight work. Junio C Hamano and Kristoffer Haugsbakk have provided substantive feedback, which Julia Evans has addressed in this iteration with style refinements and planned additions. Key issues resolved include rewording the opening definition of HEAD to avoid circular phrasing, framing detached HEAD as advantageous for experimentation, and committing to add a concrete recovery example. Build-system omissions (meson/Makefile changes) remain unaddressed in this reply but are acknowledged as critical for integration. The broader help-system usability concern (internal cross-references vs. `git help`) is noted as a potential future improvement but is not a blocker for this patch.
