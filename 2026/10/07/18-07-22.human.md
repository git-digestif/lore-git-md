This is the latest update in the thread about making `git blame` automatically use a `.git-blame-ignore-revs` file. The author, Ravi Mistry, clarifies that he misunderstood Junio C Hamano’s earlier feedback: he thought the security audit of the ignore-file parser was being delegated to him, but Junio’s intent was to involve the broader community. Ravi now plans to submit a v2 patch that tightens the parser’s handling of NUL bytes and promisor fetches, which should attract review from security-interested contributors.

The thread remains in the design phase, with no new technical objections or changes. The v2 patch will implement the agreed design (using `HEAD:.git-blame-ignore-revs` instead of the working tree file) and include the proposed security refinements. Once submitted, the patch will need broader community review to assess whether the security improvements are sufficient. The backwards-compatibility question about untracked ignore files remains unaddressed, but the current focus is on landing the core feature with secure defaults.
