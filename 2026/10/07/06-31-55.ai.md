This is a follow-up in the ongoing RFC thread proposing porcelain wrappers to share Git stashes through remotes. The author, Hanan Arshad, responds to Junio C Hamano’s decisive opposition by clarifying the original motivation: a Perforce-shelf-like workflow for temporary, independent overlays (e.g., build configurations) that should not become part of the project’s permanent history. The key distinction is that branches introduce a new line of history that must be merged, rebased, or cherry-picked when the underlying code changes, whereas the proposed stash-sharing porcelain would allow testers to apply and discard temporary configurations without altering the branch structure. Hanan acknowledges that Git already supports the underlying functionality (pushing stashes as refs) but argues that the current UX—requiring users to manually compose `git ls-remote`, `git fetch`, and `git stash import`—is incoherent for this niche use case. The response does not propose new technical changes but attempts to reframe the philosophical objection by grounding the feature in a concrete workflow rather than hypothetical scenarios. The thread’s outcome now hinges on whether this use case resonates with Junio or other participants as a sufficient justification for porcelain-level convenience.
