This is a performance optimization patch for the packed-refs backend, now at version 4. The patch speeds up operations that rewrite the packed-refs file (like deleting references) by avoiding redundant formatting of unchanged refs. Instead of using `fprintf()` for every entry, it tracks the raw byte positions of unchanged refs and writes them directly with `fwrite()`, delivering a consistent ~20% speedup in benchmarks.

The change is narrowly scoped to `refs/packed-backend.c` and introduces a `record_start` field in `struct packed_ref_iterator` to track the start of each ref record. The `write_packed_entry()` function is updated to handle raw writes when possible, bypassing the formatting step. The patch is well-motivated, with clear performance measurements showing a reduction from ~28.7 ms to ~23.8 ms when deleting 100,000 packed refs.

This version (v4) addresses feedback from Patrick Steinhardt on commit message clarity, the `record_start` documentation, and the removal of an unnecessary wrapper function. The `record_start` comment now clearly states it tracks the start of the current record and is updated only when a new record begins. The patch also inlines the `fwrite()` call, simplifying the code.

The optimization is uncontroversial and preserves backward compatibility, though it does lose some incidental sanitization (like case normalization) that was a side effect of the old formatting. This is documented in the commit message, and no compatibility issues have been raised. The patch is part of the packed-refs subsystem, actively maintained by Karthik Nayak and Patrick Steinhardt, and looks ready for integration. Junio has not yet queued it, but the technical feedback has been addressed.
