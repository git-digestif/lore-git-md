This is the **final patch in a 4-patch bugfix series** that completes the overhaul of how Git handles branch rename (`git branch -m`) and copy (`git branch -c`) operations in the ref backend. The series fixes a long-standing issue where the `reference-transaction` hook only reported the deletion of the old branch name, not the creation of the new one, leaving hooks unaware of the full transaction.

This patch **removes the now-unused backend-specific copy and rename callbacks** from the files, reftable, packed, and debug backends. The heavy lifting was done in earlier patches: patch 3/4 integrated copy/rename into the generic transaction API, and this patch simply deletes the old code paths. The diff is large (656 lines removed) but purely mechanical -- no new logic is introduced, just cleanup of dead code.

The series has already addressed Patrick Steinhardt’s earlier blocking objections by switching to per-ref-update state and centralizing hook suppression. Performance regressions are acknowledged (~137% slowdown for files-based rename with large reflogs, ~20-25% for reftable) but deemed acceptable given the correctness fix. The patch is **ready for review** and touches only ref backend internals (`refs.c`, `refs/files-backend.c`, `refs/reftable-backend.c`). If reviews confirm the architectural improvements, this series is likely to advance to `next`.
