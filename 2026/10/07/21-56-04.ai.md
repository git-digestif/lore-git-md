This is the fourth and final patch in Harald Nordgren’s v7 series introducing a "matching-inspired" fetch mode for shallow repositories. It makes `--limited-fetch` the default when adding a remote to a shallow repository, ensuring that `git remote add` does not set up a wildcard refspec that would cause `git fetch` to negotiate history for every branch on the remote.

The patch touches `builtin/remote.c` to check whether the repository is shallow (using `is_repository_shallow()`) and, if so, defaults the `limited_fetch` flag to `1` unless `--no-limited-fetch` is given. Documentation in `git-remote.adoc` is updated to explain the new default behavior, and the test suite (`t/t5505-remote.sh`) adds four new tests: one verifying that `-t` still sets an explicit refspec, one confirming that full repositories keep the wildcard refspec, one demonstrating the new default in shallow repositories, and one showing that `--no-limited-fetch` overrides the default.

This patch is a straightforward behavioral change with no design decisions left open. It is well-motivated, clearly documented, and thoroughly tested. The implementation is clean and preserves backward compatibility for non-shallow repositories. The only remaining blocker for the series is Junio’s response to the precedence rule in Patch 1/4; this patch itself is uncontroversial and ready to queue once the series is approved.
