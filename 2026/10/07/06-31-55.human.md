This is a follow-up in the ongoing RFC thread about adding porcelain commands to share Git stashes through remotes. The author, Hanan Arshad, responds to Junio C Hamano’s opposition by clarifying the original motivation: a Perforce-shelf-like workflow for temporary, independent overlays (e.g., build configurations) that should not be tied to a specific branch’s history.

The key distinction here is between *persistent* shared work (where branches are the right tool) and *ephemeral* overlays that are applied and discarded without merging or rebasing. Hanan argues that while Git’s plumbing already supports this via `git stash export` + `git push`/`git fetch`, the user experience is fragmented and unintuitive for this niche use case. The proposal remains focused on porcelain wrappers (`git stash list --remote`, `git stash get`, `git stash remove`) to streamline discovery, fetching, and cleanup of remote stash refs—without introducing new object formats or server-side changes.

The response directly addresses Junio’s objection that branches already handle these operations, but it does not yet propose a concrete counterargument to the philosophical stance that stashes should remain personal. The thread’s future likely hinges on whether Hanan or others can demonstrate that this workflow is common enough to justify dedicated porcelain, or whether the existing plumbing is deemed sufficient. For now, the proposal remains in limbo, with maintainer opposition still firm.
