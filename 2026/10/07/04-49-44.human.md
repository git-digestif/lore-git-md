This is a **platform compatibility and build system** note in the ongoing Git Contributor's Summit 2026 documentation thread. Todd Zullinger, a former Fedora Git package maintainer, clarifies that Fedora has been using Asciidoctor by default since 2020 and no longer relies on AsciiDoc. He also notes that RHEL/CentOS Stream could easily adopt Asciidoctor if needed, though they currently use AsciiDoc (with exceptions). His message removes a key obstacle to standardizing on Asciidoctor: the concern that Fedora would block the change is now outdated.

Todd suggests that switching to Asciidoctor could simplify the build process by eliminating the docbook/xmlto dependencies, though he hasn’t evaluated whether this would break other outputs (e.g., info, PDF). His tone is factual and pragmatic, offering a clear path forward without advocating strongly for any particular toolchain. This is a **well-informed, actionable clarification**—worth noting for anyone following the Asciidoctor migration discussion, but not a proposal or patch in itself. The next step would likely be a patch series or RFC to formalize the toolchain change.
