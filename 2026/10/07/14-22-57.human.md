This is the second patch in a well-reviewed two-patch performance optimization for the commit-graph subsystem. It implements the core logic of the incremental write strategy for `fetch.writeCommitGraph`, avoiding the expensive full ref scan after every fetch by writing only the newly fetched commits when possible.

The patch introduces a three-mode enum (`GRAPH_WRITE_REACHABLE`, `GRAPH_WRITE_TIPS`, `GRAPH_WRITE_SKIP`) to make the write policy explicit. After `fetch_one()` returns, it checks whether a commit-graph exists and whether any refs were updated. If the graph exists and the fetch updated at least one ref, it writes incrementally using only the new refs as seeds; if the graph exists but the fetch was a no-op, it skips the write entirely; if no graph exists, it falls back to the full reachable scan. Multi-remote fetches (e.g., `fetch --all`) also fall back to the full scan, since propagating the set of updated refs across process boundaries would complicate the implementation.

The implementation relies on the commit-graph write being additive (using split mode, `COMMIT_GRAPH_WRITE_SPLIT`), which fetch already uses. This ensures incremental updates extend the existing graph without replacing it. The patch also makes `prepare_commit_graph()` non-static so the fetch command can check for an existing graph, and adds a helper function `collect_updated_tips()` to gather the OIDs of updated refs, skipping shallow-rejected refs and no-op updates.

Test coverage is thorough, with six new tests in `t/t5510-fetch.sh` and `t/t5537-fetch-shallow.sh` verifying incremental writes, exclusion of unrelated commits, no-op fetch skipping, fallback to full scans when no graph exists, and correct handling of shallow-rejected refs. The benchmark numbers from the cover letter are compelling: in a synthetic setup with 200K packed refs, the incremental write reduces `fetch/write-commit-graph` time from ~357ms to ~9.3ms for a single ref update, and no-op fetches are skipped entirely.

This patch is technically uncontested after two prior iterations addressed all feedback from Patrick Steinhardt. The changes in v3 are purely surface-level (commit message tweaks, test script style, and the test helper addition in patch 1/2). The implementation looks solid, with careful handling of edge cases and no open technical questions. It should benefit large repositories without introducing regressions.
