Subject: [RFC] git clone --non-intrusive to disable local config/hooks
Series version: RFC (no patch version yet)
Originating author: Luca Di Carlo <luca@dicarlo.email>
Thread type: feature proposal / design discussion

Core problem or goal
Add a `--non-intrusive` flag to `git clone` that disables all repository-local Git configuration (hooks, config, etc.) to mitigate the risk of executing malicious code when cloning untrusted repositories, particularly in job-interview scenarios.

Current status
Proposal stage; no patches posted. The email outlines the desired user-facing behavior (a `.nogitconfig` marker file, restricted operations) but does not address implementation trade-offs, interaction with existing flags (`--template`, `--config`), or whether the feature should be client-side only or involve server-side signaling.

Key technical details
- Proposed CLI option: `git clone --non-intrusive`
- Proposed on-disk marker: `.nogitconfig` file in the working tree
- Restricted operations: push, fetch, and possibly others (unspecified)
- No new symbols, subsystems, or on-disk format changes identified yet
- Test coverage: none proposed

Open questions and loose ends
- Should this be a client-side safety measure or a server-side signal?
- How does `--non-intrusive` interact with `--template` and `--config`?
- What operations should be restricted, and how should users be notified?
- Is a pre-clone hook or wrapper script a better approach?
- What is the threat model (e.g., is `.git/config` or `.git/hooks` the primary concern)?
- How should the feature handle existing repositories (e.g., `git init --non-intrusive`)?

Participant positions
- Luca Di Carlo (author): proposes the feature as a user-facing safety measure; no substantive review or alternative approaches yet discussed.
