Core problem or goal
Fix two memory leaks in the `sort_stdin()` helper function in `t/helper/test-mergesort.c`: a memory pool (`lines_pool`) and a `strbuf` (`sb`) were allocated but never freed after the sorted lines were printed. The patch also adds test coverage for the `test-tool mergesort sort` subcommand, which was previously untested and thus allowed the leaks to persist undetected in the leak-sanitized test suite.

Current status
Under review; no prior versions. The patch is a single, self-contained fix. Patrick Steinhardt’s review endorses the leak fix as correct and ready for merging, but identifies a broader cleanup opportunity: the unused `generate` subcommand in the same test helper could be removed entirely, as it is not referenced by any tests or benchmarks except for a now-questioned performance test.

Key technical details
- Files touched: `t/helper/test-mergesort.c` (two lines added: `mem_pool_discard(&lines_pool)` and `strbuf_release(&sb)`), `t/t0071-sort.sh` (seven lines added: a new test case for the `sort` subcommand).
- Subsystem: test infrastructure (`t/helper/`, `t/`).
- New test: `test_expect_success 'sort subcommand works' ...` in `t/t0071-sort.sh`, verifying the `sort` subcommand’s output matches an expected sorted list.
- No changes to user-facing behavior, on-disk formats, or core Git functionality.
- The `generate` subcommand is confirmed unused outside of a single performance benchmark (`p0071-sort.sh`), whose ongoing value Patrick questions.
