This is the fourth and final patch in Harald Nordgren’s v7 series introducing a "matching-inspired" fetch mode for shallow repositories. It makes `--limited-fetch` the default when adding a remote to a shallow repository, ensuring that `git remote add` does not set up a wildcard refspec that would defeat the purpose of a shallow clone.

The patch is small and surgical: it modifies `builtin/remote.c` to check `is_repository_shallow()` when `limited_fetch` is unset, updates the documentation to explain the new default, and adds four new tests in `t/t5505-remote.sh` that verify the behavior in shallow and full repositories, with and without `--no-limited-fetch`. The logic is straightforward—if the repository is shallow and no explicit tracking or mirroring is requested, the new remote is configured with `remote.<name>.refmap` instead of `remote.<name>.fetch`, so a later `git fetch` will only negotiate the branches that local branches already track.

This patch is uncontroversial and ready to merge once the series as a whole is queued. It directly addresses the user pain point the series targets (slow fetches in shallow repositories) without introducing new edge cases or design questions. The tests are thorough and cover the main scenarios.
