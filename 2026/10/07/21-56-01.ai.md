This is the first patch in the v7 series implementing the `remote.<name>.refmap` configuration for Git fetch. It introduces the plumbing to parse and store the new `remote.<name>.refmap` setting, which defines how remote refs should be mapped to local remote-tracking refs when fetched.

The patch adds the configuration variable to `struct remote` in `remote.h`, implements its parsing in `remote.c`, and updates `builtin/fetch.c` to use the configured refmap as the default when no explicit `--refmap` is provided. Documentation is added to `config/remote.adoc` and `fetch-options.adoc` to explain the new setting. The test suite (`t/t5510-fetch.sh`) is extended to verify that `remote.<name>.refmap` behaves like the `--refmap` command-line option and that it correctly interacts with `remote.<name>.fetch` (with the latter taking precedence when both are configured).

The implementation is clean and well-scoped: it touches only the configuration parsing and refmap selection logic, leaving the dynamic branch enumeration (the "matching-inspired" fetch mode) to later patches. The precedence rule—where `remote.<name>.fetch` overrides `remote.<name>.refmap`—is now explicitly enforced, resolving the fatal error that blocked earlier versions. The patch is a necessary foundation for the series and is technically sound, with thorough test coverage for the new behavior. No controversial design decisions are embedded here; the patch simply implements the agreed-upon configuration mechanism.
