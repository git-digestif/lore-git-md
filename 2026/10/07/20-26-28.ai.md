This is a **design discussion follow-up** in the ongoing `--non-intrusive` clone RFC thread, now focused on mitigating risks from malicious `.git/` directories in archives.

Nico Williams responds to D. While this sidesteps the Git-specific threat, it does not propose a technical change to Git itself. The comment implicitly reinforces the thread’s earlier conclusion that Git’s current security model does not address archive-based risks, and suggests that external tooling (VMs, web apps) may be the only viable mitigation for now.

No new technical directions or Git features are introduced here. The thread remains stalled on the core question—whether Git should harden its handling of `.git/` directories in archives—with no clear path forward. Nico’s input leans toward treating this as a workflow problem rather than a Git design problem, leaving the door open for future proposals but offering no immediate resolution.
