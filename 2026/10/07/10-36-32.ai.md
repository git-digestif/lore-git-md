This is a substantive review reply from Johannes Sixt (Hannes) in the ongoing RFC thread about adding porcelain wrappers for sharing Git stashes through remotes. Hannes directly counters Hanan Arshad’s workflow justification by demonstrating how the same outcome can be achieved using existing Git commands—branches for transfer and `git show`/`git apply` for application—without introducing new porcelain. His response reinforces his long-standing position that stashes are inherently personal and ephemeral, and that branches already provide a robust, well-understood mechanism for sharing work. The example workflow he provides is concrete and minimal, using only standard Git operations (`git switch`, `git commit`, `git push`, `git fetch`, `git show`, `git apply`), and explicitly avoids the need for merging, rebasing, or cherry-picking the configuration branch. This reply effectively neutralizes Hanan’s core motivation by showing that the proposed use case (temporary handoff of overlays) can be satisfied without new tooling, leaving little technical justification for the feature. The thread’s momentum now hinges on whether Hanan can identify a remaining pain point that branches do not address, or whether Junio and other participants will accept Hannes’s framing as definitive.
