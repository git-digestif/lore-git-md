This is a brief follow-up in the review of Karthik Nayak’s performance patch for the packed-refs backend. Patrick Steinhardt clarifies his earlier feedback about the `record_start` field in `struct packed_ref_iterator`. He explains that the current comment ("set when advancing `pos`") misleadingly suggests `record_start` is updated every time `pos` advances, which is not true—`pos` can advance independently (e.g., during parsing or skipping). The comment needs to explicitly state that `record_start` tracks the *start of the current record* and is only updated when a new record begins, not on every `pos` movement. This is a documentation precision issue, not a code logic flaw, and the patch’s core approach remains unchanged. Karthik will need to revise the comment before sending v5.
