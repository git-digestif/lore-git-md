This is the first patch in the v3 series optimizing `fetch.writeCommitGraph` for large repositories. It adds a `commit-info` subcommand to `test-tool read-graph` to verify whether specific commits are present in the commit-graph and print their generation numbers.

The change is minimal and focused: 22 lines added to `t/helper/test-read-graph.c` to implement the new subcommand. The subcommand takes one or more commit object names as arguments, checks if each commit exists in the commit-graph, and prints its generation number if found. If any commit is missing, the tool exits with status 1, making it suitable for test assertions. This enables precise verification of commit-graph contents in the test suite, which is essential for validating the incremental write logic introduced in the second patch.

The implementation is straightforward and uncontroversial. It exposes two existing internal APIs (`lookup_commit_in_graph()` and `commit_graph_generation()`) for test use, and relies on `repo_get_oid()` for object name resolution. The patch does not change any behavior outside the test helper, and the new functionality is only used in the follow-up patch’s test coverage.

This patch is ready for integration; it has no open questions, no dependencies, and no known issues. The test helper it provides is a prerequisite for the series’ test coverage but is otherwise self-contained.
