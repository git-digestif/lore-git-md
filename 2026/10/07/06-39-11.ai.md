This is a **surface-level review** of the second patch in Kristofer Karlsson’s v2 series optimizing `fetch.writeCommitGraph` for large repositories. The review flags three cosmetic points in the commit message: two instances where commit references are set apart in their own paragraphs (unconventional for Git), a redundant explanation of auto-followed tags (tags are not stored in the commit-graph, so this detail adds no value), and a repetition of logic already explained in a code comment about shallow-rejected refs. Patrick also suggests using `test_commit` helpers in the test script for brevity, though the existing shell commands are functionally equivalent. No behavioral or correctness concerns are raised; the feedback is purely about presentation. The series is otherwise unchanged and still targets the commit-graph subsystem with the same incremental-write strategy and fallback logic described in the thread summary.
