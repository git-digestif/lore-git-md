This is the third iteration of a documentation patch that rewrites the introductory section of the `git(1)` man page. The patch is now ready for maintainer pickup once the commit message is updated to include the rationale Julia Evans just provided. The goal remains unchanged: replace outdated tutorial references (`gittutorial`, `giteveryday`, `user-manual`, `datamodel`, `cli`) with concrete, actionable instructions for accessing Git’s help system (`git push -h`, `git push --help`, `git help push`, `git help --guides`, `git help --user-interfaces`). The thread has fully documented the reasoning behind each removal: `cli` is developer-focused and not useful for interactive users, `user-manual` is outdated (e.g., still recommending `git format-patch` for collaboration), and `datamodel` feels orphaned once the other guides are removed.

The patch itself is stable and uncontroversial. All substantive feedback from Junio C Hamano, D. Ben Knoble, and Kristoffer Haugsbakk has been incorporated, including Junio’s mechanical corrections (`git help --web push` instead of `git help push --web`) and the addition of `git help push` as an alternative to `git push --help`. The only remaining action is for Julia to post v3 with the commit message update; no further technical changes are needed. The patch touches only `Documentation/git.adoc` and does not affect on-disk formats, tests, or other subsystems.

The thread also clarifies why `git-scm.com/docs` is now preferred over `git.github.io/htmldocs/git.html`: the former tracks the latest *released* version of Git (not the tip of `master`), making it more appropriate for general users. This rationale is now fully documented in the thread, though it was not part of the original commit message. The patch is part of a broader effort to modernize Git’s documentation, though no other in-flight work directly conflicts with it. Kristoffer Haugsbakk’s RFC series (`kh/doc-gitbreaking-changes7`) briefly overlapped but will be updated to align with this patch.
