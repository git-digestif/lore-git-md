This is a documentation patch that rewrites the explanation of detached HEAD state in Git. The author, Julia Evans, identifies several shortcomings in the current documentation: it doesn’t explain *why* detached HEAD is useful, takes too long to define the concept, doesn’t clarify why users might end up in this state accidentally, and includes overly complex diagrams. The patch replaces the existing section in `git-checkout.adoc` with a new, more concise explanation and moves it to a standalone guide (`gitdetachedhead(7)`), which can be referenced from Git’s advice messages.

The new explanation is framed around the idea that Git treats commits not on a branch as "garbage" (a concept borrowed from Steve Klabnik’s Jujutsu tutorial), which helps users understand why detached HEAD commits might disappear. It also highlights how `git switch` (introduced in 2019) makes it harder to detach accidentally, a UI improvement that wasn’t previously advertised. The patch includes practical advice for users who find themselves in detached HEAD state, such as how to return to a branch or create a new one to preserve commits.

The implementation is straightforward: the new content is added in `detached-head.adoc`, included in both `git-checkout.adoc` and the new `gitdetachedhead.adoc` man page, and the advice message in `advice.c` is updated to reference the new guide. The patch is well-motivated and addresses a common pain point for Git users, particularly beginners. The rewrite is clear and avoids the overly technical diagrams of the original, making it more accessible. The addition of a standalone guide is a practical improvement, as it allows users to quickly access focused help without digging through the full `git-checkout` documentation. This looks like a thoughtful, user-centric contribution.
