This is a **substantive review and proposed fix** for the push negotiation bug reported by Jens Röcker. Patrick Steinhardt confirms the root cause: `odb_has_object()` with `OBJECT_INFO_QUICK` can produce false negatives when the object database is concurrently repacked (e.g., by a pre-push hook), causing `append_negative_object()` to skip objects that should serve as negative boundaries. This leads the pack generator to walk and resend common history unnecessarily.

The proposed fix batches all negative object checks into a single `odb_reprepare()` call, reducing the overhead of reloading the object database for each missing object. The patch replaces the per-object `append_negative_object()` with a new `append_negative_objects()` that collects all candidate OIDs, checks them in bulk, and retries only the missing ones after a single `odb_reprepare()`. This avoids the race condition while minimizing performance impact—critical for repositories with many advertised objects.

Key technical details:
- **Files modified**: `send-pack.c` (core pack generation logic).
- **New data structures**: `struct oidset` to batch missing OIDs.
- **Behavior change**: Negative boundary objects are now checked in bulk, with a single `odb_reprepare()` if any are missing.
- **Performance tradeoff**: The fix adds a small overhead for the common case (no repack race) but avoids catastrophic overhead when many objects are falsely reported missing.

The patch is untested but addresses the core issue directly. It’s a targeted fix for the race condition without broader refactoring, making it a plausible candidate for `next` once validated.
