This is the first patch in a **bugfix series** targeting the diff subsystem, specifically the `--relative` option in combined diffs. The patch ensures that `--relative` is honored when printing paths in both human-readable and machine-readable combined diff output, fixing a long-standing inconsistency where combined diffs ignored the prefix and displayed repository-root paths instead.

The core change rewrites `strip_relative_prefix()` (now renamed to `relative_combined_path()`) to handle edge cases like repeated slashes (e.g., `prefix//path` → `path`) and cross-directory renames. When a renamed parent path lies outside the `--relative` prefix, the patch uses `relative_path()` to print it as `../there/file` (for `--relative=here/`), ensuring all displayed names share a consistent base. This resolves Junio’s design concern about ambiguous output while preserving the literal-prefix behavior for matching names. The patch also updates `dump_quoted_path()` and `show_raw_diff()` to use the new helper, ensuring raw and NUL-separated output respect `--relative` as well.

Test coverage is extensive: the patch adds 109 lines to `t/t4038-diff-combined.sh`, including tests for cross-directory renames, raw/NUL-separated output, and `--follow` edge cases. It also converts a known failure in `t/t4045-diff-relative.sh` into a passing test and adds 62 lines of coverage for explicit prefixes, `--no-relative`, and quoted filenames. The implementation is clean, with no regressions in the affected test suites, and builds cleanly with leak sanitizers (SHA-1/SHA-256).

Key files touched are `combine-diff.c` and the two test scripts; no on-disk formats or public APIs are changed.
