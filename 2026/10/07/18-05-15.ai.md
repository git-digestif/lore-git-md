This is the second patch in Maciej Ciemborowicz’s four-patch v3 series fixing the `reference-transaction` hook’s omission of new refs during branch rename/copy operations. It introduces `ref_transaction_replace_reflog()`, a new transactional API that allows replacing a ref’s reflog history with explicit entries queued in the same transaction, without altering the ref itself.

The patch is **refactoring with behavior change**: it centralizes reflog replacement logic that was previously scattered across backend-specific callbacks, enabling the later patches to handle branch rename/copy through ordinary transactions. The core mechanism stages files-backend replacements in temporary files (written during `prepare` and installed during `finish`) and tombstones reftable’s previous entries in the same table. A private `REF_REPLACE_REFLOG` flag ensures this cross-update behavior cannot be accidentally attached to ordinary ref updates.

Tests cover null-OID preservation, entry ordering, hook-triggered rollback, and duplicate replacement rejection. The patch is a prerequisite for the rename/copy integration in patch 3/4 and is **ready for substantive review** alongside the rest of the series. Key files modified: `refs.c`, `refs/files-backend.c`, `refs/reftable-backend.c`, and a new test script `t/t1425-reflog-transaction.sh`. Performance impact is negligible here but will compound in later patches.
