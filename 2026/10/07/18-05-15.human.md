This is the second patch in Maciej Ciemborowicz’s four-part bugfix series (v3) that ensures the `reference-transaction` hook correctly reports branch rename and copy operations. The patch introduces `ref_transaction_replace_reflog()`, a new API that lets callers replace a reference’s reflog history within a transaction without altering the reference itself.

The core idea is to stage the replacement reflog entries in temporary files (for the files backend) or tombstone the old entries (for reftable) during the transaction’s prepare phase, then atomically install them during commit. The implementation buffers writes, orders entries by their requested index, and propagates read errors rather than silently truncating the log. Tests verify that null-OID entries are preserved, ordering is respected, hook vetoes roll back cleanly, and duplicate replacements are rejected.

The patch is cleanly split from the rest of the series and touches only the ref backend and test infrastructure. It lays the groundwork for patch 3/4, which will use this API to fix the missing-creation-event bug in branch rename/copy. No performance impact is introduced here; the ~137 % slowdown mentioned in the cover letter comes from the later integration patch.
