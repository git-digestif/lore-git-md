This is a documentation patch that revises the introductory section of the `git(1)` man page to better orient new users toward Git’s help system. The patch has been through two iterations and is now in its final stages, awaiting a commit message update to address Junio C Hamano’s request for explicit rationale on why the `user-manual`, `datamodel`, and `cli` guides are no longer referenced.

The patch replaces outdated tutorial links (`gittutorial`, `giteveryday`) and guide references with concrete, actionable instructions for accessing help: `` `git push -h` `` for quick usage, `` `git push --help` `` or `` `git help push` `` for full documentation, and `` `git help --guides` `` or `` `git help --user-interfaces` `` for broader overviews. It also drops the redundant link to `git.github.io/htmldocs/git.html` in favor of `git-scm.com/docs`, which tracks the latest *released* version of Git rather than the tip of `master`. The rewrite is motivated by user feedback and aims to improve discoverability while keeping the introduction simple and practical.

All substantive feedback from Junio, D. Ben Knoble, and Kristoffer Haugsbakk has been incorporated or addressed. The only remaining action is for Julia Evans to post a v3 patch with an updated commit message that documents the rationale for removing the `user-manual`, `datamodel`, and `cli` guides. Julia’s explanation in this email—`user-manual` is outdated, `cli` is developer-focused rather than user-facing, and `datamodel` feels out of place once the others are removed—is clear and sufficient. No technical changes to the patch itself are needed.

The patch is well-crafted, thoroughly reviewed, and ready for integration once the commit message is updated. It addresses a real usability gap and aligns with the project’s ongoing documentation modernization efforts. The thread has also clarified an important distinction between `git-scm.com/docs` (release-aligned) and `git.github.io/htmldocs/git.html` (tracks `master`), which may be useful context for future documentation work.
