This thread is about improving Git’s documentation for detached HEAD state. Julia Evans authored a rewrite that addresses four key shortcomings in the current explanation: it now clarifies *why* detached HEAD is useful, defines the concept more quickly, explains how users might end up in this state accidentally, and removes overly complex diagrams. The updated text has been moved to a new standalone guide, `gitdetached-head(7)`, which is now referenced in Git’s advice messages. The patch is in its second version (v2) and is under review.

Junio C Hamano and Kristoffer Haugsbakk provided substantive feedback on the first version, which Julia addressed in v2. Key improvements include adding missing build-system changes (meson/Makefile), renaming the guide to `gitdetached-head(7)` for consistency, mentioning the reflog expiry period to address concerns about “garbage” commits, and adding a concrete recovery example. Junio’s latest review focuses on minor corrections: ensuring the help command uses the hyphenated form (`git help detached-head`), adding a sign-off for a co-author, and clarifying the reflog expiry period (suggesting "a few weeks" or 30 days instead of 90 days). He also noted a whitespace alignment issue in `command-list.txt`.

The patch is self-contained and does not depend on other in-flight work. Once these small corrections are made, it should be ready for integration. The broader usability concern about Git’s help system—specifically, the inconsistency between internal man page cross-references (e.g., `git-config(1)`) and the recommended `git help` command—remains noted but is not a blocker for this patch. Julia plans to follow up with a separate patch to hyphenate `gitmergeconflicts` for consistency.
