This thread is about a documentation patch from Julia Evans that overhauls how Git explains detached HEAD state. The current documentation is criticized for being too slow to define the concept, failing to explain why detached HEAD is useful, and not clarifying how users might end up in this state accidentally. The patch replaces the existing section in `git-checkout.adoc` with a more concise explanation and moves it to a new standalone guide, `gitdetachedhead(7)`, which can be referenced directly from Git’s advice messages.

The new explanation frames detached HEAD commits as "garbage" (a concept borrowed from Steve Klabnik’s Jujutsu tutorial), helping users understand why these commits might disappear. It also highlights how `git switch` (introduced in 2019) reduces accidental detaching, a UI improvement not previously emphasized. The patch includes practical advice for users who find themselves in detached HEAD state, such as how to return to a branch or create a new one to preserve commits. The implementation is straightforward: the new content is added in `detached-head.adoc`, included in both `git-checkout.adoc` and the new `gitdetachedhead.adoc` man page, and the advice message in `advice.c` is updated to reference the new guide.

This is a user-centric contribution that addresses a common pain point, particularly for beginners. The rewrite avoids overly technical diagrams and makes the explanation more accessible. The addition of a standalone guide is a practical improvement, allowing users to quickly access focused help without navigating the full `git-checkout` documentation. So far, the thread consists only of the initial patch submission, so no reviews or discussions have taken place yet.
