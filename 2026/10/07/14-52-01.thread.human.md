This thread is about a documentation improvement to Git’s explanation of detached HEAD state, now complete and merged to `master`. Julia Evans authored a rewrite that addresses four specific shortcomings in the existing text: it didn’t explain why detached HEAD is useful, took too long to define the concept, didn’t clarify how users might end up in this state accidentally, and included overly complex diagrams. The final version, v4, moves the explanation to a new standalone guide (`gitdetached-head(7)`) and updates Git’s advice messages to point to it. Junio C Hamano accepted the patch after all prior feedback was addressed, including build-system fixes, textual refinements, and naming conventions.

The new documentation frames detached HEAD as advantageous for experimentation—like testing commits, browsing history, or working directly on remote-tracking branches—and removes the word “unintentionally” from accidental-detachment scenarios. It also highlights the 2019 UI improvement in `git switch` that makes accidental detachment harder. The reflog expiry period is now specified as 30 days (the default for `gc.reflogExpireUnreachable`). While the patch is now merged, two loose ends remain: whether to relocate diagrams from `git-checkout(1)` to the new guide if users miss them, and a broader usability concern about Git’s help system—the inconsistency between internal man page cross-references (e.g., `git-config(1)`) and the recommended `git help` command. Julia plans to follow up with a separate patch to hyphenate `gitmergeconflicts` for consistency with the new guide’s naming convention.
