Julia Evans has proposed a rewrite of Git’s documentation for detached HEAD state, aiming to make it clearer and more practical. The patch moves the explanation from `git-checkout.adoc` to a new standalone guide (`gitdetachedhead(7)`) and updates advice messages to point to this new resource. The goal is to address four specific shortcomings in the current text: it doesn’t explain *why* detached HEAD is useful, takes too long to define the concept, doesn’t clarify how users might end up in this state accidentally, and includes overly complex diagrams.

Junio C Hamano has reviewed the patch, offering line-by-line feedback on the proposed text. His comments are substantive but focused on wording and clarity. He suggests rewording the opening definition of HEAD to avoid circular phrasing, framing detached HEAD as a tool for experimentation rather than a problem, and using more precise language (e.g., "unknowingly" instead of "unintentionally"). He also proposes adding a concrete recovery example—quoting the exact warning message Git emits when commits are left behind—to help users act without digging into reflogs. On structure, Junio is neutral about removing diagrams from `git-checkout(1)` but notes they could be relocated to the new guide if missed. The review does not object to the standalone man page or the advice-message pointer change, and no new test coverage or code changes are requested. The patch remains under review, with no prior versions or dependencies.
