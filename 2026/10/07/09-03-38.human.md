This is a **bugfix** targeting Git’s push negotiation logic, specifically addressing the redundant transfer of common history when a pre-push hook repacks the local object database. Patrick Steinhardt, a prolific contributor with deep expertise in the object database (ODB) and repack machinery, has engaged substantively with Jens Röcker’s bug report and proposed a fix.

Patrick confirms Jens’s hypothesis: the issue stems from `odb_has_object()` using `OBJECT_INFO_QUICK`, which can produce false negatives when the ODB is concurrently repacked. This causes `append_negative_object()` to skip objects that should serve as negative boundaries for the graph walk, leading to the redundant transfer of already-advertised history. The problem affects both Git 2.54.0 and 2.56.0, and Patrick’s analysis aligns with the observed behavior in Jens’s reproducible test case.

The proposed fix batches the existence checks for negative objects, gathering all potentially missing objects first and reloading the ODB only once if any are missing. This avoids the overhead of reloading the ODB for every truly-missing object while still handling concurrent repacks. The patch is untested but logically sound, and Patrick’s rationale for batching the check is well-explained. The change is confined to `send-pack.c` and introduces no new dependencies or behavioral side effects beyond fixing the bug.
