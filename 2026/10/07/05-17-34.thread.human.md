This thread is about a bugfix patch from Muhammed Dilshad A that makes the `--relative` option in `git diff` work consistently for combined diffs (such as those shown during merge conflicts). Currently, `--relative` is ignored in combined diffs, showing paths from the repository root instead of respecting the requested prefix. The patch is self-contained, touching only `combine-diff.c` and the test suite, and includes thorough test coverage.

Junio C Hamano has reviewed the patch and raised two key concerns. The first is a minor coding style issue with a helper function’s line length. The second, more significant, is about edge-case behavior: the patch may not handle multiple slashes in paths correctly (e.g., `prefix//path`), and it could produce inconsistent output when dealing with renamed files in combined diffs. For example, if one parent has `there/file` and another has `here/file`, stripping the `here/` prefix from both would leave `there/file` unchanged but reduce `here/file` to `file`, which might confuse users. Junio suggests the author reconsider whether the current approach is the right one.

The patch is still under review, and no other feedback has been provided yet. The next step is for the author to address these concerns, particularly the path normalization and rename handling issues.
