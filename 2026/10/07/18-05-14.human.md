This is the first patch in Maciej Ciemborowicz’s **v3 series fixing the `reference-transaction` hook omission during branch rename/copy**. It introduces an internal-only transaction flag (`REF_TRANSACTION_FLAG_INTERNAL`) to distinguish physical backend updates (e.g., packed-refs housekeeping) from logical ref changes (e.g., branch rename). The flag suppresses hook notifications for nested transactions, ensuring hooks only see the high-level operation rather than backend implementation details.

The change is minimal and targeted: a new flag definition in `refs/refs-internal.h` and a single early-return guard in `run_transaction_hook()`. This centralizes hook suppression logic, addressing Patrick Steinhardt’s v2 objection about scattered backend-specific checks. The patch is a prerequisite for later steps that use this flag to avoid duplicate hook events during reflog replacement and copy/rename operations.

No performance impact or behavior change is expected at this stage—this is purely infrastructure for the rest of the series. The commit message is clear and scoped, and the implementation follows Git’s idiomatic pattern for internal flags. If the series advances, this patch will likely be uncontroversial.
