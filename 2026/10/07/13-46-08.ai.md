This is the second patch in Phillip Wood’s two-patch refactoring series `pw/stash-optimize-check_changes-calls/v1`, which consolidates redundant change-detection logic in `git stash push` and `git stash create`. The patch removes a duplicate `check_changes()` call in `do_push_stash()` and adjusts the return-value convention of `do_create_stash()` so that 2 now signals “no changes to stash” (previously conflated with 1, which continues to mean “nothing was stashed” due to `--patch` with no hunks selected or `--staged` when the index matches HEAD).

The discussion in this reply advances the thread by acknowledging and addressing Junio C Hamano’s observation that the patch introduces a redundant index refresh: `do_push_stash()` now calls `repo_refresh_and_write_index()` unconditionally, then invokes `do_create_stash()`, which refreshes the index again. Phillip agrees this is inefficient and proposes a follow-up patch to make callers responsible for refreshing the index, avoiding both the double refresh and multiple `preload_index()` calls. The series’ optimization goal is thus acknowledged as incomplete, but the direction is uncontroversial.

The patch touches only `builtin/stash.c`, specifically `do_create_stash()` and `do_push_stash()`. No new functions, options, or symbols are introduced, and there are no on-disk format changes or test coverage updates. Junio’s earlier commit-message typos in the first patch are not repeated here. The series remains under review; this is still the first iteration (`v1`).
