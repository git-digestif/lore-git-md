This is the **final patch (4/4)** in Maciej Ciemborowicz’s v3 series fixing the `reference-transaction` hook omission for branch rename/copy operations. It **removes the now-unused backend-specific copy and rename callbacks** (`rename_ref` and `copy_ref`) from the files, packed, reftable, and debug backends, completing the transition to the unified transaction API introduced in earlier patches.

The patch deletes **656 lines** of backend-specific logic—primarily the `files_copy_or_rename_ref()` helper in `refs/files-backend.c` and the `write_copy_table()` machinery in `refs/reftable-backend.c`—along with their private helpers (e.g., `TMP_RENAMED_LOG`, `rename_tmp_log_callback`, and rollback logic). The debug backend’s tracing wrappers are also removed. No new behavior is introduced; this is purely cleanup after patches 1–3 refactored the copy/rename logic into the transaction API.

Key technical details:
- **Files backend**: Removes the temporary reflog staging (`TMP_RENAMED_LOG`) and rollback writes that reconstructed previously visible refs/logs. The transaction API now handles reflog replacement via `ref_transaction_replace_reflog()` (patch 2/4) and hook suppression via `REF_TRANSACTION_FLAG_INTERNAL` (patch 1/4).
- **Reftable backend**: Deletes the `write_copy_table()` function, which previously orchestrated tombstone writes and reflog history copying. The transaction API now manages this through ordinary ref updates with `REF_COPY_SOURCE` and `REF_NEEDS_PACK` flags (patch 3/4).
- **Public API**: Drops the `rename_ref_fn` and `copy_ref_fn` typedefs from `refs/refs-internal.h`, along with their backend vtable entries.
- **Test coverage**: No new tests are added here, but the series’ existing tests (`t1416-ref-transaction-hooks.sh`, `t1425-reflog-transaction.sh`) verify the transaction-based logic remains correct.

The patch is **mechanical and low-risk**, contingent on the correctness of the earlier patches. Its primary value is eliminating duplicate code and reducing backend divergence. Performance regressions (~137% for files-based rename with large reflogs) were introduced in patch 3/4 and are not addressed here; the commit message defers to the series’ rationale that the trade-off is acceptable.

**Next steps**: This patch is ready for review alongside the rest of the series. Focus areas for reviewers will likely include:
- Whether the transaction API’s per-ref-update flags (`REF_COPY_SOURCE`, `REF_NEEDS_PACK`) and helpers (`ref_transaction_prepare_copy`) are idiomatic.
- Confirmation that the removed rollback logic is no longer needed (e.g., for D/F conflicts or concurrent updates).
- Verification that the debug backend’s tracing removal doesn’t break observability for other operations.
