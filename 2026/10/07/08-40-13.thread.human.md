This thread began as an RFC proposing `git clone --non-intrusive` to disable local configuration and hooks, aiming to mitigate risks from untrusted repositories. The initial idea—a CLI flag and `.nogitconfig` marker—has since been recognized as misaligned with the actual threat: malicious hooks in `.git/` directories from archives, which execute during post-clone operations like `commit` or `push`, not during `clone` itself.

Key participants are Luca Di Carlo, the RFC’s author, and D. Ben Knoble, who provided substantive feedback correcting the threat model. Knoble also noted Git’s historical stance that archive-based threats fall outside its security model, though he called this position unsatisfactory long-term. The discussion has pivoted to exploring alternatives—hardening Git’s handling of `.git/` directories in archives, extending `safe.directory`, or adopting wrapper scripts—but no concrete proposals have emerged. The original `--non-intrusive` design is effectively abandoned, and the thread remains in an exploratory phase, awaiting fresh input or a consensus on how (or whether) Git should address this risk. For now, user education remains the only mitigation.
