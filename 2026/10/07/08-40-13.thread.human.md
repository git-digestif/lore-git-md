This thread is a **feature proposal** from Luca Di Carlo for a new `--non-intrusive` flag in `git clone`. The idea is to add an option that disables all repository-local Git configuration (hooks, config, etc.) during cloning to mitigate security risks, particularly in scenarios like job interviews where candidates might be asked to clone untrusted repositories. The proposal includes a `.nogitconfig` marker file to signal the restricted mode and remind users that certain operations (e.g., push, fetch) will be unavailable.

So far, the discussion is in its early stages. The proposal is light on technical details—it doesn’t address implementation trade-offs (e.g., whether this should be a client-side safety measure or a server-side signal), how it would interact with existing flags like `--template` or `--config`, or whether a pre-clone hook or wrapper script might be a better approach. The focus is on the user-facing security concern rather than deep technical changes, so the conversation is likely to revolve around threat models, usability, and whether this is the right solution to the problem.
