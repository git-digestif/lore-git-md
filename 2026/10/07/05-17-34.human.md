This is a bugfix patch for `git diff --relative` in combined diff mode. The issue: when running `git diff --relative` from a subdirectory during a merge conflict, the output still shows paths relative to the repository root rather than the current directory. The patch fixes this by stripping the prefix specified by `--relative` when printing paths, while keeping the original paths for file access.

The change is small but targeted: it adds a helper function `strip_relative_prefix()` in `combine-diff.c` and applies it consistently to path printing in both the human-readable and raw combined diff output. The patch also updates two test scripts: it flips a known failure in `t4045-diff-relative.sh` to a passing test and adds new coverage for edge cases like explicit prefixes, `--no-relative`, raw/NUL-separated output, quoted filenames, and renamed parent paths.

The commit message is clear and the test additions look thorough. This appears to be a well-scoped fix for a real usability annoyance in merge conflict scenarios. No controversy is evident from the patch itself.
