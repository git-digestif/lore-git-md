This is the second patch in Harald Nordgren’s v7 series introducing a "matching-inspired" fetch mode for shallow repositories. It implements the core logic that makes `git fetch` infer which branches to fetch when a remote is configured with `remote.<name>.refmap` but no `remote.<name>.fetch` refspec.

The patch adds a new helper function `branches_tracking_remote()` in `remote.c` that enumerates all local branches whose `@{upstream}` points to the given remote. In `builtin/fetch.c`, `get_ref_map()` now uses this helper to build a dynamic refspec when no explicit refspec is provided and the remote has a refmap but no fetch refspec. The inferred refspec is then used to fetch only the branches that local branches are already tracking, avoiding the performance penalty of negotiating history for all remote branches.

The implementation is clean and well-contained: it touches only `remote.c`, `remote.h`, `builtin/fetch.c`, and the documentation, and adds a new test script (`t/t5586-fetch-refmap.sh`) that verifies the dynamic branch selection logic, including edge cases like remotes with no tracked branches and branches tracking different remotes. The patch is technically sound, with no obvious regressions or design flaws, and the test coverage is thorough.

This is a well-motivated feature that addresses a real user pain point in shallow repositories. The v7 series has resolved the fatal error and design ambiguity from earlier versions, and this patch is the linchpin of the new behavior. The only remaining blocker for the series is Junio’s response to the precedence rule between `remote.<name>.fetch` and `remote.<name>.refmap`, but that decision does not affect the correctness of this patch. If the series lands, this patch will be the one that actually delivers the performance improvement.
