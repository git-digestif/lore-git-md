This is the third patch in Harald Nordgren’s v7 series introducing a "matching-inspired" fetch mode for shallow repositories. It adds a `--limited-fetch` flag to `git remote add`, which configures the new `remote.<name>.refmap` setting instead of the traditional wildcard `remote.<name>.fetch` refspec.

The flag is designed for users who want to fetch only the branches their local branches already track, avoiding the performance penalty of negotiating history for all remote branches. When `--limited-fetch` is used, `git remote add` writes a `remote.<name>.refmap` entry (e.g., `+refs/heads/*:refs/remotes/<name>/*`) and skips the usual `remote.<name>.fetch` refspec. The patch rejects the flag if combined with `-t/--track` or `--mirror`, since those options already specify what to fetch.

The implementation is straightforward: the flag is parsed in `builtin/remote.c`, and the configuration logic is updated to write the refmap entry when the flag is set and no branches are explicitly tracked. The documentation and tests are updated to reflect the new behavior, including a test that verifies the flag works in non-shallow repositories and another that confirms the conflict with `-t`.

This patch is a natural extension of the refmap-based design introduced in the first two patches. It provides a user-friendly way to opt into the new fetch mode without manually editing configuration files. The implementation is clean, the rationale is well-explained, and the edge cases (conflicts with `-t` and `--mirror`) are handled explicitly. There are no obvious design issues or missing pieces. The series as a whole remains under review pending Junio’s response to the precedence rule proposed in v7, but this patch itself looks ready.
