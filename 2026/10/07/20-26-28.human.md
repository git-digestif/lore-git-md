This is a **design discussion follow-up** in the ongoing `--non-intrusive` clone RFC thread, now focused on real-world attack vectors and practical mitigations.

Nico Williams weighs in with a pragmatic, if blunt, perspective: the only truly safe approach to untrusted repositories (especially in high-risk scenarios like fake job interviews) is to avoid running their code entirely. He suggests using hosted VMs or web-based code pads as alternatives, framing the lack of such precautions as a red flag. This reinforces the thread’s earlier pivot away from Git-specific solutions—like the abandoned `--non-intrusive` flag—and toward broader operational security practices.

The comment doesn’t propose new Git features or revisit technical designs, but it does underscore the limitations of Git’s scope. While the thread has acknowledged that malicious `.git/` directories in archives are a real threat, Nico’s response suggests that Git alone can’t solve the problem without external tooling or user vigilance. This aligns with D. Ben Knoble’s earlier observation that Git’s security model doesn’t traditionally cover this threat, though it leaves the door open for future discussion about whether Git *should* adapt. For now, the conversation remains in the realm of philosophy rather than implementation.
