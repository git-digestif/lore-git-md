This is a three-patch series that builds on the earlier memory-leak fix in `test-mergesort` by fully migrating the sorting tests to Git’s Clar-based unit-test framework and retiring the old test helper and benchmark. The series is authored by Muhammed Dilshad A, who incorporated feedback from Patrick Steinhardt’s review of the initial leak-fix patch.

The first patch is unchanged from v1: it plugs the two memory leaks in `sort_stdin()` by adding the missing `mem_pool_discard()` and `strbuf_release()` calls. The second patch moves all 1,680 test cases from the old shell-based certification test (`t/t0071-sort.sh`) into a new Clar unit test (`t/unit-tests/u-mergesort.c`). It also removes the unused `generate` and `test` subcommands from the helper, leaving only the `sort` command for the now-optional benchmark. The third patch retires the old benchmark (`t/perf/p0071-sort.sh`), the shell test script, and the entire `test-mergesort` helper, along with their build-system registrations.

The new Clar suite preserves the original test coverage—checking sort order, stability, and list length—and adds explicit tests for empty and small lists. It also improves cleanup: backing arrays are freed directly, so a failed assertion no longer requires walking linked-list links. The series passes both Make and Meson unit tests, including LeakSanitizer, and leaves the production sorting implementation untouched.

This is a well-scoped modernization effort that removes dead code and consolidates tests in the preferred unit-test framework. The series is unlikely to be controversial, as it deletes more lines than it adds and aligns with the project’s ongoing test modernization goals. The only remaining loose end is whether to keep the `sort` subcommand for future benchmarking; the series leaves it in place, but the benchmark itself is removed.
