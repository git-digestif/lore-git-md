This is the latest reply in Patrick Steinhardt’s 13-patch series refactoring Git’s object database to move alternates handling into the files backend. The email is a direct response to Karthik Nayak’s review of patch 12/13, which raised a technical concern about a potential NULL-dereference regression in `clear_midx_file()`.

Patrick addresses Karthik’s question head-on: the removed `if (r->objects)` check was redundant because the function’s only caller already dereferences `r->objects` unconditionally, and the function itself does so later. The change is thus safe and removes a false sense of security. He also clarifies the broader architectural rationale for the series, explaining why the original design (multiple sources per ODB) was abandoned in favor of a files-backend-specific linked list of object directories. Karthik’s conceptual question about mapping objects to sources is resolved by Patrick’s vision of a future “merged source” backend that would handle such logic internally, without leaking implementation details to callers.

The discussion is now technically settled on the MIDX NULL-check issue, and the architectural direction is uncontroversial. The series remains a well-motivated refactoring that simplifies the ODB subsystem and enables future work like pluggable backends. Reviewers should focus on verifying the linked-list traversal invariants (e.g., alternates ordering) and edge cases like promisor remotes or quarantine cleanup, though no such issues have been raised yet. A reroll is unlikely unless new concerns surface.
