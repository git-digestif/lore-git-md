This is a documentation cleanup patch, part of Julia Evans’s effort to remove the obsolete `gittutorial-2` document. The patch deletes the bulk of the tutorial’s content, leaving only a minimal stub that redirects users to modern alternatives (`gitdatamodel[7]` and `gitcore-tutorial[7]`). The commit message explains that `gittutorial-2` is outdated—its approach of teaching Git by examining `.git/` internals is ineffective for most beginners—and its removal simplifies the documentation landscape, making it easier to rewrite the remaining `gittutorial` in the future.

The patch itself is straightforward: it replaces 416 lines of tutorial content with a six-line stub in `Documentation/gittutorial-2.adoc`. The stub retains the NAME, SYNOPSIS, and DESCRIPTION headers, explicitly marking the document as obsolete and pointing users to `gitdatamodel[7]` for low-level object model explanations and `gitcore-tutorial[7]` for practical internals exploration. No other files are modified in this patch, and there are no functional or on-disk format changes.

The rationale is well-supported: the commit message cites the tutorial’s 20-year stagnation, outdated terminology (e.g., "the index file"), and pedagogical ineffectiveness for beginners. It also notes that the material is now better covered by other documentation, making `gittutorial-2` redundant. The patch is uncontroversial and aligns with the broader goal of modernizing Git’s tutorial material, though the thread context indicates that the fate of the older `gittutorial` (part one) remains an open question.

This patch is the first in a two-patch v2 series (the second patch updates cross-references to `gittutorial-2`). The series has already been merged to `master`, and this resend addresses only surface-level feedback (dropping `.po` file changes and rewording commit messages). The build break in `seen` (caused by a missing entry in `command-list.txt`) was resolved via a merge-fix, so this patch is effectively final. For readers following the tutorial modernization effort, this is a clean, incremental step toward a more coherent documentation set.
