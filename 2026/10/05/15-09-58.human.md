This is a bugfix feature that adds a user-facing warning when creating a commit with a date earlier than its parent. The patch introduces a new `advice.clockSkew` configuration option that, when enabled, triggers a warning during `git commit` if the committer date is older than any parent commit's date. The motivation is clear: Git's history traversal (e.g., `git log --since`) assumes commit dates are non-decreasing, so out-of-order dates can cause commits to be incorrectly skipped.

The implementation is straightforward: it parses the committer date, compares it against each parent's date, and issues a warning via Git's advice system if the new commit is older. The warning includes both the new commit's date and the parent's date in ISO8601 format, making it easy for users to spot the discrepancy. The check is skipped for merges or replayed history, focusing only on new commits.

The patch includes tests in `t/t7502-commit-porcelain.sh` that verify the warning appears when expected and can be silenced via `advice.clockSkew=false`. The commit message and documentation are well-written, explaining the problem and solution clearly. This looks like a thoughtful, well-scoped addition that addresses a real usability issue without overcomplicating the code. The change is unlikely to be controversial, though the default behavior (whether the advice is enabled by default) might spark discussion.
