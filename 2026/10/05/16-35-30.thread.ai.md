Subject: [PATCH] stash: remove redundant change detection in `stash create`
Series version: standalone patch (no series)
Originating author: Phillip Wood
Thread type: bugfix patch

Core problem or goal
The `git stash create` subcommand contains redundant change detection logic that was introduced in ef0f0b4509 without justification. Specifically, `git stash store` checks for unstaged or uncommitted changes twice: once before refreshing the index (which is unreliable) and once afterward. The patch removes the first, redundant check to restore the original return code behavior, ensuring the command exits with status 0 when there are no changes to stash.
