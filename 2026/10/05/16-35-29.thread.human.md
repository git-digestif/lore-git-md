This thread is about a small refactoring series by Phillip Wood that removes redundant change-detection logic in `git stash push` and `git stash create`. The goal is to clean up duplicate `check_changes()` calls without changing behavior, though the series does adjust the return-value convention of `do_create_stash()` to distinguish "no changes to stash" from "nothing was stashed."

The first patch in the series, which this email addresses, fixes only the commit message after Junio C Hamano pointed out three instances where it incorrectly referenced `stash store` instead of `stash create`. The underlying code change—removing a redundant `check_changes()` call from `create_stash()`—remains the same and is now accurately described. The patch is ready to proceed once the corrected commit message is incorporated. The second patch, which introduces a minor inefficiency by causing a redundant index refresh, is still under discussion; Phillip plans a follow-up to address it.
