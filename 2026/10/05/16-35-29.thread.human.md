This thread is a focused refactoring effort by Phillip Wood to eliminate redundant `check_changes()` calls in `git stash push` and `git stash create`. The series, now at its first iteration (`v1`), consolidates duplicate change-detection logic in `builtin/stash.c` for code hygiene, with no intended behavior change—though a minor inefficiency was introduced in the process.

Junio C Hamano’s review identified that the second patch causes `do_push_stash()` to refresh the index unconditionally, only for `do_create_stash()` to refresh it again. While this was already happening when changes existed, it’s now systematic. Phillip acknowledges the issue but notes the regression is minor, as the first refresh marks index entries as up-to-date, reducing the cost of the second. However, he flags a deeper inefficiency: files are being `lstat()`ed multiple times before `check_changes()` is even called. Both agree the fix is to make callers responsible for refreshing the index, eliminating the redundancy and improving performance. Phillip plans to implement this follow-up, and no objections remain.

The series itself is uncontroversial, with only mechanical changes to `do_create_stash()` and `push_stash()`. The commit message for the first patch was corrected to address Junio’s feedback, and the only loose end—the redundant index refresh—is now resolved in principle. No other reviewers have weighed in, and the changes touch no new symbols, options, or on-disk formats. The next step is Phillip’s follow-up patch to refactor index refresh responsibility.
