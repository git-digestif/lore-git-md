This thread is about a performance-focused refactoring of `git stash` by Phillip Wood, evolving from an earlier two-patch series (`pw/stash-optimize-check_changes-calls/v1`) into a more ambitious seven-patch series (`v2`). The goal is to eliminate redundant index operations—specifically `lstat()` calls and index refreshes—that occur during `git stash push` and `git stash create`. The v2 series consolidates the earlier work (removing duplicate `check_changes()` calls) while also addressing inefficiencies in index loading and refreshing, reducing the number of `lstat()` calls per changed path by four for `create` and eight for `push`.

Phillip, a well-established contributor with deep expertise in the stash and sequencer subsystems, has incorporated Junio C Hamano’s feedback from the first iteration, fixing commit message typos and resolving the unconditional double index refresh in `do_push_stash()`. The series now makes callers responsible for refreshing the index, a change that both improves performance and simplifies the code. The patches are mechanical and well-motivated, with no intended behavior changes—only measurable reductions in `lstat()` overhead and clearer code structure. The series introduces an enum (`CREATE_NO_CHANGES`) to distinguish between "no changes to stash" and "nothing stashed" (e.g., when `--patch` selects no hunks), and simplifies the `reset_tree()` function signature.

The series is under active review, with no new edge cases or controversies introduced. If merged, it would likely land in `next` as part of the ongoing effort to streamline stash internals.
