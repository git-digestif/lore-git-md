This is a feature patch revising the filtering mechanism for `git repo structure`. The v2 series abandons the `--no-<reftype>` approach (e.g., `--no-tags`, `--no-branches`) proposed in v1 in favor of a more flexible revision-based filtering system. The new design allows users to specify arbitrary revisions (commits, refs, or ranges) as inclusion or exclusion roots, with the command processing all objects reachable from the includes unless they are exclusively reachable via the excludes. This aligns with Patrick Steinhardt’s earlier suggestion to use Git’s existing revision-parsing machinery (`setup_revisions()`), making the feature more powerful and consistent with commands like `git log`.

The implementation touches `builtin/repo.c` (adding revision parsing and reachability logic), `Documentation/git-repo.adoc` (documenting the new syntax), and `t/t1901-repo-structure.sh` (expanding test coverage to 84 lines). The core change replaces the enum-based flag system from v1 with a `struct rev_info` and `setup_revisions()` call, enabling arbitrary revision specifications (e.g., `git repo structure --branches --not --tags` or `git repo structure master`). The commit message now focuses on the "what" and "why" of the new design, omitting redundant details about the diff.

This revision directly addresses the central critique of v1: the `--no-<reftype>` flags were inflexible and inconsistent with Git’s idioms. The new approach is strictly more expressive, allowing users to filter by any revision (not just predefined reference types) and avoiding the problematic transitive dependency omission of v1. The design is now uncontroversial in principle, though reviewers may scrutinize the reachability logic or edge cases (e.g., overlapping includes/excludes).
