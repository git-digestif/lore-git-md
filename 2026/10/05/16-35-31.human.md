This is the second patch in Phillip Wood’s two-patch refactoring series `pw/stash-optimize-check_changes-calls/v1`, which removes redundant change-detection logic in `git stash push` and `git stash create`.

The patch eliminates the duplicate call to `check_changes()` in `do_push_stash()` and instead relies on the return value from `do_create_stash()` to determine whether there were any changes to stash. To preserve the correct exit codes for edge cases like `--patch` with nothing selected or `--staged` when the index matches HEAD, `do_create_stash()` now returns 2 (instead of 1) when no changes are found. The only minor behavioral change is that the stash reflog is now attempted before realizing there is nothing to stash, though Phillip notes this should not matter in practice.

The diff is small (12 insertions, 11 deletions) and focused on `builtin/stash.c`. The change is mechanical and does not introduce new functions or options, but it does tighten the control flow and exit semantics. As part of a well-motivated refactoring from an experienced contributor, this patch looks clean and uncontroversial.
