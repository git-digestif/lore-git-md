This is a substantive revision to the RFC for sharing Git stashes through remotes. Hanan Arshad now abandons the earlier `git stash publish` proposal after **Johannes Sixt (Hannes)**'s opposition, acknowledging that `git push origin stash@{0}:refs/stashes/...` already covers the publishing step. The new scope is strictly limited to porcelain wrappers for *discovery*, *fetching*, and *removal* of remote stash refs—operations that currently require manual use of `git ls-remote`, `git fetch`, and `git push --delete`.

The proposed interface (`git stash list --remote`, `git stash get`, `git stash remove`) would reuse existing Git plumbing without introducing new object formats, server-side changes, or mandatory ref namespaces. The motivation remains the Perforce-shelf-like handoff of unfinished work, but the design now avoids duplicating functionality already available via `git push`. The thread's central question shifts to whether even this narrowed convenience layer is justified, given Hannes's insistence that branches are the "right tool" for shareable work and that stashes should remain personal and ephemeral. No implementation or test coverage exists yet.
