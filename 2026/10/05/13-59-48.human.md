Harald Nordgren responds to Phillip Wood's decisive recommendation to drop the second patch (which aimed to link test failures and leaks directly to specific lines in test scripts). The regression—annotation links that only work if the test file was modified in the pull request—was deemed a show-stopper. Instead of abandoning the feature entirely, Harald proposes a middle ground: **showing the test script name (and line number when available) in the annotation text itself**, while preserving the existing job-output links. This would provide context (e.g., "memory leak logged in t1060 (t1060-object-corruption.sh)") without introducing broken links.

The proposal is pragmatic and addresses Phillip's core concern: the current job-output links are more useful than potentially broken diff links. By embedding the script name and line in the annotation text, users still get actionable information without sacrificing reliability. This approach avoids the complexity of the original line-finding logic (which failed for dynamically generated test descriptions) and sidesteps the need for a fallback mechanism. The first patch—stopping leak sanitizer jobs at the first failure and annotating leaks with the script name and full output—remains uncontroversial and is already cooking in `next`.
