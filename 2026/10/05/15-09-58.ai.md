This is a feature patch introducing a new warning for clock skew during commit creation. The patch adds a check in `builtin/commit.c` that compares the new commit's date against its parents' dates. If the new commit is dated earlier than any parent, Git emits a warning (controlled by the new `advice.clockSkew` configuration setting) explaining that this can break history traversal commands like `git log --since`.

The implementation is narrowly scoped: it only warns about the commit being created, not about existing history or merges. The warning is surfaced via the advice system, so users can silence it by setting `advice.clockSkew=false`. The patch includes tests in `t/t7502-commit-porcelain.sh` covering the warning trigger, the no-warning case, and the silencing behavior.

The motivation is clear and practical: clock skew can silently break date-based history traversal, and this warning lets users catch the problem at commit time when it is still easy to fix. The commit message and documentation are well-written and explain the user-facing impact. The code itself is straightforward, touching only the commit machinery and advice plumbing. No controversial design choices are apparent.

This looks like a well-crafted, focused feature that addresses a real (if niche) usability pain point. It should be uncontroversial and ready for review.
