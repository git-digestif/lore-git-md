This is the second patch in Phillip Wood’s v2 series that teaches `git checkout -m` to remember and recreate the original conflict labels (branch names) instead of generic "base", "ours", and "theirs". The patch is the functional core of the series, implementing the storage and retrieval of conflict labels via the new `.git/MERGE_LABELS` file and updating `git checkout -m` to use them.

The implementation is clean and well-scoped. It adds `write_merge_labels()` and `read_merge_labels()` functions to store and retrieve the three conflict labels (base, ours, theirs) in `.git/MERGE_LABELS`, a new ephemeral file analogous to existing merge-related files like `MERGE_MSG` or `MERGE_MODE`. The ort merge backend is updated to write the labels when conflicts are detected, and `git checkout -m` reads them when recreating conflicts. The patch ensures portability by using `strbuf_getline()` to handle both LF and CRLF line endings, addressing Junio’s feedback from v1. Edge cases (missing or malformed `.git/MERGE_LABELS`) are handled gracefully by falling back to generic labels.

The patch also introduces `REMOVE_BRANCH_STATE_PRESERVE_CONFLICT_LABELS` to prevent `remove_branch_state()` from deleting `.git/MERGE_LABELS` during `git checkout -m <branch>`, ensuring labels remain available for subsequent `git checkout -m <path>` calls. Cleanup is ensured via `git commit` and `git sequencer`, which remove the file when appropriate. The test in `t/t7201-co.sh` verifies that the labels are preserved and used correctly.

The implementation aligns with existing patterns in Git’s merge machinery, using `.git/MERGE_LABELS` for consistency with other merge-related files. The patch is focused, with no changes to on-disk formats or CLI options beyond the new file. Phillip’s handling of edge cases and cross-platform robustness demonstrates attention to detail, and the commit message clearly explains the motivation and design choices.

This patch is ready for integration, assuming no further feedback on the unresolved question about whether `git checkout -m` should also remember the original conflict style (e.g., `diff3`). The architectural discussion around index extensions remains open but is not blocking this series. The patch is a clear improvement over the current behavior and should be uncontroversial.
