Subject: [PATCH] commit: warn on clock skew during commit creation
Series version: v1 (initial submission)
Originating author: Devi Srinivas Vasamsetti
Thread type: patch series (single patch)

Core problem or goal
Introduce a warning when a commit’s date is earlier than any of its parents, which can break date-based history traversal commands like `git log --since`. The warning is controlled by the new `advice.clockSkew` configuration setting and is surfaced via Git’s advice system.

Current status
Under review; no prior versions. Patch adds a check in `builtin/commit.c`, emits the warning through the advice system, and includes tests in `t/t7502-commit-porcelain.sh`.

Key technical details
- Files touched: `builtin/commit.c`, `advice.c`/`advice.h` (advice plumbing), `Documentation/config/advice.txt` (new config key)
- New symbols: `advice.clockSkew` (config key), internal advice message string
- Behavior: warning emitted only for the commit being created, not for existing history or merges
- Test coverage: warning trigger, no-warning case, silencing via `advice.clockSkew=false`

Open questions and loose ends
Junio C Hamano has raised fundamental objections to the feature’s usefulness:
- The warning cannot address the root problem (clocks on other machines may already be wrong).
- The warning only triggers for the current commit, missing skew in existing history.
- Even if the warning were emitted, date-based traversal (`git log --since`) remains unreliable because it is impossible to know which timestamps are correct.
- The user has no clear action to take when the warning appears (wait, ask for a force-push, or something else).
- Junio advises users to avoid date-based options entirely if they need reliable results, suggesting the warning may not be worth the added complexity.

Participant positions
- **Junio C Hamano**: Substantive objection; questions the feature’s premise and usefulness. No Reviewed-by or Acked-by.
