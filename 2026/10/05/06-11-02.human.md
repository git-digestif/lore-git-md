This is a bugfix for `git filter-branch` that corrects a regression in the `--state-branch` option introduced in Git 2.50.0. The patch, now in its third version, has received a final acknowledgment from Patrick Steinhardt, signaling readiness for merging.

The issue stems from a Perl-removal refactor (commit f6d855091e) that accidentally inverted how commit mappings are read from the state branch. The state branch stores mappings as `from_commit:to_commit`, but the code was incorrectly interpreting them as `to_commit:from_commit`, causing the map directory to be populated backwards. This leads to errors like "Is a directory" when `--prune-empty` is used, as the script attempts to create files with empty names on subsequent runs. The fix is minimal: a two-line change in `git-filter-branch.sh` that correctly splits and assigns the commit pairs.

The patch is well-motivated and thoroughly tested. It updates the existing test to ensure the state branch is actually used (by forcing a tree-filter failure) and adds a new test case from Michele Locati that directly verifies the commit mapping correctness in incremental runs with `--prune-empty` and `--subdirectory-filter`. The test coverage is comprehensive, failing on current `master` without the fix and passing with it. All prior review feedback—from Junio C Hamano, Patrick Steinhardt, and Michele Locati—has been addressed, including commit message clarifications, test hygiene improvements, and a subject typo correction.

This version is self-contained, introduces no on-disk format changes, and has no remaining loose ends. The regression is clearly documented, and the fix is targeted and minimal. With Patrick Steinhardt’s explicit approval, this patch looks ready to merge.
