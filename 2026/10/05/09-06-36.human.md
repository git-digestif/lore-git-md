This is a feature proposal update from Hanan Arshad in the ongoing RFC thread about sharing Git stashes through remotes. After Hannes’s firm opposition to even a minimal `git stash publish` wrapper, Hanan now retreats from the idea entirely and refocuses the proposal on three narrower porcelain commands: `git stash list --remote`, `git stash get`, and `git stash remove`. These would wrap existing Git operations (`ls-remote`, `fetch` + `stash store`, and `push --delete`) to simplify discovering, fetching, and cleaning up remote stash refs, while leaving the publishing step to plain `git push`. The goal remains a Perforce-shelf-like temporary handoff of unfinished work, not persistent collaboration, and the design still avoids new object formats, server-side changes, or fixed ref namespaces.

The shift is a direct response to Hannes’s argument that the existing workflow (`git stash export` + `git push`) is already sufficient. By removing the `publish` command, Hanan concedes that point but still sees friction in the discovery, retrieval, and cleanup steps. The new proposal is essentially a set of syntactic sugar commands for those three operations, with no new underlying machinery. Whether this narrower scope will satisfy Hannes—or attract broader support—remains unclear; the thread’s core tension (whether stashes should ever be shareable, even temporarily) is still unresolved. No implementation or test coverage exists yet.
