This is an off-topic discussion about a potential C preprocessor optimization.

Jon Forrest, a retired UC Berkeley researcher, proposes modifying the C preprocessor to avoid unnecessarily opening header files. Currently, even with include guards (`#ifndef HTTP_H`), the preprocessor still opens every included file to check the guard. His idea is to have the preprocessor first check if the guard symbol (e.g., `HTTP_H`) is already defined before attempting to open the file. He suggests this could speed up builds for large C/C++ projects like Git, though he acknowledges the change would need to happen in the compiler toolchain, not in Git itself.

The email is purely speculative and invites feedback on whether this is a worthwhile optimization. There’s no patch, no data on potential speedups, and no indication that anyone is actively working on this. If you’re interested in build performance, this might be worth skimming, but it’s not actionable for Git development itself.
