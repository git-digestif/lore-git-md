This is a bugfix patch for `git filter-branch`, specifically addressing a regression in the `--state-branch` functionality introduced in Git 2.50.0. The patch is now in its final form (`v3`) and has received explicit approval from Patrick Steinhardt, one of the project's most active contributors. The core issue is a commit mapping inversion in the state branch file handling, where the code incorrectly reads "to_commit:from_commit" instead of the stored "from_commit:to_commit" format. This causes the map directory to be populated backwards, leading to errors like "Is a directory" when `--prune-empty` is used, as the script attempts to create files with empty names on subsequent runs.

The fix itself is minimal and targeted: a two-line change in `git-filter-branch.sh` that correctly splits each line on the colon and writes the `to_commit` into the file named by the `from_commit`. The patch also updates the existing test to ensure the state branch is actually used, and adds a new test case that directly verifies the commit mapping correctness in incremental runs with `--prune-empty` and `--subdirectory-filter`. The test coverage is now comprehensive, with the new test failing on current `master` without the fix and passing with it, confirming both the bug and the fix.

This version addresses all prior review feedback from Junio C Hamano, Patrick Steinhardt, and Michele Locati. The commit message now explicitly names the regressing commit (f6d855091e) and explains the test change rationale, while test hygiene is improved with `test_when_finished "rm -fr incremental"`. The patch is self-contained, introduces no on-disk format changes or new symbols, and has been tested by multiple contributors. Patrick Steinhardt's approval ("I'm happy with this version") signals that the patch is ready for merging, with no further changes expected unless Junio identifies a new issue.

The regression was introduced during the Perl-removal refactor in Git 2.50.0, and the patch restores the correct behavior for users who rely on `--state-branch` for incremental repository splitting. The fix is well-motivated, thoroughly tested, and has no remaining loose ends. This is a clear example of a well-crafted bugfix that addresses a real problem with minimal risk.
