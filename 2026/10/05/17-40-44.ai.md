This is a feature patch (v2 of a single-patch series) adding revision-based filtering to the `git repo structure` command. The patch replaces the v1 `--no-<reftype>` approach with Git’s standard `setup_revisions()` machinery, allowing users to include or exclude arbitrary revisions (e.g., `git repo structure --branches --not --tags` or `git repo structure master ^foo`). This directly addresses Patrick Steinhardt’s critique of v1 as inflexible and inconsistent with Git’s idioms.

The implementation touches `builtin/repo.c` (adding revision parsing and reachability logic), `Documentation/git-repo.adoc` (documenting the new syntax), and `t/t1901-repo-structure.sh` (expanding test coverage to 84 lines). The core change replaces the v1 enum-based flag system with a `struct rev_info` and `setup_revisions()` call, enabling arbitrary revision specifications while avoiding the transitive dependency omission issue of v1. The reachability logic now processes all objects reachable from included revisions unless they are exclusively reachable via excluded revisions.

The patch is uncontroversial in principle, as it adopts the design Patrick proposed in v1. However, the reachability logic may attract scrutiny for edge cases (e.g., overlapping includes/excludes, unreachable objects). The test coverage is thorough, validating output formats and edge cases, but no reviewers have yet weighed in on v2. The commit message focuses on the "what" and "why" of the new design, omitting redundant diff details.

Key symbols introduced or modified include `setup_revisions()`, `struct rev_info`, and the `REPO_STRUCTURE_USAGE` macro. The CLI syntax now supports revision specifications like `git repo structure <revision>... [--not <revision>...]`. No performance implications are discussed, and the patch does not interact with other ongoing efforts.
