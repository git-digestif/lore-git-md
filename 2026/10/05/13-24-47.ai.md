This is the v2 submission of Phillip Wood’s two-patch series that teaches `git checkout -m` to recreate the original conflict labels (branch names) instead of the generic “base”, “ours”, and “theirs”. The series is now ready for review after addressing Junio’s feedback on line-ending portability and documentation clarity.

Patch 1 remains unchanged: it refactors `remove_branch_state()` to use an `unsigned flags` field instead of a `verbose` boolean, introducing `REMOVE_BRANCH_STATE_VERBOSE` as the sole flag. This is a pure refactoring with no user-visible change.

Patch 2 is the functional change. It stores the original conflict labels in `.git/MERGE_LABELS` when the ort backend switches to a merge result containing conflicts, and updates `git checkout -m` to read that file and reuse the same labels. The implementation now uses `strbuf_getline()` to read the labels, ensuring consistent newline handling with the writing side and fixing the CRLF portability issue raised in v1. Edge cases (missing or malformed `.git/MERGE_LABELS`) are handled by falling back to generic labels, and cleanup is ensured via `git commit` and `git sequencer`. The patch adds a test in `t/t7201-co.sh` to verify label preservation.

Phillip has explicitly rejected Johannes Sixt’s suggestion to use an index extension instead of `.git/MERGE_LABELS`, citing compatibility with other merge strategies (`MERGE_MODE`, `MERGE_RR`, `MERGE_MSG`) and alignment with existing patterns. The architectural discussion around index extensions remains open but is not blocking this series.

The open question from v1—whether `git checkout -m` should also remember and restore the original conflict style (e.g., `diff3`)—is still unresolved. Phillip invites feedback on whether this would be convenient or confusing, but no responses have been recorded yet.

The series is small, focused, and well-scoped. The implementation is solid, with clear commit messages and test coverage. The change is user-facing but not disruptive, affecting only the appearance of conflict markers. Phillip’s handling of feedback and edge cases suggests this is a mature contribution ready for integration. The unresolved question about conflict style is the only loose end, but even if deferred, the label preservation itself is a clear improvement.
