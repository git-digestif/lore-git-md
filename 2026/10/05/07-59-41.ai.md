This is a **substantive review** of the documentation patch (1/2) in Kristofer Karlsson’s incremental connectivity check series. Patrick Steinhardt engages with the technical content of the new `Documentation/technical/connectivity-check.adoc` document, raising three main points:

1. **Connectivity invariant clarification**: He suggests explicitly stating the reverse of the invariant—that objects *not* reachable from any reference cannot be assumed to be connected—even if they exist in the object database. This is a precision issue: the current text implies but does not state that unreachable objects are untrusted, which could lead to incorrect assumptions in future code.

2. **Code reference hygiene**: He objects to the direct mention of `check_connected()` and `connected.c` in the document, arguing that such references risk becoming stale as the code evolves. He prefers either moving the documentation into the source file itself or omitting the code reference entirely.

3. **Phase description critique**: He finds the three-phase breakdown of the full connectivity check redundant, saying it merely restates how revision walks work without adding insight specific to connectivity. He also questions the "subsequent object traversal" mentioned for non-commit tips, asking for clarification on what that traversal is.

The review is narrowly focused on the documentation’s accuracy and maintainability, not on the incremental mode itself (which is covered in patch 2/2). No new technical concerns about the implementation are raised here, but the feedback, if addressed, would tighten the document’s precision and longevity. The tone is constructive and matter-of-fact, typical of Patrick’s thorough reviews.
