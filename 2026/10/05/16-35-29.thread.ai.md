Thread identity: Refactoring patch series `pw/stash-optimize-check_changes-calls/v3` by Phillip Wood, targeting redundant change-detection logic, index loads, and refreshes in `git stash push` and `git stash create`.

Core problem or goal: Eliminate redundant `check_changes()` calls, index loads (`repo_read_preload_index()`), and refreshes (`refresh_index()`) in `git stash push` and `git stash create`. The series consolidates duplicate operations, reducing `lstat()` calls per changed path by four for `create` and eight for `push`, and untracked-file walks by one. The return-value convention of `do_create_stash()` is refined with an enum (`enum create_result`) to distinguish "no changes to stash" (`CREATE_NO_CHANGES`), "nothing stashed" (e.g., `--patch` with no hunks selected, `CREATE_EMPTY`), and success/error states. The series also corrects a minor behavioral anomaly: `create_stash()` previously exited with status 1 when `do_create_stash()` returned 1 (indicating no changes), even though `create_stash()` itself had already determined there were no changes via `check_changes()`. The patch ensures consistent exit statuses—`create_stash()` now exits 0 when there are no changes to stash, aligning with its documented behavior. No other user-visible behavior changes are intended.

Performance gains are modest (reduced `lstat()` overhead) but measurable; code hygiene improvements are clear. The first patch introduces `enum create_result` to replace the integer return type of `do_create_stash()`, distinguishing between success, errors, and cases where no changes were stashed. It also corrects the exit-status anomaly in `create_stash()`, ensuring consistent behavior: `git stash push --patch` (no hunks selected) and `git stash push --staged` (index matches `HEAD`) still exit with status 1, while a no-op `git stash push` exits 0. The second patch removes the duplicate `check_changes_tracked_files()` call in `create_stash()` and eliminates the redundant `repo_read_index()` call in `check_changes_tracked_files()`, as all callers now refresh the index before invoking it. The third patch removes a redundant `check_changes()` call in `do_push_stash()` and eliminates an unnecessary index refresh, leveraging the `enum create_result` to maintain consistent exit statuses. The fourth patch removes duplicate `preload_index()` calls by shifting index-reading responsibility to callers of `do_create_stash()` and replacing `repo_read_index_preload()` with `repo_read_index()` in `create_stash()` and `do_push_stash()`, and removing the redundant `repo_read_index_preload()` call in `do_create_stash()` itself. This change cuts two unnecessary `lstat()` calls per changed path, reducing the total from three to one during a typical `git stash push`. The fifth patch replaces `reset_tree()` with `create_index_from_tree()` in `stash_working_tree()`, adding a `reset` boolean parameter to control whether the index is reset or merged into, preserving intent-to-add entries and eliminating an unnecessary `repo_read_index_preload()` call. The change avoids reliance on the global `set_alternate_index_output()` mechanism, prevents overwriting the in-memory index, and aligns the implementation with the existing pattern used for `git stash push -p`. Junio’s review of this patch was substantive, engaging with the technical rationale and outcome, and calling it "the most interesting step in the series" for its elimination of in-core index flipping and side effects. The sixth patch removes redundant index load and refresh operations in `create_index_from_tree()`, as these are already performed by its caller, `do_create_stash()`, saving three `lstat()` calls per changed path. The seventh patch simplifies `reset_tree()` by removing unused parameters (`update` and `reset`), leaving it as a focused helper for merging a tree into the index without touching the worktree.
