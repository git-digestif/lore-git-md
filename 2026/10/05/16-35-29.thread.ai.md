Thread identity: Refactoring patch series `pw/stash-optimize-check_changes-calls/v3` by Phillip Wood, targeting redundant change-detection logic, index loads, and refreshes in `git stash push` and `git stash create`.

Core problem or goal: Eliminate redundant `check_changes()` calls, index loads (`repo_read_preload_index()`), and refreshes (`refresh_index()`) in `git stash push` and `git stash create`. The series consolidates duplicate operations, reducing `lstat()` calls per changed path by four for `create` and eight for `push`, and untracked-file walks by one. The return-value convention of `do_create_stash()` is refined with an enum (`enum create_result`) to distinguish "no changes to stash" (`CREATE_NO_CHANGES`), "nothing stashed" (e.g., `--patch` with no hunks selected, `CREATE_EMPTY`), and success/error states. The series also corrects a minor behavioral anomaly: `create_stash()` previously exited with status 1 when `do_create_stash()` returned 1 (indicating no changes), even though `create_stash()` itself had already determined there were no changes via `check_changes()`. The patch ensures consistent exit statuses—`create_stash()` now exits 0 when there are no changes to stash, aligning with its documented behavior. No other user-visible behavior changes are intended.
