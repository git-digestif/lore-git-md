This thread introduces a new warning for clock skew during commit creation, authored by Devi Srinivas Vasamsetti. The feature checks if a new commit's date is earlier than any of its parents and emits a warning (via Git's advice system) if so, as this can break date-based history traversal commands like `git log --since`. The warning is configurable via `advice.clockSkew` and is narrowly scoped to the commit being created, avoiding interference with existing history or merges.

The patch is well-contained, touching only `builtin/commit.c` and the advice plumbing, and includes tests in `t/t7502-commit-porcelain.sh` to verify the warning's behavior. The motivation is practical—catching clock skew at commit time when it's easiest to fix—and the implementation appears straightforward and uncontroversial. No reviews or feedback have been posted yet, so the patch is currently awaiting initial technical scrutiny. If the design holds up under review, this should be a smooth addition to Git's usability tooling.
