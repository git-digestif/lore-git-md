This is a **feature patch revision** for `git blame`, responding to Junio C Hamano’s feedback on the initial proposal to default to `.git-blame-ignore-revs`. The author, Ravi Mistry, now plans to switch from using the working tree file to the `HEAD:.git-blame-ignore-revs` blob, aligning local behavior with hosting sites like GitHub and GitLab. This addresses the behavioral inconsistency Junio identified, where local blame output could diverge from web views due to untracked or modified ignore files.

The revised approach eliminates the need to access the working tree, simplifying the security story. Ravi has audited the parser in `oidset.c` and `builtin/blame.c` and proposes two tightening measures: rejecting lines with embedded NUL bytes (currently ignored by `strchr` and `parse_oid_hex_algop`) and using `OBJECT_INFO_SKIP_FETCH_OBJECT` and `OBJECT_INFO_QUICK` in `peel_to_commit_oid` to avoid triggering lazy promisor fetches in partial clones. These changes aim to mitigate the security concerns Junio raised about parsing upstream-controlled content.

The patch is still under review, but the shift to the `HEAD` blob is a clear improvement over the initial design. The security audit appears thorough, though Junio may weigh in on whether the proposed fixes are sufficient. If accepted, this change will make `git blame` more intuitive for users who expect local and web-based blame output to match without manual configuration. The next step is a v2 patch incorporating these adjustments.
