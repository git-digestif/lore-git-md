This is Junio’s reply to Phillip Wood’s v2 cover letter for the `git checkout -m` conflict label preservation series. Junio engages with the open question about whether `git checkout -m` should also remember and restore the original conflict style (e.g., `diff3`) when recreating conflicts.

Junio frames the conflict style question as a usability trade-off. He notes that the only scenario where remembering the style would matter is when the original merge used a one-shot custom style (e.g., `git -c merge.conflictStyle=diff3 merge topic`) that differs from the user’s usual configuration. In such cases, the user would currently need to manually specify the style again when running `git checkout -m`, whereas remembering it would save effort.

He illustrates the potential convenience with an example: a user who normally uses the default `merge` conflict style might run `git merge topic`, find the conflict markers unhelpful, and then use `git -c merge.conflictStyle=diff3 checkout -m \*` to recreate the conflicts with the more informative `diff3` style. Remembering the original style would automate this step, making the workflow smoother.

Junio does not take a firm position on whether remembering the style is a good idea, but his framing suggests he sees it as a reasonable enhancement rather than a source of confusion. The tone is exploratory, inviting further discussion rather than endorsing or rejecting the proposal. No new technical concerns are raised, and the architectural discussion about index extensions is not revisited. The series itself remains ready for integration, with the conflict style question the only unresolved point.
