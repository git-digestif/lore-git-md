This is a **feature patch revision** for the `git blame` ignore-revs default file. The author, Ravi Mistry, responds to Junio C Hamano’s substantive feedback by accepting the core design change: switching from the working tree `.git-blame-ignore-revs` file to the `HEAD:.git-blame-ignore-revs` blob. This aligns local behavior with hosting sites (GitHub, GitLab) and eliminates the security concern about parsing upstream-controlled content at a fixed working tree path.

The email outlines two security-focused refinements to the ignore-file parser. First, it proposes rejecting lines with embedded NUL bytes by using `memchr` in `oidset.c`, tightening the current behavior where `strchr` and `parse_oid_hex_algop` stop at the first NUL but may ignore trailing bytes. Second, it suggests passing `OBJECT_INFO_SKIP_FETCH_OBJECT` and `OBJECT_INFO_QUICK` in `peel_to_commit_oid` to prevent lazy promisor fetches in partial clones when peeling tags or resolving missing OIDs. These changes address Junio’s call for a security audit of the parser, which now processes the `HEAD` blob by default.

The patch remains part of the blame subsystem, touching `builtin/blame.c` and `oidset.c`. No new symbols are introduced; the focus is on hardening the existing ignore-file logic. The author’s plan for v2 appears technically sound and directly responsive to the maintainer’s concerns, though the final implementation will need to demonstrate the security improvements.
