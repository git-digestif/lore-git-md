This is a **feature patch** for `git blame` that has drawn **substantive review feedback** from Junio C Hamano. The patch proposes making `git blame` automatically use a `.git-blame-ignore-revs` file in the repository root if no explicit ignore file is configured, aligning local behavior with GitHub and GitLab.

Junio’s response identifies two key issues. First, the current implementation reads the ignore file from the working tree, which can diverge from the committed state (`HEAD:.git-blame-ignore-revs`). This creates inconsistency with hosting sites, which operate on the committed version. Junio suggests instead using the blob at `HEAD:.git-blame-ignore-revs` as the default, ensuring local and hosted blame output match regardless of working tree state.

Second, Junio raises a **security concern**: the patch introduces a new attack surface by parsing upstream-controlled content at a fixed path. The current implementation uses `lstat()` to reject symlinks and non-regular files, but Junio points out that the parser itself must be audited to ensure it cannot be exploited via maliciously crafted ignore files. He also notes that reading from `HEAD:.git-blame-ignore-revs` would eliminate the need for `lstat()` checks entirely, as the blob is already trusted.

The review is substantive and technical, focusing on correctness, security, and consistency with ecosystem behavior. No alternative approaches are proposed yet, but the feedback clearly signals that the patch will need revision before it can proceed. The author will likely need to address both the working-tree vs. committed-state discrepancy and the parser security audit in a follow-up version.
