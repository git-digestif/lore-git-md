This is a **documentation review** of the first patch in Kristofer Karlsson’s v2 series introducing incremental connectivity checking for Git fetches and pushes. Patrick Steinhardt provides **substantive feedback** on the new technical document `Documentation/technical/connectivity-check.adoc`, focusing on clarity, completeness, and maintainability.

The review homes in on three key areas. First, Patrick suggests clarifying the *reverse* of the connectivity invariant: objects not reachable from any reference cannot be assumed to be connected, even if they exist in the object database. This is a subtle but important point for understanding what the check actually guarantees. Second, he questions the value of the three-phase description of the full check, arguing it mostly restates how `rev-list` walks work without adding insight specific to connectivity. Third, he flags a confusing reference to a "subsequent object traversal" for non-commit tips (tags, trees, blobs), asking for clarification on what that traversal is and how it fits into the overall process.

Patrick also raises a **maintainability concern**: the document directly names `check_connected()` and `connected.c`, which risks the documentation going stale if the code moves or is renamed. He suggests either embedding the documentation directly in the source file or avoiding code references altogether. His feedback is precise and technical, engaging with the *content* of the documentation rather than just its wording or formatting. No merge status is implied; this is still under review.
