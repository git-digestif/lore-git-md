This is a performance optimization for the packed-refs backend, now receiving a final review from Toon Claes. The patch, in its second version, speeds up operations that rewrite the packed-refs file by avoiding redundant formatting of unchanged references. Instead of using `fprintf()` for every entry, it tracks raw byte positions and writes them directly with `fwrite()`, yielding a consistent ~20% performance improvement when deleting 100,000 packed refs.

Toon’s review here is surface-level, focused on minor wording corrections in the commit message ("side effect" instead of "side", "commit message" instead of "commit"). He explicitly states he is okay with this version, marking the end of his feedback. The substantive concerns he raised earlier—documenting the side effects of bypassing `fprintf()` and splitting the write logic into separate functions—have already been addressed in v2.

The patch touches only `refs/packed-backend.c` and introduces a new `write_packed_entry_raw()` function alongside the existing `write_packed_entry()`. The key trade-off is that unchanged refs are written verbatim, preserving original formatting (case, whitespace, malformed refnames, peeled OIDs for broken refs), which could affect tools parsing packed-refs files. This is now clearly documented in the commit message.
