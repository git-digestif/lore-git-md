This is a follow-up in the ongoing RFC thread about adding porcelain commands for sharing Git stashes through remotes. The author, Hanan Arshad, responds to Johannes Sixt’s strong opposition by narrowing the proposal’s scope and clarifying its intent.

Hanan acknowledges that stashes should remain short-lived and personal, but argues there is a narrow use case for temporarily sharing an unfinished working state—similar to Perforce shelves—without converting it into a formal branch. The key question is whether Git should provide a convenience command for an operation that is already possible (but cumbersome) using existing plumbing (`git stash export`, `git push`, `git fetch`, `git stash import`). The proposal does not introduce new object formats, server-side storage, or synchronization mechanisms; it merely wraps existing functionality in porcelain.

Hanan suggests scaling back the original design to a minimal version—perhaps just a `git stash publish` command—leaving listing, fetching, and deletion to existing Git commands. This would address Hannes’s concern about over-engineering while still providing value for the targeted use case. The response is measured and directly engages with the philosophical objection, but it remains unclear whether Hannes will accept even a narrowly scoped porcelain wrapper. The thread is still open, with no consensus on whether the feature aligns with Git’s design principles.
