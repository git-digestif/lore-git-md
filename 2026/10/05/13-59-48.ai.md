This is a CI/build system follow-up in the ongoing effort to improve GitHub Actions failure reporting for Git's CI.

Harald Nordgren proposes a compromise for the abandoned second patch: instead of linking annotations to test-script lines (which broke when the test file wasn't modified in the pull request), he suggests embedding the file name and line number directly in the annotation text while preserving the existing job-output links. The examples show two formats: one for memory leaks (`memory leak logged in t1060 (t1060-object-corruption.sh)`) and one for test failures (`failed: t1060.17 partial clone of corrupted repository (t1060-object-corruption.sh:141)`). This approach avoids the regression while still providing more context than the current behavior.

The proposal directly addresses Phillip Wood's show-stopper concern about broken links while maintaining the usability improvement of surfacing the test script and line number. It keeps the first patch's improvements (stopping at first leak failure with collapsible output) intact. No new technical mechanisms are introduced; this is purely a presentation-layer adjustment to the annotation format.

Thread context shows this is a targeted refinement to salvage value from the abandoned patch rather than a revival of the original design. The compromise appears pragmatic and low-risk, though it remains to be seen whether Phillip Wood (who previously recommended dropping the patch entirely) will find this acceptable.
