This is the first patch in Phillip Wood’s two-part series to teach `git checkout -m` to remember and reuse the original conflict labels (branch names) instead of generic "base", "ours", and "theirs". This patch is a pure refactoring with no user-visible behavior change.

The patch converts the `verbose` boolean argument in `remove_branch_state()` to an `unsigned flags` field, introducing `REMOVE_BRANCH_STATE_VERBOSE` as the sole flag. This preparatory step enables the next patch to add a new flag (`REMOVE_BRANCH_STATE_PRESERVE_CONFLICT_LABELS`) for preserving conflict labels. The change is mechanical and confined to `branch.c`, `branch.h`, and `builtin/checkout.c`.

The patch itself is small and focused, touching only the necessary code to support the flags conversion. There are no edge cases or portability concerns here—this is straightforward plumbing work.
