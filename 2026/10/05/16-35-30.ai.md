This is a bugfix patch targeting the `git stash` command, specifically the `stash create` subcommand. It removes redundant change detection logic that was introduced in an earlier commit (ef0f0b4509) but never justified as an optimization.

The patch addresses a long-standing inefficiency where `git stash store` checks for unstaged or uncommitted changes twice: once before refreshing the index and again afterward. The first check is unreliable because it happens before the index is refreshed, making it redundant. Phillip Wood restores the original return code handling to ensure the command exits with status 0 when there are no changes to stash, maintaining expected behavior.

The change is minimal, touching only `builtin/stash.c` and removing the unnecessary call to `check_changes_tracked_files()`. The commit message clearly explains the history and rationale, making it easy to assess the fix. This looks like a well-motivated cleanup that should reduce confusion and potential edge cases in the stash creation logic. No controversy is evident from the patch itself.
