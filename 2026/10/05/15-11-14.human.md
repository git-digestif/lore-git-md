This is a CI/build system follow-up to a patch series improving GitHub Actions failure reporting in Git's CI. The thread has been iterating on how to surface test failures and leak sanitizer output more clearly.

Phillip Wood responds to Harald Nordgren's compromise proposal for the abandoned second patch in the series. The compromise suggests embedding the test script name (and line number when available) directly in the annotation text while keeping the existing job-output links intact. For example, memory leaks would show as `memory leak logged in t1060 (t1060-object-corruption.sh)` and test failures as `failed: t1060.17 partial clone of corrupted repository (t1060-object-corruption.sh:141)`. Phillip finds this "could be useful" and does not object, though his tone is measured rather than enthusiastic.

The first patch in the series—stopping leak sanitizer jobs at the first failure and annotating leaks with collapsible output—remains cooking in `next` and is unaffected by this discussion. The compromise directly addresses Phillip's earlier show-stopper concern about broken annotation links in the original second patch, which he had formally recommended dropping. His response here is effectively a green light for Harald to proceed with the revised approach, though it stops short of an explicit endorsement.

This exchange resolves the last major blocker for the series' usability improvements. The outcome is pragmatic: the first patch is already viable, and the second patch's key value (surfacing test script context) is salvaged without reintroducing the regression. No further iteration appears needed unless someone raises new concerns.
