This is a substantive review reply in the ongoing RFC thread about adding porcelain commands for sharing Git stashes through remotes. Johannes Sixt (Hannes) directly rejects the narrowed proposal, reinforcing his earlier opposition with a concise technical argument: the existing workflow (`git stash export` + `git push` or even just `git push` of a stash commit) already achieves the stated goal, so no convenience wrapper is justified. He frames the feature as unnecessary complexity, arguing that if the use case is frequent enough to warrant porcelain, users should instead adopt branches—the "right tool" for shareable work. The tone remains firm, with no compromise offered; the objection is to the concept itself, not just the implementation. This reply effectively closes the door on the current proposal unless Hanan Arshad can demonstrate a gap in usability that branches cannot fill. The thread now hinges on whether other participants see value in reducing friction for a niche but valid workflow, or whether Hannes’s position—that stashes should remain strictly personal and ephemeral—will prevail. No new technical details are introduced, but the exchange clarifies that the debate is now purely about workflow philosophy and tooling minimalism.
