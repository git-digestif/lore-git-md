This is a **platform compatibility bugfix** addressing 64-to-32-bit truncations on Windows (LLP64 platforms). The email is a reply to Patrick Steinhardt’s **surface-level review** of the first patch in Elia Pinto’s **v2 series**, which widens the ODB write functions’ length parameter from `unsigned long` to `size_t` to prevent silent truncation of objects larger than 4 GiB.

Elia acknowledges Patrick’s feedback and clarifies the test logic: the original test compared the *size* of the object (not its content) to the expected size, which was redundant because the OID comparison already verifies correctness. If truncation had occurred, the OID would mismatch, making the size check unnecessary. Elia confirms this by simulating truncation, which causes the OID check to fail. The revised test in **v3** will drop the size comparison entirely, replacing it with a lightweight existence check (`git cat-file -e`) to avoid reading 5 GiB of data twice.

The discussion also resolves Patrick’s concern about reading from and writing to the same file (`actual`). Elia agrees this was fragile and will remove the size check, eliminating the need for the file altogether. The use of `test_cmp_bin` is mooted since the test now only compares text OIDs.

This exchange is **procedural and test-focused**, with no technical objections to the core fix. The series remains on track for integration, pending a **v3** iteration to address the test hygiene improvements. The broader goal—preventing data corruption, crashes, and incorrect metadata handling on Windows—is unaffected by these changes.
