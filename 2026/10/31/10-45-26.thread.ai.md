Thread identity
Subject: [PATCH v2 0/6] notes: store repository in `struct notes_tree` and remove `USE_THE_REPOSITORY_VARIABLE` guard
Series version: v2 (six-patch series, now complete)
Originating author: Okhuomon Ajayi (Outreachy intern)
Thread type: patch series (architectural refactoring)

Core problem or goal
Remove implicit uses of the global `the_repository` in the notes subsystem by storing the repository in `struct notes_tree` and updating all notes API functions to use it. This directly addresses Patrick Steinhardt's architectural concern by fixing unsafe functions at the source, eliminating the need for downstream guards and making the API repository-agnostic.

Current status
Six-patch series now complete and under active review; no merge status (not in `seen`, `next`, or `master`). Patches 1/6--6/6 have been posted, incrementally refactoring `notes.c` and `notes-utils.c` to use `struct notes_tree->repo` or explicit `struct repository *` parameters. The series is structured to handle remaining `the_repository` uses incrementally; temporary use in callers (e.g., `builtin/notes.c`, `notes-cache.c`) will be addressed in later work. Patrick Steinhardt's interface feedback (renames and parameter order) has been incorporated in the v2 iteration: `init_notes()` is now `notes_tree_init()` with `struct notes_tree *` as its first parameter, and `load_notes_trees()` is now `notes_tree_load()`. The remaining `USE_THE_REPOSITORY_VARIABLE` guard in `notes.c` is intentionally scoped to functions that rely on the global `default_notes_tree` or do not propagate a repository parameter (e.g., `display_notes()`, `expand_loose_notes_ref()`, hash-size helpers), as Okhuomon Ajayi has clarified in replies to both Patrick Steinhardt and the list. Okhuomon Ajayi has posted a procedural follow-up replying to Patrick Steinhardt's comment on patch 5/6 (in which Patrick asked why the series does not eliminate the guard in `notes.c` entirely), requesting explicit confirmation that this scoping is acceptable before she posts v2 rebased on current `master`. Christian Couder has now additionally suggested dropping patch 6/6 (which removes the guard from `notes-utils.[c,h]`) and reframing the series as a preparatory step, to avoid a mixed state where `notes-utils.c` appears fully converted while its functions (e.g., `create_notes_commit()`) call into `notes.c` functions that still rely on the global `the_hash_algo` via hash-size helpers.

Key technical details
Files: `notes.c`, `notes-utils.c`, `notes-utils.h`, `notes.h`, and callers in `builtin/am.c`, `builtin/notes.c`, `notes-cache.c`, `sequencer.c`
Symbols:
- `struct notes_tree` contains a `struct repository *repo` field (added in patch 1/6)
- Updated signatures (with renames now implemented in v2):
  - `notes_tree_init(struct notes_tree *, const char *, combine_notes_fn, int, struct repository *)` (patch 1/6)
  - `notes_tree_load(struct string_list *, struct repository *)` (patch 1/6)
  - Seven core functions in `notes.c` updated to use `t->repo` (patches 2/6 and 3/6): `note_tree_find()`, `add_non_note()`, `load_subtree()`, `remove_note()`, `format_note()`, `write_notes_tree()`, and `prune_notes()`
  - Ref glob helpers updated to take an explicit `struct repository *` parameter (patch 4/6): `string_list_add_refs_by_glob(struct repository *, struct string_list *, const char *)` and `string_list_add_refs_from_colon_sep(struct repository *, struct string_list *, const char *)`
  - `combine_notes` callbacks updated to accept an explicit `struct repository *` parameter (patch 5/6): `concatenate_notes()`, `overwrite_notes()`, `ignore_notes()`, and `cat_sort_uniq_notes()`
  - `typedef int (*combine_notes_fn)(struct repository *, struct object_id *, const struct object_id *)` (patch 5/6)
  - `copy_note()` updated to use the tree's hash algorithm (`t->repo->hash_algo`) for its null object ID instead of the global hash algorithm (patch 5/6)
  - `create_notes_commit()` and `commit_notes()` updated to use the passed repository instead of `the_repository` (patch 6/6)
  - `init_copy_notes_for_rewrite()` now takes a `struct repository *` parameter (patch 6/6)
- Helper structs `write_each_note_data`, `prune_notes_data`, and `notes_rewrite_cfg` include a `struct repository *` field to propagate the repository through the call chain (patches 3/6 and 6/6)
- New behavior: `notes.c` and `notes-utils.c` functions use `struct notes_tree->repo` or an explicit `struct repository *` parameter instead of `the_repository`, making the API repository-agnostic without guards
- Removed: `USE_THE_REPOSITORY_VARIABLE` guard from `notes-utils.c` and `notes-utils.h` (patch 6/6)
- Remaining guard: `USE_THE_REPOSITORY_VARIABLE` in `notes.c` itself, intentionally scoped to functions that rely on the global `default_notes_tree` or do not propagate a repository parameter (e.g., `display_notes()`, `expand_loose_notes_ref()`, hash-size helpers)
- Inconsistency noted by Christian Couder: patch 6/6 removes the guard from `notes-utils.[c,h]`, yet `create_notes_commit()` in `notes-utils.c` calls `write_notes_tree()` in `notes.c`, which depends on hash-size helpers that still use the global `the_hash_algo`, creating a mixed state across the API boundary
- No CLI options, config keys, or on-disk format changes
- Architectural note: The global `default_notes_tree` in `notes.c` is acknowledged as problematic due to its implicit global state, but fixing it is outside the scope of this series
