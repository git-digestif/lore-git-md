Thread identity: Subject `[PATCH v5 0/6] notes: store repository in struct notes_tree and remove USE_THE_REPOSITORY_VARIABLE guard`, series version v5 (six-patch series), originating author Okhuomon Ajayi (Outreachy intern), thread type patch series (architectural refactoring). The relabeling to v5 corrects a version-labeling collision noted by Junio C Hamano: an earlier two-patch series was also labeled "v2", and the prior six-patch iteration should have been marked as a new version, so the previous round was effectively v4 and this round is v5.

Core problem or goal: Remove implicit uses of the global `the_repository` in the notes subsystem by storing the repository in `struct notes_tree` and updating notes API functions to use it, addressing Patrick Steinhardt's architectural concern at the source rather than relying on downstream `USE_THE_REPOSITORY_VARIABLE` guards.

Current status: Series under active review; no evidence of merge to `seen`, `next`, or `master`. v5 consists of six patches. Patch 1/6 adds the static helper `notes_tree_or_default()` encapsulating `if (!t) t = &default_notes_tree(); assert(t->initialized);`; six public entry points -- `add_note()`, `remove_note()`, `get_note()`, `for_each_note()`, `write_notes_tree()`, and `prune_notes()` -- now use it, while `notes_tree_init()`, `free_notes()`, and `format_note()` deliberately retain their own initialization logic. All public entry points, including `copy_note()`, now route through this helper, directly fixing the previously confirmed NULL-dereference bug in `copy_note()`. Patch 2/6 adds `struct repository *repo` to `struct notes_tree` in `notes.h` and stores the repository pointer during initialization, establishing the structural foundation for later patches. It renames `init_notes()` to `notes_tree_init(struct notes_tree *t, struct repository *r, const char *notes_ref, combine_notes_fn combine_notes, int flags)` (saving `r` into `t->repo` before proceeding) and `load_notes_trees()` to `notes_tree_load(struct repository *r, struct string_list *refs, int flags)`, and adds doc comments for the `r` and `flags` parameters of `notes_tree_init()`. Call sites updated in patch 2/6 include `builtin/notes.c` (three locations passing `the_repository` temporarily), `notes-cache.c` where `notes_cache_init()` passes its given repository, `notes-utils.c` where `init_copy_notes_for_rewrite()` passes `the_repository`, and `notes.c` itself where `load_display_notes()` and the lazy-init path in `format_note()` pass `the_repository`. Patch 3/6 converts `note_tree_find()`, `add_non_note()`, `load_subtree()`, `remove_note()`, and `format_note()` to replace reads of `the_repository->hash_algo`, `the_hash_algo`, and `the_repository->objects` with `t->repo->hash_algo` and `t->repo->objects`; the commit message documents the call-path safety argument that public entry points substitute `&default_notes_tree` for NULL `t` and assert initialization via `notes_tree_or_default()` before any dereference, and that `load_subtree()` is additionally reached only after such a guard, while noting `copy_note()` as the exception addressed in patch 4/6. Patch 4/6 converts `write_notes_tree()`, `prune_notes()`, and `copy_note()`; `write_notes_tree()` now passes `t->repo` through `struct write_each_note_data` (which gains a `repo` field) to `write_each_note_helper()` and `tree_write_stack_finish_subtree()` (both now taking an explicit `struct repository *` first parameter), replacing `odb_write_object(the_repository->objects, ...)` calls with `r->objects` or `t->repo->objects`; `prune_notes()` introduces `struct prune_notes_data` carrying the repository pointer and delete-list head, with `prune_notes_helper()` checking `odb_has_object(d->repo->objects, ...)`; `copy_note()` is now safe because it begins with `t = notes_tree_or_default(t);` before calling `get_note()` and uses `null_oid(t->repo->hash_algo)` rather than `the_hash_algo`. Patch 5/6 gives `string_list_add_refs_by_glob()` and `string_list_add_refs_from_colon_sep()` explicit `struct repository *r` first parameters; declarations change in `notes.h` while implementations in `notes.c` and `notes-utils.c` replace `get_main_ref_store(the_repository)`, `repo_get_oid(the_repository, ...)`, and the recursive call between the two helpers with uses of the passed `r`. Call sites passing `the_repository` temporarily include `notes_display_config()` and `load_display_notes()` in `notes.c` (populating `display_notes_refs` from config, environment variables, and extra notes refs) and `notes_rewrite_config()` and `init_copy_notes_for_rewrite()` in `notes-utils.c` (building the rewrite ref list from config and `GIT_NOTES_REWRITE_REF`); these are intentional stepping stones to be replaced with `t->repo` in subsequent work. Patch 6/6 updates `combine_notes_fn` and all four built-in combinators -- `combine_notes_concatenate()`, `combine_notes_overwrite()`, `combine_notes_ignore()`, and `combine_notes_cat_sort_uniq()` -- to take `struct repository *r` as the first parameter, replacing uses of `the_repository->objects` with `r->objects` in `odb_read_object()` and `odb_write_object()` calls. The static helper `string_list_add_note_lines()` also gains an explicit repository parameter and reads from `r->objects`. The single call site in `note_tree_insert()` now passes `t->repo` to the callback, ensuring combine operations act on the repository that owns the notes tree rather than the global repository. The cover letter enumerates remaining unconverted work, including `notes-cache.c` functions (`notes_cache_match_validity()`, `notes_cache_write()`, `notes_cache_get()`, `notes_cache_put()`), display-notes code, hash-size helpers, and `notes-merge.[c,h]`.

Key technical details: Files: `notes.c`, `notes.h`, `notes-utils.c`, `notes-cache.c`, `builtin/notes.c`. `struct notes_tree` has a `struct repository *repo` field. Signatures: `notes_tree_init(struct notes_tree *t, struct repository *r, const char *notes_ref, combine_notes_fn combine_notes, int flags)`; `notes_tree_load(struct repository *r, struct string_list *refs, int flags)`; `typedef int (*combine_notes_fn)(struct repository *, struct object_id *, const struct object_id *)`; `string_list_add_refs_by_glob(struct repository *r, ...)` and `string_list_add_refs_from_colon_sep(struct repository *r, ...)`. Converted functions use `t->repo` / `t->repo->hash_algo` instead of `the_repository` / `the_hash_algo`; write and prune paths thread repository through helper structs such as `struct write_each_note_data` (with `repo` field) and `struct prune_notes_data` (carrying repo pointer and delete-list head); `write_each_note_helper()`, `tree_write_stack_finish_subtree()`, and `prune_notes_helper()` take explicit repository parameters; ref-glob helpers take explicit `r` and use `get_main_ref_store(r)` and `repo_get_oid(r, ...)`; combinators and `string_list_add_note_lines()` take explicit repository parameters and use `r->objects`; `note_tree_insert()` passes `t->repo` to the combine callback. The static helper `notes_tree_or_default()` centralizes the NULL-to-default substitution and initialization assertion used by `add_note()`, `remove_note()`, `get_note()`, `for_each_note()`, `write_notes_tree()`, `prune_notes()`, and `copy_note()`. `USE_THE_REPOSITORY_VARIABLE` remains in `notes.c` and `notes-utils.[c,h]`, intentionally scoped to functions tied to the global `default_notes_tree` or lacking repository propagation. No CLI options, config keys, or on-disk format changes.
