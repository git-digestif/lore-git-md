Thread identity: Subject `[PATCH v2 0/5] notes: store repository in struct notes_tree and remove USE_THE_REPOSITORY_VARIABLE guard`, series version v2 (five-patch series; patches 1/5 through 4/5 have now been posted, with patch 4/5 being the current email `[PATCH v2 4/5]`), originating author Okhuomon Ajayi (Outreachy intern), thread type patch series (architectural refactoring).

Core problem or goal: Remove implicit uses of the global `the_repository` in the notes subsystem by storing the repository in `struct notes_tree` and updating all notes API functions to use it. This directly addresses Patrick Steinhardt's architectural concern by fixing unsafe functions at the source, eliminating the need for downstream guards and making the API repository-agnostic.

Current status: Series under active review; no merge status (not in `seen`, `next`, or `master`). Patches 1/5, 2/5, 3/5, and 4/5 have been posted in v2. Patch 2/5 converts five core functions in `notes.c` -- `note_tree_find()`, `add_non_note()`, `load_subtree()`, `remove_note()`, and `format_note()` -- to use `t->repo` instead of `the_repository` and `the_hash_algo`. Patch 3/5 converts the write and prune paths -- `write_notes_tree()`, `prune_notes()`, and `copy_note()` -- to use `t->repo`. Patch 4/5 converts the ref glob helpers `string_list_add_refs_by_glob()` and `string_list_add_refs_from_colon_sep()` to accept an explicit `struct repository *` as their first parameter instead of implicitly using `the_repository`, updating internal calls to `refs_for_each_ref_ext()`, `repo_get_oid()`, and the recursive call between the two helpers, and adjusting all current call sites in `notes.c` and `notes-utils.c` to pass `the_repository` explicitly as a temporary measure. Patrick Steinhardt's interface feedback (renames and parameter order) has been incorporated: `notes_tree_init()` takes `struct notes_tree *` as its first parameter and `struct repository *` as its second, and `notes_tree_load()` takes `struct repository *` as its first parameter. Patch 6/6 from the prior six-patch iteration has been dropped entirely to avoid a mixed state where `notes-utils.[c,h]` appears fully converted while calling into guarded `notes.c` code; as a result, the `USE_THE_REPOSITORY_VARIABLE` guard remains in both `notes.c` and `notes-utils.[c,h]`. The cover letter is reframed as a preparatory step that enumerates remaining undone work across `notes.c`, `notes-utils.[c,h]`, and `notes-merge.[c,h]`.
