Thread identity
Subject: [PATCH v2 0/6] notes: store repository in `struct notes_tree` and remove `USE_THE_REPOSITORY_VARIABLE` guard
Series version: v2 (six-patch series posted; next iteration will drop patch 6/6 and be limited to patches 1/6--5/6)
Originating author: Okhuomon Ajayi (Outreachy intern)
Thread type: patch series (architectural refactoring)

Core problem or goal
Remove implicit uses of the global `the_repository` in the notes subsystem by storing the repository in `struct notes_tree` and updating all notes API functions to use it. This directly addresses Patrick Steinhardt's architectural concern by fixing unsafe functions at the source, eliminating the need for downstream guards and making the API repository-agnostic.

Current status
Series under active review; no merge status (not in `seen`, `next`, or `master`). Patches 1/6--6/6 have been posted in v2, incrementally refactoring `notes.c` and `notes-utils.c` to use `struct notes_tree->repo` or explicit `struct repository *` parameters. Patrick Steinhardt's interface feedback (renames and parameter order) has been incorporated in the v2 iteration: `init_notes()` is now `notes_tree_init()` with `struct notes_tree *` as its first parameter, and `load_notes_trees()` is now `notes_tree_load()`. Okhuomon Ajayi has now agreed with Christian Couder to drop patch 6/6 entirely in the next iteration, limiting the series to patches 1/6--5/6 and reframing the cover letter as a preparatory step that enumerates remaining undone work across `notes.c`, `notes-utils.[c,h]`, and `notes-merge.[c,h]` (including hash-size helpers relying on the global `the_hash_algo`, the `default_notes_tree` global, display notes code, and command entry points that receive but do not propagate a repository to `format_note()`). This resolves Christian Couder's mixed-state concern by keeping the `USE_THE_REPOSITORY_VARIABLE` guard in both `notes.c` and `notes-utils.[c,h]` until a future series addresses the remaining global dependencies comprehensively. The remaining `USE_THE_REPOSITORY_VARIABLE` guard in `notes.c` is intentionally scoped to functions that rely on the global `default_notes_tree` or do not propagate a repository parameter (e.g., `display_notes()`, `expand_loose_notes_ref()`, hash-size helpers). Okhuomon Ajayi is seeking Patrick Steinhardt's explicit confirmation that this scoping is acceptable before posting the rebased iteration. The `copy_note()` hash-algorithm change (switching to `t->repo->hash_algo` for the null object ID) will be moved from patch 5/6 to patch 3/6 in the next iteration.

Key technical details
Files: `notes.c`, `notes-utils.c`, `notes-utils.h`, `notes.h`, and callers in `builtin/am.c`, `builtin/notes.c`, `notes-cache.c`, `sequencer.c`
Symbols:
- `struct notes_tree` contains a `struct repository *repo` field (added in patch 1/6)
- Updated signatures (with renames now implemented in v2):
  - `notes_tree_init(struct notes_tree *, const char *, combine_notes_fn, int, struct repository *)` (patch 1/6)
  - `notes_tree_load(struct string_list *, struct repository *)` (patch 1/6)
  - Seven core functions in `notes.c` updated to use `t->repo` (patches 2/6 and 3/6): `note_tree_find()`, `add_non_note()`, `load_subtree()`, `remove_note()`, `format_note()`, `write_notes_tree()`, and `prune_notes()`
  - Ref glob helpers updated to take an explicit `struct repository *` parameter (patch 4/6): `string_list_add_refs_by_glob(struct repository *, struct string_list *, const char *)` and `string_list_add_refs_from_colon_sep(struct repository *, struct string_list *, const char *)`
  - `combine_notes` callbacks updated to accept an explicit `struct repository *` parameter (patch 5/6): `concatenate_notes()`, `overwrite_notes()`, `ignore_notes()`, and `cat_sort_uniq_notes()`
  - `typedef int (*combine_notes_fn)(struct repository *, struct object_id *, const struct object_id *)` (patch 5/6)
  - `copy_note()` updated to use the tree's hash algorithm (`t->repo->hash_algo`) for its null object ID instead of the global hash algorithm (currently in patch 5/6, committed to move to patch 3/6)
  - `create_notes_commit()` and `commit_notes()` updated to use the passed repository instead of `the_repository` (patch 6/6, now to be dropped)
  - `init_copy_notes_for_rewrite()` now takes a `struct repository *` parameter (patch 6/6, now to be dropped)
- Helper structs `write_each_note_data`, `prune_notes_data`, and `notes_rewrite_cfg` include a `struct repository *` field to propagate the repository through the call chain (patches 3/6 and 6/6)
- New behavior: `notes.c` functions use `struct notes_tree->repo` or an explicit `struct repository *` parameter instead of `the_repository` for the converted operations, making the API repository-agnostic for those paths
- Remaining guard: `USE_THE_REPOSITORY_VARIABLE` in `notes.c` and `notes-utils.[c,h]`, intentionally retained until remaining global dependencies (hash-size helpers, `default_notes_tree`, display notes) are addressed in future work
- No CLI options, config keys, or on-disk format changes
- Architectural note: The global `default_notes_tree` in `notes.c` is acknowledged as problematic due to its implicit global state, but fixing it is outside the scope of this series
