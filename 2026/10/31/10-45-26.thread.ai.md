Subject: [PATCH v2 0/6] notes: store repository in `struct notes_tree` and remove `USE_THE_REPOSITORY_VARIABLE` guard
Series version: v2 (six-patch series)
Originating author: Okhuomon Ajayi (Outreachy intern)
Thread type: patch series (architectural refactoring)

Core problem or goal
Remove implicit uses of the global `the_repository` in the notes subsystem by storing the repository in `struct notes_tree` and updating all notes API functions to use it. This directly addresses Patrick Steinhardt’s architectural concern by fixing unsafe functions at the source, eliminating the need for downstream guards and making the API repository-agnostic.

Current status
Six-patch series under active review; no merge status (not in `seen`, `next`, or `master`). Patch 1/6 (adding the `repo` field and updating `init_notes()`/`load_notes_trees()`) and patch 2/6 (converting five core functions in `notes.c` to use `t->repo` instead of `the_repository`) have been posted. The series is structured to incrementally refactor `notes.c` without introducing guards, aligning with the project’s preference for addressing root causes.

Key technical details
Files: `notes.c` (primary), `notes-utils.c`, `notes-utils.h`, `notes.h`, and callers in `builtin/am.c`, `builtin/notes.c`, `notes-cache.c`, `sequencer.c`
Symbols:
- `struct notes_tree` contains a `struct repository *repo` field (added in patch 1/6)
- Updated signatures: `init_notes(struct notes_tree *, const char *, combine_notes_fn, int, struct repository *)` and `load_notes_trees(struct string_list *, struct repository *)` (patch 1/6)
- Five core functions in `notes.c` updated to use `t->repo` (patch 2/6): `note_tree_find()`, `add_non_note()`, `load_subtree()`, `remove_note()`, and `format_note()`
- Temporary use of `the_repository` in callers (e.g., `builtin/notes.c`, `notes-cache.c`) will be addressed in later patches
- New behavior: `notes.c` functions use `struct notes_tree->repo` instead of `the_repository`, making the API repository-agnostic without guards
- Removed: `USE_THE_REPOSITORY_VARIABLE` guard from `notes-utils.c` and `notes-utils.h` (later in the series)
- No CLI options, config keys, or on-disk format changes
- Remaining uses: `display_notes()`, `expand_loose_notes_ref()`, and `the_hash_algo` sizes in `notes.c` (potential follow-up work)
