Core problem or goal: Remove implicit uses of the global `the_repository` in the notes subsystem by storing the repository in `struct notes_tree` and updating all notes API functions to use it. This directly addresses Patrick Steinhardt's architectural concern by fixing unsafe functions at the source, eliminating the need for downstream guards and making the API repository-agnostic.

No CLI options, config keys, or on-disk format changes.

Open questions and loose ends: The NULL-dereference bug in `copy_note()` (patch 3/5) when called with NULL `t` -- where callers expect fallback to `default_notes_tree` but the patch dereferences `t->repo->hash_algo` without checking -- is confirmed by both Okhuomon Ajayi and Junio C Hamano to be fixed in the next iteration (v5), with the specific guard `if (!t) t = &default_notes_tree(); assert(t->initialized);` to be added at the top of `copy_note()` before accessing `t->repo`. The bug exists because `copy_note()` calls `get_note(t, ...)` which safely handles NULL `t` internally, but patch 3/5 added a direct dereference of `t->repo->hash_algo` in the `else if` branch (changing `null_oid(the_hash_algo)` to `null_oid(t->repo->hash_algo)`) without first ensuring `t` is non-NULL; Junio C Hamano has now confirmed this is the only remaining unsafe conversion requiring rework. Christian Couder has corrected Okhuomon Ajayi's safety argument for patch 2/5: `load_subtree()` is reachable not only from initialization but also on demand during reads via the chain `get_note()` -> `note_tree_find()` -> `note_tree_search()` -> `load_subtree()`; the actual safety guarantee for the five converted functions comes from the public entry points (`add_note()`, `remove_note()`, `get_note()`, and `format_note()`) all substituting `&default_notes_tree` for NULL `t` and asserting `t->initialized` before any dereference of `t->repo`, not from the specific reachability of individual helpers. Junio C Hamano has explicitly accepted this call-path reasoning, confirming that the five functions converted in patch 2/5 are safe from NULL-dereference given these entry-point guarantees, and narrowing the remaining correctness issue to `copy_note()` alone. Okhuomon Ajayi has now conceded Couder's correction and confirmed she will document this call-path safety argument in the commit message for patch 2/5 in v5. Junio C Hamano has additionally proposed a stylistic refactoring for the next iteration: factoring the repeated three-line pattern that substitutes `&default_notes_tree` for NULL `t` and asserts `t->initialized` at each public entry point (`add_note()`, `remove_note()`, `get_note()`, and internal `format_note()`) into a single static helper function returning `struct notes_tree *`, so each caller becomes simply `t = helper(t);`; he notes the helper will need a better name than "helper".
