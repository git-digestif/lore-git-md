Core problem or goal
Remove implicit uses of the global `the_repository` in `notes-utils.c` by converting its API to accept explicit `struct repository *` parameters. The series initially targeted mechanical refactoring but has now exposed a deeper architectural issue: the `notes-utils.h` API cannot be safely made repository-agnostic until the underlying `notes.h` functions (e.g., `write_notes_tree()`, `init_notes()`, `add_note()`) are also refactored to avoid hardcoding `the_repository`. The thread has pivoted to debating whether to:
1. Proceed with the current incremental approach (risking false abstraction), or
2. Adopt Junio’s protective measure (wrapping the API in `#ifdef USE_THE_REPOSITORY_VARIABLE` until `notes.h` is refactored).

Current status
Blocked pending architectural resolution. v2 addressed prior feedback (extending the change to `init_copy_notes_for_rewrite()` and callers) but is now challenged by Junio’s review, which argues the series is premature. The patches remain under review, but no further iterations are expected until the architectural question is settled. No merge status (still "under review").
