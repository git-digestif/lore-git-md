This is a bugfix patch targeting the merge-ort subsystem. It addresses a long-standing inconsistency in how Git handles valueless configuration settings for rename detection.

The patch fixes a regression where `git -c merge.renames merge` (or similar commands using `diff.renames` or `merge.directoryRenames`) fails with "missing value" errors, despite Git's documentation stating that valueless config settings should default to `true`. The issue affects all commands that use merge-ort for merging. The root cause is that merge-ort uses `repo_config_get_string()` which rejects valueless settings, while other parts of Git (like `git_config_rename()` and `git_parse_maybe_bool()`) already handle this case correctly.

The fix replaces `repo_config_get_string()` with `repo_config_get_value()` in merge-ort's config parsing code, aligning it with the rest of Git's behavior. The patch includes thorough test coverage: two new test cases in `t6434-merge-recursive-rename-options.sh` verify valueless `diff.renames` and `merge.renames` settings, and one in `t6423-merge-rename-directories.sh` tests valueless `merge.directoryRenames`. The tests follow the existing pattern of resetting the index and verifying merge outcomes.

The commit message clearly explains the problem, the inconsistency with documented behavior, and the solution. The code changes are minimal and focused, touching only the config parsing logic in `merge-ort.c`. This looks like a well-crafted, motivated fix that addresses a real usability issue without introducing unnecessary complexity. The patch is likely to be uncontroversial as it aligns behavior with existing conventions.
