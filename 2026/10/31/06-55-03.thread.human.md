This thread is about a bugfix from Linus Torvalds for `git describe`, which was miscomputing commit distances when commit timestamps were non-monotonic—an issue that surfaced during the Linux kernel v7.4 merge window. The fix itself is a one-line change in `builtin/describe.c` to prioritize commit generation numbers (from the commit graph) over unreliable commit dates, ensuring topological order is respected. The patch has been queued for integration by Junio C Hamano, with no maintainer objections, and the test implementation debate settled in favor of Linus’s original hard-coded date test.

The discussion has since evolved beyond the initial fix, focusing on a critical edge case: the fix’s dependency on a fresh commit graph. If the graph is stale or absent, the bug could reappear. Junio proposed amortizing the performance cost of `ensure_generations_valid()`—the function that guarantees generation numbers are available—by writing out a fresh commit-graph after the expensive walk. Derrick Stolee has now endorsed this approach, framing it as a natural progression for the commit-graph feature, even suggesting a shift from opt-in to opt-out behavior where Git proactively generates and updates commit-graphs. This introduces a broader philosophical question: should read-only commands like `git describe` mutate on-disk state? Stolee acknowledges this as a potential concern but hints at "guardrails" (e.g., user opt-out or write-back triggers) as a solution, leaving the specifics unresolved.

The thread is now converging on a systemic change to the commit-graph subsystem, with the original regression fix serving as the catalyst. Key participants—Linus, Junio, Patrick Steinhardt, and Stolee—have all engaged substantively, with no objections to the write-back proposal. The remaining open questions revolve around implementation details (e.g., whether the write-back should be automatic or configurable) and the broader implications for Git’s design principles. For now, the fix is on track for integration, but the thread’s scope has expanded to address the underlying performance-correctness trade-off in a more holistic way.
