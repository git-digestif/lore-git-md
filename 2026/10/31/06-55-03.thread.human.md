This thread is about a bugfix from Linus Torvalds for `git describe`, which was miscomputing commit distances when commit timestamps were out of order. The fix is a one-line change in `builtin/describe.c` that makes the command use commit generation numbers (from the commit graph) instead of unreliable dates, ensuring correct topological ordering. This was a real issue during the Linux kernel v7.4 merge window, where skewed commit dates caused version reporting discrepancies.

The patch itself is straightforward and under review, with no prior versions or objections to the core change. However, the test case for this fix has sparked a minor debate. Linus provided a test with hard-coded commit dates to simulate the skew, while Tuomas Ahola suggested an alternative using `test_tick` manipulation. Junio C Hamano critiqued Tuomas's rewrite, pointing out a technical flaw (a `test_config` cleanup issue in Bash) and arguing that the original test was clearer for this specific case. Tuomas has since conceded the rewrite was unnecessary and flawed, but the test implementation remains unresolved.

The thread is otherwise quiet—no other reviews or maintainer decisions have been made yet. The fix is uncontroversial, but the test case is still up in the air. If you're catching up, the key takeaway is that the patch is likely to be accepted once the test is settled, and the change itself is a small but important correctness fix for `git describe`.
