Linus’s initial one-line fix used commit generation numbers (with an opt-out `--exact` flag) and was queued for integration. However, the discussion has since reopened to consider an alternative algorithm by Kristofer Karlsson, which delivers near-exact distances without relying on generation numbers, potentially eliminating the need for the `--exact` flag and its performance trade-offs.

The key participants are now weighing two approaches: Linus’s simpler fix (which depends on commit-graph freshness and includes a warning mechanism) and Kristofer’s more robust prototype (which avoids generation numbers entirely and maintains the current performance profile). Junio C Hamano, Patrick Steinhardt, and Derrick Stolee have all signaled support for Linus’s opt-out design, while Kristofer’s proposal remains unendorsed but has been called "interesting" by Junio. Meanwhile, Junio has submitted a test-infrastructure patch to resolve a side effect of Linus’s fix—ensuring the test suite consistently expects success when commit-graphs are enabled, reflecting Git’s default behavior since 2019. This patch doesn’t address the algorithmic debate but keeps the test suite reliable while the discussion continues.

The thread is still open, with no final decision on which algorithm to adopt. The commit-graph write-back mechanism (proposed by Junio and Stolee to amortize the performance cost of Linus’s fix) also remains unimplemented.
