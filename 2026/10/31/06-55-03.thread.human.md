This thread began as a bugfix from Linus Torvalds to correct `git describe`'s miscalculation of commit distances when commit timestamps are skewed—specifically due to GitLab’s Marge-bot preserving original committer dates during rebase. The regression, which caused real-world discrepancies in the Linux kernel’s version reporting, initially prompted a one-line fix using commit generation numbers, along with an opt-out `--exact` flag and a warning mechanism. However, the design debate has since reopened with Kristofer Karlsson’s proposal of an alternative algorithm that achieves near-exact distances without relying on generation numbers, potentially eliminating the need for the `--exact` flag and its performance trade-offs.

The thread is now at a crossroads. Linus’s fix is queued for integration in `next`, but its dependency on commit-graph freshness and the performance cost of `ensure_generations_valid()` have sparked discussion about alternatives. Kristofer’s prototype, which uses a two-counter algorithm and an epsilon-based heuristic, claims to match the current implementation’s performance while delivering near-exact results by default. No maintainer or key participant has yet endorsed or rejected this proposal, though Junio C Hamano has acknowledged it as "interesting." Meanwhile, Patrick Steinhardt and Derrick Stolee have proposed a commit-graph write-back mechanism to amortize the performance cost of Linus’s fix, though this remains unimplemented.

In the latest email, Kristofer submitted a small test-fix patch to address a side effect of Linus’s fix: a disjoint-history test case now passes inconsistently depending on whether a commit-graph is present. His patch ensures the test fails as expected in both modes by unsetting `GIT_TEST_COMMIT_GRAPH` for that specific case. This is a temporary measure, pending a follow-up series that will remove the unset once the test passes reliably in all modes. The patch is a minor, surface-level adjustment to test hygiene and does not affect the core algorithmic debate. Key participants—Linus, Patrick, and Derrick—have not yet responded to Kristofer’s test-fix or his broader proposal. The thread’s next steps hinge on whether the project adopts Kristofer’s algorithm, sticks with Linus’s fix, or explores a hybrid approach.
