This is the first patch in a two-patch **bugfix series** targeting the `@{push}` revision suffix. The patch refactors `remote.c` to improve readability by extracting the `PUSH_DEFAULT_SIMPLE` logic from `branch_get_push_1()` into a new helper function, `branch_get_push_simple()`. The refactoring is purely structural—no behavior changes are introduced—and prepares the codebase for the functional fix in the second patch, which will align `@{push}` resolution with `git push` behavior in triangular workflows.

The new helper, `branch_get_push_simple()`, encapsulates the existing logic for resolving `@{push}` when `push.default=simple`. This reduces nesting in `branch_get_push_1()` and makes the code easier to follow, addressing Junio C Hamano’s feedback from the v1 review. The helper takes the same parameters as `branch_get_push_1()` (`struct repository *`, `struct remote *`, `struct branch *`, and `struct strbuf *err`) and returns the resolved push destination or `NULL` on failure, preserving the original error-handling behavior.

The patch touches only `remote.c` and introduces no new symbols beyond the helper function. The diff is mechanical: the `PUSH_DEFAULT_SIMPLE` case in `branch_get_push_1()` is replaced with a call to `branch_get_push_simple()`, and the extracted logic is moved verbatim into the new function. The commit message explicitly states that there is no functional change, which is consistent with the diff.

This refactoring is a prerequisite for the second patch, which will add a four-line conditional to `branch_get_push_simple()` to handle triangular workflows. The separation of concerns here—refactoring first, then fixing—makes the series easier to review and ensures the functional change is isolated.
