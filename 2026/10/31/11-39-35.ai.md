This is the first patch in Elia Pinto's four-part **bugfix series** addressing truncation issues with large objects (≥4 GiB) on 32-bit platforms (notably Windows). The patch converts `builtin/unpack-objects.c` from `unsigned long` to `size_t` for object sizes, fixing a crash when streaming large blobs on platforms where `unsigned long` is 32-bit.

The change is mechanical but critical: it replaces `unsigned long` with `size_t` in function signatures, struct fields, and local variables throughout `unpack-objects.c`, ensuring consistency with the pack code's use of `size_t`. The patch removes a now-unnecessary size cast in `unpack_delta_entry()` and updates downstream calls to `odb_write_object()` and `fsck_object()` (though those are handled in later patches). The failure mode is clear: on 32-bit platforms, objects ≥4 GiB trigger a truncated size in `stream_blob()`, causing the stream write to fail with an error rather than corrupting data.

No tests are included, as reproducing the issue requires processing 4 GiB of input on a 32-bit platform, but the commit message provides a concise reproduction scenario (streaming large blobs exceeding `core.bigFileThreshold`). The patch is narrowly scoped to `unpack-objects.c` and does not touch other subsystems, though it lays the groundwork for similar fixes in `index-pack` and `fsck` (covered in patches 2–4). The changes are low-risk, as they only affect platforms where `unsigned long` is 32-bit, and the series as a whole is motivated by real-world Windows compatibility issues.

Key symbols modified: `struct obj_buffer` (size field), `get_data()`, `stream_blob()`, `unpack_delta_entry()`, and all functions involved in delta resolution. The patch is a prerequisite for the rest of the series, which addresses false SHA-1 collision reports and partial object checks in other parts of the pack-receiving pipeline. No controversy is evident, and the patch appears ready for review.
