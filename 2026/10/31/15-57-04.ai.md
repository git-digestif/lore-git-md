This is the fourth and final patch in Ravi Mistry's four-patch series improving Git's HTTP transport resilience. It extends the retry logic—previously limited to GET requests—to cover HTTP POST requests, which handle the actual data transfer during fetch/clone and on-demand blob downloads in partial clones.

The patch extracts the retry wait logic from `http_request_recoverable()` into a new shared helper `http_retry_wait()`, then uses it in both `probe_rpc()` and `post_rpc()`. It also defers error reporting until retries are exhausted and ensures the "Content-Encoding: gzip" header is re-attached when retrying a compressed request. The test suite expands to verify that POST requests now retry 429 and 502 errors, that partial-clone lazy blob fetches survive transient 502s, and that gzipped POST requests preserve the Content-Encoding header across retries.

The changes are confined to `http.c`, `remote-curl.c`, and the test helpers; no on-disk format or public API is altered. The patch completes the series' goal of making Git's HTTP transport more resilient to transient server errors and rate-limiting.
