This is the v3 iteration of a well-scoped bugfix patch that corrects commit abbreviation in submodule diff headers. The patch ensures that abbreviated commit IDs shown in submodule diffs are checked against the submodule's object database rather than the superproject's, preventing potential collisions where the same abbreviated ID could refer to different objects in the two repositories.

The change is minimal and targeted: it replaces two calls to `strbuf_add_unique_abbrev()` with `strbuf_repo_add_unique_abbrev()` in `submodule.c`, passing the submodule's repository object (`sub`) when available, and falling back to `o->repo` otherwise. This eliminates reliance on the global `the_repository` and aligns with the broader Git libification effort. The test in `t/t4041-diff-submodule-option.sh` constructs a controlled collision scenario, verifying that the output uses the correct (submodule) abbreviation.

This version incorporates all prior feedback: the commit message is clear, the code style is clean, and the test coverage is thorough. The only change from v2 is a cosmetic adjustment to the commit title prefix ("Submodule:" → "submodule:"). The patch is technically complete, addresses a real correctness issue, and is ready for integration. It is part of the libification effort but is self-contained and does not depend on other in-flight work.

Key technical details for follow-up discussion: the patch introduces `repo` as a local variable in `show_submodule_header()` to avoid duplicating the repository selection logic, and the test uses SHA-1-specific commit IDs to force a collision between the superproject and submodule. The fallback repository (`o->repo`) is now used instead of `the_repository`, reducing global state reliance.
