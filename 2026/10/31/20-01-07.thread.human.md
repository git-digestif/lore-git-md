This thread is about improving `git stash` performance by eliminating redundant work during stash creation. Jasmeet Bhatia proposed a patch (v1) that reuses the already-prepared index state and untracked file list when `do_push_stash()` calls `do_create_stash()`, yielding measurable speedups—16-18% for `git stash -p` and 6% for `git stash push` on the Linux kernel repository. The patch modifies `builtin/stash.c` to add an optional parameter to `do_create_stash()`, skipping redundant index preloads and change checks when the state is already prepared.

Phillip Wood has an overlapping series, `pw/stash-change-check-only-once`, already in Junio’s `seen` branch. His approach consolidates `check_changes()` calls and removes redundant `preload_index()` calls elsewhere, rather than passing prepared state into `do_create_stash()`. Phillip reviewed Jasmeet’s patch and invited collaboration, framing the discussion as a design choice between the two approaches. Jasmeet has now acknowledged the invitation and committed to reviewing Phillip’s series in the coming days, but hasn’t yet weighed in on the technical trade-offs. The thread remains open, awaiting Jasmeet’s feedback before any architectural reconciliation can proceed.
