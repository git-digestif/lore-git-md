This thread is about a performance optimization for `git stash`. Jasmeet Bhatia identified redundant work in the stash creation process—specifically, that `do_push_stash()` was redoing index preparation and untracked file checks that had already been performed. The patch modifies `builtin/stash.c` to reuse the prepared state, avoiding duplicate calls to `repo_read_index_preload()`, `repo_refresh_and_write_index()`, and `check_changes()`.

The change is narrowly targeted: it adds an optional parameter to `do_create_stash()` to accept precomputed untracked files, which `do_push_stash()` now passes in. The existing behavior of `git stash create` is unchanged, as it doesn’t use this path. Performance measurements on the Linux kernel repository show a 16–18% speedup for `git stash -p` and a 6% improvement for `git stash push`. The patch is well-documented and includes these benchmarks, though it doesn’t add new tests to the suite.

So far, the thread consists only of the patch submission. No reviews or objections have been posted yet, so the patch’s correctness and broader impact remain unconfirmed. If you’re following `git stash` performance, this is one to watch for feedback from regular reviewers of the stash subsystem.
