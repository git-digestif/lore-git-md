This is a **bugfix patch update** (v2) targeting the sequencer subsystem. The patch prevents `git revert`, `git cherry-pick`, and all `git rebase` backends from operating on shallow boundary commits—commits that appear as root commits due to `--depth=1` cloning and are recorded in `.git/shallow`. Such operations can inadvertently delete all tracked files, and the patch now refuses them by default with a clear error message, offering `--unshallow` or the new `--allow-shallow-boundary` flag (for `revert`/`cherry-pick` only; `rebase` always refuses without override).

The v2 update addresses Phillip Wood’s feedback by moving the safeguard to the planning stage (todo-list construction) via a shared helper function, `sequencer_refuse_shallow_boundary()`. This ensures the operation is refused before any state changes occur, avoiding the messy `.git/sequencer` leftovers seen in v1. The check is now called from four entry points: `sequencer_make_script()`, `make_script_with_merges()`, `single_pick()`, and `sequencer_pick_revisions()`, covering all sequencer-based commands. The `rebase --apply` backend, which bypasses the sequencer, gets its own lightweight check before rewinding HEAD. A minor trade-off is that manually edited todo lists (e.g., adding a boundary commit’s hash) won’t trigger the safeguard, but this is deemed an acceptable edge case.

Files touched include `sequencer.c`/`sequencer.h`, `builtin/revert.c`, `builtin/rebase.c`, and `Documentation/git-revert.adoc`. The new CLI option `--allow-shallow-boundary` is exposed only for `revert`/`cherry-pick`; `rebase` offers no override. Test coverage verifies refusal in shallow repos, override behavior, autostash restoration, and edge cases like single-commit clones. The patch introduces no on-disk format changes and is well-motivated by the risk of data loss.

The discussion remains open on whether to extend the safeguard to `git commit --amend`, but the core premise—refusing shallow boundary commits by default—is uncontroversial. Junio C Hamano and Phillip Wood have both endorsed the architectural shift to early checking, and the patch now aligns with their expectations. No merge decision has been made, but the implementation looks technically sound and addresses prior feedback thoroughly. The only loose end is the manual-todo-list edge case, which Nakul acknowledges but does not propose to fix in this iteration.
