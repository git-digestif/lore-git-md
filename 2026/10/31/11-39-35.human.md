This is the first patch in a four-part bugfix series addressing truncation issues with large objects (4 GiB or more) on 32-bit platforms, particularly Windows. The patch converts `unsigned long` to `size_t` for object sizes in `builtin/unpack-objects.c`, fixing a crash that occurs when streaming large blobs on platforms where `unsigned long` is 32-bit.

The change is mechanical but critical: it replaces `unsigned long` with `size_t` for object sizes throughout the file, including function signatures, struct fields, and local variables. The patch also removes an unnecessary size cast in `unpack_delta_entry()`, aligning the code with the underlying pack-handling logic. The failure mode is clear—streaming blobs larger than 4 GiB on 32-bit platforms would previously pass a truncated size to `stream_blob()`, causing the write to fail with an error rather than corrupting data.

No tests are included, as reproducing the issue requires processing 4 GiB objects on a 32-bit platform, which is impractical. The commit message justifies this omission and provides a concise explanation of the problem and fix. The patch is well-scoped and appears technically sound, addressing a real-world compatibility issue without introducing new behavior or on-disk format changes. It’s a straightforward but necessary step toward fixing the broader 32-bit truncation problem in the pack-receiving pipeline.
