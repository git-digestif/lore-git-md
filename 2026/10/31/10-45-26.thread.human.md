This thread is Okhuomon Ajayi's Outreachy-driven refactoring of Git's notes subsystem to remove implicit uses of the global `the_repository`. The goal is to store a `struct repository *` in `struct notes_tree` and thread it through the notes API -- read, write, prune, ref-glob, and combine paths -- so that the code no longer depends on the global. The current five-patch series (v2, though mislabeled -- see below) has incorporated Patrick Steinhardt's interface feedback (function renames such as `notes_tree_init()` and `notes_tree_load()`, and parameter ordering), dropped the old sixth patch, and deliberately left the `USE_THE_REPOSITORY_VARIABLE` guard in `notes.c` and `notes-utils.[c,h]` for functions still tied to the global `default_notes_tree`. Christian Couder's two substantive reviews are resolved; Patrick Steinhardt's explicit confirmation that the remaining guard's scoping is acceptable is the gating item before the next iteration, and reviews from René Scharfe and Karthik Nayak are still pending. The series remains under active review with no merge to `seen`, `next`, or `master`.

Junio C Hamano has now weighed in -- not on the code, but on thread hygiene. He notes that the current `[PATCH v2 0/5]` collides with an earlier two-patch series also labeled "v2" from November 3rd in the same thread, and that the original six-patch iteration from November 5th should have been versioned rather than sent unlabeled. As a result, the series just posted should have been "v4", and the next iteration should be sent as "v5". This matters because duplicate version tags within one thread confuse tooling like `b4 am`, which then requires manual intervention. So the practical takeaway for anyone catching up: treat the just-posted five-patch series as effectively v4, expect the follow-up as v5, and don't be confused by the repeated "v2" labels when reading the thread.
