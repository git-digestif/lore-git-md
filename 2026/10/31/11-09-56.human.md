This is a bugfix series targeting object parsing and verification on 32-bit platforms (notably Windows). The core issue: functions that take object sizes as `unsigned long` truncate values above 4 GiB, causing large objects to be misreported as corrupt, signatures to be missed, or only partial content to be checked.

The series converts four key areas to use `size_t` instead of `unsigned long` for object sizes: object signature verification (patch 1), fsck checks (patch 2), object parsing (patch 3), and message buffer handling in tags/merges (patch 4). The changes are mechanical but touch widely used APIs like `check_object_signature()`, `parse_commit_buffer()`, and `fsck_object()`. No behavior changes are expected on 64-bit platforms.

Elia notes the fixes are limited to in-memory objects; pack-related paths (index-pack, unpack-objects) remain unaddressed for now. The series is self-contained and merges cleanly with other ongoing work, including a separate tree-walk series by the same author. No tests are included due to the impracticality of creating 4 GiB+ test objects, though the commit message suggests willingness to add platform-guarded tests if requested.

The patches look well-scoped and directly address the truncation problem described. The lack of test coverage is understandable given the constraints, and the changes appear to be straightforward type conversions rather than complex logic rewrites. This seems like a sensible cleanup that eliminates a latent bug on 32-bit systems.
