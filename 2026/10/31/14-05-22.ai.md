This is a bugfix patch (v2) targeting the sequencer subsystem. It expands the safeguard against operating on shallow boundary commits to cover `git cherry-pick` and all rebase backends (`merge`, `interactive`, and `apply`), addressing the feedback from Junio C Hamano and Phillip Wood on the initial version.

The patch now checks for shallow boundary commits at the planning stage (when the todo list is built) rather than mid-operation, ensuring no state is left behind if the command is refused. The `--allow-shallow-boundary` flag is retained for `git revert` and `git cherry-pick` but omitted from the synopsis for clarity, while `git rebase` always refuses without an override. The implementation introduces a shared helper function (`sequencer_refuse_shallow_boundary`) and a new shallow utility (`is_shallow_boundary_commit`) to centralize the logic. Test coverage is comprehensive, verifying refusal in shallow repos, override behavior, autostash restoration, and edge cases like single-commit clones.

The changes are well-motivated and technically sound, with clear documentation and thorough test coverage. The patch addresses the core problem (accidental file deletion) while minimizing disruption to non-shallow workflows. The architectural shift to early checking is a user-friendly improvement, and the scope expansion to all rebase backends aligns with reviewer expectations. No controversial design choices remain, and the patch appears ready for integration.
