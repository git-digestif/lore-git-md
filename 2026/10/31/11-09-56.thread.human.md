This thread is a four-patch series by Elia Pinto addressing object-size truncation bugs on 32-bit platforms (notably Windows). The series fixes cases where Git operations like `git fsck`, `git tag -v`, and commit-message parsing fail or misbehave when handling objects larger than 4 GiB by converting function signatures and call sites from `unsigned long` to `size_t` for object sizes and message buffer indices.

The series is now complete with the fourth patch, which tackles message-buffer length parameters in `tag.c`, `fmt-merge-msg.c`, and `ref-filter.c`, and fixes an integer-overflow bug in `copy_subject()`. In total, 21 files across the object, commit, tag, fsck, and ref-filter subsystems have been updated, with key functions like `check_object_signature()`, `parse_object_buffer()`, and `fsck_object()` now using `size_t` to avoid truncation. The commit slab in `commit.c` remains constrained to `unsigned long`, but a new helper, `cast_size_t_to_ulong()`, ensures safe narrowing for objects ≥4 GiB.

No substantive reviews have been posted yet, and the series remains under review, not queued in any integration branch. The author has offered to add `EXPENSIVE` tests for 32-bit platforms if requested, though reproducing the bugs requires objects larger than 4 GiB (or 2 GiB for the `copy_subject()` fix). The changes are 64-bit-platform-safe and introduce no on-disk format changes.
