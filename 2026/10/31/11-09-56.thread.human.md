This thread is about a bugfix series from Elia Pinto that addresses object-size truncation on 32-bit platforms, particularly Windows. The series converts function signatures and call sites from `unsigned long` to `size_t` to prevent truncation when object sizes exceed 4 GiB, which can cause issues like `git fsck` inspecting only a prefix of large objects or `git tag -v` failing to find signatures. The v1 patch set touches 24 files across multiple subsystems, including object parsing, fsck, and commit handling, and introduces a safe narrowing mechanism for the commit slab's `unsigned long` storage.

The series is still under review and hasn't been queued in any integration branch. So far, the only substantive feedback has come from Simon Richter, who points out a critical limitation: `size_t` is not a universal fix for large sizes on 32-bit systems, as it remains 32 bits there. Instead, `off_t` (which is 64 bits with large-file support) should be used for tracking on-disk sizes, while `size_t` is appropriate for in-memory buffer sizes. This suggests the series may need further refactoring to properly distinguish between these use cases. No other reviews or decisions have been recorded yet, and the question of whether to add expensive tests for 32-bit platforms remains open.
