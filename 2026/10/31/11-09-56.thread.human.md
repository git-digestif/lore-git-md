This thread is a bugfix series from Elia Pinto addressing object-size truncation on 32-bit platforms, particularly Windows. The series converts function signatures and call sites from `unsigned long` to `size_t` for in-memory object sizes and message buffer indices, fixing issues like `git fsck` inspecting only a prefix of large objects or `git tag -v` failing to find signatures. The v1 series touches 24 files across object, commit, tag, fsck, and other subsystems, with key changes to functions like `check_object_signature()`, `parse_object_buffer()`, and `copy_subject()`.

Simon Richter’s review highlighted that `size_t` is insufficient for on-disk sizes on 32-bit platforms, where `off_t` (64 bits) is required. Elia has clarified that the current series is scoped to in-memory buffers, while a separate patch (v2) addresses `off_t` for streaming reads from disk. The series remains under review with no integration branch assigned, and no substantive reviews beyond Simon’s critique. The author has offered to add `EXPENSIVE` tests for 32-bit platforms if requested, but the series currently lacks test coverage. The distinction between in-memory (`size_t`) and on-disk (`off_t`) sizes is now settled, but the broader refactoring implications remain open.
