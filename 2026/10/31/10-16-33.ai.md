This is the second patch in Elia Pinto’s four-patch bugfix series targeting 64-to-32 truncations on Windows (LLP64 platforms). It fixes a crash in the word-diff subsystem by converting the buffer allocation size variables from `unsigned long` and `long` to `size_t`.

The patch addresses a real and severe issue: on 32-bit `long` platforms (like Windows), `diff_words_fill()` can overflow its signed 32-bit `long` allocation counter when the buffer grows past ~700 MiB. This leads to undefined behavior—typically a negative size that `REALLOC_ARRAY()` interprets as a huge allocation request, causing Git to die. The fix is mechanical: change the type of `alloc` in `struct diff_words_buffer` and `diff_words_fill()` from `unsigned long`/`long` to `size_t`, aligning with Jeff King’s 2026 xdiff work (commit 3c7a31204f) that made `mmfile_t` sizes `size_t`.

The patch touches only `diff.c` and changes two lines. It is part of a broader effort to eliminate Windows-specific truncations (the cover letter notes 237 such sites; this series fixes four). The fix is well-motivated, narrowly scoped, and directly addresses a crash scenario. No test is added here, but the first patch in the series includes an `EXPENSIVE` test for 4 GiB+ object writes, and the word-diff overflow is now precluded by the type change. The patch is uncontroversial and appears ready for integration.
