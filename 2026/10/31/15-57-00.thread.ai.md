Subject: [PATCH 0/4] http: exponential backoff, configurable retry codes, POST retries
Series version: v1 (initial submission)
Originating author: Ravi Mistry (via GitGitGadget)
Thread type: patch series

Core problem or goal
Address four gaps in Git’s HTTP transport error handling: (1) an off-by-one retry count bug, (2) missing exponential backoff when Retry-After headers are absent, (3) inability to retry transient 5xx server errors, and (4) lack of retries for HTTP POST requests (used during fetch/clone and partial clone data transfers). The goal is to improve resilience when interacting with hosting backends and reverse proxies under high concurrency.

Current status
Under review; no prior versions of this exact series. Earlier proposals in 2020 and 2024 addressed subsets of these issues but did not land.

Key technical details
Files touched: `http.c`, `remote-curl.c`, documentation (`git-config.txt`, `git.txt`), and tests (`t/t5584-http-429-retry.sh`, `t/lib-httpd/http-429.sh`).
New or renamed symbols: config key `http.retryStatusCodes` (default "429"), exponential backoff behavior for `http.retryAfter` when Retry-After is missing.
Behavior changes: retry logic now applies to HTTP POST requests, retryable status codes are configurable, and backoff timing doubles on each retry in the absence of Retry-After headers.
On-disk format: unchanged.
Test coverage: new test script `t/t5584-http-429-retry.sh` and expanded helper `t/lib-httpd/http-429.sh`.
