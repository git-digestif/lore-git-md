This is the first patch in Elia Pinto’s four-patch **bugfix series** targeting 64-to-32 truncations on Windows (LLP64 platforms). It converts the object-database write path (`odb_write_object_ext`, `odb_write_object`, `odb_source_write_object`, and `write_loose_object`) from `unsigned long` to `size_t` so that files larger than 4 GiB can be written without silent truncation. The patch also updates the in-memory source’s size field to `size_t` for consistency.

The change is mechanical: every function signature and the `inmemory_object.size` field are widened, and the call sites already pass `size_t` values, so no caller adjustments are needed. On 64-bit Linux the behavior is unchanged; on Windows the patch prevents data corruption when `git add` or `git hash-object -w` processes a file over 4 GiB that requires filtering (CRLF conversion, clean filters, or ident expansion).

The patch adds an `EXPENSIVE`/`SIZE_T_IS_64BIT` test in `t1007-hash-object.sh` that writes a 5 GiB file with a null filter and verifies the object ID and its existence via `git cat-file -e`. This test was revised in v3 to drop the redundant size-file check and avoid a race condition, addressing Patrick Steinhardt’s procedural feedback from v2. The test now mirrors the existing “hash filtered files over 4 GiB” test but exercises the write path.
