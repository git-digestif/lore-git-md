Thread identity: Bugfix patch from Linus Torvalds for `git describe` miscomputing commit distance due to skewed commit dates. Thread type: regression fix (single patch).

Core problem or goal: Correct `git describe`'s commit distance calculation when commit timestamps are non-monotonic, ensuring it follows true topological order (via commit generation numbers) rather than being misled by unreliable dates. The issue caused real-world discrepancies in the Linux kernel's version reporting during the v7.4 merge window.

Current status: Patch submitted by Linus Torvalds; no prior versions. Under review. No maintainer decision yet.

Key technical details:
- **File modified**: `builtin/describe.c` (one-line change to queue comparison function).
- **New behavior**: Priority queue now uses `compare_commits_by_gen_then_commit_date` instead of `compare_commits_by_commit_date`, prioritizing commit generation numbers from the commit graph.
- **Prerequisite**: Commit graph must be available for generation numbers to be used.
- **Test coverage**: Two proposed test cases in `t/t6120-describe.sh`:
  1. Original: Hard-coded commit dates creating a tag dated before its parent (Linus's version).
  2. Rewritten: Uses `test_tick` manipulation to achieve the same skew (Tuomas Ahola's version). Junio C Hamano critiques this rewrite, arguing the original is clearer for this specific test case and pointing out a technical flaw (subshell `test_config` cleanup issue). Tuomas has since conceded the rewrite was flawed and inferior.
- **Subsystems touched**: `git describe` command, commit graph generation numbers.
- **On-disk format**: No changes.
- **Backwards compatibility**: Maintained; the fix only affects behavior when commit dates are skewed.

Open questions and loose ends:
