Key technical details:
- **File modified**: `builtin/describe.c` (one-line change to queue comparison function: `compare_commits_by_gen_then_commit_date` instead of `compare_commits_by_commit_date`).
- **New behavior**: Priority queue uses commit generation numbers from the commit graph when available, falling back to commit dates only if the graph is stale or absent. The fallback now triggers a warning.
- **User-facing changes**:
  - **`--exact` flag**: Defaults to on (opt-out via `--no-exact`), forcing a full commit-graph walk via `ensure_generations_valid()` for guaranteed accuracy. Users can opt out in read-only or legacy repositories to avoid the performance cost.
  - **Warning mechanism**: Emitted when the commit graph is unavailable and the command falls back to commit dates. Open questions remain about rate-limiting or configurability, but the mechanism itself is agreed upon.
- **Proposed performance optimization**: Commit-graph write-back after `ensure_generations_valid()` to amortize the cost (Junio/Stolee proposal). Not yet implemented; details (e.g., automatic vs. configurable, guardrails) remain unresolved.
- **Linux kernel workflow**: The regression caused real-world discrepancies in the kernel's version reporting during the v7.4 merge window, motivating the fix and the opt-out design.
- **Test coverage**: Original hard-coded date test (Linus's version) adopted as the reference. Test file: `t/t6120-describe.sh`.

- **Backwards compatibility**: Maintained; the fix and `--exact` flag preserve existing behavior for users who opt out or lack a commit graph.
