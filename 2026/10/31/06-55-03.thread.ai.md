Thread identity: Bugfix patch from Linus Torvalds for `git describe` miscomputing commit distance due to skewed commit dates caused by GitLab’s Marge-bot `--keep-committers` merge logic, now reopened for algorithmic reconsideration after a follow-up proposal. Thread type: regression fix (single patch, expanded into broader correctness guarantees, user experience design, algorithmic alternatives, and test infrastructure adjustments).

Core problem or goal: Correct `git describe`'s commit distance calculation when commit timestamps are non-monotonic by prioritizing reliable metrics over unreliable dates, while ensuring the fix is robust, performant, and user-friendly. The regression stems from GitLab’s Marge-bot workflow, which uses `--keep-committers` to preserve original committer dates during rebase, artificially skewing timestamps by up to three days. The thread has explored two competing solutions: (1) Linus’s original one-line fix using commit generation numbers (with an opt-out `--exact` flag and warning mechanism), and (2) Kristofer Karlsson’s prototype algorithm that delivers near-exact distances without relying on generation numbers, potentially obviating the need for `--exact`.

Current status: Patch submitted by Linus Torvalds; no prior versions. **Queued for integration in `next` (cooking)**, but the design debate is now reopened. The prior consensus (opt-out `--exact` with warning) is challenged by Kristofer’s proposal, which claims to achieve near-exact results without the performance cost of `ensure_generations_valid()`. No maintainer or key participant has yet substantively endorsed or rejected Kristofer’s proposal, though Junio C Hamano has labeled it "interesting." The commit-graph write-back mechanism (Junio/Stolee) remains a complementary performance optimization but is not yet implemented. Junio has now proposed a test-infrastructure patch to resolve the inconsistency in `t6120.102` (the `--candidates=2` disjoint-history test) by freezing it to run with `GIT_TEST_COMMIT_GRAPH=1` and flipping it from `expect_failure` to `expect_success`. This aligns the test with the project’s default behavior (`core.commitGraph=true` since mid-2019) and avoids testing an artificially degraded mode. The patch is minimal (four lines in `t/t6120-describe.sh`) and does not address the algorithmic debate, but it ensures the test suite remains reliable while the discussion continues.

Key technical details:
- **Files modified**:
  - `builtin/describe.c` (Linus’s fix and Kristofer’s prototype).
  - `t/t6120-describe.sh` (Kristofer’s test-fix patch, now superseded by Junio’s test-infrastructure patch).
- **Linus’s fix**: One-line change to queue comparison function (`compare_commits_by_gen_then_commit_date` instead of `compare_commits_by_commit_date`).
- **Kristofer’s prototype**: ~120 lines added, ~60 removed, replacing the priority queue logic with a two-counter algorithm (commits visited vs. commits carrying the tag’s bit) and an epsilon-based heuristic for commits outside the commit-graph.
- **Junio’s test-infrastructure patch**: Freezes `t6120.102` to run with `GIT_TEST_COMMIT_GRAPH=1` and flips it from `expect_failure` to `expect_success`, reflecting the project’s default behavior and avoiding testing an artificially degraded mode. The change is minimal (four lines) and does not affect the algorithmic debate.
- **Root cause of regression**: GitLab’s Marge-bot `--keep-committers` merge logic, which preserves original committer dates during rebase, artificially skewing commit timestamps by up to three days.
- **New behavior (Linus’s fix)**:
  - Priority queue uses commit generation numbers from the commit graph when available, falling back to commit dates (with warning) if the graph is stale or absent.
  - `--exact` flag (default: on) forces a full commit-graph walk via `ensure_generations_valid()` for guaranteed accuracy.
- **New behavior (Kristofer’s prototype)**:
  - Tracks two counters per tag: total commits visited and commits carrying the tag’s bit.
  - Depth computed as the difference between counters; commits re-enqueued when they gain a bit late.
  - Epsilon-based heuristic (1 week) for commits outside the commit-graph, enabling early termination.
  - Works with partial commit-graphs: commits outside the graph rely on epsilon, while commits inside can stop early.
  - Produces correct distances for the regression case (2a500a04d6f9 → v7.3-19059) with/without commit-graph, matches `rev-list --count` on the last merge window, and passes `t6120-describe.sh` under both `GIT_TEST_COMMIT_GRAPH` settings.
- **User-facing changes (Linus’s fix)**:
  - `--exact` flag (opt-out via `--no-exact`), warning when falling back to commit dates.
- **User-facing changes (Kristofer’s prototype)**:
  - No flag or warning needed; near-exact results by default.
- **Performance**:
  - Linus’s fix: Performance cost of `ensure_generations_valid()` when `--exact` is enabled (amortized via proposed commit-graph write-back).
  - Kristofer’s prototype: Roughly the same performance cost as the current implementation, with no dependency on commit-graph freshness.
- **Test coverage**:
  - Linus’s fix: Original hard-coded date test adopted as reference (`t/t6120-describe.sh`).
  - Kristofer’s prototype: Passes all existing tests under both `GIT_TEST_COMMIT_GRAPH` settings.
  - Junio’s test-infrastructure patch: Ensures `t6120.102` consistently passes when run with `GIT_TEST_COMMIT_GRAPH=1`, aligning with the project’s default behavior.
- **Subsystems touched**: `git describe` command, commit graph generation numbers (Linus’s fix), warning mechanism (Linus’s fix), test infrastructure (Junio’s test-infrastructure patch and Kristofer’s superseded test-fix patch), and potentially `git maintenance` integration for commit-graph write-back (unaffected by Kristofer’s prototype or Junio’s test-infrastructure patch).
- **On-disk format**: No changes to existing formats. The proposed commit-graph write-back (Linus’s fix) would introduce a new caching step; Kristofer’s prototype and Junio’s test-infrastructure patch do not require it.
- **Backwards compatibility**: Maintained by both approaches. Linus’s fix preserves existing behavior for users who opt out or lack a commit graph; Kristofer’s prototype matches the current behavior’s performance profile while improving accuracy.
