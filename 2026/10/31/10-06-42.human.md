This is a bugfix for the `merge-ort` merge strategy. The patch addresses a long-standing inconsistency where Git rejects valueless configuration settings like `-c merge.renames` or `merge.renames` in a config file, even though the documentation (`git(1)` and `git-config(1)`) states that such settings should default to `true`. The issue affects all commands that use `merge-ort`, including `git merge` and `git rebase`.

The root cause is that `merge-ort.c` uses `repo_config_get_string()` to read rename-related settings, which fails when no value is provided. The fix switches to `repo_config_get_value()`, which correctly handles valueless settings by passing them to `git_config_rename()` and `git_parse_maybe_bool()`, both of which already treat a missing value as `true`. The change is minimal: twelve lines of code are adjusted, and the patch adds regression tests to both `t6423` (directory rename detection) and `t6434` (rename option handling).

The commit message is clear and well-motivated, citing the relevant documentation and explaining why the current behavior is wrong. The tests cover the three affected settings (`diff.renames`, `merge.renames`, and `merge.directoryRenames`) and verify that the fix works both on the command line and in config files. This looks like a straightforward, well-crafted fix that should be uncontroversial.
