# Thread deltas

## 2026/10/31

- [2026/10/31/06-55-03 by Linus Torvalds <torvalds@kernel.org>] Linus Torvalds submitted a patch to fix `git describe` miscomputing the commit distance when commit dates are skewed, changing the priority queue in `builtin/describe.c` from `compare_commits_by_commit_date` to `compare_commits_by_gen_then_commit_date` and adding a test case in `t/t6120-describe.sh` for a tag dated before its parent.
- [2026/10/31/12-31-49 by Tuomas Ahola <taahol@utu.fi>] Tuomas Ahola shared an alternative rewrite of the test case using `test_tick` arithmetic instead of explicit dates, stating it works and might offer food for thought.

## 2026/11/01

- [2026/11/01/01-07-10 by Junio C Hamano <gitster@pobox.com>] Junio C Hamano reviewed Tuomas Ahola's rewrite of the skewed-commit-dates test and objected that registering a clean-up action (test_config) from inside a subshell would fail, and argued the rewrite has little value because explicit --date timestamps make each commit's relative timestamp clear in the source, unlike $test_tick arithmetic.
- [2026/11/01/09-46-53 by Tuomas Ahola <taahol@utu.fi>] Tuomas Ahola conceded his rewrite fails under Bash (which he had not tested), acknowledged it was a somewhat pointless "caveat lector" exercise, thanked Junio for the serious review, and accepted the point about explicit dates ("Okay, I'll be wiser next time").
- [2026/11/01/18-12-59 by Junio C Hamano <gitster@pobox.com>] Junio C Hamano clarified that the subshell failure is a general rule—helpers relying on test_when_finished, such as test_config, must not be used in a subshell in any shell, and detecting that misuse portably was not possible—then decided to pick up the patch and move it forward.
