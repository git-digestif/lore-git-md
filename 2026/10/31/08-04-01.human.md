This is the second patch in a two-part **bugfix** series that aligns the `@{push}` revision suffix with `git push` behavior in triangular workflows when `push.default=simple`. The first patch refactored the code for readability; this one implements the actual fix.

The issue is straightforward: when a branch’s upstream is on one remote but its push remote is another, `git push` (with `push.default=simple`) correctly pushes to the same-named branch on the push remote, but `@{push}` fails to resolve. This inconsistency causes `git status` to omit the push-branch comparison and show misleading hints. The patch makes `@{push}` resolve to the same-named branch on the push remote, matching `git push`’s behavior.

The change is minimal—just 13 lines in `remote.c`, adjusting the `branch_get_push_simple()` helper to handle the triangular case. The logic now mirrors the existing `PUSH_DEFAULT_SIMPLE` behavior in `git push`, so the fix feels natural rather than bolted-on. Test coverage is expanded: `t/for-each-ref-tests.sh` gains a regression test for `@{push}` in triangular setups, and `t/t1514-rev-parse-push.sh` is updated to clarify that the "fails with default=simple" test now applies only when the upstream branch has a different name (not when the remotes differ). The error-path test is preserved by tweaking it to use a differently named upstream branch on the same remote instead of an invalid push remote.
