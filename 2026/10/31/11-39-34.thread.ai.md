Thread identity: Subject "[PATCH v2 0/4] Fix truncation issues with large objects on 32-bit platforms", series version v2, originating author Elia Pinto <gitter.spiros@gmail.com>, thread type bugfix patch series. Based on master at e1ec09b23c.

Core problem or goal: Fix truncation and correctness issues when handling objects >=4 GiB on platforms where `unsigned long` is 32-bit (notably 64-bit Windows) while `size_t` is 64-bit. The series converts key components in the pack-receiving and verification pipeline (`unpack-objects`, `index-pack`, `git fsck`) from `unsigned long` (and one `unsigned int`) to `size_t` to match the underlying pack code, addressing an "inflate returned -5" failure, crashes, false SHA-1 collision reports, and partial object checks.

Current status: v2 under review; no merge status indicated. v1 received no review comments. Changes from v1: rebased onto current master where commit e07ac16d1c (Kristofer Karlsson) already converted `stream_blob()` to take `size_t`, so patch 1/4 drops that hunk and rewrites its commit message around the remaining affected paths (non-streamed objects, `unpack-objects -n`, delta handling); the cast previously removed from `unpack_delta_entry()` is instead placed in `write_object()` as a `cast_size_t_to_ulong()` guard so oversized objects die with a clear error rather than being written truncated, pending future conversion of `odb_write_object()` and `parse_object_buffer()`; commit messages clarified to specify the issue arises where "long" is 32 bits while `size_t` is 64.

Key technical details: Files touched are `builtin/unpack-objects.c`, `builtin/index-pack.c`, `builtin/fsck.c`, `odb.h`, and `pack.h`; subsystems are the pack-receiving pipeline, object verification, and fsck. Patch 1/4 converts `builtin/unpack-objects.c` to use `size_t` throughout, spanning `struct obj_buffer.size`, `get_data()`, `struct delta_info.size`, `add_delta_to_list()`, `write_object()`, `resolve_delta()`, `added_object()`, `unpack_non_delta_entry()`, `resolve_against_held()`, and `unpack_delta_entry()`, fixing inflate failures for non-streamed large objects, crashes when delta bases exceed 4 GiB, and silent truncation of large delta results; with `size_t` in place, `unpack-objects -n` and non-streamed objects of any size are handled correctly. The `cast_size_t_to_ulong()` guard in `write_object()` protects downstream callees still accepting `unsigned long`, causing oversized objects to die with "object too large to read on this platform" rather than being written truncated; the cast previously present in `unpack_delta_entry()` is removed since `base_size` is now `size_t` throughout. Patch 2/4 changes `write_compressed()` in `index-pack` from `unsigned int` to `size_t` to fix "serious inflate inconsistency" in `index-pack --fix-thin` when local bases exceed 4 GiB. Patch 3/4 converts `sha1_object()` and `append_obj_to_pack()` in `index-pack` to `size_t` to stop false "SHA1 COLLISION FOUND" errors for large objects already present locally. Patch 4/4 updates the `verify_fn` callback in `pack.h` and `fsck_obj_buffer()` in `builtin/fsck.c` to `size_t` so `git fsck` inspects full objects rather than prefixes. No on-disk format changes. No tests included (impractical to generate 4 GiB objects or test on 32-bit platforms); commit messages describe verifying fixes by truncating sizes to 16 bits in simulation.
