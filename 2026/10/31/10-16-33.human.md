This is the second patch in Elia Pinto’s four-part bugfix series targeting 64-to-32 truncations on Windows (LLP64 platforms). It fixes a crash in the word-diff subsystem when processing large files by converting the buffer allocation size from `unsigned long` (32-bit on Windows) to `size_t`.

The issue is straightforward: `diff_words_fill()` writes each word followed by a newline, so its output can be nearly twice the input size. When the input approaches the 1 GiB `MAX_XDIFF_SIZE` limit, the buffer allocation overflows a 32-bit `long`, leading to undefined behavior—typically a negative size that triggers a fatal `REALLOC_ARRAY()` failure. The patch changes two variables (`alloc` in `struct diff_words_buffer` and `diff_words_fill()`) to `size_t`, matching the type already used for `mmfile_t` sizes since Jeff King’s 2026 xdiff work (commit 3c7a31204f).

The change is minimal—just two lines in `diff.c`—and purely mechanical. It prevents a real-world crash on Windows while maintaining consistency with the rest of the diff subsystem. No behavior change occurs on 64-bit Linux, and the fix is preemptive: even if `MAX_XDIFF_SIZE` were removed, the `ALLOC_GROW()` macro would no longer truncate the requested size. The patch is well-motivated, clearly explained in the commit message, and part of a series that has already addressed all prior feedback. It looks ready for integration.
