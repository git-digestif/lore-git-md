This is the first patch in Elia Pinto’s four-part bugfix series addressing object-size truncation on 32-bit platforms (notably Windows). It converts the `check_object_signature()` function in `object-file.c` from using `unsigned long` to `size_t` for the object size parameter, aligning it with both its callers (which already pass `size_t`) and the internal `hash_object_file()` function it invokes.

The change is minimal—just two lines in the function signature and its header declaration—but it eliminates a silent truncation that occurs when processing objects larger than 4 GiB on platforms where `long` is 32 bits. This truncation causes Git to hash only a prefix of the object, leading to false corruption reports from `git fsck` and signature verification failures in `git tag -v`. The patch does not include a test because reproducing the issue requires objects exceeding 4 GiB in memory, though the author has offered to add `EXPENSIVE` tests if reviewers request them.

The patch is clean, well-motivated, and directly addresses the core problem described in the series cover letter. It’s a straightforward type-consistency fix with no behavioral side effects beyond fixing the truncation bug. If the rest of the series follows this pattern, it looks like a solid, uncontroversial bugfix that should be easy to review and merge.
