Thread identity: bugfix series addressing object-size truncation on 32-bit platforms (Windows); originating author Elia Pinto; thread type patch series (v1).

Core problem or goal: fix truncation bugs when object sizes exceed 4 GiB on 32-bit platforms by converting function signatures and call sites from `unsigned long` to `size_t` for object sizes and message buffer indices. The series aims to eliminate truncation when passing `size_t` to `unsigned long`, but Simon Richter’s review highlights that `size_t` itself is insufficient for 32-bit platforms, where it remains 32 bits; the correct type for on-disk sizes is `off_t` (64 bits with large-file support). User-visible symptoms include `git fsck` inspecting only a prefix of large objects (e.g., `.gitmodules`), `git tag -v` failing to find signatures, and `copy_subject()` misindexing due to integer overflow.

Current status: v1 posted; under review; not yet queued in any integration branch. 24 files touched across object, commit, tag, fsck, ref-filter, and fmt-merge-msg subsystems. Key functions modified: `check_object_signature()`, `parse_object_buffer()`, `parse_commit_buffer()`, `parse_tag_buffer()`, `decode_tree_entry_raw()`, `repo_get_commit_buffer()`, `copy_subject()`, and the fsck subsystem (`fsck_object()`, `fsck_buffer()`, `fsck_tree()`, `fsck_commit()`, `fsck_tag()`, `fsck_tag_standalone()`, `fsck_blob()`, `verify_headers()`). The commit slab in `commit.c` still stores sizes as `unsigned long`, requiring `cast_size_t_to_ulong()` in `set_commit_buffer()` to safely narrow `size_t` to `unsigned long` for objects ≥4 GiB, dying rather than truncating. The final patch also fixes an integer-overflow bug in `copy_subject()` by changing its loop index from `int` to `size_t`.
