This is the third patch in Elia Pinto’s four-part **bugfix series** addressing truncation issues with large objects (≥4 GiB) on 32-bit platforms, particularly Windows. The patch fixes a false "SHA1 COLLISION FOUND" error in `git index-pack` by ensuring object sizes are consistently handled as `size_t` rather than `unsigned long`.

The issue arises when `sha1_object()` compares the full size of a large object (stored as `size_t` in `struct object_entry`) against a truncated size passed as `unsigned long`. On 32-bit platforms, this truncation causes the function to incorrectly flag the object as corrupted, aborting the operation. The fix is mechanical: the patch updates function signatures in `builtin/index-pack.c` to use `size_t` for object sizes, aligning them with the rest of the pack-handling code.

No tests are included, as reproducing the issue requires processing 4 GiB+ objects on a 32-bit system, but the commit message clearly explains the failure mode. The change is low-risk and narrowly scoped, touching only type conversions in a single file. This patch complements the series’ earlier fixes for crashes in `unpack-objects` and inflate inconsistencies in `index-pack --fix-thin`, reinforcing the broader goal of eliminating 32-bit truncation bugs in Git’s pack-receiving pipeline. The series looks well-motivated and ready for review.
