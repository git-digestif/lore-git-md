This is the third patch in Elia Pinto’s four-patch **bugfix series** addressing truncation issues with large objects (≥4 GiB) on 32-bit platforms (notably Windows). The patch converts the `sha1_object()` and `append_obj_to_pack()` functions in `builtin/index-pack.c` from `unsigned long` to `size_t` for object sizes, aligning them with the `size_t` storage already used in `struct object_entry`. On platforms where `unsigned long` is 32-bit, the current code truncates sizes for objects ≥4 GiB, causing `sha1_object()` to falsely report "SHA1 COLLISION FOUND" when comparing a large object against its locally stored counterpart. The fix is mechanical—updating function signatures and adjusting a local variable in `append_obj_to_pack()`—and does not change on-disk formats or introduce new symbols. No test is included due to the impracticality of generating 4 GiB objects or testing on 32-bit platforms, but the commit message provides clear reproduction context. This patch directly resolves a correctness issue in the pack-receiving pipeline, complementing the earlier patches in the series that fix crashes in `unpack-objects` and inflate inconsistencies in `index-pack`. The change is uncontroversial and appears technically sound, addressing a real-world compatibility problem for Windows users.
