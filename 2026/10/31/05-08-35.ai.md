This is a **platform compatibility / test fix follow-up** from a coreutils contributor. Collin Funk, who works on GNU coreutils, replies to Todd Zullinger’s earlier review of Jeff King’s patch for `t5702-protocol-v2.sh`. He explains the motivation behind the coreutils 9.12 quoting change (making `env` output more robust against whitespace and newlines in environment variables), acknowledges that the change broke Git’s test suite, and details the subsequent fix in coreutils: quoting is now applied only when `env`’s output goes to a terminal, not to a pipe or file. This means the problematic quoting behavior that broke Git’s tests will no longer occur in practice for scripts or automated tools, though it remains visible in interactive use.

The email provides useful context for the Git project: the coreutils behavior change was intentional but proved disruptive, and the upstream fix (quoting only for terminal output) should prevent similar issues in the future. Collin also notes that Debian has already applied the fix, so users on unstable should see the corrected behavior soon. No action is requested of the Git project; this is purely informational, closing the loop on why the quoting change happened and how it was addressed upstream. The patch under review (Jeff King’s test fix) remains the correct solution for Git, as it makes the test suite more robust regardless of coreutils version.
