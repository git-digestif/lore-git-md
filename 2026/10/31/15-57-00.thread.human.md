This thread is about a four-patch series from Ravi Mistry that improves Git’s HTTP transport resilience. The series, now at v2, addresses four specific gaps: an off-by-one retry count bug, missing exponential backoff for retries without Retry-After headers, the inability to retry transient 5xx server errors, and the lack of retries for HTTP POST requests (which carry data during fetch/clone and partial-clone operations).

Junio C Hamano reviewed the first three patches in v1, raising design, documentation, and implementation concerns that Ravi addressed in v2. The fourth patch, which extends retry logic to POST requests, received only surface-level review in v1 but remains unchanged in v2. The series now includes clearer documentation, more maintainable code, and thorough test coverage, including a new test script for HTTP 429/5xx retries and POST-specific scenarios. The key technical changes involve configurable retry status codes (defaulting to 429), exponential backoff behavior, and a shared helper function for retry timing.

The main open question is whether 5xx errors should be retried by default—currently, they’re opt-in via configuration. Junio’s feedback on the first three patches has been fully addressed, but the series still awaits deeper review of the POST retry logic or a maintainer decision on the 5xx default behavior. The series is under active review and feels polished, with no major objections raised so far.
