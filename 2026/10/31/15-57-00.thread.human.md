This thread is a patch series from Ravi Mistry improving Git’s HTTP transport error handling. The v2 series, just posted, addresses four gaps: an off-by-one retry count bug, missing exponential backoff when Retry-After headers are absent, inability to retry transient 5xx server errors (now configurable via `http.retryStatusCodes`), and lack of retries for HTTP POST requests used during fetch/clone and partial clone.

Junio C Hamano reviewed the initial v1 and provided substantive feedback on the first three patches, which the author has now incorporated. The v2 changes clarify design choices, improve documentation (notably restoring explanatory text for HTTP 429), and refactor code for better maintainability. Patch 4, which enables POST retries, was already well-received in v1 and remains unchanged. The series is under active review, with no objections raised so far, and the opt-in design for 5xx retries sidesteps potential controversy. Testing is thorough, covering retry counts, backoff behavior, and POST-specific scenarios. The only open question—whether 5xx errors should be retryable by default—remains unresolved but won’t block progress. This looks ready to move forward once Junio confirms the v2 changes address his concerns.
