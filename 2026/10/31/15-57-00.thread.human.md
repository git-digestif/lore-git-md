This thread is about a five-patch series from Ravi Mistry that improves Git’s HTTP transport resilience by fixing an off-by-one retry bug, adding exponential backoff for retries, making retryable status codes configurable, and enabling retries for HTTP POST requests. The series is now in its third version, with all substantive feedback addressed, including a compromise on the default `http.retryAfter` value (10 seconds), which balances server protection and usability.

The key participants are Ravi Mistry (author), Junio C Hamano (maintainer), and brian m. carlson (reviewer). Junio’s latest feedback is procedural rather than technical: he questions whether the default value for `http.retryAfter` should be introduced in the fifth patch (retroactively changing it from 0 to 10 seconds) or integrated earlier in the series. This is a minor structural concern, not a blocker, and the series remains ready for integration once resolved. Brian’s input is solicited on this maintainability question, though the 10-second default itself is already settled.

The patches touch `http.c`, `remote-curl.c`, and related documentation, introducing new config keys (`http.retryStatusCodes`), helper functions (`is_retryable_http_code()`, `http_retry_wait()`), and exponential backoff behavior. Tests cover retry counts, backoff timing, POST retries, and edge cases like past Retry-After headers. No open technical questions remain; the only loose end is the patch organization.
