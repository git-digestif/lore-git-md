This thread is about a four-patch series from Ravi Mistry that improves Git’s HTTP transport error handling. The series addresses an off-by-one retry count bug, adds exponential backoff for retries, makes retryable HTTP status codes configurable (defaulting to 429), and extends retries to HTTP POST requests. Version 2 of the series was posted after Junio C Hamano’s feedback on the first version, incorporating clarifications, documentation improvements, and implementation refinements.

The key changes in v2 include a refactored retry-wait logic, clearer documentation for the new `http.retryStatusCodes` config key, and a more maintainable retry-loop structure. The series touches `http.c`, `remote-curl.c`, and related documentation and tests, introducing new helper functions and behavior changes like configurable retry codes and exponential backoff timing. Tests now cover POST retries, 5xx error handling, and gzipped request preservation.

Junio’s review was substantive but constructive, focusing on design, documentation, and implementation details. Ravi addressed all feedback in v2, including Junio’s concerns about the retry-loop guard clause and the use of `rate_limit_retries` for backoff counting. The only remaining open question is whether the default retryable status codes should include 5xx errors, which the series currently leaves as opt-in via configuration. The series is polished and under review, with no outstanding objections from Junio.
