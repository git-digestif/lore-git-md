This thread covers Ravi Mistry's v4 five-patch series improving Git's HTTP transport resilience against transient failures. The series addresses an off-by-one retry count bug from commit 640657ffd0, adds exponential backoff when servers omit Retry-After headers, enables retrying configurable 5xx status codes beyond 429, adds retry support for read-only POST requests during fetch/clone and partial-clone transfers while explicitly excluding pushes, and changes the default `http.retryAfter` from 0 to 10 seconds. Junio C Hamano has now approved both patch 1/5 (the retry counter fix using post-decrement with a size_t attempt count) and patch 2/5 (the exponential backoff calculation), specifically endorsing the overflow-safe doubling loop that clamps at `http.maxRetryTime`. Patches 3/5 through 5/5 -- covering the configurable retry status codes, POST retries for `git-upload-pack` with the gzip re-encoding fix, and the new 10-second default initial delay -- remain under review awaiting the maintainer's final integration decision.
