Ravi Mistry's five-patch v5 series hardens Git's HTTP transport retry logic against transient server failures, and it has reached the point where patches 1 through 4 have been approved by Junio C Hamano and only the final patch awaits his decision. The series addresses four gaps: an off-by-one bug in the retry count that made `http.maxRetries=N` perform only N-1 retries (and wrapped to a truthy -1 when set to 0), the lack of any backoff when a server omits the `Retry-After` header, the inability to retry 5xx responses since only 429 was hardcoded as retryable, and the absence of retries for the POST requests that carry smart-protocol fetch, clone, and partial-clone traffic.

Across the five patches, the retry logic now consults a new `http.retryStatusCodes` config (default "429", also settable via environment or per-URL), applies exponential backoff computed as `http.retryAfter * 2^(attempt-1)` clamped at `http.maxRetryTime`, and extends the same retry machinery to read-only POST services (`git-upload-pack`, `git-upload-archive`) while deliberately excluding `git-receive-pack` so pushes are never duplicated after a 502/504. The series also fixes a gzip header regression on retry, clears stale slot results between attempts, and documents that an empty `http.retryStatusCodes` disables all retries and that 401/404 can never be retried. Patch 5/5, the one still open, changes the default `http.retryAfter` from 0 to 10 seconds and adds raw-header inspection (via `curl_easy_header()` on libcurl >= 7.84.0) so an explicit `Retry-After: 0` still triggers an immediate retry while a missing header falls back to the new 10-second initial delay.

Junio has approved patches 1-4 individually -- including the overflow-safe backoff doubling, the configurable status codes, and the POST retry loop -- though he flagged a procedural concern that remains open: the series introduces the 10-second default as a separate final patch while the earlier patches assume 0, and his approval of the series overall was partly procedural given that Patrick Steinhardt's substantive review feedback had already been incorporated. brian m. carlson had argued for a longer initial delay, with the 10-second default accepted as a compromise. The series is complete at v5 and now waits on Junio's review of patch 5/5 and his integration decision.
