This thread is about a patch series from Ravi Mistry that improves Git’s HTTP transport error handling by fixing an off-by-one retry bug, adding exponential backoff, making retryable status codes configurable, and enabling retries for HTTP POST requests. The series is now at version 2, with all feedback from Junio C Hamano incorporated, but was blocked by a disagreement over the default initial retry delay (`http.retryAfter`).

The key dispute was between Ravi (proposing a 1-second default for fast recovery) and brian m. carlson (advocating for 30 seconds to protect servers). This has now been resolved: Ravi has agreed to a 10-second default as a compromise, balancing server protection with usability. With this policy agreement, the last substantive obstacle is cleared, and the series is expected to proceed to version 3 with this change and minor documentation tweaks. Junio’s earlier feedback on implementation and documentation has already been addressed, and the series is technically complete. The patches touch `http.c`, `remote-curl.c`, and related documentation and tests, introducing new config keys like `http.retryStatusCodes` and helper functions for retry logic.
