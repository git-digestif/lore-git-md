This thread covers Ravi Mistry's five-patch v3 series improving Git's HTTP transport resilience: fixing an off-by-one retry bug, adding exponential backoff when Retry-After headers are absent, making retryable status codes configurable via `http.retryStatusCodes`, and extending retries to POST requests for fetch/clone operations. The series is under review with all substantive feedback addressed. The main debate over the default `http.retryAfter` value resolved at 10 seconds as a compromise between server protection and interactive usability, though Junio C Hamano raised a procedural question about whether to keep the default change as a separate patch 5 or fold it into patch 2 in a v4.

Patrick Steinhardt's substantive reviews across the series have driven most of the remaining refinements. Ravi has accepted Patrick's correctness objection that POST retries must exclude non-idempotent push operations, committing to whitelist only `git-upload-pack` and `git-upload-archive` in v4 while excluding `git-receive-pack`. Most recently, Ravi agreed with Patrick's point that an explicit `Retry-After: 0` header should trigger an immediate retry rather than falling back to the 10-second default; because libcurl returns 0 for both absent headers and explicit zeros, Ravi will inspect the raw header in v4 to distinguish these cases. With this last edge case accepted, the series awaits only Junio's decision on patch organization before a potential v4.
