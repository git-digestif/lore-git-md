This thread is about a four-patch series from Ravi Mistry that improves Git’s HTTP transport resilience by fixing an off-by-one retry bug, adding exponential backoff for retries, allowing configurable retry status codes, and enabling retries for HTTP POST requests. The series is still under early review, with Junio C Hamano providing feedback on the first two patches.

Junio’s latest review focuses on the second patch, which introduces exponential backoff for retry delays when servers return HTTP 429 without a Retry-After header. While he praises the backoff logic, he raises two design questions: whether a default `http.retryAfter` value of 0 (immediate retry) undermines the backoff mechanism, and why the patch treats `http.maxRetryTime` differently for server-provided Retry-After headers versus exponentially backed-off delays. He also suggests a minor refactor to avoid introducing a new `attempt` counter variable. No objections have been raised, but these points could influence how the feature behaves in edge cases.

The series touches `http.c` and `remote-curl.c`, adds a new config key `http.retryStatusCodes`, and includes extensive test coverage. The main open question remains whether 5xx errors should be retryable by default, and Ravi has yet to respond to Junio’s earlier clarification request about a guard clause in the first patch. So far, the discussion is constructive, with no major disagreements or requests for changes.
