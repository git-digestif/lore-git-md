This thread is about a four-patch series from Ravi Mistry that improves Git’s HTTP transport layer by adding exponential backoff, configurable retry status codes, and support for retrying HTTP POST requests. The series addresses real-world issues observed when Git interacts with hosting backends or reverse proxies under high load, such as off-by-one retry count bugs, missing backoff logic, and the inability to retry transient 5xx errors or POST requests (which handle data transfers during fetch/clone and partial clone operations).

The patches touch `http.c` and `remote-curl.c`, introducing new config options like `http.retryStatusCodes` (defaulting to "429") and modifying the existing `http.retryAfter` behavior to double on each retry when Retry-After headers are absent. The test suite is expanded with a new script (`t/t5584-http-429-retry.sh`) and updates to an existing helper (`t/lib-httpd/http-429.sh`). The series is well-motivated, with clear documentation and thorough test coverage, and it builds logically from low-level fixes to broader retry logic.

This is a revisit of earlier proposals (2020 and 2024), and the series is grounded in existing code, referencing a prior commit (640657ffd0) that introduced the original 429 retry logic. The changes are opt-in via configuration, avoiding debates about default behavior, though the inclusion of 5xx errors as retryable status codes might still spark discussion. So far, the series appears uncontroversial and addresses a practical pain point for users operating at scale. No reviews or maintainer feedback have been posted yet.
