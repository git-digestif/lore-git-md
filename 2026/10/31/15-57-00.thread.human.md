The v3 series from Ravi Mistry addressing HTTP transport resilience—exponential backoff, configurable retry status codes, and POST request retries—remains under review awaiting Junio's final integration. The earlier debate over the default `http.retryAfter` value has been resolved at 10 seconds, balancing server protection concerns raised by brian m. carlson against interactive usability, and Ravi has offered Junio two options for organizing the patches to address a procedural concern about how the default value is introduced. However, Patrick Steinhardt has now raised a new edge-case question on patch 5/5 regarding `Retry-After: 0` headers: he asks whether the implementation ignores an explicit zero value from the server, arguing it should be honored so servers can instruct immediate retry rather than waiting out the new 10-second default. This joins his earlier substantive objections on patch 3/5 (against configurable `http.retryStatusCodes` in favor of ecosystem convergence on 429) and patch 4/5 (that POST retries must exclude non-idempotent operations like push to avoid duplicate pack data). The series is technically complete but now has this additional behavioral question about header precedence to resolve alongside the patch organization decision.
