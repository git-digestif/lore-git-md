This thread is about a four-patch series from Ravi Mistry that improves Git’s HTTP transport error handling. The series, now at v2, addresses an off-by-one retry count bug, adds exponential backoff for retries, makes retryable HTTP status codes configurable (defaulting to 429), and extends retries to HTTP POST requests. Junio C Hamano provided detailed feedback on v1, which Ravi fully incorporated into v2, including clarifications on retry-loop logic, exponential backoff counting, and documentation refinements.

The series touches `http.c`, `remote-curl.c`, and related documentation and tests, introducing the `http.retryStatusCodes` config key and helper functions like `http_retry_wait()`. The only remaining open question is whether 5xx errors should be retryable by default (currently opt-in). Junio’s latest email is a surface-level review of the third patch, focusing on minor documentation formatting and stylistic suggestions—nothing that affects functionality. The series is polished and effectively ready for merging, pending any final maintainer decision on the default 5xx behavior. No other reviewers have raised objections.
