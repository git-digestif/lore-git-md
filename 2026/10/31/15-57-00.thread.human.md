This thread is a four-patch series from Ravi Mistry aimed at improving Git’s HTTP transport resilience. The series addresses gaps in error handling: an off-by-one retry count bug, missing exponential backoff for retries without Retry-After headers, the inability to retry transient 5xx server errors, and—now in the final patch—the lack of retries for HTTP POST requests, which are critical for fetch/clone and partial clone data transfers.

The first three patches laid the groundwork by fixing the retry counter, introducing configurable retry status codes (defaulting to 429), and implementing exponential backoff. The just-posted fourth patch extends this logic to POST requests, ensuring they also benefit from retries, proper wait timing, and header preservation (e.g., `Content-Encoding: gzip`). Tests now cover POST retries for 429 and 502 errors, including partial-clone blob fetches. The series touches `http.c`, `remote-curl.c`, and test files, with no changes to on-disk formats or public APIs.

The series is still in early review, with no objections or requests for changes yet. One open question remains: whether 5xx errors should be retryable by default (currently opt-in via config). The work builds on prior proposals from 2020 and 2024 but is the first comprehensive attempt to land these improvements.
