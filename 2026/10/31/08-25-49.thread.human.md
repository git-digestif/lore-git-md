This thread is about a small but important bugfix for submodule diff headers. Srujith A Poojary's patch (now at v5) ensures that commit abbreviations in submodule diffs are checked against the submodule's object database rather than the superproject's, preventing potential collisions where the same abbreviated commit ID could refer to different objects in the two repositories.

The patch is technically complete and ready for integration. Junio C Hamano has already marked it as "Will queue" after v3, and the v5 update addresses all remaining feedback, including making the test coverage fully hash-agnostic. The only remaining nit is a minor clarification in the commit message about how the test handles different hash algorithms - Junio suggests rewording the explanation of the test's hash-agnostic behavior to be clearer for future readers. This is purely about presentation, not substance.

The fix touches `submodule.c` and adds test coverage in `t/t4041-diff-submodule-option.sh`, introducing `strbuf_repo_add_unique_abbrev()` as a repository-aware replacement for the global `strbuf_add_unique_abbrev()`. The patch is part of Git's broader libification effort, though it's self-contained and not dependent on other in-flight work. With Junio's final comment addressed, this should be queued in the next integration cycle.
