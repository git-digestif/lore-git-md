This thread is a two-patch bugfix series (v4) by Srujith A Poojary that fixes a subtle issue in submodule diff headers: commit abbreviations were being checked against the superproject's object database, which could lead to collisions where the same abbreviated ID referred to different objects in the submodule and superproject. The fix is simple and surgical—`show_submodule_header()` in `submodule.c` now uses the submodule's repository for abbreviation checks when available, falling back to the diff options' repository (`o->repo`) otherwise, eliminating reliance on the global `the_repository`.

The series has been through three prior iterations, with all feedback incorporated. Okhuomon Ajayi provided surface-level review on earlier versions, confirming correctness and suggesting minor improvements (commit message, title prefix, and code style), all of which were addressed. Junio C Hamano accepted v3 with a "Will queue" indication and noted the test could be made hash-agnostic, which Srujith addressed in v4 by adding SHA-256 coverage. The series is now technically complete, with no open questions or loose ends. The fix is low-risk, well-tested, and ready for integration, contributing to both correctness and the broader libification effort by reducing global state usage.
