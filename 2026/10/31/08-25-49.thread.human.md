This thread is about a small but important bugfix for submodule diff headers. Srujith A Poojary's patch ensures that commit abbreviations in submodule diffs are checked against the submodule's object database rather than the superproject's, preventing potential collisions where the same abbreviated ID could refer to different objects in the two repositories.

The fix is technically complete and has been through several iterations. The latest version (v6) addresses Junio C Hamano's only remaining request—a minor rewording of the commit message to better explain the test's hash-agnostic behavior. The patch itself is unchanged from v5, which Junio had already marked as "Will queue." Okhuomon Ajayi provided early feedback on earlier versions, but all substantive concerns have been resolved.

The change is in `submodule.c`, where `show_submodule_header()` now uses `strbuf_repo_add_unique_abbrev()` with the correct repository object. The test in `t/t4041-diff-submodule-option.sh` verifies the fix works for both SHA-1 and SHA-256 repositories. The patch is ready for integration and should land in Junio's queue shortly. It's a clean, self-contained fix that also helps reduce reliance on Git's global `the_repository` variable as part of the broader libification effort.
