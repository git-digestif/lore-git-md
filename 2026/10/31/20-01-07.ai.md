This is a performance patch targeting the `git stash` command. It eliminates duplicate work in the stash creation process by reusing the already-prepared index state and untracked file list when `do_push_stash()` calls `do_create_stash()`.

The patch modifies `builtin/stash.c` to add an optional `prepared_untracked_files` parameter to `do_create_stash()`. When this parameter is provided (as it now is in the `do_push_stash()` call path), the function skips the redundant `repo_read_index_preload()`, `repo_refresh_and_write_index()`, and `check_changes()` steps that were previously performed twice. The existing behavior of `git stash create` is preserved, as it continues to call `do_create_stash()` without the prepared state.

The commit message includes performance measurements showing a 16-18% improvement in `git stash -p` operations and a 6% speedup for `git stash push` on the Linux kernel repository. The change is narrowly scoped to the stash subsystem and does not affect other Git commands or workflows. The patch appears well-motivated and includes test results, though it does not add new tests to the suite.
