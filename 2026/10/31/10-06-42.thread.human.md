This thread is about a small but important bugfix for Git's merge-ort subsystem. Thomas Bachem identified and fixed a regression where commands like `git -c merge.renames merge` would fail with "missing value" errors, even though Git's documentation states that valueless configuration settings should default to `true`. The issue was that merge-ort was incorrectly using `repo_config_get_string()` instead of `repo_config_get_value()` when parsing configuration.

Junio C Hamano has reviewed the patch and given it a clear thumbs-up, calling it "nicely done" and noting that it aligns with similar fixes elsewhere in the codebase. The patch itself is straightforward—it replaces the problematic function call in `merge-ort.c` and adds three new test cases to verify the fix works for `diff.renames`, `merge.renames`, and `merge.directoryRenames`. No objections or open questions have been raised, and the patch appears uncontroversial. It’s now effectively queued for merging, though no formal merge status has been reported yet.
