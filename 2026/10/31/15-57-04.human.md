This is the final patch in a four-part series improving Git’s HTTP transport resilience. It extends retry logic to HTTP POST requests, which handle data transfers during fetch/clone and partial clone blob downloads. Previously, POST requests failed immediately on transient errors (429, 5xx), while GET requests already supported retries.

The patch extracts the retry wait logic from `http_request_recoverable()` into a new helper `http_retry_wait()`, then uses it in `probe_rpc()` and `post_rpc()`. It also defers error reporting until retries are exhausted and preserves the `Content-Encoding: gzip` header when retrying compressed requests. The test suite expands to verify POST retries for 429 and 502 errors, partial clone blob fetches, and gzip header preservation.

This is a well-motivated fix for a real pain point—users at scale frequently encounter transient HTTP errors during data transfers, and Git now handles them consistently across all request types. The implementation is clean, with thorough test coverage and no obvious regressions. The series as a whole looks ready for serious review.
