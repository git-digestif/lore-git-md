This is a brief follow-up in the `git imap-send` header-parsing bugfix thread. The series, which was merged to `next` on June 18, 2025, fixes order-agnostic and case-insensitive header handling for `From:`, `Date:`, and `Subject:` fields, ensuring interoperability with tools like `b4`. However, Junio C Hamano recently identified a latent bug in Patch 2/4: the `has_required_headers()` helper function assumes LF line endings (`\n\n`) to detect the end of headers, but IMAP messages use CRLF (`\r\n`). This mismatch could cause the function to scan past the header block into the message body, risking false positives or negatives.

Harald Nordgren acknowledges the issue and confirms he will address it. The fix is expected to be straightforward (e.g., adjusting the line-ending detection logic to account for CRLF), but it will require a new iteration (`v5`) of the series. The rest of the patches—covering tunnel process lifecycle, case-insensitive header matching, and the removal of a `git-send-email` special case—remain unaffected. Until this is resolved, the series cannot graduate to `master`. If you’ve been tracking this effort, watch for `v5` to land in the coming days.
