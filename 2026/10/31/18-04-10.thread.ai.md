Subject: [PATCH v3] pack-objects: fix truncation of large blob sizes on 32-bit platforms
Series version: standalone patch, v3
Originating author: Elia Pinto
Thread type: bugfix patch

Core problem or goal
Fix a data corruption bug in `git pack-objects` where blob sizes ≥4GiB are truncated when cast from `size_t` to `unsigned long` on platforms where `long` is 32 bits but `size_t` is larger (e.g., 64-bit Windows). The pack header records the wrong size while the compressed data remains full-length, causing corrupted objects during `git repack` or `git gc` when loose large blobs are pruned.

The patch is expected to enter `next` for cooking in the current cycle. All prior feedback (from Simon Richter and Junio) has been incorporated. The patch is narrowly scoped, well-motivated, and uncontroversial.

Key technical details
- File touched: `builtin/pack-objects.c`
- Symbols changed: variables `size` (to `size_t`), `datalen`/`olen` (to `off_t`), and return value of `write_large_blob_data` (to `off_t`); `write_no_reuse_object` return type (to `off_t`)
- Subsystem: pack-objects streaming path for large blobs
- On-disk format: unchanged; the fix restores correct header size recording
- Test coverage: none included (requires ≥4GiB objects on affected platforms)
- Rationale for `off_t`: aligns with the return type of `write_reuse_object()` and is appropriate for file offsets
- Platform scope: affects only platforms where `sizeof(long) == 4` and `sizeof(size_t) > 4`
