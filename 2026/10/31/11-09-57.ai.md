This is the first patch in Elia Pinto's four-part bugfix series addressing object-size truncation on 32-bit platforms (notably Windows). It updates `check_object_signature()` in `object-file.c` and its header declaration to use `size_t` instead of `unsigned long` for the object size parameter, aligning it with the `size_t` values already passed by callers like `odb_read_object()` and the internal `hash_object_file()` function.

The change is mechanical: a single-line signature update in both the implementation and header. The commit message explains the truncation risk on platforms where `long` is 32 bits (e.g., Windows), where objects ≥4 GiB would be hashed only partially, causing valid objects to be misidentified as corrupt by `git fsck` and similar commands. No test is included, as triggering the bug requires processing objects larger than 4 GiB in memory.

This patch is a prerequisite for the rest of the series, which will propagate the `size_t` type through related functions in `commit.c`, `tag.c`, `fsck.c`, and `ref-filter.c`. The thread context confirms the series is under review but not yet queued, and no substantive feedback has been posted so far. The fix is narrowly scoped to the object-file subsystem and does not alter on-disk formats.
