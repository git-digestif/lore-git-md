This thread is about a small but important fix to Git’s test suite to address a portability issue caused by a change in GNU coreutils 9.12. The problem arose when newer versions of `env` began quoting environment variable output, breaking tests in `t5702-protocol-v2.sh` that relied on grepping for `GIT_PROTOCOL=version=2`. Jeff King (Peff) authored a patch that replaces the fragile `env`-based checks with explicit shell variable printing, making the tests resilient to quoting changes while maintaining strict validation of the `GIT_PROTOCOL` value. The patch was reviewed by Todd Zullinger and Junio C Hamano, with no substantive objections, and is now queued in Junio’s `next` branch, awaiting graduation to `master`.

The fix is narrowly scoped to the test script and doesn’t touch production code. It clarifies the test expectations: fetch operations expect `GIT_PROTOCOL=version=2`, while push and archive operations confirm its absence. The discussion also highlighted the broader context of the coreutils change, which was motivated by security concerns (preventing environment variable injection attacks) but initially disrupted scripts that relied on unquoted `env` output. Collin Funk, a coreutils contributor, provided upstream context, noting that the issue was later resolved by restricting quoting to terminal output only, though Peff observed that this trade-off might not fully address injection risks in non-interactive contexts.

The thread wrapped up with a retrospective exchange between Peff and Collin, reinforcing that Git’s revised test logic is an improvement regardless of coreutils behavior. There are no open questions or loose ends, and the patch is expected to merge in the current cycle. The conversation also touched on potential future solutions, such as the `--quoting-style` option, but these were acknowledged as introducing their own portability concerns and not necessary for the immediate fix.
