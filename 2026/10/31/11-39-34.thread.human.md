This thread is Elia Pinto's v2 series of four patches fixing truncation bugs when Git handles objects of 4 GiB or larger on platforms where `unsigned long` is 32 bits but `size_t` is 64 bits -- most notably 64-bit Windows. The series targets the pack-receiving and verification pipeline: patch 1 converts `builtin/unpack-objects.c` to `size_t` throughout to fix inflate failures, crashes on large delta bases, and silent truncation, adding a guard so oversized objects die with a clear error instead of being written truncated; patch 2 fixes `write_compressed()` in `builtin/index-pack.c` to stop "serious inflate inconsistency" errors during `--fix-thin`; patch 3 converts several `index-pack` functions to `size_t` to eliminate false "SHA1 COLLISION FOUND" reports for large objects already present locally; and patch 4, just posted, updates the fsck path (`verify_fn` in `pack.h`, `fsck_obj_buffer()` in `builtin/fsck.c`) so `git fsck` inspects full objects rather than prefixes. The series is based on master at e1ec09b23c and remains under review with no merge status indicated; v1 drew no review comments.

No objections have been raised so far. The main open caveat is that full correctness still depends on a follow-up series converting `odb_write_object()`, `parse_object_buffer()`, and `fsck_object()` to `size_t` -- until then, even with these fixes, fsck and object writing will still only see a prefix of very large objects on affected platforms. No tests accompany the patches because reproducing the bugs requires multi-gigabyte objects on 32-bit-`long` systems; the author verified the fixes via size-truncation simulation.
