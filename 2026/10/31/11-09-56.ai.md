This is a bugfix series targeting object parsing and verification on 32-bit platforms (notably Windows). The patches address a class of truncation bugs that occur when an object's size exceeds 4 GiB: functions that take `unsigned long` parameters silently truncate the `size_t` values passed by their callers, causing Git to misinterpret or fail to process large objects even though no out-of-bounds memory access occurs.

The series is self-contained and does not depend on other in-flight work. It touches 13 files across the object, commit, tag, fsck, and ref-filter subsystems, converting function signatures and call sites from `unsigned long` to `size_t` for object sizes and message buffer indices. Key functions modified include `check_object_signature()`, `parse_object_buffer()`, `repo_get_commit_buffer()`, and `copy_subject()`. The commit message explicitly calls out the user-visible symptoms: `git fsck` inspecting only a prefix of large objects (e.g., `.gitmodules`), `git tag -v` failing to find signatures, and `copy_subject()` misindexing on all platforms.

Elia notes that the pack-related code paths (index-pack, unpack-objects) are intentionally left for a follow-up series, and the tree API changes are being handled in a separate tree-walk series. The series is based on master at 50fe5cc63f and applies cleanly alongside other ongoing work. No new tests are included, as reproducing the bug requires objects larger than 4 GiB in memory; the author offers to add `EXPENSIVE` tests guarded by `!LONG_IS_64BIT` if reviewers request them.
