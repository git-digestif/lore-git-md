This is the second patch in Patrick Steinhardt’s six-patch bugfix series restoring dynamic reload of alternate object databases in Git’s files-based ODB backend. The patch addresses a behavioral regression in `git receive-pack` when a quarantine directory is active: if the alternates file is updated while the quarantine is in place, the updated alternates are not loaded because the code incorrectly reads them from the quarantine directory instead of the repository’s real object directory.

The fix is surgical: it changes two lines in `odb/source-files.c` to use `files->base.path` (the path of the primary ODB) instead of `files->dirs->abspath` (the path of the current head of the directory list) when reading the alternates file and checking directory usability. This ensures alternates are always loaded from the repository’s real object directory, regardless of whether a quarantine directory is active. The change is well-motivated and clearly explained in the commit message, which describes the interaction with the upcoming reload logic in patch 3 and the earlier commit (bdee7b3013) that made the quarantine directory the temporary primary ODB.

The patch is small, focused, and uncontroversial. It does not affect the performance optimizations introduced later in the series (patches 4–6) and has no known side effects. All feedback from the v2 iteration has been addressed, and the patch is ready for integration. If you care about `git receive-pack` or the ODB abstraction effort, this is a straightforward correctness fix worth reviewing.
