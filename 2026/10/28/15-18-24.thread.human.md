This thread is about a performance regression in Git’s object quarantine mechanism during push operations. When `receive-pack` runs connectivity checks, it unnecessarily loads all refs—including hidden ones—from the repository’s own object directory, which `rev-list --alternate-refs` lists twice. This slows down pushes, especially in repositories with many hidden refs.

The solution has converged on a minimal, 10-line fix in `odb.c` proposed by Jeff King: skip any alternate whose path matches the repository’s own `commondir`. This approach is generic, future-proof, and avoids quarantine-specific logic. Kristofer Karlsson’s v3 patch implements this fix, delivering a 65.5% speedup in repositories with 200,000 hidden refs and a 16.7% improvement even without hidden refs. The patch includes a new performance test (`p5552-push-hidden-refs.sh`) and updates to existing tests to verify correctness.

The patch is merged to `next` (as of June 12, 2025) and has broad support from key participants, including Jeff King, Justin Tobler, and Junio C Hamano. It’s also confirmed compatible with Patrick Steinhardt’s concurrent `odb-reload-alternates` series. The remaining work is minor: adjusting the commit message to reflect the commondir comparison approach. The technical direction is now fully settled, and no further design debates are expected.
