This thread is about a performance regression in Git’s object quarantine mechanism during `receive-pack` connectivity checks. When a quarantine environment passes the repository’s own object directory as an alternate, `rev-list --alternate-refs` redundantly lists all refs—including hidden ones—despite prior work to exclude them. This causes measurable slowdowns, especially in repositories with many hidden refs.

Kristofer Karlsson proposed a fix in two iterations. The first version was a proof-of-concept workaround in `odb.c`, but the current v2 patch takes a more robust approach: it repurposes `GIT_QUARANTINE_ENVIRONMENT` to carry the parent repository’s object directory path, avoiding fragile path comparisons. Junio C Hamano and Jeff King have endorsed this as a pragmatic short-term solution, though Junio called the parent-path assumption "icky." The patch modifies `odb/source-files.c` to mark alternates as "borrowed" (from another repository) or not, ensuring only borrowed alternates contribute refs to `--alternate-refs`. This eliminates redundant ref listings, yielding a 67.7% speedup in repositories with 200,000 hidden refs and a 17.6% improvement even without them.

The patch is well-tested, covering edge cases like quarantines outside the commondir and pre-receive hooks. While the parent-path assumption is a stopgap, it aligns with maintainer preferences for minimal invasiveness. Justin Tobler’s earlier proposal for an ODB transaction callback remains a potential long-term solution, but no objections have been raised to the v2 approach. The patch is likely to land in `next` soon, pending final feedback from ODB maintainers Patrick Steinhardt and Justin Tobler.
