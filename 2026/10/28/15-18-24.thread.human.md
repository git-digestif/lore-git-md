This thread is about a performance regression in Git’s object quarantine mechanism, where `rev-list --alternate-refs` unnecessarily loads hidden refs from the repository’s own object directory during connectivity checks. Kristofer Karlsson’s patch (now at v3) fixes this by marking alternates as "borrowed" or not, using heuristics to skip self-referential alternates. The v2 version was merged to `next` on June 12, but v3 proposes a future-proof adjustment to handle object directories specified via Patrick Steinhardt’s `files://` object storage format extension.

The key participants are Kristofer (author), Patrick (who identified a gap in v2 and now suggests an alternative design), Junio (maintainer, who merged v2 to `next`), Jeff King (who endorsed the v2 approach), and Justin Tobler (who proposed a longer-term ODB transaction callback solution). The current debate centers on whether to proceed with Kristofer’s v3 adjustment (a short-term fix) or pivot to Patrick’s suggested approach—appending the quarantine directory to the alternates list—to avoid heuristics entirely. The patch remains viable for `next`, but the path forward depends on Justin’s input, as he’s leading the ODB abstraction effort. No new objections have been raised, and the v2 patch is already in `next`.
