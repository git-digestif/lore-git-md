This thread is about a performance regression in Git’s object quarantine mechanism, where `rev-list --alternate-refs` unnecessarily loads all refs—including hidden ones—from the repository’s own object directory during connectivity checks. The issue was introduced when the quarantine environment passed the repository’s object directory as an alternate, causing refs to be listed twice and degrading performance by up to 67.7% in repositories with 200,000 hidden refs.

Kristofer Karlsson’s patch (v2) addresses this by marking alternates as "borrowed" (from another repository) or not, using two heuristics: the alternate’s path is either the repository’s own `<commondir>/objects` or the parent of `GIT_QUARANTINE_PATH`. This prevents the connectivity check from listing the repository’s own refs. The patch has been merged to Junio’s `seen` branch (2025-06-12) and is on track for `next` and eventual graduation to `master`. Junio and Jeff King endorsed the parent-path deduction as a pragmatic short-term fix, despite its "icky" assumptions, while acknowledging the broader fragility of the alternate object store interface.

Patrick Steinhardt’s recent review identifies a gap in the patch: it doesn’t account for object directories specified via the `files://<payload>` object storage format extension, which can define a primary object directory differing from `<commondir>/objects`. The current logic might incorrectly classify such directories as "borrowed," leading to missing refs in `--alternate-refs` output. Patrick also proposes a more ambitious alternative—appending the quarantine directory to the alternates list and using `GIT_QUARANTINE_ENVIRONMENT` as a read-only flag—but acknowledges this is higher-risk. The current patch remains viable for `next`, but a follow-up may be needed to handle the `files://` case. No other open questions or objections remain, and the patch’s core logic is confirmed compatible with concurrent ODB abstraction work.
