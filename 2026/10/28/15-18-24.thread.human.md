This thread is about a performance regression in Git’s object quarantine mechanism during `receive-pack` connectivity checks. When a quarantine environment includes the repository’s own object directory as an alternate, `rev-list --alternate-refs` redundantly lists all refs—including hidden ones—despite prior work to exclude them. The issue is measurable: in repositories with 200,000 hidden refs, the patch demonstrates a 67.7% speedup (0.31s → 0.10s) for small pushes, and even without hidden refs, every ref is still listed twice, causing a 17.6% slowdown.

The author, Kristofer Karlsson, proposed a proof-of-concept patch that skips alternates matching the repository’s `commondir` in `odb.c`. Two architectural alternatives have since emerged: Justin Tobler’s ODB transaction callback (`odb_transaction_files_check_connected()`), which aligns with the ongoing ODB abstraction effort, and Junio Hamano’s suggestion to repurpose `GIT_QUARANTINE_ENVIRONMENT` to carry the parent’s object directory path, avoiding new APIs or path comparisons. Kristofer now leans toward Junio’s simpler approach as a more immediate fix, though he acknowledges the callback’s architectural merit. No objections to any of the three approaches have been raised, but the thread is awaiting feedback from ODB maintainers (Patrick Steinhardt, Justin Tobler) or Junio on the preferred direction.

The patch touches `odb.c` and adds a performance test (`t/perf/p5547-push-hidden-refs.sh`), with no new symbols introduced yet. The current status is under review, with the patch framed as a temporary workaround. The unresolved question is whether to proceed with the environment-variable fix, the callback, or another solution—each with trade-offs between simplicity and long-term design coherence. The outcome will likely depend on how well the chosen approach integrates with the broader ODB abstraction work.
