This thread addresses a performance regression in Git’s object quarantine mechanism, where `rev-list --alternate-refs` unnecessarily loads hidden refs twice during connectivity checks in `receive-pack`. Kristofer Karlsson’s patch (v3) proposes a targeted fix by marking alternates as "borrowed" or not, using heuristics to skip self-referential alternates. The v2 version of this patch was merged to `next` on June 12, 2025, and is compatible with Patrick Steinhardt’s concurrent ODB refactoring work. However, the v3 adjustment addresses a gap in v2: it accounts for object directories specified via the `files://` object storage format extension, ensuring the logic remains future-proof.

The discussion has now shifted to a broader design question. Patrick Steinhardt suggested an alternative approach—appending the quarantine directory to the alternates list instead of modifying the primary object directory—arguing it avoids heuristics and aligns better with the ongoing ODB abstraction work. Justin Tobler, leading the ODB transaction effort, has weighed in with a substantive review, agreeing that the current approach is fragile. He proposes a more principled long-term solution: propagating transaction context via environment variables to child processes, which would eliminate the need for heuristics entirely. For a short-term fix, he suggests adapting `odb_transaction_env()` to include a "read-only" mode flag that appends the quarantine directory as an alternate without altering the primary object directory. This would suffice for the connectivity check in `git-receive-pack` and aligns with his broader ODB transaction work.

The v2 patch remains in `next` unless Justin’s feedback leads to a redesign, and the v3 adjustment is backward-compatible and low-risk. Key participants—Kristofer Karlsson, Patrick Steinhardt, Justin Tobler, Junio C Hamano, and Jeff King—have all engaged substantively, with no technical objections to either approach. The choice now hinges on whether to proceed with the minimal v3 adjustment or pivot to Justin’s more robust read-only mode approach. The thread’s outcome will influence how Git handles alternates in the context of the ongoing ODB abstraction effort.
