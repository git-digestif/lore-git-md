This thread is about a performance regression in Git’s object quarantine mechanism during `receive-pack` connectivity checks. When the quarantine environment passes the repository’s own object directory as an alternate, `rev-list --alternate-refs` redundantly lists every ref twice, causing measurable slowdowns—especially in repositories with many hidden refs. The fix, now finalized in its third iteration, adopts Jeff King’s minimal 10-line commondir comparison in `odb.c` to skip self-referential alternates entirely. This approach is both performant (65.5% speedup with 200,000 hidden refs) and future-proof, avoiding quarantine-specific logic.

The patch has been merged to Junio’s `next` branch as of June 12, 2025, and is now in its final form. Key reviewers—Jeff King, Justin Tobler, and Patrick Steinhardt—have all endorsed the commondir comparison as the definitive short-term solution, resolving earlier design debates. The only remaining task was a commit message tweak to clarify `--alternate-refs`’s scope, which Junio has already approved. No further code changes are expected, and the patch is on track to graduate to `master` in the next integration cycle.

The fix touches `odb.c`, updates `rev-list` documentation, and adds a new perf test (`p5552-push-hidden-refs.sh`) to measure the improvement. It’s also compatible with Patrick Steinhardt’s concurrent `odb-reload-alternates` series, which caused a merge conflict in an earlier version but is now resolved. While the long-term solution may involve ODB transaction callbacks (as proposed by Justin Tobler), the commondir comparison is the agreed-upon short-term fix.
