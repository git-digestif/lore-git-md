This thread is about a performance regression in Git’s object quarantine mechanism, where `rev-list --alternate-refs` unnecessarily loads all refs—including hidden ones—from the repository’s own object directory during connectivity checks. The issue was introduced when the quarantine environment passed the repository’s object directory as an alternate, causing every ref to be listed twice and creating a measurable slowdown (67.7% speedup with 200,000 hidden refs after the fix).

The discussion has now converged on **Jeff King’s commondir comparison approach** as the short-term fix. This minimal, 10-line change in `builtin/rev-list.c` compares the alternate’s path directly against the repository’s commondir, avoiding quarantine-specific logic entirely. It’s future-proof, aligns with Git’s ethos of small patches, and has been endorsed by both the patch author (Kristofer Karlsson) and Justin Tobler, the maintainer of the ODB abstraction effort. The v2 patch, which used a different approach, remains in `next` for now but will likely be superseded by this new version.

Key participants include Kristofer Karlsson (author), Jeff King (who proposed the leading fix), Justin Tobler (who deferred to Peff’s approach after initially advocating for a broader ODB transaction solution), and Junio Hamano (who merged v2 to `next`). The patch touches `builtin/rev-list.c` and avoids modifying quarantine-specific logic, making it a clean, localized fix. No technical objections remain, and the performance impact has been documented in a perf test (`p5552-push-hidden-refs.sh`). The broader ODB abstraction work (including Justin’s transaction context proposal) is deferred, but this fix ensures the regression is addressed without blocking longer-term efforts.
