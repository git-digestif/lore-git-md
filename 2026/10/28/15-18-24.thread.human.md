This thread is about a **bugfix and performance patch** for Git’s object quarantine mechanism during pushes. Kristofer Karlsson identified a long-standing inefficiency where Git unnecessarily loads *all* hidden refs from the repository’s own object directory during connectivity checks in the quarantine environment. This creates a significant performance bottleneck—up to a **67.7% speedup** in repositories with many hidden refs (e.g., 200,000) and a **17.6% slowdown** even without hidden refs due to redundant ref enumeration.

The patch is a **temporary workaround** in `odb.c` that skips alternates whose paths match the repository’s `commondir`. While it fixes the immediate performance issue, the author frames it as a **proof-of-concept** to measure the bug’s impact, not a final solution. The proper fix is expected to involve changes to the quarantine mechanism itself (likely in `tmp-objdir.c`) to explicitly signal which object directory is "ours" to child processes, rather than relying on fragile path comparisons. The patch includes a **new perf test** (`p5552-push-hidden-refs.sh`) and updates to existing tests (`t5547-push-quarantine.sh`) to verify correctness.

Key participants so far are **Kristofer Karlsson** (author) and **Patrick Steinhardt** (tagged for follow-up), who may weigh in on the long-term fix. The thread is likely to focus on **where** to implement the fix (quarantine plumbing vs. alternate ref enumeration) rather than *whether* to address the issue. The patch is well-tested and motivated, but the stopgap nature of the solution suggests further iterations are coming.
