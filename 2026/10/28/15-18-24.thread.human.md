This thread is about a performance regression in Git’s object quarantine mechanism during pushes. When a repository’s own object directory is mistakenly treated as an alternate during connectivity checks, `rev-list --alternate-refs` lists all refs—including hidden ones—twice, undoing prior optimizations that excluded hidden refs. The issue is measurable: in repositories with 200,000 hidden refs, the patch demonstrates a 67.7% speedup (0.31s → 0.10s), and even without hidden refs, the redundant listing causes a 17.6% slowdown.

Kristofer Karlsson, the author, initially proposed a workaround in `odb.c` but has since shifted toward Junio C Hamano’s suggestion to repurpose `GIT_QUARANTINE_ENVIRONMENT` to carry the parent repository’s object directory path. This avoids new APIs or fragile path comparisons. A v2 patch is in progress, using the quarantine directory’s parent path to deduce the real object directory—a design Kristofer considers safe but slightly "icky." The alternative of introducing a new environment variable was deemed redundant.

The discussion is converging on this approach, with no objections raised to the performance data or the bug’s urgency. Justin Tobler’s earlier proposal for an ODB transaction callback remains a long-term option but is not the focus of the current fix. The patch targets the quarantine plumbing (`tmp-objdir.c`) rather than the ODB layer, aligning with Junio’s preference for minimal invasiveness. Expect a v2 submission soon, unless feedback steers the solution toward a new environment variable for clarity. The thread’s key participants—Kristofer, Junio, and Justin—have all engaged substantively, and the path forward appears clear.
