This thread is about a performance fix for Git’s object quarantine mechanism during `receive-pack`. The issue is that the quarantine environment unnecessarily loads all hidden refs from the repository’s own object directory during connectivity checks, causing measurable slowdowns—up to 67.7% in repositories with 200,000 hidden refs. Kristofer Karlsson proposed a v2 patch that repurposes `GIT_QUARANTINE_ENVIRONMENT` to carry the parent object directory path, avoiding redundant ref traversals without introducing new APIs or fragile path comparisons.

The patch is now converging toward a final solution. Junio C Hamano endorsed the parent-path deduction as a pragmatic short-term fix, despite calling it "another icky assumption," given the performance regression and the existing fragility of the alternate object store interface. Jeff King (Peff) recently weighed in with a substantive review, providing historical context about `GIT_QUARANTINE_PATH`’s original design (as a rendezvous point for index-pack and hooks) and endorsing the parent-path approach as "quite sensible." His feedback reinforces the architectural soundness of the fix, aligning it with Git’s broader principle of avoiding redundant ref traversals. No objections or alternatives were raised, and the patch is now targeting the quarantine plumbing (`tmp-objdir.c`) rather than the ODB layer.

The main open question is whether Patrick Steinhardt or Justin Tobler will object to the parent-path assumption’s safety or propose an alternative. Justin had previously suggested an ODB transaction callback as a long-term solution, but neither he nor Patrick has weighed in on the v2 approach yet. The patch is under active review, with no maintainer decision on integration branch placement, though the recent feedback from Junio and Peff suggests it may land in `next` soon. Follow-up work may address the broader fragility of the alternate interface, but the current fix is seen as a minimally invasive solution to an immediate performance problem.
