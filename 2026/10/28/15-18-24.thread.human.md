This thread is about a performance regression in Git’s object quarantine mechanism during `receive-pack` connectivity checks. When a repository’s own object directory is passed as an alternate during quarantine, `rev-list --alternate-refs` unnecessarily loads all refs—including hidden ones—despite prior work to exclude them. The issue is measurable: in repositories with 200,000 hidden refs, the patch demonstrates a 67.7% speedup (0.31s → 0.10s) for small pushes, and even without hidden refs, every ref is listed twice, causing a 17.6% slowdown.

Kristofer Karlsson initially proposed a v1 workaround in `odb.c` but has since shifted to a v2 approach that repurposes `GIT_QUARANTINE_ENVIRONMENT` to carry the parent’s object directory path, avoiding new APIs or fragile path comparisons. Junio C Hamano, the maintainer, has endorsed this v2 approach as a pragmatic short-term fix, describing the parent-path deduction as "icky" but acceptable. The patch now targets `tmp-objdir.c` and aligns with Junio’s preference for minimal invasiveness. While Justin Tobler previously suggested an ODB transaction callback as a long-term solution, the current focus is on landing the v2 fix. No objections have been raised to the v2 approach, and the patch is likely to proceed unless ODB maintainers (Patrick Steinhardt, Justin Tobler) raise concerns about the parent-path assumption.

The patch touches `tmp-objdir.c` and related test files, with no new symbols or on-disk format changes. Performance improvements are well-documented, and the fix is considered technically approved in principle. The next steps are final review and potential inclusion in `next`. The broader architectural debt around alternate object stores remains unaddressed, but this patch resolves the immediate performance regression.
