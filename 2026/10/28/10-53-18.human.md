This is the final review round for Patrick Steinhardt’s seven-patch series introducing the **object storage extension** (`extensions.objectStorage`), a foundational step toward pluggable object database backends in Git. The series is now **technically complete and unconditionally approved** by Karthik Nayak, with only a minor typo fix ("he" → "the") in the commit message of patch 2/7.

The architectural debate raised by SZEDER Gábor in v3—whether `extensions.objectStorage` should exist as a public API at all—remains unresolved, but this review focuses solely on the mechanical quality of the implementation. Karthik’s approval signals that the series meets the project’s technical standards for integration, including:
- **Design consistency**: The `(type, payload)` split mirrors the ref storage extension’s design, and the `files` backend’s payload (directory relocation) is now explicitly justified in the commit message for testing, alignment, and internal use cases like repository migrations.
- **User-facing interface**: CLI options (`--object-storage-format=` for `git clone`, `git init`, and `git submodule`), environment variables (`GIT_OBJECT_STORAGE_FORMAT`, `GIT_DEFAULT_OBJECT_STORAGE_FORMAT`), and inspection tools (`git rev-parse --show-object-storage-format`, `git repo objects.storageFormat`) are all in place.
- **Edge-case handling**: Local clone restrictions for non-default backends, submodule payload stripping (for consistency with ref storage), and precedence rules (CLI > env > repo config > defaults) are thoroughly tested.
- **Documentation**: Man pages for `git clone`, `git init`, `git submodule`, and `git rev-parse` are updated, though some gaps remain (e.g., payload stripping in submodules and repository format version bumps are undocumented).

The series touches **35 files**, including core subsystems (`odb/`, `setup.c`, `repository.c`), built-in commands, and tests. No substantive changes were made in v4 beyond the typo fix and expanded justification for the payload. The implementation is **ready for integration**, pending Junio’s assessment of the lingering architectural question. If merged, this will enable future backends (e.g., cloud storage) while immediately supporting directory relocation for the `files` backend—a feature Patrick notes will be used internally for migrations and testing.

For readers tracking Git’s evolution, this series is a key milestone in the **ODB abstraction effort**, alongside the ref storage extension and ongoing work like `the_repository` removal. The unresolved debate may prompt further discussion about API design, but the technical foundation is now solid.
