This is a follow-up in the RFC thread for the `git cat-file --remote-object-info` batching series. Pablo Sabater responds to Junio C Hamano’s feedback on the error message wording in patch 1/3, proposing to **remove the early `smart_options` check entirely** and rely instead on the existing `transport_fetch_object_info()` check later in the code path. This resolves the forward-compatibility concern Junio raised: the later check uses the transport’s vtable to test for actual object-info support, avoiding assumptions about `smart_options`. Pablo notes that the current error message at that point is generic but can be improved to include the remote’s URL (e.g., "object-info is not supported by <remote>"), which would be both accurate and actionable for users.

The change simplifies the code and eliminates the need to debate whether the error message should mention "bundles" or remain generic. The thread remains in the design phase, with broader questions about server-side OID limits and batching defaults still open. Pablo plans to send a v2 later in the week, incorporating this adjustment and addressing any other feedback from the RFC discussion. The series continues to target `builtin/cat-file.c` and the transport layer, with no on-disk format changes.
