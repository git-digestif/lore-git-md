This is a **bugfix** patch for the sequencer subsystem, specifically addressing a long-standing edge case in `git rebase --autosquash` where `fixup!` or `squash!` commits that cancel out their target commit (resulting in an empty commit) are not handled according to the `--empty` option. The patch is now at **v5**, incorporating all feedback from Phillip Wood, and is effectively **ready for merging** pending minor tweaks.

The core issue is that Git currently halts the rebase with an error when a `fixup!` or `squash!` commit cancels out its target, ignoring the user’s `--empty` setting (`drop`, `keep`, or `stop`). This patch teaches Git to recognize when applying a `fixup!` or `squash!` empties the target commit and to honor `--empty` for such cases. For example, if a `fixup!` reverts its target, `--empty=drop` will now drop both the original commit and the `fixup!`, while `--empty=keep` retains the empty commit, and `--empty=stop` halts for user intervention.

The implementation is careful to preserve existing behavior: only commits that *become* empty (not those picked empty to begin with) are subject to `--empty` handling, and only the final `fixup!` in a chain may drop the target commit. The patch introduces a new function, `is_amended_head_empty()`, to detect when amending HEAD would leave it empty, and persists this state across rebase restarts using a new on-disk file (`$GIT_DIR/rebase-merge/fixup-target`). It also ensures that dropped commits are not recorded as rewritten, so the post-rewrite machinery (e.g., hooks, `--update-refs`) receives no spurious notifications.

The patch touches `sequencer.c` (core logic), `Documentation/git-rebase.adoc` (user-facing docs), and adds comprehensive test coverage in `t/t3415-rebase-autosquash.sh` and `t/t5407-post-rewrite-hook.sh`. The tests cover all three `--empty` modes for both `fixup!` and `squash!`, including edge cases like mid-chain fixups, root commits, conflict resolution, and already-empty targets. The commit message is thorough, with a clear before/after example and a real-world motivation: at Meta, the author maintains a fork of LLVM where internal patches are managed as single commits using `fixup!` autosquash, and this patch enables automatic dropping of both a patch and its revert when `--empty=drop` is used.

Phillip Wood’s review confirms the patch is technically sound, with only minor improvements suggested (code organization, performance, cleanup, and one additional test case). The patch is narrowly scoped, well-explained, and addresses a genuine workflow pain point. The follow-up discussion about a potential `revert!` autosquash directive remains unresolved but is orthogonal to this patch. This looks like a clean, uncontroversial fix that should land soon.
