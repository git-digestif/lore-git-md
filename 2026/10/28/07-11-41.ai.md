This is the third patch in Patrick Steinhardt’s six-patch bugfix series (v3) restoring dynamic reload of alternate object databases in the files-based ODB backend. It directly addresses the core regression: when an object lookup fails, the backend now reloads the alternates file and retries the lookup, restoring the behavior accidentally broken in March 2026 during the ODB abstraction effort.

The patch modifies `odb_source_files_read_object_info()` to call `prepare_alternates()` on retry and introduces a `tail` pointer to track newly added directories, ensuring only those are rescanned. It also updates `odb_files_dir_is_usable()` to handle the case where no alternates existed before reloading (which can occur when a quarantine directory is active). The new test in `t/t1006-cat-file.sh` verifies the fix by simulating a concurrent alternates update, confirming that an object initially missing becomes available after the alternates file is rewritten.

Performance is a key concern: the unoptimized fix regresses lookup time for 20k missing objects from 185ms to 293ms, nearly matching the pre-regression baseline. The commit message acknowledges this trade-off, noting that the regression is inherent to restoring the correct behavior. Subsequent patches (4-6) will optimize this further, but this patch lays the groundwork by ensuring correctness first. The change is narrowly scoped to the files-based ODB backend and does not attempt to handle recursive alternates, an edge case the commit message explicitly acknowledges was never supported.
