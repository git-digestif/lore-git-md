This is the final review comment in Junio C Hamano’s feedback on the fifth patch of Kaartic Sivaraam’s RFC v3 series, which adds diagnostic context when `GIT_OBJECT_DIRECTORY` points to an unusable directory. The series as a whole aims to improve Git’s error messages by reporting *which* directory Git inspected and *where* it came from, rather than explaining *why* the directory is invalid.

Junio’s comment highlights a subtle but important edge case: the new diagnostic message for `GIT_OBJECT_DIRECTORY` could be misleading when Git fails to find a valid repository *even though* the object directory itself is accessible. For example, if you run `git status` in a non-repository directory (`/`) with `GIT_OBJECT_DIRECTORY` pointing to a valid object store (e.g., `$HOME/w/git.git/.git/objects`), Git will still fail with "not a git repository" — but the new diagnostic would incorrectly suggest the object directory is the problem. This creates confusion, as the real issue is the absence of a valid repository, not the object directory’s accessibility.

The review is substantive, identifying a scenario where the patch’s logic doesn’t align with the user’s mental model. Junio’s examples demonstrate that `GIT_OBJECT_DIRECTORY` is only part of the story: Git’s repository discovery depends on both the object directory *and* the presence of a valid `.git` directory (or equivalent). The current implementation checks `GIT_OBJECT_DIRECTORY` unconditionally at the point of failure, which works for cases where the object directory is truly unusable (e.g., deleted after a reboot) but misfires when the object directory is fine but the repository itself is missing or invalid.

This feedback doesn’t reject the patch outright but suggests the diagnostic logic needs refinement. The fix would likely involve deferring the `GIT_OBJECT_DIRECTORY` check until after Git has confirmed the repository itself is invalid, ensuring the diagnostic only triggers when the object directory is *actually* the culprit. The change would be small — a matter of moving or gating the check — but it’s critical for avoiding misleading error messages. The rest of the series (patches 1–4) remains unaffected, as they focus on other sources of repository paths (`--git-dir`, `GIT_DIR`, and `GIT_CEILING_DIRECTORIES`).
