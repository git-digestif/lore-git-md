This is a bugfix patch series (3 patches) targeting the fetch subsystem, addressing a regression in shallow fetches when backfilling tags. This is the fifth iteration (v5) of the effort, now split into three commits to resolve a memory management blocker identified in v4.

The series fixes a performance regression introduced by commit 0e358de64a ("fetch: use batched reference updates", 2025-05-19), where batched updates delayed committing references until after tag backfilling, causing the client to report no 'have' references during negotiation and forcing the server to send all objects. The solution now exposes pending transaction state via the transport's `negotiation_include_tips` field, restoring correct 'have' reporting while preserving atomicity for `--atomic` fetches. The design avoids the complexity of the v3 two-transaction approach and addresses all prior review feedback except for the unresolved memory management issue.

The key change in v5 is the addition of a precursor patch (1/3) that fixes a pre-existing memory leak in the remote-helper transport's cleanup path by introducing `transport_options_release()`. This allows the main patch (2/3) to drop its manual cleanup logic and rely on the transport's existing mechanisms. The third patch (3/3) moves a tangential test case into its own commit, keeping the core fix focused. The series touches `builtin/fetch.c`, `transport-helper.c`, `transport.c`, `transport.h`, and adds two targeted tests in `t/t5510-fetch.sh` to verify 'have' reporting during tag backfilling for both atomic and non-atomic flows.

The memory management issue from v4—a blocker-level concern about shared ownership of `negotiation_include_tips`—is now addressed by the precursor patch, which ensures proper cleanup for all transport types. The main patch still appends fetched OIDs to the transport's `negotiation_include_tips` array, but the risk of state corruption or leaks is mitigated by the new release mechanism. The scalability trade-off (advertising all fetched references during negotiation) is documented as an acceptable O(n) complexity for fetched refs, and the fix remains 17× faster than pre-batched-update behavior.

The series is now ready for maintainer review, with no outstanding technical objections. Junio C Hamano's position is still unvoiced, but the memory management blocker has been resolved, and the design aligns with Patrick Steinhardt's earlier proposal. The patches are well-motivated, with clear commit messages, targeted tests, and a focus on correctness and performance. The split into three commits improves clarity and maintainability, though the core fix remains in patch 2/3.
