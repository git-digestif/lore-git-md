This is a **bugfix** patch targeting the sequencer subsystem, specifically the `--autosquash` behavior in `git rebase`. The patch (v5) addresses a long-standing edge case where a `fixup!` or `squash!` commit cancels out all changes in its target commit, resulting in an empty commit. Currently, Git fails to honor the `--empty` option (`drop`, `keep`, or `stop`) in this scenario, halting the rebase with an error instead.

The core issue is that `allow_empty()` and `is_index_unchanged()` compare the index against `HEAD` rather than `HEAD`'s parent when amending (as happens with `fixup!`/`squash!`), causing them to miss cases where the melded commit cancels out its target. The patch introduces a new function, `is_amended_head_empty()`, to detect when applying a `fixup!` or `squash!` empties the target commit, and updates the sequencer logic to honor `--empty` for such commits. It also adds persistent state (`$GIT_DIR/rebase-merge/fixup-target`) to track whether the target commit was originally picked with changes, ensuring only commits that *become* empty are subject to `--empty` handling.

Key technical details:
- **Files touched**: `sequencer.c` (core logic), `Documentation/git-rebase.adoc` (user-facing docs), `t/t3415-rebase-autosquash.sh` (new test coverage), and `t/t5407-post-rewrite-hook.sh` (additional test coverage).
- **New symbols**: `is_amended_head_empty()` (detects when a `fixup!`/`squash!` empties its target), `enum fixup_target` (tracks whether the target commit was picked with changes), and `PICK_RESULT_DROPPED_HEAD` (signals when a commit is dropped due to being emptied).
- **Behavior changes**: The patch ensures `--empty` is honored for commits emptied by `fixup!`/`squash!`, while preserving existing behavior for commits picked empty to begin with. It also handles edge cases like mid-chain fixups, conflict resolution, and already-empty targets.
- **On-disk state**: Introduces `rebase_path_fixup_target()` to persist the target commit’s original state across rebase restarts.

The v5 incorporates all feedback from Phillip Wood’s substantive review, including fixes for correctness (e.g., `rewritten-pending` file handling), performance optimizations, and additional test coverage. Notable changes since v4:
- The last fixup in a chain now checks whether `HEAD` was emptied even if the fixup itself is dropped as already upstream.
- `ALLOW_EMPTY` is set unconditionally for non-final fixups or under `--empty=keep`, reducing redundant checks.
- `set_fixup_target_picked()` is now shared with `skip_unnecessary_picks()` to avoid redundant lookups.
- Tests now use `test_commit` and `test_cmp` for clearer diagnostics.

The patch is motivated by a real-world workflow at Meta, where internal LLVM patches are managed as single commits using `fixup!` autosquash. The fix enables automatic dropping of both a commit and its revert when `--empty=drop` is used, eliminating manual todo-list editing.
