This is the first patch in a six-part bugfix series restoring dynamic reload of alternate object databases in Git’s files-based ODB backend. The patch is a straightforward refactoring: it renames two internal functions—`odb_prepare_alternates` becomes `prepare_alternates`, and `odb_add_alternate_recursively` becomes `add_alternate_recursively`—to drop the now-misleading `odb_` prefix. The functions were originally part of the object database layer but are now specific to the files backend, so the rename aligns the code with the ongoing ODB abstraction effort.

The change is purely mechanical, touching only function declarations and call sites in `odb/source-files.c`. No behavior is altered, and the patch includes no new tests. The commit message is concise and clearly states the motivation: the old names no longer make sense given the functions’ current scope. This patch sets the stage for the substantive fixes that follow in the series, which will reintroduce the ability to reload alternates when an object lookup fails.
