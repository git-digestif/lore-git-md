This is the first patch in Patrick Steinhardt’s seven-patch series refactoring `builtin/commit-graph.c` to prepare for pluggable commit-graph backends. It performs a mechanical rename of the subcommand functions from `graph_verify` and `graph_write` to `cmd_commit_graph_verify` and `cmd_commit_graph_write`, aligning them with Git’s naming convention for subcommands wired up via `OPT_SUBCOMMAND()`. The change is confined to `builtin/commit-graph.c` and touches only the function declarations, definitions, and the `OPT_SUBCOMMAND()` invocations that reference them.

The patch is uncontroversial and purely stylistic, serving as a preparatory step for the more substantive refactoring that follows in later patches. It introduces no behavior changes, no new symbols, and no user-visible effects. The motivation is consistency with Git’s established patterns, which will make the codebase easier to navigate and extend as the pluggable backend effort progresses.

This patch is a clear example of the kind of low-risk, high-value cleanup that the `the_repository` removal and backend abstraction efforts rely on. It is unlikely to draw objections, but it sets the stage for the more consequential changes in subsequent patches, particularly the removal of the global `--object-dir=` switch in patch 4. The key names introduced here (`cmd_commit_graph_verify`, `cmd_commit_graph_write`) will be referenced in later patches and reviews, so noting them now helps future discussion tracking.
