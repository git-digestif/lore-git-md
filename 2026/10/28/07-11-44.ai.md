This is the sixth and final patch in Patrick Steinhardt’s six-patch bugfix series restoring dynamic reload of alternate object databases in the files-based ODB backend. The patch optimizes the alternates reloading logic introduced in earlier patches by tracking the alternates file’s mtime and inode using a `struct stat_validity`. This avoids unnecessary re-reads and parsing when the file has not changed, nearly restoring the pre-regression performance baseline.

The patch adds a `struct stat_validity alternates_validity` field to `struct odb_source_files` and updates `read_alternates()` to conditionally parse the file only when its stat data differs. If the file cannot be opened, the validity struct is cleared to ensure the next attempt will re-read it. The recursive alternate resolution (`add_alternate_recursively`) passes `NULL` for the validity parameter, as nested alternates are not tracked for changes. The commit message includes benchmark results showing the optimization reduces lookup time for 20k missing objects from 262.7ms (HEAD~) to 199.5ms (HEAD), a 30.9% improvement and nearly matching the pre-regression baseline of 185.3ms. Memory usage increases slightly (4.3%) due to the `stat_validity` overhead.

The patch resolves a race condition identified in v2 by reordering `stat_validity_update()` before reading the file and clearing the stat cache when `open()` fails. The fix is mechanical and aligns with existing patterns in the codebase. The commit message explicitly acknowledges the performance trade-off and considers the current state "good enough for now." The patch touches only `odb/source-files.c` and `odb/source-files.h`, adding the new field and updating the alternates-reading logic without changing behavior. All technical feedback from v2 has been addressed, and the series is now ready for final review.
