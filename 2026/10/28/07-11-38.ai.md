This is the v3 cover letter for a six-patch bugfix series targeting the files-based ODB backend. The series restores dynamic reloading of alternate object databases when an object lookup fails, a behavior accidentally broken in March 2026 during the ODB abstraction effort. The regression, though rare, has been observed in production systems where the alternates file is modified while Git is running.

The v3 iteration addresses all remaining technical and editorial feedback from v2. The most significant changes are the reinstatement of a `NEEDSWORK` comment in patch 4 (which had been removed in v2), explicit documentation of the error-message suppression in patch 5, and a fix for a race condition in patch 6 that ensures the alternates file’s stat cache is updated before reading and cleared on open failure. The cover letter now clearly states the behavioral change in patch 5: when a previously known alternate directory disappears, the "object directory does not exist" error message is suppressed for performance reasons. Patrick considers this trade-off acceptable because the suppression is narrow (only disappearing alternates, not missing ones during initial addition) and does not affect functional outcomes.

The series is now technically complete and ready for final review. The remaining cosmetic issues (typos, outdated references in the cover letter, and a lingering "map" reference in a code comment) are minor and do not affect correctness. Performance has been carefully optimized: the unoptimized fix regressed lookup time for 20k missing objects from 185ms to 310ms, but the final version reduces this to 199ms, nearly matching the pre-regression baseline. The test coverage in `t/t1006-cat-file.sh` verifies both the basic reload functionality and the edge case where a quarantine directory is active.
