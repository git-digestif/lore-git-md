This is the second patch in Karthik Nayak’s three-patch v5 series that fixes the shallow-fetch-with-tags regression. It is the **core fix** itself: it teaches `git fetch` to advertise the OIDs of the just-fetched refs as “haves” during the tag-backfill negotiation, so the server does not re-send objects the client already has.

The patch touches `builtin/fetch.c` and adds two targeted tests in `t/t5510-fetch.sh`. In `do_fetch()`, it collects the old OIDs of every ref in the `ref_map` into a temporary `oid_array` (`fetched_tips`). When `backfill_tags()` is called, it appends those OIDs to the transport’s `negotiation_include_tips` array, which the smart protocol then sends to the server. The memory-management precursor (patch 1/3) ensures the array is properly freed, so this patch no longer needs manual cleanup.

The two new tests verify that the “have” lines appear in the protocol trace for both atomic and non-atomic fetches, confirming the fix works in both code paths. The commit message explains the trade-off: advertising all fetched refs during negotiation is O(n) in the number of refs, but it is far cheaper than re-transferring objects. The regression is now resolved, and the series is ready for Junio’s final review.
