This is a refactoring patch targeting the `git diff-files` command. A new contributor, Edson, converts the command's ad-hoc option parsing to Git's standard `parse-options` API.

The patch replaces a manual loop that checks for `--base`, `--ours`, `--theirs`, and `-q` using `strcmp()` with a declarative array of `OPT_*` macros. This brings the code in line with Git's coding standards, enables auto-generated help text, and adds support for option abbreviation and shell completion. The change is confined to `builtin/diff-files.c` and touches only the option-parsing logic; the actual diff behavior remains unchanged.

The commit message is clear and explains both the problem (error-prone manual parsing) and the solution (using `parse-options`). The patch itself is small, focused, and follows established patterns from other built-in commands. No new behavior or edge cases are introduced, so this looks like a straightforward, well-motivated cleanup.
