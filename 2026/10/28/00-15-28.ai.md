This is the second patch in William Hatfield’s v2 series enhancing `git submodule foreach` with dependency-ordered traversal. It implements the `--include-superproject` flag, which runs the given command in the superproject after all submodules have been processed. The patch touches the core foreach machinery (`builtin/submodule--helper.c`, `git-submodule.sh`), updates the documentation (`Documentation/git-submodule.adoc`), and adds thorough test coverage (`t/t7427-submodule-foreach-reversive.sh`).

The implementation is careful about environment handling: it preserves the caller’s repository selection (GIT_DIR, GIT_INDEX_FILE, etc.) and only sets `$displaypath` to the superproject’s directory name, leaving other variables either unset or inherited from the environment. This matches the behavior of submodule traversal while ensuring the superproject command sees the same repository context as the original `foreach` invocation. Tests verify edge cases like detached worktrees, alternate indexes, nested foreach calls, and failure handling (the superproject command does not run if any submodule command fails).

The patch is well-motivated for workflows like committing submodule changes and then updating the superproject’s recorded state. It integrates cleanly with the `--reverse-traversal` and `--recursive` flags already introduced in the series, and the test coverage is comprehensive, exercising both happy paths and corner cases. No technical objections have been raised; the remaining discussion centers on naming (`--include-superproject` vs alternatives like `--append-superproject`), which is being tracked in the cover letter.
