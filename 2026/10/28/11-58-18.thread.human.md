This thread is about a bugfix for `git bundle-uri` that prevents crashes when processing relative URIs with excessive parent traversals (e.g., `../../../../etc/passwd`). The patch, now in its second version by Aniket Gupta, introduces a non-fatal variant of `relative_url()` to allow graceful error recovery, which is justified by the fact that bundle lists can come from untrusted servers.

The v2 patch addresses all substantive feedback from the first round, including clarifying the error recovery rationale, improving error messages with credential redaction, and adding test coverage. Patrick Steinhardt, who provided a detailed review of v1, has now weighed in on v2 with two minor refinements: the commit message should better explain why `relative_url()` remains a dying wrapper (for backward compatibility with submodule callers), and the new test in `t0060` should verify the exact error message format rather than just the absence of secrets. Neither point challenges the patch’s core design, and the patch is otherwise ready for merging. One loose end remains: the v1 test cases for certain relative URIs (e.g., `../foo`) were dropped in `t5750`, leaving a small coverage gap. The patch is technically sound and positioned for `next`, pending these final tweaks.
