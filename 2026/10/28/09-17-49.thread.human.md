This thread is about a small but important documentation update to Git's partial-clone subsystem. Edson Wasswa has submitted a patch that clarifies how Git handles promisor remotes when multiple sources exist. The update adds just nine lines to the technical design document, explaining a previously undocumented two-pass fetch order: Git first tries server-advertised promisor remotes (if the client accepts them), then falls back to configured ones. It also documents the security model, making clear that clients only accept server-advertised remotes when explicitly configured to do so.

The patch is narrowly scoped to the "Using many promisor remotes" section and doesn't touch any code or tests. It's well-motivated, addressing a gap in the documentation that could otherwise lead to confusion about fetch order and security implications. Given its self-contained nature and the lack of controversy in the summary, this should be a straightforward merge once reviewed.
