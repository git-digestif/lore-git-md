Subject: `git check-ignore -v` incorrectly matches paths with trailing slashes against CRLF blank lines
Series version: standalone patch (no series)
Originating author: Mike Beaton (reporter), Aniket Gupta (patch author)
Thread type: bug report and fix

Core problem or goal
The `git check-ignore -v` command incorrectly matches directory paths ending in a trailing slash (`foo/`) against blank lines in `.gitignore` when those lines use CRLF line endings or contain only whitespace. Documented semantics state blank lines should never match any file or directory, regardless of line-ending format.

Current status
Under review. The patch by Aniket Gupta is a minimal, surgical fix that restores documented behavior. It modifies `add_patterns_from_buffer()` in `dir.c` to skip adding a pattern if the trimmed line is empty, ensuring blank lines (after trimming carriage returns and spaces) never match any path. The patch includes a new test in `t/t0008-ignores.sh` covering CRLF and mixed-whitespace blank lines. The issue is confirmed to exist in Git 2.51.1 and 2.56.0, ruling out a recent regression. No prior versions of the patch exist.

Key technical details
- **Command affected**: `git check-ignore -v` (output correctness, not core ignore behavior)
- **Subsystem**: ignore-pattern parsing (`.gitignore` handling)
- **Files touched**: `dir.c` (ignore-pattern logic in `add_patterns_from_buffer()`), `t/t0008-ignores.sh` (new test case)
- **Functions involved**: `trim_trailing_spaces()`, `add_pattern()`
- **Behavior change**: paths ending in `/` no longer match blank lines, regardless of line-ending format (CRLF vs. LF) or trailing whitespace
- **Edge cases covered**: CRLF line endings, trailing spaces, mixed whitespace
- **On-disk format**: no changes; the bug is in runtime parsing logic
- **New symbols**: none
- **Test coverage**: reproduction case provided; new test verifies fix for CRLF and mixed-whitespace blank lines
