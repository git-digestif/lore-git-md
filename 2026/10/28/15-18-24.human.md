This is a **bugfix and performance patch** targeting the object quarantine mechanism in `git receive-pack`. The patch exposes and partially addresses a long-standing inefficiency: when pushing to a repository with many hidden refs (e.g., `refs/pull/` or `refs/changes/`), the connectivity check inside the quarantine spuriously loads *all* refs—including hidden ones—because the repository’s own object directory is mistakenly treated as an alternate.

The commit message is unusually candid: the author describes this as a “bug report in patch form” and does not expect the patch to be merged as-is. The fix itself is a path-comparison hack that skips listing refs from the repository’s own object directory, but the author explicitly calls it out as a stop-gap to measure the performance impact rather than a proper solution.

Performance numbers are striking: a push into a repository with 200,000 hidden refs speeds up by **67%** (0.31 s → 0.10 s), while a push into a repository with no hidden refs still improves by **17%** (1.25 s → 1.03 s) because every ref is now listed only once instead of twice. The patch includes both correctness tests (ensuring our own refs are not listed as alternates, but real alternates still are) and a new perf script (`p5552-push-hidden-refs.sh`) that quantifies the gain.

The author invites Patrick Steinhardt to weigh in on a cleaner design—likely involving changes to `tmp-objdir` so that child processes can distinguish the repository’s own object directory from real alternates. Until then, this patch serves as a clear demonstration of the problem and a lower bound on the potential speed-up.
