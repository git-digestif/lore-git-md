This is a **surface-level review** of Jasper Mayone’s `--branch=<branch>` patch for `git worktree list`. Kristoffer Haugsbakk points out that `git for-each-ref --format='%(worktreepath)'` already provides similar functionality and demonstrates how to use it to remove a worktree by branch name. He notes one limitation: it does not list the worktree path if the branch is being rebased, which the new `--branch` option explicitly handles by treating rebasing/bisecting worktrees as having the branch checked out.

The observation is factual and highlights an existing alternative, but it does not engage with the patch’s design or implementation. It does not address the composability argument (e.g., combining with `git branch --merged`), the porcelain output use case, or the ergonomic advantages of a dedicated `--branch` option. The review is brief and does not suggest improvements or raise technical concerns, so it should be read as a reminder of existing tooling rather than a critique of the patch itself.
