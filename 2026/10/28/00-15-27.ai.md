This is the first patch in a feature series (v2) enhancing `git submodule foreach` with reverse-order traversal. It introduces the `--reverse-traversal` flag, which processes submodules in the opposite of their usual path-ordered sequence. When combined with `--recursive`, this enables post-order processing (children before parents), which is particularly useful for dependency-sensitive workflows like builds or deployments in nested submodule hierarchies.

The implementation touches `builtin/submodule--helper.c` and `git-submodule.sh`, adding the new flag and reversing the submodule list before traversal. The patch also includes comprehensive test coverage in the new `t/t7427-submodule-foreach-reversive.sh` file, exercising edge cases like detached worktrees, partially initialized submodules, and dynamic submodule checkout during traversal. Documentation in `git-submodule.adoc` has been updated to explain the new behavior and provide usage examples.

The commit message clearly motivates the change: without this feature, users must manually script reverse-order traversal to ensure nested submodules are processed before their superprojects. The implementation is straightforward and well-tested, though the naming of the flag (`--reverse-traversal` vs alternatives like `--postorder-traversal`) remains under discussion as noted in the thread context. This patch appears technically sound and addresses a real workflow gap in submodule handling.
