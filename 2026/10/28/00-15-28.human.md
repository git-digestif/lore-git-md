This is the second patch in William Hatfield’s three-patch v2 series that extends `git submodule foreach` with dependency-ordered traversal. It implements the `--include-superproject` flag, which runs the supplied command in the superproject after all submodules have been visited. The patch touches the built-in helper, the shell wrapper, the documentation, and adds thorough test coverage for edge cases like detached worktrees, alternate indexes, and nested invocations.

The implementation is clean: the superproject is entered at the top level of the repository where `foreach` was started, and only `$displaypath` is set, leaving the rest of the environment (GIT_DIR, GIT_INDEX_FILE, etc.) intact. Tests verify that the command sees the same repository, worktree, and index as the original `foreach` invocation, including when run from a subdirectory or with a custom index file. The documentation follows the synopsis-style conventions and clearly explains the semantics.

No technical objections have surfaced; the remaining discussion is about naming (`--include-superproject` vs `--append-superproject` or `--execute-last`). This version looks ready for `next` once the interface is finalized.
