This is a bugfix patch for the bundle-uri subsystem. It prevents `git` from dying when a bundle list contains a relative URI that cannot be resolved (e.g., too many `../` components). Instead, the error is reported gracefully, allowing the rest of the bundle list to be processed.

The patch introduces `relative_url_gently()`, a new variant of the existing `relative_url()` helper that returns `NULL` and records the error in a `strbuf` instead of calling `die()`. The original `relative_url()` remains unchanged for backward compatibility with submodule callers. The new function is used in `bundle_list_update()`, where malformed URIs are now treated like other parsing errors rather than fatal conditions.

The test in `t5750-bundle-uri-parse.sh` is updated to reflect the new behavior: instead of expecting a fatal error, it now checks for a non-fatal error message and verifies that the rest of the bundle list is parsed correctly. The patch is well-motivated, with a clear commit message explaining the problem and solution. The code changes are minimal and focused, and the test coverage is thorough. This looks like a solid fix for a real usability issue.
