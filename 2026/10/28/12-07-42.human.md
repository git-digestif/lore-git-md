This is a follow-up in the RFC thread for the `git cat-file --remote-object-info` batching series. Pablo Sabater responds to Junio C Hamano’s feedback on the error message in patch 1/3, proposing to drop the early `smart_options` check entirely and rely instead on the existing `transport_fetch_object_info()` check later in the code. This change would simplify the logic and avoid forward-compatibility issues: the later check uses the transport’s vtable to test for the actual `fetch_object_info` capability, which is more precise than testing for `smart_options`. Pablo notes that the error message can still be made user-friendly (e.g., "object-info is not supported by <remote>") without the early check.

The discussion is now resolved in principle: Junio’s concern about the error message’s clarity and future-proofing is addressed by removing the problematic check rather than rewording it. Pablo plans to send a v2 series after his midterms, so the thread remains in the design phase with no code updates yet. The broader questions about server-side OID limits and batching defaults are still open.
