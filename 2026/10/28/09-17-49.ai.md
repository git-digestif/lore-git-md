This is a documentation patch for the partial-clone subsystem. It updates the technical design document (`Documentation/technical/partial-clone.adoc`) to clarify how promisor remotes are fetched when multiple sources exist.

The patch documents a previously undocumented two-pass fetch order: Git first tries promisor remotes advertised by the server (if accepted by the client), then falls back to configured promisor remotes. It also explains the security model—clients only accept server-advertised remotes when explicitly configured to do so, preventing servers from injecting untrusted remotes. The commit references `gitprotocol-v2` and `git-config` for protocol and configuration details rather than duplicating them.

The change is small (9 lines added) and narrowly scoped to the "Using many promisor remotes" section. The motivation is clear: the current documentation omits this behavior, which could lead to confusion about fetch order and security implications. The patch is well-motivated and self-contained, with no code changes or test updates. It should be uncontroversial.
