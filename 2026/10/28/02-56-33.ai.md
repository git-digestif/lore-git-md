This is the v3 iteration of Colin Hinton’s single-patch series that defers validation of `remote.<name>.followRemoteHEAD` until `git fetch`, eliminating spurious warnings in commands like `git push` or `git remote -v`. The patch now incorporates Junio C Hamano’s refactoring suggestion: the deeply indented logic that determines `follow_remote_head` has been extracted into a new helper function, `lazy_follow_remote_head()`, in `builtin/fetch.c`. The helper reduces indentation, avoids a mechanical conflict with Harald Nordgren’s in-flight `hn/fetch-refmap` topic, and will soon be reused elsewhere in `fetch.c`.

The patch touches `remote.c`, `builtin/fetch.c`, `builtin/remote.c`, documentation files, and adds test coverage in `t5510-fetch.sh`. Key changes include replacing the `follow_remote_head` and `no_warn_branch` fields in `struct remote` with `follow_remote_head_raw` (string) and `follow_remote_head_seen` (flag), and modifying `get_follow_remote_head()` to accept a `var_prefix` parameter for tailored error messages. The `enum follow_remote_head_settings` has been moved from `remote.c` to `fetch.c`. Behavior is unchanged except for the deferred validation, and backward compatibility is maintained.

All substantive feedback from v1 and v2 has been addressed: the author fixed error message ambiguity by passing the variable prefix from the caller, addressed style nits (indentation, long lines, whitespace), and incorporated Junio’s refactoring. Matt Hunter’s explicit approval ("Looks good") on v2 remains valid. Junio reports the mechanical conflict with `hn/fetch-refmap` is now mitigated but still requires that topic to graduate before this patch can be queued. The patch is technically sound, well-reviewed, and ready for integration into `next` or `master` once the dependency is resolved.

The only remaining blocker is the graduation of `hn/fetch-refmap`. Colin has agreed to monitor its progress and rebase once it lands. No other open technical questions or loose ends remain. The patch is a clean, focused refactoring that aligns with the earlier change (86129fd) for `fetch.followRemoteHEAD` and follows the project’s preference for small, self-contained helpers.
