This is the fifth and final patch in Kaartic Sivaraam’s RFC v3 series enhancing Git’s error reporting for invalid repository directories. The series now focuses on reporting *which* directory Git inspected and *where* it came from (e.g., `--git-dir`, `GIT_DIR`, repository discovery, or `GIT_OBJECT_DIRECTORY`), addressing Junio C Hamano’s critique that users are primarily confused about the inspected path’s origin rather than the specific failure reason.

This patch completes the series by adding diagnostic context when `GIT_OBJECT_DIRECTORY` points to an unusable directory. It appends a clear explanation to the "fatal: not a git repository" error (e.g., "cannot access object directory '/tmp/git-objects' set via $GIT_OBJECT_DIRECTORY: No such file or directory"). The implementation introduces a helper function `describe_unusable_object_dir()` in `setup.c` and a wrapper `die_no_repository()` to append the diagnostic context. The check is performed once at the point of failure, and `git init` remains unaffected. Error messages are kept as single translatable strings with `TRANSLATORS` comments for placeholders.

The patch adds 36 lines of test coverage to `t/t0009-git-dir-validation.sh` to verify the new diagnostic output for both explicit gitdir and repository discovery scenarios involving `GIT_OBJECT_DIRECTORY`. The series explicitly defers handling of `gitfile` (submodules/worktrees), `GIT_ALTERNATE_OBJECT_DIRECTORIES`, and edge cases like `GIT_CEILING_DIRECTORIES` entries that don’t affect the search path. No substantive objections to the implementation’s correctness or design have been raised, and the new direction aligns with Junio’s feedback. The series is now complete and ready for review.
