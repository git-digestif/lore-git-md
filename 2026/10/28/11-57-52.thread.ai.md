Originating author: Patrick Steinhardt

Core problem or goal
Refactor `builtin/commit-graph.c` to eliminate globals, simplify option handling, and remove reliance on `the_repository`, preparing the codebase for Patrick Steinhardt’s ongoing effort to make commit-graph backends pluggable. The series targets a single file (`builtin/commit-graph.c`) and reduces its line count by 3 lines (67 insertions, 64 deletions).

Current status
Under review; v1 posted. Junio C Hamano has read the entire series and described patches 1/7–5/7 as "good" but dismissed patches 6/7 and 7/7 as "Meh", indicating they do not meaningfully advance the stated goal of making the code reusable outside `builtin/`. No maintainer decision on merge status; no integration branch assignment. The global `--object-dir=` removal (patch 4/7) remains unaddressed in feedback, leaving it unresolved.

Key technical details
- Files touched: `builtin/commit-graph.c` only.
- New/renamed symbols: subcommand functions (`cmd_commit_graph_write`, `cmd_commit_graph_read`, `cmd_commit_graph_verify`, etc.), de-globalized `write_opts` and `opts` structures (now local to each subcommand), helper function `read_one_commit` now takes an explicit `struct repository *` parameter as its first argument. Patch 5/7 replaces the runtime helper `add_common_options` and dynamic `common_opts` array with a preprocessor macro `COMMIT_GRAPH_COMMON_OPTIONS`, eliminating dynamic allocation and the need for `FREE_AND_NULL(options)`. Patch 6/7 introduces `struct commit_graph_write_config_data` to carry the write options pointer through the config callback, moving `write_opts` from a file-scope static variable to a local variable inside `cmd_commit_graph_write`. Patch 7/7 moves the `opts` structure (common options for "verify" and "write" subcommands) from file scope into the local scope of each subcommand function, making it a stack variable. The `options` array now references this local variable and can no longer be `static`, so the `static` modifier is removed. The `struct commit_graph_write_config_data` is extended to carry a pointer to the local `opts` structure, allowing the config callback to access it without relying on global state.
- Behavior changes: removal of the global `--object-dir=` switch (previously accepted as a global option, now restricted to subcommand-specific use). The global switch was undocumented, unused in tests, and atypical for Git commands. The change eliminates the concatenation of `builtin_commit_graph_options` with `common_opts` (which included the global `--object-dir=` option), replacing it with a single statically allocated `options` array that only includes subcommand-specific options.
- No on-disk format changes; no test coverage changes.
- Subsystems: commit-graph plumbing.
- Additional cleanup: removal of unused `extern int read_replace_refs` declaration (patch 2/7), aligning with commit d24eda4e03c (repository: create disable_replace_refs(), 2023-06-06). Patch 3/7 propagates the repository pointer through the entire call chain in `builtin/commit-graph.c`, eliminating all remaining references to `the_repository`. The change is purely mechanical and confined to the file.

The change could break existing scripts or workflows, even if the behavior was undocumented. No tests were added or modified to validate the new behavior.
