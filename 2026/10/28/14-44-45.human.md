This is a **documentation** patch series, now in its fourth iteration, that replaces the outdated `gittutorial` man page with a new beginner-focused guide. The series is ready for merging, with all substantive feedback incorporated and only minor refinements made in this version.

The new tutorial is split into two parts: the first covers local repository creation and commits, while the second introduces pushing to a remote host (GitHub/GitLab). It reflects modern workflows and avoids confusing beginners about Git’s decentralized model. The author, Julia Evans, has tested the tutorial with 112 users, most of whom completed it successfully, and frames it as "good enough" for merging, with iterative improvements planned post-merge. The most common user feedback was a desire for more content on branching and collaboration, which the author acknowledges but defers to a future effort.

Key changes in this version (v4) focus on making the tutorial more Windows-friendly. The instructions now explicitly recommend Git Credential Manager for authentication on Windows (while keeping SSH for macOS/Linux), clarify editor setup during Git for Windows installation, and adjust terminology (e.g., "folder" instead of "directory") for broader accessibility. Earlier feedback about editor warnings—particularly around `vi`’s default behavior—has been refined to strike a balance between practical guidance and neutrality, with clearer escape instructions and links to editor configuration resources. The SSH key generation instructions now use `cat` to avoid pasting filenames and include a note about key filename variability, addressing prior concerns about user error.

The series touches only `Documentation/gittutorial.adoc`, replacing the old content entirely. No code changes or new symbols are introduced, and the behavior remains unchanged (the old tutorial is deprecated but still accessible). The commit message and range-diff show that all prior feedback—from Junio’s AsciiDoc formatting nits to Ben Knoble’s wording refinements—has been addressed. The author’s rationale for retaining certain choices (e.g., `git init` over `git clone`, `git commit -m` for simplicity) is well-documented, though a few open questions remain, such as whether to adopt newer `git config set` syntax or specify an SSH key type (`ed25519`). These are noted as areas for future refinement rather than blockers.
