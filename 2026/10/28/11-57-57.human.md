This is the fifth patch in Patrick Steinhardt’s seven-patch series refactoring `builtin/commit-graph.c` to prepare for pluggable commit-graph backends. The series is part of his larger effort to abstract Git’s object storage layer, and this patch specifically simplifies how common command-line options are wired up.

The patch replaces a helper function that dynamically concatenated a separate array of common options (`--object-dir=`) with each subcommand’s specific options. Instead, it introduces a preprocessor macro `COMMIT_GRAPH_COMMON_OPTIONS` that expands directly into the option list for each subcommand. This eliminates the need for dynamic allocation and cleanup, reducing boilerplate and making the code slightly more readable. The change is purely internal and does not affect user-visible behavior.

The patch is well-scoped and uncontroversial. It removes 19 lines of code while adding only 8, continuing the series’ goal of reducing complexity in `builtin/commit-graph.c`. The macro-based approach is idiomatic in Git’s codebase (similar patterns exist elsewhere) and aligns with the project’s preference for compile-time over runtime overhead. No test failures or performance regressions are expected, as this is a mechanical refactoring.

The only potential point of friction in the series—the removal of the global `--object-dir=` switch—was addressed in an earlier patch (4/7), so this change is unlikely to draw objections. The patch is a straightforward cleanup that supports the series’ broader goal of eliminating global state in preparation for pluggable backends. If the series as a whole is accepted, this patch will almost certainly be merged as-is.
