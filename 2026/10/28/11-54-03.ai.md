This is the fifth and final patch in Kaartic Sivaraam’s RFC v3 series improving Git’s error reporting for invalid repository directories. It targets the case where `GIT_OBJECT_DIRECTORY` points to an unusable directory, completing the series’ goal of reporting *which* directory Git inspected and *where* it came from.

The patch adds diagnostic context when `GIT_OBJECT_DIRECTORY` is set to a directory that cannot be accessed (e.g., `/tmp/git-objects` cleared after a reboot). Previously, Git would blame the repository itself with a generic "not a git repository" error, leaving users confused about the root cause. Now, the error message appends a clear explanation: "cannot access object directory '/tmp/git-objects' set via $GIT_OBJECT_DIRECTORY: No such file or directory". This aligns with the series’ design principle of clarifying the inspected path and its origin, rather than the specific failure reason.

The implementation is clean and narrowly scoped. It introduces a helper function `describe_unusable_object_dir()` in `setup.c` to check if `GIT_OBJECT_DIRECTORY` is the culprit, and a wrapper `die_no_repository()` to append the diagnostic context to existing error messages. The check is performed once at the point of failure, avoiding redundant work. The patch preserves the existing behavior for `git init`, which legitimately creates the object directory if it doesn’t exist. Error messages remain single translatable strings with `TRANSLATORS` comments for placeholders.

Test coverage is thorough, adding 36 lines to `t/t0009-git-dir-validation.sh` to verify the new diagnostic output for both explicit gitdir and repository discovery scenarios. The tests confirm that the error message includes the inaccessible object directory and its source, while commands with a usable `GIT_OBJECT_DIRECTORY` remain silent. The patch also updates the existing test for explicit gitdir to expect the new diagnostic output.

This patch completes the series’ pivot from v2’s focus on *why* a directory is invalid to v3’s focus on *which* directory was inspected and *where* it came from. The implementation is well-motivated, addressing a real user pain point with minimal code changes. No substantive objections have been raised, and the series aligns with Junio C Hamano’s critique of the v2 approach. The only deferred work is handling edge cases like `gitfile` (submodules/worktrees) and `GIT_ALTERNATE_OBJECT_DIRECTORIES`, which are explicitly out of scope for this series. If the direction is well-received, this could meaningfully improve usability for users debugging repository setup issues.
