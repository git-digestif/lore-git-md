This is the third patch in Patrick Steinhardt’s six-patch bugfix series restoring dynamic reload of alternate object databases in the files-based ODB backend. The patch directly addresses the core regression: when an object lookup fails, Git now reloads the alternates list and retries the read, restoring the behavior accidentally broken in March 2026 during the ODB abstraction effort.

The implementation is straightforward: `odb_source_files_read_object_info()` gains a retry loop that calls `prepare_alternates()` when an object is not found. A new `tail` pointer ensures only newly added directories are rescanned, avoiding redundant work. The patch also relaxes an assertion in `odb_files_dir_is_usable()` to handle the case where a quarantine directory is active and no alternates existed before the reload.

Performance impact is real but unavoidable: the fix regresses lookup time for 20k missing objects from 185ms to 293ms, nearly matching the pre-regression baseline. The commit message acknowledges this trade-off and notes that subsequent patches will optimize it. The new test in `t/t1006-cat-file.sh` verifies the fix by simulating a concurrent alternates update, ensuring the backend reloads the file and finds objects that were initially missing.

The patch is well-motivated, narrowly scoped, and clearly explained. It touches only `odb/source-files.c` and adds a single test case, making it easy to review. The performance regression is documented and will be addressed in later patches, so this change looks ready for integration.
