Subject: [PATCH v2] bundle-uri: handle relative URIs with excessive parent traversals

Core problem or goal
The `git bundle-uri` command crashes when a bundle list contains a relative URI with too many `../` components to resolve against the base URI. The crash occurs in `bundle_list_update()` when `relative_url()` calls `die()`, terminating the entire command and preventing processing of other entries in the bundle list. The patch addresses this by introducing a non-dying variant of `relative_url()` to allow graceful error recovery, justified by the fact that bundle lists can originate from untrusted servers.

Current status
Under review. This is the second version of the patch, addressing all substantive feedback from v1. The v2 clarifies the error recovery rationale, improves error messages (including credential redaction via `transport_anonymize_url()`), and adds test coverage for the new error message format and credential handling. No maintainer decision recorded; the patch is technically sound and positioned as ready for merging.

Key technical details
- Files touched: `bundle-uri.c`, `remote.c`, `remote.h`, `t/t5750-bundle-uri-parse.sh`, `t/t0060-path-utils.sh`
- New function: `relative_url_gently()` in `remote.c`/`remote.h` returns an error instead of dying; `relative_url()` remains as a dying wrapper for backward compatibility (e.g., submodule callers)
- New behavior: `bundle_list_update()` uses the gentle variant and skips malformed URIs after emitting an error, with improved error messages (URLs redacted)
- Test updates:
  - `t5750`: replaces a TODO with a concrete expectation for error output and continued parsing, but drops test cases for certain relative URIs (e.g., `../foo`), leaving a coverage gap
  - `t0060`: adds a new test verifying credential redaction in error messages and the specific error message format
- Subsystems: bundle URI, URL resolution, error handling

Open questions and loose ends
1. **Test coverage gap** – The v1 test cases for certain relative URIs (e.g., `../foo`) remain dropped in `t5750`, which Patrick Steinhardt flagged as a potential regression. The new test in `t0060` covers credential redaction but does not address this gap.
2. **Refactoring opportunity** – Patrick’s suggestion to refactor `relative_url()`’s error-handling complexity is unaddressed, though the patch does not preclude future cleanup. The current design prioritizes minimal disruption to existing callers.
