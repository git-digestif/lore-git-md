Subject: [PATCH] bundle-uri: handle relative URIs with excessive parent traversals
Series version: standalone patch (no series)
Originating author: Aniket Gupta <aniketgupta3001@gmail.com>
Thread type: bugfix patch

Core problem or goal
The `git bundle-uri` command crashes when a bundle list contains a relative URI with too many `../` components to resolve against the base URI. The crash occurs in `bundle_list_update()` when `relative_url()` calls `die()`, terminating the entire command and preventing processing of other entries in the bundle list.

Current status
Under review. No prior versions. No maintainer decision recorded.

Key technical details
- Files touched: `bundle-uri.c`, `remote.c`, `remote.h`, `t/t5750-bundle-uri-parse.sh`
- New function: `relative_url_gently()` in `remote.c`/`remote.h` returns an error instead of dying
- Old behavior preserved: `relative_url()` remains as a wrapper that still calls `die()`
- New behavior: `bundle_list_update()` uses the gentle variant and skips malformed URIs after emitting an error
- Test update: replaces a TODO in `t5750` with a concrete expectation for error output and continued parsing
- Subsystems: bundle URI, URL resolution, error handling

Open questions and loose ends
None identified. The patch addresses the crash, preserves backward compatibility, and includes test coverage.
