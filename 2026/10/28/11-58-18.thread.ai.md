Subject: [PATCH v3 0/3] bundle-uri: handle relative URIs with excessive parent traversals

Thread type: bugfix patch

Core problem or goal
The `git bundle-uri` command crashes when a bundle list contains a relative URI with too many `../` components to resolve against the base URI. The crash occurs in `bundle_list_update()` when `relative_url()` calls `die()`, terminating the entire command and preventing processing of other entries in the bundle list. The series addresses this by introducing a non-dying variant of `relative_url()` to allow graceful error recovery, justified by the fact that bundle lists can originate from untrusted servers.

The v2 addressed all substantive feedback from v1, and v3 incorporates the two minor refinements requested by Patrick Steinhardt: (1) rephrasing the commit message to clarify the backward-compatibility rationale for `relative_url()`’s dying behavior, and (2) tightening the test in `t0060` to verify the full error message format. The series is technically sound and positioned as ready for merging to `next`. No maintainer decision recorded.

Key technical details
- Files touched: `bundle-uri.c`, `remote.c`, `remote.h`, `t/t5750-bundle-uri-parse.sh`, `t/t0060-path-utils.sh`
- New function: `relative_url_gently()` in `remote.c`/`remote.h` returns an error instead of dying; `relative_url()` remains as a dying wrapper for backward compatibility (e.g., submodule callers)
- New behavior: `bundle_list_update()` uses the gentle variant and skips malformed URIs after emitting an error, with improved error messages (URLs redacted via `transport_anonymize_url()`)
- Test updates:
  - `t5750`: replaces a TODO with a concrete expectation for error output and continued parsing, but drops test cases for certain relative URIs (e.g., `../foo`), leaving a coverage gap
  - `t0060`: adds a new test verifying the full error message format, including credential redaction
- Subsystems: bundle URI, URL resolution, error handling

Open questions and loose ends

2. **Refactoring opportunity** – Patrick’s suggestion to refactor `relative_url()`’s error-handling complexity is unaddressed, though the series does not preclude future cleanup. The current design prioritizes minimal disruption to existing callers.
