This is a **surface-level review** of Jasper Mayone’s `--branch` filter patch for `git worktree list`. Kristoffer Haugsbakk points out that `git for-each-ref --format='%(worktreepath)'` already provides similar functionality, but only when the branch is not in the middle of a rebase. He demonstrates how to use it to remove a worktree by branch name, noting that the approach fails if the branch is being rebased.

The observation is technically correct but misses the patch’s broader goal: `--branch` is designed to be a general filter primitive that works *even during rebases and bisects*, and to compose cleanly with `git branch --merged` and other branch-filtering commands. The `for-each-ref` workaround is brittle and does not handle the rebase/bisect case, which the patch explicitly addresses. Kristoffer’s example is a useful reminder of the existing tooling, but it does not engage with the patch’s design or the ongoing discussion about composability, validation, or future extensibility. The review does not identify any new technical issues or suggest improvements, so it is unlikely to shift the conversation.
