This is a **bugfix and performance patch** targeting the object quarantine mechanism in `receive-pack`. The patch exposes and partially addresses a long-standing inefficiency where Git, during a push, unnecessarily loads all hidden refs from the repository’s own object directory when running connectivity checks inside the quarantine environment.

The issue stems from how the quarantine passes the repository’s own object directory as an alternate to child processes. When `rev-list --alternate-refs` runs, it lists *all* refs from that alternate—including hidden ones—despite earlier work (`bcec6780b2`) explicitly excluding hidden refs from connectivity checks. This creates a performance bottleneck: in repositories with many hidden refs (e.g., 200,000), the patch shows a **67.7% speedup** (0.31s → 0.10s) for small pushes, and even without hidden refs, every ref is still listed twice, causing a **17.6% slowdown**.

The fix itself is a **temporary workaround** in `odb.c`: it skips an alternate whose path matches the repository’s own `commondir`. The author, Kristofer Karlsson, explicitly frames this as a **proof-of-concept** to measure the bug’s cost, not as a final solution. The commit message and comments (`NEEDSWORK`) suggest the proper fix should involve the quarantine mechanism itself—likely in `tmp-objdir.c`—to explicitly signal which object directory is "ours" to child processes, rather than relying on path comparisons.

The patch includes **three key components**:
1. A **code change** in `odb.c` to skip self-referential alternates during alternate ref enumeration.
2. A **new perf test** (`p5552-push-hidden-refs.sh`) demonstrating the performance regression and the fix’s impact.
3. **Two functional tests** in `t5547-push-quarantine.sh` verifying that:
   - The repository’s own refs are *not* listed as alternate refs during quarantine.
   - Refs from *real* alternates (other repositories) are still listed correctly.

The patch is **well-motivated** and **thoroughly tested**, with clear performance data and edge-case coverage. However, the author’s hesitation about the path-comparison approach suggests this is a **stopgap**—expect follow-up work from Patrick Steinhardt (tagged in the message) or others familiar with the quarantine/ODB refactoring. The thread is likely to focus on **where** to fix this (quarantine plumbing vs. alternate ref enumeration) rather than *whether* to fix it.
