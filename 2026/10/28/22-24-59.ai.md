This is a refactoring patch for the `git diff-files` built-in command, converting its option parsing from manual string comparisons to Git’s standard `parse-options` API. The patch is now in its third iteration (v3), addressing feedback from Junio C Hamano on the previous version.

The core change remains the same: replacing a hand-rolled loop that checks for `--base`, `--ours`, `--theirs`, and `-q` with a declarative `struct option` array. The new implementation uses `OPT_SET_INT_F` for the stage-selection options (`--base`, etc.) with `PARSE_OPT_NONEG` to block negated forms, and `OPT_BIT` for the `-q` flag. The patch still targets only `builtin/diff-files.c` and does not alter behavior.

Junio’s feedback on v2 identified two mechanical issues: the `struct option` array was declared too late in the function (violating C90’s declaration-before-code rule), and the `diff_files_usage` string was passed incorrectly to `parse_options()` (which expects a NULL-terminated array of strings, not a single string). The v3 patch presumably fixes these, though the email does not show the corrected code. The maintainer’s comments suggest the patch is now technically sound but needs these adjustments to proceed.
