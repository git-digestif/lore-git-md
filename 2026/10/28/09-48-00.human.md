This is the second patch in Karthik Nayak’s three-part bugfix series (v5) targeting a performance regression in shallow fetches when backfilling tags. The series addresses a problem introduced by commit 0e358de64a ("fetch: use batched reference updates"), where batched updates delayed committing references until after tag backfilling, causing the client to report no 'have' references during negotiation and forcing the server to resend objects the client already had.

This patch implements the core fix by exposing pending transaction state to the negotiation phase. It appends the OIDs of already-fetched references to the transport’s `negotiation_include_tips` array, ensuring the server sees them as 'haves' during tag backfill. The change restores correct negotiation behavior while preserving atomicity for `--atomic` fetches, eliminating the need for the more complex two-transaction approach proposed in earlier iterations. The patch also adds two targeted tests in `t/t5510-fetch.sh` to verify that 'have' reporting works for both atomic and non-atomic flows.

The commit message is clear and well-motivated, explaining the root cause (batched updates delaying reference commits), the solution (exposing pending transaction state), and the trade-off (advertising all fetched references during negotiation, which is documented as an acceptable O(n) complexity). The code itself is clean and focused, with minimal changes to `builtin/fetch.c` and no unnecessary refactoring. The tests are straightforward and cover the key edge cases.

This patch is part of a mature series that has already resolved its most significant technical hurdle—a memory management blocker in the transport cleanup path—via a precursor patch (1/3). The design aligns with Patrick Steinhardt’s earlier proposal and addresses all prior review feedback, including Justin Tobler’s concerns about error-path logic and GC safety. The series is now ready for maintainer review, with no outstanding objections. If you care about fetch performance or shallow clones, this is worth watching.
