This is a documentation patch for the partial-clone subsystem. It clarifies how Git handles promisor remotes during fetches, specifically the two-pass order: first trying server-advertised remotes (if accepted by the client), then falling back to configured remotes.

The patch updates `Documentation/technical/partial-clone.adoc` to explain that servers can advertise promisor remotes via Git protocol v2's "promisor-remote" capability, and that these are tried before other configured remotes. It also documents the security model, emphasizing that clients only accept advertised remotes when explicitly configured to do so, preventing servers from injecting untrusted remotes.

The change is small (9 lines added) but well-motivated, addressing a gap in the existing documentation. The commit message clearly explains both the technical behavior and the security implications, making it useful for both users and future contributors working with partial clones.
