This is the third patch in Patrick Steinhardt’s seven-patch series refactoring `builtin/commit-graph.c` to prepare for pluggable commit-graph backends. It removes all remaining references to the `the_repository` global in favor of the repository pointer passed to the command’s entry point. The change is confined to `builtin/commit-graph.c` and is purely mechanical: every call that previously used `the_repository` now uses the `repo` parameter instead. No new functions or data structures are introduced; the patch simply propagates the repository pointer through the existing call chain.

The motivation is straightforward: eliminating `the_repository` is a prerequisite for pluggable backends, and this patch aligns the commit-graph command with the ongoing project-wide effort to remove the global repository variable. The commit message notes that the command cannot run outside a repository, so the repository pointer will never be NULL in practice, and even the `-h` help path is safe because `repo_config()` already handles NULL repositories gracefully.

No user-visible behavior changes are expected, and the patch does not touch on-disk formats, test coverage, or performance. The only potential friction is the mechanical churn of passing the repository pointer through several layers of functions, but the patch is small (20 insertions, 19 deletions) and the transformations are local and predictable. This is a clean, uncontroversial step in the larger refactoring series. Key names modified include the `cmd_commit_graph_verify` and `cmd_commit_graph_write` functions, which now take an explicit `struct repository *` parameter, and the helper function `read_one_commit`, which gains a repository parameter as its first argument.
