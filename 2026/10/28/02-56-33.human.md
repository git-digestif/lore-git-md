This is the v3 iteration of a bugfix/refactoring patch that defers validation of the `remote.<name>.followRemoteHEAD` configuration setting until it is actually needed—specifically, during `git fetch`. The patch eliminates spurious warnings emitted by commands like `git push` or `git remote -v` that load but never use the setting, aligning its behavior with an earlier change (86129fd) for `fetch.followRemoteHEAD`.

The author, Colin Hinton, has incorporated all prior feedback, including Junio C Hamano’s suggestion to refactor the deeply indented logic in `do_fetch()` into a new helper function, `lazy_follow_remote_head()`. This refactoring reduces indentation and mitigates a mechanical conflict with Harald Nordgren’s in-flight `hn/fetch-refmap` topic, though the dependency on that topic’s graduation remains the sole blocker to integration. The patch is otherwise technically sound, well-reviewed, and ready for `next` (or `master`) once the dependency clears.

Key changes include moving the `enum follow_remote_head_settings` from `remote.c` to `fetch.c`, replacing the `follow_remote_head` and `no_warn_branch` fields in `struct remote` with `follow_remote_head_raw` (string) and `follow_remote_head_seen` (flag), and introducing the new helper to encapsulate the logic for determining the setting’s value. The patch maintains backward compatibility and adds test coverage in `t5510-fetch.sh` to verify lazy validation and error message clarity.

Matt Hunter’s explicit approval ("Looks good") from v2 remains valid, and Junio’s feedback on error message ambiguity and style nits (indentation, long lines) has been addressed. The author has also retained a minor AsciiDoc synopsis style improvement (`<branch>` instead of `$branch`) as a consistency tweak. No open technical questions remain beyond the dependency on `hn/fetch-refmap`.

This is a clean, focused patch that resolves a real annoyance (spurious warnings) without introducing new complexity. It’s a straightforward win for users and a low-risk integration candidate once the merge conflict is resolved.
