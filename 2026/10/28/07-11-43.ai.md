This is the fifth patch in Patrick Steinhardt’s six-patch bugfix series (v3) that restores dynamic reloading of alternate object databases in the files-based ODB backend. The patch optimizes performance by avoiding redundant `stat()` syscalls for alternates that are already known to the backend.

The change reorders the logic in `odb_files_dir_is_usable()` to check the `strset` of known alternate paths *before* performing a `stat()` call. This eliminates unnecessary syscalls when an alternate is already tracked, reducing lookup time for 20k missing objects by 3.2% (from 269.2ms to 260.7ms) compared to the previous patch. The optimization comes with a trade-off: when a previously known alternate directory disappears, the "object directory does not exist" error message is now suppressed. The commit message explicitly documents this behavioral change and justifies it as a niche edge case that does not affect functional outcomes.

The patch touches only `odb/source-files.c` and is narrowly scoped to the performance optimization. It builds on the `strset` refactoring introduced in patch 4, preserving the case-insensitive comparison logic for `core.ignorecase`. The suppression of the error message was a point of discussion in the thread, but Patrick’s rationale—that it applies only to disappearing alternates (not missing ones during initial addition)—was accepted by reviewers. The commit message now clearly states this distinction, resolving the last open documentation concern in the series.
