Subject: [PATCH] bundle-uri: use passed repository parameter
Series version: v1 (first iteration, no cover letter)
Originating author: Okhuomon Ajayi
Thread type: patch series (refactoring, part of the `the_repository` removal effort)

Core problem or goal
Refactor functions in `bundle-uri.c` to use an explicitly passed `struct repository *r` instead of the global `the_repository`, advancing the project-wide goal of eliminating implicit global state. The change is mechanical and does not alter behavior.

Current status
Queued in Junio's `next` branch for integration testing (announced 2025-06-12 in "What's cooking" context). The patch is uncontroversial and aligns with established project direction. Patrick Steinhardt now proposes extending the refactoring to eliminate the last two remaining uses of `the_repository` in the file (`find_temp_filename()` and `copy_uri_to_file()`), which would allow dropping the `USE_THE_REPOSITORY_VARIABLE` define entirely from the subsystem.

Key technical details
- Files touched: `bundle-uri.c`
- Functions updated: `unbundle_from_file()`, `fetch_bundle_uri()` (already done in v1)
- Functions proposed for update: `find_temp_filename()`, `copy_uri_to_file()`
- Symbols changed: `the_repository` → `r` in calls to `get_main_ref_store()`, `trace2_region_enter`/`leave`, `odb_mkstemp()`, and `copy_file()`
- No new or renamed symbols; no on-disk format changes; no test coverage changes
- Patrick provided a ready-to-apply diff for the proposed follow-up changes

Open questions and loose ends
- Whether to address the remaining `the_repository` dependencies (`find_temp_filename()` and `copy_uri_to_file()`) in this patch or a follow-up. Patrick advocates for doing it now to drop `USE_THE_REPOSITORY_VARIABLE` entirely.
- The previously noted dependency on `fetch_pack_fsck_objects()` (which reads config from the global repository) remains unaddressed but is not a blocker for this refactoring.
