This is a refactoring series targeting the `git commit-graph` builtin, part of Patrick Steinhardt’s ongoing effort to make commit-graph backends pluggable. The goal is to let backends fully control where commit-graphs are read and written, and these seven patches are preliminary cleanups to prepare the codebase.

The first three patches are mechanical: renaming subcommand functions for clarity, removing an unused `read_replace_refs` declaration, and eliminating reliance on the global `the_repository` variable. These are uncontroversial and align with the broader `the_repository` removal effort.

The fourth patch is the most likely to draw discussion. It removes the global `--object-directory=` option, restricting it to subcommands only. Patrick acknowledges this is an outlier in Git’s option handling and says it “got in my way,” but the change could break existing scripts or workflows that rely on the current behavior. If you care about backward compatibility in `git commit-graph`, this is the patch to watch.

The final three patches simplify option handling by de-globalizing write options and common options. These are internal cleanups that shouldn’t affect user-visible behavior but make the code easier to extend for pluggable backends.

Overall, the series looks well-structured and motivated. The first six patches are straightforward refactoring, while the fourth is the only one that might require pushback or adjustment. If you’re following the commit-graph backend work, this is a useful incremental step.
