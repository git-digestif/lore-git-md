Subject: [PATCH] odb.c: skip self-referential alternates during quarantine
Series version: v3 (single patch, follow-up to v2)
Originating author: Kristofer Karlsson (via GitGitGadget)
Thread type: bugfix and performance patch

Core problem or goal
Git’s object quarantine mechanism in `receive-pack` unnecessarily loads all refs—including hidden ones—from the repository’s own object directory during connectivity checks. When the quarantine environment passes the repository’s object directory as an alternate, `rev-list --alternate-refs` lists every ref twice, creating a measurable performance regression. The patch eliminates this redundancy by marking alternates as "borrowed" (from another repository) or not, using heuristics to identify the repository’s own object directory. The v3 adjustment makes the logic future-proof by storing the default object directory in the `odb_source_files` struct, allowing Patrick Steinhardt’s concurrent `ps/odb-object-storage-extension` topic to override the default without breaking quarantine logic. Jeff King (Peff) has now proposed a **simpler, more localized fix**: compare the alternate’s path directly against the repository’s commondir in `refs_from_alternate_cb()`, avoiding the `borrowed` flag and quarantine-specific logic entirely. This approach is minimal (10 lines), future-proof (would benefit from a generic fix to self-referential alternates), and avoids the `files://` object storage format gap by not relying on heuristics. The performance impact remains the same: a 67.7% speedup in repositories with 200,000 hidden refs and a 17.6% improvement even without hidden refs, as documented in the perf test (`p5552-push-hidden-refs.sh`).

Current status
**Merged to `next` (2025-06-12) as v2** and confirmed compatible with Patrick Steinhardt’s concurrent `odb-reload-alternates` series. Junio C Hamano’s merge resolution preserved the patch’s core logic while reconciling structural changes. The discussion has now expanded to include **three competing approaches** for addressing the root cause:
1. **v3 adjustment** (Kristofer Karlsson): Stores the default object directory in `odb_source_files` to address the `files://` gap, retaining the `borrowed` flag and quarantine-specific logic. Backward-compatible and low-risk but retains heuristics.
2. **Append-to-alternates** (Patrick Steinhardt): Appends the quarantine directory to the alternates list instead of modifying the primary object directory, avoiding heuristics and aligning with the ODB abstraction work. More invasive but principled.
3. **Commondir comparison** (Jeff King): Compares the alternate’s path directly against the repository’s commondir in `refs_from_alternate_cb()`, eliminating quarantine-specific logic entirely. Minimal, future-proof, and avoids the `files://` gap by not relying on heuristics. Does not address the broader alternate interface fragility but is the simplest fix.
4. **Transaction context propagation** (Justin Tobler): Propagates ODB transaction context via environment variables to child processes, integrating with the ODB transaction effort. The most principled long-term solution but requires adapting `odb_transaction_env()` to support a "read-only" mode flag for short-term use.

The v2 patch remains in `next` unless Justin Tobler’s or Patrick Steinhardt’s feedback suggests a redesign. Jeff King’s commondir comparison approach is now the leading contender for a short-term fix due to its simplicity and alignment with Git’s ethos of small, self-contained patches. The v3 adjustment is still viable but may be rendered unnecessary if the commondir comparison is adopted. No technical objections exist to any approach; the choice hinges on trade-offs between short-term pragmatism (commondir comparison or v3) and longer-term robustness (append-to-alternates or transaction context).

- Assumptions:

  - Jeff King’s approach: The alternate’s path can be reliably compared to the repository’s commondir using `strbuf_realpath()`.

Open questions and loose ends
- **Design direction**: The decision now hinges on Justin Tobler’s and Patrick Steinhardt’s input, with Jeff King’s commondir comparison emerging as a strong contender. Four viable paths forward exist:
  1. **Commondir comparison** (Jeff King): Minimal, future-proof, and avoids heuristics. Preferred for short-term adoption due to simplicity.
  2. **v3 adjustment** (Kristofer Karlsson): Addresses the `files://` gap but retains heuristics. Viable if the commondir comparison is deemed insufficient.
  3. **Append-to-alternates** (Patrick Steinhardt): Avoids heuristics but requires more invasive changes. Aligns with ODB abstraction but may be overkill for a short-term fix.
  4. **Transaction context propagation** (Justin Tobler): The most principled long-term solution but requires adapting `odb_transaction_env()` for short-term use. May be deferred in favor of a simpler fix.
  No technical objections exist to any approach; the choice is between short-term pragmatism (commondir comparison or v3) and longer-term robustness (append-to-alternates or transaction context).
- **`files://` object storage format gap**: The v3 adjustment addresses this by storing the default object directory in `odb_source_files`, but Jeff King’s commondir comparison avoids the issue entirely by not relying on heuristics. The broader alternate interface fragility remains unaddressed, but Justin Tobler’s observation that only the connectivity check suffers measurable harm is uncontested.
- **Scope of broader alternate interface work**: Peff’s historical context about `GIT_QUARANTINE_PATH`’s original design intent (as a rendezvous point for index-pack and hooks) raises the question of whether future hook use cases could be affected by the repurposing of `GIT_QUARANTINE_ENVIRONMENT`. No immediate action is required, but this may resurface if new quarantine-related features are proposed.
