Thread identity
Subject: [PATCH] odb.c: skip self-referential alternates during quarantine
Series version: v3 (single patch, follow-up to v2)
Originating author: Kristofer Karlsson (via GitGitGadget)
Thread type: bugfix and performance patch

Core problem or goal
Git’s object quarantine mechanism in `receive-pack` unnecessarily loads all refs—including hidden ones—from the repository’s own object directory during connectivity checks. When the quarantine environment passes the repository’s object directory as an alternate, `rev-list --alternate-refs` lists every ref twice, creating a measurable performance regression. The patch eliminates this redundancy by marking alternates as "borrowed" (from another repository) or not, using heuristics to identify the repository’s own object directory. The v3 adjustment makes the logic future-proof by storing the default object directory in the `odb_source_files` struct, allowing Patrick Steinhardt’s concurrent `ps/odb-object-storage-extension` topic to override the default without breaking quarantine logic. This addresses the regression documented in the perf test (`p5552-push-hidden-refs.sh`), which shows a 67.7% speedup in repositories with 200,000 hidden refs and a 17.6% improvement even without hidden refs.

Current status
**Merged to `next` (2025-06-12) as v2** and confirmed compatible with Patrick Steinhardt’s concurrent `odb-reload-alternates` series. Junio C Hamano’s merge resolution preserved the patch’s core logic while reconciling structural changes. Kristofer Karlsson’s follow-up proposes a **v3 adjustment** to address Patrick Steinhardt’s review gap: the v2 patch did not account for object directories specified via the `files://<payload>` object storage format extension, which can define a primary object directory differing from `<commondir>/objects`. The v3 change stores the default object directory in `odb_source_files`, allowing the `files://` extension to override it without misclassifying directories as "borrowed." The discussion has now expanded to include **two alternative approaches** for a longer-term solution:
1. **Append-to-alternates** (Patrick Steinhardt): Append the quarantine directory to the alternates list instead of modifying the primary object directory, avoiding heuristics and aligning with the ODB abstraction work.
2. **Transaction context propagation** (Justin Tobler): Propagate ODB transaction context via environment variables to child processes, allowing them to reconstruct the proper environment without modifying the primary object directory. This would integrate with Justin’s ongoing ODB transaction effort and eliminate heuristics entirely. For a short-term fix, Justin suggests adapting `odb_transaction_env()` to include a "read-only" mode flag that appends the quarantine directory as an alternate without altering the primary object directory.

Justin Tobler’s input is now pivotal, as he leads the ODB transaction effort and can assess how each approach interacts with the broader refactoring. The v2 patch remains in `next` unless Justin’s feedback suggests a redesign; the v3 adjustment is backward-compatible (unrecognized directories remain "borrowed") and low-risk, with the only potential issue being a false negative (skipping refs from a quarantine inside another repository’s object directory), which Kristofer considers unlikely and low-impact. Junio and Jeff King have endorsed the v2 parent-path deduction as a pragmatic short-term fix, and the v3 adjustment does not alter this endorsement.

Open questions and loose ends
- **Design direction**: The decision now hinges on Justin Tobler’s input. Three viable paths forward exist:
  1. **v3 adjustment** (Kristofer Karlsson): A minimal, backward-compatible fix addressing the `files://` gap. Low-risk but retains heuristics.
  2. **Append-to-alternates** (Patrick Steinhardt): Avoids heuristics by appending the quarantine directory to the alternates list. Aligns with ODB abstraction but requires more invasive changes.
  3. **Transaction context propagation** (Justin Tobler): The most principled long-term solution, integrating with the ODB transaction effort. Requires adapting `odb_transaction_env()` to support a "read-only" mode flag for short-term use.
  No technical objections exist to any approach; the choice is between short-term pragmatism (v3) and longer-term robustness (append-to-alternates or transaction context).
- **`files://` object storage format gap**: The v3 adjustment addresses this by storing the default object directory in `odb_source_files`, allowing the `files://` extension to override it. This eliminates the risk of misclassifying directories as "borrowed" but does not alter the broader alternate interface fragility.
- **Scope of broader alternate interface work**: The alternate interface’s existing fragility remains unaddressed. Justin Tobler’s observation that only the connectivity check suffers measurable harm is uncontested, but Peff’s historical context about `GIT_QUARANTINE_PATH`’s original design intent (as a rendezvous point for index-pack and hooks) raises the question of whether future hook use cases could be affected by the repurposing of `GIT_QUARANTINE_ENVIRONMENT`. No immediate action is required, but this may resurface if new quarantine-related features are proposed.
