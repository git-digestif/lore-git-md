Thread identity
Subject: [PATCH] odb.c: skip self-referential alternates during quarantine
Series version: v2 (single patch)
Originating author: Kristofer Karlsson (via GitGitGadget)
Thread type: bugfix and performance patch

Core problem or goal
Git’s object quarantine mechanism in `receive-pack` unnecessarily loads all refs—including hidden ones—from the repository’s own object directory during connectivity checks. When the quarantine environment passes the repository’s object directory as an alternate, `rev-list --alternate-refs` lists every ref twice, creating a measurable performance regression. The patch eliminates this redundancy by marking alternates as "borrowed" (from another repository) or not, using two heuristics: the alternate’s path is either the repository’s own `<commondir>/objects`, or the parent of `GIT_QUARANTINE_PATH` (since quarantines are created directly inside the object directory). This prevents the connectivity check from listing the repository’s own refs, addressing the regression documented in the perf test (`p5552-push-hidden-refs.sh`), which shows a 67.7% speedup in repositories with 200,000 hidden refs and a 17.6% improvement even without hidden refs.

Current status
**Merged to `seen` (2025-06-12)** and confirmed compatible with Patrick Steinhardt’s concurrent `odb-reload-alternates` series. Junio C Hamano’s merge resolution preserved the patch’s core logic—introducing a `borrowed` flag to exclude the repository’s own object directory from `--alternate-refs`—while reconciling structural changes (e.g., renaming `odb_add_alternate_recursively` to `add_alternate_recursively`). Kristofer Karlsson explicitly reviewed the conflict resolution and endorsed it as correct. However, Patrick Steinhardt’s latest review identifies a **gap in the patch’s logic**: it does not account for object directories specified via the `files://<payload>` object storage format extension, which can define a primary object directory that differs from `<commondir>/objects`. The current `is_borrowed_object_dir()` function would incorrectly classify such directories as "borrowed," leading to missing refs in `--alternate-refs` output. The patch remains viable for `next` but may require a follow-up to handle the `files://` case. Junio and Jeff King have endorsed the parent-path deduction as a pragmatic short-term fix, with Junio describing it as "another icky assumption" but acceptable given the performance regression and the existing fragility of the alternate object store interface, and Peff calling it "quite sensible" as a natural extension of the existing rule that `--alternate-refs` should not list refs from an alternate that is actually the same repository.

Open questions and loose ends
- **`files://` object storage format gap**: The patch’s `is_borrowed_object_dir()` function does not handle object directories specified via `files://<payload>`, which can define a primary object directory that differs from `<commondir>/objects`. This could lead to missing refs in `--alternate-refs` output. Patrick Steinhardt’s review suggests this may require a follow-up patch.
- **Scope of follow-up work**: The broader alternate interface fragility (noted by Junio and Peff) remains unaddressed. Justin Tobler’s observation that only the connectivity check suffers measurable harm is uncontested, but Peff’s historical context about `GIT_QUARANTINE_PATH`’s original design intent (as a rendezvous point for index-pack and hooks) raises the question of whether future hook use cases could be affected by the repurposing of `GIT_QUARANTINE_ENVIRONMENT`. No immediate action is required, but this may resurface if new quarantine-related features are proposed.
- **Alternative approach**: Patrick Steinhardt proposes appending the quarantine directory to the alternates list and using `GIT_QUARANTINE_ENVIRONMENT` as a read-only flag, which would eliminate the need to juggle alternates during connectivity checks. This is a higher-risk change with greater potential for regressions and is not demanded as a prerequisite for merging the current patch.
