Subject: [PATCH] odb.c: skip self-referential alternates during quarantine
Series version: v3 (single patch, follow-up to v2; now likely superseded by broader discussion)
Originating author: Kristofer Karlsson (via GitGitGadget)
Thread type: bugfix and performance patch

Core problem or goal
Git’s object quarantine mechanism in `receive-pack` unnecessarily loads all refs—including hidden ones—from the repository’s own object directory during connectivity checks. When the quarantine environment passes the repository’s object directory as an alternate, `rev-list --alternate-refs` lists every ref twice, creating a measurable performance regression. The discussion has converged on **Jeff King’s commondir comparison** as the leading short-term fix: compare the alternate’s path directly against the repository’s commondir in `refs_from_alternate_cb()`, eliminating quarantine-specific logic entirely. This approach is minimal (10 lines), future-proof, and avoids heuristics. The performance impact remains significant: a 67.7% speedup in repositories with 200,000 hidden refs and a 17.6% improvement even without hidden refs, as documented in the perf test (`p5552-push-hidden-refs.sh`).

Current status
**Merged to `next` (2025-06-12) as v2** and confirmed compatible with Patrick Steinhardt’s concurrent `odb-reload-alternates` series. Junio’s merge resolution preserved the patch’s core logic while reconciling structural changes. The discussion has now expanded to **five competing approaches**, with **Jeff King’s commondir comparison emerging as the leading contender for short-term adoption** due to its simplicity and alignment with Git’s ethos of small, self-contained patches. The remaining options are:
1. **Commondir comparison** (Jeff King): Compares the alternate’s path directly against the repository’s commondir in `refs_from_alternate_cb()`. Minimal, future-proof, and avoids heuristics. Now endorsed by Kristofer Karlsson as cleaner than his v2/v3 approaches.
2. **Read-only transaction environment** (Justin Tobler): Propagates ODB transaction context via environment variables to child processes, using a read-only mode flag in `odb_transaction_env()` for the connectivity check. The most principled short-term solution but requires adapting `odb_transaction_env()` to support read-only mode. Kristofer has deferred to Justin’s judgment on whether to implement this as the short-term fix.
3. **v3 adjustment** (Kristofer Karlsson): Stores the default object directory in `odb_source_files` to address the `files://` gap, retaining the `borrowed` flag and quarantine-specific logic. Backward-compatible and low-risk but retains heuristics. May be rendered unnecessary by Jeff King’s or Justin’s approaches.
4. **Append-to-alternates** (Patrick Steinhardt): Appends the quarantine directory to the alternates list instead of modifying the primary object directory, avoiding heuristics and aligning with the ODB abstraction work. More invasive but principled. Deferred pending Justin Tobler’s input.
5. **Transaction context propagation** (Justin Tobler): The long-term solution, integrating with the ODB transaction effort. Requires broader changes and is deferred in favor of short-term fixes.

The v2 patch remains in `next` unless Justin Tobler’s or Patrick Steinhardt’s feedback suggests a redesign. Kristofer has explicitly endorsed Jeff King’s commondir comparison as the preferred path forward, but now also considers Justin’s read-only mode proposal a viable alternative. No technical objections exist to any approach. The choice now hinges on trade-offs between short-term pragmatism (commondir comparison or read-only mode) and longer-term robustness (append-to-alternates or full transaction context).
