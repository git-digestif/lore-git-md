Subject: [PATCH] odb.c: skip self-referential alternates during quarantine
Series version: v2 (single patch)
Originating author: Kristofer Karlsson (via GitGitGadget)
Thread type: bugfix and performance patch

Core problem or goal
Git’s object quarantine mechanism in `receive-pack` unnecessarily loads all hidden refs from the repository’s own object directory during connectivity checks. When the quarantine environment passes the repository’s object directory as an alternate, `rev-list --alternate-refs` lists every ref—including hidden ones—despite prior work (`bcec6780b2`) that explicitly excluded hidden refs from connectivity checks. This creates a measurable performance regression: in repositories with 200,000 hidden refs the patch demonstrates a 67.7% speedup (0.31s → 0.10s) for small pushes, and even without hidden refs every ref is still listed twice, causing a 17.6% slowdown.

Current status
Under review; converging toward a final solution. The v1 patch (a proof-of-concept workaround in `odb.c`) is superseded by a v2 approach that repurposes `GIT_QUARANTINE_ENVIRONMENT` to carry the parent’s object directory path, avoiding both new APIs and fragile path comparisons. Junio C Hamano and Jeff King have **endorsed the parent-path deduction** as a pragmatic short-term fix. Junio described it as "another icky assumption" but acceptable given the performance regression and the existing fragility of the alternate object store interface; Peff called it "quite sensible," framing it as a natural extension of the existing rule that `--alternate-refs` should not list refs from an alternate that is actually the same repository. The patch now targets the quarantine plumbing (`tmp-objdir.c`) rather than the ODB layer, aligning with maintainer preference for a minimally invasive fix. No maintainer decision on integration branch yet; awaiting final feedback from ODB maintainers (Patrick Steinhardt, Justin Tobler) on the parent-path assumption’s safety.
