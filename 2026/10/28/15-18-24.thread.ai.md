Subject: [PATCH] odb.c: skip self-referential alternates during quarantine
Series version: single patch (no series)
Originating author: Kristofer Karlsson (via GitGitGadget)
Thread type: bugfix and performance patch

Core problem or goal
Git’s object quarantine mechanism in `receive-pack` unnecessarily loads all hidden refs from the repository’s own object directory during connectivity checks. When the quarantine environment passes the repository’s object directory as an alternate, `rev-list --alternate-refs` lists every ref—including hidden ones—despite prior work (`bcec6780b2`) that explicitly excluded hidden refs from connectivity checks. This creates a measurable performance regression: in repositories with 200 000 hidden refs the patch demonstrates a 67.7 % speedup (0.31 s → 0.10 s) for small pushes, and even without hidden refs every ref is still listed twice, causing a 17.6 % slowdown.

Current status
Under review; no maintainer decision yet. The patch remains a proof-of-concept workaround that skips alternates whose path matches the repository’s own `commondir` in `odb.c`. The author now explicitly frames it as a temporary measure and leans toward Junio C Hamano’s proposal to repurpose `GIT_QUARANTINE_ENVIRONMENT` to carry the parent’s object directory path, avoiding both new APIs and fragile path comparisons. Two architectural alternatives remain on the table: (1) Justin Tobler’s ODB transaction callback (`odb_transaction_files_check_connected()`), and (2) Junio’s environment-variable approach. No objections to any of the three approaches (current patch, callback, or environment variable) have been raised.
