This thread is about a small but important bugfix in Git's transport subsystem. Karthik Nayak has sent the fifth version of a three-patch series that plugs a memory leak affecting remote-helper transports. The leak occurs because dynamically allocated fields in the `git_transport_options` structure—specifically `negotiation_restrict_tips` and `filter_options`—were never freed in `transport-helper.c` and were inconsistently cleaned up in `transport.c`.

The fix is straightforward: a new helper function, `transport_options_release()`, centralizes the cleanup logic. The patch replaces ten lines of duplicated code in `transport.c` with a single call to this helper and adds the missing cleanup in `transport-helper.c`. There’s no change in behavior, and the patch doesn’t include tests, as the leak is purely a resource-management issue. The commit message clearly explains the problem and the solution, making it easy to understand the scope and intent of the change. So far, there’s no review feedback on this version, so the series is still under consideration.
