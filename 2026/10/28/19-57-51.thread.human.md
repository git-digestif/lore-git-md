This thread is about a small but clean refactoring of Git’s interactive add (`git add -i`) subsystem. Junio C Hamano posted a patch that tightens encapsulation by making the `init_add_i_state()` and `clear_add_i_state()` functions, along with the `struct add_i_state` type, file-scope static in `add-interactive.c`. The change removes these symbols from the public header `add-interactive.h`, since external callers only need the entry point `run_add_i()`.

The patch is mechanical and self-contained, touching only two files. There’s no behavior change—just a reduction in the public API surface. So far, the patch appears uncontroversial and aligns with Git’s long-standing preference for keeping implementation details private.
