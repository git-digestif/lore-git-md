This thread is about a small but clean refactoring to the `git add -i` (interactive add) subsystem. Junio C Hamano proposed making the `init_add_i_state()` and `clear_add_i_state()` functions, along with the `struct add_i_state` type, file-scope static in `add-interactive.c`, since they are no longer needed by external callers after a prior commit (`d51b61f5dab`) decoupled `git add -p` from the interactive add internals. The patch itself is uncontroversial: it touches only two files, introduces no behavior changes, and aligns with Git’s preference for narrow interfaces.

The discussion has since drifted slightly to an orthogonal issue: `git history reword` does not respect the `notes.rewriteref` configuration variable. Junio initially raised this as a potential edge case, and D. Ben Knoble confirmed it as a known limitation (not a deliberate design choice). Ben expressed interest in seeing it fixed but hasn’t committed to implementing the change. Patrick Steinhardt provided helpful historical context for the refactoring, but no one has raised substantive concerns about the patch itself. The refactoring remains under review, with only surface-level acknowledgment of its goals. The `notes.rewriteref` issue is now part of the thread’s open state but unrelated to the patch’s core purpose.
