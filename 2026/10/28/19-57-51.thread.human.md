This thread is a small but clean refactoring of Git’s interactive add subsystem. Junio C Hamano sent a standalone patch that makes the `init_add_i_state()` and `clear_add_i_state()` functions, along with the `struct add_i_state` type, file-scope static in `add-interactive.c`. The change tightens encapsulation by removing these internals from the public header, since the only external entry point is `run_add_i()`.

The patch itself is uncontroversial and aligns with Git’s long-standing preference for narrow interfaces. Patrick Steinhardt’s reply adds useful context: the public declarations became redundant after `d51b61f5dab` (March 2026), which decoupled `git add -p` from the interactive add internals. This confirms that no callers still depend on these symbols, making the refactoring safe. D. Ben Knoble reviewed the patch but only confirmed its goal and style; no substantive feedback on correctness or edge cases has emerged.

The patch touches only `add-interactive.c` and `add-interactive.h`, introduces no behavior changes, and requires no new tests. It is now ready for integration.
