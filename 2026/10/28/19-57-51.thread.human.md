This thread is a small but tidy refactoring of Git’s interactive add subsystem. Junio C Hamano proposed making two internal functions (`init_add_i_state` and `clear_add_i_state`) and the `add_i_state` struct file-scope static in `add-interactive.c`, since they’re no longer needed by external callers after an earlier decoupling of `git add -p` from the interactive add internals. The patch itself is uncontroversial—D. Ben Knoble and Patrick Steinhardt both confirmed it aligns with Git’s preference for narrower interfaces, and no one has raised concerns about correctness or edge cases.

The only loose end is an unrelated but noted limitation: `git history reword` doesn’t respect the `notes.rewriteref` configuration. This was acknowledged as a known issue (now logged in the project’s bug tracker) rather than a deliberate omission, and Patrick Steinhardt offered to review patches if someone tackles it. The refactoring patch itself remains under review, with no changes requested or new versions posted.
