This thread is a small, uncontroversial refactoring patch from Junio C Hamano that tightens encapsulation in Git’s `add -i` (interactive add) subsystem. The patch makes the `init_add_i_state()` and `clear_add_i_state()` functions, along with the `struct add_i_state` type, file-scope static in `add-interactive.c`, removing their public declarations from `add-interactive.h`. This is a purely mechanical cleanup with no behavior change—just a narrower interface for the `add -i` internals.

The patch has received a surface-level review from Ben Knoble, who confirmed the change aligns with the commit message and Git’s coding style but did not verify callers or test the code. No substantive objections or open questions have been raised, and the patch remains under review as a standalone refactoring. It touches only two files (`add-interactive.c` and `add-interactive.h`) and is unrelated to larger efforts like ODB abstraction or Rustification. The next step is likely Junio picking it up for `next` once any remaining review feedback is addressed.
