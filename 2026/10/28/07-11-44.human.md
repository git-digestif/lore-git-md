This is the sixth and final patch in Patrick Steinhardt’s v3 bugfix series restoring dynamic reload of alternate object databases in the files-based ODB backend. The patch addresses a performance regression introduced by the earlier fix (patch 3), which restored correctness but slowed down lookups for missing objects by always re-reading the alternates file on retry.

The solution uses `struct stat_validity` to track the alternates file’s mtime and inode, allowing Git to skip re-reading the file if it hasn’t changed. The patch also fixes a race condition by updating the stat cache *before* reading the file and clearing it if the open fails. Benchmark results show the optimization nearly restores pre-regression performance: lookup time for 20k missing objects drops from 262.7ms (post-fix) to 199.5ms, just 14ms slower than the broken baseline of 185.3ms. Memory usage increases slightly (4.3%) due to the `stat_validity` overhead, but this is considered an acceptable trade-off.

The implementation is clean and follows established patterns in the codebase (e.g., `stat_validity` is already used elsewhere for similar purposes). The commit message clearly documents the performance impact and the rationale for the design. This patch completes the series, which is now ready for final review after addressing all technical and editorial feedback from earlier iterations.
