This is a narrow but substantive review follow-up in the ongoing RFC thread for `git cat-file --remote-object-info` batching. Junio C Hamano responds to Pablo Sabater’s proposed error message change ("object-info is not supported on bundles") for the "smart options required" condition in patch 1/3.

Junio acknowledges the improvement over the original cryptic message but raises a forward-compatibility concern: the new wording hardcodes "bundle" as the reason, which would become misleading if another transport (e.g., a future protocol) also lacks smart options. He suggests a more generic alternative—"object-info is not supported by this remote"—but notes it sacrifices clarity when the remote *is* a bundle. The key question is whether the remote’s URL (or other identifying information) is available at this point in the code; if so, a dynamic message like "object-info is not supported by %s" would resolve the tension between accuracy and actionability.

This exchange is a small but meaningful step in the review process. It clears the only concrete critique Junio raised for patch 1, leaving the broader design questions (server-side OID limits, batching defaults) as the remaining open items. The thread remains in the design phase, with no code updates yet.
