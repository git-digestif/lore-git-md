Subject: [PATCH] range-diff: use repository from diffopt instead of the_repository
Series version: standalone patch (v1)
Originating author: Okhuomon Ajayi (Outreachy participant)
Thread type: refactoring patch (part of the `the_repository` removal effort)

Core problem or goal
Refactor `range-diff.c` to eliminate implicit use of the global `the_repository` variable in two functions (`output_pair_header` and `patch_diff`) by instead using the repository stored in the `diffopt` structure that is already passed to them. The patch also updates `get_filespec` to accept a hash algorithm parameter rather than relying on the global `the_hash_algo`. This change is mechanical and aligns with the ongoing, high-volume effort to remove `the_repository` from Git’s codebase.

Current status
Under review; no prior versions. The patch is a single, self-contained refactoring that touches only `range-diff.c` and does not introduce new behavior or on-disk format changes.

Key technical details
- Files touched: `range-diff.c`
- Functions modified: `output_pair_header`, `patch_diff`, `get_filespec`
- New parameter: `get_filespec` now takes a `const struct git_hash_algo *` instead of using `the_hash_algo`
- Symbols unchanged: no new CLI options, config keys, or test files
- Three other functions in the same file (`read_patches`, `output`, `is_range_diff_range`) still use `the_repository`, so the `USE_THE_REPOSITORY_VARIABLE` macro remains in place
