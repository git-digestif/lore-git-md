This is a bugfix series targeting the object database (ODB) subsystem, specifically the files-based backend. The series restores the ability to dynamically reload the list of alternate object databases when an object lookup fails — a behavior accidentally broken in March 2026 during the ODB abstraction effort. The regression, though rare, has been observed in production systems where the alternates file is modified while Git is running.

The series is now in its third iteration (v3) and consists of six patches. The first two lay groundwork by renaming functions and ensuring alternates are always loaded from the repository’s real object directory, even when a quarantine directory is active. The third patch implements the core fix: reloading alternates on retry. The remaining three patches optimize performance, reducing lookup time for 20,000 missing objects from 310ms (unoptimized) to 199ms — nearly matching the pre-regression baseline of 185ms.

Key improvements in v3 include reinstating a previously removed `NEEDSWORK` comment about case-insensitive deduplication, fixing typos, and explicitly documenting a behavioral change: the suppression of error messages when a previously known alternate directory disappears. The series also addresses a race condition in the alternates file reload logic by updating the stat cache before reading the file and clearing it on failure.

The patches touch `odb/source-files.c` and its header, and add a new test scenario in `t/t1006-cat-file.sh` to verify the fix. The commit messages are clear and well-motivated, and the performance optimizations are justified with measurements. The series is based on current `master` with Patrick Steinhardt’s ODB cleanup branch merged in.

This looks like a solid, uncontroversial bugfix that addresses a real regression with minimal risk. The remaining open issues are purely cosmetic (typos, outdated references) and do not affect correctness or performance. The series is ready for final review and should be straightforward to merge.
