This thread is a focused bug report from Mike Beaton about a regression in `git check-ignore -v`. The issue is that paths ending with a trailing slash (like `foo/`) are incorrectly matched against blank lines in `.gitignore` when those lines use CRLF line endings, while the same paths are correctly ignored when the blank lines use LF. This violates Git's documented semantics, where blank lines should never match any files.

Mike provides a minimal reproduction case—creating a temporary repository with a `.gitignore` file containing a single blank CRLF line—and confirms the bug exists in both Git 2.51.1 and 2.56.0, ruling out a recent regression. The problem is specific to the trailing-slash spelling of paths and does not affect core operations like `git status` or `git add`. The commit message is thorough, including environment details (Linux/WSL), build flags, and exact reproduction steps, making it clear this is a low-level parsing issue in the ignore-pattern logic.

So far, there are no replies or reviews, so the thread is just the initial report. The fix will likely involve normalizing line endings in the ignore-pattern parser, but no patch has been proposed yet. This is a narrow, well-documented bug that should be straightforward for maintainers of the ignore subsystem to address.
