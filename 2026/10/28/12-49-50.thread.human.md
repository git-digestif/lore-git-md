This thread addresses a bug in `git check-ignore -v` where directory paths ending in a trailing slash incorrectly match blank lines in `.gitignore` files when those lines use CRLF line endings or contain only whitespace. Mike Beaton reported the issue and confirmed it exists in recent Git versions (2.51.1 and 2.56.0), ruling out a recent regression. Aniket Gupta has submitted a minimal fix that modifies `add_patterns_from_buffer()` in `dir.c` to skip adding patterns when lines are empty after trimming carriage returns and trailing spaces, along with a new test in `t/t0008-ignores.sh` covering CRLF and mixed-whitespace cases.

The patch restores documented behavior -- blank lines should never match any path -- but remains under review with no maintainer or ignore-subsystem expert having weighed in yet. Gupta has sent a follow-up ping to the list noting the lack of attention. No decisions have been made, and maintainer sign-off is still pending. The fix is narrowly scoped to runtime parsing logic and does not affect on-disk formats, comments, or negation patterns, but confirmation of this scope during review remains an open item.
