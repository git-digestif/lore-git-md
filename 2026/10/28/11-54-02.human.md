This is the fourth patch in Kaartic Sivaraam’s RFC v3 series improving Git’s error reporting when repository discovery fails. It targets the scenario where `GIT_CEILING_DIRECTORIES` blocks Git from finding a valid repository, a case that can baffle users who forget they set the variable weeks earlier.

The patch extends the "fatal: not a git repository" message with two new lines: one showing the search boundaries (e.g., "searched from '/home/user/.config/nvim' up to '/home/user/.config'") and another reporting the value of `GIT_CEILING_DIRECTORIES` if it is set. The implementation is clean: it builds the message in a `strbuf`, keeps the original translatable string intact, and adds `TRANSLATORS` comments for the placeholders. The test in `t/t0009-git-dir-validation.sh` verifies both the search-boundary line and the ceiling-variable line appear in stderr.

This change directly addresses Junio C Hamano’s critique that users are confused about *which* directory Git inspected and *where* it came from, rather than the specific failure reason. The new output gives users immediate context to diagnose misconfigurations without requiring them to remember environment variables set long ago. The patch is narrowly scoped to the ceiling-directory case and leaves other discovery scenarios (e.g., mount points) untouched, keeping the series focused. No technical objections have been raised so far, and the approach aligns with the feedback that shaped the v3 direction.
