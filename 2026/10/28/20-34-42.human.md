This is a refactoring patch from Junio C Hamano, the Git maintainer. It cleans up the `read-cache` API by hiding the `refresh_cache_entry()` function, which was exposed in 2006 to support the now-removed "recursive" merge strategy.

The patch removes the function’s declaration from `read-cache-ll.h` and restores its `static` linkage in `read-cache.c`. External callers (notably the "ort" merge strategy) still get the same functionality indirectly through `make_cache_entry()` and `rename_index_entry_at()`, so no behavior changes. The commit message is thorough, explaining the historical context and why the change is safe.

This is a small, well-justified cleanup that reduces the public surface of the index API. It’s unlikely to be controversial and looks ready for `next`.
