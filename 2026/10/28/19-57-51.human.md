This is a small refactoring patch from Junio C Hamano, the Git maintainer. It tightens the encapsulation of the `add -i` (interactive add) machinery by making the `init_add_i_state()` and `clear_add_i_state()` functions static to `add-interactive.c`, and moving the `struct add_i_state` definition from the header into the implementation file. The only public entry point remains `run_add_i()`.

The change is mechanical and well-motivated: the commit message clearly explains that external callers have no need to see these internals, so hiding them reduces the API surface. The patch itself is clean, with no behavior change—just moving code around to enforce the intended encapsulation. No controversy or follow-up discussion is expected; this looks like a routine cleanup that will likely be merged without fuss.
