This thread is a small but important i18n fix for `git checkout` that corrects how pluralized messages are handled for translation. Tanga Joris, an Outreachy applicant, identified two messages in `builtin/checkout.c` that incorrectly used the singular `_()` gettext wrapper instead of the plural-aware `Q_()` macro: the " ... and %d more." message shown when leaving orphaned commits behind, and the "only one reference expected, %d given." error. The English output remains unchanged, but the fix enables proper translation into languages with complex plural rules (like Polish) by providing the correct plural context to translators.

The patch has evolved smoothly through review. Junio C Hamano suggested improving the commit message to explicitly acknowledge the trade-off: languages without plural distinctions must now provide two identical translations to enable correctness for languages that do. Tuomas also pointed out the second message that needed conversion. Both suggestions were incorporated into this v2 patch, which is now complete and uncontroversial. The changes are mechanical (`_()` → `Q_()`) and touch only one file, with no new tests required since existing tests suffice. The interdiff confirms the fix is ready for merging.
