Core problem or goal
Add filtering capabilities to `git worktree list` by extending `git for-each-ref` with the `%(worktreepath)` atom, which now reports worktree paths for rebasing/bisecting branches (previously omitted). The series also addresses two safety issues: (1) `git worktree remove` now refuses to delete worktrees in the middle of a rebase, bisect, cherry-pick, revert, or `git am` operation unless `--force` is given, and (2) `git-for-each-ref`'s `%(worktreepath)` atom no longer silently omits worktree paths for rebasing/bisecting branches, aligning behavior with `git worktree add` and `git branch -d`. The v5 series (patches 1/5–3/5) resolves all performance, safety, and composability concerns raised in prior iterations, including Junio’s objections to patches 4/5 and 5/5, which were dropped. Phillip Wood’s review of the dropped `%(currentworktree)` patch (4/5) further confirmed its redundancy, questioning whether the atom should exist at all and noting its value is already available via `%(worktreepath)`.

Current status
The **three-patch series is complete and ready for integration**:
1. **Safety fix** for `git worktree remove` (refuses deletion of in-progress worktrees without `--force`). Junio notes this as ready for integration but suggests future unification with branch-checkout safety checks and a reusable "discardable state" helper in `worktree.c`. Jasper agrees and proposes a follow-up series to implement this helper, which would return an error code (not die) and report both the operation type (rebase, bisect, etc.) and the branch (if any), making it reusable for all call sites (currently scattered across `branch.c`, `worktree.c`, and the new safety check).
2. **Documentation update** for `git-for-each-ref(1)` warning about parsing `%(worktreepath)` safely. Junio suggests deferring consolidation of quoting advice to a future patch; no substantive objections.
3. **Enhancement** to `%(worktreepath)` (O(1) performance via hashmap, excludes `rebase --update-refs` branches, breaks bare-repository compatibility). Junio requests minor refactoring to consolidate `branch_checked_out_worktree()` with `prepare_checked_out_branches()`; Jasper does not plan to revise unless Junio requests a v6.

Patches 4/5 (`%(currentworktree)` atom) and 5/5 (`git branch` output cleanup) were dropped after Junio and Phillip Wood objected that the redundancy in `git branch` output was not a significant enough problem to justify the changes. Phillip’s review of `%(currentworktree)` argued the atom was unnecessary because its value (the worktree path) is already available via `%(worktreepath)`, and it could report inconsistent results if a branch is checked out in multiple worktrees. The atom was also deemed inefficient (using a hashmap for a single entry) and redundant with `%(HEAD)`.

All patches are **tested** (rebasing/bisecting branches, bare repositories, interactive rebase stops, `rebase --update-refs`, safety scenarios for `git worktree remove`). The series is **backward-incompatible** for scripts relying on:
- Empty `%(worktreepath)` for rebasing/bisecting branches,
- Deletion of in-progress worktrees without `--force`,
- Bare-repository `git_dir` output in `%(worktreepath)`.
