Core problem or goal
Add filtering capabilities to `git worktree list` by extending `git for-each-ref` with two ref-filter atoms: `%(worktreepath)` (now reporting worktree paths for rebasing/bisecting branches) and `%(currentworktree)` (enabling conditional formatting). The series also addresses two safety issues: (1) `git worktree remove` now refuses to delete worktrees in the middle of a rebase, bisect, cherry-pick, revert, or `git am` operation unless `--force` is given, and (2) `git-for-each-ref`'s `%(worktreepath)` atom no longer silently omits worktree paths for rebasing/bisecting branches, aligning behavior with `git worktree add` and `git branch -d`. The v5 series resolves all performance, safety, and composability concerns raised in prior iterations.

Current status
The **five-patch series is complete and ready for integration**:
1. **Safety fix** for `git worktree remove` (refuses deletion of in-progress worktrees without `--force`).
2. **Documentation update** for `git-for-each-ref(1)` warning about parsing `%(worktreepath)` safely (newlines, multi-worktree edge cases).
3. **Enhancement** to `%(worktreepath)` (O(1) performance, excludes `rebase --update-refs` branches, breaks bare-repository compatibility).
4. **New atom** `%(currentworktree)` (O(1) lookup, enables conditional formatting in `git branch`).
5. **Cleanup patch** simplifying `git branch` output by using `%(currentworktree)` to suppress redundant `+` markers and paths for rebasing/bisecting branches in the current worktree.

All patches are **tested** (rebasing/bisecting branches, bare repositories, interactive rebase stops, `rebase --update-refs`, safety scenarios for `git worktree remove`, and `%(currentworktree)` behavior in main/linked worktrees). The series is **backward-incompatible** for scripts relying on:
- Empty `%(worktreepath)` for rebasing/bisecting branches,
- The `+` marker in `git branch` output,
- Deletion of in-progress worktrees without `--force`,
- Bare-repository `git_dir` output in `%(worktreepath)`.

Key technical details
- **Mechanism**:
  - `%(worktreepath)`: Uses a hashmap (`checked_out_worktrees`) in `branch.c` for O(1) lookups; excludes `rebase --update-refs` branches.
  - `%(currentworktree)`: Uses a second hashmap (`current_worktree_branches`) for O(1) lookups; designed for `%(if)` formatting.
  - `git worktree remove`: Refuses deletion of in-progress worktrees (rebase, bisect, cherry-pick, revert, `git am`) without `--force`.
  - `git branch`: Uses `%(currentworktree)` to suppress redundant `+` markers/paths for rebasing/bisecting branches in the current worktree.
- **Files**: `ref-filter.c`, `builtin/worktree.c`, `branch.c`, `builtin/branch.c`, documentation, tests.
- **Symbols**:
  - `worktree_is_in_progress()` (checks for in-progress operations),
  - `branch_checked_out_worktree()`/`branch_current_worktree()` (O(1) hashmap lookups),
  - `%(currentworktree)` atom (new, enables conditional formatting).
- **Behavior**:
  - `%(worktreepath)` now reports paths for rebasing/bisecting branches.
  - `%(currentworktree)` returns the current worktree’s path or an empty string.
  - `git worktree remove` refuses deletion of in-progress worktrees without `--force`.
  - `git branch` output omits `+`/path for rebasing/bisecting branches in the current worktree.
  - **Breaking change**: `%(worktreepath)` no longer returns bare-repository `git_dir` paths.
- **Safety**: `git worktree remove` now protects in-progress worktrees; `%(worktreepath)` documentation warns about newlines.
- **Performance**: O(1) lookups for both atoms (resolves v4 regression).
