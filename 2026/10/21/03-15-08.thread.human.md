This thread is a **bug report** from Andrew Parmet about a failure in `git merge` when used with partial clones (`--filter=blob:none`). The issue occurs when Git attempts to fetch a blob that was generated *during* the merge (e.g., a conflict resolution or merge result) from the promisor remote. Since the remote cannot have this locally created blob, the merge fails with `fatal: remote error: upload-pack: not our ref <object-id>`. The same merge succeeds if retried or run without the blob filter, suggesting the problem is specific to how partial clones handle locally generated objects.
