This is the fourth and final patch in Jason Newton’s v3 worktree reflink series. It fixes a Windows build breakage introduced by the previous patch (3/4), which disabled reflink on Windows due to ReFS corruption risks but left the `reflink_supported()` function unused in the mingw build, triggering `-Werror=unused-function`.

The fix is minimal: the `#else` guard around the `reflink_supported()` call is removed, leaving the function call in the common code path even though Windows always returns early. This keeps the function referenced and avoids the compiler error while preserving the existing logic. The commit message explains the reasoning clearly: the call is left in place to satisfy the compiler, not because it will ever be executed on Windows.

This is a straightforward build-system fix with no user-visible behavior change. It resolves the immediate breakage without revisiting the broader design debates around reflink defaults or ephemeral branch reaping. The patch is uncontroversial and appears ready to merge once the rest of the series settles.
