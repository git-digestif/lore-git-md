Thread identity
Subject: [PATCH 0/2] Add degree-of-concern reporting to `git repo structure`
Series version: v5 (bugfix for tree size concern level, memory management corrected, invalid tag refs concern removed, configuration values rounded to powers-of-two, integer typing fixed; **all prior feedback addressed**)
Originating author: Mark C. Chu-Carroll
Thread type: patch series (feature addition)

Core problem or goal
Add a `--concern` option to the `git repo structure` command that annotates repository structure statistics with visual (star-based) or numeric indicators of how problematic each metric is, based on empirical thresholds derived from a representative sample of real repositories. The feature is configurable per-repository via Git config (`repo.concern.*`), allowing users to override default thresholds. The feature is directly inspired by `git-sizer(1)` but integrated into Git's native tooling.

Current status
Under review (v5 posted; **all prior feedback addressed**). The copy-paste error in the tree size concern level computation (using `objects->largest.commit_size.value` instead of `objects->largest.tree_size.value`) is fixed. Memory management is corrected (strbuf deallocation error in table generation resolved), invalid concern reporting for tag refs is removed, configuration values are rounded to the nearest power-of-two for human readability, and integer typing in concern computation and table generation is fixed. All substantive technical feedback from Patrick Steinhardt and Junio C Hamano is addressed. No maintainer decision yet; still in review phase.

Key technical details
- Files touched: `builtin/repo.c`, `Documentation/config/repo.adoc`, `Documentation/git-repo.adoc`, `t/t1901-repo-structure.sh`
- New CLI option: `--concern` (visual or numeric output)
- New config section: `repo.concern.*` (hyphenated keys: `commit-count`, `blob-size`, etc.) for threshold overrides; naming consistent between code and documentation
- Concern calculation: exponential scale (base-2 logarithms) where each doubling beyond the threshold adds a star; defaults set at mean(log₂) + one standard deviation from a representative repository sample, methodology documented in commit message
- Output formats: concern indicators added to table, lines, and nul-terminated output (new column in table format, `concern_level` line in lines/nul mode)
- On-disk format: no changes; purely informational output
- Test coverage: added to `t/t1901-repo-structure.sh` for functionality, configurability, and output format correctness; expanded in v5 to verify the tree size concern level fix, memory management, and edge cases (invalid keys warned, negative values rejected)
- Memory management: leak in concern string generation fixed in v2 and confirmed in v4; strbuf deallocation error in table generation corrected in v5
- Implementation details:
  - Concern thresholds defined in a single `concern_stat_thresholds[]` array with a sentinel entry (`{ 0 }`)
  - Concern level computed by `repo_structure_concern_level()`
  - Config parsing handled by `config_concern_thresholds()` via `repo_config()` with the `repo.concern.` prefix; callback passes the threshold array as a parameter, eliminating global variable usage
  - Use of `starts_with` for config key matching (replacing `strncmp` as suggested by Patrick Steinhardt)
  - Documentation: 59 lines added to `Documentation/config/repo.adoc` (14 new config keys) and `Documentation/git-repo.adoc` (--[no-]concern option and output formats); split and squashed into 1/2 and 2/2 respectively to maintain bisectability
  - Patch 1/2 introduces the core `--concern` option, its calculation logic, and its documentation; patch 2/2 adds configurability via `repo.concern.*` and its documentation
  - Config callback validates keys against the threshold array and warns on invalid names
  - Empirical methodology for default thresholds documented in the commit message of 1/2
  - **Bugfixes in v5**: tree size concern level now correctly computed using `objects->largest.tree_size.value`; strbuf deallocation error in table generation corrected; invalid concern reporting for tag refs removed; configuration values rounded to nearest power-of-two; integer typing fixed
  - UTF-8-aware string alignment for table formatting
  - Use of `log2u()` for logarithmic scaling
  - Configurability: values rounded to nearest power-of-two via `nearest_log2_value()`; invalid keys or negative values trigger warnings; config parsing only invoked when `--concern` is requested

Open questions and loose ends
- **Default threshold values**: May still attract discussion or requests for adjustment based on reviewer input.
- **Discoverability of default thresholds**: Suggestion from v1 (`--show-defaults` flag) remains unimplemented.
- **Representativeness of the empirical sample**: The documented methodology (mean(log₂) + 1 standard deviation) may still be scrutinized for bias or coverage gaps.
