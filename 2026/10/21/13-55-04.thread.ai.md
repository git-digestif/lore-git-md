Thread identity
Subject: [PATCH 0/2] Add degree-of-concern reporting to `git repo structure`
Series version: v3 (restructured from v2; bisectability fixed)
Originating author: Mark C. Chu-Carroll
Thread type: patch series (feature addition)

Core problem or goal
Add a `--concern` option to the `git repo structure` command that annotates repository structure statistics with visual (star-based) or numeric indicators of how problematic each metric is, based on empirical thresholds derived from a representative sample of real repositories. The feature is configurable per-repository via Git config (`repo.concern.*`), allowing users to override default thresholds. The feature is directly inspired by `git-sizer(1)` but integrated into Git's native tooling.

Current status
Under review (v3 posted). Feedback from v2 addressed: series restructured into two bisectable patches (1/2: core functionality and its documentation; 2/2: configurability and its documentation). The critical bisectability violation identified in v2 has been resolved by splitting and squashing the documentation into the relevant code patches, as recommended by Patrick Steinhardt. Memory leak in concern string generation, CI/CD test flakiness (zlib version workaround), config key naming inconsistency, and a typo in a key name (`objects.blobs.blob_size` → `objects.blobs.disk_size`) remain fixed from v2. The threshold array now uses a sentinel entry (`{ 0 }`) instead of `ARRAY_SIZE` for bounds checking. Patrick Steinhardt's substantive reviews of v2 raised structural and technical concerns but no fundamental objections to the feature's direction. No maintainer decision yet; still in early review phase.

Key technical details
- Files touched: `builtin/repo.c`, `Documentation/config/repo.adoc`, `Documentation/git-repo.adoc`, `t/t1901-repo-structure.sh`
- New CLI option: `--concern` (visual or numeric output)
- New config section: `repo.concern.*` (hyphenated keys: `commit-count`, `blob-size`, etc.) for threshold overrides; naming consistent between code and documentation
- Concern calculation: exponential scale (base-2 logarithms) where each doubling beyond the threshold adds a star; defaults set at mean(log₂) + one standard deviation from a representative repository sample
- Output formats: concern indicators added to table, lines, and nul-terminated output (new column in table format, `concern_level` line in lines/nul mode)
- On-disk format: no changes; purely informational output
- Test coverage: added to `t/t1901-repo-structure.sh` for functionality, configurability, and output format correctness; zlib-related test flakiness addressed in v2 by disabling compression in tests; expanded in v3 to verify custom thresholds in all output formats
- Memory management: leak in concern string generation fixed in v2 and confirmed in v3
- Implementation details:
  - Concern thresholds defined in `concern_stat_thresholds[]` (renamed from `repo_structure_concern_thresholds` in v2 with a sentinel entry `{ 0 }`)
  - Concern level computed by `repo_structure_concern_level()`
  - Config parsing handled by `config_concern_thresholds()` via `repo_config()` with the `repo.concern.` prefix; potential global variable issue in the callback noted by Patrick Steinhardt in v2 remains open
  - Use of `strncmp` for config key matching (Patrick Steinhardt suggested `istarts_with` for case-insensitivity in v2)
  - Redundant loop condition (Patrick Steinhardt suggested `ARRAY_SIZE` in v2)
  - Documentation: 59 lines added to `Documentation/config/repo.adoc` (14 new config keys) and `Documentation/git-repo.adoc` (--[no-]concern option and output formats); these lines are split and squashed into 1/2 and 2/2 respectively
  - Patch 1/2 introduces the core `--concern` option, its calculation logic, and its documentation; patch 2/2 adds configurability via `repo.concern.*` and its documentation
  - Empirical methodology for default thresholds documented in the commit message of 1/2
