Subject: [PATCH 0/3] Add degree-of-concern reporting to `git repo structure`
Series version: v2 (addresses feedback from v1)
Originating author: Mark C. Chu-Carroll
Thread type: patch series (feature addition)

Core problem or goal
Add a `--concern` option to the `git repo structure` command that annotates repository structure statistics with visual (star-based) or numeric indicators of how problematic each metric is, based on empirical thresholds derived from a sample of real repositories. The feature is configurable per-repository via Git config (`repo.concern.*`), allowing users to override default thresholds.

Current status
Under review (v2 posted). Feedback from v1 addressed: memory leak in concern string generation fixed, CI/CD test flakiness resolved (zlib version workaround), and config key naming inconsistency reconciled (now `repo.concern.*` consistently in both code and documentation). All three patches updated: 1/3 (core functionality), 2/3 (configurability), and 3/3 (documentation). No maintainer decision yet; still in early review phase.

Key technical details
- Files touched: `builtin/repo.c`, `Documentation/config/repo.adoc`, `Documentation/git-repo.adoc`, `t/t1901-repo-structure.sh`, `sideband.c` (minor typo fix)
- New CLI option: `--concern` (visual or numeric output)
- New config section: `repo.concern.*` (hyphenated keys: `commit-count`, `blob-size`, etc.) for threshold overrides; naming now consistent between code and documentation
- Concern calculation: exponential scale (base-2 logarithms) where each doubling beyond the threshold adds a star; defaults set at mean(log₂) + one standard deviation from a representative repository sample
- Output formats: concern indicators added to table, lines, and nul-terminated output (new column in table format, `concern_level` line in lines/nul mode)
- On-disk format: no changes; purely informational output
- Test coverage: added to `t/t1901-repo-structure.sh` for functionality, configurability, and output format correctness; zlib-related test flakiness addressed in v2 by disabling compression in tests
- Memory management: leak in concern string generation fixed in v2
- Implementation details: concern thresholds defined in `repo_structure_concern_thresholds[]`, concern level computed by `repo_structure_concern_level()`, config parsing handled by `config_concern_thresholds()` via `repo_config()` with the `repo.concern.` prefix
- Minor unrelated fix: missing `#` in `sideband.c` included in 1/3
- Documentation: 59 lines added to `Documentation/config/repo.adoc` listing 14 new config keys (`repo.concern.commit-count`, `repo.concern.tree-count`, etc.), each taking an integer floor of the base-2 logarithm of the threshold value; `Documentation/git-repo.adoc` updated to document `--[no-]concern` option and output formats
