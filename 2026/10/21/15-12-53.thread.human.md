This thread is about a bugfix for `git rev-list` where `--grep` misparses its argument if it looks like another option (e.g., `--grep --missing-only`). The patch, now in its third version by Azuama Odinaka Maximus, makes a minimal two-line change to ensure `--grep` correctly consumes the next argument as its pattern.

The fix itself is uncontroversial and has been confirmed to work by Tanga Joris, who tested it on current `master`. However, Joris raised three concerns: the new tests use spaces instead of tabs (a style violation), the patch only fixes `--grep` while leaving 18 similar options (`--author`, `--committer`, etc.) with the same bug, and a NEEDSWORK comment in the code is now misleading since it references the fixed case. Joris suggests either expanding the fix to cover all affected options or clarifying the commit message to limit its scope. Junio and Pushkar Singh previously reviewed the patch, with Junio focusing on test quality and Pushkar on commit message clarity—both concerns have been addressed in v3. The patch is ready for integration once the minor style and documentation issues are resolved.
