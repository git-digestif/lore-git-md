This thread is about a bugfix for `git rev-list` where the `--grep` option fails when followed by another option-like argument (e.g., `--grep --missing-only`). The issue occurs because the parser treats the next argument as a separate flag rather than the grep pattern. Azuama Odinaka Maximus posted an initial patch, which received a surface-level review from Pushkar Singh suggesting a clearer commit message and additional test coverage for the first argument scan.

The updated v1 patch addresses both requests: the commit message now better explains the problem and motivation, and the test suite (`t/t6022-rev-list-missing.sh`) now includes two new tests—one verifying `--grep` works with patterns starting with `--` (e.g., `--grep --missing-only`), and another ensuring `--grep --exclude-promisor-objects` doesn’t trigger the early argument scan. The fix itself remains minimal (two lines in `builtin/rev-list.c`) and doesn’t affect core revision-walking logic or on-disk formats.
