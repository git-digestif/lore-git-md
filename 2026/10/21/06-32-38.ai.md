This is patch 6/13 in the SHA-1/SHA-256 interoperability series, implementing **pack index v3 writing support** in `pack-write.c`. The patch extends the pack index format to store object IDs in both the primary and compatibility hash algorithms, a critical step for enabling packed objects to be mapped between algorithms (e.g., SHA-1 and SHA-256) in the same repository.

The core changes introduce a new `compat_oid` field to `struct pack_idx_entry` and refactor `write_idx_file()` to handle the v3 format. Key technical details:
- **New fields**: `compat_oid` (stores the compatibility hash algorithm’s object ID) and `idx` (tracks the object’s position in pack order) are added to `struct pack_idx_entry`.
- **Sorting logic**: When writing a v3 index, the code now maintains *three* sorted arrays: one in pack order (original), one sorted by the primary object ID, and one sorted by the compatibility object ID. This ensures the index can be efficiently searched by either algorithm.
- **Header format**: The v3 header includes metadata for both hash algorithms, including the length of abbreviated object names (to minimize padding) and offsets to the tables for each algorithm. Padding is added to ensure 32-bit alignment for performance.
- **Duplicate detection**: The `--strict` flag now checks for duplicates in *both* the primary and compatibility object ID arrays, preventing corruption from ambiguous mappings.
- **Backwards compatibility**: The patch does *not* yet enable v3 writing by default (to avoid breaking tests), but lays the groundwork for future commits to do so.

The implementation is careful about edge cases:
- **Padding**: The code calculates the minimal padding needed to align tables on 4-byte boundaries, avoiding unaligned access issues on some architectures.
- **Strict mode**: Duplicate object IDs are rejected during writing, with clear error messages.
- **Memory management**: Temporary sorted arrays are freed after use, and the original array is re-sorted by object ID before returning (to satisfy callers like `pack-objects` that rely on this order).

This patch is a foundational piece of the interoperability effort, enabling future commits to read v3 indices and automatically select the format in compatibility repositories. The changes are well-scoped and avoid disrupting existing functionality, though the added complexity (e.g., managing multiple sorted arrays) is notable. No review feedback has been received yet.
