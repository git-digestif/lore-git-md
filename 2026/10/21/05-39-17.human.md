This is the fourth patch in Patrick Steinhardt’s seven-patch series introducing the **object storage extension**, a foundational step toward pluggable object database backends in Git. This patch adds user-facing inspection tools for the object storage format, mirroring the existing functionality for the ref storage format.

The patch exposes the configured object storage backend via two commands: `` `git rev-parse --show-object-storage-format` `` and `` `git repo objects.storageFormat` ``. Both return the value of `extensions.objectStorage` if set, or `"files"` if unset. The implementation is straightforward: it adds a new field to `git repo`’s output (`objects.storageFormat`) and a new option to `` `git rev-parse` ``, along with minimal documentation updates and tests. The tests verify that the inspection tools return the expected value (`"files"`) when the extension is configured.

This patch is **uncontroversial and well-scoped**. It follows the established pattern for the ref storage extension, ensuring consistency in how users query repository configuration. The naming (`objects.storageFormat` vs. `object.format`) was discussed in earlier iterations and accepted as a pragmatic compromise, despite its potential for confusion. The implementation is clean, with no behavioral changes beyond exposing the existing `object_storage_format` field in `struct repository`.

The patch is part of a larger architectural effort to make Git’s object database pluggable, but it stands alone as a user-facing feature. It is ready for review, though no substantive feedback has been recorded yet. The primary value here is enabling scripts and users to verify the active object storage backend, which will be increasingly important as alternative backends (e.g., cloud storage) are introduced.
