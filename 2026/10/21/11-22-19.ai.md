This is the **first patch in the v4 series introducing incremental connectivity checking**, adding a **new technical documentation file** (`Documentation/technical/connectivity-check.adoc`) that explains Git’s connectivity invariant, the existing full connectivity check, and its limitations. The document is **112 lines long** and is **confirmed for build system integration** (added to both `Makefile` and `meson.build`).

The patch provides **essential background for the rest of the series**, explaining the core problem: the full connectivity check scales poorly with repository size because it must walk all trees of boundary commits (already-connected commits at the edge of the incoming set), even when the incoming changes are small. The document uses a **clear example graph** to illustrate the boundary between incoming and already-connected commits, showing how the `--not --all` arguments establish the trust boundary. It also covers **exceptions** (gitlinks, promisor objects) and **edge cases** (deepening fetches, non-commit tips), ensuring the incremental mode’s design can be evaluated against the full check’s guarantees.

This is **not a user-facing document** — it is aimed at Git developers and reviewers, providing the technical foundation for the incremental algorithm introduced in later patches. The writing is **precise and well-structured**, with separate sections for the connectivity invariant, full check mechanics, and edge cases. The example graph is particularly effective at clarifying the boundary concept, which is central to the incremental mode’s design.

The patch is **pure documentation** with no code changes, so there is no behavior change or risk of regression. It is **ready for integration** as part of the series, with no open questions or feedback needed beyond typical copy-editing. The only thing missing is a forward reference to the incremental mode (which is introduced in patch 5/6), but that is appropriate for this patch’s scope — the incremental algorithm is not yet part of the documented world.
