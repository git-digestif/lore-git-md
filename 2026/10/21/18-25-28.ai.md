This is the final patch in Justin Tobler’s four-part bugfix series addressing a race condition in Git’s object database (ODB) transaction machinery. The patch moves `.keep` lockfile creation from the quarantine phase to the transaction commit phase, eliminating the risk that concurrent `git-receive-pack` processes will delete each other’s lockfiles and leave newly written packfiles vulnerable to housekeeping deletion.

The change touches `object-file.c` and extends the test script `t/t5547-push-quarantine.sh`. In `object-file.c`, the patch introduces a new `strvec pack_names` field to `struct odb_transaction_files` to track packfile names during quarantine, and a new helper function `write_pack_lockfiles()` that batch-creates lockfiles only during transaction commit. The existing `write_pack_lockfile()` helper is updated to accept an output parameter for the registered tempfile and to explicitly initialize its return value on all exit paths (addressing Patrick Steinhardt’s stylistic feedback). The test now verifies that no `.keep` lockfile exists in the quarantine directory during the pre-receive phase and that a manually created `.keep` file (simulating a concurrent process) is not deleted by the transaction cleanup.

This patch directly implements the core fix described in the series’ goal: deferring lockfile creation until transaction commit ensures lockfiles are only written after the transaction is guaranteed to succeed, closing the race window. The test explicitly checks the concurrent-process scenario that motivated the fix, confirming that no corresponding `.pack` file exists alongside the `.keep` file (a completeness request from Patrick). All substantive feedback from earlier iterations has been addressed, and the series has Patrick Steinhardt’s explicit approval. The only lingering concern—whether leading directories for lockfiles are guaranteed to exist during quarantine—was flagged by Patrick but not revisited in his final review, and the author has not provided further justification or directory-creation logic. This is unlikely to block integration, as the series is otherwise considered complete and technically sound.
