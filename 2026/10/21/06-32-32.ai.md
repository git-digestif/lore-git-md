This is part 3 of the ongoing SHA-1/SHA-256 interoperability effort, specifically implementing **pack index v3** support. The series is a collaboration between Christian Couder and brian m. carlson, building on brian's earlier work to enable Git repositories to operate with both hash algorithms simultaneously.

The core goal is to extend the pack index format to store object IDs in both the primary and compatibility hash algorithms, mirroring the loose object mapping already implemented in earlier parts of the interoperability work. Pack index v3 is essential for interoperability because it allows packed objects to be mapped between algorithms, just as the loose object map does for loose objects.

The series consists of 13 patches, with Christian contributing one new patch (patch 10) that adds validation for pack index v3 tables, and modifying several of brian's original patches to address issues discovered during testing. Key changes include:

- **ODB mapping infrastructure** (patches 1-5): Adds functions to map object IDs between algorithms and write these mappings, implemented for the "files", "loose", and "packed" backends. The "files" backend now checks all object directories (main and alternates) for mappings, reloading loose object maps if needed.
- **Pack index v3 writing** (patches 6-8): Implements writing pack index v3 in `pack-write.c`, `index-pack`, and `pack-objects`. The v3 writer ensures objects are sorted by both main and compatibility object IDs, and properly rejects duplicate objects when `--strict` is used.
- **Pack index v3 reading** (patches 9-12): Adds support for reading pack index v3 in `packfile.c`, including looking up compatibility object IDs in packs. The implementation skips packs with older indices when mapping, and adds new functions (`nth_packed_object_id_algop` and `nth_packed_object_offset_algop`) to handle arbitrary hash algorithms.
- **Validation and documentation** (patches 10, 13): Patch 10 adds thorough validation for pack index v3 tables, checking header lengths, trailer offsets, and table positions against the file size, and ensuring reverse index offsets are within bounds. Patch 13 documents the pack index v3 format in `gitformat-pack(5)`.

The series includes extensive test coverage, with new tests in `t1016-compatObjectFormat.sh` for pack index v3 writing, reading, and abbreviated object ID lookup, as well as tests in `t5308` and `t5313` for duplicate detection and bounds checking.

Several limitations are noted in the cover letter:
- The test suite cannot yet run with `GIT_TEST_DEFAULT_HASH=sha256:sha1` due to missing support for parsing `<algo>:<compat>` in `GIT_DEFAULT_HASH`.
- Pack index v3 is not yet automatically selected in compatibility repositories.
- `index-pack` cannot compute compatibility object IDs for objects whose dependencies lack mappings, a limitation addressed in brian's full `sha256-interop` branch.
- Abbreviated compatibility object IDs only work with certain commands and do not yet work with multi-pack indices.

The series is well-structured and addresses a critical gap in the interoperability effort. The changes are technically sound, with careful attention to edge cases (e.g., duplicate detection, bounds checking) and backwards compatibility. The validation added in patch 10 is particularly valuable, as it prevents corruption from malformed or truncated indices. The test coverage is thorough and covers both happy paths and error cases. This is a substantive contribution that advances the SHA-256 interoperability effort significantly.
