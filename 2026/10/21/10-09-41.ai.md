This is a bugfix patch targeting the sequencer subsystem. It prevents `git revert` from accidentally deleting all tracked files when run on a shallow boundary commit (a commit recorded in `.git/shallow` that appears as a root commit due to `--depth=1` cloning).

The patch adds a safeguard in `do_pick_commit()` that checks whether the target commit is a shallow boundary (detected via `lookup_commit_graft()` returning a graft with `nr_parent < 0`). If so, the operation is refused by default, with a clear error message explaining the risk and suggesting either `--unshallow` or the new `--allow-shallow-boundary` flag. The flag is exposed in both `git revert` and `git cherry-pick` (via shared sequencer code) and documented in `git-revert.adoc`.

The test coverage is thorough: it verifies the refusal in a shallow repo, the override with `--allow-shallow-boundary`, and confirms that non-shallow repos remain unaffected. The commit message clearly states the problem (unintended file deletion) and the solution (default refusal with opt-in override).

This is a well-motivated, narrowly scoped fix with good test coverage and clear documentation. The safeguard is conservative (default refusal) and provides an escape hatch for users who genuinely want the behavior. The patch touches the sequencer, builtin/revert, and documentation, but the changes are localized and mechanical. No controversy is evident from the patch itself.
