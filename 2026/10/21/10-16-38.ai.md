This is the second patch in Elia Pinto’s three-patch series fixing 64-to-32 truncations on Windows (LLP64 platforms). It targets the word-diff subsystem in `diff.c`, where buffer allocation sizes were still stored as `unsigned long` or `long` even after the underlying `mmfile_t` size was changed to `size_t` in Jeff King’s earlier commit (3c7a31204f). On 32-bit `long` platforms, this mismatch causes a real crash: when the buffer grows past ~700 MiB, `alloc_nr()` overflows the signed 32-bit `long`, producing a negative size that `REALLOC_ARRAY()` turns into a huge allocation request, triggering `die()`.

The patch mechanically converts the two allocation counters (`alloc` in `struct diff_words_buffer` and `alloc` in `diff_words_fill()`) from `unsigned long`/`long` to `size_t`. The change is purely type-safe; there is no behavior change on 64-bit Linux, but it prevents undefined behavior on Windows. The commit message explains the overflow scenario in detail and notes that the fix is consistent with the rest of the xdiff subsystem. No new tests are added, as reproducing the issue requires a 32-bit `long` environment and multi-gigabyte files.

This is a clear bugfix with no downsides, touching only one file (`diff.c`) and two lines. The patch is uncontroversial and aligns with the series’ overall goal of eliminating truncation risks on Windows.
