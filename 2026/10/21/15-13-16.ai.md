This is the first patch (v3 1/2) in Erik Cervin-Edin’s two-patch series that completes the feature matrix for non-interactive `git commit --fixup`. The patch enables `-m` and `-F` message sources for all `--fixup` variants (`--fixup`, `--fixup=amend:`, `--fixup=reword:`), building on the refactoring in `prepare_to_commit()` introduced in earlier iterations.

Phillip Wood’s review here is **surface-level**, focusing on code readability and test hygiene rather than design or correctness. He notes that the unavoidable duplication in `prepare_to_commit()` (where the same logic is repeated for `-m` and `-F`) is "not worth refactoring" and otherwise approves the core logic and test updates. His only substantive concern—calling `test_set_editor()` outside a subshell—applies to the second patch (v3 2/2), not this one.

The patch itself is unchanged from v2 except for a rebase onto current `master`. It routes `-m` and `-F` messages through the existing `prepare_to_commit()` machinery, ensuring consistent behavior with interactive workflows. Test coverage in `t/t7500-commit-template-squash-signoff.sh` and `t/t7501-commit.sh` has been expanded to verify edge cases, including nested squash/amend scenarios. No changes to core data structures or on-disk formats are involved.

All prior feedback from Junio Hamano and Phillip Wood has been addressed, and the series is now production-ready. The only remaining action items are minor test hygiene tweaks in the second patch, which do not affect this one. The patch touches `builtin/commit.c`, the test suite, and documentation (`git-commit.adoc`), with no backward-compatibility concerns.
