This is the first patch in a four-patch series (v3) introducing `--reflink` support for copy-on-write worktree creation. The patch adds the core reflink infrastructure, including cross-platform primitives in `copy.[ch]` and the command-line/configuration interface in `builtin/worktree.c`.

The implementation introduces a new `reflink_file()` helper that clones regular files using platform-specific primitives: Linux's `FICLONE` ioctl, macOS's `clonefile()`, and Windows's `FSCTL_DUPLICATE_EXTENTS_TO_FILE` (though the Windows path is now permanently disabled in the series due to ReFS corruption risks). Filesystem capability is probed up-front by attempting to clone a one-byte test file, with graceful fallback to regular checkout when reflinks are unavailable. The patch handles edge cases like dirty worktrees (via `update-index --refresh` before reset), untracked files (carried over as a documented tradeoff), and symlinks (preserved).

The user interface adds a `--reflink` flag to `git worktree add`, with a corresponding `worktree.reflink` configuration (values: `true`, `false`, or `auto`). The feature degrades gracefully in `--orphan` and `--no-checkout` modes, and composes with parallel checkout via `checkout.workers`. Documentation updates include new examples in `git-worktree.adoc` and detailed limitations (e.g., overlayfs incompatibility, Windows ReFS corruption risk). Test coverage in `t2400-worktree-add.sh` verifies correct checkout behavior, option compatibility, and untracked-file handling.

Key technical details include the cross-platform reflink primitives, the filesystem probe mechanism, and the index-cloning optimization that ensures uncommitted changes in the source worktree do not leak into the new one. The patch remains **contested on design grounds**: Eric Sunshine argues the opt-in nature (via `--reflink` or config) is unjustified for tracked files, where the untracked-file copying concern does not apply. The Windows ReFS disablement (addressed in later patches) resolves the immediate technical blocker but leaves the broader design debate unresolved.
