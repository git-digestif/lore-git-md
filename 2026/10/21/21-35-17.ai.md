This is the second patch in a three-patch bugfix series targeting the branch and checkout subsystems. It refactors `setup_tracking()` to return an error code (`int`) instead of calling `exit(1)` when it cannot write the tracking configuration, enabling callers to handle the failure gracefully. The patch also updates `create_branch()` and `dwim_and_setup_tracking()` to propagate this error code, though it does not yet change the behavior of any caller—those changes come in patch 3/3.

The refactoring is minimal and focused, touching only the necessary functions in `branch.c` and their declarations in `branch.h`. The implementation is straightforward: `setup_tracking()` now returns `-1` on failure (previously it called `exit(1)`), and its callers are updated to return this value. The patch preserves the existing behavior for now—`git branch` and the recursive branch creation logic still exit with status 1 on failure—but lays the groundwork for `git switch` and `git checkout` to handle the error differently in the next patch.

Key technical details:
- Files modified: `branch.c`, `branch.h`, `builtin/branch.c`, and `builtin/checkout.c`.
- Subsystems: branch (tracking configuration), checkout/switch (worktree and HEAD updates).
- New or renamed symbols: `setup_tracking()`, `create_branch()`, and `dwim_and_setup_tracking()` now return `int` instead of `void`.
- On-disk format: no changes.
- Test coverage: not directly tested in this patch (tests for the new behavior are in patch 3/3).
