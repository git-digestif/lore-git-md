This is the final patch in Justin Tobler’s four-part bugfix series targeting a race condition in Git’s object database (ODB) transaction machinery. The series is now ready for integration, with all substantive feedback addressed and explicit approval from Patrick Steinhardt.

This patch moves the creation of `.keep` lockfiles from the quarantine phase to the transaction commit phase. The race condition occurs when concurrent `git-receive-pack` processes delete each other’s lockfiles during cleanup, leaving newly written packfiles vulnerable to deletion by housekeeping. By deferring lockfile creation until commit, the fix ensures that lockfiles are only written after the transaction is guaranteed to succeed, eliminating the risk of premature deletion. The patch also introduces a new helper, `write_pack_lockfiles()`, which batch-creates lockfiles during commit, and renames the existing `write_pack_lock()` to `write_pack_lockfile()` for consistency.

The patch touches `object-file.c` and extends the test script `t/t5547-push-quarantine.sh` to verify that no `.keep` lockfile exists in the quarantine directory during the pre-receive phase and that a manually created `.keep` file (simulating a concurrent process) is not deleted by the transaction cleanup. The test also confirms that no corresponding `.pack` file exists alongside the `.keep` file, addressing Patrick Steinhardt’s request for additional coverage.

The only lingering concern—whether leading directories for lockfiles are guaranteed to exist during quarantine—was flagged by Patrick but remains unaddressed. The author justifies the assumption as safe, and Patrick did not revisit this in his final review, so it is unlikely to block integration. The series is otherwise considered technically sound and well-motivated, with clear test coverage and thorough error handling. Junio C Hamano has signaled readiness to merge the series once this v4 reroll was submitted.
