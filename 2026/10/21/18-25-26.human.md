This is the second patch in Justin Tobler’s four-part bugfix series that fixes a race condition in Git’s object database (ODB) transaction machinery. The series is ready for integration, with all substantive feedback addressed and explicit approval from Patrick Steinhardt.

This patch refactors the parsing logic for `git-index-pack`’s output into a new public helper, `read_index_pack_report()`, in preparation for the core fix in patch 4. The helper extracts the packfile name and whether a `.keep` file was created from `git-index-pack`’s stdout, which follows the format `"pack\t<name>\n"` or `"keep\t<name>\n"`. The implementation is hash-algorithm-agnostic, using `repo->hash_algo->hexsz` to size the read buffer, and the updated comment in `pack-write.c` now reflects this by replacing the hardcoded SHA-1 reference (`%40s`) with a generic `<name>`.

The patch splits the original `index_pack_lockfile()` function into two: the new `read_index_pack_report()` handles parsing, while `index_pack_lockfile()` now calls it and constructs the lockfile path if needed. The refactoring is clean and well-motivated, with clear error handling and no behavior changes. The new helper is exposed in `pack.h` and will be used in patch 4 to record packfile names during transaction commit, deferring `.keep` file creation until the transaction is guaranteed to succeed.

The patch is part of the ongoing ODB abstraction effort led by Patrick Steinhardt, and it touches `pack-write.c` and `pack.h`. No test changes are included here, as the existing test coverage in `t/t5547-push-quarantine.sh` (extended in patch 4) verifies the end-to-end behavior. The refactoring is a necessary preparatory step for the race-condition fix, and the patch itself is uncontroversial and technically sound.
