This is a feature series introducing copy-on-write worktree creation and ephemeral branch reaping. The v3 revision (four patches) responds to platform-specific concerns by **disabling reflink on Windows entirely** due to the silent corruption risk in ReFS (Git LFS #6312), while keeping macOS clonefile() support validated in CI. The series now focuses on two core improvements: `--reflink` for CoW worktree creation (patch 1/4) and automatic cleanup of auto-created branches (patch 2/4), with patches 3/4 and 4/4 addressing the Windows-specific fallout.

The reflink implementation remains **opt-in** (via `--reflink` flag or `worktree.reflink` config) rather than automatic, a design choice that continues to face **substantive objections** from Eric Sunshine. The key technical details include cross-platform CoW primitives in `copy.[ch]` (Linux FICLONE, macOS clonefile(), Windows FSCTL_DUPLICATE_EXTENTS_TO_FILE now disabled), filesystem capability probing via one-byte test clones, and careful handling of dirty worktrees via `update-index --refresh`. The ephemeral branch reaping feature (patch 2/4) marks auto-created branches as owned by their worktree and deletes them on `worktree remove`, a behavior that remains **contested** as disruptive to existing workflows.

The Windows-specific patches (3/4 and 4/4) are a direct response to brian m. carlson's **substantive technical concern** about ReFS silent corruption. Patch 3/4 disables the Windows reflink ioctl entirely, while patch 4/4 ensures the filesystem probe remains available for future use. The macOS path is now **validated in CI** (macOS 14.8.9 runners), with all four CI jobs passing using `cp -c`. The series includes extensive test coverage in `t2400-worktree-add.sh` and updates to `git-worktree.adoc` and `config/worktree.adoc` with new examples and detailed limitations.

The reflink implementation carries untracked files (documented as a deliberate tradeoff) and degrades gracefully in `--orphan` and `--no-checkout` modes. The ephemeral branch reaping feature only targets branches created by DWIM auto-naming, leaving user-created branches untouched. The series recommends a safe pattern for multiple worktrees at the same commit: one ref per worktree created in a single `update-ref` transaction. The Windows ReFS measurements in the cover letter demonstrate the CoW behavior but also highlight the corruption risk that led to disabling the feature on Windows.

This revision drops the v1 shared-branch patch entirely, addressing earlier feedback from brian m. carlson and Junio. The remaining **open design questions** center on whether reflink should be default for tracked files (avoiding the untracked-file copying concern) and whether ephemeral branch reaping should be opt-in rather than always-on. The series now faces **substantive scrutiny** on both fronts, with Eric Sunshine's objections remaining unaddressed in this revision. The Windows disablement resolves the immediate technical blocker but leaves the broader reflink design debate unresolved.
