This is **patch 5/6 of a six-patch performance feature** introducing an **incremental connectivity check** for Git fetches and pushes. The patch implements the core algorithm in a new `tree-verify.c` file (427 lines), which processes incoming commits in topological order and verifies each tree only against its trusted parent trees, skipping unchanged subtrees. This shifts the cost of connectivity verification from repository size to incoming change size, offering dramatic speedups for small pushes to large repositories (up to 190x in synthetic benchmarks) while preserving correctness and partial-clone compatibility.

The implementation is **self-contained and well-tested**, with a 795-line test script (`t/t5413-connectivity-check.sh`) covering corruption detection, promisor object handling, and integration with fetch/push/clone. The patch also updates `t/t6700-tree-depth.sh` to enforce recursion limits for the incremental check, mirroring the existing full-check behavior. The algorithm tracks tree OIDs in three states (untrusted, trusted, expanded) and uses a merge-walk to collect same-path parent subtrees as comparison bases, ensuring OID-based trust (unchanged subtrees are recognized even after moves).

Key technical details:
- **New source file**: `tree-verify.c` (implements inductive trust model: parent trees trusted, new trees verified only where differing from parents; memoization skips objects seen in trusted trees)
- **Algorithm**: processes commits in topological order, recursively comparing new trees against parent trees; skips gitlinks entirely
- **Error handling**: detects missing/corrupt objects, type mismatches, and malformed trees; preserves partial-clone semantics (promised objects accepted, lazy-fetch prevented)
- **Performance**: up to 190x faster for small pushes to large repos (14 MB vs. 3.4 GB memory), 2.6–2.8x faster for large/medium repos at 1,000 commits, ~30% slowdown for small repos (e.g., `git.git`) but absolute times negligible (0.1–0.3s)
- **Trace2 instrumentation**: measures trees loaded and blobs checked for observability

The patch is **ready for integration**, with all prior feedback addressed (including Junio’s NULL-dereference concerns and Patrick Steinhardt’s documentation/implementation questions). The only remaining loose end is the **stack overflow risk** in recursive tree verification, which the author plans to address in a follow-up. The series is rebased onto latest master and part of a larger effort to improve Git’s scalability for large repositories.
