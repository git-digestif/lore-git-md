This thread is about formalizing a voting process for the Git project to break deadlocks in contentious decisions, such as the ongoing AI contributions debate. Emily Shaffer proposed a new `Documentation/CommunityVoting.adoc` file to define how votes would work, including eligibility, mechanisms, and safeguards. The patch is purely documentation and remains under review, with no prior versions.

Key participants include Emily (the author), Junio C Hamano (maintainer), Patrick Steinhardt, brian m. carlson, Justin Tobler, Jeff King, and Kristoffer Haugsbakk. The group has coalesced around the need for **secret ballots** to protect voters from external pressure, with Emily now committed to updating the proposal to include this. Junio and others prefer a binary eligibility standard (e.g., contributors with two or more topics in released versions) to exclude drive-by participants, while Emily leans toward inclusivity. Jeff King’s alternative—filtering by commit count and recency—remains in play as a middle ground. Kristoffer’s ideological critique—that voting inherently favors corporate interests—persists but has been somewhat blunted by the secret ballot consensus.

The patch touches only documentation files and has no code or test implications. Open questions include the exact voting mechanism (e.g., ranked-choice), eligibility criteria, and how to version proposal texts (Junio suggested using Git OIDs). The unresolved tension between inclusivity and stricter standards remains, but the focus has shifted to refining the process rather than debating its necessity. The next step is likely a revised patch from Emily incorporating secret ballots.
