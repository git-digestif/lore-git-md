This is an RFC feature proposal for `git worktree list`. The author, Jasper Mayone, wants to add `--merged` and `--no-merged` filters to the command, mirroring the behavior already available in `git branch`, `git tag`, and `git for-each-ref`. The motivation is practical: when using one worktree per topic, merged branches remain checked out, making it hard to identify which worktrees are no longer needed. The patch reuses the existing `ref_filter` infrastructure to implement the filters, ensuring consistent behavior and error messages with other Git commands.

The patch is small and focused, touching only `builtin/worktree.c`, the man page, and adding tests. It defaults to filtering against `HEAD` (matching the ref-filter commands) but asks whether filtering against each worktree’s upstream branch would be more useful for cleanup workflows. The author also raises whether the main worktree should be excluded from the output by default, and whether a future `git worktree remove --merged` would be preferable to scripting the removal.

The implementation looks clean and well-scoped. The questions posed are sensible and directly address real-world usability concerns. If the list agrees on the defaults and direction, this could be a straightforward and useful addition.
