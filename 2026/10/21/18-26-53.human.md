This is a technical reply in the ongoing discussion about `git bisect` output stability and automation. Andreas Schwab chimes in with two concrete plumbing-based alternatives to parsing human-readable `git bisect` output, demonstrating how downstream tooling could avoid the fragility highlighted in the thread.

Specifically, Schwab points out that `git rev-parse --bisect` provides the current "bad" and "good" revisions, and that piping `git rev-list` over those revisions yields the number of commits left to bisect. This is a direct response to Theodore Ts'o's proposal for structured output (e.g., `--format=json`), offering a lightweight, existing mechanism to achieve similar goals without requiring new Git features.

The suggestion is pragmatic and immediately actionable: tooling like `ktest.pl` or `xfstests-bld` could use these plumbing commands to track bisect state (e.g., progress, first bad commit) without relying on parsing messages like "Bisecting: ..." or "is the first bad commit". However, Schwab does not address the gaps noted earlier in the thread—such as the lack of a plumbing command to query whether the first bad commit has been found, or the challenges of integrating these commands into complex workflows (e.g., distributed testing, kernel build/boot/test cycles). His examples are narrowly scoped to the core bisect logic, leaving open whether they fully replace the functionality that downstream tools currently derive from human-readable output.

The tone is neutral and solution-oriented, aligning with Junio C Hamano's earlier suggestion to avoid parsing user-facing messages. While Schwab's examples are technically correct, they may not fully satisfy the use cases described by Steven Rostedt and Ted Ts'o, where progress tracking and integration with external scripts are critical. Nonetheless, the email adds a useful data point to the discussion: for some automation needs, existing plumbing commands might suffice, reducing the urgency of adding structured output. Future replies may explore whether these plumbing-based approaches can be extended to cover the remaining gaps.
