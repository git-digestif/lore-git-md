This is a **bug report** targeting the partial-clone and promisor-remote subsystems. The author, Andrew Parmet, describes a reproducible failure in `git merge` when operating on a partial clone (`--filter=blob:none`). The merge attempts to fetch a locally created blob from the remote, which the remote naturally does not have, causing the operation to fail with `fatal: remote error: upload-pack: not our ref <object-id>`. The same merge succeeds when retried or when run without the blob filter.

The email includes a self-contained shell script that reproduces the issue. The script sets up a minimal server and client repository, creates diverging commits on each, and triggers the bug during the merge. The key detail is that the blob causing the failure is generated *during* the merge (a merge result), not present in either parent commit, so the promisor remote cannot possibly supply it. The script also logs the packet trace to `$root/packets.log` for inspection.

No prior discussion or patch is referenced; this appears to be the first report of the issue. The author explicitly asks whether this is a bug in Git itself, framing it as a potential defect in how partial clones handle locally generated objects during merges. The reproduction script is clear and focused, making it easy for reviewers to verify the behavior. The issue looks genuine and well-documented, likely to attract attention from contributors familiar with promisor remotes and partial-clone internals.
