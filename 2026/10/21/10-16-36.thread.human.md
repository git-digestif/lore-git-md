This thread is a patch series from Elia Pinto that fixes 64-to-32-bit truncation bugs on Windows (LLP64 platforms), where Git silently corrupts or mishandles files larger than 4 GiB. The series has evolved from its initial version (`v1`), which addressed three specific truncation sites in the object database, diff, and file conversion subsystems. After Patrick Steinhardt’s review, the author has now posted `v2` with two key improvements: a new test for object writes over 4 GiB (marked `EXPENSIVE` and platform-specific) and a fourth patch that preemptively fixes integer-overflow risks in `convert.c`’s text statistics counters.

The bugs being fixed are serious: on Windows, `git add` or `git hash-object -w` can truncate blobs, word-diff can crash due to buffer overflow, and file conversion helpers can misclassify files as binary or skip CRLF conversion. The changes are mechanical type conversions (e.g., `unsigned long` to `size_t` or `uintmax_t`) with no behavior change on 64-bit Linux. The new test verifies that object writes (not just hashing) work correctly for large files, addressing Patrick’s concern about test coverage. The fourth patch eliminates theoretical overflow risks in `convert.c`’s counters, which could otherwise lead to incorrect CRLF or keyword expansion decisions.

Patrick Steinhardt has reviewed all patches in both versions and raised no blocking objections. The series is now narrowly scoped, well-tested, and addresses all prior feedback. It appears ready for integration, with no remaining open questions or contested points. The patches touch 11 files across the object database, diff, and file conversion subsystems, and the on-disk format remains unchanged.
