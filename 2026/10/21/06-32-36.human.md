This is part 4 of the 13-patch series implementing **pack index v3 support** for SHA-1/SHA-256 interoperability. The patch adds the core ODB (object database) functions needed to map object IDs between hash algorithms and write those mappings into the repository.

The patch introduces two new ODB-level functions: `odb_map_oid()` (to look up an object ID in a different hash algorithm) and `odb_write_oid_map()` (to persist a mapping between two object IDs). These are implemented for the "files" backend and its "loose" and "packed" sources. The "files" backend checks all object directories (main and alternates) for mappings, reloading loose object maps if needed, and writes new mappings only to the main directory. The "packed" source currently returns "not found" for lookups and "not implemented" for writes, deferring full support until pack index v3 is implemented in later patches.

The implementation is careful about concurrency: if a mapping isn’t found, the loose object map is reloaded to pick up any new mappings written by other processes. The `ODB_MAP_OID_RELOAD` flag controls this behavior. Similarly, the `ODB_WRITE_OID_MAP_WRITE` flag determines whether mappings are persisted to disk or kept in memory, though the current implementation always writes to disk.

This is a well-structured, incremental step in the interoperability effort. The code is clean, the commit message is clear, and the patch fits neatly into the larger series. It doesn’t introduce user-visible behavior changes yet—those come in later patches—but it lays the groundwork for pack index v3 by making the ODB aware of interoperability mappings. The only limitation is the stubbed-out "packed" source, which is explicitly noted as temporary.
