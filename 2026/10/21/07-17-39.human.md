This is the second patch in Jason Newton’s v3 series introducing worktree improvements. It implements **automatic reaping of ephemeral branches**—branches that `git worktree add` auto-creates when no branch is specified. The patch records ownership in the worktree’s administrative directory (`worktrees/<id>/owned-branch`) and deletes the branch when the worktree is removed, addressing a long-standing cleanup nuisance.

The implementation is careful: only DWIM-created branches are marked as owned; branches named explicitly with `-b`/`-B` or pre-existing branches are never reaped. The patch also handles branch renames by updating the ownership marker, and provides a `--keep-branch` option to preserve the branch. Deletion is unconditional (even for unmerged commits) because ephemeral branches are disposable by design—users can anchor commits with an ordinary branch beforehand if they want to keep them.

The patch includes thorough test coverage in `t2400-worktree-add.sh` and updates `git-worktree.adoc` with clear documentation of the new behavior. It also touches `builtin/branch.c` to ensure ownership markers follow branch renames, and updates a few existing tests to use `--keep-branch` where appropriate.

Eric Sunshine’s **substantive objection** remains unaddressed: he argues the feature is redundant given the existing `--detach` flag and risks disrupting workflows that rely on auto-created branches. The patch’s design—always-on reaping with no opt-in mechanism—continues to be the main point of contention. For now, this is a well-crafted but **controversial** usability improvement.
