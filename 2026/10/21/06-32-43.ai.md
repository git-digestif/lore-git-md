This is part 11 of the SHA-1/SHA-256 interoperability series, implementing **packed object mapping via pack index v3**. The patch enables Git to look up object IDs in packed objects when they are not present in the loose object map, a critical step for full interoperability between hash algorithms.

The core change is in `odb/source-packed.c`, where `odb_source_packed_map_oid()` is extended to iterate over all packfiles, skip those with older (v2 or below) indices, and use the new `nth_packed_object_id_algop()` helper to retrieve object IDs in the requested algorithm. The helper, introduced in `packfile.c`, generalizes `nth_packed_object_id()` to handle arbitrary source and destination hash algorithms, with special logic for v3 indices that store both primary and compatibility object IDs. Older indices (v1/v2) are skipped if they cannot provide the requested algorithm.

The test in `t1016-compatObjectFormat.sh` verifies the behavior: a packed object is *not* mappable via a v2 index (which only stores the main algorithm's object ID) but *is* mappable via a v3 index. The test also confirms that the mapped object ID matches the expected compatibility hash.

This patch is a well-motivated and technically sound addition to the series. It addresses a clear gap in the interoperability effort—packed objects were previously unmappable unless they also existed as loose objects—and does so with minimal overhead (skipping older indices early). The changes are localized to the ODB and packfile subsystems, and the test coverage is thorough. The only limitation noted is that the "packed" ODB source still stubs `odb_source_write_oid_map`, but that is deferred to later work. No review feedback has been received yet.
