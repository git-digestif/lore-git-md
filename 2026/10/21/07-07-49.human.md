This is the second patch in Harald Nordgren’s two-patch bugfix series for `git imap-send`. It addresses a real interoperability problem: `git imap-send` previously rejected patches where the `Subject` header appears before the `Date` header, a valid but non-canonical order produced by tools like `b4` when fetching patches from lore.kernel.org. The fix rewrites the header-parsing logic in `imap-send.c` to scan all headers first, then process them in the required order, making the code order-agnostic and RFC 5322-compliant (case-insensitive header name matching via `istarts_with()`).

The patch touches only `imap-send.c` and adds a new test in `t/t9001-send-email.sh` that verifies the fix by sending a patch with `Subject` before `Date` and confirming it is accepted. The test also checks for regressions in the existing `--imap-sent-folder` workflow, which previously required a workaround (commit `04133f5bc4`) that is now redundant. The design was validated as sound in Junio’s substantive review of the first iteration, and the case-sensitivity fix addresses the sole remaining action item.

This is a well-crafted, uncontroversial bugfix with a clear motivation and minimal footprint. The problem is real, the solution is straightforward, and the test ensures it won’t regress. The series is now ready for integration.
