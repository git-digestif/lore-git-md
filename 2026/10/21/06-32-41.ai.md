This is patch 9/13 of the SHA-1/SHA-256 interoperability series, adding **support for reading pack index v3**. The patch implements the core logic to parse and query the new v3 index format, which stores object IDs in both the primary and compatibility hash algorithms.

The key changes are in `packfile.c`, where the patch extends the index loading and lookup machinery to handle v3 indices. It introduces a new `bsearch_hash_v3` function (in `hash-lookup.c`) that performs binary search on the v3 format's dual-sorted tables: one for shortened object IDs (for efficient lookup) and one for full object IDs in pack order. The patch also updates the pack reverse index (`pack-revindex.c`) to use the v3 order map when iterating over objects, ensuring offsets are correctly resolved regardless of the hash algorithm.

The `packed_git` structure gains a new `formats` array (in `packfile.h`) to store per-algorithm metadata (offsets, short name length) for v3 indices. This allows the code to handle indices that may only contain data for one hash algorithm, failing gracefully if a lookup is attempted for an unsupported algorithm.

Tests in `t5302-pack-index.sh` are updated to generate and verify v3 indices, with conditional execution to skip older index versions when a compatibility hash is in use. The patch also fixes a bug in `pack-check.c` where the CRC offset calculation was hardcoded for v2 indices.

This is a well-structured, low-level change that integrates cleanly with the rest of the series. The refactoring of `bsearch_hash` into a reusable helper (`bsearch_hash_1`) is particularly tidy, and the validation of v3 header fields (e.g., checking `num_formats` against `GIT_HASH_NALGOS`) is a sensible safeguard. The patch is ready for substantive review, with no obvious gaps or sloppiness.
