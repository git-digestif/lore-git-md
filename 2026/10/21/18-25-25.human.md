This is the first patch in Justin Tobler’s four-part bugfix series targeting a race condition in Git’s object database (ODB) transaction machinery. The series is ready for integration, with all substantive feedback addressed and explicit approval from Patrick Steinhardt.

This patch is a preparatory refactoring that updates a code comment in `pack-write.c` to be hash-algorithm-agnostic. The comment previously described `git-index-pack` output as containing a "40-character SHA1 name," but the parsing logic already supports both SHA-1 and SHA-256. The updated comment now refers generically to the hexadecimal name of the packfile, using `hexsz` (the length of the hash in hexadecimal characters) instead of hardcoding 40. The change is purely documentary and does not alter behavior or introduce new code.

The patch is small, clean, and well-motivated. It aligns the comment with the existing implementation and removes a misleading reference to SHA-1, which is important for clarity as Git continues to support multiple hash algorithms. This is a sensible cleanup that supports the later patches in the series, which rely on the same parsing logic. No controversy or open questions are associated with this patch.
