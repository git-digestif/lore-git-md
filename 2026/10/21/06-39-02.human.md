This is a **review discussion** in the ongoing thread about Karthik Nayak’s bugfix for the shallow-fetch regression. Patrick Steinhardt responds to Justin Tobler’s v3 review with a new technical suggestion: instead of committing the fetched references mid-transaction (the current two-phase approach), the patch could supplement the backfill negotiation’s "haves" with the pending, uncommitted references from the transaction. This would avoid the need for an intermediate commit and might also fix the issue for `--atomic` fetches, which the current patch leaves broken.

Patrick acknowledges the current approach is a reasonable first step but prefers exploring Justin’s idea first, as it could be a cleaner solution. If the pending-transaction approach proves infeasible, the two-transaction fix would remain the fallback. The tone is collaborative, with no objections to the current patch’s direction—just a preference for a potentially more elegant alternative. The discussion now hinges on whether Justin’s suggestion is technically viable without excessive complexity. No new edge cases or blockers are introduced; this is a design refinement rather than a critique.
