This is a **documentation patch** addressing one of the two SSH signing verification flaws reported earlier in the thread. The patch updates the `gpg.ssh.allowedSignersFile` man page to clarify a critical ambiguity: Git checks key lifetimes (`valid-after`/`valid-before`) against the *committer or tagger date* (which the signer controls), not the time the signature was actually created. The new wording explicitly warns that this date is not evidence of when signing occurred and that key lifetimes are only trustworthy if the key has never leaked.

The change is minimal but important—it fixes a misleading implication in the current documentation that could lead users to overestimate the security of SSH-signed commits. The patch also corrects a typo ("OpensSSH" → "OpenSSH") and adds a parallel note about GPG signatures, where the creation time is similarly controlled by the signer’s clock. Phillip Wood and Patrick Steinhardt (both domain experts) are credited with helping shape the wording, which aligns with the consensus reached in the thread.

This is the first of two planned patches to address the reported issues. The second patch (not yet posted) will make revocation file errors fatal by default, closing the other flaw where Git fails open on missing or unreadable `gpg.ssh.revocationFile` configurations. The documentation update here is uncontroversial and likely to be merged quickly, as it simply clarifies existing behavior rather than changing it. For users relying on SSH signing, this patch is worth reviewing to understand the limitations of key lifetime checks.
