This is a **feature patch** that changes the default behavior of `git status` to compare the current branch against both its upstream (`@{upstream}`) and push (`@{push}`) destinations, rather than only the upstream. The patch is the second iteration (v2) of a series originally submitted by Harald Nordgren, addressing feedback from Junio C Hamano and Phillip Wood.

The v2 patch expands the commit message to provide historical context for the `status.compareBranches` configuration, explaining that the original 2026 commit (3ea95ac9c5) made the feature opt-in due to concerns about noise, with the intention of revisiting the default later. The new default (`@{upstream} @{push}`) preserves the existing output for most users, as `@{push}` resolves to the same branch as `@{upstream}` when `push.default` is set to `simple` (the default). The change only affects users in triangular workflows (where push and upstream destinations differ) or those pushing branches without an upstream.

The patch touches `remote.c` to append `@{push}` to the default comparison list, updates `Documentation/config/status.adoc` to reflect the new default, and adds comprehensive test coverage in `t/t6040-tracking-info.sh`. The tests verify the new behavior in three scenarios: when upstream and push destinations are the same, in a triangular workflow, and for a branch without an upstream. A test also confirms that setting `status.compareBranches` to `@{upstream}` restores the old behavior.

The v2 iteration keeps the existing tests unchanged (rather than mechanically updating them as in v1) and focuses on adding new tests to explicitly cover the new default. The patch is well-motivated, backward-compatible, and includes a clear escape hatch for users who prefer the old behavior. The expanded commit message and thorough test coverage address the substantive review feedback from v1, making this a strong candidate for merging. No technical objections remain, and the patch is ready for further review or integration.
