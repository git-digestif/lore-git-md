This is the third patch in Justin Tobler’s four-patch bugfix series targeting a race condition in Git’s object database (ODB) transaction machinery. The series is part of the ongoing ODB abstraction effort led by Patrick Steinhardt, and this patch prepares the ground for the core fix by refactoring how `.keep` lockfiles are written.

The patch replaces the current reliance on `git-index-pack --keep` to generate `.keep` lockfiles during the quarantine phase with an explicit in-process helper, `write_pack_lockfile()`. This change is necessary because the final patch in the series will defer lockfile creation until transaction commit, at which point `git-index-pack` is no longer available. The new helper constructs the lockfile path, writes the keep message (`"receive-pack <pid> on <hostname>"`), and registers it as a tempfile, mirroring the behavior of the external command but with tighter control over error handling and resource cleanup.

The implementation is careful: it uses `safe_create_file_with_leading_directories()` to create the lockfile, includes `errno` context in error messages, and consolidates all error paths to avoid resource leaks. The commit message justifies the change as a preparatory step for the upcoming transaction-phase lockfile creation, and the code itself is clean and well-structured. All prior feedback from Patrick Steinhardt—including naming consistency, error handling, and style—has been addressed, and the patch has his explicit approval.

This is a refactoring patch with no behavior change in this iteration, but it is a critical enabler for the race-condition fix in the next patch. The series as a whole is ready for integration, and Junio C Hamano has signaled readiness to merge it once the v4 reroll was submitted. The only lingering concern—whether leading directories for lockfiles are guaranteed to exist during quarantine—was flagged by Patrick but not revisited in his final review, and the author has not provided further justification or directory-creation logic. This is unlikely to block integration, as the series is otherwise considered complete and technically sound.
