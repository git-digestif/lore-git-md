This is **patch 5/6 of the six-patch `transfer.connectivityCheck=incremental` performance feature**, implementing the core incremental connectivity-check algorithm in the new `tree-verify.c` file. The patch adds **427 lines of C code** that process incoming commits in topological order, verifying each commit’s tree only against its parents’ trusted trees to avoid walking unchanged subtrees. It integrates with the existing `rev-list` subprocess (via the `--connectivity-check=incremental` flag added in patch 4/6) and preserves partial-clone semantics by skipping promisor objects.

Key technical details:
- **Algorithm**: inductive trust model (parent trees trusted, new trees verified only where differing from parents; memoization skips objects seen in trusted trees)
- **Data structures**: `kh_oid_tree_t` map tracks tree OIDs in three states (untrusted/trusted/expanded); `oidset` tracks trusted blobs; `work_list` queues untrusted entries for verification
- **Performance instrumentation**: Trace2 events (`trees_loaded`, `blobs_checked`) measure overhead
- **Error handling**: no new `die()` calls in library code; errors are returned and centralized at the subprocess boundary
- **Edge cases**: handles gitlinks (skipped), file/directory transitions, missing promisor objects, and replacement objects
- **Recursion limit**: enforces `core.maxTreeDepth` to match the full check’s behavior

The patch includes **774 lines of new tests** (`t/t5413-connectivity-check.sh`) that verify semantic equivalence with the full check, corruption detection, promisor object handling, and integration with fetch/push/clone. Tests cover both correctness (e.g., rejecting missing blobs, detecting malformed trees) and performance (e.g., trace2 counts for trees loaded and blobs checked). The incremental mode is shown to be **up to 190x faster** for small pushes to large repositories while using **less memory** (12 MB vs. 31 MB in synthetic benchmarks).

The implementation is **well-isolated**: it adds a single new source file (`tree-verify.c`) and header (`tree-verify.h`), and touches only `builtin/rev-list.c` (to wire up the new mode) and `connected.c` (to pass the mode through). The **trust boundary detection** relies on `git rev-list --not --all` to identify already-connected commits, then processes incoming commits in reverse topological order. Each commit’s tree is verified only against its parents’ trusted trees, with memoization skipping objects seen in trusted trees.

The patch addresses all prior feedback from **Junio C Hamano** (NULL-dereference risks, lazy-fetch concerns) and **Patrick Steinhardt** (error handling, dynamic fallback, stack overflow mitigation). The **stack overflow risk** in recursive tree verification remains unresolved but is acknowledged as a potential follow-up (noted in the commit message and documentation). The series is **ready for integration**, with no remaining blockers from a maintainer perspective.
