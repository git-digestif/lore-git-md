Tuomas Ahola replies to Dan’s report of a `git push` regression caused by libcurl 8.23.0+ stripping credentials from `CURLINFO_EFFECTIVE_URL`. Tuomas points out that the issue was already fixed in Git’s `master` branch by commit `76524c2604` ("http: handle curl stripping creds from effective url", 2026-09-28), which is included in the upcoming Git 2.55.0 release.

The fix addresses the exact scenario Dan described: push failures over smart HTTP when the remote URL contains only a token as the username (e.g., `https://<token>@forge.example/owner/repo.git`). Since the patch is already merged, this email serves as a heads-up to Dan (and others encountering the issue) that upgrading to Git 2.55.0 will resolve the problem.
