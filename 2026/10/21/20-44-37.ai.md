This is a refactoring patch in the `the_repository` removal effort, but Junio raises a fundamental question about the approach. The patch moves the global `git_commit_encoding` variable into the `repo_config_values` struct, making it repository-scoped and updating `write_commit_tree()` to accept a `struct repository *` parameter. Junio argues that this is unnecessary complexity: since `git_commit_encoding` is only used in `commit.c`, it would be simpler to pass the encoding as a `const char *` parameter directly to the functions that need it, rather than embedding it in the repository struct.

The email shifts the discussion from a mechanical refactoring to a design question: whether repository-scoped configuration is the right abstraction for this value. Junio’s alternative avoids touching `repo_config_values` entirely and keeps the change localized to the commit subsystem. This could reduce coupling and make the code easier to reason about, but it would deviate from the established pattern of the `the_repository` removal series, which has consistently moved globals into `repo_config_values`.
