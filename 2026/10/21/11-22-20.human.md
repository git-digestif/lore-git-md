This is the **performance test patch** for the incremental connectivity check feature, the second of six patches in the v4 series. It adds synthetic benchmarks that isolate the cost of Git’s connectivity verification by varying three dimensions: total repository size, number of incoming commits, and files changed per commit.

The patch introduces a Perl script (`generate-repo-p5413-connectivity-check.perl`) that generates fast-import streams for synthetic repositories. Each repository has a flat directory structure with many small files, allowing precise control over the three scaling axes. The script creates one initial commit with `dirs × files_per_dir` files, then `commits` additional commits that each modify `files_per_commit` files in round-robin fashion across the first `hot_dirs` directories. This design keeps the working set small while ensuring the connectivity check must walk the entire object graph.

The test script (`p5413-connectivity-check.sh`) defines a helper function `test_perf_conn` that sets up a fresh repository for each benchmark, repacks it to avoid pack-transfer noise, and then runs `git rev-list --objects --stdin --not --all` to measure the connectivity check in isolation. The benchmarks cover four repository sizes (5K to 800K files), seven commit counts (1 to 10,000), and six files-per-commit values (1 to 2,000), producing 17 distinct data points. Each test is guarded by a `PERL` prerequisite and includes a descriptive label that makes the scaling axis clear.

The benchmarks are well-designed for their purpose: they avoid confounding factors like network or disk I/O by using fast-import and repacking, and they provide a clean baseline for comparing the full and incremental connectivity checks. The synthetic workload is simple but representative of real-world patterns where small changes are pushed to large repositories. The patch is a straightforward addition to the performance test suite and carries no controversy or open questions.
