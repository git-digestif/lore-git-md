This is a small but important refactoring patch in the SHA-1/SHA-256 interoperability series. It adds a flag (`OBJ_MAP_WRITE`) to control whether object ID mappings are written to disk when added to the loose object map. Currently, mappings are always written, but future work (such as indexing packs) will need to temporarily store mappings in memory without persisting them. The flag is set at bit 6 to avoid conflicts with future object type bits.

The change is mechanical: the `source_add_loose_object_map()` function gains a `flags` parameter, and callers in `odb/source-loose.c` pass `OBJ_MAP_WRITE` to preserve existing behavior. The patch is well-motivated by the upcoming need to decouple mapping insertion from disk writes, and the commit message clearly explains the rationale. No behavior changes are introduced in this patch—it only prepares the infrastructure for later use.

This is the third patch in the 13-patch series implementing pack index v3 support. The series as a whole is a critical step for SHA-256 interoperability, enabling packed objects to be mapped between hash algorithms just as loose objects already can. The refactoring here is a small but necessary part of that larger effort, and the patch itself is clean and uncontroversial. Reviewers should focus on whether the flag’s placement and naming are future-proof, but the patch looks solid as-is.
