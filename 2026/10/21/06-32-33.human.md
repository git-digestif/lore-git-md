This is the first patch in the 13-part series implementing **pack index v3** support for SHA-1/SHA-256 interoperability. It refactors the loose object mapping infrastructure to allow looking up object IDs in the mapping table using an explicit `struct odb_source_loose` source, rather than iterating through all object directories in the repository.

The patch extracts the core lookup logic from `repo_loose_object_map_oid` into a new function, `source_loose_object_map_oid`, which takes an `odb_source_loose` parameter. This change preserves the existing behavior while making the function reusable for other parts of the ODB abstraction. The original `repo_loose_object_map_oid` function is updated to call the new function for each loose object directory in the repository.

The motivation is to prepare for wiring up object mapping into the ODB abstraction, a key step for enabling pack index v3 support. The patch is small and focused, touching only `loose.c` and `loose.h`, and introduces no behavior changes or new features. The commit message is clear and explains the purpose of the refactoring.

This is a well-crafted refactoring patch that lays the groundwork for later patches in the series. It is uncontroversial and unlikely to attract significant review feedback, as it is purely preparatory and does not alter Git's behavior. The patch is part of a larger, technically sound effort to enable SHA-256 interoperability, and its inclusion in the series is justified.
