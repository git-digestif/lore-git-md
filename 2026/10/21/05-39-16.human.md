This is the third patch in Patrick Steinhardt’s seven-part series introducing the **object storage extension**, a mechanism for pluggable object database backends in Git. This patch adds support for overriding the configured object storage format via the `GIT_OBJECT_STORAGE_FORMAT` environment variable, mirroring the existing behavior for ref storage (`GIT_REF_STORAGE_FORMAT`).

The change is straightforward: when Git initializes a repository, it now checks for the `GIT_OBJECT_STORAGE_FORMAT` environment variable and uses its value to override the `extensions.objectStorage` configuration if present. The variable follows the same URI format (`<schema>[://<payload>]`) as the config key, and the patch includes validation to reject unknown schemas. Documentation is updated to list the new variable alongside other Git environment variables, and a new test verifies that the override works as expected—objects are written to the directory specified in the environment variable, and invalid formats trigger an error.

The patch touches only four files: `Documentation/git.adoc` (documentation), `environment.h` (symbol definition), `setup.c` (core logic), and `t/t0001-init.sh` (tests). The implementation is minimal and follows the established pattern for ref storage, making it uncontroversial in principle. The test coverage is thorough for the happy path and error cases, though Karthik Nayak’s review of v1 suggested additional coverage for edge cases like invalid path payloads; Patrick deferred those to avoid overcomplicating the initial implementation.

This patch is a small but necessary piece of the larger series, enabling users and scripts to temporarily override the object storage backend without modifying configuration. It’s unlikely to attract significant discussion on its own, but it’s a clean, well-motivated addition that fits neatly into the broader effort. The series as a whole remains under review, with the v2 updates addressing initialization robustness and submodule integration.
