This is the second patch in Harald Nordgren’s two-patch bugfix series for `git imap-send`, targeting interoperability with tools like `b4` that emit patches with `Subject` before `Date` headers. The patch rewrites the header-parsing logic in `imap-send.c` to accept the three required headers (`From`, `Date`, `Subject`) in any order and with case-insensitive names, as mandated by RFC 5322. The helper function `has_required_headers()` now uses `istarts_with()` to scan all headers first, then checks for presence rather than enforcing a fixed sequence. This change removes the need for the special-case workaround introduced in commit `04133f5bc4` for `git send-email --imap-sent-folder`.

The patch touches only `imap-send.c` and adds a new test in `t/t9001-send-email.sh` that verifies the fix by sending a patch with `Subject` before `Date` and confirming `git imap-send` accepts it. The test also checks for regressions in the `--imap-sent-folder` workflow. The design (cursor-handling logic, order-agnostic parsing) was validated in Junio’s substantive review of v1, and the case-sensitivity fix addresses the sole remaining action item from that review.

This is a well-motivated, uncontroversial bugfix with minimal footprint. The problem is real (interoperability with `b4`/`lore.kernel.org`), the solution is straightforward, and the test ensures it won’t regress. The series is now ready for integration. Key symbols introduced: `has_required_headers()` helper in `imap-send.c`; test coverage exercises the new code path and existing `--imap-sent-folder` workflow. No on-disk format changes.
