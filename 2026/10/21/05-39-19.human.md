This is the sixth patch in Patrick Steinhardt’s seven-patch series introducing the **object storage extension**, a foundational step toward pluggable object database backends in Git. This patch wires up the new `--object-storage-format=` option in `git clone`, mirroring the functionality already added to `git init` in the previous patch.

The implementation is straightforward: the new option allows users to specify the object storage backend (e.g., `files://objs`) when cloning a repository. The patch also enforces a **local clone restriction**—if either the source or destination repository uses a non-default object storage format, local clones (which hardlink or copy objects) are disabled. In such cases, the clone either falls back to a non-local transport (with a warning) or fails outright if `--local` was explicitly requested. This restriction is a pragmatic trade-off to avoid complexity in the initial implementation, though the commit message notes that future work could relax it for cases where the `files` backend is configured with an alternative object directory path.

The patch touches `builtin/clone.c`, adding the new option, validation logic, and the `is_using_default_object_storage_format()` helper function to check whether a repository uses the default `files` backend. Documentation (`git-clone.adoc`) is updated to describe the option and its behavior, including the local clone restriction. Tests in `t/t5601-clone.sh` cover the new functionality, including valid and invalid formats, payload handling, and the local clone fallback behavior.

This patch is **well-crafted and uncontroversial**, following the established pattern set by the ref storage extension. The local clone restriction may attract discussion about whether it is too conservative, but the restriction is clearly documented and justified as a temporary measure. The implementation is minimal, correct, and aligns with the series’ goal of providing a baseline for pluggable object storage. No substantive review feedback has been recorded yet, but the patch appears ready for deeper technical scrutiny. If the series as a whole lands, this patch will be a key enabler for users to experiment with alternative object storage backends.
