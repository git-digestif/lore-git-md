This is the first patch in Justin Tobler’s four-part bugfix series targeting a race condition in Git’s ODB transaction machinery. It is a **refactoring patch** that updates a code comment in `pack-write.c` to be hash-algorithm-agnostic.

The patch modifies the comment in `index_pack_lockfile()` to stop hardcoding SHA-1 assumptions. The original comment described the expected output from `git-index-pack` as `"pack\t%40s\n"` or `"keep\t%40s\n"`, explicitly referencing the 40-character SHA-1 hash length. The updated comment now refers generically to `<name>` and uses `hexsz` (the repository’s hash algorithm’s hexadecimal length) to describe the expected format. The change aligns the documentation with the existing code, which already uses `repo->hash_algo->hexsz` to size the read buffer and thus supports both SHA-1 and SHA-256.

The patch touches only the comment in `pack-write.c`; no code behavior or logic is altered. The commit message clearly explains the motivation and the specific change, and the diff is minimal and focused. This patch is preparatory for the later patches in the series, which expose `read_index_pack_report()` (a refactored version of the parsing logic) as a public API. The series as a whole has Patrick Steinhardt’s explicit approval and is considered technically sound and ready for integration.
