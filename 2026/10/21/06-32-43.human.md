This is part 11 of the 13-patch series implementing **pack index v3** support for SHA-1/SHA-256 interoperability. The patch enables Git to map object IDs for packed objects using the new pack index v3 format, even when those objects are not present in the loose object map.

The core change is in `odb/source-packed.c`, where the `odb_source_packed_map_oid` function is extended to look up packed objects in pack index v3. The function now iterates over all packfiles, skips those with older index versions (v2 or below), and uses the new `nth_packed_object_id_algop` helper to retrieve object IDs in the requested hash algorithm. This allows the loose object mapping infrastructure to work with packed objects, a critical step for interoperability.

In `packfile.c`, the patch introduces `nth_packed_object_id_algop`, a generalized version of `nth_packed_object_id` that can handle arbitrary source and destination hash algorithms. The function checks the pack index version and fails if the requested algorithm is not available (e.g., compatibility object IDs in v2 indices). For v3 indices, it uses the pack order map to locate the correct object ID in the sorted table for the destination algorithm.

The test in `t1016-compatObjectFormat.sh` verifies the behavior: when the loose object map is missing, Git can still map packed objects using a v3 index but not a v2 index. The test creates a repository, repacks objects into a v3 index, removes the loose object map, and confirms that object ID mapping works only with the v3 index.

This patch is well-motivated and technically sound. It fills a key gap in the interoperability effort by extending object ID mapping to packed objects, and the implementation is careful to maintain backwards compatibility (e.g., skipping older indices). The test coverage is thorough and clearly demonstrates the intended behavior. The series as a whole is a significant step forward for SHA-256 support, and this patch is a critical piece of that work.
