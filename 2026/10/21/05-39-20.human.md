This is the final patch in Patrick Steinhardt’s seven-part series introducing the **object storage extension**, a foundational step toward pluggable object database backends in Git. This patch completes the series by propagating the `--object-storage-format=` option through `git submodule add` and `git submodule update`, ensuring submodules inherit the parent repository’s object storage configuration.

The implementation is mechanical and follows the established pattern for the ref storage extension. The patch adds the `--object-storage-format` option to both subcommands, validates the format using the existing `odb_source_type_by_uri()` helper, and passes it through to the underlying `git clone` invocation. Documentation updates to `git-submodule.adoc` mirror the ref storage extension’s phrasing, and a new test script (`t7427-submodule-object-storage-format.sh`) verifies initialization, cloning, and error cases (e.g., invalid formats).

The patch is uncontroversial and appears ready for review. It touches only the submodule subsystem and reuses validation logic from earlier patches, so the risk of introducing new edge cases is low. The test coverage is thorough, including recursive clone propagation and path handling for the `files` backend’s payload support. This is a clean, incremental addition that rounds out the series’ core functionality.
