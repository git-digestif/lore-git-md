This is the fifth patch in Patrick Steinhardt’s seven-patch **object storage extension** series (v2), which lays the groundwork for pluggable object database backends in Git. This patch adds **user-facing configuration and command-line support** for the object storage format to `git init`, mirroring the existing pattern for the ref storage extension.

The patch introduces the `--object-storage-format=<format>` option to `git init`, allowing users to specify the object storage backend (e.g., `files://objs` to relocate objects to `.git/objs`). It also adds the `init.defaultObjectStorageFormat` configuration key and the `GIT_DEFAULT_OBJECT_STORAGE_FORMAT` environment variable, both of which set the default format for new repositories. The precedence rules follow Git’s standard hierarchy: command-line options override environment variables, which override config, which override the hardcoded `"files"` default.

The implementation is **mechanical and correct**, reusing the validation logic (`odb_source_type_by_uri()`) and repository setup machinery (`repository_format_configure()`) introduced in earlier patches. The patch updates `setup.c` to handle the new configuration sources, extends `create_repository()` to accept an `object_storage_format_uri` parameter, and ensures the `extensions.objectstorage` config key is written (or removed) based on the chosen format. The `files` backend without a payload remains the default and does not trigger an extension, preserving backward compatibility.

Tests cover initialization with various formats (relative/absolute paths, payloads), environment variable overrides, reinitialization with mismatched formats, and error cases (invalid formats, conflicting configurations). The tests also verify that `GIT_OBJECT_DIRECTORY` takes precedence over the payload, ensuring existing workflows remain unaffected. One notable edge case is the **local clone restriction** (imposed in patch 6/7), but this patch does not yet enforce it—it only sets up the configuration plumbing.

The patch is **uncontroversial** and aligns with the established pattern for ref storage. No substantive review feedback has been recorded yet, but the implementation is thorough and well-tested. The primary value here is **ergonomics**: users can now configure object storage via familiar Git mechanisms rather than manually editing config files. The patch does not introduce new backends or behavior changes—it merely exposes the existing `files` backend through the new interface.
