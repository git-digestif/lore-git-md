This is the third patch in Justin Tobler’s four-patch bugfix series (v4 3/4) targeting a race condition in Git’s object database (ODB) transaction machinery. The series is part of the ongoing ODB abstraction effort led by Patrick Steinhardt and is now ready for integration, with all substantive feedback addressed and explicit approval from Patrick.

This patch prepares for the core fix (deferring `.keep` lockfile creation to the transaction commit phase) by refactoring `odb_transaction_files_write_pack()` to explicitly generate `.keep` lockfiles itself, rather than relying on `git-index-pack`’s `--keep` option. The change is mechanical but necessary: the new `write_pack_lockfile()` helper constructs the lockfile path, writes the keep message (`"receive-pack <pid> on <hostname>"`), and registers it as a tempfile. Error handling is robust, with `errno` context and lockfile paths included in error messages, and all resources are properly released on failure.

The patch touches only `object-file.c` and introduces no new public APIs, but it renames the internal logic to align with existing naming conventions (e.g., `write_pack_lockfile()` instead of `write_pack_lock()`). The commit message clearly explains the motivation—preparing for the deferred lockfile creation in the next patch—and the code changes are straightforward, with no behavioral impact in this patch alone. The only assumption (that leading directories for lockfiles exist during quarantine) was flagged by Patrick Steinhardt in earlier reviews but remains unaddressed; this is not considered a blocker for integration.

This patch is a refactoring step with no user-visible changes, but it is critical for the series’ correctness. The new `write_pack_lockfile()` helper will be used in the next patch to batch-create lockfiles during transaction commit, eliminating the race condition. The code is clean, well-structured, and addresses all prior feedback, including Patrick’s final stylistic tweak (explicitly assigning the return value on all exit paths). The series as a whole is technically sound and has strong test coverage in `t/t5547-push-quarantine.sh`.
