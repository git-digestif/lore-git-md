This is the **v4 iteration of a six-patch performance feature** that introduces an **incremental connectivity check** for Git fetches and pushes, gated behind the new `transfer.connectivityCheck=incremental` or `auto` configuration. The series is now **ready for integration**, with all prior feedback addressed and a **three-mode config design** (`full`/`incremental`/`auto[=<n>]`) that includes a **configurable 1,000-commit cutoff** for dynamic fallback to the full check.

The core idea is to **shift the cost of connectivity verification from repository size to incoming change size** by processing commits in topological order and tracking a growing set of "trusted" objects derived from parent commits. This avoids walking unchanged subtrees, dramatically speeding up small pushes to large repositories (up to **190x faster** in synthetic benchmarks) while preserving correctness and partial-clone compatibility. The implementation is **self-contained**, adding a new `tree-verify.c` file (427 lines) and integrating with the existing `rev-list` subprocess to avoid lazy-fetch issues in partial clones.

Key technical details:
- **New config keys**: `transfer.connectivityCheck=full|incremental|auto[=<n>]` (default: `full`), `transfer.connectivityCheckIncrementalMaxCommits=<n>` (default: 1,000)
- **New internal `rev-list` flag**: `--connectivity-check=full|incremental`
- **Algorithm**: inductive trust model (parent trees trusted, new trees verified only where differing from parents; memoization skips objects seen in trusted trees)
- **Fallbacks**: `auto` mode dynamically switches to full check for deepening fetches, pushes into empty repositories, and incoming histories exceeding the configured cutoff
- **Error handling**: no new `die()` calls in library code; errors are returned and centralized at the subprocess boundary
- **Performance**: up to 190x speedup for small pushes to large repos (14 MB vs. 3.4 GB memory), 2.6–2.8x faster for large/medium repos at 1,000 commits, ~30% slowdown for small repos (e.g., `git.git`) but absolute times negligible (0.1–0.3s)
- **Test coverage**: 795-line `t/t5413-connectivity-check.sh` (semantic equivalence, corruption detection, promisor object handling, integration with fetch/push/clone) and 92-line `t/perf/p5413-connectivity-check.sh` (benchmarks across repository size, incoming commit count, and files changed per commit)
- **Documentation**: 259-line `Documentation/technical/connectivity-check.adoc` explaining the algorithm, trust model, and tradeoffs
