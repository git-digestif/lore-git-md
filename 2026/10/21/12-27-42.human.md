This is a **feature patch** that changes the default behavior of `git status` to show comparisons against both the upstream (`@{upstream}`) and push (`@{push}`) branches, rather than just the upstream. The change targets users in triangular workflows—where code is pulled from one repository but pushed to another—making `git status` more informative by default without disrupting the experience for most users.

The patch is a **v2 revision** that directly addresses feedback from Junio C Hamano and Phillip Wood on the initial submission. The commit message now provides historical context for the `status.compareBranches` configuration (introduced in commit `3ea95ac9c5`), explaining why the comparison with `@{push}` was originally made opt-in and why the time is right to flip the default. This revision also adds thorough test coverage for the new behavior, including cases where upstream and push branches are the same, where they differ (triangular workflow), and where no upstream is configured.

The implementation is minimal: a single line in `remote.c` appends `@{push}` to the default comparison list, and the documentation is updated to reflect the new default. The patch preserves backward compatibility by allowing users to restore the old behavior with `status.compareBranches = @{upstream}`. Test updates are careful not to break existing coverage while adding explicit scenarios for the new default.
