# Thread deltas

## 2026/10/21

- [2026/10/21/10-16-36 by Elia Pinto <gitter.spiros@gmail.com>] Elia Pinto posted a 3-patch series converting remaining object and buffer sizes from `unsigned long`/`long` to `size_t` to fix silent truncation above 4 GiB on 64-bit Windows (LLP64), covering the odb write API, word-diff buffer allocation, and convert helpers; no new tests were added because each case needs multi-GiB files with a 32-bit `long`.
- [2026/10/21/10-16-37 by Elia Pinto <gitter.spiros@gmail.com>] Patch 1 changes `odb_write_object_ext()`, `odb_write_object()`, `odb_source_write_object()`, `write_loose_object()`, and the in-memory source's stored size to take `size_t`, fixing the case where `git add`/`git hash-object -w` of a file over 4 GiB run through a conversion (e.g. core.autocrlf) writes a blob truncated to `size mod 2^32` bytes while the index records the real file's stat data.
- [2026/10/21/10-16-38 by Elia Pinto <gitter.spiros@gmail.com>] Patch 2 changes `diff_words_buffer.alloc` and the local `alloc` in `diff_words_fill()` to `size_t`, fixing the signed-`long` overflow in `alloc_nr()` past about 700 MiB that produced a negative size, a huge reallocation request, and a `die()` on LLP64.
- [2026/10/21/10-16-39 by Elia Pinto <gitter.spiros@gmail.com>] Patch 3 changes `gather_stats()`, `gather_convert_stats()`, `gather_convert_stats_ascii()`, `count_ident()`, `read_blob_data_from_index()`, and index attribute reading to use `size_t`, fixing prefix-only scanning of files over 4 GiB and the `git add` failure with core.autocrlf when the staged version exceeds 4 GiB.
- [2026/10/21/11-24-25 by Patrick Steinhardt <ps@pks.im>] Patrick Steinhardt called the patch-1 bug serious and argued an EXPENSIVE test should still be added rather than skipped, and confirmed the in-memory-source fix is correct despite 4 GiB in-memory blobs.
- [2026/10/21/11-24-36 by Patrick Steinhardt <ps@pks.im>] Patrick Steinhardt verified the patch-2 allocation value is only ever used for `ALLOC_GROW()` (never as a negative value) and called the signed-`long` usage especially offending.
- [2026/10/21/11-24-43 by Patrick Steinhardt <ps@pks.im>] Patrick Steinhardt asked whether `struct text_stat`'s `unsigned` counters in patch 3 should also be widened, and noted `count_ident()` overflow is theoretically possible but unlikely since it counts `$Id$` markers.
