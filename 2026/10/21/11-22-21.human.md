This is the third patch in the six-part **incremental connectivity check** series, a performance feature that reduces the cost of verifying object connectivity during fetches and pushes. This patch is a **refactoring** that prepares the ground for the upcoming implementation by eliminating the dependency on the global `the_repository` variable in `connected.c`.

The change is mechanical but important: it modifies `check_connected()` and its helper `check_connected_promisor()` to accept an explicit `struct repository *` parameter instead of implicitly using `the_repository`. All callers—`builtin/clone.c`, `builtin/fetch.c`, `builtin/receive-pack.c`, `bundle.c`, and `fetch-pack.c`—are updated to pass `the_repository` explicitly. The patch also removes the `USE_THE_REPOSITORY_VARIABLE` define from `connected.c`, making the dependency explicit throughout the codebase.

This refactoring was **suggested by Junio C Hamano** during the v1 review and is part of the ongoing `the_repository` removal effort. It is a prerequisite for the next patch (4/6), which will read configuration inside `check_connected()`. The patch is **well-scoped and uncontroversial**, touching only the plumbing layer without changing behavior. All prior feedback on this part of the series has been addressed, and the patch is **ready for integration** as part of the larger feature.
