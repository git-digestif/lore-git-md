This is the second patch in a three-part bugfix series targeting 64-to-32-bit truncation issues on Windows (LLP64 platforms). It fixes a crash in the word-diff subsystem when processing large files.

The patch addresses a type mismatch in `diff.c`: while the `mmfile_t` structure (used for diff buffers) was recently converted to `size_t` for its size field, the word-diff code still tracks allocated buffer sizes using `unsigned long` and `long`. On 32-bit `long` platforms, this creates an overflow when the buffer grows beyond ~700 MiB. The overflow triggers undefined behavior—typically a negative size that causes `REALLOC_ARRAY()` to request an impossibly large allocation, crashing Git.

The fix is mechanical: change the `alloc` fields in `struct diff_words_buffer` and `diff_words_fill()` from `unsigned long`/`long` to `size_t`. This matches the type used in `mmfile_t` and prevents truncation. The patch also future-proofs the code against potential increases in `MAX_XDIFF_SIZE`, which currently caps input size at just under 1 GiB.

No new tests are included, as reproducing the issue requires a 32-bit `long` environment and files large enough to trigger the overflow. The commit message clearly explains the reproduction scenario and the arithmetic behind the overflow, making the problem easy to verify.

This is a straightforward, well-motivated fix that aligns with recent work by Jeff King on `xdiff` buffer sizes. It should be uncontroversial.
