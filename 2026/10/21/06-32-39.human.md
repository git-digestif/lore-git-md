This is part 7 of the 13-patch series implementing **pack index v3** for SHA-1/SHA-256 interoperability. The patch teaches `git index-pack` and `git pack-objects` to populate the compatibility object ID fields in the pack index v3 format, enabling packed objects to be mapped between hash algorithms just as loose objects already can.

The core change is in `builtin/index-pack.c`, where the code now computes both the primary and compatibility object IDs during the indexing process. For blobs, this is straightforward because the content is identical across hash algorithms, so both hashes can be computed in a single pass. For non-blobs (trees, commits, tags), the code converts the object from the primary to the compatibility algorithm before hashing, using the existing `convert_object_file()` infrastructure. To handle dependencies (e.g., a tree referencing a blob whose compatibility ID is needed), the patch temporarily stores computed compatibility IDs in the loose object map but avoids writing them to disk, preventing pollution of the on-disk index.

Thread safety is addressed with a new mutex (`repo_mutex`) to protect the loose object map, which is accessed by multiple threads during parallel indexing. The mutex is acquired and released around object conversion and map updates, ensuring safe concurrent access.

The patch also updates `git pack-objects` to populate the compatibility ID field when creating object entries, using `repo_oid_to_algop()` to map the primary ID to the compatibility algorithm. Both commands now accept `--index-version=3` as a valid option, and the patch adds tests to verify that `index-pack` can write a v3 index in a compatibility repository and reject packs with duplicate objects when using `--strict`.
