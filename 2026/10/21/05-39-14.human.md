This is the first patch in Patrick Steinhardt’s seven-part series introducing Git’s new **object storage extension** mechanism, which lays the groundwork for pluggable object database backends. This specific patch is a clean-up: it removes the unused function `repo_write_loose_object_map()` from the loose object subsystem.

The function was introduced in 2023 to write a mapping between SHA-1 and SHA-256 loose objects, but it was never called—loose object maps are instead updated incrementally via `repo_add_loose_object_map()`. Beyond being dead code, the function hardcoded the path to the loose object index as `$GIT_COMMON_DIR/objects`, which would conflict with the rest of the codebase if the object directory were relocated (a capability the object storage extension is designed to support). The patch deletes the function and its declaration, removing 46 lines of code.

This is a straightforward refactoring with no behavior change. The commit message is thorough, explaining both the unused status and the latent bug (hardcoded path) that would have surfaced once the object storage extension landed. The patch is uncontroversial and aligns with the series’ broader goal of making the object database pluggable. It’s a small but necessary step before introducing the new configuration mechanism in later patches.
