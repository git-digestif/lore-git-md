This is a feature patch series (v3) introducing two worktree improvements: copy-on-write (CoW) worktree creation via `--reflink` and automatic reaping of ephemeral branches. The series now consists of four patches, up from two in v2, reflecting significant changes to address platform-specific issues—most notably disabling reflink on Windows due to silent corruption risks with ReFS.

The core goal remains the same: reducing the overhead of creating multiple worktrees from the same repository. The `--reflink` feature (patch 1/4) allows CoW worktree creation on supported filesystems (btrfs/XFS/bcachefs on Linux, APFS on macOS), avoiding full checkouts while carefully handling edge cases like dirty worktrees and untracked files. The implementation is cross-platform, using `FICLONE` (Linux), `clonefile()` (macOS), and `FSCTL_DUPLICATE_EXTENTS_TO_FILE` (Windows ReFS). However, patch 3/4 disables reflink on Windows entirely due to a known silent corruption bug (Git LFS #6312), while patch 4/4 ensures the reflink probe remains referenced to avoid build failures on mingw.

The ephemeral branch reaping feature (patch 2/4) automatically deletes branches created by `git worktree add` when the worktree is removed, addressing a long-standing cleanup nuisance. This remains controversial, as Eric Sunshine has argued it is redundant given the existing `--detach` flag and risks disrupting workflows that rely on auto-created branches.

Key changes since v2 include the addition of two new patches to handle Windows-specific issues, a rebase onto the latest `master`, and updated test coverage. The reflink implementation now emits a warning on Windows when `--reflink` or `worktree.reflink=true` is used, while `worktree.reflink=auto` silently falls back to regular checkouts. The macOS `clonefile()` path is validated in CI, and the series includes detailed documentation of limitations (e.g., overlayfs incompatibility, Windows ReFS corruption risk).

This series is well-motivated and addresses real-world scaling needs, but the reflink feature faces design-level scrutiny over its opt-in nature, and the ephemeral branch reaping remains contested. The Windows-specific changes in v3 reflect a pragmatic response to technical constraints, though they complicate the cross-platform story. The patches are under active review, and a v4 may follow to address remaining concerns.
