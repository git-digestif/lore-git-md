This is patch 12/13 in the SHA-1/SHA-256 interoperability series, implementing the ability to look up compatibility object IDs in packfiles. The patch extends the ODB "packed" source to support resolving object IDs in any supported hash algorithm (not just the repository's primary algorithm), which is essential for disambiguation and commands like `git rev-parse --output-object-format`.

The core change is in `odb/source-packed.c`, where the `for_each_prefixed_object_in_pack` function is refactored to iterate over all supported hash algorithms (not just the primary one). For each algorithm, it checks whether the algorithm matches the desired one (or if any algorithm is acceptable), whether the repository supports it (either as primary or compatibility), and whether the pack index is v3 or newer (older indices only store the primary algorithm's object IDs). The lookup then uses the new `nth_packed_object_id_algop` and `nth_packed_object_offset_algop` functions to retrieve object IDs and offsets for the requested algorithm.

The patch also adds `nth_packed_object_offset_algop` to `packfile.c` and `packfile.h`, a generalized version of `nth_packed_object_offset` that works with arbitrary hash algorithms. This function includes a safety check to prevent looking up compatibility object IDs in older (v1/v2) pack indices, which only store the primary algorithm's object IDs.

The test in `t1016-compatObjectFormat.sh` verifies that abbreviated compatibility object IDs can be resolved using pack index v3, but not with v2 indices. The test creates a repository, packs its objects with a v3 index, removes the loose object index, and confirms that `git cat-file` and `git rev-parse` can resolve the abbreviated compatibility object ID only after the v3 index is in place.
