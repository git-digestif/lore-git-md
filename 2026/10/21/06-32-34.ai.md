This is a refactoring patch in the SHA-1/SHA-256 interoperability series, specifically part of the ODB abstraction preparatory work. The patch renames `repo_add_loose_object_map()` to `source_add_loose_object_map()` to reflect its actual parameter type (`struct odb_source_loose *` instead of `struct repository *`). This is a mechanical change with no behavior or logic modifications, touching only function declarations, definitions, and call sites in `loose.c`, `loose.h`, and `odb/source-loose.c`.

The rename is motivated by the upcoming ODB abstraction effort, where the function will be reused in a context that does not involve a `struct repository`. The patch is a small but necessary step toward decoupling the loose object mapping infrastructure from the repository global state. It is well-scoped and uncontroversial, with no open questions or review feedback yet. The change is consistent with the series' broader goal of enabling pack index v3 and future ODB backends.
