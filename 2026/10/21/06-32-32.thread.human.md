This is the second iteration of a 13-patch series that extends Git’s pack index format to store object IDs in both SHA-1 and SHA-256, a key piece of the ongoing SHA-256 interoperability effort. The series was originally posted by Christian Couder and brian m. carlson, but Junio C Hamano flagged a procedural blocker: Christian’s `Signed-off-by` trailer was missing from patches he relayed unchanged from brian, violating the Developer Certificate of Origin. Christian has now resent the entire series with the required trailers added to every patch, clearing the blocker.

The implementation introduces pack index v3, which writes object IDs in both the primary and compatibility hash algorithms, enabling packed objects to be mapped between algorithms just as loose objects already can. The series also refactors the loose object mapping infrastructure to support Patrick Steinhardt’s ODB abstraction work, and it adds comprehensive test coverage for v3 index writing, reading, duplicate detection, and bounds checking. The on-disk format is documented in `gitformat-pack.txt`, and the code is rebased onto Patrick’s `ps/odb-files-alternates` topic to simplify ODB source handling. No substantive technical feedback has been posted yet—Junio’s review focused on the DCO issue and acknowledged the rebase and test improvements—so the series is now procedurally ready for queuing. It remains under review, with no indication of merge status to any integration branch. The only hiccup is a missing `--in-reply-to` flag, which means this v2 appears as a separate thread rather than a reply to the original v1 cover letter.
