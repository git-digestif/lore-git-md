This thread is the first iteration of a 13-patch series introducing **pack index v3** to support SHA-1/SHA-256 interoperability in Git. The series, co-authored by Christian Couder and brian m. carson, extends Git’s pack index format to store object IDs in both hash algorithms, enabling packed objects to be mapped between algorithms just as loose objects already can. This is a critical step in the broader SHA-256 interoperability effort, allowing repositories to operate with both hash algorithms simultaneously. The series also refactors the loose object mapping infrastructure to align with Patrick Steinhardt’s ongoing ODB abstraction work.

The latest patch (part 4 of 13) adds core ODB functions for mapping object IDs between hash algorithms and persisting those mappings. It introduces `odb_map_oid()` and `odb_write_oid_map()`, which are implemented for the "files" backend and its "loose" and "packed" sources. The "loose" source fully supports mapping and writing, while the "packed" source currently stubs out these functions, as pack index v3 support is deferred to later patches. The patch is foundational, enabling the ODB to handle interoperability mappings, though full functionality depends on subsequent patches in the series.

The series is under active review, with no feedback received yet. Key technical details include new functions, flags for controlling mapping behavior, and integration with the existing ODB abstraction. Open questions include missing test support for `GIT_TEST_DEFAULT_HASH=sha256:sha1`, limitations in automatic pack index v3 selection, and unresolved dependencies for computing compatibility object IDs in `index-pack`. The series builds on brian’s earlier interoperability work and is part of the broader effort to enable SHA-256 support in Git. No merge status has been reported.
