This thread is about extending Git’s pack index format to support SHA-1/SHA-256 interoperability, a key piece of the ongoing effort to allow repositories to operate with both hash algorithms. Christian Couder and brian m. carlson are the primary authors of this 13-patch series, now at its first iteration. The series introduces pack index v3, which stores object IDs in both the primary and compatibility hash algorithms, enabling efficient lookup and mapping between them.

The latest update, patch 9/13, adds support for *reading* pack index v3. It implements the core logic to parse and query the new format, including binary search on dual-sorted tables (for shortened and full object IDs) and updates to the pack reverse index to ensure correct offset resolution. The patch also refactors the hash lookup machinery to handle v3’s per-algorithm metadata, allowing graceful failure if an unsupported algorithm is queried. Tests in `t5302-pack-index.sh` are expanded to verify v3 functionality, and a bug in CRC offset calculation for v2 indices is fixed.

The series is still under review, with no feedback yet. Key technical details include the introduction of new functions (`bsearch_hash_v3`, `bsearch_hash_1`), structures (`formats` array in `packed_git`), and on-disk format changes (v3 indices with dual-algorithm support). Open questions remain, such as missing test support for `GIT_TEST_DEFAULT_HASH=sha256:sha1` and limitations around abbreviated compatibility object IDs and multi-pack indices. The series builds on brian’s earlier interoperability work and also prepares the ground for Patrick Steinhardt’s ODB abstraction effort.
