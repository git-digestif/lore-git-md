This thread is about extending Git’s pack index format to support SHA-1/SHA-256 interoperability, allowing packed objects to be mapped between hash algorithms just as loose objects already can. The series, now complete at 13 patches, is the work of Christian Couder and brian m. carlson and represents a critical step in Git’s ongoing SHA-256 interoperability effort. It also refactors loose object mapping infrastructure to support future ODB abstraction work.

The series introduces pack index v3, which stores object IDs in both the primary and compatibility hash algorithms, enabling efficient lookup by either. Key changes include new functions for mapping object IDs between algorithms, refactored loose object mapping logic, and support for writing, reading, and validating v3 indices. The final patch, just posted, moves the v3 format documentation from the hash function transition document to its canonical location in `gitformat-pack.adoc`, completing the series. No reviews have been posted yet, and the series remains under initial review with no merge status reported.

The work touches core subsystems like packfile handling, object storage, and ODB abstraction, and includes new tests to verify v3 index behavior. Open questions include missing test support for certain compatibility configurations, the lack of automatic v3 index selection, and limitations in dependency mapping and abbreviated object ID resolution. The series builds on brian’s earlier interoperability work and is a preparatory step for Patrick Steinhardt’s ODB abstraction effort.
