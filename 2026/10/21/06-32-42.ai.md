This is patch 10/13 of the SHA-1/SHA-256 interoperability series, adding **validation for pack index v3 tables** to prevent reading outside the index file if it is corrupt or maliciously crafted. The patch is a critical safety measure for the new v3 format introduced earlier in the series.

The validation checks several aspects of the v3 index structure:
- Header length and trailer offset must match the file size.
- The number of formats must be valid (1 ≤ num_formats ≤ GIT_HASH_NALGOS).
- Each format entry must have a valid algorithm ID, non-zero short name length (≤ full object ID length), and table offsets within bounds.
- Duplicate format entries are rejected.
- Order map entries (used to map pack order to object ID order) are checked when read, ensuring they reference valid object positions.
- 8-byte offsets in the pack reverse index are verified to lie within the index.

The patch updates four files:
- `hash-lookup.c`: Adds bounds checking for order map entries in `bsearch_hash_v3`.
- `pack-revindex.c`: Validates 8-byte offset pointers before dereferencing.
- `packfile.c`: Extends `load_idx` with comprehensive v3 header and table validation, replacing earlier minimal checks.
- `t/t5313-pack-bounds-checks.sh`: Adds a new test case for detecting invalid order map entries.

The validation is thorough and addresses potential corruption vectors without significantly impacting performance (order map checks are deferred until lookup). The test coverage is appropriate, targeting a specific edge case that could lead to out-of-bounds reads. This is a well-crafted safety layer for the new v3 format, and the patch itself is clean and focused. No review feedback has been posted yet.
