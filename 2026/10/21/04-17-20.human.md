This is a **security bugfix** targeting Git’s SSH signing verification. The patch closes a critical flaw: when `gpg.ssh.revocationFile` is configured but missing, Git warns and proceeds as if no revocation file exists (failing open), rather than failing verification (failing closed). The fix aligns Git’s behavior with OpenSSH’s security model and the GPG backend, which already fail closed on revocation file issues.

The patch is well-motivated and clearly explained. It changes the default behavior to fail verification when the revocation file is missing, while preserving an escape hatch via Git’s `:(optional)` pathname prefix (e.g., `:(optional)/path/to/revocation`). This matches the design consensus reached in the thread, where Phillip Wood and Patrick Steinhardt endorsed making revocation errors fatal by default. The commit message documents the breaking change: setups with misconfigured paths will now fail verification instead of silently skipping revocation checks.

Code changes are minimal and focused. The patch removes the warning-and-continue logic in `gpg-interface.c`, replacing it with an explicit error return. It also updates `Documentation/config/gpg.adoc` to clarify the new behavior and the `:(optional)` escape hatch. Test coverage is thorough: the patch adds four new test cases in `t/t7528-signed-commit-ssh.sh`, covering revoked keys, missing files, and the `:(optional)` prefix.

The patch carries `Suggested-by` and `Helped-by` trailers from Patrick Steinhardt and Phillip Wood, signaling their involvement in shaping the fix. This is a clear security regression with a straightforward, well-tested solution, so it’s likely to land quickly. The only remaining loose end from the thread—the `valid-before` timestamp confusion—was already addressed in a separate documentation patch, so this patch completes the fixes for both reported flaws.
