This is the fifth patch in Patrick Steinhardt’s seven-patch v2 series introducing the **object storage extension**, a foundational step toward pluggable object database backends in Git. This patch adds user-facing configuration and command-line support for the object storage format to `git init`, mirroring the existing options for the ref storage extension.

The patch introduces the `--object-storage-format=<format>` option to `git init`, allowing users to specify the object storage backend (e.g., `files://objs` to relocate objects to `.git/objs`). It also adds the `init.defaultObjectStorageFormat` configuration key and documents the `GIT_DEFAULT_OBJECT_STORAGE_FORMAT` environment variable, both of which set the default format for new repositories. The implementation follows Git’s standard precedence rules: command-line options override environment variables, which override configuration, which in turn override the default (`files`).

The patch is **mechanical and correct**, reusing the validation and URI-parsing logic introduced in earlier patches. It updates `setup.c` to handle the new option, ensuring the chosen format is recorded in the repository’s configuration (unless it is the default `files` backend without a payload). Tests cover initialization with relative and absolute paths, environment variable overrides, invalid format handling, and reinitialization with mismatched storage formats. The patch also disables the extension when the format is `files` without a payload, preserving backward compatibility.

This patch is **not controversial** and appears ready for integration. It completes the user-facing configuration story for the object storage extension, enabling users to set the backend at repository creation time. The only open design question from earlier patches—whether to normalize relative paths to absolute paths—does not affect this patch, as it defers to the backend’s URI parsing logic. The patch is well-tested and aligns with the established pattern for the ref storage extension.
