This is the third patch in Patrick Steinhardt’s v2 series introducing the **object storage extension** (`extensions.objectStorage`), a foundational step toward pluggable object database backends in Git. This patch adds environment variable support (`GIT_OBJECT_STORAGE_FORMAT`) to override the configured object storage backend, mirroring the existing `GIT_REF_STORAGE_FORMAT` mechanism for ref storage.

The patch is **mechanical and uncontroversial**, following an established pattern. It extends the repository setup machinery in `setup.c` to check for the new environment variable and validate its value using the existing `odb_source_type_by_uri()` helper. The variable takes the same URI format as the config key (`<schema>[://<payload>]`, e.g., `files://objs`), and the patch ensures it overrides the `extensions.objectStorage` configuration when set. Documentation is updated in `git.adoc` to describe the variable, and a new test in `t0001-init.sh` verifies the override behavior, including error cases (invalid formats) and payload handling (e.g., switching from `files://objs` to `files://other`).

The implementation is **minimal and correct**: it reuses the same validation logic as the config key, avoids duplicating code, and maintains consistency with the ref storage extension. The test coverage is thorough for the new functionality, though it does not exhaustively test all possible combinations of environment variables and config keys (a point raised in v1 review but deemed non-blocking). No behavioral changes are introduced beyond the new override capability, and the patch does not touch core object storage logic or on-disk formats.

This patch is **ready for merging** as part of the series, assuming the rest of the series holds up. It addresses a key usability requirement (environment variable overrides) and aligns with Git’s existing configuration precedence rules. The only potential discussion point is whether the test coverage should be expanded to include more edge cases (e.g., empty payloads, relative paths), but the current tests are sufficient for the patch’s scope. The patch is a **clean, incremental addition** to the series’ overall goal of enabling pluggable object storage.
