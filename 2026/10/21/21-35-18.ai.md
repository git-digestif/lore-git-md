This is the third patch in a three-patch bugfix series targeting the checkout and branch subsystems. It completes the series' goal of ensuring `git switch -c` and `git checkout -b` finish the switch even when the tracking configuration cannot be written (e.g., due to a locked config file).

The patch modifies `builtin/checkout.c` to ignore the error returned by `create_branch()` when tracking config fails, allowing the switch to complete and the command to exit with status 0. The error and hint are still printed, matching the behavior of `git push -u`, `git clone`, and `git fetch`. The commit message explicitly notes that `git branch` is intentionally left failing to preserve its current behavior, and that making the switch fully atomic is a separate topic.

Key technical details:
- Files touched: `builtin/checkout.c` and three test files (`t/t2027-checkout-track.sh`, `t/t2060-switch.sh`, `t/t3200-branch.sh`).
- New behavior: `git switch -c` and `git checkout -b` now complete the switch (updating HEAD, worktree, and index) and exit with status 0 even if tracking config cannot be written. The hint message is still shown.
- Old behavior: the command would exit with status 1, leaving HEAD on the old branch while updating the worktree and index.
- Test coverage: the patch adds comprehensive tests for both `git switch` and `git checkout` scenarios, verifying that HEAD is updated, the worktree is clean, and the tracking config is not written. The tests also confirm the error message is printed.
- Subsystems: checkout/switch (worktree and HEAD updates).
- Symbols: `create_branch()` now returns an error code (refactored in patch 2/3), which this patch ignores in the checkout context.

The patch is well-motivated and aligns with the consensus from the bug report thread. The implementation is minimal and focused, and the test coverage is thorough. The commit message clearly explains the rationale and the scope of the change. This looks like a clean, uncontroversial fix for a real usability issue. The series as a whole is now complete and ready for final review.
