This is a **bugfix and portability patch series** targeting 64-bit Windows (LLP64) compatibility. The series addresses three remaining places where Git silently truncates or misbehaves with files larger than 4 GiB due to `unsigned long` being only 32 bits wide on that platform.

The patches convert three APIs to use `size_t` instead of `unsigned long` for object and buffer sizes: the object database write path (continuing Johannes Schindelin’s earlier work), the word-diff buffer allocation in the diff machinery (building on Jeff King’s `jk/xdiff-size_t` series), and the file conversion helpers (which affect `core.autocrlf` and keyword expansion). Without these changes, Git either truncates large blobs without error, crashes on allocation overflow, or only examines a prefix of files over 4 GiB.

Elia explains the motivation clearly and provides a reproducible method for finding these truncation sites using a MinGW cross-compilation setup and clang-tidy. The commit messages describe how to trigger each bug in practice, though no new tests are included due to the impracticality of creating multi-gigabyte test files. The changes are mechanical and confined to type signatures and local casts, with no behavior change on platforms where `long` and `size_t` have the same width.

The series looks well-motivated and narrowly scoped. It picks up known loose ends from prior portability work and should be uncontroversial. No cover letter was provided earlier, so this is the first public appearance of the series.
