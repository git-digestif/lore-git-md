This is patch 5/13 in the SHA-1/SHA-256 interoperability series, implementing a key refactoring in the object ID mapping infrastructure. The patch replaces the direct use of `repo_loose_object_map_oid()` in `repo_oid_to_algop()` with a call to the new ODB-level function `odb_map_oid()`, introduced in patch 4. This change centralizes the mapping logic under the ODB abstraction, reducing code duplication and paving the way for future backend-agnostic mapping operations.

The patch deletes 12 lines of code, removing the manual fallback logic that reloaded the loose object map if the initial lookup failed. That logic is now handled inside `odb_map_oid()`, which checks all object directories (main and alternates) and reloads loose object maps as needed. The change is functionally equivalent but shifts responsibility for reloading and retrying to the ODB layer, where it belongs. The commit message notes that `repo_oid_to_algop()` is retained because it performs cleanup tasks that should not be exposed to the ODB backend.

This is a clean refactoring that aligns with the series' goal of abstracting object ID mapping behind the ODB interface. The patch is small and focused, touching only `object-file-convert.c` and introducing no new behavior or edge cases. It builds directly on the ODB mapping infrastructure added in patch 4, and its correctness depends on that infrastructure working as intended. No new tests are introduced, but the existing test coverage in `t1016-compatObjectFormat.sh` and related scripts should catch any regressions. The patch is uncontroversial and looks ready for integration.
