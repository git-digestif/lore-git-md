This is a follow-up patch in the RFC thread proposing `--merged` and `--no-merged` filters for `git worktree list`. The patch implements the feature as described in the parent email, with no substantive changes to the design or open questions.

The implementation is complete and self-contained: it adds the two new options to `git worktree list`, reuses the existing `ref_filter` machinery for parsing and reachability checks, and includes thorough tests covering edge cases (unborn branches, broken worktrees, bare repositories, porcelain output, and error conditions). The code is clean and follows Git conventions, with no obvious red flags.

Key technical details remain unchanged from the parent email: the filters apply strict reachability checks to each worktree’s HEAD, default to the current worktree’s HEAD, and omit worktrees without a valid HEAD commit. The patch does not attempt to handle squash-merged or rebase-merged topics, and removal remains a separate step.

The only new information here is the full implementation and test suite, which confirm the feature’s viability. The open questions from the RFC (default commit, main worktree filtering, future `remove --merged`) are still unresolved, but this patch provides a working baseline for discussion. The patch looks ready for review and is unlikely to be controversial on technical grounds.
