This is the final patch in the six-part series introducing an **incremental connectivity check** for Git fetches and pushes. It adds the **"auto" mode**, which dynamically selects between the new incremental check and the traditional full check based on the size of the incoming history.

The patch implements a **configurable heuristic**: when `transfer.connectivityCheck` is set to `auto` (or `auto=<n>`), Git uses the incremental check for up to 1,000 incoming commits (configurable via `<n>`) and falls back to the full check beyond that. This addresses the performance trade-off identified in earlier patches—where incremental mode is faster for small pushes but slower for large ones—without requiring users to manually choose a mode. Benchmark data from real repositories (Linux, Git itself, and two internal repos) shows the 1,000-commit cutoff balances performance well, with incremental mode being 2–2.8x faster for medium-sized pushes and full mode avoiding regressions for large ones.

The implementation is clean and self-contained. The `rev-list` subprocess now counts incoming commits (cheap when the walk is limited) and switches modes at runtime. The patch also handles edge cases like malformed cutoffs (falling back to full mode with a warning) and preserves existing behavior for clones, empty-repo pushes, and deepening fetches. Tests cover the new mode thoroughly, including cutoff enforcement and fallback scenarios.

This patch completes the series, which is now **ready for integration**. All prior feedback has been addressed, and the design—particularly the three-mode config (`full`/`incremental`/`auto`)—has been shaped by substantive reviews from **Junio C Hamano** and **Patrick Steinhardt**. The only remaining loose end is the stack overflow risk in recursive tree verification, which the author plans to address in a follow-up. The series is well-motivated, thoroughly tested, and delivers a meaningful performance improvement for a common use case (small pushes to large repos) while maintaining safety and compatibility.
