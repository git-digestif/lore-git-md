This is a bug report about partial clones. The author describes a scenario where a merge in a partial clone (using `--filter=blob:none`) fails with a "not our ref" error from the remote, even though the problematic blob was created locally during the merge. The error occurs when Git attempts to fetch the locally generated blob from the promisor remote, which naturally doesn’t have it. The author provides a minimal reproducer script that demonstrates the issue, showing that the same merge succeeds without the blob filter.

The report is clear and well-structured, with a self-contained script that makes the issue easy to reproduce. The problem appears to be a real edge case in how Git handles locally created blobs during merges in partial clones, and the error message suggests a miscommunication between the client and the promisor remote. This is likely worth attention from contributors familiar with the partial-clone or promisor-remote subsystems. The author’s use of an LLM to help reduce the reproducer doesn’t detract from the validity of the issue—it’s still a concrete, actionable report.
