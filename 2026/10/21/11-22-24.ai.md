This is the **final patch (6/6) in the six-patch series introducing incremental connectivity checks for Git fetches and pushes**, completing the feature by adding the **"auto" mode** that dynamically chooses between the full and incremental checks based on the size of the incoming history. The patch implements the **three-mode config design** (`full`/`incremental`/`auto[=<n>]`) with a **configurable 1,000-commit cutoff** (default), allowing users to opt into the performance benefits of incremental checks without manually tuning the threshold.

The patch adds **~60 lines of code** across five files, primarily in `builtin/rev-list.c` and `connected.c`, to implement the heuristic: when the revision walk is limited (i.e., the receiving repository has references), the incoming commit list is already computed by `limit_list()`, so counting it is cheap. The "auto" mode then uses the incremental check for up to the configured cutoff (1,000 by default) and falls back to the full check above that. The cutoff is **conservative** (benchmarks show breakeven between 500 and 3,000 commits) but works well across repository sizes, including large monorepos with hundreds of thousands of files. The patch also updates the test suite (`t/t5413-connectivity-check.sh`) to verify the dynamic fallback behavior, including edge cases like malformed cutoffs and pushes into empty repositories.

The implementation is **clean and self-contained**, reusing the existing `revs.commits` list to avoid additional overhead. It preserves the **fallback logic** from earlier patches (e.g., deepening fetches, promisor objects) and maintains **backwards compatibility** by treating unknown values as "full" with a warning. The **configurable cutoff** (`auto=<n>`) allows future adjustments without breaking changes, addressing Patrick Steinhardt’s concern about generalization. The patch is **well-tested**, with new test cases covering the dynamic mode selection and cutoff behavior, and it **integrates smoothly** with the rest of the series, which is now complete and ready for integration.
