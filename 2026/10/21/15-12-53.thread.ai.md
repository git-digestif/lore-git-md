Subject: [PATCH v2] rev-list: fix `--grep` parsing when followed by another option
Series version: standalone patch, v3 (anticipated)
Originating author: Azuama Odinaka Maximus
Thread type: bugfix patch

Core problem or goal
The `git rev-list` command misparses a `--grep` argument that is immediately followed by another option (e.g., `--missing-only`). The parser treats the next argument as a separate flag rather than as the grep pattern, causing the command to fail or behave unpredictably. The patch ensures that `--grep` is handled early in the argument scan so that the following argument is always treated as the pattern, even if it begins with `--`.

Current status
Under review; third version anticipated. The patch remains a minimal two-line change in `builtin/rev-list.c` that increments the argument index when `--grep` is encountered. The test suite (`t/t6022-rev-list-missing.sh`) includes two new tests: one verifying `--grep` can accept a pattern starting with `--` (e.g., `--grep --missing-only` produces the same output as `--grep=--missing-only`), and another confirming the fix works during the first argument scan (e.g., `--grep --exclude-promisor-objects`). No merge status change; still under review.
