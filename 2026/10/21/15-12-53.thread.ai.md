Subject: [PATCH v2] rev-list: fix `--grep` parsing when followed by another option
Series version: standalone patch, v3 (anticipated)
Originating author: Azuama Odinaka Maximus
Thread type: bugfix patch

Core problem or goal
The `git rev-list` command misparses a `--grep` argument that is immediately followed by another option (e.g., `--missing-only`). The parser treats the next argument as a separate flag rather than as the grep pattern, causing the command to fail or behave unpredictably. The patch ensures that `--grep` is handled early in the argument scan so that the following argument is always treated as the pattern, even if it begins with `--`.

Current status
Under review; third version anticipated. The patch remains a minimal two-line change in `builtin/rev-list.c` that increments the argument index when `--grep` is encountered. The test suite (`t/t6022-rev-list-missing.sh`) currently includes two new tests that Junio C Hamano has identified as insufficient: they verify the command does not fail but do not confirm the grep pattern was applied. No merge status change; still under review.

Key technical details
- Files touched: `builtin/rev-list.c`, `t/t6022-rev-list-missing.sh`
- New test names (proposed): `rev-list --grep handles pattern starting with --`, `rev-list --grep works in first argument scan`
- Behavior change: `--grep` now correctly consumes the next argument as the pattern, regardless of whether it begins with `--`
- No on-disk format changes; no new symbols introduced
- Test flaw: tests pass even when the grep pattern is ignored because no commit message in the test history contains the pattern (`--missing-only` or `--exclude-promisor-objects`)
