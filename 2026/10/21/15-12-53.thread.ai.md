Subject: [PATCH v4] rev-list: fix `--grep` and related option parsing when followed by another option
Series version: standalone patch, v4
Originating author: Azuama Odinaka Maximus
Thread type: bugfix patch

Core problem or goal
The `git rev-list` command misparses any of the 18 `parse_long_opt()`-style options (`--grep`, `--author`, `--committer`, `--since`, `--until`, etc.) when the option is immediately followed by another argument that begins with `--`. The parser treats the next argument as a separate flag rather than as the option's value, causing the command to fail or behave unpredictably. The patch ensures these options are handled early in the argument scan so that their following arguments are always treated as values, even if they begin with `--`.

Current status
Under review; fourth version posted. The patch is a targeted refactor in `builtin/rev-list.c` that introduces a helper function, `rev_list_option_takes_argument()`, to recognize all 18 affected options during the early option scan and skip their arguments. The test suite (`t/t6022-rev-list-missing.sh`) includes five new tests verifying that `--grep` and `--author` patterns beginning with `--` are correctly applied. No merge status change; still under review.

Key technical details
- Files touched: `builtin/rev-list.c`, `t/t6022-rev-list-missing.sh`
- New helper function: `rev_list_option_takes_argument()` identifies the 18 options that take arguments

- Behavior change: all 18 options now correctly consume their next argument as the value, regardless of whether it begins with `--`

- Test hygiene: all new test code now uses tabs for indentation

- No on-disk format changes; no new symbols introduced beyond the helper function
