Subject: [PATCH v4] rev-list: fix `--grep` and related option parsing when followed by another option
Series version: standalone patch, v4
Originating author: Azuama Odinaka Maximus
Thread type: bugfix patch

Core problem or goal
The `git rev-list` command misparses any of the 18 `parse_long_opt()`-style options (`--grep`, `--author`, `--committer`, `--since`, `--until`, etc.) when the option is immediately followed by another argument that begins with `--`. The parser treats the next argument as a separate flag rather than as the option's value, causing the command to fail or behave unpredictably. The patch aims to ensure these options are handled early in the argument scan so that their following arguments are always treated as values, even if they begin with `--`.

Current status
Under review; fourth version posted. The patch is a targeted refactor in `builtin/rev-list.c` that introduces a helper function, `rev_list_option_takes_argument()`, to recognize all 18 affected options during the early option scan and skip their arguments. The test suite (`t/t6022-rev-list-missing.sh`) includes five new tests verifying that `--grep` and `--author` patterns beginning with `--` are correctly applied. **Maintainer review (Junio C Hamano) has identified a critical architectural flaw**: the hardcoded list of 19 option strings in the helper function duplicates parser logic and is already incomplete (missing `--diff-merges`, `--src-prefix`, `--dst-prefix`, etc.), creating a maintenance hazard. The patch is not ready for merging in its current form; the author must propose a more robust solution.

Open questions and loose ends
- **Architectural flaw**: The hardcoded list of options in `rev_list_option_takes_argument()` is fragile and incomplete. A more maintainable approach is needed, such as:
  - Dynamically querying the option parser for which options take arguments, or
  - Refactoring the early option scan to avoid duplicating knowledge of option semantics.
- **Scope of the fix**: The maintainer’s example (`git rev-list --src-prefix --missing-only HEAD`) suggests the problem may extend beyond the 18 options currently addressed. The fix must either:
  - Clearly document its limitations (e.g., only handling `rev-list`-specific options), or
  - Be expanded to cover all options that could appear in `rev-list` invocations.
- **No new tests or edge cases** were requested by the maintainer, but the architectural concern may necessitate revisiting test coverage to ensure the revised approach handles all cases correctly.

Key technical details
- Files touched: `builtin/rev-list.c`, `t/t6022-rev-list-missing.sh`
- New helper function: `rev_list_option_takes_argument()` (now problematic due to hardcoded list)
- New test names: `rev-list --grep handles pattern starting with --`, `rev-list --grep works in first argument scan`, `rev-list --author handles pattern starting with --`, plus two additional tests for edge cases (`-n`, `--default`, `--` terminator)
- Behavior change: all 18 options now correctly consume their next argument as the value, regardless of whether it begins with `--`
- Documentation: the NEEDSWORK comment above the loop has been updated to remove the now-fixed `--grep --exclude-promisor-objects` example and replace it with a general warning about the early scan's limitations
- Test hygiene: all new test code uses tabs for indentation
- Special cases: the patch explicitly handles `-n` and `--default` and stops scanning at `--` to avoid treating pathspecs as options
- No on-disk format changes; no new symbols introduced beyond the helper function
