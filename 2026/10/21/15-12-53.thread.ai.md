Subject: [PATCH] rev-list: fix `--grep` parsing when followed by another option
Series version: standalone patch (no series)
Originating author: Azuama Odinaka Maximus
Thread type: bugfix patch

Core problem or goal
The `git rev-list` command misparses a `--grep` argument that is immediately followed by another option (e.g., `--missing-only`). The parser treats the next argument as a separate flag rather than as the grep pattern, causing the command to fail or behave unpredictably. The patch ensures that `--grep` is handled early in the argument scan so that the following argument is always treated as the pattern, even if it begins with `--`.

Current status
Under review; no prior versions. The patch is a minimal two-line change in `builtin/rev-list.c` that increments the argument index when `--grep` is encountered, plus a new test in `t/t6222-rev-list-missing.sh` that verifies `--grep` can accept a pattern starting with `--` (e.g., `--grep --missing-only` produces the same output as `--grep=--missing-only`).

Key technical details
- Files touched: `builtin/rev-list.c`, `t/t6222-rev-list-missing.sh`
- New test name: `rev-list --grep handles pattern starting with --`
- Behavior change: `--grep` now correctly consumes the next argument as the pattern, regardless of whether it begins with `--`
- No on-disk format changes; no new symbols introduced
