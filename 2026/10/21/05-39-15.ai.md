This is the second patch in Patrick Steinhardt’s v2 series introducing the **object storage extension**, a foundational step toward pluggable object database backends in Git. This patch implements the core configuration mechanism (`extensions.objectStorage`) and integrates it into the repository setup machinery.

The patch adds the `extensions.objectStorage` configuration key, which accepts a URI in the format `<schema>[://<payload>]` (e.g., `files://objs`). The schema identifies the backend (currently only `files` is supported), and the payload is backend-specific. For the `files` backend, the payload specifies an alternative location for the `.git/objects` directory, either as an absolute path or relative to `$GIT_COMMON_DIR`. The implementation mirrors the existing `extensions.refStorage` pattern, ensuring consistency in how Git handles pluggable backends.

Key changes include:
- **New symbols**: `repo_set_object_storage_format()` (to set the storage URI in `struct repository`), `odb_source_type_by_uri()` (to parse the URI into a schema and payload), and updates to `odb_source_new()` to accept the storage format.
- **Struct field**: `object_storage_format` in `struct repository`, now always initialized (defaulting to `"files"` in this patch, though later patches ensure it is set during repository initialization).
- **Setup integration**: The `handle_extension()` function in `setup.c` is extended to validate and store the `extensions.objectStorage` value, and `apply_repository_format()` propagates it to the repository object.
- **Documentation**: Updates to `Documentation/config/extensions.adoc` and a new `Documentation/object-storage-format.adoc` file describing the `files` backend and its payload semantics.
- **Tests**: New tests in `t0001-init.sh` verify that the extension is rejected in repository version 0, works with the `files` backend, and properly rejects unknown schemas.

The patch is **well-structured and uncontroversial**, following established patterns for ref storage and addressing a clear technical need. The commit message is thorough, and the code is cleanly separated into logical changes (configuration parsing, repository setup, and backend integration). The only open design question from v1—whether to normalize relative paths to absolute paths—was deferred to avoid breaking tests, but this is not a blocker. The patch is ready for deeper technical review, particularly around edge cases in URI parsing and payload handling.
