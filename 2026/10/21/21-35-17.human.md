This is the second patch in a three-patch bugfix series targeting `git switch` and `git branch` usability issues. The patch refactors `setup_tracking()` to return an error code instead of calling `exit(1)` when it cannot write tracking configuration. This is a necessary preparatory step for the third patch, which will allow `git switch -c` and `git checkout -b` to complete the branch switch even if tracking setup fails.

The change is mechanical and focused: `setup_tracking()`, `create_branch()`, and `dwim_and_setup_tracking()` are all converted from `void` to `int` return types, propagating the error code up the call stack. The patch does not alter behavior—callers still exit with status 1 on failure, as before—but it enables the next patch to handle the error more gracefully.

Files touched are `branch.c`, `branch.h`, `builtin/branch.c`, and `builtin/checkout.c`. The refactoring is minimal and does not introduce new logic or edge cases. The commit message is clear about the purpose and scope of the change, though it cuts off abruptly at the end ("Changing checkout").
