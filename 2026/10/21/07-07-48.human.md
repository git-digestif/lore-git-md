This is the first patch in a two-part bugfix series for `git imap-send`. It plugs a minor memory leak in the tunnel-command handling when `imap.tunnel` is configured. The leak occurs because the `child_process` struct used to start the tunnel is never released after the tunnel is running—only its pipes are retained. The fix is a one-line addition to call `child_process_clear()` immediately after the tunnel is started, freeing the argument list and other resources.

The change is straightforward and uncontroversial: it touches only `imap-send.c` and adds no new behavior. The leak is not currently caught by tests because no existing test sets `imap.tunnel`, but it would be flagged by valgrind. This patch is a cleanup that stands on its own, though its primary value is as a prerequisite for the more substantial header-parsing fix in patch 2/2.

The series as a whole targets a real interoperability issue with tools like `b4` that produce non-canonical email header order (e.g., `Subject` before `Date`). This patch doesn’t address that problem directly, but it ensures the codebase is tidy before the more complex changes land. The fix is well-motivated and ready for integration.
