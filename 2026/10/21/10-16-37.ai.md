This is the first patch in Elia Pinto’s three-patch series fixing 64-to-32 truncations on Windows (LLP64 platforms). It mechanically widens the object-database write path from `unsigned long` to `size_t` so that blobs larger than 4 GiB are written in full instead of silently truncated. The change touches five files (`odb.c`, `odb.h`, `odb/source-inmemory.c`, `odb/source-loose.c`, `odb/source.h`) and is a pure type conversion with no new symbols or behavior change on 64-bit Linux. On Windows it prevents data corruption when `git add` or `git hash-object -w` processes a file over 4 GiB that requires filtering (autocrlf, eol/ident attributes, or clean filters). The commit message explains the silent truncation, the mismatch between `hash-object` and `hash-object -w`, and why no new test is added (reproduction requires a 5 GiB file and a 32-bit `long` environment). The patch builds directly on Johannes Schindelin’s earlier read-side work (c6a4629e32) and is uncontroversial in scope.
