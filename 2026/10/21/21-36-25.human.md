This is a surface-level reply to Jasper Mayone’s RFC proposing `--merged` and `--no-merged` filters for `git worktree list`.

Harald Nordgren steps back from the specific patch and questions the broader design of Git’s worktree system. He points out that Git currently prevents checking out a branch that is already checked out in another worktree, calling the restriction “a bit ridiculous” because two separate clones of the same repository would not enforce such a rule. The comment is brief and does not engage with the implementation or the open questions Jasper raised; it simply flags a perceived inconsistency in how worktrees behave compared to independent repositories. No alternative design or code is proposed.
