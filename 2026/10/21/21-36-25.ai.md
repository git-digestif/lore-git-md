This is a surface-level review reply in the ongoing `git worktree list --merged` RFC thread.

Harald Nordgren steps back from the specific patch to question a broader design choice: Git currently prevents checking out a branch that is already checked out in another worktree. He calls this restriction "a bit ridiculous" because two separate clones of the same repository would not enforce it, and speculates that the growing popularity of worktrees (and AI-assisted workflows) will make this limitation more noticeable.

The comment is brief and does not engage with the implementation details of the `--merged`/`--no-merged` filters. It instead invites the list to reconsider whether the one-branch-per-worktree rule should be relaxed or made configurable. No alternative design or code is proposed.
