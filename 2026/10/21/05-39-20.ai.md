This is the final patch in Patrick Steinhardt’s seven-part series introducing the **object storage extension** (`extensions.objectStorage`), a foundational step toward pluggable object database backends in Git. This patch completes the series by propagating the `--object-storage-format=` option through `git submodule add` and `git submodule update`, ensuring that submodules inherit the parent repository’s object storage configuration.

The implementation is mechanical and follows the established pattern for the ref storage extension (which already supports `--ref-storage-format=`). The patch adds the `--object-storage-format` option to both subcommands, validates the format using the existing `odb_source_type_by_uri()` helper, and passes the value through to the underlying `git clone` invocations. Documentation updates to `git-submodule.adoc` mirror the ref storage extension’s wording, and a new test script (`t7427-submodule-object-storage-format.sh`) verifies that submodules correctly inherit the format during `add`, `update`, and recursive clone operations.

The patch is **uncontroversial and correct**: it reuses the validation logic and error handling introduced in earlier patches, maintains consistency with the ref storage extension, and includes thorough test coverage for edge cases (e.g., invalid formats, recursive propagation, and path relocation). The only behavioral change is the addition of the new option, which has no effect unless explicitly specified. No substantive review feedback has been recorded for this patch, but given the series’ architectural alignment with prior work and the completeness of the implementation, it appears ready for integration.

This patch is the last piece needed to make the object storage extension fully usable in multi-repository workflows. With it, the series achieves its goal of providing a consistent, inspectable, and configurable mechanism for object storage backends across all Git commands that create or update repositories.
