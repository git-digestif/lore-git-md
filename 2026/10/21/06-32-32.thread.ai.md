Thread identity: SHA-1/SHA-256 interoperability – pack index v3 support. Series version: v1 (13 patches). Originating authors: Christian Couder and brian m. carlson. Thread type: patch series.

Core problem or goal: Extend Git’s pack index format to store object IDs in both the primary and compatibility hash algorithms, enabling packed objects to be mapped between algorithms just as loose objects already can. This is a critical component of the SHA-256 interoperability effort, allowing repositories to operate with both hash algorithms simultaneously. The series also refactors the loose object mapping infrastructure to support future ODB abstraction work.

Current status: Under review. This is the first iteration of the series, posted as [PATCH 0/13]. No prior versions of this specific series exist, though it builds on brian m. carlson’s earlier interoperability work (notably the loose object mapping infrastructure). No merge status to any integration branch has been reported.

- **On-disk format changes**: Introduces pack index v3, which stores object IDs in both the primary and compatibility hash algorithms. The format includes metadata for both hash algorithms (e.g., abbreviated object name lengths, table offsets) and ensures 32-bit alignment for performance. Documented in `gitformat-pack(5)` (patch 13).
- **Behavior changes**:
  - Pack index v3 writing is implemented in `pack-write.c` (patch 6), but not yet enabled by default. The code maintains three sorted arrays (pack order, primary object ID, compatibility object ID) to enable efficient lookup by either algorithm.
  - Duplicate detection in `--strict` mode now checks both primary and compatibility object ID arrays.
  - Patch 1 refactors `repo_loose_object_map_oid()` to delegate lookup logic to `source_loose_object_map_oid()`, enabling reuse in ODB abstraction contexts.
  - Patch 3 extends `source_add_loose_object_map()` with a `flags` parameter (`OBJ_MAP_WRITE`) to control whether mapped object IDs are written to disk immediately.
  - Patch 4 introduces ODB-level functions (`odb_map_oid`, `odb_write_oid_map`) for mapping object IDs between algorithms, with the "files" backend delegating to "loose" and "packed" sources. The "loose" source implements both mapping and writing; the "packed" source stubs these functions (returning -1) pending pack index v3 support.
  - Patch 5 refactors `repo_oid_to_algop()` to use `odb_map_oid()`, centralizing mapping logic under the ODB abstraction and removing manual fallback logic for reloading loose object maps.
  - Patch 6 implements pack index v3 writing, including header format, sorting logic, padding calculation, and duplicate detection.
  - Patch 7 implements core logic to populate compatibility object IDs in pack index v3 during indexing. Key changes:
    - Adds a mutex (`repo_mutex`) in `builtin/index-pack.c` to protect thread-unsafe modifications to the loose object map during threaded operations.
    - Extends `unpack_entry_data()` and `unpack_raw_entry()` to compute and store compatibility object IDs alongside primary object IDs. For blobs, hashes content simultaneously for both algorithms; for other object types, converts the object to the compatibility algorithm before hashing.
    - Modifies `resolve_delta()` to compute compatibility object IDs for delta objects and store them in the loose object map (without writing to disk to avoid polluting the loose object index).
    - Updates `cmd_index_pack()` to accept pack index version 3 as valid.
    - In `builtin/pack-objects.c`, ensures compatibility object IDs are computed and stored when creating object entries, failing if an object cannot be mapped.
  - Patch 8 fixes a critical bug where streaming large blobs directly into a pack (bypassing the loose object store) would store null OIDs for the compatibility algorithm in the pack index. Key changes:
    - Extends `stream_to_pack()` in `object-file.c` with an optional `compat_ctx` parameter to update both primary and compatibility hash contexts during streaming.
    - Modifies `odb_transaction_files_write_object_stream()` to initialize the compatibility hash context, finalize the compatibility object ID after streaming, and store it in the `compat_oid` field of `pack_idx_entry`.
  - Patch 9 implements support for reading pack index v3. Key changes:
    - Extends `packfile.c` to parse and query v3 indices, including validation of header fields (e.g., `num_formats` against `GIT_HASH_NALGOS`).
    - Introduces `bsearch_hash_v3` in `hash-lookup.c` to perform binary search on v3’s dual-sorted tables (shortened and full object IDs).
    - Updates the pack reverse index (`pack-revindex.c`) to use the v3 order map when iterating over objects.
    - Fixes a bug in `pack-check.c` where CRC offset calculation was hardcoded for v2 indices.
    - Updates `t5302-pack-index.sh` to generate and verify v3 indices, with conditional execution to skip older index versions when a compatibility hash is in use.

Open questions and loose ends:
- **Missing test support**: The test suite cannot yet run with `GIT_TEST_DEFAULT_HASH=sha256:sha1` due to missing support for parsing `<algo>:<compat>` in `GIT_DEFAULT_HASH`.
- **Automatic selection**: Pack index v3 is not yet automatically selected in compatibility repositories; this is noted as a limitation.
- **Dependency mapping**: `index-pack` cannot compute compatibility object IDs for objects whose dependencies lack mappings. This is addressed in brian’s full `sha256-interop` branch but remains a limitation here.
- **Abbreviated compatibility object IDs**: Only work with certain commands and do not yet work with multi-pack indices.
- **Packed source stubs**: The "packed" ODB source does not yet implement `odb_source_map_oid` or `odb_source_write_oid_map`, as pack index v3 support is deferred to later patches.
