This is the first patch in Patrick Steinhardt’s v2 series introducing the **object storage extension** mechanism. It removes the unused function `repo_write_loose_object_map()` from the loose object backend.

The function was introduced in 2023 to write a mapping between SHA-1 and SHA-256 for loose objects, but it was never called—loose object maps are instead written incrementally via `repo_add_loose_object_map()`. Beyond being dead code, the function hardcodes the path to the loose object index as `$GIT_COMMON_DIR/objects`, which would conflict with the rest of the codebase if the object directory were relocated (e.g., via the new `files://` backend payload). The patch deletes the function and its declaration, removing 46 lines of code from `loose.c` and one from `loose.h`.

This cleanup is a prerequisite for the object storage extension: the hardcoded path would break when alternative backends relocate the object directory, and the function’s unused status was only discovered during the extension’s development. The commit message is thorough, explaining both the immediate removal and the broader architectural motivation. No behavior changes are introduced, and the patch is uncontroversial—it simply removes code that was never used and would have caused problems later. The change is mechanical and well-justified, with no open questions or review feedback from v1.
