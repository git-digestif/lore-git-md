This is a substantive review comment on the second patch in Patrick Steinhardt’s four-patch series restoring dynamic reload of alternate object databases. Christian Couder identifies a subtle but important edge case: when Git uses a temporary primary object directory (such as during `git receive-pack` quarantine), the current fix reloads the alternates of that temporary directory—which has none—rather than the repository’s real alternates. This means objects that have moved to an alternate since the temporary directory was created will not be found, even though they would have been before the regression.

Christian traces the issue to a 2026-07 change (`bdee7b3013`) that made `receive-pack` use the quarantine as its primary directory, whereas previously it only passed the quarantine to child processes via environment variables. The fix, he suggests, is to always reload the repository’s real alternates instead of the temporary directory’s, which would restore the pre-regression behavior and extend it to all temporary-directory scenarios. He also notes that the performance optimization in patch 4 (using `stat_validity`) would make this change effectively cost-free.

The review is thorough and technically precise, referencing specific commits, functions, and code paths. It surfaces a real correctness concern that the original patch did not address, and the proposed solution is well-motivated. This is not a nit or a style comment—it is a substantive issue that could affect production workflows, particularly in server-side Git operations. The thread is now at a decision point: Patrick will need to either accept the suggestion or explain why the current behavior is preferable. Either way, the discussion is clearly worth following for anyone interested in the ODB abstraction or server-side Git reliability.
