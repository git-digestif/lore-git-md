This is patch 12/13 in the SHA-1/SHA-256 interoperability series, implementing the ability to look up compatibility object IDs in packfiles. The patch enables Git to resolve object IDs in any supported hash algorithm, not just the repository's primary one, which is essential for commands like `git rev-parse --output-object-format` that need to work across hash algorithms.

The core change is in `odb/source-packed.c`, where the `for_each_prefixed_object_in_pack` function is extended to iterate over all supported hash algorithms (not just the primary one) when looking up objects. The logic now checks whether each algorithm matches the desired one (or any algorithm, if unspecified) and whether the repository supports it. For pack index v3, which stores both primary and compatibility object IDs, the code uses the new `nth_packed_object_id_algop` and `nth_packed_object_offset_algop` functions to retrieve object IDs and offsets for the requested algorithm. Packs with older indices (v2 or below) are skipped for compatibility lookups, as they only store object IDs in the primary algorithm.

The patch also adds `nth_packed_object_offset_algop` to `packfile.c` and `packfile.h`, a generalized version of `nth_packed_object_offset` that works with arbitrary hash algorithms. This function ensures the correct pack order is used for the requested algorithm and includes a safety check to prevent lookups in older indices for unsupported algorithms.

The test in `t1016-compatObjectFormat.sh` verifies that abbreviated compatibility object IDs can be resolved using pack index v3. It creates a repository, packs its objects with a v3 index, and confirms that `git cat-file` and `git rev-parse` can resolve the abbreviated compatibility object ID, while failing with a v2 index (which lacks compatibility object IDs).
