This is part 4 of the 13-patch series implementing **pack index v3 support** for SHA-1/SHA-256 interoperability. The patch adds the core ODB (object database) functions for mapping object IDs between hash algorithms and writing those mappings to disk, implementing them for the "files" backend and its "loose" and "packed" sources.

The patch introduces two key functions: `odb_map_oid()` and `odb_write_oid_map()`, along with their corresponding callbacks in the ODB source interface. These functions allow Git to translate object IDs from one hash algorithm to another (e.g., SHA-1 to SHA-256) and persist those mappings. The "files" backend (which manages both loose objects and packs) implements these functions by delegating to its constituent "loose" and "packed" sources, checking all object directories (main and alternates) for mappings and reloading loose object maps if needed. The "loose" source implements both mapping and writing, while the "packed" source currently stubs out these functions (returning -1) since pack index v3 support is not yet implemented.

Key technical details include:
- **New functions**: `odb_map_oid()` and `odb_write_oid_map()` (public API in `odb.h`), along with their source-level counterparts (`odb_source_map_oid()` and `odb_source_write_oid_map()`).
- **Flags**: `ODB_MAP_OID_RELOAD` (reload mapping data before lookup) and `ODB_WRITE_OID_MAP_WRITE` (persist mappings to disk).
- **Behavior**: The "files" backend checks all object directories for mappings, reloading loose object maps if a mapping is not found. New mappings are only written to the main object directory.
- **Limitations**: The "packed" source does not yet implement mapping or writing, as pack index v3 support is deferred to later patches.

The patch is a foundational step for the series, enabling the ODB to handle interoperability mappings. It is well-structured and integrates cleanly with the existing ODB abstraction, though the "packed" source's stub implementation signals that full functionality depends on later patches.
