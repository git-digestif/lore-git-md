This is the fourth patch in Patrick Steinhardt’s seven-patch v2 series introducing the **object storage extension**, a foundational step toward pluggable object database backends in Git. This patch exposes the configured object storage format to users via two inspection tools: `git rev-parse --show-object-storage-format` and `git repo objects.storageFormat`.

The implementation is straightforward and follows the established pattern for the ref storage extension. The patch adds a new `--show-object-storage-format` option to `git rev-parse` that prints the value of `the_repository->object_storage_format` (defaulting to `"files"` if unset). In `git repo`, it introduces a new `objects.storageFormat` field that returns the same value, documented in `git-repo.adoc` with a cross-reference to `object-storage-format.adoc` for valid backend values. The patch also updates two tests: `t0001-init.sh` verifies that `git rev-parse --show-object-storage-format` returns the expected value after setting `extensions.objectStorage`, and `t1900-repo-info.sh` adds a test for the `objects.storageFormat` field in `git repo`.

The changes are minimal and correct, touching only the user-facing inspection layer without altering core logic. The patch addresses the design concern raised in v1 about exposing hard-coded defaults by ensuring the `object_storage_format` field is always initialized (a fix introduced in the v2 cover letter). The naming subtlety between `object.format` (hash algorithm) and `objects.storageFormat` (storage backend) remains a potential source of user confusion, but this was acknowledged as a pragmatic compromise in the cover letter and is not revisited here.

No substantive review feedback has been recorded for this patch yet, but it is uncontroversial given its mechanical alignment with the ref storage extension. The patch is ready for review and should integrate cleanly with the rest of the series.
