This is a **substantive review** of the v2 worktree copy-on-write proposal, focusing on the `--reflink` design choice. Eric Sunshine challenges the decision to make `--reflink` opt-in rather than the default behavior, pressing for a clearer technical rationale.

The review zeroes in on Junio’s earlier feedback about whether reflink should be automatic for individual tracked files (rather than a whole-worktree operation). Eric argues that the current explanation—performance on small files and untracked file copying—addresses only a superficial example Junio raised ("cp treeA treeB") but fails to justify why reflink can’t be the default for tracked files specifically. He suggests the cover letter should engage more directly with Junio’s deeper question: why not reflink each tracked file by default, avoiding the need for a user-facing flag entirely?

This is a **design-level objection**, not a nitpick. It goes to the heart of how the feature integrates with Git’s existing behavior and whether it should be transparent or require explicit user action. The review does not propose a specific alternative but demands a stronger justification for the current opt-in approach. If the response is unconvincing, this could become a sticking point for the series.
