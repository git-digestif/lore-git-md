This is a three-patch bugfix series targeting the branch and checkout subsystems. It addresses two related issues: (1) the misleading hint message in `git switch` and `git branch --set-upstream-to` when tracking configuration fails due to a locked config file (carried over from v1), and (2) the incomplete state left behind when `git switch -c` or `git checkout -b` fails to write tracking configuration.

The series is a direct response to feedback on the v1 patch (which only fixed the hint message). Junio C Hamano and others agreed that the real problem is not just the hint text but the fact that the command stops halfway, leaving the worktree, index, and new branch ref updated while HEAD remains on the old branch. The new patches (2/3 and 3/3) refactor `setup_tracking()` to return an error instead of calling `exit()`, and modify `git switch` and `git checkout` to finish the switch and exit with status 0 when the tracking config cannot be written, matching the behavior of `git push -u`, `git clone`, and `git fetch`.

Key technical details:
- Files touched: `branch.c`, `branch.h`, `builtin/branch.c`, `builtin/checkout.c`, and three test files (`t/t2027-checkout-track.sh`, `t/t2060-switch.sh`, `t/t3200-branch.sh`).
- Subsystems: branch (tracking configuration), checkout/switch (worktree and HEAD updates).
- New behavior: `git switch -c` and `git checkout -b` now complete the switch even if the tracking config cannot be written, and exit with status 0. The hint message shows the correct short branch name (e.g., `origin/feat` instead of `origin/refs/heads/feat`).
- Old behavior: the command would stop halfway, leaving HEAD on the old branch and changes staged. The hint message included the invalid `refs/heads/` prefix.
- Test coverage: the series adds comprehensive tests for both the hint message and the new "finish the switch" behavior, including the enhancements suggested in v1 review (verifying the entire hint message and confirming the suggested command works once the lock is removed).
- On-disk format: no changes.
- Regression origin: the hint message issue was introduced in commit a3f40ec4b0 (2021-12-20); the incomplete switch behavior has been present since the introduction of `git switch`.

The series is well-structured and addresses the core problem thoroughly. Patch 1/3 (the hint fix) is unchanged in substance from v1 but now includes the requested test enhancements. Patches 2/3 and 3/3 are new and implement the agreed-upon direction from the bug report thread. The commit messages are clear and explain both the problem and the rationale for the changes. The test coverage is thorough, and the refactoring in patch 2/3 is minimal and focused.

This looks like a high-quality, low-risk fix for a real usability issue. The series is self-contained, touches only the relevant subsystems, and includes regression tests. It should be uncontroversial and ready for review. The only open question is whether the "finish the switch" behavior should be extended to `git branch` (the series explicitly leaves it failing, matching the current behavior). No objections to the core approach have been raised in the thread.
