This is an Outreachy microproject targeting i18n (internationalization) improvements in `builtin/checkout.c`. The author, Muritala Mudi, proposes using Git’s `Q_()` macro to enable proper pluralization in two (or possibly three) user-facing messages that currently hardcode English plural forms. The messages appear when Git warns about commits left behind in detached HEAD state (`" ... and %d more.\n"`) and when multiple references are provided to `git checkout` (`"only one reference expected, %d given."`).

The motivation is clear: while English only needs a single plural form for these cases, languages like Polish require different forms for small numbers (2–4) versus larger ones (5+). The current code prevents translators from handling these cases correctly. Mudi also notes that the same message appears in `builtin/worktree.c` and asks whether to include those instances in the same patch or keep the change focused.

The patch scope is small and well-defined, touching only a handful of lines in `checkout.c` (and optionally `worktree.c`). The change is purely mechanical—replacing `N_()` or direct string literals with `Q_()`—and aligns with Git’s established i18n practices. No behavior change is expected for English users, but the improvement for translators is tangible. This looks like a straightforward, well-motivated microproject that fits Outreachy’s goals.
