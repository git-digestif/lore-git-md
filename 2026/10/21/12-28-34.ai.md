This is a patch series (v3) that extends `git branch --delete-merged` to detect branches whose changes have been integrated via rebase or squash merges, even if the branch tip itself is not reachable from the upstream. The series is now split into three patches: (1) a preparatory refactoring, (2) rebase-merge detection, and (3) squash-merge detection with a new `--squashed` flag.

The core change is that `--delete-merged` now treats a branch as merged if an upstream commit contains all of its changes, not just if its tip is reachable. The rebase detection (patch 2) uses fast tree-based diffing to check for exact file matches, while squash detection (patch 3) adds an opt-in `--squashed` flag that performs a three-way merge to handle cases where upstream modified the same files. The series addresses performance concerns by batching diff calculations and avoiding redundant work, and it preserves blobless clone support by only fetching blobs when `--squashed` is used.

The implementation is well-structured, with clear separation between the two detection mechanisms and thorough test coverage for edge cases (reverted squashes, partial landings, upstream modifications). The `--squashed` flag defaults to off, addressing earlier concerns about performance and false positives. The output format (`Deleted branch topic (was 1a2b3c4, landed as 9f8e7d6)`) gives users clear visibility into where their work landed.

This v3 responds to Junio’s architectural feedback by splitting the series into distinct patches for rebase and squash detection, but it does not adopt his proposed `--delete-irrelevant` CLI redesign. Instead, it treats both cases as part of `--delete-merged`, with `--squashed` as an opt-in for the more expensive squash detection.
