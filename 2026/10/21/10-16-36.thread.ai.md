Core problem or goal
Git silently truncates or misbehaves with files larger than 4 GiB on Windows (LLP64 platforms where `long` is 32-bit). The series fixes four specific truncation or overflow sites: (1) object database writes (truncated blobs), (2) word-diff buffer allocation (crash due to overflow), (3) file conversion helpers (incorrect binary detection, CRLF handling, and keyword expansion), and (4) text statistics counters in `convert.c` (theoretical overflow risk in CRLF/keyword decisions). The patches mechanically convert `size_t` values to `uintmax_t` or `size_t` to avoid narrowing to `unsigned long`, `long`, `unsigned`, or `int`, with no behavior change on 64-bit Linux. The thread has expanded to include a meta-discussion about the project's norms for AI-assisted contributions, sparked by Patrick Steinhardt's frustration with Elia's commit-message phrasing and now broadened by Junio C Hamano to explore procedural standards for such submissions.

Key technical details
Files touched: `odb.c`, `odb.h`, `odb/source-inmemory.c`, `odb/source-loose.c`, `odb/source.h`, `diff.c`, `convert.c`, `attr.c`, `read-cache-ll.h`, `read-cache.c`, `t/t1007-hash-object.sh` (12 files total).
New/renamed symbols: none (type conversions only).
Behavior change: none on 64-bit Linux; prevents data corruption (truncated blobs), crashes (word-diff buffer overflow), and incorrect metadata (binary detection, CRLF handling, keyword expansion) on Windows. The revised test (`t1007`) verifies object writes for files over 4 GiB using `git hash-object -w` and checks the object ID and its existence (`git cat-file -e`). The ODB write functions’ length parameter is now `size_t` (was `unsigned long`), matching Johannes Schindelin’s 2026 read-side ODB work (commit c6a4629e32). The word-diff buffer allocation in `diff.c` now uses `size_t` (was `unsigned long`/`long`). The file conversion helpers in `convert.c`/`attr.c`/`read-cache.c` now use `size_t` (was `unsigned long`). The fourth patch converts counters in `struct text_stat` and `count_ident()` from `unsigned`/`int` to `size_t`, eliminating a theoretical overflow risk. On-disk format: unchanged.
Test coverage: revised `t1007-hash-object.sh` test marked `EXPENSIVE` and `SIZE_T_IS_64BIT`, covering the 4 GiB+ truncation bug for object writes. The test avoids redundant file I/O by using `git cat-file -e` to verify object existence. The fourth patch adds no test, as triggering the overflow would require impractical input sizes (>4 GiB).
