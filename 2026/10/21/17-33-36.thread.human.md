The implementation is clean, reusing Git’s branch-name validation and adding thorough tests for edge cases like unborn branches and prunable worktrees. Documentation includes a worked example showing how to combine it with `git branch --merged`.

The patch drops the original `--merged`/`--no-merged` design entirely, addressing the feedback that a general filter primitive was a better foundation. It doesn’t implement Sunshine’s `foreach` idea, but leaves the door open for it later. The code is ready for review and looks like a solid step toward more flexible worktree inspection. The main open question is whether the project will eventually want the even more general `foreach` mechanism, but for now the `--branch` filter seems to have consensus as the right next step.
