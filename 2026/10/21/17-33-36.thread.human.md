Here’s the human-mode summary for a developer catching up on the thread:

The thread is about adding filtering to `git worktree list` by extending the `%(worktreepath)` atom in `git for-each-ref`. Jasper Mayone’s four-patch series now addresses both the original goal—identifying worktrees by branch—and two safety issues: preventing accidental deletion of in-progress worktrees (rebase, bisect, cherry-pick, etc.) and fixing inconsistencies in how Git reports worktree paths for rebasing or bisecting branches. The series is ready for review, with no remaining technical blockers.

Key changes include making `git worktree remove` refuse to delete in-progress worktrees unless `--force` is given, extending `%(worktreepath)` to show paths for rebasing/bisecting branches (aligning with `git branch -d`), and removing a redundant `+` marker in `git branch` output. The implementation avoids new CLI options by leveraging `for-each-ref`, but this introduces limitations: no NUL-terminated output, no distinction between main/linked worktrees, and a breaking change where `%(worktreepath)` no longer shows bare repository paths. The documentation now warns about parsing risks and clarifies edge cases, including the technically possible (but discouraged) scenario of a branch checked out in multiple worktrees.

Phillip Wood and Ben Knoble raised concerns about safety and usability, particularly around filtering mid-rebase worktrees and the risk of data loss. These are addressed by the `--force` requirement for `git worktree remove` and a documentation warning. Eric Sunshine’s earlier proposal for a `foreach`-style mechanism remains unresolved but is less urgent now. Open questions include whether the main worktree should be filtered out by default and how to handle the broken ordering invariant (main worktree no longer guaranteed to appear first in filtered output). The series is backward-incompatible for scripts relying on the old `%(worktreepath)` behavior, the `+` marker, or the ability to delete in-progress worktrees without `--force`.
