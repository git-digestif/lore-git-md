This thread is about Jasper Mayone’s four-patch series to improve `git worktree` safety and filtering. The series adds a `--force` requirement to `git worktree remove` when deleting worktrees in the middle of a rebase, bisect, cherry-pick, revert, or `git am` operation (patch 1), documents how to safely parse `%(worktreepath)` in `git for-each-ref` (patch 2), extends `%(worktreepath)` to show worktree paths for rebasing or bisecting branches (patch 3), and removes a redundant `+` marker in `git branch` output (patch 4). The patches are well-tested and address real usability and safety gaps, though patch 3 has a known performance regression that needs fixing.

The series has broad support, with Phillip Wood and Ben Knoble providing the most detailed reviews. Phillip’s feedback has been largely incorporated—including edge-case fixes for cherry-pick/revert states and performance suggestions—but one open issue remains: patch 3’s O(N*M) lookup complexity (where N is refs and M is worktrees) should be refactored to use a hashmap for O(1) performance. Phillip also proposed an architectural alternative for patch 4 (adding a `%(currentworktree)` atom to `ref-filter.c`), which could simplify the code but might be better as a follow-up. Ben Knoble’s reviews have focused on safety and documentation clarity, including a resolved debate about whether `%(worktreepath)` can show multiple worktrees for the same branch (it can’t, though Git discourages the scenario).

The only unresolved discussion is a minor documentation style debate between Ben and Phillip about whether the bulleted list in `git-worktree.adoc` should use standalone sentences or a single clause. The series is otherwise ready for integration once the performance fix for patch 3 is addressed. No major objections remain, and the backward-incompatible changes (e.g., dropping bare-worktree `git_dir` support) are explicitly documented.
