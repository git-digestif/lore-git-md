This thread is about a five-patch series by Jasper Mayone that adds filtering capabilities to `git worktree list` and improves safety around worktree operations. The series is now complete at v5 and ready for review.

The core goal is to help developers identify worktrees associated with specific branches while fixing two safety issues: (1) `git worktree remove` currently allows deletion of worktrees in the middle of operations like rebase or bisect, risking data loss, and (2) `git for-each-ref`'s `%(worktreepath)` atom doesn't report worktree paths for branches being rebased or bisected. The series addresses these by extending `%(worktreepath)` and introducing a new `%(currentworktree)` atom in `ref-filter.c`, which avoids new CLI options and aligns behavior across Git commands.

Key changes include making `git worktree remove` refuse deletion of in-progress worktrees unless `--force` is given, adding a documentation warning about safely parsing `%(worktreepath)` (which can contain newlines), extending `%(worktreepath)` to report paths for rebasing/bisecting branches with restored O(1) performance, and adding `%(currentworktree)` to simplify `git branch` output. The final patch in v5 cleans up a visual redundancy in `git branch` output by using `%(currentworktree)` to omit the `+` marker and path for branches being rebased or bisected in the current worktree.

The series has addressed all substantive feedback from earlier versions, including performance regressions and architectural suggestions. Reviewers Phillip Wood, Ben Knoble, and Junio C Hamano have engaged with the design, and all technical concerns have been resolved. The main open questions are about backward compatibility—whether scripts rely on the old behavior of `%(worktreepath)` or the ability to delete in-progress worktrees without `--force`—and whether future enhancements like `git worktree remove --merged` would be useful. The series is backward-incompatible for scripts relying on the old behavior but includes clear documentation and warnings about these changes.
