This thread is an RFC proposing new filtering options for `git worktree list` to help developers identify worktrees tied to merged or unmerged branches. Jasper Mayone initially suggested `--merged` and `--no-merged` flags, providing a full implementation that touches `builtin/worktree.c` and adds tests. However, Junio C Hamano quickly countered with a design critique, proposing a more general `--branch` filter primitive as a better foundation. Eric Sunshine has now weighed in, endorsing Junio’s direction and suggesting an even broader `for-each`-style mechanism—akin to `git submodule foreach`—that could execute arbitrary shell commands across worktrees. This would make the feature far more flexible, though it remains conceptual for now.

The discussion has shifted from a narrow feature addition to a debate over design philosophy: should Git add a focused tool for merged/unmerged worktrees, or a composable primitive that could handle many use cases? The original implementation is still on the table, but it now looks like a special case in a broader conversation. No decisions have been made, and the thread remains in the RFC stage with open design questions. Key participants include Jasper (the author), Junio (maintainer), and Eric Sunshine (reviewer), while others like Harald Nordgren and Kristoffer Haugsbakk have contributed only surface-level feedback. The outcome will likely hinge on whether the project prioritizes immediate utility or long-term flexibility.
