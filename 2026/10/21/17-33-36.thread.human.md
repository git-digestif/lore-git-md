This thread is about adding branch-filtering capabilities to `git worktree list`. Jasper Mayone initially proposed `--merged`/`--no-merged` flags but has since implemented `--branch=<branch>` as a more general filter primitive, following Junio Hamano’s feedback. This allows users to list worktrees associated with specific branches and, when combined with existing branch-filtering commands like `git branch --merged`, achieves merged/unmerged filtering.

The current implementation supports multiple `--branch` arguments, handles rebase/bisect states, and excludes detached worktrees. Phillip Wood’s review highlighted code duplication, usability concerns, and validation questions, suggesting refactoring and output improvements. The patch is not yet assigned to an integration branch, and several open questions remain, including whether the main worktree should be filtered by default and how to handle squash-merged or rebase-merged topics.

Phillip’s latest email refines the composability example in the commit message, proposing a small but practical tweak: using `--format='--branch=%(refname:lstrip=2)'` to consistently strip the `refs/heads/` prefix from branch names. This would simplify the implementation and make the example command more concise. The suggestion is minor and doesn’t address the larger architectural or usability concerns but improves the patch’s documentation and maintainability.
