This thread is an RFC proposing `--merged` and `--no-merged` filters for `git worktree list`, allowing developers to quickly identify worktrees tied to already-merged topics. The feature is now fully implemented in a follow-up patch by Jasper Mayone, who authored the original proposal.

The patch reuses Git’s existing `ref_filter` machinery for consistent parsing and error handling, adding the two new options to `git worktree list` with `HEAD` as the default commit for reachability checks. Tests cover edge cases like unborn branches and broken worktrees, and the implementation is self-contained, touching only `builtin/worktree.c` and the test suite. No maintainer feedback has arrived yet, and the open questions from the RFC—whether to filter out the main worktree by default, whether `HEAD` is the right default commit, and whether a future `git worktree remove --merged` would be useful—remain unresolved. The patch itself is technically sound and ready for review.
