This is the eighth patch in the 13-part series implementing **pack index v3** support for SHA-1/SHA-256 interoperability. The patch fixes a critical bug in `object-file.c` where large blobs streamed directly to a pack would incorrectly store a null OID for the compatibility hash algorithm in the pack index, risking repository corruption.

The change is small but important: it extends the `stream_to_pack()` function to accept an optional compatibility hash context, and updates `odb_transaction_files_write_object_stream()` to compute both the primary and compatibility object IDs when a compatibility algorithm is configured. The patch also adds a test in `t1016-compatObjectFormat.sh` that verifies a large file (5000 bytes) can be added and correctly stored in a compatibility repository without corrupting the pack index.

This is a well-motivated bugfix with clear test coverage. The commit message explains the problem and solution concisely, and the code changes are minimal and focused. The patch is part of the broader interoperability effort and depends on earlier patches in the series that introduced the `compat_oid` field in `struct pack_idx_entry`. No review feedback has been posted yet, but the fix looks technically sound and addresses a real risk of silent corruption.
