This is the **performance test patch** in the six-part incremental connectivity check series. It adds synthetic benchmarks (`t/perf/p5413-connectivity-check.sh`) that isolate the overhead of Git’s connectivity verification by varying three dimensions: total repository size, incoming commit count, and files changed per commit.

The test suite uses a Perl script (`generate-repo-p5413-connectivity-check.perl`) to generate fast-import streams that create flat directory structures with controlled numbers of files, commits, and modifications. Each benchmark fixture is a fresh repository with a single branch (`main`) containing an initial commit of `dirs × files_per_dir` files, followed by `commits` additional commits that each modify `files_per_commit` files in round-robin fashion across `hot_dirs` directories. The test then measures the time for `git rev-list --objects --stdin --not --all --quiet --exclude-promisor-objects`, which is the exact command the incremental connectivity check will optimize.

Three scaling axes are covered:
- **Tree size**: 50, 500, 2000, and 8000 directories (each with 100 files), 10 commits, 10 files changed per commit.
- **Commit count**: 200,000 files, 1, 10, 100, 500, 3000, 5000, and 10000 commits, 10 files changed per commit.
- **Files per commit**: 200,000 files, 10 commits, 1, 10, 100, 500, 1000, and 2000 files changed per commit.

The benchmarks are **self-contained** and include a `PERL` prerequisite; they do not depend on any external data or the rest of the series. The script renumbers tests to avoid collisions and is rebased onto the latest master. This patch directly supports the series’ claim that the incremental mode shifts cost from repository size to incoming change size, providing the baseline measurements against which the later implementation patch (5/6) will be compared.
