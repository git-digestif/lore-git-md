This is the third patch in Jason Newton’s four-patch v3 series introducing copy-on-write worktree creation. It **permanently disables reflink on Windows** due to a confirmed silent-corruption bug in ReFS (Git LFS issue 6312), which zero-fills files when the source data is still cached. The patch removes the Windows-specific reflink implementation from `copy.c`, leaving only a stub that always returns `ENOSYS`, and updates the documentation to warn users about the risk on Windows build 26200. The filesystem probe remains available for future use, but the ioctl is now disabled on all Windows versions.

The change is a direct response to **substantive technical feedback** from brian m. carlson, who identified the ReFS corruption issue. The patch ensures that `--reflink` and `worktree.reflink=true` fall back to regular checkouts on Windows, with a warning (unless `worktree.reflink=auto` is set, which stays silent). The test in `t2400-worktree-add.sh` verifies the warning is emitted and the checkout still succeeds. This patch resolves the immediate technical blocker but leaves the broader reflink design debate (opt-in vs. automatic) unresolved. The series’ other patches handle macOS clonefile() support and ephemeral branch reaping, which remain contested.
