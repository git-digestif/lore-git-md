This is a **substantive review** of the first patch in Harald Nordgren’s two-patch `v2` series for `git imap-send`. Patrick Steinhardt raises a deeper question about the tunnel-command lifecycle: the patch adds `child_process_clear(&tunnel)` to free the argument list, but the child process itself is never reaped with `finish_command()`. He asks whether this omission is intentional, implying that the tunnel process might be left running indefinitely or that its exit status is never checked. The review does not reject the patch but suggests the author should clarify or justify the current design. No alternative implementation is proposed, and the tone is inquisitive rather than critical. The question is narrowly scoped to the tunnel-handling code path in `imap-send.c`.
