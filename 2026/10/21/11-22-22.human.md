This is the fourth patch in Kristofer Karlsson’s six-patch series introducing an **incremental connectivity check** for Git fetches and pushes. This patch adds the **`transfer.connectivityCheck` configuration option**, which lets users choose the algorithm used for connectivity verification. For now, the only accepted value is `"full"` (the existing behavior and default), but the plumbing is in place for the upcoming `"incremental"` and `"auto"` modes. Unknown values fall back to `"full"` with a warning, ensuring forward compatibility.

The patch wires up the config key by teaching `check_connected()` to pass an explicit `--connectivity-check=<mode>` flag to its `rev-list` subprocess. This ensures `rev-list` knows it is running a connectivity check, allowing future optimizations to be scoped to that case. The implementation is minimal and mechanical: it adds the config key to `Documentation/config/transfer.adoc`, documents the internal `rev-list` flag in `Documentation/rev-list-options.adoc`, and extends `builtin/rev-list.c` and `connected.c` to parse and forward the mode.

This is a **well-crafted preparatory patch** that lays the groundwork for the incremental mode without changing behavior. The commit message is clear, the code is clean, and the fallback logic is sensible. The patch is part of a **larger, thoroughly reviewed series** that has already addressed all prior feedback from Junio C Hamano and Patrick Steinhardt. The series is now effectively ready for integration, with this patch serving as the config plumbing step before the actual incremental implementation in patch 5/6.
