This is the v2 cover letter for a two-patch bugfix series targeting `git imap-send`. The series addresses a real interoperability issue: `git imap-send` previously failed when processing patches where the `Subject` header precedes the `Date` header, a valid but non-canonical order produced by tools like `b4` (used to fetch patches from lore.kernel.org). The v2 iteration incorporates Junio’s feedback by replacing `starts_with()` with `istarts_with()` in the `has_required_headers()` helper to comply with RFC 5322’s case-insensitive header name matching requirement.

Patch 1/2 (`imap-send: avoid leaking the tunnel command`) remains unchanged from v1. It plugs a minor memory leak in tunnel-command handling, a cleanup that valgrind would flag. Patch 2/2 (`imap-send: accept messages with Subject before Date`) is the core fix. It rewrites the header-parsing logic in `imap-send.c` to scan all headers first, then process them in the required order (`Date` before `Subject`), rather than assuming a fixed sequence. The commit message explicitly notes that this change removes a workaround for `git send-email --imap-sent-folder` (commit `04133f5bc4`), as the new logic makes it redundant.

The series touches only `imap-send.c` and adds a new test in `t/t9001-send-email.sh` that verifies the fix by sending a patch with `Subject` before `Date` and confirming acceptance. The test coverage is thorough: it exercises the new code path and checks for regressions in the existing `--imap-sent-folder` workflow. The design (cursor-handling logic, order-agnostic parsing) was validated as sound in Junio’s substantive review of v1, and the case-sensitivity fix addresses the sole remaining action item.

This is a well-crafted, uncontroversial bugfix with a clear motivation (interoperability with `b4`/`lore`) and minimal footprint. The problem is real, the solution is straightforward, and the test ensures it won’t regress. The series is now ready for further review or integration.
