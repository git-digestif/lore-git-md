This is a bugfix series for `git imap-send`, now in its second iteration (`v2`). The goal is to fix a parsing failure when `Subject` appears before `Date` in email headers—a valid but non-canonical order produced by tools like `b4` (used to fetch patches from lore.kernel.org). The series also plugs a minor memory leak in tunnel-command handling.

The changes since `v1` are minimal but important: the header-parsing logic now uses `istarts_with()` instead of `starts_with()` to comply with RFC 5322’s requirement for case-insensitive header matching. This addresses the only substantive feedback from Junio’s review of `v1`. The rest of the design—order-agnostic parsing of `From`, `Date`, and `Subject` headers—remains unchanged and is validated as sound.

Patch 1/2 (`imap-send: avoid leaking the tunnel command`) is a straightforward cleanup that frees a previously leaked string. Patch 2/2 (`imap-send: accept messages with Subject before Date`) is the core fix, rewriting the header-parsing loop to scan all headers first, then check for their presence regardless of order. The commit message notes that this removes a workaround for `git send-email --imap-sent-folder` (commit `04133f5bc4`), as the new logic handles it natively.

Test coverage is thorough: a new test in `t/t9001-send-email.sh` verifies the fix by sending a patch with `Subject` before `Date` and confirming acceptance, while also checking for regressions in existing workflows. The series touches only `imap-send.c` and the test script, with no on-disk format changes or new user-facing behavior beyond the bugfix.
