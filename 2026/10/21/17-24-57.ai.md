This is a bugfix patch targeting the `rev-list` command, updating the v1 patch in response to review feedback. The patch ensures that `--grep` is handled correctly during the early argument scan in `git rev-list`, preventing the next argument from being misinterpreted as a separate option when it is actually the grep pattern.

The core issue remains the same: when `--grep` is followed by another option-like argument (e.g., `--missing-only`), the parser treats the next argument as a flag rather than as the grep pattern. The fix is still minimal—just two lines in `builtin/rev-list.c` that increment the argument index when `--grep` is encountered—but the commit message is now clearer about the problem and motivation. The author has also expanded the test coverage to address Pushkar Singh’s request: the new tests verify that `--grep` works correctly both in the second argument scan (e.g., `--grep --missing-only`) and in the first (e.g., `--grep --exclude-promisor-objects`).

The patch touches `builtin/rev-list.c` and `t/t6022-rev-list-missing.sh`, introducing two new tests: one confirming that `--grep` can accept a pattern starting with `--`, and another ensuring that `--grep --exclude-promisor-objects` does not trigger `--exclude-promisor-objects` during the early scan. The behavior change is confined to argument parsing and does not affect core revision-walking logic or on-disk formats.

This version addresses the only open question from the v1 review—whether the fix works for the first argument scan—by adding a dedicated test case. The patch remains well-scoped, with clear test coverage and a straightforward implementation.
