This is part 6 of the 13-patch series implementing **pack index v3** support for SHA-1/SHA-256 interoperability. The patch adds the core writing logic for the new index format, which stores object IDs in both the primary and compatibility hash algorithms.

The key change is in `pack-write.c`, where the `write_idx_file()` function is extended to handle index v3. The new format introduces several structural differences: objects are stored in both pack order and sorted by object ID (for both primary and compatibility hashes), and the index includes tables for both hash algorithms. The patch ensures proper padding to align tables on 4-byte boundaries, which is necessary for architectures that don’t support unaligned access. It also maintains backward compatibility by continuing to write older index versions when appropriate.

A notable implementation detail is the handling of duplicate objects. When `--strict` is used, the patch checks for duplicates in the arrays sorted by object ID (for both hash algorithms), ensuring data integrity. The patch also preserves the existing behavior where callers like `pack-objects` expect the objects array to remain sorted by object ID after writing.

While the patch adds the infrastructure to write pack index v3, it doesn’t yet enable it by default—this is deferred to a later patch in the series. The commit message notes that writing v3 indices would break tests until reading support is implemented.

This is a well-structured, incremental change that fits cleanly into the larger interoperability effort. The code is careful about edge cases (padding, alignment, duplicates) and maintains compatibility with existing code paths. The patch is ready for review and looks like a solid step toward enabling packed object interoperability.
