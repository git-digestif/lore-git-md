Subject: [PATCH] commit: move `git_commit_encoding` to `repo_config_values`
Series version: standalone patch (v2 forthcoming; part of the `the_repository` removal effort)
Originating author: Okhuomon Ajayi
Thread type: patch series (infrastructure refactoring)

Core problem or goal
Eliminate the global `git_commit_encoding` variable by making it repository-scoped, as part of the ongoing `the_repository` removal project to improve Git’s modularity and thread-safety. The design question has shifted: whether to embed the value in the `repo_config_values` struct (original approach) or pass it directly as a `const char *` parameter to functions that need it (Junio’s alternative, now adopted for v2).

Current status
Under review; v1 posted, v2 promised. The patch is a clean, incremental step in the `the_repository` removal series, but Junio’s critique led to a design pivot: v2 will pass `commit_encoding` as a parameter rather than embedding it in `repo_config_values`. This narrows the scope to `commit.c` and avoids modifying the repository struct, aligning with Junio’s preference for simplicity.

Key technical details
- Files touched: `commit.c` (v2 will not touch `environment.c` or `environment.h`)
- New or renamed symbols: none in v2; `write_commit_tree()` and `commit_tree_extended()` will take a `const char *commit_encoding` parameter
- Old behavior: `git_commit_encoding` was a global variable read by `get_commit_output_encoding()`
- New behavior: `commit_encoding` is passed explicitly to `write_commit_tree()` and `commit_tree_extended()`; the global variable is removed
- Junio’s alternative (now adopted): pass `commit_encoding` as a parameter, avoiding changes to `repo_config_values`
- On-disk format: unchanged
- Test coverage: none added; existing tests should continue to pass

Open questions and loose ends
- The global reference to `the_repository` in `commit_tree_extended()` remains; this will likely be addressed in a future patch in the series.
- The revised approach deviates from the established pattern of moving globals into `repo_config_values`, which may influence how similar globals are handled in future patches.
- No other substantive review feedback has been received yet; the discussion is now focused on the implementation details of v2.

Participant positions
- Okhuomon Ajayi (author): initially posted the patch as a mechanical refactoring following the `the_repository` removal pattern, but has agreed to Junio’s alternative for v2, passing `commit_encoding` as a parameter.
- Junio C Hamano (maintainer): objected to embedding `git_commit_encoding` in `repo_config_values`, arguing for a simpler, parameter-passing approach. His preference has been adopted for v2.

Related work
- Part of the broader `the_repository` removal effort (primary driver: René Scharfe), but this patch now deviates from the established pattern of moving globals into `repo_config_values`. The outcome may set a precedent for future patches in the series.
