Subject: [PATCH] sequencer: refuse to revert/cherry-pick a shallow boundary commit by default
Series version: standalone patch (no prior versions)
Originating author: Nakul V S
Thread type: bugfix patch

Core problem or goal
Prevent `git revert` and `git cherry-pick` from accidentally deleting all tracked files when run on a shallow boundary commit (a commit that appears as a root commit due to `--depth=1` cloning and is recorded in `.git/shallow`). The patch adds a safeguard in `do_pick_commit()` that checks for shallow boundary commits via `lookup_commit_graft()` returning a graft with `nr_parent < 0`. If detected, the operation is refused by default with a clear error message, directing users to either `--unshallow` or the new `--allow-shallow-boundary` flag.
