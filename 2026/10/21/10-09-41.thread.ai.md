Thread identity
Subject: [PATCH v2] sequencer: refuse to revert/cherry-pick a shallow boundary commit by default
Series version: v2 (standalone patch, previous version was v1)
Originating author: Nakul V S
Thread type: bugfix patch

Core problem or goal
Prevent `git revert`, `git cherry-pick`, and all `git rebase` backends (`merge`, `interactive`, `apply`) from accidentally deleting all tracked files when run on a shallow boundary commit (a commit that appears as a root commit due to `--depth=1` cloning and is recorded in `.git/shallow`). The patch adds a safeguard in the sequencer that checks for shallow boundary commits via `lookup_commit_graft()` returning a graft with `nr_parent < 0`. If detected, the operation is refused by default with a clear error message, directing users to either `--unshallow` or the new `--allow-shallow-boundary` flag (for `revert`/`cherry-pick` only; `rebase` always refuses without override).

Key technical details
- Files touched: sequencer subsystem (`sequencer.c`, `sequencer.h`), `builtin/revert.c`, `builtin/rebase.c`, and `Documentation/git-revert.adoc`.
- New CLI option: `--allow-shallow-boundary` (exposed in `git revert` and `git cherry-pick` only; `git rebase` always refuses without override). Phillip Wood questions its necessity and suggests dropping it unless a realistic use case emerges.
- New behavior: Default refusal to operate on shallow boundary commits, with an opt-in override for `revert`/`cherry-pick` and no override for `rebase`. The check is performed during todo-list construction (`sequencer_make_script()`, `make_script_with_merges()`) and at the entry points for single-pick operations (`single_pick()`, `sequencer_pick_revisions()`), ensuring no state is left behind if the command is refused. The `rebase --apply` backend, which bypasses the sequencer, receives a lightweight check before rewinding HEAD. Phillip Wood proposes restructuring this check to avoid redundant commit walks by relocating `cleanup_autostash()` and combining patch generation with shallow graft detection in a single revision walk.
- On-disk format: No changes.
- Test coverage: Verifies refusal in shallow repos, override with `--allow-shallow-boundary`, autostash restoration, and edge cases like single-commit clones. Tests cover all rebase backends. Phillip Wood recommends moving rebase tests to `t3400-rebase.sh` and trimming redundant coverage.
- New symbols: `sequencer_refuse_shallow_boundary()` (shared helper), `is_shallow_boundary_commit()` (shallow utility; now conflicts with Harald Nordgren’s topic).
- Architectural change: The safeguard is enforced at the planning stage, avoiding the `.git/sequencer` leftovers that occurred in v1.
