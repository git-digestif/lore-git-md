Thread identity
Subject: [PATCH] sequencer: refuse to revert/cherry-pick a shallow boundary commit by default
Series version: standalone patch (no prior versions)
Originating author: Nakul V S
Thread type: bugfix patch

Core problem or goal
Prevent `git revert` and `git cherry-pick` from accidentally deleting all tracked files when run on a shallow boundary commit (a commit that appears as a root commit due to `--depth=1` cloning and is recorded in `.git/shallow`). The patch adds a safeguard in `do_pick_commit()` that checks for shallow boundary commits via `lookup_commit_graft()` returning a graft with `nr_parent < 0`. If detected, the operation is refused by default with a clear error message, directing users to either `--unshallow` or the new `--allow-shallow-boundary` flag.

Current status
Under review. No prior versions of this patch exist. The patch is narrowly scoped, well-motivated, and includes thorough test coverage and documentation. Junio C Hamano has endorsed the core premise but raised a design question about extending the safeguard to `git rebase` and `git commit --amend`, and where the check should live (sequencer.c vs. a shared helper). No merge status update has been reported.

Key technical details
- Files touched: sequencer subsystem (`sequencer.c`), `builtin/revert.c`, and `Documentation/git-revert.adoc`.
- New CLI option: `--allow-shallow-boundary` (exposed in both `git revert` and `git cherry-pick`).
- New behavior: Default refusal to operate on shallow boundary commits, with an opt-in override.
- On-disk format: No changes.
- Test coverage: Verifies refusal in shallow repos, override with `--allow-shallow-boundary`, and confirms non-shallow repos remain unaffected.
- New symbols: None (the safeguard is implemented via existing `lookup_commit_graft()` and a new flag in the sequencer options).

Open questions and loose ends
1. **Scope of safeguard**: Whether the check should extend to `git rebase` and `git commit --amend` (Junio and Phillip Wood both support this extension).
2. **Implementation location**: Where the shallow-boundary detection logic should live—sequencer.c (`do_pick_commit()`) or a shared helper function (Phillip Wood’s suggestion, now endorsed by Junio).
3. **Necessity of `--allow-shallow-boundary` flag**: Phillip Wood questioned its necessity; Junio’s feedback implies the flag may remain but its scope could expand to cover additional commands.
4. **Synopsis clarity**: Phillip Wood suggested omitting `--allow-shallow-boundary` from the command synopsis to keep usage messages concise.
