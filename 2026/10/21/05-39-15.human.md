This is the second patch in Patrick Steinhardt’s v2 series introducing the **object storage extension**, a foundational step toward pluggable object database backends in Git. This patch implements the core configuration mechanism (`extensions.objectStorage`), modeled after the existing ref storage extension, and integrates it into Git’s repository initialization and setup code.

The patch adds the `extensions.objectStorage` config key, which accepts a URI in the format `<schema>[://<payload>]`. Currently, the only supported schema is `files`, which corresponds to Git’s traditional loose-objects-and-packfiles backend. The payload allows users to relocate the `.git/objects` directory (e.g., `files://objs` moves objects to `.git/objs`). The implementation includes schema validation, error handling for unknown backends, and integration with the repository struct (`struct repository` gains an `object_storage_format` field). Tests verify that the extension is rejected in repository format version 0, works correctly with the `files` backend, and properly rejects unknown schemas.

The patch touches the ODB subsystem (`odb/source.c`, `odb/source-files.c`), repository setup (`setup.c`, `repository.c`), and adds documentation (`Documentation/config/extensions.adoc`, `Documentation/object-storage-format.adoc`). It also updates the unit test harness to ensure the `object_storage_format` field is always initialized. The changes are mechanical and follow established patterns from the ref storage extension, making the patch straightforward and uncontroversial. No substantive review feedback has been recorded yet, but the implementation appears solid and aligns with the series’ goal of enabling alternative object storage backends.
