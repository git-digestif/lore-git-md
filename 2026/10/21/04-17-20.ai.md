This is a **security bugfix** for Git's SSH signing verification, addressing the second of two critical flaws reported earlier in the thread. The patch makes Git fail closed when the `gpg.ssh.revocationFile` is configured but missing or unreadable, rather than warning and proceeding as if no revocation file exists. It also adds test coverage for the revocation file logic, which was previously untested.

The change is straightforward: if the revocation file does not exist, Git now returns an error instead of silently continuing. Users who want to allow missing files can prefix the path with `:(optional)`, a Git pathname syntax that treats missing files as if the variable were unset. The patch updates `Documentation/config/gpg.adoc` to document this behavior and adds four new test cases in `t/t7528-signed-commit-ssh.sh` covering revoked keys, missing files, and the `:(optional)` escape hatch.

The implementation is clean and well-motivated. The commit message clearly explains the security rationale (failing open is unsafe), the escape hatch mechanism, and the existing behavior of `:(optional)`. The code change itself is minimal: it removes the warning-and-continue logic and replaces it with an early error return. The tests are thorough, covering both the failure case and the optional override.

This patch directly implements the design consensus reached in the thread, with `Suggested-by` and `Helped-by` trailers crediting Patrick Steinhardt and Phillip Wood for their input. The only remaining loose end from the original report is whether Git will support additional revocation mechanisms (e.g., OpenSSH's `KRL` format), but that is outside the scope of this fix. The patch is ready for review and likely to land quickly given the prior discussion and clear security motivation.
