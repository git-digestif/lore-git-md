This is the first patch in a three-patch bugfix series addressing usability issues in `git switch` and `git branch --set-upstream-to`. It fixes a misleading hint message that appears when tracking configuration fails due to a locked config file. The hint currently includes the full ref name (e.g., `origin/refs/heads/feat`) instead of the short name (e.g., `origin/feat`), causing the suggested command to fail when run.

The patch modifies `branch.c` to strip the `refs/heads/` prefix from the hint message, matching the behavior already used in the success message. The change is minimal and focused, touching only the hint formatting logic. The test coverage is thorough: it verifies the entire multiline hint message (not just individual lines) and confirms the suggested command works once the lock is removed, addressing feedback from the v1 review.

This is a clear, well-motivated fix for a real usability issue. The regression was introduced in commit a3f40ec4b0 (2021-12-20), and the patch restores consistency with the rest of the codebase. The test additions are particularly strong, ensuring the hint is both correctly formatted and actionable. No objections to this patch have been raised in the thread, and it aligns with the broader goal of the series to improve error handling in branch-tracking workflows.

The patch touches only `branch.c` and its corresponding test file (`t/t3200-branch.sh`), making it low-risk and self-contained. The commit message clearly explains the problem, the fix, and the rationale for the change. This patch is ready for review and should be uncontroversial. The remaining patches in the series (2/3 and 3/3) build on this work to address the incomplete state left behind when `git switch -c` fails to write tracking configuration.
