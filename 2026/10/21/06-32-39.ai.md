This is patch 7/13 in the SHA-1/SHA-256 interoperability series, implementing the core logic to populate compatibility object IDs in pack index v3 during indexing. The patch enables `git index-pack` and `git pack-objects` to generate SHA-1 (or other compatibility algorithm) object IDs for SHA-256 objects, storing them in the loose object map for later use in pack index v3 writing.

The key technical work happens in `builtin/index-pack.c`, where the patch:
- Adds a mutex (`repo_mutex`) to protect thread-unsafe modifications to the loose object map during threaded index-pack operations.
- Extends `unpack_entry_data()` and `unpack_raw_entry()` to compute and store compatibility object IDs alongside primary object IDs. For blobs, it hashes the content simultaneously for both algorithms; for other object types, it converts the object to the compatibility algorithm before hashing.
- Modifies `resolve_delta()` to compute compatibility object IDs for delta objects and store them in the loose object map (but not write them to disk, to avoid polluting the loose object index).
- Updates `cmd_index_pack()` to accept pack index version 3 as valid.

In `builtin/pack-objects.c`, the patch ensures compatibility object IDs are computed and stored when creating object entries, failing if an object cannot be mapped.

The patch also adds two new tests:
- A test in `t1016-compatObjectFormat.sh` verifying that `index-pack` can write a pack index v3 in a repository with a compatibility algorithm.
- A test in `t5308-pack-detect-duplicates.sh` confirming that `index-pack --strict` rejects packs with duplicate objects when writing a v3 index.

The implementation is careful to avoid thread-safety issues by protecting loose object map modifications with a mutex, and to avoid writing temporary compatibility object IDs to disk. The patch is a critical step in enabling pack index v3, as it provides the compatibility object IDs that the v3 writer (implemented in patch 6) needs to store in the index. The test coverage is appropriate, covering both the happy path and error cases (duplicate detection). This is a substantive and well-executed patch that advances the interoperability effort.
