This is the third and final patch in a well-crafted bugfix series targeting `git switch` and `git checkout`. It completes the work begun in the earlier patches by ensuring that when `git switch -c` or `git checkout -b` fails to write tracking configuration (e.g., due to a locked config file), the command finishes the switch and exits with status 0, rather than leaving the repository in an inconsistent state.

The patch modifies `builtin/checkout.c` to ignore the error returned by `create_branch()` when tracking configuration cannot be written, allowing the switch to complete. The error and hint are still printed, matching the behavior of `git push -u`, `git clone`, and `git fetch`. This change is minimal and focused, touching only the necessary code paths. The commit message clearly explains the rationale and the decision to keep `git branch` failing in the same scenario, avoiding scope creep.

Test coverage is thorough: the patch adds new tests in `t/t2027-checkout-track.sh`, `t/t2060-switch.sh`, and `t/t3200-branch.sh` to verify the new behavior in both `git checkout` and `git switch`, as well as confirming that `git branch` continues to fail as expected. The tests are well-structured and cover edge cases like verifying HEAD is correctly updated and the worktree remains consistent.

This patch is low-risk and addresses a real usability issue. The series has been reviewed favorably in earlier iterations, and this version incorporates all feedback. The changes are self-contained, touching only the branch and checkout subsystems, and the test coverage ensures regressions are unlikely. The patch is ready for final review and should be uncontroversial.
