This is a **security bugfix** for Git's SSH signing verification, addressing a critical flaw where Git would fail open (warn and continue) if the configured `gpg.ssh.revocationFile` was missing or unreadable. The patch itself is clean and well-motivated, but Junio C Hamano raises a **substantive review concern** about the placement of the new error check.

The current patch inserts the missing-file check early in the verification flow, which means Git will now fail verification entirely if the revocation file is missing—even for *known* keys. Junio points out that this differs from the existing behavior for *unknown* keys, where Git still provides signature information (via `ssh-keygen -Y check-novalidate`) before failing. This inconsistency could be confusing for users debugging signature issues, as they would no longer see partial information about a signature when the revocation file is missing.

Junio suggests refactoring the error handling to consolidate all failure cases (unknown keys, missing revocation files, etc.) into a single block, ensuring consistent behavior. The underlying security goal—failing closed by default—is not in dispute, but the review highlights a potential UX regression. The patch already includes thorough test coverage and documentation updates, and the escape hatch (`:(optional)` prefix) remains intact. This feedback is likely to prompt a v2, but the fix itself is on track to land once the error-handling flow is smoothed out.
