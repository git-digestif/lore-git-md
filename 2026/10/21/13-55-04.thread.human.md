This thread is about adding a `--concern` option to `git repo structure` that annotates repository metrics with visual or numeric indicators of how problematic each metric is, based on configurable thresholds. The feature, now in its third version (v3), was restructured from v2 to address a bisectability issue by splitting the series into two self-contained patches: the first introduces the core functionality and its documentation, while the second adds configurability via `repo.concern.*` and its documentation.

Mark C. Chu-Carroll, the author, has been responsive to feedback, fixing issues like memory leaks, CI test flakiness, and config key inconsistencies. The series is under review, with Patrick Steinhardt providing substantive technical feedback on design, implementation, and maintainability. While Patrick raised structural concerns—such as redundant threshold definitions and a potential global variable issue in config parsing—he has not objected to the feature's direction. The latest update confirms the author’s plan to follow Patrick’s suggestion to split and squash documentation, which was already implemented in v3. Open questions remain around the empirical methodology for default thresholds, code structure, and minor technical nitpicks, but the series is progressing toward a stable state. No maintainer decision has been made yet.
