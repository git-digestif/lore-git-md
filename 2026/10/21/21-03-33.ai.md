This is a **bugfix** for the **reftable backend**, addressing the root cause of a potential buffer overflow in the object record decoder. The v2 series splits the fix into two patches: the first adds the `u-reftable-record` test suite to the Makefile (previously only in Meson), and the second widens the allocation size arguments in `reftable_alloc_size()` and `reftable_calloc()` from `size_t` to `uintmax_t` to prevent truncation of 64-bit values on 32-bit systems.

The core issue is that `reftable_alloc_size()`'s overflow check was ineffective on 32-bit platforms because `size_t` could truncate 64-bit values, leading to undersized allocations. The fix changes the function's parameters to `uintmax_t` while keeping the return type as `size_t`, ensuring overflow detection works correctly. The `REFTABLE_CALLOC_ARRAY` macro remains a potential truncation risk (as it bypasses the helper), but no current callers trigger it. The series also adds a direct test for `reftable_alloc_size()` to verify overflow detection on 64-bit systems.

The patches follow feedback from Patrick Steinhardt and Aniket Gupta, who identified the root cause and refined the approach. The commit messages are now contributor-written (per Patrick's critique of AI-generated verbosity) and focus on technical precision. The Makefile change is split into a separate patch for clarity. This is a targeted, well-motivated fix that hardens the reftable backend's low-level allocation logic without changing on-disk formats or behavior. The reftable backend is under active development, so this patch is a sensible precaution.
