This is a bug report about `git log --graph` drawing an orphaned branch incorrectly.

The author describes a visual glitch in `git log --graph --all --oneline` where an orphaned commit (5a2cecdd9) is drawn with a spurious parent connection, making the rightmost lane appear to "go to nirvana" instead of cleanly terminating at the orphan. The expected behavior is that orphaned commits should be drawn without any parent lines, as they are the start of a new branch. The report includes a reproduction using a public repository (packagecontrol/thecrawl.git) and shows both the actual and expected ASCII-art representations.

The issue is clearly illustrated and appears to be a genuine rendering bug rather than a misunderstanding of Git's graph semantics. The author provides system information (Git 2.56.0 on Windows) but no patch or proposed fix. This looks like a well-documented edge case that would be worth attention from someone familiar with the graph-drawing code.
