This thread began with a simple i18n bugfix for `git describe`: replacing hardcoded English plural forms in debug messages with Git’s plural-aware `Q_()` macro to avoid grammatical errors like “found 1 tags” in non-English locales. That patch was quickly reviewed by Jeff King and Junio C Hamano as “obviously correct” and uncontroversial, though both playfully questioned whether debug messages should be translated at all.

Antoni Borowski has now posted a follow-up that reverses course entirely. Instead of fixing the pluralization, the new patch removes all gettext wrappers from `--debug` output in `builtin/describe.c`, arguing that debug messages are developer-facing and should remain untranslated for easier grepping, cross-locale comparison, and pasting into English-language bug reports. The patch prefixes each debug line with “Debug: ” to match the style already used in `transport-helper.c`. This directly addresses Junio’s earlier suggestion and shifts the thread’s focus from a narrow i18n fix to a broader design question: whether debug output should be translated at all. The patch is under review, with no objections yet raised.
