This thread began as a small i18n fix for `git describe`'s debug output—replacing singular `_()` gettext wrappers with plural-aware `Q_()`—but has evolved into a design discussion about whether debug messages should be translated at all. Antoni Borowski, the author, has now posted a follow-up patch that removes all gettext wrappers from the debug output entirely, arguing that debug messages are developer-facing and should remain untranslated for consistency, grepability, and ease of sharing in bug reports. This reverses the earlier pluralization fix and directly adopts Junio C Hamano’s playful suggestion to stop translating debug output altogether.

The current patch is a clean, mechanical change: it strips the gettext wrappers from six `fprintf()` calls in `describe_commit()` and prefixes each with `"Debug: "` to match the style used in `transport-helper.c`. There’s no behavior change beyond untranslated output, no new symbols, and no impact on on-disk formats. The patch is uncontroversial in scope, but it raises a broader question about consistency across Git’s debug output—why some subsystems (like `transport-helper.c`) leave debug messages untranslated while others don’t. So far, there are no technical objections or requests for changes, but the shift from pluralization to translation removal may prompt new feedback.

Key participants include Antoni Borowski, who authored both patches and now advocates for untranslated debug output, and Junio C Hamano, who initially endorsed the pluralization fix but playfully suggested removing debug message translation entirely—this patch now implements that suggestion. Jeff King (Peff) previously reviewed the pluralization patch as "obviously correct" but questioned the broader value of translating debug messages, though his stance on this new patch is unknown. The thread remains under review, with no merge status reported. The earlier pluralization patch is now abandoned, and this proposal supersedes it entirely.
