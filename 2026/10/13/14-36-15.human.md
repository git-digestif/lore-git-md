This is the second patch in a **feature series (v5, 2/2)** that makes `git blame` and `git annotate` automatically use `.git-blame-ignore-revs` as the default ignore-revs file when no explicit file is configured. The series is **queued for `next`** and addresses all prior feedback, including a key design decision: it now reads the **working-tree file** in non-bare repositories (matching `.mailmap` behavior) instead of the committed blob, making it ergonomic to test uncommitted changes.

The patch implements the default file lookup, adding `.git-blame-ignore-revs` (or `HEAD:.git-blame-ignore-revs` in bare repositories) as the initial entry in the ignore-revs list before any user-configured files. This ensures user overrides take precedence while aligning local behavior with hosting platforms like GitHub and GitLab, which already respect this file by default. The lookup is intentionally limited to the repository root to avoid performance costs and match hosting platform conventions.

Key technical details include:
- **Security and robustness**: The patch uses `lstat()` and `open_nofollow()` to skip symlinks and non-regular files, and enforces a **100MB size cap** (matching Git’s `.gitattributes` limit) to prevent memory exhaustion. The parser rejects NUL bytes and malformed input, and the ignore-revs list is processed starting after the last empty string entry to allow users to bypass a malformed default file.
- **Edge cases**: The patch handles subdirectory invocations, bare repositories, uncommitted working-tree changes (now read by default in non-bare repositories), CLI/config overrides, and overly large files. Test coverage is thorough, including scenarios like symlinks, comments/whitespace, and empty files.
- **Documentation**: Updates to `blame-options.adoc` and `config/blame.adoc` clarify the new behavior and override semantics.

The patch is well-crafted, with clear commit messages, thorough test coverage, and careful attention to security and edge cases. It introduces no new user-facing options—it simply makes an existing feature more convenient. The hardening in the first patch (1/2) is a prerequisite for this default lookup and ensures the feature is safe to use with upstream-controlled content. The series is feature-complete and has no unresolved technical objections.
