This is the second patch in Phillip Wood’s v4 series to make `git checkout -m` remember original conflict labels. Specifically, this is Junio’s follow-up refactoring (originally PATCH 1.5/2 in v3, now PATCH 2/3 in v4) that optimizes performance by caching merge-related config settings.

The patch introduces a new `struct checkout_merged_data` to hold per-invocation constants: the conflict style (`diff3` vs `merge`) and the `merge.renormalize` setting. These values are read once at the start of `checkout_worktree()` and then reused for every conflicted path, eliminating redundant config lookups. The change is purely internal to `builtin/checkout.c` and has no user-visible behavior.

The implementation is straightforward: `checkout_merged_prepare()` initializes the struct, and `checkout_merged()` uses the cached values instead of calling `repo_config_get_bool()` for each path. The patch also updates the function signature of `checkout_merged()` to accept the new struct. No new symbols are introduced beyond the struct and the helper function.

This refactoring is a prerequisite for the next patch (PATCH 3/3), which will cache the contents of `.git/MERGE_LABELS` to avoid repeated file I/O. Junio’s sign-off confirms the patch is ready for integration, and Phillip has incorporated it verbatim. The change is uncontroversial and aligns with Git’s existing patterns for caching per-invocation state.
