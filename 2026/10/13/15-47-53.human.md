This is the first patch in Phillip Wood’s three-part series to make `git checkout -m` remember the original conflict labels (branch names) from the initial merge. This patch is a preparatory refactoring: it converts the `verbose` boolean argument in `remove_branch_state()` to an `unsigned flags` field, introducing `REMOVE_BRANCH_STATE_VERBOSE` as the sole flag. The change is mechanical and has no user-visible behavior impact, but it enables the next patch to add a new flag for preserving conflict labels.

The patch touches `branch.c`, `branch.h`, and `builtin/checkout.c`, updating all call sites to use the new flags-based API. The diff is small and straightforward, replacing the boolean with a bitmask and adjusting the logic in `sequencer_post_commit_cleanup()` to check the flag. The commit message clearly states the purpose: enabling future flags without changing current behavior.

This is a well-executed refactoring from a trusted contributor. The change is minimal, idiomatic, and fully backward-compatible. No concerns or objections have been raised in prior iterations, and Junio’s acceptance of the series confirms this patch is ready for integration. The only thing to note is that this is just the setup for the real feature, which arrives in the next patch.
