This is a platform compatibility bugfix (v5) targeting macOS and other environments where external tools rewrite files with CRLF line endings, causing Git commands that refresh the index to incorrectly report modifications. The patch modifies `read-cache.c` to avoid treating a size change as conclusive evidence of modification when conversion (CRLF handling, clean filters) is active, instead falling through to content verification.

The core change adds four lines to `ie_modified()`: when a file's size changes and `would_convert_to_git()` returns true, Git now calls `ce_modified_check_fs()` to verify whether the size change reflects actual content modification. This affects all commands that refresh the index (`git status`, `git rebase`, `git pull --rebase`, `git update-index --refresh`), but leaves `git diff-files` and `git diff-index` unchanged (they use `ie_match_stat()`). The patch is unconditional, preserves existing behavior for non-converted files, and handles edge cases like lone-CR rewrites.

Benchmark data shows negligible overhead in realistic scenarios (12 microseconds per modified 2.6 KB file) but measurable costs in extreme cases (138ms for 10,000 modified files).
