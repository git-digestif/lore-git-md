Subject: [PATCH] completion: add --graph-indent and --no-graph-indent to git log
Series version: v2 (standalone patch)

Thread type: contributor housekeeping (bash-completion script in contrib/)

Core problem or goal
Add shell completion support for the `--graph-indent`, `--no-graph-indent`, and `--graph-lane-limit` options to `git log` in the bash-completion script (`contrib/completion/git-completion.bash`). The discussion explored the architectural limitations of the current completion system—specifically, the lack of conditional completion logic in `parse-options.h`—while the immediate goal of adding missing completions reached consensus and is now approved.

Current status
Approved and ready for integration. Junio C Hamano has explicitly endorsed the v2 patch, echoing Toon Claes’s "Looks good to me" and signaling readiness for merging. The patch is uncontroversial, addresses a clear gap in the completion system, and is expected to land in `next` shortly, graduating to `master` in the next integration cycle. The broader architectural discussion about conditional completion (suppressing `--graph`-dependent options unless `--graph` is present) and self-maintaining completion hints via `parse-options.h` remains speculative and forward-looking, with no concrete proposal or objections.

Key technical details
- File touched: `contrib/completion/git-completion.bash`
- Variables modified: `__git_log_gitk_options` (command-specific block for `git log` and `gitk`); `__git_log_common_options` (shared across commands) no longer includes `--graph-indent`, `--no-graph-indent`, or `--graph-lane-limit`
- New symbols: `--graph-indent`, `--no-graph-indent`, and `--graph-lane-limit=` (completion-only; no new CLI behavior)
- Architectural insight: The bash-completion script exists to handle options *not* processed by `parse-options.h`, which currently lacks support for conditional completion (e.g., suppressing options unless `--graph` is present). This limitation is acknowledged as a general issue affecting other Git commands with combinatorial option dependencies, not just `git log`. No infrastructure for conditional completion exists in the script or `parse-options.h`; Pablo Sabater’s suggestion to suppress `--graph`-dependent options unless `--graph` is present remains unaddressed in the immediate patch but is noted as a future consideration.
- On-disk format: none affected
- Test coverage: none (typical for completion script changes; validated manually)

Open questions and loose ends
1. Should completion of `--graph`-dependent options be conditional on `--graph` being present on the command line? If so, does the completion script have infrastructure for such logic, or would this require changes to `parse-options.h`? (Speculative; no concrete proposal yet. Toon Claes and Mirko Faina agree this would require `parse-options.h` enhancements.)
2. Could Git commands expose their own completion hints via `parse-options.h`, similar to `--help`, to make the completion system self-maintaining? (Ben Knoble’s speculative idea; no implementation plan.)
3. Are there other `--graph`-related options that might be added in the future, and should the completion script be structured to accommodate them? (No immediate candidates identified.)
4. Should `--graph-indent` and `--graph-lane-limit` completions be restricted to `git log` only, given that they are not documented for `gitk`? (Current patch follows existing pattern of grouping by relevance rather than strict command-specificity.)
