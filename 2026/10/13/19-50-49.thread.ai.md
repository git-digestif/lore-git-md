Subject: [PATCH] completion: add --graph-indent and --no-graph-indent to git log
Series version: none (standalone patch)
Originating author: Mirko Faina <mroik@delayed.space>
Thread type: contributor housekeeping (bash-completion script in contrib/)

Core problem or goal
Add shell completion support for the `--graph-indent` and `--no-graph-indent` options to `git log` in the bash-completion script (`contrib/completion/git-completion.bash`). These options were previously missing from the list of completable options in `__git_log_common_options`. The discussion has expanded to consider the semantic grouping of `--graph`-dependent options, the meaning of "common options," and potential architectural improvements to the completion system.

Current status
Under review. The original patch remains uncontroversial, but the discussion has broadened to include (1) whether `--graph`-dependent options should be grouped separately, (2) the intended meaning of `__git_log_common_options`, and (3) speculative ideas for a self-maintaining completion system based on `parse-options`. No objections to the current patch; Pablo Sabater’s review and Ben Knoble’s follow-up both suggest improvements for future iterations.

Key technical details
- File touched: `contrib/completion/git-completion.bash`
- Variable modified: `__git_log_common_options` (shared between `git log`, `git show-branch`, and other commands)
- New symbols: `--graph-indent`, `--no-graph-indent` (completion-only; no new CLI behavior)
- Additional symbols proposed for future consideration: `--graph-lane-limit`
- On-disk format: none affected
- Test coverage: none (typical for completion script changes, validated manually)
- Conditional completion logic: Pablo Sabater raises the question of whether `--graph`-dependent options should be suppressed unless `--graph` is already on the command line; Ben Knoble’s speculative proposal would obviate the need for such logic by making completion hints self-generated.

Open questions and loose ends
1. Should `--graph-indent` and `--no-graph-indent` be moved from `__git_log_common_options` to a command-specific block (e.g., `__git_log_gitk_options`) alongside `--graph`?
2. Should `--graph-lane-limit` also be added to the completion script?
3. Should completion of `--graph`-dependent options be conditional on `--graph` being present on the command line? If so, does the completion script already have infrastructure for such conditional logic?
4. Are there other `--graph`-related options that might be added in the future, and should the completion script be structured to accommodate them?
5. Could Git commands expose their own completion hints via `parse-options`, similar to `--help`, to make the completion system more self-maintaining? (Speculative; no concrete proposal yet.)
