This is a feature patch series that makes `git blame` and `git annotate` automatically use a `.git-blame-ignore-revs` file if it exists, without requiring manual configuration. The v5 revision is the latest iteration of a long-running effort to align Git's local behavior with hosting platforms like GitHub and GitLab, which already respect this file by default.

The key change in v5 is that the default ignore file is now read from the working tree (`.git-blame-ignore-revs`) in non-bare repositories, rather than from the committed blob (`HEAD:.git-blame-ignore-revs`). This matches the behavior of `.mailmap` and makes it easier to test uncommitted changes before committing them. Bare repositories still fall back to the committed blob. The patch also enforces a 100MB size cap to prevent memory exhaustion from maliciously large files, a hardening measure introduced in v4 and endorsed by Junio.

The series is well-motivated and addresses a real pain point: users are frequently surprised when their local blame output differs from what they see on the web. The implementation is careful about security, precedence, and edge cases. It rejects symlinks, non-regular files, and malformed input, and ensures user-configured ignore files take precedence over the default. The tests cover subdirectory invocations, bare repositories, CLI/config overrides, and oversized files.

Junio has already approved the series for `next`, and the only remaining loose end is whether to retain the NUL-byte check in the ignore-revs parser. The author has addressed all prior feedback, including the `the_repository` cleanup and the size cap, and the series looks ready for integration. This is a polished, user-friendly change that brings Git in line with established ecosystem practice.
