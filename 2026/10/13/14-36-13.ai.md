This is the **v5 revision of a feature patch series** that makes `git blame` and `git annotate` automatically use `.git-blame-ignore-revs` (or `HEAD:.git-blame-ignore-revs` in bare repositories) as the default ignore-revs file when no explicit ignore file is configured. The series is **queued for `next`** and addresses all prior feedback, including a critical shift in design: it now reads the working-tree file in non-bare repositories (matching `.mailmap` behavior) instead of the committed blob, making it ergonomic to test uncommitted changes.

The core change is straightforward: the patch aligns local `git blame` behavior with hosting platforms (GitHub, GitLab) that already respect `.git-blame-ignore-revs` by default. The v5 revision resolves the last open question from v4 by adopting Junio’s preference for reading the working-tree file in non-bare repositories, which he called "more ergonomic" than matching hosting platforms. This makes the feature immediately useful for local development without requiring commits to test changes.

The series is split into two patches. The first hardens the ignore-revs parser and tag-peeling logic to handle upstream-controlled content safely: it rejects NUL bytes, prevents promisor fetches in partial clones, and enforces a **100MB size cap** (matching Git’s existing `.gitattributes` limit) to prevent memory exhaustion. The second patch implements the default file lookup, using `lstat()` and `open_nofollow()` to skip symlinks and non-regular files, and ensures user-configured ignore files take precedence. The lookup is intentionally limited to the repository root to avoid performance costs and align with hosting platform conventions.

Test coverage is thorough, including edge cases like subdirectory invocations, bare repositories, CLI/config overrides, symlinks, overly large files, and comments/whitespace handling. The documentation updates clarify the new behavior and override semantics. The series is feature-complete and has no unresolved technical objections; the only remaining refinements (e.g., the NUL-byte check) are minor and can be addressed in follow-ups if needed.

Key files touched: `builtin/blame.c`, `oidset.c`, `oidset.h`, `Documentation/blame-options.adoc`, `Documentation/config/blame.adoc`, and `t/t8013-blame-ignore-revs.sh`. The patch introduces no new user-facing options—it simply makes an existing feature more convenient. The hardening in patch 1/2 is a prerequisite for the default lookup and does not depend on other in-flight efforts.
