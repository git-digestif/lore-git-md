This is the third patch in Patrick Steinhardt’s five-patch series refactoring alternates handling in Git’s object database. The series is part of the broader ODB abstraction effort, and this patch moves the second-object-read logic from the generic ODB layer into the "files" backend, removing the `OBJECT_INFO_SECOND_READ` flag entirely.

The change is a clean internal refactoring: the second read (which reloads on-disk state when an object isn’t found on the first attempt) is now handled directly by the "files" backend, where alternates are an implementation detail. The "packed" source is adjusted to use `OBJECT_INFO_QUICK` instead of `OBJECT_INFO_SECOND_READ` to determine when to scan packfiles covered by a multi-pack index, which could theoretically trigger an extra scan on the first read but is expected to have minimal performance impact. The patch reduces code by 40 lines and aligns with the series’ goal of simplifying the ODB source API.
