This is a **substantive review** of Beat Bolli’s patch that replaces Git’s manual hostname verification in `imap-send` with OpenSSL’s built-in `SSL_set1_host()`. Patrick Steinhardt identifies a **security regression**: the patch removes the `SSL_get_peer_certificate()` check, which means an attacker could strip the certificate entirely and the connection would still be accepted as long as `SSL_get_verify_result()` returns `X509_V_OK`. This creates a trivial MITM vector that the old code explicitly blocked.

The review also raises two secondary concerns. First, the commit message lacks context: it assumes the reader already knows Git performs its own hostname verification and why that is insufficient. Second, Patrick questions the choice of `X509_CHECK_FLAG_NO_PARTIAL_WILDCARDS` over `X509_CHECK_FLAG_NO_WILDCARDS`, though this is less critical than the security issue.

Most importantly, Patrick points out the **absence of tests** for this security-sensitive code path. The existing test suite does not exercise hostname verification edge cases, so the regression could easily go unnoticed. He suggests adding tests to ensure the new OpenSSL-based logic behaves as expected.

This feedback is **tested-level**: Patrick not only identifies the problem but also provides a concrete reproduction scenario (certificate stripping) and cites OpenSSL’s own documentation. The patch cannot proceed without addressing the security hole and, ideally, adding test coverage. If you care about `imap-send` security or OpenSSL integration, this review is a must-read.
