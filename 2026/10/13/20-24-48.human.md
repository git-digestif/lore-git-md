This is the **v6 update** of the patch series that makes `git blame` and `git annotate` automatically use `.git-blame-ignore-revs` (or `HEAD:.git-blame-ignore-revs` in bare repositories) as the default ignore-revs file when no explicit file is configured. The series is now **polish-only**, addressing Junio C Hamano’s final code clarity feedback from v5 while preserving all functionality, security hardening, and edge-case handling.

The key change in v6 replaces a "cute hack" in `builtin/blame.c` with a clearer implementation. Previously, the code used a misleading string (`".git-blame-ignore-revs"`) and passed the scoreboard (`&sb`) as the `.util` value to trigger the default file lookup, even though neither was actually used by `build_ignorelist()`. In v6, the string is now properly passed to `parse_default_ignore_revs()` (for both working-tree and bare repository resolution), and `.util` is set to `(void *)1` with an explanatory comment. This makes the intent explicit: any non-null `.util` entry triggers the default lookup. The change is purely about maintainability and does not affect behavior.

The rest of the series remains unchanged. Patch 1/2 hardens the ignore-revs file parser with NUL-byte rejection, promisor fetch prevention, and a 100MB size cap, while patch 2/2 implements the default file lookup with robust edge-case handling (subdirectory invocations, bare repositories, uncommitted working-tree changes, committed symlinks, and CLI/config overrides). The series is **feature-complete**, well-tested, and aligned with hosting platform conventions (GitHub, GitLab). Junio’s prior approval for `next` still stands, and this update resolves his last remaining feedback.

The only loose end is the NUL-byte check, which the author has offered to adjust in a follow-up if Junio requests it. This is a minor detail and does not affect the core functionality. The series is on track for `next` and likely `master` in the near future. For developers, this patch is worth noting as it standardizes a workflow that many already use via hosting platforms, reducing friction for teams that rely on ignore-revs files.
