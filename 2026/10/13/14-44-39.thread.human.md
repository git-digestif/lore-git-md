This thread is about a bugfix for a regression in Git 2.56.0 that affects `git fetch --all` when combined with `--depth` or `--unshallow`. The issue prevents history deepening when multiple remotes are configured, as the parent process fails to pass these flags to the fetcher subprocesses for each remote. Rong Bao’s patch modifies `builtin/fetch.c` to explicitly forward the `deepen` flag and `depth` value, and adds two new tests in `t/t5514-fetch-multiple.sh` to verify the fix.

The patch is narrowly focused, includes a clear reproduction case, and demonstrates the fix with system-call traces and test coverage. Since this is the first submission, there’s no prior discussion or review feedback yet, but the patch appears ready for review. If accepted, it will resolve a regression affecting users who rely on shallow fetches with multiple remotes.
