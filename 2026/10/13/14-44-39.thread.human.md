This thread is about a bugfix patch from Rong Bao that addresses a regression in `git fetch --all --depth=<n>` and `git fetch --all --unshallow`, where the `--depth` or `--unshallow` flags were not being forwarded to subprocesses for each remote, leaving the repository shallow instead of deepening or unshallowing as intended. The patch is narrowly scoped to `builtin/fetch.c` and includes tests to verify the fix.

Junio C Hamano has reviewed the patch and raised two substantive concerns. First, he questions whether the same propagation issue exists for submodule fetches when `--recurse-submodules` is used, since the same helper function is involved. He asks whether submodules should inherit the `--depth` flag at all, or if this could introduce unintended behavior. Second, he points out a correctness issue: the patch only propagates `--depth`, but the `deepen` variable is set if *any* deepening option (`--depth`, `--deepen-since`, or `--shallow-exclude`) is used. If the outer fetch was invoked with `--deepen-since` or `--shallow-exclude`, the `depth` variable could be `NULL`, leading to malformed subprocess arguments. Junio suggests explicitly handling each deepening option separately, though he cautions against blindly propagating `--shallow-exclude` to submodules.

The patch is still under review, and no other participants have weighed in yet. The discussion is now focused on addressing Junio’s concerns before the patch can be merged.
