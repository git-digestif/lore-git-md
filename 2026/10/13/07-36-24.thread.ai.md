Subject: [PATCH 0/5] odb: refactor and optimize alternates handling in files backend
Series version: v2 (six patches; test coverage added)
Originating author: Patrick Steinhardt
Thread type: patch series (refactoring/performance)

Core problem or goal
Refactor and optimize the alternates mechanism in the Git object database’s "files" backend. The series addresses performance inefficiencies in reading and streaming objects when alternates are present, then performs internal cleanup to simplify the ODB source API and remove redundant code. No user-visible behavior changes are intended.

Current status
Under review; v2 posted with test coverage integrated. The series consists of six patches. Johannes Schindelin’s request for a regression test (authored by Tyrie Vella) has been addressed: the test verifies that objects in alternate packfiles are checked before loose objects in the main repository, ensuring the optimization in patch 1/6 works as intended. The test (`t/t1500-alternates-performance.sh`) is portable, validated on both SHA-1 and SHA-256 repositories, and already integrated into Microsoft Git to fix the same performance issue. Justin Tobler’s feedback on error handling in `do_oid_object_info_extended()` has been incorporated as patch 5/6, which immediately fails with `ODB_READ_ERROR` when an object is found but corrupt, rather than attempting to fetch it from a promisor remote. Justin Tobler has now **confirmed the design and implementation** of patch 5/6, explicitly agreeing with the early-failure semantics and tracing the control flow to verify correctness. The final patch (6/6) removes the `local` flag from the generic ODB source struct, retaining it only in the packed source where it is still needed.

Key technical details
Files touched: 14 total (series-wide, including the new test file); primary changes in `odb.c`, `odb/source-files.c`, `odb/source.h`, `odb/source-loose.c`, `odb/source-packed.c`, `odb/source-packed.h`, and the new test script `t/t1500-alternates-performance.sh`. The optimization in patches 1/6 and 2/6 reorders loops in `odb_source_files_read_object_info()` and `odb_source_files_read_object_stream()` to check packfiles before loose objects, avoiding unnecessary `stat()` calls. Patch 3/6 confines the second-read logic to `odb/source-files.c`, where a `retry` loop replaces the generic `OBJECT_INFO_SECOND_READ` flag. The "loose" source no longer handles this flag, and the "packed" source uses `OBJECT_INFO_QUICK` to determine when to scan MIDX-covered packfiles. Patch 4/6 eliminates the redundant read loop in `do_oid_object_info_extended()` by replacing it with a single explicit re-read after promisor remote fetches, removing the `while (1)` loop and `already_retried` flag. Patch 5/6 modifies `do_oid_object_info_extended()` to fail immediately with `ODB_READ_ERROR` when an object is found but corrupt, rather than attempting to fetch it from a promisor remote. This change removes 12 lines of redundant error-handling logic and tightens the function’s error semantics. Patch 6/6 removes the `local` flag from the generic ODB source struct, retaining it only in the packed source where it is still needed. The new test script `t/t1500-alternates-performance.sh` creates an alternate repository with a deltified object, writes a loose copy of the same object in the main repository, and verifies that `git cat-file --batch-check="%(deltabase)"` resolves to the alternate’s packfile (not the loose copy).
Behavior changes: none (plumbing-level). On-disk format: unchanged.
Test coverage: relies on existing ODB tests; the new test `t/t1500-alternates-performance.sh` verifies the performance-critical behavior introduced in patch 1/6.

Open questions and loose ends
The design-level concern about the `ODB_FOR_EACH_OBJECT_LOCAL_ONLY` flag’s long-term viability remains unresolved. Patrick Steinhardt identified two current callers: `git pack-objects --local` (which he considers overly tied to the "files" backend) and `add_unseen_recent_objects_to_traversal()` in `reachable.c` (whose usage he finds dubious). He suggested the flag could potentially be removed entirely but deferred that work to a follow-up series. Justin Tobler raised concerns about the flag’s "leaky" and "awkward" nature after the `local` flag’s removal from the generic ODB source API, questioning whether all callers have legitimate "files" backend-specific reasons and confirming that the in-memory source should never be iterated when only "local" objects are requested. The phrasing of the `OBJECT_INFO_QUICK` flag in the packed source and the structure of the early loop termination in `odb_source_files_read_object_info()` were clarified in discussion with Justin Tobler, but no code changes were made or promised. The early loop termination’s current structure is a temporary convenience for a planned follow-up series on alternates reloading, which will iterate over newly added loose object directories after re-reading `.git/objects/info/alternates`. Justin Tobler proposed adding a TODO comment to document the flag’s potential removal, but this was not addressed in the exchange.
