Thread identity
Subject: [PATCH 0/5] odb: refactor and optimize alternates handling in files backend
Series version: v2 (second iteration; now six patches)
Originating author: Patrick Steinhardt
Thread type: patch series (refactoring/performance)

Core problem or goal
Refactor and optimize the alternates mechanism in the Git object database’s "files" backend. The series addresses performance inefficiencies in reading and streaming objects when alternates are present, then performs internal cleanup to simplify the ODB source API and remove redundant code. No user-visible behavior changes are intended.

Current status
Under review; v2 posted. The series consists of six patches. Patch 1/6 reorders loops in the "files" backend to prioritize packfile checks over loose-object `stat()` calls, achieving a 2x speedup in object lookup when alternates are present (benchmarked by Patrick: 1.89× improvement on `git cat-file --batch-check` in the Git repository). Patch 2/6 applies the same optimization to object streaming, aligning its behavior with the direct-read optimization in patch 1/6. Patch 3/6 moves the second object read logic from the generic ODB layer into the "files" backend, removing the `OBJECT_INFO_SECOND_READ` flag and replacing it with `OBJECT_INFO_QUICK` in the packed source to handle MIDX race conditions. Patch 4/6 removes a redundant read loop in `do_oid_object_info_extended()` by consolidating it into a single explicit re-read after fetching from a promisor remote, simplifying control flow and eliminating the `while (1)` loop and `already_retried` flag. Patch 5/6 tightens error handling in `do_oid_object_info_extended()` to fail immediately with `ODB_READ_ERROR` when the repository is corrupt, addressing Justin Tobler’s feedback from v1. Patch 6/6 removes the now-unused `local` flag from the generic `struct odb_source` and moves it into `struct odb_source_packed`, completing the internal API cleanup. The net diffstat shows a reduction of 54 lines.

Key technical details
Files touched: 12 total (series-wide); primary changes in `odb.c`, `odb/source-files.c`, `odb/source.h`, `odb/source-loose.c`, `odb/source-packed.c`, `odb/source-packed.h`. The optimization in patches 1/6 and 2/6 reorders loops in `odb_source_files_read_object_info()` and `odb_source_files_read_object_stream()` to check packfiles before loose objects, avoiding unnecessary `stat()` calls. Patch 3/6 confines the second-read logic to `odb/source-files.c`, where a `retry` loop replaces the generic `OBJECT_INFO_SECOND_READ` flag. The "loose" source no longer handles this flag, and the "packed" source uses `OBJECT_INFO_QUICK` to determine when to scan MIDX-covered packfiles. Patch 4/6 eliminates the redundant read loop in `do_oid_object_info_extended()` by replacing it with a single explicit re-read after promisor remote fetches, removing the `while (1)` loop and `already_retried` flag. Patch 5/6 modifies `do_oid_object_info_extended()` to fail immediately with `ODB_READ_ERROR` when an object is found but corrupt, rather than attempting to fetch it from a promisor remote. This change removes the `corrupt` flag and redundant checks, reducing the function by 12 lines. Patch 6/6 removes the `local` flag from the generic ODB source struct, retaining it only in the packed source where it is still needed. The patch updates `odb_source_init()` signature, removes the flag from the base struct, and adjusts the packed and loose source implementations. The `ODB_FOR_EACH_OBJECT_LOCAL_ONLY` flag’s behavior is preserved by the "files" backend’s existing logic, which already skips non-local object directories. The change also updates `midx.c` and `repack.c` to use the packed source’s `local` field instead of the generic one.
Behavior changes: none (plumbing-level). On-disk format: unchanged.
Test coverage: relies on existing ODB tests; no new tests introduced in this series.

Open questions and loose ends
The design-level concern about the `ODB_FOR_EACH_OBJECT_LOCAL_ONLY` flag’s long-term viability remains open. Patrick Steinhardt identified two current callers: `git pack-objects --local` (which he considers overly tied to the "files" backend) and `add_unseen_recent_objects_to_traversal()` in `reachable.c` (whose usage he finds dubious). He suggested the flag could potentially be removed entirely but deferred that work. Justin Tobler’s question about whether the in-memory source should ever be iterated when only "local" objects are requested was answered in the negative by Patrick, who stated he is unaware of any such scenario.
