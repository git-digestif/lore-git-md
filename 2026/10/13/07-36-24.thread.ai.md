Thread identity
Subject: [PATCH 0/5] odb: refactor and optimize alternates handling in files backend
Series version: v3 (five patches; rebased, no functional changes)
Originating author: Patrick Steinhardt
Thread type: patch series (refactoring/performance)

Core problem or goal
Refactor and optimize the alternates mechanism in the Git object database’s "files" backend. The series addresses performance inefficiencies in reading and streaming objects when alternates are present, then performs internal cleanup to simplify the ODB source API and remove redundant code. No user-visible behavior changes are intended.

Current status
Ready for integration; all substantive feedback addressed. The series now consists of five patches (rebased to drop the previously separate error-handling patch, which was merged into the main refactoring flow). The final exchange between Patrick Steinhardt and Justin Tobler confirms the architectural direction is uncontroversial and the series is complete. The unresolved question about the `ODB_FOR_EACH_OBJECT_LOCAL_ONLY` flag’s long-term viability is explicitly scoped as a follow-up effort, with no immediate action required. The new test `t/t5615-alternate-env.sh` (added in patch 1/5) remains the primary verification for the performance-critical behavior, ensuring objects in alternate packfiles are prioritized over loose objects in the main repository. Benchmark data shows a 1.89x speedup for `git cat-file --batch-check` when reading objects primarily stored in alternate packfiles. All patches have received substantive, tested reviews from Justin Tobler, who has endorsed the design and implementation of each.

Key technical details
Files touched: 12 total (series-wide, excluding the test file); primary changes in `odb.c`, `odb/source-files.c`, `odb/source.h`, `odb/source-loose.c`, `odb/source-packed.c`, `odb/source-packed.h`, `midx.c`, `repack.c`, and `builtin/pack-objects.c`. The optimization in patch 1/5 reorders loops in `odb_source_files_read_object_info()` to check all packfiles across alternates before checking any loose objects, avoiding unnecessary `stat()` syscalls when objects exist in alternate packfiles. Patch 2/5 mirrors this optimization in `odb_source_files_read_object_stream()`, splitting the original loop into two separate loops (packfiles first, then loose objects) with an early return if a packfile match is found. Patch 3/5 confines the second-read logic to `odb/source-files.c`, where a `retry` loop replaces the generic `OBJECT_INFO_SECOND_READ` flag. The "loose" source no longer handles this flag, and the "packed" source uses `OBJECT_INFO_QUICK` to determine when to scan MIDX-covered packfiles. Patch 4/5 eliminates the redundant read loop in `do_oid_object_info_extended()` by replacing it with a single explicit re-read after promisor remote fetches, removing the `while (1)` loop and `already_retried` flag. The error-handling logic for corruption (`ODB_READ_ERROR`) now fails immediately rather than attempting to fetch from a promisor remote, aligning with the principle that corruption should not be silently masked. Patch 5/5 removes the `local` flag from the generic ODB source struct, retaining it only in the packed source where it is still needed, and updates all callers to use the packed source’s `local` field instead. The in-memory source’s `for_each_object` callback is updated to return early when either `ODB_FOR_EACH_OBJECT_LOCAL_ONLY` or `ODB_FOR_EACH_OBJECT_PROMISOR_ONLY` is set, as in-memory objects are neither local nor promisor objects.
Behavior changes: none (plumbing-level). On-disk format: unchanged.
Test coverage: relies on existing ODB tests; the new test `t/t5615-alternate-env.sh` verifies the performance-critical behavior introduced in patch 1/5 and indirectly covers patch 2/5 by ensuring objects in alternate packfiles are prioritized.

Open questions and loose ends
The `ODB_FOR_EACH_OBJECT_LOCAL_ONLY` flag’s long-term viability remains unresolved. Patrick Steinhardt identified two current callers: `git pack-objects --local` (which he considers overly tied to the "files" backend) and `add_unseen_recent_objects_to_traversal()` in `reachable.c` (whose usage he finds dubious). He suggested the flag could potentially be removed entirely but deferred that work to a follow-up series. Justin Tobler raised concerns about the flag’s "leaky" and "awkward" nature after the `local` flag’s removal from the generic ODB source API, questioning whether all callers have legitimate "files" backend-specific reasons and confirming that the in-memory source should never be iterated when only "local" objects are requested. The discussion concluded with agreement that the flag’s removal is non-trivial and should be addressed separately, with Patrick preferring to keep the issue in the project’s "hive mind" rather than formalizing it as a TODO comment. No code changes or TODOs were added in response to this exchange.
