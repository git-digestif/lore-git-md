Thread identity
Subject: [PATCH 0/5] odb: refactor and optimize alternates handling in files backend
Series version: v2 (second iteration)
Originating author: Patrick Steinhardt
Thread type: patch series (refactoring/performance)

Core problem or goal
Refactor and optimize the alternates mechanism in the Git object database’s "files" backend. The series addresses performance inefficiencies in reading and streaming objects when alternates are present, then performs internal cleanup to simplify the ODB source API and remove redundant code. No user-visible behavior changes are intended.

Current status
Under review; v2 posted. The series now consists of six patches, with the new patch (5/6) addressing Justin Tobler’s feedback from v1 by tightening error handling in `do_oid_object_info_extended()` to fail immediately with `ODB_READ_ERROR` when the repository is corrupt. The other five patches are unchanged from v1. The net diffstat shows a reduction of 54 lines.

Key technical details
Files touched: 12 total (series-wide); primary changes in `odb.c`, `odb/source-files.c`, `odb/source.h`, `odb/source-loose.c`, `odb/source-packed.c`, `odb/source-packed.h`. Patch 1/6 reorders loops in the "files" backend to prioritize packfile checks over loose-object `stat()` calls, achieving a 2x speedup in object lookup when alternates are present (benchmarked by Patrick). Patch 2/6 applies the same optimization to object streaming, aligning its behavior with the direct-read optimization in patch 1/6. Patch 3/6 removes the `OBJECT_INFO_SECOND_READ` flag and moves the second object read logic into the "files" backend, replacing it with `OBJECT_INFO_QUICK` in the packed source to determine when to scan packfiles covered by a MIDX (expected to have minimal performance impact). The early loop termination in `odb_source_files_read_object_info()` is structured to accommodate a planned follow-up series that will modify alternates reloading to iterate over newly added loose object directories. Patch 4/6 removes a redundant read loop in `do_oid_object_info_extended()` by replacing it with a single explicit re-read after fetching from a promisor remote. Patch 5/6 (new in v2) tightens error handling in `do_oid_object_info_extended()` to fail immediately with `ODB_READ_ERROR` when the repository is corrupt, rather than attempting to fetch a missing object. Patch 6/6 removes the now-unused `local` flag from the generic `struct odb_source` and moves it into `struct odb_source_packed`, completing the internal API cleanup. The `ODB_FOR_EACH_OBJECT_LOCAL_ONLY` flag is now considered "leaky" by Justin Tobler, as it assumes "files" backend semantics despite being part of the generic ODB API.
Behavior changes: none (plumbing-level). On-disk format: unchanged.
Test coverage: relies on existing ODB tests; no new tests introduced in this series.

Open questions and loose ends
The design-level concern about the `ODB_FOR_EACH_OBJECT_LOCAL_ONLY` flag’s long-term viability remains open. Patrick Steinhardt identified two current callers: `git pack-objects --local` (which he considers overly tied to the "files" backend) and `add_unseen_recent_objects_to_traversal()` in `reachable.c` (whose usage he finds dubious). He suggested the flag could potentially be removed entirely but deferred that work. Justin Tobler’s question about whether the in-memory source should ever be iterated when only "local" objects are requested was answered in the negative by Patrick, who stated he is unaware of any such scenario. The patch itself is uncontroversial and moves the codebase in the right direction, but the unresolved question about the flag’s future remains open.
