Subject: [PATCH 0/5] odb: refactor and optimize alternates handling in files backend
Series version: v1 (initial submission)
Originating author: Patrick Steinhardt
Thread type: patch series (refactoring/performance)

Core problem or goal
Refactor and optimize the alternates mechanism in the Git object database’s "files" backend. The series addresses performance inefficiencies in reading and streaming objects when alternates are present, then performs internal cleanup to simplify the ODB source API and remove redundant code. No user-visible behavior changes are intended.

Current status
Under review; v1 posted. No prior versions of this specific series. Built on Patrick’s earlier `ps/odb-files-alternates` branch, which migrated alternates handling into the files backend.

Key technical details
Files touched: 12 total (series-wide); primary changes in `odb.c`, `odb/source-files.c`, `odb/source.h`, `odb/source-loose.c`, `odb/source-packed.c`, `odb/source-packed.h`. Patch 5/5 removes the `local` flag from the generic `struct odb_source` and moves it into `struct odb_source_packed`, completing the internal API cleanup. The `OBJECT_INFO_SECOND_READ` flag was removed in patch 3/5.
Behavior changes: none (plumbing-level). The second object read (triggered when an object isn’t found on the first attempt) is now handled entirely within the "files" backend instead of the generic ODB layer. The "packed" source now uses `OBJECT_INFO_QUICK` instead of `OBJECT_INFO_SECOND_READ` to determine when to scan packfiles covered by a MIDX, which may cause an extra scan on the first read but is expected to have minimal performance impact. Patch 4/5 removed a redundant read loop in `do_oid_object_info_extended()` by replacing it with a single explicit re-read after fetching from a promisor remote. Patch 5/5 removes the now-unused `local` flag from the generic ODB source struct, retaining it only in the packed source where it is still needed to propagate to opened packfiles.
On-disk format: unchanged.
Test coverage: relies on existing ODB tests; no new tests introduced in this series.
Performance impact: Patch 1/5 demonstrated a 2x speedup in object lookup when alternates are present by reordering loops to prioritize packfile checks over loose-object `stat()` calls. Patch 2/5 applied the same optimization to object streaming, with a smaller expected gain. Patches 3/5 through 5/5 are not expected to affect performance meaningfully.

Open questions and loose ends
None raised yet; series remains uncontroversial.

Participant positions
Patrick Steinhardt (author): identified and fixed performance regressions in alternates handling (patches 1/5 and 2/5), providing benchmark data for the first patch and arguing for consistency in the second. Removed the redundant read loop in `do_oid_object_info_extended()` (patch 4/5) as a follow-up to the alternates migration, further cleaning up the ODB internals. Removed the `local` flag from the generic ODB source struct (patch 5/5), retaining it only in the packed source where it is still needed. All changes are mechanical and confined to the ODB plumbing.
