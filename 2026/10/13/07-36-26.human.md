This is the second patch in Patrick Steinhardt’s five-part refactoring and performance series for the object database’s alternates handling in the files backend. It mirrors the optimization introduced in patch 1/5, but targets the streaming path (`odb_source_files_read_object_stream`) instead of direct object reads.

The change is straightforward: the function now checks all packed sources first before falling back to loose objects, rather than interleaving the two. The commit message acknowledges that the performance impact is likely smaller for streaming (since large-object reads dominate the time budget), but argues the consistency with the direct-read path justifies the change. The diff is minimal—just six lines in `odb/source-files.c`—and maintains the same internal API.

This patch is uncontroversial and clearly motivated by the earlier optimization. It continues the series’ theme of internal cleanup without user-visible behavior changes, and the author’s established expertise in the ODB subsystem makes it a safe bet for inclusion. No new tests are introduced, as the existing ODB test suite should cover the streaming path.
