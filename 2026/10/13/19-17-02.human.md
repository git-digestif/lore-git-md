This is a CI/build system patch series that improves GitHub Actions CI failure reporting for Git's test suite. Junio C Hamano has marked the series as ready for `next`, confirming the merge status change that Phillip Wood proposed in his review.

The series consists of two patches. The first, already cooking in `next`, stops leak-sanitizer test scripts at the first failure (`--immediate`) and annotates leaks with the test script name and full sanitizer output in a collapsible log group. The second, rewritten as a compromise in v6, adds file and line context to failure annotations as plain text (e.g., `failed: t1060.17 partial clone of corrupted repository (t1060-object-corruption.sh:141)`), resolving the earlier regression where annotation links only worked if the test file was modified in the same pull request.

Phillip Wood's explicit acceptance of the compromise in v6 closed the thread's primary technical objection, and Junio's marking of the series as ready for `next` formalizes its integration status. The series is now a candidate for graduation to `master` once it has cooked in `next`. No further iteration is expected unless new issues arise during integration testing.

This is a well-crafted, pragmatic improvement that directly addresses a pain point for contributors and reviewers debugging CI failures. The compromise solution preserves the usability benefits of the original patch while avoiding its technical pitfalls. Files touched: `ci/lib.sh`, `t/test-lib-github-workflow-markup.sh`, and `t/test-lib.sh`. The changes are confined to CI infrastructure and test reporting, with no impact on Git's core functionality or on-disk formats.
