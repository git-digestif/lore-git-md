This is a feature patch that makes `git blame` automatically use `.git-blame-ignore-revs` (or `HEAD:.git-blame-ignore-revs` in bare repositories) as the default ignore-revs file when no explicit file is configured. This is the sixth iteration of a well-reviewed series that has already been queued for `next` and is now addressing final polish feedback from Junio.

The patch aligns local `git blame` behavior with hosting platforms like GitHub and GitLab, which already respect this file by default. The core change is ergonomic: users no longer need to manually configure `blame.ignoreRevsFile` in every clone to get consistent results between local and web interfaces. The implementation is careful about security (rejecting malformed input, preventing promisor fetches, and enforcing a 100MB size cap) and precedence (user-configured files override the default).

This version (v6) makes two small but important improvements to code clarity, both requested by Junio. First, it replaces a "cute hack" with a clearer comment explaining how the default file lookup is triggered (using a non-null `.util` value in the ignore-revs file list). Second, it removes an unused `.util` value that was previously passing the scoreboard unnecessarily. The documentation has also been updated to consistently refer to `blame.ignoreRevsFile` as a "configuration variable" rather than an "option."

The series is feature-complete and well-tested, with thorough coverage of edge cases like subdirectory invocations, symlink rejection, bare repositories, and CLI/config overrides. The only remaining work is this final polish, and the author has already signaled willingness to address any further minor adjustments in follow-ups. This looks like a solid, uncontroversial change that will make `git blame` more convenient without introducing new complexity.
