This is the maintainer’s final review of the v5 revision of the patch series that makes `git blame` automatically use `.git-blame-ignore-revs` (or `HEAD:.git-blame-ignore-revs` in bare repositories) as the default ignore-revs file. The series is already queued for `next`, and Junio’s comments here are minor clarifications rather than requests for changes.

Junio praises the commit message’s justification for reading the working-tree file in non-bare repositories, calling it “very well written.” He agrees with the design choice—prioritizing the working-tree file over the committed blob—to make it ergonomic to test uncommitted changes, which he previously described as “more ergonomic” than matching hosting platforms.

His only substantive feedback is about a **code readability issue** in `builtin/blame.c`. The current implementation uses a string-list entry with a non-null `.util` member as a signal to trigger the default file lookup, but the string itself (`".git-blame-ignore-revs"`) and the value of `.util` (`&sb`) are ignored by `build_ignorelist()`. This is misleading to future readers, who might assume the string or the scoreboard pointer is used. Junio suggests adding a comment to clarify that the entry’s only purpose is to trigger the default lookup, and that neither the string nor the `.util` value matters. He even proposes a more explicit (but still hacky) alternative: using a placeholder string like `"<builtin default>"` to make the intent clearer.

The rest of his comments are small wording tweaks: he corrects “config option” to “configuration variable” in the documentation and notes that the current phrasing is otherwise good. No technical objections or functional changes are requested. The series remains on track for `next` and is effectively ready for merging.
