This is a bugfix for `git repack` that addresses a long-standing regression where `--dry-run` combined with `--drop-filtered` incorrectly modifies the repository by rebuilding packs and deleting old ones. The patch itself is already in `next` and expected to graduate to `master` soon, but Patrick Steinhardt raises a good follow-up question in this reply.

The fix, introduced in v2 of the series, adds an early `return` in `cmd_repack()` to prevent repository modifications when `--dry-run` is used. Patrick notices that later in the same function, there’s already a conditional check for `!dry_run` when calling `repack_promisor_objects()`. He asks whether this existing check is now redundant because of the early exit.

This is a sharp observation about code hygiene rather than a functional issue—the patch already works as intended. The question is whether the later check should be cleaned up for clarity, or if it serves a separate purpose that the early exit doesn’t cover. The answer isn’t immediately obvious from the patch alone, so this reply nudges the thread toward a minor follow-up: either a brief explanation from the author, or a trivial cleanup patch to remove the now-unnecessary condition. Either way, it’s a small detail that doesn’t block the fix from merging, but it’s worth tidying up before the topic graduates.
