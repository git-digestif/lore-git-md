This is the fourth patch in Patrick Steinhardt’s five-patch series refactoring and optimizing alternates handling in the Git object database’s "files" backend. The patch removes a redundant read loop in `odb.c` that was previously needed to handle alternates at the generic ODB layer.

The commit message explains that the loop was a legacy of the old alternates logic, which required reloading sources and retrying reads after fetching missing objects. Since alternates are now handled entirely within the "files" backend, the loop is no longer necessary and makes the code harder to follow. The patch replaces it with a straightforward, single retry after fetching from a promisor remote, simplifying the control flow.

The change is confined to `odb.c` and reduces the function’s complexity without altering behavior. It’s a clean mechanical refactoring that aligns with the series’ goal of tidying up the ODB internals after the alternates migration. No performance impact is expected, and the patch relies on existing test coverage.

This looks like a well-motivated cleanup that should be uncontroversial. It’s part of Patrick’s broader ODB abstraction effort and follows logically from the earlier patches in the series.
