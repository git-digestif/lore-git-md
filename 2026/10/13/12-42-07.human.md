This is a documentation patch discussion, continuing the thread about improving Git’s explanation of detached HEAD state. The focus here is on naming conventions and usability of Git’s help system.

Julia Evans acknowledges the earlier consensus to hyphenate the new `gitdetached-head(7)` man page (now `gitdetached-head(7)`) to match existing Git guide conventions like `core-tutorial` and `cvs-migration`. She also flags `gitmergeconflicts` as a candidate for the same hyphenation treatment in a future patch, noting that while `man gitdetached-head` feels awkward to type, `git help detached-head` reads more naturally—aligning with the project’s recommendation for how users should access documentation.

The email then steps back to observe a broader usability tension: Git’s man pages reference other pages using the traditional `git-config(1)` or `gitmodules(5)` format, which encourages users to run `man git-config` or `man gitmodules`, but the project’s official guidance is to use `git help config` or `git help modules` instead. This inconsistency isn’t blocking the current patch, but Julia suggests it might be worth revisiting later to make the help system more intuitive. No concrete proposal is offered yet, and she emphasizes this is a separate concern from the detached HEAD rewrite.
