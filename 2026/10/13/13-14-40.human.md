This is the second round of review on Beat Bolli’s patch that replaces Git’s manual hostname verification in `imap-send` with OpenSSL’s built-in `SSL_set1_host()` API. The patch is part of a two-patch v2 series that splits off uncontroversial OpenSSL compatibility fixes from a larger, still-blocked v1 series.

Patrick Steinhardt’s review is substantive and raises two main concerns. First, he points out that the commit message could be clearer about why the current manual verification is insufficient and what the minimum OpenSSL version requirement is. This is a documentation nit, not a technical objection, but it would help future reviewers.

The second concern is more serious: the patch removes the check for a peer certificate (`SSL_get_peer_certificate()`), which means an attacker could strip the certificate entirely and the connection would still be accepted as long as `SSL_get_verify_result()` returns `X509_V_OK`. This creates a potential man-in-the-middle vulnerability. Patrick flags this as a security regression and suggests retaining the peer-certificate check. He also reiterates the need for tests, since the existing test suite does not exercise these edge cases.

The review is thorough and technical, engaging with both the code’s behavior and its security implications. If you care about `imap-send` or OpenSSL integration, this is a patch worth following—it looks like a clean cleanup in principle, but the security issue needs to be fixed before it can land. The author will likely need to send a v3 to address these points.
