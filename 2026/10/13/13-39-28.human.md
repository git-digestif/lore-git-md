This is a bug report about the built-in fsmonitor daemon on Linux. The author, Erik Cervin-Edin, demonstrates a reproducible issue where edits to files in subdirectories of a renamed directory are missed by `git status` when fsmonitor is enabled. Only the top-level file in the renamed directory appears as modified, while changes in subdirectories are silently ignored until fsmonitor state is invalidated.

The problem is traced to `add_watch()` in `compat/fsmonitor/fsm-listen-linux.c`, where inotify watches for subdirectories are not properly updated after a rename. When a directory is renamed, the inotify watch follows the inode, but the path mapping in Git's fsmonitor state is not updated for subdirectories, causing their changes to be reported under their old paths and thus ignored. The author notes this was flagged as a potential issue during review of the Linux fsmonitor implementation but was never addressed.

This is a serious correctness bug that could lead to data loss if users commit based on incomplete status output. The report is clear, includes reproduction steps, and pinpoints the likely cause, making it actionable for maintainers. The issue affects only the Linux fsmonitor backend; the same operations work correctly when fsmonitor is disabled.
