This is the first patch in Patrick Steinhardt’s five-part series refactoring and optimizing alternates handling in Git’s object database (ODB) "files" backend. It directly addresses a performance regression introduced when alternates handling was reorganized for pluggable ODBs.

The patch fixes a performance issue where Git now checks each alternate source (packed and loose) sequentially, rather than scanning all packed objects first. Since checking packed objects is much cheaper (cached pack indices) than loose objects (requires a `stat` syscall), this change restores the original behavior: packed objects across all alternates are checked first, then loose objects. Benchmark results show a 1.89x speedup for `git cat-file --batch-check --unordered` when most objects are in packed alternates.

The change is minimal (3 insertions, 2 deletions in `odb/source-files.c`) and purely internal, with no user-visible behavior changes. It’s a targeted fix for a specific regression reported by Wolfgang Kritzinger, and the commit message clearly explains the problem, solution, and impact. Given Patrick’s established expertise in this area and the straightforward nature of the fix, this patch looks uncontroversial and well-motivated.
