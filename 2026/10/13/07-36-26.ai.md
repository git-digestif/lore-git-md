This is the second patch in Patrick Steinhardt’s five-patch series refactoring and optimizing alternates handling in the Git object database’s "files" backend. It mirrors the performance fix from patch 1/5, but targets the `odb_source_files_read_object_stream()` function instead of direct object reads.

The change reorders the loop logic to prioritize checking packed object sources before loose ones, aligning the streaming behavior with the direct-read behavior introduced in the previous patch. While the author expects the performance impact to be smaller here—since streaming large objects likely spends more time reading data than `stat()`-ing files—he argues the consistency across both functions justifies the change. The patch is minimal (4 insertions, 2 deletions) and confined to `odb/source-files.c`, with no new symbols or user-visible effects.

The commit message is clear but light on benchmark data, reflecting the author’s expectation that the improvement will be modest. This patch is part of the broader ODB abstraction effort and builds directly on Patrick’s earlier work migrating alternates into the files backend. Given its mechanical nature and alignment with the series’ goals, it is unlikely to be controversial.
