This is the final patch in Phillip Wood’s three-part series to make `git checkout -m` remember and reuse the original conflict labels (branch names) from the initial merge, rather than falling back to generic "base/ours/theirs" labels. The series is now functionally complete, with all prior feedback addressed, and is queued for integration in `next`.

This patch implements the core functionality: the ort merge backend now writes the original conflict labels to `.git/MERGE_LABELS` whenever a merge results in conflicts, and `git checkout -m` reads those labels when recreating conflicts. The patch also ensures the labels file is preserved during `git checkout -m <branch>` (via a new `REMOVE_BRANCH_STATE_PRESERVE_CONFLICT_LABELS` flag) and cleaned up by `git commit` and the sequencer. Test coverage in `t/t7201-co.sh` verifies that the labels are preserved and that `.git/MERGE_LABELS` is absent after a clean `git checkout -m <branch>`.

The implementation is thorough and well-motivated. It touches `merge-ort.c`, `branch.c`, `builtin/checkout.c`, and related headers, introducing new functions (`write_merge_labels()`, `read_merge_labels()`) and plumbing to cache the labels in `struct checkout_merged_data`. The use of `strbuf_getline()` ensures portability (handling both LF and CRLF line endings), and edge cases (missing or malformed `.git/MERGE_LABELS`) are handled gracefully by falling back to generic labels. The `.git/MERGE_LABELS` file follows Git’s existing pattern for ephemeral merge state (`MERGE_MSG`, `MERGE_MODE`, etc.), making it a natural fit.

Phillip is a seasoned contributor with deep expertise in the merge machinery, and this patch reflects that: the commit message is clear, the code is clean, and the test coverage is appropriate. The only unresolved discussion—whether `git checkout -m` should also remember the original conflict style (e.g., `diff3`)—does not block this series, as Phillip has explicitly scoped the work to labels only. The series is ready for integration and should graduate to `master` in the current cycle.
