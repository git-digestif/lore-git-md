Core problem or goal
The thread explores whether `git pull --rebase` miscomputes the fork-point when the user has configured a custom fetch refspec (e.g., `+refs/heads/*:refs/remotes/origin/custom/*`). The current implementation in `get_tracking_branch()` hard-codes the default layout (`refs/heads/<branch>` → `refs/remotes/<remote>/<branch>`), which may cause `get_rebase_fork_point()` to look up a non-existent or incorrect remote-tracking ref, leading to an incorrect fork-point and rebase result. Junio C Hamano and Harald Nordgren have both confirmed the issue is a legitimate defect, not a design limitation.
