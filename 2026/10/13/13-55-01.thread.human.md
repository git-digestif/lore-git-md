This thread is about a **performance regression in `git log --follow`** that was introduced in Git 2.56. The issue was reported by a user and forwarded by Patrick Steinhardt: when running `git log --stat --follow` on a file in the Linux kernel repository, the command now takes nearly 8 minutes—up from just 33 seconds in Git 2.55. The regression has been bisected to commit `304812ed33` ("log: improve --follow following renames for non-linear history"), which was merged in late June 2026.

The report is straightforward and actionable, providing the exact commit responsible, the affected command, and a real-world test case (the Linux kernel repository). Since `git log --follow` is a widely used feature for tracking file history across renames, this regression is likely to draw attention from maintainers and contributors familiar with the log subsystem. No fixes or proposed solutions have been posted yet, so the thread is currently just a bug report awaiting investigation.
