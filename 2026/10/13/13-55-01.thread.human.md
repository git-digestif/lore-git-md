The `git log --follow` performance regression introduced in Git 2.56 by commit 304813ed33 is now under active repair. The regression, which slowed `git log --stat --follow` from 33 seconds to nearly 8 minutes in the Linux kernel repository, was traced to quadratic behavior in the new `propagate_follow_pathspec_to_parent()` logic designed to improve rename tracking across merge commits. Miklos Vajna, the original author of the problematic commit, has posted a patch that restores near-original performance while preserving the corrected rename-following behavior.

The patch introduces two key optimizations: it only performs expensive rename detection when the followed path is *added* relative to a parent, and it short-circuits further diffing once an unchanged parent is found. These changes reduce the runtime of the Linux kernel test case from 6 minutes 43 seconds back to 29 seconds—almost matching the pre-regression time—without breaking any existing tests. The implementation is confined to `log-tree.c` and adds a new helper function to classify path changes between commits and their parents.

SZEDER Gábor, who previously confirmed the regression and isolated the bottleneck, and Patrick Steinhardt, who reported the issue, are now reviewing the patch. The optimizations avoid the worst-case behavior for merge commits with many parents while maintaining the correctness fixes introduced by 304813ed33. The patch does not adopt the `git log -L` strategy of skipping non-first parents entirely, but achieves similar performance gains by avoiding redundant diffs. If reviews are positive, this fix should land quickly, resolving the regression before the next Git release.
