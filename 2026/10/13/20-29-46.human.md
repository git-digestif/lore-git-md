This is a review of Curtis Allen Smith’s v5 patch addressing a CRLF conversion bug in `read-cache.c` that causes Git to incorrectly report files as modified when external tools rewrite line endings. Junio C Hamano’s feedback is substantive, focusing on two key concerns: the interaction with Git’s performance trade-offs (particularly the "racy Git" optimization) and the potential for unintended side effects in other code paths.

The patch itself modifies `ie_modified()` to avoid treating a size change as conclusive evidence of modification when conversion (CRLF handling or clean filters) is active, instead falling back to content verification. This fixes a long-standing issue on macOS and other environments where tools rewrite files with CRLF endings after Git checks them out with LF endings, causing false positives in commands like `git status` or `git rebase`.

Junio’s primary objection is architectural: the patch makes an unconditional change to a low-level function (`ie_modified()`) that is used across many code paths, some of which rely on performance trade-offs (like the "racy Git" optimization) to tolerate false positives. He suggests the fix should be disabled when `CE_MATCH_RACY_IS_DIRTY` is set, to avoid breaking these optimizations. While he acknowledges the goal of reducing false positives is valid, he warns that the current approach might introduce regressions in scenarios where Git deliberately accepts false positives for speed.

The review also notes a potential issue with the test design. The new tests in `t/t0020-crlf.sh` might run fast enough to trigger the "racy Git" code paths, which could mask problems rather than expose them. Junio implies the tests should be adjusted to ensure they exercise the intended behavior without interference from these optimizations.

Curtis’s patch is technically sound and addresses prior feedback on test design and commit message clarity, but Junio’s concerns suggest it may need another revision to account for Git’s performance trade-offs. The unresolved architectural debate—whether the fix belongs in index refresh operations or in `git add`—remains a sticking point, but Junio’s feedback here focuses on a narrower, more immediate issue: ensuring the patch doesn’t disrupt existing optimizations. This is a well-motivated bugfix with a clear real-world impact, but it’s not yet ready for merging due to these lingering questions.
