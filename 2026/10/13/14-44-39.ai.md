This is a bugfix patch targeting the fetch subsystem. It addresses a regression in Git 2.56.0 where `git fetch --all --depth=<n>` or `git fetch --all --unshallow` fails to deepen the history when multiple remotes are configured. The issue occurs because the parent process does not pass the `--depth` or `--unshallow` flags to the fetcher subprocesses spawned for each remote.

The patch modifies `builtin/fetch.c` to explicitly forward the `deepen` flag and `depth` value to subprocesses when they are specified. It adds two new tests in `t/t5514-fetch-multiple.sh` to verify that `--depth` and `--unshallow` work correctly with `--all`, ensuring the shallow repository is properly deepened or unshallowed for all remotes.

The commit message includes a clear reproduction case, a system-call trace showing the missing flag, and a demonstration of the fixed behavior. The test coverage is thorough, checking both the presence of the `.git/shallow` file and the expected commit history after the fetch. The patch is narrowly scoped and appears to address the issue without introducing side effects. No prior discussion or thread context is referenced, suggesting this is the first submission of the fix.
