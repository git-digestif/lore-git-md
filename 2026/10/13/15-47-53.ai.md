This is the first patch in the v4 series that teaches `git checkout -m` to remember original conflict labels. It is a refactoring patch with no user-visible behavior change, converting the `verbose` boolean argument of `remove_branch_state()` to an `unsigned flags` field. The new `REMOVE_BRANCH_STATE_VERBOSE` flag is introduced as the sole flag, and all call sites in `builtin/checkout.c` are updated to use the new API. This preparatory step enables the next patch to add a new flag for preserving conflict labels.

The patch touches `branch.c`, `branch.h`, and `builtin/checkout.c`, making small, mechanical changes. The commit message clearly explains the motivation (adding more flags in a future commit) and the change itself. The implementation is straightforward and idiomatic, using a bitmask for flags and updating the function signature to match. No concerns or feedback were raised on this patch in prior iterations, and it is ready for integration as part of the series.

This patch is a necessary foundation for the series' core functionality, but it does not introduce any new behavior or symbols beyond the `REMOVE_BRANCH_STATE_VERBOSE` flag.
