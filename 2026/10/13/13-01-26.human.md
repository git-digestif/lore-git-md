This is a documentation patch that rewrites Git’s explanation of detached HEAD state. The v2 iteration addresses all substantive feedback from Junio C Hamano and Kristoffer Haugsbakk: it adds the missing meson/Makefile changes, renames the man page to `gitdetached-head(7)` (hyphenated to match existing guide conventions), clarifies that “garbage” commits are deleted after 90 days (not immediately), softens the claim that detached HEAD is the *only* way to look at old code, and adds a concrete example of Git’s warning when leaving commits behind. The patch also now cross-references `git help datamodel` for deeper context.

The new text is shorter, more practical, and frames detached HEAD as a useful tool for experimentation rather than a pitfall. It explains how users might end up in this state (checking out a commit ID, tag, or remote-tracking branch) and how `git switch` makes accidental detachment harder. The advice message in `advice.c` now points to the new standalone guide, making help more accessible. This version is ready for integration; the only remaining work is the recovery-example addition Julia Evans plans for a future iteration. The patch is well-motivated, clearly improves usability, and has addressed all technical feedback.
