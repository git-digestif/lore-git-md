This is the **second patch in the v6 series** that makes `git blame` and `git annotate` automatically use `.git-blame-ignore-revs` (or `HEAD:.git-blame-ignore-revs` in bare repositories) as the default ignore-revs file when no explicit file is configured. The patch is **queued for `next`** and implements the core functionality described in the cover letter and thread summary.

The patch modifies `builtin/blame.c` to add the default ignore-revs file lookup logic, which checks for `.git-blame-ignore-revs` in the working tree (for non-bare repositories) or `HEAD:.git-blame-ignore-revs` in bare repositories. The lookup is performed **before** processing user-configured ignore-revs files, ensuring user overrides take precedence. The implementation includes security hardening (NUL-byte rejection, promisor fetch prevention, and a 100MB size cap) and handles edge cases such as subdirectory invocations, bare repositories, uncommitted working-tree changes, and symbolic links.

Key changes in this patch:
- **Default file lookup**: Uses `lstat()` and `open_nofollow()` to resolve `.git-blame-ignore-revs` in non-bare repositories, and `get_oid_with_context()` to resolve `HEAD:.git-blame-ignore-revs` in bare repositories. Non-regular files (e.g., symlinks) are silently skipped.
- **Precedence**: The default file is added to the ignore-revs list **before** any user-configured files, ensuring user overrides take precedence. Empty entries in `blame.ignoreRevsFile` or `--ignore-revs-file ""` bypass the default file entirely.
- **Security refinements**: The `oidset_parse_buffer_carefully()` helper (introduced in patch 1/2) is reused to parse the default file, enforcing the same security checks (NUL-byte rejection, size cap, and promisor fetch prevention).
- **Code clarity improvements (v6)**: Replaces the "cute hack" (passing the scoreboard as `.util`) with `.util = (void *)1` and an explanatory comment, and propagates the ignore-revs file name (`i->string`) into `parse_default_ignore_revs()` to avoid hardcoding paths.
- **Test coverage**: Adds extensive tests in `t/t8013-blame-ignore-revs.sh` for the default file lookup, including edge cases like subdirectory invocations, bare repositories, CLI/config overrides, symbolic links, and overly large files.

The patch touches `builtin/blame.c`, `oidset.c`, `oidset.h`, and documentation files (`blame-options.adoc`, `config/blame.adoc`). No new symbols are introduced; the changes modify existing blame logic to include the default file lookup while preserving user override semantics. The implementation is **scalable** (the `oidset` uses 32-bit integers, and the size cap prevents memory exhaustion) and **secure** (malformed input is rejected, and promisor fetches are avoided in partial clones).

This patch is **feature-complete** and addresses all prior feedback, including Junio’s polish-only comments in v6. The series is a **practical improvement** that aligns local `git blame` behavior with hosting platform conventions (GitHub, GitLab), reducing friction for users who rely on ignore-revs files. The default file lookup is designed to be **ergonomic** (e.g., uncommitted changes are respected in non-bare repositories) and **safe** (e.g., symlinks and oversized files are ignored).
