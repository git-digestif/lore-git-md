This is the second patch in a two-part bugfix series targeting a long-standing race condition in Git’s `rerere` subsystem. The patch adds a `--skip-locked` flag to `git rerere gc`, allowing auto-maintenance tasks (`git maintenance run --auto` and `git gc --auto`) to skip silently when the `MERGE_RR.lock` is held, rather than failing or waiting. This matches the behavior of other auto-maintenance tasks and prevents background maintenance from disrupting concurrent operations.

The implementation is minimal and focused: the flag is hidden (`OPT_HIDDEN_BOOL`) and explicitly restricted to the `gc` subcommand, preventing misuse. The `rerere_gc()` function now accepts a `flags` parameter, with `RERERE_NOWAIT` (zero timeout) used to skip the lock silently. Documentation in `Documentation/config/rerere.adoc` clarifies that auto-maintenance callers use this mode, and the test suite (`t/t4200-rerere.sh` and `t/t7900-maintenance.sh`) verifies that `--skip-locked` skips only when the lock is held, that manual `gc` calls fail after timeout, and that the flag is rejected for non-`gc` subcommands.

This patch is technically complete and ready for integration. It addresses all prior feedback, including Patrick Steinhardt’s suggestion to use a shared bitmask flag (`RERERE_NOWAIT`) instead of a dedicated enum, and Junio C Hamano’s test hygiene improvements. The conservative design (failing outright for manual calls) prioritizes correctness, and the hidden flag ensures the feature is only used by auto-maintenance, avoiding user confusion. The series as a whole is well-motivated, with clear reproduction scenarios and thorough test coverage.
