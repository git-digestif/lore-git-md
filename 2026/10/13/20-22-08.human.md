This is the **second patch in a two-patch feature series** that makes `git blame` and `git annotate` automatically use `.git-blame-ignore-revs` (or `HEAD:.git-blame-ignore-revs` in bare repositories) as the default ignore-revs file when no explicit file is configured. The series is **queued for `next`** and this patch implements the core functionality: the default file lookup, security hardening, and user override semantics.

The patch teaches `git blame` to consult `.git-blame-ignore-revs` at the root of the working tree (or `HEAD:.git-blame-ignore-revs` in bare repositories) before processing any user-configured ignore-revs files. This aligns local behavior with hosting platforms like GitHub and GitLab, which already respect this file by default. The implementation is **secure and robust**: it rejects NUL bytes, prevents promisor fetches in partial clones, enforces a 100MB size cap, and silently skips symlinks and non-regular files. The default file is added to the ignore-revs list **before** any user-configured files, ensuring user overrides take precedence, and empty entries in `blame.ignoreRevsFile` or `--ignore-revs-file ""` bypass the default file entirely.

The patch touches `builtin/blame.c`, `oidset.c`, and `oidset.h`, introducing a new `oidset_parse_buffer_carefully()` helper to parse in-memory buffers (used for blob reads) and refactoring the existing `oidset_parse_file_carefully()` to share line-parsing logic. The default file lookup is implemented in `parse_default_ignore_revs()` and `parse_default_ignore_revs_blob()`, which handle working-tree and bare repository cases, respectively. The `build_ignorelist()` function is updated to process the default file first, and the ignore-revs file list is built using `string_list_append()` to preserve order. Documentation in `blame-options.adoc` and `config/blame.adoc` is updated to reflect the new behavior, and the test suite (`t/t8013-blame-ignore-revs.sh`) is expanded with **233 lines of new tests** covering edge cases like subdirectory invocations, bare repositories, uncommitted working-tree changes, symlinks, overly large files, and CLI/config overrides.

This patch is **feature-complete and well-tested**, addressing all prior feedback from Junio, Phillip Wood, and others. The v6 revision focuses on **code clarity**, replacing a "cute hack" (passing the scoreboard as `.util`) with a clearer implementation (`.util = (void *)1` and an explanatory comment) and removing an unused `.util` value. The series is **ready for integration** and represents a practical improvement for users who rely on ignore-revs files, reducing friction and aligning Git’s behavior with hosting platform conventions.
