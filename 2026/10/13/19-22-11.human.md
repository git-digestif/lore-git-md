This is the final confirmation from Junio C Hamano that Souma’s `git history` signing series—now at v5 with two follow-up patches—is ready for the `next` branch. The series teaches `git history` to sign rewritten commits (`drop`, `fixup`, `reword`, `split`, `squash`) using the same GPG-signing configuration (`commit.gpgsign`) and command-line options (`-S/--gpg-sign`, `--no-gpg-sign`) already supported by `git commit`, `git rebase`, and `git cherry-pick`.

The only blocker was a regression in `t9902-completion.sh`, which the follow-up patches fixed by adding `--gpg-sign` and the generated `--no-gpg-sign` option to the expected completion output for `git history split`. Junio explicitly marks the series as "ready for 'next'" after verifying the fix, meaning it will graduate to `next` in the next integration cycle. The conceptual trade-off—whether signing rewritten commits that retain the original author identity is desirable or misleading—remains documented but unresolved; the infrastructure itself is considered mechanically sound.
