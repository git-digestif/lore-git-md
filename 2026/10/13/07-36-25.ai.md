This is the first patch in Patrick Steinhardt’s five-part series refactoring and optimizing alternates handling in the ODB’s files backend. It directly addresses a performance regression introduced when alternates handling was migrated into the files backend: previously, Git would scan all packfiles across alternates before checking loose objects, but the new code was iterating through each alternate’s sources (packfiles and loose objects) one by one. Because checking loose objects requires a `stat()` syscall, this change slowed down cases where most objects reside in packfiles.

The fix is simple and mechanical: the patch reorders the loops so that Git first checks all packfiles across all alternates before falling back to loose objects. The benchmark included in the commit message shows a clear improvement—nearly a 2x speedup in the reported case—without any change to user-visible behavior or on-disk format. The change is confined to a single function in `odb/source-files.c` and is part of the broader ODB abstraction effort. Given the clear performance win and the author’s established expertise in this subsystem, this patch looks uncontroversial and well-motivated.
