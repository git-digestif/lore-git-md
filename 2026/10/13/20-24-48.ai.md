This is the **v6 update** of the patch series that makes `git blame` default to `.git-blame-ignore-revs` (or `HEAD:.git-blame-ignore-revs` in bare repositories) when no ignore file is configured. The series is **feature-complete and approved for `next`**, with this revision addressing Junio’s **polish-only feedback** on code clarity from v5.

The core change in v6 replaces the "cute hack" in `builtin/blame.c`—where a hardcoded string (`".git-blame-ignore-revs"`) with `.util = &sb` was used to trigger the default file lookup—with a clearer implementation. Now, the code sets `.util = (void *)1` and includes an explanatory comment, while propagating the ignore-revs file name (`i->string`) into `parse_default_ignore_revs()` to avoid hardcoding paths in multiple places. This makes the logic self-documenting and removes the misleading use of the scoreboard (`&sb`) as a flag. The rest of the series is unchanged: security hardening (NUL-byte rejection, promisor fetch prevention, 100MB size cap), edge-case handling (bare repositories, subdirectory invocations, committed symlinks), and precedence rules (default file is processed before user-configured files) remain intact.

The patch touches `builtin/blame.c`, `oidset.c`/`oidset.h`, documentation, and tests, with no new symbols introduced. The `the_repository` cleanup (replacing the global with `sb->repo`) and the shift to reading the working-tree file in non-bare repositories (matching `.mailmap` behavior) are preserved. All prior feedback—including Phillip Wood’s usability concerns about uncommitted changes and Junio’s approval of the 100MB size cap—has been addressed. The only loose end is the NUL-byte check, which the author has offered to adjust in a follow-up if Junio requests it, but this is a minor detail.

This revision is **ready for integration** and likely to graduate to `master` soon. The changes are narrowly scoped to the blame subsystem, align with hosting platform conventions (GitHub, GitLab), and include thorough test coverage for edge cases. The code clarity improvements in v6 resolve the last maintainer feedback without altering functionality.
