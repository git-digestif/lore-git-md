Thread identity: Bugfix patch series (single patch) addressing a regression in `git fetch --all --depth=<n>` and `git fetch --all --unshallow` introduced in Git 2.56.0. Originating author: Rong Bao. Thread type: bug report and fix.

Core problem or goal: When running `git fetch --all --depth=<n>` or `git fetch --all --unshallow` with multiple remotes configured, the `--depth` or `--unshallow` flags are not forwarded to the fetcher subprocesses spawned for each remote, causing the shallow repository to remain shallow instead of being deepened or unshallowed as intended. The goal is to restore the expected behavior by ensuring these flags are explicitly passed to all subprocesses. Junio C Hamano’s review expanded the scope to consider whether the same propagation issue exists for submodule fetches when `--recurse-submodules` is used, and whether submodules should inherit deepening flags at all.

Current status: Under review. This is the second iteration of the patch (v2), addressing Junio’s review concerns. The patch now propagates `--depth` and `--deepen-since` to subprocesses for both `--all` and `--recurse-submodules` fetches, but intentionally omits `--shallow-exclude` to avoid potential issues with submodule histories. The core fix for `--all` remains uncontested, but the submodule behavior is still unresolved.

Key technical details:
- Files touched: `builtin/fetch.c` (helper function `add_options_to_argv`), `t/t5514-fetch-multiple.sh`.
- Subsystem: fetch.
- New behavior: The `deepen` flag and `depth` value are now explicitly forwarded to fetcher subprocesses when `--all` or `--recurse-submodules` is used, but only for `--depth` and `--deepen-since`. `--shallow-exclude` is omitted to avoid malformed subprocess arguments.
- On-disk impact: Ensures `.git/shallow` is updated correctly for all remotes when deepening or unshallowing. Submodule shallow files (`.git/modules/<name>/shallow`) may also be updated if deepening flags are propagated.
- Test coverage: Two existing tests verify that `--depth` and `--unshallow` work with `--all`, checking both the presence of `.git/shallow` and the expected commit history. No new tests are mentioned for submodule propagation.
- Additional technical context: The `add_options_to_argv` helper function is shared between `--all` and `--recurse-submodules` fetches, and the `deepen` variable aggregates multiple deepening options (`--depth`, `--deepen-since`, `--shallow-exclude`). The patch now handles each option individually to avoid propagating `NULL` values or malformed arguments.

Open questions and loose ends:
- Should submodule fetches inherit deepening flags from the outer fetch, or should submodule depth be controlled independently? Rong Bao argues for propagation, citing alignment with `--tags` behavior and user expectations, but Junio’s review suggests caution due to potential edge cases with submodule histories.
- The patch omits `--shallow-exclude` to avoid propagating it to submodules, where it may be incorrect. This is a deliberate scope limitation, but it leaves open whether `--shallow-exclude` should be propagated for `--all` fetches (where it would be valid).
- No objections to the core fix for `--all` have been raised, but the patch’s handling of submodules and `--shallow-exclude` remains unresolved.
