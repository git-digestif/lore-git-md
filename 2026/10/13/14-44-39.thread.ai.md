Thread identity: Bugfix patch series (single patch) addressing a regression in `git fetch --all --depth=<n>` and `git fetch --all --unshallow` introduced in Git 2.56.0. Originating author: Rong Bao. Thread type: bug report and fix.

Core problem or goal: When running `git fetch --all --depth=<n>` or `git fetch --all --unshallow` with multiple remotes configured, the `--depth` or `--unshallow` flags are not forwarded to the fetcher subprocesses spawned for each remote, causing the shallow repository to remain shallow instead of being deepened or unshallowed as intended. The goal is to restore the expected behavior by ensuring these flags are explicitly passed to all subprocesses. Junio C Hamano’s review raises additional scope considerations: whether the same propagation issue exists for submodule fetches when `--recurse-submodules` is used, and whether submodules should inherit deepening flags at all.

Current status: Under review. This is the first submission of the patch; no prior versions exist. The patch is narrowly scoped to `builtin/fetch.c` and includes two new tests in `t/t5514-fetch-multiple.sh` to verify the fix. Junio’s review identifies two correctness concerns that will require patch revision: (1) the helper function `add_options_to_argv` is also used for submodule fetches, and the same propagation logic may apply, and (2) the patch only propagates `--depth` but not other deepening options (`--deepen-since`, `--shallow-exclude`), which could lead to malformed subprocess arguments if the outer fetch used those flags.

Key technical details:
- Files touched: `builtin/fetch.c`, `t/t5514-fetch-multiple.sh`.
- Subsystem: fetch.
- New behavior: The `deepen` flag and `depth` value are now explicitly forwarded to fetcher subprocesses when `--all` is used.
- On-disk impact: Ensures `.git/shallow` is updated correctly for all remotes when deepening or unshallowing.
- Test coverage: Two new tests verify that `--depth` and `--unshallow` work with `--all`, checking both the presence of `.git/shallow` and the expected commit history.
- Additional technical context: The `add_options_to_argv` helper function is shared between `--all` and `--recurse-submodules` fetches, and the `deepen` variable is a boolean that aggregates multiple deepening options (`--depth`, `--deepen-since`, `--shallow-exclude`). The patch must handle each option separately to avoid propagating malformed arguments.

Open questions and loose ends:
- Should submodule fetches inherit deepening flags from the outer fetch, or should submodule depth be controlled independently?
- How should the patch handle `--deepen-since` and `--shallow-exclude`? Propagating `--shallow-exclude` to submodules may be incorrect, as their histories are unrelated to the top-level repository.
- No objections to the core fix for `--all` have been raised, but the patch will need revision to address these scope and correctness concerns.
