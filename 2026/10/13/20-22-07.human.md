This is the first patch in a two-part feature series that hardens Git’s ignore-revs parser and tag-peeling logic before enabling a default ignore-revs file (`.git-blame-ignore-revs`). The patch is **queued for `next`** and addresses security concerns that arise when Git automatically reads upstream-controlled content from a well-known path.

The changes focus on two critical code paths: `oidset_parse_file_carefully()` in `oidset.c` and `peel_to_commit_oid()` in `builtin/blame.c`. The first now rejects any line containing an embedded NUL byte using `memchr()`, preventing silent truncation of object names (e.g., `<oid>\0garbage`). The second overhauls tag peeling to avoid promisor fetches in partial clones by using `odb_read_object_info_extended()` with `OBJECT_INFO_SKIP_FETCH_OBJECT` and `OBJECT_INFO_QUICK`, and verifies each tag’s declared type before parsing. This ensures missing tag targets or invalid OIDs in the ignore-revs file won’t trigger network requests or pack rescans.

The patch also adds thorough tests in `t/t8013-blame-ignore-revs.sh`, covering NUL-byte rejection, chained tag peeling, and missing tag targets in partial clones. The hardening is a prerequisite for the second patch, which will enable the default ignore-revs file, aligning Git’s behavior with hosting platforms like GitHub and GitLab. The implementation is **scalable and secure**, with no new symbols introduced, and the changes are narrowly scoped to the blame subsystem.
