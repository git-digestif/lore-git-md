This is the third patch in Patrick Steinhardt’s five-part series refactoring and optimizing alternates handling in Git’s object database (ODB) "files" backend. The series overall is a well-motivated internal cleanup that improves performance and simplifies the ODB source API.

This specific patch moves the logic for a "second read" attempt — triggered when an object lookup fails initially — from the generic ODB layer into the "files" backend. The second read is an internal mechanism that tells sources to reload any on-disk state (like packfiles) that might have changed since the first attempt, potentially surfacing the object on retry. Currently, this logic is exposed via the `OBJECT_INFO_SECOND_READ` flag in the public ODB API, even though it’s only relevant to the "files" backend.

Patrick’s change makes the second read an implementation detail of the "files" source, removing the need for the `OBJECT_INFO_SECOND_READ` flag entirely. The patch also adjusts the "packed" source to use `OBJECT_INFO_QUICK` instead of `OBJECT_INFO_SECOND_READ` to determine when to scan for objects hidden by a stale multi-pack index (MIDX). This is a minor behavioral tweak: the fallback may now trigger on the first read in some cases, but only when callers are already prepared to handle false negatives (i.e., when `OBJECT_INFO_QUICK` is set).

The changes are mechanical and confined to internal plumbing, with no user-visible impact. The patch looks clean and aligns with the series’ goal of simplifying the ODB source API.
