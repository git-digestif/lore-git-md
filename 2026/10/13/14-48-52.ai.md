This is the **v5 revision of the `git blame` default ignore-revs file series**, specifically the email where the author (Ravi Mistry) confirms the final design change in response to Junio C Hamano’s feedback. The series is now **feature-complete and queued for `next`**, with all prior feedback addressed.

The key update in v5 is the **shift to reading `.git-blame-ignore-revs` from the working tree in non-bare repositories**, matching the behavior of `.mailmap` and `.gitattributes`. This change resolves the last open design question from v4, where the author had initially opted to read `HEAD:.git-blame-ignore-revs` (matching hosting platforms like GitHub and GitLab) but Junio explicitly preferred the working-tree file for ergonomics—allowing users to test uncommitted changes without requiring commits. The v5 implementation uses `lstat()` and `open_nofollow()` to resolve the file, skipping non-regular files (e.g., symlinks, subdirectories) and falling back to `HEAD:.git-blame-ignore-revs` in bare repositories. The default file is added to the ignore-revs list **before** any user-configured files, ensuring user overrides take precedence, and empty entries in `blame.ignoreRevsFile` or `--ignore-revs-file ""` bypass the default entirely.

The series remains a **two-patch feature addition** to the blame subsystem. Patch 1/2 introduces **security hardening** to the ignore-revs parser and tag-peeling logic, including NUL-byte rejection, promisor fetch prevention in partial clones, and a **100MB size cap** to prevent memory exhaustion. Patch 2/2 implements the default file lookup, with edge cases handled for subdirectory invocations (limited to the repository root), bare repositories, and malformed input. The `the_repository` global variable has been replaced with `sb->repo` in the new `parse_default_ignore_revs_blob()` function, aligning with the ongoing `the_repository` removal effort. No new symbols are introduced; the changes modify existing blame logic (`peel_to_commit_oid()`) and the ignore-file parser (`oidset_parse_file_carefully()`).

The patch is **well-motivated and thoroughly tested**, with test coverage in `t/t8013-blame-ignore-revs.sh` for the new behavior. The **100MB size cap** (matching Git’s `ATTR_MAX_FILE_SIZE` for `.gitattributes`) and the working-tree file resolution address prior usability concerns raised by Phillip Wood, while the security hardening (NUL-byte checks, promisor fetch prevention) ensures robustness. The series aligns with hosting platform conventions while improving local ergonomics, and Junio’s explicit approval signals it is ready for integration. The only remaining loose end is the **NUL-byte check**, which the author has signaled willingness to adjust in a follow-up patch if Junio requests it—but this is a minor detail and does not affect the core functionality.
