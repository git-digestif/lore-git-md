This is a bugfix for `git fetch`. The patch addresses a regression in Git 2.56.0 where `--depth=` and `--unshallow` options are ignored when fetching from multiple remotes with `--all`. The author demonstrates the issue with a clear reproduction case: a shallow clone with two remotes fails to deepen its history when `git fetch --all --unshallow` is run, leaving the repository still shallow.

The fix itself is small and surgical: in `builtin/fetch.c`, the code now passes the `--depth` flag to the fetcher subprocess when `deepen` is set. The patch includes two new tests in `t/t5514-fetch-multiple.sh` that verify the corrected behavior for both `--depth=<n>` and `--unshallow` when used with `--all`.

The commit message is well-structured, showing the problem, the root cause (missing flag propagation), and the fix. The test coverage is thorough, exercising both the depth-limiting and unshallowing paths. This looks like a clean, well-motivated fix for a real-world usability issue.
