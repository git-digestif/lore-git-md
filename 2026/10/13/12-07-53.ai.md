This is the second patch in the v8 series fixing a race condition in Git’s `rerere` subsystem. It introduces a `--skip-locked` mode for `git rerere gc` to allow auto-maintenance tasks to silently skip garbage collection when the `MERGE_RR.lock` is held, preventing disruption to concurrent operations.

The patch updates `builtin/gc.c` to pass `--skip-locked` when running `git rerere gc` in auto mode, matching the established pattern for other maintenance tasks like `git gc --skip-foreground-tasks`. In `builtin/rerere.c`, the new flag is marked as hidden (`OPT_HIDDEN_BOOL`) and explicitly restricted to the `gc` subcommand to prevent misuse. The `rerere.c` locking logic now handles the `RERERE_NOWAIT` flag (zero timeout), returning `-1` if the lock is held, which callers treat as a silent skip rather than an error. Documentation in `Documentation/config/rerere.adoc` clarifies that `git maintenance run --auto` and `git gc --auto` use this mode to avoid disrupting concurrent operations.

Test coverage in `t/t4200-rerere.sh` verifies that `--skip-locked` skips when the lock is held but still prunes when it is free, and that the flag is rejected for non-`gc` subcommands. `t/t7900-maintenance.sh` confirms that auto-maintenance succeeds even when the lock is held, while manual runs fail as expected. The patch is technically complete, with all prior feedback incorporated, including Patrick Steinhardt’s suggestion to use the existing bitmask flag (`RERERE_NOWAIT`) instead of a dedicated enum. The series is ready for integration, with no unresolved technical concerns.
