This is the third patch in Patrick Steinhardt’s five-patch series refactoring and optimizing alternates handling in the Git object database’s "files" backend. The series is part of the broader ODB abstraction effort led by Patrick.

This patch moves the logic for the second object read (triggered when an object isn’t found on the first attempt) from the generic ODB layer into the "files" backend itself. The second read is an internal mechanism that tells sources to reload on-disk state (e.g., repreparing packfiles) in case the object appeared after the first lookup. Previously, this was controlled by the `OBJECT_INFO_SECOND_READ` flag, which is now removed entirely.

The change is motivated by the fact that alternates are now an implementation detail of the "files" backend, making it cleaner to handle the second read within that backend rather than in the generic ODB layer. The patch also adjusts the "packed" source to use `OBJECT_INFO_QUICK` instead of `OBJECT_INFO_SECOND_READ` to determine when to scan packfiles covered by a multi-pack index (MIDX) for objects that might be hidden due to a race with a concurrent maintenance task. This could theoretically cause an extra scan on the first read, but the impact is expected to be minimal.

The diffstat shows a net reduction of 40 lines, with changes spread across `odb.c`, `odb.h`, `odb/source-files.c`, `odb/source-loose.c`, `odb/source-packed.c`, and `odb/source.h`. The patch is mechanical and focused on internal plumbing, with no user-visible behavior changes. It looks well-crafted and aligns with the series’ goals of simplifying the ODB source API and removing redundant code. No controversy or open questions have been raised yet.
