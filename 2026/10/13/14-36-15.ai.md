This is the **second patch in the v5 series** that implements the default `.git-blame-ignore-revs` file lookup for `git blame` and `git annotate`. The patch is **feature-complete, well-tested, and queued for `next`**, with no unresolved technical objections. It directly addresses the core goal of the series: making `git blame` automatically respect `.git-blame-ignore-revs` (or `HEAD:.git-blame-ignore-revs` in bare repositories) when no explicit ignore file is configured, aligning local behavior with hosting platforms like GitHub and GitLab.

The implementation is careful and pragmatic. In non-bare repositories, it reads the **working-tree file** (not the committed blob), which Junio explicitly preferred as "more ergonomic" because it allows users to test uncommitted changes without requiring commits. This matches the behavior of `.mailmap` and resolves the last open question from v4. In bare repositories, it falls back to `HEAD:.git-blame-ignore-revs`, ensuring the feature works in all repository modes. The lookup is intentionally limited to the repository root to avoid performance costs and align with hosting platform conventions.

The patch enforces **strict safety checks** to handle upstream-controlled content safely. It uses `lstat()` and `open_nofollow()` to skip symlinks and non-regular files, and enforces a **100MB size cap** (matching Git’s existing `.gitattributes` limit) to prevent memory exhaustion. The ignore-revs parser (`oidset_parse_buffer_carefully()`) shares logic with the existing file-based parser and rejects malformed input (e.g., NUL bytes, invalid OIDs). User-configured ignore files take precedence over the default, and empty entries in `blame.ignoreRevsFile` or `--ignore-revs-file ""` bypass the default entirely, allowing users to override a malformed default file.

Test coverage is thorough, including edge cases like subdirectory invocations, bare repositories, CLI/config overrides, symlinks, overly large files, and comments/whitespace handling. The documentation updates clarify the new behavior and override semantics. The patch touches `builtin/blame.c`, `oidset.c`, `oidset.h`, and the blame documentation, and adds 233 lines of new tests to `t/t8013-blame-ignore-revs.sh`. No new user-facing options are introduced—it simply makes an existing feature more convenient.

The series as a whole is **ready for integration**, with the hardening in patch 1/2 serving as a prerequisite for this patch. The only remaining refinement (the NUL-byte check) is minor and can be addressed in a follow-up if needed. The patch is a clean, well-motivated feature that aligns with established conventions and improves the ergonomics of `git blame` without introducing complexity or risk.
