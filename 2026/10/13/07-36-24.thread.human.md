This thread is a focused refactoring and performance optimization of Git’s alternates handling in the object database’s "files" backend, now in its second iteration (v2) with six patches. The series, authored by Patrick Steinhardt, addresses inefficiencies in reading and streaming objects when alternates are present, followed by internal cleanup to simplify the ODB source API. No user-visible changes are intended, but the work is part of a broader effort to abstract the object database for future pluggable backends.

The v2 update incorporated a regression test (`t/t1500-alternates-performance.sh`) requested by Johannes Schindelin, which verifies that objects in alternate packfiles are prioritized over loose objects in the main repository—a key optimization in the first patch. The test, originally authored by Tyrie Vella, is portable and already used in Microsoft Git to fix the same performance issue. Justin Tobler has provided thorough, substantive reviews across all patches, endorsing the design decisions and confirming the technical rationale. His feedback on error handling in patch 4/6 was addressed in v2 with a new patch (5/6) that fails immediately with `ODB_READ_ERROR` when corrupt objects are encountered.

The latest exchange between Justin and Patrick clarifies minor implementation details in patch 3/6, such as the phrasing of the `OBJECT_INFO_QUICK` flag and the structure of an early loop termination. While Justin suggested small readability improvements, Patrick retained the current approach, noting it aligns with future work on alternates reloading. The discussion remains uncontroversial, with Justin affirming the patch "sounds reasonable." The only lingering architectural question—about the `ODB_FOR_EACH_OBJECT_LOCAL_ONLY` flag’s long-term viability—was deferred to a future series, as Patrick identified only two current callers (`git pack-objects --local` and a dubious use in `reachable.c`) and suggested the flag could be removed entirely. The series is under active review, with no major objections or unresolved technical concerns.
