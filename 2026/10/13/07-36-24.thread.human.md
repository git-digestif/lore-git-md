This thread is a six-patch refactoring and optimization series from Patrick Steinhardt, focused on improving alternates handling in Git’s object database (ODB) "files" backend. The series aims to address performance inefficiencies when reading or streaming objects from alternates, followed by internal cleanup to simplify the ODB source API. No user-visible changes are intended, and the on-disk format remains unchanged.

The series is now in its second iteration (v2), with all substantive feedback incorporated. Key changes include the addition of a regression test (`t/t1500-alternates-performance.sh`) to verify that objects in alternate packfiles are prioritized over loose objects in the main repository—a fix already validated in Microsoft Git. Justin Tobler’s feedback on error handling led to a new patch (5/6) that ensures corrupt objects fail immediately with `ODB_READ_ERROR` rather than attempting to fetch them from promisor remotes. This patch received Justin’s explicit approval in the latest email, confirming the fix is ready for integration. The final patch (6/6) removes the redundant `local` flag from the generic ODB source struct, retaining it only where needed in the packed source.

The series has seen thorough review from Justin Tobler, who provided substantive, tested feedback on all patches, and Johannes Schindelin, who focused on test coverage. The only unresolved concern is the long-term viability of the `ODB_FOR_EACH_OBJECT_LOCAL_ONLY` flag, which Patrick Steinhardt considers potentially redundant but deferred removal to a follow-up series. The series is now effectively ready for Junio to pick up, with no open technical objections or requests for changes. Expect it to move to `next` in the near future.
