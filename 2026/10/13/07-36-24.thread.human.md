This thread is about Patrick Steinhardt’s six-patch series (v3) refactoring and optimizing how Git’s object database (ODB) handles alternates in the "files" backend. The goal is to improve performance and simplify the internal API without changing user-visible behavior. The series is now in final review, with all substantive feedback from earlier versions addressed.

The fourth patch in the series (the one just summarized) removes a redundant read loop in `do_oid_object_info_extended()` by replacing it with a single explicit re-read after fetching objects from a promisor remote. This change eliminates the `while (1)` loop and `already_retried` flag, making the code easier to follow while preserving existing behavior. Justin Tobler, the primary reviewer, has already confirmed the design and implementation are correct. The patch is part of a broader effort to clean up the ODB’s internals, with earlier patches in the series optimizing alternates handling and moving retry logic into the "files" backend.

The series is now complete, with test coverage added to verify the performance optimizations and all prior feedback incorporated. The only unresolved question is the long-term viability of the `ODB_FOR_EACH_OBJECT_LOCAL_ONLY` flag, which Patrick and Justin agree could be removed in a future series but is left in place for now. The series is under active review, with no major objections remaining.
