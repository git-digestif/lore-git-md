This thread is a refactoring and performance optimization series for Git’s object database (ODB) alternates handling, authored by Patrick Steinhardt. The goal is to streamline the "files" backend’s internals—speeding up object lookups and streaming when alternates are present—while cleaning up the ODB source API. The series is now in its first version (v1) and under active review.

Key changes include reordering loops to prioritize packfile checks over loose-object `stat()` calls (yielding a 2x speedup in benchmarks), aligning object streaming with the direct-read optimization, and removing redundant code paths. No user-visible behavior or on-disk format changes are introduced. Justin Tobler has provided substantive reviews across all five patches, endorsing the design and implementation while raising minor technical questions—none of which have led to requested changes. The only open discussion points are a narrow error-handling question in patch 4/5 and a design-level concern about the `ODB_FOR_EACH_OBJECT_LOCAL_ONLY` flag in patch 5/5, though Justin explicitly called the latter "reasonable" and "moving in the right direction."

The series builds on Patrick’s earlier work migrating alternates handling into the files backend and is part of the broader ODB abstraction effort. All patches remain uncontroversial, with no outstanding objections or requests for revisions. The thread is now focused on clarifying rationale and future-proofing details, particularly around loop structure in patch 3/5, as Patrick prepares for follow-up work on alternates reloading.
