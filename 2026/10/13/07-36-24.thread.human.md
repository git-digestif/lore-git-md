This thread is a focused refactoring and performance optimization of Git’s alternates handling in the object database’s "files" backend, now in its second iteration (v2). The series, authored by Patrick Steinhardt, addresses inefficiencies in how Git reads and streams objects when alternates are present, particularly avoiding unnecessary `stat()` calls by checking packfiles before loose objects. The changes are internal—no user-visible behavior or on-disk format is altered—but the performance impact is measurable, especially in repositories with many alternates.

The series has evolved from five to six patches, with the latest update incorporating a regression test requested by Johannes Schindelin (Dscho). The test, authored by Tyrie Vella, verifies that objects in alternate packfiles are prioritized over loose copies in the main repository, ensuring the optimization works as intended. This test is already validated on SHA-1 and SHA-256 repositories and has been used in Microsoft Git to fix the same issue. Justin Tobler has provided substantive reviews across all patches, endorsing the design and implementation, though he raised concerns about the long-term viability of the `ODB_FOR_EACH_OBJECT_LOCAL_ONLY` flag, which Patrick acknowledged as a potential future cleanup target.

The series is now effectively complete from a technical standpoint, with the test integration addressing the last open request. The next steps are likely to involve final review of the updated patches, though no major design objections remain. The broader ODB abstraction effort, of which this series is a part, continues, with follow-up work planned for alternates reloading and further API simplifications.
