This thread is a six-patch refactoring series by Patrick Steinhardt aimed at optimizing and cleaning up the alternates mechanism in Git’s object database "files" backend. The series, now in its second iteration (v2), addresses performance inefficiencies in object lookups and streaming when alternates are present, achieving a 2x speedup in benchmarks, and simplifies the ODB source API by removing redundant code and flags. No user-visible behavior changes are intended.

Key changes include reordering loops to prioritize packfile checks over loose-object `stat()` calls (patches 1/6 and 2/6), moving the second object read logic into the "files" backend (patch 3/6), eliminating a redundant read loop in `do_oid_object_info_extended()` (patch 4/6), tightening error handling for corrupt repositories (patch 5/6), and, in the latest email, removing the `local` flag from the generic ODB source struct (patch 6/6). The series has been thoroughly reviewed by Justin Tobler, who provided substantive feedback on design and implementation, particularly around abstraction concerns. All patches are now uncontroversial and ready for integration.

The only remaining loose end is the long-term viability of the `ODB_FOR_EACH_OBJECT_LOCAL_ONLY` flag, which Patrick identified as potentially removable in a future series. The series is part of the broader ODB abstraction effort led by Patrick and is expected to merge to `next` once final approvals are complete. The net result is a cleaner, more efficient ODB API with no regressions in functionality.
