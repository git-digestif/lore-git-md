This thread is a five-patch series from Patrick Steinhardt refactoring and optimizing the alternates handling in Git’s object database "files" backend. The goal is to improve performance—particularly in object lookups and streaming when alternates are present—and clean up the internal ODB API without changing user-visible behavior. The series is now fully under review after v1 was posted, with no prior versions.

Key changes include reordering loops to prioritize packfile checks over loose-object `stat()` calls (yielding a 2x speedup in benchmarks), aligning object streaming with the new direct-read optimization, and removing redundant code like the `OBJECT_INFO_SECOND_READ` flag and a duplicate read loop in `do_oid_object_info_extended()`. The final patch, which Justin Tobler just reviewed, moves the `local` flag from the generic `struct odb_source` into the packed source, completing the API cleanup.

Justin has provided substantive reviews for all five patches, endorsing the design direction and implementation. His only open question—a minor one about error handling in patch 4—was already noted in the thread. On the final patch, he raised a design-level concern about the `ODB_FOR_EACH_OBJECT_LOCAL_ONLY` flag, calling it "leaky" now that the `local` flag is no longer generic. While he didn’t request changes, this could spark a follow-up discussion about whether the flag should be reworked. No objections or requests for revisions are blocking the series, and the optimizations and cleanups appear to have broad support. The series remains under review, with no merge status reported.
