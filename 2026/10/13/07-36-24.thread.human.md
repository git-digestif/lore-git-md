This thread is about Patrick Steinhardt’s six-patch series (`v2`) refactoring and optimizing how Git’s object database handles alternates in the "files" backend. The goal is to improve performance when reading objects from alternate repositories and to clean up the ODB source API without changing user-visible behavior.

The series is under active review, with all patches receiving substantive feedback from Justin Tobler, who has tested and endorsed the technical direction. Johannes Schindelin’s earlier request for a regression test—verifying that objects in alternate packfiles are checked before loose objects in the main repository—has been addressed with a new test (`t/t1500-alternates-performance.sh`) integrated into the first patch. The test is portable and already used in Microsoft Git to fix the same performance issue.

The key changes include reordering loops to prioritize packfiles over loose objects (patches 1/6 and 2/6), moving the "second read" logic into the "files" backend (patch 3/6), removing a redundant read loop in `do_oid_object_info_extended()` (patch 4/6), and two cleanup patches (5/6 and 6/6) that tighten error handling and remove a now-unused `local` flag from the ODB source API. The only open design question is the long-term viability of the `ODB_FOR_EACH_OBJECT_LOCAL_ONLY` flag, which Patrick has flagged for future removal but deferred for now.

In the latest exchange, Justin Tobler and Patrick agreed to defer a small but important error-handling improvement—immediately failing with `ODB_READ_ERROR` when an object is corrupt—to a follow-up commit, keeping the current series focused on refactoring. The series remains on track for integration, with no unresolved objections.
