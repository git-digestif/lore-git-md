This thread is about Patrick Steinhardt’s five-patch series refactoring and optimizing the alternates mechanism in Git’s object database "files" backend. The goal is to improve performance when reading and streaming objects from alternates and to clean up the ODB source API without changing user-visible behavior.

The series is under active review, with all patches receiving substantive feedback from Justin Tobler, who has tested and endorsed the technical direction of the first four patches. The first two patches address performance regressions in object lookup and streaming, achieving a 2x speedup in benchmarks. The third patch moves the second object read logic into the "files" backend, simplifying the ODB source API, while the fourth patch removes a redundant read loop in `do_oid_object_info_extended()`. The fifth patch, which removes an unused flag from the ODB source struct, is the only one not yet reviewed.

Justin Tobler’s latest review of the fourth patch raises a minor question about error handling—whether to fail immediately if the repository is corrupt rather than attempting to fetch a missing object—but otherwise confirms the patch’s rationale and implementation. The series remains uncontroversial, with no open design objections or requests for significant changes. The work builds on Patrick’s earlier `ps/odb-files-alternates` branch and is part of the broader ODB abstraction effort.
