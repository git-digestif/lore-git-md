This is the **v6 revision of a feature patch series** that makes `git blame` and `git annotate` automatically use `.git-blame-ignore-revs` (or `HEAD:.git-blame-ignore-revs` in bare repositories) as the default ignore-revs file when no explicit file is configured. The series is **queued for `next`** and addresses Junio’s polish-only feedback from v5, replacing a "cute hack" with a clearer implementation and removing an unused `.util` value.

The core change remains unchanged: the patch aligns local `git blame` behavior with hosting platforms (GitHub, GitLab) that already respect `.git-blame-ignore-revs` by default. The v6 update focuses on **code clarity** in the default file lookup logic. Instead of passing the scoreboard as `.util` (which was unused), the patch now sets `.util = (void *)1` with an explanatory comment, and propagates the ignore-revs file name (`i->string`) into `parse_default_ignore_revs()` to avoid hardcoding paths in multiple places. Documentation wording was also tweaked to use "configuration variable" instead of "config option."

The series is **feature-complete and well-tested**, with thorough coverage of edge cases (bare repositories, symlinks, CLI/config overrides, subdirectory invocations). The security hardening introduced in earlier versions — NUL-byte rejection, promisor fetch prevention, and a **100MB size cap** — remains intact. The working-tree file lookup in non-bare repositories (added in v5) continues to make it ergonomic to test uncommitted changes, a usability improvement noted by Junio and Phillip Wood.

Files touched: `builtin/blame.c`, `oidset.c`, `oidset.h`, `Documentation/blame-options.adoc`, `Documentation/config/blame.adoc`, and `t/t8013-blame-ignore-revs.sh`. No new symbols are introduced; the patch modifies existing blame logic to include the default file lookup while preserving user override semantics. The implementation is **scalable** (the `oidset` uses 32-bit integers, and the size cap prevents memory exhaustion) and **secure** (malformed input is rejected, and promisor fetches are avoided in partial clones).

This revision is a **final polish step** before integration. The author has addressed all prior feedback, and Junio’s latest comments were limited to code clarity rather than functionality. The patch is a **practical improvement** that reduces friction for users who rely on ignore-revs files, and its alignment with hosting platform conventions makes it a natural addition to Git’s blame subsystem.
