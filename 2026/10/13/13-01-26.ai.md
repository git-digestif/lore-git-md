This is a documentation patch that rewrites Git’s explanation of detached HEAD state. It is the second iteration of a standalone patch by Julia Evans, addressing feedback from Junio C Hamano and Kristoffer Haugsbakk.

The patch replaces the current verbose, diagram-heavy section in `git-checkout.adoc` with a concise, practical explanation in a new standalone guide (`gitdetached-head(7)`). The new text frames detached HEAD as useful for experimentation (e.g., testing commits, browsing history, or working with remote-tracking branches) and clarifies how users might end up in this state accidentally. It also highlights the 2019 UI improvement in `git switch` that makes accidental detachment harder, which was not previously advertised. The rewrite removes the word “unintentionally” from accidental-detachment scenarios and adds a concrete recovery example quoting Git’s warning message when commits are left behind.

Key changes in this version include: adding missing meson/Makefile changes to generate the new man page, renaming the guide to `gitdetached-head(7)` (hyphenated for consistency with existing guides), mentioning the 90-day reflog expiry period to temper concerns about “garbage” commits, and adding a cross-reference to `git help datamodel` for deeper context. The patch also updates the advice message in `advice.c` to point to the new guide instead of the `git-checkout` man page.

The patch is well-motivated and addresses a common pain point for Git users, particularly beginners. The rewrite is clear, avoids overly technical diagrams, and makes the concept more accessible. The addition of a standalone guide is a practical improvement, allowing users to quickly access focused help. Build-system omissions from the first version are now addressed, and the patch is ready for integration. Julia Evans plans to follow up with a separate patch to hyphenate `gitmergeconflicts` for consistency and may revisit the broader help-system usability concern (internal cross-references vs. `git help`) in the future.
