This thread introduces a configurable timeout (`core.indexLockTimeout`, default 1 second) for Git’s index lock to reduce contention between background IDE `git status` calls and user commands like `add` or `commit`. The series, authored by Jun Wu, lets commands wait briefly for the lock instead of failing immediately, while avoiding race conditions by skipping the wait if the index was already read before locking. A key side effect is fixing a 20-year-old race condition in `git commit`, where concurrent index updates (e.g., from `git add`) could be silently discarded if the commit read the index before acquiring the lock.
