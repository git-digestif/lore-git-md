This is the fourth patch in Patrick Steinhardt’s five-patch series refactoring and optimizing alternates handling in the Git object database’s "files" backend. The patch removes a redundant read loop in `do_oid_object_info_extended()` in `odb.c`, simplifying the logic for handling object lookups.

The change is a direct follow-up to the earlier migration of alternates handling into the "files" backend (from Patrick’s `ps/odb-files-alternates` branch). Previously, the function used a loop to handle retries after fetching missing objects from promisor remotes, but now that the retry logic is managed within the backend itself, the loop is unnecessary. The patch replaces the loop with a single explicit re-read after fetching from a promisor remote, making the code easier to follow.

The diff is confined to `odb.c` and reduces the function’s complexity without altering behavior. The patch is mechanical and aligns with the series’ goal of cleaning up internal ODB plumbing. No performance impact is expected, and the change is uncontroversial given its scope and the author’s established expertise in this area.
