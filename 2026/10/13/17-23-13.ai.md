This is a feature patch series introducing a configurable timeout for Git's index lock, motivated by IDE workflows where background `git status` calls conflict with user-initiated commands like `git add` or `git commit`. The series adds a new `core.indexLockTimeout` configuration option (defaulting to 1 second) and adjusts the lock acquisition order in `git commit` to respect the timeout.

The cover letter clearly explains the problem: IDEs running periodic `git status` either degrade performance (with `--no-optional-locks`) or cause lock contention with user commands. The solution allows commands to wait briefly for the lock rather than failing immediately. The author acknowledges edge cases (skipping the wait if the index was read before locking to minimize race windows) and explicitly lists which commands support the timeout (e.g., `add`, `checkout`) versus those that don’t (e.g., `rebase`, `merge`).

Patch 1 implements the timeout mechanism and configuration, while Patch 2 modifies `git commit` to lock the index *before* reading it, ensuring the timeout applies. The series includes a new test script (`t/t0032-index-lock-timeout.sh`) and references prior discussions (including a 2017 proposal by Jeff King and the 2017 `--no-optional-locks` feature). The default timeout of 1 second is justified in the first patch but left open to debate.

Key technical details for follow-up discussion:
- **Files touched**: `repository.c` (core logic), `builtin/commit.c` (lock order change), `Documentation/config/core.adoc` (config docs), and test files.
- **Config key**: `core.indexLockTimeout` (integer, milliseconds).
- **Behavior**: Commands wait up to the timeout for the lock unless the index was already read (to avoid write races).
- **Commands supporting timeout**: `add`, `rm`, `mv`, `checkout`, `restore`, `read-tree`, `apply`, `update-index`.
- **Commands *not* supporting timeout**: `reset`, `stash`, `merge`, `rebase`, `cherry-pick`, `am`.
- **Test coverage**: New script `t0032-index-lock-timeout.sh` and additions to `t0031-lockfile-pid.sh` and `t7400-submodule-basic.sh`.

The series is well-motivated and addresses a real pain point for IDE users. The implementation appears targeted (focusing on common commands first) and includes safeguards against race conditions. The default timeout may spark debate, but the author is open to adjusting it. Test coverage looks adequate for the scope.
