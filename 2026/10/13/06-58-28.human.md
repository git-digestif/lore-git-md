This is a platform compatibility bugfix targeting macOS and other environments where external tools rewrite files with CRLF line endings, causing `git status` to incorrectly report modifications. Curtis Allen Smith sends v4 of the patch, which refines his earlier work to address a long-standing flaw in Git's index comparison logic: `ie_modified()` in `read-cache.c` has historically treated any size change as conclusive evidence of modification, even when clean filters or CRLF conversion could legitimately alter file size without changing content.

The patch inlines the fix directly into `ie_modified()`, removing the helper function introduced in v3. When a file's size changes and conversion is active (checked via `would_convert_to_git()`), Git now falls through to `ce_modified_check_fs()` to verify whether the size change reflects actual modification, rather than trusting the size difference alone. This change adds just 4 lines to `read-cache.c` and 45 lines of new tests in `t/t0020-crlf.sh`, covering both CRLF rewrites and lone-CR edge cases.

Benchmark data from Curtis shows the performance impact is negligible in most cases: a clean tree pays nothing, and a tree without conversion pays only one attribute lookup per size-changed file. The overhead becomes noticeable only when conversion is active *and* the file content genuinely differs (e.g., 25ms → 137ms for 10,000 files). The patch also includes a follow-up optimization that could reduce this overhead further if needed.

The architectural debate remains unresolved. Johannes Sixt argues the fix should target `git add` (ensuring the index records the correct post-conversion size), while Curtis maintains the fix belongs in `git status` (correcting a false positive in `ie_modified()`'s detection logic). This v4 does not address that fundamental disagreement, but it does clarify the commit message and simplify the implementation.

The patch is well-motivated and technically sound, with thorough test coverage and performance data. The unresolved architectural question is the main obstacle to merging, but the current approach is a pragmatic solution to a real problem affecting macOS users. If you work with CRLF line endings or clean filters, this patch is worth following.
