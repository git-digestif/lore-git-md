This is a bugfix report for a **performance regression** in `git log --follow`.

Patrick Steinhardt forwards a user report that `git log --stat --follow -- <file>` has become dramatically slower in Git 2.56. The command takes about 33 seconds in Git 2.55 but nearly 8 minutes in Git 2.56 when run on the Linux kernel repository. The regression was bisected to commit 304812ed33 ("log: improve --follow following renames for non-linear history", June 2026). The original author of that commit is CC’d, but Patrick has not yet investigated further.

The patch itself is not included—this is a heads-up to the list rather than a fix. The report is clear and actionable: a specific commit is identified, a real-world repository is provided, and the performance impact is quantified. Anyone interested in `git log` performance or rename detection should pay attention, as the regression appears to be a side effect of a recent improvement.
