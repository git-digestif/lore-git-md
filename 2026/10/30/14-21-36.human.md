This is a **bugfix patch** targeting the worktree subsystem. It makes `git worktree remove` refuse to delete a worktree that is in the middle of a rebase, `git am`, bisect, cherry-pick, or revert sequence unless `--force` is given. This aligns with Git’s general principle of protecting uncommitted or in-progress work and fixes a pre-existing bug that could lead to data loss.

The patch is the first in a two-part series that also extends `git for-each-ref`'s `%(worktreepath)` atom to report worktree paths for rebasing or bisecting branches. The two changes are complementary: the `%(worktreepath)` enhancement makes it easier to identify worktrees in progress, while this patch ensures those worktrees cannot be accidentally deleted. The series is well-motivated and addresses a real safety gap that becomes more pressing once the second patch lands.

The implementation is clean and thorough. It adds a new helper function `check_no_operation_in_progress()` that uses existing `wt_status_*` functions to detect rebase, `git am`, bisect, and sequencer state. The check is only performed when the worktree directory exists, preserving the existing behavior for already-deleted worktrees. The documentation is updated to clarify that a worktree in the middle of an operation is not considered "clean," and the tests cover all the edge cases: rebase (including stopped at an "edit" or "break"), `git am`, bisect, and cherry-pick/revert sequences. The error messages are specific and actionable, telling the user exactly what operation is in progress and how to override the refusal.

This is a clear improvement over the current behavior, where `git worktree remove` would silently delete a worktree in the middle of an operation as long as its files were clean. The change is backward-incompatible for scripts that rely on being able to delete in-progress worktrees without `--force`, but the commit message does not mention any such scripts, and the safety benefit outweighs the risk. The patch is ready for review and looks like a straightforward fix for a real problem.
