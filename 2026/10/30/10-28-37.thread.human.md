This thread is about a bugfix for `git cat-file` that addresses a serious type mismatch when handling large objects. The issue, reported and fixed by Elia Pinto, occurs when object lengths exceeding 2GiB are passed as an `int` to `batch_write()`, causing memory corruption or truncation. The fix is straightforward: changing the parameter type to `size_t` to match the return types of `odb_read_object()` and `filter_object()`.

The patch itself is minimal—just one line in `builtin/cat-file.c`—and the commit message clearly explains the problem, its impact, and the fix. While no tests are included (due to the impracticality of testing with multi-gigabyte objects), the change is well-justified and aligns with the types used by `fwrite()` and `write_or_die()`. This is the fourth patch in a 6-patch series, though the broader context of the series isn’t provided here.

So far, there’s no review feedback or maintainer response, so the patch remains under review. If accepted, it should resolve a latent bug affecting large-object handling in `cat-file --batch`.
