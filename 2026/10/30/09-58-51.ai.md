This is the second patch in Elia Pinto’s **v2 series fixing 64-to-32 truncations on Windows (LLP64 platforms)**. It targets a **crash bug in the word-diff subsystem** caused by integer overflow when allocating buffers for large diffs.

The patch converts the allocation size tracking in `struct diff_words_buffer` and `diff_words_fill()` from `unsigned long`/`long` to `size_t`. On Windows, where `long` is 32 bits, the current code overflows when the buffer grows past ~700 MiB, leading to undefined behavior (in practice, a negative size passed to `REALLOC_ARRAY()`, which triggers a fatal allocation error). The fix aligns the allocation logic with the `size_t` type already used for `mmfile_t` sizes (per Jeff King’s 2026 commit `3c7a31204f`), eliminating the overflow risk.

The change is minimal (two lines in `diff.c`) and purely mechanical, with no behavior change on 64-bit Linux. It prevents a crash on Windows when processing large diffs, particularly in scenarios where the word-diff output exceeds 1 GiB (e.g., files with many small changes). The patch also future-proofs the code against potential truncation if the `MAX_XDIFF_SIZE` limit is ever lifted.

This patch directly addresses feedback from the **v1 review** (no test coverage was requested here, as the crash is deterministic and covered by existing diff tests). The series as a whole is now **ready for integration**, with all prior concerns resolved.
