# Thread deltas

## 2026/10/30

- [2026/10/30/12-12-50 by Johannes Schindelin via GitGitGadget <gitgitgadget@gmail.com>] Johannes Schindelin posted a patch adding `Documentation/gitsecurityboundary.adoc`, a new man page defining Git's security boundary around unexpected or implicit execution of attacker-controlled code, and wired it into `git.adoc`, `SECURITY.md`, `command-list.txt`, and the build files.
- [2026/10/30/12-12-50 by Johannes Schindelin via GitGitGadget <gitgitgadget@gmail.com>] The commit message explains that a proposed `git --safe` mode is deliberately left out because enumerating every execution-capable mechanism would create a snapshot of today's attack surface that rots as new mechanisms appear and would provide a false sense of safety.
- [2026/10/30/12-12-50 by Johannes Schindelin via GitGitGadget <gitgitgadget@gmail.com>] The patch notes the document was rewritten by Toon Claes after review, with substantial shaping by Patrick Steinhardt and Junio C Hamano, and that it follows a git-security mailing list discussion that concluded without objection to making the boundary public.

## 2026/11/01

- [2026/11/01/18-31-47 by Junio C Hamano <gitster@pobox.com>] Junio C Hamano reviewed the security boundary documentation patch, noting that the often-forgotten point about serving an untrusted repository to `git clone` exposing `git-upload-pack` was nice to see mentioned, that `git help upload-pack` also mentions this facility, and that the document overall was a pleasant read.
