This is the second patch in Patrick Steinhardt’s three-patch bugfix series for `git grep --recurse-submodules`. It is a **defensive refactoring** that preemptively fixes a latent bug in the handling of sparse directory trees.

The patch changes a single line in `grep_cache()`: instead of reading sparse directory trees via `the_repository->objects`, it now uses the repository instance (`repo->objects`) that was passed into the function. The commit message explains that while this bug cannot currently be triggered (because submodule indices are always expanded to full indices), the code is still wrong and would become a real issue if submodules ever start using sparse indices. This is a classic "belt-and-suspenders" change—small, targeted, and motivated by future-proofing rather than an immediate regression.

The change is mechanical and low-risk: it mirrors the fix in patch 1/3, which addressed the same issue for regular trees. The patch touches only `builtin/grep.c` and does not introduce new symbols or change on-disk formats. No new tests are added here, as the existing test coverage in `t/t7814-grep-recurse-submodules.sh` (introduced in patch 1/3) already verifies the broader behavior of grepping nested submodules.

This patch is part of the ongoing effort to eliminate implicit reliance on `the_repository`, though it is not itself a major step in that direction. The series as a whole is well-motivated, clearly scoped, and intended for backporting to stable branches.
