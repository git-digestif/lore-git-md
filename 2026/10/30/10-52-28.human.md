This is the fourth patch in Harald Nordgren’s v13 series implementing `remote.<name>.fetchRefmap` for a "matching-inspired" fetch mode. The patch adds a `--limited-fetch` flag to `git remote add`, which configures the new `remote.<name>.fetchRefmap` key (e.g., `*@{upstream}`) instead of the traditional wildcard `remote.<name>.fetch` refspec. This ensures that a refspec-less `git fetch <remote>` only fetches branches already tracked by local branches, addressing the performance issue in shallow repositories where fetching all remote branches is wasteful.

The implementation is straightforward: when `--limited-fetch` is specified, the patch sets `remote.<name>.fetchRefmap` to `+refs/heads/*:refs/remotes/<name>/*` and skips setting `remote.<name>.fetch`. The flag is rejected when combined with `-t/--track` or `--mirror`, as those options already specify what to fetch. The documentation update clarifies the flag’s purpose and links to `git-fetch` for details on `fetchRefmap`. The test coverage verifies that `--limited-fetch` works in a full repository and correctly conflicts with `-t`.

This patch is a small but essential piece of the series, enabling users to opt into the new fetch mode when adding a remote. The implementation is clean and aligns with the series’ design goals, with no unresolved technical concerns. The only remaining discussion for the series as a whole is the override semantics for command-line refspecs, which does not affect this patch. The patch is ready for review and likely to graduate with the rest of the series once the override semantics are finalized.
