This is a documentation patch that introduces a new man page, `gitsecurityboundary(7)`, to formally define Git's security boundary. The patch is authored by Toon Claes with substantial contributions from Johannes Schindelin, Patrick Steinhardt, and Junio C Hamano.

The motivation is clear: the Git project receives a high volume of security reports, many of which are valid bugs but fall outside Git's security boundary. Currently, there is no single document that explains what Git considers a vulnerability, leading to confusion for reporters and maintainers alike. This patch consolidates years of scattered documentation and individual fixes into a coherent, authoritative statement.

The new document explains that Git's security boundary concerns *unexpected or implicit execution of attacker-controlled code*. It distinguishes between inspecting repository contents (which is safe) and executing them (which requires explicit user consent). The document walks through key concepts: sanitized clones, untrusted repository contents, unexpected code execution, reading/writing outside the repository, user intent, protected configuration, and local disk access. It cites specific commits and CVEs to ground the principles in real-world cases.

The patch also updates `SECURITY.md` to link to the new document and adds the man page to the build system. The commit message is thorough, explaining the rationale, the collaborative process, and the decision not to include a `--safe` mode (which would require substantial refactoring and risk providing a false sense of security).

This looks like a well-crafted, overdue contribution. It directly addresses a recurring pain point for the project and provides a firm foundation for triaging future security reports. The involvement of Junio and Patrick suggests it has strong support. If the content holds up under review, it is likely to be merged.
