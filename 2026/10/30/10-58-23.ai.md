This is the second patch in a two-patch bugfix series addressing silent truncation of trees larger than 4 GiB in Git’s tree-walk subsystem. The series converts size fields in `struct tree_desc` and `struct tree` from 32-bit types (`unsigned int` and `long`) to `size_t`, which is 64-bit on all relevant platforms, ensuring no entries are silently ignored.

This patch specifically updates `struct tree` in `tree.h` and the `parse_tree_buffer()` function in `tree.c` to use `size_t` for the tree buffer size. The change aligns the type with the size returned by `odb_read_object()` (already a `size_t`) and ensures consistency with the first patch, which updated `struct tree_desc`. The commit message notes that `parse_object_buffer()` still passes an `unsigned long` to `parse_tree_buffer()`, but this is left for a future change to avoid scope creep.

The patch is minimal and focused, touching only two files and changing three lines. It directly addresses the truncation issue on Windows (where `long` is 32-bit) and is part of a broader effort by the author to eliminate size truncations across Git. No test coverage is included for the 4 GiB boundary, as constructing such a large tree in-memory is impractical, but the author verified the fix with a simulated 16-bit environment. The series is under review with no feedback yet, but the changes appear technically sound and low-risk.
