The **core problem** is that Git's loose object backend does not validate that the decompressed size of an object matches the size declared in its header during streaming. This can lead to **silent corruption**: commands like `git cat-file blob` may exit successfully while producing incorrect output for malformed objects (e.g., a stream shorter or longer than the header claims). Patch 3/6 (this email) adds a running counter (`total_read`) to the `odb_loose_read_stream` struct and checks, at the end of the zlib stream, whether the total bytes read match the expected size from the header. If not, Git now reports the object as corrupt and returns an error. The fix is minimal, touching only `odb/source-loose.c` and adding two new test cases in `t/t1006-cat-file.sh` to verify failure for under-sized and over-sized loose objects.

**Key technical details**:
- **Files touched**: `odb/source-loose.c`, `t/t1006-cat-file.sh`.
- **New symbols**: `total_read` field in `odb_loose_read_stream` struct.
- **Behavior change**: `git cat-file` now fails with an error if the decompressed size of a loose object does not match its header-declared size (previously, it exited successfully with incorrect output).
- **Test coverage**: New test cases use the existing `loose_obj` helper to create malformed objects and verify that `git cat-file` fails with an appropriate error message.
- **Other patches in the series**: Fix a memory leak in `odb_loose_free()` and improve error handling in `odb_loose_filter()`.
