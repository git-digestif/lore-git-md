This is a six-patch bugfix series from Elia Pinto targeting loose object size handling, with particular attention to LLP64 platforms (64-bit Windows, where `long` is 32 bits but `size_t` is 64 bits). The patches address both platform-specific truncation issues and general missing size checks that could lead to out-of-bounds memory access or uninitialized memory exposure.

The series stems from a cross-compiled MinGW build and clang-tidy analysis using `-Wshorten-64-to-32`. Patches 1/6 and 3/6 fix missing size validation in the loose object reader and streaming reader, respectively, allowing Git to accept objects whose zlib streams don’t match their header-declared sizes. These affect all platforms and come with lightweight tests that fail without the fixes. The remaining patches (2/6, 4/6, 5/6, 6/6) address Windows-specific truncation issues in loose object sizes, `git cat-file --batch`, notes concatenation, and text diffing, where sizes between 2 GiB and 4 GiB can overflow buffers. These lack tests due to the impracticality of generating multi-gigabyte objects in the test suite, but the commit messages describe reproduction steps.

The fixes are straightforward: replacing `unsigned long` with `size_t` where appropriate and adding bounds checks. Patch 5/6 temporarily uses `cast_size_t_to_ulong()` to maintain compatibility with the current `odb_write_object()` interface, which will become unnecessary once Patrick Steinhardt’s "use size_t for a few more object and buffer sizes" series (referenced in the cover letter) lands. The series is based on `master` (b9e5cff180) and has no conflicts with that work.

Elia preemptively sent all but patch 3/6 to the git-security list; they were deemed non-security issues, so the series is now public. The patches look well-motivated and technically sound, addressing real bugs with clear reproductions or test cases. The Windows-specific issues are particularly noteworthy given the platform’s growing adoption in enterprise environments. This is a solid bugfix series that should attract attention from reviewers familiar with the object storage layer.
