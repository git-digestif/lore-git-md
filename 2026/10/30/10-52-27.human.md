This is the third patch in Harald Nordgren’s v13 series introducing `remote.<name>.fetchRefmap` for matching-inspired fetch mode. The series is now under final review for merging to `master` and is expected to graduate soon.

This patch implements the core dynamic branch selection logic: when neither `remote.<name>.fetch` nor command-line refspecs are given, but `remote.<name>.fetchRefmap` is configured, `git fetch` now infers which branches to fetch by enumerating local branches whose `@{upstream}` points to the remote. The refmap itself only controls where those fetched refs land, not which branches are selected. The new `branches_tracking_remote()` helper in `remote.c` drives this logic, walking every local branch and delegating to the existing `collect_upstream_from_remote()` to build the list of source refs.

The implementation is mechanical and well-tested. The patch updates `builtin/fetch.c` to call `branches_tracking_remote()` when the conditions are met, builds a temporary refspec, and passes it through the existing `get_fetch_map()` machinery. Documentation in `remote.adoc` and `fetch-options.adoc` is updated to clarify the new behavior, and the new test script `t/t5586-fetch-refmap.sh` exercises the dynamic branch selection with scenarios that verify tracking relationships, prefetch behavior, and edge cases like branches tracking a different remote.

No new design questions are raised; this patch simply wires up the plumbing whose design was finalized in earlier revisions. The only remaining open question for the series is the override semantics for command-line refspecs, which is orthogonal to this patch and will be resolved in v14. The patch is ready for review and looks uncontroversial.
