This is a brief, positive review from Patrick Steinhardt on the final version of the documentation patch that clarifies how Git checks SSH key lifetimes (`valid-before`/`valid-after`). The patch, sent by Christian Noé Ramos López, updates `Documentation/config/gpg.adoc` to explicitly state that Git uses the committer or tagger date (not the signature timestamp) for these checks, and warns that this provides no security guarantees because the signer controls the timestamp. Patrick’s feedback here is a straightforward endorsement—"this version looks good to me"—confirming that the wording he proposed in earlier discussion has been incorporated satisfactorily.

The patch is part of a broader security thread addressing two critical flaws in Git’s SSH signing verification: (1) the time-of-signature confusion (now documented) and (2) the revocation file failing open (fixed by a separate security patch). This documentation patch directly resolves the first issue by making the behavior and its limitations clear to users. The thread’s consensus was to document the current behavior rather than attempt a technical fix, as enforcing signature timestamps in a distributed system is impractical. Patrick’s review here signals that the final wording—"Git validates the signature by checking the committer or tagger timestamp is within the validity time range. This does not provide any security guarantees as the timestamp can be chosen arbitrarily by the signer"—is both accurate and appropriately concise.

The patch is ready for integration and carries `Helped-by` trailers from Junio C Hamano, Phillip Wood, and Patrick Steinhardt, indicating broad agreement. It is a standalone documentation change with no test coverage required, and the commit message clearly references the earlier discussion. Junio’s "What's cooking" report (October #09) lists this patch as ready, though it may be held alongside the revocation file fix to avoid splitting security fixes across releases. For a busy reader, this email is a simple confirmation that the documentation patch is now in its final, approved form.
