Subject: [PATCH 0/3] grep: fix reading objects in nested submodules
Series version: v2 (updated commit message only)
Originating author: Patrick Steinhardt
Thread type: bugfix patch series

Core problem or goal
The `git grep --recurse-submodules` command fails when grepping nested submodule trees because it incorrectly reads objects from `the_repository` instead of the submodule’s own repository instance. The regression was introduced in 93cd344e34f (September 2026) and affects all versions since Git v2.56.0. The goal is to fix this bug, add test coverage for nested submodule trees, and apply defensive checks to related code paths (sparse directory trees and `.gitmodules` file reading) to prevent similar issues.

Current status
Under review; v2 posted. The only change from v1 is the commit message in patch 1/3 now explicitly states the regression shipped in Git v2.56.0. No merge status reported. Series is based on Git v2.56.0, indicating intent for backporting to stable branches.

Key technical details
- Files touched: `builtin/grep.c`, test script `t/t7814-grep-recurse-submodules.sh`
- New behavior: submodule trees, sparse directory trees, and `.gitmodules` files are read via their correct repository instance (`repo->objects` instead of `the_repository->objects`). Patch 1/3 updates `grep_tree()` for submodule trees, patch 2/3 updates `grep_cache()` for sparse directory trees (line 560), and patch 3/3 updates `.gitmodules` reading (line 886) by replacing `the_repository` with `opt->repo` in `gitmodules_config_oid()`.
- Symbols: `grep_tree()`, `grep_cache()`, and `grep_objects()` consistently use the repository parameter passed to them; no new symbols introduced.
- Test coverage: new test in `t/t7814-grep-recurse-submodules.sh` (added in patch 1/3) verifies grepping nested submodule trees by setting up a two-level repository hierarchy (superproject with a submodule containing both top-level and nested files) and confirming matches are found in both locations. No additional test coverage for sparse directory trees or `.gitmodules` reading (existing tests exercise these code paths).
- On-disk format: no changes.
- Regression commit: 93cd344e34f (September 2026) introduced the bug by not adapting tree-reading logic after blobs were switched to use the submodule’s repository.
- Scope limitation: the `--no-index` case remains unaddressed due to its complexity, keeping the series focused and low-risk.
