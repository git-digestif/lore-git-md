This is the fifth and likely final version of a **documentation** patch series that replaces the outdated `gittutorial` man page with a modern, beginner-focused two-part guide. The series is now in excellent shape for merging to `next` and has already been queued in Junio’s `seen` branch.

The new tutorial is the result of extensive user testing—112 beta testers, most of whom completed it successfully. It covers local repository creation and commits in Part 1, and pushing to a remote host (GitHub/GitLab) in Part 2. The author, Julia Evans, has incorporated all substantive and surface-level feedback from prior rounds, including platform-specific adjustments for Windows users (Git Credential Manager for authentication, Git Bash as the recommended shell), clearer SSH key instructions, and neutral, practical guidance for escaping `vi` without judgmental language. The only remaining procedural nit—a missing cross-reference update in `Documentation/git.adoc` that breaks `make check-docs`—was acknowledged by Junio but not treated as a blocker.

This version (v5) makes two final tweaks: replacing a vague pronoun ("it") with "GCM" (Git Credential Manager) in the commit message to avoid ambiguity, and removing trailing whitespace flagged by CI. The series touches only `Documentation/gittutorial.adoc`, deleting the old content and replacing it entirely. No code or behavior changes are involved, and the new tutorial is compatible with Git 2.23.0+ (due to `git switch` usage).

The author frames the tutorial as "good enough" for merging, with plans to gather post-merge user feedback to refine branching and collaboration content in future iterations. The urgency to merge stems from funding constraints, but the patch is uncontroversial and well-motivated. Two open pedagogical questions remain—whether to start with `git init` or `git clone`, and whether to adopt newer `git config set` syntax—but neither blocks integration. Junio has explicitly called the series "in a pretty good shape to be merged to 'next'," and the procedural nit is minor enough to address in a follow-up if needed.
