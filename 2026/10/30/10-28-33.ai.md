This is a **bugfix series** targeting loose object handling and size truncation issues, primarily on LLP64 platforms (e.g., 64-bit Windows where `long` is 32-bit but `size_t` is 64-bit). The series addresses six distinct problems, two of which affect all platforms (missing size checks in loose object parsing) and four of which are Windows-specific (truncation/overflow bugs due to `long` vs. `size_t` mismatches). The patches are authored by Elia Pinto and are based on `master` (b9e5cff180).

The motivation stems from a systematic audit using MinGW cross-compilation and `clang-tidy` with `-Wshorten-64-to-32`, followed by manual inspection of value propagation to identify potential out-of-bounds memory accesses. Patches 1/6 and 3/6 fix missing size checks in the loose object reader, which could expose uninitialized heap memory or silently truncate objects. These are accompanied by tests that fail without the fixes. The remaining patches (2/6, 4/6–6/6) address truncation/overflow issues in specific subsystems (`cat-file`, `notes`, and `diff`) on Windows, where `long` is 32-bit. Reproduction steps for these are described in commit messages, as they require multi-gigabyte objects or 32-bit `long` environments.

Key technical details include:
- **Files touched**: `object-file.c`/`object-file.h` (core loose object handling), `odb/source-loose.c` (streaming reader), `builtin/cat-file.c`, `notes.c`, and `diff.c`.
- **Functions modified**: `unpack_loose_header()`, `stream_loose_object()`, `batch_write()`, `concat_notes()`, and `count_trailing_blank()`.
- **Types changed**: Several `unsigned long` variables are converted to `size_t` to avoid truncation on LLP64 platforms.
- **Test coverage**: New tests in `t/t1006-cat-file.sh` and `t/t1060-object-corruption.sh` validate the fixes for patches 1/6 and 3/6; other patches rely on manual reproduction steps due to their platform-specific nature.

The series was initially sent to the `git-security` list for review, but the issues were deemed non-security-sensitive. It does not conflict with the related "use size_t for a few more object and buffer sizes" series (also by Elia), as the changes are complementary. The patches are well-motivated, with clear commit messages explaining the bugs, their impact, and the fixes. The Windows-specific issues are particularly noteworthy, as they highlight latent bugs that could cause crashes or memory corruption in large repositories on that platform. The inclusion of tests for the cross-platform fixes adds confidence in the correctness of the changes.
