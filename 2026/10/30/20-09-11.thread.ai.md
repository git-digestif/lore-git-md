Core problem or goal
Restore usable performance for `git log --follow` on repositories with many merge commits. The feature regressed severely in commit 304812ed33 (June 2026), causing a test case on linux.git to balloon from 28 seconds to nearly 7 minutes. The goal is to reduce the number of expensive rename-detection passes during merge diffs while preserving correctness.

Current status
Under review. This is the fifth patch in a v4 series; prior versions addressed feedback but did not change the core two-pass strategy. The patch is not yet in any of Junio’s integration branches.

Key technical details
- **File touched**: `log-tree.c`
- **New symbols**: `commit_has_path()`, `follow_needs_renames()`
- **Behavior change**: Two-pass diff strategy for merges under `--follow`:
  1. Diff without rename detection to find a parent where the path is unchanged.
  2. Only perform rename detection against parents where the path might have been renamed (determined via merge-base checks).
- **Performance impact**: Test case now takes 36 seconds (down from ~7 minutes), close to the pre-regression baseline of 28 seconds.
- **On-disk format**: No changes.
- **Test coverage**: Performance regression test case included in the series (not detailed in this patch summary).
