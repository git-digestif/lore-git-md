This is patch 1/3 of a bugfix series targeting `git grep --recurse-submodules`. The patch fixes a regression introduced in 93cd344e34f (September 2026) where `git grep` fails when grepping nested submodule trees because it incorrectly reads tree objects from `the_repository` instead of the submodule’s repository instance. The fix is minimal: it changes a single line in `builtin/grep.c` to use `repo->objects` (the submodule’s object database) instead of `the_repository->objects`. The patch also adds a new test in `t/t7814-grep-recurse-submodules.sh` that verifies the fix by grepping a submodule with nested directories, ensuring the command now correctly reads objects from the submodule’s repository.

The regression is well-documented: the commit message explains the broken logic (trees were not adapted to use the submodule’s repository after blobs were), cites the exact commit that introduced the issue, and links to a bug report. The test coverage is thorough, adding a scenario that specifically exercises nested submodule trees, which the existing tests did not cover. The change is low-risk, touching only the object-reading path in `grep_tree()`, and aligns with the broader effort to eliminate implicit reliance on `the_repository`.

This patch is the core fix for the series; patches 2/3 and 3/3 extend the same pattern to sparse directory trees and `.gitmodules` file reading as defensive measures. The series is based on Git v2.56.0, indicating it’s intended for backporting to stable branches.
