This is a surface-level review of the second patch in Tanga Joris’s v3 series, which removes the `NO_PARSEOPT` flag from four Git built-in commands (`diff-pairs`, `fast-import`, `patch-id`, and `var`) in `git.c`. The patch itself is uncontroversial and ready to merge, but Kaartic Sivaraam suggests adding a test to prevent future regressions where commands converted to `parse-options` might still be marked with `NO_PARSEOPT`.

Sivaraam’s proposed test would generate a list of commands still using `NO_PARSEOPT` and verify that none of them respond to `--git-completion-helper` with valid options (except for a few commands like `diff` that parse their own options but delegate some to `parse-options`). The test is motivated by the observation that the current patch fixes a regression that occurred because the `NO_PARSEOPT` flag was not removed when the commands were converted to `parse-options`. While the test is not strictly necessary for this patch, it would serve as a safeguard against similar oversights in the future.

The review is constructive but remains at the level of a suggestion rather than a demand. Sivaraam does not identify any flaws in the patch itself, nor does he question the approach taken in the series. The proposed test is framed as a "would it be valuable" question, leaving room for the author or maintainers to decide whether the additional coverage is worth the complexity. The patch is otherwise well-motivated, with clear commit messages and historical context for each command’s conversion to `parse-options`. No further changes are needed for the patch to proceed, but the test idea is worth considering for a follow-up.
