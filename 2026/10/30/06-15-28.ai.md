This is the **final version of the documentation patch** that clarifies how Git checks SSH key lifetimes (`valid-after`/`valid-before`) during signature verification. The patch updates `Documentation/config/gpg.adoc` to explicitly state that Git uses the **committer or tagger date** (not the signature timestamp) for these checks, and warns that this provides no security guarantees because the signer controls the timestamp. It also fixes a typo ("OpensSSH" → "OpenSSH").

The wording in this v3 patch incorporates feedback from Patrick Steinhardt, who proposed the concise phrasing now used: "Git validates the signature by checking the committer or tagger timestamp is within the validity time range. This does not provide any security guarantees as the timestamp can be chosen arbitrarily by the signer." Junio C Hamano and Phillip Wood are credited with helping shape the patch, and the commit message notes that this version adopts Patrick’s wording.

This patch directly addresses the first of the two SSH signing verification flaws reported in the thread: the **time-of-signature confusion** issue. The thread’s consensus was to document the current behavior (using committer/tagger date) rather than attempt a technical fix, as Patrick Steinhardt and others argued that a distributed system cannot reliably enforce signature timestamps. The documentation now clearly states this limitation, closing the ambiguity Phillip Wood highlighted in his review.

The patch is **standalone** (not part of a series) and touches only documentation. It carries `Helped-by` trailers from three key participants, indicating broad agreement on the wording. The commit message is clear and references the earlier discussion, making the motivation easy to trace. No test coverage is needed for documentation changes, and the patch is ready for integration. The second flaw (revocation file fails open) is addressed by a separate security bugfix patch, which is also ready and may be held with this one to avoid splitting security fixes across releases.
