This thread is about a six-patch series from Elia Pinto that fixes a memory safety bug in Git’s loose object reading code. The issue occurs when the size of an inflated loose object doesn’t match the size declared in its header: Git could previously return uninitialized heap memory or silently truncate object data. The fix adds a size verification check in `unpack_loose_rest()` (in `object-file.c`), ensuring that the zlib stream’s output matches the expected object size from the header. If they differ, Git now reports the object as corrupt and frees the buffer, aligning the behavior with existing checks in the packfile reader and `index-pack`.

The patch includes new tests in `t1060-object-corruption.sh` that verify the fix for both under-sized and over-sized objects, using an extended `loose_obj()` helper in `lib-loose.sh` to create objects with bogus header sizes. The tests confirm that `git cat-file` and `git fsck` now correctly detect and reject such corruption. The change is narrowly scoped to the loose object path and doesn’t affect packfiles or other backends. So far, the patch appears well-crafted, with a clear commit message and thorough test coverage, addressing a real and potentially serious bug. No reviews or objections have been posted yet.
