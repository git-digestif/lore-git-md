Subject: [PATCH 0/6] loose object handling and size truncation fixes on LLP64 platforms
Series version: v1 (initial submission)
Originating author: Elia Pinto
Thread type: bugfix series

Core problem or goal
Fix six distinct bugs in loose object handling, two affecting all platforms (missing size checks in loose object parsing) and four specific to LLP64 platforms (e.g., 64-bit Windows) where `long` is 32-bit but `size_t` is 64-bit. The bugs include missing bounds checks that could expose uninitialized heap memory or silently truncate objects, and truncation/overflow issues in `cat-file`, `notes`, and `diff` subsystems due to `long` vs. `size_t` mismatches.

Current status
Under review; no maintainer decision yet. Series is based on `master` (b9e5cff180) and does not conflict with Elia’s related "use size_t for a few more object and buffer sizes" series. Issues were initially reviewed on `git-security` but deemed non-security-sensitive.

Key technical details
- **Files touched**: `object-file.c`/`object-file.h`, `odb/source-loose.c`, `builtin/cat-file.c`, `notes.c`, `diff.c`.
- **Functions modified**: `unpack_loose_header()`, `stream_loose_object()`, `batch_write()`, `concat_notes()`, `count_trailing_blank()`, `map_fd()`, `unpack_loose_rest()`, `check_stream_oid()`, `odb_source_loose_map_object()`.
- **Types changed**: Several `unsigned long` variables converted to `size_t` to avoid truncation on LLP64 platforms, particularly in the loose object reading path (patch 2/6 propagates `size_t` through `map_fd()`, `unpack_loose_header()`, `check_stream_oid()`, and `odb_source_loose_map_object()`).
- **New symbols**: None (internal refactoring only).
- **On-disk format**: Unchanged.
- **Test coverage**: New tests in `t/t1006-cat-file.sh` and `t/t1060-object-corruption.sh` for patches 1/6 and 3/6; other patches (including 2/6) rely on manual reproduction steps due to platform-specific nature (e.g., LLP64 environments or multi-gigabyte objects).
