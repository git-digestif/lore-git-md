This is the second patch in the v5 series that extends `git branch --delete-merged` to detect squash-merged and rebase-merged branches. The patch is a preparatory refactoring that updates the `delete_branches()` helper to report where a branch’s changes landed, even when its tip is not reachable from the upstream. This is a purely internal change with no user-visible behavior difference yet; the new output format (`Deleted branch topic (was 1a2b3c4, landed as 9f8e7d6)`) will be used by the upcoming `--delete-integrated` flag in patch 3/4.

The patch extends `delete_branches()` to accept a `strmap *landed_commits` parameter mapping branch names to the upstream commit where their changes were integrated. When a branch is found in the map, the merge check is skipped and the output includes both the branch’s old tip and the landing commit. The change is minimal and focused: it adds the parameter, updates the conditional logic, and extends the printf format strings. All existing callers pass `NULL`, so there is no functional change in this patch.

The patch is uncontroversial and ready for integration. It touches only `builtin/branch.c` and is purely mechanical, with no algorithmic or performance implications. The new output format is consistent with the series’ goal of making branch deletion more informative for non-tip-integrated workflows. The next patch (3/4) will introduce the `--delete-integrated` flag and populate the `landed_commits` map.
