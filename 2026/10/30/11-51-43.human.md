This is a follow-up in the ongoing discussion about how to fix Git’s quarantine mechanism unnecessarily loading hidden refs during connectivity checks. Kristofer Karlsson responds to Junio C Hamano’s proposal to repurpose `GIT_QUARANTINE_ENVIRONMENT` to carry the parent repository’s object directory path, avoiding new environment variables or APIs.

Kristofer reports progress on a v2 patch that avoids introducing a new environment variable by instead deducing the real object directory from the quarantine directory’s parent path. This approach leverages the existing structure of `tmp_objdir_create()`, where the quarantine directory is always a subdirectory of the real object directory. He acknowledges the assumption might feel "icky" but considers it safe, especially since he added tests to verify the behavior. He remains open to revisiting the idea of a new environment variable if Junio prefers a more explicit solution.

The patch remains a bugfix targeting the ODB and quarantine subsystems, with measurable performance benefits (a 67.7% speedup in repositories with 200,000 hidden refs). The discussion is now focused on implementation details rather than the problem’s validity or urgency. Kristofer’s approach is pragmatic and avoids new APIs, but the thread is still open to feedback from Junio or ODB maintainers (Patrick Steinhardt, Justin Tobler) on whether the parent-path deduction is acceptable or if a more explicit mechanism is needed. No objections have been raised yet, and the patch looks likely to land in some form.
