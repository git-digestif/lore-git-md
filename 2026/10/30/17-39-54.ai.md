This is the second patch in Junio C Hamano’s four-patch refactoring series that tightens encapsulation by marking functions as `static` where they are no longer needed outside their source files. Here, the patch targets the `add-interactive.c` subsystem, hiding the `init_add_i_state()` and `clear_add_i_state()` helper functions (and the `struct add_i_state` type itself) from external callers.

The change is straightforward: the two functions and the struct definition are moved from `add-interactive.h` into `add-interactive.c`, and the functions are marked `static`. The commit message explains that since commit d51b61f5da (March 2026), the only public entry point to this machinery has been `run_add_i()`, so the helper functions no longer need to be visible outside the file. The diff is small—11 lines added, 9 removed—and the rework is purely mechanical, with no behavior changes.

This patch continues the series’ theme of reducing unnecessary global symbols, making it clearer which parts of the codebase are truly public. The only external interface affected is the removal of the two function declarations from the header, which is safe because no other code calls them directly.
