Patrick Steinhardt’s three-patch series fixes a regression in `git grep --recurse-submodules` that causes it to fail when grepping nested submodule trees. The bug, introduced in Git 2.56 (commit 93cd344e34f), stems from the command incorrectly reading objects from the main repository instead of the submodule’s repository instance. The series adds test coverage for nested submodules and defensively updates related code paths (sparse directory trees and `.gitmodules` file reading) to prevent similar issues.

Toon Claes has reviewed the first patch, confirming the regression and verifying the test failure without the fix. He suggests minor improvements to the commit message (noting the regression version) and test cleanup but otherwise endorses the changes, calling the defensive follow-ups in patches 2 and 3 "good." No other reviews have been posted yet, and the series remains under review with no merge status reported. The patches are based on Git v2.56.0, indicating intent for backporting to stable branches.
