This thread fixes a bug in `git grep --recurse-submodules` that causes it to fail when grepping nested submodule trees. The issue, introduced in Git v2.56.0, stems from the command incorrectly reading objects from the global repository instance instead of the submodule’s own repository. Patrick Steinhardt’s three-patch series (now at v2) addresses this by ensuring all relevant code paths—submodule trees, sparse directory trees, and `.gitmodules` file reading—use the correct repository instance.

The first two patches in the series directly fix the regression and add defensive checks for related code paths, while the third (just posted) completes the cleanup by eliminating the last implicit use of `the_repository` in `builtin/grep.c`. The only change from v1 to v2 was an update to the commit message in the first patch to explicitly note the regression’s version. Toon Claes provided a substantive review of the first patch, confirming the bug and endorsing the defensive follow-ups. The series is under review and intended for backporting to stable branches, with no open questions remaining.
