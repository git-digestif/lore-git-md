## 2026/11/02

- [2026/11/02/15-44-33 by Priestess <herroyalpriestess@gmail.com>] Priestess reproduced the issue on git 2.56.GIT, confirming that from a linked worktree an alias running `git -C <unrelated-repo> rev-parse --git-dir --git-common-dir --show-toplevel` prints the worktree's git dir and common dir but the target's toplevel, while `env -u GIT_DIR` makes all three point to the target repo, confirming inherited GIT_DIR as the cause.
- [2026/11/02/15-44-33 by Priestess <herroyalpriestess@gmail.com>] Priestess noted that with the main repo as the target, --git-common-dir looks correct either way, so an unrelated repo is the better test.
- [2026/11/02/15-44-33 by Priestess <herroyalpriestess@gmail.com>] Priestess explained that the correct --show-toplevel is just the cwd after -C because GIT_DIR is set without GIT_WORK_TREE.
- [2026/11/02/15-44-33 by Priestess <herroyalpriestess@gmail.com>] Priestess observed that handle_alias() in git.c has a comment "Aliases expect GIT_PREFIX, GIT_DIR etc to be set", so the export looks intentional, making this more a design question than a microproject, and a test locking in current behavior could age badly.
- [2026/11/02/15-44-33 by Priestess <herroyalpriestess@gmail.com>] Priestess, not being a mentor, added the mentors to Cc to ask whether the project fits.
