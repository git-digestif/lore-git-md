This is a **bugfix** for a regression in `` `git grep --recurse-submodules` `` when searching a tree object. The issue, introduced in Git 2.56.0, causes the command to fail with `fatal: unable to read tree` when it encounters a directory inside a submodule. Patrick Steinhardt has now sent a patch series to fix it.

The regression was confirmed and bisected to commit `93cd344e34` ("builtin/grep: stop registering submodule ODB as source"), which removed the automatic registration of submodule object databases. The root cause is that `grep_tree()` now tries to read submodule directory trees from the superproject’s ODB instead of the submodule’s, which no longer works after the ODB registration was removed. The working-tree form of the command remains unaffected, as does searching submodules without directories.

Patrick’s fix is already posted as a two-patch series (`20261030-pks-grep-recurse-submodule-v1`). The series is concise and directly addresses the ODB lookup logic in `builtin/grep.c`. Given Patrick’s track record and the straightforward reproduction steps provided by the original reporter, this fix looks likely to be well-tested and uncontroversial. The patches are now under review, so interested readers should follow the linked thread for any follow-up discussion or test results.
