This is the final version of a documentation patch that clarifies a security-relevant ambiguity in Git’s SSH signing verification. The patch updates `Documentation/config/gpg.adoc` to state explicitly that key lifetime checks (`valid-after`/`valid-before`) use the committer or tagger date — which the signer controls — rather than the signature timestamp. It also adds a security note: because the signer can choose the timestamp arbitrarily, these checks do not provide meaningful security guarantees. The patch fixes a typo ("OpensSSH" → "OpenSSH") and carries trailers from Phillip Wood, Junio C Hamano, and Patrick Steinhardt, indicating their involvement in shaping the wording.

This patch directly addresses the first of two SSH signing flaws reported earlier in the thread. The thread consensus was that fixing the timestamp confusion technically would be difficult in a distributed system, so the project opted to document the current behavior and its limitations instead. The wording here is the one Junio accepted after Patrick Steinhardt proposed a concise phrasing that balances clarity with security awareness.

The patch is ready for integration and is part of a coordinated security fix that also includes a separate patch making revocation file errors fatal by default. Both patches are likely to be held together to avoid splitting security fixes across releases. The commit message is clear and references the earlier discussion, making the motivation easy to trace. No test coverage is needed for documentation changes.
