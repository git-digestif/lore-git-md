This is the third and final patch in Patrick Steinhardt’s three-part bugfix series targeting `git grep --recurse-submodules`. It addresses a latent code smell in how `.gitmodules` files are read when grepping objects recursively through submodules.

The change is minimal: one line in `builtin/grep.c` replaces `the_repository` with `opt->repo` when calling `gitmodules_config_oid()`. The commit message explains that this is not currently a bug—`grep_objects()` is only called by `cmd_grep()`, which always sets `opt->repo` to `the_repository`—but the inconsistency is worth fixing as a defensive measure. This aligns with the series’ overall goal of eliminating implicit reliance on the global `the_repository` variable, even in code paths that aren’t yet broken.

The patch is clearly part of the larger effort to clean up repository handling in Git, though it doesn’t fix an active regression like patch 1/3. It’s a small, safe change that future-proofs the codebase against similar issues. No new test coverage is added here, as the existing test in `t/t7814-grep-recurse-submodules.sh` (introduced in patch 1/3) already exercises the relevant code path. The series remains under review with no acks or objections yet.
