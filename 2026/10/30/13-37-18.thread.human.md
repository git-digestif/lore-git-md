This thread began as an Outreachy microproject proposal to write regression tests for an edge case in Git worktrees: when a shell alias runs a Git command (like `git -C ../other-repo rev-parse`) from inside a linked worktree, it inherits the parent worktree’s `GIT_DIR` environment variable, causing the nested command to report the wrong repository’s directories. Immaculate Mecha, the applicant, and Priestess (Cynthia) confirmed the behavior and traced it to `handle_alias()` intentionally exporting `GIT_DIR` to aliases. The discussion quickly shifted from test-writing to whether the current behavior is correct or should be changed, since a regression test would lock in a design that might later be revisited.

Immaculate has now clarified that their Outreachy contribution would focus on documenting the current behavior, reproducing the edge case, and explaining how Git handles repository environment variables in external shell aliases with linked worktrees and `git -C`. They acknowledge that changing the behavior would require broader design discussion and are seeking mentor guidance on whether this investigation is suitable for Outreachy or if a smaller task would be better. Outreachy mentors (Christian Couder, Kaartic Sivaraam, Siddharth Asthana, and Usman Akinyemi) were added to the thread but have not yet weighed in. The thread remains exploratory, with no patches or test scripts submitted, and the suitability of this task as a microproject—given the tight deadline and design implications—is still unresolved.
