This thread is an Outreachy microproject discussion about whether writing regression tests for an edge case in Git worktree environment variable handling would be a suitable contribution. Immaculate Mecha initially proposed the idea after observing that shell aliases running Git commands from inside a linked worktree inherit the parent worktree’s `GIT_DIR`, causing nested commands to report incorrect repository directories—even though `--show-toplevel` behaves correctly.

Priestess (Cynthia) confirmed the issue on Git 2.56.GIT, reproducing the behavior where `git -C <unrelated-repo> rev-parse` inside a linked worktree incorrectly reports the parent worktree’s `GIT_DIR` and `GIT_COMMON_DIR`. She traced the root cause to `handle_alias()` in `git.c`, which explicitly exports these variables to aliases, suggesting the behavior is intentional. This shifts the discussion from a simple test-writing task to a design question: whether the current behavior is correct or should be changed. Priestess cautioned that a regression test might lock in behavior that could later be revisited, and she suggested that given Outreachy’s tight deadlines, a smaller microproject might be more practical. She added Outreachy mentors (Christian Couder, Kaartic Sivaraam, Siddharth Asthana, and Usman Akinyemi) to the thread for their input.

No code or test scripts have been submitted yet, and the thread remains exploratory. The key technical details involve worktree handling and environment variable propagation, with potential test files in `t/` and possible code changes in `setup.c` or `environment.c`. The open question is whether this is a suitable microproject or if the design should be revisited first.
