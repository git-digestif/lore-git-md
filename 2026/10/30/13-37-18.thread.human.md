This thread is an Outreachy microproject proposal from Immaculate Mecha, exploring an edge case in Git's environment variable handling within linked worktrees. The issue arises when a shell alias runs a Git command (e.g., `git -C ../other-repo rev-parse`) from inside a linked worktree: the nested command inherits the parent worktree’s `GIT_DIR` environment variable, causing `rev-parse` to report incorrect repository directories, while `--show-toplevel` behaves correctly. Unsetting `GIT_DIR` resolves the issue, and the author references a 2020 discussion about `GIT_DIR` inheritance in aliases but seeks confirmation on whether adding regression tests for linked worktrees would be a worthwhile Outreachy microproject.

So far, this is a standalone inquiry with no prior discussion or responses in the thread. The focus is on validating the scope of the contribution—specifically, whether regression tests for this edge case would be valuable—rather than proposing a specific patch or design change. The thread is likely to evolve based on feedback from maintainers or experienced contributors about the feasibility and relevance of the proposed tests.
