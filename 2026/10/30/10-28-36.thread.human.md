This thread is about a bugfix patch (3/6 in a series) that plugs a silent corruption risk in Git’s loose object backend. When streaming loose objects, Git was inflating the zlib stream without checking that the decompressed size matched the size declared in the object header. As a result, a corrupt object whose stream was shorter or longer than its header claimed would be streamed out without error, and commands like `git cat-file blob` would exit successfully while producing incorrect output.

Elia Pinto’s patch adds a simple counter to track the total bytes read during decompression and verifies, when the zlib stream ends, that the count matches the expected size from the header. If they don’t match, Git now reports the object as corrupt and returns an error. The fix is minimal—it touches only `odb/source-loose.c`—and includes two new test cases in `t/t1006-cat-file.sh` that create deliberately malformed loose objects and verify that `git cat-file` fails with an appropriate error. The patch is part of Patrick Steinhardt’s ongoing ODB abstraction effort but stands alone as a correctness fix. So far, there’s no review feedback, so the only open question is whether the error message could be more specific about the size mismatch.
