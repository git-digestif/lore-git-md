This is a two-patch bugfix series targeting the tree-walk subsystem. The patches address a silent truncation issue when Git processes trees larger than 4 GiB: `struct tree_desc` and `struct tree` store tree buffer sizes in `unsigned int` and `long` respectively, both of which are 32-bit on common platforms, causing the walk to ignore entries beyond the 4 GiB boundary. The fix converts these fields to `size_t`, which is 64-bit on all relevant platforms. The commit message notes that while such large trees are rare, they can be crafted, and `fsck` is expected to validate every entry.

Patch 1/2 modifies `struct tree_desc` and its setup functions in `tree-walk.c` and `tree-walk.h` to use `size_t` for buffer sizes. Patch 2/2 applies the same change to `struct tree` and `parse_tree_buffer()` in `tree.c` and `tree.h`. The author verified the fix by simulating a 16-bit size environment but did not include a test for the actual 4 GiB case, as it would require an impractically large in-memory tree.

The series is part of a broader effort by the same author to eliminate size truncations in Git (linked series target other subsystems). It is based on `master` (b9e5cff180) and merges cleanly with the other series. No review activity is visible in the provided context, but the patches appear well-scoped and technically sound, addressing a real correctness issue with minimal risk of unintended side effects. The use of `size_t` is appropriate for buffer sizes and aligns with Git's conventions elsewhere.
