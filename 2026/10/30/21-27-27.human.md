This is the **core API patch (3/6)** in Christian Couder’s `parse-options` early-scanning series, now receiving a **surface-level review** from Kaartic Sivaraam. The series introduces `early_scan_options()`, a new helper designed to replace fragile hand-rolled early argument scans in Git commands, and this patch implements the API itself.

Kaartic’s feedback focuses on two minor documentation and validation improvements. First, he suggests adding the same `PARSE_OPT_EARLY` validation checks inside `early_scan_options()` that are already present in `parse_options_check()`. This would catch misuse (e.g., short options or `OPTION_SUBCOMMAND` marked with `PARSE_OPT_EARLY`) even if `parse_options_start()` is not called before the early scan. The suggestion is **technically sound**—it duplicates no logic and would make the API more robust—but it is **not a blocker** for the series. Second, he proposes clarifying the API documentation to note that the `option` pointer passed to the early-scan callback is only valid during the scan and should not be retained. This is a **helpful usability note** that would prevent subtle bugs in caller code.

The rest of the patch remains **unchanged and well-reviewed**. The implementation reuses `parse-options` internals to handle negated options, unambiguous abbreviations, and aliases consistently with `parse_options()`, and the scan stops at short options, unknown options, and ambiguous abbreviations to avoid misinterpreting values. The patch is **technically ready for `next`** once these minor documentation tweaks are addressed, though the broader series may still require iteration on the unresolved usability concern (caller responsibility for argument skipping). For now, this is a **clean, incremental improvement** that does not alter the API’s behavior or design.
