This is a bugfix series from Patrick Steinhardt targeting `git grep --recurse-submodules` with nested submodules. The issue is that Git currently reads submodule trees from the wrong repository, causing the command to fail when traversing nested submodule structures.

The core fix is in the first patch, which ensures that submodule trees are read via their own repository object rather than the top-level repository. The other two patches are defensive changes that apply the same pattern to sparse directory trees and `.gitmodules` file access, preventing similar issues elsewhere in the code.

The commit message is clear and references an external bug report, though the report itself isn’t included in the email. The series is intentionally minimal—Patrick notes that a full `the_repository` removal from `builtin/grep.c` would be more involved due to edge cases like `--no-index` execution outside a repository, so he’s deferring that refactoring.

The patch is based on Git v2.56.0 for easy backporting, and the test coverage (added in `t/t7814-grep-recurse-submodules.sh`) looks thorough. Given Patrick’s track record and the targeted nature of the fix, this series appears well-crafted and likely to be uncontroversial. If you work with submodules or care about `git grep` correctness, it’s worth a closer look.
