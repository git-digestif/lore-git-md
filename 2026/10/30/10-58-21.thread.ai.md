Thread identity
Subject: [PATCH 0/2] tree-walk: fix silent truncation of >4 GiB trees
Series version: v1 (initial submission)
Originating author: Elia Pinto
Thread type: bugfix patch series

Core problem or goal
Git’s tree-walk subsystem silently truncates trees larger than 4 GiB because `struct tree_desc` and `struct tree` store buffer sizes in 32-bit types (`unsigned int` and `long`). The series converts these fields to `size_t` (64-bit on all relevant platforms) so that every tree entry is validated by `fsck` and no silent truncation occurs.

Current status
Under review; no prior versions. Patches apply cleanly on `master` (b9e5cff180) and merge cleanly with the author’s other size-truncation series.

Key technical details
- Files touched: `tree-walk.c`, `tree-walk.h`, `tree.c`, `tree.h`
- Symbols changed: `struct tree_desc` (size field), `struct tree` (size field), `init_tree_desc()`, `init_tree_desc_gently()`, `decode_tree_entry()`, `dir_state` struct (internal to `get_tree_entry_follow_symlinks()`), `parse_tree_buffer()`
- Behavior change: trees >4 GiB are no longer truncated; `git ls-tree` shows all entries and `fsck` validates every path, including security-sensitive ones like `.gitmodules`
- On-disk format: unchanged
- Test coverage: none for the 4 GiB case (impractical to construct in-memory); author verified with a simulated 16-bit environment that reproduces the same truncation behavior at 64 KiB
- Future work noted: `parse_object_buffer()` still passes an `unsigned long` to `parse_tree_buffer()`; left for a follow-up to avoid scope creep
