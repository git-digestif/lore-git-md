This is a **substantive review** of the second patch in Christian Couder’s v3 series introducing `early_scan_options()`, a new `parse-options` sub-API. The patch extracts `lookup_long_opt()` from `parse_long_opt()` to enable consistent long-option lookup without side effects (no value assignment, no `die()`/`error()` calls), a prerequisite for the upcoming `early_scan_options()` API.

Kaartic Sivaraam’s review focuses on a single technical point: whether the `enum long_opt_lookup` return value should be consumed via a `switch` statement rather than a series of `if` statements in `parse_long_opt()`. The current implementation uses `if` chains to handle each enum case (`LONG_OPT_EXACT`, `LONG_OPT_ABBREV`, etc.), which works but may be less idiomatic for exhaustive enum handling. A `switch` would make the control flow clearer and could leverage compiler warnings for unhandled cases (though the `BUG()` at the end already guards against this).

The rest of the patch receives no criticism—Kaartic explicitly notes it "looks good." The refactoring is mechanical, preserves all existing behavior (exact-match precedence, abbreviation handling, ambiguity error messages), and is well-documented. The extracted helper is immediately useful for the `early_scan_options()` API and is exercised by the existing test suite.

This review is **substantive but narrow**: it engages with the code’s structure without questioning the broader design. The feedback is actionable but unlikely to block the patch’s progress, as the current implementation is functionally correct. The patch remains **ready for `next`** and should proceed independently of further API iteration.
