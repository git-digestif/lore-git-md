This is a surface-level review of the second patch in Tanga Joris's v3 series, which removes the `NO_PARSEOPT` flag from four Git built-in commands (`diff-pairs`, `fast-import`, `patch-id`, `var`) in `git.c`. Kaartic Sivaraam suggests adding a test to catch future commands that adopt `parse-options` but fail to remove their `NO_PARSEOPT` flag, preventing a recurrence of the completion regression this series fixes.

The proposed test would generate a list of commands still marked `NO_PARSEOPT`, filter out known exceptions (e.g., `diff` and `rev-list`, which parse some options manually but delegate others to `parse-options`), and verify that the remaining commands do not respond to `--git-completion-helper` with any options. This is a defensive measure: it would have caught the original regression at test time rather than in the wild. The test is not tied to any specific command, so it would automatically cover future additions to the `commands[]` table.

The suggestion is well-intentioned but remains surface-level. It does not engage with the technical details of how `parse-options` and completion interact, nor does it address whether the test's false-positive risk (e.g., commands that legitimately parse options manually) is acceptable. The patch itself is uncontroversial and ready for integration; this review comment is a minor enhancement request rather than a blocker. The series as a whole is still blocked on Christian Couder's `cc/early-scan-options` reaching `next`.
