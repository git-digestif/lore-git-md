Core problem or goal: `git log --follow` (which tracks file renames across history) became ~14x slower when processing merges after commit 304812ed33 (June 2026). The v5 series fixes two correctness bugs (`-m --follow` losing history from non-first parents and `--follow` missing edits on dropped sides of merges) and introduces a targeted optimization that reduces the number of rename-detection passes needed when following a file through merges. The optimization also addresses correctness regressions in handling file copies and unrelated histories (e.g., subtree merges). The remaining performance gap (~1.6x slower than pre-304812ed33) is fully addressed by the standalone toggle patch, which disables `--follow` by default for non-linear history, mitigating the performance cost while preserving the correctness fixes. The toggle patch is merged to `master` as of 2026-08-12 and will unblock GitLab's deployment.
