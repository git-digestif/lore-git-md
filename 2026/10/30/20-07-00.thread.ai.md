Thread type: patch series (performance bugfix, correctness regression) **and project-level policy decision, now settled and executed via the standalone toggle patch**.

Core problem or goal
`git log --follow` (which tracks file renames across history) became ~14× slower when processing merges after commit 304812ed33 (June 2026). The v5 series fixes two correctness bugs—`-m --follow` losing history from non-first parents and `--follow` missing edits on dropped sides of merges—and introduces a targeted optimization that reduces the number of rename-detection passes needed when following a file through merges. The optimization also addresses correctness regressions in handling file copies and unrelated histories (e.g., subtree merges). The remaining performance gap (~1.6× slower than pre-304812ed33) is now addressed by the **standalone toggle patch**, which **disables `--follow` by default for non-linear history**, mitigating the performance cost while preserving the correctness fixes. The toggle patch is **queued separately** and will land first to unblock GitLab’s deployment.

Key technical details
- Files touched (v5 series): `log-tree.c`, test suite (`t/t4219-log-follow-merge.sh`).
- New/updated helper functions (v5 series): `follow_parent_changed_dropped_file` and `follow_has_rename_source` (narrow rename-detection to files deleted by the merge), `follow_needs_renames()` (optimization gatekeeper, now handles copies and unrelated histories).
- Behavior change (v5 series): `--first-parent` disables rename detection after the first parent but still walks all parents to maintain history coverage. No on-disk format changes.
- Test coverage (v5 series): new tests in `t4219` for `-m --follow` correctness, dropped-side edits, `--diff-merges=first-parent` interaction, file copy tracking, and unrelated histories.
- Optimization core (v5 series): limit rename detection to files deleted by the merge, but the remaining performance gap (~1.6× slower than pre-304812ed33) is now addressed by the **standalone toggle patch**.
- Toggle patch details:
  - Files touched: `Documentation/config/log.adoc`, `builtin/log.c`, `log-tree.c`.
  - New config value: `log.follow=merges` (or flag `--follow=merges`), **disabled by default**.
  - Logic: Disables rename-following in merges unless explicitly opted in, restoring pre-304812ed33 performance for default users.
  - Open implementation items: Use `git_parse_maybe_bool()` for graceful error handling (Patrick Steinhardt’s feedback), add performance warning to `log.adoc` documentation, and simplify redundant checks in `log-tree.c`.
