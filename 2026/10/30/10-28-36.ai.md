This is a **bugfix** patch (3/6 in a series) targeting the loose object backend in Git's object database (ODB). It addresses a silent corruption issue: when streaming loose objects, Git inflates the zlib stream without verifying that the decompressed size matches the size declared in the object header. As a result, a corrupt object whose stream is shorter or longer than its header claims is streamed out without error, and commands like `git cat-file blob` exit successfully while producing incorrect output.

The patch adds a running counter (`total_read`) to the `odb_loose_read_stream` struct and checks, when the zlib stream ends, whether the total bytes read match the expected size from the header. If they do not, Git now reports the object as corrupt and returns an error. The fix is minimal and focused: it touches only `odb/source-loose.c` and adds two new test cases in `t/t1006-cat-file.sh` that create deliberately malformed loose objects (using the existing `loose_obj` helper) and verify that `git cat-file` fails with an appropriate error message.

The commit message is clear and specific: it describes the bug, the symptom (`git cat-file` exits with 0 after writing fewer bytes than `git cat-file -s` reports), and the fix. The tests are thorough and cover both under-sized and over-sized streams. The patch is part of the ongoing ODB abstraction effort led by Patrick Steinhardt, but it stands alone as a correctness fix for the loose object backend. It looks well-crafted and addresses a real problem; the only open question is whether the error message should be more specific about the nature of the corruption (size mismatch), but that is a minor point.
