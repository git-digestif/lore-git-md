This is a **bugfix** for the `status` and `checkout` commands, targeting the misleading message shown when a local branch tracks a remote branch that does not exist. The patch has been queued in `seen` (as `ep/status-missing-upstream`) and marked "Needs review" in the last three "What's cooking" reports, indicating it is still awaiting final feedback before moving to `next`.

The author, Elia Pinto, sends a gentle ping to the list, recapping the core issue: after cloning an empty repository, Git currently claims the upstream "is gone" and suggests `git branch --unset-upstream`, even though the upstream was never created and `git push` is the more appropriate action. The patch rewords the message to be neutral ("does not exist") and tailors the advice—`git push` is only suggested when it would actually create the missing branch (i.e., when `@{push}` resolves to the upstream and no restrictive `push.default` or `remote.<name>.push` refspecs are in effect).

The implementation is complete and well-tested, with no unresolved technical concerns.
