This is an Outreachy microproject proposal about a subtle edge case in Git’s environment handling.

The author, an Outreachy applicant, describes a scenario where a shell alias run from a linked worktree unintentionally inherits the `GIT_DIR` environment variable. When the alias invokes `git -C ../some-other-repo rev-parse`, the nested Git command still reports the *calling* worktree’s directories (`.git` and `commondir`) instead of the target repository’s, even though `--show-toplevel` correctly identifies the target. Unsetting `GIT_DIR` before the nested command fixes the inconsistency.

The email references a 2020 discussion on `GIT_DIR` inheritance in aliases but asks whether a focused contribution—specifically, adding regression tests for linked worktrees—would still be welcome as an Outreachy microproject. The tone is exploratory rather than proposing a specific patch, so this is not yet a code submission. The issue looks real and narrowly scoped, making it a plausible candidate for a small, well-defined contribution.
