This is the fifth iteration of a small but important fix in Harald Nordgren’s `fetch: introduce +: refspec for matching-inspired fetch mode` series, now at v12 and under active review for merging to `master`. The patch targets a gap in the `@{push}` resolution logic that was overlooked in the v12 implementation: when `remote.<name>.fetchRefmap` is configured, `@{push}` lookups fail because the code only checks `remote->fetch` and `remote->refmap`, skipping the new `remote->fetchRefmap` key. Harald proposes a one-line fix in `remote.c` that falls back to `remote->refmap` (the namespace mapping) if `remote->fetch` yields no match, ensuring `@{push}` works regardless of which configuration key is in use.

The fix is mechanical and uncontroversial: it mirrors the existing fallback logic for `@{upstream}` and aligns with the series’ design principle that `remote.<name>.refmap` handles namespace mapping. No new edge cases are introduced, and the change is covered by the existing test suite (`t/t5586-fetch-refmap.sh`). This is a last-minute polish for v13, not a design pivot, and should not delay the series’ graduation once the higher-weight override semantics edge case is resolved. Readers tracking the series can treat this as a routine correctness fix.
