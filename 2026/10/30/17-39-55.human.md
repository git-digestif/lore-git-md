This is the third patch in Junio C Hamano’s four-patch refactoring series that tightens encapsulation by marking functions as `static` where they are no longer needed outside their source files. This specific patch hides `refresh_cache_entry()` in `read-cache.c` by making it file-scope static, undoing a visibility change from 2006 that is no longer justified.

The patch removes the function’s declaration from `read-cache-ll.h` and moves the entire 258-line block of code (including the helper `refresh_cache_ent()`) earlier in `read-cache.c` so that `refresh_cache_entry()` can be declared `static` without requiring a forward declaration. Junio justifies this reordering in the cover letter as future-proofing: if the code later moves around, the lack of a forward declaration will avoid subtle breakage.

The commit message provides historical context: `refresh_cache_entry()` was made public in 2006 to support the “recursive” merge strategy, but that strategy was removed in April 2025, leaving no external callers. The only remaining users are internal to `read-cache.c` or call it indirectly through `make_cache_entry()` or `rename_index_entry_at()`, which the “ort” merge strategy (the successor to “recursive”) still uses.

This is a pure refactoring with no behavior changes, and the patch is mechanically straightforward. The reordering is the only potential point of discussion, but Junio’s rationale is reasonable. The patch is part of the ongoing effort to improve Git’s code hygiene and should be uncontroversial.
