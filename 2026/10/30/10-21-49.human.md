This is the third and final patch in Patrick Steinhardt’s three-part bugfix series for `git grep --recurse-submodules`. It addresses a latent code smell in how `.gitmodules` files are read when grepping objects recursively through submodules.

The change is minimal: one line in `builtin/grep.c` replaces `the_repository` with `opt->repo` when calling `gitmodules_config_oid()`. The commit message explains that this isn’t currently a bug—`grep_objects()` is only called from `cmd_grep()`, where `opt->repo` is always `the_repository`—but the inconsistency is still worth fixing as a defensive measure. This aligns with the series’ overall goal of eliminating implicit reliance on the global repository variable, even in cases where it doesn’t yet cause problems.

The patch is clearly part of the larger effort to clean up `the_repository` usage, though it doesn’t fix an active regression like the first patch does. It’s a small, safe change that rounds out the series by ensuring all repository-sensitive operations in `grep_objects()` use the passed-in repository parameter consistently. No new tests are added here, as the existing test coverage for nested submodules (introduced in patch 1) already exercises this code path. The series as a whole looks well-motivated and ready for review.
