This is the second patch in Patrick Steinhardt’s three-part bugfix series for `git grep --recurse-submodules`. It addresses a latent issue in how sparse directory trees are read during submodule recursion.

The patch itself is tiny—one line changed in `builtin/grep.c`—but the commit message is thorough. It explains that while the bug cannot currently be triggered (because submodules always use a full index), the code is still wrong and could easily break once submodules start supporting sparse indices. The fix preemptively switches from `the_repository` to the passed-in `repo` parameter, aligning with the ongoing effort to eliminate implicit reliance on the global repository.

This is a defensive, forward-looking change rather than an immediate bugfix. The reasoning is clear and the scope is tightly limited to the sparse-directory code path. No new test is added here because the existing test coverage in `t/t7814-grep-recurse-submodules.sh` already exercises the relevant logic. The patch looks like a low-risk, high-value cleanup that future-proofs the codebase.
