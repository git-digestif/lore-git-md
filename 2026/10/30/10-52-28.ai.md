This is the fourth patch in Harald Nordgren’s v13 series introducing `remote.<name>.fetchRefmap` for matching-inspired fetch mode. The patch adds a `--limited-fetch` option to `git remote add`, which configures `remote.<name>.fetchRefmap` (e.g., `*@{upstream}`) instead of the traditional wildcard `remote.<name>.fetch` refspec. This ensures that a refspec-less `git fetch <name>` only fetches branches already tracked by local branches at the remote, addressing the performance issue in shallow repositories where fetching all remote branches is wasteful.

The implementation is straightforward: the new `--limited-fetch` flag sets `remote.<name>.fetchRefmap` to `+refs/heads/*:refs/remotes/<name>/*` when no `-t/--track` or `--mirror` options are given, while rejecting the combination of `--limited-fetch` with those options (since they already specify what to fetch). The patch updates `builtin/remote.c` to parse the new flag, validate its usage, and write the appropriate config key, and adds two new tests in `t/t5505-remote.sh` to verify the behavior and conflict detection. Documentation in `git-remote.adoc` is updated to describe the new option and its effect.

The patch is well-scoped and uncontroversial, fitting cleanly into the series’ finalized design. It introduces no new edge cases or open questions, and the test coverage is sufficient for the added functionality. The only remaining work for the series is resolving the override semantics for command-line refspecs (addressed in other patches) and incorporating any final review feedback before graduation to `master`. This patch is ready for review and likely to be merged as-is.
