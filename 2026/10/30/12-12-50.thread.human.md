This thread introduces a new `gitsecurityboundary(7)` man page to clarify Git’s security boundary, addressing a recent surge in misaligned security reports. The patch, authored by Johannes Schindelin and conceptually driven by Toon Claes, defines Git’s security guarantees as covering only *unexpected or implicit execution of attacker-controlled code*—not inspection of repository contents or attacks from users with local disk write access. It cites historical CVEs and explains how to create a "sanitized clone" using `git clone --no-local`.

The patch is uncontroversial and touches only documentation, adding the new man page and cross-references from `git(1)` and `SECURITY.md`. Junio C Hamano and Patrick Steinhardt provided input during its development, and Junio’s recent review was positive but surface-level, praising the inclusion of a specific detail about running `upload-pack` as an unprivileged user. While the patch appears to have broad support, it has not yet undergone substantive technical scrutiny beyond light endorsement. No objections or open questions have been raised, and the patch remains under review with no prior versions.
