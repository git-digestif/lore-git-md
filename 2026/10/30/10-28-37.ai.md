This is a bugfix patch targeting the `cat-file` command. It fixes a type mismatch in `batch_write()` where an `int` parameter was used to pass object lengths that can exceed 2GiB, causing memory corruption or truncation on large objects.

The issue occurs because `odb_read_object()` and `filter_object()` return `size_t` lengths, but `batch_write()` accepts an `int`. For objects between 2GiB and 4GiB, the length wraps to a negative value, leading to buffer overruns when passed to `fwrite()` or `write_or_die()`. Objects ≥4GiB are truncated. The bug affects all platforms and can be triggered with `--batch` on non-blob objects or filtered blobs.

The fix is minimal: change the `len` parameter in `batch_write()` from `int` to `size_t`, matching the types used by `fwrite()` and `write_or_die()`. The patch touches only `builtin/cat-file.c` (1 line changed). No tests are included due to the impracticality of testing with multi-gigabyte objects.
