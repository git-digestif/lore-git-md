This is the fourth patch in a six-patch series that refactors how `git log --follow` handles renames in non-linear history. The series was introduced in v1 to address a performance regression (28s → 6m43s) in `git log --stat --follow` on merge-heavy repositories like linux.git. This patch simplifies the logic by removing the `propagate_follow_pathspec_to_parent()` helper and its associated loop, which redundantly called `diff_tree_oid()` for each parent of a merge commit. Instead, it records the path to follow for each parent directly in the existing `log_tree_diff()` loop, avoiding the extra diff pass. The change is purely internal: behavior remains identical, but the code is now cleaner and sets the stage for the performance fix in the next patch.

The patch touches only `log-tree.c`, removing 55 lines and adding 41, with no new functions or data structures. It preserves all existing `--follow` edge cases, including `--diff-merges=first-parent` and combined diffs (`-c`, `--cc`, `--remerge-diff`). The commit message clearly explains the trade-off: the current patch does not improve performance yet, but it eliminates the redundant diff call that was the root cause of the regression. The follow-up patch (5/6) will build on this simplification to restore the original speed.
