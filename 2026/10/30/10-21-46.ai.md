This is a bugfix series targeting the `git grep --recurse-submodules` command. The root issue is that when grepping nested submodule trees, Git incorrectly reads objects from the wrong repository, causing the operation to fail. The series consists of three patches: the first fixes the immediate bug, while the other two are defensive changes to ensure similar issues don't exist elsewhere in the codebase.

The fix itself is straightforward: patch 1/3 modifies `builtin/grep.c` to read submodule trees via their correct repository instance rather than defaulting to `the_repository`. The commit message and cover letter make it clear this is a targeted bugfix with minimal refactoring—Patrick explicitly notes that fully removing `the_repository` from `cmd_grep()` would require handling the `--no-index` case, which is out of scope for this series.

Patches 2/3 and 3/3 extend the same pattern to sparse directory trees and `.gitmodules` file reading, respectively. These are described as "belt-and-suspenders" measures, meaning they're precautionary rather than addressing known bugs. The series includes a new test in `t/t7814-grep-recurse-submodules.sh` to verify the fix, which is a strong positive signal for correctness.

The series is based on Git v2.56.0, indicating it's intended for backporting to stable branches. The code changes are small (6 insertions, 3 deletions across two files) and focused on the repository parameter passing, suggesting low risk of introducing regressions. The motivation is well-documented with a link to the original bug report, and the scope is clearly limited to the immediate problem. This looks like a solid, well-contained fix for a real issue.
