# Thread deltas

## 2026/10/30

- [2026/10/30/10-58-21 by Elia Pinto <gitter.spiros@gmail.com>] Posted a two-patch series to use size_t for tree buffer sizes, explaining that struct tree_desc's "unsigned int" size field truncates tree objects of 4GiB or more on all platforms, causing the walk to see only a prefix and silently drop the rest of the tree when the cut falls between entries, affecting "git ls-tree" and fsck_tree(); no test is included as it would require a tree larger than 4GiB in memory.
- [2026/10/30/10-58-22 by Elia Pinto <gitter.spiros@gmail.com>] Submitted patch 1/2 changing struct tree_desc, init_tree_desc(), init_tree_desc_gently(), decode_tree_entry(), update_tree_entry_internal(), and struct dir_state to use size_t for buffer sizes, fixing the truncation where the walk sees only "size mod 2^32" bytes; verified by simulating a 16-bit size which made "git ls-tree" list 10 of 2058 entries of a 65856-byte tree without error.
- [2026/10/30/10-58-23 by Elia Pinto <gitter.spiros@gmail.com>] Submitted patch 2/2 changing struct tree and parse_tree_buffer() to use size_t, fixing the remaining truncation on Windows where "unsigned long" is 32 bits and would still truncate trees of 4GiB or more before they reach init_tree_desc(); parse_object_buffer() still hands an "unsigned long" size to parse_tree_buffer() and is left for a later change.
