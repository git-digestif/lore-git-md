This is the second patch in Harald Nordgren’s six-patch v13 series introducing `remote.<name>.fetchRefmap` for matching-inspired fetch mode. The patch extracts the logic that checks whether the current branch builds on a remote and collects its upstream refs into a reusable helper, `collect_upstream_from_remote()`. This refactoring is foundational for the series: it enables the later patch (3/6) that extends the same logic to all branches tracked by the remote, not just the current one.

The change is a clean refactoring with no behavior change. It moves the inlined logic from `builtin/fetch.c` into `remote.c` and exposes it via `remote.h`. The helper takes a `struct repository *` parameter (aligning with the ongoing `the_repository` removal effort), a `struct remote *`, an optional branch name (NULL means current branch), and a `strvec *` to collect upstream refs. The patch updates the call site in `do_fetch()` to use the new helper, replacing the hardcoded current-branch logic with a call that passes NULL for the branch name.

The implementation is straightforward and well-contained: 18 lines removed from `builtin/fetch.c`, 15 added to `remote.c`, and 9 to `remote.h`. The commit message provides a clear example of the scenario the helper addresses (a shallow clone with a new branch pushed upstream) and cites the commit that introduced the original logic (49ca2fba39). The patch is uncontroversial and ready for review; it has no known edge cases or open questions. The extracted helper will be reused in patch 3/6 to implement the dynamic branch enumeration logic that underpins the series’ core goal.
