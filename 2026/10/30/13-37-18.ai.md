This is an **Outreachy microproject proposal** about environment variable handling in Git worktrees.

The author, an Outreachy applicant, reports a specific edge case: when a shell alias runs a Git command (`git -C ../other-repo rev-parse`) from inside a **linked worktree**, the nested command inherits the parent worktree’s `GIT_DIR` environment variable. This causes `rev-parse` to report the wrong repository’s directories, even though `--show-toplevel` works correctly. Unsetting `GIT_DIR` before the nested command fixes the issue.

The email references a 2020 discussion on `GIT_DIR` inheritance in aliases but asks whether a focused contribution—particularly **regression tests for linked worktrees**—would still be valuable as an Outreachy microproject. The tone is exploratory, not proposing a patch yet. No prior thread context is provided, so this appears to be a new inquiry.
