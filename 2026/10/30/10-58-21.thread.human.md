This thread is a two-patch bugfix series from Elia Pinto that fixes a silent truncation bug in Git’s tree-walk subsystem. When trees exceed 4 GiB, Git currently truncates them because the size fields in `struct tree_desc` and `struct tree` are 32-bit types. The series converts these fields to `size_t` (64-bit on all relevant platforms), ensuring all tree entries are validated by `fsck` and no data is silently lost. The patches apply cleanly to `master` and are part of a broader effort by the author to eliminate similar size truncations elsewhere in Git.

The first patch updated `struct tree_desc` and related functions, while this second patch focuses on `struct tree` and `parse_tree_buffer()`. The changes are minimal—just three lines across two files—and align the buffer size type with the `size_t` already used by `odb_read_object()`. The author verified the fix using a simulated 16-bit environment, though testing the actual 4 GiB boundary is impractical. No review feedback has arrived yet, but the series appears technically sound and low-risk, with no changes to the on-disk format. The only loose end is a minor inconsistency: `parse_object_buffer()` still passes an `unsigned long` to `parse_tree_buffer()`, but the author deferred this to a future change to avoid scope creep.
