Elia Pinto's five-patch v2 series fixes loose object handling and size truncation bugs, with two fixes applying to all platforms and three targeting LLP64 systems like 64-bit Windows where `long` is 32-bit but `size_t` is 64-bit. The series is under review, and Junio C Hamano has approved four of the five patches: patch 1/5 adds post-inflation size validation in `unpack_loose_rest()`, patch 2/5 widens the loose object read path from `unsigned long` to `size_t`, patch 4/5 changes `batch_write()` in `cat-file --batch` from `int` to `size_t` to fix a 2--4 GiB buffer overread, and patch 5/5 uses `st_add3()` for overflow-safe arithmetic in `combine_notes_concatenate()`. Only patch 3/5 remains open, as Junio requested rework of the streaming loose object reader to stay silent on size mismatch and set `ODB_LOOSE_READ_STREAM_ERROR` for a higher-level caller to report, which also makes the patch's proposed `oid` struct member unnecessary.

The review discussion around patch 1/5 saw Patrick Steinhardt question how the zlib stream could reach `Z_STREAM_END` when the header claims fewer bytes than the compressed data contains; Junio C Hamano clarified that this occurs when the initial 32-byte header buffer inflation already captures the entire payload, resolving the confusion without raising new objections to the approved fix. No maintainer decision on the full series has been announced yet.

Only patches 1/5 and 3/5 carry automated tests in `t/t1060-object-corruption.sh` and `t/t1006-cat-file.sh`; the LLP64-specific and multi-gigabyte fixes (2/5, 4/5, 5/5) rely on documented manual reproduction steps in their commit messages since CI cannot easily allocate near-4-GiB buffers. The series complements two other type-widening efforts by the same author, and the v1 `diff.c` fix dropped from this series is handled separately.
