This thread is a six-patch bugfix series from Elia Pinto addressing loose object handling and size truncation bugs, with particular impact on LLP64 platforms like 64-bit Windows. The series targets two universal bugs (missing size checks in loose object parsing) and four platform-specific issues where `long`/`size_t` mismatches cause truncation or overflow in `cat-file`, `notes`, and `diff` subsystems.

The second patch in the series just posted fixes a critical truncation bug where objects larger than 4 GiB could trigger buffer overflows or memory corruption on Windows. The root cause is a type mismatch: while `parse_loose_header()` now uses `size_t` for object sizes, downstream functions like `unpack_loose_rest()` still use `unsigned long`, leading to allocation mismatches. The fix propagates `size_t` consistently through the loose object reading path, affecting `object-file.c`, `object-file.h`, and `odb/source-loose.c`. Though the patch lacks automated tests (due to the impracticality of allocating 4 GiB in CI), the commit message provides manual reproduction steps.

The series remains under review with no substantive feedback yet. All patches are based on `master` and don’t conflict with Elia’s related "use size_t for object sizes" series. While the first and third patches include new tests, the platform-specific fixes (including this one) rely on manual verification due to their LLP64 dependencies. The series was initially reviewed on `git-security` but deemed non-security-sensitive. Key files touched include `object-file.c`, `notes.c`, and `diff.c`, with no on-disk format changes.
