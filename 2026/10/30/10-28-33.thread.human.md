This thread is Elia Pinto's five-patch v2 series fixing loose object handling and size truncation bugs, with a focus on LLP64 platforms like 64-bit Windows where `long` is 32-bit but `size_t` is 64-bit. The series addresses missing bounds checks in loose object parsing and streaming, an `int` truncation bug in `git cat-file --batch` for 2--4 GiB objects, and a heap overflow in notes concatenation -- all without changing the on-disk format. Only the two cross-platform fixes (patches 1/5 and 3/5) carry automated tests; the LLP64-specific and multi-gigabyte scenarios are documented with manual reproduction steps.

Junio C Hamano has now reviewed the first two patches favorably. He approved patch 1/5 outright ("Looking good. Thanks.") after confirming its post-inflation validation mirrors the existing packfile check, and he has also endorsed patch 2/5's widening of loose-object size variables from `unsigned long` to `size_t` as sensible and straightforward. His one substantive follow-up on patch 2/5 is a forward-looking question about whether any size arithmetic should use the `st_add()` family to guard against unsigned wrapping -- a concern that connects to patch 5/5's explicit use of `st_add3()`. No merge decision has been made; the series remains under review.

Patches 3/5 through 5/5 are still awaiting substantive maintainer review, and the broader question of whether `odb_write_object()`'s `unsigned long` length parameter should eventually be widened remains open as a loose end flagged by patch 5/5.
