This thread is Elia Pinto's five-patch v3 series fixing loose object handling and size truncation bugs, with three of the five patches specifically targeting LLP64 platforms like 64-bit Windows where `long` is 32-bit but `size_t` is 64-bit. The series addresses missing bounds checks in loose object parsing and streaming, a buffer overread in `git cat-file --batch` for objects between 2 and 4 GiB, and a heap overflow in `notes.c` when concatenating notes totaling 4 GiB or more. All five patches have received approval from maintainer Junio C Hamano, who called patch 4/5 "trivially correct" and approved the others with minor stylistic notes that v3 addresses.

Version 3 is the current iteration, rebased onto `master` and reworked per feedback. Patch 1/5 adds post-inflation validation to reject loose objects whose actual size disagrees with their header, with tests in `t/t1060-object-corruption.sh`. Patch 2/5 widens size variables from `unsigned long` to `size_t` throughout the loose object reading path to prevent truncation on LLP64 systems. Patch 3/5 fixes the streaming reader to fail when the inflated size mismatches the header, now returning silently with an error state so callers report the failure; it includes cross-platform tests in `t/t1006-cat-file.sh`. Patch 4/5 changes `batch_write()` in `builtin/cat-file.c` to take `size_t` instead of `int`, fixing the 2--4 GiB overread. Patch 5/5 changes `buf_len` to `size_t` in `combine_notes_concatenate()` in `notes.c` to prevent heap overflow on LLP64 platforms.

The series remains under review with no open objections. Patches 2/5, 4/5, and 5/5 lack automated tests because they require multi-gigabyte objects or 32-bit `long` platforms, but their commit messages document manual reproduction steps. The thread notes a broader API limitation that `odb_write_object()` still accepts `unsigned long` for its length parameter, which patch 5/5 works around with `cast_size_t_to_ulong()`.
