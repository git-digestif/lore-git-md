This is the second patch in Harald Nordgren’s four-patch v5 series extending `git branch --delete-merged` to detect squash-merged and rebase-merged branches. The patch is a preparatory refactoring: it extends the `delete_branches()` helper to accept an optional `strmap` that records where each branch’s changes landed. When a branch is listed in the map, the merge check is skipped and the output is updated to show both the branch’s old tip and the landing commit (e.g., `Deleted branch topic (was 1a2b3c4, landed as 9f8e7d6)`). No caller passes a map yet, so the behavior is unchanged in this patch.

The change is purely internal plumbing for the later `--delete-integrated` flag. The commit message explains the motivation clearly: branches whose changes were squash-merged are not reachable from upstream, so the current merge check would refuse to delete them, and users need to know where their changes went. The implementation is straightforward: a new `landed_commits` parameter, a conditional skip of the merge check, and updated output formatting. The patch is uncontroversial and ready for integration; it was explicitly marked as such in the thread AI summary.
