This is a test patch, part of a six-patch series from Miklos Vajna that aims to speed up `git log --follow` for merge commits. This first patch adds test coverage for existing `--follow` behavior across merges, ensuring that later optimizations don’t break edge cases.

The new tests in `t/t4219-log-follow-merge.sh` cover four scenarios: following renames through forks with different diff-merges options (`-c`, `--cc`, `--remerge-diff`), handling `--no-ff` merges where a rename comes from the second parent (tested in both commit orders), merges that keep a path while the other side renamed it, and `--diff-merges=first-parent` which diffs merges only against their first parent but still walks all parents. The tests are thorough, exercising both the happy paths and subtle ordering dependencies.

The patch is well-structured: each test case is clearly motivated in the commit message, and the shell helper functions (`setup_rename_on_second_parent`) avoid duplication. The test names are descriptive, making it easy to see what each block verifies. This looks like a solid foundation for the performance work that follows in the series.
