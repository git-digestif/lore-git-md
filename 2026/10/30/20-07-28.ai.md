This is a test patch, part 1 of a 6-patch series (v4) by Miklos Vajna. It expands the test coverage for `git log --follow` behavior across merge commits, specifically targeting edge cases that currently work but lack explicit tests. The goal is to prevent regressions in a later patch that will optimize `--follow` for merges.

The patch adds 124 new test cases to `t/t4219-log-follow-merge.sh`, covering four scenarios: (1) `--follow` through a fork with renames on both sides, tested with `-c`, `--cc`, and `--remerge-diff`; (2) a `--no-ff` merge taking a rename from the second parent, tested in both commit orders to account for walk-order dependencies; (3) a merge keeping a path while the other side renamed it; and (4) `--diff-merges=first-parent`, which diffs merges only against their first parent but still walks all parents.

The tests are structured as shell functions (`setup_rename_on_second_parent`) and loops to avoid duplication, with clear expectations for each case. No code changes outside the test file are introduced. The commit message explicitly states this is preparatory work for a later optimization, making the motivation clear. The patch appears thorough and well-scoped for its purpose.
