This is the fourth and final patch in Elia Pinto’s **v2 series fixing 64-to-32 truncations on Windows (LLP64 platforms)**. It addresses a **theoretical integer-overflow risk** in the file-conversion subsystem (`convert.c`) that Patrick Steinhardt flagged during review of the third patch.

The patch converts the counters in `struct text_stat` (used for CRLF and binary-detection heuristics) and the `count_ident()` function (used for `$Id$` keyword expansion) from `unsigned`/`int` to `size_t`. Although the overflow risk is not Windows-specific (`unsigned` is 32-bit everywhere), the change is included because it touches the same code path and was raised in the same review thread. The counters drive decisions about whether to apply CRLF conversion or keyword expansion, so an overflow could lead to incorrect behavior (e.g., skipping CRLF conversion for a file with exactly 2³² lone LFs). The patch also updates the size hint in `ident_to_worktree()` to use `st_add()` and `st_mult()`, ensuring the buffer allocation fails loudly rather than wrapping around.

The change is purely mechanical and affects only one file (`convert.c`). No test is added because triggering the overflow would require more than 4 GiB of input, but the fix is low-risk and preemptively eliminates a correctness hazard. The patch is well-motivated and directly addresses the feedback from the **v1 review**, completing the series. With this addition, the series now covers all four truncation/overflow sites identified in the author’s scan and appears ready for integration.
