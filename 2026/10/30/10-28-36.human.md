This is a bugfix patch, the third in a six-patch series by Elia Pinto. It plugs a hole in the loose-object streaming code: when Git inflates a loose object, it currently trusts the size in the object header and streams out whatever zlib produces, even if that is fewer or more bytes than the header claims. The patch adds a running counter of bytes handed out and, when the stream ends, compares it to the header size; if they do not match, the object is flagged as corrupt and the stream fails. The fix is accompanied by two new tests in `t/t1006-cat-file.sh` that create deliberately malformed objects (one too short, one too long) and verify that `git cat-file` now detects and reports the corruption. The change is confined to `odb/source-loose.c` and the test script, so it should not affect other parts of Git. The commit message is clear and the test coverage looks adequate.
