This thread began when Ulrich Windl asked whether Git’s `.gitignore` wildcard `*` can match an empty string—a question the existing documentation left ambiguous. Junio C Hamano responded with a patch to clarify the `gitignore(5)` man page, proposing that `*` matches “a string of any length” (which implicitly includes zero-length strings). Tuomas Ahola then suggested a more explicit phrasing, “string of length of zero or more,” citing the `glob(7)` man page as precedent. Ulrich confirmed both phrasings were unambiguous, but the maintainer’s preference remained open.

In this latest update, Junio revises the patch to adopt the most explicit wording from `glob(7)`, now stating that `*` matches “any string (including the empty string).” The change also expands the explanation of bracket notation and escaping, removing the `fnmatch(3)` reference to make the documentation self-contained. The patch touches only `Documentation/gitignore.adoc` and does not alter code or behavior. With the originating author’s approval and alignment with external documentation standards, the patch is likely to be merged as-is. The only remaining discussion point is whether the parenthetical is necessary, but the technical intent is settled. The series is now at v2 and under review, with no merge status yet.
