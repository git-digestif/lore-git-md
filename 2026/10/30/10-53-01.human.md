This is the third patch in Harald Nordgren’s v5 series introducing `git branch --delete-integrated`, a new flag that extends `git branch --delete-merged` to detect branches whose changes (but not their tips) have been integrated via rebase or squash merges. The patch implements the core `--delete-integrated` logic: tree-based rebase detection and squash-detection via a path-by-path three-way merge approximation.

The patch is technically mature and well-tested. It handles upstream modifications, reverted changes, partial landings, and mixed workflows, and Jasper Mayone’s tested review confirms the output format and edge-case behaviors. The CLI design is finalized and explicitly confirmed by Junio: `--delete-merged` preserves strict tip-reachability (current behavior, unchanged), while `--delete-integrated` is an opt-in flag that detects both rebased and squash-merged branches. The two flags cannot be combined, and the error message for that case is now concise ("cannot be used together").

The patch touches `builtin/branch.c`, `Documentation/`, and `t/t3200-branch.sh`. The rebase-detection logic is tree-based (no blob fetches), while squash-detection uses `ll_merge` for three-way merge approximation, which may download blobs in partial clones when upstream modifications are present. The test suite includes coverage for rebase merges, squash merges, reverted changes, and mixed workflows, and the config variable `branch.<name>.deleteMerged` applies to both flags.

The only major technical gap is the author-check mitigation (Jasper’s proposal to require that the landing commit’s author also authored at least one commit on the branch being deleted), which is still not implemented but is now the sole remaining blocker for safety in forge workflows and the "npm update" scenario. The patch is otherwise ready for review and integration.
