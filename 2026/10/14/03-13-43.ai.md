This is the **eighth patch in the v2 series** optimizing `git push` refspec matching, focusing on a **correctness fix** for duplicate destination handling. The patch ensures that when pushing to an empty remote, Git now correctly rejects attempts to push multiple refspecs to the same destination (e.g., `git push remote.git A:foo B:foo`), aligning client-side behavior with server-side enforcement.

### What the patch does
The bug stems from `match_explicit_refs()` passing a static `dst` pointer to `match_explicit()` for each refspec. When the remote is empty (`dst == NULL`), newly created destinations are appended to the list, but subsequent iterations fail to see them because they still receive the original `NULL` pointer. The fix changes `match_explicit_refs()` to pass `dst` by pointer, ensuring each iteration re-reads the updated list head. This guarantees that duplicate destinations are detected and rejected client-side, even for empty remotes.

### Test updates
The patch updates and adds tests to verify the new behavior:
- **`t5408`**: Existing tests are modified to expect the new client-side error message (`"dst ref ... receives from more than one src"`) instead of the server-side rejection (`"multiple updates for ref ... not allowed"`). Test descriptions are clarified to note that prior versions did not assert anything about partial ref update ordering.
- **`t5516`**: Six new tests cover edge cases, including:
  - Pushing two refspecs to the same new branch (with and without `--dry-run`).
  - Pushing to an empty remote (with and without `--dry-run`).
  - Mixing abbreviated and full refspecs (e.g., `main:frotz` and `main:refs/heads/frotz`).

### Key details
- **Files touched**: `remote.c`, `t/t5408-send-pack-stdin.sh`, `t/t5516-fetch-push.sh`.
- **Behavioral change**: Duplicate destinations are now rejected **client-side** for empty remotes, matching the existing behavior for non-empty remotes. This fixes a long-standing inconsistency.
- **Error message**: The new message (`"dst ref ... receives from more than one src"`) is more precise than the server-side message it replaces.
- **Backward compatibility**: The change is strictly a correctness fix; no on-disk format or protocol changes are involved.

### Context in the series
This patch is part of the broader effort to optimize refspec matching (see the thread AI summary). While earlier patches focused on performance, this one addresses a **correctness gap** exposed by the 2025 server-side change (`9d2962a7c4`) that rejects duplicate ref updates. The fix ensures client-side validation is consistent regardless of remote state.
