Thread identity: standalone bugfix patch for the reftable backend, authored by Matthew Suozzo via GitGitGadget. Thread type: bug report and fix.

Core problem or goal: fix a potential buffer overflow in the reftable backend's object record decoder (`reftable/record.c`). The decoder fails to validate that the 64-bit varint offset count does not exceed the remaining record length, which could lead to writing past an allocated array on 32-bit systems or unnecessarily large allocations on 64-bit systems. The bug is not currently triggered by Git's production code but poses a latent risk.

Current status: patch posted as a single commit, not yet reviewed or integrated. No prior versions exist. The fix is minimal: a bounds check in `reftable_obj_record_decode()` and a new unit test in `t/unit-tests/u-reftable-record.c` that verifies the decoder rejects malformed records with an oversized offset count. The test suite `u-reftable-record` is also added to the Makefile (it was previously only in Meson builds).

Key technical details:
- Files touched: `reftable/record.c`, `t/unit-tests/u-reftable-record.c`, `Makefile`.
- New behavior: decoder now returns `REFTABLE_FORMAT_ERROR` when the offset count exceeds the remaining record length.
- On-disk format: unchanged.
- Test coverage: new unit test constructs a malformed record and verifies the error code.

Open questions and loose ends: none identified. The patch is self-contained and addresses the issue fully. No design objections or requests for changes have been raised yet.
