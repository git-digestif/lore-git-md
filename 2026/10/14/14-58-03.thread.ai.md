Core problem or goal: fix a potential buffer overflow in the reftable backend's object record decoder (`reftable/record.c`). The root cause is `reftable_alloc_size()`'s overflow check being ineffective on 32-bit systems due to `size_t` truncation of 64-bit values, with a secondary concern that `REFTABLE_CALLOC_ARRAY` bypasses the helper and calls `reftable_calloc()` directly, risking truncation. The v2 series addresses the root cause by widening allocation size arguments to `uintmax_t` while preserving the return type as `size_t`, ensuring correct overflow detection. The series also ensures consistent test coverage by adding the `u-reftable-record` test suite to the Makefile (previously only in Meson).

Current status: v2 patch series posted, incorporating feedback from Patrick Steinhardt and Aniket Gupta.
