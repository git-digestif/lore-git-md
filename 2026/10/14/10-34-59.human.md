This is a brief follow-up in the CI housekeeping series, specifically addressing Jeff King’s review of the first patch. The patch adds a `SHA1` prerequisite to a test in `t/t5004-archive-corner-cases.sh` to prevent it from running in SHA-256 repositories, where it would fail due to SHA-1 object incompatibility.

Jeff raised a valid long-term concern: once Git 3.0 defaults to SHA-256, the test would effectively never run in CI, even though it remains valid for SHA-1 repositories. He proposed an alternative approach—making the test self-contained by creating a temporary SHA-1 repository (`git init --object-format=sha1`) for its duration. This would allow the test to run in any environment meeting the other prerequisites (`EXPENSIVE`, `LONG_IS_64BIT`, `UNZIP`, etc.), preserving coverage without relying on a dedicated SHA-1 CI job.

Patrick’s reply is minimal but agrees with the suggestion ("Hmm. Yeah, I guess that wouldn't hurt."). This signals he is open to revising the patch to adopt Jeff’s approach, though no updated patch has been posted yet. The change would be a small but meaningful improvement to the test’s maintainability, aligning with the series’ broader goal of simplifying CI while preserving coverage. If Patrick incorporates the feedback, the test will remain viable even after Git 3.0 shifts to SHA-256 by default. For now, this remains an open point in the series.
