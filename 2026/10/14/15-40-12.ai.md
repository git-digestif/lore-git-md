This is a performance-focused refactoring series for `git stash`, expanding on Phillip Wood’s earlier `pw/stash-optimize-check_changes-calls/v1` effort. The v2 series now targets redundant index loads and refreshes in `git stash push` and `git stash create`, reducing the number of `lstat()` calls per changed path by four for `create` and eight for `push`. It also consolidates the duplicate `check_changes()` calls from v1, ensuring untracked files are walked only once.

The series has grown from two to seven patches, all touching `builtin/stash.c`. Key changes include introducing an enum (`CREATE_NO_CHANGES`) to distinguish between "no changes to stash" and "nothing stashed" (e.g., `--patch` with no hunks selected), removing redundant `repo_read_preload_index()` and `refresh_index()` calls, and simplifying the `reset_tree()` function signature. The net effect is fewer index operations without altering user-visible behavior.

Phillip, a seasoned contributor with deep stash/sequencer expertise, addresses Junio C Hamano’s feedback from v1 by fixing commit message typos and tackling the unconditional double index refresh in `do_push_stash()`. The series now makes callers responsible for refreshing the index, eliminating redundant work. Performance gains are measurable but modest—primarily reducing `lstat()` overhead—though the code hygiene improvements are clear.

No new edge cases or controversies are introduced; the changes are mechanical and well-motivated. The series is under active review, with Junio’s earlier feedback incorporated.
