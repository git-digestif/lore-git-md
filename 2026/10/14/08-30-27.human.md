This is the first patch in Patrick Steinhardt’s v3 CI housekeeping series, a test adjustment targeting `t/t5004-archive-corner-cases.sh`. Without this change, the upcoming fix to the Fedora CI job (which enables SHA-256 by default) would break the test, as SHA-1 objects cannot be meaningfully extracted into a SHA-256 repository.

The change is minimal—one line in a single test file—and directly addresses a latent issue uncovered by the series’ broader CI updates. The test in question is already gated by several prerequisites (`EXPENSIVE`, `LONG_IS_64BIT`, `UNZIP_ZIP64_SUPPORT`), so the addition of `SHA1` is a natural fit. The commit message clearly explains the motivation and ties it to the next patch in the series, which fixes the typo that currently disables SHA-256 in the Fedora job.

This patch is uncontroversial and well-justified.
