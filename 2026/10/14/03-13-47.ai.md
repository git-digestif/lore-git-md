This is the **final patch in the v2 performance series** optimizing `git push` refspec matching, specifically targeting `--force-with-lease` overhead. It replaces the O(N*M) linear traversal of remote refs in `apply_push_cas()` with a `strmap`-based lookup, reducing complexity to O(N*rules) for N lease entries and M remote refs. The patch builds on the preparatory refactoring in patch 11 (which split `apply_push_cas()` into `apply_one_cas()` and `apply_cas_tracking()` helpers) and demonstrates **61–64% speedups** for 100-lease scenarios in the perf script (`t/perf/p5516-push-delete-refspec.sh`), with timings dropping from **0.45–0.49s to 0.16–0.19s**.

The implementation is straightforward: `apply_one_cas()` now takes a `strmap` of remote refs (keyed by refname) instead of a linked list, and uses `expand_ref_prefix()` to generate candidate patterns for each lease entry’s refname. The `strmap` is built once in `apply_push_cas()` via a new helper `ref_map_init()`, which iterates over the remote refs list and populates the map. The patch preserves all existing behavior, including the `use_tracking` and `use_force_if_includes` logic, and adds no new tests since the functionality is unchanged.

The perf results in the commit message show consistent improvements across all test cases, with the largest gains in the 100-lease scenarios. The patch touches only `remote.c` and introduces no new symbols beyond the internal `ref_map_init()` helper. This is a clean, mechanical optimization that aligns with the series’ broader goal of replacing linear traversals with `strmap` lookups.
