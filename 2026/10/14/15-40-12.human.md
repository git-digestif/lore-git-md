This is a refactoring and performance patch series for `git stash`, now expanded to version 2 (`v2`). Phillip Wood builds on his earlier `v1` series (which removed redundant change-detection calls) by addressing unnecessary index loads and refreshes in `git stash push` and `git stash create`. The result is a measurable reduction in `lstat()` calls: four fewer per changed path for `git stash create` and eight fewer for `git stash push`. The series also consolidates the handling of `do_create_stash()` return values using an enum for clarity.

The seven-patch series touches only `builtin/stash.c` and is purely internal: no user-visible behavior changes, no new options, and no test updates. Changes include removing redundant `repo_read_preload_index()` and `refresh_index()` calls, simplifying the temporary index creation logic, and cleaning up the `reset_tree()` function signature. The base commit remains `c46c1e37724f0478939de636ab8ea5a89086d532`.

Phillip is a well-regarded contributor with deep expertise in the stash and sequencer subsystems, and the patches are clearly motivated by a desire for both code hygiene and performance. The series is under active review, with Junio C Hamano already providing feedback on the first iteration. This version (`v2`) addresses that feedback and expands the scope to tackle the broader inefficiency of repeated index operations. The patches are small, focused, and mechanically sound, making them a strong candidate for merging once review converges.
