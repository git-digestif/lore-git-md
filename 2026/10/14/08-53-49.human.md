This is the fifth patch in Patrick Steinhardt’s six-patch series refactoring and optimizing alternates handling in Git’s object database (ODB) "files" backend. The patch addresses a specific edge case in error handling: when Git encounters a corrupt object in a repository with a promisor remote, it currently attempts to fetch the object from the remote and retry reading it. This patch changes that behavior to treat corruption as an unrecoverable error, refusing to re-fetch corrupt objects.

The change is small but significant: it modifies `do_oid_object_info_extended()` in `odb.c` to skip the promisor remote fetch step when the object is corrupt (returning `ODB_READ_ERROR` immediately) rather than when it is merely missing (`ODB_READ_NOT_FOUND`). The patch removes 20 lines of code, simplifying the control flow by eliminating the `corrupt` flag and the redundant read attempt. This aligns with Justin Tobler’s feedback from the first iteration of the series, which argued that papering over corruption by fetching from a remote is dubious and could mask repository integrity issues.

The patch is well-motivated and uncontroversial. It touches only one file (`odb.c`) and does not change user-visible behavior or on-disk formats. The commit message clearly explains the rationale and credits Justin for the suggestion. This is a clean, focused fix that tightens error handling in the ODB layer, and it looks ready to proceed alongside the rest of the series.
