This patch is a **bugfix** targeting the **reftable backend**, specifically the object record decoder in `reftable/record.c`. It addresses a potential buffer overflow when decoding object records where the offset count (a 64-bit varint) exceeds the remaining record length. On 32-bit systems, this could lead to writing past the allocated array; on 64-bit systems, it would cause an unnecessarily large allocation. The fix adds a bounds check to reject counts larger than the remaining record length, since each offset requires at least one byte.

The commit message clarifies that this bug is not currently triggered by Git's production code—object blocks are only read by unit tests—but the decoder is still incorrect and could pose a risk if the code path changes. The patch also adds the `u-reftable-record` test suite to the Makefile (it was already included in Meson builds) to ensure the new test runs in both build systems.

The change is minimal and focused: a single bounds check in `reftable_obj_record_decode()` and a new unit test in `t/unit-tests/u-reftable-record.c` that verifies the fix by constructing a malformed record with an offset count larger than the remaining data. The test uses `cl_assert_equal_i` to confirm the decoder returns `REFTABLE_FORMAT_ERROR` as expected.

This is a standalone patch (not part of a series) and appears well-motivated, with clear technical reasoning and test coverage. The bug is subtle but real, and the fix is straightforward. The reftable backend is an ongoing area of active development, so hardening its low-level decoders is a sensible precaution.
