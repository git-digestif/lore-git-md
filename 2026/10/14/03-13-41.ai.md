This is the **sixth patch in the v2 series** that speeds up refspec matching in `git push` for large-scale deletions. It adds **explicit test coverage** for two server-side behaviors that were previously only exercised indirectly by client-side tests: `receive-pack` rejecting duplicate ref updates and `send-pack` handling duplicate status reports from the remote.

The patch touches two test scripts:
- `t/t5408-send-pack-stdin.sh`: Adds a test where `send-pack` receives two status reports for the same ref (`refs/heads/foo`) from a mock remote. The test verifies that `send-pack` correctly reports the second error message to the user.
- `t/t5410-receive-pack.sh`: Adds a test where `receive-pack` is fed a raw protocol request containing two updates for the same ref (`refs/heads/foo`). The test checks that `receive-pack` rejects the request with an explicit error message, that the response contains two "failed to update" lines, and that the ref remains unset.

These tests are **plumbing-level** and use `test-tool pkt-line` to construct raw protocol messages, avoiding reliance on the client’s refspec-matching logic. This future-proofs the tests against the upcoming client-side change (in patch 8) that will reject duplicate destinations before sending any updates. The tests also document the current behavior, which is important because the existing `t5408` tests that exercise these paths will break once the client-side fix lands.

The patch is **well-scoped and uncontroversial**: it only adds test coverage, does not change any production code, and the new tests are clearly motivated by the need to preserve existing behavior in the face of upcoming client-side changes.
