This is the **second patch in Patrick Steinhardt’s six-patch v2 series** refactoring and optimizing alternates handling in Git’s object database (ODB) "files" backend. It applies the same performance optimization introduced in patch 1/6 to the object-streaming code path, ensuring consistent behavior between direct object reads and streaming.

The change is small and mechanical: it reorders the loops in `odb_source_files_read_object_stream()` to check packfiles before loose objects, mirroring the optimization in patch 1/6. This avoids unnecessary `stat()` calls on loose objects when the object is already available in a packfile, though Patrick notes the performance impact is likely smaller here because streaming is dominated by the time to read large objects rather than filesystem metadata checks. The patch touches only **one file** (`odb/source-files.c`) and adds **4 lines** while removing **2**, with no behavior changes or new tests.

The motivation is alignment rather than raw speedup: the commit message explains that while the performance benefit may be modest, the change ensures the streaming and direct-read paths behave consistently. This is part of the series’ broader goal of cleaning up the ODB internals after Patrick’s earlier alternates migration work. The patch is uncontroversial and follows Justin Tobler’s substantive review of the series, which endorsed the design direction. No open questions remain for this specific patch.
