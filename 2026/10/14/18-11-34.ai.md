This is the second patch in Igor Wiedler’s two-patch v2 series addressing the performance regression in connectivity checks for deepening fetches. It tackles the root cause by extending `odb_for_each_alternate_ref()` to ignore refs from shallow or grafted alternates, aligning with Junio’s design feedback from the v1 discussion.

The patch modifies `odb.c` to check for the presence of a `shallow` or `info/grafts` file in each alternate repository before reading its refs. If either file exists, the alternate’s refs are skipped, preventing Git from treating them as valid history boundaries. The change is backward-compatible: existing alternates without these files continue to work as before, but those with shallow or grafted histories no longer trigger incorrect assumptions about available history. Documentation in `rev-list-options.adoc` is updated to reflect this behavior, and a new test in `t/t5618-alternate-refs.sh` verifies that refs from a shallow alternate are excluded from `--alternate-refs`.

The commit message explicitly defers handling partial clones (promisor remotes), noting that detecting them would require reading the alternate’s config. This edge case remains open for future work, but no objections or follow-up requests have been raised yet. The patch retains the approvals from Patrick Steinhardt and Justin Tobler for the core regression fix (patch 1), but neither has reviewed this expanded scope. Junio’s design concern from v1 is directly addressed here, making this a comprehensive solution rather than a stopgap.

This is a well-motivated, targeted fix that resolves a real-world performance issue while addressing the underlying design flaw. The changes are minimal, the tests are thorough, and the documentation update ensures users understand the new behavior. The deferred partial-clone case is a reasonable trade-off for now, given the complexity of detecting promisor remotes.
