This is the third patch in a five-patch **bugfix series** for `git worktree repair`, targeting a correctness issue where the command could incorrectly modify `.git` files belonging to unrelated worktrees. This patch refactors `infer_backlink()` to use `read_gitfile_raw()`—a stricter `.git` file parser introduced in patch 2—ensuring consistent handling of trailing whitespace and malformed `gitdir:` prefixes across the worktree repair codebase. The change also extracts `get_worktree_id()` as a helper function for reuse in patch 5, which adds validation logic to prevent repairs on unrelated worktrees.

The patch touches only `worktree.c` and makes no behavior changes; its purpose is to align `infer_backlink()` with the stricter parsing rules already adopted in `repair_gitfile()`. Previously, `infer_backlink()` used `strbuf_read_file()` and `strbuf_trim()`, which silently discarded trailing whitespace and accepted malformed `gitdir:` prefixes (e.g., `gitdir:foo/bar` without a trailing space). The new code treats trailing whitespace as part of the path (e.g., `gitdir: foo/bar/   ` resolves to `worktrees/   `) and rejects `.git` files that lack a valid `gitdir:` prefix, matching the behavior of `repair_gitfile()`. This consistency is critical for the validation logic in patch 5, which relies on accurate parsing to detect unrelated worktrees.

The extracted `get_worktree_id()` helper simplifies the logic for locating the worktree ID in a `.git` file’s contents, replacing manual pointer arithmetic with a cleaner abstraction. This function will be reused in patch 5 to validate the worktree ID against the expected administrative data. The patch is small (15 insertions, 10 deletions) and mechanical, with no new edge cases introduced. Test coverage for the stricter parsing rules was added in patch 2 and remains sufficient here.
