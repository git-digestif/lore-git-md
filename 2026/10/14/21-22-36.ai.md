This is a bugfix for `git fast-import` targeting a crash when resolving commits or tags created earlier in the same session but not yet reachable via the object database (ODB). The patch modifies `parse_from_existing()` in `builtin/fast-import.c` to check the fast-import object cache before falling back to the ODB, ensuring that in-session objects (held in an in-progress packfile) can be resolved without triggering a fatal error. The fix is minimal, preserves existing behavior for objects outside the cache, and includes thorough test coverage in `t9300-fast-import.sh` for both SHA-1 and SHA-256 repositories.

The test exercises four scenarios: `reset` with a new commit OID, `commit` with `from <new-oid>`, a tag created in the same session, and a tag-of-a-tag, using `test_oid_cache` to abstract object names.

Key technical details include the use of `find_object()` for cache lookup, `dereference()` to peel tags in the cache, and `gfi_unpack_entry()` to unpack objects from the in-progress packfile.
