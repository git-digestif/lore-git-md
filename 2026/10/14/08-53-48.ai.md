This is the **fourth patch in a six-patch refactoring and performance series** targeting the object database (ODB) subsystem, specifically cleaning up alternates handling in the "files" backend. The patch removes a redundant read loop in `do_oid_object_info_extended()` by replacing it with a single explicit re-read after fetching objects from a promisor remote.

The change simplifies the control flow in `odb.c` by eliminating the `while (1)` loop and `already_retried` flag, which were artifacts of the pre-alternates-migration era when alternates handling was split between the generic ODB layer and the backend. Now that alternates are fully encapsulated in the "files" backend, the loop is no longer needed. The patch replaces it with a straightforward sequence: first attempt to read the object, then (if missing and fetch is enabled) try fetching from a promisor remote, and finally re-attempt the read exactly once. The error-handling logic for corrupt objects and missing replacements remains unchanged.

The diff is mechanical and confined to `odb.c`, removing 23 lines and adding 23. The patch is part of a broader effort to simplify the ODB source API and align it with the alternates migration completed in an earlier series. It has no user-visible behavior changes or performance impact, but it makes the code easier to reason about by removing an unnecessary layer of indirection.

This patch was uncontroversial in v1 and remains so in v2; the only substantive feedback from Justin Tobler (about error handling) was addressed in a separate patch (5/6) added to this iteration. The series as a whole is well-motivated, with clear performance wins in patches 1-2 and clean internal API improvements in patches 3-6. This patch is a small but necessary step toward that goal.
