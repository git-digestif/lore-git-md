This is a **review reply** to the first patch in Patrick Steinhardt’s six-patch **ODB refactoring and performance series**. Johannes Schindelin (Dscho) endorses the patch and **requests the inclusion of a regression test** that Microsoft Git had to add independently to fix the same performance issue. The test, authored by Tyrie Vella, verifies that objects in alternate packfiles are checked before loose objects in the main repository, ensuring the optimization works as intended.

The test is **well-structured and portable**: it creates an alternate repository with a deltified object, writes a loose copy of the same object in the main repository, and confirms that `git cat-file --batch-check="%(deltabase)"` resolves to the alternate’s packfile (not the loose copy). Dscho reports the test passes with Patrick’s patch and fails on the unfixed base, confirming its effectiveness. The test is already validated on both SHA-1 and SHA-256 repositories.

This is a **surface-level but actionable review**: the feedback is narrowly focused on test coverage, not the patch’s design or implementation. The test itself is substantive—it directly verifies the performance-critical behavior—but the review does not engage with the broader ODB abstraction or the series’ architectural decisions. The request is straightforward and aligns with the project’s emphasis on regression protection. Patrick is likely to incorporate it in the next revision.
