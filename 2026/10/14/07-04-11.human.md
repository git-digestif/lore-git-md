This is the fourth patch in Harald Nordgren’s five-part series introducing a matching-inspired fetch mode for shallow repositories. The patch adds a `--limited-fetch` flag to `git remote add`, which configures the remote to use `remote.<name>.refmap` instead of the traditional wildcard `remote.<name>.fetch` refspec. This ensures that `git fetch <name>` only fetches branches already tracked by local branches, avoiding the performance penalty of negotiating history for all remote branches.

The implementation is straightforward and well-executed. The flag is rejected when combined with `-t/--track` or `--mirror`, as those options already specify explicit fetch behavior. The patch updates `builtin/remote.c` to set the refmap configuration (e.g., `+refs/heads/*:refs/remotes/<name>/*`) when `--limited-fetch` is used, and adds documentation to `git-remote.adoc` explaining the new behavior. Four new tests in `t/t5505-remote.sh` verify the flag’s behavior, including its conflict with `-t` and its use in non-shallow repositories.
