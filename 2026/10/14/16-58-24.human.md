This is a bugfix for the sequencer, specifically targeting a subtle ref-handling issue during interactive rebase with `--update-refs`.

The patch fixes a case where the name of the branch currently checked out in the main worktree can be accidentally "clobbered" in a static buffer by a worktree that checks out a different branch pointing to the same commit. When decorations are processed in reverse alphabetical order, this can cause the wrong branch to be skipped in the rebase todo list, while the branch that should have been skipped gets a "checked out" comment instead. The commit message traces the regression to aa37f3e1d89 (2022) and the test that exposed it to 94304b9f48e (2024).

The fix itself is small and surgical: replace `refs_resolve_ref_unsafe()` with `refs_resolve_refdup()`, which returns a freshly allocated buffer that can be safely freed after use. The patch also corrects an existing test expectation and adds a new test that explicitly covers both alphabetical orderings of the branch names.

The commit message is clear and well-motivated, the code change is minimal, and the test coverage is thorough. This looks like a solid, uncontroversial fix for a real edge case.
