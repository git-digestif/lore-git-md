This is the first patch in Patrick Steinhardt’s six-part **refactoring and performance series** for the Git object database’s "files" backend, now in its second iteration (v2). It directly addresses a **performance regression** introduced when alternates handling was reorganized for pluggable ODB support. The patch reorders the object lookup loop to prioritize packfile checks over loose-object `stat()` calls, achieving a **2x speedup** in object reading when alternates are present.

The change is **well-motivated and narrowly scoped**: it swaps the order of two loops in `odb_source_files_read_object_info()` so that Git checks all packfiles across alternates before falling back to loose objects. This leverages the fact that packfile lookups are cache-friendly (using in-memory pack indices) while loose-object checks always incur a `stat()` syscall. The benchmark in the commit message shows a clear improvement—from 179ms to 95ms—when reading objects from a packed alternate repository.

The patch is **uncontroversial and already reviewed**: Justin Tobler’s substantive review confirmed the technical rationale and implementation. No behavior changes are introduced, and the diff is minimal (3 insertions, 2 deletions in a single file). This is a **clean performance win** that aligns with the broader ODB abstraction effort, and it’s likely to proceed to `next` without further debate. If you care about Git’s internals or large-repository performance, this patch is worth noting for its practical impact.
