This is the fourth patch in Jon Simons' v2 performance series that speeds up `git push` refspec matching for large-scale branch deletions. It targets the `check_push_refs()` function in `remote.c`, replacing its O(R * N) linear traversal of local refs with `strmap` lookups to achieve O(R * rules) complexity.

The patch introduces a new helper, `count_refspec_match_in_map()`, which builds a `strmap` of local refs once (O(N)) and then uses `expand_ref_prefix()` to generate the six possible refname patterns for each refspec, checking each against the map (O(R * rules)). The existing `count_refspec_match()` logic is preserved but refactored into reusable components (`add_refspec_match()`, `finish_refspec_match()`) to avoid duplication. A temporary `match_explicit_lhs_map()` function is added alongside the original `match_explicit_lhs()` to maintain compatibility with `match_explicit()`, which still operates on the ref list; these will be merged in a later patch.

Performance measurements in the commit message show modest but meaningful gains, particularly for the "mirror" case with many refspecs: a 31.1% improvement for 100 refspecs (1.19s → 0.82s). The patch is well-structured, with clear separation of concerns and no behavioral changes—just a mechanical optimization of the matching algorithm.
