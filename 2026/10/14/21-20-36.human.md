This is the final patch in a five-part **bugfix series** for `git worktree repair`. It directly addresses the core issue: the command can corrupt unrelated `.git` files or gitdirs when cross-references between a worktree and its administrative data aren’t validated. The fix adds explicit checks to ensure the worktree ID in the `.git` file matches the worktree being repaired and that the gitdir path can be inferred before proceeding.

The patch touches `worktree.c` and expands test coverage in `t/t2406-worktree-repair.sh` with new cases for skipping repairs on unrelated `.git` files and handling `.git` files that don’t belong to a linked worktree. The key change is the addition of `strcmp(get_worktree_id(dotgit_contents), wt->id)` in `repair_gitfile()`, which prevents repairs if the worktree ID doesn’t match. Similarly, `repair_worktree_at_path()` now fails early if the inferred backlink is empty, avoiding accidental corruption of unrelated gitdirs.

The test updates are thorough, covering edge cases like swapped worktree directories and copied worktrees.
