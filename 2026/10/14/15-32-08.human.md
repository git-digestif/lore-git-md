This is a bugfix patch targeting the files ref backend. Andy Koppe reports a long-standing inconsistency in how root refs (like `HEAD` or `ORIG_HEAD`) are handled by the loose ref cache: once the cache is populated by an operation that *doesn’t* request root refs, a later operation that *does* request them will still omit them, and vice versa. The patch keeps root refs out of the shared loose ref cache entirely, instead reading them into a separate, short-lived cache when needed and overlaying that iterator on the loose ref iterator. The test demonstrates the bug and verifies the fix for the `--merged` filter. The change is confined to `refs/files-backend.c` and adds a new regression test in `t6302-for-each-ref-filter.sh`. The commit message is clear and the code looks clean; the patch appears well-motivated and ready for review.
