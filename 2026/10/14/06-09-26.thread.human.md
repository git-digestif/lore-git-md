Johannes Schindelin has posted version 3 of a five-patch series addressing integer overflows flagged by Coverity across Git's archive, HTTP fetch, wrapper I/O, and date parsing code. The series hardens several subsystems against undefined behavior when arithmetic exceeds type limits, with the latest iteration incorporating Junio C Hamano's requested commit-message clarifications. Patch 2/5, now arriving, changes the `posn` variable in `http.c`'s `fwrite_sha1_file()` from `int` to `size_t` to match the buffer size type, eliminating a theoretical overflow if a single curl callback ever delivered more than `INT_MAX` bytes; the updated commit message now includes Junio's explanation that the position resets to zero on each callback invocation.

Junio has previously approved the direction of this work, calling v2 "a clear improvement over v1" and individually signing off on patches 1, 2, and 5, while Phillip Wood resolved review concerns on patch 3 by confirming all caller adjustments for the wrapper API changes were implemented. The series was flagged in a recent "What's cooking" report as waiting for response, and it now awaits Junio's final review of v3 before potentially queuing for integration. Outstanding items include Junio's suggestion to migrate `worktree.c` to the new `read_in_full_or_error()` API, which remains unaddressed, and an open question about auditing external callers for compatibility with the changed wrapper function signatures.
