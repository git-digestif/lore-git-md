This thread is a five-patch series from Johannes Schindelin, posted via GitGitGadget, that fixes integer-overflow risks flagged by Coverity in several Git subsystems (archive-tar, http, wrapper, and date). The patches are defensive, targeting latent issues rather than observed bugs, and introduce new overflow-checking macros in `git-compat-util.h`. The series is under review as v1, with no prior feedback yet.

Phillip Wood’s review of the third patch raises a platform-compatibility concern: the commit message claims that byte counts exceeding `SSIZE_MAX` "never" occur in practice, but a 2019 bugfix (`c14e5a1a50`) showed that `ssize_t` can be narrower than `size_t` on platforms like NonStop, making such overflows possible. Phillip has cc’d Randall S. Becker, the NonStop port maintainer, to clarify whether this remains a live issue. The patch itself—rejecting counts above `SSIZE_MAX` with `EINVAL`—is uncontroversial, but the assumption about caller behavior may need revisiting. The outcome depends on Randall’s input about NonStop’s current `ssize_t`/`size_t` widths and whether similar overflows have been observed there. No code changes are proposed yet, but the review adds important context about the patch’s real-world applicability.
