Johannes Schindelin has posted v3 of a five-patch series fixing integer overflows flagged by Coverity across archive-tar, HTTP fetch, the wrapper I/O layer, and date parsing. The final patch, just arrived, hardens `date.c` relative-date parsing: `approxidate_alpha()` now multiplies unit lengths in `uintmax_t` with an overflow check and returns NULL on failure instead of invoking undefined behavior, and `approxidate_digit()` rejects values above `INT_MAX` before narrowing, with `approxidate_str()` propagating the error so commands like `git reflog expire` report an invalid timestamp. Tests in `t/t0006-date.sh` cover both the 64-bit `time_t` success path ("4000 weeks ago") and rejection of an absurdly large value.

Junio C Hamano has been broadly supportive throughout, calling the v2 direction a clear improvement and approving patches 1, 2, and 5 individually; his commit-message nits on patches 1, 2, and 4 are incorporated in v3. Phillip Wood's substantive review of the wrapper write path (patch 3) traced the `ssize_t`-to-`int` return change through callers and identified latent bugs in the hook-feeding paths in `refs.c`, `sequencer.c`, and `transport.c`, all addressed. Patch 4 adds the read-side counterpart, a new `read_in_full_or_error()` returning `int` with a shared helper and a `BUG()` guard against oversized requests, migrating six call sites.

The series remains under review: Junio's "What's cooking" report still lists it as waiting for response, and his two remaining suggestions -- migrating `worktree.c` to `read_in_full_or_error()` and simplifying the shared helper's byte-count reporting -- were not addressed in v3. One loose end is that the commit messages do not address whether external callers of the changed wrapper API have been audited.
