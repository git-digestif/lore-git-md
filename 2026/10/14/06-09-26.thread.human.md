This thread is about a five-patch series from Johannes Schindelin that hardens Git against integer overflows flagged by Coverity, targeting subsystems like archive-tar, HTTP, wrapper, and date handling. The patches introduce defensive checks and new overflow-checking macros to prevent undefined behavior, crashes, or silent corruption from arithmetic exceeding type limits. The series is under review in its first version, with no major objections but a few open technical questions.

The key discussion points revolve around type choices and portability. Junio and Patrick Steinhardt have confirmed the correctness of changing `posn` in `http.c` from `int` to `size_t`, but Simon Richter now suggests using `off_t` instead, citing its conventional use for file positions and 64-bit guarantees with large file support. Meanwhile, Phillip Wood has raised concerns about the `SSIZE_MAX` vs. `size_t` width mismatch on platforms like NonStop, questioning whether the hardening in `wrapper.c` is purely theoretical or addresses a real risk. Phillip also proposed replacing the GCC-only `mult_overflows` macro with `intmax_t` arithmetic for broader compiler compatibility in `date.c`. Randall S. Becker, the NonStop port maintainer, has been cc’d but hasn’t yet responded.

The series remains uncontroversial in its goal, with no requests for code changes beyond these type-system refinements. The patches are ready for integration once Johannes addresses the macro portability feedback and the `SSIZE_MAX` question, though the `off_t` suggestion may require further discussion. No test coverage has been added for the hardened edge cases, which could prompt review requests later. The broader suggestion to enable Coverity in CI remains a low-priority process note.
