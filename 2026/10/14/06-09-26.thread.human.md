This thread is a five-patch series from Johannes Schindelin, posted via GitGitGadget, that fixes integer-overflow risks flagged by Coverity across several Git subsystems. The series is now under review in its initial version, with four similar Coverity-fix branches from the same author already merged to `master` between July and October 2026.

The patches introduce defensive overflow checks in `archive-tar.c`, `http.c`, `wrapper.c`, and `date.c`, using new helper macros (`signed_mult_overflows` and `mult_overflows`) in `git-compat-util.h`. The most recent email, from Junio, clarifies that the `date.c` patch (patch 5/5) only affects local user input like `git commit --date="..."` or `git log @{...}`, not timestamps stored in commit objects, so there’s no risk of breaking history traversal across platforms. The patch itself remains unchanged and uncontroversial.

The only open question is a platform-specific concern raised by Phillip Wood about whether byte counts exceeding `SSIZE_MAX` could occur in practice on platforms like NonStop, where `ssize_t` may be narrower than `size_t`. Randall S. Becker, the NonStop port maintainer, has been cc’d but hasn’t yet weighed in. Until that’s resolved, the series is otherwise ready for integration, with no new tests added for the hardened edge cases.
