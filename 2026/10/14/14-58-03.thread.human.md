This thread is a focused bugfix for the reftable backend, submitted by Matthew Suozzo. The patch addresses a potential buffer overflow in the object record decoder (`reftable/record.c`) when handling malformed records with an offset count that exceeds the remaining record length. While the bug isn’t currently triggered in production—object blocks are only read by unit tests—the decoder’s incorrect behavior could become a risk if the code path changes. The fix is minimal: a bounds check in `reftable_obj_record_decode()` and a new unit test in `t/unit-tests/u-reftable-record.c` to verify the decoder rejects oversized counts with a `REFTABLE_FORMAT_ERROR`.

The patch is standalone and well-justified, with clear technical reasoning and test coverage. It also ensures the `u-reftable-record` test suite runs in both Makefile and Meson builds (it was previously missing from the former). Given the reftable backend’s active development, this kind of low-level hardening is a sensible precaution. There’s been no review activity yet, so the patch is still awaiting feedback.
