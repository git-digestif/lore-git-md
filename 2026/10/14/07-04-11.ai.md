This is the fourth patch in Harald Nordgren’s v9 series introducing a matching-inspired fetch mode for shallow repositories. The patch adds a `--limited-fetch` flag to `git remote add`, which configures the remote to use `remote.<name>.refmap` (e.g., `+refs/heads/*:refs/remotes/<name>/*`) instead of the traditional wildcard `remote.<name>.fetch` refspec. This ensures that `git fetch <name>` only fetches branches already tracked by local branches, avoiding the performance penalty of negotiating history for all remote branches.

The implementation updates `builtin/remote.c` to add the flag, which is rejected when combined with `-t/--track` or `--mirror` (since those options already specify explicit fetch behavior). The flag is stored as an integer (`limited_fetch = -1` for unspecified, `1` for enabled) and is only applied when no branches are explicitly tracked (`track.nr == 0`) and no mirror mode is active. The configuration is written to `.git/config` via `repo_config_set()`, setting `remote.<name>.refmap` to the wildcard mapping. Documentation in `git-remote.adoc` is updated to describe the new flag and its effect.

Test coverage in `t/t5505-remote.sh` verifies that `--limited-fetch` works in non-shallow repositories (setting the refmap and omitting the fetch refspec) and correctly conflicts with `-t`. The patch is uncontroversial and aligns with the series’ goal of reducing unnecessary fetch overhead. Junio’s earlier review of this patch (in a prior version) acknowledged it as straightforward, with no concerns raised. The patch is ready for merging as part of the series, pending final maintainer feedback on the overall v9 submission.
