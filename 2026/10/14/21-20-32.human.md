This is the first patch in a five-part **bugfix series** targeting the `git worktree repair` command. It refactors `.git` file handling in `repair_worktree_at_path()` to align with the stricter parsing already used in `repair_gitfile()`, replacing `read_gitfile_gently()` with `read_gitfile_raw()`. The change centralizes path resolution and repository validation logic, making the code more consistent and avoiding reliance on the non-reentrant `read_gitfile_gently()`.

The patch touches only `worktree.c` and is purely internal: no user-visible behavior changes yet, but it lays the groundwork for the validation logic in patch 5. The refactoring moves error handling to the caller, which now explicitly checks for absolute paths, resolves relative paths against the `.git` file’s location, and validates the resulting gitdir with `is_git_directory()`. This matches the behavior of `repair_gitfile()` and prepares for the stricter `.git` file parsing introduced later in the series (e.g., rejecting `gitdir:` prefixes without trailing spaces).

Junio’s earlier review of v1 requested clearer separation of refactoring from behavioral changes, and this patch responds by isolating the mechanical switch to `read_gitfile_raw()`. The commit message is concise but clear, and the code changes are straightforward. The patch is unlikely to be controversial, though the stricter parsing it enables (e.g., rejecting malformed `.git` files) may raise questions in later patches. For now, this is a clean, incremental step toward the series’ goal of preventing `git worktree repair` from corrupting unrelated worktrees.
