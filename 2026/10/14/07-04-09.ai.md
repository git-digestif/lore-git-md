This is the second patch in Harald Nordgren’s five-part v9 series introducing a matching-inspired fetch mode for shallow repositories. The patch extracts the existing logic that checks whether the current branch’s upstream lives on the remote being fetched into a new helper function, `collect_upstream_from_remote()`, so the same logic can be reused for other branches in later patches.

The change is a pure refactoring with no behavioral differences. It moves the inlined code from `do_fetch()` in `builtin/fetch.c` into `remote.c`, adds a corresponding declaration in `remote.h`, and threads a `struct repository *` parameter through the new helper to avoid hardcoding `the_repository`. The helper takes a `string_list` to populate, a `remote`, and an optional branch name (NULL means the current branch), and adds the upstream refs of any matching branches to the list. The call site in `do_fetch()` now uses the helper, iterating over the populated `string_list` to push the upstream refs into `transport_ls_refs_options.ref_prefixes`.

Junio’s two review points from v8—moving the `if/else if/else` control-flow reorganization to Patch 3/5 and restoring the NULL-check for `branch`—are both addressed here. The NULL-check is present in the helper (`repo_branch_get(repo, refname)` safely handles NULL), and the control-flow changes are deferred to the next patch. The patch is mechanically clean, with no edge cases or regressions introduced. Test coverage remains unchanged, as the behavior is identical to the previous version.

This patch is uncontroversial and ready for Junio’s re-review, which is the only remaining blocker before the series can graduate to `next`. The extraction is a necessary foundation for Patch 3/5, which implements the dynamic branch enumeration logic.
