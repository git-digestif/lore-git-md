This is the fourth patch in Patrick Steinhardt’s six-patch **refactoring and performance series** for the Git object database (ODB), focusing on cleaning up alternates handling in the "files" backend. The patch removes a redundant read loop in `do_oid_object_info_extended()` by replacing it with a single explicit re-read after fetching objects from a promisor remote.

The change simplifies the logic that was previously juggling multiple retries—reloading sources, handling second reads, and fetching missing objects—by leveraging the fact that the "files" backend now handles reloads and retries internally. The new version reads from the ODB source once, attempts a promisor fetch if the object is missing, and then re-reads exactly once, making the control flow easier to follow. The patch is purely internal, with no user-visible behavior changes or performance impact, and aligns with the series’ goal of reducing complexity in the ODB layer.

The diff is mechanical and well-scoped, touching only `odb.c` and removing 23 lines while adding 23. The commit message clearly explains the rationale and the simplification achieved.
