This is a bugfix for `git fast-import` targeting a crash that occurs when referencing commits or tags created earlier in the same session. The patch is now in its fourth iteration (v4) and addresses the last remaining feedback—a minor test script indentation issue—after three prior rounds of review.

The problem is straightforward: `git fast-import` crashes with `fatal: not a valid commit: <oid>` when a `commit` or `reset` command uses `from` to reference a commit or tag created earlier in the same session. The object exists in fast-import’s internal cache and can be queried via `ls` or `cat-blob`, but the object database (ODB) lookup fails because the object is still in an in-progress packfile, not yet indexed. The fix teaches `parse_from_existing()` to check the fast-import object cache first, peeling tags as needed, before falling back to the ODB.

The change is minimal and surgical: it modifies only `builtin/fast-import.c` (adding a cache lookup path in `parse_from_existing`) and adds a thorough test in `t9300-fast-import.sh` that exercises four scenarios—`reset` with a new commit OID, `commit` with `from <new-oid>`, a tag created in the same session, and a tag-of-a-tag—across both SHA-1 and SHA-256 repositories. The test uses `test_oid_cache` to abstract object names and avoid duplication.
