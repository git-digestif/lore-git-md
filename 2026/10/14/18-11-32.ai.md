This is a two-patch bugfix series targeting the connectivity check regression in deepening fetches, now expanded to address the broader design flaw Junio identified. The series is a direct response to the v1 discussion, adopting Junio’s proposed two-step fix: first, negate `--alternate-refs` in all connectivity checks (not just deepening fetches), and second, teach `odb_for_each_alternate_ref()` to ignore refs from shallow or grafted alternates entirely.

The core change is in patch 1: `--alternate-refs` is now negated alongside `--all` in `check_connected()`, ensuring alternate refs are treated as a boundary in both regular and deepening fetches. This replaces the v1’s one-line move with a more principled fix that aligns with Junio’s observation that alternate refs should never be trusted as unconditionally present. Patch 2 extends this logic to `odb_for_each_alternate_ref()`, preventing fetch-pack and receive-pack from treating shallow alternate refs as valid "have"s. The commit message for patch 2 notes a limitation: partial clones (promisor remotes) are not detected, leaving that edge case for future work.

Tests in `t/t5618-alternate-refs.sh` are expanded to cover both patches, using `GIT_TRACE2_EVENT` to verify `rev-list` arguments and `odb_for_each_alternate_ref()` behavior. The series touches `connected.c`, `odb.c`, and documentation (`rev-list-options.adoc`), with no new symbols introduced. The on-disk format remains unchanged, and the changes are backward-compatible—existing alternates continue to work, but now with stricter boundary enforcement.

Patrick Steinhardt and Justin Tobler’s approvals from v1 still apply to the core regression fix, but the series now incorporates Junio’s design feedback, shifting the scope from a targeted regression fix to a more comprehensive solution. The open question from v1—whether to merge the minimal fix now or wait for a broader solution—is resolved here by implementing both steps upfront. The only loose end is the undetected partial-clone case, which the commit message explicitly defers.

This looks like a well-structured, well-motivated fix for a real-world performance pain point, now addressing the root cause rather than just the symptom. The series is ready for review, with no unresolved technical concerns and clear alignment with maintainer feedback.
