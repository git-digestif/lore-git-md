This is the final maintainer sign-off on the `gitmergeconflicts(7)` documentation series. Junio C Hamano clarifies a technical point about `git apply -3` but ultimately accepts Julia Evans’ justification for omitting it from the new man page.

The exchange centers on whether `git apply -3` (which performs a three-way merge when applying a patch) should be listed alongside commands like `git merge` and `git rebase` in the exhaustive list of operations that can cause merge conflicts. Julia argued that including it would require explaining the distinction between patch application and three-way merges, which would complicate the guide without clear benefit. Junio initially questioned this reasoning, noting that `apply -3` is conceptually similar to cherry-picking, but he concedes the point and agrees that the current list—while not exhaustive—is sufficient for the guide’s scope.

This email confirms that no further changes are needed to the series. Junio’s earlier review already provided a `Reviewed-by:` for patches 2–6, and the squashable refinements to patch 1/6 (the `diff3` example and phrasing adjustments) have been incorporated by Julia. The series is now fully approved and ready for merging to `next`. The only remaining step is Junio’s integration, which is expected in the next "What’s cooking" cycle.

The discussion also underscores the guide’s pragmatic design: it prioritizes clarity and practical utility over encyclopedic completeness. By omitting edge cases like `git apply -3`, the authors avoid diluting the core message for the majority of users who encounter conflicts during merges, rebases, or cherry-picks. This aligns with the series’ goal of consolidating scattered advice into a single, actionable resource.
