This is the fifth patch in Phillip Wood’s seven-patch series `pw/stash-optimize-check_changes-calls/v2`, which refactors `git stash` internals to eliminate redundant index operations and `lstat()` calls. This specific patch reworks how `git stash create` builds its temporary index file, replacing the `reset_tree()` call with `create_index_from_tree()`—the same helper already used by `git stash push -p`. The change avoids the need to call `set_alternate_index_output()`, simplifies the code, and removes an unnecessary `repo_read_index_preload()` that was costing one extra `lstat()` per changed path. A new boolean parameter (`reset`) is added to `create_index_from_tree()` so the caller can decide whether to reset the index or merge into it; `stash_working_tree()` now passes `false` to preserve intent-to-add entries. The in-memory index is left untouched, so the patch also drops the preload call entirely. The diff is confined to `builtin/stash.c` and is purely mechanical—no user-visible behavior changes, just a cleaner, more efficient code path.
