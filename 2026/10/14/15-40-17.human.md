This is the fifth patch in Phillip Wood’s seven-part performance refactoring series for `git stash`. It targets a small but measurable inefficiency in `git stash create`: the way the command builds a temporary index file to capture working-tree changes.

The patch replaces the existing `reset_tree()` call with `create_index_from_tree()`, aligning the code with what `git stash push -p` already does. The key change is avoiding the `set_alternate_index_output()` dance, which was previously needed to redirect index writes to a temporary file. By switching to `create_index_from_tree()`, the code becomes cleaner and avoids an unnecessary `repo_read_index_preload()` call, saving one `lstat()` per changed path. A new boolean parameter (`reset`) lets the caller decide whether the index should be reset or merged; for `stash create`, the index is merged so that intent-to-add entries are still detected.

The diff is confined to `builtin/stash.c` and touches only the `stash_working_tree()` and `create_index_from_tree()` functions. No new symbols or user-visible behavior changes are introduced; the patch is purely internal plumbing. The motivation is clear: fewer system calls and simpler control flow, with no downside. Phillip’s commit message is concise and to the point, and the change itself looks mechanical and safe. This patch is a natural follow-up to the earlier ones in the series, continuing the theme of eliminating redundant index operations.
