This is the core feature patch in Harald Nordgren’s five-part series implementing a matching-inspired fetch mode for shallow repositories. Patch 3/5 teaches `git fetch` to infer which branches to fetch when a remote has `remote.<name>.refmap` configured but no `remote.<name>.fetch` refspec. Instead of failing or fetching all remote branches, the command now fetches only the branches that local branches already track as their `@{upstream}` on that remote.

The patch adds the `branches_tracking_remote()` helper in `remote.c`, which iterates over all local branches and collects the source ref of each branch whose `remote_name` matches the target remote. In `builtin/fetch.c`, `get_ref_map()` uses this helper to construct a dynamic refspec when no explicit refspec is given and the remote has a refmap but no fetch refspec. The `do_fetch()` function populates `transport_ls_refs_options.ref_prefixes` with the inferred branches, limiting the transport layer’s ref requests to only the branches actually in use.

The implementation is clean and well-tested: the new `t/t5586-fetch-refmap.sh` script (119 lines) verifies edge cases such as bare fetches, explicit one-time fetches, duplicate branch tracking, cross-remote tracking, and `git remote show` compatibility. The patch also updates documentation in `config/remote.adoc` and `fetch-options.adoc` to explain the new behavior. Junio’s review concerns from earlier versions are fully resolved, and the patch is ready for final maintainer feedback before graduating to `next`. This is a well-crafted solution to a real performance pain point for shallow-repository users.
