This is a bugfix patch targeting the pack-check subsystem, authored by Patrick Steinhardt.

The patch fixes an off-by-one error in how Git handles blob verification when a blob's size exactly matches `core.bigFileThreshold`. Currently, Git incorrectly treats such blobs as corrupt during `git fsck` because the streaming path (used for large blobs) refuses to create a stream for blobs at or below the threshold, while the pack-check code mistakenly routes blobs *equal* to the threshold to the streaming path. The fix aligns the threshold comparison with the rest of the codebase by making it exclusive (using `<` instead of `<=`).

The commit message provides clear historical context: the bug was introduced in 2016 (ec9d224903) but became problematic only after a 2026 change (13eb65d366) that modified how streams are created. The patch includes a new test in `t/t1450-fsck.sh` that verifies `git fsck` succeeds when a blob's size equals the threshold. The fix is minimal and targeted, though Patrick notes a more comprehensive solution (moving policy logic out of the streaming backend) might be preferable but could impact performance.

This is a well-motivated, low-risk correction to a subtle edge case that could cause false corruption reports. The test coverage and clear commit message make it easy to assess.
