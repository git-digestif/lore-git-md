This is the first patch in Harald Nordgren’s five-part v9 series introducing a matching-inspired fetch mode for shallow repositories. It adds the `remote.<name>.refmap` configuration variable, which provides a default value for the `--refmap` option in `git fetch`, mirroring how `remote.<name>.fetch` supplies default refspecs.

The patch is a clean plumbing addition with no behavior changes. It extends the `struct remote` to include a `refmap` field, updates the configuration parser to recognize `remote.<name>.refmap`, and modifies `get_ref_map()` in `builtin/fetch.c` to use the remote’s refmap as the default when no command-line `--refmap` is given. The precedence rule is preserved: if both `remote.<name>.fetch` and `remote.<name>.refmap` are configured, the former takes precedence, and the refmap is ignored unless there is an explicit fetch refspec (command-line or via `.fetch`).

Documentation updates cover `config/remote.adoc` and `fetch-options.adoc`, and the test suite (`t/t5510-fetch.sh`) adds three new tests verifying that the refmap behaves like `--refmap` on the command line, does nothing when nothing is being fetched, and correctly yields to `.fetch` when both are present. The implementation is straightforward and uncontroversial, with no edge cases or regressions introduced. Junio’s earlier review concerns about the design have been resolved in prior versions, and this patch is ready for integration. It is a necessary foundation for the dynamic branch inference logic introduced in later patches.
