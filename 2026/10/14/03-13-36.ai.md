This is the first patch in Jon Simons' **v2 performance-focused feature series** to speed up `git push` refspec matching for large-scale deletions. It adds **input validation** for the `<refname>` component in `--force-with-lease=<refname>[:<expect>]` by using `check_refname_format()` to reject invalid refnames (e.g., `./refs/heads/main`) early, rather than silently ignoring them later.

The patch addresses a **behavioral quirk** tied to the upcoming removal of `mkpath()` from `refname_match()` (patch 3 in the series). Currently, `mkpath()`'s `cleanup_path()` strips leading `./`, causing `./refs/heads/main` to match `refs/heads/main` unintentionally. After patch 3, this match will no longer occur, and the lease would be ignored. By validating refnames upfront, the patch ensures consistent failure (both before and after patch 3) and improves user feedback.

The change is minimal: two lines added to `remote.c` in `parse_push_cas_option()` and a new test in `t/t5533-push-cas.sh` verifying that `--force-with-lease=./refs/heads/main` fails with a clear error message. The test uses `test_must_fail` and `test_grep` to confirm the expected behavior.

This patch is **well-motivated** and **low-risk**, as it only adds validation without altering existing logic. It prepares the ground for the more invasive changes in later patches (e.g., patch 3) by ensuring users receive immediate feedback for invalid refnames.
