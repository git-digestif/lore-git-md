This is the v3 iteration of a bugfix for `git fast-import` that allows the `from` command to reference commits and tags created earlier in the same session. The patch addresses a crash (`fatal: not a valid commit: <oid>`) that occurs when `fast-import` tries to resolve a commit or tag that exists in its internal object cache but is not yet reachable via the object database (ODB) because it resides in an in-progress packfile.

The core change remains the same as in v2: `parse_from_existing()` now checks the fast-import object cache (via `find_object()`) before falling back to the ODB. If the object is found in the cache and is a commit or tag, it is unpacked directly from the in-progress packfile using `gfi_unpack_entry()`. Tags are peeled in the cache using the existing `dereference()` helper to match the ODB fallback behavior. The fix is minimal and preserves existing behavior for objects not in the cache.

What’s new in v3 is a significantly improved commit message, rewritten by Junio C Hamano to clarify the timing-dependent nature of the crash, the distinction between blob and commit handling, and the role of the in-progress packfile. The test case has also been refactored to use `test_oid_cache` and `test_oid`, eliminating duplication between the SHA-1 and SHA-256 variants. The test now covers `reset`, `from`, tag, and tag-of-tag scenarios for both hash algorithms.

The patch is technically sound and addresses all feedback from v2. The commit message is now precise and comprehensive, and the test hygiene improvements make the coverage more maintainable. No further technical objections are expected, and the patch is likely to be accepted once Junio’s suggested refinements are incorporated. The change is uncontroversial: it fixes a crash without altering behavior for objects already in the ODB.
