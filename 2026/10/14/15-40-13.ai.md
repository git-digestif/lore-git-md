This is the first patch in Phillip Wood’s seven-part refactoring series `pw/stash-optimize-check_changes-calls/v2`, which targets redundant change-detection logic in `git stash push` and `git stash create`. The patch introduces an enum (`enum create_result`) to replace the integer return type of `do_create_stash()`, adding a new value `CREATE_EMPTY` to distinguish between "no changes to stash" and "nothing stashed" (e.g., `--patch` with no hunks selected). This is a preparatory step for later patches in the series that will eliminate redundant `check_changes()` calls and index operations.

The patch also fixes a minor behavioral anomaly: `create_stash()` previously exited with status 1 when `do_create_stash()` returned 1 (indicating no changes), even though `create_stash()` itself had already determined there were no changes via `check_changes()`. By introducing `CREATE_EMPTY`, the patch ensures consistent exit statuses—`create_stash()` now exits 0 when there are no changes to stash, aligning with its documented behavior.

The changes are confined to `builtin/stash.c` and involve no new CLI options, config keys, or on-disk format changes. The enum is internal to the stash subsystem, and the patch does not alter user-visible behavior beyond the exit-status fix. The diff is mechanical but well-motivated, with clear commit message explanations for the enum’s purpose and the behavioral correction. No edge cases or controversies are introduced; the patch is a straightforward refactoring that sets the stage for the series’ broader performance optimizations.
