This is the **tenth patch in the v2 series** optimizing `git push` refspec matching for large-scale deletions. It extends the existing performance test script (`t/perf/p5516-push-delete-refspec.sh`) to measure the overhead of `--force-with-lease` when pushing multiple delete refspecs, establishing a baseline for a later optimization in patch 12.

The patch adds six new test cases (`empty:lease:1`, `empty:lease:10`, `empty:lease:100`, `mirror:lease:1`, `mirror:lease:10`, `mirror:lease:100`) that push 1, 10, or 100 delete refspecs *plus* one `--force-with-lease=<refname>:<expect>` per refspec. The commit message includes baseline timings (e.g., 0.45s for 100 refspecs on an empty client), which will be compared against the optimized version in patch 12. The implementation is straightforward: it generates refspecs and leases dynamically using `test_seq` and `sed`, then invokes `git push --dry-run` with both sets of arguments.

This is a **test infrastructure patch** with no functional changes to Git itself. The work is well-motivated: the author is methodically measuring each bottleneck before optimizing it, and the test cases will help validate the 10–100x speedup claims in the series. The patch is clean and focused, touching only the perf script. No controversies or open questions here—just a necessary step in the performance analysis.
