This is the second patch in a five-part bugfix series addressing integer overflows flagged by Coverity. The series is part of Johannes Schindelin’s ongoing effort to harden Git’s codebase against latent arithmetic defects.

This patch fixes a type mismatch in `http.c`’s `fwrite_sha1_file()` helper. The function tracks the number of bytes written using an `int` variable, but the total size to write is a `size_t`. When the HTTP response body exceeds `INT_MAX` (~2 GB), the `int` overflows, causing a heap under-read and writing potentially corrupt or leaked heap data to the temporary object file. The hash check afterward would reject the object, so no bad data enters the object store, but the under-read itself is a genuine defect. The fix is simple: change the variable’s type from `int` to `size_t` to match the total size parameter.

The commit message explains that the attack surface is theoretical under normal curl configurations (which deliver data in small chunks), but the type mismatch is still a defect worth fixing. No tests are included, consistent with the series’ defensive, latent-issue focus. The change is mechanical and uncontroversial, touching only one line in `http.c`.
