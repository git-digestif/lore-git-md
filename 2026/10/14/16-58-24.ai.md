This is a bugfix targeting the sequencer subsystem, specifically the `--update-refs` logic during interactive rebase.

The patch addresses a subtle ref-name clobbering bug in `add_decorations_to_list()`. The function uses `refs_resolve_ref_unsafe()` to get the name of the branch HEAD points to, but that function returns a pointer to a static buffer. When multiple worktrees are involved, checking out a branch in another worktree overwrites this buffer, causing the wrong branch to be marked as "checked out" in the rebase todo list. The fix replaces `refs_resolve_ref_unsafe()` with `refs_resolve_refdup()`, which allocates a new buffer, and adds a `free()` call to avoid leaks.

The commit message traces the regression to aa37f3e1d89 (2022) and notes that a test added in 94304b9f48e (2024) happened to trigger the bug but did not catch it due to alphabetical ordering of branch names. The patch corrects the test expectation and adds a new test with branches that sort both before and after the current branch, ensuring the fix is robust.

The change is small (11 lines in `sequencer.c`, 21 in the test) and well-motivated. The commit message is clear and references prior commits, making it easy to follow the history. The new test covers the edge case explicitly. This looks like a solid, low-risk fix for a real-world issue.
