This is the first patch in Harald Nordgren’s five-part v9 series introducing `remote.<name>.refmap` for matching-inspired fetch mode. The patch adds a per-remote configuration variable, `remote.<name>.refmap`, which provides the default value for the `--refmap` command-line option, mirroring how `remote.<name>.fetch` supplies default refspecs. The implementation is straightforward: it extends the `struct remote` to include a `refmap` field, updates the configuration parser to recognize `remote.<name>.refmap`, and modifies `get_ref_map()` in `builtin/fetch.c` to use the remote’s refmap as the default when no explicit `--refmap` is given. Documentation is updated in `config/remote.adoc` and `fetch-options.adoc` to describe the new configuration knob.

The patch is a clean, mechanical addition with no behavioral changes. It lays the groundwork for the dynamic branch inference logic introduced in Patch 3/5 by providing the configuration mechanism that separates namespace mapping from fetch selection. The precedence rule—`remote.<name>.fetch` takes precedence over `remote.<name>.refmap` when both are configured—is implemented here and is uncontroversial. Test coverage in `t/t5510-fetch.sh` verifies that the refmap behaves like `--refmap` on the command line, does nothing when nothing is being fetched, and is ignored when `remote.<name>.fetch` is also present.

The patch is technically sound, with no edge cases or regressions introduced. It is a prerequisite for the rest of the series and is ready for merging pending Junio’s re-review of Patch 2/5. The implementation threads a `struct refspec *` through `get_ref_map()` to avoid hardcoding `the_repository`, aligning with the project’s ongoing `the_repository` removal effort. The test suite additions are thorough and cover the key behaviors without overcomplicating the patch. This is a well-executed foundational change that enables the series’ core functionality.
