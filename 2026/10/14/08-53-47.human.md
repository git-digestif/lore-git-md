This is the **third patch in a six-patch refactoring series** targeting the Git object database (ODB) subsystem, specifically the alternates mechanism in the "files" backend. The series aims to optimize performance and clean up internal APIs without changing user-visible behavior.

This patch moves the "second read" logic — currently a generic ODB-layer mechanism — into the "files" backend, where it belongs. The `OBJECT_INFO_SECOND_READ` flag is removed entirely, simplifying the ODB source API. The change is motivated by the earlier migration of alternates handling into the "files" backend, which made the second-read logic an implementation detail rather than a cross-source concern.

The patch also repurposes the `OBJECT_INFO_QUICK` flag in the "packed" source to handle a race condition where a multi-pack index (MIDX) claims an object exists in a packfile that has since been deleted. This replaces the previous use of `OBJECT_INFO_SECOND_READ` for the same scenario. The commit message acknowledges a potential performance trade-off (an extra scan of MIDX-covered packfiles) but considers it acceptable given the rarity of the race.

The diff removes 56 lines across six files, with the core logic now living in `odb/source-files.c`. The change is mechanical and well-justified, aligning with the series' goal of pushing backend-specific logic out of the generic ODB layer.
