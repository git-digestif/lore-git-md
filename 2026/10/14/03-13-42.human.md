This is the seventh patch in Jon Simons' **v2 performance-focused series** to speed up `git push` refspec matching. The patch **reinstates test coverage for refspec ordering** in `send-pack` after a behavioral change in Git 2.46 (commit `9d2962a7c4`) made the original tests ineffective.

The issue: Since Git 2.46, `receive-pack` rejects multiple updates to the same ref with "multiple updates for ref '<dst>' not allowed". This broke the existing test that relied on pushing to the same destination twice to verify ordering. The patch adds two new tests to explicitly check that:
1. Command-line refspecs are sent in the order given (`A:foo B:bar C:baz`).
2. `--stdin` refspecs are sent *after* command-line refspecs, even if they target the same destination.

The tests use a `pre-receive` hook to capture the refs pushed to the remote, then compare them against expected output. This approach avoids relying on the server-side rejection behavior and instead directly verifies the client's ordering logic.

This is a **test-only patch** with no functional changes to Git itself. It ensures the series' later optimizations (e.g., `strmap` lookups in `check_push_refs`) don’t regress the ordering guarantees of `send-pack`. The patch is narrowly scoped and well-motivated, addressing a gap in test coverage that could otherwise mask bugs in refspec processing. No controversies or open questions here—just a necessary housekeeping step for the series.
