This is the fifth and final patch in Harald Nordgren’s five-patch series introducing a matching-inspired fetch mode for shallow repositories. The patch makes `--limited-fetch` the default when adding a remote in a shallow repository, unless `--no-limited-fetch`, `-t/--track`, or `--mirror` is specified.

The change is small and surgical: it adds a single condition in `builtin/remote.c` to check `is_repository_shallow(the_repository)` when `limited_fetch` is unset (`-1`), defaulting to `--limited-fetch` in that case. The documentation in `git-remote.adoc` is updated to explain the new default behavior, and four new tests in `t/t5505-remote.sh` verify that `-t` still sets an explicit refspec, full repositories keep the wildcard refspec, shallow repositories default to `--limited-fetch`, and `--no-limited-fetch` overrides the default.

The patch is uncontroversial and ready for review. It completes the series by addressing the original pain point—shallow clones fetching all remote branches when adding a second remote—without introducing new technical debt or edge cases. The implementation reuses the existing `limited_fetch` logic and configuration machinery, so no new concepts are introduced. The shallow check is the only platform-specific concern, and it uses the existing `is_repository_shallow()` helper. The series as a whole is now a strong candidate for merging to `next`.
