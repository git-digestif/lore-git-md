This is the **eleventh patch in a 12-patch performance series** that speeds up `git push` refspec matching, particularly for large-scale branch deletions. The series targets a long-standing scalability bottleneck where client-side refspec matching degrades to O(n²) behavior when pushing many deletions to servers with large refsets (e.g., 100k refs).

This patch **restructures the loop nesting in `apply_push_cas()`** to prepare for the next commit, which will replace a linear traversal of remote refs with a `strmap` lookup. The current implementation loops over every advertised remote ref and, for each, scans the explicit lease entries until a match is found. The new structure inverts this: it loops over each explicit lease entry and stamps *all* matching remote refs in one pass, then handles the remaining refs with tracking logic. This refactoring is purely preparatory—no behavior changes or performance gains are introduced here—but it is necessary to enable the `strmap`-based optimization in the next patch.

The commit message clearly explains the loop inversion and splits the original `apply_cas()` into two helpers: `apply_one_cas()` (for explicit lease entries) and `apply_cas_tracking()` (for the tracking path).
