This is the second patch in Igor Wiedler’s two-patch series fixing a performance regression in connectivity checks for deepening fetches. It addresses the root cause by teaching `odb_for_each_alternate_ref()` to ignore refs from shallow or grafted alternates, ensuring they are no longer treated as trustworthy boundaries in any connectivity check.

The patch modifies `odb.c` to check for the presence of a `shallow` or `info/grafts` file in each alternate repository before reading its refs. If either file exists, the alternate’s refs are skipped, preventing Git from assuming their history is complete. The change is backward-compatible: existing alternates continue to work, but those with incomplete history are now handled correctly. Documentation in `rev-list-options.adoc` is updated to clarify this behavior, and a new test in `t/t5618-alternate-refs.sh` verifies that shallow alternate refs are ignored.

This patch directly implements Junio Hamano’s design feedback from the v1 series, expanding the fix beyond deepening fetches to all connectivity checks. The commit message is clear about the deferred edge case of partial clones (promisor remotes), which would require reading the alternate’s config and is left for future work. The solution is well-motivated and addresses a real-world issue where shallow or grafted alternates could cause later `git log` failures due to missing history.

Approvals from Patrick Steinhardt and Justin Tobler carried forward for the core regression fix (patch 1), but this patch’s expanded scope has not yet been reviewed. The series as a whole looks like a thoughtful, targeted fix for a CI performance pain point, with a clean separation between the immediate regression fix and the root-cause solution.
