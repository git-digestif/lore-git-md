This is the second patch in a five-part series addressing integer overflows flagged by Coverity. It hardens the HTTP subsystem by fixing a type mismatch in `fwrite_sha1_file()`.

The patch changes the `posn` variable in `http.c` from `int` to `size_t` to match the type of the total size parameter. The current `int` type risks overflow when the HTTP response body exceeds INT_MAX (~2GB), potentially causing a heap under-read and writing adjacent heap contents to the temporary object file. While the hash check would reject the corrupt object, the under-read itself is a defect. The fix is defensive: though the attack surface (a malicious HTTP server delivering >2GB in a single callback) is theoretical under normal curl configurations, the type mismatch is a genuine issue.

The change is minimal—one line in `http.c`—and aligns with the series' goal of eliminating latent integer-overflow risks. The commit message clearly explains the rationale, the potential impact, and the Coverity origin. No tests are included, consistent with the series' pattern, but the fix is straightforward and unlikely to be controversial. The new `size_t` type may see future reuse in similar HTTP-related code paths.
