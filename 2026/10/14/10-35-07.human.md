This is a performance-focused bugfix targeting the connectivity check during shallow fetches. Igor Wiedler identifies a regression in `check_connected()` where deepening fetches (e.g., `git fetch --depth=1`) unnecessarily walk the entire history of alternate object stores, even when the alternate is already trusted. The patch moves the `--alternate-refs` argument to only apply in non-deepening fetches, avoiding a 227-second stall in CI-like setups with large alternates.

The commit message is exemplary: it traces the problem to two prior commits (39b44ba771 and cf1e7c0770), explains why the current behavior is incorrect for deepening fetches, and justifies the fix with a clear technical rationale. The test coverage is minimal but targeted, using `GIT_TRACE2_EVENT` to verify the rev-list arguments rather than asserting behavior (since the outcome is identical for complete alternates).

This looks like a well-motivated, low-risk fix for a real-world pain point. The change is confined to `connected.c` and the test file, with no API or behavioral changes beyond the performance improvement. If you work with shallow clones or CI runners, this patch is likely worth your attention.
