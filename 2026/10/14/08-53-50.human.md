This is the **final patch in a six-part refactoring series** targeting the Git object database (ODB) subsystem. The series, authored by Patrick Steinhardt, focuses on cleaning up and optimizing alternates handling in the "files" backend as part of the broader ODB abstraction effort.

This patch removes the `local` flag from the generic `struct odb_source` and moves it into the packed source (`struct odb_source_packed`), where it is still needed. The flag was originally used to distinguish the primary object directory (".git/objects") from alternates, but since alternates are now handled entirely within the "files" backend, the flag no longer makes sense in the generic ODB API. The change simplifies the internal API by reducing redundancy and tightening the abstraction boundary.

The patch touches **10 files**, primarily in the `odb/` directory, and removes **31 lines** while adding **26**. The diff is mechanical: it updates constructor calls to omit the `local` parameter, moves the flag into `struct odb_source_packed`, and adjusts downstream code to reference the flag from the packed source instead of the generic one. The `ODB_FOR_EACH_OBJECT_LOCAL_ONLY` flag is still handled in the "files" backend, where it skips non-local object directories, so no behavior change is introduced.

Justin Tobler’s **substantive review** of the series raised concerns about the `ODB_FOR_EACH_OBJECT_LOCAL_ONLY` flag being "leaky" (i.e., exposing "files" backend semantics in the generic ODB API), but this patch does not address that issue—it merely relocates the `local` flag to where it is actually used. Patrick has acknowledged the flag’s awkwardness and suggested it could be removed entirely in a future series, but for now, the patch is a straightforward cleanup that aligns with the series’ goal of simplifying the ODB source API.

The patch is **well-motivated and uncontroversial**, with no user-visible changes or on-disk format modifications. It builds on the earlier patches in the series, which optimized alternates handling and consolidated redundant code, and it resolves the last remaining loose end from v1 (the error-handling improvement in patch 5/6).
