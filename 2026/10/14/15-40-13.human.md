This is the first patch in Phillip Wood’s seven-part refactoring series `pw/stash-optimize-check_changes-calls/v2`, which aims to eliminate redundant change-detection logic in `git stash`. The patch introduces an enum (`enum create_result`) to replace the integer return type of `do_create_stash()`, adding a new value `CREATE_EMPTY` to distinguish between "no changes to stash" and actual errors. This is a preparatory step for later patches that will use the enum to avoid unnecessary index operations when no changes are present.

The change also fixes a minor behavioral anomaly: `create_stash()` previously exited with status 1 (indicating no changes) even when `check_changes()`—which doesn’t refresh the index—failed to detect changes reliably. With the enum, the function now correctly returns 0 in such cases. The patch is mechanical and well-scoped, touching only `builtin/stash.c` and maintaining backward compatibility. No user-visible behavior changes are intended beyond the exit-status correction.

Phillip, a seasoned contributor with deep expertise in the stash and sequencer subsystems, addresses feedback from Junio C Hamano’s review of the v1 series. The patch is part of a broader effort to streamline stash internals by reducing redundant index loads and refreshes, with measurable performance gains (fewer `lstat()` calls) and clearer code structure. The series is under active review and, if merged, would likely land in `next`.

This patch sets the stage for the rest of the series, which will build on the enum to consolidate duplicate `check_changes()` calls and eliminate unnecessary index operations. The changes are incremental and focused, making them easy to review and low-risk. For readers tracking the stash subsystem or performance optimizations, this is a solid, uncontroversial step forward.
