This thread is about a bugfix for `--update-refs` in Git’s interactive rebase. The issue, introduced in 2022, caused the wrong branch to be marked as "checked out" in the rebase todo list when multiple worktrees were involved, due to a static buffer in `refs_resolve_ref_unsafe()` being overwritten. Andy Koppe’s single-patch fix replaces the problematic function with `refs_resolve_refdup()` (which allocates a new buffer) and adds proper cleanup to avoid leaks. The patch also corrects an existing test and adds a new one to cover edge cases.

Junio C Hamano reviewed and approved the patch, calling the original logic "obviously broken" and the fix "cleanly corrected." It’s now queued for integration and should appear in the `next` branch soon. Phillip Wood chimed in with a brief, supportive comment, praising the explanation and test coverage, but the patch was already in good shape for merging. No open questions remain, and the fix touches only the sequencer subsystem (`sequencer.c`) and tests.
