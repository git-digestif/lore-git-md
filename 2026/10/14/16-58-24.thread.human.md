This thread is about a bugfix for a subtle ref-name clobbering issue in Git's interactive rebase `--update-refs` logic. Andy Koppe identified that `add_decorations_to_list()` in the sequencer subsystem was using `refs_resolve_ref_unsafe()`, which returns a pointer to a static buffer. When multiple worktrees are in use, checking out a branch in another worktree overwrites this buffer, causing the wrong branch to be marked as "checked out" in the rebase todo list.

The fix is straightforward: replace the unsafe function with `refs_resolve_refdup()`, which allocates a new buffer, and add a corresponding `free()` call to prevent memory leaks. The patch also corrects an existing test that happened to trigger the bug but didn't catch it due to alphabetical ordering of branch names, and adds a new test to ensure the fix works regardless of branch name sorting.

The change is small (11 lines in `sequencer.c` and 21 in the test file) and well-motivated, with a clear commit message that traces the regression back to its origin in 2022. There are no open questions or objections in the thread so far—this appears to be a solid, low-risk fix for a real-world issue that could affect users with multiple worktrees.
