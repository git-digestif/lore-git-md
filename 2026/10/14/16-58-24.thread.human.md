This thread is about a bugfix for Git's interactive rebase `--update-refs` logic, submitted by Andy Koppe. The patch addresses a subtle ref-name clobbering bug in the sequencer subsystem where `refs_resolve_ref_unsafe()`'s static buffer was overwritten when multiple worktrees were involved, causing the wrong branch to be marked as "checked out" in the rebase todo list. The regression was introduced in 2022 but only recently exposed by a test added in 2024.

The fix is straightforward: replacing the unsafe function with `refs_resolve_refdup()` (which allocates a new buffer) and adding a corresponding `free()` call. The patch includes both a corrected test expectation and a new test covering edge cases. Junio C Hamano has reviewed the patch and confirmed he will queue it for integration, calling the original code "obviously broken" and the fix "cleanly corrected." The change is small (11 lines in `sequencer.c`, 21 in the test suite) and well-motivated, with no open questions remaining.

This patch is now effectively ready for the `next` branch and should appear in Junio's next "What's cooking" report. The fix addresses a real-world issue with low risk and good test coverage.
