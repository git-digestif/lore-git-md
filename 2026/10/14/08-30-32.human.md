This is the sixth patch in Patrick Steinhardt’s eight-part CI housekeeping series, now in its third iteration. It updates the `linux-feature-testbed` job to use `ubuntu:latest` instead of the end-of-life `ubuntu:20.04`, eliminating the need to manually track Ubuntu releases. The change also drops the explicit `gcc-8` dependency, letting the job use the system-provided GCC version instead.

The patch is a straightforward two-file edit (`.github/workflows/main.yml` and `.gitlab-ci.yml`), removing four lines and adding two. The motivation is clear: Ubuntu 20.04 is no longer supported, and the `latest` tag ensures the job always uses the most recent LTS release, reducing maintenance overhead. The commit message acknowledges the trade-off—reduced coverage for older GCC versions—but notes that other CI jobs (AlmaLinux 8, Debian 12) still test against older distributions.

This change is uncontroversial and well-justified. The `linux-feature-testbed` job’s purpose is to test non-default Git options (e.g., `OPENSSL_SHA1_UNSAFE`, `GIT_TEST_SPLIT_INDEX`), not to validate specific compiler versions, so the loss of GCC 8 coverage is unlikely to draw objections. The patch is purely mechanical and has already passed CI runs in the linked series. If you’re tracking the CI modernization effort, this is a minor but necessary step forward.
