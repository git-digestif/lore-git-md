This is a **design discussion** about a potential bug in `git pull --rebase` when custom fetch refspecs are used. Junio C Hamano confirms that the FIXME in `get_tracking_branch()` (in `builtin/pull.c`) is real: the code’s assumption that remote-tracking branches always follow the default layout (`refs/remotes/<remote>/<branch>`) breaks when users configure non-standard fetch mappings like `+refs/heads/*:refs/remotes/origin/custom/*`. This could cause `git pull --rebase` to miscompute the fork-point, leading to incorrect rebase results.

The discussion is still conceptual—no patch or test case has been posted yet. Junio’s reply validates the concern but does not propose a fix, leaving open questions about how to resolve the configured fetch mapping dynamically.
