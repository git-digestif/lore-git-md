This is the first patch in Patrick Steinhardt’s v3 CI housekeeping series, a test adjustment targeting `t/t5004-archive-corner-cases.sh`. The patch adds the `SHA1` prerequisite to a test that extracts a ZIP archive containing SHA-1 objects, ensuring the test is skipped in SHA-256 repositories. Without this change, fixing a typo in the Fedora CI job (patch 2/8) would expose a failure when the job switches to SHA-256 by default.

The test in question verifies Git’s ability to handle ZIP archives with objects larger than 4GB, a scenario that requires 64-bit `long` support, unzip with ZIP64 extensions, and the `EXPENSIVE` prerequisite. Currently, only the Fedora CI job meets these requirements, but it has been silently broken due to a typo that disables breaking changes (and thus SHA-256). Once that typo is corrected, the test would fail because the extracted SHA-1 objects are incompatible with a SHA-256 repository. This patch preemptively addresses that issue by restricting the test to SHA-1 environments.

The change is minimal (one line) and well-motivated, aligning with the series’ goal of improving CI reliability without altering user-visible behavior. The commit message clearly explains the context and the dependency on the upcoming typo fix in patch 2/8. For future discussion, expect references to the `SHA1` prerequisite, the Fedora job’s SHA-256 configuration, and the `EXPENSIVE` test prerequisites. This patch is uncontroversial and ready for review.
