Thread identity: performance regression fix in connectivity check for deepening fetches; two-patch series by Igor Wiedler (v3), superseding v2. Thread type: bugfix series addressing both the immediate regression and the underlying design flaw in alternate-ref trust boundaries.

Core problem or goal: eliminate multi-minute delays in shallow fetches by preventing `--alternate-refs` from forcing full history walks of large alternates (e.g., 7M objects). The v3 series implements a two-step fix: patch 1 negates `--alternate-refs` in all connectivity checks (not just deepening fetches), and patch 2 teaches `odb_for_each_alternate_ref()` to ignore refs from shallow or grafted alternates. The undetected edge case of partial clones (promisor remotes) remains explicitly deferred.

Current status: patch v3 posted and code-complete; both patches are test-stable and unblocked. The Windows CI failure in `t/t5618-alternate-refs.sh` (resolved in v3 by replacing `$TRASH_DIRECTORY` with `$(pwd)`) was the only procedural blocker. Approvals from Patrick Steinhardt and Justin Tobler for the core regression fix (patch 1) carry forward. Junio’s design feedback is fully incorporated, and Peff’s review of both patches confirms the fix is technically sound and endorses the two-step design. Junio sent a procedural reminder about mailing-list thread structure (patches should be replies to the cover letter), but this does not affect the series' technical readiness. No design, implementation, or procedural concerns are outstanding; the series is ready for integration. Prior versions (v1, v2) are obsoleted.

Patch 1 adds two tests confirming `--alternate-refs` is negated for both regular and deepening fetches; patch 2 adds a test verifying refs from shallow alternates are excluded. The Windows portability fix ensures the test passes on all platforms.
- Behavior change: alternate refs are now treated as a boundary in all connectivity checks (deepening and non-deepening), and fetch-pack/receive-pack no longer treat shallow alternate refs as valid "have"s. Backward-compatible: existing alternates without `shallow` or `info/grafts` files continue to work as before.
- On-disk format: unchanged.
- Symbols: none renamed or introduced.

- Performance impact: resolves 227s delays in reported CI workflows (shallow fetches from 7M-object alternates).
- Design boundaries: Peff’s review notes that Git generally insists on full connectivity of original objects (e.g., `fsck` ignores replace refs), but the current patch does not address this. Partial clones (promisor remotes) are explicitly deferred as a "weird setup" where detection via alternate config is complex.
