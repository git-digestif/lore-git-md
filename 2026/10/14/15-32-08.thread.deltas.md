# Thread deltas

## 2026/10/14

- [2026/10/14/15-32-08 by Andy Koppe <andy.koppe@gmail.com>] Andy Koppe submitted a patch to refs/files-backend.c that keeps root refs out of the shared loose ref cache, instead reading them into a separate ref cache when an iteration passes REFS_FOR_EACH_INCLUDE_ROOT_REFS and overlaying that iterator on the loose ref iterator; this fixes `git for-each-ref --include-root-refs --merged=main` omitting root refs merged into main because the loose ref cache was populated first by replace ref lookups, and adds a test for '--include-root-refs with --merged' in t/t6302-for-each-ref-filter.sh.

## 2026/10/15

- [2026/10/15/05-58-01 by Patrick Steinhardt <ps@pks.im>] Patrick Steinhardt questioned the proposed fix on two points: why not instead teach the ref cache itself to skip root refs when the caller does not want them, and why the root ref "cache" is recreated for every ref iterator requesting root refs rather than being cached like the loose refs.
- [2026/10/15/17-31-48 by Junio C Hamano <gitster@pobox.com>] Junio C Hamano proposed an alternative design: two caches, a primary one for refs under the refs/ hierarchy and another for those outside it, with callers choosing to use one or both.
- [2026/10/15/19-43-06 by Andy Koppe <andy.koppe@gmail.com>] Andy Koppe answered that not actually caching the root refs makes for a simpler change with less overhead, since REFS_FOR_EACH_INCLUDE_ROOT_REFS is used only twice (builtin/for-each-ref.c for `git for-each-ref --include-root-refs` and builtin/refs.c for `git refs migrate`), each invoking it only once; he had considered keeping root refs in the loose ref cache and skipping them during iteration when the flag is unset, but that would affect the much more common case more, and while dropping the flag so call sites explicitly ask for "refs/" only might be cleaner, it would be a much bigger and riskier change.

## 2026/10/16

- [2026/10/16/07-00-32 by Patrick Steinhardt <ps@pks.im>] Patrick Steinhardt explained his design rationale for not caching root refs: it is a simpler change with less overhead because REFS_FOR_EACH_INCLUDE_ROOT_REFS has only two call sites (builtin/for-each-ref.c for `git for-each-ref --include-root-refs` and builtin/refs.c for `git refs migrate`), each invoked only once; he rejected keeping root refs in the loose ref cache and skipping them during iteration when the flag is unset because that would impact the much more common case; he noted that dropping the flag and making all call sites explicitly ask for "refs/" only would be a much bigger and riskier change; and he agreed the proposed solution is good enough, calling the "cache" naming a historical wart.
