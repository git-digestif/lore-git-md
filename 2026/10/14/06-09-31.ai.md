This is the fifth and final patch in a five-patch series addressing integer overflows flagged by Coverity. It targets the `approxidate` subsystem in `date.c`, where relative-time calculations (e.g., "99999 weeks ago") could overflow an `int` multiplication, producing incorrect dates.

The patch replaces the direct multiplication `tl->length * *num` with a checked multiplication using the new `mult_overflows` macro introduced earlier in the series. On platforms with unsigned `time_t`, it also adds an upfront check to reject counts that exceed `INT_MAX` or the maximum value of `time_t`, preventing truncation or negative values from becoming bogus offsets. The change is defensive: it hardens a user-facing input path against implausibly large values without altering the behavior for normal inputs.

The commit message is clear and specific, naming the function (`approxidate_alpha`), the problematic operation, and the edge case ("99999 weeks ago"). It explains the platform-specific handling (unsigned `time_t`) and the rationale for rejecting oversized counts. The Coverity origin is noted, and the patch follows the pattern of prior Coverity-driven fixes from the same author, which have already been merged to `master`.

No tests are included, consistent with the rest of the series. The patch is small (24 insertions, 2 deletions) and mechanical, touching only the overflow-prone multiplication and the digit-parsing helper. It introduces no new CLI options, config keys, or on-disk format changes. The new logic is guarded by `#ifdef is_unsigned_type`, so it should not affect platforms where `time_t` is signed.
