This is the **third patch in a six-patch refactoring series** targeting the Git object database (ODB) subsystem, specifically the alternates mechanism in the "files" backend. The series is part of Patrick Steinhardt’s broader ODB abstraction effort and follows up on his earlier `ps/odb-files-alternates` branch.

This patch **moves the second-read logic**—previously handled generically in the ODB layer—into the "files" backend, where it belongs. The `OBJECT_INFO_SECOND_READ` flag, which instructed sources to reload on-disk state after an initial lookup failure, is removed entirely. The change is motivated by the fact that alternates are now an implementation detail of the "files" backend, making the generic flag unnecessary. The patch also repurposes `OBJECT_INFO_QUICK` in the "packed" source to handle a race condition with multi-pack indices (MIDX), where a packfile might vanish after the MIDX claims it exists. While this could theoretically trigger an extra scan of MIDX-covered packfiles, Patrick argues the performance impact is negligible and only occurs in rare race scenarios.

The diff touches six files, removing 56 lines and adding 16. The core logic is now confined to `odb/source-files.c`, where a `retry` loop replaces the generic second-read flag. The "loose" source no longer needs to handle `OBJECT_INFO_SECOND_READ`, and the "packed" source’s behavior is simplified. The patch is **mechanical and well-scoped**, with no user-visible behavior changes. Justin Tobler’s review confirmed the design direction, though he noted a minor style concern about the early loop termination in the "files" backend, which Patrick addressed in the commit message.

This patch is **uncontroversial and likely to proceed** to `next`. It aligns with the series’ goal of simplifying the ODB API and prepares the ground for future work on alternates reloading. The only open question—whether the `ODB_FOR_EACH_OBJECT_LOCAL_ONLY` flag should be removed—is deferred to a follow-up series.
