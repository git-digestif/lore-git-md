This is the first patch in Patrick Steinhardt’s six-patch **refactoring and performance series** targeting the object database’s "files" backend. It directly addresses a **performance regression** introduced by earlier ODB abstraction work: when alternates are present, Git now checks loose objects before packfiles, leading to unnecessary `stat()` syscalls. The patch reorders the loops in `odb_source_files_read_object_info()` to prioritize packfile checks across all alternates before falling back to loose objects, restoring the pre-abstraction behavior.

The change is **minimal and focused**: a single file (`odb/source-files.c`) is modified, with the diffstat showing three insertions and two deletions. The commit message provides **clear benchmark data** demonstrating a **1.89x speedup** in object lookup when most objects reside in alternate packfiles, using `git cat-file --batch-check` on the Git repository itself. The motivation is well-documented, referencing both the regression’s origin (the alternates migration) and a specific report from Wolfgang Kritzinger at Atlassian.

This patch is **uncontroversial and well-justified**. The optimization is confined to the "files" backend, avoiding cross-backend complexity, and Justin Tobler’s **substantive, tested review** in the thread confirmed the design and performance claims. No behavior changes or on-disk format modifications are introduced, and the patch relies on existing test coverage. The only open question—whether the `ODB_FOR_EACH_OBJECT_LOCAL_ONLY` flag should be removed—is scoped to a later patch in the series and does not affect this change.

The patch is **ready for `next`** and aligns with the broader ODB abstraction effort led by Patrick. Future work (e.g., alternates reloading) is explicitly accommodated by the loop structure, making this a foundational step for subsequent cleanups.
