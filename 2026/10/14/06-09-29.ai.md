This is the third patch in a five-patch series addressing integer-overflow risks flagged by Coverity. It hardens the `read_in_full()` and `write_in_full()` wrapper functions in `wrapper.c` by rejecting any requested byte count that exceeds `SSIZE_MAX` upfront, returning `EINVAL` instead of silently overflowing the `ssize_t` accumulator. The patch also adds a fallback definition of `SSIZE_MAX` to `git-compat-util.h` for platforms that lack it.

The change is purely defensive: Git never passes such large counts in practice because file sizes and buffer allocations are bounded well below `SSIZE_MAX` on all supported platforms. The fix aligns with POSIX conventions for invalid arguments and eliminates a latent undefined-behavior risk. No behavior change is expected for normal use, and no new test coverage is included. The patch is mechanical and uncontroversial, continuing the pattern of prior Coverity-driven hardening from the same author.
