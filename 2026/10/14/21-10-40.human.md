This is a documentation patch addressing a long-standing usability gap in Git’s explanation of detached HEAD state. Julia Evans has posted a v3 incorporating Junio C Hamano’s requested corrections from v2. The changes are minor but important: the help command in advice messages and documentation now uses `git help detached-head` (hyphenated), the reflog expiry period is clarified to 30 days (the default for `gc.reflogExpireUnreachable`), and whitespace in `command-list.txt` is fixed to maintain column alignment. The co-author, Marie Claire LeBlanc Flanagan, has also provided her sign-off, satisfying Git’s contribution guidelines.

The patch remains a well-motivated, self-contained improvement. It replaces the existing explanation in `git-checkout.adoc` with a concise, practical guide (`gitdetached-head(7)`) that frames detached HEAD as a useful tool for experimentation (e.g., testing commits, browsing history, or working directly on remote-tracking branches) rather than an obscure or accidental state. The new text also highlights the 2019 UI improvement in `git switch` that reduces accidental detachment. While the broader help-system usability concern (internal cross-references vs. `git help`) remains unaddressed, it is not a blocker for this patch.

The files touched are limited to documentation and build system updates: `Documentation/git-checkout.adoc`, `Documentation/detached-head.adoc`, `Documentation/gitdetached-head.txt`, `advice.c`, `Documentation/Makefile`, `meson.build`, and `command-list.txt`. No on-disk format changes or new tests are needed. The patch is now technically complete and should be ready for integration once Junio confirms the corrections. If you care about Git’s usability or have struggled to explain detached HEAD to others, this is worth reviewing.
