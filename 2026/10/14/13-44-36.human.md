This is the first patch in Patrick Steinhardt’s six-part ODB refactoring series, now updated to include a regression test requested by Johannes Schindelin. The patch fixes a performance regression in how Git reads objects when alternates are present: previously, the code checked each alternate’s loose objects before its packfiles, leading to unnecessary `stat()` calls. The fix reorders the loop to scan all packfiles first, which is cheaper because pack indices are likely cached. Benchmarks show a near 2× speedup in affected cases.

The test, authored by Tyrie Vella and already used in Microsoft Git, verifies that objects in alternate packfiles are checked before loose objects in the main repository. It creates an alternate with a deltified object, writes a loose copy in the main repo, and confirms `git cat-file --batch-check="%(deltabase)"` resolves to the packed version. The test is portable and works on both SHA-1 and SHA-256 repositories.

This is a well-motivated bugfix with clear performance benefits and now includes regression protection. The patch itself is narrowly scoped to the "files" backend and does not change user-visible behavior. The series as a whole is part of Patrick’s broader ODB abstraction effort, but this patch stands alone as a straightforward optimization. If you care about large-repository performance or alternates, it’s worth a look.
