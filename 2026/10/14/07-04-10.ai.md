This is the third patch in Harald Nordgren’s five-patch v9 series implementing a matching-inspired fetch mode for shallow repositories. It introduces the core logic that infers which branches to fetch when a remote is configured with `remote.<name>.refmap` but no `remote.<name>.fetch`. The patch dynamically enumerates local branches whose `@{upstream}` points to the remote and constructs a refspec from those branches, avoiding the slow or hanging behavior of wildcard fetches in shallow repositories.

The implementation touches `builtin/fetch.c` (integrating the new logic into `get_ref_map()` and `do_fetch()`), `remote.c`/`remote.h` (adding the `branches_tracking_remote()` helper), and documentation (`config/remote.adoc`, `fetch-options.adoc`). The new test file `t/t5586-fetch-refmap.sh` (119 lines) verifies edge cases: bare fetches with no tracked branches, explicit one-time fetches, duplicate branch tracking, cross-remote tracking, and compatibility with `git remote show`. The patch also reorganizes the `if/else if/else` control flow in `do_fetch()` to handle the new inference logic, a change Junio requested be moved from Patch 2/5 to this patch in v9.

Key technical details include the `branches_tracking_remote()` helper, which iterates over all local branches and collects the source ref for each branch whose `remote_name` matches the target remote, and the integration with `get_ref_map()`, which constructs a dynamic refspec from these branches. The `do_fetch()` function populates `transport_ls_refs_options.ref_prefixes` with the inferred branches to limit the transport layer’s ref requests. The patch preserves backward compatibility: non-shallow repositories continue using wildcard refspecs by default, and the new mode is only enabled when `remote.<name>.refmap` is configured without `remote.<name>.fetch`.
