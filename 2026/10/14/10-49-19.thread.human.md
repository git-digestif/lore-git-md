This thread is about a bugfix patch from Patrick Steinhardt that addresses a subtle off-by-one error in Git's pack-check subsystem. The issue causes `git fsck` to incorrectly flag blobs as corrupt when their size exactly matches `core.bigFileThreshold`. The bug stems from a mismatch between how the streaming path (for large blobs) and the pack-check code handle the threshold comparison—one uses `<` while the other used `<=`, leading to blobs at the threshold being routed to the wrong code path.

The fix is minimal: it changes the comparison in the pack-check code to use `<` instead of `<=`, aligning it with the streaming path's behavior. Patrick provides clear historical context, noting the bug was introduced in 2016 but only became problematic after a 2026 change to stream creation. The patch includes a new test in `t/t1450-fsck.sh` to verify the fix, and while Patrick suggests a more comprehensive solution might be preferable, he acknowledges it could impact performance.

This is a straightforward, low-risk correction to a niche but actionable edge case. No objections or alternative approaches have been raised yet, and the patch appears ready for review.
