This is the **fifth patch in a six-patch refactoring and performance series** targeting the object database (ODB) subsystem, specifically the alternates mechanism in the "files" backend. The patch addresses a **bugfix concern** raised during review of v1: it prevents Git from attempting to re-fetch corrupt objects from promisor remotes, treating such cases as unrecoverable errors instead.

The change modifies `do_oid_object_info_extended()` in `odb.c` to **fail immediately with `ODB_READ_ERROR`** when an object is found but corrupt, rather than proceeding to fetch it from a promisor remote. This aligns with Justin Tobler’s feedback that corruption should not be silently papered over. The patch simplifies the control flow by removing the `corrupt` flag and redundant checks, reducing the function by 12 lines. The logic now only triggers promisor fetches for missing objects (`ODB_READ_NOT_FOUND`), not for corruption (`ODB_READ_ERROR`).

This is a **well-scoped, uncontroversial fix** that resolves a clear edge case. The commit message is concise and cites the reviewer’s suggestion, and the implementation is straightforward. No new tests are introduced, as the change relies on existing ODB test coverage. The patch is part of Patrick Steinhardt’s broader ODB abstraction effort and follows the series’ pattern of internal cleanup without user-visible behavior changes. It is likely to proceed to `next` without further discussion.
