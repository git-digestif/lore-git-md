This is a bugfix patch targeting the pretty-printing subsystem, specifically the `%w()` format specifier in `git log` and related commands.

The patch fixes a regression in `strbuf_add_wrapped_text()` where indentation was lost after a newline followed by whitespace. The bug occurs when the function encounters a hard line break (e.g., `%n` in a format string) and then incorrectly skips the first whitespace character of the next line, causing misaligned output. The commit message provides a clear example: `git log --format="%w(11) This is%n  the %s%n  commit."` previously output " the ..." instead of the expected "  the ...".

The fix itself is small and surgical: it distinguishes between the "line too long" case (where skipping a space is correct) and the "hard line break" case (where skipping is wrong). The patch updates the logic to skip only the second newline in the latter case, preserving indentation. The change touches `utf8.c` and adds a new test in `t/t4205-log.sh` while also updating an existing test in `t/t4205-log-pretty-formats.sh` to account for the corrected behavior.

The commit message is well-structured, explaining both the bug and the fix with concrete examples. The test coverage is appropriate, covering both the specific regression and a related edge case involving `%+d` (which emits a newline followed by decoration text). The patch looks like a straightforward, low-risk fix for a real-world formatting issue. No controversy or follow-up discussion is evident from the patch itself.
