This is a bugfix for `git fast-import` that resolves a crash when referencing commits or tags created earlier in the same session. The patch is now in its third iteration (v3) and addresses all feedback from previous rounds.

The core issue is that `git fast-import` crashes with `fatal: not a valid commit: <oid>` when a `from` command references a commit or tag created in the same session but not yet reachable via the object database (ODB). The fix teaches `parse_from_existing()` to first check fast-import's internal object cache before falling back to the ODB, mirroring the behavior already used by `ls` and `cat-blob` commands. The patch also handles tag dereferencing correctly, ensuring tags pointing to commits are resolved without errors.

The commit message has been significantly improved in this version, now clearly explaining the timing-dependent nature of the crash, the distinction between blob and commit handling, and the role of the in-progress packfile. The test case has also been refined to use `test_oid_cache` and `test_oid`, reducing duplication between SHA-1 and SHA-256 variants while maintaining comprehensive coverage of the fix.

This version appears ready for merging. The changes are minimal, targeted, and well-explained, with thorough test coverage that exercises the fix for both commits and tags (including tag-of-tag scenarios) across both hash algorithms. The patch preserves existing behavior for objects already in the ODB, ensuring no regressions.
