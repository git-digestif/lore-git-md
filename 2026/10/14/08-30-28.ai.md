This is the second patch in Patrick Steinhardt’s v3 CI/build system housekeeping series. It fixes a typo in `ci/run-build-and-tests.sh` that prevented the `fedora-breaking-changes-meson` job from enabling breaking changes (`WITH_BREAKING_CHANGES=YesPlease`). The error—`fedora-breaking-changes-musl` instead of `fedora-breaking-changes-meson`—silently disabled the intended behavior, leaving the job functionally identical to the regular Fedora Meson job.

The change is a one-line substitution in a `case` statement, replacing `musl` with `meson`. This restores the job’s purpose: testing Git with experimental or disruptive changes (e.g., API breaks, new defaults) on Fedora’s Meson build. The fix is preemptively supported by patch 1/8, which adds a `SHA1` prerequisite to `t/t5004-archive-corner-cases.sh` to skip a SHA-1-specific test in SHA-256 repositories—a latent failure that would have surfaced once this job’s `WITH_BREAKING_CHANGES` flag took effect.

The patch is uncontroversial and purely mechanical, addressing a clear oversight without altering CI coverage or behavior. Expect future discussion to reference the restored `WITH_BREAKING_CHANGES` flag or the `fedora-breaking-changes-meson` job name, particularly if other breaking-change tests are added. The typo’s resolution is a prerequisite for any follow-up work relying on this job’s experimental build mode.
