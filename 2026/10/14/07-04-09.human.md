This is the second patch in Harald Nordgren’s five-part v9 series introducing a matching-inspired fetch mode for shallow repositories. The patch extracts the existing logic that checks whether the current branch’s upstream lives on the remote being fetched into a reusable helper, `collect_upstream_from_remote()`, so the same logic can later be applied to *all* local branches that track the remote.

The change is a pure refactoring with no behavioral differences: the extracted logic is identical to what was previously inlined in `do_fetch()`, and the helper is immediately used in the same place. The helper takes a `struct repository *` parameter (eliminating the hardcoded `the_repository` usage that was present in the original code), a `string_list` to populate, a `remote`, and an optional branch name (NULL means the current branch). The NULL-check for `branch` is explicitly restored, addressing Junio’s review concern from v8 that the helper could segfault if called with a non-existent branch. The commit message clearly states the motivation: the current branch’s upstream check is independent of the remote’s configured fetch refspec, and the helper will be reused in Patch 3/5 to implement dynamic branch inference.

The patch touches only three files: `builtin/fetch.c` (replaces the inlined logic with a call to the new helper), `remote.c` (implements the helper), and `remote.h` (declares the helper). The diff is small and mechanical, and the test suite continues to pass. Junio’s only remaining review requirement for the series—re-review of this patch—is now satisfied: the `if/else if/else` control-flow reorganization he objected to in v8 is moved to Patch 3/5, and the NULL-check is restored. The patch is ready for integration and is a strong candidate for `next`.
