This is the third patch in Jon Simons' **v2 performance-focused feature series** (12 patches total) that speeds up client-side refspec matching in `git push`. This patch delivers **55–82% of the total speedup** by eliminating the `mkpath()` overhead in `refname_match()`, replacing it with direct string comparisons via a helper function (`match_parse_rule()`).

The key change is in `refs.c`: `refname_match()` no longer formats each ref_rev_parse_rules entry through `mkpath()` (which used `strbuf_vaddf` and `cleanup_path`), instead using `match_parse_rule()` to perform prefix/suffix comparisons and a `memcmp`. This avoids the O(n²) cost of formatting every rule for every ref, which dominated the client-side cost when pushing many deletions to a server with 100k+ refs. The perf script added in patch 2 shows timings improving from **2.5s to 0.49s** for 100 refspecs on an empty client, and from **6.68s to 1.18s** on a mirror client.

The patch also **changes behavior**: `mkpath()` previously stripped leading `./` from refnames (e.g., `./refs/heads/foo` silently matched `refs/heads/foo`), but this is no longer true. The commit message justifies this as a bugfix, citing historical context (the `cleanup_path()` logic was intended for filepaths, not refnames) and prior work (6cd4a8982d) that removed similar `cleanup_path()` usage elsewhere. New tests in `t5510-fetch.sh` and `t5516-fetch-push.sh` assert that `./`-prefixed refspecs are now rejected, ensuring consistent failure before and after the change.

The diff moves `match_parse_rule()` earlier in `refs.c` to make it available to `refname_match()` and adds 97 lines of test coverage. No on-disk format changes are made. The patch is well-motivated, with clear performance data and historical justification for the behavioral change, but the removal of `./` stripping may require careful review to ensure no workflows inadvertently relied on the old behavior. The series' disciplined test-before-code structure (with failing tests introduced in earlier patches) helps mitigate this risk.
