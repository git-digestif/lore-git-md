This is the final patch in Patrick Steinhardt’s v3 CI housekeeping series, targeting CI/build system improvements. It repurposes the `linux-reftable` job to test reftable with SHA-256 (`GIT_TEST_DEFAULT_HASH=sha256` and `GIT_TEST_DEFAULT_REF_STORAGE_FORMAT=reftable`), addressing a gap in test coverage while preserving foreign-SCM interoperability (CVS, SVN, Perforce) in the renamed `linux-reftable-leaks` job (now `linux-reftable-sha256`). The change is purely mechanical—updating job names in `.github/workflows/main.yml`, `.gitlab-ci.yml`, and `ci/run-build-and-tests.sh`—and has no behavioral impact beyond enabling the new configuration.

The patch resolves Junio C Hamano’s earlier concern about reftable coverage trade-offs by explicitly splitting the two use cases: `linux-reftable` (now `linux-reftable-sha256`) focuses on SHA-256 compatibility, while the existing `linux-reftable-leaks` job continues to test reftable with leak sanitizers and foreign-SCM tools. This approach avoids reducing coverage for either scenario. The commit message justifies the change clearly, noting that the original `linux-reftable` job was redundant with `linux-reftable-leaks` except for its foreign-SCM tests, which the author deemed worth preserving.

Key technical details include the new environment variables (`GIT_TEST_DEFAULT_HASH=sha256` and `GIT_TEST_DEFAULT_REF_STORAGE_FORMAT=reftable`) and the job rename (`linux-reftable` → `linux-reftable-sha256`). The patch touches only CI configuration files and a supporting script, with no changes to core Git functionality. The series’ earlier patches (e.g., the `linux-feature-testbed` rename and Python 2 removal) set the stage for this change, but this patch stands alone as the most technically substantive update in the series.
