This is a **performance test patch** in Jon Simons' ongoing series to speed up `git push` refspec matching for large-scale deletions. It extends the existing `t/perf/p5516-push-delete-refspec.sh` script to measure the overhead of `--force-with-lease` when pushing multiple delete refspecs, establishing a baseline for a later optimization (patch 12/12 in the series).

The patch adds six new performance test cases (`empty:lease:1`, `empty:lease:10`, `empty:lease:100`, `mirror:lease:1`, `mirror:lease:10`, `mirror:lease:100`) that push 1, 10, or 100 delete refspecs *plus* one `--force-with-lease=<refname>:<expect>` per refspec. The test generates refspecs like `:refs/heads/b1` and leases like `--force-with-lease=refs/heads/b1:<oid>`, then measures the time for a dry-run push. The reported baseline timings (e.g., 0.45s for 100 leases on an empty client) will be compared against the optimized version in patch 12, which claims to reduce this to 0.16s.

The change is purely additive: it does not modify any production code, only the perf script. The test setup is clean, using `test_seq` and `sed` to generate input files dynamically, and the commit message clearly states its purpose ("demonstrate a speedup in a subsequent commit"). This is a well-crafted test patch that follows the series' disciplined approach of measuring before optimizing. No substantive issues are apparent.
