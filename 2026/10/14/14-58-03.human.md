This is a bugfix patch targeting the reftable backend, specifically the object record decoder in `reftable/record.c`.

The patch addresses a potential buffer overflow in `reftable_obj_record_decode()`. The issue arises when a 64-bit varint count of offsets is read from the table, but the allocation for the offsets array uses a 32-bit `size_t`. If the count exceeds 2³², the allocation wraps around to a small value, yet the subsequent loop still attempts to write all offsets from the table, leading to out-of-bounds writes. Even on 64-bit systems, an excessively large count could trigger a huge (but technically safe) allocation that the decoder fails to fill properly.

The commit message clarifies that this bug isn’t currently reachable in Git’s normal operation—object blocks are only read by unit tests—but the decoder is still incorrect and could pose a risk if the code path changes. The fix adds a simple bounds check: since each offset takes at least one byte, the count cannot exceed the remaining record length.

The patch also adds the `u-reftable-record` test suite to the Makefile (it was already present in Meson) so the new test runs in both build systems. The test itself constructs a malformed record with a count that would overflow a 32-bit `size_t` and verifies that the decoder returns `REFTABLE_FORMAT_ERROR` instead of proceeding.
