This is a bugfix for the sequencer subsystem, specifically the `--update-refs` logic in interactive rebase. Junio C Hamano has reviewed the patch and explicitly stated he will queue it for integration.

The patch fixes a ref-name clobbering bug in `add_decorations_to_list()` where `refs_resolve_ref_unsafe()`'s static buffer is overwritten when multiple worktrees are involved. This causes the wrong branch to be marked as "checked out" in the rebase todo list. The fix replaces the unsafe function with `refs_resolve_refdup()`, which allocates a new buffer, and adds a corresponding `free()` call. The commit message clearly traces the regression to aa37f3e1d89 (2022) and explains why an existing test (added in 94304b9f48e, 2024) failed to catch the bug due to alphabetical ordering of branch names.

The change is small (11 lines in `sequencer.c`, 21 in the test suite) and well-motivated. The patch corrects the existing test's expectation and adds a new test that covers branches sorting both before and after the current branch, ensuring the fix is robust.
