This is a bugfix for the files ref backend. The patch addresses an inconsistency in how root refs (like `HEAD` or `ORIG_HEAD`) are handled in the loose ref cache. Currently, root refs are only included if `REFS_FOR_EACH_INCLUDE_ROOT_REFS` is passed during the *first* iteration that creates the cache; subsequent iterations include them regardless of the flag, and earlier iterations omit them even if the flag is set. The reftable backend is unaffected.

The fix keeps root refs out of the shared loose ref cache entirely. Instead, when an iteration requests root refs, it creates a separate temporary ref cache for them, overlays its iterator on the loose ref iterator, and frees it when done. The patch updates `files-backend.c` to implement this logic and adds a test in `t/t6302-for-each-ref-filter.sh` to verify that `--include-root-refs` works correctly with `--merged`.

The commit message clearly explains the problem, the affected backend, and the solution. The test case is minimal but sufficient to demonstrate the fix. The change is localized to the refs subsystem and does not touch other backends or user-facing behavior beyond fixing the inconsistency. This looks like a well-scoped, well-motivated bugfix.
