Thread identity: bugfix patch series (single patch) targeting the pack-check subsystem, authored by Patrick Steinhardt.

Core problem or goal: fix an off-by-one error in blob verification logic that causes `git fsck` to incorrectly report corruption when a blob's size exactly matches `core.bigFileThreshold`. The bug arises because the streaming path (for large blobs) refuses to create streams for blobs at or below the threshold, while the pack-check code mistakenly routes blobs *equal* to the threshold to the streaming path.

Current status: patch under review; no prior versions. The fix aligns the threshold comparison with the rest of the codebase by making it exclusive (`<` instead of `<=`). The patch includes a new test in `t/t1450-fsck.sh` to verify the fix.

Key technical details:
- Files touched: `pack-check.c` (logic fix), `t/t1450-fsck.sh` (new test).
- Subsystem: pack-check, blob verification.
- New behavior: blobs sized exactly at `core.bigFileThreshold` are no longer incorrectly flagged as corrupt.
- On-disk format: unchanged.
- Test coverage: new test case in `t/t1450-fsck.sh` for the edge case.
