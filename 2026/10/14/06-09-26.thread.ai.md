Subject: [PATCH 0/5] Coverity-inspired integer-overflow fixes
Series version: v1 (initial)
Originating author: Johannes Schindelin (via GitGitGadget)
Thread type: patch series

Core problem or goal
Eliminate integer overflows and unsafe arithmetic in Git’s codebase flagged by Coverity, hardening several subsystems (archive-tar, http, wrapper, date) against undefined behavior, crashes, or silent corruption when arithmetic exceeds type limits. The fixes are defensive and target latent issues rather than observed bugs.

Current status
Under review; v1 posted. Four prior Coverity-fix branches from the same author were merged to master between July and October 2026.

Key technical details
- New overflow-checking macros in git-compat-util.h: `signed_mult_overflows` and `mult_overflows` (type-generic wrapper for signed/unsigned dispatch)
- Files touched: archive-tar.c, date.c, git-compat-util.h, http.c, wrapper.c
- Subsystems hardened: archive-tar (zero-length input), http (size_t for byte positions), wrapper (implausibly large byte counts), date (approxidate relative-time calculations)
- Specific changes:
  - http.c: `posn` variable in `fwrite_sha1_file()` changed from `int` to `size_t` to match the total size parameter, preventing heap under-read when HTTP response body exceeds INT_MAX (~2 GB)
  - wrapper.c: `read_in_full()` and `write_in_full()` now reject any requested byte count exceeding `SSIZE_MAX` upfront, returning `EINVAL` instead of silently overflowing the `ssize_t` accumulator
  - date.c: `approxidate_alpha()` now uses `mult_overflows` to check `tl->length * *num` for overflow before multiplication; on platforms with unsigned `time_t`, it also rejects counts exceeding `INT_MAX` or the maximum value of `time_t` to prevent truncation or negative offsets
  - git-compat-util.h: added fallback definition of `SSIZE_MAX` for platforms lacking it
- Macros handle full signed-integer range (including two’s-complement negative minimum) and fall back to no-op on compilers without GNU `typeof`
- No on-disk format changes; no new CLI options or config keys
- No test coverage added for the hardened edge cases

Open questions and loose ends
- Absence of test coverage for the hardened edge cases may prompt review requests
- Potential for future reuse of the new macros elsewhere in the codebase
- Theoretical attack surface (malicious HTTP server delivering >2 GB in a single callback) noted but deemed low-risk under normal curl configurations
