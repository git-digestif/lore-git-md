Key technical details: Files touched: `archive-tar.c`, `date.c`, `http.c`, `wrapper.c`, `wrapper.h`, plus callers `builtin/blame.c`, `combine-diff.c`, `dir.c`, `grep.c`, `imap-send.c`, `notes-merge.c`, `refs/packed-backend.c`, `strbuf.c`, `config.c`, `entry.c`, `odb/streaming.c`, `parallel-checkout.c`, and `t/unit-tests/u-reftable-stack.c` updated for wrapper API changes. `archive-tar.c` (patch v3 1/5): `get_path_prefix()` now returns 0 when the computed index `i` is zero before the `do...while` loop decrements it, preventing a `size_t` wrap to `SIZE_MAX` and subsequent out-of-bounds read; the sole caller `write_tar_entry()` currently always passes `pathlen` of at least 100 so the bug is latent, and no tests are added in this patch. `http.c` (patch v3 2/5): `posn` in `fwrite_sha1_file()` changed from `int` to `size_t`; v3 incorporates Junio's rewritten commit-message explanation that `posn` resets to zero on every curl callback invocation so overflow can only occur if a single call passes more than `INT_MAX` bytes. `wrapper.c` write path (patch v3 3/5): `write_in_full()` return type changed from `ssize_t` to `int` (0 on success, -1 with `errno` set on failure), eliminating the accumulator variable that could overflow when summing bytes for large `size_t` inputs; `write_str_in_full()` in `wrapper.h` updated to match the new signature. Callers adjusted: `config.c` changes `write_section()` and `write_pair()` to return `int` and store results in `int` locals; `entry.c` and `parallel-checkout.c` change `ssize_t wrote` to `int wrote`; `odb/streaming.c` removes the now-unneeded `wrote` variable and tests the return directly; `imap-send.c` maps success to the requested length (`n = write_in_full(...) < 0 ? -1 : len`) to preserve its existing error-checking logic; `notes-merge.c` simplifies its write loop to a single call that dies on error unless `errno` is `EPIPE`; and `t/unit-tests/u-reftable-stack.c` updates its assertion to expect 0 instead of the byte count. Phillip Wood's review of patch 3 identified that `refs.c:transaction_hook_feed_stdin()`, `sequencer.c:pipe_from_strbuf()`, and `transport.c:pre_push_hook_feed_stdin()` previously stored the `ssize_t` return in an `int` and tested `if (result < 0)`, so the old accumulation semantics could have produced false negatives or overflow artifacts in these hook-feeding paths, meaning the patch fixes latent bugs there rather than merely changing types. In v3, Johannes additionally adjusted remaining `ssize_t` local variables in `config.c`, `entry.c`, `odb/streaming.c`, and `parallel-checkout.c` to `int` where they now store the `int` return from `write_in_full()`. `wrapper.c` read path (patch v3 4/5): new `read_in_full_or_error()` returns `int` (0 on success, -1 with `errno` set on failure) for callers that only need a success/failure signal; both `read_in_full_or_error()` and `read_in_full()` share a static helper `read_in_full_1()`; `read_in_full()` adds a `BUG()` guard that aborts if the requested `count` exceeds `ssize_t` max, treating oversized requests as programming errors. Call sites `builtin/blame.c`, `combine-diff.c`, `dir.c`, `grep.c`, `refs/packed-backend.c`, and `strbuf.c` migrated to `read_in_full_or_error()` where they previously compared return value to requested size; `strbuf.c` clamps `want` to `SSIZE_MAX` before calling `read_in_full()`. The remaining `read_in_full()` callers after the series (`setup.c`, `object-file.c`, `http-backend.c`, `pkt-line.c`, `odb/streaming.c`) were confirmed by Junio to be safely bounded. `date.c` (patch v3 5/5): `approxidate_alpha()` performs unit-length multiplication in `uintmax_t` using `unsigned_mult_overflows()` and checks the result against `time_t` range via `date_overflows()`, returning `NULL` on overflow; `approxidate_digit()` rejects parsed numbers greater than `INT_MAX` before narrowing to `int`; `approxidate_str()` propagates `NULL` returns by setting `*error_ret` and returning zero so callers like `git reflog expire` report "invalid timestamp". Test coverage: new clar unit-test file `t/unit-tests/u-wrapper.c` covering successful writes, empty writes, error cases with bad file descriptors, and for patch 4 successful reads, empty reads, short reads (premature EOF mapping to `EIO`), and bad file descriptors for `read_in_full_or_error()`, plus corresponding tests for `read_in_full()` verifying it returns the short count on premature EOF, handles empty reads, and returns -1 on error; registered in `Makefile` and `t/meson.build`; new cases in `t/t0006-date.sh` verifying "4000 weeks ago" parses correctly on 64-bit `time_t` platforms and "18446744073709551615 seconds ago" is rejected with failure exit. No on-disk format changes; no new CLI options or config keys.
