Thread identity: Subject "[PATCH v2 0/5] Coverity-inspired integer-overflow fixes", series version v2, originating author Johannes Schindelin (via GitGitGadget), thread type patch series.

Core problem or goal: Eliminate integer overflows and unsafe arithmetic flagged by Coverity in archive-tar, HTTP fetch (`http.c`), wrapper I/O (`wrapper.c`/`wrapper.h`), and date parsing (`date.c`), hardening against undefined behavior, crashes, or silent corruption when arithmetic exceeds type limits.

Current status: Under review; v2 posted with patches 1 and 2 unchanged from v1 and patches 3 through 5 substantially revised. Junio C Hamano now explicitly approves the v2 direction as "a clear improvement over v1", praising the removal of the ad-hoc `signed_mult_overflows()`/`mult_overflows()` macros and the separation of `read_in_full_or_error()` from `read_in_full()` as making the wrapper APIs cleaner and easier to verify, and signals maintainer approval of the series' overall approach. Patch 1 (`archive-tar.c`) is explicitly approved by Junio C Hamano with "Looks good to me" after he verified the `if (!i) return 0;` guard covers both zero `pathlen` and zero `maxlen` without affecting `pathlen == 1` (e.g. "/") or longer paths; he also corrected the commit message off-by-one: because `struct ustar_header.name` is 100 bytes, `pathlen > sizeof(header.name)` means `pathlen` is at least 101, not 100, though he agrees the bug remains unreachable in practice because the sole caller `write_tar_entry()` always passes `pathlen` of at least 100. Patch 2 (`http.c`) is now explicitly approved by Junio C Hamano with "Looking good" after he confirmed the one-line change switching `posn` in `fwrite_sha1_file()` from `int` to `size_t` is correct, noting that `xwrite()` clamps per-call I/O to `MAX_IO_SIZE` and the `posn/eltsize` division avoids signed-to-unsigned promotion issues; the patch is unchanged from v1. Patch 3 (`wrapper.c` write path) eliminates overflow risk by changing `write_in_full()`/`write_str_in_full()` to return `int`. Patch 4 (`wrapper.c` read path) adds `read_in_full_or_error()` returning `int`, refactors `read_in_full()` to use a shared `read_in_full_1()` helper, and triggers `BUG()` when requested `count` exceeds `SSIZE_MAX`; six call sites were migrated to the new helper and `strbuf.c` clamps `want` to `SSIZE_MAX`. Patch 5 (`date.c`) uses `unsigned_mult_overflows()` and `date_overflows()` in `uintmax_t` to guard unit-length multiplication and `time_t` range checks, and rejects parsed numbers exceeding `INT_MAX`; Phillip Wood has approved patch 5, stating the revised version "looks good and is much simpler than the previous version", leaving no outstanding technical objections on that patch. Junio's latest "What's cooking" report marks the series as "Waiting for response" and warns of expiration from integration branches if no further activity occurs. Junio's newest review of patch 4 characterizes the remaining feedback as minor nits rather than fundamental objections, but the series is still waiting for a response on those commit-message corrections.

Key technical details: Files touched: `archive-tar.c`, `date.c`, `http.c`, `wrapper.c`, `wrapper.h`, plus callers `builtin/blame.c`, `combine-diff.c`, `dir.c`, `grep.c`, `imap-send.c`, `notes-merge.c`, `refs/packed-backend.c`, `strbuf.c`, and `t/unit-tests/u-reftable-stack.c` updated for wrapper API changes. `archive-tar.c`: `get_path_prefix()` now returns 0 when the computed index `i` is zero before the `do...while` loop decrements it, preventing a `size_t` wrap to `SIZE_MAX` and subsequent out-of-bounds read; the sole caller `write_tar_entry()` currently always passes `pathlen` of at least 100 so the bug is latent, and no tests are added in this patch. `http.c`: `posn` in `fwrite_sha1_file()` changed from `int` to `size_t`; discussion resolved in favor of `size_t` over `off_t` because `posn` offsets into a contiguous in-core buffer sized in `size_t`; Junio clarified that `posn` is reset to zero on every curl callback invocation so overflow can only occur if a single call passes more than `INT_MAX` bytes (`size = eltsize * nmemb`). `wrapper.c` write path: `write_in_full()` return type changed from `ssize_t` to `int` (0 on success, -1 with `errno` set on failure); `write_str_in_full()` in `wrapper.h` updated to match; `imap-send.c` maps success to requested length, `notes-merge.c` simplifies its loop, and `t/unit-tests/u-reftable-stack.c` adjusts an assertion. Phillip Wood's review of patch 3 confirms the approach and identifies that `refs.c:transaction_hook_feed_stdin()`, `sequencer.c:pipe_from_strbuf()`, and `transport.c:pre_push_hook_feed_stdin()` previously stored the `ssize_t` return in an `int` and tested `if (result < 0)`, so the old accumulation semantics could have produced false negatives or overflow artifacts in these hook-feeding paths, meaning the patch fixes latent bugs there rather than merely changing types; he also notes cleanup opportunities where `config.c`'s `write_section()`/`write_pair()` propagate the return value and could return `int`, and where `entry.c:write_entry()`, `parallel-checkout.c:write_pc_item_to_fd()`, and `odb/streaming.c:odb_stream_blob_to_fd()` still store the result in `ssize_t` variables despite the `int` return. `wrapper.c` read path: new `read_in_full_or_error()` returns 0 or -1; `read_in_full()` calls shared static `read_in_full_1()` and `BUG()`s if `count` exceeds `ssize_t` max; call sites `builtin/blame.c`, `combine-diff.c`, `dir.c`, `grep.c`, `refs/packed-backend.c`, and `strbuf.c` migrated to `read_in_full_or_error()` where they previously compared return value to requested size; `strbuf.c` clamps `want` to `SSIZE_MAX` before calling `read_in_full()`. Junio additionally notes that `worktree.c:should_prune_worktree()` passes a `size_t len` derived from `xsize_t(st.st_size)` to `read_in_full()` and suggests migrating it to `read_in_full_or_error()` for consistency with other `st.st_size` conversions. He also notes that `read_in_full_1()` currently has only two callers, both passing non-NULL `&total`, so its conditional `if (out)` check is unnecessary and the byte count should be reported unconditionally. The remaining `read_in_full()` callers after the series (`setup.c`, `object-file.c`, `http-backend.c`, `pkt-line.c`, `odb/streaming.c`) were confirmed by Junio to be safely bounded. `date.c`: `approxidate_alpha()` performs unit-length multiplication in `uintmax_t` using `unsigned_mult_overflows()` and checks the result against `time_t` range via `date_overflows()`, returning `NULL` on overflow; `approxidate_digit()` rejects parsed numbers greater than `INT_MAX` before narrowing to `int`; `approxidate_str()` propagates `NULL` returns by setting `*error_ret` and returning zero so callers like `git reflog expire` report "invalid timestamp". Test coverage: new clar unit-test file `t/unit-tests/u-wrapper.c` covering successful/empty/error writes and reads, short reads, and bad file descriptors, registered in `Makefile` and `t/meson.build`; new cases in `t/t0006-date.sh` verifying "4000 weeks ago" parses correctly on 64-bit `time_t` platforms and "18446744073709551615 seconds ago" is rejected with failure exit. No on-disk format changes; no new CLI options or config keys.
