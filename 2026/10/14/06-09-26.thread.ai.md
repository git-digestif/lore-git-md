Thread identity: Subject "[PATCH v2 0/5] Coverity-inspired integer-overflow fixes", series version v2, originating author Johannes Schindelin (via GitGitGadget), thread type patch series.

Core problem or goal: Eliminate integer overflows and unsafe arithmetic flagged by Coverity in archive-tar, HTTP fetch (http.c), wrapper I/O (wrapper.c/wrapper.h), and date parsing (date.c), hardening against undefined behavior, crashes, or silent corruption when arithmetic exceeds type limits.

Current status: Under review; v2 posted with patches 1 and 2 unchanged from v1 and patches 3 through 5 substantially revised. Patches 1 (archive-tar.c) and 2 (http.c) remain uncontroversial and ready for integration. Patch 3 (wrapper.c write path) eliminates overflow risk by changing `write_in_full()`/`write_str_in_full()` to return `int`. Patch 4 (wrapper.c read path) adds `read_in_full_or_error()` returning `int`, refactors `read_in_full()` to use a shared `read_in_full_1()` helper, and triggers `BUG()` when requested `count` exceeds `SSIZE_MAX`; six call sites were migrated to the new helper and `strbuf.c` clamps `want` to `SSIZE_MAX`. Patch 5 (date.c) uses `unsigned_mult_overflows()` and `date_overflows()` in `uintmax_t` to guard unit-length multiplication and `time_t` range checks, and rejects parsed numbers exceeding `INT_MAX`. Junio's latest "What's cooking" report marks the series as "Waiting for response" and warns of expiration from integration branches if no further activity occurs.

Key technical details: Files touched: archive-tar.c, date.c, http.c, wrapper.c, wrapper.h, plus callers builtin/blame.c, combine-diff.c, dir.c, grep.c, imap-send.c, notes-merge.c, refs/packed-backend.c, strbuf.c, and t/unit-tests/u-reftable-stack.c updated for wrapper API changes. archive-tar.c: `get_path_prefix()` now returns 0 when the computed index `i` is zero before the `do...while` loop decrements it, preventing a `size_t` wrap to `SIZE_MAX` and subsequent out-of-bounds read; the sole caller `write_tar_entry()` currently always passes `pathlen` of at least 100 so the bug is latent, and no tests are added in this patch. http.c: `posn` in `fwrite_sha1_file()` changed from `int` to `size_t`; discussion resolved in favor of `size_t` over `off_t` because `posn` offsets into a contiguous in-core buffer sized in `size_t`. wrapper.c write path: `write_in_full()` return type changed from `ssize_t` to `int` (0 on success, -1 with `errno` set on failure); `write_str_in_full()` in wrapper.h updated to match; `imap-send.c` maps success to requested length, `notes-merge.c` simplifies its loop, and t/unit-tests/u-reftable-stack.c adjusts an assertion. wrapper.c read path: new `read_in_full_or_error()` returns 0 or -1; `read_in_full()` calls shared static `read_in_full_1()` and `BUG()`s if `count` exceeds `ssize_t` max; call sites builtin/blame.c, combine-diff.c, dir.c, grep.c, refs/packed-backend.c, and strbuf.c migrated to `read_in_full_or_error()` where they previously compared return value to requested size; strbuf.c clamps `want` to `SSIZE_MAX` before calling `read_in_full()`. date.c: `approxidate_alpha()` performs unit-length multiplication in `uintmax_t` using `unsigned_mult_overflows()` and checks the result against `time_t` range via `date_overflows()`, returning `NULL` on overflow; `approxidate_digit()` rejects parsed numbers greater than `INT_MAX` before narrowing to `int`; `approxidate_str()` propagates `NULL` returns by setting `*error_ret` and returning zero so callers like `git reflog expire` report "invalid timestamp". Test coverage: new clar unit-test file t/unit-tests/u-wrapper.c covering successful/empty/error writes and reads, short reads, and bad file descriptors, registered in Makefile and t/meson.build; new cases in t/t0006-date.sh verifying "4000 weeks ago" parses correctly on 64-bit `time_t` platforms and "18446744073709551615 seconds ago" is rejected with failure exit. No on-disk format changes; no new CLI options or config keys.
