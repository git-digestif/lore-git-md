This is the eighth patch in Jon Simons' **v2 performance series** that speeds up `git push` refspec matching for large-scale branch deletions. This patch fixes a **long-standing correctness bug** in how `git push` handles duplicate destinations when the remote repository is empty.

The bug stems from `match_explicit_refs()` passing the remote ref list head (`dst`) by value rather than by pointer. When the remote is empty, `dst` is `NULL`, and each refspec iteration starts from scratch, failing to detect destinations created by earlier refspecs. The fix changes the function signature to pass `dst` by pointer, ensuring later iterations see destinations linked by earlier ones. This aligns client-side behavior with server-side enforcement (added in 2025's `9d2962a7c4`), which already rejects duplicate updates.

The patch updates two test scripts:
- `t5408-send-pack-stdin.sh`: Corrects test expectations to match the new client-side error message (`"dst ref refs/heads/foo receives from more than one src"`) and fixes a missing `2>err` redirection. The commit message clarifies that these tests were not previously asserting anything about ref update ordering.
- `t5516-fetch-push.sh`: Adds six new tests covering edge cases like `--dry-run`, empty remotes, and mixed abbreviated/full refspecs (e.g., `main:frotz` vs. `main:refs/heads/frotz`).

The change is minimal (6 lines in `remote.c`) and well-motivated, addressing a 20-year-old bug (dating to `f88395ac23` in 2005). The test coverage is thorough, though the updated error message in `t5408` might require downstream adjustments if tools parse it. This patch is a **clear correctness win** and a necessary step toward the series' broader performance goals. Awaiting substantive review, but the fix looks solid.
