This thread is about a performance regression in Git’s connectivity checks during deepening fetches, where `--alternate-refs` forces a full history walk of large alternate repositories (e.g., 7M objects), causing multi-minute delays (227s in reported cases). Igor Wiedler posted a one-line patch to fix the regression by excluding `--alternate-refs` from deepening fetches, aligning behavior with the existing `--all` logic.

The patch has been **approved by Patrick Steinhardt and Justin Tobler**, both of whom confirmed its correctness and the adequacy of its tests (which use `GIT_TRACE2_EVENT` to verify `rev-list` arguments). However, **Junio C Hamano raised a design concern**: while the patch fixes the deepening regression, the same trust-model flaw (ignoring shallow boundaries in alternate refs) persists in non-deepening fetches. Junio proposed a two-step fix—merge the current patch to address the immediate regression, then extend `odb_for_each_alternate_ref()` to ignore shallow repositories entirely—but no code or tests for the second step exist yet.

The thread’s key open question is whether to accept the targeted regression fix now or insist on a broader solution before merging. The patch touches `connected.c` and adds tests in `t/t5618-alternate-refs.sh`, with no on-disk format changes or new symbols. The regression was introduced by earlier commits (39b44ba771 and cf1e7c0770), and the broader issue may require follow-up work if the current patch is merged. For now, the patch remains under review, with no merge intent stated.
