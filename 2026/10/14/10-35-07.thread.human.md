This thread is about a performance regression in Git’s connectivity check for deepening (shallow) fetches. The issue, reported and fixed by Igor Wiedler, occurs when `--alternate-refs` forces Git to walk the full history of large alternate repositories—turning an instant check into a multi-minute operation. The fix is a one-line change in `connected.c` that moves `--alternate-refs` into the non-deepening branch of `check_connected()`, mirroring the existing `--all` logic. Two new tests in `t/t5618-alternate-refs.sh` verify the behavior using `GIT_TRACE2_EVENT` to confirm `rev-list` arguments.

Patrick Steinhardt has reviewed and approved the patch, calling it a "well-motivated" solution that addresses a real-world pain point in CI environments. The commit message provides clear historical context, noting the regression was introduced by earlier commits (39b44ba771 and cf1e7c0770). The patch is self-contained, includes tests, and preserves existing behavior for non-deepening fetches.
