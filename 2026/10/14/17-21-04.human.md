This is a bugfix patch for the pack-check subsystem, now queued for integration after Junio C Hamano's review.

The patch corrects an off-by-one error in blob verification logic that caused `git fsck` to incorrectly flag blobs as corrupt when their size exactly matched `core.bigFileThreshold`. The fix aligns the threshold comparison with the rest of Git's codebase by changing `<=` to `<`, ensuring blobs sized at the threshold are handled by the in-memory path rather than the streaming path. The commit message provides clear historical context: the bug was introduced in 2016 but only became problematic after a 2026 change to stream creation logic.

Junio's review confirms the fix is correct and consistent with Git's policy of using the streaming interface only for objects *larger* than the threshold. The patch includes a new test in `t/t1450-fsck.sh` that verifies `git fsck` succeeds when a blob's size equals the threshold, adding coverage for this edge case.

This is a minimal, well-motivated correction to a subtle bug that could cause false corruption reports. The fix is low-risk, touches only the pack-check logic and test suite, and leaves the on-disk format unchanged.
