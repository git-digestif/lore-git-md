This is the v9 cover letter for Harald Nordgren’s five-patch series implementing a matching-inspired fetch mode for shallow repositories. The series introduces `remote.<name>.refmap` to separate namespace mapping from fetch selection, dynamically infers branches to fetch from local tracking branches when no explicit refspec is given, and adds `--limited-fetch` to `git remote add` (defaulting it for shallow repositories).

The v9 respin addresses Junio’s two review points from v8: (1) the `if/else if/else` control-flow reorganization in `do_fetch()` is now moved from Patch 2/5 (the helper-extraction commit) to Patch 3/5 (the feature patch), and (2) the NULL-check for `branch` in `collect_upstream_from_remote()` is restored, eliminating the segfault risk. Patch 2/5 is now a pure refactoring with no behavioral changes. The regression where the current branch’s `@{upstream}` could be dropped is fixed, and the hardcoded `the_repository` usage is eliminated by threading a `struct repository *` parameter through callback data. All other review concerns from prior versions remain resolved, including the precedence rule (`.fetch` takes precedence over `.refmap` when both are configured) and the textual conflict with Collin’s `ch/fetch-followremotehead-lazy-validation` topic in `seen`.

The series touches `remote.c`/`remote.h` (refmap parsing, dynamic branch enumeration), `builtin/fetch.c` (integration with `get_ref_map()` and `do_fetch()`), `builtin/remote.c` (`--limited-fetch` flag and shallow-repository default), and documentation (`git-fetch.adoc`, `git-remote.adoc`, `config/remote.adoc`). Test coverage spans `t/t5510-fetch.sh` (refmap behavior), `t/t5586-fetch-refmap.sh` (dynamic inference edge cases), and `t/t5505-remote.sh` (`--limited-fetch` and shallow defaults). The implementation is technically sound, with no on-disk format changes beyond new configuration entries. Edge cases—such as bare fetches against refmap-only remotes with no tracked branches—are documented and tested.

The design is consensus-driven: `remote.<name>.refmap` reuses Git’s existing `--refmap` mechanism, and the precedence rule resolves the fatal error from earlier versions. The `--limited-fetch` flag and shallow-repository default are uncontroversial and ready for review. Junio’s re-review of Patch 2/5 is the only remaining blocker before the series can graduate to `next`. The series is a strong candidate for merging, addressing a real performance pain point for shallow-repository users without breaking backward compatibility.
