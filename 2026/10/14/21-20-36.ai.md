This is the **final patch (5/5)** in a **bugfix series** for `git worktree repair`, addressing a correctness issue where the command could incorrectly modify `.git` files or gitdirs belonging to unrelated worktrees. The patch adds validation logic to ensure the worktree ID recorded in the `.git` file matches the worktree being repaired and that the gitdir path can be inferred before proceeding with repairs.

The patch introduces two key safeguards:
1. **Worktree ID validation**: `repair_gitfile()` now checks whether the worktree ID extracted from the `.git` file matches the expected `wt->id`. If not, it aborts with an "unrelated .git file" error, preventing accidental corruption of unrelated worktrees (e.g., when worktree directories are manually swapped).
2. **Gitdir inference check**: `repair_worktree_at_path()` now fails early if the inferred gitdir path is empty, avoiding repairs that could overwrite unrelated gitdirs (e.g., when a linked worktree is copied to a new location).

The test suite (`t/t2406-worktree-repair.sh`) is expanded to cover these cases, including scenarios where:
- A `.git` file belongs to a different worktree (skipped with "unrelated .git file").
- A `.git` file does not reference a linked worktree (skipped with "not for a linked worktree").
- The gitdir path cannot be inferred (skipped with "unable to locate repository").

The patch also includes a minor refactoring of `get_worktree_id()` to improve robustness by validating the `/worktrees` prefix before extracting the ID. This helper, introduced in an earlier patch, is reused here to avoid code duplication.
