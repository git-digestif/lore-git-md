This is the seventh patch in the v2 series optimizing `git push` refspec matching for large-scale deletions. It adds test coverage for **refspec ordering guarantees** in `send-pack`, ensuring command-line refspecs are sent before `--stdin` refspecs and in the order specified.

The patch addresses a gap created by a 2025 server-side change (`9d2962a7c4`) that now rejects multiple updates to the same ref, breaking existing tests that relied on this behavior to assert ordering. The new tests use a `pre-receive` hook to capture the actual refs pushed, verifying:
1. Command-line refspecs are sent in the order given (`A:foo B:bar C:baz` → `foo`, `bar`, `baz`).
2. `--stdin` refspecs follow command-line refspecs, even if they target the same destination (`B:foo` before `A:bar`).

The tests are narrowly scoped to ordering and do not interact with the performance optimizations in the rest of the series. They are a correctness fix for a behavioral regression introduced by unrelated work.
