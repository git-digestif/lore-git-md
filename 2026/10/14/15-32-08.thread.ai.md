Subject: [PATCH v2] files-backend: fix loose ref cache inconsistency with root refs
Series version: v2 (v1 previously posted; this is the updated iteration)
Originating author: Andy Koppe
Thread type: bugfix

Core problem or goal
The files ref backend has an inconsistency in how root refs (e.g., `HEAD`, `ORIG_HEAD`) are handled in the loose ref cache. Root refs are included in the cache only if the `REFS_FOR_EACH_INCLUDE_ROOT_REFS` flag is passed during the *first* iteration that creates the cache; subsequent iterations include them regardless of the flag, and earlier iterations omit them even if the flag is set. The goal is to eliminate this inconsistency by ensuring root refs are handled predictably, either by excluding them from the shared loose ref cache entirely or by teaching the cache to respect the flag consistently.

Current status
Under review; v2 posted. The patch remains a well-scoped bugfix targeting `files-backend.c`, verified by a new test in `t/t6302-for-each-ref-filter.sh`. The v2 iteration incorporates documentation corrections and minor code organization tweaks but does not alter the core architectural approach (temporary root ref cache). Patrick Steinhardt’s initial performance and design concerns have been resolved by Andy Koppe’s explanation, leaving the patch technically unblocked. The discussion now centers on two architectural approaches: (1) Andy’s solution (temporary cache for root refs on demand), now implemented in v2, and (2) Junio C Hamano’s proposed alternative (persistent dual caches for `refs/` hierarchy and root refs). Andy’s third option—dropping the `REFS_FOR_EACH_INCLUDE_ROOT_REFS` flag entirely—remains a conceptual possibility but has not been implemented or pursued further.

Key technical details
- Files touched: `files-backend.c`, `t/t6302-for-each-ref-filter.sh`, documentation files (`Documentation/git-for-each-ref.txt`, `refs.h` comments)
- Subsystem: refs (files backend only; reftable backend unaffected)
- New behavior (v2): root refs are excluded from the shared loose ref cache; a temporary ref cache is created and overlaid on the loose ref iterator when `REFS_FOR_EACH_INCLUDE_ROOT_REFS` is passed. The implementation is unchanged from v1, but documentation and code organization have been corrected.
- New behavior (Junio’s alternative): two persistent caches (one for `refs/` hierarchy, one for root refs) would be maintained; callers combine them explicitly to include root refs. Not implemented in v2.
- Test coverage: new test case in `t/t6302-for-each-ref-filter.sh` verifies `--include-root-refs` with `--merged`; coverage remains minimal but sufficient.
- On-disk format: unchanged
- CLI options: `--include-root-refs` (existing) now behaves consistently; documentation corrected to clarify that root refs are not pseudorefs.
- Performance considerations: overhead of the temporary cache is negligible since the flag is used in only two places, both invoking it just once per command. Junio’s alternative avoids recreating the root ref cache for every iterator but has not been implemented or benchmarked.

Open questions and loose ends
- Which architectural approach will be adopted: the temporary cache (implemented in v2) or Junio’s persistent dual-cache design.
- If Junio’s alternative is chosen, whether the implementation will reuse existing cache infrastructure or introduce new mechanisms.
- Whether the chosen solution will require additional test coverage beyond the existing `--include-root-refs`/`--merged` test.
