Subject: [PATCH] files-backend: fix loose ref cache inconsistency with root refs
Series version: standalone patch
Originating author: Andy Koppe
Thread type: bugfix

Core problem or goal
The files ref backend has an inconsistency in how root refs (e.g., `HEAD`, `ORIG_HEAD`) are handled in the loose ref cache. Root refs are included in the cache only if the `REFS_FOR_EACH_INCLUDE_ROOT_REFS` flag is passed during the *first* iteration that creates the cache; subsequent iterations include them regardless of the flag, and earlier iterations omit them even if the flag is set. The reftable backend is unaffected. The goal is to eliminate this inconsistency by keeping root refs out of the shared loose ref cache entirely and instead creating a separate temporary ref cache for them when requested.

Current status
Under review; no prior versions. The patch is a well-scoped bugfix that updates `files-backend.c` and adds a test in `t/t6302-for-each-ref-filter.sh` to verify `--include-root-refs` works correctly with `--merged`. Patrick Steinhardt has raised design questions about whether the proposed solution is the most efficient or conceptually cleanest approach, but no alternative implementation has been proposed yet.

Key technical details
- Files touched: `files-backend.c`, `t/t6302-for-each-ref-filter.sh`
- Subsystem: refs (files backend only)
- New behavior: root refs are no longer stored in the shared loose ref cache; instead, a temporary ref cache is created and overlaid on the loose ref iterator when `REFS_FOR_EACH_INCLUDE_ROOT_REFS` is passed
- Test coverage: new test case in `t/t6302-for-each-ref-filter.sh` verifies `--include-root-refs` with `--merged`
- On-disk format: unchanged
- CLI options: `--include-root-refs` (existing) now behaves consistently
- Performance considerations: Patrick Steinhardt notes the current implementation recreates the root ref cache for every iterator that requests root refs, rather than caching it persistently like the loose ref cache

Open questions and loose ends
- Whether the fix should teach the existing loose ref cache to conditionally skip root refs when `REFS_FOR_EACH_INCLUDE_ROOT_REFS` is not set, instead of creating a separate temporary ref cache.
- Whether the root ref cache should be cached persistently (like the loose ref cache) rather than recreated for every iterator that requests root refs.

Participant positions
- Andy Koppe (author): identified the bug, proposed the fix, and provided a minimal test case. The solution is localized and does not affect other backends or user-facing behavior beyond fixing the inconsistency.
- Patrick Steinhardt: raised two technical questions about the design of the fix, probing whether the proposed solution is the most efficient or conceptually cleanest approach. No outright rejection of the current approach, but suggests the design may still be open to refinement.
