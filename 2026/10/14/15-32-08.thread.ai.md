Subject: [PATCH] files-backend: fix loose ref cache inconsistency with root refs
Series version: standalone patch
Originating author: Andy Koppe
Thread type: bugfix

Core problem or goal
The files ref backend has an inconsistency in how root refs (e.g., `HEAD`, `ORIG_HEAD`) are handled in the loose ref cache. Root refs are included in the cache only if the `REFS_FOR_EACH_INCLUDE_ROOT_REFS` flag is passed during the *first* iteration that creates the cache; subsequent iterations include them regardless of the flag, and earlier iterations omit them even if the flag is set. The reftable backend is unaffected. The goal is to eliminate this inconsistency by keeping root refs out of the shared loose ref cache entirely and instead creating a separate temporary ref cache for them when requested.

Current status
Under review; no prior versions. The patch is a well-scoped bugfix that updates `files-backend.c` and adds a test in `t/t6302-for-each-ref-filter.sh` to verify `--include-root-refs` works correctly with `--merged`.

Key technical details
- Files touched: `files-backend.c`, `t/t6302-for-each-ref-filter.sh`
- Subsystem: refs (files backend only)
- New behavior: root refs are no longer stored in the shared loose ref cache; instead, a temporary ref cache is created and overlaid on the loose ref iterator when `REFS_FOR_EACH_INCLUDE_ROOT_REFS` is passed
- Test coverage: new test case in `t/t6032-for-each-ref-filter.sh` verifies `--include-root-refs` with `--merged`
- On-disk format: unchanged
- CLI options: `--include-root-refs` (existing) now behaves consistently
