Subject: [PATCH] files-backend: fix loose ref cache inconsistency with root refs
Series version: standalone patch
Originating author: Andy Koppe
Thread type: bugfix

Core problem or goal
The files ref backend has an inconsistency in how root refs (e.g., `HEAD`, `ORIG_HEAD`) are handled in the loose ref cache. Root refs are included in the cache only if the `REFS_FOR_EACH_INCLUDE_ROOT_REFS` flag is passed during the *first* iteration that creates the cache; subsequent iterations include them regardless of the flag, and earlier iterations omit them even if the flag is set. The goal is to eliminate this inconsistency by ensuring root refs are handled predictably, either by excluding them from the shared loose ref cache entirely or by teaching the cache to respect the flag consistently.

Current status
Under review; no prior versions. The patch is a well-scoped bugfix that updates `files-backend.c` and adds a test in `t/t6302-for-each-ref-filter.sh` to verify `--include-root-refs` works correctly with `--merged`. The discussion has expanded to evaluate two architectural approaches: (1) Andy Koppe's original solution, which creates a separate temporary ref cache for root refs on demand, and (2) Junio C Hamano's proposed alternative, which maintains two persistent caches (one for refs under `refs/` and one for root refs) and combines them as needed. No implementation for the latter has been posted yet.

Key technical details
- Files touched: `files-backend.c`, `t/t6302-for-each-ref-filter.sh`
- Subsystem: refs (files backend only; reftable backend unaffected)
- New behavior (original patch): root refs are no longer stored in the shared loose ref cache; instead, a temporary ref cache is created and overlaid on the loose ref iterator when `REFS_FOR_EACH_INCLUDE_ROOT_REFS` is passed
- New behavior (Junio's alternative): two persistent caches (one for `refs/` hierarchy, one for root refs) are maintained; callers combine them explicitly to include root refs
- Test coverage: new test case in `t/t6302-for-each-ref-filter.sh` verifies `--include-root-refs` with `--merged`
- On-disk format: unchanged
- CLI options: `--include-root-refs` (existing) now behaves consistently under either approach
- Performance considerations: Junio's alternative avoids recreating the root ref cache for every iterator, addressing Patrick Steinhardt's concern about the original patch's efficiency

Open questions and loose ends
- Which architectural approach will be adopted: the original temporary cache or Junio's persistent dual-cache design.
- If Junio's alternative is chosen, whether the implementation will reuse existing cache infrastructure or introduce new mechanisms.
- Whether the chosen solution will require additional test coverage beyond the existing `--include-root-refs`/`--merged` test.
