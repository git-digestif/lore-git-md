Subject: [PATCH v3] files-backend: fix loose ref cache inconsistency with root refs
Series version: v3 (v1 and v2 previously posted; this is the updated iteration)
Originating author: Andy Koppe
Thread type: bugfix

Core problem or goal
The files ref backend has an inconsistency in how root refs (e.g., `HEAD`, `ORIG_HEAD`) are handled in the loose ref cache. Root refs are included in the cache only if the `REFS_FOR_EACH_INCLUDE_ROOT_REFS` flag is passed during the *first* iteration that creates the cache; subsequent iterations include them regardless of the flag, and earlier iterations omit them even if the flag is set. The goal is to eliminate this inconsistency by ensuring root refs are handled predictably, either by excluding them from the shared loose ref cache entirely or by teaching the cache to respect the flag consistently.

Current status
Cooking in `next` as of 2024-07-10 (Junio’s "What's cooking" report). The patch carries Patrick Steinhardt’s **Reviewed-by** and is now undergoing integration testing. The v3 iteration remains a well-scoped bugfix targeting `files-backend.c`, verified by a new test in `t/t6302-for-each-ref-filter.sh`. The core implementation—excluding root refs from the shared loose ref cache and using a temporary cache when `REFS_FOR_EACH_INCLUDE_ROOT_REFS` is passed—is unchanged from v2. The architectural discussion (temporary cache vs. Junio’s persistent dual-cache design) remains open but is not blocking integration. Documentation corrections (mislabeling of root refs as pseudorefs) are deferred to a separate patch.

Key technical details
- Files touched: `files-backend.c`, `t/t6302-for-each-ref-filter.sh` (documentation corrections deferred)
- Subsystem: refs (files backend only; reftable backend unaffected)
- New behavior (v3): root refs are excluded from the shared loose ref cache; a temporary ref cache is created and overlaid on the loose ref iterator when `REFS_FOR_EACH_INCLUDE_ROOT_REFS` is passed. The implementation is unchanged from v2.
- New behavior (Junio’s alternative): two persistent caches (one for `refs/` hierarchy, one for root refs) would be maintained; callers combine them explicitly to include root refs. Not implemented in v3.
- Test coverage: new test case in `t/t6302-for-each-ref-filter.sh` verifies `--include-root-refs` with `--merged`; coverage remains minimal but sufficient.
- On-disk format: unchanged
- CLI options: `--include-root-refs` (existing) now behaves consistently; documentation corrections deferred.
- Performance considerations: overhead of the temporary cache is negligible since the flag is used in only two places, both invoking it just once per command. Junio’s alternative avoids recreating the root ref cache for every iterator but has not been implemented or benchmarked.
- Code organization: `create_root_ref_cache()` moved below `get_loose_ref_cache()` for clarity, as shown in the range-diff against v1.

Open questions and loose ends
- Which architectural approach will ultimately be adopted: the temporary cache (implemented in v3) or Junio’s persistent dual-cache design. The discussion remains open but is not blocking integration.
- If Junio’s alternative is chosen, whether the implementation will reuse existing cache infrastructure or introduce new mechanisms.
- Whether the chosen solution will require additional test coverage beyond the existing `--include-root-refs`/`--merged` test.
- Documentation corrections (mislabeling of root refs as pseudorefs) will be submitted as a separate patch, per Patrick’s request.
