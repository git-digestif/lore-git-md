This thread is about a bugfix for an inconsistency in Git’s files ref backend, where root refs (like `HEAD` and `ORIG_HEAD`) are inconsistently included in the loose ref cache depending on when the cache is first created. Andy Koppe identified the issue and proposed a fix in v3 of the patch series, which now carries Patrick Steinhardt’s **Reviewed-by** and has been queued by Junio C Hamano in the `next` branch for integration testing.

The fix itself is straightforward: root refs are excluded from the shared loose ref cache, and a temporary cache is created when the `REFS_FOR_EACH_INCLUDE_ROOT_REFS` flag is used. This approach is simple and addresses the immediate bug, but Junio has also proposed an alternative design—maintaining two persistent caches (one for the `refs/` hierarchy and one for root refs)—which could avoid the overhead of recreating the cache for each iterator. The discussion about which approach to adopt remains open, though the patch is now cooking in `next` regardless.

The patch touches only `files-backend.c` and adds a test case to `t/t6302-for-each-ref-filter.sh`, with no changes to on-disk formats or CLI behavior. Documentation corrections (clarifying that root refs are not pseudorefs) have been deferred to a separate patch. While the patch is technically unblocked, the architectural trade-offs between Andy’s temporary cache and Junio’s dual-cache design are still unresolved. Patrick’s review focused on procedural readiness rather than the deeper design questions, so the thread may see further discussion if others weigh in on the alternatives.
