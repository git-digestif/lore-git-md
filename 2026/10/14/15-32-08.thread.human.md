This thread is about a bugfix for an inconsistency in Git’s files ref backend, where root refs (like `HEAD`) are inconsistently included in the loose ref cache depending on when the cache is first created. Andy Koppe identified the issue and proposed a fix in v3 of the patch series, which excludes root refs from the shared cache entirely and uses a temporary cache when the `REFS_FOR_EACH_INCLUDE_ROOT_REFS` flag is passed. The patch touches `files-backend.c` and adds a test in `t/t6302-for-each-ref-filter.sh`.

The patch is now technically unblocked after Patrick Steinhardt’s latest review, which confirmed the procedural improvements (commit message clarity, code organization, and splitting out documentation fixes) were addressed. Patrick gave the patch his "looks good to me," but the broader architectural discussion remains open. Junio C Hamano previously proposed an alternative design—maintaining two persistent caches (one for the `refs/` hierarchy and one for root refs)—but this hasn’t been implemented or endorsed yet. Andy’s current approach is simpler and sufficient for the flag’s limited use, but Junio’s alternative could avoid recreating the root ref cache for every iterator.

The patch is ready for integration from a technical standpoint, but the final design choice (temporary cache vs. persistent dual-cache) is still unresolved. Documentation corrections for mislabeling root refs as pseudorefs will be handled separately. Key participants include Andy (author), Patrick (reviewer), and Junio (maintainer, proposing an alternative). The thread is now waiting for a decision on the architectural direction.
