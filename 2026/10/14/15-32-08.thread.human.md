This thread is a focused bugfix for the files ref backend, submitted by Andy Koppe. The patch resolves an inconsistency in how root refs (like `HEAD` or `ORIG_HEAD`) are handled in the loose ref cache: they were only included if the `REFS_FOR_EACH_INCLUDE_ROOT_REFS` flag was set during the *first* cache iteration, but subsequent iterations would include them regardless of the flag, while earlier ones would omit them even if the flag was set. The reftable backend is unaffected.

The fix avoids storing root refs in the shared loose ref cache entirely. Instead, when an iteration requests root refs, it creates a separate temporary ref cache for them, overlays its iterator on the loose ref iterator, and frees it afterward. The change is implemented in `files-backend.c` and includes a test in `t/t6302-for-each-ref-filter.sh` to verify that `--include-root-refs` works correctly with `--merged`. The patch is well-scoped, targeting only the refs subsystem without affecting other backends or user-facing behavior beyond fixing the inconsistency.
