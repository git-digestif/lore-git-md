This thread is about a bugfix for the Git files ref backend, where root refs (like `HEAD` and `ORIG_HEAD`) are inconsistently handled in the loose ref cache. Andy Koppe identified the issue: root refs are only included in the cache if the `REFS_FOR_EACH_INCLUDE_ROOT_REFS` flag is set during the *first* iteration that creates the cache, leading to unpredictable behavior in later iterations. His patch removes root refs from the shared cache entirely and instead creates a temporary ref cache for them when requested, ensuring consistent behavior for the `--include-root-refs` option.

The patch is under review, with Patrick Steinhardt raising two technical questions about the design. He asks why the fix doesn’t teach the existing loose ref cache to conditionally skip root refs when the flag isn’t set, and why the root ref cache isn’t persisted like the loose ref cache. While Patrick hasn’t rejected the current approach, his feedback suggests the solution might still be refined for efficiency or conceptual clarity. The patch remains a well-scoped fix, touching only `files-backend.c` and adding a test in `t/t6302-for-each-ref-filter.sh` to verify the fix. No other backends or user-facing behaviors are affected. The discussion is still open, but the core issue and proposed solution are clear.
