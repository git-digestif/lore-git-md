This thread is about a bugfix for the files ref backend that addresses an inconsistency in how root refs (like `HEAD` and `ORIG_HEAD`) are handled in the loose ref cache. The issue is that root refs are only included in the cache if the `REFS_FOR_EACH_INCLUDE_ROOT_REFS` flag is passed during the *first* iteration that creates the cache, leading to unpredictable behavior in subsequent iterations.

Andy Koppe posted a v2 of the patch, which keeps root refs out of the shared loose ref cache entirely and instead creates a separate temporary ref cache for them when requested. This version includes minor documentation corrections and code organization tweaks but maintains the same architectural approach as v1. The patch touches `files-backend.c`, a test file, and documentation, and it includes a test verifying that `--include-root-refs` works correctly with `--merged`. Performance concerns from the initial review have been addressed, as the overhead of the temporary cache is negligible given the limited use of the flag.

The discussion has centered on two architectural approaches: Andy’s original solution (temporary cache) and Junio C Hamano’s proposed alternative (persistent dual caches for refs under `refs/` and root refs). While Junio’s suggestion is acknowledged in the commit message, this v2 does not implement it. The patch is technically unblocked, with no outstanding objections, and Patrick Steinhardt’s initial concerns have been resolved. The reftable backend is unaffected by this change. The next steps will likely involve deciding which architectural approach to adopt.
