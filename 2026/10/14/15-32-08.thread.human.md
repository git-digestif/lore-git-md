This thread is about a bugfix for an inconsistency in how Git’s files ref backend handles root refs (like `HEAD` or `ORIG_HEAD`) in its loose ref cache. The issue is that root refs are only included in the cache if the `REFS_FOR_EACH_INCLUDE_ROOT_REFS` flag is set during the *first* cache creation, leading to unpredictable behavior in later iterations. Andy Koppe’s v3 patch addresses this by excluding root refs from the shared cache entirely and using a temporary cache when the flag is passed, ensuring consistent behavior.

The patch is now technically unblocked after incorporating feedback: Andy added a range-diff against v1 for easier review and split out documentation corrections (fixing mislabeled root refs in `--include-root-refs`) into a separate patch, as requested by Patrick Steinhardt. The core implementation remains unchanged from v2. However, the architectural debate continues—Junio C Hamano has proposed an alternative design using persistent dual caches (one for `refs/` hierarchy, one for root refs), but this hasn’t been implemented. The patch touches `files-backend.c` and adds a test in `t/t6302-for-each-ref-filter.sh`, with no on-disk format changes or performance concerns.

Key participants are Andy (author), who defends the temporary cache as simpler and sufficient, and Junio, who prefers the dual-cache approach for symmetry. Patrick Steinhardt initially raised technical questions but now accepts the current design. The next steps hinge on whether Junio’s alternative gains traction or if the temporary cache is deemed acceptable. Documentation fixes will follow in a separate patch.
