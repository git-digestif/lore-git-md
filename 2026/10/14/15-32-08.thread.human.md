This thread is about a bugfix for an inconsistency in Git’s files ref backend, where root refs (like `HEAD`) are inconsistently included in the loose ref cache depending on when the cache is first created. Andy Koppe identified the issue and proposed a fix in v3 of the patch series, which excludes root refs from the shared cache and uses a temporary cache when the `REFS_FOR_EACH_INCLUDE_ROOT_REFS` flag is passed. The patch has Patrick Steinhardt’s **Reviewed-by** and is now cooking in Junio’s `next` branch for integration testing, with no changes to the core implementation since v2.

The key technical detail is that the fix targets `files-backend.c` and adds a test in `t/t6302-for-each-ref-filter.sh` to verify consistent behavior with `--include-root-refs`. The architectural debate—whether to use a temporary cache (as in v3) or Junio’s proposed persistent dual-cache design—remains unresolved but isn’t blocking integration. Documentation corrections (e.g., mislabeling root refs as pseudorefs) are deferred to a separate patch.

The latest email is a minor procedural exchange between Patrick Steinhardt and Junio about `b4`’s range-diff bookkeeping, confirming that `b4` doesn’t support the flexible approach Andy used. This doesn’t affect the patch’s status or the open architectural questions. The thread is effectively in a holding pattern: the fix is queued, but the long-term design direction is still up in the air.
