This is a contributor housekeeping patch that aligns the `credential-store` configuration with Git’s established timeout naming convention. The patch adds `credentialStore.lockTimeout` as the preferred setting while keeping `credentialStore.lockTimeoutMS` as a deprecated alias, ensuring backward compatibility.

The change is mechanical and uncontroversial: it touches only the credential-store subsystem, updating the configuration parser in `builtin/credential-store.c` to check `lockTimeout` first and fall back to `lockTimeoutMS` if the new key is unset. Documentation in `Documentation/config/credential.adoc` is updated to mark the old name as deprecated, and the test suite (`t/t0302-credential-store.sh`) gains four new cases that verify both names work, that the new name takes precedence when both are set, and that the timeout value is correctly reported in error messages.

This patch directly addresses the naming inconsistency noted in Junio C Hamano’s review of the `rerere.lockTimeout` series, where he pointed out that most Git timeout variables omit the `MS` suffix. The implementation follows the same pattern as other deprecation transitions in Git: the old name remains functional but is documented as deprecated, and the code prefers the new name. No behavior change is introduced; the patch is purely about code consistency.

The patch is well-scoped and self-contained, with thorough test coverage that exercises edge cases. It is ready for review and should integrate cleanly with the rest of the codebase.
