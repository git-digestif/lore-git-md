This is a contributor housekeeping patch that aligns the naming of Git’s timeout configuration variables. It introduces `credentialStore.lockTimeout` as the preferred setting for credential lock retries, while retaining `credentialStore.lockTimeoutMS` as a deprecated alias. The change is purely mechanical: no behavior is altered, only the config key name and its documentation.

The patch touches three files. In `Documentation/config/credential.adoc`, it updates the description of the timeout setting to use the new name and adds a deprecation notice for the old one. In `builtin/credential-store.c`, it modifies the config lookup to try the new key first, falling back to the old one if the new key is unset. The test suite (`t/t0302-credential-store.sh`) adds four new tests that verify the new key works as expected, that the old key still works, that the new key takes precedence when both are set, and that a zero timeout behaves correctly.

This is a direct follow-up to Junio C Hamano’s observation in the `rerere` race-fix thread that most timeout variables in Git use milliseconds without an explicit unit suffix. The patch adopts the same convention (`lockTimeout` instead of `lockTimeoutMS`) and ensures backward compatibility by keeping the old name as an alias. The test coverage is thorough, covering edge cases like zero timeout and precedence between the two keys. The commit message is clear and concise, explaining the motivation and the change without overstating its scope. No substantive objections are expected, as the change is uncontroversial and aligns with established project conventions.
