This is a bugfix for `git repack` targeting the promisor-object handling. The patch addresses a regression where `git repack --drop-filtered --dry-run` violates its documented behavior by actually rebuilding packs and deleting old ones despite the `--dry-run` flag. The commit message clearly explains the bug: the `--dry-run` block in `cmd_repack()` falls through into the regular repack code, causing unintended modifications to the repository.

The fix is minimal and surgical: it adds an early `return` after listing the candidate objects for dropping, preventing the code from proceeding to `repack_promisor_objects()` and `existing_packs_remove_redundant()`. The patch also includes a new test that verifies the pack directory remains unchanged with and without the `-d` flag, covering both the explicit and implicit deletion cases mentioned in the commit message.

The bug was reported by Coy Geek in a linked thread, and the patch includes a proper `Reported-by` trailer. The test coverage is thorough, checking both the output listing and the absence of side effects. This looks like a well-scoped, well-motivated fix that addresses a real user-facing issue without introducing unnecessary complexity. The code change is confined to `builtin/repack.c` and the corresponding test script, making it easy to review and unlikely to have unintended consequences elsewhere.
