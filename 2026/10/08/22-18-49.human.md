This is an RFC for a new tool, `git bisect-rebase`, which refines Alejandro Colomar’s earlier `git brebase` proposal into a more structured workflow for rebasing complex histories. The update introduces `--abort`, `--continue`, and `--quit` flags that operate at the *bisect-rebase* level rather than the individual rebase level, enabling recursive resolution of branch trees (e.g., moving a parent branch and its descendants together).

The core idea remains the same: use `git bisect` to find the first conflicting commit, then let the user resolve it with `git rebase --continue` before resuming the bisect-rebase. The new flags allow the user to pause, switch branches, and resume without restarting the entire operation. Two concrete algorithms are provided—one for rebasing a single branch, the other for a tree of branches—showing how the flags fit into a repeatable workflow. The implementation is now split into three shell scripts (main, callback, and continue helper), hosted in the Linux man-pages repository for easier review.

This version directly addresses feedback from the thread by making the workflow more predictable and scriptable, but the fundamental questions remain: should this be a standalone command, a flag for `git rebase`, or the default behavior? The author still treats it as a porcelain tool built on top of `git rebase` (plumbing), preserving the complementary relationship between the two. No C rewrite is proposed yet, so robustness for production use is still an open question. The update looks like a serious step toward usability, but the integration debate is far from settled.
