Thread identity
Subject: [RFC PATCH 0/6] Add "precious files" attribute
Series version: RFC (v1 implied)
Originating author: Mirko Faina <mroik@delayed.space>
Thread type: RFC patch series

Core problem or goal
Introduce a new file attribute (`precious`) that marks untracked files as important, preventing their accidental deletion by Git operations like `git clean` or checkout. The goal is to protect user-generated files (e.g., build artifacts, IDE metadata) that should persist across branch switches but are not version-controlled. The design document (patch 1/6) by Elijah Newren proposes a ternary state in `.gitignore` (precious `$`, untracked `!`, trashable unmarked) and command-specific behaviors to enforce preservation.

Current status
Under review (RFC stage). No prior versions. The series includes a 540-line design document (patch 1/6), refactoring patches (2-4/6), and core implementation (5-6/6). `git clean` support, documentation, and broader command coverage (e.g., `git reset`) are explicitly deferred. Patch 2/6 (this email) is a mechanical refactoring moving `PATTERN_FLAG_*` macros into `enum pattern_flags` in `attr.h` to prepare for the `PATTERN_TYPE_PRECIOUS` addition in later patches.

Key technical details
- Files/subsystems: `dir.c` (path-matching), `attr.h` (attribute definitions), `unpack-trees.c` (checkout logic), `builtin/ls-files.c` (new `--precious` flag), `builtin/check-ignore.c`, `builtin/sparse-checkout.c` (updated includes).
- New symbols: `enum pattern_flags` (moved from `dir.h` macros), `enum pattern_type` (with future `PATTERN_TYPE_PRECIOUS`), `parse_path_pattern()`, `add_pattern()`, `check_ok_to_remove()` (extended), `dir_struct` fields (`precious`/`precious_nr`).
- Behavior: Precious files (marked with `$` in `.gitignore`) are excluded from deletion during checkout or clean (once implemented), but remain untracked. Commands like `git checkout`/`merge`/`read-tree` preserve them unless `--force` is used; `git clean` will require a new `--all` flag.
- On-disk format: `.gitignore` syntax extended to support `$` prefix for precious files.
- Test coverage: Basic functionality in `t3001-ls-files-others-exclude.sh`.

Open questions and loose ends
- **Design debate**: Is the ternary `.gitignore` syntax and command-specific behaviors the right approach, given existing mechanisms (`.gitignore`, `git stash -u`)? The complexity of the proposal may face resistance.
- **Missing features**: `git clean` integration, documentation, and support for commands like `git reset` are deferred.
- **Edge cases**: Interaction with `--force` flags, submodule handling, sparse-checkout, and backward compatibility (older Git clients treating precious files as untracked).
- **Prior discussion**: The design document references prior context not summarized in the cover letter, leaving some rationale opaque.
- **Refactoring necessity**: The value of patch 2/6 depends entirely on the eventual acceptance of the precious-files feature; if the feature is rejected, the refactoring may be discarded.
