Thread identity
Subject: [RFC PATCH 0/6] Add "precious files" attribute
Series version: RFC (v1 implied)
Originating author: Mirko Faina <mroik@delayed.space>
Thread type: RFC patch series

Core problem or goal
Introduce a new file attribute (`precious`) that marks untracked files as important, preventing their accidental deletion by Git operations like `git clean` or checkout. The goal is to protect user-generated files (e.g., build artifacts, IDE metadata) that should persist across branch switches but are not version-controlled. The design document (patch 1/6) by Elijah Newren proposes a ternary state in `.gitignore` (precious `$`, untracked `!`, trashable unmarked) and command-specific behaviors to enforce preservation.

Current status
Under review (RFC stage). No prior versions. The series includes a 540-line design document (patch 1/6), refactoring patches (2-4/6), and core implementation (5-6/6). `git clean` support, documentation, and broader command coverage (e.g., `git reset`) are explicitly deferred. Patch 4/6 (this email) extends `add_pattern()` to reject precious-file patterns (`$` prefix) in disallowed contexts (e.g., `$GIT_DIR/info/sparse-checkout`), adding a `disable_precious` flag to enforce this restriction and warning users when such patterns are skipped.

Key technical details
- Files/subsystems: `dir.c` (path-matching), `attr.h` (attribute definitions), `unpack-trees.c` (checkout logic), `builtin/ls-files.c` (new `--precious` flag), `builtin/check-ignore.c`, `builtin/sparse-checkout.c` (updated to use `disable_precious`), `t7508-status.sh` (invalid pattern tests), `t1091-sparse-checkout-builtin.sh` (new test for sparse-checkout rejection).
- New symbols: `enum pattern_flags` (moved from `dir.h` macros in patch 2/6), `enum pattern_type` (with future `PATTERN_TYPE_PRECIOUS`), `parse_path_pattern()` (now returns error code), `add_pattern()` (extended with `disable_precious` flag), `add_patterns_from_buffer()`/`add_patterns_from_file_to_list()` (updated to propagate the flag), `check_ok_to_remove()` (extended in later patches), `dir_struct` fields (`precious`/`precious_nr`).
- Behavior: Precious files (marked with `$` in `.gitignore`) are excluded from deletion during checkout or clean (once implemented), but remain untracked. Commands like `git checkout`/`merge`/`read-tree` preserve them unless `--force` is used; `git clean` will require a new `--all` flag. Invalid patterns (e.g., `!$`) trigger warnings, and precious patterns are now explicitly rejected in sparse-checkout files via the `disable_precious` flag.
- On-disk format: `.gitignore` syntax extended to support `$` prefix for precious files; malformed or contextually invalid patterns are rejected during parsing.
- Test coverage: Basic functionality in `t3001-ls-files-others-exclude.sh` (patch 2/6), invalid pattern warnings in `t7508-status.sh` (patch 3/6), and sparse-checkout rejection in `t1091-sparse-checkout-builtin.sh` (patch 4/6).

Open questions and loose ends
- **Design debate**: Is the ternary `.gitignore` syntax and command-specific behaviors the right approach, given existing mechanisms (`.gitignore`, `git stash -u`)? The complexity of the proposal may face resistance.
- **Missing features**: `git clean` integration, documentation, and support for commands like `git reset` are deferred. Broader enforcement of precious patterns (e.g., in `git clean`) remains unimplemented.
- **Edge cases**: Interaction with `--force` flags, submodule handling, sparse-checkout, and backward compatibility (older Git clients treating precious files as untracked). Invalid pattern handling (e.g., `!$`) is addressed, but the `disable_precious` flag introduces new context-specific restrictions (e.g., sparse-checkout) that may require further refinement.
- **Prior discussion**: The design document references prior context not summarized in the cover letter, leaving some rationale opaque.
- **Refactoring necessity**: The value of patches 2-4/6 depends entirely on the eventual acceptance of the precious-files feature; if the feature is rejected, the refactoring may be discarded.
