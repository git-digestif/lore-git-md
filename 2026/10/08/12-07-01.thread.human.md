This thread is an RFC series exploring how Git handles local changes during operations like `git switch` and `git checkout`. Mirko Faina proposes a behavioral change in patch 5/6 to prevent these commands from clobbering "precious" files—ignored files explicitly marked as valuable—by introducing a new `is_trashable()` function. The patch modifies `unpack-trees.c` to use this function instead of the broader `is_excluded()`, but lacks tests, which may be a sticking point for reviewers.

The series is still in the design feedback phase, so no decisions have been made yet. Key questions likely to arise include whether the "precious files" concept (introduced earlier in the series) is the right approach, how to handle edge cases (e.g., config interactions), and whether the new behavior will confuse users. The patch touches core checkout/switch logic, so reviewers like Elijah Newren (merge machinery) or Phillip Wood (sequencer/worktree) might weigh in on correctness. For now, the thread is open-ended, awaiting substantive feedback on the proposed direction.
