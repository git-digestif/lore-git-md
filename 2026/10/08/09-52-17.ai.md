This is the first patch in the v3 series fixing a data-loss race in `git repack`. It corrects a long-standing behavioral inconsistency in `git pack-objects --stdin-packs=follow` where `--keep-pack` packs were incorrectly treated as closed under reachability (like `^` packs), causing the traversal to stop prematurely. The fix ensures these packs are treated as "kept-open" (`!`), allowing the traversal to continue through their objects to rescue dependencies that would otherwise be omitted.

The patch touches `builtin/pack-objects.c`, modifying `add_extra_kept_packs()` to check the `stdin_packs` mode and set `pack_keep_in_core_open` instead of `pack_keep_in_core` when in `STDIN_PACKS_MODE_FOLLOW`. This change aligns the in-core flag with the intended semantics: `--keep-pack` packs are not repacked, but they are not guaranteed to be self-contained, so the traversal must be able to go through them. The test added in `t/t5331-pack-objects-stdin.sh` reproduces the bug by creating a kept pack (`B_ONLY`) containing only a commit, with its tree and blob in an excluded pack (`B`). The test confirms the fix includes the tree and blob in the output pack.

This is a **well-motivated bugfix** with clear test coverage. The commit message explains the problem and the fix concisely, and the test case is minimal and focused. The change is unlikely to introduce regressions, as it only affects the `--stdin-packs=follow` mode and aligns the behavior with the existing `!` pack semantics. Reviewers may discuss whether the mode check in `add_extra_kept_packs()` is sufficient to cover all callers, but the test explicitly covers the corrected edge case, and the patch is part of a larger series that has already addressed architectural concerns in patch 2/5. The patch is ready for review by repack/ODB maintainers (Patrick Steinhardt, Taylor Blau) and low-level traversal experts (Jeff King).
