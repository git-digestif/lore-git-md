This is the **first patch in a two-part feature series** that hardens Git's ignore-revs parser and tag-peeling logic before introducing a default ignore-revs file (`HEAD:.git-blame-ignore-revs`). The patch addresses **security concerns** raised during v1 review by preventing two classes of issues: embedded NUL bytes in ignore-revs files (which could cause silent parsing of malformed object names) and promisor fetches in partial clones (which could trigger unintended network requests when peeling tags).

The changes are **focused and surgical**:
- In `oidset.c`, `oidset_parse_file_carefully()` now rejects any line containing an embedded NUL byte via `memchr()`, replacing the previous behavior where `strchr()` and `parse_oid_hex_algop()` would stop at the first NUL but ignore trailing garbage (e.g., `<oid>\0garbage` or `<oid>\0# comment`).
- In `builtin/blame.c`, `peel_to_commit_oid()` is rewritten to use `odb_read_object_info_extended()` with `OBJECT_INFO_SKIP_FETCH_OBJECT` and `OBJECT_INFO_QUICK`, ensuring that missing tag targets in partial clones do not trigger promisor fetches. The function now also verifies each tag's declared type before parsing, preventing type confusion.

Test coverage is **thorough**, adding two new test cases:
1. A test verifying that lines with embedded NUL bytes are rejected with a clear error message.
2. A test simulating chained tags and missing tag targets in a partial clone, confirming that the blame operation succeeds without fetching objects or emitting errors.

The patch is **well-motivated** and **technically sound**, directly addressing feedback from Junio and other reviewers. The hardening is **necessary** for the follow-up patch (2/2), which will expose the ignore-revs parser to upstream-controlled content. The changes are **minimal** and **backwards-compatible**, as they only tighten validation without altering existing behavior for well-formed input. **Worth attention** from security-interested contributors (e.g., Jeff King, brian m. carlson) to validate the completeness of the hardening.
