Core problem or goal
The thread addresses a long-standing (2005) inconsistency in Git’s index refresh logic: `git status` reports files as modified when `git diff` and `git add` correctly ignore them due to clean filters (e.g., `text eol=lf`) rewriting file contents without changing their logical meaning. The root cause is `ie_match_stat()`’s size-based shortcut, which fails to account for conversions, while the mtime-based check already handles them correctly. The minimal fix is a one-line change to disable the size shortcut for converted paths, falling back to the existing conversion-aware logic.

Current status
Under review; proposed v2 to split the series. The original v1 consisted of two patches:

A complex patch (129 insertions, 3 deletions) that combined the core fix with an optimization to avoid hashing files when the converted length mismatches the blob size. **Junio’s substantive review** questioned the complexity and suggested refactoring or justifying the new `ce_compare_converted_data()` function. The author now proposes a minimal v2 with only the core fix, deferring the optimization and config option to follow-ups if desired.
2. A config escape hatch (`core.convertAwareStatus`) to let users opt out of the new behavior, with three modes: `true` (default), `no-filter` (skip clean filters), and `false` (restore pre-patch behavior). This patch is now proposed as a follow-up.

Key technical details
- **Files touched**: `read-cache.c` (core logic), `environment.c`/`environment.h` (config plumbing, deferred), `Documentation/config/core.adoc` (docs, deferred), `t/t0020-crlf.sh` (tests).
- **Core fix**: A one-line change to `ie_match_stat()` to skip the size shortcut when `would_convert_to_git()` is true, reusing the existing conversion-aware logic in the mtime branch.
- **Deferred optimization**: `ce_compare_converted_data()` and `size_change_is_conclusive()` to avoid hashing files with mismatched converted lengths. Performance measurements showed a 3–17x slowdown without it, but the author acknowledges it is separable.
- **Deferred config**: `core.convertAwareStatus` (values: `true`, `no-filter`, `false`) to address performance concerns for expensive clean filters (e.g., Git LFS).
- **Behavior change**: The minimal fix aligns `git status` with `git diff`/`git add` for converted files by default, resolving the inconsistency without disrupting existing workflows. The deferred config option would provide backward compatibility for performance-sensitive cases.
- **Test coverage**: Expanded in `t/t0020-crlf.sh` to validate CRLF rewrites, lone CRs, Git LFS compatibility, and config modes (all deferred to follow-ups).

Open questions and loose ends
- **Optimization inclusion**: Whether the deferred optimization (`ce_compare_converted_data()`) should be included in v2 or left as a follow-up. The author argues it is separable but provides performance data to justify its value.
- **Config necessity**: Whether the `core.convertAwareStatus` config option is needed upfront or can be deferred. The author positioned it as an escape hatch for performance-sensitive users (e.g., Git LFS), but Junio has not yet weighed in on its necessity.
