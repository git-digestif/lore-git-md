Subject: [PATCH 0/2] Fix index refresh inconsistency with line-ending conversions
Series version: v1 (initial submission)
Originating author: Curtis Allen Smith
Thread type: bugfix series

Core problem or goal
The thread addresses a long-standing (2005) inconsistency in Git’s index refresh logic: `git status` reports files as modified when `git diff` and `git add` correctly ignore them due to clean filters (e.g., `text eol=lf`) rewriting file contents without changing their logical meaning. The root cause is `ie_match_stat()`’s size-based shortcut, which fails to account for conversions, while the mtime-based check already handles them correctly.

Current status
Under review; no prior versions. The series consists of two patches:
1. Modifies `ie_match_stat()` to skip the size shortcut for converted paths, falling back to the conversion-aware check, and optimizes `ce_compare_data()` to avoid hashing files with mismatched converted lengths. The patch introduces `size_change_is_conclusive()` and `ce_compare_converted_data()` to handle the logic and performance optimizations, respectively.
2. Introduces `core.convertAwareStatus` (default: `true`) to let users opt out of the new behavior, with three modes: `true` (default, consult all conversions), `no-filter` (consult only Git’s built-in conversions, skip clean filters), and `false` (restore pre-patch behavior).

Key technical details
- **Files touched**: `read-cache.c` (core logic), `environment.c`/`environment.h` (config plumbing), `Documentation/config/core.adoc` (docs), `t/t0020-crlf.sh` (tests).
- **New config**: `core.convertAwareStatus` (values: `true`, `false`, `no-filter`).
- **New symbols**: `ie_match_stat()`, `ce_compare_data()`, `ce_compare_converted_data()`, `size_change_is_conclusive()`, `count_crlf()`.
- **Performance impact**: Minimal overhead for clean trees/unconverted files; resolves a 3x slowdown for stat-dirty converted files after the first run. The optimization avoids full hashing when the converted length mismatches the blob size. The config option allows users to mitigate performance concerns for expensive clean filters (e.g., Git LFS) via `no-filter` or `false`.
- **Behavior change**: `git status` now aligns with `git diff`/`git add` for converted files by default, addressing the inconsistency without disrupting existing workflows. The escape hatch ensures backward compatibility for performance-sensitive cases.
- **Test coverage**: Expanded in `t/t0020-crlf.sh` to validate CRLF rewrites (unchanged content), lone CRs (edge case for `text=auto`), Git LFS compatibility, and all three config modes.
