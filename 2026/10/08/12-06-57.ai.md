This is the design document for the "precious files" RFC patch series, written by Elijah Newren and included as patch 1/6. It proposes a new file attribute type (`precious`) to protect untracked but important files (e.g., build artifacts, IDE metadata) from accidental deletion by Git operations like `git clean` or checkout.

The document is comprehensive, spanning 540 lines and covering objectives, background, proposal details, backward compatibility, implementation hints, and alternatives. Key points include:
- **Specification**: Precious files are marked in `.gitignore` with a leading `$` (e.g., `$.config`), creating a ternary state alongside untracked (`!`) and trashable (no prefix) files.
- **Behavior**: Commands like `git checkout`, `merge`, and `read-tree` will preserve precious files unless `--force` is used. `git clean` will require a new `--all` flag to delete them.
- **Backward compatibility**: Older Git clients will treat precious files as untracked, avoiding deletion but causing minor annoyances (e.g., `git status` listing them).
- **Implementation**: Refactors `dir_struct` to add `precious`/`precious_nr` fields and extends path-matching logic in `dir.c` and `unpack-trees.c`.
- **Open questions**: The document defers `git clean` integration, documentation, and edge cases (e.g., submodules, sparse-checkout) to future work.

The design is well-motivated and addresses a long-standing user pain point, but its complexity (e.g., ternary `.gitignore` syntax, command-specific behaviors) may spark debate. The document’s thoroughness suggests this is a serious proposal, though the RFC stage indicates it’s still exploratory. Elijah’s involvement lends credibility, but the lack of explicit buy-in from other maintainers (e.g., Junio) leaves its future uncertain.
