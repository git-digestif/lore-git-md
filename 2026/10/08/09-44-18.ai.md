This is the third patch in a four-patch bugfix series (v4) that integrates branch copy and rename operations into Git's ordinary reference transaction system. The series addresses a long-standing issue where `reference-transaction` hooks were not seeing the full picture of branch rename (`git branch -m`) and copy (`git branch -c`) operations—hooks only received the deletion of the old ref, not the creation of the new one, breaking tools that rely on transactional ref updates.

This patch specifically implements the core logic to queue source and destination ref updates as ordinary transactions, replacing the backend-specific callbacks with a unified approach. It introduces per-ref-update state (flags `REF_COPY_SOURCE` and `REF_NEEDS_PACK`, and a `copy_from` field in `struct ref_update`) to track rename/copy relationships without overloading the transaction struct. The patch handles edge cases like D/F conflicts, case-only renames on case-insensitive filesystems, symlink reflogs, and concurrent source modifications during the "preparing" hook phase. It also ensures atomic reflog replacement by staging logs in temporary files (files backend) or tombstoning old entries (reftable), so hooks never see partial changes.

The patch touches `refs.c`, `refs/files-backend.c`, `refs/reftable-backend.c`, and adds new test files (`t/t1424-ref-copy-transaction.sh` and `t/perf/p1424-ref-copy-rename.sh`). It removes backend-specific callbacks (`rename_ref`, `copy_ref`) and their private helpers, centralizing copy/rename handling in the transaction API. Performance regressions are documented (~137% slowdown for files-based rename with 10,000 reflog entries, ~20-25% for reftable) but accepted as necessary for correctness.

The patch is well-tested, covering hook behavior, reflog preservation, error recovery (e.g., reflog installation failures), and mixed transactions (renames, copies, and ordinary updates in the same transaction). The test suite includes edge cases like D/F conflicts, symlink reflogs, and concurrent source modifications. The series as a whole has resolved Junio C Hamano's blocking test breakages from v3 (`t0600.16` and `t5510.35`) and is now passing the full test suite on macOS with both files and reftable backends.

Key symbols introduced or modified include `ref_transaction_prepare_copy()`, `ref_update_record_copy_source()`, and the `REF_TRANSACTION_FLAG_INTERNAL` flag (from patch 1/4) which suppresses hooks for nested backend operations. The patch maintains backwards compatibility and does not change on-disk formats. Reviewers may focus on whether the new per-ref-update flags and helpers are idiomatic and whether the suppression logic is sufficiently isolated. Patch 1/4 is uncontroversial and ready to proceed; this patch (3/4) and patch 2/4 (reflog replacement) are the core of the series and likely to attract the most scrutiny.
