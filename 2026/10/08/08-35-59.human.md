This is the ninth patch in Patrick Steinhardt’s 13-patch series refactoring Git’s object database (ODB) to move alternates handling into the "files" backend. The patch simplifies the temporary object directory ("tmp-objdir") API by merging the logic for replacing the primary ODB source into `tmp_objdir_create()`, eliminating the need for a separate `tmp_objdir_replace_primary_odb()` call.

The change is a straightforward refactoring of the quarantine directory setup. Previously, callers had to create the quarantine directory and then explicitly replace the primary ODB source in a two-step process. Now, `tmp_objdir_create()` handles both steps internally, reducing boilerplate in callers like `log-tree.c` and `object-file.c`. The patch also updates the `tmp_objdir` struct to store the original and temporary directories directly (as `struct odb_files_dir` pointers) instead of tracking the previous ODB source.

The diff is clean and mechanical: 49 lines removed, 27 added, touching only the tmp-objdir subsystem and its callers. The new `will_destroy` parameter (passed at creation time) controls whether the quarantine directory is ephemeral, replacing the same flag previously passed to `tmp_objdir_replace_primary_odb()`. This is part of the series’ broader shift toward explicit, self-contained backend management.

This patch is a minor but useful simplification. It doesn’t introduce new behavior or edge cases, but it does reinforce the series’ architectural direction: alternates and quarantine directories are now managed as linked lists of `struct odb_files_dir` within the files backend, making them backend-specific implementation details. If you’re following the ODB refactoring effort, this is a small but logical step toward the goal of pluggable backends. The change is uncontroversial and ready for integration.
