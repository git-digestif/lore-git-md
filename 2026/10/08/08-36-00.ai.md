This is patch 10/13 in Patrick Steinhardt’s ODB refactoring series, which moves the `will_destroy` flag from the generic `struct odb_source` to the loose-object backend where it is actually used. The patch is a clean-up that eliminates a backend-specific detail from the generic ODB source structure, aligning with the series’ architectural goal of self-contained backends.

The change is mechanical: the `will_destroy` field is removed from `struct odb_source` in `odb/source.h` and added to `struct odb_source_loose` in `odb/source-loose.h`. The only functional update is in `tmp-objdir.c`, where the flag is now set directly on the loose source (`t->temp_dir->loose->will_destroy`) instead of on both the loose and packed sources. This is correct because the flag is only checked by the loose-object backend to skip fsync for ephemeral sources.

The patch is small (4 files, 9 lines total) and well-scoped. It addresses a minor but real inconsistency: the `will_destroy` flag was defined in the generic ODB source structure but only used by the loose-object backend. No behavior changes are introduced, and the commit message clearly explains the rationale. This is a straightforward refactoring with no known risks or edge cases. If you’re following the ODB series, this patch is a low-stakes but necessary step toward the architectural cleanup.
