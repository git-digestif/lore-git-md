This is patch 12/13 in Patrick Steinhardt’s ODB alternates refactoring series, now at v2. The patch moves alternates handling from the generic ODB layer into the files backend, making alternates an implementation detail of that backend. It is the largest and most consequential patch in the series, touching 35 files and shifting the alternates infrastructure from `odb.c` to `odb/source-files.c`.

The patch converts all ODB operations from iterating over `struct odb_source` to iterating over `struct odb_files_dir`, a linked list of object directories managed by the files backend. Alternates are now read only by the files backend, and the `read_alternates` callback is dropped from the ODB source interface. The `odb_source` struct loses its `next` pointer and `by_path_entry` field, as sources no longer form a linked list. Key new helpers include `odb_files_dir_is_usable()`, `odb_add_alternate_recursively()`, and `odb_prepare_alternates()`, which encapsulate the alternates logic within the files backend.

The patch also updates all callers to use the new directory-based iteration: commands like `git fsck`, `git gc`, `git pack-objects`, and `git repack` now loop through directories instead of sources. The commit-graph subsystem is updated to store `repo` and `dir` (canonicalized absolute path) instead of `odb_source`, and all commit-graph filename helpers now take `const char *dir` instead of `struct odb_source *`.

Karthik Nayak’s review of this patch raised one critical technical concern: the removal of the `if (r->objects)` check in `clear_midx_file()`, which previously guarded against NULL dereferences. Patrick Steinhardt’s response clarified that the check was redundant, as the sole caller (`builtin/bugreport.c`) already dereferences `r->objects`, and the function itself does so later. The removal is thus safe, eliminating a false sense of security rather than introducing a regression.

The patch is technically complete and ready for integration, pending resolution of merge conflicts with `seen`. It is a well-motivated refactoring that simplifies the ODB architecture and enables future work like pluggable backends. The size and scope (441 lines added, 549 removed) make it a heavy lift, but the commit message and code changes are thorough and clear. If you’re tracking ODB internals or alternates-related work, this patch is the linchpin of the series and worth close attention.
