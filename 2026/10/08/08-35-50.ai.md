This is the v2 cover letter for Patrick Steinhardt’s 13-patch series refactoring the Git object database (ODB) to move alternates handling into the "files" backend. The series is a prerequisite for future ODB work, including pluggable backends and alternates-related fixes.

The core goal remains unchanged from v1: eliminate the conceptual mismatch where alternates were managed at the ODB source level, which caused performance regressions, complicated data structures (bitmaps, commit graphs), and blocked backend-agnostic extensions to `GIT_OBJECT_DIRECTORY` and `GIT_ALTERNATE_OBJECT_DIRECTORIES`. The v2 update addresses review feedback from Karthik Nayak, primarily clarifying the motivation in the first patch’s commit message. No technical changes were made to the code itself—this is a documentation-only reroll.

The series is built on `c46c1e3772` (start of the Git 2.98 cycle) and has minor merge conflicts with `seen`, as documented in the v1 cover letter. The changes touch 52 files, with the bulk of the work in `odb/source-files.c` (482 lines added) and `odb.c` (439 lines removed). Key symbols introduced include `struct odb_files_dir` (managing multiple object directories) and `odb_source_files_find_dir()` (a files-backend-specific replacement for `odb_find_source()`). The final patch (13/13) removes the now-unused `read_alternates` callback from the ODB source interface, completing the architectural shift.

The only unresolved loose end from v1—a potential inconsistency in the test helper `git_test_write_commit_graph_or_die()`—persists. Patrick dismissed Karthik’s concern about the function’s hard-coded path assumption, arguing it’s a test-suite hack and sufficient for its purpose. Karthik accepted this without further discussion, but the issue remains a minor risk for test portability. The series is otherwise technically complete, with all review feedback addressed.

This is a well-motivated refactoring with clear benefits for future ODB work. The size and scope (13 patches, 1,800+ lines changed) make it a heavy lift for reviewers, but the commit messages and cover letter are thorough. If you’re interested in ODB internals or alternates, this series is worth tracking—especially as a foundation for upcoming changes. The lack of deeper edge-case review (e.g., promisor remotes, linked-list invariants) suggests potential blind spots, but the architectural direction is sound.
