This thread is about a small but important test fix in Git’s SHA-256 transition effort. Patrick Steinhardt identified that a test in `t5004-archive-corner-cases.sh`—which extracts a ZIP file containing SHA-1 objects larger than 4GB—would fail in SHA-256 repositories. The fix is simple: add the `SHA1` prerequisite to the test to prevent it from running in SHA-256 mode, avoiding a latent CI breakage. This change is part of a larger 8-patch series addressing CI housekeeping, though the cover letter isn’t included here.

The patch itself is uncontroversial. It’s a one-line addition to the test’s prerequisites, aligning with the test’s existing design (which already restricts execution to specific environments like `EXPENSIVE` and `LONG_IS_64BIT`). The commit message clearly explains the context: the test requires SHA-1 objects, so it shouldn’t run in SHA-256 repositories. A typo in the Fedora CI job configuration (fixed in the next patch) would have exposed this issue once corrected. No behavioral changes outside the test suite are introduced, and no further discussion is expected beyond routine review. The fix is well-motivated and ready for merging.
