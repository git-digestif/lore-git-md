This is a **security-focused review** of Christian Noé Ramos López's report about SSH signing verification flaws in Git. Phillip Wood, a well-regarded reviewer with deep expertise in Git's signing and merge machinery, responds with a concise, practical assessment.

Phillip confirms both reported issues: (1) Git checks the `valid-before` timestamp in the allowed signers file against the committer date (which the signer controls), not an independent timestamp, and (2) a missing or misconfigured `gpg.ssh.revocationFile` emits a warning but fails open, allowing verification to proceed. He agrees with the severity of the revocation file flaw and endorses making it fail closed, aligning with OpenSSH's behavior. On the timestamp issue, he suggests tightening the documentation to clarify the current behavior (checking against committer date) rather than changing it, while noting that GPG signatures also suffer from timestamp spoofing.

The review is substantive but pragmatic, focusing on actionable fixes rather than architectural overhauls. Phillip's endorsement of failing closed on revocation file errors carries weight, given his track record of identifying subtle correctness issues in prior work (e.g., the status push-tracking and `git replay` series). His observation about GPG's similar timestamp vulnerability adds useful context, though it doesn't diminish the SSH backend's inconsistency. No patch is proposed yet, but the review signals clear next steps: a documentation update for `valid-before` and a behavioral change for revocation file handling. The thread remains open for further discussion on backward compatibility or alternative revocation mechanisms.
