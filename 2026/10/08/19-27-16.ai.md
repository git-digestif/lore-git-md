This is the first patch in a five-part documentation series that converts Git’s `BreakingChanges` document into a proper manpage (`gitbreaking-changes(7)`). The patch prepares the existing `BreakingChanges.adoc` file for manpage format by adding the required `NAME`, `SYNOPSIS`, and `DESCRIPTION` sections and demoting the "Introduction" section to second-level heading. The content itself remains unchanged; this is purely a structural transformation to meet manpage conventions.

The motivation is clear: the current `BreakingChanges` document is buried in the source tree and not accessible via `git help` or `man`, making it invisible to most users—precisely the audience that needs to know about upcoming breaking changes. This patch is the first step toward making the document discoverable alongside other Git documentation.

The changes are minimal and mechanical, touching only `Documentation/BreakingChanges.adoc`. The patch adds the necessary manpage boilerplate and adjusts section levels, but does not yet rename the file or integrate it into the build system (those steps come in later patches). The interdiff confirms that no unintended whitespace or content changes were introduced.

This patch is well-motivated and technically straightforward. It sets the stage for the rest of the series, which will complete the conversion and ensure the new manpage is properly built and linked. No new symbols, CLI options, or on-disk formats are introduced, and no test coverage is required.
