This is the first patch in Patrick Steinhardt’s 13-patch series refactoring the Git object database (ODB) to move alternates handling into the "files" backend. It is a preparatory refactoring that shifts responsibility for resolving packfile paths from `fill_oids_from_packs()` to its caller (`builtin/commit-graph.c`).

The patch addresses a conceptual mismatch where the commit-graph subsystem previously assumed packfile locations relative to an ODB source, tying it to the files backend’s implementation details. By requiring callers to pass fully resolved packfile paths, the change decouples the commit-graph logic from the ODB source, aligning with the series’ broader goal of making alternates a backend-specific concern. The diff is mechanical: `builtin/commit-graph.c` now constructs absolute paths for `--stdin-packs` input, while `commit-graph.c` removes its path-resolution logic and operates on the resolved paths directly.

No behavior changes are introduced—this is purely internal restructuring. The patch is well-motivated in the context of the series, though the commit message could better explain how this change enables later patches (e.g., patch 2/13’s decoupling of the commit-graph subsystem from `struct odb_source`). The test coverage for `--stdin-packs` in `t5318-commit-graph.sh` should suffice, but reviewers should verify that edge cases (e.g., symlinked object directories, non-default ODB configurations) remain unaffected.

This patch is a small but necessary step toward the series’ architectural goals. It is uncontroversial and unlikely to break existing functionality, but its value is only clear in the context of the full series. If you’re tracking the ODB refactoring effort, this is worth noting as the foundation for later changes.
