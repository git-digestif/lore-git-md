# Git mailing list daily digest for 2026/10/08

## Long threads

### http.sslVerifyStatus OCSP stapling verification

*Long thread (root 2026/08/11/17-02-00): 33 replies so far from 5 participants over 59 days; 1 message that day.*

Grayson Gordon's series adds an `http.sslVerifyStatus` boolean mapping to libcurl's `CURLOPT_SSL_VERIFYSTATUS`, so git requests and checks stapled OCSP responses; it defaults to off because enabling it blocks connections to servers that send no stapled response. Earlier, the topic was reverted out of `next` after SZEDER Gábor reported t5585 failures on a GnuTLS curl backend, and it was tentatively ejected from `seen` after bisecting linux-* CI timeouts to it. Today Junio C Hamano confirmed by testing the topic in isolation on top of Git 2.56 that it causes many linux-* jobs to time out after 6 hours; the linux-TEST-vars and linux32 failures are unrelated, caused by failing to download long-deprecated Ubuntu 20.04.

### fetch: avoid fetching every branch of a new remote in a shallow repo

*Long thread (root 2026/09/19/14-47-26): 26 replies so far from 4 participants over 20 days; 1 message that day.*

Harald Nordgren's v7 series adds `remote.<name>.refmap`, infers branches to fetch from a refmap-only remote, adds `git remote add --limited-fetch`, and defaults to `--limited-fetch` in shallow repositories. Today Junio C Hamano reviewed the v7 documentation and `do_fetch()` code: he asked that the docs state the inference mechanism (branches used as `@{upstream}` of local branches), called the `inferred_branches` variable misleadingly named, suggested placing the existing `remote.*.fetch` handling before the new inference code, proposed extracting a `collect_upstream_from_remote()` helper in remote.c, and suggested passing a `struct repository *` through callback data instead of hardcoding `the_repository`. He also reported that merging the series to `seen` breaks t5505 and t5586 through interactions with other topics and asked for help finding the cause.

### git-bisect-rebase for iterative rebases

*Long thread (root 2026/10/01/11-58-42): 22 replies so far from 6 participants over 8 days; 2 messages that day.*

Alejandro Colomar's `git-rebase-walk` idea evolved into `git-bisect-rebase`, a script that rebases a branch step by step onto progressively newer upstream commits using bisection. Today he implemented `--abort`, `--continue`, and `--quit` with semantics different from git-rebase(1): `--abort` returns to the original HEAD and cleans up temporary state, `--continue` restarts the whole bisect-rebase process, and `--quit` exits without moving HEAD or the branch so he can pause one branch, move descendants, then resume. He provided example command sequences for moving a tree of branches and a single branch, and corrected the tree-moving algorithm to use C instead of B in one `git rebase --onto` command.

### refs: run copy and rename through transactions

*Long thread (root 2026/09/19/13-33-44): 18 replies so far from 5 participants over 20 days; 9 messages that day.*

Maciej Ciemborowicz's four-patch series routes reference copy and rename through ordinary transactions so the reference-transaction hook can observe and reject the complete operation. Today he posted v4, rebased, fixing the v3 bug where `prepare_reflog_replacements()` overwrote a packed-refs preparation error -- the cause of the t0600/t5510 failures Junio C Hamano had reported; the full test suite passes on macOS/arm64 with both files and reftable backends. The thread also drew discussion of review etiquette: Patrick Steinhardt warned that posting new versions without replying to reviewers is a red flag, and Junio C Hamano said responses to vN reviews should come before v(N+1), with days rather than hours between rounds. Maciej laid out his AI-agent workflow and agreed that stating AI use upfront could be a rule.

### faster SHA-1 collision detection

*Long thread (root 2026/09/29/11-25-40): 14 replies so far from 6 participants over 10 days; 8 messages that day.*

Scott Chacon's four-patch series ports Sam Reis's sha1dc Rust crate approach to C, claiming roughly 2.7x faster hashing on a Xeon and 2.85x on an M5 Max. Today the discussion centered on licensing: D. Sebastian Thiel welcomed the speedup, and Sam Reis said he is happy to see the patch land.

## Notable threads

### SubmittingPatches: allow responsible AI assistance
Scott Chacon's RFC proposes moving Git's AI policy toward Linux's approach: allow reviewed AI-assisted work with disclosure rather than rejecting anything that looks AI-generated. Today he argued that DCO certification does not require knowing every LLM training source, citing Red Hat, Linux Foundation and SFC statements; Luca Milanesio countered that LLMs statistically blend copied code so the AI would be the author, and fully AI-generated contributions should be rejected; brian m. carlsson argued review is already the bottleneck and Git is not obligated to follow SFC guidance; D. Ben Knoble shared an "AI Pascal's wager" argument for rejecting AI-generated contributions for now.

### SSH signing: valid-before and revocationFile fail-open
Christian Noé Ramos López reported that git checks SSH signature `valid-before` against the committer/tagger date (which the signer controls) rather than actual signing time, so a backdated commit bypasses key expiry, and that a configured but missing `gpg.ssh.revocationFile` only warns while verification proceeds -- unlike ssh-keygen and sshd, which refuse. Phillip Wood agreed that failing when the revocation file is missing is the safer option and would welcome a documentation patch for `valid-before`, noting that GPG signature timestamps can also be faked.

### repack: don't lose objects to a ".keep" that appears mid-run
Qin ShiCheng's v3 five-patch series fixes a production data-loss bug where `git repack -d` deletes a pack whose objects were never copied because a `.keep` appeared between repack's and pack-objects' separate scans; patch 5/5 hands pack-objects repack's startup snapshot via `--keep-pack-from-file`. Today qeesung posted v3, moving kept-pack cache invalidation into `repo_invalidate_kept_pack_caches()` in packfile.c, and Junio C Hamano suggested waiting until the ps/odb-files-alternates topic solidifies before merging, asking how close it is to done.

### repack: do not rebuild packs on --dry-run
Siddharth Shrimali posted a patch fixing `git repack --drop-filtered --dry-run`, which despite its documentation rebuilt a promisor pack and, with `-d`, deleted old packs; the fix returns right after listing drop candidates and adds a test that the pack directory is unchanged. D. Ben Knoble reviewed it as making sense with a reasonable test, and Junio C Hamano called the finding "very interesting" and asked whether the behavior broke from the beginning or via unrelated changes, requesting a bisect in the commit message.

### fetch: commit references before backfilling tags
Karthik Nayak posted a patch to `builtin/fetch.c` committing the previous batched reference update and starting a new transaction before backfilling tags, fixing a shallow-fetch regression where the client reported no references in the 'have' section and the server sent all repository objects. The patch adds a regression test to `t/t5510-fetch.sh`; benchmarks show 84.4 ms versus 1.468 s without batched updates, though slightly slower than master due to two transactions.
