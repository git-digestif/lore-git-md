Thread identity
Subject: SSH signing verification flaws (time-of-signature confusion, revocation file fails open)
Series version: standalone security bug report (no patch series)
Originating author: Christian Noé Ramos López <chris@nortesoftware.dev>
Thread type: security bug report

Core problem or goal
Git’s SSH signing verification had two critical flaws: (1) it checked the `valid-before` timestamp in the allowed signers file against the committer date (which the signer controls), allowing backdated commits to bypass key expiration, and (2) if the `gpg.ssh.revocationFile` was configured but missing, unreadable, or a directory, Git warned and proceeded as if no revocation file existed, failing open instead of failing closed. The GPG backend correctly rejected backdated signatures (using the signature timestamp) and failed closed on revocation file issues.

Current status
Both reported flaws are now addressed. The first issue (timestamp confusion) was resolved by a documentation patch from Christian Noé Ramos López, which updated the `gpg.ssh.allowedSignersFile` man page to clarify that `valid-before`/`valid-after` checks use the committer or tagger date (not the signature timestamp) and warned that these checks are only trustworthy if the key has never leaked. The patch carried `Helped-by` trailers from Phillip Wood and Patrick Steinhardt. The second issue (revocation file fails open) is now fixed by a security bugfix patch from Christian, which makes Git fail closed when the revocation file is configured but missing or unreadable. The patch adds test coverage for the revocation file logic (previously untested) and documents the new behavior in `Documentation/config/gpg.adoc`. Users can override the default fail-closed behavior by prefixing the revocation file path with Git’s `:(optional)` pathname syntax. The patch is ready for review and likely to land quickly given the prior discussion and clear security motivation.

Key technical details
- Subsystem: SSH signing verification (`gpg-interface.c`, `gpg-ssh.c`)
- Config keys: `gpg.ssh.revocationFile`, `gpg.ssh.allowedSignersFile`
- Symbols: `%G?` status codes (SSH-specific), `valid-before`/`valid-after` timestamp handling, `:(optional)` pathname prefix
- Behavior changes:
  - Revocation file errors now fail verification by default (was warn-and-continue); optional override via `:(optional)` prefix.
  - Documentation updated to clarify that `valid-before`/`valid-after` checks use the committer/tagger date (not the signature timestamp) and that these checks are only trustworthy for keys that have never leaked. Also fixes a typo ("OpensSSH" → "OpenSSH").
- Test coverage: added four new test cases in `t/t7528-signed-commit-ssh.sh` covering revoked keys, missing files, and the `:(optional)` escape hatch.

Open questions and loose ends
- Whether Git will support additional revocation mechanisms (e.g., OpenSSH’s `KRL` format) remains an open question, but this is outside the scope of the current fixes.
