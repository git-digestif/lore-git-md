Thread identity
Subject: SSH signing verification flaws (time-of-signature confusion, revocation file fails open)
Series version: standalone security bug report (no patch series)
Originating author: Christian Noé Ramos López <chris@nortesoftware.dev>
Thread type: security bug report

Core problem or goal
Git’s SSH signing verification had two critical flaws: (1) it checked the `valid-before` timestamp in the allowed signers file against the committer date (which the signer controls), allowing backdated commits to bypass key expiration, and (2) if the `gpg.ssh.revocationFile` was configured but missing, unreadable, or a directory, Git warned and proceeded as if no revocation file existed, failing open instead of failing closed. The GPG backend correctly rejected backdated signatures (using the signature timestamp) and failed closed on revocation file issues.

Current status
Both reported flaws are now fully addressed. The revocation file flaw (fails open) is resolved by a **v2 security bugfix patch** that incorporates Junio C Hamano’s feedback on the error-handling flow, ensuring signature information is displayed consistently whether the revocation file is missing or an unknown key is encountered. The patch is technically ready for integration, pending only a procedural correction: Junio requests that future rerolls be sent as direct replies to the prior version to maintain proper threading for automation. The timestamp confusion flaw is addressed by a **finalized documentation patch** clarifying in `gpg.adoc` that Git uses the committer or tagger date for `valid-before`/`valid-after` checks and explicitly notes the lack of security guarantees due to signer-controlled timestamps. Both patches are ready for integration but may be held together to avoid splitting security fixes across releases.

Key technical details
- Subsystem: SSH signing verification (`gpg-interface.c`, `gpg-ssh.c`)
- Config keys: `gpg.ssh.revocationFile`, `gpg.ssh.allowedSignersFile`
- Symbols: `%G?` status codes (SSH-specific), `valid-before`/`valid-after` timestamp handling, `:(optional)` pathname prefix
- Behavior changes:
  - Revocation file errors now fail verification by default (was warn-and-continue); optional override via `:(optional)` prefix.
  - Error-handling flow ensures signature information is displayed even when the revocation file is missing, aligning with behavior for unknown keys.
  - Documentation patch clarifies that `valid-before`/`valid-after` checks use the committer or tagger date (not the signature timestamp) and explicitly states that this does not provide security guarantees because the timestamp can be chosen arbitrarily by the signer. Also fixes a typo ("OpensSSH" → "OpenSSH").
- Test coverage: added four new test cases in `t/t7528-signed-commit-ssh.sh` covering revoked keys, missing files, and the `:(optional)` escape hatch.
- Files modified: `gpg-interface.c`, `Documentation/gpg.adoc`

Open questions and loose ends
- Whether Git will support additional revocation mechanisms (e.g., OpenSSH’s `KRL` format) remains an open question, but this is outside the scope of the current fixes.
- Junio’s procedural note about patch threading is noted; no further action is required beyond awareness for future submissions.
