Thread identity
Subject: SSH signing verification flaws (time-of-signature confusion, revocation file fails open)
Series version: standalone security bug report (no patch series)
Originating author: Christian Noé Ramos López <chris@nortesoftware.dev>
Thread type: security bug report

Core problem or goal
Git’s SSH signing verification has two critical flaws: (1) it checks the `valid-before` timestamp in the allowed signers file against the committer date (which the signer controls), allowing backdated commits to bypass key expiration, and (2) if the `gpg.ssh.revocationFile` is configured but missing, unreadable, or a directory, Git warns and proceeds as if no revocation file exists, failing open instead of failing closed. The GPG backend correctly rejects backdated signatures and fails closed on revocation file issues.

Current status
Reported; no patch yet. The author recommends either documenting the current `valid-before` behavior (checking against committer date) or changing it to match GPG (checking against an independent timestamp), and making a missing/broken revocation file fail verification. The flaws are demonstrated with test cases showing `%G?` status codes and merge outcomes.

Key technical details
- Subsystem: SSH signing verification (`gpg-interface.c`, `gpg-ssh.c`)
- Config keys: `gpg.ssh.revocationFile`, `gpg.ssh.allowedSignersFile`
- Symbols: `%G?` status codes (SSH-specific), `valid-before` timestamp handling
- Behavior change: revocation file errors now fail verification (was warn-and-continue)
- Test coverage: none for revocation file logic; new test cases provided in the report

Open questions and loose ends
- Should `valid-before` be checked against committer date (current behavior) or an independent timestamp (GPG behavior)?
- Are there backward-compatibility concerns with making revocation file errors fatal?
- Is there a need to support other revocation mechanisms (e.g., OpenSSH’s `KRL` format)?
- The report notes the revocation file logic is entirely untested; test suite coverage is needed.
