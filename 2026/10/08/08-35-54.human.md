This is the fourth patch in Patrick Steinhardt’s 13-patch series refactoring Git’s object database (ODB) to move alternates handling into the "files" backend. The patch adapts `odb_for_each_alternate()` to iterate over `struct odb_files_dir` (a new structure managing object directories) instead of `struct odb_source`, aligning with the series’ goal of making alternates a backend-specific implementation detail.

The changes are mechanical but foundational. The patch updates three callers (`builtin/count-objects.c`, `builtin/submodule--helper.c`, and `diagnose.c`) to use the new `abspath` field of `struct odb_files_dir` instead of the deprecated `path` field from `struct odb_source`. It also refactors the `refs_from_alternate_cb()` helper in `odb.c` to explicitly pass the repository context (previously accessed via `alternate->odb->repo`), compensating for the loss of the `odb_source` struct’s implicit repository reference. The `alternate_refs_data` struct gains a `repo` field to carry this context, and the callback type `odb_for_each_alternate_fn` is updated to take `struct odb_files_dir *` instead of `struct odb_source *`.

Karthik Nayak’s review of this patch was surface-level, confirming the type conversion but not assessing deeper correctness or edge cases (e.g., linked-list traversal order, promisor remotes, or path resolution in non-default ODB configurations). The patch itself is straightforward, but its implications ripple through the series: later patches (notably 12/13) will rely on this refactoring to relocate alternates handling entirely into the files backend. If you’re tracking the ODB refactoring effort, this patch is a key stepping stone—though the real architectural shift comes later in the series. The lack of substantive review suggests potential blind spots, but the changes are well-explained and align with the series’ direction.
