Subject: [PATCH 0/8] ci: housekeeping updates for CI configurations
Series version: v3 (reroll addressing Junio C Hamano, SZEDER Gábor, Jeff King, and now minor pattern-future-proofing feedback)
Originating author: Patrick Steinhardt
Thread type: patch series (CI/build system maintenance)

Core problem or goal
Modernize and simplify Git's CI configurations by removing outdated dependencies (EOL Docker images, Python 2 coverage), eliminating redundant or unused jobs, and updating supporting scripts. The series targets GitHub Actions and GitLab CI workflows, along with minor test adjustments, to reduce complexity and improve reliability without introducing new functionality or behavioral changes. The scope includes a resolved trade-off between reftable's foreign-SCM interoperability coverage and SHA-256 + reftable coverage, following Junio C Hamano's review of v1, and a now-resolved naming dispute over the `linux-TEST-vars` job rename to `linux-feature-testbed`.

Current status
Under review (v3 posted). The series consists of 8 patches touching `.github/workflows/main.yml`, `.gitlab-ci.yml`, `ci/install-dependencies.sh`, `ci/lib.sh`, `ci/run-build-and-tests.sh`, and `t/t5004-archive-corner-cases.sh`. Key changes from v2:
- **Naming resolution**: The `linux-TEST-vars` job is renamed to `linux-feature-testbed` (Junio C Hamano's preferred choice among 14 alternatives), resolving the dispute raised by SZEDER Gábor in v2. The rename is purely mechanical (three one-line substitutions in `.github/workflows/main.yml`, `.gitlab-ci.yml`, and `ci/run-build-and-tests.sh`) with no behavioral impact.
- **Reftable coverage**: The `linux-reftable-leaks` job is repurposed as `linux-reftable-sha256` to test reftable with SHA-256 (`GIT_TEST_DEFAULT_HASH=sha256` and `GIT_TEST_DEFAULT_REF_STORAGE_FORMAT=reftable`), while the `linux-reftable` job preserves foreign-SCM interoperability coverage (CVS, SVN, Perforce). Junio has explicitly endorsed this trade-off.
- **Dead code removal**: Patch 3/8 deletes unused logic in `ci/run-build-and-tests.sh` left behind by the removed `linux-clang` job (commit d88d727143, 2023-06-01). The four-line deletion (`NO_RUST=UnfortunatelyYes` and `GIT_TEST_DEFAULT_HASH=sha1`) is purely mechanical and has no behavioral impact.
- **Python 2 removal**: Patch 7/8 hard-codes `python3` in `ci/install-dependencies.sh` and `ci/lib.sh`, removing conditional Python 2 logic now that Ubuntu 20.04 jobs are gone. The change deletes eleven lines and adds two, with no behavioral impact beyond eliminating the no-longer-possible Python 2 code path. The rationale is that Python 2 reached end-of-life in 2020, and none of the current CI images package it.
- **Typo fix and future-proofing**: Patch 2/8 corrects `fedora-breaking-changes-musl` to `fedora-breaking-changes-meson` in `ci/run-build-and-tests.sh`, restoring the `WITH_BREAKING_CHANGES` flag for the Fedora Meson job. Jeff King (Peff) suggests broadening the `case` statement pattern to `*breaking-changes*` to guard against similar typos in future job additions. This is a **low-weight, surface-level review** that does not alter the patch’s intent or behavior.
- **32-bit platform update**: Patch 4/8 replaces `i386/ubuntu:20.04` with `i386/debian:latest` for the `linux32` job, ensuring support until at least 2030 and simplifying dependency logic. The change removes obsolete conditional logic in `ci/install-dependencies.sh` (previously handling `i386/ubuntu` separately for SVN dependencies) and updates the `CI_OS_NAME` check in `ci/lib.sh` to recognize the new image. **New open question**: Jeff King raises a **substantive technical concern** about whether the new `i386/debian:latest` image provides equivalent support for Icelandic locale tests (`is_IS`), which were previously enabled by `language-pack-is` in the Ubuntu image. If Debian lacks this package, the `linux32` job could silently drop coverage for gettext-related edge cases (e.g., non-ASCII commit messages or error messages).
- **Image updates**: Patch 6/8 updates the `linux-feature-testbed` job to use `ubuntu:latest` (dropping the explicit `gcc-8` dependency), while other jobs (AlmaLinux 8, Debian 12) retain coverage for older distributions. The `ubuntu:latest` tag is a rolling LTS reference, ensuring stability and eliminating the need for manual updates.
- **Test design feedback**: Patch 1/8, which adds the `SHA1` prerequisite to `t/t5004-archive-corner-cases.sh`, has drawn **substantive technical review** from Jeff King (Peff). Peff proposes an alternative approach: making the test self-contained by creating a temporary SHA-1 repository (`git init --object-format=sha1`) for the test’s duration, allowing it to run in any environment that meets the other prerequisites (`EXPENSIVE`, `LONG_IS_64BIT`, `UNZIP`, etc.). This would preserve test coverage without relying on a dedicated SHA-1 CI job, addressing concerns about the test’s long-term viability as Git transitions to SHA-256 by default.
- Net effect: 20 insertions, 39 deletions, reducing CI complexity while maintaining or improving coverage. All changes are mechanical and pass linked CI runs (GitLab, GitHub).

Key technical details
Files/subsystems: CI configurations (GitHub Actions, GitLab CI), supporting scripts (`ci/`), and one test file (`t/t5004-archive-corner-cases.sh`).
Symbols/configs: Job names (`linux-TEST-vars` -> `linux-feature-testbed`, `linux-reftable-leaks` -> `linux-reftable-sha256`), Docker images (`i386/ubuntu:20.04` -> `i386/debian:latest`, `ubuntu:20.04` -> `ubuntu:latest`), scripts (`ci/lib.sh`, `ci/install-dependencies.sh`, `ci/run-build-and-tests.sh`), Python-related variables (`PYTHON_PACKAGE` removed, `PYTHON_PATH` hard-coded to `/usr/bin/python3`), test prerequisites (`SHA1` added to `t/t5004`), the `WITH_BREAKING_CHANGES` flag in `ci/run-build-and-tests.sh`, and the `LANGUAGES` variable in `ci/install-dependencies.sh` (now relevant to the `linux32` job’s Icelandic locale support). The `linux-feature-testbed` job now uses `ubuntu:latest` and the system-provided GCC version. Patch 3/8 removes dead code in `ci/run-build-and-tests.sh` that set `NO_RUST=UnfortunatelyYes` and `GIT_TEST_DEFAULT_HASH=sha1` for the removed `linux-clang` job. Patch 7/8 hard-codes `python3` in `ci/install-dependencies.sh` (replacing `PYTHON_PACKAGE`) and simplifies `ci/lib.sh` by removing the Ubuntu-20.04-specific branch for `MAKEFLAGS`. Patch 8/8 introduces `GIT_TEST_DEFAULT_HASH=sha256` and `GIT_TEST_DEFAULT_REF_STORAGE_FORMAT=reftable` for the `linux-reftable-sha256` job. The typo fix (s/musl/meson/) in patch 2/8 restores the `WITH_BREAKING_CHANGES` flag for the Fedora Meson job, which is now preemptively supported by the `SHA1` prerequisite in patch 1/8. Jeff King’s future-proofing suggestion for patch 2/8 proposes using `*breaking-changes*` in the `case` statement to match any job name containing that substring. The test in `t/t5004-archive-corner-cases.sh` verifies Git’s ability to handle ZIP archives with objects larger than 4GB, requiring 64-bit `long` support, unzip with ZIP64 extensions, and the `EXPENSIVE` prerequisite; currently, only the Fedora CI job meets these requirements.

Open questions and loose ends
- **Test design**: Jeff King’s feedback on patch 1/8 raises a **substantive open question** about the long-term maintainability of the `SHA1` prerequisite approach. His proposed alternative (self-contained SHA-1 repository for the test) would preserve coverage without relying on a dedicated SHA-1 CI job, but may increase test complexity. This is likely to be a point of discussion, as it touches on test design philosophy (self-contained vs. environment-dependent) and the implications of Git’s SHA-256 transition.
- **Coverage trade-offs**: The reftable/SHA-256 split (patch 8/8) and the removal of GCC 8 testing in `linux-feature-testbed` (patch 6/8) are explicitly endorsed by Junio but may still draw feedback from contributors invested in reftable (Patrick Steinhardt, Karthik Nayak) or SHA-256 (brian m. carlson).
- **Python 2 removal**: While obsolete, the hard-coded `python3` (patch 7/8) may affect legacy workflows not covered by current CI jobs, though none are known.
- **Breaking changes job**: The restored `fedora-breaking-changes-meson` job may now expose latent test failures (e.g., the SHA-1-specific test in `t/t5004` addressed by patch 1/8) or serve as a foundation for future experimental builds.
- **Pattern future-proofing**: Jeff King’s **low-weight, surface-level review** of patch 2/8 suggests broadening the `case` statement pattern to `*breaking-changes*` to guard against similar typos in future job additions. This is a minor, mechanical suggestion that does not alter the patch’s intent or behavior but may be adopted in a future reroll.
- **Icelandic locale support**: Jeff King’s **substantive technical review** of patch 4/8 raises a new open question about whether the `i386/debian:latest` image provides equivalent support for Icelandic locale tests (`is_IS`) as the previous `i386/ubuntu:20.04` image. If Debian lacks the `language-pack-is` package, the `linux32` job could silently drop coverage for gettext-related edge cases. Resolution may require either no action (if Debian includes the package by default) or a follow-up patch to explicitly add the Icelandic locale dependency to the `debian-*` case in `ci/install-dependencies.sh`.
