Subject: [PATCH 0/8] ci: housekeeping updates for CI configurations
Series version: v2 (reroll addressing Junio C Hamano and Todd Zullinger feedback)
Originating author: Patrick Steinhardt
Thread type: patch series (CI/build system maintenance)

Core problem or goal
Modernize and simplify Git's CI configurations by removing outdated dependencies (EOL Docker images, Python 2 coverage), eliminating redundant or unused jobs, and updating supporting scripts. The series targets GitHub Actions and GitLab CI workflows, along with minor test adjustments, to reduce complexity and improve reliability without introducing new functionality or behavioral changes. The scope now includes a resolved trade-off between reftable's foreign-SCM interoperability coverage and SHA-256 + reftable coverage, following Junio C Hamano's review of v1.

Current status
Under review (v2 submission). The series consists of 8 patches touching `.github/workflows/main.yml`, `.gitlab-ci.yml`, `ci/install-dependencies.sh`, `ci/lib.sh`, `ci/run-build-and-tests.sh`, and `t/t5004-archive-corner-cases.sh`. Key changes from v1:
- **Patch 8/8 (reworked)**: Instead of removing the `linux-reftable` job, the `linux-reftable-leaks` job is repurposed to test reftable with SHA-256, preserving foreign-SCM interoperability coverage (CVS, SVN, Perforce) while adding SHA-256 coverage. This addresses Junio's concern about regression in test coverage.
- **Patch 2/8 (new fix)**: Corrects a typo in `ci/run-build-and-tests.sh` where `fedora-breaking-changes-musl` was mistakenly checked instead of `fedora-breaking-changes-meson`, restoring the `WITH_BREAKING_CHANGES` flag for the Fedora Meson job.
- **Patch 3/8 (newly summarized)**: Removes dead code in `ci/run-build-and-tests.sh` left behind when the `linux-clang` job was deleted in commit d88d727143 (2023-06-01). The patch deletes four lines that set `NO_RUST=UnfortunatelyYes` and `GIT_TEST_DEFAULT_HASH=sha1` for the now-absent job. No behavior change; purely cleanup of unused logic.
- **Patch 4/8 (updated)**: Updates the `linux32` job to use `i386/debian:latest` instead of the unsupported `i386/ubuntu:20.04`, ensuring 32-bit platform coverage until at least 2030. The patch removes obsolete Ubuntu-specific logic in `ci/install-dependencies.sh` (handling missing `libsvn-perl` on 32-bit Ubuntu) and updates `ci/lib.sh` to recognize the new image format. The commit message now clearly states Debian's 32-bit Docker image support timeline (until at least 2030) and confirms that 32-bit Docker images are still being released despite Debian's reduced 32-bit support.
- **Patch 5/8 (newly summarized)**: Renames the `linux-TEST-vars` job to `linux-exotic` in `.github/workflows/main.yml`, `.gitlab-ci.yml`, and `ci/run-build-and-tests.sh`. The job remains unchanged, exercising Git with the same non-default "exotic" options (`OPENSSL_SHA1_UNSAFE`, `GIT_TEST_SPLIT_INDEX`, `GIT_TEST_FULL_IN_PACK_ARRAY`, etc.). The rename is purely mechanical (three one-line substitutions) with no behavioral impact; the new name is clearer and avoids awkward upper-casing.
- Commit messages improved for clarity, particularly in patch 4/8 (Ubuntu 32-bit support timeline) and patch 1/8 (grammatical fixes).
- Net effect: 19 insertions, 39 deletions, reducing CI complexity while maintaining or improving coverage.

Other changes remain unchanged from v1:
- Dropping the unused "linux-clang" job logic (patch 3/8 deletes dead code in `ci/run-build-and-tests.sh` left behind by commit d88d727143).
- Updating the `linux-exotic` job to use `ubuntu:latest` (patch 6/8), replacing the EOL Ubuntu 20.04 image and removing the explicit `gcc-8` dependency.
- Removing Python 2 coverage (patch 7/8) by deleting conditional logic in `ci/lib.sh` and `ci/install-dependencies.sh` that set `PYTHON_PACKAGE=python2` for Ubuntu 20.04, replacing it with unconditional `PYTHON_PATH=/usr/bin/python3`.
- Adding the `SHA1` prerequisite to a test in `t/t5004-archive-corner-cases.sh` (patch 1/8) to skip it in SHA-256 repositories.
