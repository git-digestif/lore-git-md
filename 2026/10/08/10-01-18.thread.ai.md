Subject: [PATCH 0/8] ci: housekeeping updates for CI configurations
Series version: v3 (reroll addressing Junio C Hamano and SZEDER Gábor feedback; v2 introduced contested rename)
Originating author: Patrick Steinhardt
Thread type: patch series (CI/build system maintenance)

Core problem or goal
Modernize and simplify Git's CI configurations by removing outdated dependencies (EOL Docker images, Python 2 coverage), eliminating redundant or unused jobs, and updating supporting scripts. The series targets GitHub Actions and GitLab CI workflows, along with minor test adjustments, to reduce complexity and improve reliability without introducing new functionality or behavioral changes. The scope includes a resolved trade-off between reftable's foreign-SCM interoperability coverage and SHA-256 + reftable coverage, following Junio C Hamano's review of v1, and a now-resolved naming dispute over the `linux-TEST-vars` job rename to `linux-feature-testbed`.

Current status
Under review (v3 posted). The series consists of 8 patches touching `.github/workflows/main.yml`, `.gitlab-ci.yml`, `ci/install-dependencies.sh`, `ci/lib.sh`, `ci/run-build-and-tests.sh`, and `t/t5004-archive-corner-cases.sh`. Key changes from v2:
- **Naming resolution**: The `linux-TEST-vars` job is renamed to `linux-feature-testbed` (Junio C Hamano's preferred choice among 14 alternatives), resolving the dispute raised by SZEDER Gábor in v2. The rename is purely mechanical (three one-line substitutions) with no behavioral impact.
- **Reftable coverage**: The `linux-reftable-leaks` job is repurposed as `linux-reftable-sha256` to test reftable with SHA-256 (`GIT_TEST_DEFAULT_HASH=sha256` and `GIT_TEST_DEFAULT_REF_STORAGE_FORMAT=reftable`), while the `linux-reftable` job preserves foreign-SCM interoperability coverage (CVS, SVN, Perforce). Junio has explicitly endorsed this trade-off.
- **Typo fix**: Patch 2/8 corrects `fedora-breaking-changes-musl` to `fedora-breaking-changes-meson` in `ci/run-build-and-tests.sh`, restoring the `WITH_BREAKING_CHANGES` flag for the Fedora Meson job. This fix is now preemptively supported by patch 1/8, which adds the `SHA1` prerequisite to `t/t5004-archive-corner-cases.sh` to skip a SHA-1-specific test in SHA-256 repositories. The typo had silently disabled the job's experimental build mode since its introduction.
- **Dead code removal**: Patch 3/8 deletes unused logic in `ci/run-build-and-tests.sh` left behind by the removed `linux-clang` job (commit d88d727143, 2023-06-01).
- **32-bit platform update**: Patch 4/8 replaces `i386/ubuntu:20.04` with `i386/debian:latest` for the `linux32` job, ensuring support until at least 2030 and simplifying dependency logic.
- **Python 2 removal**: Patch 7/8 hard-codes `python3` in `ci/install-dependencies.sh` and `ci/lib.sh`, removing conditional Python 2 logic now that Ubuntu 20.04 jobs are gone.
- **Image updates**: Patch 6/8 updates the `linux-feature-testbed` job to use `ubuntu:latest` (dropping the explicit `gcc-8` dependency), while other jobs (AlmaLinux 8, Debian 12) retain coverage for older distributions.
- Net effect: 20 insertions, 39 deletions, reducing CI complexity while maintaining or improving coverage. All changes are mechanical and pass linked CI runs (GitLab, GitHub).

Key technical details
Files/subsystems: CI configurations (GitHub Actions, GitLab CI), supporting scripts (`ci/`), and one test file (`t/t5004-archive-corner-cases.sh`).
Symbols/configs: Job names (`linux-TEST-vars` -> `linux-feature-testbed`, `linux-reftable-leaks` -> `linux-reftable-sha256`), Docker images (`i386/ubuntu:20.04` -> `i386/debian:latest`, `ubuntu:20.04` -> `ubuntu:latest`), scripts (`ci/lib.sh`, `ci/install-dependencies.sh`, `ci/run-build-and-tests.sh`), Python-related variables (`PYTHON_PACKAGE` removed, `PYTHON_PATH` hard-coded to `/usr/bin/python3`), and test prerequisites (`SHA1` added to `t/t5004`). The `linux-feature-testbed` job now uses `ubuntu:latest` and the system-provided GCC version. Patch 3/8 removes dead code in `ci/run-build-and-tests.sh` that set `NO_RUST=UnfortunatelyYes` and `GIT_TEST_DEFAULT_HASH=sha1` for the removed `linux-clang` job. Patch 8/8 introduces `GIT_TEST_DEFAULT_HASH=sha256` and `GIT_TEST_DEFAULT_REF_STORAGE_FORMAT=reftable` for the `linux-reftable-sha256` job. The typo fix (s/musl/meson/) in patch 2/8 restores the `WITH_BREAKING_CHANGES` flag for the Fedora Meson job, which is now preemptively supported by the `SHA1` prerequisite in patch 1/8. The test in `t/t5004-archive-corner-cases.sh` verifies Git’s ability to handle ZIP archives with objects larger than 4GB, requiring 64-bit `long` support, unzip with ZIP64 extensions, and the `EXPENSIVE` prerequisite; currently, only the Fedora CI job meets these requirements.

Open questions and loose ends
- **Coverage trade-offs**: The reftable/SHA-256 split (patch 8/8) and the removal of GCC 8 testing in `linux-feature-testbed` (patch 6/8) are explicitly endorsed by Junio but may still draw feedback from contributors invested in reftable (Patrick Steinhardt, Karthik Nayak) or SHA-256 (brian m. carlson).
- **Python 2 removal**: While obsolete, the hard-coded `python3` (patch 7/8) may affect legacy workflows not covered by current CI jobs.
- **Breaking changes job**: The restored `fedora-breaking-changes-meson` job may now expose latent test failures (e.g., the SHA-1-specific test in `t/t5004` addressed by patch 1/8) or serve as a foundation for future experimental builds.
