Subject: [PATCH 0/8] ci: housekeeping updates for CI configurations
Series version: v2 (reroll addressing Junio C Hamano, Todd Zullinger, and SZEDER Gábor feedback)
Originating author: Patrick Steinhardt
Thread type: patch series (CI/build system maintenance)

Core problem or goal
Modernize and simplify Git's CI configurations by removing outdated dependencies (EOL Docker images, Python 2 coverage), eliminating redundant or unused jobs, and updating supporting scripts. The series targets GitHub Actions and GitLab CI workflows, along with minor test adjustments, to reduce complexity and improve reliability without introducing new functionality or behavioral changes. The scope now includes a resolved trade-off between reftable's foreign-SCM interoperability coverage and SHA-256 + reftable coverage, following Junio C Hamano's review of v1, and a naming dispute over the `linux-TEST-vars` job rename.

Current status
Under review (v2 submission). The series consists of 8 patches touching `.github/workflows/main.yml`, `.gitlab-ci.yml`, `ci/install-dependencies.sh`, `ci/lib.sh`, `ci/run-build-and-tests.sh`, and `t/t5004-archive-corner-cases.sh`. Key changes from v1:
- **Patch 8/8 (reworked)**: The `linux-reftable-leaks` job is renamed to `linux-reftable-sha256` and repurposed to test reftable with SHA-256 by setting `GIT_TEST_DEFAULT_HASH=sha256` and `GIT_TEST_DEFAULT_REF_STORAGE_FORMAT=reftable` in `ci/run-build-and-tests.sh`. The original `linux-reftable` job is preserved, maintaining foreign-SCM interoperability coverage (CVS, SVN, Perforce) while adding SHA-256 coverage. This resolves Junio's concern about regression in test coverage.
- **Patch 2/8 (new fix)**: Corrects a typo in `ci/run-build-and-tests.sh` where `fedora-breaking-changes-musl` was mistakenly checked instead of `fedora-breaking-changes-meson`, restoring the `WITH_BREAKING_CHANGES` flag for the Fedora Meson job.
- **Patch 3/8 (newly summarized)**: Removes dead code in `ci/run-build-and-tests.sh` left behind when the `linux-clang` job was deleted in commit d88d727143 (2023-06-01). The patch deletes four lines that set `NO_RUST=UnfortunatelyYes` and `GIT_TEST_DEFAULT_HASH=sha1` for the now-absent job. No behavior change; purely cleanup of unused logic.
- **Patch 4/8 (updated)**: Updates the `linux32` job to use `i386/debian:latest` instead of the unsupported `i386/ubuntu:20.04`, ensuring 32-bit platform coverage until at least 2030. The patch removes obsolete Ubuntu-specific logic in `ci/install-dependencies.sh` (handling missing `libsvn-perl` on 32-bit Ubuntu) and updates `ci/lib.sh` to recognize the new image format. The commit message now clearly states Debian's 32-bit Docker image support timeline (until at least 2030) and confirms that 32-bit Docker images are still being released despite Debian's reduced 32-bit support.
- **Patch 5/8 (contested)**: Renames the `linux-TEST-vars` job to `linux-exotic` in `.github/workflows/main.yml`, `.gitlab-ci.yml`, and `ci/run-build-and-tests.sh`. The job remains unchanged, exercising Git with the same non-default "exotic" options (`OPENSSL_SHA1_UNSAFE`, `GIT_TEST_SPLIT_INDEX`, `GIT_TEST_FULL_IN_PACK_ARRAY`, etc.). The rename is purely mechanical (three one-line substitutions) with no behavioral impact. SZEDER Gábor objects to the new name as misleading, arguing that `linux-exotic` suggests an exotic platform rather than a job testing non-default Git options. The original name (`linux-TEST-vars`) is functional and unambiguous, while the proposed replacement may require rethinking if others share Gábor's concern.
- **Patch 6/8 (updated)**: Updates the `linux-exotic` job to use `ubuntu:latest` instead of the EOL `ubuntu:20.04`, removing the explicit `gcc-8` dependency. The change is mechanical: `.github/workflows/main.yml` and `.gitlab-ci.yml` each drop three lines (image tag and `cc_package`/`CC_PACKAGE` specification) and add one (new image tag). The commit message explains that `ubuntu:latest` always points to the most recent Ubuntu LTS release, preserving test coverage for a supported platform while eliminating the need for manual updates. It also acknowledges the trade-off: the job no longer tests with GCC 8, but other CI jobs (e.g., AlmaLinux 8, Debian 12) still cover older distributions.
- **Patch 7/8 (newly summarized)**: Removes Python 2 support by hard-coding `python3` in `ci/install-dependencies.sh` and `ci/lib.sh`. The patch deletes conditional logic that set `PYTHON_PACKAGE=python2` for Ubuntu 20.04 and unconditionally sets `PYTHON_PATH` to `/usr/bin/python3`. This cleanup became possible after the last Ubuntu 20.04 job was removed in an earlier patch. The rationale is that Python 2 reached end-of-life in 2020, and none of the current CI distros still package it.
- Commit messages improved for clarity, particularly in patch 4/8 (Ubuntu 32-bit support timeline) and patch 1/8 (grammatical fixes).
- Net effect: 19 insertions, 39 deletions, reducing CI complexity while maintaining or improving coverage.

The `linux-exotic` job now uses `ubuntu:latest` and the system-provided GCC version instead of `gcc-8`. Patch 3/8 removes dead code in `ci/run-build-and-tests.sh` that set `NO_RUST=UnfortunatelyYes` and `GIT_TEST_DEFAULT_HASH=sha1` for the now-removed `linux-clang` job. Patch 8/8 introduces environment variables `GIT_TEST_DEFAULT_HASH=sha256` and `GIT_TEST_DEFAULT_REF_STORAGE_FORMAT=reftable` for the new `linux-reftable-sha256` job.
Behavior: No user-visible changes; internal CI reliability improvements only. The typo fix in `ci/run-build-and-tests.sh` (s/musl/meson/) restores the intended `WITH_BREAKING_CHANGES` flag for the Fedora Meson job. Patch 3/8 removes dead code from the same script, aligning with the earlier removal of the `linux-clang` job. Patch 4/8 replaces the EOL `i386/ubuntu:20.04` image with `i386/debian:latest`, simplifying dependency installation logic in `ci/install-dependencies.sh` (removing Ubuntu-specific `libsvn-perl` handling). Patch 5/8 renames the `linux-TEST-vars` job to `linux-exotic` without altering its logic or options; the rename is contested. Patch 6/8 updates the `linux-exotic` job to use `ubuntu:latest`, removing the explicit `gcc-8` dependency. Patch 7/8 removes Python 2 support by hard-coding `python3` and deleting conditional logic. Patch 8/8 repurposes the `linux-reftable-leaks` job to test reftable with SHA-256, preserving foreign-SCM interoperability coverage in the `linux-reftable` job.
Test coverage: Minor adjustment to `t/t5004-archive-corner-cases.sh` to skip a SHA-1-specific test in SHA-256 repositories. Reftable test coverage is now split: the `linux-reftable` job continues to exercise foreign-SCM interoperability (CVS, SVN, Perforce), while the `linux-reftable-sha256` job tests reftable with SHA-256.

Open questions and loose ends
- **Naming dispute for `linux-TEST-vars` job**: SZEDER Gábor objects to the rename to `linux-exotic`, arguing that the new name is misleading and actively worse than the original. The original name (`linux-TEST-vars`) clearly signals its purpose (setting `GIT_TEST_*` variables), while `linux-exotic` suggests an exotic platform rather than a job exercising non-default Git options. This may require broader discussion or a revised name if others share Gábor's concern.
- **SHA-256 vs. foreign-SCM coverage trade-off**: While patch 8/8 resolves the immediate regression flagged by Junio, the decision to prioritize SHA-256 coverage in the `linux-reftable-sha256` job may still require broader discussion. Contributors invested in reftable (Patrick Steinhardt, Karthik Nayak) or SHA-256 (brian m. carlson) may weigh in on whether this trade-off aligns with project priorities.
- Removal of Python 2 coverage (obsolete but may affect legacy workflows).
- Trade-offs in test coverage (e.g., `linux-exotic` no longer tests GCC 8, but other jobs still cover older distributions).
