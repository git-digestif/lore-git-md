Subject: [PATCH 0/8] ci: housekeeping updates for CI configurations
Series version: v1 (initial submission, with patch 8/8 expected to reroll)
Originating author: Patrick Steinhardt
Thread type: patch series (CI/build system maintenance)

Core problem or goal
Modernize and simplify Git's CI configurations by removing outdated dependencies (EOL Docker images, Python 2 coverage), eliminating redundant or unused jobs, and updating supporting scripts. The series targets GitHub Actions and GitLab CI workflows, along with minor test adjustments, to reduce complexity and improve reliability without introducing new functionality or behavioral changes. The scope now explicitly includes a trade-off between reftable's foreign-SCM interoperability coverage and SHA-256 + reftable coverage, following Junio C Hamano's review.

Current status
Under review (initial v1 submission). No prior versions. The series consists of 8 patches touching `.github/workflows/main.yml`, `.gitlab-ci.yml`, `ci/install-dependencies.sh`, `ci/lib.sh`, `ci/run-build-and-tests.sh`, and `t/t5004-archive-corner-cases.sh`. Key changes include:
- Dropping the unused "linux-clang" job logic (patch 3/8 deletes dead code in `ci/run-build-and-tests.sh` left behind by commit d88d727143).
- Switching the `linux32` job from the unsupported `i386/ubuntu:20.04` image to `i386/debian:latest` (patch 4/8), ensuring 32-bit platform coverage until at least 2030. This update removes obsolete Ubuntu-specific logic in `ci/install-dependencies.sh` and updates `ci/lib.sh` to recognize the new image format.
- Renaming the `linux-TEST-vars` job to `linux-exotic` (patch 5/8) for clarity, as the job exercises Git with non-default "exotic" options (`OPENSSL_SHA1_UNSAFE`, `GIT_TEST_SPLIT_INDEX`, etc.).
- Updating the `linux-exotic` job to use `ubuntu:latest` (patch 6/8), replacing the EOL Ubuntu 20.04 image and removing the explicit `gcc-8` dependency.
- Removing Python 2 coverage (patch 7/8) by deleting conditional logic in `ci/lib.sh` and `ci/install-dependencies.sh` that set `PYTHON_PACKAGE=python2` for Ubuntu 20.04, replacing it with unconditional `PYTHON_PATH=/usr/bin/python3`.
- **Patch 8/8 (reroll expected)**: Removal of the redundant `linux-reftable` job, which Junio C Hamano identified as the only CI job exercising reftable with foreign-SCM interoperability tests (CVS, SVN, Perforce). Patrick Steinhardt proposes repurposing the `linux-reftable-leaks` job to test **reftable with SHA-256** instead, trading foreign-SCM coverage for SHA-256 coverage. This change is not yet implemented and remains an open question.
- Fixing the "fedora-breaking-changes-meson" job (patch 2/8, typo fix in `ci/run-build-and-tests.sh` correcting `musl` to `meson`).
- Adding the `SHA1` prerequisite to a test in `t/t5004-archive-corner-cases.sh` (patch 1/8) to skip it in SHA-256 repositories.
Net effect: 21 insertions, 64 deletions, reducing CI complexity. The reroll of patch 8/8 may adjust these counts.

Key technical details
Files/subsystems: CI configurations (GitHub Actions, GitLab CI), supporting scripts (`ci/`), and one test file (`t/t5004-archive-corner-cases.sh`).
Symbols/configs: Job names (`linux-clang`, `linux-TEST-vars` → `linux-exotic`, `linux-reftable`, `linux32`, `fedora-breaking-changes-meson`), Docker images (`i386/ubuntu:20.04` -> `i386/debian:latest`, `ubuntu:20.04` -> `ubuntu:latest`), scripts (`ci/lib.sh`, `ci/install-dependencies.sh`, `ci/run-build-and-tests.sh`), Python-related variables (`PYTHON_PACKAGE` removed, `PYTHON_PATH` now hard-coded to `/usr/bin/python3`), and test prerequisites (`SHA1` added to `t/t5004-archive-corner-cases.sh`). The `linux-exotic` job now uses `ubuntu:latest` and the system-provided GCC version instead of `gcc-8`.
Behavior: No user-visible changes; internal CI reliability improvements only. The typo fix in `ci/run-build-and-tests.sh` (s/musl/meson/) restores the intended "breaking changes" flag for the Fedora Meson job. Patch 3/8 removes dead code from the same script, aligning with the earlier removal of the `linux-clang` job. Patch 4/8 replaces the EOL `i386/ubuntu:20.04` image with `i386/debian:latest`, simplifying dependency installation logic in `ci/install-dependencies.sh`. Patch 5/8 renames the `linux-TEST-vars` job to `linux-exotic` without altering its logic or options. Patch 6/8 updates the `linux-exotic` job to use `ubuntu:latest`, removing the explicit `gcc-8` dependency. Patch 7/8 removes Python 2 support by deleting conditional logic and hard-coding `python3`. **Patch 8/8 (proposed)**: Repurposing the `linux-reftable-leaks` job to test reftable with SHA-256, which would eliminate foreign-SCM interoperability coverage (CVS, SVN, Perforce) in favor of SHA-256 coverage. This change is not yet implemented and remains under discussion.
Test coverage: Minor adjustment to `t/t5004-archive-corner-cases.sh` to skip a SHA-1-specific test in SHA-256 repositories. Junio C Hamano flagged a **regression in reftable test coverage**: foreign-SCM interoperability tests (CVS, SVN, Perforce) are no longer exercised in CI after the removal of the `linux-reftable` job. Patrick Steinhardt proposes addressing this by repurposing the `linux-reftable-leaks` job to test reftable with SHA-256, but this trade-off has not been resolved.

Open questions and loose ends
