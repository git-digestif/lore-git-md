Subject: [PATCH 0/8] ci: housekeeping updates for CI configurations
Series version: v3 (reroll addressing Junio C Hamano, SZEDER Gábor, Jeff King, and now Icelandic locale resolution)
Originating author: Patrick Steinhardt
Thread type: patch series (CI/build system maintenance)

Core problem or goal
Modernize and simplify Git's CI configurations by removing outdated dependencies (EOL Docker images, Python 2 coverage), eliminating redundant or unused jobs, and updating supporting scripts. The series targets GitHub Actions and GitLab CI workflows, along with minor test adjustments, to reduce complexity and improve reliability without introducing new functionality or behavioral changes. The scope includes a resolved trade-off between reftable's foreign-SCM interoperability coverage and SHA-256 + reftable coverage, following Junio C Hamano's review of v1, and a now-resolved naming dispute over the `linux-TEST-vars` job rename to `linux-feature-testbed`.

Current status
Under review (v3 posted). The series consists of 8 patches touching `.github/workflows/main.yml`, `.gitlab-ci.yml`, `ci/install-dependencies.sh`, `ci/lib.sh`, `ci/run-build-and-tests.sh`, and `t/t5004-archive-corner-cases.sh`. Key changes from v2:
- **Naming resolution**: The `linux-TEST-vars` job is renamed to `linux-feature-testbed` (Junio C Hamano's preferred choice among 14 alternatives), resolving the dispute raised by SZEDER Gábor in v2. The rename is purely mechanical (three one-line substitutions in `.github/workflows/main.yml`, `.gitlab-ci.yml`, and `ci/run-build-and-tests.sh`) with no behavioral impact. Jeff King (Peff) has explicitly endorsed the new name in his **surface-level review** of patch 5/8, confirming the resolution.
- **Reftable coverage**: The `linux-reftable-leaks` job is repurposed as `linux-reftable-sha256` to test reftable with SHA-256 (`GIT_TEST_DEFAULT_HASH=sha256` and `GIT_TEST_DEFAULT_REF_STORAGE_FORMAT=reftable`), while the `linux-reftable` job preserves foreign-SCM interoperability coverage (CVS, SVN, Perforce). Junio has explicitly endorsed this trade-off. **Open question**: Jeff King (Peff) raises a **substantive technical concern** in his review of patch 8/8, questioning whether the `linux-reftable-sha256` job is redundant given that the `fedora-breaking-changes-meson` job already covers SHA-256 + reftable via the `WITH_BREAKING_CHANGES` flag. This challenges the patch’s core rationale and may lead to the job being dropped or the commit message being revised to justify its necessity.
- **Dead code removal**: Patch 3/8 deletes unused logic in `ci/run-build-and-tests.sh` left behind by the removed `linux-clang` job (commit d88d727143, 2023-06-01). The four-line deletion (`NO_RUST=UnfortunatelyYes` and `GIT_TEST_DEFAULT_HASH=sha1`) is purely mechanical and has no behavioral impact.
- **Python 2 removal**: Patch 7/8 hard-codes `python3` in `ci/install-dependencies.sh` and `ci/lib.sh`, removing conditional Python 2 logic now that Ubuntu 20.04 jobs are gone. The change deletes eleven lines and adds two, with no behavioral impact beyond eliminating the no-longer-possible Python 2 code path. The rationale is that Python 2 reached end-of-life in 2020, and none of the current CI images package it.
- **Test design update**: Patch 1/8, which adds the `SHA1` prerequisite to `t/t5004-archive-corner-cases.sh`, has seen **substantive technical discussion** between Patrick Steinhardt and Jeff King (Peff). Peff proposed an alternative approach: making the test self-contained by creating a temporary SHA-1 repository (`git init --object-format=sha1`) for the test’s duration, allowing it to run in any environment that meets the other prerequisites (`EXPENSIVE`, `LONG_IS_64BIT`, `UNZIP`, etc.). Patrick tentatively agreed with Peff’s suggestion ("Hmm. Yeah, I guess that wouldn't hurt."), signaling openness to revising the patch to adopt this approach. The current implementation (adding the `SHA1` prerequisite) remains the baseline, but the discussion is ongoing and may result in a reroll.
- **Typo fix and future-proofing**: Patch 2/8 corrects `fedora-breaking-changes-musl` to `fedora-breaking-changes-meson` in `ci/run-build-and-tests.sh`, restoring the `WITH_BREAKING_CHANGES` flag for the Fedora Meson job. Jeff King (Peff) suggests broadening the `case` statement pattern to `*breaking-changes*` to guard against similar typos in future job additions. Patrick Steinhardt has **acknowledged the technical merit of this suggestion** but proposes deferring it to a follow-up patch to avoid scope creep, citing broader structural issues in the CI scripts (duplication, unclear separation between `ci/lib.sh` and `ci/run-build-and-tests.sh`). The discussion now explicitly references a prior, abandoned patch that merged the two scripts and adopted similar pattern-matching improvements. The current patch remains unchanged, but future discussion may revisit the wildcard pattern or structural refactoring.
- **32-bit platform update**: Patch 4/8 replaces `i386/ubuntu:20.04` with `i386/debian:latest` for the `linux32` job, ensuring support until at least 2030 and simplifying dependency logic. The change removes obsolete conditional logic in `ci/install-dependencies.sh` (previously handling `i386/ubuntu` separately for SVN dependencies) and updates the `CI_OS_NAME` check in `ci/lib.sh` to recognize the new image. **Resolved**: Jeff King’s **substantive technical concern** about Icelandic locale (`is_IS`) support in the new `i386/debian:latest` image is now closed. Patrick Steinhardt confirmed that Debian’s `locales-all` package provides the necessary locale data, making the removed `i386/ubuntu`-specific logic redundant. The `linux32` job’s behavior remains unchanged, preserving test coverage for gettext-related edge cases (e.g., non-ASCII commit messages) without additional configuration.
- **Image updates**: Patch 6/8 updates the `linux-feature-testbed` job to use `ubuntu:latest` (dropping the explicit `gcc-8` dependency), while other jobs (AlmaLinux 8, Debian 12) retain coverage for older distributions. The `ubuntu:latest` tag is a rolling LTS reference, ensuring stability and eliminating the need for manual updates. Jeff King (Peff) has **surface-level reviewed** this patch, endorsing the change and calling the commit message "nicely explained." The review is uncontested and the patch remains ready for integration.
- Net effect: 20 insertions, 39 deletions, reducing CI complexity while maintaining or improving coverage. All changes are mechanical and pass linked CI runs (GitLab, GitHub).

Key technical details
Files/subsystems: CI configurations (GitHub Actions, GitLab CI), supporting scripts (`ci/`), and one test file (`t/t5004-archive-corner-cases.sh`).
Symbols/configs: Job names (`linux-TEST-vars` -> `linux-feature-testbed`, `linux-reftable-leaks` -> `linux-reftable-sha256`), Docker images (`i386/ubuntu:20.04` -> `i386/debian:latest`, `ubuntu:20.04` -> `ubuntu:latest`), scripts (`ci/lib.sh`, `ci/install-dependencies.sh`, `ci/run-build-and-tests.sh`), Python-related variables (`PYTHON_PACKAGE` removed, `PYTHON_PATH` hard-coded to `/usr/bin/python3`), test prerequisites (`SHA1` added to `t/t5004`), the `WITH_BREAKING_CHANGES` flag in `ci/run-build-and-tests.sh`, and the `LANGUAGES` variable in `ci/install-dependencies.sh` (now confirmed to support Icelandic locale via Debian’s `locales-all` package). The `linux-feature-testbed` job now uses `ubuntu:latest` and the system-provided GCC version. Patch 3/8 removes dead code in `ci/run-build-and-tests.sh` that set `NO_RUST=UnfortunatelyYes` and `GIT_TEST_DEFAULT_HASH=sha1` for the removed `linux-clang` job. Patch 7/8 hard-codes `python3` in `ci/install-dependencies.sh` (replacing `PYTHON_PACKAGE`) and simplifies `ci/lib.sh` by removing the Ubuntu-20.04-specific branch for `MAKEFLAGS`. Patch 8/8 introduces `GIT_TEST_DEFAULT_HASH=sha256` and `GIT_TEST_DEFAULT_REF_STORAGE_FORMAT=reftable` for the `linux-reftable-sha256` job. The typo fix (s/musl/meson/) in patch 2/8 restores the `WITH_BREAKING_CHANGES` flag for the Fedora Meson job, which is now preemptively supported by the `SHA1` prerequisite in patch 1/8. Jeff King’s future-proofing suggestion for patch 2/8 proposes using `*breaking-changes*` in the `case` statement to match any job name containing that substring. The test in `t/t5004-archive-corner-cases.sh` verifies Git’s ability to handle ZIP archives with objects larger than 4GB, requiring 64-bit `long` support, unzip with ZIP64 extensions, and the `EXPENSIVE` prerequisite; currently, only the Fedora CI job meets these requirements. Peff’s proposed alternative for patch 1/8 involves creating a temporary SHA-1 repository (`git init --object-format=sha1`) for the test’s duration, making the test self-contained and independent of the CI environment’s default hash algorithm. The discussion around patch 2/8 now references broader structural issues in the CI scripts, including duplication between `ci/lib.sh` and `ci/run-build-and-tests.sh` and the potential for consolidation, as well as a prior, abandoned patch that merged the two scripts and adopted similar pattern-matching improvements.
