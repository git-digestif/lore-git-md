This is the first patch in Patrick Steinhardt’s 13-patch series refactoring Git’s object database (ODB) to move alternates handling into the files backend. The patch is a preparatory refactoring that shifts responsibility for resolving packfile paths from `fill_oids_from_packs()` in `commit-graph.c` to its caller in `builtin/commit-graph.c`.

The change is small but significant: previously, `fill_oids_from_packs()` assumed it could construct packfile paths relative to the ODB source’s path, which tied the commit-graph subsystem to the ODB’s internal structure. Now, the caller (`builtin/commit-graph.c`) resolves these paths upfront, passing fully qualified paths to `fill_oids_from_packs()`. This untangles the commit-graph logic from ODB internals, aligning with the series’ broader goal of making alternates a backend-specific implementation detail.

The patch itself is mechanical and well-contained, touching only two files (`builtin/commit-graph.c` and `commit-graph.c`). The diff is clean, with no behavioral changes—just a shift in where path resolution happens. The commit message clearly explains the motivation and the benefit for future patches (specifically, patch 2/13, which will remove the ODB source argument from the commit-graph subsystem).

Karthik Nayak’s review of v1 flagged the commit message as under-motivated, and Patrick addressed this in v2 by expanding the explanation. The patch now looks ready for integration, with no open concerns. If you’re tracking the ODB refactoring effort, this is a foundational step worth noting, but it’s unlikely to break anything on its own. The real action starts in later patches.
