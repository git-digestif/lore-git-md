This is the first patch in a two-part **bugfix series** addressing a long-standing inconsistency in Git’s index refresh logic. The issue: `git status` incorrectly reports files as modified when line-ending conversions (e.g., `text eol=lf`) rewrite file contents without changing their logical meaning, while `git diff` and `git add` correctly ignore them. The root cause is `ie_match_stat()`’s size-based shortcut, which assumes a size mismatch always means content changed—a premise broken by conversion filters introduced years after the shortcut was written.

The patch modifies `ie_match_stat()` to skip the size shortcut for paths subject to conversion, falling back to the same conversion-aware check used for mtime comparisons. It also optimizes `ce_compare_data()` to avoid hashing files when their converted length already differs from the blob size, minimizing performance overhead. The changes are surgical: unconverted files and repositories without conversion remain unaffected, and the new logic aligns with existing behavior in the mtime branch of `ie_match_stat()`.

Performance measurements in the commit message show the fix resolves a 3x slowdown for stat-dirty converted files while adding negligible overhead for clean trees. The patch includes thorough test coverage in `t/t0020-crlf.sh`, validating edge cases like lone CRs and Git LFS compatibility. This is a well-motivated, low-risk fix for a user-facing bug that’s been a chronic annoyance since 2005, particularly for cross-platform workflows. The only potential controversy is the performance trade-off, but the commit message quantifies it clearly and justifies the cost.

Key technical details:
- **Files touched**: `read-cache.c` (core logic), `t/t0020-crlf.sh` (tests).
- **New functions**: `ce_compare_converted_data()` (handles conversion-aware comparison), `size_change_is_conclusive()` (determines when size changes are trustworthy).
- **Behavior change**: `git status` now matches `git diff`/`git add` for converted files.
- **Performance**: Minimal overhead for clean trees; resolves slowdowns for converted files after the first run.
