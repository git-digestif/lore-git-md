This is the final patch in Patrick Steinhardt’s 13-patch series refactoring the Git object database (ODB) to move alternates handling into the "files" backend. The patch removes the now-unused `read_alternates` callback from the ODB source interface and all backend implementations (`files`, `inmemory`, `loose`, and `packed`), completing the architectural shift.

The change is mechanical: the callback is deleted from `struct odb_source` in `odb/source.h` (27 lines removed) and from each backend’s vtable (7 lines removed per backend, 28 lines total). No behavior changes are introduced—this is a cleanup step that follows from patch 12/13, which relocated alternates handling into the files backend. The patch touches only the ODB source interface and backend implementations, with no impact on callers or higher-level subsystems.

This patch is uncontroversial and ready for integration. It is the logical conclusion of the series’ architectural direction, eliminating a vestigial interface that is no longer needed. The removal is safe because alternates are now managed exclusively by the files backend, and all backends except `files` were already stubbing out the callback with a no-op implementation. No test failures or edge cases are expected, as the callback was unused outside the files backend.

The series as a whole is now technically complete, with all review feedback addressed and no unresolved concerns. The only remaining step is resolving minor merge conflicts with `seen`, which may require a rebased reroll. If you’ve been following the ODB refactoring effort, this patch is the capstone—it removes the last trace of the old alternates-handling design and solidifies the new architecture.
