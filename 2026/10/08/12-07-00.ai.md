This is the fourth patch in the RFC series introducing "precious files" to Git. It teaches `add_pattern()` to reject precious-file patterns (those prefixed with `$`) in contexts where they are not allowed, such as `$GIT_DIR/info/sparse-checkout`.

The patch adds a new `disable_precious` flag to `add_pattern()` and its callers, including `add_patterns_from_buffer()` and `add_patterns_from_file_to_list()`. When this flag is set, any precious-file pattern triggers a warning and is skipped. The sparse-checkout builtin is updated to use this flag, ensuring precious patterns are rejected in its patterns file. A new test in `t1091-sparse-checkout-builtin.sh` verifies this behavior by checking that a `$/ciao` pattern in `.git/info/sparse-checkout` produces the expected warning.

The change is narrowly scoped: it blocks precious patterns in sparse-checkout files but does not yet implement broader enforcement (e.g., in `git clean`). The refactoring is clean, with minimal churn to existing callers (just adding the new flag parameter). The test coverage is light but sufficient for the immediate goal. This patch is a logical follow-up to the earlier refactoring in the series, preparing the codebase for the full precious-files implementation while addressing a specific edge case upfront.
