This is the design document for the "precious files" feature, written by Elijah Newren and included as the first patch in Mirko Faina’s RFC series. It proposes a new file attribute (`precious`) to protect untracked but important files (e.g., build artifacts, IDE metadata) from accidental deletion by Git operations like `git clean` or checkout.

The document is thorough, spanning 540 lines and covering objectives, background, proposal details, backward compatibility, implementation hints, and alternatives. Key points include: precious files are specified via a new `.gitignore` syntax (lines starting with `$`), existing `.gitignore` negation (`!`) is redefined to mean "untracked" (not "not ignored"), and commands like `git checkout`, `git merge`, and `git clean` will need updates to respect the new attribute. The design also addresses edge cases, such as interaction with sparse-checkout and older Git clients, and suggests deprecating the `--[no-]overwrite-ignore` flag in favor of explicit precious file marking.

This is a well-motivated proposal with clear technical depth, but it’s likely to be controversial. The backward compatibility implications (e.g., escaping `$` in existing `.gitignore` files) and the redefinition of `!` in `.gitignore` may draw scrutiny. The document itself is polished and ready for review, but the feature’s viability hinges on whether the Git community accepts the trade-offs. For now, this is the foundational reference for the series—anyone reviewing the implementation patches will need to read this first.
