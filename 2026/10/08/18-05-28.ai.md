This is a bugfix patch in a CI/build system series, specifically addressing a test failure that would surface once a typo in the Fedora CI job is corrected. The patch adds the `SHA1` prerequisite to a test in `t/t5004-archive-corner-cases.sh` that extracts a ZIP file containing SHA-1 objects, which cannot be meaningfully processed in a SHA-256 repository. The test already has several prerequisites (`EXPENSIVE`, `LONG_IS_64BIT`, `UNZIP`, `UNZIP_ZIP64_SUPPORT`, `ZIPINFO`), and this change ensures it is skipped when running in a SHA-256 context.

The motivation is clear: the Fedora-based CI job (which runs with breaking changes enabled, defaulting to SHA-256) would fail this test once the typo in `ci/run-build-and-tests.sh` is fixed (in patch 2/8). The fix is minimal and targeted, touching only one line in the test script.
