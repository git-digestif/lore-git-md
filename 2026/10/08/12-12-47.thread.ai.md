Thread identity
Subject: [RFC PATCH 0/6] Introduce "precious files" attribute
Series version: v1 (RFC)
Originating author: Mirko Faina
Thread type: RFC patch series

Core problem or goal
Add a new `precious` file attribute that marks files as important but not version-controlled, preventing accidental deletion by Git operations (e.g., `git clean`) while keeping them excluded from the repository. The feature is motivated by use cases where build artifacts or other generated files should persist across clean operations without being tracked.

Current status
Under review (RFC stage). No prior versions; this is the initial public proposal. The series implements core functionality (pattern parsing, removal safety checks, `git ls-files` support) but defers `git clean` integration and documentation updates pending feedback.

Key technical details
- New file attribute: `precious`
- Files touched: `dir.c`/`dir.h` (pattern macros refactored to enum, `parse_path_pattern()`, `add_pattern()`), `unpack-trees.c` (removal safety checks), `builtin/ls-files.c` (output support)
- New symbols: `PATTERN_TYPE_PRECIOUS` enum value, `is_precious_file()` helper
- Test coverage: `t/t3001-ls-files-others-exclude.sh` and related test scripts
- Design document: `Documentation/technical/precious-files.txt` (added by Patch 1)
- On-disk format: No changes; attribute is stored in `.gitattributes` or `.git/info/attributes`
- Behavior: Precious files are excluded from the repository but protected from deletion by Git operations

Open questions and loose ends
- Integration with `git clean` (not yet implemented)
- Documentation updates (user-facing docs for the attribute and commands)
- Feedback on the design and implementation approach (RFC stage)
- Edge cases: Interaction with `--force` flags, submodule handling, or other Git operations that might delete files
