This is the **second patch in a two-part feature series** that teaches `git blame` and `git annotate` to automatically use `HEAD:.git-blame-ignore-revs` as a default ignore-revs file when no explicit ignore file is configured. The series is now **security-hardened** (patch 1/2) and **feature-complete** (this patch).

The patch implements the core behavior: when no ignore-revs file is explicitly set via `--ignore-revs-file` or `blame.ignoreRevsFile`, Git now checks for a blob named `.git-blame-ignore-revs` in the `HEAD` tree. If found, it is parsed in memory using the hardened `oidset_parse_buffer_carefully()` helper (introduced in patch 1/2), which rejects malformed input (NUL bytes, invalid OIDs) and prevents promisor fetches in partial clones. The blob is resolved via `get_oid_with_context()` and skipped if it is not a regular file (e.g., a committed symlink). The default blob is added to the ignore-revs list **before** any user-configured files, ensuring user overrides take precedence.

Key edge cases are handled: subdirectory invocations, bare repositories, CLI/config overrides (`--no-ignore-revs-file`, `blame.ignoreRevsFile=""`), empty files, comments, whitespace, and malformed input. The patch also updates documentation to clarify the new behavior and override semantics. Test coverage is **comprehensive**, verifying all these scenarios and confirming the feature aligns with hosting platform conventions (GitHub, GitLab).

The design is **well-motivated** and **technically sound**, addressing a long-standing usability gap while maintaining backward compatibility. The security hardening (NUL byte rejection, promisor fetch prevention) is a prerequisite for exposing the parser to upstream-controlled content, and the split into two commits improves reviewability. The patch is **ready for broader review**, but its security-sensitive changes (especially the tag-peeling logic) will need scrutiny from contributors like Jeff King or brian m. carlson. **Worth attention** for anyone interested in blame workflows or security-sensitive parsing.
