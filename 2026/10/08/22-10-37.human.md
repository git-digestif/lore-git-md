This is a bugfix patch targeting the fetch subsystem, specifically addressing a regression in shallow fetches when backfilling tags.

The patch fixes a performance issue introduced in 0e358de64a (May 2025), where batched reference updates were adopted for both references and tags. The problem occurs because references aren't committed to disk before tag backfilling begins, leaving the client with no references to report in the 'have' section during negotiation. This causes the server to send all objects in the repository when backfilling tags (which has no depth limit), negating the benefits of shallow fetching.

Karthik Nayak provides clear benchmarks showing the impact: the current HEAD (with the fix) is 17x faster than the pre-fix version when fetching 10,000 refs with reftable backend. The fix commits references before starting tag backfilling, creating two transactions instead of one, which is still significantly faster than not using batched updates at all.

The patch includes a new test in `t/t5510-fetch.sh` that verifies shallow fetches don't re-fetch objects for tags, using packet tracing to confirm the negotiation behavior. The implementation is clean, with a well-explained rationale in the code comment and commit message.

This looks like a well-crafted fix for a real performance regression, with good test coverage and clear evidence of the problem and solution. The trade-off (two transactions instead of one) is justified by the dramatic performance improvement.
