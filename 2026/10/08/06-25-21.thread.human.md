This thread is about a bugfix for a regression in `git repack --drop-filtered --dry-run`, where the `--dry-run` flag was incorrectly ignored, causing packs to be rebuilt and deleted despite the flag's documented behavior. The regression, introduced in 2025, was fixed in a prior version (v2) of the patch series by Siddharth Shrimali, which added an early return in `cmd_repack()` to prevent repository modifications under `--dry-run`.

The current version (v3) is a follow-up cleanup that removes redundant `!dry_run` checks in two helper functions, `repack_promisor_objects()` and `existing_packs_remove_redundant()`, which became unreachable after the v2 fix. The series has been reviewed and deemed "good enough" by Junio C Hamano, the maintainer, and is now queued in the `next` branch for integration testing. Patrick Steinhardt, who previously noted the redundant checks, has now confirmed he has no further objections, effectively closing the thread. The topic is expected to graduate to `master` in the next cycle with no further changes.

Key participants include Siddharth Shrimali (the author), D. Ben Knoble (who provided a substantive review and `Reviewed-by` for v2), Junio C Hamano (who queued the patch and confirmed it as ready for integration), and Patrick Steinhardt (who initially pointed out the redundant checks but has now signed off on the series). The fix is purely a code hygiene improvement with no behavior changes, and all open questions have been resolved. The regression's historical context and test coverage remain unchanged from the v2 fix.
