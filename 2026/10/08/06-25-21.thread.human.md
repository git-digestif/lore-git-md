This thread is about a bugfix for `git repack` that corrects a regression in the `--dry-run` behavior when used with `--drop-filtered`. The issue, reported by Coy Geek, causes `git repack --drop-filtered --dry-run` to incorrectly rebuild packs and delete old ones despite the `--dry-run` flag, violating its documented behavior.

Siddharth Shrimali's patch provides a minimal fix by adding an early `return` in `cmd_repack()` to prevent the code from proceeding to the actual repack and deletion steps when `--dry-run` is specified. The fix is accompanied by a new test that verifies the pack directory remains unchanged in both explicit (`-d`) and implicit deletion scenarios. The change is confined to `builtin/repack.c` and the test script, making it straightforward to review and unlikely to introduce side effects elsewhere.

The patch is well-motivated, addressing a clear user-facing issue with thorough test coverage. There are no open questions or objections in the thread so far, and the fix appears ready for review and potential integration. Key participants include the author (Siddharth Shrimali) and the original reporter (Coy Geek).
