Here’s the updated human-readable summary for a developer catching up:

This thread fixes a long-standing regression in `git repack --drop-filtered --dry-run`, where the `--dry-run` flag was ignored, causing packs to be rebuilt and deleted despite the flag’s documented behavior. The issue, introduced in 2025 (commit `1e746b00aa`), was resolved in v2 of Siddharth Shrimali’s patch series by adding an early `return` in `cmd_repack()` to prevent the code from proceeding to pack modifications. The fix is minimal, targeted, and has already been queued in Junio’s `next` branch after receiving D. Ben Knoble’s `Reviewed-by`. It’s expected to graduate to `master` in the next cycle.

The follow-up v3 patch, just posted, is a cleanup that removes redundant `!dry_run` checks in `repack_promisor_objects()` and `existing_packs_remove_redundant()`. These checks became dead code after the v2 fix, so their removal doesn’t change behavior—it just tidies up the logic. Patrick Steinhardt had flagged this redundancy during the v2 review, and Siddharth addressed it promptly. The v3 patch is independent of the core fix and doesn’t block graduation; it’s a straightforward hygiene improvement that makes the code easier to follow. No new tests or on-disk changes are involved, and the series remains uncontroversial.
