This is patch 4/13 of Patrick Steinhardt’s ODB refactoring series, which adapts `odb_for_each_alternate()` to iterate over `struct odb_files_dir` instead of `struct odb_source`. The change is mechanical: the callback type and all callers are updated to use the new type, and `odb_source_files_downcast()` is used to bridge the gap where the ODB source list still contains `struct odb_source` instances. The patch touches five files (`builtin/count-objects.c`, `builtin/submodule--helper.c`, `diagnose.c`, `odb.c`, and `odb.h`), replacing `source->path` with `dir->abspath` and adding a `repo` field to `struct alternate_refs_data` to compensate for the removed `odb_source->odb->repo` access.

The motivation is clear: this is a preparatory step for later patches that will make alternates a files-backend-specific implementation detail. The change itself is straightforward, but it introduces a subtle behavioral difference: alternates are now identified by their canonicalized absolute path (`abspath`) rather than the raw path stored in the source. This could affect edge cases where path resolution matters (e.g., symlinks or relative paths), though no such issues are mentioned in the commit message or review discussion.

Karthik Nayak’s review of this patch was surface-level, confirming the mechanical change but not assessing deeper correctness or edge cases. The patch is part of a larger architectural shift, and its correctness depends on later patches (notably 12/13) that complete the alternates relocation. If you’re tracking the series, this patch is a key intermediate step—watch for follow-up discussion about path resolution or linked-list traversal in patches 6/13 and 12/13.
