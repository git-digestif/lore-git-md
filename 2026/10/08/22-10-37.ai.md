This is a bugfix patch targeting the fetch subsystem, specifically addressing a regression in shallow fetches when backfilling tags.

The patch fixes a performance issue introduced in commit 0e358de64a (fetch: use batched reference updates, 2025-05-19). The regression occurs because batched updates delay committing references to disk until after tag backfilling begins. During shallow fetches, this means the client has no references to report in the 'have' section of negotiation when backfilling tags, causing the server to send all objects in the repository since backfilling lacks a depth limit.

Karthik Nayak's solution splits the transaction into two: one for the fetched references and another for backfilling tags. While this creates two transactions (slightly slower than the single-transaction approach), it remains significantly faster than not using batched updates at all. Benchmark results show the fix runs 17.38±0.61 times faster than the pre-batched-update behavior.

The patch touches `builtin/fetch.c` and adds a test in `t/t5510-fetch.sh` that verifies shallow fetches don't refetch objects during tag backfilling. The test checks packet traces to confirm the client reports the correct 'have' references during negotiation.

This is a targeted fix for a specific edge case (shallow fetches with tags) that maintains the performance benefits of batched updates while correcting the regression. The commit message clearly explains the problem, solution, and trade-offs, and includes a Reported-by credit to Mitja Bezenšek.
