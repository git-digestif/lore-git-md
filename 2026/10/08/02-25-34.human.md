This is a bugfix targeting the `git repack` command. The original author of the `--drop-filtered` feature, Siddharth Shrimali, confirms the bug reported by Coy Geek: when `git repack --dry-run --drop-filtered` is used, it incorrectly writes new promisor packs and (with `-d`) deletes old packs, violating the documented `--dry-run` contract. The root cause is in `builtin/repack.c`—the `dry_run` flag guards only the `delete_redundant` logic, but execution continues into `finish_repack`, which unconditionally writes and deletes packs.

Shrimali proposes a minimal fix: after printing candidate object IDs in the `dry_run` block, return early with `ret = 0; goto cleanup;` to prevent any side effects. He also plans to add a test in `t/t7706-repack-drop-filtered.sh` to verify that the pack directory remains unchanged and the candidate is still printed. The fix is straightforward, well-scoped, and unlikely to be controversial. The thread has already moved from problem identification to a clear, tested solution, so this patch should land quickly once submitted. If you care about `git repack` correctness or promisor pack handling, this is worth tracking.
