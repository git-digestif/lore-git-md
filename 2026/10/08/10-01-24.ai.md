This is the sixth patch in Patrick Steinhardt’s eight-patch CI/build system series. It updates the `linux-exotic` job to stop using the now end-of-life Ubuntu 20.04 image and instead use the `ubuntu:latest` tag, which always points to the most recent Ubuntu LTS release. The change removes the explicit `gcc-8` package requirement, letting the job use the default GCC version provided by the image. The patch touches both GitHub Actions (`.github/workflows/main.yml`) and GitLab CI (`.gitlab-ci.yml`) configurations, reducing six lines to two.

The motivation is straightforward: Ubuntu 20.04 is no longer supported and has begun to cause issues in CI. While this reduces coverage for older Ubuntu versions, the `linux-exotic` job’s purpose is to test Git with non-default "exotic" options (e.g., `OPENSSL_SHA1_UNSAFE`, `GIT_TEST_SPLIT_INDEX`) rather than to validate specific compiler or distribution versions. Other CI jobs still cover older Linux distributions (e.g., AlmaLinux 8, Debian 12), so the overall test matrix remains robust. The switch to `ubuntu:latest` ensures the job stays on a supported LTS release without requiring manual updates for each new Ubuntu version.

The change is mechanical and uncontroversial, aligning with the series’ goal of simplifying and modernizing CI configurations. The patch is unlikely to generate discussion beyond minor questions about test coverage trade-offs.
