This is a documentation patch series that moves Git’s `BreakingChanges` document into a proper manpage (`gitbreaking-changes(7)`). The v2 series is now five patches (up from four in v1) and drops the RFC tag after resolving all review feedback.

The goal remains the same: make upcoming breaking changes more visible to end users by integrating the document into Git’s documentation system. The new manpage will be accessible via `git help breaking-changes` or `man gitbreaking-changes`, and the build system (`Makefile` and `meson.build`) is updated to include it. The original `BreakingChanges` file is retained as a pointer to the new manpage to avoid breaking existing links.

Key changes in v2 include splitting the initial conversion patch into two for easier review, dropping a patch that would have added a reference to `gitbreaking-changes(7)` in `git(1)` (due to a parallel effort removing guide mentions), and moving the "Adding new items" discussion to the end of the document. The series also addresses a rendering issue with one URL in AsciiDoc by linking to a reply instead of the original message, ensuring all links work in both HTML and manpage output.

The series is technically ready and resolves all known conflicts with in-flight topics. It looks well-structured, with clear commit messages and no behavior changes—just a mechanical move of content with minor editorial adjustments. If the goal of better user visibility is accepted, this is a straightforward and uncontroversial way to achieve it.
