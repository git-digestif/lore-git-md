This thread is about a small but practical fix to a flaky GPG signature verification test in Git’s test suite. Harald Nordgren identified that the test `t7004-tag.sh` sometimes fails on Alpine Linux because the current method—deleting the `gpghome` directory to simulate a missing public key—can fail if a socket file (`S.gpg-agent.extra`) isn’t present. The fix replaces the `rm -rf` approach with a cleaner method already used in `t7510`: pointing `GNUPGHOME` to an unused directory (`$GNUPGHOME_NOT_USED`), ensuring the key isn’t found without touching the filesystem.

The change is minimal, touching just two lines in the test script, and follows established patterns in the test suite. It’s a standalone patch, not part of a larger series, and addresses a well-documented flake that affects CI stability. The approach is low-risk and uncontroversial, so no follow-up discussion is expected. The fix is ready to be picked up by Junio for integration.
