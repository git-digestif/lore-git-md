This thread is a two-patch bugfix series by Curtis Allen Smith that addresses a long-standing inconsistency in Git’s index refresh logic, where `git status` incorrectly reports files as modified when line-ending conversions (e.g., `text eol=lf`) or clean filters rewrite file contents without changing their logical meaning. The first patch modifies `ie_match_stat()` to skip the size-based shortcut for converted files, aligning `git status` with `git diff` and `git add`, while the second patch introduces `core.convertAwareStatus`, a new configuration option with three modes (`true`, `no-filter`, and `false`) to let users opt out of the new behavior if needed.

The series is under review and appears well-prepared, with thorough test coverage in `t/t0020-crlf.sh` and clear documentation. The default behavior (`core.convertAwareStatus=true`) preserves the fix’s consistency benefits, while the `no-filter` and `false` modes cater to workflows where clean filters (like Git LFS) are too expensive to run during `git status`. No substantive objections or requests for changes have been raised yet, and the implementation is self-contained with minimal performance overhead. The fix is platform-agnostic, though it was originally reported against Git for Windows.
