This thread is about fixing a long-standing inconsistency in Git’s index refresh logic, where `git status` incorrectly reports files as modified when clean filters (like `text eol=lf`) rewrite file contents without changing their logical meaning. The issue, present since 2005, arises because `ie_match_stat()` uses a size-based shortcut that doesn’t account for conversions, while the mtime-based check already handles them correctly.

The original v1 series proposed a two-patch solution: the first patch modified `ie_match_stat()` to skip the size shortcut for converted paths and added an optimization to avoid hashing files with mismatched converted lengths, while the second introduced a config option (`core.convertAwareStatus`) to let users opt out of the new behavior. Junio’s review questioned the complexity of the first patch, suggesting either a clearer justification for the new `ce_compare_converted_data()` function or a refactor to consolidate logic.

In response, the author, Curtis Allen Smith, clarified that the core fix is much simpler than the original patch suggested—a single-line change to disable the size shortcut when conversions are involved, falling back to the existing conversion-aware logic. The rest of the patch (129 insertions) was an optional optimization, and the config option was an escape hatch for performance-sensitive cases. He proposed splitting the series: send the minimal fix as v2, then offer the optimization and config option as follow-ups if reviewers see value in them. Performance measurements showed a 3–17x slowdown without the optimization, but the author acknowledged it could be addressed separately. The thread is now focused on whether the minimal fix is sufficient or if the optimization should be included upfront. No new objections have been raised, and the path forward hinges on this decision.
