This is the third patch in Kristoffer Haugsbakk’s five-patch v2 series converting Git’s `BreakingChanges` document into the new `gitbreaking-changes(7)` manpage. The series as a whole is documentation-only, ready for integration, and this patch specifically replaces all message-ID references with full clickable URLs.

The change is motivated by usability: the original plain-text `BreakingChanges` document used raw message-IDs (e.g., `<xmqqa59i45wc.fsf@gitster.g>`), which require manual pasting into a URL template to access the mailing-list discussion. Since the new manpage is intended for a broader audience—including users who may not follow development closely—full URLs make the references immediately actionable. The patch also addresses rendering quirks in `asciidoc` and `asciidoctor`, which struggle with certain message-IDs even when URL-encoded. For example, one problematic ID (`CA+EOSBncr=4a4d8n9xS4FNehyebpmX8JiUwCsXD47EQDE+DiUQ@mail.gmail.com`) is replaced with a link to a second-level reply that properly quotes the original message, preserving fidelity without breaking rendering.

The patch touches only `Documentation/gitbreaking-changes.adoc`, replacing 17 message-ID references with their corresponding `https://lore.kernel.org/git/...` URLs. No other files or build system changes are needed here, as the file rename and build integration were handled in the second patch. The commit message documents the technical rationale, including edge cases like URL encoding and rendering limitations, and notes that a proposed hybrid format (URLs with message-IDs as link text) was abandoned due to implementation difficulties.
