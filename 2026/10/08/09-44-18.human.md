This is the third patch in a four-patch bugfix series (v4) that makes branch rename (`git branch -m`) and copy (`git branch -c`) operations report complete transactions to the `reference-transaction` hook. Previously, the hook only saw the deletion of the old branch name, not the creation of the new one, breaking tools that rely on transactional ref updates.

The patch integrates copy and rename into ordinary reference transactions by treating the source and destination as two updates within the same transaction. The destination update carries a pointer to its source, allowing the backend to replay the source's reflog history into the destination. This approach avoids exposing partial changes to hooks and ensures atomicity. The implementation handles edge cases like D/F conflicts, case-only renames on case-insensitive filesystems, and reflog symlinks, and includes thorough tests for hook behavior, history preservation, and error recovery.

Performance regressions are acknowledged (up to 137% for files-based rename with large reflogs) but accepted as necessary for correctness. The patch removes backend-specific callbacks in favor of a unified transaction API, reducing code duplication. It is well-tested, with new test files covering hook interactions, reflog staging, and error paths, and a performance test to measure the regression. The series is now passing all tests, including those that failed in v3, and is awaiting further review before landing in `next`.
