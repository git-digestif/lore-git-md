This is part of Patrick Steinhardt’s 13-patch series refactoring Git’s object database (ODB) to move alternates handling into the "files" backend. This specific patch (8/13) adapts the quarantine directory logic in `tmp-objdir.c` to manage the temporary object directory as a `struct odb_files_dir` instead of a standalone `struct odb_source`.

The patch is a mechanical refactor that prepares the quarantine subsystem for the architectural shift in later patches. It replaces the `prev_source` field in `struct tmp_objdir` with `temp_dir` (the new quarantine directory) and `orig_dir` (the original primary directory), and updates `tmp_objdir_replace_primary_odb()` to return a `struct odb_files_dir` instead of a `struct odb_source`. The quarantine directory is now inserted at the head of the files backend’s linked list of object directories, and the `will_destroy` flag is propagated to both the loose and packed sources within the quarantine directory.

Karthik Nayak’s review of this patch was surface-level, focusing on mechanical correctness rather than edge cases like linked-list invariants or promisor remotes. His only substantive question—a conceptual concern about removing the ability to have multiple sources per ODB—was retracted after discovering Patrick’s explanation in patch 12/13. The patch itself is uncontroversial and aligns with the series’ broader goal of consolidating alternates into the files backend.

This is a well-crafted refactoring with clear motivation and thorough implementation. If you’re tracking the ODB refactor or alternates handling, this patch is worth noting for its role in enabling the series’ architectural shift. The changes are internal and should not affect user-visible behavior. The series is now ready for integration, pending resolution of minor merge conflicts with `seen`.
