This is the third patch in Mirko Faina’s RFC series introducing "precious files" to Git. It teaches the path-pattern parser in `dir.c` to recognize the new `precious` attribute, which is marked with a `$` prefix in `.gitignore` files (e.g., `$*.log`).

The patch updates `parse_path_pattern()` to detect and reject invalid patterns (like `!$`, which would mean a negated precious file) and to set the new `PATTERN_FLAG_PRECIOUS` flag when it sees a `$` prefix. The function’s signature changes from `void` to `int` to signal parsing errors, and callers (`parse_attr_line()` and `add_pattern()`) are updated to handle those errors gracefully. A new test in `t7508-status.sh` verifies that invalid patterns trigger the expected warning.

This is a straightforward, mechanical change that prepares the pattern-parsing infrastructure for the core precious-files logic coming in later patches. The error handling is clean, and the test coverage is minimal but sufficient for the refactoring. The patch itself is uncontroversial, but its value depends entirely on whether the broader precious-files feature is accepted. If the series moves forward, this refactoring will be essential; if not, it will likely be discarded.
