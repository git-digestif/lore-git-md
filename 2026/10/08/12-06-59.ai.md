This is the third patch in Mirko Faina’s RFC series introducing "precious files" to Git. It teaches `parse_path_pattern()` in `dir.c` to recognize the new `$` prefix that marks a file as precious, while rejecting invalid patterns like `!$` (negated precious files). The patch also updates the function’s signature to return an error code, propagates that change through callers (`parse_attr_line()` and `add_pattern()`), and adds a test in `t7508-status.sh` to verify that problematic patterns trigger a warning.

The change is narrowly scoped: it extends the pattern-parsing logic to handle the new `PATTERN_FLAG_PRECIOUS` flag introduced in patch 2/6, and adds basic error handling for malformed patterns. The test coverage is minimal but sufficient to catch the immediate parsing edge case. This is a preparatory refactoring that only becomes useful if the precious-files feature is accepted; if the series is rejected, this patch will likely be discarded. The implementation looks clean and follows the established pattern for attribute parsing, but the broader design debate (ternary `.gitignore` syntax, command-specific behaviors) remains unresolved.
