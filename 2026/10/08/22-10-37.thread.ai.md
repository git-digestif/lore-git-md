Thread identity: Bugfix patch series (single patch) addressing a regression in shallow fetches when backfilling tags, authored by Karthik Nayak. This is the third iteration (v3) of the patch, refining edge-case handling after maintainer review.

Core problem or goal: Fix a performance regression in shallow fetches introduced by commit 0e358de64a ("fetch: use batched reference updates", 2025-05-19). The regression occurs because batched updates delay committing references to disk until after tag backfilling begins, causing the client to report no 'have' references during negotiation, forcing the server to send all objects since backfilling lacks a depth limit.

Current status: Under review; v3 is in preparation to address Junio C Hamano's edge-case concerns. The two-transaction approach (fetched references and backfilled tags) remains the agreed fix, but robustness in edge cases (empty main transactions, `--atomic` fetches, and cleanup path control flow) has been clarified and partially adjusted. The patch is not yet ready for `next`; a v3 will incorporate return-code separation and commit-message refinements.

Key technical details:
- Files touched: `builtin/fetch.c`
- New test: `t/t5510-fetch.sh` (reverted to original version after v2 test was found insufficient; coverage may need rethinking)
- Subsystem: fetch (shallow fetches, tag backfilling, reference transactions)
- Behavior change: Restores correct 'have' reference reporting during negotiation for shallow fetches with tags
- Performance impact: Fix is 17.38±0.61× faster than pre-batched-update behavior; two-transaction approach is 1.01× slower than single-transaction but still significantly faster than no batched updates
- Root cause: Batched updates delay reference commits until after tag backfilling, preventing 'have' reference reporting during negotiation
- Protocol constraint: Tag backfilling requires negotiation for nested annotated tags (server advertises both tag OID and recursively peeled non-tag OID)
- Edge cases resolved:
  - Empty main transaction: Regression cannot manifest (no refs to report); commit message will clarify.
  - `--atomic` fetches: Inherent limitation documented as a known trade-off; atomicity is preserved at the cost of potential full clones if tag backfilling triggers the negotiation issue.
  - Cleanup path: Return-code separation (`backfill_retcode`) ensures post-fetch steps (`FETCH_HEAD` write, upstream config) execute even if the tag backfill transaction fails.

Open questions and loose ends:
- Test coverage: The v2 test was insufficient to catch the regression; the original test version is being restored, but its adequacy remains unconfirmed. Further test refinement may be needed to reliably verify the fix.
