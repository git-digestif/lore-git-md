Thread identity: Bugfix patch series (single patch) addressing a regression in shallow fetches when backfilling tags, authored by Karthik Nayak.

Core problem or goal: Fix a performance regression in shallow fetches introduced by commit 0e358de64a ("fetch: use batched reference updates", 2025-05-19). The regression occurs because batched updates delay committing references to disk until after tag backfilling begins, causing the client to report no 'have' references during negotiation, forcing the server to send all objects since backfilling lacks a depth limit.

Current status: Under review. This is the second iteration of the patch (v2 forthcoming). The patch splits the reference transaction into two: one for fetched references and another for backfilling tags, restoring correct negotiation behavior while preserving most of the performance benefits of batched updates. The two-transaction approach is confirmed as the correct fix after Justin Tobler and Karthik Nayak ruled out the simpler alternative (skipping negotiation for tag backfilling) due to protocol constraints requiring intermediate object fetches for nested annotated tags.

Key technical details:
- Files touched: `builtin/fetch.c`
- New test: `t/t5510-fetch.sh` (verifies shallow fetches don't refetch objects during tag backfilling by directly inspecting repository state with `git cat-file`; revised from indirect packet-trace counting per Patrick's suggestion)
- Subsystem: fetch (shallow fetches, tag backfilling, reference transactions)
- Behavior change: Restores correct 'have' reference reporting during negotiation for shallow fetches with tags
- Performance impact: Fix runs 17.38±0.61 times faster than pre-batched-update behavior; benchmark comparison (HEAD~ vs HEAD) now included to quantify the performance cost of the two-transaction fix (slightly slower than single-transaction but still significantly faster than no batched updates)
- Root cause: Batched updates delay reference commits until after tag backfilling, preventing the client from reporting 'have' references during negotiation
- Protocol constraint: Tag backfilling requires negotiation for nested annotated tags because the server advertises both the tag reference OID and its recursively peeled non-tag OID, necessitating intermediate object fetches to resolve the full chain.
