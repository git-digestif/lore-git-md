Thread identity: Bugfix patch series (three patches) addressing a regression in shallow fetches when backfilling tags, authored by Karthik Nayak. This is the sixth iteration (v6) of the patch, now reordered for narrative clarity. The series targets the fetch subsystem, fixing a performance regression introduced by commit 0e358de64a ("fetch: use batched reference updates", 2025-05-19).

Core problem or goal: Fix a performance regression in shallow fetches where batched reference updates delayed committing references until after tag backfilling, causing the client to report no 'have' references during negotiation and forcing the server to send all objects. The solution exposes pending transaction state via the transport's `negotiation_include_tips` field, restoring correct 'have' reporting while preserving atomicity for `--atomic` fetches. The scalability trade-off (advertising all fetched references during negotiation) is documented as an acceptable O(n) complexity for fetched refs.

Current status: Under active review; the memory management blocker from v4 has been resolved by the precursor patch (2/3) introducing `transport_options_release()`, ensuring proper cleanup for all transport types. The **core fix (patch 3/3)** implements the pending-transaction "haves" design in `builtin/fetch.c` and adds tests to verify 'have' reporting during tag backfilling for both atomic and non-atomic flows. The series is ready for maintainer review, with no outstanding technical objections. Junio C Hamano's review remains the sole blocker. The v6 re-roll addresses surface-level feedback from Patrick Steinhardt: the commit ordering has been adjusted to place the test for upstream tracking persistence (now patch 1/3) before the precursor patch (2/3) and the core fix (3/3), improving narrative clarity. The commit message for patch 2/3 has been tweaked to clarify how it exposes the memory leak it fixes. No technical changes were made to the patches themselves.

Key technical details:
- Files touched: `builtin/fetch.c` (core fix: collecting fetched ref OIDs into `fetched_tips` and appending them to `negotiation_include_tips` during `backfill_tags()`), `t/t5510-fetch.sh` (three new tests: one verifying upstream tracking info persistence after rejected updates, two verifying 'have' reporting for atomic/non-atomic fetches), `transport-helper.c` (memory leak fix in cleanup path, patch 2/3), `transport.c` (introducing `transport_options_release()`, patch 2/3), `transport.h` (declaration of new function, patch 2/3).
- New symbols: `fetched_tips` (temporary `oid_array` in `do_fetch()`), `transport_options_release()` (new function for transport cleanup).
- Behavior change: Restores correct 'have' reference reporting during negotiation for shallow fetches with tags by exposing the OIDs of just-fetched refs via `negotiation_include_tips`. Preserves atomicity for `--atomic` fetches.
- Performance impact: Fix is 17.38±0.61× faster than pre-batched-update behavior; v6 avoids intermediate commits while maintaining batched update benefits.
- Root cause: Batched updates delayed reference commits until after tag backfilling, preventing 'have' reference reporting during negotiation.
- Memory management: The precursor patch (2/3) fixes a pre-existing memory leak in the remote-helper transport's cleanup path by introducing `transport_options_release()`, ensuring proper cleanup for all transport types. The leak was not caught by CI because no tests previously exercised the remote-helper transport's cleanup path.
- Edge cases resolved:
  - Empty transactions: Handled by exposing pending transaction state regardless of transaction initialization.
  - `--atomic` fetches: Atomicity is preserved by avoiding intermediate commits.
  - Error handling: Errors from the transaction are logged but do not halt the fetch, as batched updates allow partial success. Post-fetch operations execute even if the transaction failed to initialize.
  - Cleanup path: Post-fetch steps (`FETCH_HEAD` write, upstream config) execute regardless of transaction success, as these steps are independent of transaction state. Cleanup is now unconditional as per review feedback.
  - Rejected updates: Upstream tracking information is written even when some reference updates are rejected during a batched fetch (verified by new test in patch 1/3).
- Test coverage: Three new tests in `t/t5510-fetch.sh` verify (1) persistence of upstream tracking information after rejected updates (patch 1/3), (2) 'have' reporting during tag backfilling for non-atomic fetches (patch 3/3), and (3) 'have' reporting during tag backfilling for atomic fetches (patch 3/3). The test for upstream tracking persistence is now placed first to improve narrative clarity.
