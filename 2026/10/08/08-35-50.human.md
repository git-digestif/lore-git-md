This is the second iteration of Patrick Steinhardt’s 13-patch series refactoring the Git object database (ODB) to move alternates handling into the "files" backend. The goal is to eliminate a conceptual mismatch where alternates were previously managed at the ODB source level, which caused performance regressions, complicated data structures like bitmaps and commit graphs, and blocked backend-agnostic extensions to `GIT_OBJECT_DIRECTORY` and `GIT_ALTERNATE_OBJECT_DIRECTORIES`. This series consolidates alternates into the files backend, making them a backend-specific implementation detail and enabling future ODB work such as pluggable backends.

The v2 update addresses all review feedback from Karthik Nayak, including better motivation in the first commit message and a resolution for the only technical concern raised—a potential NULL-dereference regression in `clear_midx_file()`. Patrick demonstrated the removed check was redundant, as the sole caller already dereferences `r->objects`. The series is now **ready for further review or integration**, though it has minor merge conflicts with the `seen` branch that may require a reroll.

Key changes include introducing `struct odb_files_dir` to manage multiple object directories, refactoring `odb_for_each_alternate()` and `odb_find_source()` to work with directories instead of sources, and absorbing quarantine logic into `tmp-objdir`. The final patch removes the now-unused `read_alternates` callback from the ODB source interface, completing the architectural shift. The series touches 52 files, with significant changes to `odb/source-files.c` (482 lines added) and `odb.c` (439 lines removed), and affects core commands like `git commit-graph`, `git pack-objects`, and `git repack`.

The series is well-motivated and technically sound, with thorough commit messages and a clear architectural vision. The size and scope make it a heavy lift for reviewers, but the changes are mechanical and well-structured. If you care about ODB internals or alternates, this is a foundational series worth tracking. The unresolved loose end—`git_test_write_commit_graph_or_die()`’s assumption about the primary ODB source’s path—persists, but Patrick dismissed it as a test-suite hack, and no test failures have been reported. The series is built on `c46c1e3772` (start of the Git 2.98 cycle).
