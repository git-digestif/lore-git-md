This is the final patch in a four-part bugfix series that completes the cleanup phase of Maciej Ciemborowicz’s `reference-transaction` hook fix. The series addresses a long-standing issue where `git branch -m` (rename) and `git branch -c` (copy) operations omitted the creation of the new ref from the `reference-transaction` hook, breaking tools that rely on transactional ref updates.

Patch 4/4 removes the now-unused backend-specific copy and rename callbacks (`rename_ref`, `copy_ref`) and their private helpers from both the files and reftable backends. The patch deletes 656 lines of code, including temporary reflog handling (`TMP_RENAMED_LOG`), rollback logic, and debug tracing wrappers. The cleanup is mechanical and uncontroversial: the functionality has already been migrated to the transaction API in earlier patches, so this patch simply drops the dead code.

The series as a whole is well-motivated and thoroughly tested. Patch 1/4 (infrastructure) is already considered ready to proceed, and the v4 iteration resolved the test breakages Junio C Hamano reported in v3. Performance regressions (~137% for files-based rename with large reflogs, ~20-25% for reftable) are deemed acceptable for correctness. If no further regressions surface, expect this series to land in `next` soon.
