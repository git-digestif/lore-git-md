This thread reports and fixes two critical security flaws in Git’s SSH signing verification. The first flaw—checking key expiration (`valid-before`) against the committer date (which the signer controls) rather than the signature timestamp—is now documented in `gpg.adoc` with Junio C Hamano’s concise wording, omitting caveats about key leakage risks. The second flaw—revocation file errors failing open—has just been resolved in a v2 patch from Christian Noé Ramos López.

The v2 patch makes revocation file errors fatal by default (failing closed) while preserving an escape hatch via Git’s `:(optional)` pathname syntax. It also addresses Junio’s feedback by ensuring signature information is displayed even when the revocation file is missing, aligning the behavior with how unknown keys are handled. The fix is now technically complete, with four new test cases covering revoked keys, missing files, and the optional override. Junio and other reviewers have signed off on the security posture; the patch is ready for integration and will close a significant gap where misconfigured revocation files were silently ignored. The earlier documentation patch may land alongside it to keep the security fixes together.
