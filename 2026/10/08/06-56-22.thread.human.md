This thread is about two critical security flaws in Git’s SSH signing verification: (1) Git checked key expiration (`valid-before`) against the committer date (which the signer controls) rather than the signature timestamp, allowing backdated commits to bypass key expiration, and (2) Git failed open when the revocation file was missing or unreadable, rather than failing closed. Both issues are now resolved.

The revocation file flaw is fixed by a v2 security patch that makes errors fatal by default while supporting an `:(optional)` escape hatch, incorporating Junio C Hamano’s feedback on error-handling consistency. The timestamp confusion is addressed by a documentation patch clarifying that Git uses the committer/tagger date for key lifetime checks. Junio and Patrick Steinhardt have debated the wording of this documentation: Junio prefers brevity, while Patrick suggests retaining a brief note that the timestamp is signer-controlled to highlight the security limitation. Christian Noé Ramos López, the reporter, has adopted Junio’s concise phrasing in the current patch but may revise it further based on this discussion. Phillip Wood and Patrick Steinhardt have both supported documenting the behavior’s limitations, though the final wording is still under discussion.

The revocation file fix is ready for integration, while the documentation patch may be held until the revocation fix is finalized to avoid splitting the security fixes across releases. No open technical questions remain; the discussion is now focused on documentation clarity.
