This thread reports two critical security flaws in Git’s SSH signing verification: (1) the `valid-before` timestamp in the allowed signers file is checked against the committer date (controlled by the signer), allowing backdated commits to bypass key expiration, and (2) a missing or unreadable `gpg.ssh.revocationFile` fails open (warns and continues) instead of failing closed. Christian Noé Ramos López identified these issues and provided test cases demonstrating the flaws, recommending either documenting the current `valid-before` behavior or aligning it with GPG’s independent timestamp check, and making revocation file errors fatal.

Phillip Wood, a highly respected reviewer with deep expertise in Git’s signing and verification subsystems, has weighed in with a substantive review. He agrees with both issues and clarifies that while the documentation implies `valid-before` is checked against the signature time, it actually uses the committer date. He suggests tightening the documentation to reflect this behavior (or noting that GPG’s signature timestamp can also be faked) and endorses making revocation file errors fatal, consistent with OpenSSH’s security model. No patch has been submitted yet, but the next steps are clear: implement Phillip’s recommendations—document or adjust the `valid-before` behavior and make revocation file errors fail verification. The report’s included test cases should simplify patch validation, and given the security implications, this is likely to be resolved quickly once a patch is posted.
