This thread began when Christian Noé Ramos López reported two critical flaws in Git’s SSH signing verification: (1) Git checked key expiration timestamps against the committer date (which the signer controls), allowing backdated commits to bypass key expiration, and (2) if the revocation file was missing or unreadable, Git warned but proceeded as if no revocation file existed, failing open instead of closed. The GPG backend, by contrast, correctly used the signature timestamp and failed closed on revocation issues.

Both issues are now resolved. The revocation file flaw was fixed in a v2 security patch that makes errors fatal by default while supporting an `:(optional)` escape hatch, aligning error handling with the behavior for unknown keys. The timestamp confusion was addressed in a finalized v3 documentation patch, which clarifies that Git uses the committer or tagger date for key lifetime checks and explicitly warns that this provides no security guarantees due to signer-controlled timestamps. Both patches are fully reviewed—Patrick Steinhardt just confirmed his endorsement of the documentation patch—and are ready for integration, though they may be held together to avoid splitting security fixes across releases. Junio’s "What’s cooking" report contains a minor clerical error (a misplaced sentence), but this doesn’t affect the patches’ technical readiness. The fixes touch `gpg-interface.c` and `Documentation/gpg.adoc`, with new test coverage in `t/t7528-signed-commit-ssh.sh`. No open questions remain.
