This thread reports and fixes two critical security flaws in Git’s SSH signing verification. Christian Noé Ramos López discovered that Git checked key expiration (`valid-before`) against the committer date—controlled by the signer—rather than the signature timestamp, allowing backdated commits to bypass expiration. Additionally, if the configured revocation file was missing or unreadable, Git warned but proceeded as if no revocation file existed, failing open instead of closed. Both issues are now resolved and ready for integration.

The timestamp confusion is addressed by a finalized documentation patch, which Patrick Steinhardt has endorsed. It clarifies in `gpg.adoc` that Git uses the committer or tagger date for `valid-before`/`valid-after` checks and explicitly notes the lack of security guarantees due to signer-controlled timestamps. The revocation file flaw is fixed by a **v3 security patch** that ensures missing or unreadable revocation files now fail verification by default, with an optional `:(optional)` prefix to override this behavior. The patch also aligns error handling so signature information is displayed consistently for both missing revocation files and unknown keys.

Junio C Hamano and Phillip Wood reviewed the issues and agreed with the fixes. Junio raised a procedural note about patch threading and flagged a minor clerical error in his "What's cooking" report, but neither affects the patches' technical readiness. Both fixes may be held together to avoid splitting security fixes across releases. Test coverage has been expanded to verify the new behavior. The patches touch `gpg-interface.c` and `Documentation/gpg.adoc`, with no open technical questions remaining.
