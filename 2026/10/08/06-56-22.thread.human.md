This thread is a security bug report from Christian Noé Ramos López about two critical flaws in Git’s SSH signing verification logic. The first flaw allows signers to bypass key expiration by backdating commits, exploiting a discrepancy between the SSH and GPG backends—GPG correctly rejects such signatures, but SSH does not. The second flaw causes Git to fail *open* when the SSH revocation file is missing or unreadable, rather than failing closed as OpenSSH does, which violates security best practices.

The report is thorough, with clear reproduction steps, test cases, and comparisons to GPG’s behavior. It highlights that the revocation file logic is entirely untested in Git’s test suite and proposes two fixes: either document the current behavior (checking `valid-before` against the committer date) or align SSH with GPG’s stricter checks, and make missing/broken revocation files fail verification. The flaws are serious, as they undermine both key expiration and revocation mechanisms for SSH-signed commits and tags. No patch is attached yet, but the report provides actionable recommendations for addressing the issues. Key participants so far are the author and likely maintainers or security-focused contributors who will weigh in on the proposed fixes. The thread is still open, with no decisions or patches merged at this stage.
