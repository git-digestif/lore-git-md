This thread began as a security report by Christian Noé Ramos López, uncovering two critical flaws in Git’s SSH signing verification: (1) key expiration checks used the committer date (controlled by the signer) instead of the signature timestamp, allowing backdated commits to bypass `valid-before` restrictions, and (2) missing or unreadable revocation files failed open (warned but allowed verification to proceed) rather than failing closed.

Both issues are now resolved. The revocation file flaw is fixed by a **v2 security patch** that makes errors fatal by default while supporting Git’s `:(optional)` pathname prefix as an escape hatch. Junio C Hamano’s feedback on error-handling consistency has been incorporated, and the patch is technically ready for integration—pending only a procedural note about patch threading for future submissions. The timestamp confusion is addressed by a documentation update to `gpg.adoc`, finalized in this email, which clarifies that Git checks `valid-before`/`valid-after` against the committer or tagger date and explicitly warns that this provides no security guarantees. The documentation patch may be held until the revocation fix is merged to avoid splitting security fixes across releases.

Key participants include Christian (reporter and patch author), Junio (maintainer, who approved the documentation wording and resolved the last technical feedback on the revocation fix), Patrick Steinhardt (who shaped the documentation’s security note), and Phillip Wood (who confirmed the timestamp behavior). The fixes touch `gpg-interface.c` and `Documentation/gpg.adoc`, with new test coverage in `t/t7528-signed-commit-ssh.sh`. No open questions remain beyond the procedural threading note and the release coordination timing.
