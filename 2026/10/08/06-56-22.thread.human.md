This thread is about two critical security flaws in Git’s SSH signing verification: (1) the `valid-before` timestamp check uses the committer date (which the signer controls) instead of an independent timestamp, allowing backdated commits to bypass key expiration, and (2) the revocation file fails open if misconfigured, rather than failing closed. The discussion has reached consensus on fixes: document the `valid-before` behavior as a known limitation (noting it’s only trustworthy for uncompromised keys) and make revocation file errors fatal by default, with an escape hatch via Git’s `:(optional)` pathname prefix.

Phillip Wood and Patrick Steinhardt have refined the approach in this latest exchange, confirming the `:(optional)` prefix as the right mechanism for the revocation file override. Christian Noé Ramos López, who reported the flaws, is preparing a patch to implement the revocation file fix and add missing test coverage. The design phase is complete, and the thread is now focused on implementation. No backward-compatibility concerns have been raised, and the changes are seen as necessary security hardening. The patch will update `gpg-interface.c` and `gpg-ssh.c`, clarify the `gpg.ssh.allowedSignersFile` man page, and introduce tests for revocation file handling.
