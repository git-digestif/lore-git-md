This thread began when Christian Noé Ramos López reported two critical flaws in Git’s SSH signing verification: (1) Git checked key expiration against the committer date (which the signer controls) rather than the signature timestamp, allowing backdated commits to bypass key expiration, and (2) if the revocation file was missing or unreadable, Git warned but proceeded as if no revocation file existed, failing open instead of closed. The GPG backend correctly rejected backdated signatures and failed closed on revocation issues.

Both issues are now resolved. The revocation file flaw has been fixed by a **v2 security patch** that makes errors fatal by default while supporting Git’s `:(optional)` pathname prefix as an escape hatch. The patch also ensures consistent signature information display, whether the revocation file is missing or an unknown key is encountered. The timestamp confusion issue is addressed by a documentation patch clarifying that Git uses the committer or tagger date for `valid-before`/`valid-after` checks and noting that this does not provide security guarantees because the signer can choose the timestamp arbitrarily. Both patches are ready for integration, though the documentation patch may be held until the revocation fix is finalized to avoid splitting security fixes across releases.

Key participants include Christian Noé Ramos López (who reported the flaws, provided test cases, and submitted the fixes), Junio C Hamano (who agreed with the technical approach and provided feedback on error-handling flow), Phillip Wood (who clarified the timestamp confusion and endorsed documenting the behavior’s limitations), and Patrick Steinhardt (who advocated for documenting the limitations and helped shape the final wording). The only remaining loose end is a procedural note from Junio: future patch rerolls should be sent as direct replies to the previous version to ensure proper threading and tooling compatibility. The patch itself is technically complete and on track for integration.
