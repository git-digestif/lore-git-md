This thread began when Christian Noé Ramos López reported two critical flaws in Git’s SSH signing verification: (1) Git checked key expiration timestamps (`valid-before`) against the committer date (which the signer controls), allowing backdated commits to bypass key expiration, and (2) if the revocation file was configured but missing or unreadable, Git warned and proceeded as if no revocation file existed, failing open instead of failing closed. The GPG backend correctly used the signature timestamp and failed closed on revocation issues, exposing an inconsistency.

Both issues are now resolved. The revocation file flaw is fixed by a security bugfix patch (v2) that makes errors fatal by default while supporting an `:(optional)` escape hatch, incorporating Junio C Hamano’s feedback on error-handling consistency. The timestamp confusion flaw is addressed by a finalized documentation patch (v3) that clarifies in `gpg.adoc` that Git uses the committer or tagger date for `valid-before`/`valid-after` checks and explicitly warns that this provides no security guarantees because the signer controls the timestamp. The documentation patch adopts concise wording proposed by Patrick Steinhardt and carries `Helped-by` trailers from Junio, Phillip Wood, and Patrick, reflecting broad agreement. Both patches are ready for integration but may be held together to avoid splitting security fixes across releases.

The thread saw substantive input from Junio, who accepted the documentation wording and resolved his earlier concern about the revocation file patch’s error-handling flow, Phillip Wood, who clarified the timestamp check behavior, and Patrick Steinhardt, who argued for documenting the limitations of the current system rather than attempting a technical fix. Christian incorporated all feedback and flagged a minor clerical error in Junio’s "What’s cooking" report, which does not affect the patches’ readiness. No open questions remain, and the fixes are technically complete.
