This thread is a security bug report about two critical flaws in Git’s SSH signing verification. Christian Noé Ramos López identified the issues: (1) Git checks the `valid-before` timestamp in the allowed signers file against the committer date (which the signer controls), allowing backdated commits to bypass key expiration, and (2) if the `gpg.ssh.revocationFile` is misconfigured (missing, unreadable, or a directory), Git warns and proceeds as if no revocation file exists, failing open instead of closed. The GPG backend correctly rejects backdated signatures and fails closed on revocation file issues.

Phillip Wood reviewed the report, agreed with both issues, and suggested tightening the documentation to reflect the current behavior or noting that the GPG signature timestamp can also be faked. He endorsed making revocation file errors fatal, aligning with OpenSSH’s security model. Patrick Steinhardt later weighed in, agreeing with the issues but offering nuanced perspectives. He argued that fixing the `valid-before` timestamp problem is difficult in a distributed system, as there’s no reliable way to verify the actual signing time without centralized coordination. He leans toward documenting the current behavior’s limitations rather than attempting a technical fix, noting that `valid-before`/`valid-after` checks are only trustworthy if the signing key has never leaked. For the revocation file issue, Patrick proposed a middle-ground solution: using Git’s `:(optional)` pathname prefix to make revocation file errors fatal by default while allowing users an escape hatch.

The thread remains in the design phase, with no patch submitted yet. The technical direction is clear: document the `valid-before` behavior’s limitations and tighten revocation file handling, potentially with an optional override. The flaws are demonstrated by test cases in the original report, and the relevant subsystems (`gpg-interface.c`, `gpg-ssh.c`) and config keys (`gpg.ssh.revocationFile`) are well-defined. The discussion is focused on security implications and practical trade-offs, with no major disagreements among participants.
