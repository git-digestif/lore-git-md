This thread reports and fixes two critical security flaws in Git’s SSH signing verification. The first flaw allowed backdated commits to bypass key expiration checks because Git used the committer date (controlled by the signer) rather than the signature timestamp for `valid-before`/`valid-after` validation. The second flaw caused Git to fail open—warning but proceeding—when the `gpg.ssh.revocationFile` was configured but missing or unreadable, rather than rejecting the signature.

Both issues are now resolved. The timestamp confusion is addressed by a finalized documentation patch that clarifies the current behavior’s limitations and explicitly notes the lack of security guarantees due to signer-controlled timestamps. The revocation file flaw is fixed by a v3 security patch that makes missing or unreadable revocation files fatal by default, with an escape hatch via Git’s `:(optional)` pathname prefix. Junio C Hamano, Patrick Steinhardt, and Phillip Wood have all reviewed and endorsed the fixes, and Junio’s "What's cooking" report indicates readiness for integration. The patches may be held together to avoid splitting security fixes across releases.

The fixes touch `gpg-interface.c` and `Documentation/gpg.adoc`, with new test coverage in `t/t7528-signed-commit-ssh.sh`. No open questions remain, and the thread is effectively closed pending integration.
