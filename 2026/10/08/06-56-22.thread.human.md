This thread began as a security bug report by Christian Noé Ramos López, identifying two critical flaws in Git’s SSH signing verification: (1) the `valid-before` timestamp in the allowed signers file is checked against the committer date (which the signer controls), allowing backdated commits to bypass key expiration, and (2) if the `gpg.ssh.revocationFile` is configured but missing or unreadable, Git warns and proceeds as if no revocation file exists, failing open instead of closed. The first issue has been addressed with a documentation patch clarifying the behavior and its limitations, while the second is now resolved by the patch just submitted.

Christian’s new patch makes Git fail closed when the revocation file is missing or unreadable, aligning its behavior with the GPG backend. The fix is simple and secure: if the file doesn’t exist, Git now returns an error instead of silently continuing. Users who need to allow missing files can use Git’s `:(optional)` pathname prefix as an escape hatch. The patch includes thorough test coverage for the revocation file logic, which was previously untested, and updates the documentation to reflect the new behavior. Phillip Wood and Patrick Steinhardt, who helped shape the design consensus earlier in the thread, are credited in the commit trailers.

The patch is ready for review and likely to be merged quickly, given the prior discussion and clear security rationale. The only remaining open question from the original report—whether Git will support additional revocation mechanisms like OpenSSH’s `KRL` format—is outside the scope of this fix and remains unaddressed. For now, the thread has delivered actionable fixes for both reported flaws.
