This thread began as a security report by Christian Noé Ramos López, detailing two critical flaws in Git’s SSH signing verification: (1) key lifetime checks (`valid-before`) use the committer date (controlled by the signer) instead of the signature timestamp, allowing backdated commits to bypass expiration, and (2) revocation file errors fail open rather than closed. The thread quickly reached consensus on a two-part fix: document the timestamp limitation as a known issue and make revocation file errors fatal by default.

Christian has now submitted the first part of that fix—a documentation patch updating the `gpg.ssh.allowedSignersFile` man page to clarify that `valid-after`/`valid-before` checks rely on committer/tagger dates (not signature timestamps) and warn that these checks are only trustworthy if the key has never leaked. The patch also corrects a minor typo ("OpensSSH" → "OpenSSH"). Phillip Wood and Patrick Steinhardt, who helped shape the wording, are credited with `Helped-by` trailers. This addresses the first security issue without attempting a technical fix, as the thread agreed that timestamp confusion is difficult to resolve in a distributed system.

The second issue—revocation file errors failing open—remains unpatched. Christian has committed to submitting a separate patch with test coverage for this logic, which is currently untested. The design for that fix is settled: revocation file errors will fail verification by default, with an escape hatch via Git’s `:(optional)` pathname prefix. Phillip Wood and Patrick Steinhardt have both endorsed this approach. Until that patch lands, the thread’s work is incomplete, but the documentation update marks progress on the agreed plan.
