This is the twelfth patch in Patrick Steinhardt’s 13-patch series refactoring Git’s object database (ODB) to move alternates handling into the "files" backend. The patch is large (35 files changed, 441 insertions, 549 deletions) but mechanically straightforward: it relocates alternates management from the generic ODB layer (`odb.c`) into the files backend (`odb/source-files.c`), making alternates a backend-specific implementation detail.

The core change is architectural. Previously, alternates were managed at the ODB source level, which created conceptual mismatches with pluggable backends (e.g., performance regressions, assumptions about filesystem paths, and complications with data structures like bitmaps and commit graphs). This patch eliminates those mismatches by consolidating alternates into the files backend, where they logically belong. The `read_alternates` callback is removed from the ODB source interface, and alternates are now managed as a linked list of `struct odb_files_dir` within the files backend. Most of the diff is a direct conversion from iterating over ODB sources to iterating over object directories, with the bulk of the complexity in moving the alternates infrastructure (path parsing, deduplication, and recursive addition) from `odb.c` to `odb/source-files.c`.

Key symbols introduced or modified include:
- `odb_files_dir_is_usable()`: Checks if an object directory is usable as an alternate.
- `odb_add_alternate_recursively()`: Recursively adds alternates to the files backend.
- `odb_prepare_alternates()`: Prepares alternates for use by the files backend.
- `dirs_by_path` hashmap and `dirs_paths_icase` field: Track directories by path to avoid duplicates.
- The `next` pointer and `by_path_entry` field are removed from `struct odb_source`, as sources no longer form a linked list.

The patch also updates commands like `git fsck`, `git gc`, and `git pack-objects` to iterate over directories instead of sources, exposing a "who’s-who" of commands that don’t yet work properly with pluggable ODBs. These are mostly housekeeping commands that will either be converted later (e.g., commit graphs, MIDXs) or remain incompatible due to their tight coupling with the files backend.

Karthik Nayak’s review of this patch raised one critical technical concern: the removal of the `if (r->objects)` check in `clear_midx_file()`, which previously guarded against NULL dereferences. Patrick resolved this by demonstrating the check was redundant, as the sole caller (`builtin/bugreport.c`) already dereferences `r->objects`. This is a clean fix, but the patch’s size and scope leave room for other edge cases (e.g., linked-list invariants, promisor remotes) to surface later.

This patch is the linchpin of the series, completing the architectural shift and paving the way for future ODB work like pluggable backends. It’s well-motivated and technically sound, but its size and the lack of deeper edge-case review suggest it warrants close scrutiny during integration. If you’re tracking ODB internals or alternates-related changes, this is the patch to watch.
