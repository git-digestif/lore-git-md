This is patch 5/13 in Patrick Steinhardt’s v2 series refactoring the Git object database (ODB) to move alternates handling into the "files" backend. The patch refactors `odb_find_source()`—a generic ODB function that locates a source by its object directory path—into `odb_source_files_find_dir()`, a files-backend-specific function that returns a `struct odb_files_dir` instead of a generic `struct odb_source`.

The change is mechanical: the new function iterates through the ODB’s source list, filters for files-backed sources, and compares the requested object directory path (canonicalized via `real_pathdup()`) against the `abspath` field of each `struct odb_files_dir`. Callers in `builtin/commit-graph.c`, `builtin/multi-pack-index.c`, and `t/helper/test-read-midx.c` are updated to use the new function, replacing `source->path` with `dir->abspath` and using `odb_source_files_downcast()` where needed. The generic `odb_find_source()` and `odb_find_source_or_die()` functions are removed from `odb.h` and `odb.c`, eliminating 55 lines of dead code.

This is a preparatory step for patch 12/13, which will relocate alternates handling into the files backend. The patch itself introduces no behavioral changes—it merely shifts the lookup logic from the ODB core to the files backend, aligning with the series’ architectural goal of making alternates a backend-specific implementation detail. The commit message is clear, and the diff is straightforward, though the series’ size (13 patches, 1,800+ lines changed) means reviewers should verify that the linked-list traversal order and path canonicalization do not introduce edge cases in later patches. No test failures or regressions are expected at this stage.
