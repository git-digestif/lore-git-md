This is the first patch in a four-part bugfix series (v4) targeting the ref backend and hook infrastructure. It introduces an internal-only transaction flag, `REF_TRANSACTION_FLAG_INTERNAL`, to distinguish physical backend operations from logical ref updates. The flag suppresses `reference-transaction` hook notifications for nested transactions (e.g., packed-refs updates during a rename), ensuring hooks only see the outer logical update. The change is minimal: a six-line addition to `refs.c` and `refs/refs-internal.h`, with the suppression check centralized in `run_transaction_hook()`.

The patch directly addresses Patrick Steinhardt’s earlier objection about hook suppression logic being scattered across backends. By consolidating the check in one place, it avoids duplicating the same conditional in every backend. The flag is explicitly marked internal and not exposed in the public API, reinforcing its backend-only role. This sets the stage for the later patches, which will use the flag to handle rename/copy operations without spurious hook invocations.

No behavior changes are visible to users or hook authors; the patch is purely preparatory. The commit message clearly states the motivation and scope, and the implementation is idiomatic (a single flag and a single conditional). There are no test failures or regressions introduced here—this is infrastructure for the fixes that follow. The patch is well-motivated and uncontroversial; expect it to proceed without debate.
