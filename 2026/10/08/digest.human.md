# Git mailing list daily digest for 2026/10/08

## Long threads

### http.sslVerifyStatus for stapled OCSP responses

*Long thread: 33 replies so far from 5 participants over 59 days; 1 message that day.*

Grayson Gordon's series adds an `http.sslVerifyStatus` boolean mapping to libcurl's `CURLOPT_SSL_VERIFYSTATUS` so git verifies stapled OCSP responses instead of ignoring them, defaulting to off. Earlier it was reverted out of `next` after the new t5585 test failed on a GnuTLS curl backend, and Junio C Hamano tentatively ejected it from `seen` after bisecting linux-* CI timeouts to this topic. Today he confirmed in isolation on Git 2.56 (CI run 37673759531) that it causes the 6-hour timeouts; the linux-TEST-vars/linux32 failures are unrelated (Ubuntu 20.04 downloads).

### fetch: infer branches from a refmap-only remote

*Long thread: 26 replies so far from 4 participants over 20 days; 1 message that day.*

Harald Nordgren's four-patch series keeps shallow repos from fetching every branch of a new remote, adding `remote.<name>.refmap`, inferring fetch branches from local upstreams, and defaulting to `--limited-fetch` in shallow repos; v7 fixed the fatal "--refmap option is only meaningful with command-line refspec(s)" error. Today Junio C Hamano reviewed v7: he asked the docs to name the inference mechanism, called `inferred_branches` misleading, wondered if the current branch's upstream could be added twice, proposed a shared `collect_upstream_from_remote()` helper in remote.c, and reported that combining the series with `seen` breaks t5505 and t5586 via other topics.

### git-bisect-rebase for iterative rebases

*Long thread: 22 replies so far from 6 participants over 8 days; 2 messages that day.*

Alejandro Colomar's `git-bisect-rebase` bisects for the first commit a branch cannot cleanly rebase onto; earlier discussion weighed folding it into git-rebase(1) versus a multi-shot form. Today he implemented `--abort`, `--continue`, and `--quit` with semantics unlike git-rebase(1), gave example sequences for moving a branch tree and a single branch, and corrected the tree algorithm so one `git rebase --onto A tmpA B` uses C instead of B.

### refs: run copy and rename through transactions

*Long thread: 18 replies so far from 5 participants over 20 days; 9 messages that day.*

Maciej Ciemborowicz's four-patch series routes reference copy and rename through ordinary transactions so the reference-transaction hook sees the whole operation, where files saw only the source deletion and reftable neither endpoint. Earlier v3 broke t0600 and t5510 because a packed-refs error was overwritten by a later success. Today he posted v4, which preserves that error by jumping to cleanup after the failed packed transaction, and reported the full suite passing on both backends. Patrick Steinhardt warned that posting new versions without replying to reviewers is a red flag; the thread then debated AI-assisted workflows, with Junio C Hamano calling unnecessarily large patches a problem.

### faster SHA-1 collision detection

*Long thread: 14 replies so far from 6 participants over 10 days; 8 messages that day.*

Scott Chacon's four-patch series ports Sam Reis's sha1dc Rust crate to C in `sha1dc-accel/`, claiming about 2.7x faster hashing on a Xeon and 2.85x on an M5 Max. Today Sebastian Thiel welcomed the speedup and Reis said he is happy to see it land. D. Ben Knoble raised license compatibility of the MIT-licensed derived code with GPL-2; Reis clarified the UBC tables are autogenerated from the Stevens/Shumow methodology, and Junio C Hamano confirmed Git's GPL-2 can incorporate MIT-licensed code.

## Notable threads

### SubmittingPatches: allow responsible AI assistance
Scott Chacon's RFC proposes moving toward Linux's approach: allow reviewed AI-assisted work with disclosure instead of rejecting anything that looks AI-generated. Today he argued DCO certification does not require knowing every LLM training source. Luca Milanesio argued fully AI-generated contributions should be rejected; Kristoffer Haugsbakk called the human/LLM analogy "metaphors gone amok"; brian m. carlsson said the SFC document does not require accepting LLM contributions; D. Ben Knoble quoted an "AI Pascal's wager" for rejecting them for now.

### repack: don't lose objects to a mid-run ".keep"
Qin ShiCheng's five-patch series fixes a race where a concurrent push installs a `.keep` after `git repack -d` decided which packs to delete, so pack-objects omits them and repack deletes the pack anyway. Today qeesung posted v3, whose final patch passes repack's startup snapshot of kept packs to pack-objects via the new `--keep-pack-from-file` so both processes share one snapshot; earlier patches add `repo_invalidate_kept_pack_caches()` and sort the `--keep-pack` list. Junio C Hamano suggested waiting for the ps/odb-files-alternates topic before merging.

### ssh signing: valid-before and revocationFile fail-open issues
Christian Noé Ramos López reported that `valid-before` is checked against the committer/tagger date the signer controls, so a backdated commit bypasses key expiry, and that a configured but missing `gpg.ssh.revocationFile` only warns while verification proceeds, unlike ssh-keygen and sshd which refuse. He asked git to refuse when the revocation file is configured and missing, or document that it is ignored. Phillip Wood agreed failing on a missing revocation file is safer and noted a GPG signature timestamp can also be faked.
