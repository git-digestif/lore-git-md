This is patch 3/13 in Patrick Steinhardt’s 13-patch series refactoring the Git object database (ODB) to move alternates handling into the "files" backend. The patch introduces `struct odb_files_dir`, a new data structure that encapsulates both the loose and packed object backends for a single object directory.

The change is purely preparatory: every "files" ODB source now contains exactly one `odb_files_dir` (accessed via `files->dirs`) instead of separate `loose` and `packed` fields. The new structure also stores the absolute path to the object directory and a `local` flag indicating whether it is the primary repository directory. The patch updates all callers to use the new field (`files->dirs->loose` and `files->dirs->packed`) and adds constructor/destructor functions (`odb_files_dir_new` and `odb_files_dir_free`) for the new type.

This is a mechanical refactoring with no behavior changes. The patch touches 19 files, primarily updating field accesses and function calls to use the new `dirs` field. The commit message explains that the new structure will later become a linked list of directories, enabling the files backend to manage multiple object directories (including alternates) as a single entity. The change is well-motivated as part of the broader ODB refactoring effort and is a necessary step toward consolidating alternates handling into the files backend.
