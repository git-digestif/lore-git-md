This is a **bugfix series** targeting the index refresh logic, specifically the inconsistency between `git status`, `git diff`, and `git add` when line-ending conversions are active. The root issue is that `ie_match_stat()` uses a size comparison as a shortcut to detect modifications, but this shortcut fails when a clean filter (like `text eol=lf`) rewrites file contents without changing their logical meaning. The result is that `git status` reports files as modified while `git diff` and `git add` correctly ignore them, creating user confusion.

The series consists of two patches. **Patch 1** modifies `ie_match_stat()` to skip the size-based shortcut when the path is subject to conversion, instead falling back to the same conversion-aware check used for mtime comparisons. It also optimizes `ce_compare_data()` to avoid hashing files whose converted length already differs from the blob size. **Patch 2** introduces `core.convertAwareStatus`, a new config option that lets users opt out of the new behavior (defaulting to `true` for consistency). The commit message provides detailed performance measurements showing that the overhead of the new check is minimal for clean trees and genuinely modified files, while resolving the inconsistency for converted files.

The motivation is clear and well-supported: the current behavior is a long-standing bug (dating back to 2005) that violates user expectations. The performance trade-offs are quantified and reasonable, and the series includes thorough test coverage in `t0020-crlf.sh`. The patches are structured to minimize disruption—existing behavior is preserved for unconverted files, and the config option provides an escape hatch if needed. This looks like a well-crafted fix for a real problem, with no obvious red flags. The author has also validated the series against a broad set of tests, including edge cases like Git LFS.

Key technical details for follow-up discussion:
- **Files touched**: `read-cache.c` (core logic), `environment.c`/`environment.h` (config plumbing), `Documentation/config/core.adoc` (docs), and `t/t0020-crlf.sh` (tests).

- **Performance impact**: Minimal for clean trees/unconverted files; resolves a 3x slowdown for stat-dirty converted files after the first run.
- **Behavior change**: `git status` will now agree with `git diff`/`git add` for converted files, eliminating the inconsistency.
- **Related prior work**: The issue was originally reported against Git for Windows, but the fix is platform-agnostic. The mtime branch of `ie_match_stat()` already handles conversions correctly, so this patch aligns the size branch with it.
