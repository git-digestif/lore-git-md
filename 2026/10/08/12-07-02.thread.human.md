This thread is an RFC series introducing "precious" files to Git, specifically extending `git ls-files --ignored` to distinguish between "trashable" and "precious" ignored files. Mirko Faina is the author, and this is the sixth and final patch in the series.

The patch adds two new options: `--ignored=trashable` (shows only files marked as trashable) and `--ignored=precious` (shows only files marked as precious). The implementation touches `dir.c` and `dir.h` to add new flags, arrays, and helper functions, while `builtin/ls-files.c` handles the new CLI syntax and constraints. Tests verify the behavior, including edge cases. However, the patch doesn’t explain what makes a file "precious" or how this interacts with existing ignore mechanisms (e.g., `.gitignore`), leaving the broader design unclear. The RFC tag indicates the author is seeking feedback on the direction, which is reasonable given the open questions.

So far, there’s no discussion or review from other participants, so the series remains untested by the community. The key open question is the motivation and design for "precious" files—whether they’re tied to a config key, a new `.gitignore` extension, or some other mechanism. Until that’s clarified, it’s hard to assess whether this is a well-motivated feature or an ad-hoc addition.
