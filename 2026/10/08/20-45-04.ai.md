This is the second patch in a two-patch **bugfix series** addressing a long-standing inconsistency in Git’s index refresh logic. The series fixes the problem where `git status` reports files as modified when `git diff` and `git add` correctly ignore them due to line-ending conversions (e.g., `text eol=lf`). The first patch modified the core logic to skip the size-based shortcut for converted files, ensuring consistency across commands. This patch introduces `core.convertAwareStatus`, a new configuration option that lets users opt out of the new behavior if their clean filters (like Git LFS) are too expensive to run during `git status`.

The patch adds three modes for `core.convertAwareStatus`:
- `true` (default): Always consult conversions, including clean filters, to ensure `git status` agrees with `git diff` and `git add`.
- `no-filter`: Consult only Git’s built-in conversions (e.g., `text`/`eol` attributes, `core.autocrlf`), but skip clean filters, relying on size changes for those files.
- `false`: Always treat size changes as modifications, restoring the pre-patch behavior.

The implementation touches `environment.c` and `environment.h` to add the config plumbing, updates `read-cache.c` to respect the new setting in `size_change_is_conclusive()`, and documents the option in `Documentation/config/core.adoc`. The tests in `t/t0020-crlf.sh` validate all three modes, including edge cases like invalid values and clean filter interactions. The config option is designed to be flexible—users can set it globally or per-command (e.g., `git -c core.convertAwareStatus=no-filter status`)—and has no performance impact for repositories without conversions.

This patch is a well-considered escape hatch for the behavior change introduced in the first patch. The default (`true`) preserves the fix’s consistency benefits, while `no-filter` and `false` cater to workflows where clean filters are prohibitively slow. The documentation is clear, the tests are thorough, and the implementation is clean, with no obvious performance pitfalls. The series as a whole looks like a polished solution to a real user-facing problem.
