This is patch 6/13 of Patrick Steinhardt’s ODB refactoring series, which prepares the "files" backend to handle multiple object directories by adding a linked-list mechanism to `struct odb_files_dir`. The patch is a **pure refactoring** with no visible behavior changes—it only extends the internal data structures and updates all ODB operations in `odb/source-files.c` to loop through the list.

The core change is the addition of a `next` pointer to `struct odb_files_dir`, enabling the backend to manage multiple directories (e.g., alternates, quarantine directories). All read operations now iterate through the list until the object is found, while write operations target only the first directory. The patch is mechanical: every function in `odb/source-files.c` is updated to loop through `files->dirs` instead of assuming a single directory. The `odb_source_files_free()` and `odb_source_files_close()` helpers are also adapted to handle the linked list.

This is a foundational step for later patches (notably 12/13, which relocates alternates handling into the files backend). The commit message is clear about the intent: "this mechanism isn’t used yet," but it will be in subsequent commits. No edge cases or robustness concerns are addressed here—those will surface in later patches when the linked list is actually populated.
