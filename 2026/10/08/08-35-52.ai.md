This is patch 2/13 of Patrick Steinhardt’s ODB alternates refactoring series, targeting the commit-graph subsystem. The patch decouples commit-graph operations from `struct odb_source` by replacing it with explicit repository and object-directory path arguments. This is a foundational step for the series’ broader goal of moving alternates handling into the files backend.

The changes are mechanical but pervasive: every function in `commit-graph.c` and `commit-graph.h` that previously took a `struct odb_source *` now takes a `struct repository *` and a `const char *dir` instead. The `struct commit_graph` gains a `repo` field and a `dir` field (canonicalized absolute path) while dropping its `odb_source` field. All filename helpers (`get_commit_graph_filename()`, etc.) now take a directory path instead of a source. Callers in `builtin/commit-graph.c`, `builtin/fetch.c`, `builtin/gc.c`, and test helpers are updated to pass the repository and path explicitly.

A key behavioral change is that object-directory paths are now canonicalized to absolute paths when loading or writing commit graphs. This ensures that graphs loaded from the same directory compare equal regardless of path spelling (relative, absolute, or symlink). The test helper `git_test_write_commit_graph_or_die()` is simplified to take only a `struct repository *` but still hard-codes the path from `repo->objects->sources->path`, which Karthik Nayak flagged as a potential inconsistency. Patrick dismissed this concern, arguing the function is a test-suite hack and the current implementation is sufficient.

The patch is well-motivated and aligns with the series’ architectural direction. The commit message clearly explains the rationale and the mechanical nature of the changes. No new edge cases are introduced, but the hard-coded path in the test helper remains a minor loose end. If you’re tracking the ODB refactoring effort, this patch is worth noting as it sets the stage for later alternates relocation. The changes are straightforward and unlikely to introduce regressions, but reviewers should verify that the canonicalization logic handles symlinks and relative paths correctly.
