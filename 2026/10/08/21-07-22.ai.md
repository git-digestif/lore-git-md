This is a **feature patch series** (2/2) that teaches `git blame` and `git annotate` to automatically use the `HEAD:.git-blame-ignore-revs` blob as a default ignore-revs file, aligning local behavior with hosting platforms like GitHub and GitLab. The series is a **v2 revision** that addresses maintainer feedback by splitting the change into two commits: the first hardens the ignore-revs parser and tag-peeling logic, and the second implements the default file lookup.

The core change is now **security-focused**: the patch rejects lines with embedded NUL bytes (using `memchr` instead of `strchr`) and prevents promisor fetches in partial clones by passing `OBJECT_INFO_SKIP_FETCH_OBJECT` and `OBJECT_INFO_QUICK` when peeling tags. The default file is resolved via `get_oid_with_context()` and checked with `S_ISREG()` to skip non-regular tree entries (e.g., committed symlinks). The implementation ensures user-configured ignore files take precedence, and empty configurations (`blame.ignoreRevsFile=""` or `--no-ignore-revs-file`) bypass the default blob entirely.

Test coverage is **comprehensive**, verifying subdirectory invocations, bare repositories, CLI/config overrides, committed symlinks, and malformed input handling. The series also clarifies documentation to reflect the new behavior and override semantics. The **open question** from v1—how to handle untracked working-tree files—is resolved by ignoring them in favor of the `HEAD` blob, though this may still surprise users expecting local overrides.

The patch is **well-motivated** and **technically sound**, but its security hardening (NUL byte rejection, promisor fetch prevention) will need scrutiny from contributors like Jeff King or brian m. carlson. The split into two commits improves reviewability, and the design now aligns with Junio’s guidance. **Worth attention** for anyone interested in blame workflows or security-sensitive parsing.
