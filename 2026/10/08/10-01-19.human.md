This is a test fix patch, part of an 8-patch series from Patrick Steinhardt. It targets the `t5004-archive-corner-cases.sh` test script, which verifies Git's ability to handle ZIP archives containing objects larger than 4GB.

The issue is that one test in `t5004` extracts SHA-1 objects from a ZIP file, but the test was not explicitly marked with the `SHA1` prerequisite. This becomes problematic when running in a SHA-256 repository (the default when "breaking changes" are enabled in CI), where SHA-1 objects cannot be properly processed. The patch adds the `SHA1` prerequisite to skip the test in SHA-256 repositories, preventing a failure that would surface once a typo in the CI configuration is fixed in the next patch.

The change is minimal—just one line—and the rationale is clearly explained in the commit message. The patch is well-motivated: it anticipates a CI breakage before it happens, rather than reacting after the fact. This is a sensible, low-risk fix that aligns with Git's test suite practices. If you care about CI stability or SHA-256 compatibility, this patch is worth noting.
