This is a bugfix for `git repack`. The patch addresses a regression where `git repack --drop-filtered --dry-run` incorrectly modifies the repository by writing a new promisor pack and deleting old packs, despite the `--dry-run` flag promising no changes. The commit message clearly explains the problem: the `--dry-run` block in `cmd_repack()` falls through into the regular repack code, causing unintended side effects.

The fix is straightforward: after listing the objects that would be dropped, the function now returns early to prevent further execution. The patch also adds a test to verify that the pack directory remains unchanged with and without the `-d` flag. The test is thorough, checking both the directory contents and the presence of the expected output.

This is a well-motivated fix with a clear explanation and test coverage. The bug was reported by a user, and the patch directly addresses the issue without introducing unnecessary complexity. It looks like a solid contribution that should be uncontroversial. The repack subsystem is actively maintained, so this is likely to receive attention.
