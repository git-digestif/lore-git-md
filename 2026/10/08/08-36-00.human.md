This is the tenth patch in Patrick Steinhardt’s 13-patch series refactoring Git’s object database (ODB) to move alternates handling into the "files" backend. The patch is a small but important cleanup: it moves the `will_destroy` flag from the generic `struct odb_source` to `struct odb_source_loose`, where it is actually used.

The `will_destroy` flag was originally added to the generic ODB source structure to indicate when a source is part of a transaction that will be discarded (e.g., a quarantine directory). The idea was to let backends optimize by skipping expensive operations like fsync. However, as Patrick explains, this assumption doesn’t hold for all backends—only the loose-object backend ever checked the flag. By moving it to `struct odb_source_loose`, the patch eliminates a layering violation and makes the flag an implementation detail of the loose backend, aligning with the series’ broader goal of self-contained backends.

The change is mechanical: the flag is removed from `odb/source.h`, added to `odb/source-loose.h`, and the one callsite in `tmp-objdir.c` is updated to set it directly on the loose source. The patch deletes 9 lines and adds 5, with no behavior changes. It’s a clean follow-up to earlier patches in the series (notably 7/13 and 8/13) that absorbed quarantine logic into the files backend.

This is a well-justified refactoring with no downsides. The commit message clearly explains the motivation, and the implementation is straightforward. If you’re following the ODB refactoring effort, this patch is a minor but necessary step toward the series’ architectural goals. There’s nothing controversial here—just a small improvement to keep the codebase tidy.
