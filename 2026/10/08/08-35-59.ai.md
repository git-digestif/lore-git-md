This is patch 9/13 of Patrick Steinhardt’s v2 series refactoring the Git object database (ODB) to move alternates handling into the "files" backend. The patch simplifies the tmp-objdir API by merging the logic for replacing the primary ODB source into `tmp_objdir_create()`, eliminating the need for a separate `tmp_objdir_replace_primary_odb()` call.

The change is a straightforward refactoring of the quarantine directory setup. Previously, callers had to create the tmp-objdir and then explicitly replace the primary ODB source in a two-step process. Now, `tmp_objdir_create()` takes an additional `will_destroy` flag and installs the quarantine directory as the primary write target immediately. The `tmp_objdir` struct replaces its `prev_source` field with `orig_dir` (the original primary directory) and `temp_dir` (the quarantine directory), and the quarantine directory is inserted at the head of the files backend’s linked list of object directories. Callers in `log-tree.c` and `object-file.c` are updated to pass the `will_destroy` flag at creation time.

The patch deletes 49 lines across four files, with the bulk of the changes in `tmp-objdir.c` (removing the now-unused `tmp_objdir_replace_primary_odb()` function and consolidating its logic into `tmp_objdir_create()`). The API change is mechanical: `tmp_objdir_create()` now takes a `will_destroy` argument, and the example in `tmp-objdir.h` is updated to reflect this. The `odb_transaction_files_write_pack()` helper in `object-file.c` is updated to reprepare the whole source instead of just the quarantine directory, since the quarantine directory is now wired up at creation time.

This is a clean, well-motivated refactoring that reduces boilerplate for tmp-objdir users. The change is consistent with the series’ architectural direction (treating alternates and quarantine directories as backend-specific implementation details) and does not introduce new edge cases.
