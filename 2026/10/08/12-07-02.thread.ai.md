Thread identity
Subject: [RFC PATCH 6/6] ls-files: add `--ignored=trashable|precious` support
Series: 6-patch RFC series introducing "precious" files in `git ls-files`
Originating author: Mirko Faina
Thread type: RFC patch series

Core problem or goal
Extend `git ls-files --ignored` to filter ignored files by a new "precious" attribute, allowing users to distinguish between files that are merely ignored (trashable) and those that are ignored but should not be deleted (precious). The patch implements the CLI plumbing and directory traversal logic but does not define how files become "precious" or how this interacts with existing ignore mechanisms (e.g., `.gitignore`, `.git/info/exclude`).

Current status
Under review as an RFC; no prior versions. The series is not yet in Junio’s integration branches. The patch is the final installment of the series and depends on earlier patches (not summarized here) to establish the "precious" concept.

Key technical details
- Files touched: `dir.c`, `dir.h`, `builtin/ls-files.c`, `t3001-ls-files-others-exclude.sh`
- New flags: `DIR_SHOW_TRASHABLE`, `DIR_SHOW_PRECIOUS`
- New data structures: `precious[]` array, `precious_nr` counter
- New helper functions: `is_precious()`, `dir_add_precious()`
- CLI syntax: `--ignored=trashable` (shows only trashable ignored files), `--ignored=precious` (shows only precious ignored files)
- Constraints: `--ignored=<type>` requires `-o` (others) or `-c` (cached); combining both new flags is supported but yields no output (edge case tested)
- No changes to on-disk formats or config keys; the mechanism for marking files as "precious" is not defined in this patch

Open questions and loose ends
- **Design motivation**: What problem does "precious" solve? The commit message and patch do not explain why users need to distinguish trashable vs. precious ignored files, nor how this integrates with existing ignore workflows.
- **Marking mechanism**: How are files designated as "precious"? Is this tied to a new `.gitprecious` file, a config key, or an extension to `.gitignore` syntax? The series’ earlier patches (not yet summarized) may address this, but the current patch does not.
- **Backwards compatibility**: If "precious" is introduced as a new ignore attribute, how does it interact with tools or scripts that expect the existing `--ignored` behavior?
- **Scope of "precious"**: Is this a local-only concept (like `.git/info/exclude`) or intended to be shared across clones (like `.gitignore`)?
- **Performance impact**: The new `precious[]` array and `is_precious()` checks add overhead to directory traversal; is this justified by the use case?
