This is an RFC patch series introducing the concept of "precious files" to Git, based on a design document by Elijah Newren. The series adds a new file attribute type (`precious`) that marks files as important but not version-controlled, preventing their accidental deletion by operations like `git clean` or checkout. The implementation touches core path-matching logic (`dir.c`, `attr.h`), unpack-trees, and adds preliminary support in `git ls-files`.

The series starts with Elijah's design document (patch 1/6), which outlines the motivation and semantics: precious files are meant to protect user-generated files (e.g., build artifacts, IDE metadata) that should persist across branch switches but aren't tracked in the repository. Patches 2-4 refactor pattern handling to support the new attribute, while patches 5-6 implement the core logic and a new `--precious` flag for `git ls-files`. The author notes that `git clean` support is planned but not yet implemented, and documentation is still pending.

Key technical details include:
- A new `enum pattern_type` in `attr.h` replaces macros, adding `PATTERN_TYPE_PRECIOUS`.
- `parse_path_pattern()` and `add_pattern()` in `dir.c` are extended to handle precious patterns.
- `check_ok_to_remove()` in `unpack-trees.c` now respects the precious attribute.
- Tests verify basic functionality (e.g., `t3001-ls-files-others-exclude.sh` adds precious file cases).

The series is clearly exploratory (RFC), with the author seeking feedback before proceeding further. The design document link suggests this builds on prior discussion, but the cover letter doesn't summarize that context. The implementation appears technically sound but is likely to spark debate about whether this is the right approach to protecting untracked files, given Git's existing mechanisms (e.g., `.gitignore`, `git stash -u`). The lack of `git clean` integration and documentation suggests this is an early draft.
