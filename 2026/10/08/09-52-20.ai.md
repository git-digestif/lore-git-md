This is the fourth patch in the v3 series fixing a data-loss race in `git repack -d`. It adds `--keep-pack-from-file=<file>` to `git pack-objects`, allowing callers to specify a large number of packs to keep without hitting command-line length limits.

The new option reads pack names from a file (one per line, empty lines ignored) and treats them exactly like `--keep-pack` arguments: they are matched against local packs, ignored if they don’t exist, and kept open under `--stdin-packs=follow`. Relative paths are resolved against the working directory, matching the behavior of `git multi-pack-index write --refs-snapshot`. The implementation is straightforward: the file is read line-by-line, and each non-empty line is appended to the same `string_list` used by `--keep-pack`. The list now owns its strings (`strdup_strings = 1`), since it holds entries from two sources.

The motivation is scalability: `--keep-pack` is limited by `ARG_MAX` (shared with the environment) and, on Windows, a 32,767-character command-line cap. This becomes a problem in repositories with thousands of kept packs, which `git repack` will soon encounter when it switches to a snapshot-based `.keep` file approach (patch 5/5). The file format is pragmatic and aligns with existing Git tools (e.g., `multi-pack-index write --refs-snapshot`).

The patch includes two tests in `t/t5331-pack-objects-stdin.sh`:
1. A functional test verifying `--keep-pack-from-file` behaves identically to `--keep-pack` (including ignoring empty lines and non-existent packs).
2. An error-handling test confirming the command fails cleanly when the file is missing.

The implementation is minimal and focused: it touches only `builtin/pack-objects.c` and adds 28 lines of code, plus documentation and tests. The change is unlikely to introduce regressions, as it reuses the existing `--keep-pack` logic and does not alter behavior for existing callers. The patch is a necessary enabler for the snapshot-based fix in patch 5/5, which eliminates the race by passing `pack-objects` a static list of `.keep` packs observed at repack startup.
