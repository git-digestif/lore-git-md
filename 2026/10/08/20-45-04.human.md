This is the second patch in a two-part **bugfix series** addressing a long-standing inconsistency in Git’s index refresh logic. The issue is that `git status` incorrectly reports files as modified when line-ending conversions (or other clean filters) rewrite file contents without changing their logical meaning, while `git diff` and `git add` correctly ignore such changes. The first patch fixed the core logic; this one adds a configuration escape hatch.

The patch introduces `core.convertAwareStatus`, a new config option with three modes: `true` (the default, enabling the fix), `no-filter` (applies the fix only to Git’s built-in conversions, not clean filters like Git LFS), and `false` (restores the pre-fix behavior, treating size changes as modifications). The implementation is clean: it adds the config plumbing in `environment.c`, updates `read-cache.c` to respect the setting, and documents the option in `Documentation/config/core.adoc`. The tests in `t/t0020-crlf.sh` verify all three modes, including edge cases like invalid values and clean filters.

This is a well-considered addition. The default preserves the fix’s consistency benefits, while the `no-filter` and `false` modes give users control over performance trade-offs—critical for repositories with expensive filters (e.g., Git LFS on large files). The commit message and documentation are thorough, explaining the rationale and behavior clearly. There’s no obvious downside; the patch is self-contained and doesn’t touch unrelated code. If the first patch lands, this one should too—it’s a necessary complement for users who need to opt out.
