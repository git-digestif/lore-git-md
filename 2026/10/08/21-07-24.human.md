This is the second patch in a two-part **feature series** that makes `git blame` and `git annotate` automatically use `HEAD:.git-blame-ignore-revs` as the default ignore-revs file when no explicit ignore file is configured. The series is now **under active review** and addresses maintainer feedback by splitting the change into two commits: the first hardens the ignore-revs parser and tag-peeling logic (already posted), and this second patch implements the default file lookup.

The patch teaches Git to resolve `HEAD:.git-blame-ignore-revs` via `get_oid_with_context()` and checks the tree entry’s mode with `S_ISREG()` to skip non-regular entries (e.g., committed symlinks). The default blob is added to the ignore-revs list **before** processing configuration and CLI options, ensuring user overrides take precedence. Empty configurations (`blame.ignoreRevsFile=""` or `--no-ignore-revs-file`) bypass the default blob entirely, and the patch handles edge cases like subdirectory invocations, bare repositories, and malformed input gracefully.

Test coverage is **comprehensive**, verifying the default blob’s behavior in subdirectories, bare repos, and with CLI/config overrides, as well as handling committed symlinks, comments, whitespace, and malformed input. The documentation updates clarify the new precedence rules and override semantics.

The patch is **well-motivated** and **technically sound**, aligning local `git blame` behavior with hosting platforms like GitHub and GitLab. The split into two commits improves reviewability, and the design now aligns with Junio’s guidance. The security hardening in the first patch (NUL byte rejection, promisor fetch prevention) is a prerequisite for this change and will need validation from security-interested contributors like Jeff King or brian m. carlson. **Worth attention** for anyone interested in blame workflows or security-sensitive parsing.
