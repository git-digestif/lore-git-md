# Thread deltas

## 2026/10/08

- [2026/10/08/06-56-22 by Christian Noé Ramos López <chris@nortesoftware.dev>] Christian Noé Ramos López reported that git checks SSH signature `valid-before` against the committer/tagger date (which the signer controls) rather than the actual signing time, allowing a backdated commit to bypass key expiry, and that a configured but missing `gpg.ssh.revocationFile` only triggers a warning while verification proceeds without it (failing open), unlike ssh-keygen and sshd which refuse; he asked that git refuse when the revocation file is configured and missing (or document that it is ignored) and document where the time compared against `valid-before` comes from.
- [2026/10/08/13-42-42 by Phillip Wood <phillip.wood123@gmail.com>] Phillip Wood agreed that failing when the revocation file is missing seems like the safer option, and said he would be happy to see a patch tightening the documentation wording for `valid-before`, while noting that the timestamp in a GPG signature can also be faked.

## 2026/10/09

- [2026/10/09/12-19-20 by Patrick Steinhardt <ps@pks.im>] Patrick Steinhardt: on valid-before, there is no proper fix because in a distributed system there is no way to establish the actual time data was signed (upper bounds via subsequent trusted signed commits are not always useful); agreed that documenting that a leaked key makes valid-before/valid-after unable to guarantee anything would avoid a false sense of trustworthiness; for a missing revocationFile, suggested failing by default with a ":(optional)" path prefix as an escape hatch.
- [2026/10/09/13-29-27 by Phillip Wood <phillip.wood123@gmail.com>] Phillip Wood: said the documentation wording patch sounds sensible, since a valid signature does not tell when the commit was signed; said a test for gpg.ssh.revocationFile would be welcome and endorsed Patrick's suggestion of allowing the path to be optional.
- [2026/10/09/13-30-03 by Phillip Wood <phillip.wood123@gmail.com>] Phillip Wood: agreed that checking a signature only shows the commit was signed by that key, not when it was signed; called Patrick's ":(optional)" prefix idea good.
