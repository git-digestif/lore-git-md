This is a **CI/build system** patch in Patrick Steinhardt’s eight-part series modernizing Git’s CI configurations. Junio C Hamano’s reply to the final patch (8/8) identifies a **substantive gap in test coverage**: removing the `linux-reftable` job eliminates the only CI job that exercised the reftable backend with foreign-SCM interoperability tests (CVS, SVN, Perforce). The `linux-reftable-leaks` job explicitly disables these tests via `NO_{CVS,SVN,PR}_TESTS` in `ci/lib.sh`, so the series as merged would leave reftable untested against these tools.

The observation is factual and technical, not editorial. Junio does not object to the removal in principle but flags the coverage regression as something that should be documented (or justified) in the commit message. The patch itself is otherwise uncontroversial, and the series has already been validated in CI. Expect Patrick to address this in a reroll by either restoring the coverage (e.g., enabling foreign-SCM tests in `linux-reftable-leaks`) or explicitly documenting the trade-off in the commit message. The discussion is now focused on **what the project considers acceptable test coverage for reftable**, not on the patch’s mechanics.
