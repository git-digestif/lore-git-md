This is the eighth and final patch in Patrick Steinhardt’s CI housekeeping series. It removes the `linux-reftable` job from both GitHub Actions and GitLab CI workflows, along with a small cleanup in `ci/run-build-and-tests.sh`.

The rationale is straightforward: the `linux-reftable` job is redundant because the `linux-reftable-leaks` job already exercises the reftable backend with leak sanitizer enabled. The author argues that running the same backend without leak detection is unlikely to catch additional bugs, so the extra job adds no value and only increases CI complexity. The patch deletes three lines from each workflow file and updates a case statement in the build script to reflect the job’s removal.

This change is mechanical and uncontroversial. The series as a whole has already been validated in both GitHub and GitLab CI, and this patch simply removes an unnecessary job without altering any remaining functionality. The only potential discussion point would be whether anyone still relies on the `linux-reftable` job for debugging or local testing, but the commit message makes a reasonable case that the coverage overlap with `linux-reftable-leaks` is sufficient. Expect any follow-up to focus on the job name (`linux-reftable`) and the reftable backend itself, though the patch itself is unlikely to generate significant pushback.
