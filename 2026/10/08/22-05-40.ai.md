This email advances the ongoing discussion about incremental rebase conflict resolution by demonstrating how Alejandro Colomar’s `git-bisect-rebase` script handles complex workflows involving interdependent branches. The key development is the introduction of `--abort`, `--continue`, and `--quit` options in `git-bisect-rebase`, which provide finer-grained control over the rebase process than Git’s built-in commands. These options allow users to pause, restart, or exit the bisection-based rebase at any point, enabling the manual management of branch trees—a requirement Colomar argues is non-negotiable for his use case.

The email includes a detailed shell session showing how these options work in practice. For a single branch, the workflow is straightforward: resolve conflicts, run `git rebase --continue`, and then `git bisect-rebase --continue` to advance to the next conflicting commit. For a tree of branches, the workflow becomes more involved, with the user manually switching between branches, resolving conflicts, and using `--quit` to pause the rebase on one branch before moving to its descendants. Colomar’s example demonstrates that this manual control is essential for handling complex dependency graphs, as it allows the user to rebase branches in a specific order and verify changes incrementally.

Colomar’s implementation directly addresses Phillip Wood’s earlier proposal to extend `git rebase --update-refs` to automate rebasing interdependent branches. While Phillip’s suggestion aimed to reduce manual intervention, Colomar argues that the multi-shot approach is safer and more adaptable for complex cases, as it avoids the risk of automating steps that might require human judgment. The new options in `git-bisect-rebase` provide a middle ground: they retain manual control while streamlining the process with dedicated commands for common operations.

The email also clarifies the distinction between `git-bisect-rebase` and Phillip’s `--update-refs` proposal. Colomar’s script is designed for users who need to manage branch trees manually, while `--update-refs` would target users who prefer automation. The two approaches are complementary rather than competing, though Colomar’s latest feedback suggests that the manual workflow is more robust for his needs.

Key technical details include the behavior of the new options:
- `--abort` returns to the original HEAD and cleans up temporary state.
- `--continue` restarts the entire bisection process, requiring the current rebase to be resolved first.
- `--quit` exits the session without moving HEAD or the branch, allowing the user to switch branches and return later.
