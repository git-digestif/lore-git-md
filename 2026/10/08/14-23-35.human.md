This is a bugfix for `git repack` that addresses a regression in the `--dry-run` behavior when combined with `--drop-filtered`. Junio C Hamano, the maintainer, has replied to Siddharth Shrimali’s patch with a request for additional historical context: he asks whether the bug was present from the beginning or introduced as a side effect of unrelated changes, and suggests bisecting to identify the breaking commit for inclusion in the commit message.

The patch itself remains unchanged in this reply. It adds an early `return` in `cmd_repack()` to prevent the `--dry-run` block from falling through into the regular repack code, which would otherwise rebuild packs and delete old ones despite the `--dry-run` flag. The fix is minimal and well-scoped, touching only `builtin/repack.c` and adding a new test to verify the pack directory remains unchanged under `--dry-run`. The test covers both explicit (`-d`) and implicit deletion cases, ensuring thorough coverage.

Junio’s request is procedural rather than technical—he is not questioning the correctness of the fix, but asking for a more complete historical record. This is a common maintainer practice in Git development, where understanding when and how a regression was introduced helps prevent similar issues in the future. The patch is otherwise ready for integration, pending Siddharth’s response to the bisect request. No other objections or edge cases have been raised in the thread so far.
