This thread is about a patch series from Patrick Steinhardt that modernizes Git's CI configurations by removing outdated dependencies, eliminating redundant jobs, and updating supporting scripts. The series, now at version 3, consists of 8 patches targeting GitHub Actions and GitLab CI workflows, along with minor test adjustments. The goal is to reduce complexity and improve reliability without changing user-visible behavior.

The most recent update resolves the last open issue from the previous version: the naming of the `linux-TEST-vars` job, which tests Git with non-default configuration options. After Junio C Hamano proposed 14 alternative names and expressed a preference for `linux-feature-testbed`, Patrick agreed to adopt this name, calling it a clear and accurate description. This mechanical rename (affecting three files) removes the ambiguity that SZEDER Gábor criticized in the earlier `linux-exotic` proposal. The job itself remains unchanged, continuing to exercise Git with options like `OPENSSL_SHA1_UNSAFE` and `GIT_TEST_SPLIT_INDEX`.

Other key changes in the series include repurposing the `linux-reftable-leaks` job to test reftable with SHA-256 (now called `linux-reftable-sha256`), preserving foreign-SCM interoperability coverage in the original `linux-reftable` job. The series also updates Docker images to supported versions (e.g., replacing `i386/ubuntu:20.04` with `i386/debian:latest`), removes Python 2 support, and cleans up dead code. Junio has endorsed the SHA-256 coverage trade-off, and the series is now ready for review with all major objections addressed. The discussion underscores the project's attention to clear naming and balanced test coverage in CI workflows.
