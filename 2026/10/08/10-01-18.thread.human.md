Patrick Steinhardt’s CI housekeeping series is now in its third iteration, aiming to modernize Git’s CI configurations by removing outdated dependencies, simplifying job definitions, and improving reliability. The v3 series consists of eight patches that touch GitHub Actions, GitLab CI, and supporting scripts, with no new functionality but a net reduction in complexity (20 insertions, 39 deletions). Key changes include renaming the `linux-TEST-vars` job to `linux-feature-testbed` (resolving a naming dispute), repurposing the `linux-reftable-leaks` job to test reftable with SHA-256, removing Python 2 support, and updating Docker images to use longer-supported tags like `i386/debian:latest` and `ubuntu:latest`.

The series is under active review, with most feedback now resolved. Junio C Hamano endorsed the reftable/SHA-256 coverage trade-off and the `ubuntu:latest` update, while SZEDER Gábor’s objection to the `linux-exotic` rename was addressed by adopting Junio’s preferred `linux-feature-testbed` name. The only remaining substantive open question is Jeff King’s (Peff) feedback on the test design in patch 1/8, where he proposes making the SHA-1-specific test in `t/t5004-archive-corner-cases.sh` self-contained by creating a temporary SHA-1 repository, rather than relying on a `SHA1` prerequisite. This could influence the test’s long-term maintainability as Git transitions to SHA-256.

The latest review from Peff introduces a new technical concern about patch 4/8, which replaces the `i386/ubuntu:20.04` image with `i386/debian:latest`. Peff questions whether the Debian image provides equivalent support for Icelandic locale tests (`is_IS`), which are used to verify Git’s handling of non-ASCII commit messages and error messages. If the Debian image lacks the `language-pack-is` package, the `linux32` job could silently skip these tests, creating a gap in coverage. This is a forward-compatibility issue that could affect the reliability of the CI pipeline, though it doesn’t challenge the patch’s core motivation. The resolution will likely depend on whether the Debian image includes the necessary locale packages by default or if the CI scripts need to explicitly install them. For now, the series remains uncontested and ready for further review, with this new question as the primary loose end.
