This is an RFC patch series introducing the concept of "precious files" to Git, based on a proposal document by Elijah Newren. The series adds a new file type that sits between tracked and untracked files, aiming to protect important but untracked files (like build artifacts or editor backups) from accidental deletion by commands like `git clean`.

The series starts with a new technical document (patch 1/6) outlining the motivation and design, then makes preparatory changes to pattern handling (patch 2/6), implements core parsing logic (patches 3-4/6), teaches `unpack-trees` to respect precious files (patch 5/6), and adds basic `ls-files` support (patch 6/6). The author notes documentation isn't yet updated and seeks feedback before proceeding with `git clean` implementation.

The implementation touches several core areas: directory traversal (`dir.c`), attribute handling (`attr.h`), and the index/unpack-trees machinery. The test coverage appears light but covers basic functionality. This is clearly an early-stage proposal - the RFC tag and explicit call for feedback suggest the design may still evolve significantly. The concept itself (protecting important untracked files) addresses a real pain point, but the implementation's invasiveness across multiple subsystems will likely spark discussion.
