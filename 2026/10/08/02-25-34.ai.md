This is a **bugfix** for `git repack` that addresses a violation of the `--dry-run` contract. The author of the `--drop-filtered` feature, Siddharth Shrimali, confirms the bug reported by Coy Geek and analyzed by D. Ben Knoble: when `git repack --dry-run --drop-filtered` is invoked, it incorrectly writes new promisor packs and (with `-d`) deletes old packs, despite the manual's guarantee that `--dry-run` will only list candidate objects without making changes.

Shrimali traces the root cause to `builtin/repack.c`: the `dry_run` flag guards the `delete_redundant` logic but execution continues into `repack_promisor_objects()` and `existing_packs_remove_redundant()`, which write and delete packs unconditionally. The fix is minimal: after printing candidate object IDs in the `dry_run` block, return early with `ret = 0; goto cleanup;` to prevent any side effects. Shrimali also plans to add a test in `t/t7706-repack-drop-filtered.sh` to verify that the pack directory remains unchanged and the candidate is still printed.

The patch will target the `repack` subsystem, specifically the `finish_repack` code path in `builtin/repack.c`. Key technical details include the affected files (`.pack`, `.idx`, `.promisor`, `.rev`) and the fact that no data is lost (blobs remain accessible). The fix is uncontroversial and aligns with the existing `--dry-run` behavior in other Git commands. Shrimali's confirmation and planned test coverage suggest this is a well-scoped, high-priority bugfix likely to be merged quickly.
