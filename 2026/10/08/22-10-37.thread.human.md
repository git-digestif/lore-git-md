This thread is about a bugfix series from Karthik Nayak that addresses a performance regression in shallow fetches when backfilling tags, introduced by a recent change to batched reference updates. The regression caused clients to report no 'have' references during negotiation, forcing servers to send all objects—a significant slowdown.

The series is now in its sixth iteration (v6), consisting of three patches. The core fix exposes pending transaction state via the transport's `negotiation_include_tips` field, restoring correct 'have' reporting while preserving atomicity for `--atomic` fetches. A precursor patch fixes a pre-existing memory leak in the remote-helper transport's cleanup path, and the series includes tests to verify the fix and edge cases like rejected updates.

The latest update (v6) is a minor re-roll addressing surface-level feedback from Patrick Steinhardt: the commit ordering was adjusted for narrative clarity, and a commit message was tweaked for precision. No technical changes were made. All substantive review feedback has been addressed, including a memory management blocker from v4. The series is now ready for maintainer review, with Junio C Hamano's position still pending. Karthik has confirmed he won’t re-roll further unless new feedback arrives. The scalability trade-off (advertising all fetched references during negotiation) is documented as acceptable.
