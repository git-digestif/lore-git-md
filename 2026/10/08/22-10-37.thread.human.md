This thread is about a bugfix for a performance regression in Git's fetch subsystem, specifically affecting shallow fetches when backfilling tags. The issue was introduced in a recent commit that switched to batched reference updates, which delayed committing references to disk until after tag backfilling began. This caused shallow fetches to lose track of what objects the client already had, forcing the server to resend the entire repository history during tag backfilling.

Karthik Nayak proposed a fix that splits the reference transaction into two parts—one for fetched references and another for backfilled tags—restoring correct negotiation behavior while preserving most of the performance gains from batched updates. Benchmark results show the fix is nearly 18 times faster than the pre-batched-update behavior. The patch touches `builtin/fetch.c` and includes a new test in `t/t5510-fetch.sh` to verify the fix.

The solution is narrowly targeted at shallow fetches with tags, avoiding broader changes that might introduce new risks. The commit message credits Mitja Bezenšek for reporting the issue and clearly explains the trade-offs involved. There are no open questions or objections in the thread so far, suggesting this is likely to be accepted once reviewed.
