This thread is about a bugfix for a performance regression in shallow fetches when backfilling tags, introduced by batched reference updates in May 2025. The regression caused the client to report no "have" references during negotiation, forcing the server to send all objects. Karthik Nayak posted the fourth iteration (v4) of the patch, which now adopts Patrick Steinhardt’s proposed design: instead of splitting the reference transaction into two phases (as in v3), it exposes already-fetched refs to negotiation by adding their tips to the transport’s `negotiation_include_tips` field. This approach restores correct "have" reporting, preserves atomicity for `--atomic` fetches, and avoids the performance overhead of intermediate commits.

The patch touches `builtin/fetch.c` and adds three new tests to `t/t5510-fetch.sh`, covering atomic and non-atomic flows and ensuring upstream tracking info is set even when sibling refs are rejected. All prior review feedback—including edge cases around empty transactions, error handling, and `--atomic` fetches—has been addressed. The new design is cleaner and more robust than the v3 two-transaction approach, and the patch appears ready for Junio’s `next` branch unless new concerns emerge about the `negotiation_include_tips` mechanism. Key participants include Karthik (author), Patrick (who proposed the new design), Justin Tobler (who raised substantive questions about error handling in v3), and Junio (maintainer), whose input on the new approach is still pending. The thread is now focused on finalizing this version for integration.
