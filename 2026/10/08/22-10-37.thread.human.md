This thread is about a bugfix patch series (now at v3) by Karthik Nayak that addresses a performance regression in shallow fetches when backfilling tags. The regression was introduced in May 2025 by a patch that batched reference updates, causing shallow fetches to report no 'have' references during negotiation and forcing the server to resend all objects. The fix splits reference transactions into two phases—committing fetched references before backfilling tags—to restore correct negotiation behavior while preserving most of the performance gains from batched updates.

The v3 patch resolves edge cases raised during review, including handling empty transactions, improving error handling, and adding test coverage for key scenarios. Benchmarks show the fix is 17× faster than the pre-batched-update behavior and only marginally slower than the single-transaction approach. The patch has received substantive feedback from Junio C Hamano, Patrick Steinhardt, and Justin Tobler, with all prior concerns now addressed. It touches `builtin/fetch.c` and adds tests to `t/t5510-fetch.sh`, documenting trade-offs like the inherent limitation with `--atomic` fetches.

The patch is now closer to being ready for Junio’s `next` branch, pending any final review comments. The fix is well-tested, backward-compatible, and motivated by a real-world performance issue affecting shallow fetches.
