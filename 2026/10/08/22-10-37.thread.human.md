This thread is about a bugfix patch series (v5) by Karthik Nayak that addresses a performance regression in shallow fetches when backfilling tags. The regression was introduced by a recent change to batched reference updates, which delayed committing references until after tag backfilling, causing the client to report no 'have' references during negotiation and forcing the server to send all objects. The fix exposes pending transaction state via the transport's `negotiation_include_tips` field, restoring correct 'have' reporting while preserving atomicity for `--atomic` fetches.

The series is now technically complete and ready for maintainer review. The memory management blocker from v4 has been resolved by a precursor patch introducing `transport_options_release()`, ensuring proper cleanup for all transport types. Patrick Steinhardt, who proposed the design adopted in v4/v5, has provided surface-level feedback on commit ordering—suggesting the test for upstream tracking persistence should come before the core fix for narrative clarity. Karthik has agreed to make this change locally but won’t re-roll the series unless other feedback arrives. Junio C Hamano’s review is the only remaining step before the series can be queued for `next`.

Key participants include Karthik (author), Patrick Steinhardt (reviewer who proposed the design and resolved the memory management issue), Justin Tobler (reviewer whose substantive concerns were addressed in v4/v5), and Junio (maintainer, whose review is pending). The series touches `builtin/fetch.c`, `transport-helper.c`, `transport.c`, and `transport.h`, and adds three new tests to verify 'have' reporting and upstream tracking persistence. No open technical questions remain.
