This thread is about a three-patch bugfix series (v6) from Karthik Nayak that fixes a performance regression in shallow fetches when backfilling tags. The regression was introduced by a recent change to batched reference updates, which delayed committing references until after tag backfilling, causing the client to report no 'have' references during negotiation and forcing the server to send all objects. The fix exposes the OIDs of just-fetched refs via the transport's `negotiation_include_tips` field, restoring correct 'have' reporting while preserving atomicity for `--atomic` fetches.

The series has been through several iterations, with the latest version reordered for clarity and addressing all prior feedback. The memory management concern that blocked earlier versions has been resolved by a precursor patch introducing `transport_options_release()`, ensuring proper cleanup for all transport types. Patrick Steinhardt, who proposed the design, and Justin Tobler have both reviewed the changes and are satisfied with the current state. The series is now ready for maintainer review, with Junio C Hamano's position the only remaining unknown.

The core fix is in `builtin/fetch.c` and adds two new tests to verify 'have' reporting during tag backfilling for both atomic and non-atomic flows. The scalability trade-off—advertising all fetched references during negotiation—is documented as acceptable O(n) complexity. No further changes are expected unless Junio raises new concerns.
