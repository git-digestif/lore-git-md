This thread is about a bugfix series from Karthik Nayak that addresses a performance regression in shallow fetches when backfilling tags. The issue arose after batched reference updates were introduced, causing the client to report no "have" references during negotiation and forcing the server to resend all objects. The fifth iteration of the patch (v5) is now split into three commits to resolve a memory management blocker, with the core fix in the second patch.

The solution exposes pending transaction state via the transport's `negotiation_include_tips` field, restoring correct "have" reporting while preserving atomicity for `--atomic` fetches. The series has addressed all prior review feedback, including Patrick Steinhardt's memory management concern, and is now ready for Junio C Hamano's review. The design avoids the complexity of the earlier two-transaction approach and documents the acceptable O(n) scalability trade-off for fetched refs.

Key participants include Karthik Nayak (author), who implemented the fix and resolved the memory management issue; Patrick Steinhardt (reviewer), who proposed the design and confirmed the memory management concern is now resolved; and Justin Tobler (reviewer), who previously raised questions about error-path logic and GC safety, both of which have been addressed. Junio has not yet reviewed the latest iteration but has no outstanding technical objections. The series is now blocked only on his final review before it can proceed to the `next` branch.
