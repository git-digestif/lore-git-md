This thread is about a bugfix patch (v2) by Karthik Nayak that addresses a performance regression in shallow fetches when backfilling tags, introduced by a recent change to batched reference updates. The patch splits reference transactions into two—one for fetched references and another for tag backfilling—to restore correct negotiation behavior while preserving most of the performance gains from batched updates. The fix has been reviewed by Patrick Steinhardt and Justin Tobler, who confirmed its correctness and addressed their feedback in v2.

Junio C Hamano has now raised three substantive questions about edge cases in the patch. First, he asks whether the regression can occur even when the main fetch transaction is empty (no refs updated), which could mean the fix needs to handle cases where tag backfilling is the only work being done. Second, he notes that the patch skips the two-transaction fix when `--atomic` is used, which might force atomic fetches into full clones if tag backfilling triggers the same negotiation issue. Finally, he points out a control-flow issue where the patch jumps to `cleanup` on transaction failure, potentially skipping necessary post-fetch steps like writing `FETCH_HEAD` or setting upstream configuration, even if the primary fetch succeeded. These questions suggest the patch may need further refinement before it’s ready for `next`. Karthik will likely need to clarify or adjust the logic to address these concerns.
