This thread is about a bugfix patch series (now at v2) by Karthik Nayak that addresses a performance regression in shallow fetches when backfilling tags. The regression was introduced by a recent change to use batched reference updates, which delayed committing references until after tag backfilling, causing clients to report no 'have' references during negotiation and forcing servers to send all objects.

The fix splits the reference transaction into two—one for fetched references and one for backfilled tags—to restore correct negotiation behavior while preserving most of the performance gains. Junio C Hamano’s review of v2 raised concerns about edge cases, including empty main transactions, `--atomic` fetches, and cleanup path control flow. Karthik has now responded, clarifying that the regression cannot occur with empty transactions (since there are no refs to report) and documenting the inherent limitation with `--atomic` fetches. The most significant adjustment is splitting the return code handling to ensure post-fetch steps (like writing `FETCH_HEAD`) execute even if the tag backfill fails.

The test case is being reverted to its original version after Karthik found the current version fails to catch the regression, suggesting the test coverage may need rethinking. The patch is likely headed for a v3 iteration to incorporate these adjustments before it can be considered for Junio’s `next` branch. The discussion remains focused on robustness rather than the fundamental approach, which has already been validated by Patrick Steinhardt and Justin Tobler.
