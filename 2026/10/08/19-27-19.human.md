This is the fourth patch in a five-patch documentation series that converts Git’s `BreakingChanges` document into a proper manpage (`gitbreaking-changes(7)`). The series aims to make upcoming breaking changes more visible to end users, who are most affected but least likely to follow development discussions.

This specific patch adds a short note (an AsciiDoc admonition) to the new manpage, clarifying that the document is a "living document" subject to change. The note warns readers viewing a released version that the content may have been updated in the development version, preventing potential confusion or outdated feedback. The example in the commit message illustrates the risk: a user on an older release might read about breaking changes for Git 3.0, disagree with a point, and post feedback—only to learn that Git 3.0 was released years ago and the current document now targets Git 4.0.

The change is minimal and targeted: it adds ten lines to `Documentation/gitbreaking-changes.adoc`, following the existing "living document" paragraph. The note is concise and avoids prescribing how users should fetch the latest version, keeping the focus on awareness rather than mechanics. This aligns with the series’ broader goal of improving usability without overcomplicating the documentation.

The patch is well-motivated and uncontroversial. The note addresses a real concern—users encountering stale information—and does so without cluttering the document. The series as a whole is now technically complete, with all reviewer feedback incorporated, and is ready for integration. The only remaining work is resolving merge conflicts with two in-flight topics (`ps/ref-storage-format` and `bc/restrict-hex-to-lowercase`), which will require moving their additions from the old `BreakingChanges.adoc` to the new manpage. No test coverage is needed, as this is a documentation-only change.
