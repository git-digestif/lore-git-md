This thread is an RFC patch series by Mirko Faina proposing a new "precious files" attribute for Git, aimed at preventing accidental deletion of untracked but important files (like build artifacts or IDE metadata) during operations like `git clean` or checkout. The series includes a detailed design document by Elijah Newren and a set of preparatory refactoring patches.

So far, the series has introduced the core concept via a ternary state in `.gitignore` (precious `$`, untracked `!`, trashable unmarked) and begun refactoring the path-matching code to support it. The latest patch (4/6) adds safeguards to reject precious-file patterns in disallowed contexts, such as the sparse-checkout file, with a new `disable_precious` flag and corresponding tests. The implementation is incremental, with `git clean` support and broader command coverage (e.g., `git reset`) explicitly deferred.

The main open question remains whether the proposed design—particularly the ternary `.gitignore` syntax and command-specific behaviors—is the right approach, given existing alternatives like `git stash -u`. Edge cases around `--force` flags, submodules, and backward compatibility are also unresolved. The refactoring patches (2-4/6) are tightly coupled to the eventual acceptance of the feature, so their value hinges on the community’s reception of the core idea. So far, only Mirko and Elijah (via the design document) have engaged, leaving the broader discussion still ahead.
