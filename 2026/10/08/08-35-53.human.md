This is the third patch in Patrick Steinhardt’s 13-patch series refactoring the Git object database (ODB) to move alternates handling into the "files" backend. The series is part of the ongoing ODB abstraction effort, and this patch introduces a foundational data structure, `struct odb_files_dir`, to encapsulate both loose and packed object storage for a single object directory.

The patch is a mechanical refactoring that prepares for later changes by introducing `struct odb_files_dir`, which groups the loose and packed backends under a single entity. Currently, every "files" ODB source has exactly one such directory, but future patches will extend this to a linked list to manage multiple directories (e.g., alternates). The changes are widespread but straightforward: 19 files are touched, with most modifications replacing direct access to `files->loose` and `files->packed` with `files->dirs->loose` and `files->dirs->packed`. The patch also adds helper functions (`odb_files_dir_new` and `odb_files_dir_free`) to manage the new structure.

This is a well-crafted refactoring step with no behavior changes. The commit message clearly explains the motivation and future direction, and the code changes are minimal and focused.
