This is a **feature patch** (v2 1/2) that extends `git branch --delete-merged` to detect branches whose changes were integrated via squash merges, rebases, or patch-based workflows—even when the branch tip itself isn’t reachable from upstream. The patch is part of a two-patch series that addresses performance, correctness, and usability concerns raised in v1, while introducing a `--no-squashed` flag (added in patch 2/2) to disable the slower squash detection for performance-sensitive workflows.

The implementation now batches diff calculations and reuses results across branches, resolving Phillip Wood’s concern about recalculating upstream diffs for each branch. It also fixes a correctness bug where merged branches were incorrectly attributed to a merge commit if another branch was searched first. The output now correctly shows the topic commit itself for work integrated via merges (e.g., `Deleted branch topic (was 1a2b3c4, landed as 9f8e7d6)`). The patch handles edge cases like upstream modifying the same files as the squashed branch, reverted changes, and partial landings, with expanded test coverage in `t/t3200-branch.sh`.

Key technical details include:
- **Files touched**: `builtin/branch.c` (332 lines added, 24 removed) and `Documentation/git-branch.adoc` (15 lines added).
- **New behavior**: The `--delete-merged` option now detects squash merges, rebases, and patch-based integrations by comparing tree diffs and simulating three-way merges. The algorithm precomputes changes for each branch and checks upstream commits in reverse chronological order to find the first commit containing all changes.
- **Performance optimizations**: Uses a `changed_paths` commit slab to cache diff results and avoid redundant calculations. The `find_landed_commits` function processes all branches in a single pass, sharing diff results across searches.
- **Edge cases**: Handles upstream modifications to the same files as the squashed branch, reverted changes, and mixed workflows (e.g., a branch whose changes were partially reverted upstream is still deleted if its work landed in an earlier commit).
- **Test coverage**: New tests in `t/t3200-branch.sh` verify behavior for local `git merge --squash`, GitHub-style squash merges, rebases, and upstream file modifications.

The patch is **ready for substantive review**—it addresses prior feedback, includes comprehensive tests, and tackles a real-world pain point for users of hosting services like GitHub. The performance optimizations and edge-case handling are likely to spark further discussion, but the core functionality is well-motivated and technically sound. The `--no-squashed` flag (introduced in patch 2/2) provides a documented escape hatch for performance-sensitive workflows, though the default behavior remains unchanged.
