This is a **bugfix** for `imap-send.c`, targeting OpenSSL compatibility. The patch updates two functions (`host_matches` and `verify_hostname`) to stop assuming that `ASN1_STRING` payloads are null-terminated. Instead, it uses `ASN1_STRING_length` to determine the string length and switches to `strncasecmp` and length-limited string formatting.

The motivation is clear: OpenSSL derivatives like BoringSSL are moving away from null-terminating `ASN1_STRING` data, which could break Git’s IMAP TLS hostname verification. The change is minimal and focused, touching only the necessary code paths. The commit message explains the technical rationale well, and the patch itself looks clean and well-scoped.

This is a standalone patch, not part of a larger series. It addresses a real compatibility risk and is likely to be uncontroversial, though it may attract review from contributors familiar with the IMAP or crypto subsystems. Worth watching if you care about platform compatibility or OpenSSL-related changes.
