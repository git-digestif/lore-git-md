This is a documentation patch updating `Documentation/SubmittingPatches` to codify a long-standing review preference: contributors should avoid the "add a failing test and fix it in a subsequent commit" pattern when submitting patches. Instead, the test and its corresponding code change should be introduced in a single commit. The patch adds a clear, concise explanation under the `[[tests]]` section, noting that while `test_expect_failure` is useful for local development, it should not be submitted as a standalone commit because it obscures the relationship between the test and the fix during review.

The change is well-placed and well-written, directly addressing a common source of review friction. It aligns with the existing guidance on commit granularity while providing a practical exception to the "separate commits" rule when it would harm reviewability. The patch does not include specific examples of past discussions where this preference was stated, but Kristoffer Haugsbakk (the reviewer) suggests adding them, which would strengthen the rationale.

This is a minor but useful clarification that reflects actual project norms. It is unlikely to be controversial and should be uncontroversial to merge. The patch touches only documentation and does not affect code behavior.
