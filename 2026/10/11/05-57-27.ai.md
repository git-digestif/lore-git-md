This is a maintainer integration note for a bugfix that is now ready for wider testing. Junio C Hamano has marked the topic—`git repack --drop-filtered --dry-run` regression fix by Siddharth Shrimali—for inclusion in the `next` branch after D. Ben Knoble confirmed he is satisfied with the v2 patch and provided his `Reviewed-by`.

The patch itself is unchanged from the parent email: it adds an early `return` in `cmd_repack()` after listing candidate objects for dropping, preventing the code from proceeding to the actual repack and deletion steps when `--dry-run` is used. The regression, which has existed since `--dry-run` was introduced in commit `1e746b00aa` (2025), causes `git repack --drop-filtered --dry-run` to incorrectly rebuild packs and delete old ones despite the `--dry-run` flag. The fix is minimal, well-tested, and aligns with existing patterns in the codebase.

No further discussion or changes are expected; the topic is now cooking in `next` and will likely graduate to `master` in the next integration cycle unless integration issues surface. The patch touches only `builtin/repack.c` and adds a new test in `t/t7706-repack-drop-filtered.sh` that verifies the pack directory remains unchanged under `--dry-run`. The commit message clearly documents the regression’s origin, and the in-code comment has been reworded to avoid proposal-like language. All review feedback has been incorporated.
