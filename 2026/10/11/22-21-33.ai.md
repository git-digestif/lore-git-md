This is the second patch in the v3 series implementing the default `HEAD:.git-blame-ignore-revs` feature for `git blame`. It introduces the core functionality: automatically reading the committed `HEAD:.git-blame-ignore-revs` blob as the initial ignore-revs file when no explicit file is configured, aligning local behavior with hosting platforms like GitHub and GitLab.

The patch adds the default file lookup logic to `builtin/blame.c`, ensuring the `HEAD:.git-blame-ignore-revs` blob is parsed before any user-configured ignore files. Key technical details include:
- **Default file resolution**: Uses `get_oid_with_context()` to resolve `HEAD:.git-blame-ignore-revs` and `S_ISREG()` to skip non-regular tree entries (e.g., symlinks, subdirectories).
- **Precedence handling**: The default blob is added to the ignore-revs list **before** user-configured files, preserving override semantics. Empty entries in `blame.ignoreRevsFile` or `--ignore-revs-file ""` bypass the default blob entirely.
- **In-memory parsing**: Introduces `oidset_parse_buffer_carefully()` (moved from patch 1/2) to parse the blob’s contents, sharing line-parsing logic with the existing file-based parser.
- **Edge cases**: Handles subdirectory invocations, bare repositories, uncommitted working-tree changes, committed symlinks, and malformed input (e.g., invalid OIDs, NUL bytes).

The patch touches `builtin/blame.c`, `oidset.c`, `oidset.h`, and updates documentation (`blame-options.adoc`, `config/blame.adoc`). Test coverage in `t/t8013-blame-ignore-revs.sh` is comprehensive, validating the default blob’s behavior across scenarios like CLI/config overrides, bare repos, and malformed input.

This patch is technically sound and addresses all maintainer feedback from v2, including the `the_repository` cleanup. The design aligns with Junio’s guidance, and the implementation is clean and well-tested. The only remaining procedural decision is whether to retain the NUL-byte check (addressed in patch 1/2), but this does not affect the default file lookup logic. The patch is ready for broader review, particularly from contributors familiar with the blame subsystem or security implications of ignore-file parsing.
