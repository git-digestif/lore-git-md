This is a maintainer acknowledgment of the v3 series for the `git blame` default ignore-revs file feature. Junio confirms that the `the_repository` cleanup requested in his earlier review has been addressed in v3 (Ravi Mistry replaced the global variable with `sb->repo` in `parse_default_ignore_revs_blob()`), and he now considers the series technically sound. He plans to mark the topic ready for the `next` integration branch unless objections arise in the next few days.

The series implements two key changes: (1) security hardening of the ignore-revs parser and tag-peeling logic (rejecting malformed input and preventing promisor fetches in partial clones), and (2) automatic use of `HEAD:.git-blame-ignore-revs` as the default ignore file when none is configured. The hardening includes optional NUL-byte rejection, which Junio has previously questioned but not demanded be removed. The author has signaled willingness to drop this check if Junio prefers.

No new technical objections or security concerns have been raised since v3 was posted. The patch is feature-complete, well-tested (including new tests for NUL bytes and partial-clone tag peeling), and aligns with hosting platform conventions (GitHub, GitLab). The only remaining procedural decision is Junio’s preference on the NUL-byte check. The series is now effectively approved for integration pending a final decision on that point and any last-minute community feedback.
