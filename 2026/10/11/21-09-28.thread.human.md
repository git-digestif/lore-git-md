This thread is about a bugfix for `imap-send.c` that prevents potential buffer overreads or crashes during TLS certificate validation by avoiding an unsafe assumption about OpenSSL’s `ASN1_STRING` data being null-terminated. The patch, authored by Xiangfei Ding, updates two functions (`host_matches` and `verify_hostname`) to use bounded comparisons instead of relying on null termination, which is not guaranteed by the OpenSSL specification.

The patch is under review, with Junio C Hamano providing substantive feedback on commit message clarity and minor code hygiene issues. Aniket Gupta later flagged a build-breaking deprecation warning in OpenSSL 4.1.0-beta2 due to the use of `ASN1_STRING_length`, which should be replaced with `ASN1_STRING_get_length`. The thread has since become entangled with Beat Bolli’s September 7 series, which also modifies `host_matches()`, raising coordination concerns. Junio’s latest response clarifies that Bolli’s series is not yet ready to land, as it requires rework, leaving Xiangfei’s patch free to proceed independently—provided it addresses the deprecation warning and any remaining feedback.

The patch touches only `imap-send.c` and does not alter on-disk or network formats, nor does it include new test coverage. The main open questions are whether to adopt `ASN1_STRING_get_length` now or defer to Bolli’s series, and how to reconcile the overlapping changes to `host_matches()`. The thread remains under review, with no indication of merge status changes.
