This thread is about a bugfix patch from Xiangfei Ding that addresses a latent correctness issue in `imap-send.c`, where two functions incorrectly assume OpenSSL’s `ASN1_STRING` data is null-terminated. This assumption could lead to buffer overreads or crashes with upcoming changes in OpenSSL derivatives like BoringSSL. The patch replaces unsafe string handling with bounded comparisons and length checks, but it now faces a new challenge: a build-breaking deprecation warning in OpenSSL 4.1.0-beta2 due to the use of `ASN1_STRING_length` (deprecated in favor of `ASN1_STRING_get_length`).

Junio C Hamano reviewed the patch substantively, focusing on commit message clarity and minor code hygiene issues, while Aniket Gupta flagged the OpenSSL 4.1.0 deprecation warning. The patch was initially thought to need coordination with Beat Bolli’s September series, which also modifies `host_matches()`, but Junio clarified that Bolli’s series isn’t ready to land, so the patch could proceed independently. However, Beat Bolli has now announced he’s working on a new branch that would replace the low-level ASN.1 certificate validation code entirely, making both Xiangfei’s patch and his own September series obsolete. Until this new branch lands, Xiangfei’s patch remains the only concrete fix for the OpenSSL 4.1.0 deprecation and the buffer overread risk. The thread is still under review, with no merge status change, but the discussion has shifted toward a potential architectural overhaul.
