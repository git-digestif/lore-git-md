This thread is about a small but important bugfix to `imap-send.c` that prevents potential buffer overreads during TLS certificate validation. The patch, submitted by Xiangfei Ding, addresses a latent issue where the code incorrectly assumes OpenSSL’s `ASN1_STRING_get0_data()` returns a null-terminated string—a guarantee not provided by the OpenSSL specification. This could cause crashes or undefined behavior with upcoming changes in OpenSSL derivatives like BoringSSL.

Junio C Hamano has reviewed the patch and raised minor but actionable feedback. His comments focus on clarifying the commit message (particularly around whether the issue affects upstream OpenSSL or just derivatives) and cleaning up presentation details: removing a redundant `From:` line, fixing a duplicate `Signed-off-by:`, adjusting line wrapping, and suggesting a type change for `pat_len` to avoid a cast. The core logic of the patch remains uncontested, and the changes are straightforward to address in a follow-up revision.

The patch is still under review, with no prior versions or additional feedback from other contributors. It’s a self-contained fix touching only `imap-send.c`, with no new dependencies or test coverage added. The issue is defensive—it doesn’t alter behavior for existing OpenSSL versions but future-proofs the code against compatibility breaks. Expect a v2 soon incorporating Junio’s suggestions.
