This is a bugfix patch targeting the ZIP archive backend (`archive-zip.c`), addressing one of the three date-handling inconsistencies reported by Matthew E. Luallen. Specifically, it omits the Extended Timestamp (UT) extra field when the commit time exceeds the 32-bit signed integer range (i.e., `> 0x7fffffff`), preventing the silent timestamp wrap that causes tools like UnZip to misbehave in update mode. The patch aligns with René Scharfe’s updated position advocating **rejection** (omission) of out-of-range timestamps rather than clamping, prioritizing correctness over tool compatibility.

The implementation uses a `strbuf` to conditionally prepare the UT extra field, simplifying the output logic and avoiding repeated range checks. Tests are added to verify that the UT field is included for 32-bit timestamps (e.g., `2147483647`) and omitted for out-of-range values (e.g., `2147483648`). The patch touches `archive-zip.c` and adds test cases to `t/t5004-archive-corner-cases.sh`, introducing the `ZIPINFO_UT_EXTRA` lazy prerequisite to check for UT field support in `zipinfo(1)`.

This is a **substantive fix** for the ZIP extended timestamp wrap issue (bug #2 in the thread), but it does not address the legacy DOS date overflow (bug #1) or the `fast-import` negative timestamp validation gap (bug #3). The patch is narrowly scoped to the UT extra field, leaving the broader policy question (rejection vs. clamping) open for the DOS date field. René’s commit message and code reflect a clear technical rationale: omitting the field avoids silent misinterpretation, a stance now shared by Matthew for the extended timestamp case.

The patch is well-crafted, with a clean diff, thorough test coverage, and a focus on edge cases. It advances the thread’s goal of resolving ZIP timestamp inconsistencies but leaves two related issues unresolved. The `fast-import` debate remains active, with René opposing stricter validation for negative timestamps. Key symbols introduced/modified include `zip_extra_mtime` (a new `strbuf` for the UT field) and the `ZIPINFO_UT_EXTRA` test prerequisite.
