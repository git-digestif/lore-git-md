This is the **second and final patch in v2** of Harald Nordgren’s series extending `git branch --delete-merged` to detect squash-merged and rebase-merged branches. This patch adds the `--no-squashed` flag, which lets users skip the slower squash-detection logic and only delete branches whose tips are directly reachable from their upstream.

The implementation is straightforward: a new `DELETE_BRANCH_NO_SQUASHED` flag is plumbed through the option parser and passed to `delete_merged_branches`, where it short-circuits the search for squashed or rebased work. The documentation and tests are minimal but complete—three files are touched (`Documentation/git-branch.adoc`, `builtin/branch.c`, and `t/t3200-branch.sh`), with 44 lines added and 3 removed. The flag is rejected if used without `--delete-merged`, mirroring the existing `--dry-run` behavior.

This patch directly addresses Phillip Wood’s performance concerns by giving users an opt-out for the slower squash detection, while preserving the default behavior (squash detection enabled) that Harald Nordgren advocated. The compromise is clean and uncontroversial; the only remaining open question is whether `--no-squashed` should also disable rebase/patch detection, but that discussion belongs to future work. The patch is ready for review and likely to be accepted as-is.
