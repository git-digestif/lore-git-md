Thread identity
Subject: [PATCH] imap-send: avoid assuming ASN1_STRING data is null-terminated
Series version: standalone patch (no series)
Originating author: Xiangfei Ding
Thread type: bugfix

Core problem or goal
Fix a latent correctness issue in `imap-send.c` where two functions (`host_matches` and `verify_hostname`) assume that OpenSSL’s `ASN1_STRING_get0_data()` returns a null-terminated buffer. This assumption is not guaranteed by the OpenSSL specification and will break with upcoming changes in OpenSSL derivatives (e.g., BoringSSL), potentially causing buffer overreads or crashes during TLS certificate validation.

Current status
Under review; no prior versions. Junio C Hamano provided a **substantive review** focusing on commit message clarity and minor code hygiene. Aniket Gupta’s **surface-level review** flags a **build-breaking deprecation warning** in OpenSSL 4.1.0-beta2 due to the use of `ASN1_STRING_length` (deprecated in favor of `ASN1_STRING_get_length`), which breaks the build when `DEVELOPER=1` is set. The patch is now explicitly cross-referenced with Beat Bolli’s September 7 series ("imap-send: future proofing and two correctness fixes"), which also modifies `host_matches()`. Junio’s follow-up clarifies that Bolli’s series is not yet ready to land (requiring rework on its first two patches and substantial changes to the third), removing it as a coordination blocker. The patch may proceed independently, but must address the OpenSSL 4.1.0 deprecation warning. No merge status change; still under review.

Key technical details
- File modified: `imap-send.c`
- Functions updated: `host_matches`, `verify_hostname`
- New API usage: `ASN1_STRING_length` (to determine string length), `strncasecmp` (for bounded comparison)
- **New issue**: `ASN1_STRING_length` is deprecated in OpenSSL 4.1.0-beta2; the newer `ASN1_STRING_get_length` must be used instead to avoid deprecation warnings and build failures under `DEVELOPER=1`
- Error message change: certificate owner name now printed with `%.*s` precision specifier to avoid reading past the end of the ASN1 string
- Subsystems affected: OpenSSL/BoringSSL compatibility, TLS certificate validation
- On-disk or network format: no changes
- Test coverage: none added; the patch is defensive and does not alter behavior for existing OpenSSL versions
