This is the first patch in a two-part feature series that hardens Git’s blame ignore-revs parser and tag-peeling logic before introducing a default ignore-revs file. The patch addresses security concerns that arise when `git blame` begins reading `HEAD:.git-blame-ignore-revs` by default (implemented in patch 2/2), exposing the parser to upstream-controlled content.

The hardening focuses on two code paths. First, it modifies `oidset_parse_file_carefully()` in `oidset.c` to reject any line containing an embedded NUL byte, preventing silent truncation of malformed input like `<oid>\0garbage`. This check is optional—Junio has questioned its necessity, and the author has offered to drop it if preferred. Second, it overhauls `peel_to_commit_oid()` in `builtin/blame.c` to prevent promisor fetches in partial clones. The updated function uses `odb_read_object_info_extended()` with `OBJECT_INFO_SKIP_FETCH_OBJECT` and `OBJECT_INFO_QUICK` to avoid network requests for missing tag targets, and it verifies each tag’s declared type before parsing to prevent type confusion.

The patch includes thorough test coverage for both hardening measures. New tests in `t/t8013-blame-ignore-revs.sh` verify that lines with NUL bytes are rejected and that chained tags are peeled correctly without triggering promisor fetches. The tests also confirm that malformed tags (e.g., pointing to non-existent objects) are safely skipped.

This patch is well-motivated and technically sound. The security refinements are clearly necessary for the default file lookup feature, and the implementation is careful—using conservative flags for object lookups and explicit type checks. The NUL-byte check is the only point of contention, but it’s a minor one; the author’s flexibility on this point suggests the patch is close to final form. The hardening appears adequate for its purpose, though review from security-focused contributors like Jeff King or brian m. carlson could provide additional confidence.

The patch touches `builtin/blame.c`, `oidset.c`, and the test suite, with no new symbols introduced. It’s a prerequisite for the default file lookup in patch 2/2 and aligns with the project’s ongoing security hardening efforts. The commit message is detailed and explains the rationale clearly, making it easy to follow the changes. This looks like a solid, uncontroversial patch that’s ready for broader review.
