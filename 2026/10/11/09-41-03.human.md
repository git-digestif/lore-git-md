This is a **feature patch** (v2 of 2) that extends `git branch --delete-merged` to detect branches whose changes were integrated via squash merges, rebases, or patch-based workflows—even when the branch tip itself isn’t reachable from upstream. The series is now split into two patches: the core logic (1/2) and a new `--no-squashed` option (2/2) to skip the slower squash detection for performance-sensitive workflows.

The v2 update addresses key feedback from the review thread. The most significant change is a **performance optimization**: upstream commits are now diffed once and the results shared across all branches, eliminating redundant work. This fixes a major inefficiency in v1 where each branch recalculated the same upstream diffs. The patch also improves correctness by ensuring merge commits report the correct "landed as" commit (the topic commit itself, not the merge) and adds a test for this edge case. The commit message now explicitly mentions `git merge --squash` and GitHub’s "Squash and merge" button as common workflows driving the feature.

The new `--no-squashed` option (2/2) lets users opt out of the slower squash detection, addressing Phillip Wood’s concern that the feature could be "diabolically slow" in large repositories or partial clones. This is a pragmatic compromise: the feature defaults to "on" (with blob fetching in partial clones), but users who know their repository contains only squash merges (and no rebases) can disable patch-id detection for faster operation. The implementation is careful to handle edge cases like reverted changes and partial landings, and the test coverage is thorough, including scenarios with upstream file modifications and mixed merge/squash workflows.

The patch is **well-motivated and technically sound**. The performance improvements in v2 make the feature more practical, and the `--no-squashed` option provides a clear escape hatch for users who prioritize speed. The output format (`Deleted branch topic (was 1a2b3c4, landed as 9f8e7d6)`) is user-friendly and gives clear visibility into where work landed.
