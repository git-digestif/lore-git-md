This is a feature patch series that makes `git blame` and `git annotate` automatically use `HEAD:.git-blame-ignore-revs` as the default ignore-revs file when no explicit file is configured. The v3 revision is a minor update to v2, addressing Junio’s feedback by replacing a `the_repository` reference with `sb->repo` to align with the ongoing `the_repository` removal effort. The series remains split into two commits: the first hardens the ignore-revs parser and tag-peeling logic (rejecting NUL bytes, preventing promisor fetches in partial clones, and verifying tag types), and the second implements the default file lookup.

The motivation is straightforward: hosting platforms like GitHub and GitLab already respect `.git-blame-ignore-revs` by default, and users are frequently surprised when local `git blame` output differs from what they see on the web. The patch ensures local behavior matches the ecosystem standard without requiring manual configuration in every clone. The design is careful about edge cases: it skips non-regular tree entries (e.g., committed symlinks), handles bare repositories, and ensures user-configured ignore files take precedence over the default blob. The hardening in patch 1/2 is a prerequisite for exposing the parser to upstream-controlled content at a well-known path.

The v3 changes are mechanical and low-risk. The only substantive update is replacing `the_repository` with `sb->repo` in `parse_default_ignore_revs_blob()`, a cleanup Junio requested to avoid perpetuating a deprecated pattern. The rest of the series is unchanged from v2, which Junio described as "OK," "Good," and "Very clean." The author has also signaled willingness to drop the NUL-byte check if Junio prefers, though this remains unresolved. The promisor fetch prevention and tag type verification in patch 1/2 still need validation from security-interested contributors (e.g., Jeff King, brian m. carlson), but the urgency has diminished since the NUL-byte check was acknowledged as stylistic rather than security-critical.

Test coverage is thorough, including new tests for NUL bytes, partial-clone tag peeling, subdirectory invocations, and CLI/config overrides. Documentation updates clarify the new behavior and override semantics. The patch is well-motivated, well-tested, and aligns Git’s behavior with established ecosystem practice. It touches the blame subsystem, documentation, and tests, but does not introduce new user-facing options—it simply makes an existing feature more convenient. The series is under review and appears ready for integration once the remaining procedural feedback (NUL-byte check, `Helped-by` attribution) is resolved.
