This is a **bugfix** for `git fast-import`. The patch addresses a crash that occurs when `git fast-import` tries to look up a commit that was created earlier in the same session. Without the fix, the command fails with `fatal: not a valid commit: <new-commit-oid>` when attempting to reference a newly created commit (e.g., via `reset` or `from`).

The issue is straightforward: commits created during the current `fast-import` session are not yet available in Git’s object database, so the lookup fails. The patch adds a helper function to check the fast-import session’s internal object table before falling back to the standard object lookup, ensuring newly created commits are found without crashing. The author, Aniket Gupta, confirms the fix works for several edge cases (tags, tags of tags, and `from <new-oid>`) while preserving existing behavior for pre-existing objects.

Aniket’s review is **substantive and tested**. He reproduces the crash, verifies the fix resolves it, and runs `fsck` to confirm no corruption. His feedback is constructive: he suggests minor improvements (a double space in the commit message, a line-length violation in the code) and requests a test in `t9300-fast-import.sh` to ensure the bug doesn’t regress. The patch itself looks well-scoped and necessary, though the lack of a test in the initial submission is a notable gap.
