This thread is a small but useful documentation update to `Documentation/SubmittingPatches`. Kristoffer Haugsbakk has submitted a patch that formalizes a long-standing review preference: contributors should avoid splitting a test and its corresponding fix into separate commits (e.g., "add a failing test, then fix it in the next commit"). Instead, the test and fix should be introduced together in a single commit, except when using `test_expect_failure` for local development. The patch adds clear guidance under the `[[tests]]` section, explaining that this pattern obscures the relationship between the test and the fix during review.

The change is well-targeted and aligns with existing project norms around commit granularity. It’s unlikely to be controversial, as it merely codifies what reviewers already expect. The patch itself is documentation-only and doesn’t affect code behavior. Kristoffer notes that adding examples of past discussions where this preference was stated could further strengthen the rationale, but the current version is already clear and actionable. This should be a straightforward merge once any minor tweaks (like those suggested) are addressed.
