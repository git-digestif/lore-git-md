Subject: [PATCH] SubmittingPatches: discourage splitting test and fix into separate commits
Series version: standalone patch (v2 forthcoming)
Originating author: Jon Simons
Thread type: documentation update (contribution guidelines)

Core problem or goal
Clarify Git’s contribution guidelines to explicitly discourage the anti-pattern of splitting a test and its corresponding code fix into two separate commits (e.g., one introducing a `test_expect_failure` and a later commit converting it to `test_expect_success`). The goal is to reduce review friction by ensuring the diff context always shows the behavior being tested alongside the fix, with no ambiguity about whether `test_expect_failure` is acceptable in submitted patches.

Current status
Under review; v1 received editorial feedback from Junio C Hamano. The author has accepted Junio’s suggested revision, replacing the original two-line explanation with a single, more direct sentence: *"A bugfix patch should include tests in `test_expect_success()` blocks that demonstrate the breakage when the code change that implements the fix is omitted."* A v2 patch is expected to be posted shortly.

Key technical details
- File modified: `Documentation/SubmittingPatches`
- New or reinforced terms: `test_expect_success`, “diff context”, “self-contained bugfix commits”
- No on-disk format changes, no new symbols, no test coverage additions beyond the guideline text
- Junio’s revision removes any implied endorsement of `test_expect_failure` as a submission tool, aligning the text with the project’s preference for self-contained commits.
