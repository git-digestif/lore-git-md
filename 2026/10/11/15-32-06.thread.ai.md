Subject: [PATCH] SubmittingPatches: discourage splitting test and fix into separate commits
Series version: standalone patch (no series)
Originating author: Jon Simons
Thread type: documentation update (contribution guidelines)

Core problem or goal
Clarify Git’s contribution guidelines to explicitly discourage the anti-pattern of splitting a test and its corresponding code fix into two separate commits (e.g., one introducing a `test_expect_failure` and a later commit converting it to `test_expect_success`). The goal is to reduce review friction by ensuring the diff context always shows the behavior being tested alongside the fix, with no ambiguity about whether `test_expect_failure` is acceptable in submitted patches.

Current status
Under review; no prior versions. The patch touches only `Documentation/SubmittingPatches` and introduces no new technical concepts, only formalizing an existing reviewer preference. Junio C Hamano (maintainer) has provided editorial feedback on the proposed text, suggesting a more direct phrasing that removes any implied endorsement of `test_expect_failure` as a submission tool.
