This is a **feature patch** (v2 of 2) that extends `git branch --delete-merged` to detect branches whose changes were integrated via squash merges, rebases, or patch-based workflows—even when the branch tip itself isn’t reachable from upstream. The series is now optimized for performance (diffing upstream commits once and sharing results across branches) and adds a `--no-squashed` flag to skip the slower squash detection. It also fixes edge cases like merged branches being misreported as "landed" when another branch was searched first.

The patch touches `builtin/branch.c` and `Documentation/git-branch.adoc`, with thorough test coverage in `t/t3200-branch.sh`. Key improvements in v2 include:
- **Performance**: The algorithm now batches diff calculations and reuses results, addressing Phillip Wood’s concern about recalculating upstream diffs for each branch.
- **Correctness**: Fixes a bug where merged branches were incorrectly attributed to a merge commit if another branch was searched first. The output now shows the topic commit itself for work integrated via merges.
- **Usability**: Adds `--no-squashed` to let users opt out of the slower squash detection (e.g., in large repos or blobless clones), though the feature defaults to "on" for all branches.
- **Documentation**: Expands examples to cover local `git merge --squash` and GitHub’s "Squash and merge" buttons.

The implementation is now more robust, handling edge cases like upstream modifying the same file as the squashed branch. Tests verify behavior with reverted changes, partial landings, and mixed merge/squash workflows. The `--no-squashed` flag reflects a compromise between Phillip Wood’s performance concerns and Harald Nordgren’s goal of a unified default behavior.
