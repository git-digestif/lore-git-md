This thread is about a bugfix for `git fast-import` that prevents a crash when looking up commits created earlier in the same session but not yet written to the object database. The issue was first reported and fixed by Marc Becker, who introduced a helper function `dereference()` to check the in-memory cache before falling back to the object database.

Aniket Gupta’s review confirms the bug is reproducible and that the fix works for several edge cases, including commits, tags, and tags of tags created mid-session, while preserving existing behavior for pre-existing objects. The review is substantive, reproducing the issue and verifying the fix, though it notes a minor style nit and questions a commit-message claim about performance. The fix touches `builtin/fast-import.c` and introduces the new `dereference()` helper. The crash is triggered by commands like `reset refs/heads/newbranch` followed by `from <new-commit-oid>` in the same stream. Aniket suggests adding a test in `t9300` to cover this scenario, which is likely the next step for the patch. The series is still under review, with no merge decisions yet.
