This is the second patch in the v3 series that implements the core feature: making `git blame` and `git annotate` automatically use `HEAD:.git-blame-ignore-revs` as the default ignore-revs file when no explicit file is configured. The patch is well-crafted, thoroughly tested, and aligns with the agreed design direction from Junio and the broader community.

The change touches `builtin/blame.c`, `oidset.c`, and documentation files, and adds comprehensive test coverage in `t/t8013-blame-ignore-revs.sh`. The implementation reads the committed `HEAD:.git-blame-ignore-revs` blob (if it exists) and adds it as the initial ignore-revs file, ensuring local `git blame` behavior matches hosting platforms like GitHub and GitLab. Non-regular tree entries (e.g., committed symlinks) are skipped using `S_ISREG()`, and the default blob is added before any user-configured files, preserving override semantics.

Key edge cases are handled: subdirectory invocations, bare repositories, empty files, comments, whitespace, committed symlinks, and CLI/config overrides (e.g., `blame.ignoreRevsFile=""` or `--no-ignore-revs-file` bypass the default blob). The patch also refactors `oidset_parse_file_carefully()` to extract a helper function (`parse_oidset_line()`), improving code reuse for parsing both files and in-memory buffers.

The v3 revision addresses Junio’s feedback by replacing `the_repository` with `sb->repo` in `parse_default_ignore_revs_blob()`, aligning with the ongoing `the_repository` removal effort. The patch is technically sound, with clear documentation updates and thorough test coverage. No new objections or technical blockers have been raised, and the series appears close to final form. The only remaining procedural decision is whether to retain the NUL-byte check in the hardening patch (1/2), which the author has offered to drop if Junio prefers.
