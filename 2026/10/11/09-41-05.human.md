This is the second and final patch in Harald Nordgren’s v2 series extending `git branch --delete-merged` to detect squash-merged and rebase-merged branches. This patch adds the `--no-squashed` flag, letting users skip the slower squash-detection logic when performance matters—such as in large repositories or blobless clones.

The implementation is straightforward: a new `DELETE_BRANCH_NO_SQUASHED` flag is plumbed through the existing `delete_merged_branches()` function, and the CLI option is guarded so it can only be used with `--delete-merged`. Documentation and tests cover the new behavior, including a negative test to ensure the flag is rejected when misused. The patch is clean, well-tested, and directly addresses the performance concerns raised in v1 by Phillip Wood.

With this patch the series is now feature-complete: squash detection is enabled by default, but users who need speed can opt out with `--no-squashed`. The trade-off between correctness and performance is explicit and user-controllable, which should satisfy both sides of the earlier discussion. The patch itself is uncontroversial; any remaining debate is likely to focus on the default behavior rather than the implementation.
