This is a documentation patch to the contribution guidelines, specifically a revision to Jon Simons' proposed update to `Documentation/SubmittingPatches`. The patch aims to discourage the anti-pattern of splitting a test and its corresponding fix into separate commits, but Junio C Hamano (the maintainer) suggests a more concise and direct phrasing.

Junio agrees with the core idea—keeping tests and fixes in the same commit to improve reviewability—but finds the original wording overly permissive. He questions the need to mention `test_expect_failure` at all, arguing that the guideline should focus on the desired outcome (a self-contained, reviewable commit) rather than acknowledging intermediate steps that aren’t recommended. His proposed alternative is shorter and more prescriptive: *"A bugfix patch should include tests in `test_expect_success()` blocks that demonstrate the breakage when the code change that implements the fix is omitted."*

The discussion is narrow and non-controversial, focusing on wording rather than substance. Junio’s suggestion aligns with the project’s preference for clear, actionable guidelines and avoids implying that `test_expect_failure` is an acceptable part of the final submission. The patch remains a documentation-only change with no technical implications, but Junio’s feedback is likely to shape the final version.
