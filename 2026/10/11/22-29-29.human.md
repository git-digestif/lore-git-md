This is the v3 iteration of the second patch in a two-patch series that teaches `git blame` and `git annotate` to automatically use `HEAD:.git-blame-ignore-revs` as the default ignore-revs file when no explicit file is configured. The series is now feature-complete and addresses all maintainer feedback from v2, including a mechanical cleanup to avoid referencing the global `the_repository` variable.

The patch itself is small and focused: it adds logic to resolve `HEAD:.git-blame-ignore-revs` and parse its contents in-memory, ensuring the default blob is added to the ignore-revs list before any user-configured files. This aligns local behavior with hosting platforms like GitHub and GitLab, which already respect this file by convention. The implementation handles edge cases such as bare repositories, subdirectory invocations, and CLI/config overrides, and it shares parsing logic with the existing file-based ignore-revs parser.

Junio’s feedback on v2 was procedural rather than technical—he noted that the new function unnecessarily referenced `the_repository` when the `blame_scoreboard` struct already held a repository pointer (`sb->repo`). This was a clear violation of the ongoing `the_repository` removal effort, and the author has now addressed it in v3 by replacing `the_repository` with `sb->repo` in `parse_default_ignore_revs_blob()`. The fix is mechanical and low-risk, improving code consistency without changing behavior.

The patch is part of a well-motivated feature that has already resolved its design direction (using `HEAD:.git-blame-ignore-revs` as the default) and includes comprehensive test coverage. The only remaining procedural decision is Junio’s preference on whether to retain the optional NUL-byte check in the first patch, which the author has signaled flexibility on. No new objections or technical blockers have emerged, and the patch looks ready for integration once the final procedural details are settled. For developers following Git’s blame subsystem or the `the_repository` removal effort, this is a clean, uncontroversial change worth tracking.
