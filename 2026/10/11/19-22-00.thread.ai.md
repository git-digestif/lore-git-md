Core problem or goal
Fix a crash in `git fast-import` when it attempts to dereference a commit, tag, or tag-of-tag created earlier in the same session but not yet written to the object database. The lookup fails with “fatal: not a valid commit”, terminating the import process.

Current status
Under review. Marc Becker posted the initial fix; Aniket Gupta’s review confirms the bug is reproducible, verifies the fix resolves the crash for in-session commits, tags, and tags-of-tags, and preserves existing behavior for pre-existing objects and blobs. No maintainer decision yet.

Key technical details
- File touched: `builtin/fast-import.c`
- New helper: `dereference()` checks the fast-import session’s in-memory cache before falling back to the object database
- Affected commands: any that dereference an in-session object (e.g., `reset refs/heads/newbranch` followed by `from <new-commit-oid>` in the same stream)
- On-disk format: unchanged
- Test coverage: none yet; Aniket suggests adding a test in `t9300` using `get-mark` to capture the OID
