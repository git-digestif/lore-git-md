This is a documentation patch that updates `Documentation/SubmittingPatches` to discourage the "add a failing test and then fix it in a later commit" anti-pattern. The change adds a new paragraph advising contributors to combine a test and its corresponding fix into a single commit, unless there’s a strong reason to split them. The rationale is that separating the test from the fix can make reviews harder by obscuring the relationship between the test and the code change.

The patch is small and focused, touching only the contributor guidelines. It reflects a long-standing preference among Git reviewers, now codified in writing to reduce unnecessary back-and-forth in review cycles. The commit message is clear and practical, and the diff is straightforward.

This isn’t controversial—it’s a housekeeping improvement that aligns the documentation with existing review norms. If you care about contributor workflows or review efficiency, it’s worth a quick glance.
