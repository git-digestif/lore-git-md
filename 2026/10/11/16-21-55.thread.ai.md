Subject: [PATCH] SubmittingPatches: discourage "add failing test then fix" pattern
Series version: standalone patch
Originating author: Kristoffer Haugsbakk
Thread type: documentation patch

Core problem or goal
Clarify the long-standing but previously undocumented review preference that contributors should avoid submitting patches where a failing test is added in one commit and then fixed in a subsequent commit. Instead, the test and its corresponding code change should be introduced in a single commit to preserve reviewability.

- New guidance: `test_expect_failure` is useful for local development but should not be submitted as a standalone commit because it obscures the relationship between the test and the fix during review.
