This thread is a four-patch series by Aniket Gupta refactoring Git’s line-ending configuration (`core.autocrlf`, `core.eol`, `core.safecrlf`) to eliminate global variables and move the settings into `struct repo_config_values`. The goal is to advance Git’s libification effort, making the codebase more modular and reusable. The series is now complete with the fourth patch, which migrates the last remaining variable (`core.safecrlf`) and introduces a getter function to access it.

The changes are mechanical and follow the pattern established in earlier patches, touching files like `convert.c`, `environment.c`, and `object-file.c`. Functions now access line-ending configuration via repository-specific getters (e.g., `repo_auto_crlf(repo)`) instead of global variables, with the `struct repository *` parameter propagated through the call chain. The series does not introduce new CLI options, config keys, or test files, and the on-disk format remains unchanged.

The main open question is a design choice: whether to pass `repo` to functions (the current approach) or store resolved values in `struct conv_attrs` (an alternative). The author has explicitly invited feedback on this. The series is under review, with no merge status recorded yet, and is part of the broader libification effort to remove global state like `the_repository`.
