This thread is about a four-patch series by Aniket Gupta that moves Git’s line-ending configuration variables (`core.autocrlf`, `core.eol`, `core.safecrlf`) from global variables into a repository-specific structure (`struct repo_config_values`) as part of the ongoing libification effort. The goal is to eliminate global state and make the codebase more modular, following the pattern of earlier conversions in the same effort.

The series is now under active review, with all patches posted. Key changes include replacing global variables with repository-specific getters (e.g., `repo_auto_crlf(repo)`), propagating the `struct repository *` parameter through the call chain, and eliminating the `global_conv_flags_eol` global. The patches touch several files, including `convert.c`, `environment.c`, and `object-file.c`, but do not alter on-disk formats or introduce new CLI options or config keys.

The most significant development is a critical review from Patrick Steinhardt, who argues that the current implementation *worsens* coupling to `the_repository` rather than reducing it. Specifically, `repo_config_values()` can only be populated via `git_default_config()`, which hard-codes the global repository, undermining the libification goal. Patrick’s feedback is decisive: he states the series should not be merged until this issue is resolved. Aniket had previously invited feedback on the design choice between passing `repo` to functions or storing resolved values in `struct conv_attrs`, but Patrick’s review suggests the current approach is fundamentally flawed. The thread is now at a crossroads, with the series’ future dependent on addressing this architectural concern.
