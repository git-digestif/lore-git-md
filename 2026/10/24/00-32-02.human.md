This is a CI/build system patch that pins GitHub Actions in the main workflow file to full commit SHAs rather than version tags or branches. The change is part of a policy discussion about whether upstream Git should accommodate organizational compliance requirements.

Taylor Blau responds to Junio C Hamano’s substantive objection by clarifying the security rationale: pinning actions to commit IDs prevents malicious updates to tags from injecting code into CI runs, since GitHub’s token permissions alone may not be sufficient protection. He argues that this is not just a downstream compliance issue but a security measure that benefits upstream as well, reducing duplicated effort across forks and ensuring consistent protection. The maintenance trade-off—explicitly updating commit IDs for bug fixes—is framed as preferable to delegating trust to tag maintainers.

The patch itself remains unchanged, touching only `.github/workflows/main.yml` to replace 32 action references (e.g., `actions/checkout@v6` → `actions/checkout@d23441a48e516b6c34aea4fa41551a30e30af803`). No functional changes to Git’s behavior are introduced. The thread now hinges on whether the security argument is compelling enough to override Junio’s concern about precedent—specifically, the risk of other organizations requesting conflicting modifications. Taylor’s concrete example (applying the patch locally for every topic) underscores the practical friction of downstream-only solutions.

The discussion is mature and focused on policy rather than implementation. If the goal is to reduce CI supply-chain risk, this patch looks like a reasonable step, but its fate depends on whether the project prioritizes security hardening over strict upstream/downstream separation. For now, it remains under review.
