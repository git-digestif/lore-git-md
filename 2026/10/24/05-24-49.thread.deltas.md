# Thread deltas

## 2026/10/24

- [2026/10/24/05-24-49 by Tanga Joris <tangajoris@gmail.com>] Tanga Joris posted a patch dropping the NO_PARSEOPT flag from four builtins that now use parse-options—diff-pairs, fast-import, patch-id, and var—so that "git --list-cmds=parseopt" includes them and bash completion can offer their options via "--git-completion-helper"; the patch notes that removing the flag from var does not change its completion because it only has short options (-l and -z), and that rev-parse keeps the flag because its normal options are still parsed by hand.

## 2026/10/25

- [2026/10/25/07-59-07 by René Scharfe <l.s.r@web.de>] René Scharfe endorsed the proposal to drop NO_PARSEOPT from the four builtins, but noted that "git fast-import --git-completion-helper" prints its command-line options only after it receives a line of input, and asked whether the completion scripts still work seamlessly without requiring the user to press <return>.

## 2026/10/26

- [2026/10/26/02-59-53 by Tanga Joris <tangajoris@gmail.com>] Tanga Joris confirmed that after René Scharfe had asked whether the completion scripts still work seamlessly with "git fast-import --git-completion-helper" (which prints options only after being fed input), they do not: __git() does not redirect stdin, so the helper reads from the terminal and "git fast-import --<TAB>" waits for <return> or ^D, because fast-import only calls parse_options() after seeing the first command in the stream (or EOF) as it reads "feature" lines first. He plans to send a v2 that still removes NO_PARSEOPT from patch-id, diff-pairs and var (which return immediately) but keeps it on fast-import for now, alongside a separate patch teaching fast-import to answer --git-completion-helper before reading its input (like it does for "-h") so the flag can ultimately be removed, and asked Christian whether basing that patch on the cc/early-scan-options series would be fine.
- [2026/10/26/04-58-29 by Junio C Hamano <gitster@pobox.com>] Junio C Hamano answered Tanga Joris's question by saying basing the patch on Christian's early-scan series is not something Christian can approve nor needs his permission; the dependent topic should be as solid as possible and at least in 'next', and Tanga, as a potential user of that topic, could help make cc/early-scan-options solid and merged to 'next' sooner by carefully reviewing it, finding issues and offering improvements.

- [2026/10/29/01-26-16 by Tanga Joris <tangajoris@gmail.com>] Tanga Joris posted v2 patch 2/2, removing the NO_PARSEOPT flag from the four builtins (patch-id, diff-pairs, fast-import, var) that already use parse-options, so bash completion can query their options.

- [2026/10/29/23-16-20 by Tanga Joris <tangajoris@gmail.com>] Tanga Joris posted v3 1/2, moving the completion-helper handling from fast-import into show_usage_with_options_if_asked() in parse-options.c as Junio C Hamano suggested, so fast-import and other callers reply without reading input.
- [2026/10/29/23-16-21 by Tanga Joris <tangajoris@gmail.com>] Tanga Joris posted v3 2/2, unchanged from v2: dropping NO_PARSEOPT from patch-id, diff-pairs, fast-import, and var in git.c.
