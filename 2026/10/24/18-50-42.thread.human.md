This thread is about a targeted bugfix for an oss-fuzz regression that broke commit-graph parsing after a recent repository parameter refactoring. The issue surfaced when commit f1141b4391 (August 15, 2025) introduced a BUG assertion in `prepare_repo_settings()` when the fuzzer's repository lacked a `.git` gitdir, preventing the fuzzer from testing optional chunks like generation data and Bloom filters.

Sami Jawhar proposed a minimal fix—a single-line addition in `oss-fuzz/fuzz-commit-graph.c` to set a placeholder `.git` gitdir, which is safely freed by `repo_clear()`. The patch mirrors an existing pattern in `test-path-utils.c` and makes no changes to production code. Patrick Steinhardt reviewed the fix, confirming the root cause and endorsing the approach as safe and consistent with existing code. He also noted a broader issue—fuzzers breaking silently without CI detection—but agreed it’s outside the scope of this patch.

The fix is uncontroversial and ready to merge, restoring fuzzer coverage without side effects. No open questions remain, and the patch touches only the fuzzer harness, leaving the rest of the codebase unchanged.
