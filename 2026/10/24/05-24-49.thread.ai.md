Subject: [PATCH] completion: remove NO_PARSEOPT for commands using parse-options
Series version: standalone patch (no series)
Originating author: Tanga Joris
Thread type: bug fix (user-visible completion regression)

Core problem or goal
Git's Bash completion script was not offering command-line options for four built-in commands (`patch-id`, `diff-pairs`, `fast-import`, `var`) because they were still marked with the `NO_PARSEOPT` flag in `git.c` even though they had already been converted to use the `parse-options` API. The patch removes the flag so that completion works as expected.

Current status
Under review. No prior versions. No merge status reported.

Key technical details
- File touched: `git.c` (single-line change per command)
- Symbols: removes `NO_PARSEOPT` flag from the `commands[]` array entries for the four commands
- New behavior: Bash completion now shows available options for these commands
- Old behavior: completion offered no options
- Edge case: `git fast-import --git-completion-helper` only prints options *after* receiving a line of input, which may break seamless tab-completion (raised by René Scharfe)
- Test coverage: none mentioned; the fix is mechanical for three commands (`patch-id`, `diff-pairs`, `var`) but may require adjustment for `fast-import`

Open questions and loose ends
