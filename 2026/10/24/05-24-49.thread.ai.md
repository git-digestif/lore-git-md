Thread identity
Subject: [PATCH] completion: remove NO_PARSEOPT for commands using parse-options
Series version: two-part series (v2 for `patch-id`, `diff-pairs`, `var`; follow-up v1 for `fast-import`)
Originating author: Tanga Joris
Thread type: bug fix (user-visible completion regression)

Core problem or goal
Git's Bash completion script was not offering command-line options for four built-in commands (`patch-id`, `diff-pairs`, `fast-import`, `var`) because they were still marked with the `NO_PARSEOPT` flag in `git.c` even though they had already been converted to use the `parse-options` API. The goal is to restore expected completion behavior for all four commands, with a split approach for `fast-import` due to its unique interaction with `--git-completion-helper`.

Current status
Under review. A v2 patch removes `NO_PARSEOPT` from `patch-id`, `diff-pairs`, and `var`; a follow-up v1 patch addresses `fast-import` by moving the `--git-completion-helper` check to the start of `cmd_fast_import()` so it can return immediately without blocking or creating temporary files. The series depends on Christian Couder’s `cc/early-scan-options` series being stable and preferably in `next`; no merge status reported for either patch.

Key technical details
- Files touched: `git.c` (v2), `builtin/fast-import.c` (follow-up), `t/t9300-fast-import.sh` (new test in follow-up)
- Symbols: removes `NO_PARSEOPT` flag from `commands[]` entries for `patch-id`, `diff-pairs`, and `var`; adds early `--git-completion-helper` check in `cmd_fast_import()`
- New behavior: Bash completion now shows available options for all four commands; `fast-import --git-completion-helper` returns immediately without blocking or leaving temporary files
- Old behavior: completion offered no options for any of the four commands; `fast-import --git-completion-helper` blocked waiting for input and created temporary pack files
- Edge case: `fast-import --git-completion-helper` now handled before `fast_import_state_init()` to avoid side effects
- Test coverage: new test in `t/t9300-fast-import.sh` verifies no temporary files are created and the expected option list is printed for `fast-import`; no test coverage for completion behavior of `patch-id`, `diff-pairs`, or `var`
