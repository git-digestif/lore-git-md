Subject: [PATCH] completion: remove NO_PARSEOPT for commands using parse-options
Series version: standalone patch (v2 posted; follow-up for `fast-import` planned)
Originating author: Tanga Joris
Thread type: bug fix (user-visible completion regression)

Core problem or goal
Git's Bash completion script was not offering command-line options for four built-in commands (`patch-id`, `diff-pairs`, `fast-import`, `var`) because they were still marked with the `NO_PARSEOPT` flag in `git.c` even though they had already been converted to use the `parse-options` API. The goal is to restore expected completion behavior for these commands, with a split approach for `fast-import` due to its unique interaction with `--git-completion-helper`.

Current status
Under review. A v2 patch has been posted to remove `NO_PARSEOPT` from `patch-id`, `diff-pairs`, and `var`; the `fast-import` fix is deferred to a separate follow-up patch that will depend on Christian Couder’s `cc/early-scan-options` series. No merge status reported; the follow-up cannot proceed until `cc/early-scan-options` is stable and preferably in `next`.

Key technical details
- File touched: `git.c` (single-line change per command)
- Symbols: removes `NO_PARSEOPT` flag from the `commands[]` array entries for `patch-id`, `diff-pairs`, and `var`; retains the flag for `fast-import` pending a follow-up
- New behavior: Bash completion now shows available options for `patch-id`, `diff-pairs`, and `var`; `fast-import` completion remains unchanged until the follow-up patch
- Old behavior: completion offered no options for any of the four commands
- Edge case: `git fast-import --git-completion-helper` only prints options after receiving a line of input, which breaks seamless tab-completion (identified by René Scharfe)
- Test coverage: none mentioned; the fix is mechanical for `patch-id`, `diff-pairs`, and `var` but requires adjustment for `fast-import` via Christian Couder’s “early-scan” series
