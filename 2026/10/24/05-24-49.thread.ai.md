Subject: [PATCH] completion: remove NO_PARSEOPT for commands using parse-options
Series version: two-part series (v2 for `patch-id`, `diff-pairs`, `var`; follow-up v1 for `fast-import` with Junio’s proposed refactoring)
Originating author: Tanga Joris
Thread type: bug fix (user-visible completion regression)

Core problem or goal
Git’s Bash completion script was not offering command-line options for four built-in commands (`patch-id`, `diff-pairs`, `fast-import`, `var`) because they were still marked with the `NO_PARSEOPT` flag in `git.c` even though they had already been converted to use the `parse-options` API. The goal is to restore expected completion behavior for all four commands, with a unified, maintainable approach for handling `--git-completion-helper` across all `parse-options`-based commands.

Current status
Under review. A v2 patch removes `NO_PARSEOPT` from `patch-id`, `diff-pairs`, and `var`; the follow-up patch for `fast-import` is now superseded by Junio’s proposed refactoring, which centralizes the `--git-completion-helper` logic in `parse-options.c` instead of adding per-command boilerplate. The series still depends on Christian Couder’s `cc/early-scan-options` series being stable and preferably in `next`; no merge status reported for either patch.

Key technical details
- Files touched: `git.c` (v2), `parse-options.c` (Junio’s refactoring), `t/t9300-fast-import.sh` (new test in follow-up)
- Symbols: removes `NO_PARSEOPT` flag from `commands[]` entries for `patch-id`, `diff-pairs`, and `var`; adds `show_usage_with_options_if_asked()` in `parse-options.c` to handle `-h`, `--help`, and `--git-completion-helper` flags generically
- New behavior: Bash completion now shows available options for all four commands; `--git-completion-helper` is handled immediately and consistently for any command using `parse-options`, without blocking or leaving temporary files
- Old behavior: completion offered no options for any of the four commands; `fast-import --git-completion-helper` blocked waiting for input and created temporary pack files
- Edge case: `--git-completion-helper` is now handled before any command-specific initialization (e.g., `fast_import_state_init()`), avoiding side effects
- Test coverage: new test in `t/t9300-fast-import.sh` verifies no temporary files are created and the expected option list is printed for `fast-import`; no test coverage for completion behavior of `patch-id`, `diff-pairs`, or `var`
