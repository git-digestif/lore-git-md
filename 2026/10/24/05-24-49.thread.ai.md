Thread identity
Subject: [PATCH] completion: remove NO_PARSEOPT for commands using parse-options
Series version: v3 (centralized refactoring in `parse-options.c`; replaces v2 for `patch-id`, `diff-pairs`, `var` and follow-up for `fast-import`)
Originating author: Tanga Joris
Thread type: bug fix (user-visible completion regression)

Core problem or goal
Git’s Bash completion script was not offering command-line options for four built-in commands (`patch-id`, `diff-pairs`, `fast-import`, `var`) because they were still marked with the `NO_PARSEOPT` flag in `git.c` even though they had already been converted to use the `parse-options` API. The goal is to restore expected completion behavior for all four commands by centralizing `--git-completion-helper` handling in `parse-options.c`, avoiding per-command boilerplate and side effects like temporary file creation or blocking on input.

Current status
Under review. The v3 series (two patches) implements Junio’s proposed refactoring: the first patch moves completion-helper logic into `show_usage_with_options_if_asked()` in `parse-options.c`, and the second patch removes the now-redundant `NO_PARSEOPT` flag from the four commands in `git.c`. The series still depends on Christian Couder’s `cc/early-scan-options` series being stable and preferably in `next`; no merge status reported for either patch. Tanga has addressed Kaartic Sivaraam’s feedback by adding a clarifying sentence to the commit message and a comment in `parse-options.h` to improve maintainability. Cynthia Uche’s tested review confirms the refactoring does not alter existing behavior for any built-in command, validating correctness across the entire command set.

Key technical details
- Files touched: `parse-options.c` (adds six-line block to handle completion-helper flags in `show_usage_with_options_if_asked()`), `parse-options.h` (comment addition to explain completion-helper handling), `git.c` (removes `NO_PARSEOPT` from `patch-id`, `diff-pairs`, `fast-import`, `var`), `t/t9300-fast-import.sh` (new test)
- Symbols: `show_usage_with_options_if_asked()` now handles `--git-completion-helper` and `--git-completion-helper-all` generically; removes need for per-command boilerplate
- New behavior: Bash completion now shows available options for all four commands; `--git-completion-helper` and `--git-completion-helper-all` are handled immediately and consistently, avoiding side effects (e.g., no temporary files or blocking for `fast-import`)
- Old behavior: completion offered no options for any of the four commands; `fast-import --git-completion-helper` blocked waiting for input and created temporary pack files
- Edge case: `--git-completion-helper` and `--git-completion-helper-all` are now handled before any command-specific initialization (e.g., `fast_import_state_init()`), avoiding side effects
- Test coverage: new test in `t/t9300-fast-import.sh` verifies no temporary files are created and the expected option list is printed for `fast-import`; Cynthia Uche’s proposed test addition guards the `--git-completion-helper-all` branch; no test coverage for completion behavior of `patch-id`, `diff-pairs`, or `var`; proposed defensive test greps for `--` to catch future regressions but misses commands with only short options (e.g., `var`)
