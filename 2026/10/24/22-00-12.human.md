This is the fourth and final patch in Aniket Gupta’s four-part refactoring series that moves Git’s line-ending configuration variables (`core.autocrlf`, `core.eol`, and `core.safecrlf`) out of global variables and into `struct repo_config_values`. The series is part of the ongoing libification effort to eliminate global state and make Git’s internals more modular.

This patch specifically migrates `global_conv_flags_eol` (the variable that holds the `core.safecrlf` setting) into `repo_config_values`. It adds a new getter function, `repo_global_conv_flags_eol()`, and updates the three call sites in `diff.c`, `combine-diff.c`, and `object-file.c` to use the repository-specific value instead of the global. The change is mechanical and follows the pattern established in the earlier patches: the per-repository value is initialized in `repo_config_values_init()`, and the configuration parser in `environment.c` now updates the repository-specific structure directly.

The patch touches six files and is small (24 insertions, 11 deletions), but it completes the series’ goal of eliminating all three line-ending globals. The author’s commit message is clear and the code changes are straightforward, suggesting this is a well-crafted contribution. There are no new CLI options, config keys, or test files, and the on-disk format remains unchanged. The main point of discussion for the series as a whole — whether to pass `repo` to functions or store resolved values in `struct conv_attrs` — was already raised in the cover letter and earlier patches, so this patch is unlikely to introduce new controversy.
