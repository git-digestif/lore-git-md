This is a **design discussion reply** in the ongoing RFC thread about extending `git branch --delete-merged` to handle branches with gone upstreams. The author, DonQuinleone, responds to feedback from D. Ben Knoble and Harald Nordgren by refining the proposed interface and addressing edge cases uncovered during testing.

Don now proposes a **filtered `-d` approach** that avoids both the original `--into` flag and Knoble’s unified filtering model (`--list` + `xargs`). Instead, he suggests extending `git branch -d` to accept `--upstream-gone` and `--merged=<commit>` as composable filters, where `--merged` serves as both the selection criterion and the proof of merge. This would allow the command `git branch -d --upstream-gone --merged=origin/master` to delete gone-upstream branches only if their tips are reachable from `origin/master`. The proposal preserves existing safeguards (e.g., worktree protection, `branch.<name>.deleteMerged=false`) and avoids the "selection is not proof" issue that broke Knoble’s pipe-based approach.

The key trade-off is between **composability** and **CLI simplicity**: Don’s proposal avoids context-sensitive flags (like `--into`) and packed sub-values (like `--delete-merged='origin/*,into:origin/master'`), but it does introduce a new mode for `git branch -d`. He argues this is preferable to Knoble’s pipe-based model, which lost the merge-check context across the pipe, or Nordgren’s implicit behavior, which would relax safeguards by default. The proposal also sidesteps the broader debate about triangular workflow defaults (e.g., `push.default=current`), though Don acknowledges that teaching users to avoid `git push -u` would be a more fundamental fix.

The email includes concrete test results showing how the current `--list --merged` + `xargs` approach fails (due to `git branch -d` falling back to `HEAD` for gone-upstream branches), and how the filtered `-d` approach would resolve this. Don plans to split the implementation into two patches: first adding `--upstream-gone` as a listing filter (useful standalone for identifying gone-upstream branches), then extending `-d` to use it. The thread remains unresolved, but this reply narrows the design space to a middle ground between Knoble’s composability and Nordgren’s implicit behavior.
