This thread reports a regression in Git 2.56.0 where a fetch combining `--filter=tree:0` with `--unshallow` (or `--deepen`) triggers a `BUG()` in `should_include_obj()`. The issue was introduced by commit `d43b9acb05`, which switched shallow file handling from file descriptor passing to environment-based propagation. Daniel Zoghalchali identified the root cause and provided a reproduction case, noting that the underlying issue may predate the environment change, as the same `BUG()` can be triggered on Git 2.55.0 under a two-step fetch sequence.

Patrick Steinhardt has now confirmed the regression and proposed a targeted fix. Instead of reverting the environment-based shallow file propagation, the fix replaces the `BUG()` in `is_not_in_promisor_pack_obj()` with a graceful return (`return 0`), treating missing promisor objects as non-promisor objects. This aligns with partial clone assumptions and addresses the immediate symptom without disrupting the broader shallow file handling changes. The patch is minimal, touching only `builtin/pack-objects.c`, and is unlikely to be controversial, as it resolves a critical failure mode (a `BUG()` abort) in a way consistent with Git’s partial clone design. The thread is now focused on finalizing the patch, with no open questions remaining about the fix direction.
