This thread reports a **regression in Git 2.56.0** affecting shallow clones that combine `--filter=tree:0` with `--unshallow` or `--deepen`. The issue, introduced by commit `d43b9acb05`, causes a `BUG()` in `should_include_obj()` when the fetched ref moves past the local shallow tip. The root cause is the environment-based shallow file propagation: the `pack-objects` grandchild process inherits an empty `GIT_SHALLOW_FILE`, leading it to walk past the shallow boundary into promisor objects whose trees were never fetched.

Daniel Zoghalchali provides a **reproducible test case** showing the failure on both Ubuntu's PPA and source-built 2.56.0, while confirming the same operation succeeds on 2.55.0. The regression is severe (a `BUG()` abort) but limited to shallow clones using tree filters during unshallow operations. The author traces the issue to the environment variable propagation and suggests unsetting `GIT_SHALLOW_FILE` for the repack child process as a workaround. They also note the underlying issue predates the environment change but was masked by prior shallow file handling.

No patch has been proposed yet, but the analysis points to two likely fixes: reverting the environment-based approach or adding safeguards in `pack-objects` to handle missing promisor objects. The thread is likely to focus on which approach is safer and whether additional edge cases need addressing. Key participants will likely include shallow clone experts (e.g., Patrick Steinhardt, Jeff King) and maintainers evaluating the regression's severity.
