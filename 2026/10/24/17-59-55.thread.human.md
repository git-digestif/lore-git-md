This thread reports and fixes a regression in Git 2.56.0 that causes a `BUG()` abort during fetches combining `--filter=tree:0` with `--unshallow` (or `--deepen`). The issue was introduced by commit d43b9acb05, which switched shallow file handling to environment-based propagation, but the underlying problem—an incorrect assumption in `should_include_obj()` that all objects exist locally—was already reachable in Git 2.55.0 under specific conditions.

Patrick Steinhardt has now submitted a formal patch that replaces the `BUG()` in `is_not_in_promisor_pack_obj()` with a graceful return, treating missing promisor objects as non-promisor objects. This aligns with partial clone expectations and resolves the regression without reverting the environment-based shallow file propagation. The fix is minimal (a single line in `builtin/pack-objects.c`), well-motivated, and addresses both the immediate symptom and the root cause. Daniel Zoghalchali’s reproduction case and Patrick’s analysis confirm the fix’s correctness, and the thread has converged on this solution with no open questions remaining.

The patch is targeted at a severe regression (a `BUG()` abort) with clear impact on shallow clones using tree filters during unshallow operations. It is unlikely to be controversial, as it replaces an assertion with behavior consistent with partial clone semantics. The fix is now ready for review and integration.
