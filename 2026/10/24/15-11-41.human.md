This is the fourth patch in Harald Nordgren’s five-patch series introducing a "matching-inspired" fetch mode for shallow repositories. The patch adds a `--limited-fetch` flag to `git remote add`, letting users opt into the new dynamic branch-fetching logic by configuring `remote.<name>.refmap` instead of the traditional wildcard `remote.<name>.fetch` refspec. The implementation is straightforward and uncontroversial: the flag is rejected when combined with `-t/--track` or `--mirror` (since those already specify explicit fetch behavior), and it updates the repository configuration via `repo_config_set()`. Four new tests in `t/t5505-remote.sh` verify the flag’s behavior, conflict with `-t`, and absence of interference with existing functionality.

Ben Knoble’s review is surface-level, noting only minor stylistic points: the use of `-1` as a default for `limited_fetch` (necessary for Patch 5/5’s shallow-repository default logic) and the awkward line wrapping in the `use_limited_fetch` conditional. Neither observation requires changes to the patch, and Knoble explicitly calls the implementation "reasonable." The patch itself is ready for merging and has no unresolved technical concerns.

This is a plumbing change that enables the user-facing opt-in for the new fetch mode. It reuses existing machinery (`limited_fetch` logic, `repo_config_set()`) and introduces no new technical debt. The only open design question—whether `--limited-fetch` should be the default for *all* repositories—is a topic-level concern and not a blocker for this patch. The patch is well-scoped, self-contained, and aligns with the series’ goal of reducing unnecessary history negotiation in shallow repositories.
