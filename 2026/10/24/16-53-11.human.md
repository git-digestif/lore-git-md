This is a feature patch implementing `--branch=<branch>` for `git worktree list`, following Junio C Hamano’s suggestion to replace the earlier `--merged`/`--no-merged` proposal with a more general filter primitive. The patch adds a new option that lists only worktrees where the specified branch is checked out, including during rebase or bisect operations. It accepts multiple `--branch` arguments and works with both branch names and full refs (e.g., `refs/heads/topic`). The implementation reuses logic from `git branch -d` and `git worktree add` to handle rebasing/bisecting worktrees, and it integrates cleanly with existing `git branch` filtering options (e.g., `--merged`, `--contains`) via command substitution.

The commit message is thorough and practical, showing how the new option composes with `git branch --format` to solve the original use case (listing worktrees for branches merged into `origin/main`). Tests cover edge cases like unborn branches, detached worktrees, rebasing/bisecting states, and invalid branch names, and the code is careful to avoid quadratic scaling when filtering against many branches. The patch drops the earlier reachability-checking code entirely, reflecting the shift from a workflow-specific feature to a general-purpose filter.

This version addresses the core critique of the RFC—overly narrow scope—while keeping the implementation simple and focused. The `--branch` primitive is clearly useful on its own and also enables the merged/unmerged use case through composition with `git branch`. No controversial design choices remain; the only open question is whether the project would prefer an even more general `foreach` mechanism (as suggested by Eric Sunshine), but that would be a separate effort. The patch is well-crafted, well-tested, and ready for review.
