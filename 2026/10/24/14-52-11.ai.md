This is a **workflow discussion** reply in the ongoing RFC thread about `git branch --delete-merged` and gone-upstream branches. Harald Nordgren responds to D. Ben Knoble’s comments on Git’s defaults for triangular workflows, focusing on usability improvements rather than the RFC’s core interface debate.

Nordgren agrees with Knoble that `push.default=current` would be a better default for Git 3.0, calling the current `simple` setting a "compromise that’s not really good for anyone." He also endorses `branch.autosetupmerge=inherit`, emphasizing its simplicity for users who clone repositories: by inheriting the upstream from `origin/main` (or similar), users never need to manually specify a starting branch when creating new topics. His example (`git switch origin -c topic`) highlights how `inherit` reduces friction, though he notes this workflow isn’t widely understood. The discussion remains tangential to the RFC’s original question (how to handle gone-upstream branches in `--delete-merged`), but reinforces the thread’s broader theme: Git’s defaults often obscure triangular workflows (e.g., GitHub PRs), and small changes could improve usability without requiring new flags or composable syntax.

No new technical details or edge cases for the RFC’s feature are addressed. The exchange is purely philosophical, with Nordgren advocating for implicit, user-friendly defaults over explicit configuration.
