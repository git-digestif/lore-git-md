This is the fourth patch in Harald Nordgren’s v10 series introducing a "matching-inspired" fetch mode for shallow repositories. The patch adds a `--limited-fetch` flag to `git remote add`, which configures the remote to use the new `remote.<name>.refmap` setting instead of the traditional wildcard `remote.<name>.fetch` refspec. This is a plumbing addition that enables users to opt into the dynamic branch-fetching logic introduced earlier in the series.

The implementation is straightforward and uncontroversial. The flag is rejected when combined with `-t/--track` or `--mirror`, as those options already specify explicit fetch behavior. The patch updates `builtin/remote.c` to set the refmap configuration via `repo_config_set()` and adds documentation to `git-remote.adoc`. Four new tests in `t/t5505-remote.sh` verify the flag’s behavior, conflict with `-t`, and absence of interference with existing functionality. D. Ben Knoble’s review notes that the `limited_fetch` variable’s default of `-1` (to distinguish "unspecified" from "false") is atypical but justified by the need to support the shallow-repository default logic in Patch 5/5. The line formatting in the conditional logic is flagged as odd but not problematic.

This patch is ready for merging and has no unresolved technical concerns. It is a well-scoped plumbing change that aligns with the series’ goal of reducing unnecessary history negotiation in shallow repositories. The only open design question—whether `--limited-fetch` should be the default for *all* repositories—is orthogonal to this patch and can be addressed in follow-up work. The patch itself is self-contained and introduces no new technical debt. The series as a whole is technically complete and awaiting a second Ack before graduating to `next`.
