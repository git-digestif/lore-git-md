Thread identity: Refactoring patch series (4 patches) by Aniket Gupta to move all line-ending configuration variables (`core.autocrlf`, `core.eol`, `core.safecrlf`) from global variables into `struct repo_config_values` as part of the Git libification effort. Series version: v1 (fully posted, now under critical review).

Core problem or goal: Eliminate global state for line-ending configuration to advance Git's libification, making the codebase more modular and reusable. The change follows the established pattern of prior conversions in the libification effort, specifically preparing working tree conversion functions to access repository-specific configuration.

Current status: Under review (all four patches posted). No merge status recorded; Patrick Steinhardt explicitly states the series should not be merged in its current form due to a critical design flaw.

Key technical details:
- Files touched: `convert.c`, `convert.h`, `environment.c`, `environment.h` (primary), plus `combine-diff.c`, `diff.c`, `entry.c`, `object-file.c`, `parallel-checkout.c` (across the series).
- New structure: `struct repo_config_values` now holds all three line-ending variables (`core.autocrlf`, `core.eol`, `core.safecrlf`). The `global_conv_flags_eol` global is eliminated.
- Behavior change: Functions now access line-ending configuration via repository-specific getters (`repo_auto_crlf(repo)`, `repo_core_eol(repo)`, `repo_global_conv_flags_eol(repo)`) instead of global variables. The `struct repository *` parameter is propagated through the call chain in `convert.c` and related files. The `get_conv_flags()` helper in `object-file.c` is updated to accept an `index_state` parameter to locate the repository.
- Symbols: `enum auto_crlf` and `enum eol` remain in `environment.h` under a NEEDSWORK comment to avoid circular dependencies; new getter functions `repo_auto_crlf()`, `repo_core_eol()`, and `repo_global_conv_flags_eol()` added. No new CLI options, config keys, or test files.
- On-disk format: Unchanged.
- Test coverage: Not mentioned; likely unchanged.

Open questions and loose ends:
- **Critical design flaw**: The current implementation *increases* coupling to `the_repository` because `repo_config_values()` can only be populated via `git_default_config()`, which hard-codes the global repository. This actively works against libification goals and must be resolved before the series can proceed.
- Design choice: Whether to pass `repo` to functions (current approach) or store resolved values in `struct conv_attrs` (alternative). Author explicitly invited feedback on this; Patrick’s review now supersedes this as the primary open question.
- Circular dependency: `enum auto_crlf` and `enum eol` remain in `environment.h` under a NEEDSWORK comment, deferring cleanup to a future effort.

Participant positions:
- Aniket Gupta (author): Proposed the series, favored the `repo`-passing approach for consistency with prior conversions, and acknowledged the circular dependency trade-off as intentional deferrals. The series is now complete but requires redesign.
- Patrick Steinhardt: **Critical objection**: The current implementation undermines libification by hard-coding `the_repository` in `git_default_config()`. States the series should not be merged until this is fixed. Review is substantive, technically precise, and grounded in the broader architectural direction of the libification effort.

Related work: Part of the broader libification effort (removal of `the_repository` global and related state). Follows the pattern of earlier conversions but now requires rethinking the approach to avoid regressing modularity. No external dependencies or prior versions mentioned.
