This is a test modernization discussion targeting the `cat-file` subsystem. A new contributor, Jyotish Kumar, has identified a long-standing `FIXME` in `t1006-cat-file.sh` that marks a test for the `%(rest)` format atom as an expected failure when object names contain whitespace. The test currently uses the original object name (e.g., `HEAD:path/to/file with spaces`) as input, which `%(rest)` cannot handle correctly.

Jyotish proposes replacing the problematic object name with the resolved object ID (`$oid`), which the test helper already has available. This change makes the test pass locally (all 423 tests in the script), suggesting the `FIXME` could be removed entirely. The question is whether this is the right approach or if there’s a reason to keep the test as an expected failure.

The patch isn’t written yet—this is a pre-patch discussion seeking feedback on the proposed direction. The fix looks straightforward and well-motivated, but since it touches test expectations, it’s worth confirming whether the current behavior is intentional (e.g., to document a known limitation) or simply an oversight. If the mailing list agrees this is a valid improvement, it’s likely to be uncontroversial and could land quickly.
