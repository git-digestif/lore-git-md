This is a **bugfix** targeting the shallow clone and pack-objects subsystems, introduced in Git 2.56.0 by commit d43b9acb05 ("setup: unify setup of shallow file"). The patch reports a regression where a fetch combining `--filter=tree:0` with `--unshallow` (or `--deepen`) aborts with a BUG() in `should_include_obj()` when the fetched ref has moved past the local shallow tip. The issue stems from the environment-based shallow file propagation introduced in d43b9acb05: the `pack-objects` grandchild process inherits an empty `GIT_SHALLOW_FILE`, causing it to walk past the shallow boundary into promisor objects whose trees were never fetched, triggering the assertion.

The reproduction script is thorough and self-contained, demonstrating the failure on both Ubuntu's PPA build and a source-built 2.56.0, while confirming the same operation succeeds on 2.55.0. The author traces the regression to the environment variable propagation, showing that unsetting `GIT_SHALLOW_FILE` for the repack child process restores the old behavior. They also note the BUG() is reachable on 2.55.0 under slightly different conditions (a two-step fetch sequence), suggesting the underlying issue predates the environment change but was masked by the previous shallow file handling.

This is a clear regression with a well-documented reproduction case, making it a strong candidate for a targeted fix. The impact is limited to shallow clones using tree filters during unshallow operations, but the failure mode (a BUG() abort) is severe. The report does not include a proposed patch, but the root cause analysis points to the environment propagation as the immediate culprit. Expect discussion to focus on whether to revert the environment-based approach or add safeguards in `pack-objects` to handle missing promisor objects gracefully.
