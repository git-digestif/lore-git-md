This is a small feature patch for `gitk`, the built-in Git history browser.

The patch adds a new context-menu action labeled "Cherry-pick -x" that appears when the user right-clicks a commit. Selecting it runs `git cherry-pick -x` on that commit, appending the usual "cherry picked from commit ..." line to the new commit message. The implementation is a straightforward addition to the existing Tcl/Tk code in `gitk`: a new menu entry, a new callback procedure, and a call to the existing `exec_git` helper.

The commit message explains that this is a convenience feature for users who frequently cherry-pick commits and want the provenance trail that `-x` provides. No new dependencies or build-system changes are involved; it is purely a UI tweak.

`gitk` is maintained by Johannes Sixt (Hannes), so his review will be the gate for merging. The patch is self-contained and does not touch any core Git code, so it is unlikely to generate controversy.
