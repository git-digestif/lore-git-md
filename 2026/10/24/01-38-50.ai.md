This is a bugfix patch for `git reflog expire`. The issue is a minor but confusing UI inconsistency: when running `git reflog expire --dry-run --verbose` with `--all`, the output correctly says "would prune" for entries it would remove, but when specific refs are named on the command line, it incorrectly says "prune" instead of "would prune". The patch fixes this by ensuring the `dry_run` flag is set in the callback struct for named refs, matching the behavior already implemented for `--all`.

The commit message is clear and well-motivated, citing both the user report and the commit that introduced the inconsistency (fcd2c3d9d8). The fix itself is minimal: a one-line change to propagate the `dry_run` flag into the callback struct for named refs. The patch also adds thorough tests covering both named refs and `--all`, verifying that the output always uses "would prune" during dry runs and that no reflog entries are actually removed.

This is a straightforward, low-risk fix that addresses a real (if minor) usability issue. The test coverage is a welcome addition, as the commit notes that no prior tests checked the keep/prune wording. The patch is ready for review and looks uncontroversial.
