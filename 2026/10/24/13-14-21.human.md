This is a **workflow discussion** in the ongoing RFC thread about extending `git branch --delete-merged` to handle branches with deleted upstreams. D. Ben Knoble and Harald Nordgren, both active contributors, focus on **triangular workflows** (where users push to one branch but merge into another, e.g., GitHub PRs) and how Git’s defaults could better support them.

Knoble acknowledges Nordgren’s points about improving Git’s defaults for triangular workflows but expresses caution about changing them now, citing past controversy and the timing of Git 3.0. He agrees that `push.default=current` and `branch.autosetupmerge=inherit` would help users but notes that `inherit`’s behavior with remote-tracking branches is undocumented. He also plans to engage with Nordgren’s separate proposal to make `status.comparebranches=@{upstream} @{push}` the default, which would clarify the relationship between merge and push targets in `git status`.

The email doesn’t address the RFC’s technical questions (e.g., `--into` vs. composable filters) but reinforces the **underlying workflow pain** the RFC aims to solve. Knoble’s tone is pragmatic, balancing the desire for better defaults with the challenges of changing them. This exchange is useful for readers tracking Git’s evolving defaults but doesn’t advance the RFC’s design debate.
