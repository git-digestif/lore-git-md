# Thread deltas

## 2026/10/24

- [2026/10/24/17-59-55 by Daniel Zoghalchali <daniel@latchkey.dev>] Daniel Zoghalchali reported that since v2.56.0, a fetch combining a tree filter with --unshallow (or --deepen) aborts in pack-objects with "BUG: should_include_obj should only be called on existing objects" when the fetched ref has moved past the local tip in a non-partial shallow clone, whereas v2.55.0 completes the same fetch.
- [2026/10/24/17-59-55 by Daniel Zoghalchali <daniel@latchkey.dev>] He identified the regression as caused by d43b9acb05 ("setup: unify setup of shallow file"), which exports GIT_SHALLOW_FILE so the pack-objects grandchild inherits the empty shallow file, stops treating the local tip as a shallow boundary, walks to the tip's parent (a promisor commit fetched without trees), and hits the BUG on that parent's missing root tree.
- [2026/10/24/17-59-55 by Daniel Zoghalchali <daniel@latchkey.dev>] He confirmed the mechanism by wrapping only the repack child: unsetting GIT_SHALLOW_FILE for it makes 2.56.0 pass, while setting GIT_SHALLOW_FILE= for it makes 2.55.0 fail the same way.
- [2026/10/24/17-59-55 by Daniel Zoghalchali <daniel@latchkey.dev>] He noted the BUG() is also reachable on 2.55.0 without the environment change, via a filtered --unshallow of the local tip followed by a filtered fetch of a moved ref, because the walk reaches promisor commits whose trees were never fetched.

## 2026/10/26

- [2026/10/26/13-04-30 by Patrick Steinhardt <ps@pks.im>] Patrick Steinhardt confirmed the reproducer works, and identified the root cause as `is_not_in_promisor_pack_obj()` in builtin/pack-objects.c calling `BUG()` when `odb_read_object_info_ext()` returns an error, which is invalid in a partial clone where objects may legitimately be missing; he argued the GIT_SHALLOW_FILE propagation itself is not the bug.
- [2026/10/26/13-04-30 by Patrick Steinhardt <ps@pks.im>] He reproduced the separately reported 2.55.0 case (filtered --unshallow of the local tip followed by a filtered fetch of a moved ref) and confirmed it shares the same root cause, existing before the GIT_SHALLOW_FILE change.
- [2026/10/26/13-04-30 by Patrick Steinhardt <ps@pks.im>] He proposed fixing `is_not_in_promisor_pack_obj()` to `return 0;` instead of `BUG()` on read error, and said he would send a patch the following day.
