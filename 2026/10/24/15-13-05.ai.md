This is the final patch (5/5) in Harald Nordgren’s v10 series implementing a "matching-inspired" fetch mode for shallow repositories. D. Ben Knoble’s review of this patch is **surface-level**, focusing on a minor wording inconsistency in the commit message and documentation rather than the implementation itself.

The patch makes `--limited-fetch` the default when adding a remote in a shallow repository, addressing a long-standing usability issue where `git remote add` in a shallow clone would still configure a wildcard refspec, defeating the purpose of shallow cloning. Knoble notes that the commit message initially frames the problem as specific to "single-branch shallow clones" but the implementation only checks for shallow repositories (not single-branch). This is a reasonable simplification, as Git has no reliable way to track whether a repository was cloned with `--single-branch`, and shallow repositories are the primary use case for the feature. The documentation and code are otherwise clear and uncontroversial.

The implementation is minimal: it modifies `builtin/remote.c` to check `is_repository_shallow(the_repository)` when the `limited_fetch` flag is unset (`-1`), defaulting to `--limited-fetch` unless explicitly overridden. The change reuses existing machinery (the `limited_fetch` flag and `is_repository_shallow()` helper) without introducing new technical debt. The documentation in `git-remote.adoc` is updated to explain the new default behavior, and four new tests in `t/t5505-remote.sh` verify the shallow-repository default, `--no-limited-fetch` override, `-t/--track` behavior, and full-repository backward compatibility.

Knoble’s feedback does not raise any technical concerns or request changes to the implementation. The patch is ready for merging and aligns with the rest of the series, which is technically complete and awaiting a second Ack before graduating to `next`. The only open question—whether `--limited-fetch` should be the default for *all* repositories, not just shallow ones—is explicitly out of scope for this patch.
