This is the first patch in a four-part refactoring series by Aniket Gupta, continuing the Git libification effort by eliminating global state for line-ending configuration. The patch prepares the groundwork by adding a `struct repository *` parameter to three key working-tree conversion functions (`convert_to_working_tree_ca`, `async_convert_to_working_tree_ca`, and `get_stream_filter_ca`) and updating all callers to pass the appropriate repository instance. The parameter is marked `UNUSED` for now, as the actual migration of the configuration variables happens in later patches.

The patch moves two static inline wrapper functions (`convert_to_working_tree` and `async_convert_to_working_tree`) from `convert.h` into `convert.c` because they need to access the repository from the index, which the header cannot do. This is a mechanical but necessary change to avoid circular dependencies. The patch touches four files (`convert.c`, `convert.h`, `entry.c`, and `parallel-checkout.c`) and is part of the broader effort to make Git's internals more modular by removing reliance on global variables.

The series follows the established pattern of prior libification conversions, and the author explicitly invites feedback on the design choice between passing `repo` to functions (the current approach) and storing resolved values in `struct conv_attrs` (an alternative). This patch does not yet change behavior, but it sets the stage for the subsequent patches that will move `core.autocrlf`, `core.eol`, and `core.safecrlf` into `struct repo_config_values`.

The patch looks well-structured and aligns with the project's ongoing libification goals. The main point of discussion is likely to be the design choice mentioned above, but the patch itself is a straightforward and necessary step in the series.
