This is the third patch in Aniket Gupta’s four-patch series converting line-ending configuration variables (`core.autocrlf`, `core.eol`, `core.safecrlf`) from global variables into `struct repo_config_values` as part of the Git libification effort. The patch moves `core.eol` into the per-repository configuration structure, following the same pattern established in the earlier patches.

The change is mechanical and consistent with the series’ goal: eliminate global state to make Git’s internals more modular. The patch touches four files (`convert.c`, `convert.h`, `environment.c`, `environment.h`), removing the global `core_eol` variable and replacing it with a new field in `struct repo_config_values`. A getter function, `repo_core_eol()`, is introduced to access the value, and the configuration parsing in `environment.c` is updated to write to the per-repository structure instead of the global variable.

The circular dependency issue noted in the previous patches persists: `enum eol` remains in `environment.h` under a `NEEDSWORK` comment because moving it to `convert.h` would create a dependency loop. This is a known trade-off in the series, deferred for future cleanup. The patch does not change behavior, on-disk format, or test coverage, and no new CLI options or config keys are introduced.

This patch is a straightforward continuation of the libification effort, following the established pattern of earlier conversions. The main point of discussion for the series—whether to pass `repo` to functions or store resolved values in `struct conv_attrs`—remains open, but this patch does not revisit that question. The work appears well-scoped and aligns with the project’s ongoing goals.
