Thread type: test modernization discussion / design clarification

Core problem or goal
The `%(rest)` format atom in `git cat-file --batch-check` fails when the object name passed to it contains whitespace (e.g., `HEAD:path/to/a/file with spaces`). The test script `t1006-cat-file.sh` currently marks this case as an expected failure (`test_expect_failure`) via a long-standing `FIXME`. The discussion clarifies whether this limitation is intentional (and thus the test should skip the case) or fixable (and thus the test should be updated to use the resolved object ID `$oid` instead of the original object name).

Current status
The design question is resolved: the `%(rest)` limitation is intentional and documented, not a bug. The test should be updated to skip the whitespace case rather than treat it as an expected failure. No patch has been posted yet; the next step is a mechanical test update to skip the case and remove the `FIXME` comment. No changes to `git cat-file` or `%(rest)` are needed.

Key technical details
- Subsystem: `git cat-file` (plumbing command)
- Test file: `t/t1006-cat-file.sh`
- Format atom: `%(rest)`
