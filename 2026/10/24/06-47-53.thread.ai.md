Core problem or goal
The `%(rest)` format atom in `git cat-file --batch-check` fails when the object name contains whitespace (e.g., `HEAD:path/to/a/file with spaces`). The test script `t1006-cat-file.sh` previously marked this case as an expected failure (`test_expect_failure`) with a `FIXME` comment. The discussion clarified whether this limitation was intentional (requiring the test to skip the case) or fixable (requiring the test to use the resolved object ID `$oid`). The resolution was that the limitation is intentional and documented, so the test should skip the whitespace case.

Current status
The design question is resolved, and the author (jyotish Kumar) has submitted a mechanical patch to update the test. The patch replaces the `test_expect_failure` marker with a case-based skip for object names containing whitespace, removes the `FIXME` comment, and aligns the test suite with the established design constraint. No changes to `git cat-file` or `%(rest)` are needed or proposed. The patch is uncontroversial and ready for review.
