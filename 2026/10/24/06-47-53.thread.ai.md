Core problem or goal
The `%(rest)` format atom in `git cat-file --batch-check` fails when the object name passed to it contains whitespace (e.g., `HEAD:path/to/a/file with spaces`). The test script `t1006-cat-file.sh` marks this case as an expected failure (`test_expect_failure`) via a long-standing `FIXME`. The goal is to remove the limitation by changing the test to use the resolved object ID (`$oid`) instead of the original object name, which may contain whitespace.

Current status
No patch has been posted yet; the thread is in the design/discussion phase. The author has a working local change and is seeking feedback on whether the approach is correct before submitting a formal patch.

Key technical details
- Subsystem: `git cat-file` (plumbing command)
- Test file: `t/t1006-cat-file.sh`
- Format atom: `%(rest)`
- Behavior change: test helper now passes `$oid` (whitespace-free) instead of the original object name (which may contain whitespace)
- No on-disk format or user-visible behavior changes; this is purely a test-suite fix

Open questions and loose ends
