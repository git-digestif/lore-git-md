This thread is about a small but long-standing quirk in Git’s test suite. The test `t1006-cat-file.sh` has a `FIXME` comment marking a case where the `%(rest)` format atom in `git cat-file --batch-check` fails when given an object name containing whitespace (like `HEAD:path/to/file with spaces`). The original author, jyotish kumar, suggested fixing the test by using the resolved object ID (`$oid`) instead of the original object name to avoid the issue.

Jeff King (Peff) and Junio Hamano have since weighed in to say the limitation is intentional and documented, not a bug. The test should simply skip the whitespace case rather than treating it as an expected failure. Junio’s latest email effectively closes the design discussion: the `%(rest)` behavior is correct as-is, and the test just needs a mechanical update to reflect that. The only remaining step is for someone to prepare a patch to clean up the test and remove the misleading `FIXME`. No changes to `git cat-file` or `%(rest)` are needed.
