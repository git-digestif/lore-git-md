This thread is about modernizing a test in Git’s test suite to correctly handle a long-standing edge case. The test, `t1006-cat-file.sh`, checks how the `%(rest)` format atom in `git cat-file --batch-check` behaves when given an object name containing whitespace. The test had marked this case as an expected failure (`test_expect_failure`) with a `FIXME` comment, but the discussion clarified that the limitation is intentional and documented—`%(rest)` is not designed to work with whitespace in object names.

The key participants were Jyotish Kumar (the author), Jeff King (Peff), and Junio C Hamano (the maintainer). Initially, Jyotish proposed fixing the issue by replacing the object name with its resolved ID (`$oid`), but Peff and Junio argued that the limitation is by design, and the test should simply skip the whitespace case. Jyotish accepted this reasoning and volunteered to prepare the patch to update the test accordingly.

The patch itself is now ready: it mechanically replaces the `test_expect_failure` with a case-based skip for whitespace, removes the `FIXME` comment, and leaves the rest of the test unchanged. No changes to `git cat-file` or `%(rest)` are needed, as the behavior is intentional. The patch is uncontroversial and aligns the test suite with the established design constraint. The thread is effectively resolved, with only the patch submission remaining.
