This is the author’s reply to Junio C Hamano’s latest message in the `git reflog` feature discussion. Harald Nordgren acknowledges Junio’s suggestion to change `git reflog`’s default behavior to operate on the current branch rather than HEAD, calling it a clear improvement that he would adopt immediately. He then shifts focus to a separate UX issue: the verbose output format when `git reflog` is run on a branch (e.g., `refs/heads/fetch-shallow-narrow-refspec@{0}`), which he finds unnecessarily heavy and proposes cleaning up. The message does not engage with the deeper architectural concerns raised by Phillip Wood (correctness gaps in `--historical-branch`, viability of `--operations`) or Junio’s long-term proposal to refactor multi-step commands to work on detached HEAD. Instead, it treats the branch-default change as a settled improvement and moves on to a cosmetic formatting detail, leaving the core debates unresolved.
