This is the first patch in a four-patch refactoring series that continues the Git libification effort by preparing the working tree conversion functions to access repository-specific line-ending configuration. The patch adds a `struct repository *` parameter to three key functions in `convert.c` (`convert_to_working_tree_ca`, `async_convert_to_working_tree_ca`, and `get_stream_filter_ca`) and updates all callers to pass the appropriate repository instance. The parameter is marked `UNUSED` for now, as the actual migration of the configuration variables happens in later patches.

The patch moves the static inline wrapper functions (`convert_to_working_tree` and `async_convert_to_working_tree`) from `convert.h` into `convert.c` because they need to access the repository from the index, which the header cannot do. This is a mechanical but necessary step to avoid circular dependencies. The changes touch four files: `convert.c` (primary), `convert.h`, `entry.c`, and `parallel-checkout.c`, with most of the complexity in `convert.c`.

The patch follows the established pattern of prior libification conversions, which suggests it is a well-scoped and serious contribution. The author explicitly notes that the repository parameter is not yet used, which is a good sign of transparency. The main point of discussion for this patch is likely to be the design choice of passing `repo` to functions rather than storing resolved values in `struct conv_attrs`, though that debate is more relevant to the series as a whole than to this specific patch.

This patch does not change behavior or introduce new functionality; it is purely preparatory. The next patches in the series will migrate the line-ending configuration variables (`core.autocrlf`, `core.eol`, and `core.safecrlf`) into `struct repo_config_values`, at which point the `UNUSED` markers will be removed. The patch is part of the broader effort to eliminate global state and make Git's internals more modular.
