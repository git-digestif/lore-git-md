This is a reply from Junio C Hamano in the ongoing review of Srujith A. Poojary’s patch to use safe integer helpers in `diff-delta.c`. The patch itself is a bugfix targeting a theoretical overflow risk in allocation size calculations, and this email is Junio’s feedback on the commit message’s clarity and precision.

Junio suggests the commit message should walk through the arithmetic more explicitly: instead of saying “struct alignment padding could cause overflow,” it should lay out the exact sizes and caps (e.g., “N instances of A, each 8 bytes, plus M instances of B, which could be W or Z bytes due to padding”). He provides a template for how to phrase this analysis for the first allocation and expects the author to apply the same rigor to the second one. He also corrects a minor wording nit: “hsize + 1 inside st_add3()” is misleading because the addition happens before the helper is called, not inside it.

The email does not resolve the central question—whether the patch should proceed as a precautionary measure—but it sets the bar for the commit message’s technical precision. If the author revises the message along these lines, it will likely satisfy Junio’s review criteria for clarity, leaving only the project’s appetite for theoretical fixes as the remaining hurdle.
