Thread identity
Subject: regression: BUG() in `should_include_obj()` during `--filter=tree:0` + `--unshallow` fetch
Series version: standalone bugfix (no prior versions)
Originating author: Daniel Zoghalchali <daniel@latchkey.dev>
Thread type: bug report

Core problem or goal
A regression introduced in Git 2.56.0 (commit d43b9acb05) causes a fetch combining `--filter=tree:0` with `--unshallow` (or `--deepen`) to abort with a BUG() in `should_include_obj()`. The failure occurs when the fetched ref has moved past the local shallow tip, and the `pack-objects` grandchild process inherits an empty `GIT_SHALLOW_FILE` environment variable, leading it to walk past the shallow boundary into promisor objects whose trees were never fetched.

Current status
Under review; no patch proposed yet. The regression is confirmed on both Ubuntu's PPA build and source-built 2.56.0, while the same operation succeeds on 2.55.0. The root cause is identified as the environment-based shallow file propagation introduced in d43b9acb05. A workaround (unsetting `GIT_SHALLOW_FILE` for the repack child) restores the old behavior, but the underlying issue may predate the environment change.

Key technical details
- Subsystems: shallow clone, pack-objects
- Files: `setup.c` (environment propagation), `pack-objects.c` (`should_include_obj()`)
- New/renamed symbols: none
- Old behavior: shallow file handled via file descriptor passing; no BUG() during unshallow + tree filter
- New behavior: environment-based shallow file propagation; BUG() triggered when walking past shallow boundary into missing promisor objects
- On-disk format: unchanged
- Test coverage: reproduction script provided; no existing test failure noted

Open questions and loose ends
1. Should the fix revert the environment-based shallow file propagation or add safeguards in `pack-objects` to handle missing promisor objects gracefully?
2. The author notes the BUG() is reachable on 2.55.0 under a two-step fetch sequence, suggesting the underlying issue predates the environment change. Is this a separate bug, or does it share the same root cause?
3. No proposed patch yet; discussion likely to focus on the trade-offs between reverting the environment change and adding defensive checks.
