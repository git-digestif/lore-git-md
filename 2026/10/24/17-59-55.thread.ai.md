Thread identity
Subject: regression: BUG() in `should_include_obj()` during `--filter=tree:0` + `--unshallow` fetch
Series version: standalone bugfix (v1, formal patch submission)
Originating author: Daniel Zoghalchali <daniel@latchkey.dev>
Thread type: bug report / regression fix

Core problem or goal
A regression introduced in Git 2.56.0 (commit d43b9acb05) causes a fetch combining `--filter=tree:0` with `--unshallow` (or `--deepen`) to abort with a BUG() in `should_include_obj()`. The failure occurs when the fetched ref has moved past the local shallow tip, and the `pack-objects` grandchild process inherits an empty `GIT_SHALLOW_FILE` environment variable, leading it to walk past the shallow boundary into promisor objects whose trees were never fetched. The underlying issue predates the environment change: the same BUG() is reachable on Git 2.56.0-rc0 and Git 2.55.0 under a two-step fetch sequence, indicating the function’s assumption that all objects exist locally is incorrect in partial clones.

Current status
Patch v1 submitted by Patrick Steinhardt; under review. The fix replaces the BUG() in `is_not_in_promisor_pack_obj()` with a graceful return (`return 0`), treating missing promisor objects as non-promisor objects. This aligns with partial clone expectations and resolves the regression without reverting the environment-based shallow file propagation. The patch is minimal (single line in `builtin/pack-objects.c`), well-motivated, and addresses both the immediate symptom and the underlying incorrect assumption. No open questions remain about root cause or fix direction.
