Subject: [PATCH] gitk: add "Cherry-pick with -x" context-menu action
Series version: single-patch, no cover letter
Originating author: Ralf Habacker
Thread type: platform compatibility / UI enhancement (gitk)

Core problem or goal
Add a context-menu entry in `gitk` that invokes `git cherry-pick -x` on the selected commit, appending the “(cherry picked from …)” trailer to the resulting commit message. The change is purely in the Tcl/Tk frontend (`gitk-git/gitk`) and does not touch core Git code or documentation.

Current status
Under review; no prior versions. The patch is self-contained, has no external dependencies, and does not alter existing behavior. The maintainer of `gitk` (Johannes Sixt) has raised usability concerns about menu clutter and suggested implementation refinements (menu label wording, proc default, translation file handling) but has not rejected the patch outright. Community input on the feature's necessity and UI design remains solicited.

Key technical details
- Files touched: `gitk-git/gitk` (Tcl/Tk code)
- New menu entry: “Cherry-pick with -x” in the right-click popup (proposed relabel to “Cherry-pick with cross-reference”)
- New symbol: `cherrypick` proc extended with optional `-x` flag (proposed default to `-r` instead of `-x`)
- Test coverage: `t9001-gitk.sh` verifies the menu item appears and the trailer is added
- Translation files: avoid manual edits
- Commit message punctuation: em-dash vs. hyphens (`--`/`---`) for visual clarity in monospace contexts (low-weight discussion)

Open questions and loose ends
- **Usability**: Is the feature valuable enough to justify adding another entry to the already-long context menu? Community input is still needed.
- **Implementation**: Should the menu label avoid jargon (“-x”) and use “Cherry-pick with cross-reference”? Should the `cherrypick` proc default to `-r` (no trailer) rather than `-x` to simplify caller logic?
