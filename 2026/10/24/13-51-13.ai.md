This is a substantive review of the `git reflog` `--operations` and `--historical-branch` feature series (v2). Phillip Wood raises two major technical concerns that could significantly impact the series' viability.

First, Phillip is skeptical of `--operations`, arguing it oversells its capabilities. The option claims to show "one entry per command," but this is misleading: not all commands update the reflog (e.g., `git cherry-pick A B C` creates multiple indistinguishable entries), and some operations (like working tree modifications) leave no reflog trace at all. He suggests the feature's goals could be better achieved by filtering the branch reflog (noting that `git reflog` should default to the current branch rather than HEAD). While not outright opposed to filtering, Phillip warns against presenting this as a complete "operations log," which would require a separate subsystem.

Second, Phillip proposes an alternative implementation for `--historical-branch`: instead of a dedicated flag, he suggests exposing the branch name via a format specifier (e.g., `%gb`), allowing users to include it in custom formats. This would be more flexible and align with Git's existing decoration system. He also flags a critical correctness issue: the current implementation doesn't properly handle `git rebase <upstream> <branch>`, where the branch name in the "(finish)" message must be compared to the pre-rebase checkout (requiring backward reflog traversal). His linked patch demonstrates the complexity of this edge case, which the series currently doesn't address.

The review is substantive and tested: Phillip identifies specific technical gaps (command coverage, rebase edge cases), references his own working patch for the branch-name logic, and suggests concrete improvements (format specifiers). His concerns about `--operations` go beyond implementation to question whether the feature belongs in Git's core at all, given existing alternatives like `tig reflog`. The architectural implications—particularly for `--historical-branch`—are significant, as the current approach may need a ground-up redesign to handle all edge cases correctly.
