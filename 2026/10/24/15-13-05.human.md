This is the final patch in Harald Nordgren’s ten-iteration series that introduces a “matching-inspired” fetch mode for shallow repositories. The patch makes `--limited-fetch` the default when running `git remote add` in a shallow repository, so that the new remote does not automatically fetch every branch the remote has—something that can hang or take minutes in repositories with many branches.

The change is tiny and surgical: it adds a single check for `is_repository_shallow(the_repository)` when the `limited_fetch` flag is still unset (`-1`), defaulting to `--limited-fetch` unless the user explicitly says `--no-limited-fetch`. The documentation in `git-remote.adoc` is updated to explain the new default, and four new tests in `t/t5505-remote.sh` verify that the shallow-repository default works, that `--no-limited-fetch` overrides it, that `-t/--track` still configures an explicit refspec, and that full repositories continue using wildcard refspecs.

The patch is uncontroversial and ready to graduate to `next` alongside the rest of the series.
