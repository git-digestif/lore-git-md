This is a **platform-compatibility test fix** for a macOS-specific issue in `t/t1450-fsck.sh`. The patch corrects a typo in Torsten Bögershausen’s earlier fix for the same problem: it replaces `mv -v` (verbose) with `mv -f` (force) to suppress the BSD `mv` utility’s interactive prompt when overwriting a read-only loose object file. The error was caught by SZEDER Gábor, who noted the déjà vu—this exact issue (and the same typo) surfaced in a different test two years ago.

The fix is trivial and uncontroversial. The test in question verifies that `git rev-list --verify-objects` detects corrupted loose blobs, and the `mv` command is purely part of the test setup. Using `-f` ensures portability across platforms (GNU `mv` ignores `-f`, while BSD `mv` respects it), and the change does not alter the test’s intent. The thread confirms the root cause—BSD `mv`’s POSIX-compliant behavior when standard input is a terminal—and the resolution is procedurally final. No further discussion or rerolls are expected.
