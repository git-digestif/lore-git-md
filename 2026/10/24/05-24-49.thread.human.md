This thread fixes a Bash completion regression affecting four Git built-in commands: `patch-id`, `diff-pairs`, `fast-import`, and `var`. These commands were converted to use the `parse-options` API in earlier work, but their `NO_PARSEOPT` flags in `git.c` were never removed, so completion scripts couldn’t see their options. Tanga Joris split the fix into two patches: the first (now posted as v2) removes the flag for `patch-id`, `diff-pairs`, and `var`, while a follow-up handles `fast-import` separately due to its unique interaction with `--git-completion-helper`.

The work is straightforward and well-justified. The v2 patch is mechanical—just removing three flags—and aligns the `commands[]` table with the actual implementation. The follow-up for `fast-import` moves the `--git-completion-helper` check to the start of `cmd_fast_import()` so it returns immediately without blocking or creating temporary files, addressing an edge case René Scharfe identified. A new test in `t/t9300-fast-import.sh` verifies the fix for `fast-import`, but the other three commands lack explicit test coverage.

The series is under review and blocked on Christian Couder’s `cc/early-scan-options` series reaching stability and integration in `next`. Junio has clarified that the follow-up doesn’t need Christian’s approval but should wait for the dependent topic to settle. No objections have been raised, and the approach has broad support. The fix is minimal, focused, and restores expected completion behavior for all four commands.
