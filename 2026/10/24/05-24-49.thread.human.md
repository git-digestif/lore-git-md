This thread is about fixing a Bash completion regression for four Git built-in commands (`patch-id`, `diff-pairs`, `fast-import`, and `var`). These commands had been converted to use the `parse-options` API but were still marked with the `NO_PARSEOPT` flag in `git.c`, preventing their options from appearing in completion. Tanga Joris's v5 series (three patches) centralizes the completion-helper logic in `parse-options.c`, removes the redundant `NO_PARSEOPT` flag, and adds a defensive test to catch future regressions.

The series is now under review and has addressed all prior feedback, including edge cases for `fast-import`, test coverage for `--git-completion-helper-all`, and documentation improvements. The refactoring is stable and does not alter existing behavior, as confirmed by Cynthia Uche's tested review. The main blocker is Christian Couder's `cc/early-scan-options` series, which needs to reach stability and integration in `next` before this series can proceed.

The final patch adds a defensive test in `t/t0012-help.sh` to ensure no command retains `NO_PARSEOPT` after being converted to `parse-options`. The test skips some commands (like `var`) that only have short options, but it’s a well-motivated safeguard. All key participants—Junio, René Scharfe, and Cynthia Uche—have weighed in substantively, and the series is ready for final review.
