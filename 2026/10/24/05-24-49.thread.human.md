This thread is about fixing a Bash completion regression for four Git built-in commands (`patch-id`, `diff-pairs`, `fast-import`, and `var`) that weren’t showing their command-line options in completions because they were incorrectly marked with the `NO_PARSEOPT` flag. Tanga Joris’s v4 series (three patches) centralizes the completion-helper logic in `parse-options.c` to avoid per-command boilerplate and side effects, then removes the redundant flag from the four commands. The series is under review and depends on Christian Couder’s `cc/early-scan-options` series being stable and preferably in `next`.

The latest patch adds a defensive test to catch future regressions where commands converted to `parse-options` still retain `NO_PARSEOPT`. The test checks that no built-in command outside the parseopt list prints long options when run with `--git-completion-helper`, effectively catching the three commands fixed in the series. It skips a few diff-related commands and `rev-parse` for legitimate reasons, but it doesn’t catch `var` because that command only has short options—this limitation is clearly documented. The test is a straightforward and useful addition, though it could be refined later to cover short options.

Key participants have all weighed in: René Scharfe identified the `fast-import` edge case, Junio Hamano proposed the centralized refactoring, Kaartic Sivaraam suggested the defensive test, and Cynthia Uche validated the changes across all built-ins. The series has addressed all feedback, and the only remaining loose ends are the dependency on `cc/early-scan-options` and the test’s limitation with short options. No merge status has been reported for either series.
