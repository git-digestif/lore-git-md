This thread is about fixing a Bash completion regression for four Git built-in commands (`patch-id`, `diff-pairs`, `fast-import`, and `var`) that were converted to use the `parse-options` API but still had the `NO_PARSEOPT` flag set in `git.c`. The regression meant users got no completion suggestions for these commands' options. Tanga Joris's v3 series (two patches) centralizes the completion-helper logic in `parse-options.c` and removes the redundant `NO_PARSEOPT` flags, restoring expected behavior.

The series is under review and depends on Christian Couder's `cc/early-scan-options` series reaching stability and integration in `next`. Junio Hamano proposed the refactoring approach, and René Scharfe identified an edge case with `fast-import` that the series now handles. The patches touch `parse-options.c`, `git.c`, and add a test for `fast-import` to ensure no temporary files are created during completion. While the core fix is uncontroversial, Kaartic Sivaraam suggested adding a defensive test to catch future regressions—specifically, a test that would flag commands adopting `parse-options` but still marked `NO_PARSEOPT`. This is a minor enhancement and not a blocker.

No other participants have responded to v3 yet, and the series lacks test coverage for `patch-id`, `diff-pairs`, and `var` (only `fast-import` is tested). The fix is ready for integration once the dependency is resolved, but the maintainer may wait for broader feedback or the suggested test addition before merging.
