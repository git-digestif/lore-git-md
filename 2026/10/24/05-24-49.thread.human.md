This thread fixes a Bash completion regression affecting four Git built-in commands (`patch-id`, `diff-pairs`, `fast-import`, and `var`). These commands weren’t showing available options in completion because they were still marked with the `NO_PARSEOPT` flag in `git.c`, even though they had already been converted to use the `parse-options` API. Tanga Joris’s v4 series (three patches) centralizes the completion-helper logic in `parse-options.c`, removing the need for per-command boilerplate and avoiding side effects like temporary file creation or blocking input. The series has addressed all prior feedback, including René Scharfe’s edge case for `fast-import`, Kaartic Sivaraam’s suggestions for commit-message clarity and a defensive test, and Cynthia Uche’s validation that the refactoring doesn’t alter existing behavior.

The latest update responds to Junio’s review, revising a comment in `parse-options.h` to avoid over-specifying the `fast-import` edge case. The new comment will clarify that the function is meant for commands that defer option parsing, improving clarity without changing the code. The series is still blocked on Christian Couder’s `cc/early-scan-options` reaching stability in `next`, but no adjustments to that series are needed. Testing covers `fast-import`’s completion behavior and includes a defensive test to catch future `NO_PARSEOPT` regressions, though it doesn’t yet handle commands with only short options (like `var`). The fix is ready for integration once its dependency is stable.
