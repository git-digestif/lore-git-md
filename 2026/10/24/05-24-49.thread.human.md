This thread is about fixing a Bash completion regression for four Git commands (`patch-id`, `diff-pairs`, `fast-import`, and `var`) that were converted to use the `parse-options` API but still had the `NO_PARSEOPT` flag set, preventing their options from appearing in tab completion. Tanga Joris proposed a patch to remove the flag for all four commands, but after review from René Scharfe, it became clear that `fast-import` has a unique edge case—its `--git-completion-helper` mode only prints options after receiving a line of input, breaking seamless completion. Tanga now plans a split approach: a v2 patch to fix `patch-id`, `diff-pairs`, and `var` immediately, and a separate follow-up for `fast-import` that will depend on Christian Couder’s "early-scan" series.

Junio C Hamano weighed in to clarify the process for the follow-up patch. He noted that while Christian’s approval isn’t required, the "early-scan" series must be stable and ideally in `next` before the `fast-import` fix can proceed. He encouraged Tanga to review Christian’s series, framing it as both a way to advance their own work and a contribution to the community—topics only move forward with positive reviews, and as a potential user of the feature, Tanga is well-positioned to provide meaningful feedback. The thread is currently under review, with no merge status reported for either the v2 patch or the follow-up. The only open question is whether the `fast-import` fix will require changes to the completion script or can rely entirely on Christian’s series.
