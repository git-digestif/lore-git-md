This thread is about fixing a Bash completion regression for four Git commands (`patch-id`, `diff-pairs`, `fast-import`, and `var`) that weren’t showing available options because they were incorrectly marked with the `NO_PARSEOPT` flag. Tanga Joris sent a v3 series that centralizes completion-helper logic in `parse-options.c`, removing the need for per-command boilerplate and avoiding side effects like temporary file creation or blocking on input. The series has been well-received, with René Scharfe and Junio Hamano providing key feedback, and Cynthia Uche confirming the refactoring doesn’t break existing behavior.

The current status is that the series is under review and ready for integration once Christian Couder’s `cc/early-scan-options` series stabilizes in `next`. The only remaining loose end is test coverage: while `fast-import` is now tested, the `--git-completion-helper-all` branch and the other three commands (`patch-id`, `diff-pairs`, `var`) still lack tests. Tanga has agreed to add coverage for the `-all` branch in v4, crediting Cynthia Uche for the suggestion. No objections or new technical concerns have been raised, so the path forward is straightforward once the dependency is resolved.
