This thread is about fixing a Bash completion regression that left four Git built-in commands (`patch-id`, `diff-pairs`, `fast-import`, and `var`) unable to show their available options. The issue arose because these commands were still marked with the `NO_PARSEOPT` flag in `git.c` despite having been converted to use the `parse-options` API. Tanga Joris’s v3 series (two patches) centralizes the handling of `--git-completion-helper` in `parse-options.c`, eliminating per-command boilerplate and side effects like temporary file creation or blocking on input—most notably for `fast-import`, which previously froze during completion.

The series is under review and has converged on a design proposed by Junio Hamano: the first patch moves completion logic into `show_usage_with_options_if_asked()`, and the second removes the redundant `NO_PARSEOPT` flags. The work depends on Christian Couder’s `cc/early-scan-options` series reaching stability and integration in `next`, but no changes to that series are currently needed. René Scharfe’s review identified the `fast-import` edge case, and Kaartic Sivaraam suggested minor improvements to commit messages and documentation, which Tanga has agreed to incorporate. The only remaining loose ends are the lack of test coverage for three of the four commands and an open suggestion for a defensive test to catch future regressions. No substantive objections remain, and the series is ready for integration once its dependency is resolved.
