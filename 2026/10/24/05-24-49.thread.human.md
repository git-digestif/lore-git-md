This thread is about fixing a Bash completion regression for four Git built-in commands (`patch-id`, `diff-pairs`, `fast-import`, and `var`) that weren’t offering command-line options in completion because they were still marked with the `NO_PARSEOPT` flag despite using the `parse-options` API. Tanga Joris proposed a two-part series: a v2 patch removing `NO_PARSEOPT` for `patch-id`, `diff-pairs`, and `var`, and a follow-up v1 patch addressing `fast-import`’s unique edge case by moving the `--git-completion-helper` check to the start of its command function.

The series is under review and depends on Christian Couder’s `cc/early-scan-options` series being stable and preferably in `next`. René Scharfe identified the `fast-import` edge case, and Junio C Hamano clarified that the follow-up doesn’t need Couder’s approval but must wait for the dependent topic. In the latest email, Junio proposes a more general solution: extending `show_usage_with_options_if_asked()` in `parse-options.c` to handle completion helper flags centrally, eliminating the need for per-command boilerplate. This refactoring is small, preserves the existing test behavior, and makes the fix more maintainable. No objections have been raised, and the series is now waiting for either Tanga’s response to Junio’s suggestion or further review.
