This is the second patch in Aniket Gupta’s four-patch series refactoring Git’s line-ending configuration (`core.autocrlf`, `core.eol`, `core.safecrlf`) as part of the ongoing libification effort. The patch moves the global `auto_crlf` variable into `struct repo_config_values`, replacing direct global access with a repository-aware getter (`repo_auto_crlf()`).

The change is mechanical but non-trivial: it updates configuration parsing in `environment.c` to store the value in the per-repository structure, adds the getter, and propagates the `struct repository *` parameter through the call chain in `convert.c` so functions like `text_eol_is_crlf()` and `output_eol()` can access the repository-specific setting. The patch also preserves the `enum auto_crlf` definition in `environment.h` to avoid a circular dependency, leaving a `NEEDSWORK` comment for future cleanup.

This is a well-scoped step in the libification effort, following the established pattern of prior conversions. The patch itself is clean and focused, with no behavior change—it merely prepares the ground for later patches that will remove the global variable entirely. The main point of discussion remains the design choice (passing `repo` vs. storing resolved values in `struct conv_attrs`), which the author explicitly flagged in the cover letter.
