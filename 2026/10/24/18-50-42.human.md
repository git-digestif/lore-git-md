This is a bugfix for the OSS-Fuzz integration. The patch addresses a regression introduced in commit f1141b4391 (2025-08-15), where `parse_commit_graph()` began calling `prepare_repo_settings()`, which expects a non-NULL `gitdir` even when the repository settings are marked as initialized. The fuzzer's repository lacks a `gitdir`, causing a BUG assertion and preventing the fuzzer from exercising optional commit-graph chunks (generation data and Bloom filters).

The fix is minimal: it sets a placeholder `.git` directory (freed later by `repo_clear()`) to satisfy `prepare_repo_settings()`'s check. This mirrors an existing pattern in `test-path-utils.c`. The change is confined to the fuzzer harness (`oss-fuzz/fuzz-commit-graph.c`) and doesn’t affect production code.

The patch is well-motivated, with a clear explanation of the regression and why the fix works. It’s a targeted fix for a specific testing tool, so it’s unlikely to be controversial. If you care about fuzz testing or commit-graph internals, this is worth a quick look.
