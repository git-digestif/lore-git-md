This is a bugfix patch for `git reflog expire`. The issue is cosmetic but confusing: when using `--dry-run --verbose` with a named ref (like `HEAD`), the command incorrectly reports entries as "prune" instead of "would prune", making it seem as if they were actually removed. The fix ensures the dry-run flag is properly passed to the callback for named refs, matching the behavior already implemented for `--all`.

The patch is small and focused, touching only `builtin/reflog.c` and adding tests in `t/t1410-reflog.sh`. The commit message clearly explains the problem, references the original report, and includes a helpful note about why the dry-run logic wasn't refactored further. The tests verify both the corrected output and that no reflog entries are modified during a dry run.
