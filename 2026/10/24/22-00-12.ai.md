This is the fourth and final patch in Aniket Gupta’s four-patch series converting line-ending configuration variables (`core.autocrlf`, `core.eol`, `core.safecrlf`) from global variables into `struct repo_config_values` as part of the Git libification effort. This patch moves the last remaining variable, `global_conv_flags_eol` (which holds `core.safecrlf`), into the per-repository structure and introduces the getter `repo_global_conv_flags_eol()` to access it.

The patch touches six files: `combine-diff.c`, `convert.h`, `diff.c`, `environment.c`, `environment.h`, and `object-file.c`. The changes are mechanical and follow the established pattern from the earlier patches in the series. The `get_conv_flags()` helper in `object-file.c` is updated to accept an `index_state` parameter so it can locate the repository and call the new getter. The default value (`CONV_EOL_RNDTRP_WARN`) is set in `repo_config_values_init()`, and the configuration parsing in `environment.c` now updates the per-repository structure directly.

This completes the migration of all three line-ending configuration variables into `repo_config_values`, eliminating the last global state in this area. The series is now fully posted and ready for final review. The main technical discussion point remains the design choice between passing `repo` to functions (the current approach) and storing resolved values in `struct conv_attrs` (the alternative), as the author explicitly invited feedback on this in the cover letter. The patch itself appears clean and well-scoped, with no new CLI options, config keys, or test files introduced.
