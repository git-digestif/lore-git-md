This thread is about a small but visible inconsistency in `git reflog expire --dry-run --verbose`: when you name specific refs on the command line, the output says "prune" instead of "would prune", while `--all` correctly uses "would prune". Laveesh Bansal sent a minimal one-line fix that propagates the `dry_run` flag into the callback struct for named refs, making the output consistent. Junio C Hamano reviewed it and suggested a broader refactoring to eliminate the duplicate loops for `--all` and named refs, but agreed to merge the minimal fix first and leave the refactoring for a follow-up patch.

The patch is now ready to go: Junio has accepted the sequencing plan, and there are no objections. The fix touches only `builtin/reflog.c` and adds tests in `t/t1419-reflog-expire.sh` to verify the wording and dry-run safety. The refactoring, if it happens later, will collect all refs into a single data structure and iterate once, but the tests introduced now will still apply. Nothing else in the codebase or on-disk format changes.
