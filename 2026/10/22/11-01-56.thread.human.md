This thread is a small but practical fix to Git’s test infrastructure. Kaartic Sivaraam sent a two-patch series to make the `clar`-based unit test runner compatible with common Meson workflows. The issue is that `meson test --test-args='-ilx'` forwards the `-l` flag to the test binary, which previously rejected it as unrecognized, causing the test run to fail. The fix adds `-l`/`--long-tests` as a NOOP argument, following an established pattern, so the flag is silently ignored without changing test behavior.

The series is under review in its first version. The first patch reorders existing NOOP arguments alphabetically as a preparatory cleanup, while the second patch adds the new NOOP flag to address the core issue. The changes are minimal—just four lines modified in `t/unit-tests/unit-test.c`—and CI confirms no regressions, though some macOS runners didn’t execute. There’s been no review feedback yet, but the series is narrowly scoped and unlikely to be controversial. It’s part of the ongoing test modernization effort to adopt the `clar` unit test framework.
