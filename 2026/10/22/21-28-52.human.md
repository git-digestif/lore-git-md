This is the fourth patch in a five-part documentation and terminology cleanup series that aligns Git’s code comments and help text with the 2024 redefinition of "pseudoref" and "root ref." The series updates the glossary, man pages, and tests to consistently use "root ref" for refs outside the `refs/` hierarchy (like HEAD and ORIG_HEAD) and reserves "pseudoref" for FETCH_HEAD and MERGE_HEAD only.

This patch focuses on the refs subsystem itself, replacing outdated uses of "pseudoref" in code comments and help text. It updates the `--include-root-refs` option in `git for-each-ref` to say "root refs" instead of "HEAD ref and pseudorefs," corrects comments in `refs.h` to clarify that both root refs and pseudorefs use all-caps naming, and tweaks the bash completion script to reflect that `__git_pseudoref_exists()` actually checks both root refs and pseudorefs. The function name itself is left unchanged to avoid breaking third-party scripts.

The changes are mechanical and uncontroversial, touching only comments and help strings. The patch reinforces the glossary’s definitions and should help developers avoid confusion when reading the code. No functional changes or new behaviors are introduced. If the earlier patches in the series were well-received, this one should be equally straightforward.
