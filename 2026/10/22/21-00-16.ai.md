This is a bugfix patch targeting the fetch subsystem, specifically addressing the shallow-fetch-with-tags regression introduced by batched reference updates. This is the fourth iteration (v4) of the patch, and it adopts Patrick Steinhardt’s proposed design: instead of splitting the reference transaction into two phases, it exposes the already-fetched refs to the negotiation phase by adding their tips to the transport’s `negotiation_include_tips` field.

The patch touches `builtin/fetch.c` and adds three new tests to `t/t5510-fetch.sh`. Two tests verify that the client correctly advertises the fetched refs as 'haves' during tag backfilling, covering both atomic and non-atomic flows. The third test ensures upstream tracking info is set and tags are backfilled even when a sibling ref is rejected.

Behaviorally, the patch restores correct 'have' reference reporting during negotiation for shallow fetches with tags, eliminating the performance regression where the server would send all objects. The new design preserves atomicity for `--atomic` fetches, addressing a limitation of the previous two-transaction approach. Performance impact is expected to be minimal, as the fix avoids intermediate commits while maintaining the benefits of batched updates.

The patch is well-motivated and addresses all prior review feedback, including edge cases around empty transactions, error handling, and `--atomic` fetches. The new design appears cleaner and more robust than the v3 approach, and the test coverage is thorough.
