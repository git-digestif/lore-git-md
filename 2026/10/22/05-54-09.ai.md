This is a documentation discussion in the ongoing `gitbreaking-changes(7)` manpage thread. Patrick Steinhardt responds to Junio C Hamano’s skepticism about the long-term value of maintaining a historical record of breaking changes. He argues that the document remains useful for users upgrading across multiple versions (e.g., from an LTS release to Git 3.x), even if they do not land directly on Git 3.0. His position is pragmatic: retain the document until all supported distributions have adopted Git 3.0, ensuring users have access to breaking-change information during the transition period. This does not resolve the fundamental question but provides a concrete, time-bound justification for the document’s continued existence. The series’ integration still hinges on Junio’s final decision, but Patrick’s input shifts the discussion toward a practical middle ground rather than outright rejection. No technical changes are proposed or required.
