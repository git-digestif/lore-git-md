This is a brief follow-up in the `git worktree list --merged` RFC thread.

Harald Nordgren replies to Junio C Hamano’s authoritative dismissal of the broader design question about allowing multiple worktrees to check out the same branch. Harald acknowledges the technical rationale Junio provided — that shared repository state would cause unexpected HEAD movement — and withdraws his earlier suggestion. He also accepts Junio’s pointer to `git worktree add -d` (the `--detach` option) as the appropriate workaround.

The exchange is now closed; no new technical points or design questions are raised. The thread’s focus returns to the original `--merged`/`--no-merged` feature proposal, which remains open for review and has not yet received maintainer feedback.
