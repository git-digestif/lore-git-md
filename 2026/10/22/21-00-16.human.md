This is a well-crafted bugfix patch targeting the fetch subsystem, specifically addressing the shallow-fetch regression introduced by batched reference updates. The fourth iteration (v4) of Karthik Nayak’s patch abandons the earlier two-transaction approach in favor of a cleaner design that exposes already-fetched reference tips to the negotiation phase by populating the transport’s `negotiation_include_tips` field. This solution directly addresses the root cause—batched updates delay reference commits, so the client has no ‘haves’ to report during tag backfilling—while preserving atomicity for `--atomic` fetches and avoiding the performance penalty of an intermediate commit.

The patch touches `builtin/fetch.c` and adds three new tests in `t/t5510-fetch.sh` that verify the fix works for both atomic and non-atomic flows and that upstream tracking info is still set when a sibling ref is rejected but a tag is backfilled. Benchmark results from earlier iterations show the fix restores performance to within 1% of the single-transaction baseline, a significant improvement over the 17× regression. The commit message clearly explains the problem, the new design, and the trade-offs, and includes a Reported-by credit to Mitja Bezenšek.

All prior review feedback has been addressed: edge cases (empty transactions, `--atomic`, cleanup paths) are now handled, error-path logic is clarified, and the test coverage is thorough. The new design emerged from the thread’s discussion and has conceptual buy-in from Patrick Steinhardt and Justin Tobler; the only remaining question is whether the implementation is robust, but the code looks clean and the approach is sound. This patch is ready for `next` and should be uncontroversial.
