This is the first patch in a two-part bugfix series addressing inconsistent branch switch behavior when tracking configuration fails. The patch refactors `setup_tracking()` in `branch.c` to return an error instead of calling `exit(1)`, and updates its callers (`create_branch()` and `dwim_and_setup_tracking()`) to propagate this error. This is a preparatory change that doesn’t alter behavior yet—callers still exit on failure—but sets the stage for the second patch, which will make `git switch -c` and `git checkout -b` ignore tracking failures and complete the branch switch.

The refactoring is clean and mechanical, touching only the plumbing layer (`branch.c` and `branch.h`) and the two built-in commands that use it (`builtin/branch.c` and `builtin/checkout.c`). The commit message is clear, and the patch itself is well-scoped, focusing solely on the error-handling refactor without introducing behavioral changes. No controversy is evident; this looks like a straightforward, well-motivated step toward fixing a long-standing edge case.
