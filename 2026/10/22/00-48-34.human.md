This is a small but well-crafted i18n bugfix patch, now in its second iteration. The patch updates two messages in `git checkout` that include numeric counts—" ... and %d more." (shown when leaving a detached HEAD with orphaned commits) and "only one reference expected, %d given." (shown when too many references are provided)—to use Git’s plural-aware `Q_()` macro instead of the plain `_()` wrapper. The change is purely about translation context: English output remains unchanged, but languages with complex plural rules (like Polish) can now provide correct translations. The commit message clearly explains the trade-off: languages without plural distinctions must now provide two identical translations, but this enables correctness for languages that do need distinct forms.

The patch touches only `builtin/checkout.c`, makes no functional changes to English behavior, and requires no new tests. Feedback from Junio C Hamano and Tuomas on the first version has been incorporated: the commit message now explicitly frames the trade-off, and the second message (previously missed) is included. The interdiff is clean and the rationale is concise. This looks like a straightforward, uncontroversial fix that addresses a real i18n correctness issue.
