This is a **CLI design discussion** for Harald Nordgren’s patch series extending `git branch --delete-merged` to detect squash-merged and rebase-merged branches. Junio C Hamano replies to Jasper Mayone’s proposal, endorsing a simplified command-line structure that avoids configuration complexity.

Junio agrees with Jasper’s suggestion to split the functionality into two distinct flags: `--delete-merged <pattern>` for strict tip-reachability (the current behavior) and `--delete-integrated <pattern>` for change-based detection (including rebased and squashed branches). This clean separation avoids the need for a config variable to control granularity (e.g., enabling only rebased branches), which Junio describes as "the ultimate sophistication" in simplicity. The proposal directly addresses the ongoing debate about naming and CLI structure, offering a concrete path forward that aligns with Git’s existing conventions and user expectations.

The discussion does not revisit the unresolved questions about whether `--delete-integrated` should enable both squash *and* rebase detection by default or require explicit opt-in for each, nor does it address Jasper’s author-check mitigation for the false-positive issue. However, Junio’s endorsement of the simplified structure suggests a preference for clarity and ease of use over fine-grained control, which may influence the final implementation. The next steps will likely involve updating the patch series to reflect this CLI design, followed by further review of the safety and performance implications.
