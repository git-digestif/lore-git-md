This is a bugfix series for `git imap-send`, now at version 3 with four patches. The core issue remains the same: `git imap-send` fails when processing patches where the `Subject` header appears before the `Date` header, a valid but non-canonical order produced by tools like `b4`. The series also addresses a tunnel-command lifecycle bug and ensures RFC 5322 compliance (case-insensitive header name matching).

Version 3 splits the changes into four focused commits, each with a clear purpose. The first patch (`imap-send: wait for the tunnel command to finish`) fixes a long-standing process lifecycle issue by ensuring the tunnel command is properly reaped when the connection closes. The second (`imap-send: accept messages with Subject before Date`) rewrites the header-parsing logic to accept headers in any order, resolving the interoperability problem with `b4`. The third (`imap-send: check git send-email copies like other messages`) removes a special-case exemption for messages starting with `From git-send-email`, treating them like any other message. The fourth (`imap-send: match header names case insensitively`) ensures header name matching complies with RFC 5322.

The series touches only `imap-send.c` and adds a new test in `t/t9001-send-email.sh` that verifies the fix by sending a patch with `Subject` before `Date` and confirming it is accepted. The test coverage is thorough, exercising both the new code path and existing workflows like `--imap-sent-folder`. The changes are minimal and well-motivated, addressing real interoperability pain points without introducing new complexity.

Harald Nordgren has incorporated feedback from Junio and Patrick Steinhardt, resolving the tunnel leak and splitting the controversial special-case removal into a separate patch for clarity. The unresolved questions from earlier reviews—whether the tunnel process lifecycle was intentional and whether removing the `git-send-email` special case is safe—are now addressed directly in the series. The test prerequisite handling issue is no longer a blocker.

This looks like a solid, uncontroversial bugfix series that should be ready for `next`. The problem is real, the solution is clean, and the test coverage ensures it won’t regress. The split into four patches makes the changes easier to review and understand.
