This is a bugfix patch targeting the object database (ODB) layer, specifically the handling of loose object index files when batch-fsync is enabled alongside a compatibility hash.

The patch addresses a failure in the temporary object directory migration logic. When Git is configured with a compatibility hash (e.g., SHA-1 alongside SHA-256), loose objects are written with a mapping to their compatibility hash in a `loose-object-idx` file. If batch-fsync is also enabled, these objects and their index are first written to a temporary directory and later migrated to the primary ODB. The bug occurs when an existing `loose-object-idx` file already exists in the primary ODB: the migration fails because the code expects identical files, but the new index only contains entries for the newly written objects, not the full set.

Justin Tobler’s fix teaches the migration logic to explicitly merge the temporary index into the primary one by appending new entries rather than replacing the file. The implementation is careful: it locks the target file, validates the source index format, and ensures the header is written if the file is new. A new test in `t1016-compatObjectFormat.sh` verifies that the migration works when multiple objects are added in a single transaction.
