This is a **brief follow-up in the `git branch --delete-merged` squash/rebase detection thread**, specifically Harald Nordgren’s reply to Junio C Hamano’s latest review and test case.

Harald concedes the core safety issue raised by Junio’s test case — the current implementation’s lenient tree-based diffing can incorrectly delete branches whose changes were independently implemented by another author, even without `--squashed`. He now accepts the need to **decouple the strict `--delete-merged` (tip-reachability only) from a new, looser detection mode**, but proposes a simpler CLI design: a single `--delete-irrelevant` flag rather than Junio’s suggested `--delete-irrelevant=squashed,rebased` granularity. This keeps the interface minimal while addressing the false-positive risk, though it leaves open whether the new flag should enable both squash *and* rebase detection by default or require explicit opt-in for each.

The reply does not engage with the algorithmic trade-offs (e.g., patch IDs vs. tree-based diffing, rename detection, or performance) or address Jasper Mayone’s granular `--landed=<kind>` proposal. It also does not respond to Phillip Wood’s call for clearer documentation of the algorithm’s limitations. The focus is purely on the CLI split, and the tone suggests a willingness to adapt the series to Junio’s safety concerns. The next steps will likely involve revising the patch series to implement `--delete-irrelevant` and updating the test suite to reflect the new behavior.
