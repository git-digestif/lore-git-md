This is a documentation discussion in the ongoing `gitbreaking-changes(7)` manpage thread. Patrick Steinhardt weighs in on Junio C Hamano’s fundamental question about whether maintaining a historical record of breaking changes is worthwhile. His position is pragmatic: while the Git 1.x-to-2.0 transition documentation may no longer be relevant, users upgrading across multiple versions (e.g., from one LTS release to another) will still benefit from knowing what changed in Git 3.0. He proposes keeping the document until all supported distributions have upgraded to Git 3.0, suggesting a time-bound retention rather than an indefinite historical record. This aligns with Kristoffer Haugsbakk’s earlier proposal to treat the document as a living draft, but adds a concrete criterion for eventual retirement. The series remains technically complete and ready for integration, but its fate now hinges on Junio’s final decision about the document’s long-term utility.
