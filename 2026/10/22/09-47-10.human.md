This is a refactoring patch series, part of the ongoing effort to eliminate global state in Git by moving configuration values into repository-specific structures. The series consists of two patches: the first zero-initializes the `repo_config_values` struct using `memset`, and the second moves the `pack.packsizelimit` configuration value from a global variable into this struct.

The motivation is clear and uncontroversial: reducing global state makes Git's codebase more modular and easier to reuse as a library. This aligns with broader refactoring efforts like the `the_repository` removal. The changes are mechanical and well-contained, touching `builtin/pack-objects.c`, `environment.c`, `environment.h`, and `object-file.c`. The `pack_size_limit` is used to enforce a maximum size for packfiles during creation, so this change ensures the limit is scoped to the repository rather than being process-global.

Joy Gundu, an Outreachy contributor, incorporated feedback from Patrick Steinhardt, who reviewed the initial version. Patrick suggested the preparatory `memset` cleanup to simplify initialization and reduce boilerplate, which Joy adopted as the first patch in this v2 series. The commit message was also reworked to better explain the problem before describing the solution. Testing shows the changes pass relevant configuration and pack-object tests, though there were minor permission errors during cleanup (unrelated to the patch itself).

The series looks well-crafted and addresses a real technical goal. The `memset` cleanup is a sensible addition that makes future changes to the struct less error-prone. No edge cases or objections have been raised, and the direction has strong support from Patrick, who confirmed this matches his own local work. This is a small but meaningful step in the global-state removal effort.
