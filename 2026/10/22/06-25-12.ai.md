This is a documentation patch discussion in the ongoing SSH signing verification security thread. Patrick Steinhardt weighs in on the documentation wording for the first reported flaw (timestamp confusion in SSH key lifetime checks).

Patrick agrees with Junio C Hamano that the current wording is overly verbose but suggests retaining a brief note that the timestamp is controlled by the signer. His proposed phrasing keeps the explanation minimal while making the security limitation explicit: "This does not provide any security guarantees as the timestamp can be chosen arbitrarily by the signer." This strikes a balance between Junio’s preference for brevity and Christian Noé Ramos López’s original intent to warn users about the risks of relying on key lifetimes. The revised wording preserves the core technical fact (Git checks the committer/tagger date, not the signature timestamp) while acknowledging the limitation upfront. No new technical issues are raised; this is purely about documentation clarity. The discussion remains focused on the man page update, with no impact on the separate revocation file security fix (which is already resolved in v2).
