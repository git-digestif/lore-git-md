This is the third patch in Harald Nordgren’s four-patch `v3` series fixing `git imap-send` interoperability with tools like `b4`. The patch removes a special-case exemption for messages starting with `From git-send-email` that was introduced in commit `04133f5bc4` (2025-08-12) to work around the earlier header-order dependency. Now that the parsing logic (Patch 2/4) accepts `Subject` before `Date`, this exemption is redundant: the copy piped from `git send-email --imap-sent-folder` carries the same headers as the SMTP message, so it passes the standard `has_required_headers()` check. The patch simplifies the counting logic in `imap-send.c` by treating all messages uniformly and adds a test that verifies the `--imap-sent-folder` workflow now works without the special case.

The change is minimal and focused: it deletes 13 lines of special-case logic and replaces them with a single condition that reuses the `has_required_headers()` helper introduced in Patch 2/4. The new test exercises the exact scenario the special case was meant to handle, confirming that the copy is still counted and stored in the IMAP folder. The backward-compatibility implications are clear: the special case was a workaround for a bug that no longer exists, so removing it restores consistent behavior. The patch is uncontroversial in isolation, but its place in the series (after the order-agnostic parsing and before case-insensitive matching) makes it a logical stepping stone. No open questions remain; the only discussion point in earlier rounds was whether the special case should be removed at all, and the author has isolated it here to make that decision explicit.
