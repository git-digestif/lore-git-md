This is the second patch in Joy Gundu’s two-patch v2 series that moves the `pack.packsizelimit` configuration value from a standalone global variable into the repository-scoped `repo_config_values` struct. The patch is a pure refactoring with no behavioral change, continuing the ongoing effort to eliminate global state in Git’s codebase.

The change itself is mechanical and well-contained: the global `pack_size_limit_cfg` is removed, and its value is now stored in the `pack_size_limit` field of `repo_config_values`. The patch updates the configuration parser (`git_default_config`) and the pack-writing code (`builtin/pack-objects.c` and `object-file.c`) to read the value from the struct instead of the global variable. The diff is small (7 insertions, 7 deletions) and touches only four files: `builtin/pack-objects.c`, `environment.c`, `environment.h`, and `object-file.c`.

The commit message clearly explains the motivation: removing global state makes Git’s internals more modular and easier to reuse as a library component. This aligns with Patrick Steinhardt’s broader work on global-state removal and was explicitly supported in his review of the v1 series. The preparatory patch (1/2) in this series, which uses `memset()` to standardize initialization of `repo_config_values`, was added in response to Patrick’s feedback and makes this patch slightly cleaner by reducing boilerplate.

No edge cases or objections have been raised, and Joy reports successful test runs of `t1300-config.sh` and `t5300-pack-object.sh`. The patch is uncontroversial and appears ready for integration. The only minor detail is the use of `the_repository` in `object-file.c`, which is consistent with the current state of the codebase but will eventually be addressed by the ongoing `the_repository` removal effort.

This is a solid, incremental step in the global-state-removal effort, authored by an Outreachy contributor with clear engagement and responsiveness to feedback. The patch is well-motivated, well-explained, and technically sound.
