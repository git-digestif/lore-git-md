This is a refactoring patch series (two patches) that continues the ongoing effort to eliminate global state in Git by moving the `pack.packsizelimit` configuration value into the repository-scoped `repo_config_values` struct. The series is authored by Joy Gundu as part of an Outreachy contribution.

The first patch is a preparatory cleanup: it modifies `repo_config_values_init()` to use `memset()` for zero-initialization, reducing boilerplate and making future additions to the struct less error-prone. The second patch moves the `pack.packsizelimit` value from a standalone global variable (`pack_size_limit_cfg`) into `repo_config_values`, updating all relevant code to read the value from the struct instead. This is a pure refactoring with no behavioral changes, aligning with the broader goal of making Git’s internals more modular and reusable as a library.

The series touches four files: `builtin/pack-objects.c`, `environment.c`, `environment.h`, and `object-file.c`. The changes are mechanical and well-contained, focusing on pack-object handling and object database configuration. Joy reports successful builds and test runs (`t1300-config.sh` and `t5300-pack-object.sh`), though there were minor permission errors during cleanup (unrelated to the patch itself). The commit messages are clear and improved from the v1, explaining the problem before describing the solution.

Patrick Steinhardt’s feedback from the v1 review was incorporated, including his suggestion to use `memset()` for initialization. This addition makes the series slightly more ambitious but also more robust, as it standardizes the initialization pattern for the `repo_config_values` struct. The series is uncontroversial and aligns with Patrick’s own work in this area, signaling strong support for the direction.

No edge cases or objections have been raised, and the patch looks ready for further review or integration. The only open question is whether the `memset()` cleanup will introduce any subtle issues, but the change is small and well-motivated. This is a solid, incremental step in the global-state-removal effort.
