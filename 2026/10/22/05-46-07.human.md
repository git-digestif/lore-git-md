This is a **security bugfix** for Git's SSH signing verification, addressing the second of two critical flaws reported earlier: when `gpg.ssh.revocationFile` is configured but missing, Git now fails verification instead of silently proceeding. The patch implements the consensus security posture (fail closed) while preserving an escape hatch via the `:(optional)` pathname prefix.

Christian Noé Ramos López's v2 patch directly responds to Junio C Hamano's review concern about error-handling flow. By moving the missing-file check into the same block that handles unknown keys, the patch ensures signature information is displayed in both cases, resolving the behavioral asymmetry Junio identified. The commit message clearly explains this change and its effect on the `%G?` status code (now "U" for both missing revocation files and unknown keys, instead of v1's "B" for the former).

The patch is well-tested, adding four new test cases in `t/t7528-signed-commit-ssh.sh` that cover revoked keys, missing files, and the `:(optional)` escape hatch. The documentation update in `gpg.adoc` is minimal but precise, stating the new behavior and the escape mechanism. With Junio's substantive concern now addressed, this patch appears ready for integration; the only remaining question is whether it will be held until the related timestamp-confusion documentation patch is finalized to avoid splitting the security fixes across releases.
