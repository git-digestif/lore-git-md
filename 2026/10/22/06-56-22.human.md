This is the first patch in a four-part bugfix series for `git imap-send`, targeting a long-standing tunnel-command lifecycle issue. The patch ensures the tunnel process (used when `imap.tunnel` is configured) is properly reaped when the IMAP connection closes, fixing a memory leak and preventing unreaped child processes. The fix is minimal and surgical: it adds a call to `finish_command()` in `imap_close_server()` and stores the tunnel’s `child_process` struct in the `imap` context to make it accessible at teardown. The change is well-motivated by the commit message, which traces the bug back to the original `isync` code and the 2009 refactoring that introduced the `run-command` API.

The patch touches only `imap-send.c` and is uncontroversial. It directly addresses Patrick Steinhardt’s earlier concern about the missing `finish_command()` call, and the fix is placed in the correct location (connection teardown). No test sets `imap.tunnel`, so the leak checker hasn’t caught this, but the logic is straightforward and the risk of regression is low. This is a clear, focused bugfix that should be ready for integration.
