This is the first patch in Mihai Cosma’s two-patch series fixing index locking behavior in `git status`. It addresses a silent data-loss bug in the `index.skipHash` code path (enabled in Scalar repositories and with `feature.manyFiles`), where `git status` could overwrite concurrent index updates without detection.

The bug arises because `index.skipHash` bypasses the usual checksum verification in `verify_index_match()`, allowing `git status` to clobber staged changes made by another process between when it reads the index and when it writes it back. The fix restores stat-data-based verification for indices with a null checksum, ensuring the index is only updated if its file metadata (inode, mtime, size, etc.) matches what was read. The patch also copies stat data in `unpack_trees()` to maintain consistency when building a new index.

The commit message includes a clear reproduction case demonstrating the bug, and the new test in `t/t7508-status.sh` covers both the bugfix and edge cases with `index.skipHash` and split index. The change is minimal and focused, touching only `read-cache.c`, `read-cache-ll.h`, and `unpack-trees.c`. This is a standalone correctness fix that could be merged independently to `maint`; it doesn’t depend on the second patch in the series.

The patch is well-motivated and unlikely to introduce regressions. The only potential concern is the reliance on stat data on Windows (where inode numbers are unavailable), but the commit message acknowledges this and explains why the trade-off is acceptable. This looks ready for `next`.
