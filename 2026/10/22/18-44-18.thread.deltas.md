# Thread deltas

## 2026/10/22

- [2026/10/22/18-44-18 by Mihai Cosma <mcosma@gmail.com>] Posted a two-patch series "status: stop holding index.lock while collecting": patch 1 fixes a bug under index.skipHash where the check that stops status from overwriting a concurrently updated index passes for any index, so status can silently revert a "git add" (also on 2.56.0), and patch 2 makes status take index.lock only to write and only when it has something to write; benchmarks on a gcc checkout (124,311 files) showed "git add" failures dropping from 104/200 to 0/200 in the clean case with status running in a loop.
- [2026/10/22/18-44-19 by Mihai Cosma <mcosma@gmail.com>] Patch 1/2 "read-cache: verify skipHash index by stat data" makes verify_index_from() compare the index file's stat data (mtime, inode, device, uid, gid, size; excluding ctime) recorded when the index was read or written against the current file when the checksum is null, so a "git add" landing between status reading the index and taking the lock is not silently reverted; includes a reproduction using an fsmonitor hook and tests in t/t7508-status.sh.
- [2026/10/22/18-44-20 by Mihai Cosma <mcosma@gmail.com>] Patch 2/2 "status: lock the index only to write it" adds repo_lock_and_update_index_if_able(), which takes the lock only if the index has something to write, and calls it after wt_status_collect() instead of holding the lock during collection, so status no longer creates index.lock when it writes nothing and holds it only for the write when it does.
