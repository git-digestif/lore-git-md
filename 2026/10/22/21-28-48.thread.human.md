This thread is a documentation cleanup series by Andy Koppe to align Git’s terminology around "pseudorefs" (now limited to FETCH_HEAD and MERGE_HEAD) and "root refs" (refs outside the `refs/` hierarchy, like HEAD and ORIG_HEAD). The series updates the glossary, man pages, code comments, tests, and pedagogical documentation to reflect the 2024 terminology change, incorporating feedback from Junio C Hamano, Patrick Steinhardt, and Julia Evans.

The v2 series, posted on June 17, 2025, addresses all prior review feedback except for two minor unresolved documentation nits in `git-update-ref(1)`. Junio praised the v1 series as "a pleasant read" but hasn’t reviewed v2 yet, while Patrick Steinhardt’s suggestions—such as tightening commit messages and improving glossary entries—are largely incorporated. Julia Evans’s proposal to expand the "References" section of `gitdatamodel.adoc` is now part of the series, filling a gap in the data-model guide. Her recent follow-up focuses on refining the pseudoref definition to clarify that they may contain multiple hashes (unlike root refs) and confirming that commands like `git log` use the first hash when pseudorefs contain multiple entries. Andy’s earlier clarification about on-disk storage (root refs can use reftables; pseudorefs are file-backed) resolves her questions, and these details will likely be added to the documentation.

The series remains uncontroversial and appears ready for merging once the two remaining nits in `git-update-ref(1)` are addressed or deferred. No behavioral changes are proposed—this is purely a terminology and documentation effort. Key files touched include the glossary, six man pages, test scripts, and `gitdatamodel.adoc`. The glossary now explicitly lists supported operations for pseudorefs (e.g., direct reading via `git log`) and unsupported ones (e.g., no `git-update-ref`), while the pedagogical documentation now covers both concepts to improve user understanding.
