This thread is a documentation cleanup series by Andy Koppe that aligns Git’s terminology around "pseudorefs" (now limited to FETCH_HEAD and MERGE_HEAD) and "root refs" (refs like HEAD and ORIG_HEAD outside the `refs/` hierarchy) with a 2024 project decision. The v2 series, posted on June 17, updates the glossary, man pages, code comments, tests, and pedagogical documentation to replace outdated uses of "pseudoref" and correct inaccuracies in reflog and per-worktree ref documentation. Julia Evans’s proposal to expand the data-model guide is now incorporated.

The series is uncontroversial and nearly ready for merging. Junio Hamano and Patrick Steinhardt have reviewed v1 positively, and v2 addresses all feedback except for four lingering issues: (1) ambiguous phrasing in `git-update-ref(1)` about `core.logAllRefUpdates`, (2) outdated reflog storage documentation for the reftable backend, (3) a commit message mismatch in Patch 2/5 where the message claims MERGE_HEAD is described as a pseudoref while the diff removes it, and (4) Patrick’s suggestion to refine the glossary’s "pseudoref" definition to emphasize semantic differences (multi-object storage, metadata) over storage location. Andy considers the first two issues out of scope for this series, deferring them to a future effort.

Julia Evans’s latest email proposes a concrete example for the glossary’s "pseudoref" entry, showing the actual format of `FETCH_HEAD` (e.g., `d4c5f27105ee2e44366d718dbc5db95bbe99c714 not-for-merge branch 'example' of https://example.com/x/y`). This change would make the glossary more accessible without altering the technical scope. The series remains under review, with no merge status reported.
