This thread is a v3 patch series from Andy Koppe that cleans up Git’s documentation to align with a 2024 terminology change distinguishing "pseudorefs" (now only FETCH_HEAD and MERGE_HEAD) from "root refs" (refs outside the `refs/` hierarchy, like HEAD and ORIG_HEAD). The series updates the glossary, man pages, code comments, and tests to replace outdated terminology and clarify the behavior of these special ref types.

The latest version, posted on June 20, 2025, addresses all prior feedback from Junio C Hamano, Patrick Steinhardt, and Julia Evans. The glossary now provides precise definitions: "root refs" are irregular refs like HEAD, while "pseudorefs" are a separate category with additional semantics (e.g., storing multiple object IDs and metadata). The updated entries explicitly list supported operations (e.g., `git log` can read pseudorefs but uses only the first object ID) and limitations (e.g., `git-update-ref` cannot write pseudorefs). Julia Evans’s proposal to expand the "References" section of `gitdatamodel.adoc` is fully incorporated, improving pedagogical clarity.

Only two minor editorial suggestions remain open—Patrick Steinhardt’s requests to tweak wording in `gitdatamodel.adoc`—but these are surface-level and don’t block merging. The series is uncontroversial and appears ready for Junio to pick up. No behavioral changes are introduced; the focus is purely on documentation accuracy and consistency.
