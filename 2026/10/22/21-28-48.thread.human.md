This thread is a documentation cleanup series by Andy Koppe to align Git’s terminology with a 2024 change that narrowed "pseudoref" to `FETCH_HEAD` and `MERGE_HEAD` while introducing "root ref" for refs like `HEAD` and `ORIG_HEAD`. The v2 series (5 patches) updates the glossary, man pages, code comments, tests, and pedagogical documentation, incorporating feedback from Junio C Hamano and Patrick Steinhardt and adding Julia Evans’s proposal to expand `gitdatamodel.adoc`.

The series is nearly ready for merging, with all review feedback addressed except for five lingering issues. The most significant is Junio’s endorsement of Patrick Steinhardt’s refined glossary definition for "pseudoref," which shifts the focus to semantic differences (multi-object storage, metadata) rather than storage location. This change is editorial and uncontroversial but would improve precision. The other open items include a commit message mismatch in Patch 2/5 (claiming `MERGE_HEAD` is described as a pseudoref while the diff removes it), two minor documentation nits in `git-update-ref(1)` (ambiguous phrasing and outdated reflog storage explanation), and Julia Evans’s proposal to add a concrete `FETCH_HEAD` example to the glossary. Andy considers the `git-update-ref(1)` issues out of scope for this series, deferring them to a future effort.

Junio and Patrick have both reviewed the series positively, with Junio calling v1 "a pleasant read." Julia Evans’s contributions have sharpened the documentation’s clarity, particularly around pseudoref behavior. The only remaining action is for Andy to address the glossary refinement and commit message mismatch before the series can be merged.
