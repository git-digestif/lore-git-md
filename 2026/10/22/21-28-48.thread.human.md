This thread is a five-patch documentation cleanup (v4) by Andy Koppe to align Git’s terminology with the 2024 redefinition that narrowed "pseudoref" to just `FETCH_HEAD` and `MERGE_HEAD`, while introducing "root ref" for refs outside the `refs/` hierarchy like `HEAD` and `ORIG_HEAD`. The series updates the glossary, man pages, code comments, and tests to consistently use the new terms and correct related inaccuracies, incorporating feedback from Junio C Hamano, Patrick Steinhardt, and Julia Evans.

All substantive review feedback has now been addressed, including the latest changes in the fourth patch (v4 4/5), which updates in-code comments and error messages in `builtin/for-each-ref.c`, `contrib/completion/git-completion.bash`, `refs.h`, and `revision.c`. The most notable fix is the `--merge` error message in `revision.c`, which previously misleadingly listed `MERGE_HEAD`, `CHERRY_PICK_HEAD`, `REVERT_HEAD`, and `REBASE_HEAD` as pseudorefs—only `MERGE_HEAD` is one—and implied users should supply one of these refs as an argument. The new phrasing clarifies that an *ongoing* merge, cherry-pick, revert, or rebase is required, avoiding confusion. The `refs.h` header is also updated to better distinguish pseudorefs (which store multiple object IDs and metadata) from root refs, and the help text for `git for-each-ref --include-root-refs` now correctly refers to "root refs" instead of "HEAD ref and pseudorefs". The bash completion function `__git_pseudoref_exists()` is left unchanged to avoid breaking third-party scripts, though its comment is updated.

The series is uncontroversial and ready for merging. The only loose ends are minor deferred items: the phrasing of `core.logAllRefUpdates`’s logic in `git-update-ref(1)` and the reflog storage explanation for the reftable backend, both left for a future effort. Junio also noted that Git currently allows arbitrary files outside `refs/` (e.g., `.git/out/mister`) to be treated as refs by the revision parser, but this is not addressed in the series. No merge status has been reported yet.
