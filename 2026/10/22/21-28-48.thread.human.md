This thread is a documentation cleanup series that aligns Git’s terminology with a 2024 change narrowing "pseudoref" to just `FETCH_HEAD` and `MERGE_HEAD`, while introducing "root ref" for refs like `HEAD` and `ORIG_HEAD` that live outside the `refs/` hierarchy. Andy Koppe’s v3 series (five patches) updates the glossary, man pages, code comments, and tests to replace outdated uses of "pseudoref" with "root ref" and correct related inaccuracies. All substantive review feedback from Junio C Hamano, Patrick Steinhardt, and Julia Evans has been incorporated, and the series is uncontroversial and ready for merging.

The glossary now clearly defines "root ref" (e.g., `HEAD`, `ORIG_HEAD`) and "pseudoref" (only `FETCH_HEAD` and `MERGE_HEAD`), with detailed descriptions of their storage, supported operations, and limitations. For example, the "pseudoref" entry explains that these files can contain multiple object IDs (e.g., `FETCH_HEAD`’s multi-line format) and that commands like `git log` use the first hash when multiple entries are present. The series also updates test scripts to use the new terminology and renames test refs (e.g., `PSEUDOREF` → `ROOT_REF_HEAD`) to match root ref naming conventions. No behavioral changes are introduced—this is purely a terminology and test-label cleanup.

Two minor editorial suggestions from Patrick Steinhardt remain unresolved: dropping the word "also" in `gitdatamodel.adoc` and adding glossary cross-references. Andy has not yet responded to these, but they are surface-level and do not block merging. Junio’s and Patrick’s reviews have been positive, and the series appears to be in its final form, awaiting maintainer pickup. The thread is low-drama and focused on documentation clarity, with no open technical objections.
