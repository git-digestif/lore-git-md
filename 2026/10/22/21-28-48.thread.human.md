This thread is about a documentation and terminology cleanup series that aligns Git’s glossary, man pages, code comments, and tests with a 2024 terminology change. The change narrowed the definition of "pseudoref" to `FETCH_HEAD` and `MERGE_HEAD` only, while introducing "root ref" for refs outside the `refs/` hierarchy (e.g., `HEAD`, `ORIG_HEAD`). The series, authored by Andy Koppe, updates 38 files to replace outdated terminology and correct inaccuracies, including the glossary, man pages, built-in commands, refs internals, and test scripts.

The series has been uncontroversial and is now complete. Junio C Hamano, the maintainer, reviewed and merged it to `next` on June 25, 2025, and has now formally merged it to `master`. All review feedback from Junio, Patrick Steinhardt, and Julia Evans was incorporated in the final version (v4). Key updates include clarifying the behavioral distinction between pseudorefs (which can record multiple object IDs and carry metadata) and root refs, explicitly listing the exhaustive set of root refs, and improving documentation for commands like `git-ls-remote` and `git for-each-ref`. The series introduces no behavioral changes—it is purely a terminology and documentation cleanup. The glossary now provides clearer guidance for users and contributors, and the updated test scripts reflect the new terminology.
