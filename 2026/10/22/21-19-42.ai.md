This is a rejection of a feature request for a new `git remote set-password` command.

Brian M. Carlson, a long-standing and technically authoritative contributor, responds to Ján Waclawek’s proposal with a clear and firm rejection. He explains that the Git project has no interest in making URL-embedded passwords easier to use, citing repeated discussions about disallowing them entirely. The only reason they remain permitted at all is for low-value test environments.

Carlson highlights the security risks of storing credentials in URLs, particularly the exposure risk when configuration files (which contain the URLs) are accidentally published. He strongly advocates for credential helpers, which are already simple to use and avoid the pitfalls of URL-based credentials. The Git FAQ even provides an example of reading credentials from an environment variable, and `git-credential-store` is available for plaintext storage outside the repository. Carlson also suggests SSH with public keys as a superior alternative for automated systems.

The tone is decisive: the project is not interested in supporting or encouraging the use of credentials in URLs, and the proposed command will not be accepted. No further discussion or patch is expected on this topic unless someone presents a fundamentally different argument.
