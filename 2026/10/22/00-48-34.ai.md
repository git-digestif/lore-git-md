This is a small i18n bugfix patch, the second iteration of an Outreachy contribution. It converts two messages in `builtin/checkout.c` from the singular `_()` gettext wrapper to the plural-aware `Q_()` macro: the " ... and %d more." message shown when leaving orphaned commits behind, and the "only one reference expected, %d given." error when too many arguments precede `--`. The English strings are unchanged, but translators now receive the correct plural context, enabling proper translation into languages with complex plural rules (e.g., Polish). The commit message explicitly acknowledges the trade-off: languages without plural distinctions must now provide two identical translations to enable correctness for languages that do.

The patch is straightforward and uncontroversial. It touches only one file, adds no new tests (existing tests suffice), and incorporates all feedback from the first iteration: Junio’s suggestion to clarify the trade-off in the commit message, and Tuomas’s observation that a second message also needed conversion. The interdiff shows the two mechanical changes (`_()` → `Q_()`) and the updated commit message. This looks like a well-scoped, complete fix ready for merging.
