This is the second patch in a two-patch bugfix series targeting the checkout and branch subsystems. The series resolves an inconsistency where `git switch -c` and `git checkout -b` leave the repository in an inconsistent state when they fail to write the tracking configuration (e.g., due to a stale `.git/config.lock`). Patch 2/2 implements the core behavior change: when the tracking config cannot be written, the branch switch now completes, and Git exits with status 0, matching the behavior of `git push -u`, `git clone`, and `git fetch`. The error and hint are still printed to inform the user.

The patch modifies `builtin/checkout.c` to ignore the error returned by `create_branch()` (refactored in patch 1/2 to propagate errors instead of exiting) and updates three test scripts (`t2027-checkout-track.sh`, `t2060-switch.sh`, and `t3200-branch.sh`) to verify the new behavior. The tests simulate a locked config file and confirm that the switch completes, HEAD is updated, the worktree and index are consistent, and the tracking config is not written. The `git branch` command retains its stricter error handling, as verified by an additional test in `t3200-branch.sh`.
