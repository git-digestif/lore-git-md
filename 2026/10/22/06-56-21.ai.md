This is a **bugfix series** for `git imap-send`, now expanded to four patches in `v3`. The core issue remains the same: `git imap-send` fails when processing patches where the `Subject` header precedes the `Date` header, a valid but non-canonical order produced by tools like `b4`. The series now also addresses a tunnel-command lifecycle bug, removes a special-case logic for `git send-email` copies, and ensures RFC 5322 compliance with case-insensitive header name matching.

The key changes in `v3` are structural: the original two-patch series is split into four focused commits, each with a clearer scope. Patch 1/4 (`imap-send: wait for the tunnel command to finish`) fixes the tunnel process lifecycle by ensuring the tunnel command is properly reaped via `finish_command()` when closing the connection, resolving Patrick Steinhardt’s concern about unreaped processes. Patch 2/4 (`imap-send: accept messages with Subject before Date`) rewrites the header-parsing logic to accept headers in any order, while Patches 3/4 (`imap-send: check git send-email copies like other messages`) and 4/4 (`imap-send: match header names case insensitively`) split the remaining concerns: removing the `git-send-email` special case and enforcing case-insensitive header matching, respectively. The commit messages now explicitly explain the rationale for each change, and the tunnel leak is fixed in the correct place (during connection teardown).

The series touches `imap-send.c` and adds a new test in `t/t9001-send-email.sh` that verifies the fix by sending a patch with `Subject` before `Date` and confirming acceptance. The test coverage is thorough, exercising both the new code path and existing workflows like `--imap-sent-folder`. The memory leak in tunnel handling is now properly addressed, and the tunnel process lifecycle is explicitly managed. The removal of the `git-send-email` special case (previously a point of contention) is now isolated in its own patch, making it easier to review its backward-compatibility implications.

This version resolves all previously open technical questions: the tunnel process lifecycle, the removal of the `git-send-email` special case, and the test suite’s prerequisite handling (now marked as `#leftoverbits`).
