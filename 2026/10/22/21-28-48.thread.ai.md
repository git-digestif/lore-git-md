Subject: [PATCH 0/5] glossary & docs: align "pseudoref" vs "root ref" terminology

Originating author: Andy Koppe
Thread type: patch series (documentation/terminology cleanup)

Core problem or goal
Align Git’s documentation, code comments, and tests with the 2024 terminology change (commit 993d57eded) that narrowed "pseudoref" to FETCH_HEAD and MERGE_HEAD only, while introducing "root ref" for refs outside the "refs/" hierarchy (e.g., HEAD, ORIG_HEAD). The series updates the glossary, man pages, built-in commands, refs internals, test scripts, and pedagogical documentation to replace outdated uses of "pseudoref" with "root ref" and correct related inaccuracies. Julia Evans’s proposal to expand the "References" section of `gitdatamodel.adoc` is fully incorporated, explicitly covering pseudorefs and root refs. The glossary’s "pseudoref" entry now leads with the key behavioral distinction—pseudorefs can record multiple object IDs and carry metadata, unlike root refs—and explicitly states that pseudorefs are not handled by the ref backend. The entry clarifies that commands like `git log` use the first object ID when multiple entries are present, lists the two pseudorefs (FETCH_HEAD, MERGE_HEAD), their storage location (`.git` directory), supported operations (`git show`, `git log`), and limitations (`git-update-ref`, `git-for-each-ref`). It specifies that FETCH_HEAD records fetched objects with their source ref and merge status, while MERGE_HEAD records commits during a merge (including via `git pull`). The glossary’s "ref" entry now explicitly mentions remote-tracking branches alongside local branches and tags.
