Subject: [PATCH 0/5] glossary & docs: align "pseudoref" vs "root ref" terminology
Series version: v1 (initial submission, 5 patches)
Originating author: Andy Koppe
Thread type: patch series (documentation/terminology cleanup)

Core problem or goal
Align Git’s documentation, code comments, and tests with the 2024 terminology change (commit 993d57eded) that narrowed "pseudoref" to FETCH_HEAD and MERGE_HEAD only, while introducing "root ref" for refs outside the "refs/" hierarchy (e.g., HEAD, ORIG_HEAD). The series updates the glossary, man pages, built-in commands, refs internals, and test scripts to replace outdated uses of "pseudoref" with "root ref" and corrects related inaccuracies in reflog and per-worktree ref documentation.

Current status
Under review; v1 posted 2025-06-10. Maintainer Junio C Hamano has signaled general approval ("a pleasant read") but has not yet acked or merged the series. No merge status reported.

Key technical details
- Files touched: 36 total—glossary (Documentation/glossary-content.txt), man pages (git-update-ref.1, git-worktree.1, git-ls-remote.1, for-each-ref-options.7, rev-list-options.7, config/core.adoc), built-in commands (builtin/for-each-ref.c), refs internals (refs.h, revision.c), test scripts (t/t1400-update-ref.sh, t/t1415-worktree-refs.sh, t/t1460-refs-migrate.sh, t/t4013-diff-various.sh, t/t9902-completion.sh, etc.), and completion script (contrib/completion/git-completion.bash).
- New glossary entries: "root ref" (formal definition), updated "pseudoref" (now limited to FETCH_HEAD/MERGE_HEAD), corrected "per-worktree ref" entry. The glossary now explicitly states that pseudorefs are *not* refs, cannot be written by `git-update-ref` or listed by `git-for-each-ref`, and yield the first object ID when they contain multiple entries. It cross-references `gitrevisions(7)` for descriptions of commonly used root refs and pseudorefs.
- Symbols: `__git_pseudoref_exists()` in contrib/completion/git-completion.bash left unchanged (comment updated only); `REFS_FOR_EACH_INCLUDE_ROOT_REFS` in refs.h now lists root refs explicitly in its comment. Test-specific root refs renamed (PSEUDOREF -> ROOT_REF_HEAD, REVERSE -> REVERSE_HEAD) to follow naming rules.
- On-disk format: no changes.
- Test coverage: updated test scripts to use new terminology; no new test cases added. Expected output in `t4013-diff-various.sh` updated to reflect renamed test refs.
- Per-worktree ref clarification: Patch 2/5 updates the "per-worktree ref" entry to list all root refs (HEAD, ORIG_HEAD, etc.) plus refs under refs/worktree/ and refs/rewritten/ as per-worktree, and clarifies that pseudorefs are also worktree-specific. The "worktree" entry now describes HEAD as a per-worktree ref and MERGE_HEAD as a pseudoref, with a cross-reference to git-worktree(1).
- Documentation updates in Patch 3/5: Six man pages (`git-update-ref(1)`, `git-worktree(1)`, `git-ls-remote(1)`, `for-each-ref-options(7)`, `rev-list-options(7)`, `config/core.adoc`) now consistently use "root ref" for HEAD/ORIG_HEAD, clarify that `--refs` in `git-ls-remote` omits refs outside `refs/`, and correct minor inaccuracies (e.g., removing ORIG_HEAD from `git-update-ref(1)`’s reflog documentation, correcting `core.logAllRefUpdates` scope to include root refs). `git-worktree(1)` now states that both root refs and pseudorefs are per-worktree without tying them to a specific on-disk location (reftable compatibility).
- Patch 4/5 updates in-code comments and help text in `builtin/for-each-ref.c`, `contrib/completion/git-completion.bash`, `refs.h`, and `revision.c` to replace outdated uses of "pseudoref" with "root ref" where appropriate. The help text for `git for-each-ref --include-root-refs` now says "root refs" instead of "HEAD ref and pseudorefs"; the bash-completion script’s comments clarify that `__git_pseudoref_exists()` covers both root refs and pseudorefs (though the function name itself is left unchanged); and `refs.h` updates its description of pseudorefs to match the glossary’s definition. The only behavioral change is in `revision.c`, where the error message for `--merge` no longer calls MERGE_HEAD et al. "pseudorefs," though the list of valid refs remains the same.

Open questions and loose ends
- Junio C Hamano raised a conceptual objection to the glossary’s "pseudoref" definition in Patch 1/5, arguing that the omission of "different semantics" obscures why pseudorefs like FETCH_HEAD and MERGE_HEAD cannot be written with `git update-ref`—not merely due to storage differences, but because they can record multiple object names. This phrasing may need to be restored, potentially affecting later patches that reference the glossary.
- Deliberate omission: the completion helper `__git_pseudoref_exists()` remains named as-is due to ambiguity about what term would cover both pseudorefs and root refs.
- Potential discussion point: whether the glossary’s new structure is sufficiently clear for users unfamiliar with the 2024 terminology change.
