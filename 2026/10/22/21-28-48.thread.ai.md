Subject: [PATCH 0/5] glossary & docs: align "pseudoref" vs "root ref" terminology
Series version: v3 (5 patches, addressing all prior review feedback)
Originating author: Andy Koppe
Thread type: patch series (documentation/terminology cleanup)

Core problem or goal
Align Git’s documentation, code comments, and tests with the 2024 terminology change (commit 993d57eded) that narrowed "pseudoref" to FETCH_HEAD and MERGE_HEAD only, while introducing "root ref" for refs outside the "refs/" hierarchy (e.g., HEAD, ORIG_HEAD). The series updates the glossary, man pages, built-in commands, refs internals, test scripts, and pedagogical documentation to replace outdated uses of "pseudoref" with "root ref" and correct related inaccuracies. Julia Evans’s proposal to expand the "References" section of `gitdatamodel.adoc` is fully incorporated, explicitly covering pseudorefs and root refs. The glossary’s "pseudoref" entry now includes a detailed description of FETCH_HEAD’s multi-object format (e.g., `d4c5f27105ee2e44366d718dbc5db95bbe99c714 not-for-merge branch 'example' of https://example.com/x/y`), explicitly listing the two pseudorefs (FETCH_HEAD, MERGE_HEAD), their storage location (`.git` directory), supported operations (`git show`, `git log`), and limitations (`git-update-ref`, `git-for-each-ref`). The entry also clarifies that MERGE_HEAD is written by `git-pull` (not just `git-merge`) and that pseudorefs *may contain multiple hashes*, with commands like `git log` using the first hash when multiple entries are present. The example-driven phrasing tightens the contrast between pseudorefs and references by stating that references can only contain an object ID or symbolic ref name.

Key technical details
- Files touched: 22 total in v3—glossary (Documentation/glossary-content.txt), man pages (git-update-ref.1, git-worktree.1, git-ls-remote.1, for-each-ref-options.7, rev-list-options.7, config/core.adoc), built-in commands (builtin/for-each-ref.c), refs internals (refs.h, revision.c), test scripts (t/t1400-update-ref.sh, t/t1415-worktree-refs.sh, t/t1460-refs-migrate.sh, t/t4013-diff-various.sh, t/t9902-completion.sh), completion script (contrib/completion/git-completion.bash), and pedagogical documentation (Documentation/gitdatamodel.adoc).
- New glossary entries: "root ref" (formal definition: refs located in the root of the ref hierarchy, e.g., HEAD, ORIG_HEAD; explicitly lists naming rules—upper-case/underscore names ending in `_HEAD` or `HEAD`—and the exhaustive set of irregular root refs, including `AUTO_MERGE`, `NOTES_MERGE_PARTIAL`, with a note that this list must not be extended), updated "pseudoref" (now limited to FETCH_HEAD/MERGE_HEAD, explicitly listing supported operations—direct reading via `git log`/`git diff`—and unsupported ones—no `git-update-ref` or `git-for-each-ref`). The "ref" entry no longer includes naming rules or irregular root refs, which are now covered under "root ref". The glossary explicitly states that pseudorefs are *not* refs, cannot be written by `git-update-ref` or listed by `git-for-each-ref`, and yield the first object ID when they contain multiple entries. The "pseudoref" entry now includes a concrete example of FETCH_HEAD’s file format, explicitly lists the two pseudorefs, their storage location (`.git` directory), supported operations (`git show`, `git log`), and limitations, and clarifies that MERGE_HEAD is written by `git-pull` (not just `git-merge`). It also documents that pseudorefs *may contain multiple hashes* (with FETCH_HEAD as the example) and that commands like `git log` use the first hash when multiple entries are present. The entry contrasts pseudorefs with root refs, emphasizing semantic differences (multi-object storage, metadata) and compatibility with normal refs for the first object they contain. Junio C Hamano’s suggested wording tweaks ("different" → "additional", "carry additional" → "carry extra") are incorporated to avoid repetition and reinforce this compatibility.
- Symbols: `__git_pseudoref_exists()` in contrib/completion/git-completion.bash left unchanged (comment updated only); `REFS_FOR_EACH_INCLUDE_ROOT_REFS` in refs.h now lists root refs explicitly in its comment. The help text for `git for-each-ref --include-root-refs` now says "root refs" instead of "HEAD ref and pseudorefs".
- Test coverage: updated test scripts to use new terminology; expected output in `t4013-diff-various.sh` updated to reflect renamed test refs (PSEUDOREF -> ROOT_REF_HEAD, REVERSE -> REVERSE_HEAD). No new test cases added.
- Per-worktree ref clarification: Patch 2/5 updates the "per-worktree ref" entry to use itemized AsciiDoc lists for root refs (HEAD, ORIG_HEAD, etc.), refs under refs/worktree/, and refs under refs/rewritten/, and clarifies that pseudorefs are also worktree-specific. The "worktree" entry now describes HEAD as a per-worktree ref and no longer mentions MERGE_HEAD, aligning with the series’ goal of consistent terminology. The prose list of per-worktree refs is now formatted as an itemized AsciiDoc list for better readability and future extensibility.
- Documentation updates in Patch 3/5: Six man pages (`git-update-ref(1)`, `git-worktree(1)`, `git-ls-remote(1)`, `for-each-ref-options(7)`, `rev-list-options.7`, `config/core.adoc`) now consistently use "root ref" for HEAD/ORIG_HEAD, clarify that `--refs` in `git-ls-remote` omits refs outside `refs/`, and correct minor inaccuracies (e.g., removing ORIG_HEAD from `git-update-ref(1)`’s reflog documentation, correcting `core.logAllRefUpdates` scope to include root refs). `git-worktree(1)` now explicitly states that both root refs and pseudorefs are per-worktree and drops the outdated claim that they live directly under `$GIT_DIR` (which doesn’t hold for reftable). `git-ls-remote(1)` fixes a typo ("symbolics" → "symbolic refs"). Julia Evans’s proposal to expand the "References" section of `gitdatamodel.adoc` is fully incorporated, explicitly covering pseudorefs and root refs. The updated `gitdatamodel.adoc` now includes FETCH_HEAD as an example of a pseudoref containing multiple hashes and clarifies that commands like `git log` use the first hash when multiple entries are present. The entry also links to the glossary for definitions of root refs and pseudorefs, improving navigability.
- Patch 4/5 updates in-code comments and help text in `builtin/for-each-ref.c`, `contrib/completion/git-completion.bash`, `refs.h`, and `revision.c` to replace outdated uses of "pseudoref" with "root ref" where appropriate. The bash-completion script’s comments clarify that `__git_pseudoref_exists()` covers both root refs and pseudorefs (though the function name itself is left unchanged). The commit message for Patch 4/5 is tightened per prior feedback, removing redundant explanations of the diff’s contents.
