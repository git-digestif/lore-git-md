Subject: [PATCH 0/5] glossary & docs: align "pseudoref" vs "root ref" terminology
Series version: v2 (5 patches, addressing review feedback and incorporating Julia Evans’s `gitdatamodel.adoc` proposal)
Originating author: Andy Koppe
Thread type: patch series (documentation/terminology cleanup)

Core problem or goal
Align Git’s documentation, code comments, and tests with the 2024 terminology change (commit 993d57eded) that narrowed "pseudoref" to FETCH_HEAD and MERGE_HEAD only, while introducing "root ref" for refs outside the "refs/" hierarchy (e.g., HEAD, ORIG_HEAD). The series updates the glossary, man pages, built-in commands, refs internals, test scripts, and pedagogical documentation to replace outdated uses of "pseudoref" with "root ref" and correct related inaccuracies in reflog and per-worktree ref documentation. Julia Evans’s proposal to expand the "References" section of `gitdatamodel.adoc` is now incorporated, explicitly covering pseudorefs and root refs to address a gap where the data-model guide previously only mentioned ORIG_HEAD in passing.

Current status
Under review; v2 posted 2025-06-17. Patches 1/5 (glossary updates), 2/5 (per-worktree ref and worktree glossary entries), and 4/5 (in-code comments and help text) are now uncontroversial and appear ready for merging after addressing all feedback from Junio C Hamano and Patrick Steinhardt on v1. Patch 3/5 (man page updates) has addressed most of Patrick Steinhardt’s feedback from v1, correcting the ORIG_HEAD reflog documentation and clarifying the per-worktree nature of root refs and pseudorefs in `git-worktree(1)`. Maintainer Junio C Hamano has signaled general approval of v1 ("a pleasant read") but has not yet reviewed v2 or explicitly acked or merged the series. No merge status reported.

Key technical details
- Files touched: 22 total in v2—glossary (Documentation/glossary-content.txt), man pages (git-update-ref.1, git-worktree.1, git-ls-remote.1, for-each-ref-options.7, rev-list-options.7, config/core.adoc), built-in commands (builtin/for-each-ref.c), refs internals (refs.h, revision.c), test scripts (t/t1400-update-ref.sh, t/t1415-worktree-refs.sh, t/t1460-refs-migrate.sh, t/t4013-diff-various.sh, t/t9902-completion.sh), completion script (contrib/completion/git-completion.bash), and pedagogical documentation (Documentation/gitdatamodel.adoc).
- New glossary entries: "root ref" (formal definition: refs located in the root of the ref hierarchy, e.g., HEAD, ORIG_HEAD), updated "pseudoref" (now limited to FETCH_HEAD/MERGE_HEAD, explicitly listing supported operations—direct reading via `git log`/`git diff`—and unsupported ones—no `git-update-ref` or `git-for-each-ref`). The "ref" entry no longer includes naming rules or irregular root refs, which are now covered under "root ref". The glossary explicitly states that pseudorefs are *not* refs, cannot be written by `git-update-ref` or listed by `git-for-each-ref`, and yield the first object ID when they contain multiple entries. It cross-references `gitrevisions(7)` for descriptions of commonly used root refs and pseudorefs.
- Symbols: `__git_pseudoref_exists()` in contrib/completion/git-completion.bash left unchanged (comment updated only); `REFS_FOR_EACH_INCLUDE_ROOT_REFS` in refs.h now lists root refs explicitly in its comment. Test-specific root refs renamed (PSEUDOREF -> ROOT_REF_HEAD, REVERSE -> REVERSE_HEAD) to follow naming rules.
- On-disk format: no changes.
- Test coverage: updated test scripts to use new terminology; no new test cases added. Expected output in `t4013-diff-various.sh` updated to reflect renamed test refs.
- Per-worktree ref clarification: Patch 2/5 updates the "per-worktree ref" entry to use itemized AsciiDoc lists for root refs (HEAD, ORIG_HEAD, etc.), refs under refs/worktree/, and refs under refs/rewritten/, and clarifies that pseudorefs are also worktree-specific. The "worktree" entry now describes HEAD as a per-worktree ref and MERGE_HEAD as a pseudoref, with a cross-reference to git-worktree(1). The prose list of per-worktree refs is now formatted as an itemized AsciiDoc list for better readability and future extensibility, and the "worktree" entry no longer lists explicit examples (HEAD, MERGE_HEAD), instead cross-referencing the "per-worktree ref" section.
- Documentation updates in Patch 3/5: Six man pages (`git-update-ref(1)`, `git-worktree(1)`, `git-ls-remote(1)`, `for-each-ref-options(7)`, `rev-list-options(7)`, `config/core.adoc`) now consistently use "root ref" for HEAD/ORIG_HEAD, clarify that `--refs` in `git-ls-remote` omits refs outside `refs/`, and correct minor inaccuracies (e.g., removing ORIG_HEAD from `git-update-ref(1)`’s reflog documentation, correcting `core.logAllRefUpdates` scope to include root refs). The reflog documentation in `git-update-ref(1)` now correctly states that only HEAD (not ORIG_HEAD) gets a reflog by default. The phrasing of `core.logAllRefUpdates`’s logic remains unchanged in v2; Patrick Steinhardt’s suggestion to clarify its ambiguity is not yet addressed. The outdated reflog storage explanation in `git-update-ref(1)` (referencing `$GIT_DIR/logs/<ref>`) is also unchanged; Patrick’s suggestion to replace it with a cross-reference to `git-config(1)` is not yet addressed. `git-worktree(1)` now explicitly states that both root refs and pseudorefs are per-worktree and drops the outdated claim that they live directly under `$GIT_DIR` (which doesn’t hold for reftable). `git-ls-remote(1)` fixes a typo ("symbolics" → "symbolic refs").
- Patch 4/5 updates in-code comments and help text in `builtin/for-each-ref.c`, `contrib/completion/git-completion.bash`, `refs.h`, and `revision.c` to replace outdated uses of "pseudoref" with "root ref" where appropriate. The help text for `git for-each-ref --include-root-refs` now says "root refs" instead of "HEAD ref and pseudorefs"; the bash-completion script’s comments clarify that `__git_pseudoref_exists()` covers both root refs and pseudorefs (though the function name itself is left unchanged); and `refs.h` updates its description of pseudorefs to match the glossary’s definition. The only behavioral change is in `revision.c`, where the error message for `--merge` no longer calls MERGE_HEAD et al. "pseudorefs," though the list of valid refs remains the same. The commit message for Patch 4/5 has been tightened in v2, focusing on the core terminology changes.
- Julia Evans’s proposal: The "References" section of `Documentation/gitdatamodel.adoc` now explicitly covers root refs and pseudorefs, aligning the pedagogical documentation with the reference documentation updated by the series. The new sections describe root refs (e.g., HEAD, ORIG_HEAD) and pseudorefs (FETCH_HEAD, MERGE_HEAD) in the context of Git’s data model, addressing the prior gap where the guide only mentioned ORIG_HEAD in passing.

Open questions and loose ends
- Patrick Steinhardt’s feedback on Patch 3/5 remains partially unaddressed: (1) the phrasing of `core.logAllRefUpdates`’s logic in `git-update-ref(1)` is still ambiguous about whether "always" applies to all subsequent conditions or only the first, and (2) the reflog storage explanation in `git-update-ref(1)` is still outdated for the reftable backend, as it references `$GIT_DIR/logs/<ref>` which does not hold for reftable. His suggestion to replace the detailed explanation with a cross-reference to `git-config(1)` is not yet implemented.
- Potential discussion point: whether the glossary’s new structure is sufficiently clear for users unfamiliar with the 2024 terminology change, though no explicit objections have been raised in v2.
- The completion helper `__git_pseudoref_exists()` remains named as-is due to ambiguity about what term would cover both pseudorefs and root refs; this is a deliberate omission.
