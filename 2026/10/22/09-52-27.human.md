This is a feature request for a new `git remote set-password` command. Ján Waclawek proposes adding a built-in way to update only the password portion of a remote URL, leaving the username, hostname, and path intact. The motivation is to simplify password rotation for users who embed credentials directly in remote URLs, particularly when server policies require frequent password changes.

The request is narrowly scoped: the command would target only the password component of the URL, avoiding the need for users to manually reconstruct or script URL updates. Ján acknowledges the security trade-offs of embedding passwords in URLs but argues the feature would still benefit users who already rely on this pattern and understand the risks.

No prior discussion or related work is mentioned in the email, and this appears to be the first time the idea has been floated on the list. The proposal is lightweight and self-contained, but it touches on a sensitive area (credential handling) where Git has historically encouraged alternatives like credential managers. Whether the project would accept such a feature remains an open question.
