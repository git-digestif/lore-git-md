This thread is a four-patch bugfix series by Justin Tobler that resolves a critical flaw in Git's object database (ODB) transaction layer. The issue occurs when migrating a temporary object directory to the primary one while using a compatibility hash (e.g., SHA-1/SHA-256 interop) and batch fsync of loose objects. The migration logic previously failed if a loose-object-idx file already existed in the primary directory, risking ODB transaction failures and potential data loss.

The series has been merged to Junio C Hamano's `seen` branch and is now ready for integration. Key changes include atomic writes (replacing an unsafe append-under-lock pattern), a finite lock timeout to avoid hangs, and refactored parsing and writing logic to support the fix. The final patch (4/4) implements the core migration logic, merging entries from both temporary and primary loose-object-idx files and writing the result atomically. A regression test (`t/t1016-compatObjectFormat.sh`) verifies the fix preserves all entries during migration.

Patrick Steinhardt provided substantive review, raising blocking concerns about atomicity and locking that were fully addressed in the series. Junio merged the patches to `seen` with no functional changes, though a minor integration artifact—a leftover function declaration in `loose.h`—remains and will be cleaned up in a follow-up. The fix is high-priority for users of the compatibility-hash feature, and the series is now complete with no outstanding technical issues.
