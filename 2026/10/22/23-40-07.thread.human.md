This thread is about a bugfix series for Git’s ODB transaction layer, specifically addressing a critical issue where temporary object directory migration fails under compatibility hash configurations (e.g., SHA-1/SHA-256 interop) when batch fsync is enabled. The series, authored by Justin Tobler, is now in its third version and has been merged to Junio C Hamano’s `seen` branch, signaling it is ready for integration testing.

The core problem involved the loose-object-idx file—a mapping between objects and their compatibility hashes—not being correctly merged during migration, risking ODB transaction failures and potential data loss. The v2 series resolved the main technical concerns: atomicity (via temp-file-then-rename), locking (a 1000ms timeout instead of indefinite blocking), and refactoring (new helper functions for reading/writing the loose-object-idx). Version 3 made minor optimizations, such as reducing lock contention by reading the source file outside the lock, and added clarifying comments. All substantive reviews, including those from Patrick Steinhardt and Karthik Nayak, have been addressed, and the series is uncontroversial.

The patches touch `tmp-objdir.c`, `loose.c`, and `loose.h`, introducing new functions (`loose_object_map_read()`, `loose_object_map_write()`, `loose_object_idx_merge()`) and a regression test (`t/t1016-compatObjectFormat.sh`). While the fix is functionally complete, systemic design flaws in the loose-object-idx mechanism—such as unsorted files, lack of deduplication, and no pruning of stale entries—are acknowledged but deferred to future work. The only remaining loose end is a leftover function declaration in `loose.h`, which Justin plans to clean up post-merge.

In the latest email, Karthik Nayak provided a retrospective review, noting that the 1000ms timeout is a reasonable incremental step but flagged the lack of a config knob as a minor `#leftoverbits` item. This aligns with the series’ pragmatic approach of deferring non-critical improvements to avoid scope creep. No further changes are expected, and the series is on track for graduation to `next` and eventually `master`.
