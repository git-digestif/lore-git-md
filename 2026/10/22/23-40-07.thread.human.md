This thread is about a four-patch bugfix series (v2) from Justin Tobler that fixes a critical bug in Git’s ODB transaction layer. The bug occurs when migrating temporary object directories under compatibility hash configurations (e.g., SHA-1/SHA-256 interop) with batch fsync enabled, leading to potential data loss due to a flawed loose-object-idx migration process. The series replaces a risky append-under-lock pattern with atomic temp-file-then-rename writes, adds a finite lock timeout to prevent hangs, and refactors parsing and writing logic for reusability.

The series is now finalized and under re-review after addressing all blocking feedback from Patrick Steinhardt, the primary reviewer. Patch 1/4 (locking timeout) is effectively approved, and the remaining patches—including this one, which refactors loose-object index parsing—are uncontroversial. Patrick’s latest review on patch 2/4 is positive, with minor suggestions for clarifying the commit message and improving error diagnostics, but no functional changes are required. The broader design flaws in the loose-object-idx mechanism (unsorted files, no deduplication, no stale entry pruning) are acknowledged but deferred to future work, with Patrick warning of long-term maintenance risks.

Justin has been responsive to feedback, and the series is a high-priority fix for ODB layer stability, targeting the current integration cycle. A regression test (`t/t1016-compatObjectFormat.sh`) verifies the fix, and the atomic-write approach ensures correctness despite performance trade-offs. The series is part of Patrick Steinhardt’s ongoing ODB abstraction effort and is ready for integration once re-review is complete.
