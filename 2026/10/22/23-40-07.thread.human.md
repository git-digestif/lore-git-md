This thread is a four-patch bugfix series from Justin Tobler that fixes a critical bug in Git’s ODB transaction layer, where temporary object directory migration fails under compatibility hash configurations (e.g., SHA-1/SHA-256 interop) with batch fsync enabled. The issue causes ODB transaction failures and potential data loss due to incorrect merging of the "loose-object-idx" file—a mapping between objects and their compatibility hashes—when a preexisting index exists in the primary object directory.

The series is now in its third iteration (v3) after addressing all blocking feedback from Patrick Steinhardt, the primary reviewer. Patches 1/4 (locking timeout) and 2/4 (parsing refactor) are effectively approved, while patch 3/4 (writing refactor) remains uncontroversial. The final patch, 4/4, implements the core fix by merging entries from temporary and primary object directories and atomically writing the result using refactored helpers. Key improvements in v2 and v3 include replacing the append-under-lock pattern with Git’s standard temp-file-then-rename pattern for atomicity, introducing a finite 1000ms lock timeout to avoid hangs, and optimizing locking scope by reading the source loose-object-idx file outside the lock. The series also includes a regression test (`t/t1016-compatObjectFormat.sh`) to verify the fix.

Justin has been responsive to feedback, incorporating Patrick’s suggestions on locking optimizations and documentation clarifications. While systemic flaws in the loose-object-idx mechanism—such as unsorted files, lack of deduplication, and no pruning of stale entries—are acknowledged, they are deferred to future work. The series is considered high-priority for ODB layer stability and is expected to be ready for integration once v3 is resent. No further technical changes are anticipated beyond the two minor adjustments Patrick requested for patch 4/4.
