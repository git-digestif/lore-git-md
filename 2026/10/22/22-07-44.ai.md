This is a documentation patch in the ongoing effort to align Git’s terminology around "pseudorefs" and "root refs" following the 2024 redefinition (commit 993d57eded). This email is Junio’s review of the first patch in Andy Koppe’s five-patch series, which updates the glossary to formally define "root ref" and clarify the "pseudoref" entry.

Junio’s review is substantive. He flags a key omission in the new "pseudoref" definition: the current wording drops the phrase "different semantics," which he argues is essential to explain why pseudorefs like FETCH_HEAD and MERGE_HEAD cannot be written with `git update-ref`—not just because of storage differences, but because they can record multiple object names. He also praises the addition of a sentence clarifying that using a pseudoref with multiple object IDs yields the first one, calling it "an important addition." The review does not object to the glossary reorganization itself, which splits out irregular root refs into a dedicated section.

The review does not include tested feedback or suggest code changes, but it raises a conceptual point that could affect the rest of the series. The author may need to revise the glossary entry to restore the "different semantics" phrasing, which could ripple into later patches that reference the glossary. No other participants have weighed in yet, and the series remains under review with no merge status reported. Key terms for follow-up discussion: "different semantics," "pseudoref," "root ref," and the glossary’s cross-reference to `gitrevisions(7)`.
