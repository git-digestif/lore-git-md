This is a documentation patch clarifying how Git checks SSH key lifetimes (`valid-after`/`valid-before`) during signature verification. The patch updates the `gpg.ssh.allowedSignersFile` man page to state explicitly that Git uses the committer or tagger date (not the signature timestamp) for these checks, fixing a previously ambiguous description. It also corrects a typo ("OpensSSH" → "OpenSSH").

This is the second iteration of the patch, incorporating Junio C Hamano’s suggested wording from the thread. The new version is more concise, omitting two caveats that were in the first version: one explaining that GPG signatures *do* record their own timestamp (unlike SSH), and another warning that key lifetime checks are only trustworthy if the key has never leaked. Phillip Wood and Patrick Steinhardt had previously endorsed the more detailed wording, but Junio argued for brevity, and this version reflects his preference.

The patch is part of a broader security thread addressing two flaws in Git’s SSH signing verification. The first flaw—timestamp confusion—is what this patch documents; the second—revocation file fails-open behavior—has already been fixed in a separate patch (though Junio raised a minor control-flow concern that is still being resolved). The documentation change here is uncontroversial in substance (all parties agree on the behavior), but the debate over how much detail to include remains open. If reviewers push back, the omitted caveats may return in a future revision.

The patch is small (3 lines changed) and well-motivated, with clear test coverage in the earlier security fix. It’s ready for integration once the documentation wording is finalized, though the thread suggests this may require one more round of discussion. For readers tracking the SSH signing security fixes, this patch is worth noting but not urgent—it’s a clarification, not a behavior change.
