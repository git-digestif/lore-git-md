This is the second patch in Harald Nordgren’s four-part **bugfix series** for `git imap-send`, addressing a long-standing interoperability issue with tools like `b4`. The patch rewrites the header-parsing logic in `imap-send.c` to accept `From`, `Date`, and `Subject` headers in any order, fixing a failure when `Subject` appears before `Date` (a valid but non-canonical order produced by `git send-email` and other tools). The change is minimal and focused: it replaces a brittle string-search approach with a new helper function, `has_required_headers()`, that scans the header block for the three required headers regardless of their order. A new test in `t/t9001-send-email.sh` verifies the fix by feeding a patch with `Subject` before `Date` into `git imap-send` and confirming it is accepted.

The patch is well-motivated and clearly explained. The commit message describes the real-world scenario (fetching patches from a mailing list archive with `b4` and piping them into `git imap-send`) and the specific failure mode ("no messages found to send"). The new test covers this workflow explicitly, ensuring the fix works in practice. The implementation is clean: the helper function is straightforward and uses existing Git APIs (`starts_with()`), and the change is isolated to the message-counting logic. There are no backward-compatibility concerns here—this is purely a bugfix that makes `git imap-send` more permissive in what it accepts.

This patch is part of a larger series that has already seen one patch merged to `next` (the tunnel process lifecycle fix) and addresses all previously raised technical concerns. The remaining patches (3/4 and 4/4) deal with related but distinct issues (removing a `git-send-email` special case and enforcing case-insensitive header matching), so this one stands on its own. The test coverage is thorough, and the change is unlikely to be controversial. If you care about `git imap-send` or interoperability with mailing list tools, this is worth reviewing.
