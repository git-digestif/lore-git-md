This is a rejection of a feature request for a `git remote set-password` command.

Brian M. Carlson firmly declines Ján Waclawek’s proposal to add a command that updates only the password portion of a remote URL. The core reason is security: the project considers URL-embedded passwords an unsafe pattern and has previously discussed removing support for them entirely. The convenience of such a feature is outweighed by the risk of exposing credentials in config files, especially when those files are accidentally published (e.g., on web servers).

Carlson points to existing, safer alternatives: credential helpers (including a simple one that reads from environment variables, documented in the Git FAQ) and SSH public-key authentication. He also mentions `git-credential-store`, which ships with Git and stores credentials in a plaintext file outside the repository by default. The message makes it clear that the project’s stance is to discourage URL-based credentials rather than make them easier to use. No further discussion or patch iteration is expected on this proposal.
