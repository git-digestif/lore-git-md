This is the third patch in Harald Nordgren’s four-patch **bugfix series** for `git imap-send`, which is now cooking in `seen`. The series as a whole fixes interoperability with tools like `b4` by making `git imap-send` accept email headers in any order (notably `Subject` before `Date`) and plugs a tunnel-command lifecycle bug.

This specific patch removes a **special-case workaround** that was introduced in commit `04133f5bc4` (2025-08-12) to handle copies of sent emails produced by `git send-email --imap-sent-folder`. The old logic treated messages starting with `From git-send-email` differently, counting them as valid if they had `From` and `To` headers but ignoring `Date` and `Subject`. That workaround was necessary because `git send-email` writes `Subject` before `Date`, but now that the header-parsing logic is order-agnostic (fixed in patch 2/4), the special case is redundant. The patch simplifies the code by treating all messages uniformly, requiring only that they have the three required headers (`From`, `Date`, and `Subject`) regardless of order.

The change is minimal: it replaces a 19-line conditional block with a single line that checks for the `From` prefix and delegates the header validation to the new `has_required_headers()` helper. The patch also adds a test that verifies `git send-email --imap-sent-folder` still works as expected, ensuring backward compatibility. The test coverage is thorough, exercising the same workflow that the special case was originally designed to support.

The patch is well-motivated and uncontroversial. The special case was always a workaround, and its removal is now possible because the underlying issue (order-sensitive header parsing) has been fixed. The commit message clearly explains the rationale and the context, and the test ensures the change does not break existing functionality. This patch should be ready for integration once the series as a whole is reviewed.
