This is the second patch in a two-patch series targeting test infrastructure, specifically the `clar`-based unit test runner. It adds `-l`/`--long-tests` as a NOOP command-line argument to `t/unit-tests/unit-test.c`, mirroring the pattern established in commit 9faf3963b6 for other compatibility flags. The change is a single-line addition and directly addresses the core issue: when users run `meson test --test-args='-ilx'`, Meson forwards the `-l` flag to the test binary, which previously rejected it as unrecognized, causing the test run to fail. With this patch, the flag is silently ignored, restoring expected compatibility without altering test behavior.

The motivation is practical and well-justified: the failure surfaces in common Meson workflows and prevents tests from running at all, while the fix is minimal and follows an established precedent. The patch is part of the ongoing test modernization effort (clar unit test framework adoption) and depends on the NOOP argument infrastructure introduced in 9faf3963b6. CI pipelines confirm no regressions, though some macOS runners did not execute, which is noted but not treated as a blocker.

This patch is the actual fix; the first patch in the series was a preparatory cleanup to maintain alphabetical order in the NOOP argument list. The series is narrowly scoped, unlikely to be controversial, and touches only the unit test runner's argument parsing logic. The commit message clearly explains the context, the problem, and the solution, making it easy for reviewers to assess the change. No functional behavior change is introduced beyond making the test runner more tolerant of Meson's argument forwarding.
