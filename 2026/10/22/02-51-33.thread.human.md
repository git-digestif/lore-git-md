This thread is about a two-patch bugfix series that fixes inconsistent behavior in `git switch -c` and `git checkout -b` when they fail to write tracking configuration due to a stale `.git/config.lock`. Previously, these commands would leave the repository in an inconsistent state—updating the worktree and index, creating the new branch ref, but leaving HEAD on the old branch. The series makes the operation non-atomic but consistent: if the tracking config write fails, the switch still completes, and Git exits with status 0, matching the behavior of `git push -u`, `git clone`, and `git fetch`.

The author, tsukasa-ino, split the series at Junio’s request after the direction was agreed in the bug report thread. Patch 1 refactors `setup_tracking()` in `branch.c` to return an error instead of calling `exit()`, and patch 2 modifies `builtin/checkout.c` to ignore the tracking config failure and finish the switch, while updating the test suite to verify the new behavior. Junio has now queued the series in his integration pipeline, meaning it will appear in the next `seen` rebuild. No substantive review feedback was recorded before queuing, and the series is uncontroversial.

The patches touch `branch.c`, `branch.h`, `builtin/branch.c`, and `builtin/checkout.c`, with no on-disk format changes.
