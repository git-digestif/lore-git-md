Core problem or goal
Refactor the code that handles `git log --follow` in merge commits to simplify the logic introduced in commit 304812ed33 (June 2026) and fix a bug where `git log -m --follow` loses history on the second parent of a merge. The patch removes the separate `propagate_follow_pathspec_to_parent()` function and its loop, integrating path-following directly into the existing `log_tree_diff()` parent loop. This ensures the pathspec is correctly restored before diffing each parent, preserving history on all sides of a merge.
