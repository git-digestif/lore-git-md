This is the fourth and final patch in Harald Nordgren’s four-part bugfix series for `git imap-send`, addressing RFC 5322 compliance by making header name matching case-insensitive. The patch modifies `imap-send.c` to use `istarts_with()` instead of `starts_with()` when checking for `From:`, `Date:`, and `Subject:` headers, ensuring that messages with headers spelled in any case (e.g., `from:`, `DATE:`) are accepted. This change is minimal and mechanical, touching only three lines in the `has_required_headers()` helper introduced earlier in the series.

The motivation is clear: RFC 5322 explicitly treats header field names as case-insensitive, and `git imap-send` previously rejected messages with non-lowercase headers, breaking interoperability with tools that emit such headers. The fix aligns the parsing logic with the standard and complements the earlier patches in the series, which already made the header order agnostic and removed the `git-send-email` special case. No new symbols or on-disk format changes are introduced; the patch simply broadens the set of valid inputs.
