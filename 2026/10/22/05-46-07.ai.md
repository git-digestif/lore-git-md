This is a **security bugfix** for Git's SSH signing verification, addressing the second of two critical flaws reported by Christian Noé Ramos López: when `gpg.ssh.revocationFile` is configured but missing, Git now fails verification instead of silently proceeding. This patch is the **v2 revision** of the fix, incorporating Junio C Hamano's feedback on the error-handling flow.

The patch moves the missing-file check into the same block that handles unknown keys, ensuring that signature information is still displayed even when the revocation file is absent. This resolves the behavioral inconsistency Junio identified, where unknown keys triggered signature-info output but missing revocation files did not. The change affects `gpg-interface.c` and adds four new test cases in `t/t7528-signed-commit-ssh.sh` to verify revoked keys, missing files, and the `:(optional)` escape hatch. Documentation in `gpg.adoc` is updated to clarify the new behavior.

The security posture is now correct: revocation file errors fail closed by default, with an escape hatch via Git's `:(optional)` pathname syntax for users who prefer to proceed. The patch is well-tested and addresses the last unresolved technical point in the thread. Once merged, it will close a significant security gap where misconfigured revocation files were silently ignored. The earlier timestamp-confusion documentation issue remains under separate review but is not blocking this fix.
