This is a refactoring patch in the log subsystem, specifically simplifying the `--follow` rename-tracking logic for non-linear (merge) history. It is the third patch in a four-patch series by Miklos Vajna.

The patch removes a custom function (`propagate_follow_pathspec_to_parent`) and its associated loop that were added in an earlier version of the series. Instead, it reuses the existing parent-diffing loop in `log_tree_diff` to record the path to follow for each parent, eliminating a redundant call to `diff_tree_oid`. The change is motivated by performance considerations: the old approach required extra diff computation, while the new one piggybacks on the diffs that are already being performed.

A side effect of this refactoring is a fix for `git log -m --follow`, which previously lost history on one side of a merge because the followed path was updated before diffing the second parent. The patch adds a test that verifies the full history is now preserved in a diamond-shaped merge scenario.

The diff is confined to `log-tree.c` and a new test in `t/t4219-log-follow-merge.sh`. The commit message is clear and explains both the simplification and the behavioral fix. No performance improvement is claimed yet, but the code is now simpler and more maintainable. This looks like a well-crafted cleanup that addresses a real edge case.
