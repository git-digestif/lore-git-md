This is the second patch in a two-patch refactoring series that moves the `pack.packsizelimit` configuration value from a global variable into the repository-scoped `repo_config_values` struct. The series is part of the ongoing effort to eliminate global state in Git, making the codebase more modular and easier to reuse as a library.

The patch itself is straightforward: it removes the standalone global variable `pack_size_limit_cfg` and adds a `pack_size_limit` field to `repo_config_values`. The configuration parser (`git_default_config`) and the pack-writing code (`builtin/pack-objects.c` and `object-file.c`) are updated to read the value from the struct instead of the global. The change is mechanical and well-contained, touching only four files and preserving existing behavior.

Joy’s commit message clearly explains the motivation—removing global state to improve modularity—and the implementation is clean. The preparatory patch (1/2) in this series, which uses `memset()` to standardize initialization of `repo_config_values`, was added in response to feedback from Patrick Steinhardt, who also confirmed the direction aligns with his own work. This suggests the patch is uncontroversial and likely to be merged once reviews are complete.

Testing appears solid: Joy reports successful runs of `t1300-config.sh` and `t5300-pack-object.sh`, and the changes are unlikely to introduce regressions. The patch is a small but meaningful step in the broader `the_repository` removal effort, and it looks ready for integration.
