This is the fourth patch in Andy Koppe’s five-patch series to align Git’s documentation, code comments, and tests with the 2024 terminology change that narrowed "pseudoref" to FETCH_HEAD and MERGE_HEAD only, while introducing "root ref" for refs outside the "refs/" hierarchy (e.g., HEAD, ORIG_HEAD). The patch updates in-code comments and help text in four files—`builtin/for-each-ref.c`, `contrib/completion/git-completion.bash`, `refs.h`, and `revision.c`—to replace outdated uses of "pseudoref" with "root ref" where appropriate.

The changes are mechanical and precise: the help text for `git for-each-ref --include-root-refs` now says "root refs" instead of "HEAD ref and pseudorefs"; the bash-completion script’s comments clarify that `__git_pseudoref_exists()` covers both root refs and pseudorefs (though the function name itself is left unchanged); and `refs.h` updates its description of pseudorefs to match the glossary’s definition, while also correcting the comment for `REFS_FOR_EACH_INCLUDE_ROOT_REFS` to list root refs explicitly. The only behavioral change is in `revision.c`, where the error message for `--merge` no longer calls MERGE_HEAD et al. "pseudorefs," though the list of valid refs remains the same.

The patch is uncontroversial and well-scoped, touching only comments and help text without altering code logic or on-disk formats. It continues the series’ goal of eliminating terminology drift after the 2024 redefinition, and the author’s rationale for leaving `__git_pseudoref_exists()` named as-is (ambiguity about a term covering both root refs and pseudorefs) is reasonable. No new edge cases or test failures are introduced.
