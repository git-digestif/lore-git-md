This is a documentation patch addressing the first of two SSH signing verification flaws reported in the thread. It clarifies which timestamp Git uses when checking SSH key lifetimes (`valid-after`/`valid-before`) in the `gpg.ssh.allowedSignersFile` configuration.

The patch updates the `gpg.adoc` man page to state explicitly that Git checks the *committer or tagger date* (not the signature timestamp) against the key's validity range. This resolves the earlier ambiguity where the documentation implied the signature time was used, which is not possible with SSH signatures. The change also fixes a typo ("OpensSSH" → "OpenSSH"). This version adopts Junio C Hamano's proposed wording from the review discussion, omitting the caveats about key leakage and signature timing that were present in earlier iterations.

The patch is part of a broader security-focused thread addressing two critical flaws in Git's SSH signing verification. The other flaw (revocation file fails open) has already been patched and is awaiting final resolution of a control-flow concern raised by Junio. This documentation patch is uncontroversial in its technical content—all participants agree the committer/tagger date is the correct timestamp to use—but the discussion remains open on whether the man page should include explicit warnings about the limitations of key lifetime checks. Junio prefers brevity, while Phillip Wood and Patrick Steinhardt previously endorsed more detailed warnings.

The patch touches only the `Documentation/config/gpg.adoc` file, with no code changes. It is ready for integration once the documentation wording debate is resolved, though the outcome is unlikely to block the security fixes themselves. The commit message and trailers (`Helped-by`) reflect the collaborative shaping of the text, including Junio's input on this version.
