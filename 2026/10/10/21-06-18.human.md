This is a bugfix for `git repack` that closes a long-standing regression in the `--dry-run` option. The patch, now in its second version, fixes the issue where `git repack --drop-filtered --dry-run` incorrectly rebuilds packs and deletes old ones despite the `--dry-run` flag, which is supposed to prevent any repository modifications. The fix is minimal and surgical: it adds an early `return` in `cmd_repack()` after listing the candidate objects for dropping, ensuring the code does not proceed to the actual repacking steps.

The patch touches only `builtin/repack.c` and adds a new test in `t/t7706-repack-drop-filtered.sh` to verify that the pack directory remains unchanged under `--dry-run`, covering both explicit (`-d`) and implicit deletion cases. The commit message now clearly documents the regression's origin—it has existed since `--dry-run` was introduced in commit `1e746b00aa` (2025)—and the in-code comment has been reworded to avoid proposal-like language, as requested in the review.
