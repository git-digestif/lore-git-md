This is the first patch in Harald Nordgren’s v8 series introducing `remote.<name>.refmap`, a new configuration option that enables a "matching-inspired" fetch mode for shallow repositories. The patch adds the plumbing for the refmap setting: parsing the configuration, storing it in the `remote` struct, and integrating it into the fetch machinery.

The core idea is simple: `remote.<name>.refmap` provides a default value for the `--refmap` command-line option, just as `remote.<name>.fetch` provides default refspecs. When both are configured, `remote.<name>.fetch` takes precedence, resolving a long-standing fatal error ("--refmap option is only meaningful with command-line refspec") that occurred in earlier versions. The patch also clarifies that a refmap-only remote with no explicit refspecs to fetch behaves like a remote with no refspecs at all—it falls back to the usual defaults rather than erroring out.

The implementation touches `remote.c` and `remote.h` to add the new `refmap` field to the `remote` struct, `builtin/fetch.c` to integrate the refmap into the refspec resolution logic, and documentation to explain the new configuration. The test coverage is thorough, verifying that the refmap behaves like the `--refmap` command-line option, that it works with explicit refspecs, and that it correctly defers to `remote.<name>.fetch` when both are present.

This patch is well-crafted and uncontroversial. It lays the groundwork for the dynamic branch inference logic in Patch 3/5 without introducing any behavior changes on its own. The design—using a separate configuration key to separate namespace mapping from fetch selection—has already been consensus-approved in earlier iterations, and the precedence rule (`remote.<name>.fetch` wins) is now settled. The patch is ready for merging and sets the stage for the rest of the series.
