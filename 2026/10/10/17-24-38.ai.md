This is a bugfix for `git fast-import`. The patch addresses a crash that occurs when `git fast-import` tries to resolve a commit that was created earlier in the same session but is not yet reachable via the object database (ODB). The crash manifests as a fatal error: `not a valid commit: <new-commit-oid>`, even though the commit exists and can be queried for file content (e.g., via `ls`).

The fix modifies the `parse_from_existing` function in `builtin/fast-import.c` to first check the fast-import object cache for the commit before falling back to the ODB. If the commit is found in the cache and is of type `OBJ_COMMIT`, it is unpacked directly from the cache, avoiding the ODB lookup that would fail. The patch also handles tag dereferencing (via the existing `dereference` helper) to ensure tags pointing to commits are resolved correctly.

The change is minimal and targeted: it adds a cache lookup path without altering the existing ODB fallback, so behavior for objects not in the cache remains unchanged. The commit message is clear about the problem and the solution, though it does not include a test case or reproduction steps. The patch is likely to be uncontroversial, as it fixes a crash without introducing new behavior.
