This is the fourth patch in Harald Nordgren’s v8 series introducing a "matching-inspired" fetch mode for shallow repositories. The patch adds a `--limited-fetch` flag to `git remote add`, which configures the remote to use the new `remote.<name>.refmap` setting instead of the traditional wildcard `remote.<name>.fetch` refspec. This ensures that `git fetch <name>` only fetches branches already tracked by local branches (via `@{upstream}`), avoiding the performance penalty of negotiating history for all remote branches.

The implementation is straightforward and well-scoped. The flag is rejected when combined with `-t/--track` or `--mirror`, since those options already specify explicit fetch behavior. The patch updates `builtin/remote.c` to set `remote.<name>.refmap` (e.g., `+refs/heads/*:refs/remotes/<name>/*`) when `--limited-fetch` is used, and adds documentation to `git-remote.adoc` explaining the new behavior. Test coverage in `t/t5505-remote.sh` verifies that the flag works as expected and conflicts appropriately with `-t`.

This patch is uncontroversial and ready for review. It does not introduce new design decisions—those were settled in earlier patches—and simply provides a user-facing way to opt into the new fetch mode. The only minor edge case is that `--limited-fetch` is allowed in non-shallow repositories (though it is only *defaulted* for shallow repos in Patch 5/5), which aligns with the series’ goal of making the feature available more broadly. The implementation is clean, with no hardcoded `the_repository` usage or other technical debt.

The patch touches `builtin/remote.c`, `Documentation/git-remote.adoc`, and `t/t5505-remote.sh`, and integrates seamlessly with the rest of the series. It is a logical follow-up to Patch 3/5 (which implements the dynamic branch inference logic) and sets the stage for Patch 5/5 (which makes `--limited-fetch` the default for shallow repositories). No open questions or loose ends remain for this specific patch.
