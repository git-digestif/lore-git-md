This is a bugfix for `git fast-import`. The patch addresses a crash that occurs when `fast-import` tries to look up a commit that was created earlier in the same session but is not yet reachable through the object database (ODB). The error manifests as a fatal message: `fatal: not a valid commit: <new-commit-oid>`, even though the commit exists and can be queried for file content.

The fix modifies the lookup logic in `builtin/fast-import.c` to first check the in-memory object cache before falling back to the ODB. If the object is found in the cache and is a commit (or a tag that can be dereferenced to a commit), the code uses the cached data instead of querying the ODB. This avoids the crash and may also improve performance by skipping unnecessary ODB lookups.

The commit message is clear and includes a reproduction scenario, though it does not cite a specific regression commit or real-world use case that triggered the issue. The patch itself is small (14 insertions, 4 deletions) and focused, touching only the lookup path for newly created commits. No tests are included, which is a minor gap given the crash scenario. The fix looks technically sound and addresses a real problem, but its impact is limited to `fast-import` users who create and immediately reference commits in the same session.
