This is the fourth patch in Harald Nordgren’s v8 series introducing a matching-inspired fetch mode for shallow repositories. Junio C Hamano’s reply is a **surface-level review** acknowledging that the patch is straightforward and well-executed. He did not examine the test coverage but did not raise any concerns about the implementation itself.

The patch adds a `--limited-fetch` flag to `git remote add`, which configures the remote to use `remote.<name>.refmap` (e.g., `+refs/heads/*:refs/remotes/<name>/*`) instead of the traditional wildcard `remote.<name>.fetch` refspec. This ensures that `git fetch <name>` only fetches branches already tracked by local branches (via `@{upstream}`), avoiding the performance penalty of negotiating history for all remote branches in shallow repositories. The flag is rejected when combined with `-t/--track` or `--mirror`, as those options already specify explicit fetch behavior.

The implementation is clean and uncontroversial, touching `builtin/remote.c`, `Documentation/git-remote.adoc`, and `t/t5505-remote.sh`. It integrates seamlessly with the rest of the series and does not introduce new design decisions—those were settled in earlier patches. The patch is ready for review and has no known issues or loose ends.
