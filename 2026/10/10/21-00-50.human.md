This is a bugfix for `git repack` that corrects a long-standing regression in the `--dry-run` flag when used with `--drop-filtered`. The patch, now in its second version, ensures that `git repack --drop-filtered --dry-run` truly performs a dry run—listing objects that would be dropped without rebuilding packs or deleting anything, as documented.

The issue was straightforward: the `--dry-run` block in `cmd_repack()` fell through into the regular repack code, causing unintended modifications to the repository. The fix is minimal—adding an early `return` after listing candidate objects—and includes a new test to verify the pack directory remains unchanged under `--dry-run`, covering both explicit (`-d`) and implicit deletion cases. The regression has existed since `--dry-run` was introduced in commit `1e746b00aa`, and the updated commit message now documents this historical context.

Review feedback from D. Ben Knoble has been incorporated: the comment in the code has been reworded to avoid proposal-like language, and the patch diff now includes a larger context. The fix is well-scoped, touching only `builtin/repack.c` and the test script, and the test coverage is thorough, checking both output and side effects. This looks like a clean, uncontroversial fix for a real user-facing issue. The patch is ready for integration and should be a straightforward merge to `next`.
