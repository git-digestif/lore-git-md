This is the second patch in Harald Nordgren’s v8 series introducing a matching-inspired fetch mode for shallow repositories. The patch extracts the existing logic that fetches the current branch’s upstream into a reusable helper, `collect_upstream_from_remote()`, so it can later be applied to *all* local branches that track the remote, not just the current one.

The change is a straightforward refactoring: the inlined code that checks whether the current branch builds on the remote and collects its upstream refs is moved from `builtin/fetch.c` into `remote.c`, parameterized to accept any branch name (or NULL for the current branch). The helper is then called in both the existing fallback path and the new path that will be introduced in Patch 3/5. The commit message explains the motivation clearly: a narrow refspec (e.g., from `git remote add -t`) can leave the current branch’s upstream uncovered, so the logic must be independent of the configured refspec.

The patch touches only three files and is purely mechanical: no behavior changes, no new configuration, and no user-visible effects. The extracted helper is well-documented and follows the project’s naming conventions. This refactoring is uncontroversial and directly addresses Junio’s earlier request to reduce code duplication and clarify control flow. It is a necessary step toward the dynamic branch inference that will be implemented in the next patch.
