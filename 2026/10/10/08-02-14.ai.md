This is the final patch (5/5) in Harald Nordgren’s v8 series introducing a "matching-inspired" fetch mode for shallow repositories. It makes `--limited-fetch` the default when adding a remote to a shallow repository, ensuring that `git fetch` does not negotiate history for all remote branches by default.

The patch updates `builtin/remote.c` to check `is_repository_shallow(the_repository)` when `limited_fetch` is unset (`-1`), defaulting to `--limited-fetch` unless `--no-limited-fetch` is given. The documentation in `git-remote.adoc` is updated to explain the new behavior, and four new tests in `t/t5505-remote.sh` verify that `-t` still sets an explicit refspec, full repositories keep the wildcard refspec, shallow repositories default to `--limited-fetch`, and `--no-limited-fetch` overrides the default.

The implementation is clean and uncontroversial. It threads the shallow check through the existing `limited_fetch` logic without introducing new technical debt or hardcoded globals. The test coverage is thorough, exercising the edge cases and ensuring backward compatibility. This patch is ready to queue once the series is approved.
