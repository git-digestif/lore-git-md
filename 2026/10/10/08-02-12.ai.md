This is the core feature patch (3/5) in Harald Nordgren’s v8 series introducing a "matching-inspired" fetch mode for shallow repositories. It implements the dynamic branch inference logic: when a remote is configured with `remote.<name>.refmap` but no `remote.<name>.fetch`, a refspec-less `git fetch <name>` now infers which branches to fetch by enumerating the local branches whose `@{upstream}` is on that remote.

The patch touches `builtin/fetch.c` (integrating the inference logic into `get_ref_map()` and `do_fetch()`), `remote.c`/`remote.h` (adding the `branches_tracking_remote()` helper that iterates over local branches and collects their upstream refs), and documentation (`Documentation/config/remote.adoc` and `Documentation/fetch-options.adoc`). It also adds a new test script (`t/t5586-fetch-refmap.sh`) with 119 lines of coverage verifying edge cases: bare fetches, explicit one-time fetches, duplicate branch tracking, cross-remote tracking, and `git remote show` compatibility.

The inference logic is cleanly separated: `branches_tracking_remote()` populates a `string_list` with the upstream refs of any local branch whose `remote_name` matches the target remote, and `get_ref_map()` constructs a dynamic refspec from these branches. The `infer_from_refmap` flag ensures the inferred refspec is treated as a command-line refspec (skipping the `remote.<name>.fetch` fallback path). The patch also updates `do_fetch()` to populate `transport_ls_refs_options.ref_prefixes` with the inferred branches, limiting the transport layer’s ref requests.

The implementation is technically sound, addressing all prior review concerns: the hardcoded `the_repository` usage is fixed by threading a `struct repository *` parameter, the `inferred_branches` variable is renamed to `infer_from_refmap` for clarity, and the regression where the current branch’s `@{upstream}` could be dropped is resolved. The test coverage is thorough, and the documentation clearly explains the new behavior. The only remaining question is whether this mode should be available outside of shallow repositories, but that is a minor design choice for follow-up work. This patch is ready for merging pending Junio’s re-review.
