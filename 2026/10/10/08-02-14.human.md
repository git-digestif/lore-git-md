This is the final patch in Harald Nordgren’s five-part series introducing a "matching-inspired" fetch mode for shallow repositories. It makes `--limited-fetch` the default when adding a remote to a shallow repository, ensuring that `git fetch` only negotiates history for branches tracked by local branches rather than all remote branches.

The patch updates `builtin/remote.c` to check `is_repository_shallow(the_repository)` when `limited_fetch` is unset (`-1`), defaulting to `--limited-fetch` unless `--no-limited-fetch` is explicitly given. The change is minimal and clean, with no hardcoded `the_repository` usage or other technical debt. Documentation in `git-remote.adoc` is updated to explain the new default behavior and its interaction with `--no-limited-fetch`.

Test coverage in `t/t5505-remote.sh` is thorough, verifying that:
- `-t/--track` still sets an explicit refspec (preserving existing behavior),
- full repositories keep the wildcard refspec (no change),
- shallow repositories default to `--limited-fetch` (new behavior), and
- `--no-limited-fetch` overrides the default (escape hatch).

The patch is uncontroversial and ready to queue. It addresses the core user pain point—slow fetches in shallow repositories—without disrupting non-shallow workflows. The only remaining question (whether the matching-inspired mode should be available outside shallow repositories) is explicitly deferred to follow-up work, as it doesn’t affect this patch’s correctness or scope. The series as a whole is now technically sound and a strong candidate for `next`.
