This is a platform compatibility bugfix targeting the Windows credential helper (`contrib/credential/wincred`). The patch is a revised version (v2) of an earlier attempt to fix a long-standing bug in how the wincred helper parses multi-line secret blobs, such as credentials containing both a password and an OAuth refresh token. The v1 patch addressed the immediate parsing issues but was criticized for poor commit message clarity and overly complex code structure.

The v2 patch is a substantial refactor that splits the credential blob processing into smaller, more readable helper functions (`write_credential_item` and `write_credential`). It eliminates the unsafe string operations (`wcsncpy_s`, `wcstok_s`) that could cause buffer overreads or misinterpret newlines, replacing them with immutable scanning via `wmemchr`. The commit message is now much more detailed, explaining the root causes of the bugs (e.g., incorrect size checks, missing line advancement) and the rationale for the refactor. Wide-character handling is explicitly addressed, with all character constants and sizes now consistently treated as wide-character counts.

The patch looks well-crafted and directly addresses Junio’s feedback from v1. The refactoring improves readability and maintainability while fixing the original bug. No test coverage is included, which is typical for `contrib/` code, but the changes are confined to the Windows-specific credential helper and do not affect other platforms. This version appears ready for further review and likely eventual merging.
