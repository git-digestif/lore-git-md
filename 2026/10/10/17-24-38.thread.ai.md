Core problem or goal
`git fast-import` crashes with `not a valid commit: <oid>` when attempting to resolve a commit created earlier in the same session but not yet reachable via the object database (ODB). The commit exists in the fast-import object cache and can be queried for file content (e.g., via `ls`), but the ODB lookup fails because the object is not yet written to disk.

Current status
Under review; no prior versions. Patch is minimal and targeted: it adds a cache lookup in `parse_from_existing` (builtin/fast-import.c) before falling back to the ODB, preserving existing behavior for objects not in the cache. Tag dereferencing is handled via the existing `dereference` helper.
