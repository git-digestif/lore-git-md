Subject: [PATCH v2] fast-import: fix crash when resolving unreachable in-session commits
Series version: standalone patch, v2
Originating author: Marc Becker
Thread type: bugfix

Core problem or goal
`git fast-import` crashes with `not a valid commit: <oid>` when attempting to resolve a commit or tag created earlier in the same session but not yet reachable via the object database (ODB). The object exists in the fast-import object cache and can be queried for file content (e.g., via `ls`), but the ODB lookup fails because the object is held in an in-progress packfile until a `checkpoint` or session end.

Current status
Under review; v2 posted addressing all feedback from v1. Changes from v1: improved commit message, line-length compliance, and added a comprehensive test case in `t9300-fast-import.sh` covering SHA-1 and SHA-256 repositories. The test verifies resolution of pending commits and tags (including tag-of-tag scenarios) without crashing, while preserving existing behavior for objects already in the ODB. Junio C Hamano has reviewed the patch and confirmed the technical soundness of the fix but requested further refinements: (1) clarification in the commit message regarding the timing-dependent nature of the crash, the distinction between blob and commit handling, and the role of the in-progress packfile, and (2) a minor test hygiene improvement to reduce duplication between the SHA-1 and SHA-256 test variants using `test_oid_cache` and `test_oid`. The patch is likely to be accepted once these final adjustments are made.

Key technical details
- File touched: `builtin/fast-import.c`
- Function modified: `parse_from_existing`
- New behavior: cache lookup for `OBJ_COMMIT` and `OBJ_TAG` objects before ODB fallback; tags are peeled in the cache via `dereference()` to match the ODB fallback behavior
- Symbols: none renamed; no new CLI/config/test symbols
- On-disk format: unchanged
- Test coverage: added in `t9300` (SHA-1 and SHA-256 variants); exercises `reset`, `from`, tag, and tag-of-tag scenarios. Junio suggested using `test_oid_cache` to abstract object names and reduce test duplication.

Open questions and loose ends
- Commit message wording remains unresolved; Junio provided a suggested rewrite, but the author has not yet responded.
- Test case duplication between SHA-1 and SHA-256 variants needs to be addressed using `test_oid_cache` and `test_oid` as suggested by Junio.
