Subject: [PATCH v2] fast-import: fix crash when resolving unreachable in-session commits
Series version: standalone patch, v4
Originating author: Marc Becker
Thread type: bugfix

Core problem or goal
`git fast-import` crashes with `fatal: not a valid commit: <oid>` when attempting to resolve a commit or tag created earlier in the same session but not yet reachable via the object database (ODB). The object exists in the fast-import object cache and can be queried for file content (e.g., via `ls`), but the ODB lookup fails because the object is held in an in-progress packfile until a `checkpoint` or session end.

Current status
**Merged to 'master'** (2025-06-12, per Junio's queuing notice). The patch was queued for merging after v4 addressed all prior feedback, including test indentation, commit message clarity, and code correctness. No further revisions or discussion are expected.

Key technical details
- File touched: `builtin/fast-import.c`
- Function modified: `parse_from_existing`
- New behavior: cache lookup for `OBJ_COMMIT` and `OBJ_TAG` objects before ODB fallback; tags are peeled in the cache via `dereference()` to match the ODB fallback behavior
- Symbols: none renamed; no new CLI/config/test symbols
- On-disk format: unchanged
- Test coverage: added in `t9300-fast-import.sh` (SHA-1 and SHA-256 variants); exercises `reset`, `from`, tag, and tag-of-tag scenarios. Uses `test_oid_cache` and `test_oid` to abstract object names and reduce duplication.
- Implementation details: `find_object()` for cache lookup, `dereference()` to peel tags, `gfi_unpack_entry()` to unpack objects from the in-progress packfile.
