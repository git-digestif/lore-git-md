This is Junio’s "What’s cooking" report for early October 2026, summarizing the state of all in-flight topics in the Git project. It is not a single patch but a meta-document that gives a 30-second snapshot of where every topic stands.

The report lists 45 topics currently cooking in Junio’s integration branches. The most actionable items for a busy reader are the **new topics** at the top, which are either ready for final review or waiting for author responses, and the **cooking topics** that are in `next` (the last integration step before `master`). Highlights:

- **hn/t7004-flaky-gpg-test-fix** (1 patch) fixes a flaky test on Alpine by pointing GNUPGHOME to an unused directory instead of deleting the active one. It is marked “Will merge to next?” and has no open discussion, so it looks like a straightforward test fix.

- **ps/ci-housekeeping-and-modernizations** (8 patches) updates CI jobs to drop Python 2, switch to modern OS images, and improve reftable test coverage. SZEDER Gabor raised a question about the reftable coverage change; the author has not yet responded.

- **qs/repack-keeps-pack-fix** (5 patches) prevents `git repack` from losing objects to a `.keep` file that appears mid-run. The series adds a new `--keep-pack-from-file` option to `pack-objects` so that repack can hand it a snapshot of kept packs. Stolee’s review identified a subtle issue; a reroll is expected.

- **ss/repack-drop-filtered-dry-run** (1 patch) fixes `--dry-run` in `git repack --drop-filtered` so it no longer actually rebuilds packs. Junio and Siddharth discussed whether the output should still list the packs that would be dropped; no consensus yet.

- **rm/blame-default-ignore-revs** (2 patches) makes `git blame` and `git annotate` automatically use `HEAD:.git-blame-ignore-revs` as the default ignore list if the file exists. The parser has been hardened against missing objects and malformed files. Junio asked for a documentation update; no response so far.

Among the **cooking** topics already in `next`, the most user-visible are:

- **hn/status-push-rebased-on-newer-upstream** (6 patches) improves `git status` and `git push` advice when a pushed branch was cleanly rebased onto a newer upstream. It now suggests force-pushing instead of pulling. The series is marked “Needs review” and has no recent feedback.

- **kk/fetch-write-commit-graph-incremental** (2 patches) speeds up `fetch.writeCommitGraph` by updating the commit-graph incrementally using only the newly fetched commits as seeds. It avoids a full reachability scan and is ready for `next`.

- **ps/odb-files-alternates** (13 patches) moves alternates handling from the core object database layer into the files backend. This is part of the ODB abstraction effort; Peff and others have reviewed it, but no final ack yet.

- **pw/checkout-m-conflict-labels** (2 patches) remembers the original conflict labels (branch names) in `.git/MERGE_LABELS` so that `git checkout -m` can restore them instead of showing generic labels. The series is new and marked “Needs review”.

- **hn/fetch-refmap** (4 patches) changes the default refspec for remotes added in shallow repositories to rely on `remote.<name>.refmap` instead of `remote.<name>.fetch`, pulling only the remote branches tracked by local branches. The series is marked “Expecting a reroll” after feedback from Elijah and Junio.

The report also lists several topics that are **waiting for review**, **expecting a reroll**, or **stalled**. If you are interested in a particular subsystem (e.g., reftable, ODB, CI, or merge machinery), you can quickly scan the list for the relevant author or topic name.
