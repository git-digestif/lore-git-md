This is the final version (v7) of a two-patch bugfix series targeting the `rerere` subsystem. It fixes a long-standing race condition where background maintenance tasks (like `git rerere gc`) could deadlock or kill an in-progress rebase when both tried to acquire the `MERGE_RR.lock` simultaneously. The issue became more pronounced after Git 2.54 introduced geometric maintenance, which triggers `rerere gc` more aggressively.

The first patch makes all `rerere` operations wait for the lock (with a configurable timeout, defaulting to 1000ms) instead of failing immediately. The second patch adds a `--skip-locked` mode for `git rerere gc`, allowing auto-maintenance tasks to skip silently if the lock is held—matching the behavior of other maintenance commands like `git gc --auto`. This is a pragmatic fix that avoids disrupting concurrent operations while preserving the ability to fail loudly for manual invocations.

The series is technically sound and addresses all prior feedback. Key improvements in v7 include:
- Dropping the controversial third patch (which allowed conflict-stopping commands to proceed without `rerere`).
- Renaming flags for clarity (`RERERE_GC_NOWAIT` instead of a shared bitmask).
- Better documentation and test coverage, including a new test verifying `--skip-locked` works when the lock is *not* held.
- Cleaner error handling and commit messages, incorporating Patrick Steinhardt’s suggestions.

The patches touch `rerere.c`, `builtin/gc.c`, and related documentation, with thorough test coverage in `t/t4200-rerere.sh` and `t/t7900-maintenance.sh`. The solution is conservative—conflict-stopping commands now fail outright if the lock remains held after the timeout—and aligns with Junio’s earlier guidance to avoid silent skips in user-facing operations.

This is a well-motivated fix for a real-world problem, and the final version looks ready for integration. The only unresolved discussion points (e.g., whether rebases should run maintenance at all) are deferred to future work, with no overlap expected between this series and Patrick Steinhardt’s planned adjustments to `maintenance.rerere-gc.auto`.
