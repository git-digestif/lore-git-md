This is a refactoring patch in Harald Nordgren’s five-part series implementing a "matching-inspired" fetch mode for shallow repositories. This specific patch (v8 2/5) extracts the logic for collecting upstream branches from a remote into a shared helper function, `collect_upstream_from_remote()`, in preparation for the dynamic branch inference logic introduced in Patch 3/5.

Junio’s review identifies a structural concern: the patch reorganizes the control flow in `do_fetch()` to use an `if/else if/else` cascade, which he argues is premature. The current branch’s upstream logic should remain independent of whether `remote.<name>.fetch` is configured, rather than being nested under the "no refspecs" case. Junio suggests the helper extraction should leave the existing logic untouched, deferring the control flow changes to Patch 3/5 where they are actually needed. The review also notes a potential NULL-dereference in the new helper (if `branch` is NULL), which the patch overlooks.

The patch is otherwise straightforward and well-motivated, but Junio’s feedback suggests it needs a v9 to address these issues. The helper itself is uncontroversial, but the integration in `builtin/fetch.c` should preserve the original behavior until the next patch in the series. This is a minor technical point, not a design objection, and the series remains a strong candidate for `next` once resolved. The thread’s earlier consensus on the `remote.<name>.refmap` design and the shallow-repository default behavior is unaffected.
