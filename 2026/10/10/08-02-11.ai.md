This is a refactoring patch (part 2 of 5 in the v8 series) that extracts the logic for collecting upstream branches from a remote into a shared helper function, `collect_upstream_from_remote()`. The patch is part of Harald Nordgren’s ongoing effort to implement a "matching-inspired" fetch mode for shallow repositories, where `git fetch` dynamically infers which branches to fetch based on local branches’ `@{upstream}` settings.

The change moves the existing inlined logic in `builtin/fetch.c`—which checks whether the current branch’s upstream lives on the remote being fetched—into a new helper in `remote.c`. This refactoring reduces code duplication and prepares the codebase for the next patch in the series, which will reuse the same logic to infer branches for remotes configured with `remote.<name>.refmap` but no explicit `remote.<name>.fetch` refspec. The helper function is straightforward: it takes a `struct repository *`, a `string_list` to populate, a `remote`, and an optional branch name (NULL means the current branch), and adds the upstream refs of any matching branches to the list.

The patch is clean and well-motivated. The commit message clearly explains the purpose of the refactoring, and the implementation is minimal, touching only the necessary files (`builtin/fetch.c`, `remote.c`, and `remote.h`). The helper function is documented in the header, and the change preserves the existing behavior: when no refspec is provided, the fetch still falls back to the remote’s configured fetch refspec (if any) and separately checks whether the current branch’s upstream needs to be fetched. The only functional difference is that the logic is now reusable, which is exactly what the series needs for the dynamic branch inference introduced in Patch 3/5.
