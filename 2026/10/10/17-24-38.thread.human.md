This thread is about a bugfix for `git fast-import` that prevents a crash when the `from` command references commits or tags created earlier in the same session but not yet reachable via the object database. The crash occurs because these objects exist only in an in-progress packfile, causing the ODB lookup to fail even though the objects are valid and present in the fast-import cache.

Marc Becker posted the fix, which now stands at version 3. The core change is minimal: `parse_from_existing()` now checks the fast-import object cache before falling back to the ODB, allowing it to resolve commits and tags directly from the in-progress packfile. Tags are peeled in the cache to match the ODB behavior. The fix preserves existing behavior for objects already in the ODB and does not alter the on-disk format.

Junio C Hamano, the maintainer, has reviewed the patch and confirmed its technical soundness. All feedback from earlier versions has been addressed: the commit message is now precise about the timing-dependent nature of the crash and the distinction between blob and commit handling, and the test case has been refactored to eliminate duplication between SHA-1 and SHA-256 variants using `test_oid_cache`. The test covers `reset`, `from`, tag, and tag-of-tag scenarios for both hash algorithms. Aniket Gupta’s earlier review confirmed the bug is reproducible and the fix resolves it without regressing existing functionality.

The patch is uncontroversial and likely to be accepted soon. No further technical objections are expected, and the remaining work is purely cosmetic. The fix is a targeted solution to a specific crash and does not introduce broader changes.
