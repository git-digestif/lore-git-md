This thread is about a bugfix for `git fast-import` that prevents a crash when resolving commits or tags created earlier in the same session but not yet reachable via the object database. The issue occurs because the object exists in fast-import's cache but isn't yet written to the ODB, causing a lookup failure. Marc Becker posted a v2 patch addressing all feedback from v1, including improved commit message clarity, line-length compliance, and a comprehensive test case covering SHA-1 and SHA-256 repositories.

The patch is under review and considered technically sound by Junio C Hamano, who confirmed the fix aligns with existing patterns. The only remaining tasks are finalizing the commit message wording (Junio provided a suggested rewrite) and a minor test hygiene improvement—using Git's `test_oid_cache` to reduce duplication between SHA-1 and SHA-256 test variants. Aniket Gupta's review of v1 confirmed the bug's reproducibility and the fix's effectiveness across multiple scenarios. The patch is likely to be accepted once these small adjustments are made.
