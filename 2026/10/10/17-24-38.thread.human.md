This thread is about a bugfix for `git fast-import` that prevents a crash when resolving commits or tags created earlier in the same session but not yet written to the object database. The issue was first reported by Marc Becker, who proposed a minimal patch to check the fast-import object cache before falling back to the ODB. Aniket Gupta confirmed the bug and requested a test case in his review of the initial version.

Marc has now sent a v2 patch that addresses all feedback: the commit message is clearer, the code adheres to line-length conventions, and a comprehensive test case in `t9300-fast-import.sh` has been added. The test covers both SHA-1 and SHA-256 repositories and exercises four scenarios where the crash could occur, ensuring the fix works for pending commits, tags, and nested tags. The patch remains minimal, touching only `parse_from_existing` in `builtin/fast-import.c`, and introduces no new symbols or on-disk format changes.

The patch is now complete and ready for maintainer review. No objections or further requests have been raised, and the changes align with existing patterns in the codebase. Once Junio or another fast-import maintainer weighs in, the patch is likely to be accepted.
