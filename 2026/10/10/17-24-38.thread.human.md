This thread is about a bugfix for `git fast-import` that crashes when trying to resolve commits created earlier in the same session but not yet written to the object database. The patch, authored by Marc Becker, adds a cache lookup in `parse_from_existing` to handle these in-session commits before falling back to the ODB, preserving existing behavior for objects not in the cache.

Aniket Gupta has now confirmed the bug is reproducible and that the patch fixes it in four specific scenarios: `reset` with a new commit OID, `commit` with `from <new-oid>`, a tag created in the same session, and a tag-of-a-tag. Existing commits, tags, and blob references continue to work as expected. Aniket’s review is thorough, including reproduction steps and test results, and he requests a test case in `t9300` to ensure the fix is properly covered. The patch itself remains unchanged, and no other reviews have been posted yet. The fix is still under review, with the main open question being whether a test case will be added.
