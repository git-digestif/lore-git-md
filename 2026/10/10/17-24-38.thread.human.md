This thread is about a bugfix for `git fast-import` that prevents a crash when resolving commits or tags created earlier in the same session but not yet reachable via the object database. The issue occurs because these objects exist only in the fast-import object cache and an in-progress packfile, causing an ODB lookup failure. Marc Becker authored the fix, which adds a cache lookup for `OBJ_COMMIT` and `OBJ_TAG` objects before falling back to the ODB, ensuring tags are peeled in the cache to match ODB behavior.

The patch is now in its third version (v3), addressing all prior feedback. Junio C Hamano, the maintainer, rewrote the commit message for clarity and confirmed the fix is technically sound. The only remaining issue is a minor indentation inconsistency in the test script, which Junio flagged in the latest review. Once this cosmetic fix is applied, the patch is expected to be merged. The test coverage, which exercises `reset`, `from`, tag, and tag-of-tag scenarios for both SHA-1 and SHA-256, remains robust and unaffected by the indentation change. No open technical questions remain, and the patch is ready for acceptance.
