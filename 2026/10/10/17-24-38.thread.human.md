This thread is about a bugfix for `git fast-import` that prevents a crash when resolving commits or tags created earlier in the same session but not yet reachable via the object database. The issue occurs because these objects exist in the fast-import object cache but are held in an in-progress packfile until a `checkpoint` or session end, causing the ODB lookup to fail. Marc Becker authored the fix, which modifies `parse_from_existing()` in `builtin/fast-import.c` to check the cache before falling back to the ODB.

The patch has gone through four iterations, with the latest version (v4) addressing the last remaining feedback—a test script indentation nit. All prior technical feedback has been resolved, including improvements to the commit message, test coverage, and code correctness. The fix is minimal, preserves existing behavior for objects outside the cache, and includes thorough test coverage for both SHA-1 and SHA-256 repositories. Reviewers Aniket Gupta and Junio C Hamano have confirmed the fix resolves the crash without regressing existing functionality.

The patch is now ready for merging, with no further technical objections anticipated. It’s a targeted, well-tested fix for a reproducible crash in a niche but critical code path, and it aligns with existing patterns in `fast-import`. The change is uncontroversial and has no known loose ends or dependencies.
