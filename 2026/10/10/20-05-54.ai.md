This is a bugfix for `git repack` addressing a long-standing regression in `--dry-run` behavior with `--drop-filtered`. The author, Siddharth Shrimali, confirms that the bug has existed since `--dry-run` was introduced in commit `1e746b00aa`—the `--dry-run` block in `cmd_repack()` never returned early, causing it to fall through into the regular repack code and modify the repository despite the flag’s documented behavior. This clarification resolves Junio C Hamano’s earlier request for a bisection and will be documented in the updated log message for v2.

The fix remains minimal and well-scoped: an early `return` after listing candidate objects for dropping, preventing the code from proceeding to `repack_promisor_objects()` and `existing_packs_remove_redundant()`. The patch touches only `builtin/repack.c` and includes a new test verifying that the pack directory remains unchanged under `--dry-run`, covering both explicit and implicit deletion cases. D. Ben Knoble’s review confirmed the fix’s correctness and alignment with existing patterns, though minor comment rewording and a larger `-U` context in the patch diff were suggested and agreed upon.

This is a clear-cut regression with a straightforward fix, and the historical context now established (broken since introduction) makes it unlikely to mask deeper issues. The patch is ready for v2, pending the log message update and the agreed-upon cosmetic adjustments. No new technical questions or objections are open.
