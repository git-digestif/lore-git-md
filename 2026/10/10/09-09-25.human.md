This is the second patch in Thomas Bachem’s three-part bugfix series fixing a race condition in Git’s `rerere` subsystem, where concurrent operations contend for the shared `rr-cache` directory lock. The patch introduces a `--skip-locked` mode for `git rerere gc`, allowing background maintenance tasks (like `git maintenance run --auto` or `git gc --auto`) to silently skip garbage collection if the lock is held, rather than failing or waiting. This matches the behavior of other auto-maintenance tasks and prevents disruption to concurrent operations like `git rebase` or `git merge`.

The email is a reply to Patrick Steinhardt’s surface-level review of the patch, addressing minor wording, code comments, and API design choices. Thomas accepts all of Patrick’s suggestions: he will reword the commit message to clarify why the `--skip-locked` flag is hidden (aligning with `git gc --skip-foreground-tasks`), remove a layering-violating comment in `rerere.c`, and refactor the `RERERE_NOWAIT` flag into a dedicated `enum rerere_gc_flags` for the `rerere_gc()` function. He also agrees to split the existing test into two distinct cases—one verifying that `--skip-locked` skips when the lock is held, and another confirming it does not skip when the lock is free.

The exchange is purely mechanical and uncontroversial; no substantive objections remain. The patch is technically sound, well-tested, and ready for integration once these final tweaks are applied.
