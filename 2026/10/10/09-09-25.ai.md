This is a **surface-level review follow-up** to the second patch in Thomas Bachem’s three-part `rerere` lock contention bugfix series. The patch introduces `--skip-locked` mode for `git rerere gc`, allowing auto-maintenance tasks to skip silently if the `MERGE_RR.lock` is held. The exchange is purely mechanical: Patrick Steinhardt’s feedback targets commit message wording, code comments, API design (whether `RERERE_NOWAIT` should be a dedicated enum for `rerere_gc()`), and a missing test case. Thomas accepts all suggestions and will adjust the patch accordingly.

Key changes agreed:
- Add a final paragraph to the commit message explaining why `--skip-locked` is hidden (to match the pattern of `--skip-foreground-tasks` in `git gc`).
- Drop a layering-violating comment in `rerere.c` that assumed knowledge of callers.
- Clarify the comment on `RERERE_NOWAIT` to state that a held lock returns `-1` (treated as "nothing to do" by callers, not an error).
- Replace the shared bitmask flag with a dedicated `enum rerere_gc_flags` for `rerere_gc()`.
- Split the existing test into two: one verifying `--skip-locked` skips when locked, another verifying it does not skip when unlocked.

The patch’s core behavior (silently skipping a held lock for auto-maintenance) remains uncontested. This follow-up is a final polish before integration; no substantive objections or design debates are raised. The missing test case was already partially covered but will now be made explicit.
