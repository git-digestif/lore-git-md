This is the first patch in Harald Nordgren’s v8 series introducing `remote.<name>.refmap` for matching-inspired fetch mode. It adds the configuration knob itself, mirroring how `remote.<name>.fetch` already works: `remote.<name>.refmap` provides the default value for the `--refmap` command-line option, but only when there is something explicit to fetch (either via command-line refspecs or `remote.<name>.fetch`). If both `remote.<name>.fetch` and `remote.<name>.refmap` are configured, the former takes precedence, preserving backward compatibility. The patch touches `remote.c`/`remote.h` to parse and store the new setting, `builtin/fetch.c` to integrate it into the ref-mapping logic, and documentation to explain the behavior. Four new tests in `t/t5510-fetch.sh` verify that the refmap works like `--refmap` on the command line, that it does nothing when nothing is being fetched, and that `remote.<name>.fetch` still wins when both are present.

The implementation is clean and uncontroversial: it threads the new configuration through the existing refspec machinery without changing any on-disk formats or user-visible behavior yet. The precedence rule (`remote.<name>.fetch` over `remote.<name>.refmap`) is now consensus-approved and resolves the fatal error from earlier versions. The only remaining design question—whether the matching-inspired mode should be available outside shallow repositories—is explicitly deferred to follow-up work, so this patch is ready for integration once Junio re-reviews the series. The test coverage is thorough, and the documentation is clear.
