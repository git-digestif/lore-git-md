This is the fourth patch in Harald Nordgren’s five-patch v8 series introducing a "matching-inspired" fetch mode for shallow repositories. It adds a `--limited-fetch` flag to `git remote add`, allowing users to opt into the new behavior where `git fetch` only fetches branches already tracked by local branches (via `@{upstream}`), rather than all remote branches.

The patch is straightforward and uncontroversial. It extends `git remote add` with a new `--limited-fetch` option that sets up `remote.<name>.refmap` instead of `remote.<name>.fetch`, enabling the dynamic branch inference logic introduced in Patch 3/5. The flag is rejected when combined with `-t/--track` or `--mirror`, since those already specify explicit fetch behavior. The implementation is clean: it adds the flag, validates its usage, and updates the configuration logic in `builtin/remote.c` to write the refmap entry when the flag is set. Documentation in `git-remote.adoc` is updated to explain the new option, and a new test in `t/t5505-remote.sh` verifies that `--limited-fetch` works as expected and conflicts with `-t`.

This patch is ready to queue once the series is approved. It does not introduce new design decisions or technical debt, and the test coverage is adequate. The only remaining work for the series is Junio’s re-review, which is expected to focus on integration and edge cases rather than this patch. The series as a whole is a well-motivated feature that addresses a real performance pain point for shallow repositories, and this patch is a logical and necessary part of that solution.
