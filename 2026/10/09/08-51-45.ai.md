This is the first patch in Delilah Ashley Wu's v3 series fixing Git's global config file handling inconsistency. It adds test coverage for the edge case where no global configuration file exists, verifying that `git config list` succeeds while `git config list --global` fails. The tests focus on exit codes rather than error messages, ensuring the next patch ("config: read global scope via config_sequence") does not regress existing behavior.

The patch touches only the test suite (`t/t1300-config.sh`), adding two new tests that remove both `$HOME/.gitconfig` and `$XDG_CONFIG_HOME/git/config` before running the commands. This is a preparatory change for the core fix in patch 2, which will modify `do_git_config_sequence()` to enforce that `--global` operations fail if no global config file is readable. The tests use `test_must_fail` to confirm the expected failure mode for `--global` while preserving the success of unscoped operations.

The implementation is straightforward and uncontroversial, addressing a gap in test coverage identified during earlier iterations of the series. The changes align with the series' goal of making `--global` behavior consistent with Git's documented design, where unscoped operations read both global config files but `--global` operations should fail if neither file exists. No code changes are introduced here—this patch only establishes the baseline behavior for regression testing.
