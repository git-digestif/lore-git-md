This is the second patch in Jon Simons' 15-part performance series speeding up `git push` refspec matching for many deletions. It adds a **test exposing a behavioral quirk** in the current implementation: pushing a source ref prefixed with `./` (e.g., `./refs/heads/main`) succeeds today because `refname_match()` strips the leading `./` via `mkpath()`, even though such a refname is invalid. The test is marked `test_expect_failure` and will flip to `test_expect_success` in a later commit (patch 5) that removes the `mkpath()` call, aligning the behavior with the expectation that invalid refnames should be rejected.

The patch touches only the test file `t/t5516-fetch-push.sh`, adding a 6-line test case. The test sets up a repository with a `heads/main` branch, attempts to push `./refs/heads/main:refs/heads/frotz`, and verifies the command fails with the expected error message. This is a **test-before-code** pattern: the test demonstrates the current (incorrect) behavior, and a future patch will fix it. The commit message is clear and concise, linking the test to the specific function (`refname_match()`) and helper (`mkpath()`) that will be modified later.

This patch is a small but important part of the series' broader goal: eliminating linear ref traversals in favor of `strmap` lookups. The `mkpath()` removal (patch 5) is a prerequisite for those optimizations, as it ensures refnames are compared literally rather than after path normalization. The test here guards against regressions in that change.
