This is a platform compatibility bugfix targeting the Windows credential helper (`git-credential-wincred`). The patch addresses a long-standing issue in the `contrib/credential/wincred` helper where multi-line secret blobs (such as those containing OAuth refresh tokens) were not being parsed correctly, causing credential data to bleed across lines or be truncated.

The core problem is in the `get_credential()` function, which previously used `wcsncpy_s` with an incorrect target size and relied on `wcstok_s` to split the credential blob. The new implementation switches to direct pointer arithmetic with `wmemchr` to safely scan for newlines and equals signs, ensuring that each line is processed atomically. It also properly handles carriage returns (`\r`) that Windows might include in the blob data.

The commit message is terse but sufficient: it states the fix ("split on newline character to avoid bleed-over") and notes a safety improvement ("operate on immutable blob data"). The patch itself is well-contained, touching only the Windows credential helper in `contrib/`, so it carries minimal risk of regressing other platforms. No tests are included, which is typical for `contrib/` code, but the change is straightforward enough that manual verification should be easy for Windows users.

This looks like a solid, motivated fix for a real-world issue. If you use Git on Windows with credential helpers that store multi-line secrets (e.g., OAuth tokens), this patch is worth paying attention to. It is not part of any larger series and stands alone.
