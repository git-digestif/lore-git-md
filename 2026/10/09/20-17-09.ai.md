This is the **second patch in a two-part feature series** implementing automatic use of `HEAD:.git-blame-ignore-revs` as the default ignore-revs file for `git blame` and `git annotate`. The series is now feature-complete and security-hardened, but Junio’s reply here focuses on a **procedural nit** in the patch structure rather than the substance of the change.

The patch itself is **well-structured and technically sound**, implementing the agreed design: when no ignore-revs file is explicitly configured, Git checks for a `.git-blame-ignore-revs` blob in the `HEAD` tree, parses it in memory using the hardened `oidset_parse_buffer_carefully()` helper (introduced in patch 1/2), and adds it to the ignore list *before* any user-configured files. The implementation handles edge cases (subdirectories, bare repos, committed symlinks, CLI/config overrides) and includes comprehensive test coverage. The security hardening (NUL-byte rejection, promisor fetch prevention) is a prerequisite for exposing the parser to upstream-controlled content, and the split into two commits improves reviewability.
