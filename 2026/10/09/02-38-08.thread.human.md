This thread is about a reported bug in `git diff` where the output appears distorted compared to GNU `diff -u` for a commit that should show only deletions. David Yang initially reported the issue, noting that both local `git diff` and GitHub's diff viewer produce harder-to-read output than GNU `diffutils`. The distortion was reproducible with Git 2.45.1 on Linux x86_64, using a specific commit in the Linux kernel.

Toon Claes responded, clarifying that this is not a bug but a known limitation of Git's default "myers" diff algorithm, which is less sophisticated than alternatives like "histogram." He demonstrated that using `--diff-algorithm=histogram` produces a cleaner, deletion-only diff matching GNU `diffutils`. While this provides a practical workaround, the thread remains open on whether Git should update its default algorithm to something more modern. No other participants have weighed in yet, and the discussion is currently focused on the technical explanation rather than a broader design change.
