This is a cleanup and test modernization series targeting Git’s test infrastructure. The v3 iteration of Muhammed Dilshad A’s effort migrates the mergesort tests from the shell-based test suite to the Clar unit-test framework, simplifies the test design, adds edge-case coverage, and removes the now-unused `test-mergesort` helper and its associated performance benchmark. The series is now structured as four patches: the Clar migration, test simplification, edge-case coverage, and final cleanup.

The core goal remains unchanged: eliminate dead code, reduce the codebase by 307 lines (net 170 added, 477 removed), and preserve test coverage while adopting the modern Clar framework. The author has addressed Patrick Steinhardt’s feedback by dropping the leak-fix patch (since the helper is removed), simplifying the test inputs (replacing the 1,680-case grid with direct tests for sorted, reversed, equal-value, and repeatable random inputs), and splitting the migration into three focused commits. The final patch removes the obsolete `p0071-sort.sh` benchmark and the `test-mergesort.c` helper, which had no remaining users.

Key files touched include `t/unit-tests/u-mergesort.c` (new Clar test file), `t/helper/test-mergesort.c` (deleted), `t/perf/p0071-sort.sh` (deleted), and build-system files (`Makefile`, `meson.build`). The test coverage now includes explicit checks for empty lists, small lists, and debug hooks, while maintaining the original guarantees of sorted output, stable equal-value ordering, and correct list length. The simplification of test distributions and transformation modes was a direct response to review feedback, making the tests more maintainable without sacrificing rigor.

The series is under active review and appears to be in good shape for acceptance. Junio C Hamano and Patrick Steinhardt have both endorsed the cleanup direction, and the author has incorporated all requested changes. The commit messages are now clearer, and the test design is more focused. No user-facing behavior changes are introduced; this is purely internal test infrastructure work. The only remaining loose end is whether the simplified test design fully satisfies the original coverage goals, but the author’s approach (direct tests for key scenarios) seems reasonable and aligns with Patrick’s feedback.
