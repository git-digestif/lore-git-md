This is the first patch in a six-part documentation series introducing `gitmergeconflicts(7)`, a new man page consolidating Git’s merge-conflict resolution guidance. Junio’s review focuses on clarity, completeness, and consistency, engaging with the new guide’s explanations of merge conflicts, conflict markers, and terminology like "ours" and "theirs." The patch is well-motivated and addresses real user pain points (scattered advice, inconsistent terminology), but Junio raises several substantive points that will likely require minor revisions before merging.

Key issues Junio identifies include:
- **Omissions**: The guide omits `git am -3` and `git checkout -m` as conflict-causing commands, which may confuse users. Junio questions whether this is intentional (to simplify for beginners) or an oversight.
- **Terminology**: The guide introduces "original" (common ancestor) without defining it upfront, and uses "configuration option" instead of the project’s preferred "configuration variable." Junio suggests clarifying these in the "WHAT IS A MERGE CONFLICT?" section.
- **Conflict markers**: The guide fails to explain the `|||||||` marker in `diff3` output, which could puzzle users. Junio proposes adding a brief note where `diff3` is introduced.
- **Semantic conflicts**: Junio recommends adding a paragraph to acknowledge that Git cannot detect semantic conflicts (e.g., inconsistent function renames), setting user expectations.
- **`zdiff3`**: Junio argues `zdiff3` is a "failed experiment" that reduces `diff3`’s usefulness and suggests omitting or deprecating it in the guide.
- **Contractions**: Junio notes the use of informal contractions ("Here's," "there's") in an official manual, though this is a stylistic preference rather than a blocker.
- **`AUTO_MERGE`**: The guide’s explanation of `git diff AUTO_MERGE` is unclear about what `AUTO_MERGE` represents. Junio suggests reordering the text to define it before use.

Junio also flags a **16-year-old bug** in `git-merge.adoc` (references to steps "2" and "3" that no longer exist) and suggests a separate patch to fix it. This is unrelated to the new guide but worth addressing.

The review is **substantive**—Junio engages deeply with the guide’s content, suggesting improvements to accuracy, completeness, and user experience. His feedback is constructive and actionable, though some points (e.g., `zdiff3`, contractions) may spark minor debate. The patch is otherwise well-structured, with clear examples and a logical flow. Julia’s responsiveness to feedback in earlier versions suggests these issues will be addressed in v3.
