Core problem or goal
Add test coverage in `t5516-fetch-push.sh` for client-side validation of push refspec collisions—specifically when two refspecs attempt to create the same new branch on the remote, either in short (`main:frotz`) or fully qualified (`main:refs/heads/frotz`) form. The tests document both the expected behavior (rejection with `dst ref <ref> receives from more than one src`) and a known bug: the validation is bypassed when pushing to an empty repository, causing the server to reject the push instead.
