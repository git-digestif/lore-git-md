This is the second patch in Thomas Bachem’s three-part bugfix series addressing a long-standing race condition in Git’s `rerere` subsystem, where concurrent operations contend for the `MERGE_RR.lock`. The patch introduces `--skip-locked` mode for `git rerere gc`, a hidden flag designed exclusively for auto-maintenance (`git maintenance run --auto` and `git gc --auto`). This allows background maintenance to skip silently when the lock is held, avoiding disruptions to concurrent operations like rebase or merge.

Patrick Steinhardt’s review is surface-level, focusing on commit message clarity, code comments, and minor implementation details. He suggests rewording the commit message to better distinguish between user-initiated and auto-maintenance scenarios, and to avoid implying the lock is entirely new. His feedback also includes small technical tweaks: removing a layering-violating comment about `RERERE_NOWAIT`, questioning the error return for a skipped lock (though he acknowledges it’s debatable), and suggesting a more precise term than "free" in the flag’s documentation. Most substantively, he proposes introducing a dedicated `enum rerere_gc_flags` instead of reusing the existing `RERERE_*` flags, since none of the other flags apply to `rerere_gc`.

The patch itself remains uncontroversial and well-scoped. It cleanly separates auto-maintenance behavior from manual invocations, with thorough test coverage verifying both the silent skip behavior and the distinction between auto and manual modes. The changes align with established patterns in Git’s maintenance infrastructure (e.g., `--skip-foreground-tasks` in `git gc`). While Patrick’s suggestions are minor, they improve clarity and consistency, and Thomas is likely to incorporate them in a final revision. This patch is a pragmatic, targeted fix that fits neatly into the series’ broader goal of making `rerere` locking more resilient.
