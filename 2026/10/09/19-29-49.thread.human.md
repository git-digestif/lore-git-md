This thread is about a bugfix patch (11/15 in a series) that addresses a long-standing logic error in Git's remote subsystem. The issue causes Git to silently accept duplicate destination refs when pushing to an empty remote, rather than rejecting them as it does when the remote already has refs. The root cause is a pointer-handling error in `match_push_refs()` where the function passes the *value* of the remote ref list head rather than its *address*, preventing later iterations from seeing destinations created by earlier refspecs.

Jon Simons authored the fix, which modifies `match_explicit_refs()` to take a `struct ref **dst` parameter instead of `struct ref *dst`. This ensures each iteration re-reads the current head and detects newly linked destinations. The patch also updates six test cases in `t5408` and `t5516` from `test_expect_failure` to `test_expect_success`, confirming the fix works for both dry-run and actual pushes, and for both abbreviated and full refspec syntax. The regression dates back to 2005 (commit f88395ac23), and the patch includes a clear explanation of the NULL-handling failure along with thorough test coverage.

No new configuration keys, options, or user-visible behavior are introduced—this is purely a correctness fix affecting `remote.c` and the associated test files. The patch appears uncontroversial and is likely to be merged once reviewed.
