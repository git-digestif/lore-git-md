This is a bugfix patch addressing a regression in shallow fetches when backfilling tags. Karthik Nayak responds to Patrick Steinhardt’s review of the initial patch, clarifying two points.

First, Karthik acknowledges Patrick’s request for a benchmark comparison against `HEAD~` (the commit before the fix) to quantify the performance cost of splitting the reference transaction. He confirms he had the data but removed it for brevity and will restore it in the next version.

Second, Karthik agrees with Patrick’s suggestion to improve the test by directly verifying that no objects are re-fetched during tag backfilling, rather than relying on packet-trace counts of “have” lines. He proposes using `git cat-file` to inspect the repository state, which will make the test’s intent clearer.

The patch remains well-motivated and technically sound. The changes Karthik plans to make are minor refinements to the commit message and test, not functional adjustments to the fix itself. The two-transaction approach is now uncontroversial, and the discussion has moved to polishing the presentation. If you care about fetch performance or shallow clones, this is a small but important regression fix worth tracking.
