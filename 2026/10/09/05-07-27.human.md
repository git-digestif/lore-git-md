This is a **security hardening patch** for the `git blame` ignore-revs parser, part of a two-patch series that aims to make `HEAD:.git-blame-ignore-revs` the default ignore file. The patch addresses feedback from Junio on the v1 series, focusing on two key security concerns: embedded NUL bytes in ignore-revs files and unintended promisor fetches in partial clones.

Junio’s reply is **substantive but cautious**. He questions the necessity of rejecting lines with embedded NUL bytes, noting that the existing parser already fails safely on malformed input (e.g., trailing whitespace after a NUL). His skepticism is technical, not dismissive: he acknowledges that the current behavior might be overly permissive but isn’t convinced the stricter validation is justified. On the other hand, he **fully endorses** the promisor fetch prevention, calling it "a very reasonable thing to do" for partial clones.

The patch itself is **well-crafted and thorough**. It adds two new test cases: one for NUL byte rejection (covering both trailing garbage and comment-like patterns) and another for chained tags in partial clones (verifying no network requests are triggered). The hardening is **minimal and targeted**, modifying only the parser (`oidset_parse_file_carefully`) and tag-peeling logic (`peel_to_commit_oid`) without altering their public interfaces.

This patch is **not yet ready for merging**—Junio’s feedback suggests the NUL byte rejection may need further justification, and broader review from security-interested contributors (e.g., Jeff King, brian m. carlson) is still pending. However, the promisor fetch fix is uncontroversial and likely to stick. If the NUL byte handling is adjusted or justified, this could proceed quickly. **Worth watching** for security-focused reviewers to weigh in.
