Subject: git diff produces distorted output compared to GNU diffutils

Originating author: David Yang <mmyangfl@gmail.com>
Thread type: bug report / diff algorithm discussion

Core problem or goal
`git diff` (and GitHub's diff viewer) generates a distorted diff for a commit that should show only deletions, whereas GNU `diff -u` produces the expected clean deletion-only diff. The distortion stems from Git's default "myers" diff algorithm, which is less sophisticated than alternatives like "histogram" or GNU diffutils.

Current status
Reported and partially resolved: the distortion is confirmed to be intentional behavior of the default "myers" algorithm, not a bug. A practical workaround exists (`--diff-algorithm=histogram`), but the broader question of whether Git should update its default algorithm remains open. No patch or change to Git's default behavior has been proposed yet.

Key technical details
- **Command**: `git diff` (default "myers" algorithm)
- **Subsystem**: diff generation (xdiff/ or diff.c)
- **Expected behavior**: Clean deletion-only diff (as produced by GNU `diff -u` or `git diff --diff-algorithm=histogram`)
- **Actual behavior**: Distorted diff output that obscures deletions due to "myers" algorithm heuristics
- **Reproduction**: Specific commit (01e2de4664f6) in the Linux kernel (`drivers/net/dsa/motorcomm/chip.c`); prior patch series referenced on lore.kernel.org
- **Workaround**: `git diff --diff-algorithm=histogram` produces the expected clean diff
- **Platform**: Linux x86_64, Git 2.45.1
- **No on-disk format changes** or new symbols involved
- **Other diff modes**: Not yet tested (e.g., `--word-diff`, `--color-words`)
