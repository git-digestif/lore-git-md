Core problem or goal
Document and verify a subtle edge case in Git’s fetch logic: when a branch’s `branch.<name>.merge` configuration key is set to a value with a leading `./` (e.g., `./refs/heads/main`), the current code incorrectly matches it against remote refs because `refname_match()`—via `mkpath()`—strips the leading `./`, causing unintended matches in `FETCH_HEAD` and refspec resolution. The patch adds failing tests to expose the bug; a later patch in the series will fix it by removing the use of `mkpath()` in `refname_match()`.
