Subject: [PATCH 0/15] push: speed up refspec matching for many deletions
Series version: v2 (12 patches)
Originating author: Jon Simons
Thread type: patch series (performance-focused feature)

Core problem or goal
Client-side refspec matching in `git push` becomes a scalability bottleneck when pushing many branch deletions to a server with a large number of refs (e.g., 100k). The current implementation uses linear traversals, leading to O(n²) behavior. The series aims to achieve 10–100x speedups by replacing these traversals with `strmap` lookups and fixing long-standing behavioral quirks in `refname_match()`.

Current status
Under review; not yet in any integration branch. The author has addressed Kristoffer Haugsbakk’s process-oriented feedback by squashing failing-test commits into their corresponding fixes, reducing the series from 15 to 12 patches. No substantive technical reviews have been posted yet. The series remains structured to introduce behavioral changes via failing tests that are later resolved, ensuring robustness. Key performance improvements are demonstrated in the cover letter: a `git push --dry-run` of 100 delete refspecs to a 100k-ref server drops from 2.5–8.9s to 0.15–0.19s. Patch 1 (new in v2) adds input validation for `--force-with-lease=<refname>` to reject invalid refnames (e.g., `./refs/heads/main`) early, addressing a behavioral quirk tied to the upcoming removal of `mkpath()` in `refname_match()` (patch 3). Patch 2 (new in v2) introduces a perf test script (`t/perf/p5516-push-delete-refspec.sh`) to measure the client-side cost of matching explicit delete refspecs against a 100k-ref server, establishing baseline O(n²) timings (2.5s for 100 refspecs on an empty client, 6.85s on a mirror client) that later patches optimize. Patch 3 (formerly patch 5 in v1) delivers 55–82% of the total speedup by removing `mkpath()` overhead in `refname_match()` and eliminating the silent stripping of leading `./` in refnames, with perf script timings improving to 0.49s (empty client) and 1.18s (mirror client). Patch 8 (formerly patch 8 in v1) adds explicit test coverage for server-side behaviors—`receive-pack` rejecting duplicate ref updates and `send-pack` handling duplicate status reports—using plumbing to future-proof the tests. Patch 12 (formerly patch 15 in v1) refactored `apply_push_cas()` to optimize `--force-with-lease` overhead, reducing 100-lease timings from 4.79s to 0.16s.

Key technical details
- Files touched: `refs.c`, `remote.c`, `t/t5516-fetch-push.sh`, `t/t5408-push-porcelain.sh`, `t/t5410-receive-pack.sh`, `t/t5510-fetch.sh`, `t/t5533-push-cas.sh` (new), `t/perf/p5516-push-delete-refspec.sh` (new in v2)
- New/renamed symbols: `refname_match()` (behavior change: no longer strips leading `./` via `mkpath()`; now uses `match_parse_rule()` for direct string comparison), `check_push_refs()`, `match_explicit_refs()`, `apply_push_cas()` (refactored to invert loop nesting, splitting logic into `apply_one_cas()` and `apply_cas_tracking()` helpers), `match_parse_rule()` (helper function moved earlier in `refs.c` for use by `refname_match()`), `parse_push_cas_option()` (updated to validate `<refname>` input via `check_refname_format()`)
- Test coverage: new tests in `t5516` (patch 2: `./` refname quirk), `t5408` (patch 8: `send-pack` duplicate status handling), `t5410` (patch 8: `receive-pack` duplicate ref rejection), `t5510` (patch 3: `./`-prefixed refspec rejection), `t5533` (patch 1: `--force-with-lease` input validation), and perf script `t/perf/p5516-push-delete-refspec.sh` (patch 2). Patch 3 flipped `test_expect_failure` to `test_expect_success` for `./`-prefixed refspec cases in `t5510` and `t5516`.
- On-disk format: no changes
- Behavioral changes: duplicate destinations (e.g., pushing two refspecs to the same new branch) are now correctly rejected client-side when the remote is empty (patch 8); leading `./` in refnames are no longer stripped (patch 3), fixing a long-standing quirk where syntactically bogus refnames could be silently canonicalized into valid ones. Patch 1 ensures `--force-with-lease` rejects invalid refnames (e.g., `./refs/heads/main`) early, improving user feedback. A memory leak in `send-pack` exposed by the duplicate-destination logic was plugged in patch 5.
- Performance: 10–100x speedups in benchmarked scenarios (cover letter). Patch 2 establishes baseline O(n²) timings (2.5s for 100 refspecs on an empty client, 6.85s on a mirror client) for later comparison. Patch 3 contributes 55–82% of the total speedup by removing `mkpath()` overhead, with timings improving to 0.49s (empty client) and 1.18s (mirror client). Patch 12 optimizes `--force-with-lease` overhead, reducing 100-lease timings from 4.79s to 0.16s.

Open questions and loose ends
- The removal of `mkpath()` in `refname_match()` (patch 3) may require careful review to ensure no regressions in edge-case refspec matching, particularly in workflows that inadvertently relied on the old `./` stripping behavior. The series guards against this with new tests in `t5510` and `t5516`, and patch 1 ensures `--force-with-lease` rejects invalid refnames upfront.
