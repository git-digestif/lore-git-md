Subject: [PATCH 0/15] push: speed up refspec matching for many deletions
Series version: v2 (13 patches, now effectively 14 with the addition of refspec ordering tests and this duplicate-destination fix)
Originating author: Jon Simons
Thread type: patch series (performance-focused feature with correctness fixes)

Core problem or goal
Client-side refspec matching in `git push` becomes a scalability bottleneck when pushing many branch deletions to a server with a large number of refs (e.g., 100k). The current implementation uses linear traversals, leading to O(n²) behavior. The series aims to achieve 10–100x speedups by replacing these traversals with `strmap` lookups and fixing long-standing behavioral quirks in `refname_match()`. Additionally, it addresses correctness gaps in refspec ordering guarantees and duplicate-destination handling exposed by a 2025 server-side change (`9d2962a7c4`) that now rejects multiple updates to the same ref.

Current status
Under review; not yet in any integration branch. The author has addressed Kristoffer Haugsbakk’s process-oriented feedback by squashing failing-test commits into their corresponding fixes, reducing the series from 15 to 12 patches, and has since added two more patches (patches 6 and 7 in v2) for test coverage of server-side behaviors and refspec ordering guarantees. The eighth patch (new in this update) adds client-side rejection of duplicate destinations, which was previously only enforced server-side. This patch ensures that when pushing to an empty remote, Git now correctly rejects attempts to push multiple refspecs to the same destination (e.g., `git push remote.git A:foo B:foo`), aligning client-side behavior with server-side enforcement. The fix changes `match_explicit_refs()` to pass `dst` by pointer, ensuring each iteration re-reads the updated list head. The patch updates tests in `t5408` to expect the new client-side error message (`"dst ref ... receives from more than one src"`) and adds six new tests in `t5516` covering edge cases such as pushing two refspecs to the same new branch, pushing to an empty remote, and mixing abbreviated and full refspecs. No substantive technical reviews have been posted yet. The series remains structured to introduce behavioral changes via failing tests that are later resolved, ensuring robustness. Key performance improvements are demonstrated in the cover letter: a `git push --dry-run` of 100 delete refspecs to a 100k-ref server drops from 2.5–8.9s to 0.15–0.19s. Patch 1 (new in v2) adds input validation for `--force-with-lease=<refname>` to reject invalid refnames (e.g., `./refs/heads/main`) early. Patch 2 (new in v2) introduces a perf test script (`t/perf/p5516-push-delete-refspec.sh`) to measure the client-side cost of matching explicit delete refspecs against a 100k-ref server, establishing baseline O(n²) timings (2.5s for 100 refspecs on an empty client, 6.85s on a mirror client). Patch 3 (formerly patch 5 in v1) delivers 55–82% of the total speedup by removing `mkpath()` overhead in `refname_match()` and eliminating the silent stripping of leading `./` in refnames, with perf script timings improving to 0.49s (empty client) and 1.18s (mirror client). Patch 4 (new in this update) optimizes `check_push_refs()` by replacing its O(R * N) linear traversal of local refs with `strmap` lookups, reducing complexity to O(R * rules) for explicit refspecs and delivering a 31.1% speedup for 100 refspecs in the "mirror" case (timings drop from 1.19s to 0.82s). Patch 5 (new in this update) plugs a memory leak in `send-pack` exposed by the duplicate-destination rejection logic. Patch 6 (new in this update) adds explicit test coverage for server-side behaviors (`receive-pack` rejecting duplicate ref updates and `send-pack` handling duplicate status reports), using plumbing-level tools to avoid client-side logic. Patch 7 (new in this update) adds test coverage for refspec ordering guarantees in `send-pack`, ensuring command-line refspecs are sent before `--stdin` refspecs and in the order specified. Patch 8 (this update) adds client-side rejection of duplicate destinations. Patch 12 (formerly patch 15 in v1) refactored `apply_push_cas()` to optimize `--force-with-lease` overhead, reducing 100-lease timings from 4.79s to 0.16s.

Open questions and loose ends
- The removal of `mkpath()` in `refname_match()` (patch 3) may require careful review to ensure no regressions in edge-case refspec matching, particularly in workflows that inadvertently relied on the old `./` stripping behavior. The series guards against this with new tests in `t5510` and `t5516`, and patch 1 ensures `--force-with-lease` rejects invalid refnames upfront.
- No substantive technical reviews have been posted yet; the series is awaiting initial feedback. The new client-side error message (`"dst ref ... receives from more than one src"`) might break scripts expecting the old server-side message (`"multiple updates for ref ... not allowed"`), but this is not noted as a known issue in the commit message.
