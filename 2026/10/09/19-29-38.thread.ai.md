Subject: [PATCH 0/15] push: speed up refspec matching for many deletions
Series version: v2 (15 patches total; this update completes the series with the `--force-with-lease` optimization in patch 12/15)
Originating author: Jon Simons
Thread type: patch series (performance-focused feature with correctness fixes)

Core problem or goal
Client-side refspec matching in `git push` becomes a scalability bottleneck when pushing many branch deletions to a server with a large number of refs (e.g., 100k). The current implementation uses linear traversals, leading to O(n²) behavior. The series achieves 10–100x speedups by replacing these traversals with `strmap` lookups and fixes long-standing behavioral quirks in `refname_match()`. It also addresses correctness gaps in refspec ordering guarantees and duplicate-destination handling exposed by a 2025 server-side change (`9d2962a7c4`) that now rejects multiple updates to the same ref.

Current status
Under review; not yet in any integration branch. The series is now complete with all planned optimizations and correctness fixes. The author has addressed Kristoffer Haugsbakk’s process-oriented feedback by squashing failing-test commits into their corresponding fixes, reducing the series from 15 to 12 patches, and has since added four more patches (patches 6, 7, 9, and 10 in v2) for test coverage of server-side behaviors, refspec ordering guarantees, the `strmap`-based optimization for `match_explicit_refs()`, and performance baseline measurements for `--force-with-lease` overhead. The eleventh patch restructured `apply_push_cas()` to invert its loop nesting, splitting the logic into `apply_one_cas()` and `apply_cas_tracking()` helpers, enabling the `strmap` optimization in patch 12. The twelfth patch (this update) replaces the O(N*M) linear traversal of remote refs in `apply_push_cas()` with a `strmap`-based lookup, reducing complexity to O(N*rules) for N lease entries and M remote refs. This delivers 61–64% speedups for 100-lease scenarios, with timings dropping from 0.45–0.49s to 0.16–0.19s. The eighth patch adds client-side rejection of duplicate destinations, ensuring that when pushing to an empty remote, Git now correctly rejects attempts to push multiple refspecs to the same destination (e.g., `git push remote.git A:foo B:foo`), aligning client-side behavior with server-side enforcement. The ninth patch optimizes `match_explicit_refs()` by replacing two linear traversals of local and remote refs with `strmap` lookups, reducing complexity from O(R * N + R * M) to O(R * rules) for R refspecs, N local refs, and M remote refs. The tenth patch extends the perf script (`t/perf/p5516-push-delete-refspec.sh`) to measure `--force-with-lease` overhead, adding six new test cases that push 1, 10, or 100 delete refspecs *plus* one `--force-with-lease=<refname>:<expect>` per refspec. The series remains structured to introduce behavioral changes via failing tests that are later resolved, ensuring robustness. Key performance improvements are demonstrated in the cover letter: a `git push --dry-run` of 100 delete refspecs to a 100k-ref server drops from 2.5–8.9s to 0.15–0.19s.

Open questions and loose ends
- The removal of `mkpath()` in `refname_match()` (patch 3) may require careful review to ensure no regressions in edge-case refspec matching, particularly in workflows that inadvertently relied on the old `./` stripping behavior. The series guards against this with new tests in `t5510` and `t5516`, and patch 1 ensures `--force-with-lease` rejects invalid refnames upfront.
- No substantive technical reviews have been posted yet; the series is awaiting initial feedback. The new client-side error message (`"dst ref ... receives from more than one src"`) might break scripts expecting the old server-side message (`"multiple updates for ref ... not allowed"`), but this is not noted as a known issue in the commit message.
- The preparatory refactoring in patch 11 and the `strmap` optimization in patch 12 are structurally sound but may benefit from review to ensure no subtle edge cases in `--force-with-lease` handling, particularly in the interaction between explicit leases and the `use_tracking_for_rest` path.
