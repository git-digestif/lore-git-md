Core problem or goal
Client-side refspec matching in `git push` becomes a scalability bottleneck when pushing many branch deletions to a server with a large number of refs (e.g., 100k). The current implementation uses linear traversals, leading to O(n²) behavior. The series achieves 10–100x speedups by replacing these traversals with `strmap` lookups and fixes long-standing behavioral quirks in `refname_match()`. It also addresses correctness gaps in refspec ordering guarantees and duplicate-destination handling exposed by a 2025 server-side change (`9d2962a7c4`) that now rejects multiple updates to the same ref.
