This is the v3 cover letter for Delilah Ashley Wu's two-patch series fixing Git's global config file handling. The series addresses the inconsistency where `git config list --global` only read from `$HOME/.gitconfig` while Git actually applies configs from both that and `$XDG_CONFIG_HOME/git/config`.

Key changes in v3:
- Dropped the Windows path normalization patch entirely, opting instead to set `XDG_CONFIG_HOME` with forward slashes during tests to keep assertions consistent across platforms.
- Simplified the implementation by removing the `success_count` tracking and `attempt_git_config_from_file_with_options()` helper from v2, replacing them with a `global_had_success` flag in the core config sequence logic.
- Made `git_config_system()` respect the new `ignore_system` flag, consolidating config-scope filtering into `config_options`.
- Added tests verifying that `--global` ignores other scopes (system, local, worktree, command-line).
- Refactored `config_with_options()` to avoid long lines and ternary logic.

The series now focuses on the minimal changes needed to make `--global` read both config files while preserving existing error handling (e.g., failing if neither file is readable). The implementation reuses `do_git_config_sequence()` to avoid duplicating config-file reading logic. Tests cover edge cases like unreadable files and scope isolation.

This looks like a clean, well-scoped fix for a long-standing inconsistency. The v3 changes address Junio's feedback about structural clarity and maintainability without altering the core behavior. The Windows path issue is resolved at the test level, avoiding platform-specific code changes. The series appears ready for integration pending any final tweaks to naming or style.
