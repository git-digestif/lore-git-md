This is a **user workflow discussion** in the ongoing thread about extending `` `git branch --delete-merged` `` to detect squash-merged and rebase-merged branches. The exchange reinforces the practical demand for a more thorough branch cleanup feature, even at the cost of performance.

Harald Nordgren responds to Kristoffer Haugsbakk’s endorsement of a slower but more complete deletion operation by proposing a future `` `git full-clean` `` command. This hypothetical command would bundle `` `git branch --delete-merged` `` (with the new squash/rebase detection enabled by default) alongside all pruning operations (`` `git prune` ``, `` `git worktree prune` ``, etc.) using sensible defaults. He argues that such a command would address the common fear and confusion around Git by providing a safe, one-step cleanup for users who currently resort to drastic measures like deleting the entire repository. The proposal is speculative and not tied to the current patch, but it underscores the author’s broader vision for improving Git’s usability with opinionated, user-friendly defaults. No technical objections or new implementation details are introduced.
