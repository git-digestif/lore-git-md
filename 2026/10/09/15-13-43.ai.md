This is a small, user-visible consistency patch that aligns the advice message shown during merge conflicts with the pattern already used for rebase, revert, and cherry-pick. The patch updates `git status` output to suggest `git merge --continue` instead of `git commit` when in a conflicted merge state, touching `wt-status.c` and two test scripts (`t7060-wtstatus.sh` and `t7512-status-help.sh`). The change is purely cosmetic—`git merge --continue` has been a documented synonym for `git commit` since 2016—but it eliminates a minor inconsistency in Git’s user interface.

The patch is the third iteration (v3) of a single-patch series originally authored by Julia Evans. It addresses all prior feedback, including a cosmetic fix to the commit message’s reference formatting (now correctly using `git show -s --format=reference`) and a grammatical tweak to the advice text ("to conclude the merge"). Both substantive reviewers—Junio C Hamano and Phillip Wood—have explicitly approved the change, with Junio calling it "better late than never." The patch is technically complete, with updated test coverage verifying the new wording.

No new functions, config keys, or CLI options are introduced. The change affects only the advice text displayed by `git status` during merge conflicts, and the on-disk format remains unchanged. Translations will need updates, but the scope is minimal (command substitution and a grammatical correction). The patch is uncontroversial and ready for integration, with no open questions or loose ends.
