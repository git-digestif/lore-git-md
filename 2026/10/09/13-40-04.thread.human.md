This thread is about a user-facing improvement to `git status` and `git remote` messaging. Elia Pinto has proposed a patch that rewords the confusing "upstream is gone" message when a local branch tracks a remote branch that doesn't exist—whether because the remote repository is empty or the branch was deleted. The current message is misleading and suggests an incorrect fix (`git branch --unset-upstream`), while the new version clarifies the situation ("Your branch is set up to track 'origin/master', which does not exist") and conditionally suggests `git push` only when it would actually resolve the issue.

The patch is small and focused, touching only `remote.c` and the test suite, and preserves backward compatibility for scripts while improving the user experience. It includes thorough test coverage for edge cases like different `push.default` settings and disabled advice hints. The commit message is well-motivated, citing real user confusion (StackOverflow questions) and explaining the problem clearly. The patch is marked as an RFC, inviting feedback on the phrasing and whether it belongs under `status:` or `remote:`. So far, there are no replies, so the discussion is just getting started—this looks like a straightforward improvement that will likely be uncontroversial once the wording is settled.
