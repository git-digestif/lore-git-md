This is a bugfix patch, the first in a 15-patch series. It tightens input validation for the `--force-with-lease` option in `git push`.

The patch addresses a latent issue in `apply_push_cas()`: today, an invalid refname like `./refs/heads/main` is silently ignored because `refname_match()` uses `mkpath()`, which strips leading `./`. A later patch in the series (not yet seen) removes `mkpath()` from `refname_match()`, which would change the behavior so that the lease is no longer applied at all. To avoid a silent change in behavior, this patch adds an explicit `check_refname_format()` call in `parse_push_cas_option()`, making the command fail fast with a clear error message if the refname is invalid.

The change touches `remote.c` and adds a test case in `t/t5533-push-cas.sh` that verifies the new validation rejects `./refs/heads/main`. The commit message is clear and links the validation to the upcoming refactoring.
