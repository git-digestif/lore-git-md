This is the first patch in Delilah Ashley Wu’s v3 series fixing Git’s global config file handling. It adds test coverage for a long-standing inconsistency: when no global config file exists, `git config list` succeeds (because it falls back to other scopes), but `git config list --global` should fail. The tests verify this behavior by checking exit codes, not error messages, ensuring the next patch won’t regress it.

The patch is straightforward and uncontroversial. It touches only the test suite (`t/t1300-config.sh`), adding two new tests that remove both global config files (`$HOME/.gitconfig` and `$XDG_CONFIG_HOME/git/config`) and confirm the expected behavior. The tests are minimal but sufficient to catch regressions in the follow-up patch, which will modify `do_git_config_sequence()` to enforce this failure mode when `--global` is specified.

No code changes are made here—this is purely preparatory. The patch aligns with the series’ goal of making `--global` behavior consistent with Git’s documented design, where unscoped operations read both global config files but scoped operations (like `--global`) should fail if no files in that scope are readable. The tests are well-scoped and unlikely to cause issues, though they depend on the environment variables `$HOME` and `$XDG_CONFIG_HOME` being set (which is standard for the test suite). This patch is ready to merge as-is.
