This is the v3 cover letter for Delilah Ashley Wu's two-patch series fixing Git's global config file handling inconsistency. The series now reads both `$HOME/.gitconfig` and `$XDG_CONFIG_HOME/git/config` when `--global` is specified, aligning behavior with documentation and the unscoped `git config list` command.

The v3 iteration drops the Windows path normalization patch entirely, addressing Junio's concerns by adjusting tests to export `XDG_CONFIG_HOME` with forward slashes. This keeps platform-specific changes out of the core implementation. The series also simplifies the error-handling approach: instead of tracking `success_count` across all config files, it now uses a `global_had_success` flag to ensure at least one global config file was read when `--global` is specified. The `git_config_system()` function is updated to respect the new `ignore_system` flag, consolidating scope-filtering logic into `config_options`.

Patch 1 ("t1300: test list with missing global config") adds tests verifying that `git config list` succeeds without a global config file while `git config list --global` fails, preserving existing behavior. Patch 2 ("config: read global scope via config_sequence") implements the core fix by reusing `do_git_config_sequence()` with ignore flags to restrict reading to global scope. It also adds tests confirming both config files are respected during `--global` operations and that other scopes are ignored.

The series is technically complete and addresses all prior feedback except for minor structural refinements suggested in Junio's latest review. The implementation avoids duplicating config-file reading logic and maintains backward compatibility. Key files touched include `config.c`, `builtin/config.c`, and the test suite. No new CLI options or on-disk format changes are introduced. The thread remains active regarding the structural approach in patch 2, but the changes appear uncontroversial and well-motivated.
