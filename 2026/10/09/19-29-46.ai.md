This patch **adds test coverage** for two existing but under-tested behaviors in the push protocol: (1) `receive-pack` rejecting multiple updates for the same ref (a server-side safety check), and (2) `send-pack` handling duplicate ref status reports from the server. The tests are added to `t5408` and `t5410` and use low-level plumbing (`test-tool pkt-line`, `git receive-pack`) to bypass client-side logic, ensuring the tests remain valid even after the upcoming client-side duplicate detection is implemented (patches 9–11).

The motivation is clear: the existing tests in `t5408` that exercise these paths do so accidentally, relying on the client *not* detecting duplicates when the remote is empty. This patch makes the coverage explicit and robust, preparing for the behavioral change in later patches. The commit message explains the historical context (commits `9d2962a7c4` and `77188b5bba`) and justifies the test design (using plumbing to avoid client assumptions).
