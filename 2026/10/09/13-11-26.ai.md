This is the second iteration of a small, user-visible consistency patch. Julia Evans updates the advice message shown during a merge conflict to recommend `git merge --continue` instead of `git commit`, aligning it with the advice already given for rebase, revert, and cherry-pick. The change affects the output of `git status` in both the "unmerged paths" and "all conflicts fixed" scenarios, replacing the old phrasing with the new command and incorporating a grammatical improvement ("to conclude the merge") suggested by Phillip Wood.

The patch touches `wt-status.c` and updates two test scripts (`t7060-wtstatus.sh` and `t7512-status-help.sh`) to match the new wording. No new functions, config keys, or CLI options are introduced; the change is purely textual. The commit message explains that `git merge --continue` has been a documented synonym for `git commit` during merges since 2016, so this patch merely brings the advice text in line with existing behavior. Translations will need updating, but the change is minimal and straightforward.

This version (v2) addresses all feedback from the initial review: the commit message now uses `git show -s --format=reference` to format the reference commit, and the advice text has been reworded to "to conclude the merge" for better grammar. Junio C Hamano has explicitly approved the change as "better late than never," and Phillip Wood, who provided the substantive feedback, has no further objections. The patch is technically complete, well-motivated, and ready for integration. It is expected to land in `next` or `master` in the current cycle.
