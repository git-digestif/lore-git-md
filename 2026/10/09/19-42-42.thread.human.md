This thread reports a bug in `git svn` on Windows: cloning a local Subversion repository using a `file://` URL fails with a connection error, even though the repository itself is valid and can be checked out with Subversion tools. The issue surfaces on Git for Windows 2.51.0 when the URL includes a drive letter (e.g., `file:///D:/path/to/repo`). The error originates in the Perl SVN bindings layer (`Git/SVN.pm`), suggesting the problem lies in how `git svn` handles local filesystem paths on Windows rather than in the repository itself.

The report comes from a user, not a contributor, so no patch or workaround has been proposed yet. The thread is likely to draw responses from Windows platform maintainers (Johannes Schindelin, Johannes Sixt) and anyone familiar with the `git svn` subsystem. If a fix emerges, it will probably target either path normalization in the `git svn` wrapper or the Perl SVN bindings. For now, the issue remains open, with no indication of whether alternative URL schemes (`svn://` or `http://`) work around the problem.
