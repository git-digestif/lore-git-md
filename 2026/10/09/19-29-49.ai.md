This is a bugfix patch (11/15) targeting the remote subsystem. It fixes a long-standing logic error in `match_push_refs()` that causes Git to silently accept duplicate destination refs when pushing to an empty remote, rather than rejecting them as it does when the remote already has refs.

The root issue is that `match_explicit_refs()` passes the *value* of the remote ref list head (`dst`) to `match_explicit()` in each loop iteration, rather than the *address* of that head. When the remote is empty, `dst` is NULL, and `match_explicit()` appends new destinations through `*dst_tail` (which points to the head slot itself). Because the loop keeps reading from the original NULL, later iterations don’t see destinations created by earlier refspecs, so the duplicate-destination check never triggers.

The fix changes `match_explicit_refs()` to take `struct ref **dst` instead of `struct ref *dst`, so each iteration re-reads the current head from `*dst` and detects newly linked destinations. The patch also flips six `test_expect_failure` cases in `t5408` and `t5516` to `test_expect_success`, confirming that the bug is now fixed for both dry-run and actual pushes, and for both abbreviated and full refspec syntax.

Files touched: `remote.c` (core logic), `t/t5408-send-pack-stdin.sh` and `t/t5516-fetch-push.sh` (test updates). The commit message traces the regression back to f88395ac23 (2005), provides a clear explanation of the NULL-handling failure, and demonstrates thorough test coverage. No new config keys, options, or user-visible behavior are introduced—this is purely a correctness fix.
