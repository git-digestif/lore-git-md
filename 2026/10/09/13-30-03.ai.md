This is a **security-focused follow-up** in the ongoing discussion about Git's SSH signing verification flaws. The email is a brief but substantive exchange between Phillip Wood and Patrick Steinhardt, refining the agreed-upon fixes for two critical issues: the `valid-before` timestamp check (which uses the committer date instead of an independent timestamp) and the revocation file handling (which fails open instead of closed).

The conversation confirms the technical direction: **document the current `valid-before` behavior as a known limitation** (emphasizing that it is only trustworthy if the signing key has never leaked) and **make revocation file errors fatal by default** while providing an escape hatch via Git’s `:(optional)` pathname prefix. Phillip endorses Patrick’s proposal to use `:(optional)` for the revocation file, resolving the last design ambiguity in the thread. The discussion is now squarely in the implementation phase, with Christian Noé Ramos López committed to submitting a patch with test coverage for the revocation file logic.

Key details for follow-up: the patch will target `gpg-interface.c` and `gpg-ssh.c`, update the `gpg.ssh.allowedSignersFile` man page, and introduce new test cases for revocation file handling (currently untested). The `:(optional)` prefix is the chosen mechanism for allowing overrides, and no backward-compatibility concerns have been raised. The subsystem (`%G?` status codes, `valid-before` timestamp logic) and config keys (`gpg.ssh.revocationFile`) are well-defined, and the flaws are already demonstrated by test cases in the original report.
