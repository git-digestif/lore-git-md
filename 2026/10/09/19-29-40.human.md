This is the second patch in Jon Simons' 15-part performance series aimed at speeding up refspec matching in `git push`. The patch demonstrates a behavioral quirk in the current code: pushing a refspec with a leading `./` (e.g., `./refs/heads/main:refs/heads/frotz`) succeeds today because `refname_match()` internally strips the `./` via `mkpath()`. The test added here marks this as a bug by asserting that such a refspec should be rejected with the error "src refspec ./refs/heads/main does not match any".

The test is written as `test_expect_failure`, signaling that the current behavior is incorrect. A later patch in the series (commit 5) removes the `mkpath()` call from `refname_match()`, at which point this test will flip to `test_expect_success`. The change is part of a broader effort to tighten refspec validation and eliminate linear traversals that hurt performance when pushing many deletions to large repositories. The patch itself is small and focused, touching only the test file `t5516-fetch-push.sh`. It follows the series' disciplined test-before-code approach, making the behavioral change explicit and reviewable. No substantive feedback has appeared yet.
