Core problem or goal
`git svn clone` fails when given a local `file://` URL on Windows, throwing a Perl-level error from the SVN bindings ("Can't create session: Unable to connect to a repository at URL [...]"). The SVN repository itself is valid (user can check out a working copy), so the bug is isolated to the `git svn` ↔ local `file://` URL interaction on the Windows platform.

Current status
Under investigation; no fix or patch posted yet. The report is from Git for Windows 2.51.0, but it is unclear whether the issue is specific to that distribution or affects upstream Git as well.

Key technical details
- Subsystem: `git svn` (Perl wrapper around SVN bindings)
- Error location: `Git/SVN.pm`, line 148
- Platform: Windows (Git for Windows 2.51.0)
- URL form: `file:///D:/path/to/repo` (drive-letter, forward slashes)
- On-disk format: unchanged (SVN repository is valid)
- Test coverage: none yet; no regression test or CI coverage mentioned
