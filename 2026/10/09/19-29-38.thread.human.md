This thread is a 15-patch series from Jon Simons aimed at speeding up refspec matching in `git push`, particularly for large repositories where pushing many branch deletions to a server with 100k+ refs currently suffers from O(n²) performance. The series has demonstrated 10–100x speedups in benchmarks, with the fifth patch alone contributing 55–82% of the total improvement by removing `mkpath()` overhead and fixing a long-standing quirk where leading `./` in refnames were silently stripped.

The series is still under review, with no substantive feedback yet. Jon has taken a disciplined test-before-code approach: earlier patches introduced failing tests for behavioral changes and bugfixes, which are then resolved by later patches. The eighth patch (this email) adds explicit test coverage for two under-tested server-side behaviors—`receive-pack` rejecting duplicate ref updates and `send-pack` handling duplicate status reports—using low-level plumbing to ensure the tests remain valid even after client-side duplicate detection is implemented in later patches. This patch is test-only and introduces no behavior changes, making it a low-risk, high-value addition that future-proofs the series.

Key technical details include changes to `refs.c` and `remote.c`, new test coverage in `t5408`, `t5410`, `t5510`, and `t5516`, and behavioral changes like rejecting duplicate destinations client-side and no longer stripping leading `./` in refnames. The series is not yet in any integration branch, and the main open question is whether the removal of `mkpath()` in `refname_match()` might regress edge cases, though Jon has added tests to guard against this.
