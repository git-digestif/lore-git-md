This thread is about a patch series from Jon Simons aimed at speeding up refspec matching in `git push` when dealing with many branch deletions, while also fixing long-standing correctness issues. The series, now at version 2 with 12 patches (down from 15 after addressing feedback), tackles a scalability bottleneck that causes O(n²) behavior in large repositories—benchmarks show a 10–100x speedup in some cases.

The latest update, the eighth patch in the series, focuses on a correctness fix for duplicate destination handling. Previously, Git would only reject multiple refspecs targeting the same destination *server-side*, but this patch ensures the client catches these errors upfront, even when pushing to an empty remote. The fix is minimal (passing a pointer to track updated destinations) and comes with thorough test coverage, including edge cases like mixed abbreviated/full refspecs and dry-run scenarios. The new error message is more precise, though it might differ from what scripts expect if they relied on the old server-side rejection text.

The series as a whole is under review but hasn’t yet received substantive technical feedback. Earlier patches introduced optimizations like replacing linear traversals with `strmap` lookups and removing legacy `mkpath()` overhead, while later ones address behavioral quirks (e.g., no longer silently stripping leading `./` in refnames). The author has structured the series carefully, using failing tests to introduce changes before resolving them, and has added performance benchmarks to quantify improvements. The main open question is whether the removal of `mkpath()` might break edge-case workflows, though the series includes safeguards like input validation for `--force-with-lease`. No major objections have been raised so far, but the series is still awaiting deeper review.
