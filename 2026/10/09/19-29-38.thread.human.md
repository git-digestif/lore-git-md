This thread is about a patch series from Jon Simons that aims to speed up refspec matching in `git push` when dealing with many branch deletions. The current implementation struggles with large numbers of refs, leading to slowdowns, and this series promises 10–100x speedups by replacing linear traversals with more efficient `strmap` lookups and fixing long-standing quirks in how refnames are matched.

The series is still under review and hasn’t been picked up for integration yet. It’s structured to introduce failing tests for behavioral changes before implementing the fixes, which is a disciplined approach but drew a minor comment from Kristoffer Haugsbakk about the project’s preference for combining tests and fixes in a single commit. Jon plans to address this in the next version but is holding off until more substantive feedback arrives. Key improvements so far include removing `mkpath()` overhead in `refname_match()` (which delivered most of the speedup) and adding test coverage for server-side behaviors like duplicate ref rejection. The series also establishes baseline timings for `--force-with-lease` overhead, which will help quantify the impact of later optimizations.

No substantive technical reviews have been posted yet, so the main open question is whether the changes—particularly the removal of `mkpath()` and the handling of leading `./` in refnames—might introduce regressions in edge cases. The author has taken care to document these changes and provide historical context, but broader feedback from reviewers will be needed to confirm the approach. For now, the thread is in a holding pattern, waiting for deeper engagement from the community.
