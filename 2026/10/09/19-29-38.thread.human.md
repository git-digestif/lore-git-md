This thread is about a 15-patch series from Jon Simons that aims to speed up refspec matching in `git push` when dealing with many branch deletions, targeting a 10–100x performance improvement. The series replaces linear traversals with `strmap` lookups, and the latest patch (14/15) prepares the ground for this optimization by refactoring `apply_push_cas()` to invert loop nesting. This change is purely structural and sets up the final patch, which will introduce the `strmap` lookup.

The series has been structured carefully, with earlier patches adding failing tests for behavioral changes (like the removal of `./` stripping in refnames) and extending the performance test script to measure `--force-with-lease` overhead. The cover letter provides benchmark data showing significant speedups, with patch 5/15 already delivering 55–82% of the total improvement by removing `mkpath()` overhead. The latest patch continues this disciplined approach, ensuring the code is ready for the final optimization while maintaining existing behavior.

So far, the series is under review and hasn’t received substantive feedback yet. The refactoring in this patch is mechanical and unlikely to be controversial, though reviewers will want to verify the loop invariants hold. The series touches `refs.c` and `remote.c`, along with several test files, and introduces no on-disk format changes. The main open question remains whether the removal of `mkpath()` in `refname_match()` could introduce regressions, though the series includes tests to guard against this.
