This thread is about a performance-focused patch series from Jon Simons that speeds up client-side refspec matching in `git push` when dealing with many branch deletions against a server with a large number of refs. The series, now at v2 with 12 patches, has addressed process feedback by squashing failing-test commits into their fixes but is still awaiting substantive technical review.

The key improvement comes from replacing linear traversals with `strmap` lookups, delivering 10–100x speedups in benchmarked scenarios. The third patch in the series (which was the fifth in v1) contributes 55–82% of the total speedup by removing `mkpath()` overhead in `refname_match()` and eliminating a long-standing quirk where leading `./` in refnames were silently stripped. This behavioral change is justified as a bugfix and is protected by new tests, but may need careful review to ensure no workflows relied on the old behavior. Other notable changes include input validation for `--force-with-lease` (patch 1) and optimizations to `--force-with-lease` overhead (patch 12), which reduced 100-lease timings from 4.79s to 0.16s.

The series touches several files, primarily `refs.c` and `remote.c`, and introduces new test coverage including a performance script to measure baseline timings. While Kristoffer Haugsbakk provided surface-level process feedback on v1, no substantive technical reviews have been posted yet. The author has structured the series carefully, introducing behavioral changes via failing tests that are later resolved, which should help catch any regressions.
