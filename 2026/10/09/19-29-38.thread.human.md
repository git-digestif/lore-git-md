This thread is about a 15-patch series from Jon Simons that aims to speed up `git push` when deleting many branches against a server with a large number of refs. The current implementation suffers from O(n²) performance due to linear traversals, and the series promises 10–100x speedups by switching to `strmap` lookups. The patches are structured to introduce failing tests for behavioral fixes before the code changes that resolve them, a disciplined approach that makes the series easier to review.

The second patch in the series adds a test exposing a quirk in the current `refname_match()` function: it strips leading `./` from refnames via `mkpath()`, allowing invalid refspecs like `./refs/heads/main` to succeed when they should be rejected. This test is marked as expected to fail for now and will pass once a later patch removes the `mkpath()` call. The test is small, focused, and clearly linked to the broader goal of making refspec matching more predictable and efficient.

So far, the series has not received any substantive reviews, but the patches are well-documented and the performance improvements are compelling. The main open question is whether the `mkpath()` removal in patch 5 might introduce regressions in edge cases, though the test added here should help catch any issues. The series is still under review and not yet in any integration branch.
