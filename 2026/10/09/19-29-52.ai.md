This is the fourteenth patch in Jon Simons' fifteen-patch series **speeding up refspec matching in `git push`** for scenarios with many deletions. The series targets a **10–100x performance improvement** by replacing linear ref traversals with `strmap` lookups, and this patch restructures the `apply_push_cas()` function to prepare for that optimization in the final patch (15/15).

The patch **inverts the loop nesting** in `apply_push_cas()` to enable efficient `strmap` lookups in the next commit. Previously, the function iterated over every advertised remote ref and, for each, scanned the explicit lease entries until a match was found. The new structure iterates over explicit lease entries first, then stamps every matching remote ref in a single pass. This refactoring splits the logic into two helpers: `apply_one_cas()` (handles one explicit lease entry) and `apply_cas_tracking()` (shared by both explicit and "cover all" paths). The change is **pure refactoring**—no behavioral differences are introduced, but the new structure is necessary to replace the inner linear traversal with a `strmap` lookup in patch 15/15.

The patch touches only **`remote.c`**, moving ~30 lines of code to invert the loops. The commit message clearly explains the before/after structure and the motivation (preparing for `strmap`). The code is clean and the restructuring is mechanical, but the change is subtle enough that reviewers will want to verify the loop invariants hold—particularly that `ref->expect_old_sha1` is correctly set before skipping refs in the new `apply_one_cas()` loop.

This patch is part of the series' **disciplined test-before-code approach**: earlier patches added failing tests for behavioral changes (e.g., `./` refname handling, duplicate ref rejection), and the perf script was extended in patch 13/15 to measure `--force-with-lease` overhead (baseline timings: `0.12s` for 1 lease, `0.45s` for 100 leases).
