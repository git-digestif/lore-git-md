This is a **bugfix** targeting the sparse-checkout subsystem. Muhammed Dilshad A proposes a fix for the regression reported by Webstrand, where `git checkout` in a sparse-checkout working tree incorrectly overwrites untracked in-cone files instead of aborting. The patch ensures that untracked files inside the sparse cone are protected during branch switches, matching the behavior of non-sparse checkouts.

The fix modifies `unpack-trees.c` to use the standard untracked-file overwrite error (`ERROR_WOULD_LOSE_UNTRACKED_OVERWRITTEN`) instead of a sparsity warning when checking for conflicts. It also reorders the checks to validate all new entries before applying sparsity changes, ensuring the operation aborts if any conflict is detected. The patch includes a thorough regression test in `t1092-sparse-checkout-compatibility.sh` that verifies the fix across full checkouts, sparse checkouts, and sparse-index checkouts, confirming that untracked files, staged changes, and unrelated tracked files remain intact after a failed checkout.

The test coverage is comprehensive, checking not just the conflict scenario but also the state of the working tree, index, and HEAD after the failed operation.
