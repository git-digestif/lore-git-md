This is a platform compatibility bugfix targeting the Windows credential helper (`contrib/credential/wincred/git-credential-wincred.c`). The patch addresses a long-standing issue in how the wincred helper parses multi-line secret blobs (e.g., credentials containing both a password and an OAuth refresh token). The current code uses `wcsncpy_s` with an incorrect target size and relies on `wcstok_s` to split lines, which can lead to buffer overreads or misinterpretation of the blob content when newlines are present.

The new implementation operates on immutable blob data, using `wmemchr` to scan for newlines and carriage returns directly in the original buffer. It correctly handles line endings (`\r\n` vs `\n`), avoids modifying the input, and properly bounds all string operations. The commit message is terse but the code changes are clear: the helper now splits the blob into lines first, then looks for key-value pairs (`key=value`) only in lines after the first, which is the expected behavior for Git's credential protocol.

This is a standalone patch with no dependencies or follow-ups mentioned. The change is confined to the Windows-specific credential helper and does not affect other platforms. No tests are included, which is typical for `contrib/` code, but the fix is straightforward and addresses a real edge case (multi-line secrets) that users have occasionally reported. The patch looks well-crafted and motivated, though the lack of a test case means the fix's correctness relies entirely on the author's understanding of the Windows credential API and Git's credential protocol.
