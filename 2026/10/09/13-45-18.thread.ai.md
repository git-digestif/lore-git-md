Core problem or goal
Fix a platform-specific bug in the Windows credential helper (`contrib/credential/wincred/git-credential-wincred.c`) where multi-line secret blobs (e.g., credentials containing both a password and an OAuth refresh token) are parsed incorrectly due to unsafe string operations (`wcsncpy_s` with incorrect size, `wcstok_s`) that can cause buffer overreads, misinterpretation of newlines, and memory corruption. The goal is to replace fragile string handling with immutable wide-character-aware logic using `wmemchr` and helper functions for clarity and safety.

Key technical details
- Files touched: `contrib/credential/wincred/git-credential-wincred.c`
- Subsystem: Windows credential helper (platform-specific, `contrib/`)
- New behavior: Parses multi-line secrets immutably by scanning for `\r\n` or `\n` with `wmemchr`, splitting the blob into lines first, then processing key-value pairs only in lines after the first. Helper functions improve maintainability and auditability.
- Old behavior: Used `wcsncpy_s` and `wcstok_s`, risking buffer overreads, incorrect newline parsing, and memory corruption.
- On-disk format: unchanged
- Test coverage: none (typical for `contrib/` code)
- Wide-character handling: Consistent, using character counts for sizes and pointer arithmetic (e.g., `wmemchr` scans `wchar_t` strings correctly).
- New symbols: `write_credential_item` (helper for key-value pairs), `write_credential` (helper for full credential block).
