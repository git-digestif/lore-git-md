Core problem or goal
Fix a platform-specific bug in the Windows credential helper (`contrib/credential/wincred/git-credential-wincred.c`) where multi-line secret blobs (e.g., credentials containing both a password and an OAuth refresh token) are parsed incorrectly due to unsafe string operations (`wcsncpy_s` with incorrect size, `wcstok_s`) that can cause buffer overreads, misinterpretation of newlines, and memory corruption.

Current status
Under review (v2). Junio C Hamano’s feedback from v1 has been fully addressed: the commit message now follows Git’s standard format, the code has been refactored into helper functions (`write_credential_item`, `write_credential`) to reduce nesting and improve readability, and wide-character handling has been made consistent (using character counts rather than bytes for sizes and pointer arithmetic). The patch is now ready for final review and likely inclusion in `next`.

Key technical details
- Files touched: `contrib/credential/wincred/git-credential-wincred.c`
- Subsystem: Windows credential helper (platform-specific)
- New behavior: Parses multi-line secrets immutably using `wmemchr` to scan for `\r\n` or `\n`, splits the blob into lines first, then processes key-value pairs only in lines after the first. Helper functions improve maintainability and auditability.
- Old behavior: Used `wcsncpy_s` and `wcstok_s`, risking buffer overreads, incorrect newline parsing, and memory corruption.
- On-disk format: unchanged
- Test coverage: none (typical for `contrib/` code)
- Wide-character handling: Now consistent, using character counts for sizes and pointer arithmetic (e.g., `wmemchr` scans `wchar_t` strings correctly).
