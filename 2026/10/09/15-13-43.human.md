This is a small but user-visible consistency patch. Julia Evans updates the advice message shown during a merge conflict to recommend `git merge --continue` instead of `git commit`, aligning it with the advice already given for rebase, revert, and cherry-pick. The change is purely about improving the user experience by presenting a uniform command across all conflict-resolution workflows—`git merge --continue` and `git commit` are already documented as equivalent, so this does not alter behavior.

The patch touches `wt-status.c` to update the advice text and adjusts two test scripts (`t7060-wtstatus.sh` and `t7512-status-help.sh`) to reflect the new wording. The commit message clearly explains the motivation: `git merge --continue` was introduced in 2016 as a synonym for `git commit` during merges, but the advice text was never updated to match. This version (v3) fixes a minor cosmetic issue in the commit message formatting, ensuring the reference commit is correctly displayed using `git show -s --format=reference`.

The patch is ready for integration. Junio C Hamano and Phillip Wood have both approved it, and all feedback—both substantive (phrasing improvements) and surface-level (commit message polish)—has been addressed. The change is uncontroversial and expected to be queued in `next` or `master` soon. Translators will need to update the advice strings, but the change is minimal and should be straightforward.
