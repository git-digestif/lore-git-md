Core problem or goal
Fix a long-standing logic error in `match_push_refs()` that causes Git to silently accept duplicate destination refs when pushing to an empty remote, rather than rejecting them as it does when the remote already has refs. The bug stems from `match_explicit_refs()` passing the *value* of the remote ref list head (`dst`) to `match_explicit()` instead of its *address*, so later loop iterations fail to see destinations created by earlier refspecs.
