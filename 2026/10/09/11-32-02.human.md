This is a CI/build system patch, part of Patrick Steinhardt’s v2 series modernizing Git’s CI configurations. Specifically, this is patch 5/8, a straightforward refactoring that renames the `linux-TEST-vars` job to `linux-exotic` in both GitHub Actions and GitLab CI workflows, along with the corresponding case label in `ci/run-build-and-tests.sh`.

The change is purely cosmetic but improves clarity: the old name was awkwardly capitalized and didn’t convey that the job exercises Git with non-default, “exotic” options like `OPENSSL_SHA1_UNSAFE`, `GIT_TEST_SPLIT_INDEX`, and `GIT_TEST_FULL_IN_PACK_ARRAY`. The patch touches three files (`.github/workflows/main.yml`, `.gitlab-ci.yml`, and `ci/run-build-and-tests.sh`) with a net zero line change—just three one-line substitutions. No behavior or coverage is altered; this is purely about making the CI configuration easier to read and maintain.

The patch is uncontroversial and well-motivated. The commit message is concise and explains the rationale clearly. Since this is a mechanical rename with no functional impact, it’s unlikely to draw further discussion unless someone spots an overlooked reference to the old job name elsewhere in the codebase. It fits neatly into the broader series goal of reducing CI complexity without sacrificing coverage.
