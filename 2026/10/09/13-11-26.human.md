This is a small but user-visible documentation patch. Julia Evans updates the advice message shown during a merge conflict to suggest `` `git merge --continue` `` instead of `` `git commit` ``, bringing it in line with the advice already given for rebase, revert, and cherry-pick. The change affects the output of `` `git status` `` when in a conflicted merge state, updating both the "unmerged paths" and "all conflicts fixed" scenarios.

The patch is well-motivated and uncontroversial. `` `git merge --continue` `` has been a documented synonym for `` `git commit` `` during merges since 2016, but the advice text was never updated to reflect this. The change is purely about consistency—no behavior is altered. The commit message explains the rationale clearly, and the patch includes updated test coverage to verify the new wording.

This is the second iteration (v2) of the patch, incorporating a grammatical improvement suggested by Phillip Wood ("to conclude the merge" instead of "to conclude merge"). Junio C Hamano has already approved the change as "better late than never," and all substantive feedback has been addressed. The patch is ready for integration and is expected to land in `next` or `master` in the current cycle. Translators will need to update the advice strings, but the change is minimal and straightforward.
