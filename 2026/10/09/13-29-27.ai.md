This is a **security-focused follow-up** in the ongoing thread about Git’s SSH signing verification flaws. The email captures a private exchange between Christian Noé Ramos López and Phillip Wood, now made public to the mailing list for broader input.

Christian acknowledges Phillip’s earlier summary and clarifies a key technical point: while the GPG backend uses the signature’s creation time for `valid-before` checks, Git’s SSH backend relies on the committer date (which the signer controls). This means backdating the committer date bypasses `valid-before` for SSH signatures, whereas GPG signatures are rejected if the signature timestamp itself is backdated. Christian proposes updating the documentation to explicitly state that (1) the `valid-before` check uses the commit’s date, not the signature time, and (2) signature timestamps are not reliable evidence of when signing occurred. Phillip endorses this approach, noting that a valid signature alone doesn’t prove when the commit was signed.

On the revocation file issue, Christian highlights that making revocation file errors fatal (failing closed) is a behavior change, not just a fix, and agrees it’s the right trade-off. Phillip reiterates Patrick Steinhardt’s suggestion to use Git’s `:(optional)` pathname prefix to allow users an escape hatch if needed. Christian also commits to adding test coverage for `gpg.ssh.revocationFile`, which is currently untested.

The thread is now in the "design consensus" phase, with agreement on two actionable fixes: (1) document the `valid-before` behavior’s limitations, and (2) make revocation file errors fatal by default (with an optional override). The next step is a patch implementing these changes, including test cases. The discussion remains focused on security hardening, with no major disagreements—just implementation details like the `:(optional)` mechanism. This is a high-priority issue likely to land quickly once a patch is posted. Key subsystems affected: `gpg-interface.c`, `gpg-ssh.c`, and documentation for `gpg.ssh.allowedSignersFile` and `gpg.ssh.revocationFile`.
