This is a **licensing policy clarification** in the ongoing `sha1dc-accel` thread. Todd Zullinger responds to D. Ben Knoble’s question about how distributions should represent Git’s license when it bundles MIT-licensed code (the existing `sha1dc` collision-detection library and the proposed `sha1dc-accel` replacement).

Zullinger explains that Fedora’s Git package lists **all** licenses involved—BSD-3-Clause, GPL-2.0-only, GPL-2.0-or-later, LGPL-2.1-or-later, and MIT—rather than attempting to reduce them to a single “effective” license. He links to Fedora’s packaging guidelines, which explicitly reject the idea of an “effective license” and require listing every license that applies to any part of the package. The implication is that Gentoo’s GPL-2-only tag is an oversimplification that does not reflect the reality of mixed-license components in Git.

This message does not introduce new technical or policy objections; it simply provides concrete evidence that at least one major distribution (Fedora) already handles Git’s mixed licensing in a way that is consistent with Junio’s earlier confirmation that Git’s GPL-2-only stance is compatible with MIT-licensed code, provided the original license and copyright notices are preserved. The clarification helps resolve the licensing ambiguity Knoble raised, but it does not address the remaining **provenance question**—whether Sam Reis’s endorsement covers the *specific C implementation* submitted by Scott Chacon or merely the *idea* of porting the Rust work to Git. That distinction remains the sole unresolved blocker in the thread.
