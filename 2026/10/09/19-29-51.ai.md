This is the **13th patch in a 15-patch performance series** aimed at speeding up refspec matching in `git push`, particularly for large-scale deletion workflows. The series as a whole targets a **10–100x speedup** in scenarios where many deletions are pushed to servers with large refsets (e.g., 100k refs), and this patch extends the performance test script (`t/perf/p5516-push-delete-refspec.sh`) to measure `--force-with-lease` overhead.

The patch adds **new test rows** to the existing perf script, timing pushes that combine delete refspecs with one `--force-with-lease=<refname>:<expect>` per refspec. The commit message includes baseline timings (e.g., `0.12s` for 1 lease, `0.45s` for 100 leases) to establish a reference point for the speedup delivered in the **next patch (14/15)**. The implementation is straightforward: it generates refspecs and lease arguments dynamically using `test_seq` and `sed`, then measures the combined `git push --dry-run` invocation. No behavioral changes are introduced here—this is purely test infrastructure to quantify the impact of later optimizations.

The patch is **well-scoped and uncontroversial**, touching only the perf script and adding no new dependencies or edge cases. The commit message clearly states the purpose (measuring `--force-with-lease` paths) and provides concrete timings, which will help reviewers assess the effectiveness of the subsequent optimization. The test design—using `$(cat refspecs) $(cat leases)`—is idiomatic and avoids hardcoding values, making it easy to extend or modify later.
