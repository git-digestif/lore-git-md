This is a licensing clarification in the ongoing `sha1dc-accel` thread. Todd Zullinger, a Fedora packager, responds to D. Ben Knoble’s question about how distributions should label Git’s license when it bundles the MIT-licensed `sha1dc` (and now `sha1dc-accel`) code.

Zullinger explains that Fedora’s Git package already lists multiple licenses—BSD-3-Clause, GPL-2.0-only, GPL-2.0-or-later, LGPL-2.1-or-later, and MIT—reflecting the mixed-license reality. He links to Fedora’s packaging guidelines, which explicitly reject “effective license” analysis and require listing all licenses present in the source. His message is a factual data point rather than a technical or policy objection; it shows that at least one major distribution already handles the mixed-license case transparently.

For a busy reader, this confirms that the licensing ambiguity Knoble raised is not a blocker in practice—distributions can and do ship Git with multiple licenses listed. The thread’s remaining open question is still Junio’s request for Sam Reis to clarify whether his endorsement covers the specific C implementation, but Zullinger’s reply removes any urgency around distribution packaging concerns.
