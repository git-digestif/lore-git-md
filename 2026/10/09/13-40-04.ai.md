This is a user-facing message rewording patch targeting the `status` and `remote` subsystems. The patch addresses a long-standing confusion in `git status` output when a branch is set to track a remote branch that does not exist—either because the remote repository is empty (so the branch was never created) or because the branch was deleted on the remote. Currently, Git reports this as "the upstream is gone," which is misleading in the empty-repository case, and suggests an incorrect fix (`git branch --unset-upstream` when `git push` would resolve the issue).

The patch changes the message to "Your branch is set up to track 'origin/master', which does not exist" and conditionally suggests `git push` only when it would actually create the missing branch (e.g., not when `push.default` is `nothing` or `matching`, or when pushing to a different remote). The new wording is correct for both the "never created" and "deleted" cases, and the advice is more actionable. The patch also updates the corresponding message in `git checkout` and adds thorough test coverage for the new behavior, including edge cases like `push.default=matching` and `advice.statusHints=false`. Script-facing short formats (`git status -sb`, `git branch -vv`, `%(upstream:track)`) still show `[gone]` for compatibility.
