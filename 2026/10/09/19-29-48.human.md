This is a test modernization patch, part of a 15-patch series. It updates the `t5408-send-pack-stdin.sh` test script to reflect an upcoming behavioral change: duplicate ref updates (e.g., pushing two different source commits to the same destination ref) will soon be rejected on the client side rather than the server side.

The patch flips three existing tests from `test_expect_success` to `test_expect_failure` and updates their expected error messages from the old server-side rejection ("multiple updates for ref 'foo' not allowed") to the new client-side message ("dst ref refs/heads/foo receives from more than one src"). The test descriptions are also tweaked to remove outdated references to partial ref update ordering. A small fix for a missing `2>err` redirection is included as well.

The motivation is clear: the next patch in the series will move the duplicate-ref check from the server to the client, so these tests are being prepared to flip back to `test_expect_success` once that change lands. The patch itself is mechanical and well-scoped, touching only the test file and leaving the actual implementation change for a later commit. If you care about push behavior or test infrastructure, this is worth noting but not urgent until the follow-up patch arrives.
