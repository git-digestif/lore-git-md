This is the eighth patch in Jon Simons' 15-patch series to speed up refspec matching in `git push` when dealing with many deletions. The series targets a scalability bottleneck in large repositories, where pushing deletions to a server with 100k+ refs can take seconds due to inefficient linear traversals.

This patch focuses on **test coverage** for a specific edge case: duplicate ref updates. Currently, the only tests that exercise this scenario (in `t5408`) rely on the client *not* detecting duplicates when the remote is empty. The upcoming code changes (later in the series) will fix this by having the client reject duplicate destinations upfront, so these tests would break unless updated. The patch adds explicit tests for two distinct behaviors:
1. **`send-pack`'s handling of duplicate status reports** from the remote (a memory-leak fix from 2025).
2. **`receive-pack`'s rejection of multiple updates** for the same ref (a batched-update feature from 2025).

The new tests use `test-tool pkt-line` to craft raw protocol messages, avoiding reliance on client-side logic. This ensures the tests remain valid even after the client-side duplicate detection is added. The patch is purely preparatory—it doesn’t change any production code—but it’s critical for the series’ "test-before-code" discipline. The commit message clearly explains the motivation and ties the tests to specific historical commits, making the context easy to follow.

This looks like a well-crafted, low-risk addition. The tests are narrowly scoped and directly address a gap that would otherwise block later patches.
