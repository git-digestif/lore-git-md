Subject: [RFC PATCH] status,remote: improve advice when upstream branch does not exist
Series version: v1 (initial)
Originating author: Elia Pinto
Thread type: RFC patch series

Core problem or goal
Clarify the user-facing message in `git status` (and `git checkout`) when a local branch tracks a remote branch that does not exist—either because the remote repository is empty or the branch was deleted. The current message (“the upstream is gone”) is misleading and suggests an incorrect fix (`git branch --unset-upstream` when `git push` may be the right action).

Current status
Under review; v1 posted as an RFC. No prior versions.

Key technical details
- Subsystems: `status`, `remote`
- Files touched: `remote.c`, test suite (`t/t6040-tracking-info.sh`, `t/t7512-status-help.sh`)
- New behavior: message changes from “the upstream is gone” to “Your branch is set up to track 'origin/master', which does not exist” and conditionally suggests `git push` only when it would actually create the branch (skips when `push.default` is `nothing` or `matching`, or when pushing to a different remote).
- Script-facing formats (`git status -sb`, `git branch -vv`, `%(upstream:track)`) still show `[gone]` for backward compatibility.
- No on-disk format changes; no new symbols.

Open questions and loose ends
- Is the new phrasing acceptable?
- Should this be categorized under `status:` or `remote:` in the commit subject?
