This is a bug report about `git svn` failing to clone a local Subversion repository on Windows.

The user created a local SVN repository, made some commits, then tried to migrate it to Git using `git svn clone` with a `file:///` URL pointing to the SVN repository path. Instead of cloning successfully, Git reports "Unable to connect to a repository at URL" and "Unable to open repository" at line 148 of `Git/SVN.pm`. The empty Git repository directory is created, but no files are transferred from SVN.

The report includes detailed reproduction steps, expected vs. actual behavior, and system information (Git 2.51.0 on Windows 10, using mingw64). The user notes this is a purely local setup with no network involvement. No prior discussion or patches are mentioned in the thread so far—this appears to be the initial report. The issue looks legitimate and specific to the Windows `file:///` URL handling in `git svn`.
