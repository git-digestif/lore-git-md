This is a **performance-focused feature series** targeting the client-side refspec matching logic in `git push`. The author, Jon Simons, addresses a scalability bottleneck when pushing many branch deletions to a server with a large number of refs (e.g., 100k). The series achieves **10–100x speedups** in benchmarked scenarios by replacing linear ref traversals with `strmap` lookups and fixing long-standing behavioral quirks in `refname_match()`.

The cover letter clearly motivates the work with before/after timings: a `git push --dry-run` of 100 delete refspecs to a 100k-ref server drops from **2.5–8.9s to 0.15–0.19s**. The series is structured to introduce failing tests for behavioral changes and bugfixes *before* the code changes that resolve them, a disciplined approach that eases review. Key technical changes include:
- Removing `mkpath()` from `refname_match()` (commit 5), which stops stripping leading `./` from refnames (a subtle behavior change with performance implications).
- Converting three linear traversals in `remote.c` to `strmap` lookups: `check_push_refs()` (commit 6), `match_explicit_refs()` (commit 12), and `apply_push_cas()` (commit 15).
- Fixing a long-standing bug where duplicate destinations (e.g., pushing two refspecs to the same new branch) were incorrectly accepted client-side when the remote was empty (commits 7–11).

The series touches **`refs.c`** and **`remote.c`**, with new tests in **`t5516`**, **`t5408`**, **`t5410`**, and **`t5510`**, plus a new perf script (**`t/perf/p5516-push-delete-refspec.sh`**). The commit messages are detailed, and the benchmark table in the cover letter provides granular evidence of the improvements. The work appears well-scoped and thoroughly tested, addressing both correctness and performance in a high-impact area (large-repository workflows). No controversial design choices are evident, though the `mkpath()` removal might require careful review to ensure no regressions in edge-case refspec matching. The series is **under review** and not yet in any integration branch.
