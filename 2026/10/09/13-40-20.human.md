This is a brief but clarifying follow-up in the ongoing discussion about extending `` `git branch --delete-merged` `` to detect squash-merged and rebase-merged branches. Phillip Wood acknowledges Harald Nordgren’s observation that even Junio-signed-off branches—semantically merged into `master`—are not cleaned up by the current logic if the merge was done via patch-based workflows (the mailing-list norm). He notes that this case differs subtly from squash merges: instead of looking for a single upstream commit that contains all branch changes, Git would need to verify that each individual commit from the branch appears upstream. The point reinforces the broader motivation for the feature—real-world workflows leave behind cluttered branches that users expect to be deletable—and hints at a possible future extension to handle patch-based merges, though no design or implementation is proposed here. The exchange remains focused on refining the understanding of the problem rather than advancing the patch itself.
