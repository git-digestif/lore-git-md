This thread is about a bugfix for the Windows credential helper in Git’s `contrib/` directory, where multi-line secret blobs (like credentials containing both a password and an OAuth token) are parsed incorrectly due to unsafe string operations. The patch, submitted by Marc Becker, aims to replace problematic functions like `wcsncpy_s` and `wcstok_s` with safer parsing logic using `wmemchr` to handle newlines properly.

Junio C Hamano has reviewed the patch and raised substantive concerns about both the commit message and the code. He critiqued the commit message for lacking clarity on why the original code was unsafe and what symptoms it caused, and he suggested rewriting it in Git’s standard format. On the code side, he flagged deep nesting in the loop, potential issues with wide-character handling (e.g., `wmemchr` and pointer arithmetic on `LPCWSTR`), and the absence of test coverage—common for `contrib/` code but still a risk. The discussion is now focused on correctness and maintainability, and the author has yet to respond to Junio’s feedback. This means the patch will likely need at least one more revision before it’s ready to merge. For now, it remains under active review with open technical questions.
