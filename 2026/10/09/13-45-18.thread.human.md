This thread is about a bugfix for the Windows credential helper in Git’s `contrib/` directory. The patch, originally submitted by Marc Becker, addresses a long-standing issue where multi-line secrets (like passwords followed by OAuth refresh tokens) were misparsed due to unsafe string operations in the credential blob parser. The initial version received substantive feedback from Junio C Hamano, focusing on commit message clarity, code readability, and correctness in handling wide-character strings.

Marc has now sent a v2 patch that fully addresses Junio’s concerns. The revised version refactors the parsing logic into two helper functions—`write_credential_item()` and `write_credential()`—to reduce nesting and improve maintainability. The implementation now uses `wmemchr` to scan for newlines immutably, avoiding buffer overreads and ensuring correct parsing of wide-character strings. The commit message has also been rewritten to clearly explain the root causes (invalid size checks, missing line advancement, and CRLF handling bugs) and the symptoms they produced (memory corruption, misparsed tokens). The changes are purely structural, with no functional logic altered.

The patch is now ready for final review and is likely to be included in `next`. While the `contrib/` directory typically lacks test coverage, the fix is well-motivated and addresses a real edge case that users have encountered. No further revisions are expected unless Junio raises additional concerns.
