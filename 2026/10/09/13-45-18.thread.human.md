This thread is a small but important platform-specific fix for the Windows credential helper (`contrib/credential/wincred/git-credential-wincred.c`). Marc Becker identified a long-standing bug in how the helper parses multi-line secret blobs—such as credentials containing both a password and an OAuth refresh token—where the current code could misinterpret or overread buffers due to incorrect use of `wcsncpy_s` and `wcstok_s`. The fix replaces these with a safer approach using `wmemchr` to scan for line endings directly in the original buffer, avoiding modifications to the input and properly handling both `\r\n` and `\n` line endings.

The patch is standalone, confined to the Windows-specific helper, and doesn’t affect other platforms. While no tests are included (typical for `contrib/` code), the changes are clear and address a real edge case that users have reported. The fix is well-motivated and appears technically sound, though its correctness relies on the author’s understanding of the Windows credential API and Git’s credential protocol. There’s been no review activity yet, so the patch is still awaiting feedback from Windows-savvy contributors like Johannes Schindelin or Johannes Sixt. If it lands, it should resolve a subtle but persistent issue for Windows users.
