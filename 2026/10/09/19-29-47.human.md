This is a test patch, part 9 of a 15-patch series. It reinstates assertions about the order in which `git send-pack` sends refspecs when given both command-line arguments and `--stdin` input.

The patch addresses a gap created by a 2025 change (`9d2962a7c4`) that made the server reject multiple updates to the same ref, which previously allowed the test to observe ordering by seeing which update succeeded. Now that such pushes fail outright, the original test no longer verifies the ordering. Jon Simons adds two new tests that explicitly check the order of refs pushed to distinct destinations, using a `pre-receive` hook to record the refs as they arrive.

The tests are straightforward: one confirms that command-line refspecs are sent in the order given, and the other confirms that `--stdin` refspecs follow command-line ones. The patch is narrowly scoped to the test file `t/t5408-send-pack-stdin.sh` and looks well-crafted, with clear commit message and test logic. If the series' goal is to shore up test coverage around `send-pack` ordering, this patch delivers.
