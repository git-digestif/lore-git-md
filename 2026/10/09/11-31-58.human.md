This is a test fix, part of an 8-patch series from Patrick Steinhardt. The series appears to be CI housekeeping—cleaning up test prerequisites and job configurations.

The specific patch addresses a latent issue in `t5004-archive-corner-cases.sh`. The test in question verifies Git’s ability to handle ZIP archives containing objects larger than 4GB, but it only makes sense in SHA-1 repositories because the test data itself consists of SHA-1 objects. Currently, the test is skipped in most CI jobs due to its expensive prerequisites (64-bit `long`, unzip with 64-bit support, and `EXPENSIVE` enabled). However, a Fedora-based CI job *does* run it, and it was silently broken because a typo disabled the breaking changes that would have exposed the SHA-256 incompatibility. The next patch in the series fixes that typo, which would then cause the test to fail in SHA-256 repositories.

The fix is minimal: adding the `SHA1` prerequisite to the test ensures it only runs in SHA-1 repositories, preventing the failure when the Fedora job is corrected. The change is straightforward and well-motivated, addressing a real issue before it surfaces. No controversy or design questions are raised here—just a small, targeted fix to keep the test suite robust.
