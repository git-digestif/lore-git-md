This is a bugfix patch in a 15-part series, the eleventh installment. It plugs a long-standing logic hole in Git’s remote-ref matching: when a remote has no existing refs, duplicate destination refs (e.g., `git push remote.git A:foo B:foo`) were silently accepted instead of being rejected. The patch changes `match_explicit_refs()` to pass the remote refs list by pointer so that each refspec iteration sees destinations added by earlier iterations. With the fix, four failing tests in `t5408` and `t5516` now pass and are flipped to `test_expect_success`. The commit message gives a clear explanation of the bug’s origin (dating back to 2005) and the one-line mechanical fix. The patch looks well-motivated and well-tested; it should be uncontroversial.
