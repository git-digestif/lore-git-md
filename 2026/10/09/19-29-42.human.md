This is a test performance patch, part of a 15-patch series. Patch 4/15 adds a new performance test (`p5516`) that measures how long it takes for a client to match explicit delete refspecs during `git push --dry-run` when the server advertises a large number of refs (100,000 branches).

The test sets up two client scenarios: an empty client with no local refs, and a mirror client with a full copy of the server’s refs. Each client pushes 1, 10, or 100 delete refspecs, and the test records the time spent matching refspecs without actually transferring objects or updating refs. The baseline numbers show that matching time scales with the number of refspecs, especially for the mirror client, which takes nearly 7 seconds for 100 refspecs.

The commit message explains that this test is meant to demonstrate speedups in later patches, suggesting the series aims to optimize refspec matching. The test itself is well-structured, using `--dry-run` to isolate the matching phase and avoid side effects, and it includes clear setup steps for reproducibility.

This patch is purely preparatory—it doesn’t change any behavior but establishes a baseline for measuring improvements. If you care about `git push` performance in repositories with many refs, the later patches in this series will likely be of interest. For now, this is just the groundwork.
