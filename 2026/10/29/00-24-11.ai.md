This is the second patch in Justin Tobler’s four-patch **bugfix series (v2)** targeting the ODB transaction layer. It refactors the loose-object index parsing logic into a reusable helper, `loose_object_map_read()`, to enable atomic writes in a later patch (4/4).

The patch extracts the core parsing logic from `loose_object_map_load()` into a standalone function that takes an explicit `loose_object_map` and `oidtree` cache as arguments, rather than relying on the `odb_source_loose` struct. This decoupling allows the temporary object directory migration code (in `tmp-objdir.c`) to parse its own loose-object-idx file without attaching it to an object source. The change also tightens error handling: previously, all file-open errors (e.g., permission issues) were silently ignored; now, only `ENOENT` (file not found) is treated as success, while other errors propagate to the caller. This aligns with the series’ goal of making the loose-object-idx migration more robust.

Key technical details:
- **New function**: `loose_object_map_read()` in `loose.c`, declared in `loose.h`.
- **Behavior change**: `repo_read_loose_object_map()` now fails early if any object source’s loose-object-idx file is unreadable (previously, it continued with subsequent sources).
- **Files touched**: Only `loose.c`; the patch is a pure refactoring with no functional changes to the loose-object-idx on-disk format or migration logic.
- **Test coverage**: No new tests here, but the regression test in 4/4 (`t/t1016-compatObjectFormat.sh`) will verify the refactored logic works end-to-end.

The patch is well-motivated and cleanly structured, addressing Patrick Steinhardt’s feedback about code reuse and error handling. It sets the stage for the atomic-write fix in 4/4 by making the parsing logic reusable. The only minor trade-off is the stricter error handling, which could break workflows where loose-object-idx files are temporarily unreadable (e.g., due to filesystem permissions), but this is a reasonable correctness trade-off given the series’ focus on ODB stability. The patch is **ready for review** and should be uncontroversial.
