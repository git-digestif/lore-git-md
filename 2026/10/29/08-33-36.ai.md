This is a build system patch addressing ccache integration for Git’s precompiled header feature. It is the second iteration of a standalone patch that enables ccache to cache objects built with the precompiled header by setting two ccache "sloppiness" flags (`pch_defines`, `time_macros`).

The v2 revision moves the `CCACHE_SLOPPINESS` export from target-specific rules into the `ifndef NO_PRECOMPILED_HEADER` block, addressing the Makefile semantics question raised in the first round: whether target-specific exports propagate to recipe processes. This change ensures the variable is set globally for all compilations that use the precompiled header, not just the header itself or its direct users. The patch remains minimal (one line added to the Makefile) and continues to leave the Meson build system unmodified, as the author and reviewers have accepted that ccache sloppiness for PCH should ideally be handled upstream in Meson rather than in Git’s build scripts.

The performance claims are unchanged: a 3× speedup for warm-cache rebuilds (from ~100s to <30s) and a 6× speedup when switching between branches with a warm cache, though the first build of each branch is ~25% slower while ccache fills its cache. The edge case with Clang — where switching branches that modify headers included by the precompiled header still misses the cache due to mtime recording in the PCH — remains unresolved but is acknowledged as a limitation of the compiler, not the patch.

Key technical details for follow-up discussion include the variable `CCACHE_SLOPPINESS` and its values `pch_defines` and `time_macros`, the related commit 8d3a673147 (precompiled header introduction), and the unchanged on-disk format. The patch touches only the Makefile and has no dedicated test coverage, consistent with most build system changes. The unresolved loose end is the cross-build-system inconsistency: ccache users on Meson will not benefit from this optimization until the feature is implemented upstream in Meson itself. Harald Nordgren has indicated he may pursue that separately.
