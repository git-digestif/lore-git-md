Subject: [PATCH v6] diff-files: convert to parse-options API
Series version: v6 (standalone patch, now withdrawn)
Originating author: Edson
Thread type: patch series (single-patch)

Core problem or goal
Refactor the `git diff-files` built-in command to replace ad-hoc option parsing in `cmd_diff_files()` with Git’s standard `parse-options` API. The goal was to improve consistency, help text generation, and shell completion support while preserving existing behavior for `--base`, `--ours`, `--theirs`, and `-q`.

Current status
Withdrawn by the author. The sixth iteration of the patch was posted but not queued in any integration branch (`seen`, `next`, or `master`). After substantive technical feedback from Junio C Hamano, the author decided to drop the patch rather than address the open concerns. No maintainer decision or merge status was recorded; the thread is now closed.

Key technical details
- File touched: `builtin/diff-files.c`
- New symbols: none (would have used existing `parse-options` macros: `OPT_SET_INT_F`, `OPT_BIT`, `PARSE_OPT_NONEG`)
- Old behavior preserved: `--base`/`--ours`/`--theirs` set `rev.max_count` to 1/2/3; `-q` sets `DIFF_SILENT_ON_REMOVED`
- On-disk format: unchanged
- Test coverage: none added in this patch; existing tests for `git diff-files` were expected to verify behavior
- Implementation details: 19 lines of manual `strcmp()`-based parsing were to be replaced with 20 lines of `parse-options` boilerplate; usage message updated to `usage_with_options()`, but this introduced a regression by omitting `COMMON_DIFF_OPTIONS_HELP`

Open questions and loose ends
- **Help text regression**: The patch dropped `COMMON_DIFF_OPTIONS_HELP` from the usage message, removing standard diff options (e.g., `-p`, `--stat`, `-z`) from `git diff-files -h`. Junio suggested embedding the macro in an `OPT_GROUP()` entry but questioned whether this was worthwhile for a plumbing command. This issue was not addressed in the withdrawal.
- **Refactoring value**: Junio expressed skepticism about the trade-off between the clarity of the existing `strcmp()`-based parsing and the boilerplate of `parse-options` for a low-level command. The author agreed that the benefits (e.g., improved maintainability, reduced bug risk) did not justify the change for `diff-files`.
- **Plumbing vs. porcelain**: The discussion reinforced the project’s preference for preserving the minimalist, functional design of plumbing commands, even at the cost of consistency with porcelain commands. Future refactoring efforts may need to focus on higher-value targets.

Participant positions
- **Junio C Hamano**: Substantive technical review identifying two open issues: (1) help text regression and (2) questionable value of the refactoring for a plumbing command. No `Reviewed-by` or `Acked-by` was given; the feedback was decisive in the author’s decision to withdraw.
- **Edson**: Author; acknowledged Junio’s concerns and withdrew the patch, agreeing that the trade-off was not justified for `diff-files`. Prior iterations addressed procedural issues (threading fixes in v3/v4) but not the design-level questions raised in v6.
