This is a **bugfix** for a regression in `git grep --recurse-submodules` when searching a tree object. The issue was introduced in Git 2.56.0 by commit `93cd344e34` ("builtin/grep: stop registering submodule ODB as source", 2026-09-11). The patch causes `git grep` to fail with `fatal: unable to read tree` when it encounters a directory inside a submodule, breaking recursive searches of submodule trees.

The problem stems from a mismatch in object database access: `grep_tree()` now tries to read submodule directory trees from the *superproject's* ODB (`the_repository->objects`) instead of the submodule's ODB, which no longer works after the ODB registration was removed. The working-tree form of the command (`git grep --recurse-submodules <pattern>`) is unaffected, as is searching submodules without directories. The author provides a minimal reproduction script and confirms the regression bisects to the problematic commit. Their proposed workaround—reading from `repo->objects` instead of `the_repository->objects`—restores expected behavior but hasn’t been tested against the full test suite.

The report is thorough: it includes exact error messages, commit OIDs, line numbers in `builtin/grep.c`, and system details. The regression affects CI environments (noted in GitHub’s ubuntu-22.04 runner image) and appears to be present in all current integration branches (`master`, `next`, `seen`). No prior discussion or thread context is referenced, suggesting this is the first report of the issue. The fix will likely involve adjusting how `grep_tree()` resolves submodule objects, possibly by passing the correct repository context or reworking the ODB lookup logic.
