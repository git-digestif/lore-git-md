This is the first patch in a four-part bugfix series that is now in `seen`. It addresses a critical reliability issue in the loose-object index ("loose-object-idx") locking mechanism.

The patch replaces the existing indefinite lock timeout (`-1`) with a finite 1000-millisecond timeout (`LOOSE_OBJECT_IDX_LOCK_TIMEOUT_MS`). This change prevents Git from hanging indefinitely if a process crashes while holding the lock, leaving behind a stale lockfile. The 1000ms value matches the default timeout used elsewhere in Git (e.g., `core.packedRefsTimeout`) and is intended to balance concurrency with robustness.

The fix is minimal and surgical: it introduces a single `#define` and updates two call sites in `loose.c` where `repo_hold_lock_file_for_update_timeout()` is invoked. The change is uncontroversial and has already been approved by Patrick Steinhardt, who raised the original concern about indefinite locking. This patch is effectively ready for integration and sets the stage for the atomic-write improvements in later patches.
