This is the final patch in Patrick Steinhardt’s 12-part refactoring series that modernizes `git rerere`’s subcommand handling. The series has been under review since June 2025 and is now fully aligned with Junio C Hamano’s feedback; this patch completes the work by adding proper usage strings to each subcommand in both the man page and the code.

The patch updates `Documentation/git-rerere.adoc` to replace the single monolithic synopsis with seven distinct usage lines—one for the default `git rerere [--[no-]rerere-autoupdate]` and one for each of the six subcommands (`clear`, `diff`, `forget <pathspec>...`, `gc`, `remaining`, and `status`). In `builtin/rerere.c`, it defines seven usage macros (`RERERE_USAGE`, `RERERE_CLEAR_USAGE`, etc.), adds a per-subcommand `usage[]` array to every `cmd_rerere_*()` function, and updates the top-level `rerere_usage[]` array to include all seven variants. The result is that `git rerere -h` and `git rerere <subcommand> -h` now show the correct, minimal syntax for each operation.

No behavior changes or new options are introduced; the patch is purely about documentation and help-text correctness. The series as a whole is now ready for integration—all prior feedback has been addressed, the code is clean, and the man page is clearer for users.
