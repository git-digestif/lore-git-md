This is the second patch in Patrick Steinhardt’s 12-part refactoring series converting `git rerere` to use Git’s standard `OPT_SUBCOMMAND()` mechanism. The patch replaces the old `#define` constants for rerere flags (`RERERE_AUTOUPDATE`, `RERERE_NOAUTOUPDATE`, `RERERE_READONLY`, `RERERE_NOWAIT`) with a proper `enum rerere_flags`, bringing the code in line with Git’s modern coding guidelines. Each flag now has a clear, documented purpose in the header file, and all function signatures in `rerere.c` and `rerere.h` are updated to use the new enum type.

The change is purely mechanical and internal: no behavior changes, no new CLI options, and no on-disk format changes. The patch touches only `rerere.c` and `rerere.h`, updating function signatures and adding documentation for the four flags. The `RERERE_NOWAIT` flag’s existing comment — which describes its immediate-failure behavior when `MERGE_RR.lock` is taken — is confirmed correct and retained verbatim.

This patch addresses Junio C Hamano’s feedback from v1, where he requested full documentation of all four flags in the enum. The updated header now includes a clear explanation of each flag’s purpose, making the code more maintainable and self-documenting. The patch is uncontested and ready for integration as part of the larger series, which is now fully aligned with Junio’s review comments.
