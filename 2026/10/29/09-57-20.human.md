This is the penultimate patch in Patrick Steinhardt’s 12-part refactoring series that modernizes `git rerere`’s subcommand handling. The series replaces the command’s custom subcommand-parsing logic with Git’s standard `OPT_SUBCOMMAND()` mechanism, bringing it in line with other multi-subcommand built-ins like `git notes` and `git maintenance`. This patch (11/12) does the core conversion: it replaces the hand-rolled `if (!strcmp(...))` ladder with an `OPT_SUBCOMMAND()` table, eliminating the last vestige of the old parsing logic.

The patch introduces a new `cmd_rerere_perform()` function to serve as the fallback when no subcommand is given, preserving the existing behavior of defaulting to the recording-and-reusing action. The function parses the `--[no-]rerere-autoupdate` flag and passes the appropriate `RERERE_AUTOUPDATE` or `RERERE_NOAUTOUPDATE` flag to `rerere()`. The `OPT_SUBCOMMAND()` table lists all six subcommands ("clear", "diff", "forget", "gc", "remaining", "status") and their corresponding handler functions. The patch also removes the now-redundant global `--[no-]rerere-autoupdate` flag from the top-level parser, which was previously accepted but ignored for all subcommands except the default action.

This change is a clean, mechanical refactoring with no behavior changes beyond the intentional removal of the misleading global flag. The commit message acknowledges the backwards-incompatible change but frames it as a bug fix, since the flag was never respected for subcommands other than the default. The patch is uncontested and ready for integration; all prior feedback from Junio C Hamano has been addressed in earlier patches. The final patch in the series (12/12) will add per-subcommand usage strings to the man page and to each subcommand function, completing the modernization.
