This is a **tested review** of Harald Nordgren’s v4 series that adds `--delete-integrated` to `git branch` for detecting squash-merged and rebase-merged branches. Jasper Mayone confirms the series behaves as documented in his test suite: `--delete-merged` preserves its strict tip-reachability behavior (including Junio’s false-positive case), while `--delete-integrated` correctly deletes squash merges, GitHub-style squashes, rebase merges, and even cases where upstream modified the same file before squashing. The review is substantive and tested—Jasper built the code, ran the test suite (`t3200-branch.sh`), and exercised both flags on a variety of real-world scenarios (renames, reverts, partial landings, net-zero diffs, and the “npm update” scenario).

Key observations from the review:
- **Correctness**: The output format (`Deleted branch topic (was 1a2b3c4, landed as 9f8e7d6)`) consistently names the correct landing commit. The series keeps branches whose work only partly landed, cherry-picks with differently resolved conflicts, and branches with empty or net-zero diffs—all expected behaviors.
- **Safety**: The split between `--delete-merged` (strict) and `--delete-integrated` (change-based) is working as designed; the false-positive case (another author independently implementing the same change) is preserved by `--delete-merged` and opt-in via `--delete-integrated`.
- **Usability nits**: Three small issues: `--delete-integrated` is missing from `git branch -h` usage lines, the error message for combining both flags is overly verbose, and the cover letter still uses outdated flag names (`--squashed`, `--delete-irrelevant`). A branch checked out in a worktree is still skipped silently, which Jasper previously suggested should emit a message like `"Skipping 'topic' (checked out in <path>)"`.
- **Tested-by**: Jasper’s `Tested-by` trailer is explicit, and the review depth is **tested** (built, run, exercised on real cases).

The review does not revisit the open questions from the thread (author-check mitigation, patch IDs, or `git range-diff` trade-offs), but it confirms the current implementation is functionally sound and ready for integration once the minor usability nits are addressed. The **author-check mitigation** remains the only major technical gap, but Jasper’s testing shows the current algorithm is already robust for most workflows.
