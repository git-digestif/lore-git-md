This is the **final version (v3) of a bugfix patch series** that was previously merged to `seen`. The series fixes a critical flaw in the object database (ODB) transaction layer where temporary object directory migration fails when Git is configured with a compatibility hash (e.g., SHA-1/SHA-256 interop) and batch fsync of loose objects is enabled. The core issue is that the migration logic does not correctly merge the "loose-object-idx" file (a mapping between objects and their compatibility hashes) when a preexisting index exists in the primary object directory, leading to ODB transaction failures and potential data loss.

The v3 series is functionally identical to v2, which already addressed all blocking concerns raised by Patrick Steinhardt, including atomicity (replacing append-under-lock with temp-file-then-rename) and locking (introducing a finite 1000ms timeout). The only changes in v3 are **minor optimizations and documentation improvements**: (1) reading the source loose-object-idx file (`src`) outside the lock to reduce contention, and (2) adding a clarifying comment to `loose_object_idx_merge()` in `loose.h`. The series remains split into four patches: locking timeout (1/4), parsing refactor (2/4), writing refactor (3/4), and the core fix (4/4). The regression test (`t/t1016-compatObjectFormat.sh`) verifies that all entries from both temporary and primary indices are preserved after migration.

Key technical details include new functions (`loose_object_map_read()`, `loose_object_map_write()`, `loose_object_idx_merge()`), a new constant (`LOOSE_OBJECT_IDX_LOCK_TIMEOUT_MS`), and stricter error handling in `repo_read_loose_object_map()`. The series touches `tmp-objdir.c`, `loose.c`, and `loose.h`, and is part of the broader ODB abstraction effort led by Patrick Steinhardt. While the fix is robust for the immediate issue, systemic design flaws in the loose-object-idx mechanism (unsorted files, no deduplication/pruning) remain deferred. Justin Tobler has also noted a minor post-merge cleanup (removing a leftover declaration in `loose.h`) that will follow separately.

This is a **high-priority fix for ODB stability**, targeting users with compatibility-hash + batch-fsync enabled. The v3 series is now **ready for integration** with no outstanding technical concerns. The changes since v2 are purely cosmetic, focusing on clarity and performance micro-optimizations.
