Thread identity
Subject: redesigning signal handling in threaded Git code to fix sigchain race
Series version: not yet posted (future v2)
Originating author: ian4hu
Thread type: design discussion / RFC

Core problem or goal
Fix a race condition in Git’s `sigchain` subsystem where concurrent calls to `sigchain_pop()` for the same signal can corrupt the signal handler stack. The redesign blocks common signals (SIGINT, SIGHUP, SIGTERM, SIGQUIT, SIGPIPE) during thread creation to prevent worker threads from inheriting the main thread’s signal handlers, then restores them before joining threads. The blocking is done once per spawn loop rather than per-thread, using a guard pattern.

Current status
Design proposal stage; prior patch series dropped. Phillip Wood has endorsed the redesign, agreeing that all signals (including SIGPIPE) should be blocked during thread creation so that only the main thread handles signals, and approving the guard-pattern implementation. Oswald Buddenhagen has joined to clarify that SIGPIPE is inherently thread-directed, requiring separate reasoning even if the practical outcome (blocking it during thread creation) remains unchanged. Awaiting feedback from Jeff King (Peff) and Junio before posting v2.

Key technical details
- Subsystem: `sigchain` (signal handler stack management)
- Targeted thread pools: `preload_index()`, `index-pack`, `pack-objects`, `grep`, `name-hash`, read-cache entry loader
- Excluded threads: `fsmonitor--daemon`, `simple-ipc` (distinct lifecycle)
- Mechanism: block signals during thread creation using `sigaction` with `sa_mask = sigfillset()` to prevent handler interruption
- Guard pattern: block once per spawn loop, not per-thread
- Signals blocked: SIGINT, SIGHUP, SIGTERM, SIGQUIT, SIGPIPE
- Limitation: threads created by external libraries (e.g., libcurl’s threaded resolver) cannot be protected; will be documented in cover letter
- SIGPIPE distinction: inherently thread-directed, so blocking rationale must acknowledge this property even if the implementation does not change
