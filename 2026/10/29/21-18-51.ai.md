This is the **third patch in Justin Tobler’s four-patch bugfix series** (v2) targeting a critical ODB transaction layer bug. The patch refactors loose-object index writing logic into a reusable helper, `loose_object_map_write()`, to enable atomic migration of the "loose-object-idx" file in the final patch (4/4). This is a **clean refactoring with no behavior change**—existing callers (`repo_write_loose_object_map()`) are updated to use the new helper, which takes a file descriptor (from a locked lockfile) and a `loose_object_map` struct.

The email is a **reply to Patrick Steinhardt’s observational review** of the patch. Patrick noted the asymmetry between this patch’s file-descriptor-based interface and the path-based interface in the preceding patch (which refactored reading logic). Justin confirms the design choice: the file descriptor is used because it is already available after locking the file (via `hold_lock_file_for_update()`), and locking is intentionally left to the caller to ensure a consistent view of the preexisting index. He plans to clarify this in the next version’s commit message.

- **Design rationale**: The helper is designed for reuse in migration code (patch 4/4), where the file descriptor is already locked. Locking is not handled internally to avoid race conditions when reading preexisting indices.
