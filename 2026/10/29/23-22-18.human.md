This is the second patch in a four-part bugfix series that was recently merged to `seen`. It refactors the loose-object index parsing logic to prepare for the core fix in patch 4/4.

The patch extracts the parsing logic from `loose_object_map_load()` into a new helper function, `loose_object_map_read()`, which can operate on any provided map and cache rather than being tied to an `odb_source_loose` struct. This decoupling is necessary because the upcoming migration fix (patch 4/4) needs to parse a loose-object-idx file from a temporary object directory and merge its entries into the primary object directory’s map—something the original code couldn’t do without this refactor.

The patch also tightens error handling: while `ENOENT` (file not found) is still treated as success (since loose-object-idx files are optional), other file-open errors now propagate upward instead of being silently ignored. This change makes `repo_read_loose_object_map()` fail early if any object source’s loose-object-idx file is unreadable, rather than continuing with subsequent sources. The commit message notes this as a deliberate correctness trade-off.

No behavior changes are introduced—this is purely a refactoring to enable the later migration fix. The patch is uncontroversial and was explicitly noted as ready for integration in the thread summary. It touches only `loose.c` and is part of the broader ODB abstraction effort led by Patrick Steinhardt.
