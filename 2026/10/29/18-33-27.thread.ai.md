Core problem or goal: convert `git check-ref-format` from manual option parsing to the `parse-options` API to eliminate duplicated argument-handling logic, align the command with other Git built-ins, and preserve all existing functionality (normalization, branch-name support, refname validation).

Current status: under review; v1 posted. Junio C Hamano has raised substantive concerns requiring a revision. No merge status reported.

Key technical details: file `builtin/check-ref-format.c` modified; replaces hand-rolled `argv` loop with `struct option` array and `parse_options()` call; usage strings split into array for the API; positional argument check updated to match API convention. Junio identified the following issues: (1) two nearly identical usage strings (`builtin_check_ref_format_usage` and `builtin_check_ref_format_usages`) with confusing names and unclear synchronization; (2) the deprecated `--print` option is not marked as hidden (`PARSE_OPT_HIDDEN`), exposing it in help output; (3) silent acceptance of negated options (`--no-print`, `--no-normalize`) that were not supported by the original manual parsing, risking unintended behavior; (4) retention of `show_usage_if_asked()`, which intercepts `-h` and prevents `parse-options` from generating standard help output, defeating a primary benefit of the API.
