This is the second patch in Patrick Steinhardt’s v2 series modernizing `git rerere`’s subcommand handling. It converts the four existing `#define` flags (`RERERE_AUTOUPDATE`, `RERERE_NOAUTOUPDATE`, `RERERE_READONLY`, `RERERE_NOWAIT`) into an `enum rerere_flags` and updates all function signatures in `rerere.h` and `rerere.c` to use the new type. The patch also adds full documentation for each flag in the enum, addressing Junio C Hamano’s feedback from v1 that the `RERERE_NOWAIT` comment was correct but the enum should document all four values for clarity.

The change is purely mechanical: no behavior is altered, and the numeric values of the flags remain identical. The patch touches only `rerere.c` and `rerere.h`, updating the signatures of `rerere_cache_setup()`, `rerere()`, and `rerere_gc()` to accept `enum rerere_flags` instead of `int`. The enum’s documentation now explicitly describes the purpose of each flag, including the immediate-failure semantics of `RERERE_NOWAIT` when `MERGE_RR.lock` is held.

This patch is uncontested and ready for integration. It is a low-risk, guideline-aligned refactoring that brings `git rerere` in line with Git’s modern coding conventions. The only follow-up action is Junio’s final sign-off, which is expected to be routine given the alignment with his feedback. The patch is part of a larger series that replaces `git rerere`’s custom subcommand-parsing logic with Git’s standard `OPT_SUBCOMMAND()` mechanism, but this specific patch is self-contained and does not depend on later patches in the series.
