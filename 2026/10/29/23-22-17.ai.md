This is the first patch in the **v3 series fixing a critical ODB transaction bug** (merged to `seen`). It addresses a **locking hang risk** in the loose-object-idx mechanism by replacing the indefinite timeout (`-1`) with a finite 1000ms timeout (`LOOSE_OBJECT_IDX_LOCK_TIMEOUT_MS`). The change prevents processes from hanging indefinitely if a stale lockfile is left behind by a crashed writer, aligning the behavior with Git’s default packed-refs timeout.

The patch is **minimal and uncontroversial**: it adds a single `#define` and updates two call sites in `loose.c` to use the new timeout. The 1000ms value matches `core.packedRefsTimeout` and was accepted by Patrick Steinhardt in earlier review. This patch is **ready for integration** and has no dependencies on later patches in the series. The only functional change is the timeout itself; the locking logic and error handling remain otherwise identical. No new tests are introduced here, but the regression test in patch 4/4 (`t/t1016-compatObjectFormat.sh`) implicitly validates that locking works as expected during ODB migration.
