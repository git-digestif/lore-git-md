This is the second patch in Karthik Nayak’s three-patch bugfix series (v6) that restores correct ‘have’ reporting during shallow fetches with tag backfilling. It is a **refactoring / memory-leak fix** in the transport layer.

The patch introduces `transport_options_release()`, a helper that centralizes cleanup of the `git_transport_options` structure. The leak it fixes—memory allocated for `negotiation_restrict_tips`, `negotiation_include_tips`, and `filter_options`—only surfaces in the remote-helper transport path, which no existing test exercises. The next patch in the series (3/3) adds tests that would have caught this leak, so this patch is a prerequisite rather than a standalone fix.

Code changes are minimal: the existing cleanup logic in `disconnect_git()` is moved into the new helper, and `transport-helper.c` calls it in its own `release_helper()` path. The commit message now clearly states that the leak was previously uncaught and that the new helper ensures consistent cleanup across all transport types. No behavior change is introduced; the patch is purely about hygiene and future-proofing.
