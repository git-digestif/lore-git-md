This is the first patch in Patrick Steinhardt’s 12-patch refactoring series that modernizes `git rerere`’s subcommand handling. It is a pure rename-and-document refactoring: the function `repo_rerere()` is renamed to `rerere()` to match the naming convention of every other function in `rerere.h`. The commit message explains that the `repo_` prefix was never justified—it takes a repository parameter, but so do many other functions without such a prefix.

The patch touches nine files: `apply.c`, `builtin/am.c`, `builtin/commit.c`, `builtin/merge.c`, `builtin/rerere.c`, `builtin/stash.c`, `rerere.c`, `rerere.h`, and `sequencer.c`. All call sites are mechanically updated to use the new name. The documentation in `rerere.h` is moved and extended to better explain what the function does: it records (and optionally updates) resolved conflicts and reuses recorded resolutions for unresolved ones.

This is a low-risk, uncontroversial change that aligns with Junio C Hamano’s feedback from v1. The series as a whole is ready for integration, and this patch is the necessary first step toward the larger goal of converting `git rerere` to use Git’s standard `OPT_SUBCOMMAND()` mechanism. No behavior changes, no new CLI options, and no test updates are introduced here—just a rename and improved documentation.
