This is a **maintainer feedback email** on Kristofer Karlsson’s patch that skips self-referential alternates during quarantine. Junio C Hamano engages directly with the patch’s core architectural question: **where and how to fix the root cause**—the quarantine’s inability to distinguish the repository’s own object directory from real alternates.

Junio proposes a **cleaner alternative** to the current path-comparison hack: instead of adding a new environment variable (`GIT_QUARANTINE_OBJECT_DIRECTORY`), he suggests **repurposing the existing `GIT_QUARANTINE_ENVIRONMENT`** to carry the real object directory path. Currently, this variable only signals whether a process is in quarantine (a single bit of information); Junio’s idea is to make its value meaningful by setting it to the parent’s object directory path. This would allow child processes (like `rev-list --alternate-refs`) to identify and skip the repository’s own refs without path comparisons or new APIs.

The proposal is **minimally invasive**—it avoids introducing new environment variables or ODB transaction callbacks (as Justin Tobler suggested) while still addressing the root cause. It also aligns with the patch’s goal of fixing the quarantine plumbing rather than papering over the issue in `odb.c`. Junio does not explicitly endorse or reject the current patch, but his framing ("a bit of a shame") signals a preference for a more principled solution.

**Key technical details for follow-up**:
- **Environment variable**: `GIT_QUARANTINE_ENVIRONMENT` (currently used as a boolean flag).
- **Proposed change**: Set its value to the parent’s object directory path (e.g., `/path/to/git/objects`).
- **Impact**: Child processes could check this variable to identify and skip the repository’s own refs during alternate ref enumeration.
- **Files likely affected**: `tmp-objdir.c` (quarantine setup), possibly `environment.c` (variable handling).
- **No new symbols or APIs**: The fix would reuse existing infrastructure.

**Thread trajectory**: Expect Kristofer or Justin Tobler to respond with either:
1. A revised patch implementing Junio’s suggestion, or
2. A counter-proposal explaining why the path-comparison hack or ODB callback is preferable.

The discussion remains **focused on architecture**, not on whether the bug exists or is worth fixing—both are already established. The patch’s performance data and tests are likely to carry forward regardless of the chosen solution.
