This is a **bugfix and performance follow-up** in the ongoing discussion about Git’s object quarantine mechanism. Justin Tobler’s reply engages substantively with Kristofer Karlsson’s patch, proposing an alternative approach to fix the same underlying inefficiency: Git unnecessarily re-listing all refs (including hidden ones) from the repository’s own object directory during connectivity checks inside the quarantine environment.

Justin’s review is **substantive and tested**: he clearly understands the problem (refs being processed twice, hidden refs slipping through despite prior exclusions) and suggests a structural fix rather than the path-comparison hack in the original patch. His core idea is to **avoid setting the quarantine directory as the primary object directory for the connectivity check** (`git rev-list`), since that check doesn’t write objects and thus doesn’t need the quarantine’s isolation guarantees. This would sidestep the alternate-ref enumeration entirely for the check, eliminating the duplicate ref listing without introducing path-based heuristics.

He also floats a more ambitious direction: making the connectivity check a **first-class part of the ODB transaction interface**, with a backend-specific callback (e.g., `odb_transaction_files_check_connected()`) that configures `git rev-list` correctly. This aligns with Patrick Steinhardt’s ongoing ODB abstraction effort and would provide a cleaner, more explicit mechanism for future quarantine-aware processes.

The discussion is now focused on **where to fix the bug**—quarantine plumbing (`tmp-objdir.c`) vs. alternate ref enumeration (`odb.c`) vs. a new ODB transaction callback—rather than whether the bug exists. Justin’s proposal is technically sound and avoids the original patch’s "hack" label, but it may require more coordination with the ODB refactoring work. Expect follow-up from Patrick Steinhardt or others working on the quarantine/ODB layers.
