This is the third patch in Justin Tobler’s four-patch **bugfix series (v2)** that fixes a critical flaw in Git’s object database (ODB) transaction layer. The series targets a migration failure in the "loose-object-idx" file when Git is configured with a compatibility hash (e.g., SHA-1/SHA-256 interop) and batch fsync of loose objects is enabled.

This patch **refactors the loose-object index writing logic** by extracting it into a reusable helper function, `loose_object_map_write()`. The helper takes an explicit `loose_object_map` and file descriptor, allowing the migration code (introduced in patch 4/4) to write a merged index without being tied to the primary object directory. The refactoring is clean and well-motivated: it decouples the parsing and writing logic, improves error handling, and enables atomic writes in the next patch. The commit message clearly explains the purpose, and the code changes are straightforward.

The patch is part of a **high-priority fix** for ODB stability, and this refactoring is a necessary step toward the atomic-write solution that addresses Patrick Steinhardt’s blocking review concerns. The series is now finalized and ready for re-review, with all major objections resolved in v2. If you care about ODB correctness or compatibility-hash support, this patch is worth understanding—though the real payoff comes in patch 4/4.
