This is the first patch in Karthik Nayak’s three-patch bugfix series (v6) that restores correct ‘have’ reporting during shallow fetches with tag backfilling. It is a test-only patch that verifies a subtle but important edge case: when a batched fetch fails to update some references (e.g., because of a lock conflict), Git still writes the upstream tracking configuration for the successful updates. The test sets up a bare repository, creates a lock file to force one reference update to fail, and then confirms that the upstream tracking info for the main branch is recorded and that the backfilled tag is still fetched. This patch was moved to the front of the series in v6 to improve narrative flow, but it is functionally identical to the version in v5.
