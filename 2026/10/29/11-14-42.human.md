This is a **design discussion reply** in the ongoing `git worktree list` filtering thread. Phillip Wood responds to Jasper Mayone’s pivot from `--branch=<branch>` to extending `git for-each-ref`’s `%(worktreepath)` atom.

Phillip endorses the pivot as a useful improvement but highlights three practical gaps compared to a `git worktree list` enhancement. First, `git for-each-ref` lacks NUL-terminated output, making it awkward to handle worktree paths that contain newlines. Second, the output does not distinguish the main worktree, which matters for scripts that want to avoid deleting the entire repository. Third, `for-each-ref` cannot report multiple worktrees that have the same branch checked out, limiting its usefulness for tracking branch usage. He considers the behavior change (non-empty `%(worktreepath)` during rebase/bisect) a bug fix rather than a compatibility break.

On the main-worktree annotation question, Phillip clarifies that marking the main worktree is only necessary if the output is filtered; otherwise, scripts can safely assume the first entry is the main worktree. This aligns with Eric Sunshine’s earlier concern about the ordering invariant and suggests that any annotation mechanism should be tied to filtering rather than always-on. The reply leaves the door open for a follow-up patch but does not demand one.
