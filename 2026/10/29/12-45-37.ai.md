This is the first patch in the v6 series fixing the shallow-fetch-with-tags regression. It adds a test to `t/t5510-fetch.sh` that verifies upstream tracking information is written even when some reference updates are rejected during a batched fetch. The test sets up a scenario where a lock file prevents one ref from updating, then confirms that `branch.main.remote` is still set and that backfilled tags are present. This patch was moved to the front of the series (from its previous position as patch 3/3) to improve narrative clarity, as it now serves as a foundation for the memory-leak fix and core regression fix that follow. The test itself is straightforward and well-scoped, covering a previously untested edge case in the batched-fetch logic.
