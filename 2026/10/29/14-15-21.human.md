This is a follow-up in an ongoing thread about a bugfix targeting signal handling in Git's threading code.

The author, ian4hu, is responding to review feedback from Phillip Wood on a proposed patch that would fix a race condition in Git's `sigchain` subsystem, where concurrent signal handler pops could corrupt the signal stack. The discussion clarifies the scope and implementation details of the fix.

Key points: ian4hu plans to block signals (SIGINT, SIGHUP, SIGTERM, SIGQUIT) during thread creation to prevent signal delivery to worker threads, using a guard pattern rather than per-thread blocking. The fix will use `sigaction` with `sa_mask` set to avoid handler interruption. The author acknowledges a limitation with threads created by external libraries (like libcurl) but will document this rather than attempt to cover it.

The patch is not yet sent as v2; ian4hu is waiting for further feedback from Jeff King and Junio before proceeding. This looks like a well-considered, narrowly scoped bugfix addressing a real (if subtle) issue in Git's threading model.
