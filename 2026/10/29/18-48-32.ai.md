This is a contributor housekeeping series (v3) that keeps the documentation build system synchronized with the list of non-command manual pages. The series updates the `lint-manpages.sh` script to automatically verify that `command-list.txt` includes all concept guides and interface manuals defined in `Documentation/Makefile`, preventing future omissions.

The key change in v3 is the exemption of the obsoleted `gittutorial-2(7)` manual page from the linter check, alongside additional defensive quoting fixes. The series now depends on `je/doc-remove-gittutorial-2` (which removes the tutorial from the build) to pass the new test. Patch 1 adds the missing `gitformat-loose(5)` and `gitpacking(7)` entries to `command-list.txt`, while patch 2 extends the linter to check for completeness using a new `MAN_GUIDES` variable derived from `MAN5_TXT` and `MAN7_TXT`.

The patches are mechanical and confined to the `Documentation/` directory, with no runtime behavior changes. The linter now acts as a regression test for documentation completeness, addressing the original goal of preventing drift between `command-list.txt` and the Makefile. The author has incorporated all prior feedback (quoting fixes, commit message tweaks, and now the `gittutorial-2` exemption) and provided clear justification for excluding `gitweb.conf(5)`.

This series is part of the broader `kh/doc-datamodel` effort and depends on `c655855559` (which added `gitdatamodel(7)`). The changes are well-scoped and uncontroversial, with no expected follow-up work beyond potential future additions to the guide list. The linter enhancement is a sensible addition that will catch similar omissions early.
