This thread began with Farid Zakaria’s patch to fix a race condition in `git notes add` that could silently overwrite concurrent note additions, leading to data loss. The original patch, which fails on any concurrent update, was confirmed to prevent the bug but was quickly recognized as overly strict—blocking even non-conflicting updates. Kristoffer Haugsbakk and Junio C Hamano both endorsed the patch’s core correctness while critiquing its strictness, with Junio proposing a retry mechanism using Git’s existing merge/rebase machinery to allow non-conflicting updates to proceed.

Farid has now responded, agreeing in principle that a retry mechanism would be a better long-term solution but deferring its implementation to others. He positions the current patch as a "net-positive" interim fix, preventing silent data loss while acknowledging its limitations. The thread’s focus remains on the notes subsystem, but Farid hints at broader work on concurrency bugs, mentioning two additional race-condition fixes (in `credential-cache` and `fsmonitor`) discovered using the same tool. These aren’t yet posted but suggest a pattern of issues that could spark future discussions about Git’s concurrency model. For now, the notes patch is under review, with the door open for someone to pick up Junio’s proposed retry mechanism.
