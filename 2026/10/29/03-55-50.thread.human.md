This thread is about a bugfix for a race condition in Git’s notes subsystem, where concurrent `git notes add` operations could silently overwrite each other, leading to data loss. The patch, authored by Farid Zakaria, introduces a `base_oid` field to track the commit from which notes were read and uses it to enforce atomic updates, preventing silent overwrites. The fix is well-scoped, includes test coverage, and has not yet received any review feedback until now.

Kristoffer Haugsbakk’s recent review endorses the patch’s core approach but raises a broader design question: whether the current behavior—failing on *any* concurrent update to the notes ref—is too strict. He argues that two processes adding notes to *unrelated* commits should not interfere with each other, and suggests a more nuanced retry mechanism that only fails if there’s a true conflict. This opens a discussion about the long-term concurrency model for the notes subsystem, balancing simplicity against flexibility. The thread is now at a point where further input may shape whether the current fix is considered sufficient or if a more complex solution is warranted.
