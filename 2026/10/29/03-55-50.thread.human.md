This thread addresses a race condition in Git’s notes subsystem where concurrent `git notes add` operations can silently overwrite each other, leading to data loss. Farid Zakaria identified the issue using Rewind, a deterministic VM for exposing concurrency bugs, and proposed a fix that makes such operations fail explicitly rather than overwrite notes. The patch has been reviewed and is considered correct as an interim measure, but the discussion has broadened into whether Git should implement a more nuanced retry mechanism—using Git’s existing merge/rebase machinery—to allow non-conflicting updates to proceed.

Key participants include Farid, who authored the patch and views it as a "net-positive" fix despite its strict failure mode; Kristoffer Haugsbakk, who endorsed the patch’s correctness but raised concerns about its overly conservative behavior; and Junio C Hamano, who proposed the retry mechanism as a long-term solution. Farid has deferred implementing the retry mechanism, leaving the door open for others to take the lead. A minor procedural confusion about Farid’s earlier review phrasing was recently clarified, but the core design questions remain unresolved: whether the added complexity of a retry mechanism is justified, and how it should interact with Git’s porcelain/plumbing boundaries. The current patch is ready for merging as a safe baseline, but the thread’s direction suggests a follow-up effort may refine the concurrency model further.
