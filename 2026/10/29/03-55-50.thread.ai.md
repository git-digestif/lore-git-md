Subject: [PATCH] notes: fix race condition in concurrent note additions
Series version: standalone patch
Originating author: Farid Zakaria
Thread type: bug report and fix

Core problem or goal
The notes subsystem in Git has a race condition in `git notes add` (and related commands) where concurrent note additions can silently overwrite each other, causing data loss. The bug was discovered using Rewind, a deterministic VM that replays thread schedules to expose concurrency bugs, and confirmed in real-world scenarios (25 of 30 runs lost a note on a plain Linux machine).

Current status
Under review. The patch is a standalone bugfix with no prior versions in this thread.

Key technical details
- Files touched: `notes-utils.c`, `notes.c`, `notes.h`, `t/t3301-notes.sh`
- New field: `base_oid` in `struct notes_tree` to track the commit from which notes were originally read
- Modified functions: `init_notes()` (populates `base_oid`), `commit_notes()` (uses `base_oid` as parent and expected old value for ref update)
- Behavior change: concurrent note additions now fail with "cannot lock ref" instead of silently overwriting
- Test coverage: new test case in `t/t3301-notes.sh` simulates concurrent note addition using an editor script
