This is a refactoring patch targeting the `git diff-files` built-in command. It converts the ad-hoc option parsing in `cmd_diff_files()` to use Git's standard `parse-options` API, replacing a manual loop that checks for `--base`, `--ours`, `--theirs`, and `-q` with structured option definitions (`OPT_SET_INT_F`, `OPT_BIT`, etc.). The patch touches only `builtin/diff-files.c`, removing 19 lines of manual parsing and adding 20 lines of `parse-options` boilerplate.

The motivation is consistency with the rest of the codebase: the new approach auto-generates help text, supports shell completion, and handles option abbreviation. The commit message notes that `--base`, `--ours`, and `--theirs` are marked `PARSE_OPT_NONEG` to prevent negated forms (e.g., `--no-base`), matching the pattern used in `builtin/checkout.c` for similar stage-selection options. The patch preserves the existing behavior—`rev.max_count` is still set to 1, 2, or 3 for the respective options, and `-q` still sets `DIFF_SILENT_ON_REMOVED`.

The change is mechanical and well-scoped, with no functional impact. The updated usage message is now passed via `usage_with_options()`, and the error-checking logic for invalid arguments remains intact. This is the fourth iteration (`v4`) of the patch, suggesting it has already undergone review and refinement. The patch is part of a broader effort to modernize option parsing across Git's built-ins, though it stands alone in this series.
