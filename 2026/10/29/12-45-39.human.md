This is the final patch in Karthik Nayak’s three-part bugfix series (v6) targeting a performance regression in shallow fetches when backfilling tags. The patch implements the core fix by exposing the OIDs of just-fetched references during negotiation, ensuring the server does not resend objects the client already has.

The change is focused on `builtin/fetch.c`, where a new `fetched_tips` array collects the OIDs of fetched references before tag backfilling begins. These OIDs are then appended to the transport’s `negotiation_include_tips` field, allowing the client to advertise them as "haves" during negotiation. The patch also adds two new tests in `t/t5510-fetch.sh` to verify the fix works for both atomic and non-atomic fetches.

The commit message clearly explains the root cause (batched updates delaying reference commits until after tag backfilling) and the trade-off (advertising all fetched references during negotiation, which is documented as acceptable O(n) complexity). The solution preserves atomicity for `--atomic` fetches while restoring correct "have" reporting. The patch is well-motivated, thoroughly tested, and addresses all prior review feedback, including the memory management blocker resolved in patch 2/3.
