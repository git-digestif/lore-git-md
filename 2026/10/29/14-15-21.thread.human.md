The thread is about fixing a race condition in Git’s `sigchain` subsystem, where concurrent calls to `sigchain_pop()` for the same signal can corrupt the signal handler stack. Ian4hu has proposed a redesign that blocks common signals (SIGINT, SIGHUP, SIGTERM, SIGQUIT, and now SIGPIPE) during thread creation to prevent worker threads from inheriting the main thread’s signal handlers. The blocking is done once per spawn loop using a guard pattern, rather than per-thread, to minimize overhead.

Phillip Wood has endorsed the redesign, agreeing that only the main thread should handle signals and approving the guard-pattern implementation. The discussion is now awaiting feedback from Jeff King (Peff) and Junio before Ian4hu proceeds with a v2 patch series. The targeted thread pools include `preload_index()`, `index-pack`, `pack-objects`, `grep`, `name-hash`, and the read-cache entry loader, while threads like `fsmonitor--daemon` and `simple-ipc` are excluded due to their distinct lifecycles. A known limitation—threads created by external libraries (e.g., libcurl’s threaded resolver)—will be documented in the cover letter. No objections or alternative approaches have been raised so far.
