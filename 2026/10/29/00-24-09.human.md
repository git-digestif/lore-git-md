This is a bugfix patch series (v2) targeting the object database (ODB) transaction layer. It fixes a critical bug where the temporary object directory migration logic fails when Git is configured with a compatibility hash (e.g., SHA-1/SHA-256 interoperability) and batch fsync of loose objects is enabled. The issue occurs because the migration code cannot merge the "loose-object-idx" file—a mapping between objects and their compatibility hashes—when a preexisting index exists in the primary object directory. Without this fix, the transaction fails with a "files differ in contents" error, leading to data loss.

The series consists of four patches. The first two are preparatory: they introduce a finite timeout for locking the "loose-object-idx" file and refactor the parsing and writing logic into reusable helpers. The third patch further refactors the writing logic to support atomic updates. The final patch implements the core fix, merging new mapping entries from the temporary index into the primary index and writing the result atomically. The series also includes a regression test (`t/t1016-compatObjectFormat.sh`) that verifies the fix by writing objects in two batches and ensuring all entries appear in the final index.

This v2 addresses the blocking concerns raised by Patrick Steinhardt in the initial review. The most significant change is replacing the append-under-lock pattern with Git’s standard temp-file-then-rename pattern, eliminating the risk of file corruption from partial writes. The series also drops duplicate entries when writing the merged mapping file and uses a finite 1000ms timeout for locking instead of an indefinite one. The author acknowledges that the loose-object-idx mechanism has deeper design flaws—such as unsorted files, lack of deduplication, and no pruning of stale entries—but defers addressing those to future work.

The patch is well-crafted, with a clear commit message, thorough test coverage, and careful attention to error handling and atomicity. It is part of the broader ODB abstraction effort led by Patrick Steinhardt, and the author (Justin Tobler) is a frequent contributor in that area. The fix is high-priority for ODB layer stability, and v2 appears ready for merging. If you work with the ODB or compatibility hashes, this is worth reviewing closely.
