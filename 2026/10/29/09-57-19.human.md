This is the tenth patch in Patrick Steinhardt’s twelve-patch refactoring series that modernizes `git rerere`’s subcommand handling by switching to Git’s standard `OPT_SUBCOMMAND()` mechanism. The series is purely internal refactoring with no behavior changes, and this patch specifically converts the "gc" subcommand into a proper parse-options-driven function.

The patch extracts the "gc" logic into a new `cmd_rerere_gc()` function that uses `parse_options()` with a hidden `--skip-locked` flag, mirroring the existing behavior but now scoped to the subcommand. The global `--skip-locked` option is removed from the top-level parser, and the test that verified its rejection for non-"gc" subcommands is dropped as redundant. The change is mechanical and preserves the exact same functionality: `rerere_gc()` is called with the same flags (`RERERE_NOWAIT` when `--skip-locked` is set), and the `merge_rr` string list is still managed correctly.

This patch is part of a well-scoped, uncontested series that has already addressed all feedback from Junio C Hamano. The remaining two patches (11/12 and 12/12) will replace the hand-rolled subcommand dispatch with `OPT_SUBCOMMAND()` and add per-subcommand usage strings. The series is ready for integration and brings `git rerere` in line with other multi-subcommand built-ins like `git notes` and `git maintenance`.
