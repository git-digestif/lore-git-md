This is a **contributor housekeeping** follow-up in the bash-completion script thread. Pablo Sabater, the original implementer of the `--graph-indent` option, replies to Mirko Faina’s patch with a **substantive review** that raises three technical points.

First, he questions whether `--graph-indent` and `--no-graph-indent` belong in `__git_log_common_options`, the shared variable used by `git log`, `git show-branch`, and other commands. He notes that `--graph` itself is not in that list but appears later in a command-specific block (`__git_log_gitk_options`), suggesting the new options might fit better there. Second, he proposes adding completion for `--graph-lane-limit`, another `--graph`-dependent option that is currently missing. Third, he flags a UX concern: both `--graph-indent` and `--graph-lane-limit` require `--graph` to be present, and autocompleting them without `--graph` will produce an error. He wonders whether the completion script should suppress these options unless `--graph` is already on the command line, and whether such conditional logic already exists for other dependent options.

The review is constructive and forward-looking, anticipating that more `--graph`-related options may be added in the future. It does not object to the patch as written but suggests a broader rethink of how `--graph`-dependent options are handled in the completion script. No code changes are proposed yet; the discussion is still at the design level. Toon Claes is cc’d, likely because of his past work on `--graph` options and a Git Merge talk referenced in the email.
