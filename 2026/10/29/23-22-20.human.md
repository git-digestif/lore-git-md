This is the final patch in a four-part bugfix series that was merged to `seen`. It implements the core fix for a critical flaw in Git's object database (ODB) transaction layer: when a repository uses a compatibility hash (e.g., SHA-1/SHA-256 interop) and batch fsync of loose objects, migrating temporary object directories fails if a `loose-object-idx` file already exists in the primary object directory. The patch merges entries from both the temporary and primary indices and atomically writes the result, ensuring no data loss during migration.

The change touches `tmp-objdir.c`, `loose.c`, and `loose.h`, introducing a new function `loose_object_idx_merge()` that handles the merge logic. The patch also adds a regression test in `t/t1016-compatObjectFormat.sh` to verify that all entries from both indices are preserved after migration. The implementation uses the refactored helpers (`loose_object_map_read()` and `loose_object_map_write()`) introduced in earlier patches, ensuring atomic writes via Git's standard temp-file-then-rename pattern.

This patch is uncontroversial and ready for integration. All blocking concerns raised during review—particularly around atomicity and locking—were addressed in prior versions of the series. The only changes in this v3 iteration are minor optimizations (reading the source index outside the lock) and documentation improvements. The fix is high-priority for users of the compatibility-hash feature and batch fsync, as the bug could lead to ODB transaction failures. The series as a whole is now in `seen`, with patches 1/4 (locking timeout) and 2/4 (parsing refactor) explicitly noted as ready for integration.
