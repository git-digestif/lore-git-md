Thread type: project proposal (Outreachy internship)

Core problem or goal
Eliminate Git’s reliance on global state—particularly the `the_repository` global variable and related configuration globals—to facilitate libification (making Git’s core functionality reusable as a library). The proposal continues the ongoing community effort to thread repository instances through call chains, move configuration into repository structures, or pass only needed values rather than relying on globals. Christian Couder has raised a nuance: the distinction between `builtin/` code and reusable library code may not be as clear-cut as initially proposed, as even `builtin/` code might benefit from being refactored into library helpers, complicating the project’s scope.

Current status
Under review. Ajayi has already contributed 12 patches to this effort during the Outreachy contribution period:
- 1 patch merged to `master`
- 6 patches in `seen` (some marked “Will merge to 'next'” in Junio’s reports)
These patches remove `USE_THE_REPOSITORY_VARIABLE` from files such as `merge.c`, `diffcore-rename.c`, and `bundle-uri.c`, or move repository-specific settings (e.g., `commit_encoding`) into more appropriate structures. No changes to the integration status of these patches have been reported in this email.

Key technical details
Files and subsystems touched: `merge.c`, `diffcore-rename.c`, `bundle-uri.c`, and others involved in the `the_repository` removal effort.
New or renamed symbols: none introduced yet; focus is on removing reliance on `the_repository` and related globals (e.g., `git_log_output_encoding`, `commit_encoding`).
Old-vs-new behavior: no user-visible behavior changes; the work is purely internal refactoring to enable libification.
Test coverage: existing test suite remains applicable; no new test files introduced in the patches submitted so far.

Open questions and loose ends
- How to handle `git_log_output_encoding`, which is set in multiple places and used across subsystems.

- Whether the project’s scope should include refactoring `builtin/` code into library helpers, as raised by Christian Couder. This question was not addressed in the original proposal and may require further discussion or a revised plan.
