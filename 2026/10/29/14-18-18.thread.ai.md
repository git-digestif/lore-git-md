Subject: Outreachy proposal: Reduce Git's global state to enable libification
Series version: v3 (final project proposal, not a patch series)
Originating author: Okhuomon Ajayi <okhuomonajayi54@gmail.com>
Thread type: project proposal (Outreachy internship)

Core problem or goal
Eliminate Git’s reliance on global state—particularly the `the_repository` global variable and related configuration globals—to facilitate libification (making Git’s core functionality reusable as a library). The proposal explicitly includes refactoring reusable code from `builtin/` into library helpers, addressing Christian Couder’s feedback that the distinction between `builtin/` and library code is not clear-cut. The goal remains internal refactoring with no user-visible behavior changes.

Current status
Under review. Ajayi has contributed 18 patches to this effort during the Outreachy contribution period:
- 2 patches merged to `master` (`diffcore-break.c`, `diffcore-rename.c`)
- 4 patches in `next` (including `range-diff.c`, `bundle-uri.c`)
- 6 patches in `seen` (including a new 6-patch series for `notes.c`)
- 6 patches awaiting review
These patches remove `USE_THE_REPOSITORY_VARIABLE` from files such as `merge.c`, `diffcore-rename.c`, `bundle-uri.c`, `notes.c`, and `environment.c`, or move repository-specific settings (e.g., `commit_encoding`) into more appropriate structures. The proposal has been revised to v3 with an expanded scope (including `builtin/` refactoring) and improved structure (e.g., batched series, public blog). Integration status updated to reflect recent graduations to `master` and `next`.

Key technical details
Files and subsystems touched: `merge.c`, `diffcore-rename.c`, `bundle-uri.c`, `notes.c`, `environment.c`, and others involved in the `the_repository` removal effort; expanded scope now includes `builtin/` code for conversion into library helpers.
New or renamed symbols: none introduced yet; focus remains on removing reliance on `the_repository`, `USE_THE_REPOSITORY_VARIABLE`, `git_log_output_encoding`, `commit_encoding`, `repo_config_values`, `repo_settings`, and `have_git_dir()`.
Old-vs-new behavior: no user-visible behavior changes; the work is purely internal refactoring to enable libification.
Test coverage: existing test suite remains applicable; no new test files introduced in the patches submitted so far.
Strategies for reducing global state: (1) threading repositories through call chains, (2) moving config into repository structures, or (3) passing only needed values. Ajayi’s proposal includes a detailed case study of `git_log_output_encoding` to illustrate the design process for complex globals.

Open questions and loose ends
- Design choices for complex globals: `git_log_output_encoding` (set in multiple places, used across subsystems), `have_git_dir()`, `comment_line_str`, and abbrev settings. Ajayi’s proposal explicitly plans to discuss these with the mailing list before implementation.
- Identifying suitable `builtin/` code for conversion into library helpers while ensuring backward compatibility.
- Handling harder cases like `have_git_dir()` and environment globals in a way that aligns with the project’s libification goals.
