Subject: Outreachy proposal: Reduce Git's global state to enable libification
Series version: v2 (project proposal, not a patch series)
Originating author: Okhuomon Ajayi <okhuomonajayi54@gmail.com>
Thread type: project proposal (Outreachy internship)

Core problem or goal
Eliminate Git’s reliance on global state—particularly the `the_repository` global variable and related configuration globals—to facilitate libification (making Git’s core functionality reusable as a library). The proposal now explicitly includes refactoring reusable code from `builtin/` into library helpers, addressing Christian Couder’s feedback that the distinction between `builtin/` and library code is not clear-cut. The goal remains internal refactoring with no user-visible behavior changes.

Current status
Under review. Ajayi has contributed 18 patches to this effort during the Outreachy contribution period:
- 1 patch merged to `master`
- 6 patches in `next` (graduated from `seen`)
- 7 patches in `seen` (some marked “Will merge to 'next'” in Junio’s reports)
- 4 patches awaiting review
These patches remove `USE_THE_REPOSITORY_VARIABLE` from files such as `merge.c`, `diffcore-rename.c`, `bundle-uri.c`, and `notes-utils.c`, or move repository-specific settings (e.g., `commit_encoding`) into more appropriate structures. The proposal has been revised to v2 with an expanded scope and improved structure (e.g., batched series, public blog).

Key technical details
Files and subsystems touched: `merge.c`, `diffcore-rename.c`, `bundle-uri.c`, `notes-utils.c`, `environment.c`, and others involved in the `the_repository` removal effort; expanded scope now includes `builtin/` code for conversion into library helpers.
New or renamed symbols: none introduced yet; focus remains on removing reliance on `the_repository`, `USE_THE_REPOSITORY_VARIABLE`, `git_log_output_encoding`, `commit_encoding`, `repo_config_values`, and `repo_settings`.
Old-vs-new behavior: no user-visible behavior changes; the work is purely internal refactoring to enable libification.
Test coverage: existing test suite remains applicable; no new test files introduced in the patches submitted so far.

Open questions and loose ends
- Design choices for complex globals: `git_log_output_encoding` (set in multiple places, used across subsystems), `have_git_dir()`, `comment_line_str`, and abbrev settings.
- Identifying suitable `builtin/` code for conversion into library helpers while ensuring backward compatibility.
- Handling harder cases like `have_git_dir()` and environment globals in a way that aligns with the project’s libification goals.
