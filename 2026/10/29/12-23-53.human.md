This is a bugfix for the oss-fuzz integration, restoring the fuzzer's ability to test commit-graph parsing after a recent regression. The patch itself is a one-line addition to `oss-fuzz/fuzz-commit-graph.c`, setting a placeholder `.git` gitdir to satisfy a BUG assertion in `prepare_repo_settings()`. The fix is minimal, well-explained, and mirrors an existing pattern elsewhere in the codebase.

Patrick Steinhardt reviewed the patch and confirmed it looks good. His only comment was a minor observation that the `xstrdup` allocation doesn’t need manual freeing since `repo_clear()` handles it, which the author already accounted for. No substantive concerns were raised, and the patch is self-contained with no side effects outside the fuzzer environment.

The regression was introduced in commit f1141b4391 (August 2025) during a refactoring of `parse_commit_graph()` to take a repository parameter. The fuzzer’s repository lacks a gitdir, causing `prepare_repo_settings()` to fail before the fuzzer could test optional chunks like generation data or Bloom filters. This patch restores that coverage without touching production code.

The thread also briefly touches on a broader issue: the lack of a smoke test for fuzzers, which would have caught this regression earlier. Patrick notes this is outside the scope of the current fix, but it’s a useful observation for future improvements.

This is a straightforward, uncontroversial fix that should be ready for merging. If you follow Git’s fuzzing or commit-graph subsystems, it’s worth noting the restored coverage. Otherwise, no action is needed.
