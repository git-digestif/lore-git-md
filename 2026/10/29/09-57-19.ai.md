This is the tenth patch in Patrick Steinhardt’s v2 series modernizing `git rerere`’s subcommand handling. It extracts the "gc" action into a dedicated `cmd_rerere_gc()` function that uses Git’s standard `parse_options()` machinery, replacing the hand-rolled logic in the main `cmd_rerere()` dispatcher. The patch also removes the now-redundant global `--skip-locked` flag from the top-level parser and moves its hidden counterpart into the new subcommand’s option table. A single negative test (`--skip-locked` rejected for non-"gc" subcommands) is dropped from `t/t4200-rerere.sh` because the option is no longer visible outside the "gc" subcommand.

The change is purely mechanical: the `rerere_gc()` call site is lifted verbatim into `cmd_rerere_gc()`, preserving the existing logic and behavior. The only functional difference is that `--skip-locked` is now scoped to the "gc" subcommand, which is the intended design. The patch is uncontested and ready for integration; the next two patches will complete the series by introducing the `OPT_SUBCOMMAND()` table and per-subcommand usage strings.
