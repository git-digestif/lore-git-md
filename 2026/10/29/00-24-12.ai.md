This is the third patch in Justin Tobler’s four-patch **bugfix series (v2)** targeting a critical flaw in the ODB transaction layer’s loose-object-idx migration logic. The patch **refactors loose-object index writing** by extracting the core logic from `repo_write_loose_object_map()` into a new helper, `loose_object_map_write()`, which can write any loose object map to any file descriptor. This refactoring is a prerequisite for the final patch (4/4), which will use the helper to atomically merge the loose-object-idx file during temporary object directory migration.

The patch is **well-motivated and technically sound**. It isolates the writing logic—previously hardcoded to the primary object directory—into a reusable function that accepts both the loose object map and the target file descriptor as parameters. This enables the migration code in `tmp-objdir.c` to write the merged index to a temporary file before committing it atomically, addressing Patrick Steinhardt’s blocking concern about atomicity. The refactoring also tightens error handling: the new helper returns a proper error code (0/-1) instead of relying on `LOCK_DIE_ON_ERROR`, and the caller (`repo_write_loose_object_map`) now propagates errors more cleanly.

Key changes:
- **New helper**: `loose_object_map_write()` in `loose.c`, declared in `loose.h`, writes a given loose object map to a specified file descriptor.
- **Behavior**: The helper preserves the existing on-disk format (header + newline-separated OID pairs) but decouples the logic from the primary object directory, enabling reuse in the migration code.
- **Error handling**: The helper returns -1 on failure (e.g., write errors), and the caller rolls back the lock file and propagates the error. This is stricter than the original code, which used `LOCK_DIE_ON_ERROR`.
- **Code hygiene**: The refactoring reduces duplication and makes the writing logic more testable. The original function (`repo_write_loose_object_map`) now delegates to the helper, reducing its complexity.

The patch touches only `loose.c` and is **pure refactoring**—no behavior change for existing callers. It is part of the broader ODB abstraction effort and directly supports the atomic-write fix in patch 4/4. The commit message clearly explains the motivation (enabling migration of staged loose-object-idx files) and the technical approach (extraction into a reusable helper).
