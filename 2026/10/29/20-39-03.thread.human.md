This thread is about a patch from Edson that refactors `git diff-files` to use Git’s standard `parse-options` API instead of its current ad-hoc option parsing. The patch is now at its sixth version, having fixed earlier threading issues that made prior iterations ineligible for review.

Junio C Hamano has now provided the first substantive technical feedback on the patch. He raises two concerns: first, the patch drops standard diff options like `-p` and `--stat` from the help output, which could confuse users; second, he questions whether the refactoring is worthwhile for a plumbing command like `diff-files`, where the existing `strcmp()`-based parsing is already clear and functional. The patch remains under review, with no maintainer decision yet, but the discussion now centers on whether the trade-offs—improved consistency and shell completion at the cost of a less helpful help message—are justified for this particular command. No other reviewers have weighed in so far.
