This thread is about a regression in `git grep --recurse-submodules` that causes the command to fail with `fatal: unable to read tree` when searching tree objects inside submodules. The issue was introduced in Git 2.56.0 by commit `93cd344e34` and affects all current integration branches (`master`, `next`, `seen`). The root cause is that `grep_tree()` now reads submodule directory trees from the superproject’s ODB instead of the submodule’s ODB, breaking the expected behavior.

Root initially reported the bug and proposed a workaround, but Patrick Steinhardt has now sent a formal patch series to fix the issue. The series targets `builtin/grep.c` and aims to restore the correct ODB lookup logic. While the exact implementation details and test coverage are still unclear, Patrick’s involvement (as a domain expert in ODB and submodule handling) suggests the fix is well-positioned for a quick resolution. The regression is confirmed to affect CI environments, making this a high-priority fix that will likely need backporting to `maint` once merged.

The thread is currently focused on reviewing and testing Patrick’s patch series. Key open questions include whether the fix accounts for other commands or code paths that might rely on similar ODB resolution logic, and whether the full test suite passes with the proposed changes. No review feedback has been posted yet, but the next steps will involve verifying the fix doesn’t introduce regressions elsewhere.
