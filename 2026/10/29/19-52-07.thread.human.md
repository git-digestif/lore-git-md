This thread reports a regression in `git grep --recurse-submodules` when searching tree objects, introduced in Git 2.56.0 by commit `93cd344e34`. The bug causes `git grep` to fail with `fatal: unable to read tree` when encountering directories inside submodules, breaking recursive searches of submodule trees. The issue stems from a mismatch in object database (ODB) access: after the ODB registration for submodules was removed, `grep_tree()` incorrectly tries to read submodule directory trees from the superproject's ODB instead of the submodule's ODB.

The author, Root, provides a detailed report with reproduction steps, error messages, and system details, confirming the regression affects all current integration branches (`master`, `next`, `seen`). The working-tree form of the command remains unaffected, as does searching submodules without directories. A proposed workaround—using `repo->objects` instead of `the_repository->objects`—restores expected behavior but hasn't been fully tested. The fix will likely involve adjusting how `grep_tree()` resolves submodule objects, possibly by passing the correct repository context or reworking the ODB lookup logic. No prior discussion or patches have been posted yet, so this appears to be the first report of the issue.
