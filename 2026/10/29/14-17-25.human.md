This is a **contributor housekeeping** follow-up in the ongoing discussion about bash completion for `--graph`-related options in `git log`. Ben Knoble joins the thread with two brief but substantive observations.

First, he clarifies the meaning of `__git_log_common_options`: it is not about how "commonly" an option is used, but about options that are shared across multiple Git commands (e.g., `git log`, `git show-branch`). This helps frame Pablo Sabater’s earlier question about whether `--graph-indent` belongs in that list or in a command-specific block.

Second, Ben suggests a longer-term architectural direction: instead of manually curating completion lists in the bash script, Git commands that use `parse-options` could eventually expose their own completion hints directly. This would make the completion script more maintainable and reduce the risk of missing or misplaced options. The comment is speculative and does not propose immediate code changes, but it adds a forward-looking perspective to the design discussion.
