This is the second patch in a two-part contributor housekeeping series (v3) that keeps Git's documentation build system in sync. The patch extends the `lint-manpages.sh` script to automatically verify that `command-list.txt` includes all non-command manual pages—concept guides and interface manuals like `gitformat-loose(5)` and `gitpacking(7)`—defined in the Makefile.

The change is mechanical and defensive: it adds a new `MAN_GUIDES` variable derived from `MAN5_TXT` and `MAN7_TXT`, then checks `command-list.txt` against this list. The linter now fails if any manual page is missing, acting as a regression test for documentation completeness. Two explicit exemptions are added: `gitweb.conf(5)` (to avoid a confusing display name in `git help -a`) and the obsoleted `gittutorial-2(7)` (which was recently removed from the build). The patch also incorporates Junio’s requested quoting fixes (`"$file"` and `$(dirname "$file")`) for robustness.

The series as a whole is well-scoped and uncontroversial. The author has addressed all prior feedback—quoting fixes, commit message tweaks, and the `gittutorial-2` exemption—and the linter enhancement is a sensible addition that will catch future omissions early. This patch depends on two prior commits (`c655855559` and `je/doc-remove-gittutorial-2`) to pass the new test, but those are already in place. No runtime behavior changes; the impact is purely on the build-time validation. The series looks ready for acceptance.
