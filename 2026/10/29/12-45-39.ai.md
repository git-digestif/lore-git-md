This is the core fix (patch 3/3) in Karthik Nayak’s three-patch bugfix series targeting the fetch subsystem. It restores correct ‘have’ reference reporting during shallow fetches when backfilling tags, fixing a performance regression introduced by commit 0e358de64a (“fetch: use batched reference updates”, 2025-05-19).

The patch collects the OIDs of just-fetched refs into a temporary `oid_array` (`fetched_tips`) inside `do_fetch()`, then appends them to the transport’s `negotiation_include_tips` field during `backfill_tags()`. This ensures the server sees the client’s new ‘haves’ during negotiation, avoiding redundant object transfers. The change preserves atomicity for `--atomic` fetches and handles both atomic and non-atomic flows. Two new tests in `t/t5510-fetch.sh` verify the fix: one for non-atomic fetches and one for `--atomic` fetches, both checking that the client advertises the correct ‘have’ references during tag backfilling.

The implementation is straightforward and well-scoped: it touches only `builtin/fetch.c` and the test suite, introducing no new public APIs. The memory management blocker from earlier iterations has been resolved by the precursor patch (2/3), which introduced `transport_options_release()` to ensure proper cleanup. The scalability trade-off (advertising all fetched references during negotiation) is documented as acceptable O(n) complexity. All substantive review feedback has been addressed, and the series is now ready for maintainer review. Junio C Hamano’s position remains the only unvoiced blocker.
