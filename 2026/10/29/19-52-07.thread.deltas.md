# Thread deltas

## 2026/10/29

- [2026/10/29/19-52-07 by Root <rootminus0x1@gmail.com>] Root reported that since Git 2.56.0, `git grep --recurse-submodules <pattern> <tree>` dies with "fatal: unable to read tree" when it reaches a directory inside a submodule, while the working-tree form and submodules without directories are unaffected.
- [2026/10/29/19-52-07 by Root <rootminus0x1@gmail.com>] Root identified commit 93cd344e34 (builtin/grep: stop registering submodule ODB as source, 2026-09-11) as the cause, explaining that grep_tree() reads subdirectory trees from the superproject's object database (the_repository->objects) while grep_submodule() sets opt->repo to the submodule, so the lookup fails for submodule subdirectories.
- [2026/10/29/19-52-07 by Root <rootminus0x1@gmail.com>] Root noted that reading from repo->objects instead of the_repository->objects at builtin/grep.c:656 makes the reproduction print the expected output, and that grep_cache() performs the same the_repository->objects lookup at line 563 for sparse-directory index entries (with the sparse-index submodule case unchecked).

## 2026/10/30

- [2026/10/30/10-26-35 by Patrick Steinhardt <ps@pks.im>] Patrick Steinhardt confirmed the bug and sent a patch series (20261030-pks-grep-recurse-submodule-v1-0-d4eb5c87d8fb@pks.im) to fix `git grep --recurse-submodules <tree>` dying on a directory inside a submodule.
