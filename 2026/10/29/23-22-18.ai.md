This is the second patch in a four-patch bugfix series (v3) that was merged to `seen`. It refactors the loose-object index parsing logic in `loose.c` to prepare for a subsequent fix to ODB transaction migration.

The patch extracts the core parsing logic from `loose_object_map_load()` into a new helper function, `loose_object_map_read()`. This helper takes an explicit `loose_object_map` and optional `oidtree` cache as parameters, decoupling the parsing logic from the `odb_source_loose` struct. The change enables future callers (specifically the migration logic in patch 4/4) to parse a loose-object-idx file into an arbitrary map, not just the one tied to an object source.

Key technical details: the patch introduces stricter error handling by failing early if the loose-object-idx file cannot be opened for reasons other than `ENOENT`. This matches the existing behavior for malformed files and ensures callers are aware of read failures. The `insert_loose_map()` helper is also updated to operate on the provided map and cache rather than the object source, with the cache made optional for future use cases where caching is unnecessary.

The refactoring is uncontroversial and was explicitly noted as ready for integration in the thread summary. The commit message clearly documents the optional `cache` parameter in `insert_loose_map()` to explain its reuse in later patches. No behavior changes are introduced; this is purely a preparatory refactor for the core fix in patch 4/4. The patch touches only `loose.c` and maintains the existing loose-object-idx file format.
