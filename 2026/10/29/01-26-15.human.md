This is the first patch in a two-part follow-up to Tanga Joris’s earlier completion fix. It targets the `fast-import` command specifically, addressing the edge case René Scharfe identified: when `fast-import` is no longer marked with `NO_PARSEOPT`, running `git fast-import --<TAB>` would freeze because the command waits for input before parsing options, and each invocation leaves behind a temporary `tmp_pack_*` file.

The patch moves the `--git-completion-helper` check to the very beginning of `cmd_fast_import()`, before any input is read or temporary files are created. This ensures that completion queries return immediately without side effects. A new test in `t/t9300-fast-import.sh` verifies that no temporary pack files are created when the completion helper is invoked, and that the expected option list is printed.

The change is small, well-motivated, and directly addresses the regression René reported. The test coverage is minimal but sufficient for the narrow scope. This patch is blocked on nothing; it can land independently once reviews converge. The second patch in the series (not shown here) is the original v2 that removes `NO_PARSEOPT` from `patch-id`, `diff-pairs`, and `var`.
