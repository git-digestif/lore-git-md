This is the third patch in Justin Tobler’s four-patch series (v3) that fixes a critical ODB transaction bug. It extracts the loose-object-idx writing logic from `repo_write_loose_object_map()` into a new helper, `loose_object_map_write()`, so the upcoming migration code (patch 4/4) can atomically write a merged index to a caller-provided file descriptor.

The patch moves the core write loop into the helper, which takes a `struct loose_object_map` and a file descriptor instead of hard-coding the primary object directory. Locking responsibility is explicitly left to the caller, allowing the lock to span multiple operations (e.g., reading the preexisting index and writing the merged result). The original function becomes a thin wrapper that locks the primary object directory and delegates to the helper.

No behavior changes; the patch is pure refactoring. The commit message explains the motivation (enabling atomic migration) and the design choice (caller-managed locking). Patrick Steinhardt’s review of v2 found this uncontroversial, and the v3 changes are cosmetic (a clarifying comment in `loose.h`). The helper will be used in patch 4/4 to implement the core fix.
