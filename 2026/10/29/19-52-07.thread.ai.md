Subject: regression in `git grep --recurse-submodules` when searching tree objects
Series version: standalone bugfix (no series)
Originating author: Root <rootminus0x1@gmail.com>
Thread type: bug report

Core problem or goal
A regression in `git grep --recurse-submodules` causes the command to fail with `fatal: unable to read tree` when it encounters a directory inside a submodule. The regression was introduced in Git 2.56.0 by commit `93cd344e34` ("builtin/grep: stop registering submodule ODB as source", 2026-09-11). The root cause is that `grep_tree()` now reads submodule directory trees from the superproject’s ODB (`the_repository->objects`) instead of the submodule’s ODB, which no longer works after the ODB registration was removed.

Current status
Under review. The regression is confirmed and bisected to the problematic commit. The working-tree form of the command (`git grep --recurse-submodules <pattern>`) and searches of submodules without directories are unaffected. The issue is present in all current integration branches (`master`, `next`, `seen`). A proposed workaround (reading from `repo->objects` instead of `the_repository->objects`) restores expected behavior but has not been tested against the full test suite.

Key technical details
- **Files touched**: `builtin/grep.c` (specifically the `grep_tree()` function).
- **Subsystems**: `git grep`, submodule handling, object database (ODB) access.
- **Old behavior**: `grep_tree()` read submodule directory trees from the submodule’s ODB.
- **New behavior**: `grep_tree()` reads from the superproject’s ODB (`the_repository->objects`), causing the failure.
- **Test coverage**: Minimal reproduction script provided; no mention of existing test suite coverage for this edge case.
- **On-disk format**: No changes.
- **CLI options**: `--recurse-submodules` is the affected flag.
