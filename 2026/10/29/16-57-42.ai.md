This is a **substantive review** of Kristofer Karlsson’s patch addressing the quarantine alternate-ref performance bug. Justin Tobler engages directly with the root cause: the lack of an explicit ODB transaction concept in Git’s process model. His review suggests a cleaner architectural fix—making the connectivity check a first-class part of the ODB transaction interface—rather than the current path-comparison hack in `odb.c`.

The key new proposal is to introduce an `odb_transaction_files_check_connected()` callback for the files backend. This would let `receive-pack` invoke `git rev-list` with the correct environment (quarantine dir as primary, no self-referential alternate) without relying on fragile path matching. Justin frames this as a natural extension of the ongoing ODB abstraction work (Patrick Steinhardt’s domain), positioning it as a long-term solution rather than a stopgap.

He also downplays the urgency for other quarantine-affected processes (like pre-receive hooks), noting that the connectivity check is the only operation where the double-listing of refs causes measurable harm. This narrows the scope of any follow-up work, making the callback idea more tractable.

The review is **tested-level in spirit**—Justin doesn’t claim to have run the code, but his technical reasoning (e.g., "we don’t expect `git rev-list` to write objects") suggests deep familiarity with the quarantine machinery. Expect this thread to pivot toward Patrick Steinhardt or other ODB contributors for feedback on the callback approach. The patch’s current workaround remains a viable short-term fix, but Justin’s alternative could supersede it if the ODB maintainers agree.
