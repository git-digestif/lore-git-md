This is a refactoring patch for the `git check-ref-format` built-in command.

The patch converts the command from manual option parsing to Git’s standard `parse-options` API. This brings `check-ref-format` in line with the rest of Git’s built-ins, eliminating duplicated argument-handling logic while preserving all existing functionality—normalization, branch-name support, and refname validation. The change touches only `builtin/check-ref-format.c` and is mechanical in nature: the new `struct option` array mirrors the old manual parsing loop, and the rest of the command’s behavior remains unchanged.

The commit message is clear and concise, explaining both the *what* (switch to `parse-options`) and the *why* (consistency with other built-ins). No new features or edge cases are introduced, so the patch looks like a straightforward cleanup that should be uncontroversial.
