This is the third patch in Justin Tobler’s four-patch series that fixes a critical ODB transaction bug when Git uses compatibility hashes and batch fsync. The series is already merged to `seen` and is ready for integration.

This patch extracts the logic for writing a loose-object index file into a new helper function, `loose_object_map_write()`. The helper takes an explicit loose object map and a file descriptor, allowing callers to write the index to any location—not just the primary object directory. This refactoring is a prerequisite for the next patch, which implements the core fix by merging two loose-object-idx files (from temporary and primary object directories) during ODB migration.

The change is mechanical and uncontroversial: it moves the writing loop from `repo_write_loose_object_map()` into the new helper, leaving locking and path handling to the caller. This design ensures atomicity and avoids race conditions when reading preexisting indices. Patrick Steinhardt’s review of v2 found no issues with this refactoring, and the v3 update adds only minor documentation clarifications.

The patch touches only `loose.c` and introduces no behavior changes. It is a clean, well-motivated refactor that enables the atomic migration logic in the next patch. No further review concerns are outstanding.
