This is the first patch in a **bugfix series (v2 1/4)** targeting the object database (ODB) layer. It addresses a **locking timeout issue** in the loose-object index ("loose-object-idx") file, which tracks compatibility hashes (e.g., SHA-1/SHA-256 interop). The patch replaces the **indefinite lock timeout (`-1`)** with a **finite 1000ms timeout**, preventing hangs if a process dies while holding the lock and leaves a stale lockfile.

The change is minimal and surgical: it introduces `LOOSE_OBJECT_IDX_LOCK_TIMEOUT_MS` (set to 1000ms, matching the default for `core.packedRefsTimeout`) and updates the two callers in `loose.c` to use it. The motivation is clear—avoiding indefinite hangs is a correctness fix, and the timeout value aligns with existing Git conventions. This directly resolves one of Patrick Steinhardt’s **blocking concerns** from the v1 review, where he flagged the indefinite timeout as a risk.

The patch is **well-motivated and uncontroversial**, touching only the locking mechanism without altering the loose-object-idx’s on-disk format or merge logic. It’s a prerequisite for the later patches in the series, which rely on finite timeouts to avoid deadlocks during atomic writes. The commit message is concise but sufficient, and the code change is straightforward.

**Key details**:
- **File touched**: `loose.c` (6 insertions, 2 deletions).
- **New constant**: `LOOSE_OBJECT_IDX_LOCK_TIMEOUT_MS` (1000ms).
- **Behavior change**: Lock acquisition now fails after 1000ms instead of retrying indefinitely.
- **Subsystem**: Loose-object storage, compatibility-hash extension.
- **Test coverage**: The series includes a regression test (`t/t1016-compatObjectFormat.sh`), but this patch itself is not directly tested—its correctness is validated by the later patches’ behavior.

This patch is **ready for review** and unlikely to draw further debate. The timeout value (1000ms) is reasonable, and the change is a clear improvement over the indefinite timeout. The series as a whole is a **high-priority fix** for ODB stability, and this patch is a necessary first step.
