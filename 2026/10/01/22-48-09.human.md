This is Junio’s "What’s cooking in git.git" report for October 2026, summarizing the current state of integration branches and in-flight topics. It is not a patch but a meta-report, so the digest focuses on what a busy reader needs to know about the project’s pulse this month.

The report covers 45 topics, 11 of which have already graduated to `master` since the last update. The most notable graduates are:

- **`hn/history-squash`** – the experimental `git history` command now supports a `squash` subcommand that folds a range of commits into one and replays descendants on top.
- **`ps/ref-storage-format`** – the project has standardized on the phrase “ref storage format” across command-line options, environment variables, and configuration keys, replacing older inconsistent terminology.
- **`ps/odb-alternates-at-creation`** – alternates setup is now deferred to object-database creation time during clone, removing an ad-hoc alternate-writing API and simplifying the ODB backend interface.
- **`kn/receive-report-hook`** – a new `report` hook in `git receive-pack` allows the server to filter or modify the packet-line status report sent back to the client after reference updates.

Among the new topics queued for review, two performance-related patches stand out:

- **`jk/xdiff-size_t`** – the xdiff/merge-ll machinery has been converted from signed `long` to `size_t` for buffer sizes and offsets, fixing subtle overflows on LLP64 architectures and plugging uninitialized-memory leaks on error paths.
- **`tb/repack-cruft-less-midx-corner-cases`** – a series of fixes to ensure reachability closure when writing MIDX bitmaps after incremental repacks that omit cruft packs or include explicitly kept packs.

The report also highlights a few user-facing changes:

- **`pm/replay-add-signing-support`** – the experimental `git replay` command now supports GPG-signing commits (`-S`) and properly handles intermediate commit-creation failures.
- **`pw/checkout-m-conflict-labels`** – when recreating a merge conflict with `git checkout -m`, the original conflict labels (branch names) are now preserved in `.git/MERGE_LABELS` instead of being replaced with generic ones.
- **`hn/object-name-push-short`** – the `@{push}` notation now has a short-hand `@{p}`, mirroring the existing `@{u}` for `@{upstream}`.

On the CI/build front, **`hn/ci-leak-sanitizer-annotations`** improves the GitHub Actions experience by annotating leak test failures with file and line numbers and stopping the leak-sanitizer script at the first failure to avoid log flooding.

The report closes with a reminder that the next release due by the end of 2026 will be called Git 2.98, preparing for Git 2.99 in spring 2027. No major integration surprises are evident; the topics in `next` appear stable and are likely to graduate in the coming weeks.
