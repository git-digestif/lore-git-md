This is the third and final patch in Patrick Steinhardt's series introducing subcommand grouping to Git's parse-options API, applied here to `git refs`. It reorganizes the `git refs` subcommands into three logical groups—"Reference database", "Reading references", and "Writing references"—to make the help output more scannable.

The patch updates `builtin/refs.c` to use the new `OPT_GROUP` and `OPT_SUBCOMMAND_H` macros (introduced in the earlier patches) to define the groups and assign descriptive help text to each subcommand. The usage strings in the help output are reordered to match the new grouping, and the `git-refs.adoc` man page is updated to reflect the new structure (notably moving `optimize` into the "Reference database" section). The diff shows the mechanical changes to the option array and the reordering of usage strings.

This is a straightforward usability improvement with no behavioral changes beyond the help text. The grouping is well-motivated by the growing number of `git refs` subcommands, and the implementation is clean and consistent with the new API. The patch includes both code and documentation updates, and the changes are unlikely to be controversial. The series as a whole is foundational work for future high-level commands like `git objects`.
