This is the second patch in Taylor Blau’s eight-patch v2 series fixing MIDX reachability closure corner cases. It targets a specific bug in `git pack-objects --stdin-packs=follow` where trees and tags in included or excluded-open (`!`) packs (or loose objects with `--unpacked`) are not walked if no commit reaches them, breaking the MIDX’s invariant that it contains all objects reachable from its tips.

The patch adds trees and tags from these sources as extra roots in an `oidset` (replacing the `oid_array` from v1) and walks them after the initial commit traversal. This preserves path prefixes for delta attributes and name hashes, though tags can still introduce commits in the second walk, making path selection best-effort. The fix is narrowly scoped to the `--stdin-packs=follow` mode and includes four new tests in `t5331-pack-objects-stdin.sh` to verify tree-only input packs, excluded-open tags, and delta attribute handling, plus one test in `t7704-repack-cruft.sh` to confirm loose tree descendants are rescued during geometric repacks.

The commit message is thorough, explaining the regression’s origin (commit 5ee86c273bf), the algorithmic trade-offs, and the limitations of the two-walk approach. Jeff King’s substantive review of v1 endorsed the patch as a strict improvement while questioning whether a single traversal could suffice; Taylor Blau acknowledged the concern but deferred deeper traversal machinery changes to future work. The v2 implementation addresses Derrick Stolee’s feedback by using an `oidset` for `extra_roots` and adds a comment clarifying the non-NULL requirement of `stdin_packs_context.revs` (per Junio’s surface-level review).

This patch looks well-crafted and uncontroversial. It fixes a real issue with clear test coverage and minimal risk of unintended side effects. The only open question—whether the two-walk approach is the best long-term solution—does not block this fix, which is a net improvement over the status quo. The series as a whole remains on track for serious review.
