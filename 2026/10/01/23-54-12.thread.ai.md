Subject: [PATCH] merge-ort: fix --no-overwrite-ignore regression with directory rename detection
Series version: standalone patch (v1, now with implementation)
Originating author: Coy Geek (reporter), Aniket Gupta (patch author)
Thread type: bug report / regression fix

Core problem or goal
The `--no-overwrite-ignore` option in the `merge-ort` strategy is documented to prevent Git from overwriting untracked, ignored files during a merge. However, when directory rename detection moves a tracked file into a path that already contains an ignored, untracked file, Git silently overwrites the ignored file instead of aborting the merge. This regression violates the documented contract of the option and risks data loss for users who rely on it to protect local configuration, credentials, or build artifacts.

Current status
Patch v1 posted by Aniket Gupta; under review. The issue is confirmed across Git versions 2.54.0 through 2.56.0.138. The reproduction script demonstrates the problem in three configurations: `merge.directoryRenames=true`, `merge.directoryRenames=conflict`, and the default. In all cases, the ignored file is overwritten, and the merge either succeeds (exit 0) or reports an unrelated "file location" conflict (exit 1) without mentioning the ignored file. A control case confirms that direct collisions (without rename detection) are correctly blocked.

Key technical details
- **Subsystems/files touched**: `merge-ort.c`, `merge-ort.h`, `builtin/merge.c`, and test file `t/t7600-merge.sh`.
- **Behavior change**: The fix restores the documented behavior of `--no-overwrite-ignore` when directory rename detection is active, ensuring that ignored files are not overwritten. It also corrects the trivial-merge path in `builtin/merge.c`, which previously ignored the option.
- **New/renamed symbols**: `preserve_ignored` bit in `struct merge_options`.
- **Test coverage**: Two new tests in `t/t7600-merge.sh` cover direct collisions and directory rename scenarios. The expected outcome is an aborted merge with a clear error message when an ignored file would be overwritten.
- **On-disk format changes**: None.

Open questions and loose ends
- The exact code path in `merge-ort.c` that handles directory renames and needs to respect `--no-overwrite-ignore` has been identified and fixed.
