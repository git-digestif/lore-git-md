Subject: [PATCH] merge-ort: fix --no-overwrite-ignore regression with directory rename detection
Series version: standalone patch (no prior iterations)
Originating author: Coy Geek
Thread type: bug report / regression fix

Core problem or goal
The `--no-overwrite-ignore` option in the `merge-ort` strategy is documented to prevent Git from overwriting untracked, ignored files during a merge. However, when directory rename detection moves a tracked file into a path that already contains an ignored, untracked file, Git silently overwrites the ignored file instead of aborting the merge. This regression violates the documented contract of the option and risks data loss for users who rely on it to protect local configuration, credentials, or build artifacts.

Current status
Under review; no prior versions of this patch exist. The issue is confirmed across Git versions 2.54.0 through 2.56.0.138. The reproduction script demonstrates the problem in three configurations: `merge.directoryRenames=true`, `merge.directoryRenames=conflict`, and the default. In all cases, the ignored file is overwritten, and the merge either succeeds (exit 0) or reports an unrelated "file location" conflict (exit 1) without mentioning the ignored file. A control case confirms that direct collisions (without rename detection) are correctly blocked.

Key technical details
- **Subsystems/files touched**: `merge-ort.c` and related merge strategy logic.
- **Behavior change**: The fix will restore the documented behavior of `--no-overwrite-ignore` when directory rename detection is active, ensuring that ignored files are not overwritten.
- **Test coverage**: The reproduction script covers three directory rename configurations and a control case for direct collisions. The expected outcome is an aborted merge with a clear error message when an ignored file would be overwritten.
- **New/renamed symbols**: None introduced in this patch; the fix will likely involve modifying existing logic in `merge-ort.c`.
- **On-disk format changes**: None.
