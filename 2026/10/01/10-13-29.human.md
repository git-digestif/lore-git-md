This is a refactoring patch to the parse-options API, part of a three-patch series from Patrick Steinhardt. It extends the existing `OPT_GROUP()` macro so that it can also group subcommands, not just options. The new `OPT_SUBCOMMAND_H()` macro lets a subcommand carry a help-text description, and such subcommands now appear under their group header in the usage output.

The patch touches the core `parse-options.c` file, its header, the technical API documentation, and adds a test case. The diff is mostly mechanical: it splits the usage-formatting logic into a branch for subcommands versus options, so that subcommands can be printed without the usual `--long-name` or `-s` syntax. The test demonstrates that a subcommand with a description appears under its group, while one without remains hidden.

The motivation is straightforward: as Git grows more subcommands (especially in built-ins like `git replay` or `git maintenance`), grouping them visually in the help output makes the interface more navigable. The change is backward-compatible; existing subcommands without descriptions continue to work exactly as before.
