This is a refactoring patch in the MIDX reachability-closure series, now at v2 with eight patches. It is patch 6/8, part of the structural improvements to the MIDX write steps.

The patch addresses a technical debt issue in `repack-midx.c` where the preferred pack for a MIDX compaction step is currently determined by scanning the string-list for the last entry marked with `util = 1`. This forces the list to remain unsorted, preventing efficient membership checks. The fix introduces a new field, `preferred_pack`, in the `midx_compaction_step` struct to explicitly track the preferred pack, allowing the string-list to be sorted without affecting the selection logic.

The change is mechanical and narrow: it removes the linear scan through the string-list, replaces it with direct access to the `preferred_pack` field, and updates the compaction plan logic to set this field instead of marking list entries. The patch does not alter behavior or on-disk format, but it prepares the codebase for the subsequent patch (7/8), which will sort the string-list to enable binary search.

The commit message is clear and concise, explaining the problem, the solution, and the motivation (enabling sorted lists for efficiency). The patch itself is small (16 lines changed) and touches only `repack-midx.c`. It is uncontroversial and aligns with the series' goal of making the MIDX machinery more robust and maintainable. No test changes are needed, as the patch is purely internal refactoring.
