This thread is about a regression in Git’s `merge-ort` strategy where the `--no-overwrite-ignore` option fails to protect ignored files when directory rename detection moves a tracked file into a path containing an ignored file. The issue, reported by Coy Geek, risks data loss for users who rely on the option to safeguard local files like configurations or build artifacts.

Aniket Gupta has submitted a patch that fixes the problem by ensuring the `--no-overwrite-ignore` option is properly propagated through the merge machinery. The patch introduces a `preserve_ignored` flag in `struct merge_options`, updates the trivial-merge path in `builtin/merge.c`, and adds two new tests to verify the fix works for both direct collisions and directory renames. The implementation is minimal and addresses existing FIXME comments in the code.

The patch is under initial review, with no feedback yet. It touches `merge-ort.c`, `merge-ort.h`, and `builtin/merge.c`, and adds tests to `t/t7600-merge.sh`. No prior versions of this patch exist, and the fix is specific to the `merge-ort` strategy, leaving other merge strategies unaffected. The patch is ready for technical review and should resolve the regression cleanly.
