This thread concerns a regression in Git's `merge-ort` strategy where the `--no-overwrite-ignore` option fails to protect ignored untracked files when directory rename detection is active. Coy Geek reported the bug with a reproduction script showing that across Git versions 2.54.0 through 2.56.0.138, a tracked file moved via directory rename detection silently overwrites an existing ignored file instead of aborting the merge, creating a data-loss risk. Aniket Gupta has posted a v1 patch that fixes the issue by adding a `preserve_ignored` bit to `struct merge_options`, plumbing it through `merge-ort.c`, and correcting the trivial-merge path in `builtin/merge.c`, along with two new tests in `t/t7600-merge.sh`.

The patch remains under review with no technical feedback received yet. Aniket Gupta has sent a follow-up ping specifically nudging Elijah Newren, the merge-ort maintainer, to review the fix. Nothing has been agreed or merged; the series is still at v1 and awaiting substantive review to confirm the approach and test coverage are correct.
