This is a bugfix for `git filter-branch` that corrects a commit mapping inversion regression in the `--state-branch` feature, introduced in Git 2.50.0. The patch is now in its second version and has received substantive, tested reviews from Michele Locati and Patrick Steinhardt, confirming both the bug and the fix. The issue occurs when `git filter-branch` reads commit mappings from the state branch in the wrong order ("to_commit:from_commit" instead of "from_commit:to_commit"), leading to errors like "Is a directory" during incremental runs with `--prune-empty`.

Patrick Steinhardt’s reply here is a surface-level review focused on the commit message and test hygiene. He suggests improvements to the commit message—adding the commit that introduced the regression (f6d855091e), rewriting it in imperative mood, and reordering the trailers to place the `Signed-off-by` last. He also proposes a minor test cleanup: adding `test_when_finished rm -rf incremental` to ensure the test directory is removed even if the test fails. These are all mechanical suggestions; the technical substance of the patch remains unchanged and well-supported by existing reviews.

The patch itself is minimal (two lines in `git-filter-branch.sh`) and now has comprehensive test coverage, including a new test case contributed by Michele Locati that directly verifies the commit mapping correctness in incremental runs with `--prune-empty` and `--subdirectory-filter`. The only remaining loose end is the typo in the patch subject ("fiter-branch"), which Patrick previously advised can be handled either by the maintainer during merge or via a new patch version. This is a well-scoped, uncontroversial fix that looks ready for merging once the commit message is adjusted.
