This is the first patch in a v2 series that fixes timezone handling in the reftable backend. The series addresses a spec violation where Git stores reflog timezones in `[+-]HHMM` format, but the reftable specification requires signed offsets in minutes. This patch introduces helper functions to convert between the two formats, consolidating scattered ad-hoc logic.

The patch adds `tz_to_minutes()` and `minutes_to_tz()` to `date.h` and updates existing call sites in `apply.c`, `date.c`, and `strbuf.c` to use them. The implementation retains C89-compatible behavior for division on negative values, though the commit message notes this is technically unnecessary in C99. Junio C Hamano’s feedback on v1 led to improved clarity in the helper functions, particularly around sign handling.

This is a refactoring patch that prepares the ground for the actual on-disk format change in patch 3. It’s mechanical, well-explained, and touches only date/time utilities—no user-visible behavior changes yet. The new helpers are immediately exercised by the existing code paths, so the patch is effectively self-testing. No controversy or open questions remain; the patch looks ready for integration.
