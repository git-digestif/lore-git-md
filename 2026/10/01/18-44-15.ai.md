This is the second patch in a two-part CI/build system series (v4) that improves GitHub Actions failure reporting by making test failures and fixed known breakages point directly to the exact line in the test script where they occur.

The patch adds two new helper functions in `t/test-lib-github-workflow-markup.sh`: `github_escape_message_` (which percent-encodes `%` characters to avoid GitHub misinterpreting them as its own escape sequences) and `find_test_case_line_` (which locates the line number of a test by searching the script for its description as a fixed string). The `finalize_test_case_output` function is updated to use these helpers, replacing generic annotations with precise, file-and-line-specific GitHub Actions annotations. When a test description cannot be found verbatim (e.g., because it is dynamically generated), the patch falls back to line 1, a pragmatic compromise that ensures annotations are always emitted.

The escaping logic is now minimal and focused: it only handles `%` characters, addressing Phillip Wood’s concern about overreach while still handling the common case of format atoms like `%(raw)` in `for-each-ref` tests. The line-finding logic is similarly pragmatic, using `grep -F` to avoid regex corruption from special characters in test descriptions. The patch ensures annotations are written before any `--immediate` exit, preventing them from being silently dropped.

The unresolved issues from earlier iterations remain: the GitHub Actions UI does not make the annotations clickable, and dynamic test descriptions still fall back to line 1. However, these are usability refinements rather than correctness problems, and the patch’s core functionality is sound. The series is cooking in `next` and appears ready for broader testing. The changes are well-motivated, narrowly scoped, and address a real pain point for reviewers.
