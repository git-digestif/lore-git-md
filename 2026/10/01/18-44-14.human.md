This is the first patch in a two-part CI/build system series that improves GitHub Actions failure reporting for leak sanitizer jobs. The patch stops leak-sanitizer test scripts at the first failure (using `--immediate`) and adds GitHub Actions annotations that link the leak to the test script where it occurred, with the full sanitizer output placed in a collapsible log group.

The change is motivated by a real pain point: leak failures currently produce only a generic "Process completed with exit code 1" message, with no indication of which test script failed or what the leak was. The `--immediate` flag prevents later tests in the same script from falsely reporting "not ok" due to leftover sanitizer log entries, while the annotation ensures the failure remains visible. The patch also reorders the `test_failure_()` function to write annotations *before* any `--immediate` exit, preventing them from being silently dropped.

The implementation touches `ci/lib.sh` (adding `--immediate` to `GIT_TEST_OPTS` for leak sanitizer jobs), `t/test-lib-github-workflow-markup.sh` (adding helper functions for annotations and leak output), and `t/test-lib.sh` (reordering annotation logic). The new `finalize_test_leak_output` function points annotations at line 1 of the test script (since the exact line isn’t known) and wraps the sanitizer output in a collapsible log group.

This patch is part of a series that has been cooking in `next` and addresses all substantive review feedback from earlier versions. The remaining open questions—such as the lack of clickable links in the GitHub Actions UI and the handling of dynamic test descriptions—are usability refinements rather than correctness issues. The change is narrowly scoped, well-explained, and directly improves the developer experience for CI failures.
