This is a bugfix for `git filter-branch` that corrects a commit mapping inversion regression introduced in Git 2.50.0. The patch is now in its second version and has received thorough review and testing from Michele Locati and Patrick Steinhardt, confirming both the bug and the fix. Junio’s email is a maintainer review of the patch, asking for clarification on one test change and suggesting a minor test cleanup.

The core issue is straightforward: `git filter-branch --state-branch` stores commit mappings in "from_commit:to_commit" format but was reading them back as "to_commit:from_commit", causing the map directory to be populated backwards. When `--prune-empty` is used, this leads to commits that map to nothing, and on subsequent runs the script attempts to create files with empty names, emitting "Is a directory" errors. The fix itself is minimal—just two lines in `git-filter-branch.sh`—and the test coverage has been significantly expanded to directly verify the commit mapping correctness in incremental runs with `--prune-empty` and `--subdirectory-filter`.

Junio’s questions focus on the test changes. He asks for an explanation in the commit message for why the existing state-branch test was updated to use a failing tree filter (`exit 1`) instead of a no-op (`touch file || :`). The intent is to ensure the test fails immediately if the tree filter is incorrectly re-run, making it clear that the state branch is the only reason HEAD remains unchanged. He also suggests adding a `test_when_finished rm -fr incremental` cleanup before the new test, though he acknowledges this is a minor nit and the current approach (leaving the directory for potential future tests) is also reasonable.

The patch is otherwise ready: it is self-contained, well-motivated, and now has comprehensive test coverage. The only remaining loose ends are the typo in the patch subject ("fiter-branch") and the commit message adjustments Patrick Steinhardt requested (naming the regressing commit and using imperative mood). Junio’s review does not raise any technical concerns, so once the test explanation is added to the commit message, this looks like a strong candidate for merging.
