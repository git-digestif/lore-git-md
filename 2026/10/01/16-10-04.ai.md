This is a bugfix for `git filter-branch` that corrects a commit mapping inversion regression in the `--state-branch` feature, introduced in Git 2.50.0. The patch is now under Junio C Hamano’s review as a standalone v2, following substantive feedback and tested confirmation from Michele Locati and Patrick Steinhardt.

The core issue is straightforward: the state branch file stores commit mappings in "from_commit:to_commit" format, but the code was reading them as "to_commit:from_commit", causing the map directory to be populated backwards. This leads to errors like "Is a directory" when `--prune-empty` is used, as the script attempts to create files with empty names on subsequent runs. The fix is a minimal two-line change in `git-filter-branch.sh` that splits each line on the colon and writes the `to_commit` into the file named by the `from_commit`, matching the documented format.

Junio’s review focuses on two points: the test update in the existing state-branch test and the new test case. The existing test change replaces a no-op tree filter (`touch file || :`) with one that fails (`exit 1`), ensuring the state branch is the only reason HEAD remains unchanged. Junio asks for clarification on this change in the commit message, which is currently missing. The new test case, contributed by Michele Locati, directly verifies the commit mapping correctness in incremental runs with `--prune-empty` and `--subdirectory-filter`, ensuring the state branch file contains correctly ordered entries. Junio also raises a minor test hygiene question: whether to add `test_when_finished "rm -fr incremental"` before creating the new repository, or leave it as-is if future tests will reuse the repository.

The patch is now technically complete, with comprehensive test coverage that fails on current `master` without the fix and passes with it.
