This is a **substantive review reply** in the ongoing `rerere` race-condition fix series. The email confirms the final design decisions for the second patch, which introduces a `--skip-locked` mode for `git rerere gc` to allow auto-maintenance tasks to skip the operation silently if the lock is held.

Thomas Bachem accepts Patrick Steinhardt’s feedback on two key points: **documentation placement** and **flag naming**. The caller-specific phrasing will be removed from `git-rerere(1)` and instead documented in `Documentation/config/rerere.adoc` under `rerere.lockTimeout`, explicitly naming `git maintenance run --auto` and `git gc --auto` as the commands that skip the lock. The `--auto` flag will be renamed to `--skip-locked` and marked as hidden (undocumented), addressing Patrick’s concern that "auto" misleadingly implied heuristic behavior. The `RERERE_SKIP_LOCKED` flag in the third patch will be renamed to `RERERE_WARN_LOCKED` to avoid confusion with the new `RERERE_NOWAIT` flag.

Thomas also explored Patrick’s alternative suggestion of calling `rerere_gc()` directly from `builtin/gc.c` but rejected it because it would cause `git maintenance run` to die with exit code 128 and a lockfile message, breaking existing tests and user expectations. The `--skip-locked` option will remain for this series. The changes here are **cosmetic** (documentation and flag naming) and do not alter the core fix, which remains well-motivated and technically sound. The series is now one step closer to finalization, with only a v6 update for patch 2 pending.
