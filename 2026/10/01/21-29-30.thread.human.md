This thread is a maintainer’s guide from Junio C Hamano, serving as the project’s living documentation on how Git is managed and how contributors should engage. The key update is a clearer explanation of the integration branches—`maint`, `master`, `next`, and `seen`—in anticipation of Git 3.0. `master` is now explicitly framed as the stable branch for production-ready changes, while `next` is a staging area for polishing topics before they graduate, and `seen` remains an ephemeral collection of in-flight work with no guarantee of inclusion. The note underscores that topics in `next` or `seen` may still be dropped or rewritten, encouraging contributors to test against these branches to catch conflicts early.

Beyond the branch workflow, the guide covers practicalities: patch submission (following `SubmittingPatches` and `CodingGuidelines`), bug reporting (using `git bugreport` and Simon Tatham’s advice), and where to find archives (lore.kernel.org). It clarifies that the mailing list is the central hub for core development but points to GitHub issues for related projects like git-scm.com, Git for Windows, and the Pro Git book. The email also lists authoritative repositories for subprojects like `git-gui`, `gitk`, and localization files, reminding contributors to base patches on those trees rather than git.git. There’s no open debate here—this is a reference document, not a discussion thread.
