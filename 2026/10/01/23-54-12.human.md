This is a bug report about the `merge-ort` strategy. Coy Geek demonstrates that `git merge --no-overwrite-ignore` incorrectly overwrites ignored files when directory rename detection moves a tracked file into a path that already contains an ignored, untracked file. The protection works for direct collisions but fails when the destination path is generated by rename detection, leading to silent data loss in some cases and misleading conflict messages in others.

The report includes a minimal reproduction script that works in a throwaway repository, showing the problem with both `merge.directoryRenames=true` (silent overwrite) and the default `merge.directoryRenames=conflict` (overwrite followed by a rename conflict). The author tested across multiple Git versions (2.54.0 through 2.56.0) on macOS, confirming the bug is not version-specific.

This looks like a serious correctness issue: `--no-overwrite-ignore` is documented to protect ignored files, and users relying on it can lose unversioned data without warning. The reproduction script is clear and self-contained, making it easy for reviewers to verify the problem. The report is well-structured, with expected vs. actual behavior, and the author offers to test a patch.
