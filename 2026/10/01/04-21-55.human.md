This is a feature patch extending `git stash create` to support the `--include-untracked` (`-u`) and `--all` (`-a`) options, bringing it into parity with `git stash push` and `git stash save`. It is the second iteration (v2) of a patch series that addresses backward-compatibility concerns raised during the initial review.

The patch reuses the existing `do_create_stash()` helper and its internal `include_untracked` parameter, avoiding a separate code path. It adds proper option parsing with `PARSE_OPT_STOP_AT_NON_OPTION`, which prevents flags after the message from being misinterpreted as options — a key fix for script compatibility. The exit status behavior is also adjusted: `git stash create` now returns 0 (success) when no changes are found, matching the convention established by `git stash push` and documented in the commit message.

Test coverage is thorough, verifying short and long option forms, combined short options (`-ua`), the boundary between untracked and ignored files (including ignored-only worktrees), option parsing edge cases (like messages beginning with dashes), and the guarantee that `create` does not modify `refs/stash`, the index, or the working tree. The tests use isolated repositories to avoid cross-contamination.

The patch is well-motivated and cleanly implemented. It addresses a long-standing inconsistency in the stash command family without introducing new behavior or breaking existing scripts, provided the option parsing and exit status changes are accepted as intentional improvements. The backward-compatibility concerns raised in the first version appear to be resolved, making this a strong candidate for merging.
