Thread identity
Subject: RFC: porcelain workflow for sharing stashes through remotes
Series version: RFC (no patch version yet)
Originating author: Hanan Arshad
Thread type: feature proposal (RFC)

Core problem or goal
Extend `git stash` with porcelain commands to publish, list, import, and remove stashes through remotes, building on the existing `git stash export`/`import` plumbing. The goal is a transport-agnostic workflow that does not require new object formats, server-side services, or synchronization models.

Current status
Proposal stage; no patches posted. The author has a working prototype using existing plumbing commands and is soliciting feedback on four design questions: (1) remote ref namespace, (2) user-provided names vs. object-derived identifiers, (3) whether listing should fetch export commits to display stash messages, and (4) command naming.

Key technical details
- Subsystem: stash, remote ref management
- New porcelain commands proposed: `git stash publish`, `git stash list-shared`, `git stash import-shared`, `git stash remove-shared` (exact names still under discussion)
- Ref namespace under consideration: `refs/stashes/` (exact namespace still under discussion)
- No changes to stash object format or on-disk layout
- No new server-side requirements; uses normal push/fetch operations
- Listing behavior: whether to fetch export commits to show stash messages is an open question

Open questions and loose ends
1. Appropriate remote ref namespace for shared stashes (proposed: `refs/stashes/`)
2. Whether shared stashes should use user-provided names or object-derived identifiers
3. Whether listing should fetch export commits to display stash messages
4. Final command naming that fits with the existing `git stash` interface

Participant positions
- Hanan Arshad (author): proposes the workflow, seeks feedback on the four design questions, and demonstrates a working prototype using existing plumbing. No other participant positions recorded yet.

Related work
