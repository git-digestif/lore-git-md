This is the latest round of review feedback on the second patch in Harald Nordgren’s two-part CI/build system series, which aims to improve GitHub Actions failure reporting by making test failures and fixed known breakages point directly to their exact file and line in the test script.

Phillip Wood’s reply is a substantive technical review that homes in on a specific usability gap: the patch escapes percent signs (`%`) in test descriptions to avoid GitHub misinterpreting them as its own escape sequences, but it does not apply the same escaping to existing annotations elsewhere in the code. This inconsistency could cause GitHub to misparse those annotations, undermining the patch’s goal of reliable, actionable failure reporting. Phillip’s feedback is narrowly scoped and pragmatic, focusing on a single correctness issue rather than questioning the patch’s overall design or motivation.

The unresolved question is whether the escaping logic should be applied uniformly across all GitHub Actions annotations, or whether the patch’s current minimal approach (escaping only the new annotations) is sufficient. This is a technical detail with no clear consensus yet, and it does not block the patch’s core functionality. The series remains cooking in `next`, and this feedback is likely to be addressed in a follow-up iteration rather than requiring a major redesign.
