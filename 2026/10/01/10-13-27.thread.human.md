This thread introduces a small but useful usability improvement to Git’s command-line interface. Patrick Steinhardt has posted a three-patch series that refactors the parse-options API to support grouped subcommands, then applies this to `git refs` to organize its many subcommands into three logical categories: “Reference database,” “Reading references,” and “Writing references.” The result is a more scannable help output, making it easier for users to find the subcommand they need.

The series is under initial review, with no feedback yet. The implementation touches the parse-options API (`parse-options.{c,h}`), the `git refs` built-in (`builtin/refs.c`), and its documentation. The new `OPT_SUBCOMMAND_GROUP` macro and supporting infrastructure are designed to be reusable, setting the stage for similar grouping in future high-level commands like `git objects`. The changes are purely cosmetic—no behavior or on-disk format is altered—and the patch includes test coverage for both the API and CLI. If the series lands as-is, users will see a cleaner, more organized `git refs -h` output in the next release.
