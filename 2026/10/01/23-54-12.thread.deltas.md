## 2026/10/01

- [2026/10/01/23-54-12 by Coy Geek <coygeek@gmail.com>] Coy Geek reported a bug in merge-ort where `--no-overwrite-ignore` fails to protect an ignored, untracked file when directory rename detection moves a committed file to that file's path: with `merge.directoryRenames=true` the merge succeeds (exit 0) and overwrites the ignored content, and with the default `conflict` mode the merge stops with a file-location conflict but the ignored file has already been overwritten, losing unique unversioned data that `git merge --abort` cannot restore; a direct collision with the same path is correctly refused, so the protection is bypassed only for rename-detection destinations, reproduced on git versions 2.54.0 through 2.56.0 on macOS 27.
