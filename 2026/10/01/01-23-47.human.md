This is a bugfix for `git filter-branch` targeting a long-standing commit mapping inversion when `--state-branch` is used. The patch is now in its second version (`v2`), addressing the regression introduced in Git 2.50.0 where the state branch stored mappings in "from_commit:to_commit" format but read them back as "to_commit:from_commit". This caused the map directory to be populated backwards, leading to errors like "Is a directory" during subsequent runs, especially with `--prune-empty`.

The fix itself is minimal: a two-line change in `git-filter-branch.sh` that splits the line on the colon and writes the `to_commit` into the file named by the `from_commit`. The test coverage has been significantly improved in this version. Michele Locati contributed a new test case that directly verifies the commit mapping correctness in incremental runs with `--prune-empty` and `--subdirectory-filter`, ensuring the state branch file contains correctly ordered entries. This test fails on current `master` without the fix and passes with it, confirming the bug and the fix.

The patch has received substantive, tested reviews from Michele Locati and Patrick Steinhardt, who both confirmed the bug's existence and the fix's correctness. The only remaining loose end is the typo in the patch subject ("fiter-branch"), which Patrick Steinhardt advised can be handled either by the maintainer during merge or via a new patch version. The patch is well-motivated, includes thorough test coverage, and addresses a real issue affecting users who rely on `--state-branch` for incremental repository splitting. It looks ready for merging.
