This is a review comment from Junio C Hamano on the commit message of Kazumasa Shigeta’s patch extending `git stash create` to support `--include-untracked` (`-u`) and `--all` (`-a`). Junio’s feedback focuses on the *clarity and purpose* of the commit message, not the code itself. The review is substantive but narrowly scoped to documentation quality. Junio does not raise technical objections to the patch’s implementation, nor does he challenge the feature’s merit. Instead, he models how to rewrite the commit message to be more reader-focused, offering a concrete example of how to frame the `parse_options()` change in terms of user expectations rather than internal mechanics. His tone is direct but constructive, and he explicitly notes that the technical content is not wrong—just poorly communicated.

This feedback is worth noting for two reasons. First, it highlights a recurring theme in Git reviews: commit messages should prioritize *why* over *how*, especially for changes that affect user-facing behavior. Second, it underscores that even well-tested, backward-compatible patches can stall if their documentation fails to justify design choices clearly. The author will likely revise the commit message in a v3, but the underlying code and tests appear uncontroversial.
