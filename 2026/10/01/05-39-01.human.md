This is the second patch in a three-patch bugfix series for the reftable backend, targeting a segfault in the `dump-reftable -t` test helper. The issue arises from a mismatch between reftable's hash ID constants (`REFTABLE_HASH_SHA1`/`REFTABLE_HASH_SHA256`) and Git's (`GIT_HASH_SHA1`/`GIT_HASH_SHA256`), causing the helper to dereference a NULL pointer when looking up the hash algorithm. The fix adds an explicit switch statement to map reftable's hash IDs to Git's, ensuring the correct algorithm is used.

The patch is small (10 lines added, 1 removed) and surgical, touching only `t/helper/test-reftable.c`. It directly addresses the segfault without changing core functionality, making it a clear, low-risk fix. The commit message explains the root cause and the solution concisely, and the code change is straightforward. This segfault went unnoticed because `dump-reftable -t` isn't used in the test suite, but the next patch in the series will add a user, making this fix necessary.

The patch is part of a well-reviewed series (v2) that has already addressed feedback from Junio C Hamano and Karthik Nayak. No new objections or open questions remain, and the series is effectively ready for integration. The fix is unlikely to be controversial, as it resolves a clear bug with minimal impact.
