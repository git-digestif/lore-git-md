This is a feature patch extending `git stash create` to support `--include-untracked` (`-u`) and `--all` (`-a`) options, addressing the long-standing inconsistency with `git stash push` and `git stash save`. This is the second iteration (v2) of the series, responding to substantive review feedback from Phillip Wood on backward-compatibility concerns.

The patch now uses `PARSE_OPT_STOP_AT_NON_OPTION` to prevent option-like tokens after the message from being misinterpreted as flags, preserving script compatibility for messages containing dashes. It also explicitly maps the internal "nothing to create" status (1) to the public success status (0), aligning with the stash subcommand exit-status convention established in 786fc390465f. The commit message and documentation have been updated to clarify these behaviors, and test coverage has been expanded to verify option parsing edge cases, combined short options (`-ua`), and ignored-only worktrees.

The implementation remains clean, reusing the existing `do_create_stash()` helper and `INCLUDE_ALL_FILES` mode without introducing new code paths or on-disk format changes. The patch touches `builtin/stash.c`, `Documentation/git-stash.adoc`, and `t/t3903-stash.sh`, adding 83 lines of new tests that validate the new functionality while ensuring `create` continues to leave `refs/stash`, the index, and the working tree unmodified.

Key technical details for follow-up discussion:
- **Files modified**: `builtin/stash.c` (command implementation), `Documentation/git-stash.adoc` (documentation), `t/t3903-stash.sh` (test coverage).
- **Behavior changes**: `--include-untracked` (`-u`) and `--all` (`-a`) now supported in `git stash create`; exit status 1 (internal "nothing to create") mapped to 0 (public success); option parsing now stops at the first non-option message word.
- **New/renamed symbols**: None (reuses existing `do_create_stash()`, `INCLUDE_ALL_FILES`, and `PARSE_OPT_STOP_AT_NON_OPTION`).
- **Test coverage**: Verifies short/long option forms, combined short options, untracked/ignored file boundaries (including ignored-only worktrees), option parsing edge cases (e.g., `-- -f`), and preservation of no-change behavior.
- **Backward compatibility**: The patch now addresses Phillip Wood’s concerns about exit status and option parsing, but the discussion may continue around whether the exit status mapping is sufficient or if scripts might still rely on the old behavior.

The patch is well-motivated, thoroughly tested, and directly responds to prior review feedback. The remaining open question is whether the exit status mapping fully resolves the backward-compatibility risk, or if further adjustments (e.g., a configuration knob or deprecation period) might be needed.
