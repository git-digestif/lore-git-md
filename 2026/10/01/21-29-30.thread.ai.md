Provide a canonical, up-to-date reference for how the Git project is managed, how patches flow through integration branches, how to report bugs, and where to find project resources. The immediate trigger for this revision is preparation for a medium version bump (Git 3.0), which prompts a clarification of the roles of the integration branches.

Current status
The document is a living guide maintained by Junio; this email is the latest published revision. No merge or branch status applies—it is documentation, not code.

Key technical details
- Integration branches:
  • maint – stable branch for bug-fixes to the most recent release
  • master – stable branch for production-ready changes (target for the next feature release)
  • next – staging area for topics that look ready; topics here are polished before graduating to master
  • seen – ephemeral branch bundling all in-flight topics; no commitment to inclusion; rebuilt frequently
- Topics in next or seen may still be dropped or rewritten.
- Contributors are encouraged to test their work against next and seen to catch conflicts early.
- Patch submission: follow SubmittingPatches and CodingGuidelines.
- Bug reporting: use git bugreport and follow Simon Tatham’s advice.
- Primary archive: lore.kernel.org/git
- Non-core contributions (git-scm.com, Git for Windows, Pro Git book) use GitHub issues.
- Subprojects (git-gui, gitk, localization) have their own authoritative repositories.
