This is a performance-focused patch for the packed-refs backend, and Toon Claes has posted a **substantive review** that surfaces several subtle implications of the change. The patch itself remains well-motivated—it delivers a clear ~20 % speedup when deleting large numbers of packed refs—but Toon’s feedback reveals that the optimization comes with trade-offs that were not fully explored in the commit message.

The core idea is sound: instead of reformatting every ref entry with `fprintf()`, the patch copies unchanged entries verbatim from the snapshot using `fwrite()`. Toon’s review, however, identifies four sanitization steps that are bypassed when raw data is written:

1. **OID case preservation**: `oid_to_hex()` normalizes OIDs to lowercase; raw writes preserve whatever case was in the original file.
2. **Whitespace handling**: `next_record()` splits OID and refname on any whitespace; raw writes preserve tabs or multiple spaces.
3. **Refname validation**: invalid refnames that would previously be replaced with the zero OID are now written unchanged.
4. **Peel line handling**: broken peel lines (e.g., for malformed refnames) are copied verbatim instead of being omitted.

None of these are show-stoppers—Toon explicitly says he is not arguing against the patch—but they do represent observable behavioral differences that could matter for edge cases or future compatibility. The commit message currently treats the change as purely an optimization with no downsides; Toon’s feedback suggests it should at least acknowledge the trade-offs.

On implementation, Toon proposes splitting `write_packed_entry()` into two functions—one for formatted writes, one for raw writes—rather than overloading a single function with a `raw` parameter. This is a stylistic preference, but it would make the code easier to follow and might reduce the risk of mixing up the two modes. He also notes that the current implementation cleverly includes the peel line in the raw write, which is a nice win.

The patch is still likely to land, but the discussion now centers on whether the sanitization differences are acceptable and whether the implementation should be refactored for clarity. If you care about packed-refs performance or edge-case behavior, this thread is worth watching.
