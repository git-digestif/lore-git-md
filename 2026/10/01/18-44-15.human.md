This is the second patch in a two-part CI/build system series that improves GitHub Actions failure reporting. It makes test failures and fixed known breakages point directly to the exact line in the test script where they occur, replacing generic annotations with clickable links.

The patch adds a new helper function `find_test_case_line_` that searches the test script for the test description as a fixed string, using the first match. If the description is not found verbatim (e.g., when it is built dynamically at runtime), it falls back to line 1. Another helper, `github_escape_message_`, percent-encodes `%` characters in test descriptions to prevent GitHub from misinterpreting them as its own escape sequences. The `finalize_test_case_output` function is updated to use these helpers, emitting GitHub Actions annotations with the test script name, line number, and escaped description.

The changes are narrowly scoped to `t/test-lib-github-workflow-markup.sh` and address a real usability pain point: reviewers no longer have to manually search test scripts to locate failures. The escaping logic is now simplified to handle only `%` characters, resolving earlier concerns about overreach. The fallback to line 1 for dynamic descriptions is a pragmatic compromise, though the limitation is acknowledged.

The patch is part of a series that is cooking in `next` and has addressed all substantive review feedback. The remaining open question is whether the GitHub Actions UI will render the annotations as clickable links, but this is a limitation of the platform rather than the patch itself. The series is well-motivated and ready for broader testing.
