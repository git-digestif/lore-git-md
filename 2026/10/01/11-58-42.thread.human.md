This thread is about whether Git should include a helper script in its `contrib/` area to automate incremental rebase conflict resolution—a workflow used in projects like shadow-utils, Linux man-pages, and PostgreSQL. The discussion began with Alejandro Colomar’s minimal `git-rebase-walk` script, which rebases HEAD onto each commit in reverse topological order, stopping at conflicts for manual resolution. It has since expanded to include two bisection-based alternatives: Nico Williams’ `bisect-rebase.sh` (optimized for large histories) and Colomar’s newer `git-bisect-rebase` (a simplified, Git-like version of Nico’s script).

The core debate hinges on whether Git should endorse *any* such helper, given Junio C Hamano’s strong praise for the existing third-party tool `git-imerge` as a mature, effective solution. Junio and Patrick Steinhardt have both noted that `git-imerge` already addresses this workflow, raising questions about the need for a `contrib/` alternative. Colomar and Williams, however, argue for a shell-based solution, citing `git-imerge`’s stagnation (no updates in six years) and Python dependency as drawbacks. The latest exchange sees Nico conceding to Colomar’s simpler, single-parameter interface for `git-bisect-rebase`, effectively positioning it as the leading candidate if the project decides to include a helper.

Key unresolved questions remain: whether the project prefers a minimal script (`git-rebase-walk`), a more performant one (`git-bisect-rebase`), or neither; whether the workflow is broadly useful enough to justify inclusion; and how the naming (`git-bisect-rebase` vs. `git-rebase-walk`) and performance trade-offs (O(n) vs. O(k) conflict resolutions) will factor into the decision. The discussion has shifted from technical critiques to ergonomics and project fit, with Colomar’s `git-bisect-rebase` now the most likely contender if the maintainers approve inclusion. No decision has been made, and the thread’s outcome will depend on whether the project prioritizes minimalism, performance, or reliance on external tools.
