This thread is about whether Git should include a helper script in its `contrib/` area to automate incremental rebase conflict resolution—a workflow already supported by third-party tools like `git-imerge`. The discussion began with Alejandro Colomar’s `git-rebase-walk`, a minimal Bash script that rebases HEAD onto each commit in reverse topological order, but has since converged on `git-bisect-rebase`, a bisection-based alternative he developed with input from Nico Williams. This newer script simplifies Nico’s earlier `bisect-rebase.sh` (now deprecated) and aligns better with Git’s conventions, offering a single-parameter interface and improved performance for large histories.

The core question remains unresolved: whether Git should endorse *any* helper for this workflow, given Junio C Hamano’s strong endorsement of `git-imerge` as a proven, if unmaintained, solution. Junio’s praise for `git-imerge` ("one of the best things since sliced bread") suggests a preference for relying on the third-party tool, though he hasn’t explicitly ruled out `contrib/` inclusion. Patrick Steinhardt echoed this sentiment, arguing that the functionality would be better integrated directly into `git rebase` itself—a more ambitious effort he doesn’t expect Colomar to pursue. Meanwhile, Simon Richter proposed a conceptual extension: a bisection-based command that could also run tests to detect semantic conflicts, though this remains unimplemented.

The leading candidate for `contrib/` is now `git-bisect-rebase`, with Nico Williams and Colomar both endorsing its simplicity and performance (O(1) best-case, O(N log N) worst-case). The naming (`git-bisect-rebase` vs. `rebase-bisect`) and whether to include test execution (as Richter suggested) are still open, but the thread’s focus has shifted from technical design to project scope. Colomar has volunteered to polish `git-bisect-rebase` if there’s interest, but Junio’s and Patrick’s preference for `git-imerge` or native integration leaves its inclusion uncertain. For now, the script can be distributed separately under the `git-` namespace without project approval, but whether it belongs in `contrib/` remains an open question.
