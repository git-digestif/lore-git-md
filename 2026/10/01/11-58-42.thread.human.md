This thread is about whether Git should include a helper script in its `contrib/` area to assist with incremental rebase conflict resolution. The original proposal, `git-rebase-walk`, was a minimal Bash script automating a manual workflow used in projects like shadow-utils and PostgreSQL. The discussion has since converged on `git-bisect-rebase`, a bisection-based script by Alejandro Colomar that simplifies and improves upon earlier approaches. Nico Williams, the author of a now-deprecated alternative, has endorsed Colomar’s script as the best candidate for inclusion.

The core debate revolves around whether Git should endorse any such helper, given the existence of `git-imerge` (a third-party tool praised by Junio Hamano) and Patrick Steinhardt’s preference for integrating the functionality directly into `git rebase`. Colomar initially advocated for `contrib/` inclusion but now agrees with Steinhardt that the feature belongs in `git rebase` itself, proposing `--first-conflict` as a potential option name. Meanwhile, Phillip Wood has suggested extending `git rebase --update-refs` to automate rebasing interdependent branches, though Colomar argues this would be overly complex and inflexible for his use case. Nico Williams has clarified that `bisect-rebase` and `--update-refs` address distinct problems: the former is optimized for rebasing a single branch across large upstream histories, while the latter handles stacked branches.

The discussion remains open on several fronts. Junio’s endorsement of `git-imerge` and Steinhardt’s push for direct integration into `git rebase` leave the fate of `git-bisect-rebase` uncertain. Colomar’s latest email reinforces the need for a *multi-shot workflow*—manual control over rebase order—to handle complex dependency graphs, countering earlier proposals for automation. While `git-bisect-rebase` is the leading candidate for `contrib/`, its inclusion is not guaranteed, and the broader question of whether Git should provide any such helper remains unresolved. The thread has also surfaced new ideas, like Simon Richter’s proposal to integrate test execution into a bisection-based command, but these remain unimplemented. For now, Colomar plans to distribute the script separately under the `git-` namespace while pursuing integration into `git rebase`.
