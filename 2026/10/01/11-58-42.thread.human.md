This thread is about a proposed `contrib/` helper script, `git-rebase-walk`, authored by Alejandro Colomar, which automates an "iterative rebase" workflow for resolving large rebase conflicts incrementally. The script is a lightweight Bash alternative to third-party tools like `git-imerge`, which Patrick Steinhardt noted already addresses the same use case, albeit as an unmaintained Python tool.

Alejandro has clarified that the script is actively used in real-world projects (shadow-utils and Linux man-pages) and is seeking clarity on whether Git would include it in `contrib/` or if he should distribute it separately under the `git-` namespace. The discussion hinges on whether the project sees value in adding another tool for this workflow, given the existence of `git-imerge`, and whether the script meets Git’s standards for `contrib/` scripts. No technical objections have been raised, but the question of naming and project scope remains open. The thread is still in the early stages, with no decisions made yet.
