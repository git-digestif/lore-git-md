This thread is about whether Git should include a helper script in `contrib/` to assist with incremental rebase conflict resolution—a workflow where users resolve conflicts one commit at a time, rather than all at once. The discussion began with Alejandro Colomar’s `git-rebase-walk`, a minimal Bash script that rebases HEAD onto each commit in reverse order, but has since converged on `git-bisect-rebase`, a more efficient bisection-based alternative he developed with input from Nico Williams. The thread has clarified that the workflow must support *multi-shot* operation (manual control over rebase order) to handle complex dependency graphs, ruling out simpler single-shot designs.

Key participants include Junio C Hamano, who endorses the third-party tool `git-imerge` as a proven solution, and Patrick Steinhardt, who prefers integrating the functionality directly into `git rebase` rather than adding a standalone script. Colomar now plans to distribute `git-bisect-rebase` separately (e.g., via `manpages-utils`) while pursuing integration into `git rebase` itself, proposing `--first-conflict` as a potential option. Nico Williams has deprecated his own `bisect-rebase.sh` in favor of Colomar’s version, which is now the leading candidate for `contrib/` inclusion. Simon Richter has proposed a more ambitious bisection-based command that could also run tests to detect semantic conflicts, though this remains unimplemented.

The latest development comes from Phillip Wood, who suggests extending `git rebase --update-refs` to automate rebasing interdependent branches, eliminating the need for manual branch switching. His proposal would allow `git rebase --update-refs --rebase-merges main B` to handle branches A and B automatically, with "break" commands inserted to pause for inspection. This refines his earlier advocacy for a single-shot workflow, addressing Colomar’s concern that such an approach would break complex workflows. The discussion now centers on whether this built-in extension is feasible, or if the project should accept `git-bisect-rebase` as a stopgap. No maintainer decision has been made, and the broader question of whether Git should endorse any helper remains open.
