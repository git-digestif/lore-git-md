This thread introduces a new user-contributed helper script, `git-rebase-walk`, proposed by Alejandro Colomar. The script automates an iterative rebase workflow: it identifies all commits between the current HEAD and a specified target commit, then rebases HEAD onto each of those commits in sequence. The author uses this to break down large rebase conflicts into smaller, more manageable steps, avoiding the need to resolve everything at once. The script is written in Bash, is self-contained, and is offered for potential inclusion in Git's `contrib/` directory.

So far, the thread consists only of the initial proposal. There are no replies yet, so no feedback or decisions have been made about whether the script will be accepted, what changes might be needed, or where it would live in the codebase. The author has expressed willingness to refine the script if the project is interested, but no maintainer or reviewer has weighed in yet. The discussion is still open.
