This thread is about a proposed `contrib/` helper script, `git-rebase-walk`, by Alejandro Colomar, which automates an "iterative rebase" workflow to help users resolve large rebase conflicts incrementally. The script, written in Bash, uses existing Git commands (`git merge-base`, `git rev-list`, and `git rebase --onto`) to rebase HEAD onto each commit in reverse topological order between HEAD and a target commit. The author has offered to polish it for inclusion in Git's `contrib/` area if there is interest.

Patrick Steinhardt has responded with a substantive review, noting that the proposed workflow—resolving large rebase conflicts incrementally—is already addressed by `git-imerge`, a third-party tool that, while not updated in over six years, likely still works. His feedback raises the question of whether Git's `contrib/` area needs another tool for the same purpose, suggesting that the project may prefer to avoid duplicating functionality. The discussion is still in its early stages, with no decisions made about whether the script will be accepted or what changes might be required. The key open question remains whether the workflow is considered generally useful or too niche for inclusion.
