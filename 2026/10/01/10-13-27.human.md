This is a feature patch series introducing subcommand grouping for `git refs`. The series consists of three patches: the first fixes a minor parse-options bug, the second extends the parse-options API to support subcommand groups, and the third applies this to `git refs` to organize its growing list of subcommands into logical categories (database operations, reading, and writing).

The motivation is clear: `git refs` has accumulated enough subcommands that the usage output is becoming unwieldy. Grouping them makes the help text more scannable and reflects the natural division of functionality. The implementation touches the parse-options subsystem, which is shared infrastructure, so the change will be available for other commands (like the upcoming `git objects`) without further plumbing work.

The series looks well-structured: the API change is separated from the consumer, and the commit messages explain both the "what" and the "why". The new help output is shown in the cover letter, making the benefit immediately visible. This is a quality-of-life improvement that doesn’t change behavior but makes the tool more approachable for users. Worth watching if you care about CLI usability or the refs subsystem.
