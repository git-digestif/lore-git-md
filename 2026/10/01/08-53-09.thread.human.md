This thread is an early-stage RFC by Hanan Arshad proposing new porcelain commands to share Git stashes through remotes, building on the existing `git stash export`/`import` plumbing. The goal is a transport-agnostic workflow that avoids new object formats or server-side requirements. Four key design questions remain open: the remote ref namespace (e.g., `refs/stashes/`), whether to use user-provided names or object-derived identifiers, whether `list-shared` should fetch commits to display stash messages, and the final command naming (e.g., `git stash publish`).

So far, only Hanan and D. Ben Knoble have participated—Ben Knoble merely noted a duplicate RFC thread, while Junio C Hamano later speculated that the duplicate might have been accidental. No substantive technical feedback has been provided yet, so the proposal is still awaiting input from reviewers. The thread is in its initial phase, with no patches posted and no decisions made. If you’re interested in stash workflows or remote ref management, now is a good time to weigh in on the design questions.
