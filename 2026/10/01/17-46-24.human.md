This is the second review in Patrick Steinhardt’s three-patch series introducing subcommand grouping to Git’s parse-options API. Junio C Hamano responds to patch 2/3, which implements the core API changes for grouping.

Junio’s feedback is substantive but narrowly focused. He suggests a cleaner refactoring path: instead of adding a new `OPT_SUBCOMMAND_H` macro that accepts a help string (while leaving the existing `OPT_SUBCOMMAND_F` unchanged), he would prefer extending `OPT_SUBCOMMAND_F` to support help text directly. This would avoid introducing an incomplete variant and keep the API surface smaller. He also notes that extracting the option-formatting logic into a helper function would have made the patch easier to follow and reduced nesting depth.

The review does not question the overall goal or design—grouping subcommands is still seen as a valid improvement—but it does push for a more elegant implementation. No other concerns are raised; the feedback is purely about code structure and API design. This is a typical Junio review: precise, technically grounded, and aimed at long-term maintainability rather than immediate functionality. The ball is now back in Patrick’s court to decide whether to revise the patch accordingly.
