This is a bugfix for `git filter-branch` targeting the `--state-branch` commit mapping inversion regression introduced in Git 2.50.0. The patch is now in its second version (`v2`), addressing the core issue described in the thread: the state branch file stores mappings in "from_commit:to_commit" format, but the code was reading them as "to_commit:from_commit", causing the map directory to be populated backwards. This leads to errors like "Is a directory" when `--prune-empty` is used, as the script attempts to create files with empty names on subsequent runs.

The fix itself is a minimal two-line change in `git-filter-branch.sh`: the code now splits each line on the colon, assigns the parts to `from_commit` and `to_commit` variables, and writes the `to_commit` into the file named by the `from_commit`. This matches the documented "from_commit:to_commit" format and resolves the inversion. The test coverage has been significantly expanded in this version—Michele Locati contributed a new test case that directly verifies the commit mapping correctness in incremental runs with `--prune-empty` and `--subdirectory-filter`, ensuring the state branch file contains correctly ordered entries. This test fails on current `master` without the fix and passes with it, confirming the bug and the fix.

The patch touches only two files: the shell script and its corresponding test file (`t/t7003-filter-branch.sh`). The test changes include an update to the existing state-branch test (replacing a no-op tree filter with one that fails, ensuring the state branch is the only reason HEAD remains unchanged) and Locati’s new test, which exercises the exact scenario that triggers the bug—incremental runs with `--prune-empty` and `--subdirectory-filter`. The test now checks that the rewritten parents are used correctly and that the state branch file contains the expected "original:rewritten" entries.

This version incorporates feedback from substantive, tested reviews by Michele Locati and Patrick Steinhardt, both of whom confirmed the bug’s existence and the fix’s correctness. The only remaining loose end is the typo in the patch subject ("fiter-branch"), which Patrick Steinhardt advised can be handled either by the maintainer during merge or via a new patch version, depending on Junio’s preference. The patch is self-contained, well-motivated, and now has comprehensive test coverage, making it a strong candidate for merging. No on-disk format changes or new symbols are introduced.
