This is a bugfix patch from Patrick Steinhardt, part of a 3-patch series (this is the first patch). It targets the parse-options API, which is the core machinery Git uses to handle command-line flags across all built-in commands.

The bug is in the `--git-completion-helper` output format. When the first option in the list is skipped (for example, because it is a group header or a hidden option), the code still treats the *next* option as if it were the first, leading to a spurious leading space in the generated completion list. The fix is small: replace the pointer comparison `opts == original_opts` with a boolean flag that tracks whether anything has been printed yet.

The patch includes a test case in `t/helper/test-parse-options.c` that adds a group header as the first option, ensuring the bug is caught if it regresses. The change is mechanical and confined to `parse-options.c`; no other subsystems are touched.

Given the author and the test coverage, this looks like a solid, low-risk fix for a real (if minor) bug. It is unlikely to be controversial.
