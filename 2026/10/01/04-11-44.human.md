This is a bugfix patch (part 3 of 8) in Taylor Blau’s ongoing series to fix MIDX reachability closure corner cases. It targets a regression introduced in June 2025 (commit 5ee86c273bf) where incremental repacks could omit cruft packs from the MIDX when `repack.midxMustContainCruft` is set to "false". The result is a MIDX that isn’t closed under reachability, breaking bitmap generation.

The fix is simple and surgical: when `git repack` runs with `--incremental`, it now forces `midx_must_contain_cruft = 1`, ensuring cruft packs are included in the MIDX. The commit message explains the scenario clearly—an incremental repack can write a new commit and tree while leaving blobs they reference in a cruft pack—and the patch adds a concise comment in the code to document the reasoning. A new test in `t7704-repack-cruft.sh` verifies that the incremental repack can now successfully write a reachability bitmap.

This patch is uncontroversial and well-motivated. It addresses a real bug with minimal risk, and the test coverage is appropriate. The only caveat is that the separate `--write-midx=incremental` writer still needs its own handling, which is addressed later in the series (patch 8/8). For anyone tracking MIDX or bitmap correctness, this is worth reviewing.
