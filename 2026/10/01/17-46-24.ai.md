This is a **substantive review** of patch 2/3 in Patrick Steinhardt’s series introducing subcommand grouping to the parse-options API. Junio C Hamano engages with the implementation details, suggesting structural improvements to the code.

The review focuses on two main points. First, Junio observes that the patch makes the `usage_with_options_internal()` function more deeply nested by adding a new conditional branch for `OPTION_SUBCOMMAND`. He suggests refactoring the existing option-formatting logic into a helper function as a preliminary step, which would both simplify the patch and prevent excessive indentation.

Second, Junio critiques the API design: the patch introduces `OPT_SUBCOMMAND_H` (which accepts a help string) but leaves `OPT_SUBCOMMAND_F` (which accepts flags) unable to take help text. He argues that `OPT_SUBCOMMAND_F` should be extended to support help text directly, rather than introducing a new variant that is itself incomplete. This would avoid proliferating similar-but-incomplete macros and keep the API more consistent.

The review is technical and constructive, targeting code structure and API design rather than correctness or functionality. It does not object to the feature itself, but suggests a cleaner implementation path. No test results or performance measurements are reported; this is purely a design-level review. The feedback is likely to require a v2 of this patch, but the changes should be mechanical and non-controversial.
