This is a usability bugfix discussion about `git config --list --show-origin`. Patrick Steinhardt replies to Christophe Lohr’s report, agreeing that the current behavior—showing `.git/config` as a relative path—is confusing. He suggests two possible fixes: either always display the full absolute path, or adjust the relative path to be relative to the current working directory (rather than the repository root) when the user is not in the root.

Patrick raises a practical concern: whether changing the output format could break scripts that parse `--show-origin` and expect `.git/config` to be shown relative to the repository root. He considers the risk low but wants input from others before proceeding. The discussion is now open for broader feedback on the trade-off between consistency and potential compatibility issues. This is a minor but actionable issue, and the fix is likely to be uncontroversial if script breakage is deemed unlikely.
