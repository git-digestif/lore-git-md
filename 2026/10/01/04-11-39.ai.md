This is a bugfix patch (2/8 in the v2 series) targeting the multi-pack-index (MIDX) and cruft-pack machinery. It ensures that trees and tags in included or excluded-open (`!`) packs (and loose objects with `--unpacked`) are treated as roots during the `--stdin-packs=follow` traversal, preserving reachability closure in the MIDX.

The patch addresses a corner case where geometric repacks could produce MIDXs that omit objects reachable only from trees or tags, breaking bitmap generation. The fix introduces an `oidset` (`extra_roots`) to collect these objects during the initial traversal, then walks them afterward to preserve path prefixes for delta attributes and name hashes. Tags can introduce commits in the second walk, so path selection remains best-effort. The patch also updates the `git-pack-objects` man page to document this behavior.

Key changes include:
- Adding `extra_roots` to `stdin_packs_context` to track trees and tags from included/`!` packs or loose objects.
- Deferring the traversal of `extra_roots` until after the initial commit walk to prioritize path prefixes for delta attributes.
- Updating `add_loose_object()` to include trees and tags in `extra_roots` when `--stdin-packs=follow` is active.
- New tests in `t5331-pack-objects-stdin.sh` verify the fix for tree-only input packs, excluded-open tags, and delta attribute preservation. A test in `t7704-repack-cruft.sh` confirms that loose trees are correctly handled.

The patch is narrowly scoped to the `--stdin-packs=follow` logic and includes thorough test coverage. It incorporates feedback from v1, replacing the `oid_array` with an `oidset` for efficiency and semantic correctness. Jeff King’s substantive review of v1 raised concerns about the two-walk approach’s limitations, but the patch is a strict improvement over the status quo, and deeper traversal machinery changes are deferred. The fix is uncontroversial and ready for review.
