This is a CI/build system patch series that refines GitHub Actions failure reporting for Git's test suite. The two-patch v4 series is now cooking in `next` and addresses the long-standing problem of buried leak sanitizer and test failures in CI output.

The first patch stops leak-sanitizer test scripts at the first failure (using `--immediate`) and annotates leaks with the test script name and full sanitizer output in a collapsible log group. The second patch ensures regular test failures and fixed known breakages point directly to their exact file and line in the test script, making them clickable in the GitHub UI. Harald has simplified the escaping logic in this version, removing unnecessary carriage-return handling while still properly escaping percent signs in test descriptions.

The series is well-motivated and thoroughly iterated. Harald has addressed all substantive feedback from v3, including the `--immediate` exit ordering bug, non-portable `\r` escaping, and inconsistent output redirection. The commit messages now clearly explain the trade-offs (like stopping at the first leak to avoid false "not ok" reports from later tests) and the technical reasoning behind helper function design. The proof-of-concept GitHub Actions run demonstrates the feature working as intended.

One critical loose end remains: Phillip Wood's observation that the `linux-leaks` job output still doesn't produce clickable links in the GitHub Actions UI, contradicting the commit message's claim. This is a significant gap in functionality that may require adjustments to the annotation format or GitHub's parser. The dynamic test description problem (where line-finding logic fails for tests that build descriptions at runtime) also remains unaddressed, though the fallback to line 1 is acknowledged as a pragmatic compromise.

The series is otherwise ready for wider attention. It's a quality-of-life improvement that will make CI failures significantly easier to debug for contributors and reviewers. The changes are focused, well-tested, and unlikely to be controversial. If the clickable-links issue can be resolved, this should graduate to `master` smoothly.
