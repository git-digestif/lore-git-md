This is a refactoring patch in the MIDX reachability-closure bugfix series, now at v2 (8/8). It prepares the `repack-midx.c` codebase for the next patch (8/8), which will allow the append plan to skip packs already covered by the MIDX chain.

The patch defers allocation of the write step in `repack_make_midx_append_plan()` until the first pack is actually added, rather than pre-allocating it unconditionally when `opts->names->nr` is non-zero. This change is mechanical and does not alter behavior: the append plan still considers only newly written packs, preserving existing functionality. The motivation is to accommodate future logic where a non-empty candidate list no longer guarantees that a write step is needed (e.g., when packs are already covered by the MIDX chain).

The diff touches only `repack-midx.c`, moving the write-step allocation inside the loop that iterates over `opts->names` and introducing a `step` pointer that is initialized to `NULL` and set only when the first pack is processed. The `strbuf` is now declared outside the loop to avoid repeated initialization and release, and the loop structure is simplified by removing the conditional block that previously wrapped the write-step creation.

This is a narrow, uncontroversial refactoring that lays the groundwork for patch 8/8. No new tests are introduced here, as the behavior remains unchanged. The patch is part of the broader effort to ensure MIDX reachability closure in incremental repack scenarios.
