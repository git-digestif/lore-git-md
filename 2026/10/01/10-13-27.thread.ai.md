Subject: [PATCH 0/3] refs: introduce subcommand grouping to parse-options API
Series version: v2 (v1 previously)
Originating author: Patrick Steinhardt
Thread type: patch series

Core problem or goal
Refactor Git’s parse-options API to support grouped subcommands, then apply this to `git refs` to organize its many subcommands into logical categories (database operations, reading, writing). The immediate goal is to improve usability by making the `git refs` help output more scannable; the broader goal is to establish a reusable API for future high-level commands like `git objects`.

Current status
Under review; v2 posted incorporating Junio C Hamano’s feedback from v1. The series now consists of **four** patches: (1) a preparatory bugfix in `--git-completion-helper` output (leading space when first option is skipped), (2) a refactoring patch extracting option-formatting logic into helper functions (`usage_print_flag()` and `usage_print_option()`) to reduce nesting in `usage_with_options_internal()`, (3) the core API patch extending `OPT_SUBCOMMAND_F()` to accept an optional help string (eliminating the redundant `OPT_SUBCOMMAND_H()` macro from v1) and enabling subcommands to be grouped under `OPT_GROUP()` headings, and (4) **the application patch to `git refs`**, which organizes subcommands into three groups ("Reference database", "Reading references", "Writing references") and updates the man page to match. Junio’s stylistic suggestion (`shown` instead of `first`) and structural feedback (reducing nesting, API consistency) have been fully incorporated. No new reviews yet; no merge status reported.

Key technical details
- Files touched: `parse-options.{c,h}`, `builtin/remote.c`, `builtin/stash.c`, `Documentation/technical/api-parse-options.txt`, `t/t0040-parse-options.sh`, `t/helper/test-parse-options.c`, **`builtin/refs.c`**, **`Documentation/git-refs.adoc`**.
- New API: `OPT_SUBCOMMAND_F()` now accepts an optional `help` parameter (defaulting to `NULL` for backward compatibility); `OPT_SUBCOMMAND_H()` has been removed as redundant.
- Internal changes: `usage_print_option()` in `parse-options.c` now prints subcommands with help text under their group heading; the `shown` flag (renamed from `first` in patch 2/4) tracks whether a group has been printed.
- Behavior change: `git refs -h` now displays grouped subcommands under headings; `--git-completion-helper` output no longer emits a spurious leading space when the first option is skipped (fixed in patch 1/4). The `optimize` subcommand is moved to the "Reference database" section in the man page.
- Documentation updated: `api-parse-options.adoc` clarifies that groups apply to both options and subcommands with help strings; `git-refs.adoc` reflects the new grouping structure.
- No on-disk format changes; test coverage added for the new grouping behavior (subcommands with help text appear under their group heading in usage output).
- Backward compatibility: subcommands without help text (the default) are omitted from the usage output, preserving existing behavior.

Open questions and loose ends
- The extended `OPT_SUBCOMMAND_F()` API and grouping behavior need review to confirm they address the nesting and consistency concerns raised in v1.
- No substantive review yet on the CLI grouping (patch 4/4) beyond Junio’s brief "Nice." in v1; the updated implementation may still draw feedback.
- The API change requires callers to pass `NULL` explicitly for subcommands without help text, which could be seen as less intuitive, though the backward-compatible default mitigates this.
