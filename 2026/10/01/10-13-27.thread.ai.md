Subject: [PATCH 0/3] refs: introduce subcommand grouping to parse-options API
Series version: v1 (v2 pending)
Originating author: Patrick Steinhardt
Thread type: patch series

Core problem or goal
Refactor Git’s parse-options API to support grouped subcommands, then apply this to `git refs` to organize its many subcommands into logical categories (database operations, reading, writing). The immediate goal is to improve usability by making the `git refs` help output more scannable; the broader goal is to establish a reusable API for future high-level commands like `git objects`.

Current status
Under review; v1 posted, v2 planned. Junio C Hamano reviewed all three patches. Patch 1/3 is settled: Junio’s stylistic suggestion (`shown` instead of `first`) was accepted by Patrick Steinhardt. Patch 2/3 drew structural feedback: (1) excessive nesting in `usage_with_options_internal()` due to the new `OPTION_SUBCOMMAND` branch, suggesting a preliminary refactoring of the option-formatting logic into a helper function; (2) API inconsistency: `OPT_SUBCOMMAND_H` accepts a help string, but `OPT_SUBCOMMAND_F` (which accepts flags) cannot, making the API incomplete. Junio recommended extending `OPT_SUBCOMMAND_F` to support help text directly rather than introducing a new variant. Patrick has now accepted both suggestions and will incorporate them into v2. Patch 3/3 received a brief, positive "Nice." with no further commentary. No other reviews yet; no merge status reported.

Key technical details
- Files touched: `parse-options.{c,h}`, `builtin/refs.c`, `Documentation/git-refs.adoc`, `Documentation/technical/api-parse-options.txt`, test scripts in `t/`, and `t/helper/test-parse-options.c` (new test for the bugfix).
- New API: `OPT_SUBCOMMAND_GROUP`, `OPT_GROUP`, `OPT_SUBCOMMAND_H`, and supporting infrastructure in `parse-options.h`; `OPT_SUBCOMMAND_F` will be extended to accept a help string in v2.
- New symbols: `parse_options_add_subcommand_group`, `struct subcommand_group`, plus the internal `shown` flag in `parse_options()` (renamed from `first`); a new helper function (name not yet finalized, e.g., `format_option()` or `print_option_usage()`) will be introduced in v2 to refactor option-formatting logic.
- Behavior change: `git refs -h` now displays grouped subcommands under headings “Reference database”, “Reading references”, and “Writing references”; `--git-completion-helper` output no longer emits a spurious leading space when the first option is skipped.
- Man page updated: `git-refs.adoc` reordered to match new grouping, with `optimize` moved to the “Reference database” section.
- No on-disk format changes; test coverage added for both API and CLI.
