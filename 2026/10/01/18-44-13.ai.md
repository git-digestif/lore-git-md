This is a CI/build system patch series (v4 of 2/2) that improves GitHub Actions failure reporting by linking leak sanitizer failures and regular test failures directly to the test script line where they occur.

Harald Nordgren has iterated the series to address all substantive feedback from v3. The key changes in v4 are clarifications in the commit messages and a simplification of the escaping logic: the `github_escape_message_` helper now only escapes percent signs (`%`), dropping the previous attempt to also escape carriage returns (`\r`). This resolves Phillip Wood’s concern that the escaping was overkill for single-line test descriptions, while still handling the common case of format atoms like `%(raw)` in `for-each-ref` tests.

The series remains split into two focused commits. The first stops leak-sanitizer scripts at the first failure (using `--immediate`) and annotates leaks with the test script name and full sanitizer output in a collapsible log group. The second ensures regular test failures and fixed known breakages point to their exact file and line in the test script. Both commits now ensure annotations are written before any `--immediate` exit, preventing them from being silently dropped.

The critical loose end from v3—the lack of clickable links in the GitHub Actions UI—remains unresolved. Harald’s proof-of-concept CI run confirms the issue, but the annotation format or GitHub’s parser may need adjustment. The dynamic test description problem (where line-finding logic fails for tests that build descriptions at runtime) is also still open, though the fallback to line 1 is acknowledged as a pragmatic compromise.

The series is cooking in `next` and appears ready for broader testing. The changes are well-motivated, narrowly scoped, and address a real pain point for reviewers. The remaining open questions are usability refinements rather than correctness issues, and the simplification of escaping logic in v4 reduces complexity without sacrificing functionality.
