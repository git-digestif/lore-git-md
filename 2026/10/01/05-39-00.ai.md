This is the first patch in the v2 series fixing timezone handling in the reftable backend. It introduces two new helper functions in `date.h`/`date.c`: `tz_to_minutes()` converts the traditional Git timezone format (`[+-]HHMM`) to signed minutes, and `minutes_to_tz()` does the reverse. The patch updates existing call sites in `apply.c`, `date.c`, and `strbuf.c` to use these helpers, consolidating previously ad-hoc timezone conversion logic.

The implementation retains C89-compatible behavior for division on negative values, using explicit sign-flipping to ensure consistent truncation toward zero. This addresses a historical edge case where C89 left the behavior of negative division implementation-defined. Junio C Hamano's review of v1 endorsed this approach for clarity, even though the mathematical outcome is unchanged from the original code.

Key technical details include the new public API (`tz_to_minutes()` and `minutes_to_tz()`), the retention of the sign-handling dance in `gm_time_t()`, and the updated `local_time_tzoffset()` function which now uses `minutes_to_tz(offset) * eastwest` for better transparency. The patch touches four files and lays the groundwork for the reftable backend's timezone format fix in patch 3.

No new objections or open questions remain for this patch. The changes are mechanical and well-motivated, with clear test coverage implications for the series' later patches. The patch is effectively ready for integration as part of the broader reftable timezone fix.
