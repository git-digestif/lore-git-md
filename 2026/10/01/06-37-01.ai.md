This is a usability bugfix discussion targeting the configuration subsystem. Patrick Steinhardt replies to Christophe Lohr’s report about `git config --list --show-origin` displaying `.git/config` as a relative path (`file:.git/config`), which can mislead users about the repository’s actual location.

Patrick agrees the current behavior is confusing but raises two considerations. First, he suggests an intermediate solution: when the user is not in the repository root, the path could be made relative to the current working directory rather than the repository root, which might reduce confusion without fully switching to absolute paths. Second, he flags a potential compatibility concern: scripts parsing `--show-origin` output might expect `.git/config` to always be relative to the repository root, and changing that could break them. He acknowledges the risk is low but invites broader input.

The discussion is now open for others to weigh in on the trade-off between usability and backward compatibility. No patch has been proposed yet, and the thread remains in the exploratory phase. This is a minor but actionable issue that could be resolved with a small display-layer change and a new test in `t/t1300-config.sh`.
