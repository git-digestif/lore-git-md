This is the second patch in Patrick Steinhardt’s v2 series fixing timezone handling in the reftable backend. It addresses a segfault in the `test-tool dump-reftable -t` subcommand, which is currently unused in the test suite but will be needed in the next patch.

The bug occurs because the reftable library’s hash ID constants (`REFTABLE_HASH_SHA1`, `REFTABLE_HASH_SHA256`) do not match Git’s internal constants (`GIT_HASH_SHA1`, `GIT_HASH_SHA256`). The code attempts to map the reftable hash ID to Git’s hash algorithm table, but the lookup fails, resulting in a NULL pointer dereference. The fix replaces the broken lookup with an explicit switch statement that correctly maps reftable’s hash IDs to Git’s.

The change is minimal (10 insertions, 1 deletion) and confined to `t/helper/test-reftable.c`. It introduces no new symbols or behavior changes beyond fixing the segfault. The patch is a prerequisite for the next commit, which will add a test case that exercises `dump-reftable -t`.

This is a straightforward bugfix with no known downsides. The fix is well-motivated and aligns with the series’ goal of improving reftable interoperability. The patch is unlikely to be controversial and appears ready for integration.
