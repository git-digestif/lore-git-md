This is the latest round of discussion on the second patch in Harald Nordgren’s two-part CI/build system series, which aims to make GitHub Actions test failure annotations point directly to the exact line in the test script where the failure occurred.

Phillip Wood’s reply homes in on a lingering inconsistency: while the patch now escapes percent signs (`%`) in test descriptions to avoid GitHub misinterpreting them as its own escape sequences, it does not apply the same escaping to existing annotations elsewhere in the code. He calls this puzzling, given that the same problem (e.g., `for-each-ref` format atoms like `%(raw)`) can corrupt those annotations too. The observation is substantive but narrow: it does not question the patch’s core functionality, only its completeness. Harald has not yet responded, so the thread remains open on this point. The rest of the series—including the first patch’s leak-sanitizer improvements—is cooking in `next` and appears uncontroversial.
