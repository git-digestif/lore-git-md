Thread identity: standalone RFC proposing a new `contrib/` helper script, `git-rebase-walk`, authored by Alejandro Colomar. The script automates an "iterative rebase" workflow for resolving large rebase conflicts incrementally by rebasing HEAD onto each commit in reversed topological order between HEAD and a target commit.

Core problem or goal: provide a built-in, lightweight alternative to third-party tools for incrementally resolving rebase conflicts, with the goal of inclusion in Git's `contrib/` area.

Current status: initial proposal; no prior discussion or versions. The script is offered as-is, with the author volunteering to polish it if there is interest. Patrick Steinhardt’s review notes that the workflow is already addressed by `git-imerge`, a third-party tool that, while unmaintained, likely still functions. This raises the question of whether Git’s `contrib/` area needs another tool for the same purpose.

Key technical details: the script is a short, self-contained Bash script using `git merge-base`, `git rev-list`, and `git rebase --onto` to implement the workflow. It does not modify Git's C code, build system, or test suite; it would live in `contrib/` if accepted. No new Git symbols, CLI options, or on-disk formats are introduced.

Open questions and loose ends:
- Whether the project wants such a helper in `contrib/`, given the existence of `git-imerge`.
- Whether the script meets Git’s coding and documentation standards for `contrib/` scripts.
- Whether the workflow is considered generally useful or niche, and if it justifies inclusion alongside or instead of `git-imerge`.

Participant positions:
- **Patrick Steinhardt**: notes that `git-imerge` already addresses the same workflow, implying that the need for `git-rebase-walk` is questionable. The review is substantive (engages with the problem space and existing solutions) and carries medium weight.

Related work: `git-imerge`, a third-party tool for incremental merging/rebase, mentioned as a pre-existing solution for the same workflow.
