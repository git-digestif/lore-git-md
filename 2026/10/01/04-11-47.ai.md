This is patch 4/8 in the v2 series fixing MIDX reachability closure corner cases. It is a refactoring patch that prepares the codebase for a subsequent fix (patch 5/8) by improving how explicitly kept packs are tracked.

The patch replaces a linear search through `--keep-pack` arguments with a sorted list and binary search. Currently, `existing_packs_collect()` performs a linear scan of the `extra_keep` list for each local pack, which is inefficient when the list grows. The change sorts the `keep_pack_list` using `fspathcmp()` and replaces the manual loop with `string_list_has_string()`, making the search O(log n) instead of O(n). The patch also documents the requirement that `extra_keep` must be sorted and use `fspathcmp()` as its comparator.

This is a mechanical refactoring with no behavior change. The motivation is to avoid duplicating the clunky for-loop in a future caller (patch 5/8) that will also need to search the kept-pack list. The change is small (8 insertions, 7 deletions) and touches only `builtin/repack.c`, `repack.c`, and `repack.h`. The commit message clearly explains the rationale and the technical details, including the sorting requirement.

The patch is uncontroversial and well-justified. It is a prerequisite for patch 5/8, which addresses a performance pitfall with `.keep` packs during geometric repacks. The sorting step is performed once at the start of `cmd_repack()`, so the overhead is negligible compared to the work `git repack` is about to perform. The change is narrowly scoped to the repack subsystem and does not affect MIDX behavior directly.
