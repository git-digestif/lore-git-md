## 2026/11/07

- [2026/11/07/19-54-28 by Tanga Joris <tangajoris@gmail.com>] Tanga Joris posted [Outreachy PATCH 1/2] "apply: do not keep names from an unused 'diff --git' line", which frees patch->def_name, old_name, and new_name when a "diff --git" line is followed by a non-git-header line (such as a blank line or an indented "new file mode"), fixing the check_preimage assertion `patch->is_new <= 0' crash in `git apply --check` for new files and in `git apply -R` for deletions with such headers, and causing an empty "diff --git" section followed by another section to be ignored rather than producing a "bad git-diff" error.
- [2026/11/07/19-54-29 by Tanga Joris <tangajoris@gmail.com>] Tanga Joris posted [Outreachy PATCH 2/2] "apply: reject new and deleted files that have both names", which makes parse_git_diff_header() reject a new file that also has an old name (when a "---" line precedes "new file mode") and a deleted file that also has a new name (when "+++ /dev/null" precedes "deleted file mode"), following d70e9c5c8c's approach of reporting conflicting header lines instead of hitting the assertion; the author noted the alternative of accepting "--- /dev/null" before "new file mode" as a new file.
