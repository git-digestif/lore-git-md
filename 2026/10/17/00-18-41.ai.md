This is a review follow-up to the second patch in Johannes Schindelin’s integer-overflow hardening series. The patch changes the `posn` variable in `http.c` from `int` to `size_t` to prevent a heap under-read when HTTP response bodies exceed `INT_MAX`.

Simon Richter replies to Junio’s confirmation that the type change is correct. He suggests using `off_t` instead of `size_t` for `posn`, arguing that `off_t` is the conventional type for file positions and is guaranteed to be 64-bit when large file support (`O_LARGEFILE`) is enabled. His comment is substantive but narrow: it engages with the type choice without questioning the patch’s overall goal or introducing new edge cases. The suggestion is technically plausible but does not address whether `size_t` (already approved by Junio and Patrick Steinhardt) would cause practical problems, nor does it resolve the broader `SSIZE_MAX` vs. `size_t` platform-compatibility question still open in patch 3.

No code changes or test adjustments are proposed here; the discussion remains focused on type-system conventions. The thread’s readiness for integration is unchanged, but this reply adds a minor point of contention that Johannes may need to address in a future revision.
