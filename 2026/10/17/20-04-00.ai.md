This is a bugfix for the files ref backend, addressing the loose ref cache inconsistency with root refs (`HEAD`, `ORIG_HEAD`, etc.). This is the v2 iteration of Andy Koppe’s patch, incorporating feedback from the initial review.

The core issue remains the same: root refs are inconsistently included in the loose ref cache depending on whether `REFS_FOR_EACH_INCLUDE_ROOT_REFS` was passed during the *first* cache creation. This v2 patch implements the same architectural approach as v1—keeping root refs out of the shared loose ref cache entirely and creating a separate temporary ref cache for them when requested—but now includes documentation corrections and minor code organization tweaks.

Key changes since v1:
- Moved `create_root_ref_cache()` below `get_loose_ref_cache()` for a cleaner diff.
- Corrected the documentation, help text, and `refs.h` comment for `--include-root-refs`, which previously mislabeled root refs as pseudorefs.
- Expanded the commit message to discuss alternative approaches, though the implementation remains unchanged.

The patch touches `files-backend.c`, `t/t6302-for-each-ref-filter.sh`, and documentation files. The test coverage is minimal but sufficient, verifying that `--include-root-refs` works correctly with `--merged`. Performance concerns raised in the initial review have been addressed: the overhead of creating a temporary root ref cache is negligible since the flag is only used in two places, both invoking it just once per command.

The discussion in the thread has narrowed to two architectural approaches: Andy’s original solution (temporary cache) and Junio’s proposed alternative (persistent dual caches). This v2 does not implement Junio’s suggestion, but the commit message now acknowledges it as a possible direction. The patch remains technically unblocked, with no outstanding objections to the current implementation. The reftable backend is unaffected.
