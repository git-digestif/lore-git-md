This is a follow-up in the ongoing discussion about Harald Nordgren’s patch to fix `branch.autoSetupMerge=inherit` when the starting point is a remote-tracking branch. The patch aims to align `inherit`’s behavior with the default (`true`) by setting up tracking for remote-tracking starting points, but Junio C Hamano’s review has expanded the scope to question the intended behavior for *all* starting points—tags, commit hashes, and local branches without tracking.

Harald’s latest reply clarifies his position: he wants the fix to apply *only* when the starting point is a remote branch, leaving the current behavior unchanged for other cases. He pushes back against Junio’s suggestion to introduce new config modes (`inherit-or-fail`, `inherit-or-direct`), calling it "overkill" for the problem at hand. However, he acknowledges that the original author of the `inherit` mode (CC’ed in the thread) might provide useful context about the original intent, particularly for non-tracking starting points.

The discussion remains unresolved. Junio’s preference is to preserve the current behavior (doing nothing for non-tracking starting points) and offer new modes as opt-in alternatives, while Harald’s patch proposes a narrower change focused solely on remote-tracking branches. The original author’s input could break the deadlock, but until then, the patch is unlikely to move forward without addressing the broader design questions. The thread is now a design discussion rather than a straightforward bugfix review.
