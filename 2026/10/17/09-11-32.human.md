This email from Luca Milanesio is a brief but significant update in the ongoing discussion about Git 3.0's ecosystem readiness, specifically addressing JGit's pluggable backend infrastructure. Milanesio corrects and expands on Johannes Schindelin's earlier characterization of JGit as a "gap" for SHA-256 support by providing concrete, production-scale evidence that JGit's pluggable backend architecture is not only technically viable but has been deployed at scale for over a decade.

He cites two major examples: Google's internal Git servers (including `gerrit.googlesource.com`), which have used a proprietary JGit backend built on the same open-source pluggable interfaces since the early 2010s, and GerritForge's open-source global refdb backend, which powers multi-site Gerrit deployments with globally consistent ref updates. The linked GitHub repository ([GerritCodeReview/modules_global-refdb](https://github.com/GerritCodeReview/modules_global-refdb)) serves as a reference implementation for distributed ref storage. Milanesio also notes that the Cassandra backend prototype mentioned by Daniele Sassoli aligns with modern demands for AI-driven storage optimizations, further validating the architecture's forward compatibility.

This shifts the narrative from "JGit is a technical obstacle" to **"JGit's pluggable backend is production-ready but underutilized"**, removing a key technical barrier to Git 3.0's ODB interoperability goals. The email does not propose new technical directions but provides actionable context for future coordination, emphasizing that resource constraints—not technical limitations—are the primary obstacle for SHA-256 support and broader adoption. Milanesio also invites Git community members to attend Google's upcoming talk at the Gerrit User Summit (October 23–24, 2026) on JGit's SHA-256 plans, offering a direct opportunity for collaboration. The tone is collaborative and solution-oriented, framing JGit as a complementary strength rather than a liability.
