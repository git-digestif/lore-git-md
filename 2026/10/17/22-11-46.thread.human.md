This thread is about fixing a severe performance regression in `git fetch` from shallow repositories over protocol v2, where fetches can take minutes instead of seconds due to inefficient history traversal. Harald Nordgren proposed a patch to align protocol v2 behavior with protocol v0 by directly advertising shallow grafts when no specific depth is requested, avoiding redundant traversal. The patch initially showed promising performance improvements (reducing fetch time from 7 minutes to 1 second) but was found to have a critical flaw: it misused the `packet_write_fmt` API instead of the `packet_writer` API, breaking sideband multiplexing and causing client-side crashes.

Junio C Hamano identified this issue in his review and provided a failing test case to guard against the protocol violation. Harald has acknowledged the feedback and intends to revise the patch to use the correct API while preserving the performance optimization. The thread is now focused on implementation correctness, with no objections to the underlying approach. The fix targets `shallow.c` and `upload-pack.c`, and the revised patch will need to pass Junio's test case to ensure protocol compliance. No other participants have weighed in, and the thread remains in a "needs revision" state.
