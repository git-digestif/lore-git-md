This thread is about a performance regression in `git fetch` from shallow repositories over protocol v2, where fetches can take minutes instead of seconds due to inefficient history traversal. Harald Nordgren proposed a single-patch RFC to fix this by aligning protocol v2's shallow commit advertisement with protocol v0's behavior, avoiding redundant traversal. The patch showed dramatic performance improvements (7 minutes → 1 second) but was flagged by Junio C Hamano for a critical correctness issue: it breaks protocol v2's sideband multiplexing by using the wrong API (`packet_write_fmt` instead of `packet_writer`), causing client-side crashes when interpreting raw 'shallow' lines as sideband data.

Junio’s review included a failing test case that reproduces the crash, confirming the protocol violation. While the underlying goal of the patch remains valid, the implementation now requires a rewrite to use the correct API while preserving the performance optimization. The thread is now in a "needs revision" state, with a clear technical direction for the next iteration. No other reviewers have weighed in yet, and the patch’s RFC status suggests the author is seeking feedback on both the approach and its correctness. The fix touches `shallow.c` and `upload-pack.c` and is self-contained to the upload-pack/shallow subsystem.
