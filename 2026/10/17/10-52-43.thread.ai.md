Subject: [PATCH] merge-blobs: remove implicit dependency on the_repository
Series version: standalone patch (part of the ongoing `the_repository` removal effort)

Core problem or goal
Eliminate the global `the_repository` variable from `merge-blobs.c` by making the repository pointer explicit in the call chain, specifically in `fill_mmfile_blob()`. This is a small, mechanical step in the larger project-wide effort to remove all implicit repository references.

Current status
Queued in `next` (marked ready for integration by Junio C Hamano). The patch’s core refactoring is uncontroversial and has passed review. The only prior discussion point—parameter naming (`r` vs. `repo`)—was resolved in favor of `r` after Junio explicitly rejected the proposed change, citing idiomatic consistency. No substantive technical concerns or behavioral objections have been raised.

Key technical details
- File modified: `merge-blobs.c`
- Function signature change: `fill_mmfile_blob()` now takes `struct repository *r` (consistent with libification idioms) instead of using the global `the_repository`
- Macro removed: `USE_THE_REPOSITORY_VARIABLE`
- Headers added: `read-cache-ll.h`, `repository.h`
- Caller (`merge_blobs()`) passes `istate->repo` as the repository argument
- Subsystem: low-level blob merging machinery used during conflict resolution

Open questions and loose ends
None. The patch is now in the integration pipeline (`next` branch) and is expected to graduate to `master` in due course. Junio noted a minor stylistic preference (introducing a local `repo` variable in `merge_blobs()` to avoid repeated `istate->repo` dereferencing) but explicitly stated this is not worth revisiting.
