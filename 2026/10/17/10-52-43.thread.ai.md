Subject: [PATCH] merge-blobs: remove implicit dependency on the_repository
Series version: standalone patch (part of the ongoing `the_repository` removal effort)
Originating author: Okhuomon Ajayi
Thread type: refactoring patch

Core problem or goal
Eliminate the global `the_repository` variable from `merge-blobs.c` by making the repository pointer explicit in the call chain, specifically in `fill_mmfile_blob()`. This is a small, mechanical step in the larger project-wide effort to remove all implicit repository references.

Current status
Under review, effectively ready for integration. The author previously planned to send a `v2` incorporating a stylistic naming tweak (`r` -> `repo`) suggested by a reviewer, but Junio C Hamano explicitly rejected that change, arguing that `r` is the idiomatic parameter name for `struct repository *` in the codebase. The reviewer (Usman Akinyemi) has now conceded, acknowledging that the naming difference is not significant enough to warrant a resend. The patch’s core refactoring remains uncontroversial; the only open item—parameter naming—has been resolved in favor of `r`.

Key technical details
- File modified: `merge-blobs.c`
- Function signature change: `fill_mmfile_blob()` now takes `struct repository *r` (consistent with libification idioms) instead of using the global `the_repository`
- Macro removed: `USE_THE_REPOSITORY_VARIABLE`
- Headers added: `read-cache-ll.h`, `repository.h`
- Caller (`merge_blobs()`) passes `istate->repo` as the repository argument
- Subsystem: low-level blob merging machinery used during conflict resolution

Open questions and loose ends
None. The sole unresolved item (parameter naming) has been resolved in favor of `r`; no substantive technical concerns or behavioral objections have been raised.
