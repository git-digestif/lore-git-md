This is the **first patch in v2 of the configurable index lock timeout series**, a refactoring that prepares the ground for the timeout feature by splitting the existing `repo_hold_locked_index()` function into two variants.

The patch introduces `repo_try_hold_locked_index()`, a non-blocking version of the index-locking function, and migrates all callers that currently use `repo_hold_locked_index()` with a zero timeout (i.e., those that treat the lock as optional) to the new function. These callers include `git commit`, `git describe`, `git diff`, `git merge`, `git rebase`, `git sequencer`, and `wt-status.c`. For now, the two functions are identical; the next patch will add the timeout logic to `repo_hold_locked_index()`.

The change is purely mechanical and does not alter behavior. It clarifies intent by separating "must-have-lock" callers (which will soon support waiting) from "optional-lock" callers (which will continue to fail immediately if the lock is unavailable). The patch touches nine files, adding 24 lines and removing 8, with no new symbols or on-disk format changes. Test coverage is unchanged; the new function is exercised by existing tests.
