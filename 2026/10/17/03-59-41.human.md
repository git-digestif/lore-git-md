This is a **bugfix review** from Junio C Hamano targeting the test suite in Mark C. Chu-Carroll’s v7 patch that adds revision filtering to `` `git repo structure` ``. The patch itself is otherwise ready for merging, but Junio identifies a **platform compatibility issue**: the new test cases hardcode SHA-1 object IDs (40-character hex strings) and will break when Git 3.0 switches the default hash function to SHA-256.

The problem is in ``t/t1901-repo-structure.sh``, specifically the new ``test_expect_success 'filter by object type'`` block. Junio points out that constants like ``97d808e45116bf02103490294d3d46dad7a2ac62`` are SHA-1 specific and will not match the 64-character SHA-256 OIDs. While the existing tests in the same file use the ``SHA1`` prerequisite to avoid running on SHA-256 builds, Junio notes this is a stopgap and encourages a more forward-looking fix.

He offers two options: either (1) refactor the test to be hash-agnostic, following recent patterns that allow the same test to run under both hash functions, or (2) add the ``SHA1`` prerequisite to the new test as a temporary workaround. The linked pull request (GitGitGadget #2252) provides an example of the preferred approach, but Junio leaves the choice to the author. No other issues with the patch are raised.
