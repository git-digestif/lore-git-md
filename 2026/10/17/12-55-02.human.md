This is the final patch in a five-part bugfix series for `git worktree repair`. It introduces validation to prevent the command from incorrectly modifying `.git` files or gitdirs that belong to unrelated worktrees. The patch directly addresses the core issue described in the series: without validation, `git worktree repair` could corrupt administrative files when worktree directories are manually swapped or copied, rather than moved using `git worktree move`.

The patch adds two key safeguards. First, `repair_gitfile()` now checks whether the worktree ID extracted from the `.git` file matches the expected `wt->id`; if not, it aborts with an "unrelated .git file" error. Second, `repair_worktree_at_path()` fails early if it cannot infer the gitdir path, avoiding repairs that could overwrite unrelated gitdirs. The `get_worktree_id()` helper, introduced in an earlier patch and hardened here, handles non-canonical path separators (backslashes, duplicate slashes) to ensure robust validation across platforms.

The test coverage is thorough, adding cases for skipping unrelated `.git` files, handling `.git` files with extra separators or Windows-style backslashes, and verifying the new error messages. The patch is narrowly scoped to `worktree.c` and the test script, with no changes to on-disk formats or user-visible behavior beyond the intended bugfix.
