This is a bugfix patch for the pretty-printing subsystem, specifically the `%w()` format specifier in `git log` and related commands. It addresses a long-standing but undocumented regression where indentation was lost after a newline followed by whitespace, breaking alignment in formatted output like commit messages or file lists.

The patch is a clear improvement: it surgically fixes the logic in `strbuf_add_wrapped_text()` to distinguish between line-wrapping (where skipping a space is correct) and hard line breaks (where it isn’t). The updated test cases and documentation make the behavior explicit, removing ambiguity that has existed since 2007. Junio and René have both signaled support for the change, provided the documentation is updated—which this version now includes.

The fix touches `utf8.c` and two test files, with no on-disk format changes. The commit message and documentation updates are thorough, explaining the problem, solution, and edge cases (like `%+d` decorations).
