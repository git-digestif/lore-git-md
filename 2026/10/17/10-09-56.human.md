This is the third patch in Beat Bolli’s three-patch v3 series addressing OpenSSL compatibility and correctness in `git imap-send`. It adds forward-compatibility macros for OpenSSL 4.0, which deprecates `SSL_set1_host()` in favor of `SSL_set1_dnsname()`. The patch is purely mechanical: it defines `SSL_set1_dnsname()` as an alias for `SSL_set1_host()` when compiling against OpenSSL versions older than 4.0, and updates the error message to reflect the correct function name.

The change is confined to `imap-send.c` and touches only the compatibility layer introduced in patch 2/3. No runtime behavior change is expected, and the patch is uncontroversial on its own. However, it is part of a series that remains blocked by a **security regression** in patch 2/3 (certificate stripping) and an **error-reporting regression** (hostname-specific error messages lost under `SSL_VERIFY_PEER`). This patch does not address either issue but ensures the series will compile cleanly when OpenSSL 4.0 is released.

The commit message is clear but minimal; it could usefully note that the new function takes the same parameters, avoiding the need for logic changes. The patch is well-timed: OpenSSL 4.0 is not yet released, so this is a proactive compatibility measure rather than a reactive fix. If you care about OpenSSL compatibility or `git imap-send`, this patch is a safe, incremental step, but the series as a whole will not land until the security and error-reporting regressions are resolved.
