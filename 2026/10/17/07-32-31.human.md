This is the fourth and final patch in Jun Wu’s v2 series introducing a configurable index lock timeout (`core.indexLockTimeout`) to reduce contention in IDE workflows. This patch specifically fixes a **pre-existing write-race condition in `git reset`** (present for over 20 years) by reordering the lock acquisition to follow the "lock → read → write" pattern, matching the earlier fix for `git commit` in Patch 3.

The change is narrow: it moves `repo_hold_locked_index()` to the start of the non-`--soft` code path in `builtin/reset.c`, ensuring the index is locked before being read. This eliminates a race window where concurrent updates (e.g., from `git add`) could be silently discarded if `reset` read the index before acquiring the lock. The patch also removes a redundant lock acquisition later in the function. The commit message frames this as a **correctness fix**, addressing feedback from Jeff King (Peff) that the lock-order changes should be motivated as such rather than just enabling the timeout feature.

No new tests are added here, as the existing `t0032-index-lock-timeout.sh` script already covers the timeout behavior, and the change is straightforward. The patch is conservative, touching only `builtin/reset.c` and leaving `--soft` resets (which don’t write the index) unchanged. With this fix, `git reset` now qualifies for the "waiting for index lock" behavior introduced in Patch 2, making it more resilient to lock contention in IDE-heavy workflows.

The series as a whole is now complete: Patch 1 refactors the lock API, Patch 2 implements the timeout, and Patches 3–4 fix the long-standing race conditions in `commit` and `reset`. The default 1-second timeout remains open to debate, but the implementation is careful to avoid amplifying existing race windows by skipping the timeout for commands that read the index before locking. This patch is a clean, well-motivated fix that rounds out the series. **Worth attention** for users who’ve encountered lock contention or subtle index corruption in concurrent workflows.
