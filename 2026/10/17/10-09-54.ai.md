This is the first patch in Beat Bolli’s three-patch v3 series targeting `git imap-send` OpenSSL compatibility. It replaces the deprecated `SSLv23_method()` with the modern `TLS_method()`, a purely mechanical API swap that has been the OpenSSL-recommended function since 1.1.0. The change is confined to `imap-send.c` and updates only two lines of code plus an error message; no runtime behavior change is expected.

The patch is uncontroversial and well-motivated: OpenSSL has been deprecating older TLS initialization functions for years, and this keeps Git from relying on APIs that may disappear in future releases. The commit message is concise but sufficient, citing the deprecation timeline and the replacement function. This patch was previously part of the v2 series and has already seen review; no new concerns have surfaced.

This v3 iteration is part of a broader effort to address regressions identified in the v2 series’ hostname verification patch (2/2). The v3 cover letter (not shown here) indicates that the series now includes a new patch (3/3) implementing Xiangfei Ding’s proposed verification callback to restore lost error context, while this patch (1/3) and the hostname verification rewrite (2/3) remain largely unchanged from v2. The security regression in v2 patch 2/2 (certificate stripping) is not addressed in this patch but is expected to be resolved in 2/3.

If you care about OpenSSL compatibility or `git imap-send`, this patch is a safe, incremental step forward. It is unlikely to draw further review scrutiny, but the series as a whole remains blocked on the security and error-reporting regressions in the hostname verification logic.
