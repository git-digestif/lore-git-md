This is an RFC proposing a new feature for `git branch --delete-merged` to handle branches whose upstream has been deleted by the hosting service (e.g., GitHub after merging a pull request). The author, DonQuinleone, is a first-time contributor to the list.

The problem: when a topic branch is merged on the server and its remote counterpart is deleted, `git branch --delete-merged` refuses to delete the local branch because its upstream is gone. This is by design (as noted in prior discussion), but it leaves users with no way to bulk-delete local branches that are provably merged into a named ref (e.g., `origin/master`). The current workflow requires manual deletion or scripting around `git branch -vv` and `merge-base`.

The proposal separates *selection* (branches with gone upstreams) from *proof* (the branch tip is reachable from a user-named ref). Two shapes are suggested:
- **(A)** A modifier like `--into origin/master` to `--delete-merged`, which would delete branches matching the pattern only if their tip is reachable from the named ref.
- **(B)** Composable filters like `--upstream-gone --merged=origin/master` to `-d`, which could also enable standalone listing of gone-upstream branches.

The author leans toward (A) for its simplicity and preservation of existing safeguards (e.g., worktree/stacked-branch exclusions). The RFC explicitly excludes squash/rebased merges from scope, aligning with the current strictness of `--delete-merged`. Harald Nordgren (author of related in-flight patches) and Phillip Wood (reviewer of prior work) are CC’d for context.

The included script demonstrates the issue: after fetching and pruning, a provably merged branch (via `merge-base`) is still skipped by `--delete-merged`. The patch touches the branch deletion logic in `builtin/branch.c`, but no implementation is provided yet—this is purely a design discussion. Key technical details: the change would involve passing a user-specified commit (e.g., `origin/master`) to `check_branch_commit()` instead of `HEAD` for gone-upstream branches.
