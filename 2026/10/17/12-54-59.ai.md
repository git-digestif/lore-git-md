This is the second patch in the five-part v3 series fixing a bug in `git worktree repair` where it could incorrectly modify unrelated worktrees. The patch refactors `repair_worktree_at_path()` to centralize and clarify the logic for selecting the inferred backlink, ensuring it is computed after reading the `.git` file but before validating the backlink’s gitdir.

The change reorders the processing steps so that the inferred backlink is always determined before any validation of the backlink’s gitdir. This makes the code easier to follow and ensures the inferred backlink is preferred when both a valid gitdir and an inferred path exist — a key edge case where a worktree was copied (rather than moved) alongside its main repository. The patch does not introduce new functions or change behavior; it is purely internal refactoring to reduce redundancy and improve clarity.

The diff shows the logic being moved and consolidated, with the inferred backlink now computed unconditionally after reading the `.git` file, and the validation of the backlink’s gitdir happening afterward. The commit message explains the motivation clearly: prioritizing the inferred backlink over the one read from the `.git` file when they differ, which handles the copy-vs-move ambiguity correctly.
