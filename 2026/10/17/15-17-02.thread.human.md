This thread is about a bug in `git apply --check` that causes Git to crash with an assertion failure when processing patches with malformed headers. The issue, reported by first-time contributor Gingrspacecadet, stems from long-standing logic errors in how Git parses new-file and deleted-file patches, specifically when `---` or `+++` lines appear before mode lines or when blank lines follow `diff --git` headers.

Tanga Joris proposed a two-part fix that has now been revised to adopt stricter validation, rejecting any patch header format not generated by `git diff` or `git format-patch`. This aligns with maintainer Junio C Hamano’s guidance and addresses concerns raised by Phillip Wood, who argued that Git should reject corrupt input outright rather than attempting to normalize it. The series now explicitly rejects patches with blank lines after `diff --git` or inconsistent header ordering, and it includes thorough test coverage in a new test file, `t/t4133-apply-filenames.sh`. The fix targets the `maint` branch and merges cleanly with `master`, `next`, and `seen`.

All key participants—Gingrspacecadet, Tanga Joris, Phillip Wood, and Junio—are now aligned on the stricter validation approach. The only remaining open questions are minor: whether the error messages are sufficiently clear and whether the handling of empty `diff --git` sections should be revisited. The series is technically complete and awaiting final review, likely by Eric Sunshine, to assess these last details before integration. No further philosophical debate is expected.
