This thread is about a bug fix for a Git crash in `git apply --check` when processing patches with malformed headers. The issue, reported by first-time contributor Gingrspacecadet, involves an assertion failure in `apply.c` caused by inconsistent patch header parsing, particularly when `---` or `+++` lines appear before `new file mode` or `deleted file mode` lines. The fix is now in its second iteration as a two-part series by Tanga Joris, addressing both the root causes and incorporating stricter validation rules endorsed by the maintainer, Junio C Hamano.

The series has evolved significantly from its initial version, which attempted to normalize some malformed headers, to now outright rejecting any patch format not generated by `git diff` or `git format-patch`. This stricter approach, advocated by reviewer Phillip Wood and endorsed by Junio, ensures that corrupt input—such as blank lines or indented mode lines after `diff --git`—is rejected with clear error messages. The fix targets the `maint` branch and merges cleanly with `master`, `next`, and `seen`, with thorough test coverage in a new test file, `t/t4133-apply-filenames.sh`.

The only remaining open questions are minor: whether the error messages are sufficiently actionable for users and whether the handling of empty `diff --git` sections should be revisited. However, the series is technically complete and aligned with maintainer expectations, with no further philosophical debate expected. The next step is final review, likely by Eric Sunshine, to assess error message clarity and the backwards-compatibility implications of rejecting previously accepted (but malformed) patches.
