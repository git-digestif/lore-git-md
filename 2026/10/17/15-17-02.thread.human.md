This thread began as a bug report from first-time contributor Gingrspacecadet about a Git crash in `git apply --check` when processing patches with malformed headers. The crash, triggered by an assertion failure (`patch->is_new <= 0` in `apply.c`), occurs when `---` or `+++` lines appear *before* `new file mode` or `deleted file mode` lines, respectively, or when blank lines or unrelated text follow the `diff --git` header. The issue affects released versions (2.43, 2.45.0, and `master`) and stems from long-standing logic errors in how the apply machinery parses and validates patch headers.

Tanga Joris submitted a three-part fix series that now fully addresses the root causes, review feedback, and edge cases. The series takes a strict validation approach—endorsed by Junio C Hamano and Phillip Wood—rejecting any patch header format not generated by `git diff` or `git format-patch`, including `diff --git` lines in commit message bodies (which are explicitly out of scope for `git apply`). Patch 1/3 fixes a memory leak in `parse_git_diff_header()`, enabling the reinstatement of a previously dropped test case. Patch 2/3 rejects patches with blank lines or indented mode lines after `diff --git`, while Patch 3/3 (the latest addition) explicitly rejects patches with inconsistent header ordering (`---` before `new file mode` or `+++` before `deleted file mode`). The series includes thorough test coverage in `t/t4133-apply-filenames.sh`, verifying both `--check` and actual application, including reverse application (`-R`). Error messages have been refined to reference problematic header lines (e.g., `"---" before "new file mode"`) instead of stripped filenames, improving clarity for users.

The fix is now technically complete and aligned with maintainer expectations. The only remaining edge case—empty `diff --git` sections followed by another `diff --git`—remains accepted (per prior precedent), though Junio has hinted this may warrant re-evaluation. The series targets `maint` and merges cleanly with `master`, `next`, and `seen`. Final review (likely by Eric Sunshine) is pending to confirm the memory leak fix and backwards-compatibility trade-offs, but no further debate is expected. The series is ready for graduation.
