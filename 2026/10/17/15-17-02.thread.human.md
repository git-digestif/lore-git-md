This thread is about a Git crash in `git apply --check` when processing a patch that creates a new file. The issue was first reported by Gingrspacecadet, a first-time contributor, and has since been confirmed as a long-standing bug in `apply.c`'s `check_preimage` function. The crash occurs due to an assertion failure (`patch->is_new <= 0`) triggered by a specific ordering of patch headers (`--- /dev/null` before `new file mode`) combined with a blank line after the `diff --git` header.

Tanga Joris, who helped narrow down the trigger, has identified the root cause and is actively working on a fix. The bug is reproducible across multiple Git versions (2.43, 2.54.0, and `master`), indicating it is not a recent regression. The crash affects `git apply --check` workflows, and while other `git apply` modes (e.g., `--index`, `--cached`) remain untested, the underlying parsing logic suggests they may also be impacted.

The next steps involve reviewing Tanga’s proposed fix to ensure it handles the edge case without breaking valid workflows. The original reporter’s patch, which was LLM-generated, is incidental to the bug itself—this is a general parsing issue in Git’s apply machinery. No workarounds or patches have been proposed yet, but the thread is now focused on resolving the crash.
