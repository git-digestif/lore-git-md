This is the second patch in Beat Bolli’s three-patch v3 series for `git imap-send`, replacing Git’s manual TLS hostname verification with OpenSSL’s built-in `SSL_set1_host()` API. The patch aims to achieve full RFC 6125 compliance (including IP-type SANs) and reduce maintenance burden, but it introduces **two critical regressions** that block the series: a **security regression** (certificate stripping) and an **error reporting regression** (loss of hostname-specific error messages).

The patch removes the manual `verify_hostname()` function and its helper `host_matches()`, replacing them with OpenSSL’s `SSL_set1_host()` and a new `verify_peer()` function. The new code sets `X509_CHECK_FLAG_NO_PARTIAL_WILDCARDS` to match Git’s prior behavior (rejecting partial wildcard matches like `*.example.com` for `foo.bar.example.com`). However, the removal of the `SSL_get_peer_certificate()` check creates a trivial MITM vector by allowing certificate stripping, and the new error path loses the hostname-specific error message when verification fails under `SSL_VERIFY_PEER`.

The commit message is clear about the motivation (OpenSSL’s built-in verification is more complete and future-proof) but does not mention the regressions. The diff is large (101 lines) but mechanical: the old verification logic is entirely replaced. The patch touches only `imap-send.c` and introduces no new configuration options or user-visible behavior changes beyond stricter RFC 6125 compliance. However, the security regression undermines this goal, and the error reporting regression reduces usability.

This patch is **not ready for merging** due to the unresolved regressions. The v3 series includes a new patch (3/3) implementing Xiangfei Ding’s proposed verification callback to restore the lost error context, but it does not address the security regression. Patrick Steinhardt’s review identified both regressions and highlighted the lack of test coverage for this security-sensitive code path. The series remains blocked until these issues are resolved.

If you care about `git imap-send` or OpenSSL compatibility, this patch is worth tracking, but the regressions make it a non-starter in its current form. The next iteration will need to restore the `SSL_get_peer_certificate()` check and ensure error messages remain informative. The absence of tests for these edge cases is a significant gap that should be addressed in any follow-up.
