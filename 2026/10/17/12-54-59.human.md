This is the second patch in a five-patch bugfix series for `git worktree repair`. The series addresses a correctness issue where the command could incorrectly modify `.git` files or gitdirs belonging to unrelated worktrees due to missing validation of cross-references between a linked worktree and its administrative data.

This patch refactors `repair_worktree_at_path()` to centralize the logic for selecting the inferred backlink, making the code clearer and easier to follow. The key change is reordering the processing steps so that the inferred backlink is computed after reading the `.git` file but before validating the backlink’s gitdir. This ensures the inferred backlink is preferred when both a valid gitdir and an inferred path exist, which is important for edge cases like copied worktrees (where the `.git` file might point to the original repository rather than the copy). The patch does not introduce new behavior but makes the existing logic more robust and maintainable.

The refactoring is straightforward and well-motivated, with no changes to user-visible behavior or on-disk formats. The commit message clearly explains the rationale, and the code changes are minimal and focused. This patch lays the groundwork for the validation logic introduced in patch 5/5, which prevents repairs on unrelated worktrees.
