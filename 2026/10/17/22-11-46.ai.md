This is a performance bugfix targeting the upload-pack subsystem, specifically addressing slow fetches from shallow repositories over protocol v2.

The patch fixes a regression where fetching from a shallow repository with a long history (e.g., 900k commits) can take minutes instead of seconds. The issue occurs because protocol v2 inefficiently traverses the entire history to determine which shallow commits to advertise, repeatedly visiting the same commits in merge-heavy histories. Protocol v0 avoids this by simply listing all shallow commits and letting the client handle them.

Harald Nordgren's solution aligns protocol v2 behavior with v0 when the client doesn't request a specific depth: it now advertises all shallow grafts directly rather than performing an expensive traversal. The change also ensures `git clone --reject-shallow` works consistently across both protocols. For operations like `git fetch --unshallow` that still require history traversal, the patch optimizes the walk to visit each commit only once.

The implementation touches two files: `shallow.c` (modifying the depth comparison logic) and `upload-pack.c` (replacing the deepen call with a simpler graft advertisement). The diff is minimal (4 insertions, 4 deletions) and focused on the core issue.

This appears to be a well-motivated fix for a real performance problem, with clear before/after measurements (7 minutes → 1 second) and a straightforward technical approach. The patch is marked as RFC, suggesting the author is seeking feedback on the solution's correctness rather than its necessity.
