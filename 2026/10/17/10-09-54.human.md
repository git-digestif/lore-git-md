This is the first patch in a three-patch v3 series updating `git imap-send` for OpenSSL compatibility. It replaces the deprecated `SSLv23_method()` with the modern `TLS_method()`, a purely mechanical change that keeps Git from relying on APIs OpenSSL has deprecated since 1.1.0. The patch touches only `imap-send.c` and updates an error message to match the new function name.

The motivation is clear and uncontroversial: OpenSSL’s documentation recommends `TLS_method()` as the replacement, and this patch aligns Git with that guidance. No runtime behavior change is expected, and the commit message cites the deprecation timeline and replacement function without overreaching. This is a safe, incremental step that should not draw objections.

This v3 series appears to be a follow-up to the earlier v2 effort, which split off the TLS initialization change from a larger, more contentious series addressing hostname verification and memory-safety issues. The earlier v2 patch 2/2 introduced a security regression (certificate stripping) and an error-reporting regression, blocking the series. This v3 patch is unchanged from its v2 counterpart, so it remains a straightforward, well-justified update.

If you care about OpenSSL compatibility or `git imap-send`, this patch is worth noting but unlikely to require deep attention. The real discussion is likely to focus on the later patches in the series, which must address the security and error-reporting regressions identified in v2.
