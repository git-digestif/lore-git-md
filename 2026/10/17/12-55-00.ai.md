This is the third patch in Yoichi NAKAYAMA’s five-patch v3 series fixing a bug in `git worktree repair` where the command could incorrectly modify unrelated worktrees. This patch refactors `infer_backlink()` to use the stricter `read_gitfile_raw()` helper (introduced in patch 1) instead of `strbuf_read_file()`, ensuring consistent `.git` file parsing with `repair_gitfile()`. The key change is that trailing whitespace in `.git` files is now treated as part of the path, which may cause the path to be rejected if it doesn’t reference a valid repository. The patch also extracts `get_worktree_id()` as a helper function, which will be reused in patch 5 to validate worktree IDs before repair.

The refactoring is purely internal and does not change behavior, but it aligns the parsing rules across the worktree repair codepaths. The new `get_worktree_id()` function replaces manual pointer arithmetic with a cleaner abstraction, improving readability. The patch touches only `worktree.c` and is a stepping stone for the validation logic in patch 5, which will prevent repairs on unrelated worktrees. No test updates are included here, as the behavior change (trailing whitespace handling) is subtle and will be covered in later patches. The patch is well-structured and directly addresses the series’ goal of making `.git` file parsing more robust.
