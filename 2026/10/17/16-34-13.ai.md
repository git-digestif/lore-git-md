This is a follow-up in the `git format-rev` deprecation thread, focusing on the feasibility of replacing `git format-rev` with `git diff-tree` for NUL-terminated pretty-printing. The author, Kristoffer Haugsbakk, corrects their earlier misunderstanding: while `git diff-tree` *does* support NUL termination (`-z`) for pretty-printing (`-v`), it uses *separators* rather than *terminators* for output records. This means the first commit in a stream has no delimiter, and subsequent commits are preceded by a NUL (or newline), making it difficult to parse incrementally in scripts that read piecemeal (e.g., shell coprocs). The author experimented with modifying `log-tree.c` to add a `--use-terminator` option but found the code resistant to this change.

The email also provides context for the author’s use case: a shell script generating `git log`/`git format-patch`-like output with interdiffs between commit ranges. The script currently uses `git format-rev` for commit messages (via a coproc) and individual `git diff-tree` calls for diffs, but the author hoped to consolidate to a single `git diff-tree` coproc. However, `git diff-tree`’s lack of NUL-terminated diff output (`--patch`) for human-readable formats makes this impossible, leaving the functional gap between the two commands unresolved. The author concludes that `git diff-tree` cannot fully replace `git format-rev` for their workflow, though it comes close for pretty-printing if terminator behavior were added.

This clarification underscores the thread’s central tension: `git format-rev`’s convenience (direct revision input, NUL-terminated output) versus its redundancy with `git diff-tree`. The proposed `--use-terminator` option, if implemented, could bridge the gap, but the email does not include a patch or RFC for it. The discussion remains open, with no clear consensus on whether `git format-rev` should be deprecated or extended to address its limitations.
