This thread is about a small but useful modernization of the `git var` built-in command. Keryle, an Outreachy contributor, has refactored the command to use Git’s standard `parse-options` API instead of manual argument parsing. The patch enforces mutual exclusivity between the `-l` (list) flag and positional variable arguments, making the behavior consistent with the usage string.

The change is confined to `builtin/var.c` and is mechanical but not trivial—it replaces old `usage()` calls and manual `argc` checks with the `parse-options` machinery. Feedback on the first version was minor (whitespace, redundant comments) and has been addressed in this second iteration. The patch is now small and focused, with no reported test failures or edge cases, so the main discussion will likely center on whether the conversion is complete and whether the new error messages are clear. It’s a standalone patch, not part of a larger series, and appears ready for review.
