This is the third patch in Beat Bolli’s v3 series addressing OpenSSL compatibility in `git imap-send`. It adds forward-compatibility macros for OpenSSL 4.0, which deprecates `SSL_set1_host()` in favor of `SSL_set1_dnsname()`. The patch is purely mechanical: it defines `SSL_set1_dnsname()` as an alias for `SSL_set1_host()` when building against OpenSSL versions below 4.0, and updates the error message to reflect the correct function name. No runtime behavior change is expected.

The patch is narrowly scoped and well-motivated. OpenSSL 4.0’s deprecation of `SSL_set1_host()` is a breaking change, and this patch ensures Git continues to compile without warnings or errors when built against future OpenSSL releases. The compatibility macros are a standard pattern in Git’s codebase (e.g., similar macros exist for other OpenSSL API changes), and the change is confined to `imap-send.c`.

However, this patch is **premature** in the context of the series. The v3 series remains blocked on a **security regression** in patch 2/3 (certificate stripping), and this patch does not address that issue. While the compatibility macros are uncontroversial, they are not urgent: OpenSSL 4.0 is not yet released, and the macros could be added later without disrupting the current series. Including them now risks distracting reviewers from the unresolved security issue in patch 2/3.

The patch is also **incomplete** in its current form. The commit message and code focus solely on `SSL_set1_host()`, but OpenSSL 4.0’s deprecation may affect other APIs used in `imap-send.c` (e.g., `SSL_get_peer_certificate()`, which was removed in patch 2/3 but may need to be restored to fix the security regression). If the series is revised to address the security issue, additional compatibility macros may be needed.

If you are tracking OpenSSL compatibility or `git imap-send`, this patch is a minor but necessary step for future-proofing. However, it should not be prioritized over resolving the security regression in patch 2/3. The series as a whole will likely need another iteration to address the blocking issues before this patch becomes relevant.
