Thread identity
Subject: [RFC] git branch --delete-merged: handle branches with gone upstreams
Series version: RFC (no patch version)
Originating author: DonQuinleone (first-time contributor)
Thread type: RFC / design discussion

Core problem or goal
Allow `git branch --delete-merged` to delete local branches whose upstream has been deleted by the hosting service (e.g., GitHub after merging a PR), provided the branch tip is reachable from a user-specified ref (e.g., `origin/master`). The current command refuses to delete such branches because the upstream is gone, forcing users to manually identify and delete them.

Current status
No implementation exists; this is a design discussion. Two shapes are proposed:
- (A) A modifier like `--into origin/master` to `--delete-merged`, which deletes branches only if their tip is reachable from the named ref.
- (B) Composable filters like `--upstream-gone --merged=origin/master` to `-d`, enabling standalone listing of gone-upstream branches.
The author prefers (A) for simplicity and alignment with existing safeguards (e.g., worktree/stacked-branch exclusions). The RFC explicitly excludes squash/rebased merges from scope, preserving the current strictness of `--delete-merged`.

Key technical details
- Files touched: `builtin/branch.c` (branch deletion logic).
- New behavior: Pass a user-specified commit (e.g., `origin/master`) to `check_branch_commit()` instead of `HEAD` for gone-upstream branches.
- On-disk format: No changes.
- Test coverage: Not yet addressed; the included script demonstrates the issue (a provably merged branch is skipped by `--delete-merged` after fetching and pruning).

Open questions and loose ends
- Design direction: (A) vs. (B) vs. other alternatives.
- Safeguards: Whether to preserve existing exclusions (worktrees, stacked branches) or relax them for gone-upstream branches.
- User experience: Whether the feature should require explicit opt-in (e.g., `--into`) or be enabled by default for gone-upstream branches.
- Edge cases: Handling of branches with no upstream set, or upstreams that are gone but not due to a merge (e.g., force-pushed).
