This is a brief follow-up in the integer-overflow hardening series, specifically about the type choice for the `posn` variable in `http.c`. Junio replies to Simon Richter’s suggestion to use `off_t` instead of `size_t` for the byte position in `fwrite_sha1_file()`. He acknowledges the theoretical concern that the total bytes written (`eltsize * nmemb`) could exceed `size_t` range, but notes that `posn` is used to offset into a contiguous in-core buffer (`ptr + posn`). Since the buffer’s allocation size is measured in `size_t`, `posn` should also be `size_t` to avoid type mismatches when calculating the offset. The reply is substantive but narrow, focusing on the memory-safety implications of the type choice rather than the broader file-position convention Simon raised. No new edge cases or code changes are introduced; the discussion remains centered on whether `size_t` or `off_t` is the more appropriate type for this specific use. The patch’s readiness for integration is unchanged, but Junio’s reasoning reinforces the original `size_t` choice.
