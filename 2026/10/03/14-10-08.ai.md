This is a **documentation patch** in the ongoing RFC series to introduce `gitbreaking-changes(7)`, a manpage for Git’s breaking changes. The series converts the existing plain-text `BreakingChanges` document into a proper manpage for better discoverability via `git help` and `man`. This specific email is a **follow-up discussion** about the formatting of message-ID references in the new manpage, not a new patch version.

The thread has already resolved all substantive feedback except for one narrow disagreement: whether to use Junio C Hamano’s proposed hybrid format (URL + raw message-ID) or stick with plain URLs for message-ID references. Kristoffer Haugsbakk, the author, has implemented the hybrid format in the revised patch but now pushes back, citing usability concerns. In HTML output, message-IDs are rendered as `mailto:` links, which could confuse users unfamiliar with message-IDs. He also notes that short message-IDs (e.g., `<xmqqa59i45wc.fsf@gitster.g>`) visually resemble email addresses, making plain URLs more intuitive. He suggests dropping the patch entirely if consensus cannot be reached, as the current URL-only approach is already an improvement over raw message-IDs.

The discussion is **technical and minor**, focusing on documentation formatting rather than the series’ broader goal. The hybrid format is a refinement, not a blocker, and the disagreement reflects a trade-off between preserving raw message-IDs for future reference (Junio’s preference) and prioritizing user experience (Kristoffer’s preference). No new patch version has been posted yet, and the files touched remain unchanged (`Documentation/gitbreaking-changes.adoc`). The outcome will determine whether the final manpage uses the hybrid format or plain URLs, but the series’ core goal—making breaking changes more discoverable—is unaffected.
