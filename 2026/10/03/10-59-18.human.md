This is a feature request for `git bisect`.

Alejandro Colomar proposes that `BISECT_HEAD` (the special ref pointing to the commit currently being tested) should be set unconditionally during a `git bisect` run, rather than only when `--no-checkout` is used. His use case involves checking out the bisect commit, running a custom test, switching to a different branch to perform a rebase, and then telling `git bisect` whether the commit was good or bad — all while needing to reference the original bisect commit. Currently, without `--no-checkout`, `BISECT_HEAD` is not available, forcing him to track the commit manually.

The request is small and targeted: make `BISECT_HEAD` available regardless of whether `--no-checkout` is specified. There’s no patch attached, just a clear description of the desired behavior and the motivation. The change would be backward-compatible, as it only adds a convenience feature without altering existing behavior. If implemented, it would simplify workflows that involve manual testing during bisect sessions.
