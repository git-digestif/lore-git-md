This is the main feature patch in Souma’s v5 series teaching `git history` to sign rewritten commits. It adds `--gpg-sign`/`--no-gpg-sign` support to all five subcommands (`drop`, `fixup`, `reword`, `split`, `squash`) and makes them honor the `commit.gpgsign` configuration variable. Command-line options override config, and the last option wins.

The patch threads the signing key through the entire replay machinery: a new `sign_commit` field in the `replay_revisions_options` struct, plumbing in `pick_regular_commit`, `create_commit`, `commit_tree_ext`, `commit_tree_with_edited_message`, and `split_commit`. A custom `history_config` callback reads `commit.gpgsign` before command-line parsing so flags can override it. The `OPT_HISTORY_GPG_SIGN` macro handles the command-line option. On-disk format is unchanged; only the commit object’s signature trailer is added when signing is enabled.

Test coverage is thorough: GPG-gated tests in `t3451`–`t3455` verify config-driven signing, command-line overrides, explicit key selection, and the no-new-commit case for `drop`. All flag/config combinations are covered. The patch also updates the `git-history` man page to document the new options and cross-reference `git-commit` for details on `-S`.
