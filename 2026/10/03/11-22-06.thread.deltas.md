# Thread deltas

## 2026/10/03

- [2026/10/03/11-22-06 by Fionn via GitGitGadget <gitgitgadget@gmail.com>] Fionn Fitzmaurice submitted a patch to `contrib/completion/git-completion.zsh` that introduces a `__git_file_exclude` array populated with existing command-line arguments and passed to `compadd` via `-F`, so that files already present in the argument list are not offered again as completion candidates, matching the deduplication behavior of Zsh's bundled `_git` completion.

## 2026/10/04

- [2026/10/04/08-07-23 by SZEDER Gábor <szeder.dev@gmail.com>] SZEDER Gábor questioned the patch's wording and implementation: he asked what "existing arguments" refers to, flagged the index `2` in `__git_file_exclude=(${words[2,-1]:#${words[CURRENT]}})` as suspicious, and asked what would be excluded in `git -C dir -C subdir -c foo.bar=baz add file1 file2 <TAB>`, suspecting everything starting with "dir" would be excluded rather than just file1 and file2 after "add".
- [2026/10/04/16-17-04 by Fionn <fionn@fionn.email>] Fionn clarified that "existing arguments" means arguments of a subcommand that takes paths, and explained that word[1] is the subcommand (e.g. "add"), so indexing from 2 skips it regardless of where the subcommand appears in the command line. He reported that in his testing the exclusion works correctly (file1 and file2 are no longer offered, while e.g. dir or foo would still be offered if they exist), that he has dogfooded the change for about 8 months on and off, that occasionally hoped-for exclusions are still present because the fallback completion bypasses __gitcomp_file (a separate issue), and that he has not encountered candidates being unexpectedly excluded; he also gave instructions for testing by linking git-completion.zsh to _git and adjusting fpath in ~/.zshrc.
- [2026/10/04/21-13-14 by Junio C Hamano <gitster@pobox.com>] Junio C Hamano noted he was writing the same message as SZEDER Gábor, and raised a new edge-case question: if a file called 'add' exists in the working tree and the user types "a<TAB>", whether 'add' is offered together with other files whose names begin with 'a'.
