This is a user support follow-up in the ongoing thread about finding a robust plumbing equivalent for checking whether `git bisect` has isolated a single commit.

Kristoffer Haugsbakk suggests using `git rev-list --bisect` or its variants (`--bisect-all`, `--bisect-vars`) as a more direct plumbing approach. These options are specifically designed for bisect operations and might provide a cleaner, more stable way to query the current bisect state than manually constructing a `git rev-list` pipeline. However, he notes that he has not personally used these options, so their exact behavior in this context is untested.

The thread remains focused on identifying a version-independent, plumbing-based command or pipeline that reliably reports the number of commits still under consideration in a bisect, including handling skipped commits. The current proposal—using `git rev-list` with `bisect/*` refs—has been refined to account for skipped commits, but Kristoffer’s suggestion introduces a potentially simpler alternative. No objections or confirmations have been raised yet, and the question of which approach is canonical or recommended is still open. The discussion is still in the exploratory phase, with no maintainer input or merge implications.
