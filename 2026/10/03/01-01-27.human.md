This is a bugfix for `git filter-branch` targeting the `--state-branch` commit mapping inversion regression introduced in Git 2.50.0. The patch is now in its third version (`v3`), addressing the final review feedback from Junio C Hamano and Patrick Steinhardt. The core issue remains the same: the state branch file stores mappings in "from_commit:to_commit" format, but the code was incorrectly reading them as "to_commit:from_commit", causing the map directory to be populated backwards. This leads to errors like "Is a directory" when `--prune-empty` is used, as the script attempts to create files with empty names on subsequent runs.

The fix itself is minimal—just two lines in `git-filter-branch.sh`—but the commit message and test coverage have been significantly improved in this version. The commit message now explicitly names the regressing commit (f6d855091e) and explains the test change rationale: replacing `touch file || :` with `exit 1` forces the test to rely on the state branch, ensuring the test fails if the state branch is not used correctly. The new test case, contributed by Michele Locati, directly verifies the commit mapping correctness in incremental runs with `--prune-empty` and `--subdirectory-filter`, ensuring the state branch file contains correctly ordered "original:rewritten" entries. This test fails on current `master` without the fix and passes with it, confirming both the bug and the fix.

The patch touches only two files: the shell script and its corresponding test file (`t/t7003-filter-branch.sh`). The test changes now include proper cleanup with `test_when_finished "rm -fr incremental"`, addressing Patrick Steinhardt’s test hygiene concern. The typo in the patch subject ("fiter-branch") has been corrected in this version, removing the last cosmetic blocker. The patch is self-contained, well-motivated, and now has comprehensive test coverage, making it a strong candidate for merging.

All substantive review feedback has been addressed. Michele Locati, Patrick Steinhardt, and Junio C Hamano have all confirmed the bug’s existence and the fix’s correctness. The patch is ready for Junio to pick up and queue in his integration branches. No on-disk format changes or new symbols are introduced, and the fix is backward-compatible with existing state branch files. This is a clean, targeted fix for a real-world regression that affects users relying on `--state-branch` for incremental repository splitting.
