This is a documentation patch in the ongoing RFC series to create a `gitbreaking-changes(7)` manpage. The series aims to make Git’s upcoming breaking changes more visible to users by converting the existing plain-text `BreakingChanges` document into a proper manpage accessible via `git help` and `man`.

This specific email is a minor correction in the discussion about how to format message-ID references in the new manpage. The thread has already settled the broader approach—moving to a manpage, reordering sections, and integrating it into the documentation build system—but remains stuck on a narrow formatting question: whether to use Junio C Hamano’s proposed hybrid format (URL + raw message-ID) or stick with plain URLs. Kristoffer Haugsbakk, the author, has pushed back on the hybrid format, citing usability concerns in HTML output (message-IDs rendered as `mailto:` links) and the visual similarity of short message-IDs to email addresses. In this email, he simply corrects a typo in his earlier argument ("exception" → "expectation"), clarifying that users would expect message-IDs formatted as links to behave like `mailto:` links, which could confuse them.

The discussion is now purely about user experience trade-offs in documentation formatting. The hybrid format is a refinement, not a blocker, and the disagreement is unlikely to derail the series. No new patch version has been posted yet, but the author has suggested dropping the patch entirely if consensus cannot be reached, as the current URL-only approach is already an improvement over raw message-IDs. The series itself remains well-motivated and technically sound, with all other review feedback addressed. If you care about how Git’s documentation presents references to mailing-list discussions, this thread is worth following; otherwise, it’s safe to skip.
