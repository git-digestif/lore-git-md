This is a user support thread about scripting `git bisect` robustly.

Alejandro Colomar follows up on D. Ben Knoble’s earlier plumbing-based proposal to replace the porcelain `git bisect visualize --oneline | wc -l` pipeline. He confirms that Knoble’s suggested approach—using `git rev-list` to count commits between `bisect/bad` and all `bisect/good-*` refs—works for his current use case, but notes he is now extending his script to support `git bisect skip`. The original plumbing pipeline does not account for skipped commits, so it will incorrectly report more than one commit remaining when the bisect range has actually narrowed to a single commit that was skipped.

The thread remains open: the core question (how to robustly count the number of commits still under consideration, including skipped ones) has not been answered. Alejandro’s follow-up shifts the focus from “does this plumbing work?” to “how do we handle skipped commits in the plumbing?” No new technical symbols or interfaces have been introduced; the discussion still revolves around the `bisect/*` refs and `git rev-list`.
