Core problem or goal
Sphinx asks whether Git should warn users when a destructive operation (e.g., `git revert` or `git restore`) on a shallow clone (`--depth=1`) results in an empty working tree—i.e., all tracked files are removed. The inquiry centers on Git’s safety boundaries: should the tool itself detect and warn about such transitions, or is this responsibility delegated to external tooling or user awareness?

Current status
No decisions or agreements yet. The thread remains in the initial inquiry phase. Carlisle T. Hamlin has responded with a position opposing warnings, framing the issue as one of user responsibility rather than a usability gap. No maintainers or other contributors have weighed in yet.

Key technical details
- **Commands involved**: `git revert`, `git restore`, `git clone --depth=1`
- **Scenario**: Shallow clone of a repository with two commits (A → B), where B is the only commit present locally. Reverting or restoring B removes all tracked files, leaving an empty working tree.
- **Subsystems touched**: shallow clone internals, working tree management, user-facing warnings (none currently exist for this case)
- **Behavior**: Git currently performs the operation without warning, producing an empty tree.
- **Test coverage**: Not mentioned; the question remains about design intent rather than implementation.

Open questions and loose ends
- Is Git’s current behavior (no warning) the intended design, or should it be considered a usability gap?
- Are there existing safeguards for similar destructive operations (e.g., `git reset --hard`, `git checkout` to a divergent branch) that could serve as precedent or counterexamples?
- How does shallow clone behavior interact with empty-tree detection? Are there edge cases where this could lead to data loss or confusion beyond the immediate scenario?
- Would a warning mechanism for empty trees conflict with Git’s philosophy of minimal user interruption, or is this a justified exception?
- Could this scenario be addressed through documentation (e.g., `git clone --depth` man page) rather than code changes?
