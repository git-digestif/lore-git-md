This thread is a user support question from Alejandro Colomar asking for a robust, version-independent plumbing command or pipeline to replace `git bisect visualize --oneline | wc -l` in a script. The goal is to reliably check whether `git bisect` has narrowed the candidate range to exactly one commit without relying on porcelain commands that might change.

The only substantive reply so far is from D. Ben Knoble, who suggests using `git rev-list` to count commits between the `bisect/bad` ref and all `bisect/good-*` refs. His proposed pipeline—`git rev-list bisect/bad --not $(git for-each-ref --format='%(refname)' refs/bisect/good-*) | wc -l`—avoids porcelain commands and directly queries Git’s ref storage, making it stable for scripting. Knoble notes this approach doesn’t account for skipped commits, but that’s irrelevant here since the original script doesn’t use `git bisect skip`. No objections or alternative proposals have been raised yet. The thread remains open, with the core question now framed around whether Knoble’s plumbing-based solution is the best approach.
