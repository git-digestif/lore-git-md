This is a feature request for `git bisect`.

The author, Alejandro Colomar, proposes that `BISECT_HEAD` (the special ref pointing to the commit currently being tested by `git bisect`) should be set unconditionally, even when `--no-checkout` is not used. Currently, `BISECT_HEAD` is only available when `--no-checkout` is passed, which prevents Git from checking out the commit under test. The author needs to perform additional operations (like rebasing another branch) while still tracking which commit is being tested, and `BISECT_HEAD` would be a convenient way to reference it.

The request is motivated by a workflow where the user checks out the bisect commit, runs tests, then switches to a different branch to perform unrelated work (like a rebase), and later needs to report the test result back to `git bisect`. Without `BISECT_HEAD`, the user must manually track the commit hash. The author acknowledges a workaround (storing the commit in a shell variable) but argues that unconditionally setting `BISECT_HEAD` would be a cleaner long-term solution.

No implementation or patch is provided—this is purely a proposal. The email does not discuss potential downsides (e.g., whether `BISECT_HEAD` could conflict with other refs or whether its unconditional presence might break existing scripts). The request is narrowly scoped to the `git bisect` command and the `BISECT_HEAD` ref, with no mention of related subsystems or prior work.

This is likely to be uncontroversial if it doesn’t introduce edge cases, but the lack of a patch or deeper analysis means the discussion may focus on whether the change is truly safe and necessary. The author’s use case is plausible, but the mailing list may ask for more concrete examples or test scenarios before accepting the idea.
