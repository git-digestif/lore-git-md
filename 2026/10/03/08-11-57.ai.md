This is the second patch in Harald Nordgren’s v5 two-patch CI/build system series, now cooking in `next`. It replaces the generic “failed: t1234.56 some test” annotations that GitHub Actions currently attaches to the workflow file with precise, clickable links pointing to the exact line in the test script where the failure or fixed breakage occurred.

The implementation adds a new helper function, `find_test_case_line_`, that searches the test script for the test’s description as a fixed string (using `grep -F`) and returns the first matching line number. This works for statically written test descriptions but falls back to line 1 when the description is built dynamically (e.g., `test_expect_success "case $i: $desc"`). The fallback is acknowledged in the commit message and remains an open design question, but it does not block the patch. The new logic is wired into `finalize_test_case_output` in `t/test-lib-github-workflow-markup.sh`, replacing the previous generic annotations with GitHub’s `::error::` and `::notice::` markup that includes the file path (`t/$script_name`) and line number.

The patch is narrowly scoped: it touches only one file, changes no on-disk formats, and has no runtime behavior outside the CI environment. All substantive review feedback from earlier iterations has been addressed, including Junio C Hamano’s concerns about portability and escaping, and Phillip Wood’s usability critiques. The unresolved issue—GitHub’s UI not making the annotations clickable—is confirmed in Harald’s proof-of-concept CI run but is not a regression and does not block the series. This is a well-crafted, incremental improvement that delivers immediate value by making test failures easier to locate, even if the dynamic-description fallback and UI presentation could be refined later.
