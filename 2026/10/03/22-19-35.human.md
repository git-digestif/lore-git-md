This is a technical follow-up in the ongoing `git brebase` RFC thread, focusing on implementation details of Alejandro Colomar’s shell script. Nico Williams proposes a concrete refactoring to eliminate the temporary callback file used by `git bisect run`, replacing it with an in-memory approach that embeds the callback logic directly into the main script and passes arguments via positional parameters.

Nico’s patch demonstrates how to add a `--bisect-run-callback` flag to the script, allowing the main script to invoke itself recursively for the bisect callback. Instead of writing a separate temporary file, the callback logic is executed conditionally when the flag is present, and arguments (branch name, rebase options, pre/post-exec commands) are passed as positional parameters. This avoids filesystem I/O and simplifies cleanup, addressing Alejandro’s earlier concerns about temporary file management. The patch also fixes a few minor quoting issues in the callback logic.

Alejandro’s hesitation about this approach stems from his preference for the current temporary-file design, which he finds simpler and more maintainable. Nico counters that avoiding temporary files is cleaner and reduces the risk of leaving garbage behind, even with `trap`-based cleanup. The exchange highlights a stylistic difference: Alejandro favors explicit, file-based state management, while Nico prefers in-memory execution and environment variables.

The broader design debate—whether this functionality should live in a new command (`git brebase`) or be integrated into `git rebase` itself—remains unresolved. This email advances the discussion by providing a tested, working alternative to the temporary-file approach, but the philosophical divide persists. The patch is not yet adopted, and Alejandro has not indicated whether he will incorporate Nico’s suggestions. The detached HEAD support issue, previously raised by Nico, is not addressed in this email but was fixed in a separate update to the script.
