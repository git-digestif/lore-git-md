This is the second patch in Harald Nordgren’s two-part CI/build system series, now at v5, that improves GitHub Actions failure reporting by making test failure annotations point directly to the specific line in the test script where the problem occurred. The series is cooking in `next` and addresses all prior review feedback.

The patch replaces generic "failed: t1234.56 some test" annotations with precise, clickable links that take the reader to the exact `test_expect_success` line in the test file. It does this by searching the test script for the test’s description string and using the first matching line number; if the description is generated dynamically (e.g., `test_expect_success "case $i: $desc"`), it falls back to line 1. The implementation is contained in a new helper function `find_test_case_line_` in `t/test-lib-github-workflow-markup.sh` and updates the annotation logic in `finalize_test_case_output`.

The commit message now includes a concrete example ("failed: t1060.17 partial clone of corrupted repository") and explains the fallback behavior, making the user-facing improvement clear. All correctness and portability issues raised by Junio C Hamano and Phillip Wood have been resolved, and the escaping logic that was a point of contention in earlier versions has been removed entirely after Harald demonstrated that GitHub’s annotation parser handles unescaped percent signs correctly.

Two open issues remain: the GitHub Actions UI does not currently make these annotations clickable (confirmed in Harald’s proof-of-concept run), and the line-finding logic still falls back to line 1 for dynamically generated test descriptions. Neither is considered a blocker, and Phillip Wood’s suggestion to consolidate test and leak output into a single collapsible section is still unaddressed but not critical. This patch is a well-scoped, incremental improvement that should land smoothly.
