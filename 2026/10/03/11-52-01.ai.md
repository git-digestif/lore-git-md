This is the **revised documentation patch** in the `gitbreaking-changes(7)` RFC series, responding to Junio C Hamano’s feedback on patch 2/4. The patch is part of a four-patch series converting the existing `BreakingChanges` plain-text document into a manpage for better user visibility. All substantive review feedback has been addressed except for this final point: how to format message-ID references in the manpage.

The email focuses on Junio’s proposed hybrid format (URL + raw message-ID) and Kristoffer Haugsbakk’s pushback. Kristoffer argues the hybrid approach creates usability issues: in HTML output, the message-ID is rendered as a `mailto:` link, which could confuse users unfamiliar with message-IDs. He also notes that most message-IDs in the document are short (e.g., `<xmqqa59i45wc.fsf@gitster.g>`), making them visually similar to email addresses, and that users are more likely to recognize a plain URL as a link. He suggests dropping the patch entirely if consensus cannot be reached, as the current URL-only approach is already an improvement over raw message-IDs.

The discussion is **narrow and technical**, centering on documentation formatting rather than the series’ broader goal. The hybrid format is a refinement, not a blocker, and the disagreement is about user experience trade-offs. The files touched remain the same (`Documentation/gitbreaking-changes.adoc`), and the change is still purely mechanical. The key detail for future discussion is whether to adopt the hybrid format or stick with plain URLs. No new patch version has been posted yet.
