This thread introduces **git-carrier 0.1.0**, an external tool by Oscar Mira designed to help teams manage conflicted merges by "parking" them for later resolution. The tool provides three new Git commands (`git park`, `git unpark`, and `git land`) implemented as a standalone bash script. It stores conflicted paths in a `.hangar` directory as ordinary commits, allowing the state to be shared via push/pull and reviewed like any other branch. The design aligns with prior Git mailing list discussions, particularly suggestions from Junio Hamano and Chris Torek, but remains out-of-tree as recommended for such extensions.

Oscar, a maintainer of the Molly Signal client fork, developed git-carrier to handle large, conflict-heavy upstream updates. The tool is MIT-licensed, with its `.hangar` format documented under CC0, and includes a bats test suite. It currently supports only merge conflicts (not rebase, cherry-pick, or octopus merges) and assumes a single merge source. Key design choices include preserving conflict markers in the carrier branch and avoiding new ref namespaces or server-side changes. The announcement invites feedback on the `.hangar` format and bug reports, with the tool available on GitHub and a request to list it on the Git wiki’s tools page.
