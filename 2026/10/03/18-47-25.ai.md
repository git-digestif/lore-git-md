This is a user report in the `post-worktree` hook design discussion. Maciej Ciemborowicz describes a real-world scenario where the proposed hooks would solve a problem that cannot be addressed by user-written wrappers: IDEs (specifically, VS Code with Codex) create worktrees directly, bypassing any wrapper script. His tool needs to provision isolated container environments for each worktree, but without hooks, there is no reliable way to detect creation or removal events when the IDE—not the user or agent—initiates them. This results in races between worktree creation and agent startup, and between worktree removal and environment cleanup.

The email strengthens Domen Kožar’s observability argument by providing a concrete, high-stakes use case (parallel AI agents in IDEs) where wrappers are insufficient. It does not engage with Kristoffer Haugsbakk’s `--id=<string>` counterproposal or the potential complementarity of hooks and IDs, but it implicitly supports Domen’s framing: hooks are needed for observability when the caller is uncontrolled, regardless of ownership. The report is brief and factual, with no code or technical details, but it carries weight as evidence that the problem is not hypothetical.
