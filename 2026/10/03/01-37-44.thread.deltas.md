# Thread deltas

## 2026/10/03

- [2026/10/03/01-37-44 by Oscar Mira <valldrac@molly.im>] Oscar Mira announced git-carrier 0.1.0, claiming it is the first tool to implement parking a stopped merge and landing it later as a real merge in plain git, distributed as a single bash script implementing `git park`, `git unpark`, and `git land`.
- [2026/10/03/01-37-44 by Oscar Mira <valldrac@molly.im>] The workflow stores conflicted paths under a `.hangar` directory in ordinary commits on a carrier branch that can be pushed, cloned, and reviewed like any branch; `git land` stages the finished work onto the destination without `.hangar`, writes MERGE_HEAD, and stops for `git commit` to complete the two-parent merge.
- [2026/10/03/01-37-44 by Oscar Mira <valldrac@molly.im>] Design constraints stated: the carrier branch carries conflict markers by design and is never merged directly; currently supports merge conflicts only (no rebase, cherry-pick, revert, octopus, or submodule gitlinks); not proposed for contrib/ or core inclusion but requested for listing on the git wiki's tools page.
- [2026/10/03/01-37-44 by Oscar Mira <valldrac@molly.im>] The hangar format spec (docs/hangar-format.txt) is CC0 and the tool is MIT licensed, requiring bash 3.2+ and git 2.34+; the author disclosed that the bash code was mostly authored through LLM iterations, with commits carrying "Assisted-by: LLM" trailers.
