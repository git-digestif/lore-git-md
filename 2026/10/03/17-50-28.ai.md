This is a user support thread about Git's bisect plumbing, continuing the search for a robust way to check whether `git bisect` has isolated a single commit, now with explicit attention to handling skipped commits.

Alejandro Colomar replies to D. Ben Knoble, acknowledging the earlier plumbing pipeline (`git rev-list` with `refs/bisect/good-*` and `refs/bisect/bad`) is insufficient because it does not account for skipped commits. Colomar shares a working one-liner—`git refs list | grep refs/bisect/ | sed '/good/s/^/^/' | cut -f1 -d' ' | xargs git rev-list`—that dynamically constructs the set of candidate commits by negating the good refs and including the bad and skip refs. However, he now recognizes that even this approach fails to capture the bisect algorithm's internal state regarding skipped commits. As a fallback, he proposes writing a temporary script to `git bisect run`, effectively sidestepping the plumbing question. The thread remains open; no maintainer or domain expert has weighed in to confirm whether the `--bisect` family of `git rev-list` options (previously suggested by Kristoffer Haugsbakk) can reliably report the number of remaining candidates, including skipped commits.
