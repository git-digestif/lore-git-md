This is a follow-up in the ongoing RFC thread proposing `git brebase`, a tool for incremental rebasing of complex histories. The author, Alejandro Colomar, responds to feedback from Nico Williams, who had suggested integrating the bisect-driven conflict detection workflow directly into `git rebase` rather than creating a new command.

Alejandro remains unconvinced about merging the functionality into `git rebase` itself, though he acknowledges that adding a `--first-conflict` or `--onto-first-conflict` flag *could* make sense. The discussion here focuses on implementation details of the standalone shell script rather than the larger design debate. Alejandro pushes back on Nico’s suggestion to use `getopts`, explaining that Git’s CLI conventions (specifically the use of `--` to separate commits from paths) make it incompatible. He also clarifies that the callback script used by `git bisect run` doesn’t need command-line arguments, though he later corrects himself to note that `git bisect run` *does* pass arguments—just not ones the script currently uses.

The most concrete improvement in this email is Alejandro’s admission that the script currently requires the user to be on a branch (not in detached HEAD mode), which Nico pointed out as a limitation. Alejandro calls this a bug and plans to fix it, noting that `git rebase` itself supports detached HEAD mode. He also agrees to use `trap` for cleaning up temporary files and to filter out the callback script’s filename from `git bisect run` output to avoid confusing users.

The tone is collaborative, but the email doesn’t move the integration debate forward. Instead, it clarifies edge cases and implementation constraints that would need to be addressed regardless of whether the functionality lives in a new command or `git rebase`. The script is improving incrementally, but the core question—whether this should be a separate tool or part of `git rebase`—remains unresolved. If you’re following this thread for the design discussion, there’s little new here; if you’re interested in the script’s robustness, the detached HEAD fix and temporary file cleanup are worth noting.
