Thread identity: Feature request for `git bisect` to unconditionally set `BISECT_HEAD` ref, even when `--no-checkout` is not used. Originating author: Alejandro Colomar. Thread type: RFC (Request for Comments).

Core problem or goal: Currently, the special ref `BISECT_HEAD` (which points to the commit currently being tested by `git bisect`) is only available when the `--no-checkout` flag is used. The request is to make `BISECT_HEAD` available unconditionally, so users can reference the bisect commit even after switching branches or performing other operations. The motivating use case is a workflow where the user checks out the bisect commit, runs tests, switches to another branch to perform unrelated work (e.g., rebasing), and later needs to report the test result back to `git bisect`. Without `BISECT_HEAD`, the user must manually track the commit hash, which is cumbersome.
