This is a follow-up in the Rust-based SHA-1 backend series, where Johannes Schindelin responds to Junio C Hamano’s questions about the functional equivalence of the Rust and C implementations. The series proposes replacing Git’s C-based `sha1dc` with a faster Rust crate, offering a runtime escape hatch (`core.sha1dcBackend`) to switch back to the C version if needed.

Schindelin clarifies that the two implementations take different technical approaches—leveraging SIMD optimizations in Rust—but ultimately cover the same collision-detection vectors and produce identical results. He acknowledges the Rust implementation is newer and less battle-tested, but his AI-assisted analysis (using GPT-5.5 Sol and Opus 5.5) found it mathematically equivalent to the C version under the original paper’s assumptions. He also notes that while he hasn’t yet run Git’s full test suite against both backends, his static analysis and targeted tests support the Rust implementation’s correctness.

The email doesn’t alter the series’ technical content but provides reassurance about the Rust backend’s safety. It also explains why the runtime escape hatch exists: to mitigate risk for binary distributions like Git for Windows, where users can’t easily recompile. The tone is pragmatic, framing the Rust backend as an optional performance win rather than a mandatory change. The thread remains under review, with the key open question now addressed—though independent validation of the Rust implementation’s correctness may still be needed.
