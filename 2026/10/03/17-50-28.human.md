This is a user support thread about Git's bisect plumbing, continuing the search for a robust way to check whether `git bisect` has isolated a single commit—now with explicit attention to handling skipped commits.

Alejandro Colomar responds to D. Ben Knoble's acknowledgment that the earlier plumbing-based proposal (using `git rev-list` and `git for-each-ref` to count commits between `bisect/bad` and `bisect/good-*` refs) does not account for skipped commits. With no clear plumbing solution in sight, Colomar proposes a pragmatic fallback: writing a temporary script to `stdin` via a heredoc and passing it to `git bisect run`. This sidesteps the plumbing question entirely by relying on the porcelain command's built-in logic, at the cost of version stability. The thread remains open, with no maintainer or domain expert weighing in on whether a true plumbing solution exists or is planned. The question of how to handle skipped commits in a version-independent way is still unresolved.
