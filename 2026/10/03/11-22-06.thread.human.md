This thread is about a small but tricky patch to improve Git’s bundled Zsh completion. The goal is to stop Git from suggesting files that are already on the command line—for example, if you type `git add file1 file2 <TAB>`, it shouldn’t offer `file1` or `file2` again. The patch only touches `contrib/completion/git-completion.zsh` and doesn’t affect Bash completion or core Git.

The patch is currently stuck. The initial version had a serious flaw: it excluded *all* arguments after the Git command, including options like `-C dir` and even subcommand names like `add`. For instance, if you had a file named `add` in your working tree, typing `git a<TAB>` would wrongly suppress the `add` subcommand. Both Junio C Hamano (the maintainer) and SZEDER Gábor flagged this as a blocking regression. The author, Fionn, has acknowledged the issue but hasn’t proposed a fix, leaving the patch in limbo. Until the exclusion logic is rewritten to distinguish between options, subcommands, and file arguments, the patch can’t move forward.
