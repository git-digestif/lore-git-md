This thread is about a small but user-facing improvement to Git's bundled Zsh completion script. The patch, submitted by Fionn via GitGitGadget, aims to prevent Git from offering files that are already present in the command line as completion candidates, aligning its behavior with Zsh's native `_git` completion. The change is confined to `contrib/completion/git-completion.zsh` and doesn’t affect Bash completion or core Git functionality.

The patch is currently under review, with no prior versions or integration status. SZEDER Gábor has raised a substantive concern: the current implementation incorrectly excludes *all* arguments from the second word onward, rather than just file arguments. For example, in a command like `git -C dir -C subdir -c foo.bar=baz add file1 file2 <TAB>`, the patch would exclude `dir`, `subdir`, `foo.bar=baz`, `file1`, and `file2`—breaking completion entirely. Gábor’s feedback is precise and actionable, pinpointing the problematic line and clarifying that only file arguments after the subcommand should be excluded. This issue will likely require a non-trivial revision to the patch. No other reviews or positions have been recorded yet.
