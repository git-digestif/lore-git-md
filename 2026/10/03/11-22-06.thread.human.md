This thread is about a small but user-visible improvement to Git's Zsh completion script. Fionn has submitted a patch that makes Git's bundled Zsh completion exclude files already specified as arguments from further completion candidates, bringing it in line with Zsh's own `_git` completion behavior. For example, when typing `git add aa a<tab>` with untracked files `aa` and `ab`, the patch ensures only `ab` is offered as a completion, not `aa`.

The change is confined to `contrib/completion/git-completion.zsh` and uses standard Zsh scripting idioms—no core Git code or Bash completion is affected. While this is a polish patch rather than a bugfix, it addresses a minor inconsistency that users might notice. The patch is unlikely to be controversial, though it could spark discussion about whether Git's completion should strictly follow Zsh's native conventions or chart its own path. So far, there’s been no review feedback, so the patch is still awaiting input from maintainers or other contributors.
