This thread is about a small but user-visible improvement to Git’s bundled Zsh completion script. Fionn proposed a patch to stop Git from offering files that are already on the command line as completion candidates, matching the behavior of Zsh’s native `_git` completion. The patch modifies only `contrib/completion/git-completion.zsh` and is purely additive.

SZEDER Gábor quickly spotted a critical flaw: the current logic risks excluding *all* arguments after the subcommand (including options like `-C dir` or `-c foo.bar=baz`), not just the intended file arguments. Fionn replied that his testing shows the patch working as intended—excluding only `file1` and `file2` in examples like `` `git -C dir -C subdir -c foo.bar=baz add file1 file2 <TAB>` ``—but he hasn’t revised the code to address the underlying risk. The objection remains unresolved, and no new version of the patch has been posted yet. If you use Zsh completion, this is worth watching; the fix will need to distinguish file arguments from options before it can land.
