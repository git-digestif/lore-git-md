This thread is about a patch to improve Git's bundled Zsh completion by preventing already-specified file arguments from being offered again as completion candidates. The patch, submitted by Fionn via GitGitGadget, modifies `contrib/completion/git-completion.zsh` to align Git's behavior with Zsh's native `_git` completion.

The patch has run into a critical technical issue: its exclusion logic incorrectly filters out *all* arguments from the second word onward, including options like `-C` or `-c`, rather than just file arguments. SZEDER Gábor identified this flaw early, providing a concrete example where the patch would break completion for commands like `git -C dir -C subdir -c foo.bar=baz add file1 file2 <TAB>`. Junio C Hamano has now weighed in, reinforcing Gábor's objection by highlighting another edge case—if a file named `add` exists, the current logic might suppress it when the user types `a<TAB>` after the subcommand. Both maintainer and reviewer agree the patch cannot proceed without a fix to distinguish file arguments from options and subcommands.

Fionn, the author, acknowledges the issue but has not proposed a revised approach, leaving the thread stalled. The patch remains under review with no updates or new versions posted. Until the exclusion logic is corrected, the series is unlikely to move forward.
