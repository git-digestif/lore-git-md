Thread identity: Patch series improving Git's bundled Zsh completion in `contrib/completion/git-completion.zsh` to exclude already-specified file arguments from further completion candidates. Originating author: Fionn via GitGitGadget. Thread type: single-patch contribution (user-interface polish).

Core problem or goal: Align Git's bundled Zsh completion behavior with Zsh's native `_git` completion by preventing files already present in the command line from being offered again as completion candidates. The change is purely additive to the Zsh completion script and does not affect Bash completion or core Git functionality.

Current status: Initial patch posted; under review. No prior versions. No integration branch status reported.

Key technical details: Modifies `contrib/completion/git-completion.zsh` only. Introduces a local Zsh array `__git_file_exclude` that collects file arguments already present in the command line (excluding the current word being completed), then passes this array to `compadd` via the `-F` option to filter completion candidates. Uses Zsh array manipulation (`${words[2,-1]:#${words[CURRENT]}}`) and `compadd -F` for filtering. No new symbols, CLI options, or on-disk format changes. Test coverage not mentioned. **Critical regression risk confirmed**: the current implementation incorrectly excludes *all* arguments from the second word onward (e.g., `-C dir`, `-c foo.bar=baz`, `file1`, `file2`) in commands like `` `git -C dir -C subdir -c foo.bar=baz add file1 file2 <TAB>` ``, rather than just the file arguments (`file1`, `file2`). Junio C Hamano and SZEDER Gábor further highlight that the logic fails to distinguish *subcommand names* from file arguments, risking suppression of valid subcommands (e.g., a file named `add` would be incorrectly excluded when completing `a<TAB>` after the Git command). Fionn’s reply confirms that subcommand names *are* offered in practice, but this does not resolve the underlying flaw in the exclusion logic, which still misclassifies option arguments (e.g., `-C`, `-c`) as file arguments.

Open questions and loose ends: Whether Git's completion should precisely match Zsh's native behavior or maintain its own conventions. **Critical unresolved issue**: the exclusion logic must be revised to distinguish file arguments from option arguments (e.g., `-C`, `-c`) *and* subcommand names. Fionn’s reply does not propose a technical solution to this problem, leaving the blocking objection unresolved.
