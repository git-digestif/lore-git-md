This is a review comment on the first patch of Johannes Schindelin’s four-patch series introducing a Rust-based SHA-1 backend for Git. The series aims to deliver a 3× performance improvement in `git index-pack` by replacing the existing C-based `sha1dc` implementation with a Rust crate, while keeping the Rust backend optional and providing a runtime escape hatch (`core.sha1dcBackend=c`) to fall back to the C version.

Brian M. Carlson raises a **build-system compatibility concern**: the `sha1dc` Rust crate requires Rust 1.87, which is newer than Git’s current minimum Rust version (1.63) and also exceeds the version available in Debian stable (1.85.1). Git’s `Cargo.toml` currently declares compatibility with Rust 1.49.0, and the project has informally aimed to support the Rust version in Debian stable. Carlson argues that raising the minimum Rust version should be handled in a separate policy discussion, not as a side effect of this performance-focused series. The comment is substantive but narrowly scoped to build requirements; it does not engage with the patch’s technical design, performance claims, or collision-detection correctness.
