This is a CI/build system patch series that refines GitHub Actions failure reporting for Git's test suite. The series is now in its fifth iteration (v5) and remains cooking in `next`.

Harald Nordgren addresses a long-standing pain point: when tests fail in CI, the GitHub Actions UI buries the actual failure details at the end of a long log, forcing reviewers to scroll through hundreds of lines to find the problem. The series splits the fix into two focused commits. The first stops leak-sanitizer scripts at the first failure (using `--immediate`) and annotates leaks with the test script name and full sanitizer output in a collapsible log group. The second ensures regular test failures and fixed known breakages point directly to their exact file and line in the test script, making the annotations clickable in the GitHub UI.

In v5, Harald removes percent-sign escaping entirely after verifying that GitHub's annotation parser handles unescaped `%` characters correctly in all existing test descriptions. This resolves Phillip Wood's earlier concern about escaping consistency while keeping the implementation minimal. The commit messages are now clearer, with concrete examples (e.g., "failed: t1060.17 partial clone of corrupted repository") illustrating the problem and solution. The series also fixes a subtle bug in v3 where `--immediate` could exit before writing annotations, ensuring failures are always reported regardless of exit path.

The patch is well-motivated and thoroughly tested. Harald provides a live CI job link demonstrating the feature in action, showing that annotations now correctly display the test filename, line number, and sanitizer output. The remaining open questions are minor: dynamic test descriptions (e.g., `test_expect_success "case $i: $desc"`) still fall back to line 1, and the GitHub UI does not yet make these annotations clickable. However, these are usability refinements rather than blockers. Junio C Hamano has marked the series as ready for `next`, and no substantive objections remain. This is a quality-of-life improvement that will save reviewers significant time when debugging CI failures.
