This is an RFC proposing a new Git command, `git brebase`, designed as an alternative to `git imerge` for handling complex rebases. The author, Alejandro Colomar, presents it as a simpler and more powerful tool for rebasing branches with merge commits, arbitrary commit skipping, and semantic conflict detection. The implementation is a 164-line shell script that internally uses `git bisect` and `git rebase` to automate incremental rebasing up to the first conflicting commit with the target branch.

The tool introduces three key features not present in `git imerge` (per the author's analysis): support for rebasing branches containing merge commits (via `--rebase-merges`-like behavior), the ability to skip arbitrary commits (using `--pre-exec` to filter commits before rebasing), and detection of semantic conflicts (via `--post-exec` to run validation after each rebase step). It also handles complex branch topologies (e.g., trees of branches) by allowing manual resolution from leaves to root, which the author claims reduces redundant conflict resolution.

The implementation is minimal but functional, with rudimentary option parsing (only supporting `--foo=bar` syntax) and transparent passthrough of other flags to `git rebase`. The script uses `git bisect` to find the first conflicting commit and a callback mechanism to orchestrate the rebase steps. The author acknowledges limitations like the inability to create merge commits directly (though a workaround is suggested) and the lack of persistent conflict-resolution history, which they frame as an advantage for keeping the intermediate history clean.

The email explicitly seeks feedback on the tool's design and integration approach, noting uncertainty about whether it should be a new Git command or a flag for `git rebase`. The author's tone is enthusiastic, positioning this as a significant improvement over `git imerge` for certain workflows, but the RFC status and lack of prior list discussion suggest this is an early-stage proposal. The technical details (e.g., reliance on `git bisect`, handling of exit codes) indicate careful attention to edge cases, though the shell-based implementation may raise questions about robustness for production use.
