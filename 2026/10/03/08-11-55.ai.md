This is a CI/build system patch series (v5 of a two-patch effort) that improves GitHub Actions failure reporting by linking test failures and leak sanitizer errors directly to the specific line in the test script where they occurred.

The series is now cooking in `next` and addresses all substantive review feedback from earlier iterations. The key change in v5 is the removal of percent-sign escaping entirely, after Harald Nordgren verified that GitHub’s annotation parser handles unescaped `%` characters correctly in all existing test descriptions. This resolves Phillip Wood’s concern about escaping consistency while simplifying the code. The commit messages have also been rewritten to include concrete examples (e.g., `failed: t1060.17 partial clone of corrupted repository`) to clarify the user-facing improvement.

Patch 1 stops leak-sanitizer scripts at the first failure (using `--immediate`) and annotates leaks with the test script name and full sanitizer output in a collapsible log group. Patch 2 replaces generic "test script failed" annotations with precise, clickable links pointing to the exact line in the test file where the failure or fixed breakage occurred. The line-finding logic falls back to line 1 for dynamically generated test descriptions (e.g., `test_expect_success "case $i: $desc"`), which remains an acknowledged limitation.

The implementation touches `ci/lib.sh` (to add `--immediate` to `GIT_TEST_OPTS`), `t/test-lib-github-workflow-markup.sh` (new functions `find_test_case_line_` and `github_annotation_`), and `t/test-lib.sh` (reordered annotation logic to ensure failures are reported even with `--immediate`). No on-disk format changes are involved, and test coverage is implicit in the CI workflow. The `--immediate` trade-off (stopping at the first leak to avoid polluting output with duplicate "not ok" reports) is explicitly justified in the commit message.

Open issues include the lack of clickable links in the GitHub Actions UI (confirmed in Harald’s proof-of-concept run) and the dynamic-description fallback, but these are not blocking the series. Phillip Wood’s suggestion to consolidate test and leak output into a single collapsible section remains unaddressed, though the current approach is functional. Junio C Hamano has marked the series as ready for `next`, and no new objections have been raised. This is a well-scoped, incremental improvement to CI usability that should land smoothly.
