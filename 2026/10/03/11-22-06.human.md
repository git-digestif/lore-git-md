This is a small but user-visible improvement to Git's Zsh completion script. The patch addresses a discrepancy between Git's bundled `git-completion.zsh` and the upstream Zsh project's `_git` completion function: when completing file arguments (e.g., in `git add`), the upstream version excludes files already mentioned earlier in the command line, while Git's version does not. The example given is `git add aa a<tab>`—with the patch, only `ab` (not `aa`) would be offered as a completion candidate, matching the behavior of common commands like `rm`.

The change is minimal: it introduces a local array `__git_file_exclude` to track existing arguments, then passes it to `compadd` via the `-F` flag to filter out duplicates. The implementation closely mirrors the upstream Zsh `_git` completion's approach. The patch touches only one file (`contrib/completion/git-completion.zsh`) and adds just four lines of code.

This is a quality-of-life fix for Zsh users who rely on Git's completion. The commit message is clear and includes a concrete example, making the motivation easy to understand. No tests are included, but the change is small enough that manual verification (as described in the message) should suffice. The patch looks well-crafted and uncontroversial—worth a quick review for anyone who uses Zsh.
