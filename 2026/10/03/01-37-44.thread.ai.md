Thread identity: external tool announcement for **git-carrier 0.1.0**, a bash-based Git extension for parking and landing conflicted merges. Originating author: Oscar Mira (valldrac@molly.im). Thread type: tool announcement (not a patch series, RFC, or bug report).

Core problem or goal: provide a mechanism to distribute merge resolution work across a team by allowing conflicted merges to be parked, shared, and later landed. The tool addresses the specific pain point of large, conflict-ridden merges (e.g., upstream updates in forks) by storing conflicted paths as ordinary commits in a `.hangar` directory, enabling push/pull/review workflows without requiring new ref namespaces or server-side changes.

Current status: initial release (0.1.0) announced. No prior versions or integration status (external tool, not part of Git core). The tool is explicitly out-of-tree, aligning with the mailing list’s prior guidance to keep such functionality external.

Key technical details:
- Implements three new Git commands: `git park`, `git unpark`, and `git land`.
- Single bash script with no dependencies beyond Git and standard Unix utilities.
- Stores conflicted paths in `.hangar` as ordinary commits; conflict markers are preserved in the carrier branch.
- Supports only merge conflicts (no rebase, cherry-pick, or octopus merges); assumes a single merge source.
- `.hangar` format is documented under CC0; implementation is MIT-licensed with a bats test suite.
- Files touched: none in Git core (external tool).
- New symbols: none (external commands).
- On-disk format: `.hangar` directory containing conflicted paths as commits.
