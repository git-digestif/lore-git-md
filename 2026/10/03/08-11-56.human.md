This is the first patch in a two-part CI/build system series that improves GitHub Actions failure reporting for leak sanitizer jobs. It stops leak-sanitizer test scripts at the first failure (using `--immediate`) and adds GitHub Actions annotations that link the leak to the specific test script where it occurred, with the full sanitizer output displayed in a collapsible log group.

The patch touches three files: `ci/lib.sh` (to add `--immediate` to `GIT_TEST_OPTS` for leak sanitizer jobs), `t/test-lib-github-workflow-markup.sh` (introducing new helper functions `github_annotation_` and `finalize_test_leak_output`), and `t/test-lib.sh` (reordering annotation logic to ensure failures are reported even when `--immediate` exits early). The reordering is a key correctness fix—without it, annotations would be silently dropped when `--immediate` terminates the script.

The commit message clearly explains the motivation: leaks were previously buried at the end of test runs with no annotation, producing only a generic "Process completed with exit code 1" message. The `--immediate` trade-off is explicitly justified—it prevents later tests from inheriting the same sanitizer log entries and reporting duplicate "not ok" messages, which would obscure the real failure. The patch also addresses a Firefox scrolling regression from earlier versions by keeping the leak output collapsible.

This is a well-crafted, incremental improvement that directly targets a real pain point in CI usability. The series is cooking in `next`, and this patch resolves all substantive review feedback from prior iterations, including correctness issues raised by Junio C Hamano and escaping concerns from Phillip Wood. The only remaining open questions are usability refinements (e.g., consolidating test and leak output into a single collapsible section) rather than blocking issues.
