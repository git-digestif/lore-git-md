This is an **announcement of an external tool** (`git-carrier`) that addresses a long-standing workflow problem in Git: distributing conflict resolution work across a team when dealing with large merges.

The tool provides three new Git commands (`git park`, `git unpark`, and `git land`) implemented in a single bash script. It allows users to "park" a stopped merge (with conflicts) as an ordinary commit on a carrier branch, where the conflicted state is stored in a `.hangar` directory. Team members can then clone this branch, resolve conflicts incrementally, and later "land" the resolved merge as a real merge commit. The design intentionally avoids new ref namespaces or server-side changes, making it compatible with standard Git workflows.

The author, Oscar Mira, positions this as a practical solution for their team (maintainers of Molly, a Signal client fork) and frames it as an implementation of ideas previously discussed on the Git mailing list. The tool’s data format (`hangar-format.txt`) is explicitly CC0-licensed, suggesting it could serve as a reference for future Git-native solutions. The announcement references past discussions (2020–2025) and notes that the Git project has historically deferred this problem to external tooling until first-class conflict handling is implemented.

While the tool is new and its bash implementation was partly LLM-assisted, the author emphasizes careful review and testing. It’s designed for plain Git users (unlike `jj`, which handles conflicts natively) and focuses solely on merge conflicts (no rebase/cherry-pick support). The announcement invites feedback on the format and bug reports, but makes no proposal for inclusion in Git itself.
