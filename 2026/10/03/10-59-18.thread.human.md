This thread is a feature request for `git bisect` from Alejandro Colomar. He proposes that the special ref `BISECT_HEAD`—which currently only exists when `--no-checkout` is used—should be set unconditionally during a bisect session. The motivation is to allow users to reference the commit under test even after switching branches, such as when rebasing another branch while bisecting. Currently, users must manually track the commit hash, which the author argues is less ergonomic than relying on `BISECT_HEAD`.

The request is framed as a workflow improvement, with no implementation or patch provided yet. While the use case is plausible, the discussion may focus on whether the change is safe (e.g., potential conflicts with existing scripts or refs) and whether the benefit justifies the change. No responses or objections have been posted yet, so the thread is still in the early proposal stage. If the idea gains traction, it will likely need a patch and test coverage to move forward.
