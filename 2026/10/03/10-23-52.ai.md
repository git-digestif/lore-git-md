This is a follow-up in the Rust-based SHA-1 backend series, responding to Junio C Hamano’s question about functional equivalence between the Rust and C implementations.

Johannes Schindelin clarifies that the two backends take fundamentally different approaches to collision detection, despite sharing the same high-level goal. The Rust implementation leverages SIMD optimizations to reorganize and group the differential vector (DV) checks, resulting in a distinct UBC filter compared to the C version. However, both implementations cover the same affine solution space over GF(2) and detect the same class of collisions under the original paper’s assumptions. Schindelin conducted a static analysis (with AI assistance) and partial testing, confirming that the Rust backend is robust and produces identical SHA-1 outputs for the same inputs, though he notes that a full test suite run comparing both backends across architectures (x86_64 and aarch64) is still pending.

The response frames the Rust backend as a performance optimization rather than a correctness change, emphasizing that the escape hatch (`core.sha1dcBackend=c`) remains a viable fallback. Schindelin’s tone is pragmatic: he acknowledges the time constraints that prevented a deeper manual review but presents the AI-assisted analysis as a reasonable substitute. The open question of functional equivalence is now addressed, though the answer may not fully satisfy reviewers who prefer rigorous, human-verified proofs. The thread remains under review, with the next likely steps being independent validation of the Rust implementation’s correctness and performance claims.
