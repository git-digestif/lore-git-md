This is the first patch in Harald Nordgren’s v5 two-patch CI/build system series, now cooking in `next`. It stops leak-sanitizer scripts at the first failure (using `--immediate`) and adds GitHub Actions annotations that link the leak to the test script name (line 1) while displaying the full sanitizer output in a collapsible log group.

The patch touches three files: `ci/lib.sh` (adds `--immediate` to `GIT_TEST_OPTS` for leak-sanitizer jobs), `t/test-lib-github-workflow-markup.sh` (introduces `github_annotation_` and `finalize_test_leak_output`), and `t/test-lib.sh` (reorders `test_failure_()` to ensure annotations are written before any `--immediate` exit). The reordering prevents annotations from being silently dropped when `--immediate` is active, addressing a correctness issue raised by Junio C Hamano in earlier reviews.

The key behavior change is that leak-sanitizer jobs now fail fast, avoiding duplicate "not ok" reports from later tests that inherit the same sanitizer log entries. The annotation points to the test script (not the exact line, which is unknown) and includes the full sanitizer report in a collapsible section, making leaks visible without cluttering the main log. The `--immediate` trade-off is explicitly justified in the commit message: it prevents output pollution while ensuring the first leak is surfaced clearly.

All substantive review feedback from prior versions has been addressed. The escaping logic (previously a point of contention) was removed entirely after Harald demonstrated that GitHub’s annotation parser handles unescaped percent signs correctly in Git’s test descriptions. The commit message now includes concrete examples (e.g., linking to `t1060`) and explains the reasoning behind `--immediate` and the annotation design.

Open issues from earlier reviews—such as the lack of clickable links in the GitHub Actions UI and the fallback to line 1 for dynamically generated test descriptions—remain unaddressed but are not blocking the series. Phillip Wood’s suggestion to consolidate test and leak output into a single collapsible section is also unresolved, though the current approach is functional. Junio has marked the series as ready for `next`, and no new objections have been raised. This patch is a focused, incremental improvement to CI usability that should land smoothly.
