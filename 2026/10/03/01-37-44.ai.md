This is an announcement of an external tool, **git-carrier 0.1.0**, that provides Git extensions for parking and later landing conflicted merges. The tool is designed to address the problem of distributing merge resolution work across a team, particularly for large merges with many conflicts.

The tool implements three new Git commands (`git park`, `git unpark`, and `git land`) as a single bash script with no dependencies beyond Git and standard Unix utilities. It stores conflicted paths in a `.hangar` directory as ordinary commits, allowing the conflict state to be pushed, pulled, and reviewed like any other branch. The design aligns with prior discussions on the Git mailing list, notably Junio Hamano’s and Chris Torek’s suggestions for a data format to pass partially resolved merges between users.

The author, Oscar Mira, is a maintainer of Molly (a Signal client fork) and developed this tool to handle upstream updates that arrive as large, conflict-ridden merges. The tool is explicitly out-of-tree, following the list’s advice to keep such functionality external rather than integrating it into Git core. The `.hangar` format is documented separately under CC0, and the implementation is MIT-licensed with a bats test suite. The tool currently supports only merge conflicts (no rebase, cherry-pick, or octopus merges) and assumes a single merge source.

The announcement emphasizes the tool’s design decisions, such as preserving conflict markers in the carrier branch and avoiding new ref namespaces or server-side changes. It also acknowledges the tool’s novelty and reliance on LLM-assisted bash scripting, though it has been reviewed and tested. The author invites feedback, particularly on the `.hangar` format, and requests bug reports. The tool is available on GitHub, and the author hopes it will be listed on the Git wiki’s tools page.
