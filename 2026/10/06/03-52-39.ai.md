This is a **CI/build system** and **test infrastructure** patch that extends Git's test framework to allow lazy prerequisite snippets to be written as here-documents, reducing awkward quoting in complex shell snippets.

The patch builds on an earlier change (1d133ae91f, 2024) that enabled `test_expect_success` and `test_expect_failure` to read their test bodies from stdin via here-docs. Jeff King now extends this capability to `test_lazy_prereq`, which previously required manual quoting of single quotes and shell variables inside the snippet. The change is small: it modifies `test_lazy_prereq` to use the existing `test_body_or_stdin` helper, which reads the snippet either from the argument or from stdin if a `-` is passed. The patch updates the `HAVE_CURL_HTTP2_BUG` prereq in `t/t5551-http-fetch-smart.sh` as a real-world example, replacing the previous manual quoting with a cleaner here-doc syntax (`<<\EOT`).

The motivation is purely ergonomic: the here-doc syntax eliminates the need to escape single quotes and shell variables, making the prereq snippet more readable and less error-prone. The change does not alter the behavior of the prereq or the tests that use it; it only changes how the snippet is written. The patch is technically straightforward and uncontroversial, touching only test infrastructure (`t/test-lib-functions.sh`) and the example prereq in `t5551-http-fetch-smart.sh`.

This patch is a follow-up to the recent CI workaround for the Debian 12 HTTP/2 authentication flakiness (js/ci-debian-12-http2-workaround), and it depends textually on the quoting fix that preceded it. It is intended as a cleanup rather than a bugfix, and Jeff suggests it could be applied on top of the immediate fix or as a separate topic. The commit message clearly explains the change and its benefits, making it easy for future maintainers to understand the motivation. No further discussion or changes are expected.
