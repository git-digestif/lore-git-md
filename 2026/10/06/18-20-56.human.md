This is a small but sensible documentation patch that aligns Git's merge conflict advice with its other conflict-resolution workflows. Junio C Hamano reviews Julia Evans' patch to update the `git status` output during a merge conflict, replacing the suggestion to use `git commit` with `git merge --continue`. The change is purely about consistency—`git merge --continue` has been a documented synonym for `git commit` during merges since 2016, but the advice text was never updated to reflect this.

Junio's review is supportive and substantive. He notes that the patch moves Git in the "right direction" and observes that the existing message for merges is less specific than those for cherry-pick and revert, which already use command-specific advice. He also points out a minor administrative issue with GitGitGadget's handling of malformed email addresses in the Cc: field, though this is unrelated to the patch itself.

The patch touches `wt-status.c` and updates two test scripts (`t7060-wtstatus.sh` and `t7512-status-help.sh`) to match the new wording. No behavior changes are introduced—this is purely a user interface tweak to improve clarity and uniformity. Phillip Wood previously suggested a grammatical improvement to the advice text ("to conclude the merge" instead of "to conclude merge"), which Julia is likely to incorporate in a follow-up version.

This is a well-motivated, uncontroversial change that addresses a minor but visible inconsistency in Git's interface. It looks ready for merging once the grammatical tweak is applied.
