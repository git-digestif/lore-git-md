This is the **second patch in a two-patch series** that teaches `git checkout -m` to remember and reuse the original conflict labels (branch names) from the initial merge, rather than falling back to generic labels like "ours" and "theirs". The series targets the ort merge backend and is now in its second iteration, with all substantive feedback from Junio C Hamano addressed.

Phillip Wood responds to Junio’s **substantive review** of the second patch, clarifying or accepting all minor technical points. The discussion centers on naming, conditional logic, and idiomatic improvements, with no fundamental objections raised. Key exchanges: (1) Junio noted that the `REMOVE_BRANCH_STATE_PRESERVE_CONFLICT_LABELS` flag’s name misleadingly suggests it controls *writing* the labels, when in reality it only prevents *deletion* of `.git/MERGE_LABELS` during cleanup. Phillip acknowledges the ambiguity and proposes appending "_FILE" to the flag name for clarity, though he notes the name is already long. (2) Junio questioned whether the conditional preservation of `.git/MERGE_LABELS` (only when `autostash_res == STASH_APPLY_CONFLICT`) is necessary, since `write_merge_labels()` is called unconditionally in `merge_switch_to_result()`. Phillip counters that unconditional preservation could leave stale `.git/MERGE_LABELS` files if a user resolves conflicts and later runs `git checkout` without `-m` (or with `-m` but no new conflicts). (3) Junio suggested using `strbuf_detach()` instead of `xmemdupz()` for detaching the buffer in `parse_merge_label_line()`, and Phillip accepts this as a more idiomatic approach. (4) Junio pointed out a style nit (asterisks in function declarations) and a missing comment explaining why extra lines in `.git/MERGE_LABELS` are ignored; Phillip agrees to both.

The patch remains **ready for integration**, with only minor stylistic tweaks outstanding. The unresolved conflict-style question (whether `git checkout -m` should also remember the original conflict style, e.g., `diff3`) is not revisited here. The series touches `branch.c`, `branch.h`, `merge-ort.c`, and `builtin/checkout.c`, and introduces the ephemeral `.git/MERGE_LABELS` file (analogous to `MERGE_MSG`). Test coverage is added in `t/t7201-co.sh`. No changes to CLI options or on-disk formats beyond `.git/MERGE_LABELS`.
