This small but long-overdue patch from Julia Evans updates Git’s merge conflict advice to recommend `git merge --continue` instead of `git commit`, bringing it in line with the advice already shown for rebase, revert, and cherry-pick. The change is purely about consistency: `git merge --continue` has long been a documented synonym for `git commit` during merges, so no behavior changes.

The patch itself is a single commit touching `wt-status.c` and updating two test scripts to reflect the new wording. Junio Hamano and Phillip Wood have both approved it, calling it a sensible improvement. The only feedback left was a minor cosmetic fix to the commit message—Julia just sent a v3 that corrects the reference commit formatting, so the patch is now ready to be queued. Expect it in `next` or `master` in the current cycle.
