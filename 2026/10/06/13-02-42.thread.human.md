This thread is about a small but user-facing consistency improvement to Git's merge conflict advice. Julia Evans noticed that when a merge conflict occurs, `git status` suggests using `git commit` to finalize the merge, while similar operations like rebase, revert, and cherry-pick advise `git <command> --continue`. Her patch updates the merge advice to recommend `git merge --continue` instead, making Git's messaging uniform across all conflict-resolution workflows.

The change is straightforward: it modifies the advice text in `wt-status.c` and updates two test scripts to match the new wording. Julia explains that `git merge --continue` has been a documented synonym for `git commit` since 2016, so this patch doesn't alter behavior—just the guidance shown to users. The patch is uncontroversial and well-justified, addressing a minor inconsistency without introducing any new complexity. Translators will need to update their strings, but the change is simple enough that it shouldn't cause issues. No objections or alternative approaches have been raised so far.
