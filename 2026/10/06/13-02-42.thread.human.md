This thread is about a small but user-visible improvement to Git’s merge conflict advice. Julia Evans proposed updating the message shown during merge conflicts to suggest `git merge --continue` instead of `git commit`, aligning it with the advice already given for rebase, revert, and cherry-pick. The patch is a single change to the advice text in `wt-status.c`, with corresponding test updates.

The patch is now in its second version (v2), addressing a grammatical tweak suggested by Phillip Wood. Junio C Hamano has explicitly approved it, calling it “better late than never,” and all substantive feedback has been incorporated. The only remaining item is a minor cosmetic fix to the commit message formatting, noted by Kristoffer Haugsbakk: the changelog claims to use `git show -s --format=reference` for the reference commit, but the actual message still shows the raw OID. This is a surface-level polish request and does not affect the patch’s readiness for integration. The patch is expected to land in `next` or `master` in the current cycle.
