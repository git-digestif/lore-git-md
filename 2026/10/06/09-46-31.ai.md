This is the first patch in the v2 series optimizing `fetch.writeCommitGraph` for large repositories. It adds a new `commit-info` subcommand to `test-tool read-graph`, allowing tests to verify whether specific commits are present in the commit-graph and to inspect their generation numbers.

The change is small and focused: 22 lines added to `t/helper/test-read-graph.c`, introducing a loop that parses object IDs from command-line arguments, checks their presence in the commit-graph using `lookup_commit_in_graph()`, and prints their generation numbers. If any commit is not found, the tool exits with status 1. The implementation is straightforward and leverages existing commit-graph APIs (`lookup_commit_in_graph()` and `commit_graph_generation()`), which are also made non-static in the second patch for use in `builtin/fetch.c`.

This is a test infrastructure patch, not user-facing. Its purpose is to enable the series' new tests (in `t/t5510-fetch.sh` and `t/t5537-fetch-shallow.sh`) to verify that incremental commit-graph writes after fetch preserve coverage of local-only commits and correctly exclude shallow-rejected refs. The tool is used in the series' tests to confirm that the incremental write strategy does not lose commits that were previously in the graph.

The patch is uncontested and appears ready. It is a prerequisite for the series' test coverage but does not affect Git's runtime behavior. The implementation is clean, with no obvious edge cases or platform concerns. The only dependency is the second patch, which exposes the APIs used here.
