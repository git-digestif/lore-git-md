This is a performance optimization for the packed-refs backend, now in its third iteration. The patch speeds up operations that rewrite the packed-refs file—such as deleting references—by avoiding redundant formatting of unchanged refs. Instead of using `fprintf()` for every entry, it tracks raw byte positions and writes them directly with `fwrite()`, yielding a consistent ~20% performance improvement when deleting 100,000 packed refs (from 28.7 ms to 23.8 ms).

This version (v3) addresses only surface-level feedback from Toon Claes, who reviewed the commit message wording and declared himself satisfied with the current state. The substantive concerns he raised earlier—documenting the side effects of bypassing `fprintf()` and splitting the write logic into separate functions—were already resolved in v2. The patch now clearly notes that unchanged refs are written verbatim, preserving original formatting (case, whitespace, malformed refnames, peeled OIDs for broken refs), which could affect tools parsing packed-refs files.

The change is narrow and well-motivated, touching only `refs/packed-backend.c` and introducing a new `write_packed_entry_raw()` function alongside the existing `write_packed_entry()`. The on-disk format remains backward-compatible, but external tools like JGit or libgit2 might observe subtle formatting differences. No specific compatibility issues have been raised yet, and the commit message now thoroughly documents the trade-offs.
