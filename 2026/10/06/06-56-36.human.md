This is a CI/build system patch series that delivers the compromise solution for better GitHub Actions failure reporting. The v6 cover letter (now v7 in the patch text) shows Harald Nordgren has addressed the critical usability regression that sank the original second patch: annotation links no longer break when the test file is unchanged in the pull request. Instead, the file name and line number are now embedded directly in the annotation text (e.g., `failed: t1060.17 partial clone of corrupted repository (t1060-object-corruption.sh:141)`), preserving the job-output links while providing the missing context.

The series is now effectively two standalone improvements. Patch 1/2 (leak sanitizer annotations) remains unchanged from its cooking-in-`next` state; it stops leak-sanitizer scripts at the first failure and annotates leaks with the test script name and full sanitizer output in a collapsible log group. Patch 2/2 (test failure annotations) is the revived compromise: it embeds the file and line number in the annotation text, avoiding the broken-link regression while still giving reviewers the exact location of failures. Phillip Wood has accepted this approach, and the proof-of-concept CI job shows it working in practice.

The implementation is clean and focused: `ci/lib.sh` adds `--immediate` to leak sanitizer jobs, `t/test-lib-github-workflow-markup.sh` provides the annotation logic, and `t/test-lib.sh` ensures annotations are written before any `--immediate` exit. The escaping logic has been simplified (no `%` escaping needed), and the commit messages now include concrete examples of the new annotation format. This is a well-crafted, uncontroversial improvement that directly addresses a long-standing pain point for reviewers. The series looks ready for `next` and eventual graduation to `master`.
