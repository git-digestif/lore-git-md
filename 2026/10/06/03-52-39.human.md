This is a **test infrastructure** patch that extends Git's test framework to allow lazy prerequisite snippets to be written as here-documents, making it easier to use single quotes within them. The patch is a cleanup follow-up to the recent CI workaround for the Debian 12 HTTP/2 authentication flakiness (js/ci-debian-12-http2-workaround).

The change is small but impactful for test readability. Currently, lazy prerequisites (like the `HAVE_CURL_HTTP2_BUG` check introduced in the earlier patch) require awkward quoting to embed single quotes inside shell snippets. This patch enables the use of here-docs (`<<\EOT`) for lazy prerequisites, just as `test_expect_success` and `test_expect_failure` already support. The conversion of the `HAVE_CURL_HTTP2_BUG` prereq in `t/t5551-http-fetch-smart.sh` demonstrates the improvement: the `awk` script is now written naturally with single quotes, and the outer shell quoting is handled cleanly by the here-doc syntax.

The implementation is straightforward. The patch modifies `test_lazy_prereq` to use `test_body_or_stdin` (introduced in 2024) to read the snippet either from the argument or from stdin, just like the existing test helpers. The change is confined to `t/test-lib-functions.sh` and the example conversion in `t5551-http-fetch-smart.sh`. No behavior changes are introduced—this is purely a syntactic improvement for test authors.

Jeff King (Peff) is the author, and the patch is motivated by the quoting pain he encountered while writing the `HAVE_CURL_HTTP2_BUG` prereq. The commit message clearly explains the rationale and shows the before-and-after for the curl version check. This is a quality-of-life improvement for anyone writing complex test prerequisites, and it aligns the lazy prereq syntax with the rest of the test framework.

The patch is uncontroversial and ready for integration. It doesn’t touch production code or on-disk formats, and the here-doc support is a natural extension of existing functionality. If merged, it will make future test prerequisites easier to write and maintain.
