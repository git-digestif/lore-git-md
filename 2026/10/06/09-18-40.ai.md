This is a performance optimization patch targeting the packed-refs backend, now in its third iteration. The patch speeds up operations that rewrite the packed-refs file (such as deleting references) by avoiding redundant formatting of unchanged refs. Instead of using `fprintf()` for every entry, it tracks the raw byte positions of unchanged refs in the snapshot iterator and writes them directly with `fwrite()`, achieving a consistent ~20% speedup in benchmarks.

The implementation is clean and focused, touching only `refs/packed-backend.c`. It introduces a `record_start` field in `struct packed_ref_iterator` to track the start of each ref record, and splits the write logic into two functions: `write_packed_entry()` for formatted writes and `write_packed_entry_raw()` for raw writes. This structural separation addresses feedback from Toon Claes, who reviewed the previous version and is now satisfied with the changes. The commit message explicitly documents the side effects of bypassing `fprintf()`—such as preserving original formatting (case, whitespace, malformed refnames, and peeled OIDs for broken refs)—which could affect tools parsing packed-refs files.

The patch is part of the packed-refs subsystem maintained by Karthik Nayak and Patrick Steinhardt. It is backward-compatible with the on-disk format, though external tools may observe subtle formatting differences. The benchmark, which measures the time to delete 100,000 packed refs, shows a clear improvement from ~28.7 ms to ~23.8 ms. No new dependencies or platform-specific code are introduced, and the risk of regression appears low given the narrow scope.
