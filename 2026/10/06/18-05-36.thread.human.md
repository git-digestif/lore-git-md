The Git Contributor's Summit 2026 thread continues to document and refine key project discussions, with the latest focus on governance—specifically, the proposed community voting process to resolve contentious decisions like the AI contribution policy. The summit covered seven major topics (security, Git 3.0, documentation, Outreachy, pluggable ODB, AI policy, and Protocol v2 pushes), all now actionable to varying degrees, but the voting process itself remains under active review.

The latest exchange between Junio C Hamano and Kristoffer Haugsbakk clarifies a key concern: some users who don’t contribute to Git may still try to influence divisive votes (e.g., AI policy) due to strong opinions about broader issues like GenAI. While Junio acknowledges this point, the core tension—whether to enforce a two-year activity window to filter out opportunistic participation—remains unresolved. Earlier reviews by Phillip Wood, brian m. carlson, and others have refined eligibility criteria (e.g., counting patch series, requiring substantive reviews), but Junio’s preference for a simple five-commit threshold and opposition to time-based cutoffs clash with Kristoffer’s and Phillip’s pragmatic safeguards. The voting mechanism (email-based vs. external tools like *devotee*) and tooling neutrality are also still undecided.

Elsewhere, the Git 3.0 rollout plan (two-stage release, SHA-256 support, Rust inclusion) and documentation tooling (Asciidoctor standardization) are moving forward, while pluggable ODB and Protocol v2 pushes await technical follow-ups. The AI policy vote now hinges on finalizing the voting process, with no timeline set. Key open questions include whether the vote will be binding, how to define "active contributors," and how to prevent last-minute "dogpiling" by outsiders.
