Here’s the human-readable summary of the Git Contributor’s Summit 2026 thread, now complete with the final installment on Protocol v2 for pushes:

The Git Contributor’s Summit 2026 thread, initiated by Taylor Blau, has now covered all seven major topics discussed at the summit: security process, Git 3.0 planning, documentation, Outreachy sponsorship, pluggable ODB, AI contribution policy, and—just concluded—Protocol v2 for pushes. The goal has been to share key discussions with the broader community and enable focused follow-up.

The most actionable outcomes so far are the security process (Peff is drafting a public proposal for faster releases and documentation), Git 3.0 planning (consensus on a two-stage rollout with SHA-256 support and Rust inclusion, though LTS status and Rust mandates remain unresolved), and the AI contribution policy (a two-phase process of drafting proposals, legal review, and a contributor vote). Outreachy sponsorship requires outreach to potential sponsors, while pluggable ODB work is targeting a repository extension in Git 2.57, though gaps like commit-graph and MIDX support remain. Documentation improvements are still in the idea phase, with no concrete proposals or funding yet.

The final topic, Protocol v2 for pushes, addresses a long-standing bottleneck: today’s `git push` still uses the v0 protocol, forcing servers to advertise every ref—even in repositories with millions of refs, where this can consume hundreds of megabytes. The infrastructure for v2 (used in fetches) already exists, but the push side has never been implemented. Two key use cases emerged: large repositories (where optimizations like prefix filtering or server-side configuration could skip irrelevant refs) and automated replication (where generation numbers or checksums could avoid full ref advertisements). SHA-256 interoperability was also cited as a strong reason to prioritize this work. The group agreed on incremental implementation, starting with low-hanging optimizations like compression or prefix filtering, with no objections in principle.

Open questions remain across all topics, from funding for documentation and Outreachy to technical details of pluggable ODBs and the AI policy’s legal risks. The Protocol v2 discussion leaves specifics like negotiation methods and reftable integration to future patches, but the direction is clear: this is a needed improvement, and the path forward is actionable. The thread has surfaced both strategic decisions (Git 3.0, SHA-256) and practical next steps (security docs, Outreachy outreach), making it a useful reference for anyone catching up on the project’s direction.
