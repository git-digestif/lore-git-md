This is the sixth and final patch in Harald Nordgren’s six-patch feature series improving `git status` and `git push` handling of rebased push branches. It completes the series by making `git push` rejection messages smarter when the divergence is due to a clean rebase.

The patch teaches `git push` to detect when the remote branch carries no new work—only commits the local branch has since rewritten (via a clean rebase)—and to suggest `--force-with-lease` instead of the generic `git pull` advice. The logic reuses the `stat_outside_upstream()` helper introduced earlier in the series to determine whether the non-upstream commits are identical on both sides. When they are, the rejection message now says the branch was "rebased cleanly on 'upstream/main'" and offers only the force-push option. The new advice message (`message_advice_force_after_clean_rebase`) is opt-in and consistent with Git’s existing advice patterns.

The implementation touches `builtin/push.c` (adding the new advice message and adjusting the rejection logic), `remote.c` (adding the `branch_rebased_cleanly()` helper), and `remote.h` (exporting the helper). The test file (`t/t6040-tracking-info.sh`) adds a 25-line test case verifying the new rejection message and the subsequent `git status` output after a successful force push.

This patch is narrowly focused on the push rejection path and does not change any core object storage or ref handling. The behavior is opt-in: only users who configure `status.compareBranches` to include `@{push}` will see the new advice. The series as a whole looks well-scoped and the commit message is clear, but the real test will be whether reviewers agree that `--force-with-lease` is always the right advice in these scenarios.
