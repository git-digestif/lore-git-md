This is a six-patch feature series from Harald Nordgren that enhances `git status` and `git push` to better handle cases where a push branch has been rebased onto a newer upstream. The series introduces more granular tracking of divergence between the local branch, its upstream, and its push target, and adjusts the advice given to users when a push is rejected or when status detects a clean rebase.

The cover letter explains the core idea: when `git status` compares the local branch with its push target (`@{push}`), it now distinguishes commits that come from the upstream branch from those that don’t. If the non-upstream commits are identical on both sides—meaning the local branch was rebased cleanly onto a newer upstream—`git status` reports this explicitly and suggests a force push with `--force-with-lease`. Similarly, when `git push` is rejected because the remote branch has diverged, the error message now checks whether the divergence is due to a clean rebase and, if so, offers `--force-with-lease` as an option instead of or alongside `git pull`.

The series touches two main subsystems: `remote.c` (where the branch comparison logic lives) and `builtin/push.c` (where the push rejection hints are generated). It also adds a new test file, `t/t6040-tracking-info.sh`, with 163 lines of new tests covering the new behaviors. The changes are focused on user-facing messages and advice, not on core object storage or ref handling.

The motivation is clear: users who rebase their work onto a newer upstream often end up with a push branch that has diverged, but the current `git status` and `git push` messages treat all divergence the same, leading to confusing advice. This series makes the tooling smarter about the *kind* of divergence, which should reduce friction for workflows that involve frequent rebasing.
