This thread tackles a performance regression in Git’s `test-lint` target, specifically the `test-grep-lint` check introduced in commit c9a92e239f. The check, which enforces the use of `--perl-regexp` (`-P`) in `grep` invocations within the test suite, had ballooned the runtime of `test-lint` from ~9 seconds to ~50 seconds for five consecutive runs, creating a noticeable workflow bottleneck. Junio C Hamano flagged the issue, and Jeff King (Peff) confirmed it with performance data, proposing an initial optimization to skip files without "grep" in their content.

Tyler Cipriani responded with a four-patch series that delivers a tested solution, reducing `test-lint` runtime from ~25 seconds to ~6 seconds for five runs on a 16-core machine. The series incorporates Peff’s optimization (patch 2/4), which cuts standalone `test-grep-lint` runtime in half, and introduces a new shared library (`lib-greplint.pl`) to consolidate parsing effort between `test-grep-lint` and `chainlint` (patch 3/4). The final patch (4/4), just posted, teaches `chainlint.pl` to run greplint checks during its own tokenization pass, eliminating redundant file I/O and parsing. This refactoring achieves a ~4x speedup in `test-lint` runtime (from ~4.5 seconds to under 1 second on a 16-core machine) while preserving standalone functionality for both tools.

The series is uncontroversial and ready for review. It touches only the test-lint infrastructure (`t/Makefile`, `t/chainlint.pl`, `t/greplint.pl`, and the new `lib-greplint.pl`), updates one interop test to use `test_grep` for compatibility, and introduces no behavior changes to Git itself. No objections or requests for changes have been raised, and the performance gains are both measurable and significant. The implementation is conservative, respecting existing workflows (e.g., `GIT_TEST_CHAIN_LINT=0`) and maintaining backward compatibility. With Junio’s original concern addressed and Peff’s feedback incorporated, the series appears poised to land.
