This is the second patch in a two-patch CI/build system series (v6) that improves GitHub Actions failure reporting by embedding file and line context directly in test failure annotations. The patch addresses the critical regression in the earlier version where annotation links were broken unless the test file was modified in the same pull request. By searching the test script for the test description and appending the file and line (e.g., `(t1060-object-corruption.sh:141)`) to the annotation text, it provides actionable context without relying on GitHub’s link resolution.

The implementation adds a new helper function, `find_test_case_line_`, which uses `grep -F` to locate the test description verbatim in the script file, avoiding regex corruption from special characters. The function falls back to just the script name if the description is dynamically generated (e.g., `test_expect_success "case $i: $desc"`). The `finalize_test_case_output` function is updated to include this context in error and notice annotations while preserving the existing collapsible log group for full output. The change is minimal and focused, touching only `t/test-lib-github-workflow-markup.sh`.

This patch resolves the show-stopper issue from v5 and has been accepted by Phillip Wood, the primary reviewer. The compromise solution—embedding file/line context as plain text—avoids the earlier regression while retaining the usability improvement. The only known limitation is the fallback behavior for dynamic test descriptions, which is acknowledged but not blocking. The patch is technically sound, well-motivated, and ready for `next`. It complements the first patch (already cooking in `next`), which stops leak-sanitizer scripts at the first failure and annotates leaks with the script name and sanitizer output. Together, the series significantly improves CI debugging for Git contributors.
