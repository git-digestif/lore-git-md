Thread identity
Subject: push negotiation bug: repacking hook causes redundant transfer of common history
Series version: standalone bug report (no patch series)
Originating author: Jens Röcker
Thread type: bug report with reproducible test case

Core problem or goal
Git’s push negotiation logic incorrectly resends common history that was already advertised to the receiver when a pre-push hook repacks the local object database and removes loose objects. The redundant transfer occurs regardless of `push.negotiate` setting, causing the receiver to store a new pack roughly the size of the historical blob (4 MiB in the test case).

Current status
Under review. Root cause confirmed and a proposed fix posted by Patrick Steinhardt. No integration branch placement yet; patch is untested but addresses the core issue directly.

Key technical details
- **Subsystems touched**: push negotiation, object database (ODB), pack generation, hooks
- **Files implicated**: `send-pack.c` (pack generation), `object.c`/`object.h` (`odb_has_object()` with `OBJECT_INFO_QUICK`)
- **New symbols**: `append_negative_objects()` (replaces per-object `append_negative_object()`), `struct oidset` for batching missing OIDs
- **Behavior change**: Without the hook, transfer is minimal (≈300 B); with the hook, the 4 MiB historical blob is resent. The fix batches negative object checks into a single `odb_reprepare()` call, eliminating the race condition while minimizing performance overhead.
- **On-disk impact**: receiver no longer stores a redundant packfile containing already-advertised objects
- **Test coverage**: self-contained Python reproducer (`reproduce.txt`, SHA-256 verified) that creates fresh repo pairs, seeds a deterministic 4 MiB blob, and measures receiver pack size after push

Open questions and loose ends
- Patch is untested; needs validation against the reproducer and broader regression testing
- Scope of affected Git versions: confirmed on Apple Git 2.54.0 and upstream Git 2.56.0 on macOS/arm64; no data on other platforms or versions
- No follow-up on whether the fix should be backported to maintenance branches
