This is the seventh and final installment of Taylor Blau’s Git Contributor’s Summit 2026 notes, covering the discussion on **Protocol v2 for pushes**. The session focused on the need to extend Git’s wire protocol to better handle large-scale repositories—particularly those with millions of refs—and to enable more efficient push operations.

The core problem is straightforward: today’s push protocol requires the server to advertise *all* refs before the client can send its pack, which becomes prohibitively expensive for repositories with tens or hundreds of thousands of refs. Brian m. carlson cited a real-world case where a single ref advertisement ballooned to 896 MB, and noted that AI-driven workflows are exacerbating the issue by generating even more branches. The group agreed that Protocol v2 for pushes is overdue, since much of the necessary code (capability advertisement, fetch-v2 infrastructure) already exists and just needs wiring up.

Several optimizations were proposed. Jonathan Tan and Elijah Newren suggested that the client should be able to request only a small subset of refs (e.g., via prefix filtering) rather than receiving the full advertisement. Peff floated the idea of a multi-pass negotiation: the client first tries a minimal set of refs, then falls back to a larger set if some objects remain unreachable. Server-side configuration could also limit the advertised refs to “interesting” ones (e.g., main branches), though this risks breaking clients that rely on seeing the full set. Martin Fick (Gerrit) added a use case for automated replication: a checksum or generation number could let a client quickly determine whether a mirror is already up-to-date, avoiding the full ref advertisement entirely.

The discussion also touched on interoperability. Brian pointed out that today’s push protocol forces the client to use the server’s hash algorithm, whereas fetch already supports some negotiation. Protocol v2 would make it easier to push between repositories using different hash algorithms (e.g., SHA-1 and SHA-256). Patrick Steinhardt suggested benchmarking alternative advertisement formats, including compressed ref lists and direct reftable transmission, to shrink the wire footprint.

No one objected to the overall direction, but the group acknowledged that the easiest first step might be a server-side configuration that limits the ref advertisement without changing the protocol. That could deliver immediate relief while the full v2 implementation is polished. The notes close with a consensus that push v2 is worth pursuing, and that the existing fetch-v2 hooks provide a solid foundation.
