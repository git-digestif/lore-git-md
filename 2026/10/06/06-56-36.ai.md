This is a CI/build system patch series (v6) that revives and refines the abandoned second patch from the original series, now as a two-patch set. The goal remains the same: make GitHub Actions CI failures easier to debug by linking annotations directly to the failing test script and line. The key change in this iteration is a **compromise solution** that embeds file and line context directly in the annotation text, avoiding the broken annotation links that doomed the previous version while preserving the usability improvement.

The first patch (unchanged from v5) stops leak-sanitizer test scripts at the first failure (`--immediate`) and annotates leaks with the test script name and full sanitizer output in a collapsible log group. This patch is already cooking in `next` and remains viable for graduation. The second patch, now rewritten, adds file and line context to failure annotations as plain text (e.g., `failed: t1060.17 partial clone of corrupted repository (t1060-object-corruption.sh:141)`), sidestepping the earlier regression where annotation links only worked if the test file was modified in the same pull request. Phillip Wood has accepted this compromise, resolving the show-stopper issue from v5.

The implementation touches `ci/lib.sh` (to enable `--immediate` for leak sanitizer jobs), `t/test-lib-github-workflow-markup.sh` (new functions for finding test case lines and formatting annotations), and `t/test-lib.sh` (reordering annotation logic to ensure failures are reported before `--immediate` exits). The compromise avoids on-disk format changes and maintains backward compatibility with existing CI workflows. Test coverage is implicit in the GitHub Actions workflow, as demonstrated in the linked CI job (https://github.com/git/git/actions/runs/37205086805?pr=2426).

This iteration addresses all substantive feedback from the v5 discussion. The broken annotation links are resolved, escaping logic is simplified (no `%` escaping needed), and the commit messages now include concrete examples of the new annotation format. The only remaining loose end is a low-priority UI suggestion from Phillip Wood to consolidate test and leak output into a single collapsible section, which is not blocking. The `--immediate` trade-off (stopping at the first leak to avoid polluting output with duplicate "not ok" reports) is also noted but not contested.

The series is now technically sound and has buy-in from Phillip Wood, the most vocal reviewer. No further iteration is planned unless new issues arise, and the first patch is already in `next`. This is a well-motivated quality-of-life improvement for contributors and reviewers, with clear value for CI debugging. The compromise solution salvages the usability gains of the original second patch while avoiding its critical regression.
