This is the second patch in a two-patch CI/build system series (v6) that improves GitHub Actions failure reporting. The first patch, already cooking in `next`, stops leak-sanitizer test scripts at the first failure and annotates leaks with the test script name. This patch adds file and line context to failure annotations as plain text, making it easier to locate failing tests without relying on broken annotation links.

The patch modifies `t/test-lib-github-workflow-markup.sh` to search the test script for the test description and embed the file and line number directly in the annotation message (e.g., `failed: t1060.17 partial clone of corrupted repository (t1060-object-corruption.sh:141)`). If the description is generated dynamically and not found verbatim, it falls back to showing just the script name. This sidesteps the earlier regression where annotation links only worked if the test file was modified in the same pull request, while preserving the usability improvement.

The implementation is straightforward: a new helper function (`find_test_case_line_`) uses `grep -F` to locate the test description in the script, and the annotation logic is updated to include the file/line context. The change is minimal and focused, touching only the annotation formatting logic. Phillip Wood, the most vocal reviewer of the earlier version, has accepted this compromise, resolving the critical issue that previously blocked the patch.

This is a well-motivated quality-of-life improvement for contributors and reviewers, with clear value for CI debugging. The patch is technically sound, addresses all substantive feedback, and has buy-in from key reviewers. The only remaining loose ends are low-priority UI suggestions (e.g., consolidating test and leak output into a single collapsible section), which are not blocking. The series is now a candidate for `next`.
