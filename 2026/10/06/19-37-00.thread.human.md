This thread is about replacing Git’s outdated `gittutorial` man page with a modern, beginner-focused two-part guide authored by Julia Evans. The new tutorial, tested with 112 users, aims to provide a practical introduction to Git that reflects current workflows while avoiding confusion about its decentralized model. The series is now at version 2, incorporating minor feedback from D. Ben Knoble, such as clarifications on platform assumptions, accessibility (e.g., `+`/`-` sigils in `git diff` for colorblind users), and command syntax.

The first patch deletes the old `gittutorial.adoc` file, while the second introduces the new guide, which includes expanded explanations of `git status`, a troubleshooting section for common issues (e.g., SSH host verification), and disclaimers about simplified SSH key setup. The changes are documentation-only, with no code or on-disk format modifications. Key unresolved questions remain, such as whether to start with `git init` or `git clone` and how to handle authentication generically without tying instructions to specific forges. Julia frames the tutorial as "good enough" for merging, with plans for post-merge iteration based on user feedback.

In this latest email, Ben Knoble raises two minor, surface-level suggestions. First, he asks whether the tutorial should use the newer `git config set`/`get` syntax instead of the traditional `git config --global` form, citing compatibility with older Git versions (e.g., Git 2.32 on macOS 12.7.6). Second, he questions whether combining `mkdir` and `git init` into a single step (`git init myproject`) would improve readability or if the current approach better reinforces that Git can track any existing project. Both points are framed as optional refinements rather than objections, and Ben defers to Julia’s judgment. The thread remains on track for merging, with no new technical concerns or changes to the core design.
