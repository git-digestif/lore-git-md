This thread is about replacing Git’s outdated `gittutorial` man page with a modern, beginner-focused guide tested on 112 users. Julia Evans authored the two-part series, which covers local repository creation and commits (Part 1) and pushing to a remote host like GitHub or GitLab (Part 2). The goal is to provide a practical introduction that reflects current workflows while avoiding confusion about Git’s decentralized model.

The series is under review, with no prior versions, and touches only the `Documentation/gittutorial.adoc` file. Feedback so far has been surface-level, focusing on wording, platform assumptions, and minor UX details rather than the tutorial’s core structure. Julia has incorporated several of D. Ben Knoble’s suggestions, such as clarifying the tutorial’s *nix environment assumption, improving accessibility for colorblind users, and adding a brief explanation of the `-u` flag in `git push -u`. She has also defended some of her choices, like using `git commit -m` as a pragmatic starting point and starting with `git init` in an empty directory for consistency.

Two key design questions remain unresolved: whether to start with `git init` locally or clone from a forge (risking decentralization confusion), and how to handle SSH/HTTPS authentication generically without tying the tutorial to specific forge UIs. The author is open to iteration on these points, and broader input may be needed to resolve them. The series is a serious effort to improve Git’s onboarding experience, and it’s worth tracking for anyone interested in documentation or beginner workflows.
