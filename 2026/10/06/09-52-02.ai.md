This is the final review and acceptance of a CI/build system patch series (v6) that improves GitHub Actions CI failure reporting for Git's test suite. Phillip Wood, the primary reviewer, explicitly endorses the series for merging after Harald Nordgren addressed the critical regression in the second patch by embedding file and line context directly in annotation text instead of relying on broken annotation links.

The series consists of two patches. The first, already cooking in `next`, stops leak-sanitizer test scripts at the first failure (`--immediate`) and annotates leaks with the test script name and full sanitizer output in a collapsible log group. The second, now rewritten as a compromise, adds file and line context to failure annotations as plain text (e.g., `failed: t1060.17 partial clone of corrupted repository (t1060-object-corruption.sh:141)`), resolving the earlier issue where annotation links only worked if the test file was modified in the same pull request. Phillip Wood's acceptance of this compromise closes the thread's primary technical objection.

Key implementation details include new functions in `t/test-lib-github-workflow-markup.sh` (`find_test_case_line_`, `github_markup_script_name`) and reordering annotation logic in `t/test-lib.sh` to ensure failures are reported before `--immediate` exits. The compromise avoids on-disk format changes and maintains backward compatibility. The only remaining loose ends are low-priority UI suggestions (consolidating test and leak output into a single collapsible section) and the `--immediate` trade-off (stopping at the first leak to avoid polluting output with duplicate "not ok" reports), neither of which are blocking.
