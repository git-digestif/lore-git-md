This is the second patch in Harald Nordgren’s six-patch series improving how `git status` and `git push` handle rebased push branches. It teaches `git status` to detect when a local branch and its push target have diverged *cleanly*—meaning the non-upstream commits on both sides are identical—and to report this explicitly in the status message.

The core change is in `remote.c`, where a new helper `stat_outside_upstream()` now uses `git rev-list --cherry-mark` to count how many of the diverging commits carry the same changes on both sides. When all non-upstream commits are identical, the status message adds a parenthetical note: “(rebased cleanly on 'upstream/main')”. The test in `t/t6040-tracking-info.sh` verifies the new wording in a scenario where the local branch is rebased onto a newer upstream and then compared against its push target.

The patch is narrowly scoped: it only affects the status message, not the underlying ref logic or push behavior. The implementation looks clean—it reuses the existing `stat_branch_pair()` machinery and adds a single new parameter to track “same” commits. The test coverage is thorough, exercising the exact scenario the patch targets.

This is a well-motivated usability improvement. Users who rebase their work onto a newer upstream will now see a clearer explanation of why their branch and its push target have diverged, which should reduce confusion and guide them toward the correct next step (`--force-with-lease`). The patch is unlikely to be controversial, though follow-up discussion may explore edge cases (e.g., merge commits or conflict resolutions that alter commit content).
