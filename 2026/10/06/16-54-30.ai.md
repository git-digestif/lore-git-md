This is the final version of a documentation patch that removes empty SYNOPSIS sections from Git’s section 7 man pages and updates the `lint-man-section-order.perl` script to exempt section 7 documents from requiring a SYNOPSIS. The patch is now merged to `master` and addresses the edge case raised in post-merge discussion: it initializes `$man_section_number` by explicitly checking for undefined values and exits early with an error message if the first line of a file does not match the expected `gitglossary(7)` pattern, aligning with Julia Evans’s preference for explicit error reporting over silent fallback.

The implementation touches 11 `.adoc` files in `Documentation/` (removing empty SYNOPSIS blocks) and modifies `lint-man-section-order.perl` to add an `optional_in_man_sections` configuration for section 7, reset section tracking at file boundaries using `$.`, and validate the first line’s format. The change is self-contained, well-tested (`make lint-docs` passes for both single-file and multi-file cases), and uncontroversial. The follow-up discussion about robustness (silent fallback vs. explicit error reporting) remains open-ended but does not affect the patch’s correctness or merge status.

Key technical details for future reference: the Perl script now uses `$.` to reset the man section number at each file boundary, checks for undefined `$man_section_number` on the first line, and skips the SYNOPSIS check for section 7 via the new `optional_in_man_sections` hash. No new CLI options, symbols, or on-disk formats are introduced. The patch is co-authored by Tuomas Ahola, who provided the declarative implementation resolving the multi-file regression.
