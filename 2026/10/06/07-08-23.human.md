This is the fifth patch in Harald Nordgren’s six-patch series improving how `git status` and `git push` handle rebased branches. It focuses on the push rejection message: when you amend or rebase commits you’ve already pushed, `git push` now detects whether the remote branch’s tip is a commit your local branch used to point to (via reflog). If so, it names the specific remote branch and offers `--force-with-lease` as an alternative to the generic “pull first” advice.

The patch adds a new rejection reason flag (`REJECT_NON_FF_HEAD_REWRITE`) and a helper function (`local_ref_used_to_be_at`) that scans the reflog to see if the remote’s current tip was ever the local branch’s tip. When this condition is met, the push rejection message changes from the old generic hint to a branch-specific message that lists both the pull command and the force-push alternative. The test in `t/t6040-tracking-info.sh` verifies that the new message appears after an amend and that the old message still appears when pushing to the upstream branch.

The change is narrow and well-scoped: it only affects the advice text, not the push logic itself, and the reflog check is lightweight. The new advice is opt-in (it only appears when the reflog confirms the remote tip was once local) and consistent with Git’s existing advice patterns. No new configuration is introduced; the behavior is controlled by the same `advice.*` settings as before.
