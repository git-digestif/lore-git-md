This is the second patch in the v2 series optimizing `fetch.writeCommitGraph` for large repositories. It implements the core logic that replaces the full reachable ref scan with an incremental write strategy using only the newly updated refs as seeds.

The patch modifies `builtin/fetch.c` to track which refs were updated during `do_fetch()`, then uses that set of OIDs to write the commit-graph incrementally when possible. The three-mode enum (`GRAPH_WRITE_REACHABLE`, `GRAPH_WRITE_TIPS`, `GRAPH_WRITE_SKIP`) controls the behavior: no-op fetches skip the write entirely, single-remote fetches with an existing graph write only from the updated refs, and edge cases (no existing graph or multi-remote fetches) fall back to the full reachable scan. The `prepare_commit_graph()` function is made non-static so fetch can check for an existing graph, and the new `collect_updated_tips()` helper filters out shallow-rejected refs (whose history is incomplete) and no-op updates.

Test coverage is thorough, with six new tests in `t/t5510-fetch.sh` and `t/t5537-fetch-shallow.sh` verifying incremental writes, exclusion of unrelated commits, no-op fetch skipping, fallback to full scans, no coverage loss after incremental writes, and correct handling of shallow-rejected refs. The synthetic benchmark numbers in the commit message (357ms → 9.3ms for a single ref update) demonstrate a clear performance win, and the fallback logic ensures correctness is preserved in edge cases.

This patch is technically uncontested after Patrick Steinhardt’s substantive review of v1, and the reroll addresses all prior feedback. The implementation is clean, well-scoped, and unlikely to introduce regressions. The series is ready for final review, with no open technical questions. Files modified include `builtin/fetch.c`, `commit-graph.c`, `commit-graph.h`, `t/t5510-fetch.sh`, and `t/t5537-fetch-shallow.sh`.
