This is the first patch in a two-patch CI/build system series (v6) that improves leak sanitizer failure reporting in GitHub Actions. The patch is already cooking in `next` and remains unchanged from v5.

The patch addresses two long-standing usability issues in Git’s CI: (1) leak sanitizer failures are buried at the end of test runs with only a generic "Process completed with exit code 1" message, and (2) once a leak is detected, every subsequent test in the same script redundantly reports "not ok" due to uncleared sanitizer logs, obscuring the actual failure. The solution adds two key behaviors: leak sanitizer jobs now stop at the first failure (`--immediate`), and leaks are annotated with the test script name (e.g., `memory leak logged in t1060 (t1060-object-corruption.sh)`) alongside a collapsible log group containing the full sanitizer output.

The implementation touches three files. In `ci/lib.sh`, it enables `--immediate` for leak sanitizer jobs to prevent redundant "not ok" reports. In `t/test-lib-github-workflow-markup.sh`, it introduces `finalize_test_leak_output` to format leak annotations and log groups, and sets `github_markup_script_name` to track the current test script. In `t/test-lib.sh`, it reorders the annotation logic in `test_failure_()` to ensure failures are reported *before* any `--immediate` exit, preventing silent drops. The patch is technically sound, with no regressions or on-disk format changes, and has already been vetted for correctness and portability in earlier iterations.

This is a well-motivated quality-of-life improvement for CI debugging, particularly for contributors unfamiliar with Git’s test infrastructure. The `--immediate` trade-off (stopping at the first leak to avoid polluting output) is pragmatic and uncontested, though Phillip Wood previously requested a more principled justification or alternative approach. The patch’s value is clear: it surfaces actionable failure information that was previously invisible, reducing the time needed to diagnose CI failures. No further iteration is expected for this patch, and it is a strong candidate for graduation to `master`.

Key symbols introduced: `finalize_test_leak_output`, `github_markup_script_name`. Files touched: `ci/lib.sh`, `t/test-lib-github-workflow-markup.sh`, `t/test-lib.sh`. Behavior change: leak sanitizer jobs now stop at the first failure and emit annotations with script names and sanitizer output. Test coverage is implicit in the GitHub Actions workflow. The patch is decoupled from the second patch’s fate, which addresses a separate but related usability issue (file/line context in failure annotations).
