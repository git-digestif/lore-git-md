This thread is a bug report from Jens Röcker about a push negotiation bug in Git. When a pre-push hook repacks the local object database and removes loose objects, Git incorrectly resends common history that was already advertised to the receiver, leading to redundant transfers (e.g., a 4 MiB blob in the test case). The issue occurs regardless of the `push.negotiate` setting and affects both Apple Git 2.54.0 and upstream Git 2.56.0 on macOS/arm64.

The report includes a self-contained, verified Python reproducer that demonstrates the problem by measuring the receiver’s pack size after a push. Jens hypothesizes the root cause is a stale pack catalogue in the parent process causing `odb_has_object(OBJECT_INFO_QUICK)` to miss repacked objects, but this hasn’t been confirmed. So far, the only reply is a surface-level question from D. Ben Knoble asking for clarification on whether the issue is specifically about redundant object transfers due to the repack hook. No maintainer or substantive review has been posted yet, and no fix has been proposed. The thread remains under review with the core problem well-documented but unresolved.
