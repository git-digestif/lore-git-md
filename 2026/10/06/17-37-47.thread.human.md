This thread is a bug report from Jens Röcker about a push negotiation bug in Git. When a pre-push hook repacks the local object database and removes loose objects, Git incorrectly resends common history that was already advertised to the receiver. This results in redundant transfers—about 4 MiB in the test case—regardless of the `push.negotiate` setting.

The report includes a reproducible Python script that demonstrates the issue by creating fresh repository pairs, seeding a 4 MiB blob, and measuring the receiver's pack size after a push. Without the hook, the transfer is minimal (around 300 bytes), but with the hook, the entire 4 MiB blob is resent. Jens hypothesizes that a stale pack catalogue in the parent process causes `odb_has_object(OBJECT_INFO_QUICK)` to miss repacked objects, leading the pack generator to walk history without excluding advertised bases. The issue has been confirmed on Apple Git 2.54.0 and upstream Git 2.56.0 on macOS/arm64, but no fix has been proposed yet.

In this follow-up email, Jens clarifies that the original reproducer had formatting issues due to Gmail's line wrapping. He attaches the exact, tested script (`reproduce.txt`) as a text/plain attachment, ensuring it runs as intended. The attachment is functionally identical to the original script and produces the same results. No new technical findings or fixes are introduced in this update. The thread remains under review with no maintainer response or integration branch placement yet.
