This thread reports a bug in Git’s push negotiation logic where a pre-push hook that repacks the local object database causes Git to resend common history that was already advertised to the receiver. The issue was confirmed by Jens Röcker with a reproducible test case, and Patrick Steinhardt has now proposed a fix.

The root cause is a race condition in `odb_has_object()` with `OBJECT_INFO_QUICK`: when a pre-push hook repacks the object database, the function can return false negatives, causing the pack generator to walk and resend history unnecessarily. Steinhardt’s fix batches all negative object checks into a single `odb_reprepare()` call, reducing overhead and avoiding the race. The patch modifies `send-pack.c` to use a new `append_negative_objects()` function that collects candidate OIDs, checks them in bulk, and retries only the missing ones after reloading the object database.

The thread is now focused on validating the fix. No maintainer response or integration branch placement has occurred yet, but the proposed solution is targeted and efficient, making it a strong candidate for `next` once testing confirms its correctness. The only prior review was a surface-level clarification request from D. Ben Knoble, so the thread is still open for substantive feedback.
