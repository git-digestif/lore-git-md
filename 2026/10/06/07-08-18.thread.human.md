The thread introduces a six-patch series from Harald Nordgren aimed at improving how `git status` and `git push` handle rebased branches. The goal is to make these commands smarter about detecting when a local branch has been cleanly rebased onto a newer upstream, and to provide more actionable advice—such as suggesting `--force-with-lease`—instead of generic divergence warnings. The series touches `remote.c`, `builtin/push.c`, and `transport.c`, adding new helpers like `stat_outside_upstream()` and `branch_rebased_cleanly()` to analyze commit divergence and reflog history.

So far, the series is in its initial version (v1) and under review. Harald reports he’s already using the feature via Junio’s `seen` branch and shares a real-world example where `git status` now breaks down divergence into commits not present in upstream, explicitly noting when the divergence is due to a clean rebase. The push rejection message in this case offers only `--force-with-lease`, which aligns with the user’s intent after a clean rebase. The test suite (`t/t6040-tracking-info.sh`) covers the new behavior, including edge cases like reflog-based rewrite detection and push rejection messages for non-upstream targets.

No reviews have been posted yet, so the main open question is whether reviewers will agree that `--force-with-lease` is always the right advice in these scenarios. There are also edge cases to consider, such as how the logic handles merge commits, conflict resolutions, or reflog expiration, and whether the three-way `rev-list` approach scales for large divergence counts. The series is opt-in, affecting only users who configure `status.compareBranches` to include `@{push}`, so it shouldn’t disrupt existing workflows.
