This thread is Harald Nordgren's six-patch series to make `git status` and `git push` smarter about rebased branches. When a local branch has been rebased onto a newer upstream, the series teaches Git to distinguish commits that came from upstream from those that did not, so `git status` can report "rebased cleanly" and suggest `--force-with-lease`, and `git push` can give more specific advice about which remote branch to pull from. The series is still at v1 and under review.

The main technical conversation so far is a performance concern raised by Aniket Gupta, who measured that the `--cherry-mark` logic in `stat_outside_upstream()` makes `git status` five to eight times slower when branches have diverged significantly, because computing patch-ids for thousands of commits is expensive. Harald Nordgren acknowledged the regression is serious but pushed back on Gupta's suggested two-phase optimization (counting commits first, then only comparing patch-ids for small divergence counts), worrying that users would find it confusing if the "rebased cleanly" detection sometimes appeared and sometimes did not depending on how much the branches diverged.

The performance question remains unresolved. No decision has been made on whether to implement the optimization, what threshold would trigger the expensive comparison, or how to handle the user experience of inconsistent output. Until this is addressed, the series cannot advance.
