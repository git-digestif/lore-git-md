This is a CI/build system patch that fixes a quoting bug in the recently proposed workaround for an intermittent HTTP/2 authentication failure in Git's Debian 12 CI job. The patch is a follow-up to Johannes Schindelin's `js/ci-debian-12-http2-workaround` and addresses a subtle shell interpolation issue in the test prerequisite (`HAVE_CURL_HTTP2_BUG`) that was introduced when the prereq was rewritten to handle a version range.

The bug occurs because the `awk` script inside the prereq uses `$1` and `$2` to parse the curl version, but the prereq itself is wrapped in double quotes. This causes the shell to interpolate `$1` and `$2` before `awk` ever sees them, resulting in nonsense like `--some-garbage >= 88` instead of the intended version check. The consequence is that the prereq fails to detect buggy curl versions (7.88.0–8.3.0), allowing the flaky tests (`t5559.15` and `t5559.16`) to run and sometimes fail. Jeff King (Peff) caught this while reviewing the patch and provides three potential fixes, opting for the least invasive one: switching the outer quotes to single quotes and escaping the interior single quotes as `'\''`.

The patch is minimal—just four lines changed in `t/t5551-http-fetch-smart.sh`—and does not affect the logic of the version check or the tests it guards. It is a clear, well-motivated fix for a latent bug that would have undermined the original workaround. The commit message is thorough, explaining the problem, the chosen solution, and even the trade-offs of alternative approaches. This is a textbook example of a surface-level review that catches a real issue before it lands. The patch is ready for integration and should be applied on top of `js/ci-debian-12-http2-workaround`.
