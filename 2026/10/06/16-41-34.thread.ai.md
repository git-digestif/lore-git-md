Subject: Performance regression in `test-lint` (test-grep-lint)

Thread type: bug report / workflow discussion → performance optimization series

Core problem or goal
The `test-lint` target in Git’s build system has become noticeably slower due to the `test-grep-lint` check added in commit c9a92e239f. The check, which ensures `grep` invocations in the test suite use `--perl-regexp` (`-P`) where appropriate, now takes ~50 s for five consecutive runs (or ~6.5 s for a single run), up from ~9 s when reverted. The goal is to eliminate this workflow bottleneck by consolidating redundant parsing effort between `test-grep-lint` and `chainlint`, while preserving standalone functionality for both tools.

Current status
Tyler Cipriani’s four-patch series provides a tested solution that reduces total `test-lint` runtime from ~25 s to ~6 s for five runs on a 16-core machine. The series incorporates Peff’s earlier optimization (an early return in `greplint.pl` to skip files without "grep"), restructures the linting system to share parsing effort, and updates interop tests to use `test_grep` for compatibility. Patch 2/4 implements Peff’s optimization, cutting standalone `test-grep-lint` runtime by roughly half (from ~6.5 s to ~3.2 s per run). Patch 3/4, now posted, refactors the core greplint logic into a new shared library (`lib-greplint.pl`), enabling `chainlint.pl` to invoke greplint checks during its own tokenization pass without duplicating file I/O or parsing. The patches touch `t/Makefile`, `t/chainlint.pl`, `t/greplint.pl`, `lib-greplint.pl` (new), and one interop test script. No objections or requests for changes have been raised; the series remains uncontroversial and ready for review.

Key technical details
- **Files touched**: `t/Makefile`, `t/chainlint.pl`, `t/greplint.pl`, `lib-greplint.pl` (new), and `t/interop/i5700-protocol-transition.sh` (updated to use `test_grep`).
- **New symbols/functions**: `lib-greplint.pl` encapsulates the core greplint logic, exposing `check_tokens()` to allow `chainlint.pl` to invoke greplint checks during tokenization. Patch 2/4 adds a simple regex-based early exit (`$body =~ /grep/`) in `t/greplint.pl` to skip files without "grep".
- **Performance data**: Five consecutive runs of `test-lint` drop from ~25 s to ~6 s on a 16-core machine; standalone `test-grep-lint` runtime is halved by patch 2/4 (from ~6.5 s to ~3.2 s per run). Patch 3/4 itself does not improve runtime but enables the ~4x speedup in patch 4/4.
- **Behavior change**: None to Git functionality; the optimization is internal to the test-lint infrastructure. Standalone `greplint.pl` remains functional (for use when `GIT_TEST_CHAIN_LINT=0`).
- **Test coverage**: The series updates one interop test to use `test_grep` instead of bare `grep`, ensuring compatibility with the lint check. No additional test failures or regressions are expected.
- **On-disk format changes**: None.
