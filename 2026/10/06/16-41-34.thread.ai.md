Subject: Performance regression in `test-lint` (test-grep-lint)
Series version: N/A (standalone discussion)
Originating author: Junio C Hamano
Thread type: bug report / workflow discussion

Core problem or goal
The `test-lint` target in Git’s build system, specifically the `test-grep-lint` check added in commit c9a92e239f, now takes ~50 s to run five consecutive times (or ~6.5 s for a single run), up from ~9 s when the check is reverted. This slowdown is noticeable during `make test` as a pause between cleanup and the first test output, degrading developer experience. The check verifies that `grep` invocations in the test suite use `--perl-regexp` (`-P`) where appropriate, but its implementation is inefficient.

Current status
Under discussion; one concrete optimization proposed. Jeff King (Peff) provided a tested patch that reduces runtime by ~50% by skipping further parsing if the test body doesn’t contain the string `grep`. The patch is simple but conflicts with the broader architectural goal of sharing parsing effort with other lint checks (e.g., `chainlint`).
