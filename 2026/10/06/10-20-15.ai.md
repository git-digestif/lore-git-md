This is the **core fix patch** in a two-patch bugfix series targeting the packfile subsystem. It addresses a subtle but serious corruption bug caused by stale delta base cache entries referencing freed `packed_git` structs. The patch is the second in the v2 series (the first was a mechanical refactoring to prepare for this change), and it remains **unchanged from v1** except for minor commit message improvements.

The bug manifests when Git reuses memory addresses for new `packed_git` structs after closing and freeing old ones. If the new pack has entries at the same offsets as the old one, the delta base cache—keyed by pack address and offset—may return stale data, leading to logical corruption. The fix is straightforward: evict cache entries belonging to a pack when it is closed, via a new `delta_base_cache_evict_entry()` function. This is a **minimal, targeted solution** that plugs the leak without disrupting other cache behavior.

The regression test in `t/t6437-submodule-merge.sh` demonstrates the bug by triggering memory reuse via recursive submodule merges. It creates 16 submodules with similar pack layouts, then merges divergent branches to force Git to open and close their object databases repeatedly. The test is **platform-dependent** (relying on glibc’s allocator behavior) and path-length-sensitive (fewer submodules suffice in `/tmp/`), but it reliably reproduces the issue on the author’s system. The test’s limitations are documented, and the thread has accepted them as a trade-off for simplicity.

The patch is **well-motivated and uncontested**. The commit message clearly explains the bug’s mechanism (pointer reuse, not a traditional user-after-free), its trigger conditions, and why AddressSanitizer (ASan) cannot catch it (ASan prevents the bug by allocating unique addresses for freed memory). The fix itself is **low-risk**: it only affects the delta base cache’s eviction logic and does not change on-disk formats or user-visible behavior. The test, while imperfect, provides coverage for a previously untested edge case.

Key technical details for follow-up:
- **Files touched**: `packfile.c` (core fix) and `t/t6437-submodule-merge.sh` (regression test).
- **New function**: `delta_base_cache_evict_entry()` evicts cache entries for a given pack.
- **Test behavior**: Creates 16 submodules with divergent branches, then merges them to trigger memory reuse. The test’s reliability depends on glibc’s allocator and the test directory’s path length.
- **Related prior work**: The bug became exposed after commit 6f1e9394e2 (2024-08-08) stopped leaking packfiles, altering memory reuse patterns.

This patch is **high-priority and likely to proceed** as-is. The only open discussion points are documentation-related (e.g., whether to note the test’s platform dependency more prominently), not technical. No substantive objections have been raised, and the fix’s correctness is uncontested. The series is a strong candidate for `next` once the thread settles.
