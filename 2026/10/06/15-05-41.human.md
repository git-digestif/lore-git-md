This is the latest exchange in Phillip Wood’s two-patch series that teaches `git checkout -m` to remember the original conflict labels from the initial merge. The series is functionally complete and addresses all substantive feedback from Junio on documentation, portability, and edge cases.

The only remaining open question is whether `git checkout -m` should also remember and restore the original conflict style (e.g., `diff3`) as a fallback when the user does not explicitly specify one. Junio framed this as a trade-off between convenience and explicit control, noting that users can already specify the style manually. Phillip has clarified that preserved styles would only apply as a fallback, not override user-specified styles, but no consensus has emerged. This discussion is not blocking the series.
