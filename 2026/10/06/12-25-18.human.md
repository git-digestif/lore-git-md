This is a **CI/build system** follow-up patch that fixes a quoting bug in the `HAVE_CURL_HTTP2_BUG` test prerequisite introduced earlier in the thread. The bug caused the version check to fail silently, allowing the flaky HTTP/2 authentication tests (`t5559.15` and `t5559.16`) to run even on affected curl versions (7.88.0–8.3.0), where they intermittently fail.

The issue is straightforward: the `awk` script inside the prereq snippet uses `$1` and `$2` to parse the curl version, but the snippet itself is wrapped in double-quotes. This causes the shell to interpolate those variables before `awk` sees them, breaking the version check. Jeff King’s fix replaces the outer double-quotes with single-quotes and escapes the inner single-quotes in the `awk` script, ensuring the variables are passed literally to `awk`. The change is minimal—only four lines in `t/t5551-http-fetch-smart.sh`—and does not affect the logic or scope of the workaround.

Junio C Hamano acknowledges the "double-quote outside, single-quote inside" anti-pattern and endorses Jeff’s fix, as well as his separate proposal to extend `test_lazy_prereq` to support here-documents for cleaner quoting in complex snippets. The patch is uncontroversial and ready for integration, as it addresses a latent bug that could have masked the flakiness the original patch was designed to avoid. The commit message clearly explains the quoting issue and the chosen fix, making it easy for future maintainers to understand the change.

This is a surface-level but necessary correction—no substantive discussion is needed, and the patch is unlikely to draw further feedback. It should be applied on top of the main CI workaround (`js/ci-debian-12-http2-workaround`).
