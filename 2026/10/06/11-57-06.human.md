This is a cleanup patch in Patrick Steinhardt’s ongoing ref-storage-format abstraction effort. The patch renames the configuration key `references.format` to `references.storageFormat` in the experimental `git repo` command, aligning it with the rest of the codebase after the terminology was standardized in commit 2f28db44d5.

The change is mechanical and uncontroversial, touching only the man page (`Documentation/git-repo.adoc`), the C implementation (`builtin/repo.c`), and the test suite (`t/t1900-repo-info.sh`). The behavior of the command remains unchanged; only the exposed key name is updated. The patch also updates the tests to verify both the new key’s output and error cases.

The backward-compatibility break is acknowledged but deemed acceptable because `git repo` is marked experimental. Both Patrick and Karthik Nayak agree that the break is justified, and there are no plans to support the old key temporarily. Karthik’s review was surface-level, noting only the compatibility concern, and Patrick confirmed the break was intentional.

This is a one-off cleanup with no open questions or loose ends. It’s ready for merging and doesn’t require further iteration. The broader context is Patrick’s ref-storage-format effort, but this patch is a small, self-contained follow-up.
