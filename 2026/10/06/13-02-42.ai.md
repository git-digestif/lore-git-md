This is a small but user-visible consistency patch. Julia Evans updates the advice message shown during a merge conflict to suggest `git merge --continue` instead of `git commit`, aligning it with the advice given for rebase, revert, and cherry-pick. The change affects the output of `git status` when in a conflicted merge state, updating both the "unmerged paths" and "all conflicts fixed" scenarios.

The commit message provides clear historical context: `git merge --continue` was introduced in 2016 as a synonym for `git commit` during merges, but the advice text was never updated to reflect this. The patch touches `wt-status.c` and updates two test scripts (`t7060-wtstatus.sh` and `t7512-status-help.sh`) to match the new wording. Julia notes that translations will need updating but expects the change to be straightforward since it only involves a command name.

The patch is well-motivated and uncontroversial. It addresses a minor inconsistency in Git's user interface without changing behavior—`git merge --continue` and `git commit` are already documented as equivalent. The change is purely about improving the user experience by presenting a uniform command across all conflict-resolution workflows.
