This is the first patch in Harald Nordgren’s six-patch feature series improving `git status` and `git push` handling of rebased branches. It modifies the branch-comparison logic in `remote.c` so that when `git status` reports divergence between the local branch and its push target (`@{push}`), it now breaks out how many of the differing commits are *not* present in the upstream branch (`@{upstream}`). The new message looks like:

```
Your branch and 'origin/topic' have diverged,
and have 51 and 1 different commits each (1 and 1 not in 'upstream/main').
```

The patch adds a helper function `stat_outside_upstream()` that runs a three-way `git rev-list` (`branch...push ^upstream`) to count the commits that exist in the branch-vs-push comparison but are absent from upstream. The counts are then passed through to `format_branch_comparison()`, which now accepts an optional upstream name and the two “unmerged” counts. The test file `t/t6040-tracking-info.sh` gains a 32-line test case that sets up a rebase scenario and verifies the new message format.

No behavior is changed for users who do not configure `status.compareBranches` to include `@{push}`; the patch only affects the message text when push-tracking is active. The implementation is clean and the commit message is detailed, but the series is still in its first iteration and has not yet received review.
