The core insight is that the verifier still relies on `git rev-list --not --all` to mark preexisting ref tips as uninteresting, just like the full connectivity check. This query implicitly identifies the "old tips" (already-connected commits), and the incremental mode processes incoming commits in reverse topological order, verifying each commit’s tree only against its parents’ trusted trees. The inductive trust model ensures correctness: ancestors are processed before descendants, so each commit’s parents are either already connected or earlier incoming commits whose trees have already been verified.

Kristofer confirms this is not the case—the boundary detection mechanism remains unchanged, though the incremental mode avoids the full tree walk of boundary commits. The discussion also reaffirms that the subprocess architecture (using `die()` for errors) is safe, as the parent process (e.g., `git-receive-pack`) can cleanly handle subprocess failures.
