Core problem or goal
Replace the outdated `gittutorial` man page with a two-part beginner guide tested on 112 users. Part 1 covers local repository creation and commits; Part 2 covers pushing to a remote host (GitHub/GitLab). The goal is to provide a modern, practical introduction that reflects current workflows while avoiding confusion about Git’s decentralized model.

Under review. No prior versions. The series touches only `Documentation/gittutorial.adoc`, replacing its content entirely. No code changes.

Open questions and loose ends
1. **Repository creation**: whether to start with `git init` locally (alternative approach) or clone from a forge (current approach, risking confusion about decentralization). The current draft guides users through creating an empty repository on GitLab/GitHub, but UI changes make this fragile.
2. **Authentication**: how to handle SSH/HTTPS setup generically. The draft uses SSH with simplified instructions and disclaimers about security policies, plus guidance for converting HTTPS URLs to SSH.
3. **Platform assumptions**: D. Ben Knoble suggests clarifying that the tutorial assumes a *nix environment (or Git for Windows Bash), noting potential confusion for PowerShell/CMD users who lack commands like `ls` or `cd`.
4. **Terminology**: minor suggestions about "folder" vs. "directory" and de-emphasizing color in `git diff` output for colorblind users.
5. **Git commands**: proposes mentioning newer `git config set`/`get` syntax (with compatibility caveats) and flags the use of `git commit -m` as potentially encouraging poor commit messages.
6. **Upstream tracking**: questions whether `git push -u` should be introduced without explaining upstream tracking, suggesting it could be deferred to a later tutorial.
