Core problem or goal
Replace the outdated `gittutorial` man page with a two-part beginner guide tested on 112 users. Part 1 covers local repository creation and commits; Part 2 covers pushing to a remote host (GitHub/GitLab). The goal is to provide a modern, practical introduction that reflects current workflows while avoiding confusion about Git’s decentralized model. The author emphasizes the tutorial is "good enough" for merging, with iterative improvements planned post-merge.

Open questions and loose ends
1. **Repository creation**: Whether to start with `git init` (current approach) or `git clone` from a forge. The author defends `git init` as more consistent for beginners but remains open to alternatives. No consensus yet.
2. **Authentication**: How to handle SSH/HTTPS setup generically without tying instructions to specific forge UIs. The author acknowledges the fragility of forge-dependent instructions but considers it "probably ok" for beginners. No resolution.
3. **Pedagogical choices**:
   - Use of `git commit -m` (defended as pragmatic for beginners; no objections, but no explicit approval).
   - Whether to adopt newer `git config set`/`get` syntax (raised by Ben Knoble; compatibility with older Git versions noted, but no consensus).
4. **Post-merge iteration**: The author plans to gather user feedback after merging to refine branching and collaboration content. This is noted as a follow-up effort, not a blocker.
5. **Minor usability tweak**: Julia deferred a decision on Junio’s suggestion to replace `ls ~/.ssh/*.pub` with `cat ~/.ssh/id_ed25519.pub` to reduce the risk of users pasting filenames instead of key contents. This remains unresolved but is not a blocker.
