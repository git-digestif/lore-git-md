Core problem or goal
Replace the outdated `gittutorial` man page with a two-part beginner guide tested on 112 users. Part 1 covers local repository creation and commits; Part 2 covers pushing to a remote host (GitHub/GitLab). The goal is to provide a modern, practical introduction that reflects current workflows while avoiding confusion about Git’s decentralized model. The author emphasizes the tutorial is "good enough" for merging, with iterative improvements planned post-merge.

Current status
Mechanically complete and ready for merging. All substantive and surface-level feedback has been addressed. The v3 patches include:
- A compatibility note specifying Git 2.23.0 or later (required for `git switch`).
- Platform clarification for Windows users (Git Bash recommended, with a disclaimer about PowerShell adjustments).
- Editor warnings (default `vi` behavior, escape instructions, and `git commit -m` usage).
- Improved SSH key handling (generic `ssh-keygen` instructions, `cat` example to avoid pasting filenames, and a note about key filename variability).
- Minor UX tweaks (emphasis on `git status`, clarification of `--set-upstream`, and phrasing fixes from test readers).
- The old tutorial has been **removed in the first patch of v3**, and the new content added in the second patch, completing the replacement. This split was done to simplify review by avoiding a noisy diff.

The series is pending Junio’s final review. It is uncontroversial and validated through user testing.

Open questions and loose ends
1. **Repository creation**: Whether to start with `git init` (current approach) or `git clone` from a forge. The author defends `git init` as more consistent for beginners but remains open to alternatives. No consensus yet.
2. **Authentication**: How to handle SSH/HTTPS setup generically without tying instructions to specific forge UIs. The author acknowledges the fragility of forge-dependent instructions but considers it "probably ok" for beginners. No resolution.
3. **Pedagogical choices**:
   - Use of `git commit -m` (defended as pragmatic for beginners; no objections, but no explicit approval).
   - Whether to adopt newer `git config set`/`get` syntax (raised by Ben Knoble; compatibility with older Git versions noted, but no consensus).
   - SSH key generation: Julia prefers leaving the key type unspecified (`ssh-keygen`) for future-proofing, while Junio suggests `ssh-keygen -t ed25519` for immediate usability. The trade-offs are clarified but unresolved.
   - Key copying instructions: Junio suggested replacing `ls ~/.ssh/*.pub` with `cat ~/.ssh/id_ed25519.pub` to reduce user error, but the filename may vary. The current v3 uses `cat` with a note about variability.
4. **Post-merge iteration**: The author plans to gather user feedback after merging to refine branching and collaboration content. This is noted as a follow-up effort, not a blocker.
