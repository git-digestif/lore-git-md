Core problem or goal
Replace the outdated `gittutorial` man page with a two-part beginner guide tested on 112 users. Part 1 covers local repository creation and commits; Part 2 covers pushing to a remote host (GitHub/GitLab). The goal is to provide a modern, practical introduction that reflects current workflows while avoiding confusion about Git’s decentralized model. The author emphasizes the tutorial is "good enough" for merging, with iterative improvements planned post-merge.

Current status
Under review. The series is now ready for merging once the trivial AsciiDoc formatting warnings are resolved. Julia Evans has addressed all substantive and surface-level feedback from Junio C Hamano and D. Ben Knoble. The remaining task is to add blank lines before the Setext-style section delimiters at lines 124 ("Step 3") and 487 of the new `gittutorial.adoc` file to comply with AsciiDoc’s stricter parsing rules, or to switch to Atx-style headings (`==`). Junio has clarified that he has no strong preference between the two styles, noting that Atx-style avoids character-counting and handles non-ASCII text more gracefully, but the choice is left to the author. These are purely mechanical whitespace or markup adjustments unrelated to the tutorial’s content. The v2 patches, initially delayed by 10 hours in the mailing list archive, are now available for review.

Open questions and loose ends
1. **Repository creation**: Whether to start with `git init` (current approach) or `git clone` from a forge. The author defends `git init` as more consistent for beginners but remains open to alternatives. No consensus yet.
2. **Authentication**: How to handle SSH/HTTPS setup generically without tying instructions to specific forge UIs. The author acknowledges the fragility of forge-dependent instructions but considers it "probably ok" for beginners. No resolution.
3. **Pedagogical choices**:
   - Use of `git commit -m` (defended as pragmatic for beginners; no objections, but no explicit approval).
   - Whether to adopt newer `git config set`/`get` syntax (raised by Ben Knoble; compatibility with older Git versions noted, but no consensus).
4. **Post-merge iteration**: The author plans to gather user feedback after merging to refine branching and collaboration content. This is noted as a follow-up effort, not a blocker.
5. **Minor usability tweaks**:
   - **SSH key generation**: Julia prefers leaving the key type unspecified (`ssh-keygen`) for future-proofing and post-quantum readiness, while Junio suggests specifying `ssh-keygen -t ed25519` for immediate usability and consistency with the tutorial’s "get started quickly" ethos. The trade-offs are now clarified but unresolved.
   - **Key copying instructions**: Junio suggested replacing `ls ~/.ssh/*.pub` with `cat ~/.ssh/id_ed25519.pub` to reduce the risk of users pasting filenames instead of key contents. The discussion now notes that the filename may vary depending on the default key type, complicating the hardcoded approach. This remains unresolved but is not a blocker.
