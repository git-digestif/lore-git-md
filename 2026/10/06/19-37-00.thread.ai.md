Subject: [PATCH 0/2] Replace gittutorial with beginner-focused guide

Originating author: Julia Evans
Thread type: documentation patch series

Core problem or goal
Replace the outdated `gittutorial` man page with a two-part beginner guide tested on 112 users. Part 1 covers local repository creation and commits; Part 2 covers pushing to a remote host (GitHub/GitLab). The goal is to provide a modern, practical introduction that reflects current workflows while avoiding confusion about Git’s decentralized model. The author emphasizes the tutorial is "good enough" for merging, with iterative improvements planned post-merge.

Current status
Merged to `next` for integration testing. Junio reviewed the v5 series and called v4 "in a pretty good shape to be merged to 'next'" after addressing the final surface-level nits. The v4 series was merged to Junio’s `seen` branch, and v5 finalized the series by incorporating Junio’s fixup commit to resolve a mechanical build issue: the removal of `gittutorial.adoc` in the first patch caused `make` to fail because `Documentation/Makefile`, `Documentation/meson.build`, `command-list.txt`, and several `.adoc` files still referenced the deleted file. The series remains in `next` for integration testing, with no further procedural or technical obstacles to graduation.

Open questions and loose ends
1. **Repository creation**: Whether to start with `git init` (current approach) or `git clone` from a forge. The author defends `git init` as more consistent for beginners but remains open to alternatives. No consensus yet.
2. **Authentication**: The platform-specific split (SSH for macOS/Linux, GCM for Windows) resolves the earlier tension about forge-dependent instructions. Julia’s research confirms GCM’s broad compatibility with major Git hosts, making it a viable default for Windows without custom server configurations.
3. **Pedagogical choices**:
   - Use of `git commit -m` (defended as pragmatic for beginners; no objections, but no explicit approval).
   - Whether to adopt newer `git config set`/`get` syntax (raised by Ben Knoble; compatibility with older Git versions noted, but no consensus).
   - SSH key generation: Julia prefers leaving the key type unspecified (`ssh-keygen`) for future-proofing, while Junio suggested `ssh-keygen -t ed25519` for immediate usability. The trade-offs are clarified but unresolved.
   - Key copying instructions: Junio suggested replacing `ls ~/.ssh/*.pub` with `cat ~/.ssh/id_ed25519.pub` to reduce user error, but the filename may vary. The current version uses `cat` with a note about variability.
4. **Post-merge iteration**: The author plans to gather user feedback after merging to refine branching and collaboration content. This is noted as a follow-up effort, not a blocker.
5. **Cross-reference fix**: The cross-reference in `Documentation/git.adoc` remains broken, failing `make check-docs`. Junio acknowledged the issue but did not block the series, stating he will address it with a follow-up update. The build issue is resolved for integration purposes, but the cross-reference remains a low-priority loose end. Future updates to the topic must include these mechanical fixes to avoid requiring maintainer intervention.
