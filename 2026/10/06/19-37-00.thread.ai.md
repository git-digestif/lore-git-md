Core problem or goal
Replace the outdated `gittutorial` man page with a two-part beginner guide tested on 112 users. Part 1 covers local repository creation and commits; Part 2 covers pushing to a remote host (GitHub/GitLab). The goal is to provide a modern, practical introduction that reflects current workflows while avoiding confusion about Git’s decentralized model.

Current status
Under review. The series remains at v1, but the author has incorporated minor editorial feedback from D. Ben Knoble. The patch touches only `Documentation/gittutorial.adoc`, replacing its content entirely. No code changes.

Key technical details
- Files: `Documentation/gittutorial.adoc` (replaced)
- New symbols: none (documentation-only)
- On-disk format: unchanged
- Test coverage: none (documentation-only change)
- Updates in response to feedback:
  - Added a note clarifying the tutorial assumes a *nix environment (or Git for Windows Bash).
  - Emphasized `+`/`-` sigils in `git diff` output for colorblind accessibility.
  - Added a brief explanation of the `-u` flag in `git push -u` (upstream tracking).
  - Included a disclaimer about simplified SSH key setup and security policies.

Open questions and loose ends
1. **Repository creation**: whether to start with `git init` locally (current approach) or clone from a forge (alternative approach, risking confusion about decentralization). The author defends the current approach as ensuring consistency for all readers but remains open to alternatives.
2. **Authentication**: how to handle SSH/HTTPS setup generically without tying the tutorial to specific forge UIs. The author acknowledges the fragility of forge-dependent instructions but considers it "probably ok" for beginners.
3. **Pedagogical choices**: lingering questions about the use of `git commit -m` (defended as pragmatic for beginners) and whether to introduce newer `git config set`/`get` syntax (deferred for now).
