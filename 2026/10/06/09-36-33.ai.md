This is a performance optimization for the packed-refs backend, now in its third iteration. The patch speeds up operations that rewrite the packed-refs file (such as deleting references) by avoiding redundant formatting of unchanged refs. Instead of using `fprintf()` for every entry, it tracks raw byte positions and writes them directly with `fwrite()`, yielding a consistent ~20% performance improvement when deleting 100,000 packed refs. The trade-off is that unchanged refs are written verbatim, preserving original formatting (case, whitespace, malformed refnames, peeled OIDs for broken refs), which is now clearly documented in the commit message as a side effect.

This version (v3) addresses only surface-level feedback from Toon Claes on commit message wording ("side effect" instead of "side", "commit message" instead of "commit"). Toon has explicitly stated he is satisfied with this version, marking the end of his review. The substantive concerns he raised earlier—documenting the side effects of bypassing `fprintf()` and splitting the write logic into separate functions—were already addressed in v2.

The patch touches only `refs/packed-backend.c` and introduces a new `write_packed_entry_raw()` function alongside the existing `write_packed_entry()`. It is part of the packed-refs subsystem maintained by Karthik Nayak and Patrick Steinhardt, with no dependencies on other in-flight topics. The optimization is narrow, well-motivated, and benchmarked, making it a strong candidate for merging once Junio picks it up.

The main open question remains whether the formatting changes (e.g., uppercase OIDs, tabs) could affect tools parsing packed-refs files (e.g., JGit, libgit2), though no specific compatibility issues have been raised. The commit message now documents these side effects to mitigate potential interoperability concerns. No maintainer decision has been recorded yet; the patch remains under review.
