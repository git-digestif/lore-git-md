This is the first patch in a two-patch CI/build system series that improves leak sanitizer failure reporting in GitHub Actions. The patch is already cooking in `next` and remains unchanged from its previous iteration.

The patch addresses two long-standing annoyances in Git’s CI workflow. First, leak sanitizer failures are only discovered at the end of a test script, after every test has already reported "ok", and they receive no annotation at all — the only visible failure is a generic "Process completed with exit code 1". This patch gives each leak its own GitHub Actions annotation, naming the script it occurred in (e.g., `memory leak logged in t1060 (t1060-object-corruption.sh)`) and placing the full sanitizer report in a collapsible log group next to it. Second, once a script has one leak, it keeps running, and the sanitizer log directory is never cleared between tests, so every later test in the same script sees the same leftover log entries and also reports "not ok", burying the real failure in duplicates. The patch stops leak-sanitizer scripts at their first failure using `--immediate`.

The implementation is straightforward: it adds `--immediate` to `GIT_TEST_OPTS` for leak sanitizer jobs in `ci/lib.sh`, introduces a new `finalize_test_leak_output` function in `t/test-lib-github-workflow-markup.sh` to format the leak annotation and log group, and reorders the annotation logic in `t/test-lib.sh` to ensure the failure annotation is written before any `--immediate` exit. The patch is well-motivated, with clear examples in the commit message showing the before-and-after behavior. It touches only CI and test infrastructure, with no on-disk format changes or user-visible behavior outside GitHub Actions.

This is a quality-of-life improvement for contributors and reviewers, making CI failures easier to debug without any downsides. The patch has already been reviewed and is technically sound; the only remaining discussion is about the second patch in the series, which is now a separate, accepted compromise. If you work with Git’s CI, this patch is worth your attention.
