This is a reply to a surface-level review of the first patch in Patrick Steinhardt’s 13-patch series refactoring Git’s object database (ODB) to move alternates handling into the files backend. The patch itself shifts responsibility for resolving packfile paths from `fill_oids_from_packs()` to its caller in `builtin/commit-graph.c`, requiring fully resolved paths for the `--stdin-packs` option.

Patrick acknowledges Karthik Nayak’s feedback that the original commit message lacked motivation. He clarifies that the change removes assumptions in `commit-graph.c` about where packfiles live relative to an ODB source, making the code more backend-agnostic. This is a preparatory step for later patches in the series, which will further decouple the commit-graph subsystem from ODB internals. The explanation is brief but sufficient to address the reviewer’s concern; a reroll with an improved commit message is likely.

The patch remains a small, mechanical refactoring with no behavior changes. Existing tests for `--stdin-packs` should cover it, and the change is uncontroversial. The thread’s broader context—moving alternates into the files backend to simplify ODB architecture—makes this patch a logical first step.
