This is a documentation proposal from Julia Evans to replace Git’s aging `gittutorial` with a modern, two-part beginner’s guide. The new tutorial walks users through creating an empty repository and making two commits (covering `git init`, `git add`, `git commit`, `git status`, and `git diff`), then pushing to a remote host like GitHub or GitLab (`git remote add` and `git push`). Julia has already tested the draft with 112 beta testers, most of whom completed it successfully, and is now seeking focused feedback on two structural questions before refining the text further.

The first question is whether to start the tutorial by creating the repository locally (`git init`) or on the forge (GitHub/GitLab). The current draft uses the local-first approach to emphasize that Git works without a forge, but testers frequently hit conflicts when the forge’s default `README.md` already exists. Julia is leaning toward guiding users to create an empty repository on the forge’s web UI, despite the UI constantly changing, as the least-bad option.

The second question is authentication: the draft uses SSH and includes minimal setup instructions, with disclaimers about security policies and a tip for converting HTTPS URLs to SSH. Julia acknowledges the tension between forge-specific tools (like `gh auth login`) and a generic tutorial, and between Git’s documentation and the lack of a beginner-friendly SSH guide elsewhere.

The patch series removes the old `gittutorial` and adds the new content in a single file (`Documentation/gittutorial.adoc`), replacing 457 lines with 397. The commit message does not yet explain the pedagogical choices in detail, but the cover letter makes it clear this is a work-in-progress aimed at real beginners rather than experienced users. The tone is refreshingly pragmatic, treating the tutorial as a living document that will evolve with further testing.
