This is the second installment of the Git Contributor's Summit 2026 notes, focusing on **Git 3.0 planning**. The discussion is high-level and strategic, not a code patch, but it sets the timeline and scope for a major release.

The group reached consensus on a two-phase rollout: a **2.99 "signal" release** in early 2027, followed immediately by **3.0**, which will flip default settings for breaking changes (e.g., disabling SHA-1, mandating Rust support). The 2.99 release is intended to give users and distributions a clear warning before the actual 3.0 cutover. No objections were recorded to requiring Rust in 3.0, and the schedule now targets **March–April 2027** for the final releases.

Key decisions include dropping the planned 2.57 release in favor of an earlier 2.98, and considering a **2.99 LTS** for distributions like Gentoo that want long-term support for the pre-3.0 codebase. The SHA-256 interoperability work—allowing SHA-1 and SHA-256 repositories to exchange objects—is described as complete but not yet upstreamed; brian m. carlson confirmed it handles historical tags and is already in use on Codeberg.

The discussion also touched on ecosystem readiness: GitHub expects general availability of SHA-256 support by November 2026, GitLab already has it, and JGit remains unsupported (Google will not fund it). The notes suggest the project is comfortable proceeding without JGit, relying instead on libgit2 and potential future work in gitoxide.
