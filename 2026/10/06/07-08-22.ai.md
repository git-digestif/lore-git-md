This is the fourth patch in Harald Nordgren’s six-patch feature series improving `git status` and `git push` handling of rebased push branches. It focuses on the push rejection message when the push target (`@{push}`) has diverged from the local branch but is not the upstream branch.

The patch modifies `builtin/push.c` to detect when the branch that diverged is not the upstream and, in that case, names the specific remote branch in the rejection hint. Instead of the generic *"Use 'git pull' before pushing again"*, the message now says *"Use 'git pull origin topic' to integrate the remote changes"*, making it clear which branch to pull from. The logic is careful to fall back to the generic message if the push target *is* the upstream, preserving the existing behavior in that case.

The implementation adds a new advice message (`message_advice_pull_from_branch_before_push`) and extends `advise_pull_before_push()` to take the push remote as an argument. It uses `repo_remote_for_push_tracking()` and `apply_refspecs()` to resolve the push target’s refname, then compares it to the upstream branch to decide which advice to show. The patch also adds two new tests in `t/t6040-tracking-info.sh`: one verifying the new message when pushing to a non-upstream push branch that someone else updated, and another confirming the old message is still used when pushing to the upstream.

This change is a natural follow-up to the earlier patches in the series, which introduced the machinery to distinguish commits originating from upstream from those that don’t. Here, that distinction is used to make the push rejection message more actionable. The patch is well-scoped, the commit message is clear, and the test coverage is thorough. It should be uncontroversial, though real-world testing may reveal edge cases around refspec resolution or ambiguous branch names.
