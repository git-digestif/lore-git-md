This is the second patch in Harald Nordgren’s six-patch feature series enhancing `git status` and `git push` to better handle rebased push branches. It modifies `remote.c` to detect when a local branch and its push target have diverged due to a *clean rebase*—meaning the commits outside the upstream branch carry identical changes on both sides—and updates the status message to report this explicitly.

The patch introduces a new helper function, `stat_outside_upstream()`, which performs a three-way `git rev-list --cherry-mark` comparison (`branch...push ^upstream`) to count commits present in the branch-vs-push comparison but absent from upstream. If the non-upstream commits are identical (flagged by `PATCHSAME`), the function sets a `same_changes` flag. The `format_branch_comparison()` function then uses this flag to emit a new message: *"Your branch and 'origin/topic' have diverged, and have 51 and 1 different commits each (rebased cleanly on 'upstream/main')."* The test in `t/t6040-tracking-info.sh` verifies this behavior in a rebase scenario.

This is a user-facing improvement with no changes to core object storage or ref handling. The implementation is opt-in, requiring users to configure `status.compareBranches` to include `@{push}`. The patch is well-scoped, with clear commit messages and test coverage, but the logic for determining a "clean rebase" may need refinement—edge cases like merge commits, conflict resolutions, or cherry-picks that alter content are not addressed here. The new message is a step toward smarter advice, but the series will likely spark discussion about whether `--force-with-lease` is always safe in these scenarios.
