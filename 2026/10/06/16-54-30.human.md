This is a documentation patch, now merged to `master`. It removes empty SYNOPSIS sections from Git’s section 7 man pages (conceptual guides like `gitglossary(7)` and `gitcli(7)`) and updates the `lint-man-section-order.perl` script to exempt section 7 documents from requiring a SYNOPSIS. The change is uncontroversial and self-contained, touching only 11 `.adoc` files and the linter script.

The v3 iteration addresses a robustness edge case: if the first line of a file does not match the expected `gitglossary(7)` pattern, the script now reports an explicit error and exits rather than proceeding with an undefined `$man_section_number`. Julia tested this behavior on a malformed file and confirmed the script fails fast with a clear message. This aligns with her preference for explicit error reporting over silent fallback, though Junio had previously suggested initializing the variable to `"0"` instead. Neither approach affects the patch’s core correctness, and the discussion remains open-ended.

The implementation is clean and declarative, using `$.` to reset section tracking at file boundaries and a simple hash (`optional_in_man_sections`) to mark SYNOPSIS as optional for section 7. Tuomas Ahola contributed the final Perl logic and is credited as coauthor. The patch passed `make lint-docs` and manual inspection of rendered output.

This is a small but well-justified improvement that eliminates redundant content without altering user-facing behavior. The follow-up discussion about linter robustness is optional and does not detract from the patch’s value.
