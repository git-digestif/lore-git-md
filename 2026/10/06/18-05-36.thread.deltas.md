## 2026/10/21

- [2026/10/21/20-05-06 by Emily Shaffer <nasamuffin@google.com>] Emily Shaffer evaluated three voting mechanism options for the proposed community voting process: Debian's devotee (which appears to require hosting, making neutral hosting tricky), CIVS (previously used by the Linux Foundation's Technical Advisory Board, which Konstantin Ryabitsev said was not too challenging to set up, and which uses the same tallying algorithm as devotee), and a GitHub poll (which would provide only simple majority and require GitHub accounts, potentially creating a barrier). She noted that devotee and CIVS seem better suited to ballots with many similar options, and that both CIVS and devotee are email-based, which aligns with her proposal to base eligibility on mailing list participation and patch submissions.
- [2026/10/21/20-05-06 by Emily Shaffer <nasamuffin@google.com>] Emily Shaffer outlined three principles guiding the voting eligibility rule: recognizing that not all contributions are code (though she believes Git has less issue with this since moderators typically have code or review contributions), avoiding dogpiling (her biggest concern, wanting to measure opinions of project participants rather than random passers-by), and keeping eligibility determination easy and scriptable (which becomes difficult if considering non-mailing-list contributions like user support on other platforms).
