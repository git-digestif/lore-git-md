This is a **bugfix report** targeting Git’s push negotiation logic, specifically a regression where repacking during a pre-push hook causes Git to resend already-advertised common history. The author, Jens Röcker, has refined their earlier report by attaching a clean, unwrapped version of the Python reproducer (`reproduce.txt`) to avoid formatting issues. The test remains self-contained and demonstrates the bug on both Apple Git 2.54.0 and upstream Git 2.56.0, with or without `push.negotiate=true`.

The issue is well-documented: when a pre-push hook repacks loose objects into a pack, the parent process’s stale pack catalogue causes `odb_has_object(OBJECT_INFO_QUICK)` to miss the repacked objects, leading the pack generator to walk and resend the entire history. The reproducer creates fresh repository pairs, seeds a 4 MiB blob as common history, and measures the receiver’s pack size after a push—showing a 4 MiB redundant transfer when the hook runs, versus a minimal 300-byte transfer without it. The test isolates system configuration, uses local transport, and outputs structured JSON results.

The report is thorough and credible, with a plausible mechanism and clear expected/actual behavior. The attached script is ready to run and preserves the exact measurements from the original report. No maintainer response or proposed fix has appeared yet, but the reproducer’s reliability makes this a strong candidate for further investigation. If you work on push negotiation, ODB, or hooks, this is worth your time.
