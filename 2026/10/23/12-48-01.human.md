This is the second patch in Patrick Steinhardt’s six-patch v2 series restoring dynamic reloading of alternate object databases in Git’s files-based ODB backend. The patch enforces a key design change: alternates are now always reloaded from the repository’s real object directory (`files->base.path`) rather than the current primary directory (`files->dirs->abspath`), which may be a temporary quarantine directory.

The change is small (two lines) but critical. It fixes a behavioral regression in `git receive-pack` where objects moved to an alternate after a quarantine was created would not be found, even if the alternates file was updated. The patch ensures that `prepare_alternates()` and `odb_files_dir_is_usable()` consistently use the repository’s real object directory, restoring pre-regression behavior. This addresses feedback from Christian Couder, who identified the issue in v1, and the fix is now uncontroversial and agreed upon.

The patch touches only `odb/source-files.c` and is purely mechanical, replacing `files->dirs->abspath` with `files->base.path` in two places. No new symbols are introduced, and the change is well-explained in the commit message. This is a targeted, low-risk fix that paves the way for the core reloading logic in the next patch.
