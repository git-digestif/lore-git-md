This is a CI/build system patch that implements the agreed stricter approach for handling Perforce, Git LFS, and JGit installations in GitHub Actions.

The patch replaces the previous behavior—where failed installations of these tools were silently tolerated—with immediate build failures on platforms that require them (ubuntu-* for all three, macos-* for Perforce). This eliminates the risk of broken downloads going unnoticed, as the corresponding tests would previously skip without alerting maintainers. The change removes the now-redundant presence checks and warnings at the end of `ci/install-dependencies.sh`, since the build will fail before reaching that point if any required tool is missing. Version output (`p4d -V`, `git-lfs version`, `jgit version`) is now printed immediately after successful installation, making it easier to debug issues.

The diff is clean and focused: it adds failure checks to each installation step, removes the final warning logic, and moves version reporting inline. This aligns with Patrick Steinhardt’s critique of the original patch, which argued that optional tools create a maintenance risk by allowing silent test skips. The new approach is more robust, though it does impose a small maintenance burden—future platform additions must explicitly list required tools, or the build will fail.

The patch is well-motivated and addresses a real problem: CI logs were cluttered with irrelevant warnings, and broken tool installations could go unnoticed. The implementation is straightforward and unlikely to be controversial, as the direction was already agreed upon in the thread. This is a small but meaningful improvement to CI reliability.
