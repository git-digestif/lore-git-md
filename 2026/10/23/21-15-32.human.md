This is the first patch in a two-patch refactoring series advancing the ongoing `the_repository` removal effort. It introduces `repo_for_each_remote()`, a new function that takes an explicit `struct repository *` parameter, and turns the existing `for_each_remote()` into a backward-compatible wrapper that passes `the_repository`. The change is mechanical and follows the established pattern of the broader project-wide effort.

The patch touches `remote.c` and `remote.h`, adding the new function and updating the call chain to read the remote configuration from the passed repository rather than the global `the_repository`. The backward-compatible wrapper ensures no disruption to existing callers, and the commit message clearly explains the motivation: enabling functions like `unique_tracking_name()` (updated in the next patch) to operate on arbitrary repository instances rather than being hardcoded to `the_repository`.

This iteration resolves the design tension Junio raised in the previous round, where the patch’s modularity promise was undercut by `for_each_remote()`’s implicit dependency on `the_repository`. By introducing `repo_for_each_remote()`, the series now fully delivers on its goal without requiring callers to document limitations. The change is well-scoped, with no behavior changes or new test requirements, and the code itself is clean and straightforward.
