This is the fourth patch in a six-patch series introducing an **incremental connectivity check** for Git fetches and pushes. This patch adds the `transfer.connectivityCheck` configuration option, which lets users choose the algorithm used for verifying object connectivity during transfers. For now, the only accepted value is `full` (the existing behavior and default), but the plumbing is in place for the incremental mode introduced in the next patch.

The patch wires up the config key in `connected.c`, adds a new internal `--connectivity-check=<mode>` flag to `git rev-list`, and documents both in the man pages. The config key is read in `check_connected()`, and the mode is passed explicitly to `rev-list`, which now knows it is running a connectivity check. This explicit signaling allows future optimizations to be scoped to connectivity checks only. Unknown config values fall back to `full` with a warning, ensuring forward compatibility.

The implementation is straightforward and self-contained, touching only the necessary files (`connected.c`, `builtin/rev-list.c`, and the documentation). The commit message is clear and concise, and the code follows Git’s conventions. This patch is purely preparatory—it doesn’t change behavior but sets the stage for the incremental mode in patch 5/6. The series as a whole is well-motivated, with benchmarks showing dramatic performance improvements for small pushes to large repositories, and this patch is a necessary step toward that goal.
