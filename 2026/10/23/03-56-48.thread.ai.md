Subject: [PATCH] diff-delta: use safe integer helpers for allocation size calculations
Series version: standalone patch (v2 posted)
Originating author: Srujith A Poojary (Outreachy contributor)
Thread type: bugfix patch

Core problem or goal
Replace manual integer arithmetic in `diff-delta.c:create_delta_index()` with the safe integer helpers `st_mult()`, `st_add()`, and `st_add3()` to prevent silent overflows during allocation size calculations. The helpers call `die()` on overflow, whereas the original code could proceed with an undersized buffer. Junio C Hamano has raised a substantive question about whether the existing bounds on `entries` and `hsize` actually prevent overflow on 32-bit platforms, making the patch’s necessity theoretical rather than practical.

Current status
v2 posted; the commit message is corrected (removing the incorrect claim that the helpers return NULL on overflow). The patch itself is unchanged. Under review, with Junio’s question about overflow risk now central to the discussion. No new version has been posted in response.

Key technical details
- File: `diff-delta.c`
- Function: `create_delta_index()`
- Symbols: `st_mult()`, `st_add()`, `st_add3()` (safe integer helpers)
- Subsystem: delta compression
- On-disk format: unchanged
- Test coverage: none added by this patch; existing tests exercise the code path
- Bounds check: `if (bufsize >= 0xffffffffUL) entries = 0xfffffffeU / RABIN_WINDOW;` caps `entries` and derived `hsize`
- Overflow risk: Junio questions whether `memsize` can exceed `SIZE_MAX` on 32-bit systems given the cap

Open questions and loose ends
- **Primary**: Can the integer arithmetic in `create_delta_index()` actually overflow on 32-bit platforms, or does the existing bounds check prevent it? (high weight)
- Alignment of `st_add()` and `st_add3()` arguments (low weight, stylistic; noted by Phillip Wood).
- Potential edge case: whether `hsize + 1` could overflow before being passed to `st_mult()` (low weight, bounds question; noted by Phillip Wood).
