Core problem or goal
Replace manual integer arithmetic in `diff-delta.c:create_delta_index()` with the safe integer helpers `st_mult()`, `st_add()`, and `st_add3()` to prevent silent overflows during allocation size calculations. The justification remains a theoretical risk: while current bounds on `entries` and `hsize` prevent overflow on 32-bit platforms under the existing `struct unpacked_index_entry` layout, Junio’s analysis confirms that padding to an 8-byte boundary could still cause `4 * hsize + 16 * entries` to exceed 2³². The patch documents this struct-padding scenario as a plausible (if unobserved) overflow risk, aligning with the project’s defensive coding standards.

Key technical details
- File: `diff-delta.c`

- Symbols: `st_mult()`, `st_add()`, `st_add3()` (safe integer helpers)

- Test coverage: none added by this patch; existing tests exercise the code path
- Bounds check: `if (bufsize >= 0xffffffffUL) entries = 0xfffffffeU / RABIN_WINDOW;` caps `entries` and derived `hsize` at 2²⁶, ensuring `hsize + 1` cannot overflow
- Overflow risk: confirmed present under 8-byte struct padding (theoretical, no observed cases)
- Struct layout: `struct unpacked_index_entry` contains two `unsigned int` fields; padding to 8-byte alignment would make its size 16 bytes, enabling overflow in `4 * hsize + 16 * entries`
