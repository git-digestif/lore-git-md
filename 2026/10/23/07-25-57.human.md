This is the twelfth patch in Christian Couder’s 13-patch series implementing **pack index v3** support for SHA-1/SHA-256 interoperability. The patch enables Git to look up **compatibility object IDs** (e.g., SHA-1 in a SHA-256 repository) in packfiles, closing a key gap in the bidirectional mapping infrastructure.

The core change is in `odb/source-packed.c`, where the `for_each_prefixed_object_in_pack()` function is extended to iterate over **both the main and compatibility hash algorithms** when resolving object IDs. The patch introduces logic to skip unsupported algorithms (e.g., v1/v2 indices, which only store the main algorithm’s object IDs) and uses new helpers like `nth_packed_object_id_algop()` and `nth_packed_object_offset_algop()` to retrieve compatibility object IDs from v3 indices. The implementation is careful to preserve existing behavior for single-algorithm lookups while adding support for cross-algorithm disambiguation (e.g., `git rev-parse --output-object-format`).

A new test in `t1016-compatObjectFormat.sh` verifies the functionality: it creates a repository, repacks with a v3 index, removes the loose object map, and confirms that abbreviated compatibility object IDs (e.g., `sha1:abc123...`) can still be resolved. The test also demonstrates that v2 indices (which lack compatibility data) fail gracefully, ensuring no silent fallbacks to incorrect behavior.

The patch is **well-motivated and technically sound**, with clear commit messages and thorough test coverage. It builds directly on earlier patches in the series (e.g., v3 index writing/reading) and addresses a critical usability gap: without this change, users could not reliably reference packed objects in the compatibility algorithm. The implementation is conservative, avoiding performance regressions by skipping unsupported indices early and reusing existing lookup infrastructure.

**Key files touched**: `odb/source-packed.c`, `packfile.c`, `packfile.h`, and `t/t1016-compatObjectFormat.sh`.
**New helpers**: `nth_packed_object_offset_algop()` (extends `nth_packed_object_offset()` to handle cross-algorithm lookups).
**Test coverage**: Adds a test for abbreviated compatibility object ID resolution in packed objects.

This patch is **ready for review** and should be uncontroversial, though reviewers may want to verify:
1. The algorithm iteration logic in `odb/source-packed.c` (e.g., does it handle edge cases like `GIT_HASH_UNKNOWN` correctly?).
2. Thread-safety of the new lookup code (e.g., is the iteration over packfiles safe under concurrent access?).
3. The choice to skip v1/v2 indices entirely (is this the right trade-off between correctness and compatibility?).
