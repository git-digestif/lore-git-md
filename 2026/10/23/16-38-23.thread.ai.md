Subject: [PATCH] ci: pin GitHub Actions to full commit IDs
Series version: standalone patch
Originating author: Taylor Blau <ttaylorr@openia.com>
Thread type: patch

Core problem or goal
Pin all GitHub Actions in the main workflow file to full commit SHAs instead of version tags or branches, motivated by organizational policies requiring explicit commit hashes for security/compliance (preventing CI compromise via malicious action updates). The patch itself makes no functional changes to Git’s behavior—only to CI execution on GitHub.

Current status
Under review; no prior version recorded. Junio C Hamano has raised a **substantive policy objection**: the change addresses a downstream constraint (organizational compliance) rather than an upstream need, and he suggests such modifications belong in downstream forks. The patch’s justification may need strengthening to demonstrate broader project benefit beyond compliance.

Key technical details
- File touched: `.github/workflows/main.yml`
- 32 action references replaced (e.g., `actions/checkout@v6` → `actions/checkout@d23441a48e516b6c34aea4fa41551a30e30af803`)
- Actions affected: `actions/checkout`, `actions/github-script`, `actions/upload-artifact`, `actions/download-artifact`, `actions/setup-python`, `git-for-windows/setup-git-for-windows-sdk`, `git-for-windows/get-azure-pipelines-artifact`, `microsoft/setup-msbuild`
- Each replacement retains the original version tag in a trailing comment
- No functional changes to Git’s behavior; purely CI infrastructure
- Part of broader CI modernization efforts (branches `ps/ci-housekeeping-and-modernizations` and `jk/http-curl-strip-creds`)

Open questions and loose ends

- **Precedent risk**: Junio warns that accommodating one organization’s policy could invite conflicting requests from others ("last one wins" scenario).
