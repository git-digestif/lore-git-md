Subject: [PATCH] ci: pin GitHub Actions to full commit IDs
Series version: standalone patch (v2 pending)
Originating author: Taylor Blau <ttaylorr@openia.com>
Thread type: patch

Core problem or goal
Pin all GitHub Actions in the main workflow file to full commit SHAs instead of version tags or branches, motivated by security concerns: explicit commit hashes prevent CI compromise via malicious action updates or supply-chain attacks. The patch makes no functional changes to Git’s behavior—only to CI execution on GitHub.

Current status
Under review; Junio C Hamano has conditionally accepted the change pending a revised commit message that more clearly articulates the security rationale (direct control over CI dependencies, reduced attack surface, mitigation of supply-chain risks). The prior **substantive policy objection**—that the change addresses a downstream constraint rather than an upstream need—has been softened but not fully withdrawn; Junio remains concerned about precedent ("last one wins") but is willing to proceed if the trade-offs are explicitly documented. No technical objections exist. A v2 is expected.

Key technical details
- File touched: `.github/workflows/main.yml`
- 32 action references replaced (e.g., `actions/checkout@v6` → `actions/checkout@d23441a48e516b6c34aea4fa41551a30e30af803`)
- Actions affected: `actions/checkout`, `actions/github-script`, `actions/upload-artifact`, `actions/download-artifact`, `actions/setup-python`, `git-for-windows/setup-git-for-windows-sdk`, `git-for-windows/get-azure-pipelines-artifact`, `microsoft/setup-msbuild`
- Each replacement retains the original version tag in a trailing comment
- No functional changes to Git’s behavior; purely CI infrastructure
- Part of broader CI modernization efforts (branches `ps/ci-housekeeping-and-modernizations` and `jk/http-curl-strip-creds`)

Open questions and loose ends
