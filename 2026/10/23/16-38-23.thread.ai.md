Subject: [PATCH] ci: pin GitHub Actions to full commit IDs
Series version: standalone patch
Originating author: Taylor Blau <ttaylorr@openia.com>
Thread type: patch

Core problem or goal
Pin all GitHub Actions in the main workflow file to full commit SHAs instead of version tags or branches, motivated by security concerns: explicit commit hashes prevent CI compromise via malicious action updates or supply-chain attacks. The patch makes no functional changes to Git’s behavior—only to CI execution on GitHub.

Current status
Under review; no prior version recorded. Junio C Hamano has raised a **substantive policy objection**, arguing the change addresses a downstream constraint (organizational compliance) rather than an upstream need and should remain in downstream forks. Taylor Blau counters that the security benefits (direct control over CI dependencies, reduced attack surface) justify upstream adoption, framing the maintenance overhead (SHA updates for security fixes) as a worthwhile trade-off. The debate remains unresolved; no technical objections exist.

Key technical details
- File touched: `.github/workflows/main.yml`
- 32 action references replaced (e.g., `actions/checkout@v6` → `actions/checkout@d23441a48e516b6c34aea4fa41551a30e30af803`)
