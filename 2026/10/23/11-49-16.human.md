This is the final patch in Patrick Steinhardt’s **v3 object storage extension series**, which introduces pluggable object database backends for Git. This patch teaches `git submodule` to propagate the `--object-storage-format=` option to newly cloned submodules, mirroring the existing behavior for `--ref-storage-format=`.

The patch updates `git-submodule.sh` and `builtin/submodule--helper.c` to accept the new option in both the `add` and `update` subcommands, ensuring that submodules inherit the parent repository’s object storage configuration. The implementation follows the established pattern for ref storage: submodules receive the *type* (e.g., `files`) but **not the payload** (e.g., `files://objs` becomes `files`), a deliberate design choice for consistency. The patch also adds validation to reject invalid formats (e.g., `--object-storage-format=garbage`) and explicitly blocks payloads in submodule clones, aligning with the series’ earlier restrictions.

Documentation in `git-submodule.adoc` is updated to describe the new option, and a new test script (`t7427-submodule-object-storage-format.sh`) verifies propagation, error handling, and edge cases like recursive clones and explicit format overrides. The tests confirm that submodules retain the parent’s storage type while ignoring payloads, and that the `.git/objects` directory is correctly relocated when a payload is used.

This patch is **well-crafted and uncontroversial**, completing the series’ submodule support without introducing new design questions. The implementation is consistent with the ref storage backend, and the tests cover the expected behavior thoroughly. If the series lands, this patch will be a straightforward inclusion.
