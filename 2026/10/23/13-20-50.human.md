This is a **shell completion** and **documentation** patch series from D. Ben Knoble, now at v2, addressing a mix of usability improvements and cleanup for `git stash`. The series is small (five patches, 18 lines added, 12 removed) and touches Bash/Zsh completion scripts, the `git-stash` man page, and the built-in command help text.

The first three patches are uncontroversial and fix real problems: patch 1 refactors stash subcommand completion to use Git’s built-in helper, adding the previously omitted `store` subcommand; patch 2 extracts common stash-listing code to reduce duplication; patch 3 fixes a Zsh-specific bug where stash names like `stash@{0}` were not completing correctly due to Zsh’s brace expansion. The Zsh fix is a targeted override—Bash is unaffected, and the author confirms no portable solution exists.

The last two patches are more of a policy question: they remove the deprecated `git stash save` from the man page synopsis and from completion entirely. The subcommand has been deprecated since Git 2.16 (2018) but is still documented and completed as if it were current. The author frames this as a cleanup and conversation starter rather than a demand, and the v2 commit messages now clarify that option completion for manually typed `git stash save --<tab>` still works, which softens the impact. The `GIT_COMPLETION_SHOW_ALL` setting restores `save` to the list of completable subcommands if needed.

The v2 changes are minor but helpful: reworded commit messages (thanks to Patrick Steinhardt) and clearer documentation of the behavior around `git stash save`. The series is well-structured, with focused patches and good commit messages. The first three patches look ready to merge; the last two are worth discussing but not blocking. No tests are added, but the Zsh fix addresses a real usability issue that lacked automated coverage.
