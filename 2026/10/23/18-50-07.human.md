This is a bugfix and refactoring patch that aligns the behavior of `remote.<name>.followRemoteHEAD` with an earlier change for `fetch.followRemoteHEAD`. The patch defers validation of the remote-level setting until it is actually needed (during `git fetch`), eliminating spurious warnings emitted by commands like `git push` or `git remote -v` that load remote configuration but never use this setting.

The implementation is clean and well-motivated. It replaces the parsed `follow_remote_head` and `no_warn_branch` members in `struct remote` with a raw string (`follow_remote_head_raw`) and a seen flag, deferring parsing to the `get_follow_remote_head()` helper in `fetch.c`. The `enum follow_remote_head_settings` definition has been moved to `fetch.c` since it is no longer referenced in `remote.c`. Error messages now distinguish between the fetch-level and remote-level settings by passing the variable prefix from the caller, addressing a blocker from the v1 review.

The patch also includes a minor documentation improvement, replacing `$branch` with `<branch>` in the AsciiDoc synopsis for consistency. Test coverage is thorough, adding cases for the new behavior and verifying that unrecognized values are properly reported with the correct variable name. The NEEDSWORK comment left behind by the earlier change (86129fd) is removed, and the `set_head()` function is updated to compare against the raw string when deciding whether to rewrite "always" to "warn".

This looks like a straightforward improvement that eliminates a persistent annoyance while maintaining backward compatibility. The v2 patch addresses all substantive feedback from the v1 review, and the remaining changes are minor style and refactoring tweaks.
