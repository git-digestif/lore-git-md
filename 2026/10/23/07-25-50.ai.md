This is the fifth patch in Christian Couder’s 13-patch series implementing **pack index v3** for SHA-1/SHA-256 interoperability. It refactors `repo_oid_to_algop()`—the function that maps object IDs between hash algorithms—to use the new ODB mapping infrastructure (`odb_map_oid()`) introduced earlier in the series.

The change is a **cleanup and simplification**: the old implementation manually handled loose-object map lookups and reloads, while the new version delegates this logic to the ODB layer. The patch removes 12 lines of code, replacing them with a single call to `odb_map_oid(repo->objects, src, to, dest, 0)`. This aligns with the series’ goal of centralizing mapping logic in the ODB backend, making future extensions (e.g., packed-object support) easier.

**Key details**:
- **Function affected**: `repo_oid_to_algop()` in `object-file-convert.c`.
- **Behavior change**: None; the function’s external contract is preserved. The cleanup logic (e.g., reloading the loose-object map if an object is missing) is now handled inside `odb_map_oid()`.
- **Dependencies**: Relies on patches 1–4, which introduced `odb_map_oid()` and the ODB mapping callbacks.
- **Testing**: No new tests are added here, but the patch is covered by existing tests in `t1016-compatObjectFormat.sh` (which verify mapping correctness).

**Assessment**: This is a **low-risk, high-value refactor**. The patch is mechanically straightforward and improves code clarity by reducing duplication. It’s unlikely to be controversial, though reviewers may want to verify that the `flags` parameter (currently `0`) is used correctly in later patches (e.g., `OBJ_MAP_WRITE`). The commit message could be slightly clearer about why the cleanup logic is still necessary (it’s now handled by `odb_map_oid()`), but the rationale is evident from the code.
