This is the v3 cover letter for a performance-focused patch series that teaches `git ls-files` to reuse and update the untracked cache populated by `git status`. The series now consists of three patches, all previously summarized in the thread context.

The key update in v3 is a behavioral change to avoid blocking index writers: the index lock is now released after reading the directory but before printing paths, so a slow reader of `git ls-files` output can no longer hold the lock. The `--debug` mode is also explicitly excluded from optional index writes, ensuring the stat data shown reflects what was read from the index rather than what might be written back. The rest of the series remains unchanged from v2, including the ignore-file hash fix (patch 1), cache sharing between `git status -unormal` and `git status -uall` (patch 2), and the core `git ls-files` cache reuse functionality (patch 3).

The benchmarks continue to show dramatic improvements: on a synthetic tree with 100,000 files, a wildcard query (`**/pyproject.toml`) now runs in 33 ms (down from 241 ms upstream), and combined `git status` + `git ls-files` time drops from 293 ms to 93 ms. The series touches `dir.c`, `builtin/ls-files.c`, and updates documentation and tests, with no on-disk format changes. The new tests cover cache reuse, optional index writes, and fsmonitor token preservation, while the performance tests in `t/perf/p3010-ls-files.sh` quantify the speedup.

The changes are well-motivated and address the feedback from v1 (premature benchmark claims) and v2 (cache sharing between status modes). The v3 adjustments are minor but important for correctness and usability, particularly the lock release timing and `--debug` behavior. No objections or requests for changes have been raised yet, and the series appears ready for substantive review. The author has demonstrated attention to detail in addressing edge cases (e.g., pathspec prefixes, `--with-tree`, concurrent index modifications) and maintaining backward compatibility.
