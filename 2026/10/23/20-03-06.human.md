This is the third and final patch in a well-crafted performance series that teaches `git ls-files` to reuse and update the untracked cache populated by `git status`. The patch is clean, thoroughly tested, and addresses the feedback from earlier iterations.

The core change is straightforward: `git ls-files --others --exclude-standard` now reuses the untracked cache when available, eliminating redundant directory scans. The implementation is careful about edge cases: it respects `--no-optional-locks`, avoids writing the index when a pathspec prefix or `--with-tree` is used, and releases the index lock before printing paths to prevent blocking other writers. The commit also ensures exclude-file processing order matches the pre-cache behavior, preserving correctness.

New tests cover cache reuse after `git status -unormal`, optional lock handling, `--debug` behavior, and fsmonitor token preservation with `index.skipHash`. The performance tests in `t/perf/p3010-ls-files.sh` quantify the speedup: a wildcard query (`**/pyproject.toml`) on a 100 k-file tree runs in 33 ms (down from 241 ms), and combined `git status` + `git ls-files` time drops from 293 ms to 93 ms.

The patch is part of a three-patch series that also fixes an ignore-file hash inconsistency (patch 1) and enables cache sharing between `git status -unormal` and `git status -uall` (patch 2). All three patches are self-contained, modify no on-disk formats, and maintain backward compatibility. No objections have been raised yet, and the series appears ready for substantive review.
