This is the **v3 revision of a documentation patch series** replacing the outdated `gittutorial` man page with a beginner-focused two-part guide. The series is now **mechanically complete** and ready for merging, pending only Junio’s final review.

The new tutorial is based on extensive user testing with 112 participants, most of whom completed it successfully. It covers local repository creation, commits, and pushing to a remote host (GitHub/GitLab), while avoiding confusion about Git’s decentralized model. The author, Julia Evans, frames this as a "good enough" version for merging, with plans to iteratively improve it post-merge based on user feedback—particularly for branching and collaboration, which were the most requested additions.

Key changes in v3 include:
- **Compatibility note**: The tutorial now specifies it works with Git 2.23.0 or later (when `git switch` was introduced), aligning with future branching content.
- **Platform clarification**: Added a note that Windows users should use Git Bash, with a disclaimer about potential adjustments for PowerShell.
- **Editor warnings**: A new section warns users about `vi` being the default editor, provides escape instructions, and suggests configuring an alternative editor or using `git commit -m`.
- **SSH key handling**: Improved instructions for copying SSH keys, including a `cat` example to avoid pasting filenames, and a note that the key filename may vary (e.g., not always `id_ed25519.pub`).
- **Minor UX tweaks**: Added a section emphasizing the importance of `git status`, clarified `--set-upstream` behavior, and incorporated small phrasing fixes from test readers.

The series retains some unresolved pedagogical choices, such as starting with `git init` (instead of `git clone`), using `git commit -m` (for simplicity), and leaving SSH key generation generic (`ssh-keygen` without `-t ed25519`). These were debated in earlier rounds but are not blockers. The author also opted to keep Setext-style headings (e.g., `----`) for consistency with Git’s existing documentation, despite acknowledging Atx-style (`==`) might be easier to maintain, due to a linter constraint on the `DESCRIPTION` section.

The patch touches only `Documentation/gittutorial.adoc`, replacing the old content entirely. No code changes are involved. The motivation is clear: the existing tutorial is outdated, and the new version has been validated through user testing. The unresolved questions are practical and unlikely to derail merging, though they may spark follow-up discussion. The author’s urgency stems from funding constraints, but the patch itself is uncontroversial.
