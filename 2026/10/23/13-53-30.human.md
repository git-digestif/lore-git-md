This is a bugfix patch targeting `git apply`. The author, Hannes Brandstätter-Müller, reports a regression where applying a patch series containing a pure rename followed by an edit fails when `core.fileMode=false` is set. The error message is "renamed: wrong type".

The reproduction case is clear: create a file, rename it, edit it, generate a patch series, then try to apply it with `--check`. The failure occurs only when `core.fileMode=false`; it works fine with `core.fileMode=true` or when applying the patches separately. The issue was introduced somewhere between Git 2.44.0 and 2.45.0, and the author suspects commit 0482c32c33 ("apply: ignore working tree filemode when !core.filemode, 2023-12-26") as the likely culprit, though they haven't confirmed this with a bisect.

The proposed fix is a one-line change in `apply.c` that falls back to `patch->old_mode` when `previous->new_mode` is zero. The patch includes a regression test that fails without the fix and passes with it. The author has also run the broader `t41*` and `t42*` test suites, which passed with no new failures.

This looks like a well-researched and narrowly scoped bugfix. The reproduction is straightforward, the diagnosis is plausible, and the fix is minimal. The regression test adds confidence that the fix doesn't break other cases. The patch is likely to receive attention from reviewers familiar with the apply subsystem.
