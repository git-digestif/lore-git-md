This is the first patch in Phillip Wood’s seven-part refactoring series `pw/stash-optimize-check_changes-calls/v4`, which is now cooking in `next` and on track for `master`. The patch introduces an `enum create_result` to replace the integer return type of `do_create_stash()`, distinguishing between success (`CREATE_SUCCESS`), errors (`CREATE_ERROR`), and cases where no changes were stashed (`CREATE_EMPTY`). This is a preparatory step for later patches that will add a fourth state (`CREATE_NO_CHANGES`) to handle the "no changes to stash" scenario more cleanly.

The patch also fixes a minor behavioral anomaly: `create_stash()` previously exited with status 1 when `do_create_stash()` returned 1 (indicating no changes), even though `create_stash()` itself had already determined there were no changes via `check_changes()`. With the new enum, `create_stash()` now exits 0 when there are no changes to stash, aligning with its documented behavior. The change is confined to `builtin/stash.c` and touches several helper functions (`stash_staged()`, `stash_patch()`, `do_create_stash()`, `create_stash()`, and `do_push_stash()`), updating their return types and logic to use the enum.

This is a well-crafted refactoring with a clear technical rationale. The enum improves code clarity and type safety, and the behavioral fix is a sensible correction. The patch is part of a larger performance-focused series that eliminates redundant index operations, but its immediate impact is purely structural. No user-visible behavior changes are intended beyond the exit-status correction, and the patch has already incorporated all prior feedback, including Junio’s stylistic suggestions for v4. If you care about `git stash` internals or performance optimizations, this series is worth tracking.
