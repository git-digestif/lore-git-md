This is the fifth patch in Phillip Wood’s seven-patch series `pw/stash-optimize-check_changes-calls/v4`, which is now cooking in `next` and on track to graduate to `master`. The series refactors redundant index operations in `git stash push` and `git stash create`, eliminating unnecessary `lstat()` calls and index refreshes while preserving existing behavior.

This patch replaces `reset_tree()` with `create_index_from_tree()` in `stash_working_tree()` to create the temporary index file used for stashing uncommitted working tree changes. The key improvement is avoiding side effects on the repository’s in-memory index and the global state relied upon by `set_alternate_index_output()`. By switching to `create_index_from_tree()`, the patch removes the need for `set_alternate_index_output()` and its associated global variable, making the code easier to reason about. It also adds a `reset` boolean parameter to `create_index_from_tree()` to control whether the index is reset or merged, preserving intent-to-add entries that would otherwise be lost. As a bonus, the patch eliminates a redundant `repo_read_index_preload()` call, saving one `lstat()` per changed path.

The change aligns the implementation with the existing pattern used for `git stash push -p`, improving consistency. Junio’s review of the previous iteration praised this patch as "the most interesting step in the series" for its elimination of in-core index flipping and side effects. The patch is confined to `builtin/stash.c` and touches only the `stash_working_tree()` and `create_index_from_tree()` functions. No user-visible behavior changes are introduced beyond the performance and code hygiene improvements.
