This thread is the start of a 13-part patch series refactoring Git’s loose object mapping logic as part of the ongoing **ODB (object database) abstraction** effort. The series is authored by brian m. carlson and carried forward by Christian Couder, who posted this first patch.

The patch introduces a new helper function, `source_loose_object_map_oid()`, which extracts the core logic for looking up object IDs in a loose object map. Instead of implicitly relying on the repository global, the helper takes an explicit `struct odb_source_loose` parameter, making the code more modular and reusable. The existing `repo_loose_object_map_oid()` function is then updated to use this helper, preserving its current behavior while paving the way for future ODB abstraction work. The change is mechanical and preparatory, touching only `loose.c` and `loose.h` without altering behavior or adding tests.

This series is a building block for Patrick Steinhardt’s long-running effort to restructure Git’s object storage layer, enabling pluggable backends. The patch itself is low-risk, but the series as a whole will likely interest contributors working on storage backends, hash transition, or repository scalability.
