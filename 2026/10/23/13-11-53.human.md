This is the **cover letter for v5 of a six-patch performance feature** that introduces an **incremental connectivity check** for Git fetches and pushes. The series is **ready for integration** and addresses all prior feedback from Junio C Hamano and Patrick Steinhardt.

The goal is to reduce the cost of verifying object connectivity during transfers, which currently scales with the size of the repository rather than the size of the incoming changes. The new opt-in mode (`transfer.connectivityCheck=incremental` or `auto`) processes incoming commits in topological order, tracking trusted objects from parent commits to skip unchanged subtrees. This shifts the cost from repository size to incoming change size, with benchmarks showing up to **190x speedup** for small pushes to large repositories (1.9s → 0.01s) and **14 MB vs. 3.4 GB memory usage** in the same scenario.

The **auto mode** (patch 6/6) dynamically switches between incremental and full checks based on a **configurable 1,000-commit cutoff**, balancing performance and safety. The series includes **thorough documentation** (a new technical doc explaining the algorithm), **extensive test coverage** (795-line correctness suite and 92-line performance benchmarks), and **refactoring** to drop `the_repository` dependencies. The latest revision (v5) resolves Junio’s forward-compatibility concern by **eliminating reliance on `repo->fetch_if_missing`** in the new code paths, using `odb_read_object_info_extended()` with `OBJECT_INFO_SKIP_FETCH_OBJECT` instead.

The implementation is **self-contained**, touching only `rev-list`, `connected.c`, and a new `tree-verify.c` (427 lines). Edge cases (promisor objects, shallow boundaries, deepening fetches) are handled via fallback to the full check. The series is **well-motivated**, with clear benchmarks and a conservative design (opt-in, configurable cutoff). No new blockers remain, and the maintainer’s tone ("This is exciting") suggests strong interest. If you care about large-repository performance, this is worth reviewing.
