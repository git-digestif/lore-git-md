This is the **core implementation patch (5/6) of a six-patch performance feature** introducing an **incremental connectivity check** for Git fetches and pushes. The patch adds the new `tree-verify.c` source file (433 lines) and wires it into `builtin/rev-list.c` and `connected.c`, implementing the inductive trust algorithm described in the series' technical documentation.

The incremental check processes incoming commits in topological order, comparing each new tree against its trusted parent trees. Only entries that differ from parents are recursively verified, skipping unchanged subtrees. This shifts the cost from repository size to the size of incoming changes, with dramatic speedups for small pushes to large repositories (up to 190x faster, 14 MB vs. 3.4 GB memory usage). The implementation preserves partial-clone semantics, promisor-object handling, and corruption detection, and falls back to the full check for deepening fetches, clones, and pushes into empty repositories.

Key technical details include:
- **New source file `tree-verify.c`**: implements the verifier with a three-state tree tracking system (untrusted/trusted/expanded), a work queue for untrusted entries, and recursive verification with same-path parent subtree comparison. Uses `kh_oid_tree_t` and `oidset` for efficient OID tracking.
- **Performance instrumentation**: Trace2 events (`trees_loaded`, `blobs_checked`) measure overhead.
- **Error handling**: Centralized at the subprocess boundary, with improved error messages for missing/corrupt objects. Uses `odb_read_object_info_extended()` with `OBJECT_INFO_SKIP_FETCH_OBJECT` to avoid lazy fetches, addressing Junio’s forward-compatibility concern.
- **Edge cases**: Handles gitlinks, promisor objects, replacement objects, shallow boundaries, and tree/blob type mismatches. The recursive tree verification is bounded by `core.maxTreeDepth` to match the full check’s behavior.
- **Integration**: The verifier runs inside `rev-list` after the normal revision walk, consuming incoming commits before the usual object traversal. The `verify_commits_incremental()` function is called from `cmd_rev_list()` when the `--connectivity-check=incremental` flag is set.

The patch includes **thorough test coverage** in the new `t/t5413-connectivity-check.sh` (774 lines), verifying semantic equivalence with the full check, corruption detection, promisor-object handling, and integration with fetch/push/clone. The tests use a synthetic repository with nested directories and controlled changes to isolate connectivity-check overhead, and include trace2-based assertions for tree/blob counts. The patch also updates `t/t6700-tree-depth.sh` to enforce the same recursion limits as the full check.

The implementation is **well-executed and self-contained**, with clear commit messages and detailed documentation in `Documentation/technical/connectivity-check.adoc`. The series is **ready for integration**, having addressed all prior feedback (including Patrick Steinhardt’s concerns about stack overflow risk and error handling) and rebased onto the latest `master`. The only remaining loose end is the **stack overflow risk for very deep trees**, which is acknowledged in the documentation and planned for a follow-up.
