This is a **feature patch** revisiting the default behavior of `git status` in triangular workflows. The patch itself (v2) was summarized earlier; this email is Junio C Hamano’s reply expressing skepticism about changing the default.

Junio’s core objection is that the patch assumes users in triangular workflows *want* to see both `@{upstream}` and `@{push}` comparisons by default, but the commit message does not provide evidence that this assumption holds. He argues that `@{push}` is typically a personal branch where only the user pushes, so monitoring it closely is less critical than monitoring `@{upstream}`, which may receive unexpected changes from others. The escape hatch (`status.compareBranches = @{upstream}`) is acknowledged, but Junio dismisses it as insufficient justification for surprising existing users.

The email also questions the claim that users new to triangular workflows would benefit most from the change. Junio points out that such users must already configure `push.default` and a push remote, so they are equally capable of discovering the `status.compareBranches` setting. The tone suggests the patch’s rationale remains unconvincing, and the default should not be changed without stronger evidence of user demand.

This reply reopens the discussion that v2 appeared to close. The patch is well-crafted and addresses prior feedback, but Junio’s objection is not about implementation—it’s about whether the change is desirable at all. The thread is now back in review, and further progress likely depends on either new data (e.g., user surveys or anecdotes) or a shift in Junio’s assessment. For now, the patch is not ready for merging.
