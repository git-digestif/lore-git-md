This is a CI/build system patch that tightens GitHub Actions behavior by making tool installation failures fatal on relevant platforms. The patch replaces the previous warning-based approach with strict checks: if Perforce, Git LFS, or JGit fail to install on ubuntu-* (all three tools) or macos-* (Perforce), the build now fails immediately rather than allowing tests to skip silently. The change is confined to `ci/install-dependencies.sh` and aligns with the thread’s consensus that explicit failures are preferable to silent skips.

The implementation is straightforward and well-scoped. Each tool installation step now includes error handling that prints a message and exits with status 1 on failure. The final presence checks and warnings are removed entirely, since the build would have already failed if installation had not succeeded. Version output (`p4d -V`, `git-lfs version`, `jgit version`) is printed immediately after successful installation, providing clear confirmation in the logs. Junio’s review notes the removal of cleanup steps (no longer needed after failing fast) and the elimination of redundant checks as improvements.

The patch reflects the agreed direction from earlier discussion, where Patrick Steinhardt argued that optional tools create a risk of unnoticed test skips. Harald Nordgren’s v2 patch implements this stricter approach without substantive disagreement from other participants. The only minor point Junio raises is a potential inconsistency in error handling for macOS’s `xattr` step, but this does not affect the patch’s correctness or the overall goal.

This is a low-risk, high-signal change that reduces CI noise and improves reliability. The patch is ready for final review and looks likely to be merged. If you care about CI hygiene or have ever been frustrated by silent test skips, this is worth a quick look.
