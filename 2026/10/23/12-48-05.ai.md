This is the sixth and final patch in Patrick Steinhardt’s v2 series restoring dynamic reloading of alternate object databases in the files-based ODB backend. It introduces a `struct stat_validity` field to track the alternates file’s mtime and inode, allowing Git to skip re-reading the file when it hasn’t changed. The optimization reduces lookup time for 20k missing objects from 262.7ms (post-patch 5) to 199.5ms, nearly matching the pre-regression baseline of 185.3ms. Memory usage increases slightly (4.3% over the broken state) but remains within acceptable bounds.

The patch modifies `odb/source-files.c` and `odb/source-files.h`, adding the `alternates_validity` field to `struct odb_source_files` and updating `read_alternates()` to conditionally parse the file only when its stat data differs. The change is mechanical and preserves correctness: if the file cannot be read, the validity struct is cleared, ensuring the next attempt will re-read it. The recursive alternate resolution (`add_alternate_recursively`) passes `NULL` for the validity parameter, as nested alternates are not tracked for changes.

Performance benchmarks are included in the commit message, showing a 30.9% speedup over the unoptimized fix (patch 3) and a 1.4x improvement over the pre-regression state. The patch completes the series, which is now well-scoped, uncontroversial, and ready for merging. No further objections or edge cases have been raised in the thread.
