This is a performance optimization series targeting `git ls-files` and `git status`, now in its second revision. The goal is to eliminate redundant directory traversals by reusing the untracked cache populated by `git status`, with benchmarks showing a 7.3× speedup (241 ms → 33 ms) for wildcard queries on large repositories.

The series is well-structured and addresses a real pain point: repeated invocations of `git ls-files` and `git status` in common workflows (e.g., build systems or IDE integrations) currently scan the working tree redundantly. Patch 1 fixes a long-standing inconsistency in ignore-file hash computation, ensuring the cache remains valid. Patch 2 enables cache sharing between `git status -unormal` (stops after first untracked file) and `git status -uall` (lists all untracked files) by refactoring `read_directory_recursive()` to expand partial listings on demand. Patch 3 teaches `git ls-files` to reuse the cache and optionally write updates back to the index, with safeguards for pathspec prefixes, `--with-tree`, and `--no-optional-locks`.

The implementation is careful: it avoids modifying on-disk formats, maintains backward compatibility (older Git versions rebuild the cache before use), and includes thorough test coverage for performance, cache sharing, and edge cases like fsmonitor integration. The benchmarks—using `hyperfine` on a synthetic 100,000-file tree—demonstrate consistent speedups across cache modes and fsmonitor configurations. The author has addressed feedback from v1 by expanding the scope (adding cache sharing between status modes) and clarifying trade-offs (e.g., scanning more directories for wildcard pathspecs to benefit repeated queries).
