This thread is about Patrick Steinhardt’s seven-patch series introducing a new `extensions.objectStorage` configuration mechanism for Git’s object database (ODB). The series is part of his ongoing effort to make Git’s object storage pluggable, allowing alternative backends beyond the traditional loose-objects-and-packfiles system.

The second patch in the series adds the `extensions.objectStorage` repository extension, which lets users specify the primary object storage backend using a URI-like string (e.g., `files:///path/to/objects`). Currently, only the `files` schema is supported, corresponding to Git’s default backend, but the mechanism is designed to be extensible. The patch updates repository initialization code, adds plumbing in the ODB subsystem, and documents the new extension. It maintains backward compatibility by ignoring the extension unless `core.repositoryFormatVersion` is set to 1, ensuring no user-visible changes unless explicitly configured.

The implementation introduces an `enum object_storage_format` and updates `struct repository` and `struct repository_format` to store the backend format and payload. Tests verify that the extension works as expected with the `files` backend and rejects unknown backends. So far, the series appears uncontroversial, with no substantive objections or requests for changes raised in this patch. The focus remains on laying the groundwork for future backends while keeping the current behavior unchanged by default.
