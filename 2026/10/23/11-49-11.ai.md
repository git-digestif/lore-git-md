This is the second patch in a seven-patch series introducing a new `extensions.objectStorage` configuration mechanism for Git's object database (ODB). The series is part of Patrick Steinhardt's ongoing ODB abstraction effort, which aims to make Git's object storage pluggable.

The patch adds a new repository extension (`extensions.objectStorage`) that lets users specify the primary object storage backend via a URI-like string (`<schema>[://<payload>]`). Currently, the only supported schema is `files`, which corresponds to Git's traditional loose-objects-and-packfiles backend. The payload for the `files` backend allows users to override the default `.git/objects` directory location. The patch updates the repository initialization code to parse and apply this extension, adds the necessary plumbing in the ODB subsystem, and documents the new extension in `Documentation/config/extensions.adoc` and a new `Documentation/object-storage-format.adoc` file.

Key technical details: the patch introduces an `enum object_storage_format` to represent supported backends, adds fields to `struct repository` and `struct repository_format` to store the format and payload, and modifies `odb_source_new()` to accept these parameters. The implementation is careful to maintain backward compatibility: the extension is ignored unless `core.repositoryFormatVersion` is set to 1, and the default behavior (traditional `.git/objects` directory) remains unchanged. Tests verify that the extension is rejected with repo version 0, works with the `files` backend, and correctly rejects unknown backends.

The patch is well-structured and clearly motivated. It lays the groundwork for future alternative backends while introducing no user-visible behavior changes beyond the new configuration knob. The commit message and documentation are thorough, and the test coverage is appropriate for the scope. This looks like a solid step in the ODB abstraction effort.
