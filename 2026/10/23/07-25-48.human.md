This is the third patch in Christian Couder’s 13-part series implementing **pack index v3** for SHA-1/SHA-256 interoperability. The patch adds a simple but crucial control flag (`OBJ_MAP_WRITE`) to the loose-object mapping layer, allowing the caller to decide whether a newly recorded object-ID mapping should be written to disk immediately or kept in memory.

The change is a small, targeted refactoring: the existing `source_add_loose_object_map()` function gains an `int flags` parameter, and the new `OBJ_MAP_WRITE` bit (chosen as `1 << 6` to avoid colliding with future object-type bits) gates the actual disk write. All existing callers continue to behave exactly as before—they pass `OBJ_MAP_WRITE` and thus write mappings to disk—so there is no functional change in this patch. The motivation is future-proofing: later patches in the series will use the flag to defer disk writes while indexing packs, keeping compatibility object IDs in memory until the entire pack is processed.

The patch is clean, well-motivated, and introduces no regressions. It is uncontroversial and ready for review.
