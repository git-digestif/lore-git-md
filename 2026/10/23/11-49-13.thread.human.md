This thread is about Patrick Steinhardt’s ongoing work to extend Git’s object database (ODB) abstraction. The fourth patch in his seven-part series introduces two new ways to inspect a repository’s object storage format: `git rev-parse --show-object-storage-format` and the `git repo` field `objects.storageFormat`. The change is purely additive, exposing the existing `extensions.objectStorage` value (or `files` if unset) with an optional payload suffix. The implementation is straightforward, touching `odb.c`, `builtin/repo.c`, and `builtin/rev-parse.c`, and includes tests in `t0001-init.sh` and `t1900-repo-info.sh`.

So far, the patch appears uncontroversial—it mirrors the existing ref-storage-format inspection commands and doesn’t alter behavior. This is part of Patrick’s larger ODB abstraction effort, which aims to make Git’s object storage layer more modular. No reviews or objections have surfaced yet, but the series is still early in its lifecycle. If you’ve been following the ODB work, this is a small but logical step forward.
