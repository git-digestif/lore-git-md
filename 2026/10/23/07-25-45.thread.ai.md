Thread identity: SHA-1/SHA-256 interoperability effort, part 3 – pack index v3 support. Series version: initial posting (no vN tag yet). Originating author: Christian Couder (based on brian m. carlson’s prior work). Thread type: patch series.

Core problem or goal: Implement pack index v3, a new index format that stores object IDs in both the main and compatibility hash algorithms, enabling bidirectional mapping between SHA-1 and SHA-256 repositories. This is the third installment in the interoperability effort; parts 1 and 2 (ODB infrastructure and loose-object mapping) are already merged to `master`.

Current status: Under review. Series consists of 13 patches split into four logical groups: (1) ODB mapping infrastructure (patches 1–5), (2) pack index v3 writing (patches 6–8), (3) pack index v3 reading (patches 9–12), and (4) documentation (patch 13). Key improvements over brian’s original branch include adaptation to Patrick Steinhardt’s `ps/odb-files-alternates` topic, strict duplicate detection, v3 index validation, and improved error handling. Patch 2/13 renamed `repo_add_loose_object_map()` to `source_add_loose_object_map()` to better reflect its parameter type; patch 3/13 adds a `flags` parameter to the same function, introducing the `OBJ_MAP_WRITE` flag (bit 6) to control whether mapped object IDs are written to disk. Patch 4/13 introduces the ODB mapping infrastructure with `odb_map_oid()` and `odb_write_oid_map()`, implementing them for the "files" backend (loose and packed sources). Patch 5/13 refactors `repo_oid_to_algop()` to use the new ODB mapping infrastructure (`odb_map_oid()`), removing 12 lines of manual lookup/reload logic and replacing it with a single call to `odb_map_oid(repo->objects, src, to, dest, 0)`. This centralizes mapping logic in the ODB layer, simplifying future extensions (e.g., packed-object support). Mappings are written only to the main object directory, and the "packed" sources currently return "not found" for both reading and writing, deferring full support until later patches. The `ODB_MAP_OID_RELOAD` flag forces a reload of the loose object map, while `ODB_WRITE_OID_MAP_WRITE` (aliased to `OBJ_MAP_WRITE`) controls disk writes.

Key technical details: Files touched: `pack-write.c`, `packfile.c`, `odb/` (loose.c, packed.c, source-loose.c, source-files.c, loose.h, etc.), `object-file-convert.c`, headers. New or renamed symbols: `odb_map_oid()`, `odb_write_oid_map()`, `source_add_loose_object_map()` (formerly `repo_add_loose_object_map()`), `nth_packed_object_id_algop()`, `nth_packed_object_offset_algop()`, `OBJ_MAP_WRITE` (1 << 6), `ODB_MAP_OID_RELOAD`, `ODB_WRITE_OID_MAP_WRITE`. On-disk format change: pack index v3 stores object IDs in both algorithms, sorted by each algorithm’s hash. Test coverage: new tests in `t1016-compatObjectFormat.sh` (v3 writing/reading, large files, abbreviated IDs), `t5308-pack-detect-duplicates.sh` (duplicate detection), and `t5313-pack-bounds-checks.sh` (bounds checking). No performance regressions expected.

Open questions and loose ends: (1) v3 index validation logic (patch 10) may draw scrutiny. (2) Memory usage during indexing: compatibility object IDs are kept in memory. (3) Index-pack cannot yet map objects whose dependencies (e.g., trees referenced by commits) are not already mapped. (4) Multi-pack-index does not yet support compatibility object IDs. (5) Automatic v3 selection and `show-index` support are deferred to later parts of brian’s series. (6) Bit choice for `OBJ_MAP_WRITE` (1 << 6) should be reviewed for potential conflicts with future object-type flags. (7) Reviewers may want to check the reload logic in `odb_source_files_map_oid()` and the decision to write mappings only to the main object directory. (8) The `flags` parameter in `odb_map_oid()` (currently `0` in patch 5) should be reviewed for correct usage in later patches (e.g., `OBJ_MAP_WRITE`).
