This is a documentation patch series that introduces `gitmergeconflicts(7)`, a new man page consolidating Git’s merge conflict resolution guidance. The series is now in its fourth version (v4) and is ready for merging, having addressed all prior feedback.

The core goal is to fix a long-standing usability issue: Git’s documentation currently scatters merge-conflict advice across multiple command man pages, leading to duplication, omissions, and confusion. The new `gitmergeconflicts(7)` guide centralizes this information, clarifies terminology (e.g., "ours" vs. "theirs"), and provides practical examples. The series also updates existing man pages (`git merge`, `git rebase`, `git revert`, `git cherry-pick`, and `git pull`) to link to the new guide instead of repeating conflict-resolution advice.

Key improvements in v4 include Junio’s refined `diff3` example, which now uses neutral language ("has" instead of "added") and illustrates a scenario where both sides removed a fruit from a list, emphasizing how the common ancestor reveals the *intent* behind conflicting changes. The guide also now includes `git am -3` in the exhaustive list of conflict-causing commands, following Junio’s clarification that it behaves identically to other three-way merge operations. Mechanical fixes—punctuation consistency, spelling out `--patch` instead of `-p`, and removing a redundant `Signed-off-by`—round out the updates.

The series is well-crafted and thoroughly reviewed. All patches carry Junio’s `Reviewed-by` (patches 2–6) or are finalized with his squashable refinements (patch 1). The new guide is additive, with no behavior changes, and integrates cleanly into the documentation build system. The only loose ends are deferred follow-ups: a more thorough explanation of `zdiff3` (removed from the guide) and potential enhancements like embedding commit details in conflict markers. These are non-blocking and may evolve into separate efforts.

This is a user-focused improvement that addresses a real pain point. The guide’s structure—prioritizing examples and workflows over technical minutiae—aligns with the project’s recent documentation efforts (e.g., Jean-Noël Avila’s synopsis-style conversion).
