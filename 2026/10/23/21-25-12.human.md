This is a **bugfix patch** targeting the ODB transaction layer, addressing a data-loss bug in repositories using compatibility hashes (e.g., SHA-1/SHA-256 interop) with batch fsync enabled. The issue occurs when migrating loose objects from a temporary directory to the primary object directory: the "loose-object-idx" mapping file (which tracks object-to-compatibility-hash mappings) fails to merge if an index already exists in the primary directory, causing entries to be lost. The patch introduces `loose_object_idx_merge()` to append new entries to the primary index instead of overwriting it, preserving both old and new mappings.

The discussion here is a **follow-up to Patrick Steinhardt’s substantive review**, where he raised concerns about locking, atomicity, duplicate entries, and child process writes. Justin Tobler (the author) responds to each point, clarifying design choices and agreeing to some adjustments. Key takeaways from this exchange:
- **Locking**: Justin acknowledges the indefinite timeout (`-1`) in `repo_hold_lock_file_for_update_timeout()` could cause hangs and proposes making it configurable or defaulting to 1000ms. He also notes this mirrors existing behavior in `write_one_object()`.
- **Atomicity**: Patrick’s suggestion to use Git’s standard temp-file-then-rename pattern (instead of appending under lock) is accepted in principle, though Justin points out this would deviate from the current `write_one_object()` implementation.
- **Child processes**: Justin confirms `git-receive-pack` can spawn `git-unpack-objects` children that write to the quarantine directory, justifying the need to support child process writes in the migration logic.
- **Preexisting quirks**: Both agree that issues like unsorted index files, duplicate entries, and lack of pruning for stale mappings are long-term problems outside this patch’s scope.

The patch is **well-motivated and addresses a real bug**, but Steinhardt’s feedback suggests a **v2 is likely needed** to refine locking and atomicity. The regression test (`t/t1016-compatObjectFormat.sh`) is a strong addition, and the discussion remains collaborative with no signs of controversy. This is part of Patrick Steinhardt’s broader ODB abstraction effort, so the fix is worth tracking for integration. **Busy readers should watch for v2 to see how the locking and merge logic evolve.**
