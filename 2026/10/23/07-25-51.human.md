This is the sixth patch in Christian Couder’s 13-patch series implementing **pack index v3** for SHA-1/SHA-256 interoperability. It adds the core writing logic for the new index format, which stores object IDs in both the main and compatibility hash algorithms.

The patch extends the `pack_idx_entry` struct to include a `compat_oid` field (for the secondary hash) and an `idx` field (to track the object’s position in pack order). The `write_idx_file()` function is refactored to handle v3 indices: it now writes two sorted object ID tables (one per algorithm), computes the minimum padding needed to align tables on 4-byte boundaries (for architectures that disallow unaligned access), and enforces strict duplicate detection in both tables. The main hash algorithm is always written first to optimize CRC32 lookups for native operations.

Key implementation details:
- **Format**: The v3 header includes a count of hash algorithms (`nr_formats`), and each algorithm’s table is preceded by a `pack_idx_format_header` specifying its format ID, short name length, and offset.
- **Memory**: When writing a v3 index, the patch duplicates the object array to maintain both pack order and sorted order, freeing the copies before returning.
- **Strict mode**: Duplicate detection now checks both the main and compatibility object ID tables.
- **Limitations**: The patch does *not* yet populate `compat_oid` (that comes in a later patch) or enable v3 by default (to avoid breaking tests until reading support is added).

The changes are confined to `pack-write.c` and `pack.h`, with no user-visible behavior changes in this patch. The code is clean, well-commented, and builds on the ODB mapping infrastructure introduced earlier in the series. Reviewers may focus on the padding calculation, memory usage during indexing, and the decision to always write the main hash first.
