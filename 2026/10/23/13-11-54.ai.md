This is the **first patch in v5 of a six-patch performance feature series** introducing an incremental connectivity check for Git fetches and pushes. This patch adds **technical documentation** explaining the connectivity invariant, the mechanics of the existing full connectivity check, and the boundary between incoming and already-connected objects.

The new file, `Documentation/technical/connectivity-check.adoc`, is a **259-line technical note** that describes the connectivity invariant (every object reachable from references must be available locally, with exceptions for submodules and promisor objects), the purpose of the check (preventing truncated or corrupted transfers from leaving the repository in a broken state), and the implementation of the full check (a `git rev-list` subprocess with `--not --all` to establish the trust boundary). It includes a **detailed example graph** illustrating the boundary commits, incoming commits, and already-connected commits, and explains edge cases like deepening fetches (where the shallow boundary moves) and non-commit tips (tags, trees, or blobs).

The documentation is **well-structured and thorough**, covering both the high-level purpose and the low-level mechanics. It is **build-system integrated** (added to both `Makefile` and `meson.build`) and will be useful for future contributors working on connectivity-related code. The patch itself is **minimal and self-contained**, touching only the documentation directory and adding no new code or behavior.

This patch is **not controversial** and appears ready for integration. It provides the necessary background for the rest of the series, particularly the incremental verifier implementation in patch 5/6 and the auto mode in patch 6/6. The documentation is **clear and accurate**, and the example graph is a helpful aid for understanding the trust boundary. No prior feedback on this patch has been noted, and it aligns with the series' overall goal of improving connectivity-check performance.
