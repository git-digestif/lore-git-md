This is the first patch in the **v4 series introducing `gitmergeconflicts(7)`**, a new man page consolidating Git’s merge-conflict resolution guidance. The patch creates the core document (`Documentation/gitmergeconflicts.adoc`), adds it to the build system (`Makefile`, `meson.build`, `command-list.txt`), and configures `.gitattributes` to handle conflict markers in the source file.

The new guide is **339 lines of practical, example-driven documentation** addressing long-standing user pain points: scattered advice across multiple man pages, inconsistent terminology ("ours" vs. "theirs"), unclear references (e.g., "steps 2 and 3"), and cultural assumptions (RCS analogies, "let's go shopping"). Key sections include:
- **What is a merge conflict?** Explains Git’s behavior during conflicts (staging merged files, leaving conflicted files unstaged) and defines "original" (common ancestor).
- **Commands that can cause conflicts**: Lists `git merge`, `git rebase`, `git cherry-pick`, `git pull`, `git revert`, and others, with a note that `git am -3` is included in later patches.
- **Resolution workflow**: A four-step process (identify, edit, stage, continue) with formal phrasing ("You can either resolve the conflict or abort the operation").
- **Merge conflict markers**: Explains `<<<<<<<`, `=======`, `>>>>>>>`, and `|||||||` (in `diff3`), with side-by-side examples contrasting default and `diff3` formats.
- **Tools for handling conflicts**: Static views (`git diff`, `git log --merge --patch <filename>`) vs. dynamic ones (`git diff AUTO_MERGE`, graphical merge tools), with active promotion of `merge.conflictstyle=diff3`.
- **"Ours" and "theirs"**: Explicitly ties these terms to `HEAD` and the other commit, clarifying the "upside down" behavior during rebases.
- **Sample `git status` output**: Guides users to `--abort`/`--continue` commands.

The patch is **finalized**—all feedback from v1–v3 is incorporated, including Junio’s squashable refinements to the `diff3` example (now using neutral language and a scenario where both sides *removed* a fruit) and Patrick Steinhardt’s editorial suggestions. The `zdiff3` deprecation note is removed, deferring a more thorough explanation to future work. The guide’s focus on user-reported confusion (e.g., "ours" vs. "theirs") and practical examples (e.g., `AUTO_MERGE` diffs) makes it a clear improvement over the current scattered documentation.

**Files touched**: `.gitattributes`, `Documentation/Makefile`, `Documentation/meson.build`, `command-list.txt`, and the new `gitmergeconflicts.adoc`. **No behavior changes**—this is purely additive documentation.
