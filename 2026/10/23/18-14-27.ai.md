This is a maintainer review of the `rev-list --grep` bugfix patch, focusing on test quality. Junio C Hamano points out that the two new tests in `t/t6022-rev-list-missing.sh` are too weak: they only verify that the command does not fail when `--grep` is followed by an argument starting with `--`, but they do not actually check whether the grep pattern was applied. The tests compare output between `--grep=--missing-only` and `--grep --missing-only`, but since there is no commit in the test history whose message contains `--missing-only`, the tests pass regardless of whether the pattern was used. The same flaw applies to the second test, which uses `--grep --exclude-promisor-objects`.

Junio’s feedback is substantive: he is not questioning the fix itself (which remains a minimal two-line change in `builtin/rev-list.c`), but rather the adequacy of the test coverage. The tests as written do not distinguish between “the parser did not crash” and “the grep pattern was actually matched.” This leaves the patch’s correctness claim unproven. The author will need to revise the tests to include a commit whose message contains the pattern being tested, so that the output actually changes when the pattern is matched. No other changes to the code or commit message are requested at this stage.
