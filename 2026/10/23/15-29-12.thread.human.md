This thread is about an Outreachy microproject proposal to add test coverage for the `--no-allow-onelevel` option in `git check-ref-format`. Fien Dora, an Outreachy applicant, identified that while the existing test suite covers `--allow-onelevel`, it omits tests for `--no-allow-onelevel` and its interaction with `--allow-onelevel`. The proposal was met with community approval: Harald Nordgren confirmed the expected command-line behavior (exit code 1 when both options are used), and Phillip Wood endorsed the test gap as a suitable microproject, praising its small scope and clear benefit.

Phillip Wood later clarified the technical reasoning behind the observed behavior: when both options are specified, Git's option parser honors the last one (`--no-allow-onelevel` overrides `--allow-onelevel`), causing the command to fail because "foo" is a one-level ref name, which `--no-allow-onelevel` explicitly rejects. This explanation underscores the importance of adding tests to document the behavior explicitly. No objections or requests for changes have been raised, and the microproject is now approved in principle. The next step is for Fien to draft a patch adding the tests to `t/t1402-check-ref-format.sh`.
