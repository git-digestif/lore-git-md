This is part of the ongoing SHA-1/SHA-256 interoperability effort, specifically **patch 4/13** in Christian Couder’s series implementing pack index v3 support. This patch adds the core ODB mapping infrastructure that enables bidirectional translation between object IDs in different hash algorithms.

The patch introduces two key functions—`odb_map_oid()` and `odb_write_oid_map()`—and implements them for the "files" backend (which handles both loose and packed objects). The "files" backend searches all object directories (main and alternates) for mappings, reloading loose object maps if needed to catch updates from other processes. New mappings are written only to the main object directory, mirroring how Git writes new objects. The "packed" source currently returns "not found" for both functions, as pack index v3 support (which will enable reading these mappings) comes in a later patch.

The implementation is careful about concurrency: it reloads loose object maps on demand when another process might have added new mappings. The `ODB_MAP_OID_RELOAD` flag controls this behavior, while `ODB_WRITE_OID_MAP_WRITE` (aliased to the existing `OBJ_MAP_WRITE` flag) determines whether mappings are persisted to disk or kept in memory. This design allows later patches to defer disk writes during indexing, avoiding unnecessary I/O.

This is a **well-crafted, incremental step** in the interoperability effort. The code is clean, the commit message is clear, and the patch integrates smoothly with Patrick Steinhardt’s `ps/odb-files-alternates` topic. No functional changes are introduced yet—this is purely infrastructure—but it lays the groundwork for the v3 index writing and reading logic that follows. Reviewers may want to check the error handling and the choice of flags, but the patch looks uncontroversial and ready for feedback.
