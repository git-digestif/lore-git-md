This is the first patch in a now-finalized documentation series introducing `gitmergeconflicts(7)`, a new man page that consolidates Git’s merge-conflict resolution guidance. The patch adds the core 339-line guide, which is the centerpiece of the series. The new page is well-structured, example-driven, and addresses long-standing user pain points: scattered and inconsistent advice across multiple command man pages, unclear terminology ("ours" vs. "theirs"), and outdated analogies (e.g., RCS references).

The guide covers foundational concepts (what a merge conflict is, when it occurs), an exhaustive list of commands that can trigger conflicts (`git merge`, `git rebase`, `git cherry-pick`, `git pull`, `git am -3`, `git checkout -m`, `git stash pop`, `git revert`), and a clear four-step resolution workflow (identify, edit, stage, continue). It actively promotes `merge.conflictstyle=diff3` as a best practice, using side-by-side examples to demonstrate how the common ancestor reveals intent (e.g., both sides removing a fruit from a list). The "ours" and "theirs" section explicitly ties these terms to `HEAD` and the other commit, clarifying the "upside down" behavior during rebases. Practical tools like `git diff AUTO_MERGE` and `git log --merge --patch <filename>` are explained with examples, and the guide includes sample `git status` output to guide users toward `--abort`/`--continue` commands.

The patch touches five files: the new `Documentation/gitmergeconflicts.adoc`, plus build system updates (`Makefile`, `meson.build`, `command-list.txt`) and `.gitattributes` to set conflict-marker size. No CLI options, config keys, or runtime behavior changes are introduced—the new guide is purely additive. This patch is the most substantive in the series and delivers the core value: a single, authoritative resource for merge conflicts that replaces duplicated advice in existing man pages. The guide’s focus on user-reported confusion (e.g., "ours" vs. "theirs") and practical examples makes it a valuable addition.
