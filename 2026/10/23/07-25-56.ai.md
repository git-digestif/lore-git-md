This is **patch 11/13 in the SHA-1/SHA-256 interoperability series**, implementing **packed-object mapping via pack index v3**. The patch teaches Git to look up packed objects in the compatibility hash algorithm when they are not found in the loose object map, using the new v3 index format that stores object IDs in both algorithms.

The core change is in `odb/source-packed.c`, where `odb_source_packed_map_oid()` is updated to iterate through all packfiles, skip those with v1/v2 indices (which only store the main algorithm’s object IDs), and use `nth_packed_object_id_algop()` to retrieve the compatibility object ID from v3 indices. The new helper `nth_packed_object_id_algop()` extends the existing `nth_packed_object_id()` to handle cross-algorithm lookups, returning an error if the index lacks data for the requested algorithm. The patch also updates `packfile.c` to validate that both source and destination algorithms are supported by the v3 index before attempting a lookup.

A new test in `t1016-compatObjectFormat.sh` verifies that packed objects are correctly mapped only when a v3 index is present: it creates a repository, repacks with a v3 index, removes the loose object map, and confirms that `git rev-parse` can still resolve the compatibility object ID. The test also checks that a v2 index (which lacks compatibility data) fails to provide a mapping, ensuring the code does not silently fall back to incorrect behavior.

This patch is a **logical and well-tested extension** of the v3 index infrastructure introduced earlier in the series. It addresses a key limitation of the loose-object-only mapping approach by leveraging the v3 index’s ability to store both hash algorithms, and the changes are narrowly scoped to the packed-object lookup path. The test coverage is thorough, and the commit message clearly explains the motivation and implementation. No performance regressions are expected, though the added packfile iteration may have a minor cost in repositories with many packs. Reviewers may want to verify the thread-safety of the new lookup logic and the correctness of the algorithm validation in `nth_packed_object_id_algop()`.
