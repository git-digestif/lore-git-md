This is a **follow-up discussion** in the ongoing review of Justin Tobler’s bugfix patch for the ODB transaction layer, addressing a loose-object-idx migration failure in repositories using compatibility hashes (SHA-1/SHA-256 interop) with batch fsync enabled. The patch introduces `loose_object_idx_merge()` to append new mapping entries to the primary index instead of overwriting it, preventing data loss during temporary object directory migration.

Justin responds to Patrick Steinhardt’s **substantive review** with clarifications and proposed adjustments. Key updates and unresolved questions:
- **Terminology**: Justin agrees to tweak the commit message to call the "loose-object-idx" a "mapping file" for clarity, though the name itself remains unchanged.
- **Child processes**: Justin confirms that `git-receive-pack` can spawn `git-unpack-objects` to write loose objects (and thus mapping entries) into the quarantine directory, justifying the need to support child process writes.
- **Locking**: Justin acknowledges the indefinite timeout (`-1`) in `repo_hold_lock_file_for_update_timeout()` could cause hangs and proposes either making it configurable or defaulting to 1000ms. He also agrees to explore Git’s standard temp-file-then-rename pattern for atomicity, moving away from appending under lock.
- **File corruption and duplicates**: Justin notes these are preexisting issues in `write_one_object()` and defers addressing them to avoid scope creep, though Patrick’s concerns about partial writes and duplicate entries remain open.
- **Stale entries**: Both agree the lack of pruning for stale mapping entries is a separate long-term problem.

**Assessment**: The discussion is collaborative and technical, with Justin receptive to feedback but cautious about overhauling preexisting quirks. The patch is likely headed for a **v2** to address locking, atomicity, and possibly duplicate handling. The regression test (`t/t1016-compatObjectFormat.sh`) remains a strong addition, but the core logic needs refinement before merging. This is part of Patrick Steinhardt’s broader ODB abstraction effort and touches the compatibility-hash feature, which is still in flight. **Worth tracking for v2**, especially around locking and merge safety.
