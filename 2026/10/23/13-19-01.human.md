This is the first patch in a two-patch bugfix series (v2) that adjusts Git’s hook configuration behavior. The patch makes `hook.<event>.enabled=false` disable *both* config-defined hooks and the traditional hook in the hooks directory (`.git/hooks/`), aligning the implementation with the documentation’s wording. This is explicitly framed as a **behavior change**, not a bugfix, and acknowledges that users who relied on the old behavior (where the hookdir hook still ran) will see a change.

The patch touches `builtin/hook.c`, `hook.c`, `hook.h`, `Documentation/config/hook.adoc`, and the test suite (`t/t1800-hook.sh`). The core change is moving the `event_disabled` flag from the `configured` struct to the top-level `struct hook`, so it applies to both config and hookdir hooks. The documentation is updated to clarify that `hook.<event>.enabled` now covers both types of hooks. Tests are expanded to verify the new behavior, including checking that `git commit` skips the hookdir hook when `hook.pre-commit.enabled=false` and that `git hook list` marks hookdir hooks as "event-disabled".

The series addresses feedback from v1, where Adrian Ratiu (the original author of `hook.<event>.enabled`) proposed this middle ground to resolve the ambiguity between the documentation and implementation. Junio’s earlier hesitation about classifying this as a breaking change is now moot, as the patch is explicitly framed as a behavior change. No technical objections have been raised, but the thread remains open for broader community input on the compatibility implications. The implementation looks clean and the test coverage is thorough.
