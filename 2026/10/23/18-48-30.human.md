This is a feature patch that proposes changing the default behavior of `git status` to compare against both `@{upstream}` and `@{push}` by default, aiming to better support triangular workflows. The patch itself is technically sound—v2 addressed all earlier feedback, including adding historical context and comprehensive test coverage—but Junio C Hamano’s latest reply reopens the core justification debate.

Harald Nordgren responds to Junio’s skepticism by arguing that most users, particularly those new to Git, are already missing upstream information due to GitHub’s `git push -u` behavior, which defaults to setting the push branch as upstream. He contends that this patch would help users transition into triangular workflows by making upstream changes visible without losing the connection to the push branch, reducing confusion. His rationale emphasizes usability for non-expert users, many of whom never consult Git’s documentation.

The discussion now hinges on whether the benefit of this default change outweighs the potential surprise to existing users. Junio’s earlier objection—that `@{push}` is less likely to introduce "surprises" than `@{upstream}`—remains unaddressed in this reply, and Harald does not directly engage with it. Instead, he focuses on the user experience for beginners, which may not fully resolve Junio’s concerns about the patch’s underlying assumptions.

No new technical objections have been raised, and the implementation (modifying `remote.c`, updating documentation, and adding tests) remains unchanged. However, the patch’s readiness for merging is still in doubt unless Harald can provide a stronger argument for why the default should change. A v3 or further discussion is likely needed to settle the debate. For now, this remains a well-crafted but contentious proposal.
