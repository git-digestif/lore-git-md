This is a CI/build system patch that implements the stricter approach agreed in the thread: failing the CI build immediately if Perforce, Git LFS, or JGit fail to install on platforms where they are required. The patch replaces the original warning-based logic with mandatory installation checks, removing redundant presence checks and moving version output inline for clarity.

The change is confined to `ci/install-dependencies.sh` and affects only GitHub Actions CI behavior. On ubuntu-* (all three tools) and macos-* (Perforce), the script now exits with an error if installation fails, ensuring broken tool downloads are caught early rather than silently skipped. Version output (`p4d -V`, `git-lfs version`, `jgit version`) is printed immediately after successful installation, providing clear confirmation in the logs.

Junio's review notes the removal of cleanup steps (no longer needed since the build fails immediately) and the elimination of final presence checks as logical improvements. He raises a minor consistency question about the macOS Perforce installation: the `xattr` line is allowed to fail silently (`|| true`), but the `tar` extraction is not. This is left as-is, since the `xattr` step is non-critical and the current structure avoids complicating the error handling.

The patch is a straightforward implementation of the thread's consensus that explicit failures are preferable to silent skips. It is ready for final review and appears uncontroversial. No new technical questions or objections have been raised.
