This is the fourth patch in Christian Couder’s 13-patch series implementing **pack index v3** support for SHA-1/SHA-256 interoperability. It introduces the **ODB mapping infrastructure** that allows Git to translate object IDs between hash algorithms and persist those mappings on disk.

The patch adds two core functions—`odb_map_oid()` and `odb_write_oid_map()`—and implements them for the "files" backend (which comprises "loose" and "packed" sources). The "files" backend searches all object directories (main and alternates) for mappings, reloading loose object maps if needed to catch updates from other processes. Mappings are written only to the main object directory, mirroring how objects themselves are stored. The "packed" sources currently return "not found" for both reading and writing, deferring full support until pack index v3 is implemented in later patches.

Key technical details:
- **New functions**: `odb_map_oid()` (translates an object ID from one algorithm to another) and `odb_write_oid_map()` (persists a mapping between two object IDs).
- **Flags**: `ODB_MAP_OID_RELOAD` forces a reload of the loose object map; `ODB_WRITE_OID_MAP_WRITE` (aliased to `OBJ_MAP_WRITE`) controls whether mappings are written to disk or kept in memory.
- **Files touched**: `odb.c`, `odb.h`, `odb/source-files.c`, `odb/source-loose.c`, `odb/source-packed.c`, and `odb/source.h`.
- **Symbols introduced**: `odb_map_oid()`, `odb_write_oid_map()`, `ODB_MAP_OID_RELOAD`, `ODB_WRITE_OID_MAP_WRITE`.

This is a **foundational patch** with no user-visible behavior change yet. It prepares the ODB layer for later patches that will use these functions to write and read pack index v3 files. The implementation is clean, well-documented, and follows the established pattern of delegating backend-specific logic to individual sources. Reviewers may want to check the reload logic in `odb_source_files_map_oid()` and the decision to write mappings only to the main object directory.
