This is the sixth and final patch in Patrick Steinhardt’s v2 series restoring dynamic reloading of alternate object databases in Git’s files-based ODB backend. The patch addresses a performance regression introduced by the earlier fix: while the core logic now correctly reloads alternates when an object lookup fails, it does so unconditionally, even when the alternates file hasn’t changed. This creates unnecessary overhead in the common case where the file is static.

The solution uses `struct stat_validity` to track the alternates file’s mtime and inode. Before re-reading the file, Git now checks whether it has changed; if not, the expensive parse-and-reload step is skipped. Benchmark results show the optimization nearly restores pre-regression performance: lookup time for 20,000 missing objects drops from 262.7 ms (unoptimized) to 199.5 ms, just 14 ms slower than the original 185.3 ms baseline. Memory usage increases slightly (about 0.3 MiB) due to the `stat_validity` struct, but this is a reasonable trade-off for the speedup.

The implementation is clean and mechanical. The `read_alternates()` function is modified to accept a `stat_validity` pointer; when provided, it short-circuits the read if the file is unchanged. The `odb_source_files` struct gains a new `alternates_validity` field, initialized in `prepare_alternates()` and cleared in `odb_source_files_free()`. The patch also improves error handling by properly closing file descriptors and surfacing read errors via `warning_errno()`.

This is a well-motivated, uncontroversial optimization that completes the series. The commit message is clear, the performance data is concrete, and the code changes are minimal and focused. The series as a whole now looks ready for merging.
