This is a performance-focused patch series (v3) that teaches `git ls-files` to reuse and update the untracked cache populated by `git status`. The series is now in its third iteration, addressing feedback from earlier versions and refining the implementation.

The core goal remains reducing redundant directory traversals in common workflows where `git status` and `git ls-files` are run in sequence. The v3 update makes two key improvements: it releases the index lock before printing paths, preventing a slow reader from blocking other index writers, and it skips optional index writes when `--debug` is used, ensuring the stat data shown reflects what was read from the index rather than what might be written back.

The series consists of three patches. The first fixes a long-standing inconsistency in ignore-file hash computation, ensuring the cache remains valid when exclude files haven’t changed. The second enables cache sharing between `git status -unormal` (which stops after finding one untracked file) and `git status -uall` (which lists all untracked files), with later commands completing partial scans as needed. The third patch implements the core functionality, letting `git ls-files` reuse the cache and optionally write updates back to the index unless `--no-optional-locks` is given or the lock is busy.

Performance benchmarks show dramatic improvements. On a synthetic tree with 100,000 files, a wildcard query (`**/pyproject.toml`) now runs in 33 ms (down from 241 ms upstream), and the combined `git status` + `git ls-files` time drops from 293 ms to 93 ms. The series also benefits from fsmonitor integration, with similar speedups observed when fsmonitor is enabled. The changes are well-tested, with new performance tests in `t/perf/p3010-ls-files.sh` and expanded regression tests in `t/t7063-status-untracked-cache.sh`, `t/t3001-ls-files-others-exclude.sh`, and `t/t7519-status-fsmonitor.sh`.

The implementation is careful to maintain backward compatibility. Older Git versions will rebuild the cache before using it, and the series avoids modifying on-disk formats. The patches touch `dir.c`, `builtin/ls-files.c`, and documentation files, with no changes to core object storage or ref handling. The author has addressed earlier feedback about benchmark claims and edge cases, and the series now looks ready for serious review. If the performance gains hold up under real-world testing, this could be a significant quality-of-life improvement for users working with large repositories.
