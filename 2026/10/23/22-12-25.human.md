This is a follow-up discussion in the ongoing bugfix series for a shallow-fetch regression. The thread focuses on a **blocker-level memory management issue** in the v4 patch that exposes pending transaction state via the transport’s `negotiation_include_tips` field.

Karthik Nayak acknowledges a critical flaw in the current design: the `negotiation_include_tips` array is shared between the `--negotiation-include` user option and the fetched-tips backfill logic, risking state corruption or memory leaks. The transport only frees this array for smart transports, leaving non-smart transports (or remote helpers) with dangling state. This was initially masked by a leak sanitizer failure in `t5509-fetch-push-namespaces`, which Karthik now recognizes as an existing bug in remote-helper cleanup rather than a regression from his patch. He plans to address this with a precursor commit to fix the transport cleanup logic before revisiting the core fix.

The patch remains **not ready for `next`** until this issue is resolved. The discussion confirms that the current approach—appending fetched OIDs to `negotiation_include_tips` without exclusive ownership—is unsafe. Karthik’s proposed solution (a precursor commit to enforce cleanup) may pave the way for a safer implementation, but the shared-state problem must be addressed before the series can advance. No other technical objections are raised in this email.
