This thread is about a regression in `git apply` that breaks patch series containing a pure rename followed by an edit when `core.fileMode=false` is set. The issue, introduced between Git 2.44.0 and 2.45.0, causes the error `error: renamed: wrong type`. Hannes Brandstätter-Müller reported the bug and proposed a fix, which Aniket Gupta later refined to address a security edge case.

The discussion has focused on whether the scenario is valid input (confirmed: it is, and the workflow is supported) and whether the fix behaves correctly in reverse (also confirmed). Junio C Hamano, the maintainer, initially raised technical concerns but has now had all but one question resolved. The remaining open point—whether the two patches are applied in a single `git apply` invocation or separately—has been clarified by Aniket: the bug reproduces in both workflows, and the regression only affects `core.fileMode=false` setups. The refined fix, which masks permission bits and enforces a regular file type, has passed the broader test suite and includes a new regression test.

The patch is still under review, with no maintainer decision yet. Both Hannes and Aniket support the fix, and Junio’s technical objections have been addressed. The only loose end is whether the fix will be merged, held, or dropped.
