This thread is about a regression in `git apply` that causes patch series containing a pure rename followed by an edit to fail when `core.fileMode=false` is set. The issue, introduced between Git 2.44.0 and 2.45.0, was reported by Hannes Brandstätter-Müller, who also proposed a fix and added a regression test.

The discussion has centered on whether the scenario is valid input or corrupt data, and whether the fix should handle it. Aniket Gupta confirmed the bug, identified a security edge case in the original fix, and proposed a refined version that masks `patch->old_mode` and forces `S_IFREG`. Junio C Hamano raised fundamental questions about the validity of the input and the fix’s behavior when applied in reverse. Aniket has now clarified that the scenario is valid (produced by `git format-patch`) and that the refined fix behaves correctly in reverse, addressing Junio’s concerns.

The patch remains under review, with no maintainer decision yet. The broader test suite passes with both fixes, and the refined version is considered safer. The key remaining question is whether Junio will accept the fix or hold it pending further discussion.
