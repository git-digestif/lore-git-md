This thread is about a regression in `git apply` that causes patch series with pure renames followed by edits to fail when `core.fileMode=false` is set. The issue, introduced between Git 2.44.0 and 2.45.0, was reported by Hannes Brandstätter-Müller, who also proposed a fix and added a regression test.

The root cause lies in `apply.c`'s `check_preimage()` function, where a pure rename leaves `previous->new_mode` as zero, causing later edits to fail a file-type comparison. Hannes's fix falls back to `patch->old_mode` when `previous->new_mode` is zero, but Aniket Gupta recently identified a potential security edge case: if `patch->old_mode` includes file type bits, a malicious patch could change a regular file into a symlink when `core.fileMode=false`, bypassing the type-check that would otherwise catch this. Aniket proposed a refined fix—masking `patch->old_mode` to preserve only permission bits and explicitly setting the file type to regular (`S_IFREG`)—which passes all tests and addresses the vulnerability.

The patch is still under review, with no maintainer feedback yet. The discussion has shifted from confirming the bug to refining the fix to avoid unintended side effects, particularly around security. The next steps will likely involve further review of Aniket's proposed solution or alternative approaches.
