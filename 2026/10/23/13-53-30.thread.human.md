This thread is about a regression in `git apply` that causes patch series with a pure rename followed by an edit to fail when `core.fileMode=false` is set. The issue, introduced between Git 2.44.0 and 2.45.0, triggers an `error: renamed: wrong type` when applying such patches. Hannes Brandstätter-Müller reported the bug and proposed a fix, which Aniket Gupta later refined to address a potential security edge case where a malicious patch could change a regular file into a symlink when `core.fileMode=false`.

The discussion has now entered a critical phase with Junio C Hamano’s review. He questions whether the scenario—a pure rename followed by a patch that changes the file type—should even be considered valid input, suggesting the tool might not need to handle inherently corrupt data gracefully. He also probes the robustness of Aniket’s refined fix, particularly whether it behaves correctly when the patch is applied in reverse, a key requirement for `git apply`. No decision has been made yet; the thread remains under active review, with the focus on correctness and design intent rather than just the security implications of the original fix. The outcome will determine whether the refined fix is merged or if further adjustments are needed.
