This thread is about a regression in `git apply` that causes patch series with a pure rename followed by an edit to fail when `core.fileMode=false` is set. The issue, introduced between Git 2.44.0 and 2.45.0, was reported by Hannes Brandstätter-Müller, who also proposed a fix and added a regression test. Aniket Gupta later refined the fix to address a security edge case, and all technical concerns raised by Junio C Hamano—about the validity of the scenario, the fix's behavior under reverse application, and the workflow in which the patches are applied—have been resolved. The patch is now technically uncontested and passes the broader test suite.

The key participants are Hannes (the original reporter and fix author), Aniket (who refined the fix and addressed maintainer concerns), Junio (who raised and later resolved technical questions), and Patrick Steinhardt (who provided process feedback on mailing list etiquette). The fix itself touches `apply.c` and ensures that a pure rename followed by an edit works correctly when file mode changes are ignored, without introducing new symbols or changing on-disk formats.

The only remaining open item is Junio’s decision on whether to merge the patch. The recent exchange between Aniket and Patrick was purely procedural—Aniket acknowledged Patrick’s feedback about quoting context in replies—and did not affect the technical status of the patch. The thread is now in a holding pattern, awaiting the maintainer’s verdict.
