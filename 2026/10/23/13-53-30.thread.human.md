This thread is about a regression in `git apply` where applying a patch series containing a pure rename followed by an edit fails when `core.fileMode=false` is set, producing the error `error: renamed: wrong type`. The issue was introduced between Git 2.44.0 and 2.45.0, possibly linked to commit 0482c32c33.

Hannes Brandstätter-Müller, the author, has submitted a well-documented patch that includes a clear reproduction case, a regression test, and a proposed fix in `apply.c`. The fix addresses a scenario where a pure rename leaves `previous->new_mode` as zero, causing a later file-type comparison to fail during the edit step. The patch falls back to `patch->old_mode` when `previous->new_mode` is zero, and the accompanying test confirms the fix works while failing without it. The broader test suite (`t41*` and `t42*`) also passes with the change.

The patch is currently under review, and while the author expresses caution about the fix's correctness, the diagnosis and solution appear reasonable. This is likely to attract attention from reviewers familiar with the `apply` subsystem, particularly those who have worked on file mode handling or the `git apply` command. No responses or reviews have been posted yet, so the discussion is still in its early stages.
