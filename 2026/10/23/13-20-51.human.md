This is the first patch in D. Ben Knoble’s five-part series improving `git stash` shell completion. It refactors the Bash completion logic for `git stash` subcommands to use Git’s built-in `--git-completion-helper` mechanism instead of a hard-coded list. The change is small and mechanical, replacing a static list of subcommands with a dynamic lookup that matches how other Git commands handle completion.

The immediate benefit is that the `store` subcommand — previously omitted from the hard-coded list — is now included in completions. This fixes an oversight without changing any other behavior. The patch also preserves the special handling for the deprecated `save` subcommand: it remains completable only if `GIT_COMPLETION_SHOW_ALL=1` is set, or if the user has already typed at least "sa" (so `git stash sa<TAB>` still works). Option autocompletion for manually typed `save` (e.g., `git stash save --<TAB>`) is unaffected and continues to work as before.

The commit message is clear and explains both the motivation (reducing duplication, aligning with other completion helpers) and the edge cases (the `save` special case). The diff is minimal and focused, touching only the Bash completion script. This patch is uncontroversial and looks like a straightforward improvement. It sets the stage for the rest of the series by cleaning up the completion logic before later patches address the Zsh bug and the `save` deprecation.
