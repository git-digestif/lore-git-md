This is the fifth patch in Patrick Steinhardt’s six-patch bugfix series restoring dynamic reloading of alternate object databases in Git’s files-based ODB backend. The patch is a targeted performance optimization: it avoids redundant `stat()` syscalls when checking whether an alternate object directory already exists in the tracked set.

The change is simple but effective. The original code first checked whether the alternate directory existed on disk, then whether it was already known. This patch reorders the logic to check the in-memory `strset` (`files->dir_paths`) first, skipping the `stat()` call entirely if the path is already tracked. The benchmark shows a 3.9% speedup over the previous patch (from 269.2 ms to 260.7 ms for 20k missing-object lookups), bringing the total series performance within 10% of the pre-regression baseline.

The patch touches only `odb/source-files.c` and is purely mechanical—no new functions or data structures are introduced. The commit message includes concrete performance data and clearly explains the motivation. This is a well-justified micro-optimization that complements the broader reloading fix without adding complexity. No controversy or open questions remain; this patch looks ready to merge.
