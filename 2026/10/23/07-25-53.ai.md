This is patch 8/13 in the ongoing SHA-1/SHA-256 interoperability effort, implementing **pack index v3 support**. This specific patch ensures that large blobs streamed directly into a pack also compute and store their compatibility-algorithm object IDs, preventing corruption when the repository is in compatibility mode.

The change is small but critical: it extends `odb_transaction_files_write_object_stream()` to initialize a second hash context for the compatibility algorithm, updates both contexts during streaming, and stores the resulting compatibility object ID in the pack index entry. The patch also adds a test that verifies a 5 KB file added in a compatibility repository is correctly stored and retrievable, with its object ID matching expectations.

This is a **bugfix** that plugs a hole in the v3 index writing logic introduced in earlier patches. Without it, large blobs would silently store a null OID for the compatibility algorithm, breaking interoperability. The implementation is clean: it reuses the existing streaming infrastructure and only adds the minimal extra work needed for the second hash. The test is well-scoped and covers the exact scenario that would otherwise fail.

The patch touches `object-file.c` and adds a new test case to `t1016-compatObjectFormat.sh`. Key symbols introduced or modified: `stream_to_pack()` now takes an optional `compat_ctx` parameter, and `odb_transaction_files_write_object_stream()` initializes and finalizes the compatibility hash context when needed. The change is thread-safe and does not affect performance for non-compatibility repositories.
