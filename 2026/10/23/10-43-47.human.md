This is the second patch in Igor Wiedler’s two-patch bugfix series, now receiving a substantive review from Patrick Steinhardt. The patch teaches Git to ignore refs from alternate repositories that are shallow or grafted, preventing a performance regression where deepening fetches would force full history walks of large alternates (e.g., 7M objects). Patrick’s review confirms the fix is technically sound and aligns with Git’s existing behavior in `git clone --reference`, which already rejects shallow or grafted reference repositories. He notes the edge case of manually created shallow alternates is unlikely to matter in practice, and the change is backward-compatible—existing alternates without `shallow` or `info/grafts` files continue to work as before.

The review is substantive but brief, focusing on the design rationale rather than implementation details. Patrick raises no objections and implicitly endorses the patch by calling it "good." His only tangential comment is a mild skepticism about the broader concept of alternate refs, though this does not translate into a request for changes. The patch itself is minimal: three new file-existence checks in `odb.c` and a documentation update, with test coverage already verified in the series’ expanded `t/t5618-alternate-refs.sh`.

This patch completes the two-step fix proposed by Junio and endorsed by Peff, addressing both the immediate regression and its root cause. With Patrick’s review now added, the series has approvals from three respected contributors (Patrick, Peff, and Justin Tobler) for the core regression fix in patch 1, and no outstanding objections to patch 2. The only prior procedural blocker—a Windows CI test failure—was resolved in v3. The series looks ready for integration, resolving a real-world performance pain point in CI workflows.
