This is a brief follow-up in the ongoing discussion about the CLI design for Harald Nordgren’s `git branch --delete-merged` series, which extends the command to detect squash-merged and rebase-merged branches. Harald acknowledges Jasper Mayone’s observation that the existing `--delete-merged <pattern>` syntax (where `<pattern>` specifies the upstream branch) conflicts with any attempt to use the same flag for granular levels like `--delete-merged=squashed`. This rules out both `--delete-merged=<level>` and, by extension, `--delete-integrated=<level>` to maintain consistency.

The exchange reinforces the earlier consensus that the new functionality should be exposed via a separate flag, now likely `--delete-integrated <pattern>`, with a clean separation from `--delete-merged`. No new technical proposals or objections are raised here—this is purely a syntax clarification that removes one of the remaining design options. The next steps will involve finalizing the flag name and implementing the agreed-upon author-check mitigation to address false positives.
