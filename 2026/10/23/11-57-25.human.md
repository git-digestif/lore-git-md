This is a **brief follow-up in a bugfix thread** addressing a correctness gap in Patrick Steinhardt’s series to restore dynamic reload of alternate object databases. The series targets a regression introduced during the ODB abstraction effort, where Git lost the ability to reload alternates when an object lookup fails — a behavior observed in production systems where the alternates file may be modified while Git is running.

The exchange here is a **direct response to Christian Couder’s substantive review** of the second patch, which identified a **behavioral regression in `git receive-pack`**: when a temporary primary ODB (like the quarantine directory) is in use, the current fix reloads alternates from that directory — which has none — rather than from the repository’s real alternates. This breaks workflows where objects have moved to an alternate since the quarantine was created, even if the alternates file was updated.

Patrick **acknowledges the issue** and agrees with Christian’s proposed design change: **always reload the repository’s real alternates**, not the current `files->dirs`'s alternates. This would restore pre-regression behavior for `receive-pack` and extend it to any context using a temporary primary directory. The fix is straightforward — using `files->base.path` instead of `files->dirs->abspath` — and aligns with the series’ goal of restoring the original behavior.

The tone is **pragmatic and collaborative**, with Patrick expressing mild frustration at the complexity of the ODB abstraction but focusing on the immediate fix. This response **confirms the need for a v2** of the series, though the change itself is small and mechanical. The performance optimizations in later patches (stat validity tracking) remain valid and will not be affected by this adjustment.

For a busy reader, this email signals that the series is **on track but requires a minor revision** to address a subtle correctness issue. The fix is well-motivated, and the interaction between Patrick and Christian suggests the series is in good hands. If you care about `git receive-pack`, object quarantine, or the ODB abstraction effort, this thread is worth watching for the v2.
