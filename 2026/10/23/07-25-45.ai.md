This is part 3 of the ongoing SHA-1/SHA-256 interoperability effort, specifically implementing **pack index v3** support. The series is based on brian m. carlson's work and introduces a new pack index format that stores object IDs in both the main and compatibility hash algorithms, enabling bidirectional mapping between them.

The patch series is **well-structured and technically sound**, with clear commit messages explaining the rationale and implementation details. It builds on previous interoperability work (parts 1 and 2, already merged) and introduces the following key components:

1. **ODB mapping infrastructure** (patches 1-5): Adds callbacks for mapping object IDs between algorithms and implements them for loose and packed backends. This is the foundation for the rest of the series.
2. **Pack index v3 writing** (patches 6-8): Implements the new index format in `pack-write.c`, `index-pack`, and `pack-objects`, with strict duplicate detection and proper handling of compatibility algorithms.
3. **Pack index v3 reading** (patches 9-12): Adds support for reading v3 indices in `packfile.c`, including validation, reverse index generation, and compatibility object ID lookups.
4. **Documentation** (patch 13): Documents the v3 format in `gitformat-pack(5)`.

**Key improvements over brian's original branch**:
- Adapts to Patrick Steinhardt's `ps/odb-files-alternates` topic (single `odb->source`).
- Fixes strict duplicate detection in v3 indices.
- Adds validation for v3 index tables (new patch 10).
- Improves error handling (e.g., missing algorithm data, corrupt indices).
- Adds comprehensive tests for edge cases (duplicate objects, large files, abbreviated IDs).

**Notable technical details**:
- The v3 index format stores object IDs in both algorithms, sorted by each algorithm's hash.
- The "files" backend writes mappings only to the main object directory (like objects).
- Index-pack computes compatibility object IDs for commits/trees/tags during indexing.
- The series avoids writing mappings to disk during indexing (keeps them in memory).

**Testing**:
- Adds tests in `t1016-compatObjectFormat.sh` for v3 index writing/reading, large file handling, and abbreviated ID lookups.
- Extends `t5308-pack-detect-duplicates.sh` to test strict duplicate detection with v3 indices.
- Adds bounds-checking tests in `t5313-pack-bounds-checks.sh`.

**Limitations (not blockers)**:
- Some features (e.g., automatic v3 selection, `show-index` support) are deferred to later parts of brian's series.
- Index-pack can't yet map objects whose dependencies aren't already mapped (e.g., trees referenced by commits).
- Multi-pack-index doesn't support compatibility object IDs yet.

**Assessment**:
This is a **high-quality, incremental step** toward full SHA-1/SHA-256 interoperability. The changes are focused, well-tested, and address feedback from earlier iterations. The series is ready for review and should be uncontroversial, though reviewers may want to scrutinize:
1. The v3 index validation logic (patch 10).
2. Memory usage during indexing (compat object IDs are kept in memory).
3. Performance implications of the new index format (though no regressions are expected).

**Files touched**: `pack-write.c`, `packfile.c`, `odb/`, `loose.c`, and related headers.
**Key functions introduced**: `odb_map_oid()`, `odb_write_oid_map()`, `nth_packed_object_id_algop()`, `nth_packed_object_offset_algop()`.
**Test coverage**: Extensive, with new tests for v3-specific behavior.
