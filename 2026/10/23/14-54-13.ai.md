This is a bugfix targeting the config subsystem, specifically addressing the issue where Git ignores filesystem permission bits when writing configuration files. Junio C Hamano responds to Patrick Steinhardt’s substantive review, clarifying the scope and motivation of the patch while acknowledging the architectural question raised.

Junio explains that the patch is intentionally narrow, focusing only on out-of-tree config files like `$HOME/.gitconfig` and XDG counterparts, which are uniquely vulnerable because they reside outside the repository. He argues that in-tree files (e.g., `.git/index`) are not a concern, as users have no sensible reason to "protect" them from Git, and the existing read-only bits under `.git/objects/` serve a different purpose (preventing accidental overwrites by external tools). This distinction justifies the patch’s config-specific approach rather than a broader lockfile API refactoring.

The response also reveals a pragmatic constraint: Junio deliberately limited the patch to the caller side of the lockfile API to avoid the time-consuming task of auditing all lockfile users. This suggests the patch is a targeted fix rather than a systemic change, though Patrick’s earlier feedback may still prompt broader discussion about whether permission checks should be centralized in `lockfile.c` for consistency.

Key technical details remain unchanged: the patch introduces a `CONFIG_NO_WRITE` error code, modifies `repo_config_set_multivar_in_file_gently()`, and uses `access(2)` to check permissions before lockfile creation. The unresolved edge cases (race conditions, symlinks, NFS) are not addressed here, nor is the question of backwards compatibility with scripts expecting config writes to succeed regardless of permissions.

The tone is matter-of-fact, neither dismissing Patrick’s concern nor committing to a larger refactoring. The patch’s future may hinge on whether others weigh in on the architectural question or if the current scope is deemed sufficient. For now, it remains a well-motivated but narrowly scoped bugfix.
