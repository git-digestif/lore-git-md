This is the **third patch in the v2 series** improving `git stash` shell completion, focusing on a **Zsh-specific bugfix** for stash name completion. The patch addresses a long-standing usability issue where Zsh users could not properly complete stash names like `stash@{0}` due to Zsh’s brace expansion behavior.

The problem occurs because Git’s completion script for Zsh uses `compadd -Q`, which leaves braces unquoted. When a user types `git stash show stash@<TAB>`, Zsh treats the braces as part of a brace expansion pattern, preventing the completion from working as expected. The patch removes the `-Q` flag, allowing Zsh to quote metacharacters (e.g., `stash@\{0\}`), which resolves the issue. While this changes the displayed format slightly (adding backslashes), the author argues this is preferable to the current broken behavior.

The fix is minimal and targeted: it overrides the stash listing completion in Zsh with a working version, leaving Bash unaffected. The author confirms no portable solution exists, so the Zsh-specific override is the only viable approach for now. The patch touches only `contrib/completion/git-completion.zsh` and adds a new helper function, `__git_complete_stashes`, which replicates the logic from the Bash script but without the problematic `-Q` flag.

This is a **substantive usability improvement** for Zsh users, though it lacks automated test coverage. The change is unlikely to be controversial, but the thread remains open for discussion about whether a unified Bash/Zsh solution would be preferable. Patrick Steinhardt raised this question in the v1 review, but the author has not yet addressed it in v2. The patch stands on its own as a practical fix, even if the broader design question remains unresolved.
