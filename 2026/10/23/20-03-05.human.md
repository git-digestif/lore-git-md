This is the second patch in Tamir Duberstein’s three-patch series that lets `git ls-files` and `git status` share the untracked cache. It removes the long-standing limitation that forced a full rescan whenever the user switched between `--untracked-files=normal` (stops at the first untracked file) and `--untracked-files=all` (lists every untracked file).

The patch introduces a new `UNTRACKED_CACHE_LAZY` flag (0x80000006) that older Git versions will see as an unknown value and therefore rebuild the cache, preserving backward compatibility. Inside the cache, each directory’s `check_only` bit now marks a partial scan; when `git status -uall` needs the full listing, it rescans only the directories that were previously marked incomplete. The rest of the cache remains valid, so subsequent `git status -unormal` calls can stop early again without rescanning.

The implementation touches `dir.c` and `dir.h`, updates the on-disk index documentation to explain the new flag, and adds tests that verify partial listings are completed on demand, nested repositories are handled correctly, and wildcard pathspecs still work without triggering extra filesystem scans. The diff is large (245 lines) but most of it is mechanical refactoring of `read_directory_recursive()` and test updates; the core idea is a single flag and a few lines of logic to reuse cached directories. No on-disk format changes are made beyond the flag value, and the series remains independent of other in-flight efforts.
