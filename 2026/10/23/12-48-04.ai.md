This is the fifth patch in Patrick Steinhardt’s six-patch v2 series restoring dynamic reloading of alternate object databases in the files-based ODB backend. The patch is a performance optimization that avoids redundant `stat()` syscalls when checking whether an alternate object directory already exists in the tracked set.

The change reorders the logic in `odb_files_dir_is_usable()`: instead of first checking whether the alternate directory exists (via `is_directory()`) and then checking whether it is already known (via `strset_contains()`), the function now checks the `strset` first. This eliminates a `stat()` call for every alternate that is already tracked, reducing lookup overhead. The benchmark data shows a measurable improvement: lookup time for 20k missing objects drops from 269.2ms (with the previous patch) to 260.7ms, a 3.2% speedup over the already-optimized baseline. The optimization is straightforward and does not affect correctness, as the existence check is still performed before marking the directory as usable.

The patch touches only `odb/source-files.c` and is a clean, mechanical reordering of two code blocks. No new symbols are introduced, and the change is narrowly scoped to the performance regression introduced by the earlier patches in the series. The commit message includes concrete benchmark data, making the benefit clear. This is a well-motivated, uncontroversial optimization that complements the broader bugfix effort.
