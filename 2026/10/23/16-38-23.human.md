This is a CI/build system patch from Taylor Blau. It pins all GitHub Actions in the main workflow file (`.github/workflows/main.yml`) to full commit IDs instead of version tags or branch names. The motivation is to comply with organizational policies that restrict which actions may run, specifically requiring commit-level pinning.

The patch is mechanical: it replaces every `uses: actions/...@vN` or `uses: org/repo@branch` line with a commit SHA, keeping the version tag in a trailing comment for future reference. The diff touches 32 lines across a single file, with no functional changes to the workflow logic itself.

This is a practical housekeeping change that makes the CI workflow more portable across different GitHub Enterprise environments. The commit message is clear and the rationale is well-explained. No controversy is expected; it looks like a straightforward improvement that should be uncontroversial.
