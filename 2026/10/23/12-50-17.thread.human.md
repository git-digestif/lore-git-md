This thread is Patrick Steinhardt’s seven-patch series refactoring Git’s `rerere` subsystem to remove its implicit dependency on the global `the_repository` variable. The goal is to bundle all previously global state into a dedicated `rerere_state` struct, making the codebase more modular and explicitly repository-aware. This is part of the ongoing, multi-year effort to eliminate `the_repository` from Git’s internals.

The series is under review in its first version, posted on October 22, 2026. So far, no design objections or requests for changes have been raised, but reviewers are expected to scrutinize the locking and caching mechanisms, which are subtle and easy to break. The first three patches lay the groundwork: patch 1 introduces a repository-aware `rerere_path()` helper, patch 2 threads a `struct repository *` parameter through all internal static helpers, and patch 3 removes redundant config calls. The fourth patch, just summarized, caches the result of `is_rerere_enabled()` in the repository struct, eliminating redundant filesystem checks and config lookups. This is a straightforward performance and correctness improvement, uncontroversial but requiring verification that the caching logic handles edge cases correctly.

The series touches primarily `rerere.c` and `rerere.h`, with minor changes to `repository.c`, `builtin/rerere.c`, and `hex.c`. No new user-facing behavior or on-disk format changes are introduced, and no additional test coverage has been added. The work depends on Junio’s integration branch and Taylor Blau’s `tb/rerere-wait-for-merge-rr-lock` topic, which is already merged. Patrick is the sole participant so far, and the series remains open for review.
