This is the first patch in a 13-part series refactoring the loose object mapping logic as part of the ongoing **ODB (object database) abstraction** effort. The patch introduces a new helper function, `source_loose_object_map_oid()`, which allows looking up object IDs in a loose object map using an explicit `struct odb_source_loose` parameter instead of implicitly relying on the repository. The existing `repo_loose_object_map_oid()` function is then updated to use this helper, preserving its current behavior while making the code more modular and reusable.

The change is mechanical and preparatory: it extracts a common operation (mapping an object ID from one hash algorithm to another) into a standalone function that can later be used by other parts of the ODB abstraction. The commit message explicitly states this is "in preparation for wiring up object mapping into the ODB abstraction," which aligns with Patrick Steinhardt’s long-running effort to restructure Git’s object storage layer for pluggable backends. The patch touches `loose.c` and `loose.h`, adding the new function and updating the existing one without altering behavior.

The diff shows the new function handling the same logic previously duplicated in `repo_loose_object_map_oid()`: it checks whether the target hash algorithm is the repository’s "compat" (SHA-1) or "storage" (SHA-256) variant, looks up the source OID in the appropriate khash map, and copies the result to the destination. The existing function is simplified to iterate over loose object directories and delegate the lookup to the new helper. No tests or documentation are included, which is typical for early refactoring patches in a series.
