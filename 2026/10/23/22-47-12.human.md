This is the first patch in Harald Nordgren’s v2 series introducing `--operations` and `--historical-branch` options to `git reflog` and `git log -g`. The patch is a preparatory refactoring that replaces hard-coded reflog message strings (e.g., `"checkout: moving from "`, `"Branch: renamed "`, rebase `"start"`/`"finish"`/`"abort"`) with `#define` constants in `reflog.h`. It touches seven files but claims no behavior change.

Junio C Hamano’s review of v2 raised an architectural concern: this refactoring touches the exact places that would need to emit machine-readable markers if reflog messages were later made translatable (by splitting them into human-readable and machine-parseable parts). The later patches in the series parse these strings, creating a dependency that could complicate future work. Junio acknowledged the patch is technically sound but flagged the long-term design tension.

In this reply, Harald briefly addresses Junio’s request for tests to verify the "no behavior change" claim by pointing to existing tests that would break if the refactoring were incorrect. He does not engage with the architectural concern about translatable reflog messages. The thread remains in review, with the broader question of whether this refactoring aligns with Git’s future direction still unresolved. No other reviewers have weighed in on this specific point since Junio’s review.
