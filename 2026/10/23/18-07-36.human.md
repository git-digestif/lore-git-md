This is the fifth patch in D. Ben Knoble’s v2 series improving `git stash` shell completion. The patch removes Bash completion support for the deprecated `git stash save` subcommand, which has been deprecated since 2017. The change is straightforward: `save` is no longer offered as a completion candidate when users type `git stash <TAB>`, unless `GIT_COMPLETION_SHOW_ALL=1` is set. However, option autocompletion for manually typed `save` (e.g., `git stash save --<TAB>`) remains unaffected, preserving a muscle-memory escape hatch for users still accustomed to the old subcommand.

Junio C Hamano enthusiastically endorsed the removal ("Nice to see this go") but proposed a more user-friendly enhancement: automatically rewriting `git stash save --<TAB>` to `git stash push --<TAB>` on the first tab press, then completing options for `push`. This would nudge users toward the modern `push` subcommand while preserving the convenience of the old syntax. The author, however, declined to implement this enhancement, citing increased complexity and a lack of motivation to seek consensus for it. The thread now awaits further discussion or a potential follow-up from someone else interested in implementing Junio’s suggestion.

The patch itself is uncontroversial and well-motivated, aligning with the project’s long-standing deprecation of `save`. The only open question is whether the community prefers the current minimal approach or Junio’s more user-friendly alternative. The author has made it clear they are not planning to pursue the enhancement themselves, leaving the door open for another contributor to pick it up if there is sufficient interest. For now, the patch stands as a clean removal of deprecated functionality.
