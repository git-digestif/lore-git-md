This is the fifth patch in Phillip Wood’s seven-patch series `pw/stash-optimize-check_changes-calls/v4`, which is now cooking in `next` and on track to graduate to `master`. The patch reworks how `git stash create` generates the temporary index file used to capture uncommitted working-tree changes, replacing `reset_tree()` with `create_index_from_tree()` to avoid overwriting the in-memory index and eliminate reliance on the global-variable-based `set_alternate_index_output()`.

The key change is mechanical: `stash_working_tree()` now calls `create_index_from_tree(&info->i_tree, stash_index_path.buf, false)` instead of `reset_tree(&info->i_tree, 0, 0)` followed by `set_alternate_index_output()`. The new `reset` boolean parameter (`false` here) tells `create_index_from_tree()` to merge the tree into the temporary index rather than resetting it, preserving intent-to-add entries. This matches the pattern already used for `git stash push -p` and removes the need for `repo_read_index_preload()`, saving one `lstat()` call per changed path. The patch also deletes the now-unnecessary `set_alternate_index_output()` calls and the redundant index preload, simplifying the control flow.

The diff touches only `builtin/stash.c`, modifying `stash_working_tree()` and `create_index_from_tree()`. The latter gains the `reset` parameter and passes it through to `unpack_trees()`’s `opts.reset` field. Junio’s review of the v3 version called this patch “the most interesting step in the series,” praising its elimination of in-core index flipping and side effects; no further changes were requested. The patch is a pure refactoring with no user-visible behavior change beyond the performance gain from fewer `lstat()` calls.
