This is a bugfix patch targeting the `git apply` command. The author, Hannes Brandstätter-Müller, reports a regression where applying a patch series containing a pure rename followed by an edit fails when `core.fileMode=false` is set. The error message is `error: renamed: wrong type`.

The reproduction case is straightforward: create a file, rename it, edit it, generate a patch series with `git format-patch`, then try to apply it with `git apply --check`. The check fails, but applying the patches separately works, as does checking the series with `core.fileMode=true`. The issue appears to have been introduced between Git 2.44.0 and 2.45.0, possibly related to commit 0482c32c33 ("apply: ignore working tree filemode when !core.filemode, 2023-12-26").

The proposed fix is in `apply.c`'s `check_preimage()` function. The author observes that a pure rename leaves `previous->new_mode` as zero, and the later edit then fails a file-type comparison. The patch falls back to `patch->old_mode` when `previous->new_mode` is zero. The fix is accompanied by a regression test that passes with the change and fails without it. The broader test suite (`t41*` and `t42*`) also passes with the fix.

The patch is well-motivated and includes a clear reproduction case, a regression test, and a plausible diagnosis. The author is cautious about the fix's correctness but provides enough context for reviewers to assess it. This looks like a real bug with a reasonable proposed solution, and the patch is likely to attract attention from reviewers familiar with the apply subsystem.
