This is a CI/build system patch that pins all GitHub Actions in the main workflow file to full commit IDs instead of version tags or branches. The change is motivated by organizational policies that restrict which actions may run, requiring explicit commit hashes for security or compliance reasons.

The patch touches only `.github/workflows/main.yml`, replacing 32 instances of versioned action references (e.g., `actions/checkout@v6`) with their corresponding commit SHAs (e.g., `actions/checkout@d23441a48e516b6c34aea4fa41551a30e30af803`). Each replacement retains the original version tag in a trailing comment for maintainability. The affected actions include `actions/checkout`, `actions/github-script`, `actions/upload-artifact`, `actions/download-artifact`, `actions/setup-python`, `git-for-windows/setup-git-for-windows-sdk`, `git-for-windows/get-azure-pipelines-artifact`, and `microsoft/setup-msbuild`.

The commit message notes this is based on a merge of two other branches (`ps/ci-housekeeping-and-modernizations` and `jk/http-curl-strip-creds`), suggesting it’s part of a broader CI modernization effort. The patch itself is mechanical and low-risk, with no functional changes to Git’s behavior—only to how its CI workflows are executed on GitHub. The motivation is clear and practical, addressing a real-world constraint for some downstream users.
