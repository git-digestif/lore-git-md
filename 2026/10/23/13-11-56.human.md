This is the third patch in a six-patch series introducing an **incremental connectivity check** for Git fetches and pushes. This patch is a **refactoring** that removes the dependency on the global `the_repository` variable in `connected.c`, preparing the codebase for the upcoming incremental mode implementation.

The patch modifies `check_connected()` and its helper `check_connected_promisor()` to accept an explicit `struct repository *` parameter instead of implicitly using `the_repository`. This aligns with the ongoing `the_repository` removal effort and allows the next patches to read configuration from the correct repository. The changes are mechanical: every caller of `check_connected()` is updated to pass `the_repository` (or the appropriate repository in `bundle.c`), and the functions now use the passed-in repository for operations like `odb_reprepare()`, `repo_has_promisor_remote()`, and `add_packed_git()`.

The patch touches seven files (`builtin/clone.c`, `builtin/fetch.c`, `builtin/receive-pack.c`, `bundle.c`, `connected.c`, `connected.h`, and `fetch-pack.c`), but the changes are straightforward and do not alter behavior. The commit message is clear and credits Junio C Hamano for the suggestion. This is a well-executed preparatory step that sets the stage for the incremental mode implementation in later patches. The series as a whole is **ready for integration**, and this patch is uncontroversial.
