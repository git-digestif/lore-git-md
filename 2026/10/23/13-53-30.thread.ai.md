Subject: [PATCH] apply: fix regression in pure-rename patch series with core.fileMode=false
Series version: standalone patch (no series)
Originating author: Hannes Brandstätter-Müller
Thread type: bug report with fix

Core problem or goal
A regression in `git apply` causes patch series containing a pure rename followed by an edit to fail when `core.fileMode=false` is set. The error is `error: renamed: wrong type`. The regression was introduced between Git 2.44.0 and 2.45.0, likely by commit 0482c32c33 ("apply: ignore working tree filemode when !core.filemode, 2023-12-26").

Current status
Under review. The patch is a proposed bugfix with a regression test. No prior versions exist. The broader test suite (`t41*` and `t42*`) passes with the original fix; Aniket Gupta’s refined version also passes these suites.

Key technical details
- Subsystem: `apply.c`, specifically the `check_preimage()` function.
- Root cause: a pure rename leaves `previous->new_mode` as zero, causing a later edit to fail a file-type comparison.
- Original fix: fall back to `patch->old_mode` when `previous->new_mode` is zero.
- Refined fix: mask `patch->old_mode` to `07777` (permission bits only) and explicitly set the file type to `S_IFREG`, preventing a malicious patch from changing a regular file into a symlink when `core.fileMode=false`.
- Test coverage: new regression test added; existing `t41*` and `t42*` test suites pass with both fixes.
- On-disk format: unchanged.
- CLI: unchanged.
- New symbols: none.

Open questions and loose ends
- Whether the refined fix (masking `patch->old_mode` and forcing `S_IFREG`) is the correct resolution or if further edge cases remain.
- No maintainer or reviewer feedback beyond Aniket’s review has been recorded.

Participant positions
