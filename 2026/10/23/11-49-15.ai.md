This is the sixth patch in Patrick Steinhardt’s **v3 object storage extension series**, which introduces pluggable object database backends for Git. This patch wires up the `--object-storage-format=` option in `git clone`, mirroring the functionality already added to `git init` in the previous patch.

The implementation is straightforward: the new option allows users to specify the object storage format (e.g., `files://objs`) when cloning a repository. The patch enforces a key restriction—**local clones (hardlinking or copying objects) are disabled** if either the source or destination repository uses a non-default object storage format. This is a deliberate design choice to avoid complexity with alternative backends, though the commit message notes that future work could relax this for the `files` backend with a custom object directory path. The restriction is documented in the man page and enforced with a clear error message or a warning (depending on whether `--local` was explicitly requested).

The patch touches `builtin/clone.c`, adding the new option, validating the format, and implementing the local-clone restriction via a helper function (`is_using_default_object_storage_format`). The tests cover initialization, payload handling, error cases (invalid formats, local clone restrictions), and integration with bundle URIs. The implementation is consistent with the rest of the series, following the same `(type, payload)` design and precedence rules established earlier.
