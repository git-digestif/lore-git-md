This is the second patch in Patrick Steinhardt’s six-patch v2 series restoring dynamic reloading of alternate object databases in the files-based ODB backend. It enforces a key design change: alternates are now always reloaded from the repository’s real object directory (`files->base.path`) rather than the current primary directory (`files->dirs->abspath`), which may be a quarantine directory. This resolves the behavioral regression in `git receive-pack` identified by Christian Couder, where objects moved to an alternate since the quarantine was created were not found even if the alternates file was updated.

The patch is a minimal, targeted fix: it changes two lines in `odb/source-files.c`, replacing `files->dirs->abspath` with `files->base.path` in `odb_files_dir_is_usable()` and `prepare_alternates()`. The change ensures that alternates are always read from the repository’s real object directory, restoring pre-regression behavior. The commit message clearly explains the problem (transactions prepend a quarantine directory, which would cause `prepare_alternates()` to read from the wrong location) and the solution (use `files->base.path` instead). This is a correctness fix, not a performance optimization, and it is uncontroversial: the design change was proposed by Christian and accepted by Patrick in v2.

The patch is part of the ODB abstraction effort and is based on Patrick’s earlier ODB cleanup branch. It does not introduce new symbols or touch test files, but it is a prerequisite for the core reloading logic in patch 3. The change is well-motivated and narrowly scoped, addressing a specific interaction between the ODB abstraction regression and the quarantine directory logic introduced in commit bdee7b3013. This looks like a clean, necessary fix that should proceed without further discussion.
