This is a v2 bugfix series from Patrick Steinhardt targeting the files-based object database (ODB) backend. It restores the ability to dynamically reload alternate object databases when an object lookup fails — a behavior accidentally broken in March 2026 during the ODB abstraction effort. The series now consists of six patches, up from four in v1, reflecting a design change to address a behavioral regression in `git receive-pack` when a quarantine directory is active.

The core issue remains the same: if the alternates file is modified while Git is running, the process will not see the new alternates until it restarts. This is rare but has been observed in production. The fix is still narrowly scoped to the files-based backend and does not attempt to handle recursive alternates (an edge case the commit message acknowledges was never supported).

What’s new in v2 is patch 2, which ensures alternates are always reloaded from the repository’s real object directory, even when a quarantine directory is the current primary ODB. This restores pre-regression behavior for `git receive-pack` and similar workflows, where objects that have moved to an alternate since the quarantine was created were not found. The change is minimal — a one-line adjustment to the `prepare_alternates()` call — but it resolves a correctness gap identified by Christian Couder in v1. The remaining patches (3–6) are reworked versions of the original performance optimizations, now simplified and reordered: patch 4 deduplicates alternates more cleanly, patch 5 avoids redundant `stat()` calls, and patch 6 uses `struct stat_validity` to track the alternates file’s mtime and inode, reducing unnecessary re-reads.

Performance data in the commit messages shows the fix is now nearly as fast as the pre-regression baseline: the unoptimized fix regressed lookup time for 20k missing objects from 180ms to 309ms, but the optimizations in v2 bring it down to 197ms. The series touches `odb/source-files.c`, `odb/source-files.h`, and adds a new test scenario in `t/t1006-cat-file.sh`. The commit messages are thorough, explaining both the regression and the performance trade-offs, and the test coverage is a strong positive signal.

This looks like a well-crafted, uncontroversial bugfix that addresses the feedback from v1. The design change is agreed upon, the performance work is justified, and the series is ready for review. It should be straightforward to merge once the remaining optimizations are verified.
