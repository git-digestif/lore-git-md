This thread is about a small but important security hardening change to Git’s CI infrastructure. Taylor Blau proposed pinning all GitHub Actions in the project’s main workflow file to full commit SHAs rather than version tags or branches, motivated by supply-chain security concerns—explicit commit hashes prevent CI compromise via malicious action updates. The patch itself is mechanical, touching only `.github/workflows/main.yml` to replace 32 action references (e.g., `actions/checkout@v6` → `actions/checkout@d234...`) while preserving the original version tags in comments for readability.

After Taylor revised the commit message to clearly articulate the security rationale—direct control over CI dependencies, reduced attack surface, and mitigation of supply-chain risks—Junio accepted the patch. A lingering concern about setting a precedent ("last one wins") remains noted but is no longer a blocker. The patch is now queued for inclusion in the `next` branch and carries no functional changes to Git itself.
