This thread is about a patch from Taylor Blau that pins all GitHub Actions in Git’s CI workflow to full commit SHAs instead of version tags, motivated by organizational policies requiring explicit commit hashes for security compliance. The patch itself is straightforward—it updates `.github/workflows/main.yml` to replace 32 action references (like `actions/checkout@v6`) with their full commit IDs—but Junio C Hamano has raised a policy concern: he argues that Git’s upstream workflow should not be dictated by the constraints of downstream organizations. Instead, he suggests that organizations with such policies could maintain these modifications in their own forks, noting that even pinned SHAs would still require manual updates when action versions change, leading to merge conflicts either way.

The discussion is now at a crossroads. Junio’s feedback is substantive but not a technical objection—he acknowledges the practical constraint but frames it as a downstream concern rather than an upstream requirement. The patch’s motivation may need to be strengthened to justify its inclusion in Git’s main repository, or it may need to be re-scoped as a downstream-only change. Ben Knoble previously suggested improving the commit message to explicitly state the security rationale (preventing attacks on CI/secrets by compromised action suppliers), but no other reviews have been posted yet. The thread remains under review with no clear resolution.
