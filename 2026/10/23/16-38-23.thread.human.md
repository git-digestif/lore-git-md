This thread is about a patch from Taylor Blau that pins GitHub Actions in Git’s CI workflow to full commit SHAs instead of version tags, motivated by security and compliance policies. The change itself is technically simple—updating 32 action references in `.github/workflows/main.yml`—but Junio C Hamano has raised a substantive policy objection: he argues the patch addresses a downstream organizational constraint rather than an upstream need and could set a precedent for conflicting requests.

Taylor’s latest response reframes the patch as a security measure, not just compliance. He argues that pinning to commit SHAs reduces the attack surface by making CI dependencies explicit and verifiable, mitigating risks like malicious tag updates. He also highlights the practical burden on downstream forks, where contributors must repeatedly apply and revert the same patch to meet organizational policies. The discussion remains unresolved, with the core question being whether the security rationale justifies overriding Junio’s preference for keeping such constraints downstream. No new technical objections have emerged, and the patch’s functional impact on Git remains zero—it only affects CI execution on GitHub.
