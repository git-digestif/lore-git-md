This thread is about a patch from Taylor Blau that pins GitHub Actions in Git’s CI workflow to full commit SHAs instead of version tags, motivated by security concerns—specifically, to prevent supply-chain attacks and maintain direct control over CI dependencies. The patch itself is straightforward, touching only the workflow file and making no functional changes to Git, but it has sparked a policy debate.

Junio C Hamano initially objected on principle, arguing that the change addresses a downstream compliance need rather than an upstream requirement and should remain in downstream forks. Taylor countered that the security benefits justify the maintenance overhead (updating SHAs for security fixes), and Ben Knoble suggested improving the commit message to better articulate the rationale. Junio has now softened his stance, indicating that a revised commit message that clearly explains the security trade-offs could make the patch acceptable. The "last one wins" concern—about setting a precedent for accommodating conflicting organizational policies—remains unresolved but is not a blocker at this stage.

The patch is under review, with no technical objections raised. If Taylor submits a v2 with a clearer justification, the thread is likely to conclude with the change being merged. No other participants have weighed in beyond the initial exchange.
