This is a **brief follow-up in a bugfix thread** addressing a correctness gap in the ODB alternates reloading series. Patrick Steinhardt acknowledges Christian Couder’s substantive review identifying a behavioral regression in `git receive-pack` when a temporary primary ODB (like the quarantine directory) is in use. The issue: `prepare_alternates(files, NULL)` reloads alternates from the temporary directory — which has none — rather than the repository’s real alternates, breaking object lookups for moved objects.

Patrick agrees with Christian’s proposed design change: **always reload the repository’s real alternates** (using `files->base.path`) instead of the current `files->dirs`'s alternates. This would restore pre-regression behavior for `receive-pack` and extend it to any context using a temporary primary directory. The change is minimal (a one-line adjustment to the `prepare_alternates()` call) but resolves a subtle correctness issue affecting production workflows like `git push` with object quarantine. No performance impact is expected, and the fix aligns with the series’ goal of restoring dynamic alternates reloading.

The remaining patches (performance optimizations) may need reordering or minor adjustments, but the core fix is now clearer. The discussion remains narrowly scoped to the files-based ODB backend and does not revisit broader ODB abstraction design questions.
