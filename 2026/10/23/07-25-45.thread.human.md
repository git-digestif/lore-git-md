This thread is about the ongoing SHA-1/SHA-256 interoperability effort in Git, specifically the implementation of **pack index v3**, a new index format that stores object IDs in both hash algorithms to enable bidirectional mapping between repositories. The series, authored by Christian Couder and building on brian m. carlson’s prior work, is now at its 10th patch out of 13. The first two parts of the interoperability effort (ODB infrastructure and loose-object mapping) are already merged to `master`.

The series is split into four logical groups: ODB mapping infrastructure (complete), pack index v3 writing (patches 6–8), pack index v3 reading (patches 9–12), and documentation (patch 13). Key improvements over earlier work include adaptation to Patrick Steinhardt’s `ps/odb-files-alternates` topic, strict duplicate detection, and robust error handling. Recent patches have focused on reading support and validation. Patch 9/13 added v3 reading, while **patch 10/13** (the latest) introduces **validation logic** to prevent out-of-bounds reads or undefined behavior from corrupt or malicious indices. This patch is a security hardening measure, adding bounds checks for headers, tables, and order maps, and is expected to be uncontroversial.

The series is under active review, with no substantive feedback recorded yet. Open questions include memory usage during indexing, support for multi-pack-index compatibility object IDs, and the performance impact of computing compatibility hashes for all objects. The next patches will address v3 index validation (patch 11), automatic v3 selection, and `show-index` support, which are deferred to later parts of brian’s series. The work touches core subsystems (`packfile.c`, `pack-objects.c`, `index-pack.c`, `odb/`) and introduces new symbols like `odb_map_oid()` and `nth_packed_object_pack_order_algop()`. No regressions are expected, though the added validation and hash computation may have measurable overhead.
