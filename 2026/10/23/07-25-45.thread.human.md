This thread is about the third part of Git’s SHA-1/SHA-256 interoperability effort, implementing pack index v3—a new index format that stores object IDs in both hash algorithms to enable bidirectional mapping between repositories. Christian Couder posted a 13-patch series (v2) building on brian m. carlson’s prior work; the first two parts of the interoperability effort (ODB infrastructure and loose-object mapping) are already merged to `master`.

The series is now ready for integration: Junio C Hamano has announced it will be merged to `next` in its current form, with no technical changes from v1. The only procedural feedback was to ensure future revisions reply to the cover letter for automation tools. Key components include ODB mapping infrastructure, v3 index writing and reading, validation logic, and packed-object disambiguation. The implementation is incremental, deferring features like automatic v3 selection and multi-pack-index support to later work. New tests cover v3-specific behavior (duplicate detection, bounds checking, abbreviated ID resolution), and no performance regressions are expected.

Reviewers may still scrutinize the v3 validation logic (patch 10) and memory usage during indexing, but the series is otherwise uncontroversial. The patches touch `pack-write.c`, `packfile.c`, `odb/`, and related headers, introducing functions like `odb_map_oid()` and `nth_packed_object_id_algop()`. The series adapts to Patrick Steinhardt’s `ps/odb-files-alternates` topic and is well-documented in `gitformat-pack.adoc`. So far, only surface-level feedback has been provided (Ben Knoble suggested moving the "Changes compared to v1" section earlier in the cover letter). The next step is integration testing in `next`.
