This thread is about the third installment of the SHA-1/SHA-256 interoperability effort: implementing pack index v3, a new index format that stores object IDs in both hash algorithms to enable bidirectional mapping between repositories. Christian Couder posted the initial version of a 13-patch series that builds on already-merged infrastructure (parts 1 and 2) and Patrick Steinhardt’s ODB refactoring. The series is split into four groups: ODB mapping infrastructure (now complete), v3 index writing, v3 index reading and validation, and documentation.

The patches introduce new functions like `odb_map_oid()` and `nth_packed_object_id_algop()`, extend the `pack_idx_entry` structure with compatibility OIDs, and add strict validation for the v3 format. Key improvements over earlier work include adaptation to Steinhardt’s single-ODB-source topic, duplicate detection in both hash spaces, and fixes for large-blob streaming. The series is under review, with no maintainer decisions yet; the only feedback so far is a minor stylistic suggestion from Ben Knoble about the cover letter’s organization, which does not affect the code itself. Open questions remain around memory usage, thread safety, and performance impact, but the core design is uncontested.
