This thread is about Christian Couder’s 13-patch series implementing **pack index v3**, a key piece of the SHA-1/SHA-256 interoperability effort. The series builds on prior work (parts 1 and 2, already merged to `master`) and Patrick Steinhardt’s ODB refactoring, aiming to enable bidirectional mapping between hash algorithms in Git repositories.

The latest update is patch 5/13, a cleanup that refactors `repo_oid_to_algop()` to use the new ODB mapping infrastructure. This simplifies the code by centralizing mapping logic in the ODB layer, removing manual loose-object map handling and reducing duplication. The change is low-risk—it preserves the function’s external behavior while making future extensions (like packed-object support) easier. No new tests were added, but existing tests in `t1016-compatObjectFormat.sh` cover the functionality.

The series is still in its early review phase, with no substantive feedback yet. Key technical details include new ODB mapping functions (`odb_map_oid()`, `odb_write_oid_map()`), a renamed symbol (`source_add_loose_object_map()`), and a new on-disk format for pack index v3. Open questions remain around memory usage during indexing, validation logic, and deferred features like multi-pack-index support. The series is a prerequisite for brian m. carlson’s remaining interoperability work, including automatic v3 selection and `show-index` support.
