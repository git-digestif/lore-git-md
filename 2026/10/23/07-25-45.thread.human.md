This thread is about the third part of the SHA-1/SHA-256 interoperability effort, implementing **pack index v3** support. Christian Couder has posted a well-structured 13-patch series that builds on brian m. carlson's earlier work and previous parts of the interoperability project (parts 1 and 2, already merged). The series introduces a new pack index format that stores object IDs in both hash algorithms, enabling bidirectional mapping between them.

The patches are organized into four logical groups: ODB mapping infrastructure (patches 1-5), pack index v3 writing (6-8), pack index v3 reading (9-12), and documentation (13). Key improvements over brian's original branch include adaptation to Patrick Steinhardt's ODB changes, stricter duplicate detection, validation for v3 index tables, and better error handling. The series is technically sound, with comprehensive test coverage for edge cases like duplicate objects and large files.

The implementation is incremental and focused, avoiding controversial changes while laying groundwork for future interoperability features. Reviewers are likely to focus on the v3 index validation logic, memory usage during indexing (since compatibility object IDs are kept in memory), and potential performance implications. The series touches core components like `pack-write.c`, `packfile.c`, and the ODB subsystem, introducing new functions for object ID mapping and index operations. While some features like automatic v3 selection are deferred, this appears to be a solid step forward that should be ready for merging after review.
