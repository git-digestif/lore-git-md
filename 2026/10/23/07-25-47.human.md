This is the second patch in Christian Couder’s 13-patch series implementing **pack index v3** for SHA-1/SHA-256 interoperability. It is a **pure refactoring** that renames the function `repo_add_loose_object_map` to `source_add_loose_object_map` to reflect its actual parameter type (`struct odb_source_loose` instead of `struct repository`). The change is mechanical and confined to three files: `loose.c`, `loose.h`, and `odb/source-loose.c`.

The patch is **well-motivated and uncontroversial**. The commit message clearly explains the rationale (the function does not operate on a `struct repository`), and the rename prepares the code for the ODB abstraction work in later patches. No behavior changes are introduced, and the diff is minimal. This is a typical, clean preparatory step in a larger series. Reviewers are unlikely to object, though they may check that the new name is consistent with the rest of the ODB codebase.
