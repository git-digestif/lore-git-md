This is the eighth patch in Christian Couder’s 13-part series implementing **pack index v3** for SHA-1/SHA-256 interoperability. It fixes a critical bug in the object-file subsystem: when streaming large blobs directly into a pack (bypassing the loose-object path), the code previously failed to compute and store the compatibility-algorithm object ID, leaving the `compat_oid` field in the pack index as all zeros. The patch ensures that both the main and compatibility hashes are computed and stored during streaming writes.

The change is small but essential: it extends `stream_to_pack()` to accept an optional second hash context (`compat_ctx`), updates the streaming loop to feed data to both contexts, and populates the `compat_oid` field in the `pack_idx_entry` structure when a compatibility algorithm is configured. The test verifies that a 5 KB file added in a compatibility repository is correctly stored, with both object IDs matching expectations.

This is a **bugfix** that plugs a repository-corruption risk in the new v3 index format. The patch is narrowly scoped, well-tested, and uncontroversial; it should be a straightforward merge once the earlier patches in the series land. No performance impact is expected, as the extra hash computation is negligible compared to the I/O cost of streaming large blobs.
