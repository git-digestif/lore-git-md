This is the first patch in Tamir Duberstein’s three-part performance series that enables `git ls-files` to reuse the untracked cache populated by `git status`. The patch fixes a long-standing inconsistency in how ignore-file object IDs are computed, ensuring the untracked cache remains valid when switching between direct file reads and index lookups.

The issue is straightforward: `add_patterns()` appends a newline to the buffer *before* computing the object ID, but this newline is not present in the actual file. When Git later reads the same file from the index (which stores the raw file content), the computed object ID differs, causing the untracked cache to be invalidated unnecessarily. The fix moves the newline append *after* the hash computation, aligning both code paths. The change is minimal—just a few lines in `dir.c`—and updates the test expectations in `t/t7063-status-untracked-cache.sh` to match the new object IDs.

This is a well-motivated bugfix with clear correctness implications for the untracked cache. No behavioral changes are visible to users, but the patch is a prerequisite for the later performance improvements in the series.
