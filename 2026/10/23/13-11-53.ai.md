This is the **cover letter for v5 of a six-patch performance feature** introducing an **incremental connectivity check** for Git fetches and pushes. The series is **ready for integration**, having addressed all prior feedback and rebased onto the latest `master`. The goal is to reduce the cost of verifying object connectivity during transfers, particularly for small pushes to large repositories, by shifting the cost from repository size to the size of incoming changes.

The **auto mode** (patch 6/6) implements a **three-mode config design** (`full`/`incremental`/`auto[=<n>]`) with a **configurable 1,000-commit cutoff**, dynamically switching to incremental mode for small incoming histories and falling back to the full check otherwise. This heuristic is based on benchmark data showing it works well across repository sizes, including large monorepos. The cutoff is conservative but effective, and the fallback logic preserves all existing behavior (deepening fetches, promisor objects, etc.).

Key technical details include new config keys (`transfer.connectivityCheck`, `transfer.connectivityCheckIncrementalMaxCommits`), a new internal `rev-list` flag (`--connectivity-check=`), and a new source file (`tree-verify.c`) implementing the incremental verifier. The verifier uses an inductive trust algorithm: parent trees are trusted, and new trees are verified only where they differ from parents. The latest revision (v5) **eliminates reliance on `repo->fetch_if_missing`** by using `odb_read_object_info_extended()` with `OBJECT_INFO_SKIP_FETCH_OBJECT`, addressing Junio’s forward-compatibility concern without broader refactoring.

Performance benchmarks show dramatic speedups for small pushes to large repositories (up to 190x faster, with memory usage reduced from 3.4 GB to 14 MB for a single commit). The incremental mode introduces a modest regression (1.5x slower) for very long incoming histories (10,000+ commits), but the "auto" mode mitigates this by falling back to the full check. Test coverage is thorough, with correctness tests in `t/t5413-connectivity-check.sh` and performance tests in `t/perf/p5413-connectivity-check.sh`, covering semantic equivalence, corruption detection, partial clones, and integration with fetch/push/clone.

The series is **well-motivated and well-executed**, with clear benchmarks, a conservative design (opt-in, fallback to full check for edge cases), and thorough documentation. The implementation is self-contained, touching only the necessary subsystems, and the commit messages are detailed and informative. The **stack overflow risk** (raised by Patrick Steinhardt) is acknowledged but not addressed in this series, as the recursive tree verification is bounded by `core.maxTreeDepth` and similar to existing code. The series is **effectively cleared for integration** pending final sign-off from Junio.
