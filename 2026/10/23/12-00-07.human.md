This is a **substantive review follow-up** in the ongoing bugfix series for shallow fetches with tag backfilling. Patrick Steinhardt raises a **memory management concern** about the v4 patch’s handling of `negotiation_include_tips`: if the field is already set when `backfill_tags()` runs, the patch appends new OIDs without freeing the existing array, potentially leaking the original contents. More subtly, the patch’s design exposes the internal `fetched_tips` array to the transport layer, meaning any later modifications (e.g., by other fetch steps) could corrupt the negotiation state.

The question is **not about correctness**—the patch still fixes the regression—but about **cleanliness and safety**. Patrick’s suggestion (using a local `struct oid_array`) would isolate the negotiation tips from the caller’s state, avoiding both leaks and unintended side effects. This is a **minor but important refinement** that doesn’t change the core fix but tightens its implementation. Karthik’s v5 preview already plans to adopt this approach, along with other cleanups from Patrick’s review.

The thread remains **on track for `next`**; this is a routine clarification rather than a blocker. No new technical risks have emerged, and the scalability trade-off (documented in v5) is still the only open discussion point. Junio’s position is still unvoiced, but the patch is otherwise ready.
