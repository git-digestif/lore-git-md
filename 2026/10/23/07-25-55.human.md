This is the **tenth patch in a 13-patch series** implementing pack index v3 support for SHA-1/SHA-256 interoperability. The patch adds **validation logic** to ensure that v3 pack indices are well-formed and safe to read, preventing out-of-bounds access or corruption from malformed or malicious files.

The changes focus on three files: `hash-lookup.c`, `pack-revindex.c`, and `packfile.c`. The core work is in `packfile.c`, where `load_idx()` is extended to validate the v3 header, format entries, and table offsets before trusting them. Key checks include:
- Rejecting duplicate format IDs or invalid short-name lengths.
- Ensuring all table offsets lie within the index file bounds.
- Validating that the trailer offset matches the expected size.
- Checking that order map entries point to valid object positions.

The patch also updates `bsearch_hash_v3()` in `hash-lookup.c` to reject order map entries that exceed the number of objects, and `create_pack_revindex()` in `pack-revindex.c` to verify 8-byte offset pointers before dereferencing them. A new test in `t5313-pack-bounds-checks.sh` verifies that an invalid order map entry triggers a "corrupt index" error.

This is a **security and robustness improvement** with no behavior change for valid indices. The validation is thorough but lightweight, adding minimal overhead to the loading process. The patch is **well-motivated and uncontroversial**, addressing a clear gap in the v3 implementation. Reviewers may focus on edge cases (e.g., 32-bit systems, unaligned access) or the choice of error messages, but the logic appears sound. The series as a whole remains on track for merging, with this patch filling a critical safety requirement.
