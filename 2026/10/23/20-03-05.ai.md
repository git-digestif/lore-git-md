This is the second patch in Tamir Duberstein’s three-patch series that enables the untracked cache to be shared between `git status -unormal` and `git status -uall`. The patch refactors the directory traversal logic in `dir.c` to record incomplete scans with the `check_only` bit and expand them on demand, eliminating redundant filesystem scans when switching between output modes.

The core change introduces a new `UNTRACKED_CACHE_LAZY` flag (0x80000006) that allows the cache to be reused for both `--untracked-files=normal` and `--untracked-files=all`. Older Git versions will rebuild the cache before using it, preserving backward compatibility. The patch also updates `read_directory_recursive()` to handle cached directories, ensuring that partial listings are completed when needed and that nested repository changes are detected. Tests in `t/t7063-status-untracked-cache.sh` are updated to reflect the new behavior, including scenarios for partial listing rescans, nested repository cache integrity, and filtered status operations.

The implementation is careful to maintain the existing pruning behavior for pathspecs with fixed prefixes, attributes, or excludes, while caching complete listings for wildcard pathspecs and applying the filter afterward. The patch is well-motivated, addressing a long-standing inefficiency in the untracked cache design, and the changes are thoroughly tested. No objections or requests for changes have been raised yet, and the patch appears ready for substantive review.
