This is the third patch in Christian Couder’s 13-patch series implementing **pack index v3** for SHA-1/SHA-256 interoperability. The patch adds a `flags` parameter to `source_add_loose_object_map()` and introduces the `OBJ_MAP_WRITE` flag (bit 6) to control whether mapped object IDs are written to disk. The change is preparatory: future patches will use this flag to temporarily store mappings in memory during pack indexing, avoiding premature disk writes. The patch touches `loose.c`, `loose.h`, and `odb/source-loose.c`, and is a straightforward plumbing adjustment with no functional changes in this commit. Reviewers should note the bit choice (1 << 6) to avoid conflicts with future object-type flags.
