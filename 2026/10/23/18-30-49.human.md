This is a maintainer response to a two-patch bugfix series that fixes inconsistent branch switch behavior when tracking configuration fails to write.

Junio has queued the series for integration, signaling that it is ready to proceed. The patches address a long-standing edge case where `git switch -c` or `git checkout -b` would leave the repository in an inconsistent state—updating the worktree, index, and new branch ref but failing to update HEAD—if the tracking configuration could not be written (e.g., due to a stale `.git/config.lock`). The fix makes the operation non-atomic but consistent: if the tracking config write fails, the branch switch still completes, and Git exits with status 0, aligning with the behavior of `git push -u`, `git clone`, and `git fetch`. The `git branch` command retains its stricter error handling.

The series was previously part of a larger effort but was split out at Junio’s request after the direction was agreed in the bug report thread. Patch 1 refactors `setup_tracking()` to return an error instead of calling `exit()`, and patch 2 updates `builtin/checkout.c` to ignore the tracking config failure and finish the switch, while also updating the test suite to verify the new behavior. The patches are well-motivated, surgically targeted, and uncontroversial, with thorough test coverage and clear commit messages. No further discussion or objections are evident in the thread.
