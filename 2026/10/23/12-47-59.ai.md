This is a bugfix series targeting the object database (ODB) subsystem, specifically the files-based backend. The v2 iteration of Patrick Steinhardt’s six-patch series restores dynamic reloading of alternate object databases when an object lookup fails—a behavior accidentally broken in March 2026 during the ODB abstraction effort. The key change from v1 is a design fix that ensures alternates are always reloaded from the repository’s real object directory, even when a quarantine directory is active, addressing a behavioral regression in `git receive-pack` identified by Christian Couder.

The series is now six patches instead of four. Patch 2 is new and enforces the design change: it modifies `prepare_alternates()` to reload alternates from `files->base.path` (the repository’s real object directory) rather than `files->dirs->abspath` (the current primary directory, which may be a quarantine). This restores pre-regression behavior and resolves the `receive-pack` issue. The remaining patches are reordered and adjusted: patch 3 (formerly patch 2) implements the core reloading logic, patch 4 simplifies directory deduplication, patch 5 avoids redundant `stat()` calls for known alternates, and patch 6 uses `struct stat_validity` to skip re-reading the alternates file when it hasn’t changed. The performance optimizations now bring lookup time for 20k missing objects down to 199.5ms, nearly matching the pre-regression baseline of 185.3ms.

Files touched are `odb/source-files.c`, `odb/source-files.h`, and `t/t1006-cat-file.sh` (which gains a new test scenario). The series is based on `master` as of 2026-10-19 with Patrick’s ODB cleanup branch merged in. The commit messages are clear, the performance data is concrete, and the design change is now agreed upon. This looks like a well-scoped, uncontroversial bugfix that should be ready for final review and merging.
