This is the second patch in a two-patch series (v2) that fixes edge cases in Git’s hook configuration system. It addresses a minor but annoying inconsistency: the boolean config keys `hook.<name>.enabled` and `hook.<name>.parallel` now accept empty values (treated as `true`), matching Git’s standard boolean config behavior. Previously, Git would reject these keys if they lacked a value, which was out of step with how other boolean config settings work.

The change is small and mechanical: the `hook_config_lookup_all()` function in `hook.c` now skips the "missing value" error check for `.enabled` and `.parallel` keys, letting `git_parse_maybe_bool()` handle them as it does elsewhere. The test suite (`t/t1800-hook.sh`) adds two new test cases (lines 516–533 and 1080–1097) to verify that empty values for both keys are correctly interpreted as `true`. The implementation is uncontroversial and aligns with Git’s existing conventions.

This patch complements the first patch in the series, which clarified that `hook.<event>.enabled` disables *both* config-defined hooks and traditional hooks in the hooks directory.
