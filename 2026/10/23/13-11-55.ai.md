This is the **performance test patch (2/6)** in the six-patch series introducing an incremental connectivity check for Git fetches and pushes. The patch adds synthetic benchmarks to `t/perf/p5413-connectivity-check.sh` that measure the overhead of the `git rev-list` connectivity check across three dimensions: repository size, incoming commit count, and files changed per commit.

The benchmarks use a Perl script (`generate-repo-p5413-connectivity-check.perl`) to generate controlled test repositories with a flat directory structure (many directories, each with 100 files). Each test case varies one parameter while holding the others constant, isolating the connectivity-check overhead from pack transfer noise. The script creates an initial commit with a fixed number of files, then chains additional commits that modify a configurable number of files in round-robin directories. The generated repositories are repacked to ensure consistent conditions.

The test script defines a helper function `test_perf_conn` that sets up a fresh repository for each benchmark, generates the fast-import stream, and measures the runtime of `git rev-list --objects --stdin --not --all --quiet --exclude-promisor-objects` (the exact command the incremental mode will optimize). The benchmarks cover a wide range: from 5,000 to 800,000 files, 1 to 10,000 commits, and 1 to 2,000 files changed per commit. The "hot dirs" parameter simulates workloads where changes are concentrated in a subset of directories.

This patch is **well-designed and self-contained**, with clear documentation and a conservative approach to test isolation. The benchmarks are synthetic but realistic enough to expose the scalability limits of the current full connectivity check, providing a baseline for evaluating the incremental mode's performance improvements. The commit message is concise but sufficient, and the code follows Git's test conventions. No prior feedback on this patch has been noted, and it is ready for integration. The benchmarks will be directly referenced in the series' cover letter and later patches to justify the performance trade-offs of the incremental mode.
