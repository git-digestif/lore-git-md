This is a bugfix patch for `git rev-list` that fixes `--grep` parsing when followed by another option. Junio C Hamano, the maintainer, has replied to the v2 patch with a review focused on the test coverage.

The patch itself remains a minimal, well-scoped fix: two lines in `builtin/rev-list.c` that ensure `--grep` correctly consumes the next argument as the pattern, even if it begins with `--`. The implementation is unchanged from v2 and looks solid.

Junio’s feedback is substantive but narrow: he points out that the new tests do not actually verify that the `--grep` pattern was applied, only that the command did not fail. The tests pass even if `--grep` ignored the pattern entirely, as long as the subsequent option (e.g., `--missing-only`) was not misinterpreted as a flag. He suggests the tests should include a positive check that the pattern was used — for example, by grepping for a commit that contains the pattern string.

The author, Azuama Odinaka Maximus, is expected to send a v3 addressing this test coverage gap, along with the two housekeeping items already noted (adding a "Changes in v2" section to the commit message and restoring the `Signed-off-by` trailer). Once those are addressed, the patch should be ready for merging. The fix itself is uncontroversial and addresses a real edge case in argument parsing.
