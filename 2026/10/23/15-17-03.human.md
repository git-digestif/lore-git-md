This is a **documentation** patch series, now at **v3**, that replaces the outdated `gittutorial` man page with a modern, beginner-focused two-part guide. The author, Julia Evans, has tested the new tutorial with 112 users, most of whom completed it successfully, and incorporated feedback from both testers and reviewers. The series is now ready for merging, with only minor mechanical adjustments (blank lines before Setext-style headings) remaining.

The new tutorial is designed to be practical and accessible, covering local repository creation, commits, and pushing to a remote host (GitHub/GitLab). It avoids overwhelming beginners with advanced topics like branching or collaboration, though the author plans to address these in future iterations based on post-merge user feedback. The tutorial is compatible with Git versions 2.23.0 and later, ensuring broad applicability.

Key improvements in v3 include clarifications about platform-specific quirks (e.g., Git Bash on Windows), warnings about the default `vi` editor, and more explicit instructions for SSH key generation and copying. The author has also added a section emphasizing the importance of `git status` and made small phrasing fixes based on tester feedback. Notably, the tutorial retains `git init` (instead of `git clone`) to avoid confusing beginners about Git’s decentralized model, and it uses `git commit -m` for simplicity, despite acknowledging that longer commit messages are preferable.

The series has received **surface-level reviews** from D. Ben Knoble and Junio C Hamano, focusing on wording, formatting, and minor usability tweaks. No substantive objections remain, and the author has addressed all feedback except for two unresolved points: whether to specify `ssh-keygen -t ed25519` (Junio’s suggestion) for usability or leave the key type unspecified (Julia’s preference) for future-proofing, and whether to hardcode `cat ~/.ssh/id_ed25519.pub` (Junio) or use a more generic approach (Julia) to avoid filename assumptions. Neither issue is a blocker for merging.

The author’s urgency to merge stems from funding constraints, but the patch is unlikely to be controversial given its focus on documentation and user-tested design. The series touches only `Documentation/gittutorial.adoc`, replacing the old content entirely. If merged, it will provide a much-needed modern entry point for new Git users, with plans for iterative improvements based on real-world feedback.
