This is the fifth patch in Patrick Steinhardt’s **v3 object storage extension series**, which introduces pluggable object database backends for Git. This patch specifically adds **user-facing configuration options** for the object storage format, mirroring the existing support for reference storage formats. It enables users to specify the object storage backend via command-line flags (`--object-storage-format=`), environment variables (`GIT_OBJECT_STORAGE_FORMAT` and `GIT_DEFAULT_OBJECT_STORAGE_FORMAT`), and configuration (`init.defaultObjectStorageFormat`).

The patch updates `git init` and related commands (`git clone`, `git submodule`) to accept the new `--object-storage-format` option, which supports both simple formats (e.g., `files`) and payloads (e.g., `files://objs` to relocate the objects directory). It also extends the repository initialization logic in `setup.c` to handle the new format, including precedence rules (command-line > environment > config > default) and validation. The implementation is consistent with the ref storage backend’s design, including the split `(type, payload)` representation introduced in v3.

Tests cover initialization, environment variable overrides, error cases (invalid formats, reinitialization with mismatched storage), and integration with `GIT_OBJECT_DIRECTORY`. The patch is **well-motivated and technically sound**, following established patterns for Git’s extension mechanisms. It looks ready for review, with no obvious gaps or controversies. The only potential discussion point is whether the repository format version bump (to `1`) for the `files` backend with a payload is overly conservative, but this is a deliberate design choice to ensure compatibility with older Git versions.
