This is the first patch in a three-part performance series that enables `git ls-files` to reuse the untracked cache populated by `git status`. The patch fixes a long-standing inconsistency in how ignore-file object IDs are computed, which could invalidate the untracked cache even when the ignore files themselves hadn’t changed.

The bug is straightforward: `add_patterns()` appends a newline to the buffer *before* computing the object ID, but that newline isn’t present in the actual file. When Git later reads the same file via the index (because the entry is up-to-date and needs no conversion), it uses the index’s object ID, which doesn’t include the extra newline. The mismatch causes the untracked cache to treat the file as changed and invalidate the cache below it. The fix moves the newline append *after* the hash is computed, ensuring both code paths agree on the object ID. The patch updates the test expectations in `t/t7063-status-untracked-cache.sh` to match the corrected hash values.

This is a small but necessary correctness fix that paves the way for the later patches. The change is mechanical, well-explained, and touches only the ignore-file parsing logic and its tests. No behavior changes are visible to users—only the internal consistency of the untracked cache improves. The patch looks solid and uncontroversial.
