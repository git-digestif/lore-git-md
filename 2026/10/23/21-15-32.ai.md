This is the first patch in a two-patch refactoring series advancing the `the_repository` removal effort. It introduces `repo_for_each_remote()`, a new function that takes an explicit `struct repository *` parameter, and converts the existing `for_each_remote()` into a backward-compatible wrapper that passes `the_repository`. The change is mechanical and follows the established pattern of the broader effort.

The patch touches `remote.c` and `remote.h`, adding the new function and updating the internal implementation to use the passed repository instead of the global `the_repository`. The wrapper ensures no disruption to existing callers, and the commit message clearly explains the motivation: enabling functions like `unique_tracking_name()` (updated in the next patch) to operate on arbitrary repository instances rather than being hardcoded to `the_repository`.

This resolves the design tension Junio raised in the v2 review, where the earlier version of the series documented a limitation rather than addressing it. The new function is a clean abstraction that fully delivers on the modularity promise, and the patch is well-structured with no obvious oversights. No new tests are needed, as the change is purely internal and existing tests should continue to pass.

The patch is part of a larger, ongoing effort led by René Scharfe to eliminate `the_repository` across the codebase. The introduction of `repo_for_each_remote()` may influence future patches in this series, particularly those touching the remote subsystem or other functions with similar dependencies. The series is under review and appears to be in good shape for merging once discussion converges.
