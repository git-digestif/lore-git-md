This is the third and final patch in Tamir Duberstein’s three-patch series that teaches `git ls-files` to reuse and update the untracked cache populated by `git status`. The patch implements the core functionality: `git ls-files --others` now reads from the untracked cache and, when optional locking is enabled, writes pending updates back to the index so later commands can benefit.

The patch touches `builtin/ls-files.c` and `dir.c`, with supporting documentation in `Documentation/git-ls-files.adoc` and new tests in `t/perf/p3010-ls-files.sh`, `t/t3001-ls-files-others-exclude.sh`, `t/t7063-status-untracked-cache.sh`, and `t/t7519-status-fsmonitor.sh`. The key change is in `cmd_ls_files()`: it now parses options before reading the index, takes the optional lock if the call is eligible, and releases the lock after the directory walk but before printing paths, so a slow reader cannot block other index writers. The patch also records the object IDs of standard exclude files before assigning `dir->untracked`, ensuring exclude options are processed in the same order as before reading the index.

Behavioral constraints are carefully enforced: the index is not written when a pathspec prefix or `--with-tree` is used, with `--debug` (which prints stat data that an index write can change), with `--no-optional-locks`, or when the lock is busy. The new tests cover cache reuse after `git status -unormal`, optional lock handling, `--debug` behavior, and fsmonitor token preservation with `index.skipHash`. The performance tests in `t/perf/p3010-ls-files.sh` quantify the speedup: on a synthetic tree with 100,000 files, a wildcard query (`**/pyproject.toml`) now runs in 33 ms (down from 241 ms upstream), and combined `git status` + `git ls-files` time drops from 293 ms to 93 ms.

The patch is well-motivated, self-contained, and maintains backward compatibility. It addresses the feedback from earlier versions by refining lock handling and `--debug` behavior, and the new tests provide thorough coverage of edge cases. No objections or requests for changes have been raised yet, and the patch appears ready for substantive review.
