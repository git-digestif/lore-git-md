This is the v2 revision of a two-patch bugfix series targeting Git’s hook configuration system, addressing the same two issues as v1 but with updated commit messages, documentation, and expanded test coverage. The series now explicitly frames the first patch as a **behavior change** (not a bugfix) and clarifies that `hook.<event>.enabled` will disable *both* config-defined hooks and the traditional hook in the hooks directory. The documentation in `hook.adoc` has been updated to match this wording, resolving the ambiguity noted in the v1 discussion.

The key technical changes since v1 are minimal: the implementation remains the same (adjusting how the `event_disabled` flag is checked in `builtin/hook.c` and `hook.c`), but the commit message and documentation now reflect Adrian Ratiu’s proposed middle ground—accepting the patch while explicitly documenting the broader scope of `hook.<event>.enabled`. The test suite (`t/t1800-hook.sh`) has grown from 51 to 75 lines, adding coverage for the hookdir hook’s interaction with the `enabled` flag and verifying that other events remain unaffected.

The backward-compatibility trade-off is now front-and-center: the series acknowledges that users who relied on the old behavior (where `hook.<event>.enabled=false` left the hookdir hook untouched) will see a change. Junio’s earlier hesitation about classifying this as a breaking change is addressed by the updated framing, though the thread remains open for broader community input. No technical objections or alternatives have been raised, and the author has incorporated all requested documentation updates.

For follow-up discussion, the critical details are:
- **Files**: `builtin/hook.c`, `hook.c`, `hook.h`, `Documentation/config/hook.adoc`, `t/t1800-hook.sh`
- **Config keys**: `hook.<event>.enabled` (now covers hookdir hooks), `hook.<event>.parallel` (empty values treated as `true`)
- **Test additions**: Lines 516–533 and 1080–1097 in `t/t1800-hook.sh` verify empty-value handling and hookdir interaction
- **Related symbols**: `event_disabled` flag in `struct hook` (now set for hookdir hooks)
- **Documentation change**: `hook.adoc` now explicitly states that `hook.<event>.enabled` applies to both config and hookdir hooks.

The series is now positioned as a deliberate design choice rather than a bugfix, with the documentation updated to match. The implementation is uncontroversial, but the backward-compatibility implications may still draw scrutiny.
