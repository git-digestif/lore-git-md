This is **patch 5/6 of the incremental connectivity check series**, implementing the core algorithm in the new `tree-verify.c` file. The patch adds the incremental verifier that processes incoming commits in topological order, comparing each new tree against its trusted parent trees to avoid walking unchanged subtrees. It introduces the inductive trust model described in the technical documentation, tracking tree OIDs in three states (untrusted, trusted, expanded) and using a merge-walk to collect same-path parent subtrees as recursive comparison bases.

The implementation is self-contained in `tree-verify.c` (433 lines) and `tree-verify.h` (15 lines), with minimal changes to existing files: `builtin/rev-list.c` wires up the new mode, `connected.c` passes the mode through, and the documentation is updated to describe the new behavior. The verifier preserves partial-clone semantics by skipping promisor objects and avoids lazy fetches by using `odb_read_object_info_extended()` with `OBJECT_INFO_SKIP_FETCH_OBJECT`. Error handling is centralized at the subprocess boundary, with detailed error messages for missing or corrupt objects.

The test coverage in `t/t5413-connectivity-check.sh` (774 lines) is thorough, verifying semantic equivalence with the full check, corruption detection, promisor object handling, and integration with fetch/push/clone. The tests use a synthetic repository with nested directories to isolate the incremental check's behavior, and Trace2 events measure trees loaded and blobs checked. The patch also updates `t/t6700-tree-depth.sh` to enforce the same recursion limit as the full check, ensuring consistent behavior.

Key technical details include the use of `kh_oid_tree_t` to track tree states, `oidset` for trusted blobs, and a work queue for untrusted entries. The verifier processes commits in topological order, ensuring parent trees are trusted before verifying descendants, and skips gitlinks and promisor objects. The incremental mode is selected via the internal `--connectivity-check=incremental` flag in `rev-list`, and the config plumbing for `transfer.connectivityCheck=incremental` was added in patch 4/6.

The patch addresses all prior feedback, including the forward-compatibility concern about lazy fetching (resolved in v5) and the configurable 1,000-commit cutoff for the auto mode (added in patch 6/6). The stack overflow risk for deep trees remains acknowledged but unaddressed, as the recursion is bounded by `core.maxTreeDepth` and similar to existing code. The series is ready for integration, with no new blockers introduced in this patch.
