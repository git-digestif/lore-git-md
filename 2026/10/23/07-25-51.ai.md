This is **patch 6/13 in the SHA-1/SHA-256 interoperability series**, implementing **pack index v3 writing support**. It extends the pack index entry structure to include compatibility object IDs (for the non-native hash algorithm) and the entry’s index number, then teaches `write_idx_file()` to write the new v3 format.

The patch is **focused and well-scoped**: it adds the v3 header, writes both main and compatibility object IDs (sorted by each algorithm’s hash), pads the short-name tables to 4-byte alignment for unaligned-access architectures, and enforces strict duplicate detection in both hash spaces. The code is careful to preserve the caller’s expectation that the `objects` array remains in pack order after writing, while internally creating temporary sorted copies for the v3 tables.

Key technical details:
- **New fields in `pack_idx_entry`**: `compat_oid` (for the non-native hash) and `idx` (the entry’s position in the pack).
- **Header format**: v3 adds a variable-length header with format descriptors for each hash algorithm, specifying the offset and length of the short-name table.
- **Padding**: short-name tables are padded to 4-byte boundaries to avoid unaligned access.
- **Duplicate detection**: `--strict` now checks for duplicates in both the main and compatibility object ID spaces.
- **Memory management**: temporary sorted arrays are freed before returning, and the original `objects` array is re-sorted by object ID if needed (e.g., for bitmap code).

The patch **does not yet enable v3 by default** (that comes later in the series) and **does not populate the `compat_oid` field** (also deferred). It is a clean, incremental step that builds on the ODB mapping infrastructure introduced in earlier patches.

**Files touched**: `pack-write.c` (core implementation), `pack.h` (struct extension).
**Key functions modified**: `write_idx_file()` (now handles v3), with new helpers `write_v3_header()`, `find_short_name_len()`, and comparison functions `oid_compare()`/`oid_compare_compat()`.
**Test coverage**: The series adds tests in `t1016-compatObjectFormat.sh` and `t5308-pack-detect-duplicates.sh`, but this patch itself is infrastructure and does not introduce new testable behavior.

**Assessment**: This is a **high-quality, low-risk change** that lays the groundwork for v3 index reading (patches 9–12). The implementation is careful about alignment, memory usage, and caller expectations, and the commit message clearly explains the design choices (e.g., padding, duplicate detection). Reviewers may want to check the padding logic and the decision to keep the `objects` array in pack order, but the patch looks ready for substantive review.
