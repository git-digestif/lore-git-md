This is the second patch in Patrick Steinhardt’s seven-part series introducing a new `extensions.objectStorage` configuration mechanism. It lays the groundwork for pluggable object database (ODB) backends by adding a repository extension that lets users specify which backend should serve as the primary object store.

The patch defines the `extensions.objectStorage` key, whose value is a URI in the form `<schema>[://<payload>]`. Currently the only supported schema is `files`, which corresponds to Git’s traditional loose-objects-and-packfiles backend. The optional payload lets users relocate the `.git/objects` directory; relative paths are resolved against `$GIT_COMMON_DIR`, and the payload is ignored if `GIT_OBJECT_DIRECTORY` is already set. Documentation is added for the new extension and the `files` schema, and the repository data structures (`struct repository`, `struct repository_format`) are extended to store the chosen format and payload.

Code changes touch the ODB layer (`odb.c`, `odb.h`, `odb/source*.c`) to parse the URI, instantiate the correct backend, and pass the payload through to the files backend. The setup code (`setup.c`) wires up the extension parser, and new tests in `t0001-init.sh` verify that the extension is rejected in repository format version 0, accepted in version 1, and correctly diagnoses unknown schemas.

The patch is cleanly structured, well-documented, and includes thorough test coverage. It is clearly part of the larger ODB abstraction effort and does not yet expose any user-visible behavior beyond the configuration knob itself.
