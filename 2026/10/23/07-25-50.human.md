This is the fifth patch in Christian Couder’s 13-patch series implementing **pack index v3** for SHA-1/SHA-256 interoperability. It refactors the `repo_oid_to_algop()` function in `object-file-convert.c` to use the new ODB mapping infrastructure (`odb_map_oid()`) introduced earlier in the series.

The change is a **cleanup and simplification**: the function now delegates the object ID mapping logic to the ODB layer, removing 12 lines of manual map-reloading code and replacing it with a single call to `odb_map_oid()`. The commit message explains that `repo_oid_to_algop()` is retained because it handles cleanup tasks that the ODB backend shouldn’t need to manage.

This patch is **low-risk and uncontroversial**. It’s a straightforward refactoring that aligns with the series’ goal of centralizing ODB mapping logic. The only functional difference is that the ODB layer may now handle map reloading internally (via the `ODB_MAP_OID_RELOAD` flag), but the behavior remains equivalent. No new tests are added here, as the existing test suite (particularly `t1016-compatObjectFormat.sh`) already covers the mapping functionality.

If reviewers have concerns, they’re likely to focus on whether the ODB layer’s reloading logic is as robust as the old code, but the patch itself is small and well-motivated. This is a **solid incremental step** in the interoperability effort.
