This is a **cleanup patch** in the v3 object storage extension series, removing a dead function that was introduced but never used. The patch targets the loose object subsystem (`loose.c` and `loose.h`).

The function `repo_write_loose_object_map()` was added in 2023 to write a mapping between SHA-1 and SHA-256 for loose objects, but it was never called. Instead, the codebase uses `repo_add_loose_object_map()` to update the mapping incrementally when new loose objects are created. The dead function also hardcodes the location of the loose-object index file, which conflicts with how other parts of the code derive the path from the loose source’s location. Removing it eliminates 46 lines of unused code and avoids potential inconsistencies in file path handling.

The patch is **mechanically straightforward**: it deletes the function and its declaration, with no behavior changes. The commit message clearly explains why the function is unnecessary and highlights the inconsistency it would introduce if ever used. This cleanup is a prerequisite for the broader object storage extension work, as it removes a vestigial piece of code that could complicate future backend refactoring.

The patch is part of the larger effort to make Git’s object database pluggable, but it stands alone as a minor cleanup with no dependencies on the rest of the series.
