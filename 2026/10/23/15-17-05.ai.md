This is the **second patch in the v3 series** replacing the outdated `gittutorial` man page with a beginner-focused two-part guide. The patch **adds the new tutorial** after the first patch removed the old one, completing the replacement.

The new `gittutorial` is a **user-tested, practical introduction** to Git, designed to be completed in under an hour. It covers local repository creation (`git init`, `git add`, `git commit`, `git status`, `git diff`) and pushing to a remote host (`git remote add`, `git push`). The tutorial avoids explaining branches or collaboration, focusing instead on core concepts like commits, snapshots, and the `.git` directory. Key design choices include:
- Starting with an empty repository (`git init`) rather than cloning, to avoid requiring an existing project.
- Using SSH for authentication, with generic instructions for key generation (`ssh-keygen`) and copying (`cat ~/.ssh/*.pub`).
- Warning users about `vi` being the default editor and providing escape instructions.
- Emphasizing `git status` as a critical tool for understanding repository state.
- Including a troubleshooting section for common issues (e.g., SSH host verification prompts).

The tutorial is **compatible with Git 2.23.0 or later** (required for `git switch`) and has been tested with 112 users, with feedback incorporated into v3. The patch touches only `Documentation/gittutorial.adoc`, replacing the old content entirely. No new symbols or behavior changes are introduced.

The unresolved questions from earlier revisions—such as whether to start with `git init` or `git clone`, how to handle SSH key generation generically, and the use of `git commit -m`—remain open but are not blockers. The author, Julia Evans, frames the tutorial as "good enough" for merging, with plans to iterate post-merge based on user feedback. The patch is **ready for Junio’s final review** and is uncontroversial, given its documentation focus and validation through user testing.
