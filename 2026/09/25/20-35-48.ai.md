This is the first patch in Jeff King (Peff)'s two-patch series fixing a regression in `git shortlog` and related revision commands. The patch addresses a latent bug in the revision option parsing logic that predates the recent `(null)` regression: when a known option is provided with invalid arguments (e.g., `--default` without a value), the code incorrectly reports it as an "unknown option" instead of letting the earlier error message ("bad --default argument") stand.

The fix is minimal and surgical. In `parse_revision_opt()`, Peff changes the condition `if (n <= 0)` to `if (n < 0)` to distinguish between malformed options (negative return from `handle_revision_opt()`) and truly unknown options (zero return). For malformed options, the code now skips the "unknown option" error and just shows the usage message, letting the earlier error message take precedence. The patch also adds a test case to `t/t4201-shortlog.sh` to verify that invalid options like `--default` are not misreported as unknown.

The change is low-risk and well-motivated. The commit message clearly explains the distinction between malformed and unknown options, and the test coverage ensures the fix works as intended. The patch touches only `revision.c` and the test suite, with no new symbols or behavior changes beyond the error message correction.
