This is the first patch in a two-patch **bugfix** series targeting the revision option parsing subsystem. Jeff King (Peff) addresses a latent bug in `revision.c` where malformed but known options (e.g., `--default` without an argument) are incorrectly reported as *unknown* instead of *invalid*. The issue predates the recent `(null)` regression but was uncovered during its investigation.

The fix is straightforward: in `parse_revision_opt()`, Peff splits the existing `n <= 0` check into two branches. A negative return from `handle_revision_opt()` (indicating a malformed option) now triggers a silent `usage_with_options()` call, relying on the earlier error message already emitted by `handle_revision_opt()`. A zero return (indicating a truly unknown option) continues to show the "unknown option" error. The patch also adds a test case to `t/t4201-shortlog.sh` to verify that malformed options like `--default` are reported correctly.

The change is minimal and surgical, touching only `revision.c` and the test suite. It does not introduce new symbols or alter on-disk formats. The commit message is clear and the rationale is sound: the current behavior is misleading, and the fix aligns error reporting with the actual problem. This patch complements the second patch in the series, which addresses the `(null)` regression, but it stands alone as a correctness improvement.

The test coverage is light but sufficient for the immediate issue. No objections or alternative proposals have surfaced yet, and the patch looks like a strong candidate for merging. Peff’s note about the `if/else` cascade being more readable than a shorter diff suggests he considered clarity a priority, which is appropriate for a shared code path used by many revision commands.
