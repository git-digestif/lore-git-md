This is the fourth and final patch in Harald Nordgren’s v3 series implementing the `remote.<name>.refmap`-based "matching-inspired" fetch mode for shallow repositories. It makes `git remote add` default to `--limited-fetch` when the repository is shallow, ensuring that adding a remote to a shallow clone does not trigger a full fetch of all remote branches.

The patch modifies `builtin/remote.c` to check whether the repository is shallow (using `is_repository_shallow()`) and, if so, enables `--limited-fetch` by default unless `--no-limited-fetch`, `-t/--track`, or `--mirror` is specified. The documentation in `git-remote.adoc` is updated to explain the new behavior, and the test suite (`t/t5505-remote.sh`) adds four new tests covering edge cases: explicit `-t` refspecs in shallow repositories, wildcard refspecs in full repositories, the shallow-repository default, and the `--no-limited-fetch` override.

This is a targeted, backward-compatible change that directly addresses the performance pitfall the series was designed to solve. The implementation is clean, the commit message is clear, and the test coverage is thorough. The patch does not introduce new edge cases beyond those already discussed in the series, and the shallow-repository default aligns with the user expectation that a shallow clone should remain shallow. No controversy is expected here; this is a natural completion of the refmap-based design.
