This is a bugfix identifying a regression in error reporting. Kristoffer Haugsbakk reports that when `git shortlog` (or presumably any revision command) encounters an unknown option like `--not-an-option`, the error message incorrectly shows `(null)` instead of the actual option name. The issue was introduced by commit cd439487 ("revision: manage memory ownership of argv in setup_revisions()", 2025-09-19) and persists even after the recent `jk/rev-info-argv-to-free` topic (which fixed related issues) was merged.

The bug is straightforward: the error path in revision option parsing now frees and nulls the `argv` entry before formatting the error message, causing `error("unknown option `%s'", arg)` to print `(null)` when `arg` is NULL. Haugsbakk bisected the issue across `master`, `seen`, and `next`, confirming it affects all current integration branches. The reproduction case is simple—run `git shortlog -n --not-an-option master`—and the fix will likely involve moving the free-and-null operation after the error message is generated.

This is a clear regression with a well-defined scope: a single commit, a single code path, and a trivial reproduction. The patch should be small and uncontroversial, though it may require coordination with the ongoing revision-argv memory management work. The issue affects user-facing error messages, making it more visible than typical internal bugs.
