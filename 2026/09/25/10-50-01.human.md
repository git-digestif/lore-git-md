This is the third patch in Harald Nordgren’s v3 series implementing the "matching-inspired" fetch mode for shallow repositories. It adds a `--limited-fetch` flag to `git remote add`, allowing users to explicitly create a remote that only fetches branches tracked by local branches (plus the remote’s default branch), instead of the traditional wildcard refspec that fetches all remote branches.

The patch extends `builtin/remote.c` to parse the new flag, rejecting it if combined with `-t/--track` or `--mirror` (since those already specify what to fetch). When `--limited-fetch` is used, the remote’s configuration sets `remote.<name>.refmap` (e.g., `+refs/heads/*:refs/remotes/<name>/*`) instead of `remote.<name>.fetch`, enabling the dynamic branch enumeration logic introduced in Patch 2/4. Documentation is updated in `git-remote.adoc` to explain the flag’s behavior, and a new test in `t/t5505-remote.sh` verifies the configuration is set correctly and that the flag conflicts with `-t` as expected.

This is a straightforward plumbing addition that complements the core fetch logic in Patch 2/4. The implementation is clean and well-scoped, with clear error handling for invalid flag combinations. The test coverage is minimal but sufficient for the feature’s scope. The patch doesn’t address the open questions from earlier in the series (e.g., whether the mode should be available outside shallow repositories), but those are design-level concerns that don’t affect this specific change. For users of shallow repositories, this flag provides a convenient way to opt into the new fetch behavior without manual configuration.
