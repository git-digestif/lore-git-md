This is the final confirmation exchange in D. Ben Knoble’s four-patch bugfix series for `git stash` autostash handling of staged index entries. The series replaces subprocess-based index merging with an in-core merge via `merge-ort.c` to eliminate a race condition that could corrupt staged entries during autostash operations.

The email confirms the memory leak in Patch 4—previously identified by Phillip Wood—is real and detectable in CI, though the output is buried deep in the test failure log. The leak occurs because the `merge_result` struct is not finalized before returning on conflict, leaving allocations unfreed. Both parties agree the fix is trivial (add `merge_finalize(&o, &result)` before the error return) and does not affect the patch’s core correctness. The author has already acknowledged the issue and plans to include the fix in the upcoming v3, which is expected to be the final iteration of the series.

No new technical concerns are raised; this exchange is purely about confirming the leak’s presence and the fix’s simplicity. The series remains technically sound, with all prior feedback—including Junio C Hamano’s critical correction to the tree argument order in `merge_incore_nonrecursive()`—already addressed. The only remaining work is the memory leak fix, which can be incorporated without a full re-roll. The thread is now effectively closed, pending the author’s v3 submission.
