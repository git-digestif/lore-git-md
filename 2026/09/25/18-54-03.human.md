This is a CI/build system patch that improves leak sanitizer failure reporting in GitHub Actions.

The patch addresses a long-standing pain point in Git's CI: when a leak test fails, the error message appears only at the very end of the test script, after all tests have already reported "ok". The failure annotation lacks file and line information, leaving reviewers with nothing to click through—just a generic "Process completed with exit code 1". Harald Nordgren changes this so that each leak-sanitizer script stops at its first failure, and both the failure and leak annotations now point to the actual test file and line, including the specific error message and stack trace.

The implementation touches three files: `ci/lib.sh` (to add `--immediate` to `GIT_TEST_OPTS` for leak jobs), `t/test-lib-github-workflow-markup.sh` (to add new functions that extract the failing test line and format GitHub Actions annotations), and `t/test-lib.sh` (to declare a no-op stub for the new `finalize_test_leak_output` function). The proof-of-concept link shows the new output in action, with clickable annotations that take you directly to the failing test.

This looks like a well-crafted, narrowly scoped improvement. The commit message is clear, the code is clean, and the motivation is compelling—anyone who has tried to debug a leak in CI will recognize the problem. There is no controversy here; it is a straightforward usability win for contributors.
