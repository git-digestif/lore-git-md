This is the first patch in Harald Nordgren’s four-part series introducing a new `remote.<name>.refmap` configuration to enable a matching-inspired fetch mode for shallow repositories. The patch adds the plumbing for the refmap configuration, allowing users to define namespace mappings for fetched refs without specifying what to fetch. Junio C Hamano’s review here is surface-level, focusing on documentation wording and code clarity rather than technical behavior.

The review suggests minor tweaks to the documentation to clarify that `remote.<name>.refmap` is not conditional on explicit refspecs—it simply defines how refs are mapped when they *are* fetched. Junio’s proposed rewording removes the implication that the refmap only "takes effect" when something is explicitly fetched, aligning the description with the existing `--refmap` option’s behavior. The code changes themselves are uncontroversial: they introduce a `refmap` field to `struct remote`, parse the new configuration key, and update `builtin/fetch.c` to use the configured refmap as the default for `--refmap` when an explicit refspec is provided.

This patch is foundational for the series, enabling the dynamic branch enumeration and shallow-repository defaults in later patches. The implementation is clean and follows Git’s existing patterns, though Junio notes a broader opportunity to reduce reliance on file-scope static variables (like `refmap`) in favor of a `struct fetch_config`—a refactoring that would be out of scope here. The test coverage is adequate for the added functionality, and no backward compatibility issues are introduced. The review does not raise substantive concerns, suggesting this patch is on track for acceptance once the documentation wording is adjusted.
