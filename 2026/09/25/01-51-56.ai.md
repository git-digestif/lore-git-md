This is a maintainer review of a bugfix patch for `git fetch-pack`. Junio C Hamano raises a design concern about the proposed change. The patch aims to make `git fetch-pack` consistent with `git fetch` by marking exact OIDs (object IDs) in refs, which would prevent "unknown ref" errors when invoking `git fetch-pack $OID`. However, Junio argues that `fetch-pack` is a lower-level command and should not apply the same heuristic DWIM (Do What I Mean) behavior as `git fetch`. He suggests that if users need to pass exact OIDs, they should do so explicitly, rather than relying on implicit parsing. This would preserve the ability to send `want-ref` requests for specific OIDs, which `git fetch` does not support.

The review is substantive, as it questions the fundamental approach of the patch rather than its implementation. Junio does not reject the patch outright but implies that the current design might be misguided. He also notes that `git fetch-pack` is rarely used directly today, as the manual itself recommends `git fetch` instead. The discussion now hinges on whether the patch should proceed as-is (making `fetch-pack` behave like `fetch`) or whether a more explicit mechanism for specifying OIDs should be introduced. This could lead to a broader conversation about the role of `fetch-pack` in Git's command hierarchy.
