This is the second patch in Tamir Duberstein’s v2 CI/build system series, addressing parallelism in Git’s GitHub Actions workflows. The patch aligns job counts across CI providers by dynamically setting `-j` for `make` and `prove` to the runner’s CPU count, replacing GitHub’s hardcoded `JOBS=10` with the same logic GitLab already uses.

The change is a straightforward refactor of `ci/lib.sh`: instead of setting `JOBS` at OS detection time, it now sets it afterward using a unified `case` statement. On Linux, it uses `nproc`; on Windows, `NUMBER_OF_PROCESSORS`; and on macOS, `sysctl -n hw.logicalcpu` (avoiding a dependency on GNU coreutils). The patch is conservative, opting for `1x CPU count` rather than oversubscribing, and the benchmark data in the cover letter shows this yields a 2% speedup on Linux while eliminating ENOSPC errors in large clone/repack tests.

This revision responds directly to Patrick Steinhardt’s review feedback, unifying the logic for GitHub and GitLab and using native CPU-count queries on all platforms. The implementation is clean, well-motivated, and unlikely to be controversial. No new CLI options or on-disk formats are introduced, and the change is limited to CI infrastructure. The patch is ready for integration once Patrick’s remaining question about oversubscription is resolved.
