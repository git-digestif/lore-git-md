This is the first patch in Harald Nordgren’s v3 series implementing the `remote.<name>.refmap`-based "matching-inspired" fetch mode for shallow repositories. It adds the plumbing for a new per-remote configuration variable, `remote.<name>.refmap`, which provides the default value for the `--refmap` option in `git fetch`.

The patch is a straightforward extension of Git’s existing refspec machinery. It mirrors how `remote.<name>.fetch` already works: the new `refmap` config is only used when there is something explicit to fetch (either on the command line or via `remote.<name>.fetch`), matching the behavior of `--refmap` itself. The implementation touches `remote.c` and `remote.h` to add the new field and parsing logic, updates `builtin/fetch.c` to use the config when no command-line `--refmap` is given, and adds documentation and tests.

The change is minimal and well-scoped. It does not alter any existing behavior; it merely adds a new configuration knob that will be used by later patches in the series. The test coverage is thorough, verifying that the config behaves identically to the command-line option. This patch is a solid foundation for the rest of the series and looks ready for integration. There are no red flags here—just clean, incremental plumbing work.
