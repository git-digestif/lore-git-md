This is a brief follow-up in the `http.sslVerifyStatus` thread. SZEDER Gábor confirms Patrick Steinhardt’s diagnostic guess: Gábor’s system was using the GnuTLS backend for libcurl, which does not fully support OCSP stapling, causing the new `t5585-http-ssl-ocsp.sh` test to fail. Switching to the OpenSSL backend makes the test pass. The core functionality of `http.sslVerifyStatus` itself is unaffected; the issue was purely environmental and confined to the test suite. No further changes to the patch are needed, but the test’s prerequisite logic may need to be tightened to detect and skip tests when the backend lacks OCSP support.
