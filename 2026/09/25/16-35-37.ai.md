This is the cover letter for v2 of a two-patch CI/build system series from Tamir Duberstein, addressing resource exhaustion in GitHub Actions CI jobs. The series targets two specific bottlenecks: (1) a test that generates enormous output, triggering OOM kills when `diff` compares it, and (2) overly aggressive parallelism in `make` and `prove` that overwhelms Linux runners with only 2 CPU cores.

Patch 1 replaces `test_cmp` (which uses `diff`) with `test_cmp_bin` (which uses `cmp`) in `t/t4205-log-pretty-formats.sh`. The change is endorsed by both Jeff King and Junio C Hamano, who agree the lightweight `cmp` is sufficient for this edge case. Benchmark data shows `diff` peaks at 4 GiB RSS and takes 5 seconds, while `cmp` uses 1.2 MiB and finishes in 0.5 seconds. The v2 revision drops the early file deletion, which was deemed unnecessary since subsequent tests overwrite the files anyway.

Patch 2 dynamically sets `-j` for `make` and `prove` to the runner’s CPU count on Linux, aligning GitHub Actions with GitLab CI’s existing policy. The v2 revision unifies the logic for both CI platforms and uses native CPU-count queries on macOS and Windows. Benchmark data shows a 2% speedup on Linux with `1x CPU count` and a 7% speedup with `2x CPU count`, but Tamir opts for the conservative `1x` baseline to ensure consistency. The patch is a minimal four-line addition to `ci/lib.sh`.

The series is under review, with Patch 1 effectively settled and Patch 2 awaiting further feedback on whether oversubscribing (e.g., `2x CPU count`) would be a better trade-off. The changes are pragmatic, well-motivated, and unlikely to be controversial. No new CLI options, on-disk formats, or test coverage changes are introduced. Files touched: `.github/workflows/main.yml`, `t/t4205-log-pretty-formats.sh`, and `ci/lib.sh`.
