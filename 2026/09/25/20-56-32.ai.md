This is a bugfix patch targeting the packfile subsystem. It addresses a resource leak where temporary pack files created during `git gc` or `git maintenance` operations are left behind if the process is killed, leading to disk space exhaustion in environments like Kubernetes pods running Gitea mirrors.

The patch registers temporary pack files (created via `odb_mkstemp()` in `pack-write.c` and `pack-bitmap-write.c`) with Git's tempfile subsystem, ensuring they are automatically cleaned up on graceful process exit. This aligns the behavior with `git repack`, which already handles this correctly. The commit message provides concrete examples of the problem: orphaned temp files accumulating to hundreds of gigabytes across multiple killed repacks.

The change is minimal (8 lines across two files) and leverages existing tempfile cleanup infrastructure. The author notes that the fix is self-evident and relies on the tempfile subsystem's existing test coverage, though they experimented with unit tests that weren't included in the final submission. The patch touches core packfile-writing code paths used by `git gc` and `git maintenance`, making it relevant to both local development and server-side Git operations.

Key technical details include:
- Files modified: `pack-bitmap-write.c` and `pack-write.c`
- Functions affected: `odb_mkstemp()` call sites
- Related prior work: `git repack` already uses `register_tempfile()`
- The tempfile subsystem was introduced in commit 1a9d15db25 (2015)
