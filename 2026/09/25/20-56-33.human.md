This is a bugfix patch targeting the packfile subsystem. It plugs a resource leak where temporary pack files created during `git gc` or `git maintenance` operations are left behind if the process is killed, leading to disk space exhaustion in environments like Kubernetes pods running Gitea mirrors.

The patch registers these temporary files with Git's tempfile subsystem by calling `register_tempfile()` immediately after each `odb_mkstemp()` call in `pack-write.c` and `pack-bitmap-write.c`. This ensures the files are automatically cleaned up on process exit, matching the behavior already implemented for `git repack`. The fix is minimal—just eight lines across two files—and leverages existing infrastructure, making it a straightforward and low-risk change.

The problem is well-documented in the commit message, with concrete examples of orphaned temp files (e.g., `tmp_pack_XXXXXX`, `tmp_idx_XXXXXX`) accumulating to hundreds of gigabytes. The solution follows the established pattern used by `git repack`, which has handled this correctly since 2015 (commit 1a9d15db25).
