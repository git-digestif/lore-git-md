This is a small feature patch for the `git-contacts` contrib script, part of the ongoing effort to improve its interoperability with external tools like `b4`. The patch implements the conventional UNIX `-` idiom to read patch content from stdin, allowing mixed file/stdin usage (e.g., `git contacts patch1 - patch3 <patch2`).

Version 4 adopts Junio’s suggestion to avoid implying that `git-contacts` processes arguments in a predictable order, a clarification now reflected in the commit message. The implementation treats `-` as a special filename argument, setting a `$read_from_stdin` flag when encountered, and calls `scan_patches()` with the stdin filehandle if the flag is set. This replaces the v2 behavior, which implicitly read from stdin when no arguments were given and stdin was not a terminal.

The patch touches only `contrib/contacts/git-contacts`, a Perl script, and introduces no new CLI options, symbols, or on-disk format changes. The structural design question raised in the thread—whether to eliminate the `$read_from_stdin` flag in favor of treating `-` as a special filename in `scan_patch_file`—remains unresolved, but the feature concept itself is uncontroversial and endorsed by Junio. The author has indicated willingness to address this in a follow-up patch if desired.

The change is narrowly scoped and low-risk, with no test coverage added, but the simplicity of the modification reduces the likelihood of regressions. The patch is actionable independently of the related `b4` integration effort, though it was motivated by cross-project interoperability needs. The thread’s open question is purely about code structure, not functionality.
