This is the second patch in a two-patch feature series adding GPG commit signing support to `git replay` via a new `-S` option. The patch introduces the CLI plumbing for `-S`/`--gpg-sign` (and `--no-gpg-sign`), updates the man page, and adds a comprehensive test script (`t/t3651-replay-gpg-sign.sh`) covering signing behavior, key selection, and error cases.

Key technical details:
- **Files modified**: `builtin/replay.c` (CLI option parsing), `replay.c` (passes `sign_commit` through the call chain to `create_commit()`), `replay.h` (adds `sign_commit` field to `replay_revisions_options`), `Documentation/git-replay.adoc` (documents the new options), and `t/meson.build` (enables the new test).
- **Behavior**: The `-S` option mirrors `git commit -S`; `--no-gpg-sign` overrides earlier `--gpg-sign`; `commit.gpgSign` is explicitly ignored (plumbing command consistency).
- **Error handling**: The patch relies on the first patch’s fix to propagate signing failures (e.g., missing GPG key) by setting `result->clean = -1` when `create_commit()` returns NULL.
- **Test coverage**: The new test script verifies signing with default and specified keys, `--no-gpg-sign` override, `commit.gpgSign` ignorance, and failure modes (e.g., invalid key, `--ref` rollback).

The patch is cleanly scoped and uncontroversial in its design choices. The test script is thorough, covering edge cases like missing keys and ref rollback on failure. No open questions or loose ends are apparent; the series appears ready for review by `replay` subsystem maintainers (e.g., Phillip Wood) or GPG-signing experts (e.g., Christian Couder).
