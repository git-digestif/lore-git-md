This is a bugfix report for the revision parsing subsystem. Kristoffer Haugsbakk identifies a regression in `git shortlog` (and likely other revision-based commands) where an invalid option like `--not-an-option` is reported as `(null)` instead of the actual option string. The issue bisects to cd439487 ("revision: manage memory ownership of argv in setup_revisions()", 2025-09-19), a commit that refactored how revision arguments are handled.

The bug is straightforward: when an unknown option is encountered, the code appears to free the option string prematurely, leaving a `NULL` pointer that later gets formatted into the error message as `(null)`. Haugsbakk confirms the issue persists even after the recent `jk/rev-info-argv-to-free` topic (which addressed related memory issues) was merged to `master`.

Reproduction is simple: run `git shortlog -n --not-an-option master` and observe the malformed error message. The fix will likely involve adjusting the memory ownership logic in `setup_revisions()` to ensure option strings remain valid until they're no longer needed. This looks like a clean, well-isolated bug with a clear regression point and reproduction case—worth attention from anyone working on revision parsing.
