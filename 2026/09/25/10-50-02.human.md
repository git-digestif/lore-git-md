This is the fourth and final patch in Harald Nordgren’s v3 series implementing the "matching-inspired" fetch mode for shallow repositories. It makes `git remote add` default to `--limited-fetch` when the repository is shallow, ensuring that adding a remote to a shallow clone does not trigger a full fetch of all remote branches.

The patch is small and focused: it modifies `builtin/remote.c` to check `is_repository_shallow(the_repository)` when `limited_fetch` is unset (its default value, `-1`), and updates the documentation to explain the new behavior. Three new tests in `t/t5505-remote.sh` verify that the default works as intended—shallow repositories get `--limited-fetch` unless explicitly overridden with `--no-limited-fetch`, while full repositories retain the traditional wildcard refspec.

This is a sensible usability improvement that directly addresses the original pain point: users who clone with `--depth` or `--single-branch` no longer risk slow or hanging fetches when they later add a remote. The change is backward-compatible (full repositories are unaffected) and opt-out (users can still request the old behavior with `--no-limited-fetch`). The implementation looks clean, and the tests cover the key edge cases. No controversy is evident in the thread so far; this patch should be ready to merge once the rest of the series lands.
