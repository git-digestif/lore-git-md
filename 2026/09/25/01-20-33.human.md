This is a meta-discussion reply in the ongoing thread about what version number Git should use after 2.56. Kristoffer Haugsbakk responds to Harald Nordgren’s proposal to change several user-facing configuration defaults in time for Git 3.0. Haugsbakk does not engage with the version numbering question itself but instead **pushes back on the feasibility of changing defaults**, calling it "difficult" due to the need to convince many people that the disruption is justified. He then floats an alternative: a **configuration analyzer tool** that would read a user’s Git config, compare it to "modern Git practice," and recommend better settings. This idea, he notes, has been discussed before on the list.

The tone is pragmatic and cautious. Haugsbakk does not outright reject Harald’s proposal but clearly signals that changing defaults is a high bar, while a tool-based approach might be an easier sell. No code or patches are attached; this is purely a design-level suggestion that keeps the sub-thread alive without advancing the version numbering discussion. The proposal is well-motivated but underdeveloped — Haugsbakk does not sketch how such a tool would work, what "modern Git practice" means, or how it would avoid becoming just another piece of folklore. It is likely to spark further discussion about how Git should evolve its defaults without breaking existing workflows.
