This is the first patch in a two-part feature addition to `git replay`, introducing commit signing support. The patch fixes a latent bug in error handling: when `pick_regular_commit()` fails to create a commit, it currently returns `NULL` while leaving `result->clean` set to `1` (success), which confuses the caller into treating the failure as a successful operation. The fix ensures `result->clean` is set to `-1` (error) when commit creation fails, preparing the codebase for the next patch, which will add signing as a new failure mode.

The change is minimal and surgical—just six lines added to `replay.c`—and directly addresses a `FIXME` noted in the code. The commit message is clear and explains the problem, the fix, and the motivation (upcoming signing support). No test coverage is added here, but the patch is a prerequisite for the next one, which includes thorough tests. This looks like a well-crafted, uncontroversial bugfix that should attract little debate. Reviewers familiar with the `replay` subsystem (e.g., Phillip Wood) may want to verify the error propagation logic, but the patch itself is straightforward.
