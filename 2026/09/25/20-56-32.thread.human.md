This thread is about a bugfix patch from Royce Remer that addresses resource leaks in Git's packfile subsystem. When `git gc` or `git maintenance` operations are interrupted (e.g., by a SIGKILL), temporary pack files created during the process are left behind, leading to disk space exhaustion in environments like Kubernetes pods running Gitea mirrors. The patch ensures these temporary files are registered with Git's tempfile subsystem, which already handles cleanup for similar cases in `git repack`.

The fix is minimal—just eight lines across two files—and leverages existing infrastructure (`register_tempfile()`), making it a low-risk solution. The author's commit message clearly explains the problem and provides real-world examples, though they note the lack of explicit unit tests for this specific scenario. The patch touches core packfile-writing code paths, so its impact is broad but limited to cleanup behavior.

So far, there's been no review feedback, so the patch's correctness and edge cases (like cleanup during abnormal termination) remain unvalidated. However, the fix aligns with established patterns in the codebase and addresses a tangible operational issue, making it a strong candidate for inclusion. The only open question is whether additional test coverage is needed, but the change itself is straightforward and well-motivated. If merged, it would close a long-standing gap in tempfile cleanup for critical Git operations.
