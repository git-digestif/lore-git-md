This thread is about a bugfix patch from Royce Remer that plugs a resource leak in Git’s packfile subsystem: temporary files created during `git gc` or `git maintenance` are left behind if the process is killed, because they aren’t registered with Git’s tempfile cleanup machinery. The patch is tiny (eight lines) and uses the existing `register_tempfile()` infrastructure, so it’s low-risk and uncontroversial on the surface.

Patrick Steinhardt’s review, however, shifts the conversation from a simple bugfix to a deeper architectural question. He argues that the real issue isn’t the missing registration—it’s that `odb_mkstemp()` itself is poorly designed. The function returns a file descriptor but not a `struct tempfile *`, forcing callers to manually register tempfiles and creating the very inconsistency this patch fixes. Worse, he points out that `odb_mkstemp()` is tied to the "files" ODB backend’s directory structure, making it a poor fit for the ODB layer, which should be backend-agnostic. His proposed solution—moving the function to `tempfile.h` and redesigning it to return a tempfile directly—would require a larger refactoring but would eliminate the need for manual registration entirely.

The thread is now at a crossroads: Royce can either proceed with the minimal fix (which solves the immediate problem) or engage with Patrick’s feedback and propose a broader redesign. No other reviews have landed yet, so the next move is Royce’s. The patch remains under review, with no merge status reported.
