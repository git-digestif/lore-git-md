This is a CI/build system patch that improves leak sanitizer failure reporting in GitHub Actions.

The patch addresses a long-standing pain point in Git's CI workflow: when a leak sanitizer test fails, the error message appears only at the very end of the test script, with no link to the specific test case or line that triggered the leak. Reviewers currently see only a generic "Process completed with exit code 1" message, making it difficult to debug. Harald Nordgren's change makes two key improvements: it stops the test script at the first leak failure (rather than continuing with an already-tainted run), and it enhances GitHub Actions annotations to point directly to the failing test file and line, including the actual leak error message.

The implementation touches three files: `ci/lib.sh` (to add `--immediate` to `GIT_TEST_OPTS` for leak sanitizer jobs), `t/test-lib-github-workflow-markup.sh` (to add new functions for escaping messages, finding test case lines, and generating proper GitHub annotations), and `t/test-lib.sh` (to add a no-op stub for the new `finalize_test_leak_output` function). The proof-of-concept link shows the feature working in a real GitHub Actions run, with annotations now displaying the test filename, line number, and the first 40 lines of the leak sanitizer output.

This is a well-motivated quality-of-life improvement for contributors and reviewers. The commit message clearly explains the problem, the solution, and provides evidence that it works. The patch itself is focused and appears to handle edge cases (like missing line numbers) appropriately. No controversy is expected - this is the kind of CI polish that typically gets quick approval.
