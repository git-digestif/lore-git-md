This thread is about a patch by Harald Nordgren to improve GitHub Actions CI failure reporting, specifically for leak sanitizer errors. The goal is to make failures easier to debug by linking them directly to the relevant test script and line, rather than burying them in logs.

Harald has revised the patch into two focused commits after feedback. The first stops leak-sanitizer scripts at the first failure (using `--immediate`) and annotates leaks with the test script name and full sanitizer output in a collapsible log group. The second ensures regular test failures also point to their exact file and line. Key improvements in this version include uncapped leak output (avoiding truncation that hid details) and removal of a giant unfolded annotation that caused scrolling issues in Firefox.

Phillip Wood had raised concerns about `--immediate` hiding subsequent leaks and UI regressions, but Harald has addressed these by clarifying the trade-off (stopping at the first leak avoids burying real failures under noise) and fixing the scrolling issue. The commit messages now better explain the reasoning behind `--immediate` and escaping logic. Ben Knoble had suggested reordering helper functions for readability, which Harald has incorporated. The patch touches `ci/lib.sh`, `t/test-lib-github-workflow-markup.sh`, and `t/test-lib.sh`, introducing new annotation helpers like `github_annotation_` and `find_test_case_line_`.

The series is under review and appears uncontroversial, with the remaining work being minor clarifications in commit messages and helper function ordering. No related in-flight topics or conflicts are apparent.
