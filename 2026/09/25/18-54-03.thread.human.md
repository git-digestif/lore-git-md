This thread began as a simple quality-of-life patch to make GitHub Actions CI leak sanitizer failures more visible by stopping at the first leak and emitting annotations with file and line details. Harald Nordgren’s patch adds helper functions in `t/test-lib-github-workflow-markup.sh` and modifies `ci/lib.sh` to use `--immediate` in leak sanitizer jobs.

Phillip Wood’s review has shifted the discussion toward trade-offs. He questions whether stopping at the first leak (`--immediate`) is the right call, since it hides later leaks in the same run, and reports a usability regression: the new output format causes odd scrolling behavior in Firefox, making the CI log harder to navigate. The patch also introduces escaping logic and annotation generation without clear justification in the commit message, which complicates review. No other reviewers have weighed in yet, and Harald hasn’t responded to Phillip’s points. The thread is now at a decision point: whether to keep the current “first leak only” approach or find a way to report all leaks while still providing useful annotations. The scrolling issue adds urgency, as it risks degrading the CI experience beyond just leak sanitizer failures.
