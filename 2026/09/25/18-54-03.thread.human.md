This thread is about improving Git’s GitHub Actions CI to make leak sanitizer failures easier to debug. Harald Nordgren’s patch modifies the test script to stop at the first leak failure and emit GitHub Actions annotations that point directly to the failing test, including the leak error message. The goal is to replace the current behavior, where leaks are buried at the end of long test runs with only a generic exit code.

The patch is under review and has attracted substantive feedback, particularly from Phillip Wood, who raised two major concerns. First, stopping at the first leak (`--immediate`) simplifies debugging but hides subsequent leaks, creating a trade-off between usability and completeness. Harald acknowledges that the current behavior—where one leak causes every subsequent test to report “not ok”—already buries real leaks in noise, but the thread remains at an impasse on whether `--immediate` is the right solution. Second, the new output format causes a usability regression in the GitHub Actions UI, where Firefox exhibits strange scrolling behavior that degrades the CI experience for all test failures, not just leaks. Harald has promised to investigate but has not yet proposed a fix.

Other feedback includes a suggestion from Ben Knoble to reorder helper functions for readability, which Harald has agreed to implement, and a request to expand the commit message to justify the new plumbing functions (e.g., escaping logic and line-finding logic), which remain undocumented. The patch touches `ci/lib.sh`, `t/test-lib-github-workflow-markup.sh`, and `t/test-lib.sh`, introducing new symbols like `escape_message` and `generate_github_annotation`. No revised patch has been posted, and the thread is stalled on unresolved design and usability issues. The next step is likely a v2 patch that addresses the trade-offs, fixes the scrolling regression, and documents the changes. Until then, the patch is not ready for merging.
