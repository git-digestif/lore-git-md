This thread is about improving Git’s GitHub Actions CI to make test failures—especially leak sanitizer failures—easier to debug. Harald Nordgren’s two-patch v5 series is now cooking in Junio’s `next` branch. The first patch stops leak-sanitizer runs at the first failure and annotates the output with the test script name and full sanitizer log in a collapsible GitHub Actions group; the second patch replaces generic failure messages with precise, clickable links to the exact line in the test file where the failure occurred.

All substantive technical feedback from Junio C Hamano and Phillip Wood has been addressed: escaping logic was removed after it proved unnecessary, commit messages were expanded with concrete examples, and the annotation logic was reordered to ensure failures are reported even when `--immediate` exits the script. Junio has marked the series ready for `next` and has no further objections.

The remaining open questions are usability refinements: the GitHub Actions UI still doesn’t make the links clickable, the line-finding logic fails for dynamically generated test descriptions, and Phillip Wood would prefer a single collapsible section for both test and leak output. None of these are blocking the series, but Phillip’s latest email shifts focus to communication: he’s frustrated that the commit messages still don’t show the new output format, forcing reviewers to dig through GitHub’s UI to see what changed. He’s not objecting to the code itself—he calls both patches “useful improvements”—but wants clearer explanations to save reviewer time. The ball is now with Harald to improve the documentation before the series graduates to `master`.
