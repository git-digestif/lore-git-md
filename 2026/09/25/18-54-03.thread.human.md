This thread is about improving Git’s GitHub Actions CI to make leak sanitizer failures easier to debug. Harald Nordgren’s two-patch series (v6) tackles long-standing usability issues where failures were buried at the end of test runs with only a generic error message, and subsequent tests redundantly reported "not ok" after a leak was detected.

The first patch, unchanged since v5, is already cooking in Junio’s `next` branch. It makes two key changes: leak sanitizer jobs now stop at the first failure (`--immediate`) to avoid polluting the output with redundant "not ok" reports, and leaks are annotated with the test script name and full sanitizer output in a collapsible log group. This surfaces actionable failure information that was previously invisible, making CI debugging much faster for contributors. The patch touches `ci/lib.sh`, `t/test-lib-github-workflow-markup.sh`, and `t/test-lib.sh`, and is technically sound with no regressions or on-disk format changes. It’s a strong candidate for graduation to `master` and is decoupled from the second patch’s fate.

The second patch, rewritten as a compromise after Phillip Wood identified a critical regression in its original form, has been accepted by Phillip and is now a candidate for `next`. It embeds file name and line number directly in failure annotations as plain text (e.g., `failed: t1060.17 (t1060-object-corruption.sh:141)`), avoiding broken annotation links that only worked if the test file was modified in the same pull request. The compromise preserves the usability improvements while resolving the regression.

Phillip Wood’s substantive review was instrumental in salvaging the second patch, and Junio has not objected to the split or the compromise. The only remaining loose ends are low-priority: a principled justification for `--immediate`, UI presentation tweaks, and edge cases for dynamically generated test descriptions. These are not blocking, and the series is effectively ready for integration.
