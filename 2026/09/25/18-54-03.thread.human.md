This thread is about improving Git’s GitHub Actions CI to make leak sanitizer and test failures easier to debug. Harald Nordgren’s two-patch series (now at v3) is cooking in Junio’s `next` branch. The first patch stops leak sanitizer runs at the first failure and annotates leaks with the test script name and full sanitizer output in a collapsible log group; the second ensures regular test failures and fixed breakages point to their exact file and line in the test script.

Harald has addressed all substantive feedback from earlier versions, fixing a bug where annotations were dropped when `--immediate` was used, replacing a non-portable `\r` escape in `sed`, and clarifying the commit messages. The series is now functionally complete from a correctness standpoint, but two key issues remain unresolved: the annotations do not produce clickable links in the GitHub Actions UI (contradicting the commit message’s claim), and the escaping logic for test descriptions is overly cautious and may not be needed. Phillip Wood has also raised concerns about how dynamic test descriptions are handled and whether stopping at the first leak is the right trade-off.

Junio has marked the series as ready for `next` and has not raised further objections, but his latest reply simply acknowledges Phillip’s feedback without weighing in on the open questions. The ball is now back in Harald’s court to decide how—or whether—to address the remaining UI and escaping issues before the series graduates to `master`.
