This thread is about a small but impactful improvement to Git's CI workflow on GitHub Actions. Harald Nordgren has submitted a patch that makes leak sanitizer failures much easier to debug. Currently, when a leak test fails, reviewers see only a generic error at the end of a long test run, with no indication of which test case or line triggered the leak. The new patch stops the test run immediately on the first leak failure and enhances GitHub Actions annotations to point directly to the failing test file and line, including the actual leak error message.

The implementation is straightforward, touching just three files: `ci/lib.sh` to enable immediate failure, `t/test-lib-github-workflow-markup.sh` to add new annotation functions, and `t/test-lib.sh` for a no-op stub. Harald included a proof-of-concept link showing the feature working in a real GitHub Actions run, with clear annotations displaying the test filename, line number, and leak output. This is a quality-of-life improvement that should make life easier for contributors and reviewers alike, and it's the kind of focused, well-motivated CI polish that typically gets quick approval. No objections or requests for changes have been raised yet.
