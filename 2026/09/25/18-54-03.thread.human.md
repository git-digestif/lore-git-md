This thread is about improving Git’s GitHub Actions CI to make leak sanitizer failures easier to debug. Harald Nordgren sent a two-patch series (v5) that first stops leak-sanitizer jobs at the first failure and annotates leaks with the test script name and full output, then adds precise annotation links to the exact line in the test file where failures occur. The series was cooking in `next` but hit a critical snag: the annotation links only work if the test file was modified in the same pull request, otherwise they point to broken or irrelevant locations.

Phillip Wood has now formally recommended dropping the second patch entirely, as the broken links make it worse than the current behavior, which links to job output. He still supports the first patch, which improves leak reporting without regressions. Harald has paused further work pending this feedback, and Junio had previously marked the series as ready for `next` but deferred on the broken links. With Phillip’s recommendation, the series is effectively split: the first patch remains viable for `next` and eventual graduation to `master`, while the second is abandoned unless someone proposes a fallback mechanism. No further iteration is expected unless new ideas emerge.
