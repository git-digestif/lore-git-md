This thread is about improving Git’s GitHub Actions CI to make test failures easier to debug. Harald Nordgren’s two-patch series (now at v4) addresses two pain points: leak sanitizer failures that get buried at the end of test runs, and generic failure messages that don’t point to the exact line in the test script. The first patch stops leak sanitizer runs at the first failure and annotates leaks with the test script name and full sanitizer output in a collapsible log group. The second patch replaces vague failure messages with precise, clickable links to the failing test line—though clickability in the GitHub UI remains broken, a known limitation.

The series is cooking in Junio’s `next` branch after addressing all substantive feedback from earlier versions. Phillip Wood’s latest review raised a few lingering concerns: the escaping logic for GitHub annotations is inconsistent (percent signs are escaped in new annotations but not existing ones), dynamic test descriptions still don’t work with the line-finding logic, and the UI could be more intuitive by consolidating test and leak output. Junio’s brief reply clarified the patch’s intent but didn’t resolve these issues, leaving them for Harald to address in a likely v5. The `--immediate` trade-off—stopping at the first leak to avoid duplicate reports—also remains a point of discussion, though the current approach is pragmatic.

Harald has iterated carefully on feedback, splitting the series into focused commits, fixing correctness issues, and simplifying escaping logic. The only unresolved technical blocker is the escaping inconsistency, while the dynamic-description and UI issues are acknowledged but not yet fixed. The series is close to graduation, pending these refinements.
