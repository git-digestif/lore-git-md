This thread is about improving Git’s GitHub Actions CI to make test failures—especially leak sanitizer failures—easier to debug by providing clearer, more actionable error messages. Harald Nordgren’s v5 patch series (two commits) is currently cooking in `next`. The first commit stops leak-sanitizer runs at the first failure and annotates leaks with the test script name and full sanitizer output in a collapsible log group; the second ensures regular test failures point to their exact file and line in the test script.

The series has addressed most technical feedback: escaping logic was removed after it proved unnecessary, commit messages were expanded with concrete examples, and Junio C Hamano’s portability and correctness concerns were resolved. However, Phillip Wood has just identified a critical usability regression: the new annotation links only work if the test file was modified in the same pull request. Otherwise, they point to a broken or irrelevant location, undermining the patch’s core goal. This is a functional regression, not a theoretical issue—Phillip provided live GitHub URLs demonstrating the broken behavior. The series also still has open questions about dynamic test descriptions, UI presentation, and the principled trade-off of stopping at the first leak failure.

Harald has been responsive to feedback, but this latest issue is a blocker. Until it’s fixed, the series can’t be considered ready for `next`, despite Junio’s earlier approval. Phillip’s review is substantive and tested, and the ball is now in Harald’s court to either revert the annotation link logic or make it context-aware.
