This thread is about a two-patch series from Harald Nordgren that improves GitHub Actions CI failure reporting. The goal is to make test failures—both from leak sanitizers and regular test scripts—easier to debug by providing actionable annotations in the GitHub UI.

The first patch (already covered in the thread) stops leak sanitizer runs at the first failure and annotates the output with the test script name and full sanitizer log in a collapsible group. The second patch, just posted as v2, focuses on regular test failures: it adds helper functions to escape test descriptions and locate the exact line of a failing test in the script, then generates GitHub Actions annotations that link directly to the failure. This completes the series by ensuring all test failures, not just leaks, are actionable.

Harald has addressed earlier feedback from Phillip Wood and Ben Knoble, splitting the series into two focused commits, removing a problematic giant annotation that caused Firefox scrolling issues, and expanding commit messages to explain the reasoning behind `--immediate` and escaping logic. The remaining open questions are minor: whether the helper functions in `t/test-lib-github-workflow-markup.sh` are optimally ordered for readability, and whether the pragmatic choice to stop at the first leak (`--immediate`) needs deeper justification. Phillip Wood’s substantive review raised these points, but the scrolling issue he flagged appears resolved.

The series is under review and has no dependencies or conflicts with other work. If the current version holds up, it should make CI failures significantly easier to debug without introducing regressions.
