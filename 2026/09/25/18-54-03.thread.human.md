This thread is about a small but practical improvement to Git’s GitHub Actions CI: making leak sanitizer failures easier to debug. Harald Nordgren sent a patch that modifies the CI scripts so that, when a leak is detected, the test run stops immediately and emits a GitHub Actions annotation pointing directly to the failing test file and line, complete with the leak error message. This replaces the current behavior, where leaks are buried at the end of a long test log with only a generic exit code.

The patch is straightforward and self-contained, touching only CI and test infrastructure (`ci/lib.sh` and a new helper script in `t/`). Ben Knoble reviewed it and suggested a minor readability tweak—reordering some helper functions—which Harald has agreed to. No one else has weighed in, and there are no open technical questions or objections. The patch is still under review, with no prior versions or merge status. If you’re catching up, this is a low-risk, high-utility change that should make CI failures easier to triage.
