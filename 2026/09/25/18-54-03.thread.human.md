This thread is about a two-patch series (v3) by Harald Nordgren that improves GitHub Actions CI failure reporting for Git. The goal is to make test failures—both from leak sanitizers and regular tests—immediately actionable by annotating them with precise file and line information in the GitHub UI.

The first patch, previously summarized, ensures leak sanitizer failures stop at the first error and emit collapsible, annotated output with the test script name. The second patch (this update) adds exact line-number annotations for all test failures, replacing generic script-level pointers with clickable links to the failing test case. It introduces two helper functions: `find_test_case_line_` (which uses literal string matching to avoid regex pitfalls) and `github_escape_message_` (which handles GitHub’s annotation escaping rules). Harald has addressed all substantive feedback from earlier versions, including Junio C Hamano’s portability concerns and Phillip Wood’s questions about design trade-offs.

The series is now under final review, with no known correctness or portability issues. The only remaining discussion points are minor (e.g., helper function ordering for readability). Key participants—Harald, Junio, Phillip Wood, and D. Ben Knoble—have all weighed in, and the changes are widely seen as a usability improvement that avoids regressions in CI workflows. If no further objections arise, this is likely to be merged soon.
