This thread is about a two-patch series from Harald Nordgren that improves GitHub Actions CI failure reporting for Git’s leak sanitizer and regular test failures. The goal is to make failures easier to debug by stopping at the first leak (using `--immediate`), annotating leaks with the test script name and full sanitizer output in a collapsible log group, and ensuring regular test failures point to their exact file and line in the test script.

The series is now at v2 and under active review. Harald has addressed earlier feedback by splitting the series into two focused commits, removing a problematic unfolded annotation that caused Firefox scrolling issues, and expanding commit messages to explain the reasoning behind `--immediate` and escaping logic. However, Junio C Hamano recently identified a correctness issue in the second patch: the annotation logic for test failures is skipped when `--immediate` is set *and* `invert_exit_code` is set, due to an early `exit 0` path that bypasses the annotation. Harald has acknowledged this issue and plans to fix it by ensuring the annotation is written before any `--immediate` exit, regardless of `invert_exit_code`. Other open issues include portability concerns with `\r` in `sed` and stylistic inconsistencies in output redirection.

Phillip Wood and Junio have provided substantive technical reviews, with Phillip raising concerns about the `--immediate` trade-off and Junio flagging correctness and portability issues. Ben Knoble’s feedback on helper function ordering was partially addressed but may still need further attention. The series is close to resolution but must address these remaining nits before it can graduate.
