This thread is about improving Git’s GitHub Actions CI to make leak sanitizer failures easier to debug. Harald Nordgren’s two-patch series (v5) aims to stop test runs at the first leak failure and annotate failures with precise, clickable links to the test script. The series is cooking in `next` but is blocked by a critical regression: the annotation links only work if the test file was modified in the same pull request, otherwise they point to broken or irrelevant locations. Junio previously approved the series, but Phillip Wood’s review identified this as a show-stopper, and Harald has paused further work pending Phillip’s feedback on whether the broken links are acceptable or if the feature should be abandoned.

Harald has iterated on earlier feedback, splitting the series to separate leak sanitizer improvements from regular test failure reporting, and addressing correctness and usability concerns. However, the broken annotation links remain unresolved, and Phillip’s request for clearer commit messages and a principled justification for stopping at the first leak failure is still open. Harald’s latest reply frames the regression as a trade-off between improved leak reporting and secondary features like clickable links, but he hasn’t proposed a technical solution or fallback. The thread’s next step hinges on Phillip’s response—whether he considers the regression a dealbreaker or if the series can proceed with the links removed. Until then, the series remains in limbo.
