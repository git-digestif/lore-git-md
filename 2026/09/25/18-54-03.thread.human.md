This thread is about improving Git’s GitHub Actions CI to make test failures—especially leak sanitizer failures—easier to debug. Harald Nordgren originally sent a two-patch series (v5) that aimed to stop leak-sanitizer runs at the first failure and annotate failures with the test script name and sanitizer output. The first patch is already cooking in Junio’s `next` branch and is on track for `master`; the second, which tried to link annotations directly to test-script lines, was abandoned after Phillip Wood identified a critical regression: the links only worked if the test file was modified in the same pull request.

Harald has now proposed a compromise for the abandoned second patch. Instead of broken links, he suggests embedding the file name and line number directly in the annotation text while keeping the existing job-output links. For example, a memory leak would show as “memory leak logged in t1060 (t1060-object-corruption.sh)” and a test failure as “failed: t1060.17 partial clone of corrupted repository (t1060-object-corruption.sh:141)”. This keeps the usability improvement without the regression. Phillip’s earlier recommendation to drop the patch entirely may still stand, but this proposal is a targeted refinement rather than a revival of the original design. The first patch remains unaffected and continues cooking in `next`.
