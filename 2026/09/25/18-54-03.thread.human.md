This thread is about improving Git’s GitHub Actions CI to make test failures—especially leak sanitizer failures—easier to debug. Harald Nordgren’s two-patch series (now at v4) stops leak-sanitizer runs at the first failure, annotates the output with the test script name and full sanitizer log in a collapsible group, and replaces generic failure messages with precise, clickable links to the exact line in the test file where the failure occurred. The series has been cooking in `next` since the last update, with all substantive review feedback addressed.

The main open questions have been around usability: whether the GitHub Actions UI will render the annotations as clickable links (it doesn’t, and this remains unresolved), how to handle dynamically generated test descriptions (the current logic falls back to line 1, which isn’t ideal), and whether to consolidate test and leak output into a single collapsible section for better readability. Phillip Wood has been the most active reviewer, raising pragmatic concerns about these points, while Junio C Hamano has focused on correctness and portability, all of which have now been fixed.

The latest email simplifies the patch further by removing the escaping logic for percent signs in annotations. Harald argues that since Git tests don’t currently include literal `%25` (the only case that would break GitHub’s parser), escaping is unnecessary and risks inconsistency if not applied uniformly across all annotations. This is a calculated trade-off—it keeps the patch minimal but leaves a small risk of future parsing issues if test descriptions ever include `%25`. The series is otherwise ready to graduate, with no new objections from Junio or Phillip.
