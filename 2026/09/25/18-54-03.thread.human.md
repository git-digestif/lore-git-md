This thread is about a two-patch series (v6) by Harald Nordgren that improves GitHub Actions CI failure reporting for Git. The first patch, already cooking in `next`, stops leak-sanitizer scripts at the first failure and annotates leaks with the test script name and sanitizer output. The second patch, now rewritten as a compromise, embeds file and line context directly in test failure annotations to avoid broken links that plagued earlier versions.

The key issue was that annotation links in GitHub Actions only worked if the test file was modified in the same pull request, making them useless for most contributors. Harald’s compromise embeds the file and line number as plain text (e.g., `t1060-object-corruption.sh:141`) in the annotation, providing actionable context without relying on GitHub’s link resolution. Phillip Wood, the primary reviewer, initially recommended dropping the second patch due to the regression but has now accepted the compromise. The implementation is minimal, focusing on a new helper function to locate test descriptions in the script file, with a fallback to just the script name for dynamic test cases.

The series is now a candidate for `next`, with the first patch already cooking there and the second patch technically sound and ready for integration. The only open low-priority items are UI presentation (consolidating test and leak output) and a principled trade-off for stopping at the first leak, neither of which are blocking. Junio has not objected to the compromise, and the series is expected to graduate to `master` in due course.
