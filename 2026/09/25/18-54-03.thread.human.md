This thread is about a two-patch series from Harald Nordgren that improves GitHub Actions CI failure reporting for Git's test suite. The series is now cooking in Junio's `next` branch.

The first patch makes leak sanitizer failures more actionable by stopping at the first failure and annotating leaks with the test script name and full sanitizer output in a collapsible log group. The second patch, which just arrived in this update, replaces generic failure annotations with precise, clickable links pointing to the exact line in the test script where a failure or fixed breakage occurred. This makes it much easier for developers to jump directly to the failing test case.

Harald has addressed all substantive review feedback from earlier versions, including concerns about escaping logic, portability, and usability. Junio C Hamano has marked the series as ready for `next` and raised no new objections. Phillip Wood's remaining concerns about the `--immediate` trade-off (stopping at the first leak) and UI presentation (consolidating test and leak output) are acknowledged but not blocking. Two limitations remain: GitHub's UI doesn't yet make the annotations clickable, and the line-finding logic falls back to line 1 for dynamically generated test descriptions. Both are noted as future refinements rather than blockers.

The series is a well-scoped, incremental improvement that delivers immediate value by making test failures easier to debug, even if some usability aspects could be polished further down the line.
