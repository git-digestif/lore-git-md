This thread is about a two-patch series (v6) by Harald Nordgren that improves how Git’s GitHub Actions CI reports test failures, particularly for leak sanitizer issues. The first patch, already cooking in `next`, stops test scripts at the first leak failure and annotates leaks with the test script name and full sanitizer output in a collapsible log group. The second patch, rewritten as a compromise after feedback, now embeds file and line context directly in failure annotations as plain text (e.g., `failed: t1060.17 partial clone of corrupted repository (t1060-object-corruption.sh:141)`), fixing a critical regression where annotation links were broken unless the test file was modified in the same pull request.

Phillip Wood, the primary reviewer, has accepted the compromise and endorsed the series for merging. The only remaining loose ends are minor UI suggestions and a low-priority discussion about the `--immediate` trade-off, neither of which are blocking. The series is technically sound, addresses a clear pain point for CI debugging, and is ready for `next`. The first patch is already in `next`, and the second is now a candidate for inclusion. No further iteration is expected unless new issues arise.
