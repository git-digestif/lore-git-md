This thread is about improving Git’s GitHub Actions CI to make test failures easier to debug. Harald Nordgren’s two-patch series (now at v4) tackles two related problems: leak sanitizer failures and regular test failures both used to produce generic error messages at the end of long test runs, forcing developers to dig through logs. The first patch stops leak sanitizer runs at the first failure and annotates the output with the test script name and full sanitizer log in a collapsible group; the second patch ensures regular test failures and fixed breakages point directly to the exact line in the test script where they occurred.

The series is now cooking in Junio’s `next` branch after addressing all substantive review feedback. Phillip Wood and Junio C Hamano both provided detailed technical reviews, raising concerns about correctness, portability, and usability—all of which Harald has resolved. The escaping logic is now minimal (handling only `%` characters), the annotation logic is reordered to ensure failures are reported even with `--immediate`, and the commit messages clearly explain the trade-offs, such as stopping at the first leak to avoid polluting the output with duplicate reports.

Two usability issues remain open: the GitHub Actions UI doesn’t make the annotations clickable, and dynamically generated test descriptions (like those with variables) still fall back to line 1. These aren’t blocking the series, but they’re noted as areas for future refinement. The patches are narrowly scoped, well-tested, and solve a real pain point for reviewers, making CI failures much more actionable.
