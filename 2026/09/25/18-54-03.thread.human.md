This thread began with Harald Nordgren’s patch series to improve how Git’s GitHub Actions CI reports leak sanitizer failures. The first patch, which stops leak sanitizer jobs at the first failure and annotates leaks with the test script name and full sanitizer output in a collapsible log group, has been cooking in `next` and is ready to graduate to `master`. The second patch, which aimed to provide exact file and line pointers for regular test failures, was abandoned after Phillip Wood identified a critical regression: annotation links only worked if the test file was modified in the same pull request, making them useless in most cases.

Harald proposed a compromise to salvage the second patch’s usability improvements by embedding the file name and line number directly in the annotation text (e.g., `memory leak logged in t1060 (t1060-object-corruption.sh:141)`) while preserving the existing job-output links. Phillip Wood has now accepted this compromise, resolving the last open question in the thread. The compromise is a low-risk, presentation-layer adjustment that avoids the regression while still providing more context than the current behavior. No further iteration is expected, and the first patch is now unblocked for graduation. If Harald chooses to submit the compromise as a follow-up patch, it is likely to be accepted.
