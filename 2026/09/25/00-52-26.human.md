This is a documentation patch that modernizes cross-references in Git's man pages. The patch systematically replaces informal plain-text section references (e.g., "see EXAMPLES below") with formal AsciiDoc link syntax (`<<EXAMPLES,EXAMPLES>>`) across 38 files in the `Documentation/` directory. The goal is to improve navigation in HTML-rendered man pages by making these references clickable.

The patch is part of the ongoing documentation synopsis-style conversion effort led by Jean-Noël Avila, and it has already been approved by Junio C Hamano and queued in `next` since July 2024. The author, Julia Evans, revised the commit message in this version to clarify why the two-part AsciiDoc link form (`<<EXAMPLES,EXAMPLES>>`) is necessary: the shorthand form (`<<EXAMPLES>>`) can produce inconsistent or broken output (e.g., `the section called "EXAMPLES"` or `[EXAMPLES]`) due to quirks in the AsciiDoc/Asciidoctor toolchain. The two-part form ensures consistent rendering across backends and output formats.

The patch also changes some HTML section IDs from auto-generated anchors (e.g., `_examples`) to manual anchors (e.g., `EXAMPLES`), which could break existing external links. This trade-off between link stability and readability was explicitly framed as a design decision in the thread, though the project has not yet settled on a long-term policy. The author tested the change by building all man pages before and after the patch and verified no functional differences were introduced. Junio and Jeff King (Peff) also reviewed and validated the approach, with Peff providing a detailed technical explanation of the toolchain behavior.

This is a well-motivated, mechanical improvement to documentation usability, and the patch itself is thorough and well-tested. The only open question is the anchor style trade-off, which is noted in the commit message and thread but does not block integration. No further technical changes are expected.
