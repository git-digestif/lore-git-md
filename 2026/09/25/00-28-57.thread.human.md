This thread is about a regression in Git's error reporting for unknown command-line options. When you run `git shortlog` (or any revision command) with an unrecognized option like `--not-an-option`, Git now displays `(null)` instead of the actual option name in the error message. Kristoffer Haugsbakk identified the cause: commit cd439487 from September 2025, which changed how memory ownership is managed in `setup_revisions()`, accidentally freed the option string before the error message could use it.

The bug is present in all current integration branches (`master`, `next`, and `seen`) and has a simple reproduction case: `git shortlog -n --not-an-option master`. The fix should be straightforward—moving the free-and-null operation after the error message is generated—but may need to coordinate with ongoing work on revision argument memory management. While the impact is limited to error messages (the command still fails as expected), it’s a visible regression that affects user experience. No discussion or review has happened yet, so the next step is likely a patch from Haugsbakk or someone else addressing the issue.
