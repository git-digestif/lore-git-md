This thread is about a regression in Git where `git shortlog` and other revision commands incorrectly display `(null)` instead of the actual unknown option name when an invalid option is provided. The issue was introduced by a recent commit and affects all current integration branches. Jeff King (Peff) has proposed a two-patch series to fix both the regression and a latent bug in the revision option parsing logic.

The first patch, now under review, addresses the latent bug: when a known option is provided with invalid arguments (e.g., `--default` without a value), the code previously misreported it as an "unknown option" instead of showing the correct error message. Peff’s fix is minimal, changing a single condition in `parse_revision_opt()` to distinguish between malformed and unknown options. The patch includes a test case to verify the fix and is considered low-risk.

The second patch, which will follow, will fix the `(null)` regression by ensuring the original option string is referenced in error messages. So far, there are no objections or alternative proposals, and the discussion has focused on the technical details of the fixes. The thread is still under review, with Kristoffer Haugsbakk reporting the bug and Peff driving the fixes.
