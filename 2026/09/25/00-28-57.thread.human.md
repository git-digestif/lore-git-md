Here’s the human-readable summary for a developer catching up on the thread:

This thread is about a regression in `git shortlog` (and other revision commands) where invalid options now show `(null)` instead of the actual option name in error messages. Kristoffer Haugsbakk reported the bug, which was introduced by commit cd439487 in September 2025 and affects all current integration branches. The root cause is a memory management change in `setup_revisions()` that frees and nulls the `argv` entry before the error message is generated.

Jeff King (Peff) has proposed two fixes. The first is a minimal change that avoids referencing the now-NULL `argv` entry by using a still-valid copy of the option string. The second is a more ambitious approach that restores an older assumption about memory ownership, potentially addressing similar lurking issues. Both fixes are small and target only `revision.c`, with no on-disk format changes or new symbols. The bug is user-facing but trivial to reproduce (`git shortlog -n --not-an-option master`), and no objections or alternative proposals have emerged yet. The thread is still early in review, but the fix is expected to be uncontroversial.
