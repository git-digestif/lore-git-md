This thread is about a regression in `git shortlog` and other revision commands where unknown options were incorrectly displayed as `(null)` instead of their actual name (e.g., `--not-an-option`). The bug was introduced by a recent memory-management change in revision option parsing and affects all current integration branches.

Kristoffer Haugsbakk reported the issue and identified its root cause, while Jeff King (Peff) proposed a two-patch fix. The first patch addressed a latent bug where known-but-invalid options were misreported as unknown, and the second patch—now under discussion—restores the correct error message behavior by ensuring the option name is still accessible when formatting the error. Peff’s detailed commit message explains why the fix is safe and minimal, avoiding broader changes to memory ownership assumptions.

The series is under review with no objections so far, though the second patch’s implications for shared revision command logic may draw closer scrutiny. If accepted, the fix will resolve the `(null)` regression, the latent misreporting bug, and an older issue where known options with invalid arguments were incorrectly labeled as unknown. The changes are confined to `revision.c` and the test suite, with no new symbols or on-disk format changes.
