This thread is about a regression in `git shortlog` (and other revision commands) that caused unknown options to be displayed as `(null)` instead of their actual names (e.g., `--not-an-option`). The bug was introduced in Git v2.52.0 and affects all current integration branches. Jeff King (Peff) proposed a two-patch series to fix the issue, which Junio C Hamano has reviewed, tested, and approved for inclusion in `next` and eventual graduation to `master`.

The patches correct the error reporting by ensuring the option name is preserved during memory management in `setup_revisions()`. They also address two latent bugs: misreporting known-but-invalid options (e.g., `--max-count=foo`) as unknown, and misreporting known options with invalid arguments (e.g., `--default` without a value) as "unknown option" instead of showing the appropriate error message. The fix is accompanied by new test cases in `t/t4201-shortlog.sh`.

In recent discussion, Peff clarified two minor points raised by the original reporter, Kristoffer Haugsbakk: `.mailmap` entries don’t apply to commit trailers (so Kristoffer’s preferred email won’t appear in `Reported-by` lines), and the new test case’s purpose is to serve as a regression guard rather than self-documenting code. Neither point affects the patch’s technical content or merge status. The series is now ready for integration.
