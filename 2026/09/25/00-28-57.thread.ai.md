Thread identity
Subject: regression: `git shortlog` shows `(null)` for unknown options
Series version: standalone patch series (2 patches)
Originating author: Kristoffer Haugsbakk (bug report); Jeff King (Peff) (fix series)
Thread type: bug report and fix

Core problem or goal
A regression in error reporting causes `git shortlog` and other revision commands to display `(null)` instead of the actual unknown option name (e.g., `--not-an-option`) when an invalid option is provided. The bug was introduced by commit cd439487 ("revision: manage memory ownership of argv in setup_revisions()", 2025-09-19) and persists across all current integration branches (`master`, `next`, `seen`). The root cause is that the error path in revision option parsing frees and nulls the `argv` entry before formatting the error message, leading to `error("unknown option `%s'", arg)` printing `(null)` when `arg` is NULL. A second, older latent bug was also uncovered: the code could misreport known-but-invalid options (e.g., `--max-count=foo`) as unknown due to similar memory management issues. A third, even older latent bug was identified: known options with invalid arguments (e.g., `--default` without a value) were incorrectly reported as "unknown option" instead of showing the earlier error message (e.g., "bad --default argument").

Current status
Under review. The issue is confirmed via bisection and a simple reproduction case (`git shortlog -n --not-an-option master`). Jeff King (Peff) has proposed a two-patch series:
1. A minimal fix for the latent "misreported invalid options" bug, changing `if (n <= 0)` to `if (n < 0)` in `parse_revision_opt()` to distinguish between malformed options (negative return from `handle_revision_opt()`) and truly unknown options (zero return). The patch also adds a test case to `t/t4201-shortlog.sh` to verify the fix.
2. A broader fix restoring a pre-cd439487 assumption by conditionally nulling `*value` only when `opt->free_removed_argv_elements` is set, addressing both the `(null)` regression and the latent "misreported invalid options" bug. Peff provided a detailed commit message for the second patch to justify the broader change. No objections or alternative proposals have been raised yet.

Key technical details
- **Files/subsystems touched**: `revision.c` (option parsing logic in `setup_revisions()` and `parse_revision_opt()`), `t/t4201-shortlog.sh` (new test cases).
- **New/renamed symbols**: None.
- **Behavior change**: Error messages for unknown options now show the correct option name (e.g., `--not-an-option`) instead of `(null)`. Known-but-invalid options (e.g., `--max-count=foo`) are now correctly reported as invalid rather than unknown. Known options with invalid arguments (e.g., `--default`) now show the earlier error message (e.g., "bad --default argument") instead of being misreported as unknown.
- **On-disk format changes**: None.
- **Test coverage**: A new test case in `t/t4201-shortlog.sh` verifies the fix for the latent "misreported invalid options" bug. The `(null)` regression and the broader latent bug are covered implicitly by the second patch but lack explicit test coverage.
