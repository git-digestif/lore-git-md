Subject: regression: `git shortlog` shows `(null)` for unknown options
Series version: standalone patch (not part of a multi-patch series)
Originating author: Kristoffer Haugsbakk
Thread type: bug report

Core problem or goal
A regression in error reporting causes `git shortlog` (and other revision commands) to display `(null)` instead of the actual unknown option name when an invalid option (e.g., `--not-an-option`) is provided. The bug was introduced by commit cd439487 ("revision: manage memory ownership of argv in setup_revisions()", 2025-09-19) and persists across all current integration branches (`master`, `next`, `seen`). The root cause is that the error path in revision option parsing frees and nulls the `argv` entry before formatting the error message, leading to `error("unknown option `%s'", arg)` printing `(null)` when `arg` is NULL.

Current status
Under review. The issue is confirmed via bisection and a simple reproduction case (`git shortlog -n --not-an-option master`). No patch has been posted yet, but the fix is expected to be small and uncontroversial, likely involving reordering the free-and-null operation to occur after the error message is generated. The bug affects user-facing error messages, increasing its visibility.

Key technical details
- **Files/subsystems touched**: `revision.c` (specifically the option parsing logic in `setup_revisions()`).
- **New/renamed symbols**: None.
- **Behavior change**: Error messages for unknown options now show `(null)` instead of the option name.
- **On-disk format changes**: None.
- **Test coverage**: The reproduction case is trivial and will likely be added to the test suite as part of the fix.
