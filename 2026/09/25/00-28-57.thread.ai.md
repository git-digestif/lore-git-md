Thread identity
Subject: regression: `git shortlog` shows `(null)` for unknown options
Series version: standalone patch series (2 patches)
Originating author: Kristoffer Haugsbakk (bug report); Jeff King (Peff) (fix series)
Thread type: bug report and fix

Core problem or goal
A regression in error reporting causes `git shortlog` and other revision commands to display `(null)` instead of the actual unknown option name (e.g., `--not-an-option`) when an invalid option is provided. The bug was introduced by commit cd439487 ("revision: manage memory ownership of argv in setup_revisions()", 2025-09-19) and persists across all current integration branches (`master`, `next`, `seen`). The root cause is that the error path in revision option parsing frees and nulls the `argv` entry before formatting the error message, leading to `error("unknown option `%s'", arg)` printing `(null)` when `arg` is NULL. Two latent bugs were also uncovered: (1) known-but-invalid options (e.g., `--max-count=foo`) were misreported as unknown due to similar memory management issues, and (2) known options with invalid arguments (e.g., `--default` without a value) were incorrectly reported as "unknown option" instead of showing the earlier error message (e.g., "bad --default argument").

Current status
Under review. The issue is confirmed via bisection and a simple reproduction case (`git shortlog -n --not-an-option master`). Jeff King (Peff) has proposed a two-patch series that fully addresses the regression and both latent bugs:
1. A minimal fix for the latent "misreported invalid options" bug, changing `if (n <= 0)` to `if (n < 0)` in `parse_revision_opt()` to distinguish between malformed options (negative return from `handle_revision_opt()`) and truly unknown options (zero return). The patch also adds a test case to `t/t4201-shortlog.sh` to verify the fix.
2. A broader fix restoring a pre-cd439487 assumption by conditionally nulling `*value` only when `opt->free_removed_argv_elements` is set, and modifying `parse_revision_opt()` to look for the unknown option in the consolidated destination (`ctx->out[ctx->cpidx - 1]`) rather than the original, now-NULL location (`ctx->argv[0]`). This patch addresses the `(null)` regression and the latent "misreported invalid options" bug, and includes a test case to verify unknown options are reported correctly.

Key technical details
- **Files/subsystems touched**: `revision.c` (option parsing logic in `setup_revisions()` and `parse_revision_opt()`), `t/t4201-shortlog.sh` (new test cases).
- **New/renamed symbols**: None.
- **Behavior change**: Error messages for unknown options now show the correct option name (e.g., `--not-an-option`) instead of `(null)`. Known-but-invalid options (e.g., `--max-count=foo`) are now correctly reported as invalid rather than unknown. Known options with invalid arguments (e.g., `--default`) now show the earlier error message (e.g., "bad --default argument") instead of being misreported as unknown.
- **On-disk format changes**: None.
- **Test coverage**: New test cases in `t/t4201-shortlog.sh` verify the fix for the latent "misreported invalid options" bug and the correct reporting of unknown options. The broader latent bug (misreported known options with invalid arguments) is covered implicitly by the second patch but lacks explicit test coverage.
