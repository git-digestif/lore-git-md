Subject: [PATCH 0/2] replay: add commit signing support via -S
Series version: v1 (initial submission)
Originating author: Patrick Monette
Thread type: patch series

Core problem or goal
Add GPG commit signing support to `git replay` via a new `-S` option, addressing a latent error-handling flaw in `pick_regular_commit()` and aligning the command with other Git commands that support signing. The series explicitly ignores `commit.gpgSign` to maintain plumbing command consistency (user configuration should not alter behavior).

Current status
Under review; no prior versions. Two patches:
1. Fixes error handling in `pick_regular_commit()` to propagate signing-related failures by ensuring `result->clean` is set to -1 (error) when commit creation fails (e.g., due to signing issues). The patch introduces a temporary variable `new_commit` to hold the result of `create_commit()` and checks for NULL before proceeding. **Reviewed-by: Patrick Steinhardt** (substantive, confirms correctness of the error propagation logic; no additional concerns raised).
2. Adds the `-S`/`--gpg-sign` and `--no-gpg-sign` CLI options, updates documentation, and introduces comprehensive test coverage in `t/t3651-replay-gpg-sign.sh`. The test script verifies signing behavior (default and specified keys), `--no-gpg-sign` override, `commit.gpgSign` ignorance, and failure modes (e.g., invalid key, `--ref` rollback on failure). **Merge conflict risk**: Patrick Steinhardt flags a potential conflict with Tian Yuchen’s in-flight `git history` signing series ([20260912160045.360064-1-git@5ouma.me](https://lore.kernel.org/git/20260912160045.36064-1-git@5ouma.me)), which touches overlapping commit-creation logic. Steinhardt recommends rebasing this series after the `git history` work lands.

Open questions and loose ends
- **Policy choice**: Whether `git replay` should respect `commit.gpgSign` (currently ignored). The series justifies the omission as plumbing command consistency, but Steinhardt’s review of patch 2 suggests this may warrant further discussion. No consensus yet; author has not responded.
- **Error propagation**: Patch 1’s fix is approved by Steinhardt, but the absence of explicit "LGTM" leaves patch 1’s approval status pending further confirmation. No other edge cases (e.g., partial signing failures) have been raised.
- **Integration timing**: The series must be rebased after Tian Yuchen’s `git history` signing series merges to resolve shared commit-creation logic conflicts. No substantive changes to the patches are implied, but the author has not yet acknowledged this requirement.

Key technical details
- **Files touched**: `replay.c` (patch 1), `builtin/replay.c`, `replay.h`, `Documentation/git-replay.adoc`, `t/meson.build`, new test script `t/t3651-replay-gpg-sign.sh`.
- **New CLI options**: `-S`/`--gpg-sign` (mirrors `git commit -S`), `--no-gpg-sign` (overrides earlier `--gpg-sign`).
- **Behavior change**: Commit signing is opt-in via `-S`; `commit.gpgSign` is ignored (plumbing command consistency).
- **Error handling**: Patch 1 ensures failures during commit creation (including signing failures) propagate correctly by setting `result->clean = -1` when `create_commit()` returns NULL. Patch 2 relies on this fix to handle signing failures (e.g., missing GPG key).
- **Test coverage**: Dedicated test script covers signing with default/specified keys, `--no-gpg-sign` override, `commit.gpgSign` ignorance, and edge cases (e.g., invalid key, `--ref` rollback on failure).
- **Conflict risk**: Shared commit-creation logic (likely `commit.c`/`commit.h` and `gpg-interface.c`) with Tian Yuchen’s `git history` signing series.
