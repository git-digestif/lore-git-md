This is a small feature patch for the `git-contacts` contrib script, now in its fourth iteration. The patch teaches `git-contacts` to read patch content from stdin when the user passes `-` as an argument, enabling mixed file/stdin usage (e.g., `git contacts patch1 - patch3 <patch2`). This version implements the `-` idiom as suggested by Junio C Hamano and removes any implication that the script processes arguments in a predictable order, addressing the last open technical point from the review.

The change is minimal and localized: it adds a `$read_from_stdin` flag set when `-` is encountered in `@ARGV`, then calls the existing `scan_patches()` helper with the stdin filehandle. The implementation avoids the implicit stdin detection (`-t STDIN` check) used in earlier versions, making the behavior more explicit and interoperable with external tools like `b4`. The commit message now clearly states that the script does not guarantee deterministic output order for the same input files, and the usage comment has been reverted to its pre-v2 text since the `-` idiom is self-documenting.

This patch is part of a cross-project effort (linked in the commit message) but is actionable on its own. The author has incorporated all feedback from the maintainer except for a structural alternative Junio proposed—eliminating the `$read_from_stdin` flag by treating `-` as a special filename in `scan_patch_file`—which remains unaddressed in this version. The feature itself is uncontroversial and appears ready for merging once the design question is resolved.

The patch touches only `contrib/contacts/git-contacts`, introduces no new CLI options or on-disk format changes, and carries no test coverage, though the simplicity of the change reduces the risk of regression. It’s a clean, well-motivated improvement that aligns with UNIX conventions and improves workflow flexibility.
