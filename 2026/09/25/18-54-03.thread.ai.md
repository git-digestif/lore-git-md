Subject: [PATCH v2] ci: improve leak sanitizer failure reporting in GitHub Actions

Originating author: Harald Nordgren
Thread type: patch (CI/build system improvement)

Core problem or goal
Git’s GitHub Actions CI buries leak sanitizer failures and regular test failures at the end of test runs, producing only a generic “Process completed with exit code 1” message. The series originally proposed two focused commits: the first stops leak-sanitizer scripts at the first failure (using `--immediate`) and annotates leaks with the test script name and full sanitizer output in a collapsible log group; the second ensured regular test failures and fixed known breakages also point to their exact file and line in the test script. The goal remains to provide actionable failure annotations while balancing early failure (simpler debugging) and comprehensive reporting (catching all leaks), but the second patch is now abandoned due to a critical usability regression.

Current status
The first patch (1/2) is **cooking in `next`** and remains viable for graduation to `master`; the second patch (2/2) is **abandoned** after Phillip Wood’s formal recommendation. The regression—annotation links that only work if the test file was modified in the same pull request—is deemed a show-stopper. No further iteration is planned unless a fallback mechanism (e.g., preserving job-output links) is proposed. Junio’s earlier approval is now scoped to the first patch only.

Key technical details
Files touched: `ci/lib.sh` (adds `--immediate` to `GIT_TEST_OPTS` for leak sanitizer jobs), `t/test-lib-github-workflow-markup.sh` (new functions: `github_annotation_`, `finalize_test_leak_output`, `github_markup_script_name`; **only `github_annotation_` and `finalize_test_leak_output` remain relevant**), `t/test-lib.sh` (reorders annotation logic to ensure failures are reported even with `--immediate`).
New symbols: `github_annotation_`, `finalize_test_leak_output` (retained); `github_markup_script_name`, `find_test_case_line_` (abandoned).
Behavior change: test script now stops on first leak failure (`--immediate`) and emits GitHub Actions annotations with the test script name (line 1) and full leak sanitizer output in a collapsible log group. The reordering of `test_failure_()` ensures annotations are written before any `--immediate` exit. The `--immediate` trade-off avoids polluting the output with duplicate "not ok" reports from later tests that inherit the same sanitizer log entries. **Abandoned feature**: precise annotation links to test-script lines, which were useless unless the test file was modified in the pull request. No on-disk format changes; test coverage is implicit in the CI workflow.

Open questions and loose ends
1. **Broken annotation links (resolved by abandonment)**: The second patch’s annotation links were **useless or broken** unless the test file was modified in the same pull request. Phillip Wood’s live examples demonstrated the regression, and he formally recommended dropping the patch. No fallback mechanism (e.g., linking to job output) was proposed or discussed.
2. **Dynamic test descriptions (low priority)**: The line-finding logic in the abandoned patch failed for dynamically generated test descriptions (e.g., `test_expect_success "case $i: $desc" ...`), where the fallback to line 1 was acknowledged but not addressed. This is now moot.
3. **UI presentation (low priority)**: Phillip Wood’s suggestion to consolidate test output and leak output into a single collapsible section in the GitHub Actions UI remains open but is not blocking. The current implementation separates them.
4. **Principled trade-off for `--immediate` (low priority)**: Phillip Wood’s request for a principled justification or alternative approach to stopping at the first leak remains open. The current approach is pragmatic (avoiding false "not ok" reports) but may hide subsequent distinct leaks.
5. **Commit message clarity (low priority)**: Phillip Wood’s critique about the lack of concrete annotation format examples in the commit messages remains unresolved for the abandoned patch. The first patch’s commit message is unaffected.
