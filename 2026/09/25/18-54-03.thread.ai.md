Subject: [PATCH] ci: improve leak sanitizer failure reporting in GitHub Actions
Series version: standalone patch (no series)
Originating author: Harald Nordgren
Thread type: patch (CI/build system improvement)

Core problem or goal
Git’s GitHub Actions CI currently buries leak sanitizer failures at the end of test runs, producing only a generic “Process completed with exit code 1” message. The patch aims to stop the test script at the first leak failure and emit GitHub Actions annotations that point directly to the failing test file and line, including the actual leak error message. The goal has expanded to address trade-offs between early failure (simpler debugging) and comprehensive reporting (catching all leaks), as well as unintended side effects on CI usability (e.g., scrolling behavior in the GitHub Actions UI).

Current status
Under review; no prior versions. The patch remains self-contained but has attracted substantive technical feedback. Harald Nordgren has agreed to reorder helper functions for readability (as suggested by Ben Knoble) but has not yet addressed Phillip Wood’s concerns about the `--immediate` flag or the GitHub Actions UI regression. No Reviewed-by or Acked-by trailers have been added.

Key technical details
Files touched: `ci/lib.sh` (adds `--immediate` to `GIT_TEST_OPTS` for leak sanitizer jobs), `t/test-lib-github-workflow-markup.sh` (new functions: `escape_message`, `find_test_case_line`, `generate_github_annotation`), `t/test-lib.sh` (no-op stub for `finalize_test_leak_output`).
New symbols: `escape_message`, `find_test_case_line`, `generate_github_annotation`, `finalize_test_leak_output`, `github_escape_message_`, `find_test_case_line_`, `github_annotation_`.
Behavior change: test script now stops on first leak failure (`--immediate`) and emits GitHub Actions annotations with file, line number, and the first 40 lines of leak sanitizer output. The new output format may cause unintended scrolling behavior in Firefox.
No on-disk format changes; test coverage is implicit in the CI workflow.

Open questions and loose ends
1. **Trade-off between early failure and comprehensive reporting**: Is stopping at the first leak failure (`--immediate`) the right choice, or should the patch aim to report all leaks while still providing useful annotations?
2. **GitHub Actions UI regression**: The new output format causes strange scrolling behavior in Firefox, degrading the CI experience for other failures beyond leak sanitizer tests. This needs investigation and remediation.
3. **Lack of justification for new plumbing**: The commit message does not explain the necessity of the escaping logic (`github_escape_message_`) or line-finding logic (`find_test_case_line_`), making the patch harder to review.
4. **Helper function reordering**: Harald Nordgren has agreed to reorder `escape_message`, `find_test_case_line`, and `generate_github_annotation` before their use in `finalize_test_leak_output` for readability, but this change is not yet implemented.
