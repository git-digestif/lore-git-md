Subject: [PATCH v2] ci: improve leak sanitizer failure reporting in GitHub Actions
Series version: v2 (two-patch series)
Originating author: Harald Nordgren
Thread type: patch (CI/build system improvement)

Core problem or goal
Git’s GitHub Actions CI buries leak sanitizer failures and regular test failures at the end of test runs, producing only a generic “Process completed with exit code 1” message. The series splits the improvement into two focused commits: the first stops leak-sanitizer scripts at the first failure (using `--immediate`) and annotates leaks with the test script name and full sanitizer output in a collapsible log group; the second ensures regular test failures and fixed known breakages also point to their exact file and line in the test script. The goal is to provide actionable failure annotations while balancing early failure (simpler debugging) and comprehensive reporting (catching all leaks), and to avoid unintended side effects on CI usability (e.g., scrolling behavior in the GitHub Actions UI).

Current status
Under review; v2 posted. The series is split into two commits:
1. Leak sanitizer improvements (stop at first leak, full output in collapsible group).
2. Regular test failure annotations (exact file and line).
Harald Nordgren has addressed Phillip Wood’s concerns about output truncation and Firefox scrolling by removing the giant unfolded annotation and showing full leak output. The commit messages now explain the reasoning behind `--immediate` and escaping logic. The second patch adds two new helper functions (`github_escape_message_` and `find_test_case_line_`) to locate and annotate the exact line of failing tests, using literal string matching to avoid regex misinterpretation. Junio C Hamano has identified three correctness, portability, and consistency issues in the second patch: (1) the annotation logic for test failures is skipped when `--immediate` is set *and* `invert_exit_code` is set, due to an early `exit 0` path that bypasses the annotation logic, (2) the patch introduces a portability risk by feeding the two-letter sequence `\r` to `sed`, which may not be interpreted as a carriage return on BSD-derived systems, and (3) an inconsistency in output redirection style that breaks the surrounding script’s visual pattern. Harald Nordgren has acknowledged the first issue and signaled intent to fix it by reordering the exit paths in `test_failure_()` to ensure `finalize_test_case_output` is called before any `--immediate` exit, regardless of `invert_exit_code`.

Key technical details
Files touched: `ci/lib.sh` (adds `--immediate` to `GIT_TEST_OPTS` for leak sanitizer jobs), `t/test-lib-github-workflow-markup.sh` (new functions: `github_annotation_`, `finalize_test_leak_output`, `github_markup_script_name`, `github_escape_message_`, `find_test_case_line_`), `t/test-lib.sh` (reorders annotation logic to ensure failures are reported even with `--immediate`).
New symbols: `github_annotation_`, `finalize_test_leak_output`, `github_markup_script_name`, `github_escape_message_`, `find_test_case_line_`.
Behavior change: test script now stops on first leak failure (`--immediate`) and emits GitHub Actions annotations with file, line number, and full leak sanitizer output in a collapsible log group. Regular test failures also generate annotations pointing to the exact test script line, using literal string matching to avoid regex edge cases. No on-disk format changes; test coverage is implicit in the CI workflow.

Open questions and loose ends
1. **Helper function justification and ordering**: The commit messages now explain the escaping logic and `--immediate` trade-off, but the range-diff suggests `find_test_case_line_` and other helpers could still use more detailed justification. The helper functions in `t/test-lib-github-workflow-markup.sh` may also need reordering for readability (as previously suggested by Ben Knoble).
2. **Principled trade-off for `--immediate`**: Harald Nordgren has clarified the practical benefits of stopping at the first leak (avoiding false "not ok" reports), but Phillip Wood’s request for a principled justification or alternative approach remains unresolved. The current approach is pragmatic but may not satisfy all reviewers.
3. **Annotation logic correctness**: The interaction between `--immediate` and `invert_exit_code` is acknowledged and will be fixed by reordering the exit paths in `test_failure_()` to ensure `finalize_test_case_output` is called before any `--immediate` exit, regardless of `invert_exit_code`.
4. **Portability of `\r` in `sed`**: Junio’s review raises a cross-platform concern: the two-letter sequence `\r` may not be interpreted as a carriage return on BSD-derived `sed` implementations. The escaping logic must be made portable across all supported platforms.
5. **Output redirection consistency**: The patch changes a `test-tool` invocation to redirect output at the end of the command line, breaking the surrounding code’s pattern of early redirection. This stylistic inconsistency should be resolved for maintainability.
