Subject: [PATCH v2] ci: improve leak sanitizer failure reporting in GitHub Actions

Core problem or goal
Git’s GitHub Actions CI buries leak sanitizer failures and regular test failures at the end of test runs, producing only a generic “Process completed with exit code 1” message. The series improves this by (1) stopping leak-sanitizer scripts at the first failure (`--immediate`) and annotating leaks with the test script name and full sanitizer output in a collapsible log group, and (2) embedding file name and line number directly in failure annotations as plain text (e.g., `failed: t1060.17 partial clone of corrupted repository (t1060-object-corruption.sh:141)`). This avoids the earlier regression where annotation links only worked if the test file was modified in the same pull request, while still providing more context than the current behavior.

Key technical details
Files touched: `ci/lib.sh` (adds `--immediate` to `GIT_TEST_OPTS` for leak sanitizer jobs), `t/test-lib-github-workflow-markup.sh` (new functions: `github_annotation_`, `finalize_test_leak_output`, `find_test_case_line_`, `github_markup_script_name`), `t/test-lib.sh` (reorders annotation logic to ensure failures are reported even with `--immediate`). New symbols: `github_annotation_`, `finalize_test_leak_output`, `find_test_case_line_`, `github_markup_script_name`. Behavior change: test script now stops on first leak failure (`--immediate`) and emits GitHub Actions annotations with the test script name (line 1) and full leak sanitizer output in a collapsible log group. The second patch adds file/line context to failure annotations as plain text by searching the test script for the test description using `grep -F` and appending the file and line (e.g., `(t1060-object-corruption.sh:141)`). The fallback behavior for dynamically generated test descriptions (e.g., `test_expect_success "case $i: $desc"`) defaults to the script name only. The reordering of `test_failure_()` ensures annotations are written before any `--immediate` exit. No on-disk format changes; test coverage remains implicit in the CI workflow.

Open questions and loose ends
1. **Broken annotation links (resolved)**: The original second patch’s annotation links were **useless or broken** unless the test file was modified in the same pull request. Harald’s compromise embeds file/line context in the annotation text while preserving job-output links, resolving this issue. **Phillip Wood has accepted the compromise**.
2. **Dynamic test descriptions (low priority)**: The line-finding logic may fail for dynamically generated test descriptions (e.g., `test_expect_success "case $i: $desc" ...`), falling back to line 1. This is acknowledged but not addressed; not blocking.
3. **UI presentation (low priority)**: Phillip Wood’s suggestion to consolidate test output and leak output into a single collapsible section in the GitHub Actions UI remains open but is not blocking.
4. **Principled trade-off for `--immediate` (low priority)**: Phillip Wood’s request for a principled justification or alternative approach to stopping at the first leak remains open. The current approach is pragmatic (avoiding false "not ok" reports) but may hide subsequent distinct leaks.
