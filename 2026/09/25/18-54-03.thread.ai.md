Core problem or goal
Git’s GitHub Actions CI buries leak sanitizer failures and regular test failures at the end of test runs, producing only a generic “Process completed with exit code 1” message. The series splits the improvement into two focused commits: the first stops leak-sanitizer scripts at the first failure (using `--immediate`) and annotates leaks with the test script name and full sanitizer output in a collapsible log group; the second ensures regular test failures and fixed known breakages also point to their exact file and line in the test script. The goal is to provide actionable failure annotations while balancing early failure (simpler debugging) and comprehensive reporting (catching all leaks), and to avoid unintended side effects on CI usability (e.g., scrolling behavior in the GitHub Actions UI).

Key technical details
Files touched: `ci/lib.sh` (adds `--immediate` to `GIT_TEST_OPTS` for leak sanitizer jobs), `t/test-lib-github-workflow-markup.sh` (new functions: `github_annotation_`, `finalize_test_leak_output`, `github_markup_script_name`, `github_escape_message_`, `find_test_case_line_`), `t/test-lib.sh` (reorders annotation logic to ensure failures are reported even with `--immediate`).
New symbols: `github_annotation_`, `finalize_test_leak_output`, `github_markup_script_name`, `github_escape_message_`, `find_test_case_line_`.
Behavior change: test script now stops on first leak failure (`--immediate`) and emits GitHub Actions annotations with the test script name (line 1) and full leak sanitizer output in a collapsible log group. The reordering of `test_failure_()` ensures annotations are written before any `--immediate` exit, preventing them from being silently dropped. The second patch replaces generic annotations with precise, clickable links pointing to the exact line in the test file where the failure or fixed breakage occurred. The `--immediate` trade-off is explicitly justified in the commit message: it avoids polluting the output with duplicate "not ok" reports from later tests that inherit the same sanitizer log entries. No on-disk format changes; test coverage is implicit in the CI workflow.

Open questions and loose ends
1. **Clickable links in GitHub UI**: The lack of clickable links in the GitHub Actions UI remains unresolved. Harald’s proof-of-concept CI run confirms the issue, but the annotation format or GitHub’s parser may need adjustment to resolve this. This is a critical gap in the patch’s functionality.
2. **Dynamic test descriptions**: The line-finding logic fails for dynamically generated test descriptions (e.g., `test_expect_success "case $i: $desc" ...`), where the fallback to line 1 is acknowledged but not addressed. This remains an open design question.
3. **UI presentation**: Phillip Wood suggests consolidating test output and leak output into a single collapsible section in the GitHub Actions UI, rather than separating them, to improve usability. This remains an open usability refinement.
4. **Principled trade-off for `--immediate`**: Phillip Wood’s request for a principled justification or alternative approach to stopping at the first leak remains open. The current approach is pragmatic (avoiding false "not ok" reports) but may not fully address concerns about hiding subsequent distinct leaks.
