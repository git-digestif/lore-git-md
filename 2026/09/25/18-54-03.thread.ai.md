Subject: [PATCH v2] ci: improve leak sanitizer failure reporting in GitHub Actions

Originating author: Harald Nordgren
Thread type: patch (CI/build system improvement)

Core problem or goal
Git’s GitHub Actions CI buries leak sanitizer failures and regular test failures at the end of test runs, producing only a generic “Process completed with exit code 1” message. The series originally proposed two focused commits: the first stops leak-sanitizer scripts at the first failure (using `--immediate`) and annotates leaks with the test script name and full sanitizer output in a collapsible log group; the second aimed to ensure regular test failures and fixed known breakages also point to their exact file and line in the test script. The second patch was abandoned due to a critical usability regression (annotation links that only worked if the test file was modified in the same pull request), but Harald now proposes a compromise: embed the file name and line number directly in the annotation text while preserving job-output links, avoiding the regression while still providing more context than the current behavior.

Current status
The first patch (1/2) is **cooking in `next`** and remains viable for graduation to `master`. The second patch (2/2) is **abandoned in its original form**, but Harald’s new proposal seeks to salvage its usability improvements without reintroducing the regression. No merge status change has occurred; the first patch’s status is unchanged, and the second patch’s fate depends on Phillip Wood’s response to the compromise. No further iteration is planned unless the compromise is accepted or a new fallback is proposed.

Key technical details
Files touched: `ci/lib.sh` (adds `--immediate` to `GIT_TEST_OPTS` for leak sanitizer jobs), `t/test-lib-github-workflow-markup.sh` (new functions: `github_annotation_`, `finalize_test_leak_output`, `github_markup_script_name`; **only `github_annotation_` and `finalize_test_leak_output` remain relevant in the first patch**), `t/test-lib.sh` (reorders annotation logic to ensure failures are reported even with `--immediate`).
New symbols: `github_annotation_`, `finalize_test_leak_output` (retained in first patch); `github_markup_script_name`, `find_test_case_line_` (abandoned in original second patch, now proposed for revival in modified form).
Behavior change: test script now stops on first leak failure (`--immediate`) and emits GitHub Actions annotations with the test script name (line 1) and full leak sanitizer output in a collapsible log group. The reordering of `test_failure_()` ensures annotations are written before any `--immediate` exit. The `--immediate` trade-off avoids polluting the output with duplicate "not ok" reports from later tests that inherit the same sanitizer log entries.
**Proposed compromise**: Embed file name and line number directly in annotation text (e.g., `memory leak logged in t1060 (t1060-object-corruption.sh)` or `failed: t1060.17 partial clone of corrupted repository (t1060-object-corruption.sh:141)`) while preserving existing job-output links. This avoids the regression of broken annotation links when the test file is unmodified in the pull request. No on-disk format changes; test coverage remains implicit in the CI workflow.

Open questions and loose ends
1. **Broken annotation links (partially resolved)**: The original second patch’s annotation links were **useless or broken** unless the test file was modified in the same pull request. Phillip Wood’s live examples demonstrated the regression, and he formally recommended dropping the patch. Harald’s compromise addresses this by embedding the file/line context in the annotation text while preserving job-output links. **Pending Phillip Wood’s response**.
2. **Dynamic test descriptions (low priority)**: The line-finding logic in the abandoned patch failed for dynamically generated test descriptions (e.g., `test_expect_success "case $i: $desc" ...`), where the fallback to line 1 was acknowledged but not addressed. This remains moot unless the compromise is accepted and the logic is revived.
3. **UI presentation (low priority)**: Phillip Wood’s suggestion to consolidate test output and leak output into a single collapsible section in the GitHub Actions UI remains open but is not blocking. The current implementation separates them.
4. **Principled trade-off for `--immediate` (low priority)**: Phillip Wood’s request for a principled justification or alternative approach to stopping at the first leak remains open. The current approach is pragmatic (avoiding false "not ok" reports) but may hide subsequent distinct leaks.
5. **Commit message clarity (low priority)**: Phillip Wood’s critique about the lack of concrete annotation format examples in the commit messages remains unresolved for the abandoned patch. The compromise proposal includes examples, which may address this concern if accepted.
