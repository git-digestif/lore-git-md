This is the first patch in Harald Nordgren’s v3 series implementing the `remote.<name>.refmap`-based "matching-inspired" fetch mode for shallow repositories. It introduces the plumbing for the new `remote.<name>.refmap` configuration variable, which defines namespace mappings for fetched refs without specifying what to fetch.

The patch adds the `refmap` field to the `struct remote` in `remote.h` and extends `remote.c` to parse the new configuration key. The logic in `builtin/fetch.c` is updated to use the configured refmap as the default value for the `--refmap` command-line option, but only when there is an explicit refspec to fetch (matching the existing behavior of `--refmap`). Documentation is added to `config/remote.adoc` and `fetch-options.adoc` to explain the new configuration and its relationship to the `--refmap` option. The test in `t/t5510-fetch.sh` verifies that `remote.<name>.refmap` behaves identically to passing `--refmap` on the command line.

This is a foundational patch that enables the rest of the series. It is narrowly scoped, touching only the configuration parsing and refmap selection logic, and does not yet implement the dynamic branch enumeration or shallow-repository defaults. The implementation is clean and follows Git’s existing patterns for configuration handling. The test coverage is adequate for the added functionality, though the real edge cases (e.g., stale `HEAD`, empty repositories) will be addressed in later patches. No backward compatibility issues are introduced, as the new configuration is opt-in and only takes effect when explicitly set.
