This is the second patch in Harald Nordgren’s v3 series implementing the "matching-inspired" fetch mode for shallow repositories. It introduces the core logic that infers which branches to fetch when a remote has a `remote.<name>.refmap` configured but no `remote.<name>.fetch` refspec.

The patch dynamically enumerates branches to fetch by inspecting the `@{upstream}` configuration of local branches: if a local branch tracks a branch on the remote, that remote branch is included in the fetch. It also always fetches the remote’s default branch (resolved via `HEAD`), ensuring the remote’s primary branch is available even before any local branches are set up to track it. This addresses the performance problem in shallow repositories where a refspec-less fetch would otherwise negotiate history for every remote branch.

Key changes are in `builtin/fetch.c` and `remote.c`:
- `get_ref_map()` now accepts a `bootstrap_head_branch` out-parameter to communicate the remote’s default branch name back to the caller.
- When no explicit refspec is given and the remote has a refmap but no fetch refspec, the code builds a temporary refspec by iterating over local branches that track the remote (`branches_tracking_remote()` helper in `remote.c`) and appends the remote’s default branch.
- The `set_head()` function is updated to accept a pre-resolved default branch name, avoiding redundant `HEAD` resolution when the branch is already known.
- The `do_fetch()` function passes the inferred branch list to the transport’s `ls-refs` command, ensuring the server only advertises the branches that will actually be fetched.

The new test script `t/t5585-fetch-refmap.sh` verifies the dynamic branch selection: it confirms that only the default branch and branches tracked by local branches are fetched, that branches are not duplicated when multiple local branches track the same remote branch, and that branches tracking a different remote are ignored. The tests also check that `git remote show` does not choke on a refmap-only remote.

The implementation is clean and well-tested, with no obvious edge-case gaps beyond the open questions already noted in the thread (e.g., whether the mode should be available outside shallow repositories). The patch directly delivers the feature’s core value: shallow repositories can now fetch only the branches they actually use, without manual refspec management.
