This is the latest exchange in SZEDER Gábor’s four-patch series that adds precompiled headers to Git’s Makefile, targeting `git-compat-util.h` for a ~35 % build-time speed-up. The thread is now focused on a real-world edge case Jeff King (Peff) reported: when a target-specific `EXTRA_CPPFLAGS` (e.g., `-DNO_OPENSSL`) differs from the flags used to generate the precompiled header, the compiler emits a `-Winvalid-pch` warning.

SZEDER acknowledges the issue and explains why it didn’t surface in his testing: the `EXTRA_CPPFLAGS` set in the main Makefile don’t affect `git-compat-util.h`, but user-supplied flags like `-DNO_OPENSSL` do. He suggests a simple workaround—appending `-Wno-invalid-pch` to the custom `EXTRA_CPPFLAGS`—and notes that there’s no clean way to override the `-include precompiled.h` directive. The discussion then turns to Peff’s motivation: he disables OpenSSL for historical builds to avoid deprecated-API errors, and his config.mak uses target-specific flags to avoid breaking some older versions that still need OpenSSL. SZEDER shares a similar setup but hasn’t encountered the same breakage, and both agree that Peff’s use case is niche.

The upshot is that the precompiled-header machinery assumes uniform flags across most object files; when that assumption breaks, the warning is cosmetic but unavoidable without deeper Makefile surgery. SZEDER’s proposed workaround is pragmatic: if you deliberately set flags that affect `git-compat-util.h`, silence the warning yourself. No changes to the patch series are planned, and the series remains under review with no maintainer objections.
