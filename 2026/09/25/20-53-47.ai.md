This is a bugfix patch in the `git replay` series, specifically the first of two patches adding GPG signing support via the `-S` option. The patch addresses a latent error-handling flaw in `pick_regular_commit()` where a failure to create a commit (e.g., due to signing issues) would incorrectly leave `result->clean` set to 1 (success), causing the caller to treat the operation as successful despite returning NULL. The fix ensures that `result->clean` is set to -1 (error) when commit creation fails, enabling proper error propagation.

The change is minimal and targeted: it introduces a temporary variable `new_commit` to hold the result of `create_commit()`, checks for NULL, and updates `result->clean` accordingly. The patch touches only `replay.c` (6 insertions, 1 deletion) and is motivated by the upcoming addition of signing support in the next patch, which will introduce new failure modes during commit creation.
