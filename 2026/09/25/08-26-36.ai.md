This is a **bugfix** targeting the revision option parsing subsystem in `revision.c`. Jeff King (Peff) replies to Kristoffer Haugsbakk’s regression report with two proposed fixes for the `(null)` error message bug in `git shortlog` and other revision commands. The issue stems from commit cd439487, which altered memory ownership handling in `setup_revisions()` but inadvertently freed and nulled the `argv` entry before the error message could use it.

Peff’s first patch is a minimal fix: instead of referencing the now-NULL `ctx->argv[0]` in the error message, it uses `ctx->out[ctx->cpidx - 1]`, which still holds the original option string. The second patch is more ambitious, restoring a pre-cd439487 assumption by conditionally nulling `*value` only when `opt->free_removed_argv_elements` is set. This would address not just the immediate bug but any similar lurking issues in the same code path. Peff acknowledges the opacity of the second approach and promises a fuller explanation in a follow-up.

The fix is clearly scoped to `revision.c` and does not touch on-disk formats or introduce new symbols. Both patches are small and mechanical, suggesting low risk of unintended side effects. The regression affects user-facing error messages, making it more visible than typical internal bugs, but the reproduction case is trivial (`git shortlog -n --not-an-option master`). No objections or alternative proposals have surfaced yet, and the thread remains in early review. The coordination concern with the `jk/rev-info-argv-to-free` topic (mentioned in the thread summary) appears to be resolved by Peff’s direct involvement.
