This is the second patch in Harald Nordgren’s four-part v3 series implementing the "matching-inspired" fetch mode for shallow repositories. The patch teaches `git fetch` to infer which branches to fetch when a remote has a `remote.<name>.refmap` configured but no `remote.<name>.fetch` refspec. Instead of fetching every branch the remote has (the current behavior), it now fetches only the branches tracked by local branches at that remote, plus the remote’s default branch.

The core logic lives in `builtin/fetch.c`’s `get_ref_map()`: when no explicit refspec is given and the remote has no fetch refspec but does have a refmap, the code enumerates every local branch whose `@{upstream}` points to the remote, adds those branch names to an inferred refspec, and always includes the remote’s default branch (resolved from `HEAD`). The remote’s default branch is also passed back to `set_head()` so that `git remote set-head` can work without an extra round-trip. Documentation in `config/remote.adoc` and `fetch-options.adoc` is updated to explain the new behavior, and a new test script (`t/t5585-fetch-refmap.sh`) verifies the dynamic branch selection, edge cases (empty repositories, multiple tracking branches), and backward compatibility.

The implementation is clean and well-tested; the only open question is whether this mode should be available outside shallow repositories (the series currently defaults to it only in shallow repos). No controversial design choices remain—this patch simply carries out the consensus reached in the v2 discussion.
