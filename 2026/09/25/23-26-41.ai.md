This is the second patch in Harald Nordgren’s v3 series implementing the "matching-inspired" fetch mode for shallow repositories. Junio C Hamano’s review raises **substantive design concerns** about the patch’s core assumption: that the remote’s default branch (resolved via `HEAD`) should always be fetched, even when the user has no interest in it.

Junio argues that automatically fetching the remote’s default branch is **overly presumptive** and potentially wasteful. He gives two examples: a user working only on `maint` or `next` branches who has no use for `master`, and a user who already has a local branch tracking the remote’s default branch (making the automatic fetch redundant). He also notes that this feature is intended for secondary remotes, where the primary remote (e.g., `origin`) may already provide the default branch, making the automatic fetch doubly unnecessary.

The review suggests **removing the forced inclusion of the remote’s default branch** from the dynamic branch enumeration logic. This would simplify the code (eliminating the special-case handling of `HEAD` in `builtin/fetch.c`) and avoid the awkward fetch report output (`* [new ref] HEAD -> second/main` instead of `* [new branch] main -> second/main`). Junio’s tone implies this is not just a nit but a **fundamental design question** that could affect the feature’s usability and adoption.

The patch’s documentation (`fetch-options.adoc`) is also flagged for revision: the phrase "plus the remote's default branch, which is always included" should be removed if the forced inclusion is dropped. The current wording already reflects the design under review, so this change would be contingent on the outcome of the discussion.

No merge status is implied; the series remains under active review. The next step is likely a **v4 iteration** addressing Junio’s concerns, either by removing the forced default branch fetch or by providing a stronger rationale for keeping it. The thread’s earlier consensus on the `remote.<name>.refmap` design remains intact, but this patch’s core behavior is now in question.
