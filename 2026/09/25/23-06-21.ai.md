This is a refactoring patch targeting the `fetch.followRemoteHEAD` configuration handling in `builtin/fetch.c`. Colin Hinton’s v3 defers validation of the config setting until it is actually needed in `do_fetch()`, addressing feedback from Junio C Hamano and Matt Hunter. The patch now safely handles valueless truth settings (e.g., `fetch.followRemoteHEAD` with no value) by using `xstrdup_or_null(v)` and treating them as `FOLLOW_REMOTE_NEVER` with a warning at lazy-validation time.

The implementation introduces a `char *follow_remote_head_raw` field in `struct fetch_config` to store the raw config string and a helper function `get_follow_remote_head()` to parse it into the appropriate enum value when called in `do_fetch()`. This eliminates spurious warnings for fetches that never consult the setting while preserving the existing precedence rules (remote override vs. config fallback vs. default). The remote-side parser in `remote.c` remains unchanged in this version, as Colin notes the only substantive difference between local and remote parsers is the `warn-if-not-$branch` setting, which is remote-specific and not supported for `fetch.followRemoteHEAD`.

Key technical details include the new `follow_remote_head_raw` field, the lazy-validation helper function, and the use of `xstrdup_or_null(v)` to avoid segfaults on valueless truth settings. The patch does not change on-disk formats or test coverage, and it avoids introducing new behavior. The commit message clearly explains the motivation: avoiding irrelevant warnings for operations that never use the config value.

Open questions remain about whether to merge the remote-side parser refactoring into a follow-up patch and how to handle memory management for `follow_remote_head_raw` if multiple config definitions are encountered during lazy validation. Matt Hunter’s follow-up patch raises minor design questions, such as the awkward warning message for `remote.<name>.followRemoteHEAD` and the placement of the enum definition, but these do not block the current refactoring. The patch is well-crafted and addresses a real problem, making it worth attention for reviewers focused on fetch plumbing or config handling.
