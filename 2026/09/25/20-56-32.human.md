This is a bugfix patch targeting the packfile subsystem. It addresses a real-world problem where orphaned temporary pack files accumulate on disk when `git gc` or `git maintenance` processes are killed mid-operation, potentially exhausting disk space in environments like Kubernetes pods running Gitea.

The patch itself is small and focused: it registers temporary pack files (created via `odb_mkstemp()` in `pack-write.c` and `pack-bitmap-write.c`) with Git's tempfile subsystem, ensuring they are automatically cleaned up when the process exits gracefully. The author notes that `git repack` already handles this correctly, and the fix simply extends that behavior to the lower-level code paths used by `git gc` and `git maintenance`.

The commit message is unusually thorough for a first-time contributor. It includes concrete measurements from production (224 GiB recovered in one case), explains why the existing temp files are safe to remove, and traces the historical context of the tempfile subsystem. The absence of tests is justified by the self-evident nature of the fix and reliance on existing tempfile subsystem coverage.

This looks like a well-motivated, low-risk fix that addresses a genuine pain point. The patch touches only two files and makes minimal changes, suggesting it’s unlikely to introduce regressions. If you care about disk space management or run Git in containerized environments, this is worth reviewing.
