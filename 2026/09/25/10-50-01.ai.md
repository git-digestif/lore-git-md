This is the third patch in Harald Nordgren’s v3 series implementing the `remote.<name>.refmap`-based "matching-inspired" fetch mode. It adds a `--limited-fetch` flag to `git remote add` that explicitly opts a new remote into the new fetch behavior: instead of tracking all remote branches via a wildcard `remote.<name>.fetch` refspec, the remote is configured with `remote.<name>.refmap` so that a refspec-less `git fetch` only fetches the branches already tracked by local branches plus the remote’s default branch.

The patch touches `builtin/remote.c` to add the new flag, updates the documentation in `Documentation/git-remote.adoc` to explain the option, and adds two tests in `t/t5505-remote.sh` that verify the flag works in non-shallow repositories and correctly rejects incompatible combinations (`-t/--track` or `--mirror`). The implementation is straightforward: when `--limited-fetch` is given and neither `-t` nor `--mirror` is present, the code writes a single `remote.<name>.refmap` entry (`+refs/heads/*:refs/remotes/<name>/*`) instead of the usual wildcard `remote.<name>.fetch` refspec.

This patch is a clean, well-scoped addition that fits neatly into the series’ overall design. The commit message and documentation are clear, the error handling is sensible, and the tests cover the main success and failure cases. There are no obvious loose ends or edge cases left unaddressed in this specific patch; any remaining open questions (e.g., whether the new mode should be available outside shallow repositories) are design-level concerns that belong to the series as a whole rather than to this individual change. The patch looks ready for review and is unlikely to generate controversy.
