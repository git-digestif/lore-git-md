This thread introduces GPG commit signing support to `git replay` via a new `-S` option, authored by Patrick Monette. The series consists of two patches: the first fixes a latent error-handling bug in `pick_regular_commit()` to ensure signing failures propagate correctly, and the second adds the `-S`/`--gpg-sign` CLI options with comprehensive test coverage. Patrick Steinhardt reviewed the first patch, confirming the error-handling fix, but raised a design question about whether `git replay` should ignore `commit.gpgSign` (a policy choice the author justified as plumbing command consistency). No consensus has emerged on this point yet.

The series is now blocked on Tian Yuchen’s in-flight `git history` signing series, which touches overlapping commit-creation logic. Both Patrick Steinhardt and Junio Hamano have endorsed waiting for that work to land before proceeding, though the author hasn’t yet acknowledged this requirement. The error-handling fix in patch 1 is effectively approved, but the second patch’s policy choice remains open. No substantive changes are expected—just a routine rebase once the `git history` series merges. The thread is otherwise quiet, with no new technical objections or edge cases raised.
