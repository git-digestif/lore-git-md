This thread introduces GPG commit signing support to `git replay` via a new `-S` option, submitted by Patrick Monette as a two-patch series. The first patch fixes a latent error-handling bug in `pick_regular_commit()` to ensure signing failures propagate correctly, while the second adds the `-S` option, updates documentation, and includes comprehensive test coverage.

The series is under initial review and remains uncontroversial. The design explicitly ignores `commit.gpgSign` to maintain plumbing command consistency, and the test script verifies signing behavior, key selection, and error cases (e.g., missing GPG keys, ref rollback on failure). No objections or open questions have been raised yet, but reviewers may scrutinize whether the error propagation in the first patch covers all edge cases. The series is self-contained and aligns with the `replay` command introduced in Git 2.46. Key participants expected to review include Phillip Wood (replay subsystem) and Christian Couder (GPG signing).
