This is a bugfix patch for the Git protocol v2 `upload-pack` subsystem, addressing a client-side crash during shallow fetches when `uploadpack.allowRefInWanted` is enabled. The issue occurs because the server sends "wanted-ref" information before "shallow-info", but the client expects "shallow-info" first and crashes with `fatal: expected 'packfile', received 'shallow-info'` when it encounters the sections out of order.

The fix is minimal and surgical: it swaps the order of two function calls in `upload_pack_v2()` so that `send_shallow_info()` runs before `send_wanted_ref_info()`. The patch includes two new test cases in `t/t5703-upload-pack-ref-in-want.sh` that verify both a single-commit shallow clone and a subsequent two-commit incremental fetch work correctly with the new ordering. The commit message now clearly explains the failure mode, the technical rationale (client-side `peek` logic in `process_section_header()` skips unexpected sections), and confirms backward compatibility since this feature combination never worked in production.
