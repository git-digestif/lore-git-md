This thread is about a small but long-standing bug in Git’s Windows ANSI emulation layer, where a formatting error in `compat/winansi.c:die_lasterr()` caused Windows API failure messages to display the address of a `va_list` instead of the intended integer handle. Yongqiang Tian proposed the fix, which has gone through four iterations—each refining the approach based on feedback from Johannes Sixt, René Scharfe, and Junio C Hamano.

The current version (v4) removes the problematic helper function entirely, inlines the Windows-specific error handling, and aligns the output with Git’s existing Windows diagnostic style. Junio has reviewed the latest version and found no technical issues, requesting only minor commit message improvements. The only remaining discussion is cosmetic—whether the error message should use "Windows error" or the current phrasing—but this isn’t considered a blocker. The patch is now effectively ready for integration and is a strong candidate for `next`.

Key participants include Yongqiang Tian (author), Junio C Hamano (maintainer), Johannes Sixt (who proposed removing the variadic argument and later endorsed the inlined approach), and René Scharfe (who suggested a macro-based alternative). The fix is narrow in scope, touching only `compat/winansi.c`, and doesn’t introduce new symbols or change on-disk behavior. No test coverage was added, but the fix has been verified manually and through builds with `DEVELOPER=1` under MinGW GCC 13.
