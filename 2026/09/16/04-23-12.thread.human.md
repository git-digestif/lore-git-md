This thread is about a long-standing Windows-specific bug in Git’s ANSI emulation layer, where a helper function (`die_lasterr()`) incorrectly displayed the address of a `va_list` instead of the intended integer handle when reporting Windows API failures. Yongqiang Tian’s latest patch removes the problematic helper entirely, replacing its four call sites with direct `die()` calls that report the raw `GetLastError()` value and the handle (formatted as `%li`). This approach avoids `va_list` forwarding, heap allocation, and POSIX `errno` conversion, aligning with existing Windows-specific error reporting in Git.

The patch has evolved through four iterations, with input from Johannes Sixt (who initially objected to the variadic design and later endorsed the inlined approach) and René Scharfe (who proposed a macro-based alternative). The current version addresses all technical objections, leaving only minor cosmetic tweaks—such as the phrasing of the error message—to resolve. Johannes Sixt has already approved the core approach, and the patch is now effectively ready for integration into Junio’s `next` branch. The change is minimal (19 lines total), self-contained, and verified under MinGW GCC 13. No test coverage was added, as the bug is in a fatal-error helper that’s difficult to trigger deterministically.
