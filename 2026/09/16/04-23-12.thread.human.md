This thread is about a long-standing bug in Git’s Windows compatibility layer that causes error messages to display the wrong information when `DuplicateHandle()` fails. Yongqiang Tian sent a minimal patch to fix the issue in `compat/winansi.c`, where the `die_lasterr()` function was incorrectly formatting Windows API error messages, showing the address of a `va_list` instead of the intended integer handle.

The patch is under review, and three different approaches have now been proposed. Yongqiang’s original patch preserves the handle value in error messages using a `strbuf`. Johannes Sixt suggested removing the variadic argument entirely, arguing that the handle value isn’t useful for debugging. René Scharfe proposed a macro-based solution that forwards arguments directly to `die_errno()`, avoiding heap operations and `va_list` manipulation. The discussion has stalled on which approach is best—whether to prioritize diagnostic precision, code simplicity, or a Windows-specific solution that avoids POSIX `errno` conversion. No resolution has been reached yet, and the thread is awaiting further feedback from Patrick Steinhardt or Johannes Schindelin, the designated Windows platform reviewers. The patch remains small and self-contained, with no broader impact on other parts of Git.
