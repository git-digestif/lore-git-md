Subject: [PATCH] compat/winansi: fix die_lasterr() formatting bug
Series version: standalone patch
Originating author: Yongqiang Tian
Thread type: bugfix

Core problem or goal
Fix a long-standing formatting bug in `compat/winansi.c:die_lasterr()` that causes Windows API failure messages to display the address of a `va_list` instead of the intended integer handle when `DuplicateHandle()` fails. The bug has no effect on other callers, which pass fixed strings.

Current status
Under review; no prior versions. Patch is minimal (7 insertions, 2 deletions), self-contained, and targets only `compat/winansi.c`. Junio C Hamano (maintainer) has redirected the patch to Patrick Steinhardt and Johannes Schindelin for review. Four distinct approaches have now been proposed: the original patch (Yongqiang Tian), a variadic-removal refactor (Johannes Sixt), a macro-based simplification (René Scharfe), and now Sixt’s implied preference for a Windows-specific solution that avoids POSIX `errno` conversion. No resolution yet; awaiting further feedback from Patrick Steinhardt, Johannes Schindelin, or other Windows platform maintainers.

Key technical details
- File: `compat/winansi.c`
- Function: `die_lasterr()`
- New symbols: none (original patch uses a temporary `strbuf` and `strbuf_vaddf()`; Sixt’s alternative removes the variadic argument; Scharfe’s macro forwards directly to `die_errno()`; Sixt’s latest position rejects POSIX `errno` conversion entirely)
- Behavior change: Windows API failure messages now show either the correct integer handle (original patch), a simplified fixed string (Sixt’s variadic-removal alternative), the raw `die_errno()` output (Scharfe’s macro), or a yet-unspecified Windows-specific diagnostic (Sixt’s implied preference)
- On-disk format: unchanged
- Test coverage: none added; the bug is in a fatal-error helper that is difficult to trigger deterministically

Open questions and loose ends
The discussion now centers on which of the four approaches is preferable: preserving the handle value in error messages (original patch), removing the variadic complexity entirely (Sixt’s variadic-removal alternative), using a macro to avoid heap operations and `va_list` manipulation (Scharfe’s alternative), or adopting a Windows-specific solution that avoids POSIX `errno` conversion (Sixt’s implied preference). The key technical trade-off remains between diagnostic precision (preserving the exact Windows error code) and code simplicity (avoiding heap operations, `va_list` manipulation, or POSIX conversion). No resolution yet; awaiting further feedback from Patrick Steinhardt, Johannes Schindelin, or other Windows platform maintainers.
