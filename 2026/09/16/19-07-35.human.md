This is Junio’s "What’s cooking" report for September 2026, summarizing the state of Git’s integration branches as the 2.56 release cycle winds down.

Git 2.56-rc1 is tagged, so the focus is on stabilization. The report lists 87 non-merge commits in `next` and 166 in `seen`; most in-flight topics will remain cooking until after the final release. A few last-minute fixes may still graduate to `master`, but no new features are expected.

Notable graduations to `master` include:
- **jc/rust-cargo-build-target**: Respects `CARGO_BUILD_TARGET` when cross-compiling Rust code, fixing build failures.
- **js/rust-in-windows-ci** and **js/win-cmake-use-ucrt64**: Enable Rust support in Windows CI and switch the cmake build to UCRT64, aligning with Git for Windows’ migration.
- **ps/odb-pluggable-fsck**: Moves fsck checks into backend-specific layers, making them pluggable for different object storage formats.
- **ps/odb-stop-registering-in-memory-sources**: Removes the ad-hoc alternate registration mechanism, simplifying object database management.
- **hn/history-squash**: Adds a `squash` subcommand to the experimental `git history` command, allowing users to fold a range of commits into one.

New topics under review:
- **jc/advice-config-set-global**: Suggests using `--global` when advising users to disable advice messages, as these are typically user-level preferences.
- **sg/precompile-git-compat-util**: Precompiles `git-compat-util.h` with GCC to speed up compilation. This looks well-motivated and is likely to merge soon.
- **of/commit-reach-repo-awareness**: Fixes a bug in submodule merging where `can_all_from_reach()` incorrectly read from the superproject’s commit-graph. The fix is straightforward and addresses a real issue.

Other topics cooking in `next`:
- **ps/ref-storage-format**: Standardizes terminology around reference storage formats (e.g., `--ref-storage-format`), unifying command-line options, environment variables, and configuration keys. This is part of an ongoing effort to clean up ref backend interfaces.
- **kn/receive-report-hook**: Introduces a new `receive-report` hook to allow servers to filter or modify the status report sent back to clients after reference updates. The implementation looks clean and addresses a gap in the hook system.
- **yt/pathspec-negative-prefix**: Fixes an out-of-bounds memory access when negative pathspecs are shorter than the common prefix of positive pathspecs. The fix is small and well-explained.

Topics needing attention:
- **tb/rerere-wait-for-merge-rr-lock**: Makes `rerere` wait for the `MERGE_RR.lock` instead of failing when `rerere gc` is running. This is a usability improvement but may need more testing to ensure it doesn’t introduce deadlocks.
- **tc/push-force-if-includes-fixes**: Fixes edge cases in `--force-if-includes` by checking the local branch’s reflog (not the remote’s) and improving advice for detached HEAD scenarios. The changes are sensible but may need a reroll to address feedback.
- **mm/diff-process-hunks**: Introduces a `diff.<driver>.process` configuration to let external tools act as hunk providers. This is ambitious and could enable powerful integrations, but the implementation is complex and may need more review.

Discarded topics:
- **vm/advice-config-global-hint**: Superseded by **jc/advice-config-set-global**, which takes a more general approach.

Overall, the report reflects a project in good health, with a mix of small fixes, cleanups, and a few larger efforts (like ref storage format unification) that are making steady progress. The Rust-related changes (Windows CI, build target fixes) are particularly notable as they pave the way for broader Rust adoption in the codebase.
