This is a platform compatibility bugfix targeting the Windows ANSI emulation layer in Git’s `compat/` directory.

The patch fixes a long-standing formatting bug in `die_lasterr()`, the helper that reports Windows API failures. When `DuplicateHandle()` fails, the code currently passes a `va_list` directly to `die_errno()` as if it were a variadic argument. `die_errno()` then formats the *address* of the `va_list` instead of the intended integer handle, producing a misleading fatal message. The other callers of `die_lasterr()` happen to pass fixed strings, so they are unaffected.

The fix introduces a temporary `strbuf`, uses `strbuf_vaddf()` to format the caller’s arguments into it, saves `GetLastError()` before any strbuf growth (which might clobber the thread’s last-error value), converts the saved Windows error to `errno`, and finally hands the completed message to `die_errno()` via a literal `"%s"`. This ensures percent signs in the formatted message are not interpreted a second time.

The change is minimal (7 insertions, 2 deletions), touches only `compat/winansi.c`, and includes a clear commit message that explains both the problem and the solution. The patch is well-motivated, self-contained, and unlikely to be controversial. It should be a straightforward candidate for `next`.
