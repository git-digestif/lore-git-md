This is a bugfix patch targeting the Git protocol v2 `upload-pack` subsystem, addressing a client-side crash during shallow fetches when `uploadpack.allowRefInWanted` is enabled. The patch swaps the order of `send_shallow_info()` and `send_wanted_ref_info()` in `upload_pack_v2()` to ensure the server sends "shallow-info" before "wanted-refs", matching the client's expectations.

The issue manifests as a hard crash (`fatal: expected 'packfile', received 'shallow-info'`) when a protocol v2 client performs a shallow fetch (e.g., `--depth=1`) against a server with `uploadpack.allowRefInWanted=true`. The root cause is the client's `process_section_header()` logic, which uses a `peek` bit to skip unexpected sections—when "wanted-refs" arrives first, the client skips it while searching for "shallow-info", leading to the crash. The patch fixes this by reordering the function calls, a server-side-only change that maintains backward compatibility since the feature combination never worked in practice.

The fix is minimal (one line moved) and is validated by two new test cases in `t/t5703-upload-pack-ref-in-want.sh`, covering both single-commit shallow clones and incremental shallow fetches. The tests confirm correct ref resolution and commit history, suggesting the patch is technically sound and ready for review.

No new symbols or on-disk format changes are introduced. The patch is narrowly scoped to the `upload-pack.c` implementation and the test suite, with no broader subsystem interactions. The regression appears to have been latent since the introduction of `uploadpack.allowRefInWanted`, as the feature combination was previously unusable.

Key technical details for follow-up discussion: the `peek` bit in `process_section_header()`, the `UPLOAD_SEND_PACK` state in `upload_pack_v2()`, and the test file `t5703-upload-pack-ref-in-want.sh` (lines 298–315). The patch does not affect protocol v0/v1 or non-shallow fetches.
