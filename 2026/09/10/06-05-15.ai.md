This is the first patch in the v4 series updating Git's MinGW/Windows build and runtime adjustments. It enables Python support in the MinGW build by removing the `NO_PYTHON` flag in `config.mak.uname`. The change allows Git for Windows to leverage MSYS2-provided Python interpreters when users work within the Git for Windows SDK, even though Git for Windows itself does not ship Python to save bandwidth. The patch is a one-line addition and does not affect non-Windows platforms.

The commit message explains the motivation clearly: while Git for Windows avoids bundling Python, MSYS2 offers Python interpreters that users can easily install, and this change makes those interpreters usable with Git. The patch is part of the broader effort to upstream Git for Windows-specific adjustments into the main Git codebase, supporting the project's migration from MINGW64 to UCRT64. Johannes Sixt is credited with helping refine the patch.

This is a straightforward build-system adjustment with no behavioral changes or new symbols introduced. It touches only the build configuration and is unlikely to be controversial. The patch is part of a series that has already been merged to `next` in a previous iteration, and this version is a polish pass with no substantive changes from v3. If you are tracking the series for Windows compatibility, this patch is a minor but necessary piece of the overall effort.
