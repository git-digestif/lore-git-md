This is the **12th patch in the v4 series** from Johannes Schindelin, part of the ongoing effort to upstream Git for Windows build and runtime adjustments. The patch enables direct invocation of `git.exe` (e.g., `C:\Program Files\Git\mingw64\bin\git.exe`) instead of relying on the "Git wrapper" (`C:\Program Files\Git\cmd\git.exe`), a legacy workaround that sets up environment variables before spawning the real executable.

The change is **Windows-specific** and has no impact on non-Windows platforms. It works by detecting the absence of the `MSYSTEM` environment variable (a tell-tale that the wrapper hasn’t run) and then initializing `MSYSTEM`, `PLINK_PROTOCOL`, and `PATH` in `compat/mingw.c`. The `PATH` is reconstructed to prepend `$HOME/bin`, `/mingw64/bin`, and `/usr/bin` (relative to the Git installation directory), ensuring scripts and tools are found without picking up unrelated executables from other Git installations. The patch also updates the build system (`config.mak.uname`, CMake, and Meson) to pass the `MSYSTEM` and `MINGW_PREFIX` values as compile-time definitions, with hard-coded fallbacks for CMake and new Meson options (`msystem` and `mingw-prefix`) for flexibility.

The motivation is practical: Git for Windows wants to add `git.exe` to users’ `PATH` without cluttering it with unnecessary executables like `wish.exe`. The patch addresses GitHub issue [git-for-windows/git#2283](https://github.com/git-for-windows/git/issues/2283) and is part of the urgent UCRT64 migration. Test coverage is added to `t/t0060-path-utils.sh` to verify that `MSYSTEM` and `PATH` are set correctly when `git.exe` is invoked directly.
