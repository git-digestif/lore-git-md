This is the seventh patch in the v4 series (13 patches total) from Johannes Schindelin, part of the ongoing effort to upstream Git for Windows build and runtime adjustments. The series as a whole is already in `next`; this iteration is a polish pass.

This patch makes a targeted **platform compatibility** change: it restricts MSYS2-specific build flags to environments where `MSYSTEM` is actually set during compilation. The key change moves the `-DDETECT_MSYS_TTY` flag inside the `ifneq (,$(MSYSTEM))` conditional block in `config.mak.uname`, ensuring the MSYS2 tty detection logic is only enabled when building in an MSYS2 environment. The patch also removes `-DDETECT_MSYS_TTY` from the unconditional `COMPAT_CFLAGS` line, eliminating redundant flag assignment.

The motivation is straightforward: avoid enabling MSYS2-specific features when they are not needed, which could otherwise lead to unnecessary overhead or subtle behavioral differences in non-MSYS2 MinGW builds. This aligns with the series' broader goal of making the build system more precise and maintainable for Windows environments without affecting non-Windows platforms.

The change is minimal and mechanical, touching only `config.mak.uname`. It carries a `Helped-by` trailer crediting Johannes Sixt, who provided feedback on earlier iterations. The patch does not introduce new symbols or change behavior for end users; it is purely a build-system hygiene improvement. No test coverage is added here, as the change is compile-time only.

If you are tracking the series, this patch is a small but logical refinement of the MSYS2 integration work. It does not address the open question about the empty-`MSYSTEM` guard (raised by Junio in the v3 thread) but is not blocked by it. The patch is uncontroversial and ready for integration.
