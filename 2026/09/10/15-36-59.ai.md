This is a review reply from Junio C Hamano to the second patch in Vsevolod Myalitsin’s three-patch v4 series introducing a `scope_hint` field to Git’s advice settings. The patch implements the core mechanism for programmatically constructing the correct `git config` scope flag (e.g., `--global`) in advice messages.

Junio identifies a **build failure** under `DEVELOPER=YesPlease` mode: the `switch` statement in `vadvise()` does not handle all values of the `CONFIG_SCOPE` enum (`CONFIG_SCOPE_WORKTREE`, `CONFIG_SCOPE_COMMAND`, and `CONFIG_SCOPE_SUBMODULE`). The compiler flags this as an error because the enum is not exhaustively handled. Junio suggests adding a `default` case that calls `BUG()` to catch any unexpected scope values at runtime, treating them as programming errors.

The issue is mechanical and straightforward: the patch reuses the existing `CONFIG_SCOPE` enum but only accounts for the subset of values that make sense for advice settings (`LOCAL`, `GLOBAL`, `SYSTEM`, and `UNKNOWN`). The missing cases are not currently used by the advice subsystem, but the compiler’s `-Werror=switch` flag (enabled in developer mode) requires all enum values to be explicitly handled. The fix is a one-line addition to the `switch` statement.

This is a **surface-level review** targeting a build correctness issue rather than a substantive design concern. The patch remains well-motivated and technically sound; the feedback is purely about ensuring the code compiles cleanly under all build configurations. The series is still under review, and this issue is likely to be addressed in a v5 iteration.
