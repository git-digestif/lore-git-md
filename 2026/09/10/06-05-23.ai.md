This is a **platform compatibility** patch (part 9/13 of the v4 series) targeting **Windows/MinGW build hygiene**. It begins the phased deprecation of Git’s "dashed form" executables (e.g., `git-commit`) by skipping their creation during the Windows build process.

The patch adds a single line to `config.mak.uname` under both the `Windows` and `MINGW` conditionals: `SKIP_DASHED_BUILT_INS = YabbaDabbaDoo`. This variable, when set, prevents the build system from generating hard-linked executables for built-in commands. The commit message explains the motivation: these hard-links are a historical artifact (dating back to Git 1.5.4’s deprecation in 2008), add unnecessary build time (~30 seconds per Windows build), confuse Windows Explorer, and have generated repeated "bug" reports. The change is Windows-specific and does not affect other platforms.

The patch is straightforward and well-motivated, with clear context about the long-standing deprecation. It aligns with the series’ broader goal of reducing Windows-specific build overhead and is validated by Johannes Sixt’s real-world testing (personal builds since November 2025, GitHub CI passes). The `YabbaDabbaDoo` value is a placeholder; the build system only checks for the variable’s presence, not its value.

This is a minor but meaningful step toward removing dashed-form executables entirely (a goal Junio C Hamano has suggested for Git 3.0). The patch itself is uncontroversial and ready for integration, though future discussion may revisit the broader deprecation timeline.
