This is a refactoring patch that mechanically converts existing `advice_enabled()` + `advise()` call pairs into the newer `advise_if_enabled()` helper. The change is part of the ongoing `defaultBranchName` advice documentation fix thread, but it is a separate, broader cleanup.

Junio C Hamano writes a Coccinelle semantic patch to automate the conversion, then applies it and hand-edits the results to tidy up formatting. The patch touches seven files (`advice.c`, `branch.c`, `builtin/am.c`, `builtin/checkout.c`, `builtin/submodule--helper.c`, and `sequencer.c`), replacing 23 lines of conditional advice with 24 lines of the new helper. No behavior changes are intended—this is purely a refactoring to reduce boilerplate and make the code more consistent.

The patch is well-motivated: the `advise_if_enabled()` helper was introduced in 2020 to centralize the advice-checking logic, yet many call sites still use the older pattern. Junio’s Coccinelle script makes the conversion systematic and repeatable, which is a good sign of maintainability. The hand-edits to avoid overly long lines show attention to readability.

This is not a blocker for the `defaultBranchName` patch, but it is a logical follow-up. If merged, it would simplify future advice-related changes by reducing the number of places that need to be updated. The patch itself looks clean and uncontroversial; it is a textbook example of a safe, mechanical refactoring.
