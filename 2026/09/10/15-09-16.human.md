This is the sixth patch in Patrick Steinhardt’s 9-patch series refactoring ODB alternates handling during repository creation, part of the ongoing ODB abstraction effort. The patch completes the consolidation of alternates logic by moving the setup of alternates for non-shared local clones (`git clone --local --no-shared`) into `collect_alternates()`, fixing a latent bug in worktree alternates handling and adding test coverage for the regression.

The patch renames `copy_alternates()` to `read_alternates()` and refactors it to gather alternates paths into a `strvec` instead of immediately writing them to the ODB, aligning with the series’ goal of deferring alternates writes until ODB creation. The key fix is reusing the resolved common directory path from `collect_alternates()` (already computed for shared clones) to handle non-shared local clones, ensuring alternates are correctly resolved for worktrees. Previously, Git failed to resolve the common directory of the referenced repository when cloning from a worktree, causing alternates setup to break. The patch also removes the manual alternates handling in `copy_or_link_directory()`, as alternates are now fully handled by `collect_alternates()`.

Two new tests in `t/t5604-clone-reference.sh` verify the bug fix: one ensures alternates are correctly carried over when cloning from a linked worktree, and another confirms relative alternates paths are properly resolved. The changes are minimal (34 insertions, 11 deletions) and preserve existing behavior while preparing for the removal of the `write_alternates()` callback in patch 9/9. Karthik Nayak’s surface-level review of v4 acknowledged the connection to patch 5/9’s consolidation of shared local clones but did not engage with the patch’s core technical contributions. The patch is uncontroversial and aligns with the series’ incremental approach.
