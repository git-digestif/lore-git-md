This is a bugfix patch targeting the refs/files backend, addressing a spurious `packed-refs` lock issue when deleting root refs like `HEAD` or `AUTO_MERGE`. The v2 revision incorporates feedback from Patrick Steinhardt, refining the fix and its test coverage.

The core issue remains the same: root refs cannot be packed, so taking a `packed-refs` lock when deleting them is unnecessary and can cause failures in linked worktrees with read-only shared metadata. The v2 patch keeps the same logic but improves the in-code comment to focus on the general case rather than root refs specifically, as Patrick suggested.

The test coverage has been streamlined. The seven redundant tests from v1 are gone, replaced by two focused cases: one verifying that deleting a root ref succeeds even when `packed-refs.lock` is held, and another ensuring that a transaction deleting *both* a root ref and a packed branch fails if the lock is held (preserving both refs). This addresses Patrick’s concern about the missing edge case in v1.

The patch is well-motivated and technically sound. It touches only `refs/files-backend.c`, adding a small helper (`is_root_ref()`) and modifying `files_transaction_prepare()` to skip the `packed-refs` lock for root refs. The new tests in `t/t0600-reffiles-backend.sh` are thorough without being excessive, and the broader test suites (refs, worktree, sequencer) pass, indicating no regressions. The author used AI assistance but the contribution is clearly grounded in real-world scenarios.
