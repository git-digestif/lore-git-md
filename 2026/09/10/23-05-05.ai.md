This is the first patch in a **bugfix series** (v3, 2/2) targeting the `--force-if-includes` safety mechanism in `git push`. The patch corrects a long-standing flaw where the check incorrectly consults the reflog of the *local* branch matching the *remote* destination name (e.g., `refs/heads/main` when pushing to `refs/remotes/origin/main`), rather than the branch actually being pushed (e.g., `refs/heads/src` in `src:main`). This can cause false rejections (e.g., pushing from a differently named local branch) or unintended data loss (e.g., pushing an outdated branch that shares a name with a local branch containing the remote tip).

The fix modifies `remote.c` to use `ref->peer_ref->name` (the pushed ref) instead of `ref->name` (the destination ref) when locating the local reflog. It adds special handling for `HEAD`-based pushes by resolving the symref, and explicitly rejects detached HEAD states by setting `remote->unverifiable` (a new flag introduced in this series). Deletions are allowed via `is_null_oid(&remote->peer_ref->new_oid)`. The patch includes 65 lines of new test coverage in `t/t5533-push-cas.sh`, covering mismatched local/remote names, `HEAD`-based pushes, and detached HEAD scenarios.
