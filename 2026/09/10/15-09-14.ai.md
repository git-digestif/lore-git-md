This is patch 4/9 of Patrick Steinhardt’s 9-patch series refactoring ODB alternates handling during repository creation, part of the ongoing ODB abstraction effort. The patch refactors the `--reference` and `--reference-if-able` logic in `git clone` to gather alternates paths into a `strvec` instead of immediately writing them to the object database, using a new `struct collect_alternates_data` to track whether each alternate is required or optional. This is a mechanical intermediate step that enables the consolidation of alternates logic in later patches (5-6/9) and the eventual removal of the `write_alternates()` callback in patch 9/9.

The patch renames `setup_reference()` to `collect_alternates()` to clarify its new scope—it no longer sets up alternates itself but instead collects them for later use. The `add_one_reference()` helper is renamed to `collect_one_alternate()` and now appends valid alternates paths to a `strvec` (via `strvec_pushf()`) instead of writing them directly to the ODB with `odb_add_to_alternates_file()`. The `collect_alternates_data` struct replaces the previous `int required` parameter, now using a `bool` to track whether an alternate is required (for `--reference`) or optional (for `--reference-if-able`). The patch preserves existing behavior: after collecting alternates, `cmd_clone()` iterates over the `strvec` and writes each path to the ODB using the existing `odb_add_to_alternates_file()` helper, maintaining backward compatibility while preparing for the lockfile-based atomic writes introduced in patch 7/9.

Key changes are confined to `builtin/clone.c` and include the introduction of `struct collect_alternates_data` (with `alternates` and `required` fields), the renaming of `add_one_reference()` to `collect_one_alternate()`, and the refactoring of `setup_reference()` into `collect_alternates()`. The patch also initializes a `strvec alternates` in `cmd_clone()` and updates the alternates-writing loop to use the collected paths. No new symbols are exposed outside `builtin/clone.c`, and the patch does not alter user-visible behavior. Karthik Nayak’s surface-level review of v4 suggested minor readability improvements (e.g., inverting a conditional to reduce nesting), but Patrick Steinhardt opted to retain the existing structure, noting that the changes were inconsequential. The `required` field in `collect_alternates_data` is now a `bool` (addressing Karthik’s feedback about `int` usage for boolean-like values), and the commit message clarifies that alternates are now added outside `collect_alternates()`.

This patch is uncontroversial and aligns with the series’ incremental approach. It sets the stage for patch 5/9’s consolidation of shared local clones (`git clone --shared`) into `collect_alternates()` and patch 6/9’s handling of non-shared local clones, both of which will reuse the `strvec` infrastructure introduced here. The refactoring is purely preparatory and does not yet adopt the lockfile-based alternates writing (patch 7/9) or remove the `write_alternates()` callback (patch 9/9). Reviewers may focus on the clarity of the new `collect_alternates_data` struct and the mechanical correctness of the `strvec` handling, but the patch’s core logic is straightforward and well-documented.
