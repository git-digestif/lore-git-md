This is patch 5/9 of Patrick Steinhardt’s 9-patch series refactoring ODB alternates handling during repository creation, part of the ongoing ODB abstraction effort. The patch moves the setup of alternates for shared local clones (`git clone --shared`) from `clone_local()` into the newly extended `collect_alternates()` function, consolidating all alternates logic into a single code path. This change is a direct follow-up to patch 4/9’s refactoring of `--reference` and `--reference-if-able` logic and prepares for patch 6/9’s consolidation of alternates for non-shared local clones.

The patch adds `local_source_repo` (formerly `src_repo` in earlier iterations) and `is_local` parameters to `collect_alternates()`, enabling it to handle shared local clones by computing the common directory of the source repository and pushing the alternates path into the `strvec`. A critical correctness fix is included: the `option_shared` guard ensures alternates are only added for shared local clones, addressing Justin Tobler’s feedback from v3 that the original implementation would incorrectly add alternates for non-shared local clones (`git clone --local --no-shared`). The change is minimal (14 insertions, 9 deletions) and preserves existing behavior while preparing for the removal of the `write_alternates()` callback in patch 9/9.

The patch’s commit message explicitly notes that the `commondir` computation (unused when `option_shared` is false) is intentional to prepare for patch 6/9’s consolidation of alternates logic for non-shared local clones, addressing Karthik Nayak’s surface-level observation from v4. The `collect_alternates()` function now handles both reference-based clones (`--reference`, `--reference-if-able`) and shared local clones (`--shared`), with non-shared local clones (`--local --no-shared`) deferred to patch 6/9. This incremental approach is uncontroversial and aligns with the series’ goal of simplifying the ODB interface by making alternates an implementation detail of the backend.

No new symbols are introduced, and the patch touches only `builtin/clone.c`. The `strvec_pushf()` call for shared local clones is now guarded by `option_shared`, ensuring correctness for non-shared local clones. The patch is well-documented and addresses all substantive review feedback, making it a strong candidate for integration. Reviewers may focus on the `option_shared` guard’s placement, but the fix is straightforward and resolves the latent bug identified in v3. The patch’s core logic remains unchanged from v4, with only minor documentation and naming improvements carried forward from earlier iterations.
