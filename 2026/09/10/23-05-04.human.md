This is a bugfix series targeting the `--force-if-includes` safety mechanism in `git push`. The v3 posting is a **procedural resend only**—no technical changes—correcting a threading issue in v2 (patches were incorrectly threaded under the v1 cover letter rather than v2). The series is now properly threaded and remains **ready for merge** with no unresolved questions.

The core issue is that `--force-if-includes` incorrectly checks the reflog of the *local* branch whose name matches the *remote* destination branch (e.g., `refs/heads/main` when pushing to `refs/remotes/origin/main`), rather than the branch actually being pushed (e.g., `refs/heads/src` in `src:main`). This flaw has caused false rejections in reported cases (e.g., pushing from a differently named local branch or detached HEAD) and could enable unintended data loss (e.g., pushing an unrelated branch that happens to share a name with a local branch containing the remote tip).

The fix spans two patches. The first corrects the core logic in `remote.c` to consult the reflog of the pushed ref (`ref->peer_ref->name`) instead of the destination ref (`ref->name`), with special handling for `HEAD`-based pushes (resolving the symref) and detached HEAD states (rejecting by default, with a new `ref->unverifiable` flag). The second patch adjusts the advice message for detached HEAD scenarios, introducing a new `advice.forceIfIncludesDetachedHead` config knob (documented as `advice.pushRefUnverifiable`) and actionable guidance for users (e.g., `--force-with-lease=<ref>:<expect>` or `--no-force-if-includes`). All transport layers (direct pushes, transport helpers, send-pack) are updated for consistency.

Test coverage is thorough: eight new cases in `t/t5533-push-cas.sh` verify the fix for mismatched local/remote names, `HEAD`-based pushes, detached HEAD states, and the new advice message. The series is self-contained, touches 12 files (including documentation and advice infrastructure), and leaves on-disk formats unchanged. Prior feedback from D. Ben Knoble (substantive review) and Junio (procedural threading note) has been addressed. The series is based on `maint` and explicitly documents the detached HEAD rejection policy as a settled trade-off.
