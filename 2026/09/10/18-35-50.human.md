This is a **documentation patch** from Junio C Hamano, posted as a follow-up in the ongoing thread about Vsevolod Myalitsyn’s advice-scope-hint series. The patch clarifies the `<file-option>` placeholder in the `git config` man page, which currently appears in the SYNOPSIS without explanation.

Junio’s patch adds a short paragraph early in the documentation that explicitly links `<file-option>` to the scope-limiting flags (`--system`, `--global`, `--local`, `--worktree`) and the `--file <filename>` option. This addresses a usability gap he noticed while reviewing the advice-scope series: the man page’s SYNOPSIS refers to `<file-option>` but never defines it, leaving users to infer its meaning from scattered hints elsewhere in the text. The patch also leaves a `NEEDSWORK` comment about `<display-option>`, another undefined placeholder in the same SYNOPSIS.

The patch is a small, self-contained improvement to the `git-config` documentation and is not directly tied to the technical implementation of the advice-scope series. However, it emerged from the discussion about which config scopes (`--global`, `--system`, `--worktree`) are relevant for advice settings, illustrating how review of one patch can surface broader documentation issues. The patch is well-motivated and uncontroversial; it should be easy to merge once Junio picks it up.
