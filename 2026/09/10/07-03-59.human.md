This is a review comment on the third patch in the v4 series optimizing `git last-modified` by reusing Bloom filters. The series aims to speed up the command by up to 3.7×, with this patch introducing a helper function, `bloom_filter_contains_any_vec()`, to check if *any* key in a Bloom key vector is present in the filter. The helper is critical for enabling `--show-trees` to report changes to parent directories without false negatives.

Patrick Steinhardt points out a discrepancy in the function's behavior and documentation. The helper calls `bloom_filter_contains()`, which can return `-1` (indicating an empty filter), but the documentation only mentions returns of `0` or `1`. He suggests either updating the documentation to reflect the `-1` case or modifying the helper to return only `0` or `1` (e.g., by treating `-1` as `0`). He also notes that a boolean return type might be more appropriate if the function is simplified to avoid the `-1` case.

The review is substantive but narrowly scoped, focusing on a single edge case in the new helper. The fix is likely to be minor—either a documentation update or a small code change—but it addresses a potential source of confusion or bugs. The patch itself is otherwise well-crafted and directly supports the series' goals. This feedback does not block integration but should be addressed before the series is merged.
