This is patch 7/9 in Patrick Steinhardt’s ODB abstraction series, implementing the core design change: alternates are now written during ODB creation using Git’s standard lockfile API. The patch adds support for writing alternates to the "files" backend via the new `odb_create_on_disk_options` struct, which carries a `strvec` of alternates paths. The implementation reads any preexisting alternates (e.g., from templates), deduplicates them with the new entries using a `strset`, and writes the combined set atomically using `commit_lock_file()`. The ODB is then reprepared to activate the new alternates. Error handling is thorough, with rollback on failure and proper cleanup of resources.

The patch touches `odb/source-files.c` (adding the alternates-writing logic), `odb/source.h` (introducing `odb_create_on_disk_options` and updating the `create_on_disk` callback signature), and `setup.c` (updating `create_object_database()` to pass the alternates `strvec` via the options struct). The lockfile adoption resolves the primary security concern from v1 (TOCTOU race and concurrent access) and is uncontroversial. Karthik Nayak’s substantive review of v4 raised two technical points: (1) the robustness of error handling (checking `ferror()` per-write vs. post-write), noting that the current implementation checks `ferror()` only after writing all alternates, which could leave the file in a partially written state if an error occurs mid-write, though the lockfile mechanism would prevent corruption; and (2) whether backends should formalize error codes to distinguish "alternates not supported" from other failures, probing the ODB interface’s clarity and extensibility. These points remain open but do not block the patch’s readiness.

The patch is a direct follow-up to patches 1-6, which consolidated all alternates logic into a single code path and deferred ODB setup until after URI resolution. It prepares for patch 8/9 (wiring the alternates `strvec` to `create_object_database()`) and patch 9/9 (removing the `write_alternates()` callback). The changes are mechanical and well-documented, with no user-visible behavior changes. The lockfile cleanup logic and reprepare step ensure robustness in concurrent scenarios, though reviewers may focus on the error handling improvements suggested by Karthik Nayak. The patch is a strong candidate for integration, aligning with the series’ goal of making alternates an ODB backend implementation detail.
