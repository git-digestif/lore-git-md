This is the third patch in the v10 series introducing the `receive-report` hook, a server-side filter for Git’s push status reports. It refactors the status-report generation logic into a reusable `generate_report()` helper, eliminating redundancy between the `report()` and `report_v2()` functions.

The patch moves the core message-generation logic from both `report()` and `report_v2()` into a single `generate_report()` function, which takes an `enum report_status_version` parameter to handle protocol-specific details (e.g., the detailed ref-update reports in v2). The `report()` function is now a thin wrapper around `generate_report()`, passing the version parameter through. This refactoring is purely internal and does not change user-visible behavior, but it prepares the codebase for the next patch, which will reuse `generate_report()` to feed the status report to the new `receive-report` hook.

The diff shows a straightforward consolidation: the loop over `commands` and the pkt-line formatting logic are lifted into `generate_report()`, while `report()` handles only the sideband/writing logic. The `report_v2()` function is removed entirely, as its functionality is now covered by `generate_report()`. The change is well-motivated by the upcoming hook, which needs to intercept the same report that would otherwise be sent directly to the client.

This patch addresses Patrick Steinhardt’s substantive review from v6, which identified the redundancy between `report()` and `report_v2()` as a missed refactoring opportunity. The implementation is clean and aligns with the series’ goal of minimizing code duplication. No new issues are introduced, and the patch is uncontroversial. It is queued in `next` alongside the rest of the series and is on track for graduation to `master`.
