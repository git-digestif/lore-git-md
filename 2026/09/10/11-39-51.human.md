This is a bugfix patch for a memory leak in the `git history reword` command, part of Patrick Steinhardt’s ongoing `git history` work. The patch is a refined version of an earlier fix that has already been merged, now with a clearer explanation of the root cause.

The leak occurs when `git history reword` retrieves a commit message buffer via `repo_logmsg_reencode()` but fails to release it with `repo_unuse_commit_buffer()`. The commit message now explains why this happens: when commits are loaded from the commit-graph, their buffers are not cached in the commit slab, so they must be explicitly freed. The patch adds the missing cleanup call in `builtin/history.c`.

The author includes a minimal reproduction recipe and notes that the leak also surfaces in the test suite (`t3451-history-reword.sh`) when run with `GIT_TEST_COMMIT_GRAPH=1`. The patch itself is a single-line addition, following the standard pattern for managing commit buffers elsewhere in Git.
