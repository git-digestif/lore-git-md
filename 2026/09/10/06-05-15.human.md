This is the first patch in Johannes Schindelin’s 13-part v4 series **upstreaming Git for Windows build and runtime adjustments** into the main Git codebase. The series as a whole is already merged to `next`; this iteration is a polish pass following Junio’s editorial cleanup of v3.

This specific patch **enables Python support in the MinGW build** by removing the `NO_PYTHON` flag in `config.mak.uname`. The change is minimal—just one line—but important for Git for Windows users who rely on MSYS2’s Python interpreters (e.g., within the Git for Windows SDK). The commit message clarifies that Git for Windows itself does not ship Python (to save bandwidth), but the build system now allows users to leverage MSYS2’s Python packages if they choose. No behavior changes occur on non-Windows platforms, and the patch is uncontroversial. If you care about Windows compatibility or Python tooling integration, this is a small but necessary step in the series.
