Thread identity: Bugfix patch series addressing resource cleanup in low-level merge driver infrastructure when interrupted by SIGINT/SIGQUIT. Originating author: Michal Koutný; v3 submission by Jeff King (Peff). Thread type: standalone patch series (2 patches in v3).

Core problem or goal: Ensure temporary files (`.merge_file_*`) created during external merge driver execution are reliably removed even when the merge process is abruptly terminated by the user (e.g., via Ctrl+C). The solution replaces custom signal handling with Git’s `tempfile` API for atomic, signal-safe cleanup, while modernizing adjacent code (e.g., replacing manual buffer management with `strbuf`). The series additionally addresses latent robustness issues in file operations (e.g., ignoring `close()` errors after successful `write()` calls) and a type-safety bug in the `strbuf`-based refactoring, resolved with a `die()` check for oversized files.

Current status: Series is **ready for merging** as of v3. v3 incorporates all prior feedback: (1) a **stylistic improvement** in the first patch to split the combined `write_in_full()`/`close()` error check in `create_temp()` into two separate `die_errno()` calls for clarity, (2) a **commit-message tweak** in the second patch to use `Reported-by:` trailers for Jean Delvare and Michal Koutný, and (3) the **type-safety fix** for oversized files in `strbuf_detach()` and `read_mmfile()`. The core logic remains unchanged from v2, which received **substantive approval** from Elijah Newren. The series is uncontroversial and aligns with Git’s established patterns for resource cleanup. **Attribution resolved**: Peff adopted Michal’s preference for `Reported-by:` trailers in the second patch’s commit message. **Test coverage discussion**: Peff and Michal reaffirmed that automated tests for interrupt scenarios are unnecessary, as the current cleanup behavior is preferable for users and leaving temporary files for debugging is not required. No merge status reported (not in `pu`, `next`, or `master`).

Key technical details:
- **Files modified**: `merge-ll.c` (only file touched).
- **Functions**: `ll_ext_merge()` (refactored to use `strbuf` and `tempfile` APIs), `create_temp()` (modified to split `write_in_full()`/`close()` error checks into two separate `die_errno()` calls for clarity), `temp_path_basename()` (new helper for backward compatibility).
- **Temporary files**: `.merge_file_*` (created during external merge driver execution).
- **APIs introduced/used**: `xmks_tempfile()`, `close_tempfile_gently()`, `delete_tempfile()`, `get_tempfile_path()`, `strbuf_read_file()`, `write_in_full()`, `temp_path_basename()`, `strbuf_detach()`.
- **Behavior**:
  - No functional change in cleanup guarantees for interrupt scenarios; implementation is now more robust and signal-safe via Git’s `tempfile` subsystem.
  - Manual buffer management replaced with `strbuf` for file I/O.
  - `close()` errors after `write()` are now treated as fatal, aligning with Git’s defensive programming patterns (confirmed by Elijah Newren).
  - Backward compatibility preserved for merge drivers using shell metacharacters in command templates (via `temp_path_basename()`).
  - **Latent bug resolved**: The `strbuf`-based refactoring in the first patch previously silently truncated file sizes exceeding `LONG_MAX` to negative values, risking buffer overreads. The fix adds `if (result_buf.len > LONG_MAX) die(_("external merge result is too large"));` before `strbuf_detach()`. The same check is applied to `read_mmfile()` to address an identical issue.
  - **Edge cases addressed**:
    - Error-checking bug in original signal handler (fixed in v2).
    - Const-correctness in `get_tempfile_path()` (fixed in v2).
    - `close()` errors after `write()` (fixed in v2, confirmed by Elijah Newren).
    - Type mismatch between `result->size` (`long`) and `strbuf_detach()` (`size_t`), now resolved with a `die()` check in v3.
    - Shell quoting limitations in `get_tempfile_path()` for absolute paths (non-blocking, cosmetic; addressed by `temp_path_basename()` in the second patch).
    - **Stylistic improvement**: The combined `write_in_full()`/`close()` error check in `create_temp()` is now split into two separate `die_errno()` calls to avoid a subtle pattern that could lead to file descriptor leaks if copied to other contexts.
- **Test coverage**: Lightly tested by Michal for regular termination and SIGINT; no automated test coverage for interrupt scenarios (Peff and Michal agree this is acceptable). The `strbuf` conversion, `close()` error handling, type-safety fix, and stylistic improvement are purely internal and do not require new tests. The type-safety bug is theoretical but plausible on LLP64 platforms (e.g., Windows).
