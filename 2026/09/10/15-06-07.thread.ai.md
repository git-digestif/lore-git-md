Thread identity: Bugfix patch series addressing resource cleanup in low-level merge driver infrastructure when interrupted by SIGINT/SIGQUIT. Originating author: Michal Koutný; v2 submission by Jeff King (Peff). Thread type: standalone patch series (3 patches, now complete).

Core problem or goal: Ensure temporary files (`.merge_file_*`) created during external merge driver execution are reliably removed even when the merge process is abruptly terminated by the user (e.g., via Ctrl+C). The issue arises because SIGINT/SIGQUIT sent to the external merge driver propagates to the parent `git merge` process, preventing cleanup handlers from running. The solution replaces custom signal handling with Git’s `tempfile` API for atomic, signal-safe cleanup, while also modernizing adjacent code (e.g., replacing manual buffer management with `strbuf`). Additionally, the series addresses latent robustness issues in file operations, such as ignoring `close()` errors after successful `write()` calls.

Current status: Series is **technically complete** and ready for review. v2 (Peff’s submission) incorporates feedback and testing from Michal Koutný, addressing the core issue, minor edge cases (e.g., error-checking bug in signal handler, const-correctness), and adjacent cleanups (e.g., `strbuf` conversion, `close()` error handling). The third patch finalizes the transition to the `tempfile` API, including a helper function (`temp_path_basename()`) to maintain backward compatibility with user-configured merge drivers. No merge status reported (not in `pu`, `next`, or `master`). The series is uncontroversial and aligns with Git’s established patterns for resource cleanup and modern code idioms.

Key technical details:
- **Files modified**: `merge-ll.c` (only file touched).
- **Functions**: `ll_ext_merge()` (refactored to use `strbuf` and `tempfile` APIs), `create_temp()` (modified to check `close()` errors), `temp_path_basename()` (new helper for backward compatibility).
- **Temporary files**: `.merge_file_*` (created during external merge driver execution).
- **APIs introduced/used**: `xmks_tempfile()`, `close_tempfile_gently()`, `delete_tempfile()`, `get_tempfile_path()`, `strbuf_read_file()`, `write_in_full()`, `temp_path_basename()`.
- **Behavior**:
  - No functional change in cleanup guarantees for interrupt scenarios; implementation is now more robust and signal-safe via Git’s `tempfile` subsystem.
  - Manual buffer management replaced with `strbuf` for file I/O.
  - `close()` errors after `write()` are now treated as fatal, aligning with Git’s defensive programming patterns.
  - Backward compatibility preserved for merge drivers using shell metacharacters in command templates (via `temp_path_basename()`).
- **Test coverage**: Lightly tested by Michal for regular termination and SIGINT; no automated test coverage for interrupt scenarios (Peff notes difficulty in testing this in the suite). The `strbuf` conversion and `close()` error handling are purely internal and do not require new tests.
- **Edge cases addressed**:
  - Error-checking bug in original signal handler (fixed in v2).
  - Const-correctness in `get_tempfile_path()` (fixed in v2).
  - `close()` errors after `write()` (fixed in v2).
  - Type mismatch between `result->size` (`long`) and `strbuf_detach()` (`size_t`), left as-is to avoid scope creep.
  - Shell quoting limitations in `get_tempfile_path()` for absolute paths (non-blocking, cosmetic).
