Subject: [PATCH v2] refs/files-backend: avoid spurious packed-refs lock when deleting root refs
Series version: standalone patch, v2 (v3 expected)
Originating author: Ariel Keselman
Thread type: bugfix patch

Core problem or goal
Fix a bug in the `refs/files` backend where an unnecessary lock on `packed-refs` is taken when deleting root refs (e.g., `HEAD`, `refs/heads/main`, `AUTO_MERGE`). Root refs cannot be packed, so the lock is redundant and causes spurious errors in linked worktrees when the shared metadata directory is read-only.

Current status
Under review; v2 posted in response to Patrick Steinhardt’s initial feedback. A v3 is expected to incorporate Patrick’s latest test-coverage suggestions. Patch modifies `files_transaction_prepare()` in `refs/files-backend.c` to skip packed-ref transactions for root refs via the `is_root_ref()` helper. Includes two new regression tests in `t/t0600-reffiles-backend.sh`: one verifies root-ref deletion succeeds even when `packed-refs.lock` is held, and the other ensures mixed root/non-root ref transactions fail correctly if the lock is held. Broader test suites (refs, worktree, sequencer, SHA-256) pass, indicating no regressions.

Key technical details
- File modified: `refs/files-backend.c`
- Function modified: `files_transaction_prepare()`
- Helper added: `is_root_ref()`
- New behavior: skips packed-ref transactions for root refs; mixed root/non-root ref transactions fail if `packed-refs.lock` is held
- Test coverage: two new regression tests in `t/t0600-reffiles-backend.sh`; Patrick Steinhardt suggests two enhancements: (1) explicitly verify `AUTO_MERGE` is not packed after `git pack-refs --all`, and (2) strengthen the mixed-transaction test by capturing full ref state with `git refs list --include-root-refs` instead of just the two refs under test. Minor test-script cleanups (dropping redundant `start/prepare/commit` lines, inlining heredoc) are also proposed.
- Subsystems touched: refs backend (files), worktree handling
- No changes to on-disk format, CLI, or config

Open questions and loose ends
None currently open. Patrick Steinhardt’s concerns about test coverage and the mixed-transaction edge case have been addressed in v2, with additional test robustness suggestions pending for v3.
