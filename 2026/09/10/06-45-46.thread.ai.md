Subject: [PATCH v2] refs/files-backend: avoid spurious packed-refs lock when deleting root refs
Series version: standalone patch, v3 (final)
Originating author: Ariel Keselman
Thread type: bugfix patch

Core problem or goal
Fix a bug in the `refs/files` backend where an unnecessary lock on `packed-refs` is taken when deleting root refs (e.g., `HEAD`, `refs/heads/main`, `AUTO_MERGE`). Root refs cannot be packed, so the lock is redundant and causes spurious errors in linked worktrees when the shared metadata directory is read-only.

Current status
Review complete; v3 posted (in a separate thread) incorporating all feedback. Patch modifies `files_transaction_prepare()` in `refs/files-backend.c` to skip packed-ref transactions for root refs via the `is_root_ref()` helper. Includes two new regression tests in `t/t0600-reffiles-backend.sh`: one verifies root-ref deletion succeeds even when `packed-refs.lock` is held, and the other ensures mixed root/non-root ref transactions fail correctly if the lock is held. Test coverage now explicitly checks that `AUTO_MERGE` is not packed after `git pack-refs --all` and uses `git refs list --include-root-refs` to capture full ref state in the mixed-transaction test. Broader test suites (refs, worktree, sequencer, SHA-256) pass, indicating no regressions.

Key technical details
- File modified: `refs/files-backend.c`

- Helper added: `is_root_ref()`
