This is the v7 iteration of Andrew Pleeter’s patch series extending `git var` to expose individual identity components (author/committer name, email, date), the resolved signing key, and support for multiple arguments with NUL-terminated output. The patch is part of a long-running effort to provide a unified, scriptable interface for Git’s identity and signing configuration, replacing the earlier `git ident` proposal.

The v7 patch addresses all substantive feedback from Junio’s and Phillip Wood’s reviews of v6. Key improvements include: streamlined documentation that groups related variables (e.g., `GIT_AUTHOR_*` and `GIT_COMMITTER_*`) to avoid repetitive descriptions; explicit `BUG()` checks in `ident_part()` to guard against future breakage in `split_ident_line()`; simplified multi-valued variable handling by making the `multiread` callback return `void` (relying on `string_list->nr` for length); and relaxed error handling for multi-variable queries, where unset variables now print an empty record instead of causing the command to fail. The test suite has also been updated to use Git’s `nul_to_q` helper, avoiding binary comparison errors in `test_cmp`.

The patch is technically sound and ready for integration. It touches `builtin/var.c`, `Documentation/git-var.adoc`, and `t/t0007-git-var.sh`, adding new variables (`GIT_AUTHOR_NAME`, `GIT_AUTHOR_EMAIL`, `GIT_AUTHOR_DATE`, `GIT_COMMITTER_NAME`, `GIT_COMMITTER_EMAIL`, `GIT_COMMITTER_DATE`, and `GIT_SIGNING_KEY`) and supporting features like `-z` for NUL-terminated output and strict argument ordering (options before variable names). The implementation aligns with Git’s existing patterns, using `parse_options()` for argument parsing and `get_signing_key()` for signing key resolution. Junio’s remaining concerns about output format ambiguity (extra delimiters for multi-valued variables) and documentation style have been addressed, and Phillip’s feedback on error handling and test robustness has been incorporated.

The series is in `seen` and appears close to graduation to `next`. No fundamental objections remain, and the changes are incremental and well-tested. The patch is a clear improvement over the current `git var` interface, offering better scripting support and a more intuitive way to query identity and signing configuration.
