This is the v5 cover letter for Patrick Steinhardt’s 9-patch series refactoring ODB alternates handling during repository creation, part of the ongoing ODB abstraction effort. The series is now well-documented and addresses all substantive review feedback from v4, making it a strong candidate for integration.

The core goal remains unchanged: eliminate the ability to write ODB alternates after repository creation by consolidating alternates handling into the ODB creation process. This simplifies the ODB interface, prepares for alternates to become an ODB backend implementation detail, and resolves TOCTOU race and concurrent access concerns by adopting Git’s standard lockfile API for writing the `info/alternates` file. The v5 iteration incorporates minor naming and documentation improvements from Karthik Nayak’s surface-level reviews of v4: `add_one_alternate` and `add_one_alternate_data` are renamed to `collect_one_alternate` and `collect_alternates_data` for clarity, and the commit message for patch 5/9 now explicitly notes that the `commondir` computation (unused in shared clones) is intentional to prepare for patch 6/9’s consolidation of non-shared local clones. The `collect_alternates()` function also drops an unused parameter (`src_repo` renamed to `local_source_repo` for clarity), and the `required` field in `collect_alternates_data` is now a `bool` instead of an `int`.

The series touches `builtin/clone.c` (refactoring reference and alternates logic, deferring ODB setup until after URI resolution), `setup.c`/`setup.h` (splitting `init_db()` into `create_repository()`, `create_object_database()`, and `initialize_repository()` with improved documentation for `reinit_ok` and the new helpers), `odb/source-files.c` (adding lockfile-based alternates writing during ODB creation), and several ODB source files (removing the now-unused `write_alternates()` callback). New tests in `t/t5604-clone-reference.sh` verify the latent bug fix for worktree alternates handling and relative path resolution. The patches are mechanical and incremental, with no user-visible behavior changes, but they lay critical groundwork for the ODB abstraction effort by making alternates an implementation detail of the "files" backend.

Key symbols introduced or renamed include `collect_alternates()` (formerly `setup_reference()`, now gathering alternates paths into a `strvec` for all clone types), `collect_one_alternate()` (formerly `add_one_alternate()`, using `struct collect_alternates_data` to track required/optional alternates), and `odb_create_on_disk_options` (a new struct carrying the alternates `strvec` for ODB creation). The `write_alternates()` callback and its supporting infrastructure are removed in patch 9/9, completing the series. The lockfile API adoption in patch 7/9 resolves the primary security concern from v1, and Karthik Nayak’s substantive review of this patch in v4 raised two technical points: error handling robustness (checking `ferror()` per-write vs. post-write) and whether backends should formalize error codes for alternates support. These remain open but do not block the series’ trajectory.

The series is built on `2c3adbb2c4` (The 18th batch, 2026-08-24) with `ps/odb-eagerly-load-alternates` merged in. All patches are now well-documented, and the recent exchanges with Karthik Nayak resolve minor naming and readability feedback without affecting core logic. The series is uncontroversial and aligns with the broader ODB abstraction goals, though reviewers may focus on the lockfile cleanup logic and error handling in patch 7/9. Justin Tobler’s forward-looking question about ODB interface flexibility (whether `--shared` should be restricted to the "files" backend) remains unresolved but is not a blocker.
