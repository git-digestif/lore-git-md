This is the fourth iteration of Mike Hommey's patch series to relocate Git's experimental Rust code into a dedicated `rust/` subdirectory, part of the ongoing Rust infrastructure reorganization effort. The patch addresses all mechanical review feedback from v3: it fixes the `.gitignore` and `Makefile` duplicate entries, updates the `Makefile clean` target to match the new `Cargo.lock` location, and corrects the `meson.build` path to point to the relocated `rust/` directory (resolving the build-breaking error Tuomas Ahola identified).

The changes remain purely mechanical—moving files and updating paths in `.gitignore`, `Makefile`, and `meson.build`—with no functional behavior changes. The patch now appears ready for acceptance from a technical standpoint, pending any new feedback. The long-term forward-compatibility discussion (how downstream projects will handle Git 3.0's mandatory Rust components) remains unresolved but is orthogonal to this reorganization.

Key files touched: `.gitignore`, `Makefile`, `meson.build`, and the entire Rust source tree (relocated from `src/` to `rust/`). The patch preserves all existing build functionality while establishing a cleaner project structure for future Rust development. The commit message clearly states the motivation: avoiding misleading top-level `Cargo.toml` behavior and preventing cargo from treating the entire Git repository as a single crate, which currently supports downstream projects that vendor Git's C code while excluding its Rust components.
