This is the second patch in the v10 series introducing the `receive-report` hook, a refactoring that replaces the static boolean variables `report_status` and `report_status_v2` with an `enum report_status_version`. The patch is **internal-only**—no user-visible behavior changes—and is motivated by maintainability: the enum makes the mutually exclusive nature of the report status versions explicit and easier to extend.

The patch introduces the new `enum report_status_version` with three values: `REPORT_STATUS_UNKNOWN`, `REPORT_STATUS_V0`, and `REPORT_STATUS_V2`. The `REPORT_STATUS_UNKNOWN` case is now handled explicitly in the `switch` statement, replacing the previous `BUG()` call that assumed the client always requested a status report. This resolves Junio C Hamano’s critical design concern from v9, where clients omitting the `report-status` capability (e.g., older Git versions) would trigger a fatal error. The enum is passed by reference through `read_head_info()`, eliminating the need for static variables and making the data flow clearer.

The diff touches only `builtin/receive-pack.c`, converting the static variables into a local `enum report_status_version version` initialized to `REPORT_STATUS_UNKNOWN`. The `switch` statement in `cmd_receive_pack()` now dispatches to `report_v2()`, `report()`, or silently `break`s for `REPORT_STATUS_UNKNOWN`, matching the behavior of the original code but with improved clarity. The patch includes a `Helped-by` credit to Junio for the enum refactoring.

This patch is uncontroversial and addresses all prior feedback. The enum-based approach is strictly better than the static booleans, and the `REPORT_STATUS_UNKNOWN` handling is now robust. The only prior issue—a typo in the enum name (`REPORT_STATUS_UNKOWN` → `REPORT_STATUS_UNKNOWN`)—was fixed in v8. The patch is **ready for `master`** and has no known open questions.
