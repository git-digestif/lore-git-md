This is the cover letter for v5 of Patrick Steinhardt’s 9-patch series refactoring how Git handles ODB alternates during repository creation. The series is part of the ongoing ODB abstraction effort and aims to simplify the ODB interface by removing the ability to write alternates after repository creation.

The key changes in v5 are minor but clarify intent: `add_one_alternate` and `add_one_alternate_data` have been renamed to `collect_one_alternate` and `collect_alternates_data` to better reflect their role in gathering alternates paths. The `collect_alternates()` function has also been simplified by dropping an unused parameter, and the commit message for patch 5/9 now explains why `commondir` is computed even when unused (it will be needed in patch 6/9). These adjustments address feedback from Karthik Nayak and Justin Tobler in v4, focusing on naming and documentation clarity without altering the series’ core logic.

The series remains well-structured and uncontroversial. It defers ODB setup in `git clone` until after URI resolution, consolidates alternates logic into a single code path, and adopts the lockfile API for atomic alternates writes (resolving a security concern raised by Junio in v1). The patches are incremental, with no user-visible behavior changes, and the v5 updates are purely cosmetic. The series is now better documented and ready for integration, with all substantive feedback addressed. Reviewers may focus on the lockfile cleanup logic in patch 7/9 (error handling robustness) and the broader ODB abstraction goals, but the changes are otherwise mechanical and low-risk.
