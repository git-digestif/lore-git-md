This is a feature patch extending `git var` to expose individual identity components (name, email, date), commit signing keys, and support for multiple variable arguments with NUL-terminated output. It is the seventh iteration of a long-running series that implements the design consensus reached in prior discussion, replacing the earlier `git ident` proposal.

The patch is technically mature and addresses all substantive feedback from Junio’s and Phillip Wood’s high-weight reviews of v6. Key improvements in v7 include: streamlined documentation to avoid repetitive descriptions of identity variables, added `BUG()` checks in `ident_part()` to guard against future breakage in `split_ident_line()`, simplified multi-valued variable handling by making the `multiread` callback return `void`, and relaxed error handling to avoid non-zero exit codes for unset variables in multi-variable queries (matching Phillip Wood’s recommendation). The test suite now uses Git’s `nul_to_q` helper to avoid binary comparison errors in `-z` mode tests.

The implementation is clean and well-structured, using Git’s standard argument parsing (`parse_options()` with `PARSE_OPT_STOP_AT_NON_OPTION`) to enforce strict option-before-argument ordering. The new variables (`GIT_AUTHOR_NAME`, `GIT_AUTHOR_EMAIL`, `GIT_AUTHOR_DATE`, `GIT_COMMITTER_NAME`, `GIT_COMMITTER_EMAIL`, `GIT_COMMITTER_DATE`, and `GIT_SIGNING_KEY`) are exposed through a table-driven approach, and multi-valued variables (like `GIT_CONFIG_GLOBAL`) are handled via `string_list`-based callbacks. The `-z` output format aligns with `git config -z` (`key\nvalue\0`), and multi-variable queries print an extra delimiter after multi-valued variables to disambiguate the stream.

The patch touches `builtin/var.c`, `Documentation/git-var.adoc`, and `t/t0007-git-var.sh`, with no on-disk format changes or new configuration options. The motivation is clear: provide a unified, scriptable interface to Git’s identity and signing configuration, consolidating functionality that previously required parsing composite strings or querying multiple `git config`/`git var` invocations. The design avoids controversial choices, such as modifying existing commands or introducing new porcelain.

Junio’s v6 feedback on documentation conciseness and output format ambiguity is fully addressed, and Phillip Wood’s concerns about error handling strictness and test robustness are resolved. The only remaining loose end is the unresolved question about whether `GIT_SIGNING_KEY` alone is sufficient for callers to determine the signing mechanism (GPG/SSH/X.509), but this is not a blocker for integration. The patch is in `seen` and appears ready for `next` once Junio confirms the final polish meets his expectations.
