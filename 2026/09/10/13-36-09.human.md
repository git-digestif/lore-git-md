This is a maintainer response to a bugfix patch that is now ready for merging. Junio C Hamano’s reply to Kaartic Sivaraam’s v2 patch for the `git history reword` memory leak is brief and procedural rather than technical. He objects to the use of scissors lines (`-- 8< --`) in the commit message where they do not serve their intended purpose of excluding text from the final commit log. The scissors lines in the email are used to quote the ASAN leak report and reproduction steps, but Junio points out that they should only be used when the author explicitly wants to discard the text above them from the commit message. Here, the quoted material is meant to be preserved, so the scissors lines are misleading and should be removed or replaced with clearer formatting.

The patch itself is uncontroversial and well-motivated: it fixes a real leak in `git history reword` caused by missing cleanup of a commit buffer that bypasses the slab cache (likely due to commit-graph loading). The fix is a single line in `builtin/history.c` (`repo_unuse_commit_buffer`), and the commit message provides a thorough explanation, reproduction steps, and root cause analysis. The broader thread has already confirmed that the fix resolves the leak without regressions, and related leaks (e.g., in the topological walk slab) have been addressed separately.

Junio’s feedback is purely about presentation, not substance. The patch is otherwise merge-ready, and the discussion about whether to adjust the default ASAN leak detection settings (`detect_leaks=0` in `t/test-lib.sh`) is a minor tangent that does not affect the patch’s correctness. The fix is part of Patrick Steinhardt’s `git history` command work and touches commit buffer management and slab cache behavior.
