This is the cover letter for Vsevolod Myalitsin’s v4 patch series, which refines Git’s advice system to suggest the correct configuration scope when telling users how to disable advice messages. The series is now split into three focused patches: one to adjust the `vadvise()` interface, one to add a `scope_hint` field to advice settings, and one to assign the global scope to the `defaultBranchName` advice.

The motivation is clear and practical: when Git advises users to disable the `defaultBranchName` message during `git init`, the suggested command (`git config advice.defaultBranchName false`) writes to the local repository’s config, which is useless because the advice only appears during initialization and won’t repeat for that repository. The series fixes this by teaching the advice system to recommend `--global` for this setting, ensuring the change applies to future repositories.

The cover letter explains the problem, the solution, and the series structure concisely. The three-patch split follows Junio’s guidance from the v3 review, with each patch addressing a distinct step in the change. The mechanical feedback from Junio and Peff on v3 has been addressed in this reroll, and the series now looks ready for substantive review. No new technical questions are raised here; the focus is on landing the infrastructure and applying it to the one advice setting where the scope issue is most acute.

This is a well-scoped, uncontroversial improvement that should be easy to review and merge. The changes are confined to `advice.c`, and the commit messages are clear and focused. If the patches hold up under review, this looks like a straightforward win for usability.
