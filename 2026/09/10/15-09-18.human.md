This is patch 8/9 in Patrick Steinhardt’s nine-patch series refactoring ODB alternates handling during repository creation, part of the ongoing ODB abstraction effort. The patch wires up the alternates `strvec` collected by `collect_alternates()` to the ODB creation process via the new `odb_create_on_disk_options` struct, eliminating the manual alternates loop in `cmd_clone()` and preparing for the removal of the `write_alternates()` callback in the final patch.

The change is mechanical and straightforward: `create_object_database()` now accepts a `strvec` of alternates paths (or `NULL` for no alternates), and `cmd_clone()` passes the alternates `strvec` directly to `create_object_database()` instead of manually writing each alternate via `odb_add_to_alternates_file()`. The patch touches four files: `builtin/clone.c` (removing the manual alternates loop), `builtin/init-db.c` (updating `cmd_init_db()` to pass `NULL` for alternates, preserving existing behavior), `setup.c` (extending `create_object_database()` to accept the alternates `strvec` via `odb_create_on_disk_options`), and `setup.h` (updating the function signature and documentation). No new symbols are introduced, and the patch preserves existing behavior while simplifying the code.

This is a direct follow-up to patch 7/9, which implemented the core design change of writing alternates during ODB creation using Git’s standard lockfile API. The patch is uncontroversial and aligns with the series’ incremental approach, though it may attract scrutiny from reviewers focused on the lockfile cleanup logic or error handling in the alternates-writing loop (raised by Karthik Nayak in patch 7/9). The series remains a strong candidate for integration, with all substantive review feedback addressed and no open technical concerns for this specific patch. The final patch (9/9) will remove the now-unused `write_alternates()` infrastructure, completing the refactoring.
