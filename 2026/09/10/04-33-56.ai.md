This is a substantive review comment on Junio C Hamano’s refactoring patch in the advice subsystem. Jeff King (Peff) identifies two issues: the Coccinelle rule missed a few call sites with more complex conditionals (specifically in `commit.c`), and he raises a broader design question about whether the extra turn-off instructions shown by `advise_if_enabled()` would be perceived as ugly or overwhelming by users. The review is tested in the sense that Peff manually inspected the code and identified a concrete example (`commit.c`) that the automated transformation missed. The feedback is substantive because it engages with both the mechanical correctness of the patch and the user experience implications of the underlying design choice. This is not a blocker for the refactoring patch itself, but it does reopen the design discussion about the advice subsystem’s output consistency.
