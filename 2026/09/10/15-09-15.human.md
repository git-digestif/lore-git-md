This is the fifth patch in Patrick Steinhardt’s nine-patch series refactoring how Git handles ODB alternates during repository creation, part of the broader ODB abstraction effort. The patch moves the setup of alternates for shared local clones (`git clone --shared`) from `clone_local()` into the newly extended `collect_alternates()` function, consolidating all alternates logic into a single code path. This is a mechanical but important step toward deferring alternates writes until ODB creation, which will simplify the ODB interface and prepare for alternates to become an implementation detail of the "files" backend.

The patch adds `local_source_repo` and `is_local` parameters to `collect_alternates()` and includes a critical correctness fix: the `option_shared` guard ensures alternates are only added for shared local clones, addressing Justin Tobler’s feedback from v3 that the original implementation would incorrectly add alternates for non-shared local clones (`git clone --local --no-shared`). The change is minimal (14 insertions, 9 deletions) and preserves existing behavior while preparing for the removal of the `write_alternates()` callback in patch 9/9. The `commondir` computation (unused when `option_shared` is false) is intentional and prepares for patch 6/9’s consolidation of alternates logic for non-shared local clones.

This patch is uncontroversial and aligns with the series’ incremental approach. Karthik Nayak’s review of v4 raised a surface-level observation about the unused `commondir` computation, but Patrick Steinhardt has clarified the forward-looking design in the commit message. The patch is well-documented and addresses the correctness issue identified in earlier iterations, making it a solid step toward the series’ goal. Reviewers may focus on the `option_shared` guard to ensure it correctly isolates shared clones, but the fix appears correct and has been confirmed by Justin Tobler’s follow-up.
