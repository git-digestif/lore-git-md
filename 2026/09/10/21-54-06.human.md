This is a documentation patch, the first in Karthik Nayak’s four-part series introducing the `receive-report` hook. The series is queued in `next` and addresses GitLab’s need for server-side status filtering in their MVCC (multi-version concurrency control) system.

This patch plugs a small but noticeable gap in the `git-receive-pack` man page: it adds an eight-line `PROC-RECEIVE HOOK` section that explains when the `proc-receive` hook runs (when `receive.procReceiveRefs` is configured and the push commands match those refs) and what it does (executes commands instead of the internal `execute_commands()` function). The text is styled consistently with the surrounding hook documentation and links to `git-receive-pack(1)` for cross-reference. Patrick Steinhardt is credited with a `Helped-by` trailer.

The change is purely additive and uncontroversial; it merely documents an existing hook that was previously missing from the man page. No code or behavior is altered. This patch is ready for `master` and should graduate alongside the rest of the series.
