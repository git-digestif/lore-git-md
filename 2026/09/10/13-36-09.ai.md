This is a merge confirmation for a bugfix patch targeting a memory leak in `git history reword`. Junio C Hamano replies to Kaartic Sivaraam’s v2 patch with two minor editorial notes but no technical objections, signaling the patch is ready for integration.

The patch itself is a one-line fix in `builtin/history.c` (`commit_tree_ext`) that adds `repo_unuse_commit_buffer` to free a commit message buffer dynamically allocated by `repo_logmsg_reencode`. The buffer is not cached in Git’s commit slab because the commit comes from the commit-graph, which bypasses raw object parsing. The commit message is unusually thorough: it includes a full ASAN leak report, a clear root-cause analysis, a minimal reproduction recipe, and confirmation that the leak surfaces in the test suite (`t3451-history-reword.sh`) when `GIT_TEST_COMMIT_GRAPH=1` is set. Junio’s only substantive feedback is to avoid abusing scissors lines (`-- >8 --`) when the text is intended to be part of the commit message, not discarded.

The broader thread context confirms this leak is part of a systemic pattern in Git’s slab management, particularly when commit-graph is involved. The original patch resolves the `git history reword` leak and also fixes related test failures (`t345x`), while a separate patch (already merged) addressed a distinct leak in the topological walk slab (`init_topo_walk`). No regressions or design objections remain; the only open question is whether the intentional suppression of leak detection (`detect_leaks=0` in `t/test-lib.sh`) is still justified, though this is tangential to the patch’s correctness.

Key technical details for follow-up: the fix touches `builtin/history.c` (`commit_tree_ext`), interacts with `repo_logmsg_reencode`, `repo_get_commit_buffer`, and `repo_unuse_commit_buffer`, and is triggered by commit-graph loading. The reproduction command is `SANITIZE=leak GIT_TEST_COMMIT_GRAPH=1 make test`. The patch is narrowly scoped, well-motivated, and merge-ready.
