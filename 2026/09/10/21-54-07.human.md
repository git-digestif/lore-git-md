This is the second patch in the v10 series introducing the `receive-report` hook. It refactors how `git receive-pack` tracks the client’s requested status-report protocol version, replacing two static boolean variables (`report_status` and `report_status_v2`) with a single `enum report_status_version`. The enum includes a `REPORT_STATUS_UNKNOWN` sentinel value, which now triggers a silent `break` instead of a `BUG()` call when the client does not request a status report. This change is purely internal and makes the protocol-version switch more explicit and extensible.

The patch addresses Junio C Hamano’s earlier maintainability concern about the boolean parameters and resolves a critical design flaw identified in v9: the `BUG()` call in the `switch` statement assumed the client’s requested protocol version was always valid, but clients may omit the `report-status` or `report-status-v2` capability entirely. The fix (replacing `default: BUG(...)` with an explicit `REPORT_STATUS_UNKNOWN` case) is now applied and uncontroversial. The patch includes a `Helped-by` credit to Junio for the enum refactoring.

No user-visible behavior changes or test coverage are introduced here, as the patch is a mechanical refactoring. The change is a prerequisite for the core hook implementation in patch 4/4, which relies on the enum to handle the protocol version correctly. The patch is well-motivated and aligns with Git’s coding style, though it is unlikely to draw further discussion on its own.
