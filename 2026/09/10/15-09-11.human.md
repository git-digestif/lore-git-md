This is the first patch in Patrick Steinhardt’s 9-patch series refactoring ODB alternates handling, part of the ongoing ODB abstraction effort. The patch splits `init_db()` into three focused functions: `create_repository()`, `create_reference_database()`, and `create_object_database()`. This refactoring eliminates the need for skip flags (`SKIP_REFDB`, `SKIP_ODB`) and the `QUIET` flag, simplifying the interface and preparing for deferred ODB creation in `git clone`.

The core change is mechanical: `init_db()` is renamed to `create_repository()` and now only handles skeleton creation (directories, config, templates). Callers (`cmd_init_db()` and `cmd_clone()`) are updated to explicitly invoke `create_reference_database()` and `create_object_database()` afterward. The `reinit_ok` parameter replaces the `EXIST_OK` flag, allowing `git init` to detect reinitialization and print the correct status message. The patch also moves the initialization message from `init_db()` to `cmd_init_db()`, since it’s specific to that command.

This is a well-executed refactoring with clear benefits for the series’ goal of deferring ODB setup. The commit message explains the motivation thoroughly, and the new function names and documentation in `setup.h` improve clarity. Justin Tobler’s feedback from v3 (better documentation for `reinit_ok` and the new helpers) has been addressed. The patch is uncontroversial and aligns with the broader ODB abstraction effort. No user-visible behavior changes.
