This is a refactoring patch in the advice subsystem, posted by Junio C Hamano as a follow-up to the ongoing `defaultBranchName` advice documentation fix thread.

The patch mechanically converts existing code that checks `advice_enabled()` before calling `advise()` into direct calls to the newer `advise_if_enabled()` helper. This affects seven files (`advice.c`, `branch.c`, `builtin/am.c`, `builtin/checkout.c`, `builtin/submodule--helper.c`, `sequencer.c`, and a new Coccinelle rule in `tools/coccinelle/advice.cocci`) and removes 23 lines of boilerplate while preserving behavior. The Coccinelle rule automates most of the conversion, though Junio notes that manual edits were needed afterward to fix line wrapping and formatting.

The change is purely internal and does not alter user-visible behavior. It unifies the codebase toward the newer helper, which was introduced in 2020 specifically for cases where turn-off instructions are desired. Earlier in the thread, Junio and Jeff King clarified that the existing pattern—checking `advice_enabled()` before expensive work and then calling `advise()`—is intentional and should not be mechanically converted everywhere, but this patch targets only the subset of callers where the turn-off instructions are appropriate.

The patch is low-risk and ready for review. It does not block the core `defaultBranchName` fix, which is already effectively ready for merging in its v3 iteration. The only loose end is a minor manual cleanup of line wrapping, but this is not a blocker.
