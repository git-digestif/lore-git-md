This is the second patch in a **bugfix series** (v3, 2/2) targeting the `--force-if-includes` safety mechanism in `git push`. The series is **technically complete and ready for merge**, with this patch addressing a misleading advice message when `--force-if-includes` rejects a push from a detached HEAD state.

The patch introduces a new `ref->unverifiable` flag to distinguish detached HEAD rejections from remote-update rejections, ensuring users receive actionable advice. Currently, when `--force-if-includes` rejects a push from a detached HEAD (where no per-branch reflog exists to verify the remote tip), the advice incorrectly suggests running `git pull`, which cannot resolve the issue. The fix replaces this with a clear message instructing users to either specify the expected remote tip via `--force-with-lease=<ref>:<expect>` or bypass the check with `--no-force-if-includes`.

Key changes include:
- A new `ADVICE_PUSH_REF_UNVERIFIABLE` enum and corresponding `advice.forceIfIncludesDetachedHead` config knob (documented as `advice.pushRefUnverifiable`).
- Updates to all transport layers (`builtin/push.c`, `send-pack.c`, `transport-helper.c`, `transport.c`) to handle the new `REF_STATUS_REJECT_UNVERIFIABLE` status and display the correct advice.
- Eight new test cases in `t/t5533-push-cas.sh` verifying the advice message for detached HEAD scenarios and mismatched local/remote branch names.

The patch touches 12 files, including core logic in `remote.c` (where the `unverifiable` flag is set) and `advice.c` (where the new advice message is defined). No on-disk format changes are introduced. The series has received **substantive review** from D. Ben Knoble, who confirmed the root cause and verified the fix, and Junio C Hamano, who noted only a procedural threading issue (now resolved in v3). The series is based on `maint`.
