This is a refactoring patch in the advice subsystem, part of the ongoing `defaultBranchName` advice documentation fix thread. Junio C Hamano demonstrates a mechanical conversion of existing `advice_enabled()` + `advise()` call sites to the newer `advise_if_enabled()` helper, using a Coccinelle semantic patch to automate the bulk of the work. The patch touches seven files (`advice.c`, `branch.c`, `builtin/am.c`, `builtin/checkout.c`, `builtin/submodule--helper.c`, `sequencer.c`, and a new `tools/coccinelle/advice.cocci` rule) and replaces 23 lines of conditional logic with 24 lines of direct calls, reducing boilerplate while preserving behavior.

The change is motivated by the earlier discussion in the thread: `advise_if_enabled()` was introduced in 2020 to show turn-off instructions, but most advice callers still use the older pattern (`if (advice_enabled(...)) advise(...)`) to avoid unnecessary work when the advice is disabled. This patch mechanically unifies the codebase toward the newer helper, which Jeff King and Junio agreed is acceptable as long as the redundancy is not problematic. The Coccinelle rule is straightforward, but Junio notes that most hunks required manual editing afterward to fix line wrapping and formatting.

This refactoring does not affect the core `defaultBranchName` patch (v3 is still ready for review), but it does address the broader design question raised earlier: whether the advice subsystem should consistently use `advise_if_enabled()` everywhere. The patch answers "yes" for the existing callers, though the intentional distinction between `advise()` (for performance) and `advise_if_enabled()` (for turn-off instructions) remains intact. No new advice keys or behaviors are introduced; this is purely internal cleanup.

The patch is low-risk: it changes only control flow, not output, and the Coccinelle rule ensures the transformation is systematic. However, the manual edits afterward suggest that a follow-up might be needed to clean up formatting. The new `.cocci` file is a welcome addition to the tooling, making future advice-related refactorings easier. No test failures are expected, and the patch does not alter on-disk formats or user-visible behavior.
