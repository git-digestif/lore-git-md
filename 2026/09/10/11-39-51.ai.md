This is a bugfix patch (v2) targeting a memory leak in `git history reword`, part of Patrick Steinhardt’s `git history` command series. The patch is now merge-ready and addresses a systemic issue in Git’s commit buffer management when commits are loaded from the commit-graph.

The leak occurs in `builtin/history.c`’s `commit_tree_ext` function, where `repo_logmsg_reencode()` retrieves a commit message buffer that is not cached in the commit slab (likely because the commit comes from the commit-graph). The buffer is dynamically allocated by `odb_read_object` but never freed, as the required `repo_unuse_commit_buffer` call is missing. The fix adds this single-line cleanup call, following the established pattern for managing uncached commit buffers.

The commit message is thorough and well-structured: it includes a full ASAN leak report, a clear explanation of the root cause (commit-graph bypassing slab caching), a minimal reproduction recipe, and confirmation that the leak surfaces in the test suite (`t3451-history-reword.sh`) when `GIT_TEST_COMMIT_GRAPH=1` is set. The author also notes that the leak is only detectable when `SANITIZE=leak` is used, not with the default `SANITIZE=address,leak` (due to `detect_leaks=0` being set in `t/test-lib.sh`), and questions whether this intentional suppression of leak detection is still justified.

This patch is a targeted fix for a real, reproducible bug, and the discussion in the thread confirms it resolves the issue without introducing regressions. The broader thread has already addressed related leaks (e.g., in the topological walk slab), so this patch is narrowly scoped to the `git history reword` case. The author’s question about `detect_leaks=0` is a minor tangent and not critical to the patch’s correctness.

- **Reproduction**: `SANITIZE=leak GIT_TEST_COMMIT_GRAPH=1 make test` (specifically `t3451-history-reword.sh`).
