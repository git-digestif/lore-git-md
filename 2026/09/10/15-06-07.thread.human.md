This thread is about a bugfix for resource cleanup in Git’s low-level merge driver infrastructure. When a user interrupts an external merge driver (e.g., with Ctrl+C), temporary files like `.merge_file_*` were not being removed, leaving clutter behind. Michal Koutný initially proposed a fix, but Jeff King (Peff) later submitted a refined three-patch series (`v2`) that replaces the original signal-handling approach with Git’s established `tempfile` API, ensuring atomic cleanup even on abrupt termination.

The series is now technically complete and addresses the core issue without changing functionality—only improving robustness. It touches only `merge-ll.c`, refactoring file handling to use `strbuf` and `tempfile` objects, and fixes a minor error-checking bug along the way. Michal tested the changes for both normal and interrupted scenarios, confirming they work as intended, though there’s no automated test coverage for interrupt handling yet. The patches are well-documented and uncontroversial, with no substantive objections remaining.

Peff’s submission is ready for review and likely to be merged once Junio picks it up. The only loose ends are the lack of automated tests for edge cases (a minor point) and the usual integration process. No merge status has been reported yet, so the series is still under review. Key participants are Peff (author of the final version) and Michal (original reporter and tester), with Jean Delvare having initially reported the issue.
