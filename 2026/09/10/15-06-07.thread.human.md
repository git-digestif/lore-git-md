This thread is a bugfix patch series addressing resource cleanup in Git’s low-level merge driver infrastructure when interrupted by signals like SIGINT (Ctrl+C). The series, originally authored by Michal Koutný and now in its third iteration (v3) prepared by Jeff King (Peff), ensures temporary files created during external merge operations are reliably removed even if the process is abruptly terminated. The solution replaces custom signal handling with Git’s `tempfile` API for atomic, signal-safe cleanup, while also modernizing adjacent code—such as replacing manual buffer management with `strbuf` and fixing latent robustness issues like ignored `close()` errors after successful `write()` calls.

The series is uncontroversial and nearly ready for inclusion. The latest update, a minor stylistic tweak to the error-handling code in `create_temp()`, was proposed by Peff to avoid a subtle pattern that could mislead future contributors into introducing file descriptor leaks in other contexts. The change splits a combined `die_errno()` check for `write_in_full()` and `close()` failures into two separate statements, making the intent clearer without altering behavior. This adjustment, along with the previously agreed type-safety fix for a latent bug in the `strbuf`-based refactoring (a `die()` check for oversized files), will be included in v3. Elijah Newren and Junio C Hamano have endorsed the type-safety fix, and Elijah also confirmed the correctness of the `close()` error handling in an earlier version. No substantive objections remain, and the series aligns with Git’s established patterns for resource cleanup and defensive programming.

The patches touch only `merge-ll.c`, refactoring `ll_ext_merge()` to use the `tempfile` API and introducing a new helper, `temp_path_basename()`, for backward compatibility with merge drivers using shell metacharacters. The series has been lightly tested for interrupt scenarios, though Peff and Michal agreed automated tests are unnecessary, as the new behavior is preferable for users and temporary files are not needed for debugging. The series is not yet queued in Junio’s integration branches (`pu`, `next`, or `master`). Key participants include Peff (driving the series), Michal Koutný (original author), Elijah Newren (substantive reviewer), and Junio (maintainer).
