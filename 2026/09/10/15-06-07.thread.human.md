This thread is a bugfix patch series by Michal Koutný, now being shepherded by Jeff King (Peff), that ensures temporary files created during external merge driver execution are reliably cleaned up even when the process is interrupted by SIGINT or SIGQUIT. The series has evolved through two versions and is now ready for a third, addressing a latent type-safety bug in the `strbuf`-based refactoring that could cause buffer overreads on LLP64 platforms like Windows.

The core issue—temporary files (`.merge_file_*`) being left behind after an interrupt—is resolved by replacing custom signal handling with Git’s `tempfile` API, which guarantees atomic, signal-safe cleanup. Alongside this, the series modernizes adjacent code, replacing manual buffer management with `strbuf` and tightening error handling (e.g., treating `close()` errors after `write()` as fatal). Elijah Newren provided substantive review, confirming the correctness of these changes and identifying the type-safety bug, which Peff will fix in v3 with a `die()` check for oversized files. The series also includes a backward-compatibility helper (`temp_path_basename()`) for merge drivers using shell metacharacters in command templates.

The latest exchange between Peff and Michal reaffirms the design choice to prioritize cleanup over preserving merge output for debugging, dismissing the idea as unnecessary for users. No objections remain, and the series is uncontroversial, aligning with Git’s established patterns for resource management. The only pending work is Peff’s v3 submission, which will include the type-safety fix and a minor stylistic improvement to split a combined error check for clarity.
