This thread is a three-patch bugfix series addressing a longstanding resource cleanup issue in Git’s low-level merge driver infrastructure. The problem occurs when an external merge driver is interrupted by SIGINT or SIGQUIT (e.g., via Ctrl+C): temporary files (`.merge_file_*`) created during the merge are left behind because the signal propagates to the parent `git merge` process, preventing cleanup handlers from running. Jeff King (Peff) took over the series from original reporter Michal Koutný and submitted v2, which replaces custom signal handling with Git’s `tempfile` API for atomic, signal-safe cleanup. The series also modernizes adjacent code, such as replacing manual buffer management with `strbuf` and fixing latent robustness issues (e.g., treating `close()` errors after `write()` as fatal).

The series is technically complete but requires a v3 to address a latent type-safety bug in the first patch, where a type mismatch between `result->size` (`long`) and `strbuf_detach()` (`size_t`) could cause buffer overreads on LLP64 platforms like Windows. Elijah Newren identified the issue and proposed a targeted fix (a `die()` check for file sizes exceeding `LONG_MAX`), which Junio C Hamano has endorsed as a sensible mitigation. The second patch, ensuring `close()` errors are treated as fatal, received substantive confirmation from Elijah, while the third patch (completing the `tempfile` transition) was approved with minor commit-message nits. Michal Koutný tested the series for SIGINT cleanup and agreed with Peff that automated tests for interrupt scenarios are unnecessary.

The only remaining loose end is the type-safety fix, which Peff will incorporate into v3. The series is uncontroversial and aligns with Git’s established patterns for resource cleanup and defensive programming. Once v3 is posted, it should be ready for merging, though no merge status has been reported yet (it’s not in `pu`, `next`, or `master`). Key participants include Peff (author of v2), Michal (original reporter), Elijah (substantive reviewer), and Junio (endorsed the type-safety fix). The latest exchange was a minor clarification about commit-message attribution, with Michal preferring a `Reported-by:` trailer over Elijah’s suggested tweak—no technical changes were needed.
