This thread is about a bugfix patch from Michal Koutný that ensures temporary files (`.merge_file_*`) created during external merge driver execution are properly cleaned up even when the process is interrupted by SIGINT/SIGQUIT (e.g., via Ctrl+C). The issue occurs because signals sent to the external merge driver propagate to the parent `git merge` process, preventing cleanup handlers from running.

Michal's initial patch addressed this by adopting a signal-handling idiom from `editor.c`, using `sigchain_push`/`sigchain_pop` to temporarily ignore signals during child termination while preserving interrupt behavior. However, Jeff King (Peff) responded with a **substantive review** proposing a cleaner alternative: leveraging Git's existing `tempfile` API, which already handles signal propagation and atomic cleanup. Peff's approach refactors `ll_ext_merge()` to use `struct tempfile` objects, eliminating the need for custom signal handling while maintaining the same cleanup guarantees. His review includes a complete, lightly tested patch that replaces manual file management with `tempfile`-based helpers (`create_temp()`, `get_temp_path()`), aligning the solution with Git's established patterns.

No objections to the original problem statement have been raised, and the discussion has shifted toward evaluating Peff's more idiomatic solution.
