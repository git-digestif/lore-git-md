This thread addressed a bugfix series to ensure Git reliably cleans up temporary `.merge_file_*` files when external merge drivers are interrupted by signals like SIGINT (Ctrl+C). Originally reported and prototyped by Michal Koutný, the series was refined and submitted as v3 by Jeff King (Peff), incorporating feedback from Elijah Newren and Junio C Hamano. The solution replaced custom signal handling with Git’s `tempfile` API for atomic, signal-safe cleanup, while also modernizing adjacent code (e.g., replacing manual buffer management with `strbuf`) and fixing latent issues like type-safety bugs and error-handling gaps.

The series—two patches in its final form—was merged to Junio’s `next` branch on July 10, 2024, and is now uncontroversial. All prior feedback was addressed, including a stylistic improvement to split error checks in `create_temp()`, a commit-message tweak for precision, and a critical type-safety fix for oversized files. The backward-compatibility trade-off (preserving relative paths for shell metacharacters) was explicitly approved by Junio. Michal Koutný confirmed in this latest email that the merged patches achieve the original goal: users will no longer encounter leftover temporary files after interrupts. The series is expected to graduate to `master` in the next integration cycle, with no open questions or follow-up work remaining.
