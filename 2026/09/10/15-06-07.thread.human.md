This thread is a focused bugfix series addressing a long-standing resource cleanup issue in Git’s low-level merge driver infrastructure. The problem: when a user interrupts an external merge driver (e.g., with Ctrl+C), temporary files like `.merge_file_*` aren’t reliably deleted, leaving clutter behind. The solution, now complete in its third patch, replaces custom signal handling with Git’s `tempfile` API, ensuring atomic, signal-safe cleanup without changing the user-facing behavior.

Jeff King (Peff) took the lead on this iteration, refining Michal Koutný’s original work with feedback and testing. The series touches only `merge-ll.c`, modernizing the code with `strbuf` for file I/O and tightening error handling (e.g., treating `close()` errors as fatal after successful writes). A small helper function, `temp_path_basename()`, preserves backward compatibility with user-configured merge drivers by stripping absolute paths to relative ones—though Peff notes this sidesteps shell-quoting for stability, a minor trade-off. Michal confirmed the fix works for SIGINT, and while there’s no automated test coverage for interrupt scenarios, the changes are otherwise uncontroversial and align with Git’s established patterns.

The series is technically complete and ready for review, with no substantive objections or merge status reported yet. It’s a joint effort between Peff and Michal, with Peff driving the final submission. The only loose ends are the lack of automated tests for interrupts and a noted (but unaddressed) type mismatch in `result->size`, neither of which are blockers. Expect this to land smoothly once Junio picks it up.
