This thread is about a bugfix patch from Ariel Keselman that prevents Git from taking an unnecessary lock on `packed-refs` when deleting root refs (like `HEAD` or `refs/heads/main`). Root refs cannot be packed, so the lock was redundant and caused spurious errors in linked worktrees with read-only shared metadata.

The patch is now in its second version, responding to feedback from Patrick Steinhardt. The core fix remains the same—skipping the `packed-refs` lock for root refs—but the in-code comment is now more general, and the test coverage is streamlined. The original seven tests are replaced with two focused cases: one verifying that deleting a root ref succeeds even when `packed-refs.lock` is held, and another ensuring that a transaction deleting both a root ref and a packed branch fails if the lock is held (preventing partial success). This addresses Patrick’s concern about mixed transactions.

The patch touches only `refs/files-backend.c` and adds tests to `t/t0600-reffiles-backend.sh`. It has no impact on on-disk format or CLI behavior. Ariel confirms the fix resolves the regression and passes broader test suites, including SHA-256 validation. The discussion is now focused on whether the revised tests adequately cover the edge cases, with no further objections raised. The patch appears ready for integration unless new concerns emerge.
