This thread is about a bugfix patch from Ariel Keselman that prevents Git from taking an unnecessary lock on `packed-refs` when deleting root refs (like `HEAD` or `refs/heads/main`). Root refs can't be packed, so the lock is redundant and causes spurious errors in linked worktrees when the shared metadata directory is read-only. The patch is narrowly scoped, touching only `refs/files-backend.c` and adding seven regression tests that fail without the fix and pass with it.

Patrick Steinhardt reviewed the patch and agreed with the core idea but suggested a few improvements. He recommended tweaking the in-code comment to keep it general rather than root-ref-specific. More importantly, he found the test coverage excessive—testing one root ref in one state would suffice—and identified a missing test case: a transaction that updates both a root ref and a non-root ref while a `packed-refs.lock` already exists. The current patch might incorrectly allow the root ref portion to proceed, which could introduce a subtle bug. He also questioned the need for `core.packedRefsTimeout` in the tests, as it doesn’t affect the outcome.

The patch is under review, with no prior versions or related work. The author used AI assistance to generate the patch, tests, and commit message, but the contribution is technically sound and addresses a real-world issue. The next step is likely a revised version incorporating Patrick’s feedback, particularly the missing test case.
