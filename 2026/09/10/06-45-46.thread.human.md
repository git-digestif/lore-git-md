This thread is about a bugfix patch that prevents Git from taking an unnecessary lock on `packed-refs` when deleting root refs like `HEAD` or `AUTO_MERGE`. The issue surfaces in linked worktrees when the shared metadata directory is read-only, causing spurious failures during post-commit cleanup. Ariel Keselman posted v2 of the patch, which modifies `files_transaction_prepare()` in `refs/files-backend.c` to skip packed-ref transactions for root refs using a new `is_root_ref()` helper. The patch includes two regression tests and has passed broader test suites.

Patrick Steinhardt reviewed v2 and suggested minor but meaningful improvements to the test coverage, such as verifying that `AUTO_MERGE` isn’t packed after `git pack-refs --all` and strengthening the mixed-transaction test by capturing the full ref state. He also proposed small test-script cleanups. The core fix remains uncontroversial and addresses a real-world regression. Ariel is likely to post a v3 incorporating Patrick’s feedback, but the patch is already technically sound and ready for merging once the tests are finalized. No open questions or conflicts remain.
