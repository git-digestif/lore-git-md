This is the ninth patch in Johannes Schindelin’s 13-patch series **upstreaming Git for Windows build and runtime adjustments** into the main Git codebase. The series is already cooking in `next`; this iteration (v4) is a polish pass after v3 was merged.

This specific patch **stops building and linking the deprecated dashed-form executables** (e.g., `git-commit`) on Windows. The dashed form has been officially deprecated since Git 1.5.4 (2008), but the hard-links have persisted for backwards compatibility. On Windows, these hard-links add noticeable build time (about 30 seconds per build), confuse some Windows Explorer versions into reporting inflated disk usage, and generate recurring "bug" reports. The patch sets `SKIP_DASHED_BUILT_INS = YabbaDabbaDoo` in `config.mak.uname` for both the generic Windows and MINGW sections, effectively skipping the linking step.

The change is **Windows-only** and does not affect non-Windows platforms. It is a step toward eventually removing dashed-form executables entirely (a goal Junio has mentioned for Git 3.0), but this patch alone does not break existing scripts that still use the dashed form — it merely stops producing the hard-links during the build. The commit message positions this as a **phased deprecation** specific to Git for Windows, aligning with the series’ overall goal of reducing Windows-specific friction without disrupting other platforms.
