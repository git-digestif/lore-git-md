This is the **core implementation patch (4/4)** of the `receive-report` hook series, now in its **v10 iteration** and **queued in `next`**. The patch introduces the new hook, which allows server administrators to intercept and modify Git’s push status report before it is sent to the client. The hook is motivated by GitLab’s MVCC (multi-version concurrency control) system, where the status report must reflect the repository state *after* all server-side operations—including those beyond `ref_transaction_commit()`—are complete.

The hook acts as a bidirectional filter: it receives the pkt-line encoded status report on stdin, replaces it with its stdout, and forwards stderr to the client via sideband. A non-zero exit rewrites all ref status lines to `"receive-report hook failed"` and overwrites `cmd->error_string` fields (now with a memory leak fix in this version). The commit message explicitly acknowledges the **consistency trade-off**: the hook can report a push as failed (`ng`) while still committing ref updates, violating Git’s traditional principle that remote-tracking branches reflect the server’s state. This divergence is justified by GitLab’s use case, where conservative client-side behavior (not updating remote-tracking branches when the hook reports `ng`) is the desired outcome.

The patch adds the hook implementation in `builtin/receive-pack.c`, including the `run_receive_report_hook()` and `override_cmds_error()` helpers, and documents the hook in `githooks.adoc` and `git-receive-pack.adoc`. The documentation explains the hook’s three ways of affecting push outcome: rewriting individual ref status lines, aborting the entire push (non-zero exit), and modifying the `unpack` status line. The **257-line test suite** (`t/t5412-receive-report-hook.sh`) covers passthrough behavior, failure modes, stdin/stdout handling, sideband relay, and the hook’s ability to modify the `unpack` status line and individual ref statuses. The memory leak fix in `override_cmds_error()` (using a new `error_string_owned` flag) is now verified by a dedicated test case.
