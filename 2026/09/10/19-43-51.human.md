This is the second patch in a two-part contributor housekeeping series that keeps Git’s documentation build system in sync. The patch extends `lint-manpages.sh` to automatically verify that every non-command manual page (concept guides and interface manuals like `gitformat-loose(5)` and `gitpacking(7)`) is listed in `command-list.txt`. If any are missing, the linter now fails, acting as a regression test for future omissions.

The change is straightforward and well-executed. It introduces a `MAN_GUIDES` variable in the Makefile, derived from `MAN5_TXT` and `MAN7_TXT`, and updates the linter to check these against `command-list.txt`. The patch also exempts `gitweb.conf(5)` to avoid a confusing display name in `git help -a`. Junio’s feedback from v1 (quoting fixes for paths with spaces) is incorporated, and the commit message clearly explains the motivation and mechanics.

This is a sensible, low-risk improvement to Git’s documentation hygiene. The linter enhancement will catch similar omissions early, and the patch itself is uncontroversial. The series is ready for acceptance pending maintainer re-review. No further discussion or follow-up work is expected.
