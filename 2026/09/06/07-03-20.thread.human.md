This thread is a design discussion about what the next major Git release after 2.56 should be called—3.0, a transitional version like 2.99, or something else—and whether it should include user-facing breaking changes to defaults. Junio C Hamano kicked off the discussion, outlining four options and calling for input. The conversation has since expanded to include sub-discussions on readiness criteria for 3.0 (like SHA-256 support on GitHub and the lowercase-only object IDs series), whether 3.0 should include breaking changes to defaults (firmly rejected by Junio for this release), and how Git might responsibly evolve defaults in the future.

Key participants include Junio, who has ruled out breaking changes for 3.0 and framed the transitional version as a warning mechanism for downstream projects; brian m. carlson, who advocates for a cautious delay to allow foundational work to stabilize; Emily Shaffer, who emphasizes GitHub’s SHA-256 support as a critical gap; and Phillip Wood, who proposed a `core.defaults` meta-config variable to let users opt into modern settings without disruptive changes. Jeff King (Peff) recently weighed in with skepticism about `core.defaults`, arguing that if a default change is disruptive enough to need an opt-out mechanism, it’s just as disruptive whether users opt out via `core.defaults` or by overriding individual settings. His review underscores the difficulty of predicting real-world impact and suggests the project’s cautious approach may be the least risky path.

No decision has been reached on the version number, but the discussion has narrowed to practical concerns about how to modernize defaults without causing disruption. The transitional version (e.g., 2.98) remains a candidate as an advance warning mechanism, while 3.0 is still on the table if outstanding issues like GitHub’s SHA-256 support and the lowercase-only object IDs series are resolved. The thread is now focused on whether tools like `core.defaults` or a configuration analysis tool could provide a middle ground between inertia and progress.
