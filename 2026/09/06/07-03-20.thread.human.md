This thread is a design discussion about what version number Git should use for its next major release after 2.56, scheduled for late September 2026. Junio C Hamano, the maintainer, kicked off the conversation by outlining four options: jump straight to 3.0, use a transitional version like 2.99, pick an intermediate number like 2.97 or 2.95, or stick with incremental numbering (2.57). The core question is whether the project is ready for a 3.0 release, given unresolved breaking changes and ecosystem compatibility concerns, particularly around SHA-256 support on major forges like GitHub.

Brian M. Carlson initially advocated for a cautious delay (option 3: 2.97 or 2.95), citing the need for more time to stabilize foundational work like the lowercase-only object IDs series. His position was partly undermined when Patrick Steinhardt noted that two of Carlson’s technical blockers—libgit2’s SHA-256 and reftable support—are now resolved. Emily Shaffer later emphasized GitHub’s SHA-256 support as the most critical unresolved gap, given its market dominance, while acknowledging that the project isn’t obligated to wait indefinitely. Randall S. Becker’s recent update revealed progress toward Rust platform support (including NonStop), though details remain under NDA, further weakening Carlson’s earlier exclusion of Rust as a blocker. Carlson’s latest reply acknowledges this progress but doesn’t alter his stance on version numbering, leaving the core questions unanswered.

The thread remains in the discussion phase, with no consensus or maintainer decision yet. Key unresolved issues include the status of the lowercase-only object IDs series, whether GitHub’s SHA-256 support will arrive in time, and how to balance readiness with ecosystem expectations. Downstream tools like Jujutsu and GitOxide have varying levels of SHA-256 support, and large organizations like Google may mitigate compatibility issues via configuration. The project’s next steps hinge on whether the remaining work can be completed in time for the September release or if a transitional version would better signal intent while allowing more time for stabilization.
