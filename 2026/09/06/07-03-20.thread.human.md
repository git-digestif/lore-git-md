This thread is a design discussion about what the next Git version number should be after 2.56, scheduled for late September 2026. Junio C Hamano opened the conversation by laying out four options: jump straight to 3.0, use a transitional version like 2.99, increment to 2.97 or 2.95, or stick with the usual 2.57. The main sticking point is whether the project is ready for a major version bump, particularly around SHA-256 support on major forges like GitHub and the unresolved lowercase-only object IDs series.

Brian M. Carlson has been the most vocal advocate for caution, arguing that key foundational work—especially the lowercase-only object IDs series—needs more time to stabilize before a 3.0 release. His position was partially undercut by Patrick Steinhardt, who noted that two of Carlson’s technical blockers (libgit2’s SHA-256 and reftable support) are now resolved. Emily Shaffer added that GitHub’s SHA-256 support is the most critical gap, given its market dominance, but the project isn’t obligated to wait indefinitely. The latest input from Randall S. Becker, the NonStop port maintainer, introduces a new wrinkle: Rust platform support (which Carlson had dismissed as a non-blocker) may arrive sooner than expected, though details are still under NDA. This doesn’t change the immediate decision but could ease long-term concerns about Rustification.

No consensus has emerged yet, and Junio hasn’t tipped his hand on which option he prefers. The unresolved questions remain: whether the lowercase-only object IDs series will be ready in time, how much weight to give GitHub’s SHA-256 support (or lack thereof), and whether a transitional version like 2.99 would better signal the project’s intent. The thread is still in the discussion phase, with no clear path forward.
