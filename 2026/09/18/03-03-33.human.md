This is the third patch in a five-part bugfix series that plugs a data-loss race in `git repack -d` when concurrent pushes create `.keep` files mid-repack. The series is under active review and targets the repack/ODB subsystem.

This patch is a **performance optimization** in `git pack-objects`. It sorts the `--keep-pack` list once and replaces linear scans with binary search (`string_list_has_string`), cutting the time to match 20,000 kept packs against 20,000 repository packs from 11 seconds to under 1 second. The change is internal-only: the comparison function (`fspathcmp`) and matching semantics remain unchanged, so no behavior changes are introduced.

The patch touches only `builtin/pack-objects.c` and is a prerequisite for patch 4/5, which adds `--keep-pack-from-file` to handle repositories where the number of kept packs exceeds command-line limits. The optimization is well-motivated and unlikely to be controversial, though reviewers may verify that the sorted list does not interact poorly with future callers expecting insertion order. The commit message clearly explains the problem and solution, and the code change is minimal and focused.
