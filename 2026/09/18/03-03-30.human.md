This is the **v2 cover letter** for a **bugfix series** targeting the `git repack` machinery. The series fixes a race condition where `git repack -d` can delete packs whose objects were never copied elsewhere, leading to data loss (dangling refs pointing to nonexistent commits). The issue was observed in production on Git 2.43 and reproduces on `master`.

The root cause is a timing window between when `repack` scans for `.keep` files (to decide which packs to delete) and when `pack-objects` (spawned with `--honor-pack-keep`) does its own scan. If a concurrent push or fetch finishes migrating its quarantine during this window—dropping a duplicate pack but linking its `.keep` onto an older pack—`pack-objects` will skip the pack’s objects, but `repack` will still delete it based on its stale snapshot.

The **v2 series drops the first patch** from v1 (which prevented `receive-pack` from removing `.keep` files it didn’t create) in favor of Justin Tobler’s ODB-focused series, which will handle `.keep` file ownership more cleanly by having the ODB transaction create the `.keep` itself at commit time. The remaining five patches (unchanged except for renumbering) focus on eliminating the race by passing `pack-objects` the exact list of `.keep` packs that `repack` observed at startup, rather than letting it rescan. This is done via a new `--keep-pack-from-file` option (patch 4/5) and a snapshot-based approach (patch 5/5).

The series also includes **critical groundwork**:
- Patch 1/5 aligns `--stdin-packs=follow` behavior with on-disk `.keep` packs by treating `--keep-pack` packs as traversal blockers (like `^` packs).
- Patch 2/5 fixes a pre-existing bug where the cruft walk uses a stale kept-pack cache, masked by `--honor-pack-keep`.
- Patch 3/5 optimizes `--keep-pack` name lookups by sorting the list, enabling scalability for repositories with many kept packs.

The series is **well-tested**: each fix is validated by a test that fails without it, and the race itself is reproduced in `t7703-repack-geometric.sh`. All tests pass, and the series merges cleanly into `next` and `seen`. Key files touched include `builtin/pack-objects.c`, `builtin/repack.c`, and `packfile.c`, with new plumbing in `packfile.h` and `tempfile.h`.

This is a **serious, production-tested fix** for a subtle but critical data-loss bug. The commit messages are clear, the tests are comprehensive, and the design avoids introducing new races. The series is likely to attract attention from maintainers of the repack and ODB subsystems (e.g., Patrick Steinhardt, Taylor Blau) and may prompt discussion about the trade-off between safety and disk space (alternate ODB packs are now packed rather than skipped). The withdrawal of the first patch in favor of Justin Tobler’s ODB-focused series simplifies the fix and aligns with the project’s preference for architectural clarity.
