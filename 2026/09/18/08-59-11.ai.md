This is a substantive review reply in the ongoing discussion about the GPG signature-prefix matching patch (2/7) in Johannes Schindelin’s Git for Windows hardening series. Junio C Hamano responds to Johannes’s defense of propagating a `slen` (signature length) parameter through `check_signature()` and its callers, arguing that the parameter is redundant and that the patch’s approach is unnecessarily invasive.

Junio’s core position is that the audit of existing callers shows `slen` is redundant: all current callers pass a NUL-terminated string (either directly from a `strbuf` or an offset sub-buffer that still ends at a NUL), so the length parameter does not add safety. He proposes an alternative design that would remove `slen` entirely, forcing all callers to pass NUL-terminated strings and eliminating the need for length-aware checks in `get_format_by_sig()`. This would simplify the API and avoid propagating a new parameter through multiple layers.

The reply also reveals a philosophical difference: Junio frames the choice as a trade-off between minimalism and robustness, suggesting that once code is written and reviewed, the marginal benefit of changing it is not worth the cost. He explicitly acknowledges that the difference between the two approaches is small, implying that the patch’s current design is acceptable but not ideal. This stance leaves the door open for Johannes to either accept the simplification or defend the current patch as a necessary hardening measure, setting up a narrow but substantive technical disagreement about API design and defensive programming.
