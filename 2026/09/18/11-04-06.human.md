This is a bugfix patch targeting the `git status --ignored` command. René Scharfe addresses a long-standing regression where pathspec substring matching incorrectly includes ignored directories containing nested repositories. The issue was introduced in 2020 by commit `95c11ecc73` and partially fixed later for files and symlinks, but the corner case for ignored directories with nested repos remained broken.

The patch modifies `dir.c` to ensure pathspec matching is performed even for excluded directories when they contain a nested repository. This restores the expected behavior where `git status --ignored -- ba` only matches directories named exactly `ba`, not those containing `ba` as a substring (like `bar/`). The fix is minimal and surgical—it adds a helper function `dir_match()` to avoid code duplication and ensures the pathspec check happens in all necessary cases.

A new test case is included in `t/t7061-wtstatus-ignore.sh` to verify the fix. The test confirms that `git status --porcelain --ignored` correctly omits an excluded directory when the pathspec is only a prefix match. The patch is well-motivated, clearly explaining the regression and the fix, and the test coverage is appropriate for the scope.
