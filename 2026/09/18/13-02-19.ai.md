This is **patch 5/6 of Derrick Stolee’s RFC series introducing a "safe" `strbuf` API** that cannot call `die()`. The series aims to harden low-level libraries like trace2 by eliminating transitive `die()` calls from memory allocation failures.

This patch **prepares `json-writer.c` to adopt the safe API** by switching its header inclusion from `strbuf.h` to `strbuf-safe.h`. The change is mechanical but has ripple effects: `json-writer.h` previously exposed `strbuf.h` to its includers (notably trace2’s event and perf targets), so those files now explicitly include `strbuf.h` to maintain their existing dependencies. The patch itself is trivial—just four lines changed—but it’s a necessary step for the broader goal of making `json-writer` a "safe" API.

**Key context from the series**:
- `strbuf-safe.h` (introduced in patch 1) contains the `strbuf` struct definition and constants like `STRBUF_INIT`, enabling safe methods to work without pulling in the full `strbuf.h` (which includes `die()`-prone functions).
- Later patches (e.g., 6/6) will convert `json-writer` to use `sstrbuf_grow()` and other safe methods, but this patch ensures the header is ready.
- The trace2 files (`tr2_tgt_event.c`, `tr2_tgt_perf.c`) now explicitly include `strbuf.h` to avoid breaking their existing usage of `strbuf` functions.

**Why this matters**:
This is a **build-system and header hygiene patch** that paves the way for the real safety work. It’s uncontroversial in isolation but critical for the series’ success. The only potential gotcha is whether other files implicitly rely on `json-writer.h` to transitively include `strbuf.h`—the patch addresses the two known cases (trace2 targets), but if there are others, they’d break at compile time.

**Next steps**:
Patch 6/6 will likely convert `json-writer` to use the safe API, completing the series’ core goal. The open questions from the RFC (naming, transition plan, `GIT_ALLOC_LIMIT` handling) remain unresolved but aren’t blockers for this specific change.
