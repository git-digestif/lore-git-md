This is a bugfix for `git diff --no-index -R` when handling file/directory conflicts. The patch addresses a case where one path is a file on one side and a directory on the other: the reverse diff (`-R`) flag was incorrectly reporting both paths as deleted (or added, depending on operand order) instead of properly reversing the file change alongside the directory contents.

The fix itself is small—a two-line change in `diff-no-index.c` that swaps the filespecs when `reverse_diff` is set before queuing the early file entry. The commit includes regression tests for both directions (file→directory and directory→file), which verify that the output now correctly shows the file as added or deleted in reverse mode.

The problem is clearly explained in the commit message, and the test coverage looks thorough for the reported edge case. This is a targeted fix for a specific behavioral inconsistency rather than a broad refactoring, and it doesn’t appear to introduce any new risks. If you use `git diff --no-index` with `-R` on mixed file/directory hierarchies, this patch is worth paying attention to.
