This is **part 1 of a 6-patch RFC series introducing a "safe" `strbuf` API** that cannot call `die()` or `exit()`. The series is motivated by the need to prevent recursive `die()` loops in low-level libraries like trace2, where memory allocation failures in `strbuf` operations could trigger fatal errors.

This patch **moves the `strbuf` struct definition and related constants** (`strbuf_slopbuf`, `STRBUF_INIT`) from `strbuf.h` to a new header, `strbuf-safe.h`. The original `strbuf.h` now includes `strbuf-safe.h`, ensuring backward compatibility for existing code. The new header is explicitly positioned as the foundation for a "safe" API subset, with a comment clarifying its purpose: to provide implementations that avoid `die()` and are suitable for use in low-level APIs like trace2.

The change is **mechanical and preparatory**, with no functional impact on Git’s behavior. It lays the groundwork for subsequent patches in the series, which will implement safe versions of `strbuf` methods (e.g., `sstrbuf_grow()`, `sstrbuf_init()`). The patch is **well-scoped and uncontroversial** in isolation, though the broader RFC raises questions about naming (`sstrbuf_*` vs. `strbuf_*_gently`), the transition plan for callers, and whether this is the right approach to hardening the API.

Key files introduced: `strbuf-safe.h` (new header). Files modified: `strbuf.h` (reduced to a thin wrapper). The patch touches no implementation code, only headers, so there are no new symbols or behavior changes to test. The focus here is purely on refactoring for future extensibility.
