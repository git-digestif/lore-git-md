Subject: [PATCH] diff --no-index: fix -R handling for file/directory conflicts
Series version: standalone patch (no series)
Originating author: Haokai Ding
Thread type: bugfix patch

Core problem or goal
Fix a regression in `git diff --no-index -R` where file/directory conflicts (one side a file, the other a directory) are incorrectly reported as deletions or additions instead of being reversed. The bug occurs because `queue_diff()` processes the file separately before recursing into the directory, bypassing the normal reverse-diff handling.

Current status
Under review. The patch is a minimal two-line fix in `diff-no-index.c` that swaps filespecs of the early queue entry when `reverse_diff` is set, plus regression tests in `t/t4053-diff-no-index.sh` covering both directions of the conflict. René Scharfe has reviewed the patch and endorsed its correctness ("Good find!") and test design ("I like the explicit exit code expectation"), signaling readiness for integration.

Key technical details
- Files touched: `diff-no-index.c` (core logic), `t/t4053-diff-no-index.sh` (tests)
- New symbols: none (internal logic change only)
- Behavior change: `-R` flag now correctly reverses file/directory conflict cases
- Test coverage: two new tests for "file→directory" and "directory→file" scenarios, using `--name-status` and explicit exit code checks
- Subsystem: `diff --no-index` (standalone file comparison outside Git repositories)
