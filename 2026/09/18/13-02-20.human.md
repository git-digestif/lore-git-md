This is the final patch in Derrick Stolee’s six-part RFC series introducing a "safe" `strbuf` API that cannot call `die()`. It adds the missing `sstrbuf_init()` and `sstrbuf_release()` methods, completing the core safe API surface.

The patch begins the transition of `json-writer.c` to the safe API by converting its internal helpers (`fmt_double()`, `append_sub_jw()`) to return error codes and replacing `strbuf_release()` with `sstrbuf_release()`. The public `jw_release()` method now returns an `int` instead of `void`, but its callers are not yet updated to handle errors—this is explicitly deferred to future work. The commit message acknowledges the resulting gap: if an allocation fails, `json-writer` consumers may continue running and encounter a different error later.

The implementation is straightforward: `sstrbuf_init()` delegates to `sstrbuf_grow()` for the hinted allocation, and `sstrbuf_release()` frees the buffer and re-initializes the struct. The existing `strbuf_init()` and `strbuf_release()` in `strbuf.c` are updated to call their safe counterparts and die on failure, preserving backward compatibility.

This patch is a logical continuation of the series’ incremental approach. It does not yet make `json-writer` fully safe (callers still ignore errors), but it lays the groundwork for that conversion. The choice to split the transition into phases—first landing the API, then updating callers—keeps the changes digestible and reviewable. The patch is well-motivated and technically sound, though the deferred error-handling work means the series remains incomplete.
