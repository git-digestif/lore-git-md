This is a bugfix patch targeting the `dir.c` subsystem, specifically addressing a regression in `git status --ignored` with pathspec substring matching. René Scharfe provides a minimal fix for the issue reported by Sean Whitton (forwarding Lester Longley's Emacs issue), where ignored directories containing nested repositories were incorrectly matched when the pathspec was a substring of the directory name (e.g., `ba` matching `bar/`).

The patch restores the expected behavior by ensuring `match_pathspec_with_flags()` is called for excluded directories with nested repositories, even when they would otherwise be skipped due to an optimization introduced in commit `95c11ecc73`. The fix is localized to `dir.c` and includes a new test case in `t/t7061-wtstatus-ignore.sh` to prevent regression. The test verifies that `git status --porcelain --ignored -u` omits an excluded directory with a nested repository when the pathspec is a prefix match.

René’s commit message is clear and directly ties the fix to the regression’s origin, though he notes the removed optimization might be repairable in a future iteration. The patch is well-scoped and addresses the core issue without introducing new complexity.
