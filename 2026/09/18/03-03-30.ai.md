This is the **v2 revision of a bugfix series** targeting a data-loss race in `git repack -d` where concurrent pushes can cause objects to vanish despite `.keep` files. The series is now **five patches** (down from six) after the author withdrew patch 1/6 in favor of Justin Tobler’s ODB-focused approach, which will handle `.keep` file ownership more cleanly.

The core issue remains: a timing window between when `repack` scans for `.keep` files and when `pack-objects` (spawned with `--honor-pack-keep`) does its own scan. If a concurrent push finishes migrating its quarantine during this window—linking a `.keep` onto a pack that `repack` has already decided to delete—`pack-objects` will skip the pack’s objects, but `repack` will still delete the pack, leaving dangling refs. The fix (patch 5/5) eliminates the race by passing `pack-objects` the exact list of `.keep` packs that `repack` observed at startup, rather than letting it rescan.

Patches 1–4 lay the groundwork for patch 5:
- **1/5** aligns `--stdin-packs=follow` behavior so `--keep-pack` packs act as traversal blockers (like `^` packs), matching the behavior of on-disk `.keep` packs.
- **2/5** fixes a pre-existing bug where the cruft-pack walk uses a stale kept-pack cache, previously masked by `--honor-pack-keep`.
- **3/5** optimizes `--keep-pack` name lookups by sorting the list, yielding an 11× speed-up for repositories with many kept packs.
- **4/5** adds `--keep-pack-from-file` to handle repositories where the number of kept packs exceeds command-line limits (e.g., 32K characters on Windows).

The series is **well-tested**: each patch includes a test that fails without it, and the race itself is reproduced in `t7703-repack-geometric.sh`. All tests pass, and the series merges cleanly into `next` and `seen`. Key files touched include `builtin/pack-objects.c`, `builtin/repack.c`, and `packfile.c`, with new plumbing in `packfile.h` and `tempfile.h`.

This is a **production-tested fix** for a serious data-loss bug. The commit messages are clear, the tests are comprehensive, and the design avoids introducing new races.
