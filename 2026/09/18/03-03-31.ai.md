This is the first patch in the v2 series fixing the `git repack` concurrent-push data-loss race. It corrects a long-standing behavioral inconsistency in `git pack-objects --stdin-packs=follow`: packs named with `--keep-pack` were incorrectly treated as closed under reachability (like `^` packs), causing the traversal to stop at them. The fix marks such packs as "kept-open" (`!`) instead, allowing the traversal to continue through their objects to rescue dependencies that would otherwise be omitted.

The change is minimal and targeted: it adds a mode check in `add_extra_kept_packs()` to set `pack_keep_in_core_open` instead of `pack_keep_in_core` when `stdin_packs` is `STDIN_PACKS_MODE_FOLLOW`. The new test in `t/t5331-pack-objects-stdin.sh` reproduces the bug by creating a kept pack containing only a commit (not its tree or blob), with the tree and blob in an excluded pack. Without the fix, the tree and blob are missing from the output pack; with the fix, they are included.

This patch is a prerequisite for the series' main fix (patch 5/5), which replaces `--honor-pack-keep` with a snapshot-based approach. The inconsistency it addresses would otherwise cause objects to be omitted from the repack, leading to dangling refs. The commit message is clear and the test is comprehensive, covering the edge case explicitly. No performance impact is expected, and the change is internal-only (no user-visible behavior change outside the corrected edge case). Reviewers may focus on whether the mode check is sufficient to cover all callers, but the patch is narrowly scoped and unlikely to introduce regressions.
