This is the first patch in Derrick Stolee’s six-part RFC series introducing a "safe" `strbuf` API that cannot call `die()` or `exit()`. It lays the groundwork by moving the core `struct strbuf` definition and its documentation into a new header, `strbuf-safe.h`.

The patch is **mechanical and low-risk**: it extracts the existing `struct strbuf` definition, the `STRBUF_INIT` macro, and the explanatory comments from `strbuf.h` into `strbuf-safe.h`, then includes that header in `strbuf.h`. No behavior changes are introduced yet. The motivation is to allow future patches to add safe implementations of `strbuf` methods without cluttering the main header, and to make it clear which parts of the API are guaranteed not to call `die()`.

The commit message is clear and concise, explaining the purpose of the new header and its intended use. The diff itself is straightforward, with the only functional change being the `#include "strbuf-safe.h"` line in `strbuf.h`. The documentation comments are preserved verbatim, ensuring that the invariants and usage guidelines for `strbuf` remain available to developers.

This patch is **not controversial** and looks like a sensible first step in the series. It doesn’t yet introduce the safe API (that comes in later patches), but it sets up the infrastructure for it. The real discussion points—whether the safe API is the right approach, the naming convention, and the transition plan—are deferred to the rest of the series. For now, this patch is a clean, well-explained refactoring that doesn’t disrupt existing code.
