This thread is about a targeted bugfix for `git diff --no-index -R`, which incorrectly handled file/directory conflicts (e.g., one side a file, the other a directory) by reporting them as deletions or additions instead of reversing them. The issue was introduced when `queue_diff()` processed the file separately before recursing into the directory, bypassing the reverse-diff logic.

Haokai Ding authored a minimal two-line fix in `diff-no-index.c` that swaps filespecs of the early queue entry when `reverse_diff` is set, along with regression tests in `t/t4053-diff-no-index.sh` covering both directions of the conflict. The patch has received two substantive reviews: René Scharfe confirmed the issue and fix ("Good find!") and praised the test design, while Jacob Keller added his **Reviewed-by** in this latest email, further endorsing the solution. Both reviewers engaged with the technical content, and there are no open questions or objections.

The patch is now effectively ready for integration, with no dependencies or follow-up work indicated. The next step is likely Junio picking it up for `next` or `master`.
