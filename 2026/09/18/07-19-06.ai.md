This is a bugfix patch targeting the `diff --no-index` subsystem, specifically addressing a regression in the `-R` (reverse diff) flag when dealing with file/directory conflicts.

The patch fixes a case where `git diff --no-index -R` incorrectly reports paths as deleted or added when one side of the comparison is a file and the other is a directory. The issue occurs because `queue_diff()` processes the file separately before recursing into the directory, bypassing the normal reverse-diff handling. The fix swaps the filespecs of the early queue entry when `reverse_diff` is set, ensuring consistent behavior with the `-R` flag.

The commit message clearly explains the problem and solution, and the patch includes regression tests for both directions of the file/directory conflict. The change is minimal (two lines in `diff-no-index.c`) and well-scoped to the specific issue. The test coverage in `t/t4053-diff-no-index.sh` verifies the fix works as intended.

Key technical details:
- Files touched: `diff-no-index.c` (core logic) and `t/t4053-diff-no-index.sh` (tests)
- New behavior: `-R` flag now correctly reverses file/directory conflict cases
- Test cases: Two new tests covering both "file→directory" and "directory→file" scenarios
- Related subsystem: `diff --no-index` (used for comparing files outside Git repositories)
