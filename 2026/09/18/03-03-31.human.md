This is the first patch in a five-part bugfix series that plugs a data-loss race in `git repack -d` when concurrent pushes create `.keep` files mid-repack. The series is well-motivated, production-tested, and already at v2 after withdrawing an earlier patch in favor of Justin Tobler’s cleaner ODB-focused approach.

This specific patch fixes a subtle but critical flaw in `git pack-objects --stdin-packs=follow`: when a pack is named with `--keep-pack`, it was incorrectly treated as a closed boundary (`^` pack), stopping reachability traversal at its objects. In reality, `--keep-pack` only means “don’t repack this pack,” not “this pack is self-contained.” The fix changes the in-core flag so that `--keep-pack` packs are treated as kept-open (`!` packs) instead, allowing the traversal to continue through them to rescue dependent objects that would otherwise be omitted. This behavior now matches how on-disk `.keep` packs have always worked, ensuring consistency once the series removes the `--honor-pack-keep` mechanism in patch 5.

The patch touches only `builtin/pack-objects.c` and adds a new test in `t/t5331-pack-objects-stdin.sh` that reproduces the bug: a kept pack (`B_ONLY`) contains only a commit, while its tree and blob reside in an excluded pack (`B`). Without the fix, the tree and blob are missing from the output pack; with the fix, they are correctly included. The test is clear and fails without the code change, confirming the fix’s necessity.

The commit message is excellent: it explains the problem, the fix, and why it matters for the larger series. The code change is minimal and focused, adding only a mode check in `add_extra_kept_packs` to set the correct flag (`pack_keep_in_core_open` instead of `pack_keep_in_core`). The patch is unlikely to be controversial, though reviewers may discuss whether the flag naming (`open` vs. `closed`) could be clearer or whether the behavior should be documented in `git-pack-objects.adoc`.

This patch is a prerequisite for patch 5’s snapshot-based `.keep` handling, which eliminates the race by passing `pack-objects` the exact list of `.keep` packs observed at repack startup. The fix is narrow but essential: without it, the traversal logic would incorrectly treat kept packs as boundaries, leading to incomplete packs and potential data loss. The series as a whole is a serious, well-tested effort to address a real-world bug, and this patch is a solid first step.
