This is the **final patch (5/5) in a v2 bugfix series** that closes a data-loss race in `git repack -d`. The race occurs when a concurrent push creates a `.keep` file after `repack` has already decided which packs to delete but before `pack-objects` (spawned with `--honor-pack-keep`) rescans the directory. The result is that `pack-objects` skips the pack’s objects, but `repack` still deletes the pack, leaving dangling refs.

This patch **eliminates the race** by passing `pack-objects` the exact list of `.keep` packs that `repack` observed at startup, using a new `--keep-pack-from-file` option (added in patch 4/5). The list is written to a temporary file next to the refs snapshot already used for `multi-pack-index write`, ensuring both processes work from the same snapshot. The `--honor-pack-keep` option is dropped entirely, and the cruft pack-objects (which already receives kept packs on stdin) now sees the same list for consistency.

The implementation is straightforward: `repack` writes the kept-pack names (one per line, with `.pack` suffix) to a tempfile, and `pack-objects` reads them via `--keep-pack-from-file`. The patch refuses packs with newlines in their names up front, since they would split into two entries in the file. Alternate ODB packs, previously skipped by `--honor-pack-keep`, are now packed (not deleted), trading disk space for safety.

The patch includes **three new tests**:
1. A regression test in `t7700-repack.sh` confirming that `--keep-pack` with `--pack-kept-objects` still excludes the kept pack’s objects.
2. A test in `t7703-repack-geometric.sh` that reproduces the race (a `.keep` appearing mid-repack) and verifies objects are not lost.
3. A second test in `t7703` ensuring kept packs do not block traversal of objects reachable through them.

The series is **production-ready**: the commit message clearly explains the race, the fix is minimal and well-tested, and the design avoids introducing new edge cases. The withdrawal of patch 1/6 (v1) in favor of Justin Tobler’s ODB-focused series simplifies the fix by offloading `.keep` file ownership to a separate effort. This patch is likely to attract attention from repack/ODB maintainers (Patrick Steinhardt, Taylor Blau) and low-level traversal experts (Jeff King), but the groundwork laid in patches 1–4 makes the change uncontroversial.
