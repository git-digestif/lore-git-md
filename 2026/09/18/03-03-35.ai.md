This is the **fifth and final patch in a v2 bugfix series** that closes a data-loss race in `git repack -d` where concurrent pushes can cause objects to vanish despite `.keep` files. The series replaces the `--honor-pack-keep` mechanism with a snapshot-based approach, ensuring `.keep` files are managed consistently.

This patch **eliminates the race** by passing `pack-objects` the exact list of `.keep` packs that `repack` observed at startup, rather than letting `pack-objects` rescan the directory mid-repack. The list is written to a temporary file (one `<name>.pack` per line) next to the refs snapshot already used for `multi-pack-index write`, and passed via the new `--keep-pack-from-file` option introduced in patch 4/5. When no packs are kept, no file is written, matching the behavior of `--honor-pack-keep` when it found no `.keep` files.

The implementation is straightforward: `existing_packs_snapshot_kept()` writes the kept-pack names to a tempfile, and `prepare_pack_objects()` passes the file path to `pack-objects` when `--pack-kept-objects` is not in effect. The patch also removes a redundant loop in `write_filtered_pack()` that was passing kept-pack names without the `.pack` suffix, which `pack-objects` would not recognize. Alternate ODB packs are no longer skipped; they are now packed (not deleted), trading disk space for safety.

Three new tests verify the fix:
1. `t7700-repack.sh` confirms `--keep-pack` with `--pack-kept-objects` still excludes the kept pack’s objects.
2. `t7703-repack-geometric.sh` reproduces the race (a `.keep` appearing mid-repack) and confirms objects are not lost.
3. A second test in `t7703-repack-geometric.sh` ensures kept packs do not block traversal of objects reachable through them.

The patch is **well-motivated and production-tested**, with clear commit messages and comprehensive test coverage. The design avoids introducing new races and aligns with existing Git conventions (e.g., the snapshot file format matches `git multi-pack-index write --refs-snapshot`). The only notable trade-off is that alternate ODB packs are now packed rather than skipped, which may increase disk usage but cannot lose data. This is a **critical fix** for a serious bug, and the series is likely to attract attention from repack/ODB maintainers (Patrick Steinhardt, Taylor Blau) and low-level traversal experts (Jeff King).
