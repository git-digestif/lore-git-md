This is the third patch in Derrick Stolee’s six-part RFC series introducing a "safe" `strbuf` API that cannot call `die()` or `exit()`. The series targets a real problem: the trace2 subsystem (via `json-writer`) can trigger recursive `die()` loops if memory allocation fails, which is unacceptable for low-level libraries.

This patch refactors the memory limit checking logic in `wrapper.c` to create a new `safe_memory_limit_check()` function that never calls `die()`. The existing `memory_limit_check()` is preserved for backward compatibility but now delegates to the safe version, calling `die()` only when not in "gentle" mode. The key change is that the safe version assumes `SIZE_MAX` as the limit if `git_alloc_limit` is unset, rather than attempting to parse the `GIT_ALLOC_LIMIT` environment variable (which can itself call `die()`). This assumption is justified by the earlier patch in the series that proactively initializes `GIT_ALLOC_LIMIT` during Git’s startup (`setup_environment()`), ensuring the limit is set before any safe API calls occur.

The patch touches only `wrapper.c` and is a straightforward refactoring with no behavior changes for existing callers. The new `safe_memory_limit_check()` will be used by the upcoming safe `strbuf` methods (e.g., `sstrbuf_grow()`) to avoid fatal errors during memory allocation. The commit message clarifies the trade-off: safe APIs may fail to allocate memory that would have succeeded under the old logic if called *very* early in Git’s startup, but this is deemed an acceptable risk given the narrow window and the safety guarantee.

This is a **well-motivated, low-risk refactoring** that directly enables the safe API’s core property. The patch is **technically sound** and aligns with the series’ goal of hardening low-level APIs like trace2. No new tests are introduced here, but the safety property will be verified by CodeQL in later patches. The only likely discussion point is whether the `SIZE_MAX` fallback is sufficiently robust for edge cases, though the commit message addresses this explicitly.
