This is a brief follow-up in the ongoing CI/build system thread about enabling Rust compilation in Git’s GitHub Actions Windows CI jobs. The series itself was merged to `next` and fast-tracked to `master` earlier this week, but Junio flags a new issue: GitLab’s Windows runners (`saas-windows-medium-amd64`) do **not** have Rust preinstalled, as evidenced by a recent CI failure where `cargo` was not found.

Johannes had previously asked GitLab contributors (notably Patrick Steinhardt) to test the patch series on GitLab’s runners, but no confirmation was received. The GitLab documentation does not clarify whether Rust is available, and the linked CI job log confirms the absence of `cargo`. This means the merged patches will break GitLab’s Windows CI unless Rust is explicitly installed in the pipeline.

The problem is narrow and practical: the series assumes Rust is preinstalled (as it is in GitHub Actions), but GitLab’s runners do not meet that assumption. No design or technical objections are raised; the fix is likely a matter of adding a `rustup` installation step to GitLab’s CI configuration. The thread is now focused on gathering information from GitLab contributors to determine the minimal change needed to restore CI functionality.
