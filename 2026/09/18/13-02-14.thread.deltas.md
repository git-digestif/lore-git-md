# Thread deltas

## 2026/09/18

- [2026/09/18/13-02-14 by Derrick Stolee via GitGitGadget <gitgitgadget@gmail.com>] Derrick Stolee posted an RFC series proposing a 'safe' strbuf API that cannot transitively reach die() or exit(), aiming to prevent recursive die() loops in trace2 when allocation fails, and asked whether this direction is worthwhile or should be abandoned.
- [2026/09/18/13-02-15 by Derrick Stolee via GitGitGadget <gitgitgadget@gmail.com>] Stolee created strbuf-safe.h and moved the strbuf struct definition and STRBUF_INIT macro into it, so consumers can include the safe API surface without pulling in non-safe methods.
- [2026/09/18/13-02-16 by Derrick Stolee via GitGitGadget <gitgitgadget@gmail.com>] Stolee added initialize_git_alloc_limit() to read GIT_ALLOC_LIMIT proactively during setup_environment() rather than implicitly at allocation time, and documented GIT_ALLOC_LIMIT in Documentation/git.adoc instead of renaming it to GIT_TEST_ALLOC_LIMIT.
- [2026/09/18/13-02-17 by Derrick Stolee via GitGitGadget <gitgitgadget@gmail.com>] Stolee created safe_memory_limit_check() which returns an error code without calling die(), and modified memory_limit_check() to call it and die only when not in gentle mode.
- [2026/09/18/13-02-18 by Derrick Stolee via GitGitGadget <gitgitgadget@gmail.com>] Stolee added sstrbuf_grow() as the first safe strbuf method using an 's' prefix naming convention, and changed the non-safe strbuf_grow() to call it and die on failure.
- [2026/09/18/13-02-19 by Derrick Stolee via GitGitGadget <gitgitgadget@gmail.com>] Stolee changed json-writer.h to include strbuf-safe.h instead of strbuf.h, and added direct strbuf.h includes to trace2/tr2_tgt_event.c and trace2/tr2_tgt_perf.c to compensate for the lost transitive include.
- [2026/09/18/13-02-20 by Derrick Stolee via GitGitGadget <gitgitgadget@gmail.com>] Stolee added sstrbuf_init() and sstrbuf_release() safe methods, adapted json-writer.c to use sstrbuf_release() and return error codes from jw_release(), fmt_double(), and append_sub_jw(), while noting that callers of those json-writer methods are not yet adapted to handle the new return values.

## 2026/09/19

- [2026/09/19/15-23-41 by Phillip Wood <phillip.wood123@gmail.com>] Phillip Wood endorsed the general direction of APIs that return errors rather than dying on allocation failures or overflow, noting that the xdiff and reftable code already have something similar, but objected to the name "safe" as not describing how the APIs differ from existing ones, preferring documentation and naming that reflect returning errors on failure.
- [2026/09/19/15-23-41 by Phillip Wood <phillip.wood123@gmail.com>] Phillip Wood proposed that for the strbuf API, checking for failure on every function call would not be attractive, and instead suggested a sticky error bit like the stdio functions so a string can be built and checked for failures once just before use.
- [2026/09/19/15-23-41 by Phillip Wood <phillip.wood123@gmail.com>] Phillip Wood identified a flaw in the RFC's CodeQL verification: the implementation of sstrbuf_grow() in patch 4 calls st_add3(), which dies on overflow, rather than st_add_overflows(), indicating the checks are not working as intended.
