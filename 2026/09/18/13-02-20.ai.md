This is the **sixth and final patch in an RFC series introducing a "safe" `strbuf` API** that cannot call `die()` or `exit()`. The series targets a critical problem: the trace2 subsystem (via `json-writer`) can trigger recursive `die()` loops if memory allocation fails, which is unacceptable for low-level libraries. This patch adds the remaining core methods to the safe API: `sstrbuf_init()` and `sstrbuf_release()`, and begins converting `json-writer.c` to use them.

The patch is **technically straightforward but consequential**. It implements the two new safe methods in `strbuf-safe.c` and updates `strbuf.c` to delegate the existing `strbuf_init()` and `strbuf_release()` to them, preserving backward compatibility by dying on failure. The real work happens in `json-writer.c`, where `jw_release()` is converted to return an error code (aggregating the results of both `sstrbuf_release()` calls) and two helper functions (`fmt_double()` and `append_sub_jw()`) are updated to propagate errors from the safe API. The `jw_init()` function remains unchanged for now, as it does not allocate memory.

The **transition is incomplete but intentional**. The patch leaves a window where `json-writer` consumers (like trace2) may continue running after an error occurs, potentially leading to follow-on errors. This is acknowledged in the commit message: callers are not yet adapted to handle errors, and that work is deferred to future patches. The change to `json-writer.h` updates the signature of `jw_release()` to return an `int`, signaling the shift to error-aware usage.

**Key technical details**:
- **New symbols**: `sstrbuf_init()` and `sstrbuf_release()` in `strbuf-safe.h`/`strbuf-safe.c`.
- **Behavior changes**: `jw_release()` now returns an error code (nonzero on failure), and `fmt_double()`/`append_sub_jw()` propagate errors from the safe API. The existing `strbuf_init()`/`strbuf_release()` still die on failure, so no behavior change for existing callers.
- **Files touched**: `json-writer.c` (conversion to safe API), `json-writer.h` (signature change), `strbuf-safe.c`/`strbuf-safe.h` (new methods), and `strbuf.c` (delegation to safe methods).
- **Error handling**: The patch uses `enum safe_result` (`SUCCESS`/`MEMORY_ERROR`) for consistency with earlier patches, and aggregates errors in `jw_release()` without short-circuiting (both buffers are released even if one fails).

**Likely discussion points**:
- **Error propagation**: Whether the deferred adaptation of `json-writer` callers is acceptable, or if the patch should include those changes now.
- **Naming**: The `sstrbuf_*` prefix remains consistent with earlier patches, but the choice may still draw feedback.
- **Safety guarantees**: The patch adds `#include "banned-die.h"` to `json-writer.c` to enforce the no-`die()` rule, a strong signal of intent.
- **Performance**: The overhead of error-code returns (vs. `die()`) is not addressed here but may come up in review.

The patch is **well-motivated and carefully implemented**, but the incomplete transition to error-aware callers leaves open questions about how this will integrate with the rest of the codebase. The use of `banned-die.h` and the aggregation of errors in `jw_release()` suggest a thoughtful approach to safety, but the real test will be how callers adapt in follow-up work. For now, this patch completes the safe API’s core functionality and sets the stage for broader adoption.
