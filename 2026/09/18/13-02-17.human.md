This is the third patch in Derrick Stolee’s six-part RFC series introducing a "safe" `strbuf` API that cannot call `die()`. The series aims to prevent fatal recursion in low-level libraries like trace2 when memory allocation fails.

This patch refactors the memory limit checking logic in `wrapper.c` to create a new `safe_memory_limit_check()` function. The key change is splitting the existing `memory_limit_check()` into two parts: a safe version that only returns errors (never calls `die()`), and the original version that wraps it and calls `die()` when not in gentle mode. The safe version assumes `SIZE_MAX` as the limit if `git_alloc_limit` is unset, which is safe because the series already proactively initializes `GIT_ALLOC_LIMIT` during startup (in `setup_environment()`). The patch is small, focused, and well-explained, with no behavior changes for existing callers.

The motivation is clear: the safe API (introduced in later patches) needs a memory limit check that cannot crash, and this patch provides it. The commit message acknowledges the brief window before `setup_environment()` where the safe version might use `SIZE_MAX`, but argues this is acceptable because safe API calls during that window would only allocate small amounts of memory. This is a reasonable trade-off for the safety guarantee.

This patch is a necessary building block for the series and looks solid. The refactoring is clean, and the safety property is preserved. No new tests are added here, but the series uses CodeQL to verify safety in later patches. The only open question is whether the `SIZE_MAX` fallback is robust enough, but the commit message addresses this directly.
