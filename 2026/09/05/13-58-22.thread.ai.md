Subject: Update CI to use Debian 12 instead of Debian 11
Series version: standalone patch (no series)
Originating author: Jeff King (Peff)
Thread type: CI/build system maintenance

Core problem or goal
Replace Debian 11 with Debian 12 in GitHub Actions and GitLab CI workflows because Debian 11 reached end-of-LTS (2024-07-10). The goal remains keeping CI testing on a supported distribution for the next two years (until 2028-06-30). A secondary discussion has emerged about the long-term viability of 32-bit (`linux32`) and older Ubuntu LTS jobs (`linux-TEST-vars`), with a concrete proposal to use Alpine Linux for 32-bit coverage. Patrick Steinhardt now proposes using the `oldstable` Docker tag instead of a hard-coded `debian:12` to reduce future maintenance.

Current status
Queued in `seen`; Junio C Hamano has signaled intent to merge. Patch touches `.github/workflows/main.yml` and `.gitlab-ci.yml`, updating `jobname` and `image` fields from `debian:11` to `debian:oldstable` (currently pointing to Debian 12) and comments to reflect the new support window. Expected to graduate to `next` in the next integration cycle.

Key technical details
Files: `.github/workflows/main.yml`, `.gitlab-ci.yml`
Symbols: none (CI configuration only)
Behavior: no user-visible change; CI environment now runs on Debian 12 instead of Debian 11
On-disk format: none
Test coverage: none (CI infrastructure change)
Additional context: The `linux32` job remains on Ubuntu 20.04 (out of LTS for a year) because it is the last Ubuntu LTS with i386 support; Debian has also dropped i386. The `linux-TEST-vars` job still uses Ubuntu 20.04, possibly for testing older platforms. Alpine Linux is now proposed as an alternative for 32-bit coverage, as it still supports 32-bit platforms and is already tested via the `linux-musl-meson` job. The `oldstable` tag is a Debian Docker convention that will automatically track the next oldstable release when it becomes available, eliminating the need to manually update the CI configuration again in two years.

Open questions and loose ends
- Whether the project should retain a job for an older LTS release (e.g., Debian 11) to catch compatibility regressions, or whether the existing AlmaLinux 8 job (supported until 2029) already provides sufficient coverage for older environments. This remains unaddressed but is not a blocker.
- Long-term viability of the `linux32` job: Patrick Steinhardt proposes using Alpine Linux (already present in CI via `linux-musl-meson`) for 32-bit coverage, either by extending that job or merging `linux32` into it. This would mean losing 32-bit glibc coverage but may be an acceptable trade-off given the shrinking support landscape.
- Whether the `linux-TEST-vars` job should be updated to the oldest in-scope Ubuntu LTS; Steinhardt notes the lack of a stable tag to avoid manual updates. No action is proposed until problems arise.
