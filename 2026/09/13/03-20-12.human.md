This is the first patch in a two-patch bugfix series for the `git worktree repair` command. The goal here is to refactor the code to reduce redundant `.git` file reads and extract the worktree ID, setting up the groundwork for the actual validation logic that arrives in patch 2/2.

The patch touches only `worktree.c` and makes two key changes. First, it moves the file-reading and trimming logic out of `infer_backlink()` and into its caller, `repair_worktree_at_path()`, using `read_gitfile_raw()` instead of `read_gitfile_gently()`. This eliminates duplicate file reads and simplifies error handling. Second, it introduces `get_worktree_id()`, a helper function that extracts the worktree ID from the `.git` file contents, which will be used in the next patch to validate the repair target.

The refactoring is clean and well-motivated: the commit message explains why the changes are needed (reducing redundancy and preparing for validation), and the code itself is straightforward. The patch does not change behavior yet, but it makes the code easier to work with and paves the way for the actual fix. If you care about worktree correctness, this is worth paying attention to, as it’s the foundation for preventing `git worktree repair` from accidentally corrupting unrelated worktrees.
