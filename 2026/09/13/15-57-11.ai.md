This is the first patch in the v4 series enabling Rust compilation in Git’s GitHub Actions Windows CI jobs. It maps the `MSYSTEM` environment variable to the correct Rust target triple (e.g., `x86_64-pc-windows-gnu` for `UCRT64`, `aarch64-pc-windows-gnullvm` for `CLANGARM64`) so that Cargo produces a static library (`libgitcore.a`) compatible with MinGW’s linker. The patch repurposes the `HOST_CPU` variable to derive the CPU architecture (`i686`, `x86_64`, or `aarch64`) and adjusts the `RUST_LIB` path to include the target triple, ensuring the correct `.a` file is linked. It also exports `CARGO_BUILD_TARGET` for cross-compilation cases (e.g., `aarch64` builds on `x86_64` runners), while native builds omit the `--target` flag entirely to avoid breaking Cargo’s internal assumptions.

The patch touches `Makefile` and `config.mak.uname`, with no changes to core Git functionality or user-facing features. It is a CI/build-system adjustment that directly addresses the link-time failure observed in prior CI runs (e.g., `ld.exe` unable to find `libgitcore.a` because Cargo defaulted to the MSVC ABI). The mapping logic is explicit and mirrors the behavior in `config.mak.uname`, enumerating the expected Rust target triple for each `MSYSTEM` value. This patch is a prerequisite for the second patch in the series, which removes the `NO_RUST` opt-out in `ci/lib.sh`.

All prior feedback has been addressed: the v4 revision removes the now-unnecessary `--target` flag for native builds (aligning with James Le Cuirot’s feedback and the merged `jc/rust-cargo-build-target` topic), and the commit message clarifies that `rustup target add` is sufficient for installing the required Rust components. The patch is narrowly scoped, well-motivated, and unlikely to be controversial. The only remaining open question is whether the logic works on GitLab’s Windows runners (`saas-windows-medium-amd64`), as Rust availability and toolchain compatibility there remain unconfirmed. Johannes explicitly requests testing from GitLab contributors but does not treat this as a blocker.
