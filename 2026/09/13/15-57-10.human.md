This is a CI/build system patch series, now at v4, that enables Rust compilation in Git’s GitHub Actions Windows CI jobs. The goal is to stop opting out of Rust (required by default since Git 2.55.0) by configuring the pre-installed Rust toolchain on GitHub’s Windows runners to target GCC (used by Git for Windows) instead of the default Visual C. The series is narrowly scoped to CI configuration and does not affect core Git functionality.

The v4 revision is a minor update to v3, addressing a small oversight: the commit message for the first patch still referenced the `--target` flag, which was removed in v3 after feedback clarified that Cargo’s `--target` should not be set for native builds. The rest of the series remains unchanged. Both patches are now ready for final review, with all prior feedback incorporated.

The changes touch `.github/workflows/main.yml`, `ci/lib.sh`, `config.mak.uname`, and the `Makefile`. The key technical detail is the use of `CARGO_BUILD_TARGET` (aligned with the recently merged `jc/rust-cargo-build-target` topic) to map the `MSYSTEM` environment variable to the correct Rust target triple (e.g., `x86_64-pc-windows-gnu` for `UCRT64`). The series also removes the `NO_RUST` opt-out in `ci/lib.sh` and adds a step to install the precompiled Rust `std` library via `rustup target add`.

The series looks well-crafted and addresses a clear need: unblocking Rust in Windows CI without bloating the minimal Git for Windows SDK. The request for testing on GitLab’s Windows runners (`saas-windows-medium-amd64`) remains open, but this is not a blocker for merging. If the GitLab runners behave as expected, this series should be uncontroversial.
