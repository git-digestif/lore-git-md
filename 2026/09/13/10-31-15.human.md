This is the first patch in a two-part CI/build system series (v3) that enables Rust compilation in Git’s GitHub Actions Windows CI jobs. The patch configures the Rust toolchain to target the GCC-compatible ABI (used by Git for Windows) instead of the default MSVC ABI, ensuring Cargo produces a static library (`libgitcore.a`) that MinGW’s `ld.exe` can link.

The core change maps the `MSYSTEM` environment variable to the correct Rust target triple (e.g., `x86_64-pc-windows-gnu` for `UCRT64`, `aarch64-pc-windows-gnullvm` for `CLANGARM64`) and repurposes the `HOST_CPU` variable to derive the CPU architecture (`i686`, `x86_64`, or `aarch64`). The `RUST_LIB` path is adjusted to include the target triple, ensuring the build process picks up the correct `.a` file. The patch touches `config.mak.uname` and the `Makefile`, with no changes to core Git functionality or user-facing features.

This is a well-motivated fix for a concrete problem: since Git 2.55.0, Rust is required by default, but Windows CI jobs currently opt out because the minimal Git for Windows SDK lacks Rust. The patch leverages the pre-installed Rust toolchain on GitHub’s Windows runners, aligning it with Git for Windows’ build environment. The commit message clearly explains the issue (MSVC-targeted `.lib` files incompatible with MinGW) and includes a link to a failed CI run demonstrating the problem.

Feedback from earlier versions has been addressed. Junio C Hamano’s review identified a potential edge-case inconsistency in the Rust target triple mapping for UCRT64, which was corrected in v2. The v3 revision aligns the variable naming (`CARGO_BUILD_TARGET`) with the recently merged `jc/rust-cargo-build-target` topic, resolving a naming inconsistency noted by Junio and James Le Cuirot. The patch is now ready for final review and looks uncontroversial.

The series is narrowly scoped to Windows CI and is a prerequisite for the broader Rustification effort in Git. It does not interact with other in-flight efforts (e.g., ODB abstraction, reftable backend) and is self-contained. The second patch in the series will remove the `NO_RUST` opt-out and install the precompiled Rust `std` library, completing the setup.
