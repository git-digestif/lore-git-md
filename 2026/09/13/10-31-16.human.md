This is the second patch in Johannes Schindelin’s v3 series enabling Rust compilation in Git’s GitHub Actions Windows CI jobs. It removes the `NO_RUST` opt-out and adds a step to install the precompiled Rust `std` library for the GCC-compatible target triple (e.g., `x86_64-pc-windows-gnu` for `MINGW64`).

The patch is straightforward and well-motivated. The Windows runners already include `rustup`, but only the MSVC-targeted toolchain is preinstalled. Since Git for Windows uses MinGW’s GCC, the build needs the GCC-compatible `std` library, which this patch installs via `rustup target add`. The mapping from `MSYSTEM` to Rust target triple mirrors the logic already in `config.mak.uname`, ensuring consistency. The patch also adjusts the `PATH` to ensure `cargo.exe` is found in the minimal Git for Windows SDK environment.

This is a CI/build-system-only change, touching `.github/workflows/main.yml` and `ci/lib.sh`. It has no effect on core Git functionality, on-disk formats, or user-facing features. The series as a whole is a prerequisite for the broader Rustification effort, unblocking the eventual removal of the Rust opt-out in Git’s CI. Feedback from v2 has been fully addressed, and this patch is now ready for final review. The only loose end is a request to test on GitLab’s Windows runners, but that’s not a blocker for merging. This looks like a clean, practical solution to a real problem.
