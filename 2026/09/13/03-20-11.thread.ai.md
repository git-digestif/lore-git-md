Subject: [PATCH 0/2] worktree repair: fix incorrect repair of unrelated worktrees

Thread type: patch series (bugfix)

Core problem or goal
The `git worktree repair` command can incorrectly modify `.git` files or gitdirs belonging to unrelated worktrees when cross-references between a linked worktree and its administrative data are not validated before repair. The goal is to add validation that ensures the repair target is correct before making changes, preventing accidental corruption of unrelated worktrees. The issue manifests in edge cases such as manually swapped worktree directories or copied linked worktrees, where `git worktree repair` would previously operate on the wrong administrative files without checks.

Current status
Under review, v2 posted. The series is now five patches: patches 1–4 refactor code to reduce redundant `.git` file reads, extract the worktree ID, centralize backlink selection logic, and improve code clarity, while patch 5 adds validation logic to prevent repairs on unrelated worktrees. Junio C Hamano provided a substantive review of the v1 refactoring patch (1/2) on 2026-10-05, engaging with correctness, edge-case behavior (e.g., whitespace handling, `gitdir:` prefix validation), and error-handling consistency. Yoichi NAKAYAMA responded on 2026-10-06, clarifying intended behavior changes—particularly that the refactored code rejects `.git` files with missing spaces after `gitdir:` (e.g., `gitdir:foo/bar`) and treats trailing whitespace as part of the path (e.g., `gitdir: foo/bar/   ` resolves to `worktrees/   `). The author split the v1 refactoring patch into four smaller commits (patches 1–4 in v2) for clarity, as requested.

Patch 1 replaces `read_gitfile_gently()` with `read_gitfile_raw()` in `repair_worktree_at_path()`, aligning path resolution and repository validation with `repair_gitfile()` and eliminating reliance on the non-reentrant helper. Patch 2 refactors `repair_worktree_at_path()` to centralize the logic for selecting the inferred backlink, reordering processing steps so the inferred backlink is computed after reading the `.git` file but before validating the backlink’s gitdir. This ensures the inferred backlink is preferred when both a valid gitdir and an inferred path exist, addressing edge cases where a worktree was copied (rather than moved) alongside its main repository. Patch 3 (this email) refactors `infer_backlink()` to use `read_gitfile_raw()`—the stricter `.git` file parser introduced in patch 2—ensuring consistent handling of trailing whitespace and malformed `gitdir:` prefixes across the worktree repair codebase. It also extracts `get_worktree_id()` as a helper function for reuse in patch 5. Patches 4–5 (not yet summarized) further centralize `.git` file parsing and add validation logic; none have been reviewed yet. No merge status has been reported or cited in "What's cooking."

Key technical details
- Files touched: `worktree.c`, `t/t2406-worktree-repair.sh` (patches 2–5)
- New/renamed symbols: `read_gitfile_raw()` (new helper function for stricter `.git` file parsing, introduced in patch 2), `get_worktree_id()` (new helper function, internal use only, introduced in patch 3)
- Behavior change: `git worktree repair` now validates the worktree ID and gitdir path before making changes, skipping repairs if the target is unrelated. The refactoring in patches 1–4 also adjusts error handling for malformed `.git` files:
  - Rejects `.git` files with `gitdir:` prefixes missing a trailing space (e.g., `gitdir:foo/bar`), which the original code accepted.
  - Treats trailing whitespace in `.git` files as part of the path (e.g., `gitdir: foo/bar/   ` resolves to `worktrees/   `), whereas the original code trimmed it.
  - Behavior for completely invalid `.git` files (e.g., missing `gitdir:` prefix) remains unchanged, as `read_gitfile_gently()` is still used for initial validation.
- Patch 1:
  - Replaces `read_gitfile_gently()` with `read_gitfile_raw()` in `repair_worktree_at_path()`, moving path resolution and repository validation to the caller.
  - Uses `strbuf` for `.git` file content, avoiding memory leaks and aligning with `repair_gitfile()`.
  - Explicitly handles absolute and relative paths in `.git` files, stripping the `.git` suffix and appending relative paths when necessary.
  - Preserves existing fallback to inferred backlinks when the `.git` file is invalid but an inferred path exists.
- Patch 2:
  - Refactors `repair_worktree_at_path()` to centralize inferred backlink selection logic, reordering steps so the inferred backlink is computed after reading the `.git` file but before validating the backlink’s gitdir.
  - Ensures the inferred backlink is preferred when both a valid gitdir and an inferred path exist, addressing edge cases where a worktree was copied (rather than moved) alongside its main repository.
  - No new functions or behavior changes; the logic is now clearer and easier to follow.
- Patch 3 (this email):
  - Refactors `infer_backlink()` to use `read_gitfile_raw()`, ensuring consistent parsing of `.git` files (e.g., trailing whitespace handling, `gitdir:` prefix validation) with `repair_gitfile()` and `repair_worktree_at_path()`.
  - Extracts `get_worktree_id()` as a helper function to simplify worktree ID extraction, replacing manual pointer arithmetic with a cleaner abstraction. This function is reused in patch 5 for validation logic.
  - No behavior changes; the patch is purely internal refactoring to align parsing rules and reduce code duplication.
