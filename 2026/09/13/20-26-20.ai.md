This is a bugfix series targeting the object database (ODB) transaction layer, specifically a race during transaction commit when both loose objects and large blobs are present and `core.fsync` is configured to batch loose-object writes.

The two-patch series addresses a scenario where a "large" blob (exceeding `core.bigFileThreshold`) is written to a packfile in the transaction's temporary directory, but the transaction is migrated to the main ODB before the packfile is finalized. This leaves the packfile unflushed, causing a "No such file or directory" error when Git later tries to rename the temporary packfile. The fix ensures pending packfiles are flushed before the transaction migrates its objects.

Patch 1/2 refactors `odb_maybe_flush_packfile()` to lift the ODB reprepare step out of the packfile flush logic, making the function more focused. Patch 2/2 adds a call to flush any pending transaction packfile before migrating objects during transaction commit. The series includes a new test in `t/t1050-large.sh` that reproduces the bug with a minimal repository setup: two files (one small, one large), `core.fsync` enabled, and `core.fsyncMethod` set to `batch`.

The fix is narrowly scoped to the ODB transaction layer, touching only `object-file.c` and adding a targeted test.
