This is a CI/build system patch series that has reached final approval. Junio C Hamano confirms that the v4 iteration of Johannes Schindelin’s two-patch series—enabling Rust compilation in Git’s GitHub Actions Windows CI jobs—is ready for integration. The patches configure the Rust toolchain to target the GCC ABI (MinGW) instead of the default MSVC ABI, ensuring Cargo produces a static library (`libgitcore.a`) compatible with Git for Windows’ linker. All prior feedback from Junio and James Le Cuirot has been addressed, including the removal of the `--target` flag for native builds to align with Cargo’s expected behavior.

The series touches `.github/workflows/main.yml`, `ci/lib.sh`, `config.mak.uname`, and the `Makefile`, but does not affect core Git functionality, on-disk formats, or user-facing features. Junio plans to merge the patches directly into `next` and fast-track them to `master`, bypassing the usual one-week cooking period due to the lower likelihood of Windows users building from source. The only remaining loose end is testing on GitLab’s Windows runners (`saas-windows-medium-amd64`), where Rust availability and toolchain compatibility are still unconfirmed, but this is not treated as a blocker.

This series is a prerequisite for the broader Rustification effort in Git, as it removes the `NO_RUST` opt-out in CI and unblocks future patches introducing Rust code. The patches are narrowly scoped, well-motivated, and unlikely to be controversial.
