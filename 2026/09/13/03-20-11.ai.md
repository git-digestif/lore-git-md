This is a two-patch bugfix series targeting the `git worktree repair` command. The issue is that the command can incorrectly modify `.git` files or gitdirs that belong to unrelated worktrees if the cross-references between a linked worktree and its administrative data are not properly validated before repair. The series first refactors the code to reduce redundant `.git` file reads and extract the worktree ID, then uses that ID to validate the repair target before making changes.

The fix is structured as a refactoring (patch 1/2) followed by the actual validation logic (patch 2/2), which is a clean approach. The test file (`t/t2406-worktree-repair.sh`) is updated to cover the new validation, suggesting the fix is tested.
