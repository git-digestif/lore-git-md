This is the second patch in a two-part bugfix series for `git worktree repair`. It addresses a correctness issue where the command can incorrectly modify `.git` files or gitdirs belonging to unrelated worktrees, potentially corrupting them.

The patch adds validation logic to ensure the worktree ID recorded in the `.git` file matches the worktree being repaired. If the IDs don’t match or the gitdir path cannot be inferred, the repair stops with an error message. The test suite (`t/t2406-worktree-repair.sh`) is expanded with new cases to verify this behavior, including scenarios where worktrees are swapped or copied without using `git worktree move`.

The fix is narrowly scoped to `worktree.c` and the test script, with no changes to on-disk formats or broader behavior. The commit message clearly explains the edge cases (e.g., swapped worktree directories, copied worktrees) and how the validation prevents corruption.
