This thread is a two-patch bugfix series from Justin Tobler addressing a race condition in Git's object database (ODB) transaction layer. The issue surfaces during commit when loose objects and large blobs are present with `core.fsync` batching enabled: a large blob written to a packfile in a transaction's temporary directory can be left unflushed if the transaction migrates to the main ODB before the packfile is finalized, causing a "No such file or directory" error.

The first patch, already posted, refactored `odb_maybe_flush_packfile()` to separate ODB reprepare logic from packfile flushing, making the code modular for the fix. The second and final patch, just posted, moves the call to `flush_packfile_transaction()` earlier in `odb_transaction_files_commit()` to ensure pending packfiles are flushed before transaction migration. It also adds a new test (`t/t1050-large.sh`) that reproduces the bug with a minimal repository setup and verifies the fix.

The series is narrowly scoped, touching only `object-file.c` and introducing no on-disk format changes or new CLI/config options. It’s part of the ongoing ODB abstraction effort led by Patrick Steinhardt, and Justin is a frequent contributor to that work. The fix appears correct and uncontroversial, but no reviews have been posted yet. Once reviewed, it’s likely to be merged, as it resolves a real bug without broader implications.
