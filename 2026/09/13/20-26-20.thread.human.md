This thread is a two-patch bugfix series from Justin Tobler addressing a race condition in Git’s object database (ODB) transaction layer. The issue surfaces when loose objects and large blobs (exceeding `core.bigFileThreshold`) are present with `core.fsync` batching enabled, causing a "No such file or directory" error during transaction migration. The fix ensures pending packfiles are flushed before the transaction moves to the main ODB, eliminating the race.

The series is under active review, with a v2 update planned to incorporate feedback. Patch 1 refactors `odb_maybe_flush_packfile()` to separate reprepare logic from packfile flushing, while Patch 2 adds an early call to `flush_packfile_transaction()` in `odb_transaction_files_commit()` and includes a test (`t/t1050-large.sh`) to reproduce the bug. Karthik Nayak and Patrick Steinhardt have reviewed the patches, with Patrick raising concerns about inaccuracies in the commit message and test for Patch 2. Justin has agreed to address these by correcting the commit message (which incorrectly claimed ODB repreparation was deferred) and improving the test’s clarity by adopting Patrick’s subshell suggestion and removing a misleading comment. The core fix remains unchanged, and the series is on track for merging once these adjustments are finalized.

The work is part of the broader ODB abstraction effort led by Patrick Steinhardt, which aims to enable pluggable backends. No major technical objections remain, and the changes are confined to `object-file.c` and the new test file, with no on-disk format or CLI/configuration changes. The latent issue of `flush_packfile_transaction()` swallowing errors via `die()` is acknowledged but deferred to a future series.
