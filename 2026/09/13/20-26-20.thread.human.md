This thread is about a two-patch bugfix series from Justin Tobler that fixes a race condition in Git’s ODB transaction layer. The issue occurs when large blobs are written to packfiles during a commit with `core.fsync` batching enabled: the transaction migrates to the main ODB before the packfile is finalized, leaving it unflushed and causing a "No such file or directory" error. The fix refactors `odb_maybe_flush_packfile()` to separate reprepare logic (patch 1/2) and adds an early call to `flush_packfile_transaction()` in `odb_transaction_files_commit()` to ensure packfiles are flushed before migration (patch 2/2). A new test (`t/t1050-large.sh`) reproduces the bug and verifies the fix.

The series is now effectively approved. Karthik Nayak reviewed both patches, suggesting a minor optimization for patch 1/2 (declined by Justin) and a stylistic test tweak for patch 2/2 (also declined, as the existing cleanup makes it unnecessary). No further feedback is outstanding, and the fix is uncontroversial. The patches touch `object-file.c` and add the new test, with no on-disk format changes or new CLI/config options. This work is part of Patrick Steinhardt’s broader ODB abstraction effort, stabilizing the transaction API for pluggable backends.
