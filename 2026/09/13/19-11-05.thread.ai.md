Subject: [PATCH 0/2] Windows (mingw) test fixes for Perl and UTF-8 handling
Series version: v1 (initial submission)
Originating author: Johannes Schindelin (via GitGitGadget)
Thread type: patch series (platform compatibility)

Core problem or goal
Fix two minor test failures that surfaced during full Windows/ARM64 test runs in preparation for Git for Windows v2.56.0-rc0. The failures are Windows-specific and do not affect core Git functionality; they prevent clean test runs on the platform. The first patch adjusts Perl environment detection in `t/t9700/test.pl` to accommodate MSYS2 Perl now reporting itself as `cygwin` (via `$^O`), while the second patch unconditionally skips UTF-8 tests in `t/t9129` on Windows due to fundamental encoding incompatibilities between Git for Windows (native Win32 "Code Pages") and MSYS2 Perl (Unix-style `LC_ALL`).

Current status
Under review (initial submission). Two patches:
1. **t9700**: Replaces `$^O eq 'msys'` with `defined $ENV{MSYSTEM} && $ENV{MSYSTEM} ne 'MSYS'` to correctly identify environments where `git.exe` reports absolute Windows paths (requiring `cygpath` conversion) versus pseudo-Unix paths. The change is minimal (one line) and preserves compatibility with both Cygwin and older MSYS2 setups.
2. **t9129**: Unconditionally skips all UTF-8-related tests on Windows (`!MINGW`) due to the irreconcilable encoding mismatch. The patch modifies two `test_expect_success` invocations to include the `!MINGW` prerequisite (two lines).

- Files touched: `t/t9700/test.pl` (Perl environment string matching), `t/t9129-git-svn-i18n-commitencoding.sh` (UTF-8 test skipping).
