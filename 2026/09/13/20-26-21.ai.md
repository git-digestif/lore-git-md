This is the first patch in a two-patch bugfix series targeting a race condition in Git's ODB transaction layer. The patch refactors `odb_maybe_flush_packfile()` to separate ODB repreparation from packfile flushing, making the logic more modular and preparing the ground for the actual fix in patch 2/2.

The change lifts the `odb_reprepare()` call out of `flush_packfile_transaction()` and moves it to the callers: `odb_transaction_files_write_object_stream()` (where it remains functionally unchanged) and `odb_transaction_files_commit()` (where it is now conditional on whether a packfile was actually written). This refactoring is small (10 lines changed) and touches only `object-file.c`. The commit message explains the motivation clearly: repreparation is being slightly deferred in the subsequent patch, so the ODB must be explicitly refreshed by callers after flushing.

The patch is well-scoped and appears to be a clean preparatory step for the actual bugfix. No behavior change is introduced yet, and the refactoring is straightforward. The test coverage for the race itself will come in patch 2/2, but this patch does not break any existing functionality. Justin Tobler is a frequent contributor to the ODB abstraction effort, and this patch aligns with the ongoing work to stabilize the transaction API for pluggable backends. The series as a whole addresses a real and well-documented race, and this patch is a necessary step toward that fix.
