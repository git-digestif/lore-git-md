# Thread deltas

## 2026/09/13

- [2026/09/13/20-26-20 by Justin Tobler <jltobler@gmail.com>] Justin Tobler posted a two-patch series fixing a commit failure for an ODB transaction containing both a loose object and a "large" blob when `core.fsyncMethod` is `batch`, caused by the transaction's temporary directory being migrated to the main ODB before the packfile is flushed.
- [2026/09/13/20-26-21 by Justin Tobler <jltobler@gmail.com>] Patch 1/2 lifts the `odb_reprepare()` call out of `flush_packfile_transaction()` and instead requires callers to invoke it explicitly, adding explicit calls in `odb_transaction_files_write_object_stream()` and `odb_transaction_files_commit()`.
- [2026/09/13/20-26-22 by Justin Tobler <jltobler@gmail.com>] Patch 2/2 moves the `flush_packfile_transaction()` call in `odb_transaction_files_commit()` to occur before objects are migrated to the main ODB, and adds a test case in `t/t1050-large.sh` verifying that adding a large file alongside a loose object under batch fsync leaves no objects in temporary locations.
