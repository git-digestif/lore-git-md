Thread identity: Bugfix series addressing a race in the ODB transaction layer during commit when loose objects and large blobs are present with `core.fsync` batching enabled. Series version: v1 (initial submission). Originating author: Justin Tobler. Thread type: patch series (bugfix).

Core problem or goal: Fix a race condition where a "large" blob (exceeding `core.bigFileThreshold`) is written to a packfile in a transaction's temporary directory, but the transaction migrates to the main ODB before the packfile is finalized. This leaves the packfile unflushed, causing a "No such file or directory" error during the subsequent rename operation. The fix ensures pending packfiles are flushed before transaction migration by refactoring `odb_maybe_flush_packfile()` (patch 1/2) and adding a call to flush pending transaction packfiles during commit (patch 2/2).

Current status: Under review (initial submission). The series consists of two patches, both posted:
1. Refactored `odb_maybe_flush_packfile()` to separate ODB reprepare logic from packfile flushing (no functional change; preparatory for patch 2/2). Karthik Nayak suggested a minor optimization to conditionally flush packfiles only when `have_packfile` is true, but Justin Tobler declined, noting that `flush_packfile_transaction()` already handles the no-op case efficiently. The patch remains unchanged.
2. Adds a call to `flush_packfile_transaction()` earlier in `odb_transaction_files_commit()` to flush pending packfiles before transaction migration, resolving the race. Includes a new test (`t/t1050-large.sh`) that reproduces the bug with a minimal repository setup (two files, `core.fsync` enabled, `core.fsyncMethod=batch`). Karthik Nayak confirmed the logic is correct and necessary, with only a minor stylistic suggestion for the test (using `test_config` instead of manual `git config` calls, though the existing `test_when_finished` cleanup makes this optional).

- Behavior change: Patch 2/2 ensures packfiles are flushed before transaction migration, eliminating the race. No on-disk format changes or new CLI/config options introduced.
