Thread identity: Bugfix series addressing a race in the ODB transaction layer during commit when loose objects and large blobs are present with `core.fsync` batching enabled. Series version: v2 (incorporates review feedback). Originating author: Justin Tobler. Thread type: patch series (bugfix).

Core problem or goal: Fix a race condition where a "large" blob (exceeding `core.bigFileThreshold`) is written to a packfile in a transaction's temporary directory, but the transaction migrates to the main ODB before the packfile is finalized. This leaves the packfile unflushed, causing a "No such file or directory" error during the subsequent rename operation. The fix ensures pending packfiles are flushed before transaction migration by refactoring `odb_maybe_flush_packfile()` (patch 1/2) and adding a call to flush pending transaction packfiles earlier in `odb_transaction_files_commit()` (patch 2/2).

Current status: Under review, with v2 addressing all prior feedback. The series consists of two patches:
1. Refactored `odb_maybe_flush_packfile()` to separate ODB reprepare logic from packfile flushing, making callers explicitly invoke `odb_reprepare()`. The commit message now correctly clarifies that the reprepare step is *not* deferred—only the packfile flush is moved earlier in patch 2/2. No functional changes were introduced; the patch is purely preparatory for the race fix in patch 2/2.
2. Adds a call to `flush_packfile_transaction()` earlier in `odb_transaction_files_commit()` to flush pending packfiles before transaction migration, resolving the race. The test (`t/t1050-large.sh`) has been improved for readability (wrapped in a subshell) and now omits the inaccurate comment about checking for leftover objects in temporary locations. The test continues to verify object readability, which remains the correct validation for this bug.

Key technical details:
- Files touched: `object-file.c` (ODB transaction layer), `t/t1050-large.sh` (test).
- Symbols: `odb_maybe_flush_packfile()` (refactored to separate reprepare logic), `flush_packfile_transaction()` (now called earlier in `odb_transaction_files_commit()`), `odb_transaction_files_write_object_stream()` and `odb_transaction_files_commit()` (callers updated to handle reprepare logic explicitly).
- Behavior change: Patch 2/2 ensures packfiles are flushed before transaction migration, eliminating the race. Patch 1/2’s refactoring does not alter the original behavior regarding `odb_reprepare()` calls (it is only invoked when there is a packfile to flush). No on-disk format changes or new CLI/config options introduced.
- Test coverage: The race is reproduced and fixed in `t/t1050-large.sh`, which verifies object readability after commit under `core.fsync=loose-object` and `core.fsyncMethod=batch` settings. The test improvements in v2 include subshell wrapping for cleaner cleanup and removal of an inaccurate comment.
