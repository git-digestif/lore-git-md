This is a CI/build system patch series that enables Rust compilation in Git’s GitHub Actions Windows CI jobs. Junio C Hamano has just marked the v4 iteration as ready for integration, noting that while the project typically cooks new patches in `next` for a week, the Windows platform—with its higher proportion of binary users—would not benefit as much from this delay. He therefore intends to merge the series directly into `next` and fast-track it to `master`.

The series, authored by Johannes Schindelin, configures GitHub’s pre-installed Rust toolchain to target the GCC ABI (used by Git for Windows) rather than the default MSVC ABI, ensuring Cargo produces a static library (`libgitcore.a`) compatible with MinGW’s linker. This unblocks the Rust requirement introduced in Git 2.55.0 for Windows CI without expanding the minimal Git for Windows SDK. The v4 revision removes the `--target` flag for native builds, aligning with feedback from James Le Cuirot and the recently merged `jc/rust-cargo-build-target` topic, and now sets `CARGO_BUILD_TARGET` only for cross-compilation cases.

The patches touch `.github/workflows/main.yml`, `ci/lib.sh`, `config.mak.uname`, and the `Makefile`, but do not affect core Git functionality, on-disk formats, or user-facing features. All prior feedback has been addressed, and the series is considered ready for merging. The only remaining open question is whether the patches work on GitLab’s Windows runners (`saas-windows-medium-amd64`), as Rust availability and toolchain compatibility there remain unconfirmed. Johannes has explicitly requested testing from GitLab contributors but does not treat this as a blocker.

This series is a prerequisite for the broader Rustification effort in Git, as it removes the `NO_RUST` opt-out in CI and directly unblocks future Rust-related work. The patches are narrowly scoped, well-motivated, and unlikely to be controversial. Junio’s decision to fast-track the series reflects confidence in its readiness and the low risk of regressions for Windows users.
