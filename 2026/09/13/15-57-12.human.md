This is the second patch in Johannes Schindelin’s v4 series enabling Rust compilation in Git’s GitHub Actions Windows CI jobs. It removes the `NO_RUST` opt-out in `ci/lib.sh` and adds a step to install the precompiled Rust `std` library for the GCC-compatible target triple via `rustup target add`.

The patch is narrowly scoped to the CI workflow and does not affect core Git functionality. It mirrors the target-triple mapping logic from `config.mak.uname` in the CI script, explicitly handling each `MSYSTEM` value (`MINGW64`, `UCRT64`, `CLANGARM64`, etc.) to ensure the correct Rust target is installed. The step runs after the Git for Windows SDK is set up but before the build, ensuring Cargo can produce a static library (`libgitcore.a`) compatible with MinGW’s linker. The commit message clarifies that `rustup target add` is sufficient because Cargo does not invoke an external linker for `staticlib` crates.

All prior feedback has been addressed: the v4 revision aligns with the recently merged `jc/rust-cargo-build-target` topic, and the mapping logic is now explicit and well-documented. The only open question is whether the patch works on GitLab’s Windows runners, but Johannes does not treat this as a blocker. The series is ready for final review and is unlikely to be controversial. If you care about Rust support in Git’s CI, this patch is worth a quick look.
