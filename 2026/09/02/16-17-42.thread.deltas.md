# Thread deltas

## 2026/09/02

- [2026/09/02/16-17-42 by Alessio Attilio via GitGitGadget <gitgitgadget@gmail.com>] Alessio Attilio posted v1 of a patch introducing a boolean `hooks.allowNoVerify` configuration (default `true`; `false` makes `git commit/push/merge/rebase/am --no-verify` abort with a fatal error), with tests in t/t7599-hooks-allownoverify.sh.
- [2026/09/02/16-35-25 by Alessio Attilio via GitGitGadget <gitgitgadget@gmail.com>] Alessio Attilio posted v2, expanding the variable to granular values (`true`/`always`, `warn`, `false`/`never`/`error`), adding the `GIT_ALLOW_NO_VERIFY=1` environment variable as an emergency override, and centralizing the check in a new `validate_no_verify()` in hook.c/hook.h called from all affected commands.
- [2026/09/02/17-23-14 by Alessio Attilio via GitGitGadget <gitgitgadget@gmail.com>] Alessio Attilio posted v3, dropping the `always`/`never`/`error` aliases so only `true` (default), `warn`, and `false` remain.
- [2026/09/02/17-45-23 by Alessio Attilio via GitGitGadget <gitgitgadget@gmail.com>] Alessio Attilio posted v4, whose only change over v3 is a new test that `hooks.allowNoVerify=false` disallows `git am --no-verify`.
- [2026/09/02/19-21-01 by Junio C Hamano <gitster@pobox.com>] Junio C Hamano rejected the proposal, arguing it starts a slippery slope (a further variable would be needed to block `git -c hooks.allowNoVerify=... --no-verify`) and that limiting such a setting to hooks is not a good idea since bypassable verifications are not always hooks.
- [2026/09/02/22-14-41 by brian m. carlson <sandals@crustytoothpaste.net>] brian m. carlson agreed with the rejection, stating `--no-verify` is the right option when a user does not want local hooks, that forced local hooks are not an effective control per the Git FAQ, and that hooks can be trivially bypassed anyway via `core.hooksPath=/dev/null`.
