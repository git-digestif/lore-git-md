This thread is about a patch series introducing a new `parse-options` sub-API called `early_scan_options()`, designed to replace fragile hand-rolled early argument scans in Git commands. The series is now in its third version (v3), addressing feedback from Junio Hamano and Kaartic Sivaraam on earlier iterations. The core goal is to provide a minimal, reusable API that handles negated options, unambiguous abbreviations, and aliases consistently with Git's existing `parse_options()` function, while fixing a real bug in `git fast-import` where `--allow-unsafe-features` was silently ignored when preceded by `--depth 5`.

The series is under active review, with most patches technically sound and ready for the `next` branch. The preparatory refactorings (patches 1/6 and 2/6) are uncontroversial and could proceed independently. Patch 4/6, which fixes the `git fast-import` bug, is also ready for `next` and has received maintainer approval. The main API patch (3/6) addresses all prior feedback but still has an unresolved usability concern: whether the caller or the API should handle argument skipping (e.g., `--option value`). Christian Couder maintains that the caller should handle this, while Junio Hamano has suggested the API would be easier to use if it handled skipping internally. This design question may require further iteration before the series is ready for `next`.

Kaartic Sivaraam recently reviewed patch 2/6, suggesting a minor but meaningful improvement to replace an `if`-statement chain with a `switch` on an enum return value for better clarity and maintainability. This change is not a blocker but would align the code with Git's style guidelines. The series as a whole is well-tested, with comprehensive coverage for edge cases like stuck values, negated options, and ambiguous abbreviations. The API is designed to err on the side of caution, stopping the scan at arguments it cannot reliably skip (e.g., short options, ambiguous abbreviations) to avoid misinterpreting values. No on-disk format changes or option semantics are altered beyond the bugfix.
