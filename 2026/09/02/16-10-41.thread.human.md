This thread is about a patch series introducing a new `parse-options` sub-API (`early_scan_options()`) to replace fragile hand-rolled early argument scans in Git commands. The series, now in its second version (v2), is authored by Christian Couder and focuses on fixing a real bug in `git fast-import`: the `--allow-unsafe-features` option was silently ignored when preceded by `--depth 5`, causing the command to refuse unsafe features from the input stream.

The v2 redesign addresses feedback from Junio Hamano by eliminating a separate `early_scan_option` structure and requiring commands to adopt the full `parse-options` API before using the early scanner. The series is now more focused, dropping conversions for `git bisect` and `git rev-parse` (deemed of low practical value) and concentrating on the `git fast-import` bugfix. The API is deliberately limited—ignoring short options, negated forms, abbreviations, and subcommands—to prioritize simplicity and speed. Key changes include a new `PARSE_OPT_EARLY` flag, the `early_scan_options()` function, and preparatory refactoring to avoid code duplication.

Junio had previously approved the `git fast-import` conversion in v1, and the bugfix itself is likely ready for the `next` branch. However, the broader API design remains under discussion, with lingering questions about its long-term viability and scope of adoption. Christian argues that the v2 design ensures future refactoring (e.g., a "dry-run" mode in `parse_options()`) won’t require redoing the conversion work, as the API now reuses `struct option`. The series has passed CI cleanly, and the remaining patches are well-tested and documented, but further iteration may be needed to address design questions before the API is ready for broader adoption.
