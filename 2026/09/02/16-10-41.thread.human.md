This thread introduces a new `parse-options` sub-API called `early_scan_options()` to replace fragile hand-rolled early argument scans in Git commands. The series, now at its fourth and final version, fixes a real bug in `git fast-import` where `--allow-unsafe-features` was silently ignored when preceded by `--depth 5`. The API is designed to be conservative—stopping at short options, unknown options, ambiguous abbreviations, and low-level callbacks—to avoid misinterpreting option values.

The core of the series is uncontroversial and ready for integration. All feedback from earlier versions has been addressed, including validation checks, code clarity improvements (like replacing an `if`-statement chain with a `switch`), and documentation clarifications. The `git fast-import` bugfix and preparatory refactorings are fully tested, with 28 new tests covering edge cases like negated options, ambiguous abbreviations, and non-option arguments. Junio Hamano approved the `fast-import` conversion early on, and reviewers Kaartic Sivaraam and Cynthia Uche have confirmed the final version resolves all prior concerns.

The new API is now robust and well-documented, with no open questions remaining. It touches core argument-parsing infrastructure and is designed for broader adoption in commands like `git bisect` or `git rev-parse`, though that’s not a blocker for this series. The series is ready for Junio’s `next` branch.
