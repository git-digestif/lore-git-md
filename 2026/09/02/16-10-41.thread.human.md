This thread is about a patch series introducing `early_scan_options()`, a new sub-API for Git’s `parse-options` library that replaces fragile hand-rolled early argument scans in commands like `git fast-import`. The series, now in its third version (v3), addresses feedback from earlier iterations by reusing `parse-options` internals to handle negated options, unambiguous abbreviations, and aliases consistently with the main `parse_options()` function. The redesign fixes a real bug in `git fast-import` where `--allow-unsafe-features` was silently ignored when preceded by `--depth 5`, and it adds comprehensive test coverage for edge cases.

The series is under active review, with broad approval for the core design. Two preparatory refactorings (patches 1/6 and 2/6) and the `git fast-import` bugfix (patch 4/6) are uncontroversial and ready to proceed independently. The main API patch (3/6) is technically sound but has two unresolved technical concerns from Kaartic Sivaraam’s review: validation checks in `early_scan_options()` to catch invalid uses of `PARSE_OPT_EARLY`, and clarifying the API documentation to warn callers about the ephemeral nature of the `option` pointer passed to callbacks. Junio Hamano’s earlier usability concern—whether the API should handle argument skipping internally or leave it to callers—remains unresolved but is no longer a blocker for progress.

Christian Couder, the author, has not yet responded to the latest feedback, but the remaining issues are minor and actionable. The series is close to being ready for Junio’s `next` branch, pending resolution of these small items. Once merged, the API could be adopted by other commands with early-scan needs, such as `git bisect` or `git rev-parse`.
