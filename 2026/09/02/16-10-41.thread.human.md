This thread introduces a new `parse-options` sub-API (`early_scan_options()`) to replace fragile hand-rolled early argument scans in Git commands, fixing a real bug in `git fast-import` where `--allow-unsafe-features` was silently ignored when preceded by `--depth 5`. The series, now at its fourth iteration (v4), has addressed all feedback from prior rounds, including validation checks, code clarity improvements, and documentation updates. Key participants—Christian Couder (author), Junio C Hamano (maintainer), Kaartic Sivaraam (reviewer), and Cynthia Uche (reviewer)—have all signed off on the final version, with Junio explicitly marking the topic as ready for the `next` branch in his latest email.

The API reuses `parse-options` internals (`lookup_long_opt()`) to handle negated options, unambiguous abbreviations, and aliases consistently with `parse_options()`. It introduces new flags (`PARSE_OPT_EARLY`, `EARLY_SCAN_STOP_AT_NON_OPTION`) and functions (`early_scan_options()`, `find_early_scan_option()`) while extending existing validation (`parse_options_check()`). The series touches core argument-parsing infrastructure (`parse-options.h`, `parse-options.c`), `fast-import.c`, and documentation, adding 28 new tests in `t/t0040-parse-options.sh` to cover edge cases like stuck/separate values, negated options, and ambiguous abbreviations. The `git fast-import` bugfix is tested in `t/t9300-fast-import.sh` with four new tests confirming the regression is resolved.

With all open questions resolved and the series now queued for integration testing in `next`, this effort is effectively complete. The API is designed to be reusable for other commands with hand-rolled early scans (e.g., `git bisect`, `git rev-parse`), though such adoption would be follow-up work. No further revisions or discussion are expected.
