This thread is about a patch series introducing `early_scan_options()`, a new sub-API in Git’s `parse-options` framework to replace fragile hand-rolled early argument scans in commands. The series, now in its third version (v3), is authored by Christian Couder and addresses feedback from Junio Hamano and Kaartic Sivaraam on earlier iterations. The goal is to provide a minimal, reusable API that handles negated options, unambiguous abbreviations, and aliases consistently with Git’s existing `parse_options()` function, while fixing a real bug in `git fast-import` where `--allow-unsafe-features` was silently ignored when preceded by `--depth 5`.

The v3 redesign reuses `parse-options` internals (`lookup_long_opt()`) to ensure consistency with `parse_options()`, and the scan now stops at short options, unknown options, ambiguous abbreviations, and low-level callbacks to avoid misinterpreting values. The series is split into six patches: the first is a preparatory refactoring (extracting `parse_options_takes_argument()` from shell completion logic), the second introduces the core API, and the third converts `git fast-import` to use the new API, fixing the bug. The remaining patches add tests and documentation. The `git fast-import` conversion is ready for Junio’s `next` branch, but the broader API design remains under discussion due to a lingering usability concern: whether the API should handle argument skipping internally (as Junio suggested) or leave it to callers (as Christian implemented). This decision could require further iteration before the series graduates to `next`.

Key participants include Christian (the author), Junio (the maintainer), and Kaartic (a reviewer). Junio initially approved the `git fast-import` fix but raised the argument-skipping concern in v2, which remains unresolved. Kaartic’s v2 feedback about abbreviated options was fully addressed in v3 by reusing `lookup_long_opt()`. The series has passed CI and is well-tested, with comprehensive coverage for edge cases like stuck values, negated options, and ambiguous abbreviations. The API is designed to err on the side of caution, potentially missing some options but never reporting false positives. While the series is not yet ready for `next`, the `git fast-import` bugfix is a clear win and could proceed independently.
