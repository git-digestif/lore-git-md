This thread is about a patch series introducing `early_scan_options()`, a new sub-API for Git’s `parse-options` library, now in its third version. The goal is to replace fragile hand-rolled early argument scans in Git commands with a reusable, consistent API that handles negated options, unambiguous abbreviations, and aliases the same way `parse_options()` does. The series fixes a real bug in `git fast-import`, where `--allow-unsafe-features` was silently ignored when preceded by `--depth 5`.

Christian Couder has revised the series to address feedback from Junio Hamano and Kaartic Sivaraam, focusing on safety and consistency. The API now stops at short options, unknown options, ambiguous abbreviations, and low-level callbacks to avoid misinterpreting values, and it reuses `parse-options` internals (`lookup_long_opt()`) to handle edge cases like negated options and abbreviations. The preparatory refactorings (patches 1/6 and 2/6) and the `git fast-import` bugfix (patch 4/6) are ready for Junio’s `next` branch, but the core API (patch 3/6) is still under review due to a lingering usability concern: whether the caller or the API should handle skipping arguments (e.g., `--option value`). Christian argues for keeping this responsibility with the caller, while Junio suggested it would be easier to use if the API handled it internally.

The series is technically sound, well-tested (28 new tests cover edge cases), and documented, but the argument-skipping question remains unresolved. Kaartic’s feedback has been fully addressed, and the API’s behavior is now aligned with `parse_options()`. The next steps will likely involve further discussion on the usability trade-off before the core API can proceed to `next`.
