This thread introduces a new `parse-options` sub-API called `early_scan_options()` to replace fragile hand-rolled early argument scans in Git commands. The series, now at version 4, is a bugfix and API refactoring led by Christian Couder. The key motivation is fixing a real bug in `git fast-import`: `--allow-unsafe-features` was silently ignored when preceded by an option with a separate value (e.g., `--depth 5 --allow-unsafe-features`), causing the command to refuse unsafe features from the input stream.

The series has converged after addressing all feedback from Junio Hamano, Kaartic Sivaraam, and Cynthia Uche. The core API (patch 3/4) now includes validation checks, clearer documentation, and thorough test coverage, while the `git fast-import` conversion (patch 4/4) is uncontroversial and ready for integration. The preparatory refactorings (patches 1-2/4) are also stable. Junio’s "What's cooking" report should now list this topic as ready for the `next` branch.

The new API reuses `parse-options` internals to handle negated options, unambiguous abbreviations, and aliases consistently with `parse_options()`. It stops the scan at short options, unknown options, ambiguous abbreviations, and low-level callbacks to avoid misinterpreting values. The `git fast-import` conversion removes outdated documentation and adds tests to verify the bugfix, abbreviation handling, and edge cases. No open questions remain, and the series is now considered complete.
