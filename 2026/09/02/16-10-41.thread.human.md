This thread is about a patch series introducing a new `parse-options` sub-API (`early_scan_options()`) to replace hand-rolled early argument scanning in Git commands. The series, now in its second version, focuses on fixing a real bug in `git fast-import` where `--allow-unsafe-features` was silently ignored when preceded by `--depth 5`. The v2 redesign addresses maintainer Junio C Hamano’s feedback from v1 by simplifying the API, reusing the existing `struct option` instead of a separate abstraction, and dropping less compelling conversions (e.g., `git bisect`).

The core API is deliberately minimal, ignoring short options, negated forms, abbreviations, and subcommands to prioritize simplicity and speed. The series includes a preparatory refactoring (patch 1/6), the core API implementation (patch 2/6), and the `git fast-import` bugfix (patch 3/6). Junio previously approved the `git fast-import` conversion in v1, and his remaining concerns about the API’s scope have been resolved by Christian’s decision to focus the series on the most practical use case. The series is now under review, with no major objections remaining, though a usability concern about argument-skipping responsibility (whether the API or the caller should handle `--option value`) may require further iteration before the series is ready for the `next` branch.

Christian has defended the current design as a pragmatic trade-off, and Junio’s latest reply accepts the revised scope, leaving the API’s long-term viability as the primary open question. The series is well-tested, with comprehensive coverage for edge cases and the `git fast-import` bugfix. No merge status has been reported for the API patches, but the `git fast-import` conversion is likely to land in `next` once the remaining design details are settled.
