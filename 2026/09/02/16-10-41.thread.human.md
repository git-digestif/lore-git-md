This thread introduces a new `parse-options` sub-API, `early_scan_options()`, designed to replace fragile hand-rolled early argument scans in Git commands. The series, now at version 4, addresses all prior feedback and is ready for integration into Junio’s `next` branch. The core goal is to provide a minimal, reusable API that reuses `parse-options` internals to handle negated options, unambiguous abbreviations, and aliases consistently, while fixing a real bug in `git fast-import` where `--allow-unsafe-features` was silently ignored when preceded by `--depth 5`.

Christian Couder authored the series, which has evolved through four iterations to resolve concerns from Junio Hamano, Kaartic Sivaraam, and Cynthia Uche. The v4 series streamlines the implementation to four patches, adding validation checks, clearer documentation, and thorough test coverage. The `git fast-import` bugfix (patch 4/4) and preparatory refactorings (patches 1/4 and 2/4) are uncontroversial and ready for merging. The core API (patch 3/4) now includes improvements like a `switch`-based dispatch in `parse_long_opt()` for better readability and validation checks to prevent invalid uses of `PARSE_OPT_EARLY`.

The technical details include new flags (`PARSE_OPT_EARLY`, `EARLY_SCAN_STOP_AT_NON_OPTION`), new functions (`early_scan_options()`, `find_early_scan_option()`, and helpers), and updates to `parse-options.h`, `parse-options.c`, `fast-import.c`, and related test files. The API is designed to stop scanning at short options, unknown options, ambiguous abbreviations, and low-level callbacks to avoid misinterpreting option values. Test coverage includes 28 new tests in `t/t0040-parse-options.sh` and three new tests in `t/t9300-fast-import.sh`, ensuring the bugfix and edge cases are thoroughly validated.

All substantive concerns from earlier versions have been resolved, including usability (argument skipping), validation checks, and documentation clarifications. The final reply in the thread addresses Cynthia Uche’s feedback on the `EARLY_SCAN_STOP_AT_NON_OPTION` flag, adding a clarifying comment and a test for the edge case where a non-option argument precedes `--allow-unsafe-features`. With this, the series is fully documented, tested, and uncontroversial, making it ready for integration. Future work may explore broader adoption of this API in other commands like `git bisect` or `git rev-parse`, but this is not a blocker for the current series.
