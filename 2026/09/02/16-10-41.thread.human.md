This thread is about Christian Couder’s v2 patch series introducing a new `parse-options` sub-API, `early_scan_options()`, designed to replace fragile hand-rolled early argument scans in Git commands. The series focuses on fixing a real bug in `git fast-import`, where `--allow-unsafe-features` was silently ignored when preceded by `--depth 5`. The v2 redesign addresses Junio Hamano’s feedback from v1 by reusing the existing `struct option` and dropping less compelling conversions (e.g., `git bisect`), making the series more focused and aligned with the `parse-options` API.

The series is under active review, with Junio’s prior approval of the `git fast-import` conversion suggesting it is ready for `next` once broader design questions are resolved. However, a substantive review from Kaartic Sivaraam raises a **correctness concern**: the API’s decision to ignore option abbreviations could misalign with `parse_options()` behavior. For example, in `git fast-import --quiet --export-pack --allow-unsafe-features`, `--export-pack` is an abbreviation of `--export-pack-edges`, so `--allow-unsafe-features` should be treated as its value, not as a separate option. Sivaraam proposes stopping the scan at the first unrecognized argument to mitigate this. The review also highlights minor clarity and test-coverage gaps, such as handling missing option values and adjusting return indices for better caller usability.

Christian’s v2 series is well-structured, with a preparatory refactoring (patch 1/6), the core API (patch 2/6), and the bugfix (patch 3/6). The API is deliberately limited—ignoring short options, negated forms, and subcommands—to prioritize simplicity and speed, though this trade-off remains a point of discussion. Junio’s feedback on v2 centers on a **usability concern**: the API requires callers to handle argument skipping (`--option value`), which could lead to duplication or inconsistencies. This is the primary open question, though it is more of a design refinement than a fundamental critique. The series is otherwise clean, well-tested, and likely to proceed to `next` once these edge cases are addressed.
