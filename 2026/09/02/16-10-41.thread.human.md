This thread is about a patch series from Christian Couder that introduces a new `parse-options` sub-API called `early_scan_options()` to fix a bug in `git fast-import` and provide a reusable way for Git commands to scan arguments early. The series is now in its second version, focusing narrowly on the `git fast-import` bugfix after Junio Hamano's feedback led to a major redesign.

The bug being fixed is that `git fast-import --depth 5 --allow-unsafe-features` would silently ignore the `--allow-unsafe-features` option because the hand-rolled argument scanner didn't properly account for options that take separate arguments. The new API ensures early scanning agrees with the full `parse-options` behavior, fixing this issue while also requiring the option to be spelled in full (no abbreviations) for safety. The series is under review, with the `git fast-import` conversion patch looking ready for Junio's `next` branch, though the broader API design may still see further discussion.

Christian has addressed Junio's earlier concerns by simplifying the API to reuse the existing `struct option` rather than introducing a parallel abstraction, and by focusing the series on the most compelling use case. The implementation is well-tested, with new tests verifying the bugfix and edge cases. While the API is deliberately limited—ignoring short options, negated forms, and abbreviations—it's documented clearly and should serve as a template for other commands that need early argument scanning. The main open question is whether this API will see broader adoption or if Junio's vision of a "dry-run" mode in `parse_options()` will eventually supersede it.
