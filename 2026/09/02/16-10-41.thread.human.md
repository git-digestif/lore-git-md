This thread is about a patch series introducing `early_scan_options()`, a new sub-API for Git’s `parse-options` library that replaces fragile hand-rolled argument scans in commands like `git fast-import`. The series is now in its third version, addressing earlier feedback by reusing `parse-options` internals to handle negated options, abbreviations, and aliases consistently with the main `parse_options()` function. The immediate goal is to fix a bug in `git fast-import` where `--allow-unsafe-features` was ignored when preceded by `--depth 5`, but the API is designed for broader use.

Christian Couder is the author, and the series has drawn attention from Junio Hamano (the maintainer) and Kaartic Sivaraam, who provided detailed reviews. The latest feedback comes from Cynthia Uche, who tested the `git fast-import` conversion patch (4/6) and confirmed it works as intended: the new API correctly detects `--allow-unsafe-features` even when it appears after other options, and the `EARLY_SCAN_STOP_AT_NON_OPTION` flag prevents misinterpreting non-option arguments. Cynthia also noted a small documentation gap—the comment above the `early_scan_options()` call could better explain why the flag is used—but this is a minor clarity issue, not a correctness problem. The patch is ready to proceed independently of the rest of the series.

The core API patch (3/6) is technically sound and well-tested, but two open questions remain: whether `early_scan_options()` should duplicate validation checks to catch invalid uses of `PARSE_OPT_EARLY`, and whether the API documentation should warn callers about the ephemeral nature of the `option` pointer passed to callbacks. Kaartic raised these in his review, and Christian hasn’t yet responded. There’s also a lingering usability concern from Junio about whether the API should handle argument skipping internally rather than leaving it to callers, though this hasn’t blocked progress. The preparatory refactorings (patches 1/6 and 2/6) and the `git fast-import` bugfix (4/6) are uncontroversial and could merge soon, while the core API may need one more iteration to address the remaining feedback.
