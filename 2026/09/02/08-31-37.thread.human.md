This thread is about a three-patch series (v6) from Thomas Bachem that fixes a long-standing race condition in Git’s `rerere` subsystem, where concurrent operations (like `git rebase` and background maintenance) contend for the shared `rr-cache` directory lock. The issue became more noticeable after Git 2.54’s geometric maintenance strategy made `git rerere gc` run more aggressively, but the race itself is a general robustness flaw in `rerere` locking.

The series takes a pragmatic approach: it introduces a configurable timeout (`rerere.lockTimeout`, defaulting to 1 second) for lock acquisition, allows background maintenance (`git rerere gc --skip-locked`) to silently skip a held lock, and lets conflict-stopping commands (e.g., `git rebase`, `git merge`) proceed with a warning if the lock remains held after the timeout. Users are advised to run `git rerere` manually to recover the conflict preimage, while post-resolution recording (e.g., `git rebase --continue`) and explicit `git rerere` commands still fail immediately to prevent corruption. The final patch in the series, just posted, implements this core behavioral change, touching nine files and expanding test coverage to ensure all edge cases are handled.

Key participants—Phillip Wood, Patrick Steinhardt, and Junio C Hamano—have all weighed in with substantive feedback, which Thomas has fully incorporated. Phillip initially opposed the timeout-based fix, arguing for deeper changes like disabling maintenance during rebase, but now accepts it as a stopgap while those fixes are developed separately. Patrick clarified the root cause (a long-standing locking flaw, not just a maintenance-heuristic issue) and helped refine the error handling, while Junio emphasized the need for loud, actionable failures after the timeout. The series is now final and ready for integration, with all prior concerns addressed. The only unresolved discussion is whether rebases should run maintenance at all (Phillip argues garbage collection is useless mid-rebase), but that’s being deferred to a future patch.
