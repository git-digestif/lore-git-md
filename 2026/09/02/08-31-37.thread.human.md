This thread is about a two-patch series (v7) by Thomas Bachem that fixes a long-standing race condition in Git’s `rerere` subsystem, where concurrent operations contend for the shared `rr-cache` directory lock. The issue, exacerbated by Git 2.54’s geometric maintenance strategy, affects any two concurrent `rerere` operations, not just background maintenance. The series introduces a configurable lock timeout (`rerere.lockTimeout`, default 1000 ms) for all `rerere` writers and a hidden `--skip-locked` mode for `git rerere gc` to silently skip held locks during auto-maintenance.

The v7 series is final and technically ready for integration, with all prior feedback incorporated. The latest discussion involves a minor internal API design preference from Patrick Steinhardt: he prefers using a single `RERERE_NOWAIT` flag in the existing bitmask over the current approach, which introduces a separate `enum rerere_gc_flags`. This is a purely internal change with no user-visible impact, and Thomas can choose either approach without blocking the series. Key participants—Junio C Hamano, Patrick Steinhardt, and Phillip Wood—have reviewed the series, with Phillip Wood accepting the timeout-based fix as a pragmatic stopgap while deeper fixes are explored. Open questions remain about rebase-specific maintenance behavior and the broader fork-based background maintenance design, but these are deferred to future work. The series is now awaiting Junio’s queue.
