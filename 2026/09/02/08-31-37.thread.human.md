This thread is about a two-patch series (v8) by Thomas Bachem that fixes a long-standing race condition in Git’s `rerere` subsystem, where concurrent operations contend for the shared `rr-cache` directory lock. The issue was exacerbated by Git 2.54’s geometric maintenance strategy but is fundamentally a robustness flaw in `rerere` locking.

The first patch introduces a configurable timeout (`rerere.lockTimeout`, defaulting to 1000ms) for the `MERGE_RR.lock` file, allowing processes to wait briefly before failing rather than terminating immediately. The second patch adds a `--skip-locked` mode for `git rerere gc`, letting auto-maintenance tasks (like `git maintenance run --auto` or `git gc --auto`) silently skip garbage collection if the lock is held, while manual invocations still fail after the timeout. This aligns with Git’s existing maintenance patterns and avoids disrupting concurrent operations.

Key participants include Thomas Bachem (author), Junio C Hamano (maintainer), Patrick Steinhardt, and Phillip Wood. Junio and Patrick provided substantive reviews, with their feedback fully incorporated into v8. Phillip initially opposed the timeout-based fix but now accepts it as a pragmatic stopgap while deeper fixes are explored. The series is technically complete, with no unresolved objections, and is ready for integration. Open questions remain about whether rebases should run maintenance at all and whether the fork-based background maintenance design is inherently flawed, but these are deferred to future discussions. The sequencer config-override patch (disabling maintenance during rebase) is still pending.
