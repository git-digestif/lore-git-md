The `rerere` race-condition fix is now complete and ready for final review. Thomas Bachem’s three-patch v5 series addresses a long-standing robustness flaw in Git’s `rerere` subsystem, where concurrent writers contend for the shared `rr-cache` directory lock. The issue, while exacerbated by the geometric maintenance strategy introduced in Git 2.54, is a general problem: any two concurrent `rerere` operations can collide.

The series introduces three key changes. First, all `rerere` writers now wait for the lock with a configurable timeout (`rerere.lockTimeout`, defaulting to 1000 ms). Second, `git rerere gc --auto` (triggered by background maintenance) skips a held lock silently, matching the behavior of other auto-maintenance tasks. Third, conflict-stopping commands—such as `git rebase`, `git merge`, `git am --3way`, `git stash pop`, and `git apply --3way`—emit a warning and proceed if the lock remains held after the timeout, allowing users to recover the conflict preimage manually. Post-resolution recording (e.g., during `git rebase --continue` or `git commit`) and explicit `git rerere` commands still fail immediately to prevent silent corruption of the `MERGE_RR` file.

The v5 series incorporates all prior feedback from Junio C Hamano, Phillip Wood, and Patrick Steinhardt. Junio’s insistence on loud, actionable error messages led to the use of `advise_if_enabled()` for the advisory message, which provides explicit recovery guidance. Phillip Wood, initially skeptical of the timeout-based fix, now accepts it as a pragmatic stopgap while deeper fixes—such as disabling background maintenance during rebase—are implemented. Patrick Steinhardt’s concerns about the locking implementation and the distinction between auto and manual maintenance are fully addressed. The series is logically separated into three patches, each with thorough test coverage, and no open questions remain. The only pending work is an orthogonal patch to disable maintenance during rebase via config overrides, which will ensure consistency between the merge and apply backends.
