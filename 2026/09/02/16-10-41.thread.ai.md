Core problem or goal
Introduce a minimal, reusable `parse-options` sub-API (`early_scan_options()`) to replace fragile hand-rolled early argument scans in Git commands. The v3 redesign addresses v2 feedback by reusing `parse-options` internals (`lookup_long_opt()`) to handle negated options, unambiguous abbreviations, and aliases consistently with `parse_options()`. The series fixes a real bug in `git fast-import`: `--allow-unsafe-features` was silently ignored when preceded by `--depth 5`, causing the command to refuse unsafe features from the input stream. The API is designed to err on the side of caution—stopping at short options, unknown options, ambiguous abbreviations, and low-level callbacks—to avoid misinterpreting option values.

Key technical details
- New flags: `PARSE_OPT_EARLY` (marks options to be reported during early scanning), `EARLY_SCAN_STOP_AT_NON_OPTION` (stops at non-options, matching `PARSE_OPT_STOP_AT_NON_OPTION`).
- New functions: `early_scan_options()` (core API), `parse_options_check()` (extended to validate `PARSE_OPT_EARLY` usage), `parse_options_takes_argument()` (extracted from `show_gitcomp()`), `lookup_long_opt()` (extracted from `parse_long_opt()` for reuse in `early_scan_options()`).
- Files touched: `parse-options.h`, `parse-options.c`, `fast-import.c`, `t/helper/test-parse-options.c`, `t/helper/test-tool.{c,h}`, `t/t0040-parse-options.sh`, `t/t9300-fast-import.sh`, `Documentation/technical/api-parse-options.txt`, `Documentation/git-fast-import.txt`.
- Subsystems: argument parsing, command-line interface.
- New test helper: `test-parse-options --early-scan-options` (exercises the API with edge cases: stuck values, negated options, ambiguous abbreviations, non-options, low-level callbacks).
- Test coverage: comprehensive API tests in `t/t0040-parse-options.sh` (28 new tests covering stuck/separate values, negated options, ambiguous abbreviations, non-options, and low-level callbacks); `git fast-import` bugfix tested in `t/t9300-fast-import.sh` (two new tests: `--depth 5 --allow-unsafe-features` is recognized, ambiguous abbreviations are rejected when `GIT_TEST_DISALLOW_ABBREVIATED_OPTIONS` is set).
- Behavior changes:
  - Fixes `git fast-import --depth 5 --allow-unsafe-features` (previously ignored `--allow-unsafe-features`).
  - Aligns with `parse_options()` behavior for negated options, unambiguous abbreviations, and aliases.
  - Stops the scan at short options, unknown options, ambiguous abbreviations, low-level callbacks, `--`, and `--end-of-options` to avoid misinterpreting values.
  - Removes a NEEDSWORK comment and outdated documentation in `git-fast-import.txt`.
  - No changes to on-disk format or option semantics beyond the bugfix.
- Refactoring:
  - `early_scan_options()` reuses `lookup_long_opt()` to handle negated options, unambiguous abbreviations, and aliases consistently with `parse_options()`.
  - The scan stops at arguments it cannot reliably skip (e.g., short options, ambiguous abbreviations, low-level callbacks).
  - `EARLY_SCAN_STOP_AT_NON_OPTION` matches `PARSE_OPT_STOP_AT_NON_OPTION` behavior.
  - Stuck-argument handling (`--option=value`) mirrors `parse_options()`’s logic for `PARSE_OPT_OPTARG` and `PARSE_OPT_LASTARG_DEFAULT`.
  - `parse_options_takes_argument()` treats `PARSE_OPT_LASTARG_DEFAULT` options as taking an argument, simplifying early scanning logic.
  - `lookup_long_opt()` performs the lookup part of long-option parsing without side effects, returning an enum (`LONG_OPT_EXACT`, `LONG_OPT_ABBREV`, `LONG_OPT_AMBIGUOUS`, or `LONG_OPT_UNKNOWN`) and populating output parameters (`found`, `other`, `stuck`). The function is now used by both `parse_long_opt()` and `early_scan_options()`.
- API limitations: The scan stops at short options, unknown options, ambiguous abbreviations, low-level callbacks, `--`, and `--end-of-options` to avoid misinterpreting values. This errs on the side of caution, potentially missing options but never reporting false positives. The limitations are documented in `parse-options.h` and `api-parse-options.adoc`. The **usability concern** (caller responsibility for argument skipping) remains unresolved.

Open questions and loose ends
- **Usability**: The API’s requirement for callers to handle argument skipping (`--option value`) remains a **substantive usability concern**. Junio’s v2 feedback argued the API would be easier to use if the callee (`find_early_scan_option()`) skipped arguments internally. This is a **key design decision** that may require further iteration before the series is ready for `next`. Christian’s v3 implementation maintains the caller’s responsibility for argument skipping, but this could lead to inconsistencies or bugs in commands adopting the API. (High weight)
- **Code clarity in `parse_long_opt()`**: Kaartic Sivaraam suggested replacing the `if`-statement chain in `parse_long_opt()` with a `switch` on the `enum long_opt_lookup` return value. This is a **minor but meaningful** improvement that would make the control flow more explicit and easier to extend, aligning with Git’s coding style. The suggestion is **well-founded** and does not affect behavior, but the patch remains **ready for `next`** even without it. (Medium weight)
- **Scope of adoption**: The series focuses solely on `git fast-import`, but the API is designed for broader use. The practical value of the API for commands with simpler early-scan needs (e.g., `--help`) remains unclear, though this is no longer a blocker for the series.
