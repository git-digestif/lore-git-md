Core problem or goal
Introduce a minimal, reusable `parse-options` sub-API (`early_scan_options()`) to replace fragile hand-rolled early argument scans in Git commands. The API reuses `parse-options` internals (`lookup_long_opt()`) to handle negated options, unambiguous abbreviations, and aliases consistently with `parse_options()`. The series fixes a real bug in `git fast-import`: `--allow-unsafe-features` was silently ignored when preceded by `--depth 5`, causing the command to refuse unsafe features from the input stream. The API is designed to err on the side of caution—stopping at short options, unknown options, ambiguous abbreviations, and low-level callbacks—to avoid misinterpreting option values.

Key technical details
- New flags: `PARSE_OPT_EARLY` (marks options to be reported during early scanning), `EARLY_SCAN_STOP_AT_NON_OPTION` (stops at non-options, matching `PARSE_OPT_STOP_AT_NON_OPTION`).
- New functions: `early_scan_options()` (core API), `find_early_scan_option()` (internal helper), `parse_options_check()` (extended to validate `PARSE_OPT_EARLY` usage and now called inside `early_scan_options()`), `parse_options_takes_argument()` (extracted from `show_gitcomp()` in patch 1/4), `lookup_long_opt()` (extracted from `parse_long_opt()` for reuse in `early_scan_options()`).
- Files touched: `parse-options.h`, `parse-options.c`, `fast-import.c`, `t/helper/test-parse-options.c`, `t/helper/test-tool.{c,h}`, `t/t0040-parse-options.sh`, `t/t9300-fast-import.sh`, `Documentation/technical/api-parse-options.txt`, `Documentation/git-fast-import.txt`.
- Subsystems: argument parsing, command-line interface.
- New test helper: `test-parse-options --early-scan-options` (exercises the API with edge cases).
- Test coverage: 28 new tests in `t/t0040-parse-options.sh` (stuck/separate values, negated options, ambiguous abbreviations, non-options, low-level callbacks); `git fast-import` bugfix tested in `t/t9300-fast-import.sh` (four new tests: `--depth 5 --allow-unsafe-features` is recognized, ambiguous abbreviations are rejected, unsafe features are refused when `--allow-unsafe-features` follows a non-option argument, and `--depth 5 extra --allow-unsafe-features` stops at `extra`).
- Behavior changes:
  - Fixes `git fast-import --depth 5 --allow-unsafe-features` (previously ignored `--allow-unsafe-features`).
  - Aligns with `parse_options()` behavior for negated options, unambiguous abbreviations, and aliases.
  - Stops the scan at short options, unknown options, ambiguous abbreviations, low-level callbacks, `--`, and `--end-of-options` to avoid misinterpreting values.
  - Removes a NEEDSWORK comment and outdated documentation in `git-fast-import.txt`.
  - No changes to on-disk format or option semantics beyond the bugfix.
- Refactoring:
  - `early_scan_options()` reuses `lookup_long_opt()` to handle negated options, unambiguous abbreviations, and aliases consistently with `parse_options()`.
  - The scan stops at arguments it cannot reliably skip (e.g., short options, ambiguous abbreviations, low-level callbacks).
  - `EARLY_SCAN_STOP_AT_NON_OPTION` matches `PARSE_OPT_STOP_AT_NON_OPTION` behavior.
  - Stuck-argument handling (`--option=value`) mirrors `parse_options()`’s logic for `PARSE_OPT_OPTARG` and `PARSE_OPT_LASTARG_DEFAULT`.
  - `parse_options_takes_argument()` treats `PARSE_OPT_LASTARG_DEFAULT` options as taking an argument, simplifying early scanning logic (patch 1/4).
  - `lookup_long_opt()` performs the lookup part of long-option parsing without side effects, returning an enum (`LONG_OPT_EXACT`, `LONG_OPT_ABBREV`, `LONG_OPT_AMBIGUOUS`, or `LONG_OPT_UNKNOWN`) and populating output parameters (`found`, `other`, `stuck`).
  - **Code clarity improvement in v4**: Replaced the `if`-statement chain in `parse_long_opt()` with a `switch` on the `enum long_opt_lookup` return value, as suggested by Kaartic Sivaraam in v3.
  - **Validation checks in v4**: `early_scan_options()` now calls `parse_options_check()` internally to validate options before scanning, preventing invalid uses of `PARSE_OPT_EARLY` (e.g., short options, `OPTION_SUBCOMMAND`).
  - **API documentation in v4**: Clarified that the `option` pointer passed to the callback is ephemeral and must not be retained after the scan completes.
  - **Documentation update in v4 (final)**: The comment above `early_scan_options()` in `fast-import.c` now explicitly explains why `EARLY_SCAN_STOP_AT_NON_OPTION` is passed: any non-option argument causes `parse_argv()` to reject the command line, so the scan must stop before processing the stream with unsafe features. The comment also notes that the scan stops early "in case of doubt" to avoid misinterpreting option values.
