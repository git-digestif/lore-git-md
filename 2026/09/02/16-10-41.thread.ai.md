Core problem or goal
Introduce a minimal, reusable `parse-options` sub-API (`early_scan_options()`) to replace fragile hand-rolled early argument scans in Git commands. The v2 redesign addresses Junio’s v1 feedback by eliminating the separate `early_scan_option` structure and requiring commands to adopt the full `parse-options` API before using the early scanner. The series focuses exclusively on fixing a real bug in `git fast-import`: `--allow-unsafe-features` was silently ignored when preceded by `--depth 5`, causing the command to refuse unsafe features from the input stream. The API is deliberately limited—ignoring short options, negated forms, abbreviations, and subcommands—to prioritize simplicity and speed over completeness.

Key technical details
- New flag: `PARSE_OPT_EARLY` (marks options to be reported during early scanning).
- New functions: `early_scan_options()` (core API), `parse_options_check()` (extended to validate `PARSE_OPT_EARLY` usage), `parse_options_takes_argument()` (extracted from `show_gitcomp()` to determine if an option consumes the next argument).
- Files touched: `parse-options.h`, `parse-options.c`, `fast-import.c`, `t/helper/test-parse-options.c`, `t/helper/test-tool.{c,h}`, `t/t0040-parse-options.sh`, `t/t9300-fast-import.sh`, `Documentation/technical/api-parse-options.txt`, `Documentation/git-fast-import.txt`.
- Subsystems: argument parsing, command-line interface.
- New test helper: `test-parse-options --early-scan-options` (exercises the API with edge cases: stuck values `--option=value`, optional arguments, non-options).
- Test coverage: comprehensive API tests in `t/t0040-parse-options.sh`; `git fast-import` bugfix tested in `t/t9300-fast-import.sh` (two new tests: `--depth 5 --allow-unsafe-features` is recognized, abbreviations like `--allow-unsafe` are rejected).
- Behavior changes:
  - Fixes `git fast-import --depth 5 --allow-unsafe-features` (previously ignored `--allow-unsafe-features`).
  - Adds a safety requirement: `--allow-unsafe-features` must be spelled in full (no abbreviations).
  - No changes to on-disk format or option semantics beyond the bugfix.
- Refactoring:
  - `early_scan_options()` now takes a `struct option *` array (no separate `early_scan_option` structure).
  - The scan stops at `--` and `--end-of-options`, matching `parse_options()` behavior.
  - Ignores short options, negated forms (`--no-...`), abbreviations, subcommands, and aliases.
  - `parse_options_takes_argument()` handles edge cases like `PARSE_OPT_LASTARG_DEFAULT` (consumes argument only if not the last one).
- API limitations: documented in `parse-options.h` and `api-parse-options.adoc`; includes ignoring short options, negated forms, abbreviations, and subcommands.
