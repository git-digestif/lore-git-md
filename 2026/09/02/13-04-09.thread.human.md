This thread is about a bugfix series from Yannik Tausch that addresses two related issues in Git’s pathspec handling during directory traversal. The first patch fixes a heap-buffer-overflow that occurs when an exclude pathspec is shorter than the common prefix derived from positive pathspecs, while the second patch corrects a logical bug where an exclude pathspec appearing first in the list prevents `common_prefix_len()` from finding the common prefix among subsequent positive pathspecs. This breaks an optimization that avoids scanning unrelated directories.

The series has evolved through several iterations, with the latest (v4) returning to a two-patch structure by basing itself on Junio C Hamano’s synthetic merge base, which already includes his preparatory const-correctness patch. The core changes remain unchanged from earlier versions, but the commit messages now use clearer terminology and explicitly describe the incorrect behavior (e.g., `git ls-files a/b ':!x/b' a/c` incorrectly excluding `a/b/m`). The series also incorporates Elijah Newren’s suggested deterministic regression test for the heap-buffer-overflow, ensuring the bug can be reliably detected without AddressSanitizer.

Junio has confirmed the integration plan: the series is queued for merging, and no further action is required from the author. The patches touch `dir.c`, the functional test suite (`t/t6132-pathspec-exclude.sh`), and unit tests (`t/unit-tests/u-dir.c`), with no broader subsystem changes. The fix is narrowly scoped to pathspec handling and directory traversal, and the maintainer has clarified that the optimization it restores was already present but broken by the bug. The series is now effectively ready for integration, with all substantive feedback addressed.
