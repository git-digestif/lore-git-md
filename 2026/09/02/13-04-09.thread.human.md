This thread is a two-patch bugfix series from Yannik Tausch that fixes memory-safety and logical bugs in Git’s pathspec handling during directory traversal. The series is now in its fourth iteration (v4) and is queued for merging by Junio C Hamano, the project maintainer.

The bugs being fixed are a heap-buffer-overflow in `match_pathspec_with_flags()` when an exclude pathspec is shorter than the common prefix of positive pathspecs, and a logical error in `common_prefix_len()` where an exclude pathspec appearing first in the list causes the function to incorrectly return an empty string instead of the common prefix of subsequent positive pathspecs (e.g., `a/` from `a/b` and `a/c`). These issues manifest as false positives in negative pathspec matching and memory-safety violations under AddressSanitizer. The fixes are minimal and narrowly scoped to the pathspec subsystem, with no observable behavior change for end users beyond restoring a directory-walk optimization that avoids scanning unrelated directories.

The v4 iteration is functionally identical to earlier versions but adopts consistent "non-exclude/exclude" terminology in commit messages and adds deterministic regression tests for both the heap-buffer-overflow (from Elijah Newren) and the false-positive bug (from Junio). The series is based on a synthetic merge base that includes Junio’s preparatory const-correctness patch, and all technical feedback from reviewers—including Elijah Newren and Junio—has been addressed. The author has confirmed no further action is required, and Junio has stated the series is ready for integration without needing to be resent. The only unresolved detail is a minor implementation choice about the output parameter type in `common_prefix_len()`, but this does not affect correctness and is not a blocker.
