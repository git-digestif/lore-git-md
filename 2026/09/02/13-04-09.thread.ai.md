Core problem or goal
Fix two related bugs in Git’s pathspec handling during directory traversal: (1) a heap-buffer-overflow in `match_pathspec_with_flags()` when an exclude pathspec is shorter than the common prefix derived from positive pathspecs, and (2) a logical error in `common_prefix_len()` where an exclude pathspec appearing first in the list causes the function to incorrectly return an empty string instead of the common prefix of subsequent positive pathspecs (e.g., `a/` from `a/b` and `a/c`), breaking an optimization that avoids scanning unrelated directories. The bugs manifest as false positives in negative pathspec matching (e.g., `git ls-files a/b ':!x/b' a/c` incorrectly excluding `a/b/m`) and memory-safety violations under AddressSanitizer.

Key technical details
- Files touched: `dir.c`, `t/t6132-pathspec-exclude.sh`, `t/unit-tests/u-dir.c`
- Subsystem: pathspec handling and directory traversal
- Behavior change: `common_prefix_len()` now correctly returns the common prefix of positive pathspecs even when an exclude pathspec appears first (patch 2); `match_pathspec_with_flags()` no longer applies the common prefix to negative pathspecs, preventing both out-of-bounds reads and false positives in negative pathspec matching (patch 1). The fix in patch 1 is minimal: `do_match_pathspec()` for exclude pathspecs now passes `0` as the prefix length instead of the common prefix derived from positive pathspecs, ensuring exclude pathspecs are matched against the full pathname. Patch 2 refactors `common_prefix_len()` to use the first *non-exclude* pathspec as the comparison base, returning both the prefix length and the matched string via an output parameter (`const char **`). This ensures the directory-walk optimization (avoiding root traversal when positive pathspecs share a directory) works correctly while preserving the existing behavior that exclude pathspecs are matched against full paths.
- New symbols: `common_prefix_len()` now takes an additional output parameter (`const char **out`) to return the matched prefix string.
- Test coverage: Functional test in `t/t6132-pathspec-exclude.sh` covers the memory-safety issue, the common prefix edge case, and the false-positive bug in negative pathspec matching (including deterministic test cases for the heap-buffer-overflow and the false-positive bug); unit tests in `t/unit-tests/u-dir.c` cover the edge case with an unrelated exclude item followed by two non-exclude items sharing a directory. The v4 iteration adds Elijah Newren’s deterministic test case for the heap-buffer-overflow (exclude pathspec length matching the common prefix of positive pathspecs) and Junio C Hamano’s deterministic test case for the false-positive bug (`git ls-files a/b ':!x/b' a/c`).
- Alternative design: Junio’s output-parameter approach (`common_prefix_len(pathspec, &matched_prefix)`) remains the agreed-upon solution.
- Performance impact: The traversal optimization (avoiding root traversal when positive pathspecs share a directory) is restored; the fix does not introduce measurable overhead.
