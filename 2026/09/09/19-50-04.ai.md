This is the second patch in SZEDER Gábor’s 4-patch **build system** series introducing precompiled headers for faster Git builds. It generalizes the CMake build system’s parsing of the Makefile to ignore any `*_OBJS` variables (e.g., `XDIFF_OBJS`, `REFTABLE_OBJS`) when extracting source file lists. The change is a preparatory cleanup for the upcoming precompiled header patch, ensuring that object-file variables added later won’t accidentally pollute the source lists.

The patch modifies a single line in `contrib/buildsystems/CMakeLists.txt`, replacing a hardcoded removal of `$(COMPAT_OBJS)` with a regex that strips all `*_OBJS` variables. The commit message explains the rationale clearly: the current approach would fail when new object-file variables are introduced, and the regex is carefully scoped to avoid over-matching directory-prefixed variables like `$(UNIT_TEST_DIR)/test-lib.o`. Gábor notes uncertainty about the idiomatic CMake approach, which may prompt feedback from Windows/CMake builders.

This is a **refactoring** change with no runtime impact, and the implementation looks technically sound. The regex is precise enough to avoid false positives, and the change aligns with the series’ goal of keeping the build system robust as new object-file variables are added. No test coverage is needed, as this is purely build infrastructure. The patch is unlikely to be controversial but may draw review from CMake experts to validate the approach.
