This is a surface-level review of Mike Hommey's v3 patch to relocate Git's Rust code to a `rust/` subdirectory. Junio C Hamano's feedback focuses entirely on mechanical and presentational issues: commit message phrasing, `.gitignore` consistency, duplicate entries in the Makefile, and apparent contradictions between the patch's changes to `.gitignore` and the `clean` target in the Makefile.

The review does not engage with the technical rationale for the move, the build system implications, or the Rust-specific concerns that motivated the patch. Instead, it flags four specific problems: the commit message should use imperative mood ("Move all files there" instead of "This moves..."); the `.gitignore` entries for `/target/` and `/Cargo.lock` should be removed rather than duplicated; the Makefile contains duplicate entries for `lib.rs` and `varint.rs`; and the `clean` target still references `Cargo.lock` at the top level while `.gitignore` now expects it in `rust/`. These are all straightforward, non-controversial fixes that do not require rethinking the patch's direction.
