This is patch 7/9 in Patrick Steinhardt’s nine-patch series refactoring how Git writes ODB alternates during repository creation. The patch implements the core design change: alternates are now written during ODB creation via a new `odb_create_on_disk_options` struct, using Git’s standard lockfile API to ensure atomic writes.

The patch adds support for writing alternates to the "files" ODB backend (`odb_source_files_create_on_disk()`) when the database is created. It introduces `struct odb_create_on_disk_options`, which carries a `strvec` of alternates paths, and updates the `create_on_disk` callback signature to accept this struct. The implementation handles preexisting alternates (e.g., from templates) by reading and deduplicating them before writing new entries, and reprepares the ODB to activate the new alternates. The lockfile API adoption resolves the TOCTOU race and concurrent access concerns raised by Junio C Hamano in v1, making this a security and correctness improvement.

The patch is uncontroversial and aligns with the series’ goal of consolidating alternates handling into ODB creation. Reviewers may focus on the lockfile cleanup logic (e.g., rollback on error) and the reprepare step, but the implementation appears robust. The patch is part of the broader ODB abstraction effort and is a strong candidate for integration.
