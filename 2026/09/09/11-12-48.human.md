This is the second patch in Patrick Steinhardt’s 13-patch v3 series to unify Git’s terminology around "ref storage format." The series is a refactoring with functional fixes, and this patch specifically renames the `--ref-format=` option in `git init` to `--ref-storage-format=`.

The patch updates `builtin/init-db.c` to replace the old option with the new one, retaining `--ref-format=` as a hidden backward-compatible alias using `OPT_ALIAS_F()` (introduced in patch 1/13). The help text for the old option now includes a deprecation breadcrumb ("use `--ref-storage-format=` instead"). Documentation (`git-init.adoc`, `git.adoc`, and `config/init.adoc`) is updated to reflect the new terminology, and 12 test scripts are mechanically adjusted to use `--ref-storage-format=` in place of `--ref-format=`. The internal variable `ref_format` is renamed to `ref_storage_format_str` for consistency.

This is a straightforward mechanical change that aligns with the series’ goal of standardizing terminology ahead of the upcoming `--object-storage-format=` extension. The backward-compatible alias ensures existing scripts continue to work, and the deprecation breadcrumb guides users toward the new name. No functional behavior changes are introduced in this patch—it’s purely a rename with documentation updates. The test adjustments are minimal and confirm the new option works as expected. This patch is uncontroversial and looks ready for integration.
