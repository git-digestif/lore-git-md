This is a **maintainer clarification** in the `receive-report` hook thread, now cooking in `next`. Junio C Hamano explains why the test suite did not catch the `BUG()` flaw in patch 2/4: the built-in `git send-pack` client always requests a status report if the server advertises the `report-status` or `report-status-v2` capabilities, and there is no mechanism to disable this behavior. Writing a test for the edge case—where the client omits the capability entirely—would require either a custom client or a way to suppress the server’s capability advertisement, neither of which exists today. The response implicitly endorses the v9 fix (silently skipping the hook when no report is requested) while acknowledging the test coverage gap as a practical limitation rather than a design flaw. No action is proposed; the series remains on track for `master`.
