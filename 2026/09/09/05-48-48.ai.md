This is patch 6/9 in Patrick Steinhardt’s v4 series refactoring ODB alternates handling during repository creation. The patch moves the setup of alternates for non-shared local clones (`git clone --local --no-shared`) into the `collect_alternates()` function, completing the consolidation of all alternates logic into a single code path.

The change fixes a latent bug in worktree alternates handling: previously, Git failed to resolve the common directory of the referenced repository when cloning from a worktree, causing alternates setup to break. The patch reuses the resolved common directory path from `collect_alternates()` (already computed for shared clones) to handle non-shared local clones, ensuring alternates are correctly resolved for worktrees. The `copy_alternates()` function is renamed to `read_alternates()` and refactored to gather alternates paths into a `strvec` instead of immediately writing them to the ODB, aligning with the series’ goal of deferring alternates writes until ODB creation.

Two new tests in `t/t5604-clone-reference.sh` verify the bug fix: one ensures alternates are correctly carried over when cloning from a linked worktree, and another confirms relative alternates paths are properly resolved. The patch also removes the manual alternates handling in `copy_or_link_directory()`, as alternates are now fully handled by `collect_alternates()`.

This is a well-motivated refactoring that addresses a real edge case while preparing for the removal of the `write_alternates()` callback in patch 9/9. The commit message clearly explains the bug and the fix, and the test coverage is thorough. The patch is uncontroversial and aligns with the series’ incremental approach to consolidating alternates logic. Reviewers may focus on the `read_alternates()` error handling (e.g., `fopen()` vs. `xfopen()`), but the change is minimal and preserves existing behavior. The series remains on track for integration.
