This thread is a small but important piece of Git’s documentation housekeeping. Tuomas Ahola’s v3 patch series aims to keep `command-list.txt` in sync with Git’s non-command manual pages—like `gitformat-loose(5)` and `gitpacking(7)`—by adding missing entries and extending the `lint-manpages.sh` script to catch future omissions automatically. The series is now under review, with one key design question still open.

The core change is straightforward: the linter now verifies that all non-command manual pages are listed in `command-list.txt`, with an explicit exemption for the obsoleted `gittutorial-2(7)`. Junio Hamano’s feedback on v1 and v2 was mechanical (quoting fixes and commit message tweaks), while Julia Evans’ review of v3 raised a deeper concern: the script currently sources variables from both the top-level `Makefile` (for command-related variables) and `Documentation/Makefile` (for manual page variables), which could create maintenance issues. She suggested consolidating all variable extraction to `Documentation/Makefile` for clarity, but Tuomas has hesitated, unsure whether the top-level variables are accessible there. The discussion remains unresolved, and a v4 may be needed to address it.

The series touches only build-time tooling—no runtime behavior changes—and the linter itself acts as a regression test for documentation completeness. If the Makefile consolidation is feasible, it would make the script more maintainable without altering its function. For now, the thread is waiting on Tuomas’ response to Julia’s feedback.
