This is the third patch in Patrick Steinhardt’s v2 series to standardize Git’s terminology for ref storage formats. The patch mechanically renames `--ref-format=` to `--ref-storage-format=` in the `git refs migrate` command, retaining the old option as a hidden backward-compatible alias. The change is uncontroversial and aligns with the series’ goal of eliminating inconsistent terminology across Git’s CLI, environment variables, and configuration.

Kaartic Sivaraam’s review raised a minor consistency question about the `PARSE_OPT_NONEG` flag, which prevents the option from being negated (e.g., `--no-ref-storage-format`). The flag is present in `git refs migrate` but absent in other commands that accept the same argument (e.g., `git init`, `git clone`). Kaartic suggested dropping the flag for consistency, but Patrick declined to address it in this series, noting it is outside the scope of the current work. This is a reasonable stance: the flag’s presence or absence does not affect functionality, and the series is already large (11 patches) with a clear focus on terminology unification.

The patch itself is well-scoped and introduces no functional changes. It updates the help text, option parsing, and retains the old `--ref-format=` as a hidden alias, matching the approach taken in earlier patches in the series. The discussion about `PARSE_OPT_NONEG` is unlikely to derail the patch, but it may prompt a follow-up tweak if others agree the flag should be removed for consistency.

The series as a whole remains on track. It addresses a real problem (inconsistent terminology) with clear motivation (preparing for an analogous `--object-storage-format=` extension) and has already resolved design-level concerns raised by Junio C Hamano. The remaining open questions—such as the long-term handling of the old `--ref-format=` option and URI edge cases—are procedural rather than technical and are being actively discussed in other parts of the thread. This patch is a small, uncontroversial step in that larger effort.
