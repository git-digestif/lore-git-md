This is the final patch in Patrick Steinhardt’s 11-patch series to unify Git’s ref-storage terminology under `--ref-storage-format=`. The series is a well-motivated refactoring that also fixes a real bug (silent repository corruption on reinitialization) and prepares the ground for a future `--object-storage-format=` option.

In this reply, Patrick acknowledges Kaartic Sivaraam’s feedback about documentation consistency: the updated `ref-storage-format.adoc` file, which now documents URI payload syntax for the "files" and "reftable" backends, is included by both `git-refs(1)` (a command man page) and `git-repo(1)` (a conceptual overview). Patrick agrees that the change is not appropriate for `git-refs(1)` in its current form and proposes to **revert the documentation update in `ref-storage-format.adoc`**, limiting the URI syntax documentation to `git-init(1)` and `git-clone(1)` for now. This is a minor but sensible concession to avoid overloading the `git-refs` man page with implementation details that do not yet apply to the command itself.

The rest of the patch—URI parsing, immutability enforcement, and test coverage—remains uncontroversial and ready for integration. The series as a whole is now effectively complete, with only this small documentation tweak outstanding. Expect a v3 with the reverted change, after which the series should be ready for `next`.
