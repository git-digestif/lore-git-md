This is the second patch in Patrick Steinhardt’s nine-part series refactoring how Git handles ODB alternates during repository creation. The patch defers object database (ODB) initialization in `git clone` until after the clone source URI is resolved, addressing two key issues: forward compatibility with alternate ODB backends (which may require object hash information at creation time) and the need to resolve alternates paths before ODB setup. The change is purely structural and prepares for later patches that write alternates during ODB creation using Git’s lockfile API.

The patch touches only `builtin/clone.c`, moving the `create_object_database()` and `setup_reference()` calls to occur after URI resolution. This reordering is uncontroversial and aligns with the series’ broader goal of simplifying repository initialization by eliminating skip flags and consolidating alternates logic. Justin Tobler’s review was surface-level, noting the need to defer refdb creation as well, though Patrick clarified that `setup_reference()` actually handles alternates, not references. The patch itself is a mechanical reordering with no new symbols or behavior changes, and the commit message provides a clear rationale.

This patch is a necessary stepping stone for the series, enabling the core design change in patch 7 (writing alternates during ODB creation). The change appears low-risk, though reviewers may later verify that the reordering doesn’t introduce regressions in edge cases like template config rewriting. The thread’s focus remains on the later patches that implement the lockfile API and remove the `write_alternates()` infrastructure, but this patch is a well-motivated and uncontroversial part of the effort.
