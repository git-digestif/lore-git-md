This is the third patch in Patrick Steinhardt’s 13-patch v3 series standardizing Git’s terminology for "ref storage format." It updates `git clone` to rename the `--ref-format=` option to `--ref-storage-format=` while retaining the old name as a hidden backward-compatible alias via the new `OPT_ALIAS_F()` mechanism introduced in patch 1/13. The change is mechanical: the option’s variable name in `builtin/clone.c` is updated from `ref_format` to `ref_storage_format_str`, and all references in the code, documentation, and test scripts are adjusted accordingly. The documentation now includes a deprecation breadcrumb ("Deprecated alias of `--ref-storage-format=<format>`") to guide users toward the new name.

The patch touches seven files: `builtin/clone.c`, `Documentation/git-clone.adoc`, and five test scripts (`t0610-reftable-basics.sh`, `t1460-refs-migrate.sh`, `t5510-fetch.sh`, `t5601-clone.sh`, and `t7424-submodule-mixed-ref-formats.sh`). The test updates are straightforward string replacements, ensuring existing test coverage continues to pass. No functional changes are introduced; the patch is purely a rename with backward compatibility.

This patch is part of the broader effort to prepare for an analogous `--object-storage-format=` extension and to centralize URI parsing for ref storage backends. The series as a whole is under review, with all substantive feedback from v2 addressed in v3. The remaining open questions—such as the long-term lifecycle of the old option names and edge cases in URI payload handling—are policy-level decisions and do not block this patch. The patch is well-scoped, thoroughly tested, and aligns with the series’ goal of terminological consistency.
