This is patch 5/13 in Patrick Steinhardt’s v3 series standardizing Git’s terminology for "ref storage format." The patch updates `git submodule` and its helper to rename the `--ref-format=` option to `--ref-storage-format=`, retaining the old name as a hidden backward-compatible alias via `OPT_ALIAS_F()`. The changes are mechanical: the shell script (`git-submodule.sh`) and C helper (`builtin/submodule--helper.c`) are updated to accept both option names, and the documentation (`git-submodule.adoc`) is revised to reflect the new terminology while marking the old name as deprecated. The test script (`t7424-submodule-mixed-ref-formats.sh`) is updated to use the new option name.

The patch is part of the broader effort to unify terminology ahead of the upcoming `--object-storage-format=` extension. It follows the same pattern established in earlier patches (e.g., `git init`, `git clone`) and maintains consistency with the series’ backward-compatibility strategy. No functional changes are introduced; the patch is purely a refactoring with documentation updates. The test coverage remains unchanged, and the changes are straightforward, touching only the submodule-related code paths. This patch is unlikely to be controversial, as it aligns with the series’ already-reviewed design and addresses no unresolved edge cases.
