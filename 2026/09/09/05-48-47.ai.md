This is patch 5/9 in Patrick Steinhardt’s 9-patch series refactoring ODB alternates handling during repository creation. The patch moves the setup of alternates for shared local clones (`git clone --shared`) from `clone_local()` into the newly extended `collect_alternates()` function, consolidating all alternates logic into a single code path.

The change is a targeted refactoring that prepares for the series’ goal of writing alternates at ODB creation time rather than after the fact. The patch adds two new parameters to `collect_alternates()`: `src_repo` (the source repository path) and `is_local` (a boolean indicating whether the clone is local). When `is_local` is true and `option_shared` is set, the function now adds the source repository’s `objects` directory to the alternates `strvec` using `strvec_pushf()`. This replaces the manual alternates setup in `clone_local()`, which previously called `odb_add_to_alternates_file()` directly. The patch also includes a critical correctness fix: the `option_shared` guard ensures alternates are only added for shared local clones, addressing Justin Tobler’s feedback from v3 that the original implementation would incorrectly add alternates for non-shared local clones (`git clone --local --no-shared`).

The diff is minimal (14 insertions, 9 deletions) and touches only `builtin/clone.c`. The change is mechanical and preserves existing behavior, but the `option_shared` guard is a key correctness improvement. The patch does not yet handle non-shared local clones (`--local --no-shared`); that logic will be moved into `collect_alternates()` in patch 6/9. The updated call to `collect_alternates()` in `cmd_clone()` now passes the source repository path and `is_local` flag, enabling the new logic.

This patch is uncontroversial and aligns with the series’ incremental approach. The consolidation of alternates logic is a necessary step toward eliminating the `write_alternates()` callback in patch 9/9. Reviewers may focus on the `option_shared` guard to ensure it correctly isolates shared clones, but the fix is straightforward and addresses the specific issue raised in v3. The patch includes no new symbols or user-visible changes.
