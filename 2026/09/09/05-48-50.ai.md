This is patch 8/9 of Patrick Steinhardt’s 9-patch series refactoring ODB alternates handling during repository creation, part of the ongoing ODB abstraction effort. The patch wires up the alternates `strvec` collected by `collect_alternates()` to the ODB creation process via the new `odb_create_on_disk_options` struct, eliminating the manual alternates loop in `cmd_clone()` and preparing for the removal of the `write_alternates()` callback in patch 9.

The change is mechanical and uncontroversial: `create_object_database()` now accepts a `strvec` of alternates paths (or `NULL` for no alternates, preserving existing behavior in `cmd_init_db()`), and `cmd_clone()` passes the alternates `strvec` directly to `create_object_database()` instead of manually writing each alternate via `odb_add_to_alternates_file()`. The patch touches `builtin/clone.c` (removing the manual alternates loop), `builtin/init-db.c` (updating `cmd_init_db()` to pass `NULL` for alternates), `setup.c` (extending `create_object_database()` to accept the alternates `strvec` via `odb_create_on_disk_options`), and `setup.h` (updating the function signature and documentation). No new symbols are introduced, and the patch preserves existing behavior while simplifying the code.

This patch is a direct follow-up to patch 7/9, which introduced the `odb_create_on_disk_options` struct and implemented alternates writing during ODB creation using the lockfile API. The consolidation of alternates logic in patches 4-6 (via `collect_alternates()`) ensures that all alternates paths are gathered before ODB creation, making this patch a natural and safe progression. The patch is well-motivated and aligns with the series’ goal of making alternates an ODB backend implementation detail.
