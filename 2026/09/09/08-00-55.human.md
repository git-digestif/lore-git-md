This is patch 8/11 in Patrick Steinhardt’s ongoing series to standardize Git’s terminology for "ref storage format" and enable URI-based configuration. The patch itself is a refactoring of the repository initialization logic that fixes a bug where reinitializing a repository with a different ref storage format silently corrupted it.

Kaartic Sivaraam’s reply is a **substantive review** that identifies a real edge case: the current implementation uses a simple string comparison (`strcmp`) to check whether the ref storage payload (e.g., a filesystem path) has changed during reinitialization. This means that equivalent paths like `/path/to/store` and `/path/to/./store` are treated as different, causing the reinitialization to fail even though they resolve to the same location. Kaartic suggests using `strbuf_realpath` instead, which normalizes paths, to avoid this false positive. This matches how Git already handles path resolution in the `refs_compute_filesystem_location` function, making the suggestion a natural fit for consistency.

The rest of the patch — which enforces immutability of the ref storage format, clarifies precedence rules, and improves error messages — is uncontroversial and receives no further feedback in this email. The edge case Kaartic raises is narrow but meaningful: it affects usability without introducing a correctness bug, and the fix is straightforward. If Patrick incorporates this suggestion, it will make the reinitialization logic more robust against path variations without changing the patch’s core behavior. The series remains on track for review, with this feedback addressing a minor but user-visible quirk.
