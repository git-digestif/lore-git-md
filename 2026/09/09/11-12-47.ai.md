This is a refactoring patch to the parse-options API, part of a larger series (v3 01/13) by Patrick Steinhardt aimed at unifying the ref storage format.

The patch extends the existing `OPT_ALIAS()` macro to support hidden aliases. Currently, Git allows creating option aliases (e.g., mapping an old deprecated option name to a new one), but there’s no way to mark such aliases as hidden (`PARSE_OPT_HIDDEN`). This makes it impossible to properly deprecate old option names while keeping them functional but out of help text. The patch introduces a new `OPT_ALIAS_F()` macro that accepts flags, and updates the option preprocessing logic to propagate those flags when rewriting aliases.

The change is minimal and mechanical: two files (`parse-options.c` and `parse-options.h`) are touched, with the core logic being a one-line addition to preserve the alias’s flags during preprocessing. The patch is well-motivated by the stated use case (deprecation with hidden aliases) and fits cleanly into the existing parse-options infrastructure. No behavior changes are introduced yet—this is purely plumbing for later patches in the series to build on.

This is the first patch in the v3 series; the cover letter or later patches will likely demonstrate how this new capability is used to hide deprecated ref-storage options. The patch itself is uncontroversial and appears ready for integration.
