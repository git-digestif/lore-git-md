This is the second patch in Karthik Nayak’s four-part series introducing the `receive-report` hook for `git-receive-pack`. The series is now in its ninth iteration and is queued in `next`, awaiting final review before graduating to `master`.

This patch refactors how `git-receive-pack` tracks the protocol version used for status reports. Previously, two static boolean variables (`report_status` and `report_status_v2`) were used to indicate whether the client requested a v0 or v2 status report. This patch replaces them with a single `enum report_status_version` that can take one of three values: `REPORT_STATUS_UNKNOWN`, `REPORT_STATUS_V0`, or `REPORT_STATUS_V2`. The enum is passed by reference through the call chain, making the flow easier to follow and more extensible.

The key change is in the `read_head_info()` function, which now takes an additional `enum report_status_version *` parameter. When the client advertises the `report-status` or `report-status-v2` capability, the function sets the appropriate enum value instead of toggling a static variable. The `cmd_receive_pack()` function then uses a `switch` statement to dispatch to the correct reporting function (`report()` or `report_v2()`) based on the enum value. If the client does not request a status report (`REPORT_STATUS_UNKNOWN`), the code silently skips the reporting step, avoiding the `BUG()` call that was present in earlier versions.

This refactoring is purely internal and does not change user-visible behavior. It addresses Junio C Hamano’s maintainability concern about the use of static variables and boolean flags, and it resolves the critical design flaw identified in v8, where the code would crash if the client omitted the `report-status` or `report-status-v2` capability. The fix aligns with the existing behavior and is a prerequisite for the upcoming hook implementation in patch 4/4.
