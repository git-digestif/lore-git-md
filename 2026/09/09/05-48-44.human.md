This is the second patch in Patrick Steinhardt’s 9-patch series refactoring ODB alternates handling during repository creation, part of the ongoing ODB abstraction effort. The patch defers the setup of the object database in `git clone` until after the clone source URI is resolved, addressing two related problems.

First, it future-proofs the code for alternate ODB backends that may need to know the object hash at creation time. Currently, the "files" backend doesn’t require this, but other backends likely will. Second, and more immediately, it ensures alternates are written with full context: the URI provided by the user may be rewritten via `url.<base>.insteadOf`, and the final URI is only known after repository initialization (which can copy a `.git/config` from templates, further rewriting the path). By deferring ODB creation, the code can resolve the URI first, then create the ODB with the correct alternates.

The patch moves the `create_object_database()` call in `cmd_clone()` to occur after URI resolution and transport setup, and also defers `setup_reference()` (which handles alternates, despite its name) until after ODB creation. The change is mechanical and touches only `builtin/clone.c`, with no user-visible behavior changes. It prepares the ground for patch 7, which will write alternates during ODB creation rather than as a separate step.

This is a well-motivated refactoring that aligns with the series’ goal of simplifying the ODB interface. The commit message clearly explains the rationale, and the change itself is straightforward. No controversy or open questions are evident here; the patch looks ready for integration.
