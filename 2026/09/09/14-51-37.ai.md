This is the second patch in Karthik Nayak’s four-part series introducing the `receive-report` hook for `git-receive-pack`. The patch replaces the static boolean variables `report_status` and `report_status_v2` with a new `enum report_status_version` to track the client’s requested status-report protocol version. The change is purely internal and prepares the codebase for the upcoming hook implementation by making the version-tracking logic more explicit and extensible.

The patch touches only `builtin/receive-pack.c` and is a refactoring with no user-visible behavior changes. It introduces the `enum report_status_version` with three values: `REPORT_STATUS_UNKNOWN`, `REPORT_STATUS_V0`, and `REPORT_STATUS_V2`. The static variables are removed, and the version is now passed as an output parameter to `read_head_info()`, which populates it based on the client’s advertised capabilities. The `if/else` chain that previously dispatched to `report()` or `report_v2()` is replaced with a `switch` statement over the enum, addressing Patrick Steinhardt’s subjective preference for this style.

The critical fix from v9 is visible here: the `switch` statement now includes an explicit `REPORT_STATUS_UNKNOWN` case that simply `break`s, replacing the `default: BUG("unknown report status version")` from earlier iterations. This ensures the code silently skips the status report when the client does not request one, resolving Junio C Hamano’s substantive review identifying a crash risk when clients omit the `report-status` or `report-status-v2` capability. The fix aligns with the existing behavior and is the final blocker before the series can graduate from `next` to `master`.

The patch carries a `Helped-by` credit to Junio for the enum refactoring and is well-motivated by the need to make the version-tracking logic more maintainable. The commit message clearly states the goal (dropping static variables in favor of an enum) and the outcome (a more explicit flow). The change is mechanical and does not introduce new test coverage, but it is a necessary precursor to the hook implementation in patch 4/4. All prior feedback on this patch has been addressed, including the typo fix (`REPORT_STATUS_UNKOWN` → `REPORT_STATUS_UNKNOWN`) and the stale comment in the `generate_report()` helper (handled in patch 3/4). The series is rebased onto `master` and resolves conflicts with Justin Tobler’s concurrent "pluggable writes" series.
