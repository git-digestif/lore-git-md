This is a brief exchange in the ongoing `receive-report` hook series, now at version 9 and cooking in `next`. Junio C Hamano responds to Patrick Steinhardt’s observation that the critical `BUG()` flaw in patch 2/4—where the code crashed if the client did not request a status report—went unnoticed in testing. Junio explains why the gap exists: the built-in `send-pack` client always requests a status report if the server advertises the capability, and there is no configuration knob to disable it. Writing a test would therefore require either a custom client or a way to suppress the server’s capability advertisement, neither of which is currently available. The exchange leaves the test coverage question open but does not block the series; it simply documents why the edge case remains untested. The series itself is otherwise ready for final review and likely graduation to `master`.
