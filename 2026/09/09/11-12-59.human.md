This is the final patch in Patrick Steinhardt’s 13-part series to unify Git’s terminology around "ref storage format." It enables the `--ref-storage-format=` command-line option (for `git init` and `git clone`) to accept a URI-style payload, bringing it in line with the existing environment variable and config key support. For example, you can now write `git init --ref-storage-format=files:///path/to/alt-refs` to initialize a repository whose refs are stored in an alternate directory.

The patch updates the option parser in both commands to use the new `ref_storage_format_by_uri()` helper instead of the older `ref_storage_format_by_name()`, so the payload is parsed and stored in the repository’s `extensions.refstorage` config key. Documentation for `git-init.adoc` and `git-clone.adoc` is expanded to explain the URI syntax and to document that the "files" and "reftable" backends accept payloads. The test suite gains a new case (`t/t1423-ref-backend.sh`) that verifies the URI is correctly stored, that reinitialization with a different payload is rejected, and that the refs are actually written to the specified alternate directory.

The change is purely additive: no existing functionality is removed, and the old `--ref-format=` alias remains available as a hidden backward-compatible option. The patch completes the series’ goal of making the command-line interface, environment variables, and config keys consistent in both naming and functionality.
