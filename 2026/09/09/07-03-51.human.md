This is a **surface-level review reply** in the ongoing refactoring series to unify Git's ref-storage terminology. Patrick Steinhardt responds to Kaartic Sivaraam's suggestion about error-message phrasing in patch 7/11, which extracts URI-parsing logic for reference storage formats. Kaartic proposed rewording the error from `"unknown ref storage format: 'garbage://hello-world'"` to `"invalid ref storage format configuration: 'garbage://hello-world'"` to clarify that the input is a configuration value. Patrick declines, preferring "unknown" over "invalid" for precision and arguing that printing the full URI helps users identify the source of the problematic string. The exchange is purely editorial; no technical concerns or edge cases are raised, and the patch remains a pure refactoring with no behavior changes beyond the error-message wording.
