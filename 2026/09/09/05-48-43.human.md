This is the first patch in Patrick Steinhardt’s 9-patch series refactoring how Git handles ODB alternates during repository creation, part of the ongoing ODB abstraction effort. The patch splits `init_db()` into three focused functions: `create_repository()`, `create_reference_database()`, and `create_object_database()`, addressing the growing complexity of `init_db()`’s skip flags and divergent behavior between `git init` and `git clone`.

The core change is moving responsibility for creating the reference and object databases to the caller, allowing `git clone` to defer ODB setup until after URI resolution (a prerequisite for the series’ later patches). The patch eliminates the `SKIP_REFDB` and `QUIET` flags, replacing them with a `reinit_ok` pointer that conveys whether reinitialization is allowed and reports back whether it occurred. This simplifies the interface while preserving `git init`’s ability to print the correct initialization message. The new `create_repository()` function handles only skeleton creation (directories, config, and repository format), while `create_reference_database()` and `create_object_database()` handle their respective subsystems.

The patch updates `builtin/clone.c` and `builtin/init-db.c` to use the new functions, with `git clone` now calling `create_repository()` followed by `create_object_database()` (and later `create_reference_database()` after branch resolution). The `git init` command retains its existing behavior but now uses the new helpers, moving the initialization message into `cmd_init_db()` to avoid leaking command-specific logic into the setup layer. The documentation in `setup.h` clarifies the purpose of each function and the `reinit_ok` parameter, addressing Justin Tobler’s feedback from v3.

This is a well-motivated refactoring that reduces interface complexity and prepares for the series’ later patches, which consolidate alternates handling into ODB creation. The changes are mechanical and introduce no user-visible behavior changes. Reviewers may focus on the clarity of the new function boundaries and the handling of the `reinit_ok` parameter, but the patch appears uncontroversial and ready for integration.
