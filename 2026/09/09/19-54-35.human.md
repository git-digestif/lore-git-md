This is a surface-level review from Junio on Mike Hommey’s v3 patch that moves Git’s experimental Rust code into a dedicated `rust/` subdirectory. The patch is part of the ongoing Rust infrastructure reorganization effort and aims to improve project hygiene by clarifying the mixed C/Rust codebase structure.

Junio’s feedback focuses on minor mechanical and stylistic issues. He notes that the commit message’s final sentence should use imperative mood ("Move all files there" instead of "This moves..."), a standard Git convention. He also points out three specific problems in the patch: the `.gitignore` entries for `/target/` and `/Cargo.lock` should likely be removed since they’re now redundant with the new `/rust/target` and `/rust/Cargo.lock` entries; there’s a duplicate listing of `lib.rs` and `varint.rs` in `RUST_SOURCES` (likely a rebase error); and the `clean` target’s `Cargo.lock` removal path doesn’t match the new location, creating a contradiction with the `.gitignore` update.

The patch itself remains well-motivated and technically sound—it addresses the earlier concerns about misleading top-level `Cargo.toml` and mixed-language confusion while preserving all build functionality. Junio’s comments are purely about polish, not substance, suggesting this patch is close to ready once these small issues are fixed. No deeper technical objections or alternative approaches are raised in this review.
