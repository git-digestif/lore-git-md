This is patch 6/13 of Patrick Steinhardt’s v3 series unifying Git’s terminology for "ref storage format." The patch renames the `git rev-parse` option `--show-ref-format` to `--show-ref-storage-format` and retains the old name as a hidden backward-compatible alias using the new `OPT_ALIAS_F()` infrastructure introduced in patch 1/13. The change is mechanical: it updates the option name in the command implementation, documentation, shell completions, and 8 test scripts (53 test scripts are touched across the entire series, but this patch affects only a subset).

The patch follows the same pattern as earlier patches in the series: the new option name is the primary interface, the old name is retained as a hidden alias, and documentation includes a breadcrumb marking the old name as deprecated. The shell completion script (`contrib/completion/git-prompt.sh`) and the performance test helper (`t/perf/perf-lib.sh`) are updated to use the new option name, ensuring consistency across the codebase. Test scripts are updated to use `--show-ref-storage-format` in place of `--show-ref-format`, with no changes to test logic or coverage.

This patch is a straightforward refactoring with no functional changes. It is part of the series’ broader goal of standardizing terminology ahead of the upcoming `--object-storage-format=` extension, and it addresses all prior feedback on the option-renaming strategy. The only remaining open question for the series is the long-term lifecycle of the old option names (whether they should eventually emit deprecation warnings or be retained indefinitely as hidden aliases), but this is a policy decision rather than a technical blocker for this patch. The patch is well-tested and integrates cleanly with the rest of the series.
