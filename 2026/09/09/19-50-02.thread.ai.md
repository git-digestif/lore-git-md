Subject: [PATCH 0/4] Precompile git-compat-util.h for faster builds

Core problem or goal
Introduce precompiled headers to the Git build process, targeting the frequently included `git-compat-util.h` header to reduce build times by ~35%. The series is purely build-system focused, with no runtime behavior changes.

Current status
Under review; v2 posted. The update addresses Junio C Hamano’s editorial feedback on Patch 3’s commit message (reordering explanation to prioritize the series’ goal, then the exclusion rationale, then the mechanical change). No technical changes were made between v1 and v2. Patch 1/4 (obsolete `XDIFF_OBJS` cleanup) is uncontroversial and ready for merging as a prerequisite. Patch 2/4 (CMake generalization) is explicitly flagged as needing review from Windows/CMake builders to confirm the regex behaves as intended. The final patch (4/4) implements the core precompiled-header logic and is now posted for review. No maintainer decisions or merge signals yet for the full series.

Key technical details
- Files touched: `Makefile`, `contrib/buildsystems/CMakeLists.txt`, `.gitignore`
- New artifacts: `.git-compat-util.h.gch` (precompiled header, excluded from version control), `tools/precompiled.h.gch` (final patch)
- Subsystem: build system only; no core Git functionality modified
- Symbols: none (build-time optimization only)
- On-disk format: unchanged
- Test coverage: none (build system change; no new runtime tests)
- Cleanup prerequisite (Patch 1): removes an obsolete `XDIFF_OBJS` initialization in `Makefile` (leftover from 2025 removal of static `XDIFF_LIB` in cf680cdb95), with no functional impact. The change is purely mechanical and aligns the `Makefile` for later patches.
- Patch 2: generalizes CMake’s parsing of the Makefile to ignore all `*_OBJS` variables (e.g., `XDIFF_OBJS`, `REFTABLE_OBJS`) via a regex, replacing a hardcoded `$(COMPAT_OBJS)` removal. The regex is constrained to avoid over-matching directory-prefixed variables like `$(UNIT_TEST_DIR)/test-lib.o`. No functional changes; purely preparatory for later patches.
- Patch 3: Resurrects the `REFTABLE_OBJS` Makefile variable to isolate reftable object files (except `reftable/system.c`) from precompiled-header processing, as these files deliberately avoid including `git-compat-util.h` for embeddability. The change is mechanical: moves reftable objects from `LIB_OBJS` to `REFTABLE_OBJS` and adds `REFTABLE_OBJS` to `LIB_OBJS` to preserve the final link. CMake is updated to parse `REFTABLE_OBJS` and include those sources in the `libgit` target. The commit message now leads with the series’ goal, followed by the exclusion rationale and the mechanical change, addressing Junio’s editorial feedback from v1.
- Patch 4: Implements the Makefile logic for precompiled headers, including:
  - A rule to generate `tools/precompiled.h.gch` from `git-compat-util.h`.
  - `PRECOMPILED_HEADER_USERS` definition to exclude `COMPAT_OBJS`, `REFTABLE_OBJS`, and `THIRD_PARTY_SOURCES`.
  - A build rule for `PRECOMPILED_HEADER_USERS` using `-include tools/precompiled.h` and `-Winvalid-pch`.
  - A `NO_PRECOMPILED_HEADER` knob for disabling the feature.
  - Dependency tracking via computed header dependencies or `LIB_H`/`GENERATED_H` fallback.
  - Hardcoded `.gch` suffix for GCC/Clang compatibility (future compilers may require a configurable knob).
  - Benchmark: 35% reduction in build time (29.4s → 21.7s with `-j12`), though anecdotal and lacking CI validation. Follow-up refinement (v1) showed only a 1% improvement (21.7s → 21.5s) for finer-grained exclusion logic, which was abandoned as unjustified complexity.

Open questions and loose ends
- Benchmark reproducibility: the 35% speedup claim remains anecdotal; no detailed measurements or CI validation provided. The follow-up refinement shows only a 1% improvement for finer-grained filtering, suggesting diminishing returns.
- CMake adjustments: Patch 2’s regex-based generalization and Patch 3’s `REFTABLE_OBJS` parsing may need review from Windows/CMake builders to confirm no regressions, particularly for cross-platform consistency.
- Precompiled header compatibility: potential concerns about compiler support or cross-platform consistency (e.g., `.gch` suffix hardcoding, lack of a configurable knob for future compilers).
- Dependency tracking: reliance on computed header dependencies (when enabled) or `LIB_H`/`GENERATED_H` fallback may not cover all edge cases.
- Interaction with target-specific `EXTRA_CPPFLAGS`: the patch documents how `-Winvalid-pch` interacts with these flags but does not address whether this could cause issues in practice.
