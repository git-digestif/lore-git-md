This is the second patch in Patrick Steinhardt’s 9-patch series refactoring ODB alternates handling during repository creation, part of the ongoing ODB abstraction effort. The patch defers the setup of the object database in `git clone` until after the clone source URI is resolved, addressing two key problems: forward compatibility with alternate ODB backends (which may require object hash information at creation time) and the need to resolve the URI before writing alternates.

The change is mechanical but foundational. It moves the `create_object_database()` call in `cmd_clone()` from immediately after repository skeleton creation to after URI resolution and transport setup, ensuring alternates can be written with full context. This also requires deferring `setup_reference()` (which handles alternates, despite its name) until after ODB creation. The patch touches only `builtin/clone.c` and makes no user-visible behavior changes.

This patch enables the later consolidation of alternates logic into a single code path (patches 4–6) and the eventual removal of the `write_alternates()` callback (patch 9). The deferral is uncontroversial and aligns with the series’ goal of simplifying the ODB interface. Reviewers may focus on whether the new call order introduces any edge cases, but the patch itself is straightforward and well-motivated. The thread context confirms this is a necessary step toward making alternates an ODB backend implementation detail.
