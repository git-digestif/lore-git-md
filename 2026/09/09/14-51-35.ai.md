This is the v9 iteration of Karthik Nayak’s four-patch series introducing the `receive-report` hook for `git-receive-pack`. The series is now **feature-complete and ready for final review**, with the critical design flaw identified by Junio C Hamano in v8 resolved in patch 2/4.

The hook allows server administrators to intercept and modify the pkt-line encoded status report sent to the client after ref updates are committed but before the response is finalized. It is motivated by GitLab’s need to implement multi-version concurrency control (MVCC) on the server side, where the status report must reflect the repository state *after* all server-side operations (including those beyond `ref_transaction_commit()`) are complete. The hook’s design as a bidirectional filter (stdin → status report, stdout → replacement report, stderr → sideband) is now stable, and the exit semantics (non-zero exit rewrites all ref status lines to `"receive-report hook failed"`) align with the `pre-receive` hook.

Key technical details remain unchanged from v8:
- Files touched: `builtin/receive-pack.c`, `Documentation/githooks.adoc`, `Documentation/git-receive-pack.adoc`, `t/t5412-receive-report-hook.sh`.
- New enum `report_status_version` (values: `UNKNOWN`, `V0`, `V2`) replaces the static `detailed_reports` boolean.
- The hook is **not integrated with the config-based hook infrastructure** (justified by its role as a filter, not a notification hook).
- Test coverage: 224 lines in `t/t5412-receive-report-hook.sh` covering passthrough, failure modes, stdin/stdout handling, sideband relay, and the hook’s ability to modify the `unpack` status line.

The **critical fix in v9** replaces the `default: BUG("unknown report status version")` case in patch 2/4 with an explicit `REPORT_STATUS_UNKNOWN` case that `break`s, ensuring the code silently skips the status report when the client does not request one. This resolves Junio’s substantive review identifying a crash risk when clients omit the `report-status` or `report-status-v2` capability. The fix aligns with the existing behavior and is the **final blocker** before the series can graduate from `next` to `master`.
