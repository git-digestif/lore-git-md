This is patch 6/9 in Patrick Steinhardt’s nine-part series refactoring how Git writes ODB alternates during repository creation. The series is part of the ongoing ODB abstraction effort and aims to simplify the interface by moving alternates handling into the "files" backend.

This patch completes the consolidation of alternates logic by moving the setup of alternates for non-shared local clones (`git clone --local --no-shared`) into the `collect_alternates()` function. Previously, this logic was scattered across `copy_or_link_directory()` and `copy_alternates()`, but now all alternates handling is unified in `collect_alternates()`. The patch also fixes a latent bug: when cloning from a worktree, the code failed to resolve the referenced repository’s common directory, which meant alternates were not properly set up. The fix reuses the resolved common directory path from the `--local` case, ensuring alternates are correctly configured for worktrees.

The patch renames `copy_alternates()` to `read_alternates()` to reflect its new role—gathering alternates paths into a `strvec` rather than immediately writing them to the ODB. It also removes the manual alternates handling in `copy_or_link_directory()`, since alternates are now handled earlier in `collect_alternates()`. Two new tests in `t/t5604-clone-reference.sh` verify the bug fix and ensure relative alternates paths are properly resolved when cloning from a worktree.

The changes are minimal (34 insertions, 11 deletions) and preserve existing behavior while preparing for the removal of the `write_alternates()` callback in patch 9. The patch is uncontroversial and aligns with the series’ goal of consolidating alternates logic into a single code path. Justin Tobler’s earlier feedback on the series has been addressed, and this patch follows the incremental approach established in patch 5/9 (which handled shared local clones). No further review concerns are expected for this step.
