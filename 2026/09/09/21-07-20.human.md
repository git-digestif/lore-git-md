This is the third patch in SZEDER Gábor’s four-part series to speed up Git builds by precompiling `git-compat-util.h`. Junio C Hamano’s reply suggests a clearer commit message for the patch, which currently resurrects the `REFTABLE_OBJS` Makefile variable to exclude reftable object files from precompiled-header processing.

The patch itself is a mechanical refactoring: it moves reftable object files from `LIB_OBJS` to `REFTABLE_OBJS` (while keeping them in the final link) so the next patch can easily filter them out. The motivation is technical—reftable is designed to be embeddable in other projects, so its source files (except `reftable/system.c`) deliberately avoid including `git-compat-util.h`. Precompiling that header for them would be incorrect.

Junio’s feedback is purely editorial: he asks the author to reword the commit message to state the *goal* of the series (precompiling Git-specific headers, including `git-compat-util.h`) upfront, rather than framing the change as a resurrection of an old Makefile variable. The substance of the patch is not in question, and Junio does not raise any technical concerns about the approach. This is a surface-level review aimed at improving clarity for future readers.
