This is a **substantive review reply** in the ongoing ref-storage-format terminology unification series. Patrick Steinhardt responds to Kaartic Sivaraam’s edge-case concern about the immutability check for ref storage payloads in patch 8/11.

Patrick rejects the suggestion to use `strbuf_realpath()` for normalizing payload paths before comparison. His rationale is that payloads are not guaranteed to be filesystem paths—they could represent arbitrary backend-specific data (e.g., database connection strings). The normalization logic in `refs_compute_filesystem_location()` is backend-specific and cannot be generalized to the higher-level immutability check in `setup.c`. The current string comparison remains in place, meaning semantically identical but syntactically different payloads (like `files:///path/to/store` vs. `files:///path/to/./store`) will still trigger a fatal error during reinitialization.

The reply does not introduce new technical issues or reopen settled questions. It clarifies the design intent behind payload handling and leaves the edge case unresolved for now. Future discussion may revisit this if other reviewers weigh in, but for now the immutability check stands as written.
