This is a refactoring and consistency cleanup series targeting Git's reference storage terminology. The 13-patch v3, authored by Patrick Steinhardt, finalizes the effort to standardize on `--ref-storage-format=` (and related names) across Git's CLI, environment variables, and configuration. The series resolves the long-standing inconsistency where the same concept was called `--ref-format=` in some places, `GIT_REFERENCE_BACKEND` in others, and `refStorage` as a repository extension.

The core motivation remains unchanged from v2: the current terminology is a "huge mess" that would only worsen with the upcoming object storage extension, which will introduce an analogous `--object-storage-format=` option. This version addresses all remaining feedback from v2, including Kaartic Sivaraam's concerns about backward compatibility and error message clarity. Key improvements in v3 include using `OPT_ALIAS()` for hidden backward-compatible options (instead of manual aliasing), adding breadcrumbs in documentation to mark old names as deprecated, and fixing error messages to correctly report which environment variable was used. The series also renames the test helper variable `GIT_TEST_DEFAULT_REF_FORMAT` for consistency and removes the controversial `ref-storage-format.adoc` inclusion from `git-refs.adoc`, as the URI payload feature is only supported in `git init` and `git clone`.

The functional scope is now complete: `--ref-storage-format=` accepts URIs like `files://path/to/repo` or `reftable://path/to/db`, with payloads stored in the repository config and used to locate the ref storage directory. The immutability check for existing repository formats (introduced in v2 to prevent silent corruption on reinitialization) remains unchanged, despite Kaartic's suggestion to normalize payload paths—Patrick argues that normalization logic is backend-specific and not all payloads are filesystem paths. The series touches 50 files, including built-in commands (`init`, `clone`, `refs`, `submodule`, `rev-parse`), documentation, test scripts, and shell completions.

This version looks ready for merging. The changes are mechanical but thorough, the backward-compatibility strategy is well-considered, and the motivation is clear. The only loose end is the long-term lifecycle of the deprecated `--ref-format=` option, but Patrick's approach of quiet deprecation (hidden aliases without warnings) is reasonable for now. The series is cooking in `seen` and should graduate to `next` once Junio picks it up.
