This is the latest exchange in the now-abandoned `--[no-]range-diff-notes` feature thread. Kristoffer Haugsbakk responds to Junio C Hamano’s dissection of the toggle mechanism’s usability problem by proposing a simplified redesign that eliminates the toggle sequence (`--no-range-diff-notes --range-diff-notes`) and the arg-less `--range-diff-notes` variant.

Kristoffer’s proposal adopts Junio’s suggested rule: `--no-range-diff-notes` would mean “no notes for range-diff” without fallback, and `--range-diff-notes=<ref>` would require an explicit ref argument. This removes the need for the toggle mechanism and makes the behavior more predictable. The redesign also drops the niche feature of reverting to the patch notes for range-diff output, which Junio demonstrated was useful in alias scenarios but added conceptual overhead. Kristoffer acknowledges that the trade-off—losing the ability to easily revert to patch notes—is acceptable given the complexity it introduces.

The email includes a concrete plan for implementation: replacing the custom `revision.c` option handler with a standard `parse-options` callback, since the arg-less variant is no longer needed. The interaction rule between patch notes and range-diff notes remains unchanged: if no range-diff notes options are given, the range-diff uses the same notes as the patches; otherwise, it uses only the explicitly specified notes (including none, via `--no-range-diff-notes`).

This exchange does not reopen the feature or signal intent to revive it. The thread remains closed, and no further action is expected. If someone revisits this feature, Kristoffer’s redesign would likely be the starting point, as it directly addresses Junio’s usability concerns by simplifying the CLI semantics and eliminating the toggle mechanism.
