This is the second patch in a two-patch contributor housekeeping series that extends the documentation linter to catch missing entries in `command-list.txt`. The patch updates `lint-manpages.sh` to verify that all non-command manual pages (concept guides and interface manuals in sections 5 and 7) are listed in `command-list.txt`. It extracts the `MAN5_TXT` and `MAN7_TXT` variables from the Makefile, combines them into a new `MAN_GUIDES` variable, and checks that each guide has a corresponding entry in `command-list.txt`. The only exception is `gitweb.conf(5)`, which is explicitly skipped to avoid a confusing display name in `git help -a`.

The change is mechanical and confined to the `Documentation/` directory. It introduces no new user-facing behavior but ensures the linter will now fail if `command-list.txt` is incomplete, preventing future documentation drift. The patch depends on the first patch in the series (which adds the missing entries) and on `c655855559` (which adds `gitdatamodel(7)`) to pass the new test. The implementation is straightforward and aligns with the broader `kh/doc-datamodel` effort to improve Git’s documentation infrastructure.

No controversy or design objections are expected. The patch is a sensible addition that complements the existing linter checks for command documentation. The commit message and code are clear, and the exclusion of `gitweb.conf(5)` is well-justified. This is a low-risk, high-value housekeeping change.
