This is the **v3 iteration of a 12-patch platform compatibility series** from Johannes Schindelin, upstreaming Git for Windows build and runtime adjustments into the main Git codebase. The series targets MinGW/Windows-specific quirks—Python buildability, compiler flexibility, MSYS2 integration, deprecated build artifacts, locale handling, and direct `git.exe` invocation—without affecting non-Windows platforms.

The **only changes since v2** are mechanical cleanups: compiler-definition hunks (`ENSURE_MSYSTEM_IS_SET` and `MINGW_PREFIX`) were moved from Patch 8 to Patch 12 (where they are consumed by the C code), and a fly-by style cleanup in `t0060-path-utils.sh` was dropped. These adjustments address Johannes Sixt’s feedback about logical ordering and maintainability, leaving the substantive technical content of the series unchanged.

Key technical details remain consistent with v2: the series touches `compat/mingw.c`, `config.mak.uname`, CMake/Meson build files, and `t0060-path-utils.sh`, introducing no new symbols or on-disk format changes. Behavior is unchanged for non-Windows platforms. The unresolved discussion about guarding against an empty `MSYSTEM` export in Patch 12 persists, with Junio C Hamano reinforcing the precedent for defensive programming in the build system, but Johannes Schindelin has not revisited this point in v3.

The series is **ready for integration** apart from the `MSYSTEM` guard question, which is now a minor correctness nit rather than a blocker. Patches 10 (simplifying `ETC_GITCONFIG`/`ETC_GITATTRIBUTES` path logic) and 11 (locale-handling regression fix) remain uncontroversial, and real-world validation comes from Johannes Sixt’s personal Windows builds (running a subset of these patches since November 2025) and GitHub CI passing on Windows. The only forward-looking suggestion—removing dashed-form executables entirely in Git 3.0—is not a request for changes to this series.

If you care about Windows compatibility or build system hygiene, this series is a routine but important maintenance update. Otherwise, it can be safely ignored unless you encounter a Windows-specific build issue later. The patches are narrowly scoped, well-motivated, and carry no risk for non-Windows users.
