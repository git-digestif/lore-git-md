This is the final patch in Patrick Steinhardt’s v3 series unifying Git’s terminology for "ref storage format." It enables the `--ref-storage-format=` command-line option (used by `git init` and `git clone`) to accept URIs with payloads, matching the existing support in repository extensions and environment variables.

The patch teaches `git init` and `git clone` to parse URIs like `files://path/to/alt-refs` or `reftable://path/to/repo`, passing the full URI string to `init_db()`. The `setup.c` layer then uses the already-introduced `ref_storage_format_by_uri()` helper to extract the format and payload. Documentation for both commands is updated to describe the URI syntax and note that the "files" and "reftable" backends accept payloads. Test coverage is extended to verify that reinitializing a repository with a different payload (or no payload) now fails with a clear error message, closing the silent-corruption bug that motivated the series.

The change is mechanical: the patch replaces the old `ref_storage_format_by_name()` call with `ref_storage_format_by_uri()` and propagates the URI string through the call chain instead of the pre-parsed enum. The immutability check added in patch 9/13 now covers payloads, so reinitializing with `files:///path/to/store` after `files:///path/to/./store` will still fail, but this edge case remains unresolved. The patch also updates the error message in `t/t0001-init.sh` to match the new phrasing ("specified via command line"). No new backward-compatibility concerns are introduced; the URI feature is additive and the old plain-format syntax continues to work.
