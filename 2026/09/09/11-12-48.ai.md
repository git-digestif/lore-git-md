This is the second patch in Patrick Steinhardt’s 13-patch v3 series to unify Git’s terminology around "ref storage format." It renames the `--ref-format=` option in `git init` to `--ref-storage-format=` and retains the old name as a hidden backward-compatible alias using the new `OPT_ALIAS_F()` infrastructure introduced in patch 1/13. The patch touches `builtin/init-db.c`, the `git-init` man page, and 13 test scripts, updating all references to the option name while preserving existing functionality.

The change is mechanical: the internal variable `ref_format` becomes `ref_storage_format_str`, and the option’s help text now includes a deprecation breadcrumb ("Deprecated alias of `--ref-storage-format=<format>`"). All test scripts are updated to use the new option name, and the man page cross-references are adjusted to match. The backward-compatible alias ensures scripts or users still using `--ref-format=` will not break, though the old name is now marked as deprecated in the documentation.

This patch is part of the broader effort to standardize terminology ahead of the upcoming `--object-storage-format=` extension. The v3 revision addresses all prior feedback: the alias is now implemented via `OPT_ALIAS_F()` with `PARSE_OPT_HIDDEN`, the help text includes a deprecation breadcrumb, and the test suite is fully updated. No functional changes are introduced beyond the rename and aliasing. The patch is well-tested, with all affected test scripts passing under the new option name.
