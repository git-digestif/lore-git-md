This is the fifth patch in Patrick Steinhardt’s 9-patch series refactoring ODB alternates handling during repository creation. It moves the setup of alternates for shared local clones (`git clone --shared`) from `clone_local()` into the newly extended `collect_alternates()` function, consolidating all alternates logic into a single code path.

The patch is a targeted refactoring that prepares for the series’ goal of writing alternates at ODB creation time. It adds `src_repo` and `is_local` parameters to `collect_alternates()` and moves the manual alternates setup from `clone_local()` into the new conditional block. The change is narrowly scoped: it only handles shared local clones (`option_shared` is true), leaving non-shared local clones (`git clone --local --no-shared`) to be addressed in the next patch. This incremental approach is intentional and aligns with the series’ design.

A critical correctness fix is included: the `strvec_pushf()` call is guarded by `option_shared`, ensuring alternates are only added for shared local clones. This addresses Justin Tobler’s review feedback from v3, which identified that the original patch would unconditionally add alternates for all local clones, breaking the expected isolation of non-shared repositories. The fix is minimal and correct, as confirmed by Justin’s follow-up retraction.

The patch touches only `builtin/clone.c` and is mechanical in nature, with no new symbols or user-visible behavior changes. It is uncontroversial and well-motivated, serving as a stepping stone for the subsequent consolidation of non-shared local clones in patch 6. The updated test coverage in `t/t5604-clone-reference.sh` (added in earlier patches) ensures the new logic is exercised, though no new tests are introduced here.

This is a solid, incremental step in the ODB abstraction effort, addressing a latent bug while paving the way for the eventual removal of the `write_alternates()` callback. The patch is ready for integration and unlikely to attract further debate.
