This is the eighth patch in Patrick Steinhardt’s v3 series to unify Git’s terminology around "ref storage format." This patch refactors the URI parsing logic for reference backends, extracting it from `setup.c` into a new public function `ref_storage_format_by_uri()` in `refs.c`. The goal is to centralize URI handling (`<format>[://<payload>]`) so that future patches can reuse it for commands like `git clone` and `git init`.

The change is a clean refactoring: it moves the existing `parse_reference_uri()` logic into `refs.c`, renames it to `ref_storage_format_by_uri()`, and updates all callers in `setup.c` to use the new function. The patch also fixes a minor bug where error messages previously reported the parsed format name (e.g., `"files"`) instead of the full URI (e.g., `"files:///path/to/store"`), which is more helpful for debugging. No functional behavior changes are introduced beyond this clarity improvement.

The patch touches three files: `refs.c` (adds the new function), `refs.h` (declares it), and `setup.c` (replaces the old static function and updates callers). The diff is straightforward and well-contained, with no test changes required since the logic is unchanged. This is a preparatory step for the next patch in the series, which will add URI support to more commands.

The refactoring looks solid and aligns with the series’ goal of consistent terminology and centralized parsing. The only open question from earlier feedback—whether to normalize payload paths (e.g., `files:///path/to/./store`)—is not addressed here, but Patrick has explicitly rejected that suggestion, arguing that normalization is backend-specific. This patch doesn’t introduce new edge cases beyond what already existed.
