This is the third patch in SZEDER Gábor’s four-patch **build system** series introducing precompiled headers for faster Git builds. The patch resurrects the `REFTABLE_OBJS` Makefile variable, which was removed in a 2025 cleanup (f3b4c89d59), to explicitly list the reftable object files.

The motivation is straightforward: the reftable implementation is designed to be embeddable in other projects, so its source files (except `reftable/system.c`) do not include `git-compat-util.h`. Since the next patch in the series will introduce a precompiled header for `git-compat-util.h`, these reftable files must be compiled the old way—without the precompiled header—to avoid including Git-specific definitions. By reintroducing `REFTABLE_OBJS`, the series can cleanly filter out these files from the precompiled header mechanism.

The change is mechanical: it moves the reftable object files from `LIB_OBJS` into `REFTABLE_OBJS` and then adds `REFTABLE_OBJS` back to `LIB_OBJS`, restoring the status quo ante. The CMake build system is updated to parse `REFTABLE_OBJS` and include those sources in the `libgit` target. There is no functional impact—this is purely preparatory plumbing for the precompiled header patch that follows.

The commit message is clear and well-justified, and the patch itself is uncontroversial. It does not affect runtime behavior or on-disk formats, and it touches only the build system. The only potential point of discussion would be whether this intermediate step is necessary, but given the series’ goal of avoiding precompiled headers for reftable files, it is a sensible and low-risk approach.
