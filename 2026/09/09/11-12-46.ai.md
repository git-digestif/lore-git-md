This is the v3 iteration of Patrick Steinhardt’s 13-patch series to unify Git’s terminology around "ref storage format." The series is a refactoring with functional fixes, targeting the command-line interface, environment variables, configuration keys, and documentation to replace inconsistent terms like `--ref-format=`, `GIT_REFERENCE_BACKEND`, and `init.defaultRefFormat` with the standardized `--ref-storage-format=`, `GIT_REF_STORAGE_FORMAT`, and `init.defaultRefStorageFormat`. The v3 revision addresses all feedback from v2: it adds breadcrumbs in documentation to mark old names as deprecated, switches from manual option aliasing to `OPT_ALIAS()`, fixes error messages to correctly report the source environment variable, renames the test helper `GIT_TEST_DEFAULT_REF_FORMAT` to match the new pattern, and drops the `ref-storage-format.adoc` update from commands that don’t yet support URIs.

The series now uses `OPT_ALIAS()` for all backward-compatible option aliases (e.g., `--ref-format=` is now a hidden alias of `--ref-storage-format=`), which clarifies the relationship and avoids manual string duplication. Error messages in `setup.c` now correctly report whether a value came from the new or old environment variable, resolving a user-facing clarity issue. The test suite is fully updated, including the previously overlooked `GIT_TEST_DEFAULT_REF_FORMAT` variable. The URI payload feature (e.g., `--ref-storage-format=files://path/to/alt-refs`) remains unchanged from v2, but the documentation no longer includes `ref-storage-format.adoc` in `git-refs.adoc` since the `git refs` command doesn’t support URIs yet.

Key technical details for follow-up: the new `parse-options.c` patch (1/13) adds `OPT_ALIAS_F()` support for hidden aliases, which is used throughout the series to implement the backward-compatible option names. The environment variable handling in `setup.c` now checks both old and new names but reports the correct source in error messages. The immutability check for existing repository formats (patch 9/13) still uses direct string comparison for payloads, which may reject semantically identical but syntactically different paths (e.g., `files:///path/to/store` vs. `files:///path/to/./store`), but this edge case remains unresolved as Patrick considers normalization logic backend-specific.

The series is now functionally complete and addresses all prior feedback. The remaining open question is the long-term lifecycle of the old option names—whether they should eventually emit deprecation warnings or be retained indefinitely as hidden aliases—but this is a policy decision rather than a technical blocker. The patches touch 50 files, with the bulk of changes being mechanical renames in built-in commands, documentation, and test scripts. The core logic in `setup.c` and `refs.c` is well-tested, and the URI payload feature is documented only for the commands that support it (`git init` and `git clone`).
