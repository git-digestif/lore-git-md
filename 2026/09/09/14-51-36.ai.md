This is the first patch in Karthik Nayak’s four-part series introducing the `receive-report` hook for `git-receive-pack`. This specific patch is a **documentation update** that adds an eight-line `PROC-RECEIVE HOOK` section to `git-receive-pack.adoc`, explaining the existing `proc-receive` hook’s purpose and linking to `githooks(5)`. The change plugs a gap in the man page, which previously documented other hooks invoked during pushes but omitted `proc-receive`.

The patch is purely additive and does not touch code or tests. It is styled consistently with the surrounding hook documentation and includes a `Helped-by` credit to Patrick Steinhardt. The content clarifies that the hook is invoked when `receive.procReceiveRefs` is set and commands match the configured refs, and that it replaces the internal `execute_commands()` function. This documentation is unrelated to the new `receive-report` hook (which is introduced in patch 4/4) but is included here to address a prior gap noted in review.

The patch is **queued in `next`** alongside the rest of the series and is ready for final review. No substantive changes are expected, as the content is factual and aligns with the existing `proc-receive` implementation. The only prior feedback was surface-level (grammar, linking), which has been addressed in earlier iterations. This patch is uncontroversial and serves as a prerequisite for the later patches, which reference the hook’s behavior.
