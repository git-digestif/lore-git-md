This is a small but necessary follow-up to the ongoing `defaultBranchName` advice documentation fix. The author, Vsevolod Myalitsin, responds to Junio C Hamano’s feedback about maintaining backward compatibility for the existing `advise()` function, which is not tied to any specific `advice_setting[]` entry.

The core issue is that the refactored `vadvise()` interface now expects an `advice_setting` struct, but `advise()` has no such struct to pass. Junio suggested creating an ad-hoc struct on the stack with default values, and Vsevolod agrees with this approach. However, he proposes a cleaner solution: introducing a new `ADVICE_LEVEL_UNKNOWN` value to the `enum advice_level` instead of reusing existing values like `ADVICE_LEVEL_ENABLED` or `ADVICE_LEVEL_DISABLED`, which would be semantically misleading. This ensures the ad-hoc struct clearly signals its special status without hacking the interface.

The change is minor and mechanical, addressing a corner case that would otherwise break the existing `advise()` call. It does not alter the series’ primary goal (correcting the scope hint for `defaultBranchName`) or the architectural improvements already agreed upon. The patch remains on track for a v3 resubmission, with this detail now resolved. No objections or further questions are raised here.
