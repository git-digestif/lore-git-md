This is the fourth patch in Johannes Schindelin’s 12-part MinGW/Windows build and runtime adjustment series. It refines the linker flag `-Wl,--large-address-aware` so that it applies **only to 32-bit builds** (`MINGW32`). The flag is irrelevant (and sometimes unsupported) in 64-bit builds (`MINGW64` and `CLANGARM64`), so the patch removes it from those configurations.

The change is a straightforward platform-compatibility fix: the flag was originally added to work around 32-bit address-space limitations, but modern 64-bit Windows toolchains either ignore it or emit warnings. The patch touches only `config.mak.uname` and makes no behavior changes for non-Windows platforms.

This patch is uncontroversial and ready for integration. It’s a small, well-motivated cleanup that aligns the build system with current Windows toolchain realities. If you don’t work on Windows, you can safely ignore it; if you do, it’s a minor but welcome improvement.
