This is the sixth iteration of a feature patch extending `git var` to expose individual identity components (author/committer name, email, date), commit signing keys, and support for multiple variable arguments with NUL-terminated output. The patch directly implements the design consensus from prior discussion, replacing the earlier `git ident` proposal.

The implementation is now technically robust: it uses a first-class `multiread` callback for multi-valued variables (e.g., `GIT_CONFIG_GLOBAL`), replaces embedded NUL buffers with `string_list` for safer handling, and enforces strict argument ordering via `parse_options()`. The documentation for identity variables is expanded to clarify their relationship to `git commit`, and the `-z` output format is finalized to match `git config -z` (key-value pairs separated by newlines, entries by NUL). Error handling is script-friendly: unset variables produce empty records and the command continues processing remaining arguments, exiting with code 1 if any variable was unset.

Key changes since v5 address Junio’s substantive review concerns:
- **Multi-valued variables**: switched from NUL-delimited strings to a `string_list`-based `multiread` callback, avoiding edge cases with empty strings.
- **Error handling**: added `BUG()` for unknown `ident_part` values and removed redundant NULL checks in `ident_part()`.
- **Documentation**: expanded descriptions of identity variables to explicitly state they reflect the values that would be used by `git commit`.
- **Output format**: clarified that single-variable queries and `git var -l` do not print extra delimiters after multi-valued variables, while multi-variable queries do.

The patch touches `builtin/var.c`, `Documentation/git-var.adoc`, and `t/t0007-git-var.sh`, with comprehensive test coverage for `-z` mode, multi-valued variables, argument ordering, and unset variables. No new configuration options or on-disk format changes are introduced. The implementation is ready for final review, though Junio’s prior feedback suggests the output format backward-compatibility and error handling may still require minor adjustments before integration.
