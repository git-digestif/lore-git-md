This is the ninth patch in Johannes Schindelin’s 12-part platform compatibility series, targeting Windows build adjustments. It disables the generation of hard-linked `git-<command>` executables (e.g., `git-commit`) in `libexec/git-core/` for Windows builds by setting `SKIP_DASHED_BUILT_INS = YabbaDabbaDoo` in `config.mak.uname`.

The patch is a straightforward cleanup: the "dashed form" of Git commands has been deprecated since 2008, and these hard-links are a historical artifact that now cause unnecessary overhead on Windows (slow builds, misleading space usage, and frequent user confusion). The change is Windows-specific and carries no risk for other platforms. Junio C Hamano previously noted that this could be taken further by removing dashed-form executables entirely in Git 3.0, but this patch merely stops generating them on Windows—a logical first step.

The implementation is minimal: a single line added to the MINGW section of `config.mak.uname`. The value `YabbaDabbaDoo` is a non-empty placeholder (any non-empty string would work) to trigger the existing build logic that skips dashed-form linking. No new symbols or behavior changes are introduced.

This patch is uncontroversial and ready for integration. If you maintain scripts that still rely on `git-commit` (instead of `git commit`), note that this change only affects Windows builds—other platforms will continue generating the dashed-form executables for now. For everyone else, this is a low-risk, high-value cleanup that reduces build time and user confusion on Windows.
