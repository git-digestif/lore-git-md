This is the second patch in SZEDER Gábor’s four-patch **build system** series introducing precompiled headers for faster Git builds. It prepares the CMake build system for upcoming changes by generalizing how object-file variables (`*_OBJS`) are handled when parsing the Makefile.

The patch replaces a hard-coded removal of `$(COMPAT_OBJS)` with a regex that strips any `$(..._OBJS)` variable from the list of sources. This is necessary because later patches in the series will reintroduce or add new object-file variables (e.g., `REFTABLE_OBJS`), and the current CMake logic would misinterpret them as source files. The change is mechanical and narrowly scoped to `contrib/buildsystems/CMakeLists.txt`, with no impact on the Makefile itself or runtime behavior.

The commit message explains the rationale clearly: the existing logic only handles `COMPAT_OBJS`, but future patches will add more `*_OBJS` variables, so the removal needs to be generalized. The author also notes a constraint—the regex can’t be too broad, as some Makefile variables (like `$(UNIT_TEST_DIR)/test-lib.o`) are legitimate directory prefixes and must be preserved.

This patch looks like a sensible, low-risk cleanup. It’s unlikely to be controversial, though CMake experts (e.g., Dscho or Ben Knoble) might suggest minor tweaks to the regex or approach. The change is a prerequisite for the precompiled header work in patch 4, so its correctness is important for the series’ overall goal.
