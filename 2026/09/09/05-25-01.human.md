This is the second patch in a two-part contributor housekeeping series that keeps Git’s documentation infrastructure in sync. The patch extends the `lint-manpages.sh` script to automatically verify that all non-command manual pages (concept guides and interface manuals like `gitformat-loose(5)` and `gitpacking(7)`) are listed in `command-list.txt`. The change is mechanical and confined to the `Documentation/` directory.

The patch extracts the `MAN5_TXT` and `MAN7_TXT` variables from the Makefile, combines them into a new `MAN_GUIDES` variable, and then checks `command-list.txt` against this list. It explicitly exempts `gitweb.conf(5)` to avoid a confusing display name in `git help -a`, matching the rationale in the first patch. The linter will now fail if future manual pages are omitted, acting as a regression test.

This is a sensible addition that complements the first patch (which added the missing entries). The changes are well-scoped and unlikely to be controversial. The series is part of the broader `kh/doc-datamodel` documentation effort, though this patch itself is purely infrastructure. No runtime behavior changes are introduced.
