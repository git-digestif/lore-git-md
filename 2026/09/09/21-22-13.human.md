This is a follow-up in the ongoing patch series to improve Git's advice system by making configuration scope hints more accurate. The author, Vsevolod Myalitsin, responds to Jeff King's (Peff) review of the v3 patch, agreeing to adopt two of Peff's suggestions while raising a concern about the third.

Vsevolod accepts Peff's proposal to avoid string interpolation in the translatable advice message, opting instead to use a single placeholder for the entire command. This should make the string clearer for translators. He also agrees to replace the hardcoded `0` comparison with the more readable `ADVICE_LEVEL_NONE` constant, a straightforward improvement.

The open question remains whether to reuse Git's existing `CONFIG_SCOPE` enum or define a new `ADVICE_SCOPE` enum. Vsevolod points out that reusing `CONFIG_SCOPE` would cause all existing `advice_setting` entries without an explicit `scope_hint` to default to `CONFIG_SCOPE_UNKNOWN` (value `0`), which does not match the current behavior of defaulting to local scope. He suggests this might be incorrect but defers to Peff's judgment if `CONFIG_SCOPE_UNKNOWN` is deemed acceptable. This is the last unresolved design point before the patch can be finalized.

The patch remains under review, with a small reroll expected to address these changes. The discussion is now focused on a single technical detail, and the author appears ready to implement whatever consensus emerges. The patch itself is well-scoped, touching only `advice.c`, and the feedback so far has been constructive and narrowly targeted.
