This is the final patch in Patrick Steinhardt’s 9-patch series refactoring ODB alternates handling during repository creation. The patch removes the now-unused `odb_source_write_alternates()` function and its supporting infrastructure across all ODB backends, completing the series’ goal of consolidating alternates handling into ODB creation.

The patch deletes 117 lines across seven files, removing the `write_alternate` callback from the `odb_source` struct and its implementations in the "files", "inmemory", "loose", and "packed" backends. It also removes the `odb_add_to_alternates_file()` helper from `odb.h` and `odb.c`, which was the last remaining caller of `odb_source_write_alternates()`. The cleanup is mechanical and uncontroversial: all alternates logic has already been moved into the ODB creation process via the new `odb_create_on_disk_options` struct (introduced in patch 7), and the manual alternates loop in `cmd_clone()` was removed in patch 8.

This patch is a straightforward deletion with no behavior changes. The series has already addressed all substantive review feedback, including Justin Tobler’s critical correctness fix in patch 5 (ensuring alternates are only added for shared local clones) and the lockfile API adoption in patch 7 (resolving Junio C Hamano’s security concern about TOCTOU races). The documentation improvements in v4 (clarifying the `reinit_ok` parameter and the purpose of the new repository creation helpers) further strengthen the series’ readiness for integration.

The patch touches the ODB subsystem and alternates handling, but no new symbols or interfaces are introduced. The removal of `odb_source_write_alternates()` and its infrastructure is the logical conclusion of the series’ design, which simplifies the ODB interface by making alternates an implementation detail of the backend. Reviewers may focus on verifying that all callers have been updated (they have), but the patch itself is unlikely to attract significant discussion. The series is now complete and appears ready for `next`.
