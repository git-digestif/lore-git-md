This is the final patch in a **build system** series from SZEDER Gábor that introduces precompiled headers to Git's Makefile-based build process. The goal is to speed up builds by roughly 35% by precompiling `git-compat-util.h`, a header included by nearly every source file in the project.

The patch adds a new rule to generate `tools/precompiled.h.gch` (the precompiled header) and updates the Makefile to compile most object files with `-include tools/precompiled.h` and `-Winvalid-pch` to enforce correctness. The precompiled header is built only once, and its dependencies are tracked to ensure it is rebuilt when any included header changes. The patch also introduces a `NO_PRECOMPILED_HEADER` knob to disable the feature for testing or compatibility with compilers that don’t support `-Winvalid-pch`.

The implementation is careful to exclude object files that don’t include `git-compat-util.h` (e.g., reftable and third-party sources) to avoid build issues, and it avoids target-specific `EXTRA_CPPFLAGS` to prevent conflicts with GCC’s `-Winvalid-pch` option. The patch includes a benchmark showing a 35% speedup on the author’s system, though the series does not provide broader CI validation.

This is a well-motivated, self-contained improvement that touches only the build system (`Makefile` and `.gitignore`). The changes are mechanical and unlikely to be controversial, though the CMake adjustments in earlier patches (not part of this one) may draw attention from Windows or cross-platform builders. The series as a whole is a solid contribution that addresses a real pain point for developers.
