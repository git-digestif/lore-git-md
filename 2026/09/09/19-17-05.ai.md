This is the first patch in Johannes Schindelin’s 12-part **platform compatibility** series, targeting MinGW/Windows build adjustments. It removes the `NO_PYTHON` setting for the MINGW platform in `config.mak.uname`, enabling Python support in Git for Windows builds. The change allows users to leverage MSYS2-provided Python interpreters when working within Git for Windows’ SDK environment, even though Git for Windows itself does not ship Python to save bandwidth.

The patch is a one-line addition (`NO_PYTHON =`) and is uncontroversial. It aligns with the series’ goal of upstreaming Windows-specific build improvements without affecting non-Windows platforms. No new symbols or behavior changes are introduced, and the motivation is clearly stated in the commit message. This is a routine build-system adjustment that carries no risk for other platforms.

If you care about Windows compatibility or build flexibility, this patch is a minor but necessary step toward enabling Python-based tooling in Git for Windows. Otherwise, it can be safely ignored. The patch is ready for integration and has seen no review feedback or objections in the thread.
