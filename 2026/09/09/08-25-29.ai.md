This is the first patch in the v4 series that defers auto maintenance until sequencer completion. It introduces `git_config_append_parameter()`, a helper function in `config.c` that appends a single `'key'='value'` pair to a `struct strbuf`, properly shell-quoted for use in `GIT_CONFIG_PARAMETERS`. The function is designed to be reusable: it handles `NULL` values (treating them as boolean `true`), adds a space separator if the buffer is non-empty, and documents its format in the header comment. The existing `git_config_push_split_parameter()` is refactored to use the new helper, reducing code duplication.

The patch is a refactoring with no user-visible behavior change. It prepares the ground for the sequencer to build its own `GIT_CONFIG_PARAMETERS` string in the next patch, where it will disable auto maintenance during intermediate steps. The implementation is straightforward and uncontroversial; prior feedback on earlier iterations focused on parameter naming (`env` instead of `buf`) and documentation clarity, both of which are addressed here. The header comment now explicitly describes the format (`space-separated list of 'key'='value' pairs, both sides single-quoted`) and the meaning of `NULL` values.
