Series version: v1 (initial)
Originating author: Tuomas Ahola
Thread type: patch series (contributor housekeeping)

Core problem or goal
Ensure the `command-list.txt` file stays in sync with the set of non-command manual pages (concept guides and interface manuals such as `gitformat-loose(5)` and `gitpacking(7)`). The immediate goal is to add two missing entries (`gitformat-loose(5)` as "developerinterfaces" and `gitpacking(7)` as "guide") and extend the `lint-manpages.sh` script so that future omissions are caught automatically. `gitweb.conf(5)` is intentionally omitted to avoid a confusing display name ("web.conf") in `git help -a`.

Current status
Under review; no prior versions. The series is two patches:
1. Adds the missing entries to `command-list.txt`.
2. Updates `lint-manpages.sh` to verify that all non-command manual pages are listed, using a new `MAN_GUIDES` variable derived from `MAN5_TXT` and `MAN7_TXT` in the Makefile. The linter now fails if `command-list.txt` is incomplete. The patch depends on `c655855559` (which adds `gitdatamodel(7)`) to pass the new test. Junio C Hamano identified two shell quoting issues in the second patch that require fixing before the series can be accepted.

Key technical details
- Files touched: `Documentation/` directory, `command-list.txt`, `lint-manpages.sh`.
- New or renamed symbols: `MAN_GUIDES` variable in `lint-manpages.sh`.
- Old-vs-new behavior: no runtime change; the linter now acts as a regression test for documentation completeness.
- On-disk format changes: none.
- Test coverage: the linter itself provides coverage.

Open questions and loose ends
Junio’s review requests two quoting fixes in the shell script: `$file` and `$(dirname $file)` must be quoted to handle paths containing whitespace or shell metacharacters. These are mechanical changes with no impact on the patch’s design or functionality.
