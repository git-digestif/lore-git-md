This is a small but user-visible improvement to Git's advice system. The patch teaches Git to suggest the correct config scope (`--global`, `--system`, or local) when it tells users how to disable an advice message. Currently, the suggestion always omits the scope, which can be confusing if the advice setting is actually configured at a higher level.

The patch is part of a single-patch series (v3) that Peff has already reviewed. His feedback is purely surface-level: he flags a potential translation hazard (the `set%s` placeholder might confuse translators) and suggests a cleaner way to map the config scope enum instead of redefining it. The code itself is straightforward and uncontroversial; it simply adds a `scope_hint` field to the advice settings table and uses it to construct the correct `git config set` command in the advice message.

No new advice settings are introduced; the only visible change is that the "default branch name" advice now suggests `--global` because that setting is typically configured globally. The rest of the advice messages remain unchanged until their settings are updated in future patches.

The patch looks well-crafted and addresses a real usability papercut. Peff’s nits are minor and do not block merging; they are more about code hygiene than correctness. If you care about small UX polish, this is worth a quick skim.
