This is the fourth patch in Patrick Steinhardt’s nine-patch series refactoring how Git handles ODB alternates during repository creation. The series is part of the ongoing ODB abstraction effort and aims to simplify the interface by moving alternates handling into the ODB backend.

This patch refactors the handling of `--reference` and `--reference-if-able` in `git clone` by renaming the confusingly named `setup_reference()` function to `collect_alternates()` and changing it to gather alternates paths into a `strvec` instead of immediately writing them to the ODB. The new function uses a `struct add_one_alternate_data` to track whether an alternate is required or optional, and the alternates are later written to the ODB in a loop after `create_object_database()` is called. This prepares for the series’ goal of consolidating all alternates logic into a single code path and eventually moving alternates handling into the ODB backend itself.

The change is mechanical and introduces no new behavior or user-visible changes. It touches only `builtin/clone.c`, replacing `add_one_reference()` with `add_one_alternate()` and updating the function signature and logic to use a `strvec` for alternates paths. The patch is well-motivated and aligns with the series’ broader refactoring goals. It is uncontroversial and appears ready for integration, though reviewers may focus on the clarity of the new function name and the incremental nature of the refactoring. The next patches in the series will complete the consolidation of alternates logic and move the alternates writing into the ODB backend.
