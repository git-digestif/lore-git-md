This is the **ninth patch in the v3 MinGW/Windows build adjustments series**, a platform compatibility change that disables the generation of hard-linked `git-<command>` executables (e.g., `git-commit`) in `libexec/git-core/` for Windows builds. The patch adds a single line to `config.mak.uname` under both the `Windows` and `MINGW` sections:

```make
SKIP_DASHED_BUILT_INS = YabbaDabbaDoo
```

The commit message explains the rationale: the "dashed form" (`git-commit`) is a historical artifact from Git's early days, when commands were shell scripts wrapping low-level plumbing. Since Git 1.5.4 (February 2008), this form has been officially deprecated, but the hard links have persisted. On Windows, these links introduce measurable overhead—adding ~30 seconds to every build—and trigger spurious "disk space" warnings in Windows Explorer due to its incomplete hard-link awareness. The patch begins the process of phasing out these links, starting with Git for Windows.

The value `YabbaDabbaDoo` is a non-empty placeholder; the build system only checks whether the variable is defined, not its content. This is consistent with existing patterns in the codebase (e.g., `NO_PYTHON = UnfortunatelyYes`).

The change is **Windows-specific** and has no effect on other platforms. It touches only the build configuration, requiring no code changes or test updates. The patch is uncontroversial and ready for integration, though Junio C Hamano previously noted that the deprecation could be completed by removing the dashed-form executables entirely in Git 3.0—a forward-looking suggestion unrelated to this series.

If you maintain Windows-specific tooling or scripts that rely on the dashed form, this patch signals the start of its removal. Otherwise, it is a routine cleanup with no user-visible impact.
