This is the fifth patch in Patrick Steinhardt’s 13-patch v3 series unifying Git’s terminology around "ref storage format." It updates `git submodule` to replace the old `--ref-format=` option with `--ref-storage-format=`, keeping the old name as a hidden backward-compatible alias via `OPT_ALIAS_F()`.

The patch touches five files: `Documentation/git-submodule.adoc`, `builtin/clone.c`, `builtin/submodule--helper.c`, `git-submodule.sh`, and the test script `t/t7424-submodule-mixed-ref-formats.sh`. The changes are mechanical but slightly more involved than in other commands because `git submodule` delegates much of its logic to the `submodule--helper` built-in. The documentation now marks `--ref-format=` as deprecated and adds breadcrumbs pointing users to the new name. The shell script (`git-submodule.sh`) and the helper (`submodule--helper.c`) both handle both option names, ensuring that scripts using the old name continue to work.

This patch is part of the broader effort to prepare for an analogous `--object-storage-format=` extension. The series as a whole is under review and addresses all prior feedback; this patch itself is uncontroversial and aligns with the established pattern of using `OPT_ALIAS_F()` for backward compatibility. The only remaining open question for the series is the long-term lifecycle of the old option names, but that is a policy decision rather than a technical blocker.
