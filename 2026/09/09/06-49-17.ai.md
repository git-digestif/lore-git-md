This is a follow-up in the `defaultBranchName` advice documentation fix series, focusing on a backward-compatibility detail for the `advise()` function. The author, Vsevolod Myalitsin, responds to Junio C Hamano’s suggestion to create an ad-hoc `advice_setting` struct for the existing `advise()` call, which is not tied to any entry in the `advice_setting[]` table. Myalitsin proposes adding a new `ADVICE_LEVEL_UNKNOWN` value to the `advice_level` enum to handle this case cleanly, rather than repurposing existing `ADVICE_LEVEL_ENABLED` or `ADVICE_LEVEL_DISABLED` values, which would be semantically misleading.

The patch remains part of the advice subsystem refactoring, which now uses a `scope_hint` field in the `advice_setting` struct to recommend configuration scope (e.g., `--global`) for advice keys like `defaultBranchName`. The architectural direction is settled, and this email addresses the last mechanical detail before the author sends v3. The change is low-risk and self-contained, touching only `advice.c` and introducing no new behavior—just ensuring the existing `advise()` function continues to work after the interface refactor. The unresolved syntax preference (`--global` vs `set --global`) from Ben Knoble is still pending, but this email does not revisit it.
