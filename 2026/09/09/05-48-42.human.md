This is the cover letter for v4 of Patrick Steinhardt’s 9-patch series refactoring how Git handles ODB alternates during repository creation. The series is part of the ongoing ODB abstraction effort and aims to simplify the ODB interface by moving alternates handling into the "files" backend.

The core change is eliminating the ability to write alternates after repository creation. Currently, alternates can be added at any time via `odb_source_write_alternate()`, but Git only uses this during initial setup (e.g., `git clone --reference`). The series introduces a new option in `odb_source_create_on_disk()` to handle alternates at creation time, removing the need for a separate `write_alternates()` callback. This aligns with the broader goal of making alternates an implementation detail of the ODB backend.

Key updates in v4 include improved documentation for the new repository creation functions (`create_repository()`, `create_reference_database()`, and `create_object_database()`) in `setup.h`, addressing feedback from Justin Tobler. The series also refactors `init_db()` into `create_repository()`, which now only creates the repository skeleton without setting up the refdb or ODB, eliminating the need for skip flags and moving command-specific logic into the commands themselves. This refactoring simplifies the interface and makes the code more maintainable.

The patches touch `builtin/clone.c` (deferring ODB setup and consolidating alternates logic), `setup.c`/`setup.h` (splitting `init_db()` and adding the new helpers), and the ODB source files (removing the `write_alternates()` callback). The series also updates tests in `t/t5604-clone-reference.sh` to verify the new behavior, including edge cases for cloning from worktrees and resolving relative alternates paths. The lockfile API is used to ensure atomic writes of the `info/alternates` file, addressing security concerns raised in earlier versions.

This is a well-crafted series with a clear technical goal. The refactoring is mechanical but foundational, and the improved documentation in v4 makes the changes easier to understand. The series is uncontroversial in its current form, as it removes unused flexibility rather than introducing new behavior. Reviewers will likely focus on ensuring the refactoring doesn’t introduce regressions, particularly in clone behavior and alternates handling. The series is built on recent ODB-related work (`ps/odb-eagerly-load-alternates`), indicating it’s part of an active development stream.
