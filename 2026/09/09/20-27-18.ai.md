This is a **substantive review** of a patch that improves Git's advice system by making the suggested configuration command scope-aware. The patch is part of a thread where Vsevolod Myalitsin is adding a `scope_hint` field to advice settings so that users are instructed to use the correct config scope (e.g., `--global`) when disabling advice messages.

Jeff King (Peff) reviews the v3 patch and raises two main technical points. First, he notes that the new `set%s` placeholder in the translatable string might confuse translators, suggesting either a clarifying comment or an alternative approach that avoids string interpolation. Second, he proposes reusing Git's existing `CONFIG_SCOPE` enum instead of defining a new `ADVICE_SCOPE` enum, demonstrating how this could work with a code snippet that constructs the command string programmatically using `config_scope_name()`. The snippet also avoids the hardcoded `0` comparison in favor of the more readable `ADVICE_LEVEL_NONE` constant.

The review is substantive because it engages with the design choices (enum reuse, translation clarity) and provides a concrete alternative implementation. Peff’s tone is exploratory rather than prescriptive—he acknowledges uncertainty about which approach is clearer but leaves the decision to the author. The patch itself is small and focused, touching only `advice.c` and introducing no new user-facing behavior beyond more accurate advice messages.
