This is the tenth patch in Patrick Steinhardt’s v3 series to standardize Git’s terminology around "ref storage format." It renames the environment variables `GIT_REFERENCE_BACKEND` and `GIT_DEFAULT_REF_FORMAT` to `GIT_REF_STORAGE_FORMAT` and `GIT_DEFAULT_REF_STORAGE_FORMAT`, respectively, while retaining the old names as backward-compatible aliases. The patch also fixes a minor indentation issue in the documentation.

The changes are mechanical but thorough: the patch updates `setup.c` to check both the new and old environment variables, ensuring that error messages correctly report which variable was used. The precedence order is now explicit: command-line option > `GIT_REF_STORAGE_FORMAT` > `GIT_REFERENCE_BACKEND` > existing repository format > `GIT_DEFAULT_REF_STORAGE_FORMAT` > `GIT_DEFAULT_REF_FORMAT` > config key > compiled-in default. The test suite is updated to reflect the new variable names, including the previously overlooked `GIT_TEST_DEFAULT_REF_FORMAT` (now `GIT_TEST_DEFAULT_REF_STORAGE_FORMAT`).

This patch is part of a well-structured series that has already addressed all substantive feedback from earlier iterations. The backward-compatible aliases are implemented cleanly, and the documentation includes deprecation breadcrumbs. The only unresolved edge case—whether to normalize paths in URI payloads—is backend-specific and not a blocker. The series as a whole looks ready for final review, and this patch in particular is a straightforward step toward the goal of consistent terminology.
