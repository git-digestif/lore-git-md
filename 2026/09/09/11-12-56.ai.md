This is patch 10/13 in Patrick Steinhardt’s v3 series to unify Git’s terminology around "ref storage format." The patch renames the environment variables `GIT_REFERENCE_BACKEND` and `GIT_DEFAULT_REF_FORMAT` to `GIT_REF_STORAGE_FORMAT` and `GIT_DEFAULT_REF_STORAGE_FORMAT`, respectively, while retaining the old names as backward-compatible aliases. It also fixes indentation in the documentation for `GIT_REF_STORAGE_FORMAT` to use tabs instead of spaces.

The patch touches nine files: `Documentation/config/init.adoc`, `Documentation/git.adoc`, `environment.h`, `setup.c`, and five test scripts (`t/t0001-init.sh`, `t/t1419-exclude-refs.sh`, `t/t1423-ref-backend.sh`, `t/t7424-submodule-mixed-ref-formats.sh`, and `t/test-lib.sh`). In `setup.c`, the patch updates the precedence logic to check the new environment variables first, then fall back to the old ones, and ensures error messages correctly report the source (e.g., "unknown ref storage format specified via GIT_REF_STORAGE_FORMAT"). The test scripts are updated to use the new variable names, and `t/test-lib.sh` now exports `GIT_DEFAULT_REF_STORAGE_FORMAT` instead of `GIT_DEFAULT_REF_FORMAT`.

This patch is a mechanical but necessary part of the series, ensuring consistency across environment variables, configuration keys, and CLI options. The backward-compatible aliases prevent breakage for users or scripts still using the old names, and the updated error messages improve clarity. The test coverage is thorough, verifying that the new variables work as expected and that the old ones remain functional. The patch does not introduce new behavior but lays the groundwork for the URI payload feature in later patches (e.g., `--ref-storage-format=files://path/to/alt-refs`).

The series as a whole is well-motivated—standardizing terminology ahead of the upcoming `--object-storage-format=` extension—and this patch specifically addresses the environment variable layer. The changes are low-risk, as they preserve backward compatibility and are confined to variable renames and documentation updates. The patch is ready for final review, with no unresolved technical concerns. The only open question is the long-term lifecycle of the old variable names (whether they should eventually emit deprecation warnings), but this is a policy decision rather than a blocker.
