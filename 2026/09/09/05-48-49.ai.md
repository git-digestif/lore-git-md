This is patch 7/9 of Patrick Steinhardt’s ODB abstraction series, implementing the core design change: alternates are now written during ODB creation using Git’s standard lockfile API. The patch adds support for writing alternates to the "files" backend via the new `odb_create_on_disk_options` struct, which carries a `strvec` of alternates paths. This enables the eventual removal of the `write_alternates()` callback in patch 9/9.

The implementation is careful: it reads any preexisting alternates (e.g., from templates), deduplicates them with the new entries, and writes the combined set atomically using `commit_lock_file()`. The ODB is then reprepared to activate the new alternates. Error handling is thorough, with rollback on failure and proper cleanup of resources. The lockfile adoption resolves Junio C Hamano’s earlier concern about TOCTOU races and concurrent access, a key blocker from v1.

The patch touches `odb/source-files.c` (adding the alternates-writing logic), `odb/source.h` (introducing `odb_create_on_disk_options` and updating the `create_on_disk` callback signature), and `setup.c` (updating `create_object_database()` to pass an empty options struct). The new `strset` usage for deduplication is a clean solution, and the code is well-structured with clear error paths.

This is a substantive, well-executed change that directly addresses the series’ goal of consolidating alternates handling into ODB creation. The lockfile adoption and reprepare step ensure robustness, and the patch is uncontroversial given the earlier resolution of the security concern. Reviewers may focus on the lockfile cleanup logic (e.g., rollback on error) and the reprepare step, but the implementation appears solid. The patch is a strong candidate for integration and paves the way for the final cleanup in patch 9/9.
