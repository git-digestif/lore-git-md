This is part 4 of Patrick Steinhardt’s 13-patch v3 series to unify Git’s terminology around "ref storage format." The series is a refactoring with functional fixes, replacing inconsistent terms like `--ref-format=` with the standardized `--ref-storage-format=` across the CLI, environment variables, and documentation.

This patch updates the `git refs migrate` command to rename `--ref-format=` to `--ref-storage-format=`, keeping the old name as a hidden backward-compatible alias via the new `OPT_ALIAS_F()` mechanism introduced in patch 1. The change touches the command’s usage string, help text, and error messages, along with updates to `Documentation/git-refs.adoc` and three test scripts (`t/t1423-ref-backend.sh`, `t/t1460-refs-migrate.sh`, and `t/t7424-submodule-mixed-ref-formats.sh`). The `PARSE_OPT_NONEG` flag inconsistency noted in the thread summary remains unresolved here—it is still present in `git refs migrate` but absent in other commands like `git init` and `git clone`.

The patch is mechanical and well-scoped, updating only what is necessary for the rename. The test updates are thorough, covering both the new option name and the backward-compatible alias. No functional changes are introduced beyond the terminology shift, and the patch aligns with the series’ goal of preparing for the upcoming `--object-storage-format=` extension. The immutability check edge case for URI payloads (discussed in the thread) does not affect this patch, as it is handled in later patches.
