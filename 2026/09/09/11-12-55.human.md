This is the ninth patch in Patrick Steinhardt’s v3 series to unify Git’s terminology around "ref storage format." The patch refactors the logic in `setup.c` that determines which ref storage backend a repository should use, splitting the code that *selects* the format from the code that *validates* it. The goal is to make the precedence rules clearer and to fix a bug where reinitializing a repository with a different ref storage format (e.g., via `GIT_REFERENCE_BACKEND`) silently corrupts the repository.

The refactoring is straightforward: the old logic interleaved selection and validation, leading to repetitive code and missed edge cases. The new version first determines the desired format (respecting the precedence order: command-line option → `GIT_REFERENCE_BACKEND` → existing repository format → `GIT_DEFAULT_REF_FORMAT` → `init.defaultRefFormat` → compiled-in default), then validates that the result is compatible with the existing repository. This makes the code easier to extend and harder to get wrong.

The patch also fixes the bug Patrick demonstrated in the commit message: reinitializing a repository with a different ref storage format now fails with a clear error message instead of corrupting the repository. The test in `t/t0001-init.sh` verifies this behavior. One edge case remains unresolved: the immutability check for payloads uses direct string comparison, which can incorrectly reject semantically identical but syntactically different paths (e.g., `files:///path/to/store` vs. `files:///path/to/./store`). Patrick has rejected suggestions to normalize paths, arguing that payloads are not guaranteed to be filesystem paths and that normalization logic is backend-specific.

The patch is well-motivated and the refactoring is clean. The new precedence order (command-line overrides environment variables) matches Git’s usual conventions, and the validation logic is now explicit and complete. The test coverage is adequate, and the commit message clearly explains the problem and the solution. This patch is ready for review and looks like a clear improvement.
