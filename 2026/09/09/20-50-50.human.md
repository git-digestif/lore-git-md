This is a small but thoughtful feature patch that improves Git’s advice messages by adding a scope hint. The patch teaches Git to suggest the correct configuration scope (`--global`, `--local`, or `--system`) when telling users how to disable an advice message—for example, `git config --global advice.defaultBranchName false` instead of the generic `git config advice.defaultBranchName false`.

The patch touches only `advice.c`, adding a `scope_hint` field to the `advice_setting` struct and a small enum to represent the possible scopes. The implementation is straightforward: when an advice message is displayed and the user’s configuration has not suppressed it, the code now interpolates the appropriate scope flag into the turn-off instructions. The author has already addressed earlier feedback about enum naming and string interpolation, and the current version (v3) is under review.

Junio’s reply is constructive and highlights two remaining points. First, the commit message should explicitly mention that the patch makes `advice.defaultBranchName` a global-scope setting, since it is too late to set it per-repository once the repository exists. Second, he suggests splitting the work into three logical patches: (1) narrow the `vadvise()` interface, (2) introduce the scope-hint mechanism, and (3) apply the hint to `defaultBranchName`. The code itself is clean and Junio calls the “end shape” good, so the patch looks likely to land once the commit-message and patch-splitting nits are resolved.
