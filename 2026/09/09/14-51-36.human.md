This is a documentation patch, the first in Karthik Nayak’s four-part series introducing the `receive-report` hook for `git-receive-pack`. The series is now in its ninth iteration and cooking in `next`.

The patch plugs a small but noticeable gap in the `git-receive-pack(1)` man page: it adds an eight-line `PROC-RECEIVE HOOK` section that explains when the existing `proc-receive` hook is invoked (when `receive.procReceiveRefs` is set and the push commands match the configured refs) and what it does (executes the commands instead of the internal `execute_commands()` function). The section is styled consistently with the surrounding hook documentation and links to `githooks(5)` for further details. Patrick Steinhardt helped shape the wording, earning a `Helped-by` credit.

The change is purely additive and does not touch any code or tests. It is a prerequisite for the later patches in the series, which introduce the new `receive-report` hook and will reference the existing `proc-receive` hook in their documentation. The patch is uncontroversial and ready to graduate.
