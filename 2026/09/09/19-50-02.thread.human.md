This thread is about a 4-patch series from SZEDER Gábor that introduces precompiled headers to Git's build process, targeting `git-compat-util.h` to reduce build times by about 35%. The series is purely a build-system optimization with no runtime changes, and it's currently under review in its first version.

The second patch in the series, just posted, is a preparatory cleanup for the CMake build system. It generalizes how CMake parses the Makefile to ignore any `*_OBJS` variables (like `XDIFF_OBJS` or `REFTABLE_OBJS`) when extracting source file lists. This ensures that future additions of object-file variables won't accidentally pollute the source lists. The change is small and technically sound, using a precise regex to avoid false positives, but Gábor notes some uncertainty about whether this is the idiomatic CMake approach, which might draw feedback from Windows/CMake builders.

So far, the series has only seen initial submission with no reviews or maintainer decisions. The main open questions are around benchmark reproducibility (the 35% speedup claim hasn't been validated in CI) and whether the CMake changes will work smoothly across platforms. The author hasn't incorporated any feedback yet, and the series remains a standalone build-system improvement unrelated to larger efforts like ODB abstraction or Rustification.
