This thread is about a patch series from SZEDER Gábor that introduces precompiled headers for Git’s `git-compat-util.h` to speed up builds by about 35%. The series is now at version 2, which only updated a commit message to address Junio C Hamano’s editorial feedback—no technical changes were made.

The first patch, a cleanup of an obsolete `XDIFF_OBJS` initialization, is uncontroversial and ready to merge. The second patch generalizes CMake’s parsing logic to handle new object variables, but needs review from Windows/CMake builders to confirm the regex behaves correctly. The third patch isolates reftable object files to avoid precompiled-header processing, as those files deliberately skip including `git-compat-util.h`. The fourth patch implements the core precompiled-header logic, but two edge cases have surfaced: Jeff King (Peff) reported that target-specific compiler flags (like `-DNO_OPENSSL`) can trigger `-Winvalid-pch` warnings, and SZEDER now notes that the `__FILE__` macro in `git-compat-util.h` expands differently when the precompiled header is used, altering error messages in assertions and compiler diagnostics. Neither issue affects runtime behavior, and SZEDER considers them acceptable trade-offs for the build speedup.

The series is still under review, with no maintainer decisions yet. The main open questions are whether the CMake adjustments work cross-platform and whether the edge cases around compiler flags and macro expansion need further attention. So far, only Junio and Peff have weighed in, with Junio’s feedback limited to commit-message clarity and Peff’s highlighting a niche but real limitation.
