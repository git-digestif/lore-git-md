This thread is about a patch series from SZEDER Gábor that introduces precompiled headers to Git’s build process, targeting `git-compat-util.h` to reduce build times by around 35%. The series is now at version 2, which addressed Junio C Hamano’s editorial feedback on commit message clarity but made no technical changes. The first patch, a cleanup of an obsolete `XDIFF_OBJS` initialization, is uncontroversial and ready to merge. The second patch generalizes CMake’s parsing logic and is flagged for review from Windows/CMake builders. The fourth and final patch implements the core precompiled-header logic and has drawn substantive feedback.

Jeff King (Peff) identified an edge case where target-specific compiler flags (like `-DNO_OPENSSL`) can invalidate the precompiled header, triggering `-Winvalid-pch` warnings. The build still succeeds, but the warning reveals a limitation: precompiled headers assume uniform flags across most object files. SZEDER proposed a workaround—appending `-Wno-invalid-pch` to the target’s `EXTRA_CPPFLAGS`—and confirmed it works in practice. The discussion clarified that Peff’s use case (building historical Git versions with conditional OpenSSL support) is niche but valid, and SZEDER plans to adopt Peff’s technique for his own workflow. No changes to the patch series are planned for now, as the issue is considered unlikely to affect most users.

The series remains under review, with no maintainer decisions or merge signals yet. The main open questions are whether the benchmarked speedup is reproducible in CI, whether the CMake adjustments work cross-platform, and how to handle the precompiled-header limitation for specialized build configurations. For now, the workaround is documented, and the series is otherwise technically sound.
