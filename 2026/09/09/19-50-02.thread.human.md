This thread is about a four-part patch series from SZEDER Gábor that introduces precompiled headers to Git's build process, targeting `git-compat-util.h` to reduce build times by roughly 35%. The series is purely a build-system optimization with no runtime changes.

The first three patches lay the groundwork: the first removes an obsolete `XDIFF_OBJS` initialization, the second generalizes CMake's Makefile parsing to ignore all `*_OBJS` variables, and the third—this patch—resurrects the `REFTABLE_OBJS` variable to keep reftable object files out of precompiled-header processing, since they avoid including `git-compat-util.h` for embeddability. Junio C Hamano reviewed this patch and offered only editorial feedback on the commit message, suggesting it clarify the series' goal upfront before explaining the reftable exclusion. The patch itself is uncontroversial and mechanically straightforward.

The series is still under review, with no maintainer decisions or merge signals yet. The main open questions remain around benchmark reproducibility, CMake adjustments for Windows builders, and broader compiler compatibility for precompiled headers. Gábor has already noted that finer-grained exclusion logic (like splitting object lists into `_NOPCH` variants) yields minimal performance gains and isn't worth the added complexity. So far, only Gábor and Junio have weighed in, with Junio's feedback limited to presentation rather than technical concerns.
