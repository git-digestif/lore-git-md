This is the v4 cover letter for Patrick Steinhardt’s 9-patch series refactoring how Git writes ODB alternates during repository creation. The series is part of the ongoing ODB abstraction effort and aims to simplify the ODB interface by moving alternates handling into the "files" backend.

The core change is eliminating the ability to write alternates after repository creation, replacing it with a new option in `odb_source_create_on_disk()` that handles alternates at creation time. This removes the need for the `write_alternates()` callback and prepares for alternates to become an ODB backend implementation detail. The v4 iteration adds documentation for the new repository creation functions (`create_repository()`, `create_reference_database()`, and `create_object_database()`) and clarifies the `reinit_ok` parameter, addressing Justin Tobler’s feedback from v3.

Key technical details remain unchanged from v3: the series defers ODB setup in `git clone` until after URI resolution (patch 2), consolidates all alternates logic into `collect_alternates()` (patches 4-6), and adopts the lockfile API for atomic alternates writes (patch 7). Patch 8 updates `create_object_database()` to accept a `strvec` of alternates paths, and patch 9 removes the now-unused `write_alternates()` infrastructure. The series is built on `ps/odb-eagerly-load-alternates` and introduces no user-visible behavior changes.

The v4 changes are minor but important: the added documentation in `setup.h` improves clarity for future contributors, and the incremental refactoring of `init_db()` into `create_repository()` (introduced in v3) continues to simplify the interface by removing skip flags and moving command-specific logic into the commands themselves. The series is now well-documented and addresses all substantive review feedback, making it a strong candidate for integration. Reviewers may focus on the lockfile cleanup logic in patch 7 and the robustness of the reprepare step, but the core design appears uncontroversial.
