The change is a mechanical refactoring with no behavior change: it moves code from `setup.c` into `refs.c`, replaces the private `parse_reference_uri()` helper with the public `ref_storage_format_by_uri()`, and updates call sites to use the new function. The patch prepares for the next commit (9/13), which will enforce immutability of the ref storage format and payload once set.

The refactoring touches three files: `refs.c` (adds the new function), `refs.h` (declares it), and `setup.c` (removes the private helper and updates call sites). The new function `ref_storage_format_by_uri()` parses URIs in the format `<format>[://<payload>]` (e.g., `files://path/to/alt-refs`) and returns the format enum while optionally populating a `payload` output parameter. The patch maintains backward compatibility by preserving the existing error messages and behavior, including the use of direct string comparison for payloads (an edge case noted in the thread summary: semantically identical but syntactically different paths like `files:///path/to/store` vs. `files:///path/to/./store` will be treated as distinct).
