This is patch 9/13 of Patrick Steinhardt’s v3 series to unify Git’s terminology around "ref storage format." The patch refactors the logic in `setup.c` that determines which ref storage format a repository should use, splitting the previously intertwined "determine desired format" and "validate sanity" steps into distinct phases. This makes the precedence order explicit (command-line option > `GIT_REFERENCE_BACKEND` environment variable > existing repository format > `GIT_DEFAULT_REF_FORMAT` > `init.defaultRefFormat` > compiled-in default) and fixes a bug where reinitializing a repository with a different format via `GIT_REFERENCE_BACKEND` would silently corrupt it.

The key change is the introduction of a two-phase approach: first, the desired format is resolved from all possible sources; then, if the repository already exists, the resolved format is compared against the existing one and rejected if they differ. This immutability check now also covers the URI payload (e.g., `files://path/to/alt-refs`), preventing silent corruption when reinitializing with a different payload. The patch updates error messages to correctly report the source of the value (e.g., "unknown ref storage format specified via GIT_DEFAULT_REF_FORMAT: 'garbage'") and adds a test case for the `GIT_REFERENCE_BACKEND` reinitialization edge case.

The refactoring is mechanical and well-motivated, with no behavior change other than the bug fix. The new precedence order aligns with Git’s usual rule that command-line options override environment variables. The immutability check for payloads still uses direct string comparison, which may reject semantically identical but syntactically different paths (e.g., `files:///path/to/store` vs. `files:///path/to/./store`), but this edge case remains unresolved as Patrick considers normalization logic backend-specific. The patch touches `setup.c` and `t/t0001-init.sh`, adding 75 lines and removing 40.
