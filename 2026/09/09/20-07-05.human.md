This is a **build system** and **platform compatibility** patch addressing a cross-compilation issue in Git's Rust build infrastructure. Junio C Hamano replies to James Le Cuirot's v2 patch with two technical observations.

The patch itself is now uncontroversial in its goal—respecting `CARGO_BUILD_TARGET` when locating the compiled Rust library (`libgitcore.a`)—and has been extended to cover both the Meson and `make`-based build systems. However, Junio points out two minor but important details. First, the patch should be rebased onto a more recent version of the `Makefile` that includes support for universal macOS builds via `RUST_TARGETS` (post-924dfced6b). Second, the shell script's parameter expansion (`${CARGO_BUILD_TARGET-}`) introduces a double slash in the path when the variable is unset, which, while not technically incorrect, is unintended and could be avoided with a cleaner alternative (`${CARGO_BUILD_TARGET+$CARGO_BUILD_TARGET/}`).

The feedback is substantive but narrowly scoped: it does not question the core fix, only its implementation details. The patch is otherwise well-motivated, minimal, and aligned with the broader Rustification effort. It is particularly relevant for cross-compilation workflows (e.g., Gentoo, embedded systems) and does not depend on other in-flight topics. James will likely send a v3 addressing these points, after which the patch should be ready for integration.
