This is the third patch in Patrick Steinhardt’s 13-patch v3 series to unify Git’s terminology around "ref storage format." It updates `git clone` to rename the `--ref-format=` option to `--ref-storage-format=`, keeping the old name as a hidden backward-compatible alias via the new `OPT_ALIAS_F()` mechanism introduced in patch 1/13. The change is mechanical: the option’s functionality remains identical, but the name now matches the standardized terminology used across the rest of the series.

The patch touches seven files: the `git-clone` man page, the `clone.c` implementation, and five test scripts. In `Documentation/git-clone.adoc`, the old option is documented as a deprecated alias with a breadcrumb pointing users to the new name. The `builtin/clone.c` changes are straightforward—renaming the variable and updating the option definition to use `OPT_ALIAS_F()`—and the test updates are purely mechanical, replacing `--ref-format=` with `--ref-storage-format=` in test invocations. No new functionality is introduced; this is purely a refactoring to align with the series’ goal of consistent terminology.

The patch is well-crafted and uncontroversial. It addresses all prior feedback: the backward-compatible alias is now implemented via `OPT_ALIAS_F()` (rather than manual string duplication), and the documentation includes a deprecation breadcrumb. The test coverage remains thorough, with all affected test scripts updated to use the new option name. There are no open questions specific to this patch; the remaining loose ends in the series (e.g., the `PARSE_OPT_NONEG` inconsistency and URI payload edge cases) are handled in other patches. This patch is ready for merging once the series as a whole is approved.
