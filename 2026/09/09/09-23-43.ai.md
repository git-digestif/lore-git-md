This is the final patch in Patrick Steinhardt’s 11-patch series to unify Git’s ref-storage terminology, and this email is a reply to Kaartic Sivaraam’s **surface-level review** of the documentation update. Patrick agrees with Kaartic’s observation that the updated `ref-storage-format.adoc` file (which now documents URI payload syntax for the "files" and "reftable" backends) is not appropriate for inclusion in `Documentation/git-refs.adoc` (the man page for `git refs`), as that command does not currently support URI syntax. He plans to **revert the change to `ref-storage-format.adoc`** and instead **update only the documentation for `git init` and `git clone`**, which are the commands that actually support the new URI payload feature. This is a minor but sensible adjustment to avoid misleading users or over-documenting functionality that isn’t yet implemented in all relevant commands. The rest of the patch—URI parsing, immutability enforcement, and test coverage—remains uncontroversial and ready for merging. The series as a whole is now effectively complete, with only this small documentation tweak pending.
