This is the third patch in Karthik Nayak’s four-part series introducing the `receive-report` hook for `git-receive-pack`. The series is now in `next` and feature-complete, with all prior feedback addressed.

This patch refactors the status-report generation logic into a reusable `generate_report()` helper in `builtin/receive-pack.c`. Previously, the code had two nearly identical functions, `report()` and `report_v2()`, which differed only in whether they included additional per-ref details (e.g., `option refname`, `option old-oid`) for the v2 protocol. The patch unifies them into a single `report()` function that takes an `enum report_status_version` parameter, eliminating redundancy. The `generate_report()` helper handles both protocol versions, with the v2-specific logic gated on the `version` parameter.

The change is purely internal and does not alter user-visible behavior, but it prepares the codebase for the upcoming hook implementation by centralizing the report-generation logic. The stale comment referencing the removed `detailed_report` boolean is updated to reference the `version` parameter, addressing Patrick Steinhardt’s substantive review from v6.
