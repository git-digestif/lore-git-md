This is the fourth and final patch in SZEDER Gábor’s **build system** series introducing precompiled headers to Git’s Makefile, targeting `git-compat-util.h` for a claimed ~35% build speedup. The patch itself is a straightforward implementation of the precompiled header logic, but Gábor’s reply here adds a **detailed follow-up** exploring whether finer-grained filtering of object files could yield additional gains.

The core of the patch remains unchanged: it wires up precompiled headers by generating `tools/precompiled.h.gch` from `git-compat-util.h` and defines `PRECOMPILED_HEADER_USERS` to exclude `COMPAT_OBJS`, `REFTABLE_OBJS`, and `THIRD_PARTY_SOURCES` (which avoid including `git-compat-util.h`). The new twist is Gábor’s **experimental patch** showing how to further split these exclusion lists into `*_NOPCH_OBJS` (e.g., `REFTABLE_NOPCH_OBJS`, `COMPAT_NOPCH_OBJS`) to include only the subset of files that *actually* don’t use `git-compat-util.h`. His benchmark shows this refinement shaves off just **0.2 seconds (1%)** from a 21.7-second build, leading him to conclude it’s not worth the added complexity.

The patch is **well-motivated and technically sound**, with clear attention to edge cases (e.g., excluding reftable files for embeddability, avoiding `EXTRA_CPPFLAGS` to prevent `make` quirks). The commit message and follow-up provide thorough justification for the trade-offs, and the implementation is careful to avoid runtime behavior changes. The only open question is whether the **CMake adjustments** in earlier patches (2/4 and 3/4) will need tweaks from Windows builders, but this patch itself looks uncontroversial. If the series lands, it’s likely to be a net win for developer productivity.
