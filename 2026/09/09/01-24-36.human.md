This is the sixth iteration of a feature patch extending `git var` to expose individual identity components (author/committer name, email, date) and the resolved commit signing key, while adding support for multiple variable arguments and NUL-terminated output. The patch directly implements the design consensus reached in prior discussion, replacing the earlier `git ident` proposal.

Andrew Pleeter has addressed all feedback from Junio C Hamano’s substantive review of v5. The key improvements in v6 are:

- **Multi-valued variable handling**: switched from embedded NUL buffers to a first-class `int (*multiread)(struct string_list *)` callback in `struct git_var`, eliminating edge cases with empty strings and improving robustness. The `GIT_CONFIG_GLOBAL` variable now populates a `string_list` directly.
- **Error handling**: added `BUG("unknown ident_part %d", part)` to the default case in `ident_part()`, and removed redundant NULL checks on `split.name_begin` and `split.mail_begin` after successful `split_ident_line()`.
- **Documentation**: expanded descriptions for `GIT_AUTHOR_*` and `GIT_COMMITTER_*` variables to clarify they reflect the values that would be used if `git commit` were run now. Explicitly documented that single-variable queries and `git var -l` do not print an extra delimiter after multi-valued variables.
- **Code hygiene**: reverted a cosmetic refactoring in `get_git_var()` to keep the diff minimal and focused.

The patch remains technically sound, with thorough test coverage for edge cases (unset variables, multi-valued variables with `-z`, argument ordering, signing key resolution). The implementation is self-contained, touching only `builtin/var.c`, `Documentation/git-var.adoc`, and `t/t0007-git-var.sh`. No new configuration options or on-disk format changes are introduced.

Junio’s v5 review raised concerns about output format backward-compatibility, error handling robustness, and multi-valued variable implementation; all have been addressed in v6. The patch is now likely ready for integration, pending any final mechanical feedback. It remains in `seen` and has not been marked for graduation to `next`.
