This is the final patch in Maciej Ciemborowicz’s three-part bugfix series restoring correct object IDs to the reference-transaction hook when branches or tags are deleted. The series targets a regression introduced in Git 2.31 that broke external tools (Gerrit, GitLab, CI systems) by sending all-zero OIDs instead of the resolved old OID during deletions via `git branch -d`, `git tag -d`, `git remote prune`, and `git fetch --prune`.

Junio’s review of the v4 series caught a build-breakage issue: the first patch updated the `refs_delete_refs()` function signature but missed some call sites, causing compilation errors in intermediate commits. Maciej acknowledges the oversight and confirms he has fixed it locally by updating all call sites in the first patch, passing `NULL` for the new optional parameter where later patches supply real data. The fix is mechanical and does not alter the series’ behavior or design. With this resolved, the series is now technically complete and ready for merging to `next`.

The patch itself updates `git fetch` and `git remote` to collect old OIDs from `get_stale_heads()` and pass them to `refs_delete_refs()`, ensuring the hook receives the correct pre-deletion OID followed by all-zeros. It also handles partial failures gracefully using `REF_TRANSACTION_ALLOW_FAILURE`, preserving the unconditional deletion behavior expected by `git fetch --prune` and `git remote prune` while enabling granular error reporting. The UI now shows "[deleted]" for successful prunes and omits failed refs from dangling symref checks, matching existing behavior.

Test coverage is thorough, verifying the fix works across files and reftable backends, SHA-1/SHA-256, broken/symbolic refs, and all affected commands. Performance gains from the original optimization (reducing bulk tag deletion time from 30 minutes to ~0.85 seconds for 10,000 tags) are preserved. The series addresses all prior feedback, including Junio’s request for granular error reporting and Karthik Nayak’s API consistency concerns.

This is a well-motivated, narrowly scoped bugfix with clear real-world impact. The regression has persisted for five years, and the fix restores the pre-2.31 behavior without breaking backward compatibility. The build-breakage issue was the last blocker, and the author’s response suggests it will be resolved promptly. If you rely on the reference-transaction hook, this series is worth tracking.
