This is a **CI/build system** follow-up in the ongoing thread about the Debian 12 HTTP/2 authentication workaround. Jeff King (Peff) provides a concrete implementation of his earlier suggestion: a runtime prereq that detects the buggy curl version (7.88.1) and skips the affected tests (`t5559.15` and `t5559.16`, which correspond to the two tests in `t5551` that Peff’s patch modifies).

The patch is small and targeted, touching only `t/t5551-http-fetch-smart.sh`. It introduces a new prereq `HAVE_CURL_HTTP2_BUG` that is true only when HTTP/2 is enabled and the libcurl version is exactly 7.88.1. The two tests that previously failed intermittently are then marked with `!HAVE_CURL_HTTP2_BUG`, so they are skipped on the problematic version. This approach avoids hard-coded test numbers and works both in CI and locally, addressing both of Peff’s earlier concerns.

Peff’s implementation is straightforward and does not attempt to generalize beyond the known-broken version (7.88.1). He notes that a more complete solution might check a range of versions, but this patch covers the immediate need. The patch is offered as a proof-of-concept rather than a formal submission; Peff does not resend it as a `[PATCH]` but instead invites discussion on whether this direction is preferable to the original CI-only workaround. The thread remains open on the trade-off between simplicity (original patch) and robustness (this alternative).
