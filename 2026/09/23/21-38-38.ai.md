This is a maintainer feedback email on the v2 patch introducing the `+:` refspec for matching-inspired fetch mode in shallow repositories. Junio C Hamano rejects the current implementation as too monolithic and proposes a four-commit refactoring that replaces the `+:` refspec with a new `remote.X.refmap` configuration. The refmap would define the namespace mapping (e.g., `+refs/heads/*:refs/remotes/second/*`) without specifying what to fetch, while the fetch logic itself would dynamically determine which branches to fetch based on local tracking branches. The proposal also includes a new `--limited-fetch` option for `git remote add` and heuristics to enable this mode by default in shallow repositories.

The feedback is substantive and design-level, addressing both the technical approach and the patch structure. Junio’s alternative avoids the ambiguity of the `+:` syntax (which lacks explicit namespace mapping) and cleanly separates the concerns of namespace mapping and branch selection. The four-step plan—configuration, fetch logic, `git remote add` plumbing, and heuristics—is well-motivated and would make the feature easier to review and test incrementally. However, this represents a significant departure from the current patch, and the thread will likely need a v3 series to implement the new design.

Key technical details for follow-up discussion:
- The new `remote.X.refmap` configuration (replacing `remote.X.fetch` for this use case).
- The `--limited-fetch` option for `git remote add` and its heuristics (e.g., defaulting to shallow repositories).
- The dynamic branch enumeration logic (fetching only branches tracked by local branches + the remote’s default branch).
- Backward compatibility: existing wildcard refspecs remain unchanged, and the new mode is opt-in (at least initially).
- Edge cases: handling stale `HEAD`, empty repositories, and multiple tracking branches.

The feedback is constructive and aligns with Git’s design principles, but the scope of changes means the feature is unlikely to land in its current form. The thread is now focused on refining the design rather than reviewing the v2 patch.
