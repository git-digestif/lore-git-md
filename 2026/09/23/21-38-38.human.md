This is a maintainer review of Harald Nordgren’s patch introducing the `+:` refspec for matching-inspired fetch mode in shallow repositories. Junio C Hamano finds the patch too large and proposes a four-commit refactoring that replaces the `+:` refspec with a new `remote.X.refmap` configuration. The goal remains the same—avoiding slow fetches in shallow repos by fetching only tracked branches plus the remote’s default branch—but the implementation path changes significantly.

The review identifies a key design flaw: the `+:` refspec does not specify where remote-tracking branches should be stored, making it ambiguous compared to traditional wildcard refspecs like `+refs/heads/*:refs/remotes/origin/*`. Junio’s alternative uses `remote.X.refmap` to define the mapping namespace separately from what to fetch, then teaches `git fetch` to enumerate tracked branches when no explicit refs are given. This approach keeps the configuration explicit and avoids inventing new refspec syntax.

Junio outlines four incremental commits: (1) make `remote.X.refmap` act like `--refmap` on the command line, (2) teach `git fetch` to enumerate tracked branches when no refs are specified, (3) add `git remote add --limited-fetch` to set up `refmap` instead of `fetch`, and (4) add heuristics (e.g., shallow repos default to limited fetch). The review also suggests starting with an explicit `--limited-fetch` flag before adding automatic heuristics, keeping the change opt-in initially.

This is a substantive, design-level critique that will require a full rewrite of the patch. The proposed refactoring is well-structured and addresses the ambiguity in the original design while preserving the performance benefit. The discussion is now focused on implementation strategy rather than the core problem or goal.
