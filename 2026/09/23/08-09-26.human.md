This is the first patch in Christian Couder’s **v2 series introducing a new `parse-options` sub-API for early argument scanning**, focusing on a preparatory refactoring. The patch adds `parse_options_takes_argument()`, a helper function that determines whether a given `struct option` consumes the next command-line argument (e.g., `--depth 5` vs. `--help`). This logic was previously open-coded in `show_gitcomp()` (the function behind `git <cmd> --git-completion-helper`) and will be reused in the upcoming `early_scan_options()` API.

The implementation is straightforward: the function checks the option’s type (e.g., `OPTION_STRING`, `OPTION_INTEGER`) and flags (e.g., `PARSE_OPT_NOARG`, `PARSE_OPT_LASTARG_DEFAULT`) to decide if the option takes an argument. The commit message notes that `PARSE_OPT_LASTARG_DEFAULT` is intentionally excluded from the "takes argument" category, matching the existing behavior in `show_gitcomp()`. The patch updates `show_gitcomp()` to use the new helper, eliminating a 13-line switch statement in favor of a single conditional.

This is a **clean, well-motivated refactoring** with no behavior changes. The new function is immediately useful for the next patch in the series, which introduces `early_scan_options()`, and could also benefit other parts of Git that need to reason about option arguments (e.g., help text generation or validation). The commit message clearly explains the motivation and edge cases, and the code is covered by existing tests (no new test failures are expected).
