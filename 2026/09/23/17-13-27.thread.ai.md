Subject: [PATCH 0/2] ci: reduce resource exhaustion in GitHub Actions
Series version: v2 (Patch 1 settled and ready for integration; Patch 2 revised, under review)
Originating author: Tamir Duberstein
Thread type: patch series (CI/build system)

Core problem or goal
Address resource exhaustion in GitHub Actions CI jobs running the full test suite on Linux runners. The series targets two specific issues: (1) `t4205-log-pretty-formats.sh` generates enormous output that triggers OOM kills when `diff` compares it, and (2) default `make` and `prove` parallelism (`-j10`) is too aggressive for the Linux runner’s 2 CPU cores, causing ENOSPC errors during large clone/repack tests.

Current status
Patch 1 is settled and ready for integration: the `test_cmp_bin` replacement in `t/t4205-log-pretty-formats.sh` is endorsed by Jeff King, Junio C Hamano, and Patrick Steinhardt. The next revision will drop the ineffective `rm` lines and include the benchmark data in the commit message, as previously agreed. Patch 2 (v2) remains under review: it unifies GitHub/GitLab CI logic by dynamically setting `-j` to the runner’s CPU count, with benchmark data showing a 2 % speedup on Linux with `1x CPU count` and a 7 % speedup with `2x CPU count`. Tamir opts for `1x CPU count` as a conservative baseline. Patrick Steinhardt’s latest review requests two commit-message improvements—adding the benchmark data and clarifying the macOS justification—but does not object to the technical approach.

Key technical details
- Patch 1: Replace `test_cmp` (which uses `diff -u`) with `test_cmp_bin` (which uses `cmp`) in `t/t4205-log-pretty-formats.sh`. Benchmark data: `diff -u` on 2 GiB files peaks at 4 GiB RSS and takes 5 seconds; `cmp` uses 1.2 MiB and finishes in 0.5 seconds. The OOM kill occurred in a private repository where GitHub runners have half the memory of public ones. Files touched: `t/t4205-log-pretty-formats.sh`. The ineffective `rm` lines will be dropped in the next revision.
- Patch 2: Dynamically set `-j` for `make` and `prove` to the runner’s CPU count (`JOBS=$(nproc)`) when `CI_OS_NAME` is `linux`, matching GitLab CI policy. The v2 revision unifies the logic for both CI platforms and uses native CPU-count queries on macOS (`sysctl -n hw.logicalcpu`) and Windows (`NUMBER_OF_PROCESSORS`). Benchmark data: on Linux, `1x CPU count` yields a 2 % speedup over the current `-j10`, while `2x CPU count` yields a 7 % speedup. Tamir opts for `1x CPU count` as a conservative, consistent baseline across CI providers. Files touched: `ci/lib.sh` (12 insertions, 4 deletions).
- No new symbols, CLI options, or on-disk format changes.
- Test coverage: unchanged (long-running tests remain enabled).
