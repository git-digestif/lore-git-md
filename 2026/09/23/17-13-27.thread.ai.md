Subject: [PATCH 0/2] ci: reduce resource exhaustion in GitHub Actions
Series version: v2 (Patch 2 revised; Patch 1 unchanged, now simplified)
Originating author: Tamir Duberstein
Thread type: patch series (CI/build system)

Core problem or goal
Address resource exhaustion in GitHub Actions CI jobs running the full test suite on Linux runners. The series targets two specific issues: (1) `t4205-log-pretty-formats.sh` generates enormous output that triggers OOM kills when `diff` compares it, and (2) default `make` and `prove` parallelism (`-j10`) is too aggressive for the Linux runner’s 2 CPU cores, causing ENOSPC errors during large clone/repack tests.

Current status
Under review (v2 posted). Patch 1 is settled: the `test_cmp_bin` replacement in `t/t4205-log-pretty-formats.sh` is endorsed by Jeff King and Junio C Hamano and ready for integration. Patch 2 revised to use `1x CPU count` and unify GitHub/GitLab CI logic; benchmark data shows a 2 % speedup on Linux with `1x CPU count` and a 7 % speedup with `2x CPU count`. No maintainer decision on Patch 2.

Key technical details
- Patch 1: Replace `test_cmp` (which uses `diff -u`) with `test_cmp_bin` (which uses `cmp`) in `t/t4205-log-pretty-formats.sh`. Benchmark data: `diff -u` on 2 GiB files peaks at 4 GiB RSS and takes 5 seconds; `cmp` uses 1.2 MiB and finishes in 0.5 seconds. The OOM kill occurred in a private repository where GitHub runners have half the memory of public ones. The change is a single-line replacement in the test script. Files touched: `t/t4205-log-pretty-formats.sh`.
- Patch 2: Dynamically set `-j` for `make` and `prove` to the runner’s CPU count (`JOBS=$(nproc)`) when `CI_OS_NAME` is `linux`, matching GitLab CI policy. The v2 revision unifies the logic for both CI platforms and uses native CPU-count queries on macOS and Windows. Benchmark data: on Linux, `1x CPU count` yields a 2 % speedup over the current `-j10`, while `2x CPU count` yields a 7 % speedup. Tamir opts for `1x CPU count` as a conservative, consistent baseline across CI providers. The change is a four-line addition to `ci/lib.sh`. Files touched: `.github/workflows/main.yml`, `ci/lib.sh`.
- No new symbols, CLI options, or on-disk format changes.
- Test coverage: unchanged (long-running tests remain enabled).

Open questions and loose ends
- Patch 2: Would oversubscribing (e.g., `2x CPU count`) yield a better performance/resource trade-off? Benchmark data shows a 7 % speedup on Linux with `2x CPU count`, but Tamir defers this exploration to a future patch. No new failure logs demonstrating ENOSPC errors have been provided.
