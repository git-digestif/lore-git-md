Subject: [PATCH 0/2] ci: use cmp and align job-count selection
Series version: v3 (Patch 1 unchanged and ready for integration; Patch 2 revised to use 2x CPU count)
Originating author: Tamir Duberstein
Thread type: patch series (CI/build system)

Core problem or goal
Mitigate resource exhaustion in GitHub Actions CI jobs running the full test suite on Linux runners by addressing two issues: (1) `t4205-log-pretty-formats.sh` generates enormous output that triggers OOM kills when `diff` compares it, and (2) default `make` and `prove` parallelism is misaligned across CI platforms, causing performance regressions or instability.

Current status
Patch 1 remains settled and ready for integration: the `test_cmp_bin` replacement in `t/t4205-log-pretty-formats.sh` is endorsed by Jeff King, Junio C Hamano, and Patrick Steinhardt. Patch 2 has been revised to use **twice the detected CPU count** (2x CPU count) for `make` and `prove` parallelism on all CI platforms (GitHub Actions and GitLab CI), replacing the v2 proposal of 1x CPU count. The revision is data-driven, incorporating cross-platform benchmark data (Linux, macOS, Windows) that shows a 7 % speedup on Linux and avoids a 26 % slowdown on macOS. The commit message now includes the benchmark table, addressing Patrick Steinhardt’s prior request for evidence. No open technical questions remain for either patch.

Key technical details
- Patch 1: Replace `test_cmp` (which uses `diff -u`) with `test_cmp_bin` (which uses `cmp`) in `t/t4205-log-pretty-formats.sh`. Benchmark data: `diff -u` on 2 GiB files peaks at 4 GiB RSS and takes 5.3 seconds; `cmp` uses 1.2 MiB and finishes in 0.5 seconds. The OOM kill occurred in a private repository where GitHub runners have half the memory of public ones. Files touched: `t/t4205-log-pretty-formats.sh`. No changes from v2.
- Patch 2: Dynamically set `-j` for `make` and `prove` to **twice the runner’s CPU count** (`JOBS=$(($(nproc) * 2))`) when `CI_OS_NAME` is `linux`, `macos`, or `windows`, unifying the logic for both CI platforms. Native CPU-count queries are used: `nproc` (Linux), `sysctl -n hw.logicalcpu` (macOS), and `NUMBER_OF_PROCESSORS` (Windows). Benchmark data (median build/test-step times across 10 runs):
  - Linux: `2x CPU count` yields a 7 % speedup over `1x CPU count` (no reliable change over `-j10`).
  - macOS: `2x CPU count` avoids a 26 % slowdown observed with `1x CPU count`.
  - Windows: `2x CPU count` is neutral.
  Files touched: `ci/lib.sh` (17 insertions, 4 deletions). No new symbols, CLI options, or on-disk format changes. Test coverage: unchanged.
- The ineffective `rm` lines in Patch 1 were dropped in v2 and are not reintroduced.
