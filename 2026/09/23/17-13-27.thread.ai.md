Subject: [PATCH 0/2] ci: use cmp and align job-count selection
Series version: v3 (both patches final and ready for integration)
Originating author: Tamir Duberstein
Thread type: patch series (CI/build system)

Core problem or goal
Mitigate resource exhaustion in GitHub Actions CI jobs running the full test suite on Linux runners by addressing two issues: (1) `t4205-log-pretty-formats.sh` generates enormous output that triggers OOM kills when `diff` compares it, and (2) default `make` and `prove` parallelism is misaligned across CI platforms, causing performance regressions or instability.

Current status
Both patches have been signed off by Patrick Steinhardt and are ready for integration into Junio’s `next` branch. Patch 1 (OOM mitigation via `test_cmp_bin`) is settled and endorsed by Jeff King, Junio C Hamano, and Patrick Steinhardt. Patch 2 (unified parallel job-count selection) has converged on **twice the detected CPU count** (2x CPU count) for `make` and `prove` parallelism on all CI platforms (GitHub Actions and GitLab CI), incorporating cross-platform benchmark data that demonstrates a 7 % speedup on Linux and avoids a 26 % slowdown on macOS. Patrick Steinhardt’s final review explicitly accepts the cross-platform trade-off, noting that macOS is already the fastest platform and that special-casing it for marginal gains is not worthwhile. The series is now fully resolved and ready for integration.

Key technical details
- Patch 1: Replace `test_cmp` (which uses `diff -u`) with `test_cmp_bin` (which uses `cmp`) in `t/t4205-log-pretty-formats.sh`. Benchmark data: `diff -u` on 2 GiB files peaks at 4 GiB RSS and takes 5.3 seconds; `cmp` uses 1.2 MiB and finishes in 0.5 seconds. The OOM kill occurred in a private repository where GitHub runners have half the memory of public ones. Files touched: `t/t4205-log-pretty-formats.sh`. No changes from v2. The patch is self-contained, addressing only the OOM risk without altering test behavior or introducing new CLI options, on-disk formats, or test coverage gaps.
- Patch 2: Dynamically set `-j` for `make` and `prove` to **twice the runner’s CPU count** (`JOBS=$(($(nproc) * 2))`) when `CI_OS_NAME` is `linux`, `macos`, or `windows`, unifying the logic for both CI platforms. Native CPU-count queries are used: `nproc` (Linux), `sysctl -n hw.logicalcpu` (macOS), and `NUMBER_OF_PROCESSORS` (Windows). Benchmark data (median build/test-step times across 10 runs):
  - Linux: `2x CPU count` yields a 7 % speedup over `1x CPU count` (no reliable change over `-j10`).
  - macOS: `2x CPU count` avoids a 26 % slowdown observed with `1x CPU count`.
  - Windows: `2x CPU count` is neutral.
  Files touched: `ci/lib.sh` (17 insertions, 4 deletions). No new symbols, CLI options, or on-disk format changes. Test coverage: unchanged.
