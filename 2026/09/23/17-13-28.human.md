This is the first patch in a two-part CI/build system series aimed at reducing resource exhaustion in GitHub Actions. It tackles a specific bottleneck in the `t4205-log-pretty-formats.sh` test, which generates a commit message larger than 2 GiB. The current implementation uses `test_cmp` (which internally calls `diff`) to compare the output, but this triggers an OOM kill in the Linux CI environment.

The fix is straightforward: replace `test_cmp` with `test_cmp_bin`, which performs a byte-for-byte comparison without constructing a line-oriented diff, and immediately delete the temporary files after comparison. This releases over 4 GiB of memory before subsequent tests run. The change is minimal—just two lines modified in one test script—and preserves the test's intent while avoiding the resource spike. The commit message clearly explains the problem and solution, and the approach feels pragmatic rather than hacky. No controversy is evident; this looks like a sensible fix for a real CI pain point.
