This is the **core API patch** in Christian Couder’s v2 series introducing `early_scan_options()` to the `parse-options` subsystem. The patch adds a new helper function that lets Git commands safely scan their command-line arguments for specific options *before* full parsing, avoiding the fragile hand-rolled scans that currently exist in several commands.

The implementation is **clean and well-documented**. It reuses the existing `struct option` array (marked with a new `PARSE_OPT_EARLY` flag) and the `parse_options_takes_argument()` helper from patch 1/3, ensuring consistency with the main `parse_options()` logic. The scan stops at `--` and `--end-of-options`, matching `parse_options()` behavior, and deliberately ignores short options, negated forms, abbreviations, subcommands, and aliases to keep the implementation simple and fast. These limitations are clearly documented in `parse-options.h` and `api-parse-options.adoc`.

The patch includes **comprehensive test coverage** in `t/t0040-parse-options.sh`, exercising edge cases like stuck values (`--option=value`), optional arguments, non-options, and early termination. A new test helper (`test-parse-options --early-scan-options`) makes it easy to verify the API’s behavior. The commit message explains the design trade-offs and justifies the deliberate simplifications, making it clear why a full "dry-run" mode in `parse_options()` was not pursued.

This patch is **ready for review** and looks like a solid foundation for the series. It addresses Junio’s v1 feedback by eliminating the separate `early_scan_option` structure and reusing `struct option`, reducing duplication and programmer burden. The API is **narrowly focused** on the most compelling use case (fixing `git fast-import`’s `--allow-unsafe-features` bug in patch 3/3) while remaining general enough for future adoption by other commands. The implementation is **well-tested and documented**, and the commit message provides excellent context for reviewers.
