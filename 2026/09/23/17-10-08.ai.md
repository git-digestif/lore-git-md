This is the first patch in Tamir Duberstein’s two-part performance series for `git ls-files`, targeting untracked cache correctness. The patch fixes a subtle bug in how ignore-file hashes are computed: the hash was previously calculated *after* the parser added a trailing linefeed, causing the fast path (which copies the blob ID from the index) and the fallback path (which computes the hash) to disagree even when the ignore file was unchanged. This mismatch triggered unnecessary untracked cache invalidation, undermining the cache’s purpose.

The fix is mechanical: move the linefeed addition after the hash computation. The change is confined to `dir.c` and updates the expected test hashes in `t/t7063-status-untracked-cache.sh` to match the corrected behavior. No new functionality is introduced, and the patch does not modify the on-disk cache format or index state. The motivation is clear—eliminate spurious cache invalidation—but the commit message could more explicitly quantify the performance impact of this bug (e.g., how often it occurs in real-world workflows).

This patch is a prerequisite for the second patch, which implements untracked cache reuse in `git ls-files`. The series is well-scoped, with thorough test coverage and synthetic benchmarks already demonstrating significant speedups.
