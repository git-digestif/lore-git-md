This is a feature patch implementing the "matching-inspired fetch mode" design that emerged from the earlier thread discussion. The patch introduces a new special refspec `+:` (or `:` for non-forced updates) that dynamically fetches only the branches tracked by local branches at the remote being fetched, plus the remote's default branch. In shallow repositories, `git remote add` now defaults to this refspec instead of the traditional wildcard `+refs/heads/*:refs/remotes/<name>/*`, addressing the performance issue where a refspec-less fetch in a shallow repository would negotiate history for all remote branches.

The implementation touches several key files: `builtin/fetch.c` (core logic for the new refspec and its integration with fetch), `builtin/remote.c` (default refspec selection in shallow repositories), `refspec.c`/`refspec.h` (parsing and representation of the new refspec), and `remote.c`/`remote.h` (helper functions to enumerate branches tracking a remote). The patch also adds a new test script `t/t5585-fetch-tracking-refspec.sh` with comprehensive coverage of the new behavior, including edge cases like multiple local branches tracking the same remote branch and branches tracking different remotes.

The design is well-motivated and addresses the root cause of the performance issue without requiring new configuration options. The choice to make this the default for `git remote add` in shallow repositories is sensible, as it preserves existing behavior for non-shallow repositories while providing immediate relief for the shallow case. The implementation is thorough, with careful attention to edge cases (e.g., stale `HEAD`, multiple tracking branches) and good test coverage. The documentation updates in `git-remote.adoc` and `pull-fetch-param.adoc` are clear and complete.

Key technical details to note for future discussion:
- The new refspec syntax `+:` and its behavior (fetching tracked branches + default branch).
- The `tracking` flag added to `struct refspec_item` to distinguish this special refspec.
- The `branches_tracking_remote()` helper function that enumerates branches tracking a remote.
- The integration with `git remote add` in shallow repositories (defaulting to `+:`).
- The priming mechanism: the remote's default branch is always fetched, even before any tracking is set up.
- The backward compatibility: non-shallow repositories continue to use wildcard refspecs by default.
