This is the second patch in Justin Tobler’s two-patch bugfix series (v2) targeting a race condition in Git’s object database (ODB) transaction layer. The patch ensures pending packfiles are flushed before transaction migration, preventing a "No such file or directory" error when large blobs are written to a packfile in a transaction’s temporary directory.

The change is minimal but critical: `flush_packfile_transaction()` is now called earlier in `odb_transaction_files_commit()`, before the temporary directory is migrated to the main ODB. This guarantees that all packfiles are finalized and synced before the transaction’s objects are moved, eliminating the race. The patch also adds a new test (`t/t1050-large.sh`) that reproduces the bug by creating a repository with `core.fsync=loose-object` and `core.fsyncMethod=batch`, then verifying that both small and large objects remain readable after commit.

The test improvements in v2 address prior feedback from Patrick Steinhardt: the setup is now wrapped in a subshell for cleaner cleanup, and the inaccurate comment about checking for leftover objects has been removed. The test remains focused on the core issue—object readability after commit—rather than implementation details. No new CLI options, config keys, or on-disk format changes are introduced.

This patch directly resolves the race described in the series’ cover letter and thread context. The fix is narrowly scoped to the ODB transaction layer, aligning with the ongoing ODB abstraction effort led by Patrick Steinhardt. The change is well-motivated, with clear error reproduction steps and a targeted solution. The unresolved issue of `flush_packfile_transaction()` swallowing errors via `die()` is noted in the commit message but deferred to a future series, as expected for a focused bugfix.
