This is a performance-focused patch series that revives and expands the effort to make `git ls-files` reuse the untracked cache populated by `git status`. The v2 series now consists of three patches, up from the original two, and addresses feedback from the earlier iteration.

The first patch remains largely unchanged: it fixes inconsistent ignore-file hashes by computing the hash before the parser appends a newline, preventing spurious cache invalidation. The commit message is clearer now, explicitly noting that the fast path (using an up-to-date index entry) and the fallback path (hashing the buffer) now agree on the object ID.

The second patch is new and lets `git status -unormal` and `git status -uall` share the same untracked cache. Previously, `-unormal` would stop scanning a directory after finding an untracked file, while `-uall` would scan everything. Now, a later command can complete the listing if needed, avoiding redundant work. This is a clever middle ground that preserves the performance intent of `-unormal` while still allowing reuse.

The third patch teaches `git ls-files` to use the untracked cache and write pending updates back to the index. This is the core of the performance win: repeated queries like `` `git ls-files --cached --others --exclude-standard -z -- "**/pyproject.toml"` `` no longer walk the working tree if the cache is already populated. The patch also respects `--no-optional-locks`, so users can suppress index writes if desired. For wildcard pathspecs without a fixed prefix, the implementation applies the pathspec after reading complete directory listings, which can mean scanning more directories than strictly necessary on the first query but pays off on subsequent ones.

The benchmarks in the cover letter are impressive: on a synthetic tree with 100,000 files, the v2 series cuts the time for a warm query from 241 ms to 33 ms (a 7× speedup) and reduces the combined query+status time from 293 ms to 93 ms. Even with fsmonitor enabled, the improvements hold. The measurements now include alternating modes and cache invalidation, showing the series is robust across different usage patterns.

The series touches `dir.c` (core directory traversal), `builtin/ls-files.c` (the command implementation), and adds tests in `t/perf/p3010-ls-files.sh`, `t/t7063-status-untracked-cache.sh`, and `t/t7519-status-fsmonitor.sh`. The changes are well-scoped and avoid modifying the on-disk cache format. The motivation is clear: eliminate redundant filesystem walks when the untracked cache is already populated, and do so without breaking existing behavior. The author has clearly iterated on the design based on feedback, and the result looks like a solid improvement.
