This is the second patch in Tamir Duberstein’s two-patch performance series that teaches `git ls-files` to reuse the untracked cache populated by `git status`. It builds on the first patch (which fixed spurious cache invalidation) and implements the core optimization: expanding collapsed directories and filtering cached listings on demand without writing the expanded cache back to the index.

The patch adds a new `untracked_cache_expand` flag to `struct dir_struct` and wires it into `cmd_ls_files`. When the flag is set and the query is a simple wildcard without attribute or exclude magic, the code skips the usual directory pruning and instead walks the entire cached tree, then filters the results in memory. This preserves correctness for complex pathspecs while delivering the advertised speedup: synthetic benchmarks show a 7× improvement (361 ms → 50 ms) on a tree with 100 k tracked files and a 2× improvement (659 ms → 339 ms) on a mixed workload.

Tests in `t/perf/p3010-ls-files.sh` measure the before/after performance, and `t/t7063-status-untracked-cache.sh` adds regression tests that verify the expanded cache is not written back, that directory pruning still works for fixed-prefix queries, and that attribute/exclude pathspecs are handled correctly. The implementation is confined to `dir.c` and `builtin/ls-files.c`; no on-disk format changes are made.
