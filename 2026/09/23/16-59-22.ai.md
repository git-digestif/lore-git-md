This is a **CI/build system** follow-up in the thread about the Debian 12 HTTP/2 authentication workaround. Jeff King (Peff) refines his earlier proposal by offering a version-range-aware prereq that skips the affected tests (`t5559.15` and `t5559.16`) for any curl version between 7.88.1 and 8.3.0 (exclusive). The patch remains minimal, touching only `t/t5551-http-fetch-smart.sh`, and introduces a single prereq `HAVE_CURL_HTTP2_BUG` that is true when HTTP/2 is enabled and the libcurl version falls in the problematic range. This version-range approach is more future-proof than the original CI-only skip or Peff’s initial single-version check, but still avoids hard-coding test numbers and works both in CI and locally.

Peff’s patch uses `awk` to parse the libcurl version string and conservatively marks any version from 7.88.1 up to (but not including) 8.3.0 as broken. The implementation is concise and leverages the existing `build_option` helper to extract the version. He presents this as a refinement of his earlier proof-of-concept rather than a formal patch submission, leaving the final choice between this version-range approach, his single-version alternative, or the original CI-only workaround to the thread participants. The core diagnosis and the need for a workaround remain uncontested; the discussion is now focused on which implementation strategy best balances robustness and simplicity.
