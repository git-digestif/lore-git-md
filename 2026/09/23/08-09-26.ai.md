This is the first patch in the v2 series introducing a new `parse-options` sub-API for early argument scanning. It refactors existing logic in `show_gitcomp()` into a reusable helper, `parse_options_takes_argument()`, which determines whether an option consumes the next command-line argument. The helper will be used in the next patch to implement the early scanner itself.

The change is a clean refactoring: it extracts a rule that was previously open-coded in shell completion logic (`show_gitcomp()`) and makes it available for reuse. The new function is well-documented and handles all edge cases (e.g., `PARSE_OPT_LASTARG_DEFAULT` options, which only consume arguments when not the last one). The patch touches only `parse-options.c` and `parse-options.h`, with no behavior changes—just moving code into a shared location.

This is a preparatory step for the core API (`early_scan_options()`) introduced in patch 2/3. The refactoring is uncontroversial and aligns with the series’ goal of reducing duplication in argument parsing. The commit message clearly explains the motivation and the function’s semantics. No test changes are needed here, as the existing completion tests already cover the logic being refactored.
