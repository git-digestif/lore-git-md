This is a documentation patch follow-up, part of the ongoing effort to modernize cross-references in Git's man pages. Jeff King (Peff) replies to Julia Evans's patch with a substantive review that surfaces a trade-off between usability and link stability.

Peff notes that AsciiDoc now auto-generates section IDs (e.g., `_editing_patches`), which could replace the manual `[[EDITING_PATCHES]]` anchors Julia added. Using auto-generated IDs would avoid breaking existing fragment links in the HTML output (e.g., `git-scm.com/docs/git-add#_editing_patches` would remain valid), but the auto-generated IDs are less readable and may still change over time due to AsciiDoc implementation details. Julia's patch intentionally uses manual anchors to produce cleaner, all-caps fragment IDs (e.g., `#EDITING_PATCHES`), which Peff prefers aesthetically but acknowledges will break existing links.

The review also catches minor typographic inconsistencies, such as quotes around section names (`<<OBJECT_PREREQUISITES,"OBJECT PREREQUISITES">>`) and backticks inside cross-references (`<<BATCH_OUTPUT,`BATCH OUTPUT`>>`). Peff suggests these can be cleaned up later, as the patch is already large and mechanical.

This is a well-informed, tested review: Peff tested both AsciiDoc and Asciidoctor backends, referenced the auto-ID behavior, and weighed the trade-offs between link stability and readability. The discussion is now about whether to accept the link breakage for the sake of cleaner URLs, not about the patch's core goal.
