This thread is about a two-patch series from Tamir Duberstein that tackles resource exhaustion in GitHub Actions CI jobs. The first patch is now effectively settled: it replaces `test_cmp` with `test_cmp_bin` in `t/t4205-log-pretty-formats.sh` to prevent OOM kills when comparing large test outputs. The change is minimal and well-supported by benchmark data showing dramatic memory and runtime improvements. Both Jeff King and Junio Hamano have endorsed the approach, and the early file deletion from the first version has been dropped as unnecessary.

The second patch, which dynamically adjusts `make` and `prove` parallelism to match the runner’s CPU count, remains under review. Tamir revised it in v2 to use `1x CPU count` and unify the logic for GitHub and GitLab CI, providing benchmark data that shows a modest speedup. Patrick Steinhardt has raised questions about oversubscription and requested evidence of CI failures, but no new objections have emerged. The series is still cooking, with the first patch ready to merge and the second awaiting further feedback.
