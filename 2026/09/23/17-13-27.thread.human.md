This thread is about a two-patch series from Tamir Duberstein aimed at reducing resource exhaustion in GitHub Actions CI jobs. The first patch replaces `test_cmp` with `test_cmp_bin` in a specific test script to avoid OOM kills caused by enormous output comparisons, and the second dynamically adjusts parallelism for `make` and `prove` based on the runner’s CPU count.

The first patch is effectively settled: both Jeff King and Junio C Hamano endorsed the `test_cmp_bin` change as a targeted fix, and Tamir has dropped the early file deletion that Patrick Steinhardt questioned as unnecessary. The second patch, which sets parallelism to match the runner’s CPU count, has now seen new benchmark data from Tamir. The data shows a modest 2% speedup on Linux with 1x CPU count and a 7% improvement with 2x, but results on macOS and Windows are mixed. Tamir opted for the conservative 1x approach to unify GitHub and GitLab CI logic, addressing Patrick’s earlier concern about divergent configurations. The ball is now back to Patrick to assess whether the data and unified logic satisfy his review concerns. No maintainer decision has been made on the second patch yet.
