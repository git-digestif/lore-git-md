This thread is a two-patch series from Tamir Duberstein aimed at fixing resource exhaustion in GitHub Actions CI jobs running the full test suite on Linux. The first patch reduces memory pressure by replacing `diff` with `cmp` in a particularly large test (`t4205-log-pretty-formats.sh`) and deleting temporary files early, reclaiming about 4 GiB of memory. The second patch, now detailed, dynamically sets the parallelism level (`-j`) for `make` and `prove` to match the runner’s CPU count, aligning GitHub Actions with GitLab CI’s existing policy. This prevents disk space exhaustion (ENOSPC errors) caused by overly aggressive parallelism on private Linux runners with limited CPUs.

The series is under review as version 1, with no prior iterations or maintainer decisions. The changes are minimal, confined to CI infrastructure (`.github/workflows/main.yml` and `ci/lib.sh`), and preserve full test coverage rather than disabling long-running tests. Tamir has provided clear technical rationale for both patches, framing them as pragmatic fixes for real CI bottlenecks. No reviews or objections have been recorded yet, but the implementation is straightforward and well-motivated. If the goal is to maintain the full test suite on GitHub Actions without resource exhaustion, this series appears to be a sensible solution.
