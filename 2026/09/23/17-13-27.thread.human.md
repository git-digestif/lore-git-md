This thread is about a two-patch series from Tamir Duberstein aimed at reducing resource exhaustion in GitHub Actions CI jobs. The first patch replaces `test_cmp` with `test_cmp_bin` in a test script (`t4205-log-pretty-formats.sh`) to avoid OOM kills when comparing large outputs, while the second dynamically adjusts parallelism for `make` and `prove` on Linux runners to prevent ENOSPC errors.

The series is under review, with the first patch now effectively approved by both Jeff King and Junio Hamano. They agree the `test_cmp_bin` change is a reasonable, targeted fix for the edge case, and no further optimization (like early file deletion or a hybrid `test_cmp` improvement) is needed. The open question about whether to retain the early file deletion in Patch 1 remains, but Tamir has already conceded it may not be worth keeping. For Patch 2, Patrick Steinhardt has raised questions about the reproducibility of the ENOSPC errors, the runtime impact of reduced parallelism, and whether GitLab and GitHub CI logic should be unified—none of which have been addressed yet.

Key participants include Tamir (the author), Patrick Steinhardt (who raised technical questions), and Jeff King and Junio Hamano (who endorsed Patch 1). The series touches CI infrastructure and test scripts but introduces no new symbols or on-disk changes. The next steps are likely for Tamir to address Patrick’s questions on Patch 2 or revise the series based on the feedback.
