This thread is about a two-patch series from Tamir Duberstein aimed at reducing resource exhaustion in GitHub Actions CI jobs. The series targets two specific problems: (1) a test script (`t4205-log-pretty-formats.sh`) that generates enormous output, triggering OOM kills when `diff` compares it, and (2) overly aggressive parallelism in `make` and `prove` on Linux runners with only 2 CPU cores, leading to ENOSPC errors during large clone/repack tests.

The first patch replaces `test_cmp` (which uses `diff`) with `test_cmp_bin` (which uses `cmp`) in the problematic test script. Benchmark data shows this reduces memory usage from 4 GiB to 1.2 MiB and cuts runtime from 5 seconds to 0.5 seconds. Jeff King (Peff) has now endorsed this change, calling the improvement "a big difference" and dismissing the need for further optimization, as the current fix is a reasonable, targeted solution for an edge case. The author had previously conceded that an additional early file deletion step may not be worth keeping, and no new objections have emerged.

The second patch dynamically adjusts parallelism (`-j`) for `make` and `prove` to match the runner’s CPU count on Linux, aligning with GitLab CI policy. Patrick Steinhardt’s review raised open questions about whether the ENOSPC errors are reproducible, the runtime impact of reduced parallelism, and whether oversubscribing (e.g., `-j4` on a 2-CPU runner) might be a better trade-off. He also suggested unifying GitLab and GitHub CI logic. No new data or failure logs have been provided yet, so these questions remain unresolved.

The series is still under review, with no maintainer decision recorded. The key participants are Tamir (the author) and Patrick Steinhardt, who has provided substantive feedback. Jeff King’s endorsement of the first patch strengthens its case, but the second patch’s fate hinges on addressing Patrick’s concerns.
