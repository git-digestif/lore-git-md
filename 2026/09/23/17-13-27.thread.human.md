This thread is about a two-patch series from Tamir Duberstein aimed at reducing resource exhaustion in GitHub Actions CI jobs. The first patch replaces `test_cmp` with `test_cmp_bin` in `t/t4205-log-pretty-formats.sh` to avoid OOM kills caused by `diff` comparing enormous test outputs, while the second dynamically adjusts `make` and `prove` parallelism to match the runner’s CPU count.

Patch 1 is now effectively settled. Patrick Steinhardt, after reviewing Tamir’s benchmark data showing `cmp` uses far less memory and time than `diff -u`, has accepted the `test_cmp_bin` change and recommended dropping an ineffective `rm` of temporary files. Once Tamir posts a final revision with these adjustments and includes the benchmark data in the commit message, the patch will be ready for integration. Jeff King and Junio C Hamano had already endorsed the technical direction, so this closes the discussion on Patch 1.

Patch 2 remains under review. It unifies GitHub and GitLab CI logic by dynamically setting `-j` to the runner’s CPU count, with benchmark data showing a 2% speedup on Linux. Tamir opted for a conservative `1x CPU count` baseline, but Patrick has left open the question of whether oversubscribing (e.g., `2x CPU count`) might offer a better performance/resource trade-off. No maintainer decision has been made yet on this patch.
