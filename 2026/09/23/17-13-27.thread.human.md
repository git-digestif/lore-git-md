This thread is about a two-patch series from Tamir Duberstein aimed at reducing resource exhaustion in GitHub Actions CI jobs on Linux runners. The series addresses two specific issues: (1) an out-of-memory kill in `t4205-log-pretty-formats.sh` caused by `diff` memory usage when comparing large test outputs, and (2) "no space left on device" errors due to overly aggressive parallelism (`-j10`) on runners with only 2 CPU cores.

The first patch replaces `test_cmp` with `test_cmp_bin` (using `cmp` instead of `diff`) and deletes large temporary files early to reclaim memory. Patrick Steinhardt’s review of this patch questioned the technical rationale, requesting CI failure logs and benchmark data to justify the change. The second patch dynamically sets parallelism to the runner’s CPU count (`JOBS=$(nproc)`) for Linux runners, matching GitLab CI policy. Patrick has now reviewed this patch as well, asking for evidence of the ENOSPC issue and benchmark data to assess the runtime impact. He also suggested aligning GitHub and GitLab CI logic for consistency.

The series is still under review, with no maintainer decision or prior versions. Tamir has provided context for both patches but has yet to address Patrick’s requests for data. The open questions revolve around whether the proposed changes are justified by measurable improvements—memory savings for Patch 1 and runtime impact for Patch 2. No other participants have weighed in yet.
