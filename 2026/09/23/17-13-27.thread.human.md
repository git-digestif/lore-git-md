This thread is about a two-patch series from Tamir Duberstein aimed at reducing resource exhaustion in GitHub Actions CI jobs. The first patch, which replaces `test_cmp` with `test_cmp_bin` in `t/t4205-log-pretty-formats.sh` to avoid OOM kills during large diff operations, is settled and ready for integration. Jeff King, Junio Hamano, and Patrick Steinhardt have all endorsed the change, and the next revision will drop unnecessary `rm` lines and include benchmark data in the commit message.

The second patch, which dynamically sets `-j` for `make` and `prove` to the runner’s CPU count (matching GitLab CI policy), is now in its second revision. Tamir unified the logic for GitHub and GitLab CI, opting for a conservative `1x CPU count` baseline after benchmarking showed a 2% speedup on Linux. Patrick Steinhardt’s latest review focuses on improving the commit message: he wants the performance impact (the 2% speedup) explicitly stated and suggests rewording the macOS justification to clarify why `sysctl` is used instead of `nproc`. While these are minor tweaks, they’ll likely be addressed in the next revision. The patch’s technical approach isn’t contested, but the question of whether oversubscribing (e.g., `2x CPU count`) would offer a better trade-off remains open. No maintainer decision has been made on this patch yet.
