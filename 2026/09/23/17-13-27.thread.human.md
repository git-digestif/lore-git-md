This thread is about a two-patch series from Tamir Duberstein aimed at reducing resource exhaustion in GitHub Actions CI jobs. The first patch, which replaces `test_cmp` with `test_cmp_bin` in a test script to avoid out-of-memory kills when comparing large outputs, is settled and ready for integration. It’s been endorsed by Jeff King, Junio Hamano, and Patrick Steinhardt, and the only remaining change is a minor revision to drop ineffective cleanup lines.

The second patch has evolved significantly. Initially, it proposed matching GitLab’s policy of one job per CPU, but after benchmarking, Tamir now proposes using *twice* the detected CPU count for both GitHub and GitLab. This change is backed by data showing a 7% speedup on Linux and avoiding a 26% slowdown on macOS. The patch unifies the logic across platforms and includes detailed benchmark results in the commit message. Patrick Steinhardt’s earlier concerns about rationale and alignment have been addressed, and the only remaining task is incorporating the benchmark data into the commit message, which Tamir has now done in this v3 revision. The series is effectively final, pending any last objections to the oversubscription policy.
