This thread is about a two-patch series from Tamir Duberstein aimed at reducing resource exhaustion in GitHub Actions CI jobs. The series targets two specific issues: (1) a test script (`t4205-log-pretty-formats.sh`) that generates enormous output, causing out-of-memory (OOM) kills when `diff` compares it, and (2) overly aggressive parallelism in `make` and `prove` on Linux runners with only 2 CPU cores, leading to "no space left on device" (ENOSPC) errors during large clone/repack tests.

The first patch replaces `test_cmp` (which uses `diff`) with `test_cmp_bin` (which uses `cmp`) in the problematic test script and attempts to delete the large temporary files early to reclaim memory. Patrick Steinhardt’s review questioned the necessity of the change, requesting evidence of the OOM kills and benchmark data comparing the two approaches. Tamir has now provided that evidence: benchmarking shows `diff` peaks at 4 GiB of memory and takes 5 seconds to compare two 2 GiB files, while `cmp` uses only 1.2 MiB and finishes in 0.5 seconds. He also clarified that the OOM kills occurred in a private repository with half the memory of public runners. However, he concedes that the early file deletion is ineffective because the files are rewritten shortly afterward, and is now seeking input on whether to keep or drop that part of the change.

The second patch dynamically sets the `-j` flag for `make` and `prove` to match the runner’s CPU count, aiming to prevent ENOSPC errors. Patrick’s review asked for evidence of the issue and benchmark data on the runtime impact, and suggested exploring whether oversubscribing (running more jobs than CPU cores) might be a better trade-off. Tamir has not yet responded to these questions, so the discussion on this patch remains open.

The series is still under review, with no maintainer decision recorded. The next steps will likely involve Tamir revising the first patch based on feedback about the early file deletion, and addressing the open questions on the second patch. Key participants are Tamir and Patrick Steinhardt, whose review has shaped the discussion so far.
