This thread is about a two-patch series from Tamir Duberstein aimed at improving Git's CI performance and stability. The first patch, which replaces `test_cmp` with `test_cmp_bin` in a test script to prevent out-of-memory kills, is settled and ready for integration, with endorsements from Jeff King, Junio Hamano, and Patrick Steinhardt. The second patch, now in its third version, standardizes parallel job-count selection across GitHub Actions and GitLab CI by setting the job count to twice the detected CPU count. This change is backed by cross-platform benchmark data showing a 7% speedup on Linux and avoiding a 26% slowdown on macOS, addressing Patrick Steinhardt’s earlier request for evidence.

The series is now final, with no open technical questions. The only remaining point is the oversubscription policy (2x CPU count), but the data-driven approach and cross-platform consistency make this a straightforward improvement. Both patches are self-contained, touching only CI scripts and test infrastructure without introducing new CLI options, on-disk formats, or test coverage changes.
