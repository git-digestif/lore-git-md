This thread is about a two-patch series from Tamir Duberstein aimed at reducing resource exhaustion in GitHub Actions CI jobs. The first patch, which replaces `test_cmp` with `test_cmp_bin` in a test script to avoid OOM kills, is effectively settled—both Jeff King and Junio C Hamano have endorsed it, and it’s ready for integration. The second patch, now in its second version, dynamically adjusts the parallelism for `make` and `prove` to match the runner’s CPU count, unifying the logic across GitHub and GitLab CI. This change addresses ENOSPC errors caused by overly aggressive parallelism on Linux runners, which have only 2 CPU cores.

Tamir’s revision to the second patch simplifies the CI logic by using native CPU-count queries on all platforms and opts for a conservative `1x CPU count` baseline, which benchmarks show yields a 2% speedup on Linux. While a `2x CPU count` setting could offer a 7% speedup, Tamir deferred that exploration to a future patch. Patrick Steinhardt’s review raised questions about the performance trade-offs of oversubscription, but no new failure logs or further objections have emerged. The patch is a straightforward refactoring of CI infrastructure and aligns GitHub Actions with GitLab’s more resource-aware approach. The series as a whole is well-motivated, targeting real CI pain points, and while the first patch is ready to go, the second remains under review pending a final decision on the parallelism setting.
