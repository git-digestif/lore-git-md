This thread is about a two-patch series from Tamir Duberstein aimed at reducing resource exhaustion in GitHub Actions CI jobs. The first patch addresses a specific test (`t4205-log-pretty-formats.sh`) that generates over 2 GiB of output, causing the `diff` process to be OOM-killed on Linux runners. The fix replaces `test_cmp` (which uses `diff`) with `test_cmp_bin` (which uses `cmp`) for a byte-for-byte comparison, and immediately deletes the large temporary files afterward to free memory. The change is minimal and preserves the test's intent while eliminating the memory pressure.

The second patch in the series (not yet reviewed in detail here) dynamically adjusts parallelism for `make` and `prove` to match the runner's CPU count, aligning with GitLab CI policy. The series is currently under review, with no objections or reviews recorded yet. Tamir presents the changes as pragmatic fixes for real CI bottlenecks, and the first patch appears uncontroversial. The thread is still early, so feedback from other contributors will determine whether the approach is accepted or if adjustments are needed.
