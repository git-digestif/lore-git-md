This is a **bugfix patch update** addressing Junio C Hamano’s layering concern in the second patch of the `git repack` concurrent-push race series. The patch fixes a latent cruft-pack walk bug that would delete objects reachable only through packs `pack-objects` was not told about, a problem that becomes critical once the series removes `--honor-pack-keep`.

Qin ShiCheng acknowledges the layering issue—`pack-objects` should not downcast ODB sources to the files backend—and proposes a cleaner solution for v3. Instead of exposing a new public function, the patch moves the cache-invalidation logic into `repo_invalidate_kept_pack_caches()`, a repository-level helper that sits alongside the existing `has_object_kept_pack()` reader in `packfile.c`. This keeps the downcast with its peers and removes the new dependency from `pack-objects`, though it does not yet make the code work with non-files backends. The fix is minimal and correct for the current codebase, and Qin argues it is sufficient until the ODB abstraction effort (led by Patrick Steinhardt) moves packfile management down to the files backend.

The commit message in v2 already included a test (`t5329`) that reproduces the bug: a cruft repack with expiration drops objects reachable only through an untold pack. The v3 update does not change the test or the fix’s behavior, only its internal structure. Reviewers who were concerned about layering violations should find this version more palatable, though the broader architectural question—whether the kept-pack cache should live in the files backend—remains open. The patch is now ready for re-review, and the series as a whole is one step closer to merging.
