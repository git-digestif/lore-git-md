This is the third and final patch in Tamir Duberstein’s v2 series to make `git ls-files` reuse the untracked cache populated by `git status`. It implements the core functionality: `git ls-files --others` now reads from the untracked cache and, when optional locking is enabled, writes pending updates back to the index so later commands can benefit.

The patch is careful about when it writes the index. It avoids doing so if the command uses a pathspec prefix (which prunes the in-memory index) or the `--with-tree` option (which adds entries), if `--no-optional-locks` is given, or if the index lock is busy. It also ensures that exclude-file object IDs are recorded before the untracked cache is assigned, so the exclude options are processed in the same order as they would be without the cache. The implementation handles wildcard pathspecs by reading complete directory listings and applying the pathspec afterward, which trades a small overhead in single queries for large gains in repeated queries.

Tests cover the new behavior thoroughly: performance benchmarks in `t/perf/p3010-ls-files.sh` show the speedup, while `t/t3001-ls-files-others-exclude.sh` verifies that exclude options are preserved and ordered correctly. The most detailed tests are in `t/t7063-status-untracked-cache.sh`, which checks that `git ls-files` expands cached directories, filters wildcard results correctly, reuses the cache after `git status -unormal`, respects optional locks, and does not write the index when it shouldn’t. A new test in `t/t7519-status-fsmonitor.sh` confirms that the fsmonitor token is saved even when `index.skipHash` is enabled.

The patch is well-motivated, touches only the necessary files (`builtin/ls-files.c`, `dir.c`, and documentation), and maintains backward compatibility. No on-disk formats are changed, and older Git versions simply rebuild the cache before using it. The series as a whole looks ready for serious review; this patch in particular is the payoff for the refactoring in patches 1 and 2.
