This is the **final patch (4/4)** in D. Ben Knoble’s **four-patch bugfix series** for `git stash`, targeting a race condition in autostash handling when `stash.index=true` is set. The patch replaces the existing subprocess-based index merge logic (`git diff-tree` + `git apply`) with an **in-core merge using `merge-ort.c`**, eliminating the race condition that could corrupt the `MERGE_AUTOSTASH` ref and cause SIGSEGV on conflicted merges.

The change is a **clean, surgical refactoring** of `do_apply_stash()` in `builtin/stash.c`. The old implementation (62 lines of subprocess calls and index manipulation) is replaced with 23 lines of in-core merge logic, using `merge_incore_nonrecursive()` with fixed branch labels (`"Upstream index"`, `"Stashed index changes"`, `"Stash base"`) and `merge_finalize()` for cleanup. The patch also adds a **new test case** in `t/t7600-merge.sh` to verify that fast-forward merges with `--autostash` and `stash.index=true` work correctly when a file is staged beforehand.

**Key technical details**:
- **Files touched**: `builtin/stash.c` (core logic), `t/t7600-merge.sh` (test).
- **Behavior change**: The index merge is now performed in-core, avoiding external process calls and the race condition. The on-disk format is unchanged.
- **Merge options**: Reuses `init_ui_merge_options()` (standardized in patch 2/4) with `o.verbosity = 0` to avoid overhead. Uses `merge_finalize()` to ensure proper cleanup of the `merge_result` strmap.
- **Graceful failure**: If the index merge fails (e.g., conflicts), the patch returns an error without SIGSEGV, preserving the pre-merge state.

**Context in the series**:
This patch builds on the earlier cleanup (patch 1/4, already accepted) and refactoring (patch 2/4, which moved `init_ui_merge_options()` earlier in `do_apply_stash()`). Patch 3/4 added test coverage for conflicted index merges. All feedback from Phillip Wood (merge algorithm consistency, assertion safety, option lifecycle) has been addressed in v2.

**Why this matters**:
The bug is **subtle but real**—it only manifests during autostash operations with staged index entries, a scenario that became possible with the introduction of `stash.index`. The fix is **low-risk** (in-core merges are well-tested in `merge-ort.c`) and **high-reward** (eliminates a race condition and simplifies the code). The test coverage ensures the fix is verifiable.
