Subject: submodule merge: stale delta-base cache causes "repository corrupt" or misread commits
Series version: standalone patch (bugfix)

Thread type: bug report with reproducer and proposed fix

Core problem or goal
When merging a superproject containing two submodules (A and B), Git may attempt to read a commit that exists only in submodule B from submodule A. Instead of reporting a submodule conflict, the merge either fails with "repository corrupt" or misreads the commit due to stale delta-base cache data. The root cause is identified as a stale cache entry: when a pack is closed, its cached data may linger, and if another submodule’s pack reuses the same memory address and base offset, Git returns incorrect cached data rather than the correct object.

Current status
Under review. The patch is a bugfix with a clear, self-contained reproducer that reliably triggers the issue in 93 out of 100 runs across two container environments. No prior versions of this patch have been posted.
