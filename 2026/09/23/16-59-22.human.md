This is a **CI/build system** follow-up in the thread about the Debian 12 HTTP/2 authentication workaround. Jeff King (Peff) refines his earlier proposal with a more general version-checking prereq that skips the problematic tests (`t5559.15` and `t5559.16`) for all curl versions between 7.88.1 and 8.3.0, rather than just the single known-broken version. The patch remains minimal, touching only `t/t5551-http-fetch-smart.sh`, and introduces a new prereq `HAVE_CURL_HTTP2_BUG` that is true when HTTP/2 is enabled and the libcurl version falls within the affected range.

Peff’s updated approach addresses the concern that other versions besides 7.88.1 might exhibit the same bug, though he notes the exact range is conservative since the first affected version is unknown. The implementation uses `awk` to parse the version string from `build_option libcurl`, making it robust against future version bumps. Like his previous patch, this one avoids hard-coded test numbers and works both in CI and locally, offering a more maintainable alternative to the original CI-only workaround.

The thread remains open on whether to adopt this version-range approach, stick with the single-version check, or proceed with the original hard-coded test skip. No new objections have been raised; the discussion is now focused on the trade-off between completeness (this patch) and simplicity (the original or single-version approaches). Peff presents this as a proof-of-concept rather than a formal submission, leaving the final decision to Johannes Schindelin and Junio C Hamano.
