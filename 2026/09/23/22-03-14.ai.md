This is the first patch in Justin Tobler’s v2 bugfix series for the ODB transaction race. It refactors `odb_maybe_flush_packfile()` to separate the ODB reprepare step from packfile flushing, preparing the ground for patch 2/2’s early flush.

The patch lifts the `odb_reprepare()` call out of `flush_packfile_transaction()` and makes callers responsible for invoking it explicitly. The change is mechanical: `odb_transaction_files_write_object_stream()` and `odb_transaction_files_commit()` now call `odb_reprepare()` immediately after flushing, preserving the original behavior. The commit message clarifies that the reprepare step is *not* deferred—only the packfile flush is moved earlier in a subsequent patch.

No functional changes are introduced; the patch is purely preparatory. The diff is small (10 lines, 1 file) and well-scoped, touching only the ODB transaction layer in `object-file.c`. The test coverage remains unchanged, as the race fix itself is implemented in patch 2/2. Feedback from v1 (notably Patrick Steinhardt’s concern about misleading commit message wording) has been addressed in this version.
