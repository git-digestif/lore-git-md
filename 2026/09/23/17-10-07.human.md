This is a two-patch performance optimization for `git ls-files`. The series lets `git ls-files` reuse the untracked cache that `git status` already populates, avoiding redundant working-tree walks when the same files are queried repeatedly.

The first patch fixes a bug where ignore-file hashes were computed inconsistently, causing the untracked cache to be invalidated even when the ignore files had not changed. The second patch teaches `ls-files` to read from the untracked cache and expand partial scans or collapsed directories on demand, without writing the expanded cache back to the index.

Tamir reports benchmarks on a synthetic macOS tree with 100,000 files: a query that previously took 361 ms now averages 50 ms, and directory opens drop from over 5,000 to single digits. The improvement is most dramatic when the cache is already warm and populated by a prior `git status` run. Literal queries (exact path matches) show little change, as expected.

The patches touch `dir.c`, `builtin/ls-files.c`, and add perf tests in `t/perf/p3010-ls-files.sh` and regression tests in `t/t7063-status-untracked-cache.sh`. The commit messages are clear and the code appears well-tested; this looks like a solid, uncontroversial speed-up for a common operation.
