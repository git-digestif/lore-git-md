This is a documentation patch, part of the ongoing effort to modernize cross-references in Git’s man pages. Jeff King (Peff) joins the thread to clarify the technical behavior of AsciiDoc’s link syntax, confirming Julia Evans’s pragmatic choice to use the two-part form (`<<target,text>>`) universally.

Peff explains that the single-form syntax (`<<target>>`) is inconsistent across AsciiDoc implementations and output backends: vanilla AsciiDoc renders it as `[target]` in HTML, while Asciidoctor uses `target`; in man pages, both expand it to the awkward "the section called ‘target’". The two-part form avoids these quirks by explicitly controlling the displayed text. He notes that the single form is more readable in source but concedes that configuring both AsciiDoc and Asciidoctor to behave consistently would be a larger project. For now, the patch’s approach is sound.

The discussion does not challenge the patch’s readiness—it remains approved and queued in `next`—but Peff suggests the commit message could better reflect the real reason for the two-part form (backend consistency) rather than the cross-file reference rationale Julia initially emphasized. No changes to the patch are proposed; this is purely a documentation clarification for future readers. The thread remains focused on a well-tested, uncontroversial improvement.
