This is the first patch in a two-part performance optimization for `git ls-files` that reuses the untracked cache populated by `git status`. The patch fixes a subtle bug in how ignore-file hashes are computed, which was causing unnecessary cache invalidation.

The issue is in `dir.c`'s `add_patterns()` function: the ignore-file hash was being computed *after* a trailing newline was appended for the pattern parser. This meant the fast path (using the blob ID from the index) and the fallback path (computing the hash from the file contents) produced different hashes for the same file, triggering cache invalidation even when the ignore file hadn't changed. The fix moves the hash computation before the newline is added, ensuring both paths agree on the file's identity.

The patch updates the expected hash values in the test suite (`t/t7063-status-untracked-cache.sh`) to match the corrected behavior. The change is minimal—just two lines swapped in `dir.c` and updated test expectations—but it's a critical correctness fix for the untracked cache to work reliably. Without this, the second patch (which teaches `git ls-files` to reuse the cache) would be undermined by spurious invalidations.
