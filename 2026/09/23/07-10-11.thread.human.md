This thread is about a bug in Git’s HTTP transport layer that mishandles Basic Authentication when credentials include an empty username but a non-empty password. Xavier Morel reported that Git fails to include the Basic Auth header in follow-up requests after a 401 Unauthorized response, causing authentication to fail. The issue stems from `init_curl_http_auth` exiting early if the username is empty, unless `proactiveAuth=basic` is enabled. The problem affects Git 2.47 and 2.55 with curl 8.5.0 and is particularly relevant for custom credential helpers or server setups where empty usernames are valid.

The patch will likely target `http.c` or related HTTP transport code, with a small, focused fix. While the scope is narrow, it could impact how Git interacts with credential helpers, especially those that don’t precompute the `credential` field. Xavier suggests two workarounds—enabling `proactiveAuth=basic` or having the credential helper return the precomputed `credential` field—but notes the latter shifts the burden to the helper. The report is well-documented, including reproduction steps, making it easy for reviewers to verify. No prior discussion or decisions are noted, so this appears to be the initial report.
