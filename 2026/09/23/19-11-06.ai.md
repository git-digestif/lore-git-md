This means the patched version will silently continue even if the patch application fails, which is not the intended behavior.

The fix touches the same `applyCommit()` function in `git-p4.py` and the same test file (`t9803-git-p4-shell-metachars.sh`). The regression is subtle but critical: the original patch prioritized security (removing shell interpolation) over correctness (preserving error handling). Junio’s feedback suggests the helper should either propagate the pipeline’s exit status or explicitly raise an exception on failure to match the original behavior. The test coverage remains unchanged, as it only verifies the shell injection fix, not the error-handling logic.
