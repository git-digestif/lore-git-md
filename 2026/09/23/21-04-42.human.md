This is the third and final patch in the v5 bugfix series restoring correct reference-transaction hook behavior when pruning remote refs. The patch ensures that `git fetch --prune` and `git remote prune` pass the resolved old OID (rather than all-zeros) to the hook, matching the pre-2.31 behavior and fixing the regression for external tools like Gerrit and GitLab.

The patch modifies `builtin/fetch.c` and `builtin/remote.c` to retain the old OIDs recorded by `get_stale_heads()` and pass them into the deletion transaction. If a ref changes after the stale scan (e.g., due to a concurrent update), the deletion is rejected for that ref, preserving the new value. Non-atomic pruning uses `refs_delete_refs()` in partial-failure mode, allowing unaffected stale refs to be deleted while still reporting granular errors. Atomic fetches remain all-or-nothing, as before.

The UI is updated to reflect the transaction result: successful deletions are reported as "[deleted]" or "[pruned]", while rejected refs are omitted from both the output and the dangling symref check. The patch adds three new tests to `t/t1416-ref-transaction-hooks.sh` covering hook payloads for pruned remote refs (files/reftable, SHA-1/SHA-256), UI consistency for partial failures, and rejected-ref handling.

This patch directly addresses Junio’s v4 feedback about granular error reporting and Karthik’s API consistency concerns. The changes are narrowly scoped to the pruning paths and preserve the performance gains of the original optimization. With this patch, the series is technically complete and ready for merging to `next`.
