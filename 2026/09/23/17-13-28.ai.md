This is the first patch in a two-part CI/build system series addressing resource exhaustion in GitHub Actions. It targets a specific test (`t4205-log-pretty-formats.sh`) that generates output exceeding 2 GiB, causing the `diff` process to be OOM-killed in Linux CI runners.

The fix replaces `test_cmp` (which uses `diff`) with `test_cmp_bin` (which uses `cmp`) to perform a byte-for-byte comparison without constructing a line-oriented diff. After the comparison succeeds, it immediately deletes the two large temporary files, freeing over 4 GiB of memory before subsequent tests run. The change is minimal—just two lines modified in one test script—and preserves the test's intent while eliminating the memory pressure.

The commit message clearly explains the problem (SIGKILL due to OOM) and the solution (switch to `cmp` and early cleanup). The technical rationale is sound: `cmp` is a lightweight alternative for binary comparison, and the early file deletion is a pragmatic way to reclaim memory in a resource-constrained environment. No new symbols or behaviors are introduced, and the test coverage remains unchanged.

This patch looks like a well-targeted, low-risk fix for a real CI bottleneck. The only potential concern would be whether `test_cmp_bin` is the right tool for the job (e.g., if the test relies on line-oriented diff output for debugging), but the commit message doesn’t suggest that’s the case here. The series as a whole (see thread context) is under review, and this patch appears uncontroversial.
