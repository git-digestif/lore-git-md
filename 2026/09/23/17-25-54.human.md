This is a brief follow-up in the ongoing `git repo info` path-keys series. The author responds to Junio C Hamano’s review of the fourth patch (adding `path.index.absolute` and `path.index.relative`) by opting to **retain the current implementation** that calls `repo_get_index_file(repo)`, which internally invokes `BUG("")` if the repository is not ready to return the index file path. The author explicitly chooses not to replace the function call with direct access to `repo->index_file` and a null check, deferring instead to the existing `BUG()` behavior.

This decision leaves the **latent correctness issue** unresolved. The current implementation will still trigger a fatal error in edge cases where the repository is not fully initialized, rather than gracefully returning an error message. While the change is mechanical and localized to two getter functions in `builtin/repo.c`, it remains a **high-weight technical concern** that could affect script reliability. The author’s response does not address the broader implications of this choice, nor does it engage with Junio’s expressed uncertainty about whether the proposed alternative would be preferable.

The rest of the series — including the unresolved `path.cdup` edge-case discrepancy, the Patch 2/7 refactoring requirement, and the architectural duplication concern — is unaffected by this exchange. Reviewers should note that this issue is now a **known limitation** of the v6 implementation and may require further discussion before merging.
