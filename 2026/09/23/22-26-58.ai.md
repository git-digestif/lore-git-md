This is the first patch in Tamir Duberstein’s v2 series optimizing `git ls-files` to reuse the untracked cache. It fixes a long-standing inconsistency in how ignore-file object IDs are computed, which has been causing unnecessary untracked-cache invalidations.

The bug is straightforward: `add_patterns()` appends a newline to the in-memory buffer before hashing it, but the newline is not present in the on-disk file. When Git later reads the same file from the index (via its blob ID), the hash differs, so the untracked cache treats the file as changed and rebuilds the cache. The patch moves the newline append after the hash is computed, ensuring both paths (direct read and index lookup) produce the same object ID. The fix is confined to `dir.c` and updates the expected test values in `t/t7063-status-untracked-cache.sh` to match the new hashes.

This is a pure correctness fix with no behavior change beyond eliminating spurious cache rebuilds. It is a prerequisite for the later patches in the series, which rely on a stable cache. The patch is small, well-explained, and touches only the core directory traversal logic. No objections or review comments have appeared yet.
