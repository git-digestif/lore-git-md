Thread identity: Performance optimization for `git ls-files` to reuse the untracked cache populated by `git status`. Three-patch series by Tamir Duberstein (v2), superseding the v1 series where patch 2 was retracted.

Core problem or goal: Reduce directory traversal overhead in `git ls-files` and `git status` by reusing and updating the untracked cache, eliminating redundant scans for common workflows. The series fixes a long-standing inconsistency in ignore-file hash computation (patch 1), enables cache sharing between `git status -unormal` and `git status -uall` (patch 2), and teaches `git ls-files` to reuse the cache with optional index writes (patch 3).

Current status: Under active review. All three patches are now fully detailed. Patch 1 (ignore-file hash fix) ensures consistent object IDs between direct file reads and index lookups. Patch 2 (cache sharing between status modes) introduces `UNTRACKED_CACHE_LAZY` for backward compatibility, records incomplete scans with the `check_only` bit, and refactors `read_directory_recursive()` to expand partial listings on demand. Patch 3 (cache reuse in `git ls-files`) implements the core functionality: `git ls-files` now reads from the untracked cache and conditionally writes pending updates back to the index when optional locking is enabled, unless a pathspec prefix or `--with-tree` is used, `--no-optional-locks` is given, or the lock is busy. The series remains self-contained, modifies no on-disk formats, and maintains backward compatibility; older Git versions rebuild the cache before use.

Key technical details:
- **Files touched**: `dir.c`, `builtin/ls-files.c`, `builtin/status.c`, `Documentation/git-ls-files.adoc`, `Documentation/gitformat-index.adoc`.
- **New symbols**: `untracked_cache_expand` flag in `struct dir_struct` (patch 2), `UNTRACKED_CACHE_LAZY` in `dir_flags` (patch 2), `DIR_SHOW_OTHER_DIRECTORIES` (retained for parent directory invalidation).
- **New tests**: Performance tests in `t/perf/p3010-ls-files.sh`, regression tests in `t/t7063-status-untracked-cache.sh` (updated for patch 1), `t/t3001-ls-files-others-exclude.sh`, and fsmonitor integration tests in `t/t7519-status-fsmonitor.sh`. Patch 2 adds tests for partial listing expansion and nested repository cache integrity. Patch 3 adds tests for cache reuse after `git status -unormal`, respect for optional locks, and fsmonitor token preservation with `index.skipHash`.
- **Behavior changes**:
  - Patch 1: Fixes ignore-file hash computation by moving the newline append in `add_patterns()` after the hash is computed, ensuring consistent object IDs between direct file reads and index lookups. Updates test expectations in `t/t7063-status-untracked-cache.sh`.
  - Patch 2: Enables cache sharing between `git status -unormal` (stops after first untracked file) and `git status -uall` (lists all untracked files) by recording incomplete scans with the `check_only` bit and expanding them on demand. Refactors `read_directory_recursive()` to handle cached directories and introduces `UNTRACKED_CACHE_LAZY` for backward compatibility. Retains `DIR_SHOW_OTHER_DIRECTORIES` to ensure index updates invalidate parent directories.
  - Patch 3: Teaches `git ls-files` to reuse the untracked cache and write pending updates back to the index when optional locking is enabled, unless a pathspec prefix or `--with-tree` is used, `--no-optional-locks` is given, or the lock is busy. The implementation records the object IDs of standard exclude files before assigning `dir->untracked`, ensuring exclude options are processed in the same order as before reading the index. For wildcard pathspecs without a fixed prefix, the implementation reads complete directory listings and applies the pathspec afterward, trading single-query overhead for repeated-query gains.
- **Performance impact**: Benchmarks show a 7.3× speedup (241 ms → 33 ms) for a wildcard query (`**/pyproject.toml`) on a synthetic tree with 100 k files. Combined `git status` + `git ls-files` time drops from 293 ms to 93 ms. Similar speedups observed with fsmonitor enabled. Measurements use `hyperfine` with warm caches.
