Thread identity: Performance optimization for `git ls-files` to reuse the untracked cache populated by `git status`. Three-patch series by Tamir Duberstein (v3), superseding v1 (where patch 2 was retracted) and v2.

Core problem or goal: Reduce directory traversal overhead in `git ls-files` and `git status` by reusing and updating the untracked cache, eliminating redundant scans for common workflows. The series fixes a long-standing inconsistency in ignore-file hash computation (patch 1), enables cache sharing between `git status -unormal` and `git status -uall` (patch 2), and teaches `git ls-files` to reuse the cache with optional index writes (patch 3).

Current status: Under active review. Patch 1 (ignore-file hash fix) is confirmed correct and minimal in scope. Patch 2 (cache sharing between status modes) is fully detailed, with refactoring of `read_directory_recursive()` and backward-compatibility mechanisms in place. Patch 3 (cache reuse in `git ls-files`) drew a substantive review identifying a concurrency regression: when `core.untrackedCache=true` and the cache is cold, v3 holds `index.lock` for the entire directory scan, causing concurrent `git add` to fail. The author has confirmed this regression and states that v4 will resolve it by acquiring the lock after `fill_directory()` completes rather than before, using a new `repo_lock_and_update_index_if_able()` helper. This is enabled by commit 6b6d1d56eb ("read-cache: verify skipHash index by stat data"), which landed on `master` after v3 was sent and allows the optional index write to detect concurrent modifications via stat data even when `index.skipHash` is enabled, removing the previous need for early locking. The series is self-contained, modifies no on-disk formats, and maintains backward compatibility; older Git versions rebuild the cache before use.

Key technical details:
- **Files touched**: `dir.c`, `builtin/ls-files.c`, `builtin/status.c`, `Documentation/git-ls-files.adoc`, `Documentation/gitformat-index.adoc`, `t/t7063-status-untracked-cache.sh` (updated for patch 1), `t/perf/p3010-ls-files.sh`, `t/t3001-ls-files-others-exclude.sh`, `t/t7519-status-fsmonitor.sh`.
- **New symbols**: `untracked_cache_expand` flag in `struct dir_struct` (patch 2), `UNTRACKED_CACHE_LAZY` in `dir_flags` (0x80000006, patch 2), `DIR_SHOW_OTHER_DIRECTORIES` (retained for parent directory invalidation), `repo_lock_and_update_index_if_able()` helper (planned for v4 to defer locking until after `fill_directory()`).
- **New tests**: Performance benchmarks in `t/perf/p3010-ls-files.sh`, regression tests in `t/t7063-status-untracked-cache.sh` (updated for patch 1 to match corrected object IDs), `t/t3001-ls-files-others-exclude.sh`, and fsmonitor integration tests in `t/t7519-status-fsmonitor.sh`. Patch 2 adds tests for partial listing expansion, nested repository cache integrity, and filtered status operations. Patch 3 adds tests for cache reuse after `git status -unormal`, optional lock handling, `--debug` behavior, and fsmonitor token preservation with `index.skipHash`. Planned v4 changes remove the test assertion expecting early-lock behavior and add coverage verifying concurrent index updates succeed and persist across `git ls-files` invocations, exercised with `index.skipHash` both enabled and disabled.
- **Behavior changes**:
  - Patch 1: Fixes ignore-file hash computation by moving the newline append in `add_patterns()` after the hash is computed, ensuring consistent object IDs between direct file reads and index lookups. Minimal change in `dir.c`; updates test expectations to reflect corrected hashes. No user-visible behavioral changes.
  - Patch 2: Enables cache sharing between `git status -unormal` (stops after first untracked file) and `git status -uall` (lists all untracked files) by recording incomplete scans with the `check_only` bit and expanding them on demand. Refactors `read_directory_recursive()` to handle cached directories, introduces `UNTRACKED_CACHE_LAZY` for backward compatibility, and retains `DIR_SHOW_OTHER_DIRECTORIES` to ensure index updates invalidate parent directories. Pruning behavior is preserved for pathspecs with fixed prefixes, attributes, or excludes; wildcard pathspecs cache complete listings and apply the filter afterward.
  - Patch 3: Teaches `git ls-files --others` to reuse the untracked cache and write pending updates back to the index when optional locking is enabled, unless a pathspec prefix or `--with-tree` is used, `--no-optional-locks` or `--debug` is given, or the lock is busy. Records object IDs of standard exclude files before assigning `dir->untracked` to ensure exclude options are processed in the same order as before reading the index. For wildcard pathspecs without a fixed prefix, reads complete directory listings and applies the pathspec afterward, trading single-query overhead for repeated-query gains. The v3 update releases the index lock after reading the directory but before printing paths, preventing slow readers from blocking index writers. However, when the untracked cache is cold and `core.untrackedCache=true`, v3 still acquires `index.lock` before the directory scan begins, holding it for the duration of the scan; v4 will defer this lock acquisition until after `fill_directory()` completes.
- **Performance impact**: Benchmarks show a 7.3x speedup (241 ms -> 33 ms) for a wildcard query (`**/pyproject.toml`) on a synthetic tree with 100 k files. Combined `git status` + `git ls-files` time drops from 293 ms to 93 ms. Similar speedups observed with fsmonitor enabled. Measurements use `hyperfine` with warm caches.
