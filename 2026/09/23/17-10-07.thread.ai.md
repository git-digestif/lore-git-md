Thread identity: Performance optimization for `git ls-files` to reuse the untracked cache populated by `git status`. Two-patch series by Tamir Duberstein (v1, with patch 2 retracted).

Core problem or goal: Reduce directory traversal overhead in `git ls-files` by reusing the untracked cache, which is already populated by `git status`. The series first fixes a bug causing unnecessary cache invalidation (patch 1) and *intended* to implement cache reuse (patch 2), but the latter has been withdrawn for further iteration.

Current status: Patch 1 remains under review; patch 2 has been retracted by the author and is not currently under consideration. No prior versions exist. The series is self-contained and does not modify the on-disk cache format or index state.

Key technical details:
- **Files touched**: `dir.c` (core directory traversal), `builtin/ls-files.c` (command implementation).
- **New symbols**: `untracked_cache_expand` flag in `struct dir_struct` (introduced in the now-retracted patch 2).
- **New tests**: Performance tests in `t/perf/p3010-ls-files.sh` and regression tests in `t/t7063-status-untracked-cache.sh` (both introduced in the original series).
- **Behavior changes**:
  - Patch 1 (active): Fixes ignore-file hash computation by moving it *before* a trailing linefeed is added, ensuring consistent hashes for unchanged ignore files. This prevents spurious untracked cache invalidation. The change is confined to `dir.c` and updates test expectations in `t/t7063-status-untracked-cache.sh`.
  - Patch 2 (retracted): *Intended* to teach `git ls-files` to reuse the untracked cache by expanding collapsed directories and filtering cached listings on demand. The expanded cache was not to be written back to the index. The implementation planned to skip directory pruning for simple wildcard queries and filter results in memory, preserving correctness for complex pathspecs. Synthetic benchmarks originally showed a 7× speedup (361 ms → 50 ms) on a tree with 100 k tracked files and a 2× improvement (659 ms → 339 ms) on mixed workloads, but these results are now considered premature.
- **Performance impact**: Patch 1 reduces cache invalidation frequency; its real-world impact is unquantified but expected to be positive. Patch 2’s performance claims are withdrawn pending further iteration.
