This is a follow-up to Tamir Duberstein’s two-patch performance series for `git ls-files` that reuses the untracked cache populated by `git status`. The thread so far has established the goal (eliminating redundant directory traversals), the technical approach (fixing a cache-invalidation bug in patch 1 and implementing cache reuse in patch 2), and the measured speedups (7× on synthetic workloads, 2× on mixed workloads).

This email is a brief, informal retraction of the second patch. Tamir acknowledges that the cover letter and benchmark notes he sent were unintentionally noisy and premature—he characterizes them as “slop” caused by operator error. He clarifies that the first patch (the ignore-file hash fix) is in reasonable shape, but the second patch (the cache-reuse logic) is still under active iteration and not ready for review. No new technical details or objections are raised; the message simply withdraws the current version of patch 2 from consideration. The thread remains open, with the first patch still under review and the second expected to return in a future revision.
