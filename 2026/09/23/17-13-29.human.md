This is the second patch in a two-part CI/build system series aimed at reducing resource exhaustion in GitHub Actions. The author, Tamir Duberstein, addresses a specific issue where GitHub Actions runs ten concurrent `make` test suites on Linux runners with only two CPUs, leading to ENOSPC errors during large clone and repack tests. The fix dynamically sets the parallelism (`-j`) for `make` and `prove` to the runner’s CPU count using `nproc`, matching the existing policy in GitLab CI.

The change is minimal—just four lines added to `ci/lib.sh`—and keeps the long-running tests enabled rather than disabling them. The rationale is pragmatic: smaller runners should not be overloaded with excessive parallelism, and this adjustment aligns GitHub Actions with the more conservative approach already used in GitLab CI. The patch itself is straightforward, touching only the CI infrastructure without affecting core Git functionality or test coverage.

This patch complements the first in the series, which tackles an OOM kill in `t4205-log-pretty-formats.sh` by replacing `diff` with `cmp` and deleting temporary files early. Together, the two patches address real CI bottlenecks without introducing complexity or controversy. The series looks like a well-motivated, low-risk fix for a persistent pain point in the project’s CI pipeline. If the goal is to keep the full test suite running reliably on GitHub Actions, this is a sensible step forward.
