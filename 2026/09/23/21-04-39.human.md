This is a **bugfix series** targeting the refs subsystem, specifically a regression in the reference-transaction hook that has affected external tools like Gerrit and GitLab since Git 2.31. The v5 series (three patches) is the final iteration and is **ready for merging to `next`**.

The regression causes the hook to receive all-zero OIDs for both old and new fields when branches, tags, or remote refs are deleted via high-level commands (`git branch -d`, `git tag -d`, `git remote prune`, `git fetch --prune`). This breaks tools that rely on the hook to monitor ref changes, as the old OID (which was correctly reported in Git 2.28–2.30) is lost. The issue was introduced by a 2021 optimization (`8198907795`) that replaced `delete_ref()` with `delete_refs()` but omitted the old OID for safety-checked deletions. Direct deletions via `git update-ref -d` remain unaffected.

The v5 series restores the pre-regression behavior—passing the resolved old OID to the hook—while preserving the performance gains of the original optimization. It resolves the core design conflict by adopting `REF_TRANSACTION_ALLOW_FAILURE`, which allows partial failures (e.g., when a concurrent update rejects one ref) while maintaining unconditional deletion for `git fetch --prune` and `git remote prune`. The UI now reports "[deleted]" for successful prunes and omits failed refs from dangling symref checks, matching existing behavior. The series includes comprehensive test coverage for both files and reftable backends, SHA-1/SHA-256, broken/symbolic refs, and all affected commands.

Key changes since v4 address a build-breakage issue: patch 1/3 now updates *all* call sites of `refs_delete_refs()` to use the new signature with `NULL` for the optional `string_list` parameter, ensuring the series builds cleanly after each patch. The final tree is identical to v4, preserving the restored hook behavior and granular error reporting. The rebase onto `master` (commit `3bc0341127`) is clean, and the full test suite passes with `DEVELOPER=1`.

This is a well-motivated, technically complete fix for a real-world regression. The patches are low-risk (affecting only error reporting and hook payloads) and maintain backward compatibility. The series has addressed all feedback from Junio and Karthik, including granular error reporting and API consistency, and is a strong candidate for merging. External tooling will benefit immediately from the restored hook behavior.
