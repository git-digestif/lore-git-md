This is a brief follow-up in the `parse-options` early-scanning API thread. Christian Couder acknowledges Junio C Hamano’s skepticism about the practical value of fixing `--` detection in `git bisect` when a term name is `--`. In response, he has **dropped the `git bisect` conversion patches entirely from v2** of the series, focusing the effort on the more compelling `git fast-import` bugfix and the core API refactoring. He notes that the `git bisect` conversion could still happen later if the parse-options API is adopted there, but for now the series is streamlined to address only the most clear-cut use case. This keeps the discussion centered on the API’s design and the `git fast-import` fix, which Junio had previously approved in principle.
