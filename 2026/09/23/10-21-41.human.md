This is a **bugfix** patch (v2) that corrects a regression in `git reflog expire` introduced in Git 2.50. The patch restores the documented default expiry periods: reachable reflog entries now expire after 90 days (instead of the buggy 30-day default), while unreachable entries expire after 30 days (instead of the incorrect 90-day default). The issue was caused by commit `85658275702b`, which reversed the order of `.default_expire_total` and `.default_expire_unreachable` in `REFLOG_EXPIRE_OPTIONS_INIT()`.

The fix itself is minimal—just swapping two lines in `reflog.h`—but the v2 patch significantly improves test coverage. The new test in `t/t1410-reflog.sh` verifies both reachable and unreachable entries, confirming that 60-day-old reachable entries are retained, 100-day-old reachable entries are expired, and unreachable entries older than 30 days are pruned while newer ones remain. This addresses the feedback from Junio and Peff, who requested broader test validation in the initial review.

The patch is uncontroversial and well-motivated, targeting only the misordered defaults without touching other logic or on-disk formats. The regression affects all platforms, as it’s in core Git logic, but does not impact `git gc` unless it invokes `reflog expire` with default settings. The author, Pushkar Singh, credits the original reporter (r.norouzi) and incorporates all prior review feedback, making this version likely ready for merging.

This is a standalone fix unrelated to ongoing efforts like ODB abstraction or `the_repository` removal. The commit message now clearly explains when and how the regression was introduced, satisfying the earlier requests for context. If no further issues are raised, this patch should land quickly.
