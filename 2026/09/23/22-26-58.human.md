This is the first patch in Tamir Duberstein’s v2 series optimizing `git ls-files` to reuse the untracked cache. It fixes a long-standing inconsistency in how ignore-file hashes are computed, which has been causing unnecessary cache invalidation.

The bug is straightforward: `add_patterns()` appends a newline to the buffer *before* hashing it, but that newline isn’t present in the actual file. When Git later reads the same ignore file from the index (bypassing the filesystem), it uses the stored blob ID, which doesn’t include the extra byte. The result is two different object IDs for the same file, forcing the untracked cache to rebuild even when nothing changed. The patch moves the newline append *after* the hash is computed, so both code paths agree on the object ID.

The change is confined to `dir.c` and updates the expected hashes in the existing untracked-cache test (`t/t7063-status-untracked-cache.sh`). No new functionality is introduced; this is purely a correctness fix that paves the way for the later patches in the series. The commit message is clear and the diff is minimal, suggesting a well-scoped, uncontroversial change. If the series as a whole delivers the promised performance gains, this patch will be a necessary first step.
