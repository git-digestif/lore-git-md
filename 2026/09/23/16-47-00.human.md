This is a **CI/build system** review comment on the recently approved patch to work around Debian 12's HTTP/2 authentication failures in Git's CI.

Jeff King (Peff) acknowledges the patch as a good short-term fix for the immediate CI pain but raises two concerns about its long-term robustness. First, the workaround keys off the CI job name (`debian-12`) rather than detecting the actual buggy curl version, so it won’t help developers running the tests locally on Debian 12. Second, it relies on hard-coded test numbers (`t5559.15` and `t5559.16`), which could drift if new setup tests are added earlier in the script. He suggests a more principled approach: have the test script itself check for the buggy curl version, set a prereq (e.g., `!HAVE_CURL_HTTP2_BUG`), and mark the affected tests with that prereq. While he concedes this might require version parsing and could be more work, it would be more maintainable and portable. The review is substantive but not blocking; the patch is already approved and ready for integration.
