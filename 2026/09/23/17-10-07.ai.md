This is a two-patch performance optimization for `git ls-files` that reuses the untracked cache populated by `git status`. The series targets the directory traversal overhead in repeated queries like `` `git ls-files --cached --others --exclude-standard -z -- "**/pyproject.toml"` ``.

The first patch fixes a bug where ignore-file hashes were computed *after* the parser added a trailing linefeed, causing hash mismatches and unnecessary cache invalidation. The fix moves the hash computation before the linefeed is added, ensuring consistent hashes for unchanged ignore files.

The second patch teaches `git ls-files` to reuse the untracked cache. It expands partial scans and collapsed directories on demand but does not write the expanded cache back to the index. The implementation filters the cached listings after the walk, preserving directory pruning for fixed-prefix queries while retaining full traversal for attribute and exclude pathspecs (where matching a directory can differ from matching its children).

Benchmark results on macOS show significant speedups: a synthetic tree with 100,000 tracked files and a few untracked files improved from 361 ms to 50 ms, with directory opens dropping from 5,000+ to single digits. Mixed workloads (50% untracked files) still benefit, improving from 659 ms to 339 ms. The commit message notes that literal queries show no regression, with minor variance in both directions.

The series touches `dir.c` (core directory traversal logic), `builtin/ls-files.c` (the command implementation), and adds performance tests in `t/perf/p3010-ls-files.sh` and regression tests in `t/t7063-status-untracked-cache.sh`. The changes are well-scoped and avoid modifying the on-disk cache format or index state. The motivation is clear: eliminate redundant filesystem walks when the untracked cache is already populated.
