Thread identity: Bug report about HTTP Basic Authentication handling when credentials have an empty username but non-empty password. Originating author: Xavier Morel. Thread type: bug report (single patch expected).

Core problem or goal: Git's HTTP transport layer fails to include the Basic Auth header in follow-up requests after a 401 Unauthorized response when the credential helper supplies an empty username with a non-empty password. This causes authentication to fail despite valid credentials, as `init_curl_http_auth` exits early unless `proactiveAuth=basic` is enabled. The issue affects Git 2.47 and 2.55 with curl 8.5.0, and impacts custom credential helpers or server setups where empty usernames are valid.

Current status: Initial report; no patch yet posted. Under review as a bug report.

Key technical details:
- Files/subsystems: HTTP transport layer, likely `http.c` or related files.
- Behavior: `init_curl_http_auth` exits early if the username is unset/empty, unless `proactiveAuth=basic` is enabled. Basic Auth does not require non-empty usernames or passwords, so the current behavior is incorrect.
- Workarounds: Enable `proactiveAuth=basic` or have the credential helper precompute and return the `credential` field directly.
