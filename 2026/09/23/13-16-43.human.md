This is a **bugfix** for a regression in `git rebase` introduced in Git 2.56.

The patch restores the ability to amend commits after resolving conflicts during an interactive rebase. A recent change (6257588252) made `git commit` refuse to amend when it detects a conflicted rebase state, which was meant to prevent a common footgun—users accidentally amending the wrong commit during conflict resolution. However, the check was overly broad: it persisted even after the conflict was resolved and committed, blocking legitimate amendments.

Patrick’s fix uses the presence of the `MERGE_MSG` file as a proxy to determine whether the conflict has already been committed. The commit message acknowledges this is a somewhat indirect approach but argues it’s the best available given the current rebase state tracking. The patch includes a new test in `t/t3404-rebase-interactive.sh` that verifies the fix works as intended.

The regression is recent (September 1), and Patrick explicitly asks for it to be fixed before the Git 2.56 release. The patch is small, well-explained, and comes with test coverage—it looks like a straightforward candidate for `maint` and `master`.
