This thread is about a three-patch performance optimization series by Tamir Duberstein that lets `git ls-files` reuse the untracked cache populated by `git status`, eliminating redundant directory scans in common workflows. The series is now in its second version after patch 2 was retracted in v1.

The first patch fixes a long-standing inconsistency in ignore-file hash computation that caused spurious cache invalidations. The second patch enables cache sharing between `git status -unormal` (which stops after the first untracked file) and `git status -uall` (which lists all untracked files) by introducing a lazy expansion mechanism and backward-compatibility flag. The third and latest patch teaches `git ls-files` to read from the untracked cache and optionally write updates back to the index, with safeguards for concurrent operations and optional locking.

Benchmarks show significant speedups: a wildcard query like `**/pyproject.toml` on a 100k-file tree runs 7.3× faster (241 ms → 33 ms), and combined `git status` + `git ls-files` time drops from 293 ms to 93 ms. The series is under active review but has no objections or requests for changes yet. It touches `dir.c`, `builtin/ls-files.c`, and `builtin/status.c`, with new tests covering performance, cache reuse, and fsmonitor integration. The changes are backward-compatible and modify no on-disk formats.
