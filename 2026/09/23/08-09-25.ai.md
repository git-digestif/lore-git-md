This is a **revised API refactoring and bugfix series** targeting the `parse-options` subsystem. The v2 series is a **major redesign** of the early argument scanning mechanism introduced in v1, now requiring commands to use the `parse-options` API before adopting the new `early_scan_options()` helper. The series converts only `git fast-import` (fixing a real bug where `--allow-unsafe-features` was silently ignored when preceded by `--depth 5`), dropping the `git bisect` and `git rev-parse` conversions from v1 after Junio questioned their practical value.

Key technical details:
- New `PARSE_OPT_EARLY` flag marks options that should be reported during early scanning.
- `early_scan_options()` now takes a regular `struct option *` array (no separate `early_scan_option` structure), eliminating duplication and ensuring consistency with `parse_options()`.
- The scan always stops at `--` and `--end-of-options`, matching `parse_options()` behavior.
- The implementation deliberately ignores short options, negated forms (`--no-...`), abbreviations, subcommands, and aliases, trading completeness for simplicity and speed.
- New test helper (`test-parse-options --early-scan-options`) exercises the API, with comprehensive tests in `t/t0040-parse-options.sh` covering edge cases (stuck values, optional arguments, non-options).
- The `git fast-import` conversion adds a safety requirement: `--allow-unsafe-features` must be spelled in full (no abbreviations) to allow unsafe stream features.

The series addresses Junio’s v1 feedback by:
- Removing the dedicated `early_scan_option` structure in favor of reusing `struct option`.
- Dropping the `git bisect` and `git rev-parse` conversions, focusing on the most compelling bugfix.
- Adding `PARSE_OPT_EARLY` validation in `parse_options_check()` to reject invalid uses (e.g., on options without long names or subcommands).
- Documenting the API’s limitations in `parse-options.h` and `api-parse-options.adoc`.

The implementation is **clean and well-tested**, with clear commit messages explaining the trade-offs. Junio’s approval of the `git fast-import` conversion in v1 suggests this patch (now 3/3) is ready for `next`, but the broader API design remains under discussion. The series is **worth attention** from maintainers of commands with hand-rolled early scans (e.g., `git bisect`, `git rev-parse`), as it provides a safer alternative once they adopt `parse-options`.
