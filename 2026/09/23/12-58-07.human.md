This is the **final patch in a four-part bugfix series** for `git stash`, addressing a subtle but serious correctness issue in autostashing when `stash.index=true` is set. The patch replaces a fragile subprocess-based index merge (using `git diff-tree` and `git apply`) with an in-core merge via `merge-ort.c`, eliminating a race condition that could corrupt the `MERGE_AUTOSTASH` ref and cause `git stash apply --index` to fail with a SIGSEGV on conflicted index merges.

The change is surgical: it removes 62 lines of subprocess plumbing (three helper functions: `diff_tree_binary`, `apply_cached`, and `reset_head`) and replaces them with 23 lines of in-core merge logic. The new implementation uses fixed ancestor/branch labels (`"Stash base"`, `"Upstream index"`, `"Stashed index changes"`) to satisfy `merge-ort.c`'s requirements, sets verbosity to `0` to avoid overhead, and ensures proper cleanup with `merge_finalize()`. The on-disk format is unchanged, and the behavior is now deterministic—no more filesystem race conditions during autostash operations.

The test added in `t/t7600-merge.sh` verifies the fix by staging a file before a fast-forward merge with `--autostash` and `stash.index=true`, confirming the autostash is applied cleanly and the stash list is empty afterward. This complements earlier test additions in the series that cover conflicted index merges and graceful failure modes.
