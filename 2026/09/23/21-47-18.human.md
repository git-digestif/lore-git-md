This is a procedural update on the `http.sslVerifyStatus` security feature. Junio C Hamano replies to SZEDER Gábor’s test failure report, acknowledging the issues and reverting the patch from `next` to give the author a clean slate for fixing the test infrastructure.

The core functionality of `http.sslVerifyStatus`—enabling OCSP staple validation via libcurl’s `CURLOPT_SSL_VERIFYSTATUS`—remains intact in `master` and is not in question. The revert is purely procedural, triggered by two test problems Gábor identified: (1) the `SSL_VERIFYSTATUS` prerequisite check is too permissive, passing when `git ls-remote` fails for unrelated reasons, and (2) the test’s expectation that a revoked certificate is accepted without `http.sslVerifyStatus` is invalid on systems where libcurl checks CRLs by default. Gábor also noted two minor code-quality nits in the test script.

Junio’s reply is brief and constructive, thanking Gábor for the detailed report and agreeing that the prerequisite logic needs a positive test rather than a negative one. No follow-up patch has been posted yet, but the issues are confined to the test infrastructure and do not affect the feature’s security guarantees or user-facing behavior. The feature is still on track for the next release once the tests are fixed.
