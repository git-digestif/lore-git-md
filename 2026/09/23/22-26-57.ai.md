This is a performance-focused patch series (v2) that teaches `git ls-files` to reuse and update the untracked cache populated by `git status`. The series now consists of three patches, expanding on the original goal of reducing directory traversal overhead in repeated queries.

The first patch remains largely unchanged from v1: it fixes inconsistent ignore-file hashes by computing the hash before appending a parser newline, preventing spurious cache invalidation. The commit message now clarifies that the "fast path" (using an up-to-date index entry's blob ID) and the "fallback" (hashing the buffer) now agree on the object ID, eliminating unnecessary cache rebuilds.

The second patch is new and addresses a limitation in the untracked cache's design: previously, `git status -unormal` (which stops scanning a directory after finding one untracked file) and `git status -uall` (which lists all untracked files) could not share the same cache. This patch lets them reuse the same cache, with later commands completing partial scans as needed. This change required significant refactoring in `dir.c`, including new logic to handle partial directory listings and cache expansion.

The third patch implements the core functionality: `git ls-files` now reuses the untracked cache and writes pending updates back to the index. The `--no-optional-locks` option suppresses these writes, preserving the existing behavior for scripts that cannot tolerate index modifications. The patch also introduces a new `dir_flags` value to ensure older Git versions rebuild the cache before using it, maintaining compatibility. For wildcard pathspecs without a fixed prefix, the implementation reads complete directory listings and applies the pathspec afterward, which can mean scanning more directories than strictly necessary for a single query but pays off in repeated queries.

The revised benchmarks show dramatic improvements: on a synthetic tree with 100,000 files, the "query" (`` `git ls-files --cached --others --exclude-standard -z -- "**/pyproject.toml"` ``) now runs in 33 ms (down from 241 ms upstream and 133 ms in v1). Even when combined with `git status`, the total time drops from 293 ms upstream to 93 ms. The series also benefits from fsmonitor integration, with similar speedups observed when fsmonitor is enabled. The benchmarks use `hyperfine` with warm caches, reflecting real-world usage patterns where `git status` and `git ls-files` are run in sequence.

The series touches `dir.c` (core directory traversal logic), `builtin/ls-files.c` (the command implementation), and updates documentation in `Documentation/git-ls-files.adoc` and `Documentation/gitformat-index.adoc`. It adds new tests in `t/perf/p3010-ls-files.sh`, `t/t3001-ls-files-others-exclude.sh`, `t/t7063-status-untracked-cache.sh`, and `t/t7519-status-fsmonitor.sh`, covering performance, cache sharing, invalidation, and optional index writes. The changes are well-motivated and avoid modifying the on-disk cache format, focusing instead on in-memory optimizations and index updates. The author has addressed the premature benchmark claims from v1 by providing more comprehensive measurements and clarifying the trade-offs.
