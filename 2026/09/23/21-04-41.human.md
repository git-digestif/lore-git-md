This is the second patch in the v5 series fixing the reference-transaction hook regression. It restores the pre-2.31 behavior for `git branch -d` and `git tag -d` by ensuring the hook receives the resolved old OID (instead of all-zeros) when branches or tags are deleted in bulk.

The patch modifies `builtin/branch.c` and `builtin/tag.c` to collect the old OIDs during the initial ref resolution and pass them to `refs_delete_refs()`. This is done by introducing a new `struct tags_to_delete` in `tag.c` (containing both a `string_list` of ref names and an `oid_array` of old OIDs) and extending `delete_branches()` in `branch.c` to use an `oid_array` alongside the existing `string_list`. The changes are mechanical and narrowly scoped: no new ref reads are added, and the race protection (rejecting deletions if the ref changes concurrently) is preserved.

Test coverage is thorough: the new `t/t1416-ref-transaction-hooks.sh` tests verify that the hook receives the correct old OIDs for both branches and tags, and that concurrent updates are properly rejected. The tests cover packed refs (via `git pack-refs --all`) and ensure the hook payloads match the expected format.

This patch is a direct follow-up to the first patch in the series, which updated `refs_delete_refs()` to accept an optional `oid_array` parameter. The build-breakage issue identified in v4 has been fixed in v5 by updating all call sites in patch 1/3, so this patch applies cleanly and the series builds after each step. The changes are low-risk and restore the documented behavior without affecting performance or on-disk format. A well-crafted fix for a long-standing regression.
