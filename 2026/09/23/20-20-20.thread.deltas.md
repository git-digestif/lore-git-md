# Thread deltas

## 2026/09/23

- [2026/09/23/20-20-20 by Guillaume CHAUVEL <guillaume.chauvel@gmail.com>] Guillaume CHAUVEL reported that during a merge of a superproject with submodules, Git v2.56.0-rc2 sometimes attempts to read from submodule A a commit that exists only in submodule B, yielding "error: failed to merge submodule A (repository corrupt)" instead of a submodule conflict; he supplied a reproducer that triggered the bug in all 50 Ubuntu 26.04 runs and 43 of 50 Alpine runs, and noted an AI analysis identifying a likely cause as a stale delta-base cache entry remaining after its pack is closed, where a pack from another submodule reusing the same packed_git address and base offset could return cached data from the wrong repository.

## 2026/09/30

- [2026/09/30/18-31-44 by Philippe Blain <levraiphilippeblain@gmail.com>] Philippe Blain noted that the related commit-graph lookup bug (the first problem in the thread) was fixed in 700f7b74de ("commit-reach: parse commits in the given repository", 2026-09-16), which is in 'next' but not yet in master.
- [2026/09/30/18-31-44 by Philippe Blain <levraiphilippeblain@gmail.com>] Philippe Blain confirmed reproducing the submodule merge failure on v2.56.0-rc2 on RHEL 9; he found that v2.48.1 instead reports a submodule conflict but with a spurious "hash mismatch" message and the wrong conflict reason ("commits not present"), while v2.33.0 gives the correct behavior.
- [2026/09/30/18-31-44 by Philippe Blain <levraiphilippeblain@gmail.com>] Philippe Blain adapted the reproducer into bisection scripts and found that the "repository corrupt" merge failure bisects to bb5da75d61 ("commit: use commit graph in lookup_commit_reference_gently()", 2026-02-16, v2.54.0-rc0~136^2) — the same commit implicated in the commit-graph bug — and CC'ed its author Patrick.
- [2026/09/30/18-31-44 by Philippe Blain <levraiphilippeblain@gmail.com>] Philippe Blain found that the "hash mismatch" behavior bisects to 6f1e9394e2 ("object: fix leaking packfiles when closing object store", 2024-08-08, v2.47.0-rc0~123^2), also authored by Patrick.
- [2026/09/30/18-31-44 by Philippe Blain <levraiphilippeblain@gmail.com>] Philippe Blain observed that disabling commit-graphs via core.commitGraph=false does not change either the "repository corrupt" or the "hash mismatch" behavior; the reproducer does not trigger on v2.56.0-rc2 under Ubuntu 22.02 WSL (but does on v2.55.0 there), and behaves the same in an Ubuntu 22.04 Docker container as on RHEL 9.

## 2026/10/01

- [2026/10/01/14-09-41 by Patrick Steinhardt <ps@pks.im>] Patrick Steinhardt confirmed that the delta-base cache retaining entries after packfiles are closed is the cause of the submodule merge bug, stating that packfiles should be cleared from the delta base cache when closing but currently are not, and said he would investigate further the next day.

## 2026/10/02

- [2026/10/02/08-10-44 by Patrick Steinhardt <ps@pks.im>] Patrick Steinhardt sent patch series <20261002-pks-packfile-stale-delta-base-cache-v1-0-7592a3e31ae0@pks.im> to fix the stale delta-base cache issue that caused submodule merges to try reading submodule B's commit from submodule A.
