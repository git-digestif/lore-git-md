This is the **third and final patch in the v5 bugfix series** addressing the reference-transaction hook regression. It restores the pre-2.31 behavior for `git fetch --prune` and `git remote prune`, ensuring the hook receives the resolved old OID (instead of all-zeros) when remote refs are deleted. The patch also preserves granular error reporting: if a concurrent update rejects one ref, the command still reports "[deleted]" for successful prunes and omits the failed ref from dangling symref checks.

The changes touch `builtin/fetch.c` and `builtin/remote.c`, introducing a new `struct stale_ref` to bundle ref names and old OIDs, and using the `failed_refs` list returned by `refs_delete_refs()` to filter UI output. Three new tests in `t/t1416-ref-transaction-hooks.sh` verify hook payloads for pruned remote refs (files/reftable, SHA-1/SHA-256), UI consistency for partial failures, and rejected-ref handling. The patch is low-risk, narrowly scoped to error reporting and hook payloads, and addresses all prior feedback. It is ready for merging to `next`.
