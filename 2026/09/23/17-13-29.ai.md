This is the second patch in a two-patch CI/build system series addressing resource exhaustion in GitHub Actions CI jobs. The series targets Linux runners where the full test suite—including long-running tests—is enabled for pull requests, leading to out-of-memory (OOM) kills and "no space left on device" (ENOSPC) errors.

This patch dynamically sets the parallelism level (`-j`) for `make` and `prove` to the number of available CPU cores on Linux runners, matching the policy already in place for GitLab CI. The change is a four-line addition to `ci/lib.sh` that sets `JOBS=$(nproc)` when `CI_OS_NAME` is `linux`. The motivation is clear: GitHub Actions currently hardcodes `JOBS=10`, which is too aggressive for private Linux runners with only two CPUs, causing multiple multi-gigabyte clone and repack fixtures to overlap and exhaust disk space.

The patch is minimal, well-motivated, and aligns with existing practice in GitLab CI. It preserves the long-running test coverage rather than disabling it, which is a pragmatic choice for CI reliability. The commit message succinctly explains the problem (ENOSPC during concurrent large fixtures) and the solution (dynamic parallelism). No new symbols, options, or on-disk formats are introduced, and the change is confined to the CI infrastructure.

This patch, combined with the first one (which reduces memory pressure in `t4205-log-pretty-formats.sh`), forms a targeted fix for a real CI bottleneck. The series has not yet received reviews, but the technical rationale is straightforward and the implementation is clean. If the goal is to keep the full test suite enabled on GitHub Actions without resource exhaustion, this looks like a sensible adjustment.
