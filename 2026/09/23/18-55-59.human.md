This is a **user-experience bugfix** targeting the rev-parse and object-name subsystem. The v3 patch narrows the scope to the uncontroversial part of the original proposal: when a user in a shallow clone tries to access an ancestor that isn’t present locally via `<rev>~N` or `<rev>^N` syntax, Git now prints a clear, actionable hint explaining why the command failed and exactly how to fetch more history.

The patch adds a new advice (`advice.shallowHistory`) that fires only when the walk stops *exactly* at a recorded shallow boundary, not just because the repo happens to be shallow elsewhere. The suggested `git fetch --deepen=<n>` command is context-aware: for `<rev>~N` it calculates the exact `--deepen` value needed (accounting for history already present), and for `<rev>^N` it always suggests `--deepen=1` because a shallow boundary commit has no parents recorded locally. Remote and branch names are auto-detected via `remote_find_tracking` instead of assuming a `refs/remotes/<remote>/<branch>` layout, making the advice work even with custom refspecs.

The implementation is careful to avoid false positives and double-printing. The advice is suppressed during internal re-resolution (via `GET_OID_QUIETLY`) and in non-shallow repos. A bug in chained `<rev>^^^` lookups that caused the hint to print twice has been fixed by threading the quiet flag through the inner lookup. Test coverage is thorough, with 14 new cases verifying the advice appears (or doesn’t) in all expected scenarios, including merge parents, partial depths, disabled advice, and non-shallow repos.

The commit message and documentation now consistently use `<rev>` instead of `<ref>` to match `gitrevisions(7)` syntax, addressing a nit from earlier reviews. The patch drops the problematic `git log -<n>` integration entirely, as Junio’s review identified a fundamental flaw in the detection logic for silent truncation. This leaves the `<rev>~N`/`<rev>^N` advice as a clean, well-tested improvement that directly addresses a real usability pain point. The implementation looks solid, the rationale is clear, and the test coverage is comprehensive.
