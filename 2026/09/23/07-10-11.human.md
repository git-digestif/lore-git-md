This is a bugfix targeting the HTTP transport layer. The author, Xavier Morel, reports that when a Git operation triggers HTTP authentication (401 response) and the credential helper provides an empty username with a non-empty password, Git fails to send Basic Auth credentials on the second request. The issue is traced to `init_curl_http_auth`, which exits early if the username is unset or empty unless `proactiveAuth=basic` is enabled. The workaround is to either enable proactive auth or have the credential helper return a precomputed `credential` field instead of separate username/password. The bug affects Git 2.47 and 2.55 with curl 8.5.0, and the behavior is surprising because Basic Auth does not technically require non-empty usernames or passwords. The patch is likely small and focused on the HTTP auth initialization logic.
