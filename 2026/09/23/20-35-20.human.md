This is a feature patch that implements the consensus design from the thread: a new special fetch refspec `+:` that dynamically fetches only the branches tracked by local branches, plus the remote’s default branch. The patch makes `git remote add` default to this refspec (instead of the usual wildcard `+refs/heads/*:refs/remotes/<name>/*`) when the repository is shallow, avoiding the performance problem of negotiating history for every remote branch on the next plain fetch.

The implementation is clean and well-scoped. It touches `builtin/fetch.c` to add the new refspec logic, `builtin/remote.c` to change the default refspec for shallow repositories, and adds thorough test coverage in a new file `t/t5585-fetch-tracking-refspec.sh`. The tests verify that the feature works as intended: it fetches only the tracked branches plus the default branch, updates `refs/remotes/<name>/HEAD` correctly, and has no effect on non-shallow repositories. The documentation in `Documentation/git-remote.adoc` and `Documentation/pull-fetch-param.adoc` is clear and complete.

This patch directly addresses the root cause identified in the thread (wildcard refspecs in shallow repositories causing slow fetches) and does so in a way that is backward-compatible and opt-out rather than opt-in. The design is now consensus-driven, and the implementation looks solid, with good test coverage and clear documentation. This is a well-crafted contribution that should be worth the attention of anyone interested in shallow repository performance or fetch behavior.
