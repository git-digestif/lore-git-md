This is a **CI/build system** review of the Debian 12 HTTP/2 authentication workaround patch. Jeff King (Peff) replies to Johannes Schindelin’s patch with a **substantive review** that identifies two limitations of the current approach and suggests a more robust alternative.

Peff acknowledges the diagnosis and fix as sound but notes that the workaround—skipping `t5559.15` and `t5559.16` based on the `debian-12` CI job name—has two downsides. First, it only helps CI, not developers running the tests locally on Debian 12. Second, it relies on hard-coded test numbers, which could silently break if new tests are added earlier in the script (or in `t5551`, which `t5559` is based on). He proposes a more principled solution: have the test script itself detect the buggy curl version, set a prereq (e.g., `!HAVE_CURL_HTTP2_BUG`), and mark the affected tests with that prereq. This would work both in CI and locally, and would not depend on test numbering.

The review is constructive and technically grounded, but Peff does not insist on the alternative—he notes the version-checking logic might not be worth the effort. The thread remains open for discussion on whether to refine the workaround or accept it as-is.
