This is the third and final patch in Tamir Duberstein’s v2 series optimizing `git ls-files` to reuse the untracked cache populated by `git status`. It implements the core functionality: `git ls-files` now reads from the untracked cache and, when optional locking is enabled, writes pending updates back to the index so later commands can benefit.

The patch modifies `builtin/ls-files.c` to parse options early, take an optional index lock, and conditionally write the index after a complete traversal. It avoids writing the index when a pathspec prefix or `--with-tree` is used, when `--no-optional-locks` is given, or when the lock is busy. The implementation records the object IDs of standard exclude files before assigning `dir->untracked`, ensuring exclude options are processed in the same order as before reading the index. New tests in `t/perf/p3010-ls-files.sh`, `t/t3001-ls-files-others-exclude.sh`, `t/t7063-status-untracked-cache.sh`, and `t/t7519-status-fsmonitor.sh` verify performance gains, cache reuse after `git status -unormal`, respect for optional locks, and fsmonitor token preservation with `index.skipHash`.

The changes are well-scoped and maintain backward compatibility; older Git versions will rebuild the cache before use. The patch is part of a self-contained performance optimization that touches only in-memory data structures and index updates, with no on-disk format changes.
