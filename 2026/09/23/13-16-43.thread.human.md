This thread is about a regression fix in Git 2.56-rc0's interactive rebase functionality. Patrick Steinhardt identified that a recent safety check in `git commit --amend` was incorrectly blocking legitimate amendments after conflict resolution during rebases. The overly restrictive behavior was introduced by commit 6257588252, which aimed to prevent users from accidentally amending the wrong commit during conflicts but failed to account for the post-resolution case.

The fix is a targeted change to `sequencer.c` that uses the presence of the `MERGE_MSG` file as a signal that conflict resolution has already been committed, allowing amendments to proceed. While Patrick acknowledges this approach is somewhat indirect ("fishy"), he couldn't find a better solution and included a new test in `t/t3404-rebase-interactive.sh` to protect against regression. The patch is well-motivated for the upcoming 2.56 release, though the mailing list may yet discuss alternative implementations given Patrick's expressed dissatisfaction with the current solution.
