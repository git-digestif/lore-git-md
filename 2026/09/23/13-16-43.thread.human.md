This thread is about a regression in `git commit --amend` during interactive rebase, introduced in Git 2.56-rc0. The issue stems from an overzealous safety check in `sequencer.c` that prevents amending commits after conflict resolution, breaking established workflows. The maintainer (Junio C Hamano) and key reviewers (Elijah Newren, Patrick Steinhardt) have agreed to revert the regressing commit entirely for the 2.56 release cycle, prioritizing stability over partial fixes. The revert is not yet coded or merged.

The broader architectural question—whether plain `git commit` should be rejected during conflict resolution for sequencer-based commands—remains open but deferred until after Git 2.56. A future direction has emerged: extending `git commit` to consume a new pseudoref (`REBASE_HEAD`) to preserve authorship information, though no code has been posted yet. Johannes Sixt’s recent email flags a minor localization concern (reintroducing a translatable error message) but doesn’t affect the technical decision. The only immediate action is the revert, which is expected to land as -rc2 material.
