This is the fourth patch in the v7 series adding path-related keys to `` `git repo info` ``. It introduces ``path.hooks.absolute`` and ``path.hooks.relative``, which expose the repository’s hooks directory in a scriptable format, respecting the ``core.hooksPath`` configuration.

The implementation uses ``repo_git_path_replace()`` to determine the hooks path, then formats it as either an absolute or relative path using the existing ``format_path()`` helper. The patch documents that when ``core.hooksPath`` is set to ``/dev/null``, the keys return that value verbatim, and the test suite explicitly covers this edge case (skipped on Windows, where ``/dev/null`` is not a canonical filesystem path). Tests also verify standard hooks paths and custom ``core.hooksPath`` overrides.

The patch is clean, well-tested, and uncontroversial. It follows the established pattern of the series: each key is implemented as a pair of getter functions, documented in ``git-repo.adoc``, and tested in ``t/t1900-repo-info.sh``. The commit message clearly explains the motivation—replacing ad-hoc invocations of ``git rev-parse --git-path hooks`` with a consistent, scriptable interface—and the code aligns with the series’ design principle of returning paths unconditionally, even when the directory does not exist. No substantive review issues remain for this patch.
