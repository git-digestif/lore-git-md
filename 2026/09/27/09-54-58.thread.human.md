This thread is about a small but important documentation fix for `git name-rev`. The man page currently describes the `--annotate-stdin` and `--name-only` options using outdated references to "40-character SHA-1 hexes" and "SHA-1", even though the code has been hash-algorithm-agnostic since 2023. Jyotish Kumar, the author, proposes updating the wording to use generic terms like "object ID" to match the implementation's support for both SHA-1 and SHA-256.

The change is uncontroversial in principle—it’s a straightforward cleanup that aligns with Git’s broader effort to support multiple hash algorithms. The patch would only touch `Documentation/git-name-rev.txt`, and the author has offered to prepare it if the maintainers agree the change is appropriate. So far, there’s been no discussion or feedback, so the next step is likely a review of the proposed wording or a request for the author to submit the patch. This appears to be Jyotish’s first contribution to this part of the documentation.
