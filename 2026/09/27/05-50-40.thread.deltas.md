- [2026/09/27/05-50-40 by Matthias Goergens <matthias.goergens@gmail.com>] Matthias Goergens submitted a documentation patch clarifying that `git remote set-head <name> <branch>` does not change the remote repository's own `HEAD` (the branch a fresh `git clone` checks out); the patch adds wording to `Documentation/git-remote.adoc` stating that every change the command makes is local and that Git provides no client-side way to change a remote's own default branch.

## 2026/09/29

- [2026/09/29/12-00-10 by Matthias Goergens <matthias.goergens@gmail.com>] Matthias Goergens posted [PATCH v2] "doc: remote: say that it only affects the local repository", adding a paragraph near the top of the DESCRIPTION in Documentation/git-remote.adoc stating that `git remote` changes only the local repository (its configuration and refs) and never modifies a remote repository, while noting that some subcommands such as `show`, `prune`, `update` and `set-head --auto` contact a remote repository to read from it.
