This is the fifth patch in the v7 series adding path-related keys to `git repo info`. It introduces `path.index.absolute` and `path.index.relative`, exposing the repository’s index file location in a scriptable format. The implementation uses `repo_get_index_file(repo)` to respect the `GIT_INDEX_FILE` environment override and returns the configured path even in bare repositories or when the file does not exist, aligning with `git rev-parse --git-path index` behavior.

The patch touches `builtin/repo.c` (adding two new getter functions, `get_path_index_absolute` and `get_path_index_relative`), `Documentation/git-repo.adoc` (documenting the new keys), and `t/t1900-repo-info.sh` (adding tests for standard index paths, `GIT_INDEX_FILE` overrides, and bare-repository edge cases). The tests confirm that the keys return the expected paths in all scenarios, including when `GIT_INDEX_FILE` is set to a custom location or when the repository is bare.

A latent correctness issue remains: `repo_get_index_file(repo)` invokes `BUG("")` if the repository is not ready to return the index file path, though the dead code that previously followed this call has been removed. The author opted to retain the existing implementation despite Junio’s suggestion to replace it with direct access to `repo->index_file` and a null check. This decision may still draw scrutiny during substantive review, but the patch is otherwise mechanically clean and well-tested.

The patch is uncontroversial in its design, as the unconditional path-return behavior was explicitly endorsed by Junio in earlier iterations. The documentation clearly states that the keys return the configured path regardless of whether the file exists or the repository is bare, which matches the precedent set by `git rev-parse --git-path`. The test coverage is thorough, including edge cases like bare repositories and environment overrides, and the implementation is straightforward.

This patch is ready for substantive technical review, though reviewers may focus on the `BUG()` invocation in `repo_get_index_file(repo)` as a potential point of concern. The rest of the implementation and testing appears solid and aligns with the series’ overall goals.
