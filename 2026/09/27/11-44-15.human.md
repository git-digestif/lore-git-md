This is the third patch in the v7 series adding path-related keys to `git repo info`. It introduces `path.superproject-root.absolute` and `path.superproject-root.relative`, which expose the working tree root of the superproject when the current repository is an initialized submodule. The implementation builds on the fixed `get_superproject_working_tree()` function from patch 2/8, which now correctly respects the repository parameter and uses the repository’s working directory instead of `xgetcwd()`.

The patch is straightforward: it adds two new getter functions (`get_path_superproject_absolute` and `get_path_superproject_relative`) that call `get_superproject_working_tree()`, format the result using `format_path()`, and return an empty string if not in a submodule. The documentation updates the `git-repo.adoc` man page with clear descriptions of both keys, and the tests cover both submodule and non-submodule contexts, including the expected empty-string behavior when not in a submodule.

This patch is uncontroversial and mechanically clean. The correctness fix in patch 2/8 ensures the underlying function works as intended, and the tests in `t/t1900-repo-info.sh` verify the new keys behave correctly in both absolute and relative modes. The only remaining loose end is the broader architectural question about deduplicating shared logic between `git repo info` and `git rev-parse`, but that is deferred to a follow-up series and does not affect this patch’s correctness. The patch is ready for substantive review and unlikely to draw significant pushback.
