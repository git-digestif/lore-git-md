Series version: standalone patch (v1)
Originating author: Jyotish Kumar
Thread type: documentation patch

Core problem or goal
The `git name-rev` man page still describes the `--annotate-stdin` and `--name-only` options in terms of "40-character SHA-1 hexes" and "SHA-1", respectively, while the actual implementation has been hash-algorithm-agnostic since commit 1c4675dc57 ("builtin/name-rev: make hash-size independent", 2023). The goal is to replace these hard-coded SHA-1 references with generic language such as "object ID" or "full-length object ID" to accurately reflect the code's support for both SHA-1 and SHA-256.

Current status
Patch v1 posted. The patch updates the man page wording as proposed; brian m. carlson has already endorsed the principle of the change, so the patch is uncontroversial and ready for review. No merge status has been reported by Junio.
