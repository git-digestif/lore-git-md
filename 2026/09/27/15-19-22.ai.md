This is a **CI/build system** patch in an ongoing thread about improving leak sanitizer failure reporting in GitHub Actions. The thread has shifted from a straightforward quality-of-life improvement to a more nuanced discussion about trade-offs between usability and completeness.

Phillip Wood's review raises two substantive concerns. First, he questions whether stopping the test script at the first leak failure (`--immediate` flag) is the right choice: it makes debugging easier for the first leak, but hides subsequent leaks in the same run. This is a classic tension between early failure (which simplifies triage) and comprehensive reporting (which catches all issues at once). Second, he reports a usability regression in the GitHub Actions UI: the new output format causes strange scrolling behavior in Firefox, where the page jumps to the bottom and resists manual scrolling. This suggests the patch may have unintended side effects on the CI experience beyond its intended scope.

The patch itself is more complex than initially described. While the original summary framed it as a simple annotation improvement, Phillip points out it also introduces new escaping logic and changes how annotations are generated. The lack of explanation for these changes in the commit message makes the patch harder to review, as reviewers must reverse-engineer the rationale from the diff. The escaping function (`github_escape_message_`) and line-finding logic (`find_test_case_line_`) appear to be plumbing for the new annotation format, but their necessity isn't justified in the patch.

No other participants have weighed in on these concerns, and Harald Nordgren hasn't yet responded to Phillip's feedback. The thread is now at a decision point: whether to prioritize immediate failure (current approach) or find a way to report all leaks while still providing useful annotations. The scrolling issue adds urgency, as it risks degrading the CI experience for other failures beyond leak sanitizer tests.
