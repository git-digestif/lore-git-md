This is a documentation patch that clarifies the behavior of `git remote set-head`. The current man page wording ("Set or delete the default branch... for the named remote") has been misinterpreted as changing the remote repository's own `HEAD`—the branch a fresh `git clone` would check out. The patch makes it explicit that `set-head` only affects the local repository and that Git offers no client-side mechanism to modify a remote's default branch.

The change is small but well-motivated: the author cites a real-world misreading on another project's mailing list, where the confusion persisted until testing disproved it. The commit message is clear and includes a link to the discussion for context. While the patch doesn't propose new functionality, it helpfully points out that remote `HEAD` modification depends on the hosting setup (e.g., gitolite's `symbolic-ref` command on kernel.org) and hints at a possible future feature (a push option for client-side changes).

The patch touches only `Documentation/git-remote.adoc` and adds six lines of explanation. It’s a straightforward improvement that should prevent similar misunderstandings without introducing controversy. Worth a quick review for anyone who’s ever been confused about `set-head`.
