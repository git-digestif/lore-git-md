This is the second patch in the v7 series adding path-related keys to `git repo info`. It fixes a **substantive correctness bug** in the `get_superproject_working_tree()` function, which previously used `xgetcwd()` to determine the repository whose superproject should be checked. This was incorrect when `--git-dir` pointed to a repository different from the one associated with the current working directory, potentially returning the wrong superproject or an empty result.

The patch updates `get_superproject_working_tree()` to accept a `struct repository *` parameter and use the repository’s working directory (via `repo_get_work_tree()`) instead of the current working directory. This ensures the function respects the repository being inspected, not the shell’s working directory. The change touches `submodule.c` (implementation), `submodule.h` (function signature), `builtin/rev-parse.c` (updated caller), and adds a new test in `t/t7400-submodule-basic.sh` to verify the fix works with `--git-dir`.

The fix is **mechanically clean and well-tested**, addressing Junio’s high-weight concern from v6. The test covers the edge case where `--git-dir` points to a submodule’s `.git/modules/<name>` directory, confirming the function now correctly returns the superproject’s root. The commit message clearly explains the problem and solution, and the code changes are minimal and focused. This patch is **ready for substantive review** and unlikely to be controversial, though reviewers may check for other callers of `get_superproject_working_tree()` that might need similar updates. The fix is a prerequisite for the next patch (3/8), which introduces the `path.superproject-root` keys.
