This thread is a small but useful documentation cleanup. Matthias Goergens proposed a patch to clarify that `git remote set-head` only affects the local view of a remote's default branch, not the remote repository itself. The current wording has led users to mistakenly believe Git can modify a remote's `HEAD` ref, which it cannot.

Junio C Hamano reviewed the patch and agreed the clarification is needed, but suggested a broader approach: adding a general note at the top of the `git-remote` man page stating that *all* `git remote` commands operate locally. This would eliminate the need for per-command clarifications and cover other commands like `remote prune` that might also be misunderstood. The discussion is still open, with no revised patch posted yet, but the goal remains the same—preventing user confusion about Git's local-only remote management. No code or test changes are involved; this is purely about improving the man page wording.
