This thread is about a small but important documentation fix to the `git remote` man page. The patch, now in its second version, adds a general statement at the top of the page to clarify that `git remote` commands only affect the *local* view of remotes, not the remote repositories themselves. This addresses a common source of user confusion, where the current wording has been misread as implying remote-side changes—which Git does not support.

The author, Matthias Goergens, initially proposed a targeted clarification for the `set-head` subcommand but revised the patch after Junio C Hamano suggested a broader approach: a single, upfront statement in the DESCRIPTION section. Junio has now explicitly approved the v2 wording, calling it clear and sufficient. The patch is uncontroversial, touches only the documentation file (`Documentation/git-remote.adoc`), and makes no changes to code, behavior, or on-disk formats. No substantive objections remain, and the thread has effectively converged on this version.

With Junio’s approval, the patch is now ready for merging. Any further discussion is likely to focus on minor wording tweaks rather than the core approach. This is a straightforward fix that should land soon.
