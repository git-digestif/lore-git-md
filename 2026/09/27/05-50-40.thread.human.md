This thread is about a documentation patch to clarify that `git remote` commands operate only on the local repository, not the remote. The original patch by Matthias Goergens targeted a specific misconception about `set-head`, but after discussion with Junio C Hamano, it evolved into a broader change: adding a general statement at the top of the `git-remote` man page to cover all subcommands.

The revised patch (v2) has now been posted. It inserts a concise five-line clarification in the DESCRIPTION section, explicitly stating that `git remote` affects only local configuration and refs, and that subcommands contact the remote only to read from it. The change is purely additive and uncontroversial, addressing a documented source of user confusion without altering any code or behavior. No technical objections have been raised, and the discussion has focused solely on wording effectiveness. The patch is small, well-motivated, and likely to be merged after any final tweaks.
