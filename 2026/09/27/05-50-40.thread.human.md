This thread is about a small but important documentation fix for `git remote set-head`. Matthias Goergens noticed that the current man page wording could mislead users into thinking the command changes the remote repository's default branch, when in fact it only updates the local view of that branch. The patch adds a clear disclaimer: Git has no client-side way to modify a remote's `HEAD`, and `set-head` is purely a local operation.

The change is straightforward—just six lines added to the `git-remote` man page—and is well justified by a real-world example from the Linux kernel community where this confusion came up. No code is touched, and the patch is uncontroversial. It’s the kind of targeted improvement that should land quickly once it gets a quick sanity-check review.
