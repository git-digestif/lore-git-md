This is a bugfix for the `contrib/credential/libsecret` credential helper, addressing a crash and silent data loss issue in the GNOME keyring backend. The v2 patch from Daniel Martí refines the commit message and implementation to address feedback from Junio C Hamano, making the rationale and design choices clearer without relying on prior discussion.

The patch removes the `SECRET_SEARCH_LOAD_SECRETS` flag from the `secret_service_search_sync()` call and instead explicitly loads the secret for the matched item using `secret_item_load_secret_sync()`. This change ensures that errors—such as locked or concurrently deleted items—are properly reported rather than silently discarded, preventing assertion failures in `secret_value_get_text()` and `secret_value_unref()`. The fix maintains the same number of D-Bus round-trips as before (one SearchItems call plus one GetSecret per item) while eliminating the race condition that caused data loss.

The updated commit message now explicitly explains why the `SECRET_SEARCH_LOAD_SECRETS` flag is problematic: it skips locked items and ignores load failures, leaving secrets as NULL, which the GNOME keyring daemon silently omits from its reply. The patch ensures that genuinely inaccessible items produce a useful error message, while still allowing Git to fall back to password prompting. The code change is minimal, touching only `contrib/credential/libsecret/git-credential-libsecret.c` with 13 additions and 1 deletion.

This version resolves the main blocker from the v1 review—clarity of the commit message—by making the design trade-off explicit: the patch prioritizes simplicity and reliability over preserving the batch-fetch optimization, which was Junio’s alternative proposal. The discussion confirmed that libsecret’s behavior is intentional, meaning Git must handle NULL secrets regardless of the flag. No test coverage is included, as the race condition requires concurrent credential operations or a locked keyring to trigger, but the fix is well-motivated and self-contained.

The patch is ready for further review, with the unresolved design question being whether to retain the flag for its perceived optimization benefits (Junio’s preference) or drop it entirely (Martí’s approach). The v2 strengthens the case for the latter by aligning with libsecret’s own `secret-tool` utility and ensuring all errors are surfaced.
