This is the second patch in the v7 series adding new path-related keys to `git repo info`. It fixes a correctness bug in the `get_superproject_working_tree()` function, which previously used `xgetcwd()` to determine the repository whose superproject should be checked. This was incorrect when `--git-dir` pointed to a repository different from the current working directory, potentially returning the wrong superproject or an empty result.

The patch updates `get_superproject_working_tree()` to accept a `struct repository *` parameter, allowing it to determine the superproject from the repository being inspected rather than the current working directory. The function now uses `repo_get_work_tree(r)` to get the repository’s working tree path and constructs the parent directory path from there. The change ensures that `git repo info path.superproject-root` and `git rev-parse --show-superproject-working-tree` behave consistently, even when invoked with `--git-dir`.

The patch touches `submodule.c` (the core fix), `submodule.h` (updated function signature), `builtin/rev-parse.c` (updated caller), and adds a new test in `t/t7400-submodule-basic.sh` to verify the fix works with `--git-dir`. The test creates a superproject and submodule, then checks that `git --git-dir=<submodule-git-dir> repo info path.superproject-root.absolute` returns the correct superproject root path.
