This is the fourth patch in the v7 series adding path-related keys to `git repo info`. It introduces `path.hooks.absolute` and `path.hooks.relative`, exposing the repository’s hooks directory in a scriptable format that respects `core.hooksPath` configuration. The implementation uses `repo_git_path_replace()` to resolve the hooks path, supporting both standard `.git/hooks` locations and custom overrides, including the `/dev/null` edge case (documented and tested, with Windows skipped due to path canonicalization differences).

The patch is clean and well-tested, covering standard hooks paths, custom `core.hooksPath` overrides, and the `/dev/null` special case. The documentation clearly states that `/dev/null` is returned verbatim when configured, aligning with `git rev-parse --git-path hooks` behavior. The test helper `test_repo_info_path` is updated to handle absolute paths (e.g., `/dev/null`) correctly, avoiding the need for `real_path` canonicalization in those cases. No substantive issues remain; this patch is ready for review and unlikely to be controversial.
