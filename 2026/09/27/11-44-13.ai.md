This is the first patch in the v7 series adding path-related keys to `git repo info`. It introduces `path.toplevel.absolute` and `path.toplevel.relative`, which expose the top-level working tree directory in absolute and relative formats, respectively. The implementation uses `repo_get_work_tree()` and `format_path()` to ensure consistent behavior, returning an empty string in bare repositories where no working tree exists. The patch touches `builtin/repo.c` (implementation), `Documentation/git-repo.adoc` (documentation), and `t/t1900-repo-info.sh` (tests), adding thorough test coverage for both subdirectory execution and bare-repository edge cases.

The patch is mechanically clean and aligns with the series' design principles: it avoids exposing Git internals directly, supports suffix-based formatting, and returns empty strings for inapplicable contexts (bare repositories). The tests confirm the output matches `test-tool path-utils real_path` and expected relative paths (e.g., `../` from a subdirectory). This patch is uncontroversial and ready for substantive review, though it is part of the larger effort to expose repository component paths in a scriptable format. The remaining patches in the series build on this foundation to add keys for hooks, index, grafts, superproject root, and relative path navigation (`path.git-prefix` and `path.cdup`).
