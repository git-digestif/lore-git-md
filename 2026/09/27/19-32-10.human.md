This is Junio’s reply in the ongoing Git version numbering thread, specifically addressing Phillip Wood’s proposal to adopt a consequentialist approach for changing default config values and to introduce a `core.defaults` meta-config variable. Junio engages with both ideas but remains skeptical about their practicality and necessity.

Junio acknowledges that Git already takes a consequentialist approach to some degree—citing the example of changing the default merge strategy multiple times—but he frames the challenge as one of measurement. He argues that "net benefit" and "potential downside" are speculative until a change is released and observed in the wild, and that waiting months for feedback from distributions complicates the process. His tone suggests that while the idea is theoretically sound, the project lacks the data or mechanisms to reliably assess the impact of default changes before they are made.

On the `core.defaults` proposal, Junio raises a practical objection: if the goal is to measure how many users would benefit from a default change, it would be simpler to directly poll the target configuration (e.g., `diff.algorithm`) rather than introducing a new meta-variable. He suggests that the number of users who explicitly set a value for a config variable could serve as a rough proxy for how many would prefer it as the default. This implies that `core.defaults` might add unnecessary complexity without solving the core problem of assessing user preferences.

The reply does not outright reject Phillip’s ideas but instead highlights the difficulty of implementing them in a way that provides actionable data. Junio’s focus on measurement and real-world feedback reflects his pragmatic, evidence-based approach to project governance. The exchange leaves open the question of whether the project could develop better mechanisms for evaluating default changes in the future, but for now, Junio’s skepticism suggests that neither the consequentialist approach nor `core.defaults` are likely to gain traction without further refinement or proof of concept. This is a substantive review of Phillip’s proposal, though it stops short of offering alternatives or next steps.
