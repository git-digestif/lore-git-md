This is a CI/build system patch that improves leak sanitizer failure reporting in GitHub Actions, but the discussion now surfaces a usability trade-off.

Phillip Wood raises two practical concerns about Harald Nordgren’s patch. First, by stopping the test script at the first leak failure (via `--immediate`), the patch will report only the first leak in a given test run, potentially hiding additional leaks that would have been caught later. Second, he reports strange scrolling behavior in Firefox when viewing the GitHub Actions log: the page jumps to the bottom of the test output and resists manual scrolling, making it harder to inspect earlier parts of the log.

The patch itself also introduces more changes than the commit message initially suggested. It adds escaping for GitHub Actions annotations, changes how annotations are formatted, and modifies the output grouping. Phillip notes that these changes lack explanation in the commit message, making it harder for reviewers to assess their necessity or correctness.

Harald has not yet responded to these points, so the trade-off between immediate failure (which simplifies debugging for the first leak) and continued execution (which might reveal multiple leaks) remains unresolved. The scrolling issue, if confirmed, could be a regression in usability even if the annotations themselves are improved. This thread is now at a decision point: whether to proceed with the current approach, adjust it to report multiple leaks, or investigate the scrolling behavior before finalizing the change.
