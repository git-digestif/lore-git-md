This is the eighth and final patch in the v7 series adding path-related keys to `git repo info`. It introduces the `path.cdup` key, which exposes the relative path from the current working directory to the repository’s top-level working tree—functionality previously only available via `git rev-parse --show-cdup`. The implementation is straightforward: it checks whether the current directory is inside the working tree (using `is_inside_work_tree(repo)`) and, if not, returns the absolute path to the working tree root via `repo_get_work_tree(repo)`. When inside the working tree, it constructs the relative path by counting slashes in the repository’s `prefix` field and appending `../` for each level. The patch includes thorough test coverage for three scenarios: invocation from the repository root (returns an empty string), invocation from a subdirectory (returns `../../`), and invocation from outside the working tree (returns the absolute path to the working tree root, respecting `GIT_WORK_TREE`).

The patch directly addresses the last open design question from earlier iterations—Junio’s insistence on symmetry with `git rev-parse --show-cdup`—and resolves the edge-case discrepancy he identified in v6. The implementation now matches `git rev-parse` behavior exactly, including the outside-working-tree case, which was the source of the earlier disagreement. The commit message is clear and concise, and the tests are well-structured, covering both standard and edge cases. This patch is uncontroversial and ready for substantive review; the only remaining question for the series as a whole is whether the two-phase refactoring plan (merge v7 as-is, then extract shared logic into `repo-info.c`) will be accepted.
