The patch addresses a memory leak in `git history reword` by ensuring `repo_unuse_commit_buffer()` is called after `repo_logmsg_reencode()`, matching the documented pairing requirement. The leak occurs intermittently—only when the commit buffer is dynamically allocated (e.g., from commit-graph parsing or reencoding) rather than cached in Git’s commit slab.

The v4 iteration makes no functional changes; it replaces the commit message with a more concise version suggested by Jeff King (Peff), which better clarifies the leak’s root cause (unpaired buffer allocation) and its intermittent nature (triggered by commit-graph or reencoding). The fix itself—a single line addition in `builtin/history.c` (`commit_tree_ext`)—remains identical to v3. The patch is narrowly scoped, well-tested (resolving `t3451-history-reword.sh` failures under `GIT_TEST_COMMIT_GRAPH=1`), and already integrated into `master`.

Key technical details include the leak’s dependency on commit-graph parsing (which bypasses raw object reads and thus slab caching), the reproduction recipe (`SANITIZE=leak GIT_TEST_COMMIT_GRAPH=1`), and the affected functions (`repo_logmsg_reencode`, `repo_unuse_commit_buffer`).
