This is a brief follow-up in the "What's cooking" thread about the `ks/history-commit-leakfix` topic. The patch fixes a memory leak in `git history` by unusing the commit buffer after it is no longer needed. The fix is straightforward: it adds a `free_commit_buffer()` call in the `show_commit()` function to release the buffer after the commit is processed.

The patch has been reviewed by Jeff King (Peff), who approved the code and suggested a more concise commit message. Kaartic Sivaraam sent a v4 incorporating Peff’s feedback, which Junio can now pick up. The change is uncontroversial and aligns with Git’s memory management practices, so it is likely to graduate to `next` soon. No further discussion or objections are evident in the thread. The patch touches only `builtin/history.c` and is part of the ongoing stabilization of the experimental `git history` command.
