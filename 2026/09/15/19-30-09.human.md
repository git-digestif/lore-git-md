This is a bugfix patch targeting the `upload-pack` subsystem, specifically the Git protocol v2 implementation. The patch corrects a response-ordering issue in `upload_pack_v2` when handling shallow fetches with `uploadpack.allowRefInWant=true`.

The problem occurs when a client performs a shallow clone or incremental shallow fetch using protocol v2. The server was sending wanted-ref information *before* shallow-info, which violates the protocol's expected order. The fix is a one-line swap in `upload-pack.c`: `send_shallow_info` now runs before `send_wanted_ref_info`. The patch includes two new tests in `t/t5703-upload-pack-ref-in-want.sh` that verify both shallow clone and incremental shallow fetch work correctly with ref-in-want enabled.
