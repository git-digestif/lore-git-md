This is a resend of a bugfix patch that was already merged to `master`. The patch plugs a memory leak in `git history reword` by ensuring that every call to `repo_logmsg_reencode()` is paired with `repo_unuse_commit_buffer()`. The leak occurs intermittently—only when the commit buffer is dynamically allocated (e.g., from commit-graph loading or reencoding) rather than cached in Git’s commit slab.

The v4 iteration makes no functional changes to the code; it simply adopts Jeff King’s suggested commit message, which is more concise and clearly explains the leak’s root cause and intermittency. The fix itself remains a one-line addition in `builtin/history.c` (`commit_tree_ext`). The reproduction recipe (`SANITIZE=leak GIT_TEST_COMMIT_GRAPH=1`) and confirmation that the fix resolves related test failures (`t3451-history-reword.sh`) are preserved.

This patch is part of a broader thread addressing memory leaks in Git’s slab management, particularly those exposed by commit-graph interactions. The original fix for `git history reword` was merged earlier, and this resend is purely stylistic—no further review or action is needed. The thread has since moved on to discuss systemic slab cleanup gaps, but this patch is settled.
