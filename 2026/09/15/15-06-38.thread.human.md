This thread is a bug report from André Kießling about an inconsistency in Git’s `fetch` behavior. The documentation claims that the `+` prefix in a refspec should be equivalent to the `--force` flag, but in practice, `git fetch origin --tags --force` preserves local tags that no longer exist on the remote, while a refspec like `+refs/tags/*:refs/tags/*` *does* delete them (acting like `--prune`). This discrepancy affects Git 2.54.0 on Windows and likely other platforms.

The report is well-documented, with clear reproduction steps and a direct quote from the `git-push` man page that explicitly equates `+` with `--force`. No patches or reviews have been posted yet, so the thread is currently just the initial report. If this behavior is confirmed, it may require either a documentation update (to clarify the difference) or a code change (to align the two mechanisms). The issue is likely to draw attention from maintainers of the fetch/push refspec machinery, such as Patrick Steinhardt or Jeff King.
