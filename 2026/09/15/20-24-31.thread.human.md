This thread reports a bug in Git’s hook environment handling: when a `post-checkout` hook runs in a worktree, `GIT_WORK_TREE` is not exported to the hook’s environment, even though `GIT_DIR` is. This causes `git rev-parse --show-toplevel` (and likely other Git commands) to return the current working directory instead of the actual worktree root, breaking scripts that rely on the correct toplevel path. The issue is specific to worktrees; the main worktree’s hook environment behaves as documented.

Phil Sainty reported the bug with clear reproduction steps across Git versions 2.34, 2.55 maint, and 2.56.0.rc0, confirming it persists. Junio C Hamano responded with a proposed patch that exports `GIT_WORK_TREE` alongside `GIT_DIR` when a worktree is detected during repository setup. The patch is small and focused, touching `setup.c`, but Junio noted a "large NEEDSWORK comment" in the surrounding code, suggesting the fix may need broader design reconsideration before finalization. This could expand the discussion to address deeper questions about how Git exports environment variables to hooks.

The thread is now under review. No objections or alternative approaches have been raised yet, but the NEEDSWORK comment hints at potential contention if reviewers push for a more comprehensive refactor. The fix would need regression tests to verify `GIT_WORK_TREE` is correctly exported for both main and worktree checkouts. The `githooks(5)` man page already implies these variables should be exported together, but the behavior is not explicitly enforced. No other hooks (e.g., `post-commit`, `pre-rebase`) have been tested for similar issues, leaving that as an open question.
