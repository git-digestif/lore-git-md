This thread is about a bug in Git’s hook environment handling: when a `post-checkout` hook runs in a worktree, `GIT_WORK_TREE` is either missing or set incorrectly, causing `git rev-parse --show-toplevel` and similar commands to return the wrong path. Phil Sainty originally reported the issue and confirmed it affects Git versions 2.34 through 2.56.0.rc0.

Junio C Hamano posted an initial patch to export `GIT_WORK_TREE` alongside `GIT_DIR` when a worktree is detected, but Phil’s follow-up testing revealed the fix is incomplete: the variable is now exported, but its value is hardcoded to `.` (current directory) rather than the actual worktree root. This stems from how `discovery.worktree` is populated in `setup.c`, where the worktree path is set to `.` in multiple locations. The NEEDSWORK comment Junio noted earlier now appears directly relevant, as the issue may require broader changes to how Git tracks and exports worktree paths during repository setup.

The thread is now focused on whether to fix the path resolution in `setup.c` or revisit the entire hook environment export mechanism. No alternative approaches have been proposed yet, and the discussion remains open. Key participants are Phil Sainty (who reported the bug and provided test results) and Junio C Hamano (who posted the initial patch and noted the broader design concerns). The fix will need to ensure `GIT_WORK_TREE` is both exported and set to the correct path for worktree hooks.
