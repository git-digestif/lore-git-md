This thread is about a bug in Git’s hook environment handling that affects worktrees. Phil Sainty reports that when a `post-checkout` hook runs in a worktree, `GIT_WORK_TREE` is not exported to the hook’s environment, even though `GIT_DIR` is. This breaks scripts that rely on `git rev-parse --show-toplevel` to return the correct worktree root, as the command instead returns the current working directory. The issue is specific to worktrees and has been confirmed across multiple Git versions (2.34, 2.55 maint, and 2.56.0.rc0).

The proposed fix would ensure `GIT_WORK_TREE` is consistently exported alongside `GIT_DIR` for worktree hooks, aligning with the documented expectation that these variables should be set together. The bug is isolated to the `post-checkout` hook (other hooks were not tested) and involves the `run-command.c` and `hook.c` subsystems. No prior discussion of this issue exists in the thread, but the report includes clear reproduction steps, making it actionable for a fix. The `githooks(5)` man page hints at this behavior but does not explicitly require `GIT_WORK_TREE` to be set. No reviews or decisions have been made yet.
