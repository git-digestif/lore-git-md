This is a bug report about inconsistent behavior between the `+` refspec modifier and the `--force` flag in `git fetch`.

André Kießling reports that the Git documentation states the `+` prefix in a refspec should behave identically to `--force`, but in practice it does not. When using `git fetch origin --tags --force`, tags that changed on the remote are updated but local tags are not deleted. However, when using a refspec like `+refs/tags/*:refs/tags/*`, local tags *are* deleted as if `--prune` were enabled. This contradicts the documentation and creates unexpected behavior for users who expect `+` and `--force` to be equivalent.

The report includes clear reproduction steps and cites the relevant documentation. The issue appears to affect Git 2.54.0.windows.1, though it may not be Windows-specific. This looks like a genuine bug rather than a documentation error, as the two mechanisms should behave consistently. The report is well-structured and provides enough detail for someone to investigate or verify the issue.
