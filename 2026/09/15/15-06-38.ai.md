This is a bug report about inconsistent behavior between the `+` refspec modifier and the `--force` flag in `git fetch`.

André Kießling reports that the Git documentation states the `+` prefix in a refspec should behave identically to `--force`, but this does not hold for `git fetch`. Specifically: `git fetch origin --tags --force` updates tags but does not delete local tags that no longer exist on the remote, while `git fetch origin` with `remote.origin.fetch = +refs/tags/*:refs/tags/*` *does* delete local tags as if `--prune` were set. The behavior difference is surprising and contradicts the documentation.

The report is clear and includes concrete reproduction steps (commands and configuration), the Git version (`2.54.0.windows.1`), and a direct quote from the `git-push` man page that the `+` refspec "does the same thing as --force". No patch is provided; this is a pure bug report. The issue appears well-motivated and is likely to attract attention from maintainers of the fetch/push refspec machinery.
