This is a bugfix targeting Git's hook environment handling. Phil Sainty reports that when a `post-checkout` hook runs in a worktree, `GIT_WORK_TREE` is not exported to the hook's environment, even though `GIT_DIR` is. This causes `git rev-parse --show-toplevel` (and likely other Git commands) to return the current working directory instead of the actual worktree root, because Git falls back to the CWD when `GIT_WORK_TREE` is missing.

The issue is straightforward: the hook documentation suggests that Git exports relevant environment variables so hooks can locate the repository, but in worktree scenarios, `GIT_WORK_TREE` is omitted. Phil tested this across multiple Git versions (2.34, 2.55 maint, and 2.56.0.rc0) and confirmed the behavior is consistent. He also notes that unsetting `GIT_DIR` works around the problem, but argues this shouldn't be necessary since the hook is operating within the same worktree where the checkout occurred.

The patch itself isn't provided in the email, but the report is clear and well-motivated. It includes system info, reproducer details, and references to both the Git book and `githooks(5)` man page to explain the expected behavior. This looks like a real, if niche, bug that would be worth fixing—especially since it affects worktree usability, an area that has seen increasing attention in recent years. The fix would likely involve ensuring `GIT_WORK_TREE` is exported alongside `GIT_DIR` for worktree hooks.
