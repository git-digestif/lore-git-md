Subject: Inconsistent behavior between `+` refspec modifier and `--force` in `git fetch`
Series version: N/A (bug report)
Originating author: André Kießling
Thread type: bug report

Core problem or goal
The `+` refspec modifier and the `--force` flag are documented to behave identically, but in `git fetch` they diverge: `--force` updates tags without pruning deleted ones, while `+` in the refspec both updates *and* prunes local tags that no longer exist on the remote. The documentation in `git-push(1)` claims `+` "does the same thing as --force", yet this equivalence does not hold for `git fetch`.

Current status
Under review; no patch yet. The report includes reproduction steps, Git version (`2.54.0.windows.1`), and a direct quote from the `git-push` man page. The discussion has shifted from assuming a bug to questioning whether the behavior is intentional and documented.

- Subsystem: fetch/push refspec machinery
- CLI options: `--force`, `--tags`, `+` refspec prefix
- Config key: `remote.origin.fetch`
- Behavior: `+` in refspec prunes deleted tags; `--force` does not
- On-disk: no format changes; only ref updates are affected
- Test coverage: none yet; reproduction steps provided in the report
- Documentation: `git-fetch(1)` PRUNING section may explain the discrepancy

Open questions and loose ends

- If the behavior is unintentional, should `--force` be made to prune (breaking change) or should `+` be made to not prune (backward-compatible)?
- Are there other refspec modifiers or fetch modes where similar inconsistencies exist?
