Thread identity
Subject: Bug: GIT_WORK_TREE not exported to post-checkout hook in worktrees
Series version: standalone patch (initial version posted by Junio C Hamano)
Originating author: Phil Sainty
Thread type: bug report and fix

Core problem or goal
When a `post-checkout` hook runs in a worktree, `GIT_WORK_TREE` is not exported to the hook’s environment, even though `GIT_DIR` is. This causes `git rev-parse --show-toplevel` (and likely other Git commands) to return the current working directory instead of the actual worktree root, breaking scripts that rely on the correct toplevel path. The issue is specific to worktrees; the main worktree’s hook environment behaves as documented.

Current status
Under review. Junio C Hamano posted an initial patch that exports `GIT_WORK_TREE` alongside `GIT_DIR` when a worktree is detected during repository setup. The patch is small and targeted, but Junio notes a "large NEEDSWORK comment" in the surrounding code, suggesting the broader hook environment handling may need reconsideration before the fix is finalized. No objections or alternative approaches have been raised yet.

Key technical details
- **Files touched**: `setup.c` (repository setup), `run-command.c`, `hook.c` (hook environment handling).
- **Environment variables**: `GIT_WORK_TREE`, `GIT_DIR`.
- **Commands affected**: `git rev-parse --show-toplevel`; other commands relying on worktree detection in hooks may also be impacted.
- **New symbols**: None.
- **On-disk format**: No changes.
- **Test coverage**: Regression tests needed to verify `GIT_WORK_TREE` is correctly exported for both main and worktree checkouts.
- **Documentation**: `githooks(5)` man page implies these variables should be exported together, but the behavior is not explicitly enforced.

Open questions and loose ends
- Whether other hooks (e.g., `post-commit`, `pre-rebase`) are similarly affected; the original report tested only `post-checkout`.
- Whether the fix should extend to all worktree hooks or remain scoped to `post-checkout`.
- The NEEDSWORK comment in `setup.c` hints at unresolved design questions about how Git exports environment variables to hooks, which could lead to broader discussion or refactoring.
