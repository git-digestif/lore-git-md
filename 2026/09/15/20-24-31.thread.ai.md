Thread identity
Subject: Bug: GIT_WORK_TREE not exported to post-checkout hook in worktrees
Series version: standalone patch (initial version posted by Junio C Hamano; now under deeper revision)
Originating author: Phil Sainty
Thread type: bug report and fix

Core problem or goal
When a `post-checkout` hook runs in a worktree, `GIT_WORK_TREE` is exported to the hook’s environment with the value `.` (current directory) instead of the actual worktree root path. This causes `git rev-parse --show-toplevel` and any other Git command that relies on worktree detection to return incorrect results, breaking scripts that depend on the correct toplevel path. The issue is specific to worktrees; the main worktree’s hook environment behaves as documented.

Current status
Under review, with a deeper problem identified. Junio C Hamano posted an initial patch that exports `GIT_WORK_TREE` alongside `GIT_DIR` when a worktree is detected, but Phil Sainty’s follow-up testing revealed the exported value is `.` rather than the worktree root. The fix now requires correcting how `discovery.worktree` is populated in `setup.c`. Junio’s earlier NEEDSWORK comment about the broader hook environment handling is now directly relevant, as the issue appears to stem from unresolved design questions in repository setup logic.

Key technical details
- **Files touched**: `setup.c` (repository discovery and setup logic), `run-command.c`, `hook.c` (hook environment handling).
- **Environment variables**: `GIT_WORK_TREE` (exported but with incorrect value `.`), `GIT_DIR` (correctly exported).
- **Commands affected**: `git rev-parse --show-toplevel`; other commands relying on worktree detection in hooks.
- **New symbols**: None.
- **On-disk format**: No changes.
- **Test coverage**: Regression tests needed to verify `GIT_WORK_TREE` is exported with the correct worktree root path for both main and worktree checkouts.
- **Documentation**: `githooks(5)` man page implies these variables should be exported together, but the behavior is not explicitly enforced.
- **Related code paths**: `repo_discovery_set_worktree()` and `setenv(GIT_WORK_TREE_ENVIRONMENT, ".", 1)` calls in `setup.c` (lines 510, 1213, 1269) hardcode the value to `.`.
