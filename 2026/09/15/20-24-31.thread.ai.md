Subject: Bug: GIT_WORK_TREE not exported to post-checkout hook in worktrees
Series version: standalone patch (no versioning yet)
Originating author: Phil Sainty
Thread type: bug report

Core problem or goal
When a `post-checkout` hook runs in a worktree, `GIT_WORK_TREE` is not exported to the hook’s environment, even though `GIT_DIR` is. This causes `git rev-parse --show-toplevel` (and likely other Git commands) to return the current working directory instead of the actual worktree root, breaking scripts that rely on the correct toplevel path. The issue is specific to worktrees; the main worktree’s hook environment behaves as documented.

Current status
Under review. No prior discussion of this specific issue in the thread. The report includes reproduction steps across Git versions 2.34, 2.55 maint, and 2.56.0.rc0, confirming the bug persists. No patch versioning yet; this is the initial report.

Key technical details
- **Files touched**: `run-command.c`, `hook.c` (hook environment handling).
- **Environment variables**: `GIT_WORK_TREE`, `GIT_DIR`.
- **Commands affected**: `git rev-parse --show-toplevel`; other commands relying on worktree detection may also be impacted.
- **On-disk format**: No changes.
- **Test coverage**: Regression tests needed to verify hook environment for both main and worktree checkouts.
- **Documentation**: `githooks(5)` man page hints at the expectation but does not explicitly require `GIT_WORK_TREE` to be set.
