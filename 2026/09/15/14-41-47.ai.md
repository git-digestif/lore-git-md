This is a design discussion about the `OPT_ALIAS_F()` mechanism introduced in patch 1/13 of Patrick Steinhardt’s ref-storage terminology unification series. Junio C Hamano clarifies the intended lifecycle of deprecated options in Git: initially, deprecated options should remain public (visible in `git cmd -h`) to warn existing users, but after sufficient time, they should be hidden (`OPT_HIDDEN`) to avoid cluttering help output for new users. Eventually, they can be removed entirely or retained only to emit an error message.

Junio confirms that `OPT_HIDDEN` is the correct mechanism for deprecation, even for aliases, and that the inability to apply `OPT_HIDDEN` to `OPT_ALIAS()` is a limitation of the current infrastructure—not a reason to avoid using `OPT_ALIAS_F()`. He suggests leaving a `#leftoverbit` to track this as a future cleanup task, but it is not a blocker for the series. The reply implicitly endorses Patrick’s approach of using `OPT_ALIAS_F()` with `PARSE_OPT_HIDDEN` for the `--ref-format=` alias, while acknowledging Kaartic Sivaraam’s observation that Git has historically tolerated public aliases for deprecated options (e.g., `--recursive` in `git clone`). The discussion remains focused on implementation details rather than the series’ core goal. No merge status is reported; the series is still under review.
