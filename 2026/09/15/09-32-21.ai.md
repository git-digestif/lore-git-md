This is a surface-level review reply in the ongoing `[PATCH v3 00/13]` series to unify Git’s ref-storage terminology. Kaartic Sivaraam joins the discussion of patch 1/13, which introduces `OPT_ALIAS_F()` to allow hidden aliases for deprecated option names. He offers historical context: Git already uses public `OPT_ALIAS()` for deprecated variants like `--recursive` (alias of `--recurse-submodules` in `git clone`) and `--negotiation-tip` (alias of `--negotiation-restrict` in `git fetch`). Neither alias is hidden, yet both remain functional and appear in help text. Sivaraam’s point is pragmatic: if Git has tolerated public deprecated aliases for years, exposing `--ref-format=` as a public alias of `--ref-storage-format=` may not be problematic. The reply does not challenge the series’ core goal but questions whether the added complexity of `OPT_ALIAS_F()` is justified when simpler public aliases have worked in the past. No merge status is reported; the series remains under review.
