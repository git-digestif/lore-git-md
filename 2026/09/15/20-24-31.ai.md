This is a bugfix targeting Git's hook environment handling. The author reports that when a `post-checkout` hook runs in a worktree, `GIT_WORK_TREE` is not exported to the hook's environment, even though `GIT_DIR` is. This causes `git rev-parse --show-toplevel` (and likely other Git commands) to return the current working directory instead of the actual worktree root, breaking scripts that rely on the correct toplevel path.

The issue is specific to worktrees: the hook environment includes `GIT_DIR=/path/to/repo/.git/worktrees/name` but omits `GIT_WORK_TREE`, which violates the documented behavior that these variables should be exported together. The author tested this across multiple Git versions (2.34, 2.55 maint, and 2.56.0.rc0) and confirmed it affects only the `post-checkout` hook (other hooks were not tested). The proposed fix would ensure `GIT_WORK_TREE` is consistently exported alongside `GIT_DIR` for worktree hooks.

Key technical details for follow-up discussion:
- **Subsystem**: Hook environment handling (`run-command.c`, `hook.c`).
- **Environment variables**: `GIT_WORK_TREE`, `GIT_DIR`.
- **Commands affected**: `git rev-parse --show-toplevel`, possibly others that rely on worktree detection.
- **Test coverage**: The issue is reproducible in worktrees; regression tests would need to verify the hook environment for both main and worktree checkouts.
- **Related documentation**: The `githooks(5)` man page already hints at this expectation but does not explicitly require `GIT_WORK_TREE` to be set.
