This is a security feature patch that has now graduated to `next`. The patch introduces `http.sslVerifyStatus`, a new boolean configuration option (default `false`) that enables Git to validate OCSP staples during HTTPS certificate verification. When enabled, Git will reject connections to servers whose certificates are revoked or that do not provide a stapled OCSP response, closing a security gap for government and FIPS-compliant users (e.g., US DoD PKI) where OpenSSL-linked Git binaries currently ignore staples.

This v7 iteration is the final, combined version the author and reviewers agreed on. It merges Grayson Gordon’s original tests (which verify fail-closed behavior, per-URL scoping, and edge cases) with Patrick Steinhardt’s test harness (which exercises success and failure paths for stapled responses). The patch touches `http.c`, `Documentation/config/http.adoc`, and the test suite (`t5551-http-fetch-smart.sh` and the new `t5585-http-ssl-ocsp.sh`). The `SSL_VERIFYSTATUS` prerequisite is now shared between both test files via `lib-httpd.sh`, and the OCSP stapling infrastructure in `lib-httpd` is opt-in via `LIB_HTTPD_OCSP`.

The commit message and documentation are clear and well-motivated, explaining the security trade-offs (fail-closed for security, default-off to avoid breaking existing remotes) and the specific use case (government customers who mandate OCSP stapling).
