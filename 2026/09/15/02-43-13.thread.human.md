This thread is about a small but useful enhancement to `git-contacts`, a Perl helper script in `contrib/` that scans patches for author and reviewer contact information. Brigham Campbell proposed allowing the script to read patch content from stdin when no arguments are given and stdin isn’t a terminal, making it easier to pipe patches from tools like `b4`. Junio reviewed the first version, suggested minor stylistic tweaks (commit message trailers, argument-handling cleanup, and a usage comment update), and Brigham posted a v2 that incorporated all of them.

The feature itself is uncontroversial and ready for Junio to pick up. In this latest message, Junio floats an alternative design: instead of silently reading stdin when no arguments are given, the script could treat `-` as a filename argument meaning “read from stdin,” following the common UNIX convention. This would let users mix file arguments and stdin (e.g., `git contacts patch1 - patch3 <patch2`) and avoid changing the usage comment. He presents it as a thought experiment rather than a blocker, so the v2 patch remains the current candidate for merging. No other concerns have been raised, and the next step is simply for Junio to queue it.
