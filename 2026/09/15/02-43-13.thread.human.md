This thread is about extending the `git-contacts` contrib script to accept patch input from stdin using the conventional `-` idiom, allowing mixed file/stdin usage (e.g., `git contacts patch1 - patch3 <patch2`). The feature is intended to improve interoperability with tools like `b4`.

The patch is now at v3, which implements the `-` idiom as suggested by Junio C Hamano. Junio has proposed two refinements: a structural change to avoid a separate `$read_from_stdin` flag by treating `-` as a special filename in the `scan_patch_file` function, and a commit message clarification to avoid implying that arguments are processed in a predictable order. Brigham Campbell, the author, has accepted the commit message adjustment but has not yet responded to the structural suggestion. The feature itself has no functional objections and remains under review.

The only remaining open question is the design choice for integrating the `-` idiom—whether to keep the current v3 implementation or adopt Junio’s alternative. The thread is now waiting for Brigham’s response to this suggestion. Junio and Brigham are the key participants, with Junio guiding the design and Brigham implementing the changes.
