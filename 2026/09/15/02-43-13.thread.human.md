This thread is about a small but useful enhancement to `git-contacts`, a contrib script that helps identify potential reviewers for patches. Brigham Campbell has been refining a patch to let the script read patch content from stdin using the conventional `-` idiom, making it easier to mix file and stdin input (like `git contacts patch1 - patch3 <patch2`). This change is part of a broader effort to improve interoperability with tools like `b4`, though it stands on its own.

The patch is now at version 4, incorporating Junio Hamano’s feedback to clarify in the commit message that the script doesn’t guarantee a predictable order for processing arguments. The core implementation remains simple: when `-` is passed as an argument, the script reads from stdin, replacing the older behavior that only read from stdin when no arguments were given and stdin wasn’t a terminal. Junio has also suggested a structural tweak—moving the stdin logic into the `scan_patch_file` function to avoid a separate flag—but this is a minor design question, not a blocker. The feature itself is uncontroversial and has Junio’s endorsement.

The only open question is whether to adjust the code structure as Junio proposed, but Brigham has indicated he’s open to addressing that in a follow-up if needed. The patch is low-risk, touching only the Perl script and introducing no new options or on-disk changes. No objections have been raised, and the thread is effectively waiting for either a final nod or a small follow-up to tidy up the implementation.
