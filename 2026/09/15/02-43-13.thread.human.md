This thread is about a small but useful enhancement to `git-contacts`, a contrib script that helps identify people to CC on patches. Brigham Campbell proposed allowing the script to read patch content from stdin using the conventional `-` idiom (e.g., `git contacts patch1 - patch3 <patch2`), which would improve interoperability with tools like `b4`. The feature has been through three iterations: v1 introduced implicit stdin reading, v2 refactored argument handling based on Junio’s feedback, and v3 switched to the `-` idiom as Junio suggested.

The patch is under review and has no functional objections, but Junio’s latest reply proposes a different code structure. Instead of using a separate `$read_from_stdin` flag, he suggests treating `-` as a special filename throughout the code path, pushing the stdin logic into `scan_patch_file`. This would make the behavior more localized and potentially cleaner. The ball is now back to Brigham to either adopt Junio’s suggestion or explain why the current approach is better. The patch remains narrowly scoped to `contrib/contacts/git-contacts` and doesn’t introduce new symbols or CLI options.
