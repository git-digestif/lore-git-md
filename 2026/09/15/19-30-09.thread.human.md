This thread is about a bugfix for a Git protocol v2 regression in `upload-pack` that causes client crashes during shallow fetches when `uploadpack.allowRefInWanted=true` is enabled. The issue stems from the server sending "wanted-refs" before "shallow-info", which the client cannot process correctly, leading to a fatal error (`fatal: expected 'packfile', received 'shallow-info'`). Royce Remer, the patch author, has confirmed this is a long-standing bug—no existing clients could successfully perform shallow operations under these conditions, meaning the fix restores functionality rather than breaking backward compatibility.

The patch itself is simple: it swaps the order of two function calls in `upload_pack_v2()` to ensure "shallow-info" is sent first. Junio C Hamano, the maintainer, has reviewed the patch substantively, requesting the commit message clarify the failure mode, technical rationale, and backward compatibility. Royce’s latest response provides this context, explaining the crash and confirming the fix has been tested in production-like environments with new test cases covering both single-commit shallow clones and incremental fetches. The only remaining loose end is Junio’s question about whether the client crashes or silently ignores unexpected sections, though Royce’s description suggests a crash. A v2 patch incorporating these details is expected soon.
