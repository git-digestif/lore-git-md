This thread is about a bugfix for a client-side crash in Git's protocol v2 `upload-pack` when performing shallow fetches with `uploadpack.allowRefInWanted=true` enabled. The issue causes a hard crash (`fatal: expected 'packfile', received 'shallow-info'`) due to a misordered function call in the server's response handling. Author Royce Remer identified the root cause: the client's `process_section_header()` logic skips unexpected sections using a `peek` bit, so when "wanted-refs" arrives before "shallow-info", the client misses critical data and crashes.

The fix is a one-line change in `upload-pack.c`, swapping the order of `send_shallow_info()` and `send_wanted_ref_info()` to ensure the server sends sections in the expected order. The patch includes two new test cases in `t/t5703-upload-pack-ref-in-want.sh` to validate the fix for both single-commit shallow clones and incremental shallow fetches. Junio Hamano reviewed the v1 patch and requested improvements to the commit message, specifically requiring explicit documentation of the failure mode, technical rationale, and backward compatibility assessment. Royce has now posted v2 with these details addressed, confirming the feature combination never worked in practice and thus poses no backward compatibility risk.

The patch is technically sound, narrowly scoped, and ready for further review. No new symbols or on-disk format changes are introduced, and the fix is server-side only, with no impact on protocol v0/v1 or non-shallow fetches. The thread is now focused on finalizing the commit message and ensuring the fix is merged before the next release.
