This thread is about a bugfix for a Git protocol v2 regression that causes client crashes during shallow fetches when `uploadpack.allowRefInWanted=true` is enabled. The issue was introduced by a server-side ordering bug in `upload-pack.c`, where `send_wanted_ref_info()` was called before `send_shallow_info()`, causing the client to crash with `fatal: expected 'packfile', received 'shallow-info'`. The fix—swapping the order of these two function calls—has been validated by new test cases and production-like testing, and is now technically sound.

The author, Royce Remer, has clarified that the failure is a hard client crash (not silent misbehavior) and that the feature combination has never worked in practice, meaning the fix is backward-compatible. Junio Hamano, the maintainer, has reviewed the patch and confirmed its correctness but requested improvements to the commit message before merging. The updated message must include: (1) the precise failure mode (client crash with error message), (2) the technical rationale for the ordering requirement (client-side `peek` logic in `process_section_header()`), and (3) a backward compatibility assessment (no existing clients are affected).

The patch is narrowly scoped to the protocol v2 shallow fetch path, touching only `upload-pack.c` (one line moved) and adding two test cases to `t/t5703-upload-pack-ref-in-want.sh`. No new symbols or on-disk format changes are involved. The thread is now awaiting a v2 patch with the improved commit message, after which it should be ready for merging. No further technical changes are expected.
