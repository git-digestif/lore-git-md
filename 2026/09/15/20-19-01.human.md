This is a follow-up review from Junio C Hamano on Royce Remer’s patch to fix a Git protocol v2 regression in shallow fetch ordering when `uploadpack.allowRefInWanted` is enabled. Junio reconstructs the likely client-side behavior in `fetch-pack.c`, where `process_section_header()` calls check for "shallow-info" and "wanted-refs" sections with the peek bit set. This means the client can safely ignore a section if it doesn’t match what it expects next. If the server sends wanted-ref info first, the client might skip it while looking for shallow-info, then process it later—but only if shallow-info arrives second. If shallow-info is sent first, the client processes it immediately, then moves on to wanted-refs. Junio’s key question is whether the client crashes or behaves incorrectly if shallow-info arrives *after* wanted-refs, which would explain the bug. He asks Royce to confirm this scenario and document it in the commit message, as it would make the rationale for the fix clear and compelling.
