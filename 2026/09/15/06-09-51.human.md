This is the third patch in SZEDER Gábor’s four-patch series to speed up Git builds by precompiling `git-compat-util.h`. The patch reintroduces the `REFTABLE_OBJS` Makefile variable, which was removed in 2025 when the reftable static library was merged into `LIB_OBJS`. The change is purely mechanical: it moves reftable object files from `LIB_OBJS` to `REFTABLE_OBJS` and adds `REFTABLE_OBJS` back to `LIB_OBJS` to preserve the final link. The CMake build system is updated to parse `REFTABLE_OBJS` and include those sources in the `libgit` target.

The motivation is clear: reftable source files (except `reftable/system.c`) deliberately avoid including `git-compat-util.h` so the reftable implementation can be embedded in other projects. Precompiling that header would break this design, so these files must be excluded from the precompiled-header mechanism. The commit message now leads with the series’ goal (precompiling `git-compat-util.h`) before explaining the exclusion rationale, addressing Junio’s editorial feedback from v1.

The patch itself is uncontroversial and well-explained. It touches only the `Makefile` and `contrib/buildsystems/CMakeLists.txt`, with no runtime behavior changes. The CMake adjustment is straightforward, but the author has flagged it as needing review from Windows/CMake builders to confirm the parsing works as intended. No objections have been raised so far, and the change is a necessary prerequisite for the final patch in the series.
