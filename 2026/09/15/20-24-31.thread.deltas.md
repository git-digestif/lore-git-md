# Thread deltas

## 2026/09/15

- [2026/09/15/20-24-31 by Phil Sainty <psainty@orcon.net.nz>] Phil Sainty reported that when post-checkout-hook runs for a checkout within a worktree directory, GIT_DIR is set but GIT_WORK_TREE is not, causing `git rev-parse --show-toplevel` to return the current working directory instead of the genuine toplevel; he tested this in git versions 2.34, 2.55 (maint), and 2.56.0.rc0.355.g945ea7012d (next), noted he had only tested post-checkout-hook, and stated his impression that GIT_WORK_TREE should be set for this hook when dealing with a worktree.

## 2026/09/16

- [2026/09/16/21-39-49 by Junio C Hamano <gitster@pobox.com>] Junio C Hamano noted that unsetting GIT_DIR would be a possible workaround but questioned why GIT_DIR needs to be exported in the first place, and proposed a patch to setup.c that would export GIT_WORK_TREE when a worktree exists and GIT_DIR is also exported, while flagging that a large NEEDSWORK comment in the precontext of the hunk merits consideration before moving forward.

## 2026/09/25

- [2026/09/25/19-11-39 by Phil Sainty <psainty@orcon.net.nz>] Phil Sainty reported that testing Junio C Hamano's patch shows GIT_WORK_TREE is exported as '.' rather than the actual worktree path (regardless of which subdirectory was in use), so "git rev-parse --show-toplevel" still returns the CWD; he suggested discovery.worktree may not be the right value and identified setup.c lines 510, 1213, and 1269 as locations setting that '.' value.
