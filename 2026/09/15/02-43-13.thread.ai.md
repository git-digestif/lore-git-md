Thread identity
Subject: [PATCH] git-contacts: accept patch input from stdin
Series version: standalone patch (v2)
Originating author: Brigham Campbell
Thread type: feature patch for a contrib script

Core problem or goal
Extend `git-contacts` (a contrib Perl script in `contrib/contacts/`) to read patch content from stdin when stdin is not a terminal and no arguments are supplied, improving interoperability with external tools such as `b4`. A design alternative remains under consideration: adopt the conventional UNIX idiom of treating `-` as a filename argument meaning "read from stdin," which would allow mixing file arguments and stdin input without requiring a usage comment change.

Current status
Under review; v2 posted incorporating Junio C Hamano’s stylistic feedback (commit message trailer cleanup, argument-handling refactor, usage comment update). The feature concept remains endorsed; no functional objections have been raised. Junio has suggested the `-` idiom as a possible refinement but has not requested a v3. The author has stated openness to implementing the `-` idiom if Junio explicitly requests it, otherwise leaving v2 as the current version for further review.

Key technical details
- File touched: `contrib/contacts/git-contacts`
- Current v2 behavior: when invoked with no arguments and stdin is not a tty (`-t STDIN` false), the script calls the existing `scan_patches()` helper on the stdin filehandle.
- Proposed alternative: treat `-` as a filename argument meaning "read from stdin," enabling mixed file/stdin usage (e.g., `git contacts patch1 - patch3 <patch2`).
- No new symbols, CLI options, or on-disk format changes in either approach.
- Usage comment at the top of the file updated in v2 to document stdin capability; the `-` idiom would obviate this change.
- Argument-handling logic in v2 refactored to use an early `$read_from_stdin` variable, aligning with the script’s existing style.

Open questions and loose ends
- Whether to adopt the `-` idiom or retain the current v2 behavior. Junio has not requested a change, and the author has deferred to Junio’s preference. No further action is required unless Junio explicitly asks for a revision.
