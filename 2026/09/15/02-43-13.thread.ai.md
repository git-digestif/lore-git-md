Thread type: feature patch for a contrib script (merged), now with documentation and internal usage comment updates

Core problem or goal
Extend `git-contacts` (a contrib Perl script in `contrib/contacts/`) to read patch content from stdin using the conventional UNIX `-` idiom, enabling mixed file/stdin usage (e.g., `git contacts patch1 - patch3 <patch2`) and improving interoperability with external tools such as `b4`. The feature patch (v4) is merged to `master`; the follow-up (v5) added documentation for the new behavior and updated the script's internal usage comment to reflect the `-` convention. The v6 update consolidates all changes into a single commit, corrects the script's internal usage comment to include `'-'` as a valid input option, and expands the documentation to clarify support for multiple patches from stdin.

Current status
Feature patch v4 merged to `master` (date unknown). The v5 submission was a two-patch series: (1) a re-send of the unchanged v4 feature patch (for context), and (2) a documentation update adding a sentence to `git-contacts.adoc` explaining that a single dash `'-'` reads patch file(s) from stdin, plus an internal usage comment update. Junio observed that the feature and its documentation should ideally have been submitted together in a single patch rather than as a post-merge follow-up, but the documentation patch itself was uncontroversial and ready to apply. Junio further noted that the script's internal usage comment should be updated to include `'-'` as a valid input option, aligning with the established pattern of updating usage comments when behavior changes. The v6 update consolidates the feature, documentation, and internal usage comment changes into a single commit, corrects the internal usage comment to `usage: git contacts ['-'] <file>...`, and expands the documentation to clarify that the feature supports multiple patches from stdin via mbox `From ` headers. The v6 update is uncontroversial and ready to apply.

Key technical details
- Files touched: `contrib/contacts/git-contacts` (feature, merged; internal usage comment updated in v5 and corrected in v6), `contrib/contacts/git-contacts.adoc` (documentation follow-up in v5, expanded in v6)
- Feature behavior: treats `-` as a filename argument meaning "read from stdin," enabling mixed file/stdin usage without requiring a terminal check. Supports mbox-separated concatenated patches via `From ` headers.
- Implementation: v4 removed implicit stdin detection (`-t STDIN` check) and replaced it with an explicit `$read_from_stdin` flag set when `-` is encountered in `@ARGV`; calls `scan_patches()` with the stdin filehandle if the flag is set. No changes to the v4 implementation in v5 or v6 beyond the internal usage comment update.
- Documentation: v5 added a sentence to the `<patch>` placeholder description: "A single dash `'-'` reads patch file(s) from the standard input." The v6 update expands this to include an example showing stdin usage and clarifies that the feature supports multiple patches from stdin via mbox `From ` headers.
- Internal usage comment: the script's top-level usage line was updated in v5 to include `'-'` as a valid input option, but the exact syntax was not finalized. The v6 update corrects it to `usage: git contacts ['-'] <file>...`, matching the project's established pattern.
- No new symbols, CLI options, or on-disk format changes.
