Subject: [PATCH] git-contacts: accept patch input from stdin
Series version: standalone patch (v4, now merged to master); documentation follow-up
Originating author: Brigham Campbell (feature), Junio C Hamano (documentation)
Thread type: feature patch for a contrib script, now with documentation update

Core problem or goal
Extend `git-contacts` (a contrib Perl script in `contrib/contacts/`) to read patch content from stdin using the conventional UNIX `-` idiom, enabling mixed file/stdin usage (e.g., `git contacts patch1 - patch3 <patch2`) and improving interoperability with external tools such as `b4`. The feature patch is now merged; the follow-up documents the new behavior.

Current status
Merged to master (feature patch v4). The documentation update is a routine follow-up: it adds a sentence to `git-contacts.adoc` explaining that a single dash `'-'` reads a patch from stdin. The update is uncontroversial and ready to apply. No open technical questions remain; the only minor uncertainty is whether the wording should account for multiple concatenated patches from stdin, but this is deferred for later.

Key technical details
- Files touched: `contrib/contacts/git-contacts` (feature, now merged), `contrib/contacts/git-contacts.adoc` (documentation follow-up)
- Feature behavior: treats `-` as a filename argument meaning "read from stdin," enabling mixed file/stdin usage without requiring a terminal check.
- Implementation: v4 removed implicit stdin detection (`-t STDIN` check) and replaced it with an explicit `$read_from_stdin` flag set when `-` is encountered in `@ARGV`; calls `scan_patches()` with the stdin filehandle if the flag is set.
- Documentation: adds a sentence to the `<patch>` placeholder description: "A single dash `'-'` reads a patch from the standard input."
- No new symbols, CLI options, or on-disk format changes.

Open questions and loose ends
None for the feature itself. The documentation update notes a minor wording uncertainty: whether `scan_patches()` can handle multiple concatenated patches from stdin, suggesting the phrasing could be adjusted to "patch file(s)" if so. This is left for future consideration and does not block the current update.
