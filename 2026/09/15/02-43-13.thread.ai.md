Subject: [PATCH] git-contacts: accept patch input from stdin
Series version: standalone patch (v4 feature merged to master); v5 documentation follow-up (two-patch series: feature re-send + documentation)
Originating author: Brigham Campbell (feature), Junio C Hamano (documentation)
Thread type: feature patch for a contrib script (merged), now with documentation update

Core problem or goal
Extend `git-contacts` (a contrib Perl script in `contrib/contacts/`) to read patch content from stdin using the conventional UNIX `-` idiom, enabling mixed file/stdin usage (e.g., `git contacts patch1 - patch3 <patch2`) and improving interoperability with external tools such as `b4`. The feature patch (v4) is merged to `master`; the follow-up (v5) adds documentation for the new behavior.

Current status
Feature patch v4 merged to `master` (date unknown). The v5 submission is a two-patch series: (1) a re-send of the unchanged v4 feature patch (for context), and (2) a documentation update adding a sentence to `git-contacts.adoc` explaining that a single dash `'-'` reads patch file(s) from stdin. Junio observed that the feature and its documentation should ideally have been submitted together in a single patch rather than as a post-merge follow-up, but the documentation patch itself remains uncontroversial and ready to apply. The feature supports mbox-separated concatenated patches via `git-format-patch`'s `From ` headers, but the documentation phrasing remains singular ("a patch") for clarity.

Key technical details
- Files touched: `contrib/contacts/git-contacts` (feature, merged), `contrib/contacts/git-contacts.adoc` (documentation follow-up)
- Feature behavior: treats `-` as a filename argument meaning "read from stdin," enabling mixed file/stdin usage without requiring a terminal check. Supports mbox-separated concatenated patches via `From ` headers.
- Implementation: v4 removed implicit stdin detection (`-t STDIN` check) and replaced it with an explicit `$read_from_stdin` flag set when `-` is encountered in `@ARGV`; calls `scan_patches()` with the stdin filehandle if the flag is set. No changes to the v4 implementation in v5.
- Documentation: adds a sentence to the `<patch>` placeholder description: "A single dash `'-'` reads a patch from the standard input."
- No new symbols, CLI options, or on-disk format changes.

None. The minor procedural observation about patch organization (feature and documentation ideally submitted together) is noted but does not block the documentation update. The feature's support for multiple patches from stdin is reflected in the implementation but not in the documentation phrasing, which remains singular for clarity.
