This is the second patch in SZEDER Gábor’s four-part **build system** series introducing precompiled headers to speed up Git builds. This patch generalizes CMake’s parsing of the Makefile to ignore all `*_OBJS` variables (e.g., `XDIFF_OBJS`, `REFTABLE_OBJS`) rather than hardcoding exclusions for specific variables like `COMPAT_OBJS`.

The change is mechanical and targeted: it replaces a hardcoded `string(REPLACE "$(COMPAT_OBJS)" ...)` with a regex-based `string(REGEX REPLACE "\\$\\([^)]*_OBJS\\)" ...)` to filter out any Makefile variable ending in `_OBJS`. The commit message explains the rationale clearly—future patches will reintroduce `REFTABLE_OBJS` and potentially other object-file variables, so this generalization avoids polluting CMake’s source lists. The regex is carefully scoped to avoid over-matching (e.g., it won’t strip directory-prefixed variables like `$(UNIT_TEST_DIR)/test-lib.o`).

This patch is a prerequisite for the precompiled-header rollout and is unlikely to be controversial, but it may draw attention from Windows/CMake builders to confirm the regex behaves as intended across platforms. The change is minimal (one line) and well-explained, with no runtime impact. If the series lands, this patch will help keep CMake’s parsing logic maintainable as new object-file variables are added.
