Core problem or goal
Extend `git branch --delete-merged` to recognize branches whose changes (but not their tips) have been integrated into an upstream branch via squash merges, rebases, or patch-based workflows. The series provides a practical, one-step repository maintenance command for common forge and local workflows. The CLI design is now **finalized**: `--delete-merged <pattern>` for strict tip-reachability (current behavior, unchanged) and `--delete-integrated <pattern>` for change-based detection of rebased *and* squashed branches (opt-in, both methods enabled by default). The series explicitly addresses the **false-positive issue** (branches incorrectly deleted because another author independently made the same change) by splitting the strict and change-based behaviors into separate flags, ensuring `--delete-merged` never deletes such branches. Junio’s reproducible test case (an unrelated upstream commit adding an identical file) is now included in the test suite to enforce this safety constraint.

The **author-check mitigation** (Jasper’s proposal) is expected to have minimal performance impact.
- **Correctness**: The test suite now includes Junio’s false-positive test case, Knoble’s "npm update" scenario, and coverage for the new `--delete-integrated` flag. The **author-check mitigation** (Jasper’s proposal) is required to address the "npm update" scenario but is not yet implemented.

The test expects `--delete-merged` to preserve branches whose changes were independently implemented by another author.

  - `--delete-integrated <pattern>`: change-based detection for rebased *and* squashed branches (opt-in, both methods enabled by default). Cannot be combined with `--delete-merged`. The **author-check mitigation** (Jasper’s proposal) is required but not yet implemented.
- Config: `branch.<name>.deleteMerged` now applies to both `--delete-merged` and `--delete-integrated`, allowing users to opt out of deletion for specific branches regardless of the flag used.

- **Algorithmic considerations**:
  - **Rebase detection**: Uses fast tree-based diffing to check for exact file matches. The **author-check mitigation** (Jasper’s proposal) or **patch IDs** (Knoble’s proposal) are required to address the "npm update" scenario but are not yet implemented.
  - **Squash detection**: Uses path-by-path three-way merge approximation via `merge_ll()` to handle upstream modifications. The algorithm lacks rename detection and is intentionally lenient (checks for *containment* of changes rather than *exact* squash-merge equivalence). The **author-check mitigation** (Jasper’s proposal) is required to reduce false positives.
