Core problem or goal
Extend `git branch --delete-merged` to recognize branches whose changes (but not their tips) have been integrated into an upstream branch via squash merges, rebases, or patch-based workflows, including cases where upstream modified the same files before integration. The series provides a practical, one-step repository maintenance command for common forge and local workflows. The CLI design is **finalized**: `--delete-merged <pattern>` for strict tip-reachability (current behavior, unchanged) and `--delete-integrated <pattern>` for change-based detection of rebased *and* squashed branches (opt-in, both methods enabled by default). The series explicitly addresses the **false-positive issue** by splitting the strict and change-based behaviors into separate flags, ensuring `--delete-merged` never deletes branches whose changes were independently implemented by another author. The **upstream modification problem** (where squash-merged files are later edited upstream) is now handled via a path-by-path three-way merge approximation.

- New behavior:
  - `--delete-merged <pattern>`: strict tip-reachability only (current behavior, unchanged). Enforced by Junio’s test case to never delete branches whose changes were independently implemented by another author.
  - `--delete-integrated <pattern>`: change-based detection for rebased *and* squashed branches (opt-in, both methods enabled by default). Handles upstream modifications via a path-by-path three-way merge approximation. The **author-check mitigation** is required but not yet implemented.
- Output format: `Deleted branch topic (was 1a2b3c4, landed as 9f8e7d6)` (updated to show landing commit).
- Performance optimizations: Rebase detection remains tree-based (no blob fetches); squash detection uses a path-by-path three-way merge via `ll_merge`, which may download blobs in partial clones when upstream modifications are present. The **author-check mitigation** is expected to have minimal performance impact.
- Edge cases handled: Upstream modifications to squashed files (three-way merge approximation), reverted changes, partial landings, mixed workflows, Knoble’s "npm update" scenario, automated scripts, and the upstream modification case (shared file edited on both branch and upstream, then squash-merged). The **author-check mitigation** is required to handle forge workflows and manually applied patches.
- Test coverage: Expanded in `t/t3200-branch.sh`; includes Junio’s test case, Knoble’s "npm update" scenario, coverage for `--delete-integrated`, and a new test case for upstream modifications. The test expects `--delete-merged` to preserve branches whose changes were independently implemented by another author.
- New CLI options:
  - `--delete-integrated <pattern>`: change-based detection for rebased *and* squashed branches (opt-in, both methods enabled by default). Handles upstream modifications via three-way merge. Cannot be combined with `--delete-merged`. The **author-check mitigation** is required but not yet implemented.
- Config: `branch.<name>.deleteMerged` applies to both flags.
- Symbols:
  - Preparatory patch: `branch_opted_out()` helper.
  - Landing-message patch: `landed_commits` strmap, `delete_branches()` helper extended to report landing commit.
  - Core `--delete-integrated` patch: `DELETE_BRANCH_INTEGRATED` flag, rebase-detection logic (tree-based diffing), squash-detection logic (three-way merge approximation via `merge_ll()`), `change_state` enum.
- **Algorithmic considerations**:
  - **Rebase detection**: Tree-based diffing for exact file matches. The **author-check mitigation** or **patch IDs** are required to address the "npm update" scenario but are not yet implemented.
  - **Squash detection**: Path-by-path three-way merge approximation via `ll_merge()` to handle upstream modifications. Lacks rename detection and is intentionally lenient. The **author-check mitigation** is required to reduce false positives.
