Subject: [PATCH] branch --delete-merged: detect squash-merged and rebase-merged branches
Series version: v1 (initial submission)
Originating author: Harald Nordgren
Thread type: patch series

Core problem or goal
Extend `git branch --delete-merged` to recognize branches whose changes (but not their tips) have been squash-merged or rebase-merged into an upstream branch. The current implementation only deletes branches whose tips are reachable from the upstream, which fails for GitHub-style squash merges where the branch tip is not part of the upstream history.

Current status
Under review; no prior versions. Patch is self-contained and does not depend on other in-flight series.

Key technical details
- Files touched: `builtin/branch.c`, `Documentation/git-branch.txt`
- New behavior: `--delete-merged` now detects when an upstream commit contains all changes from a branch by comparing tree diffs and simulating a three-way merge.
- Output format: `Deleted branch topic (was 1a2b3c4, landed as 9f8e7d6)`
- Edge cases handled: reverted changes, partial landings (avoids false positives by requiring every change from the branch to be present in the upstream commit).
- Test coverage: added to `t/t3200-branch.sh`; scenarios include reverted squash merges and partial landings.
- New or renamed symbols: none (internal logic only).
