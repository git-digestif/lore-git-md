Core problem or goal
Extend `git branch --delete-merged` to recognize branches whose changes (but not their tips) have been integrated into an upstream branch via squash merges, rebases, or patch-based workflows, including cases where upstream modified the same files before integration. The series provides a practical, one-step repository maintenance command for common forge and local workflows. The CLI design is **finalized**: `--delete-merged <pattern>` for strict tip-reachability (current behavior, unchanged) and `--delete-integrated <pattern>` for change-based detection of rebased *and* squashed branches (opt-in, both methods enabled by default). The series explicitly addresses the **false-positive issue** by splitting the strict and change-based behaviors into separate flags, ensuring `--delete-merged` never deletes branches whose changes were independently implemented by another author. The **upstream modification problem** (where squash-merged files are later edited upstream) is handled via a **path-by-path three-way merge approximation** using Git’s low-level merge machinery (`ll_merge`), now with **correct `.gitattributes` support** (index read once before the walk, behavior explicitly documented), **performance optimizations** (single index read), and **explicit documentation** of the attribute-resolution behavior, blob-fetching in partial clones, and edge-case robustness.
