Core problem or goal
Extend `git branch --delete-merged` to recognize branches whose changes (but not their tips) have been integrated into an upstream branch, whether via squash merges (GitHub-style or local `git merge --squash`), rebases, or traditional patch-based workflows (e.g., mailing-list contributions where individual commits are applied upstream). The current implementation only deletes branches whose tips are reachable from the upstream, which fails in all three scenarios. The discussion has expanded to consider a broader user need: a high-level, one-step repository maintenance command (`git full-clean`) that combines branch cleanup and pruning under sensible defaults, addressing real-world frustration where users resort to deleting entire repositories due to maintenance complexity.

The discussion has shifted from a binary config flag (`branch.deleteMergedDetectSquash`) to a CLI option (`--delete-merged=<mode>`), with the author now advocating for a single, unified behavior that works out-of-the-box without requiring users to specify detection modes explicitly. The unresolved tension remains whether to provide a way to disable patch-id detection entirely for performance-sensitive workflows.
