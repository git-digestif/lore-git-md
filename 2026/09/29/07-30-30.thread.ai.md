Core problem or goal
Extend `git branch --delete-merged` to recognize branches whose changes (but not their tips) have been integrated into an upstream branch via squash merges, rebases, or patch-based workflows, including cases where upstream modified the same files before integration. The series provides a practical, one-step repository maintenance command for common forge and local workflows. The CLI design is **finalized**: `--delete-merged <pattern>` for strict tip-reachability (current behavior, unchanged) and `--delete-integrated <pattern>` for change-based detection of rebased *and* squashed branches (opt-in, both methods enabled by default). The series explicitly addresses the **false-positive issue** by splitting the strict and change-based behaviors into separate flags, ensuring `--delete-merged` never deletes branches whose changes were independently implemented by another author. The **upstream modification problem** (where squash-merged files are later edited upstream) is handled via a **path-by-path three-way merge approximation** using Git’s low-level merge machinery (`ll_merge`), now with **correct `.gitattributes` support** (index read once before the walk, behavior explicitly documented), **performance optimizations** (single index read), and **explicit documentation** of the attribute-resolution behavior, blob-fetching in partial clones, and edge-case robustness.

Key technical details
- Files touched: `builtin/branch.c` (preparatory refactoring, landing-message helper, core `--delete-integrated` flag, squash-detection with upstream modifications via three-way merge approximation), `Documentation/git-branch.adoc`, `Documentation/config/branch.adoc`, `t/t3200-branch.sh`.
- New behavior:
  - `--delete-merged <pattern>`: strict tip-reachability only (current behavior, unchanged).
  - `--delete-integrated <pattern>`: change-based detection for rebased *and* squashed branches (opt-in, both methods enabled by default). Handles upstream modifications via a **path-by-path three-way merge approximation** using `ll_merge()` with **correct `.gitattributes` support**, **performance optimizations**, and **explicit documentation** of attribute-resolution behavior, blob-fetching in partial clones, and edge-case robustness. The **author-check mitigation** is required but not yet implemented and does not block integration.
- Output format: `Deleted branch topic (was 1a2b3c4, landed as 9f8e7d6)`.
- Performance optimizations: Rebase detection remains tree-based (no blob fetches); squash-detection uses `ll_merge()` which may **download blobs in partial clones** (explicitly documented). Index is read once before the walk in `find_landed_commits()`.
- Edge cases handled: Upstream modifications to squashed files, reverted changes, partial landings, mixed workflows, "npm update" scenario, automated scripts. New test cases verify `unmerged`, `half-landed`, and `conflicting` branches are not incorrectly deleted.
- Test coverage: Expanded in `t/t3200-branch.sh`; includes Junio’s test case, "npm update" scenario, coverage for `--delete-integrated`, upstream modifications, rebase-merged branches, mixed workflows, and edge-case robustness tests.
- New CLI options:
  - `--delete-integrated <pattern>`: change-based detection for rebased *and* squashed branches. Cannot be combined with `--delete-merged`.
- Config: `branch.<name>.deleteMerged` applies to both flags.
- Symbols:
  - Preparatory patch (v8 1/4): `branch_opted_out()` helper.
  - Landing-message patch (v8 2/4): `landed_commits` strmap, `delete_branches()` helper extended to report landing commit.
  - Core `--delete-integrated` patch (v8 3/4): `DELETE_BRANCH_INTEGRATED` flag, `landing_search` struct, `changed_paths` commit slab, `change_state` enum, `find_landed_commit()` and `find_landed_commits()` helpers.
  - Squash-detection patch (v8 4/4): `merge_keeps_upstream()` function, `ll_merge()`, `.gitattributes` support, test cases for `unmerged`, `half-landed`, `conflicting`.
- **Algorithmic considerations**:
  - **Rebase detection**: Tree-based diffing for exact file matches. The **author-check mitigation** or **patch IDs** are required to address the "npm update" scenario but are not yet implemented.
  - **Squash detection**: Path-by-path three-way merge approximation via `ll_merge()` with correct `.gitattributes` support, performance optimizations, explicit documentation, and edge-case test coverage. Lacks rename detection. The **author-check mitigation** is required to reduce false positives.
