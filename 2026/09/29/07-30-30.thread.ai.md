Core problem or goal
Extend `git branch --delete-merged` to recognize branches whose changes (but not their tips) have been integrated into an upstream branch via squash merges, rebases, or patch-based workflows, including cases where upstream modified the same files before integration. The series provides a practical, one-step repository maintenance command for common forge and local workflows. The CLI design is **finalized**: `--delete-merged <pattern>` for strict tip-reachability (current behavior, unchanged) and `--delete-integrated <pattern>` for change-based detection of rebased *and* squashed branches (opt-in, both methods enabled by default). The series explicitly addresses the **false-positive issue** by splitting the strict and change-based behaviors into separate flags, ensuring `--delete-merged` never deletes branches whose changes were independently implemented by another author. The **upstream modification problem** (where squash-merged files are later edited upstream) is handled via a **path-by-path three-way merge approximation** using Git’s low-level merge machinery (`ll_merge`), now with correct `.gitattributes` support after calling `repo_read_index()` before the merge.

Key technical details
- Files touched: `builtin/branch.c` (preparatory refactoring, landing-message helper, core `--delete-integrated` flag, squash-detection with upstream modifications via three-way merge approximation), `Documentation/git-branch.adoc`, `Documentation/config/branch.adoc`, `t/t3200-branch.sh`.
- New behavior:
  - `--delete-merged <pattern>`: strict tip-reachability only (current behavior, unchanged). Enforced by Junio’s test case to never delete branches whose changes were independently implemented by another author.
  - `--delete-integrated <pattern>`: change-based detection for rebased *and* squashed branches (opt-in, both methods enabled by default). Handles upstream modifications via a **path-by-path three-way merge approximation** using `ll_merge()`, now with **correct `.gitattributes` support** after calling `repo_read_index()`. The **author-check mitigation** is required but not yet implemented.
- Output format: `Deleted branch topic (was 1a2b3c4, landed as 9f8e7d6)` (updated to show landing commit).
- Performance optimizations: Rebase detection remains tree-based (no blob fetches); squash-detection uses `ll_merge()` for upstream modifications, which may **download blobs in partial clones**. The **author-check mitigation** is expected to have minimal performance impact. **New performance concern**: redundant index reads in `merge_keeps_upstream()` (Jasper’s feedback).
- Edge cases handled: Upstream modifications to squashed files (three-way merge approximation with correct `.gitattributes` support), reverted changes, partial landings, mixed workflows, Knoble’s "npm update" scenario, automated scripts, and the upstream modification case (shared file edited on both branch and upstream, then squash-merged). The **author-check mitigation** is required to handle forge workflows and manually applied patches. **New correctness concern**: `.gitattributes` resolution from the wrong tree (Jasper’s feedback).
- Test coverage: Expanded in `t/t3200-branch.sh`; includes Junio’s test case, Knoble’s "npm update" scenario, coverage for `--delete-integrated`, and a new test case for upstream modifications. **No coverage for `.gitattributes`-driven merge scenarios** (though the fix is implemented) or Jasper’s newly identified edge cases (unrelated upstream changes, partial hunk landings, conflicting merges).
- New CLI options:
  - `--delete-integrated <pattern>`: change-based detection for rebased *and* squashed branches (opt-in, both methods enabled by default). Handles upstream modifications via three-way merge with correct `.gitattributes` support. Cannot be combined with `--delete-merged`. The **author-check mitigation** is required but not yet implemented.
- Config: `branch.<name>.deleteMerged` applies to both flags.

- **Algorithmic considerations**:
  - **Rebase detection**: Tree-based diffing for exact file matches. The **author-check mitigation** or **patch IDs** are required to address the "npm update" scenario but are not yet implemented.
  - **Squash detection**: Path-by-path three-way merge approximation via `ll_merge()` to handle upstream modifications. Now with correct `.gitattributes` support in v6, but **new concerns about resolution from the wrong tree** (Jasper’s feedback). Lacks rename detection and is intentionally lenient. The **author-check mitigation** is required to reduce false positives.
