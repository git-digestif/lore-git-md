Core problem or goal: Extend `git branch --delete-merged` to recognize branches whose changes (but not their tips) have been integrated into an upstream branch via squash merges, rebases, or patch-based workflows, including cases where upstream modified the same files before integration. The CLI design is finalized: `--delete-merged <pattern>` for strict tip-reachability (unchanged) and `--delete-integrated <pattern>` for change-based detection of rebased and squashed branches (opt-in, both methods enabled by default). The series splits strict and change-based behaviors into separate flags to prevent `--delete-merged` from deleting branches whose changes were independently implemented by another author. Upstream modification handling uses a path-by-path three-way merge approximation via `ll_merge()` with correct `.gitattributes` support, single index read for performance, and explicit documentation of attribute-resolution and partial-clone blob-fetching behavior.

Symbols and internals (v8 3/4 core machinery): `DELETE_BRANCH_INTEGRATED` flag; `delete_integrated` strvec parsed from `--delete-integrated <pattern>`; `landing_search` struct; `branch_change` array recording each branch's modified paths and blob OIDs relative to merge base; `changed_paths` commit slab caching which paths each upstream commit touches; `change_state` enum; `find_landed_commits()` computes merge bases, collects changed paths, walks upstream commits in reverse; `find_landed_commit()` checks whether any single upstream commit contains the branch's exact version of every changed file using `changes_landed()` and `change_landed()` tree-entry comparisons; when found, branch name mapped to landing commit in a `strmap`. Patch 1/4: `branch_opted_out()` helper extracted from `delete_merged_branches()` for shared opt-out logic. Patch 2/4: `delete_branches()` extended with optional `struct strmap *landed_commits` parameter; skips `check_branch_commit()` for mapped branches and reports `landed as %s` using `strmap_get()` and `repo_find_unique_abbrev()`; behavior-neutral for existing callers passing `NULL`. Patch 4/4: `merge_keeps_upstream()` function using `ll_merge()` for path-by-path three-way merge approximation with `.gitattributes` support (index read once before walk in `find_landed_commits()` via `repo_read_index()`). The `branch_change` struct gains `base_oid`, `upstream_oid`, and `state` fields, with `change_state` enum values `CHANGE_MISSING`, `CHANGE_LANDED`, `CHANGE_NEEDS_MERGE`. `changes_landed()` runs in two passes: first checking for exact tree-entry matches via `change_state_at()`, then invoking `merge_keeps_upstream()` only for paths marked `CHANGE_NEEDS_MERGE`; a change counts as landed if the merge result is byte-identical to the upstream blob (`result.size == upstream.size && !memcmp(...)`).

Confirmed crash edge case and proposed fix (Jasper Mayone): When a path is a gitlink (submodule pointer) in the merge base but regular files on both branch and upstream, `collect_branch_changes()` records `base_oid` as the submodule's commit OID without recording its mode; `change_state_at()` returns `CHANGE_NEEDS_MERGE` because modes match and OIDs differ; `merge_keeps_upstream()` then calls `read_mmblob()` on the commit OID, which dies with `fatal: unable to read blob object <oid>` (type validation in `read_mmblob()` prevents a segfault but aborts the command with no branches deleted). Jasper's proposed fix adds an `unsigned short base_mode` field to `struct branch_change`, populates it in `collect_branch_changes()` from `p->one->mode`, and extends the guard in `change_state_at()` to return `CHANGE_MISSING` when `!S_ISREG(change->base_mode)`; with this applied the branch is correctly kept and `t/t3200-branch.sh` passes. Jasper requests that Harald add a regression test for this scenario.

Algorithmic considerations: Rebase detection is tree-based (no blob fetches) using exact tree-entry comparisons of changed files; the author-check mitigation or patch IDs remain required to address the "npm update" false-positive scenario but are not yet implemented. Squash detection uses `ll_merge()` which may download blobs in partial clones (explicitly documented); lacks rename detection. Test coverage expanded in `t/t3200-branch.sh` (176 lines in patch 3/4 plus additional in 4/4) covering rebase-merged, squash-merged onto upstream-modified files (expecting deletion with "landed as" attribution), reverted, partial-landing, unmerged, conflicting, and "npm update" scenarios; regression test for gitlink-to-blob case requested but not yet added.
