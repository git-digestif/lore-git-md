Core problem or goal: Extend `git branch --delete-merged` to recognize branches whose changes (but not their tips) have been integrated into an upstream branch via squash merges, rebases, or patch-based workflows, including cases where upstream modified the same files before integration. The CLI design is finalized: `--delete-merged <pattern>` for strict tip-reachability (unchanged) and `--delete-integrated <pattern>` for change-based detection of rebased and squashed branches (opt-in, both methods enabled by default). The series splits strict and change-based behaviors into separate flags to prevent `--delete-merged` from deleting branches whose changes were independently implemented by another author. Upstream modification handling uses a path-by-path three-way merge approximation; as of v10 this is a plain text merge via `xdl_merge()` guarded by a new `mergeable_as_text()` helper, ignoring merge drivers from `.gitattributes` so a driver like `union` cannot mask the branch's changes and cause false-positive deletion. v10 also drops the single `repo_read_index()` call added in v6 since the index is no longer consulted for attribute resolution, and fixes a bug where a branch that replaced a file or submodule with a directory was never detected as landed (new `S_ISDIR(mode)` checks in `change_state_at()` and related path comparisons).
