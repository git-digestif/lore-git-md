This is the fourth and final patch in Kaartic Sivaraam’s RFC v2 series improving Git’s error reporting for invalid repository directories when `--git-dir` is explicitly provided. It ties the implementation together by modifying `repo_discover_explicit_gitdir()` in `setup.c` to use the new `is_git_directory_verbose()` helper (introduced in patch 3) and appending detailed failure reasons to error messages.

The patch adds a `strbuf invalid_gitdir_reason` to capture why a directory is rejected (e.g., missing `HEAD`, invalid `GIT_OBJECT_DIRECTORY`, or broken symlinks) and formats it into a two-line error message: the original "not a git repository" line followed by a new "reason:" line. For example, an invalid `GIT_OBJECT_DIRECTORY` now produces:

```
fatal: not a git repository: 'repo.git'
reason: cannot access object directory '/does/not/exist' set via $GIT_OBJECT_DIRECTORY
```

The test updates in `t/t0009-git-dir-validation.sh` verify that the new "reason:" lines appear in error output for the three scenarios covered by the series: missing `HEAD`, invalid `HEAD` symlinks, and misconfigured `GIT_OBJECT_DIRECTORY`. The implementation is narrowly scoped to explicit `--git-dir` usage and leaves repository discovery, `gitfile` handling, and `GIT_ALTERNATE_OBJECT_DIRECTORIES` unchanged for now.

This patch completes the series by integrating the verbose helper into the repository setup code path. The change is mechanical and follows the pattern established in earlier patches: the existing `is_git_directory()` call is replaced with `is_git_directory_verbose()`, and the resulting `strbuf` is formatted into a single `die()` call. The error messages are localized and align with Git’s existing conventions. No substantive objections have been raised to the implementation or error message design, and Junio’s earlier feedback on style and test mechanics has been addressed. The series remains in the RFC phase, awaiting broader feedback on direction before expanding coverage to remaining cases.
