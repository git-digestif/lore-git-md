Subject: [PATCH 0/3] reftable: fix timezone handling in reflog entries
Series version: v1
Originating author: Patrick Steinhardt <ps@pks.im>
Thread type: patch series (bugfix)

Core problem or goal
The reftable backend stores reflog entry timezones in a format ("[+-]HHMM") that violates the reftable specification, which requires signed offsets in minutes. This mismatch causes interoperability issues and a segfault in the `dump-reftable` test helper. The goal is to align Git’s reflog timezone storage with the reftable spec while minimizing user-visible impact.

Current status
Under review; v1 posted. No prior versions.

Key technical details
- Files touched: `date.c`, `date.h`, `refs/reftable-backend.c`, `t/helper/test-reftable.c`, `t/t0610-reftable-basics.sh`, `apply.c`, `strbuf.c`
- New symbols: `parse_timezone_minutes()`, `format_timezone_minutes()`, `tz_to_minutes()`, `minutes_to_tz()`
- On-disk change: reflog timezone offsets are now stored as signed minutes instead of "[+-]HHMM" (applied in patch 3). The change is transparent to the rest of Git: `minutes_to_tz()` converts back to "[+-]HHMM" on read, so only the reftable backend sees the raw minutes.
- Test coverage: new helper functions are exercised in `t0610-reftable-basics.sh`; the segfault in `dump-reftable` is fixed (patch 2); `dump-reftable -t` is now usable for future tests. Patch 3 adds a round-trip test covering edge cases (+1400, +0530). Karthik Nayak requests an additional test case for a negative timezone with non-zero minutes (e.g., `-0530`).
- Backwards compatibility: existing reflog entries will be reinterpreted on read, but the change is limited to display formatting and does not affect core operations. The commit message includes a table showing the divergence between current and correct interpretations.
- Portability: retains C89-compatible behavior for division on negative values.
- Hash ID mapping: patch 2 resolves a mismatch between reftable’s `REFTABLE_HASH_SHA1`/`REFTABLE_HASH_SHA256` and Git’s `GIT_HASH_SHA1`/`GIT_HASH_SHA256` by introducing an explicit switch statement in `t/helper/test-reftable.c`.

Open questions and loose ends
- **Sign-handling in `local_time_tzoffset()`**: Karthik Nayak flags a potential inconsistency in the order of operations: `minutes_to_tz()` is applied to the offset *before* multiplying by `eastwest`, which may invert the intended sign. This is not yet confirmed as a bug but is actionable and may require clarification or a follow-up patch.
- **Test coverage nit**: Karthik requests a test case for a negative timezone with non-zero minutes (e.g., `-0530`) in patch 3. This is a low-risk, surface-level addition.
