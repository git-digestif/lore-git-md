Subject: [PATCH 0/3] reftable: fix timezone handling in reflog entries
Series version: v2
Originating author: Patrick Steinhardt <ps@pks.im>
Thread type: patch series (bugfix)

Core problem or goal
The reftable backend stores reflog entry timezones in a format ("[+-]HHMM") that violates the reftable specification, which requires signed offsets in minutes. This mismatch causes interoperability issues with other reftable implementations (notably JGit) and a segfault in the `dump-reftable` test helper. The goal is to align Git’s reflog timezone storage with the reftable spec while minimizing user-visible impact.

Current status

Key technical details
- Files touched: `date.c`, `date.h`, `refs/reftable-backend.c`, `t/helper/test-reftable.c`, `t/t0610-reftable-basics.sh`, `apply.c`, `strbuf.c`
- New symbols: `parse_timezone_minutes()`, `format_timezone_minutes()`, `tz_to_minutes()`, `minutes_to_tz()`
- On-disk change: reflog timezone offsets are now stored as signed minutes instead of "[+-]HHMM" (applied in patch 3). The change is transparent to the rest of Git: `minutes_to_tz()` converts back to "[+-]HHMM" on read, so only the reftable backend sees the raw minutes.
- Test coverage: new helper functions are exercised in `t0610-reftable-basics.sh`; the segfault in `dump-reftable` is fixed (patch 2); `dump-reftable -t` is now usable for future tests. Patch 3 adds round-trip tests covering edge cases (+1400, +0530, -0830, -0530). Patch 1 consolidates timezone conversion logic in `apply.c`, `date.c`, and `strbuf.c` using the new `tz_to_minutes()` and `minutes_to_tz()` helpers, ensuring consistent behavior across call sites. Patch 2 resolves the hash ID mismatch between reftable’s `REFTABLE_HASH_SHA1`/`REFTABLE_HASH_SHA256` and Git’s `GIT_HASH_SHA1`/`GIT_HASH_SHA256` by introducing an explicit switch statement in `t/helper/test-reftable.c`, fixing the segfault in `dump-reftable -t`.
- Backwards compatibility: existing reflog entries are reinterpreted on read, but the change is limited to display formatting and does not affect core operations. The commit message includes a table showing the divergence between current and correct interpretations.
- Portability: retains C89-compatible behavior for division on negative values. Junio endorsed the explicit sign-flipping logic in `tz_to_minutes()` for clarity, not correctness.
- Sign-handling: `local_time_tzoffset()` now applies `minutes_to_tz(offset) * eastwest` (per Junio’s and Karthik’s suggestion) to better reflect the function’s purpose. The original `minutes_to_tz(offset * eastwest)` was mathematically equivalent but less transparent.
