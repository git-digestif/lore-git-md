## 2026/09/29

- [2026/09/29/07-42-22 by Kazumasa Shigeta <kazumasa.shigeta@kanamei.com>] Kazumasa Shigeta submitted a patch to expose the existing untracked modes `-u`/`--include-untracked` and `-a`/`--all` in `git stash create` by passing the mode through to `do_create_stash()`, while keeping create's existing behavior of only creating objects without updating `refs/stash` or modifying the index/working tree, and translating `do_create_stash()`'s return code 1 (no changes found) to success to preserve the no-object, empty-output behavior.
- [2026/09/29/16-08-08 by Phillip Wood <phillip.wood123@gmail.com>] Phillip Wood reviewed the patch, objecting that changing the exit status from 1 to 0 when there are no changes to stash is not a good idea, and recommending that `PARSE_OPT_STOP_AT_NON_OPTION` be passed to `parse_options()` to prevent option permutation so that a message like "handle new -u flag" is not misinterpreted as an option; he affirmed the idea is fine but said the implementation needs tweaks to be as backward compatible as possible.
