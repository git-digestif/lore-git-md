This is the second patch in Jeff King’s five-patch series converting xdiff’s buffer types from `unsigned long` to `size_t`. Specifically, this patch eliminates the redundant `mmbuffer_t` type by merging it into `mmfile_t`, which is now used uniformly for both input and output buffers throughout the xdiff and merge subsystems.

The change is purely mechanical: every `mmbuffer_t` variable or parameter is replaced with `mmfile_t`, and the `mmbuffer_t` struct definition is removed from `xdiff/xdiff.h`. The patch touches 16 files, including core merge machinery (`merge-ll.c`, `merge-ort.c`), built-in commands (`builtin/merge-file.c`, `builtin/rerere.c`), and documentation (`Documentation/technical/api-merge.adoc`). No new symbols are introduced; the only visible effect is the removal of `mmbuffer_t` from the public API.

The commit message explains that the two types were historically distinct in upstream xdiff but were collapsed into identical `ptr/len` pairs during Git’s initial import in 2006. Peff argues that maintaining two types adds no value and makes it awkward to reuse helpers like `read_mmfile()` for output buffers. He acknowledges the change might be controversial but notes that Git’s xdiff fork has diverged so far from upstream that pulling in further changes is unlikely.

This patch is a prerequisite for later patches in the series that simplify `ll_ext_merge()` and fix integer overflow risks. The diffstat (31 insertions, 37 deletions) reflects the straightforward type substitution. No behavior changes are intended, and existing tests should continue to pass. The only open question is whether reviewers will object to the conceptual consolidation, but the technical implementation looks clean and uncontroversial.
