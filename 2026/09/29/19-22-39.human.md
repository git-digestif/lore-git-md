This is the fourth patch in Jeff King’s five-patch series converting xdiff’s `mmfile_t` buffer sizes from `unsigned long` to `size_t`. Junio C Hamano replies with a **substantive review** that identifies a latent bug in the error-handling logic.

The patch itself is a tiny, mechanical cleanup: it replaces a hand-rolled file-reading loop in `ll_ext_merge()` with a single call to `read_mmfile()`, which was made safe in an earlier patch. Junio’s concern is not with the simplification, but with the assumption that `read_mmfile()` failures can be ignored. He traces the call chain and finds that two callers (`merge-ort.c` and `apply.c`) already treat a NULL `result.ptr` as an error, but `rerere.c` does not, leading to undefined behavior when `fwrite(NULL, 0, 1, f)` is called. Junio proposes a defensive patch that forces any driver claiming success (`LL_MERGE_OK`) while returning a NULL buffer to be treated as `LL_MERGE_ERROR` instead.

The review is thorough, cites specific callers, and includes a ready-to-apply diff. It does not block the series, but it does surface a real edge case that should be addressed before the patch lands.
