This is the fourth patch in the v4 series fixing `git stash` autostash handling of staged index entries. It is a **test-environment fix** (not a code fix) that prevents premature reflog expiration in `t5520-pull.sh`, which was causing flaky test failures when the stash series was merged with `tb/rerere-lock-grace`.

The patch pins `gc.reflogExpire` and `gc.reflogExpireUnreachable` to `never` in the test setup, mirroring a similar fix (`ea7d894f44`) applied to rebase tests. The issue arose because `git pull --rebase` internally uses `git merge-base --fork-point`, which relies on reflog entries for fork-point detection even when an explicit upstream is provided. The stash series’ elimination of `git reset --quiet --refresh` calls reduced the number of reflog entries generated during tests, shifting the timing of auto-maintenance’s reflog expiration and causing the fork-point lookup to fail. This patch ensures the necessary reflog entries persist for the duration of the test.

The change is authored by Thomas Bachem (who diagnosed the root cause) and carried forward by D. Ben Knoble. It is uncontroversial and already merged to `master` as a prerequisite for the stash series. The patch touches only `t/t5520-pull.sh` and has no impact on Git’s runtime behavior outside the test environment. Reviewers focused on the stash series itself can safely treat this as a resolved dependency.
