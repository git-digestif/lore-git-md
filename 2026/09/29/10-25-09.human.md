This is the third patch in Kaartic Sivaraam’s four-part RFC v2 series improving Git’s error reporting for invalid repository directories when `--git-dir` is explicitly provided. The patch introduces `is_git_directory_verbose()`, a new helper function in `setup.c` that mirrors the existing `is_git_directory()` but appends detailed failure reasons to a caller-provided `strbuf`. The function checks the same repository signatures (HEAD, objects directory, refs directory) as its silent counterpart, but now explains why each check fails—for example, “cannot access object directory '/does/not/exist' set via $GIT_OBJECT_DIRECTORY” or “HEAD is a symlink but target lives outside refs/”. The existing `is_git_directory()` is refactored to call the new helper with a NULL `strbuf`, preserving its silent behavior for callers that do not need verbose output.

The implementation is clean and narrowly scoped: it touches only `setup.c` and leaves the rest of the repository setup machinery untouched. The new helper is already structured to support future expansion (e.g., `GIT_ALTERNATE_OBJECT_DIRECTORIES`), though that work is explicitly deferred to follow-up patches. The commit message clearly states the motivation—current “fatal: not a git repository” errors are unhelpful—and the code delivers on that goal without changing any on-disk formats or user-visible behavior yet. The patch looks well-crafted and addresses a real usability pain point; if the RFC direction is accepted, this helper will be the foundation for the improved error messages in the next patch.
