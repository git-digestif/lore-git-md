This is a documentation patch that revises the `git-remote` man page to clarify that all `git remote` commands operate only on the local repository, never modifying the remote itself. The v2 patch adopts Junio’s suggestion from the earlier discussion: instead of adding a targeted clarification to the `set-head` subcommand, it inserts a general statement at the top of the DESCRIPTION section. The new wording explicitly states that `git remote` affects only the local repository’s configuration and refs, and that subcommands like `show`, `prune`, `update`, and `set-head --auto` contact the remote only to read from it. The patch is purely additive—five lines in `Documentation/git-remote.adoc`—and does not alter any code or on-disk formats.

The motivation remains the same as in v1: the current man page wording has been misread as implying remote-side changes, most recently in a Linux MAINTAINERS discussion where someone assumed `set-head` would alter the remote’s `HEAD`. The v2 patch drops the v1’s specific mention that Git offers no client-side mechanism to change a remote’s default branch, since that detail was tied to the now-removed `set-head` paragraph. The range-diff shows the shift from a per-command clarification to a single, up-front statement covering all subcommands.

No technical objections have been raised; the discussion has focused solely on the most effective way to convey the local-only nature of these commands. The patch is well-motivated, small, and uncontroversial, addressing a real source of user confusion with minimal disruption. It is ready for review and likely to be merged once any final wording tweaks are settled.
