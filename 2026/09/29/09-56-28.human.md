This is a bugfix series targeting the reftable backend. Patrick Steinhardt addresses a mismatch between Git's on-disk storage of reflog timezones and the reftable specification, which requires signed offsets in minutes rather than the "[+-]HHMM" format Git currently uses.

The series consists of three patches. The first adds helper functions to convert between the two timezone formats, the second fixes a segfault in the `dump-reftable` test helper, and the third corrects the actual reftable backend implementation. While this change will reinterpret existing reftables, Patrick notes the impact is limited since reflog timezones are only used for display purposes, not computations.

The patches touch core date handling (`date.c`, `date.h`), the reftable backend (`refs/reftable-backend.c`), and test infrastructure (`t/helper/test-reftable.c`, `t/t0610-reftable-basics.sh`). The series is well-motivated with a clear problem statement and includes both the fix and test coverage, suggesting it's a serious, well-considered contribution.

This appears to be a straightforward correctness fix for a recently introduced backend, so it's likely to receive attention from reftable maintainers and reviewers familiar with the format. The change is narrowly scoped to the reftable implementation, so broader impact should be minimal.
