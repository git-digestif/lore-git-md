This is the first patch in a three-part bugfix series for the reftable backend. It introduces helper functions to convert between Git’s traditional "[+-]HHMM" timezone format (e.g., "-0700") and signed-minute offsets, which the reftable specification requires.

The patch adds two new functions to `date.h` and `date.c`: `tz_to_minutes()` and `minutes_to_tz()`. These functions encapsulate the logic previously scattered across the codebase, making it reusable for the reftable backend’s timezone handling. The implementation retains C89-compatible behavior for division on negative values, ensuring portability even though C99 guarantees truncation toward zero.

Four call sites are updated to use the new helpers: `apply.c`, `date.c` (in `gm_time_t` and `match_object_header_date`), and `strbuf.c`. The changes are mechanical and do not alter behavior. The commit message explains the rationale for keeping the C89 workaround, which may reassure reviewers concerned about edge cases.

This patch is a preparatory refactoring with no functional impact on its own. It sets the stage for the next patch, which fixes a segfault in the `dump-reftable` test helper, and the final patch, which aligns the reftable backend’s timezone storage with the specification. The series is well-structured, and this patch is a clean, uncontroversial foundation.
