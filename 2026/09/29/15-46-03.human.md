This is the fourth patch in the v4 series fixing `git stash` autostash handling of staged index entries. The patch itself is a **test-environment fix** that ensures reflog entries critical for `git pull --rebase` fork-point detection are not prematurely expired during tests. The issue surfaced when the stash series (which eliminates `git reset` calls in `stash apply --index`) reduced the number of reflog entries generated during tests, shifting the timing of auto-maintenance’s reflog expiration and causing `git pull --rebase` to fail.

The fix pins `gc.reflogExpire` and `gc.reflogExpireUnreachable` to `never` in `t/t5520-pull.sh`, mirroring a similar fix applied to rebase tests. This is uncontroversial and already merged to `master` as a prerequisite for the stash series. Phillip Wood’s review confirms the changes are correct, though he notes the commit message could be clearer about the root cause: the interaction between the stash series’ removal of `git reset` calls (which previously generated reflog entries) and `git rebase`’s new auto-maintenance behavior. The patch has no impact on Git’s runtime behavior outside the test environment.

For readers following the stash series, this patch is a resolved dependency. The broader series (patches 2–5) is now technically complete, with all prior blockers addressed: the NULL-dereference risk, verbosity regression, bisectability regression, and this test interaction. Junio has confirmed the series is ready for integration. If you’re tracking the stash autostash bugfix, this patch is a minor but necessary part of the solution.
