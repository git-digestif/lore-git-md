This is the second patch in D. Ben Knoble’s five-patch bugfix series for `git stash`, which fixes a bug where autostashing fails to correctly handle staged index entries when `stash.index=true` is set. The series is now in its fourth iteration (v4) and is ready for re-integration after resolving all prior blockers, including a critical NULL-dereference risk in the final patch.

This patch is a preparatory refactoring that moves the initialization of merge options (`init_ui_merge_options`) earlier in `do_apply_stash()`. The change is mechanical: the options are now set up before the conditional logic that handles index merging, rather than after. This paves the way for the next patch, which will reuse these options for the index merge (not just the worktree merge). The commit message is clear and concise, and the diff is small and focused. There are no functional changes here—just a reordering to enable future work.

The patch touches only `builtin/stash.c` and makes no behavior changes, so it should be uncontroversial. It’s a necessary step for the larger fix, which replaces subprocess-based merging (`git diff-tree` and `git apply`) with in-core merging via `merge-ort.c` to avoid race conditions and SIGSEGV risks. Reviewers familiar with the stash or merge code may want to verify that the options are correctly scoped for reuse, but the patch itself looks clean and well-motivated. No test changes are included here, as the real validation will come in later patches.
