This is the third patch in Harald Nordgren’s v4 series introducing a "matching-inspired" fetch mode for shallow repositories. It adds a `--limited-fetch` flag to `git remote add` that explicitly opts a new remote into the new behavior: instead of writing the usual wildcard `remote.<name>.fetch` refspec that tracks every branch, it writes a single `remote.<name>.refmap` entry (`+refs/heads/*:refs/remotes/<name>/*`). This refmap-only remote will then fetch only the branches that local branches already track at that remote, avoiding the slow negotiation of all remote branches that plagues shallow clones.

The implementation is straightforward: the flag is rejected if combined with `-t/--track` or `--mirror` (since those already specify what to fetch), and the configuration logic in `builtin/remote.c` is updated to write the refmap entry instead of the wildcard fetch refspec. Documentation in `git-remote.adoc` explains the new option, and the test suite (`t/t5505-remote.sh`) verifies that it works in non-shallow repositories and correctly rejects incompatible combinations.

This patch is a clean, well-scoped addition that fits neatly into the series’ overall design. It gives users an explicit way to opt into the new fetch mode without waiting for the shallow-repository default (which is handled in the next patch). No substantive objections have been raised against the approach, and the code itself is minimal and focused. If the series lands, this flag will be the primary way users create refmap-only remotes in full repositories.
