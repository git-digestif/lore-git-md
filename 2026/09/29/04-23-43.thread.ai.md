Subject: [RFC] Optional per-repository consent before running local hooks
Series version: RFC (no patch version)
Originating author: Dmytro Lymarenko
Thread type: RFC / design discussion

Core problem or goal
Add an opt-in safety mechanism that requires explicit user consent before Git runs any local hook in a repository the user has not previously marked as trusted. The prompt would show the hook’s path and offer three choices: run once, trust all hooks in the current repository, or decline. For hooks inside the working tree, Git would re-prompt if the script changes. Default behavior remains unchanged.

Current status
Early RFC; no implementation posted. Seeking feedback on the concept.
