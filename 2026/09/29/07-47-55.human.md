This is a CI/build system patch, the first of two in a v2 series improving GitHub Actions leak sanitizer failure reporting. The patch stops leak-sanitizer test scripts at the first failure (using `--immediate`) and annotates leaks with the test script name and full sanitizer output in a collapsible log group.

Harald Nordgren confirms Junio C Hamano’s understanding: once a script has one leak, every subsequent test sees the same accumulated sanitizer log and reports "not ok", burying the real failure. Stopping at the first leak avoids this noise. The change is uncontroversial in principle, but Junio spots a correctness issue in the implementation: the annotation logic is skipped when `--immediate` is set *and* `invert_exit_code` is set, due to an early `exit 0` path. Harald acknowledges the problem and plans to fix it.

The patch itself is small and focused, touching only `ci/lib.sh` and `t/test-lib-github-workflow-markup.sh`. It introduces no new user-facing behavior—only CI workflow improvements—so the risk is low. The correctness fix Junio identified is straightforward and should not derail the series. If addressed promptly, this patch looks ready to graduate. The second patch in the series (regular test failure annotations) is still under review for separate issues.
