This is the second patch in Scott Chacon’s four-part performance series introducing `sha1dc-accel`, a faster SHA-1 collision-detection subsystem for Git. It vectorizes the unavoidable-bitconditions (UBC) check—the expensive filter that rules out 95 % of blocks—using SSE2, AVX2, and NEON instructions, yielding a **1.27–1.29× speedup** over the scalar version.

The patch adds a new `ubc_check.c` file that implements four forms of the UBC check: portable C, SSE2, AVX2, and NEON. Each form uses a solver-generated table of conditions packed into vector lanes for a fast prefix that runs on every block, plus a scalar tail that only runs for the few blocks the prefix leaves alive. The tables are derived from Sam Reis’s Rust `sha1dc` crate and are MIT-licensed. Build-system integration is updated for Makefile, Meson, and CMake, and a new `x86.c` file detects AVX2 availability at runtime. Unit tests verify bit-for-bit compatibility with the original `sha1dc` implementation across all forms, including edge cases where each bit of the message schedule is flipped in turn.

Performance data shows the vectorized forms reduce the UBC check’s cost from ~50 % of compression time to ~20 %, delivering the promised 1.27–1.29× speedup on both x86-64 and ARM64. The patch is well-motivated, technically sound, and includes thorough test coverage, though the mailing list will likely scrutinize the trade-off between code complexity (multiple backends, fallback paths) and performance gains.
