This is the third patch in Jeff King’s five-patch series converting xdiff’s `mmfile_t` buffer sizes from `unsigned long` to `size_t`. It flips the `size` field in the `mmfile_t` struct itself and updates the one place in `diff.c` that prints it (`emit_binary_diff_body`) to use `PRIuMAX` and a cast to `uintmax_t` so the format string matches the new type. The patch is purely mechanical: no logic changes, no new behavior, and no test coverage added. It builds on the memory-leak fix and error-handling cleanup in patch 1 and the `mmbuffer_t` consolidation in patch 2, and it paves the way for the final two patches that deliver the original `ll_ext_merge()` cleanup goal. The diff is tiny (two lines changed) and the commit message explains the rationale clearly: `size_t` is the natural type for buffer sizes, and the change eliminates integer-overflow risks on LLP64 systems (e.g., Windows) where `long` is 32-bit but `size_t` is 64-bit.
