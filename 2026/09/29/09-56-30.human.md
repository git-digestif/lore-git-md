This is the second patch in Patrick Steinhardt’s three-patch series fixing timezone handling in the reftable backend. It addresses a segfault in the `test-tool dump-reftable -t` command, which was previously unused in the test suite but will be needed in the next patch.

The bug occurs because the reftable library’s hash ID values don’t match Git’s internal `GIT_HASH_*` constants. The code previously tried to look up the hash algorithm directly, leading to a NULL pointer dereference. The fix adds a simple switch statement to map reftable’s hash IDs to Git’s constants, ensuring the correct algorithm is used.

The change is minimal (10 lines added, 1 removed) and focused on the test helper (`t/helper/test-reftable.c`). It’s a straightforward correctness fix with no behavioral impact beyond preventing the crash. The patch is well-motivated and unlikely to be controversial, though it highlights a subtle integration issue between Git and the reftable library. This is a necessary precursor to the third patch, which will use this fixed helper to verify timezone formatting.
