This is the third patch in Scott Chacon’s four-patch series introducing `sha1dc-accel`, a faster SHA-1 collision-detection implementation for Git. This patch adds **x86-64 hardware acceleration** using Intel’s SHA-NI instructions (available on Ice Lake and later, and AMD Zen), delivering a **2.07× speedup** on a Xeon test machine. Combined with the vectorized UBC check from patch 2, the series now achieves **2.7× faster SHA-1 throughput** and cuts `index-pack` runtime by **~50%** (both single-threaded and multi-threaded).

The patch implements the SHA-1 compression and recompression steps using `sha1rnds4`, `sha1msg1`, and `sha1msg2` instructions, which process four rounds at a time. It handles two key challenges: (1) the instructions do not expose the expanded message schedule, so the code spills it manually (with shuffles to account for SHA-NI’s reversed word order), and (2) recompression must work forward-only, so it runs the partner block to step 80 to derive the input chaining value, then verifies by running forward again. The implementation includes runtime CPU detection (via `cpuid`), target attributes for safe compilation, and new unit tests that verify bit-for-bit compatibility with the portable SHA-1 step function.
