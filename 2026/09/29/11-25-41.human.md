This is the first patch in a four-part performance series introducing `sha1dc-accel`, a faster SHA-1 collision-detection implementation for Git. The patch lays the groundwork by adding a new block loop around the existing `sha1dc` code, ensuring correctness while enabling the optimizations that follow in later patches.

The patch creates a new `sha1dc-accel/` directory and replaces the direct use of `sha1dc`'s block loop with a new one that works on the same `SHA1_CTX` and disturbance vector (DV) table. For now, it includes only a portable C backend that mimics the original `sha1dc` behavior, so performance is slightly worse (about 4% slower on an M5 Max) due to the added abstraction overhead. The real speedups come in subsequent patches, which add vectorized and hardware-accelerated backends.

Test coverage is thorough: a new unit test (`u-sha1dc.c`) verifies that every backend produces the same results as `sha1dc` across all modes (collision detection, safe hash, UBC filter, and reduced-round collisions) and input splits. The existing `t0013-sha1dc.sh` is extended to test two collision cases (SHAttered and SHA-mbles) against each backend, and a new `test-tool sha1dc-compare` command checks that the new implementation agrees with `sha1dc` in every combination of settings and block splits. The patch also adds a reduced-round collision test vector to exercise the post-collision code paths.

The build system is updated to include the new files in Makefile, Meson, and CMake builds, with a `DC_SHA1_NO_ACCEL` flag to fall back to the original `sha1dc` code. The patch is well-structured and clearly motivated, with detailed commit messages and performance data. The only current backend ("portable") is always available, so there are no platform compatibility concerns yet. The series is part of a broader effort to close the performance gap between collision-detecting SHA-1 and OpenSSL's SHA-1, which lacks detection but is 2.7–2.8× faster.
