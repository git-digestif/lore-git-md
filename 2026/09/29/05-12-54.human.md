This is the first patch in a two-patch bugfix series targeting resource cleanup in Git’s low-level merge driver infrastructure. The patch addresses a latent robustness issue in `merge-ll.c`: when writing temporary files for external merge drivers, the code checks for `write()` errors but ignores `close()` failures. While rare, a delayed write error (e.g., on a network filesystem) could go unnoticed, leaving the process unaware of a failed operation. The fix splits the combined error check into two separate `die_errno()` calls—one for `write_in_full()` and one for `close()`—and updates the error message to include the file path for clarity. The change is purely internal and does not alter user-visible behavior, but it aligns with Git’s defensive programming practices.

The patch is narrowly scoped to the `create_temp()` function in `merge-ll.c` and introduces no new dependencies. It also modernizes the existing error message by marking it for translation and matching the style of other translated messages in the codebase. The v3 iteration refines the implementation to avoid a subtle pattern that could risk file descriptor leaks if copied to other contexts (e.g., functions that return errors instead of calling `die()`). This stylistic improvement was suggested during review and makes the code more obviously correct without changing its behavior.

The series as a whole replaces custom signal handling with Git’s `tempfile` API to ensure atomic cleanup of temporary files (`.merge_file_*`) even when the process is interrupted by SIGINT/SIGQUIT. This patch lays the groundwork for that change by hardening the file-writing logic. The second patch in the series will complete the refactoring by introducing the `tempfile` API. Reviewers, including Elijah Newren, have confirmed the correctness of treating `close()` errors as fatal, and the series has received substantive approval.

No new tests are included, as the change is internal and the existing manual testing by Michal Koutný (the original reporter) confirms the fix works for both regular termination and interrupt scenarios. The patch is uncontroversial and ready for merging, with no open questions or objections. It is part of a well-motivated effort to improve robustness in a rarely exercised but critical code path.
