This is the second patch in Harald Nordgren’s v4 series introducing a "matching-inspired" fetch mode for shallow repositories. It implements the core logic: when a remote has a `remote.<name>.refmap` configured but no `remote.<name>.fetch` refspec, a refspec-less `git fetch` now infers what to fetch by enumerating the local branches whose `@{upstream}` points to that remote.

The patch updates `builtin/fetch.c` to add dynamic branch enumeration in `get_ref_map()` and `do_fetch()`, using a new helper `branches_tracking_remote()` in `remote.c` that iterates over local branches and collects their upstream refs. The inferred branches are passed to the transport’s `ls-refs` command, ensuring only those branches are fetched. Documentation in `config/remote.adoc` and `fetch-options.adoc` is updated to explain the new behavior, and a new test script (`t/t5585-fetch-refmap.sh`) verifies the feature works as intended, including edge cases like duplicate branches, branches tracking other remotes, and `git remote show` compatibility.

This patch directly addresses the slow-fetch problem in shallow repositories by avoiding the negotiation of all remote branches. It is well-motivated, thoroughly tested, and resolves the last substantive design objection (the forced default-branch fetch) from v3. The implementation is clean and integrates naturally with the existing refspec machinery. If the series lands, this patch will be the most impactful change for users of shallow clones.
