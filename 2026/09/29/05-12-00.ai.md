This is the **v3 submission of a bugfix patch series** (now 2 patches) targeting resource cleanup in Git’s low-level merge driver infrastructure. The series ensures temporary files (`.merge_file_*`) created during external merge driver execution are reliably removed even when the process is interrupted by SIGINT/SIGQUIT, replacing custom signal handling with Git’s `tempfile` API for atomic, signal-safe cleanup. The patches are confined to `merge-ll.c` and introduce no functional behavior changes—only robustness improvements.

The v3 iteration drops the unrelated `strbuf_read()` cleanup patch from v2, deferring it to a future series, and incorporates two key refinements: (1) a **stylistic improvement** to split the combined `write_in_full()`/`close()` error check in `create_temp()` into two separate `die_errno()` calls for clarity, avoiding a subtle pattern that could risk file descriptor leaks if copied to other contexts, and (2) a **commit-message tweak** in the second patch to replace "prog" with "program" and adjust attribution to use `Reported-by: Michal Koutný` (resolving a minor phrasing preference). The core logic remains unchanged from v2, which already addressed the latent type-safety bug (a `die()` check for oversized files) and received substantive approval from Elijah Newren.

The series is **ready for merging** and uncontroversial, aligning with Git’s established patterns for resource cleanup. The changes are narrowly scoped to `merge-ll.c`, touching `ll_ext_merge()` and `create_temp()` to use `xmks_tempfile()`, `close_tempfile_gently()`, and `delete_tempfile()`. The new `temp_path_basename()` helper preserves backward compatibility for merge drivers using shell metacharacters in command templates. No automated test coverage exists for interrupt scenarios, but Michal Koutný’s manual testing confirms the fix works for both regular termination and SIGINT. The dropped `strbuf_read()` cleanup is acknowledged as a separate effort, with Peff noting it involves deeper refactoring of the `mmfile_t`/`mmbuffer_t` distinction.

Key technical details for follow-up:
- **Files**: `merge-ll.c` (only file modified).
- **Functions**: `ll_ext_merge()` (refactored to use `tempfile` API), `create_temp()` (split error checks for `write_in_full()`/`close()`), `temp_path_basename()` (new helper).
- **APIs**: `xmks_tempfile()`, `close_tempfile_gently()`, `delete_tempfile()`, `get_tempfile_path()`.
- **Behavior**: Temporary files are now cleaned up atomically via Git’s `tempfile` subsystem, eliminating custom signal handling. `close()` errors after `write()` are treated as fatal (confirmed by Elijah Newren).
- **Edge cases**: Backward compatibility for merge drivers with shell metacharacters; no functional changes to user-visible behavior.
- **Test status**: Lightly tested by Michal; no automated tests for interrupt scenarios (agreed as acceptable by Peff and Michal).
