This is a usability bug report about `git config --list --show-origin`. The author points out that when the command lists configuration sources, it shows the full path for every file *except* `.git/config`, which is displayed as a relative path. This creates confusion because it suggests the `.git` directory is in the current working directory, even when it is actually located higher up in the directory tree. The suggestion is to display the full path to `.git/config` for consistency and clarity.

The report is clear and well-motivated, focusing on a specific, observable behavior that could mislead users. There is no patch attached—this is purely a request for discussion or a future change. The issue is minor but real, and the proposed fix (showing the full path) is straightforward. This is unlikely to be controversial, but it may require coordination with other Git commands that display repository-relative paths to maintain consistency.
