This is an RFC patch series (now v2) from Kaartic Sivaraam that improves Git’s error reporting when a directory is rejected as a valid repository due to explicit `--git-dir` usage. The series adds explanatory "reason" lines to fatal errors, clarifying why Git considers a directory invalid (e.g., missing `HEAD`, inaccessible object directories, or unreadable refs directories). The goal is to help users diagnose misconfigurations more easily by surfacing the underlying cause directly in the error output.

The v2 series consists of four patches, expanding on the original three-patch RFC. The new first patch is a preparatory style fix (normalizing an `if-else` block in `setup.c` to follow project conventions). The second patch adds test coverage for the new error scenarios, the third introduces the `is_git_directory_verbose()` helper function in `setup.c`, and the fourth updates the repository discovery logic to append detailed failure reasons to error messages. The implementation covers explicit `--git-dir` usage and repository validation in `setup.c`, but leaves repository discovery (filesystem walking), `gitfile` handling, and `GIT_ALTERNATE_OBJECT_DIRECTORIES` unchanged for now.

Key technical details include the new `is_git_directory_verbose()` function, which appends failure reasons to a caller-provided `strbuf`, and the refactoring of `repo_discover_explicit_gitdir()` to use a `strbuf invalid_gitdir_reason` for capturing and formatting failure details. The series touches `setup.c` and adds nine test cases in `t/t0009-git-dir-validation.sh` (three existing, three new in the preparatory patch, and three new in the final patch). The error messages now include explanatory lines like "cannot access object directory '/does/not/exist' set via $GIT_OBJECT_DIRECTORY" or "HEAD is missing or unreadable." The existing `is_git_directory()` API remains unchanged, preserving silent behavior for callers that do not need verbose output.

Kaartic has addressed Junio’s feedback from the first RFC iteration: the unnecessary subshell in the test patch was removed, the dead `strbuf_release()` call after `die()` was dropped, and the error message assembly was revised to use a single `die()` call with format arguments (replacing manual `strbuf_addf()` calls). The indentation of `strbuf_addf()` calls in `setup.c` was adjusted to align with the surrounding single-line `} else {` style, with short messages on one line and longer messages split across lines with aligned arguments. The series remains in the RFC phase, with no substantive objections raised to the implementation or error message design.

The motivation is clear and practical: current error messages can be misleading (e.g., blaming the repository directory when the issue is an invalid `GIT_OBJECT_DIRECTORY`). The proposed changes address this by surfacing the underlying cause directly, which could meaningfully improve usability for users debugging repository setup issues. The patch is narrowly scoped to error reporting rather than behavior changes, and the test coverage is thorough. If the direction is well-received, Kaartic plans to expand coverage to the remaining cases (e.g., repository discovery, `gitfile` handling) in follow-up work. The series looks well-crafted and addresses a real pain point for users.
