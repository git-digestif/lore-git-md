This is a **substantive review follow-up** in the ongoing thread about extending `` `git branch --delete-merged` `` to detect squash-merged and rebase-merged branches.

D. Ben Knoble replies to Harald Nordgren’s proposal to hide the new behavior behind a config flag (e.g., `` `branch.deleteMergedDetectSquash` ``). Knoble suggests a more granular approach: a CSV-style option value like `` `--delete-merged=squashed,rebased` ``, allowing users to enable only the detection modes they need. He acknowledges this idea is partly motivated by performance concerns but also considers whether it might serve distinct use cases. His closing reflection—“Mostly I think people just want to go ‘gah, delete merged branches’ and not think about it further”—hints at a preference for simplicity over fine-grained control, leaving the question open for further discussion. No implementation or documentation changes are proposed; the exchange remains conceptual.
