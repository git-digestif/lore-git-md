Thread identity
Subject: [PATCH 0/5] xdiff: switch mmfile_t buffers from unsigned long to size_t
Series version: v1 (initial posting)
Originating author: Jeff King <peff@peff.net>
Thread type: patch series (refactoring + bugfix)

Core problem or goal
Replace `unsigned long` with `size_t` for buffer sizes in the xdiff subsystem (`mmfile_t` struct) to eliminate integer overflow risks during memory allocation and file operations. The series consolidates the redundant `mmbuffer_t` type into `mmfile_t` (patch 2), delivers the original cleanup goal (simplifying `ll_ext_merge()` to use `read_mmfile()`) while ensuring the underlying buffer handling is safe and consistent, fixes a latent memory leak in `read_mmfile()`'s error path (patch 1), adds a defensive NUL-terminator to all `mmfile_t` buffers (patch 5), and now also addresses a latent error-handling bug in `read_mmfile()` where a successful external merge driver exit code (0) with a missing or unreadable output file could return `LL_MERGE_OK` with a `NULL` buffer, leading to undefined behavior in downstream callers.

Key technical details
- Files touched: `xdiff/xdiff.h`, `xdiff/xutils.c`, `xdiff/xmerge.c`, `xdiff-interface.c`, `merge-ll.c`, `merge-ll.h`, `merge-ort.c`, `builtin/merge-file.c`, `builtin/rerere.c`, `rerere.c`, `diff.c`, `Documentation/technical/api-merge.adoc`.
- New/renamed symbols: `mmbuffer_t` removed (merged into `mmfile_t`); `mmfile_t->size` type changed from `unsigned long` to `size_t`; `emit_binary_diff_body()` in `diff.c` updated to use `PRIuMAX` and cast to `uintmax_t` for printing the `size` field; `read_mmfile()` now uses `xmallocz()` to allocate a NUL-terminated buffer.
- Behavior: no intended changes to user-visible behavior; purely mechanical refactoring with the exception of the memory leak fix in `read_mmfile()`, the defensive NUL-termination, and the new error-handling fix in `ll_merge()` to reject `LL_MERGE_OK` with a `NULL` buffer.
- On-disk format: unaffected.
- Test coverage: none added; existing tests should continue to pass, though the new error-handling fix may prevent previously undetected crashes in edge cases.
