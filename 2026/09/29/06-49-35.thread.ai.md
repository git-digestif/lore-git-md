Subject: [PATCH 0/5] xdiff: switch mmfile_t buffers from unsigned long to size_t
Series version: v1 (now expanded to 7 patches with bugfix follow-up for patch 4/5 and regression test)
Originating author: Jeff King <peff@peff.net>
Thread type: patch series (refactoring + bugfix + regression test)

Core problem or goal
Replace `unsigned long` with `size_t` for buffer sizes in the xdiff subsystem (`mmfile_t` struct) to eliminate integer overflow risks during memory allocation and file operations. The series consolidates the redundant `mmbuffer_t` type into `mmfile_t` (patch 2), delivers the original cleanup goal (simplifying `ll_ext_merge()` to use `read_mmfile()`) while ensuring the underlying buffer handling is safe and consistent, fixes a latent memory leak in `read_mmfile()`'s error path (patch 1), adds a defensive NUL-terminator to all `mmfile_t` buffers (patch 5), and addresses a latent error-handling bug in `ll_ext_merge()` where a successful external merge driver exit code (0) with a missing or unreadable output file could return `LL_MERGE_OK` with a `NULL` buffer, leading to undefined behavior in downstream callers. The follow-up patches (6/5 and 7/5) centralize the error check in `ll_ext_merge()` by forcing a driver error (status 129) if `read_mmfile()` fails, converting the result to `LL_MERGE_ERROR` without requiring changes to downstream callers, and add a regression test in `t/t4200-rerere.sh` to reproduce the bug.

Key technical details
- Files touched: `xdiff/xdiff.h`, `xdiff/xutils.c`, `xdiff/xmerge.c`, `xdiff-interface.c`, `merge-ll.c`, `merge-ll.h`, `merge-ort.c`, `builtin/merge-file.c`, `builtin/rerere.c`, `rerere.c`, `diff.c`, `Documentation/technical/api-merge.adoc`, `t/t4200-rerere.sh` (new test).
- New/renamed symbols: `mmbuffer_t` removed (merged into `mmfile_t`); `mmfile_t->size` type changed from `unsigned long` to `size_t`; `emit_binary_diff_body()` in `diff.c` updated to use `PRIuMAX` and cast to `uintmax_t` for printing the `size` field; `read_mmfile()` now uses `xmallocz()` to allocate a NUL-terminated buffer.
- Behavior: no intended changes to user-visible behavior; purely mechanical refactoring with the exception of the memory leak fix in `read_mmfile()`, the defensive NUL-termination, the error-handling fix in `ll_ext_merge()` (converting `LL_MERGE_OK` with a `NULL` buffer to `LL_MERGE_ERROR`), and the new regression test. The fix ensures that downstream callers (e.g., `rerere.c`) no longer dereference `NULL` buffers in edge cases.
- On-disk format: unaffected.
- Test coverage: new regression test in `t/t4200-rerere.sh` reproduces the latent bug by simulating a merge driver that removes read permissions from its output file. Existing tests should continue to pass, and the new test validates the fix.
