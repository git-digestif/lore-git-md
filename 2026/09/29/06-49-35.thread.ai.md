Thread identity
Subject: [PATCH 0/5] xdiff: switch mmfile_t buffers from unsigned long to size_t
Series version: v1 (initial posting)
Originating author: Jeff King <peff@peff.net>
Thread type: patch series (refactoring + bugfix)

Core problem or goal
Replace `unsigned long` with `size_t` for buffer sizes in the xdiff subsystem (`mmfile_t` struct) to eliminate integer overflow risks during memory allocation and file operations. The series consolidates the redundant `mmbuffer_t` type into `mmfile_t` (patch 2), delivers the original cleanup goal (simplifying `ll_ext_merge()` to use `read_mmfile()`) while ensuring the underlying buffer handling is safe and consistent, and fixes a latent memory leak in `read_mmfile()`'s error path (patch 1).

Current status
Under review (no prior versions). Textual conflict exists with the `jk/merge-ll-tempfile-cleanup` topic, but the conflict is minor and Peff has offered to rebase if needed. No merge status reported; no maintainer decision yet.

Key technical details
- Files touched: `xdiff/xdiff.h`, `xdiff/xutils.c`, `xdiff/xmerge.c`, `xdiff-interface.c`, `merge-ll.c`, `merge-ort.c`, `builtin/merge-file.c`, `builtin/rerere.c`, `rerere.c`, `diff.c`, `Documentation/technical/api-merge.adoc`, and other files in the xdiff and merge subsystems.
- New/renamed symbols: `mmbuffer_t` removed (merged into `mmfile_t`); `mmfile_t->size` type changed from `unsigned long` to `size_t`; `emit_binary_diff_body()` in `diff.c` updated to use `PRIuMAX` and cast to `uintmax_t` for printing the `size` field.
- Behavior: no intended changes; purely mechanical refactoring with the exception of the memory leak fix in `read_mmfile()`.
- On-disk format: unaffected.
- Test coverage: none added; existing tests should continue to pass.
