Thread identity
Subject: [PATCH 0/5] xdiff: switch mmfile_t buffers from unsigned long to size_t
Series version: v1 (now 7 patches, including follow-ups for bugfix, regression test, and stylistic test update)
Originating author: Jeff King <peff@peff.net>
Thread type: patch series (refactoring + bugfix + regression test + stylistic test update)

Core problem or goal
Replace `unsigned long` with `size_t` for buffer sizes in the xdiff subsystem (`mmfile_t` struct) to eliminate integer overflow risks during memory allocation and file operations. The series consolidates the redundant `mmbuffer_t` type into `mmfile_t`, delivers the original cleanup goal (simplifying `ll_ext_merge()` to use `read_mmfile()`), fixes a latent memory leak in `read_mmfile()`'s error path, adds a defensive NUL-terminator to all `mmfile_t` buffers, and addresses a latent error-handling bug in `ll_ext_merge()` where a successful external merge driver exit code (0) with a missing or unreadable output file could return `LL_MERGE_OK` with a `NULL` buffer, leading to undefined behavior in downstream callers. The follow-up patches centralize the error check in `ll_ext_merge()` by forcing a driver error (status 129) if `read_mmfile()` fails, converting the result to `LL_MERGE_ERROR` without requiring changes to downstream callers, and add a regression test in `t/t4200-rerere.sh` to reproduce the bug. The final patch updates the regression test to use `rm "$1"` instead of `chmod 0 "$1"` for idiomatic consistency with the test suite.

Key technical details
- Files touched: `xdiff/xdiff.h`, `xdiff/xutils.c`, `xdiff/xmerge.c`, `xdiff-interface.c`, `merge-ll.c`, `merge-ll.h`, `merge-ort.c`, `builtin/merge-file.c`, `builtin/rerere.c`, `rerere.c`, `diff.c`, `Documentation/technical/api-merge.adoc`, `t/t4200-rerere.sh` (new test and stylistic update).
- New/renamed symbols: `mmbuffer_t` removed (merged into `mmfile_t`); `mmfile_t->size` type changed from `unsigned long` to `size_t`; `emit_binary_diff_body()` in `diff.c` updated to use `PRIuMAX` and cast to `uintmax_t` for printing the `size` field; `read_mmfile()` now uses `xmallocz()` to allocate a NUL-terminated buffer.
- Behavior: no intended changes to user-visible behavior; purely mechanical refactoring with the exception of the memory leak fix in `read_mmfile()`, the defensive NUL-termination, the error-handling fix in `ll_ext_merge()` (converting `LL_MERGE_OK` with a `NULL` buffer to `LL_MERGE_ERROR`), and the new regression test. The fix ensures that downstream callers (e.g., `rerere.c`) no longer dereference `NULL` buffers in edge cases. The regression test now uses `rm "$1"` for clarity and idiomatic consistency.
- On-disk format: unaffected.
- Test coverage: new regression test in `t/t4200-rerere.sh` reproduces the latent bug by simulating a merge driver that removes its output file (or makes it unreadable). Existing tests should continue to pass, and the new test validates the fix.
