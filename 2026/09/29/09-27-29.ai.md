This is the second patch in the v4 series introducing a matching-inspired fetch mode for shallow repositories. The email is a follow-up from the author, Harald Nordgren, noting a minor design quibble about the current behavior: when a user runs a bare `git fetch` against a refmap-only remote (one with `remote.<name>.refmap` but no `remote.<name>.fetch` refspec), no branches are fetched at all, which means there are no remote-tracking refs available for `git branch --set-upstream-to` to use. Harald acknowledges this is a small edge case and not a blocker for the current series, but flags it as something that might warrant future discussion.

The thread context confirms this patch implements the core dynamic branch enumeration logic, which infers which branches to fetch by scanning local branches whose `@{upstream}` points to the remote. The forced inclusion of the remote’s default branch (a point of contention in v3) was removed in v4, resolving Junio’s substantive objection. The current implementation is clean, well-tested, and addresses all prior feedback; this follow-up is the only new input in the v4 cycle and does not challenge the patch’s readiness. The series remains under review, with no merge status.
