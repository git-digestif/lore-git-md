This is a usability bug report about `git config --list --show-origin`. The author, Christophe Lohr, points out that when the command lists configuration sources, it prints `.git/config` without the full path, while all other config files (like `/home/user/repo/.git/config` or `/etc/gitconfig`) are shown with absolute paths. This inconsistency can mislead users into thinking the config file is in the current directory rather than the actual repository root.

The suggestion is simple: always show the full path to `.git/config` to match the behavior for other config files. The report is clear and well-motivated, focusing on a real (if minor) source of confusion. No patch is attached, so this is currently just an observation and proposal. If someone picks it up, it would likely be a small, uncontroversial documentation or output-format tweak.
