This is the first patch in Jeff King’s five-part series converting xdiff’s `mmfile_t` buffer sizes from `unsigned long` to `size_t`. It fixes a memory leak in the `read_mmfile()` error path: when the function fails, it leaves the caller responsible for freeing any partially allocated buffer, but some callers (notably `diff_two()` in `builtin/rerere.c`) don’t do this. Peff makes the interface more robust by having `read_mmfile()` itself free the buffer on error, then updates the callers to match.

The patch touches only three files (`xdiff-interface.c`, `builtin/rerere.c`, and `rerere.c`) and is a straightforward cleanup. It doesn’t change behavior—just plugs a leak that would only trigger if `fread()` fails after `fopen()` succeeds, which is rare but possible. The commit message is clear and the diff is minimal, making this a low-risk, well-motivated refactoring that paves the way for the rest of the series.
