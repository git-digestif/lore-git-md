This is the first patch in the v3 series addressing resource cleanup in Git’s low-level merge driver infrastructure. It fixes a latent robustness issue in `merge-ll.c` where `close()` errors after successful `write()` calls were ignored, risking delayed write failures (e.g., on network file systems). The patch splits the combined `write_in_full()`/`close()` error check into two separate `die_errno()` calls, improving clarity and avoiding a subtle pattern that could lead to file descriptor leaks if copied to other contexts. The error messages are also marked for translation and now include the affected path, aligning with Git’s existing conventions.

The change is confined to the `create_temp()` function and is purely internal—no user-visible behavior is altered. The patch is uncontroversial and follows Git’s defensive programming practices, as confirmed by Elijah Newren’s substantive review. The stylistic improvement (splitting the error checks) was incorporated in v3 to address a minor but valid concern about code clarity. No new test coverage is needed, as the fix targets a theoretical edge case that is difficult to reproduce in practice.

This patch pairs with the second patch in the series, which replaces custom signal handling with Git’s `tempfile` API for atomic cleanup of temporary files during interrupts. Together, they modernize the merge driver’s resource management while preserving backward compatibility. The series is ready for merging and expected to graduate to `next` soon.
