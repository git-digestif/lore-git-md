This is a performance-focused patch series that dramatically speeds up SHA-1 collision detection in Git. Scott Chacon (of GitButler) openly acknowledges the code is AI-generated but presents compelling benchmark results: the new implementation is **2.7–2.85× faster** than the current `sha1dc` on both x86 (Xeon) and ARM (M5 Max), reducing the overhead of collision detection from 1.5–2.5× down to just 0.2× relative to OpenSSL’s SHA-1. The series is split into four patches, each introducing a key optimization:

1. A new block loop around `sha1dc`’s context (groundwork, slightly slower but verifiably correct).
2. Vectorized unavoidable-bitconditions (UBC) checks using SSE2, AVX2, and NEON, yielding ~1.3× speedup.
3. Hardware-accelerated compression via x86 SHA-NI instructions (2.07× speedup on Xeon).
4. ARMv8 SHA-1 instruction support (2.4× speedup on M5 Max).

The patches touch the build system (`Makefile`, `meson.build`, `CMakeLists.txt`), add new files under `sha1dc-accel/`, and include thorough tests (collision vectors, unit tests, and performance comparisons). While the AI-generated nature might raise eyebrows, the benchmarks and test coverage suggest this is a serious contribution—worth attention from anyone working on Git’s server-side performance or ARM-based clients. The series is self-contained and doesn’t appear to depend on other ongoing efforts.
