This is a reply from the maintainer to an RFC proposing optional per-repository consent before running local hooks. Junio C Hamano raises a fundamental security concern: if a malicious tool or project setup can install hooks, it could also manipulate the proposed trust mechanism to auto-approve those hooks, rendering the protection ineffective. The observation is brief but substantive, directly challenging the core premise of the RFC by pointing out a potential bypass that would need to be addressed in any implementation. No alternative design or mitigation is suggested yet—this is a conceptual critique aimed at the proposal's feasibility. The thread remains in early discussion, with no patches or further replies at this stage.
