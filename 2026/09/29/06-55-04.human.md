This is the final patch in Jeff King’s five-part series refactoring the xdiff subsystem’s buffer handling. It adds a defensive NUL-terminator to buffers read by `read_mmfile()`, matching a common Git idiom where buffers are allocated with an extra byte to guard against off-by-one errors or accidental string-function use.

The change is tiny (one line in `xdiff-interface.c`) and purely defensive: the commit message acknowledges no known bug, but notes that the original `ll_ext_merge()` code already did this, and the cost is negligible. The patch also removes a special-case hack for empty files, since `xmallocz()` naturally handles zero-length allocations.

This is a classic "belt-and-suspenders" cleanup that fits the series’ overall goal of making the xdiff buffer handling more robust. It’s unlikely to be controversial, but Peff himself calls it "obviously optional" and puts it last in the series, so reviewers may skip it if they’re pressed for time. No new tests are added, and the patch is mechanical enough that existing tests should continue to pass.
