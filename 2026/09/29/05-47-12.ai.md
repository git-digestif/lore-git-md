This is the feature patch for the `git-contacts` stdin enhancement, now at v5 (1/2). The patch itself is unchanged from the merged v4; it modifies `contrib/contacts/git-contacts` to treat a single dash (`-`) as an explicit stdin marker, setting a `$read_from_stdin` flag and passing the stdin filehandle to the existing `scan_patches()` helper. This enables mixed file/stdin usage (e.g., `git contacts patch1 - patch3 <patch2`) and improves interoperability with tools like `b4`.

The implementation is straightforward: it removes the implicit terminal check (`-t STDIN`) and replaces it with an explicit flag, avoiding ambiguity in argument processing order. The feature supports mbox-separated concatenated patches via `git-format-patch`'s `From ` headers, though the documentation (addressed in the follow-up patch) uses singular phrasing for clarity. No new CLI options, symbols, or on-disk formats are introduced.

This patch is already merged to `master`; the v5 submission is part of a two-patch series where the second patch adds documentation. The thread context confirms the feature is uncontroversial and aligns with Git’s established stdin conventions. Key technical details for follow-up: the `-` idiom, the `$read_from_stdin` flag, and the unchanged `scan_patches()` call. The only file touched is `contrib/contacts/git-contacts`.
