This thread is a three-patch series from Patrick Steinhardt fixing a timezone handling bug in Git’s reftable backend. The issue is that Git currently stores reflog timezone offsets in the "[+-]HHMM" format, but the reftable specification requires signed offsets in minutes. This mismatch causes interoperability problems and even a segfault in the `dump-reftable` test helper.

The series is now complete with v1 posted and under review. The first two patches lay the groundwork—adding helper functions for timezone conversion and fixing the segfault in the test helper—while the third patch makes the core change: storing timezones as signed minutes on disk while preserving the "[+-]HHMM" format for the rest of Git. The change is well-tested, with new checks in `t/t0610-reftable-basics.sh` covering edge cases like half-hour offsets. Though this is a breaking change to the on-disk format, the impact is limited because Git only uses reflog timezones for display, not computations.

No reviews have been posted yet, so the series is still awaiting feedback. The patches are narrowly scoped and address a clear spec compliance issue, so they’re likely to be uncontroversial once reviewed.
