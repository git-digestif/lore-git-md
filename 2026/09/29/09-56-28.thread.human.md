This thread is a short bugfix series from Patrick Steinhardt that fixes a timezone-handling mismatch in Git’s reftable backend. The reftable spec requires reflog entry timezones to be stored as signed minutes, but Git was storing them in the format `[+-]HHMM`, causing interoperability issues and a segfault in the `dump-reftable` test helper. The series aligns Git’s storage with the spec while keeping the change transparent to the rest of Git—timezones are converted back to `[+-]HHMM` on read, so only the reftable backend sees the raw minutes.

The series is now effectively ready for integration. Karthik Nayak reviewed the patches, raising a minor test coverage nit (adding a test case for negative timezones with non-zero minutes, like `-0530`), which Patrick has agreed to address in a follow-up. The only remaining work is this surface-level test update; all substantive technical concerns, including sign-handling in `local_time_tzoffset()`, have been resolved. The patches touch `date.c`, `refs/reftable-backend.c`, and related test files, introducing new helper functions like `parse_timezone_minutes()` and `format_timezone_minutes()` to handle the conversion. Existing reflog entries will be reinterpreted on read, but the change is limited to display formatting and doesn’t affect core operations.
