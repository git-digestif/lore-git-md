This thread is a three-patch bugfix series from Patrick Steinhardt addressing a timezone format mismatch in Git’s reftable backend. The reftable specification requires timezone offsets to be stored as signed minutes, but Git currently uses the "[+-]HHMM" format (e.g., "-0700"), causing interoperability issues and a segfault in the `dump-reftable` test helper.

The first patch, just posted, is a preparatory refactoring that introduces helper functions (`tz_to_minutes()` and `minutes_to_tz()`) to convert between the two formats. These functions replace scattered logic in the codebase and ensure portability by handling C89’s division behavior for negative values. The changes are mechanical and do not alter existing behavior, but they lay the groundwork for the subsequent fixes. No reviews have been posted yet, and the series is under initial review. The remaining patches will address the segfault and align the reftable backend’s storage with the specification.
