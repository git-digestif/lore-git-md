This is the first patch in a three-part bugfix series for the reftable backend. It introduces helper functions to convert between Git’s traditional "+HHMM" timezone format (e.g., "-0700") and signed-minute offsets, which the reftable specification requires.

The patch adds `tz_to_minutes()` and `minutes_to_tz()` to `date.h` and updates existing code in `apply.c`, `date.c`, and `strbuf.c` to use them. The commit message explains the C89/C99 portability concern that motivated the original implementation’s careful handling of negative values, and the patch retains that logic for safety even though C99 now guarantees truncation toward zero.

This is a refactoring patch that prepares the ground for the actual reftable fix in patch 3. It is mechanical, well-explained, and unlikely to be controversial. The new helpers are exercised by the existing code paths, so there is no new test coverage here, but the next patch will add specific tests for the reftable backend.
