Thread identity
Subject: `git config --list --show-origin` displays `.git/config` as relative path
Series version: none (standalone bug report)
Originating author: Christophe Lohr
Thread type: usability bug report

Core problem or goal
The `git config --list --show-origin` command displays the full filesystem path for every configuration source *except* `.git/config`, which is shown as a relative path (e.g., `file:.git/config`). This inconsistency can mislead users into thinking the `.git` directory is in the current working directory when it may actually be located higher up in the directory tree.

Current status
Reported; no patch or discussion yet. The issue is minor but actionable, with a straightforward proposed fix: display the full path to `.git/config` for consistency.

Key technical details
- Command: `git config --list --show-origin`
- Subsystem: configuration parsing and display
- Current behavior: `.git/config` shown as relative path (`file:.git/config`)
- Proposed behavior: show full path (e.g., `file:/path/to/repo/.git/config`)
- No on-disk format or CLI option changes; purely a display-layer change
- Test coverage: none yet; would need a new test in `t/t1300-config.sh`

Open questions and loose ends
- Should other Git commands that display repository-relative paths (e.g., `git rev-parse --git-dir`) be updated for consistency?
- Is there a risk of breaking scripts that parse the output of `--show-origin` and expect the relative path form?

Participant positions
- Christophe Lohr (author): reports the inconsistency and proposes showing the full path.
