This is a **bugfix patch** in Jeff King’s ongoing series to switch the xdiff subsystem’s `mmfile_t` buffers from `unsigned long` to `size_t`. It is the first of two follow-up patches (6/5 and 7/5) that address a latent error-handling bug Junio C Hamano identified in patch 4/5: when an external merge driver exits successfully (status 0) but its output file is missing or unreadable, `ll_ext_merge()` would return `LL_MERGE_OK` with a `NULL` buffer, leading to undefined behavior in downstream callers like `rerere.c`.

The patch is a simple refactoring that moves the exit-status conversion immediately after `run_command()`, before `read_mmfile()` is called. This allows the next patch to override the result if reading the output fails, without having to fake an exit status. The change is mechanical and does not alter behavior yet, but it sets up the fix in patch 7/5. The commit message explains why the code cannot skip `read_mmfile()` for non-`LL_MERGE_OK` cases (callers still need the partial output even on conflicts), and why skipping it for `LL_MERGE_ERROR` is not worth the complexity.

The patch touches only `merge-ll.c` and is clearly well-motivated. It is part of a series where patches 1 and 2 are already acked by Junio, and the latent bug in patch 4/5 has been confirmed and addressed by these follow-ups. The fix looks targeted and uncontroversial, and the reproducer script in patch 7/5 provides a clear regression test. This patch is a necessary step toward merging the full series.
