This is the final bugfix patch in Jeff King’s seven-part series converting `mmfile_t` buffer sizes from `unsigned long` to `size_t` in the xdiff subsystem. The patch addresses a latent error-handling bug in `ll_ext_merge()`: when an external merge driver exits successfully (status 0) but its output file is missing or unreadable, the function previously returned `LL_MERGE_OK` with a `NULL` buffer, leading to undefined behavior in downstream callers like `rerere.c`.

The fix is minimal and targeted. It modifies `merge-ll.c` to force a `LL_MERGE_ERROR` return if `read_mmfile()` fails, regardless of the driver’s exit status. This ensures callers receive a clear error signal rather than a misleading success code. The accompanying regression test in `t/t4200-rerere.sh` simulates the bug by using a custom merge driver that removes read permissions from its output file, verifying that `rerere` preserves the conflicted state instead of recording an empty resolution.

The patch is well-motivated and clearly explained. The test is particularly thorough, using a controlled driver to trigger the failure deterministically while avoiding interference with normal rerere operation.
