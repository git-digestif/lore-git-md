This is the sixth patch in Jeff King’s seven-patch series converting `mmfile_t` buffer sizes from `unsigned long` to `size_t` in the xdiff subsystem. The patch is a **bugfix refactoring** that addresses the latent error-handling issue Junio C Hamano identified in patch 4/5: when an external merge driver exits successfully (status 0) but its output file is missing or unreadable, `ll_ext_merge()` currently propagates `LL_MERGE_OK` with a `NULL` buffer, leading to undefined behavior in downstream callers like `rerere.c`.

The fix is mechanical and targeted: it reorders the code in `ll_ext_merge()` to convert the driver’s exit status to an `ll_merge_result` *before* attempting to read the output file. This allows the function to override the result if `read_mmfile()` fails, without faking an exit status or requiring changes to callers. The patch touches only `merge-ll.c` and makes no behavior changes yet—it merely prepares the ground for the actual fix in patch 7/5. The commit message explains why the reordering is safe (callers still need the result even for `LL_MERGE_CONFLICT`) and why skipping `read_mmfile()` for `LL_MERGE_ERROR` isn’t worth the complexity.

This is a well-motivated, minimal change that directly addresses a correctness hole. The patch is part of a series that has already seen thorough review (patches 1 and 2 are acked by Junio, and Phillip Wood called patches 4 and 5 "obviously correct"), and the follow-up in patch 7/5 will complete the fix. The only remaining procedural question is integration order with `jk/merge-ll-tempfile-cleanup`, but Peff has offered to rebase if needed. The series is now effectively ready for merging once the final patches are reviewed.
