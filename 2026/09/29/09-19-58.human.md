This is the final patch in Harald Nordgren’s four-part series introducing a "matching-inspired" fetch mode for shallow repositories. It makes `git remote add` default to `--limited-fetch` when the repository is shallow, ensuring that adding a remote does not trigger a full fetch of all remote branches.

The patch modifies `builtin/remote.c` to check `is_repository_shallow()` and enable `--limited-fetch` by default unless the user explicitly specifies `--no-limited-fetch`, `-t/--track`, or `--mirror`. The documentation in `git-remote.adoc` is updated to explain the new behavior, and the test suite (`t/t5505-remote.sh`) adds four new tests covering edge cases: explicit `-t` in shallow repos, wildcard refspecs in full repos, the shallow default, and `--no-limited-fetch` override.

This change directly addresses the core problem the series targets—slow or hanging fetches in shallow repositories—by ensuring that `git remote add` in a shallow clone does not commit to fetching every branch the remote has. The implementation is backward-compatible: non-shallow repositories continue using wildcard refspecs, and users who want the old behavior can opt out with `--no-limited-fetch`. The patch is technically clean, well-tested, and aligns with the consensus design established in earlier iterations. No substantive objections remain, and the series as a whole looks ready for serious review.
