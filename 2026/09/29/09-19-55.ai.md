This is the first patch in the v4 series implementing the matching-inspired fetch mode for shallow repositories. It introduces the `remote.<name>.refmap` configuration variable, which defines the default `--refmap` value for a remote, mirroring how `remote.<name>.fetch` provides default refspecs.

The patch adds the new configuration to `remote.c`, extending the `struct remote` to include a `refmap` field and updating the config parser to recognize `remote.<name>.refmap`. The `builtin/fetch.c` logic is adjusted so that the effective refmap is either the command-line `--refmap`, the remote’s configured `refmap`, or the remote’s `fetch` refspecs (in that priority order). Documentation is updated in `config/remote.adoc` and `fetch-options.adoc` to describe the new setting, and a test in `t/t5510-fetch.sh` verifies that the configuration behaves identically to the `--refmap` command-line option.

This is a foundational change that enables the later patches in the series. The implementation is clean and well-tested, and the documentation wording is now precise (addressing Junio’s review request in v3). No substantive objections remain on this patch. The new configuration is backward-compatible: existing remotes without a `refmap` continue using their `fetch` refspecs as before.
