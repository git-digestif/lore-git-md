This is a **bugfix** for the HTTP transport layer, concluding the discussion about how to handle libcurl 8.23.0's credential-stripping behavior in redirect detection. The thread settles the last open implementation question: whether to use `CURLINFO_REDIRECT_COUNT` or URL comparison. Jeff King (Peff) tested Patrick Steinhardt's suggestion and found it unreliable because libcurl counts the initial 401→200 auth retry as a redirect, making the count-based approach unsuitable. Patrick now explicitly endorses Peff's original URL-comparison patch, removing the only substantive alternative from consideration.

The patch touches `http.c` and introduces `match_effective_url()`, a helper that strips credentials from the requested URL using libcurl's `curl_url()` interface (available since curl 7.62.0) before comparing it to the effective URL. For older libcurl versions, the extra comparison is skipped. The behavior change is confined to redirect detection; no user-visible changes occur beyond fixing the credential-flushing regression. Test coverage is confirmed via `t5550.15`, which now passes with libcurl 8.23.0+.
