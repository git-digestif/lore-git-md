This is the second patch in Patrick Steinhardt’s three-patch series fixing timezone handling in the reftable backend. It addresses a segfault in the `test-tool dump-reftable -t` command, which was previously unused in the test suite but will be needed in the next patch.

The bug occurs because the reftable library’s hash ID values (`REFTABLE_HASH_SHA1`, `REFTABLE_HASH_SHA256`) do not match Git’s internal `GIT_HASH_SHA1` and `GIT_HASH_SHA256` constants. The original code directly used `hash_algo_by_id()` on the reftable hash ID, leading to an invalid lookup and a NULL pointer dereference. The fix replaces this with an explicit switch statement that maps reftable’s hash IDs to Git’s corresponding constants.

The change is minimal (10 insertions, 1 deletion) and confined to `t/helper/test-reftable.c`. It introduces no new symbols or dependencies, and the logic is straightforward: a direct mapping between two sets of constants. The fix is necessary for the subsequent patch, which will add a test case exercising the `dump-reftable -t` command.

This is a targeted, low-risk bugfix with no user-visible impact. The segfault was previously hidden because the command was unused, but the fix ensures the test helper works correctly for future use. The patch is well-motivated and unlikely to be controversial. Key context for follow-up discussion: the hash ID mismatch is a recurring theme in reftable integration, and this patch resolves one instance of it.
