Subject: [RFC PATCH] submodule: introduce `^/` syntax for root-relative URLs
Series version: RFC (single patch)
Originating author: Stanislav Aleksandrov
Thread type: RFC feature proposal

Core problem or goal
Allow submodule URLs to be specified relative to the superproject’s remote server root, enabling portable forks across arbitrary hierarchy depths (e.g., GitLab subgroups). The `^/` syntax dynamically replaces only the path portion of the superproject’s remote URL, preserving protocol, host, and credentials without manual configuration.

Current status
Under review; no prior versions. The patch remains in RFC phase with no merge status reported. Discussion has clarified the design rationale but not yet resolved whether new syntax is justified.

Key technical details
- New syntax: `^/org/lib.git` resolves against the superproject’s remote URL (e.g., `https://host/me/super.git` → `https://host/org/lib.git`).
- Files touched: `builtin/submodule--helper.c`, `submodule-config.c`, `remote.c` (new `root_relative_url()`), documentation, and tests.
- Symbols: `root_relative_url()` function, new config/CLI handling in submodule code.
- Behavior: opt-in; existing URLs unchanged. Explicitly rejects local paths, `file://`, and helper transports; fails for malformed `^/` URLs that could alter URL type (e.g., changing protocol).
- Test coverage: cloning, syncing, HTTPS/SSH/local forks, nested submodules, remote URL changes, and error conditions (including shell escaping and IPv6 in SCP-style URLs).

Open questions and loose ends
- Shell escaping: `^` is special in `cmd.exe` and Git Bash; users may need quoting. Jacob Keller raised this as a practical concern; the author acknowledges it but does not consider it a blocker.
- Ecosystem adoption: libgit2, JGit, and forges would need to implement the syntax. Jacob Keller questions whether new syntax is justified over existing mechanisms (`url.<base>.insteadOf`, `.gitmodules` extensions). The author argues these alternatives are static and require per-clone setup, while `^/` dynamically resolves against the superproject’s remote URL.
- Relative traversal: Jacob Keller suggested `../../` as an alternative; the author clarified that while it works, it requires knowing the superproject’s depth—a fragile assumption that breaks across forks at different nesting levels. The `^/` syntax avoids this by resolving to the server root.
- IPv6 in SCP-style URLs: Jacob Keller raised this edge case; the author notes the code uses `skip_bracketed_host()` which should handle it, but no explicit test coverage was added.
- Alternatives: Jacob Keller proposed `url.<base>.insteadOf` and `.gitmodules` protocol extensions as potential solutions. The author has addressed these, arguing they are static and require manual configuration, but the design choice of new syntax remains open for debate.

Participant positions

Maintains that `^/` is justified despite alternatives.

Raises alternatives (`insteadOf`, `.gitmodules` extensions) without outright rejection; feedback is constructive and focused on robustness and trade-offs.
