Thread identity
Subject: [RFC PATCH] submodule: introduce `^/` syntax for root-relative URLs
Series version: RFC (single patch)
Originating author: Stanislav Aleksandrov
Thread type: RFC feature proposal

Core problem or goal
Allow submodule URLs to be specified relative to the root of the superproject’s remote server, resolving a long-standing pain point when superprojects are forked into deeper hierarchies (e.g., GitLab subgroups). The `^/` syntax replaces only the path portion of the superproject’s remote URL, preserving protocol, host, and credentials.

Current status
Under review; no prior versions. The patch is self-contained and ready for discussion. No merge status reported; still in RFC phase.

Key technical details
- New syntax: `^/org/lib.git` resolves against the superproject’s remote URL (e.g., `https://host/me/super.git` → `https://host/org/lib.git`).
- Files touched: `builtin/submodule--helper.c`, `submodule-config.c`, `remote.c` (new `root_relative_url()`), documentation, and tests.
- Symbols: `root_relative_url()` function, new config/CLI handling in submodule code.
- Behavior: opt-in; existing URLs unchanged. Fails for remotes without a host (local paths, `file://`, helper transports) and rejects malformed `^/` URLs that could change the URL type.
- Test coverage: cloning, syncing, HTTPS/SSH/local forks, nested submodules, remote URL changes, and error conditions.

Open questions and loose ends
- Shell escaping: `^` is special in `cmd.exe` and Git Bash; users may need quoting. Jacob Keller notes this as a practical concern but does not object to the trade-off.
- Ecosystem adoption: libgit2, JGit, and forges would need to implement the syntax. No objections raised yet, but Jacob Keller questions whether new syntax is justified over existing mechanisms.
- Local paths: `^/` URLs require a `^` directory and `protocol.file.allow=always`; `git submodule add` rejects them. Jacob Keller probed this edge case; the author’s clarification (explicit rejection) is accepted.
- IPv6 in SCP-style URLs: not explicitly tested, but code uses `skip_bracketed_host()` which should handle them. Jacob Keller raised this; no resolution yet.
- Alternatives: Jacob Keller suggests `url.<base>.insteadOf` or `.gitmodules` protocol extensions as potential solutions. The author has not addressed these yet, leaving the design choice of new syntax open for debate.
- Relative traversal: Jacob Keller asks whether `../../` could solve the problem; the author did not respond, implying the current design intentionally limits resolution to the server root.

Participant positions
- Author (Stanislav Aleksandrov): proposes the feature, documents limitations, and provides thorough test coverage. No substantive objections to Jacob Keller’s feedback; clarifies edge cases (shell escaping, local paths).
- Jacob Keller: substantive review engaging with core design (syntax choice, protocol handling) and edge cases (IPv6, local paths, shell escaping). Prefers avoiding new syntax but acknowledges `^/` has precedent. Raises alternatives (`insteadOf`, `.gitmodules` extensions) without outright rejection. Feedback is constructive and focused on robustness.
