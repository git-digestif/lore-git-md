Subject: [RFC PATCH] submodule: introduce `^/` syntax for root-relative URLs
Series version: RFC (single patch)
Originating author: Stanislav Aleksandrov
Thread type: RFC feature proposal

Core problem or goal
Allow submodule URLs to be specified relative to the root of the superproject’s remote server, resolving a long-standing pain point when superprojects are forked into deeper hierarchies (e.g., GitLab subgroups). The `^/` syntax replaces only the path portion of the superproject’s remote URL, preserving protocol, host, and credentials.

Current status
Under review; no prior versions. The patch is self-contained and ready for discussion.

Key technical details
- New syntax: `^/org/lib.git` resolves against the superproject’s remote URL (e.g., `https://host/me/super.git` → `https://host/org/lib.git`).
- Files touched: `builtin/submodule--helper.c`, `submodule-config.c`, `remote.c` (new `root_relative_url()`), documentation, and tests.
- Symbols: `root_relative_url()` function, new config/CLI handling in submodule code.
- Behavior: opt-in; existing URLs unchanged. Fails for remotes without a host (local paths, `file://`, helper transports) and rejects malformed `^/` URLs that could change the URL type.
- Test coverage: cloning, syncing, HTTPS/SSH/local forks, nested submodules, remote URL changes, and error conditions.

Open questions and loose ends
- Shell escaping: `^` is special in `cmd.exe` and Git Bash; users may need quoting.
- Ecosystem adoption: libgit2, JGit, and forges would need to implement the syntax.
- Local paths: `^/` URLs require a `^` directory and `protocol.file.allow=always`; `git submodule add` rejects them.
- IPv6 in SCP-style URLs: not explicitly tested, but code uses `skip_bracketed_host()` which should handle them.
