This is the second patch in Kaartic Sivaraam’s four-part RFC v2 series improving Git’s error reporting for invalid `--git-dir` directories. The patch adds three new test cases to `t/t0009-git-dir-validation.sh` to validate the error scenarios the series aims to enhance: missing `HEAD`, `HEAD` as a symlink pointing outside `refs/`, and an invalid `GIT_OBJECT_DIRECTORY` configuration. These tests complement the preparatory style fix in the first patch and set the stage for the implementation in the third patch, which will introduce the detailed "reason" lines in error messages.

The tests are narrowly focused on the `--git-dir` code path and cover edge cases that currently produce generic "not a git repository" errors. Each test creates a minimal repository setup, deliberately breaks it in a specific way, and verifies that Git rejects the directory. The scenarios are realistic: a missing `HEAD` file, a `HEAD` symlink pointing to a non-ref file, and an object directory that doesn’t exist. The test infrastructure is clean, using `test_when_finished` to ensure cleanup and `test_must_fail` to verify the expected failure.

This patch is purely preparatory and does not change any behavior. Its purpose is to establish the baseline for the new error reporting that the next patch will introduce. The test cases are well-chosen and cover the core failure modes the series addresses. No substantive feedback has been raised on the test design, and the patch looks ready for review alongside the rest of the series. If the RFC direction is accepted, these tests will help ensure the new error messages remain accurate as the code evolves.
