This is the third patch in Kaartic Sivaraam’s four-patch RFC v2 series improving Git’s error reporting for invalid repository directories when `--git-dir` is explicitly provided. The patch introduces `is_git_directory_verbose()`, a new helper function in `setup.c` that mirrors the existing `is_git_directory()` but appends detailed failure reasons to a caller-provided `strbuf`. The function checks the same repository validity conditions (HEAD, object directory, refs directory) but populates the `strbuf` with explanatory messages like "cannot access object directory '/does/not/exist' set via $GIT_OBJECT_DIRECTORY" or "HEAD is a symlink but target lives outside refs/". The existing `is_git_directory()` is refactored to call the new helper with a NULL `strbuf`, preserving its silent behavior for backward compatibility.

The implementation is clean and mechanical: the new helper duplicates the logic of `is_git_directory()` but adds `strbuf_addf()` calls at each failure point, with messages that pinpoint the exact issue (e.g., stat failures, symlink targets, or access errors). The patch touches only `setup.c` and makes no behavioral changes on its own—callers will use the new helper in the next patch. The error messages are localized and follow Git’s existing conventions.
