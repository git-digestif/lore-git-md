This is a feature patch that extends `git branch --delete-merged` to recognize branches whose changes were squash-merged or rebase-merged into an upstream branch, even if the branch tip itself is not reachable. The patch is well-motivated: it addresses a common frustration for users who prefer GitHub-style squash merges but still want to clean up local branches with `--delete-merged`. The commit message explains the problem clearly and shows the new output format (`Deleted branch topic (was 1a2b3c4, landed as 9f8e7d6)`), which helps users understand where their work went.

The implementation is substantial: it adds about 150 lines of C code to `builtin/branch.c`, introducing new helper functions (`collect_branch_changes`, `merge_keeps_upstream`, `change_landed`, `find_landed_commit`) that use diff machinery to determine whether an upstream commit contains all changes from a branch. The logic is careful to handle edge cases like partial landings and reverts, and the patch includes thorough tests in `t/t3200-branch.sh` that cover squash merges, partial merges, and reverts.

The patch is self-contained and does not appear to be part of a larger series. It touches only the branch deletion logic and its documentation, making it easy to review in isolation. The code quality looks solid: the commit message is clear, the tests are comprehensive, and the implementation avoids obvious pitfalls (e.g., it checks file modes and handles null OIDs correctly). This seems like a well-crafted contribution that directly addresses a real user pain point.
