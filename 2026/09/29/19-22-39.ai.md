This is a **substantive review** of Jeff King’s patch 4/5 in the `mmfile_t` refactoring series. Junio C Hamano identifies a latent bug in the error-handling logic: if an external merge driver claims success (exit code 0) but the output file is missing or unreadable, `read_mmfile()` leaves `result->ptr` as `NULL` and `result->size` as `0`, yet the function still returns `LL_MERGE_OK`. Downstream callers treat `NULL` buffers inconsistently—some (like `merge-ort.c`) correctly treat it as an error, while others (like `rerere.c`) pass the `NULL` pointer to `fwrite()`, which is undefined behavior. Junio proposes a follow-up patch that forces any `LL_MERGE_OK` with a `NULL` buffer to become `LL_MERGE_ERROR`, centralizing the safety check in `ll_merge()` rather than relying on every caller to get it right. The fix is small (17 lines) and touches only `merge-ll.c` and `merge-ll.h`, but it plugs a real correctness hole that the original patch exposed.
