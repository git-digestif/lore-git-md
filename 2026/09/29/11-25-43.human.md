This is the third patch in Scott Chacon’s four-part series introducing `sha1dc-accel`, a faster SHA-1 collision-detection implementation for Git. It adds **x86-64 hardware acceleration** using Intel’s SHA-NI instructions (available on Ice Lake and later, and AMD Zen), which perform four SHA-1 rounds at a time. The patch delivers a **2.07× speedup** on a Xeon test machine, bringing the cumulative speedup from the first two patches to **2.7×** over the original `sha1dc` implementation. For `git index-pack`, this translates to a **1.76–1.92× reduction in runtime**, depending on thread count.

The implementation is technically dense but well-explained. It handles two key challenges: (1) SHA-NI instructions do not expose the expanded message schedule, so the code spills it manually as each group of four words is used, and (2) recompression (needed for collision detection) must run forwards from the partner block’s state at step 60 or 64, since the instructions only go forwards. The patch includes thorough unit tests that verify bit-for-bit compatibility with the portable implementation and validate the recompression logic. Build-system integration is minimal (a single Makefile tweak), and the code is guarded by runtime CPU detection and compile-time target attributes, so there is no user-facing configuration.

This patch is clearly **performance-critical** for both servers and clients, particularly for operations like `index-pack` that spend significant time hashing. The speedups are substantial and well-documented, and the code appears to be carefully tested. The main open question is whether the added complexity (multiple platform backends, fallback paths) is justified by the performance gains — a point likely to be debated in review.
