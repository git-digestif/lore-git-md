This is the fourth patch in D. Ben Knoble’s five-patch bugfix series for `git stash` autostash handling. It is a test-environment fix that prevents premature reflog expiration from breaking `t5520-pull.sh`, a test script that exercises `git pull --rebase` behavior.

The patch pins `gc.reflogExpire` and `gc.reflogExpireUnreachable` to `never` in the test setup, mirroring an earlier fix (`ea7d894f44`) for similar issues in rebase tests. The root cause is a subtle interaction between the test’s fixed commit dates (hardcoded to 2005) and Git’s auto-maintenance machinery: since Git 452b12c2e0 (February 2026), `git maintenance run --auto` triggers reflog expiration once HEAD’s reflog accumulates 100 entries. Because the test’s reflog entries all share the same 2005 timestamp, the first maintenance run after the threshold is crossed expires *all* entries, including those critical for `git pull --rebase`’s fork-point detection. This causes the rebase to miscompute its upstream, leading to spurious conflicts.

The fix is minimal—six lines added to `t/t5520-pull.sh`—and uncontroversial. It was originally authored by Thomas Bachem (who diagnosed the issue) and is carried forward in this series with his sign-off. The patch resolves the last known integration blocker for the stash series; without it, the series’ tests would fail when merged into `seen` due to unrelated changes in `tb/rerere-lock-grace`. There is no impact on the stash logic itself—this is purely a test-suite hygiene measure.

The patch is ready for integration and should be merged alongside the rest of the series. Reviewers familiar with test infrastructure or reflog expiration may want to verify the config keys are set in the correct scope, but the approach is standard and has precedent.
