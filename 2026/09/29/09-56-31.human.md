This is the final patch in Patrick Steinhardt’s three-part bugfix series for the reftable backend, targeting a mismatch between Git’s reflog timezone storage and the reftable specification. The series as a whole is a well-motivated, surgical fix for a real interoperability issue that also caused a segfault in the test helper.

This patch (3/3) makes the actual on-disk change: reflog timezone offsets are now stored as signed minutes instead of the traditional "[+-]HHMM" format. The commit message is unusually thorough, walking through the trade-offs and explaining why the breaking change is justified. The fallout is contained because Git only uses reflog timezones for display, not for computation, so existing entries will be misinterpreted only until they are rewritten. The patch includes a new test that verifies both the write path (conversion to minutes) and the read path (conversion back to "[+-]HHMM" for display).

The change touches `refs/reftable-backend.c` and the `dump-reftable` test helper, relying on the helper functions (`tz_to_minutes`, `minutes_to_tz`) introduced in patch 1. The test coverage is solid: it exercises edge cases like +1400 and -1200, and confirms that the display output remains unchanged even though the on-disk format has changed.

This looks like a clean, low-risk fix that should be uncontroversial. The series is ready for review and appears to address the problem completely.
