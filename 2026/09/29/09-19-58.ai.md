This is the fourth and final patch in Harald Nordgren’s v4 series introducing a matching-inspired fetch mode for shallow repositories. It makes `git remote add` default to `--limited-fetch` when the repository is shallow, ensuring that adding a remote to a shallow clone does not trigger a full fetch of all remote branches.

The patch modifies `builtin/remote.c` to check `is_repository_shallow(the_repository)` and enables `--limited-fetch` by default unless `--no-limited-fetch`, `-t/--track`, or `--mirror` is specified. Documentation in `git-remote.adoc` is updated to explain the new default behavior and the `--no-limited-fetch` override. Tests in `t/t5505-remote.sh` verify that the shallow-repository default works as intended, that explicit `-t` still writes a wildcard refspec, that full repositories retain the old behavior, and that `--no-limited-fetch` overrides the default.

This patch completes the series by addressing the original user-facing problem: slow or hanging `git fetch` operations in shallow repositories with many remote branches. The implementation is conservative—non-shallow repositories continue using wildcard refspecs, and users can opt out with `--no-limited-fetch`—so backward compatibility is preserved. No substantive objections have been raised in the v4 cycle, and the patch aligns with the consensus design established in earlier iterations.
