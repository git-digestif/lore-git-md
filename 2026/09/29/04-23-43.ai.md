This is an RFC proposing a new security feature: optional per-repository consent before running local hooks.

The author, Dmytro Lymarenko, suggests adding a safety setting that would require explicit user approval before Git runs any hook in a repository the user hasn't previously trusted. When enabled, Git would show the hook's path and prompt the user to either run it once, trust all hooks in the current repository, or decline to run it. This protection would apply immediately before hook execution, covering both existing hooks and any installed later. For hooks inside the working tree, Git would re-prompt if the script changes. The default behavior would remain unchanged, with this feature enabled only via an explicit user setting.

The motivation appears to be protecting users from malicious or unexpected hooks installed by tools or project setups. The proposal is clearly marked as an RFC, indicating it's seeking feedback rather than being ready for merging. No implementation details or specific configuration options are provided yet, suggesting this is an early-stage concept. The feature would be opt-in, preserving backward compatibility.
