This patch extends `git branch --delete-merged` to recognize branches whose changes have been squash-merged or rebase-merged into an upstream branch, even if the branch tip itself is not reachable from the upstream. The feature addresses a common pain point for users who prefer GitHub-style squash merges: such branches were previously not deleted by `--delete-merged` because their tips do not appear in the upstream history. The patch adds logic to detect when an upstream commit contains all the changes from a branch (by comparing tree diffs and simulating a three-way merge) and reports the first such commit in the deletion message. The implementation touches `builtin/branch.c`, updates the man page, and adds comprehensive tests in `t/t3200-branch.sh`.

The patch is well-motivated: the commit message cites user feedback after Git 2.56 and explains the technical gap clearly. The code is careful to handle edge cases (reverted changes, partial landings) and avoids false positives by requiring that every change from the branch be present in the upstream commit. The new output format (`Deleted branch topic (was 1a2b3c4, landed as 9f8e7d6)`) gives users clear visibility into where their work landed. The test coverage is thorough, including scenarios with reverted squash merges and partial landings. No controversial design choices are apparent; the approach aligns with how GitHub users expect squash-merged branches to behave. The patch is self-contained and does not depend on other in-flight series.
