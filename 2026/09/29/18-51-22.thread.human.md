This thread introduces a new `^/` syntax for submodule URLs, proposed by Stanislav Aleksandrov as an RFC patch. The feature allows submodule URLs to be resolved relative to the root of the superproject's remote server, addressing a long-standing pain point when superprojects are forked into deeper hierarchies (e.g., GitLab subgroups). For example, a superproject at `https://host/me/super.git` with a submodule URL `^/org/lib.git` would resolve to `https://host/org/lib.git`, preserving protocol, host, and credentials.

The implementation is conservative and well-scoped, touching the submodule subsystem (`submodule--helper.c`, `submodule-config.c`) and adding a new `root_relative_url()` helper in `remote.c`. It handles edge cases like local paths, `file://` URLs, and malformed inputs, and includes thorough test coverage for cloning, syncing, and error conditions. The patch is candid about its limitations: the `^` character is special in `cmd.exe` and Git Bash, and adoption would require support from libgit2, JGit, and forges. Local paths starting with `^/` are also rejected unless a `^` directory exists and `protocol.file.allow=always` is set.

The proposal directly addresses a real-world need documented in a GitLab issue, and the implementation avoids breaking existing URLs while adding an opt-in feature. No reviews or objections have appeared yet, so the discussion is still in the early stages. The patch is currently an RFC, so feedback on the design and trade-offs is the next likely step.
