This thread proposes a new `^/` syntax for submodule URLs, allowing them to be specified relative to the superproject’s remote server root. The feature aims to make forks portable across arbitrary hierarchy depths (e.g., GitLab subgroups) by dynamically resolving the path portion of the superproject’s remote URL while preserving protocol, host, and credentials. Stanislav Aleksandrov is the author, and the patch remains in RFC phase.

Junio has indicated the patch will be queued in `seen` once a minor test renumbering (t7427 → t7428) is resolved, which the author has now confirmed. The design—including the `^/` syntax, protocol inheritance, and rejection of local paths—has faced no technical objections, though earlier discussion explored trade-offs with alternatives like `url.<base>.insteadOf` and relative traversal (`../../`). Jacob Keller provided substantive feedback on edge cases (shell escaping, IPv6, fork isolation), but the core proposal stands.

The patch touches `submodule--helper.c`, `submodule-config.c`, and `remote.c`, introducing a new `root_relative_url()` function. Test coverage includes cloning, syncing, HTTPS/SSH/local forks, nested submodules, and error conditions. Open questions remain about ecosystem adoption (libgit2, JGit, forges) and whether the explicit fork isolation semantics will surprise users.
