This is the **v3 submission of a bugfix patch series** for the low-level merge driver infrastructure in Git. The series ensures that temporary files (`.merge_file_*`) created during external merge driver execution are reliably cleaned up even when the process is interrupted by SIGINT or SIGQUIT (e.g., via Ctrl+C). Jeff King (Peff) is the author, incorporating feedback from Michal Koutný and Elijah Newren.

The series is now **trimmed to two patches**, down from three in v2. The dropped patch (which refactored file reading to use `strbuf_read()`) was deemed non-critical and deferred to a future series to avoid scope creep. The remaining patches focus on the core issue: replacing custom signal handling with Git’s `tempfile` API for atomic, signal-safe cleanup. Patch 1 fixes error handling for `close()` after `write()` operations, while Patch 2 implements the `tempfile` conversion, including a new `temp_path_basename()` helper for backward compatibility with merge drivers using shell metacharacters.

Key improvements in v3 include **more granular error reporting** in Patch 1, splitting the combined `write_in_full()`/`close()` check into two separate `die_errno()` calls for clarity and to avoid potential file descriptor leaks in other contexts. The commit message for Patch 2 also adopts Michal Koutný’s preferred `Reported-by:` attribution and clarifies terminology ("program" instead of "prog"). The series remains **uncontroversial** and aligns with Git’s established patterns for resource cleanup. No substantive objections remain, and the changes are confined to `merge-ll.c`.

The series is **ready for merging**, pending Junio’s review. It addresses a real-world annoyance (leftover temporary files after interrupted merges) with minimal risk, and the `tempfile` API is the idiomatic solution for this class of problem. The lack of automated test coverage for interrupt scenarios is acknowledged but not considered a blocker, as the behavior is now more robust and the edge case is rare. If you care about merge driver reliability or signal safety, this series is worth a quick look.
