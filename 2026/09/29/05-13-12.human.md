This is the second patch in a two-part bugfix series that modernizes resource cleanup in Git’s low-level merge driver infrastructure. The patch replaces manual temporary file management with Git’s `tempfile` API, ensuring that `.merge_file_*` files are reliably deleted even when the merge process is interrupted by signals like SIGINT (Ctrl+C). This is a pure robustness improvement—there is no change to user-visible behavior, but the implementation is now signal-safe and follows Git’s established patterns for atomic cleanup.

The patch touches only `merge-ll.c`, refactoring `ll_ext_merge()` and introducing a new helper function, `temp_path_basename()`, to preserve backward compatibility. The original code used short, relative filenames (e.g., `.merge_file_abc123`), but the `tempfile` API returns absolute paths. To avoid breaking merge drivers that rely on shell metacharacters in their command templates (e.g., `my-driver '%A'`), the patch continues reporting relative paths to the driver while internally using absolute paths for cleanup. This is a conservative choice that avoids compatibility risks.

The commit message clearly explains the trade-off: shell-quoting the filenames would be the "correct" solution from a security standpoint, but it could break existing configurations. The patch opts for the safer route, noting that the current behavior is harmless with vanilla relative paths.
