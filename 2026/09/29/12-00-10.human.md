This is a documentation patch for `git remote`. The author revises their earlier proposal to clarify that *all* `git remote` subcommands operate locally, addressing a common user misconception that these commands modify remote repositories. The new version follows Junio Hamano’s suggestion to add a single, general statement at the top of the `git-remote` man page rather than annotating each subcommand individually.

The patch is small, well-motivated, and directly responsive to real-world confusion cited in the commit message. It removes the previous six-line clarification for `set-head` and replaces it with a concise five-line paragraph in the DESCRIPTION section, explicitly stating that `git remote` only affects the local repository and listing subcommands that contact remotes solely for reading. The change is purely textual, with no code or behavior modifications.

The discussion remains open on wording effectiveness, but there are no technical objections. The patch looks like a clear improvement over the current documentation and is likely to be uncontroversial.
