This thread is a usability bug report about `git config --list --show-origin`. Christophe Lohr noticed that when the command lists configuration sources, it shows the full path for every file *except* `.git/config`, which appears as a relative path (e.g., `file:.git/config`). This can mislead users into thinking the `.git` directory is in their current working directory, even when it’s actually located higher up in the filesystem tree. The report suggests making the output consistent by always showing the full path to `.git/config`.

The issue is minor but real, and the proposed fix—displaying the full path—is straightforward. No patch has been submitted yet, so this is currently just a discussion starter. The thread may eventually need to consider whether other Git commands that display repository-relative paths should follow the same convention for consistency. So far, there’s been no response from maintainers or other contributors, so the discussion is still open.
