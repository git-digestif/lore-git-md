The thread is about a minor but confusing inconsistency in `git config --list --show-origin`: while all other configuration sources are displayed with full filesystem paths, `.git/config` appears as a relative path (`file:.git/config`). This can mislead users into thinking the `.git` directory is in their current working directory when it might actually be higher up in the tree.

Christophe Lohr reported the issue, and Patrick Steinhardt acknowledged the confusion but suggested a middle-ground solution—showing the path relative to the current working directory when the user isn’t in the repository root—while also flagging potential script compatibility concerns. Brian M. Carlson has now weighed in, advocating for absolute, canonicalized (symlink-free) paths to match the behavior of other configuration sources. He sees the risk of breaking scripts as low, noting that users can already get the absolute path via `git rev-parse --path-format=absolute --git-path config`.

The discussion is still open, with no patch yet proposed. The main question remains whether to adopt absolute paths (Carlson’s preference) or the intermediate solution (Steinhardt’s proposal). The change would be purely cosmetic—no on-disk or CLI changes—but would need a new test in `t/t1300-config.sh`. The thread is now waiting for broader input on the trade-offs between usability and backward compatibility.
