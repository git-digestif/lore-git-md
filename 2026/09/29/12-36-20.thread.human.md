This thread is about a minor but actionable usability issue in Git’s configuration display. Christophe Lohr reported that `git config --list --show-origin` inconsistently shows `.git/config` as a relative path (`file:.git/config`), which can mislead users about the repository’s true location. The proposed fix is to display the full path for consistency.

Patrick Steinhardt agrees the current behavior is confusing but suggests a middle ground: when the user isn’t in the repository root, the path could be made relative to the current working directory instead of the repository root. He also raises a backward-compatibility concern—scripts parsing `--show-origin` output might expect the relative path form, though he acknowledges the risk is low. The discussion is now open for broader input, with no patch yet proposed. The fix would be a small display-layer change, likely requiring a new test in `t/t1300-config.sh`. No decisions have been made, and the thread remains exploratory.
