This is a test stabilization patch for `t5520-pull.sh`. The patch prevents reflog expiration from breaking a test that relies on reflog entries to compute the fork point during a `git pull --rebase -f` operation.

The issue stems from two upcoming changes: one that eliminates `git reset` calls during `git stash apply --index` (reducing reflog entries), and another that triggers auto-maintenance at the end of `git rebase`. Together, these changes cause reflog expiration to occur at a point where the test expects reflog entries to still exist. Since the test suite hardcodes commit dates to 2005, reflog entries are immediately eligible for expiration under the default `maintenance.reflog-expire.auto` setting, making the test flaky.

The fix disables reflog expiration for the duration of the test by setting `gc.reflogExpire` and `gc.reflogExpireUnreachable` to `never`, following the precedent set by `ea7d894f44` for rebase tests. The patch touches only `t/t5520-pull.sh` and is uncontroversial, with no objections from participants in the thread. Junio C Hamano has already integrated it into the synthetic merge base for D.
