This thread is about Kazumasa Shigeta’s patch series adding `--include-untracked` (`-u`) and `--all` (`-a`) support to `git stash create`, bringing it in line with `git stash push` and `git stash save`. The feature itself is uncontroversial—it reuses existing plumbing (`do_create_stash()`) and doesn’t change the on-disk format or modify the working tree or index. However, Phillip Wood’s review has surfaced two backward-compatibility risks that could break scripts relying on the current behavior.

The first issue is the exit status: the patch changes `git stash create` to exit with 0 when no changes are found (matching `git stash push`), but the current implementation exits with 1. This breaks scripts that depend on the non-zero status to detect when no stash was created. The second issue is option parsing: the patch uses `parse_options()` without `PARSE_OPT_STOP_AT_NON_OPTION`, so flags like `-u` or `-a` appearing after a message argument (e.g., `git stash create "fix bug" -u`) would be treated as options rather than part of the message. Phillip recommends adding the flag to preserve the current behavior, where all arguments after the command are concatenated into the stash message.

The series is still at version 1, and no other reviews have been posted yet. The open questions are now these two compatibility concerns—both fixable, but critical for scripts that might rely on the current behavior. The thread is likely to proceed once the author addresses these points, either by adjusting the implementation or by documenting the changes as intentional (though the latter seems unlikely given the potential for breakage). For now, the series remains under review.
