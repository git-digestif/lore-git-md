This thread is about extending `git stash create` to support the `--include-untracked` (`-u`) and `--all` (`-a`) options already available in `git stash push`. The discussion has broadened to address how to expose more of the underlying `do_create_stash()` functionality without breaking backward compatibility, particularly around the command’s positional message grammar, which treats the rest of the command line as a stash message.

The series is now in the design discussion phase after feedback from Junio C Hamano and Phillip Wood on earlier versions. Three main approaches are under consideration: (1) extending `stash create` with a subset of `stash push` options (e.g., `-u`, `-m`, `--pathspec-from-file`) while preserving backward compatibility, (2) adding a new subcommand like `git stash make` to avoid `create`’s positional message constraints, or (3) adding a `--create-only` flag to `git stash push` to reuse its option grammar while separating creation from application. Junio has expressed a preference for the third option, describing it as "the safest," while Phillip Wood has endorsed extending `stash create` with a carefully chosen subset of options.

The original patch touched `builtin/stash.c`, `Documentation/git-stash.adoc`, and `t/t3903-stash.sh`, adding support for `-u` and `-a` while preserving the existing behavior for `git stash create <message>`. The discussion now centers on which additional options to expose and how to handle edge cases like messages beginning with `-`.
