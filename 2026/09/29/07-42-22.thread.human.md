This thread is about extending `git stash create` to support the `--include-untracked` (`-u`) and `--all` (`-a`) options, bringing it into parity with `git stash push` and `git stash save`. The series, now in its second iteration (v2) by Kazumasa Shigeta, has addressed earlier technical feedback from Phillip Wood but is now facing scrutiny from Junio C Hamano over the clarity and motivation of its commit message.

The core goal is to eliminate a long-standing inconsistency in the stash command family without introducing new behavior or breaking existing scripts. The implementation reuses existing internal plumbing, avoiding on-disk format changes or new code paths. Key changes in v2 include fixing option parsing to prevent misinterpretation of message tokens as flags (e.g., `git stash create adding -u option` now treats `-u` as part of the message, not an option) and aligning the exit status with other stash subcommands. The test suite has also been expanded to cover edge cases like ignored-only worktrees and combined short options (`-ua`).

The author will need to revise the commit message to address these points, particularly the rationale for the design choices and the feature’s scope.
