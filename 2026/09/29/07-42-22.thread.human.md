This thread is about extending `git stash create` to support the `--include-untracked` (`-u`) and `--all` (`-a`) options, bringing it closer to parity with `git stash push`. The goal is to resolve an inconsistency in Git’s stash subsystem while preserving backward compatibility, particularly for scripts that rely on `git stash create`’s positional message syntax.

The discussion has shifted from a narrow feature addition to a broader design question: should `git stash create` support *all* options available in `git stash push` that create a stash, or should it proceed incrementally with a minimal subset?
