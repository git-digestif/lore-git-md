This thread is about adding `--include-untracked` (`-u`) and `--all` (`-a`) options to `git stash create`, bringing it in line with `git stash push` and `git stash save`. The feature is uncontroversial in principle, but the first version raised backward-compatibility concerns around exit status and option parsing. Kazumasa Shigeta has now posted a second version (v2) that addresses those issues by using `PARSE_OPT_STOP_AT_NON_OPTION` to prevent misinterpreting message arguments as flags, and by mapping the internal "nothing to create" status (1) to the public success status (0).

Phillip Wood’s review of the first version identified two key problems: scripts might rely on the old exit status (1 when no changes are found), and flags after message arguments (like `-- -f`) would break. The new version fixes both, and adds thorough test coverage for edge cases like combined short options (`-ua`) and ignored-only worktrees. The implementation remains clean, reusing existing helpers without introducing new code paths or on-disk changes.

The only remaining question is whether the exit status mapping is sufficient for backward compatibility, or if scripts might still expect the old behavior. The patch is otherwise ready for further review or integration.
