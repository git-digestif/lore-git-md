# Thread deltas

## 2026/09/29

- [2026/09/29/12-36-20 by Christophe Lohr <christophe.lohr@cegetel.net>] Christophe Lohr suggested that `git config list --show-origin` display the full path to the `.git/config` file used by the current git command, because the current output showing only `.git/config` gives the impression that the `.git` directory is in the current working directory even when it is located higher up in the directory tree.

## 2026/10/01

- [2026/10/01/06-37-01 by Patrick Steinhardt <ps@pks.im>] Patrick Steinhardt agreed that `git config list --show-origin` showing `.git/config` relative to the repository top-level is confusing, and argued that when not at the repository root the relative path should instead be relative to the current working directory; he expressed uncertainty about whether the path should be absolute, raised the concern that scripts parsing the output might break if the behavior changed, assessed the risk of breakage as comparatively low, and asked what others think.

## 2026/10/02

- [2026/10/02/21-01-02 by brian m. carlson <sandals@crustytoothpaste.net>] brian m. carlson said it would be fine to specify the repository-local config path as an absolute path provided it is canonicalized (symlink-free), noting that other paths in the output are already absolute so callers already handle that case; he agreed the risk of breakage is likely low and noted that `git rev-parse --path-format=absolute --git-path config` can be used to identify which file is the local one among multiple.
