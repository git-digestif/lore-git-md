This is a bugfix series targeting the reftable backend. It addresses a mismatch between Git's on-disk storage of reflog timezones and the reftable specification, which requires signed offsets in minutes rather than the "[+-]HHMM" format used elsewhere in Git.

The series consists of three patches. The first adds helper functions to convert between the traditional "+HHMM" timezone format and the signed-minute offsets required by the reftable spec. The second fixes a segfault in the `dump-reftable` test helper when processing timezones. The third patch updates the reftable backend to store timezones in the correct format, ensuring compatibility with the specification.

The commit message acknowledges that this change will reinterpret existing reflog data but downplays the impact, noting that reflog timezones are only used for display purposes and not for computations. This suggests the fix is safe but may cause minor display inconsistencies in existing reflogs until they are rewritten.

The series touches several subsystems: date handling (`date.c`, `date.h`), the reftable backend (`refs/reftable-backend.c`), and test infrastructure (`t/helper/test-reftable.c`, `t/t0610-reftable-basics.sh`). Key new functions introduced are `parse_timezone_minutes()` and `format_timezone_minutes()`, which handle the conversion between formats.

This is a targeted, well-motivated fix with clear test coverage. The change is mechanical and unlikely to be controversial, though it does involve a breaking change to the on-disk format. The series is built on Git v2.56.0 and appears ready for review.
