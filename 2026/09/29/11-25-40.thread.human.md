This thread is about a patch series from Scott Chacon that introduces `sha1dc-accel`, a faster SHA-1 collision-detection subsystem for Git. The goal is to replace the existing `sha1dc` implementation with one that uses vectorized (SSE2, AVX2, NEON) and hardware-accelerated (x86-64 SHA-NI, ARMv8 SHA-1) instructions, reducing the collision-detection overhead from 1.5–2.5× down to 0.2× relative to OpenSSL SHA-1. This yields a 2.85× speedup in SHA-1 throughput and cuts `index-pack` runtime by about half.

The series is currently under review at v1, with all four patches submitted. Johannes Schindelin initially raised two substantive technical objections: code duplication in the first patch and maintainability concerns about the large `ubc_check.c` tables. Schindelin later addressed the latter by providing a Perl script to regenerate the tables from the original Rust source, improving long-term maintainability. In a recent follow-up, Schindelin introduced a targeted optimization for the x86-64 SHA-NI backend that closes most of the remaining performance gap between the C and Rust implementations. His patch avoids reordering the message schedule in the SHA-NI path, delivering a 1.8% improvement in `index-pack` runtime and leaving the C version only about 1% slower than Rust. He also ran extensive validation across platforms, confirming the C and Rust implementations are now effectively equivalent in speed, and explicitly endorsed merging the series.

The main open question is whether Schindelin’s optimization should be folded into the original series or submitted as a follow-up. The trade-off is between added code complexity (mirrored variants and runtime schedule reversal) and a modest but measurable performance gain. The series has no Reviewed-by or Acked-by trailers yet, but Schindelin’s shift from technical objections to clear support suggests the remaining issues are likely to be resolved. Real-world validation on non-Apple ARMv8 hardware (e.g., Graviton) would still be beneficial, and the code duplication in the first patch needs to be addressed before the series can be accepted.
