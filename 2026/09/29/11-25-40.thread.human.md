This thread is about Scott Chacon’s patch series introducing `sha1dc-accel`, a new subsystem that replaces Git’s existing SHA-1 collision-detection implementation with a faster, vectorized version using platform-specific instructions (SSE2, AVX2, NEON, x86-64 SHA-NI, and ARMv8 SHA-1). The goal is to reduce the overhead of collision detection from 1.5–2.5× down to 0.2× relative to OpenSSL SHA-1, delivering a 2.85× speedup in SHA-1 throughput and a ~50% reduction in `index-pack` runtime. The series is now at v1 and under active review, with Johannes Schindelin having shifted from raising technical objections to endorsing the effort after providing a tested optimization patch that closes most of the remaining performance gap between the C and Rust implementations.

The key technical details include new platform-specific backends, a Perl script to regenerate the large `ubc_check.c` tables from the original Rust source, and unit tests verifying bit-for-bit compatibility across all modes. Performance gains are substantial: single-threaded `index-pack` runtime improves from 16.1s to 8.7s for a 319MB pack, with multi-threaded performance also seeing notable gains. Schindelin’s optimization further reduces runtime by 1.8%, leaving the C implementation only ~1% slower than Rust. However, the series now faces a critical policy hurdle: Junio C Hamano has raised a pointed question about the licensing and provenance of the AI-generated code, asking for concrete assurance that it did not “borrow” from incompatible sources in violation of Git’s AI policy. This is now the sole blocker, as Junio ties the question directly to the legal vetting done by Software Freedom Conservancy lawyers. The thread remains open pending a response from the author to address this licensing concern.
