This thread introduces a new `sha1dc-accel` subsystem to Git, replacing the existing SHA-1 collision-detection implementation with a faster, hardware-accelerated version. The series, authored by Scott Chacon, is now complete at version 1 with four patches. The first two patches established the portable infrastructure and vectorized UBC checks (SSE2, AVX2, NEON), delivering a 1.27–1.29× speedup over the scalar version. The third patch added x86-64 hardware acceleration using Intel SHA-NI instructions, achieving a 2.7× speedup in SHA-1 throughput and a ~50% reduction in `index-pack` runtime. The final patch, just posted, adds ARMv8 hardware acceleration, pushing the speedup to **2.85×** on an Apple M5 Max and further reducing `index-pack` runtime by **1.86×**.

The implementation touches the build system (Makefile, Meson, CMake) and introduces a new `sha1dc-accel/` directory with platform-specific backends for x86-64 (SHA-NI) and ARMv8 (SHA-1 instructions). The code maintains bit-for-bit compatibility with the existing `sha1dc` implementation, verified by extensive unit tests and collision-detection checks. Performance gains are substantial, particularly on modern hardware, though the series has yet to receive substantive technical review. Key open questions include the trade-off between code complexity (multiple backends, fallback paths) and performance, as well as long-term maintainability, especially given the use of AI-generated code. The series remains under review with no maintainer decision recorded.
