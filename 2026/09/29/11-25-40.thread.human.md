This thread is about a patch series from Scott Chacon that replaces Git’s SHA-1 collision-detection implementation with a faster, vectorized version called `sha1dc-accel`. The goal is to cut the performance overhead of collision detection from 1.5–2.5× down to 0.2× relative to OpenSSL’s SHA-1, which lacks collision checks, yielding a 2.7–2.85× speedup in SHA-1 throughput and a ~50 % reduction in `index-pack` runtime. The series is at v1 and under active review.

Johannes Schindelin initially raised two technical concerns—code duplication in the first patch and maintainability of large lookup tables—but has since shifted to a supportive stance after providing a Perl script to regenerate the tables and a tested optimization patch for the x86-64 SHA-NI backend. Sebastian Thiel (gitoxide maintainer) and Sam Reis (original Rust author) have both endorsed the series, and the earlier policy blocker about AI-generated code provenance has been addressed in principle by Reis’s explicit approval and Chacon’s policy proposal.

The main open questions now are licensing and build-system integration. D. Ben Knoble’s recent review highlights a potential policy issue: Git’s existing `sha1dc` code is MIT-licensed, but Git itself is GPL-2-only, creating ambiguity for packagers like Gentoo. Knoble asks whether the new code should match the MIT license or be relicensed to GPL-2. Junio has not yet ruled on this or the series’ readiness, though he acknowledged Schindelin’s contributions. The series is otherwise technically sound, with real-world validation pending on non-Apple ARMv8 hardware.
