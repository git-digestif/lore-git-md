This thread introduces `sha1dc-accel`, a new subsystem by Scott Chacon that replaces Git’s SHA-1 collision-detection code with a faster implementation using vectorized (SSE2, AVX2, NEON) and hardware-accelerated (x86-64 SHA-NI, ARMv8 SHA-1) instructions. The goal is to reduce the collision-detection overhead from 1.5–2.5× down to just 0.2× relative to OpenSSL’s SHA-1, delivering a 2.7–2.85× speedup in SHA-1 throughput and cutting `index-pack` runtime by roughly half.

The series is now at its third patch, which adds x86-64 hardware acceleration via Intel’s SHA-NI instructions (available on Ice Lake and later, and AMD Zen). This patch alone delivers a 2.07× speedup on a Xeon test machine, and when combined with the vectorized UBC check from the second patch, the series now achieves the full projected 2.7× SHA-1 throughput improvement and ~50% reduction in `index-pack` runtime. The implementation handles the low-level challenges of SHA-NI—such as the lack of exposed message schedule and the need for forward-only recompression—with careful manual spilling and shuffling, and includes runtime CPU detection and unit tests for bit-for-bit compatibility.

The series remains under review with no maintainer decision or substantive technical feedback yet. Open questions include the trade-off between code complexity and performance gains, the long-term maintainability of AI-generated code, and build-system integration across platforms. The final patch, which will add ARMv8 SHA-1 hardware acceleration and complete the integration, is still pending.
