This is a review of a feature patch extending `git stash create` to support `--include-untracked` (`-u`) and `--all` (`-a`) options. The patch is part of an ongoing effort to bring parity to the stash command family, and the review from Phillip Wood is substantive, identifying two key backward-compatibility concerns.

Phillip’s review flags two issues in the implementation. First, the patch changes the exit status of `git stash create` when no changes are found: instead of exiting with status 1 (indicating no stash was created), it exits with status 0. This breaks scripts that rely on the exit status to distinguish between "no changes" and "stash created." Second, the patch uses default `parse_options()` behavior, which allows options to appear after the message argument. This means a command like `git stash create handle new -u flag` would now stash untracked files instead of creating a stash with the message "handle new -u flag," violating the principle of least surprise for script authors.

The review is constructive and technically precise, pointing to specific lines in the diff and explaining the implications for script compatibility. Phillip acknowledges the overall goal of the patch ("the idea is fine") but insists on preserving backward compatibility in these two areas. The author, Kazumasa Shigeta, has already signaled openness to feedback, so the next revision is likely to address these points. If fixed, the patch should be uncontroversial and a clear improvement to the stash interface.
