This is the third patch in D. Ben Knoble’s five-patch bugfix series for `git stash`, now at v4. The series fixes a long-standing bug where autostashing fails to correctly handle staged index entries when `stash.index=true` is set, particularly during merge operations.

This specific patch adds a test to `t/t3903-stash.sh` that verifies `git stash apply --index` leaves the working tree and index untouched when it fails due to conflicts. The test sets up a conflicted index state, attempts to apply a stash with `--index`, and checks that the index and working tree remain unchanged after the failure. The test also confirms the error message matches expectations.

The test is a prerequisite for the next patch (4/5), which refactors index handling to use in-core merging via `merge-ort.c`. The new test ensures the refactoring does not regress the existing behavior of failing gracefully on conflicted index merges. Phillip Wood helped design the test, which is straightforward and well-scoped. The patch itself is uncontroversial and ready for integration.
