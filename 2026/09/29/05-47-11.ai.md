This is a documentation follow-up to the now-merged `git-contacts` stdin feature. The series consists of two patches: the first is the already-merged v4 feature patch (allowing `git-contacts` to read patches from stdin via the `-` idiom), and the second adds a single sentence to `git-contacts.adoc` documenting that behavior. The documentation patch is routine and uncontroversial, touching only the AsciiDoc file in `contrib/contacts/` to clarify that a dash reads from stdin.

The feature itself was motivated by interoperability with external tools like `b4` and enables mixed file/stdin usage (e.g., `git contacts patch1 - patch3 <patch2`). The implementation treats `-` as an explicit stdin marker, avoiding implicit terminal checks and setting a flag to pass the stdin filehandle to the existing `scan_patches()` helper. No new CLI options, symbols, or on-disk formats were introduced.

The thread context confirms the feature patch is already in `master`, so this v5 submission is solely about landing the documentation update. The only minor uncertainty—whether the wording should account for multiple concatenated patches from stdin—was noted by Junio but deferred for future consideration. The documentation patch addresses the immediate need without overcommitting to untested behavior.

This is a low-risk, high-clarity update. The files touched are confined to `contrib/contacts/`, and the change aligns with established Git conventions for stdin handling. No further technical discussion is expected, and the patch is ready to apply. Key details for follow-up: the new documentation line reads "A single dash `'-'` reads a patch from the standard input," and the feature supports mbox-separated concatenated patches via `git-format-patch`'s `From ` headers.
