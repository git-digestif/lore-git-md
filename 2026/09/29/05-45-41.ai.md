This is a post-merge discussion about test precision in the already-merged `git reflog expire` regression fix. Patrick Steinhardt replies to Junio C Hamano’s defense of the current test timing thresholds (60/100 days for reachable entries, 20/40 days for unreachable). Patrick acknowledges Junio’s point about avoiding `approxidate()` edge cases but argues that the current test values (60 and 100 days) are too loose to meaningfully verify the 90-day expiry policy—they could mask bugs where the actual expiry period is anywhere between 60 and 100 days. He suggests 88 days as a tighter, still-safe alternative that would better reflect the intended 90-day behavior without risking flakiness. The exchange remains purely about test hygiene; no code changes are proposed or needed, and the fix itself remains merged to `master`. Key technical detail: the test uses `test-tool date timestamp` to simulate aged reflog entries, and Patrick’s concern is about the precision of the test’s assertions, not the expiry logic itself.
