This is the second patch in the v3 series addressing resource cleanup in Git’s low-level merge driver infrastructure. It replaces manual temporary file management with Git’s `tempfile` API to ensure atomic, signal-safe cleanup of `.merge_file_*` files when the merge process is interrupted (e.g., by SIGINT). The patch is narrowly scoped to `merge-ll.c` and introduces no functional behavior changes—only robustness improvements.

The core change is the refactoring of `ll_ext_merge()` and `create_temp()` to use `xmks_tempfile()`, `close_tempfile_gently()`, and `delete_tempfile()` instead of manual `xmkstemp()`/`unlink()` calls. A new helper, `temp_path_basename()`, preserves backward compatibility for merge drivers that use shell metacharacters in command templates (e.g., `'%A'`), ensuring relative paths are still reported despite the `tempfile` API’s use of absolute paths. The commit message explains the trade-off: shell-quoting filenames would break existing configurations, so the conservative approach (relative paths) is retained.

Key technical details include the replacement of the `temp[3][50]` array with three `struct tempfile *` variables (`tmp_o`, `tmp_a`, `tmp_b`), and the use of `get_tempfile_path()` to retrieve absolute paths for file operations. The patch also removes the manual `unlink_or_warn()` loop in favor of `delete_tempfile()`, which handles cleanup atomically. The `strbuf`-based command construction remains unchanged, but now uses `temp_path_basename()` to insert relative paths into the shell command.

The patch addresses a latent edge case: merge drivers with shell metacharacters in their command templates (e.g., spaces in directory names) would fail if absolute paths were used without proper quoting. The solution (`temp_path_basename()`) avoids breaking existing configurations while maintaining signal-safety.
