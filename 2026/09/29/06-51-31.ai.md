This is the first patch in Jeff King’s 5-patch series converting xdiff’s `mmfile_t` buffer sizes from `unsigned long` to `size_t`. It fixes a memory leak in the `read_mmfile()` error path by ensuring the function itself frees any allocated buffer when it fails, rather than leaving cleanup to the caller. The patch also tidies up two callers (`diff_two()` and `rerere_forget_one_path()`) that no longer need to handle the error case manually.

The change is a small but meaningful step toward making the xdiff buffer interface less error-prone. It touches `xdiff-interface.c`, `builtin/rerere.c`, and `rerere.c`, with a net diff of +7/-3 lines. No new symbols are introduced; the patch is purely about fixing a latent leak and simplifying error handling. The leak itself is unlikely to be triggered in practice (it requires `fread()` to fail after `fopen()` succeeds), but the fix is a clear improvement to the code’s robustness.
