This is an RFC feature patch introducing a new `^/` syntax for submodule URLs, allowing them to be resolved relative to the root of the superproject's remote server. The patch is well-structured, with a clear commit message, thorough documentation updates, and comprehensive test coverage.

The motivation is practical: relative paths like `../lib.git` break when a superproject is forked into a deeper hierarchy (e.g., GitLab subgroups), while absolute URLs force a specific protocol on all contributors. The `^/` syntax (borrowed from `svn:externals`) resolves this by replacing only the path portion of the superproject's remote URL, preserving protocol, host, and credentials. For example, `https://host/me/super.git` with `^/org/lib.git` becomes `https://host/org/lib.git`.

The implementation touches the submodule subsystem (`builtin/submodule--helper.c`, `submodule-config.c`), adds a new `root_relative_url()` function in `remote.c`, and updates documentation and tests. The patch handles edge cases: it fails for remotes without a host (e.g., local paths, `file://`, or helper-based transports), and rejects malformed `^/` URLs that could change the URL type (e.g., `^//evil.com`). Tests cover cloning, syncing, and error conditions across HTTPS, SSH, and local forks.

The RFC section in the commit message candidly addresses trade-offs: the `^` character is special in `cmd.exe` and Git Bash, and the syntax would require adoption by libgit2, JGit, and forges. The patch also notes that local paths starting with `^/` would need a `^` directory and `protocol.file.allow=always`, and are rejected by `git submodule add`. These limitations are clearly documented in the man pages.

The patch is part of a real-world need: GitLab has an open issue requesting this exact functionality. The implementation is careful and conservative, avoiding behavior changes for existing URLs while adding a new, opt-in feature. The test suite is particularly thorough, covering nested submodules, remote URL changes, and error cases. The only notable omission is explicit handling of IPv6 addresses in SCP-style URLs, but the code appears to handle them correctly via `skip_bracketed_host()`.
