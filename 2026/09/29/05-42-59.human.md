This is a **bugfix** for the HTTP transport layer, wrapping up the discussion on how to handle libcurl 8.23.0's credential-stripping behavior in redirect detection. The thread is now settled: Patrick Steinhardt, after initially suggesting a cleaner alternative (`CURLINFO_REDIRECT_COUNT`), has accepted Jeff King's original approach using URL comparison with credential stripping. The reason is practical—libcurl counts the initial 401→200 auth retry as a redirect, making the count unreliable for detecting actual URL changes.

The patch itself is small and targeted, touching only `http.c` and introducing a helper function `match_effective_url()` that uses libcurl's `curl_url()` interface to strip credentials before comparing URLs. This ensures redirect detection works correctly with newer libcurl versions while maintaining compatibility with older ones (the extra comparison is skipped for curl < 7.62.0). Junio C Hamano has already endorsed the implementation as "very sensible," and the patch is on track for merging.

No user-visible behavior changes are expected beyond fixing the credential-flushing regression, and the existing test `t5550.15` now passes with libcurl 8.23.0+. The discussion is closed—no further alternatives or objections remain, and the author has ruled out the count-based approach after testing. This looks like a clean, well-motivated fix that addresses a real-world compatibility issue without introducing complexity. Worth noting for anyone tracking HTTP transport or libcurl compatibility.
