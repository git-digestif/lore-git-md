Harald Nordgren's v9 series extends `git branch` with a `--delete-integrated <pattern>` flag that detects branches whose changes were absorbed via rebase or squash-merge, complementing the existing strict `--delete-merged`. The four-patch series splits tip-reachability from change-based detection to avoid deleting branches whose work was independently implemented upstream, using tree-entry comparisons for rebase detection and `ll_merge()` three-way merges for squash detection with upstream modifications. V9 itself is a bugfix iteration: it adds a `base_mode` guard and regression test fixing a type-confusion crash when a branch replaces a submodule with a regular file while upstream does the same, a fix supplied by Jasper Mayone after Junio identified the reachable `read_mmblob()` death path.

Junio C Hamano has now acknowledged that the v8-to-v9 diff -- the `base_mode` guard and its test -- looks acceptable, though he explicitly notes this blessing covers only the incremental fix, not the correctness of earlier versions or the series as a whole. The series therefore remains under review with no integration branch status announced. Earlier in the thread, Junio confirmed the CLI design separating `--delete-merged` from `--delete-integrated`, but he has since raised design questions about the `branch_opted_out` helper naming and default semantics in patch 1/4, questioned whether `branch.<name>.deleteMerged` is the right config key for the new flag (suggesting a future-proof `deleteDone` alternative), and identified test-coverage gaps for `--dry-run` combined with `--delete-integrated`, the config opt-out with the new flag, and `--quiet` behavior. He also argues that `--dry-run` should work without requiring a delete-mode flag so it can report non-deletion reasons like a checked-out branch.

Still unresolved are the major technical gaps and open design choices. The "npm update" false-positive scenario -- where unrelated upstream changes to the same files could trick change-based detection into deleting a branch -- remains unmitigated; proposals for author-checks or patch-ids from Jasper Mayone and D. Ben Knoble have not been implemented. Phillip Wood's requests for clearer documentation of limitations such as the lack of rename detection are only partially addressed. The series is functionally complete at v9 and the crash fix is blessed, but it awaits resolution of Junio's config-key and dry-run semantics questions and the missing test coverage before it can be considered ready for integration.
