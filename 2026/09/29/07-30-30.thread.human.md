This thread is about a patch series (`v7`) by Harald Nordgren that extends `git branch --delete-merged` to detect branches whose changes were integrated via squash merges, rebases, or patch-based workflows—even when the upstream later modified the same files. The new `--delete-integrated` flag (opt-in) handles both rebase-merged and squash-merged branches by default, using a three-way merge approximation to account for upstream edits. The CLI design is finalized and explicitly approved by Junio, with strict and change-based behaviors split into separate flags to avoid false positives.

The series is now technically complete and ready for integration. All substantive review feedback has been addressed in `v7`: performance inefficiencies (redundant index reads) are fixed, the `.gitattributes` resolution behavior is explicitly documented, and new test cases verify edge-case robustness (e.g., partial landings, conflicting merges). The first two patches (refactoring and a landing-message helper) are uncontroversial and ready for merging, while the third (`--delete-integrated` flag) and fourth (squash-detection with upstream modifications) are now complete after addressing feedback from Jasper Mayone and Junio. The only remaining gap is the *author-check mitigation*—a proposed safeguard to prevent false positives in forge workflows (e.g., "npm update" scenarios)—but this does not block integration.

Key participants include Harald (author), Junio (maintainer), Jasper (reviewer who provided detailed feedback and test cases), and Phillip Wood (who raised documentation and algorithmic concerns). The series touches `builtin/branch.c`, adds new test coverage, and introduces symbols like `merge_keeps_upstream()` (for squash-detection) and `DELETE_BRANCH_INTEGRATED` (the core flag). Open questions remain about whether to implement the author-check mitigation or alternative approaches (e.g., patch IDs), but the current implementation is considered production-ready.
