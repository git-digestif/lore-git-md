Harald Nordgren's v11 series proposes a new `git branch --delete-integrated <pattern>` flag that detects branches whose changes have landed upstream via rebase or squash merge, complementing the existing strict tip-reachability `--delete-merged`. The series is split into five patches: pure refactoring to extract the config opt-out helper, plumbing for "landed as" reporting in `delete_branches()`, `--dry-run` support for plain `-d`/`-D` with operation-specific error messages, tree-based rebase detection, and blob-based squash detection using `xdl_merge()`. Version 11 refines v10 by making `--dry-run` error messages name the unsupported operation (creation, renaming, copying) rather than emitting a generic message, while Harald maintains that universal `--dry-run` support should wait for a follow-up series.

Junio C Hamano has driven much of the design discussion, questioning whether the existing `branch.<name>.deleteMerged` config key should govern the new change-based mode or whether a separate key is needed, and arguing that mature commands like `git branch` should signal future `--dry-run` support with "not supported yet" rather than neutral wording. Reviewers Phillip Wood, D. Ben Knoble, and Jasper Mayone have raised substantive concerns about false positives when another author independently makes identical changes (the "npm update" scenario), suggesting author-checks or patch-ids as mitigation, none of which are implemented yet. Phillip Wood also called for clearer documentation of limitations such as lack of rename detection. The series remains under review with no integration status announced; open questions include the appropriate config key for `--delete-integrated`, performance on large repositories, and whether to adopt patch-ids or `git range-diff` for improved accuracy.
