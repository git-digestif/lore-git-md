Harald Nordgren’s patch proposes extending `git branch --delete-merged` to detect branches whose changes (but not their tips) have been squash-merged or rebase-merged into an upstream branch, addressing a long-standing pain point for users of GitHub-style "Squash and merge" or local `git merge --squash` workflows. The initial implementation is under review, with no prior versions, and touches `builtin/branch.c` and its documentation. The patch simulates a three-way merge to detect when an upstream commit contains all changes from a branch, handling edge cases like reverted changes and partial landings, and includes comprehensive test coverage.

Two reviewers—Kristoffer Haugsbakk and D. Ben Knoble—have engaged substantively, clarifying the patch’s scope (both local and forge-style squash merges) and exploring implementation trade-offs. Haugsbakk reinforced the motivation by noting the prevalence of squash merges due to tooling defaults, while Knoble raised potential optimizations (e.g., leveraging `git log --cherry-mark` for rebase cases) and flagged performance concerns. The author has addressed some of these by reporting speed improvements and proposing a config flag (`branch.deleteMergedDetectSquash`) to let users opt in, though Knoble later suggested a more granular CLI option (`--delete-merged=squashed,rebased`) for finer control. No objections or requests for changes have been raised, and the discussion remains additive, focusing on balancing simplicity, performance, and flexibility. A v2 is anticipated to expand the commit message with workflow examples and contextual notes.
