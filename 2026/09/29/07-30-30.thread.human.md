This thread introduces a new feature for `git branch --delete-merged` to detect branches whose changes (but not their tips) have been squash-merged or rebase-merged into an upstream branch. The current implementation only deletes branches whose tips are reachable, which misses common workflows like GitHub's "Squash and merge" or local `git merge --squash`.

Harald Nordgren submitted the initial patch, which is now under review. The patch touches `builtin/branch.c` and updates the documentation, adding logic to compare tree diffs and simulate three-way merges to detect when all changes from a branch are present in an upstream commit. Tests cover edge cases like reverted squash merges and partial landings. While the feature is self-contained and doesn't depend on other in-flight work, Harald plans a v2 to expand the commit message with examples of both GitHub-style and local squash-merge workflows, addressing feedback from Kristoffer Haugsbakk and D. Ben Knoble.

The discussion has been substantive but additive so far. Kristoffer Haugsbakk clarified that the patch handles both local and forge-style squash merges, reinforcing its motivation by noting the widespread adoption of squash merges due to tooling defaults. D. Ben Knoble explored potential optimizations (like using `git log --cherry-mark` or short-circuiting the squash check) and raised performance concerns, which Harald addressed by reporting noticeable speed improvements in the latest implementation. Harald also suggested adding a config flag (e.g., `branch.deleteMergedDetectSquash`) to let users opt into the feature, leaving the performance question open for further discussion. No objections or requests for changes have been raised yet, and the thread remains focused on refining the feature's implementation and documentation.
