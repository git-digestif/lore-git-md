This thread is about Harald Nordgren’s patch series introducing `git branch --delete-integrated`, a new flag that extends `git branch --delete-merged` to detect branches whose changes (but not their tips) have been integrated via squash merges, rebases, or patch-based workflows. The series is now in its fourth iteration, with the CLI design finalized as `--delete-merged` for strict tip-reachability and `--delete-integrated` for change-based detection of rebased and squashed branches.

The latest update, the fourth patch in v4, addresses a key real-world scenario: when upstream modifies the same files after a squash merge, the branch’s exact tree is no longer present in the squash commit. The patch implements a path-by-path three-way merge to detect these cases, ensuring the branch is still deleted even when upstream changes overlap. This approach may download blobs in partial clones, a trade-off noted in the documentation. The test suite now includes a case for this scenario, and the output format has been updated to show both the branch’s old tip and the landing commit (e.g., `Deleted branch topic (was 1a2b3c4, landed as 9f8e7d6)`).

The first two patches—preparatory refactoring and a landing-message helper—are uncontroversial and ready for integration. The third and fourth patches, which introduce the core `--delete-integrated` flag and squash-detection logic, remain under review. A critical open issue is the "npm update" scenario, where a branch’s changes might be independently implemented by another author, leading to false positives. Jasper Mayone proposed an author-check mitigation (requiring the landing commit’s author to have authored at least one commit on the branch), but this is not yet implemented. Other unresolved questions include whether to adopt patch IDs or `git range-diff` for rebase detection, how to improve squash-detection accuracy, and whether to document the algorithm’s limitations more explicitly. Performance trade-offs, particularly for large repositories or blobless clones, also remain unaddressed. The series is under active review, with Junio having confirmed the CLI design and safety constraints.
