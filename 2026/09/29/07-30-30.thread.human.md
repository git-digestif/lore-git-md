This thread introduces a small but useful enhancement to `git branch --delete-merged`: it now detects branches whose changes (but not their tips) have been squash-merged or rebase-merged into an upstream branch. The current version only deletes branches whose tips are reachable, which misses common GitHub-style "Squash and merge" workflows and local `git merge --squash` operations.

Harald Nordgren sent the initial patch, which adds logic to compare tree diffs and simulate a three-way merge to determine if all changes from a branch are present in an upstream commit. The patch includes tests for edge cases like reverted changes and partial landings, and it prints a helpful message like `Deleted branch topic (was 1a2b3c4, landed as 9f8e7d6)`. Kristoffer Haugsbakk reviewed the patch and suggested expanding the commit message to clarify that the feature handles both GitHub-style squash merges and local `git merge --squash` workflows. Harald agreed to update the commit message in a v2.

The discussion has been constructive and focused on improving documentation rather than code. Kristoffer noted that while `git merge --squash` likely inspired forge-style squash merges, the forge implementations (like GitHub’s) popularized the pattern by offering a more polished user experience. No technical objections or new edge cases have been raised, and the patch remains under review with no major changes expected beyond the commit message update.
