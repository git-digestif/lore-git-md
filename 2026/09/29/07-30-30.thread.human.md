Harald Nordgren has posted version 11 of a five-patch series that adds a new `--delete-integrated` flag to `git branch`, designed to recognize branches whose changes have been integrated upstream via squash merges or rebases even when the branch tip itself is not reachable. The series splits detection into two complementary methods: patch 4/5 uses a tree-based comparison that checks whether any single upstream commit contains the exact file versions from the branch, which works for rebased branches and remains cheap in partial clones because it never reads blob contents; patch 5/5 extends this with a three-way text merge via `xdl_merge()` for squash merges where upstream also modified the same files, treating a change as landed only when the merge result is byte-identical to upstream while deliberately ignoring `.gitattributes` merge drivers to avoid false positives. Alongside the new flag, v11 refines `--dry-run` support so it works with plain `-d`/`-D` deletions and emits operation-specific error messages when combined with unsupported operations like renaming or copying, addressing feedback from maintainer Junio C Hamano.

Junio has been actively engaged in shaping the CLI design and semantics, questioning whether the existing `branch.<name>.deleteMerged` config opt-out should apply to the new change-based detection or whether a separate key is needed, and debating whether error messages should hint at future support using "not supported yet" given that `git branch` is a mature command. Reviewers Jasper Mayone, D. Ben Knoble, and Phillip Wood have raised substantive concerns about correctness and safety, particularly the "npm update" false-positive scenario where another author independently makes identical changes; they have proposed author-check mitigation or patch-ids to address this gap, which remains unimplemented. Phillip Wood has also called for clearer documentation of limitations such as the lack of rename detection, while performance on very large repositories remains an open question.

The series is currently at v11 and remains under review with no integration status announced. The five patches cover a pure refactoring to extract `opted_out_of_delete_merged()`, plumbing in `delete_branches()` to report landed commits, the `--dry-run` relaxation, tree-based rebase detection, and the squash-merge detection just described. Open questions include whether to implement author verification or patch-id comparison to prevent false deletions, whether to add rename detection, whether a separate config key is needed for the new flag, and whether to pursue a conceptual `git full-clean` command instead.
