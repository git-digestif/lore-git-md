This thread introduces a small but useful quality-of-life improvement for Git users: extending `git branch --delete-merged` to detect branches whose changes have been squash-merged or rebase-merged into an upstream branch, even when the branch tip itself isn’t part of the upstream history. The feature is particularly relevant for workflows involving GitHub’s "Squash and merge" or local `git merge --squash` commands, where the original branch tip is discarded but the changes live on in a new commit.

Harald Nordgren authored the patch, which is currently under review. The implementation is self-contained, touching only `builtin/branch.c` and the documentation, and includes thorough test coverage for edge cases like reverted changes and partial landings. Kristoffer Haugsbakk provided a substantive review, noting that the patch’s scope extends beyond GitHub-style merges to include local squash workflows—a point Harald plans to clarify in the commit message for the next version. No technical objections or requests for changes have been raised so far, and the discussion has focused on improving the documentation rather than the code itself.

The patch is ready for a v2 with an expanded commit message, unless other reviewers surface additional feedback. If no further concerns arise, it’s likely to proceed toward integration.
