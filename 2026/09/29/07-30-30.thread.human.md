This thread extends `git branch --delete-merged` to detect branches whose changes have been integrated via squash merges or rebases, even when the branch tip itself isn’t reachable. Harald Nordgren’s v3 series reorganizes the work into three patches—rebase detection, squash detection, and a `--no-squashed` flag—addressing Junio C Hamano’s earlier architectural concern that the two workflows require distinct algorithms.

The core debate now centers on how to implement each detection method. Junio suggests reusing `git range-diff`’s commit-matching logic for rebases, which considers log messages and authorship alongside patch IDs, while D. Ben Knoble argues that patch IDs alone would be more reliable for local rebases with edited messages. For squash merges, the current approach (path-by-path three-way merge approximation) is intentionally lenient—it checks whether the upstream commit *contains* the branch’s changes, not whether it’s an exact squash merge—but this can lead to misleading attribution (e.g., labeling a branch as "landed" in a commit with unrelated modifications). Junio proposes locally simulating squash merges or using message-based matching for better accuracy, while Phillip Wood suggests stricter alternatives like patch IDs or test merges.

The series is under active review, with key questions still unresolved: whether to adopt Junio’s two-phase approach (rebase detection first, squash detection later), how to handle edge cases like edited commit messages, and whether the CLI should evolve toward finer-grained controls (e.g., `--delete-merged=rebased,squashed`). Harald has clarified that rename detection isn’t a reliable signal for branch integration, but the algorithm’s leniency remains a point of contention. Performance optimizations (batching, blob fetching) and blobless clone support are implemented, but the trade-offs for large repositories are still being discussed. The broader `git full-clean` proposal—a high-level maintenance command combining this feature with pruning operations—remains conceptual.
