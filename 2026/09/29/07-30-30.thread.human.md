This thread is about extending `git branch --delete-merged` to detect branches whose changes (but not their tips) have been integrated into an upstream branch via rebases, squash merges, or other workflows. Harald Nordgren’s v3 patch series implements this with a three-part approach: preparatory refactoring, rebase detection (this email), and squash detection with an opt-in `--squashed` flag.

The rebase-detection patch itself is uncontroversial and ready for integration. It uses fast tree-based diffing to identify branches whose changes appear in an upstream commit, even if the branch tip isn’t directly reachable. This handles common workflows like GitHub’s “Rebase and merge” button efficiently, without fetching blobs, making it suitable for partial clones. The output format remains consistent (`Deleted branch topic (was 1a2b3c4, landed as 9f8e7d6)`), and test coverage is thorough.

The larger debate centers on whether this functionality should remain under `--delete-merged` or be split into a new `--delete-irrelevant` option, as proposed by Junio C Hamano. Harald argues for keeping rebase and squash detection unified under `--delete-merged`, prioritizing workflow efficiency, while Junio emphasizes safety and predictability, warning that looser detection could lead to false positives (e.g., deleting branches whose changes were independently implemented by others). Jasper Mayone’s real-world testing reinforced this concern, showing that v2 incorrectly deleted such a branch. The squash-detection algorithm’s leniency—checking for *containment* of changes rather than exact equivalence—further complicates the debate, as it may misattribute changes in the output.

Performance optimizations (batching via `changed_paths` slab) and blobless clone support are preserved, but the CLI design remains unresolved. Harald’s rejection of Junio’s split leaves the series in limbo, with no clear consensus on how to balance safety, usability, and performance. The first patch (refactoring) is uncontroversial, but the broader architectural question lingers.
