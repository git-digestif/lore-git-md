This thread is about Harald Nordgren’s patch series adding a `--delete-integrated` flag to `git branch --delete`, which extends the command to detect branches whose changes (but not their tips) have been integrated into an upstream branch via squash merges, rebases, or patch-based workflows—even when upstream modified the same files before integration. The series is now in its seventh iteration (v7) and consists of four patches: preparatory refactoring, a landing-message helper, the core `--delete-integrated` flag, and squash-detection with upstream modifications via a three-way merge approximation.

The CLI design is finalized and explicitly confirmed by Junio Hamano: `--delete-merged` retains its strict tip-reachability behavior (unchanged), while `--delete-integrated` is an opt-in flag that detects both rebased and squashed branches by default. The series addresses the false-positive issue by splitting the behaviors into separate flags, ensuring `--delete-merged` never deletes branches whose changes were independently implemented by another author. The upstream modification problem (where squash-merged files are later edited upstream) is handled via a path-by-path three-way merge using Git’s low-level merge machinery, now with correct `.gitattributes` support, performance optimizations, and explicit documentation of edge cases and blob-fetching behavior in partial clones.

All substantive review feedback has been addressed in v7. Jasper Mayone, who raised key concerns in v6 about performance, correctness, and edge-case robustness, has now confirmed that all three issues are resolved. The performance inefficiency (redundant index reads) was fixed by reading the index once before the walk, the `.gitattributes` resolution behavior is now explicitly documented, and new test cases verify edge cases like unmerged, partially landed, and conflicting branches. Tuomas Ahola’s surface-level editorial suggestions were also incorporated. The first three patches are explicitly uncontroversial and ready for integration, while the fourth (squash-detection) is now technically complete after Jasper’s final confirmation. The only remaining gap for the series is the unimplemented author-check mitigation (Jasper’s proposal to require the landing commit’s author to have authored at least one commit on the branch being deleted), which addresses the "npm update" scenario and forge workflows but does not block integration.

Key participants include Harald Nordgren (author), Junio Hamano (maintainer, who confirmed the CLI design and addressed a correctness issue in v5), Jasper Mayone (reviewer who provided Tested-by and confirmed all issues resolved in v7), and Phillip Wood (who called for clearer documentation of limitations like lack of rename detection). The series is ready for Junio’s queue, with the author-check mitigation as the sole major technical gap for future work.
