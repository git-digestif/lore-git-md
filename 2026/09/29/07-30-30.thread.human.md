This thread covers Harald Nordgren's patch series extending `git branch` with a new `--delete-integrated <pattern>` flag that detects branches whose changes have landed upstream via squash or rebase merges, even when their tips are unreachable. The existing `--delete-merged` flag keeps its strict tip-reachability behavior, and the CLI split between the two flags has been confirmed as final by Junio C Hamano. The series is now at v8, which contains only commit-message and documentation rewording in the fourth patch; all code has been stable since v7 and is considered technically complete and ready for integration.

The main technical work centers on `builtin/branch.c`: tree-based diffing for rebase detection (no blob fetches) and a path-by-path three-way merge via `ll_merge()` for squash-merged branches where upstream later modified the same files. Jasper Mayone's substantive review of v6 identified performance, `.gitattributes` correctness, and edge-case concerns; all three were resolved in v7, and he has since confirmed the patch builds cleanly, passes tests, and adds his `Tested-by` trailer. Output now reports the landing commit, e.g. `Deleted branch topic (was 1a2b3c4, landed as 9f8e7d6)`.

The one remaining technical gap is the author-check mitigation proposed by Jasper Mayone and supported by D. Ben Knoble: requiring that the landing commit's author also authored a commit on the branch being deleted, to avoid false positives in scenarios like "npm update" or forge workflows. This is not yet implemented but does not block integration. Minor usability nits -- outdated flag names in the cover letter, silent skipping of worktree-checked-out branches, and Phillip Wood's request for clearer documentation of limitations like rename detection -- also remain open.
