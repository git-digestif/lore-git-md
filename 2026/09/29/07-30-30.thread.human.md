The thread proposes a new `git branch --delete-integrated` flag that detects branches whose changes have been landed via squash merges or rebases, even when the branch tip itself is not reachable from upstream. Harald Nordgren's v10 series of five patches is now complete, splitting strict tip-reachability deletion (`--delete-merged`) from change-based detection (`--delete-integrated`), with the final patch implementing squash detection via three-way text merge that deliberately ignores `.gitattributes` merge drivers. Jasper Mayone has now provided a `Tested-by` confirming the series builds cleanly with no warnings under `DEVELOPER=1` and passes all 215 tests in `t3200`, including manual verification that the submodule-to-file edge case is handled correctly and that `merge=union` false positives are avoided.

The series remains under review with no integration status announced. Junio C Hamano has questioned whether the `branch.<name>.deleteMerged` config opt-out should extend to the new `--delete-integrated` mode or whether a separate key is needed, and the "npm update" false-positive scenario -- where another author independently makes identical changes -- remains unaddressed, with reviewers like D. Ben Knoble and Jasper Mayone urging author-check or patch-id mitigation. Other open items include clearer documentation of limitations such as the lack of rename detection, and minor usability refinements Jasper Mayone has previously raised.
