This thread is about a patch by Harald Nordgren that extends `git branch --delete-merged` to detect branches whose changes (but not their tips) have been squash-merged or rebase-merged into an upstream branch. The current implementation only deletes branches whose tips are reachable from the upstream, which doesn’t work for GitHub-style squash merges or local `git merge --squash` workflows.

The patch is under review, with no prior versions. Harald has provided test coverage and agreed to expand the commit message to include examples of both GitHub’s "Squash and merge" and local squash-merge workflows. The discussion has shifted from a binary config flag (`branch.deleteMergedDetectSquash`) to a more granular CLI option (`--delete-merged=squashed,rebased`), though no decision has been made. Performance concerns remain, but Harald reports speed improvements in the latest implementation.

Key reviewers include Kristoffer Haugsbakk, who reinforced the patch’s motivation by noting the prevalence of squash merges in both local and forge-driven workflows, and D. Ben Knoble, who explored implementation trade-offs and proposed the granular CLI option. Harald’s latest reply clarifies that his preference for a flag is purely performance-related and that he favors simplicity—users should not have to specify detection modes explicitly. The design question remains open, with Harald leaning toward a unified behavior rather than fine-grained control.
