This thread is about a patch by Harald Nordgren that extends `git branch --delete-merged` to detect branches whose changes (but not their tips) have been squash-merged or rebase-merged into an upstream branch. The current implementation only deletes branches whose tips are reachable from the upstream, which fails for common workflows like GitHub’s "Squash and merge" or local `git merge --squash`.

The patch is under review and touches `builtin/branch.c` and the documentation. It works by comparing tree diffs and simulating a three-way merge to detect when an upstream commit contains all changes from a branch. The author has added test coverage for edge cases like reverted squash merges and partial landings. Two reviewers—Kristoffer Haugsbakk and D. Ben Knoble—have provided substantive feedback, clarifying the patch’s scope and exploring implementation trade-offs, but neither has raised objections or requested changes. The author plans a v2 to expand the commit message with examples of both GitHub-style and local squash-merge workflows, including notes on their prevalence and tooling defaults.

The discussion has also included a contextual exchange between Kristoffer and D. Ben Knoble about the real-world use of squash merges. They note that while squash merges are widely used—often due to tooling defaults—they tend to produce poor commit messages, reinforcing the patch’s motivation. Open questions remain about whether the rebase case could leverage existing Git tools like `git log --cherry-mark`, whether the squash check could short-circuit in some cases, and whether a performance caveat is needed in the documentation. The patch is self-contained and not blocked on any other work.
