This thread introduces a small but useful enhancement to `git branch --delete-merged`: it will now detect branches whose changes (but not their tips) have been squash-merged or rebase-merged into an upstream branch. The current implementation only deletes branches whose tips are reachable, which misses common workflows like GitHub’s “Squash and merge” or local `git merge --squash`.

Harald Nordgren posted the initial patch, which compares tree diffs and simulates a three-way merge to determine if all changes from a branch are present in an upstream commit. The patch handles edge cases like reverted changes and partial landings, and includes tests for both GitHub-style and local squash merges. Kristoffer Haugsbakk reviewed it, noting that the feature applies to both forge-based and local workflows, with forge implementations like GitHub’s popularizing the pattern. D. Ben Knoble added anecdotal support, observing that GitHub’s default squash-merge message (which concatenates commit messages) is widely used due to tooling defaults, not user preference.

The patch is under review and self-contained, with no dependencies on other series. The only pending action is an update to the commit message to include examples of both GitHub-style and local squash merges, along with a brief note on their relative prevalence. No objections or technical concerns have been raised so far.
