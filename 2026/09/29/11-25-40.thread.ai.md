Thread identity
Subject: [PATCH 0/4] sha1dc-accel: faster SHA-1 collision detection
Series version: v1 (initial submission)
Originating author: Scott Chacon <scott@gitbutler.net>
Thread type: patch series

Core problem or goal
Replace Git’s existing `sha1dc` SHA-1 collision-detection implementation with a new `sha1dc-accel` subsystem that uses vectorized (SSE2, AVX2, NEON) and hardware-accelerated (x86-64 SHA-NI, ARMv8 SHA-1) versions of the unavoidable-bit-conditions (UBC) check and SHA-1 compression steps. The goal is to reduce the collision-detection overhead from 1.5–2.5× down to 0.2× relative to OpenSSL SHA-1 (which lacks collision detection), yielding a 2.7–2.85× speedup in SHA-1 throughput and a ~50 % reduction in `index-pack` runtime.

Current status
Under review; no maintainer decision recorded. Series remains at v1. All four patches are now submitted: patches 1 and 2 established the portable block-loop infrastructure, build-system integration, and vectorized UBC checks (SSE2, AVX2, NEON) delivering a 1.27–1.29× speedup over the scalar version; patch 3 added x86-64 hardware acceleration using Intel SHA-NI instructions (Ice Lake and later, AMD Zen), achieving a 2.07× speedup on a Xeon test machine; patch 4 (final integration) adds ARMv8 hardware acceleration using SHA-1 instructions (Apple M-series, Graviton, etc.), achieving a 2.85× speedup on an Apple M5 Max and bringing the cumulative series speedup to 2.85× SHA-1 throughput and a 1.86× reduction in single-threaded `index-pack` runtime for a 319MB pack.

Key technical details
- Files touched: `Makefile`, `meson.build`, `CMakeLists.txt`, new directory `sha1dc-accel/` (portable C implementation, platform-specific backends, and unit tests), `ubc_check.c` (vectorized UBC checks), `x86.c` (runtime AVX2 and SHA-NI detection, SHA-NI implementation), `arm.c` (ARMv8 SHA-1 instruction implementation and runtime detection), `sha1dc-accel/internal.h` (new function declarations), `sha1dc-accel/sha1.c` (backend integration and recompression logic).
- New symbols: `sha1dc-accel` subsystem, block-loop wrapper, vectorized UBC check forms (portable C, SSE2, AVX2, NEON), x86-64 SHA-NI backend (`sha1rnds4`, `sha1msg1`, `sha1msg2` instructions), ARMv8 SHA-1 backend (`sha1c`, `sha1m`, `sha1p` instructions), `test-tool sha1dc-compare`, `test-tool sha1dc-backends`.
- On-disk format: unchanged.
- Test coverage: unit tests (`u-sha1dc.c`) verify bit-for-bit compatibility with `sha1dc` across all modes (collision detection, safe hash, UBC filter, reduced-round collisions); `t0013-sha1dc.sh` extends collision tests to include the SHA-mbles chosen-prefix attack and real collision cases; new test tools (`test-tool sha1dc-compare`, `test-tool sha1dc-backends`) allow manual backend verification. Patch 3 adds unit tests for SHA-NI compression and recompression; patch 4 adds unit tests for ARMv8 compression and recompression, including edge cases.
- Performance data: patch 1 introduced a small 2–4 % slowdown; patch 2 recovered this and delivered a 1.27–1.29× speedup over the scalar UBC check, reducing its cost from ~50 % to ~20 % of compression time. Patch 3 achieves a 2.07× speedup on a Xeon test machine using SHA-NI. Patch 4 achieves a 2.85× speedup on an Apple M5 Max using ARMv8 SHA-1 instructions, bringing the cumulative series speedup to 2.85× SHA-1 throughput and a 1.86× reduction in single-threaded `index-pack` runtime (from 16.1s to 8.7s) for a 319MB pack. Multi-threaded `index-pack` runtime improves from 6.7s to 5.9s.
