Subject: [PATCH 0/4] sha1dc-accel: faster SHA-1 collision detection
Series version: v1 (initial submission)
Originating author: Scott Chacon <scott@gitbutler.net>
Thread type: patch series

Core problem or goal
Replace Git’s existing `sha1dc` SHA-1 collision-detection implementation with a new `sha1dc-accel` subsystem that uses vectorized (SSE2, AVX2, NEON) and hardware-accelerated (x86-64 SHA-NI, ARMv8 SHA-1) versions of the unavoidable-bit-conditions (UBC) check and SHA-1 compression steps. The goal is to reduce the collision-detection overhead from 1.5–2.5× down to 0.2× relative to OpenSSL SHA-1 (which lacks collision detection), yielding a 2.7–2.85× speedup in SHA-1 throughput and a ~50 % reduction in `index-pack` runtime.

Current status
Under review; no maintainer decision recorded. Series remains at v1. Johannes Schindelin has raised **two substantive technical objections** in earlier reviews: (1) code duplication in patch 1 (`compress_portable()` vs. `sha1_compression_states()`), and (2) maintainability concerns about the 1,789-line `ubc_check.c` tables, the latter now addressed by his Perl regeneration script. In this latest email, Schindelin provides a **substantive, tested optimization patch** for the x86-64 SHA-NI backend that closes most of the remaining performance gap between the C and Rust implementations, reducing `index-pack` runtime by an additional 1.8 % and leaving the C implementation only ~1 % slower than Rust. He explicitly endorses merging the series, marking a shift from his earlier technical objections to a clear supportive stance. No Reviewed-by or Acked-by trailers yet.

Key technical details
- Files touched: `Makefile`, `meson.build`, `CMakeLists.txt`, new directory `sha1dc-accel/` (portable C implementation, platform-specific backends, and unit tests), `ubc_check.c` (vectorized UBC checks), `x86.c` (runtime AVX2 and SHA-NI detection, SHA-NI implementation), `arm.c` (ARMv8 SHA-1 instruction implementation and runtime detection), `sha1dc-accel/internal.h` (new function declarations), `sha1dc-accel/sha1.c` (backend integration and recompression logic). Schindelin’s follow-up patch touches `sha1dc-accel/internal.h`, `sha1dc-accel/sha1.c`, `sha1dc-accel/ubc_check.c`, `sha1dc-accel/x86.c`, and `sha1dc-accel/u-sha1dc.c`.
- New symbols: `sha1dc-accel` subsystem, block-loop wrapper, vectorized UBC check forms (portable C, SSE2, AVX2, NEON), x86-64 SHA-NI backend (`sha1rnds4`, `sha1msg1`, `sha1msg2` instructions), ARMv8 SHA-1 backend (`sha1c`, `sha1m`, `sha1p` instructions), `test-tool sha1dc-compare`, `test-tool sha1dc-backends`, mirrored UBC check variants (`sha1dc_ubc_check_sse2_mirrored`, `sha1dc_ubc_check_avx2_mirrored`).
- On-disk format: unchanged.
- Test coverage: unit tests (`u-sha1dc.c`) verify bit-for-bit compatibility with `sha1dc` across all modes (collision detection, safe hash, UBC filter, reduced-round collisions); `t0013-sha1dc.sh` extends collision tests to include the SHA-mbles chosen-prefix attack and real collision cases; new test tools (`test-tool sha1dc-compare`, `test-tool sha1dc-backends`) allow manual backend verification. Patch 3 adds unit tests for SHA-NI compression and recompression; patch 4 adds unit tests for ARMv8 compression and recompression, including edge cases. Schindelin’s patch extends unit tests to verify bit-for-bit compatibility of the mirrored UBC check variants.
- Performance data: patch 1 introduced a small 2–4 % slowdown; patch 2 recovered this and delivered a 1.27–1.29× speedup over the scalar UBC check, reducing its cost from ~50 % to ~20 % of compression time. Patch 3 achieves a 2.07× speedup on a Xeon test machine using SHA-NI. Patch 4 achieves a 2.85× speedup on an Apple M5 Max using ARMv8 SHA-1 instructions, bringing the cumulative series speedup to 2.85× SHA-1 throughput and a 1.86× reduction in single-threaded `index-pack` runtime (from 16.1s to 8.7s) for a 319MB pack. Multi-threaded `index-pack` runtime improves from 6.7s to 5.9s. Schindelin’s optimization reduces the mean `index-pack` runtime on his Ryzen 7 from 8.201s to 8.053s (a 1.8 % improvement), leaving the C implementation only ~1 % slower than Rust. His validation confirms the C and Rust implementations are now effectively equivalent in speed.
- **New**: Perl script provided by Johannes Schindelin regenerates the 1,789-line `ubc_check.c` tables from the original Rust source (`srijs/sha1dc`), ensuring future maintainability. NEON backend readability improved via `vbicq_u32`/`vandq_u32` masking (stylistic suggestion only). Schindelin’s optimization introduces mirrored UBC check variants that avoid reordering the message schedule in the SHA-NI path, eliminating a measurable inefficiency.

Open questions and loose ends
- Trade-off between code complexity (multiple platform backends, fallback paths, mirrored UBC check variants) and performance gains.
- Long-term maintainability of AI-generated code, now mitigated by Schindelin’s Perl script.
- Build-system integration (Makefile, Meson, CMake) correctness across platforms, particularly for less common toolchains and architectures (e.g., runtime detection on macOS vs. Linux, compiler support for target attributes).
- Real-world validation on non-Apple ARMv8 hardware (e.g., Graviton) would be beneficial.
- Code duplication in `compress_portable()` (patch 1) must be resolved by reusing `sha1_compression_states()` from the existing `sha1dc/` subsystem.
- Whether to include Schindelin’s Perl script in the series (either in this patch or a follow-up) to formalize table regeneration.
- Whether to fold Schindelin’s optimization patch into the original series or submit it as a follow-up. The technical trade-off is between code complexity (adding mirrored variants and runtime schedule reversal) and the modest but measurable performance gain.
