This is a **feature patch follow-up** in the ongoing discussion about extending `` `git branch --delete-merged` `` to detect squash-merged and rebase-merged branches. The thread is now focused on how to expose the new behavior to users.

Harald Nordgren responds to D. Ben Knoble’s suggestion of a granular CLI option (e.g., `` `--delete-merged=squashed,rebased` ``). He clarifies that the only reason to hide the feature behind any kind of flag would be performance concerns, not use-case differentiation. Harald reinforces the preference for simplicity, arguing that most users would want the command to "just work" without specifying patterns or modes. He illustrates this by showing that `` `git branch --delete-merged` `` and `` `git branch --delete-merged '*/*'` `` should behave identically, implying that the default should include squash and rebase detection without requiring extra flags.

The exchange remains conceptual—no code or documentation changes are proposed here—but it narrows the design space: the discussion is now between a performance-motivated config flag (Harald’s original proposal) and a simpler default behavior (his current preference). The thread is still open, with no consensus yet on whether to expose fine-grained control or keep the interface minimal.
