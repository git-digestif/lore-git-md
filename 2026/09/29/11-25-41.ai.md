This is the first patch in a four-part performance series introducing `sha1dc-accel`, a new subsystem designed to accelerate Git’s SHA-1 collision detection. The patch lays the groundwork by adding a block loop around the existing `sha1dc` implementation, ensuring correctness while enabling the vectorized and hardware-accelerated optimizations that follow in later patches. The key change is the introduction of the `sha1dc-accel/` directory, which contains a portable C implementation of the block loop and infrastructure for platform-specific backends.

The patch touches the build system (`Makefile`, `meson.build`, `CMakeLists.txt`) to integrate the new subsystem, and adds extensive test coverage: a new unit test (`u-sha1dc.c`) verifies that the accelerated implementation produces identical results to the original `sha1dc` across all modes (collision detection, safe hash, UBC filter, and reduced-round collisions), while `t0013-sha1dc.sh` extends collision detection tests to include the SHA-mbles chosen-prefix attack and ensures the new backend agrees with `sha1dc` on real collision cases. The test suite also exercises the new `test-tool sha1dc-compare` and `test-tool sha1dc-backends` commands, which allow manual verification of backend behavior and compatibility.

The commit message is thorough, explaining the motivation (closing the performance gap between `sha1dc` and OpenSSL’s SHA-1), the technical approach (spilling the expanded message schedule and intermediate states to enable vectorized UBC filtering and hardware-accelerated recompression), and the trade-offs (a small 2–4% slowdown in this initial patch, which is later offset by the optimizations in patches 2–4). The code is well-structured, with clear separation between the portable backend and future platform-specific implementations, and the use of relaxed atomics for thread-safe backend selection. The patch is part of a larger, well-motivated effort to improve SHA-1 performance without sacrificing collision detection, and the foundation it establishes is both necessary and sound.
