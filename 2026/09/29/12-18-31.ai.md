This is the final patch in a five-patch bugfix series targeting `git stash`, specifically addressing a long-standing autostash bug where staged index entries are incorrectly handled when `stash.index=true` is set. The patch replaces the existing subprocess-based index merging logic (`git diff-tree` and `git apply`) with an in-core merge using `merge-ort.c`, eliminating a race condition that could corrupt the index state during concurrent merge operations.

The core change refactors `do_apply_stash()` in `builtin/stash.c` to use `merge_incore_nonrecursive()` for the index merge, removing the need for subprocess calls and filesystem round-trips. This fixes the bug where `save_autostash()` (triggered by `remove_merge_branch_state()`) would attempt to lock a deleted `MERGE_AUTOSTASH` ref, causing a SIGSEGV. The patch also ensures the merge trees are ordered correctly, with a new test in `t/t3903-stash.sh` validating this behavior. Additionally, a test in `t/t7600-merge.sh` verifies `--autostash` works with `stash.index=true`.

Key technical details:
- **Files touched**: `builtin/stash.c`, `t/t3903-stash.sh`, `t/t7600-merge.sh`.
- **Functions modified**: `do_apply_stash()` (replaces subprocess logic with `merge_incore_nonrecursive()`).
- **New test**: `stash apply --index merges the correct trees` (ensures staged changes are preserved).
- **Eliminated subprocess helpers**: `diff_tree_binary`, `apply_cached`, `reset_head`.
- **Safety fix**: The patch checks `result.clean` before dereferencing `result.tree`, preventing NULL-dereference crashes on catastrophic merge failures (e.g., missing objects).

The series is now technically complete, with all prior blockers (NULL-dereference risk, verbosity regression, bisectability, and test interactions) resolved. This patch is the culmination of the effort, replacing the last subprocess-based logic with in-core merging. The changes are narrowly scoped to the stash/merge-ort interaction, with no broader subsystem impact. The patch is ready for integration, pending final review from maintainers familiar with the stash or merge subsystems.
