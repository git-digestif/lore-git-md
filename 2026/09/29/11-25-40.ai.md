This is a performance-focused patch series introducing a faster SHA-1 collision detection implementation for Git, based on an approach originally developed in Rust for gitoxide. The series adds a new `sha1dc-accel` subsystem that replaces the existing `sha1dc` implementation with vectorized and hardware-accelerated versions of the unavoidable-bitconditions (UBC) check and SHA-1 compression steps. The result is a **2.7–2.85x speedup** in SHA-1 hashing throughput with collision detection enabled, reducing the overhead of collision detection from 1.5–2.5x to just 0.2x compared to OpenSSL’s SHA-1 (which lacks collision detection).

The series is structured as four patches:
1. **Groundwork**: Introduces a block loop around `sha1dc`’s context, ensuring correctness while adding test coverage for all modes, including real collision cases.
2. **Vectorization**: Rewrites the UBC filter using SSE2, AVX2, NEON, and scalar forms, achieving a 1.27–1.29x speedup.
3. **x86-64 hardware acceleration**: Uses SHA-NI instructions for compression, delivering another 2.07x speedup on Xeon.
4. **ARMv8 hardware acceleration**: Adds support for ARMv8 SHA-1 instructions, yielding a 2.4x speedup on Apple M5 Max.

The patches touch the build system (`Makefile`, `meson.build`, `CMakeLists.txt`), add new files under `sha1dc-accel/`, and include thorough test coverage (unit tests, collision test vectors, and performance benchmarks). The author, Scott Chacon, openly acknowledges the code is AI-generated but provides detailed performance data and references to the original Rust implementation (Sam Reis’s `sha1dc` crate) and its adoption in gitoxide. The series is well-motivated for server and client performance, particularly for operations like `index-pack`, which sees a **~50% reduction in runtime** in the provided benchmarks. The implementation appears technically sound, with platform-specific optimizations and fallback paths, though the mailing list will likely scrutinize the trade-offs between complexity and performance gains.
