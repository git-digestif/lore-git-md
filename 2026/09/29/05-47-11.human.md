This is a small but useful feature update for `git-contacts`, the contrib script that identifies likely reviewers from patch metadata. The v5 series now includes both the implementation (already merged in v4) and its documentation follow-up.

The patch teaches `git-contacts` to read patch content from stdin when the user supplies a single dash (`-`) as an argument, following the conventional UNIX idiom. This enables mixed file/stdin usage (e.g., `git contacts patch1 - patch3 <patch2`) and improves interoperability with external tools like `b4`. The implementation is straightforward: it removes the implicit terminal check from earlier versions and instead uses an explicit flag set when `-` appears in the argument list.

The documentation update is minimal and uncontroversial: it adds a single sentence to `git-contacts.adoc` clarifying that a dash reads from stdin. The author notes that the script can handle multiple concatenated patches from stdin (separated by mbox `From ` headers), though the documentation wording leaves this detail for future refinement. No open technical questions remain, and the series is ready to apply.

This is a well-motivated, low-risk change that aligns with Git’s existing conventions. The cross-project context (integration with `b4`) is mentioned but doesn’t block the patch’s standalone usefulness. The series has been through several iterations, incorporating feedback from Junio and others, and the final version is clean and well-explained. Worth a quick review for anyone who uses `git-contacts` or contributes to its documentation.
