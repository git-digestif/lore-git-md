This thread is an early RFC from Dmytro Lymarenko proposing a safety feature that would require explicit user consent before Git runs any local hook in an untrusted repository. The idea is to prompt the user with the hook’s path and offer choices to run once, trust all hooks in the repository, or decline—with re-prompts if in-worktree hooks are modified. The default behavior would remain unchanged.

Junio C Hamano has raised a fundamental security concern: if a malicious tool or project can install hooks, it could also manipulate the proposed trust mechanism to auto-approve them, making the protection ineffective. This critique targets the core premise of the feature rather than its implementation, suggesting the design may need rethinking to address this flaw. No other participants have weighed in yet, so the discussion is still in its early stages. Key open questions include how to securely persist trust state, whether a global override should exist, and how the feature would interact with existing hook-related settings.
