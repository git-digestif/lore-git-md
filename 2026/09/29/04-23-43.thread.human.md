This thread is an early-stage proposal from Dmytro Lymarenko for a new security feature in Git: **optional per-repository consent before running local hooks**. The idea is to add a safety setting that would require users to explicitly approve hooks in repositories they haven't previously trusted. When enabled, Git would prompt the user with the hook's path and offer options to run it once, trust all hooks in the repository, or decline. The feature would cover both existing and newly installed hooks, with re-prompts if working-tree hooks are modified. It would be opt-in, leaving Git's default behavior unchanged.

The motivation is to protect users from malicious or unexpected hooks that might be installed by tools or project setups. Since this is marked as an RFC, the proposal is seeking feedback rather than presenting a finished design—no implementation details or specific configuration options have been suggested yet. So far, the thread consists only of the initial proposal, so there are no decisions, objections, or alternative approaches to report. If you're interested in Git's security model or hook execution, this is a thread to watch for early discussion.
