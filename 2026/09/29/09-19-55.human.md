This is the first patch in Harald Nordgren’s v4 series introducing a new `remote.<name>.refmap` configuration to enable a matching-inspired fetch mode for shallow repositories. The patch adds the config variable itself, integrates it into the fetch machinery, and documents it.

The change is straightforward: `remote.<name>.refmap` provides the default value for the `--refmap` command-line option, just as `remote.<name>.fetch` provides the default refspecs. The implementation updates `remote.c` to parse the new config key, extends `builtin/fetch.c` to use the configured refmap as the default when no explicit `--refmap` is given, and adds a small helper in `remote.h` to expose the refmap structure. Documentation in `config/remote.adoc` and `fetch-options.adoc` is updated to describe the new setting, and a test in `t/t5510-fetch.sh` verifies that the config behaves identically to the command-line option.

This patch is the foundation for the rest of the series: it separates the “where to store” logic (refmap) from the “what to fetch” logic (refspecs), which is the key design change that enables the dynamic branch enumeration in later patches. The implementation is clean and well-tested, and it addresses Junio’s earlier documentation wording request by defining the refmap’s purpose precisely. No backward compatibility issues are introduced; the new config is ignored unless explicitly set.
