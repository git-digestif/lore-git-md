This is a feature patch series (v4) implementing a new "matching-inspired" fetch mode for shallow repositories. The series introduces `remote.<name>.refmap` configuration to separate ref-mapping from ref-fetching logic, then uses that mechanism to dynamically fetch only branches tracked by local branches at the remote—without the previously debated forced inclusion of the remote’s default branch.

The v4 iteration removes the automatic default-branch fetch that Junio objected to in v3, simplifying the design. A refspec-less fetch against a refmap-only remote now fetches nothing until a local branch explicitly tracks a remote branch, at which point only that branch is fetched. The series also adds `git remote add --limited-fetch` to explicitly create refmap-only remotes and makes that the default behavior when adding remotes to shallow repositories.

Files touched include `remote.c`/`remote.h` (refmap parsing and dynamic branch enumeration), `builtin/fetch.c` (integration with `--refmap` and dynamic branch selection), `builtin/remote.c` (`--limited-fetch` flag and shallow-repository default), and documentation (`config/remote.adoc`, `fetch-options.adoc`, `git-remote.adoc`). Tests cover the new behavior in `t/t5510-fetch.sh`, `t/t5585-fetch-refmap.sh` (new), and `t/t5505-remote.sh`.

The series is now technically complete and addresses the core concern—slow fetches in shallow repositories—without breaking backward compatibility. The removal of the forced default-branch fetch resolves the last substantive design objection, leaving only documentation wording updates (already addressed in v4) and edge-case handling (e.g., empty repositories) as potential follow-ups.
