This patch extends `git stash create` to support the `--include-untracked` (`-u`) and `--all` (`-a`) options, bringing it into parity with `git stash push` and `git stash save`. The change is a feature addition to the stash subsystem, touching the built-in command implementation, documentation, and test coverage.

The patch reuses the existing `do_create_stash()` helper, which already supports untracked and ignored file modes, but until now those modes were only exposed in the interactive `push`/`save` commands. The implementation translates the internal `include_untracked` parameter into the same `INCLUDE_ALL_FILES` mode used by the other stash subcommands, avoiding a separate code path. When no changes are found, the patch preserves the existing behavior of producing no output rather than failing.

The commit message provides a thorough historical context, tracing the evolution of untracked-file handling in `stash create` from a 2014 proposal through a 2017 refactoring (9ca6326dff29) that added the internal plumbing but left the user interface unchanged. It also references a recent GitGitGadget pull request (1892) that proposed exposing `--include-untracked` alone, positioning this patch as the logical completion of that work.

Test coverage is comprehensive: it verifies both short and long option forms, the boundary between untracked and ignored files, option/message parsing edge cases (including messages that begin with a dash), the no-change behavior, and the guarantee that `create` does not modify `refs/stash`, the index, or the working tree. The tests use isolated repositories to avoid contaminating unrelated test state.

The patch is well-motivated, cleanly implemented, and thoroughly tested. It addresses a long-standing inconsistency in the stash command family without introducing new behavior or breaking existing scripts. The only potential point of contention is whether exposing these options in `create` could encourage script authors to rely on them in ways that might later change, but the commit message explicitly states that the working tree and index remain unmodified, which should allay those concerns.
