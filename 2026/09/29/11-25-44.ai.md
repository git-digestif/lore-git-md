This is the final patch in Scott Chacon’s four-part series introducing `sha1dc-accel`, a faster SHA-1 collision-detection implementation for Git. It adds ARMv8 hardware acceleration using the SHA-1 instructions available on most 64-bit ARM CPUs (Apple M-series, Graviton, etc.). The patch integrates the new backend into the build system (Makefile, Meson, CMake), implements the compression and recompression logic in `sha1dc-accel/arm.c`, and extends the unit tests to verify bit-for-bit compatibility with the existing `sha1dc` implementation.

The ARMv8 backend is simpler than the x86-64 SHA-NI backend (patch 3) because the instructions keep the working state in natural order, eliminating the need for shuffling. Detection logic is more involved: on macOS with Apple clang, the instructions are always available; on Linux, the code uses `getauxval()` to check for hardware support at runtime; on other platforms, it falls back to portable code. The patch also handles older compilers that only declare the intrinsics when the entire file targets the instructions, using target attributes for GCC 9+ and clang 17+.

Performance data on an Apple M5 Max shows a **2.85× speedup** in SHA-1 throughput (from 700 MiB/s to 2 GiB/s) and a **1.86× reduction** in single-threaded `index-pack` runtime (from 16.1s to 8.7s) for a 319MB pack. Multi-threaded performance improves from 6.7s to 5.9s. The full test suite passes, and the unit tests verify compatibility across all modes, including real collision cases. The patch is well-tested under qemu-user for Linux runtime detection but would benefit from real-world validation on Graviton or similar hardware.

The series is now complete, with all four patches submitted. The implementation is technically sound, with thorough test coverage and clear performance gains, though the mailing list will likely scrutinize the trade-off between code complexity (multiple platform backends, fallback paths) and the substantial speedups.
