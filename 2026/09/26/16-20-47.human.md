This is the third patch in Andrew Pleeter’s v9 series extending `git var` to support multiple variable arguments. The series implements the design consensus reached earlier: a unified, scriptable interface for Git’s identity and signing configuration.

This patch teaches `git var` to accept more than one variable in a single invocation. When multiple variables are requested, the output is formatted as `VARIABLE=value` pairs (or `VARIABLE\nvalue\0` with `-z`), matching the behavior of `git var -l` but limited to the variables the user asked for. A single variable still prints its bare value and exits with status 1 if unset, preserving backwards compatibility. When multiple variables are requested, unset variables are simply omitted from the output rather than causing the command to fail — a deliberate design choice to avoid penalizing scripts that ask for both `GIT_CONFIG_SYSTEM` and `GIT_CONFIG_GLOBAL` when the user has disabled system config.

The implementation is clean: it reuses the existing argument-parsing infrastructure, enforces strict ordering (options before variable names), and handles both single-valued and multi-valued variables consistently. The code is table-driven and type-safe, using `enum ident_part` and `string_list` callbacks. Test coverage is thorough, verifying output format, argument ordering, unset variables, and exit codes.

This patch is part of a well-structured four-patch series that has already addressed all prior feedback from Junio and Phillip Wood. The series is technically complete, with no unresolved technical objections, and is ready for integration pending Junio’s review of v9. The only open question — whether to add a trailing delimiter in `-z` mode — is minor and not a blocker. The patch touches only `builtin/var.c`, the man page, and the test script, with no on-disk format changes or new configuration options.
