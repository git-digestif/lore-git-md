This is the v9 submission of Andrew Pleeter’s patch series extending `git var` to provide unified identity and signing configuration access. The series is now split into four focused patches as Junio requested, addressing all prior feedback from Junio and Phillip Wood.

The goal remains unchanged: extend the existing `git var` plumbing command to expose Git’s identity (author/committer names, emails, dates) and signing configuration in a scriptable, machine-readable way. The series is now structurally sound, with each patch building cleanly on the previous one. Patch 1 converts multi-valued variables to use `string_list` internally, patch 2 adds `-z` output mode, patch 3 enables multi-variable queries, and patch 4 introduces the new identity variables (`GIT_AUTHOR_NAME`, `GIT_AUTHOR_EMAIL`, `GIT_AUTHOR_DATE`, `GIT_COMMITTER_NAME`, `GIT_COMMITTER_EMAIL`, `GIT_COMMITTER_DATE`). The controversial `GIT_SIGNING_KEY` variable has been dropped due to ambiguity in its interpretation across signing mechanisms.

The implementation is technically complete and well-tested. Exit-code behavior is now finalized: multi-variable queries exit 0 if any requested variable is set (omitting unset variables from output), while non-zero codes are reserved for actual errors like unknown variables. The `-z` output mode matches `git config -z` (`key\nvalue\0`), and multi-valued variables are formatted as repeated `VARIABLE=value` entries. Tests cover all edge cases, including argument ordering, unset variables, and NUL-terminated output. The series touches only `builtin/var.c`, `Documentation/git-var.adoc`, and `t/t0007-git-var.sh`, with no on-disk format changes or new configuration options.

Junio’s prior review requested this exact split, and Phillip Wood’s feedback on exit codes, multi-valued variables, and output format has been fully addressed. The only open question is whether to use trailing delimiters for multi-valued variables in multi-variable mode, but Andrew has deferred to Phillip’s suggestion. The series is ready for `next` once Junio confirms the reorganization meets his expectations.

This looks like a well-crafted, thoroughly reviewed contribution that directly implements the design consensus from earlier discussion. The split patches make the changes easier to review and maintain, and the implementation aligns with Git’s existing conventions. If you care about scripting Git’s identity or signing configuration, this series is worth tracking.
