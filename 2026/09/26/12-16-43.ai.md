This is the **v3 cover letter** for a **five-patch bugfix series** targeting `git stash`, authored by D. Ben Knoble. The series fixes a bug where autostashing fails to correctly handle staged index entries when `stash.index=true` is set, particularly during merge operations. The root cause—a race condition in subprocess-based index merging—is resolved by switching to in-core merging via `merge-ort.c`.

The series is now complete and ready for integration. Key changes since v2:
- **Patch 3/5 is new**: adds a test for `stash --index` merges, validating the corrected tree argument order in `merge_incore_nonrecursive()` (a critical fix identified by Junio C Hamano).
- **Patch 4/5 (formerly 3/4)**: expanded test assertions to verify both worktree and index state preservation using `git diff-files -p` and `git diff-index --cached HEAD`, addressing Phillip Wood’s feedback.
- **Patch 5/5 (formerly 4/4)**: fixes a memory leak (missing `merge_finalize()`), updates conflict labels for clarity, and finalizes the tree argument order fix. The commit message now credits Junio for the argument-order correction.

The series touches `builtin/stash.c`, `merge-ort.c`, and the test suite (`t/t3903-stash.sh`, `t/t7600-merge.sh`). The behavior change is internal: index merges now use in-core logic, eliminating subprocess races. Test coverage is thorough, including conflicted index merges and graceful failure scenarios. All prior feedback (memory leaks, test robustness, argument order) is resolved, and the series is technically complete. Junio and Phillip Wood have endorsed the fixes, and no further revisions are expected.
