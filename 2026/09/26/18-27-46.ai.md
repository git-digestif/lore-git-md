This is the second patch in Kristoffer Haugsbakk’s v2 series introducing `--[no-]range-diff-notes` to `git format-patch`. It implements the new functionality after the preparatory refactoring in patch 1/2.

The patch adds two CLI options: `--range-diff-notes=<ref>` (which requires an explicit ref argument) and `--no-range-diff-notes` (which suppresses notes in the range-diff section). This design enforces explicit separation between patch notes and range-diff notes, addressing the usability concerns raised in the v1 discussion. The implementation introduces a new `struct rdiff_notes` to track whether the user wants to override the default notes behavior for range-diffs, and replaces the custom `revision.c` option handler with a standard `parse-options` callback (`rdiff_notes_cb`).

The commit message clearly explains the motivation: users often add iteration notes (e.g., "v3: [desc]") to patch series, but these notes clutter the range-diff output where they serve no purpose. The new options allow suppressing range-diff notes while retaining them in the patch output, or specifying different notes refs for each context. The message also justifies the design choices, such as allowing `--range-diff-notes` without `--range-diff` (to avoid breaking aliases) and requiring an explicit ref argument (for consistency with `--notes`).

Test coverage is thorough, verifying scenarios like suppressing all range-diff notes, using different notes refs for patches and range-diffs, and ensuring `--range-diff-notes` requires a value. Two additional tests specifically address the single-patch case, serving as regression tests for a bug fixed in a prior commit (155986b4, 2025-09-25). The documentation is updated to reflect the simplified behavior, removing references to the toggle mechanism and clarifying the explicit separation between patch notes and range-diff notes.
