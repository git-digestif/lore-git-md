This is the second patch in Andrew Pleeter’s v9 series extending `git var` to provide a unified, scriptable interface for Git’s identity and signing configuration. It adds a `-z` output mode that terminates entries with NUL bytes instead of newlines, matching the behavior of `git config -z` and resolving long-standing parsing ambiguities for values containing newlines or multi-valued variables.

The patch is technically straightforward and well-executed. It switches argument parsing to `parse_options()`, enforces strict ordering (options before variable names), and updates both single-variable and `-l` (list) modes to support `-z`. The implementation is careful to maintain backward compatibility: single-variable queries still print bare values, while `-l` mode now emits `VARIABLE\nvalue\0` pairs. Documentation and tests are thorough, covering edge cases like multi-valued variables and argument ordering.

This is a **refactoring with a clear user-facing benefit**: scripts can now safely parse `git var` output without worrying about embedded newlines or ambiguous delimiters. The patch is part of the agreed four-patch split (preparatory refactoring, `-z` mode, multi-variable support, and new identity variables) and addresses all prior feedback from Junio and Phillip Wood. The series remains in `seen` and is ready for maintainer review; this patch itself has no open technical questions.

If you care about scripting Git’s identity or configuration plumbing, this patch is worth watching—it’s a small but meaningful improvement that eliminates a long-standing pain point. The rest of the series builds on this foundation to expose author/committer details and signing configuration in a machine-readable way.
