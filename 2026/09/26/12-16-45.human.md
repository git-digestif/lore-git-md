This is the second patch in a five-patch bugfix series for `git stash`, targeting a race condition in autostash handling of staged index entries. The patch is a small but necessary refactoring: it moves the initialization of merge options (`init_ui_merge_options`) earlier in `do_apply_stash()`, preparing the code for an upcoming change where the same options will be reused for index merges (not just worktree merges). The change is purely preparatory—no behavior is altered yet—and consists of moving two lines of code.

The patch is clean, well-motivated by the series' goal, and has no known issues. It was previously reviewed by Phillip Wood, who confirmed the design is sound. Since this is a mechanical refactor with no functional impact, it is unlikely to be controversial. The commit message clearly states the purpose ("prepare merge options earlier") and the context ("reuse these options for the index merge"), making it easy for reviewers to follow the series' logic. No further changes are expected for this patch.
