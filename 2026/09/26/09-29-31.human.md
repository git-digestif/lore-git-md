This is a bug report for a crash in `git pack-objects` during a fetch in a partial clone with `tree:0` filter.

Lourens Naudé reports that `git fetch origin main` in a partial clone of the `NousResearch/hermes-agent` repository triggers a `BUG` assertion in `builtin/pack-objects.c:5004`. The assertion (`should_include_obj should only be called on existing objects`) fires when the code encounters a promised tree (`d0daf5223f2367bd20fc2deb9d66aed05fcd30e8`) that is not present locally and cannot be fetched lazily. The failure occurs in `is_not_in_promisor_pack_obj()`, called from `process_tree()` in `list-objects.c`. The repository is configured with `remote.origin.promisor=true` and `remote.origin.partialclonefilter=tree:0`, and `git fsck` reports no issues.

The report references an earlier thread and another user’s reproduction steps, but no minimal test case is provided. The crash is not deterministic, and the core dump is not shared. This appears to be a regression or edge case in the promisor-object handling logic, specifically when `pack-objects` processes trees that are expected to exist but are missing from the local object store. The issue is likely to affect users of partial clones with tree filters, a configuration that is becoming more common in large repositories.
