This is the **final version (v3)** of a **five-patch bugfix series** for `git stash`, authored by D. Ben Knoble. The series fixes a bug where autostashing fails to correctly handle staged index entries when `stash.index=true` is set, particularly during merge operations. The root cause—a race condition in subprocess-based logic—is resolved by switching to in-core merging via `merge-ort.c`.

The series is now **technically complete and ready for integration**. Patch 1 (a cleanup) is already merged to `master`; the remaining four patches refactor merge option initialization, add test coverage for conflicted index merges, and implement the core fix. Key improvements in v3 include:
- A **critical correctness fix** (swapping tree arguments in `merge_incore_nonrecursive()` to ensure the correct merge direction).
- A **new test (3/5)** to validate the argument-order fix, contributed by Junio C Hamano with proper Signed-off-by attribution.
- **Memory leak fixes** (adding `merge_finalize()` before returning on conflict).
- **Enhanced test robustness** in Patch 4 (using `git diff-files -p` and `git diff-index --cached HEAD` to verify unstaged changes and index preservation).
- **Clearer conflict labels** in the merge output.

The series touches `builtin/stash.c`, `merge-ort.c`, and the test suite (`t/t3903-stash.sh` and `t/t7600-merge.sh`). The behavior change is internal: the index is now merged in-core, eliminating external process calls and their associated race conditions. The on-disk format remains unchanged.

Reviewers (Junio C Hamano and Phillip Wood) have **endorsed the design and fixes**, including the decision to defer broader argument-order standardization to a future cleanup. The expanded test coverage—particularly Phillip Wood’s proposed scenario for content-level merge conflicts—ensures the fix is robust. The series is well-structured, with clear precursors (cleanup, refactoring, and test additions) leading to the functional fix.

This is a **high-quality bugfix** addressing a real-world correctness issue. The commit messages are detailed, the changes are narrowly scoped, and the test coverage is thorough. The series looks ready for `next`.
