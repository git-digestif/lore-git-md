This is the second patch in a two-part feature series adding `--[no-]range-diff-notes` to `git format-patch`. The patch implements the new functionality after the preparatory refactoring in the first patch.

The feature allows users to control Git notes inclusion independently in the range-diff section versus the patch output. The v2 design simplifies the interface by removing the toggle mechanism and requiring an explicit ref argument for `--range-diff-notes=<ref>`, while `--no-range-diff-notes` suppresses notes in the range-diff without fallback. This addresses the usability concerns Junio raised about the v1 proposal, making the behavior predictable and consistent with existing `--notes` semantics.

The implementation introduces a new `struct rdiff_notes` to track whether the user wants to override the default notes behavior for range-diffs, and replaces the custom `revision.c` option handler with a standard `parse-options` callback. The `get_notes_args` function is updated to take this struct as a parameter, and the interaction between patch notes and range-diff notes follows a clear rule: if no range-diff notes options are given, the range-diff uses the same notes as the patches; otherwise, it uses only the explicitly specified notes (including none).

Test coverage is thorough, verifying scenarios like suppressing all range-diff notes, using different notes refs for patches and range-diffs, and ensuring `--range-diff-notes` requires a value. Two additional tests specifically address the single-patch case, serving as regression tests for a bug fixed in the prior commit (155986b4, 2025-09-25). The documentation is updated to reflect the simplified behavior, removing references to the toggle mechanism and clarifying the explicit separation between patch notes and range-diff notes.

The patch is well-structured and the commit message clearly explains the motivation and changes.
