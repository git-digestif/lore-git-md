This is the first patch in the v9 series extending `git var` to provide unified identity and signing configuration. It refactors the internal representation of multi-valued variables (currently only `GIT_CONFIG_GLOBAL`) to use a `string_list` instead of a newline-joined string, eliminating a fragile round-trip through a delimiter that could appear in values.

The patch touches `builtin/var.c` and `Documentation/git-var.adoc`, adding a `multiread` callback to `struct git_var` and updating the `GIT_CONFIG_GLOBAL` handler to append values directly to a `string_list`. The output format remains unchanged, but the documentation now explicitly states that `GIT_CONFIG_GLOBAL` can have multiple values. The change is purely internal and preparatory for the later patches in the series, which will introduce `-z` output mode and multi-variable queries.

The implementation is clean and table-driven, using the existing `struct git_var` infrastructure. The patch is well-motivated: it removes a known fragility (newline-delimited values) and sets up the plumbing for the rest of the series. No new behavior is exposed yet, so this is effectively a refactoring patch that paves the way for the feature work in patches 2–4. The commit message is concise and technical, focusing on the "why" (fragile round-tripping) and the "how" (string-list conversion).

This patch directly addresses Junio’s request in the v8 review to split the series into smaller, logically independent steps. It is the first of four patches, each building on the previous one, and is ready for review as part of the larger effort. No controversy or open questions are evident here; the focus is on mechanical correctness and preparation for the subsequent feature additions.
