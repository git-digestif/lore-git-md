This is the third patch in Andrew Pleeter’s v9 series extending `git var` to support multi-variable queries. It implements the core functionality: allowing `git var` to accept more than one variable argument in a single invocation, printing each as a `VARIABLE=value` pair (or `VARIABLE\nvalue\0` under `-z`), and omitting unset variables without error. The patch preserves backwards compatibility for single-variable queries (bare value, exit code 1 if unset) while introducing structured output for multi-variable queries.

The implementation is table-driven and uses the `string_list` refactoring introduced in patch 1. It enforces strict argument ordering (options before variable names) via `parse_options()` with `PARSE_OPT_STOP_AT_NON_OPTION`, and handles both single-valued and multi-valued variables consistently. Error handling is precise: multi-variable queries exit 0 if any requested variable is set, while unknown variables or invalid arguments trigger non-zero exit codes and usage messages. Test coverage is thorough, verifying output format, argument ordering, unset variables, and exit-code behavior.
