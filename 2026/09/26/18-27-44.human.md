This is a feature patch revisiting the abandoned `--[no-]range-diff-notes` options for `git format-patch`. The v2 series is a complete redesign that addresses the usability concerns Junio raised in the original thread.

The new version drops the complex toggle mechanism (`--no-range-diff-notes --range-diff-notes`) and the argument-less `--range-diff-notes` variant entirely. Instead, it adopts a simpler model: `--range-diff-notes=<ref>` requires an explicit notes ref, and `--no-range-diff-notes` means "no notes for the range-diff" without any fallback to `--notes`. This matches Junio’s suggested rule and eliminates the ambiguous semantics that doomed v1.

The implementation is now much cleaner. Patch 1/2 is a minor refactoring to simplify parameter handling in `get_notes_args`. Patch 2/2 introduces the new options via a standard `parse-options` callback, avoiding the custom `revision.c` handler used in v1. The documentation is rewritten to clearly explain the independent control over patch notes versus range-diff notes, and the tests are updated to reflect the new behavior (notably, `--range-diff-notes` now requires a value).

The series looks well-structured and directly addresses the v1 feedback. The commit messages are clear, the test coverage is thorough, and the implementation avoids the edge cases that made v1 problematic. If this had been the initial proposal, it likely would have been accepted. As it stands, this is a strong candidate for merging if the author chooses to revive the feature.
