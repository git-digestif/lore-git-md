This is the fourth and final patch in Andrew Pleeter’s v9 series extending `git var` to provide broken-out identity variables. It adds the six new variables (`GIT_AUTHOR_NAME`, `GIT_AUTHOR_EMAIL`, `GIT_AUTHOR_DATE`, `GIT_COMMITTER_NAME`, `GIT_COMMITTER_EMAIL`, `GIT_COMMITTER_DATE`) that scripts can query individually instead of parsing the monolithic `GIT_AUTHOR_IDENT` or `GIT_COMMITTER_IDENT` strings. The patch is cleanly split from the earlier preparatory work (string-list conversion, `-z` output mode, and multi-variable support) and is ready for integration.

The implementation is straightforward: each new variable is backed by a small helper function that calls `split_ident_line()` on the corresponding ident string and returns the requested component. The code is type-safe (using an `enum ident_part`) and reuses Git’s existing ident-parsing logic, so awkward characters in names or emails are handled correctly. Documentation is updated to show both single-variable and multi-variable usage examples, and the test suite verifies that each component can be queried individually, that unset identities are rejected, and that the new variables appear in `git var -l` output.

This patch completes the series’ technical goals: scripts now have a robust, scriptable interface to Git’s identity configuration without having to reimplement ident parsing. The exit-code behavior (omitting unset variables in multi-variable queries) and output format (consistent with `git config -z`) were settled in earlier patches, so there are no open technical questions here. The only remaining loose end is the unresolved suggestion to add a trailing delimiter in `-z` mode, but that is not a blocker and can be addressed in a follow-up if needed.
