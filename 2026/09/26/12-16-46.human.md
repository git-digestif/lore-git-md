This is the third patch in a five-patch bugfix series for `git stash`. It adds a test to verify that `git stash apply --index` correctly merges staged index entries when autostashing during operations like merges. The test was suggested by Phillip Wood and directly addresses a critical correctness issue identified by Junio C Hamano: the order of tree arguments in `merge_incore_nonrecursive()` was backwards in the original code, causing incorrect merges.

The test creates a scenario where a file has staged changes, is stashed, modified again, committed, and then the stash is popped with `--index`. It verifies that staged changes (`committed B staged`) are correctly merged into the index and unstaged changes (`committed B unstaged`) remain in the worktree. The test is minimal but sufficient to catch the argument-order bug, and it resets the repository state afterward to avoid interfering with later tests.

This patch is uncontroversial and ready for integration. It complements the functional fix in Patch 5 by providing the necessary test coverage for the corrected merge logic. The series as a whole is technically complete, with all prior feedback resolved, and no further revisions are expected.
