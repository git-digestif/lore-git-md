This is the fourth patch in a five-patch bugfix series targeting `git stash` autostash behavior with staged index entries. The patch adds a test to `t/t3903-stash.sh` that verifies `git stash apply --index` correctly preserves both worktree and index state when the apply fails due to conflicts. The test creates a scenario with staged and unstaged changes, stashes them, introduces a conflicting change, then attempts to apply the stash with `--index`. It confirms that the apply fails gracefully (emitting the expected error message) and that both the worktree (`git diff-files -p`) and index (`git diff-index --cached HEAD`) remain unchanged. This test directly supports the functional fix in Patch 5, which replaces subprocess-based index merging with in-core logic to eliminate race conditions.

The test is minimal but thorough, addressing feedback from Phillip Wood and Junio C Hamano about test robustness. It uses raw diff output for comparison (blob IDs are stable for fixed content) and avoids the `diff_cmp()` helper, which filters index lines. The test resets the repository state afterward to avoid interfering with later tests. It is uncontroversial and ready for integration, with all prior feedback incorporated.
