This is the v9 preparatory update for Andrew Pleeter’s `git var` extension series, which aims to provide a unified, scriptable interface for Git’s identity and signing configuration. The patch is now structurally reorganized into four smaller commits (multi-valued variable representation, `-z` output mode, multi-variable support, and new identity variables) as requested by Junio and Phillip Wood. The series remains in `seen` and is ready for `next` once v9 is posted.

Andrew has dropped the `GIT_SIGNING_KEY` variable after realizing it cannot reliably indicate the signing mechanism (GPG/SSH/X.509) without also checking `gpg.format`. This resolves the last open technical question from Phillip’s review. The exit code behavior is now consistent: multi-variable queries omit unset variables and exit 0, while single-variable queries still exit 1 if unset. The output format for multi-valued variables (e.g., `GIT_CONFIG_GLOBAL`) now emits each value as a separate `VARIABLE=value` line, matching `git var -l`’s existing behavior.

The patch touches `builtin/var.c`, `Documentation/git-var.adoc`, and `t/t0007-git-var.sh`, with no new configuration options or on-disk format changes. Test coverage is thorough, using Git’s `nul_to_q` helper to avoid binary comparison issues. The series is well-motivated, with clear commit messages and no obvious gaps in functionality. If v9 matches this plan, it should graduate to `next` quickly.
