This is the third patch in a five-patch bugfix series for `git stash`. It adds a test to `t/t3903-stash.sh` that verifies `git stash pop --index` correctly merges staged index entries when autostashing during a merge. The test was suggested by Phillip Wood and directly addresses the critical correctness issue Junio C Hamano identified in Patch 5: the tree argument order in `merge_incore_nonrecursive()` was backwards, causing the merge to apply the wrong change. The test creates a scenario with staged and unstaged changes, stashes them, commits a conflicting change, then pops the stash with `--index` and verifies the staged changes are correctly merged into the index while unstaged changes remain in the worktree. The test is minimal but sufficient to catch the argument-order bug and is uncontroversial. It resets the repository state afterward to avoid interfering with later tests. This patch is ready for integration and completes the test coverage needed for the series.
