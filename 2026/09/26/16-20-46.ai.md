This is the second patch in Andrew Pleeter’s v9 series extending `git var` to provide unified identity and signing configuration. It adds a `-z` output mode that terminates entries with NUL bytes instead of newlines, matching the behavior of `git config -z` and resolving ambiguity when parsing multi-valued variables or values containing newlines.

The patch switches `git var` to `parse_options()` for argument parsing, enforcing strict ordering (options before variable names) and introducing the new `-z` flag. In `-z` mode, single-variable queries print the bare value followed by NUL, while `-l` (list) mode prints each entry as `VARIABLE\nvalue\0`, identical to `git config -z`. Multi-valued variables are formatted as repeated `VARIABLE=value` entries, each terminated by NUL. The implementation handles both single-valued and multi-valued variables consistently, using a delimiter (`\n` for `-z`, `=` otherwise) and terminator (`\0` for `-z`, `\n` otherwise) that are passed through the code.

Test coverage is thorough: the patch adds tests for `-z` output with single-valued variables, multi-valued variables, and the `-l` flag, using Git’s `nul_to_q` helper to avoid binary comparison issues. It also verifies that options must precede variable arguments, a requirement introduced by the switch to `parse_options()`.

This patch is a direct response to Junio’s v8 review, which requested splitting the original monolithic patch into smaller, focused changes. It is technically complete, addresses all prior feedback on output format, and is ready for integration. The only remaining open question is whether to include a trailing delimiter in `-z` mode (raised by Phillip Wood), but this is not a blocker. The series remains in `seen` pending Junio’s review of v9.
