This is the **final patch in a five-part bugfix series** for `git stash`, fixing a long-standing autostash bug where staged index entries are mishandled when `stash.index=true` is set. The patch replaces subprocess-based index merging (`git diff-tree` + `git apply`) with in-core merging via `merge-ort.c`, eliminating a race condition that could corrupt the index or trigger a SIGSEGV during conflicted merges.

The core change is in `builtin/stash.c`: the `do_apply_stash()` function now uses `merge_incore_nonrecursive()` to merge the stashed index changes directly in memory, avoiding filesystem round-trips and subprocess overhead. The patch removes three helper functions (`diff_tree_binary`, `apply_cached`, and `reset_head`) that were previously used to shell out to Git commands, replacing them with a cleaner, more efficient in-core workflow. A critical correctness fix—swapping the tree arguments in `merge_incore_nonrecursive()` from `(head, merge, merge_base)` to `(merge_base, merge, head)`—was identified by Junio C Hamano and is now incorporated, ensuring the merge applies the correct changes.

The patch also adds a test in `t/t7600-merge.sh` to verify that `--autostash` works correctly with `stash.index=true`, confirming the bug is fixed. The test creates a staged change, triggers a fast-forward merge with autostash, and checks that the stash is applied cleanly without leaving residual state.

This patch is **ready for integration**. All prior feedback has been addressed, including a memory leak fix (adding `merge_finalize()` before returning on conflict), test robustness improvements, and the tree argument order correction.
