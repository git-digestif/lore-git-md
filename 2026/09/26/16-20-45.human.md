This is the first patch in Andrew Pleeter’s v9 series extending `git var` to provide unified identity and signing configuration. It refactors the internal representation of multi-valued variables (currently only `GIT_CONFIG_GLOBAL`) to use a `string_list` instead of a newline-joined string, eliminating a fragile round-trip through a delimiter that can legitimately appear in values.

The patch is a clean refactoring with no user-visible changes. It replaces the `read` function pointer for `GIT_CONFIG_GLOBAL` with a new `multiread` callback that appends each value to a `string_list`, and updates the variable-lookup and listing logic to handle the new callback type. The documentation is updated to explicitly state that `GIT_CONFIG_GLOBAL` can have multiple values. The code is well-structured, with clear separation between single-valued and multi-valued variables, and the commit message explains the motivation clearly.

This is a necessary foundation for the rest of the series, which will add `-z` output mode, multi-variable queries, and the new identity variables. The patch looks technically sound and addresses the fragility concern raised in earlier reviews. No controversy or open questions are apparent here; it should be uncontroversial.
