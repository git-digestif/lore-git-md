This is the v9 preparatory update for the `git var` extension series, now dropping the `GIT_SIGNING_KEY` variable entirely. Andrew Pleeter responds to Phillip Wood’s prior feedback and explains the decision: `get_signing_key()` returns values whose meaning depends on `gpg.format` (a GPG key, an SSH key path, or even a committer ident in the default case), so the variable alone cannot reliably tell callers which signing mechanism to use. Rather than ship a misleading variable, Andrew removes it from the series, leaving the door open to revisit it once a concrete caller emerges.

The exit-code behavior is also finalized: multi-variable queries now exit 0 even if some requested variables are unset, omitting those from the output. Non-zero exit codes are reserved for actual errors (unknown variable names, etc.), aligning with `GIT_CONFIG_NOSYSTEM` precedent. The series is split into four patches as previously agreed: (1) string-list conversion for multi-valued variables, (2) `-z` output mode, (3) multi-variable support, and (4) the new identity variables (`GIT_AUTHOR_NAME`, `GIT_AUTHOR_EMAIL`, etc.). The `-z` mode’s output format matches `git config -z` (`key\nvalue\0`), and multi-valued variables are emitted as repeated `VARIABLE=value` entries rather than a single entry with a trailing delimiter. Tests now use `nul_to_q` to avoid binary-comparison issues.

The series remains focused on extending `git var` as a scriptable plumbing interface for identity and configuration, with no new configuration options or on-disk format changes. Integration awaits the v9 submission, which should address all remaining structural and technical feedback. The unresolved question about `GIT_SIGNING_KEY` is now moot for this iteration.
