This is a four-patch series introducing a compile-time option to use a new Rust-based SHA-1 implementation (`sha1dc` crate) for Git, with a focus on performance gains—particularly for Windows and large repositories. The series adds the Rust crate as an optional feature, provides a runtime escape hatch (`core.sha1dcBackend=c`) to fall back to the C implementation, and includes thread-safety fixes for Windows and non-PTHREADS builds.

The motivation is clear: the Rust crate offers significant speedups (author reports ~3x faster `git index-pack` in informal testing) due to SIMD optimizations. The patches are pragmatic, introducing a config knob to disable the Rust backend without recompiling, and addressing thread-safety gaps in the existing code. The series touches core hashing infrastructure (`hash.h`, `sha1dc_git.c`), build system (`Makefile`, `Cargo.toml`), and platform compatibility (`compat/win32/pthread.c`), with new test coverage in `t/t0013-sha1dc.sh`.

The approach is cautious: the Rust backend is enabled by default but can be toggled at runtime, and the author explicitly invites dropping the non-Rust-specific patches if they’re deemed undesirable. This suggests awareness of potential resistance to Rust in Git’s codebase, though the series itself doesn’t engage with the broader Rustification debate. The thread-safety fixes (patches 3–4) are likely uncontroversial, while the Rust integration (patches 1–2) may spark discussion about dependencies, build complexity, and platform support (e.g., NonStop).
