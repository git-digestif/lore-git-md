This is the third patch in Johannes Schindelin’s four-part series introducing a Rust-based SHA-1 backend for Git, with a focus on thread-safety fixes. This patch adds `pthread_once()` shims for Windows and `NO_PTHREADS` builds, enabling the upcoming Rust backend (and other code) to perform one-time initialization safely across platforms.

The patch is a small but critical piece of infrastructure. It touches `compat/win32/pthread.c`, `compat/win32/pthread.h`, and `thread-utils.h`, adding a Win32 implementation of `pthread_once()` using `InitOnceExecuteOnce()` and a trivial no-op shim for single-threaded builds. The changes are mechanical and follow Git’s existing patterns for platform compatibility. The commit message is clear: this is preparatory work for the Rust SHA-1 backend’s initialization logic, which needs to run exactly once even under concurrent access.

There’s nothing controversial here—this is a routine portability fix. The patch is well-scoped and addresses a gap that would otherwise block the Rust backend from working on Windows or in non-PTHREADS configurations. The implementation is straightforward, and the shims align with Git’s existing threading abstractions. If the series as a whole is accepted, this patch will likely be uncontroversial; if the Rust backend is rejected, this patch could still stand on its own as a general improvement to Git’s threading support.

The patch is part of a larger performance-driven effort, but it doesn’t itself introduce Rust code or change hashing behavior. It’s a prerequisite for the Rust backend’s thread-safe initialization, and its inclusion in the series suggests the author is taking care to ensure the new code works reliably across all platforms. For reviewers, this patch is a low-risk, high-value addition—exactly the kind of housekeeping that makes larger features possible.
