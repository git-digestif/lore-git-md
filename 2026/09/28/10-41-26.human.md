This is the second patch in Kristoffer Haugsbakk’s four-part RFC series converting Git’s `BreakingChanges` document into a proper manpage (`gitbreaking-changes(7)`). The patch replaces all message-ID references (e.g., `<20140304174806.GA11561@sigill.intra.peff.net>`) with clickable URLs pointing to the same threads on `lore.kernel.org`.

The change is small but user-focused: instead of forcing readers to manually construct URLs from message IDs, every reference now links directly to the relevant discussion. Two message IDs required URL encoding to work with AsciiDoc, which the patch handles. The commit message explains the rationale clearly—prioritizing convenience for a broader audience now that the document is public-facing—and the implementation is straightforward.

This patch is uncontroversial and well-motivated. It complements the first patch’s structural conversion by making the content more immediately usable without altering its substance. If the series’ overall goal (better visibility for breaking changes) is accepted, this is a sensible refinement. No objections have been raised yet, and the patch looks ready to proceed once the RFC period concludes.
