This is a **performance feature** introducing an incremental connectivity check for Git, now in its second version (v2). The patch series adds an opt-in `transfer.connectivityCheck=incremental` configuration that reduces the cost of verifying object connectivity during fetches and pushes, particularly in large repositories where the existing full check scales poorly with repository size.

The v2 update addresses the two technical concerns raised by Junio C Hamano in the initial review. First, it adds explicit NULL checks after `get_commit_tree_oid()` calls in `verify_commit_tree()`, replacing potential NULL-dereference crashes with clear `die()` messages. Second, it makes the lazy-fetch protection more robust by setting `repo->fetch_if_missing = 0` early in the `rev-list` option parsing when `--verify-trees-incremental` is detected, and adds a `BUG()` assertion to catch any future callers that might forget this requirement. The series also includes a new test verifying that promised blobs are not lazy-fetched during incremental checks, and reuses existing error message strings to avoid new localization work.

The implementation remains clean and self-contained, with the verifier running inside the existing `rev-list` subprocess (triggered by the new `--verify-trees-incremental` flag). This design avoids the fragility of the earlier in-process prototype, which required complex plumbing to handle promisor objects, shallow boundaries, and error isolation. The incremental mode processes incoming commits in topological order, tracking a growing set of "trusted" objects derived from parent commits to skip unchanged subtrees. Benchmarks show dramatic speedups for small pushes to large repositories (up to 190x faster, with memory usage reduced from 3.4 GB to 14 MB in the best case), while introducing only a modest regression (1.5x slower) for very long incoming histories (10,000+ commits). The author argues this tradeoff is acceptable for an opt-in feature targeting the common case of small pushes.

Test coverage is thorough, with correctness tests in `t5412-connectivity-check.sh` (680 lines) verifying semantic equivalence with the full check, corruption detection, partial clone handling, and integration with real fetch/push/clone operations. Performance tests in `t/perf/p5412-connectivity-check.sh` benchmark the feature across repository size, incoming commit count, and files changed per commit. The series also includes foundational documentation in `Documentation/technical/connectivity-check.adoc`, explaining the algorithm, tradeoffs, and edge cases like submodules and promisor objects.

The patch touches 13 files, adding a new `tree-verify.c` (316 lines) and updating `builtin/rev-list.c` and `connected.c` to wire up the feature. The changes are well-motivated, with clear benchmarks and a conservative design that falls back to the full check for edge cases like deepening fetches, shallow boundaries, and promisor objects. The author notes that future work could optimize the commit boundary-finding step, which remains a bottleneck for repositories with many refs.
