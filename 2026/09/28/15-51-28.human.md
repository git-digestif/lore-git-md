This is the first patch in a four-part series introducing a Rust-based SHA-1 backend for Git, targeting performance improvements—especially on Windows and in large repositories. The patch adds the `sha1dc` Rust crate as an optional compile-time feature (`DC_SHA1_RS`), controlled via the build system (`Makefile`, `Cargo.toml`). It provides the necessary C shims (`sha1dc_rs.h`) and Rust implementation (`src/sha1dc_rs.rs`) to integrate the crate with Git’s hashing infrastructure (`hash.h`).

The motivation is clear: the Rust crate delivers a significant speedup (author reports ~3x faster `git index-pack` in informal benchmarks) due to SIMD optimizations. The patch is pragmatic, avoiding a shim for collision detection by passing Git’s `die()` function directly to Rust, which calls it upon detecting a collision. The build system enforces mutual exclusivity with other SHA-1 backends and ensures Rust support is available when the feature is enabled. Performance claims are backed by benchmarks across Windows (UCRT64), WSL (ext4), and macOS (M4), though the author notes the Rust crate requires a newer Rust version (1.87) than Git’s existing Rust support (1.63).

The patch is well-structured and addresses a concrete performance bottleneck, but its reception may hinge on broader concerns about Rust in Git’s codebase—build complexity, platform support (e.g., NonStop), and the ongoing Rustification debate. The author’s approach is cautious, making the feature optional and leaving room for the community to shape the final implementation. The thread-safety fixes in later patches (3–4) are likely uncontroversial, but this patch’s Rust integration may spark discussion about dependencies and long-term maintenance. The series is under review and not yet merged to any integration branch.
