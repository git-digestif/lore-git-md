This is a follow-up in the GitLab CI Windows Rust breakage thread, focusing on a forward-looking question about Rust integration in the Git for Windows (GfW) SDK. Johannes Schindelin responds to Patrick Steinhardt’s curiosity about whether Rust will be included in the GfW SDK itself, rather than provisioned separately in CI. Schindelin expresses ambivalence: while the recent `sha1dc` Rust crate integration (via an upcoming patch series) necessitates Rust in the SDK, the 110MB size increase would more than double the minimal SDK’s current 70MB footprint. He notes the trade-off between consistency (CI matching release builds) and efficiency (GitHub Actions already includes Rust, avoiding repeated downloads, while GitLab runners do not). No decision is reached, and the discussion remains speculative—this exchange does not affect the current CI fix series, which remains ready for integration as-is. The key technical detail for future reference is the `sha1dc` Rust crate, which may drive eventual SDK inclusion.
