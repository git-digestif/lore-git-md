This is the fourth and final patch in an RFC series converting Git’s `BreakingChanges` document into a proper manpage (`gitbreaking-changes(7)`). The goal is to make upcoming breaking changes more visible to end users, who are most affected but least likely to follow development discussions.

This patch updates `git(1)`’s "SEE ALSO" section to include a reference to the new `gitbreaking-changes(7)` manpage, ensuring users can discover it via `git help` or `man git`. The change is minimal: it adds the manpage to the list of related guides and includes a brief inline mention in the introductory text, following the same double-spacing convention used elsewhere in the file. The `command-list.txt` file is also updated to classify `gitbreaking-changes` as a "guide," which ensures it appears in the correct section of the documentation index.

The patch is straightforward and aligns with the series’ overall goal of improving user visibility. The commit message explains the rationale clearly, and the change itself is mechanical, with no behavior impact. If the series is accepted, this patch completes the integration by making the new manpage discoverable alongside other Git documentation. The RFC tag indicates the author is still seeking feedback on the approach, but this specific patch is unlikely to be controversial.
