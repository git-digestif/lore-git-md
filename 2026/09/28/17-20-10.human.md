This is the **Git v2.56.0 release announcement** from Junio C Hamano. The latest feature release includes **748 non-merge commits** from **104 contributors**, 39 of whom are new to the project. The release notes cover a wide range of improvements, fixes, and internal changes across Git's UI, workflows, performance, and development support.

### Key Highlights
**UI and Workflows:**
- **`git status`** now suggests `git pull <remote> <branch>` when the local branch is behind its push branch.
- **`git refs`** gains new subcommands (`create`, `delete`, `update`, `rename`) for managing references directly.
- **`git history`** (experimental) adds a `drop` subcommand to remove commits, replaying descendants onto their parents.
- **`git branch --delete-merged`** removes local branches already merged into their tracked remote-tracking branches.
- **`git add --resolved`** stages conflict-resolved paths while leaving unrelated changes unstaged.
- **`git bisect`** introduces `--reset-when-found` to automatically return to the original state after finding a culprit.
- **`git replay --linearize`** mimics `git rebase --no-rebase-merges` by dropping merge commits.
- **`git cat-file --batch-command`** adds `remote-object-info` to fetch object metadata (e.g., size) from a remote server without downloading the full object.

### Performance and Internals:

- **`the_repository` removal** continues, with global state (e.g., `ignore_case`, `trust_executable_bit`) migrated to per-repository structures.
- **Object Database (ODB) abstraction** progresses, enabling pluggable backends (e.g., `receive-pack` now uses ODB transactions).
- **Reftable backend** optimizations reduce syscalls when writing refs.
- **Merge-base computation** speeds up by early-exiting when one side’s commits are exhausted.
- **`git repack --drop-filtered`** deletes local promisor blobs exceeding size limits in partial clones.
- **Geometric repacking** thresholds now match `git gc --auto` to avoid over-aggressive repacking.

### Documentation and Developer Support:

- **Man pages** are being converted to a consistent AsciiDoc synopsis style (e.g., `git fast-export`, `git imap-send`).
- **`SubmittingPatches`** clarifies expectations for responding to design critiques and retracting abandoned patches.
- **`b4` integration** is recommended for patch submission, with project-specific configuration added.
- **Test suite** improvements include a `greplint` linter to catch bare `grep` assertions and fixes for flaky tests (e.g., `t7900-maintenance.sh`).

### Notable Fixes:

- **Memory leaks** in Bloom filters, hash contexts, and `git merge` (when run without arguments).
- **Crashes** in `git clone --revision`, `git diff --relative --cached`, and `git cat-file --batch-command`.
- **Windows-specific fixes**, including symlink handling to prevent NTLM credential leaks and a switch to the URCR64 runtime.
- **Reftable hardening** against corrupted tables (OOB reads/writes, NULL pointer issues).

### New Contributors:

Welcome to 39 first-time contributors, including Adrian Friedli, Alan Stokes, and Antonio De Stefani, among others.

### Assessment
This is a **major release** with significant advancements in Git’s internals (ODB abstraction, `the_repository` removal) and user-facing features (e.g., `git history drop`, `git refs` subcommands). The performance optimizations (merge-base, reftable) and pluggable backends are particularly noteworthy for large repositories. The release also addresses long-standing issues like memory leaks and Windows compatibility. **Worth upgrading for users and developers alike**, especially those working with partial clones, reftable, or experimental commands like `git history`.
