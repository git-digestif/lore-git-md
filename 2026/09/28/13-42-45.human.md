This is the final patch in Christian Couder’s five-part series introducing `uploadpack.lazyFetchTrusted`, a server-side protected configuration that lets operators mark repositories as trusted for lazy fetching. The patch activates the mechanism by conditionally setting `GIT_NO_LAZY_FETCH=0` when serving a trusted repository, overriding the default `GIT_NO_LAZY_FETCH=1` that disables lazy fetching for security.

The v4 update addresses Junio’s key critique from v3: the environment-handling logic now checks whether `GIT_NO_LAZY_FETCH` is already set by the operator before overriding it, preserving operator control. This resolves the design nit about configuration variables overriding environment variables. The commit message is also clarified to explain what the server operator vouches for (trustworthiness of promisor remotes, hooks, and configuration) and to explicitly list the three possible states for `GIT_NO_LAZY_FETCH` handling.

The patch documents the new configuration in `git-upload-pack.adoc`, `git.adoc`, and `Documentation/config/uploadpack.adoc`, and adds six test cases covering allowlisting, recursion safeguards, and non-bare repository handling. The series as a whole is technically sound, with all v2 and v3 feedback addressed, though Junio’s lingering conceptual doubt about using a configuration variable for this purpose and brian m. carlson’s security objection remain unresolved but mitigated by the server-side trust model. This patch is now ready for integration, pending any new substantive reviews.
