This is a documentation patch for `git remote` that clarifies a common misconception about the `set-head` subcommand. The thread reveals a small but meaningful disagreement about *where* the clarification belongs. The patch, as submitted, adds six lines to the `set-head` section of the `git-remote` man page, explicitly stating that the command only affects the local repository and does not modify the remote's `HEAD`.

Junio, however, suggests a broader approach: instead of singling out `set-head`, he proposes adding a general disclaimer at the top of the man page stating that *all* `git remote` commands operate locally and never modify the remote repository. This would obviate the need for per-command caveats like the one in the patch, and would also clarify other commands (e.g., `prune`) that might be similarly misunderstood.

The patch itself is well-motivated and addresses a real source of confusion, as evidenced by the external discussion the author cites. The proposed wording is clear and accurate. The only open question is whether the clarification should be scoped narrowly (as in the patch) or broadly (as Junio suggests). Neither approach is wrong, but the broader one would be more comprehensive and might prevent similar misunderstandings in the future.
