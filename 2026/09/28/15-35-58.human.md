This is the second patch in Kristoffer Haugsbakk’s two-part series adding `--[no-]range-diff-notes` to `git format-patch`. The patch implements the new options and is technically sound, with Junio C Hamano’s review identifying only a minor redundancy in the test script: a duplicate `test_when_finished` call that Haugsbakk has already agreed to remove.

The series as a whole is a redesign of an earlier attempt that was abandoned due to usability concerns. This version adopts Junio’s suggested rule—`--no-range-diff-notes` means “no notes for range-diff” without fallback, and `--range-diff-notes=<ref>` requires an explicit ref—eliminating the ambiguous toggle mechanism and arg-less variant that caused problems in v1. The interaction between patch notes and range-diff notes is now explicit and predictable: if no range-diff notes options are given, the range-diff uses the same notes as the patches; otherwise, it uses only the explicitly specified notes (including none).

The patch touches `builtin/log.c`, `log-tree.c`, `revision.c`, and documentation, with comprehensive test coverage verifying edge cases like single-patch scenarios and explicit notes suppression. Junio’s review found nothing questionable beyond the test redundancy, and Haugsbakk has confirmed the fix will be included in the next version. The series is now technically ready for integration if the maintainer decides to revive the feature, though no such decision has been made yet.
