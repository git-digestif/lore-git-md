Subject: git -C via alias in worktree mis-sets GIT_DIR and GIT_COMMON_DIR
Series version: none (standalone bug report)
Originating author: jumps_dollies_9s@icloud.com
Thread type: bug report

Core problem or goal
When `git -C other_repo <command>` is invoked via a Git alias from within a worktree, the environment variables `GIT_DIR` and `GIT_COMMON_DIR` are incorrectly set to the worktree’s repository instead of `other_repo`. The bug does not manifest when the same command is run directly (not via alias) or when run from the original clone (not a worktree). The consequence is that commands such as `git -C submodule_path restore` operate on the wrong repository, potentially corrupting state.
