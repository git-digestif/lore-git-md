Thread identity: RFC inquiry about adding an `includeIf "hostname:..."` condition to Git's configuration system. Originating author: Isabella Caselli (undergraduate student). Thread type: feature proposal (RFC).

Core problem or goal: Enable users to conditionally include Git configuration files based on the machine's hostname, facilitating dotfile sharing across multiple machines. The proposal extends Git's existing `includeIf` mechanism with a new `hostname:` condition, modeled after the `onbranch:` implementation. The feature is motivated by a GitHub issue (gitgitgadget/git#1665) and aims to address hostname-based configuration needs distinct from the stalled 2022 OS-based `includeIf` proposal.

Current status: Early-stage RFC with constructive feedback received. No patches submitted yet. Jeff King (Peff) confirmed the feature is reasonable and not currently being pursued by others, based on a list archive search. The 2024 patch series by Ignacio Encinas (which touched on hostname normalization) is noted as stalled after v3, implying no active work on this front. Peff suggested exposing Git’s view of the hostname via `git var GIT_HOSTNAME` as a debugging aid, adding a new technical detail to the proposal.

Key technical details:
- Files touched: `config.c` (core logic), `t1305-config-include.sh` (tests), `config.adoc` (documentation).
- New condition: `includeIf.hostname:<pattern>` (syntax to be finalized).
- Hostname resolution: Unresolved whether to use the system-reported hostname exactly or normalize it (e.g., short name vs. FQDN). Peff referenced a 2024 consensus to document system-dependency rather than enforce normalization.
- New debugging aid: `git var GIT_HOSTNAME` proposed by Peff to expose Git’s hostname interpretation.
- No new CLI options, config keys, or on-disk format changes anticipated.
- Test coverage would extend the existing `includeIf` test suite.

Open questions and loose ends:
1. Hostname normalization: Should the condition match short names, FQDNs, or both? How should edge cases (e.g., `.local` domains, custom hostnames) be handled? Peff’s feedback frames this as a system-dependent choice rather than a Git-enforced rule.
2. Implementation scope: Should the feature support globbing, regex, or exact matching for hostnames? Still unresolved.
3. Prior art: Are there alternative approaches (e.g., environment variables) that could address the same use case? No alternatives proposed yet.
4. Next steps: Isabella has not yet indicated whether she plans to proceed with implementation.
