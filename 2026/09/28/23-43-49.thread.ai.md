Thread identity: Implementation series for `includeIf.hostname:<pattern>` condition in Git's configuration system. Originating author: Isabella Caselli (undergraduate student). Thread type: patch series (v1), transitioning from RFC to implementation.

Core problem or goal: Enable users to conditionally include Git configuration files based on the machine's hostname, addressing the use case of dotfile sharing across multiple machines. The implementation extends Git's existing `includeIf` mechanism with a new `hostname:` condition, modeled after the `onbranch:` implementation, and includes a `git var GIT_HOSTNAME` debugging aid as suggested by Jeff King.

Current status: Isabella Caselli has posted a complete three-patch v1 series implementing the feature. The series is under active review and addresses all prior feedback from the RFC phase, including Peff's suggestion for `git var GIT_HOSTNAME` and Junio's reinforcement of the 2024 design consensus (system-dependent hostname matching without normalization). The first patch added `git var GIT_HOSTNAME` (uncontroversial), the second patch fixed a test consistency issue in `t/t6500-gc.sh` by replacing the external `hostname` command with `git var GIT_HOSTNAME`, ensuring the test and the `git gc` command agree on the hostname value, and the third patch adds the core logic, documentation, and test coverage for `includeIf.hostname:<pattern>`. Junio C Hamano reviewed the third patch and described the implementation approach as "neat" and "quite nice," indicating no substantive objections. Isabella's latest clarification confirms the second patch's fix is critical for test correctness: without it, the test in `t/t6500-gc.sh` writes a bogus hostname to `.git/gc.pid`, causing `lock_repo_for_gc()` to skip the `kill(pid, 0)` check and silently exercise the wrong code path. Junio has now explicitly agreed that the commit message for the second patch should be updated to clarify this reliability issue. Peff's recent surface-level review confirms he has read the series and found no issues, further indicating the series is ready for final review. All prior feedback has been addressed, and no substantive objections remain.

Key technical details:
- Files touched: `config.c` (core logic in `include_by_hostname()` and condition parsing, leveraging the existing `include_condition_is_true()` helper), `builtin/var.c` (new `git var GIT_HOSTNAME`), `t1305-config-include.sh` (tests for exact and wildcard hostname matching), `t/t0007-git-var.sh` (minimal test for `GIT_HOSTNAME`), `t/t6500-gc.sh` (test consistency fix: replaces `hostname` with `git var GIT_HOSTNAME` to ensure the test and `git gc` agree on the hostname value), `config.adoc` (documentation with examples and caveats about system-dependent hostname reporting), `git-var.adoc` (documentation for new `git var` command).
- New condition: `includeIf.hostname:<pattern>` (supports standard glob wildcards; exact matching, case-sensitive).
- Hostname resolution: System-dependent (short name or FQDN), documented as such; no normalization or DNS lookups. This aligns with the 2024 consensus confirmed by Ignacio Encinas and Junio.
- New debugging aid: `git var GIT_HOSTNAME` (replaces the dropped `test-tool xgethostname` helper). Implementation calls `xgethostname()` and returns the result; exits non-zero if the hostname cannot be determined, and `git var -l` omits the variable in such cases.
- Test coverage: Extends `t1305-config-include.sh` with two new test cases (exact hostname matching and wildcard matching); uses `git var GIT_HOSTNAME || echo unknown` to avoid silent failures. The first patch added a minimal test in `t/t0007-git-var.sh` to verify the output is non-empty. The second patch ensures `t/t6500-gc.sh` uses the same hostname resolution as the rest of Git, preventing a test reliability issue where the external `hostname` command and Git's internal `xgethostname()` could return different values, causing the test to simulate a lock held by a process on a different machine rather than the intended concurrent-local case.
- No new CLI options, config keys, or on-disk format changes.
- Implementation builds directly on Ignacio Encinas' 2024 v3 series (hostname normalization work) with his explicit permission.

2. **Matching semantics**: The series uses exact matching with standard glob wildcards (like `includeIf.onbranch:`), but no proposals or objections have been raised regarding alternative matching modes (e.g., regex).
