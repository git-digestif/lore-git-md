This is the second patch in Johannes Schindelin’s four-patch series introducing an optional Rust-based SHA-1 backend for Git. It adds a runtime escape hatch (`core.sha1dcBackend`) that lets users switch between the new Rust implementation and the existing C one without recompiling, addressing a key concern about adopting unproven code in critical hashing infrastructure.

The patch is narrowly focused: it wires up a set of function pointers in `sha1dc_git.c` that are initialized on the first call to `git_hash_init()`, based on the config value. The Rust backend remains the default when `DC_SHA1_RS` is defined, but users can now opt out by setting `core.sha1dcBackend=c`. The implementation is careful to avoid symbol conflicts (reordering includes in `sha1dc_git.c`) and to maintain thread safety, though the latter is addressed more fully in later patches.

Documentation is updated (`Documentation/config/core.adoc`) and tests are extended (`t/t0013-sha1dc.sh`) to verify the config-driven switching. The test helper `test-sha1` gains a `--backend` flag to report which implementation is active, making it easier to debug issues in the wild.

The patch is well-motivated and pragmatic: it directly responds to the risk of introducing a new, untested backend by giving users an immediate fallback. The code is clean, with no obvious gotchas, and the commit message clearly explains the design choices (e.g., why the function pointers are initialized lazily). If the series lands, this patch will be the safety net that makes the Rust backend palatable to cautious users.
