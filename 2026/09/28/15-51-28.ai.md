This is the first patch in Johannes Schindelin’s four-patch series introducing a Rust-based SHA-1 backend for Git, targeting performance improvements in `git index-pack`. The patch adds the `sha1dc` Rust crate as an optional compile-time feature (`DC_SHA1_RS`), controlled via the `Makefile` and `Cargo.toml`. It introduces a new header (`sha1dc_rs.h`) and Rust implementation (`src/sha1dc_rs.rs`) that wraps the crate’s `Hasher` type, exposing C-compatible functions (`sha1dc_rs_init`, `sha1dc_rs_update`, etc.) for Git’s hashing infrastructure.

The patch is narrowly scoped: it wires up the Rust crate as an alternative to the existing C-based `sha1dc` implementation, with no runtime behavior changes unless explicitly enabled at build time. The Rust code is careful to handle FFI safety, including direct calls to Git’s `die()` function for collision detection (avoiding a shim) and proper cleanup of heap-allocated `Hasher` instances. The `Makefile` logic ensures the Rust backend cannot be combined with other SHA-1 backends (OpenSSL, BLK_SHA1, etc.) and enforces Rust version 1.87 (higher than Git’s current minimum of 1.63).

Performance claims are central to the motivation: the commit message reports a **3× speedup** for `git index-pack` on Windows (UCRT64) and WSL, with similar gains on macOS, attributed to the crate’s SIMD optimizations. The patch includes detailed benchmark results across three backends (C, Rust 0.1.2, Rust 0.1.3) and platforms, though the author acknowledges these are informal tests. The Rust backend is enabled by default when `DC_SHA1_RS` is defined, but the series’ later patches add a runtime escape hatch (`core.sha1dcBackend=c`) to revert to the C implementation.

Key technical details for follow-up discussion:
- **Files added**: `sha1dc_rs.h`, `src/sha1dc_rs.rs`.
- **Build system**: `DC_SHA1_RS` flag, `Cargo.toml` feature `sha1dc-rs`, and `Makefile` guards to prevent conflicts with other SHA-1 backends.
- **FFI design**: Direct `die()` calls from Rust, `Box`-managed `Hasher` instances, and `#[no_mangle]` extern functions.
- **Performance**: Benchmark data for Windows, WSL, and macOS, with `perf` analysis showing reduced time in `git_hash_update()`.
- **Rust version**: Requires 1.87 (higher than Git’s current 1.63 minimum).

The patch is well-structured and addresses a clear performance bottleneck, but its reception may hinge on broader concerns about Rust in Git (e.g., build complexity, platform support like NonStop). The author’s tone is pragmatic, framing the Rust backend as an optional optimization rather than a mandatory dependency. Subsequent patches in the series address thread-safety and runtime configuration, but this patch is the core of the Rust integration.
