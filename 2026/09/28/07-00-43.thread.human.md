This thread is about a discrepancy in how Git’s reftable backend encodes timezone offsets in reflogs. The current implementation writes them as signed HHMM integers (e.g., +05:30 → 0530), but the published reftable specification requires signed minutes (e.g., +05:30 → 330). This mismatch breaks interoperability with other reftable implementations like JGit, though Git’s own reader and writer remain internally consistent.

The discussion has reached a consensus that Git should align with the specification by switching to signed minutes. Junio C Hamano and Patrick Steinhardt agree the practical impact is limited—reflogs are short-lived (typically garbage-collected within 30 days), and the misinterpretation is bounded (at most 10 hours). They also dismiss a format version bump as unnecessary for SHA-1 repositories, which use version 1. The focus has shifted to migration strategy, with Junio suggesting a one-time offline conversion but questioning whether it’s worth the effort given the minimal disruption.

No patch has been posted yet, and the thread remains in the design-discussion phase. The key open question is whether to implement a conversion mechanism or simply fix the encoding going forward. The author, Josh McKinney, has not yet responded to the latest consensus, but the direction appears settled.
