This thread reports a **bug in Git 2.55.0’s reftable backend** where timezone offsets in reflogs are stored as signed *HHMM* integers (e.g., `+05:30` → `0530`), but the reftable specification requires signed *minutes* (e.g., `+05:30` → `330`). Josh McKinney provides a clear reproducer—using a temporary SHA-1 reftable repository and a Python script—to demonstrate the mismatch, showing that Git’s writer and reader agree internally but deviate from the spec.

The issue raises critical questions about **interoperability and backwards compatibility**: whether the spec should be updated to match Git’s behavior, how existing reftable implementations (like JGit) might be affected, and how to interpret tables written in the current format if the spec changes. No patch is proposed yet; the thread is currently a **diagnostic report seeking maintainer guidance**. Given the reftable backend’s importance and the potential for on-disk format breakage, resolution will likely require coordination with other reftable consumers. Key participants (e.g., Patrick Steinhardt, Karthik Nayak) have not yet weighed in.
