This thread is about a discrepancy in how Git’s reftable backend encodes timezone offsets in reflogs. Git 2.55.0 writes them as signed HHMM integers (e.g., +05:30 → 0530), but the published reftable specification requires signed minutes (e.g., +05:30 → 330). While Git’s internal consistency avoids runtime issues, the mismatch breaks interoperability with other reftable implementations like JGit.

Patrick Steinhardt has confirmed the bug and provided a minimal test case to reproduce it. He argues for fixing Git to match the specification, noting that JGit already implements it correctly and that the practical impact is limited—timezone offsets would be misinterpreted by at most 10 hours, and only in reflogs, which are typically short-lived. He dismisses a format version bump as unnecessary for SHA-1 repositories, which already use version 1. The discussion is now focused on reaching consensus before proceeding with a patch, though no objections have been raised so far.

The thread remains open for alternative perspectives, but the current direction is to align Git with the specification. Since this affects on-disk format compatibility, coordination with JGit and other reftable consumers may be needed if the fix moves forward. The reproducer and test case make the issue easy to verify, and the discussion is grounded in technical specifics. No patch has been posted yet.
