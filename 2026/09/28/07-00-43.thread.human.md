This thread is about a discrepancy in how Git’s reftable backend encodes timezone offsets in reflogs. The current implementation writes them as signed HHMM integers (e.g., +05:30 → 0530), but the published reftable specification requires signed minutes (e.g., +05:30 → 330). This mismatch breaks interoperability with other reftable implementations like JGit, though it’s internally consistent within Git.

The discussion has reached consensus: Git should align with the specification by switching to signed minutes. Junio C Hamano and Patrick Steinhardt agree the practical impact is limited—reflogs are short-lived, and the misinterpretation is bounded to at most 10 hours—so no special migration strategy (like a one-time conversion) is needed. Josh McKinney, who reported the issue, initially suggested updating the specification to match Git’s behavior but now supports fixing Git instead, especially after confirming the issue arose in a development context rather than production.

No patch has been posted yet, but the design question is settled. The fix will target the reftable backend (`refs/reftable/`) and use the existing test case in `t/t0610-reftable-basics.sh` for validation. The thread is effectively closed on the technical direction, with implementation as the next step.
