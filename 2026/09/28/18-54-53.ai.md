This is the second patch in Harald Nordgren’s two-part CI/build system series (v2) improving GitHub Actions failure reporting. It focuses on making test failures and fixed known breakages actionable by pointing annotations directly to the relevant file and line in the test script.

The patch adds two new helper functions in `t/test-lib-github-workflow-markup.sh`: `github_escape_message_` (escapes `%` and carriage returns in test descriptions) and `find_test_case_line_` (locates the exact line of a failing test by searching the script for its description as a fixed string). The `finalize_test_case_output` function is updated to use these helpers, generating GitHub Actions annotations that include the test script name, line number, and escaped description. This ensures users can click through from the GitHub UI to the precise location of the failure.

The implementation is pragmatic: it matches test descriptions literally to avoid regex misinterpretation of special characters like `[` or `*`, and falls back to line 1 when the description isn’t found verbatim (e.g., for dynamically generated descriptions). The escaping logic prioritizes `%` first to prevent mangling of carriage return encodings. The patch also simplifies the output logic by removing redundant `test-tool` invocations and streamlining the annotation flow.

This patch directly addresses the usability gap left by the first patch (which focused on leak sanitizer failures) and completes the series’ goal of providing actionable failure annotations. The changes are well-scoped and unlikely to introduce regressions, though the helper function ordering and justification for `find_test_case_line_` remain minor points of discussion from earlier feedback. No related in-flight topics or conflicts are apparent. The series as a whole is a practical improvement to Git’s CI workflow, with this patch ensuring regular test failures are as debuggable as leak sanitizer errors.
