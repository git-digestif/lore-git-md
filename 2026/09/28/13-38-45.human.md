This is the fourth patch in Christian Couder’s five-part series introducing `uploadpack.lazyFetchTrusted`, a server-side mechanism to safely enable lazy fetching for trusted repositories. This patch specifically prevents infinite recursion when a repository is configured to lazy-fetch from another repository that in turn lazy-fetches back to the original.

The problem is straightforward: if repository R is configured to lazy-fetch from promisor remote P, and P is configured to lazy-fetch from R, a request for a missing object triggers an infinite loop. In practice, this loop terminates only when the environment variable list grows too long for `exec()`, causing a fatal error. The fix introduces a recursion depth counter, `GIT_INTERNAL_LAZY_FETCH_DEPTH`, which increments with each nested lazy-fetch attempt and aborts if it exceeds `MAX_LAZY_FETCH_DEPTH` (set to 5). This limit is chosen to allow legitimate nesting (e.g., `git fetch` invoking `index-pack` to fetch REF_DELTA bases) while preventing pathological cases.

The implementation touches `promisor-remote.c` and adds a new environment variable in `environment.h`. The `fetch_objects()` helper is modified to pass the current depth to child processes, and `lazy_fetch_objects()` checks the depth before proceeding. A new test in `t/t0410-partial-clone.sh` verifies that recursion is bounded and that the warning message is displayed. The patch is cleanly integrated with the rest of the series: it complements the server-side trust mechanism (introduced in patch 3/5) by ensuring that even trusted repositories cannot trigger infinite loops.

Junio’s feedback from v3 (a minor type nit about using `int` instead of `unsigned long` for the depth counter) is addressed here by casting the environment variable to `int`. The patch is well-motivated, with a clear explanation of the problem and a conservative limit that balances safety and functionality. The test coverage is thorough, and the warning message is informative. This is a sensible safeguard that directly addresses a real risk introduced by the broader lazy-fetch trust mechanism.
