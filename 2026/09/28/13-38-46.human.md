This is the final patch in Christian Couder’s five-part series introducing `uploadpack.lazyFetchTrusted`, a server-side protected configuration variable that lets operators explicitly mark repositories as trusted for lazy fetching. The patch activates the mechanism by teaching `git upload-pack` to consult the allowlist before disabling lazy fetching.

The implementation is straightforward: if `GIT_NO_LAZY_FETCH` is already set, the code honors it (preserving operator control). Otherwise, if the served repository is in the `uploadpack.lazyFetchTrusted` allowlist, lazy fetching remains enabled; if not, it is disabled as before. This logic is implemented in `builtin/upload-pack.c` with a simple environment check and a call to `upload_pack_lazy_fetch_trusted()`. The patch also adds extensive documentation in `git-upload-pack.adoc`, `git.adoc`, and a new `uploadpack.lazyFetchTrusted` section in `config/uploadpack.adoc`, clarifying the configuration’s syntax, semantics, and security implications. Tests in `t/t5710-promisor-remote-capability.sh` verify the behavior: trusted repositories can lazy-fetch, untrusted ones cannot, and explicit `GIT_NO_LAZY_FETCH` overrides the configuration.

The patch is well-crafted and directly addresses Junio’s feedback from v3: the environment-handling logic now preserves operator control, and the commit message is reframed to clarify that the configuration teaches the code to consult the allowlist rather than overriding the environment. The documentation is thorough, specifying that the configuration is multi-valued, identifies repositories by their `.git` directory, and warns against self-referential promisor remotes. The tests cover edge cases like non-bare repositories, explicit environment overrides, and recursion safeguards (though the recursion limit itself is introduced in patch 4/5). This patch is the payoff for the series, tying together the refactoring in patches 1–4 and delivering the core functionality. It looks ready for `next` once the series as a whole is approved.
