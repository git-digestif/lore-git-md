This thread began as an RFC to add a porcelain interface for sharing Git stashes across repositories, framing the use case as a lightweight, temporary handoff of unfinished work akin to Perforce shelves. The original proposal suggested a `git stash publish` command, but after strong opposition from **Johannes Sixt (Hannes)**, who argued that stashes should remain personal and ephemeral and that branches are the appropriate tool for shareable work, the author has now abandoned that idea. The revised proposal is far narrower: it would add porcelain wrappers (`git stash list --remote`, `git stash get`, and `git stash remove`) to simplify discovery, fetching, and deletion of remote stash refs, all of which can already be done manually with `git ls-remote`, `git fetch`, and `git push --delete`.

The core debate remains unresolved. Hannes continues to oppose even this minimal convenience layer, insisting that the existing plumbing is sufficient and that the feature encourages misuse of stashes. The author, **Hanan Arshad**, has responded by further narrowing the scope to avoid duplicating `git push` functionality, but it’s unclear whether this will sway other participants. **brian m. carlson** previously raised concerns about ref namespaces and metadata, but hasn’t yet weighed in on the revised design. No implementation exists, and the thread now hinges on whether the community sees value in reducing friction for a niche workflow or whether Hannes’s position—that stashes are inherently personal—will prevail.
