This thread proposes a new Git feature to share stashes across repositories, framing it as a lightweight way to hand off temporary work (like build configurations) without cluttering project history. The idea has evolved through several revisions in response to feedback, narrowing from a broader design to a minimal set of porcelain commands (`git stash list --remote`, `git stash get`, and `git stash remove`) that wrap existing Git plumbing.

The proposal has met strong resistance from key participants, including maintainer Junio C Hamano and longtime contributor Johannes Sixt (Hannes). Both argue that branches already serve this purpose well and that stashes should remain personal and ephemeral. Hannes’s latest reply drives this point home by demonstrating how the same workflow—transferring and applying temporary overlays—can be achieved with standard Git commands (`git switch`, `git commit`, `git push`, `git fetch`, `git show`, and `git apply`), without any new tooling. This leaves the thread at a crossroads: the author’s use case is now shown to be achievable without the proposed feature, and the maintainer’s position remains firm. Unless a compelling new argument emerges for why branches are insufficient, the proposal is unlikely to move forward. The discussion has shifted from technical implementation to whether the feature aligns with Git’s design principles.
