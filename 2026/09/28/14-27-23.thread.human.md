This thread proposes a feature to enable lightweight sharing of Git stashes across repositories, framing it as a temporary handoff of unfinished work (akin to Perforce shelves) rather than a persistent or collaborative workflow. The author, Hanan Arshad, has narrowed the design in response to feedback, now proposing porcelain commands (`git stash list --remote`, `git stash get`, and `git stash remove`) that wrap existing Git plumbing (`git ls-remote`, `git fetch`, and `git push --delete`) without introducing new object formats or server-side changes.

The discussion has reached a critical juncture with Junio C Hamano’s recent response, which aligns with Johannes Sixt (Hannes)’s long-standing opposition. Both maintain that branches are the "right tool" for shareable work and that the existing workflow (`git stash export` + manual `git push`/`fetch`/`ls-remote`) is sufficient. Junio’s brief but decisive message signals that the proposal, in its current form, is unlikely to proceed without a compelling counterargument to this philosophical stance. The thread now hinges on whether other participants can articulate a use case where the convenience of porcelain wrappers justifies diverging from Git’s design principles, which treat stashes as strictly personal and ephemeral. No technical objections to the implementation have been raised; the debate remains purely about workflow and project alignment.
