This thread is an RFC by Hanan Arshad proposing porcelain commands to share Git stashes across repositories, framing it as a lightweight alternative to branches for temporary, ephemeral work like Perforce shelves. The idea is to wrap existing Git plumbing (`git stash export`, `git ls-remote`, `git fetch`, etc.) into user-friendly commands (`git stash list --remote`, `git stash get`, `git stash remove`) without introducing new object formats or server-side changes.

The proposal has faced strong opposition from both Johannes Sixt (Hannes) and Junio C Hamano, who argue that branches are the "right tool" for shareable work and that the existing manual workflow is already sufficient. Hanan has narrowed the design twice—first abandoning a standardized ref namespace, then dropping the `git stash publish` command—to address feedback, but the maintainers remain unconvinced. In this latest response, Hanan clarifies the motivation: stashes as temporary overlays (e.g., build configurations) that testers can apply and discard without altering branch history, unlike branches which require merging or rebasing. The thread now hinges on whether this use case can overcome the philosophical objection that stashes are inherently personal and ephemeral. No implementation exists yet, and without broader support, the proposal is unlikely to proceed.
