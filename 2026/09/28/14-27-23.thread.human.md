This thread is an early-stage RFC proposing porcelain commands to share Git stashes across repositories, using existing plumbing like `git stash export` and `git push`. The author, Hanan Arshad, initially faced pushback from **brian m. carlson** over namespace rigidity and metadata trade-offs, which were addressed by making remote refs user-configurable. However, **Johannes Sixt (Hannes)** remains firmly opposed, arguing that stashes are inherently personal and ephemeral, and that branches should be used instead for shareable work.

In the latest email, Hanan narrows the scope further, framing the feature as a lightweight, temporary handoff of unfinished work—akin to Perforce shelves—rather than a replacement for branches. The proposal now emphasizes wrapping existing plumbing into a minimal porcelain interface (e.g., `git stash publish`) to make an already-possible workflow more discoverable, while deferring listing, fetching, and deletion to standard Git commands. This reframing shifts the discussion from whether stashes *should* be shareable to whether a narrowly scoped convenience command has value. No consensus has been reached, but the tone remains collaborative, with Hanan open to further adjustments to address concerns. The feature’s necessity and alignment with Git’s design principles remain the key open questions.
