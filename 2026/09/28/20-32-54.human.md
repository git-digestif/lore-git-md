This is a documentation patch that updates the `git(1)` man page to better guide users through Git’s help system. Julia Evans proposes replacing the current aspirational references to `gittutorial` and `giteveryday` (which she argues are not actually helpful to new users) with concrete, actionable instructions. The new text explains how to get help for any subcommand (`git push -h` for short help, `git push --help` for full docs) and highlights discoverable features like `git help --guides` and `git help --user-interfaces`. She deliberately omits `git help --developer-interfaces` as irrelevant to end users and leaves out the recently added `gitdatamodel` guide, judging its placement awkward in the revised flow.

The patch is well-motivated: it directly addresses user frustration that the documentation structure is opaque, and the commit message transparently lists open questions (e.g., whether to add examples for `--user-interfaces`). Kristoffer Haugsbakk, the most recent editor of this page, is CC’d, signaling awareness of prior work. The change is small (12 insertions, 10 deletions) and focused on the single file `Documentation/git.adoc`. While the patch itself is uncontroversial, the accompanying notes suggest that broader discussion about guide discoverability (e.g., surfacing guides in Git’s advice messages) may follow.
