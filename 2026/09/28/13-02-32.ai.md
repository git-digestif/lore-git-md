This is the **implementation patch (2/2)** of Kristofer Karlsson's **incremental connectivity check** series, now at v2. It introduces the core logic for the new `transfer.connectivityCheck=incremental` mode, which reduces the cost of verifying object connectivity during fetches and pushes by processing incoming commits incrementally against their parents rather than walking the full object closure of boundary commits.

The patch adds a new source file `tree-verify.c` (316 lines) that implements the incremental verifier. The algorithm processes incoming commits in topological order (ancestors first), comparing each commit's tree against its parent trees to identify and skip unchanged subtrees. Trust is established inductively: parent trees are trusted (either because they are already connected or because they were verified earlier in the traversal), and new trees are verified only where they differ from their parents. The verifier tracks tree OIDs in three states (untrusted, trusted, expanded) to avoid redundant work, and uses a merge-walk strategy to collect same-path parent subtrees as recursive comparison bases. Blobs are verified only when not already trusted, and gitlink entries (submodules) are skipped entirely.

The implementation integrates with the existing `check_connected()` machinery in `connected.c` by adding a new `--verify-trees-incremental` flag to `rev-list`. When the incremental mode is enabled, `rev-list` processes incoming commits through the verifier before the usual object traversal, ensuring that any non-commit tips (tags, trees, blobs) are still handled by the existing full check. The patch also hardens lazy-fetch protection by setting `repo->fetch_if_missing = 0` early in option parsing and adding a `BUG()` assertion to enforce this requirement, addressing a concern raised by Junio in the v1 review. Partial-clone semantics are preserved: promised objects are accepted as connected, and on-demand fetching is prevented by excluding promisor objects from traversal.

Test coverage is extensive, with 680 lines of new tests in `t5412-connectivity-check.sh` verifying semantic equivalence with the full check, corruption detection (missing objects, malformed trees, type mismatches), promisor object handling, and integration with fetch/push/clone operations. The tests include edge cases like file-to-directory transitions, merge commits, shallow boundaries, and replacement objects. Performance benchmarks in `t/perf/p5412-connectivity-check.sh` (92 lines) show dramatic speedups for small pushes to large repositories (up to 190x faster, with memory usage reduced from 3.4 GB to 14 MB in the best case) while introducing only a modest regression (1.5x slower) for very long incoming histories (10,000+ commits). Trace2 instrumentation measures trees loaded and blobs checked, providing observability into the verifier's behavior.

The patch is well-structured and self-contained, with clear separation between the verifier logic and its integration points. The commit message includes detailed performance data and a worked example illustrating how the algorithm handles subtree moves and changes. The v2 update addresses all prior technical concerns, including explicit NULL checks after `get_commit_tree_oid()` calls and robust lazy-fetch protection. The series looks ready for further review, with no unresolved objections and thorough test coverage. The incremental mode is opt-in and falls back to the full check for edge cases like deepening fetches, shallow boundaries, and promisor objects, making it a safe and conservative optimization for the common case of small pushes to large repositories.
