This thread introduces a Rust-based SHA-1 backend as an optional compile-time feature, promising a 3× performance improvement in `git index-pack` on Windows and large repositories. Johannes Schindelin, the author, frames it as a pragmatic optimization with a runtime escape hatch (`core.sha1dcBackend=c`) to fall back to the C implementation, addressing concerns about mandatory Rust dependencies. The series wires up the Rust crate via FFI, adds thread-safety fixes for Windows and non-PTHREADS builds, and includes tests for the config knob and collision detection. Schindelin has clarified that while the Rust and C backends differ in collision-detection implementation (SIMD-optimized UBC filter vs. original DV checks), they produce identical SHA-1 outputs and cover the same collision class.

His review is substantive, engaging with project-wide conventions rather than the patch’s technical merits, and is likely to prompt broader discussion about whether the performance gains justify a version bump or if the series should target 1.85.1 instead.
