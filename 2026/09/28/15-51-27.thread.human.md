This thread introduces an optional Rust-based SHA-1 backend for Git, aiming to deliver a roughly 3× performance improvement in `git index-pack` on Windows and large repositories. Johannes Schindelin, via GitGitGadget, is the author of the four-patch series, which remains at its initial v1 submission under review.

The series replaces Git’s existing C-based SHA-1 implementation (sha1dc) with a Rust crate (`sha1dc`), adding it as an optional compile-time feature. A runtime escape hatch (`core.sha1dcBackend=c`) allows users to fall back to the C implementation if needed. The first three patches set up the Rust crate via FFI, implement the escape hatch, and add thread-safety shims for Windows and non-PTHREADS builds. The newly arrived fourth patch ensures thread-safe initialization of the backend selection logic using `pthread_once()`, a prerequisite for safe multi-threaded use in commands like `git index-pack`.

Key technical details include the new `core.sha1dcBackend` config key, the Rust version requirement (1.87, higher than Git’s current minimum of 1.63), and the build system changes to integrate the crate via `Cargo.toml`. The series has sparked discussion about broader concerns: the optional nature of Rust in Git, platform support (e.g., NonStop lacks a Rust toolchain), build complexity, and the need for independent performance validation. While the thread-safety fix in the latest patch is uncontroversial, the series as a whole remains under review, with no merge to Junio’s integration branches yet. The outcome may influence the ongoing Rustification debate in the project.
