This thread introduces a patch series by Johannes Schindelin that replaces Git’s existing C-based SHA-1 implementation with an optional Rust-based backend, aiming for a roughly threefold performance improvement in `git index-pack` on Windows and large repositories. The series is now at its first version, with all four patches posted and under review but not yet merged. The Rust backend is optional at compile time, includes a runtime escape hatch to fall back to the C implementation, and addresses thread-safety concerns for Windows and non-PTHREADS builds.

The key technical changes involve wiring up the Rust crate via FFI, adding a new `core.sha1dcBackend` config key, and ensuring thread-safe initialization. While the author presents informal benchmarks showing significant speedups, the series has yet to undergo independent performance validation or broader review. Open questions remain around build complexity, platform support (particularly for systems like NonStop that lack Rust toolchains), and whether the runtime escape hatch is necessary or over-engineered.

Johannes has clarified two minor transcription errors in the original cover letter—adding "in Git for Windows" after "Windows" and fixing a missing comma—but these are purely editorial and do not affect the series’ substance. The thread is still in the early review phase, with no objections or approvals recorded yet.
