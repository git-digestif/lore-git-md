This is the second patch in Thomas Bachem’s three-part v5 series fixing a race condition in Git’s `rerere` subsystem. It introduces a `--auto` mode for `git rerere gc` that skips the operation if the `MERGE_RR.lock` is held, matching the behavior of other auto-maintenance tasks like `git pack-refs --auto`.

The patch cleanly separates manual and auto-maintenance behavior: manual invocations of `git rerere gc` (or scheduled maintenance runs) still wait for the lock and fail if it remains held, while `git rerere gc --auto` (triggered by `git maintenance run --auto` or `git gc --auto`) silently does nothing. This distinction addresses Patrick Steinhardt’s concern about auto-maintenance being non-blocking and aligns with how other auto tasks handle lock contention. The implementation is straightforward—adding a `RERERE_NOWAIT` flag to `rerere_gc()` and passing `--auto` from the maintenance machinery—and the test coverage verifies the behavior under both auto and manual scenarios, including edge cases like invalid command-line usage.

The change is well-motivated and uncontroversial. It touches only the `rerere` and maintenance subsystems, with no impact on other Git operations, and the documentation updates clearly explain the new behavior. This patch looks ready for integration.
