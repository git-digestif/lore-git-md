This is the second patch in Patrick Steinhardt’s seven-patch refactoring series that simplifies the `create_repository()` interface. The patch introduces `safe_create_leading_directories_no_share_const()`, a new helper in `path.c` and `path.h` that allows callers to pass a `const char *path` to `safe_create_leading_directories_no_share()` without requiring the path to be modifiable. The implementation is a trivial wrapper around `safe_create_leading_directories_const()`, delegating the actual work while preserving the `no_share` behavior (ignoring `core.sharedRepository`).

The patch also updates the documentation block in `path.h` to group the four `safe_create_leading_directories_*()` variants under a single explanatory paragraph, clarifying their intended use cases (git-dir vs. working-tree files), behavior regarding `core.sharedRepository`, and whether the input path is modified. This addresses Kaartic Sivaraam’s feedback from v1, which requested better documentation for the function family.

The change is purely additive and mechanical: five lines added in `path.c` (the new function) and eight lines adjusted in `path.h` (documentation rewording). No behavior changes or callers are modified in this patch; the new helper is introduced in preparation for future patches in the series that will use it. The patch is uncontroversial and aligns with the series’ goal of reducing `the_repository` usage and simplifying repository initialization.
