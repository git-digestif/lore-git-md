This thread is an early-stage RFC about adding an `includeIf.hostname:<pattern>` condition to Git’s configuration system, proposed by undergraduate student Isabella Caselli. The goal is to let users share dotfiles across machines by conditionally including Git config files based on the system’s hostname. The idea builds on Git’s existing `includeIf` mechanism and is motivated by a long-standing GitHub issue.

So far, the discussion has been constructive. Jeff King (Peff) confirmed the feature is reasonable and not actively pursued by others, while Ignacio Encinas—author of a related 2024 hostname-normalization series—clarified that his work stalled due to complexity, not rejection, removing any ambiguity about prior objections. Peff also suggested adding `git var GIT_HOSTNAME` as a debugging aid, which would expose Git’s view of the hostname. Junio C Hamano recently weighed in, expressing mild regret that Ignacio’s 2024 series didn’t complete, but reinforcing that the design was sound and Isabella can proceed with confidence if she implements the feature.

Key technical details include extending `config.c` and the test suite, with no new CLI options or on-disk format changes planned. Open questions remain about hostname normalization (short names vs. FQDNs) and matching rules (globbing, regex, or exact matching), though Peff’s feedback suggests treating this as system-dependent rather than enforcing a Git-wide rule. Isabella hasn’t yet indicated whether she’ll proceed with implementation, but the path is clear for her to do so.
