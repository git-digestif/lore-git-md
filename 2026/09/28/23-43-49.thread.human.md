This thread is an early-stage RFC about adding an `includeIf.hostname:...` condition to Git’s configuration system, proposed by undergraduate student Isabella Caselli. The goal is to let users share dotfiles across machines by conditionally including Git config files based on the system’s hostname. The idea extends Git’s existing `includeIf` mechanism, modeled after `onbranch:`, and is motivated by a GitHub issue requesting this feature.

Feedback so far has been constructive. Jeff King (Peff) confirmed the feature is reasonable and not actively pursued by others, while Ignacio Encinas clarified that his 2024 hostname-normalization work stalled due to complexity—not rejection—removing any ambiguity about prior objections. Peff also suggested adding `git var GIT_HOSTNAME` as a debugging aid to expose Git’s hostname interpretation. Key technical details include touching `config.c`, extending the test suite (`t1305-config-include.sh`), and documenting the new condition (`includeIf.hostname:<pattern>`). Open questions remain about hostname normalization (short names vs. FQDNs) and matching rules (globbing, regex, or exact matching), but no objections have been raised.

Isabella hasn’t yet indicated whether she’ll proceed with implementation, but the path is clear for her to do so. The thread remains in a collaborative, low-pressure phase, with Peff and Ignacio both supportive of the effort.
