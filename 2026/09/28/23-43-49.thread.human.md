This thread implements the `includeIf.hostname:<pattern>` condition in Git’s configuration system, allowing users to include different Git configurations based on the machine’s hostname. The feature is designed for dotfile sharing across multiple machines and was introduced by undergraduate student Isabella Caselli as a three-patch series.

The first two patches laid the groundwork: the first added `git var GIT_HOSTNAME` as a debugging aid (addressing feedback from Jeff King and Eric Sunshine), and the second fixed a test consistency issue in `t/t6500-gc.sh` by replacing an external `hostname` command with `git var GIT_HOSTNAME`. The just-posted final patch completes the feature by adding the core logic, documentation, and test coverage. It teaches Git to recognize `includeIf.hostname:<pattern>` in `.gitconfig` files, using the system-reported hostname (short name or FQDN) without normalization or DNS lookups, in line with the 2024 consensus from Ignacio Encinas’ earlier work. The implementation supports standard glob wildcards but uses exact, case-sensitive matching by default, mirroring `includeIf.onbranch:`.

The series is now fully implemented and under active review. All prior feedback from the RFC phase has been addressed, including Peff’s suggestion for `git var GIT_HOSTNAME` and Junio’s reinforcement of the 2024 design consensus. The only remaining open question is whether hostname matching should be case-insensitive or support a `hostname/i:` variant, but this does not block the current implementation. Key participants—Isabella Caselli, Jeff King, Ignacio Encinas, Junio Hamano, and Eric Sunshine—have all contributed to shaping the series, and the patches appear ready for further review.
