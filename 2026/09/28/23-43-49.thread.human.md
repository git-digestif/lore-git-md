This thread is about Isabella Caselli’s implementation of `includeIf.hostname:<pattern>` in Git’s configuration system, allowing users to conditionally include configuration files based on the machine’s hostname. The feature is designed for dotfile sharing across multiple machines and extends Git’s existing `includeIf` mechanism.

The complete three-patch v2 series is now under final review. The first patch added a `git var GIT_HOSTNAME` debugging aid (uncontroversial and ready for integration), the second fixed a test consistency issue in `t/t6500-gc.sh` by ensuring the test and production code use the same hostname resolution, and this third patch adds the core logic, documentation, and test coverage for `includeIf.hostname:<pattern>`. Junio C Hamano described the implementation as “neat” and “quite nice,” and Jeff King’s recent review found no issues, indicating the series is ready for integration. All prior feedback has been addressed, including Peff’s suggestion for `git var GIT_HOSTNAME` and Junio’s clarification on test reliability.

The implementation uses case-sensitive glob matching, consistent with `includeIf.onbranch:`, and explicitly documents that the hostname may be a short name or fully qualified domain name, depending on system configuration. The only remaining open question is whether hostname matching should be case-insensitive or support a `hostname/i:` variant, but no proposals or objections have been raised about the current semantics. The series is now complete and awaiting final approval.
