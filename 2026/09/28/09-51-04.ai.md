This is the third patch in Patrick Steinhardt’s seven-patch refactoring series that simplifies the `create_repository()` interface by enforcing statelessness. The patch targets `builtin/init-db.c` and replaces a convoluted workaround for ignoring `core.sharedRepository` during directory creation with a direct call to `safe_create_leading_directories_no_share_const()`, a helper introduced in patch 2/7.

The change removes ten lines of awkward manual state manipulation (saving, zeroing, and restoring the shared repository setting) and replaces them with a single function call. The logic is functionally identical: both approaches ignore `core.sharedRepository` when creating leading directories for the new repository. The patch is purely mechanical and does not alter behavior or touch any other files.

This is a clean, uncontroversial refactoring that aligns with the series’ broader goal of simplifying repository initialization. The commit message clearly explains the motivation and the mechanical nature of the change. No substantive review feedback has surfaced yet, but the patch looks solid and ready for integration. It is a prerequisite for the interface enforcement in patch 7/7, which will clear the repository at the start of `create_repository()`.
