This is an **announcement for Git for Windows 2.56.0**, the latest release of the Windows-specific distribution of Git. It is not a patch or development discussion for upstream Git itself, but rather a downstream packaging update.

The release tracks upstream Git v2.56.0 and includes updated dependencies (Git LFS v3.8.0, cURL v8.22.0, OpenSSL v3.5.8). The most notable change is the **drop of Windows 8.1 support**, following the MSYS2 project's lead. This shifts the default Git binary path from `/mingw64/bin/git.exe` to `/ucrt64/bin/git.exe`, though `/cmd/git.exe` remains stable for compatibility.

For users who upgraded to the previous version (v2.55.0.windows.5), an installer bug may have disabled the "Use external OpenSSH" option, forcing the bundled version. Affected users should rerun the installer with "Only show new options" unchecked to restore their preferred OpenSSH setup. Other fixes address a 4GB object commit limit, parallel checkout crashes, a vim display bug, and `git difftool` crashes with Windows-illegal filenames.

The announcement includes SHA-256 checksums for all downloadable artifacts (installers, portable builds, and MinGit variants for 32/64-bit and ARM64). No upstream Git development is discussed here—this is purely a packaging and platform-specific release. Users of Git for Windows should review the OpenSSH note and path changes if they rely on custom setups.
