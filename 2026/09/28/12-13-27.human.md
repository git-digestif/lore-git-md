This is a **bugfix discussion** targeting the reftable backend, specifically a discrepancy between Git's reflog timezone encoding and the published reftable specification.

Patrick Steinhardt, the primary maintainer of the reftable backend, confirms the issue and provides a Git-native reproducer: a test case that creates a reflog entry with a +05:30 timezone, then verifies that Git stores it as `0530` (HHMM) instead of the spec-mandated `330` (signed minutes). The test also reveals a secondary bug in the `test-reftable` helper, which fails to handle SHA-256 repositories correctly.

Patrick argues for fixing Git to match the specification rather than updating the spec to match Git. His reasoning hinges on interoperability with JGit, which already implements the spec correctly, and on the limited scope of the damage: the discrepancy only affects reflogs, the maximum divergence is under 10 hours, and reflogs are typically garbage-collected within 30 days. He dismisses the idea of introducing a format version bump as unhelpful for SHA-1 repositories, which already use version 1.

The discussion is now open for alternative proposals, but Patrick’s position is clear: treat this as a bug, fix Git, and accept the temporary timezone skew in existing reflogs. The reproducer and test case make it easy for others to verify the problem and proposed solution.
