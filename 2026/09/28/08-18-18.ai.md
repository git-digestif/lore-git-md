This is a surface-level review comment on the second patch of Thomas Bachem’s two-part `rerere` locking fix series. The patch itself is a well-motivated bugfix that allows conflict-stopping commands (e.g., `git rebase`, `git merge`) to proceed with a warning if the `rr-cache` lock remains held after the timeout, while still failing for post-resolution recording and explicit `git rerere` commands to prevent silent corruption.

Patrick Steinhardt’s comment is a minor nit: he asks whether the new advisory message in `rerere.c` should use `advise_if_enabled()` instead of the plain `advise()` call. This is purely about message formatting and suppression (the `advise_if_enabled()` helper respects the `advice.*` config namespace, allowing users to silence specific advice messages). The change would not affect the patch’s core logic or behavior, only whether the warning can be disabled via configuration. No other feedback is provided in this email.
