This is a CI/build system patch that sparked a design discussion.

Harald Nordgren’s original patch silences "missing tool" warnings for Perforce, Git LFS, and JGit on platforms where those tools are not expected (e.g., Alpine or Fedora). The change is purely about log noise: it wraps each tool check in a `case` block that matches only the platforms where the tool is meant to be installed (ubuntu-* for all three, macos-* additionally for Perforce).

Patrick Steinhardt now questions the entire premise. He points out that the current setup allows tool installation to fail without failing the build, which gives a false sense of confidence—tests that depend on those tools are simply skipped, and the pipeline stays green. His counter-proposal is to make the build fail outright if any of these tools cannot be installed on a platform that expects them. If that were done, the warnings would become redundant: on platforms that need the tools, the build would already fail; on platforms that don’t, the warnings are irrelevant.

The discussion is now open: should CI continue to tolerate missing tools (with warnings) or should it enforce their presence on the platforms that require them? No updated patch has been sent yet.
