This is a documentation patch discussion, specifically about how best to clarify that `git remote` commands operate locally and do not modify the remote repository. Junio C Hamano responds to Matthias Goergens' patch, which adds a six-line clarification to the `set-head` command's documentation, explicitly stating that it does not alter the remote's `HEAD`.

Junio acknowledges the patch improves the current wording but suggests a broader approach: adding a general statement at the top of the `git-remote` man page that *all* `git remote` commands affect only the local repository, not the remote. This would obviate the need for per-command clarifications (like the one for `set-head`) and would also cover other commands such as `remote prune`, which similarly operate locally but might be misinterpreted as remote-side actions.

The discussion is still open, with no revised patch yet. The core issue—preventing user confusion about the local-only nature of `git remote`—remains the same, but the scope of the documentation change is now under reconsideration. No code or test changes are involved; this is purely about man page wording. The thread is lightweight and uncontroversial, focusing on how to most effectively communicate an existing behavior.
