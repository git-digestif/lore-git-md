This is the fourth and final patch in Johannes Schindelin’s four-patch series introducing an optional Rust-based SHA-1 backend for Git. The patch makes the `sha1dc_init()` function thread-safe by ensuring the backend selection logic runs exactly once, even when called concurrently from multiple threads.

The change is straightforward: it replaces the direct assignment of `sha1dc_init` to `sha1dc_choose` with a set of wrapper functions (`initial_init`, `initial_clone`, etc.) that use `pthread_once()` to guard the backend selection. This prevents data races during the one-time initialization of the function pointers. The patch builds on the thread-safety shims introduced in patch 3/4, which provided `pthread_once()` implementations for Windows and non-PTHREADS builds.

The implementation is careful but verbose, repeating the `pthread_once()` check in every wrapper function to avoid code duplication. This is a pragmatic choice given the constraints of C’s memory model, though it does make the patch longer than strictly necessary. The error handling is consistent: if `pthread_once()` fails, the process dies with a descriptive message.

This patch is a prerequisite for the Rust backend to work safely in multi-threaded scenarios (e.g., `git index-pack` running with multiple threads). Without it, concurrent calls to `sha1dc_init()` could corrupt the function pointers or trigger undefined behavior. The change is uncontroversial in isolation—thread-safety fixes are rarely debated—but its necessity underscores the complexity of integrating new backends into Git’s hashing infrastructure.

The patch touches only `sha1dc_git.c` and is well-scoped, addressing a single technical requirement for the series. It does not introduce new dependencies or alter the build system, and the thread-safety guarantees are a clear improvement over the previous state.
