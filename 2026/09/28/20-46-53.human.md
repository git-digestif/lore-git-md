This is a CI/build system patch, part of a two-patch series (v2) improving GitHub Actions leak sanitizer failure reporting. Junio C Hamano’s reply to the first patch in the series raises a technical question about the interaction between `--immediate` and `invert_exit_code` in the test harness.

The patch itself is well-motivated and addresses a real usability pain point: leak sanitizer failures currently produce only a generic "Process completed with exit code 1" message, with no annotation or context. The patch stops leak-sanitizer test scripts at the first failure (using `--immediate`) and adds GitHub Actions annotations that link to the test script and display the full sanitizer output in a collapsible log group. The v2 iteration has already addressed earlier concerns about output truncation and Firefox scrolling regressions, and the commit message now clearly explains the reasoning behind `--immediate`.

Junio’s question is narrow but substantive: he notices that the patch adds a two-line comment explaining why `finalize_test_case_output` is called before the `--immediate` exit paths, but the code still exits early with `exit 0` when `invert_exit_code` is set, potentially skipping the annotation. His concern is whether this logic should be unified so that leak annotations are always emitted, regardless of the `invert_exit_code` setting. This is a classic maintainer question — not a rejection, but a request for clarification about the intended control flow.

The patch is otherwise uncontroversial and appears well-crafted. The remaining loose ends are minor: the helper functions in `t/test-lib-github-workflow-markup.sh` could still benefit from reordering for readability (as previously suggested by Ben Knoble), and the commit message could provide more detail about the new plumbing functions. Junio’s question is the only substantive technical point still open, and it is likely to be resolved with a small code adjustment or a clarifying explanation in the next iteration. For a busy reader, this patch looks like a solid improvement that is close to being ready for `next`.
