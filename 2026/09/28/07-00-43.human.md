This is a **bugfix report** targeting the reftable backend, specifically its reflog timezone encoding.

Josh McKinney identifies a mismatch between Git’s reftable implementation and the published specification. The spec requires timezone offsets to be stored as signed *minutes* (e.g., GMT+02:30 → +150), but Git 2.55.0 stores them as signed *HHMM* integers (e.g., +0230 → +230). The discrepancy is reproducible on macOS arm64 with a SHA-1 reftable repository; a Python/zlib inspection confirms that Git writes 530 for +05:30, while the spec expects 330.

Git’s reader and writer are internally consistent—it reads back the correct +05:30 offset—so the issue is purely about interoperability with other reftable implementations. Josh provides a concise shell/Python reproducer that creates an empty commit with a fixed timestamp and dumps the raw reflog bytes, making the problem easy to verify. He asks whether the spec or the implementation should change and how existing tables should be interpreted, noting that values like 330 are valid under both interpretations. His tentative conclusion is that the spec should be updated to match Git’s behavior unless other implementations would be broken.
