This is a **bugfix** for the HTTP transport layer, addressing a regression caused by an upcoming change in libcurl 8.23.0.

Jeff King (Peff) reports that starting with libcurl 8.23.0, the library will strip credentials from the URL returned by `CURLINFO_EFFECTIVE_URL`. Git currently detects redirects by comparing the requested URL with the effective URL; when credentials are stripped, the comparison fails, causing Git to incorrectly believe a redirect occurred. This triggers a flush of cached HTTP credentials, forcing the user to re-authenticate unnecessarily. The issue is visible in test `t5550.15`, which expects a clone with credentials in the URL to proceed without user prompts.

The fix introduces a helper function `match_effective_url()` that performs a more careful comparison: if the direct string comparison fails, it strips credentials from the requested URL and compares again. The credential-stripping logic uses libcurl’s own `curl_url()` interface (available since curl 7.62.0) to ensure consistency with curl’s internal behavior. For older curl versions, the extra comparison is skipped, preserving the existing behavior.

The patch is minimal and targeted, adding only the necessary compatibility shim in `git-curl-compat.h` and the new comparison logic in `http.c`. It handles errors gracefully, falling back to the old behavior if anything goes wrong. The commit message clearly explains the motivation, the upstream change, and the design choices, including why `curl_url()` was preferred over Git’s own URL parsing utilities.

This is a well-crafted fix for a real-world compatibility issue, with thorough test coverage and a clear upgrade path. It is likely to be uncontroversial and should be a strong candidate for merging.
