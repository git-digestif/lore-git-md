This is a **bugfix** for the HTTP transport layer, specifically addressing a regression caused by an upcoming change in curl 8.23.0.

Jeff King (Peff) identifies a problem where curl’s new behavior of stripping credentials from the `CURLINFO_EFFECTIVE_URL` response breaks Git’s redirect detection logic. When Git compares the requested URL (which may include embedded credentials) to the effective URL returned by curl, the string mismatch causes Git to mistakenly believe a redirect occurred, flushing stored HTTP authentication credentials and prompting the user again. This breaks existing workflows that rely on credentials embedded in URLs, as seen in failing tests like `t5550.15`.

The fix introduces a helper function `match_effective_url()` that performs a more careful comparison: if a direct string match fails, it strips credentials from the requested URL and compares again. The credential-stripping logic uses curl’s own `curl_url()` interface for consistency with curl’s internal behavior, but is conditionally compiled for curl versions 7.62.0 and later (the oldest version where `curl_url()` is available). Older versions fall back to the original string comparison, preserving compatibility.

The patch is minimal, well-motivated, and includes a clear explanation of the problem, the solution, and the trade-offs considered. It looks like a straightforward fix for a real issue that will affect users once curl 8.23.0 is released.
