This is the first patch in Kristoffer Haugsbakk’s RFC series converting Git’s `BreakingChanges` document into a proper manpage (`gitbreaking-changes(7)`). The patch mechanically moves the existing AsciiDoc content from `Documentation/BreakingChanges` into a new manpage template at `Documentation/gitbreaking-changes.adoc`, preserving all text while adapting it to manpage conventions (e.g., adding a `NAME` and `SYNOPSIS` section, demoting the "Introduction" section to second-level).

The old `BreakingChanges` file is retained but reduced to a single line pointing to the new manpage, ensuring no links break. The build system (`Makefile` and `meson.build`) is updated to include the new manpage, and `command-list.txt` is modified in a later patch (not shown here). The motivation is clear: the current plain-text document is invisible to most users, while a manpage makes the information discoverable via `git help breaking-changes` or `man gitbreaking-changes`.

The patch is purely mechanical—no content is altered beyond formatting adjustments—and the series as a whole is well-structured. If the goal of improving user visibility is accepted, this is a straightforward way to achieve it. The RFC tag indicates the author is seeking feedback on the approach before finalizing, but no substantive objections have been raised yet. The patch itself looks technically sound and uncontroversial.
