This is the **first patch in Christian Couder’s v4 series** introducing `uploadpack.lazyFetchTrusted`, a server-side protected configuration to mark repositories as trusted for lazy fetching. The patch is a **pure refactoring** of `promisor-remote.c`, extracting the lazy-fetching logic into a new helper function `lazy_fetch_objects()` while preserving existing behavior. Two minor but observable changes are documented: the `GIT_NO_LAZY_FETCH` check is now performed once up front (instead of once per promisor remote), and `promisor_remote_init()` is no longer called when lazy fetching is disabled, which is safe because downstream functions like `is_promisor_object()` do not need it in that case.

The patch addresses Junio’s **documentation feedback** from v3 by completely rewriting the comment for `try_promisor_remotes()`. The new documentation now explicitly describes the function’s behavior (fetching objects, not just checking), clarifies the semantics of `remaining_oids` and `remaining_nr` (including how they are updated when a fetch fails), and explains the ownership rules for `*remaining_oids` via the `to_free` parameter. The return value is now documented as `1` (success) or `0` (failure), reverting the v3 attempt to use `bool` for consistency with existing conventions. Junio’s earlier concern about the phrase *"from the (non-)accepted remotes"* is resolved by replacing it with precise language about ignoring promisor remotes with unset `.accepted` members.

No **functional changes** are introduced, and the refactoring is uncontroversial. The patch is **ready for integration** once the series as a whole is accepted, though it could be merged earlier if the larger effort stalls. The new `lazy_fetch_objects()` helper is later modified in patch 4/5 to add recursion safeguards, but this patch stands alone as a clean extraction. The documentation improvements directly respond to Junio’s request for clarity, and the reversion to `int` return types aligns with his preference for consistency over stylistic modernization.
