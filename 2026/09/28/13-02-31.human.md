This is a **documentation patch** and the first part of Kristofer Karlsson’s two-patch series introducing an incremental connectivity check for Git. It adds a new technical document, `Documentation/technical/connectivity-check.adoc`, that explains the connectivity invariant Git enforces after fetches, pushes, clones, or bundles, and how the existing full connectivity check works.

The document is thorough and well-structured, covering the core invariant (every object reachable from references must be locally available), the exceptions (submodules and promisor objects in partial clones), and the mechanics of the full check. It includes a clear example graph illustrating the boundary between incoming and already-connected commits, and walks through the three phases of the check: finding the incoming set, marking boundary objects as trusted, and verifying the trees of incoming commits. The document also explains edge cases like deepening fetches (where the shallow boundary moves) and non-commit tips (tags, trees, or blobs).

This patch is purely additive and does not change any code. It lays the conceptual foundation for the incremental mode introduced in the second patch, so reviewers can understand the problem space before diving into the implementation. The writing is precise and avoids oversimplification, making it a useful reference for future contributors working on connectivity or related areas. If you care about fetch/push performance or the internals of Git’s object verification, this document is worth reading.
