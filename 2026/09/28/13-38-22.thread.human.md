This thread is about a recently discovered regression in Git's alias and worktree handling. The issue surfaces when running `git -C other_repo` through an alias from within a worktree: the environment variables `GIT_DIR` and `GIT_COMMON_DIR` incorrectly point to the worktree's repository rather than `other_repo`. The problem doesn't occur when the command is run directly or from the original clone, making it a subtle but real bug.

The report comes from a new contributor (jumps_dollies_9s@icloud.com) and is thorough—it includes a minimal reproduction script, confirms the bug across multiple Git versions (2.52.0 through 2.55.0) and platforms (AlmaLinux, macOS, Ubuntu), and explains the practical impact (e.g., commands like `git -C submodule_path restore` may copy files from the wrong repository). While no patch is attached yet, the provided gist gives reviewers everything needed to reproduce and debug the issue. So far, there’s been no response from maintainers or other contributors, so the thread is still in the initial bug-report phase.
