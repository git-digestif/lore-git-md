This is a substantive review in the ongoing Git version numbering and default configuration thread. Jeff King (Peff) responds to Phillip Wood’s proposal for a `core.defaults` meta-config variable, which would allow users to opt into "modern defaults" without requiring disruptive breaking changes for everyone. Peff’s reply is skeptical, questioning the practical value of `core.defaults` and suggesting that the project’s current approach—changing defaults outright when justified—may be more straightforward.

Peff acknowledges the convenience of grouping related config options under a single variable (e.g., `feature.triangular` for triangular workflows) but argues that `core.defaults` doesn’t solve the core problem: if a default change is disruptive enough to require an opt-out mechanism, it would be just as disruptive whether users opt out via `core.defaults` or by overriding individual settings. He frames the issue as a trade-off between inertia (the status quo) and progress (changing defaults), noting that the project often defaults to inertia because it’s difficult to predict which changes will annoy the fewest users. His skepticism isn’t a rejection of Phillip’s idea but a reminder that the project’s cautious approach to default changes is rooted in uncertainty about real-world impact.

The review is substantive because it engages with the philosophical and practical challenges of default changes, rather than just the mechanics of `core.defaults`. Peff’s points about script compatibility and user annoyance apply equally to Phillip’s proposal and to the broader question of how Git should evolve its defaults. His observation that "we don’t actually *know* what will annoy the fewest people" underscores the difficulty of measuring the costs and benefits of default changes—a key concern Junio raised in his earlier reply. Peff doesn’t propose an alternative but implies that the project’s current deontological stance (avoiding disruptive changes) may be the least risky path, even if it frustrates users who want modernization.
