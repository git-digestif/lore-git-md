This thread is about a small but important fix to stabilize a test in `t5520-pull.sh` that was failing unpredictably due to reflog expiration. The test, which exercises `git pull --rebase -f`, relies on reflog entries to compute the fork point, but because the test suite hard-codes commit dates to 2005, those entries become immediately eligible for expiration under the default settings. The fix, authored by Thomas Bachem, disables reflog expiration for the duration of the test by setting `gc.reflogExpire=never` and `gc.reflogExpireUnreachable=never` in the test’s setup block.

The patch has already been queued in Junio’s `seen` branch as part of a synthetic merge base for D. Ben Knoble’s `dk/stash-apply-index-incore` series, and the current version (v2) addresses all prior feedback. The only remaining discussion is editorial: Phillip Wood’s latest review suggests minor clarifications to the commit message to correct a factual error (about `--autostash` tests not actually triggering `git stash apply --index`) and improve the phrasing around how upcoming changes interact with reflog expiration. The patch itself is unchanged and ready for integration; no further technical objections are expected. Junio, D. Ben Knoble, and Phillip Wood have all been involved in debugging and reviewing, and the fix is now effectively merged for integration testing.
