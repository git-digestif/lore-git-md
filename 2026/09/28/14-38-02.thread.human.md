This thread is about a small but important test stabilization patch for Git’s test suite. The test in question, part of `t5520-pull.sh`, was failing unpredictably because it relies on reflog entries to compute the fork point during `git pull --rebase -f`. The issue arose after a change to geometric reflog expiry made reflog cleanup more aggressive under default settings, and the test’s hardcoded 2005 commit dates meant those entries were immediately eligible for expiration. The fix, authored by Thomas Bachem, disables reflog expiration for the duration of the test by setting `gc.reflogExpire` and `gc.reflogExpireUnreachable` to `never` in the test’s setup block.

The patch has gone through three iterations, with the final version (v3) incorporating feedback from Phillip Wood, who caught a factual error in the commit message about which tests generate the problematic reflog entries. The fix itself is uncontroversial and follows established precedent—an earlier patch (`ea7d894f44`) used the same approach to stabilize rebase tests. Junio C Hamano has already queued the patch in the `seen` branch as part of a synthetic merge base for an upcoming stash-related series, so it’s effectively merged for integration testing. No further changes or discussion are expected.

The regression was bisected to a rerere-related topic and is made worse by two upcoming changes: D. Ben Knoble’s `git stash apply --index` series, which reduces reflog entries by merging the index in-core, and auto-maintenance during `git rebase`, which triggers reflog expiration earlier. The patch resolves this interaction cleanly without altering Git’s behavior outside the test suite.
