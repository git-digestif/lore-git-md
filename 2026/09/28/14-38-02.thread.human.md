This thread is about a small but important fix to stabilize a test in Git’s test suite. The test in `t5520-pull.sh`, which checks the behavior of `git pull --rebase -f`, was failing unpredictably because reflog entries it relied on were being expired too aggressively. The root cause was a recent change to geometric reflog expiry, combined with the test’s use of hard-coded 2005 commit dates, which made the entries immediately eligible for cleanup. The fix, authored by Thomas Bachem, disables reflog expiration during the test to prevent this interference.

The patch has gone through two iterations, with the second version improving the commit message to clarify the mechanics of the failure and its connection to upcoming changes in `git stash apply --index` and auto-maintenance during rebase. Junio C Hamano, the maintainer, has integrated the fix into the synthetic merge base for D. Ben Knoble’s `dk/stash-apply-index-incore` series, which is the procedural path for landing it. The latest update confirms that the merge base has been refreshed to include the v2 patch, so the fix is now effectively queued for integration testing in Junio’s `seen` branch. No technical objections remain, and the patch is expected to graduate smoothly. Key participants include Junio, Ben Knoble (who helped debug the issue), and Phillip Wood (who reviewed the commit message).
