This thread is about a small but important test stabilization patch that prevents a flaky test in `t5520-pull.sh` from failing unpredictably. The test, which exercises `git pull --rebase -f`, relies on reflog entries to compute the fork point, but because the test suite hard-codes commit dates to 2005, those entries become eligible for expiration under Git’s default settings. The issue was introduced by a change to geometric reflog expiry and is made worse by two upcoming features: D. Ben Knoble’s work on `git stash apply --index` and auto-maintenance during `git rebase`.

Thomas Bachem authored the fix, which disables reflog expiration for the duration of the test by setting `gc.reflogExpire=never` and `gc.reflogExpireUnreachable=never` in the test’s setup block. The patch has been through three iterations, with the latest version incorporating all feedback, including a correction from Phillip Wood about the source of the problematic reflog entries. Junio has already queued the patch in `seen` as part of a synthetic merge base for Knoble’s stash series, and no further changes or objections are expected. The only recent update was a minor clarification in Junio’s "What’s cooking" report to correctly attribute the flakiness to the *reflog-expire* task of auto-maintenance rather than geometric repacking, but this doesn’t affect the patch itself. The fix is effectively finalized and ready for integration.
