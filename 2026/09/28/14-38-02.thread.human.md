This thread is about a small but important test stabilization patch for `t5520-pull.sh`. The test exercises `git pull --rebase -f` but was failing unpredictably because reflog entries—dated to 2005 in the test suite—were being expired too aggressively under Git's default maintenance settings. Thomas Bachem authored the fix, which disables reflog expiration for the duration of the test by setting `gc.reflogExpire` and `gc.reflogExpireUnreachable` to `never`. This follows a precedent set by a similar fix for rebase tests (`ea7d894f44`).

The root cause was a combination of two upcoming changes: one that reduces reflog entries during `git stash apply --index` and another that triggers auto-maintenance after `git rebase`. Together, these shifted when reflog expiration occurred, exposing the test's reliance on entries that were immediately eligible for cleanup. Junio C Hamano reported the regression and bisected it to a rerere-related topic, while D. Ben Knoble and Phillip Wood assisted in debugging. The patch itself is minimal—just two `git config` lines added to the test script's setup block—and uncontroversial.

Junio has already queued the patch in `seen` as part of a synthetic merge base for D. Ben Knoble’s `dk/stash-apply-index-incore` series, resolving the procedural question of how to land it. The latest email confirms the patch is ready for inclusion, and no further discussion or objections are expected. The thread is effectively closed, with the fix now in the integration pipeline.
