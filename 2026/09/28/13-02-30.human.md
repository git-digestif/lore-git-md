This is the **v2 revision of a performance feature** introducing an incremental connectivity check for Git, gated behind `transfer.connectivityCheck=incremental`. The patch series addresses the scalability problem of the existing full connectivity check, which becomes slow in large repositories, by shifting the cost from repository size to the size of incoming changes.

The core idea remains unchanged: the verifier runs inside the existing `rev-list` subprocess (triggered by a new `--verify-trees-incremental` flag) and processes incoming commits in topological order, tracking a growing set of "trusted" objects derived from parent commits to skip unchanged subtrees. This design avoids the fragility of the earlier in-process prototype, which required complex workarounds for lazy fetches and error handling.

**Key improvements since v1** focus on robustness:
- Explicit NULL checks for `get_commit_tree_oid()` returns, preventing potential crashes.
- Explicitly setting `fetch_if_missing = 0` in `rev-list` to prevent lazy fetches during incremental checks, with a `BUG()` assertion to catch future regressions.
- A new test verifying that promised blobs are not lazy-fetched during incremental checks.
- Reuse of existing error message strings to avoid localization churn.

The benchmarks continue to show dramatic speedups for small pushes to large repositories (up to 190x faster, with memory usage dropping from 3.4 GB to 14 MB for a single commit). The incremental mode remains opt-in and falls back to the full check for edge cases like deepening fetches or very long incoming histories (where it is 1.5x slower). The author argues this tradeoff is acceptable for the target use case.

The implementation is self-contained, adding a new `tree-verify.c` file and updating only `builtin/rev-list.c` and `connected.c`. Documentation is thorough, including a new technical document explaining the algorithm and tradeoffs, and test coverage is extensive (655 lines of correctness tests, plus performance benchmarks). The series looks well-motivated and ready for further review, with the v1 feedback addressed in a straightforward manner.
