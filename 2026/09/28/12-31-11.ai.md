This is a CI/build system patch discussion. Patrick Steinhardt replies to Harald Nordgren’s patch that silences "missing tool" warnings for Perforce, Git LFS, and JGit on platforms where they are not expected. Patrick questions the fundamental premise: whether these warnings (or the tools’ optional installation) should exist at all.

Patrick argues that allowing these tools to fail silently creates a false sense of confidence, as test skips due to missing tools might go unnoticed for a long time. He proposes a stricter approach: if a tool is required for a platform, its installation should be mandatory, causing the build to fail outright if it cannot be installed. This would eliminate the need for warnings entirely, as failures would be explicit and unavoidable. On platforms where the tools are not required, the warnings are already irrelevant, so removing them would not lose any signal.

The review is substantive: it challenges the patch’s underlying assumptions rather than its implementation. The key technical detail is the trade-off between CI robustness (failing fast on missing dependencies) and flexibility (allowing optional tools to be skipped). No specific code changes are suggested yet, but the discussion implies a potential future patch to make tool installation mandatory where expected. The thread’s open question is whether the project prefers strict failure or permissive skipping for these tools.
