This is the first patch in Christian Couder’s five-part v4 series introducing `uploadpack.lazyFetchTrusted`, a server-side mechanism to mark repositories as trusted for lazy fetching. This patch is a pure refactoring of the promisor-remote subsystem, extracting the lazy-fetching logic from `fetch_objects()` and `promisor_remote_get_direct()` into a new helper function, `lazy_fetch_objects()`.

The motivation is twofold: first, the current code checks the `GIT_NO_LAZY_FETCH` environment variable once per promisor remote, which is inefficient; second, the logic for deciding which promisor remotes to try is tangled with the logic for checking whether unfetched objects are promisor objects. The refactoring consolidates the environment check into a single up-front call and clarifies the ownership rules around the `remaining_oids` and `to_free` parameters, which are easy to misuse. The patch also documents both the new `lazy_fetch_objects()` and the existing `try_promisor_remotes()` functions, addressing Junio’s v3 feedback about parameter semantics.

The changes are observably equivalent: the `GIT_NO_LAZY_FETCH` check now happens once instead of per remote, and `promisor_remote_init()` is called only when lazy fetching is enabled, which aligns with the convention that initialization should happen where the data is needed. The patch touches only `promisor-remote.c` and is a clean refactoring with no intended behavior change, making it a safe candidate for early integration if the series stalls. Junio’s v3 review requested clearer documentation for `try_promisor_remotes()` and its parameters; this patch delivers that, though the wording may still need refinement in future iterations. The refactoring sets the stage for the recursion safeguards and configuration integration introduced in later patches.
