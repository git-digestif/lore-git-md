This is the first patch in a two-patch CI/build system series (v2) that improves GitHub Actions leak sanitizer failure reporting. It stops leak-sanitizer test scripts at the first failure (using `--immediate`) and adds GitHub Actions annotations for leaks, linking them to the test script and displaying the full sanitizer output in a collapsible log group.

The patch modifies `ci/lib.sh` to add `--immediate` to `GIT_TEST_OPTS` for leak sanitizer jobs, ensuring scripts exit at the first leak rather than continuing and producing redundant "not ok" reports. In `t/test-lib-github-workflow-markup.sh`, it introduces three new functions: `github_annotation_` (a helper for generating annotations), `finalize_test_leak_output` (which creates a leak-specific annotation pointing to the test script and embeds the full sanitizer output in a log group), and tracks the script name via `github_markup_script_name`. The patch also reorders logic in `t/test-lib.sh` to ensure failure annotations are written *before* `--immediate` exits the script, preventing them from being silently dropped.

The commit message clearly explains the motivation: leaks are currently buried at the end of test runs with no annotation, producing only a generic "Process completed with exit code 1" message. The `--immediate` change avoids false "not ok" reports from later tests, while the annotation and log group ensure the full leak output remains visible and actionable. The patch is well-scoped and directly addresses the usability pain point described in the thread.

This patch is uncontroversial in its goals but has seen substantive review discussion about the `--immediate` trade-off (whether stopping at the first leak hides subsequent leaks) and helper function justification. The v2 iteration has addressed earlier concerns about output truncation and Firefox scrolling regressions, and the commit message now better explains the reasoning behind `--immediate`. The remaining loose ends are minor: the helper functions in `t/test-lib-github-workflow-markup.sh` could still benefit from reordering for readability, and the commit message could provide more detail about `find_test_case_line_` (though this function is introduced in the second patch).

Key technical details for follow-up discussion:
