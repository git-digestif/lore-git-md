This is a documentation patch discussion, specifically a review reply to Julia Evans’s proposed rewrite of the `git(1)` man page introduction. The patch aims to replace outdated tutorial references with direct instructions for accessing Git’s help system.

Ben Knoble’s reply is substantive but narrowly focused. He praises the conciseness of Julia’s proposed examples (`git push -h` and `git push --help`) but argues that `git help cmd` is more powerful—it supports aliases, HTML output, and other document types. He notes that simply mentioning `git help` in the man page is unlikely to guide users toward discovering `git help cmd`, though the help output itself does mention it. His concern is that the patch’s examples might steer users away from the more flexible `git help` subcommand.

The review also includes a brief aside about discoverability: Ben observes that Git lacks easy access to the HTML documentation installed on the system (via `git --html-path`), something he works around with a custom script. This point is unrelated to the patch under discussion and does not propose a change.

The thread remains open; no revised patch has been posted yet. The discussion is about wording and discoverability, not about the patch’s core goal, which is still well-motivated and uncontroversial.
