This is the final patch (5/5) in Christian Couder’s v4 series introducing `uploadpack.lazyFetchTrusted`, a server-side protected configuration variable that lets operators explicitly mark repositories as trusted for lazy fetching. The patch activates the mechanism by conditionally setting `GIT_NO_LAZY_FETCH=1` in `builtin/upload-pack.c`—but only if the environment variable isn’t already set by the operator and the served repository isn’t in the allowlist.

The implementation now preserves operator control: if `GIT_NO_LAZY_FETCH` is already set, the code honors it and leaves it untouched. Otherwise, it checks whether the repository is in the `uploadpack.lazyFetchTrusted` allowlist; if so, lazy fetching remains enabled, and if not, it is disabled as before. This logic directly addresses Junio’s v3 feedback about operator precedence and reframes the commit message to clarify that the configuration variable teaches the code to consult the allowlist rather than overriding the environment.

The patch also adds extensive documentation for `uploadpack.lazyFetchTrusted` in `Documentation/config/uploadpack.adoc`, including multi-valued syntax, repository identification by `.git` directory, interpolation rules (`~` and `%(prefix)`), security implications, and warnings against self-referential promisor remotes. Cross-references are added to `git-upload-pack.adoc` and `git.adoc` to guide users from the environment variable to the new configuration. The test suite expands `t/t5710-promisor-remote-capability.sh` with six new test cases covering the allowlist mechanism, operator override, protected-config enforcement, recursion safeguards, and path validation for non-bare repositories.

Key symbols introduced or modified include the conditional environment-setting logic in `cmd_upload_pack()` and the new documentation sections. The patch completes the series by making the configuration variable operational, with all prior feedback incorporated and no unresolved high-weight concerns specific to this patch.
