This thread is about a bugfix for Git’s HTTP transport layer to handle a behavioral change in libcurl 8.23.0, where credentials are stripped from the effective URL returned by libcurl. This causes Git’s redirect detection to fail, triggering unnecessary credential cache flushes. Jeff King (Peff) proposed a patch that introduces a helper function, `match_effective_url()`, to compare URLs while accounting for stripped credentials using libcurl’s `curl_url()` interface (available since curl 7.62.0). For older curl versions, the extra comparison is skipped.

The patch is under review, with no prior versions, and has gained strong support from Junio C Hamano, who endorsed the current implementation as the simplest and most reliable approach. Junio also agreed with the decision to maintain compatibility with curl 7.62.0 rather than raising the minimum supported version. Patrick Steinhardt previously suggested an alternative approach using `CURLINFO_REDIRECT_COUNT` to detect redirects directly, which would avoid URL parsing entirely, but this has not gained further traction since Junio’s approval of the original patch.

The key technical details involve changes to `http.c` and the introduction of `git-curl-compat.h`, with no changes to on-disk formats. The existing test `t5550.15` now passes with libcurl 8.23.0+. The main open question remains whether to proceed with the URL-based comparison or switch to the `CURLINFO_REDIRECT_COUNT` approach, though the latter seems less likely given Junio’s endorsement of the current patch. No other reviewers have weighed in since Patrick’s initial feedback.
