This thread is about a bugfix for Git’s HTTP transport layer that addresses a regression introduced by libcurl 8.23.0. The issue occurs when libcurl strips credentials from the effective URL during redirects, causing Git to incorrectly detect a URL change and unnecessarily flush cached HTTP credentials. Jeff King (Peff) proposed a patch that introduces a helper function, `match_effective_url()`, to perform a more careful comparison by stripping credentials from the requested URL using libcurl’s `curl_url()` interface. This approach is backward-compatible with older libcurl versions, where the extra comparison is skipped.

The discussion initially considered an alternative approach using `CURLINFO_REDIRECT_COUNT`, suggested by Patrick Steinhardt, but Peff’s testing showed this method was unreliable because libcurl counts the initial 401→200 auth retry as a redirect. After this finding, Patrick endorsed Peff’s original URL-based solution, resolving the only substantive implementation question. Junio C Hamano had already signaled the patch was on track for merging, calling the compatibility choice “very sensible.” The patch touches `http.c` and introduces no user-visible changes beyond fixing the regression, with test coverage confirmed via `t5550.15`.

With no remaining objections or requests for revision, the patch is now a strong candidate for inclusion in Junio’s `next` branch. The fix is narrowly scoped, well-tested, and addresses a clear regression without altering Git’s on-disk format or user-facing behavior.
