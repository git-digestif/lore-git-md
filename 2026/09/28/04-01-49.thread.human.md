This thread is about a bugfix patch from Jeff King (Peff) that addresses a regression in Git’s HTTP transport layer. Starting with libcurl 8.23.0, the library strips credentials from the effective URL returned after a request, causing Git’s redirect detection logic to fail. This triggers an unnecessary flush of cached HTTP credentials, forcing users to re-authenticate. Peff’s patch introduces a helper function, `match_effective_url()`, to perform a more careful comparison by stripping credentials from the requested URL using libcurl’s `curl_url()` interface.

Patrick Steinhardt has now submitted a substantive review, questioning whether the patch’s approach is the most direct solution. He suggests using `CURLINFO_REDIRECT_COUNT`—a libcurl API available since 2001—to detect redirects instead of comparing URLs. This alternative would avoid URL parsing entirely and could simplify the fix. The discussion is now focused on whether to proceed with Peff’s patch or adopt Patrick’s suggested approach. No other reviews or objections have been recorded yet, and the patch remains under review.
