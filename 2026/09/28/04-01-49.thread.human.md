This thread is about a **bugfix for Git’s HTTP transport layer** to address a regression caused by an upcoming change in libcurl 8.23.0. The issue arises because libcurl will soon strip credentials from the URL returned by `CURLINFO_EFFECTIVE_URL`, causing Git to misdetect redirects and unnecessarily flush cached HTTP credentials. Jeff King (Peff) identified the problem and proposed a targeted fix.

The solution introduces a helper function, `match_effective_url()`, which performs a more careful comparison of requested and effective URLs. If a direct string comparison fails, it strips credentials from the requested URL using libcurl’s `curl_url()` interface (available since curl 7.62.0) and retries the comparison. This ensures consistency with libcurl’s behavior while gracefully falling back to the old logic for older curl versions. The patch is minimal, focused on `http.c` and a new compatibility header, and includes clear error handling.

The fix is well-documented, with a commit message explaining the upstream change, the design rationale, and test coverage (notably `t5550.15`). Given its narrow scope and real-world impact, it is likely to be uncontroversial and a strong candidate for merging. No objections or alternative approaches have been raised in the thread so far.
