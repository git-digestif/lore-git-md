This thread is about a bugfix for Git’s HTTP transport layer to handle a change in libcurl 8.23.0, where credentials are stripped from the effective URL during redirects. This causes Git to incorrectly flush cached HTTP credentials, as the URL comparison for detecting redirects fails. Jeff King (Peff) proposed a patch that introduces a helper function, `match_effective_url()`, to perform a more careful comparison by stripping credentials from the requested URL using libcurl’s `curl_url()` interface. This approach is backward-compatible with older libcurl versions, which skip the extra comparison.

The discussion has centered on whether to use the URL-based comparison or an alternative approach suggested by Patrick Steinhardt, which uses `CURLINFO_REDIRECT_COUNT` to detect redirects directly. Peff’s latest email explains why the `CURLINFO_REDIRECT_COUNT` approach was ruled out: libcurl counts the initial 401→200 auth retry as a redirect, making the count unreliable for detecting actual URL changes. This confirmation leaves the original patch’s implementation as the only viable solution. Junio C Hamano has already endorsed the current approach, calling the compatibility choice “very sensible,” and no new objections or requests for revision have emerged.

The patch touches `http.c` and `git-curl-compat.h`, introducing the `match_effective_url()` helper and ensuring redirect detection works correctly with libcurl 8.23.0+. The existing test `t5550.15` now passes with the new libcurl version, confirming the fix. With no remaining open questions or substantive objections, the patch appears ready for merging.
