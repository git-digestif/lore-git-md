This is the third patch in the RFC series introducing `gitbreaking-changes(7)`, a new manpage that moves Git’s breaking changes documentation from a plain-text file to a more discoverable format. The series as a whole aims to improve user visibility of upcoming breaking changes by integrating the content into the standard documentation system.

This specific patch adds a short note (formatted as an AsciiDoc admonition) to clarify that the document is a *living draft* and may change between releases. The motivation is to preempt potential confusion: users reading the manpage in a released version of Git might encounter outdated information and mistakenly post feedback about decisions that have already been revised in the development version. The example in the commit message illustrates this risk—someone on Debian Stable might read about Git 3.0 changes and complain, only to learn the document now reflects Git 4.0 plans.

The change is minimal and targeted: it inserts a 6-line note after the existing "living document" paragraph, using Git’s standard AsciiDoc admonition style. The wording is concise and avoids prescribing specific actions (like how to fetch the latest source), keeping the focus on awareness rather than process. No other files are modified, and the patch maintains the series’ documentation-only scope.

The patch is well-motivated and addresses a real usability concern. The note is unobtrusive and unlikely to be controversial, though the broader RFC series may still draw feedback on whether a manpage is the right vehicle for this content. For now, this patch is a sensible, low-risk addition that complements the series’ goal of making breaking changes more transparent.
