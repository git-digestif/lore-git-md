Subject: [PATCH] git(1): rewrite intro to orient users toward help system
Series version: standalone patch (no series)
Originating author: Julia Evans
Thread type: documentation patch

Core problem or goal
Rewrite the introductory section of the `git(1)` man page to replace outdated references to `gittutorial` and `giteveryday` with concrete, actionable instructions for accessing Git’s help system (`git push -h`, `git push --help`, `git help --guides`, `git help --user-interfaces`). The goal is to improve discoverability and practicality for new users by directing them to the help system rather than deprecated tutorials.

Current status
Under review; no prior versions. Patch touches only `Documentation/git.adoc`. Junio C Hamano has weighed in, aligning with Ben Knoble’s substantive review and signaling that the current `--help`-centric approach may need adjustment to incorporate `git help cmd` while preserving simplicity for new users. No explicit maintainer decision yet; next step likely involves Julia Evans revisiting the wording.

Key technical details
- File modified: `Documentation/git.adoc`
- Symbols/sections: introductory section of `git(1)` man page
- Behavior change: removes outdated tutorial references, adds direct help commands (`git cmd -h`, `git cmd --help`, `git help --guides`, `git help --user-interfaces`)
- No on-disk format or test coverage changes

Open questions and loose ends
- **Discoverability trade-off**: The debate over `git cmd --help` vs. `git help cmd` remains unresolved. Ben Knoble and Junio C Hamano advocate for `git help cmd` due to its support for aliases, HTML output, and broader documentation formats, while Julia Evans’ patch prioritizes simplicity for new users. Resolution pending: whether to hint at `git help cmd` as an alternative or revise the patch to emphasize it.
- **HTML documentation access**: Ben Knoble noted (as an aside) that accessing HTML docs via `git --html-path` is cumbersome and poorly integrated into the help system, though this is unrelated to the current patch.

Participant positions

- Ben Knoble: **substantive review** praising conciseness but questioning the omission of `git help cmd`. Argues for its superiority in functionality (aliases, HTML output) while acknowledging the patch’s goal of streamlining. - Junio C Hamano (maintainer): **high-weight response** aligning with Ben Knoble’s position.
