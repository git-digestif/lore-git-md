Subject: [PATCH] git(1): rewrite intro to orient users toward help system
Series version: standalone patch (v3)
Originating author: Julia Evans
Thread type: documentation patch

Core problem or goal
Rewrite the introductory section of the `git(1)` man page to replace outdated references to `gittutorial`, `giteveryday`, `user-manual`, `datamodel`, and `cli` with concrete, actionable instructions for accessing Git’s help system (`git push -h`, `git push --help`, `git help push`, `git help --guides`, `git help --user-interfaces`). The goal is to improve discoverability and practicality for new users by adopting an "every page is page one" model, where documentation is self-contained and does not assume prior reading of other guides. The patch prioritizes the help system over standalone guides to align with modern user expectations and reduce maintenance burden. The rationale for removing outdated guides is now fully documented: `cli` is developer-focused and not useful for interactive users, `user-manual` is outdated (e.g., still recommending `git format-patch` for collaboration), and `datamodel` feels orphaned once the other guides are removed. The patch also clarifies why `git-scm.com/docs` is preferred over `git.github.io/htmldocs/git.html` (the former tracks the latest *released* version of Git, not the tip of `master`).

Current status
Ready for integration; patch v3 is final and incorporates all feedback, including Junio’s requested commit message update. The patch is uncontroversial and on track for `master`. No further code changes or discussion are needed.

Key technical details

The patch drops the redundant link to `git.github.io/htmldocs/git.html` in favor of `git-scm.com/docs`, which tracks the latest *released* version of Git.
