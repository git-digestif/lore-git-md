Subject: [PATCH] git(1): rewrite intro to orient users toward help system
Series version: standalone patch (v3)
Originating author: Julia Evans
Thread type: documentation patch

Core problem or goal
Rewrite the introductory section of the `git(1)` man page to replace outdated references to `gittutorial`, `giteveryday`, `user-manual`, `datamodel`, and `cli` with concrete, actionable instructions for accessing Git’s help system (`git push -h`, `git push --help`, `git help push`, `git help --guides`, `git help --user-interfaces`). The goal is to improve discoverability and practicality for new users by directing them to the help system, while balancing simplicity and functionality. The v2 patch adopted a tiered approach: simple commands (`-h`, `--help`) upfront, followed by `git help cmd` and its advanced features (e.g., HTML output via `--web`), and dropped the redundant link to `git.github.io/htmldocs/git.html` in favor of `git-scm.com/docs`. The v3 iteration adds explicit rationale for removing the `user-manual`, `datamodel`, and `cli` guides, addressing Junio C Hamano’s request for clarity on why these are no longer relevant to new users. The thread now fully documents the distinction between `git-scm.com/docs` (updated to the latest *released* version of Git) and `git.github.io/htmldocs/git.html` (tracks the tip of `master` and may include unreleased features), confirming that the former’s release-aligned content is more appropriate for general users.
