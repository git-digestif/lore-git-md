Subject: [PATCH] git(1): rewrite intro to orient users toward help system
Series version: standalone patch (no series)
Originating author: Julia Evans
Thread type: documentation patch

Core problem or goal
Rewrite the introductory section of the `git(1)` man page to replace outdated references to `gittutorial` and `giteveryday` with concrete, actionable instructions for accessing Git’s help system. The goal is to improve discoverability and practicality for new users by directing them to the help system (`git push -h`, `git push --help`, `git help cmd`, `git help --guides`, `git help --user-interfaces`), while balancing simplicity and functionality. The current proposal adopts a tiered approach: simple commands upfront, with a later mention of `git help`’s advanced features (e.g., HTML output via `--web`).

Current status
Under review; no prior versions. Patch touches only `Documentation/git.adoc`. Junio C Hamano and Ben Knoble have provided substantive feedback, with Junio signaling openness to a compromise that incorporates `git help cmd` without sacrificing simplicity. Julia Evans’ latest proposal (a tiered approach) directly addresses this, and Junio’s most recent email refines the wording further with two mechanical corrections: (1) the tutorial’s own output is outdated (noted but not blocking), and (2) the command `git help push --web` must be written as `git help --web push` to match Git’s CLI style. The thread’s main contention (balancing simplicity and functionality) is resolved; the next step is a v2 patch incorporating these tweaks. No explicit maintainer decision yet.
