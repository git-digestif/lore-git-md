Subject: [PATCH] git(1): rewrite intro to orient users toward help system
Series version: standalone patch (no series)
Originating author: Julia Evans
Thread type: documentation patch

Core problem or goal
Rewrite the introductory section of the `git(1)` man page to replace outdated references to `gittutorial` and `giteveryday` with concrete, actionable instructions for accessing Git’s help system. The goal is to improve discoverability and practicality for new users by directing them to the help system (`git push -h`, `git push --help`, `git help --guides`, `git help --user-interfaces`) while balancing simplicity and functionality. The current proposal adopts a tiered approach: simple commands upfront, with a later mention of `git help`’s advanced features (e.g., HTML output via `--web`).

Current status
Under review; no prior versions. Patch touches only `Documentation/git.adoc`. Junio C Hamano and Ben Knoble have provided substantive feedback, with Junio signaling openness to a compromise that incorporates `git help cmd` without sacrificing simplicity. Julia Evans’ latest proposal (a tiered approach) directly addresses this, likely resolving the thread’s main contention. No explicit maintainer decision yet; next step is review of the revised wording.

Key technical details
- File modified: `Documentation/git.adoc`
- Symbols/sections: introductory section of `git(1)` man page
- Behavior change: removes outdated tutorial references, adds direct help commands (`git cmd -h`, `git cmd --help`, `git help cmd`, `git help --guides`, `git help --user-interfaces`), and mentions HTML documentation access via `--web`
- No on-disk format or test coverage changes
