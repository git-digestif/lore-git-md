This thread is about an RFC patch series that moves Git’s plain-text `BreakingChanges` document into a new `gitbreaking-changes(7)` manpage, making upcoming breaking changes more visible to users via `git help` and `man`. The series is now complete at four patches, with all substantive feedback addressed.

Kristoffer Haugsbakk proposed the change to improve discoverability and usability, converting message-ID references to clickable URLs and clarifying the document’s living-draft status. Patrick Steinhardt reviewed the series, suggesting usability improvements like moving the "how to add new entries" section to the end of the document—all of which have been incorporated. The latest exchange resolves the last open questions: Patrick endorsed Kristoffer’s three-step restructuring plan (convert, rename, and add a pointer file) and agreed to retain a historical section for Git 3.0, deferring Git 4.0 discussion until later. This clears the way for reviewers to focus on the current patches without lingering mechanical or lifecycle concerns.

The series touches only documentation (`Documentation/gitbreaking-changes.txt`, `git.txt`, `command-list.txt`, `Makefile`, and `meson.build`), adding no new code or on-disk changes. It remains under review as an RFC, but the path forward is now clear. No further changes are requested at this stage.
