This thread is an RFC patch series by Kristoffer Haugsbakk to improve the visibility of Git’s upcoming breaking changes by converting the existing plain-text `BreakingChanges` document into a proper manpage, `gitbreaking-changes(7)`. The goal is to make the document more discoverable via `git help` and `man`, while also clarifying its living-draft nature to avoid user confusion. The series is now complete with four patches and is under review.

Patrick Steinhardt has provided substantive feedback, engaging with both the motivation and implementation. Kristoffer has accepted all of Patrick’s suggestions, including moving the "how to add new entries" section to the end of the document and fixing minor formatting issues (e.g., ensuring two spaces after URLs). The latest patch replaces all message-ID references with clickable URLs to `lore.kernel.org` threads, improving usability. No new patch version has been posted yet, but the series is ready for further review.

The only open question is forward-looking: whether to retain the manpage post-Git 3.0 and add a new section for Git 4.0, or to archive it. Patrick suggests retaining it, while Kristoffer proposes keeping a historical section for Git 3.0 and deferring Git 4.0 discussion. This is exploratory and not a blocker. The series remains an RFC, seeking broader feedback on the approach before finalization.
