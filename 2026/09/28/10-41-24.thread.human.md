This thread is about an RFC patch series by Kristoffer Haugsbakk to convert Git’s existing plain-text `BreakingChanges` document into a proper manpage, `gitbreaking-changes(7)`, so users can access it via `git help` and `man`. The series has broad support for its goal—improving discoverability of upcoming breaking changes—and has addressed all substantive feedback except for one narrow formatting question.

The only remaining disagreement is how to format message-ID references in the manpage. Junio C Hamano proposed a hybrid format combining a clickable URL with the raw message-ID (e.g., `cf. https://lore.kernel.org/git/xmqqa59i45wc.fsf@gitster.g/[<xmqqa59i45wc.fsf@gitster.g>^]`), which Kristoffer implemented in the revised patch. However, he now pushes back, arguing that the hybrid format creates usability issues in HTML output, where message-IDs are rendered as `mailto:` links and short message-IDs resemble email addresses. He prefers plain URLs and has suggested dropping the patch if consensus can’t be reached, as the current URL-only approach is already an improvement over raw message-IDs. Patrick Steinhardt, who reviewed the series, has not yet weighed in on this specific point.

The series itself is technically aligned and ready to proceed once this formatting question is resolved. The files touched include `Documentation/gitbreaking-changes.adoc` (the new manpage), `Documentation/git.txt` and `command-list.txt` (for integration), and the build system (`Makefile`, `meson.build`). The broader goal—making breaking changes more visible to users—is uncontested, and the outcome of this discussion will only affect whether the final manpage uses the hybrid format or plain URLs. No new patch version has been posted yet.
