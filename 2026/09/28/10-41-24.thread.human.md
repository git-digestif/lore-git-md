This thread is about converting Git’s plain-text `BreakingChanges` document into a proper manpage, `gitbreaking-changes(7)`, to make upcoming breaking changes more visible to users via `git help` and `man`. The series, now at v2 with five patches, is ready for integration and has addressed all reviewer feedback.

Kristoffer Haugsbakk proposed the change and restructured the series into logical steps—preparation, renaming, URL formatting, and a final admonition—to improve readability. Key updates since v1 include replacing commit-message-style message-IDs with plain URLs (to fix rendering issues), moving the "Adding new items" discussion to the end, and adding a note clarifying the document’s living-draft status. The build system (`Makefile`, `meson.build`, `command-list.txt`) has been updated to include the new manpage, and `Documentation/BreakingChanges.adoc` remains as a stub pointing to the new file.

Reviewers Patrick Steinhardt and Junio C Hamano endorsed the series’ goals, with Junio initially proposing a hybrid URL+message-ID format but later conceding to plain URLs after testing revealed usability issues. D. Ben Knoble’s recent feedback was minor, noting that while the document is technically accessible via `git --html-path`, this method is far less discoverable than a manpage—reinforcing the series’ motivation without raising technical concerns. The only remaining task is resolving merge conflicts with `ps/ref-storage-format` (in `master`) and `bc/restrict-hex-to-lowercase` (in `seen`) during integration. The series is otherwise complete and uncontested.
