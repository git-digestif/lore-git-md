The `gitbreaking-changes(7)` RFC series is moving toward finalization after addressing all substantive feedback. The goal is to make Git’s upcoming breaking changes more visible to users by converting the existing plain-text `BreakingChanges` document into a proper manpage, accessible via `git help` and `man`. The series, now complete at four patches, has resolved all major design questions and usability concerns raised during review.

The key remaining technical detail was how to format links to mailing-list discussions in the new manpage. Junio C Hamano proposed a hybrid approach—embedding both a clickable URL and the raw message-ID (e.g., `cf. https://lore.kernel.org/git/xmqqa59i45wc.fsf@gitster.g/[<xmqqa59i45wc.fsf@gitster.g>^]`)—to preserve the message-ID for future reference while keeping the rendered output clean. Patrick Steinhardt has now accepted this approach, aligning the series with existing Git documentation conventions. The only action left is for Kristoffer Haugsbakk to update patch 2/4 to implement this change.

The broader goals of the series—improving discoverability, clarifying the document’s living-draft nature, and integrating it into the documentation build system—are uncontroversial. The document will retain a historical section for Git 3.0, with discussion of Git 4.0 deferred. Once the hybrid link format is incorporated, the series should be ready for merging.
