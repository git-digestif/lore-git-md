This thread is about converting Git’s `BreakingChanges` document into a proper manpage, `gitbreaking-changes(7)`, to make upcoming breaking changes more discoverable to users via `git help` and `man`. The series, originally proposed by Kristoffer Haugsbakk, is now in its second version (v2) and is fully reviewed and ready for integration.

All feedback has been addressed, including structural improvements, URL formatting, and build system updates. The series splits the conversion into logical steps, moves the "Adding new items" discussion to the end for better readability, and adds a note clarifying the document’s living-draft nature. The only remaining work is Junio’s integration, which will require resolving minor merge conflicts with two other topics already in `master` and `seen`. These conflicts are trivial—just moving entries from the old file to the new one.

The motivation is straightforward: breaking changes are currently buried in a plain-text file that users rarely find, while a manpage ensures they’re easily discoverable. The series has broad support, with no outstanding objections or open questions. Kristoffer’s recent follow-up is a gentle nudge to check if the maintainer still plans to pick it up, as there’s been no response since v2 was posted twelve days ago. The series is technically complete and ready to go.
