This thread is about converting Git’s plain-text `BreakingChanges` document into a proper manpage, `gitbreaking-changes(7)`, to make upcoming breaking changes more visible to users via `git help` and `man`. The series, originally posted as an RFC by Kristoffer Haugsbakk, is now ready for its second version after all review feedback has been addressed.

The only remaining point of contention—how to format message-ID references in the manpage—has been resolved. Junio C Hamano initially proposed a hybrid URL+message-ID format for usability and future-proofing but withdrew his objection after testing revealed HTML rendering issues (notably `mailto:` links). The consensus now favors plain URLs (e.g., `https://lore.kernel.org/git/xmqqa59i45wc.fsf@gitster.g/`), which are clickable in terminals and browsers and require minimal effort from email-only users to extract the message-ID if needed. Kristoffer’s proposed footnote-based compromise to preserve raw message-IDs was rejected as unnecessary.

With this final decision, the series is technically complete and ready for integration. Kristoffer will post a v2 incorporating the plain-URL consensus, after which the series can be merged. The effort remains documentation-only, touching files like `Documentation/gitbreaking-changes.adoc`, `Documentation/git.txt`, and build system updates, with no new symbols, CLI options, or on-disk format changes. The broader goal of improving user visibility of breaking changes has been uncontroversial throughout the thread.
