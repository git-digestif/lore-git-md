This thread is about an RFC patch series to convert Git’s `BreakingChanges` document into a proper manpage, `gitbreaking-changes(7)`, making upcoming breaking changes more discoverable to users. The series is now technically aligned on all feedback except for one narrow but contentious point: how to format message-ID references in the manpage.

Kristoffer Haugsbakk, the author, has posted a revised version of the second patch in the series, addressing Junio C Hamano’s proposal to use a hybrid format for message-ID references—combining a clickable URL with the raw message-ID (e.g., `cf. https://lore.kernel.org/git/xmqqa59i45wc.fsf@gitster.g/[<xmqqa59i45wc.fsf@gitster.g>^]`). Kristoffer pushes back, arguing that the hybrid approach creates usability issues, particularly in HTML output where the message-ID is rendered as a `mailto:` link, which could confuse users. He prefers plain URLs, noting that most message-IDs in the document are short and visually similar to email addresses, making them less intuitive as links. He’s suggested dropping the patch entirely if consensus can’t be reached, as the current URL-only approach is already an improvement over raw message-IDs.

Patrick Steinhardt has endorsed the series’ goals and the hybrid format, while Junio’s proposal aligns with existing conventions in Git’s documentation (e.g., `RelNotes`). The disagreement is purely about user experience trade-offs—whether to prioritize clickable links with raw message-IDs for future reference or simpler, more recognizable URLs. The series remains under review as an RFC, with no unresolved technical or conceptual questions beyond this formatting detail. Kristoffer is expected to post a final version of the patch once this is resolved.
