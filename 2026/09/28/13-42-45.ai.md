This is the v4 update to the final patch in Christian Couder’s five-part series introducing `uploadpack.lazyFetchTrusted`, a server-side protected configuration that lets operators mark repositories as trusted for lazy fetching. The patch now fully addresses Junio’s design critique about environment variable handling: instead of unconditionally setting `GIT_NO_LAZY_FETCH=1` early and later relaxing it, the code now checks the environment first (`no_lazy_fetch_set = !!getenv(NO_LAZY_FETCH_ENVIRONMENT)`) and only sets `GIT_NO_LAZY_FETCH` if it wasn’t already set by the operator. This preserves operator control while still defaulting to safe behavior for untrusted repositories. The commit message is updated to explicitly list the three possible states (operator-set environment, allowlisted repository, default behavior) and clarify what the operator vouches for when listing a repository (trustworthiness of its promisor remotes, configuration, and hooks).

The rest of the patch remains unchanged: it activates the mechanism by setting `GIT_NO_LAZY_FETCH=0` for trusted repositories, documents the new configuration in `git-upload-pack.adoc`, `git.adoc`, and `Documentation/config/uploadpack.adoc`, and adds six test cases covering allowlisting, recursion safeguards, and non-bare repository handling. The series as a whole is now technically complete, with all v3 feedback addressed and no new substantive reviews posted. Junio’s lingering conceptual concerns (scalability, using a configuration variable for this purpose) and brian m. carlson’s security objection remain unresolved but are mitigated by the server-side trust model. This patch is ready for integration once Junio confirms the environment-handling logic meets his expectations. Files touched: `builtin/upload-pack.c` (environment logic), three documentation files, and test scripts `t/t5710-promisor-remote-capability.sh` and `t/t0410-partial-clone.sh`.
