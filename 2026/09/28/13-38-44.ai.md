This is the third patch in Christian Couder’s five-part v4 series introducing `uploadpack.lazyFetchTrusted`, a server-side protected configuration variable that lets operators explicitly mark repositories as trusted for lazy fetching. The patch implements the core logic for reading and validating the new configuration, building on the generic path-allowlist helpers (`path_allowlist_apply()` and `path_allowlist_config_apply()`) introduced in earlier patches.

The patch adds a new `upload_pack_lazy_fetch_trusted()` function that checks whether the repository being served is allowlisted in `uploadpack.lazyFetchTrusted`. The implementation enforces stricter path validation than the existing `safe.directory` mechanism: only absolute paths are accepted, and `.` (the current directory) is explicitly rejected, since `upload-pack` always serves repositories identified by absolute paths. Non-bare repositories must be allowlisted by their `.git` directory (e.g., `/srv/repo/.git` for `/srv/repo`), reflecting how `upload-pack` discovers repositories via `enter_repo()`. The configuration is read only from protected files, ensuring it cannot be overridden by untrusted clients.

Key technical details include the new `allow_trusted_path()` callback, which validates paths for the `uploadpack.lazyFetchTrusted` variable, and the `upload_pack_protected_lazy_fetch_config()` helper, which processes the configuration and updates the allowlist. The patch also introduces a `lazy_fetch_trusted` struct to track the repository path and trust status during configuration parsing. The function returns `true` only if the repository’s git directory is explicitly allowlisted, providing a clear boolean signal for later use in enabling lazy fetching.
