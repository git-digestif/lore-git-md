# Thread deltas

## 2026/09/28

- [2026/09/28/04-01-49 by Jeff King <peff@peff.net>] Jeff King posted a patch for "http: handle curl stripping creds from effective url": because upcoming curl 8.23.0 strips credentials from CURLINFO_EFFECTIVE_URL, the direct string comparison against the requested URL would falsely detect a redirect and flush http_auth credentials, causing re-prompting (breaking t5550.15); the patch adds match_effective_url() which, on direct-comparison failure, strips credentials from the requested URL via curl's curl_url() interface (conditional on curl >= 7.62.0) and compares again.
- [2026/09/28/13-01-07 by Patrick Steinhardt <ps@pks.im>] Patrick Steinhardt asked whether CURLINFO_REDIRECT_COUNT, which reports the number of redirects that occurred, might be a more direct way to detect whether a redirect happened than comparing URLs.
- [2026/09/28/15-01-12 by Junio C Hamano <gitster@pobox.com>] Junio C Hamano reviewed Jeff King's patch, calling the curl_url()-based approach "very nice" and the decision to keep supporting curl 7.61.0 rather than raising the minimum to 7.62.0 "very sensible".
- [2026/09/28/19-36-44 by Jeff King <peff@peff.net>] Jeff King clarified the strip-versus-flush wording distinction, explained that stripping credentials from the URL immediately after extracting them into http_auth does not work because the URL is passed across process boundaries (e.g., to http-push) while the http_auth struct is not (noticed by t5540), and reported that Patrick Steinhardt's CURLINFO_REDIRECT_COUNT alternative does not work: curl reports 1 redirect for the initial request because it counts the automatic auth retry (401 then 200 with password), so the string-based "did the URL meaningfully change" check is still required.

## 2026/09/29
