This is the second patch in a two-part CI/build system series that improves GitHub Actions failure reporting for Git's test suite. It focuses on making test failures and fixed known breakages actionable by linking them directly to the relevant test script and line number in the GitHub UI.

The patch adds logic to locate the exact line where a failing test is defined by searching the test script for its description as a fixed string. This avoids regex misinterpretation of special characters like `[` or `*`, and falls back to line 1 if the description isn't found verbatim (which happens when tests build their descriptions dynamically). The implementation also handles proper escaping of `%` and carriage returns in test descriptions to ensure GitHub annotations remain intact.

The changes are contained to `t/test-lib-github-workflow-markup.sh`, adding two new helper functions (`github_escape_message_` and `find_test_case_line_`) and modifying `finalize_test_case_output` to emit properly formatted GitHub annotations with file and line information. The patch is well-scoped and addresses a clear usability gap in the current CI output.
