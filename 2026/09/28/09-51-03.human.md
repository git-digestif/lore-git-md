This is a refactoring patch that introduces a new helper function, `safe_create_leading_directories_no_share_const()`, as part of Patrick Steinhardt’s seven-patch series to simplify the `create_repository()` interface. The patch is the second in the series and addresses a gap in the existing API: while `safe_create_leading_directories_const()` exists for callers with constant paths, there was no equivalent for `safe_create_leading_directories_no_share()`, which ignores the `core.sharedRepository` setting. This new helper allows callers to pass a `const char *path` without modifying it in-place, aligning with the existing `_const()` pattern.

The change is small and mechanical: the new function is a one-line wrapper around `safe_create_leading_directories_const()`, passing `NULL` as the repository argument to match the behavior of `safe_create_leading_directories_no_share()`. The patch also updates the documentation in `path.h` to group the four variants of the function (`safe_create_leading_directories()`, `safe_create_leading_directories_const()`, `safe_create_leading_directories_no_share()`, and the new `_no_share_const()`) under a single explanatory paragraph, clarifying their intended use cases (git-dir vs. working-tree files) and whether they modify the input path. This documentation improvement was added in response to feedback from Kaartic Sivaraam on the v1 series.

The patch is uncontroversial and appears well-motivated. It prepares the ground for later patches in the series (specifically, patches 3/7 and 4/7) that will add callers for this new helper. The commit message clearly explains the rationale: the existing in-place modification of the path argument forces callers to use non-constant strings, and while the optimization may not be critical, the `_const()` pattern is already established and should be consistent across all variants. The change is purely additive and does not alter existing behavior.

This is a typical example of Patrick’s incremental, well-structured refactoring work. The patch is a prerequisite for the series’ larger goal of enforcing statelessness in `create_repository()`, but it stands on its own as a sensible cleanup. No substantive review feedback has been raised yet, and the patch looks ready to proceed.
