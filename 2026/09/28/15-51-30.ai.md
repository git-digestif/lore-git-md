This is the third patch in Johannes Schindelin’s four-patch series introducing an optional Rust-based SHA-1 backend for Git. It provides missing `pthread_once()` shims for Windows and `NO_PTHREADS` builds, enabling thread-safe one-time initialization in the upcoming Rust SHA-1 backend (patch 4/4).

The patch is a platform-compatibility fix, touching `compat/win32/pthread.c`, `compat/win32/pthread.h`, and `thread-utils.h`. On Windows, it maps `pthread_once()` to the native `InitOnceExecuteOnce()` API, while for `NO_PTHREADS` builds it implements a trivial single-threaded fallback. The implementation is straightforward: the Windows shim uses a callback to invoke the initialization routine exactly once, and the `NO_PTHREADS` version simply checks a flag and calls the routine if needed. Both shims return POSIX-compliant error codes.

This is a prerequisite for patch 4/4, which will use `pthread_once()` to initialize the Rust SHA-1 backend’s function pointers safely across threads. The patch is uncontroversial in isolation—it fills a gap in Git’s threading compatibility layer and follows established patterns for platform shims. The only potential discussion point is whether the `NO_PTHREADS` fallback is sufficiently robust for single-threaded builds, but the implementation is simple and matches the minimal requirements of the use case.

The patch is well-motivated and self-contained, with no obvious quality issues. It should be a straightforward merge once the series as a whole is accepted.
