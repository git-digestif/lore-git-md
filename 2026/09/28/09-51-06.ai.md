This is patch 5/7 in Patrick Steinhardt’s v2 series refactoring the `create_repository()` interface. It aligns `git clone` with `git init` by ensuring that leading directories are created with the process’s umask rather than honoring the `core.sharedRepository` configuration, even when that configuration is set globally or system-wide.

The patch touches `builtin/clone.c` (two call sites) and adds two new tests to `t/t1301-shared-repo.sh` that verify the permissions of leading directories for both `git init --bare` and `git clone --bare`. The change is a straightforward mechanical replacement: `safe_create_leading_directories_const(the_repository, ...)` becomes `safe_create_leading_directories_no_share_const(...)`, introduced in an earlier patch. The commit message explains that the previous divergence between the two commands was unintentional and that the new behavior is consistent and more intuitive.

No functional behavior changes are introduced beyond the alignment; the patch is purely a cleanup that removes a subtle inconsistency. The added test coverage ensures that both commands now behave identically when creating leading directories, regardless of the `core.sharedRepository` setting. This patch is uncontroversial and appears well-justified as part of the series’ broader goal of simplifying repository initialization.
