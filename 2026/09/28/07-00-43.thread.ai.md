Subject: reftable reflog timezone encoding discrepancy
Series version: none (standalone bug report / bugfix implementation)
Originating author: Josh McKinney
Thread type: bug report / design discussion / implementation update

Core problem or goal
Git 2.55.0’s reftable backend writes reflog timezone offsets as signed HHMM integers (e.g., +05:30 → 0530), but the published reftable specification requires signed minutes (e.g., +05:30 → 330). The mismatch breaks interoperability with other implementations (notably JGit) and violates the documented format. The goal is to standardize on the specification’s representation (signed minutes) and apply the fix without special backwards-compatibility handling, given the limited practical impact.

Current status
Implementation in progress. The design question is closed; Patrick Steinhardt is preparing a patch to land this week. Junio C Hamano, Patrick Steinhardt, and Josh McKinney previously agreed the fix should proceed without a migration strategy or version bump, as reflogs are short-lived (typically garbage-collected within 30 days) and the timezone offset misinterpretation is bounded to at most 10 hours. The issue is considered a clear bug, not a design choice.

Key technical details
- Subsystem: reftable backend (`refs/reftable/`)
- On-disk format: reflog timezone offset encoding
- Old behavior: signed HHMM (e.g., +05:30 → 0530)
- New behavior: signed minutes (e.g., +05:30 → 330)
- Test coverage: minimal test case in `t/t0610-reftable-basics.sh`; reproducer uses a temporary SHA-1 reftable repository and Python script
- Interoperability risk: JGit and other reftable consumers (JGit already implements the specification correctly)
- Format version: SHA-1 repositories use version 1; a version bump is considered unhelpful for this issue

Open questions and loose ends
1. Patch readiness: Patrick Steinhardt aims to post the fix later this week. The test case and reproducer will validate it.
2. Coordination: no new input on whether coordination with JGit or other reftable implementations is needed before landing the fix.

Participant positions
