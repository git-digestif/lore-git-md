This is the final patch in Patrick Steinhardt’s seven-part refactoring series to simplify the `create_repository()` interface. It enforces that the `struct repository` passed to `create_repository()` must be stateless by calling `repo_clear()` at the start of the function. This removes the last vestige of in/out parameter usage (previously used to propagate `core.sharedRepository`) and ensures future callers cannot accidentally rely on pre-existing state.

The patch is minimal—just three lines added to `setup.c`—but it completes the series’ core goal: turning `create_repository()` into a pure out-parameter interface. The commit message explains why a more radical change (allocating a new repository) isn’t feasible: `repo_config_values()` requires `the_repository`, so the function must still accept an existing struct. The enforcement is thus a pragmatic compromise, clearing the input repository before initializing it.

This patch is the most conceptually significant in the series, as it locks in the interface change. While the earlier patches were mechanical cleanups, this one could surface undocumented dependencies if any callers relied on the old in/out behavior. The series’ test coverage (including new tests in `t/t1301-shared-repo.sh`) suggests Patrick has anticipated this, but no substantive technical review has yet engaged with this specific patch or the broader unification goal mentioned in the cover letter.

The patch looks clean and well-motivated, with a clear rationale for the chosen approach. It’s a logical capstone to the series, though the real test will be whether any callers break in practice. For now, it’s a low-risk change that aligns with the project’s ongoing efforts to reduce global state and improve interface clarity.
