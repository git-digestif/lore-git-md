This is the second patch in a small feature series adding GPG commit signing to `git replay` via a new `-S` option. The author, Patrick Monette, has already addressed a latent error-handling bug in the first patch, and this one implements the CLI plumbing, documentation, and tests. The series is cleanly designed and uncontroversial, but Patrick Steinhardt’s review raises a single question: why does the patch ignore the `commit.gpgSign` configuration, breaking consistency with commands like `git commit` that respect it?

The question is fair and worth answering, though the series’ overall quality is not in doubt. The commit message and cover letter explicitly state that `git replay` is a plumbing command and should not be influenced by user configuration, a position that aligns with Git’s long-standing practice for plumbing (e.g., `git fast-import` ignores `core.autocrlf`). Steinhardt’s feedback does not challenge the implementation itself—only the rationale for this design choice. If Monette can briefly restate the plumbing argument in reply, the series should be ready to proceed. No other technical issues are apparent; the patch is well-tested and the error-handling fix in patch 1 has already received a substantive review.
