This is a CI/build system patch series (two patches) that improves GitHub Actions failure reporting by linking test failures and leak sanitizer errors directly to the relevant test script and line.

Harald Nordgren has split the original patch into two focused commits. The first patch now stops leak-sanitizer scripts at the first failure (using `--immediate`) and annotates leaks with the test script name and full sanitizer output in an uncapped log group. The second patch extends the same annotation treatment to regular test failures and known breakages, pointing them to their specific file and line.

The v2 revision addresses several concerns raised in review. Leak output is no longer artificially capped or embedded in the annotation message, avoiding the scrolling issues Phillip Wood noted. The commit messages are now split to explain each change’s reasoning separately. The giant unfolded annotation that caused UI problems in Firefox has been removed entirely.

This remains a well-motivated quality-of-life improvement for CI contributors. The changes appear to handle edge cases appropriately, and the split into two commits makes the logic clearer. The unresolved question about `--immediate`’s trade-off (stopping at first leak vs. reporting all leaks) is now explicitly acknowledged in the commit message, though not yet resolved. No controversy is expected—this is the kind of CI polish that typically lands once the UI quirks are ironed out.
