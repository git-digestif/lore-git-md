This is a CI/build system patch, part of a two-patch series (v2) improving GitHub Actions leak sanitizer failure reporting. Junio C Hamano’s reply to the first patch in the series raises a technical correctness concern about the interaction between `--immediate` and `invert_exit_code` in the test failure logic.

The patch currently emits a GitHub Actions annotation for test failures *only* when `--immediate` is set but `invert_exit_code` is *not* set, due to an early `exit 0` path that skips the annotation. Junio points out that this is inconsistent: if `--immediate` is active (as it is for leak sanitizer jobs), the annotation should be written *regardless* of the `invert_exit_code` setting, because the annotation is about the failure itself, not the exit code. The two-line comment in the patch ("Write the annotation before the --immediate exit paths...") suggests the intent was to ensure the annotation is always written, but the code does not match that intent.

The issue is subtle but important: in leak sanitizer jobs, `invert_exit_code` is typically *not* set (leaks are treated as hard failures), so the annotation would be written as expected. However, if a future change or misconfiguration sets `invert_exit_code` in a leak sanitizer job, the annotation would be silently skipped, burying the leak report in the same way the patch aims to fix. Junio’s observation is a defensive programming point: the annotation logic should be decoupled from `invert_exit_code` when `--immediate` is active.

No other concerns are raised in this reply. The rest of the patch — the leak annotation itself, the collapsible log group for full sanitizer output, and the `--immediate` change — remains uncontroversial. The series is still under review, and this is a targeted technical nit rather than a fundamental objection. The fix is likely to be a small reordering of the exit paths in `test_failure_()` to ensure the annotation is always written before any `--immediate` exit.
