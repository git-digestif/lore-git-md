This is the second patch in Harald Nordgren’s two-part CI/build system series, now under targeted review by Junio C Hamano. The patch aims to make test failures and fixed known breakages more actionable by pointing GitHub Actions annotations directly to the relevant file and line in the test script.

Junio’s review raises two specific portability and consistency concerns. First, he questions whether feeding the two-character sequence `\r` to `sed` is portable across all `sed` implementations, noting that BSD-derived versions may not interpret it as a carriage return. This could break the escaping logic on macOS and other BSD-based systems. Second, he points out that the patch changes the redirection pattern in the `finalize_test_case_output` function, moving the `>>$github_markup_output` from the start of the `test-tool` command line to the end. While functionally equivalent, this breaks the surrounding code’s consistent style and could make future maintenance harder to follow.

The rest of the patch — the new `find_test_case_line_` helper that locates test script lines via literal string matching, the escaping logic that prioritizes `%` to avoid mangling carriage returns, and the streamlined annotation flow — remains uncontested and appears sound. The patch is a practical improvement that complements the first patch’s leak sanitizer annotations, and the concerns raised are narrow and fixable. If addressed, this series will make Git’s GitHub Actions CI significantly more debuggable for both leak sanitizer and regular test failures.
