This is a documentation patch series (RFC) that moves Git’s `BreakingChanges` document into a proper manpage (`gitbreaking-changes(7)`). The goal is to make upcoming breaking changes more visible to end users, who are most affected but least likely to follow development discussions.

The series consists of four patches. The first converts the existing AsciiDoc-formatted `BreakingChanges` file into a manpage template, preserving all content while adapting it to manpage conventions. The second replaces commit-message-style IDs (e.g., `abc1234`) with clickable URLs pointing to the commits on `lore.kernel.org`. The third adds a note clarifying that the document is a living draft, not a static release note. The fourth updates `git(1)`’s "SEE ALSO" section to reference the new manpage.

The build system (`Makefile` and `meson.build`) and `command-list.txt` are updated to include the new manpage, ensuring it is built and listed alongside other Git documentation. The net change is minimal: the content moves from one file to another, with only small editorial adjustments.

The motivation is clear: breaking changes are currently buried in a plain-text document that users rarely see. A manpage makes the information discoverable via `git help breaking-changes` or `man gitbreaking-changes`, and integrates it into the broader documentation ecosystem. The RFC tag suggests the author is seeking feedback on the approach before finalizing.

The series looks well-structured and technically sound. The commit messages explain each step, and the changes are mechanical with no behavior impact. If the goal of better user visibility is accepted, this is a straightforward way to achieve it.
