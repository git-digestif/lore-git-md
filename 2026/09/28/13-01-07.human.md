This is a **bugfix review** for the HTTP transport layer, focusing on the compatibility issue with libcurl 8.23.0.

Patrick Steinhardt responds to Jeff King’s patch with a substantive technical question. He restates the problem clearly: Git’s redirect detection logic, which relies on comparing the requested URL with the effective URL returned by libcurl, will break when libcurl 8.23.0 starts stripping credentials from the effective URL. While he acknowledges the patch’s approach—adding a helper function to strip credentials and compare—he suggests an alternative: using `CURLINFO_REDIRECT_COUNT` to directly query the number of redirects libcurl performed, rather than inferring it from URL comparison.

This is a **substantive review** that engages with the design of the fix. Patrick’s suggestion is technically sound and could simplify the logic by avoiding URL parsing altogether. However, it would require a different code path and might not cover all edge cases (e.g., whether `REDIRECT_COUNT` resets between requests or how it interacts with cached credentials). The question is now open for Jeff (or others) to address: is the direct approach more robust, or does it introduce new assumptions? The patch remains well-motivated and targeted, but this feedback could lead to a v2 if the alternative proves viable.
