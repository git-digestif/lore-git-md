This is a maintainer comment on the ongoing seven-patch series to refactor `create_repository()` so that its input `struct repository` must be stateless. Junio C Hamano weighs in on a minor documentation nit that surfaced in patch 6/7: whether the commit message should reference `free(3)` (standard POSIX) or `free(3p)` (POSIX programmer’s manual). Junio sides with `free(3)` for this context, calling the extra `p` "noise" since the patch does not depend on any POSIX-specific behavior of `free()`. The exchange is purely cosmetic and does not engage with the series’ technical substance—patches 1/7 through 6/7 remain uncontroversial plumbing, and the capstone patch 7/7 (which enforces statelessness by calling `repo_clear()` at the start) still awaits substantive review. The series as a whole is well-structured and clearly motivated, but this latest reply keeps the focus on documentation style rather than the interface change itself.
