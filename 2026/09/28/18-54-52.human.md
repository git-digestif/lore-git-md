This is a CI/build system patch, the first of two in v2 of Harald Nordgren’s series to improve leak sanitizer failure reporting in GitHub Actions.

The patch addresses two long-standing pain points in Git’s CI workflow. First, leak sanitizer failures currently appear only as a generic "Process completed with exit code 1" at the end of a test run, with no indication of which test script triggered the leak. Second, once a leak is detected, the sanitizer log directory is never cleared, causing every subsequent test in the same script to also report "not ok" and bury the original failure under redundant noise. Harald fixes both issues: leaks now get their own GitHub Actions annotation pointing to the test script (line 1, since the exact line isn’t known) and the full sanitizer report is preserved in a collapsible log group, while the test script stops at the first leak using `--immediate`.

The implementation touches three files. In `ci/lib.sh`, it adds `--immediate` to `GIT_TEST_OPTS` for leak sanitizer jobs. In `t/test-lib-github-workflow-markup.sh`, it introduces two new functions: `github_annotation_` (a helper for emitting GitHub Actions annotations) and `finalize_test_leak_output` (which writes the leak annotation and log group). In `t/test-lib.sh`, it reorders the annotation logic so that `finalize_test_case_output` is called before the `--immediate` exit path, ensuring regular test failures are still annotated even when the script stops early.

The commit message is unusually clear for a CI patch, walking through the problem, the solution, and the trade-offs (e.g., stopping at the first leak avoids false "not ok" reports but could theoretically hide later leaks). The code itself is straightforward and well-scoped, with no on-disk format changes or new dependencies. The only loose end is the lack of deeper justification for the new helper functions (`find_test_case_line_` is mentioned in the thread but not in this commit), but that’s a minor documentation nit rather than a technical concern.

This is a practical, uncontroversial improvement that directly addresses a real usability issue in Git’s CI. The v2 changes (splitting the series, removing the giant unfolded annotation, and showing full leak output) show thoughtful iteration on feedback. The patch is likely to be merged once the remaining helper function ordering and commit message clarifications are addressed.
