Thread identity: RFC patch series introducing `gitbreaking-changes(7)` manpage, converting the existing `BreakingChanges` document into a proper manpage for better user visibility. Originating author: Kristoffer Haugsbakk.

Core problem or goal: Make Git’s upcoming breaking changes more discoverable to end users by moving the existing plain-text `BreakingChanges` document into a manpage (`gitbreaking-changes(7)`), ensuring it is accessible via `git help` and `man`, and integrating it into the documentation build system. The series also aims to clarify the document's living-draft nature to prevent user confusion about outdated information.

Current status: Under review as an RFC. The series consists of four patches, now complete and ready for further review. All substantive feedback from Patrick Steinhardt’s review has been addressed: message-ID references replaced with clickable URLs (two requiring URL encoding), the "how to add new entries" section moved to the end of the document, and a minor formatting nit (two spaces after a URL) fixed. Patrick Steinhardt has endorsed the proposed three-step restructuring plan (convert `BreakingChanges` to AsciiDoc in-place, rename to `gitbreaking-changes.txt`, and resurrect `BreakingChanges` as a one-line pointer), simplifying the series organization. The forward-looking question about the document’s lifecycle post-Git 3.0 has been resolved: the document will retain a historical section for Git 3.0, and Git 4.0 discussion is deferred. Junio C Hamano has provided feedback on the URL formatting in patch 2/4, proposing a hybrid approach (URL + message-ID) to preserve raw message-IDs for future reference while maintaining usability. This remains an open discussion point; no new patch version has been posted yet.

Key technical details:
- Files touched: `Documentation/BreakingChanges` (retained as a pointer), `Documentation/gitbreaking-changes.txt` (added as `gitbreaking-changes.adoc`), `Documentation/git.txt` (updated), `command-list.txt` (updated), `Makefile` (updated), `meson.build` (updated).
- New manpage: `gitbreaking-changes(7)`.
- Changes in this patch: Replaced all message-ID references (e.g., `<xmqqa59i45wc.fsf@gitster.g>`) with clickable URLs pointing to `lore.kernel.org` threads. Two message-IDs required URL encoding to avoid breaking AsciiDoc parsing. Updated explanatory text to clarify the purpose of the links. Moved the "how to add new entries" section to the end of the document for better usability, as suggested by Patrick Steinhardt.
- Junio’s feedback: Proposes embedding both the URL and the raw message-ID in the source (e.g., `cf. https://lore.kernel.org/git/xmqqa59i45wc.fsf@gitster.g/[<xmqqa59i45wc.fsf@gitster.g>^]`) to preserve the message-ID for future reference while keeping the rendered output clean. Notes that URL encoding (e.g., `%` → `%25`) is necessary for some message-IDs and should be made explicit.
- No new symbols, CLI options, or on-disk format changes.
- Test coverage: None added; the series is documentation-only.

Open questions and loose ends:
- The RFC tag indicates the author is seeking feedback on the overall approach (moving to a manpage and usability improvements like clickable URLs) before finalizing. The only unresolved technical question is Junio’s proposal for a hybrid URL+message-ID format in `Documentation/gitbreaking-changes.adoc`; this may require further iteration or consensus.
