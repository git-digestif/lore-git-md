Thread identity: RFC patch series introducing `gitbreaking-changes(7)` manpage, converting the existing `BreakingChanges` document into a proper manpage for better user visibility. Originating author: Kristoffer Haugsbakk.

Core problem or goal: Make Git’s upcoming breaking changes more discoverable to end users by moving the existing plain-text `BreakingChanges` document into a manpage (`gitbreaking-changes(7)`), ensuring it is accessible via `git help` and `man`, and integrating it into the documentation build system. The series also aims to clarify the document's living-draft nature to prevent user confusion about outdated information.

Current status: Under review as an RFC. The series consists of four patches, now complete. All substantive feedback from Patrick Steinhardt’s review has been addressed: message-ID references replaced with clickable URLs (two requiring URL encoding), the "how to add new entries" section moved to the end of the document, and a minor formatting nit (two spaces after a URL) fixed. No new patch version has been posted yet, but the series is now ready for further review.
