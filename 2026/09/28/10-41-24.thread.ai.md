Thread identity: RFC patch series introducing `gitbreaking-changes(7)` manpage, converting the existing `BreakingChanges` document into a proper manpage for better user visibility. Originating author: Kristoffer Haugsbakk. Series version: five patches, v2, ready for integration.

Core problem or goal: Make Git’s upcoming breaking changes more discoverable to end users by moving the existing plain-text `BreakingChanges` document into a manpage (`gitbreaking-changes(7)`), ensuring it is accessible via `git help` and `man`, and integrating it into the documentation build system. The series also clarifies the document's living-draft nature to prevent user confusion about outdated information. The post-Git-3.0 lifecycle of individual entries has been addressed with a proposed solution: adding a new section summarizing Git 3.0 changes and a note explaining the future-tense context for users reading from version 2.98, avoiding a large-scale rewrite. The maintainer has now raised a broader question about whether maintaining a historical record of breaking changes is worthwhile at all, comparing it to the limited utility of the Git 1.x-to-2.0 transition documentation. Kristoffer Haugsbakk has proposed pragmatic alternatives: treating the document as a living draft (deleting old entries after a new release) or retaining only the most recent breaking-change discussion (e.g., keeping Git 4.0 and 5.0 entries when approaching Git 5.0).
