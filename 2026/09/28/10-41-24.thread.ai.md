Thread identity: RFC patch series introducing `gitbreaking-changes(7)` manpage, converting the existing `BreakingChanges` document into a proper manpage for better user visibility. Originating author: Kristoffer Haugsbakk. Series version: five patches, v2, ready for integration.

Core problem or goal: Make Git’s upcoming breaking changes more discoverable to end users by moving the existing plain-text `BreakingChanges` document into a manpage (`gitbreaking-changes(7)`), ensuring it is accessible via `git help` and `man`, and integrating it into the documentation build system. The series also clarifies the document's living-draft nature to prevent user confusion about outdated information. The post-Git-3.0 lifecycle of individual entries is now resolved in principle: the document will either be treated as a living draft (deleting old entries after each new release) or retain only the most recent breaking-change discussion (e.g., keeping Git 4.0 and 5.0 entries when approaching Git 5.0). The maintainer has tentatively approved the series, contingent on the post-transition awkwardness being manageable, and Patrick Steinhardt’s earlier proposal to retain the document until Git 3.0 is widely adopted has been acknowledged as a pragmatic justification.

Current status: The v2 series is technically complete, all reviewer feedback has been addressed, and the maintainer has signaled tentative approval. The only remaining steps are resolving minor merge conflicts with `ps/ref-storage-format` (in `master`) and `bc/restrict-hex-to-lowercase` (in `seen`) by moving their additions from `BreakingChanges.adoc` to `gitbreaking-changes.adoc`. No further changes from the author are expected. The series is now unblocked and appears ready for integration; no evidence of merge to any integration branch has appeared yet.
