Thread identity: RFC patch series introducing `gitbreaking-changes(7)` manpage, converting the existing `BreakingChanges` document into a proper manpage for better user visibility. Originating author: Kristoffer Haugsbakk. Series version: five patches, v2, ready for integration.

Core problem or goal: Make Git’s upcoming breaking changes more discoverable to end users by moving the existing plain-text `BreakingChanges` document into a manpage (`gitbreaking-changes(7)`), ensuring it is accessible via `git help` and `man`, and integrating it into the documentation build system. The series also clarifies the document's living-draft nature to prevent user confusion about outdated information.

Current status: The v2 series is technically complete and ready for integration. All reviewer feedback has been addressed, including structural improvements, URL formatting, build system integration, and the relocation of the "Adding new items" discussion to the end of the document for better readability. Key changes since v1:
- Split the conversion into logical steps (preparation, renaming, URL formatting, and a final admonition).
- Replaced commit-message-style message-IDs with plain clickable URLs to resolve `asciidoc`/`asciidoctor` rendering issues.
- Moved the "Adding new items" discussion to the end for better readability.
- Dropped the `git(1)` mention due to a parallel topic removing guide references.
- Retained `Documentation/BreakingChanges.adoc` as a stub pointing to the new manpage.
- Added a NOTE block clarifying the document is a living draft.
- Updated build system files (`Makefile`, `meson.build`, `command-list.txt`) to include the new manpage.
Merge conflicts with `ps/ref-storage-format` (in `master`) and `bc/restrict-hex-to-lowercase` (in `seen`) will require their additions to be moved from `BreakingChanges.adoc` to `gitbreaking-changes.adoc` during integration.
