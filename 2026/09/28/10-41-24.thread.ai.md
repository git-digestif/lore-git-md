Thread identity: RFC patch series introducing `gitbreaking-changes(7)` manpage, converting the existing `BreakingChanges` document into a proper manpage for better user visibility. Originating author: Kristoffer Haugsbakk. Series version: five patches, v2, ready for integration after resolving all review feedback.

Core problem or goal: Make Git’s upcoming breaking changes more discoverable to end users by moving the existing plain-text `BreakingChanges` document into a manpage (`gitbreaking-changes(7)`), ensuring it is accessible via `git help` and `man`, and integrating it into the documentation build system. The series also clarifies the document's living-draft nature to prevent user confusion about outdated information.

Current status: The v2 series is technically aligned with all reviewer feedback and ready for integration. Key changes since v1 include:
- Splitting the conversion into logical steps (preparation, renaming, URL formatting).
- Replacing commit-message-style message-IDs with plain clickable URLs (e.g., `https://lore.kernel.org/git/xmqqa59i45wc.fsf@gitster.g/`) to address rendering issues with `asciidoc`/`asciidoctor`.
- Moving the "Adding new items" discussion to the end for better readability.
- Dropping the `git(1)` mention due to a parallel topic removing guide references.
- Minor whitespace fixes and interdiff adjustments.
The second patch in the series (this update) performs the file rename: `Documentation/BreakingChanges.adoc` is moved to `Documentation/gitbreaking-changes.adoc`, with the original file retained as a stub pointing to the new location. Build system files (`Makefile`, `meson.build`) and `command-list.txt` are updated to include the new manpage. No content changes are made in this patch. Merge conflicts with `ps/ref-storage-format` (in `master`) and `bc/restrict-hex-to-lowercase` (in `seen`) will require their additions to be moved from `BreakingChanges.adoc` to `gitbreaking-changes.adoc` during integration.
