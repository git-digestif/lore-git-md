Thread identity: RFC patch series introducing `gitbreaking-changes(7)` manpage, converting the existing `BreakingChanges` document into a proper manpage for better user visibility. Originating author: Kristoffer Haugsbakk.

Core problem or goal: Make Git’s upcoming breaking changes more discoverable to end users by moving the existing plain-text `BreakingChanges` document into a manpage (`gitbreaking-changes(7)`), ensuring it is accessible via `git help` and `man`, and integrating it into the documentation build system. The series also aims to clarify the document's living-draft nature to prevent user confusion about outdated information.

Current status: Under review as an RFC. The series consists of four patches and is now technically aligned on all feedback. All substantive review comments have been addressed: message-ID references are to be replaced with a hybrid URL+message-ID format (e.g., `cf. https://lore.kernel.org/git/xmqqa59i45wc.fsf@gitster.g/[<xmqqa59i45wc.fsf@gitster.g>^]`), the "how to add new entries" section was moved to the end of the document, and a minor formatting nit (two spaces after a URL) was fixed. Patrick Steinhardt endorsed the proposed three-step restructuring plan (convert `BreakingChanges` to AsciiDoc in-place, rename to `gitbreaking-changes.txt`, and resurrect `BreakingChanges` as a one-line pointer), and the forward-looking question about the document’s lifecycle post-Git 3.0 was resolved (retain a historical section for Git 3.0, defer Git 4.0 discussion). Junio C Hamano’s feedback on the URL formatting in patch 2/4 has been accepted by Patrick Steinhardt, and the only remaining action is for Kristoffer Haugsbakk to post a revised version of patch 2/4 implementing the hybrid format.

Key technical details:
- Files touched: `Documentation/BreakingChanges` (retained as a pointer), `Documentation/gitbreaking-changes.txt` (added as `gitbreaking-changes.adoc`), `Documentation/git.txt` (updated), `command-list.txt` (updated), `Makefile` (updated), `meson.build` (updated).
- New manpage: `gitbreaking-changes(7)`.
- Changes in this patch: Message-ID references (e.g., `<xmqqa59i45wc.fsf@gitster.g>`) are now to be replaced with a hybrid format combining a clickable URL and the raw message-ID (e.g., `cf. https://lore.kernel.org/git/xmqqa59i45wc.fsf@gitster.g/[<xmqqa59i45wc.fsf@gitster.g>^]`). Two message-IDs required URL encoding to avoid breaking AsciiDoc parsing. The "how to add new entries" section was moved to the end of the document for better usability. No new symbols, CLI options, or on-disk format changes.
- Test coverage: None added; the series is documentation-only.
