This is a brief follow-up in the GitLab CI Windows Rust breakage thread. Johannes Schindelin responds to Patrick Steinhardt’s curiosity-driven question about whether Rust will be included in the Git for Windows (GfW) SDK. Schindelin is torn: while he wants to integrate the new `sha1dc` Rust crate (a patch series is about to land), adding Rust to the SDK would more than double the size of the minimal SDK (from ~70MB to ~180MB). He notes that GitHub Actions already includes Rust, which would save bandwidth, but GitLab runners do not, leaving the current CI-only provisioning strategy in place for now. The exchange is purely informational—no technical concerns are raised, and the v2 patch series remains ready for integration. The discussion highlights a trade-off between SDK completeness and download efficiency, with no immediate resolution.
