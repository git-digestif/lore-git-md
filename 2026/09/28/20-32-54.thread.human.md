This thread is about a documentation patch by Julia Evans that rewrites the introductory section of the `git(1)` man page to replace outdated tutorial references with direct instructions for accessing Git’s help system (`git push -h`, `git push --help`, `git help --guides`, etc.). The goal is to improve discoverability for new users by steering them toward actionable help commands rather than deprecated tutorials.

The patch has drawn substantive review from Ben Knoble, who praised its conciseness but questioned its focus on `git cmd --help` over `git help cmd`. Ben argued that `git help cmd` is more powerful (supporting aliases, HTML output, and other formats) and suggested the patch might benefit from hinting at this alternative. Junio C Hamano has now weighed in, aligning with Ben’s position. Junio framed the user preference for `--help` (cited in the patch) as a symptom of underutilization rather than a justification for the status quo, signaling that the current approach may need adjustment. The patch remains under review, with no prior versions, and touches only `Documentation/git.adoc`.

The key open question is whether Julia will revise the patch to incorporate `git help cmd` while preserving its simplicity for new users. The discussion remains narrowly focused on the `git(1)` rewrite, with no broader implications for Git’s documentation system or the unrelated issue of HTML documentation access raised by Ben. Kristoffer Haugsbakk, the most recent editor of this section, has not yet responded.
