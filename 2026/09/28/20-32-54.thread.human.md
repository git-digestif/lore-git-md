This thread is about rewriting the introductory section of the `git(1)` man page to make it more practical for new users. Julia Evans proposed replacing outdated references to `gittutorial` and `giteveryday` with direct instructions for accessing Git’s help system, such as `git cmd -h`, `git cmd --help`, and `git help --guides`. The goal is to improve discoverability while keeping the text simple and actionable.

The discussion has largely converged on a compromise: a tiered approach that presents simple commands upfront while still mentioning `git help`’s advanced features (like HTML output via `--web`) later in the section. Junio C Hamano and Ben Knoble provided substantive feedback, with Junio initially favoring `git help cmd` for its functionality but signaling openness to a balanced solution. Julia’s latest proposal addresses these concerns, and the thread’s main contention appears resolved. The only remaining open points are minor wording tweaks, such as correcting the syntax for `git help --web push` to match Git’s CLI conventions.

The patch is under review, with no prior versions, and touches only `Documentation/git.adoc`. No maintainer decision has been made yet, but the next step is likely a v2 patch incorporating Junio’s small corrections. The broader question of modernizing the `git help tutorial` output remains unaddressed but is tangential to this effort. Kristoffer Haugsbakk, who last edited this section, has not yet responded.
