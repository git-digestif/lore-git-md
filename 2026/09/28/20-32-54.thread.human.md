This thread is about rewriting the introductory section of the `git(1)` man page to improve new-user discoverability. Julia Evans proposed replacing outdated references to deprecated tutorials (`gittutorial`, `giteveryday`) with direct instructions for Git’s help system, initially favoring `git cmd --help` for simplicity. The patch, which touches only `Documentation/git.adoc`, sparked a debate over whether to prioritize simplicity (`--help`) or functionality (`git help cmd`), with Ben Knoble and Junio C Hamano advocating for the latter due to its support for aliases, HTML output, and broader documentation formats.

Julia has now proposed a compromise: keep the initial guidance simple (`git push --help` or `git help push`) while adding a later sentence highlighting `git help`’s advanced features, including `--web` for HTML documentation. This approach addresses the core tension—balancing new-user accessibility with the power of `git help`—and aligns with Junio’s feedback. The tone remains collaborative, and the suggested wording is concrete, making it likely to resolve the thread’s main contention. No maintainer decision has been made yet, but this revision appears poised to move the patch closer to acceptance. Kristoffer Haugsbakk, the most recent editor of this section, has not yet responded.
