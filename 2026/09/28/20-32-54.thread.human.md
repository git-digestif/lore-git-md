This thread is about a small but user-facing documentation improvement: rewriting the introduction of the `git(1)` man page to replace outdated tutorial references with clear, actionable instructions for accessing Git’s help system. Julia Evans proposed the change after hearing from users who struggled to discover Git’s built-in help commands.

The patch has evolved through two versions, with all substantive feedback from Junio C Hamano, D. Ben Knoble, and Kristoffer Haugsbakk now incorporated. The current version (v2) takes a tiered approach: it starts with simple commands like `git push -h` and `git push --help`, then introduces `git help push` and its advanced features (such as HTML output via `--web`). The redundant link to `git.github.io/htmldocs/git.html` was removed in favor of `git-scm.com/docs`, a decision Julia clarified in her latest reply—it offers the same content but with better navigation tools. D. Ben Knoble has explicitly approved the patch, and Junio’s feedback has been addressed, including mechanical corrections to match Git’s CLI style.

The patch is ready for Junio to pick up and integrate. The only loose ends are minor: Kristoffer noted a trivial merge conflict with his own documentation work, but he plans to drop the conflicting change, and Julia may tweak the commit message to include the rationale for removing the `git.github.io` link. Neither is a blocker. The thread’s core question—how to balance simplicity and functionality in presenting the help system—has been resolved without controversy.
