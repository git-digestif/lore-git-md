This thread is about a documentation patch to rewrite the introduction of the `git(1)` man page, replacing outdated tutorial references with direct instructions for accessing Git’s help system. The patch, authored by Julia Evans, aims to improve discoverability for new users by guiding them to commands like `git cmd -h`, `git cmd --help`, and `git help cmd`.

The discussion has converged on a tiered approach: simple commands upfront, with advanced features like HTML documentation (`git help --web push`) mentioned later. Junio C Hamano and Ben Knoble provided substantive feedback, refining the proposal to balance simplicity and functionality. Junio’s latest input clarified Git’s CLI style (options before arguments), ensuring the v2 patch will adhere to conventions. The core design question is resolved, and Julia plans to send v2 shortly.

The patch modifies only `Documentation/git.adoc`, with no changes to on-disk formats or test coverage. Open questions include the cumbersome nature of `git --html-path` (not addressed here) and the outdated output of `git help tutorial` (noted but deferred). The thread is now awaiting v2, with no explicit maintainer decision yet. Key participants—Julia, Ben, and Junio—have aligned on the approach, and the patch is on track for integration.
