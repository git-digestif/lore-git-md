This thread is about a documentation patch by Julia Evans that rewrites the introduction of the `git(1)` man page to better orient new users toward Git’s help system. The goal is to replace outdated references to `gittutorial` and `giteveryday` with concrete, actionable instructions for accessing help (`git push -h`, `git push --help`, `git help push`, `git help --guides`, and `git help --user-interfaces`). The patch also drops a redundant link to `git.github.io/htmldocs/git.html` in favor of `git-scm.com/docs`, a change now confirmed by Junio C Hamano as justified by better usability (search, table of contents, and grouping).

The patch has evolved through feedback from D. Ben Knoble, Junio C Hamano, and Kristoffer Haugsbakk, with all substantive concerns addressed in the v2 iteration. Junio’s mechanical corrections (e.g., `git help --web push` instead of `git help push --web`) and Ben Knoble’s advocacy for including `git help cmd` to highlight its advanced features (aliases, HTML output) were incorporated. Kristoffer Haugsbakk’s minor coordination concern—his in-flight RFC series briefly conflicted with this patch—has been resolved, and his nitpick about the commit message’s rationale for removing the `git.github.io` link was addressed by Julia’s clarification, which Junio confirmed.

The patch is now uncontroversial and ready for integration. The only remaining loose end is whether Julia will tweak the commit message to include the rationale for removing the `git.github.io` link, but this is a minor documentation hygiene issue. The thread is effectively complete, awaiting maintainer pickup. No further discussion or objections are expected.
