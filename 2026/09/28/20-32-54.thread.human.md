This thread is about a documentation patch by Julia Evans that rewrites the introduction of the `git(1)` man page to better guide new users toward Git’s help system. The patch replaces outdated references to `gittutorial` and `giteveryday` with concrete, actionable instructions for accessing help (`git push -h`, `git push --help`, `git help push`, `git help --guides`, and `git help --user-interfaces`). It also drops a redundant link to `git.github.io/htmldocs/git.html` in favor of `git-scm.com/docs`, which offers the same content with usability enhancements like search and a table of contents.

The patch has evolved through two versions, with all substantive feedback from Junio C Hamano, D. Ben Knoble, and Kristoffer Haugsbakk now incorporated. Junio’s latest email confirms the rationale for removing the `git.github.io` link, removing any lingering ambiguity about the change. D. Ben Knoble has explicitly approved the patch, and Junio’s earlier feedback—focusing on wording refinements and the inclusion of `git help cmd`—has been fully addressed. The only remaining loose end is whether Julia will tweak the commit message to include the rationale for removing the `git.github.io` link, but this is a minor documentation hygiene issue rather than a technical blocker.

The patch is now uncontroversial and ready for integration. No further changes are expected, and the thread is effectively complete, awaiting Junio’s pickup. The broader discussion about HTML documentation access and the outdated state of `git help tutorial` remains tangential to this patch but may resurface in future documentation efforts.
