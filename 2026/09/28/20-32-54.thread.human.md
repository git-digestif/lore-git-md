This thread is about a documentation patch by Julia Evans that rewrites the introductory section of the `git(1)` man page to improve discoverability for new users. The patch replaces outdated references to tutorials and guides (`gittutorial`, `giteveryday`, `user-manual`, `datamodel`, `cli`) with concrete instructions for accessing Git’s help system, such as `git push -h`, `git help push`, and `git help --guides`. After three iterations, the patch is now stable and uncontroversial, with all substantive feedback from Junio C Hamano, D. Ben Knoble, and Kristoffer Haugsbakk incorporated.

The key changes include removing redundant or outdated links, clarifying the rationale for dropping certain guides (e.g., `user-manual` is outdated, `cli` is developer-focused), and preferring `git-scm.com/docs` over `git.github.io/htmldocs/git.html` because the former tracks the latest *released* version of Git. The patch is ready for maintainer pickup once Julia posts the final version with an updated commit message that includes this rationale. No further technical changes are needed, and the patch only touches `Documentation/git.adoc` without affecting other subsystems or tests.

The thread also notes minor asides, such as Ben Knoble’s observation about the cumbersome nature of `git --html-path` and Junio’s comment about the outdated output of `git help tutorial`, but these are not actionable in this patch and may resurface in future discussions. Kristoffer Haugsbakk’s conflicting RFC series will be updated to align with this patch. Overall, the patch is poised for integration once the commit message is finalized.
