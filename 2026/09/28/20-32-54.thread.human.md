This thread is about a documentation patch by Julia Evans that rewrites the introductory section of the `git(1)` man page to better orient new users toward Git’s help system. The patch replaces outdated references to standalone guides (`gittutorial`, `giteveryday`, `user-manual`, `datamodel`, and `cli`) with direct, actionable instructions for accessing help—such as `git push -h`, `git help push`, and `git help --guides`—and prioritizes `git-scm.com/docs` over the now-removed `git.github.io/htmldocs/git.html`. The rationale for removing the guides is now fully documented: they were either outdated, developer-focused, or orphaned, and the new approach adopts an "every page is page one" model to improve discoverability and reduce maintenance burden.

The patch has reached its final version (v3) and is ready for integration into `master`. All feedback has been addressed, including Junio’s request to clarify the design philosophy behind the new presentation order and his observation about the niche value of the `cli` guide (which the patch leaves open to future updates). Reviews from D. Ben Knoble and Junio were substantive and supportive, while Kristoffer Haugsbakk’s minor coordination concern (a merge conflict with his in-flight RFC series) has been resolved. The patch is uncontroversial and touches only `Documentation/git.adoc`, with no changes to on-disk formats or test coverage. No further discussion or changes are expected.
