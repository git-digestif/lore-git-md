This thread is about a documentation patch to rewrite the introductory section of the `git(1)` man page. The goal is to replace outdated references to `gittutorial` and `giteveryday` with clear, actionable instructions for accessing Git’s help system, making it more practical for new users.

The patch, now in its second version, has incorporated all substantive feedback from the thread. Julia Evans, the author, initially proposed a simple approach but evolved it into a tiered structure: basic commands (`git push -h`, `git push --help`) are presented first, followed by more advanced options like `git help push` and its features (e.g., `--web` for HTML output, `--guides`, and `--user-interfaces`). The redundant link to `git.github.io/htmldocs/git.html` has been replaced with `git-scm.com/docs`. Junio C Hamano and D. Ben Knoble both provided feedback, with Junio refining the wording to match Git’s CLI style and Ben advocating for the inclusion of `git help cmd` to highlight its superior functionality. All corrections have been addressed in the v2 patch.

With Ben Knoble’s explicit approval in the latest email, the patch is now ready for Junio’s final review and integration. There are no remaining open questions or controversies directly tied to this patch, though earlier discussions noted tangential topics like the cumbersome nature of `git --html-path` and the outdated content in `git help tutorial`, which may resurface in future documentation efforts. The patch modifies only `Documentation/git.adoc` and requires no changes to tests or on-disk formats.
