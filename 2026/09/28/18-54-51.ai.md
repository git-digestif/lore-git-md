This is a CI/build system patch series (v2) that improves GitHub Actions failure reporting by linking test failures and leak sanitizer errors directly to the relevant test script and line.

Harald Nordgren revises the approach based on earlier feedback, splitting the work into two focused commits. The first commit stops leak-sanitizer scripts at the first failure (using `--immediate`) and annotates leaks with the test script name and full sanitizer output in a collapsible log group. The second commit ensures regular test failures and fixed known breakages also point to their exact file and line in the test script. The v2 changes address key usability concerns: leak output is now uncapped and displayed in full, avoiding the earlier truncation that buried important details, and the giant unfolded annotation that caused scrolling issues in Firefox has been removed.

The series touches `ci/lib.sh` (adding `--immediate` to `GIT_TEST_OPTS`), `t/test-lib-github-workflow-markup.sh` (adding annotation helpers and leak output handling), and `t/test-lib.sh` (reordering annotation logic to ensure failures are reported even with `--immediate`). New functions (`github_annotation_`, `finalize_test_leak_output`) generate GitHub Actions annotations, while `find_test_case_line_` locates the exact line of a failing test. The implementation now avoids capping leak output, instead showing the full sanitizer report in a log group, and ensures annotations are written before `--immediate` exits the script.

Harald has responded to Phillip Wood’s earlier concerns about `--immediate` hiding subsequent leaks by clarifying the trade-off: stopping at the first leak avoids burying the real failure under false "not ok" reports from later tests, while still preserving the full leak output. The scrolling regression in Firefox appears to be resolved by dropping the giant unfolded annotation. The commit messages now better explain the reasoning behind `--immediate` and the escaping logic, though the range-diff suggests some helper function details (like `find_test_case_line_`) could still use more justification.
