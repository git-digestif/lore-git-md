Subject: [PATCH] http: handle credential stripping in libcurl 8.23.0
Series version: standalone patch (no series)
Originating author: Jeff King <peff@peff.net>
Thread type: bugfix

Core problem or goal
Git’s HTTP transport layer detects redirects by comparing the requested URL with the effective URL returned by libcurl. Starting with libcurl 8.23.0, the library will strip credentials from the effective URL, causing the comparison to fail. This triggers an unnecessary flush of cached HTTP credentials, forcing users to re-authenticate.

Current status
Under review; no prior versions. The patch is minimal, targeted, and includes a helper function `match_effective_url()` that performs a more careful comparison by stripping credentials from the requested URL using libcurl’s `curl_url()` interface (available since curl 7.62.0). For older curl versions, the extra comparison is skipped. The fix is in `http.c` and `git-curl-compat.h`, with test coverage in `t5550.15`.

Key technical details
- Files touched: `http.c`, `git-curl-compat.h`
- New symbols: `match_effective_url()`
- Subsystem: HTTP transport layer
- Behavior change: redirect detection now handles credential-stripped effective URLs
- On-disk format: unchanged
- Test coverage: `t5550.15` (existing test now passes with libcurl 8.23.0+)
