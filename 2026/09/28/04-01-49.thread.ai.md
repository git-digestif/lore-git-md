Thread identity
Subject: [PATCH] http: handle credential stripping in libcurl 8.23.0
Series version: standalone patch (no series)
Originating author: Jeff King <peff@peff.net>
Thread type: bugfix

Core problem or goal
Git’s HTTP transport layer detects redirects by comparing the requested URL with the effective URL returned by libcurl. Starting with libcurl 8.23.0, libcurl strips credentials from the effective URL, causing the comparison to fail and triggering an unnecessary flush of cached HTTP credentials.

Current status
Under review; no prior versions. The patch introduces a helper function `match_effective_url()` that performs a more careful comparison by stripping credentials from the requested URL using libcurl’s `curl_url()` interface (available since curl 7.62.0). For older curl versions, the extra comparison is skipped. Junio C Hamano has endorsed the current implementation, calling the compatibility choice “very sensible” and signaling the patch is on track for merging. Patrick Steinhardt’s alternative approach using `CURLINFO_REDIRECT_COUNT` has been explicitly ruled out by the author after testing showed it miscounts redirects due to libcurl’s 401→200 auth retry logic.

Key technical details
- Files touched: `http.c`, `git-curl-compat.h`
- New symbols: `match_effective_url()`
- Subsystem: HTTP transport layer
- Behavior change: redirect detection now handles credential-stripped effective URLs; no user-visible behavior changes beyond fixing the credential-flushing regression
- On-disk format: unchanged
- Test coverage: `t5550.15` (existing test now passes with libcurl 8.23.0+)
- Alternative approach: `CURLINFO_REDIRECT_COUNT` (available since libcurl 7.9.7) was tested and rejected because libcurl counts the initial 401→200 auth retry as a redirect, making the count unreliable for detecting actual URL changes

Open questions and loose ends
None. The only remaining question—whether to adopt the URL-based comparison or switch to `CURLINFO_REDIRECT_COUNT`—has been resolved in favor of the URL-based approach after testing demonstrated the count-based method’s unreliability. No substantive objections or requests for revision remain.

Participant positions
- Jeff King (Peff) authored the original patch, proposing a URL-based comparison using `curl_url()`. After testing Patrick Steinhardt’s suggestion, Peff confirmed `CURLINFO_REDIRECT_COUNT` is unreliable and reaffirmed the URL-based approach as the correct solution.
- Patrick Steinhardt provided a substantive review, suggesting `CURLINFO_REDIRECT_COUNT` as a more direct alternative. No objections to the patch’s goal, but initially questioned the implementation choice. His suggestion has been addressed and ruled out by the author’s testing.
- Junio C Hamano endorsed the current implementation, calling the compatibility choice “very sensible” and signaling the patch is on track for merging. No other reviews or positions recorded yet.
