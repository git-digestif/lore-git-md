Thread identity
Subject: [PATCH] http: handle credential stripping in libcurl 8.23.0
Series version: standalone patch (no series)
Originating author: Jeff King <peff@peff.net>
Thread type: bugfix

Core problem or goal
Git’s HTTP transport layer detects redirects by comparing the requested URL with the effective URL returned by libcurl. Starting with libcurl 8.23.0, libcurl strips credentials from the effective URL, causing the comparison to fail and triggering an unnecessary flush of cached HTTP credentials.

Current status
Under review; no prior versions. The patch introduces a helper function `match_effective_url()` that performs a more careful comparison by stripping credentials from the requested URL using libcurl’s `curl_url()` interface (available since curl 7.62.0). For older curl versions, the extra comparison is skipped. Junio C Hamano has endorsed the current implementation, calling the compatibility choice “very sensible” and signaling the patch is on track for merging. Patrick Steinhardt previously proposed an alternative approach using `CURLINFO_REDIRECT_COUNT` to detect redirects directly, but no new objections or compelling arguments for switching have emerged.

Key technical details
- Files touched: `http.c`, `git-curl-compat.h`
- New symbols: `match_effective_url()`
- Subsystem: HTTP transport layer
- Behavior change: redirect detection now handles credential-stripped effective URLs
- On-disk format: unchanged
- Test coverage: `t5550.15` (existing test now passes with libcurl 8.23.0+)
- Alternative approach: use `CURLINFO_REDIRECT_COUNT` (available since libcurl 7.9.7) to detect redirects without URL comparison

Open questions and loose ends
Whether to adopt the original patch’s URL-based comparison or switch to the `CURLINFO_REDIRECT_COUNT` approach. The latter remains untested in the thread and has not gained traction since Junio’s endorsement of the current implementation.

Participant positions
- Jeff King (Peff) authored the original patch, proposing a URL-based comparison using `curl_url()`.
- Patrick Steinhardt provided a substantive review, suggesting `CURLINFO_REDIRECT_COUNT` as a more direct alternative. No objections to the patch’s goal, but questions the implementation choice.
- Junio C Hamano endorsed the current implementation, calling the compatibility choice “very sensible” and signaling the patch is on track for merging. No other reviews or positions recorded yet.
