This is the first patch in Christian Couder’s five-part v4 series introducing `uploadpack.lazyFetchTrusted`, a server-side mechanism for marking repositories as trusted for lazy fetching. This patch is a pure refactoring of the promisor-remote subsystem, extracting the lazy-fetching logic from `fetch_objects()` and `promisor_remote_get_direct()` into a new helper function, `lazy_fetch_objects()`.

The patch consolidates the `GIT_NO_LAZY_FETCH` environment check into a single up-front call, avoiding redundant checks when multiple promisor remotes are involved. It also moves the `promisor_remote_init()` call into the new helper, aligning with the convention that initialization should happen where the data is needed rather than preemptively. The commit message notes two observably equivalent shifts: the environment check now runs once instead of per-remote, and initialization is deferred until lazy fetching is actually attempted.

The patch adds detailed documentation for both the new `lazy_fetch_objects()` and the existing `try_promisor_remotes()`, clarifying the ownership rules around the `remaining_oids`, `remaining_nr`, and `to_free` arguments. This addresses Junio’s v3 review request for clearer parameter semantics, though the commit message does not claim to fully resolve it. The implementation itself is straightforward: the new helper calls `try_promisor_remotes()` twice (once for accepted remotes, once for all others) and returns early if lazy fetching is disabled.

No behavior change is intended, and the patch is a clean candidate for early integration if the series stalls. The only unresolved concern is Junio’s request for even more precise documentation around `try_promisor_remotes()`’s parameters, but this is not blocking. The patch touches only `promisor-remote.c` and introduces no new symbols beyond the `lazy_fetch_objects()` helper.
