This is the first patch in an RFC documentation series that converts Git’s `BreakingChanges` document into a proper manpage (`gitbreaking-changes(7)`). The goal is to make upcoming breaking changes more visible to end users, who are most affected but least likely to follow development discussions.

The patch moves the existing AsciiDoc-formatted `BreakingChanges` file into a new `gitbreaking-changes.adoc` manpage template, preserving all content while adapting it to manpage conventions. The old `BreakingChanges` file is replaced with a single-line pointer to the new manpage. The build system (`Makefile` and `meson.build`) is updated to include the new manpage, ensuring it is built and listed alongside other Git documentation.

The motivation is clear: the current `BreakingChanges` document is buried in the source tree and rarely seen by users. A manpage makes the information discoverable via `git help breaking-changes` or `man gitbreaking-changes`, integrating it into the broader documentation ecosystem. The patch itself is mechanical, with no editorial changes beyond formatting adjustments for the manpage template.

This is a well-structured and uncontroversial step toward better user visibility. The RFC tag indicates the author is seeking feedback on the approach, but the patch itself looks technically sound and aligns with the series’ goal. If the community accepts the premise, this is a straightforward way to achieve it.
