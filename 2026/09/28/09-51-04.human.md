This is the third patch in Patrick Steinhardt’s seven-part refactoring series to simplify the `create_repository()` interface. The series aims to enforce statelessness in the `struct repository` passed to `create_repository()`, removing the last in/out usage (propagation of `core.sharedRepository`) and preparing for future unification of repository initialization.

This specific patch cleans up a messy section in `builtin/init-db.c` where `git init` creates leading directories. Currently, the code temporarily overrides `core.sharedRepository` to zero, calls `safe_create_leading_directories_const()`, and then restores the original value—all to avoid applying shared permissions. The patch replaces this awkward dance with a direct call to `safe_create_leading_directories_no_share_const()`, a helper introduced in patch 2/7 that explicitly ignores `core.sharedRepository`. The change is purely mechanical, removing ten lines of boilerplate and replacing them with two, and aligns the code with the intended use of the `_no_share` variant.

The patch touches only `builtin/init-db.c` and is uncontroversial: it simplifies the logic without changing behavior. The commit message clearly explains the motivation and the refactoring, and the diff is straightforward. This is a small but well-motivated step in the larger effort to clean up repository initialization. If the series as a whole holds up under review, this patch is likely to be merged as-is.
