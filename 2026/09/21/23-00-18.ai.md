This is a **user-experience discussion** in the ongoing thread about improving shallow-clone advice. Junio C Hamano pushes back on Harald Nordgren’s earlier clarification that the new `advice.shallowHistory` message is scoped only to explicit `<rev>~N`/`<rev>^N` syntax in commands that fail (e.g., `` `git show HEAD~20` ``). Junio argues that `` `git log -20 HEAD` ``—which silently stops at the shallow boundary—is *more* confusing to users than the failing case, because it provides no error message or hint about why the history is truncated. He suggests the advice should also appear in these silent-failure scenarios, even though they do not use the `<rev>~N` syntax directly.

The technical challenge is where to inject the advice: `` `git log -20` `` does not error out, so there is no natural place to print the message without disrupting the normal output. Junio does not propose a specific implementation, but his position implies that the current scope is too narrow and that the feature’s value would be significantly higher if it also addressed silent truncation in commands like `` `git log -n` `` or `` `git log --since` ``. This reopens the design question that Harald’s previous reply had considered settled.
