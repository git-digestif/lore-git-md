# Thread deltas

## 2026/09/21

- [2026/09/21/22-09-56 by Junio C Hamano <gitster@pobox.com>] Junio C Hamano described the Git community as a loosely knit group of self-nominated volunteers, noting that `CODE_OF_CONDUCT.md` refers to the Git PLC at SFC as "Community leaders," which he considers the closest thing to an official structure.
- [2026/09/21/22-09-56 by Junio C Hamano <gitster@pobox.com>] Junio C Hamano stated that the project does not have an official list of reviewers with approval bits or privileges, and that clout in the community is earned through continued contribution over time.
- [2026/09/21/22-09-56 by Junio C Hamano <gitster@pobox.com>] Junio C Hamano said he is somewhat indifferent but would not oppose a descriptive document of how governance currently works, though he thinks it might be hard to come up with a good one.
- [2026/09/21/22-09-56 by Junio C Hamano <gitster@pobox.com>] Junio C Hamano warned that a prescriptive document could open a big discussion with different opinions not backed by common experience, leading to wasted time and effort.

## 2026/09/24

- [2026/09/24/07-56-01 by Antonin Delpeuch <antonin@delpeuch.eu>] Antonin Delpeuch agreed with aiming for a descriptive, explicitly non-prescriptive governance document; identified additional well-delimited roles to describe (people with access to the git-security list and the maintainer(s) of git-scm.com); and argued that the questions raised while writing the document could themselves prompt the team to identify gaps or desired changes, citing the git-security team's potential high report volume as an example where describing membership and renewal might surface willing volunteers.

## 2026/10/06

- [2026/10/06/11-09-39 by Antonin Delpeuch <antonin@delpeuch.eu>] Antonin Delpeuch announced he plans to proceed with documenting Git's governance unless anyone thinks it is a bad idea, outlining a plan to write an initial document from information he can find himself and then fill gaps by asking questions, asking others with a good grasp of the project's social structures to volunteer help so he does not have to bother Junio too much, and stating his goal is official inclusion in the documentation or website, or external publication clearly marked as unofficial if that does not work out.
- [2026/10/06/11-47-46 by Christian Couder <christian.couder@gmail.com>] Christian Couder suggested that Antonin write an initial document and send it to the list as a patch to add it to the Git code base, explaining that the people who reply to the patch will be those willing to help, because relying on promises is unreliable as someone might get sick or go on vacation when the first draft is ready.
- [2026/10/06/11-47-46 by Christian Couder <christian.couder@gmail.com>] Christian Couder said that if the document is not accepted in the code base or on git-scm.org, it might be accepted on the Git Developer Pages at https://git.github.io/ or as a "How the Git project works" article in Git Rev News.
