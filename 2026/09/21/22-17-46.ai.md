This is a **user-experience bugfix** refining the shallow-clone advice introduced in the previous patch. Harald Nordgren replies to Junio C Hamano’s question about whether the new `advice.shallowHistory` message should also appear when `<rev>~N` fails *internally* during commands like `` `git log -20 HEAD` `` or `` `git log --since=2.months HEAD` ``.

Harald clarifies that `` `git log -20` `` does not error out—it simply stops at the shallow boundary—so there is no natural place to inject the advice. The current implementation only triggers when the user explicitly writes `<rev>~N` or `<rev>^N` in a command that fails to resolve (e.g., `` `git show HEAD~20` ``). This keeps the advice tightly scoped to the revision syntax that directly caused the error, avoiding noise in commands that handle shallow boundaries gracefully. No code changes are proposed; the reply simply closes the open question about internal resolution failures.
