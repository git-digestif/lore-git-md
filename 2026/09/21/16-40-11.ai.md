This is a **substantive review** of the `git log -L` bug report, clarifying the line-log feature’s design limitations rather than proposing a fix. Johannes Sixt (Hannes) explains that Git’s function boundary detection is inherently heuristic and language-agnostic: it relies on the same regex patterns used for diff hunk headers, which treat *any* content (including blank lines or comments) between one function’s end and the next function’s start as part of the first function. This behavior is not a bug but a deliberate trade-off—Git does not parse code semantically, so it cannot distinguish between actual function code and adjacent whitespace or comments.

The review directly addresses the reporter’s expectation (that only commits modifying the function body should appear) by noting that Git’s current logic is consistent with its hunk-header patterns, even if it feels counterintuitive. Hannes also highlights a more pressing limitation: comments *above* a function are incorrectly attributed to the *previous* function, which could mislead users about which commits affect documented code. This broader context suggests the reported issue is part of a larger design constraint, not an isolated edge case.

Key technical details for follow-up:
- **Subsystem**: Line-log (`-L` option) and its regex-based function boundary detection (defined in `userdiff.c` for each language).
- **Root cause**: The line-log parser uses diff hunk patterns to define function ranges, which cannot distinguish between code, whitespace, or comments.
- **Scope**: Affects *all* languages using Git’s function detection (Python, C, shell, etc.), not just Python.
- **Related issue**: Comments above functions are misattributed to the prior function, a more disruptive problem than trailing blank lines.

Hannes does not propose a patch or suggest a timeline for improvement, but his explanation reframes the discussion: any fix would require either (1) language-specific semantic parsing (a major architectural change) or (2) accepting the current heuristic’s limitations.
