This is a **user-experience bugfix** for shallow clones, refining the advice introduced in the previous patch. The author, Harald Nordgren, responds to Junio C Hamano’s question about whether the new `advice.shallowHistory` message should also appear when commands like `` `git log -20 HEAD` `` or `` `git log --since=2.months HEAD` `` internally fail to resolve `HEAD~20`.

Harald clarifies that `` `git log -20` `` does not error out—it simply stops at the shallow boundary—so there is no natural place to show the advice. This keeps the feature’s scope tightly focused: the advice only triggers when a user explicitly writes `<rev>~N` or `<rev>^N` and Git cannot resolve the ancestor. The response leaves the original design intact (advice for explicit revision syntax only) and does not expand it to cover internal resolution failures in other commands. A v2 addressing Junio’s earlier points (whether to include `<rev>^N` and the `<ref>` vs. `<rev>` documentation) is still expected.
