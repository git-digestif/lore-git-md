This is a bug report about `git log -L` (the line-log feature). The reporter, Nikita Makarov, describes an edge case where `git log -L :'foo':bug.py` incorrectly includes a commit that only removes a blank line *after* a Python function, even though the function body itself is unchanged. The issue manifests only when the function is at the end of the file.

The reproduction steps are clear: create a file with a Python function followed by a blank line, commit it, then remove the blank line and commit again. The second commit appears in the line-log output despite not modifying the function body, which violates the expected behavior. The reporter’s expectation is that only commits touching the function’s actual code should be shown.

The report includes system information (Git 2.43.0 on Ubuntu) but no prior discussion or patch. This looks like a genuine bug in the line-log’s function boundary detection for Python, likely due to how the `-L` option parses function endings. The edge case (function at EOF) suggests the logic may not handle trailing whitespace or empty lines correctly.

Key technical details for follow-up: the issue affects Python function detection, involves the `-L` option’s line-range parsing, and is reproducible with minimal steps.
