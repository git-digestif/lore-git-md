This thread reports a bug in `git log -L` where removing a trailing blank line after a Python function at the end of a file incorrectly causes the commit to appear in the line-log output, even though the function itself is unchanged. The issue was initially reported by Nikita Makarov, who provided reproduction steps and confirmed it affects Git 2.43.0.

Kristofer Karlsson followed up to clarify the exact conditions: the bug occurs when the *second* commit adds a trailing blank line (not the first), and removing that blank line later triggers the incorrect behavior. He confirmed the issue on Git 2.43 and plans to submit a patch soon, suggesting the fix is straightforward. The problem lies in the line-log’s function boundary detection logic, which misinterprets trailing whitespace at the end of a file as part of the function. No other participants have weighed in yet, and the bug remains unpatched. The upcoming fix will likely target `line-log.c` or the Python diff driver.
