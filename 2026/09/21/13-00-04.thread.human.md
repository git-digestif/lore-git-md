This thread is about a small portability patch to enable `RUNTIME_PREFIX` support on OpenBSD. The patch, originally submitted by Brad Smith, adds a new code path in `exec_cmd.c` using OpenBSD's `getexecpath()` function to detect Git's runtime prefix dynamically. Chris Torek reviewed the patch and raised a minor structural concern: the patch introduces a new conditional block (`HAVE_GETEXECPATH`) alongside an existing one (`HAVE_BSD_KERN_PROC_SYSCTL`) without documenting that these methods are mutually exclusive. While the feedback is purely about maintainability and clarity—not correctness—it highlights a potential pitfall for future contributors.

The patch itself is narrowly scoped, touching only `exec_cmd.c` and introducing the `HAVE_GETEXECPATH` macro and a helper function (`git_get_exec_path_getexecpath()`). It extends Git's ability to locate runtime files (like templates or hooks) relative to the executable's path, which is particularly useful for portable installations. There’s no indication this is part of a broader effort; it appears to be an isolated OpenBSD compatibility fix. The discussion is unlikely to become contentious, as the feedback is low-stakes and the patch addresses a straightforward portability gap.
