This thread is about enabling Git’s `RUNTIME_PREFIX` feature on OpenBSD by adding support for the `getexecpath()` function in the `exec_cmd.c` file. The patch, submitted by Brad Smith, allows OpenBSD builds to locate runtime files (like templates and system hooks) relative to the executable’s path instead of relying on hardcoded installation directories.

The discussion has focused on a minor review comment from Chris Torek, who noted that the patch’s code structure implied mutual exclusivity between `HAVE_GETEXECPATH` and `HAVE_BSD_KERN_PROC_SYSCTL` but lacked documentation. Johannes Sixt (Hannes) clarified that the `&&` chaining in `git_get_exec_path()` ensures only the first successful method is used, making the exclusivity inherent in the code itself. This resolves the concern without requiring changes to the patch. The patch remains a small, targeted fix for OpenBSD, with no impact on other platforms.

The patch is now effectively ready for Junio’s queue, assuming no further objections arise. The only remaining loose end is whether the patch has been tested on OpenBSD, but no validation reports have been shared in the thread. The change is isolated to the `exec_cmd` subsystem and doesn’t interact with broader efforts like ODB abstraction or Rustification. If merged, this will be a straightforward portability improvement for OpenBSD users.
