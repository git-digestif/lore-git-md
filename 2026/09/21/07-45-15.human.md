This is a bug report about `git log -L`, the line-log feature that shows history for specific lines or functions in a file.

Nikita Makarov describes a misbehavior in how Git identifies the boundaries of Python functions when they appear at the end of a file. The command incorrectly includes a trailing blank line as part of the function, which causes `git log -L` to report changes that do not actually affect the function body. The report includes a minimal reproduction recipe: two commits that differ only by the presence of a blank line after a function, and the command `git log -L :'foo':bug.py` shows the second commit even though the function itself is unchanged.

The issue is specific to Python and to functions at the end of the file; the report does not mention other languages or mid-file functions. The provided system information shows Git 2.43.0 on Linux, but the bug is likely version-agnostic. No prior discussion or patches are referenced, so this appears to be a new report rather than a follow-up.
