This is a **user-experience bugfix** for shallow clones, part of an ongoing discussion about how Git should advise users when revision syntax like `<rev>~N` fails because the needed history is not present locally.

Junio C Hamano replies to Harald Nordgren’s clarification that the new `advice.shallowHistory` message is currently scoped only to explicit `<rev>~N` or `<rev>^N` syntax in commands that fail to resolve (e.g., `` `git show HEAD~20` ``). Junio argues that `` `git log -20 HEAD` ``—which silently stops after showing only two commits—is *more* confusing than the explicit error, because it gives no hint that the shallow boundary is the cause. He suggests the advice should also appear in these internal resolution failures, where the user never wrote `<rev>~N` but still hits the shallow limit. The reply keeps the discussion open: no code changes yet, just a design question about where to draw the line between helpful guidance and noise.
