This is a follow-up in the `fetch.shallow` feature thread. Harald Nordgren acknowledges Phillip Wood’s observation that the performance issue he encountered is not tied to sparse checkouts but rather to the presence of many remote-tracking branches in a shallow repository. Specifically, the problem arose after adding a second remote (upstream) with a wildcard fetch refspec, which caused `git pull` to negotiate history for all remote branches. Harald agrees that improving `git remote add` behavior in shallow repositories—by avoiding wildcard refspecs and instead fetching only the relevant branch(es)—could be a more targeted solution than introducing a new config option. The thread is now pivoting toward exploring this alternative approach.
