Subject: `git log -L` incorrectly includes commits that only remove blank lines after Python functions
Series version: N/A (bug report, not a patch series)
Originating author: Nikita Makarov <n.makarov@yadro.com>
Thread type: bug report

Core problem or goal
The line-log feature (`git log -L`) is intended to show only commits that modify the specified function or line range. However, when a Python function is followed by a blank line at the end of the file, the line-log parser incorrectly treats the *addition* of that blank line (and its subsequent removal) as a modification to the function itself, even though the function body is unchanged. This violates the expected behavior of showing only commits that touch the function’s actual code.

Current status
Reported as a bug; confirmed by Kristofer Karlsson, who plans to submit a patch shortly. The issue is reproducible with corrected steps: (1) create a Python file with a function *without* a trailing blank line, (2) commit, (3) add a trailing blank line, (4) commit, (5) run `git log -L :'foo':bug.py` -- the second commit (adding the blank line) incorrectly appears in the output. The bug affects Git 2.43.0 and is specific to Python function boundary detection when the function is at the end of the file.

Key technical details
- **Subsystem affected**: line-log (`-L` option) and its language-specific function boundary detection (Python in this case).
- **Files touched**: The issue is internal to the line-log implementation (likely in `line-log.c` or the Python diff driver in `userdiff.c`).
- **Behavior**: The line-log parser misinterprets the *addition* of a trailing blank line after a Python function (at EOF) as part of the function’s range, causing commits that later remove that blank line to be incorrectly included in the output.
- **Edge case**: The bug manifests only when the function is at the end of the file and a blank line is added *after* the initial commit, suggesting the logic for detecting function endings does not handle dynamic changes to trailing whitespace correctly.
- **Test coverage**: No existing test covers this edge case; the corrected reproduction scenario could be adapted into a regression test.
