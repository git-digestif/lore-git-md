This thread is about a small but important consistency fix for `git log -L :funcname:`, which determines the range of lines belonging to a function. Kristofer Karlsson noticed that `git log -L` includes trailing empty lines in the range, while `git grep -W` explicitly skips them, and proposed a patch to align the two behaviors by trimming trailing empty lines from function ranges in the line-log subsystem.

The patch is under review and has received its first substantive feedback from Junio Hamano. Junio pointed out that the patch only trims lines that start with a literal newline (`\n`), while `git grep -W` treats any line containing only whitespace (spaces or tabs) as empty. This means the patch doesn’t fully achieve its goal: `git log -L` would still include trailing whitespace-only lines, while `git grep -W` excludes them. Junio also noted a potential issue with CRLF line endings on Windows, where a whitespace-only line would end with `\r\n` rather than just `\n`. He suggested the patch should adopt the same logic as `git grep -W` to resolve both the behavioral and cross-platform concerns.

The patch touches `line-range.c` and updates the test suite (`t/t4211-line-log.sh`) to verify the new behavior. Two new tests were added to confirm that trailing empty lines are excluded, but Junio’s feedback implies the tests may not cover whitespace-only lines or CRLF edge cases. The patch is still in its initial version (v1), and no other reviews have been posted yet. The next step is for Kristofer to address Junio’s feedback and send a revised version.
