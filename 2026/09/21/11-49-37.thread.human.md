This thread is about a bugfix to `git log -L :funcname:`, which determines the range of lines belonging to a function when using the line-log feature. The initial version of the patch only trimmed trailing empty lines (those containing just a newline), but Junio C Hamano pointed out that `git grep -W` trims *all* trailing whitespace-only lines (spaces, tabs, or newlines). The author, Kristofer Karlsson, has now posted a revised version (v2) that aligns `git log -L`'s behavior with `git grep -W` by trimming any trailing blank lines—those containing only whitespace.

The patch modifies `parse_range_funcname()` in `line-range.c` to scan backward from the end of the function range, skipping lines that consist solely of whitespace. It also updates the test suite to verify the new behavior, including cases with spaces, tabs, and mixed whitespace. The commit message clarifies that the change handles CRLF line endings correctly, though the tests don’t explicitly cover this edge case. While the patch resolves the technical discrepancy, the thread remains open on whether the documentation for `git log -L` and `git grep -W` should be updated to reflect the now-consistent behavior, as neither command’s man page currently promises this trimming logic.

Junio’s feedback on the first version was the primary driver for this update, and the revised patch directly addresses his concerns. No other participants have weighed in yet, so the discussion is still focused on whether this alignment is the right design choice. The patch is under review and not yet merged.
