Subject: Enable RUNTIME_PREFIX support on OpenBSD via getexecpath()

Originating author: Brad Smith
Thread type: platform compatibility / portability fix

Core problem or goal
Extend Git’s runtime prefix detection to OpenBSD by adding a new code path in `exec_cmd.c` that uses the `getexecpath()` function. This allows OpenBSD builds to use `RUNTIME_PREFIX`, locating runtime files (templates, system hooks) relative to the executable’s path rather than hardcoded installation directories.

Current status
Under review. The patch is a single, small change that introduces a new conditional block (`HAVE_GETEXECPATH`) in `git_get_exec_path()`. No prior versions exist. The mutual exclusivity concern (whether `HAVE_GETEXECPATH` and `HAVE_BSD_KERN_PROC_SYSCTL` could conflict) was raised by Chris Torek, then resolved by Johannes Sixt’s explanation: the `&&` chaining in `git_get_exec_path()` ensures only the first successful method is used, so no build-system constraints or documentation are required.
