This is a follow-up to Nikita Makarov’s bug report about `git log -L` incorrectly including commits that only remove a trailing blank line after a Python function. Kristofer Karlsson confirms the issue but notes that the reproduction steps in the original report were reversed: the blank line should be *added* in the second commit (`c2`), not removed. With the corrected steps, he reproduces the bug on Git 2.43.0 and plans to submit a fix shortly.

The bug affects the line-log’s function boundary detection for Python, specifically when a function is at the end of the file. The parser appears to treat trailing blank lines as part of the function, causing commits that modify them to appear in the output even when the function body is unchanged. This is a clear edge case in the language-specific diff driver logic, likely in `line-log.c` or related code.

Kristofer’s response suggests the issue is real and actionable, and his offer to fix it indicates this is not a contentious or ambiguous problem. The fix will likely involve adjusting how the line-log determines the end of a Python function, ensuring trailing blank lines are excluded from the function’s range. No other contributors have weighed in yet, so the priority and scope of the fix remain unclear, but this looks like a straightforward correctness issue.
