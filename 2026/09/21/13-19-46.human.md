This is the second patch in Maciej Ciemborowicz’s three-patch v2 series fixing a regression in the `reference-transaction` hook, where batched branch and tag deletions lost the resolved old OID values after Git 2.31. The patch updates `git branch` and `git tag` to collect and pass the old OIDs to `refs_delete_refs()`, restoring the pre-regression safety check (conditional deletion) and ensuring the hook receives meaningful old OIDs without additional ref reads. The changes are minimal and focused: both commands now build an `oid_array` of resolved old OIDs and pass it to `refs_delete_refs()`, while new tests verify the hook receives the correct old OIDs and that concurrent updates are preserved.

Karthik Nayak’s review is surface-level, suggesting a minor readability improvement—collecting the old OIDs directly in `collect_tags()` rather than iterating over the list again—but otherwise approves the patch. The suggestion is sensible but not critical, and the patch remains uncontroversial. The core unresolved question from the series—whether the project accepts the intentional race condition trade-off (safety via conditional deletion) or prefers unconditional deletion—is not addressed here, but this patch itself is ready for integration once that decision is made. The test coverage is thorough, covering both the hook’s behavior and the safety check edge case.
