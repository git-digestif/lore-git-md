This is the **final patch (3/3)** in the `dk/use-nsec-runtime` series, which converts the build-time `USE_NSEC` macro into a runtime configuration option (`core.useNanosec`). The series has already graduated to `next` and is effectively complete, with this patch representing the core functional change.

The patch replaces compile-time `#ifdef USE_NSEC` guards with a runtime check for the new `core.useNanosec` config key (defaults to false). It updates `is_racy_stat()` in `read-cache.c` and `match_stat_data()` in `statinfo.c` to use the cached config value from `repo_config_values(istate->repo)->use_nanosec`, eliminating nested preprocessor directives in favor of a single ternary expression. The `use_nanosec` field is unconditionally added to `struct repo_config_values` but ignored (treated as false) when `NO_NSEC` is defined, preserving backward compatibility. Documentation in `Documentation/config/core.adoc` and `Documentation/technical/racy-git.adoc` is updated to reflect the runtime option and clarify platform/filesystem limitations.

Key technical details include the retention of the `#ifndef NO_NSEC` guard in `environment.c` around the config handler for `core.usenanosec`, which prevents reading nanosecond values on unsupported platforms. Jeff King (Peff) noted this guard introduces a subtle correctness risk: mixed builds (one with `NO_NSEC` and one without) on a nanosecond-capable system could lead to false "racy" comparisons, though this edge case is unlikely in practice. The patch also removes `USE_NSEC` from `Makefile`, `configure.ac`, and `compat/posix.h`, and updates a comment in `builtin/update-index.c` to reference the runtime option instead of the build knob.

The architectural constraint introduced by the new call to `repo_config_values()` in `is_racy_stat()`—a latent bug when operating on non-`the_repository` repositories—remains unresolved but is documented as a forward-looking limitation. The series adopts a safe default (treating `core.useNanosec` as false when `istate->repo != the_repository`) as a stopgap, which Junio flagged as a blocker for future recursive submodule operations. The patch is backward-compatible and resolves the v1 performance regression (~41× slowdown) by caching the config value in `repo_config_values`.

Files touched: `Documentation/config/core.adoc`, `Documentation/technical/racy-git.adoc`, `Makefile`, `builtin/update-index.c`, `compat/posix.h`, `configure.ac`, `environment.c`, `environment.h`, `read-cache.c`, and `statinfo.c`. The commit message references benchmarks and CI results, and the diff includes a `Best-viewed-with: --ignore-space-change` hint due to the conversion from `#ifdef` to runtime logic. No further changes are expected for this patch or the series.
