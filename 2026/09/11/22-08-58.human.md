This is the second patch in the v6 series adding path-related keys to `git repo info`. Junio C Hamano suggests splitting it into two patches to better isolate the **critical correctness fix** in `get_superproject_working_tree()` from the new feature (`path.superproject-root`). The fix addresses a long-standing bug in the function (introduced in 2017) where it ignored its `repo` parameter and relied on `xgetcwd()`, causing incorrect behavior in `--git-dir` cases and submodule contexts.

The proposed split would first introduce a **standalone bugfix patch** that corrects `get_superproject_working_tree()`, adds targeted tests to `t1500-rev-parse.sh` (adjacent to the original test from 2017), and demonstrates the improvement. The second patch would then use the fixed function to implement `path.superproject-root.absolute` and `path.superproject-root.relative`, along with the existing tests in `t1900-repo-info.sh`. This separation aligns with Git’s preference for small, self-contained patches and makes the bugfix more discoverable for future maintenance.

The suggestion is **mechanical and non-controversial** but carries **high weight** for the series’ merge readiness. The current patch is already mechanically sound and correctness-fixed, but the split would improve clarity and testability. The author will need to decide whether to implement this change in v7 or defer it to a follow-up. Reviewers should focus on whether the split improves the patch’s structure without complicating the review process.
