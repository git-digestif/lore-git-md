This is the final patch in the v6 series adding path-related keys to `git repo info`. It introduces `path.cdup`, which returns the relative path from the current working directory to the repository’s top-level working tree (e.g., `../../` in a subdirectory, empty string at the root). The implementation is straightforward, reusing the repository’s `prefix` field to count slashes and generate `../` sequences. The patch includes clear documentation and tests covering both root and subdirectory cases.

The addition of `path.cdup` completes the relative-path key set (`path.git-prefix` and `path.cdup` are inverses) and directly addresses Junio C Hamano’s earlier design feedback. The implementation is mechanically sound, with no unresolved technical concerns. The patch aligns with the series’ overall design and reuses existing infrastructure, avoiding duplication. Reviewers can focus on the test coverage and edge-case handling (e.g., trailing slashes), though these appear correct.

This is a well-motivated, user-facing feature that fills a gap in Git’s plumbing. The series as a whole is now feature-complete and ready for final review, with the only remaining open question being the deferred architectural refactoring of shared logic between `git repo info` and `git rev-parse`.
