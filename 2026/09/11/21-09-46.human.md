This is a CI/build system review comment on the first patch of Johannes Schindelin’s two-part series (v2) that enables Rust compilation in Git’s GitHub Actions Windows CI jobs. The series configures the Rust toolchain to target the GCC ABI (used by Git for Windows) instead of the default MSVC ABI, ensuring Cargo produces a static library compatible with MinGW’s linker.

Junio C Hamano raises a small but important consistency point: the patch introduces a new `CARGO_TARGET` variable to specify the Rust target triple, but Cargo’s official environment variable for this purpose is `CARGO_BUILD_TARGET`. Junio suggests aligning with the existing variable name to avoid confusion and to ensure compatibility with a recently merged patch (`jc/rust-cargo-build-target`) by James Le Cuirot. That patch makes Git respect `CARGO_BUILD_TARGET` when locating build artifacts, ensuring the correct target-tuple subdirectory is used during cross-compilation. The change is trivial—renaming `CARGO_TARGET` to `CARGO_BUILD_TARGET`—but it prevents a subtle inconsistency in the build system.

The review is substantive but narrow: it does not question the overall goal or logic of the patch, only the choice of variable name. The feedback is well-founded and easy to address, and the author is likely to incorporate it in a follow-up iteration. The patch remains uncontroversial and is still on track for eventual merge, pending the variable rename and confirmation that the logic works on GitLab’s Windows runners.
