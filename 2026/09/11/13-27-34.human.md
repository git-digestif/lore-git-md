This is the final patch in Patrick Steinhardt’s 10-patch series refactoring Git’s object integrity verification (`fsck`) to make consistency checks pluggable per ODB backend. It moves loose-object verification from `builtin/fsck.c` into the loose ODB backend (`odb/source-loose.c`), completing the series’ goal of relocating all backend-specific fsck logic out of the monolithic `cmd_fsck()` function.

The patch removes 90 lines from `builtin/fsck.c` and adds 89 lines to `odb/source-loose.c`, introducing a new `ODB_FSCK_VERBOSE` flag to preserve the original behavior of printing status messages when `--verbose` is passed. It also fixes a latent bug in the progress-meter logic: the old code captured the progress meter in the callback data before it was initialized, causing the meter to jump from 0 to 256 at completion; the new code initializes the meter first, restoring incremental updates. The `fsck_loose()` helper is relocated and adapted to use a new `struct fsck_loose_data`, which consolidates callback data and error state, and the patch threads the `ODB_FSCK_VERBOSE` and `ODB_FSCK_PROGRESS` flags through the `struct odb_fsck_options` to ensure the loose backend respects caller preferences without exposing backend details.

Review feedback from Toon Claes remains unresolved but is minor: whether `ODB_FSCK_VERBOSE` and `ODB_FSCK_PROGRESS` should be documented as mutually exclusive (Patrick states they are not, as their outputs do not interfere), and whether the `object_cb` callback should be guarded against NULL (Patrick declines, noting no current callers pass NULL). Neither affects correctness or blocks integration. The series is now complete, with all patches rebased onto Junio’s integration branch and all prior feedback addressed. This patch is a clean, well-motivated refactoring that fits the series’ architectural goals.
