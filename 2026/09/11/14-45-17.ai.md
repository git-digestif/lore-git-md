This is the fifth patch in the v6 series adding path-related keys to `git repo info`. It introduces `path.grafts.absolute` and `path.grafts.relative` to expose the repository’s grafts file location in a scriptable format, mirroring the behavior of `git rev-parse --git-path info/grafts` but integrated into the `git repo info` interface.

The implementation is straightforward: it uses `repo_get_graft_file()` to resolve the path, respecting the `GIT_GRAFT_FILE` environment variable, and formats it as either an absolute or relative path using the existing `format_path()` helper. The path is returned unconditionally, even if the file does not exist, aligning with the series’ design principle and Junio’s prior endorsement for similar keys (`path.index`, `path.hooks`). Documentation and tests cover the standard case and the `GIT_GRAFT_FILE` override, ensuring the key behaves predictably in edge cases.

The test coverage is adequate, though it does not explicitly verify bare-repository behavior—this is consistent with the series’ approach, as `path.grafts` (like `path.index`) returns a path even in bare repositories.
