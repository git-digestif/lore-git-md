This is part of Patrick Steinhardt’s 13-patch series removing ad-hoc ODB source linking, specifically the third patch in v3. It continues the `the_repository` removal effort by refactoring the `submodule-config` subsystem to accept an explicit `struct repository *` parameter instead of implicitly using the global `the_repository`.

The patch touches seven files (`builtin/fetch.c`, `builtin/grep.c`, `builtin/submodule--helper.c`, `submodule-config.c`, `submodule-config.h`, `submodule.c`, and `t/helper/test-submodule.c`). It updates eight functions in `submodule-config.c` to take a `struct repository *` parameter and adjusts their callers accordingly. The changes are mechanical: every function that previously used `the_repository` now receives it as an explicit argument, and callers pass `the_repository` directly (even when a different repository is available in context). This preserves behavior while eliminating implicit global state dependencies.

No functional changes are introduced; the patch is purely a refactoring step toward the series’ broader goal of simplifying ODB source management. The commit message notes that this approach simplifies migration and avoids behavior changes during the transition. All callers updated in this patch are internal to Git’s submodule handling, so the impact is contained to the submodule-config subsystem.

The patch is uncontroversial and aligns with the series’ overall direction. Earlier reviews from Junio C Hamano, Karthik Nayak, and Justin Tobler on other patches in the series confirm the correctness of the repository dependency encapsulation, and this patch follows the same pattern. No new objections or questions have been raised about this specific change. The series as a whole is now fully reviewed and ready for Junio’s queue.
