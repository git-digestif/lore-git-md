This is patch 10/13 in Patrick Steinhardt’s v3 series refactoring the object database (ODB) subsystem to remove ad-hoc source linking. The patch enforces the documented constraint that `git multi-pack-index --object-dir=` must point to an alternate object directory, rejecting non-alternate paths with a clear error message instead of silently constructing an ad-hoc source. This aligns behavior with the documentation (since 2021) and removes the last non-test caller of the ad-hoc source mechanism, a key goal of the series.

The change is minimal: three lines in `builtin/multi-pack-index.c` replace the call to `odb_add_to_alternates_memory()` with a `die()` call, and nine lines in `t/t5319-multi-pack-index.sh` adjust test setup to retain the temporary repository (`repo64`) that links the test object directory (`objects64`) as an alternate. The test adaptation is necessary because the test chain previously relied on the now-removed ad-hoc source creation to access `objects64`, which was not connected to any repository. The updated tests now explicitly use `repo64` (initialized with `objects64` as an alternate) to invoke `git multi-pack-index`, preserving the test’s intent while complying with the new constraint.

Justin Tobler’s **substantive review** of v2 confirmed the patch’s correctness, noting that the 2021 documentation already described the restriction and that the change removes the last non-test use of the ad-hoc source API. The patch is uncontroversial and ready for integration, with no open questions or dependencies. It is part of the broader ODB abstraction effort and the ongoing `the_repository` removal work, but its impact is self-contained to `git multi-pack-index` and its test suite.
