This is patch 7/13 of Patrick Steinhardt’s ODB refactoring series, removing the infrastructure for registering submodule object databases as in-memory sources. The patch deletes the `submodule_source_paths` string list from `struct object_database`, removes the `odb_add_submodule_source_by_path()` and `register_all_submodule_sources()` functions from `odb.c`/`odb.h`, and cleans up the now-obsolete `GIT_TEST_FATAL_REGISTER_SUBMODULE_ODB` test mode from documentation and test scripts.

The change is mechanical and uncontroversial: earlier patches in the series (notably 5/13 and 6/13) have already removed the last callers of `odb_add_submodule_source_by_path()`, so this patch simply deletes the unused code. The commit message explains that the mechanism was a transitional crutch during the migration to explicit submodule repository passing (dating back to 2021) and is no longer needed. The patch also removes the test mode’s documentation from `t/README` and its exports from seven test scripts (`t/t5526-fetch-submodules.sh`, `t/t5531-deep-submodule-push.sh`, `t/t5545-push-options.sh`, `t/t5572-pull-submodule.sh`, `t/t6437-submodule-merge.sh`, `t/t7418-submodule-sparse-gitmodules.sh`, and `t/t7814-grep-recurse-submodules.sh`), as the mode is now a no-op.

The diff is clean: 36 lines removed from `odb.c`, 14 from `odb.h`, 7 from `t/README`, and 3 from each of the seven test scripts. No functional changes are introduced; the patch merely completes the cleanup begun in earlier patches. Karthik Nayak’s review of this patch in v2 confirmed the safe removal of the infrastructure, and the series as a whole is fully reviewed and ready for Junio’s queue. This patch is a straightforward deletion with no open questions.
