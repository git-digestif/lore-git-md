This is a follow-up in the `--matched-only` feature thread for `git range-diff`. Harald Nordgren responds to Junio C Hamano’s proposed refactor of the option naming and combination logic.

Harald acknowledges the design direction but pushes back on the scale of the change, particularly the introduction of deprecated options that would linger indefinitely. Instead, he suggests a lighter approach: name the new options `--hide-left` and `--hide-right` (dropping the `-only` suffix for brevity), allow them to be combined freely, and treat `--matched-only` as pure syntactic sugar rather than a necessary shorthand. This would avoid the need for deprecation while still achieving the same filtering behavior. The tone is pragmatic, focusing on minimizing long-term maintenance burden rather than questioning the feature’s utility. No new implementation details or code changes are proposed in this reply.
