This is a refactoring patch series targeting the object database (ODB) subsystem, now in its third iteration. The goal is to eliminate the mechanism that allows registering in-memory sources (like submodule object databases) in the ODB, simplifying the codebase by ensuring the sources list contains only alternates. This cleanup removes a long-standing design wart and prepares the ground for future performance improvements in alternate handling.

The series is well-motivated and uncontroversial. The dual-use of the ODB sources list has been a source of complexity and subtle bugs, and recent refactoring (like submodule sources no longer needing to link into the main ODB) makes this removal feasible. The 13 patches touch a broad but focused set of files: `odb.c`/`odb.h` (removing the registration API), `submodule-config.c` (adapting to the new model), `builtin/grep.c` (stopping submodule ODB registration), and various test helpers. The changes are mechanical and well-tested, with no behavioral regressions expected beyond a memory leak fix and a breaking change in `git multi-pack-index --object-dir=` (now correctly rejecting non-alternate directories).

Key improvements in v3 are minor: the commit message for patch 5/13 was tweaked to clarify that the repository being registered is a submodule, not `the_repository`. This addresses a surface-level ambiguity noted by Justin Tobler in v2. The series is now fully reviewed, with substantive approvals from Junio C Hamano (patches 1/13 and 6/13), Karthik Nayak (patches 2/13, 7/13, and the full series), and Justin Tobler (patches 5/13 and 10/13). The author, Patrick Steinhardt, has confirmed the root causes of the bugs fixed in patches 2/13 and 5/13, and the series is ready for Junio’s queue.

The patch count has grown slightly from v1 (12 patches) to v3 (13 patches), but the additions are all cleanups or fixes that became possible after earlier patches removed dependencies. The series is self-contained and depends only on prior work in the ODB abstraction effort. If you care about Git’s internals or plan to work on the ODB, this is worth skimming; otherwise, it’s safe to wait for it to land in `next`.
