This is patch 7/10 in Patrick Steinhardt’s ongoing ODB abstraction series, which refactors Git’s fsck checks to be pluggable per backend. The patch moves reverse-index verification from `builtin/fsck.c` into the packed ODB backend (`odb/source-packed.c`), replacing the dedicated `ERROR_PACK_REV_INDEX` bit with the generic `ERROR_OBJECT` bit. The new implementation respects the `--connectivity-only` and `--no-full` flags, skipping reverse-index checks when either is passed.

Toon Claes’s reply is a surface-level review that confirms the architectural fit: the reverse-index check now lives in the packed ODB’s `fsck` callback, which is invoked by the central `odb_fsck()` helper. He notes that negative return values from the callback are converted to `ERROR_OBJECT` in `builtin/fsck.c`, preserving the existing error-reporting contract. The comment is purely observational and does not raise technical concerns, edge cases, or design questions. It serves as a lightweight sign-off on the patch’s placement within the ODB abstraction scaffolding introduced in earlier patches.
