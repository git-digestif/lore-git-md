This is the tenth patch in Patrick Steinhardt’s 13-patch series refactoring the object database (ODB) subsystem to remove ad-hoc in-memory source registration. The series is part of the ongoing ODB abstraction effort and continues the `the_repository` removal work.

This patch enforces the documented constraint that `git multi-pack-index --object-dir=` must point to an alternate object directory. Previously, Git would silently create an ad-hoc ODB source for any directory, even if it wasn’t an alternate, contradicting the documentation and creating questionable behavior (e.g., bitmaps operating on the wrong repository’s refs). The patch replaces this behavior with an explicit error message when the specified directory isn’t an alternate.

The change is minimal: three lines modified in `builtin/multi-pack-index.c` to replace the ad-hoc source creation with a `die()` call. The test suite is updated to retain a temporary repository (`repo64`) that links to the test object directory (`objects64`), ensuring the directory remains a valid alternate. This aligns with the documented behavior since 2021 and removes the last non-test caller of the ad-hoc source mechanism, a key goal of the series.

The patch is uncontroversial and well-motivated. The commit message clearly explains the rationale, the breaking change, and the test adjustments. Justin Tobler’s review in v2 confirmed the correctness of this enforcement, and the series as a whole is now fully reviewed and ready for Junio’s queue. No further iteration is expected.
