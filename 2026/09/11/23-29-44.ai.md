This patch proposes a **feature** change to `git blame`: it makes the command automatically look for and use a `.git-blame-ignore-revs` file in the repository root if no explicit ignore file is configured. The change addresses a long-standing inconsistency where web interfaces (GitHub, GitLab, etc.) respect ignore files by default, but local `git blame` invocations require manual configuration.

The motivation is clear: the `.git-blame-ignore-revs` file has become an ecosystem standard, and users are frequently surprised when their local blame output differs from what they see on the web. The patch anchors the default file lookup to the working tree root, uses `lstat()` to reject symlinks and non-regular files, and ensures user-configured ignore files take precedence. It also handles edge cases like empty files, comments, and whitespace gracefully.

The implementation is careful about security and precedence: the default file is loaded before any user configuration, but an empty `blame.ignoreRevsFile` or `--ignore-revs-file ""` will bypass it entirely. The patch includes thorough test coverage for subdirectory invocations, symlink rejection, bare repositories, and CLI/config overrides. Documentation updates clarify the new behavior and override semantics.

This is a well-motivated, well-tested change that aligns Git’s behavior with established ecosystem practice. The commit message explains both the original design rationale (avoiding unrequested filesystem I/O) and why the ecosystem shift now justifies a default. The patch touches the blame subsystem, documentation, and tests, but does not introduce new user-facing options — it simply makes an existing feature more convenient.
