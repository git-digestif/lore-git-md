This is a bugfix patch in Patrick Steinhardt’s 13-part ODB refactoring series. It plugs a memory leak in the packed ODB source backend (`odb/source-packed.c`) that surfaces when packed sources are no longer automatically linked to the main object database. The leak occurs because the source’s packs and multi-pack indices are not closed when the source is freed; the fix adds a single line (`odb_source_close(source)`) to ensure proper cleanup. This is a prerequisite for later patches that stop linking ad-hoc packed sources, ensuring the refactoring does not introduce regressions.

The patch is minimal (one line added) and self-contained, touching only `odb/source-packed.c`. It addresses a latent issue that becomes visible in subsequent commits, so its correctness depends on the broader series context. The commit message clearly explains the leak’s cause and the fix’s role in the larger refactoring. No test updates are needed, as the leak is not user-visible and the existing test suite already covers the affected code paths.

This patch is uncontroversial and fully reviewed as part of the series. It was introduced in v2 to address a gap identified during review, and v3 contains no changes to it. The series as a whole is ready for Junio’s queue, with all patches approved by Karthik Nayak, Justin Tobler, and Junio himself (in v1). The memory leak fix is a small but necessary step toward removing the ad-hoc ODB source registration mechanism.
