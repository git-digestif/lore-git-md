This is the first patch in a three-part **bugfix series** addressing resource cleanup in Git’s low-level merge driver infrastructure. The series, originally authored by Michal Koutný and now submitted as v2 by Jeff King (Peff), ensures temporary files created during external merge operations are reliably removed even when the process is interrupted by SIGINT or SIGQUIT.

This specific patch modernizes the code that reads the external merge driver’s output file by replacing manual file-handling logic with Git’s `strbuf` API. The change reduces boilerplate and eliminates potential error paths (e.g., forgetting to close the file descriptor or mismanaging buffer allocation). While not strictly necessary for the core fix, it simplifies the codebase and avoids textual conflicts with the later patches in the series. The commit message clearly explains the rationale and edge cases, such as the type mismatch between `long` and `size_t` in the `mmbuffer_t` struct, which remains unresolved but is acknowledged as out-of-scope for this series.

The patch is uncontroversial and aligns with Git’s established patterns for file I/O. It touches only `merge-ll.c` and introduces no functional changes—just a cleaner implementation. The rest of the series (patches 2 and 3) will address the actual signal-safety issue by replacing custom signal handling with Git’s `tempfile` API, but this patch stands alone as a worthwhile cleanup.

For a busy reader, this patch is worth noting as a small but well-executed step toward a larger fix. It’s unlikely to draw significant discussion, but it sets the stage for the more critical changes that follow. The series as a whole looks like a solid, low-risk improvement to a long-standing robustness issue.
