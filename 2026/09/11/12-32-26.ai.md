This is the **v7 cover letter** for the `dk/use-nsec-runtime` series, which has already graduated to `next` and is effectively complete. The series converts the build-time `USE_NSEC` macro into a runtime configuration option (`core.useNanosec`), allowing users to enable nanosecond precision on supported filesystems without recompiling Git. This version is a **final polish** addressing minor documentation and architectural concerns raised in earlier iterations.

The v7 changes are minimal: a **typo fix** ("comparisions" → "comparisons") in the `core.useNanosec` documentation and a **decision not to pursue further `#ifdef` adjustments** or add a "safe default" for repositories other than `the_repository`. The author explicitly confirms that the series is **technically complete** and no longer plans a v8, aligning with prior consensus from Junio and Jeff King (Peff) that the remaining preprocessor guard (`#ifndef NO_NSEC`) is acceptable despite its trade-offs. Key technical details remain unchanged from earlier versions: the `use_nanosec` field in `struct repo_config_values` is unconditionally present but ignored (treated as false) when `NO_NSEC` is defined, preserving backward compatibility. The performance regression from v1 (~41× slowdown) is resolved by caching the config value in `repo_config_values`. The **architectural constraint**—a latent bug in `is_racy_stat()` when operating on non-`the_repository` repositories—is documented but unresolved, as deeper refactoring was deferred due to complexity. Junio has flagged this as a blocker for future recursive submodule operations, but the current stopgap (treating `core.useNanosec` as false for non-`the_repository`) is deemed sufficient for now.
