This is Junio’s "What’s cooking" report for September 2026, summarizing the state of Git’s integration branches as the 2.56 release cycle progresses. The report is not a patch itself but a curated snapshot of in-flight topics, their status, and recent movements between integration branches. It is essential reading for anyone tracking Git’s development rhythm.

Git 2.56-rc0 has been tagged, and the focus is now on stabilizing topics in `next` for the final release. The report lists 80 non-merge commits in `next` and 228 in `seen`, with the usual caveat that most of the latter will not graduate in time for 2.56. The tone is matter-of-fact: topics are either cooking, waiting for review, or marked for discard after prolonged inactivity.

Notable graduations to `master` include CI updates (Debian 12, system asciidoctor) and a large batch of MinGW build improvements from Git for Windows. These are uncontroversial housekeeping patches that address platform support and CI reliability.

In `next`, the most substantial work revolves around object database (ODB) refactoring. Patrick Steinhardt’s `ps/odb-alternates-at-creation` and `ps/odb-pluggable-fsck` series continue the ODB abstraction effort, moving alternates setup to database creation time and making fsck checks pluggable. Both are marked as "Needs review" but appear technically sound and well-scoped. The `ps/odb-stop-registering-in-memory-sources` topic, which just graduated, removes the ad-hoc alternate registration API, simplifying the backend interface.

Other significant topics in `next` include Elijah Newren’s conflict-resolution safety net (`en/no-amend-during-conflicts`), which prevents `commit --amend` and partial commits during conflicted operations, and Phillip Wood’s `tb/rerere-lock-grace` series, which defers automatic maintenance until the end of sequencer operations to avoid lock contention.

The report flags several topics as "Waiting for response" or "Expecting a reroll," indicating open discussion or known issues. Christian Couder’s `cc/lazy-fetch-trusted-bit` introduces a new `uploadpack.lazyFetchTrusted` option to allow lazy fetching from promisor remotes in trusted repositories, but Junio has raised questions about the design. Tyler Cipriani’s `tc/push-force-if-includes-fixes` corrects a long-standing bug in the `--force-if-includes` protection, which incorrectly checked the reflog of the remote branch rather than the local branch being pushed.

Two Rust-related topics are cooking: `jc/rust-cargo-build-target` and `mh/rust-crate-subdir`. The former respects `CARGO_BUILD_TARGET` when cross-compiling, while the latter moves Rust code into a dedicated `rust/` subdirectory to avoid confusing Cargo. Both are small, targeted fixes that address immediate build issues rather than advancing the broader Rustification effort.

The report also highlights several documentation and test improvements, such as Jean-Noël Avila’s `kh/doc-datamodel` series, which links the new `gitdatamodel(7)` tutorial from key documentation pages, and Toon Claes’s `ta/command-list-guides-sync-lint`, which adds a linter to keep `command-list.txt` in sync with the Makefile.

Discarded topics include a retracted attempt to move `libgit.a` sources into a `lib/` directory (too many merge conflicts) and several patches that stalled due to lack of response. These are noted for completeness but are not actionable.

Overall, the report paints a picture of a project in steady forward motion, with ODB refactoring and conflict-resolution safety as the most prominent technical themes. The Rust topics are incremental and pragmatic, addressing build issues rather than pushing the language boundary. The tone is calm and methodical, reflecting Junio’s usual integration discipline.
