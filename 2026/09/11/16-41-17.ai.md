This is a feature patch adding a `--matched-only` option to `git range-diff`. The new option filters the output to show only commits that appear in both input ranges, skipping any that exist on only one side. It reuses the existing suppression logic for `--left-only` and `--right-only` by internally setting both flags when `--matched-only` is specified. The patch updates the documentation, adds the new option to the command-line parser, extends the mutual-exclusion check to reject combining `--matched-only` with either of the other two filtering options, and includes a thorough test case demonstrating the new behavior and its interaction with the existing flags.

The motivation is clear: when reviewing a rebase or range-diff, users often want to focus on the commits that survived the operation and see how they changed, rather than scrolling past commits that were simply added or dropped. The implementation is straightforward and leverages existing code paths, which suggests it is unlikely to introduce subtle bugs. The test coverage is comprehensive, verifying both the new functionality and the mutual-exclusion logic. The commit message and documentation are well-written and explain the use case effectively.
