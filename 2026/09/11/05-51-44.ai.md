This is the first patch in Patrick Steinhardt’s **v3 13-patch series** refactoring the object database (ODB) subsystem to remove ad-hoc in-memory source registration. The patch targets the `cache-tree` subsystem as part of the broader `the_repository` removal effort.

The change eliminates an implicit dependency on `the_repository` in `cache_tree_fully_valid()` by making the function accept a `struct index_state` instead of a `struct cache_tree`. This ensures the correct repository is used for object existence checks, as the `index_state` already holds a reference to its owning repository. The patch renames the original function to `cache_tree_fully_valid_recursive()` (now file-scoped static) and introduces a wrapper that delegates to it using `istate->repo->objects`. Callers in `builtin/checkout.c`, `builtin/commit.c`, `sequencer.c`, `sparse-index.c`, and `unpack-trees.c` are updated to pass the `index_state` instead of the cache tree.

The patch is **uncontroversial** and **well-motivated**, addressing a technical debt issue identified by Junio C Hamano in an earlier review. It touches 7 files and 18 lines, with no behavioral changes expected. The commit message clearly explains the rationale and the mechanical transformation, and the change aligns with the series’ goal of simplifying ODB internals. Junio’s earlier substantive approval ("Yay. Very nice.") for this patch in v1, combined with the lack of objections in v2/v3, suggests it is ready for merging.

Key symbols modified: `cache_tree_fully_valid()` (now takes `struct index_state *`), `cache_tree_fully_valid_recursive()` (new static helper). No new symbols are introduced.
