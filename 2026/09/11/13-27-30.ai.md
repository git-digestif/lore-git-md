This is patch 6/10 of Patrick Steinhardt’s v3 series refactoring Git’s object integrity verification (fsck) to make consistency checks pluggable per ODB backend. The patch moves packfile verification from `builtin/fsck.c` into the packed ODB backend (`odb/source-packed.c`), continuing the architectural shift begun in earlier patches. It threads the progress meter and object callback through the new `struct odb_fsck_options`, ensuring the packed backend respects caller preferences without exposing backend details. The change removes 33 lines from `cmd_fsck()` and adds 46 lines to `odb/source-packed.c`, plus a small addition to `odb.h` to expose the progress flag and callback fields.

The patch also simplifies error reporting by replacing the undocumented `ERROR_PACK` bit with the generic `ERROR_OBJECT` bit. The `ERROR_PACK` bit was never exercised in the test suite and was specific to the object storage backend, making it a poor fit for the new pluggable infrastructure. The new implementation uses the `verify_packs()` helper, which iterates over all packfiles in the packed ODB source and invokes `verify_pack()` with the caller-provided object callback and progress meter. The helper respects the `ODB_FSCK_FULL` flag, skipping verification when it is not set.

No behavior changes are introduced; the patch is a pure refactoring that aligns with the series’ goal of moving fsck logic into backend-specific implementations. The progress meter and object callback are now passed through the `odb_fsck_options` structure, preserving the original semantics while decoupling `builtin/fsck.c` from backend-specific details. The patch touches `builtin/fsck.c`, `odb.h`, and `odb/source-packed.c`, and depends on the scaffolding introduced in earlier patches (e.g., `struct odb_fsck_options`, `ODB_FSCK_FULL` flag).

Review feedback from earlier iterations has been addressed, and the patch is uncontroversial. The only notable change is the replacement of `ERROR_PACK` with `ERROR_OBJECT`, which is consistent with the series’ broader pattern of using generic error bits for backend-specific verification. The patch is ready for integration and does not introduce new open questions or dependencies.
