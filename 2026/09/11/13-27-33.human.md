This is the ninth patch in Patrick Steinhardt’s ten-part series refactoring Git’s object integrity verification (`fsck`) to make consistency checks pluggable per ODB backend. The patch moves multi-pack index (MIDX) verification from `builtin/fsck.c` into the packed ODB backend (`odb/source-packed.c`), continuing the pattern established in earlier patches. It replaces the dedicated `ERROR_MULTI_PACK_INDEX` bit with the generic `ERROR_OBJECT` bit and ensures the new implementation respects the `--no-full` and `--connectivity-only` flags. A new test in `t/t5319-multi-pack-index.sh` verifies these semantics.

The patch removes 18 lines from `cmd_fsck()` and adds 27 lines to `odb/source-packed.c`, introducing the `verify_midx()` helper. This helper spawns `git multi-pack-index verify` as a child process, checks the repository’s `core_multi_pack_index` setting, and threads the progress meter flag through the `odb_fsck_options` structure. The implementation uses early returns for stylistic clarity and calls `prepare_repo_settings()` to ensure repository settings are initialized gracefully, addressing feedback from Toon Claes’s review of the v2 iteration.

The test added to `t/t5319-multi-pack-index.sh` confirms that MIDX checks are skipped when `--connectivity-only` is passed and are performed when `--no-full` is used, matching the behavior of other backend-specific checks in the series. The patch is uncontroversial and ready for integration; the only unresolved question from Toon’s review—why `verify_midx()` checks for negative returns while `verify_bitmap_files()` does not—is a minor implementation detail that does not affect correctness. All other feedback has been addressed in this v3 update.
