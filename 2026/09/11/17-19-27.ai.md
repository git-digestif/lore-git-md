This is a review reply from Junio C Hamano to Harald Nordgren’s `--matched-only` feature patch for `git range-diff`. The review is substantive and suggests a more general refactoring of the existing `--left-only` and `--right-only` options.

Junio observes that the current implementation’s description of `--matched-only` as “the same as using `--left-only` and `--right-only` together” is misleading because the existing options are defined as *showing* one side, not *hiding* the other. He proposes a cleaner design: introduce `--hide-left-only` and `--hide-right-only` as synonyms for the current `--right-only` and `--left-only`, deprecate the original names, and then allow the new `--hide-*` options to be combined. This would make `--matched-only` a true shorthand for `--hide-left-only --hide-right-only`, aligning the documentation with the implementation.

He also points out a minor mechanical nit: the patch’s mutual-exclusion check should use the existing helper `die_for_incompatible_opt3()` instead of open-coding the error. Beyond that, Junio notes that the new option’s output—numbered gaps where unmatched commits were omitted—is acceptable, though it loses the hint that a larger `--creation-factor` might produce better matches. The review is constructive and focuses on internal consistency and future extensibility rather than questioning the feature’s utility.
