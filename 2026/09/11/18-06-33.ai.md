This is a **substantive review** of the first patch in Peff’s three-part bugfix series for merge driver resource cleanup. Elijah Newren identifies a **previously latent bug** in the `strbuf`-based refactoring: when the external merge result exceeds `LONG_MAX` bytes, the old code would fail fast (due to `xmallocz` rejecting the oversized allocation), but the new code silently truncates the size to a negative value, risking buffer overreads by callers. His suggested fix—a simple `die()` check—is a targeted, low-risk mitigation that preserves the patch’s cleanup goals while closing the safety gap.

The review is **tested-level**: Elijah traces the type conversion behavior on LLP64 platforms (e.g., Windows), where `long` is 32-bit and `size_t` is 64-bit, and demonstrates how the wraparound could lead to memory corruption. This is a real edge case, albeit rare, and his fix aligns with Git’s defensive programming ethos. The rest of the patch (the `strbuf` conversion itself) remains uncontroversial and well-motivated.

No other concerns are raised; Elijah’s feedback is narrowly scoped to the type-safety issue. The patch is otherwise ready for review, and the fix is trivial to implement. The series’ broader goal—replacing custom signal handling with Git’s `tempfile` API—is unaffected. Expect a v3 from Peff incorporating the check, likely with no further discussion needed.
