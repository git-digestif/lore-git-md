This is the fifth patch in Patrick Steinhardt’s 13-patch series refactoring the object database (ODB) subsystem to remove ad-hoc in-memory source registration. The series is part of the ongoing ODB abstraction effort and continues the `the_repository` removal work.

This patch removes the last call to `odb_add_submodule_source_by_path()` in `submodule-config.c`, eliminating the final implicit dependency on `the_repository` in this file. The change is straightforward: when reading `.gitmodules` from a blob in a submodule repository, the code no longer registers that submodule’s object database as an in-memory source of `the_repository`. The commit message explains that this registration was a workaround for a 2019 limitation in `config_with_options()`, which was resolved in 2021 (commit `e3e8bf046e`). With earlier patches in the series ensuring the `cache-tree` subsystem correctly accesses submodule objects, this workaround is now unnecessary. The patch also removes the `USE_THE_REPOSITORY_VARIABLE` define, as it is no longer needed.

The change is uncontroversial and aligns with the series’ goal of simplifying the ODB subsystem by removing dual-use of the sources list. Justin Tobler’s review in v2 confirmed the safety of this removal, and the v3 revision incorporates his suggested commit message clarification to emphasize that the repository being registered is a submodule, not `the_repository`. The patch touches only `submodule-config.c` and deletes four lines, making it a clean, mechanical cleanup.

This patch is a key step in the series, as it removes the last non-test caller of the ad-hoc source registration mechanism. The series as a whole is now fully reviewed and ready for Junio’s queue, with no open questions or loose ends. If you’re following the ODB abstraction or `the_repository` removal efforts, this patch is worth noting as a milestone in eliminating implicit global state dependencies.
