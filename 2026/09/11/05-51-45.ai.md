This is patch 2/13 of Patrick Steinhardt’s ODB refactoring series, targeting the `cache-tree` subsystem as part of the ongoing `the_repository` removal effort. The patch eliminates an implicit dependency on `the_repository` by ensuring the correct repository context is used for object existence checks and `.gitmodules` lookups, which previously relied on the global state.

The change is mechanical but critical: it propagates a `struct repository *` parameter through the `cache_tree_update()`, `cache_tree_write()`, and `cache_tree_read()` functions, replacing all direct uses of `the_repository` and `the_hash_algo`. The `must_prefetch_predicate` callback type is extended to accept a `void *cb_data` parameter, allowing the repository context to be passed through `prefetch_cache_entries()`. This ensures that when reading `.gitmodules` from a submodule’s index, the object is fetched from the correct repository rather than `the_repository`.

The patch also removes the last dependency on registering submodule object databases with the main ODB, a mechanism slated for removal in later patches. The commit message highlights this by noting that tests with `GIT_TEST_FATAL_REGISTER_SUBMODULE_ODB=true` now pass, confirming the fix. No behavioral changes are expected, and the patch is uncontroversial, with Karthik Nayak’s review in v2 confirming the correctness of the repository dependency encapsulation.

Files touched include `cache-tree.c` (the bulk of the changes), `cache-tree.h` (updated function signatures), `read-cache-ll.h` (callback type extension), `read-cache.c` (parameter propagation), and `unpack-trees.c` (callback adaptation). The patch is a prerequisite for later work in the series, particularly the removal of the `odb_add_submodule_source_by_path()` API. Junio’s earlier substantive approval of the series ("Yay. Very nice.") and the lack of new objections in v2/v3 suggest this is ready for integration.
