This is a follow-up cleanup to the `receive-report` hook series, now cooking in `next`. Junio C Hamano proposes a small but idiomatic improvement to the `override_cmds_error()` helper introduced in patch 4/4 of Karthik Nayak’s series. The helper currently guards its `FREE_AND_NULL()` call with an `if` check, but since `FREE_AND_NULL()` is designed to be safe on `NULL` pointers, the guard is redundant. Junio’s patch removes the conditional, simplifying the code and aligning it with Git’s established practice of unconditionally freeing pointers. The change is mechanical and uncontroversial, touching only two lines in `builtin/receive-pack.c`.

Junio also updates the Coccinelle semantic patch (`free.cocci`) to automate this pattern across the codebase, ensuring future contributors follow the same idiom. The Coccinelle rule is straightforward: it replaces any `if (E) FREE_AND_NULL(E);` with `FREE_AND_NULL(E);`, eliminating unnecessary conditionals. This is a minor but useful consistency fix that reduces boilerplate and makes the codebase slightly more maintainable.

The patch is a direct response to Karthik’s v10 implementation, which already addressed the memory leak Junio previously identified. This follow-up is purely stylistic and does not affect functionality or test coverage. It is a typical example of the kind of small cleanup Junio often applies after a series lands in `next`, ensuring the codebase remains idiomatic and consistent. The change is unlikely to generate discussion, but it is worth noting for readers tracking the series’ progress toward `master`.
