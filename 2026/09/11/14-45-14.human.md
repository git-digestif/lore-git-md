This is the second patch in the v6 series adding new path-related keys to `` `git repo info` ``. It introduces ``path.superproject-root.absolute`` and ``path.superproject-root.relative``, which expose the top-level working tree of the superproject when the current repository is a submodule.

The patch is **mechanically sound and correctness-bug-fixed**: it updates the ``get_superproject_working_tree()`` function to respect its ``repo`` parameter (instead of relying on ``xgetcwd()``) and uses the repository’s working directory, resolving the critical bug identified in v5. The fix is accompanied by additional test coverage for the ``--git-dir`` case, ensuring the key works correctly when invoked from a submodule’s Git directory. The implementation follows the established pattern of returning an empty string when not inside a submodule.

The documentation and tests are thorough, covering submodule contexts, bare-repository edge cases, and ``--git-dir`` usage.
