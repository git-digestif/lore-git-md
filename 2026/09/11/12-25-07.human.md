This is a CI/build system patch update from Johannes Schindelin, responding to Junio C Hamano’s review of the first patch in his two-part series enabling Rust compilation in Git’s GitHub Actions Windows CI.

Johannes confirms Junio’s observation: the UCRT64 environment, which uses GCC rather than Clang, was incorrectly mapped to the `x86_64-pc-windows-gnullvm` target in the second patch. The correct target should be `x86_64-pc-windows-gnu` to match the GCC ABI used by Git for Windows. This resolves the inconsistency Junio flagged between the `Makefile` logic (which correctly assigns `-gnu`) and the shell script (which incorrectly assigned `-gnullvm`). The fix is straightforward and aligns the two patches.

The series remains narrowly focused on CI infrastructure, with no changes to Git’s core functionality or user-facing features. The correction is a minor but necessary adjustment to ensure the Rust toolchain produces a static library compatible with MinGW’s linker. No new testing or CI results are provided in this reply, but the change is unlikely to introduce regressions since it restores consistency with the existing build logic.

This update clears the only open technical question from the initial review. The series is now one step closer to being ready for integration, assuming no further issues surface. If you care about Windows CI or the ongoing Rustification effort, this is a small but essential piece of the puzzle.
