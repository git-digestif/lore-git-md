This is the first patch in the v4 series that defers auto maintenance until sequencer completion. The patch introduces `git_config_append_parameter()`, a helper function that formats a single `'key'='value'` pair for use in `GIT_CONFIG_PARAMETERS`, the environment variable Git uses to pass configuration to child processes. The function is reusable, handles `NULL` values (treating them as boolean `true`), and documents its format in the header comment. The existing `git_config_push_split_parameter()` is refactored to use the new helper, reducing code duplication.

Patrick Steinhardt’s review is surface-level, focusing on the commit message and documentation clarity. He approves the improved commit message but suggests a minor tweak to the header comment to avoid implying the helper is tied to `-c` command-line arguments, since later patches use it for other purposes. His proposed wording clarifies the function’s role in propagating configuration across Git processes and describes the format more generically. The feedback is uncontroversial and addresses a small but worthwhile documentation improvement.

The patch itself remains unchanged in functionality. It is a preparatory refactoring with no user-visible impact, laying the groundwork for the sequencer to disable auto maintenance during intermediate steps in the next patch. The implementation is clean and aligns with prior feedback on parameter naming and documentation. This patch is ready to proceed as soon as the header comment is updated.
