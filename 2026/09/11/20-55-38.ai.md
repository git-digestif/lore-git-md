The new `--matched-only` flag filters `git range-diff` output to show only commits present in both input ranges, omitting those that exist on only one side. This directly addresses the workflow pain point of reviewing rebases or range-diffs where users want to focus on how surviving commits changed, rather than seeing added or dropped commits. The implementation reuses the existing suppression logic for `--left-only` and `--right-only` by internally setting both flags when `--matched-only` is specified, avoiding code duplication.

The error handling now uses `die_for_incompatible_opt3()` for consistency with other Git commands.
