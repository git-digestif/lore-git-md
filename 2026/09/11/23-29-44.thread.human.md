This small patch series from Ravi Mistry makes `git blame` and `git annotate` automatically use `.git-blame-ignore-revs` (or `HEAD:.git-blame-ignore-revs` in bare repositories) as the default ignore-revs file when no explicit file is configured. The change aligns local Git behavior with hosting platforms like GitHub and GitLab, which already respect this file by default. The series is now in its sixth iteration and has been queued for the `next` branch after Junio Hamano’s approval.

The implementation is feature-complete and includes security hardening—rejecting NUL bytes, preventing promisor fetches in partial clones, and capping file size at 100MB—as well as careful handling of edge cases like subdirectory invocations, bare repositories, uncommitted working-tree changes, and symbolic links. The latest version (v6) addressed Junio’s polish-only feedback, replacing a "cute hack" with clearer code and removing an unused value. All prior technical objections have been resolved, including usability concerns raised by Phillip Wood about uncommitted changes and file size limits.

The series touches `builtin/blame.c`, `oidset.c`, and related documentation, but introduces no new symbols. It ensures user-configured ignore-revs files take precedence over the default, and empty configurations bypass the default entirely. Testing covers all major scenarios, including security checks and edge cases. With no open questions beyond a minor willingness to adjust the NUL-byte check in a follow-up, the patch is ready for integration.
