The `git blame` series that automatically uses `HEAD:.git-blame-ignore-revs` as the default ignore file when none is configured is now approved for integration into Junio’s `next` branch, but two usability and robustness concerns remain open. The series, now at v3, addresses all prior maintainer feedback—including a mechanical cleanup to avoid the global `the_repository` variable—and aligns local behavior with GitHub and GitLab conventions.

Phillip Wood’s latest review raises two practical issues. First, the current implementation ignores uncommitted changes to `.git-blame-ignore-revs` in non-bare repositories, always reading the committed `HEAD` blob instead. This differs from `.gitattributes` behavior and may frustrate users who expect to test local edits immediately. Second, the `oidset` parser lacks an explicit size limit, leaving a theoretical risk of memory exhaustion from maliciously large ignore-revs files, though the 32-bit entry count in `khash` makes this unlikely in practice. Neither issue blocks Junio’s approval, but they could lead to follow-up patches if users encounter friction. The author has signaled willingness to adjust the series based on Junio’s final guidance, particularly around the optional NUL-byte check and these usability refinements.
