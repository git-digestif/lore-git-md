This thread is about a small but useful feature for `git blame`: making it automatically use `.git-blame-ignore-revs` (or `HEAD:.git-blame-ignore-revs` in bare repositories) as the default ignore-revs file when no explicit file is configured. The goal is to align Git's local behavior with hosting platforms like GitHub and GitLab, which already respect this file by default. The series, now at version 6, was authored by Ravi Mistry and has been through several iterations to address feedback.

The feature is effectively complete and has received maintainer approval. Junio C Hamano explicitly endorsed the v6 design, calling it "very cleanly done" and praising the removal of a "cute hack" in favor of clearer code. The series is now queued for `next`, meaning it will likely graduate to `master` in the next release cycle unless last-minute objections arise. Key improvements in v6 include better code clarity, security hardening (NUL-byte rejection, promisor fetch prevention, and a 100MB size cap), and edge-case handling (subdirectory invocations, bare repositories, uncommitted working-tree changes, and CLI/config overrides).

The only remaining loose end is a minor detail about the NUL-byte check, which the author is willing to adjust in a follow-up if needed. Otherwise, all feedback has been addressed, and the patch is ready for integration. Reviewers like Phillip Wood and Kristoffer Haugsbakk raised practical concerns earlier in the thread, but these have been resolved, and the series is now uncontroversial. Expect this feature to land in the next Git release.
