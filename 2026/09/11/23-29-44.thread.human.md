This thread introduces a practical improvement to `git blame`: it will now automatically look for and use a `.git-blame-ignore-revs` file in the repository root if no explicit ignore file is configured, aligning local behavior with what web interfaces like GitHub and GitLab already do by default. The change is motivated by user surprise when local blame output differs from web views, a discrepancy that has become more common as the ignore-file convention has spread across the ecosystem.

Ravi Mistry’s patch is careful about both security and precedence. It anchors the default file lookup to the working tree root, rejects symlinks and non-regular files via `lstat()`, and ensures user-configured ignore files always take precedence. The implementation handles edge cases—empty files, comments, whitespace—gracefully and includes thorough test coverage for subdirectory invocations, bare repositories, and CLI/config overrides. Documentation updates clarify the new behavior and how to override it.

The patch is self-contained, touching only the blame subsystem, its documentation, and tests. It doesn’t introduce new user-facing options; it simply makes an existing feature more convenient by removing the need for manual configuration. The commit message explains both the original design rationale (avoiding unrequested filesystem I/O) and why the ecosystem shift now justifies a default.
