This thread is about a proposed change to make `git blame` and `git annotate` automatically use `HEAD:.git-blame-ignore-revs` as the default ignore-revs file when no explicit file is configured. The goal is to align Git's local behavior with hosting platforms like GitHub and GitLab, which already respect this file by default.

The author, Ravi Mistry, has revised the patch series to version 2, addressing maintainer feedback by splitting the work into two commits: one for security hardening of the ignore-revs parser and tag-peeling logic, and another for implementing the default file lookup. The security improvements include rejecting malformed input (like embedded NUL bytes) and preventing promisor fetches in partial clones, ensuring the parser is robust before exposing it to upstream-controlled content. Junio Hamano, the maintainer, has accepted the design direction but remains cautious about the necessity of some security refinements, particularly the NUL-byte rejection.

The patch is now feature-complete and under review, with no new technical objections raised. However, the security hardening needs validation from security-interested contributors like Jeff King or brian m. carlson before integration. Junio’s latest feedback was procedural, suggesting a minor reorganization of the patch structure rather than raising functional concerns. The implementation handles edge cases like subdirectory invocations, bare repositories, and committed symlinks, and ensures user-configured files take precedence over the default blob. The thread is now awaiting broader community review, particularly on the security aspects.
