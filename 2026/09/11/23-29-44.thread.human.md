This thread is about a proposed change to `git blame` to automatically use a `.git-blame-ignore-revs` file if no ignore file is explicitly configured, aligning local behavior with web interfaces like GitHub and GitLab. The patch, originally submitted by Ravi Mistry, initially used the working tree version of the file but ran into substantive feedback from Junio C Hamano.

Junio raised two key issues: a behavioral inconsistency with hosting sites (which use the `HEAD` version of the file, not the working tree version) and a security concern about parsing upstream-controlled content at a fixed path. Ravi has now revised the approach to use `HEAD:.git-blame-ignore-revs` instead, addressing both concerns. He also proposes two security-focused refinements to the ignore-file parser: rejecting lines with embedded NUL bytes and preventing lazy promisor fetches in partial clones. These changes directly respond to Junio’s call for a security audit of the parser.

The patch touches `builtin/blame.c` and `oidset.c`, hardening the existing ignore-file logic without introducing new symbols. The thread is now awaiting a revised patch submission, which will need to demonstrate the security improvements before the feature can proceed. The only remaining open question is how to handle untracked `.git-blame-ignore-revs` files (e.g., local developer overrides) if the default switches to `HEAD`, though this was not addressed in Ravi’s latest response.
