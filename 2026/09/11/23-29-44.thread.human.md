This thread is about a small but useful feature for `git blame`: making it automatically use `.git-blame-ignore-revs` (or `HEAD:.git-blame-ignore-revs` in bare repositories) as the default ignore-revs file when none is explicitly configured. The goal is to align Git's local behavior with hosting platforms like GitHub and GitLab, which already respect this file by default. The series is now in its fifth iteration (v5) and consists of two patches.

The first patch hardens the ignore-revs parser with security measures: it rejects malformed input (like NUL bytes), prevents promisor fetches in partial clones, and enforces a 100MB size cap to avoid memory exhaustion. The second patch implements the default file lookup, reading the working-tree file in non-bare repositories (matching `.mailmap` behavior) and falling back to `HEAD:.git-blame-ignore-revs` in bare repositories. This makes it easy to test uncommitted changes without requiring commits. The series has been approved by Junio Hamano, the project maintainer, and is queued for the `next` branch, meaning it’s on track for inclusion in the next Git release.

Key participants include Ravi Mistry (the author), who addressed all feedback in v5, and Junio, who explicitly approved the series and praised its design choices, such as reading the working-tree file in non-bare repositories. Phillip Wood provided substantive technical feedback on earlier versions, highlighting usability concerns that are now resolved. The only remaining loose end is a minor code clarity issue raised by Junio in the latest email, which Ravi has agreed to address in a follow-up patch. No open technical objections or security concerns remain.
