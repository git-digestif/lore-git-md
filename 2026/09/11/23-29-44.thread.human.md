This thread is about a proposed change to make `git blame` automatically use `HEAD:.git-blame-ignore-revs` as the default ignore-revs file when none is explicitly configured, aligning Git's behavior with platforms like GitHub and GitLab. The author, Ravi Mistry, has revised the patch series to version 2 after maintainer Junio C Hamano raised security concerns about the initial implementation.

The v2 series is now split into two commits: the first hardens the ignore-revs parser and tag-peeling logic to reject malformed input (like embedded NUL bytes) and prevent unintended network requests in partial clones, while the second implements the default file lookup. Junio's feedback on the security hardening was mixed—he agreed with preventing promisor fetches but questioned whether rejecting entire files with NUL bytes might be overly aggressive, as the existing parser already fails safely on malformed object names. The hardening is necessary before exposing the parser to upstream-controlled content in the default file, so broader review from security-interested contributors like Jeff King or brian m. carlson is still needed before integration.

The technical changes are well-scoped, touching `builtin/blame.c` and related files to add NUL byte rejection and promisor fetch prevention, with thorough test coverage. The design direction is settled, and the series is feature-complete, but the security refinements remain under community review. No other reviewers have weighed in yet, and the patch is not ready for merging until the security audit is complete. The thread is now focused on validating these hardening measures.
