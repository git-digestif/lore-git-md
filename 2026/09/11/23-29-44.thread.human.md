This thread is about a patch series that makes `git blame` and `git annotate` automatically use `HEAD:.git-blame-ignore-revs` as the default ignore-revs file when no explicit file is configured. The goal is to align local Git behavior with hosting platforms like GitHub and GitLab, which already respect this file by default. The series is now in its third version (v3), posted by Ravi Mistry, and addresses all maintainer feedback from earlier iterations.

The series consists of two patches: one that hardens the ignore-revs parser and tag-peeling logic (rejecting malformed input and preventing promisor fetches in partial clones), and another that implements the default file lookup. Junio C Hamano, the maintainer, has reviewed the v3 series and confirmed that the requested cleanup (replacing the global `the_repository` variable) has been addressed. He now considers the series technically sound and plans to mark it ready for the `next` integration branch unless objections arise in the next few days. The only remaining procedural decision is whether to retain or drop the optional NUL-byte check, which Junio has questioned but not demanded be removed.

The patch is feature-complete, well-tested, and aligns with hosting platform conventions. No new technical objections or security concerns have been raised since v3 was posted. The author has signaled flexibility on the NUL-byte check and is awaiting Junio’s final decision. The series is effectively approved for integration pending that decision and any last-minute community feedback. Key contributors like Phillip Wood and Kristoffer Haugsbakk provided substantive design feedback in earlier iterations, while Eric Sunshine’s input was limited to minor style fixups. Security-interested reviewers like Jeff King and brian m. carlson have not yet weighed in on the hardening, though the urgency for their review has diminished.
