This thread is about a patch series that makes `git blame` automatically use `HEAD:.git-blame-ignore-revs` as the default ignore-revs file when none is explicitly configured. The goal is to align Git's behavior with hosting platforms like GitHub and GitLab, which already respect this file by default. The series is now in its second version, addressing maintainer feedback by splitting the work into two commits: one for security hardening of the ignore-revs parser and tag-peeling logic, and another for implementing the default file lookup.

The design direction is settled, with Junio Hamano (the maintainer) approving the use of `HEAD:.git-blame-ignore-revs` and describing the code as "OK," "Good," and "Very clean." However, he raised a procedural concern about patch organization, specifically that a refactoring helper (`parse_oidset_line()`) should be moved from the second patch to the first. The author, Ravi Mistry, has agreed to make this change in the next revision. The security hardening—particularly the rejection of malformed input (like embedded NUL bytes) and the prevention of promisor fetches in partial clones—remains under scrutiny, though the author has clarified that the NUL-byte check is more about consistency than security and is willing to drop it if Junio prefers. The promisor fetch prevention, meanwhile, is uncontroversial.

The series is feature-complete and has no major technical blockers, but it is not yet ready for integration. The hardening must still undergo broader review, especially from security-interested contributors like Jeff King or brian m. carlson. The author has also acknowledged contributions from Phillip Wood and Kristoffer Haugsbakk in earlier iterations, while Eric Sunshine’s feedback was limited to minor stylistic fixes. A minor revision (v3) is likely to address Junio’s patch organization feedback, but the changes will be cosmetic and won’t affect the core functionality.
