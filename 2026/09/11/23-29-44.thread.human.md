This thread is about a patch series (v3) by Ravi Mistry that makes `git blame` and `git annotate` automatically use `HEAD:.git-blame-ignore-revs` as the default ignore-revs file when no explicit file is configured. This aligns Git's behavior with hosting platforms like GitHub and GitLab, which already respect this file by default.

The series has been approved by Junio C Hamano for integration into the `next` branch, pending final decisions on two minor refinements: whether to retain an optional NUL-byte check in the ignore-revs parser and how to handle uncommitted changes to the `.git-blame-ignore-revs` file. The author has addressed all prior feedback, including a mechanical cleanup to avoid referencing the global `the_repository` variable. The series is feature-complete, well-tested, and includes security hardening to prevent promisor fetches in partial clones and reject malformed input.

Phillip Wood raised two usability concerns in his review: the current implementation ignores uncommitted changes to `.git-blame-ignore-revs` (inconsistent with `.gitattributes` behavior), and the lack of an explicit size limit in the `oidset` parser could theoretically allow memory exhaustion from maliciously large blobs. Ravi responded that the uncommitted changes behavior was a deliberate choice based on Junio’s earlier feedback, but he remains flexible on both points. The next step is Junio’s final decision on whether to adjust the behavior to match Phillip’s suggestions before merging the series into `next`. No new technical objections have been raised.
