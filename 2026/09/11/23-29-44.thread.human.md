This thread is about a patch series (v3) by Ravi Mistry that makes `git blame` automatically use `HEAD:.git-blame-ignore-revs` as the default ignore-revs file when no explicit file is configured. The feature aligns Git's behavior with hosting platforms like GitHub and GitLab, which already respect this file by default. The series includes security hardening for the ignore-revs parser and tag-peeling logic, and it was approved by Junio Hamano for integration into the `next` branch, pending a final decision on an optional NUL-byte check.

The latest development is a substantive review from Phillip Wood, who raises three usability and edge-case concerns. First, he questions why the patch ignores uncommitted changes to `.git-blame-ignore-revs` in non-bare repositories, arguing this is inconsistent with how Git handles other special files like `.gitattributes`. Second, he briefly considers but dismisses support for `.git-blame-ignore-revs` files in subdirectories due to implementation complexity. Third, he notes a theoretical scalability concern with the `oidset` implementation, though this is unlikely to be a practical issue. None of these points challenge the core functionality or security hardening, and the author has already indicated flexibility to adjust the implementation if needed.

The series remains approved for integration, with the only unresolved procedural decision being Junio's preference on the NUL-byte check. The thread is otherwise feature-complete, well-tested, and aligned with hosting platform conventions. No new technical objections or security concerns have been raised since v3 was posted.
