This thread introduces a small but user-visible change to `git blame` and `git annotate`: when no ignore-revs file is explicitly configured, Git will now automatically use `HEAD:.git-blame-ignore-revs` as the default, matching the behavior already implemented by GitHub and GitLab. The feature has evolved through four iterations, with the latest (v4) addressing all prior feedback, including a new 100MB size cap on the ignore-revs blob to prevent memory exhaustion from maliciously large files.

The series is now queued for the `next` branch after Junio C Hamano’s explicit approval. The core functionality—security hardening of the ignore-revs parser and the default file lookup—is complete and well-tested. Two minor loose ends remain: whether to retain a NUL-byte check in the parser (Junio hasn’t weighed in yet) and how to handle uncommitted changes to `.git-blame-ignore-revs`. The current implementation always reads the committed `HEAD` blob, ignoring working-tree changes, which Junio justifies as matching hosting platform behavior but Phillip Wood calls a user-experience regression. The author has signaled openness to revisiting this in a future update.

Key participants include Junio (maintainer, approving), Ravi Mistry (author, responsive to feedback), Phillip Wood (substantive reviewer, raised usability concerns), and Kristoffer Haugsbakk (design input in earlier rounds). The patch touches `blame.c`, the ignore-revs parser, and documentation, and is ready for integration unless Junio requests further tweaks.
