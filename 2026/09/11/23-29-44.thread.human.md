This thread is about a proposed change to `git blame` to automatically use a `.git-blame-ignore-revs` file if no explicit ignore file is configured, aligning local behavior with web interfaces like GitHub and GitLab. The original patch suggested using the working tree file, but after feedback from Junio C Hamano (the maintainer), the design was revised to use `HEAD:.git-blame-ignore-revs` instead, addressing consistency and security concerns.

The author, Ravi Mistry, has accepted this change and is preparing a v2 patch that includes security-focused refinements to the ignore-file parser, such as rejecting lines with embedded NUL bytes and preventing lazy promisor fetches in partial clones. The patch is still under review, and the next step is for Ravi to submit the revised implementation for broader community evaluation, particularly regarding security adequacy. Key open questions include how to handle untracked `.git-blame-ignore-revs` files (currently unaddressed) and ensuring the security improvements are sufficient.

Junio’s feedback was decisive in shaping the design, and while he expressed mild skepticism about the security refinements, he delegated the final audit to the broader community. The thread remains in the design phase, with no merge status implied. The v2 patch will determine whether the feature is ready for integration.
