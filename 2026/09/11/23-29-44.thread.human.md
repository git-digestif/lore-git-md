This thread is about a patch series (v2) by Ravi Mistry that makes `git blame` and `git annotate` automatically use `HEAD:.git-blame-ignore-revs` as the default ignore-revs file when no explicit file is configured. This aligns Git's behavior with hosting platforms like GitHub and GitLab, which already respect this file by default. The series has evolved significantly since its initial version, addressing maintainer feedback with security hardening (e.g., preventing promisor fetches in partial clones) and robust tag-peeling logic.

The current status is that the design direction is settled, with Junio Hamano (the maintainer) approving the use of `HEAD:.git-blame-ignore-revs`. The v2 series is feature-complete, with two patches: one hardening the ignore-revs parser and another implementing the default file lookup. Junio's feedback on v2 has been procedural (e.g., patch organization) and approving of the code itself. The only remaining decisions are whether to retain a NUL-byte check (a stylistic choice the author is willing to drop) and a minor cleanup to avoid referencing the global `the_repository` variable, which Junio flagged in the latest email. The patch is not yet ready for integration but is close, pending these final adjustments and broader community review of the hardening.

Key technical details include modifications to `builtin/blame.c` and `oidset.c`, with new logic to handle edge cases like subdirectory invocations, bare repositories, and malformed input. The security hardening ensures no network requests are triggered for missing tag targets in partial clones and verifies tag types before parsing. The default file lookup logic is sound, with user-configured files taking precedence over the default blob. The series includes comprehensive test coverage, including new tests for NUL bytes and partial-clone tag peeling.

The thread has seen substantive input from Junio, Phillip Wood, and Kristoffer Haugsbakk, while Eric Sunshine's contributions were limited to minor style fixes. Security-focused reviewers like Jeff King and brian m. carlson have not yet weighed in on the hardening, though the urgency for their review has diminished with the concession on NUL bytes. The patch is a standalone feature change with no dependencies on other in-flight efforts.
