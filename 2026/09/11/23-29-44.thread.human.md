This thread is about a patch series (v2) by Ravi Mistry that makes `git blame` automatically use `HEAD:.git-blame-ignore-revs` as the default ignore-revs file when none is explicitly configured, aligning Git’s behavior with platforms like GitHub and GitLab. The series has two patches: the first hardens the ignore-revs parser to reject malformed input (like NUL bytes) and prevent promisor fetches in partial clones, while the second implements the default file lookup. Junio Hamano, the maintainer, initially opposed the design but now approves the direction and code quality, though he suggests a minor refactoring tweak (moving a helper function to the first patch).

The series is under review, with no major technical objections, but the security hardening—particularly the NUL-byte rejection—still needs validation from security-focused contributors like Jeff King or brian m. carlson. Eric Sunshine’s recent email clarifies that his earlier feedback was purely stylistic and doesn’t affect the current version, so his `Helped-by:` attribution may no longer apply. The only open questions are procedural (patch organization) and whether the hardening is sufficient. The feature is feature-complete, but broader review is needed before integration.
