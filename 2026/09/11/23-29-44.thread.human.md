This thread is about a patch series that makes `git blame` automatically use `HEAD:.git-blame-ignore-revs` as the default ignore-revs file when no explicit file is configured. The goal is to align local behavior with hosting platforms like GitHub and GitLab, which already respect this file by default. The series is now in its third version (v3), posted by Ravi Mistry, and addresses all maintainer feedback from earlier iterations.

The key changes in v3 include security hardening for the ignore-revs parser and tag-peeling logic, such as rejecting malformed input (e.g., embedded NUL bytes) and preventing promisor fetches in partial clones. The series also implements the default file lookup using `HEAD:.git-blame-ignore-revs`, with user-configured files taking precedence. Junio Hamano, the maintainer, has approved the design direction and the code itself, though he has questioned the necessity of the NUL-byte check. Ravi has addressed all procedural feedback, including a mechanical cleanup to avoid referencing the global `the_repository` variable, and remains flexible about dropping the NUL-byte check if Junio prefers.

The patch is feature-complete and ready for integration, pending Junio’s final decision on the NUL-byte check and broader community validation of the security hardening. No new objections or technical blockers have been raised, though review from security-interested contributors (e.g., Jeff King, brian m. carlson) would help assess the completeness of the promisor fetch prevention and tag type verification logic. The series is a standalone change to the blame subsystem and does not depend on other in-flight efforts.
