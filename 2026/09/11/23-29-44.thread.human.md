This thread is about a patch series that makes `git blame` automatically use `HEAD:.git-blame-ignore-revs` as the default ignore-revs file when no explicit file is configured. The series, now at version 4, has been approved for integration by Junio C Hamano and is ready for the `next` branch.

The key changes in this version address all prior feedback, including a new 100MB size cap on the ignore-revs blob to prevent memory exhaustion from maliciously large files. The series consists of two patches: the first hardens the ignore-revs parser and tag-peeling logic to reject malformed input (like NUL bytes) and prevent promisor fetches in partial clones, while the second implements the default file lookup. The hardening is now feature-complete and aligns with hosting platform conventions (GitHub, GitLab).

Junio has endorsed the security improvements, particularly the size cap, and the series is well-tested. However, there’s an open user-experience trade-off: the current implementation always reads the committed `HEAD` blob, ignoring uncommitted changes to `.git-blame-ignore-revs` in non-bare repositories. Junio justifies this as matching hosting platform behavior, but Phillip Wood considers it a usability regression. The author, Ravi Mistry, has addressed all maintainer feedback and remains open to further adjustments if needed. No new technical objections have been raised since v4 was posted.
