This thread is about a patch series that makes `git blame` automatically use `HEAD:.git-blame-ignore-revs` as the default ignore-revs file when no explicit file is configured, aligning with how GitHub and GitLab already handle this. The series is now at version 4, with two patches: one hardening the ignore-revs parser (including a 100MB size cap to prevent memory exhaustion) and another implementing the default file lookup.

Junio C Hamano has approved the series for integration into the `next` branch, meaning it’s on track for the next release. All prior feedback has been addressed, including a cleanup of the `the_repository` global variable and the addition of the 100MB size cap. The only remaining discussion point is whether the feature should read the committed `HEAD` blob (matching hosting platforms) or the working-tree file (which feels more intuitive to users). Junio has now explicitly rejected the "match hosting platforms" justification and prefers reading the working-tree file in non-bare repositories, calling it "more ergonomic." This is a clear direction for the next revision, though it doesn’t block the current series from moving forward.

The patches touch `builtin/blame.c`, `oidset.c`, and related documentation, with security refinements like NUL-byte rejection, promisor fetch prevention, and the 100MB size cap. The default file lookup is intentionally limited to the repository root for performance reasons, and user-configured ignore files take precedence over the default. Phillip Wood raised usability concerns about ignoring uncommitted changes, but Junio’s latest feedback resolves this in favor of the working-tree file. The series is feature-complete and well-tested, with no outstanding technical objections.
