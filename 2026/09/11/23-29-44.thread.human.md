This thread proposes making `git blame` automatically use a `.git-blame-ignore-revs` file if no ignore file is explicitly configured, aligning local behavior with GitHub and GitLab. The patch, submitted by Ravi Mistry, has been under review with no feedback until now.

Junio C Hamano has raised two significant concerns. First, the patch currently uses the working tree version of `.git-blame-ignore-revs`, which may differ from the committed version (`HEAD:.git-blame-ignore-revs`). Since hosting sites use the committed version, this could still lead to inconsistent blame output. Junio suggests defaulting to the `HEAD` blob instead, ensuring consistency regardless of working tree state. Second, he highlights a new security risk: the ignore-file parser will now process upstream-controlled content at a fixed path, whereas previously it only read user-configured files. While the patch includes `lstat()` checks to reject symlinks and non-regular files, Junio argues these precautions are unnecessary if the default switches to the `HEAD` blob, which avoids working tree access entirely. He calls for a security audit of the parser to ensure it cannot be exploited via malformed input.

The author will need to address these concerns, either by revising the approach to use the `HEAD` blob or by justifying why the working tree version is preferable. The patch remains under review, and no other feedback has been recorded yet.
