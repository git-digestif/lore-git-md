This thread introduces a small but useful quality-of-life improvement for `git blame`: when no ignore-revs file is explicitly configured, Git will now automatically look for `.git-blame-ignore-revs` in the working tree (or `HEAD:.git-blame-ignore-revs` in bare repositories) and use it as the default ignore list. This aligns local behavior with GitHub and GitLab, which already respect this file by convention, and makes it easier to test uncommitted ignore lists without requiring commits.

The series has been through five iterations, with the latest version addressing all prior feedback. Junio Hamano, the maintainer, has explicitly approved the change and queued it for the `next` branch, signaling it is on track for the next release. The implementation is careful: it reads the working-tree file in non-bare repositories (matching `.mailmap` behavior), skips symlinks and non-regular files, enforces a 100MB size cap to prevent memory exhaustion, and ensures user-configured ignore files take precedence. The only minor loose end is whether to retain a NUL-byte check in the parser, but the author has indicated willingness to adjust this in a follow-up if needed.

Key participants include Ravi Mistry (the author), Junio Hamano (who approved the series), and Phillip Wood (who provided substantive usability feedback that shaped the final design). The patch is feature-complete, well-tested, and touches only the blame subsystem, making it a low-risk addition that improves ergonomics without introducing complexity.
