This thread is about a small but useful feature for `git blame`: making it automatically use `.git-blame-ignore-revs` (or `HEAD:.git-blame-ignore-revs` in bare repositories) as the default ignore-revs file when no explicit file is configured. This aligns Git's behavior with hosting platforms like GitHub and GitLab, which already respect this file by default. The series, now at version 6, is authored by Ravi Mistry and has been through several iterations to address feedback.

The implementation is feature-complete and well-tested, with security hardening (NUL-byte rejection, promisor fetch prevention, and a 100MB size cap) and thorough edge-case handling (subdirectory invocations, bare repositories, uncommitted working-tree changes, and more). Junio C Hamano, the maintainer, has approved the series for integration into the `next` branch, calling the latest version "very cleanly done." The only remaining loose end is a minor detail about the NUL-byte check, which the author is willing to adjust in a follow-up if needed.

Phillip Wood, a key reviewer, raised a small technical point in the latest email about a redundant `lstat()` call, but this is a low-impact observation and doesn’t challenge the core functionality. The series is on track to appear in the next "What's cooking" report as ready for `next`, with no open technical objections or security concerns.
