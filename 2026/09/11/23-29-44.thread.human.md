This thread is about a small but useful feature addition to `git blame` and `git annotate`: making them automatically use `.git-blame-ignore-revs` (or `HEAD:.git-blame-ignore-revs` in bare repositories) as the default ignore-revs file when no explicit file is configured. The goal is to align local Git behavior with hosting platforms like GitHub and GitLab, which already respect this file by default.

The series, now at version 5, is feature-complete and has been approved by Junio C Hamano for integration into the `next` branch. The key change in this version is that it now reads the working-tree file (`.git-blame-ignore-revs`) in non-bare repositories, matching the behavior of `.mailmap` and `.gitattributes`. This makes it easier to test uncommitted changes without requiring commits, addressing a usability concern raised by Phillip Wood. The implementation is careful about security, with a 100MB size cap, NUL-byte rejection, and protections against promisor fetches in partial clones. It also handles edge cases like bare repositories, subdirectory invocations, and malformed input gracefully.

The patch has seen thorough review, with substantive feedback from Phillip Wood and design input from Kristoffer Haugsbakk, both of which have been incorporated. Junio’s explicit approval and the resolution of all prior feedback mean this is now a straightforward integration, with no remaining technical objections. The only minor loose end is whether to retain the NUL-byte check, but the author has signaled flexibility to adjust this in a follow-up if needed. The series is well-tested and aligns with both hosting platform conventions and local workflow ergonomics.
