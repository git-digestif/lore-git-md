This thread is about a patch series that makes `git blame` automatically use `.git-blame-ignore-revs` (or `HEAD:.git-blame-ignore-revs` in bare repositories) as the default ignore-revs file when no explicit file is configured. The goal is to align Git's local behavior with hosting platforms like GitHub and GitLab, which already respect this file by default. The series is now in its sixth iteration (v6), addressing only minor code clarity improvements after Junio C Hamano, the maintainer, approved the v4 version for integration into the `next` branch.

The key changes in v6 replace a "cute hack" in the code with a clearer implementation, using `.util = (void *)1` and an explanatory comment to trigger the default file lookup. This revision preserves all prior functionality, including security hardening (NUL-byte rejection, promisor fetch prevention, and a 100MB size cap), edge-case handling (bare repositories, subdirectory invocations, committed symlinks), and precedence rules (the default file is processed before user-configured files). The series also includes a `the_repository` cleanup and now reads the working-tree file in non-bare repositories, matching the behavior of `.mailmap`.

The patch has received substantive technical reviews from Phillip Wood, who raised usability concerns about uncommitted changes and the lack of a size limit in earlier versions, both of which have been addressed. Junio's feedback has been fully incorporated, and the series is feature-complete with no remaining technical objections. The only minor loose end is the NUL-byte check, which the author has offered to adjust in a follow-up if requested. The patch is ready for integration and is expected to graduate to `master` soon.
