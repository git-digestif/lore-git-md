This thread is about a patch to make `git blame` automatically use a `.git-blame-ignore-revs` file if no ignore file is explicitly configured, aligning local behavior with web interfaces like GitHub and GitLab. The initial implementation proposed using the working tree file, but Junio C Hamano, the maintainer, objected due to behavioral inconsistency and security concerns, instead proposing that the file be read from `HEAD:.git-blame-ignore-revs`. The author, Ravi Mistry, has accepted this design change and is preparing a v2 patch with additional security refinements to the ignore-file parser, including rejecting lines with embedded NUL bytes and preventing lazy promisor fetches in partial clones.

The current status is that the design direction is resolved, but the patch is not yet ready for integration. The v2 patch must demonstrate the proposed security improvements before further review. Two open questions remain: how to handle untracked `.git-blame-ignore-revs` files (e.g., local developer overrides) and whether the security refinements are sufficient. Junio’s latest reply clarifies that his earlier feedback was meant to delegate the security audit to others, not to endorse a specific plan. He remains cautiously optimistic but emphasizes that the community will ultimately decide whether the security improvements are adequate. The next step is for Ravi to submit the v2 patch for broader review.
