This is the **third and final patch** in a bugfix series targeting resource cleanup in Git’s low-level merge driver infrastructure. The patch replaces custom signal handling with Git’s `tempfile` API to ensure temporary files (`.merge_file_*`) are reliably deleted even when the merge process is interrupted by SIGINT/SIGQUIT (e.g., via Ctrl+C). This completes the series’ core goal: atomic, signal-safe cleanup without functional behavior changes.

The patch modifies `merge-ll.c` to use `xmks_tempfile()` for creating temporary files, `close_tempfile_gently()` for error-checked cleanup, and `delete_tempfile()` for explicit removal. A helper function, `temp_path_basename()`, extracts relative paths from the absolute paths returned by the `tempfile` API to maintain backward compatibility with user-configured merge drivers (e.g., those using shell metacharacters in their command templates). The commit message acknowledges a trade-off: while shell-quoting the paths would be more robust, it risks breaking existing configurations, so the patch opts for the conservative approach.

Jeff King (Peff) authored this iteration, incorporating feedback from Michal Koutný (the original reporter) and addressing edge cases like `close()` error handling and const-correctness. The patch is well-motivated, with clear commit messages and no substantive objections remaining. It aligns with Git’s established patterns for resource management and modern code idioms (e.g., `strbuf` for file I/O). The only minor limitation is the lack of automated test coverage for interrupt scenarios, though Michal’s manual testing confirms the fix works for SIGINT.

This patch is uncontroversial and ready for review. It touches only `merge-ll.c` and introduces no new dependencies or behavioral regressions.
