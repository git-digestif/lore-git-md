This is the third patch in the v6 series adding path-related keys to `git repo info`. It introduces `path.hooks.absolute` and `path.hooks.relative` to expose the repository’s hooks directory in a scriptable format, respecting the `core.hooksPath` configuration.

The implementation uses `repo_git_path_replace()` to resolve the hooks path, then formats it as either an absolute or relative path using the existing `format_path()` helper. The patch documents that `/dev/null` is returned verbatim when `core.hooksPath` is set to that value, aligning with `git rev-parse --git-path hooks` behavior. Tests cover standard hooks paths, custom `core.hooksPath` overrides, and the `/dev/null` edge case (skipped on Windows due to path canonicalization differences).

The patch is mechanically clean and well-tested, with no unresolved feedback. The unconditional path-return behavior (even in bare repositories or when the directory does not exist) matches the series’ design and has been endorsed by Junio. This is a straightforward, uncontroversial addition that fits neatly into the larger feature. Reviewers should focus on the test coverage for `/dev/null` handling and the clarity of the documentation.
