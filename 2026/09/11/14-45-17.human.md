This is the fifth patch in the v6 series adding new path-related keys to `git repo info`. It introduces `path.grafts.absolute` and `path.grafts.relative`, exposing the location of the repository’s grafts file in a scriptable format.

The patch is straightforward and well-executed. It uses `repo_get_graft_file()` to resolve the grafts file path, respecting the `GIT_GRAFT_FILE` environment variable, and formats the result as either an absolute or relative path. The implementation mirrors the pattern established by earlier patches in the series (e.g., `path.index` and `path.hooks`), returning the path unconditionally even if the file does not exist. This aligns with the series’ design and `git rev-parse --git-path` precedent, as previously endorsed by Junio C Hamano.

Documentation is clear and concise, explaining the behavior and environment variable override. The test coverage is minimal but sufficient, verifying the standard grafts path and a `GIT_GRAFT_FILE` override. Edge cases like bare repositories are implicitly covered by the unconditional path-return behavior, which the series has already established as intentional.

This patch is mechanically sound and uncontroversial. It fits neatly into the series’ goal of exposing repository paths without requiring direct access to Git’s internals. No unresolved feedback remains, and the implementation is consistent with the rest of the series.
