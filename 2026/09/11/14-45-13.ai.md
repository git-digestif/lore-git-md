This is the first patch in the v6 series adding path-related keys to `git repo info`. It introduces `path.toplevel.absolute` and `path.toplevel.relative`, which expose the repository’s top-level working tree directory in a scriptable format. The implementation is straightforward: it uses `repo_get_work_tree()` to fetch the path and `format_path()` to handle absolute vs. relative formatting. In bare repositories, both keys return an empty string, matching the documented behavior.

The patch touches `builtin/repo.c` (adding the new keys and their getter functions), `Documentation/git-repo.adoc` (documenting the new keys), and `t/t1900-repo-info.sh` (adding tests for both normal and bare repositories). The tests cover edge cases like subdirectory execution and verify that the output matches `test-tool path-utils real_path` for absolute paths and expected relative paths (e.g., `../` from a subdirectory).

This is a clean, well-scoped addition with no known issues. The commit message clearly explains the motivation (replacing ad-hoc `git rev-parse --show-toplevel` usage) and the design (empty string in bare repositories). The implementation aligns with the series’ established pattern of using `format_path()` for suffix-based formatting and respects the repository’s working directory.
