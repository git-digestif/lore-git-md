Subject: [PATCH v3 0/2] blame: default to HEAD:.git-blame-ignore-revs if no ignore file configured
Series version: v4 (2 patches)
Originating author: Ravi Mistry (via GitGitGadget)
Thread type: feature patch series

Core problem or goal
Make `git blame` and `git annotate` automatically use `HEAD:.git-blame-ignore-revs` as the default ignore-revs file when no explicit ignore file is configured, aligning local behavior with hosting platforms (GitHub, GitLab) that already respect this file by default. The v4 revision addresses all prior feedback, including a new **100MB size cap** on the ignore-revs blob to prevent memory exhaustion from maliciously large files. The series remains feature-complete: (1) security hardening of the ignore-revs parser and tag-peeling logic (rejecting malformed input, preventing promisor fetches in partial clones, and enforcing the size cap), and (2) implementation of the default file lookup. The hardening now includes the size cap, which Junio previously endorsed as a "sensible thing to worry about."

Current status
**Approved for integration** and marked ready for the `next` branch by Junio C Hamano. The `the_repository` cleanup requested in v2 and the **100MB size cap** requested in v3 have both been addressed. No new technical objections or security concerns have been raised since v4 was posted. The uncommitted changes handling (always reading the committed `HEAD` blob) remains a **user-experience trade-off** rather than a technical blocker; Junio justifies this as matching hosting platform behavior but concedes that consulting the working-tree file "feels more intuitive." The series is feature-complete, well-tested, and aligns with hosting platform conventions.

Key technical details
- Files touched: `builtin/blame.c`, `oidset.c`, `oidset.h`, `Documentation/blame-options.adoc`, `Documentation/config/blame.adoc`, `t/t8013-blame-ignore-revs.sh`
- **Security refinements (patch 1/2)**:
  - **NUL byte rejection**: `oidset_parse_file_carefully()` uses `memchr()` to scan the entire line for NUL bytes, rejecting any line containing them. This remains optional but is retained in v4.
  - **Promisor fetch prevention**: `peel_to_commit_oid()` uses `odb_read_object_info_extended()` with `OBJECT_INFO_SKIP_FETCH_OBJECT` and `OBJECT_INFO_QUICK`, ensuring missing tag targets in partial clones do not trigger network requests. The function also verifies each tag’s declared type before parsing to prevent type confusion.
  - **Size cap**: A new **100MB limit** (`IGNORE_REVS_MAX_FILE_SIZE`) is enforced via `odb_read_object_info()` before loading the blob, preventing memory exhaustion from maliciously large blobs. The check is performed before I/O, avoiding unnecessary work. The limit matches Git’s existing `ATTR_MAX_FILE_SIZE` for `.gitattributes`.
- **Default file lookup (patch 2/2)**:
  - **Resolution**: Uses `get_oid_with_context()` to resolve `HEAD:.git-blame-ignore-revs` and `S_ISREG()` to skip non-regular tree entries (e.g., symlinks, subdirectories).
  - **Precedence**: The default blob is added to the ignore-revs list before any user-configured files, ensuring user overrides take precedence. Empty entries in `blame.ignoreRevsFile` or `--ignore-revs-file ""` bypass the default blob entirely.
  - **In-memory parsing**: Introduces `oidset_parse_buffer_carefully()` to parse the blob’s contents, sharing line-parsing logic with the existing file-based parser (`parse_oidset_line()`).
  - **Edge cases**: Handles subdirectory invocations, bare repositories, uncommitted working-tree changes, committed symlinks, malformed input (e.g., invalid OIDs, NUL bytes), and CLI/config overrides. The current implementation ignores uncommitted changes to `.git-blame-ignore-revs` in non-bare repositories, always reading the committed `HEAD` blob. Junio justifies this as matching hosting platform behavior but acknowledges that consulting the working-tree file "feels more intuitive." Phillip Wood considers this a **user-experience regression**.
  - **Subdirectory support**: The lookup is intentionally limited to the repository root, aligning with hosting platform conventions and avoiding the performance cost of scanning all directories.
  - **Scalability**: The `oidset` implementation (using `khash`) uses 32-bit integers for entry counts, but the new size cap ensures the ignore-revs file cannot exceed 100MB. The parser filters out non-commit OIDs and duplicates, so the set cannot grow larger than the number of local commits.
- Symbols: No new symbols; modifies existing blame logic (`peel_to_commit_oid()`) and ignore-file parser (`oidset_parse_file_carefully()`) to include security hardening and default file lookup. The `the_repository` cleanup replaces the global variable with `sb->repo` in `parse_default_ignore_revs_blob()`.

Open questions and loose ends
1. **Uncommitted changes handling**: The current implementation always reads the committed `HEAD` blob, ignoring uncommitted changes to `.git-blame-ignore-revs` in non-bare repositories. Junio justifies this as matching hosting platform behavior but concedes that consulting the working-tree file "feels more intuitive." Phillip Wood considers this a **user-experience regression** and inconsistency with `.gitattributes`. No explicit request for change has been made, but the door remains open for adjustment in a future revision.
2. **NUL-byte check retention**: The NUL-byte check remains in v4, but Junio has not yet weighed in on whether to retain or drop it. The author has signaled flexibility and will adjust in the next revision if Junio requests it.
