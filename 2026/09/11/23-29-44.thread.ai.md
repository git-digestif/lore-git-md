Subject: [PATCH v2 0/2] blame: default to HEAD:.git-blame-ignore-revs if no ignore file configured

Originating author: Ravi Mistry (via GitGitGadget)
Thread type: feature patch series

Core problem or goal
Make `git blame` and `git annotate` automatically use `HEAD:.git-blame-ignore-revs` as the default ignore-revs file when no explicit ignore file is configured, aligning local behavior with hosting platforms (GitHub, GitLab) that already respect this file by default. The v2 revision addresses maintainer feedback by hardening the ignore-revs parser and tag-peeling logic to reject malformed input (embedded NUL bytes) and prevent promisor fetches in partial clones, ensuring the parser is robust before exposing it to upstream-controlled content. The NUL-byte rejection has since been acknowledged as **not a security requirement** but a stylistic choice for consistency with other trailing-garbage handling; the author has offered to drop it if Junio prefers.

Current status
Under review; design direction resolved in favor of Junio’s proposal to use `HEAD:.git-blame-ignore-revs`. The v2 series is feature-complete with both commits posted: (1) **security hardening of the ignore-revs parser and tag-peeling logic**, and (2) **implementation of the default file lookup**. Junio’s feedback remains **procedural** (patch organization, NUL-byte check, and now a `the_repository` cleanup nit) and **approving** of the code itself ("OK", "Good", "Very clean"). Key technical details
- Files touched: `builtin/blame.c`, `oidset.c`, `Documentation/git-blame.txt`, `t/t8013-blame-ignore-revs.sh`
- **Security refinements (patch 1/2)**:
  - **NUL byte rejection (optional)**: `oidset_parse_file_carefully()` uses `memchr()` to scan the entire line for NUL bytes, rejecting any line containing them. This was added for **consistency** with other trailing-garbage handling but is **not a security requirement**; the author has offered to drop it if Junio prefers.
  - **Promisor fetch prevention**: `peel_to_commit_oid()` uses `odb_read_object_info_extended()` with `OBJECT_INFO_SKIP_FETCH_OBJECT` and `OBJECT_INFO_QUICK`, ensuring missing tag targets in partial clones do not trigger network requests. The function also verifies each tag’s declared type before parsing to prevent type confusion. Junio agrees this change is reasonable and uncontroversial.
- **Default file lookup (patch 2/2)**: `git blame` checks for `HEAD:.git-blame-ignore-revs` (via `get_oid_with_context()`) if no ignore file is explicitly configured. Non-regular tree entries (e.g., committed symlinks) are skipped using `S_ISREG()`. The default blob is added to the ignore-revs list **before** any user-configured files, ensuring user overrides take precedence. The patch includes a refactoring of `oidset_parse_file_carefully()` to extract a helper function (`parse_oidset_line()`), which the author has agreed to move to patch 1/2 for logical consistency. Junio’s latest feedback identifies a **technical debt opportunity**: the new `parse_default_ignore_revs_blob()` function unnecessarily references the global `the_repository` variable even though the `blame_scoreboard` struct already holds a repository pointer (`sb->repo`). Replacing `the_repository` with `sb->repo` would align with the ongoing `the_repository` removal effort.
- Edge cases handled: subdirectory invocations, bare repositories, empty files, comments, whitespace, committed symlinks, CLI/config overrides (`blame.ignoreRevsFile=""` or `--no-ignore-revs-file` bypasses the default blob), and malformed input.
- Symbols: No new symbols; modifies existing blame logic (`peel_to_commit_oid()`) and ignore-file parser (`oidset_parse_file_carefully()`) to include security hardening and default file lookup.
