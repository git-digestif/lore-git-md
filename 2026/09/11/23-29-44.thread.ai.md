Subject: [PATCH v3 0/2] blame: default to HEAD:.git-blame-ignore-revs if no ignore file configured
Series version: v6 (2 patches)
Originating author: Ravi Mistry (via GitGitGadget)
Thread type: feature patch series

Core problem or goal
Make `git blame` and `git annotate` automatically use `.git-blame-ignore-revs` (or `HEAD:.git-blame-ignore-revs` in bare repositories) as the default ignore-revs file when no explicit ignore file is configured, aligning local behavior with hosting platforms (GitHub, GitLab) that already respect this file by default. The v6 revision addresses Junio’s polish-only feedback from v5, focusing on code clarity improvements while preserving all prior functionality, including the working-tree file lookup in non-bare repositories, security hardening (NUL-byte rejection, promisor fetch prevention, and a 100MB size cap), and edge-case handling (subdirectory invocations, bare repositories, uncommitted working-tree changes, committed symlinks, and CLI/config overrides).

Key technical details
- Files touched: `builtin/blame.c`, `oidset.c`, `oidset.h`, `Documentation/blame-options.adoc`, `Documentation/config/blame.adoc`, `t/t8013-blame-ignore-revs.sh`
- **Security refinements (patch 1/2)**:
  - **NUL byte rejection**: `oidset_parse_file_carefully()` uses `memchr()` to scan the entire line for NUL bytes, rejecting any line containing them with a clear error message. The author has signaled willingness to adjust this check in a follow-up if Junio requests it.
  - **Promisor fetch prevention**: `peel_to_commit_oid()` uses `odb_read_object_info_extended()` with `OBJECT_INFO_SKIP_FETCH_OBJECT` and `OBJECT_INFO_QUICK`, ensuring missing tag targets in partial clones do not trigger network requests. The function also verifies each tag’s declared type before parsing and peels tags one layer at a time while checking for local object existence.
  - **Size cap**: A 100MB limit (`IGNORE_REVS_MAX_FILE_SIZE`) is enforced via `odb_read_object_info()` before loading the blob, matching Git’s existing `ATTR_MAX_FILE_SIZE` for `.gitattributes`.
- **Default file lookup (patch 2/2)**:
  - **Resolution**: Uses `lstat()` and `open_nofollow()` to resolve `.git-blame-ignore-revs` in non-bare repositories (reading the working-tree file) or `get_oid_with_context()` to resolve `HEAD:.git-blame-ignore-revs` in bare repositories. Non-regular files (e.g., symlinks, subdirectories) are skipped. Phillip Wood’s review questions the necessity of the `lstat()` call, noting that `open_nofollow()` already handles symlink detection, but this is a **low-impact** observation that does not affect functionality.
  - **Precedence**: The default file is added to the ignore-revs list before any user-configured files, ensuring user overrides take precedence. Empty entries in `blame.ignoreRevsFile` or `--ignore-revs-file ""` bypass the default file entirely.
  - **Code clarity improvements (v6)**:
    - Replaces the "cute hack" (passing the scoreboard as `.util`) with `.util = (void *)1` and an explanatory comment, clarifying that any non-null `.util` entry triggers the default lookup.
    - Propagates the ignore-revs file name (`i->string`) into `parse_default_ignore_revs()` to avoid hardcoding paths in multiple places.
    - Documentation tweaks to use "configuration variable" instead of "config option."
  - **Edge cases**: Handles subdirectory invocations (limited to the repository root), bare repositories, uncommitted working-tree changes (read by default in non-bare repositories), committed symlinks (skipped), malformed input (e.g., invalid OIDs, NUL bytes), and CLI/config overrides. Test coverage includes NUL-byte rejection, tag-peeling with chained tags and missing targets, and size cap enforcement.
  - **Scalability**: The `oidset` implementation (using `khash`) uses 32-bit integers for entry counts, but the 100MB size cap ensures the ignore-revs file cannot exceed this limit. The parser filters out non-commit OIDs and duplicates.
- Symbols: No new symbols; modifies existing blame logic (`peel_to_commit_oid()`) and ignore-file parser (`oidset_parse_file_carefully()`) to include security hardening and default file lookup. The `the_repository` cleanup replaces the global variable with `sb->repo` in `parse_default_ignore_revs_blob()`.

Open questions and loose ends
1. **NUL-byte check retention**: The NUL-byte check remains in v6, but the author has signaled willingness to adjust it in a follow-up patch if Junio requests it. This is a minor detail and does not affect the core functionality.
2. **Redundant `lstat()` call**: Phillip Wood’s review questions whether the `lstat()` call preceding `open_nofollow()` is necessary, as `open_nofollow()` already handles symlink detection. This is a **low-weight** code hygiene observation and does not block integration.
