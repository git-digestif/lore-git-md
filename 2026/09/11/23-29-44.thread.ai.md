Subject: [PATCH] blame: default to .git-blame-ignore-revs if no ignore file configured
Series version: standalone patch (v2 in preparation)
Originating author: Ravi Mistry (via GitGitGadget)
Thread type: feature patch

Core problem or goal
Make `git blame` automatically look for and use a `.git-blame-ignore-revs` file in the repository root if no explicit ignore file is configured, aligning local behavior with web interfaces (GitHub, GitLab) that already respect this file by default. The change addresses user surprise when local blame output differs from web views due to manual configuration requirements.

Current status
Under review; design direction resolved in favor of Junio C Hamano’s proposal to use `HEAD:.git-blame-ignore-revs` instead of the working tree file. The author has accepted this change and is preparing a v2 patch that incorporates security-focused refinements to the ignore-file parser. The patch is not yet ready for integration; the revised implementation must demonstrate the proposed security improvements and undergo broader community review for security adequacy.

Key technical details
- Files touched: `builtin/blame.c`, `Documentation/git-blame.txt`, `t/t8013-blame-ignore-revs.sh`, `oidset.c`
- New behavior: `git blame` checks for `HEAD:.git-blame-ignore-revs` (not the working tree file) if no ignore file is explicitly configured.
- **Security refinements**:
  - Reject lines with embedded NUL bytes by using `memchr` in `oidset.c` (replacing `strchr` and `parse_oid_hex_algop` logic that stops at NUL but may ignore trailing bytes).
  - Pass `OBJECT_INFO_SKIP_FETCH_OBJECT` and `OBJECT_INFO_QUICK` in `peel_to_commit_oid` to prevent lazy promisor fetches in partial clones when peeling tags or resolving missing OIDs.
- Edge cases handled: subdirectory invocations, bare repositories, empty files, comments, whitespace, symlinks (now moot due to `HEAD` blob usage).
- Symbols: No new symbols; modifies existing blame logic and ignore-file parser to include default file lookup and security hardening.

Open questions and loose ends
1. **Backwards compatibility**: How should untracked `.git-blame-ignore-revs` files (e.g., local developer overrides) be handled? The current design does not address this; the `HEAD` blob takes precedence, potentially ignoring working tree changes.
2. **Implementation readiness**: The v2 patch must demonstrate the proposed security improvements (NUL byte rejection, promisor fetch prevention) in the ignore-file parser and attract broader review from security-interested contributors to assess completeness.
3. **Test coverage**: The revised patch should include tests for the new security behaviors (e.g., malformed input, partial clone scenarios).

Participant positions
- **Junio C Hamano (maintainer)**: **Opposed the initial implementation** due to behavioral inconsistency (working tree vs `HEAD` blob) and security concerns. His proposal to use `HEAD:.git-blame-ignore-revs` has been **accepted by the author** and is now the agreed design direction. Feedback on the security refinements is **procedural and cautionary**: he delegates the final security audit to the broader community, expressing mild skepticism about the sufficiency of the proposed changes but not rejecting them. Position remains **high-weight** (substantive, authoritative, and tested).
- **Ravi Mistry (author)**: **Revised position** to adopt Junio’s design. Proposes security-focused refinements to the ignore-file parser (NUL byte rejection, promisor fetch prevention) in preparation for v2. Position is now **aligned with maintainer guidance** but awaits community validation of the security improvements.
