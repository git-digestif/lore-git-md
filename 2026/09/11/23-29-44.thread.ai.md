Subject: [PATCH v3 0/2] blame: default to HEAD:.git-blame-ignore-revs if no ignore file configured
Series version: v3 (2 patches)
Originating author: Ravi Mistry (via GitGitGadget)
Thread type: feature patch series

Core problem or goal
Make `git blame` and `git annotate` automatically use `HEAD:.git-blame-ignore-revs` as the default ignore-revs file when no explicit ignore file is configured, aligning local behavior with hosting platforms (GitHub, GitLab) that already respect this file by default. The v3 revision addresses all maintainer feedback from v2, including a mechanical cleanup to avoid referencing the global `the_repository` variable. The series remains feature-complete: (1) security hardening of the ignore-revs parser and tag-peeling logic (rejecting malformed input and preventing promisor fetches in partial clones), and (2) implementation of the default file lookup. The hardening includes optional NUL-byte rejection, which the author has offered to drop if Junio prefers.

Current status
**Approved for integration** and marked ready for the `next` branch by Junio C Hamano, pending a final decision on the optional NUL-byte check and any last-minute community feedback on usability refinements. The `the_repository` cleanup requested in v2 has been addressed in v3 by replacing `the_repository` with `sb->repo` in `parse_default_ignore_revs_blob()`. No new technical objections or security concerns have been raised since v3 was posted. The series is feature-complete, well-tested (including new tests for NUL bytes and partial-clone tag peeling), and aligns with hosting platform conventions.

Key technical details
- Files touched: `builtin/blame.c`, `oidset.c`, `oidset.h`, `Documentation/blame-options.adoc`, `Documentation/config/blame.adoc`, `t/t8013-blame-ignore-revs.sh`
- **Security refinements (patch 1/2)**:
  - **NUL byte rejection (optional)**: `oidset_parse_file_carefully()` uses `memchr()` to scan the entire line for NUL bytes, rejecting any line containing them. This was added for consistency with other trailing-garbage handling but is not a security requirement; the author has offered to drop it if Junio prefers.
  - **Promisor fetch prevention**: `peel_to_commit_oid()` uses `odb_read_object_info_extended()` with `OBJECT_INFO_SKIP_FETCH_OBJECT` and `OBJECT_INFO_QUICK`, ensuring missing tag targets in partial clones do not trigger network requests. The function also verifies each tag’s declared type before parsing to prevent type confusion.
- **Default file lookup (patch 2/2)**:
  - **Resolution**: Uses `get_oid_with_context()` to resolve `HEAD:.git-blame-ignore-revs` and `S_ISREG()` to skip non-regular tree entries (e.g., symlinks, subdirectories).
  - **Precedence**: The default blob is added to the ignore-revs list before any user-configured files, ensuring user overrides take precedence. Empty entries in `blame.ignoreRevsFile` or `--ignore-revs-file ""` bypass the default blob entirely.
  - **In-memory parsing**: Introduces `oidset_parse_buffer_carefully()` to parse the blob’s contents, sharing line-parsing logic with the existing file-based parser (`parse_oidset_line()`).
  - **Edge cases**: Handles subdirectory invocations, bare repositories, uncommitted working-tree changes, committed symlinks, malformed input (e.g., invalid OIDs, NUL bytes), and CLI/config overrides. **New concern**: The current implementation ignores uncommitted changes to `.git-blame-ignore-revs` in non-bare repositories, always reading the committed `HEAD` blob. This is inconsistent with `.gitattributes` behavior and may inconvenience users testing local modifications.
  - **Scalability**: The `oidset` implementation (using `khash`) uses 32-bit integers for entry counts, which could theoretically limit the ignore-revs file to 2³² entries. While unlikely to be a practical issue, the parser does not currently enforce a size limit to prevent memory exhaustion from maliciously large blobs.
- Symbols: No new symbols; modifies existing blame logic (`peel_to_commit_oid()`) and ignore-file parser (`oidset_parse_file_carefully()`) to include security hardening and default file lookup. The `the_repository` cleanup replaces the global variable with `sb->repo` in `parse_default_ignore_revs_blob()`.

Open questions and loose ends
1. **NUL-byte check retention**: Junio’s preference for whether to retain or drop the NUL-byte check remains unresolved. The author has signaled flexibility and will adjust in the next revision if Junio requests it.
2. **Uncommitted changes handling**: Phillip Wood’s review raises the question of whether the default file lookup should respect uncommitted changes to `.git-blame-ignore-revs` in non-bare repositories, similar to `.gitattributes`. The current implementation always reads the committed `HEAD` blob, which may inconvenience users.
3. **Scalability limit**: The `oidset` parser does not enforce a size limit on the ignore-revs file, which could theoretically allow memory exhaustion from maliciously large blobs. While the 32-bit entry count limit makes this unlikely, the lack of an explicit size cap remains a minor loose end.
4. **Security adequacy**: The promisor fetch prevention and tag type verification have not yet been explicitly validated by security-interested contributors (e.g., Jeff King, brian m. carlson), though Junio’s approval reduces the urgency for additional review.
