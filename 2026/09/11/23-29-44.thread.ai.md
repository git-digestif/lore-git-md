Subject: [PATCH] blame: default to .git-blame-ignore-revs if no ignore file configured
Series version: standalone patch (no series)
Originating author: Ravi Mistry (via GitGitGadget)
Thread type: feature patch

Core problem or goal
Make `git blame` automatically look for and use a `.git-blame-ignore-revs` file in the repository root if no explicit ignore file is configured, aligning local behavior with web interfaces (GitHub, GitLab) that already respect this file by default. The change addresses user surprise when local blame output differs from web views due to manual configuration requirements.

Current status
Under review; no prior versions. Patch touches the blame subsystem, documentation, and tests. No new user-facing options are introduced—existing ignore-file functionality is extended with a default lookup.

Key technical details
- Files touched: `builtin/blame.c`, `Documentation/git-blame.txt`, `t/t8013-blame-ignore-revs.sh`
- New behavior: `git blame` now checks for `.git-blame-ignore-revs` in the working tree root if no ignore file is explicitly configured via `blame.ignoreRevsFile` or `--ignore-revs-file`.
- Security: uses `lstat()` to reject symlinks and non-regular files; user-configured ignore files (including empty values) take precedence over the default.
- Edge cases handled: subdirectory invocations, bare repositories, empty files, comments, whitespace.
- Symbols: no new symbols; modifies existing blame logic to include default file lookup.
