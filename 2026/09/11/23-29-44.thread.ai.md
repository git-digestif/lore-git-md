Subject: [PATCH v3 0/2] blame: default to HEAD:.git-blame-ignore-revs if no ignore file configured
Series version: v5 (2 patches)
Originating author: Ravi Mistry (via GitGitGadget)
Thread type: feature patch series

Core problem or goal
Make `git blame` and `git annotate` automatically use `.git-blame-ignore-revs` (or `HEAD:.git-blame-ignore-revs` in bare repositories) as the default ignore-revs file when no explicit ignore file is configured, aligning local behavior with hosting platforms (GitHub, GitLab) that already respect this file by default. The v5 revision adopts Junio’s preference for reading the **working-tree file** in non-bare repositories (matching `.mailmap` behavior), making it ergonomic to test uncommitted changes without requiring commits. The series is feature-complete: (1) security hardening of the ignore-revs parser and tag-peeling logic (rejecting malformed input, preventing promisor fetches in partial clones, and enforcing a **100MB size cap**), and (2) implementation of the default file lookup.

Current status
**Queued for `next`** after Junio C Hamano’s explicit approval. All prior feedback has been addressed, including the `the_repository` cleanup, the **100MB size cap**, and the shift to reading the working-tree file in non-bare repositories. The series is feature-complete, well-tested, and aligns with hosting platform conventions. No open technical objections or security concerns remain.

Key technical details
- Files touched: `builtin/blame.c`, `oidset.c`, `oidset.h`, `Documentation/blame-options.adoc`, `Documentation/config/blame.adoc`, `t/t8013-blame-ignore-revs.sh`
- **Security refinements (patch 1/2)**:
  - **NUL byte rejection**: `oidset_parse_file_carefully()` uses `memchr()` to scan the entire line for NUL bytes, rejecting any line containing them. This closes a parsing ambiguity where trailing garbage after a valid OID could be silently ignored.
  - **Promisor fetch prevention**: `peel_to_commit_oid()` uses `odb_read_object_info_extended()` with `OBJECT_INFO_SKIP_FETCH_OBJECT` and `OBJECT_INFO_QUICK`, ensuring missing tag targets in partial clones do not trigger network requests. The function also verifies each tag’s declared type before parsing to prevent type confusion.
  - **Size cap**: A new **100MB limit** (`IGNORE_REVS_MAX_FILE_SIZE`) is enforced via `odb_read_object_info()` before loading the blob, preventing memory exhaustion from maliciously large blobs. The limit matches Git’s existing `ATTR_MAX_FILE_SIZE` for `.gitattributes`.
- **Default file lookup (patch 2/2)**:
  - **Resolution**: Uses `lstat()` and `open_nofollow()` to resolve `.git-blame-ignore-revs` in non-bare repositories (reading the working-tree file) or `HEAD:.git-blame-ignore-revs` in bare repositories. Non-regular files (e.g., symlinks, subdirectories) are skipped.
  - **Precedence**: The default file is added to the ignore-revs list before any user-configured files, ensuring user overrides take precedence. Empty entries in `blame.ignoreRevsFile` or `--ignore-revs-file ""` bypass the default file entirely.
  - **In-memory parsing**: Introduces `oidset_parse_buffer_carefully()` to parse the file’s contents, sharing line-parsing logic with the existing file-based parser (`parse_oidset_line()`).
  - **Edge cases**: Handles subdirectory invocations (limited to the repository root), bare repositories, uncommitted working-tree changes (now **read by default** in non-bare repositories), committed symlinks (skipped), malformed input (e.g., invalid OIDs, NUL bytes), and CLI/config overrides. The lookup is intentionally limited to the repository root to align with hosting platform conventions and avoid performance costs.
  - **Scalability**: The `oidset` implementation (using `khash`) uses 32-bit integers for entry counts, but the **100MB size cap** ensures the ignore-revs file cannot exceed this limit. The parser filters out non-commit OIDs and duplicates, so the set cannot grow larger than the number of local commits.
- Symbols: No new symbols; modifies existing blame logic (`peel_to_commit_oid()`) and ignore-file parser (`oidset_parse_file_carefully()`) to include security hardening and default file lookup. The `the_repository` cleanup replaces the global variable with `sb->repo` in `parse_default_ignore_revs_blob()`.
