Subject: [PATCH v3 0/2] blame: default to HEAD:.git-blame-ignore-revs if no ignore file configured

Originating author: Ravi Mistry (via GitGitGadget)
Thread type: feature patch series

Core problem or goal
Make `git blame` and `git annotate` automatically use `HEAD:.git-blame-ignore-revs` as the default ignore-revs file when no explicit ignore file is configured, aligning local behavior with hosting platforms (GitHub, GitLab) that already respect this file by default. The v3 revision addresses all maintainer feedback from v2, including a mechanical cleanup to avoid referencing the global `the_repository` variable. The series remains feature-complete: (1) **security hardening of the ignore-revs parser and tag-peeling logic**, and (2) **implementation of the default file lookup**. The hardening includes rejecting malformed input (embedded NUL bytes) and preventing promisor fetches in partial clones, though the NUL-byte check remains optional and the author has offered to drop it if Junio prefers.

Current status
Under review; design direction resolved in favor of Junio’s proposal to use `HEAD:.git-blame-ignore-revs`. The v3 series is feature-complete with both commits posted. Junio’s feedback remains **procedural** (NUL-byte check, now resolved by the `the_repository` cleanup) and **approving** of the code itself ("OK", "Good", "Very clean"). The author has addressed the `the_repository` cleanup nit by replacing `the_repository` with `sb->repo` in `parse_default_ignore_revs_blob()`, aligning with the ongoing `the_repository` removal effort. The patch is **not yet ready for integration**—the hardening’s adequacy (particularly promisor fetch prevention and tag type verification) still requires broader community review, though the urgency for security-focused review has diminished with the concession on NUL bytes. No new objections or technical blockers have been raised.

Key technical details
- Files touched: `builtin/blame.c`, `oidset.c`, `oidset.h`, `Documentation/blame-options.adoc`, `Documentation/config/blame.adoc`, `t/t8013-blame-ignore-revs.sh`
- **Security refinements (patch 1/2)**:
  - **NUL byte rejection (optional)**: `oidset_parse_file_carefully()` uses `memchr()` to scan the entire line for NUL bytes, rejecting any line containing them. This was added for **consistency** with other trailing-garbage handling but is **not a security requirement**; the author has offered to drop it if Junio prefers.
  - **Promisor fetch prevention**: `peel_to_commit_oid()` uses `odb_read_object_info_extended()` with `OBJECT_INFO_SKIP_FETCH_OBJECT` and `OBJECT_INFO_QUICK`, ensuring missing tag targets in partial clones do not trigger network requests. The function also verifies each tag’s declared type before parsing to prevent type confusion. Junio agrees this change is reasonable and uncontroversial.
- **Default file lookup (patch 2/2)**:
  - **Resolution**: Uses `get_oid_with_context()` to resolve `HEAD:.git-blame-ignore-revs` and `S_ISREG()` to skip non-regular tree entries (e.g., symlinks, subdirectories).
  - **Precedence**: The default blob is added to the ignore-revs list **before** any user-configured files, ensuring user overrides take precedence. Empty entries in `blame.ignoreRevsFile` or `--ignore-revs-file ""` bypass the default blob entirely.
  - **In-memory parsing**: Introduces `oidset_parse_buffer_carefully()` to parse the blob’s contents, sharing line-parsing logic with the existing file-based parser (`parse_oidset_line()`).
  - **Edge cases**: Handles subdirectory invocations, bare repositories, uncommitted working-tree changes, committed symlinks, malformed input (e.g., invalid OIDs, NUL bytes), and CLI/config overrides.
- Symbols: No new symbols; modifies existing blame logic (`peel_to_commit_oid()`) and ignore-file parser (`oidset_parse_file_carefully()`) to include security hardening and default file lookup. The `the_repository` cleanup replaces the global variable with `sb->repo` in `parse_default_ignore_revs_blob()`.

Open questions and loose ends

3. **Backwards compatibility**: The design intentionally ignores untracked `.git-blame-ignore-revs` files in the working tree, favoring the `HEAD` blob. This may surprise users expecting local overrides, but the behavior is documented and aligned with maintainer guidance.
