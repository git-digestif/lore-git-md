Subject: [PATCH] blame: default to .git-blame-ignore-revs if no ignore file configured
Series version: standalone patch (no series)
Originating author: Ravi Mistry (via GitGitGadget)
Thread type: feature patch

Core problem or goal
Make `git blame` automatically look for and use a `.git-blame-ignore-revs` file in the repository root if no explicit ignore file is configured, aligning local behavior with web interfaces (GitHub, GitLab) that already respect this file by default. The change addresses user surprise when local blame output differs from web views due to manual configuration requirements.

Current status
Under review; no prior versions. Junio C Hamano has provided **substantive feedback** identifying two key issues: (1) a behavioral inconsistency with hosting sites (working tree vs `HEAD` blob) and (2) a new security threat vector introduced by parsing upstream-controlled content at a fixed path. The patch is not yet ready for integration; the author must address Junio’s concerns before the feature can proceed.

Key technical details
- Files touched: `builtin/blame.c`, `Documentation/git-blame.txt`, `t/t8013-blame-ignore-revs.sh`
- New behavior: `git blame` checks for `.git-blame-ignore-revs` in the working tree root if no ignore file is explicitly configured.
- **Junio’s critique**: The working tree version may differ from `HEAD:.git-blame-ignore-revs`, causing divergence from hosting site behavior. He proposes using the `HEAD` blob instead to ensure consistency.
- Security: The current implementation uses `lstat()` to reject symlinks/non-regular files, but Junio argues this precaution is moot if the default switches to the `HEAD` blob (which avoids working tree access entirely). A security audit of the ignore-file parser is now required to ensure it cannot be exploited via malformed input.
- Edge cases handled: subdirectory invocations, bare repositories, empty files, comments, whitespace.
- Symbols: No new symbols; modifies existing blame logic to include default file lookup.

Open questions and loose ends
1. **Design direction**: Should the default ignore file be the working tree version (current patch) or `HEAD:.git-blame-ignore-revs` (Junio’s proposal)? The latter would align with hosting sites but may complicate implementation (e.g., handling missing blobs).
2. **Security audit**: The ignore-file parser must be reviewed for vulnerabilities, as it will now process upstream-controlled content by default.
3. **Backwards compatibility**: If the default switches to `HEAD`, how should untracked `.git-blame-ignore-revs` files (e.g., local developer overrides) be handled? Junio’s proposal does not address this.

Participant positions
- **Junio C Hamano (maintainer)**: **Opposes the current implementation** due to behavioral inconsistency and security concerns. Proposes using `HEAD:.git-blame-ignore-revs` instead. His feedback is **high-weight** (substantive, tested, and authoritative).
- **Ravi Mistry (author)**: Initial patch author; has not yet responded to Junio’s feedback. Position remains **unrevised**.

Related work
None mentioned. The patch remains a standalone feature change to the blame subsystem, though its design now hinges on alignment with hosting site conventions.
