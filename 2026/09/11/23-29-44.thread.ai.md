Subject: [PATCH v2 0/2] blame: default to HEAD:.git-blame-ignore-revs if no ignore file configured
Series version: v2 (2 patches)
Originating author: Ravi Mistry (via GitGitGadget)
Thread type: feature patch series

Core problem or goal
Make `git blame` and `git annotate` automatically use `HEAD:.git-blame-ignore-revs` as the default ignore-revs file when no explicit ignore file is configured, aligning local behavior with hosting platforms (GitHub, GitLab) that already respect this file by default. The v2 revision addresses maintainer feedback by hardening the ignore-revs parser and tag-peeling logic to reject malformed input (embedded NUL bytes) and prevent promisor fetches in partial clones, ensuring the parser is robust before exposing it to upstream-controlled content.

Current status
Under review; design direction resolved in favor of Junio’s proposal to use `HEAD:.git-blame-ignore-revs`. The v2 series is feature-complete with both commits posted: (1) **security hardening of the ignore-revs parser and tag-peeling logic**, and (2) **implementation of the default file lookup**. The patch is **not yet ready for integration**—the security improvements must undergo broader community review, particularly from security-interested contributors (e.g., Jeff King, brian m. carlson). Junio’s latest feedback remains **procedural and cautionary**, questioning the necessity of the NUL-byte rejection while agreeing the promisor fetch prevention is reasonable. No new objections or technical blockers have been raised, but the hardening’s adequacy is still under scrutiny.

Key technical details
- Files touched: `builtin/blame.c`, `oidset.c`, `Documentation/git-blame.txt`, `t/t8013-blame-ignore-revs.sh`
- **Security refinements (patch 1/2)**:
  - **NUL byte rejection**: `oidset_parse_file_carefully()` now uses `memchr()` to scan the entire line for NUL bytes, rejecting any line containing them. This replaces the prior behavior where `strchr()` and `parse_oid_hex_algop()` would stop at the first NUL but ignore trailing garbage (e.g., `<oid>\0garbage` or `<oid>\0# comment`). Junio’s feedback questions whether this is overly aggressive, as the existing parser already fails safely on malformed object names.
  - **Promisor fetch prevention**: `peel_to_commit_oid()` now uses `odb_read_object_info_extended()` with `OBJECT_INFO_SKIP_FETCH_OBJECT` and `OBJECT_INFO_QUICK`, ensuring missing tag targets in partial clones do not trigger network requests. The function also verifies each tag’s declared type before parsing to prevent type confusion. Junio agrees this change is reasonable.
- **Default file lookup (patch 2/2)**: `git blame` checks for `HEAD:.git-blame-ignore-revs` (via `get_oid_with_context()`) if no ignore file is explicitly configured. Non-regular tree entries (e.g., committed symlinks) are skipped using `S_ISREG()`. The default blob is added to the ignore-revs list **before** any user-configured files, ensuring user overrides take precedence.
- Edge cases handled: subdirectory invocations, bare repositories, empty files, comments, whitespace, committed symlinks, CLI/config overrides (`blame.ignoreRevsFile=""` or `--no-ignore-revs-file` bypasses the default blob), and malformed input.
- Symbols: No new symbols; modifies existing blame logic (`peel_to_commit_oid()`) and ignore-file parser (`oidset_parse_file_carefully()`) to include security hardening and default file lookup.

Open questions and loose ends
1. **Security adequacy**: The hardening (NUL byte rejection, promisor fetch prevention) requires validation from security-interested contributors (e.g., Jeff King, brian m. carlson) to assess completeness. Junio’s feedback suggests the NUL-byte rejection may be overly aggressive, while the promisor fetch prevention is uncontroversial.
2. **Backwards compatibility**: The design intentionally ignores untracked `.git-blame-ignore-revs` files in the working tree, favoring the `HEAD` blob. This may surprise users expecting local overrides, but the behavior is documented and aligned with maintainer guidance.
