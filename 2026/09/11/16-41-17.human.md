This is a feature patch adding a `--matched-only` option to `git range-diff`.

The patch introduces a new flag that filters the output to show only commits that exist in both input ranges, skipping any that appear on only one side. This is useful when reviewing a rebase or other history rewrite where the reviewer cares only about how the surviving commits changed, not about the ones that were added or dropped. The implementation reuses the existing suppression logic for `--left-only` and `--right-only` by internally setting both flags when `--matched-only` is given.

The patch updates the documentation, adds the new option to the command-line parser, and extends the existing conflict check to reject combinations of `--left-only`, `--right-only`, and `--matched-only`. A new test case verifies that the three options are mutually exclusive and that each suppresses the expected one-sided commits.

The motivation is clear and the implementation is straightforward: the new option is a convenience wrapper around an existing capability, and the patch includes thorough tests. The change looks well-crafted and uncontroversial.
