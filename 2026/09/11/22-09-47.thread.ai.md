Subject: [PATCH] coccinelle: remove risky "if (!E) free(E)" rule
Series version: standalone patch (now with follow-up)
Originating author: Junio C Hamano
Thread type: patch (CI/build system)

Core problem or goal
Remove a Coccinelle semantic patch rule (`tools/coccinelle/free.cocci`) that converted `if (!E) free(E);` into an unconditional `free(E)`, as it risked introducing bugs by freeing pointers that were conditionally guarded for a reason. A follow-up patch extends the rule to explicitly allow unconditional `FREE_AND_NULL(E)` calls, reinforcing the principle that such macros are safe to call without guards.

Current status
Under review. The original patch deleted 10 lines from `tools/coccinelle/free.cocci`, removing the risky rule for `free(E)` and `commit_list_free(E)`. The follow-up patch adds 2 lines to the same file, explicitly allowing unconditional `FREE_AND_NULL(E)` calls. No other files or subsystems are touched. The commit messages explain the safety rationale for both changes.

Key technical details
- File touched: `tools/coccinelle/free.cocci`
- Symbols affected: `free(E)`, `commit_list_free(E)`, `FREE_AND_NULL(E)`
- Old behavior: Coccinelle rule generated patches to remove the `if (!E)` guard for `free(E)` and `commit_list_free(E)`; `FREE_AND_NULL(E)` was not explicitly allowed.
- New behavior: Risky rule is deleted; unconditional `free(E)`, `commit_list_free(E)`, and `FREE_AND_NULL(E)` are explicitly allowed. No automatic transformation occurs for guarded calls.
