This is the final patch in a three-part bugfix series addressing resource cleanup in Git’s low-level merge driver infrastructure. The patch replaces custom signal handling with Git’s `tempfile` API to ensure temporary files (`.merge_file_*`) are reliably deleted even when the merge process is interrupted by SIGINT/SIGQUIT (e.g., via Ctrl+C). This completes the series’ core goal: atomic, signal-safe cleanup without changing user-visible behavior.

The patch modifies `merge-ll.c` to use `xmks_tempfile()` for creating temporary files, `close_tempfile_gently()` for error-checked cleanup, and `delete_tempfile()` for explicit removal. A new helper function, `temp_path_basename()`, extracts relative paths from the absolute paths returned by the `tempfile` API to maintain backward compatibility with user-configured merge drivers (e.g., those using shell metacharacters in their command templates). The commit message acknowledges a pragmatic trade-off: shell-quoting the paths would be more robust but risks breaking existing configurations, so the patch opts for the conservative approach.
