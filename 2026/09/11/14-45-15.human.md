This is the third patch in the v6 series adding path-related keys to `` `git repo info` ``. It introduces ``path.hooks.absolute`` and ``path.hooks.relative``, exposing the repository’s hooks directory in a scriptable, config-like format.

The implementation uses ``repo_git_path_replace()`` to respect ``core.hooksPath``, so it returns the configured hooks directory (or ``/dev/null`` if that is set) rather than always returning the default ``.git/hooks``. The patch documents this behavior explicitly and includes tests for the standard hooks directory, a custom hooks path, and the ``/dev/null`` edge case (skipped on Windows, where ``/dev/null`` is not a canonical filesystem path).

The code is clean, the commit message is clear, and the tests cover the advertised behavior. There are no unresolved review comments on this patch; the only prior feedback was about documentation clarity and test hygiene, both of which have been addressed. This patch is ready for merge once the series as a whole lands.
