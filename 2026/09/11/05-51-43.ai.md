This is the v3 revision of Patrick Steinhardt’s 13-patch series refactoring the object database (ODB) subsystem to remove the mechanism for registering in-memory sources. The series is part of the ongoing ODB abstraction effort and continues the `the_repository` removal work.

The core goal remains unchanged: eliminate the dual-use of the ODB sources list for both alternates and temporary in-memory sources (primarily submodules). This simplifies the codebase by ensuring the sources list contains only alternates, paving the way for future migration of alternate handling into the "files" backend. The series is now fully reviewed and uncontroversial, with all patches approved by Karthik Nayak, Justin Tobler, and Junio C Hamano (in v1). The only change in v3 is a minor commit message tweak in patch 5/13 to clarify that the repository being registered is a submodule, not `the_repository`.

Key technical details include the removal of the `odb_add_to_alternates_memory()` API (patch 13/13), the elimination of submodule ODB registration infrastructure (patches 5-7/13), and the enforcement of an alternate-only constraint for `git multi-pack-index --object-dir=` (patch 10/13). The series also fixes a memory leak in the packed ODB source backend (patch 9/13) and updates test helpers to manage ODB sources explicitly (patches 11-12/13). No behavioral changes are expected beyond the memory leak fix and the breaking change in `git multi-pack-index`, which now rejects non-alternate object directories (aligning with documented behavior since 2021).

The series touches 33 files, primarily in the ODB (`odb.c`/`odb.h`), submodule handling (`submodule-config.c`), and test infrastructure (`t/helper/`). It removes ~80 lines of code while maintaining functionality, a clear net improvement in maintainability. The cover letter notes this work sets the stage for future performance fixes in alternate handling, though those are not part of this series.
