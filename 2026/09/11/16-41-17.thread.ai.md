Thread identity: patch series introducing `--matched-only` option to `git range-diff`; originating author Harald Nordgren; thread type: feature patch; series version v1.

Core problem or goal: add a `--matched-only` flag to `git range-diff` that filters output to show only commits present in both input ranges, addressing the workflow pain point of reviewing rebases or range-diffs where users want to focus on how surviving commits changed rather than seeing added or dropped commits.

Current status: initial version (v1) posted; under review. Junio C Hamano has proposed a design refactor to improve internal consistency and extensibility, suggesting the introduction of `--hide-left-only` and `--hide-right-only` as synonyms for the existing `--right-only` and `--left-only` (to be deprecated), with `--matched-only` becoming a shorthand for combining the new `--hide-*` options.

Key technical details:
- Files touched: `builtin/range-diff.c`, `Documentation/git-range-diff.txt`, `t/t3206-range-diff.sh`.
- New CLI option: `--matched-only` (v1 implementation).
- Proposed refactor: introduce `--hide-left-only` and `--hide-right-only` as synonyms for `--right-only` and `--left-only`, deprecate the original names, and redefine `--matched-only` as `--hide-left-only --hide-right-only`.
- New behavior: when `--matched-only` is specified, internally suppresses commits unique to either input range, reusing existing logic.
- Mutual exclusion: `--matched-only` cannot be combined with `--left-only` or `--right-only` (v1 implementation); proposed refactor would allow combining `--hide-*` options.
- Implementation nit: mutual-exclusion check should use existing helper `die_for_incompatible_opt3()` instead of open-coding the error.
- No new symbols (functions, structs, config keys) introduced; purely additive to the CLI and output filtering logic.
- No on-disk format changes; purely a presentation-layer feature.
- Test coverage: new test case in `t3206-range-diff.sh` verifies the new option, mutual exclusion, and interaction with existing flags (v1 implementation).
- Output behavior: numbered gaps where unmatched commits are omitted are acceptable, though the loss of a hint about `--creation-factor` is noted.
