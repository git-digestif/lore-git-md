Thread identity: patch series introducing `--matched-only` option to `git range-diff`; originating author Harald Nordgren; thread type: feature patch; series version v3 (final, mechanically complete).

Core problem or goal: add a `--matched-only` flag to `git range-diff` that filters output to show only commits present in both input ranges, addressing the workflow pain point of reviewing rebases or range-diffs where users want to focus on how surviving commits changed rather than seeing added or dropped commits. The feature’s motivation is concretely illustrated: when rebasing a long-lived branch against `master`, the default output buries relevant changes under hundreds of unrelated commits, while `--matched-only` filters to show only the commits present in both ranges, eliminating irrelevant entries. The distinction from `--left-only` is now clarified: while `--left-only` can filter out dropped commits, it cannot simultaneously suppress added commits, making `--matched-only` the only solution for the core use case.
