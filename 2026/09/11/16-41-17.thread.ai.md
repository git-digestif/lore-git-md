Thread identity: patch series introducing `--matched-only` option to `git range-diff`; originating author Harald Nordgren; thread type: feature patch; series version v3 (final, mechanically complete).

Core problem or goal: add a `--matched-only` flag to `git range-diff` that filters output to show only commits present in both input ranges, addressing the workflow pain point of reviewing rebases or range-diffs where users want to focus on how surviving commits changed rather than seeing added or dropped commits.

Current status: **mechanically complete and ready for merging**. The v3 implementation resolves the sole remaining architectural concern: the error-handling layering violation introduced in v2 has been reverted. The patch now uses `error()` in the library layer (`range-diff.c`) and leaves the CLI front-end (`builtin/range-diff.c`) responsible for calling `die()` if needed, restoring the architectural separation between library and CLI code. No other changes are expected unless new objections arise.

Key technical details:
- Files touched: `builtin/range-diff.c` (CLI option, mutual-exclusion logic, and error-handling responsibility), `range-diff.c` (output filtering and error handling), `range-diff.h` (struct field addition for the new option), `Documentation/git-range-diff.txt` (synopsis, description, and option documentation), `t/t3206-range-diff.sh` (test coverage for the new option, mutual exclusion, and output behavior).
- New CLI option: `--matched-only`.
- No refactor or deprecation of existing flags (`--left-only`, `--right-only`).
- Mutual exclusion: `--matched-only` cannot be combined with `--left-only` or `--right-only`; enforced via a simple arithmetic check (`left_only + right_only + matched_only > 1`) in the library layer, with the CLI front-end calling `die()` if needed.
- Implementation: reuses existing suppression logic for `--left-only` and `--right-only` by internally setting both flags when `--matched-only` is specified.
- No new symbols (functions, structs, config keys) introduced beyond the `matched_only` struct field; purely additive to the CLI and output filtering logic.
- No on-disk format changes; purely a presentation-layer feature.
- Test coverage: new test case in `t/t3206-range-diff.sh` verifies the new option, mutual exclusion, interaction with existing flags, and output format.
- Output behavior: numbered gaps where unmatched commits are omitted remain acceptable; documentation accurately describes this behavior.

Open questions and loose ends: **None**. The sole remaining item (error-handling layering) has been resolved in v3.
