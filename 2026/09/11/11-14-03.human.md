This is patch 5/10 of Patrick Steinhardt’s ongoing ODB abstraction effort, introducing pluggable fsck checks. The patch itself is a clean refactoring that adds scaffolding—new callbacks, options structures, and a helper function—without changing behavior. It’s well-structured and clearly motivated, laying the groundwork for moving fsck logic into backend-specific implementations in later patches.

Toon Claes’s review raises a thoughtful design question: whether the `odb_fsck()` helper should decide which sources to include based on the `ODB_FSCK_FULL` flag, or whether that responsibility should be delegated to the sources themselves. Toon argues that the current approach centralizes logic that might better belong in the backends, especially if future sources interpret "local" differently. This isn’t a nitpick—it’s a substantive architectural point that could affect how easily the code accommodates new ODB backends.

The question is still open, and Patrick hasn’t replied yet. If he agrees, it could mean revisiting the helper’s logic in this patch or a follow-up. For now, the patch remains a solid piece of infrastructure work, but Toon’s feedback suggests there’s room to refine the layering before the series lands.
