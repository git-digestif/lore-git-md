This is a **bugfix patch series** (3 patches) targeting the low-level merge driver infrastructure in Git. The goal is to ensure temporary files (`.merge_file_*`) created during external merge driver execution are reliably cleaned up, even when the process is interrupted by signals like SIGINT (Ctrl+C). The series is now in its second iteration (`v2`), submitted by Jeff King (Peff) after incorporating feedback and testing from Michal Koutný.

The core issue is that when a user interrupts an external merge driver (e.g., via Ctrl+C), the signal propagates to the parent `git merge` process, preventing cleanup handlers from running and leaving temporary files behind. Peff’s solution replaces the original signal-handling approach with Git’s established `tempfile` API, which provides atomic, signal-safe cleanup. This aligns the implementation with Git’s existing patterns (e.g., in `editor.c`) and eliminates custom signal chain manipulation.

The series touches only `merge-ll.c` and makes three focused changes:
1. **Patch 1** refactors the code to use `strbuf` for reading the external merge result, improving robustness and readability.
2. **Patch 2** fixes a minor error-checking bug in the original code, ensuring `close()` errors are properly caught when writing temporary files.
3. **Patch 3** (the main fix) replaces the ad-hoc temporary file handling with the `tempfile` API, using `xmks_tempfile()`, `close_tempfile_gently()`, and `delete_tempfile()` to manage resources safely.

Michal Koutný tested the earlier version of this approach and confirmed it works for both regular termination and SIGINT scenarios. Peff’s `v2` addresses a minor const-correctness warning in the `tempfile` path handling and includes additional tweaks for error handling. The series is well-motivated and technically sound, with clear commit messages and a narrow scope. It’s likely to be uncontroversial, though the lack of automated test coverage for interrupt scenarios (noted by Peff as tricky to implement) might be a minor gap.

This is a **standalone fix** with no dependencies on other ongoing efforts. The patches are small, focused, and ready for review. If accepted, they’ll resolve a long-standing cleanup issue in a critical part of Git’s merge machinery.
