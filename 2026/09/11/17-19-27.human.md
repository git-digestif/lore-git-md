This is a review of Harald Nordgren’s feature patch adding `--matched-only` to `git range-diff`. Junio C Hamano’s reply is substantive and constructive, engaging with both the design and the implementation details.

The core idea—a flag to show only commits present in both input ranges—remains uncontroversial and well-motivated. Junio’s main suggestion is to rework the underlying option model rather than bolt on a third mutually-exclusive flag. He proposes deprecating the existing `--left-only` and `--right-only` in favor of `--hide-left-only` and `--hide-right-only`, which could then be combined to produce the same effect as `--matched-only`. This would make the documentation claim (“the same as using `--left-only` and `--right-only` together”) literally true, whereas today the two existing flags are defined as positive filters and cannot be used together at all. The patch’s current implementation simply adds a third flag and extends the mutual-exclusion check, which Junio finds slightly misleading.

On the code side, Junio points out two minor nits: the patch could use the existing `die_for_incompatible_opt3()` helper instead of open-coding the error message, and the test output numbering might lose some context (e.g., how many commits were hidden) but this is not a major concern.

No fundamental objections are raised; the discussion is about refining the interface rather than questioning the feature itself. The patch is still under review and not yet in any integration branch.
