This thread introduced the `--matched-only` option to `git range-diff`, a feature that filters output to show only commits present in both input ranges. The goal was to improve the rebase and range-diff review workflow by letting users focus on how surviving commits changed, rather than seeing added or dropped commits. Harald Nordgren authored the patch, which went through one iteration (v1) before settling on its final form.

The implementation is minimal and uncontroversial: it adds the new CLI option, enforces mutual exclusion with `--left-only` and `--right-only`, and updates the documentation with Junio’s final wording. No code changes were needed beyond the initial v1; only documentation and mechanical details (like using `die_for_incompatible_opt3()` for error handling) were adjusted. The patch is now ready for integration, with no open questions or objections. Junio, the maintainer, signaled the design is settled, and the thread is effectively closed.
