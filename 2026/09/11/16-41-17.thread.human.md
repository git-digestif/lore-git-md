This thread is about adding a `--matched-only` option to `git range-diff`, allowing users to filter output to show only commits present in both input ranges. The feature is designed to improve workflows like reviewing rebases, where users want to focus on how surviving commits changed rather than seeing added or dropped commits. The patch series, now at version 3, is authored by Harald Nordgren and is ready for merging but has stalled in Junio’s `seen` branch due to lack of review rather than any technical issues.

The implementation is straightforward and additive: it introduces the new `--matched-only` flag, enforces mutual exclusion with other filtering options, and reuses existing suppression logic. The patch touches the CLI front-end, library layer, documentation, and test suite, with no on-disk format changes or new symbols beyond a single struct field. Junio initially raised architectural concerns about error-handling layering, but these were resolved in v3 by reverting to `error()` in the library layer and delegating `die()` to the CLI front-end. The only substantive feedback came from Ben Knoble, who questioned the feature’s motivation; Harald’s response clarified the use case with a concrete example (rebasing a long-lived branch against `master`), addressing the concern.

The patch is low-risk and uncontroversial, with all technical objections resolved. The current blocker is purely procedural: it needs a reviewer to step in before Junio drops it from `seen`. No further changes are planned or needed.
