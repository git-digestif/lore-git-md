This thread is about Harald Nordgren’s patch series adding a `--matched-only` option to `git range-diff`, which filters the output to show only commits present in both input ranges. The feature is designed to help users focus on how surviving commits changed during rebases or range-diffs, rather than seeing added or dropped commits.

The series reached what appeared to be its final form in v1, with Junio Hamano providing the exact wording for the man page update and approving the use of `die_for_incompatible_opt3()` for mechanical consistency. However, Junio has now revisited a key mechanical detail: the error-handling approach. The current patch moves error handling from the CLI front-end into the reusable library layer (`range-diff.c`), replacing an `error()` call with `die()`. Junio argues this is a layering violation that would prevent alternative front-ends (e.g., GUI tools) from recovering gracefully from incompatible option combinations. He has requested the patch revert to the original design, where the caller (the CLI front-end) decides how to handle the error. This change is narrow but affects the same lines of code as the `--matched-only` logic, so the patch will need a small update before it can be merged.

The rest of the patch—its behavior, tests, and documentation—remains unchanged and uncontested. The series is otherwise ready for integration once the error-handling adjustment is made. Key participants are Junio (maintainer) and Harald (author), with Junio’s position now prioritizing architectural consistency over mechanical uniformity. No other open questions remain.
