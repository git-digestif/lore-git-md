This thread introduces a new `--matched-only` option for `git range-diff`, letting users focus on commits that appear in both input ranges while ignoring added or dropped commits. The feature was proposed by Harald Nordgren to improve rebase and range-diff workflows by filtering out noise from commits that don’t survive the operation.

The implementation is now final after three iterations. The latest version (v3) resolves the last architectural concern by restoring proper layering in error handling: the library layer now returns an `error()` rather than calling `die()`, leaving the CLI front end to decide whether to exit. This matches Junio C Hamano’s preference for keeping reusable library code free of fatal-error calls. The patch touches the CLI front end, the range-diff library, documentation, and tests, but introduces no new symbols or on-disk changes. It reuses existing logic by internally setting both `--left-only` and `--right-only` when `--matched-only` is specified, ensuring mutual exclusion with those flags.

Junio initially suggested a more invasive refactor but later accepted a minimal alternative that focused on documentation and error-handling clarity. Harald incorporated Junio’s final wording for the man page and adjusted the error-handling layering as requested. With that resolved, the patch is now ready for merging and should land in the next integration cycle.
