This thread introduced a new `--matched-only` option for `git range-diff`, allowing users to focus on commits present in both input ranges when reviewing rebases or range-diffs. The feature, proposed by Harald Nordgren, was initially debated between a more invasive refactor and a minimal implementation. The maintainer, Junio C Hamano, ultimately settled on retaining the original v1 implementation with only documentation updates to clarify its behavior alongside existing flags like `--left-only` and `--right-only`.

The final patch, just posted by Junio, updates the man page to remove a misleading sentence and solidify the design direction. No code changes were made, and the implementation remains as submitted in v1, including its mutual exclusion with `--left-only` and `--right-only`. The thread is now effectively closed unless new objections arise. Key participants—Junio and Harald—agreed on the minimal approach, prioritizing stability and avoiding unnecessary code churn. The feature is ready for integration.
