This thread is about a patch series by Harald Nordgren that adds a `--matched-only` option to `git range-diff`. The feature filters the output to show only commits present in both input ranges, making it easier to review rebases or range-diffs where you want to focus on how surviving commits changed rather than seeing added or dropped commits. The series is now at version 3, which resolves the last technical concern about error-handling layering by reverting to a simpler approach.

The patch is technically ready and has been queued in Junio’s `seen` branch, but it risks being dropped unless a reviewer steps in to validate its conceptual fit. Junio has clarified that the feature addresses a real workflow pain point—specifically, the inability of existing syntax to filter out unrelated commits when comparing two ranges that share no common base—but the discussion has also highlighted that some users can achieve similar filtering with careful input selection. The patch remains in limbo: no one has objected to the implementation, but no one has yet endorsed the feature as a necessary addition to `git range-diff`.

Key participants include Harald (the author), Junio (the maintainer), Ben Knoble (who raised questions about the feature’s motivation and redundancy), and Matt Hunter (who initially suggested existing syntax could replace the feature but later acknowledged its limitations). The patch touches only the presentation layer, adds no new symbols beyond the `--matched-only` option, and includes test coverage. The ball is now in the court of potential reviewers to decide whether the feature’s utility justifies its inclusion.
