This thread is about a small but useful feature addition to `git range-diff`: a `--matched-only` option that filters the output to show only commits present in both input ranges. The goal is to help users reviewing rebases or range-diffs focus on how surviving commits changed, without distraction from added or dropped commits.

The patch, now in its third and final version, is authored by Harald Nordgren and is currently queued in Junio’s `seen` branch. The implementation is minimal and uncontroversial: it adds the new flag, enforces mutual exclusion with `--left-only` and `--right-only`, reuses existing suppression logic, and includes thorough test coverage. The only substantive discussion point—error-handling layering—was resolved in v3 by reverting to `error()` in the library layer and letting the CLI front-end handle `die()`. Junio’s earlier objections have been fully addressed, and the patch is ready for merging.

The patch has received little attention, likely because the code is straightforward and raises no obvious concerns. It touches only the presentation layer, introduces no new symbols beyond a single struct field, and makes no on-disk format changes. The test coverage verifies the option’s behavior, mutual exclusion, and output format.
