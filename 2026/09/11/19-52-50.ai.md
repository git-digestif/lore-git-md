This is a CI/build system patch that resends Jeff King’s earlier proposal to modernize GitLab CI’s Asciidoctor installation. The patch replaces the manual `gem install asciidoctor -v 1.5.8` with `apt-get install asciidoctor`, dropping the outdated version pin and relying on the Ubuntu image’s default package (2.0.20). This matches the approach already taken in Jeff’s follow-up series (`peff/ci-asciidoctor-bump`) and aligns with the thread’s broader goal of simplifying CI configuration.

The patch itself is identical to Jeff’s second patch in his series, but it is sent as a standalone update by Tuomas Ahola, who adds his Signed-off-by and notes in the cover text that the change was already claimed in the v2.56.0 release notes draft despite not being merged. This suggests the patch fell through the cracks during the earlier discussion. The modification is minimal: it removes the explicit version pin and adds `asciidoctor` to the `apt-get install` line, making the installation logic consistent with GitHub Actions and real-world user environments.

The motivation is clear and uncontroversial: the version pin (1.5.8, from 2018) is obsolete, and Asciidoctor 2.0.x has worked fine since 2019. Using the system package reduces maintenance overhead and ensures CI tests versions users are actually likely to have installed. The patch also implicitly addresses Patrick Steinhardt’s earlier concern about redundant Ruby installation by making it a dependency of the `asciidoctor` package, though the explicit `ruby` installation is retained for robustness.

No substantive objections are expected. The patch is a straightforward maintenance update with no behavioral changes, and the technical details are well-documented in the commit message. The only loose end is the `concurrent-ruby` gem, which remains installed but whose necessity is still unclear; this is orthogonal to the patch and does not block it. The resend is likely a nudge to Junio to merge the change before the v2.56.0 release.
