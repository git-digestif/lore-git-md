This is the fourth patch in the v6 series adding path-related keys to `git repo info`. It introduces `path.index.absolute` and `path.index.relative`, exposing the repository’s index file location in a scriptable format. The implementation uses `repo_get_index_file()` and respects the `GIT_INDEX_FILE` environment override, returning the configured path even in bare repositories or when the file does not exist. This aligns with the series’ design principle of mirroring `git rev-parse --git-path` behavior and avoids special-casing edge cases like `/dev/null` (unlike `path.hooks`, which explicitly documents `/dev/null` handling).

The patch touches `builtin/repo.c` (adding two new getter functions), `Documentation/git-repo.adoc` (documenting the new keys), and `t/t1900-repo-info.sh` (adding test coverage for standard index paths, `GIT_INDEX_FILE` overrides, and bare-repository edge cases). The tests confirm that the keys return the expected paths in all scenarios, including relative paths from subdirectories and absolute paths in bare repositories. The implementation is straightforward and follows the established pattern of the series, using `format_path()` to handle path formatting.
