This is a Coccinelle rule cleanup from Junio. The patch removes a controversial semantic patch that converts `if (!E) free(E);` into an unconditional `free(E)`. The original rule, added in 2017, aimed to flag "useless" free calls where the pointer was known to be NULL, but Junio argues this transformation is risky—it turns a no-op into code that might hide a real bug (e.g., a typo where the programmer meant to free something else).

The commit message suggests replacing the rule with a `BUG()` call to force developers to address the pattern explicitly, but Junio opts to simply drop the rule for now, rewriting the no-op into a simpler form. The change affects only the Coccinelle script (`tools/coccinelle/free.cocci`), not Git’s runtime behavior.

This is a cautious, maintainer-level decision about tooling hygiene. The patch is small and self-contained, but the underlying question—whether to silently "fix" or loudly flag dubious patterns—could spark broader discussion about Coccinelle’s role in the project. For now, it’s a clean revert of a long-standing but questionable rule.
