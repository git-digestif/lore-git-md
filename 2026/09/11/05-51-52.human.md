This is a bugfix patch in Patrick Steinhardt’s 13-part ODB refactoring series. It plugs a memory leak in the packed object database source backend that surfaces only when sources are no longer automatically linked to the main ODB — a change introduced earlier in the series.

The patch adds a single line to `odb_source_packed_free()` in `odb/source-packed.c`: a call to `odb_source_close(source)` before the existing loop that frees individual packfiles. This ensures that the source’s packs and multi-pack indices are properly closed, preventing memory leaks when ad-hoc packed sources are created and freed. The leak went unnoticed until now because packed sources were historically always linked to the main ODB, which outlived them.

The fix is minimal, well-explained, and clearly necessary for the refactoring to proceed without regressions. It’s uncontroversial and already reviewed as part of the larger series. No test updates are needed; the leak is caught by existing memory-leak detection in the test suite. This patch is a prerequisite for later patches in the series that remove the automatic linking mechanism entirely.
