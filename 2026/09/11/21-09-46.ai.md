This is a CI/build system review comment on the first patch of Johannes Schindelin’s two-part v2 series enabling Rust compilation in Git’s GitHub Actions Windows CI jobs. The series configures the Rust toolchain to target the GCC ABI (used by Git for Windows) instead of the default MSVC ABI, ensuring Cargo produces a static library (`libgitcore.a`) compatible with MinGW’s `ld.exe`.

Junio C Hamano’s reply is a **substantive review** that identifies a naming inconsistency in the patch. The patch introduces a new `CARGO_TARGET` variable to specify the Rust target triple, but Junio points out that Cargo’s officially supported environment variable for this purpose is `CARGO_BUILD_TARGET`. He references a recently merged topic (`jc/rust-cargo-build-target`, authored by James Le Cuirot) that already respects `CARGO_BUILD_TARGET` when locating build output, and suggests aligning the new variable with this established convention. The review includes a diff from the merged topic to illustrate how `CARGO_BUILD_TARGET` is used in practice.

The feedback is narrowly scoped but important: adopting `CARGO_BUILD_TARGET` would avoid introducing a parallel variable and ensure consistency with existing Rust build logic in Git. The change is mechanical and unlikely to be controversial, but it is necessary for the patch to integrate cleanly with the broader Rust build system. No objections to the patch’s overall goal or implementation are raised; the review is focused solely on variable naming. The author will likely address this in a v3 or as a follow-up.
