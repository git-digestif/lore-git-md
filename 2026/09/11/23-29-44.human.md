This is a feature patch that makes `git blame` automatically look for and use a `.git-blame-ignore-revs` file in the repository root if it exists. The feature addresses a long-standing friction point: web interfaces like GitHub and GitLab already support ignoring revisions for blame purposes, but local `git blame` commands require manual configuration to achieve the same effect.

The patch is well-motivated and thorough. The commit message explains why the original 2019 implementation avoided a default file (caution around a new, unproven feature) and why the ecosystem has since standardized on `.git-blame-ignore-revs` as a convention. It also details the security and precedence semantics: the default file is loaded before user or repository config, symbolic links and non-regular files are rejected, and empty filenames or `--no-ignore-revs-file` cleanly bypass the default. Documentation and test coverage are comprehensive, covering edge cases like subdirectory invocations, symlink rejection, whitespace handling, and bare repositories.

The implementation itself is clean: it adds the default file lookup early in `cmd_blame()`, uses `lstat()` to ensure the file is regular, and prevents duplicate parsing with a `strset`. The patch has already incorporated feedback from earlier iterations, including hardening against corrupted files and clarifying override semantics. This looks like a mature, uncontroversial improvement that aligns local tooling with established ecosystem practice. It should be a straightforward merge candidate.
