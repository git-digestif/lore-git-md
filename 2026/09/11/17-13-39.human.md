This is the final patch in a three-part bugfix series that ensures temporary files created during external merge driver execution are reliably cleaned up, even when the process is interrupted by SIGINT or SIGQUIT. The series replaces custom signal handling with Git’s `tempfile` API, a well-established pattern for atomic, signal-safe resource cleanup. This patch specifically implements the `tempfile` conversion in `merge-ll.c`, completing the series.

The change is straightforward and conservative: it replaces manual file management (with relative paths like `.merge_file_abc123`) with Git’s `tempfile` subsystem, which automatically handles cleanup on signals or errors. The patch also introduces a helper function, `temp_path_basename()`, to work around a limitation in the `tempfile` API—it returns absolute paths, which could cause shell-quoting issues if passed directly to external merge drivers. To avoid breaking backward compatibility (e.g., for users who configure merge drivers with custom shell quoting), the patch continues to report relative paths to the driver, preserving existing behavior.

The implementation is clean and aligns with Git’s defensive programming practices. It addresses the core issue—temporary files left behind after interrupts—while avoiding unnecessary risk. The commit message is thorough, explaining both the problem and the trade-offs (e.g., the shell-quoting limitation). No functional behavior changes are introduced, and the patch is unlikely to be controversial.

This series is ready for review and should be uncontroversial.
