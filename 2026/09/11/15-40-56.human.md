This is the second patch in a **bugfix series** that improves the advice messages shown when `git push --force-if-includes` rejects a push from a detached HEAD. The series is **ready for merge** and addresses a real usability issue: the current advice incorrectly tells users to run `git pull`, which cannot resolve the problem.

The patch introduces a new `ref->unverifiable` flag to distinguish detached HEAD rejections from other types of push failures. It adds a clear, actionable advice message instructing users to either specify the expected remote tip with `--force-with-lease=<ref>:<expect>` or bypass the check entirely with `--no-force-if-includes`. The new message is consistent across all transport layers (direct pushes, transport helpers, and `send-pack`), and the behavior is configurable via a new `advice.forceIfIncludesDetachedHead` config key (documented as `advice.pushRefUnverifiable`).
