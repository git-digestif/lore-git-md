This is a CI/build system follow-up in the thread updating Git's CI from Debian 11 to Debian 12. Jeff King (Peff) responds to Patrick Steinhardt's suggestion to use the `oldstable` Docker tag instead of `debian:12`, explaining why the numeric scheme may still be preferable. The core issue is the misalignment between Debian's release cycle (every ~2 years) and its LTS window (5 years), which means no single Docker tag (`oldstable` or `oldoldstable`) consistently points to the oldest supported release. Peff concludes that the current approach—hard-coding the version number and updating it every few years when support ends—remains the most reliable, even if it requires occasional manual maintenance. This reply effectively closes the `oldstable` proposal, leaving the original patch (now in `seen`) unchanged in its technical approach. The thread's broader questions about 32-bit testing and older Ubuntu LTS jobs remain open but are not addressed here.
