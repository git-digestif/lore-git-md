This is the fourth patch in the v6 series adding path-related keys to `git repo info`. It introduces `path.index.absolute` and `path.index.relative`, exposing the repository’s index file location in a scriptable format.

The patch is straightforward and well-executed. It uses `repo_get_index_file()` to retrieve the index path (respecting `GIT_INDEX_FILE` overrides) and formats it as either an absolute or relative path via the existing `format_path()` helper. The implementation matches the established pattern for other path keys in the series, and the documentation clearly states that the keys return the configured path even in bare repositories or when the file does not exist—consistent with `git rev-parse --git-path` behavior.

Tests cover the standard case, a `GIT_INDEX_FILE` override, and bare-repository edge cases, including the expected relative path from a subdirectory. The test hygiene is good, with `test_when_finished` used to clean up temporary repositories.

This patch is uncontroversial and mechanically sound. The only potential point of discussion is the unconditional path-return behavior (even when the file does not exist), but this aligns with prior reviewer endorsements for similar keys (`path.grafts`, `path.hooks`) and is explicitly documented.
