This is the first patch in a three-part **bugfix series** targeting resource cleanup in Git’s low-level merge driver infrastructure. The series, authored by Jeff King (Peff) and building on work by Michal Koutný, ensures temporary files (`.merge_file_*`) are reliably removed even when the merge process is interrupted by SIGINT/SIGQUIT. This specific patch refactors the file-reading logic in `ll_ext_merge()` to use `strbuf` instead of manual buffer management, simplifying the code and reducing error-prone boilerplate.

The change replaces a hand-rolled loop with `strbuf_read_file()`, which handles file reading, allocation, and error cases in a single call. The patch also addresses a subtle type mismatch: `result->size` uses `long`, while `strbuf_detach()` expects `size_t`, so the conversion requires an intermediate cast. This is noted as a minor technical debt but is left untouched to avoid scope creep. The patch is a cleanup that stands alone but conflicts textually with the rest of the series, making it a logical first step.

No functional behavior changes are introduced—callers still receive the same `mmbuffer_t` structure and error handling semantics. The patch is uncontroversial and aligns with Git’s modern idioms for file I/O. It touches only `merge-ll.c` and is well-motivated by the broader goal of making the merge driver’s resource cleanup more robust. The commit message clearly explains the rationale and edge cases, and the diff is minimal and focused.

For follow-up discussion, the key technical detail is the `strbuf` conversion in `ll_ext_merge()`, which sets the stage for the subsequent patches to introduce Git’s `tempfile` API. The patch is ready for review and unlikely to draw substantive feedback beyond minor stylistic nitpicks. No test coverage is added here, as the change is purely internal refactoring.
