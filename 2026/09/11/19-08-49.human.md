This is the first patch in a two-part CI/build system series (v2) that enables Rust compilation in Git’s GitHub Actions Windows CI jobs. The patch ensures that when Git is built under MSYS2/MinGW with Rust support, `cargo build` produces a static library (`libgitcore.a`) compatible with MinGW’s `ld.exe`, rather than the default MSVC-targeted `.lib` file that MinGW cannot link.

The core issue is that the Rust toolchain installed via `rustup` on GitHub’s Windows runners defaults to the MSVC ABI, which is incompatible with Git for Windows’ MinGW-based build environment. The patch fixes this by mapping the `MSYSTEM` environment variable to the correct Rust target triple: `x86_64-pc-windows-gnu` for MSVCRT-based MinGW subsystems (e.g., UCRT64, MINGW64) and `aarch64-pc-windows-gnullvm` for Clang/LLVM subsystems (the only option for ARM64, where no MinGW-GCC port exists). The patch reuses and corrects the `HOST_CPU` variable to derive the target triple, avoiding reliance on environment variables that are not defined in Git for Windows’ minimal SDK.

The changes are minimal and focused: the `Makefile` is updated to include the target triple in the `RUST_LIB` path and pass it to `cargo` via `CARGO_ARGS`, while `config.mak.uname` defines the mapping logic. The commit message clarifies that `rustup target add` is sufficient to install the required Rust components, as the linker is already provided by the SDK. This patch does not affect core Git functionality or user-facing features—it is purely a build-system adjustment to unblock Rust compilation in CI.

The patch addresses feedback from v1, where Junio C Hamano noted an inconsistency in the UCRT64 target triple mapping. The v2 patch now consistently maps UCRT64 to `x86_64-pc-windows-gnu` (GCC ABI) instead of `x86_64-pc-windows-gnullvm` (Clang ABI), aligning with the MinGW toolchain used by Git for Windows. The series is well-motivated and practical, with clear test coverage via CI validation (the commit message links to a failed CI run demonstrating the original problem).

This patch is a prerequisite for the broader Rustification effort in Git, as it removes a key obstacle to compiling Rust code in Windows CI jobs. It looks ready to merge, though the author has requested testing on GitLab’s Windows runners to confirm whether additional changes are needed there. The patch is unlikely to be controversial, assuming the GitLab runners behave as expected.
