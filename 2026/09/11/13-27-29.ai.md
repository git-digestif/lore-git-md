This is patch 5/10 of Patrick Steinhardt’s v3 series refactoring Git’s object integrity verification (fsck) to make backend-specific checks pluggable. The patch introduces the scaffolding for pluggable fsck checks: a new `fsck` callback in the `struct odb_source` vtable, empty stubs for all existing source types (`files`, `inmemory`, `loose`, `packed`), and the `struct odb_fsck_options` structure with the `ODB_FSCK_FULL` flag. The patch replaces the old `check_full` boolean with the new options structure and adds the `odb_fsck()` helper, which iterates over all sources and invokes their respective `fsck` callbacks.

The key change in this v3 iteration is the relocation of the `ODB_FSCK_FULL` filtering logic from the central `odb_fsck()` helper into the "files" backend’s `fsck` callback (in `odb/source-files.c`). This makes the infrastructure more flexible for non-local backends (e.g., reftable, cloud storage) by allowing each backend to decide whether to skip checks based on the flag. The change is minimal (three lines added to `odb/source-files.c`) and does not alter behavior. The patch also replaces the `--full` flag’s `OPT_BOOL` with `OPT_BIT`, preserving `--no-full` functionality via bitwise negation.

Files touched include `builtin/fsck.c` (replacing `check_full` with `odb_fsck_opts`), `odb.c` (adding the `odb_fsck()` helper), `odb.h` (introducing `struct odb_fsck_options` and `enum odb_fsck_flags`), and the backend-specific source files (`odb/source-files.c`, `odb/source-inmemory.c`, `odb/source-loose.c`, `odb/source-packed.c`), where empty `fsck` callbacks are added to the vtable. The `odb/source.h` header is updated to declare the new `fsck` callback and its inline helper.

Review feedback from Karthik Nayak and Toon Claes on this patch has been fully addressed. Karthik’s question about `OPT_BIT` versus `OPT_BOOL` for the `--full` flag was resolved by Patrick, who confirmed that `OPT_BIT` provides equivalent `--no-full` semantics. Toon’s architectural question about where to filter sources based on `ODB_FSCK_FULL` was resolved in v3 by moving the check into the "files" backend’s callback, aligning with the series’ goal of backend-specific control. No unresolved feedback or open questions remain for this patch.
