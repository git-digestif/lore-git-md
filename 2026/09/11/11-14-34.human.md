This is patch 7/10 in Patrick Steinhardt’s ongoing refactoring to make Git’s object integrity checks pluggable per ODB backend. The patch moves reverse-index verification from `builtin/fsck.c` into the packed ODB backend (`odb/source-packed.c`), replacing the dedicated `ERROR_PACK_REV_INDEX` bit with the generic `ERROR_OBJECT` bit. It also ensures the new implementation respects the `--connectivity-only` and `--no-full` flags, skipping reverse-index checks when either is passed.

Toon Claes’s reply is a surface-level review that simply acknowledges the patch’s structure: the check is now part of the ODB’s `.fsck` callback, invoked by `odb_fsck()`, and negative return values are converted to `ERROR_OBJECT` in `builtin/fsck.c`. His comment is purely observational, confirming the patch’s design aligns with the series’ stated goal of moving backend-specific logic into the appropriate ODB source. There are no technical objections, edge-case questions, or requests for changes; the patch appears uncontroversial and well-placed within the larger refactoring effort.

The series as a whole remains under review due to an open architectural question Toon raised earlier about where the `ODB_FSCK_FULL` filtering logic should reside, but that discussion does not affect this specific patch. All other feedback from the v2 iteration has been addressed, and this patch is a clean, mechanical refactoring with no user-visible behavior changes beyond the intentional flag-based skipping of checks. If the series lands, this patch will be a straightforward part of the infrastructure for pluggable ODB backends.
