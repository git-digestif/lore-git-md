This is patch 4/10 of Patrick Steinhardt’s v3 series refactoring Git’s object integrity checks to make them pluggable per ODB backend. This specific patch fixes a long-standing discrepancy between the documented and actual behavior of the `--full` flag in `git fsck`.

The man page for `git fsck` states that `--full` controls whether Git checks objects in alternate object pools (e.g., `GIT_ALTERNATE_OBJECT_DIRECTORIES`) *and* packed archives. However, the current implementation only honors this flag for packfiles—loose objects in alternates are always checked, regardless of `--full`. This patch aligns the code with the documentation by skipping loose-object checks in alternates when `--no-full` is passed.

The change is minimal: a three-line addition in `builtin/fsck.c` (`if (check_full || source->local)`) ensures that `fsck_source()` is only called for local sources when `--no-full` is used. The patch also adds a regression test in `t/t1450-fsck.sh` to verify that `git fsck --no-full` produces no output when alternates contain only loose objects, confirming the fix.

Karthik Nayak’s earlier review of this patch confirmed the intent and logic, and Patrick has incorporated all feedback. The fix is straightforward and uncontroversial, addressing a clear behavioral inconsistency without introducing new complexity. This patch is a small but necessary step in the larger ODB abstraction effort, ensuring that the `--full` flag behaves predictably as the fsck logic is refactored into pluggable backends.
