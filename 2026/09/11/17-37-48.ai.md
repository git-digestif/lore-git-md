This is the seventh and final patch in the v6 series adding path-related keys to `git repo info`. Junio C Hamano raises a **substantive edge-case discrepancy** between the new `path.cdup` key and `git rev-parse --show-cdup` when the current working directory is outside the repository’s working tree.

The issue: when `GIT_WORK_TREE` and `GIT_DIR` are set but the current directory is outside the working tree, `path.cdup` returns an empty string while `git rev-parse --show-cdup` returns the absolute path to the working tree root. This inconsistency undermines the series’ stated goal of consolidating repository path information under `git repo info`.

The discrepancy is not a mechanical bug but a **design choice** that now conflicts with existing Git behavior. The patch’s current implementation relies on `repo->prefix`, which is empty when outside the working tree, whereas `git rev-parse --show-cdup` computes the absolute path to the working tree root in this scenario. This is a **high-weight issue** that must be resolved before merging, as it affects script compatibility and user expectations.

The fix will require modifying the `get_path_cdup()` function in `builtin/repo.c` to handle the outside-working-tree case, likely by falling back to `get_git_work_tree()` when `repo->prefix` is empty. This change is localized but touches a core design principle of the series: whether `git repo info` should mirror `git rev-parse` behavior exactly or allow deviations for simplicity.

No other feedback is provided; the rest of the patch (documentation, tests, and subdirectory behavior) remains uncontroversial. The series as a whole is otherwise feature-complete and mechanically sound, but this edge case must be addressed to align with the architectural goal of consolidating path-related information. Reviewers should focus on whether the fix should prioritize strict compatibility with `git rev-parse` or allow a simpler, repo-centric design.
