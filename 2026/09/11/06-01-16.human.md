This is a reply from Patrick Steinhardt in the ongoing "What's cooking" thread, responding to Junio's latest integration report. It covers three topics: a small documentation fix, a stalled refactoring effort, and a major ODB simplification series.

The first item is a trivial documentation patch (`bc/maintenance-doc-markup-fix-for-asciidoc`) that fixes bullet-point formatting in the `git maintenance` man page. Patrick confirms it looks good, so this is likely to graduate to `next` soon. It’s a low-risk, uncontroversial fix that busy readers can safely ignore.

The second is Patrick’s own stalled series (`ps/libgit-in-subdir`), which proposed moving `libgit.a` sources into a `lib/` subdirectory. He acknowledges the series failed to gain consensus and suggests it may be discarded unless he can revive it at the upcoming Contributor’s Summit. This is a clear signal that the effort is on hold, and readers tracking the codebase reorganization can stop following it for now.

The third is the more substantial `ps/odb-stop-registering-in-memory-sources` series, which removes Git’s ability to register in-memory alternate object sources. This is part of Patrick’s long-running ODB abstraction effort, and the series is now effectively complete—Patrick sent a v3 to address a minor commit message nit, but no functional changes. The series touches core object database management, submodule handling, and several built-in commands, so it’s worth attention from anyone working on object storage or submodule code. The simplification should make future ODB work cleaner, though the removal of ad-hoc alternate registration could affect external tools that relied on it.
