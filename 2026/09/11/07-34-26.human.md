This is the second patch in the v4 series that defers auto maintenance until the end of sequencer-driven operations. The patch moves the `run_auto_maintenance()` call from the sequencer to the built-in commands (`git rebase`, `git cherry-pick`, and `git revert`), consolidating it into a single exit path per command. The author’s commit message justifies this design by noting that the sequencer lacks a unified exit point, but Patrick Steinhardt’s review challenges that claim, pointing out that nearly all code paths—including single picks, multi-pick sequences, `--continue`, and `--skip`—eventually converge on `pick_commits()`. The only exception is `--abort`, which could be handled separately.

Patrick’s feedback is substantive: he argues that the current implementation scatters maintenance calls across multiple sites, making the code harder to reason about, and suggests instead triggering maintenance once in `pick_commits()` and once during abort. This would simplify the logic and align better with the sequencer’s internal flow. The review is constructive and technically grounded, focusing on code structure rather than behavior. No objections to the overall goal—deferring maintenance until sequence completion—but the implementation choice is now under scrutiny. The author may need to revisit the design to address Patrick’s concern before the series can proceed.
