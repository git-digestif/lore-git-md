This is the final patch in Patrick Steinhardt’s 13-patch series refactoring the object database (ODB) subsystem to remove ad-hoc source linking. The series as a whole is a well-reviewed, uncontroversial cleanup that eliminates the dual-use of the ODB sources list for both alternates and temporary in-memory sources (primarily submodules). This patch removes the now-unused `odb_add_to_alternates_memory()` function, completing the refactoring.

The patch itself is trivial—just 14 lines deleted from `odb.c` and `odb.h`—but it represents the culmination of a larger effort to simplify the ODB codebase. With this change, the ODB sources list now contains only the primary source and its alternates, which paves the way for future work to migrate alternate handling into the "files" backend. The series has been thoroughly reviewed by Karthik Nayak, Justin Tobler, and Junio C Hamano, with no outstanding objections or loose ends.

This is a clear maintainability win: the codebase is now simpler, with fewer implicit dependencies and a more predictable ODB structure. The series also includes a memory leak fix (patch 9/13) and enforces an existing documented constraint in `git multi-pack-index` (patch 10/13), but those changes are already accounted for in earlier patches. If you’ve been following the ODB abstraction effort or the `the_repository` removal work, this series is a meaningful step forward and looks ready for Junio’s queue.
