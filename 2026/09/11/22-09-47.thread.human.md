This thread is about a small but important change to Git’s Coccinelle rules: Junio C Hamano removed a rule that automatically converted `if (!E) free(E);` into an unconditional `free(E)`, arguing it was risky because it could free pointers that were guarded for a reason. A follow-up patch then explicitly allowed unconditional `FREE_AND_NULL(E)` calls, reinforcing that such macros are safe to call without guards.

The patch itself is straightforward—it only touches `tools/coccinelle/free.cocci`—but René Scharfe’s review raises deeper questions. He agrees with the safety concern but wonders whether the rule was ever useful in practice. Instead of just removing it, he suggests alternatives like replacing the guarded `free(E)` with a `BUG()` (to force attention) or simply removing the call entirely (since `free(NULL)` is a no-op). He also questions whether Coccinelle should even try to catch such cases, or if runtime tools like LeakSanitizer (with good test coverage) would be a better fit.

So far, the discussion is between Junio and René, with no objections but no clear resolution either. The thread is still under review, and the open questions—whether the rule was ever justified, how aggressive Coccinelle rules should be, and whether other free-like macros need similar treatment—could shape how Git uses static analysis in the future. For now, the patch is a simple cleanup, but the broader conversation about tooling and safety might lead to further changes.
