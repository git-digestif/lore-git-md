This thread is about a small but important change to Git’s Coccinelle rules, specifically removing a rule that automatically converted `if (!E) free(E);` into an unconditional `free(E)`. The concern was that this rule could introduce bugs by freeing pointers that were guarded for a reason. Junio C Hamano sent the original patch to remove the rule, and a follow-up to explicitly allow unconditional `FREE_AND_NULL(E)` calls, which are safe by design.

The discussion has focused on whether the original rule was ever useful and how aggressive Coccinelle rules should be in Git’s CI pipeline. René Scharfe raised a substantive point: instead of leaving an unconditional `free(E)`, why not just remove the call entirely? Junio responded that while this would be the safest approach, it could trigger compiler warnings for empty `if` blocks, potentially breaking CI if warnings are treated as errors. No new patch has been proposed yet, and the thread remains open to further input on how to balance correctness, simplicity, and build hygiene.

The only file touched is `tools/coccinelle/free.cocci`, and the changes are minimal—removing the risky rule and explicitly allowing `FREE_AND_NULL`. The thread is still under review, with no objections but some open questions about the best path forward.
