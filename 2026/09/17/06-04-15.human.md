This is the fifth iteration of Mike Hommey’s patch series moving Git’s Rust code into a dedicated `rust/` subdirectory. The patch is part of the ongoing Rust infrastructure reorganization and now addresses the CI breakage Junio reported in the previous version.

The core change remains the same: all Rust files (including `Cargo.toml`, `build.rs`, and the source tree) are relocated from the top-level and `src/` into `rust/`. The update fixes the CI script `ci/run-rust-checks.sh` by adjusting its path references to point to the new location, ensuring Rust formatting, clippy, and MSRV checks now run correctly. The patch also updates `.gitignore`, `Makefile`, and `meson.build` to reflect the new paths, preserving build functionality for both single-target and multi-target Rust builds.

This version resolves the last known blocker—the CI failure—making the series technically complete. The reorganization itself is uncontroversial; the only prior objections were mechanical (build breaks and CI dependencies), all of which are now fixed. The patch is well-motivated: it prevents Cargo from treating the entire Git repository as a single crate, which is especially important for downstream projects that vendor Git’s C code while excluding its Rust components. The commit message clearly explains the rationale, and the changes are purely mechanical path updates with no functional impact.

The series is now ready for integration, assuming no new issues surface in review. It establishes a clean organizational precedent for Git’s mixed C/Rust codebase and supports the project’s long-term Rustification goals, including the upcoming Git 3.0 release where Rust components will become mandatory.
