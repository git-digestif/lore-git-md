This is the fifth patch in Johannes Schindelin’s seven-patch series fixing Coverity-reported issues in Git for Windows post v2.56.0-rc0. It is a **test-only patch** targeting the reftable unit-test suite.

The patch plugs a latent NULL-dereference bug in `test_reftable_table__seek_invalid_log_offset()`. The test, introduced by commit a1c085df8dcb (reftable/table: fix NULL pointer access when seeking to bogus offsets, 2026-07-03), previously ignored the return value of `reftable_table_init_log_iterator()`, which can fail with `REFTABLE_OUT_OF_MEMORY_ERROR` and leave the iterator’s ops table uninitialized. If initialization fails, the subsequent call to `reftable_iterator_seek_log()` dereferences a NULL function pointer. The fix adds a `cl_assert_equal_i()` check to ensure the iterator is successfully initialized before proceeding.

The change is minimal—one line added—and purely defensive. It does not alter any production code, only the unit test’s robustness. The patch is uncontroversial and aligns with the series’ overall goal of hardening against static-analysis warnings. No follow-up discussion is expected beyond routine review.
