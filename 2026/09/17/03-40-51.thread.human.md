This thread is about enabling `RUNTIME_PREFIX` support on OpenBSD by using the system’s `getexecpath()` function to locate Git’s binary at runtime. The patch, authored by Brad Smith, allows Git to be installed in non-standard prefixes while still finding its support files, which is particularly useful for package managers and custom installations.

Junio C Hamano provided substantive review feedback on the initial patch, focusing on the commit message rather than the code itself. He requested clarification on why `getexecpath()` is preferable to the existing BSD sysctl-based method, whether the old method is being deprecated, and the accuracy or advantages of `getexecpath()` over sysctl. Brad has since responded, explaining that `getexecpath()` is the first proper API for resolving the executable path on OpenBSD, replacing a "pile of hacks" that produced inconsistent results. The new method is described as more accurate and consistent, though this rationale has not yet been incorporated into the commit message. The patch already enforces the use of `getexecpath()` only on OpenBSD 8.0 and later.

The technical implementation remains unchanged: it adds a `git_get_exec_path_getexecpath()` wrapper in `exec-cmd.c`, defines `HAVE_GETEXECPATH` in the `Makefile`, and gates the feature to OpenBSD 8.0+ in `config.mak.uname`. The patch follows the established pattern for `RUNTIME_PREFIX` support on other platforms and introduces no new CLI options, config keys, or on-disk format changes. No other participants have weighed in, and the patch is still under review with no merge status reported. If Brad addresses the remaining gaps in the commit message—particularly the version range in the title and the rationale for preferring `getexecpath()`—the patch appears uncontroversial and ready for merging.
