This thread is about a small but useful platform-compatibility patch from Brad Smith that enables `RUNTIME_PREFIX` support for OpenBSD. The patch adds runtime detection of Git's own binary location using OpenBSD's `getexecpath()` function, which was introduced in OpenBSD 8.0. This allows Git to be installed in non-standard locations while still finding its support files, a feature that's particularly helpful for package managers or users with custom installation prefixes.

The implementation is minimal and follows the established pattern used for other platforms: it adds a new wrapper function in `exec-cmd.c`, updates the build system to detect the feature, and enables it specifically for OpenBSD 8.0 and later. The patch touches only the necessary files (`exec-cmd.c`, `Makefile`, and `config.mak.uname`) and doesn't include test coverage, which is typical for platform-specific runtime detection code that's hard to test in a cross-platform way.

So far, the patch appears uncontroversial and well-crafted, aligning with the project's existing approach to `RUNTIME_PREFIX` support. Unless someone raises concerns about the stability of OpenBSD's `getexecpath()` implementation, this should be a straightforward addition that improves Git's usability on OpenBSD.
