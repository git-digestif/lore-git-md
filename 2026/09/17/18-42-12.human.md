This is the first patch in a three-part series that refactors Git’s config-parameter handling to support deferring auto maintenance during sequencer operations. It introduces `git_config_append_parameter()`, a helper that formats a single `'key'='value'` pair into a `strbuf` with proper shell quoting. The existing `git_config_push_split_parameter()` is updated to use this helper, making the code more modular and reusable.

The motivation is straightforward: the sequencer (used by `git rebase`, `git cherry-pick`, and `git revert`) needs to disable auto maintenance for individual commands spawned during the operation, and this helper allows it to build the `GIT_CONFIG_PARAMETERS` environment variable incrementally. The header comment now clearly documents the format (a space-separated list of quoted pairs) and behavior (a `NULL` value is treated as boolean `true`), addressing Patrick Steinhardt’s earlier feedback about undocumented assumptions.

The patch is a clean refactoring with no behavior change. It touches only `config.c` and `config.h`, and the diff is minimal and focused. The commit message is concise and explains the purpose well. This helper is uncontroversial and ready for integration; its real value will become clear in the next patch, where it is used to implement the maintenance deferral logic.
