This is the first patch in Johannes Schindelin’s seven-part series fixing Coverity-reported issues in Git for Windows post-v2.56.0-rc0. It addresses a potential signed overflow in `writev_in_full()`, a wrapper introduced just last month (d70eb7f3600d, August 2026). The fix is straightforward: before adding each successful `xwritev()` chunk to the running total, the code now checks whether the sum would exceed `SSIZE_MAX` and, if so, fails the operation with `errno = EOVERFLOW`.

The patch is minimal—four lines in `wrapper.c`—and purely defensive. No behavior change is intended; it simply plugs a static-analysis warning that Coverity flagged as a possible integer-overflow bug. The commit message is clear and cites the exact Coverity report, the offending commit, and the rationale. This looks like a textbook hardening patch: small, targeted, and uncontroversial. If the series as a whole is queued for review, this patch is likely to sail through without debate.
