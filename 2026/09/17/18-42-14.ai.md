This is the third and final patch in the v5 series adjusting when auto maintenance runs during sequencer-driven operations (`git rebase`, `git cherry-pick`, `git revert`). The patch disables auto maintenance for all commands spawned by the sequencer (`git commit`, `git merge`, and exec commands) by passing `maintenance.auto=false` via `GIT_CONFIG_PARAMETERS`. This ensures auto maintenance runs exactly once at sequence completion, matching the apply backend’s behavior and preventing interference with intermediate steps.

The implementation uses the `disable_auto_maintenance()` helper introduced in patch 1, which builds and caches the config string in the `replay_ctx` struct. The cached string is appended to the environment of every spawned command, overriding any user settings. The patch updates `run_git_commit()`, `do_merge()`, and `do_exec()` to call this helper, and modifies `continue_single_pick()` to handle single-pick cases (e.g., `cherry-pick <commit>`) that bypass the main `pick_commits()` loop.

Test coverage in `t/t3418-rebase-continue.sh` and `t/t3510-cherry-pick-sequence.sh` has been expanded to verify auto maintenance is deferred until sequence completion. The rebase test now explicitly triggers a conflict (both branches add `F2`) and confirms maintenance runs only after the final `--continue`. The cherry-pick tests cover single-pick, sequence, `--continue`, and `--skip` scenarios, using `GIT_TRACE2_EVENT` to assert maintenance is invoked exactly once. The tests also check that intermediate commits (e.g., conflict resolutions) do not trigger maintenance.

The patch is technically uncontroversial and addresses all prior feedback. The design—delegating maintenance to built-in commands rather than the sequencer—has been settled, with the commit message now clearly documenting why the sequencer cannot reliably trigger maintenance at a single exit point (single-pick cases bypass `pick_commits()`). The series is code-identical to v4 and appears ready for `next`. The only unresolved hypothetical is whether very long sequences might benefit from mid-sequence repacking, but no concrete issue has been identified.
