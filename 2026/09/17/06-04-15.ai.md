This is the fifth iteration of Mike Hommey’s patch series moving Git’s Rust code into a dedicated `rust/` subdirectory. The patch is now technically complete: it updates all build system references (Makefile, meson.build, .gitignore) and—critically—fixes the CI breakage Junio reported in v4 by updating `ci/run-rust-checks.sh` to look for Rust files in their new location. The reorganization itself is uncontroversial; the only remaining discussion is about long-term forward-compatibility for downstream projects when Git 3.0 makes Rust components mandatory.

Key files touched: `.gitignore`, `Makefile`, `meson.build`, `ci/run-rust-checks.sh`, and the entire Rust source tree (relocated from `src/` to `rust/`). The patch preserves all Rust functionality while preventing Cargo from treating the entire Git repository as a single crate, which supports downstream projects that vendor Git’s C code while excluding its Rust components. The CI script now correctly checks formatting, clippy warnings, and minimum Rust version in the new `rust/` directory.

This version addresses all prior mechanical feedback and should be ready for integration once Junio confirms the CI fix. The only open question is whether Mike’s proposed solution—publishing the `gitcore` crate to crates.io under a Git project namespace—will be adopted as the official path forward for handling mixed C/Rust dependencies post-Git 3.0. That discussion is orthogonal to this patch and can proceed separately.
