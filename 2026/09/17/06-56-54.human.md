This is a small feature patch for `git-contacts`, a contrib script that helps identify people to CC on patches. The author, Brigham Campbell, has posted a v2 that lets the script read patch content from stdin when no arguments are given and stdin isn’t a terminal. Junio C Hamano, the maintainer, suggested an alternative design: using the conventional UNIX `-` idiom (where `-` as a filename means “read from stdin”) instead of the current silent stdin behavior. This would allow mixing file arguments and stdin input (e.g., `git contacts patch1 - patch3 <patch2`) and avoid changing the usage comment.

Brigham’s reply is brief and pragmatic. He acknowledges considering the `-` approach but says his choice wasn’t particularly deliberate. He’s open to sending a v3 if Junio prefers the `-` idiom, but otherwise plans to wait for further review on v2. The tone is cooperative and low-stakes—this is a minor interface tweak, not a deep technical debate.

The patch itself is well-scoped and uncontroversial. It touches only `contrib/contacts/git-contacts`, a Perl script, and doesn’t introduce new CLI options or on-disk formats. The v2 already incorporates Junio’s stylistic feedback (commit message trailers, argument-handling refactor, usage comment update), so the code quality looks solid. The open question is purely about interface design: silent stdin vs. explicit `-`. Either approach would work, and the decision hinges on which convention feels more natural for this script.

If you use `git-contacts` with external tools like `b4`, this patch is worth noting—it makes the script more flexible. Otherwise, it’s a small quality-of-life improvement for a niche contrib tool. No urgency here, but it’s ready to merge once the interface choice is settled.
