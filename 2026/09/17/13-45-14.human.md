This is a platform compatibility patch for OpenBSD, addressing feedback from Junio C Hamano on Brad Smith’s initial submission. The patch enables `RUNTIME_PREFIX` support on OpenBSD by using the system’s `getexecpath()` function to resolve Git’s binary location at runtime, which is essential for installations in non-standard prefixes.

Junio’s review highlights that the original commit message was too terse—it didn’t explain why `getexecpath()` is preferable to the existing method (BSD sysctl), whether the old method is being deprecated, or which OpenBSD versions support the new function. The patch itself is technically sound, following the established pattern for `RUNTIME_PREFIX` on other platforms (e.g., Darwin’s `NSGetExecutablePath`), but the lack of context left key questions unanswered. The updated version should clarify these points, particularly the version gating (OpenBSD 8.0+) and the practical benefits of switching.

The implementation is minimal and focused: it adds a new `git_get_exec_path_getexecpath()` wrapper in `exec-cmd.c`, defines `HAVE_GETEXECPATH` in the `Makefile`, and enables the feature in `config.mak.uname` for OpenBSD 8+. No new CLI options, config keys, or on-disk format changes are introduced, and the patch doesn’t include test coverage, which is consistent with other platform-specific runtime detection code.

This looks like a straightforward improvement for OpenBSD users, especially package maintainers or those installing Git in custom locations. The patch is unlikely to be controversial once the commit message addresses Junio’s concerns, but the version gating (OpenBSD 8.0+) might prompt discussion about whether older releases should retain the sysctl fallback. For now, the patch is under review and awaits a revised version from the author.
