This is the first patch in Johannes Schindelin’s seven-part series fixing Coverity-reported issues in Git for Windows post-v2.56.0-rc0. It targets a potential signed overflow in `writev_in_full()`—a helper introduced in commit d70eb7f3600d (wrapper: introduce writev(3p) wrappers, 2026-08-07). The fix adds a defensive check using `signed_add_overflows()` to detect when the cumulative byte count (`total_written`) would exceed `SSIZE_MAX`, treating it as an I/O failure with `errno = EOVERFLOW`.

The patch is minimal and surgical: it touches only `wrapper.c`, adding four lines of code to guard the accumulation loop. No new symbols are introduced, and the change is purely defensive—no behavior is altered for normal operation. The commit message clearly identifies the Coverity report’s concern and the specific commit that introduced the unchecked accumulation, making the motivation unambiguous.

This fix stands out as the most serious issue in the series, as signed overflow in I/O operations could lead to silent data corruption or undefined behavior. The use of `signed_add_overflows()` aligns with Git’s existing overflow-checking patterns, and the choice of `EOVERFLOW` as the error code is idiomatic for this class of problem. The patch is unlikely to be controversial, though follow-up discussion might explore whether similar overflow risks exist elsewhere in the codebase’s I/O helpers.
