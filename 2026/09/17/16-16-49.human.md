This is a minor documentation suggestion about the Git v2.56.0-rc1 release notes. Tuomas Ahola points out that the phrasing of one entry—describing a segfault fix in `git history` when a tree object is missing—could be slightly clearer. The current wording ("can segfault") might read as if the bug is still present, so Tuomas suggests adding "which has been corrected" to make it unambiguous that the issue is fixed. This is a surface-level, nitpick-style observation about the release notes' wording, not a technical critique of the code itself. The change, if adopted, would be purely editorial and would not affect the release's functionality.
