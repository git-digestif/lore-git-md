This is the fourth patch in Johannes Schindelin’s seven-patch series fixing Coverity-reported issues in Git for Windows after v2.56.0-rc0. It targets a latent defect in the `rerere` subsystem that has existed since 2015: when writing the preimage or postimage of a conflict resolution fails, the code still marks the variant as resolved, potentially replaying incomplete or corrupted data in later invocations.

The patch adds missing error handling around `handle_file()` and `copy_file()` calls in `do_rerere_one_path()`. If either operation fails, the function now reports the error, leaves the rerere status unchanged, and (where applicable) removes any partially written files. The changes are confined to `rerere.c` and introduce no new symbols or behavior changes—only defensive checks that prevent silent data corruption.

The fix is narrow and uncontroversial: it plugs a clear resource-leak and data-integrity hole without altering the intended workflow. The commit message traces the defect to its introduction in commit 629716d256a7 (2015) and explains why Coverity only flagged it recently. No follow-up work is implied beyond the immediate fix. This patch is likely to be merged as-is once the series completes review.
