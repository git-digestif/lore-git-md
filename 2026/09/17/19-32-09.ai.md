This is a substantive review comment on the second patch in Johannes Schindelin’s seven-patch series fixing Coverity-reported issues in Git for Windows. Junio C Hamano suggests an alternative design: instead of propagating the new `slen` parameter through `get_format_by_sig()` and its callers, drop the parameter from `check_signature()` entirely, since all existing callers already pass a NUL-terminated buffer from a `strbuf`. The implication is that the length-aware `starts_with_mem()` check could be confined to `get_format_by_sig()` without changing the public interface of `check_signature()`. This would simplify the patch by avoiding a cascade of signature changes across multiple functions, while still addressing the buffer-overread risk. The review does not question the correctness of the fix but proposes a less invasive implementation path.
