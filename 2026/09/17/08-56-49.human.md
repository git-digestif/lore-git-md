This is a bug report with a clear reproducer for `git rerere remaining`. The author, Mikko Rantalainen, identifies a bug where `git rerere remaining` skips consecutive conflicted paths when each path has only a stage-1 index entry. This causes `git mergetool` to exit successfully while unresolved conflicts still remain, as `mergetool` relies on `rerere remaining` to determine which paths to process.

The issue is traced to `check_one_conflict()` in `rerere.c`, where a loop intended to skip multiple stage-1 entries for the same conflicted pathname instead skips entries for the *next* pathname. The author suggests a potential fix involving an additional same-path check using `ce_same_name()`. The provided reproducer script demonstrates the bug by creating a rebase scenario with two files renamed differently in two branches, leaving consecutive stage-1-only conflicts that `rerere remaining` fails to report fully.

The bug is well-documented, with a minimal reproducer, clear expected vs. actual behavior, and a plausible root cause. The author notes the issue has likely existed for years, as the relevant code hasn’t changed in the last eight years. While the fix is not yet submitted as a patch, the analysis and reproducer make it easy for a maintainer to verify and address. This looks like a real, actionable bug that could affect users during complex rebases.
