This is an **announcement of Git for Windows 2.56.0-rc1**, the first release candidate for the next version of Git for Windows. It is not a patch to Git itself, but a downstream packaging of upstream Git 2.56.0-rc1 with Windows-specific fixes and tooling updates.

The release drops support for Windows 8.1, following the MSYS2 project on which Git for Windows is based. This change alters internal paths: `/mingw64/bin/git.exe` is no longer present, replaced by `/ucrt64/bin/git.exe`. Users are encouraged to switch to `/cmd/git.exe` for stability. The installer is now properly 64-bit, fixing a regression in the previous version (2.55.0(5)) where the "Use external OpenSSH" option was incorrectly disabled, forcing the bundled OpenSSH to be installed. Users relying on external OpenSSH should re-run the installer to restore their preference.

New features include bundling Git 2.56.0-rc1, Git LFS 3.8.0, cURL 8.22.0, and OpenSSL 3.5.8. Bug fixes address a 4GB object commit limit, a stack-smashing crash in parallel checkouts, and a regression in the previous release where Vim would often open files with the first line missing. The announcement provides download links for 64-bit, ARM64, and 32-bit installers, portable builds, and MinGit variants, along with SHA-256 checksums for verification.

This is a routine release candidate for Git for Windows, not a source-level change to Git. Users who rely on Git for Windows should review the OpenSSH installer regression and the Windows 8.1 deprecation notice, but there is no action required for those not affected. The release appears well-tested and addresses several platform-specific issues.
