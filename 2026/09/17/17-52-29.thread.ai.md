Subject: [PATCH 0/7] Fix Coverity-reported issues in Git for Windows post v2.56.0-rc0
Series version: v1 (initial submission)
Originating author: Johannes Schindelin
Thread type: patch series (hardening, static-analysis fixes for Git for Windows)

Core problem or goal
Address seven Coverity-reported static-analysis warnings that surfaced in Git for Windows after merging v2.56.0-rc0. The issues span potential signed-overflow in writev, missing input validation in GPG signature parsing, MIDX pack-ID checks, rerere conflict resolution edge cases, reftable iterator initialization, and fuzz-testing harnesses. The series is purely defensive programming with no intended behavior changes.

Current status
Under review; queued as GitGitGadget PR-2231. Base commit is 12cb6293d6 (v2.56.0-rc0). No prior versions exist.

Key technical details
Files touched: wrapper.c (writev_in_full overflow check), gpg-interface.c (signature-prefix matching via starts_with_mem), midx.c (pack-ID validation), rerere.c (conflict resolution error handling), unit tests for reftable iterator, oss-fuzz reftable harness, test-read-midx helper.
New/renamed symbols: none.
Behavior changes: none; only defensive checks added.
On-disk format changes: none.
Test coverage: existing unit tests and fuzz harnesses extended for edge cases. The writev fix adds a guard against SSIZE_MAX overflow using signed_add_overflows() and returns EOVERFLOW on detection, targeting a helper introduced in commit d70eb7f3600d (wrapper: introduce writev(3p) wrappers, 2026-08-07). The GPG fix replaces starts_with() with starts_with_mem() in get_format_by_sig() to prevent buffer overreads when matching signature prefixes, addressing a latent defect exposed by commit c8762c30df5b (object-file-convert: convert tag objects when writing, 2023-10-01) and observable after 215d305f450f (odb: compute compat object ID in odb_write_object_ext(), 2026-07-17). The MIDX fix adds a bounds check on local pack IDs before converting to chain-global IDs, preventing potential underflow or invalid memory access when resolving MIDX layers via nth_midxed_pack(). The rerere fix adds error handling around handle_file() and copy_file() calls in do_rerere_one_path(); if either operation fails, the function now reports the error, leaves the rerere status unchanged, and removes any partially written files, addressing a defect introduced in commit 629716d256a7 (2015).

Open questions and loose ends
- Whether the added checks fully address Coverity’s concerns or if deeper design issues remain, particularly in GPG and MIDX subsystems.
- Potential follow-up discussion on whether similar overflow risks exist in other I/O helpers beyond writev_in_full().
- Whether additional length-aware checks are needed elsewhere in the GPG subsystem, given the pattern identified in this patch.
