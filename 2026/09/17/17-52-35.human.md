This is the sixth patch in Johannes Schindelin’s seven-patch series fixing Coverity-reported issues in Git for Windows after v2.56.0-rc0. It plugs a NULL-dereference bug in the oss-fuzz reftable fuzzer (`oss-fuzz/fuzz-reftable.c`).

The patch addresses a Coverity warning that the fuzzer ignored initialization failures from `reftable_table_init_ref_iterator()` and `reftable_table_init_log_iterator()`. Under memory-allocation failure, either function can return `REFTABLE_OUT_OF_MEMORY_ERROR` without installing an ops table, so a subsequent `reftable_iterator_seek_*()` call would dereference NULL. The fix wraps each initialization in a success check; if initialization fails, the fuzzer skips the seek and iteration but still safely destroys the uninitialized iterator.

The change is purely defensive and touches only the fuzzer harness—no production code, no behavior change, and no new dependencies. It looks like a straightforward, uncontroversial hardening patch that matches the rest of the series.
