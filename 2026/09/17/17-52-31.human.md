This is the second patch in Johannes Schindelin’s seven-patch series fixing Coverity-reported issues in Git for Windows after v2.56.0-rc0. It addresses a latent buffer-read-overrun in GPG signature parsing that has existed since v2.45.0 but became reachable only after recent object-conversion changes.

The bug is straightforward: `parse_signed_buffer()` receives an exact-sized buffer from `convert_tag_object()`, yet `get_format_by_sig()` uses `starts_with()`, which expects a NUL-terminated string. A tag payload ending in a partial signature prefix (e.g., a lone '-') could therefore trigger an invalid read past the allocation, potentially crashing Git or corrupting the compat-hash object being written. The fix replaces `starts_with()` with `starts_with_mem()`, which respects the known buffer length, and propagates the length parameter through the call chain.

The commit message is unusually thorough, tracing the defect’s history, explaining why it was missed in earlier reviews, and crediting the helper function (`starts_with_mem()`) that was added precisely for this kind of problem. No behavior change is intended—this is purely a hardening patch. The change is confined to `gpg-interface.c` and looks uncontroversial. If any discussion arises, it will likely focus on whether similar length-aware checks should be added elsewhere in the GPG subsystem.
