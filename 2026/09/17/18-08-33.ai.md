This is an **announcement email** for **Git for Windows 2.56.0-rc1**, the first release candidate of the Windows-specific distribution of Git. It is *not* an upstream Git patch or development discussion, but a packaging and platform-specific release notice.

The email announces the availability of Git for Windows 2.56.0-rc1, which tracks upstream Git v2.56.0-rc1. Key changes include dropping support for Windows 8.1 (following the MSYS2 project), which alters internal paths (e.g., `/ucrt64/bin/git.exe` replaces `/mingw64/bin/git.exe`). Users are advised to use `/cmd/git.exe` for stability. The installer is now 64-bit, fixing a regression in v2.55.0(5) that disabled the "Use external OpenSSH" option for some users. Affected users must re-run the installer to re-enable external OpenSSH if needed.

New bundled versions include Git LFS v3.8.0, cURL v8.22.0, and OpenSSL v3.5.8. Bug fixes address a 4GB object commit limit, a stack-smashing crash in parallel checkouts, and a vim integration bug that omitted the first line of files. The email provides SHA-256 checksums for all downloadable artifacts (installers, portable builds, and MinGit variants for 32/64-bit and ARM64 architectures).

This release is specific to Git for Windows and does not affect upstream Git development. The changes are primarily packaging, installer, and platform compatibility fixes rather than core Git functionality. Users relying on external OpenSSH or affected by the vim bug should pay particular attention to the upgrade instructions. The announcement is routine and does not signal any controversy or major architectural shift.
