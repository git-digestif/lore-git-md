This is the second patch in the v5 series adjusting when auto maintenance runs during sequencer-driven operations (`git rebase`, `git cherry-pick`, `git revert`). The patch implements the core behavior change: deferring auto maintenance until sequence completion by invoking `git maintenance run --auto` in the built-in command wrappers (`builtin/rebase.c` and `builtin/revert.c`) rather than the sequencer itself.

The patch modifies `run_specific_rebase()` to trigger maintenance only after a successful merge-backend rebase (when the sequencer’s state directory is gone) and updates `run_sequencer()` in `builtin/revert.c` to run maintenance after any successful sequencer operation (`--continue`, `--skip`, or a single pick). The commit message now explicitly justifies why the sequencer cannot reliably trigger maintenance at a single exit point: single-pick cases (`cherry-pick <commit>`, `revert <commit>`, and their `--continue`/`--skip` variants) bypass `pick_commits()` entirely, exiting early through `continue_single_pick()` or `skip_single_pick()`. This design choice—delegating maintenance to the built-in commands—was previously contested but is now settled and documented.

Test coverage is expanded in `t/t3418-rebase-continue.sh` and `t/t3510-cherry-pick-sequence.sh` to verify that `git maintenance run --auto` executes exactly once at sequence completion and not during intermediate steps. The rebase test now explicitly confirms it triggers a conflict (both topic and main branches add `F2`), and the failing exec ensures maintenance only runs at the very end. The cherry-pick tests cover both single-pick and sequence cases, including `--continue`/`--skip` scenarios, and use `GIT_TRACE2_EVENT` to assert the absence of maintenance during intermediate steps.

The patch is technically sound and addresses all prior reviewer feedback. The implementation is minimal and focused, touching only the necessary call sites and avoiding changes to the sequencer’s internals. The commit message is concise yet thorough, documenting the design rationale and edge cases.
