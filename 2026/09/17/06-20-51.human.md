This is a bugfix patch targeting the Git protocol v2 `upload-pack` subsystem. The patch resolves a long-standing client-side crash (`fatal: expected 'packfile', received 'shallow-info'`) that occurs during shallow fetches when `uploadpack.allowRefInWanted` is enabled. The issue stems from a misordered function call in `upload_pack_v2()`: the server was sending "wanted-refs" before "shallow-info", but the client expects "shallow-info" first due to its `peek` logic in `process_section_header()`. The fix is minimal—swapping the order of `send_shallow_info()` and `send_wanted_ref_info()`—and is validated by two new test cases covering both single-commit shallow clones and incremental shallow fetches.

The regression has existed since the introduction of the ref-in-want feature in 2018 but was latent because the feature combination (`uploadpack.allowRefInWanted` with shallow fetches) was previously unusable. The patch is server-side only and maintains backward compatibility, as no existing clients relied on the broken behavior. The patch touches only `upload-pack.c` (one line moved) and the test suite (`t/t5703-upload-pack-ref-in-want.sh`), with no new symbols or on-disk format changes. Test coverage is thorough, verifying both ref resolution and commit history in shallow fetch scenarios.
