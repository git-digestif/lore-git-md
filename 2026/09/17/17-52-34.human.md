This is the fifth patch in Johannes Schindelin’s seven-patch series fixing Coverity-reported issues in Git for Windows after v2.56.0-rc0. It targets a unit test for the reftable backend.

The patch plugs a NULL-dereference risk in `test_reftable_table__seek_invalid_log_offset()`. The test calls `reftable_table_init_log_iterator()` but ignores its return value; if initialization fails (e.g., due to out-of-memory), the iterator’s ops table remains NULL, and the subsequent `reftable_iterator_seek_log()` call dereferences it. The fix is a one-line addition that asserts the initialization succeeds before proceeding.

The change is purely defensive and uncontroversial: it tightens test robustness without altering production behavior. The patch touches only the unit-test file `t/unit-tests/u-reftable-table.c` and is part of the broader hardening effort described in the series cover letter.
