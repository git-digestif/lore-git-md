This is the sixth patch in Johannes Schindelin’s seven-patch series fixing Coverity-reported issues in Git for Windows post-v2.56.0-rc0. It plugs a NULL-dereference bug in the oss-fuzz reftable fuzzer (`oss-fuzz/fuzz-reftable.c`).

The patch addresses a Coverity warning that the fuzzer ignored initialization failures from `reftable_table_init_ref_iterator()` and `reftable_table_init_log_iterator()`. Under memory-allocation failure, either function can return `REFTABLE_OUT_OF_MEMORY_ERROR` without installing an ops table, leaving the iterator in an uninitialized state. A subsequent call to `reftable_iterator_seek_ref()` or `reftable_iterator_seek_log()` would then dereference a NULL function pointer.

The fix is straightforward: check the return value of the initialization functions and skip the seek/iteration loop if initialization fails. The iterator is still safely destroyed afterward, regardless of its state. The change is purely defensive and does not alter the fuzzer’s intended behavior—it simply avoids crashing on allocation failure. The patch is uncontroversial and aligns with the hardening theme of the series.
