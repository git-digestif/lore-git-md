Subject: [PATCH] exec-cmd: add OpenBSD getexecpath() support for RUNTIME_PREFIX
Series version: standalone patch
Originating author: Brad Smith <brad@comstyle.com>
Thread type: platform compatibility patch

Core problem or goal
Enable `RUNTIME_PREFIX` support on OpenBSD by using the system’s `getexecpath()` function to resolve Git’s binary location at runtime. This allows Git to be installed in non-standard prefixes while still locating its support files, aiding package managers and custom installations.

Current status
Under review; no prior versions. The patch is minimal, touching only `exec-cmd.c`, `Makefile`, and `config.mak.uname` to add the new detection and wrapper function.

Key technical details
- New function: `git_get_exec_path_getexecpath()` in `exec-cmd.c`
- New `HAVE_GETEXECPATH` define in `Makefile`
- OpenBSD 8.0+ gating in `config.mak.uname`
- No new CLI options, config keys, or on-disk format changes
- No test coverage (consistent with other platform-specific runtime detection)

Open questions and loose ends
None raised yet; the patch is expected to be uncontroversial unless concerns arise about `getexecpath()` stability on OpenBSD.

Participant positions
None recorded yet; the patch has not yet received review.

Related work
Follows the established pattern for `RUNTIME_PREFIX` support on other platforms (e.g., BSD sysctl, Darwin’s `NSGetExecutablePath`).
