- [2026/09/11/19-08-48 by Johannes Schindelin via GitGitGadget <gitgitgadget@gmail.com>] Johannes Schindelin posted [PATCH v2 0/2] "Use Rust in the Windows CI jobs", whose changelog states the UCRT64 clang/gcc inconsistency pointed out by Junio was fixed by clarifying that UCRT64 uses GCC; the cover letter also asks (RFH) whether the series builds on GitLab's `saas-windows-medium-amd64` runner without further changes.
- [2026/09/11/19-08-50 by Johannes Schindelin via GitGitGadget <gitgitgadget@gmail.com>] The v2 range-diff for [PATCH v2 2/2] "ci(windows): build with Rust" shows the workflow's UCRT64 case changed from `x86_64-pc-windows-gnullvm` to `x86_64-pc-windows-gnu`, and adds a "Helped-by: Junio C Hamano" trailer.
- [2026/09/11/21-09-46 by Junio C Hamano <gitster@pobox.com>] Junio C Hamano suggested that [PATCH v2 1/2] use `CARGO_BUILD_TARGET` instead of `CARGO_TARGET` to match Cargo's officially supported environment variable and to work better with the `jc/rust-cargo-build-target` topic (after James Le Cuirot had written a commit respecting `CARGO_BUILD_TARGET` when locating build output).
- [2026/09/11/22-26-11 by James Le Cuirot <chewi@gentoo.org>] James Le Cuirot agreed with Junio that `--target` should not be set explicitly at all, advising to avoid setting `CARGO_BUILD_TARGET` (or passing `--target`) when not cross-compiling, since an explicit target changes Cargo's behavior (e.g., `RUSTFLAGS` then applies only to target binaries, not build-host binaries).
