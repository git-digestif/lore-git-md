This thread began with Patrick Steinhardt’s minimal fix to restore GitLab CI’s documentation job by ensuring Ruby was available for Asciidoctor installation. It quickly evolved into a broader modernization effort when Jeff King (Peff) identified an outdated version pin in the CI configuration and proposed a two-patch series to remove dead code and switch to the system-provided Asciidoctor package. The original fix and Jeff’s follow-up are now fully merged to `master`, with Junio confirming the final patch landed in commit `47ce80527c` after the v2.56.0-rc0 tag.

The key change replaces a manual, version-pinned `gem install asciidoctor -v 1.5.8` with a simpler `apt-get install asciidoctor`, eliminating maintenance overhead and aligning CI with real-world user environments (Debian 11, RHEL 8). The Ubuntu image’s default Asciidoctor version (2.0.20) is now used, and the change has been validated in GitHub Actions. A minor loose end—the undocumented role of the `concurrent-ruby` gem—remains unresolved but doesn’t affect the merged work. The thread also sparked a tangential discussion about the long-term viability of supporting both Asciidoc and Asciidoctor, though no concrete proposals emerged.
