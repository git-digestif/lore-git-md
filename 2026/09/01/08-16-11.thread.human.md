This thread began with Patrick Steinhardt’s minimal fix to restore GitLab CI’s documentation job by ensuring Ruby was available for Asciidoctor installation. It quickly evolved into a broader modernization effort when Jeff King identified an outdated version pin in the CI configuration and proposed a two-patch series to remove dead code and switch to the system-provided Asciidoctor package. The original fix and Jeff’s follow-up are now fully merged to `master`, with Junio C Hamano confirming the final patch—replacing the manual `gem install` with `apt-get install asciidoctor`—has been queued and will land shortly.

The key outcome is a simplified and more maintainable CI setup: the Ubuntu image’s default Asciidoctor version (2.0.20) is now used, matching what users on Debian 11, RHEL 8, and GitHub Actions already have. This eliminates the 2018-era pin to 1.5.8, which had lingered long after its original compatibility blocker was resolved in 2019. The dependency chain—Patrick’s Ruby fix, Jeff’s dead-code removal, then the system-package switch—has been respected, and the thread’s original goal is now complete.

A tangential discussion about the long-term viability of supporting both Asciidoc and Asciidoctor remains open but exploratory, with no immediate changes proposed. The only loose end is the undocumented role of the `concurrent-ruby` gem, though this does not affect the merged changes. All substantive review feedback has been addressed, and no further action is needed.
