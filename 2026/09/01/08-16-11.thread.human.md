This thread began as a quick fix to restore GitLab CI’s documentation build after a transitive dependency removal broke the Asciidoctor installation, then evolved into a small but useful modernization of the CI configuration. Patrick Steinhardt’s original patch (`ps/ci-depends-on-ruby`) is already merged, ensuring Ruby is available for `gem install asciidoctor`. Jeff King followed up with a two-patch series (`jk/ci-use-system-asciidoctor`) to remove dead code and replace the outdated version-pinned `gem install asciidoctor -v 1.5.8` with `apt-get install asciidoctor`, using the system-provided version (2.0.20) that matches what users have locally. The first patch in Jeff’s series is merged; the second was resent by Tuomas Ahola as a standalone patch and is ready for Junio to merge—it just needs to be applied after Jeff’s first patch and Patrick’s original fix.

The discussion has been entirely cooperative and low-drama. Patrick raised a couple of tangential questions—whether the `concurrent-ruby` gem is necessary (it’s now handled by the system package, but its purpose remains undocumented) and whether forward compatibility with older Asciidoctor versions is worth testing (Jeff dismissed this, arguing that users on outdated versions can file bug reports if issues arise). Both points are now closed. Todd Zullinger added useful context about Asciidoctor packaging in RHEL and its clones, noting that the package lives in EPEL and is currently unmaintained, but this doesn’t affect the current patch. The only open question is a forward-looking one Jeff floated in the latest email: whether Git should eventually drop Asciidoc support entirely, keeping only Asciidoctor. He framed it as a hypothetical future cleanup, not an immediate concern, and the thread remains focused on the ready-to-merge CI patches.
