This thread is about a 13-patch series from Patrick Steinhardt that refactors Git’s object database (ODB) subsystem to remove ad-hoc source linking, simplifying the code and preparing for future ODB abstraction work. The series is now in its third version (v3), posted on September 8, 2026, with no functional changes—just a minor commit message tweak to clarify a detail in patch 5.

The core goal is to eliminate the dual use of the ODB sources list for both alternates and temporary sources (like submodules), which has been a source of complexity. The series also continues the broader effort to remove implicit dependencies on `the_repository`, ensuring functions explicitly receive the repository they operate on. Key changes include removing functions like `odb_add_submodule_source_by_path()`, updating `submodule-config.c` to accept an explicit `struct repository *` parameter, and enforcing stricter constraints in `git multi-pack-index`.

The series is fully reviewed and uncontroversial. Junio C Hamano gave unqualified approval to patches 1 and 6 in the first version, while Karthik Nayak and Justin Tobler provided substantive reviews for the rest in v2, confirming the correctness of the refactoring. The latest patch (4/13) in this update removes the last uses of `the_hash_algo` in `submodule-config.c`, replacing them with the repository’s or object ID’s hash algorithm—a mechanical but important step in removing global state dependencies.

No open questions remain, and the series is ready for Junio to pick up. It touches multiple subsystems (ODB, submodules, cache-tree, and test infrastructure) but introduces no on-disk format changes or behavioral regressions. The only breaking change is in `git multi-pack-index`, which now correctly rejects non-alternate object directories, aligning with documented behavior. The series is a clean, incremental improvement that paves the way for future ODB work.
