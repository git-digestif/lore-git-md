This thread is a 13-patch series from Patrick Steinhardt refactoring Git’s object database (ODB) subsystem to remove ad-hoc source linking, a legacy mechanism that allowed temporary or submodule object directories to be registered in-memory. The goal is to simplify the codebase and prepare for future ODB abstraction work. The series is now in its second version, posted on September 5, 2026, with all patches complete and addressing prior feedback.

Key changes include removing the last non-test callers of the ad-hoc source API, eliminating implicit dependencies on `the_repository`, and enforcing a long-documented constraint in `git multi-pack-index --object-dir=` (patch 10/13, just reviewed by Justin Tobler). This patch replaces silent ad-hoc source creation with an explicit error, aligning behavior with documentation and removing the final real-world caller of the mechanism. Other patches fix memory leaks, update test infrastructure, and remove unused submodule ODB registration code. Junio C Hamano approved two patches in the first version with strong praise, while Karthik Nayak and Justin Tobler provided substantive reviews for several patches in v2, confirming the correctness of the refactoring. The series is uncontroversial, with no outstanding objections, though Junio has not yet signaled merge intent.

The refactoring touches core ODB code, submodule handling, and test infrastructure, with no on-disk format changes. The only behavioral change is the enforcement in `git multi-pack-index`, which now rejects non-alternate object directories as documented since 2021. The series also continues the broader effort to remove `the_repository` globals, with Patrick confirming fixes for bugs where subsystems incorrectly used `the_repository` for submodule operations. The latest exchange between Patrick and Justin Tobler addressed a minor wording tweak in a commit message, but this is cosmetic and not a blocker. The series is now fully self-contained, with all callers of the ad-hoc API either updated or removed.
