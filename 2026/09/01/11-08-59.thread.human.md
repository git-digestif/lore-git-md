This thread is about a 13-patch series from Patrick Steinhardt that refactors Git’s object database (ODB) subsystem to remove an ad-hoc mechanism for registering in-memory sources, simplifying the codebase and paving the way for future ODB abstraction work. The series is now in its third version (v3), posted on September 8, 2026, and is fully reviewed and uncontroversial. The only change in v3 was a minor, surface-level tweak to a commit message in patch 5/13 to clarify repository context, addressing feedback from Justin Tobler.

The core goal is to eliminate dual-use of the ODB sources list for both alternates and temporary sources, which has been a source of complexity. The series also continues the broader effort to remove implicit dependencies on `the_repository` global state, touching subsystems like `cache-tree`, `submodule-config`, and `grep`. Key reviewers—Junio C Hamano (maintainer), Karthik Nayak, and Justin Tobler—have all provided substantive approvals, with Junio calling patches 1/13 and 6/13 "very nice" in v1. Karthik and Justin confirmed the correctness of the repository dependency encapsulation and the safe removal of unused infrastructure in v2.

The series is now complete, with all patches reviewed and ready for Junio’s queue. The only loose end is a NEEDSWORK comment in `builtin/grep.c` about a remaining thread-safety issue, but this is outside the scope of the series. The patches touch a wide range of files and symbols, including the removal of several ODB source registration functions, updates to test helpers, and a memory leak fix in the packed ODB source backend (patch 9/13). No on-disk format changes or behavioral regressions are expected, though patch 10/13 enforces an existing constraint in `git multi-pack-index --object-dir=` by rejecting non-alternate directories. The series is part of Patrick’s ongoing ODB abstraction work and has no external dependencies.
