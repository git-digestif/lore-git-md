Subject: [PATCH 0/13] odb: remove ad-hoc source linking
Series version: v3 (revision of v2; no functional changes, only a minor commit message tweak in patch 5/13 to clarify the repository context)
Originating author: Patrick Steinhardt
Thread type: patch series

Core problem or goal
Refactor the object database (ODB) subsystem to remove the mechanism allowing registration of in-memory sources (primarily used for submodules and temporary object directories). This eliminates dual-use of the ODB sources list for both alternates and temporary sources, simplifying the codebase and preparing for future migration of alternate handling into the "files" backend. The series also continues the broader `the_repository` removal effort by eliminating implicit dependencies on global state in the `cache-tree`, `submodule-config`, and related subsystems.

- Symbols removed: ODB source registration functions (`odb_add_submodule_source_by_path()`, `register_all_submodule_sources()`, `odb_add_to_alternates_memory()`, `tmp_objdir_add_as_alternate()`), `submodule_source_paths` string list in `struct object_database`, `GIT_TEST_FATAL_REGISTER_SUBMODULE_ODB` test mode, `#define USE_THE_REPOSITORY_VARIABLE` in `submodule-config.c`.
- Symbols modified: `must_prefetch_predicate` callback type extended to accept `void *cb_data` for repository context; all functions in `submodule-config.c` updated to accept `struct repository *` parameter; `hash_oid_string` updated to use the hash algorithm embedded in the object ID (`hash_algos[oid->algo].rawsz`). Patch 1/13 encapsulates the repository dependency within `cache-tree.c` by renaming `cache_tree_fully_valid()` to `cache_tree_fully_valid_recursive()` (file-scoped static) and adding a wrapper that delegates to it using `istate->repo`. The commit message for patch 1/13 explicitly states the change eliminates an implicit dependency on `the_repository` by ensuring the correct repository is used for object existence checks via the `index_state` parameter. Patch 2/13 updates `must_check_existence()` and `update_one()` to accept a `struct repository *` parameter, propagates it through `cache_tree_write()`/`cache_tree_read()`, and adjusts `prefetch_cache_entries()` to accept `void *cb_data`. The patch also removes the last dependency on registering submodule object databases with the main ODB, confirmed by tests with `GIT_TEST_FATAL_REGISTER_SUBMODULE_ODB=true` now passing. Patch 3/13 updates eight functions in `submodule-config.c` (`config_from_gitmodules()`, `config_from_path()`, `config_from_gitmodules_for_path()`, `config_from_gitmodules_for_name()`, `configset_in_gitmodules()`, `gitmodules_is_unmerged()`, `gitmodules_is_interesting()`, `gitmodules_config_oid()`) to accept an explicit `struct repository *` parameter, adjusting their callers in `builtin/fetch.c`, `builtin/grep.c`, `builtin/submodule--helper.c`, `submodule.c`, and `t/helper/test-submodule.c` to pass `the_repository` directly. The changes are mechanical and preserve behavior while eliminating implicit global state dependencies. Patch 4/13 updates `gitmodules_cb` to use `repo->hash_algo` and `hash_oid_string` to use `hash_algos[oid->algo].rawsz`, adding a defensive check to ensure the object ID is properly initialized. Patch 5/13 removes the last call to `odb_add_submodule_source_by_path()` in `submodule-config.c` (a 2019 workaround for `config_with_options()`’s limitation, made obsolete by commit `e3e8bf046e` in 2021 and the removal of implicit `the_repository` dependencies in earlier patches). The commit message for patch 5/13 was clarified in v3 to replace *"we register the repository's object database"* with *"we register that repository's object database"* to emphasize that the repository in question is a submodule, not `the_repository`. Patch 6/13 removes the now-unnecessary registration of submodule ODBs in `git grep`. Patch 7/13 removes the `submodule_source_paths` string list and deletes `odb_add_submodule_source_by_path()`/`register_all_submodule_sources()`. Patch 8/13 removes `tmp_objdir_add_as_alternate()`. Patch 9/13 adds a call to `odb_source_close(source)` in `odb/source-packed.c` to fix a memory leak. Patch 10/13 enforces the alternate-only constraint for `git multi-pack-index --object-dir=`, replacing ad-hoc source creation with an explicit error message (3 lines changed in `builtin/multi-pack-index.c` and 9 lines changed in `t/t5319-multi-pack-index.sh` to retain `repo64` for alternate validity). Patches 11/13 and 12/13 update test helpers to manage ODB sources explicitly, replacing `odb_add_to_alternates_memory()` with direct creation/freeing of standalone `odb_source_packed` instances. Patch 13/13 removes the final `odb_add_to_alternates_memory()` function (14 lines deleted).
