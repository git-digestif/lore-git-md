This thread is about enabling Rust compilation in Git’s GitHub Actions Windows CI workflows. Johannes Schindelin (via GitGitGadget) posted a two-patch series, now at version 4, that configures the Rust toolchain to target the GCC ABI (MinGW) instead of the default MSVC ABI. This ensures Cargo produces a static library (`libgitcore.a`) compatible with Git for Windows’ linker, unblocking the default Rust requirement introduced in Git 2.55.0 for Windows CI.

The series has received substantive review from Junio C Hamano and James Le Cuirot, with all feedback now addressed. Key changes include removing the `--target` flag for native builds to align with Cargo’s expected behavior and splitting the series into two patches for clarity. Junio has approved the v4 iteration and plans to merge it directly into `next`, fast-tracking it to `master` due to the low risk of regressions for Windows users building from source. The patches touch CI/build system files (`.github/workflows/main.yml`, `ci/lib.sh`, `config.mak.uname`, and the `Makefile`) but do not affect core Git functionality or user-facing features.

The only remaining loose end is testing on GitLab’s Windows runners, where Rust availability and toolchain compatibility are unconfirmed, but this is not a blocker. This series is a prerequisite for the broader Rustification effort in Git, as it removes the `NO_RUST` opt-out in CI and paves the way for future patches introducing Rust code.
