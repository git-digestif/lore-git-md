This thread is about enabling Rust compilation in Git’s GitHub Actions Windows CI jobs, ensuring the Rust toolchain targets the GCC ABI used by Git for Windows. The series, now at v2, was posted by Johannes Schindelin and has been under review.

The key issue is configuring the Rust toolchain to produce a static library compatible with MinGW’s linker. The v2 patches corrected the UCRT64 target triple mapping and clarified the build setup, but Junio C Hamano pointed out a naming inconsistency: the series introduces `CARGO_TARGET`, while the recently merged `jc/rust-cargo-build-target` topic established `CARGO_BUILD_TARGET` as the convention. James Le Cuirot, the author of that merged topic, has now weighed in, recommending that the `--target` flag (and thus `CARGO_BUILD_TARGET`) be omitted entirely for native builds, as Cargo defaults to the host target and explicit targeting can disrupt assumptions. His feedback reinforces the need to align variable naming with existing build logic.

The series is otherwise complete, with both patches addressing the core goal: configuring the Rust ABI and removing the `NO_RUST` opt-out. The only remaining open items are testing on GitLab’s Windows runners (to confirm Rust availability there) and resolving the variable naming issue. Johannes is expected to revise the series to adopt `CARGO_BUILD_TARGET` and adjust the target logic accordingly. No objections to the patch’s goal or implementation have been raised.
