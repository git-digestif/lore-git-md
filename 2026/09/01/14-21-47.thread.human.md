This thread is about enabling Rust compilation in Git’s GitHub Actions Windows CI jobs, a prerequisite for the broader Rustification effort in Git. Johannes Schindelin (via GitGitGadget) posted a two-part patch series to address this, with the second patch now under review.

The goal is to configure the Rust toolchain in Git’s Windows CI workflows to target the GCC ABI (used by Git for Windows) instead of the default MSVC ABI, ensuring Cargo produces a static library (`libgitcore.a`) compatible with MinGW’s `ld.exe`. The first patch in the series introduced the necessary `CARGO_TARGET` mapping and ABI configuration, while this second patch removes the `NO_RUST` opt-out and installs the precompiled Rust `std` library for the correct target triple. The series has evolved from v1 to v2, addressing feedback from Junio C Hamano about inconsistencies in the Rust target triple mapping for UCRT64.

The changes are CI/build-system-only, touching `.github/workflows/main.yml`, `ci/lib.sh`, `config.mak.uname`, and `Makefile`. The patch is minimal, well-documented, and unlikely to be controversial, though testing on GitLab’s Windows runners remains an open question. Johannes has explicitly requested this testing to confirm Rust availability and toolchain compatibility there. The series is now effectively complete and appears ready to merge once the GitLab testing question is resolved. No further objections or open technical issues remain.
