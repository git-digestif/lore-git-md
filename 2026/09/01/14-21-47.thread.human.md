This thread is about enabling Rust compilation in Git’s GitHub Actions Windows CI jobs, a necessary step to unblock the broader Rustification effort in Git. Johannes Schindelin (via GitGitGadget) posted the fourth version of a two-patch series that configures the Rust toolchain to target the GCC ABI (used by Git for Windows) instead of the default MSVC ABI, ensuring Cargo produces a static library compatible with MinGW’s linker.

The series is now complete and addresses all prior feedback. The first patch maps the `MSYSTEM` environment variable to the correct Rust target triple (e.g., `x86_64-pc-windows-gnu` for `UCRT64`) and adjusts the build configuration, while the second patch—just summarized—removes the `NO_RUST` opt-out in `ci/lib.sh` and adds a step to install the precompiled Rust `std` library via `rustup target add`. Key adjustments in v4 include omitting the `--target` flag for native builds (aligned with the recently merged `jc/rust-cargo-build-target` topic) and ensuring the `PATH` is set correctly in the minimal Git for Windows SDK environment.

Junio Hamano and James Le Cuirot provided substantive reviews in earlier versions, focusing on naming consistency and Cargo’s expected behavior. Their feedback has been fully incorporated, and there are no remaining objections. The only loose end is testing on GitLab’s Windows runners, though this is not considered a blocker. The series is narrowly scoped to CI/build system changes and does not affect core Git functionality or user-facing features. It is now ready for final review and merging.
