This thread is about enabling Rust compilation in Git’s GitHub Actions Windows CI jobs, a necessary step to support Git 2.55.0’s default Rust requirement. Johannes Schindelin (via GitGitGadget) posted the third version of a two-patch series that configures the Rust toolchain to target the GCC ABI (used by Git for Windows) instead of the default MSVC ABI, ensuring Cargo produces a static library compatible with MinGW’s linker.

The series is now complete and under final review. The first patch introduced the ABI configuration and target triple mapping, while the second (just summarized) removes the `NO_RUST` opt-out in `ci/lib.sh` and adds a CI step to install the precompiled Rust `std` library for the GCC-compatible target. All prior feedback—including Junio’s concerns about target triple consistency and James Le Cuirot’s clarification on Cargo’s native build behavior—has been addressed. The series is narrowly scoped to CI infrastructure and does not affect core Git functionality.

Key participants are aligned: Junio and James have no remaining objections, and Johannes has incorporated all feedback. The only open question is whether GitLab’s Windows runners support Rust, but this isn’t a blocker. The series is a prerequisite for Git’s broader Rustification effort, unblocking the eventual removal of the Rust opt-out in CI. Expect this to merge soon unless new concerns arise.
