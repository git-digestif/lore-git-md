This thread began as a patch series (v4) to enable Rust compilation in Git’s GitHub Actions Windows CI jobs, ensuring compatibility with Git for Windows’ MinGW toolchain. The series, authored by Johannes Schindelin, was merged to `master` after addressing all review feedback, including adjustments to Cargo’s target configuration and alignment with the recently merged `jc/rust-cargo-build-target` topic. The changes are narrowly scoped to CI/build infrastructure, with no impact on core Git functionality or user-facing features.

The key outcome was resolving the default Rust requirement introduced in Git 2.55.0 for Windows CI by configuring the Rust toolchain to target the GCC ABI (used by Git for Windows) instead of MSVC. The series also removed the `NO_RUST` opt-out in CI scripts, unblocking future Rustification efforts. All prior feedback—including Junio C Hamano’s concerns about target triple mapping and James Le Cuirot’s clarification on Cargo’s native build behavior—was incorporated into the final version.

The last open question, about Rust availability on GitLab’s Windows runners, has now been resolved: Junio confirmed Rust is not preinstalled there, and Johannes has redirected further work to a separate thread focused on installing Rust via `rustup` for GitLab CI. The original series remains merged, and no further action is needed on this thread.
