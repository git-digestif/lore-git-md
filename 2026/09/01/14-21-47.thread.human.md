This thread is about enabling Rust compilation in Git’s GitHub Actions Windows CI workflows, ensuring compatibility with the GCC ABI used by Git for Windows. The series, authored by Johannes Schindelin via GitGitGadget, was merged to `master` in its fourth iteration (v4) after addressing all prior feedback. The key change configures the Rust toolchain to target MinGW or Clang/LLVM based on the `MSYSTEM` environment variable, avoiding the default MSVC ABI that would break MinGW’s linker. The series also removes the `NO_RUST` opt-out in CI and installs the precompiled Rust `std` library via `rustup`.

Junio C Hamano and James Le Cuirot provided substantive reviews, focusing on Cargo’s expected behavior and variable naming consistency. Junio’s latest email confirms that Rust is *not* preinstalled on GitLab’s Windows runners (`saas-windows-medium-amd64`), answering an open question from Johannes about toolchain compatibility there. This doesn’t affect the series’ status—it remains merged—but clarifies that GitLab’s runners will need additional setup (e.g., `rustup`) to build Rust-enabled Git. The series is narrowly scoped to GitHub Actions and doesn’t interact with other in-flight efforts, though it unblocks the broader Rustification effort by removing the CI opt-out.
