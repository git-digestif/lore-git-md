This thread is about enabling Rust compilation in Git’s GitHub Actions Windows CI jobs, ensuring the Rust toolchain targets the GCC ABI used by Git for Windows rather than the default MSVC ABI. Johannes Schindelin (via GitGitGadget) posted a two-part v2 series to address this, with the first patch introducing a `CARGO_TARGET` variable to map the Rust target triple and the second removing the `NO_RUST` opt-out and installing the precompiled Rust `std` library.

The series is under review and has incorporated feedback from v1, including a correction to the UCRT64 target triple mapping. Junio C Hamano’s latest review raises a **substantive technical point**: the patch introduces `CARGO_TARGET`, but Cargo’s officially supported environment variable for this purpose is `CARGO_BUILD_TARGET`. Junio references a recently merged topic (`jc/rust-cargo-build-target`) that already uses `CARGO_BUILD_TARGET` and suggests aligning the new variable with this convention to avoid redundancy. This feedback is narrowly scoped but important for consistency, and the author will likely address it in a v3 or follow-up.

The series is now complete and ready for merge pending GitLab runner testing, though the request for testing on GitLab’s Windows runners (`saas-windows-medium-amd64`) remains open. No objections to the series’ goal or implementation have been raised beyond the variable naming issue. The patch is CI/build-system-only and does not affect core Git functionality or user-facing features. It directly unblocks the broader Rustification effort in Git by removing the `NO_RUST` opt-out in CI.
