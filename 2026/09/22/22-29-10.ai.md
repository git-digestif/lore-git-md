This is the **v4 bugfix series** for the reference-transaction hook regression, targeting the refs subsystem. The series restores the pre-2.31 behavior where the hook receives the resolved old OID (instead of all-zeros) when branches, tags, or remote refs are deleted, while preserving the performance gains of the original optimization. This version addresses all remaining feedback from Junio and Karthik, including granular error reporting for partial failures and internal API consistency.

The core change is in patch 1, which modifies `refs_delete_refs()` to always use `REF_TRANSACTION_ALLOW_FAILURE` (ensuring best-effort deletion) and now returns the exact set of failed refs via an optional `string_list` parameter. This allows callers like `git fetch --prune` and `git remote prune` to report successful deletions even when some refs fail due to concurrent updates, matching existing user expectations. The patch also simplifies the API by treating null OIDs as unconditional deletions in `ref_transaction_delete()`, removing the need for callers to handle this conversion.

Patches 2 and 3 update the callers (`git branch`, `git tag`, `git fetch --prune`, and `git remote prune`) to pass resolved old OIDs and handle partial failures. The UI now reports "[deleted]" for successful prunes and omits failed refs from dangling symref checks, while still showing errors for the rejected updates. Test coverage has been expanded to include partial prune scenarios for both fetch and remote operations.

Key technical details:
- **Functions modified**: `refs_delete_refs()`, `ref_transaction_delete()`, `prune_refs()`, `prune_remote()`
- **New behavior**: Hook receives the resolved old OID followed by all-zeros on deletion; partial failures are reported granularly
- **Performance**: No regression (~0.85s for 10k packed tags)
- **Test coverage**: New tests in `t/t1416-ref-transaction-hooks.sh` for partial fetch/remote pruning, UI consistency, and rejected-ref handling
- **Backends**: Files and reftable (both tested)
- **Commands fixed**: `git branch -d`, `git tag -d`, `git remote prune`, `git fetch --prune`

The series is now technically complete, with all feedback addressed and a clean rebase onto `master` (3bc0341127). The changes are low-risk (affecting only error reporting and hook payloads) and maintain backward compatibility. The full test suite passes with `DEVELOPER=1`.
