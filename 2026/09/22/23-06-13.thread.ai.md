Thread identity: CI/build system fix for intermittent HTTP/2 authentication failure in Debian 12 CI job (`t5559.15` and `t5559.16`). Single-patch series (PR #2236) by Johannes Schindelin via GitGitGadget, now with two proposed alternative implementations by Jeff King.

Core problem or goal: Work around an intermittent HTTP/2 authentication failure in Git's Debian 12 CI job, triggered by Apache returning an early 401 response and closing the HTTP/2 stream before libcurl 7.88.1 (Debian 12) finishes sending the request body. The failure affects `t5559`'s half-auth clone tests (subtests 15 and 16), which curl 7.88.1 treats as transport errors rather than allowing authentication retries (a behavior fixed in curl 8.3.0).

Current status: Patch is under active discussion. The original patch (CI-only, hard-coded test skip via `GIT_SKIP_TESTS` in `ci/lib.sh`) was approved by Junio C Hamano but critiqued by Jeff King for its limitations. Peff has now provided two refinements: (1) a runtime prereq (`HAVE_CURL_HTTP2_BUG`) that detects curl 7.88.1 and skips the affected tests via test prerequisites, and (2) a version-range-aware prereq that skips the tests for any curl version between 7.88.1 and 8.3.0 (exclusive). The thread remains open to decide between the original CI-only approach, the single-version runtime prereq, or the version-range-aware runtime prereq.

Key technical details:
- Files touched: Original patch: `ci/lib.sh`; Peff's alternatives: `t/t5551-http-fetch-smart.sh` (introduces `HAVE_CURL_HTTP2_BUG` prereq and marks tests with `!HAVE_CURL_HTTP2_BUG`).
- New symbols: `HAVE_CURL_HTTP2_BUG` prereq (Peff's patches).
- Tests affected: `t5559.15` and `t5559.16` (half-auth clone tests).
- Root cause: curl 7.88.1 (Debian 12) treats early 401 responses as transport errors; fixed in curl 8.3.0.

- Peff's alternatives are minimal (checks curl version via `build_option` and `awk`) but extensible to other versions if needed. The version-range approach is more future-proof than the single-version check.
