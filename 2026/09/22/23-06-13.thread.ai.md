Thread identity: CI/build system fix for intermittent HTTP/2 authentication failure in Debian 12 CI job (`t5559.15` and `t5559.16`). Single-patch series (PR #2236) by Johannes Schindelin via GitGitGadget.

Core problem or goal: Work around an intermittent HTTP/2 authentication failure in Git's Debian 12 CI job, which began after the job was upgraded from Debian 11 to Debian 12. The failure occurs in `t5559`'s half-auth clone test (subtests 15 and 16), where Apache returns an early 401 response and closes the HTTP/2 stream before libcurl finishes sending the request body. Debian 12's curl 7.88.1 treats this as a transport error rather than allowing an authentication retry, a behavior fixed in curl 8.3.0.

Current status: Patch is ready for integration. The proposed fix is minimal: skip the problematic tests (`t5559.15` and `t5559.16`) on Debian 12 by setting `GIT_SKIP_TESTS` in the CI environment. The change is confined to `ci/lib.sh` and adds a case block for `debian-12` that exports the skip directive. The commit message notes this is a regression in Git v2.56 but only affects CI, not production code, so it doesn’t require fast-tracking into the release.

Key technical details: Files touched: `ci/lib.sh`. New environment variable: `GIT_SKIP_TESTS` for `debian-12` CI job. Tests skipped: `t5559.15` and `t5559.16`. Root cause: curl 7.88.1 (Debian 12) treats early 401 responses as transport errors, unlike curl 8.3.0. No on-disk format or production behavior changes; purely a CI workaround.

Open questions and loose ends: None. The patch is well-motivated, targets a specific CI issue, and avoids upgrading curl (which would defeat the job's purpose of testing older supported distributions). No objections or requests for changes have been raised.
