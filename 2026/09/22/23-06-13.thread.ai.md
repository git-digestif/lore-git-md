Thread identity: CI/build system fix for intermittent HTTP/2 authentication failure in Debian 12 CI job (`t5559.15` and `t5559.16`). Single-patch series (PR #2236) by Johannes Schindelin via GitGitGadget, now with two proposed alternative implementations by Jeff King and a corrected version boundary.

Core problem or goal: Work around an intermittent HTTP/2 authentication failure in Git's Debian 12 CI job, triggered by Apache returning an early 401 response and closing the HTTP/2 stream before libcurl 7.88.0 (Debian 12) finishes sending the request body. The failure affects `t5559`'s half-auth clone tests (subtests 15 and 16), which curl 7.88.0–8.3.0 treats as transport errors rather than allowing authentication retries (a behavior fixed in curl 8.3.0).

Current status: Patch is under active discussion. The original patch (CI-only, hard-coded test skip via `GIT_SKIP_TESTS` in `ci/lib.sh`) was approved by Junio C Hamano but critiqued by Jeff King for its limitations. Peff has since provided two refinements: (1) a runtime prereq (`HAVE_CURL_HTTP2_BUG`) that detects curl 7.88.0 and skips the affected tests via test prerequisites, and (2) a version-range-aware prereq that skips the tests for any curl version between 7.88.0 and 8.3.0 (exclusive). Johannes Schindelin has confirmed the bug was introduced in curl 7.88.0 (not 7.88.1), adjusting the version range accordingly. Junio’s feedback targeted the commit message wording of the version-range approach, calling the "conservative" label misleading—he argued that assuming all versions from 7.88.0 onward are broken is aggressive, not conservative, since it could skip tests unnecessarily on unaffected versions. Peff’s latest reply clarifies the trade-off: the "conservative" framing depends on whether the priority is avoiding false positives (skipping tests unnecessarily) or false negatives (allowing flaky failures). Junio’s follow-up email confirms the version range (7.88.0–8.3.0) is now settled, signaling readiness to proceed with the version-range-aware runtime prereq as the leading candidate. The thread remains unresolved on final implementation choice, though the version-range approach with corrected bounds is favored by the author and maintainer.
