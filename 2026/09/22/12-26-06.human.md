This is the **final version (v3) of a three-patch bugfix series** targeting the refs subsystem. It restores the correct behavior of the `reference-transaction` hook when branches, tags, or remote refs are deleted, fixing a regression introduced in Git 2.31 that caused the hook to receive all-zero OIDs instead of the resolved old OID.

The series is now **fully resolved** after incorporating all feedback from v2, including Junio C Hamano’s critical design feedback and Karthik Nayak’s substantive review concerns. The core conflict—whether deletions should be conditional (safety-checked) or unconditional—has been settled in favor of a "best-effort" approach using `REF_TRANSACTION_ALLOW_FAILURE`. This preserves the performance gains of the original optimization (bulk deletion of 10,000 packed tags remains at ~0.85 seconds) while ensuring the hook receives meaningful old OIDs and allowing partial failures for non-atomic operations like `git fetch --prune` and `git remote prune`. Atomic fetches retain their all-or-nothing behavior.

Key changes since v2:
- **Rebase onto `master`** (post-commit `d38352cd43`) to resolve merge conflicts.
- **Use `REF_TRANSACTION_ALLOW_FAILURE`** for conditional batch deletion, enabling partial failures while preserving unconditional deletion for unaffected refs.
- **Improved input validation**: Skip length checks for empty refname lists and document null OIDs as the unconditional-deletion sentinel for broken refs.
- **Code cleanup**: Eliminate redundant loops (e.g., append tag OIDs in `collect_tags()` instead of a second pass), fix atomic-path formatting in `builtin/fetch.c`, and replace deprecated `test_create_repo` calls.
- **Test coverage**: Add tests for partial prune failure, UI consistency (suppressing "[pruned]" on failure), and edge cases like broken refs.

The series touches the refs backend (`refs.c`, `refs.h`), built-in commands (`git branch`, `git tag`, `git fetch`, `git remote`), and adds regression tests to `t/t1416-ref-transaction-hooks.sh`. It affects both the files and reftable backends and works with SHA-1/SHA-256. The patches are well-motivated, with clear commit messages and thorough test coverage, making them a strong candidate for merging. No open technical questions remain.
