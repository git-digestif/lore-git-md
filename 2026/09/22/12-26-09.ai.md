This is the third and final patch in Maciej Ciemborowicz's **v3 bugfix series** for the reference-transaction hook regression, targeting the `git fetch --prune` and `git remote prune` commands. The patch ensures these commands pass the resolved old OIDs to the hook when pruning stale remote refs, restoring the pre-2.31 behavior where the hook received meaningful old OID values (instead of all-zeros) while preserving the performance gains of the original optimization.

The patch modifies `builtin/fetch.c` and `builtin/remote.c` to reuse the old OIDs already collected by `get_stale_heads()` during the stale ref scan, avoiding additional ref reads. For non-atomic pruning, it uses `refs_delete_refs()` with `REF_TRANSACTION_ALLOW_FAILURE` to allow partial failures (e.g., if a ref changes concurrently), ensuring unconditional deletion behavior for `git fetch --prune` and `git remote prune` while still passing old OIDs to the hook. Atomic fetches remain all-or-nothing. The patch also suppresses "[pruned]" output when a deletion fails, fixing a UI inconsistency where prune commands previously reported success even after failures.

Test coverage is thorough, adding two new tests to `t/t1416-ref-transaction-hooks.sh`:
1. Verifies the hook receives the correct old OIDs for pruned remote refs across `git remote prune`, `git fetch --prune`, and `git fetch --atomic --prune`.
2. Confirms that `git remote prune` rejects deletions if a ref changes concurrently, preserving the new value and suppressing "[pruned]" output.

The patch is well-motivated and technically sound, addressing all feedback from v2 (including Junio's design concerns about all-or-nothing transactions and Karthik's code cleanup suggestions). The changes are confined to the pruning logic and do not affect other commands or backends. The series is now ready for merging, with no open questions or loose ends.
