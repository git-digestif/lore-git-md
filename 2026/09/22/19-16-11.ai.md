This is the **third and final patch** in Maciej Ciemborowicz's **v3 bugfix series** for the reference-transaction hook regression, now receiving a **substantive review** from Junio C Hamano. The patch updates `git fetch --prune` and `git remote prune` to pass resolved old OIDs to the hook when pruning stale remote refs, restoring pre-2.31 behavior while preserving performance and backward compatibility.

Junio identifies a **user-facing inconsistency** in the error reporting logic: when `refs_delete_refs()` fails to prune some refs (e.g., due to concurrent updates), the current patch suppresses *all* "[deleted]" output, even for refs that were successfully pruned. This deviates from the existing behavior, where `git fetch --prune` and `git remote prune` report success for each ref individually. The review suggests restoring this granular reporting—showing "[deleted]" for successful prunes and "[failed to delete]" for failures—rather than treating the entire operation as all-or-nothing. This aligns with the "best-effort" design of `refs_delete_refs()` and matches user expectations.

The feedback is **technically precise**, referencing the exact code paths (`display_ref_update()` in `builtin/fetch.c` and the reporting loop in `builtin/remote.c`) and the intended UI behavior. It does not question the core fix (passing old OIDs to the hook) but focuses on a secondary but visible aspect of the change. The issue is **low-risk**—it affects only error reporting, not correctness or performance—but it is **user-visible** and could confuse users accustomed to seeing partial success.

The patch remains **ready for merging** with this minor adjustment. The series as a whole is a **high-priority bugfix** for a regression affecting external tools (Gerrit, GitLab, CI systems) and has already addressed all prior feedback, including Junio’s critical design concerns about transaction behavior and Karthik Nayak’s code cleanup suggestions. The fix is **well-tested**, with comprehensive coverage for both files and reftable backends, SHA-1/SHA-256, and edge cases like concurrent updates. No further architectural changes are needed.

Key technical details to carry forward:
- **Files touched**: `builtin/fetch.c`, `builtin/remote.c`
- **Functions modified**: `prune_refs()`, `prune_remote()`
- **New behavior**: Granular "[deleted]" reporting for successful prunes, even if some refs fail
- **Test coverage**: `t/t1416-ref-transaction-hooks.sh` (already includes tests for partial failures)
- **Related symbols**: `display_ref_update()`, `refs_delete_refs()`, `REF_TRANSACTION_ALLOW_FAILURE`
