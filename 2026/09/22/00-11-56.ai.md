This is Junio's "What's cooking in git.git" report for September 2026 (#08), summarizing the state of in-flight topics as Git 2.56-rc1 has been tagged and the project prepares for the final release. The report lists topics graduated to `master`, new topics under review, and ongoing work cooking in `next` or `seen`.

Key highlights for a future AI summarizer:

**Graduated to `master`:**
- `tz/doc-pack-refs-and-refs-fixes`: Documentation updates for `git pack-refs` and `git refs`, converting synopsis and options to the new AsciiDoc style and backtick-quoting commands/options consistently.
- `yt/pathspec-negative-prefix`: Fixes a bug in pathspec matching where negative pathspecs shorter than the common prefix of positive pathspecs could trigger out-of-bounds memory access. The fix preserves the prefix optimization for positive pathspecs while correctly handling negative ones.

**New topics (not yet in `next`):**
- `rr/upload-pack-swap-shallow-wanted-ref`: Fixes a protocol v2 fetch failure when `uploadpack.allowRefInWant` is enabled by swapping the server response order of `wanted-refs` and `shallow-info` to match client expectations.
- `bs/runtime-prefix-obsd-getexecpath`: Enables proper `RUNTIME_PREFIX` resolution on OpenBSD 8.0+ by using the new `getexecpath(3)` function, replacing the unreliable `argv[0]` fallback.
- `js/coverity-fixes`: Seven assorted fixes for boundary conditions and error handling, including uninitialized iterator checks in reftable, midx validation, and signature-prefix matching.
- `yt/winansi-die-lasterr-fix`: Simplifies error reporting in the WinANSI compatibility layer to correctly format fatal errors and pass the exact Windows error code.
- `hd/diff-no-index-reverse-fix`: Fixes a bug in `git diff --no-index -R` where file/directory conflicts were mishandled in reverse output.
- `js/gitlab-ci-windows-rust`: Updates the GitLab CI Windows job to provision GNU Rust for MinGW builds, fixing linker support and dependency setup for Rust-enabled builds.

**Cooking in `next` (stable, candidate for future release):**
- `sg/precompile-git-compat-util`: Speeds up compilation by precompiling `git-compat-util.h` and cleans up Makefile/CMake variable handling for ODB and xdiff sources.
- `of/commit-reach-repo-awareness`: Fixes submodule merging bugs by making `can_all_from_reach()` and related functions repository-aware, preventing them from incorrectly reading the superproject's commit-graph.
- `jc/cocci-free-updates`: Updates Coccinelle semantic patches to correctly handle `FREE_AND_NULL()` and avoid generating broken transformations for negated pointer checks.
- `ak/refs-files-root-ref-lock`: Optimizes the files ref backend to avoid locking `packed-refs` when deleting root refs (which are never packed).
- `ps/ref-storage-format`: Unifies terminology around reference storage formats across CLI options, environment variables, and config keys (e.g., `--ref-storage-format`, `GIT_REF_STORAGE_FORMAT`). The option now accepts payloads in the form `<format>://<payload>`.
- `ps/odb-alternates-at-creation`: Defer alternates setup to object database creation time during clone, removing an unused ad-hoc alternate-writing API and simplifying the ODB backend interface.
- `kn/receive-report-hook`: Introduces a new `receive-report` hook that runs after reference updates, allowing servers to filter or modify the packet-line status report sent back to clients.
- `dk/use-nsec-runtime`: Converts the build-time `USE_NSEC` knob to a runtime `core.useNanosec` config, allowing distributions to ship a single binary that adapts to filesystem capabilities.
- `hn/history-squash`: Adds a `git history squash` subcommand to fold a range of commits into a single commit, with descendants replayed on top. Supports editing squashed commit messages and protects branches from accidental modification.

**Notable stalled/needs-review topics:**
- `mm/diff-process-hunks`: Introduces `diff.<driver>.process` config to allow external processes to act as hunk providers, enabling tools to control which lines Git considers changed while leaving output formatting to Git. Depends on `mm/line-log-limited-ops`.
- `tb/midx-incremental-custom-base`: Fixes `git multi-pack-index write --incremental --base` to correctly include packs above the custom base and honor reachability closure for bitmaps.
- `as/utimensat-utimes`: Treewide conversion from `utime()` to `utimensat()` for high-precision timestamps, with fallback compatibility. Stalled due to unresolved review feedback.
- `cc/early-scan-options`: Unifies early option scanning in commands like `git bisect` and `git rev-parse` using a new sub-API to prevent logic bugs. Waiting for maintainer response.

**Breaking changes preparation:**
- `bc/restrict-hex-to-lowercase`: Updates hex object name parsing to reject uppercase characters in Git 3.0's breaking changes mode.

**Experimental features:**
- `kh/format-rev-more-options`: Teaches `git format-rev` (experimental) `--abbrev`, `--color`, and `--date` options.
- `gg/http-ssl-verify-status`: Adds `http.sslVerifyStatus` config to check stapled OCSP responses during TLS handshake.

The report also notes that Git 2.98 (not 2.57) will follow Git 2.56, reflecting the version numbering change discussed at the Contributor's Summit. No new feature topics are expected to graduate before Git 2.56 final.
