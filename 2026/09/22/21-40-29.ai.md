This is an **announcement** for Git for Windows 2.56.0-rc2, the second release candidate for the upcoming Git for Windows version. It is **not** a patch or contribution to the Git project itself, but rather a downstream release of the Windows-specific fork maintained by Johannes Schindelin.

The announcement highlights several key changes since the previous Git for Windows release (v2.55.0). Most notably, Windows 8.1 support has been dropped, following the upstream MSYS2 project, which results in internal path changes (e.g., `/ucrt64/bin/git.exe` replaces `/mingw64/bin/git.exe`). Users are advised to switch to `/cmd/git.exe` for stability if their setups break. The installer for the previous version had a bug that disabled the "Use external OpenSSH" option for some users, forcing the bundled OpenSSH to be installed. Affected users are encouraged to re-run the installer to re-enable their preferred OpenSSH version.

The release includes updates to bundled components: Git v2.56.0-rc2, Git LFS v3.8.0, cURL v8.22.0, and OpenSSL v3.5.8. Several bugs are fixed, including a 32-bit installer issue that broke the external OpenSSH option, a long-standing limitation preventing commits of 4GB or larger objects, a stack-smashing crash in parallel checkouts, and a regression in v2.55.0(5) where Vim would often open files with the first line missing. Download links and SHA-256 checksums are provided for all variants (64-bit, ARM64, 32-bit, portable, and MinGit with BusyBox).

This is a routine pre-release announcement for Git for Windows, with no direct implications for the upstream Git project. The changes are specific to the Windows port and its packaging. Users of Git for Windows should take note of the dropped Windows 8.1 support and the OpenSSH installer bug if they are upgrading from v2.55.0(5). The announcement does not mention any upstream Git features or regressions, so it is unlikely to generate discussion on the Git mailing list beyond the Windows-specific context.
