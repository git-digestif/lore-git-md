This is a feature suggestion, not a patch. The author proposes a mechanism
to remove personal information from Git history without disrupting ongoing
development—no rebases, merges, or manual reconciliation required.

The motivation is clear: accidental commits of sensitive data happen, and
current tools (`git filter-repo`, BFG, `git filter-branch`) require a full
rewrite of history, forcing every developer to rebase their work. The
suggestion is that Git should offer a built-in way to surgically excise
data while leaving commit hashes and branch pointers intact, so clones can
fetch the cleaned history without coordination.

No design or implementation is offered; the email is purely a high-level
proposal. It is well-motivated but lacks technical detail, so it is likely
to spark discussion rather than immediate action. Readers who care about
privacy or repository hygiene may want to follow the thread to see if
anyone picks up the idea and sketches a concrete approach.
