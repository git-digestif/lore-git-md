This thread is about a **security fix for `git-p4`**, the Git-Perforce bridge. Anupam Mediratta identified and patched a shell injection vulnerability in `git-p4.py`'s `applyCommit()` function, where a malicious commit ID passed via `--commit` (e.g., containing `$(touch evil)`) could be executed as shell code during command substitution.

The fix replaces a shell-based pipeline (`git diff-tree ... | git apply ...`) with direct subprocess calls connected by a pipe, eliminating the shell entirely. This aligns with existing safe patterns in `git-p4.py` (`read_pipe`, `p4_system`). The patch also adds a regression test in `t9803` to verify that `git p4 submit --commit` with shell metacharacters doesn’t execute them.

The vulnerability is well-documented in the commit message, and the fix is minimal and targeted. No review feedback or objections have appeared yet, but the patch is clearly a serious security contribution that addresses a real risk. If you use `git-p4`, this is a critical update to apply.
