This thread is about a security fix for `git-p4`, addressing a shell injection vulnerability in the `--commit` option. The issue allows arbitrary command execution when a user supplies a crafted commit ID containing shell metacharacters. Anupam Mediratta proposed a patch that replaces the vulnerable shell pipeline with direct subprocess calls, eliminating the shell entirely.

Junio C Hamano, the maintainer, initially identified a regression in the first version of the patch: the new helper function ignored the exit status of the diff-apply pipeline, unlike the original code which raised an exception on failure. Anupam has now posted a v2 patch that restores the original error-handling semantics while preserving the shell injection mitigation. The updated helper now raises `CalledProcessError` on failure by default, matching the original behavior, and includes a regression test to verify the fix.

The patch touches only `git-p4.py` and adds a test in `t9803-git-p4-shell-metachars.sh` to ensure the attack vector is blocked. The commit message is thorough, and the range-diff shows the key adjustment. With the regression fixed, the patch appears ready for further review and eventual merging. No other objections or open questions remain.
