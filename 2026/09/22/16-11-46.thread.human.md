This thread is about a security fix for a shell injection vulnerability in `git-p4.py`, where a user-supplied commit ID could execute arbitrary commands via shell metacharacters. The original patch by Anupam Mediratta replaced a vulnerable shell pipeline with direct subprocess calls to eliminate the injection risk, but Junio C Hamano identified a regression: the new helper function ignores the exit status of the diff-apply pipeline, silently continuing even if the patch application fails. This breaks the original error-handling behavior, which raised an exception on failure.

The fix is now under revision to restore the original error-handling semantics while preserving the shell injection mitigation. The patch remains minimal, targeting only the `applyCommit()` function in `git-p4.py`, and includes a regression test (`t9830-git-p4-shell-injection.sh`) to verify the security fix. No objections or additional concerns have been raised, but the author will need to address Junio’s feedback before the patch can proceed. The thread is focused on this single, self-contained issue with no dependencies or prior versions.
