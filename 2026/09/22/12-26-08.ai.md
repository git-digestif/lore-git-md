This is the second patch in the v3 series fixing the reference-transaction hook regression for batched branch and tag deletions. It updates the `git branch` and `git tag` commands to pass the resolved old OIDs to `refs_delete_refs()`, restoring the pre-2.31 behavior where the hook receives meaningful old OID values (instead of all-zeros) when refs are deleted. The change also reintroduces race protection: if a ref changes concurrently, its deletion is rejected.

The patch touches `builtin/branch.c` and `builtin/tag.c`, adding an `oid_array` to collect the old OIDs during ref resolution and passing it to `refs_delete_refs()`. The `git branch` change is straightforward, appending each resolved OID to the array before deletion. The `git tag` change is more involved, introducing a new `tags_to_delete` struct to hold both the ref list and OID array, and updating the `collect_tags` callback to populate both. Both commands now use the same `refs_delete_refs()` signature, ensuring consistent behavior.

Test coverage in `t/t1416-ref-transaction-hooks.sh` is expanded with two new cases: one verifies the hook receives the correct old OIDs for batched deletions, and another confirms that concurrent updates are rejected (preserving the new ref value). The tests cover both commands and use packed refs to exercise the batched deletion path.

The patch is well-structured, with clear commit messages and minimal code churn. It directly addresses the regression by leveraging the infrastructure introduced in patch 1, avoiding additional ref reads. The race protection is a deliberate trade-off (restoring the pre-2.31 safety check) and aligns with the series' goal of backward compatibility. No performance impact is expected, as the OIDs are already resolved before deletion. The changes are confined to the high-level commands and do not affect the ref backend or on-disk format.
