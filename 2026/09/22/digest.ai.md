## Notable threads

### `git commit --fixup` message-option unification (v3)
[2026/05/18/11-22-24] Erik Cervin-Edin posted v3 of the series enabling non-interactive message specification for all `--fixup` variants. The series completes the feature matrix by supporting `-m`, `-F`, `-c`, and `-C` options across `--fixup`, `--fixup=amend:`, and `--fixup=reword:` modes. The only change since v2 is the removal of the redundant `die_for_incompatible_opt3()` function, which became obsolete after refactoring. The implementation routes all message sources through `prepare_to_commit()`, preserving message origin information and maintaining consistent behavior with interactive workflows. Comprehensive test coverage in `t/t7500` and `t/t7501` verifies the behavior, including edge cases for `-C` with plain `--fixup` and `-c` with `--fixup=amend:`. The series is production-ready, with all prior feedback from Junio Hamano and Phillip Wood addressed.

### `git repack` concurrent-push data-loss fix (layering concern)
[2026/09/14/11-31-17] Junio C Hamano raised a layering concern about patch 2/5 in the `git repack` data-loss fix series. The patch exposes and calls `packfile_store_invalidate_kept_pack_cache()` to reset the kept-pack cache after re-marking fresh packs as kept. Junio's concern centers on the unchecked downcast in the loop over ODB sources: the code assumes every source is a `files`-backend source and calls `odb_source_files_downcast()` without first checking the source type, which will trigger a `BUG()` if the source is from a different backend (e.g., a future pluggable ODB). Junio suggests either checking the source type before downcasting (a layering violation) or re-architecting the code to push packfile management details down to the files backend layer entirely. The review is forward-looking and architectural, not a rejection of the immediate fix. The thread is now open for discussion on whether to accept the patch as-is or address the layering concern before merging.

### Reference-transaction hook regression fix (v4)
[2026/09/19/13-34-15] Maciej Ciemborowicz posted v4 of the bugfix series restoring the pre-2.31 behavior where the reference-transaction hook receives the resolved old OID (instead of all-zeros) when branches, tags, or remote refs are deleted. The v4 series addresses all remaining feedback from Junio and Karthik, including granular error reporting for partial failures and internal API consistency. The core change is in patch 1, which modifies `refs_delete_refs()` to always use `REF_TRANSACTION_ALLOW_FAILURE` (ensuring best-effort deletion) and now returns the exact set of failed refs via an optional `string_list` parameter. This allows callers like `git fetch --prune` and `git remote prune` to report successful deletions even when some refs fail due to concurrent updates, matching existing user expectations. Patches 2 and 3 update the callers (`git branch`, `git tag`, `git fetch --prune`, and `git remote prune`) to pass resolved old OIDs and handle partial failures. The UI now reports "[deleted]" for successful prunes and omits failed refs from dangling symref checks, while still showing errors for the rejected updates. Test coverage has been expanded to include partial prune scenarios for both fetch and remote operations. The series is technically complete, with all feedback addressed and a clean rebase onto `master` (3bc0341127). This is a strong candidate for merging to `next`.

### Git Contributors' Summit recap and Git 3.0 planning
[2026/09/22/00-11-56] Johannes Schindelin provided a detailed recap of the Git Contributors' Summit 2026, covering Git 3.0 planning, security processes, documentation improvements, pluggable ODBs, AI policy, and push protocol v2. The summit proposed a Git 3.0 release in spring 2027 (March–April), with v2.98 (December 2026) and v2.99 (transitional release) as intermediate steps. Rust support is a goal for v3.0 but not guaranteed due to unresolved portability concerns (e.g., NonStop platform). SHA-256 interoperability is technically complete but not upstreamed, with ecosystem gaps (e.g., JGit). The security mailing list faces challenges with AI-generated reports, triage bottlenecks, and unclear release criteria. Documentation improvements focus on user accessibility and discoverability, while pluggable ODBs remain technically unresolved. The AI policy debate is contentious, with no consensus on acceptable use or DCO compliance. Junio C Hamano clarified that the summit's consensus on Rust support may not fully reflect the broader mailing list's portability concerns, and the v3.0 roadmap remains fluid pending public release of the summit notes and further community feedback. Schindelin requested Junio outline a provisional release plan in the next "What's cooking" report to aid downstream coordination.
