This is a bugfix patch targeting the fetch subsystem. It defers validation of the `fetch.followRemoteHEAD` configuration setting until the point where it is actually used, rather than warning about invalid values during config parsing.

The patch addresses a long-standing annoyance: users would see warnings about unrecognized `fetch.followRemoteHEAD` values even when running fetches that never consult that setting (e.g., fetching from a URL directly rather than a configured remote). The fix stores the raw config string and only resolves it to an enum value in `do_fetch()`, when the setting is relevant. The commit message is clear and the code change is focused, touching only `builtin/fetch.c`.

This looks like a well-motivated, low-risk improvement. The patch is small (28 insertions, 29 deletions) and the rationale is straightforward. No controversy is expected.
