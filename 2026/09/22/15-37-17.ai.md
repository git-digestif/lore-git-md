This is a design-discussion follow-up in the now-consensus-driven `fetch.shallow` thread. The email captures a key implementation question for the agreed-upon alternative solution: how `git remote add` should determine the narrower refspec for shallow repositories without making a network call to the remote. Harald Nordgren (the original author) raises the concern that the local repository lacks information about the remote’s branches and default branch, which would be needed to construct a precise refspec (e.g., `+refs/heads/main:refs/remotes/origin/main`). The discussion is now focused on whether to use the local repository’s current branch as a proxy, rely on the remote’s `HEAD` (which may be stale), or introduce a new configuration option to allow users to specify the branch explicitly. No code has been written yet; this is a pre-implementation detail that will shape the eventual patch.
