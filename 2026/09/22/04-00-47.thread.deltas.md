## 2026/09/24

- [2026/09/24/07-50-09 by Matt Hunter <m@lfurio.us>] Matt Hunter suggested that an unrecognized `fetch.followRemoteHEAD` value should be treated as `FOLLOW_REMOTE_NEVER` rather than `FOLLOW_REMOTE_UNCONFIGURED`, so a user porting a `.gitconfig` to an older git that does not recognize the setting does not silently get default behavior; he also suggested the same reasoning could apply to `remote.foo.followRemoteHEAD`.
- [2026/09/24/07-50-09 by Matt Hunter <m@lfurio.us>] Matt Hunter proposed, as a separate topic, skipping the remote HEAD query when `FOLLOW_REMOTE_CREATE` is in effect and the remote already has a local HEAD symref, to save network and server overhead.
