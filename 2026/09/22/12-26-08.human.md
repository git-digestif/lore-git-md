This is the second patch in the v3 bugfix series restoring correct old-OID reporting in the reference-transaction hook for batched branch and tag deletions. It updates `git branch -d` and `git tag -d` to pass the resolved old OIDs to `refs_delete_refs()`, fixing the regression where the hook received all-zero OIDs after the 2021 optimization that switched from `delete_ref()` to `delete_refs()`.

The patch is clean and focused: it adds an `oid_array` to collect the old OIDs during the existing ref-resolution loops, then passes that array to `refs_delete_refs()`. The changes are minimal and reuse the existing code paths, avoiding additional ref reads. Test coverage is thorough, verifying that the hook receives the correct old OID for both branches and tags, and that concurrent updates are correctly rejected (restoring the pre-regression safety check). The new tests also cover the reftable backend and SHA-256 repositories, ensuring the fix works across all configurations.

This patch directly addresses the core issue for the two most common user-facing deletion commands. The implementation is straightforward and aligns with the series' overall goal of restoring the pre-2.31 behavior without sacrificing performance. The commit message clearly explains the motivation and the technical approach, making it easy to understand why the change is necessary. The patch is ready for merging and should have no unintended side effects.
