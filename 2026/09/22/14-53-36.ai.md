This is a design-discussion follow-up in the `fetch.shallow` thread, now solidifying consensus on the alternative solution. The email confirms that the preferred approach is to modify `git remote add` to avoid wildcard fetch refspecs in shallow repositories, rather than introducing the `fetch.shallow` configuration option proposed in the original patch. Both Phillip Wood (the reviewer who identified the root cause) and Harald Nordgren (the original author) now agree that fixing `git remote add` is the cleaner solution, as it would prevent the performance issue from arising in the first place without requiring users to opt into a new configuration. No code has been written yet for this alternative, and the original patch remains unmerged. The discussion is now focused on implementation details for the `git remote add` change, such as whether the behavior should be configurable or automatic for shallow repositories.
