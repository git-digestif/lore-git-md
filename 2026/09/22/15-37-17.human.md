This is a design follow-up in the now-abandoned `fetch.shallow` patch thread. The discussion has settled on an alternative solution: modifying `git remote add` to avoid wildcard fetch refspecs in shallow repositories, preventing the performance issue at its source rather than introducing a new configuration option. Harald Nordgren, the original author, agrees with Phillip Wood’s reasoning but raises a practical concern about the alternative approach: `git remote add` lacks local information about the remote’s branches and default branch without making a network call, which complicates constructing a narrower refspec (e.g., `+refs/heads/main:refs/remotes/origin/main`) automatically. The thread remains in the design phase, with no code changes yet proposed for the alternative solution. This exchange highlights a key implementation challenge for the preferred approach.
