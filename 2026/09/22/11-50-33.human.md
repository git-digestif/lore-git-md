This is a CI/build system follow-up in the GitLab Windows CI breakage thread. Johannes Schindelin identifies a new issue: recent GitLab Runner images (specifically 19.4.0~pre.2085.g4d3dddee) introduce a problematic cleanup phase that calls `git credential reject`, triggering Git Credential Manager to open an interactive dialog. Since CI runs are non-interactive, this causes a two-hour timeout during cleanup, leading to job failures in the `test:msvc-meson` jobs.

The root cause is a change in the Runner’s cleanup logic, not the patch series itself. The failing jobs all used the newer Runner image, while successful retries and passing jobs used Runner 18.8.0, which lacks the credential-clearing call. Schindelin suggests reporting this to the GitLab Runner team, as it affects CI stability beyond this specific patch series.

This email shifts the thread’s focus from validating the Rust CI fix to diagnosing an unrelated infrastructure regression. The original patch series (restoring Windows CI after Rust enablement) remains validated, but the new Runner issue may require separate attention from GitLab’s infrastructure team. No action is needed on the Git side yet, but the observation is worth noting for anyone tracking CI reliability.
