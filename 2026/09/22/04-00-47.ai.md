This patch refactors the handling of the `fetch.followRemoteHEAD` configuration setting in `builtin/fetch.c`. Currently, the value is validated and any unrecognized setting triggers a warning during config parsing, even if the fetch operation never uses the setting. The patch defers validation until the setting is actually needed—specifically, in `do_fetch()`—by storing the raw config string and resolving it lazily.

The change touches only `builtin/fetch.c`, replacing the direct enum assignment in `git_fetch_config()` with a `char *` field (`follow_remote_head_raw`) that holds the raw string. A new helper function, `get_follow_remote_head()`, parses the string into the appropriate enum value when called in `do_fetch()`. The logic for determining the effective `follow_remote_head` setting (remote override vs. config fallback vs. default) remains the same, but now only runs when the fetch operation actually consults the setting.

This is a targeted refactoring that eliminates spurious warnings for fetches that don’t involve remote HEAD tracking. The commit message clearly explains the motivation: avoiding irrelevant warnings for operations that never use the config value. The implementation is straightforward and preserves the existing precedence rules for remote vs. config vs. default settings. No new behavior is introduced, and the patch does not touch any other files or subsystems.
