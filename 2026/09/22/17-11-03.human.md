This is a design discussion email from Junio C Hamano in response to Phillip Wood’s review of Harald Nordgren’s abandoned `fetch.shallow` patch. The thread has now pivoted to exploring an alternative solution: modifying `git remote add` to avoid wildcard fetch refspecs in shallow repositories.

Junio endorses Phillip’s suggestion to avoid wildcard refspecs but raises the challenge of designing a suitable alternative. He proposes a new fetch mode inspired by `git push`’s "matching" mode, where the set of local branches with upstream tracking defines which remote branches to fetch. This would allow `git fetch` to dynamically determine the branches of interest without requiring a wildcard refspec or a new configuration option.

Junio notes two key differences from `git push`’s matching mode: (1) multiple local branches can track the same remote branch, and (2) the fetched branches are stored as remote-tracking branches (e.g., `refs/remotes/R/U`) rather than matching the local branch names. He suggests using `:` or `+:` as a special refspec to trigger this mode, though he acknowledges this is not a perfect analogy to `git push`. The email does not propose a concrete implementation or syntax, but it frames the problem and suggests a direction for further discussion.

The email is substantive and design-focused, offering a potential path forward for the alternative solution. It does not address the earlier open question about how to construct a narrower refspec in `git remote add` without a network call, but it introduces a new idea that could complement or replace that approach.
