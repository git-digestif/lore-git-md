This is an **announcement** for Git for Windows 2.56.0-rc2, the second release candidate for the upcoming Git for Windows version. It is **not** a patch or discussion about the upstream Git project itself, but rather a downstream packaging effort targeting Windows users.

The release tracks upstream Git v2.56.0-rc2 and includes updates to bundled components like Git LFS v3.8.0, cURL v8.22.0, and OpenSSL v3.5.8. A notable change is the **dropping of Windows 8.1 support**, following the MSYS2 project’s lead, which alters internal paths (e.g., `/ucrt64/bin/git.exe` replaces `/mingw64/bin/git.exe`). Users are advised to switch to `/cmd/git.exe` for stability if their setups break.

The announcement also addresses a **regression in the v2.55.0 installer** that disabled the "Use external OpenSSH" option for some users, forcing the bundled OpenSSH version. Affected users are urged to rerun the installer to restore their preferred configuration. Other fixes include resolving a 4GB object commit limit, a stack-smashing bug in parallel checkouts, and a vim-related issue where the first line of files was often missing.

This is a routine release candidate for Git for Windows, with no direct implications for upstream Git development. Windows users relying on external OpenSSH or large objects may want to test this build, but the changes are specific to the Windows distribution.
