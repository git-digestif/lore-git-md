This is the **v4 bugfix series** for the reference-transaction hook regression, targeting the refs subsystem. The series restores the pre-2.31 behavior where the hook receives the resolved old OID (instead of all-zeros) when branches, tags, or remote refs are deleted, while preserving the performance gains of the original optimization. This version addresses all remaining feedback from Junio and Karthik, including the user-facing inconsistency in error reporting for partial failures.

The core change is in patch 1, which modifies `refs_delete_refs()` to accept an optional `oid_array` of old OIDs and a `string_list` of failed refs. The function now always uses `REF_TRANSACTION_ALLOW_FAILURE` to allow partial failures, preserving best-effort deletion behavior while still passing old OIDs to the hook. Patch 1 also simplifies the API by treating null OIDs as unconditional deletions in `ref_transaction_delete()`, reducing boilerplate in callers. Patches 2 and 3 update `git branch`, `git tag`, `git fetch --prune`, and `git remote prune` to pass the resolved old OIDs and handle partial failures gracefully, ensuring the hook receives meaningful values without additional ref reads.

The series now restores granular error reporting for partial failures: successful deletions are still reported as "[deleted]" or "[pruned]", while rejected refs are omitted from the output and dangling symref checks. This matches the existing behavior of `git fetch --prune` and `git remote prune` and addresses Junio’s feedback about user-facing consistency. Test coverage has been expanded to include partial prune failures for both fetch and remote operations, and the series has been rebased onto Git 2.56-rc2 (commit `3bc0341127`). The full test suite passes, including focused reference-transaction tests with SHA-1/SHA-256 and both files and reftable backends.

Key technical details:
- **Commands fixed**: `git branch -d`, `git tag -d`, `git remote prune`, `git fetch --prune` (all now pass the resolved old OID to the hook).
- **New behavior**: Hook receives the resolved old OID followed by all-zeros on deletion; deletions use `REF_TRANSACTION_ALLOW_FAILURE` to allow partial failures, with granular error reporting.
- **Functions modified**: `refs_delete_refs()`, `ref_transaction_delete()`, `prune_refs()`, `prune_remote()`.
- **New symbols**: `refs_delete_refs()` now accepts an optional `failed_refs` parameter (as a `string_list`) to return the exact set of rejected refs.
- **Performance**: No regression (~0.85 seconds for 10,000 packed tags).
- **Test coverage**: New tests in `t/t1416-ref-transaction-hooks.sh` cover partial fetch/remote pruning, UI consistency, and all affected commands.

The series is well-motivated, with clear commit messages and thorough test coverage. It resolves the core design conflict (all-or-nothing transactions vs. unconditional deletion) and addresses all feedback from v3, making it a strong candidate for merging.
