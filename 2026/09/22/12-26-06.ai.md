This is the **v3 bugfix series** for the reference-transaction hook regression, targeting the refs subsystem. The series restores the pre-2.31 behavior where the hook receives the resolved old OID (instead of all-zeros) when branches, tags, or remote refs are deleted, while preserving the performance gains of the original optimization. The core change is in patch 1, which modifies `refs_delete_refs()` to accept an optional `oid_array` of old OIDs, making deletions conditional if an OID is provided. Patches 2 and 3 update the callers (`git branch`, `git tag`, `git fetch --prune`, and `git remote prune`) to pass the resolved old OIDs, ensuring the hook receives meaningful values without additional ref reads.

The series now uses `REF_TRANSACTION_ALLOW_FAILURE` to allow partial failures in non-atomic batches, addressing the critical design feedback from Junio and Karthik: this preserves unconditional deletion behavior for `git fetch --prune` and `git remote prune` (where users expect all stale refs to be removed regardless of concurrent updates) while still passing old OIDs to the hook. The UI is also made consistent by suppressing "[pruned]" output when a deletion fails. Test coverage is comprehensive, including both files and reftable backends, SHA-1/SHA-256, broken/symbolic refs, atomic fetch pruning, and concurrent updates. Performance remains unchanged (~0.85 seconds for 10,000 packed tags).

Key technical details:
- **Commands fixed**: `git branch -d`, `git tag -d`, `git remote prune`, `git fetch --prune` (all now pass the resolved old OID to the hook).
- **Commands unaffected**: `git update-ref -d` (already worked correctly).
- **Backends**: files and reftable.
- **New behavior**: Hook receives the resolved old OID followed by all-zeros on deletion; deletions use `REF_TRANSACTION_ALLOW_FAILURE` to allow partial failures (preserving unconditional deletion for `git fetch --prune` and `git remote prune`).
- **Functions modified**: `refs_delete_refs()`, `ref_transaction_delete()`, `get_stale_heads()`.
- **New symbols**: `refs_delete_refs()` now accepts an optional `old_oids` parameter (as an `oid_array`); `stale_ref` struct in `builtin/fetch.c` and `builtin/remote.c` to carry ref name and old OID.
- **Input validation**: `refs_delete_refs()` validates that the `oid_array` size matches the refname count and skips null OIDs (treating them as no verification).
- **Test coverage**: New regression tests in `t/t1416-ref-transaction-hooks.sh` cover partial prune failures, UI consistency, and all affected commands.
