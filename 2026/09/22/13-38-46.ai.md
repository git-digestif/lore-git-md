This is a **user-experience bugfix** targeting the rev-parse and log subsystems in shallow clones. The v2 patch expands the scope of Harald Nordgren’s original shallow-history advice feature to cover both failing `<rev>~N`/`<rev>^N` syntax and the silent truncation that occurs in `git log -<n>` and `git log --since=<date>` when they hit a shallow boundary.

Key technical details:
- **Files touched**: `advice.c`, `advice.h`, `object-name.c`, `shallow.c`, `shallow.h`, `builtin/log.c`, plus new tests in `t/t1500-rev-parse.sh` and `t/t4202-log.sh`.
- **New advice**: `ADVICE_SHALLOW_HISTORY` fires when a revision walk stops exactly at a recorded shallow boundary, not merely because the repo is shallow elsewhere.
- **Context-aware suggestions**: for `<rev>~N` it suggests `--deepen=<N - current_depth>`; for `<rev>^N` it always suggests `--deepen=1` (since a boundary commit has no parents recorded locally). Remote and branch are auto-detected via `remote_find_tracking` instead of assuming `refs/remotes/<remote>/<branch>`.
- **Log integration**: `git log -<n>` and `git log --since` now show the advice when the last commit printed is a shallow boundary, but only if the command would have printed more commits had history been deeper. A plain `git log` running out of history stays silent.
- **Paging awareness**: the advice waits for the pager to close so it isn’t wiped from the terminal.
- **Test coverage**: 14 new test cases verify the advice appears (or doesn’t) in all the expected scenarios, including merge parents, partial depths, disabled advice, and non-shallow repos.

The patch is well-motivated, thoroughly tested, and directly addresses the usability pain point of shallow clones hiding the fact that more history exists upstream. The expanded scope—covering silent truncation in `git log`—is a significant improvement over v1 and aligns with Junio’s feedback that these cases are *more* confusing than the failing syntax. The implementation is careful to avoid false positives and provides actionable, context-specific suggestions.
