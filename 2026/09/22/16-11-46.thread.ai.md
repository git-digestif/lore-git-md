Subject: [PATCH] git-p4: prevent shell injection from user-supplied commit ID
Series version: standalone patch (no series)
Originating author: Anupam Mediratta (via GitGitGadget)
Thread type: security bugfix (patch)

Core problem or goal
A shell injection vulnerability exists in `git-p4.py`'s `applyCommit()` function. When a user supplies a commit ID via the `--commit` option, the value is interpolated into a shell pipeline (`git diff-tree ... | git apply ...`) without validation. An attacker can craft a commit ID containing shell metacharacters (e.g., `$(touch evil)`) that will be executed during command substitution, leading to arbitrary command execution.

Current status
Under review. The original patch replaced the vulnerable shell pipeline with two direct subprocess calls (`read_pipe`, `p4_system`) connected by a pipe, eliminating the shell entirely. However, Junio C Hamano identified a **regression**: the new `diffTreeApply()` helper ignores the exit status of the diff-apply pipeline, whereas the original code raised an exception on failure via `p4_system()`. The patch must be revised to restore the original error-handling semantics while preserving the shell injection mitigation. A regression test in `t9830-git-p4-shell-injection.sh` verifies the shell injection fix but does not cover the error-handling regression.

Key technical details
- **File touched**: `git-p4.py` (specifically the `applyCommit()` function)
- **Subsystem**: `git-p4` (bidirectional Git-Perforce bridge)
- **Vulnerability**: Shell injection via unvalidated `--commit` argument
- **Fix**: Replace `os.system(shell=True)` pipeline with direct subprocess calls (`read_pipe`, `p4_system`), but the helper must now propagate the pipeline’s exit status or raise an exception on failure to match the original behavior.
- **Test coverage**: New test `t9830-git-p4-shell-injection.sh` exercises the attack vector; error-handling regression is untested.
- **Symbols**: No new or renamed symbols; the fix modifies existing control flow in `diffTreeApply()`.
- **Behavior change**: The `--commit` option is now safe from shell injection; error handling must be restored to avoid silent failures.
- **On-disk format**: No changes.

Open questions and loose ends
- The patch must be revised to address the error-handling regression identified by Junio. The helper should either propagate the pipeline’s exit status or explicitly raise an exception on failure.
- No other objections or requests for changes have been raised.
