Subject: [PATCH v2] git-p4: prevent shell injection from user-supplied commit ID
Series version: standalone patch (v2)
Originating author: Anupam Mediratta (via GitGitGadget)
Thread type: security bugfix (patch)

Core problem or goal
A shell injection vulnerability exists in `git-p4.py`'s `applyCommit()` function. When a user supplies a commit ID via the `--commit` option, the value is interpolated into a shell pipeline (`git diff-tree ... | git apply ...`) without validation. An attacker can craft a commit ID containing shell metacharacters (e.g., `$(touch evil)`) that will be executed during command substitution, leading to arbitrary command execution.

Current status
Under review. The v2 patch resolves the error-handling regression Junio identified in v1 by restoring the original pipeline’s exit-status propagation. The new `diffTreeApply()` helper now raises `CalledProcessError` on failure by default (matching the original `p4_system()` behavior) while preserving the shell injection mitigation. The regression test `t9803-git-p4-shell-metachars.sh` verifies both the shell injection fix and the error-handling path.

Key technical details
- **File touched**: `git-p4.py` (specifically the `applyCommit()` function and the new `diffTreeApply()` helper)
- **Subsystem**: `git-p4` (bidirectional Git-Perforce bridge)
- **Vulnerability**: Shell injection via unvalidated `--commit` argument
- **Fix**: Replace `os.system(shell=True)` pipeline with direct subprocess calls (`read_pipe`, `p4_system`) connected by a pipe. The helper now propagates the pipeline’s exit status and raises exceptions by default, matching the original behavior.
- **Test coverage**: New test `t9803-git-p4-shell-metachars.sh` exercises the attack vector (shell metacharacters in `--commit`) and the error-handling path (failed `git apply`).
- **Symbols**: No new or renamed symbols; the fix modifies existing control flow in `applyCommit()` and adds the `diffTreeApply()` helper.
- **Behavior change**: The `--commit` option is now safe from shell injection; error handling is restored to avoid silent failures.
- **On-disk format**: No changes.
