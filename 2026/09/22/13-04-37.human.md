This is the second patch in Erik Cervin-Edin’s v3 series completing the feature to make `git commit --fixup` fully non-interactive. It enables `-c` and `-C` (reuse message from another commit, optionally editing it) for all `--fixup` variants (`--fixup`, `--fixup=amend:`, `--fixup=reword:`), rounding out the feature matrix so that all four message-specification options (`-m`, `-F`, `-c`, `-C`) now work consistently across every fixup mode.

The patch removes the last vestige of the old option-checking logic: the redundant `die_for_incompatible_opt3()` that became obsolete once `-c`/`-C` were unified with the other message options. The implementation routes all message sources through `prepare_to_commit()`, preserving message origin information and maintaining the existing behavior that strips “amend!” lines when using `-c`/`-C` with amend-style fixups. Documentation and tests are updated to reflect the new capabilities, and the commit message explains why `-c`/`-C` needed special handling once the other options were unified.

All prior feedback from Junio Hamano and Phillip Wood has been addressed, and the series is now production-ready. Erik has dogfooded the feature for months, and the only change since v2 is the removal of the redundant option-checking function. The patch touches only `builtin/commit.c`, the documentation, and the test suite; no core data structures or on-disk formats are altered. With this patch, the feature matrix is complete: every message-specification option now works with every `--fixup` variant.
