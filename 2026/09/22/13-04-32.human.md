This is a feature patch series (v3) that completes Erik Cervin-Edin's effort to make `git commit --fixup` fully scriptable by supporting all message specification options (`-m`, `-F`, `-c`, `-C`) across all `--fixup` variants (plain, amend, reword). The series is now down to two patches after addressing the last bit of feedback from Junio Hamano: a redundant option-checking function that became obsolete once the main logic was refactored.

The core idea is simple: today only `-m` works with plain `--fixup`, and neither `-m` nor `-F` work with `--fixup=amend:` or `--fixup=reword:`, forcing users into interactive workflows. Erik’s patches route all four message sources through the same code path (`prepare_to_commit()`) so that every combination behaves consistently. The second patch, which adds `-c`/`-C` support, also removes an unnecessary compatibility check that Junio spotted—this is the only change from v2.

The implementation is careful about edge cases: when `-C` points to an “amend!” commit, the “amend! X” subject line is stripped so it doesn’t end up in the final squashed message, matching what happens when you edit interactively. Tests in `t/t7500` and `t/t7501` cover the new combinations, and the documentation is updated to reflect the expanded capabilities. Erik has been dogfooding the feature for months, and the series has already absorbed all substantive feedback from Junio and Phillip Wood. The only remaining loose end is a minor code hygiene follow-up that Erik plans to send after travel.
