This is a security bugfix for `git-p4`, the bidirectional bridge between Git and Perforce.

The patch closes a shell-injection vulnerability in `git p4 submit --commit`. When the user supplies a commit identifier via `--commit`, the code interpolates it into a shell pipeline (`git diff-tree ... | git apply ...`) without validation or proper escaping. A maliciously crafted commit name containing shell metacharacters (e.g., `$(touch /tmp/pwned)`) would be executed by the shell. The fix replaces the shell pipeline with direct subprocess calls connected via a pipe, eliminating the shell entirely. A new regression test verifies that a commit name containing shell metacharacters is not executed.
