This is Junio’s biweekly “What’s cooking in git.git” report for September 2026 (#08), summarizing the state of all in-flight topics as the Git 2.56 release cycle winds down.

Git 2.56-rc1 has been tagged, so only last-minute fixes will land before the final release; everything else will stay cooking in `next` until after 2.56 ships.  The next release after 2.56 will be Git 2.98, reflecting the project’s new versioning scheme adopted at the Contributor’s Summit.

Two small documentation patches graduated to `master` this cycle: one backtick-quotes commands and options consistently in the `pack-refs` and `refs` documentation, and the other fixes an out-of-bounds memory access when a negative pathspec is shorter than the common prefix of positive pathspecs.

New topics that have appeared since the last report:

- A one-patch fix from Royce Remer swaps the server-side protocol v2 response order for `wanted-refs` and `shallow-info` to match the client’s expectation, resolving a fetch failure when `uploadpack.allowRefInWant` is enabled and the client performs a shallow fetch.  It is marked “Will merge to `next`.”

- Brad Smith contributed a one-line patch that enables `RUNTIME_PREFIX` on OpenBSD by using the new `getexecpath(3)` function introduced in OpenBSD 8.0.  Junio asked for a follow-up to clarify the commit message, so it is waiting for a response.

- Johannes Schindelin sent a seven-patch series fixing various boundary and error conditions found by Coverity.  The fixes touch `test-read-midx`, the reftable iterator, `rerere`, the MIDX incremental pack ID validation, GPG signature-prefix matching, and a signed-overflow guard in `writev_in_full()`.  Junio’s replies suggest the series is on track for `next`.

- Yichen Tian fixed a formatting bug in the WinANSI compatibility layer’s `die_lasterr()` helper that was causing incorrect argument substitution in fatal error messages.  Junio asked for a reworded commit message, so the patch is waiting for a response.

- Hendrik De Vloed fixed a long-standing bug in `git diff --no-index -R` that mishandled file/directory conflicts when the reverse output was requested.  The patch is marked “Will merge to `next`?”

- Johannes Schindelin also sent a four-patch series that fixes the GitLab CI Windows job by provisioning the GNU Rust toolchain for MinGW builds, preserving exclusions during dependency setup, and providing host-linker support.  The series is marked “Will merge to `next`?”

Among the topics already cooking:

- Junio’s own one-patch topic suggests using `--global` in advice snippets that recommend configuration changes, since global config is more appropriate for user-level preferences than per-repository settings.  It needs review.

- SZEDER Gábor’s four-patch series precompiles `git-compat-util.h` to speed up compilation, while excluding sources that do not include the compatibility header.  It graduated to `next` on September 21.

- Orestis Floros made the `can_all_from_reach()` and `can_all_from_reach_with_flag()` functions repository-aware, preventing submodule merges from incorrectly reading the superproject’s commit-graph.  It is marked “Will merge to `next`.”

- Han-Wen Nienhuys added a `--matched-only` option to `git range-diff` to skip commits that appear on only one side, making it easier to focus on retained commits.  It needs review.

- Junio also sent a two-patch Coccinelle update to correctly handle the `FREE_AND_NULL()` macro and avoid generating broken transformations for negated pointer checks.  It is cooking in `next`.

- Jonathan Tan fixed an ODB transaction bug that failed to flush large blob packfiles in the temporary directory before migrating them to the main object store when `core.fsyncMethod` is set to `batch`.  The series is waiting for review.

- Karthik Nayak’s one-patch fix avoids unnecessarily locking the `packed-refs` file when deleting a root ref (which are never packed).  It is cooking in `next`.

- Taylor Blau’s three-patch series defers automatic maintenance tasks until the end of sequencer operations (`rebase`, `cherry-pick`, `revert`), preventing nested commands from triggering GC operations that could contend for locks or delete open packs.  It needs review.

- Patrick Steinhardt’s 13-patch series unifies the terminology around reference storage formats across command-line options, environment variables, configuration variables, and source code, standardizing on “ref storage format” (e.g., `--ref-storage-format`, `GIT_REF_STORAGE_FORMAT`).  The series also extends the `--ref-storage-format` option to accept payloads in the form `<format>://<payload>`.  It is cooking in `next`.

- Teemu Ahola added a linter test to `Documentation/lint-manpages.sh` that ensures all non-command manual pages listed in `Documentation/Makefile` are present in `command-list.txt`.  It needs review.

- Andrew Pleeter extended `git var` to expose individual identity components (`GIT_AUTHOR_NAME`, etc.), the commit signing key, and to accept multiple variables to query at once, with a new `-z` option for safe formatting.  It is marked “Expecting a reroll.”

- Tyler Cipriani fixed three bugs in the `--force-if-includes` protection for `git push`: it now consults the reflog of the local branch being pushed (not the remote destination branch), the advice for detached HEAD scenarios has been corrected, and a regression that rejected valid fast-forward pushes when reflogs were expired has been fixed.  The series needs review.

- Alex Smith’s one-patch topic preserves `WWW-Authenticate` headers across HTTP redirects when the target yields an authentication challenge, fixing an issue where they were incorrectly cleared.  It needs review.

- Kristoffer Haugsbakk added support for `--abbrev`, `--color`, and `--date` options to the experimental `git format-rev` command.  It needs review.

- Gregory Gordon added a new `http.sslVerifyStatus` configuration variable to check the revocation status of the server certificate using stapled OCSP responses during the TLS handshake.  It is marked “Will merge to `next`?”

- Toon Claes’s six-patch series optimizes `git last-modified` by using Bloom filters to pre-filter commits and by maintaining per-path Bloom filters even when wildcard pathspecs are used.  It is waiting for a response.

- Derrick Stolee’s seven-patch series bans functions like `xstrfmt()` and `xcalloc()` from the trace2 API to prevent calls to `die()` that lead to unwanted process exits and recursion when memory allocation fails.  It needs review.

- Paul Zaleckas added a `fetch.submoduleErrors` configuration to make submodule fetch errors non-fatal, and fixed a premature failure during recursive submodule fetches.  It needs review.

- Fabian Zaremba fixed `git rebase --autosquash` to honor the `--empty` option when a `fixup!` or `squash!` commit empties its target.  It is waiting for a response.

- Ian Jackson updated the shell script implementation of `git subtree` to check for the presence of the new Rust implementation’s configuration file, preventing users from accidentally running the old script on repositories already managed by the new tool.  It is marked “Expecting a reroll.”

- Matthias Montalbo’s 11-patch series introduces a new `diff.<driver>.process` configuration to allow a long-running external process to act as a hunk provider, enabling external tools to control which lines Git considers changed while leaving all output formatting to Git’s standard pipeline.  It is marked “Expecting a reroll.”

- Kristoffer Haugsbakk added options to `git format-patch` to configure notes specifically for range-diff output, allowing them to differ from the notes displayed on the patches themselves.  It is marked “Expecting a reroll.”
