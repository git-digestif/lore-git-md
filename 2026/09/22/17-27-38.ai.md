This is a **bugfix** patch addressing the `git reflog expire` regression in Git 2.50, where the default expiry periods for reachable and unreachable reflog entries were accidentally swapped. The patch itself is straightforward—correcting the order of `.default_expire_total` and `.default_expire_unreachable` in `REFLOG_EXPIRE_OPTIONS_INIT()`—but Junio’s review raises important questions about the commit message and test coverage.

Junio’s feedback focuses on two key points. This is a common request for bugfix patches—readers should understand the scope and history of the issue without digging through the thread. Second, he suggests expanding the regression test to cover both sides of the expiry logic: not just that 60-day-old reachable entries are retained (as the current test does), but also that unreachable entries older than 30 days are *not* retained, and that reachable entries older than 90 days *are* expired. This would make the test more robust by verifying the full intended behavior.
