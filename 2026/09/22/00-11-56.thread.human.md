Here’s the human-mode summary for a developer catching up on the thread:

This thread is Junio’s September 2026 “What’s cooking” report, now expanded into a planning discussion for Git 3.0. The core question is when and how to cut the next major version, with a provisional timeline that targets April 2027 for Git 3.0 but leaves room for delays if the stabilization period for the transitional 2.99.x releases drags on. Key participants include Junio (maintainer), Johannes Schindelin (Git for Windows), Luca Milanesio (JGit), Toon Claes (GitLab), and Ramsay Jones (portability testing).

The big picture is that Git 2.56-rc1 has been tagged, so no new features will land before the final 2.56. The Git 3.0 plan calls for a final 2.x feature release (2.98) in December 2026, a transitional 2.99 in March 2027 with breaking changes disabled, and Git 3.0 in April 2027 with those changes enabled. Junio has since clarified that the April date is tentative; if 2.99 needs more bug-fix releases (2.99.2 or 2.99.3), Git 3.0 will slip accordingly. Downstream projects like Git for Windows have tied their roadmaps to this schedule, but Junio’s caveats now introduce some uncertainty.

On the technical side, the thread has clarified that JGit’s pluggable backend infrastructure is production-ready—Google has used it internally for over a decade, and GerritForge’s open-source global refdb backend demonstrates its scalability. SHA-256 support in JGit is technically feasible but not actively developed due to resource constraints, not technical barriers. The upcoming Gerrit User Summit on November 10, 2026, will be a key venue for Git and JGit maintainers to coordinate on interoperability, though no immediate updates are expected before then. Rust support remains a goal for Git 3.0 but isn’t guaranteed; Ramsay Jones provided encouraging data that the experimental Rust code compiles on Cygwin, though NonStop remains untested.

Open questions include the final scope of breaking changes, the readiness of downstream projects (especially JGit for SHA-256), and whether the 2.99 stabilization period will require extra releases. Security process improvements and documentation tooling are also in focus, with Toon Claes committing to document Git’s security model and Schindelin endorsing a collaborative approach to the next security release. The thread’s latest email is purely logistical—Luca Milanesio confirming his attendance at the Gerrit User Summit—but it underscores that the summit will be a critical checkpoint for Git 3.0’s ecosystem coordination.
