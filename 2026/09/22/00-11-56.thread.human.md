Here’s the human-mode narrative summary for a developer catching up on the thread:

This thread started as Junio’s September 2026 “What’s cooking” report, summarizing where all in-flight patch series stand as Git 2.56-rc1 was tagged. Since then, the discussion has broadened into planning for Git 3.0, slated for spring 2027. The key participants are Junio, Johannes Schindelin (who recapped the recent Contributor’s Summit), and now Daniele Sassoli, a JGit contributor.

The main decisions so far: Git 2.56 will be the last 2.x feature release; the next two releases will be v2.98 (December 2026) and a transitional v2.99 before the 3.0 cut. Rust support is a goal for 3.0 but not guaranteed—portability concerns, especially for the NonStop platform, remain unresolved. SHA-256 interoperability is technically complete in Git but not yet upstreamed, and JGit’s readiness was initially flagged as a gap. Sassoli’s follow-up clarifies that JGit already has the infrastructure for pluggable backends and SHA-256; the holdup is funding and prioritization, not technical barriers. That shifts the conversation from “can JGit do this?” to “how do we resource it?”

Still open: Junio has yet to publish a detailed release plan with conditions for delay. The summit also highlighted security-process bottlenecks, documentation funding constraints, and an unresolved AI policy. On the patch front, a few stalled series need review or rerolls, and the new `git history squash` command is cooking in `next` but may face design scrutiny before graduation.
