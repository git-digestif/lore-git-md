Here’s the human-mode summary for a developer catching up on the thread:

This thread is Junio’s September 2026 “What’s cooking” report, summarizing all in-flight patch series and the Git 3.0 planning that followed the Contributor’s Summit. Git 2.56-rc1 has been tagged, so no new features will graduate before the final 2.56 release. The community is aligning on a provisional three-phase timeline for Git 3.0: Git 2.98 (December 2026) as the last 2.x feature release, Git 2.99 (March 2027) as a transitional release with breaking changes disabled, and Git 3.0 (April 2027) with those changes enabled. The month between 2.99 and 3.0 is meant as an “advertisement” period for downstream projects, not a full development cycle.

Key participants include Junio (maintainer), Johannes Schindelin (Git for Windows), Daniele Sassoli (JGit), Toon Claes (security and documentation), and D. Ben Knoble (downstream coordination). The summit recap highlighted several Git 3.0 goals: Rust support (still a stretch goal due to portability concerns like the NonStop platform), SHA-256 interoperability, and pluggable object database backends. JGit’s readiness for these goals was clarified in the latest exchange—its pluggable backend infrastructure is functional and production-ready, but SHA-256 support lacks active development due to resource constraints rather than technical barriers. Schindelin now acknowledges JGit’s technical capability but remains skeptical about SHA-256 progress without corporate funding.

Security process improvements and documentation sustainability were also discussed. Toon Claes committed to documenting Git’s security model and increasing GitLab’s staffing for report triage, while the community is refining a two-pronged documentation strategy: incremental updates for reference material and complete rewrites for tutorials. The `git-scm.com` website and its “UI list” are identified as maintenance bottlenecks, with a stalled PR linked as an example. Julia Evans’ Sovereign Tech Fund grant is noted as a positive step for documentation funding, but broader efforts are needed.

Open questions remain around the final scope of Git 3.0’s breaking changes, downstream coordination (especially for LTS distributions), and the unresolved portability concerns for Rust. The timeline is still subject to mailing list feedback, and Junio explicitly solicits input on these points. Downstream projects like Git for Windows have tied their roadmaps to the April 2027 target, but other stakeholders (e.g., JGit, distributions) have yet to confirm their readiness.
