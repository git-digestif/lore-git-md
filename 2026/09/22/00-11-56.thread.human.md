This thread is about the Git 3.0 release planning and the outcomes of the recent Contributor's Summit, with a focus on aligning the community around the timeline, scope, and ecosystem readiness for breaking changes. Git 2.56-rc1 has been tagged, and the provisional timeline for Git 3.0 is spring 2027, with intermediate releases (v2.98 and v2.99) planned to smooth the transition.

The discussion has covered technical readiness (e.g., Rust support, SHA-256 interoperability, pluggable ODBs), security process improvements, and documentation sustainability. Junio’s latest email adds clarity to the documentation strategy: while incremental updates to reference material (like man pages) are valuable, tutorials and conceptual guides may need complete rewrites to reflect how users interact with Git today. This distinction is important because even experienced contributors may not fully grasp what new users find confusing, and outdated tutorials can create more problems than they solve. The emphasis on rewriting conceptual material suggests a more ambitious effort than initially assumed, though no concrete timeline or resourcing plan has been proposed yet.

Key participants include Junio (maintainer), Johannes Schindelin (who recapped the summit), Daniele Sassoli (who clarified JGit’s technical readiness), Toon Claes (who committed to security and documentation improvements), and D. Ben Knoble (who volunteered to coordinate with downstream distributions). The thread remains collaborative, with no major disagreements, but several open questions remain, such as the final scope of Git 3.0, the fate of stalled patch series, and how to address the maintenance bottlenecks in `git-scm.com`. Junio is expected to outline a more detailed release plan in the next "What's cooking" report.
