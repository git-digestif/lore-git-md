Subject: [PATCH] fetch: defer validation of fetch.followRemoteHEAD until needed
Series version: single patch (no series)
Originating author: Colin Hinton
Thread type: patch (refactoring)

Core problem or goal
Refactor the handling of the `fetch.followRemoteHEAD` configuration setting in `builtin/fetch.c` to defer validation until the setting is actually used in `do_fetch()`. Currently, the config parser issues warnings for unrecognized values even when the fetch operation never consults the setting, which is unnecessary and potentially confusing.

Current status
Under review; no prior versions. Patch introduces a new `char *follow_remote_head_raw` field in `builtin/fetch.c` to store the raw config string and a helper function `get_follow_remote_head()` to parse it lazily in `do_fetch()`. The existing precedence rules (remote override > config > default) are preserved.

Key technical details
- Files touched: `builtin/fetch.c` only
- New symbols: `follow_remote_head_raw` (field), `get_follow_remote_head()` (function)
- Old behavior: config validation and warnings during parsing
- New behavior: validation deferred until `do_fetch()` consults the setting
- No on-disk format changes; no test coverage changes
