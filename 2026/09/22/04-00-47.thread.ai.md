Thread identity
Subject: [PATCH] fetch: defer validation of fetch.followRemoteHEAD until needed
Series version: single patch (no series)
Originating author: Colin Hinton
Thread type: patch (refactoring)

Core problem or goal
Refactor the handling of the `fetch.followRemoteHEAD` configuration setting in `builtin/fetch.c` and `remote.c` to defer validation until the setting is actually used in `do_fetch()`. Currently, the config parser issues warnings for unrecognized values even when the fetch operation never consults the setting, which is unnecessary and potentially confusing. The patch must address premature validation in both the local (`builtin/fetch.c`) and remote-side (`remote.c::handle_config()`) parsers to fully achieve lazy validation.

Current status
Under review; no prior versions. Patch v1 introduced a new `char *follow_remote_head_raw` field in `builtin/fetch.c` to store the raw config string and a helper function `get_follow_remote_head()` to parse it lazily in `do_fetch()`. Junio C Hamano’s review identified two gaps: (1) the patch still fails during config parsing for valueless truth settings (e.g., `fetch.followRemoteHEAD` with no value), and (2) the remote-side parser in `remote.c` shares the same problem and must be refactored in tandem. Colin Hinton agrees with Junio’s feedback and plans to revise the patch to defer the `die(...)` call for valueless settings to the lazy-validation point, and to address the remote-side parser in the same patch. Junio also suggested simplifying the logic by initializing `follow_remote_head` to `FOLLOW_REMOTE_NEVER` and testing it directly, eliminating the redundant `do_set_head` state.

Key technical details
- Files touched: `builtin/fetch.c`, `remote.c`
- New symbols: `follow_remote_head_raw` (field), `get_follow_remote_head()` (function)
- Old behavior: config validation and warnings during parsing in both `builtin/fetch.c` and `remote.c`
- New behavior: validation deferred until `do_fetch()` consults the setting; remote-side config parsing must also be deferred
- No on-disk format changes; no test coverage changes
- Control flow: `do_fetch()` -> `get_follow_remote_head()` -> parse `follow_remote_head_raw`; remote-side parsing in `handle_config()` must be similarly deferred
- Edge cases: valueless truth settings (handled by deferring `die(...)`), multiple config definitions (existing code handles this; patch must preserve)

Open questions and loose ends
- Whether to include the remote-side parser refactoring in this patch or defer it to a follow-up. Colin seeks guidance on this point.
- Memory management for `follow_remote_head_raw` if multiple config definitions are encountered during lazy validation.

Participant positions

- **Junio C Hamano (maintainer)**: Substantive review identifying gaps (valueless truth settings, remote-side parser) and suggesting simplifications (eliminate `do_set_head`). No approval or rejection yet; discussion is constructive and ongoing.
