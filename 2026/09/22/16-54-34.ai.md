This is a **bugfix** patch that restores the correct default expiry periods for `git reflog expire`, addressing the regression reported by r.norouzi in Git 2.50. The patch swaps the values of `.default_expire_total` and `.default_expire_unreachable` in `REFLOG_EXPIRE_OPTIONS_INIT()` to match the documented behavior: reachable entries should expire after 90 days, while unreachable entries should expire after 30 days. The regression was introduced by commit `85658275702b`, which reversed these defaults.

The patch touches two files: `reflog.h` (correcting the field order in the macro) and `t/t1410-reflog.sh` (adding a regression test). The test verifies that a 60-day-old reachable reflog entry is retained after `git reflog expire --all`, confirming the fix works as intended. The change is minimal and targeted, focusing only on the misordered defaults without altering any other logic or on-disk formats.

This fix is uncontroversial and well-motivated, as it directly addresses a documented behavior regression with a clear reproduction case. The added test ensures the issue won’t recur. The patch is likely to be merged quickly, given the straightforward nature of the bug and the inclusion of test coverage. It affects all platforms, as the bug is in core Git logic, but does not impact `git gc` directly unless it invokes `reflog expire` with default settings.

Key symbols modified include `.default_expire_total` and `.default_expire_unreachable` in `reflog.h`, and the test introduces no new configuration or command-line options.
