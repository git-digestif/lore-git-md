This is the second patch in the v4 bugfix series restoring correct old-OID reporting in the reference-transaction hook for batched branch and tag deletions. It updates `git branch` and `git tag` to pass the resolved old OIDs to `refs_delete_refs()`, fixing the regression introduced in Git 2.31 where the hook received all-zero OIDs instead of the actual pre-deletion values.

The patch is straightforward: both commands already resolve the old OIDs before deletion, so the change simply forwards those values to the refs API. This restores the pre-2.31 behavior where deletions were conditional (rejecting concurrent updates) while preserving the performance gains of batched deletion. The implementation is clean, using an `oid_array` to track old OIDs alongside the existing `string_list` of ref names. New tests verify that the hook receives the correct old OIDs for both branches and tags, and that concurrent updates are properly rejected.

This is a well-motivated bugfix with minimal risk. The changes are confined to the two affected commands, and the added test coverage ensures the fix works for both files and reftable backends. The patch integrates cleanly with the rest of the series (which handles granular error reporting and fetch/remote pruning) and addresses all prior feedback. It’s ready for merging.
