# Thread deltas

## 2026/09/22

- [2026/09/22/23-06-13 by Johannes Schindelin via GitGitGadget <gitgitgadget@gmail.com>] Johannes Schindelin submitted patch pr-2236 adding a `debian-12` case in `ci/lib.sh` to export `GIT_SKIP_TESTS` for t5559.15 and t5559.16, working around intermittent `curl 92 Stream error in the HTTP/2 framing layer` failures in the half-auth clone caused by Debian 12's curl 7.88.1 treating an early 401 HTTP/2 stream closure as a transport error instead of allowing an authentication retry; he noted the regression does not affect production code and need not be fast-tracked into v2.56.0, but should reach master soon to reduce developer friction.

## 2026/09/23

- [2026/09/23/16-16-22 by Junio C Hamano <gitster@pobox.com>] Junio C Hamano praised Johannes Schindelin's diagnosis and agreed with the workaround reasoning, saying there is no reason to cook the patch as long as usual patches and that fast-tracking would keep things working on older Debian.
- [2026/09/23/16-47-00 by Jeff King <peff@peff.net>] Jeff King thanked Schindelin for finding and fixing the issue but flagged two downsides of the CI-based approach: it detects by CI job name rather than the bug itself (so it won't help people running tests on debian-12 directly), and it relies on test numbering that can silently go out of sync; he proposed instead having t5559 detect the buggy curl version, set a prereq, and mark the tests with !HAVE_CURL_HTTP2_BUG, while unsure it was worth much implementation effort.
- [2026/09/23/16-53-48 by Jeff King <peff@peff.net>] Jeff King shared an Astra-generated diff adding a HAVE_CURL_HTTP2_BUG lazy prereq that matches libcurl exactly 7.88.1 and marks the two half-auth tests with !HAVE_CURL_HTTP2_BUG, noting it covers at least as much as the CI debian-12 specifier.
- [2026/09/23/16-59-22 by Jeff King <peff@peff.net>] Jeff King offered an alternative range-based prereq using awk to treat libcurl versions from 7.88.1 up to (but not including) 8.3.0 as broken, and left the choice between the exact-version and range approaches to Junio.
- [2026/09/23/17-17-05 by Junio C Hamano <gitster@pobox.com>] Junio C Hamano objected to describing the 7.88.1-up assumption as "conservative" when the first affected version is unknown, noting 7.88.1 is from early 2023 so one cannot simply skip everything older than 8.3.0.
- [2026/09/23/19-25-14 by Jeff King <peff@peff.net>] Jeff King replied that "conservative" depends on which bad outcome is being guarded against—skipping tests that could run versus letting flaky failures through—and said he is fine with either the range check or just matching 7.88.1.
