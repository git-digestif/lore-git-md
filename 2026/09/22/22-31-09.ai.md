This is the second patch in the v4 series fixing the reference-transaction hook regression for batched branch and tag deletions. It updates `git branch` and `git tag` to pass the resolved old OIDs to `refs_delete_refs()`, restoring the pre-2.31 behavior where the hook receives meaningful old OID values (instead of all-zeros) while preserving the performance gains of batched deletion.

The patch modifies `delete_branches()` in `builtin/branch.c` and `delete_tags()` in `builtin/tag.c` to collect the old OIDs during ref resolution and pass them to `refs_delete_refs()`. This ensures the reference-transaction hook receives the correct old OID followed by all-zeros on deletion, matching the behavior of Git 2.28–2.30. The changes also restore race protection: if a ref changes concurrently, its deletion is rejected, and the new value is preserved.

Key technical details:
- **New data structures**: `oid_array` is used to track old OIDs in `delete_branches()`; `struct tags_to_delete` (containing a `string_list` and `oid_array`) is introduced in `delete_tags()` to pass both ref names and old OIDs.
- **Functions modified**: `delete_branches()`, `delete_tags()`, and helper `collect_tags()`.
- **Test coverage**: Two new tests in `t/t1416-ref-transaction-hooks.sh` verify the hook receives the correct old OIDs for batched deletions and that concurrent updates are rejected with appropriate error messages.
- **Backward compatibility**: The patch restores the pre-regression behavior without changing the on-disk format or user-facing output.

The changes are minimal and focused, addressing only the two commands affected by the regression. The patch integrates cleanly with the rest of the series (which modifies `refs_delete_refs()` to handle partial failures and updates `git fetch --prune`/`git remote prune` in patch 3). All feedback from Junio and Karthik on earlier iterations has been addressed, including API consistency and granular error reporting. This is a well-motivated, low-risk fix that completes the series' goal of restoring the hook's expected behavior.
