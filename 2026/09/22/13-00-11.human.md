This is a design discussion in the ongoing `fetch.shallow` feature thread. The conversation has shifted from the original patch (which introduced a `fetch.shallow` config to restrict refspec-less fetches to the current branch in shallow repositories) to exploring a more targeted solution: modifying `git remote add` to avoid wildcard fetch refspecs in shallow repositories.

Harald Nordgren, the original author, responds to Phillip Wood’s suggestion that the root cause of the performance issue lies in `git remote add` defaulting to a wildcard refspec (`+refs/heads/*:refs/remotes/<name>/*`) even in shallow repositories. Harald agrees that this could be a better approach and asks whether the `git remote add` fix should replace or complement the `fetch.shallow` config. His question—"Seems maybe we only need the fix on `git remote add`"—signals openness to abandoning the original patch in favor of a narrower, more maintainable solution.

The thread is now focused on designing the alternative: how `git remote add` should behave in shallow repositories (e.g., defaulting to a branch-specific refspec like `+refs/heads/<default-branch>:refs/remotes/<name>/<default-branch>`), whether this behavior should be configurable, and how it would interact with existing workflows. No code has been written yet for this approach, and the original patch remains unmerged. The discussion is still in the exploratory phase, with no clear consensus on the path forward.
