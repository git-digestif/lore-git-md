This is the first patch in the **v3 bugfix series** for the reference-transaction hook regression, targeting the refs subsystem. It introduces the core mechanism that restores the pre-2.31 behavior where the hook receives the resolved old OID (instead of all-zeros) when branches, tags, or remote refs are deleted.

The patch modifies `refs_delete_refs()` to accept an optional `oid_array` of old OIDs, allowing callers to specify the expected current value for each ref. If the array is provided, deletions become conditional: a ref is deleted only if it still points to the specified OID. A null OID in the array requests an unconditional deletion (e.g., for broken refs). The patch also enables `REF_TRANSACTION_ALLOW_FAILURE` when old OIDs are supplied, preserving the helper’s best-effort behavior—individual deletions can fail (e.g., due to concurrent updates) while others proceed. This resolves the core design conflict from v2 by avoiding all-or-nothing transactions while still passing old OIDs to the hook.

Key changes include:
- **New parameter**: `refs_delete_refs()` now takes an optional `old_oids` array, validated to match the refname count.
- **Conditional deletion**: Non-null OIDs trigger a compare-and-delete operation; null OIDs remain unconditional.
- **Best-effort transactions**: `REF_TRANSACTION_ALLOW_FAILURE` allows partial failures, addressing Junio’s feedback about preserving unconditional deletion for commands like `git fetch --prune`.
- **Error handling**: A new rejection handler tracks failures and emits warnings for mismatched OIDs, ensuring callers are aware of skipped deletions.
- **Backward compatibility**: Existing callers (e.g., `bisect.c`, `builtin/fetch.c`) pass `NULL` for `old_oids`, preserving their current behavior.

The patch is well-structured, with clear commit messages and input validation. It directly addresses the regression’s root cause while maintaining the performance gains of the original optimization. The use of `REF_TRANSACTION_ALLOW_FAILURE` is a clean solution to the all-or-nothing transaction problem raised in v2, and the conditional deletion logic aligns with Karthik Nayak’s proposed middle ground. No open questions remain; this patch is ready for final review.
