This is a follow-up in the ongoing design discussion about how to improve `git fetch` performance in shallow repositories. The thread has abandoned the original patch (`fetch.shallow` config) in favor of two alternative approaches: (1) making `git remote add` default to narrower refspecs in shallow repositories, and (2) introducing a new "matching-inspired" fetch mode for `git fetch` that dynamically fetches only the remote branches tracked by local branches.

Harald Nordgren responds to Junio C Hamano’s proposal for the matching-inspired fetch mode, endorsing the idea but suggesting a refinement: the remote’s default branch should always be fetched, even if no local branch currently tracks it. He motivates this with a common workflow—setting the upstream of a new local branch to the remote’s default branch—and notes that this currently fails in shallow repositories unless `git remote set-head --auto` is run first. His suggestion would eliminate this manual step by ensuring the default branch is always available locally.

The email does not address the narrower-refspec approach or how the two alternatives might coexist. It also leaves open the exact refspec syntax (e.g., `:` or `+:`) and whether this mode would become the default for shallow repositories. The discussion remains focused on refining the matching-inspired fetch mode, with Harald’s input highlighting a practical edge case that would need to be handled.
