This thread is about fixing an intermittent HTTP/2 authentication failure in Git’s Debian 12 CI job, which affects two tests (`t5559.15` and `t5559.16`) in the half-auth clone suite. The issue stems from curl 7.88.1 (now corrected to 7.88.0) treating early 401 responses as transport errors, preventing authentication retries—a behavior fixed in curl 8.3.0.

The original patch by Johannes Schindelin proposed a CI-only workaround (hard-coded test skips in `ci/lib.sh`), which Junio approved but Peff critiqued for its limitations. Peff then offered two alternatives: a runtime prereq (`HAVE_CURL_HTTP2_BUG`) that skips the affected tests via test prerequisites, and a version-range-aware variant covering curl 7.88.0–8.3.0. Junio objected to the "conservative" label in Peff’s commit message, arguing the version-range approach could skip tests unnecessarily on unaffected versions. Peff clarified the trade-off between false positives and false negatives but left the final choice open.

Johannes’s latest reply refines the version range to start at 7.88.0 (not 7.88.1), tightening the scope of the workaround. The thread remains unresolved on whether to adopt the original CI-only skip, Peff’s single-version prereq, or the version-range prereq, though the corrected version boundary edges the discussion closer to consensus on the latter. No objections to the core diagnosis or need for a fix exist; the focus is now on implementation precision.
