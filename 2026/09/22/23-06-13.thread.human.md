This thread is about fixing an intermittent HTTP/2 authentication failure in Git’s Debian 12 CI job, specifically in tests `t5559.15` and `t5559.16`. The issue stems from Apache returning an early 401 response and closing the HTTP/2 stream before libcurl 7.88.1 (used in Debian 12) finishes sending the request body, causing curl to treat it as a transport error rather than allowing an authentication retry—a behavior fixed in curl 8.3.0.

Johannes Schindelin initially proposed a CI-only workaround (hard-coded test skips in `ci/lib.sh`), which Junio C Hamano approved. However, Jeff King (Peff) critiqued the approach for its limitations and offered two alternatives: a runtime prereq (`HAVE_CURL_HTTP2_BUG`) that detects curl 7.88.1 and skips the affected tests, and a more future-proof version-range-aware prereq that skips tests for any curl version between 7.88.1 and 8.3.0. The discussion now centers on which implementation to adopt, balancing robustness (Peff’s approaches) against simplicity (the original patch).

In the latest email, Junio raised a minor but pointed critique of the commit message wording in Peff’s version-range proposal. He argued that describing the version-range assumption as “conservative” is misleading, as assuming *all* versions from 7.88.1 onward are broken is aggressive, not conservative. While Junio didn’t dispute the technical approach, his feedback flags a potential source of confusion for future readers. The core question—whether to use the original CI-only skip, the single-version prereq, or the version-range prereq—remains unresolved, though Junio’s comment is unlikely to derail the discussion. No objections to the diagnosis or the need for a workaround have been raised.
