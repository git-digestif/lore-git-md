This thread is about fixing an intermittent HTTP/2 authentication failure in Git’s Debian 12 CI job, which affects two tests (`t5559.15` and `t5559.16`). The issue stems from Apache returning an early 401 response that curl 7.88.1 (Debian 12’s version) treats as a transport error, preventing authentication retries—a behavior fixed in curl 8.3.0.

Johannes Schindelin proposed a simple CI-only workaround (hard-coded test skip in `ci/lib.sh`), which Junio C Hamano approved. Jeff King (Peff) then offered two more robust alternatives: a runtime prereq (`HAVE_CURL_HTTP2_BUG`) that skips the tests for curl 7.88.1, and a version-range-aware prereq that skips any curl version between 7.88.1 and 8.3.0. Junio critiqued the commit message of the version-range approach, calling its "conservative" label misleading, as it assumes all versions in that range are broken. Peff’s latest reply clarifies the trade-off—prioritizing either avoiding flaky failures (version-range) or minimizing unnecessary test skips (single-version)—but leaves the final choice open.

The discussion remains focused on implementation strategy: whether to use the original CI-only skip, Peff’s single-version prereq, or the version-range prereq. All participants agree on the root cause and the need for a workaround, and no objections have been raised to the technical substance of the patches. The thread is nearing resolution, pending a decision on which approach to adopt.
