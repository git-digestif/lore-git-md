This thread is about a small but important fix to a recent CI workaround for an intermittent HTTP/2 authentication failure in Git’s Debian 12 CI job. The original patch introduced a runtime check (`HAVE_CURL_HTTP2_BUG`) to skip two problematic tests when running on curl versions 7.88.0 through 8.3.0, where an early 401 response from Apache causes libcurl to treat the failure as a transport error rather than allowing an authentication retry.

The new email reveals a latent quoting bug in that runtime check: the `awk` script’s `$1` and `$2` variables were being interpolated by the shell before `awk` could process them, which could cause the version check to fail silently. Jeff King (Peff) submitted a minimal fix—just four lines in the test script—that replaces the outer double-quotes with single-quotes and escapes the inner single-quotes, ensuring the variables are passed literally to `awk`. Johannes Schindelin, the original author, acknowledged the bug and suggested an alternative (moving the logic into a shell function for clarity), but he didn’t object to Jeff’s fix, which is already implemented and ready for integration.

The series is now technically settled. The main workaround patch, the quoting fix, and a follow-up patch that adds here-document support to the test framework are all confined to test infrastructure and don’t affect production code. Junio and Peff have both signed off on the approach, and the commit messages clearly document the version range assumptions and the quoting issue. The thread is effectively closed, with no open questions or loose ends.
