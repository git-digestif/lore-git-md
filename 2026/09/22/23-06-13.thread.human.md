This thread is about fixing an intermittent HTTP/2 authentication failure in Git’s Debian 12 CI job, specifically in tests `t5559.15` and `t5559.16`. The issue stems from Apache returning an early 401 response and closing the HTTP/2 stream before libcurl 7.88.0 (used in Debian 12) finishes sending the request body, causing curl to treat it as a transport error rather than allowing an authentication retry—a behavior fixed in curl 8.3.0.

The original patch by Johannes Schindelin hard-coded a test skip in `ci/lib.sh`, which Junio C Hamano approved but Jeff King (Peff) critiqued for being too limited. Peff proposed two alternatives: a runtime prereq (`HAVE_CURL_HTTP2_BUG`) that skips the affected tests for curl 7.88.0, and a version-range-aware prereq that skips tests for any curl version between 7.88.0 and 8.3.0. Johannes later confirmed the bug was introduced in curl 7.88.0 (not 7.88.1), adjusting the version range accordingly. The discussion now centers on which implementation to adopt, with the version-range approach favored by Johannes and Peff, though Junio has raised concerns about the commit message’s wording, arguing that labeling the version-range approach as "conservative" is misleading.

The latest email from Junio is a brief confirmation request to ensure the version range (7.88.0–8.3.0) is accurate before Johannes sends the next patch iteration. No new objections or proposals were raised, and the core unresolved question—whether to use the original CI-only skip, Peff’s single-version prereq, or the version-range-aware prereq—remains open. The participants agree on the diagnosis and the need for a workaround, but the implementation details and documentation clarity are still under discussion. Johannes is expected to send an updated patch with the corrected version range soon.
