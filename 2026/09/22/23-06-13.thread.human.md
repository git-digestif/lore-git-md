This thread is about fixing an intermittent HTTP/2 authentication failure in Git’s Debian 12 CI job, which affects two tests in `t5559` (subtests 15 and 16). The issue stems from Apache returning an early 401 response and closing the HTTP/2 stream before libcurl 7.88.1 (the version in Debian 12) can finish sending the request body, causing curl to treat it as a transport error rather than allowing an authentication retry—a behavior fixed in curl 8.3.0.

The original patch by Johannes Schindelin proposed a CI-only workaround, hard-coding a skip for the affected tests in `ci/lib.sh`. Junio approved this approach, but Jeff King (Peff) critiqued its limitations and offered two alternatives: first, a runtime prereq (`HAVE_CURL_HTTP2_BUG`) that skips the tests for curl 7.88.1, and now a refined version that extends the prereq to cover the entire problematic version range (7.88.1 to 8.3.0, exclusive). Peff’s latest patch is minimal, touching only `t/t5551-http-fetch-smart.sh`, and avoids hard-coded test numbers while working both in CI and locally.

The discussion now centers on which implementation to adopt: the original CI-only skip, Peff’s single-version prereq, or his newer version-range-aware prereq. Johannes and Junio have signaled acceptance of the original patch, while Peff prefers the more robust version-range approach but has left the decision open. No one disputes the diagnosis or the need for a workaround; the debate is purely about balancing simplicity and future-proofing. The thread remains unresolved, awaiting a final call on the implementation strategy.
