This thread is about fixing an intermittent HTTP/2 authentication failure in Git's Debian 12 CI job, which affects two tests (`t5559.15` and `t5559.16`) in the half-auth clone suite. The issue stems from Apache returning an early 401 response and closing the HTTP/2 stream before libcurl 7.88.0 (Debian 12) finishes sending the request body, causing curl 7.88.0–8.3.0 to treat it as a transport error rather than allowing authentication retries—a behavior fixed in curl 8.3.0.

The original patch, a CI-only workaround by Johannes Schindelin, was approved by Junio but critiqued by Jeff King (Peff) for its limitations. Peff proposed two alternatives: a runtime prereq detecting the buggy curl version and a version-range-aware prereq skipping tests for curl 7.88.0–8.3.0. After discussion, the version-range approach emerged as the leading candidate, with the version boundary corrected to reflect the bug's introduction in curl 7.88.0 (not 7.88.1). Junio’s latest feedback confirmed the version range is settled, though he noted the commit message should avoid calling the approach "conservative" to prevent misleading future readers.

The final patch, now posted by Johannes, implements the version-range-aware runtime prereq (`HAVE_CURL_HTTP2_BUG`) in `t/t5551-http-fetch-smart.sh`, marking the affected tests with `!HAVE_CURL_HTTP2_BUG`. It’s a minimal, CI-only change with no impact on production behavior or on-disk formats. The commit message documents the version range and trade-offs clearly, and the patch is ready for integration. The thread is effectively resolved, with consensus on the implementation and version bounds.
