This thread is about a fix for an intermittent HTTP/2 authentication failure in Git's Debian 12 CI job, specifically affecting tests `t5559.15` and `t5559.16`. The issue stems from a bug in curl versions 7.88.0 through 8.3.0, where Apache's early 401 response causes libcurl to treat the failure as a transport error rather than allowing an authentication retry. Johannes Schindelin initially diagnosed the problem and proposed a patch, which has since been refined into a version-range-aware runtime workaround.

The final patch, now ready for integration, introduces a new test prerequisite (`HAVE_CURL_HTTP2_BUG`) that detects affected curl versions and skips the problematic tests. The version range was corrected to 7.88.0–8.3.0 after Jeff King clarified the bug's introduction point. Junio Hamano and Peff have both reviewed and approved the approach, with Peff's latest "looks good to me" confirming the version-range implementation is settled. The fix is confined to the test script `t/t5551-http-fetch-smart.sh` and does not affect production code or on-disk formats. All open questions about the version range and implementation have been resolved.
