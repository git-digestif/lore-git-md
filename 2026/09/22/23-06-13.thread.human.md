This thread began with a fix for an intermittent HTTP/2 authentication failure in Git's Debian 12 CI job, where Apache's early 401 response triggered a transport error in curl 7.88.0–8.3.0. Johannes Schindelin implemented a runtime workaround using a version-aware test prerequisite (`HAVE_CURL_HTTP2_BUG`) to skip the affected tests (`t5559.15` and `t5559.16`), with the version range (7.88.0–8.3.0) settled by Junio Hamano and Jeff King. A follow-up patch from Peff fixed a quoting bug in the prerequisite snippet to ensure the version check worked correctly.

The latest email introduces a small but useful improvement to Git's test infrastructure. Jeff King extended the `test_lazy_prereq` function to support here-documents, allowing prerequisites to be written more cleanly without manual quoting of single quotes or shell variables. This change is purely ergonomic—it doesn’t alter test behavior—but makes complex prerequisites (like the `HAVE_CURL_HTTP2_BUG` check) easier to read and maintain. The patch updates the existing `HAVE_CURL_HTTP2_BUG` snippet as a real-world example, replacing its awkward manual quoting with a cleaner here-doc syntax. The change is uncontroversial and ready for integration, either as part of the original CI fix or as a separate topic. No further discussion or revisions are expected.
