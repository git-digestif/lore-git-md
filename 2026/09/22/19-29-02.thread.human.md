This thread is about modernizing cross-references in Git's man pages, replacing informal plain-text references with formal AsciiDoc link syntax to improve navigation in HTML-rendered documentation. Julia Evans proposed the change, which systematically updates 38 man pages to use the two-part AsciiDoc link form (`<<target,text>>`) for consistent rendering across backends. The patch was approved by Junio C Hamano and has been queued in the `next` branch since July 2024, though it hasn’t yet merged to `master`.

The key technical decision was adopting the two-part link form to avoid rendering inconsistencies in the docbook layer, where single-form links (`<<target>>`) can produce broken or nonsensical output (e.g., `[REMOTES]` in HTML or duplicated text in man pages). The patch uses manual anchors (e.g., `[[EDITING_PATCHES]]`) to preserve existing HTML fragment identifiers, though this may break some external links. The trade-off between link stability and readability was explicitly framed as a project decision, with the current approach prioritizing manual anchors for now. Jeff King (Peff) provided a detailed technical review, testing both AsciiDoc and Asciidoctor backends and confirming the necessity of the two-part form. His latest reply endorses the updated commit message but adds no new technical feedback.

The patch is ready for integration, with no open technical objections. The remaining discussion point—whether to prioritize link stability (manual anchors) or readability (auto-generated anchors)—was left unresolved but is not blocking the current effort. Minor typographic inconsistencies were noted but deferred for follow-up work. The thread reflects a collaborative effort to improve documentation maintainability while navigating toolchain quirks.
