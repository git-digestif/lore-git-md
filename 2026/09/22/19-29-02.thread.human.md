This thread is about modernizing cross-references in Git's man pages to make them clickable in HTML output. Julia Evans proposed a patch that replaces informal plain-text references (like "see EXAMPLES below") with formal AsciiDoc links (`<<target,text>>`) across 38 man pages. The patch has been approved by Junio Hamano and is queued in the `next` branch, meaning it's under integration testing but not yet merged into the main codebase.

The key technical detail is the use of the two-part AsciiDoc link form, which ensures consistent rendering across different backends (AsciiDoc and Asciidoctor). Jeff King (Peff) tested this thoroughly and confirmed it avoids edge cases where simpler link forms would break or produce odd output. The patch uses manual anchors (like `[[EDITING_PATCHES]]`) to preserve existing HTML fragment identifiers, which keeps external links working but diverges from AsciiDoc's auto-generated anchor conventions. This trade-off between link stability and readability is now the main open question, though it doesn't block the current patch from moving forward.

Julia's latest email clarifies the rationale behind the two-part link form and lays out three options for handling HTML fragment identifiers, leaning toward accepting some broken external links as the simplest solution. While the patch itself is uncontroversial and ready for integration, the broader discussion about anchor style could lead to future follow-up work. The thread also highlights how this effort fits into the ongoing documentation modernization led by Jean-Noël Avila.
