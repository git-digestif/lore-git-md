This thread is about modernizing cross-references in Git’s man pages to make them clickable in HTML output. Julia Evans proposed a patch replacing informal plain-text references (like "see EXAMPLES below") with formal AsciiDoc links (`<<target,text>>`) across 38 files. The patch was approved by Junio Hamano and is queued in `next`, with no prior versions or open questions.

The key technical detail is the use of the two-part link form (`<<target,text>>`) to ensure consistent rendering across AsciiDoc and Asciidoctor backends, avoiding edge cases like broken or duplicated text. Jeff King (Peff) validated this approach, testing both backends and documenting the trade-offs. However, in a recent review, Peff raised a new consideration: Git’s toolchain now supports auto-generated section IDs, which could simplify the patch but would change HTML fragment identifiers, breaking existing external links. While Peff prefers the readability of auto-generated IDs, he acknowledges the trade-off between link stability and maintainability.

The patch itself remains approved and ready for integration, but Peff’s feedback introduces a design question for future work: should the project prioritize link stability or adopt auto-generated IDs for cleaner markup? The discussion is collaborative, with no immediate need for a v2 unless Julia or others decide to revisit the approach. Other participants, like Kristoffer Haugsbakk, offered surface-level support, but the substantive review came from Peff and Junio.
