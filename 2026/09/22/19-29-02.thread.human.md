This thread is about modernizing cross-references in Git’s man pages to make HTML-rendered documentation more navigable. Julia Evans proposed a patch replacing informal plain-text references (e.g., "see EXAMPLES below") with formal AsciiDoc link syntax (`<<target,text>>`) across 38 files in the `Documentation/` directory. The patch was approved by Junio Hamano and is now queued in the `next` branch, meaning it’s under integration testing but not yet merged to the main codebase.

The key technical decision was adopting the two-part link form (`<<target,text>>`) to ensure consistent rendering across AsciiDoc and Asciidoctor backends, avoiding edge cases where the single form (`<<target>>`) produces broken output. The patch uses manual anchors (e.g., `[[EDITING_PATCHES]]`) to preserve existing HTML fragment identifiers, but this raises a design trade-off: auto-generated anchors (e.g., `_editing_patches`) would align with toolchain conventions but break external links. Julia framed this as an open question—whether to prioritize link stability or readability—but the current patch is uncontroversial and ready for integration. Jeff King (Peff) provided thorough testing and confirmed the two-part form’s necessity, while also clarifying minor details about where rendering issues appear (man pages, not HTML).

The only remaining loose end is the anchor style trade-off, which may be revisited in future discussions. For now, the patch is on track, with no further changes expected before it graduates to `master`.
