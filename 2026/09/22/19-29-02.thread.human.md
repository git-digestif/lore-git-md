This thread is about modernizing cross-references in Git’s man pages to improve navigation in HTML-rendered output. Julia Evans proposed replacing informal plain-text references (e.g., "see EXAMPLES below") with formal AsciiDoc link syntax (`<<target,text>>`) across 38 man pages. The patch was approved by Junio C Hamano and has been queued in `next` since July 18, 2024, with no technical changes needed—only a commit message revision to clarify the necessity of the two-part link form.

The core issue was ensuring consistent rendering across AsciiDoc and Asciidoctor backends, where the single-form link (`<<target>>`) could produce broken or nonsensical output (e.g., `[REMOTES]` in HTML or duplicated text in man pages). Jeff King (Peff) provided a detailed technical breakdown confirming the two-part form’s reliability, tracing the problem to the docbook layer’s default rendering behavior. While the patch uses manual anchors (e.g., `[[EDITING_PATCHES]]`) to preserve existing HTML fragment identifiers, the broader trade-off between link stability and readability remains unresolved. Julia framed this as a conscious design decision, and Peff’s follow-up reinforced the technical rationale without reopening the discussion.

Key participants include Julia (author), Junio (maintainer), and Peff (substantive reviewer). Kristoffer Haugsbakk offered a surface-level endorsement. The patch is ready for integration, but the anchor style question—whether to prioritize link stability or toolchain conventions—is left open for future consideration. No further action is expected unless someone revisits the docbook layer’s rendering defaults.
