The thread covers two related but distinct documentation efforts in Git. The first, now largely settled, is a cross-reference modernization in 38 man pages—replacing informal plain-text references with formal AsciiDoc links to improve HTML navigation. That patch series (v2) was approved by Junio C Hamano and has been queued in `next` since mid-July, though it hasn’t yet graduated to `master`. The only open question there is a design trade-off around anchor style: the current approach uses manual anchors for link stability but may break some external references, while auto-generated anchors would align better with toolchain conventions but risk more disruption.

The second effort, still in the early design phase, is a proposed rewrite of Git’s introductory tutorial. Julia Evans wants to simplify the tutorial by focusing on a core set of commands (`git init`, `git add`, `git commit`, `git status`, `git diff`, `git push`, `git config`, and `git remote add`) and deferring branches to a follow-up tutorial. The goal is to reduce cognitive load for beginners, but Junio has raised two concerns: first, that topics omitted from the new tutorial need a clear home—either discarded, relocated to other Git docs, or deferred to external resources—and second, that relying on external links (like `git-scm.com/learn`) is risky unless they can be reliably maintained. Julia has pushed back on the latter, noting that `git-scm.com/doc/ext` has been stable since 2013 and could be updated if links break, but Junio’s preference for a self-contained solution remains unresolved. The discussion is still at the strategy level, with no patch series posted yet, though early feedback from test readers (including Jeff King) has been positive. The rewrite aligns with the project’s recent shift toward ground-up tutorial improvements rather than incremental tweaks.
