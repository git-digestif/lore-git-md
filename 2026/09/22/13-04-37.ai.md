This is the second patch in Erik Cervin-Edin’s v3 series completing the `--fixup` message-option unification. It enables `-c` and `-C` for all `--fixup` variants (`--fixup`, `--fixup=amend:`, `--fixup=reword:`), removing the last inconsistency in the feature matrix.

The patch deletes the now-redundant `die_for_incompatible_opt3()` check that previously rejected `-c`/`-C` with `--fixup`; those options are already covered by the adjacent `die_for_incompatible_opt4()` that groups them with `-m` and `-F`. The fixup code path in `prepare_to_commit()` is extended to look up the commit referenced by `-c`/`-C` and seed its message, mirroring the existing `--fixup=amend` behavior when no message source is given. Documentation (`git-commit.adoc`) is updated to reflect that all four message options (`-m`, `-F`, `-c`, `-C`) now work consistently across all `--fixup` forms.

Test coverage in `t/t7500` is expanded with four new cases: `-C` with plain `--fixup`, `-c` with `--fixup=amend:`, message equivalence between `-C` and interactive amend, and nested squash/amend scenarios. The implementation preserves the existing logic that strips “amend!” lines when using `-c`/`-C` with amend-style fixups, ensuring clean final autosquash messages. All prior feedback has been addressed, and the series is now production-ready.
