This is an announcement for **Git for Windows 2.56.0-rc2**, the second release candidate for the upcoming Windows-specific distribution of Git. Johannes Schindelin, the maintainer of Git for Windows, has released this update to address several platform-specific issues and bundle the latest upstream components.

Key changes include the **dropping of Windows 8.1 support**, following the upstream MSYS2 project, which introduces internal path changes (e.g., `/ucrt64/bin/git.exe` replacing `/mingw64/bin/git.exe`). Users are advised to switch to `/cmd/git.exe` for stability if their setups are affected. The installer for the previous version (v2.55.0) had a bug that disabled the "Use external OpenSSH" option for some users, forcing the bundled OpenSSH to be installed; affected users are encouraged to re-run the installer to restore their preferred OpenSSH version. The release also fixes several bugs, including a 32-bit installer issue, a long-standing limitation preventing commits of 4GB or larger objects, a stack-smashing crash in parallel checkouts, and a regression in v2.55.0(5) where Vim would open files with the first line missing.

The bundled components have been updated to Git v2.56.0-rc2, Git LFS v3.8.0, cURL v8.22.0, and OpenSSL v3.5.8. This is a routine pre-release announcement for Git for Windows and has no direct implications for the upstream Git project. Users of Git for Windows should take note of the dropped Windows 8.1 support and the OpenSSH installer bug if upgrading from v2.55.0(5). No discussion or feedback is expected on the Git mailing list beyond Windows-specific context.
