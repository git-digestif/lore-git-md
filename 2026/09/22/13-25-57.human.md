This is a discussion about the Git v3.0 release timeline and scope, initiated by Johannes Schindelin in response to Junio C Hamano’s "What's cooking" report. Schindelin seeks confirmation on the agreed-upon release shape and timeline to help dependent projects plan accordingly.

The email clarifies that Git v2.99.1 and v3.0 will be released simultaneously around March–April 2027, differing only in their default handling of breaking changes. The version jump from v2.56 to v2.98 (skipping v2.57) was a deliberate decision to signal the proximity of v3.0. The primary purpose of v3.0 is to serve as a compatibility transition rather than introducing new features. Rust support is considered mandatory for v3.0, though portability concerns (e.g., for platforms like NonStop) remain unresolved despite no objections at the Contributor Summit.

A key challenge for v3.0 is SHA-256 interoperability, which is reportedly complete but not yet upstreamed. While GitLab and GitHub are progressing toward SHA-256 support (GitHub in private preview), JGit lacks it entirely, and no funding for its implementation was identified. This creates an uneven ecosystem transition. Schindelin’s summary also notes that v3.0 will handle historical tags in SHA-256 repositories, addressing a long-standing concern.

The tone is factual and collaborative, with Schindelin seeking Junio’s validation of the Contributor Summit’s consensus. The email does not propose changes but aims to align expectations for downstream projects. If Junio confirms this timeline, it will provide clarity for teams planning migrations or integrations around Git v3.0.
