This is the **second patch in the v3 bugfix series** for the reference-transaction hook regression, focusing on the `git branch` command. The series restores the pre-2.31 behavior where the hook receives the resolved old OID (instead of all-zeros) when branches are deleted, and this patch updates `git branch -d` to pass those OIDs to the refs API.

The patch modifies `delete_branches()` in `builtin/branch.c` to resolve the old OID for each branch before deletion and pass it to `refs_delete_refs()`. This ensures the reference-transaction hook receives meaningful old OID values, matching the behavior prior to Git 2.31. The change is straightforward: the function now iterates over the branch list, resolves each branch’s current OID, and stores it in a new `oid_array` passed to `refs_delete_refs()`. The patch also updates the function signature to accept a `quiet` flag, suppressing error messages when deletions fail (e.g., due to concurrent updates), which aligns with the existing behavior of `git branch -d`.

Key details:
- **Subsystem**: `git branch` command (`builtin/branch.c`).
- **New behavior**: `git branch -d` now resolves old OIDs before deletion and passes them to `refs_delete_refs()`, restoring the pre-2.31 hook behavior.
- **Backward compatibility**: The `quiet` flag ensures error messages are suppressed when deletions fail, preserving the existing user experience.
- **Performance**: No measurable impact, as the OIDs are resolved during the existing branch iteration.
- **Test coverage**: The series includes regression tests in `t/t1416-ref-transaction-hooks.sh` to verify the hook receives the correct old OIDs for branch deletions.

Junio’s review of the first patch (included in the parent summary) raises broader questions about the refs API design, such as whether `REF_TRANSACTION_ALLOW_FAILURE` should always be used in `refs_delete_refs()` and whether `ref_transaction_delete()` should handle null OIDs internally. However, these concerns are architectural and do not block this patch, which is a targeted fix for the regression. The patch is well-motivated, addresses the immediate issue, and integrates cleanly with the rest of the series. It is ready for final review alongside the other two patches.
