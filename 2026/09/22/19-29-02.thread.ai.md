Thread identity: Two distinct but related documentation improvement efforts in Git's `Documentation/` directory. The first is the **cross-reference modernization** (v2 patch series, originating author Julia Evans), a systematic replacement of informal plain-text section references with formal AsciiDoc link syntax (`<<target,text>>`) across 38 man pages to improve HTML navigation. The second is a **proposed rewrite of the Git tutorial** (`gittutorial.adoc`), also by Julia Evans, aiming to simplify the tutorial by focusing on a smaller set of commands (`git init`, `git add`, `git commit`, `git status`, `git diff`, `git push`, `git config`, `git remote add`) and omitting branches entirely, with the intention of covering branches in a separate follow-up tutorial (`gittutorial-2.adoc`). Both threads are documentation improvements but address different aspects: markup/toolchain behavior (cross-reference modernization) and pedagogy (tutorial rewrite).

Core problem or goal:
1. **Cross-reference modernization**: Replace informal references (e.g., "see EXAMPLES below") with formal AsciiDoc cross-references to improve navigation in HTML-rendered man pages. The effort explicitly addresses toolchain inconsistencies (AsciiDoc vs. Asciidoctor) and the trade-off between link stability (manual anchors) and readability (auto-generated anchors). The necessity of the two-part link form (`<<target,text>>`) is confirmed to avoid rendering edge cases (e.g., `[REMOTES]` in HTML or duplicated text in man pages).
2. **Tutorial rewrite**: Reduce cognitive load for Git beginners by simplifying the tutorial to cover only the most essential commands, deferring branches to a follow-up tutorial. The goal is to make the initial learning experience less overwhelming, with early feedback from test readers (including Jeff King) indicating positive reception. A key structural concern is ensuring that topics omitted from the new tutorial are either discarded, relocated to other Git documentation, or deferred to external resources, rather than left in limbo. Julia Evans now proposes a two-pronged strategy to address this: (1) writing new, clearer guides for material that still belongs in Git’s documentation, and (2) curating and linking to high-quality external resources (via `git-scm.com/learn`) for topics better suited to books or third-party guides. She argues that outdated guides like `gittutorial` and `giteveryday` are actively harmful and should be replaced with either improved internal guides or well-vetted external links.

Key technical details:
1. **Cross-reference modernization**:
   - Files: 38 files in `Documentation/`, including `git-rebase.adoc`, `git-grep.adoc`, `git-notes.adoc`, and `git-push.adoc`.
   - Change: Systematic replacement of informal references with formal AsciiDoc cross-references using the two-part form (`<<target,text>>`). Manual anchors (e.g., `[[EDITING_PATCHES]]`) are used for section targets, which may break existing external links.
   - Behavior: No functional change to man page content; only HTML navigation is improved. The two-part form ensures consistent rendering across AsciiDoc and Asciidoctor backends, avoiding edge cases where the single form fails (e.g., producing `the section called "EXAMPLES"` or `[EXAMPLES]` in HTML). The rendering inconsistencies stem from the docbook layer, where single-form links are expanded into verbose or inconsistent text.
   - Testing: Author built all man pages before and after the patch and verified no functional differences. Junio spot-checked specific examples. Jeff King independently tested both backends, confirming the two-part form’s reliability and documenting edge cases (e.g., `[REMOTES]` rendering, duplicated text in man pages).
   - Related effort: Part of the ongoing documentation synopsis-style conversion led by Jean-Noël Avila.
2. **Tutorial rewrite**:
   - File: `Documentation/gittutorial.adoc`.
   - Change: Complete replacement of the existing tutorial with a new version covering a smaller set of commands (`git init`, `git add`, `git commit`, `git status`, `git diff`, `git push`, `git config`, `git remote add`). Branches are omitted and deferred to `gittutorial-2.adoc`.
   - Behavior: Pedagogical simplification; no technical implementation details or edge cases discussed yet. The rewrite aligns with the 2026 Contributor’s Summit consensus favoring ground-up rewrites over incremental polishing of tutorial materials. Julia Evans now proposes addressing omitted topics by either writing new internal guides or linking to external resources via `git-scm.com/learn`.
   - Testing: Early feedback from test readers (including Jeff King) has been positive, but no formal testing or validation has occurred.

Open questions and loose ends:
1. **Cross-reference modernization**:
   - **Anchor style trade-off**: The patch uses manual anchors (e.g., `[[EDITING_PATCHES]]`), preserving existing HTML fragment identifiers but diverging from AsciiDoc toolchain conventions. Auto-generated anchors (e.g., `_editing_patches`) would align with toolchain conventions but break external links. Julia Evans outlines three options: (1) accept breaking some external links (current approach), (2) manually align anchors with auto-generated IDs (error-prone and confusing), or (3) find a way to use the single-form (`<<PRUNING>>`) reliably (ideal but unclear how to implement). The project has not yet decided whether to prioritize link stability or readability, though the current patch is approved and queued. This question remains open for follow-up discussion.
   - Minor typographic inconsistencies (e.g., quotation mark placement around cross-referenced text) were noted by Jeff King but deemed suitable for follow-up work.
2. **Tutorial rewrite**:
   - **Omitted topics triage**: Julia Evans has clarified her intent to address the gap left by omitted topics through a combination of new internal guides and external resources, but she has not yet specified which topics fall into which bucket (discardable, relocatable, or external). This remains an open question.
   - High-level objections to the proposed structure (e.g., omitting branches from the initial tutorial) are still solicited. No specific technical or pedagogical concerns have been raised beyond the triage question.
