Thread identity: Documentation cross-reference modernization in Git's man pages. Single patch, originating author Julia Evans, thread type: documentation improvement.

Core problem or goal: Replace informal plain-text section references (e.g., "see EXAMPLES below") with AsciiDoc link syntax (`<<target,text>>`) across 38 man pages in the `Documentation/` directory to improve navigation in HTML-rendered man pages. The two-part link form is confirmed as necessary for consistent rendering across AsciiDoc and Asciidoctor backends, avoiding edge cases where the single form (`<<target>>`) produces broken or nonsensical output (e.g., `[REMOTES]` in HTML or duplicated text in man pages). The thread explicitly frames the design trade-off between link stability (manual anchors preserving existing fragment identifiers) and readability (auto-generated anchors following AsciiDoc toolchain conventions) as a conscious project decision rather than an implementation detail.

Current status: Patch approved by Junio C Hamano and queued for integration in `next` since date unknown. Key technical details:
- Files: 38 files in `Documentation/`, including `git-rebase.adoc`, `git-grep.adoc`, `git-notes.adoc`.
- Change: Systematic replacement of informal references with formal AsciiDoc cross-references using the two-part form (`<<target,text>>`). The patch uses manual anchors (e.g., `[[EDITING_PATCHES]]`) for section targets.
- Behavior: No functional change to man page content; only navigation in HTML output is improved. The two-part form ensures consistency across all references and backends (AsciiDoc 10.2.1, Asciidoctor 2.0.26), avoiding edge cases where the single form fails (e.g., producing `the section called "EXAMPLES"` or `[EXAMPLES]` in HTML). The quoted rendering issue occurs only in man pages, not HTML, and includes additional context. Auto-generated anchors (e.g., `_editing_patches`) are supported by Git's toolchain but would alter HTML fragment identifiers, breaking existing external links.
- Testing: Author built all man pages before and after the patch and verified no functional differences. Junio spot-checked specific examples in the diff. Jeff King (Peff) independently tested both AsciiDoc and Asciidoctor implementations, confirming the two-part form’s reliability and documenting edge cases (e.g., `[REMOTES]` rendering, duplicated text in man pages). Peff also tested auto-generated anchors and noted their impact on link stability.
- Related effort: Part of the ongoing documentation synopsis-style conversion led by Jean-Noël Avila. The discussion includes broader documentation maintenance challenges, such as the fragility of auto-generated IDs for list items and the trade-off between link stability and readability.

Open questions and loose ends:
- **Anchor style trade-off**: The patch uses manual anchors (e.g., `[[EDITING_PATCHES]]`), preserving existing HTML fragment identifiers but diverging from AsciiDoc toolchain conventions. Auto-generated anchors (e.g., `_editing_patches`) would align with toolchain conventions but break external links. Julia Evans explicitly outlines three options: (1) accept breaking some external links (current approach), (2) manually align anchors with auto-generated IDs (error-prone and confusing), or (3) find a way to use the single-form (`<<PRUNING>>`) reliably (ideal but unclear how to implement). The project has not yet decided whether to prioritize link stability or readability, though the current patch is approved and queued. This question remains open for follow-up discussion.
