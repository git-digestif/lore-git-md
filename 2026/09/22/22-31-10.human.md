This is the third and final patch in a v4 bugfix series that restores the pre-2.31 behavior of the reference-transaction hook when pruning remote refs. The series targets a regression introduced in Git 2.31 where `git fetch --prune` and `git remote prune` stopped passing the resolved old OID to the hook, instead sending all-zero OIDs for both old and new values.

This patch updates the pruning logic in `builtin/fetch.c` and `builtin/remote.c` to pass the old OIDs recorded by `get_stale_heads()` into the deletion transaction. If a ref changes between the stale scan and deletion (e.g., due to a concurrent update), the transaction rejects that deletion but still removes the other stale refs. The UI now reports successful deletions individually ("[deleted]" or "[pruned]") while omitting failed refs from dangling symref checks, matching the existing behavior of these commands.

The implementation is clean: `prune_refs()` and `prune_remote()` now collect old OIDs into an `oid_array` and pass them to `refs_delete_refs()`, which returns a list of failed refs via its new `string_list` parameter. The patch also introduces a small helper struct (`stale_ref`) in `remote.c` to associate OIDs with ref names. Test coverage is thorough, with new tests in `t/t1416-ref-transaction-hooks.sh` verifying the hook receives the correct old OIDs for both atomic and non-atomic pruning, and that the UI correctly handles partial failures.

This patch completes the series. All feedback from Junio and Karthik has been addressed, and the rebase onto `master` is clean. The changes are low-risk (affecting only hook payloads and error reporting) and maintain backward compatibility. The series is ready for merging to `next`.
