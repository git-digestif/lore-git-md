This is a design discussion email from Junio C Hamano in response to Phillip Wood’s review of Harald Nordgren’s abandoned `fetch.shallow` patch. Junio endorses Phillip’s suggestion to address the root cause—wildcard fetch refspecs in shallow repositories—by modifying `git remote add` behavior, but proposes a more sophisticated alternative to simply narrowing the refspec to the current branch.

Junio suggests a new "matching-inspired" fetch mode for `git fetch` that would dynamically determine which remote branches to fetch based on the local branches’ upstream settings. In this mode, `git fetch` would inspect each local branch with an `@{upstream}` configured to the remote being fetched, then fetch only the corresponding remote branches (e.g., if local branch `feature` tracks `origin/main`, `git fetch origin` would fetch `refs/heads/main` from `origin`). This approach avoids the need for a network call to determine the remote’s default branch and instead relies on the local repository’s existing tracking relationships.

The proposal introduces a special refspec syntax (e.g., `:` or `+:`) to trigger this mode, analogous to `git push`’s matching mode, but Junio notes key differences: unlike push, this fetch mode would not enforce a one-to-one correspondence between local and remote branches (e.g., multiple local branches tracking the same remote branch would only fetch that remote branch once). The mode’s scope is limited to determining which remote branches to fetch, not how they are stored locally.

No code has been written yet, and Junio does not address how this mode would integrate with `git remote add` or whether it would replace the narrower refspec idea entirely. The email focuses on the conceptual design and leaves implementation details—such as the exact refspec syntax, how to handle edge cases (e.g., no local branches tracking the remote), and whether this would be the default for shallow repositories—open for further discussion. The proposal is positioned as a "useful addition" rather than a replacement for the original problem’s solution, suggesting it could coexist with other approaches.
