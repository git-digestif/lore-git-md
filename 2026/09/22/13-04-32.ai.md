This is a feature patch series (v3) completing Erik Cervin-Edin's effort to make `git commit --fixup` fully non-interactive by supporting all message specification options (`-m`, `-F`, `-c`, `-C`) across all `--fixup` variants (`--fixup`, `--fixup=amend:`, `--fixup=reword:`). The series is now in its third iteration, addressing the last remaining code hygiene issue identified in v2: a redundant option-checking function that became obsolete after the refactoring.

The two-patch series remains cleanly split: patch 1/2 enables `-m` and `-F` for all `--fixup` forms, while patch 2/2 extends that support to `-c` and `-C`. The only change since v2 is the removal of `die_for_incompatible_opt3()` in patch 2/2, which had become redundant because the remaining options it checked (`-C`, `-c`, `-F`) are already rejected by the adjacent `die_for_incompatible_opt4()` that groups them with `-m`. The commit message for patch 2/2 has also been reworded to better explain why `-c`/`-C` needed special handling once the other message options were unified.

The implementation continues to route all message sources through `prepare_to_commit()`, preserving message origin information and maintaining consistent behavior with interactive workflows. A subtle but intentional design choice keeps the existing logic that strips "amend!" lines when using `-c`/`-C` with amend-style fixups, ensuring the final autosquashed message does not retain redundant subject lines. The series includes comprehensive test coverage in `t/t7500` and `t/t7501`, and the documentation updates reflect the expanded capabilities.

All prior feedback from Junio Hamano and Phillip Wood has been addressed, and the series appears production-ready. Erik has dogfooded the feature for months, and the only remaining action is the minor code hygiene follow-up already implemented in this v3. The patches touch `builtin/commit.c` and the test suite, with no changes to core data structures or on-disk formats. The feature matrix is now complete: all four message specification methods work consistently across all three `--fixup` variants.
