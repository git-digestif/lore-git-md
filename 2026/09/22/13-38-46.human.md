This is a **user-experience bugfix** that addresses a long-standing pain point in shallow clones. Harald Nordgren’s v2 patch expands the scope of the original proposal to cover both failing and silently-truncated operations, making it a more complete solution.

The patch adds a new advice message (`advice.shallowHistory`) that fires whenever a revision walk stops exactly at a recorded shallow boundary. It now handles two distinct scenarios:

1. **Explicit ancestor syntax** (`<rev>~N` or `<rev>^N`) in commands like `git show HEAD~20` that fail with “is not a commit”. The advice explains the shallow boundary and suggests the exact `git fetch --deepen=<n>` command needed, auto-detecting the remote and branch if `<rev>` looks like `<remote>/<branch>`.
2. **Silent truncation** in commands like `git log -20` or `git log --since=2.months` that stop early at the shallow boundary without any error. The advice appears only when the last commit printed is the boundary itself, and it waits for the pager to close so it isn’t wiped from the terminal.

The implementation is careful: it suppresses the advice during internal re-resolution (to avoid double-printing), uses the remote’s real refspec to name the branch correctly, and only suggests deepening when the boundary is a true cutoff rather than a genuine root commit. Test coverage is thorough, with new cases for both failing and truncating scenarios, disabled advice, and non-shallow repos.

Junio’s review has already accepted the technical quality of the patch; the remaining discussion is about design scope rather than correctness. This v2 looks like a well-crafted, well-tested fix that directly improves the shallow-clone experience.
