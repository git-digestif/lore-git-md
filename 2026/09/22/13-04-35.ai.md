This is the first patch in Erik Cervin-Edin’s v3 series enabling non-interactive message specification for all `git commit --fixup` variants. It unifies support for the `-m` (inline message) and `-F` (message from file) options across plain `--fixup`, `--fixup=amend:`, and `--fixup=reword:` modes, eliminating the previous inconsistent restrictions.

The patch refactors `builtin/commit.c` to route `-m` and `-F` through the same `prepare_to_commit()` logic used for regular commits, removing the ad-hoc checks that previously rejected `-F` for any `--fixup` variant and `-m` for amend-style fixups. The key change is lifting the `!fixup_message` guard around the `-F` and stdin-reading branches, allowing them to supply message content alongside `-m`. The documentation (`git-commit.adoc`) is updated to reflect that `-m` and `-F` are now supported for all fixup types, and the test suite (`t/t7500`) is expanded with new cases verifying the behavior.

The implementation preserves backward compatibility: if no message option is provided, the editor still launches as before. The patch also maintains the existing logic that strips redundant "amend!" lines when autosquashing amend-style fixups, ensuring the final commit message remains clean. The only remaining restriction is on `-c`/`-C` (reuse existing commit message), which is handled in the follow-up patch (2/2) due to its need for special handling of message origin tracking.

This patch is a clean, focused refactoring that addresses all prior feedback on code reuse and test hygiene. The changes are confined to `builtin/commit.c` and the test suite, with no impact on core data structures or on-disk formats. The series as a whole is now production-ready, with Erik having dogfooded the feature for months and all substantive review comments from Junio Hamano and Phillip Wood resolved. The only remaining work is the second patch’s code hygiene follow-up, which has already been addressed in v3.
