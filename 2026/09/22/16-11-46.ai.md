This is a **security bugfix** for `git-p4`, the bidirectional bridge between Git and Perforce. The patch eliminates a shell injection vulnerability in the `applyCommit()` function, where a user-supplied commit ID passed via the `--commit` option could be interpreted as shell syntax (e.g., `$(touch evil)`) and executed during command substitution.

The fix replaces a shell-based pipeline (`git diff-tree ... | git apply ...`) with two direct subprocess calls connected by a pipe, removing the shell entirely. This matches the pattern already used elsewhere in `git-p4.py` (`read_pipe`, `p4_system`). The commit also adds a regression test in `t9803` that verifies `git p4 submit --commit` with a shell metacharacter payload does not execute it.

The vulnerability is clearly motivated: the commit ID from `--commit` is not validated, and the existing code uses `os.system(shell=True)` with interpolated values. The fix is minimal and surgical, touching only the affected code path. The test coverage is appropriate, exercising the exact attack vector. The commit message is thorough, explaining the problem, the fix, and the test. This looks like a well-crafted, serious contribution that addresses a real security issue.
