This thread is about adding lifecycle hooks to Git worktrees, with a focus on a missing piece: a **pre-worktree-remove** hook. Michał Papis argues that the current proposal lacks a way to clean up external resources (like Docker containers or databases) tied to a worktree before it’s deleted. Right now, post-removal hooks fire too late—after the worktree is gone—making it impossible to reliably map resources to their worktrees. Papis shares a real-world example where AI-generated worktrees left orphaned resources, requiring manual cleanup scripts to reverse-engineer associations. A pre-removal hook would solve this by allowing deterministic teardown while the worktree’s configuration is still accessible.

The discussion is pragmatic, acknowledging that the pre-removal hook wouldn’t veto removal but would complement existing hooks. It also notes a limitation: the hook would only work with `git worktree remove`, not manual deletions followed by `git worktree prune`, so post-removal hooks would still be needed for those cases. The thread hasn’t yet seen responses from maintainers or other contributors, so the idea remains open for feedback or objections.
