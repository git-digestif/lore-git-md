This is a discussion email clarifying the Git v3.0 timeline and scope, part of the ongoing "What's cooking" thread. Johannes Schindelin seeks Junio C Hamano's confirmation on whether his summary of the Git Contributor Summit's v3.0 plans accurately reflects the agreed-upon release shape and timeline.

The email recaps key decisions from the summit: Git v2.99.1 and v3.0 will be released simultaneously around March–April 2027, differing only in breaking-change defaults (not in features). The version numbering skips v2.57 in favor of v2.98 (December 2026) to emphasize the transition. Rust support is considered mandatory for v3.0, though portability concerns (e.g., NonStop platform) remain unresolved. SHA-256 interoperability is technically complete but not yet upstreamed, with uneven ecosystem adoption (GitLab supports it, GitHub is in preview, JGit lacks funding for implementation).

Schindelin’s summary also highlights the deliberate focus of v3.0 as a compatibility transition rather than a feature release. The email is a request for validation from Junio, positioning it as a reference for downstream projects planning around Git’s major version bump. No code changes or patches are proposed here—this is purely about aligning expectations. The tone is factual and collaborative, aiming to document consensus rather than debate technical details.
