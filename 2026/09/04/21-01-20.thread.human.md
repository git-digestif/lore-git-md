This thread fixes a long-standing bug in Git’s `--force-if-includes` safety mechanism, which incorrectly checked the reflog of the *local* branch matching the *remote* destination name (e.g., `refs/heads/main`) instead of the branch actually being pushed (e.g., `refs/heads/src` in `src:main`). The flaw could cause false rejections or unintended data loss, particularly when pushing from a differently named branch or a detached HEAD. The v4 series, now ready for merge, addresses all prior feedback from Junio C Hamano and Patrick Steinhardt, including edge cases like deletions, unresolved `HEAD`, and non-branch revisions (e.g., tags, object IDs). It also improves advice messages for unverifiable pushes (e.g., detached HEAD) and adds a config knob to customize behavior.

The series consists of two patches: the first fixes the core logic in `remote.c` to check the correct reflog, while the second updates advice messages and transport layers for consistency. All substantive review feedback has been resolved, and the series includes 81 lines of new test coverage. However, D. Ben Knoble recently raised a backwards-compatibility concern: the new behavior now rejects non-branch pushes (e.g., `git push origin <TAG>:hotfix`) when `--force-if-includes` is enabled, breaking workflows like resetting a hotfix branch to a tag and force-pushing it.
