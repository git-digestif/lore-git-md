This thread is about a patch series (v3) by Thomas Bachem that adjusts when Git's auto maintenance runs during sequencer-driven operations—`git rebase`, `git cherry-pick`, and `git revert`—to defer it until the sequence completes. This change aligns the behavior of these commands with the apply backend, preventing maintenance from interfering with intermediate steps.

The series is now effectively complete. All prior feedback from reviewers Phillip Wood, Patrick Steinhardt, and Junio C Hamano has been addressed, including design refinements like consolidating maintenance into a single exit path per command and removing a redundant `gc.auto=0` setting. The latest exchange resolves the final design question: Phillip Wood approved moving the `run_auto_maintenance()` call from the sequencer to the built-in commands (`rebase` and `revert`), simplifying the logic to "the command runs maintenance once when done." The only remaining work is minor polish to commit messages and tests, which the author has committed to addressing in the final version.

Key participants include Thomas Bachem (author), who implemented the deferral and addressed all feedback; Phillip Wood, who provided substantive reviews and approved the design; Patrick Steinhardt, who raised clarity and consolidation concerns; and Junio C Hamano, who offered mechanical feedback. The series is now ready for integration, with no open technical objections. The only watch item is a hypothetical edge case about long sequences where mid-sequence repacking might improve performance, but this is not considered a blocker.
