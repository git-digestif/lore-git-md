This thread is about a patch series by Thomas Bachem that adjusts when Git’s auto maintenance runs during sequencer-driven operations (`git rebase`, `git cherry-pick`, and `git revert`). The goal is to defer maintenance until the sequence completes, matching the behavior of the apply backend and preventing interference with intermediate steps. The series is now technically complete—all feedback from reviewers Phillip Wood, Patrick Steinhardt, and Junio C Hamano has been addressed, and the design has settled on moving the maintenance call out of the sequencer and into the built-in commands for a cleaner exit path.

Junio has signaled intent to queue the series ("Will queue"), meaning it will enter the `seen` branch shortly and is likely to graduate to `next` in the next integration cycle. The only remaining task is a final round of commit message polish in v4, focusing on brevity and clarity. Junio and Patrick have both critiqued recent commit messages for verbosity, urging tighter phrasing and human authorship over checklist-style or LLM-generated prose. Kristoffer Haugsbakk’s reply contextualizes this trend, noting that commit messages have grown more explicit (and longer) in recent months, though not necessarily clearer. Thomas has agreed to revise the messages to address these concerns, and once v4 is posted, the series should be ready for merging.

The technical changes are straightforward: auto maintenance now runs exactly once at sequence completion, and the config string passed via `GIT_CONFIG_PARAMETERS` has been simplified to `maintenance.auto=false` (dropping the redundant `gc.auto=0`). Tests verify that maintenance doesn’t run during intermediate steps, and the code structure is cleaner, with a reusable helper for building config strings and a cached `const char *` in `replay_ctx`. No open technical objections remain, though Phillip Wood has flagged a hypothetical edge case about long sequences where mid-sequence repacking might help—this is noted as a watch item but not a blocker. The series is on track for inclusion in the next release.
