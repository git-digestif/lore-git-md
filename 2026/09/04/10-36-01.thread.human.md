This thread is about Patrick Steinhardt’s 11-patch series to standardize Git’s terminology for "ref storage" across CLI options, environment variables, config keys, and documentation. The goal is to replace inconsistent terms like `--ref-format=` with `--ref-storage-format=` to avoid confusion, especially as Git prepares for a similar `--object-storage-format=` option. The series also fixes a bug where reinitializing a repository with a different ref storage format could silently corrupt it.

The latest update, patch 11, completes the series by enabling `--ref-storage-format=` to accept URIs like `files://path/to/alt-refs` or `reftable://path/to/db`. This allows users to specify alternate directories or database paths for the "files" and "reftable" backends, respectively. The patch enforces immutability of the ref-storage payload during reinitialization, ensuring mismatched payloads are rejected rather than causing corruption. Two new tests verify URI handling and reinitialization behavior. Earlier patches in the series addressed feedback from Junio C Hamano (who initially questioned the terminology) and Karthik Nayak (who pointed out inconsistencies in help text and missing macros), resulting in a cleaner, more consistent implementation.

The series is now under review, with no major objections remaining. Open questions include edge cases around URI handling (e.g., malformed URIs or unsupported schemes) and backward compatibility for third-party tools that might parse help output or error messages. The refactoring is mechanical and well-tested, with no functional regressions expected. If merged, it will pave the way for the upcoming object storage extension while improving clarity and robustness in Git’s ref storage configuration.
