This thread is Patrick Steinhardt’s v2 patch series to standardize Git’s terminology for "ref storage" across CLI options, environment variables, config keys, and documentation. The goal is to replace inconsistent terms like `--ref-format=` with `--ref-storage-format=` to avoid confusion, particularly ahead of a planned `--object-storage-format=` extension. The series also centralizes URI parsing for ref storage backends, enabling `--ref-storage-format=` to accept URIs like `files://path/to/repo`, and fixes a bug where reinitializing a repository with a different ref storage format silently corrupts it.

The v2 series is under review, with most feedback focused on surface-level details rather than technical objections. Junio C Hamano’s initial design concern—ambiguity around the term "ref-storage"—was resolved by adopting `--ref-storage-format=` to explicitly distinguish it from object hash. Karthik Nayak’s feedback on placeholder consistency and a missing environment variable macro has been addressed. Kaartic Sivaraam raised procedural questions about the backward-compatibility strategy for the old `--ref-format=` option (whether to deprecate it with warnings or retain it as a hidden alias) and minor inconsistencies, such as a typo in a test script (now fixed) and the `PARSE_OPT_NONEG` flag in `git refs migrate`. Patrick has acknowledged these points but deferred addressing the `PARSE_OPT_NONEG` inconsistency, leaving it as-is for now.

The series touches 53 test scripts and updates CLI options, environment variables, config keys, and error messages across `git init`, `git clone`, `git refs`, `git submodule`, and `git rev-parse`. It also introduces URI support for `--ref-storage-format=` (e.g., `files://path/to/repo`) and enforces immutability of the ref storage format during reinitialization to prevent silent corruption. Open questions remain about the lifecycle of the old `--ref-format=` option, URI handling edge cases (e.g., relative paths, security implications), and documentation gaps for backends other than "files" and "reftable." The series is uncontroversial in its core goal, but the backward-compatibility strategy and minor inconsistencies may require further discussion before merging.
