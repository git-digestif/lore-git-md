This thread is about Patrick Steinhardt’s v3 patch series to standardize Git’s terminology for "ref storage format" across CLI options, environment variables, config keys, and documentation. The goal is to replace inconsistent names like `--ref-format=` and `GIT_REFERENCE_BACKEND` with `--ref-storage-format=` and related variants, both for clarity and to prepare for a future `--object-storage-format=` extension. The series also fixes a bug where reinitializing a repository with a different ref storage format silently corrupted it, now enforcing immutability of the format and its URI payload (e.g., `files://path/to/alt-refs`).

Key participants are Patrick (author), Karthik Nayak and Kaartic Sivaraam (reviewers), and Junio Hamano (maintainer). The series is nearly ready to merge, with all substantive feedback addressed. Junio’s latest reply signals no remaining technical objections, though he and Karthik have questioned a minor implementation detail: whether `PARSE_OPT_HIDDEN` is redundant on the backward-compatible option aliases (e.g., `--ref-format=`). Patrick hasn’t responded to this nit, but both reviewers agree it’s not a blocker. Kaartic also raised a test coverage gap—no explicit tests for the deprecated aliases—but this too is non-blocking.

The series introduces URI support for `--ref-storage-format=` (e.g., `files://path/to/alt-refs`), centralizes URI parsing, and updates 54 test scripts. One edge case remains unresolved: the immutability check for payloads uses direct string comparison, which may reject semantically identical paths (e.g., `files:///path/to/store` vs. `files:///path/to/./store`). Patrick rejected Kaartic’s suggestion to normalize paths, arguing payloads aren’t guaranteed to be filesystem paths. The old option/variable names are retained as hidden aliases, with deprecation breadcrumbs in documentation. No merge status has been reported; the series is still under review.
