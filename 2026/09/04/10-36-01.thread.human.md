This thread is about Patrick Steinhardt’s eleven-patch series (v2) to standardize Git’s terminology for "ref storage" across CLI options, environment variables, config keys, and documentation. The goal is to replace inconsistent names like `--ref-format=` with `--ref-storage-format=` to avoid confusion, especially before introducing a similar `--object-storage-format=` option. The series also centralizes URI parsing for ref storage backends, allowing `--ref-storage-format=` to accept URIs like `files://path/to/repo`, and fixes a bug where reinitializing a repository with a different ref storage format silently corrupted it.

The series is under active review, with v2 addressing feedback from Junio Hamano (who initially questioned the ambiguity of "ref-storage"), Karthik Nayak (who pointed out inconsistencies in help text and a missing macro), and Kaartic Sivaraam (who raised procedural questions about backward compatibility and minor editorial issues). Key changes in v2 include renaming all instances of `--ref-format=` to `--ref-storage-format=` while retaining the old names as hidden aliases, adding URI payload support for the "files" and "reftable" backends, and enforcing immutability of the existing ref storage format to prevent silent corruption. The series touches 53 test scripts, multiple built-in commands (`init`, `clone`, `refs`, `submodule`, `rev-parse`), and environment variables/config keys, but makes no on-disk format changes.

Feedback has been largely surface-level, focusing on long-term maintainability (e.g., whether the old `--ref-format=` option should be deprecated or retained as an alias) and user communication (e.g., error message clarity, consistency of `PARSE_OPT_NONEG` flags). Kaartic’s latest review of patch 7/11 suggests tweaking error messages to label inputs as "configuration" for clarity, but this is purely editorial. No technical objections or edge-case concerns have been raised, though open questions remain about URI handling (e.g., relative paths, security implications) and the lifecycle of backward-compatible aliases. The series is still in discussion, with no merge status reported.
