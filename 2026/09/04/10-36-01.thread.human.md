This thread is a cleanup series by Patrick Steinhardt that standardizes Git's terminology for "ref storage format" across CLI options, environment variables, config keys, and documentation. The series, now at v2, replaces inconsistent names like `--ref-format=` with `--ref-storage-format=` to avoid confusion with object hash formats (controlled by `--object-format=`), and prepares the codebase for an analogous `--object-storage-format=` extension. It also centralizes URI parsing for ref storage backends, enabling `--ref-storage-format=` to accept URIs like `files://path/to/repo`, and fixes a bug where reinitializing a repository with a different format silently corrupted it.

The series is under active review, with Junio Hamano's initial design concern about terminology ambiguity resolved by adopting the more explicit `--ref-storage-format=` naming. Karthik Nayak's feedback on placeholder consistency and a missing environment variable macro has been addressed in v2. The refactoring is largely mechanical, with no behavior changes except for the bug fix in patch 8, which enforces immutability of the existing repository format to prevent silent corruption. Patch 11 enables URI payloads for `--ref-storage-format=`, completing the series' functional scope.

The latest review from Kaartic Sivaraam raises a procedural question about the backward-compatibility strategy for the old `--ref-format=` option: whether it should be deprecated with warnings (and eventually removed) or retained as a hidden alias. This introduces a new discussion point about the lifecycle of deprecated options, but the series itself remains uncontroversial and well-motivated. No merge status has been reported; the series is still in discussion pending further review.
