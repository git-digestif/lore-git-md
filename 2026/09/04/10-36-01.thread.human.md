This thread is about Patrick Steinhardt’s patch series to standardize Git’s terminology for "ref storage format" across the codebase, replacing inconsistent names like `--ref-format=` with `--ref-storage-format=` (and analogous updates for environment variables, config keys, and documentation). The series, now at v2, aims to eliminate confusion ahead of a planned `--object-storage-format=` extension and includes functional fixes like preventing silent repository corruption on reinitialization with mismatched formats.

Key participants include Patrick (the author), Karthik Nayak (who reviewed v1 and flagged minor inconsistencies now resolved), and Junio C Hamano (the maintainer, whose initial design concern about terminology ambiguity was addressed by adopting `--ref-storage-format=`). The series is under active review, with no major objections remaining. The latest update (the third patch in v2) mechanically renames `--ref-format=` to `--ref-storage-format=` in `git refs migrate`, retaining backward compatibility. This aligns with the broader effort to unify terminology without introducing regressions.

The series touches 41 test scripts, CLI options, environment variables, and config keys, with no on-disk format changes but new enforcement of immutability for existing repositories. Open questions remain about URI handling edge cases and backward compatibility for third-party tools parsing help output or error messages. The work is foundational for Patrick’s ongoing ODB abstraction and reftable backend efforts.
