This thread is about Patrick Steinhardt’s patch series to standardize Git’s terminology for "ref storage format" across CLI options, environment variables, config keys, and documentation. The series, now at v2, renames `--ref-format=` to `--ref-storage-format=` (and related names) to avoid confusion with future `--object-storage-format=` extensions, centralizes URI parsing for ref storage backends, and fixes a bug where reinitializing a repository with a different ref storage format silently corrupts it.

The series is under active review, with most feedback incorporated in v2. Junio C Hamano’s initial design concern about the ambiguity of "ref-storage" was resolved by adopting the more explicit `--ref-storage-format=` terminology. Karthik Nayak’s feedback on placeholder consistency and a missing macro was addressed, and Kaartic Sivaraam has raised procedural questions about backward compatibility and minor implementation details. The latest review from Kaartic on patch 9/11 highlights two small issues: error messages that misleadingly cite new environment variable names even when values come from old aliases, and an inconsistent test helper variable name. Neither is a blocker, but both are worth fixing for clarity. The series also introduces URI payload support (e.g., `files://path/to/alt-refs`) and enforces immutability of the ref storage format during reinitialization, though Kaartic identified an edge case where path normalization could cause false positives in the immutability check.

The main open questions remain the lifecycle of the old `--ref-format=` option (deprecate with warnings or retain indefinitely as a hidden alias) and minor consistency issues like the `PARSE_OPT_NONEG` flag and URI error message phrasing. No merge status has been reported, and the series is still in discussion pending further review.
