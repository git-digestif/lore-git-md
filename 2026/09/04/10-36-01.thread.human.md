This thread is the third iteration of Patrick Steinhardt’s 13-patch series to standardize Git’s terminology around "ref storage format." The goal is to replace inconsistent terms like `--ref-format=`, `GIT_REFERENCE_BACKEND`, and `init.defaultRefFormat` with a unified `--ref-storage-format=` (and related names) across CLI options, environment variables, config keys, and documentation. The series also fixes a bug where reinitializing a repository with a different ref storage format could silently corrupt it, and it centralizes URI parsing to allow `--ref-storage-format=` to accept paths like `files://path/to/alt-refs` for backends like "files" and "reftable."

The v3 revision addresses all feedback from v2. Key changes include:
- Using `OPT_ALIAS()` for backward-compatible option aliases (e.g., `--ref-format=` is now a hidden alias of `--ref-storage-format=`), which clarifies the relationship and avoids manual string duplication.
- Fixing error messages to correctly report whether a value came from the new or old environment variable (e.g., `GIT_REFERENCE_BACKEND` vs. `GIT_REF_STORAGE_FORMAT`).
- Renaming the test helper variable `GIT_TEST_DEFAULT_REF_FORMAT` to match the new pattern.
- Dropping the `ref-storage-format.adoc` update from `git-refs.adoc` since the `git refs` command doesn’t yet support URIs (documentation is now limited to `git init` and `git clone`).

The series is functionally complete and ready for review.
