This thread is about Patrick Steinhardt’s patch series (v3) to standardize Git’s terminology for "ref storage format" across CLI options, environment variables, config keys, and documentation. The goal is to replace inconsistent names like `--ref-format=` with `--ref-storage-format=` to avoid confusion, especially before introducing a similar `--object-storage-format=` option. The series also fixes a bug where reinitializing a repository with a different ref storage format could silently corrupt it.

Key changes include renaming options (e.g., `--ref-format` → `--ref-storage-format`), environment variables (`GIT_REFERENCE_BACKEND` → `GIT_REF_STORAGE_FORMAT`), and config keys (`init.defaultRefFormat` → `init.defaultRefStorageFormat`), while retaining backward-compatible aliases. It also centralizes URI parsing for ref backends, allowing `--ref-storage-format=` to accept URIs like `files://path/to/repo` with payloads (e.g., alternative directories for the "files" backend). The immutability of the ref storage format and its payload is now enforced to prevent silent corruption.

Most feedback has been addressed, including error message clarity, test variable renames, and documentation updates. The main open discussion revolves around the deprecation strategy for old option names: Patrick uses `OPT_ALIAS_F()` with `PARSE_OPT_HIDDEN` to hide deprecated aliases, while Junio C Hamano and Kaartic Sivaraam note that Git has historically tolerated public aliases (e.g., `--recursive` in `git clone`). Junio endorses Patrick’s approach but acknowledges the trade-off. A minor test coverage gap for deprecated aliases remains, but the series is otherwise ready for merging. No substantive objections or technical blockers are outstanding.

The series touches many commands (`init`, `clone`, `submodule`, `rev-parse`, etc.) and test scripts, with no on-disk format changes. It’s part of broader efforts to prepare for object storage extensions and ref backend improvements.
