This thread is about Patrick Steinhardt’s 11-patch series (v3) to standardize Git’s terminology for "ref storage format" across CLI options, environment variables, config keys, and documentation. The goal is to replace inconsistent names like `--ref-format=` and `GIT_REFERENCE_BACKEND` with `--ref-storage-format=` and `GIT_REF_STORAGE_FORMAT`, respectively, to avoid confusion ahead of a planned `--object-storage-format=` extension. The series also centralizes URI parsing for ref backends (e.g., `files://path/to/alt-refs`) and fixes a bug where reinitializing a repository with a different ref storage format silently corrupted it.

All substantive feedback from earlier versions has been addressed. The series now uses `OPT_ALIAS_F()` for backward-compatible option aliases, enforces immutability of the ref storage format and URI payloads, and updates error messages to clarify the source of values (e.g., environment variables). Karthik Nayak and Kaartic Sivaraam have reviewed the series, with Karthik signaling it’s ready for maintainer attention. Junio C Hamano’s latest reply approves the series but asks for further consideration of a minor implementation detail: whether `PARSE_OPT_HIDDEN` is redundant on `OPT_ALIAS_F()` aliases, a nit previously raised by Karthik. No other technical objections remain.

The series is effectively complete, pending this small flag adjustment. Once resolved, it’s likely to be merged. The only open question is whether to add explicit tests for the deprecated backward-compatible aliases, as suggested by Kaartic Sivaraam, though this is not a blocker. The work touches 54 test scripts, multiple built-in commands (`init`, `clone`, `refs`, `submodule`, `rev-parse`), and core files like `setup.c` and `refs.c`.
