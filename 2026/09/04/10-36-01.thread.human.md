This thread is Patrick Steinhardt’s 13-patch series to standardize Git’s terminology for "ref storage format" across CLI options, environment variables, config keys, and documentation. The goal is to replace inconsistent names like `--ref-format=` and `GIT_REFERENCE_BACKEND` with `--ref-storage-format=` and `GIT_REF_STORAGE_FORMAT`, clearing the way for a future `--object-storage-format=` extension. The series also fixes a bug where reinitializing a repository with a different ref storage format silently corrupted it, and adds support for URIs (e.g., `files://path/to/alt-refs`) to specify backend-specific payloads.

The v3 revision addresses all prior feedback, including backward-compatible aliases for old names, clearer error messages, and immutability checks to prevent corruption. Karthik Nayak and Kaartic Sivaraam reviewed the series, with Nayak’s latest acknowledgment signaling it’s ready for maintainer attention. The only remaining open question is Kaartic’s request to add explicit test coverage for the deprecated aliases (e.g., `--ref-format=`), ensuring they continue to work as intended. This is a test-coverage gap rather than a technical blocker, and Patrick will likely address it in a v4 or follow-up patch. The series is otherwise complete, with no substantive objections or unresolved design concerns.

Key changes since v2 include URI support in `git init`/`git clone`, stricter immutability checks for payloads, and mechanical renames of test variables. The backward-compatible aliases are implemented via `OPT_ALIAS_F()` and environment-variable fallbacks, but the test suite now exclusively uses the new names, leaving the old ones untested. The series touches 54 test scripts, `setup.c`, and most built-in commands that interact with ref storage, but no on-disk format changes are introduced.
