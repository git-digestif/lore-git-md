This thread is about Patrick Steinhardt’s patch series (v2) to standardize Git’s terminology for "ref storage" across CLI options, environment variables, config keys, and documentation. The goal is to replace inconsistent terms like `--ref-format=` with `--ref-storage-format=` to avoid confusion, especially as Git prepares for a similar `--object-storage-format=` extension. The series also centralizes URI parsing for ref storage backends, enabling `--ref-storage-format=` to accept URIs (e.g., `files://path/to/repo`) and fixes a bug where reinitializing a repository with a different ref storage format silently corrupted it.

The series is under active review, with v2 addressing feedback from Junio C Hamano (who initially questioned the ambiguity of "ref-storage" but was satisfied by the adoption of `--ref-storage-format=`), Karthik Nayak (who noted minor inconsistencies in help text and a missing macro, both fixed in v2), and Kaartic Sivaraam. Kaartic’s feedback has focused on backward-compatibility strategies—such as whether the old `--ref-format=` option should be deprecated or retained as a hidden alias—and minor consistency issues, like a typo in a test script and the use of the `PARSE_OPT_NONEG` flag in `git refs migrate`. No substantive technical objections have been raised, and the series remains a well-scoped refactoring with clear motivation.

Key changes in v2 include renaming CLI options (e.g., `--ref-format=` → `--ref-storage-format=`), environment variables (`GIT_REFERENCE_BACKEND` → `GIT_REF_STORAGE_FORMAT`), and config keys (`init.defaultRefFormat` → `init.defaultRefStorageFormat`), all while retaining backward-compatible aliases. The series also enforces immutability of the ref storage format during reinitialization to prevent silent corruption and introduces URI support for `--ref-storage-format=`, allowing payloads like alternate directories for the "files" backend. Open questions remain about the lifecycle of the old `--ref-format=` option and edge cases in URI handling (e.g., relative paths, security implications), but the series is otherwise uncontroversial and nearing readiness for integration.
