This thread is about Patrick Steinhardt’s eleven-patch series (v2) to standardize Git’s terminology for "ref storage format" across CLI options, environment variables, config keys, and documentation. The goal is to replace inconsistent names like `--ref-format=` with `--ref-storage-format=` to avoid confusion, especially before introducing an analogous `--object-storage-format=` option. The series also centralizes URI parsing for ref backends, enabling `--ref-storage-format=` to accept URIs like `files://path/to/repo`, and fixes a bug where reinitializing a repository with a different ref storage format silently corrupted it.

Key participants include Patrick (the author), Junio C Hamano (the maintainer), Karthik Nayak, and Kaartic Sivaraam. Junio’s initial concern about the ambiguity of "ref-storage" was resolved by adopting `--ref-storage-format=` to explicitly distinguish it from object hash. Karthik’s feedback on placeholder consistency and a missing macro was addressed in v2. Kaartic has raised procedural questions about the backward-compatibility strategy for the old `--ref-format=` option—whether it should be deprecated with warnings or retained indefinitely as a hidden alias—and spotted a minor typo in a test script. The series is under review, with no major technical objections raised so far. The refactoring is mechanical except for the bug fix in patch 8, which enforces immutability of the existing repository format to prevent silent corruption. URI payload support is now complete, allowing backends like "files" and "reftable" to use alternate directories or database paths. Open questions remain about the lifecycle of the old `--ref-format=` option and edge cases in URI handling.
