This thread is about Patrick Steinhardt’s patch series to standardize Git’s terminology for "ref storage format" across CLI options, environment variables, config keys, and documentation. The goal is to replace inconsistent names like `--ref-format=` with `--ref-storage-format=` (and related variants) to avoid confusion, particularly in preparation for an analogous `--object-storage-format=` extension. The series also centralizes URI parsing for reference storage backends, enabling `--ref-storage-format=` to accept URIs like `files://path/to/repo`, and fixes a bug where reinitializing a repository with a different ref storage format silently corrupts it.

The series is now at version 3, with all substantive feedback from earlier iterations addressed. Key changes include backward-compatible option aliases (e.g., `--ref-format=`) marked as hidden and deprecated in documentation, corrected error messages, and a renamed test helper variable. The series touches many areas—`git init`, `git clone`, `git refs migrate`, `git submodule`, environment variables, config keys, and 53 test scripts—but introduces no functional changes beyond the immutability enforcement for existing repository formats. The latest patch (5/13) updates `git submodule` to use the new terminology, following the same pattern as earlier patches.

The main open questions involve URI handling edge cases, such as whether backends other than "files" and "reftable" should reject payloads, how to handle relative paths in payloads, and whether the immutability check for payloads should normalize paths before comparison. Patrick has declined to address the latter, arguing that normalization is backend-specific. There’s also a minor inconsistency in the `PARSE_OPT_NONEG` flag usage across commands, which remains unresolved. Reviews from Karthik Nayak and Kaartic Sivaraam have been largely positive, with feedback focused on clarity and consistency rather than fundamental design objections. Junio C Hamano’s initial design concern was resolved by adopting the more explicit `--ref-storage-format=` terminology. The series is still under review, with no merge status reported.
