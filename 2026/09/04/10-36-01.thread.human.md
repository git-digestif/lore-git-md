This thread is about Patrick Steinhardt’s eleven-patch series to standardize Git’s terminology for reference storage formats. The goal is to replace inconsistent terms like `--ref-format=`, `GIT_REFERENCE_BACKEND`, and `init.defaultRefFormat` with a single, clear convention (`--ref-storage-format=`, `GIT_REF_STORAGE_FORMAT`, `init.defaultRefStorageFormat`) before introducing a similar mechanism for object storage. The series also centralizes URI parsing for ref backends (enabling paths like `files://path/to/alt-refs`) and fixes a bug where reinitializing a repository with a different ref storage format silently corrupts it.

The first version of the series is under review, with Junio C Hamano’s initial concern about ambiguous terminology resolved by adopting `--ref-storage-format=` to distinguish storage format from object hash. Karthik Nayak’s review has been largely positive, calling the refactoring “relatively quite an easy read” and noting only minor issues, such as a missing macro in `environment.h` (now fixed) and a placeholder inconsistency in help text (addressed in the planned v2). Patch 9, the latest update, mechanically renames environment variables while preserving backward compatibility, ensuring scripts using the old names continue to work.

The series is still in discussion, with v2 expected to finalize the new terminology across CLI options, config keys, documentation, and tests. Open questions include edge cases around URI handling and potential impacts on third-party tools parsing Git’s output. No merge status has been reported, and the series remains focused on cleanup and consistency rather than new features.
