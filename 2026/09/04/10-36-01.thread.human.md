This thread is about Patrick Steinhardt’s eleven-patch series to standardize Git’s terminology for "ref storage format" across CLI options, environment variables, config keys, and documentation. The series, now at v2, replaces inconsistent terms like `--ref-format=` with `--ref-storage-format=` to avoid confusion, particularly ahead of a planned `--object-storage-format=` extension. It also centralizes URI parsing for ref backends, enabling `--ref-storage-format=` to accept URIs like `files://path/to/repo`, and fixes a bug where reinitializing a repository with a different ref storage format silently corrupted it.

Key changes in v2 include adopting `--ref-storage-format=` (and `--object-storage-format=` for future object storage extensions) to address Junio C Hamano’s concern about ambiguity, fixing an inconsistency in the help text placeholder for `--ref-storage-format=`, and adding a missing macro for the default ref storage environment variable, both pointed out by Karthik Nayak. The series retains backward-compatible aliases for old option names, environment variables, and config keys to minimize disruption. Patch 8, the latest addition, refactors the logic for determining and validating the ref storage format during repository initialization, enforcing immutability of the existing format once set. This fixes the silent corruption bug and prepares the codebase for URI payload support in the final patch.

The series is under active review, with no substantive objections raised beyond the resolved terminology and placeholder issues. Karthik Nayak described v1 as "relatively quite an easy read" and "looks good otherwise," signaling broad agreement on the refactoring’s clarity and motivation. The remaining open questions center on URI handling edge cases, backward compatibility for third-party tools parsing help output or error messages, and documentation gaps for URI syntax in backends beyond "files" and "reftable." No merge status has been reported; the series is still in discussion pending further review.
