Thread identity
Subject: [PATCH 0/2] Modernize test scripts: replace `test -f` with `test_path_is_file`
Series version: v1 (initial submission; rejected in current form)
Originating author: Mark C. Chu-Carroll
Thread type: patch series (test modernization)

Core problem or goal
Replace older shell test idioms (`test -f`, `! test -f`, `test -d`) with more semantic helper functions (`test_path_is_file`, `test_path_is_missing`, `test_path_is_dir`) in 63 test scripts under `t/`. The goal is syntactic modernization, aligning with the project’s test guidelines; no behavioral changes or performance improvements are intended.

Current status
Rejected in its current form. Both Junio C Hamano and Patrick Steinhardt have reviewed the first patch and found the mechanical replacement of `test -f` with `test_path_is_file` incorrect when used in control-flow logic (e.g., checking for platform-specific files like `/proc/$shell_pid/winpid` or lazy file creation). The helper functions are designed for assertions, not silent conditionals, and their use in such contexts would turn silent checks into loud assertion failures. The series is blocked pending a rethink of the approach; no integration status or prior versions exist.

Key technical details
- Files touched: 63 test scripts in `t/` (exact list recoverable from the patches).
- New symbols: `test_path_is_file`, `test_path_is_missing`, `test_path_is_dir`, and related `test_path_is_*` helpers.
- Old-vs-new behavior: the patch as submitted would change silent conditionals into assertion failures, altering test semantics. Specific examples:
  - `t/t0031-lockfile-pid.sh` checks `/proc/$shell_pid/winpid` only on MINGW; conversion would error on non-MINGW platforms.
  - `t/t1007-hash-object.sh` uses `test -f` to avoid regenerating a 5GB file; conversion would fail if the file is missing.
  - `t/t4032-diff-inter-hunk-context.sh` expects missing files during setup; conversion would error.
- Base commit: `2c3adbb2c475981e340c79fdc5e7f4f9b5d9054e`.
- Change ID: `20260904-file-tests-use-shell-functions-e0d6c545d6c5`.

Open questions and loose ends
- How to distinguish between `test -f` used for assertions (where `test_path_is_file` is appropriate) and `test -f` used for control flow (where it is not).
- Whether the series should be split into smaller, targeted patches addressing only assertion contexts.
- The author has not yet responded to the rejection or indicated next steps.
- Procedural issues: the commit message lacks a Signed-off-by trailer, uses non-imperative style, and omits the rationale for the change.

Participant positions
