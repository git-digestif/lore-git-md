Core problem or goal
The `--force-if-includes` safety mechanism in `git push` incorrectly checks the reflog of the *local* branch whose name matches the *remote* destination branch (e.g., `refs/heads/main` when pushing to `refs/remotes/origin/main`), rather than the branch actually being pushed (e.g., `refs/heads/src` in `src:main`). This flaw can cause false rejections or unintended data loss. The series fixes the core logic to consult the reflog of the pushed ref (`ref->peer_ref->name`), rejects non-branch pushes (e.g., tags, object IDs, `HEAD~`) by default (configurable via `advice.forceIfIncludesDetachedHead`), and replaces misleading advice messages with actionable guidance. The v4 update tightens validation to reject all non-branch revisions, documents the rationale for allowing deletions, and refactors edge-case handling.
