Subject: [PATCH 0/2] sequencer: defer auto maintenance until rebase completion
Series version: v4 (3 patches, final unless design controversy requires v5)
Originating author: Thomas Bachem (via GitGitGadget)
Thread type: patch series

Core problem or goal
Adjust when auto maintenance runs during sequencer-driven operations (`git rebase`, `git cherry-pick`, `git revert`) so that it defers until sequence completion, matching the apply backend’s behavior. This prevents maintenance from interfering with intermediate steps and ensures consistent behavior across all three commands.

Current status
The series is in `seen` after Junio C Hamano signaled intent to queue it ("Will queue"). The reusable `git_config_append_parameter()` helper and config string caching remain in place. All prior feedback from Phillip Wood, Junio C Hamano, and earlier Patrick Steinhardt reviews has been addressed, including the minor header-comment rewording suggested in the latest email. The redundant `gc.auto=0` setting remains removed, and the config string is still `maintenance.auto=false` only. The test coverage question raised by Phillip Wood about `t/t3418-rebase-continue.sh` has been resolved: the test *does* trigger a conflict (both topic and main branches add `F2`), and the failing exec ensures maintenance only runs at the very end. Thomas has agreed to add a clarifying comment to the test, but no code changes are needed.

The **design controversy** is now the central blocker. Patrick Steinhardt’s **substantive review** challenges the current design’s delegation of maintenance to built-in commands (`builtin/rebase.c` and `builtin/revert.c`), arguing that the sequencer *does* have a single exit point (`pick_commits()`) where maintenance could be triggered consistently. Thomas’s latest reply demonstrates that single-commit paths for `git cherry-pick` and `git revert` (`cherry-pick <commit>`, `revert <commit>`, and their `--continue`/`--skip` variants) bypass `pick_commits()` entirely, exiting early through `continue_single_pick()` or `skip_single_pick()`. Only `git rebase` reliably reaches `pick_commits()`. This means Patrick’s alternative—triggering maintenance in `pick_commits()` and on abort—would miss the single-pick cases unless the sequencer also hooks the three early-return paths. Thomas has offered to implement either approach (sequencer hooks or built-in delegation) but asks Patrick to choose. The outcome will determine whether the series requires a v5 rewrite or can proceed as-is.

Key technical details
- Files touched: `sequencer.c` (specifically `pick_commits()`, `continue_single_pick()`, `skip_single_pick()`), `config.c`, `config.h`, `builtin/rebase.c` (`run_specific_rebase()`), `builtin/revert.c` (`run_sequencer()`), test files `t/t3418-rebase-continue.sh` and `t/t3510-cherry-pick-sequence.sh`
- New behavior: auto maintenance runs exactly once at sequence completion (after autostash is applied) instead of during intermediate commits/merges. The current patch delegates this to built-in commands; Patrick’s alternative proposes triggering it in `pick_commits()` and on abort, but this would miss single-pick cases unless the sequencer also hooks `continue_single_pick()` and `skip_single_pick()`.
- CLI/config impact: disables auto maintenance for individual commands (`git commit`, `git merge`, exec commands) during any sequencer-driven operation by passing `maintenance.auto=false` via `GIT_CONFIG_PARAMETERS`; invokes `git maintenance run --auto` at sequence completion. The redundant `gc.auto=0` setting remains removed.
- Subsystems: sequencer, auto maintenance, config
- New symbols: `git_config_append_parameter()` (helper in `config.c` for building `GIT_CONFIG_PARAMETERS` strings with proper shell quoting; format documented in header comment as a space-separated list of `'key'='value'` pairs, each side single-quoted, with `NULL` values treated as boolean `true`; the comment now clarifies the helper is general-purpose and not tied to `-c` command-line arguments), `disable_auto_maintenance()` (helper in `sequencer.c` that builds and caches the config string in `replay_ctx` as a `const char *` (immutable))
- Test coverage: extended in `t/t3418-rebase-continue.sh` and `t/t3510-cherry-pick-sequence.sh` using `GIT_TRACE2_EVENT` to verify `git maintenance run --auto` is executed exactly once at sequence end and not during intermediate steps. Tests assert the absence of maintenance during intermediate steps and use `test_grep` for better failure output. The rebase test now explicitly confirms it triggers a conflict (both topic and main branches add `F2`), and the failing exec ensures maintenance only runs at the very end. A clarifying comment will be added to the test.
