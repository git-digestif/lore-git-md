Thread identity
Subject: [PATCH 0/4] Fix MIDX reachability closure corner cases
Series version: v2 (eight patches, incorporating all feedback from v1)
Originating author: Taylor Blau
Thread type: patch series (bugfix)

Core problem or goal
The series fixes corner cases in Git’s multi-pack-index (MIDX) and cruft-pack machinery where MIDXs can end up containing objects that are not closed under reachability. This violates the MIDX’s invariant that it contains all objects reachable from its tips, causing failures in bitmap generation. The problem surfaces in four scenarios: `--stdin-packs=follow`, incremental repacks, `.keep` packs, and `--write-midx=incremental` (including `GIT_TEST_MULTI_PACK_INDEX_WRITE_INCREMENTAL`).

Current status
Under review; v1 was the initial submission, and v2 (now eight patches) addresses all substantive feedback from Jeff King, Derrick Stolee, and Junio C Hamano. The series is well-motivated, narrowly scoped, and ready for serious review. Patch 1/8, a pure refactoring introducing `stdin_packs_context`, has received maintainer approval in spirit and is uncontroversial. Patch 4/8, a mechanical refactoring replacing a linear search through `--keep-pack` arguments with a sorted list and binary search, is also uncontroversial and prepares the codebase for patch 5/8. Patch 6/8, a refactoring in `repack-midx.c`, introduces a `preferred_pack` field in the `midx_compaction_step` struct to explicitly track the preferred pack, removing the dependency on string-list order and enabling future optimizations such as sorting the list for faster membership checks. This change is mechanical, narrowly scoped, and uncontroversial, with no behavior changes. The patches touch `builtin/pack-objects.c`, `repack.c`, `repack-midx.c`, and add new tests in `t5331-pack-objects-stdin.sh`, `t7704-repack-cruft.sh`, and `t7705-repack-incremental-midx.sh`. Patch 1/8 is a mechanical refactoring; patch 2/8 addresses the `--stdin-packs=follow` scenario by ensuring trees and tags in included/excluded-open packs (or loose objects with `--unpacked`) are treated as roots for the reachability walk, now using an `oidset` for `extra_roots` (replacing the `oid_array` from v1) to avoid duplicates and ensure semantic correctness. The patch defers traversal of `extra_roots` until after the initial commit walk to preserve path prefixes for delta attributes and namehashes, though this remains best-effort due to tags potentially introducing commits in the second walk. Patch 3/8 fixes incremental repacks by forcing `midx_must_contain_cruft` to `1` when `--incremental` is passed to `pack-objects`, ensuring cruft packs are included in the MIDX. This patch is a narrow, well-justified fix addressing a regression introduced in commit 5ee86c273bf (June 2025), where incremental repacks could omit cruft packs from the MIDX when `repack.midxMustContainCruft` was set to "false". The change is minimal—just six lines in `builtin/repack.c`—and adds a targeted test in `t7704-repack-cruft.sh` to verify that incremental repacks can successfully write reachability bitmaps. Patch 4/8 refactors `existing_packs_collect()` to sort the `keep_pack_list` using `fspathcmp()` and replace the manual linear search with `string_list_has_string()`, making the search O(log n) instead of O(n). The patch documents the requirement that `extra_keep` must be sorted and use `fspathcmp()` as its comparator. This change is a prerequisite for patch 5/8, which addresses a performance pitfall with `.keep` packs during geometric repacks. Patch 5/8 modifies `builtin/repack.c` to pass excluded kept packs to the `--stdin-packs=follow` walk during geometric repacks when `repack.midxMustContainCruft` is false. Kept packs are marked with `!` (if outside the existing MIDX) or `^` (if already covered by it), allowing the walk to copy objects reachable from kept commits out of cruft packs without copying the kept objects themselves. This avoids the previous behavior of unconditionally including all cruft packs, which could cause performance issues during pushes. The patch also updates `repack-midx.c` to ensure cruft packs are included in the MIDX when kept packs are present, even in non-geometric repacks, and adds two new tests in `t7704-repack-cruft.sh` to verify the behavior. Patches 6/8 through 8/8 introduce structural improvements to the MIDX write steps, including handling geometric repacks with `.keep` packs by traversing ancestors of kept objects without copying the kept objects themselves, explicitly tracking the preferred pack in `midx_compaction_step`, and consolidating fixes for incremental MIDX writes.

Key technical details
- New struct: `stdin_packs_context` (refactoring of `--stdin-packs` handling in `pack-objects`).
- New data structure: `extra_roots` OID set in `stdin_packs_context` to collect trees and tags during pack traversal, replacing the `oid_array` from v1 for efficiency and semantic correctness.
- New field: `preferred_pack` in `midx_compaction_step` (patch 6/8) to explicitly track the preferred pack, removing dependency on string-list order and enabling future optimizations.
- Refactoring: Patch 4/8 replaces a linear search through `--keep-pack` arguments with a sorted list and binary search, improving efficiency from O(n) to O(log n). The `keep_pack_list` is sorted using `fspathcmp()` and searched using `string_list_has_string()`. Patch 5/8 modifies the geometric repack traversal to include ancestors of kept objects without copying the kept objects themselves, addressing a performance pitfall during pushes. Patch 6/8 refactors `midx_compaction_step` to track the preferred pack explicitly, simplifying the code and improving maintainability.
- Subsystems: MIDX, cruft packs, `git repack`, `git pack-objects`.
- On-disk format: unchanged; the fixes ensure MIDXs remain reachability-closed.
- Test coverage: new tests in `t5331` (four tests) verify `--stdin-packs=follow` scenarios (tree-only input packs, excluded-open tags, delta attributes for subtree contents), `t7704` (five tests) confirm incremental repacks, geometric repacks with `.keep` packs, and cruft pack inclusion, and `t7705` (two tests) verify incremental MIDX writes and bitmap generation.
- Files modified: `builtin/pack-objects.c` (patches 1/8, 2/8, and 5/8), `repack.c` (patches 3/8, 4/8, and 5/8), `repack.h` (patch 4/8), `repack-midx.c` (patches 4/8, 5/8, 6/8, 7/8, and 8/8), and the man pages for `git-pack-objects` (patch 2/8) and `git-repack` (patch 8/8).
- Behavior change: Trees and tags in included/excluded-open packs (or loose objects with `--unpacked`) are now walked *after* the commit traversal to preserve path prefixes for delta attributes and namehashes. Incremental repacks now always include cruft packs in the MIDX to maintain reachability closure. Geometric repacks now traverse ancestors of kept objects without copying the kept objects themselves, avoiding performance pitfalls during pushes. Incremental MIDX writes now include all required packs, not just newly written ones. The `keep_pack_list` is now sorted and searched using binary search, improving efficiency. The `midx_compaction_step` struct now explicitly tracks the preferred pack, removing dependency on string-list order.
- Bug origin: Patch 3/8 fixes a regression introduced in commit 5ee86c273bf (June 2025), where incremental repacks could omit cruft packs from the MIDX when `repack.midxMustContainCruft` was set to "false". Patch 8/8 addresses a previously unnoticed gap in `write_midx_incremental()`, which did not respect `midx_must_contain_cruft`. Patch 5/8 fixes a performance pitfall with temporary `.keep` files during pushes by adjusting the geometric repack traversal.
- Jeff King’s feedback on patch 2/8: Confirms the patch fixes a "timebomb" scenario where MIDXs could omit objects reachable only from trees/tags, breaking bitmap generation. Raises two technical nuances: (1) whether blobs could be handled similarly to trees/tags (answer: no, blobs can’t reference other objects), and (2) whether the two-walk approach (commits first, then `extra_roots`) is necessary or if a single traversal with all objects could suffice. Peff is skeptical of the two-walk approach’s ability to fully resolve path context ambiguities (e.g., tags pointing to commits could reintroduce the same issue) and suggests prioritizing high-context objects in the traversal queue as a more complete solution. Despite these concerns, Peff endorses the patch as a strict improvement over the status quo. Taylor Blau acknowledges these limitations but defends the current design as a net win, deferring deeper traversal machinery changes to future work. The v2 series documents the two-walk approach as best-effort for path context.
- Jeff King’s feedback on patch 3/8: Confirms the patch’s core premise—that incremental repacks (but not geometric repacks) can omit cruft packs from the MIDX when `repack.midxMustContainCruft` is false—and endorses the fix as reasonable. Identifies an **unaddressed edge case** in `write_midx_incremental()`, which is now fixed in patch 8/8. The fix in patch 3/8 is uncontroversial and ready for integration.
- Jeff King’s feedback on patch 4/8: No substantive feedback yet; the patch is a mechanical refactoring with no behavior change and is uncontroversial.
- Jeff King’s feedback on patch 5/8: The patch directly addresses Peff’s v1 concern about performance pitfalls during pushes by adjusting the geometric repack traversal to include ancestors of kept objects without copying the kept objects themselves. This avoids the race condition with temporary `.keep` files while maintaining reachability closure.

Open questions and loose ends
Jeff King’s **substantive review** of patch 2/8 questions the necessity of the two-walk approach (commits first, then `extra_roots`) and suggests a single traversal with all objects might suffice, while acknowledging the current approach is a net improvement. The discussion concludes with mutual agreement that rethinking the traversal machinery is best deferred to future work. The v2 series documents the two-walk approach as best-effort for path context, leaving the deeper traversal machinery changes as a loose end. Jeff King’s **substantive review** of patch 4/8 in v1 raised the question of whether `.keep` packs should be traversed during the reachability walk rather than unconditionally including cruft packs; this remains a design consideration for future work, though the v2 series addresses the immediate performance concern for geometric repacks (patch 5/8). The pre-existing edge case involving `--pack-kept-objects` and cruft packs that are themselves kept is acknowledged but deferred to a separate follow-up.
