Thread identity
Subject: [PATCH 0/4] Fix MIDX reachability closure corner cases
Series version: v2 (eight patches, incorporating all feedback from v1)
Originating author: Taylor Blau
Thread type: patch series (bugfix)

Core problem or goal
The series fixes corner cases in Git’s multi-pack-index (MIDX) and cruft-pack machinery where MIDXs can end up containing objects that are not closed under reachability. This violates the MIDX’s invariant that it contains all objects reachable from its tips, causing failures in bitmap generation. The problem surfaces in four scenarios: `--stdin-packs=follow`, incremental repacks, `.keep` packs, and `--write-midx=incremental` (including `GIT_TEST_MULTI_PACK_INDEX_WRITE_INCREMENTAL`).

Current status
Under review; v1 was the initial submission, and v2 (now eight patches) addresses all substantive feedback from Jeff King, Derrick Stolee, and Junio C Hamano. The series is well-motivated, narrowly scoped, and ready for serious review. Patch 1/8, a pure refactoring introducing `stdin_packs_context`, has received maintainer approval in spirit and is uncontroversial. The patches touch `builtin/pack-objects.c`, `repack.c`, `repack-midx.c`, and add new tests in `t5331-pack-objects-stdin.sh`, `t7704-repack-cruft.sh`, and `t7705-repack-incremental-midx.sh`. Patch 1/8 is a mechanical refactoring; patch 2/8 addresses the `--stdin-packs=follow` scenario by ensuring trees and tags in included/excluded-open packs (or loose objects with `--unpacked`) are treated as roots for the reachability walk, now using an `oidset` for `extra_roots` (replacing the `oid_array` from v1) to avoid duplicates. Patch 3/8 fixes incremental repacks by forcing `midx_must_contain_cruft` to `1` when `--incremental` is passed to `pack-objects`, ensuring cruft packs are included in the MIDX. Patches 4/8 through 7/8 introduce structural improvements to the MIDX write steps, including handling geometric repacks with `.keep` packs by traversing ancestors of kept objects without copying the kept objects themselves. Patch 8/8 consolidates fixes for incremental MIDX writes, addressing the `--write-midx=incremental` edge case Jeff King identified in v1 and ensuring all required packs are included in the MIDX chain.

Key technical details
- New struct: `stdin_packs_context` (refactoring of `--stdin-packs` handling in `pack-objects`).
- New data structure: `extra_roots` OID set in `stdin_packs_context` to collect trees and tags during pack traversal, replacing the `oid_array` from v1 for efficiency and semantic correctness.
- Subsystems: MIDX, cruft packs, `git repack`, `git pack-objects`.
- On-disk format: unchanged; the fixes ensure MIDXs remain reachability-closed.
- Test coverage: new tests in `t5331` (four tests) verify `--stdin-packs=follow` scenarios (tree-only input packs, excluded-open tags, delta attributes for subtree contents), `t7704` (three tests) confirm incremental repacks and geometric repacks with `.keep` packs, and `t7705` (two tests) verify incremental MIDX writes and bitmap generation.
- Files modified: `builtin/pack-objects.c` (patches 1/8, 2/8, and 5/8), `repack.c` (patch 3/8), `repack-midx.c` (patches 4/8, 5/8, 6/8, 7/8, and 8/8), and the man pages for `git-pack-objects` (patch 2/8) and `git-repack` (patch 8/8).
- Behavior change: Trees and tags in included/excluded-open packs (or loose objects with `--unpacked`) are now walked *after* the commit traversal to preserve path prefixes for delta attributes and namehashes. Incremental repacks now always include cruft packs in the MIDX to maintain reachability closure. Geometric repacks now traverse ancestors of kept objects without copying the kept objects themselves, avoiding performance pitfalls during pushes. Incremental MIDX writes now include all required packs, not just newly written ones.
- Bug origin: Patch 3/8 fixes a regression introduced in commit 5ee86c273bf (June 2025), where incremental repacks could omit cruft packs from the MIDX when `repack.midxMustContainCruft` was set to "false". Patch 8/8 addresses a previously unnoticed gap in `write_midx_incremental()`, which did not respect `midx_must_contain_cruft`. Patch 5/8 fixes a performance pitfall with temporary `.keep` files during pushes by adjusting the geometric repack traversal.
- Jeff King’s feedback on patch 2/8: Confirms the patch fixes a "timebomb" scenario where MIDXs could omit objects reachable only from trees/tags, breaking bitmap generation. Raises two technical nuances: (1) whether blobs could be handled similarly to trees/tags (answer: no, blobs can’t reference other objects), and (2) whether the two-walk approach (commits first, then `extra_roots`) is necessary or if a single traversal with all objects could suffice. Peff is skeptical of the two-walk approach’s ability to fully resolve path context ambiguities (e.g., tags pointing to commits could reintroduce the same issue) and suggests prioritizing high-context objects in the traversal queue as a more complete solution. Despite these concerns, Peff endorses the patch as a strict improvement over the status quo. Taylor Blau acknowledges these limitations but defends the current design as a net win, deferring deeper traversal machinery changes to future work. The v2 series documents the two-walk approach as best-effort for path context.
- Jeff King’s feedback on patch 3/8: Confirms the patch’s core premise—that incremental repacks (but not geometric repacks) can omit cruft packs from the MIDX when `repack.midxMustContainCruft` is false—and endorses the fix as reasonable. Identifies an **unaddressed edge case** in `write_midx_incremental()`, which is now fixed in patch 8/8.
- Jeff King’s feedback on patch 4/8: Raises two technical questions about the handling of `.keep` packs. First, whether the fix might trigger **racily** during pushes due to temporary `.keep` files Git installs to prevent pruning, potentially causing MIDXs to include cruft packs unnecessarily and degrade performance. Second, why the patch opts to **unconditionally include cruft packs** rather than treating `.keep` packs like other included follow-packs (i.e., traversing them during the reachability walk). Peff suggests the latter approach might be more principled, though it would require deeper changes to the pack-selection logic. Taylor Blau’s v2 response addresses the race condition concern for geometric repacks by adjusting the traversal to include ancestors of kept objects without copying the kept objects themselves (patch 5/8). For non-geometric repacks, the patch retains the conservative behavior of unconditionally including cruft packs, as kept objects may remain untraversed.

Open questions and loose ends
Jeff King’s **substantive review** of patch 2/8 questions the necessity of the two-walk approach (commits first, then `extra_roots`) and suggests a single traversal with all objects might suffice, while acknowledging the current approach is a net improvement. The discussion concludes with mutual agreement that rethinking the traversal machinery is best deferred to future work. The v2 series documents the two-walk approach as best-effort for path context, leaving the deeper traversal machinery changes as a loose end. Jeff King’s **substantive review** of patch 4/8 raises the question of whether `.keep` packs should be traversed during the reachability walk rather than unconditionally including cruft packs; this remains a design consideration for future work, though the v2 series addresses the immediate performance concern for geometric repacks. The pre-existing edge case involving `--pack-kept-objects` and cruft packs that are themselves kept is acknowledged but deferred to a separate follow-up.
