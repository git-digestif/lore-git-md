Subject: [PATCH 0/4] Fix MIDX reachability closure corner cases
Series version: v1 (initial submission)
Originating author: Taylor Blau
Thread type: patch series (bugfix)

Core problem or goal
The series fixes corner cases in Git’s multi-pack-index (MIDX) and cruft-pack machinery where MIDXs can end up containing objects that are not closed under reachability. This can cause failures when generating reachability bitmaps because the MIDX claims to contain all objects reachable from its tips, but some reachable objects are missing from the input packs. The problem surfaces in three specific scenarios: `--stdin-packs=follow`, incremental repacks, and `.keep` packs.

Current status
Under review; no prior versions of this series exist. The patches touch `builtin/pack-objects.c`, `repack.c`, `repack-midx.c`, and add new tests in `t5331-pack-objects-stdin.sh` and `t7704-repack-cruft.sh`. Patch 1/4 is a pure refactoring introducing `stdin_packs_context` to prepare for the subsequent fixes. Patch 2/4 addresses the `--stdin-packs=follow` scenario by ensuring trees and tags in included/excluded-open packs (or loose objects with `--unpacked`) are treated as roots for the reachability walk. Patch 3/4 fixes incremental repacks by forcing `midx_must_contain_cruft` to `1` when `--incremental` is passed to `pack-objects`, ensuring cruft packs are included in the MIDX to maintain reachability closure. Patch 4/4 fixes `.keep` packs by unconditionally including cruft packs in the MIDX whenever any kept packs are present, ensuring reachability closure.

Key technical details
- New struct: `stdin_packs_context` (refactoring of `--stdin-packs` handling in `pack-objects`).
- New data structure: `extra_roots` OID array in `stdin_packs_context` to collect trees and tags during pack traversal.
- Subsystems: MIDX, cruft packs, `git repack`, `git pack-objects`.
- On-disk format: unchanged; the fixes ensure MIDXs remain reachability-closed.
- Test coverage: new tests in `t5331` (four tests) verify `--stdin-packs=follow` scenarios (tree-only input packs, excluded-open tags, delta attributes for subtree contents) and `t7704` (three tests) confirm incremental repacks, geometric repacks with `.keep` packs, and rescue of descendants of loose trees.
- Files modified: `builtin/pack-objects.c` (patches 1/4, 2/4, and 4/4), `repack.c` (patch 3/4), `repack-midx.c` (patch 4/4), and the `git-pack-objects` man page (patch 2/4).
- Behavior change: trees and tags in included/excluded-open packs (or loose objects with `--unpacked`) are now walked *after* the commit traversal to preserve path prefixes for delta attributes and namehashes. Incremental repacks now always include cruft packs in the MIDX to maintain reachability closure. MIDXs now unconditionally include cruft packs whenever any kept packs are present.
- Bug origin: Patch 3/4 fixes a regression introduced in commit 5ee86c273bf (June 2025), where incremental repacks could omit cruft packs from the MIDX when `repack.midxMustContainCruft` was set to "false". Patch 4/4 addresses a previously unnoticed gap where `.keep` packs could reference objects in cruft packs, breaking MIDX reachability closure.
