Subject: [PATCH 0/4] Fix MIDX reachability closure corner cases
Series version: v1 (initial submission, v2 planned)
Originating author: Taylor Blau
Thread type: patch series (bugfix)

Core problem or goal
The series fixes corner cases in Git’s multi-pack-index (MIDX) and cruft-pack machinery where MIDXs can end up containing objects that are not closed under reachability. This can cause failures when generating reachability bitmaps because the MIDX claims to contain all objects reachable from its tips, but some reachable objects are missing from the input packs. The problem surfaces in three specific scenarios: `--stdin-packs=follow`, incremental repacks, and `.keep` packs.

Current status
Under review; v1 is the initial submission, and v2 is planned to address Jeff King’s feedback on patch 3/4. The patches touch `builtin/pack-objects.c`, `repack.c`, `repack-midx.c`, and add new tests in `t5331-pack-objects-stdin.sh` and `t7704-repack-cruft.sh`. Patch 1/4 is a pure refactoring introducing `stdin_packs_context` to prepare for the subsequent fixes. Patch 2/4 addresses the `--stdin-packs=follow` scenario by ensuring trees and tags in included/excluded-open packs (or loose objects with `--unpacked`) are treated as roots for the reachability walk. Patch 3/4 fixes incremental repacks by forcing `midx_must_contain_cruft` to `1` when `--incremental` is passed to `pack-objects`, ensuring cruft packs are included in the MIDX to maintain reachability closure. Patch 4/4 fixes `.keep` packs by unconditionally including cruft packs in the MIDX whenever any kept packs are present, ensuring reachability closure. Taylor Blau has addressed Junio C Hamano’s **surface-level** review of patch 1/4 by adding a comment to the `stdin_packs_context` struct to clarify that its `.revs` field must remain non-NULL. Taylor Blau has also accepted Derrick Stolee’s **substantive** suggestion to replace the `oid_array` for `extra_roots` in `stdin_packs_context` with an `oidset`; this change is mechanical, confined to `builtin/pack-objects.c`, and eliminates duplicate OIDs while aligning the data structure with its semantic purpose (tracking reachability, not order). The v2 series will include a fix for the unaddressed edge case in `write_midx_incremental()`, which does not respect `midx_must_contain_cruft`, potentially leaving the same reachability issue unresolved in `--write-midx=incremental` and `GIT_TEST_MULTI_PACK_INDEX_WRITE_INCREMENTAL` scenarios. The fix will add predatory patches to improve clarity, increasing the series length but maintaining coherence.

Key technical details
- New struct: `stdin_packs_context` (refactoring of `--stdin-packs` handling in `pack-objects`).
- New data structure: `extra_roots` OID set in `stdin_packs_context` to collect trees and tags during pack traversal. The change from `oid_array` to `oidset` was suggested by Derrick Stolee and Jeff King for efficiency and semantic correctness, as order and duplicates are irrelevant.
- Subsystems: MIDX, cruft packs, `git repack`, `git pack-objects`.
- On-disk format: unchanged; the fixes ensure MIDXs remain reachability-closed.
- Test coverage: new tests in `t5331` (four tests) verify `--stdin-packs=follow` scenarios (tree-only input packs, excluded-open tags, delta attributes for subtree contents) and `t7704` (three tests) confirm incremental repacks, geometric repacks with `.keep` packs, and rescue of descendants of loose trees.
- Files modified: `builtin/pack-objects.c` (patches 1/4, 2/4, and 4/4), `repack.c` (patch 3/4), `repack-midx.c` (patch 4/4), and the `git-pack-objects` man page (patch 2/4).
- Behavior change: Trees and tags in included/excluded-open packs (or loose objects with `--unpacked`) are now walked *after* the commit traversal to preserve path prefixes for delta attributes and namehashes. Incremental repacks now always include cruft packs in the MIDX to maintain reachability closure. MIDXs now unconditionally include cruft packs whenever any kept packs are present. The v2 series will address the `write_midx_incremental()` edge case by ensuring it respects `midx_must_contain_cruft`.
- Bug origin: Patch 3/4 fixes a regression introduced in commit 5ee86c273bf (June 2025), where incremental repacks could omit cruft packs from the MIDX when `repack.midxMustContainCruft` was set to "false". Patch 4/4 addresses a previously unnoticed gap where `.keep` packs could reference objects in cruft packs, breaking MIDX reachability closure.
- Jeff King’s feedback on patch 2/4: Confirms the patch fixes a "timebomb" scenario where MIDXs could omit objects reachable only from trees/tags, breaking bitmap generation. Raises two technical nuances: (1) whether blobs could be handled similarly to trees/tags (answer: no, blobs can’t reference other objects), and (2) whether the two-walk approach (commits first, then `extra_roots`) is necessary or if a single traversal with all objects could suffice. Peff is skeptical of the two-walk approach’s ability to fully resolve path context ambiguities (e.g., tags pointing to commits could reintroduce the same issue) and suggests prioritizing high-context objects in the traversal queue as a more complete solution. Despite these concerns, Peff endorses the patch as a strict improvement over the status quo. Taylor Blau acknowledges these limitations but defends the current design as a net win, deferring deeper traversal machinery changes to future work.
- Jeff King’s feedback on patch 3/4: Confirms the patch’s core premise—that incremental repacks (but not geometric repacks) can omit cruft packs from the MIDX when `repack.midxMustContainCruft` is false—and endorses the fix as reasonable. Identifies an **unaddressed edge case**: the `write_midx_incremental()` function (used by `--write-midx=incremental` and `GIT_TEST_MULTI_PACK_INDEX_WRITE_INCREMENTAL`) does not respect `midx_must_contain_cruft`, meaning the same reachability issue could still occur in those scenarios. Peff’s test with `--write-midx=incremental` reproduces the failure, though the environment variable `GIT_TEST_MULTI_PACK_INDEX_WRITE_INCREMENTAL=1` does not. Frames this as a pre-existing gap rather than a regression, leaving it to the author to decide whether to address it now or defer it to future work. The v2 series will address this edge case.
- Jeff King’s feedback on patch 4/4: Raises two technical questions about the patch’s handling of `.keep` packs. First, whether the fix might trigger **racily** during pushes due to temporary `.keep` files Git installs to prevent pruning, potentially causing MIDXs to include cruft packs unnecessarily and degrade performance. Second, why the patch opts to **unconditionally include cruft packs** rather than treating `.keep` packs like other included follow-packs (i.e., traversing them during the reachability walk). Peff suggests the latter approach might be more principled, though it would require deeper changes to the pack-selection logic. Neither question challenges the patch’s core goal, but both could prompt follow-up discussion or revisions.

Open questions and loose ends

The discussion concludes with mutual agreement that rethinking the traversal machinery is best deferred to future work. Jeff King’s **substantive review** of patch 3/4 surfaces an unaddressed edge case in `write_midx_incremental()`, which will be fixed in v2. Jeff King’s **substantive review** of patch 4/4 raises two new questions: (1) whether temporary `.keep` files during pushes could cause the MIDX to racily include cruft packs, degrading performance, and (2) whether `.keep` packs should be traversed during the reachability walk rather than unconditionally including cruft packs. The first question is particularly actionable, as it surfaces a potential real-world edge case not covered by existing tests. Junio C Hamano’s prior review of patch 1/4 noted a minor maintenance concern about the non-NULL guarantee of `stdin_packs_context.revs` if the struct is reused in future code; this has been addressed by Taylor Blau with a **surface-level** documentation improvement (a comment in the struct definition).
