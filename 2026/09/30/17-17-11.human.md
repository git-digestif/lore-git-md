This is Junio C Hamano's review of the final patch in Pablo Sabater's five-part series adding a `--dry-run` option to `git backfill`. The series is under active review and this email focuses on a specific implementation detail in the size-reporting logic.

Junio raises a design concern about the use of `ctx->object_info_enabled` to track whether size information is available. Currently, the code sets `ctx->object_info_enabled = 0` if the server either doesn't support the `object-info` capability (`FETCH_OBJECT_INFO_NOT_ENABLED`) or if the `results->sizes` array isn't populated. Junio finds this "yuck" because it overloads the meaning of `object_info_enabled`—it was originally meant to indicate whether the capability is supported, but now it's also being used to signal whether the size data is valid.

His suggestion is to introduce a dedicated boolean field, such as `ctx->sizes_valid`, to explicitly track whether the size data is usable. This would make the code clearer and safer, especially if other error conditions (beyond just `FETCH_OBJECT_INFO_NOT_ENABLED`) could leave `results->sizes` in an unusable state. The current implementation might be safe within the narrow scope of this series, but Junio's concern is about future maintainability and clarity.

The review is substantive but narrowly focused: it doesn't question the overall feature or its usefulness, but rather a specific internal design choice that could lead to confusion or bugs later. Pablo has already accepted other stylistic feedback from Karthik Nayak and is likely to address this suggestion in the upcoming v2 of the series. The patch remains well-crafted and addresses a real user need, but this review highlights a small but important refinement opportunity.
