This is a **documentation** patch in Kristoffer Haugsbakk’s RFC series converting Git’s `BreakingChanges` document into the new `gitbreaking-changes(7)` manpage. The email is a **substantive review** from Patrick Steinhardt, engaging with both the motivation and the implementation approach.

Patrick endorses the goal of making the breaking-changes document more discoverable to all Git users, not just contributors. He raises a forward-looking question: what happens to the document after Git 3.0 ships? His suggestion is to retain it (now that it is a manpage) and eventually add a new section for Git 4.0, though he notes that major releases should remain infrequent.

On implementation, Patrick critiques the patch’s mechanical approach: instead of first converting the existing `BreakingChanges` file in-place to the new AsciiDoc manpage format and *then* renaming it, the patch does both at once. This makes it harder to review what formatting changes were actually made. The critique is technical and specific, not a rejection of the series’ direction. No other objections or requests for changes are raised in this reply.
