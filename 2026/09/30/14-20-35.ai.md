This is the second patch in Tamir Duberstein’s v3 CI/build system series, now finalized and ready for integration. It unifies parallel job-count selection across GitHub Actions and GitLab CI by setting `JOBS` to **twice the detected CPU count** for both `make` and `prove`, replacing GitHub’s fixed `-j10` and GitLab’s one-job-per-CPU policy.

The patch is data-driven: cross-platform benchmarking (Linux, macOS, Windows) shows that `2x CPU count` yields a 7 % speedup on Linux over `1x CPU count` while avoiding a 26 % slowdown on macOS. The commit message includes a clear table of median build/test-step times, addressing Patrick Steinhardt’s prior request for evidence. Implementation touches only `ci/lib.sh` (13 insertions, 4 deletions), using native CPU-count queries (`nproc` on Linux, `sysctl -n hw.logicalcpu` on macOS, `NUMBER_OF_PROCESSORS` on Windows). No new CLI options, on-disk formats, or test coverage changes are introduced.

The oversubscription policy (2x CPU count) is the sole remaining point of review, but the empirical justification and cross-platform consistency make this a low-risk, high-impact improvement. The patch is self-contained and ready for integration alongside Patch 1.
