This is the v3 revision of a two-patch CI/build system series from Tamir Duberstein, addressing resource exhaustion in GitHub Actions CI jobs. The series is now effectively final, with both patches settled and ready for integration.

Patch 1 remains unchanged from v2: it replaces `test_cmp` (which uses `diff`) with `test_cmp_bin` (which uses `cmp`) in `t/t4205-log-pretty-formats.sh` to avoid OOM kills when comparing enormous test outputs. The change is well-motivated by benchmark data showing `diff` peaks at 4 GiB RSS and takes 5 seconds, while `cmp` uses 1.2 MiB and finishes in 0.5 seconds. This patch is uncontroversial and endorsed by Jeff King, Junio C Hamano, and Patrick Steinhardt.

Patch 2 is the substantive update in v3. It now uses *twice* the detected CPU count for `make` and `prove` on both GitHub Actions and GitLab CI, replacing GitHub’s fixed `-j10` and doubling GitLab’s existing one-job-per-CPU policy. The change is driven by new benchmark data: on Linux, `2x CPU count` yields a 7% speedup over `1x CPU count` (259.9 vs. 273.9 minutes total across jobs), while macOS shows a 16% slowdown with `1x CPU count` but only a 5% slowdown with `2x CPU count` compared to the fixed `-j10` baseline. The commit message now includes detailed timing data and justifies the trade-off: prioritizing Linux speed while mitigating macOS regressions. The implementation uses native CPU-count queries (`nproc` on Linux, `sysctl` on macOS, and `NUMBER_OF_PROCESSORS` on Windows) and unifies the logic for both CI platforms.

The series is pragmatic and well-explained, with no open technical questions. The changes are minimal (14 insertions, 5 deletions across two files) and do not introduce new CLI options, on-disk formats, or test coverage gaps. The only remaining step is integration.
