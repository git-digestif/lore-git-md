This is a bugfix for `git filter-branch` targeting the `--state-branch` commit mapping inversion. The patch is now under review by Patrick Steinhardt, who raises two process-oriented concerns: the lack of direct test coverage for the bug (the existing test only verifies that the state branch is consulted, not that the mapping is correct) and the absence of a reference to the commit that introduced the regression (f6d855091e, "filter-branch: stop depending on Perl", Git 2.50.0).

Patrick suggests a simpler one-line fix (`echo "${line#*:}" >../map/"${line%:*}"`) but does not object to the current two-line version. He asks Michele Locati—who previously confirmed the bug and the fix in a substantive, tested review—to contribute a more direct test case that exercises the swapped mapping entries and the `--prune-empty` scenario. The patch itself is technically sound and ready; the open question is whether the test suite should be expanded to catch this class of bug in the future.
