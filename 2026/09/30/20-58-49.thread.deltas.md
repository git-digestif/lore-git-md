# Thread deltas

## 2026/09/30

- [2026/09/30/20-58-49 by Harald Nordgren via GitGitGadget <gitgitgadget@gmail.com>] Harald Nordgren submitted a patch to teach "git stash pop" the --label-ours, --label-theirs, and --label-base options that "git stash apply" gained in 2.55 (13817db274), noting that pop applies the entry the same way and only differs by dropping it afterward.
- [2026/09/30/21-33-16 by Junio C Hamano <gitster@pobox.com>] Junio C Hamano questioned whether the feature is "because we can do it" rather than "because we need to have it", asked why the three options were added to "git stash apply" in the first place, and suggested that if there is no good use case the options should perhaps be removed from "git stash apply" rather than added to "pop".

## 2026/10/01

- [2026/10/01/09-47-52 by Phillip Wood <phillip.wood123@gmail.com>] Phillip Wood answered Junio's earlier question by saying the label options were added to "git stash apply" so that "git checkout -m" could have meaningful conflict labels; he judged better labels for autostashing commands a good use case for "apply" but was not convinced there is a good use case for "pop", since scripts should use "create" and "apply" rather than "push" and "pop".
- [2026/10/01/17-58-40 by Junio C Hamano <gitster@pobox.com>] Junio C Hamano agreed with that assessment ("Yup") and added that he had not realized the sequencer spawns "git stash apply" as a subprocess in do_stash_apply() rather than calling it internally, so the options do need to be exposed on "git stash apply".
