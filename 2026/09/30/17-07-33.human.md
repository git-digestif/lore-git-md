This is a review comment from Junio C Hamano on the third patch in Pablo Sabater’s five-patch series adding a `--dry-run` option to `git backfill`. The patch refactors `fetch_object_info()` to return a status code instead of dying when the server does not advertise the `object-info` capability, enabling graceful fallback for the upcoming dry-run feature.

Junio’s feedback is narrowly focused: he suggests renaming the `FETCH_OBJECT_INFO_NOT_ENABLED` enum value to `FETCH_OBJECT_INFO_NOT_AVAILABLE` to better reflect that the client cannot distinguish between a server that *cannot* support the capability and one that *chooses not to* enable it. The comment is purely about clarity and naming; Junio explicitly calls the code change itself "very cleanly done" and does not raise any technical concerns.

The patch remains ready for deeper technical review, but the author will likely incorporate this suggestion in the upcoming v2, which will also squash the enum-addition patch into this one and address other stylistic feedback from Karthik Nayak. No other objections or questions have surfaced in the thread so far.
