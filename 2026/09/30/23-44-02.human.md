This is the first patch in Jeff King’s seven-part series converting `mmfile_t` buffer sizes from `unsigned long` to `size_t` in the xdiff subsystem. It fixes a memory leak in `read_mmfile()`’s error path: when the function fails, it now frees any allocated buffer before returning, making the interface less error-prone for callers. The patch also plugs a related leak in `diff_two()` (used by `git rerere`) where a successful read of the first file followed by a failure on the second would leak the first buffer. Most callers already handle this correctly, but the change simplifies `rerere_forget_one_path()` by removing redundant initialization.

The fix is straightforward and well-motivated: the leak is real, the solution is minimal, and the commit message clearly explains the problem and the trade-offs (e.g., why not all callers can drop initialization). Junio has already acked this patch, and it looks ready to merge. If you care about memory safety in Git’s diff/merge machinery, this is a small but solid improvement.
