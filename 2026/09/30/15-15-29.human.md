This is a performance patch targeting the packed-refs backend. Karthik Nayak identifies a bottleneck in `write_with_updates()`: when rewriting the `packed-refs` file, unchanged references are still formatted via `fprintf()` even though they are already available in the snapshot buffer. The patch adds a `record_start` field to the `packed_ref_iterator` to track the raw bytes of each reference record, then uses `fwrite()` to copy them verbatim instead of reformatting. Benchmarks show a consistent ~20 % speed-up when deleting references from a large packed-refs file (100 000 refs).

The change is confined to `refs/packed-backend.c` and is purely internal; no user-visible behavior or on-disk format changes. The commit message is clear, includes before/after timings, and the code itself is straightforward: it adds a small state field to the iterator and switches one call site from `fprintf()` to `fwrite()`. No new tests are included, but the existing test suite should catch any regressions in ref handling. The patch looks well-motivated and ready for review.
