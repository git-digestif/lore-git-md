This is the second patch in a four-patch bugfix series for `git stash`, part of a follow-up to the recently merged `dk/stash-apply-index-incore` topic. The series addresses a latent error-handling bug in `do_apply_stash()` where hard merge failures could cause crashes.

This patch is a mechanical refactoring that moves the initialization of merge options (`init_ui_merge_options()`) earlier in `do_apply_stash()`. The change is preparatory: the next patch will reuse these options for error handling in the index merge path. The patch itself makes no functional changes—it simply relocates existing code to enable future reuse. The diff is clean, with no added or removed logic, just reordering.

The motivation is clear from the commit message: the options struct needs to be ready before the index merge is attempted, not just for the worktree merge. This is a sensible cleanup that reduces duplication and sets up the subsequent fix. The patch is uncontroversial and should integrate smoothly.

Reviewers familiar with the stash subsystem (like Phillip Wood) will likely approve this quickly, as it’s a straightforward preparation step for the real fix coming in patch 4. The series as a whole is well-structured, with this patch serving as a necessary foundation for the error-handling improvements.
