This is a bugfix for `git filter-branch` that corrects a long-standing commit mapping inversion in the `--state-branch` option. The patch is part of an ongoing review thread where the technical fix itself is settled, but there are minor process-oriented discussions still in play.

The bug causes `git filter-branch` to read commit mappings backwards when using `--state-branch`, leading to empty commit files and "Is a directory" errors on subsequent runs, especially when `--prune-empty` is used. The fix is a simple two-line change in `git-filter-branch.sh` that swaps how the "from" and "to" commits are written to the map directory. The author initially considered a one-line alternative suggested by Patrick Steinhardt but opted for the more explicit version for clarity.

The test coverage for this bug was previously broken—the existing test only verified that the state branch was consulted, not that the mapping was correct. The patch updates the test to use a failing tree filter (`exit 1`), ensuring the state branch is the only reason the command succeeds. While this change improves the test, Patrick Steinhardt notes it still feels indirect and has asked for a more direct test case to catch this class of bug in the future.

The patch is technically sound and has received a substantive, tested review from Michele Locati, who confirmed the bug and the fix. The only remaining loose ends are a typo in the patch subject ("fiter-branch") and whether the author should submit a revised version to address it. The author, being new to the project, asks whether such fixes are handled by the maintainer or require a resubmission. Given the minor nature of the typo, it’s likely the maintainer will correct it during integration.

Overall, this is a well-motivated, narrowly scoped bugfix with clear value for users who rely on `--state-branch` for incremental repository splitting. The patch is ready for merging once the test suite is expanded to directly verify the commit mapping correctness.
