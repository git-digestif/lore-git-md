This is the first patch in Jeff King’s v4 xdiff buffer-size refactoring series. It fixes a latent memory leak in `read_mmfile()`’s error path: when the function fails, it leaves the caller’s `mmfile_t` buffer allocated, forcing every caller to manually free it. The patch makes `read_mmfile()` clean up its own allocation on failure, eliminating the need for callers to handle this edge case. It also fixes a related leak in `diff_two()` where a successful read of the first file followed by a failure on the second would leak the first buffer. The change is purely internal and does not affect user-visible behavior. Junio C Hamano has already acked this patch, and it is uncontested. The patch touches `xdiff-interface.c`, `builtin/rerere.c`, and `rerere.c`.
