This is the fourth patch in a five-patch series adding a `--dry-run` option to `git backfill`. It implements the core dry-run logic: counting the missing blobs that would be fetched without actually downloading them.

The patch adds the `--dry-run` flag to the command-line parser, introduces a new `dry_run_batch()` helper that accumulates blob counts instead of fetching, and modifies the main backfill loop to branch on the dry-run flag. When the walk completes, it prints a message like "48 blobs would be fetched" using Git's pluralization helper. The test coverage verifies that the count matches the number of missing blobs and that no actual fetches occur (using `GIT_TRACE2_EVENT` to confirm).

The implementation is straightforward and clean: it reuses the existing batching machinery, only swapping out the download step for a counter. The commit message is clear, and the code follows Git's idioms (e.g., `Q_()` for pluralization, `OPT__DRY_RUN` for the flag). The only loose end is the output format, which the author has already flagged for feedback in the cover letter.

This patch looks ready for review; the preparatory refactorings in patches 1–3 have already modernized the `fetch_object_info()` API, so the dry-run logic here is not tangled with error-handling changes. The next patch (5/5) will extend the output to include blob sizes when the server supports `object-info`.
