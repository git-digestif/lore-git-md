This is the first patch in a four-patch bugfix series targeting the multi-pack-index (MIDX) and cruft pack machinery. The patch introduces a `stdin_packs_context` struct to refactor how `git pack-objects` handles `--stdin-packs` input, preparing the ground for later fixes to reachability closure corner cases.

The change wraps the existing `rev_info` pointer and `--stdin-packs` mode enum in a new struct, allowing the mode to be accessed within object enumeration callbacks. This is a pure refactoring with no functional changes: the logic remains identical, but the code is reorganized to make future patches cleaner. The diff touches only `builtin/pack-objects.c`, renaming function parameters and updating call sites to pass the new struct instead of separate arguments.

The commit message explains the motivation clearly: the current code passes the `rev_info` struct to callbacks, but the mode is only available at the top level, making it awkward to reference in lower-level functions. The new struct solves this by bundling both pieces of data together. The patch is well-scoped and does not introduce any new behavior, so it should be uncontroversial as a preparatory step.

This patch is a classic "prep patch" -- it does no real work on its own but enables the subsequent fixes in the series. The refactoring is mechanical and confined to a single file, reducing the risk of introducing bugs. Reviewers will likely focus on whether the new struct is the right abstraction and whether the call-site updates are correct, but the change itself is straightforward.

The series as a whole addresses a subtle but real issue in MIDX reachability closure, and this patch is the first step toward fixing it. The remaining patches will build on this refactoring to handle the three specific corner cases described in the cover letter.
