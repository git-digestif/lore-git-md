This is the third patch in Taylor Blau’s four-patch bugfix series targeting MIDX reachability closure corner cases. It addresses a specific scenario in incremental repacks where cruft packs might be omitted from the MIDX, breaking reachability bitmaps.

The patch fixes a long-standing issue (dating back to commit 5ee86c273bf from June 2025) where an incremental repack could write a new pack containing a commit and tree while leaving objects they reach (e.g., blobs) in an existing cruft pack. When `repack.midxMustContainCruft` is set to "false", the MIDX written after such a repack might exclude the cruft pack, causing bitmap generation to fail because the MIDX claims to contain all objects reachable from its tips but is missing some.

The fix is straightforward: when performing an incremental repack (i.e., when `--incremental` is passed to `pack-objects`), the code now forces `midx_must_contain_cruft` to `1`, ensuring cruft packs are included in the MIDX. This guarantees reachability closure even when geometric repacking (which would normally handle this via `--stdin-packs=follow`) is not used. The change is minimal, touching only `builtin/repack.c` and adding a single test in `t7704-repack-cruft.sh` to verify the fix.

The patch is well-motivated, with a clear explanation of the bug’s origin and why the fix works. The test coverage is appropriate, reusing an existing fixture to exercise the scenario where a cruft commit becomes reachable again. This is a targeted fix for a real issue, and the change is confined to the repack logic, so the risk of unintended side effects is low. The series remains uncontroversial and appears ready for review.
