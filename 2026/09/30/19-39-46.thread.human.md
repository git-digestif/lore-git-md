This thread is about adding `@{p}` as a shorthand for `@{push}` in Git’s revision syntax, mirroring the existing `@{u}` shorthand for `@{upstream}`. The patch, authored by Harald Nordgren, addresses a long-standing inconsistency: `@{u}` was introduced alongside `@{upstream}` in 2010, but `@{push}` (added in 2015) was never given a shorthand, not due to any deliberate exclusion but because the oversight went unnoticed.

The patch is uncontroversial and has been queued in Junio’s `seen` branch since July 10, 2026, with a clear path to graduation. The only remaining task is a commit message update to clarify the historical context—specifically, that the asymmetry was an oversight, not a design choice. Junio’s recent follow-up provides deeper historical background, linking to the 2015 `@{push}` series and a 2014 discussion where he himself questioned why `@{p}` wasn’t allowed alongside `@{u}`. This reinforces the patch’s rationale but doesn’t change its status. No technical objections remain, and the feature is a straightforward addition with no on-disk format changes or new symbols. Testing covers the new shorthand in various configurations. The patch is now just waiting for the author to send a v2 with the updated commit message.
