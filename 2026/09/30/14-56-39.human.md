This is the latest review in Harald Nordgren’s two-patch CI/build system series, now cooking in `next`. Phillip Wood’s reply to the second patch (v3 2/2) is a substantive technical review that surfaces usability and design questions about the GitHub Actions annotation format.

The patch itself replaces generic test-failure annotations with precise, clickable links pointing to the exact line in the test script where a failure or fixed breakage occurred. Phillip’s main concern is that the current GitHub Actions UI does not actually render these annotations as clickable links in the linux-leaks job output, making the improvement invisible to users. He also questions the necessity of escaping test descriptions (which have not needed escaping up to now) and carriage returns (since test descriptions are single-line), and notes that the patch does not apply the same escaping logic to existing annotations like the “group::” markers. Finally, he points out that dynamically generated tests—where line numbers would be most useful—cannot benefit from the literal-string-matching approach, leaving them with the fallback to line 1.

Harald has already addressed all correctness and portability issues raised in earlier rounds, but this feedback suggests the patch may still fall short of its usability goal in practice. The discussion is now focused on whether the annotation format is being interpreted correctly by GitHub’s UI and whether the escaping logic is over-engineered for the problem at hand.
