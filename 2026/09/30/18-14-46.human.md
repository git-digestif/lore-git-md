This is a feature proposal for `git backfill` that adds a `--dry-run` option to preview the cost of a backfill operation. The author, Pablo Sabater, is seeking feedback on whether the feature is actually useful to regular users.

Derrick Stolee, the original author of `git backfill`, responds with skepticism. He questions whether the size estimate (uncompressed blob sizes) is meaningful, since the actual download will be much smaller due to compression and deltification. He also points out that the "dry run" involves network calls, which might not align with users' expectations of what a dry run should entail. Stolee suggests that if the feature is kept, it should be split into separate options like `--info=count` or `--info=size` to make the cost of the preview explicit.

The exchange reveals a tension between the author's speculative motivation ("it seemed useful") and Stolee's preference for features grounded in real user needs. No technical objections to the implementation itself are raised here, but the discussion casts doubt on whether the feature, as currently conceived, solves a real problem. The thread is now waiting for either a stronger use case or a decision to drop the feature.
