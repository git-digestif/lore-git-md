This thread is about a patch from Harald Nordgren that adds `--label-ours`, `--label-theirs`, and `--label-base` options to `git stash pop`, mirroring functionality already available in `git stash apply`. The patch itself is straightforward—it touches `builtin/stash.c` and the man page, adds two tests, and passes the labels through to the existing conflict-marker machinery—but the discussion has stalled on whether these options belong in user-facing commands at all.

Junio C Hamano and Phillip Wood have both questioned the fundamental motivation. Junio clarified that the options were originally exposed in `stash apply` because the sequencer (used by `git rebase` and `git cherry-pick`) spawns `git stash apply` as a subprocess, so removing them would break autostash. That technical constraint doesn’t extend to `stash pop`, though, and both maintainers remain unconvinced that users will ever manually type long label arguments for `pop`. The patch is under review, but its fate hinges on whether a compelling use case emerges; for now, the discussion is stuck on whether the feature is a useful addition or unnecessary complexity.
