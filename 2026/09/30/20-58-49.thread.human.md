This thread introduces a small but useful quality-of-life improvement for `git stash`. Harald Nordgren has submitted a patch that extends `git stash pop` to support the same custom conflict-label options (`--label-ours`, `--label-theirs`, `--label-base`) that `git stash apply` already accepts. The change is minimal and mirrors the existing implementation: the options are plumbed through from `pop_stash()` to `do_apply_stash()`, documented in the man page, and verified with two new tests that check conflict marker labeling and empty-label handling.

The patch itself is straightforward and uncontroversial—it simply brings `pop` in line with `apply` without altering any existing behavior. There’s been no discussion yet, so no objections or requests for changes have surfaced. If the patch follows the usual path, it will likely be queued for `next` once it receives a Reviewed-by or Acked-by from a regular contributor. For now, it’s a clean, well-tested addition that fills a small gap in the stash workflow.
