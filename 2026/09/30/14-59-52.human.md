This is a gentle ping on a feature patch that makes `git blame` automatically look for and use a `.git-blame-ignore-revs` file in the repository root if no explicit ignore file is configured. The patch was posted a few days ago and has not yet received any review feedback.

The change aligns local `git blame` behavior with web interfaces like GitHub and GitLab, which already respect this file by default. This addresses a common source of user surprise when local blame output differs from what they see on the web. The implementation is careful: it uses `lstat()` to reject symlinks and non-regular files, ensures user-configured ignore files take precedence, and handles edge cases like subdirectory invocations, bare repositories, and empty files. The patch includes thorough test coverage and updates the documentation to clarify the new behavior.

The motivation is well-explained in the commit message, and the patch itself is self-contained, touching only the blame subsystem, documentation, and tests. No new user-facing options are introduced—it simply extends the existing ignore-file functionality with a sensible default. If this lands, users will no longer need to manually configure `blame.ignoreRevsFile` to match their web interface experience.

The patch looks ready for review, but so far no one has weighed in. If you work with blame or have opinions on default behavior, this is a good time to take a look.
