This is the second patch in Jeff King’s seven-part series refactoring the xdiff subsystem to use `size_t` instead of `unsigned long` for buffer sizes. This specific patch consolidates the redundant `mmbuffer_t` type into `mmfile_t`, eliminating a long-standing duplication that dates back to Git’s initial xdiff import in 2006.

The change is purely mechanical: every instance of `mmbuffer_t` is replaced with `mmfile_t`, and the now-unused `mmbuffer_t` struct is removed from `xdiff/xdiff.h`. The patch touches 16 files, including core merge logic (`merge-ll.c`, `merge-ort.c`), built-in commands (`builtin/merge-file.c`, `builtin/rerere.c`), and documentation (`Documentation/technical/api-merge.adoc`). No behavior changes are intended, and the commit message explains that the two types were functionally identical—both are simple `ptr`/`size` pairs—so the consolidation simplifies helper functions and removes an unnecessary distinction.

Junio C Hamano has already acked this patch, and the only substantive discussion during review centered on naming: Patrick Steinhardt questioned whether `mmfile_t` is the most semantically accurate name, but accepted the current approach as a practical step. The patch is uncontroversial and ready for merging as part of the larger series.
