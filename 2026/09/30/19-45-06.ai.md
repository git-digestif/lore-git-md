This is a **documentation patch review** in the `gitbreaking-changes(7)` RFC series. Junio C Hamano responds to Patrick Steinhardt’s review of Kristoffer Haugsbakk’s patch (2/4), which replaces message-ID references with clickable URLs in the new manpage. Junio’s feedback is **substantive but narrow**: he endorses the usability goal but argues the patch goes too far by removing the message-IDs entirely. Instead, he proposes a hybrid approach—embedding both the URL and the message-ID in the source (e.g., `cf. https://lore.kernel.org/git/xmqqa59i45wc.fsf@gitster.g/[<xmqqa59i45wc.fsf@gitster.g>^]`), so readers see a clean link while preserving the raw message-ID for future reference. He also notes that some message-IDs require URL encoding (e.g., `%` → `%25`), a detail the current patch handles but which could be made more explicit.

The review is **not a rejection** but a refinement request. Junio’s tone is constructive, and his suggestion is a minor technical adjustment rather than a conceptual shift. The hybrid format he proposes is a common pattern in Git’s documentation (e.g., in `RelNotes`), so it would align with existing conventions. No new patch version has been posted yet, so this remains an open discussion point. The files and subsystems touched are unchanged from the original patch (`Documentation/gitbreaking-changes.adoc`), and the change is still purely mechanical—no behavior or test coverage implications. The key detail for future discussion is the URL+message-ID format, which may become a point of consensus or further iteration.
