This is a bugfix for `git filter-branch` targeting a long-standing commit mapping inversion when `--state-branch` is used. The patch is under active review by Patrick Steinhardt, who acknowledges the fix but questions the test coverage and suggests a simpler alternative for the code change.

The core issue remains the same: the state branch stores mappings as "from_commit:to_commit" but the code reads them as "to_commit:from_commit", causing the map directory to be populated backwards. This becomes especially problematic with `--prune-empty`, leading to errors like "Is a directory" on subsequent runs. The fix itself—a two-line change in `git-filter-branch.sh`—is straightforward and uncontroversial, though Patrick proposes an even simpler one-line alternative that swaps the `${line%:*}` and `${line#*:}` expressions directly.

The test update is where discussion is focused. The current test verifies that the state branch is used by forcing a tree-filter failure (`exit 1`) and checking that HEAD remains unchanged, but Patrick finds this approach "roundabout" and asks for a more direct test that explicitly exercises the swapped mapping entries. Michele Locati, who previously confirmed the bug and fix through substantive testing, is now being asked to contribute a more targeted test case.

The patch is ready to merge from a technical standpoint, but the test coverage is the remaining open question. If Michele or Grant provides a clearer test, this could move forward quickly. The typo in the subject line ("fiter-branch") is a minor nit that won’t block progress.
