This is the fourth patch in Pablo Sabater’s five-patch series adding a `--dry-run` option to `git backfill`. It implements the core dry-run logic: walking the object graph, counting missing blobs, and printing the total without actually fetching anything.

The patch adds the `--dry-run` flag to the command-line parser, introduces a new `dry_run_batch()` helper that accumulates blob counts instead of downloading, and gates the actual download path behind a `ctx->dry_run` check. The output is a single line: “After backfill, N blobs would be fetched.” (with correct pluralization). Two new tests verify that the count is accurate and that no fetches occur during dry-run.

The preparatory refactorings in patches 1–3 already converted `fetch_object_info()` to return status codes instead of dying, so this patch can focus on the counting logic without worrying about error handling. The next patch (5/5) will extend the output to include blob sizes when the server supports the `object-info` capability.

Code changes are confined to `builtin/backfill.c`, the man page, and the test script. The implementation is straightforward and the commit message clearly explains the motivation and design. No substantive review feedback has appeared yet, but the patch looks clean and ready for technical scrutiny.
