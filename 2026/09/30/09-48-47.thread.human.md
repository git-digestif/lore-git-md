Phillip Wood’s patch series teaches `git checkout -m` to remember and reuse the original branch names in conflict markers, rather than falling back to generic labels like "ours" and "theirs." The series is under review, with two patches: the first refactors `remove_branch_state()` to use flags instead of a boolean, and the second adds the core functionality, storing labels in `.git/MERGE_LABELS` and updating `git checkout -m` to use them.

Junio’s review flagged two actionable concerns—documenting `.git/MERGE_LABELS` and handling line-ending portability on Windows—but the design itself was not questioned until Johannes Sixt (Hannes) suggested using an index extension instead of a separate file. This challenges the series’ core approach, as an index extension would avoid a new on-disk file and its associated cleanup and documentation overhead. The trade-offs (e.g., index bloat, compatibility) aren’t yet explored, but the suggestion is substantive enough to potentially reshape the series. Phillip also left open whether `git checkout -m` should remember the original conflict style (e.g., `diff3`), but no one has weighed in on that yet.

The series is still in its first version, and the next steps will likely depend on whether Phillip or Junio sees the index extension as a better path—or whether the current approach is defended. For now, the open questions are the conflict style feature and the storage mechanism, with Junio’s feedback on documentation and portability still unaddressed.
