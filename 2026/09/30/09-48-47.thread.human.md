This thread is about Phillip Wood’s two-patch series to make `git checkout -m` remember the original branch names used in conflict markers, so they match what the user saw during the initial merge. The series is under review, with no prior versions.

Phillip has implemented the change by storing the original labels in a new `.git/MERGE_LABELS` file, following the same pattern as other merge-related files like `MERGE_HEAD`. Junio reviewed the series and raised two actionable concerns: the new file should be documented alongside existing special files, and there’s a potential portability issue with line endings on Windows. Johannes Sixt suggested using an index extension instead of a standalone file, arguing it would be cleaner, but Phillip has now defended the current approach, citing compatibility with other merge strategies and consistency with existing Git practices.

The main open questions are whether the series should also remember the original conflict style (e.g., `diff3`), and whether the portability concern around line endings needs to be addressed before the series can move forward. The architectural discussion about index extensions remains exploratory but is unlikely to block this series, as Phillip has signaled a preference for the current design. No objections to the core functionality have been raised, and the series is expected to proceed once the documentation and portability feedback is addressed.
