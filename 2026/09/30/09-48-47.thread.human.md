This thread is about a small but user-visible improvement to `git checkout -m`: making it remember and reuse the original branch names in conflict markers, rather than showing generic labels like "ours" and "theirs". Phillip Wood sent a two-patch series to implement this for Git's ort merge backend. The first patch, just summarized, is a preparatory refactoring that converts a boolean argument to a flags field, setting the stage for the actual feature in the second patch.

So far, the series is under review with no feedback yet. Phillip has explicitly asked whether the feature should also remember the original conflict style (like `diff3`), not just the labels, but hasn't received any responses on that question. The implementation touches the merge machinery (`merge-ort.c`), branch handling (`branch.c`), and the checkout command itself, and adds a new `.git/MERGE_LABELS` file to store the original labels. The test in `t/t7201-co.sh` verifies that the labels are preserved correctly. No objections or concerns have been raised yet, but the discussion is still early.
