This thread is about a two-patch series by Phillip Wood that teaches `git checkout -m` to remember and recreate the original branch names in conflict markers, rather than using generic labels like "ours" and "theirs". The series is now ready for merging after three iterations.

Phillip addressed all technical feedback from Junio Hamano in the latest version (v3), including a correctness bug that could write malformed `.git/MERGE_LABELS` files for clean merges, API improvements, and portability fixes. The implementation stores the original conflict labels in a new ephemeral file `.git/MERGE_LABELS` (analogous to existing files like `MERGE_MSG`) and reuses them when `git checkout -m` is invoked. Tests verify the feature works as intended and that the file is properly cleaned up.

Junio has accepted the series and will queue it in his integration branches. The only remaining discussion—whether `git checkout -m` should also restore the original conflict style (e.g., `diff3`)—was explicitly scoped out of this series to keep it uncontroversial. Phillip and Junio both noted that users can already specify the style manually if needed, so the current design is sufficient. The architectural alternative of using an index extension instead of `.git/MERGE_LABELS` was raised by Johannes Sixt but rejected by Phillip for compatibility reasons.
