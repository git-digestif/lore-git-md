This thread is about a two-patch series by Phillip Wood that improves `git checkout -m` by making it remember and reuse the original conflict labels (branch names) from the initial merge, rather than showing generic labels like "ours" and "theirs". The series is now at version 2, addressing Junio Hamano’s feedback on documentation and line-ending portability.

The first patch is a preparatory refactoring with no user-visible changes: it replaces the `verbose` boolean argument in `remove_branch_state()` with an `unsigned flags` field, introducing `REMOVE_BRANCH_STATE_VERBOSE` as the sole flag. This sets the stage for the second patch, which adds the new functionality. The refactoring is uncontroversial and has not drawn any substantive feedback.

The second patch, which implements the core feature, stores the original conflict labels in `.git/MERGE_LABELS` and reuses them when `git checkout -m` is invoked. It handles edge cases like missing or malformed labels by falling back to generic labels, ensures cleanup via `git commit` and `git sequencer`, and uses `strbuf_getline()` for consistent line-ending handling across platforms. Junio’s feedback on documentation and portability has been fully addressed in this version.

Two open questions remain: whether `git checkout -m` should also remember the original conflict style (e.g., `diff3`), and whether the `.git/MERGE_LABELS` file is the right architectural choice (Johannes Sixt suggested using an index extension instead). Phillip has rejected the index extension approach for now, citing compatibility with other merge strategies and alignment with existing patterns like `MERGE_MODE`. Junio explored the trade-offs but remained neutral. No feedback has been provided yet on the conflict style question.

The series is under review, with Phillip and Junio as the key participants. Phillip has demonstrated attention to detail in addressing edge cases and cross-platform robustness, while Junio’s concerns have been fully resolved in v2. The architectural discussion around index extensions is unresolved but not blocking the series.
