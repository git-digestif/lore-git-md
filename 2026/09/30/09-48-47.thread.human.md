This thread is about Phillip Wood’s patch series that teaches `git checkout -m` to remember and reuse the original branch names in conflict markers, rather than showing generic labels like "ours" and "theirs". The series is now in its fourth iteration (v4) and has been accepted by Junio Hamano for integration.

The core change is straightforward: when a merge conflict occurs, Git’s ort backend now stores the original conflict labels (the branch names) in a new `.git/MERGE_LABELS` file, and `git checkout -m` reads this file to recreate the same markers the user saw during the initial merge. Junio contributed two follow-up patches to optimize performance by caching per-invocation constants, such as merge settings and the `.git/MERGE_LABELS` file state, in a new `struct checkout_merged_data`. All technical feedback from prior versions—including a correctness bug in how `.git/MERGE_LABELS` was written, portability fixes, and API improvements—has been addressed.

The series is now queued in Junio’s `next` branch, replacing the earlier version, and is on track to graduate to `master` in the current release cycle. There are no remaining technical blockers, though two broader questions remain open but out of scope: whether `git checkout -m` should also remember the original conflict style (e.g., `diff3`), and whether ephemeral merge state like `.git/MERGE_LABELS` should instead use an index extension. Phillip and Junio have kept the series narrowly focused on label preservation, leaving those discussions for future work. The implementation is compatible with existing merge strategies and aligns with Git’s patterns for transient state files.
