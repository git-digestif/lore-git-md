This thread is about a small but user-visible improvement to `git checkout -m`: when recreating conflict markers after a merge conflict has been resolved, Git will now use the original branch names (e.g., "main" vs. "feature") instead of generic labels like "ours" and "theirs". The series, authored by Phillip Wood, has been through three iterations and is now queued for integration in Junio's `next` branch, on track for the upcoming release.

The implementation stores the original conflict labels in a new ephemeral file, `.git/MERGE_LABELS`, and reuses them when `git checkout -m` is invoked. Junio reviewed the series thoroughly, raising concerns about portability, API design, and edge-case handling; all were addressed in the final version. He also contributed a follow-up patch (now part of the series as patch 1.5/2) that optimizes performance by caching per-invocation constants, eliminating redundant config reads and file I/O. Phillip incorporated this patch verbatim, and Junio has now signed off on it.

The only open discussion was whether `git checkout -m` should also remember and restore the original conflict style (e.g., `diff3`), but Phillip kept the scope narrow, and Junio framed the question as a trade-off between convenience and explicit control. No consensus emerged, but the current series does not attempt to address it. The series is functionally complete, with test coverage verifying both label preservation and cleanup of `.git/MERGE_LABELS` after a clean checkout.
