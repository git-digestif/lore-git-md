This thread is about a two-patch series from Phillip Wood that improves `git checkout -m` by making it remember and reuse the original conflict labels (e.g., branch names) from the initial merge, instead of showing generic "base", "ours", and "theirs". The series is currently under review, with no prior versions.

The first patch refactors `remove_branch_state()` to use flags instead of a boolean, preparing the ground for the second patch. The second patch adds plumbing to store the original labels in `.git/MERGE_LABELS` and updates `git checkout -m` to use them. It also includes a test in `t/t7201-co.sh` and handles edge cases like missing or malformed label files, with cleanup via `git commit` and `git sequencer`.

Junio C Hamano reviewed the second patch and raised two key points. First, he asked where `MERGE_HEAD` and `CHERRY_PICK_HEAD` are documented, suggesting `MERGE_LABELS` should be mentioned alongside them for consistency. Second, he flagged a potential portability issue: the patch writes the labels file with LF line endings, but on Windows, stdio might convert these to CRLF, which the reading logic doesn’t account for. This could result in labels with trailing `\r` characters. Junio’s feedback is technical and actionable but not blocking—the patch is likely to proceed after addressing these concerns.

Phillip also left an open question in the cover letter: whether `git checkout -m` should also remember and restore the original conflict style (e.g., `diff3`). No one has responded to this yet. The series is otherwise self-contained and touches the merge machinery, specifically the ort backend. No decisions have been made about merging, and the series remains under active review.
