This thread is about a two-patch series from Phillip Wood that improves `git checkout -m` by making it remember and reuse the original conflict labels (like branch names) instead of generic "base", "ours", and "theirs" when recreating merge conflicts. The series is under review and targets the ort merge backend, introducing a new `.git/MERGE_LABELS` file to store the labels.

Phillip has addressed the two main concerns raised by Junio Hamano in his review of the second patch. First, he clarified that `.git/MERGE_LABELS` is an ephemeral file similar to `MERGE_MSG` or `MERGE_MODE`, not a ref, and deferred broader documentation improvements to a future series. Second, he fixed a portability issue by switching to `strbuf_getline()` to handle CRLF line endings correctly on Windows, eliminating a subtle correctness risk. These changes resolve the immediate feedback and pave the way for a revised version.

The series is now technically sound and ready for a v2 submission. The remaining open questions—whether `git checkout -m` should also preserve the original conflict style (like `diff3`) and the broader architectural discussion about using index extensions instead of `.git/MERGE_LABELS`—are orthogonal to the core implementation and don’t block progress. Johannes Sixt suggested the index extension approach, but Phillip rejected it for this series, citing compatibility with existing patterns. Junio’s follow-up framed this as a trade-off between cleanliness and accessibility, but no concrete examples or prototypes have been provided to evaluate the alternative. For now, the `.git/MERGE_LABELS` approach remains the agreed-upon solution.
