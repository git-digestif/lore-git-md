This thread is about improving `git checkout -m` to remember the original branch names used in conflict markers when recreating conflicts after a merge has been resolved. Phillip Wood sent a two-patch series (now at v2) that teaches Git's ort merge backend to store these labels in `.git/MERGE_LABELS` and reuse them, making the conflict markers consistent with what the user originally saw. The first patch, a refactoring of `remove_branch_state()`, is uncontroversial and ready to merge. The second patch, which implements the label preservation, has addressed all feedback from Junio on documentation and portability and is technically complete.

The only remaining open question is whether `git checkout -m` should also remember and restore the original conflict style (e.g., `diff3`). Phillip has clarified that his proposal would not override user-specified styles—if the user runs `git checkout --conflict=diff3 -m` or sets `merge.conflictStyle`, that style would still take precedence. The preserved style would only apply as a fallback when no style is explicitly requested. Johannes Sixt initially objected to preserving the style, arguing it would limit workflow flexibility, but Phillip's clarification narrows the debate to whether this fallback behavior would be convenient or confusing for users. No other participants have weighed in on this point yet. The series is otherwise ready for integration.
