This thread is about a two-patch series by Phillip Wood that improves `git checkout -m` by making it remember and recreate the original conflict labels (branch names) from the initial merge, rather than using generic labels like "base", "ours", and "theirs". The series is now at version 2, addressing Junio Hamano’s feedback on documentation and line-ending portability.

The first patch refactors `remove_branch_state()` to use flags instead of a boolean, preparing the ground for the second patch. The second patch, just summarized, implements the core functionality: it stores the original conflict labels in a new ephemeral file, `.git/MERGE_LABELS`, and updates `git checkout -m` to use these labels when recreating conflicts. The implementation is robust, handling edge cases like missing or malformed label files by falling back to generic labels, and ensuring cleanup via `git commit` and `git sequencer`. It also addresses cross-platform line-ending issues, making it work consistently on both LF and CRLF systems.

The series is under review and appears ready for integration. The only open question is whether `git checkout -m` should also remember the original conflict style (e.g., `diff3`), which Phillip raised but hasn’t received feedback on. There’s also an unresolved architectural discussion about whether to use an index extension instead of `.git/MERGE_LABELS`, but this isn’t blocking the series. Junio’s feedback has been fully addressed, and the patch is uncontroversial. Key participants include Phillip (the author), Junio (who reviewed and approved the changes), and Johannes Sixt (who suggested the index extension alternative).
