This thread is about a patch series by Phillip Wood that teaches `git checkout -m` to remember and reuse the original branch names shown in conflict markers during a merge, rather than falling back to generic labels like "ours" and "theirs". The series is now in its fourth iteration (v4) and is functionally complete, with all technical feedback from Junio Hamano addressed.

The core change involves storing the original conflict labels in a new `.git/MERGE_LABELS` file and reusing them when `git checkout -m` is invoked. The series also includes a preparatory refactor of `remove_branch_state()` to support preserving this file during cleanup, and a performance optimization from Junio that caches per-invocation constants (like conflict style and `merge.renormalize`) to eliminate redundant config reads and file I/O. The latest email covers this optimization patch, which is uncontroversial and aligns with Git’s existing patterns for caching state.

Junio has accepted the series for integration, and it is now queued in the `next` branch, on track for graduation to `master` in the current cycle. The only open discussions—whether to preserve the original conflict style as a fallback and whether to use an index extension instead of `.git/MERGE_LABELS`—remain unresolved but are explicitly out of scope for this series. Phillip and Junio have both indicated the series is ready for integration, and no further changes are expected.
