This thread is about a two-patch series from Phillip Wood that improves `git checkout -m` by remembering the original branch names used in conflict markers during a merge, rather than defaulting to generic labels like "ours" and "theirs". The series is under review, with no prior versions.

The first patch refactors a function to use flags instead of a boolean, preparing the ground for the second patch, which introduces `.git/MERGE_LABELS` to store the original labels and updates `git checkout -m` to use them. The implementation handles edge cases like missing or malformed label files and ensures cleanup via `git commit` and the sequencer. Junio Hamano reviewed the series and raised two actionable concerns: the need to document `.git/MERGE_LABELS` alongside other special files like `MERGE_HEAD`, and a potential portability issue with line endings on Windows. Johannes Sixt (Hannes) suggested using an index extension instead of a separate file, sparking a discussion about architectural trade-offs—cleanliness versus accessibility—but no consensus has emerged.

Phillip also left an open question about whether `git checkout -m` should remember the original conflict style (e.g., `diff3`) in addition to the labels, inviting feedback on whether this would be helpful or confusing. So far, no one has weighed in on this point. The thread is now waiting on Phillip to address Junio’s feedback and either incorporate or defer Hannes’s suggestion in a future revision.
