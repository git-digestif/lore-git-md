This thread is about a two-patch series by Phillip Wood that improves `git checkout -m` by making it remember and reuse the original branch names in conflict markers, rather than showing generic labels like "base", "ours", and "theirs". The series is now in its third version and is functionally complete, addressing all technical feedback from Junio Hamano.

The first patch refactors `remove_branch_state()` to use a flags field instead of a boolean, preparing the codebase for the new functionality. This patch is uncontroversial and ready to be merged. The second patch adds the core feature: when a merge conflict occurs, Git now stores the original conflict labels in `.git/MERGE_LABELS` and reuses them when `git checkout -m` is run. The implementation is careful to handle edge cases, such as missing or malformed label files, and ensures cleanup by removing the file after use. It also fixes a correctness bug from an earlier version that could write invalid data for clean merges.

The only remaining discussion is whether `git checkout -m` should also remember and restore the original conflict style (e.g., `diff3`). Phillip has clarified that this series does not attempt to address that question, keeping the scope narrow. Junio framed this as a trade-off between convenience and explicit control, noting that users can already specify the style manually if needed. Johannes Sixt raised concerns about workflow flexibility, but no consensus has emerged, and this discussion is not blocking the series. The patch is ready for integration.
