This thread improves `git checkout -m` to remember the original branch names used in conflict markers, so users see consistent labels when re-resolving conflicts. Phillip Wood’s v3 series, which stores these labels in `.git/MERGE_LABELS` and reuses them during `checkout -m`, is now queued for integration in Junio’s `next` branch after addressing all technical feedback, including a correctness bug, portability fixes, and API improvements.

Junio has since posted a follow-up refactoring patch that optimizes the performance of Phillip’s change. The patch avoids repeatedly reading configuration and `.git/MERGE_LABELS` for every conflicted path by caching these values in a new `struct checkout_merged_data` during a single `git checkout -m` invocation. This is a pure refactoring with no user-visible behavior change, and it’s uncontroversial—Junio suggests it could either be squashed into Phillip’s original patch or kept separate.

The series is functionally complete and ready for integration. Two open discussions remain unresolved but don’t block this work: whether `git checkout -m` should also remember the original conflict style (e.g., `diff3`), and whether `.git/MERGE_LABELS` should use an index extension instead of a file. Phillip has kept the scope narrow, focusing only on label preservation, and Junio has accepted this approach. The performance optimization is a natural follow-up and doesn’t introduce new concerns.
