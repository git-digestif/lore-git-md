This thread is about a two-patch series from Phillip Wood that improves `git checkout -m` by making it remember and reuse the original branch names in conflict markers, rather than falling back to generic labels like "ours" and "theirs". The series is under review, with no prior versions.

Phillip’s implementation stores the original conflict labels in a new `.git/MERGE_LABELS` file and updates the ort merge backend to read and apply them. The first patch refactors `remove_branch_state()` to use flags instead of a boolean, preparing the ground for the second patch, which adds the label-preservation logic. Junio C Hamano reviewed the series and raised two actionable concerns: the new `.git/MERGE_LABELS` file should be documented alongside other special files like `MERGE_HEAD`, and the patch’s handling of line endings could cause portability issues on Windows. Johannes Sixt (Hannes) suggested an alternative design—using an index extension instead of a separate file—which Junio acknowledged as an interesting idea but noted it would trade off user accessibility for cleanliness.

The thread is still open on two fronts. First, Phillip asked whether `git checkout -m` should also remember the original conflict style (e.g., `diff3`), not just the labels, but no one has weighed in yet. Second, the discussion about where to store the labels—separate file or index extension—remains unresolved. Junio’s latest reply keeps the door open for either approach, so the next revision may address his feedback or explore the index-extension idea further. For now, the series is still cooking, with no objections to the core goal but some design questions still in play.
