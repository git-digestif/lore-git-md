This is the third patch in Pablo Sabater’s five-patch series adding a `--dry-run` option to `git backfill`. It refactors the `fetch_object_info()` API to return an `enum fetch_object_info_status` instead of dying when the server does not advertise the `object-info` capability, enabling graceful fallback in the upcoming `--dry-run` implementation.

The patch touches seven files, converting the function signature and propagating the new status code through the transport layer. The only behavioral change is that `fetch_object_info()` now returns `FETCH_OBJECT_INFO_NOT_ENABLED` instead of calling `die()`; `git cat-file` immediately converts this status back to a die message, so its behavior is unchanged. The preparatory work is clean and mechanical, with no functional regression. The commit message clearly explains the motivation: the next patch in the series needs to handle missing `object-info` capability without aborting the entire operation.

Key technical details for follow-up discussion: the new `fetch_object_info_status` enum (`OK`, `ERR`, `NOT_ENABLED`), the changed return type of `fetch_object_info()` and `transport_fetch_object_info()`, and the unchanged behavior of `git cat-file`. The patch is well-scoped and appears ready for review.
