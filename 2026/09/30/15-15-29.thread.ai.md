Subject: [PATCH] refs/packed-backend: optimize packed-refs file rewrites
Series version: standalone patch (no series)
Originating author: Karthik Nayak <karthik.188@gmail.com>
Thread type: performance optimization patch

Core problem or goal
Speed up operations that rewrite the packed-refs file (e.g., deleting references) by avoiding redundant formatting of unchanged refs. The current implementation uses `fprintf()` for every entry; the patch tracks raw byte positions of unchanged refs and writes them directly with `fwrite()`.

Current status
Under review. No prior versions. No maintainer decision recorded.

Key technical details
- Files touched: `refs/packed-backend.c` only
- New/renamed symbols: `record_start` field added to `struct packed_ref_iterator`; `write_packed_entry()` now accepts a `raw` parameter
- Behavior change: unchanged refs are written as raw bytes instead of being reformatted, preserving original formatting (case, whitespace, malformed refnames, peeled OIDs for broken refs)
- On-disk format: unchanged (backward-compatible, but tools parsing packed-refs may observe subtle differences in formatting)
- Test coverage: performance benchmark included (deleting 100,000 packed refs, ~20% speedup from 28.7 ms to 23.8 ms)

Open questions and loose ends
1. **Correctness vs. performance tradeoff**: Toon Claes identified four side effects of bypassing `fprintf()` (case sensitivity, whitespace handling, invalid refnames, peeled OIDs for broken refs). None are expected to cause observable issues, but they should be documented in the commit message.
2. **Implementation structure**: Toon proposes splitting `write_packed_entry()` into two functions (formatted vs. raw writes) to avoid mixing concerns. Karthik has not yet responded to this suggestion.
3. **Interoperability**: Subtle formatting changes (e.g., uppercase OIDs, tabs) could affect tools parsing packed-refs files (e.g., JGit, libgit2), though no specific compatibility issues have been raised.

Participant positions

Feedback is narrowly scoped to the packed-refs subsystem and does not oppose the optimization in principle. Review is tested in spirit (code path analysis) but not locally executed.
