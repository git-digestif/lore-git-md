Core problem or goal
Speed up operations that rewrite the packed-refs file (e.g., deleting references) by avoiding redundant formatting of unchanged refs. The current implementation uses `fprintf()` for every entry; the patch tracks raw byte positions of unchanged refs and writes them directly with `fwrite()`, while documenting side effects of preserving original formatting (case, whitespace, malformed refnames, peeled OIDs for broken refs).

Current status
Under review, now with explicit reviewer approval from both Toon Claes and Patrick Steinhardt. v4 addressed Patrick Steinhardt’s feedback on commit message clarity, `record_start` documentation, and wrapper inlining. v5 incorporates the final documentation precision fix: the `record_start` comment now states plainly that it tracks the start of the current record and is updated only when a new record begins, not on every `pos` advancement. Junio C Hamano’s terminology nit ("sanitation" → "sanitization") was adopted in v3. Both Toon Claes and Patrick Steinhardt have now explicitly approved the patch, calling the ~20% speedup (deleting 100,000 packed refs in ~23.8 ms vs. ~28.7 ms) significant. No maintainer decision recorded; patch remains in "under review" state awaiting Junio’s pickup.

Key technical details
- Files touched: `refs/packed-backend.c` only
- New/renamed symbols: `record_start` field in `struct packed_ref_iterator` (documentation revised to state it tracks the start of the current record and is updated only when a new record begins, not on every `pos` movement)
- Behavior change: unchanged refs are written as raw bytes instead of being reformatted, preserving original formatting (case, whitespace, malformed refnames, peeled OIDs for broken refs). Side effects documented in commit message.
- On-disk format: unchanged (backward-compatible, but tools parsing packed-refs may observe subtle formatting differences)
- Test coverage: performance benchmark included (deleting 100,000 packed refs, ~20% speedup from 28.7 ms to 23.8 ms)
