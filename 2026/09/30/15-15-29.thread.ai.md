Subject: [PATCH v3] refs/packed-backend: optimize packed-refs file rewrites
Series version: standalone patch, now v3
Originating author: Karthik Nayak <karthik.188@gmail.com>
Thread type: performance optimization patch

Core problem or goal
Speed up operations that rewrite the packed-refs file (e.g., deleting references) by avoiding redundant formatting of unchanged refs. The current implementation uses `fprintf()` for every entry; the patch tracks raw byte positions of unchanged refs and writes them directly with `fwrite()`, while documenting side effects of preserving original formatting (case, whitespace, malformed refnames, peeled OIDs for broken refs).

Current status
Under review. v3 posted addressing surface-level feedback from Toon Claes on commit message wording. Patrick Steinhardt reviewed the patch, identifying two minor issues (commit message clarity and misleading documentation of `record_start`) but endorsing the 20% speedup as significant. Junio C Hamano noted a minor terminology nit ("sanitation" → "sanitization") in the commit message, a correction he would typically make himself during integration. No maintainer decision recorded; patch remains in "under review" state.

Key technical details
- Files touched: `refs/packed-backend.c` only
- New/renamed symbols: `record_start` field in `struct packed_ref_iterator`; `write_packed_entry_raw(FILE *fh, const char *entry, size_t len)` for raw writes; `write_packed_entry()` retains formatted writes
- Behavior change: unchanged refs are written as raw bytes instead of being reformatted, preserving original formatting (case, whitespace, malformed refnames, peeled OIDs for broken refs). Side effects documented in commit message.
- On-disk format: unchanged (backward-compatible, but tools parsing packed-refs may observe subtle formatting differences)
- Test coverage: performance benchmark included (deleting 100,000 packed refs, ~20% speedup from 28.7 ms to 23.8 ms)

Open questions and loose ends
1. **Commit message clarity**: Patrick Steinhardt notes the commit message does not clearly state the performance problem with the current `fprintf()`-based approach. Junio’s terminology nit ("sanitation" → "sanitization") is a minor refinement of this.
2. **Documentation accuracy**: The `record_start` field in `struct packed_ref_iterator` is documented in a way that suggests `pos` and `record_start` always move together, but Patrick’s reading shows they advance independently. The comment should be corrected.
3. **Wrapper function necessity**: `write_packed_entry_raw()` is a trivial wrapper around `fwrite()`; Patrick questions its necessity but does not demand removal.
4. **Interoperability**: Subtle formatting changes (e.g., uppercase OIDs, tabs) could affect tools parsing packed-refs files (e.g., JGit, libgit2), though no specific compatibility issues have been raised. Documentation in the commit message is intended to mitigate this.
5. **Maintainer pickup**: Junio has not yet queued the patch in `seen` or commented on its technical merits. No timeline for integration.
