This is a feature proposal for `git backfill` that adds a `--dry-run` (or possibly `--info`) option to preview the number and total size of blobs that would be fetched. The thread has reached a conceptual impasse: the author, Pablo Sabater, has accepted all technical feedback and is ready to revise the implementation, but Derrick Stolee, the original author of `git backfill`, remains unconvinced the feature addresses a real user need.

Stolee argues that Git features should be driven by concrete "itches" rather than speculation, and questions whether the uncompressed size estimate (the only size metric available via the `object-info` protocol) would meaningfully inform a user's decision. He suggests that if the feature proceeds, it should use a more explicit argument like `--info=(count|size)` to clarify the trade-off between information depth and network effort. Sabater acknowledges the limitations of the `object-info` protocol and concedes that without evidence of user demand, the feature may not be worth including.

The technical implementation itself is sound and addresses prior feedback about API design, error handling, and control-flow correctness. The upcoming v2 will incorporate all stylistic suggestions (squashing patches, renaming helpers, and replacing a `goto`-based pattern) and resolve a latent correctness issue by introducing a dedicated `ctx->sizes_valid` flag. However, without a clear use case or endorsement from a regular `backfill` user, the feature is unlikely to advance further. The thread is now effectively stalled on the conceptual question of whether the feature belongs in Git at all.
