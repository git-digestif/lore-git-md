This is a small feature patch for `git stash`. Since Git 2.55 (April 2026), `git stash apply` has supported custom labels for conflict markers via `--label-ours`, `--label-theirs`, and `--label-base`, but `git stash pop`—which is just `apply` followed by `drop`—has not. Harald Nordgren extends those same three options to `pop` so users no longer have to manually apply and drop if they want non-default labels.

The implementation is straightforward: the `pop_stash` function in `builtin/stash.c` gains the three label options, passes them through to `do_apply_stash`, and updates the usage string and documentation. Two new tests in `t/t3903-stash.sh` verify that the labels appear in conflict markers and that empty labels are handled correctly. The patch is clean, well-tested, and directly mirrors the existing `apply` behavior.
