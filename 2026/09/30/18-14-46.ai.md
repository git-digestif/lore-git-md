This is a feature proposal for `git backfill` that adds a `--dry-run` option to preview the number and total size of blobs that would be fetched. The thread reveals a fundamental disagreement about the feature's value and design.

Derrick Stolee, the original author of `git backfill`, questions whether the feature addresses a real user need. He argues that Git features should be driven by concrete "itches" rather than speculation, and expresses skepticism that the size estimate (which reports uncompressed blob sizes) would meaningfully inform a user's decision to run `backfill`. Stolee suggests that if the feature proceeds, it should use a more explicit argument like `--info=(count|size)` to clarify the trade-off between information depth and network effort.

The technical implementation itself is not in dispute—it is already well-structured and addresses prior feedback about API design and error handling. The unresolved question is whether the feature belongs in Git at all. Stolee's position carries significant weight given his domain expertise and authorship of the command. The author, Pablo Sabater, has not provided evidence of user demand, which weakens the case for inclusion. The thread is now at a conceptual impasse: without a clear use case or endorsement from a regular `backfill` user, the feature may not advance further.
