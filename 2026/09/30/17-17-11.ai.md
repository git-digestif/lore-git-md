This is a substantive review comment from Junio C Hamano on the final patch (5/5) of Pablo Sabater’s `git backfill --dry-run` series. Junio identifies a latent design flaw in how the code tracks whether blob size information is available: the `ctx->object_info_enabled` flag is overloaded to mean both "the server supports the `object-info` capability" and "the size data we received is valid." He points out that this conflation is unsafe because `transport_fetch_object_info()` can return errors other than `FETCH_OBJECT_INFO_NOT_ENABLED` (e.g., network failures, malformed responses), and in those cases the `results->sizes` array might be partially populated or invalid. To fix this, Junio suggests introducing a dedicated `ctx->sizes_valid` flag that is set only when the size data is known to be complete and trustworthy, decoupling it from the capability-checking logic. The review is narrowly focused on this one control-flow ambiguity, but it is a correctness concern that could lead to incorrect size reporting if left unaddressed. The rest of the patch (output format, fallback behavior, resource cleanup) remains uncontested.
