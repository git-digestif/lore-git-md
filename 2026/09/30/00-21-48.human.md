This is the third patch in Pablo Sabater’s five-part series adding a `--dry-run` option to `git backfill`. It refactors the `fetch_object_info()` API so that it returns a status code (`FETCH_OBJECT_INFO_NOT_ENABLED`, `FETCH_OBJECT_INFO_OK`, or `FETCH_OBJECT_INFO_ERR`) instead of dying when the server lacks the `object-info` capability. This change is necessary for the upcoming `--dry-run` implementation, which needs to gracefully handle servers that cannot report blob sizes.

The patch touches seven files, primarily converting function signatures and propagating the new enum through the transport layer. The only behavioral change is that `fetch_object_info()` no longer dies on missing `object-info`; instead, it returns `FETCH_OBJECT_INFO_NOT_ENABLED`, leaving it to the caller (here, `builtin/cat-file.c`) to decide whether to die or fall back. The commit message is clear and the diff is mechanical, suggesting the patch is well-prepared for review.

This is a refactoring patch with no user-visible impact on its own, but it is a prerequisite for the `--dry-run` feature. The series as a whole looks like a thoughtful addition to `git backfill`, and this patch in particular appears to be a clean, necessary step toward that goal.
