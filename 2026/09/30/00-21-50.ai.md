This is the final patch in Pablo Sabater’s five-part series adding a `--dry-run` option to `git backfill`. It completes the feature by extending the dry-run output to report the total uncompressed size of the missing blobs when the remote server supports the `object-info` capability, falling back to the blob count alone when it does not.

The patch touches `builtin/backfill.c`, `Documentation/git-backfill.adoc`, and `t/t5620-backfill.sh`. In `backfill.c`, it adds logic to detect the `object-info` capability, fetch blob sizes via the transport layer, and accumulate the total size. The output now reads “48 blobs would be fetched (1.20 KiB)” when size information is available, and “48 blobs would be fetched.” otherwise. The documentation is updated to clarify that the reported size is an upper bound (uncompressed, undeltified), and the test suite verifies both object-info and non-object-info scenarios.

The implementation is clean and conservative: it reuses the existing `fetch_object_info()` API (refactored in earlier patches), gracefully handles servers that lack the capability, and frees all allocated resources. The only open question is whether the output format and units (KiB) are optimal for users, but that is a matter of taste rather than correctness. With this patch, the series is now feature-complete and ready for substantive review.
