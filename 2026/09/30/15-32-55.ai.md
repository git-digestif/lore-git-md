This is the fifth and final patch in Jeff King’s xdiff buffer refactoring series, now under light review. The patch adds a defensive NUL-terminator to buffers read by `read_mmfile()`, replacing the previous `xmalloc(sz ? sz : 1)` with `xmallocz(sz)`. The change is purely defensive—no current code path relies on the NUL byte—but it restores a safety guard that was present before patch 3/5 and aligns with Git’s general practice of NUL-terminating ptr/len pairs to guard against off-by-one errors or accidental string-function use.

Patrick Steinhardt’s review is lukewarm but not opposed. He acknowledges the xdiff code’s complexity and the potential value of defensive programming, though he also notes the inconsistency of addressing only this one class of errors. His suggestion to add fuzzing for the xdiff subsystem is a forward-looking idea but not a blocker for this patch. The review is substantive but not deep; it engages with the patch’s motivation and design rather than its implementation details.

The patch itself is trivial—one line in `xdiff-interface.c`—and uncontroversial. It completes the series, which has already fixed a latent memory leak, consolidated redundant types, switched buffer sizes to `size_t`, and addressed a latent error-handling bug in `ll_ext_merge()`. The only remaining procedural question is integration order with the conflicting `jk/merge-ll-tempfile-cleanup` topic, but the author has already offered to rebase if needed. This patch is ready for merging.
