This is the first patch in Phillip Wood’s two-patch series that teaches `git checkout -m` to remember the original conflict labels (e.g., branch names) instead of using generic “ours”/“theirs” when re-creating conflicts. This specific patch is a preparatory refactoring: it converts the `verbose` boolean argument of `remove_branch_state()` into a flags field so the next patch can add a new flag that controls whether the original labels are preserved.

The change is small and mechanical—only three files are touched (`branch.c`, `branch.h`, and `builtin/checkout.c`). The commit message is clear, and the diff is straightforward. There is no behavior change yet; this is purely plumbing for the feature that lands in patch 2. Phillip is a well-known contributor with deep expertise in the sequencer and merge machinery, so the refactoring is likely solid and uncontroversial. If you care about the conflict-label feature, this patch is worth a quick skim to see how the flags are introduced; otherwise, it can safely be skipped—just know that it enables the real work in the next patch.
