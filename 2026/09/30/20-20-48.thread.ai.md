Subject: sparse-checkout regression: checkout clobbers untracked in-cone files
Series version: N/A (standalone bug report and fix)
Originating author: Webstrand
Thread type: bug report and fix

Core problem or goal
A regression in Git v2.27.0 (commit 681c637b4a) causes `git checkout` in a sparse-checkout working tree to silently overwrite untracked files that lie within the sparse-checkout cone when switching branches, instead of aborting with an error. The expected behavior (preserving untracked content and aborting) is violated, and the misleading warning message "paths were already present and thus not updated" incorrectly describes the conflict.

Current status
Under review. A fix has been proposed by Muhammed Dilshad A that modifies `unpack-trees.c` to enforce untracked-file protection in sparse checkouts, ensuring the operation aborts rather than proceeding. The patch also reorders sparsity checks to prevent the misleading warning from masking the actual error. No maintainer decisions or integration status updates have been recorded yet.

- Subsystem: sparse-checkout

- Test coverage: New regression test in `t1092` verifies consistent abort behavior across full checkouts, sparse checkouts, and sparse-index checkouts; existing test in `t1011` adjusted to confirm advisory warnings for sparsity changes while preserving local content
