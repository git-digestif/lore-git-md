This is a CI/build system patch series (v3, two patches) that Junio C Hamano has marked as ready for `next` after reviewing the latest iteration. The series improves GitHub Actions failure reporting by linking leak sanitizer and test failures directly to the relevant test script line, making CI failures more actionable.

The core goal is unchanged: to stop leak sanitizer runs at the first failure (using `--immediate`) and annotate both leaks and regular test failures with the exact file and line in the test script. The v3 iteration addresses all substantive review feedback from v2, including Junio’s three key issues: the `--immediate`/`invert_exit_code` interaction bug (fixed by reordering exit paths in `test_failure_()`), the non-portable `\r` escape in `sed` (replaced with a literal carriage-return byte via `printf`), and the inconsistent output redirection style (reverted to the original form). The series now ensures annotations are written before any `--immediate` exit, regardless of `invert_exit_code`, and uses portable escaping logic.

Key technical details include the new helper functions (`github_escape_message_` and `find_test_case_line_`) in `t/test-lib-github-workflow-markup.sh`, which handle cross-platform escaping and locate the exact line of failing tests using literal string matching. The changes touch `ci/lib.sh`, `t/test-lib-github-workflow-markup.sh`, and `t/test-lib.sh`, introducing no new dependencies or on-disk format changes. The proof-of-concept CI run (linked in the cover letter) demonstrates the feature working in practice, with annotations showing the test filename, line number, and full leak sanitizer output in a collapsible log group.
