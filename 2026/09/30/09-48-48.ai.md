This is the first patch in Phillip Wood's two-patch series improving how `git checkout -m` remembers and restores conflict labels. It is a refactoring patch that converts the `verbose` boolean argument in `remove_branch_state()` to a flags field, preparing the ground for the next patch which will add a new flag to preserve conflict labels.

The change is mechanical: the function signature in `branch.h` and `branch.c` is updated to take an `unsigned flags` parameter instead of an `int verbose`, and the single existing bit (`REMOVE_BRANCH_STATE_VERBOSE`) is defined as a flag. The only caller in `builtin/checkout.c` is updated to use the new flags interface, preserving the existing behavior. No new functionality is introduced yet, and the commit message is clear about the purpose: enabling future extensions.

This is a typical preparatory refactoring, well-scoped and uncontroversial. The patch is small, touches only three files, and does not change any user-visible behavior. Phillip is a seasoned contributor with deep knowledge of the sequencer and merge machinery, so the implementation is likely solid. The only thing to watch in follow-up discussion is whether reviewers see any edge cases in the flags conversion, but so far there are no red flags. The patch is a necessary step toward the actual feature (label preservation) in the next patch.
