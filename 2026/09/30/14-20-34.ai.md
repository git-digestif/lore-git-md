This is the first patch in Tamir Duberstein’s v3 CI/build system series, targeting a specific test-suite performance and stability issue. The patch replaces `test_cmp` with `test_cmp_bin` in `t/t4205-log-pretty-formats.sh` to avoid OOM kills when comparing multi-gigabyte commit-message outputs in GitHub Actions CI.

The change is minimal—one line in a single test script—and is backed by clear benchmark data: `diff -u` on 2 GiB files peaks at 4 GiB RSS and takes 5.3 seconds, while `cmp` uses only 1.2 MiB and finishes in 0.5 seconds. The OOM kill occurred in a private repository where GitHub runners have half the memory of public ones, making this a real-world issue rather than a theoretical edge case.

This patch is settled and ready for integration. It has been endorsed by Jeff King, Junio C Hamano, and Patrick Steinhardt, and the v3 revision does not alter the patch itself—only the cover letter now includes the benchmark table for clarity. No open technical questions remain, and the change introduces no new CLI options, on-disk formats, or test coverage gaps. The only file touched is `t/t4205-log-pretty-formats.sh`, and the test’s behavior is unchanged except for the more efficient comparison mechanism.

The patch is part of a two-patch series, but it stands alone: it addresses a distinct problem (OOM kills in a specific test) and does not depend on the second patch, which focuses on CI parallelism alignment. If the second patch were dropped or revised further, this one would remain valid and mergeable as-is.

No substantive review feedback is expected at this stage, but if any arises, it would likely focus on the choice of `test_cmp_bin` over alternatives (e.g., truncating the output or skipping the test entirely). The current approach is the most conservative, preserving the test’s intent while eliminating the resource exhaustion risk.
