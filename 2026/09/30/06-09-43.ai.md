This is the second patch in Harald Nordgren’s two-part CI/build system series (v3) that improves GitHub Actions failure reporting by annotating test failures and fixed known breakages with their exact file and line number in the test script. The patch introduces two new helper functions—`github_escape_message_` and `find_test_case_line_`—to locate the line where a test is defined and escape its description for GitHub’s annotation format.

The core change replaces the previous generic annotations (which only named the test script) with precise, clickable links pointing to the specific line in the test file where the failure or fixed breakage occurred. The `find_test_case_line_` function uses literal string matching (`grep -F`) to avoid regex misinterpretation of special characters like `[` or `*`, and falls back to line 1 if the description isn’t found verbatim (e.g., when it’s constructed dynamically). The `github_escape_message_` function ensures the test description is properly escaped for GitHub’s annotation format, handling `%` and carriage returns in the correct order to prevent mangling.

This patch directly addresses the usability gap noted in the thread: previously, annotations lacked file/line information, forcing developers to manually search for failures. The implementation is pragmatic, prioritizing correctness (literal string matching) and portability (using `printf` for carriage returns) over complex regex solutions. The commit message clearly explains the escaping logic and fallbacks, and the code is narrowly scoped to the annotation plumbing in `t/test-lib-github-workflow-markup.sh`.
