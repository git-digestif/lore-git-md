This is the fourth patch in Jeff King’s v4 xdiff buffer-size refactoring series, now positioned as patch 4/7 after reordering. It defensively NUL-terminates every `mmfile_t` buffer read by `read_mmfile()` by switching the allocation from `xmalloc()` to `xmallocz()`. The change eliminates a latent off-by-one risk (though no actual bug is known) and removes a one-byte hack that `read_mmfile()` used to handle empty files. The patch touches only `xdiff-interface.c` and is purely mechanical: one line changed, one line removed. Junio has already acked the earlier patches in the series, and this one is uncontroversial. The reordering ensures that the NUL-termination lands before the main refactoring, so no intermediate unsafe state remains.
