This is the third patch in Kristoffer Haugsbakk’s four-part RFC series converting Git’s `BreakingChanges` document into a proper manpage (`gitbreaking-changes(7)`). The series aims to make upcoming breaking changes more discoverable to end users by integrating the document into the standard documentation system, so it appears in `git help` and `man` output.

This patch focuses on usability improvements to the new manpage. It replaces all message-ID references (like `<xmqqa59i45wc.fsf@gitster.g>`) with clickable URLs pointing to the relevant threads on `lore.kernel.org`. Two message-IDs required URL encoding to avoid breaking AsciiDoc parsing. The patch also moves the “how to add new entries” section to the end of the document, as Patrick Steinhardt suggested in review, to improve readability. The commit message explains these changes clearly and notes the motivation for each.

The patch is well-crafted and addresses feedback directly. It touches only documentation files (`Documentation/gitbreaking-changes.txt`, `Documentation/BreakingChanges`) and does not introduce new symbols, CLI options, or on-disk format changes. No tests are added, which is appropriate for a documentation-only change. The author has accepted all review feedback so far, including a minor formatting nit (two spaces after a URL), and the patch looks ready to proceed once the RFC discussion settles.

The broader RFC question—whether to retain the document after Git 3.0 and how to structure it for future major releases—remains open but is not a blocker for this patch. Patrick Steinhardt suggested keeping the manpage and eventually adding a Git 4.0 section, while Kristoffer Haugsbakk proposed adding a historical Git 3.0 section for users on older versions. This is a forward-looking discussion and does not affect the immediate usability improvements in this patch.
