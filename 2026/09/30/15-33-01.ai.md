This is a **substantive review** of the fourth patch in Jeff King’s seven-patch series converting xdiff’s `mmfile_t` buffer sizes from `unsigned long` to `size_t`. The patch itself is a small refactoring in `merge-ll.c` that replaces a hand-rolled file-reading loop in `ll_ext_merge()` with a call to `read_mmfile()`, consolidating error handling and simplifying the code.

Patrick Steinhardt’s review identifies two technical points. First, the patch removes the NUL-termination that `xmallocz()` provided in the original code; this is later restored in the series’ final patch (7/7), but Patrick suggests reordering the patches so the NUL-termination fix comes first, making the intermediate state safer. Second, he notes an unintended behavior change: the new `read_mmfile()` call emits an error message on read failures, whereas the original code silently ignored them. This could be a usability improvement or a regression depending on context, but the commit message does not discuss it, so the change is effectively undocumented. Neither point blocks the patch, but both warrant follow-up: the reordering suggestion is a design consideration for the series as a whole, and the error-message change may need a commit-message update or a small follow-up patch to clarify intent.
