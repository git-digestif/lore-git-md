This is the fourth patch in Pablo Sabater’s five-patch series adding a `--dry-run` option to `git backfill`. The patch implements the core dry-run logic: it walks the object graph, counts missing blobs, and prints the total without fetching anything. The output is a simple line like “After backfill, 48 blobs would be fetched.”

Karthik Nayak’s review is surface-level, focusing on readability and style rather than technical correctness. He suggests using a `bool` for the `dry_run` field (since `OPT__DRY_RUN` is a boolean option), renaming `dry_run_batch()` to `count_batch()` for clarity, and restructuring the control flow to avoid a `goto` in favor of a straightforward `if (dry_run) count() else download()` pattern. These are minor improvements, not blockers, and the patch remains clean and ready for deeper technical review.

The implementation is straightforward: it adds the `--dry-run` flag, introduces a helper to accumulate blob counts, and gates the actual download path behind a context flag. Two new tests verify that the count is accurate and that no fetches occur during dry-run. The preparatory refactorings in earlier patches already converted `fetch_object_info()` to return status codes, so this patch can focus on counting logic without error-handling distractions.

The feature itself is a user-facing improvement for partial clones, giving users a preview of the download cost before committing to the actual backfill. The next patch (5/5) will extend the output to include blob sizes when the server supports the `object-info` capability. No substantive objections have been raised yet, but the author explicitly asks whether the preview capability is valuable to regular `git backfill` users — a question that may draw broader feedback.
