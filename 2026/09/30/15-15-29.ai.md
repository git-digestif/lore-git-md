This patch is a performance optimization targeting the packed-refs backend. It speeds up operations that rewrite the packed-refs file (such as deleting references) by avoiding unnecessary formatting of unchanged refs. Instead of using `fprintf()` for every entry, the patch introduces logic to track the raw byte positions of unchanged refs in the snapshot iterator and write them directly with `fwrite()`.

The change is confined to `refs/packed-backend.c` and modifies the `packed_ref_iterator` struct to record the start of each ref record. The `write_packed_entry()` function is updated to accept raw data (when available) and bypass formatting. Benchmarks show a consistent ~20% improvement when deleting 100,000 packed refs, reducing runtime from ~28.7 ms to ~23.8 ms.

The patch is well-motivated and includes clear performance measurements. The implementation is straightforward: it adds a `record_start` field to the iterator, updates `next_record()` to set it, and modifies `write_packed_entry()` to handle raw writes. The diff is clean and focused, touching only the necessary code paths.

This is part of the packed-refs subsystem, which is actively maintained by Karthik Nayak and Patrick Steinhardt. The optimization is likely to be uncontroversial since it preserves behavior while improving performance. The patch does not introduce new dependencies or platform-specific code, and the risk of regression appears low given the narrow scope.
