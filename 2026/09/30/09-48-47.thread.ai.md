Thread identity
Subject: [PATCH 0/2] checkout -m: remember original conflict labels
Series version: v1 (initial submission)
Originating author: Phillip Wood
Thread type: patch series

Core problem or goal
When `git checkout -m` recreates conflict markers after a merge conflict has been resolved, it currently uses generic labels ("base", "ours", "theirs") instead of the original branch names that were shown during the initial merge. This series teaches Git's ort merge backend to store the original conflict labels in `.git/MERGE_LABELS` and reuse them when `git checkout -m` is invoked, ensuring the labels match what the user originally saw.

Current status
Under review; no prior versions. The series consists of two patches:
1. Refactors `remove_branch_state()` in `branch.c` and `branch.h` to replace its `verbose` boolean argument with an `unsigned flags` field, introducing `REMOVE_BRANCH_STATE_VERBOSE` as the sole flag. This preparatory step has no user-visible behavior change but enables the next patch to add a new flag for preserving conflict labels.
2. Adds plumbing to store and retrieve original conflict labels in the ort backend, updates `git checkout -m` to use the stored labels, and adds a test in `t/t7201-co.sh`. The patch introduces `REMOVE_BRANCH_STATE_PRESERVE_CONFLICT_LABELS` to prevent `remove_branch_state()` from deleting `.git/MERGE_LABELS` during `git checkout -m <branch>`, ensuring labels remain available for subsequent `git checkout -m <path>` calls. The implementation handles edge cases (missing or malformed `.git/MERGE_LABELS`) by falling back to generic labels and ensures cleanup via `git commit` and `git sequencer`.

Key technical details
- Files touched: `branch.h`, `branch.c`, `builtin/checkout.c` (patch 1); `merge-ort.c`, `branch.c`, `builtin/checkout.c`, and related headers (patch 2).
- New on-disk file: `.git/MERGE_LABELS` (stores original conflict labels).
- New behavior: `git checkout -m` now shows the same branch names in conflict markers that were present during the initial merge.
- New symbols: `REMOVE_BRANCH_STATE_VERBOSE` (flag, patch 1), `REMOVE_BRANCH_STATE_PRESERVE_CONFLICT_LABELS` (flag, patch 2), `.git/MERGE_LABELS` (file).
- Test coverage: `t/t7201-co.sh` verifies label preservation.
- No changes to on-disk formats or CLI options beyond `.git/MERGE_LABELS`.
- Edge-case handling: Fallback to generic labels if `.git/MERGE_LABELS` is missing or malformed; cleanup via `git commit` and `git sequencer`.
