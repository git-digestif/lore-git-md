Thread identity
Subject: [PATCH 0/2] checkout -m: remember original conflict labels
Series version: v1 (initial submission)
Originating author: Phillip Wood
Thread type: patch series

Core problem or goal
When `git checkout -m` recreates conflict markers after a merge conflict has been resolved, it currently uses generic labels ("base", "ours", "theirs") instead of the original branch names that were shown during the initial merge. This series teaches Git's ort merge backend to store the original conflict labels in `.git/MERGE_LABELS` and reuse them when `git checkout -m` is invoked, ensuring the labels match what the user originally saw.

Current status
Under review; no prior versions. The series consists of two patches:
1. (Newly summarized) Refactors `remove_branch_state()` in `branch.c` and `branch.h` to replace its `verbose` boolean argument with an `unsigned flags` field, introducing `REMOVE_BRANCH_STATE_VERBOSE` as the sole flag. This is a preparatory step with no user-visible behavior change, enabling the next patch to add a new flag for preserving conflict labels.
2. Adds plumbing to store and retrieve original conflict labels in the ort backend, updates `git checkout -m` to use the stored labels, and adds a test in `t/t7201-co.sh`.

Key technical details
- Files touched: `branch.h`, `branch.c`, `builtin/checkout.c` (patch 1); `merge-ort.c`, `branch.c`, `builtin/checkout.c`, and related headers (patch 2).
- New on-disk file: `.git/MERGE_LABELS` (stores original conflict labels).
- New behavior: `git checkout -m` now shows the same branch names in conflict markers that were present during the initial merge.
- New symbols: `REMOVE_BRANCH_STATE_VERBOSE` (flag), `.git/MERGE_LABELS` (file).
- Test coverage: `t/t7201-co.sh` verifies the label preservation.
- No changes to on-disk formats or CLI options beyond the new `.git/MERGE_LABELS` file.

Open questions and loose ends
Phillip explicitly asks whether `git checkout -m` should also remember and restore the original conflict style (e.g., `diff3`), not just the labels. He is unsure if this would be convenient or confusing and invites feedback.
