This thread is about a performance optimization for Git’s packed-refs file rewrites. Karthik Nayak’s patch (now at v3) speeds up operations like deleting references by avoiding redundant formatting of unchanged refs—writing them directly as raw bytes instead of reformatting each one with `fprintf()`. The change preserves original formatting (case, whitespace, malformed refnames) and delivers a 20% speedup in benchmarks, but it’s still under review.

The patch has drawn feedback from Toon Claes and Patrick Steinhardt. Toon’s early review flagged correctness concerns about bypassing `fprintf()`, which Karthik addressed in v2 by documenting the side effects and splitting the write logic into separate functions. Patrick’s more recent review endorsed the performance gain but noted two minor issues: the commit message could better explain the problem with the current `fprintf()` approach, and a comment about the `record_start` field is misleading. Neither reviewer requested a reroll, suggesting the issues are small enough to fix during integration. Junio C Hamano just chimed in with a surface-level nit on the commit message’s wording (“sanitation” vs. “sanitization”), which he’d likely correct himself if the patch moves forward.

The patch touches only `refs/packed-backend.c` and doesn’t change the on-disk format, though tools parsing packed-refs files might notice subtle formatting differences. No maintainer decision has been made yet, and the patch isn’t queued in Junio’s integration branches. The main open questions are the commit message clarity, the `record_start` documentation, and whether the trivial `write_packed_entry_raw()` wrapper is necessary—all minor points that don’t block progress.
