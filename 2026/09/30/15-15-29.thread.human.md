This thread is about a performance optimization for Git’s packed-refs backend, authored by Karthik Nayak. The patch speeds up operations that rewrite the packed-refs file—like deleting references—by avoiding redundant formatting of unchanged refs. Instead of using `fprintf()` for every entry, it writes unchanged refs directly with `fwrite()`, preserving their original formatting (including case, whitespace, and even malformed refnames). The change is narrow, touching only `refs/packed-backend.c`, and delivers a consistent ~20% speedup in benchmarks (deleting 100,000 refs now takes ~23.8 ms instead of ~28.7 ms).

The patch is now in its second version, addressing feedback from Toon Claes. The key improvement is splitting the write logic into two functions—`write_packed_entry()` for formatted writes and `write_packed_entry_raw()` for raw writes—making the code clearer and explicitly documenting the side effects of bypassing `fprintf()`. Karthik also added a `record_start` field to the `packed_ref_iterator` struct to track ref record positions. The on-disk format remains backward-compatible, though external tools parsing packed-refs files might notice subtle formatting differences.

The main open question is whether these formatting changes could affect tools like JGit or libgit2, though no specific compatibility issues have been raised yet. The patch is under active review, with no unresolved technical concerns, and is ready for further feedback or maintainer consideration. It’s part of the packed-refs subsystem maintained by Karthik and Patrick Steinhardt.
