This thread is about a performance optimization for Git’s packed-refs file rewrites. Karthik Nayak’s patch (now at v5) speeds up operations like deleting references by avoiding redundant formatting of unchanged refs, achieving a ~20% speedup in benchmarks (deleting 100,000 packed refs in ~23.8 ms vs. ~28.7 ms). The change writes unchanged refs as raw bytes instead of reformatting them, preserving original formatting like case and whitespace, with side effects documented in the commit message.

The patch has cleared all reviewer feedback. Toon Claes initially raised correctness concerns about bypassing `fprintf()` and proposed structural improvements, which Karthik addressed in v2 by documenting side effects and splitting the write logic. Patrick Steinhardt later approved the patch after Karthik resolved minor issues in v4 and v5, including commit message clarity and precise documentation of the `record_start` field. Junio C Hamano’s only input was a terminology nit ("sanitation" → "sanitization"), which was adopted in v3. The patch is now effectively complete from a reviewer standpoint but remains under review, awaiting Junio’s pickup. The main open question is whether subtle formatting changes (e.g., uppercase OIDs) might affect tools parsing packed-refs files, though no specific compatibility issues have been raised.
