This thread is about a performance optimization for Git’s packed-refs backend, authored by Karthik Nayak. The patch, now in its third version, speeds up operations that rewrite the packed-refs file (like deleting references) by avoiding redundant formatting of unchanged refs. Instead of using `fprintf()` for every entry, it tracks raw byte positions and writes unchanged refs directly with `fwrite()`, preserving original formatting like case, whitespace, and even malformed refnames.

The patch has been under review since its first iteration, with feedback from Toon Claes and Patrick Steinhardt shaping its evolution. Toon’s early review raised concerns about side effects of bypassing `fprintf()`, which were addressed in v2 by documenting these effects and splitting the write logic into separate functions. Patrick’s recent feedback on v3 focused on two minor but clear issues: the commit message’s lack of a clear problem statement and misleading documentation for the `record_start` field in `struct packed_ref_iterator`. Karthik has agreed to amend the commit message, correct the documentation, and inline the trivial `write_packed_entry_raw()` wrapper. Junio C Hamano also noted a terminology nit ("sanitation" → "sanitization"), which the author has adopted locally.

The patch’s core approach—using `fwrite()` for unchanged refs—is uncontested, and the 20% speedup benchmark (deleting 100,000 packed refs in ~23.8 ms vs. ~28.7 ms before) remains unchallenged. The patch touches only `refs/packed-backend.c` and introduces no on-disk format changes, though tools parsing packed-refs files might observe subtle formatting differences. No maintainer decision has been recorded yet, and the patch is still under review. The next steps involve Karthik sending a new version with the corrected documentation and commit message, but no further structural changes are expected.
