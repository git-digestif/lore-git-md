This thread is about a performance optimization for Git’s packed-refs backend, now in its third version. The patch, authored by Karthik Nayak, speeds up operations that rewrite the packed-refs file (such as deleting references) by avoiding redundant formatting of unchanged refs. Instead of using `fprintf()` for every entry, it tracks raw byte positions and writes them directly with `fwrite()`, resulting in a consistent ~20% performance improvement when deleting 100,000 packed refs. The trade-off is that unchanged refs are written verbatim, preserving original formatting (case, whitespace, malformed refnames, peeled OIDs for broken refs), which is now clearly documented in the commit message.

The patch has undergone thorough review, with Toon Claes providing substantive feedback in earlier versions. His concerns—documenting the side effects of bypassing `fprintf()` and splitting the write logic into separate functions—were addressed in v2, and his final review in v3 was limited to minor commit message wording. Karthik incorporated all feedback, and Toon has explicitly stated he is satisfied with the current version. The patch touches only `refs/packed-backend.c` and introduces a new `write_packed_entry_raw()` function alongside the existing `write_packed_entry()`. It is part of the packed-refs subsystem maintained by Karthik and Patrick Steinhardt, with no dependencies on other in-flight topics.

The main open question is whether the formatting changes (e.g., uppercase OIDs, tabs) could affect tools parsing packed-refs files, such as JGit or libgit2, though no specific compatibility issues have been raised. The commit message now documents these side effects to mitigate potential interoperability concerns. Junio has not yet queued the patch in `seen` or commented on it, so it remains under review with no timeline for integration. The optimization is narrow, well-motivated, and benchmarked, making it a strong candidate for merging once it is picked up.
