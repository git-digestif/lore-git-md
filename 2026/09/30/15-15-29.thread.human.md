This thread is about a performance optimization for Git’s packed-refs backend, authored by Karthik Nayak. The patch speeds up operations that rewrite the packed-refs file (like deleting references) by avoiding redundant `fprintf()` calls for unchanged refs. Instead, it tracks raw byte positions and writes them directly with `fwrite()`, yielding a ~20% speedup in benchmarks (deleting 100,000 packed refs).

Karthik has addressed feedback from Toon Claes, who raised concerns about side effects of bypassing `fprintf()`—such as preserving original formatting (case, whitespace, malformed refnames, and peeled OIDs for broken refs). While these changes aren’t expected to cause issues, they could affect tools parsing packed-refs files (e.g., JGit or libgit2), so Karthik has agreed to document them in the commit message. The patch also adopts Toon’s suggestion to split `write_packed_entry()` into two functions: one for formatted writes (existing behavior) and a new `write_packed_entry_raw()` for raw writes, improving code clarity.

The implementation remains confined to `refs/packed-backend.c`, with no changes to the on-disk format or backward compatibility.
