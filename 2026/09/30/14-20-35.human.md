This is the second patch in Tamir Duberstein’s v3 CI/build system series, now finalized and ready for review. It unifies GitHub Actions and GitLab CI job-count selection by setting `make` and `prove` parallelism to **twice the detected CPU count** on Linux, macOS, and Windows runners.

The patch replaces GitHub’s fixed `-j10` and GitLab’s one-job-per-CPU policy with a single rule: `JOBS=$(($(nproc) * 2))` on Linux, `JOBS=$(($(sysctl -n hw.logicalcpu) * 2))` on macOS, and `JOBS=$(($NUMBER_OF_PROCESSORS * 2))` on Windows. The change is motivated by cross-platform benchmark data showing that `2x CPU count` delivers a 7 % speedup on Linux while avoiding a 26 % slowdown on macOS. The commit message includes a clear table of median build/test-step times across all three platforms, making the trade-offs explicit.

The implementation touches only `ci/lib.sh` (13 insertions, 4 deletions) and uses native CPU-count queries, so it does not depend on GNU coreutils. No new CLI options, on-disk formats, or test coverage changes are introduced. The patch is self-contained and data-driven, addressing Patrick Steinhardt’s earlier request for evidence. The only remaining discussion point is whether the oversubscription policy (2x CPU count) is acceptable; the technical approach itself is settled.
