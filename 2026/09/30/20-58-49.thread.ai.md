Subject: [PATCH] stash: extend `pop` with custom conflict-label options
Series version: single patch, no prior iterations
Originating author: Harald Nordgren
Thread type: patch series

Core problem or goal
Extend `git stash pop` to accept the same `--label-ours`, `--label-theirs`, and `--label-base` options that `git stash apply` already supports, so users can customize conflict markers when popping a stash.

Current status
Under review; no prior summary existed.

Key technical details
- Files touched: `builtin/stash.c` (adds the three options to `pop_stash()` and passes them through to `do_apply_stash()`), `Documentation/git-stash.txt` (updates the man page).
- New CLI options: `--label-ours=<text>`, `--label-theirs=<text>`, `--label-base=<text>` for `git stash pop`.
- Behavior: when a conflict occurs during `pop`, the supplied labels replace the default “ours”/“theirs”/“base” markers in the conflict hunk headers.
- Test coverage: two new tests in `t/t3903-stash.sh` verify that the labels appear in conflict markers and that empty labels are handled correctly.
