This is a CI/build system patch that improves GitHub Actions leak sanitizer failure reporting. Phillip Wood’s review engages with the patch’s design choices and suggests refinements, making it a substantive review.

The patch ensures leak sanitizer failures are annotated with the test script name and full sanitizer output in a collapsible log group, while stopping leak-sanitizer scripts at the first failure using `--immediate`. Phillip’s feedback focuses on two main points: first, he questions whether the annotation format is as useful as it could be, noting that the current output doesn’t link to the test source file and separates test output from leak output. He suggests a more integrated approach where the leak annotation would point directly to the failing test case and display both test and sanitizer output together when expanded. Second, he acknowledges the pragmatic benefit of `--immediate` (avoiding duplicate "not ok" reports) but notes that it hides subsequent leaks if multiple tests in the same script leak differently.

Harald’s implementation is already a clear improvement over the status quo, and Phillip explicitly states he’d be happy to take it as-is if further refinement isn’t feasible. The patch itself is technically sound, with no correctness or portability issues, and has already addressed all substantive feedback from earlier iterations. The discussion here is about polish rather than blocking problems, and the trade-offs (early failure vs. comprehensive reporting) are explicitly acknowledged in the commit message. This is cooking in `next` and looks ready for wider testing.
