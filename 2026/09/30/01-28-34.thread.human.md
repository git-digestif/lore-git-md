This thread is a well-scoped bugfix series from Taylor Blau addressing corner cases in Git’s multi-pack-index (MIDX) and cruft-pack machinery where MIDXs can violate their reachability-closure invariant, breaking bitmap generation. The series is now at v2 (eight patches) after incorporating all substantive feedback from Jeff King, Derrick Stolee, and Junio C Hamano on the initial submission.

The core issue—MIDXs containing objects not closed under reachability—manifests in four scenarios: `--stdin-packs=follow`, incremental repacks, `.keep` packs, and `--write-midx=incremental`. The fixes are narrowly targeted, with each patch addressing a specific scenario or refactoring the codebase to prepare for later fixes. Patch 6/8, the latest addition, is a mechanical refactoring in `repack-midx.c` that makes the MIDX write steps more robust by tracking the preferred pack explicitly, rather than relying on the order of entries in a string list. This change simplifies the code, improves maintainability, and enables future optimizations like sorting the string list for faster membership checks—critical for later patches in the series.

The series has received thorough review from key contributors. Jeff King (Peff) engaged deeply with the algorithmic trade-offs in patch 2/8 (the two-walk approach for handling trees and tags in `--stdin-packs=follow`), ultimately endorsing it as a strict improvement while deferring deeper traversal machinery changes to future work. Derrick Stolee’s feedback on patch 2/8 led to a technical improvement (replacing an `oid_array` with an `oidset` for `extra_roots`), and Junio C Hamano’s maintainer review of patch 1/8 prompted clarifications in the code. The only remaining loose end is the pre-existing edge case involving `--pack-kept-objects` and cruft packs that are themselves kept, which Taylor has deferred to a separate follow-up. The series is now ready for final review, with no open technical objections and strong test coverage across the affected scenarios.
