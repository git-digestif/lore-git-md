This thread is about a four-patch series from Taylor Blau that fixes corner cases in Git’s multi-pack-index (MIDX) and cruft-pack machinery where MIDXs can end up missing objects that should be reachable from their tips. This breaks reachability bitmaps and can cause failures in scenarios like `--stdin-packs=follow`, incremental repacks, and `.keep` packs. The series is under active review, with no prior versions.

The patches touch the `git repack` and `git pack-objects` commands, introducing a new `stdin_packs_context` struct to refactor `--stdin-packs` handling and ensuring trees and tags in included or excluded-open packs are treated as roots for reachability walks. The fixes are narrowly scoped, with each patch addressing one of the three problematic scenarios, and include new tests to verify the behavior. The on-disk format remains unchanged, but the fixes ensure MIDXs stay reachability-closed.

Key reviewers have weighed in. Junio C Hamano, the maintainer, reviewed the first two patches, confirming the refactoring’s correctness and offering a minor stylistic suggestion for readability. Derrick Stolee suggested a technical improvement to replace an `oid_array` with an `oidset` for efficiency. Jeff King (Peff) provided a substantive review of the second patch, endorsing it as a strict improvement but raising nuanced questions about whether a single traversal could replace the current two-walk approach and whether path context ambiguities persist for tags pointing to commits. Peff’s feedback is cautious but supportive, and the patch’s core goal remains uncontested.

The main open question is whether the `extra_roots` mechanism could be simplified or replaced, but this doesn’t block the series. The only actionable technical suggestion so far is Stolee’s `oidset` proposal, which is narrowly scoped. The series is independent of other in-flight work and is still under review, with no merge decisions yet.
