This is the second patch in Harald Nordgren’s two-part CI/build system series (v3), completing the effort to make GitHub Actions test failures actionable by pointing directly to the relevant line in the test script. The patch introduces two new helper functions—`github_escape_message_` and `find_test_case_line_`—to locate the exact line where a test is defined and escape its description for GitHub’s annotation format. The escaping logic is now fully portable (using `printf` to insert a literal carriage return) and the line-finding logic avoids regex edge cases by matching the test description literally. When a test fails or a known breakage is fixed, the CI output now includes a clickable annotation linking to the test script at the correct line, replacing the previous generic message that named the test but provided no location. The patch is narrowly scoped, well-motivated, and directly addresses the usability gap identified in the series’ cover letter. All substantive review feedback from v2 has been incorporated, including Junio C Hamano’s portability and correctness concerns, and the commit message clearly explains the design choices (e.g., literal string matching to avoid regex misinterpretation, escaping order to prevent mangling). The series as a whole appears ready for final review, with no known technical blockers.
