# Thread deltas

## 2026/09/30

- [2026/09/30/15-15-29 by Karthik Nayak <karthik.188@gmail.com>] Karthik Nayak posted a patch modifying `write_with_updates()` in refs/packed-backend.c to write unchanged references verbatim using `fwrite()` instead of `fprintf()` by tracking record positions in the packed-refs snapshot iterator, reporting a consistent ~20% performance improvement (1.21x faster, from 28.7 ms to 23.8 ms) when deleting a ref from 100,000 packed refs.

## 2026/10/01

- [2026/10/01/20-30-24 by Toon Claes <toon@iotcl.com>] Toon Claes noted that "packfile" generally refers only to objects, though the file contains one mention, so he was unsure about the terminology.
- [2026/10/01/20-30-24 by Toon Claes <toon@iotcl.com>] Toon Claes listed sanitizations lost by using `fwrite()`: uppercase OIDs would be copied verbatim instead of being normalized by `oid_to_hex()`; tab separators between OID and refname would be preserved instead of being normalized by `isspace(3)`; refs with invalid names that previously received the zero OID via `oidclr()` would now keep their original OID if `refname_is_safe()` passes (with no observable difference in Git since the zero OID is read into memory anyway); and broken peelable refs (`REF_ISBROKEN`) that previously omitted the peeled OID would now copy the ref and its peeled commit OID verbatim. He suggested some of these side-effects might be worth mentioning in the commit message.
- [2026/10/01/20-30-24 by Toon Claes <toon@iotcl.com>] Toon Claes affirmed the ~20% performance improvement as "Not bad."
- [2026/10/01/20-30-24 by Toon Claes <toon@iotcl.com>] Toon Claes suggested naming the helper function that wraps the `fwrite()` call, noting that an earlier version may have called `fwrite()` directly from `write_with_updates()`.
- [2026/10/01/20-30-24 by Toon Claes <toon@iotcl.com>] Toon Claes objected to having both `fwrite()` and `fprintf()` paths in a single `write_packed_entry()` function, proposing instead to keep `write_packed_entry()` as-is and add a separate function such as `write_packed_entry_preformatted()` or `write_packed_entry_from_iter()`.
- [2026/10/01/20-30-24 by Toon Claes <toon@iotcl.com>] Toon Claes noted that while `fwrite_or_die()` swaps `len` and `1` and compares the return against `len` to handle zero-length writes, that cannot happen here so no change is needed.
- [2026/10/01/20-30-24 by Toon Claes <toon@iotcl.com>] Toon Claes found the single `if()` statement combining the `fwrite()` and `fprintf()` branches ugly.
- [2026/10/01/20-30-24 by Toon Claes <toon@iotcl.com>] Toon Claes appreciated that because `packed_iter->pos` points at the next record, the computed `len` includes the peeled OID line as well, allowing it to be written in one `fwrite()` call, calling it a nice win.
