This is the first patch in a two-part CI/build system series (v3) that improves GitHub Actions failure reporting for leak sanitizer jobs. The patch stops leak-sanitizer test scripts at the first failure (using `--immediate`) and adds GitHub Actions annotations that link each leak to its test script with the full sanitizer output in a collapsible log group.

The motivation is clear: currently, leak failures are buried at the end of test runs, producing only a generic "Process completed with exit code 1" message. This patch ensures leaks are immediately visible and actionable by annotating them with the script name and full sanitizer report. The `--immediate` flag prevents later tests from falsely reporting "not ok" due to leftover sanitizer logs, while the annotation logic is moved earlier in `test_failure_()` to ensure it runs even with `--immediate`.

The changes are narrowly scoped to `ci/lib.sh` (adding `--immediate` to `GIT_TEST_OPTS`), `t/test-lib-github-workflow-markup.sh` (new functions `github_annotation_` and `finalize_test_leak_output`), and `t/test-lib.sh` (reordering annotation logic). The patch is well-motivated and addresses all substantive feedback from v2, including Junio C Hamano’s concerns about `--immediate`/`invert_exit_code` interactions. The only remaining discussion point is the principled trade-off for `--immediate`, which the commit message now explains pragmatically.

This looks like a clean, ready-to-merge improvement that directly enhances CI usability without introducing new dependencies or on-disk changes. The proof-of-concept CI run (linked in the cover letter) demonstrates the feature working as intended.
