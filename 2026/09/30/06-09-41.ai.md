This is a CI/build system patch series (v3 of 2 patches) that improves GitHub Actions failure reporting by linking leak sanitizer and test failures directly to the relevant test script line. The series is now under active review and addresses all three issues Junio C Hamano raised in v2: the `--immediate`/`invert_exit_code` interaction bug (fixed by reordering exit paths), the non-portable `\r` escape in `sed` (replaced with a literal carriage-return byte via `printf`), and the inconsistent output redirection style (reverted to the original form).

The core goal remains unchanged: to make CI failures actionable by annotating them with the exact file and line in the test script, and to stop leak-sanitizer runs at the first failure to avoid false "not ok" reports. The v3 changes are surgical and focused on correctness and portability. The first patch ensures leak annotations are written before any `--immediate` exit, regardless of `invert_exit_code`, while the second patch makes the escaping logic portable across `sed` implementations and restores the original output redirection style.

Key technical details include the new `github_escape_message_` helper (now using `printf` for cross-platform carriage-return handling), the `find_test_case_line_` function (which uses literal string matching to avoid regex edge cases), and the unconditional `finalize_test_case_output` call in `test_failure_()`. The series touches `ci/lib.sh`, `t/test-lib-github-workflow-markup.sh`, and `t/test-lib.sh`, introducing no new dependencies or on-disk format changes. The proof-of-concept CI run (linked in the cover letter) demonstrates the feature working in practice, with annotations now showing the test filename, line number, and full leak sanitizer output in a collapsible log group.

Harald Nordgren has addressed all substantive review feedback from v2, including Phillip Wood’s concerns about output truncation and Firefox scrolling (resolved by removing the giant unfolded annotation) and Junio’s portability and correctness issues. The remaining discussion points—such as the principled trade-off for `--immediate` and the justification for helper function ordering—are now largely stylistic rather than technical. The series appears ready for final review, with no known correctness or portability blockers. The changes are well-motivated, narrowly scoped, and directly improve the developer experience for CI debugging.
