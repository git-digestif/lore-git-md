This is a small but user-facing feature patch. It adds `@{p}` as a shorthand for `@{push}`, mirroring the existing `@{u}` shorthand for `@{upstream}`.

The patch is straightforward: it updates the revision parser in `object-name.c` to recognize `@{p}` alongside `@{push}`, adjusts the documentation to mention the new shorthand, and adds a test case in `t/t1514-rev-parse-push.sh` to verify that `@{p}` resolves to the same branch as `@{push}`. The test also checks that the shorthand works case-insensitively (`@{P}`), which is consistent with Git's existing behavior for other revision suffixes.

The motivation is clear and practical: users who are accustomed to `@{u}` for upstream naturally expect `@{p}` to work for push destinations, and currently it fails with "unknown revision". The change aligns the two shorthands, making the interface more consistent and intuitive.

The implementation is minimal and focused, touching only the necessary files. The test coverage is adequate for the change, and the commit message explains the rationale well. This looks like a well-crafted, uncontroversial improvement that addresses a real usability gap.
