This is the third patch in Jeff King’s seven-patch series converting `mmfile_t` buffer sizes in the xdiff subsystem from `unsigned long` to `size_t`. The patch itself is a straightforward type change: it updates the `size` field in the `mmfile_t` struct from `long` to `size_t` and adjusts the `printf` format in `emit_binary_diff_body()` to use `PRIuMAX` with an explicit cast to `uintmax_t` for correct printing.

The commit message explains the motivation clearly: `size_t` is the more natural type for buffer sizes, and using `long` creates potential integer overflow risks, particularly on LLP64 systems like Windows where `long` is 32-bit but `size_t` is 64-bit. While the practical impact on LP64 systems (like Linux) is minimal, the change eliminates a latent source of bugs and aligns the code with safer type practices. The message also notes that the existing `MAX_XDIFF_SIZE` check (which is unsigned) provides some protection, but the conversion to `size_t` is still a worthwhile defensive measure.

This patch is uncontroversial and has already been acked by Junio Hamano. It is part of a larger refactoring effort that includes defensive NUL-termination of buffers, consolidation of redundant types, and a fix for a latent error-handling bug in `ll_ext_merge()`. The series is procedurally ready for merging, with only minor textual conflicts remaining (e.g., with `jk/merge-ll-tempfile-cleanup`). If you’re tracking the xdiff subsystem or integer-overflow risks, this patch is worth noting for its type-safety improvements.
