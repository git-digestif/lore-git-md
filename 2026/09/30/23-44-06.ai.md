This is the second patch in Jeff King’s v4 series converting the xdiff subsystem’s buffer sizes from `unsigned long` to `size_t`. This specific patch consolidates the redundant `mmbuffer_t` type into `mmfile_t`, eliminating a long-standing duplication that dates back to Git’s initial xdiff import in 2006.

The change is purely mechanical: both types were already identical (`ptr`/`size` pairs), but `mmfile_t` was used for input buffers and `mmbuffer_t` for output. By dropping `mmbuffer_t`, the patch simplifies the codebase and makes it easier to reuse helpers like `read_mmfile()` for both input and output. Sixteen files are touched, mostly type declarations and variable definitions; no behavior changes are intended. The commit message explains the rationale and acknowledges that the name `mmfile_t` is not ideal but defers a more descriptive rename to a future effort.

Junio has already acked this patch, and Patrick Steinhardt’s review raised only a non-blocking naming concern. The patch is uncontested and procedurally ready for merging as part of the larger series.
