This is a feature patch series introducing a `--dry-run` option to `git backfill`. The series is marked RFC, reflecting the author’s uncertainty about whether the feature is actually useful and whether the output format is appropriate.

The five-patch series starts with three preparatory refactorings: updating an outdated comment in the transport layer, introducing an enum for `fetch_object_info()` status codes, and changing that function to return a status instead of dying when the server does not support the object-info capability. The last two patches implement the new option: patch 4 adds the basic `--dry-run` flag that reports how many blobs would be fetched, and patch 5 extends it to also report the total uncompressed size of those blobs when the server advertises the object-info capability.

The author explicitly invites feedback on both the usefulness of the feature and the output format, noting that they do not use `git backfill` themselves. The implementation looks clean and the commit messages are clear, but the RFC status and the author’s self-described unfamiliarity with the command suggest this is still exploratory. If the feature resonates with actual `git backfill` users, it could be a nice usability improvement.
