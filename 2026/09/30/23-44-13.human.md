This is the fourth patch in Jeff King’s seven-patch series converting `mmfile_t` buffer sizes from `unsigned long` to `size_t` in the xdiff subsystem. It adds defensive NUL-termination to all buffers read by `read_mmfile()` by switching the allocation from `xmalloc()` to `xmallocz()`, which allocates one extra byte and zeroes it. The change is motivated by defensive programming: while no current code path exploits the NUL byte, it guards against future off-by-one errors or accidental use of string functions. The patch also removes a hack that allocated a single byte for empty files, since `xmallocz(0)` now reliably returns a valid pointer. This patch was moved earlier in the series (now fourth instead of fifth) to eliminate an intermediate unsafe state where `mmfile_t` buffers lacked NUL-termination. It touches only `xdiff-interface.c` and is uncontested in review.
