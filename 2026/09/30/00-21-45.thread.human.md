This thread introduces a `--dry-run` option for `git backfill`, letting users preview how many blobs and their total uncompressed size would be fetched before committing to the actual operation. Pablo Sabater’s initial v1 series is under review, with a v2 planned to incorporate feedback.

The feature itself—estimating download cost—has drawn no technical objections, but Junio C Hamano recently spotted a subtle correctness issue in the final patch: the code currently uses a single flag (`object_info_enabled`) to track both whether the server supports the `object-info` capability *and* whether the returned size data is valid. This conflation is unsafe, as network errors or malformed responses could leave the size array partially populated while still setting the flag. Junio’s fix—adding a separate `sizes_valid` flag—will ensure the preview only reports sizes when they’re known to be complete and trustworthy. Pablo is likely to adopt this change in v2.

Other feedback has been stylistic: Karthik Nayak suggested squashing an enum-addition patch into the API-conversion patch, switching a field from `int` to `bool`, renaming a helper function, and simplifying control flow—all of which Pablo accepted. Junio also proposed renaming an enum value for clarity, which will probably be included. The output format (“After backfill, N blobs would be fetched (M KiB).”) and units (KiB) remain unchallenged, though Pablo is still seeking input on whether the feature is useful to regular `git backfill` users. Test coverage is in place for basic scenarios, but edge cases (e.g., zero blobs) may need attention.

No substantive technical reviews have landed yet, leaving the core implementation—including the preparatory refactorings—open for deeper scrutiny. Derrick Stolee, the original `backfill` author, was CC’d but hasn’t weighed in. The series is feature-complete and ready for integration once the flag issue is resolved.
