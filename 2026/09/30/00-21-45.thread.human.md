This thread introduces a `--dry-run` option for `git backfill`, letting users preview how many blobs (and their total uncompressed size) would be fetched before committing to the actual operation. Pablo Sabater’s five-patch series is now complete and under review, with no prior versions.

The preparatory refactorings—converting `fetch_object_info()` from a die-on-failure API to one that returns status codes—have drawn only surface-level feedback from Karthik Nayak, who suggested squashing one patch for tighter organization. The dry-run logic itself (patches 4 and 5) has now received its first review, also from Karthik: three minor style tweaks (use `bool` for the dry-run flag, rename a helper function, and simplify control flow) that don’t affect functionality. No substantive technical objections have been raised yet, so the feature remains feature-complete and ready for deeper scrutiny.

The output format—“After backfill, N blobs would be fetched (M KiB).” when size information is available—is still open for comment, as is the overall usefulness of the preview capability. Derrick Stolee, the original `backfill` author, has been CC’d but hasn’t weighed in.
