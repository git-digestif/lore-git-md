This thread is about Pablo Sabater’s patch series adding a `--dry-run` option to `git backfill`, which would estimate the number and total uncompressed size of blobs to be fetched before performing the actual operation. The series is now at its first revision, with a v2 planned after incorporating feedback.

The key technical change in v2 will be a fix for a correctness issue Junio C Hamano identified: the `ctx->object_info_enabled` flag was overloaded to track both whether the server supports the `object-info` capability and whether the size data returned is valid. Pablo has agreed to rename this flag to `ctx->sizes_valid` and adjust the control flow so it’s only set when the data is known to be complete and trustworthy. This resolves the ambiguity and should allow the series to move forward to substantive technical review.

The series has also seen stylistic refinements—squashing two patches, renaming a helper function, and improving a `die()` message—but the main blocker was the control-flow issue. Derrick Stolee, the original author of `git backfill`, has questioned the feature’s conceptual value, arguing that the uncompressed size estimate may not meaningfully inform users and that Git features should address concrete needs. His objection remains unresolved, and without broader support or evidence of user demand, the feature’s future is uncertain. The next revision will focus on the correctness fix, leaving the conceptual debate for later discussion.
