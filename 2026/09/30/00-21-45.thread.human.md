This thread introduces a `--dry-run` option for `git backfill`, letting users preview how many blobs (and, in the next patch, their total size) would be fetched before committing to the actual operation. Pablo Sabater’s five-patch series is under initial review: the first three patches refactor the transport layer to return status codes instead of dying, and the fourth—just summarized—adds the core counting logic. The implementation is clean, with new tests covering the basic count and no-fetch behavior, and the output is a simple line like “After backfill, 48 blobs would be fetched.”

No reviews have landed yet, so the main open questions remain: whether the feature is useful enough to regular `backfill` users, and whether the output format (blob count only in this patch, size estimate in the next) is clear and actionable. The preparatory refactorings appear uncontroversial, and the dry-run logic itself is straightforward, so the series seems ready for technical feedback. Derrick Stolee, the original `backfill` author, has been CC’d but hasn’t weighed in yet.
