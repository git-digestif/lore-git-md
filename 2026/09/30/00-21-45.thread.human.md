This thread introduces a `--dry-run` option for `git backfill`, letting users preview how many blobs—and, when supported by the server, their total uncompressed size—would be fetched before committing to the actual operation. Pablo Sabater’s five-patch series is now complete: the first three patches refactored `fetch_object_info()` to return status codes instead of dying, while the last two implement the dry-run logic and size reporting. The feature is under review, with no prior versions or acks yet.

The implementation touches `builtin/backfill.c`, transport code, and documentation, adding a new `--dry-run` flag and output like “48 blobs would be fetched (1.20 KiB)” when the server supports the `object-info` capability. The series is clean, conservative, and ready for technical scrutiny, though Pablo has explicitly asked whether the feature’s usefulness and output format (units, wording) meet user needs. Derrick Stolee, the original `backfill` author, was CC’d but hasn’t weighed in yet. No objections or requests for changes have surfaced so far.
