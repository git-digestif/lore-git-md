This thread introduces a `--dry-run` option for `git backfill`, allowing users to preview the number and total uncompressed size of blobs that would be fetched before committing to the actual operation. The feature is technically sound after two rounds of review: Pablo Sabater incorporated feedback from Karthik Nayak and Junio C Hamano, squashing patches, improving control flow, and clarifying error messages. However, the feature's value is now in question. Derrick Stolee, the original author of `git backfill`, argues that the uncompressed size estimate may not meaningfully inform a user's decision and that Git features should address concrete user needs. Pablo acknowledges these concerns and suggests the feature might not be worth merging without evidence of demand, effectively stalling the thread until someone steps forward with a use case. No further technical work is planned until this conceptual impasse is resolved.
