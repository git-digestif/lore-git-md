This is a feature addition to `git backfill`, introducing a `--dry-run` option that estimates the number and total size of blobs that would be fetched. The series is structured as five patches: three preparatory refactorings to the `fetch_object_info()` API, followed by the core feature implementation in two steps.

The motivation is straightforward: users may want to know how much data a `git backfill` operation will download before committing to it. The dry-run output reports the count of missing blobs and, if the remote server supports the `object-info` capability, their total uncompressed size (noting that this is an upper bound due to compression and deltification). The preparatory patches modernize the `fetch_object_info()` API to return status codes instead of dying, which allows `git backfill` to handle servers that lack `object-info` gracefully.

The series touches the transport layer (`transport-internal.h`, `transport.c`), the `fetch-object-info` module, and the `backfill` builtin. It also adds tests in `t/t5620-backfill.sh`. The author explicitly invites feedback on both the usefulness of the feature and the output format, acknowledging they are not a regular `git backfill` user. Derrick Stolee is CC’d, likely due to his prior work on the `backfill` command.

Key technical details for follow-up discussion: the new `--dry-run` option, the `fetch_object_info_status` enum, the `fetch_object_info()` function’s changed signature, and the test coverage for both object-info and non-object-info servers. The output format ("48 blobs would be fetched (1.20 KiB)") and the upper-bound nature of the size estimate are also likely points of refinement.
