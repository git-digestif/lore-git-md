This is a **substantive review** of the second patch in Taylor Blau’s four-patch series fixing MIDX reachability-closure corner cases. Derrick Stolee raises a technical concern about the data structure choice in the patch: the new `extra_roots` field in `stdin_packs_context` is currently implemented as an `oid_array`, but Stolee argues it should be an `oidset` instead. His rationale is that `oidset` avoids duplicate objects (which are irrelevant for reachability checks) and better expresses the intent—this is purely a set membership problem, not an ordered collection. The review is narrowly focused on this implementation detail, but it’s a meaningful one: using `oidset` would make the code more robust and self-documenting. No other issues are raised, and the rest of the patch’s logic (walking trees/tags as roots, preserving path prefixes) remains uncontested. The author will likely address this in a follow-up revision.
