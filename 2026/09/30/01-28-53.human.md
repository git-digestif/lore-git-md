This is the third patch in Taylor Blau’s four-patch series fixing MIDX reachability-closure corner cases. It targets a specific scenario: **incremental repacks** that write new packs without copying objects from existing cruft packs.

The bug surfaces when a commit or tree in a new pack points to objects still stranded in a cruft pack. If `repack.midxMustContainCruft` is `false`, the MIDX written after the repack may omit that cruft pack, breaking reachability bitmaps. The fix is simple: force `midx_must_contain_cruft = 1` during incremental repacks, ensuring cruft packs are included in the MIDX. The patch adds a six-line comment explaining the rationale and a new test in `t7704-repack-cruft.sh` that verifies the fix by running an incremental repack with `--write-midx --write-bitmap-index` and confirming `git rev-list --test-bitmap` succeeds.

The change is narrowly scoped and well-motivated. The commit message traces the regression back to its origin (5ee86c273bf, June 2025) and explains why geometric repacks (which *do* copy once-cruft objects) avoid the issue, while incremental repacks do not. The test coverage is minimal but sufficient: it exercises the exact scenario described in the commit message. This looks like a clean, uncontroversial fix that plugs a real hole in the MIDX logic.
