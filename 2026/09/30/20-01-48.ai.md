This is a minor follow-up in the `git backfill --dry-run` series. Junio C Hamano suggests renaming the enum value `FETCH_OBJECT_INFO_NOT_ENABLED` to `FETCH_OBJECT_INFO_UNAVAILABLE` for semantic precision. The current wording ("not enabled") could misleadingly imply the server *could* enable the `object-info` capability but chose not to, whereas "unavailable" neutrally covers both unsupported servers and servers that decline to provide the information. Pablo Sabater has already accepted the idea in principle and will apply the change in the upcoming v2, updating both the enum value and the corresponding `die()` message in `git cat-file`. The change is purely cosmetic—no logic is altered—but removes an unintended implication.
