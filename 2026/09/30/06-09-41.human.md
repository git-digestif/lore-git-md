This is a CI/build system patch that refines GitHub Actions failure reporting for Git’s test suite. The v3 iteration of Harald Nordgren’s two-patch series directly addresses the three technical issues Junio C Hamano flagged in v2: the `--immediate` exit path now reliably emits annotations even when `invert_exit_code` is set, the escaping logic no longer relies on non-portable `\r` in `sed`, and the output redirection style is restored to the surrounding script’s pattern.

The series keeps its original split: the first patch stops leak-sanitizer scripts at the first failure (using `--immediate`) and wraps the full sanitizer output in a collapsible GitHub Actions log group, while the second patch ensures regular test failures and fixed known breakages are annotated with the exact file and line number. Both patches now include clear, focused commit messages that explain the trade-offs—early failure versus comprehensive reporting, literal string matching versus regex—and the reasoning behind each helper function.

The proof-of-concept CI run (linked in the cover letter) shows the feature working as intended: annotations now point directly to the failing test line, and the full leak output is preserved in a foldable section. The changes are confined to CI plumbing (`ci/lib.sh`, `t/test-lib-github-workflow-markup.sh`, and `t/test-lib.sh`) and introduce no on-disk format or user-visible behavior changes. This is a well-scoped, well-motivated improvement that should make CI failures easier to debug without disrupting existing workflows.
