This is a maintainer update on the Git 3.0 release timeline, responding to Johannes Schindelin’s request for a concrete plan. Junio C Hamano outlines a provisional schedule and process for transitioning from Git 2.x to 3.0, filling in details left open at the Contributor’s Summit.

The plan calls for Git 2.98 to ship by the end of 2026, followed by 2.99 in March 2027. The 2.99 release will serve as a "signal" that Git 3.0 is coming, with a shorter-than-usual lead time (about a month) before 3.0’s release in April 2027. During this month, only bugfixes will be applied to 2.99, resulting in 2.99.1, which will be functionally identical to 3.0 except that breaking changes will be disabled in 2.99.1 and enabled in 3.0. This approach allows LTS distributions to continue using 2.99.X indefinitely while still benefiting from bugfixes.

Junio also proposes retaining the `WITH_BREAKING_CHANGES` Makefile knob in the 3.0 release to minimize differences between 2.99.1 and 3.0, deferring the removal of "dead code" (used when breaking changes are disabled) to a later 3.X release. This reflects his preference for a clean, minimal divergence between the two versions. The plan is shaped by the Contributor’s Summit consensus but includes Junio’s own preferences where details were not firmly decided.

The proposal is pragmatic and addresses downstream coordination needs while preserving flexibility for last-minute adjustments. It does not resolve open questions about specific breaking changes (e.g., Rust support, SHA-256 interoperability) but provides a clear framework for how those changes will be introduced. The tone is matter-of-fact, and the plan looks well-considered and actionable.
