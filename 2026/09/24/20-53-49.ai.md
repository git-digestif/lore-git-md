This is a CI/build system patch that implements the version-range-aware runtime workaround for the Debian 12 HTTP/2 authentication flakiness, now favored by the thread participants.

The patch replaces the original CI-only hard-coded skip with a new test prerequisite `HAVE_CURL_HTTP2_BUG` that detects curl versions between 7.88.0 and 8.3.0 (exclusive) and skips the affected `t5559.15` and `t5559.16` tests when the buggy version is present. The implementation is minimal: it checks the curl version via `build_option` and `awk`, and marks the two half-auth clone tests with `!HAVE_CURL_HTTP2_BUG`. The change is confined to `t/t5551-http-fetch-smart.sh` and does not touch production code or on-disk formats.

The commit message now correctly identifies curl 7.88.0 (not 7.88.1) as the version where the bug was introduced, reflecting the discussion in the thread. It also clarifies that this is a CI-only workaround for a flaky test, not a regression in production behavior, so it doesn’t require fast-tracking into the release. The patch is part of a single-patch series (PR #2236) and is ready for integration, with the version range and implementation choice now settled by the maintainer and author.

This version addresses the limitations of the original patch (CI-only, hard-coded test numbers) while avoiding the complexity of a full curl upgrade. The trade-off—skipping tests on potentially unaffected versions—is documented in the commit message, and the version range is explicitly bounded to minimize false positives. The patch is well-motivated, with clear references to the upstream curl fix and the specific tests involved.
