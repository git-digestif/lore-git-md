This is the second patch in Patrick Steinhardt’s 7-patch Meson build improvement series. It targets a minor inefficiency in the Meson build process where `git-remote-http` and its aliases (`git-remote-https`, `git-remote-ftp`, `git-remote-ftps`) were being recompiled from source for each executable, rather than reusing the already-compiled objects. The patch modifies `meson.build` to build `git-remote-http` once and then reuse its object files for the aliases, reducing redundant compilation.

The change is straightforward: it introduces a variable (`git_remote_http`) to hold the compiled executable and then uses its extracted objects for the aliases, replacing the previous approach of recompiling `remote-curl.c` for each alias. The performance improvement is modest (about 1% speedup in clean build times), but the patch aligns the Meson build with the existing pattern used for `git-receive-pack` and similar executables, improving consistency. The author also considered an alternative approach (hardlinking the executables) but found it offered negligible performance gains and was less native to Meson.

The patch touches only `meson.build` and is a low-risk refactoring with no functional changes to Git’s behavior. It complements the first patch in the series, which introduced a static library (`libgit-curl.a`) to avoid redundant compilation of HTTP sources. The series as a whole focuses on build optimization and CI reliability, with this patch contributing to the former. No objections or open questions are evident from the commit message.
