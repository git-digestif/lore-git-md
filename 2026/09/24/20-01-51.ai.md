This is the second patch in Johannes Schindelin’s v2 CI/build system series fixing GitLab CI breakage for Windows builds after Rust support was enabled. It addresses a silent data loss issue in the dependency setup script where `.git/info/exclude` was being truncated, discarding exclusions added by `install-sdk.ps1` (notably `/git-sdk`).

The patch modifies `ci/install-dependencies.ps1` to check for the existence of `.git/info/exclude` before creating it, preserving any existing contents. This is a targeted fix for a specific CI workflow interaction—no changes to Git’s core behavior or user-facing features. The change is minimal (3 lines added, 1 removed) and well-motivated: the commit message clearly explains the problem (truncation during `New-Item -Force`), the impact (CI failures due to unignored SDK files), and the solution (conditional file creation).

The patch is part of a larger effort to stabilize GitLab’s Windows CI after Rust toolchain integration, but this specific change is narrowly scoped to the `.git/info/exclude` preservation issue. It has no dependencies on other patches in the series and could theoretically land independently, though it’s most meaningful in the context of the full CI restoration effort. No substantive review feedback has been raised against this patch in either v1 or v2, suggesting it’s uncontroversial.
