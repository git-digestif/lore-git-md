This is the fourth patch in Patrick Steinhardt’s seven-part refactoring series to simplify the `create_repository()` interface. The goal here is to move the handling of `core.sharedRepository` from `builtin/init-db.c` into `setup.c`, eliminating another piece of the awkward in-out parameter pattern that the series aims to remove.

The change is small—just three lines removed from `init-db.c` and three added to `setup.c`—but it’s a deliberate step toward making the input `struct repository` stateless. The commit message explains that `git init` currently juggles two scopes for `core.sharedRepository`: one for creating the repository directory, and another for overriding the new repository’s configuration. By moving the setting into `create_repository()`, the caller no longer needs to pre-configure the repository, which aligns with the series’ broader goal of enforcing statelessness.

The patch notes that `git clone` already passes `-1` for this parameter and doesn’t modify the repository, so there’s no behavior change there. The diff itself is straightforward, and the commit message is clear about the motivation and scope. This looks like a well-crafted, incremental step in the refactoring effort, with no obvious red flags. The series as a whole is shaping up as a clean, mechanical cleanup that should reduce confusion in the repository setup code.
