This is a documentation patch in the ongoing effort to modernize cross-references in Git's man pages. Junio C Hamano responds to Julia Evans' proposed revision of the commit message for her patch, which replaces informal plain-text references (e.g., "see EXAMPLES below") with formal AsciiDoc cross-references (`<<target,text>>`). The patch is already approved and queued in `next`, but Junio requests a minor clarification in the commit message to ensure the rationale for using the two-part link form is unambiguous.

Junio rephrases Julia's explanation to confirm his understanding: the short form `<<EXAMPLES>>` uses the same text for both the link target and the clickable text, which can lead to inconsistent rendering (e.g., `"EXAMPLES"` or `[EXAMPLES]` in HTML). The two-part form (`<<EXAMPLES,"EXAMPLES">>` or `<<EXAMPLES,[EXAMPLES]>>`) ensures consistent output across all contexts. He suggests this wording to make the trade-off clearer, though he emphasizes it is not an attempt to improve the message—just to verify alignment. The patch itself remains unchanged; only the commit message will be adjusted.

The broader discussion about the trade-off between link stability (manual anchors preserving existing fragment identifiers) and readability (auto-generated anchors following AsciiDoc conventions) is still open, but this email does not revisit it.
