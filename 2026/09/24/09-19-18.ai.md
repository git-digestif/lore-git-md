This is a refactoring series targeting the repository setup subsystem, specifically the `create_repository()` function. The goal is to simplify its interface by ensuring the input `struct repository` is stateless—currently, it’s used as an in/out parameter, which Patrick argues is confusing and error-prone. The series removes the last remaining in/out usage (propagating `core.sharedRepository`) and enforces this by clearing the repository at the start of `create_repository()`.

The patches are mechanical and focused:
1. Drops an unused helper (`safe_create_leading_directories_1()`).
2. Introduces a variant of `safe_create_leading_directories()` that doesn’t apply shared permissions to leading directories.
3. Refactors `git init` to move shared-repository handling into `setup.c`.
4. Adjusts `git clone` to avoid applying `core.sharedRepository` to leading directories.
5. Updates `repo_clear()` to fully reset the repository state.
6. Finally, enforces that the input repository carries no relevant state by clearing it upfront.

The series touches `builtin/init-db.c`, `builtin/clone.c`, `path.c`, `repository.c`, and `setup.c`, with a new test in `t/t1301-shared-repo.sh` to verify the behavior. The motivation is twofold: simplify the interface and pave the way for unifying repository initialization in future work. The patches are built on recent changes (including Patrick’s ODB alternates work) and appear well-scoped, though the follow-up unification effort isn’t detailed here.

Key names introduced/modified:
- `safe_create_leading_directories_no_share_const()` (new function)
- `create_repository()` (interface change)
- `repo_clear()` (enhanced to fully reset state)
- Test `t1301.28` (new test case)

The series looks like a clean, incremental step toward a larger refactoring goal. No controversy is evident from the cover letter, but the enforcement of statelessness (patch 7) might draw scrutiny if callers rely on undocumented behavior. The test coverage suggests Patrick has anticipated this.
