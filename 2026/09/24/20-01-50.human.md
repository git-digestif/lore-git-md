This is the first patch in Johannes Schindelin’s v2 series fixing GitLab CI breakage for Windows builds after Rust support was enabled. It modifies `ci/install-dependencies.ps1` to provision the correct Rust toolchain for MinGW-based builds.

The patch adds a `-Mingw` switch to the script, which selects the `gnu` Rust target (GCC-compatible) instead of the default `msvc` target. When the switch is used, the script installs Rust and exits early, skipping the Git and Meson installations that are already provided by the minimal Git for Windows SDK. The existing Rust installation logic (for MSVC builds) is preserved but moved later in the script to avoid duplication.

The change is narrowly scoped to CI infrastructure and does not affect Git’s core behavior. The commit message clarifies that the MinGW Makefile build requires the GCC-targeting Rust toolchain, not another Git or Meson installation. This addresses the original CI breakage by ensuring the correct toolchain is available for MinGW builds. The patch looks technically sound and aligns with the series’ goal of restoring Windows CI functionality.
