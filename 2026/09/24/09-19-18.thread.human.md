This thread is a seven-patch series from Patrick Steinhardt refactoring the `create_repository()` function to enforce statelessness, removing its last in/out parameter usage. The goal is to simplify the interface and prepare for future repository initialization unification. The series is now fully posted as v1 and under review.

The first six patches are plumbing prerequisites—relocating logic, introducing new helper functions, and ensuring consistent handling of `core.sharedRepository`—without changing behavior. The capstone, patch 7/7, enforces statelessness by clearing the input repository at the start of `create_repository()`, a minimal change that completes the interface simplification. Tests confirm leading directory permissions now respect the umask for both `git init` and `git clone`.

So far, feedback has been light and surface-level. Kaartic Sivaraam reviewed two patches, noting minor documentation omissions and observing that one patch incidentally reduced reliance on `the_repository`, but raised no technical concerns. The series remains uncontested, with no open objections or requests for changes. The main loose end is whether any undocumented callers rely on the old in/out behavior, which the enforcement in patch 7/7 may surface.
