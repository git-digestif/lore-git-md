This thread is about Patrick Steinhardt’s seven-patch series to refactor Git’s `create_repository()` function to enforce statelessness in its input `struct repository`. The goal is to simplify the interface and prepare for future unification of repository initialization. The series is now at v2, with updates focused on documentation and commit message clarifications.

The first six patches are uncontroversial plumbing changes—relocating logic, simplifying helpers, and aligning behavior between `git init` and `git clone`—while the seventh patch, the capstone, enforces statelessness by clearing the input repository at the start of `create_repository()`. So far, reviews have been surface-level, focusing on cosmetic details like man-page references (`free(3)` vs. `free(3p)`) and comment wording, without engaging with the technical substance of the interface change. Junio C Hamano recently weighed in to suggest using `free(3)` instead of `free(3p)` for simplicity, but this remains a minor documentation nit.

The series is still under review, with no substantive technical feedback yet. The main open question is whether patch 7/7 might surface undocumented caller reliance on the old in/out behavior, but this hasn’t been tested in practice. The broader goal of unifying repository initialization is mentioned but not yet detailed. Key participants—Patrick Steinhardt (author), Kaartic Sivaraam, and Karthik Nayak—have all endorsed the series as well-structured, but no one has yet reviewed the core interface change in depth.
