This thread is a refactoring series by Patrick Steinhardt to simplify the `create_repository()` interface by enforcing statelessness in its input `struct repository`. The series, now at v2, consists of seven patches—six plumbing prerequisites and a capstone patch (7/7) that calls `repo_clear()` at the start of `create_repository()` to eliminate the last in/out usage (propagation of `core.sharedRepository`). The goal is to reduce confusion and prepare for future unification of repository initialization.

So far, reviews from Kaartic Sivaraam and Karthik Nayak have been supportive but surface-level, focusing on documentation clarity and mechanical cleanups rather than the core interface change. The latest exchange between Patrick and Karthik addressed minor implementation details in patch 6/7, confirming that replacing `FREE_AND_NULL()` with plain `free()` calls in `repo_clear()` is safe due to the subsequent `memset()`. No substantive technical concerns have been raised, though patch 7/7 may yet surface undocumented caller reliance on the old behavior.

The series touches several files (`repository.c`, `setup.c`, `path.c`, and others) and introduces or adjusts helper functions like `safe_create_leading_directories_no_share_const()`. Behavior changes are minimal: patch 5/7 aligns `git clone` with `git init` by respecting the umask for leading directory permissions, and new tests verify this consistency. The refactoring remains uncontroversial, but the capstone patch’s enforcement of statelessness has not yet received deep technical scrutiny.
