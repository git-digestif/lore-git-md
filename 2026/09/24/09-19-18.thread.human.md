This thread is a seven-patch series from Patrick Steinhardt that refactors Git’s `create_repository()` function to enforce a stateless interface, removing the last in/out parameter usage (for `core.sharedRepository`). The goal is to simplify the function’s contract and prepare for future unification of repository initialization. The series is now at v2, which improved documentation and commit messages in response to minor feedback but made no functional changes.

The first six patches are plumbing prerequisites—relocating logic, inlining functions, and introducing small helpers like `safe_create_leading_directories_no_share_const()`. Patch 4/7, the latest email, moves the `core.sharedRepository` setting from `git init` into `create_repository()`, eliminating the awkward in/out pattern. The capstone patch (7/7) will enforce statelessness by clearing the input repository at the start of `create_repository()`. So far, reviews from Kaartic Sivaraam and Karthik Nayak have been supportive but surface-level, focusing on documentation clarity and mechanical cleanups rather than the core interface change or broader design goals. The series remains under review with no substantive technical objections raised.
