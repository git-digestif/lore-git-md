This thread is a seven-patch series from Patrick Steinhardt refactoring the `create_repository()` interface to enforce stateless input, removing the last in/out parameter usage (propagation of `core.sharedRepository`). The goal is to simplify the interface and prepare for future repository initialization unification.

The series is now complete and under review. The first six patches are plumbing prerequisites—relocating logic, simplifying helpers, and ensuring `git init` and `git clone` respect the umask for leading directory permissions. The final patch (7/7) enforces statelessness by calling `repo_clear()` at the start of `create_repository()`, eliminating the last in/out usage. Patrick has addressed a minor documentation nit from Kaartic Sivaraam by proposing a revised comment block in `path.h` to clarify the four `safe_create_leading_directories_*()` variants, though this is purely documentary and doesn’t affect behavior.

Reviews so far have been surface-level and supportive. Kaartic Sivaraam and Karthik Nayak have both noted the patches are well-structured and uncontroversial, with no technical objections or open questions raised. The series touches several core files (`repository.c`, `setup.c`, `path.c`, etc.) and introduces minor symbol changes (e.g., `safe_create_leading_directories_no_share_const()`), but no on-disk format changes or regressions are expected. The only loose end is potential undocumented caller reliance on the old in/out behavior, which the enforcement in patch 7/7 may surface. The series is ready for maintainer pickup, pending any deeper technical review.
