This thread is a seven-patch series from Patrick Steinhardt refactoring the `create_repository()` function to enforce a stateless interface, removing the last in/out parameter usage (propagation of `core.sharedRepository`). The goal is to simplify the interface and prepare for future unification of repository initialization.

The series is under review, with all patches now posted. The first six patches are plumbing prerequisites—relocating or simplifying logic without behavior changes—while the seventh enforces statelessness by clearing the input repository at the start of `create_repository()`. Key changes include moving `core.sharedRepository` handling into `setup.c`, ensuring `git init` and `git clone` respect the umask for leading directory permissions, and introducing a new helper function (`safe_create_leading_directories_no_share_const()`).

So far, the only feedback is a minor documentation nit from Kaartic Sivaraam about the new function’s visibility in `path.h`. The series remains uncontroversial, with no substantive objections or open technical questions yet. The enforcement in patch 7/7 could surface undocumented caller dependencies, but this hasn’t been raised in review. The work builds on Patrick’s recent ODB alternates efforts and sets the stage for further repository initialization unification.
