This thread is about Patrick Steinhardt’s seven-patch series refactoring the `create_repository()` function to enforce statelessness, removing the last in/out parameter usage (propagation of `core.sharedRepository`). The goal is to simplify the interface and prepare for future unification of repository initialization. The series is now at v2, with updated documentation and commit messages addressing minor feedback.

So far, the patches have been uncontroversial, with reviews from Kaartic Sivaraam and Karthik Nayak focusing on surface-level details like documentation wording, redundant NULL assignments, and cosmetic grouping of declarations. The core change—enforcing statelessness in `create_repository()` (patch 7/7)—has not yet received substantive technical review. The latest feedback from Kaartic is a minor documentation nit in patch 6/7, suggesting the removal of a `(3p)` suffix in a man-page reference, which Patrick will likely address in a future update.

The series touches several files, including `repository.c`, `path.c`, and `builtin/init-db.c`, and introduces or modifies functions like `safe_create_leading_directories_no_share_const()` and `repo_clear()`. The capstone patch (7/7) adds a call to `repo_clear()` at the start of `create_repository()`, enforcing statelessness, though this is constrained by `repo_config_values()` requiring `the_repository`. No behavior changes are expected, but there’s a risk of surfacing undocumented caller reliance on the old in/out behavior. Two new tests in `t/t1301-shared-repo.sh` verify leading directory permissions for `git init` and `git clone`. The series remains under review, with no major objections or open technical questions yet.
