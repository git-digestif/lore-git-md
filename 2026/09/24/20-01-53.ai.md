This is the fourth and final patch in Johannes Schindelin’s v2 series fixing GitLab CI breakage for Windows builds after Rust support was enabled. It addresses a specific linker issue in the MinGW environment by ensuring the Rust MSI installer includes the `Gcc` feature, which provides the `x86_64-w64-mingw32-gcc` linker required for host executables like `build.rs`.

The patch is minimal—just one line changed in `ci/install-dependencies.ps1`—and directly resolves the "cannot find `x86_64-w64-mingw32-gcc`" error observed in GitLab job #16593470275. The fix appends `,Gcc` to the `ADDLOCAL` MSI property when the `-Mingw` switch is used, ensuring linker compatibility with the existing MinGW-provided GCC toolchain. This aligns with earlier clarifications in the series: the `Gcc` feature does not install a redundant GCC but only ensures the Rust toolchain can link against MinGW’s GCC.

The commit message is precise, linking to both the failing job and the Rust MSI installer’s source code to document the `Gcc` feature’s purpose. The patch is uncontroversial and completes the series’ goal of restoring CI functionality for Windows builds. No further technical objections are expected, and the series as a whole appears ready for integration. The only remaining loose end is the unrelated GitLab Runner regression (credential-clearing timeout), which does not affect this patch.
