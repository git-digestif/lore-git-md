This thread adds revision-based filtering to `git repo structure`, letting users analyze specific subsets of a repository’s object graph by including or excluding commits, refs, or ranges. The feature, authored by Mark C. Chu-Carroll, has reached its seventh iteration and is now ready for merging. The v7 patch makes no substantive changes from v6—just a one-word commit message fix to address a typo noted by Kristoffer Haugsbakk.

The implementation uses Git’s standard `setup_revisions()` machinery, replacing an earlier approach with a design consistent with Git’s revision-parsing idioms. It allows commands like `git repo structure --branches --not --tags` to process only objects reachable from branches but not from tags. The patch touches `builtin/repo.c`, updates documentation, and expands test coverage to handle edge cases like overlapping includes/excludes and various output formats. While the patch includes an acknowledged inefficiency—a second ref-walk to count references by type—this is considered acceptable for a diagnostic tool.

All prior feedback has been addressed, including fixes for empty repository handling, documentation clarity, and error message precision. Patrick Steinhardt, the primary reviewer, confirmed the patch is procedurally clean and ready for integration, and Junio’s earlier procedural concerns have been resolved. The feature itself is uncontroversial and meets Git’s standards for merging. Unless new substantive feedback emerges, this is the final iteration.
