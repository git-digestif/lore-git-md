This thread introduces revision-based filtering to `git repo structure`, a command used for diagnosing repository structure. The v2 patch, authored by Mark C. Chu-Carroll, replaces the earlier `--no-<reftype>` approach with Git’s standard `setup_revisions()` machinery, allowing users to include or exclude specific revisions (e.g., `git repo structure --branches --not --tags`). This change directly addresses Patrick Steinhardt’s critique of the v1 design as inflexible and inconsistent with Git’s idioms.

The implementation modifies `builtin/repo.c` to parse revisions and apply reachability logic, updates the documentation, and expands test coverage to 84 lines. The core logic now processes objects reachable from included revisions unless they’re exclusively reachable via excluded revisions, avoiding the transitive dependency issues of v1. While the design is uncontroversial in principle—having adopted Patrick’s proposed alternative—no reviewers have yet weighed in on the v2 implementation. The main open question is whether the reachability logic handles edge cases (e.g., overlapping revisions) correctly.

The patch is ready for review, with no objections raised so far. If feedback remains positive, it’s likely to proceed toward integration, as it aligns with Git’s conventions and resolves the central design concern from v1.
