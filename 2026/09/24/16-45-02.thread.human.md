This thread is about adding filtering options to `git repo structure`, a command used for diagnosing repository structure and performance issues. The initial patch proposed `--no-<reftype>` flags (e.g., `--no-tags`, `--no-branches`) to exclude specific reference types and their transitive dependencies from the report, but this approach was contested by Patrick Steinhardt, who argued for a more flexible revision-based filtering system using Git’s existing `setup_revisions()` machinery.

Mark Chu-Carroll has now posted a v2 series that abandons the `--no-<reftype>` design in favor of Patrick’s proposed revision-based approach. This new version allows users to specify arbitrary revisions (e.g., `git repo structure --branches --not --tags` or `git repo structure master`) to include or exclude objects based on reachability, aligning the feature with Git’s established patterns in commands like `git log`. The implementation touches `builtin/repo.c`, documentation, and tests, replacing the enum-based flag system with `struct rev_info` and `setup_revisions()`. The design is now uncontroversial in principle, though the reachability logic and edge cases (e.g., overlapping includes/excludes) may still draw scrutiny.

The thread is currently under active review, with no feedback yet on v2. Patrick’s earlier critique was the primary driver of the redesign, and his approval will likely be decisive. No other reviewers have weighed in, leaving open questions about whether the implementation fully meets expectations. The feature remains self-contained, though it now integrates more deeply with Git’s revision-parsing infrastructure.
