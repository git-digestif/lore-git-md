This thread introduces a new feature for `git repo structure`: filtering options to exclude specific reference types (tags, branches, remotes, etc.) from the repository structure report. The initial patch by Mark C. Chu-Carroll adds `--no-<reftype>` flags (e.g., `--no-tags`) to omit these references and their transitive dependencies entirely, aiming to help users diagnose large objects or performance issues in focused ways.

The patch is under active review, with Patrick Steinhardt raising a fundamental design concern. Instead of hardcoded `--no-<reftype>` flags, Patrick proposes a more flexible approach: filtering by arbitrary revisions (e.g., `git repo structure --branches` or `git repo structure master`). This would align the command with Git’s existing revision-parsing machinery, making it more powerful and consistent with commands like `git log`. Patrick’s critique also highlights a minor coding style issue and suggests significant refactoring to support this alternative, which would touch the same files (`builtin/repo.c`, documentation, and tests).

No other reviewers have weighed in yet, and the discussion now centers on whether to adopt Patrick’s revision-based filtering or refine the current implementation. The outcome will determine whether the feature remains a simple exclusion mechanism or evolves into a more versatile tool for repository analysis.
