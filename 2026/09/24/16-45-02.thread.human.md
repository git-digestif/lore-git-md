This thread is about adding revision-based filtering to the `git repo structure` command, allowing users to analyze subsets of a repository’s object graph for diagnostic purposes. The feature, proposed by Mark C. Chu-Carroll, is now in its fourth iteration as a single-patch series. While the core idea is uncontroversial, the implementation has faced persistent technical feedback, particularly from Patrick Steinhardt, who has raised concerns about the commit message’s lack of motivation, documentation precision, overly restrictive revision-parsing defaults, insufficient test coverage, and a performance inefficiency caused by a double ref-walk in the code.

The v4 patch fixes a procedural issue—an accidental corruption in `revision.c` and `revision.h` that blocked v3—but does not address the substantive feedback from prior reviews. The commit message still fails to explain why revision filtering is useful, and the documentation does not align with Git’s established terminology or synopsis conventions. The revision-parsing logic, which defaults to `HEAD` and restricts inputs to commit-ish objects, may prevent filtering by trees or blobs, and the test suite lacks coverage for edge cases like `--filter=object:type=blob`. The double ref-walk, a workaround for `setup_revisions()`’s lack of a custom callback, could introduce performance overhead for large repositories or complex revision specifications, but this trade-off has not been discussed.

Patrick Steinhardt’s feedback remains the most critical, as his concerns touch on design choices that could limit the feature’s flexibility and usability. The author has not engaged with these issues in the v4 cover letter, leaving the patch in a state where it is procedurally clean but not yet ready for merging. A fifth version addressing these points—particularly the commit message, documentation, revision-parsing defaults, and test coverage—will likely be needed before the patch can progress. The feature itself is not in dispute, but the implementation details require further refinement.
