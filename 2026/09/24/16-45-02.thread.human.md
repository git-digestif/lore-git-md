This thread covers Mark C. Chu-Carroll's v8 patch adding revision-based filtering to `git repo structure`, which lets users include or exclude specific commits, refs, or ranges from the repository structure report using standard `setup_revisions()` machinery. The series has been through eight iterations, with Patrick Steinhardt signing off that the latest version looks good, and the SHA-256 test compatibility issue resolved by adding `SHA1` prerequisites to the affected tests. However, Junio C Hamano has now raised three new, unresolved implementation concerns in the option parsing and resource management: the `parse_options()` call omits `PARSE_OPT_KEEP_DASHDASH`, preventing proper disambiguation of pathspecs from revisions with `--`; the `argc > 1` check incorrectly triggers `setup_revisions()` for non-revision flags like `--objects` or `--stdin`; and an error path leaks resources by failing to call `release_revisions()` on the `revs` struct. These join his earlier still-open concern about brittle hardcoded disk-size values in test expectations. The patch remains under review, awaiting the author's response to these parsing and cleanup issues.
