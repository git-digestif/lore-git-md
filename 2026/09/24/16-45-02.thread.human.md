This thread is about adding revision-based filtering to `git repo structure`, allowing users to include or exclude specific revisions (commits, refs, or ranges) from the repository structure report. The feature was initially proposed in v1 with a `--no-<reftype>` approach but was redesigned in v2 to use Git’s standard `setup_revisions()` machinery after Patrick Steinhardt criticized the original design as inflexible and inconsistent with Git’s idioms.

The v2 patch is under active review, with Patrick Steinhardt providing a detailed critique focused on the commit message’s lack of motivation, documentation precision, revision-parsing defaults, and test coverage. Kaartic Sivaraam contributed a minor suggestion to tweak the commit title, which the author has accepted, but the substantive issues remain unresolved. The patch currently modifies `builtin/repo.c`, `Documentation/git-repo.adoc`, and `t/t1901-repo-structure.sh`, introducing CLI syntax like `git repo structure <revision>... [--not <revision>...]` and replacing the v1 enum-based flag system with `struct rev_info` and `setup_revisions()`.

Key open questions include whether the commit message adequately justifies the feature’s benefits, whether the documentation aligns with Git’s terminology, whether the revision-parsing defaults are overly restrictive, and whether test coverage is sufficient for edge cases like filtering by trees or blobs. The thread is still awaiting a v3 patch to address these concerns. No performance implications have been discussed yet, and the feature is otherwise self-contained with no dependencies on other in-flight efforts.
