The `git repo structure` command is gaining revision-based filtering to let users analyze specific subsets of a repository’s object graph. Mark C. Chu-Carroll’s fifth iteration of the patch adds standard Git revision syntax (e.g., `git repo structure --branches --not --tags`) via `setup_revisions()`, replacing the earlier `--no-<reftype>` approach. The v5 patch fixes the critical “empty repository” regression, improves the commit message, and cleans up redundant control flow, bringing the series closer to readiness.

Two key issues remain unresolved. First, Patrick Steinhardt continues to question the restrictiveness of the revision-parsing defaults (`.def = "HEAD"` and `.revarg_opt = REVARG_COMMITTISH`), which prevent filtering by trees or blobs; the author defends them as necessary to avoid breakage in empty repositories. Second, test coverage for trees/blobs and revision options like `--filter=object:type=blob` is still missing, and the double ref-walk inefficiency persists as a trade-off for consistency with Git’s idioms. While the feature itself is uncontroversial, these implementation details may require a sixth version before the patch can be merged.
