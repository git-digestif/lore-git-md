This thread is about adding revision-based filtering to `git repo structure`, allowing users to analyze subsets of a repository’s object graph for diagnostic purposes. Mark C. Chu-Carroll’s v3 patch implements this using Git’s standard `setup_revisions()` machinery, replacing an earlier enum-based approach. While the feature’s goal is uncontroversial, the implementation has drawn scrutiny over its revision-parsing defaults, test coverage, and documentation clarity.

The patch is under active review, with Patrick Steinhardt providing the most substantive feedback. He’s raised concerns about the commit message’s lack of motivation, overly restrictive revision-parsing defaults (e.g., `.def = "HEAD"` and `.revarg_opt = REVARG_COMMITTISH`), missing test cases for trees/blobs, and a potential performance issue from a double ref-walk workaround. Kaartic Sivaraam’s feedback has been minor, focusing on commit message improvements. Junio C Hamano’s latest email, however, shifts focus to procedural issues: the v3 patch contains two nonsensical hunks (likely editing accidents) that undermine its credibility. This suggests the patch isn’t yet ready for deeper technical review and will need a v4 to address both the sloppiness and Patrick’s unresolved concerns. No merge decisions have been made, and the series remains in the review phase.
