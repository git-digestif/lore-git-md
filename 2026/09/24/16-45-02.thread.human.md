Mark C. Chu-Carroll’s patch series adding revision-based filtering to `git repo structure` has reached its second iteration after a design overhaul. The v2 patch replaces the v1’s `--no-<reftype>` approach with Git’s standard `setup_revisions()` machinery, addressing Patrick Steinhardt’s critique that the original implementation was inflexible and inconsistent with Git’s idioms. The goal—flexible filtering of repository structure reports—is now uncontroversial, but the implementation is under active review.

Patrick Steinhardt’s recent feedback on v2 focuses on three areas: the commit message lacks motivation for the design change, the documentation should use Git’s established terminology (e.g., “revisions” instead of “query clauses”), and the revision-parsing logic could be more permissive. He questions whether the `setup_revision_opt` struct is needed at all, suggesting that passing `NULL` would let `setup_revisions()` handle all revision types without default assumptions. He also requests additional test coverage for edge cases like filtering by trees or blobs. The review is constructive but not yet a sign-off, and the patch may need a v3 to address these points.

The series touches `builtin/repo.c`, the documentation, and the test suite, and uses `struct rev_info` to parse revision specifications like `git repo structure --branches --not --tags`. No performance concerns have been raised yet, but the lack of feedback beyond Patrick’s leaves open whether the implementation fully meets expectations.
