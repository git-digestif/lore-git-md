The `git repo structure` command is gaining revision-based filtering to let users analyze subsets of a repository’s object graph. Mark C. Chu-Carroll’s fifth iteration of the patch replaces the early `--no-<reftype>` flags with Git’s standard `setup_revisions()` machinery, making the syntax familiar (`git repo structure <revision>... [--not <revision>...]`) and the behavior consistent: objects reachable from the included revisions are shown unless they’re only reachable via the excluded ones. After fixing the empty-repository handling and sharpening the documentation in v5, the patch is now procedurally clean and the core design uncontroversial.

Patrick Steinhardt’s thorough reviews have shaped every version. In v5 he raised only minor nits—tightening an error message, removing a stray newline, and stripping out unrelated test cleanups—while explicitly calling the patch “happy” on the technical merits. The remaining open questions from earlier rounds (whether the revision-parsing defaults are too restrictive, whether tests should cover trees and blobs, and the double ref-walk inefficiency) are no longer blocking; Patrick now considers them either tolerable or already addressed.
