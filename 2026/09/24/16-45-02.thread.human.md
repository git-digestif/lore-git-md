This thread covers Mark C. Chu-Carroll's effort to add revision-based filtering to the `git repo structure` command, allowing users to include or exclude specific commits, refs, or ranges when generating repository structure reports. The series has reached version 8, which differs from v7 only by adding `SHA1` test prerequisites to the new tests in `t/t1901-repo-structure.sh` -- the short-term fix for the SHA-256 compatibility issue that Junio C Hamano identified regarding hardcoded 40-character object IDs.

Patrick Steinhardt reviewed the series through multiple iterations and has signed off, stating the version looks good to him. All substantive technical feedback from prior rounds -- including commit message motivation, empty repository handling, documentation precision, and error message improvements -- has been incorporated. The implementation uses Git's standard `setup_revisions()` machinery to parse revision arguments, falling back to walking all references when none are provided.

The patch is considered ready for integration with no blocking issues remaining. Accepted trade-offs include a double ref-walk inefficiency when revisions are specified (tolerated for a diagnostic tool), restrictive revision-parsing defaults that Patrick suggested could be broadened but were not changed, and the absence of a `ref^{tree}` test case. The author maintains a long-term commitment to rewrite all tests in the file to be hash-agnostic before Git 3.0, though the immediate SHA-256 concern is resolved by the current prerequisite guards.
