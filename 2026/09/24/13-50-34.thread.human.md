This thread is about a bugfix patch from Nathan Froyd that makes `git fetch-pack` mark exact OIDs in refs, aligning its behavior with `git fetch`. Currently, `fetch-pack` sends `want-ref $OID` instead of `want $OID` when given an exact OID, causing "unknown ref" errors from the remote.

The patch is under review, with Junio C Hamano opposing the change on design grounds. He argues that `fetch-pack` should remain a low-level command without DWIM heuristics, preserving the ability to send `want-ref` requests for arbitrary ref names—even those that look like OIDs. His latest email sharpens this objection, explaining that the patch’s approach would break existing use cases that rely on exact ref-name transmission. Nathan, the author, advocates for consistency with `git fetch`, but the fundamental question—whether `fetch-pack` should adopt DWIM behavior or require explicit OID specification—remains unresolved. No alternative mechanism has been proposed yet. The discussion is still open, with no clear path forward.
