This is the implementation patch in Kaartic Sivaraam’s RFC series to improve Git’s error messages when an explicitly provided `--git-dir` is rejected as invalid. The patch introduces `is_git_directory_verbose()`, a new helper in `setup.c` that mirrors the existing `is_git_directory()` but populates an optional `strbuf` with detailed reasons why the directory failed validation. The existing `is_git_directory()` is then reimplemented as a thin wrapper that calls the new helper with a NULL `strbuf`.

The implementation covers the three main failure modes: problems with `HEAD` (missing, unreadable, or pointing outside `refs/`), inaccessible object directories (including those set via `GIT_OBJECT_DIRECTORY`), and unreadable `refs/` directories. Each failure path appends a human-readable, translatable explanation to the provided `strbuf`. The code is careful to preserve the exact same validation logic as the original, so behavior is unchanged—only the error reporting is enhanced.

This is the second patch in a three-patch series; the first added test coverage for the current behavior, and the third will update the call-sites to use the new helper. The patch is narrowly scoped to the explicit `--git-dir` case, leaving repository discovery and `gitfile` handling for potential follow-ups. The commit message is clear, the code is clean, and the motivation—helping users diagnose misconfigurations—is compelling. If the RFC direction is well-received, this implementation looks ready to proceed.
