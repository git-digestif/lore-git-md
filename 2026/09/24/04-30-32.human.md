This is a maintainer clarification in the Git 3.0 planning thread, correcting minor typos in Junio C Hamano’s earlier message while restating the provisional timeline and technical strategy for the transition from Git 2.x to 3.0. The email refines the earlier proposal without altering its substance, offering a cleaner version of the same plan for community discussion.

Junio reiterates the three-phase timeline: Git 2.98 in December 2026 (the final 2.x feature release), Git 2.99 in March 2027 (a transitional release with breaking changes disabled), and Git 3.0 in April 2027 (identical to 2.99.1 but with breaking changes enabled). The month-long gap between 2.99 and 3.0 is explicitly framed as an "advertisement" period for downstream projects, not a full development cycle. This aligns with the Contributor’s Summit consensus that 2.99 should serve as a signal for upcoming changes, though Junio notes no firm agreement was reached on the exact date for 2.99.1 and 3.0.

The technical strategy remains unchanged: Git 2.99.1 will be a bugfix-only release, while Git 3.0 will enable breaking changes via the `WITH_BREAKING_CHANGES` Makefile knob. Junio’s preference for retaining this knob in Git 3.0—minimizing divergence between 2.99.1 and 3.0—is restated, with cleanup of disabled code deferred to later 3.x releases. This approach reduces maintenance overhead but leaves conditional compilation in place. The proposal also accommodates LTS distributions by allowing volunteers to maintain 2.99.x indefinitely.

The email advances the thread by providing a polished version of the earlier plan, making it easier for the community to engage with the specifics. Key open questions remain, such as the scope of breaking changes (e.g., Rust support, SHA-256 interoperability) and whether the timeline aligns with downstream needs (e.g., LTS distribution schedules). Junio’s tone is pragmatic, emphasizing that this is his interpretation of the summit consensus and inviting further feedback. The next "What’s cooking" report is likely to reflect refinements based on mailing list discussion.
