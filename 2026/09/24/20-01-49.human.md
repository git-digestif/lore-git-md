This is a CI/build system patch series, the second iteration of Johannes Schindelin’s fix for GitLab CI breakage in Windows builds after Rust support was enabled. The series restores pipeline functionality by addressing Rust toolchain provisioning (`cargo`), GNU Rust host-linker support, and silent data loss in `.git/info/exclude`.

The v2 update is purely cosmetic: commit messages have been reworded to clarify previously confusing statements. For example, the first patch now explains that "GNU Rust" refers to the Rust toolchain targeting GCC (not MSVC), and the fourth patch corrects "GNU MSI" to "Rust MSI" when describing the `Gcc` feature. No code changes were made, and the series remains narrowly scoped to GitLab’s MinGW-based Windows environment.

The original breakage was confirmed by Junio C Hamano, and Karthik Nayak validated v1 in GitLab’s internal CI (MR #671, pipeline #2863888081), where both `build:mingw64` and `build:msvc-meson` jobs now succeed. Patrick Steinhardt’s earlier questions about toolchain redundancy and script behavior have been resolved in the thread, leaving no technical objections. The series is ready for integration, though Johannes notes the `build:mingw64` job name may be outdated (`ucrt64` would be more accurate).

An unrelated GitLab Runner regression (credential-clearing timeouts in Runner 19.4.0~pre) was identified during testing but does not affect this series. The issue has been escalated to GitLab’s infrastructure team, so no further action is expected here.

For developers following Git’s CI stability, this is a straightforward fix with no impact on core functionality. The key files are `.gitlab-ci.yml` and `ci/install-dependencies.ps1`, and the series is part of the broader Rustification effort—though its focus is purely on CI infrastructure.
