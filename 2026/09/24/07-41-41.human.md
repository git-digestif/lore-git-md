This is a follow-up in the `http.sslVerifyStatus` thread, now focused on fixing the test infrastructure after the feature was merged to `master` and then reverted from `next`. SZEDER Gábor clarifies his earlier report about the `SSL_VERIFYSTATUS` prerequisite: the check itself is correct in principle, but the error message it looks for is misleading. The prerequisite only tests whether libcurl supports `CURLOPT_SSL_VERIFYSTATUS`, not whether the server can provide OCSP staples, so it should pass even if the connection fails for unrelated reasons (e.g., repository not found). Gábor suggests renaming the prerequisite to `CURL_SSL_VERIFYSTATUS` and matching against the more specific error string "could not enable OCSP status verification" instead of "http.sslVerifyStatus is set" to make the intent clearer. This is a minor but helpful improvement to the test’s robustness and readability. The core issue Gábor originally raised — that the prerequisite was too permissive — is now understood to be a non-issue; the real problem was the confusing error message. No code changes are proposed yet, but Gábor’s clarification paves the way for a straightforward follow-up patch.
