The warning (`-Winvalid-pch`) surfaces this mismatch, though it does not break the build in his case.

The scenario involves Peff’s `config.mak` setup, where he conditionally disables OpenSSL for historical builds to avoid deprecated API usage. Because the precompiled header is generated with a fixed set of flags (without `NO_OPENSSL`), it cannot be reused for targets like `imap-send.o` that override `EXTRA_CPPFLAGS`. Peff notes this is mostly cosmetic for him (he also disables `-Werror` for old builds), but it highlights a potential limitation: precompiled headers are sensitive to flag mismatches, and target-specific flags may invalidate them.

This is not a showstopper for the series, but it reveals a design constraint. The patch’s current approach assumes uniform flags across most object files, which may not hold for specialized targets (e.g., those with `EXTRA_CPPFLAGS`). Peff’s use case is niche (historical builds), but similar issues could arise for other conditional compilation scenarios (e.g., platform-specific flags).
