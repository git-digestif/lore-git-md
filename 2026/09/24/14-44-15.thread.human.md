This thread is about a new `gitmergeconflicts(7)` man page, introduced by Julia Evans to consolidate Git’s scattered merge-conflict resolution advice into a single, user-friendly guide. The series is now at v2, with all prior feedback addressed, and is considered complete and ready for merging—pending only minor trailer adjustments in a planned v3.

Junio C Hamano, the maintainer, has just provided a detailed review of the first patch, focusing on clarity, completeness, and consistency. While he praises the guide’s motivation and structure, he raises several substantive points that will likely require minor revisions. Key issues include omissions (e.g., `git am -3` and `git checkout -m` as conflict-causing commands), undefined terminology ("original" for the common ancestor), unexplained `diff3` markers (`|||||||`), and the need to acknowledge semantic conflicts. He also suggests deprecating `zdiff3` as a "failed experiment" and clarifying the `AUTO_MERGE` reference in `git diff`. Additionally, he flags a long-standing bug in `git-merge.adoc` (broken step references) that warrants a separate fix.

The series has already incorporated significant improvements from earlier feedback, including a new foundational section ("WHAT IS A MERGE CONFLICT?"), a rewritten "OURS" AND "THEIRS" explanation, and active promotion of `merge.conflictstyle=diff3` as a best practice. Junio’s latest contributions—detailed examples demonstrating how `diff3` reveals the *intent* behind conflicting changes—have been integrated into the guide. Other participants, like D. Ben Knoble and Patrick Steinhardt, have provided substantive feedback on terminology, user experience, and technical completeness, all of which Julia has addressed. Patrick’s proposal to embed commit details in conflict markers remains under discussion as a potential follow-up.

The series is fully integrated into the documentation build system, with no further content revisions planned. The only remaining action is a procedural update to the trailers in v3, replacing proposed `Reviewed-by:` entries with `Helped-by:` for Knoble and Steinhardt, per Junio’s clarification. Once these adjustments are made, the series is expected to merge. Open questions include whether Patrick’s commit-accessibility enhancement or Junio’s suggested code changes (e.g., conflict marker labels, `git status` wording) will materialize as follow-up patches.
