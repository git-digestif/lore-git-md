This thread is about Julia Evans’s patch series introducing `gitmergeconflicts(7)`, a new man page that consolidates Git’s scattered merge-conflict advice into a single, example-driven guide. The series is now in Junio’s `seen` branch for integration testing, but a `make check-docs` failure surfaced because the new page wasn’t registered in the documentation linting infrastructure.

Jeff King (Peff) just diagnosed the issue: the new guide needs to be added to `command-list.txt` under the “guides” section, matching the pattern used for `gitdatamodel(7)`. This is a mechanical fix—no content changes are required—and once applied, the series should clear the linting check and continue toward `next`. The rest of the series remains under review, with open questions about technical accuracy, scope (e.g., whether `git apply` conflicts should be included), and the balance between brevity and completeness in the new guide. Junio’s earlier feedback on build-system integration has already been addressed in the current version.
