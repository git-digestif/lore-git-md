This is a refactoring patch series from Patrick Steinhardt, part of the ongoing effort to clean up Git’s repository initialization code. The goal is to simplify the interface of `create_repository()`, which currently acts as both an input and output parameter—passing in a partially configured `struct repository` and returning it fully initialized. The series removes the last remaining input dependency (the `core.sharedRepository` setting) so the function becomes a pure output operation, making the API clearer and safer.

The series starts with small preparatory cleanups: removing an unused helper (`safe_create_leading_directories_1()`), adding a variant of the directory-creation function that doesn’t apply shared permissions (`safe_create_leading_directories_no_share_const()`), and tidying up the messy directory-creation logic in `builtin/init`. It then moves the handling of `core.sharedRepository` out of `builtin/init` and into `setup.c`, ensuring the setting no longer affects leading directory permissions during clone operations. Finally, it modifies `repo_clear()` to fully reset the repository and enforces that any repository passed to `create_repository()` must be stateless—clearing it immediately to catch misuse.

The motivation is sound: the current interface is confusing and error-prone, and this refactoring paves the way for further unification of repository initialization. The series is well-structured, with each patch addressing a logical step, and includes a new test in `t/t1301-shared-repo.sh` to verify the behavior. Given Patrick’s track record and the thoroughness of the commit messages, this looks like a solid, uncontroversial cleanup that should merge smoothly. If you care about low-level repository plumbing, this is worth a quick skim; otherwise, it’s safe to wait for the follow-up work that builds on it.
