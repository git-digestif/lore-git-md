Subject: [PATCH 0/7] repository: simplify `create_repository()` interface
Series version: v1 (initial)
Originating author: Patrick Steinhardt
Thread type: patch series

Core problem or goal
Refactor the `create_repository()` function to enforce that its input `struct repository` is stateless (currently used as an in/out parameter), removing the last in/out usage (propagation of `core.sharedRepository`). The goal is to simplify the interface, reduce confusion, and prepare for future unification of repository initialization.

Current status
Under review; v1 posted. The series is now complete with all seven patches submitted. Patches 1/7 through 6/7 are plumbing prerequisites that relocate or simplify logic without behavior changes. Patch 7/7 enforces statelessness by calling `repo_clear()` at the start of `create_repository()`, eliminating the last in/out parameter usage. No prior versions or merge status reported.

Key technical details
- Files touched: `builtin/init-db.c`, `builtin/clone.c`, `path.c`, `path.h`, `repository.c`, `repository.h`, `setup.c`, `t/t1301-shared-repo.sh`
- New/renamed symbols:
  - `safe_create_leading_directories_no_share_const()` (introduced in patch 2/7; accepts `const char *path`)
  - `safe_create_leading_directories_1()` (removed in patch 1/7)
  - `repo_clear()` (overhauled in patch 6/7 to use `memset`; declaration moved next to `repo_init()` in `repository.h`)
- Behavior change: `create_repository()` now clears the input repository at the start, enforcing statelessness. Patch 5/7 ensures both `git init` and `git clone` respect the umask for leading directory permissions, rather than overriding it with `core.sharedRepository`. Patch 4/7 moves the `core.sharedRepository` setting from `cmd_init_db()` into `create_repository()` in `setup.c`, removing the last in/out usage for this value.
- Patch 7/7 details: adds a call to `repo_clear()` at the start of `create_repository()` in `setup.c`; minimal three-line change. The enforcement is constrained by `repo_config_values()` requiring `the_repository`, preventing a more radical interface change (e.g., allocating a new repository).
- On-disk format: unchanged
- Test coverage: new test `t1301.28` in `t/t1301-shared-repo.sh` verifies leading directory permissions for both `git init` and `git clone`

Open questions and loose ends
