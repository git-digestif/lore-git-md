Subject: [PATCH 0/7] repository: simplify `create_repository()` interface
Series version: v1 (initial)
Originating author: Patrick Steinhardt
Thread type: patch series

Core problem or goal
Refactor the `create_repository()` function to enforce that its input `struct repository` is stateless (currently used as an in/out parameter), removing the last in/out usage (propagation of `core.sharedRepository`). The goal is to simplify the interface, reduce confusion, and prepare for future unification of repository initialization.

Current status
Under review; v1 posted. Patches 1/7 (mechanical cleanup in `path.c`) and 2/7 (new const helper in `path.c`) are uncontroversial plumbing prerequisites. Patch 3/7 (mechanical cleanup in `builtin/init-db.c`) replaces a manual workaround for `core.sharedRepository` with a direct call to the new `safe_create_leading_directories_no_share_const()` helper, removing boilerplate without behavior change. No prior versions or merge status reported.

Key technical details
- Files touched: `builtin/init-db.c`, `builtin/clone.c`, `path.c`, `path.h`, `repository.c`, `setup.c`
- New/renamed symbols:

  - `safe_create_leading_directories_1()` (removed in patch 1/7)
  - `repo_clear()` (enhanced in later patches)
- Behavior change: `create_repository()` will clear the input repository at the start, enforcing statelessness (enforced in patch 7/7)

- Patch 2/7 details: adds `safe_create_leading_directories_no_share_const()` to avoid in-place modification of constant paths; delegates to `safe_create_leading_directories_const()` with `NULL` repository
- Patch 3/7 details: replaces a manual `core.sharedRepository` save-zero-restore dance in `builtin/init-db.c` with a direct call to `safe_create_leading_directories_no_share_const()`, removing ten lines of boilerplate; no behavior change
