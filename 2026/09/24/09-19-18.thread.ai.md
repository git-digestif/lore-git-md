Core problem or goal
Refactor the `create_repository()` function to enforce that its input `struct repository` is stateless (currently used as an in/out parameter), removing the last in/out usage (propagation of `core.sharedRepository`). The goal is to simplify the interface, reduce confusion, and prepare for future unification of repository initialization.

Current status
Under review; v1 posted. The series is complete with all seven patches submitted. Patches 1/7 through 6/7 are plumbing prerequisites that relocate or simplify logic without behavior changes. Patch 7/7 enforces statelessness by calling `repo_clear()` at the start of `create_repository()`, eliminating the last in/out parameter usage. The author has accepted documentation feedback from Kaartic Sivaraam and updated the comment block in `path.h` to group and clarify the four `safe_create_leading_directories_*()` variants under a single explanatory paragraph, replacing per-variant descriptions with a unified explanation of use cases (git-dir vs. working-tree files), behavior regarding `core.sharedRepository`, and path modification. No functional changes are involved; this update is purely documentary. No new version has been posted since v1.
