This is a **substantive review** of the second patch in the v5 bugfix series for the reference-transaction hook regression. Patrick Steinhardt, the primary maintainer of the refs subsystem, questions whether the current approach—updating individual callers like `git branch` and `git tag` to pass old OIDs—is the right architectural level for the fix.

The patch itself is a clean, well-motivated fix that restores the pre-2.31 behavior for `git branch -d` and `git tag -d` by passing resolved old OIDs to `refs_delete_refs()`. However, Patrick argues that the goal—ensuring the reference-transaction hook always receives the old OID—could be achieved more broadly by resolving the old OID *during the transaction itself*, rather than requiring every caller to provide it. This would make the fix universal (covering all ref modifications, not just deletions) and avoid the need to update each command individually.

His proposal is a **backwards-incompatible change** to the hook’s behavior, but he notes that the hook is already considered an internal interface where such changes are permissible. The trade-off is between a targeted, low-risk fix (the current patch) and a more ambitious, systemic improvement that would eliminate the problem for all future callers.

This review **reopens the architectural discussion** for the entire series. The author must now decide whether to defend the current approach (which is already merged to `next` and addresses the regression) or pivot to Patrick’s proposal, which would require a significant rewrite. The outcome will shape how Git handles reference-transaction hooks going forward.
