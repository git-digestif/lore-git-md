This is a CI/build system patch addressing GitHub Actions resource exhaustion. Tamir Duberstein replies to Patrick Steinhardt’s substantive review of the first patch in the series, providing the requested evidence and reconsidering one aspect of the fix.

Tamir supplies benchmark data comparing `diff -u` and `cmp` on two identical 2 GiB files: `diff` peaks at 4 GiB RSS and takes 5 seconds, while `cmp` uses only 1.2 MiB and finishes in 0.5 seconds. This confirms `test_cmp_bin` (which uses `cmp`) is a far lighter alternative. He also explains the OOM kills occurred in a private repository where GitHub runners have half the memory of public ones. However, he concedes Patrick’s point that the early file deletion is ineffective because the files are rewritten in subsequent tests, and asks whether to drop that part of the change.

The reply directly addresses all open questions from the review: CI failure context, benchmark data, and the value of early deletion. No new technical concerns are raised, so the discussion now hinges on whether the simpler `test_cmp_bin` replacement alone is sufficient or if the deletion should be kept despite its limited benefit. The next revision will likely focus on these two points.
