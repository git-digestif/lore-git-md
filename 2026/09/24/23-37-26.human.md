This is a documentation integration follow-up to Julia Evans’s `gitmergeconflicts(7)` series. Jeff King (Peff) identifies the root cause of the `make check-docs` failure that Junio reported after merging the series into `seen`: the new man page is not listed in `command-list.txt`, which the `ta/command-list-guides-sync-lint` topic uses to validate documentation links. That topic, which is in `seen` but not yet in `master`, enforces that all guides mentioned in `git(1)` are properly registered. Peff suggests adding `gitmergeconflicts` to `command-list.txt` under the "concept guides" section, following the precedent set by `gitdatamodel(7)` in commit c655855559.

The fix is mechanical and uncontroversial—it’s a routine step for any new guide. The series itself remains well-structured: it consolidates scattered merge-conflict advice into a single, example-driven man page and replaces redundant sections in existing command docs with cross-references. The only remaining work is this one-line addition to `command-list.txt`; once that’s done, the series should be ready to graduate from `seen` to `next`.
