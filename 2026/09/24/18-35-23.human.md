This is a user-proposed feature request in the Git version numbering discussion thread. Harald Nordgren suggests a set of breaking changes to Git’s default configuration values, arguing that now — before Git 3.0 is released — is the ideal time to introduce them, as it would avoid waiting another decade for the next major version.

Nordgren proposes changing the default values for nine configuration settings, all aimed at improving usability: enabling autostash for `checkout` and `rebase`, adopting more intuitive branch and tag sorting, switching to the `histogram` diff algorithm and enabling color-moved detection, and making `git status` compare the current branch against both its upstream and push targets by default. These are not new options — all exist today — but changing their defaults would alter the out-of-the-box behavior for all users, which is why he frames them as breaking changes.

He acknowledges the proposal is forward but suggests submitting a formal patch to open discussion. The timing is opportunistic: with Git 3.0 still undecided, he sees a window to include these changes in the next major release. However, the thread’s focus remains on version numbering, not on specific breaking changes, so his proposal introduces a new dimension — what *should* constitute a breaking change in Git 3.0 — rather than advancing the existing discussion.

The patch itself is not yet written, so there is no code to review or test. The motivation is clear (improving user experience), but the proposal is likely to be controversial: changing defaults affects every user, and some may prefer the current behavior. Whether these changes belong in Git 3.0 will depend on whether the project views 3.0 as a vehicle for user-facing improvements or primarily for internal architectural shifts. For now, this email serves as an early signal of interest and a prompt for discussion.
