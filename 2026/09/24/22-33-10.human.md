This is a **bugfix patch** targeting the reference-transaction hook regression introduced in Git 2.31. The patch restores the pre-regression behavior where the hook receives the correct old object ID (instead of all-zeros) when branches, tags, or remote refs are deleted via high-level commands like `git branch -d`, `git tag -d`, or `git remote prune`. The fix is well-motivated, narrowly scoped, and addresses a long-standing issue that broke external tools like Gerrit and GitLab.

The v6 approach moves the fix into the transaction hook layer itself, resolving old OIDs on demand and storing them in a separate field (`hook_old_oid`/`hook_old_target`) that does not influence transaction safety checks. This design preserves unconditional deletion semantics (avoiding changes to `refs_delete_refs()` or its callers) and aligns with Patrick Steinhardt’s architectural feedback. The commit message clearly documents the rationale, including why the fix belongs in the transaction layer and how it avoids overloading the refs API.

Key details:
- **Subsystems touched**: refs, reference-transaction hook (no changes to `refs_delete_refs()` or callers).
- **Commands fixed**: All ref-modifying commands (`git branch -d`, `git tag -d`, `git remote prune`, `git fetch --prune`, `git push`, `git symbolic-ref`) now report correct old OIDs in the hook. `git update-ref -d` remains unaffected (already correct).
- **Backends**: Works for both files and reftable.
- **Performance trade-off**: The bulk-deletion optimization (5s vs. 30m for 10k tags) is preserved, but on-demand resolution of old OIDs in the hook layer may introduce latency for large batches. This is acknowledged but unquantified.
- **Tests**: Updated regression tests verify hook payloads for all ref-modifying commands (files/reftable, SHA-1/SHA-256), symbolic refs, and concurrent updates.

The patch is **ready for merging**, resolving a persistent regression with minimal risk. The only open question is whether the performance trade-off is acceptable, but this is unlikely to block progress given the fix’s importance for external tooling. The series is rebased onto `master` and passes the full test suite with `DEVELOPER=1`.
