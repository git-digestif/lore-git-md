Thread identity: Documentation patch series introducing `gitmergeconflicts(7)`, a new man page consolidating merge conflict resolution guidance. Originating author: Julia Evans (via GitGitGadget). Thread type: patch series.

Core problem or goal: Git’s current documentation scatters merge-conflict advice across multiple command man pages (`git merge`, `git rebase`, `git revert`, `git cherry-pick`, `git pull`), leading to duplication, omissions, and user confusion. The series introduces a dedicated `gitmergeconflicts(7)` guide to centralize this information, improve clarity (e.g., clarifying "ours" vs. "theirs"), and provide practical examples based on user feedback. The goal is to replace redundant sections in existing man pages with cross-references to the new guide, reducing maintenance burden and improving user experience. The series now explicitly balances centralization with preserving command-specific nuances, particularly for operations like `git cherry-pick` that involve unique pseudo-refs (`CHERRY_PICK_HEAD`) and workflows. Junio’s review has clarified that the new guide is not a complete substitute for removed sections, especially for cherry-pick-specific details, which must be retained in the command’s man page.

Junio expanded on this guidance, clarifying that the recommended approach is to merge a topic branch *into* an integration branch (e.g., `next` or `jch`) to uncover interactions with other in-flight work, rather than applying patches directly onto it.   - `git diff AUTO_MERGE` for tracking progress.
