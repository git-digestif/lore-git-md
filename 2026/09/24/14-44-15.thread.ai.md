Thread identity: Documentation patch series introducing `gitmergeconflicts(7)`, a new man page consolidating merge conflict resolution guidance. Series version: v1 (initial, pending mechanical integration fixes and content refinements). Originating author: Julia Evans (via GitGitGadget). Thread type: patch series.

Core problem or goal: Git’s current documentation scatters merge-conflict advice across multiple command man pages (`git merge`, `git rebase`, `git revert`, `git cherry-pick`, `git pull`), leading to duplication, omissions, and user confusion. The series introduces a dedicated `gitmergeconflicts(7)` guide to centralize this information, improve clarity (e.g., clarifying "ours" vs. "theirs"), and provide practical examples based on user feedback (e.g., Mastodon polls). The goal is to replace redundant sections in existing man pages with cross-references to the new guide, reducing maintenance burden and improving user experience.

- Behavior changes: Replaces duplicated conflict-resolution sections in existing man pages with cross-references to the new guide. No on-disk or runtime behavior changes. The new guide is purely additive and does not alter existing functionality.
- Structure of the new guide: Organized as a practical, example-driven document with sections covering:
  - When merge conflicts occur (`git merge`, `git rebase`, `git cherry-pick`, `git pull`, `git revert`).
  - Resolution paths (fix or abort).
  - Merge conflict markers (`<<<<<<<`, `=======`, `>>>>>>>`) and the four-step resolution process (identify, edit, stage, continue).
  - Tools for handling conflicts (graphical merge tools, `merge.conflictstyle=diff3`/`zdiff3`, `git show :1:filename`).
  - Terminology clarification ("ours" vs. "theirs") and edge cases (e.g., `git rebase` inverts "ours"/"theirs").
  - `git diff AUTO_MERGE` for tracking progress.
  - Side-by-side examples of `diff3` vs. `zdiff3` output.
  - Sample `git status` output to guide users on `--abort`/`--continue` commands.
- Retained command-specific content: The series preserves explanations of options unique to individual commands (e.g., `--skip` for `git rebase`, `--no-commit` for `git cherry-pick`), while centralizing general conflict-resolution advice in the new guide.
- Pull-specific details: The updated `git-pull.adoc` replaces a brief mention of aborting merge conflicts with a cross-reference to the new guide, which covers resolution tools and examples but does not explicitly mention pull-specific edge cases (e.g., `--no-commit` or `--no-ff` conflicts).
- Build system integration: The new guide is now properly integrated into both the Makefile and Meson build systems, with the `.gitattributes` conflict-marker-size setting folded into the first patch.
