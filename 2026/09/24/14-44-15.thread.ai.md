Thread identity: Documentation patch series introducing `gitmergeconflicts(7)`, a new man page consolidating merge conflict resolution guidance. Series version: v1 (initial, pending mechanical integration fixes, `command-list.txt` registration, and content refinements). Originating author: Julia Evans (via GitGitGadget). Thread type: patch series.

Core problem or goal: Git’s current documentation scatters merge-conflict advice across multiple command man pages (`git merge`, `git rebase`, `git revert`, `git cherry-pick`, `git pull`), leading to duplication, omissions, and user confusion. The series introduces a dedicated `gitmergeconflicts(7)` guide to centralize this information, improve clarity (e.g., clarifying "ours" vs. "theirs"), and provide practical examples based on user feedback. The goal is to replace redundant sections in existing man pages with cross-references to the new guide, reducing maintenance burden and improving user experience. However, the series must balance centralization with preserving command-specific nuances, particularly for operations like `git cherry-pick` that involve unique pseudo-refs (`CHERRY_PICK_HEAD`) and workflows.

  - Resolution paths (fix or abort).
  - Merge conflict markers (`<<<<<<<`, `=======`, `>>>>>>>`) and the four-step resolution process (identify, edit, stage, continue).
  - Tools for handling conflicts (graphical merge tools, `merge.conflictstyle=diff3`/`zdiff3`, `git show :1:filename`).
  - Terminology clarification ("ours" vs. "theirs") and edge cases (e.g., `git rebase` inverts "ours"/"theirs").
  - `git diff AUTO_MERGE` for tracking progress.
  - Side-by-side examples of `diff3` vs. `zdiff3` output.
  - Sample `git status` output to guide users on `--abort`/`--continue` commands.
