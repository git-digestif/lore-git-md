This is a brief follow-up from Junio C Hamano in the Git 3.0 planning thread, responding to Johannes Schindelin’s confirmation that the provisional timeline provides sufficient clarity for Git for Windows’ roadmap. Junio clarifies that the timeline—particularly the dates for Git 2.99.1 and 3.0—should not be treated as final. He emphasizes that the stabilization period for Git 2.99 may extend beyond the current plan, potentially requiring additional maintenance releases (e.g., 2.99.2 or 2.99.3) before Git 3.0 is released. The April 2027 target for Git 3.0 is explicitly framed as tentative, with decisions deferred until later in the year.

The email does not introduce new technical details or objections but serves as a pragmatic caveat to downstream projects. Junio’s tone is cautious, reinforcing that the timeline is a working proposal rather than a commitment. This reply tempers Schindelin’s enthusiasm with a reminder of the uncertainties inherent in the stabilization process, particularly for a major version release. It does not alter the technical strategy (e.g., the `WITH_BREAKING_CHANGES` knob) or the scope of Git 3.0 but underscores the need for flexibility in planning. Downstream projects like Git for Windows should account for potential delays when aligning their roadmaps.
