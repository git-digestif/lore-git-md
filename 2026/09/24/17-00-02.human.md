This is a brief but important clarification from Junio C Hamano in the Git 3.0 planning thread. He responds to Johannes Schindelin’s earlier confirmation that the provisional timeline provides the clarity needed for Git for Windows’ roadmap, emphasizing that the timeline—particularly anything beyond December 2026—should not be treated as final.

Junio reiterates that the proposed schedule (Git 2.99 in March 2027 and Git 3.0 in April 2027) is contingent on stabilization efforts. If Git 2.99 requires more time to mature, the 2.99.x series could extend with additional maintenance releases (e.g., 2.99.2 or 2.99.3), and Git 3.0 might coincide with one of these later versions instead of the initial 2.99.1. His tone is pragmatic, framing the timeline as a flexible target rather than a commitment. This aligns with his earlier statements that the proposal reflects his interpretation of the Contributor’s Summit consensus but remains subject to mailing list feedback and real-world testing.

The email does not introduce new technical details or objections but serves as a reminder that the timeline is still fluid. Downstream projects like Git for Windows should plan for flexibility, especially around the 2.99.x stabilization phase. Junio’s caution is a standard part of Git’s release process, where integration testing in `next` and `seen` often reveals unforeseen issues that can delay graduation to `master`. This clarification is unlikely to derail planning but reinforces the need for contingency plans.
