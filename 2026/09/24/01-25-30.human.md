This is a small feature patch for the `git-contacts` contrib script, now in its third iteration. The patch teaches `git-contacts` to read patch content from stdin when the user explicitly passes `-` as an argument, replacing the v2 behavior that implicitly read from stdin when no arguments were given and stdin was not a terminal. This change aligns with the conventional UNIX idiom of using `-` to mean "read from stdin," allowing mixed usage of file arguments and stdin input (e.g., `git contacts patch1 - patch3 <patch2`).

The motivation remains the same: improving interoperability with external tools like `b4`, which the author is also patching in a separate effort. The v3 update simplifies the implementation by removing the implicit stdin detection and instead requiring the user to explicitly request stdin input with `-`. The commit message notes this change makes the script's behavior more predictable and flexible, though it does require users to update their invocations if they were relying on the v2 implicit behavior.

The patch touches only the Perl script in `contrib/contacts/` and does not alter any core Git functionality. It includes a minor update to the argument-handling logic and maintains the existing usage pattern of the script. The author has incorporated feedback from Junio C Hamano across the three versions, with this revision addressing the maintainer's suggestion to adopt the `-` idiom rather than implicit stdin detection.

This version looks clean and well-motivated, addressing the open question from v2 about which stdin-handling approach to adopt. The change is small enough that regression risk appears minimal, though it does introduce a minor breaking change from v2's behavior. The patch is ready for final review and likely to be merged unless further stylistic concerns emerge.
