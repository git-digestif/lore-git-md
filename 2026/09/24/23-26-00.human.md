This is Junio’s "What’s cooking" report for September 2026, summarizing the state of in-flight topics in Git’s integration branches. The report covers 35 topics, with a mix of new additions, stalled efforts, and ongoing work. Below are the highlights for a busy reader.

The upcoming Git 2.56 release is in its final stages, with 2.56-rc2 already tagged. No new feature topics are expected before the final release, so most in-flight work will remain in `next` until then. After 2.56, the next version will be Git 2.98, reflecting the project’s new versioning scheme discussed at the Contributor’s Summit.

Several topics are marked for merging to `next` or are already cooking there. **jk/pull-null-merge-head** fixes a segfault in `git pull` when commit lookup fails. **ps/reflog-expiry-fix** corrects a regression that swapped the default expiry periods for reachable and unreachable reflog entries. **kn/ci-unit-tests-on-windows-fix** ensures unit tests run correctly on Windows CI. **jt/object-file-batch-fsync-fix** addresses a bug in the ODB transaction logic when `core.fsyncMethod` is set to `batch`. **tb/rerere-lock-grace** improves lock handling during `git rebase`, `cherry-pick`, and `revert` to avoid contention with automatic maintenance tasks.

A few topics are awaiting review or rerolls. **je/doc-asciidoc-xrefs** updates documentation cross-references to use explicit AsciiDoc syntax, improving web rendering and link integrity. **js/ci-debian-12-http2-workaround** skips a flaky test in Debian 12 CI due to a curl bug. **hn/shallow-history-advice** adds helpful advice when `~N` or `^N` fails in shallow clones. **mc/refs-batched-deletions-old-oids** and **td/ls-files-untracked-cache** are performance optimizations that need feedback. **je/doc-merge-conflicts** introduces a new `gitmergeconflicts(7)` man page to centralize merge conflict documentation, with updates to related commands to link to it.

Build system improvements are also in progress. **ps/meson-improvements** optimizes Meson builds by avoiding redundant recompilation of HTTP sources and using precompiled headers for tests. **ps/setup-enforce-repo-passed-to-create-repository-has-no-state** refactors repository initialization to treat the repository object as purely an out-parameter, part of a broader effort to clean up object database setup.

Some topics are stalled or waiting for responses. **fz/rebase-autosquash-empty** and **as/utimensat-utimes** have been inactive for too long. **bs/runtime-prefix-obsd-getexecpath** adds OpenBSD support for resolving Git’s executable path, but needs maintainer feedback. **cc/lazy-fetch-trusted-bit** introduces a configuration to allow lazy fetching from promisor remotes in trusted repositories, but the design is still under discussion.

The report also includes several refactoring and cleanup efforts. **jc/cocci-free-updates** improves Coccinelle semantic patches to handle `FREE_AND_NULL()` correctly. **ps/ref-storage-format** standardizes terminology around reference storage formats across command-line options, environment variables, and configuration. **kn/receive-report-hook** adds a new `report` hook to `git receive-pack` to allow servers to modify the status report sent to clients.

For those following larger efforts, **hn/history-squash** (part of the experimental `git history` command) adds a `squash` subcommand to fold a range of commits into one. **mm/diff-process-hunks** introduces a new `diff.<driver>.process` configuration to allow external tools to act as hunk providers, enabling more flexible diff behavior.

Overall, the report shows a healthy mix of bugfixes, performance improvements, documentation updates, and refactoring. Most topics are in good shape, though a few need review or revision. The upcoming 2.56 release is the immediate focus, with Git 2.98 shaping up to be a significant update later this year.
