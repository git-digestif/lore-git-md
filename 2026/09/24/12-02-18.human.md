This is an RFC patch series from Kaartic Sivaraam that improves Git's error reporting when a directory is not recognized as a valid repository. The series focuses on cases where `--git-dir` is explicitly provided but the repository is invalid for some reason, such as a missing or inaccessible `HEAD` file, an invalid `GIT_OBJECT_DIRECTORY`, or an unreadable refs or objects directory.

The current behavior is blunt: Git simply says the directory is "not a git repository" without explaining why. This can be confusing, especially when the issue lies in an environment variable or a symlink target rather than the directory itself. The series adds a "reason" line to the error message, making it clearer what went wrong. For example, if `GIT_OBJECT_DIRECTORY` points to a nonexistent path, the error now explains that the object directory cannot be accessed.

The patches cover eight specific failure scenarios when `--git-dir` is given, including missing or unreadable `HEAD`, invalid symlinks, and inaccessible object or refs directories. The series does not yet address discovery walks (where Git searches parent directories), gitfile cases (like submodules or worktrees), or `GIT_ALTERNATE_OBJECT_DIRECTORIES`, which the author acknowledges as future work.

The implementation introduces a new helper function, `is_git_directory_verbose`, and updates existing code to use it. The accompanying tests in `t0009-git-dir-validation.sh` verify the new behavior. The series is well-motivated and addresses a real usability pain point, though it’s still marked as RFC to gather feedback on the direction. If the approach is well-received, the author plans to extend it to the remaining cases. The patches look clean and focused, with a clear scope and good test coverage.
