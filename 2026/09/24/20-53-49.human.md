This is a CI/build system patch that works around an intermittent HTTP/2 authentication failure in Git's Debian 12 CI job. The patch is the second iteration of a single-patch series by Johannes Schindelin, incorporating feedback from Jeff King to replace a hard-coded CI skip with a runtime version check.

The core issue remains the same: Debian 12's curl 7.88.1 (and versions up to 8.3.0) treats early HTTP/2 401 responses as transport errors rather than allowing authentication retries, causing `t5559.15` and `t5559.16` to fail intermittently. The new version introduces a `HAVE_CURL_HTTP2_BUG` test prerequisite that checks the curl version at runtime, skipping the affected tests for any curl between 7.88.0 and 8.3.0. This is more robust than the original CI-only workaround, as it will also skip the tests for users running the same buggy curl versions outside CI.

The patch touches only `t/t5551-http-fetch-smart.sh`, adding the version check and marking the two problematic tests with `!HAVE_CURL_HTTP2_BUG`. The implementation is minimal (using `build_option` and `awk`) and well-documented, with clear references to the upstream curl fix and the specific commit that introduced the regression. The commit message now correctly notes the bug was introduced in curl 7.88.0, not 7.88.1, and explains the trade-offs of the version-range approach.

This version addresses Junio's earlier concern about the "conservative" label in the commit message, though the version range itself is now settled. The patch looks ready for integration, as it resolves the flakiness without affecting production code or requiring a curl upgrade. The runtime check is a clear improvement over the original CI-only skip, making the workaround more general and future-proof.
