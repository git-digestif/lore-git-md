Thread identity: RFC patch series proposing improved error reporting for invalid Git repository directories when `--git-dir` is explicitly provided. Series version: v2. Originating author: Kaartic Sivaraam. Thread type: RFC patch series.

Core problem or goal: Enhance Git's error messages when rejecting a directory as a valid repository due to explicit `--git-dir` usage. The goal is to add explanatory "reason" lines to fatal errors, clarifying *why* Git considers a directory invalid (e.g., missing/unreadable `HEAD`, inaccessible object directories, or unreadable refs directories). This aims to help users diagnose misconfigurations more easily by surfacing the underlying cause directly in the error output.

Current status: Under review as an RFC v2. The series consists of four patches: (1) a preparatory style fix normalizing an `if-else` block in `setup.c` to follow project conventions, (2) a test patch adding three new test cases for error scenarios (missing `HEAD`, invalid `HEAD` symlink, invalid `GIT_OBJECT_DIRECTORY`), (3) the implementation patch introducing `is_git_directory_verbose()` and refactoring `setup.c` to append detailed failure reasons, and (4) a follow-up test patch validating the new behavior. The implementation covers explicit `--git-dir` usage and repository validation in `setup.c`, but leaves repository discovery (filesystem walking), `gitfile` handling, and `GIT_ALTERNATE_OBJECT_DIRECTORIES` unchanged. Junio C Hamano provided low-weight style reviews on the initial RFC, all of which have been addressed in v2: unnecessary subshells in tests were removed, the dead `strbuf_release()` call after `die()` was dropped, and error message assembly was revised to use a single `die()` call with format arguments. The indentation of `strbuf_addf()` calls in `setup.c` was adjusted to align with the surrounding single-line `} else {` style, with short messages on one line and longer messages split across lines with aligned arguments. The first patch in v2 is a purely stylistic refactoring of an `if-else` block in `setup.c` to adhere to the project's single-line `} else {` convention, with no behavioral changes. The second patch adds three new test cases to `t/t0009-git-dir-validation.sh` to validate the error scenarios that the implementation will handle, using `test_must_fail` with `2>stderr` to capture error output. No substantive objections to the implementation or error message design have been raised. The series remains in the RFC phase, awaiting further feedback on direction and edge-case coverage.

Key technical details:
- Files touched: `setup.c` (implementation, style fix, and refactoring), `t/t0009-git-dir-validation.sh` (tests).
- New symbols: `is_git_directory_verbose()` (helper function in `setup.c` that appends failure reasons to a caller-provided `strbuf`).
- Subsystems: Repository setup and validation.
- Behavior: Error messages for `--git-dir` failures now include explanatory "reason" lines (e.g., "cannot access object directory '/does/not/exist' set via $GIT_OBJECT_DIRECTORY", "HEAD is missing or unreadable", "HEAD is a symlink but target lives outside refs/"). The existing `is_git_directory()` API remains unchanged, preserving silent behavior for callers that do not need verbose output. The new `strbuf invalid_gitdir_reason` in `repo_discover_explicit_gitdir()` captures failure reasons and formats them into error messages via a single `die()` call with format arguments. The preparatory style fix normalizes an `if-else` block in `setup.c` to follow the project's single-line `} else {` convention. The second patch adds three new test cases to `t/t0009-git-dir-validation.sh` covering missing `HEAD`, invalid `HEAD` symlinks, and invalid `GIT_OBJECT_DIRECTORY` configurations, using `test_must_fail` with `2>stderr` to capture error output.
- On-disk format: No changes.
- Test coverage: Fifteen test cases in `t/t0009-git-dir-validation.sh` (three existing, three new in the preparatory patch, three new in the second patch, three new in the test patch, and three new in the final patch) covering edge cases for `--git-dir` validation, including missing `HEAD`, invalid `HEAD` symlinks, misconfigured `GIT_OBJECT_DIRECTORY`, and inaccessible object directories. The tests verify that "reason" lines are present and match expected patterns.
