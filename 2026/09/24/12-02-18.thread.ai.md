Thread identity: RFC patch series proposing improved error reporting for invalid Git repository directories when `--git-dir` is explicitly provided. Series version: v2 (next iteration expected to address feedback, but direction may change significantly). Originating author: Kaartic Sivaraam. Thread type: RFC patch series.

Core problem or goal: Enhance Git's error messages when rejecting a directory as a valid repository due to explicit `--git-dir` usage. The goal is to clarify *why* Git considers a directory invalid (e.g., missing/unreadable `HEAD`, inaccessible object directories) to help users diagnose misconfigurations. Junio C Hamano has raised a fundamental critique, arguing that the real user confusion stems from *which* directory Git is inspecting and *how* it was chosen (e.g., via `GIT_DIR`, auto-discovery, or `GIT_CEILING_DIRECTORIES`), rather than the specific failure reason. He suggests that reporting the inspected path and its origin (e.g., "inspecting '/path/to/dir' (from $GIT_DIR)") would be more diagnostically useful than detailed failure reasons, and that the current approach may be over-engineered for the problem.

Current status: Under review as an RFC v2, facing significant design-level pushback and pending implementation refinements or a potential rethink. The series consists of four patches: (1) a preparatory style fix in `setup.c`, (2) test additions for error scenarios, (3) the implementation introducing `is_git_directory_verbose()`, and (4) integration into `repo_discover_explicit_gitdir()`. Junio’s latest feedback questions the series’ direction, proposing that a simpler patch reporting the inspected path and its origin would address the core diagnostic need without the complexity of detailed failure reasons. Kaartic has acknowledged Patrick Steinhardt’s technical feedback and plans to address it in the next iteration, but Junio’s design critique remains unresolved and may require a significant rethink or abandonment of the current approach. No technical flaws in the implementation are raised; the critique is purely about design effectiveness and scope.

Key technical details:
- Files touched: `setup.c` (implementation, style fix, refactoring, and integration), `t/t0009-git-dir-validation.sh` (tests).
- New symbols: `is_git_directory_verbose()` (helper function in `setup.c` that appends failure reasons to a caller-provided `strbuf`).
- Subsystems: Repository setup and validation.
- Behavior: The series appends explanatory "reason:" lines to error messages for `--git-dir` failures (e.g., "reason: cannot access object directory '/does/not/exist' set via $GIT_OBJECT_DIRECTORY"). Junio’s feedback suggests an alternative approach: reporting the inspected path and its origin (e.g., "inspecting '/path/to/dir' (from $GIT_DIR)") instead of detailed failure reasons. The existing `is_git_directory()` API remains unchanged, preserving silent behavior for callers that do not need verbose output. The preparatory style fix normalizes an `if-else` block in `setup.c` to follow the project’s single-line `} else {` convention. The second patch adds three new test cases covering missing `HEAD`, invalid `HEAD` symlinks, and invalid `GIT_OBJECT_DIRECTORY` configurations. The third patch introduces `is_git_directory_verbose()`, which duplicates `is_git_directory()` logic but adds `strbuf_addf()` calls at failure points. The fourth patch integrates the verbose helper into `repo_discover_explicit_gitdir()`, appending "reason:" lines to error messages. Patrick Steinhardt’s feedback on the fourth patch suggests renaming the `strbuf` variable from `invalid_gitdir_reason` to `errbuf` and correcting a grammar nit in the commit message ("more easy" → "easier"), as well as a subjective preference for combining the "fatal:" and "reason:" lines or using an "error:" prefix.
- On-disk format: No changes.
- Test coverage: Eighteen test cases in `t/t0009-git-dir-validation.sh` (three existing, three new in the preparatory patch, three new in the second patch, three new in the third patch, and six new in the final patch) covering edge cases for `--git-dir` validation. The tests verify that "reason:" lines are present and match expected patterns, but Junio’s feedback may necessitate revisiting these expectations. Pending refinements include adding `strerror(errno)` to error messages, restructuring the implementation to avoid interleaving with `validate_headref()`, and addressing Patrick’s surface-level suggestions.

Open questions and loose ends:
- Junio’s critique raises a fundamental question: Is the series’ approach of adding detailed failure reasons the right solution, or would reporting the inspected path and its origin be more effective? This may require a significant rethink of the implementation and could supersede some of Patrick Steinhardt’s technical concerns. No response to this critique has been provided yet, and the series’ direction remains uncertain.

Junio’s feedback suggests that the current direction may not align with user needs, and the series may need to pivot or be abandoned.

These may need to be resolved if the series proceeds in its current form, but Junio’s critique may render them moot.
