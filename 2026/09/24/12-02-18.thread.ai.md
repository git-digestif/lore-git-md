Thread identity: RFC patch series proposing improved error reporting for invalid Git repository directories when `--git-dir` is explicitly provided. Series version: v2. Originating author: Kaartic Sivaraam. Thread type: RFC patch series.

Core problem or goal: Enhance Git's error messages when rejecting a directory as a valid repository due to explicit `--git-dir` usage. The goal is to add explanatory "reason" lines to fatal errors, clarifying *why* Git considers a directory invalid (e.g., missing/unreadable `HEAD`, inaccessible object directories, or unreadable refs directories). This aims to help users diagnose misconfigurations more easily by surfacing the underlying cause directly in the error output.

Current status: Under review as an RFC v2. The series is now complete with four patches: (1) a preparatory style fix normalizing an `if-else` block in `setup.c` to follow project conventions, (2) a test patch adding three new test cases for error scenarios (missing `HEAD`, invalid `HEAD` symlink, invalid `GIT_OBJECT_DIRECTORY`), (3) the implementation patch introducing `is_git_directory_verbose()` and refactoring `setup.c` to append detailed failure reasons, and (4) the final patch integrating the verbose helper into `repo_discover_explicit_gitdir()` and formatting the "reason:" lines into error messages. The implementation covers explicit `--git-dir` usage and repository validation in `setup.c`, but leaves repository discovery (filesystem walking), `gitfile` handling, and `GIT_ALTERNATE_OBJECT_DIRECTORIES` unchanged. Junio C Hamano provided low-weight style reviews on the initial RFC, all of which have been addressed in v2: unnecessary subshells in tests were removed, the dead `strbuf_release()` call after `die()` was dropped, and error message assembly was revised to use a single `die()` call with format arguments. The indentation of `strbuf_addf()` calls in `setup.c` was adjusted to align with the surrounding single-line `} else {` style, with short messages on one line and longer messages split across lines with aligned arguments. Patrick Steinhardt raised three substantive technical concerns in his review of the third patch: (1) missing `strerror(errno)` in error messages, which omits system-level context (e.g., "Permission denied") for access failures, (2) interleaving of the new `is_git_directory_verbose()` implementation with modifications to `validate_headref()`, reducing reviewability, and (3) inconsistency in error reporting, as not all error paths in the new helper include system-level details. In his final review of the fourth patch, Patrick provided two surface-level suggestions: a grammar nit in the commit message ("more easy" → "easier") and a preference for naming the `strbuf` variable `errbuf` instead of `invalid_gitdir_reason`. He also voiced a subjective concern about the two-line error message format ("fatal: ...\nreason: ..."), suggesting it might feel cleaner to combine the lines or use an "error:" prefix before "fatal:". The first patch in v2 is a purely stylistic refactoring of an `if-else` block in `setup.c` to adhere to the project's single-line `} else {` convention, with no behavioral changes. The second patch adds three new test cases to `t/t0009-git-dir-validation.sh` to validate the error scenarios that the implementation will handle, using `test_must_fail` with `2>stderr` to capture error output. The third patch introduces `is_git_directory_verbose()`, a new helper function in `setup.c` that mirrors `is_git_directory()` but appends detailed failure reasons to a caller-provided `strbuf`. The fourth patch modifies `repo_discover_explicit_gitdir()` to use the new helper, adding a `strbuf invalid_gitdir_reason` to capture failure reasons and formatting them into two-line error messages (e.g., "fatal: not a git repository: 'repo.git'\nreason: cannot access object directory '/does/not/exist' set via $GIT_OBJECT_DIRECTORY"). The existing `is_git_directory()` is refactored to call the new helper with a NULL `strbuf`, preserving its silent behavior for backward compatibility. No substantive objections to the implementation or error message design have been raised beyond Patrick's technical feedback.

Key technical details:
- Files touched: `setup.c` (implementation, style fix, refactoring, and integration), `t/t0009-git-dir-validation.sh` (tests).

- Subsystems: Repository setup and validation.
- Behavior: Error messages for `--git-dir` failures now include explanatory "reason:" lines (e.g., "cannot access object directory '/does/not/exist' set via $GIT_OBJECT_DIRECTORY", "HEAD is missing or unreadable", "HEAD is a symlink but target lives outside refs/"). The existing `is_git_directory()` API remains unchanged, preserving silent behavior for callers that do not need verbose output. The new `strbuf invalid_gitdir_reason` in `repo_discover_explicit_gitdir()` captures failure reasons and formats them into error messages via a single `die()` call with format arguments. The preparatory style fix normalizes an `if-else` block in `setup.c` to follow the project's single-line `} else {` convention. The second patch adds three new test cases to `t/t0009-git-dir-validation.sh` covering missing `HEAD`, invalid `HEAD` symlinks, and invalid `GIT_OBJECT_DIRECTORY` configurations, using `test_must_fail` with `2>stderr` to capture error output. The third patch introduces `is_git_directory_verbose()`, which duplicates the logic of `is_git_directory()` but adds `strbuf_addf()` calls at each failure point to pinpoint the exact issue (e.g., stat failures, symlink targets, or access errors). The fourth patch integrates the verbose helper into `repo_discover_explicit_gitdir()`, appending the captured reasons to the error output. The error messages are localized and follow Git’s existing conventions.
- On-disk format: No changes.
- Test coverage: Eighteen test cases in `t/t0009-git-dir-validation.sh` (three existing, three new in the preparatory patch, three new in the second patch, three new in the third patch, and six new in the final patch) covering edge cases for `--git-dir` validation, including missing `HEAD`, invalid `HEAD` symlinks, misconfigured `GIT_OBJECT_DIRECTORY`, and inaccessible object directories. The tests verify that "reason:" lines are present and match expected patterns.
