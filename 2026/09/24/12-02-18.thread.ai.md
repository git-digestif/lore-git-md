Thread identity: RFC patch series proposing improved error reporting for invalid Git repository directories when `--git-dir` is explicitly provided. Series version: v2. Originating author: Kaartic Sivaraam. Thread type: RFC patch series.

Core problem or goal: Enhance Git's error messages when rejecting a directory as a valid repository due to explicit `--git-dir` usage. The goal is to clarify *why* Git considers a directory invalid (e.g., missing/unreadable `HEAD`, inaccessible object directories) to help users diagnose misconfigurations. Junio C Hamano has raised a fundamental critique, arguing that the real user confusion stems from *which* directory Git is inspecting and *how* it was chosen (e.g., via `GIT_DIR`, auto-discovery, or `GIT_CEILING_DIRECTORIES`), rather than the specific failure reason. He suggests that reporting the inspected path and its origin would be more diagnostically useful than detailed failure reasons.

Current status: Under review as an RFC v2, but facing significant design-level pushback. The series consists of four patches: (1) a preparatory style fix in `setup.c`, (2) test additions for error scenarios, (3) the implementation introducing `is_git_directory_verbose()`, and (4) integration into `repo_discover_explicit_gitdir()`. Junio’s latest feedback questions the series’ direction, proposing that a simpler patch reporting the inspected path and its origin (e.g., "inspecting '/path/to/dir' (from $GIT_DIR)") would address the core diagnostic need without the complexity of detailed failure reasons. He notes that the current implementation already reports the path for `HEAD` failures but inconsistently omits origin context for other errors (e.g., `objects/` directory errors include "set via $GIT_OBJECT_DIRECTORY"). No technical flaws in the implementation are raised; the critique is purely about design effectiveness and scope. Patrick Steinhardt’s prior technical feedback (missing `strerror(errno)`, interleaved implementation, and inconsistent error reporting) remains unresolved, but Junio’s critique may supersede or reframe these concerns.

Key technical details:
- Files touched: `setup.c` (implementation, style fix, refactoring, and integration), `t/t0009-git-dir-validation.sh` (tests).
- New symbols: `is_git_directory_verbose()` (helper function in `setup.c` that appends failure reasons to a caller-provided `strbuf`).
- Subsystems: Repository setup and validation.
- Behavior: The series appends explanatory "reason:" lines to error messages for `--git-dir` failures (e.g., "cannot access object directory '/does/not/exist' set via $GIT_OBJECT_DIRECTORY"). Junio’s feedback suggests an alternative approach: reporting the inspected path and its origin (e.g., "inspecting '/path/to/dir' (from $GIT_DIR)") instead of detailed failure reasons. The existing `is_git_directory()` API remains unchanged, preserving silent behavior for callers that do not need verbose output. The preparatory style fix normalizes an `if-else` block in `setup.c` to follow the project’s single-line `} else {` convention. The second patch adds three new test cases covering missing `HEAD`, invalid `HEAD` symlinks, and invalid `GIT_OBJECT_DIRECTORY` configurations. The third patch introduces `is_git_directory_verbose()`, which duplicates `is_git_directory()` logic but adds `strbuf_addf()` calls at failure points. The fourth patch integrates the verbose helper into `repo_discover_explicit_gitdir()`, appending "reason:" lines to error messages.
- On-disk format: No changes.
- Test coverage: Eighteen test cases in `t/t0009-git-dir-validation.sh` (three existing, three new in the preparatory patch, three new in the second patch, three new in the third patch, and six new in the final patch) covering edge cases for `--git-dir` validation. The tests verify that "reason:" lines are present and match expected patterns, but Junio’s feedback may necessitate revisiting these expectations.

Open questions and loose ends:
- Junio’s critique raises a fundamental question: Is the series’ approach of adding detailed failure reasons the right solution, or would reporting the inspected path and its origin be more effective? This may require a significant rethink of the implementation.
- The author explicitly invited feedback on the direction before expanding coverage to remaining cases (e.g., repository discovery, `gitfile` handling, `GIT_ALTERNATE_OBJECT_DIRECTORIES`). Junio’s feedback suggests that the current direction may not align with user needs.
- Patrick Steinhardt’s unresolved technical concerns remain: (1) missing `strerror(errno)` in error messages, (2) interleaved implementation of `is_git_directory_verbose()` with `validate_headref()` modifications, and (3) inconsistency in error reporting across all paths in the new helper. These may need to be addressed if the series proceeds in its current form.
- Patrick’s surface-level suggestions (grammar nit, variable naming, and two-line error message format) are still pending.
- No substantive objections to the implementation’s correctness have been raised, but Junio’s feedback implies that the design may be over-engineered for the problem it aims to solve.
