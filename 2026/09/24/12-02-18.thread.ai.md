Thread identity: RFC patch series proposing improved error reporting for invalid Git repository directories when `--git-dir` is explicitly provided. Series version: RFC (no prior version numbers). Originating author: Kaartic Sivaraam. Thread type: RFC patch series.

Core problem or goal: Enhance Git's error messages when rejecting a directory as a valid repository due to explicit `--git-dir` usage. The goal is to add explanatory "reason" lines to fatal errors, clarifying *why* Git considers a directory invalid (e.g., missing/unreadable `HEAD`, inaccessible object directories, or unreadable refs directories). This aims to help users diagnose misconfigurations more easily by surfacing the underlying cause directly in the error output.

Current status: Under review as an RFC. The series consists of three patches: (1) a preparatory test patch verifying current behavior (updated to remove unnecessary subshells per Junio’s feedback), (2) the implementation patch introducing `is_git_directory_verbose()` and refactoring `setup.c` to append detailed failure reasons, and (3) a follow-up test patch validating the new behavior. The implementation covers both explicit `--git-dir` usage and repository discovery logic in `setup.c`, though repository discovery (filesystem walking) and `gitfile` handling remain unchanged. No merge status reported; still in early review. Junio C Hamano provided three low-weight style reviews: one on the first patch (unnecessary subshell usage in tests, now acknowledged and addressed by the author), one on the second patch (inconsistent brace placement in `setup.c`), and one on the third patch (dead code after `die()` and unconventional error message assembly). Kaartic has now addressed the third patch’s mechanical issues: the dead `strbuf_release()` call after `die()` will be removed, and the error message assembly will be revised to use a single `die()` call with format arguments, aligning with project conventions. In response to Junio’s brace placement feedback on the second patch, Kaartic proposed adjusted indentation for `strbuf_addf()` calls to better match the surrounding codebase’s single-line `} else {` style, providing examples for both short (single-line) and longer (multi-line with aligned arguments) messages. The series remains in the RFC phase, with no substantive objections raised.

Key technical details:
- Files touched: `setup.c` (implementation), `t/t0009-git-dir-validation.sh` (tests).
- New symbols: `is_git_directory_verbose()` (helper function in `setup.c` that appends failure reasons to a caller-provided `strbuf`).
- Subsystems: Repository setup and validation.
- Behavior: Error messages for `--git-dir` failures now include explanatory "reason" lines (e.g., "HEAD is missing or unreadable", "object directory is inaccessible", "HEAD is a symlink but target lives outside refs/"). The existing `is_git_directory()` API remains unchanged, preserving silent behavior for callers that do not need verbose output. The new `strbuf invalid_gitdir_reason` in `repo_discover_explicit_gitdir()` captures failure reasons and formats them into error messages. The manual assembly of error messages using `strbuf_addf()` will be replaced with a single `die()` call per project conventions. The dead `strbuf_release(&die_msg)` after `die()` will be removed. Indentation of `strbuf_addf()` calls in `setup.c` will be adjusted to align with the surrounding single-line `} else {` style, with short messages on a single line and longer messages split across lines with aligned arguments.
- On-disk format: No changes.
- Test coverage: Nine test cases in `t/t0009-git-dir-validation.sh` (3 existing + 3 new in the preparatory patch + 3 new in the final patch) covering edge cases for `--git-dir` validation, including missing `HEAD`, invalid `HEAD` symlinks, misconfigured `GIT_OBJECT_DIRECTORY`, and inaccessible object directories. The tests verify that "reason" lines are present and match expected patterns.
