Thread identity: RFC patch series proposing improved error reporting for invalid Git repository directories when `--git-dir` is explicitly provided. Series version: RFC (no prior version numbers). Originating author: Kaartic Sivaraam. Thread type: RFC patch series.

Core problem or goal: Enhance Git's error messages when rejecting a directory as a valid repository due to explicit `--git-dir` usage. The goal is to add explanatory "reason" lines to fatal errors, clarifying *why* Git considers a directory invalid (e.g., missing/unreadable `HEAD`, inaccessible object directories, or unreadable refs directories). This aims to help users diagnose misconfigurations more easily by surfacing the underlying cause directly in the error output.

Current status: Under review as an RFC. The series consists of three patches: (1) a preparatory test patch verifying current behavior, (2) the implementation patch introducing `is_git_directory_verbose()` and refactoring `setup.c` to append detailed failure reasons, and (3) a follow-up test patch validating the new behavior. The implementation now covers both explicit `--git-dir` usage and repository discovery logic in `setup.c`, though repository discovery (filesystem walking) and `gitfile` handling remain unchanged. No merge status reported; still in early review.

Key technical details:
- Files touched: `setup.c` (implementation), `t/t0009-git-dir-validation.sh` (tests).
- New symbols: `is_git_directory_verbose()` (helper function in `setup.c` that appends failure reasons to a caller-provided `strbuf`).
- Subsystems: Repository setup and validation.
- Behavior: Error messages for `--git-dir` failures now include explanatory "reason" lines (e.g., "HEAD is missing or unreadable", "object directory is inaccessible", "HEAD is a symlink but target lives outside refs/"). The existing `is_git_directory()` API remains unchanged, preserving silent behavior for callers that do not need verbose output. The new `strbuf invalid_gitdir_reason` in `repo_discover_explicit_gitdir()` captures failure reasons and formats them into error messages.
- On-disk format: No changes.
- Test coverage: Nine test cases in `t/t0009-git-dir-validation.sh` (3 existing + 3 new in the preparatory patch + 3 new in the final patch) covering edge cases for `--git-dir` validation, including missing `HEAD`, invalid `HEAD` symlinks, misconfigured `GIT_OBJECT_DIRECTORY`, and inaccessible object directories. The tests verify that "reason" lines are present and match expected patterns, though the regexes could be tightened in future iterations.
