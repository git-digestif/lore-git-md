This is a feature patch adding filtering options to the `git repo structure` command. The patch introduces flags like `--no-tags`, `--no-branches`, and similar to exclude specific reference types from the repository structure report, which is used for diagnosing performance issues caused by large objects.

The motivation is clear: the current `git repo structure` command outputs summary information for *all* references (branches, tags, remotes, etc.), but users often need to focus on a subset when troubleshooting. The patch adds an enum for structure flags, integrates them into the command's options, and modifies the `count_references` function to conditionally exclude refs based on the flags. If a ref type is excluded, its transitive dependencies are also omitted from the stats.

The implementation touches `builtin/repo.c` (core logic), `Documentation/git-repo.adoc` (usage docs), and adds a new test file `t/t1901-repo-structure.sh` to verify the filtering behavior. The patch follows Git's established pattern for disable-only flags (e.g., `--no-verify`), which simplifies the interface by avoiding affirmative counterparts like `--tags`.

This looks like a well-scoped, practical improvement. The commit message is detailed, the tests are thorough, and the change aligns with Git's existing conventions. No red flags here—just a straightforward enhancement to an existing diagnostic tool. If you care about repository introspection or performance debugging, this patch is worth a look.
