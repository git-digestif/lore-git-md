This is a documentation patch thread, specifically a commit message refinement for an already approved and queued patch improving AsciiDoc cross-references in Git's man pages. Junio C Hamano (the maintainer) and Julia Evans clarify the rationale for using the two-part AsciiDoc link form (`<<EXAMPLES,EXAMPLES>>`) instead of the short form (`<<EXAMPLES>>`). The discussion confirms that the short form can produce inconsistent output like `the section called "EXAMPLES"` or `[EXAMPLES]` in HTML, while the two-part form ensures predictable rendering as plain `EXAMPLES`. Julia acknowledges some uncertainty about the exact conditions triggering these edge cases but emphasizes the two-part form's reliability.

The patch itself remains unchanged and is still queued in `next`. This email exchange focuses solely on refining the commit message to better explain the design choice, addressing Junio's earlier request for editorial clarification. The key technical detail is the trade-off between leaving rendering to the toolchain (short form) and gaining explicit control over output (two-part form). No new technical concerns or open questions are introduced; the discussion is purely about communication clarity.

This is part of the ongoing documentation modernization effort led by Jean-Noël Avila, though the patch stands alone as a systematic improvement to cross-references across 38 man pages. The contribution is well-tested (validated by Julia and independently by Jeff King) and uncontroversial, with no further changes expected. The broader anchor style trade-off (manual vs. auto-generated anchors) remains unresolved but is not reopened here. The thread is effectively closed, pending Junio's final integration.
