This is a small feature patch for the `git-contacts` contrib script, now in its third iteration. The patch implements the conventional UNIX `-` idiom for stdin input, replacing the previous v2 behavior that implicitly read from stdin when no arguments were given and stdin was not a terminal. The new version requires the user to explicitly pass `-` as an argument (e.g., `git contacts - <patch` or `git contacts patch1 - patch3 <patch2`), which allows mixing file arguments and stdin input in a single invocation.

The change is narrowly scoped to `contrib/contacts/git-contacts`, touching only the argument-handling logic. The commit message explains the motivation: improving interoperability with external tools like `b4`, which the author is also patching in a separate effort. This version simplifies the implementation by removing the implicit stdin detection and instead using an explicit flag (`$read_from_stdin`) set when `-` is encountered. The usage comment was updated in v2 to document stdin capability, but the `-` idiom makes that change unnecessary and it has been reverted in v3.

The patch is part of a cross-project effort (linked in the commit message) and is useful on its own even if the `b4` integration is delayed. No new symbols, CLI options, or on-disk formats are introduced. The author incorporated feedback from Junio C Hamano, who suggested the `-` idiom as a refinement and did not request further changes. The patch appears well-crafted, with a clear commit message and minimal, focused changes to the code.
