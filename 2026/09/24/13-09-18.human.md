This is a CI/build system bugfix for the Git project. Karthik Nayak identifies a regression in Git's continuous integration pipelines where unit tests were not running on Windows platforms. The issue stems from a mismatch in indexing: since commit 3141df7ec4 (February 2026), both GitLab and GitHub CI workflows use one-indexed slices for Windows tests, but the unit test execution script was still checking for zero-indexed slice numbers.

The patch is a two-line change to `ci/run-test-slice.sh`, adjusting the condition from `"$1" == "0"` to `"$1" == "1"` so that unit tests run in the first slice. The commit message clearly explains the motivation and references the earlier commit that introduced the problem. This looks like a straightforward, well-motivated fix that addresses a real gap in test coverage on Windows. No controversy or follow-up discussion is apparent from the patch itself.
