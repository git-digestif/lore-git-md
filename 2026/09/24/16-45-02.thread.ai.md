Core problem or goal: Add flexible revision-based filtering to the `git repo structure` command, enabling users to include or exclude specific revisions (commits, refs, or ranges) from the repository structure report. The v2 patch replaces the v1 `--no-<reftype>` approach with Git’s standard `setup_revisions()` machinery, addressing the design critique that the original implementation was inflexible and inconsistent with Git’s idioms. The goal is uncontroversial in principle, with focus on implementation details: reachability logic, edge cases (e.g., overlapping revisions, unreachable objects), and alignment with Git’s revision-parsing conventions.

Current status: Under active review. The v2 patch implements revision-based filtering via `struct rev_info` and `setup_revisions()`, enabling arbitrary revision specifications (e.g., `git repo structure --branches --not --tags` or `git repo structure master`). The commit title has been updated from "add filtering options" to "add revision filtering support" per Kaartic Sivaraam’s suggestion. The series remains at v2; Patrick Steinhardt’s substantive review has identified open questions about commit message motivation, documentation precision, revision-parsing defaults, and test coverage. No technical feedback has been incorporated yet, as the author’s acknowledgment addressed only the commit title.

Key technical details:
- Files modified: `builtin/repo.c`, `Documentation/git-repo.adoc`, `t/t1901-repo-structure.sh`.
- New CLI syntax: Revision-based filtering using `setup_revisions()` (e.g., `git repo structure <revision>... [--not <revision>...]`).
- Behavior: The command processes all objects reachable from the included revisions unless they are exclusively reachable via the excluded revisions. This avoids the transitive dependency omission issue of v1 by focusing on reachability rather than reference types.
- Symbols: Uses `struct rev_info` and `setup_revisions()` for parsing; replaces the v1 enum-based flag system in `count_references`. The `setup_revision_opt` struct is populated with `.def = "HEAD"` and `.revarg_opt = REVARG_COMMITTISH`, which Patrick Steinhardt questions as potentially overly restrictive.
- Test coverage: Expanded to 84 lines, validating edge cases (e.g., overlapping includes/excludes, output formats like table/lines/nul). Patrick requests additional tests for filtering by trees/blobs and revision options like `--filter=object:type=blob`.
- Performance: No discussion yet of potential performance implications for large repositories with complex revision specifications.
