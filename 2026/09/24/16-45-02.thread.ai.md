Thread identity: `[PATCH] repo: add --no-<reftype> filtering options to 'git repo structure'`
Series version: v1 (single-patch series)
Originating author: Mark C. Chu-Carroll
Thread type: patch series (feature addition)

Core problem or goal: Add filtering options to the `git repo structure` command to exclude specific reference types (e.g., tags, branches, remotes, notes, stashes) from the repository structure report, enabling focused diagnostics when dealing with large objects or performance issues. The patch addresses a practical user need by allowing granular exclusion of reference types and their transitive dependencies, but the design direction is now contested.

Current status: Under active review. The initial patch introduces `--no-<reftype>` flags (e.g., `--no-tags`, `--no-branches`) to omit references and their transitive dependencies entirely from the report. Patrick Steinhardt has proposed an alternative design: filtering by arbitrary revisions (e.g., `git repo structure --branches` or `git repo structure master`) using Git’s existing revision-parsing machinery (`struct rev_info`, `setup_revisions()`), which would make the feature more flexible and consistent with commands like `git log`. The discussion now centers on whether to adopt this alternative or refine the current approach.

Key technical details:
- Files modified: `builtin/repo.c`, `Documentation/git-repo.adoc`, `t/t1901-repo-structure.sh`.
- New CLI options (current implementation): `--no-tags`, `--no-branches`, `--no-remotes`, `--no-notes`, `--no-stashes`.
- Behavior (current implementation): Excluded references and their transitive dependencies are omitted entirely from the report (not just hidden). The filtering logic is implemented in `count_references` and propagated through `stats_table_setup_structure` and `structure_keyvalue_print`.
- Symbols: New enum-based flag system in `count_references` for filtering logic.
- Proposed alternative: Use `PARSE_OPT_KEEP_UNKNOWN_OPT` to pass unrecognized arguments to `setup_revisions()`, enabling revision-based filtering (e.g., `git repo structure master`).
- Test coverage: Comprehensive, with 276 lines of tests validating edge cases (e.g., multiple simultaneous filters, output formats like table/lines/nul).

- **Transitive dependency omission**: The current design omits transitive dependencies entirely, which may be overly aggressive. Revision-based filtering would avoid this issue by focusing on reachability from specified revisions.
