Thread identity: `[PATCH] repo: add --no-<reftype> filtering options to 'git repo structure'`
Series version: v1 (single-patch series)
Originating author: Mark C. Chu-Carroll
Thread type: patch series (feature addition)

Core problem or goal: Add filtering options to the `git repo structure` command to exclude specific reference types (e.g., tags, branches, remotes, notes, stashes) from the repository structure report, enabling focused diagnostics when dealing with large objects or performance issues. The patch addresses a practical user need by allowing granular exclusion of reference types and their transitive dependencies.

Current status: Under review (initial submission). The patch introduces `--no-<reftype>` flags (e.g., `--no-tags`, `--no-branches`, `--no-remotes`, `--no-notes`, `--no-stashes`) to omit references and their transitive dependencies entirely from the report. Implementation touches `builtin/repo.c`, updates `Documentation/git-repo.adoc`, and adds 276 lines of test coverage in `t/t1901-repo-structure.sh`. The design follows Git’s established pattern for disable-only flags (e.g., `--no-verify` in `git push`).

Key technical details:
- Files modified: `builtin/repo.c`, `Documentation/git-repo.adoc`, `t/t1901-repo-structure.sh`.
- New CLI options: `--no-tags`, `--no-branches`, `--no-remotes`, `--no-notes`, `--no-stashes`.
- Behavior: Excluded references and their transitive dependencies are omitted entirely from the report (not just hidden). The filtering logic is implemented in `count_references` and propagated through `stats_table_setup_structure` and `structure_keyvalue_print`.
- Symbols: New enum-based flag system in `count_references` for filtering logic.
- Test coverage: Comprehensive, with 276 lines of tests validating edge cases (e.g., multiple simultaneous filters, output formats like table/lines/nul).

Open questions and loose ends:
- Reviewers may scrutinize the choice to omit transitive dependencies entirely (vs. hiding them from output). The rationale is that if a reference type is irrelevant to the diagnosis, its dependencies likely are too, but this design decision could draw discussion.
- Test coverage adequacy, though the volume (276 lines) suggests thoroughness.
