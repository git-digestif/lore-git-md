Core problem or goal: Add flexible revision-based filtering to the `git repo structure` command, enabling users to include or exclude specific revisions (commits, refs, or ranges) from the repository structure report. The v2 patch abandons the v1 `--no-<reftype>` approach in favor of Git’s standard `setup_revisions()` machinery, addressing the design critique that the original implementation was inflexible and inconsistent with Git’s idioms. The goal is now uncontroversial in principle, with the focus shifting to implementation details (reachability logic, edge cases, and performance implications).

Current status: Under active review. The v2 patch replaces the enum-based flag system with a `struct rev_info` and `setup_revisions()` call, enabling arbitrary revision specifications (e.g., `git repo structure --branches --not --tags` or `git repo structure master`). This aligns with Patrick Steinhardt’s proposed alternative and resolves the central design objection from v1. The series remains at v2, with no new feedback on this iteration.
