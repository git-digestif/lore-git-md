This is the first patch in a seven-part documentation series introducing `gitmergeconflicts(7)`, a new man page consolidating Git’s merge conflict resolution guidance. The patch adds the new guide itself (`Documentation/gitmergeconflicts.adoc`) and updates the build system (`Makefile`, `meson.build`) to ensure it is processed.

The new page is 294 lines long and structured as a practical, example-driven guide. It begins with a high-level overview of when merge conflicts occur (during `git merge`, `git rebase`, `git cherry-pick`, `git pull`, or `git revert`) and the two main resolution paths: fixing the conflict or aborting the operation. The core of the page explains merge conflict markers (`<<<<<<<`, `=======`, `>>>>>>>`), walks through the four-step resolution process (identify conflicts, edit files, stage changes, continue the operation), and provides concrete examples (e.g., resolving a fruit list conflict). It also documents tools for handling conflicts, such as graphical merge tools, `merge.conflictstyle=diff3`/`zdiff3`, and commands like `git show :1:filename` to inspect the common ancestor or conflicting versions. The guide clarifies terminology ("ours" vs. "theirs") and edge cases (e.g., how `git rebase` inverts the meaning of "ours" and "theirs"), and includes a section on using `git diff AUTO_MERGE` to track progress.

The content is explicitly shaped by user feedback, addressing long-standing pain points in Git’s existing documentation: inconsistent terminology, unclear references (e.g., "2" and "3" in the original `git merge` man page), cultural references (e.g., "Conflict resolution is hard; let's go shopping"), and scattered advice across multiple command pages. The guide’s tone is conversational and example-heavy, prioritizing practical workflows over technical minutiae. Key technical details, such as the difference between `diff3` and `zdiff3`, are explained with side-by-side examples, and the page includes a sample `git status` output to help users identify the correct `--abort` and `--continue` commands for their context.

This patch is purely additive and does not change any existing behavior.
