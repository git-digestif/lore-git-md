This is a meta-discussion reply in the ongoing Git version numbering thread, specifically Junio C Hamano’s response to Harald Nordgren’s proposal to include user-facing breaking changes in Git 3.0.

Junio corrects Harald’s misunderstanding of the version numbering strategy: the jump from 2.56 to 2.98 (or similar) is not just a mechanical increment but a deliberate signal to downstream projects and distributions that a major transition is coming. The purpose of the transitional version is to provide advance warning, not to serve as a placeholder for last-minute feature additions.

On Harald’s proposal to change default configuration values (e.g., enabling autostash, switching to the `histogram` diff algorithm, modifying `git status` behavior), Junio is unequivocal: it is too late for any such changes to be considered for Git 3.0. The cutoff for new design or code contributions has already passed, and these proposals do not meet the criteria for inclusion. Junio also notes that some of Harald’s suggestions may not even qualify as breaking changes, meaning they could be revisited after 3.0 without waiting for 4.0. The tone is firm but not dismissive, leaving the door open for future discussion while firmly closing it for the upcoming release.
