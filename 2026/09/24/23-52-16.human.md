This is a **build system** review comment on the final patch of SZEDER Gábor’s precompiled headers series. Jeff King (Peff) reports a **cosmetic but potentially widespread issue** with the precompiled header mechanism when target-specific `EXTRA_CPPFLAGS` are used.

The problem surfaces when building individual objects (e.g., `make imap-send.o`) with per-target flags (like `-DNO_OPENSSL` in Peff’s `config.mak`). The precompiled header (`tools/precompiled.h.gch`) is built with the global flags, but the object file is compiled with additional target-specific flags, triggering a `-Winvalid-pch` warning. While Peff’s use case (building historical versions with relaxed flags) is niche, the underlying issue — mismatched flags between the precompiled header and object files — could affect any developer using per-target `EXTRA_CPPFLAGS`.

The warning is harmless in practice (Peff’s builds still succeed), but it’s noisy and could mask real issues. The patch’s current design doesn’t account for this edge case, though the commit message does document the interaction between `-Winvalid-pch` and `EXTRA_CPPFLAGS`. No fix is proposed yet, and Peff doesn’t suggest one, but this feedback may prompt follow-up discussion or adjustments to the precompiled header logic. The series as a whole remains a well-motivated build-time optimization, but this observation highlights a potential rough edge for advanced users.
