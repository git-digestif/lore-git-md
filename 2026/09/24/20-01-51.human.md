This is the second patch in Johannes Schindelin’s four-part v2 series fixing GitLab CI breakage for Windows builds after Rust support was enabled. It addresses a silent data loss issue in the CI dependency setup script.

The patch prevents `ci/install-dependencies.ps1` from overwriting `.git/info/exclude` when the file already exists. Previously, the script used `New-Item -Force` to create the file, which truncated any existing content—including the `/git-sdk` exclusion added by `install-sdk.ps1`. This caused `ci/lib.sh` to flag SDK files as unignored build artifacts, breaking the CI pipeline. The fix checks for the file’s existence before creating it, preserving prior exclusions.

The change is minimal (three lines added, one removed) and narrowly scoped to the PowerShell script’s file-handling logic. It carries no risk of regressing Git’s core functionality since it only affects CI infrastructure. The commit message clearly explains the problem, the cause, and the solution, and the patch has already been validated in GitLab’s internal CI pipeline (MR #671, pipeline #2863888081).

This is a straightforward bugfix with no open questions or controversy. It complements the rest of the series by ensuring the CI environment remains consistent after Rust toolchain provisioning. No further review feedback is expected beyond routine surface-level checks.
