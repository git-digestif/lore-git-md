- Techniques:
  - Patch 1: Refactored HTTP sources (`http.c`, `http-walker.c`) into a dedicated static library (`libgit-curl.a`) to avoid redundant compilation (7x reduction, ~8% build speedup).
  - Patch 2: Eliminated redundant recompilation of `git-remote-http` objects for aliases (`git-remote-https`, `git-remote-ftp`, `git-remote-ftps`) by reusing the compiled executable's objects. Performance: ~1% speedup in clean build times.
  - Patch 3: Extended precompiled-header support (previously introduced for `libgit.a` in March 2026) to the test-helper executable via a one-line addition in `t/helper/meson.build` pointing to `tools/precompiled.h`. Performance: ~19% speedup (6.36s → 5.33s), the largest single-patch gain in the series.
  - Patch 4: Extended precompiled-header support to the unit-test executable (`unit-tests`) by refactoring `clar.c` into a separate static library (`libclar.a`) to avoid including `git-compat-util.h`. Performance: ~5% speedup (5.34s → 5.08s). New symbols: `libclar.a` (static library).
  - Patch 5: Fixed shell completion test failures by reverting from Meson 1.3.0’s `fs.copyfile()` to `configure_file()` in `contrib/completion/meson.build`. The issue arose because `contrib/completion` is processed after test dependencies are wired up, causing `fs.copyfile()` dependencies to be ignored during test execution. `configure_file()` ensures tests always see up-to-date completion scripts by automatically re-running when source files change.
  - Patch 6: Updated subproject `.wrap` files for curl (8.10.1→8.12.1), expat (2.7.1→2.8.4), openssl (3.0.8→3.0.10), pcre2 (10.45→10.48), and zlib (1.3.1→1.3.2) to their latest upstream versions. The patch modernizes the `[provide]` section syntax in some wrappers, switching from legacy variable-style declarations (`libcurl = libcurl_dep`) to the newer `dependency_names` list format. No behavioral changes or performance impact; purely a maintenance update for compatibility and security.
  - Patch 7: Fixed hanging MSVC jobs in GitLab CI by disabling PortableGit’s default credential helper (Git Credential Manager for Windows) after installation. The hang occurs because GitLab Runner 19.x invokes `git credential reject` during cleanup, which triggers GCM’s attempt to use Windows Credential Manager—an operation that fails and blocks indefinitely. The fix adds an explicit `git config unset --all --system credential.helper` call in `ci/install-dependencies.ps1`. The change is minimal (8 lines) and platform-specific, with no impact on non-Windows builds.
