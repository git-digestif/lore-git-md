This is the sixth patch in Julia Evans' seven-patch documentation series introducing `gitmergeconflicts(7)`, a new man page consolidating merge conflict resolution guidance. The series aims to replace scattered, duplicated advice across multiple command man pages with a single, centralized resource.

This patch updates `Documentation/git-pull.adoc` to replace a brief mention of aborting merge conflicts with a cross-reference to the new `gitmergeconflicts(7)` guide. The change is minimal: it removes one line of redundant advice (`git merge --abort` or `git rebase --abort`) and adds a link to the new guide, directing users to a more comprehensive resource. The patch touches only one file and makes no behavioral changes—it is purely a documentation refactoring.

The series as a whole is well-motivated, addressing a long-standing pain point in Git's documentation: merge conflict guidance is currently fragmented across `git merge`, `git rebase`, `git revert`, `git cherry-pick`, and `git pull`, leading to inconsistencies and omissions. Julia’s approach—centralizing this information in a new guide while preserving command-specific details (e.g., `--skip` for `git rebase`)—is a clean solution. The new guide’s example-driven structure and focus on practical workflows (e.g., `diff3`/`zdiff3` output, "ours" vs. "theirs" clarification) align with recent efforts to improve documentation clarity, such as Jean-Noël Avila’s synopsis-style conversion.
