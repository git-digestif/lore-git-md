This is a refactoring patch, part 2 of Patrick Steinhardt’s 7-patch series to simplify the `create_repository()` interface. It introduces `safe_create_leading_directories_no_share_const()`, a new helper that lets callers pass a string constant to the existing `safe_create_leading_directories_no_share()` function without forcing them to make a copy. The change is purely mechanical: the new function just delegates to the existing `_const` variant with a NULL repository pointer. No behavior changes, no new tests, and the commit message explains the motivation clearly—upcoming patches in the series will use this helper. It looks like a straightforward, uncontroversial step toward the larger goal of making repository initialization stateless.
