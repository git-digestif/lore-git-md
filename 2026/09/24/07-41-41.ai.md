This is a **test-infrastructure follow-up** in the `http.sslVerifyStatus` security feature thread. SZEDER Gábor replies to Junio C Hamano’s revert announcement with two clarifications and a documentation suggestion.

Gábor now believes the `SSL_VERIFYSTATUS` prerequisite is fundamentally sound: it only checks whether libcurl supports `CURLOPT_SSL_VERIFYSTATUS`, not whether the server is capable of stapling. Therefore, a failed `git ls-remote` (e.g., repository not found) is irrelevant to the prerequisite and should not cause it to fail. The current implementation—looking for the absence of the string “http.sslVerifyStatus is set” in the error message—is technically correct, but Gábor finds the error message misleading. He suggests two improvements: (1) change the prerequisite’s string match to look for the absence of “could not enable OCSP status verification” (the second half of the error message), which is clearer, and (2) rename the prerequisite from `SSL_VERIFYSTATUS` to `CURL_SSL_VERIFYSTATUS` to better reflect its scope (libcurl support, not server support).

The thread remains focused on test infrastructure; no new technical issues with the core `http.sslVerifyStatus` feature are raised. The next step is a follow-up patch that tightens the prerequisite’s error-message check and renames it.
