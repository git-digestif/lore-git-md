This thread is an RFC patch series by Kaartic Sivaraam proposing improved error reporting for invalid Git repository directories when `--git-dir` is explicitly provided. The goal is to clarify why Git rejects a directory (e.g., missing `HEAD` or inaccessible object directories) to help users diagnose misconfigurations. However, Junio C Hamano has raised a fundamental critique, arguing that the real confusion stems from *which* directory Git is inspecting and *how* it was chosen (e.g., via `GIT_DIR` or auto-discovery), rather than the specific failure reason. He suggests a simpler approach: reporting the inspected path and its origin (e.g., "inspecting '/path/to/dir' (from $GIT_DIR)") would be more diagnostically useful.

The series is currently at v2 and under review, with no technical flaws identified but significant design-level pushback. The latest patch integrates the new `is_git_directory_verbose()` helper into `repo_discover_explicit_gitdir()` to append explanatory "reason:" lines to error messages. Patrick Steinhardt reviewed this patch, offering only surface-level suggestions (grammar, variable naming, and error message formatting), which Kaartic plans to address in the next iteration. However, Junio’s broader critique remains unresolved and may require a substantial rethink of the series’ direction before further work proceeds. The implementation touches `setup.c` and adds test coverage but does not alter on-disk formats or existing APIs. Key open questions include whether the current approach aligns with user needs and how to reconcile Junio’s alternative proposal with the series’ goals.
