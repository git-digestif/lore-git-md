This thread is about an RFC patch series (v3) by Kaartic Sivaraam that improves Git’s error messages when it cannot find a valid repository. The series has pivoted from explaining *why* a directory is invalid to reporting *which* directory Git inspected and *where* it came from—such as via `--git-dir`, `GIT_DIR`, repository discovery, or `GIT_OBJECT_DIRECTORY`. This change addresses Junio C Hamano’s feedback that users are primarily confused about the inspected path and its origin, not the specific failure reason.

The first two patches in the series were preparatory: a minor stylistic refactoring in `setup.c` and expanded test coverage in `t/t0009-git-dir-validation.sh`. The third patch, just posted, focuses on improving error messages for explicitly specified directories (via `--git-dir` or `GIT_DIR`). Instead of a generic "fatal: not a git repository: 'project.git'", the error now includes a hint like "this path was taken from $GIT_DIR (which can also be set with --git-dir or --bare)". This change is minimal, touching only one `die()` call in `setup.c` and updating two tests to verify the new hint. The implementation is clean, using a single translatable string with a `TRANSLATORS` comment for placeholders.

The series is under review, with no substantive objections raised so far. Junio’s critique of the v2 approach has been addressed, and the new direction aligns with his suggestion. Patrick Steinhardt’s earlier technical feedback on v2 is now moot due to the pivot. The remaining patches will handle repository discovery and `GIT_OBJECT_DIRECTORY` cases, while edge cases like `gitfile` and `GIT_ALTERNATE_OBJECT_DIRECTORIES` are deferred to future work. If the series lands, it will significantly improve usability for common misconfigurations.
