This thread is an RFC patch series from Kaartic Sivaraam proposing clearer error messages when Git rejects a directory specified via `--git-dir`. The goal is to help users diagnose misconfigurations by appending explanatory "reason" lines to fatal errors—for example, why a directory is deemed invalid (e.g., missing `HEAD`, inaccessible object directories, or unreadable refs).

The series consists of three patches: a preparatory test patch, the implementation introducing `is_git_directory_verbose()` in `setup.c`, and a follow-up test patch. The implementation covers explicit `--git-dir` usage but leaves repository discovery and `gitfile` handling unchanged. Junio C Hamano’s review so far has been limited to stylistic nitpicks (indentation and brace placement) in the second patch, with no substantive objections to the design or error-message clarity. The series remains in early review, awaiting broader feedback on edge-case coverage (e.g., `GIT_ALTERNATE_OBJECT_DIRECTORIES`) before further revisions. No merge status has been reported.
