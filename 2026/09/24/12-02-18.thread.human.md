This thread is an RFC patch series by Kaartic Sivaraam proposing clearer error messages when Git rejects a directory specified via `--git-dir`. The goal is to help users diagnose misconfigurations by appending explanatory "reason" lines to fatal errors (e.g., "HEAD is missing or unreadable"). The series consists of three patches: a preparatory test patch, the implementation introducing `is_git_directory_verbose()` in `setup.c`, and a follow-up test patch.

So far, Junio C Hamano has provided three rounds of low-weight feedback—first on test design (unnecessary subshell usage), then on brace placement in `setup.c`, and now on a bug in the third patch: a `strbuf_release(&die_msg)` call after `die()` that can never execute, along with a suggestion to simplify error message construction using a single `die()` call with format arguments. Kaartic has not yet responded to these style notes, and the series remains in the RFC phase, awaiting broader feedback on its direction and edge-case coverage (e.g., `GIT_ALTERNATE_OBJECT_DIRECTORIES`). No substantive objections to the implementation or error message design have been raised.
