This thread is an RFC patch series from Kaartic Sivaraam proposing clearer error messages when Git rejects a directory specified via `--git-dir`. The goal is to help users diagnose misconfigurations by surfacing the *reason* for rejection—such as a missing `HEAD` file, an inaccessible object directory, or an invalid refs directory—directly in the error output.

The series is now two-thirds complete: the first patch added preparatory tests, and this latest email introduces the core implementation. The new `is_git_directory_verbose()` helper in `setup.c` mirrors the existing `is_git_directory()` but appends explanatory failure reasons to a caller-provided buffer. The original function is refactored to delegate to the new helper while preserving its silent behavior, ensuring backward compatibility. The error messages are specific and actionable—for example, "cannot access object directory '/path/to/objects'"—without exposing internal details. The third patch, still to come, will update call sites to use the new helper.

No substantive review feedback has arrived yet, and the series remains in the "request for comments" phase. The author is explicitly seeking feedback on the approach before expanding coverage to repository discovery, `gitfile` handling, or `GIT_ALTERNATE_OBJECT_DIRECTORIES`. If the direction is approved, this could significantly improve usability for users debugging repository setup issues.
