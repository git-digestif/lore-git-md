This thread is an RFC patch series from Kaartic Sivaraam proposing clearer error messages when Git rejects a directory specified via `--git-dir`. The series is now complete at version 2, with four patches that refactor `setup.c` and add tests to show why a directory is invalid—such as a missing `HEAD` file, an unreadable object directory, or a broken symlink. The final patch ties everything together by appending a "reason:" line to the familiar "not a git repository" error, so users see both the symptom and the cause in one message.

Junio C Hamano reviewed the initial RFC and suggested minor style and test cleanups, all of which Kaartic addressed in v2. No substantive objections have surfaced; the discussion is still in the RFC phase, waiting for broader feedback on whether the direction is right before tackling additional cases like repository discovery or `GIT_ALTERNATE_OBJECT_DIRECTORIES`. The implementation is deliberately narrow, touching only the explicit `--git-dir` code path, and preserves backward compatibility by keeping the original `is_git_directory()` API unchanged.
