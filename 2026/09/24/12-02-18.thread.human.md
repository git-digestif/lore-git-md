This thread is an RFC patch series by Kaartic Sivaraam proposing improved error reporting for invalid Git repository directories when `--git-dir` is explicitly provided. The goal is to enhance Git's error messages by adding explanatory "reason" lines that clarify why a directory is rejected (e.g., missing `HEAD`, inaccessible object directories, or unreadable refs directories). The series is now at v2, consisting of four patches: a preparatory style fix, new test cases, the implementation introducing `is_git_directory_verbose()`, and integration into `repo_discover_explicit_gitdir()`.

Junio C Hamano provided minor style feedback on the initial RFC, all of which has been addressed in v2. Patrick Steinhardt raised three technical concerns in his review of the third patch—missing `strerror(errno)` in error messages, interleaved implementation reducing reviewability, and inconsistent error reporting—but these remain unresolved. In his latest review, Patrick offered cosmetic suggestions (grammar, variable naming, and error message formatting) but explicitly endorsed the motivation and did not contest the implementation. The series is still in the RFC phase, with the author seeking feedback on whether to expand coverage to other cases like repository discovery or `GIT_ALTERNATE_OBJECT_DIRECTORIES`. No substantive objections to the design or error message clarity have been raised beyond Patrick's technical feedback.
