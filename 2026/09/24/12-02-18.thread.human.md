This thread is about an RFC patch series (v3) by Kaartic Sivaraam that improves Git's error messages when it cannot find a valid repository. Instead of explaining why a directory is invalid, the series now reports *which* directory Git inspected and *where* it came from—such as `--git-dir`, `GIT_DIR`, repository discovery, or `GIT_OBJECT_DIRECTORY`. This change addresses Junio C Hamano’s feedback that users are primarily confused about the inspected path’s origin rather than the specific failure reason.

The series is now complete, with all five patches posted. The first two patches were preparatory: a minor stylistic refactoring in `setup.c` and expanded test coverage in `t/t0009-git-dir-validation.sh`. The third and fourth patches added diagnostic context for explicitly specified directories and repository discovery with `GIT_CEILING_DIRECTORIES`, respectively. This latest patch, the fifth, finalizes the series by handling cases where `GIT_OBJECT_DIRECTORY` points to an unusable directory, appending a clear explanation to the error message (e.g., "cannot access object directory '/tmp/git-objects' set via $GIT_OBJECT_DIRECTORY: No such file or directory"). The implementation is straightforward, with a helper function in `setup.c` and additional test coverage.

No substantive objections have been raised, and the series aligns with Junio’s earlier critique. The author has explicitly deferred handling of `gitfile` (submodules/worktrees), `GIT_ALTERNATE_OBJECT_DIRECTORIES`, and edge cases like irrelevant `GIT_CEILING_DIRECTORIES` entries for future work. The series is now ready for review, with thorough test coverage for the core scenarios. Key participants include Junio, who shaped the direction, and Patrick Steinhardt, whose earlier feedback on v2 is now moot due to the redesign.
