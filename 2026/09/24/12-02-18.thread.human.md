This thread is an RFC patch series from Kaartic Sivaraam proposing clearer error messages when Git rejects a directory as a valid repository after an explicit `--git-dir` is provided. The goal is to help users diagnose misconfigurations by surfacing the underlying reason (e.g., missing `HEAD`, inaccessible object directories) directly in the error output.

The series is now complete with three patches: a preparatory test patch, the core implementation introducing `is_git_directory_verbose()` in `setup.c`, and this final patch updating repository discovery logic to use the new helper and append explanatory "reason" lines to fatal errors. The implementation is narrowly scoped to explicit `--git-dir` usage, leaving repository discovery and `gitfile` handling unchanged. Tests verify the enhanced error messages cover edge cases like missing `HEAD` or misconfigured `GIT_OBJECT_DIRECTORY`.

No substantive review feedback has arrived yet, and the series remains in the "request for comments" phase. The author has explicitly invited discussion on the direction before expanding coverage to other cases like `GIT_ALTERNATE_OBJECT_DIRECTORIES`. The patches are additive and preserve backward compatibility, so objections are unlikely, but the clarity of error messages and edge-case coverage may draw attention. If well-received, this could significantly improve the debugging experience for repository setup issues.
