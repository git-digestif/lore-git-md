This is a small but useful feature patch for the `git-contacts` contrib script, now in its final review stage. Junio C Hamano, the maintainer, replies to Brigham Campbell’s v3 submission with a minor technical suggestion about the implementation.

The patch itself extends `git-contacts` to accept patch input from stdin using the conventional UNIX `-` idiom, enabling mixed file/stdin usage (e.g., `git contacts patch1 - patch3 <patch2`). This replaces the v2 behavior, which implicitly read from stdin when no arguments were given and stdin was not a terminal. The feature is motivated by improved interoperability with external tools like `b4`, though it stands on its own.

Junio’s feedback focuses on the argument-handling logic. He suggests a cleaner approach: treat `-` as just another filename in the `@files` array, then handle the stdin case inside `scan_patch_file` rather than introducing a separate `$read_from_stdin` flag. This would simplify the control flow and align more closely with how other Git commands handle stdin. The change is purely internal and does not affect the user-facing behavior.

The patch is well-motivated, narrowly scoped, and has already incorporated earlier stylistic feedback. Junio has not raised any functional objections, and this latest suggestion is a refinement rather than a blocker. Once addressed, the patch looks ready to merge. It touches only `contrib/contacts/git-contacts` and introduces no new symbols or on-disk format changes.
