This is an RFC patch series proposing improved error reporting for cases where Git rejects a directory as a valid repository. The series adds explanatory "reason" lines to fatal errors when `--git-dir` is explicitly provided, covering scenarios like missing or unreadable `HEAD`, inaccessible object directories (including those set via `GIT_OBJECT_DIRECTORY`), and unreadable refs directories. The goal is to help users diagnose misconfigurations more easily by clarifying *why* Git considers a directory invalid, rather than just stating that it is.

The series introduces a new helper function `is_git_directory_verbose()` in `setup.c` and updates existing validation logic to use it. Three new test cases in `t/t0009-git-dir-validation.sh` verify the enhanced error messages. The implementation is limited to explicit `--git-dir` usage for now; cases like repository discovery (walking up the filesystem) and `gitfile` handling (submodules/worktrees) are left unchanged, as are errors from `GIT_ALTERNATE_OBJECT_DIRECTORIES`, which the author notes require separate treatment.

The motivation is clear: current error messages can be misleading (e.g., blaming the repository directory when the issue is an invalid `GIT_OBJECT_DIRECTORY`). The proposed changes address this by surfacing the underlying cause directly in the error output. The patch touches core repository setup code, so correctness is critical, but the scope is narrowly focused on error reporting rather than behavior changes.

The series is marked RFC, and the author explicitly invites feedback on the direction before expanding coverage to the remaining cases. The implementation looks clean and well-scoped, with thorough test coverage for the new functionality. If the approach is well-received, this could meaningfully improve usability for users debugging repository setup issues.
