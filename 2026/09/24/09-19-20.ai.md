This is the second patch in Patrick Steinhardt’s seven-patch series refactoring `create_repository()` to enforce stateless input. It introduces `safe_create_leading_directories_no_share_const()`, a variant of the existing `safe_create_leading_directories_no_share()` that accepts a `const char *path` instead of a mutable string. The change is purely mechanical: the new function delegates to the existing `safe_create_leading_directories_const()` with a `NULL` repository parameter, matching the behavior of its non-const counterpart.

The patch touches only `path.c` and `path.h`, adding the function declaration and a six-line definition. No callers are converted yet; those appear in later patches. The motivation is to support upcoming changes in `git init` and `git clone` that will need to create leading directories without applying shared-repository permissions, while avoiding in-place string modification of constant paths. The commit message acknowledges the dubious value of the existing optimization (in-place modification to avoid allocation) but defers any broader cleanup.

This is a straightforward plumbing addition with no behavior change. The patch is well-scoped and uncontroversial, serving as a prerequisite for the interface simplification that follows. Future discussion is likely to focus on the callers introduced in patches 3 and 4 rather than this helper itself. Key names: `safe_create_leading_directories_no_share_const()`, `path.c`, `path.h`.
