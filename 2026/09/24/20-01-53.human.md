This is the final patch in a four-part CI/build system series from Johannes Schindelin, fixing GitLab CI breakage for Windows builds after Rust support was enabled. The series as a whole restores pipeline functionality by addressing Rust toolchain provisioning, `.git/info/exclude` data loss, and `cargo` accessibility.

This specific patch ensures the GNU Rust toolchain’s host-linker support is available for MinGW builds. The change is minimal: it adds the `Gcc` feature to Rust’s MSI installer when the `-Mingw` switch is used, ensuring the linker (`x86_64-w64-mingw32-gcc`) is available for host executables like `build.rs`. The commit message clarifies that this does not install a redundant GCC toolchain—it only ensures compatibility with the existing MinGW-provided GCC. The fix addresses a specific failure in GitLab job #16593470275, where `build.rs` linking failed due to the missing linker.

The patch is narrowly scoped to GitLab’s CI infrastructure and has no impact on Git’s core behavior or other platforms. It builds on earlier patches in the series, which introduced the `-Mingw` switch and adjusted `PATH` to make `cargo` accessible. The reworded commit messages in v2 (of which this is part) resolve earlier confusion about the "GNU Rust" toolchain and the `Gcc` feature’s purpose.

Review feedback from v1 has been addressed, and Karthik Nayak’s internal GitLab validation confirms the series fixes the original breakage. No technical objections remain, and the patch appears well-motivated and correct. The series is ready for integration, though no maintainer decision has been announced yet.
