This is a review comment on the first patch of Julia Evans' seven-part documentation series introducing `gitmergeconflicts(7)`. Junio C Hamano points out a mechanical oversight: the patch adds the new man page to `Documentation/Makefile` but omits the corresponding update to `Documentation/meson.build`, which is needed for the Meson build system. He suggests folding the `.gitattributes` conflict-marker-size setting (currently planned as the final patch in the series) into this patch to avoid treating it as an afterthought.

The feedback is surface-level and purely about build system consistency. It does not engage with the content or structure of the new guide, nor does it question the series' overall goal. The requested change is straightforward and unlikely to be controversial. The review does not affect the series' core value—centralizing merge conflict resolution guidance—but ensures the new man page is properly integrated into both build systems from the start.
