This is a **substantive review** of the first patch in Mark C. Chu-Carroll’s test modernization series. Junio C Hamano critiques the mechanical conversion of `t4001-diff-rename.sh` and `t4009-diff-rename-4.sh` to modern test syntax, arguing that the patch stops short of true modernization by preserving outdated test structure.

The review highlights three key shortcomings in the patch’s approach:
1. **Indentation and block structure**: While the patch converts multi-line `test_expect_success` blocks to single-quoted strings, it fails to reindent the test bodies with a single tab, a modern style requirement.
2. **Logical test boundaries**: The patch retains overly granular test steps (e.g., separate blocks for `update-index --add`, `write-tree`, and `diff-index`), which Junio argues obscure the test’s actual purpose—validating rename detection. Modern style favors grouping related steps into a single logical test.
3. **Naming conventions**: The patch preserves legacy filenames (`current`/`expected`) and comparison order (`compare_diff_patch current expected`), whereas modern style uses `actual`/`expect` and compares in the order `expect actual`.

Junio provides a counterexample diff that demonstrates a more thorough modernization: collapsing the setup and rename/edit steps into a single `test_expect_success` block, renaming output files to `actual`/`expect`, and reordering the comparison. His version reduces the patch’s line count from 31 to 11 while improving clarity.

The review is constructive but firm, suggesting the series needs rework to align with Git’s current testing philosophy. This feedback elevates the discussion beyond surface-level syntax to the *design* of tests, making it a substantive critique rather than a nitpick. The author will likely need to revise the series to address these points before it can proceed.
