This is the v4 iteration of Andrew Pleeter’s patch series extending `git var` to expose broken-down identity components (name, email, date for both author and committer), a resolved commit signing key (`GIT_SIGNING_KEY`), support for multiple variable arguments in a single invocation, and NUL-terminated output via the `-z` flag. The patch is part of the ongoing effort to provide a unified, scriptable interface for Git’s identity and signing configuration, replacing the earlier `git ident` proposal.

Key changes since v3:
- Renamed `GIT_DEFAULT_KEY` to `GIT_SIGNING_KEY` and dropped the alias mechanism; the variable now resolves the key that would be used for a commit regardless of `commit.gpgsign` status, addressing feedback from Junio C Hamano and Phillip Wood.
- Adopted `parse_options()` with `PARSE_OPT_STOP_AT_NON_OPTION` to strictly enforce that options (e.g., `-z`) precede variable arguments, preventing ambiguous invocations like `git var GIT_AUTHOR_NAME -z`.
- Aligned the `-z` output format with `git config -z` (key\nvalue\0) to avoid ambiguity when keys (e.g., signing keys) contain `=` characters. Multi-valued variables (e.g., `GIT_CONFIG_GLOBAL`) are delimited with NUL bytes under `-z`.
- Replaced the `char` parameter in `ident_part()` with an `enum ident_part` for type safety and clarity.
- Reworded variable descriptions in the documentation to remove legacy phrasing ("of a piece of code") and split the synopsis into separate lines for `-l` and `<variable>...` invocations.
- Added comprehensive tests covering `-z` output format, multi-valued variables, and argument ordering.

The patch touches `builtin/var.c`, `Documentation/git-var.adoc`, and `t/t0007-git-var.sh`, introducing no new configuration options or on-disk format changes. It maintains backwards compatibility with existing `git var` usage, though scripts relying on the current output format may need updates for `-z` mode. The implementation is now table-driven for variable handling and uses Git’s standard argument parsing infrastructure, addressing prior feedback about code structure and usability.

This revision directly addresses all substantive review points from Junio and Phillip Wood, including output format ambiguity, argument parsing, and the utility of the signing key variable. The patch is now focused on code-level polish and is likely to be merged once the remaining mechanical improvements (e.g., shorter lines, clarifying comments) are addressed. The series remains in `seen` and is not yet merged.
