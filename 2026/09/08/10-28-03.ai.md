This is the v3 cover letter for a three-patch series targeting the sequencer subsystem. The series is now technically complete and addresses all prior feedback from Phillip Wood, Patrick Steinhardt, and Junio C Hamano. The goal is to adjust when auto maintenance runs during sequencer-driven operations (`git rebase`, `git cherry-pick`, `git revert`) so that it defers until sequence completion, matching the apply backend’s behavior.

The key design change in v3 is moving the `run_auto_maintenance()` call out of the sequencer and into the built-in commands (`run_specific_rebase()` in `builtin/rebase.c` and `run_sequencer()` in `builtin/revert.c`). This consolidates maintenance into a single exit path per command, aligning with the apply backend’s design and Patrick Steinhardt’s preference for a unified exit path. The redundant `gc.auto=0` setting has been removed, simplifying the config string to `maintenance.auto=false` only, as Git’s maintenance infrastructure now exclusively uses `git maintenance`.

The series touches `sequencer.c`, `config.c`, `config.h`, `builtin/rebase.c`, `builtin/revert.c`, and test files `t/t3418-rebase-continue.sh` and `t/t3510-cherry-pick-sequence.sh`. New symbols include `git_config_append_parameter()` (a helper for building `GIT_CONFIG_PARAMETERS` strings with proper shell quoting) and `disable_auto_maintenance()` (a helper that caches the config string in `replay_ctx` as a `const char *`). Test coverage has been expanded to verify that auto maintenance runs exactly once at sequence completion and not during intermediate steps, covering single-pick, multi-pick, conflict-resolution, and exec scenarios.

The only remaining prerequisite for merging is a v4 with revised commit messages that explicitly justify the design choice of delegating maintenance to callers and ensure they read as human-written. Patrick Steinhardt’s concerns about LLM-generated messages lacking meaningful context must be addressed. The series is otherwise ready for merging, with no open technical objections. The edge case about very long sequences where mid-sequence repacking might improve performance is noted as a watch item but not a blocker.
