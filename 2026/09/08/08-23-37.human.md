This is a bugfix report targeting the `git bundle` command. Peter Elmers describes a reproducible regression: when `git bundle create` is run with bitmaps enabled, it can omit a tree object that is required by an advertised ref, even though the bundle declares no prerequisites for that object. The recipient can verify and unbundle successfully but then cannot traverse the commit graph because the tree is missing.

The reproduction script is thorough: it creates two sibling commits sharing the same root tree, stores one in a local branch and the other in a remote-tracking ref, writes a pack bitmap, and then creates a bundle that includes only the local branch. The bundle advertises the local commit but silently drops the shared tree, causing `git cat-file` to fail after unbundle. Disabling bitmaps (`-c pack.useBitmaps=false`) works around the issue; the boundary-traversal setting (`pack.useBitmapBoundaryTraversal=true`) does not.

The report is clear, self-contained, and includes system information. It looks like a genuine bitmap-format bug rather than a user error.
