This is the second patch in Patrick Steinhardt’s 9-patch series refactoring how Git handles ODB alternates during repository creation, part of the broader ODB abstraction effort. The patch defers object database (ODB) initialization in `git clone` until after the clone source URI is resolved, addressing two key issues: forward compatibility with future ODB backends (which may require object hash information at creation time) and the need to resolve alternates paths before ODB setup.

The change is mechanical but foundational. It moves the `create_object_database()` call in `cmd_clone()` to occur after URI resolution and transport setup, ensuring alternates can be written with full context. The patch also defers `setup_reference()`—which configures alternates—until after ODB creation, as this function depends on the ODB being initialized. The diff touches only `builtin/clone.c`, shifting four lines of code to a later point in the function. No new symbols or behavior changes are introduced; this is purely a reordering to prepare for later patches.

Justin Tobler’s review confirms the patch’s purpose: it’s a structural change in preparation for writing alternates during ODB creation (via `odb_create_on_disk_options`) in a subsequent patch. The review is brief but substantive, acknowledging the patch’s role in the series’ broader design. The change is uncontroversial and appears well-motivated, though reviewers may verify that the reordering doesn’t introduce regressions in edge cases (e.g., template config rewriting URIs).

This patch directly addresses feedback from v2, where Justin noted the growing complexity of `init_db()`’s skip flags. By deferring ODB setup, Patrick’s refactoring avoids the need for additional flags and aligns with the series’ goal of simplifying repository initialization. The patch is a necessary stepping stone for the lockfile-based alternates writing in patch 7.
