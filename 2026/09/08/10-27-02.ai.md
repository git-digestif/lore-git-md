This is the second patch in the v8 series introducing the `receive-report` hook, a refactoring that replaces static variables tracking the report status version with an explicit `enum report_status_version`. The patch is purely internal and makes no user-visible behavior changes, but it addresses Junio C Hamano’s maintainability concern about the previous boolean-based approach (`report_status` and `report_status_v2` static variables) by introducing a more explicit and extensible mechanism.

The patch defines a new `enum report_status_version` with three values: `REPORT_STATUS_UNKNOWN`, `REPORT_STATUS_V0`, and `REPORT_STATUS_V2`. The `REPORT_STATUS_UNKNOWN` sentinel value triggers a `BUG()` if neither v0 nor v2 is set, ensuring the protocol version is always explicitly initialized. The static variables `report_status` and `report_status_v2` are removed, and the `read_head_info()` function is updated to take an `enum report_status_version *` parameter, which it populates based on the client’s feature requests. The `if/else` chain in `cmd_receive_pack()` that previously checked the static variables is replaced with a `switch` statement over the enum, addressing Patrick Steinhardt’s subjective preference for this style.

The patch also fixes a typo in the enum’s sentinel value (`REPORT_STATUS_UNKOWN` → `REPORT_STATUS_UNKNOWN`), which was identified by Junio in the v7 review and acknowledged by Karthik in the follow-up email. The change is mechanical and low-risk, touching only the `builtin/receive-pack.c` file. The commit message credits Junio with a `Helped-by` for the enum refactoring, and the patch is part of a larger effort to prepare the codebase for the upcoming `receive-report` hook implementation by making the protocol-version switch more explicit.

This patch is a prerequisite for the core hook implementation (patch 4/4) and the unified `generate_report()` helper (patch 3/4), as it centralizes the protocol-version logic and eliminates redundancy. The series is queued in `next`, and this patch has no outstanding review concerns. The enum-based approach is a clear improvement over the static variables, as it makes the mutually exclusive nature of the protocol versions explicit and reduces the risk of inconsistent state.
