This is the third patch in a three-patch series (v3) that completes the effort to defer auto maintenance until sequencer-driven operations (`git rebase`, `git cherry-pick`, `git revert`) finish. The series is now technically ready for merging, pending only commit message polish in v4.

This patch disables auto maintenance in all commands spawned by the sequencer—`git commit`, `git merge`, and any command run via `exec`—by passing `maintenance.auto=false` through `GIT_CONFIG_PARAMETERS`. The config string is built once, cached in `replay_ctx` as a `const char *`, and appended to the environment of every spawned command. This prevents maintenance from running in the background during intermediate steps, avoiding lock contention (e.g., `MERGE_RR.lock` with rerere) and race conditions where maintenance might delete packs the sequencer still has open. The patch also updates tests in `t/t3418-rebase-continue.sh` and `t/t3510-cherry-pick-sequence.sh` to verify that auto maintenance runs exactly once at sequence completion and not during intermediate steps, using `GIT_TRACE2_EVENT` to assert the absence of maintenance during conflict resolution and exec commands.

The implementation introduces a new helper, `disable_auto_maintenance()`, in `sequencer.c` that builds the config string using the reusable `git_config_append_parameter()` helper (added in patch 1) and caches it in `replay_ctx`. The environment variable is set for every spawned command, including those run via `exec`, ensuring consistent behavior across all sequencer operations. The patch also removes the redundant `gc.auto=0` setting, as Git’s maintenance infrastructure now exclusively uses `git maintenance` (which respects `maintenance.auto`).

The commit message explicitly justifies the design choice of disabling maintenance in spawned commands to avoid interference, notes edge cases (e.g., `MERGE_RR.lock` with rerere), and clarifies that user-initiated commands (e.g., `git commit --amend` during an edit) are unaffected. The message also addresses Patrick Steinhardt’s concerns about LLM-generated phrasing by removing the "Claude Fable 5.1" assisted-by credit and ensuring the text reads as human-written.
