Thread identity
Subject: `git bundle` with bitmaps omits required tree object
Series version: standalone bug report (no patch series)
Originating author: Peter Elmers <peter.elmers@databricks.com>
Thread type: bug report

Core problem or goal
When `git bundle create` is run with bitmaps enabled, the resulting bundle may omit tree objects that are required by advertised refs, even though the bundle passes verification (`git bundle verify`) and can be successfully unbundled. The missing tree prevents the recipient from accessing the tree of an advertised commit, breaking workflows that rely on bundles for offline transport or backup.

Current status
Reported; no patches or fixes proposed yet. The issue is confirmed to be specific to bitmap traversal: disabling bitmaps (`-c pack.useBitmaps=false`) produces a correct bundle that includes all required objects. The `pack.useBitmapBoundaryTraversal` configuration does not mitigate the problem.

Key technical details
- Subsystem: `git bundle`, pack-objects, bitmap traversal
- Files touched: none yet (bug report only)
- New/renamed symbols: none
- Behavior: with bitmaps enabled, `git bundle create` omits a tree object (`shared_tree`) that is required by an advertised commit (`local_tip`), despite the tree being reachable from the commit and not excluded by the bundle's refspec
- On-disk format: bundles are self-contained, so missing objects are a functional regression
- Test coverage: reproduction script provided in the report; no existing test in the Git test suite covers this scenario

Open questions and loose ends
- Root cause: why does bitmap traversal omit `shared_tree` when it is reachable from `local_tip` and not excluded by the bundle's refspec?
- Scope: does the bug affect other object types (blobs, commits) or only trees?
- Workaround: disabling bitmaps is effective but may impact performance for large repositories
- Fix: no proposed solution yet; likely requires changes to the bitmap traversal logic in `pack-objects.c`
