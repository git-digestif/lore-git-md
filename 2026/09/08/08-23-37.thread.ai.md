Thread identity
Subject: `git bundle` with bitmaps omits required tree object
Series version: standalone bug report, now with proposed fix (v1)
Originating author: Peter Elmers <peter.elmers@databricks.com>
Thread type: bug report and fix

Core problem or goal
When `git bundle create` is run with bitmaps enabled, the resulting bundle may omit tree objects that are required by advertised refs, even though the bundle passes verification and can be unbundled. The missing tree prevents the recipient from accessing the tree of an advertised commit, breaking workflows that rely on bundles for offline transport or backup.

Current status
A fix has been proposed by Taylor Blau. The patch restricts pack "haves" to only those UNINTERESTING commits marked as BOUNDARY (i.e., prerequisites recorded in the bundle header), aligning the pack-objects traversal with the bundle's advertised prerequisites. The fix is lightly tested and includes a new test case that directly verifies the reported issue is resolved. The patch also updates an existing test to reflect the correct object count when no prerequisites are recorded. No substantive review feedback has been incorporated yet.

Key technical details
- Subsystem: `git bundle`, pack-objects, bitmap traversal
- Files touched: `bundle.c`, `t/t6020-bundle-misc.sh`
- New/renamed symbols: none
- Behavior: with bitmaps enabled, `git bundle create` previously omitted a tree object (`shared_tree`) that is required by an advertised commit (`local_tip`), despite the tree being reachable from the commit and not excluded by the bundle's refspec. The fix ensures all objects required by advertised refs are included.
- On-disk format: bundles remain self-contained; the fix addresses the functional regression without altering the bundle format.
- Test coverage: reproduction script provided in the original report; new test case (`bundle with bitmaps includes trees shared with an excluded sibling`) verifies the fix. Updated test (`create bundle 4 - with tags`) reflects correct object count when no prerequisites are recorded.

Open questions and loose ends
- Root cause: confirmed as a mismatch between pack "haves" (all UNINTERESTING objects) and bundle prerequisites (only BOUNDARY commits). The fix resolves this but may have edge cases in test compatibility, particularly for bundles including tags but excluding branch tips.
- Scope: still unknown whether the bug affects other object types (blobs, commits) or only trees.
- Workaround: disabling bitmaps remains effective but may impact performance for large repositories.
- Review: no substantive feedback yet; the patch is signed off but not yet reviewed or acked.

Participant positions

- Taylor Blau: proposed the fix, provided technical rationale, updated tests, and flagged potential test compatibility concerns. Signed off on the patch; includes Peter Elmers in the trailer.
