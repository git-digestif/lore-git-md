This is a review comment on the second patch of Karthik Nayak’s `receive-report` hook series, now in its eighth iteration and cooking in `next`. Junio C Hamano spots a **substantive correctness issue** in the error-handling logic: the patch replaces the old boolean-based fallback behavior (`if (report_status_v2) ... else if (report_status) ...`) with a `switch` over an `enum report_status_version`, but the `default` case now calls `BUG()` if the version is neither `V0` nor `V2`. Junio points out that this is wrong because the version is determined by the client’s advertised capabilities, not by Git’s own code — a client could legitimately omit the `report-status` capability entirely, in which case the server should simply skip sending a status report rather than crashing. The `BUG()` macro is reserved for programming errors on the server side, not for protocol-level choices made by the client.

Junio’s suggested fix is to add a `REPORT_STATUS_UNKNOWN` case that does nothing, preserving the old fallback behavior. The review is **substantive** — it identifies a real correctness issue that could cause the server to crash on valid input — and **tested-level** in spirit, since it traces the code path from client capability advertisement to server-side handling. The patch is already in `next`, so this feedback will likely trigger a v9 iteration before the series graduates to `master`.
