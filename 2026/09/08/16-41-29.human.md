This is the final patch in Christian Couder’s v3 series introducing `uploadpack.lazyFetchTrusted`, a server-side protected configuration variable that lets operators explicitly mark repositories as trusted for lazy fetching. This patch activates the mechanism by making `upload-pack` set `GIT_NO_LAZY_FETCH=0` when serving a trusted repository, thereby allowing lazy fetching to proceed.

The patch is straightforward: it checks whether the served repository is in the `uploadpack.lazyFetchTrusted` allowlist and, if so, relaxes the default `GIT_NO_LAZY_FETCH=1` setting to `0`. The change is minimal—just eleven lines in `builtin/upload-pack.c`—but it is the payoff for the entire series. The rest of the patch is documentation (50+ lines in `Documentation/config/uploadpack.adoc`, plus smaller updates to `git-upload-pack.adoc` and `git.adoc`) and a comprehensive test script (`t/t5710-promisor-remote-capability.sh`) that verifies the new behavior: trusted repositories can lazy-fetch, untrusted ones cannot, and explicit `GIT_NO_LAZY_FETCH=1` overrides the configuration.

The documentation is thorough and clear: it explains that repositories are identified by their `.git` directory, warns against self-referential promisor remotes, and emphasizes that the configuration is protected (only respected in system or global scope). The tests cover edge cases like non-bare repositories, explicit overrides, and recursion safeguards (the latter implemented in patch 4/5).

This patch completes the series’ shift from the earlier client-side `GIT_NO_LAZY_FETCH=fromAccepted` proposal to a server-controlled trust model. The unresolved concerns from Junio and brian m. carlson remain—scalability of the allowlist and the conceptual fit of a configuration variable for security decisions—but the implementation is now fully functional and well-documented. If the series lands, this patch is the one that actually enables the feature.
