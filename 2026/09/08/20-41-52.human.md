This is the first patch in the **v15 reroll of the `git history squash` feature**, a new standalone subcommand that folds a commit range into its oldest ancestor. The series is now technically complete and ready for integration, with Junio having signaled intent to queue it ("Will replace") since v7.

This patch is a **refactoring** that extracts a helper function, `first_parent_tree_oid()`, to centralize the logic for resolving the tree of a commit's first parent (or the empty tree for root commits). The change touches three existing call sites in `builtin/history.c` that previously repeated the same parse-and-copy dance. No behavior changes are introduced—this is purely preparatory work for the core squash functionality that follows in later patches.

The helper is straightforward: it takes a `struct repository *`, a `struct commit *`, and an output `struct object_id *`, then either copies the parent's tree OID or falls back to the empty tree. Error handling is consistent with the existing code, returning -1 on parse failures. The patch is **well-motivated**—eliminating duplication in a new codebase is good hygiene, and the extracted helper will be reused by the squash logic in subsequent patches.

For a human reader, this patch is a **low-drama housekeeping change** that signals the series is in good shape.
