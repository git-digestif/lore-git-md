This is the **core implementation patch (7/8) of the `git history squash` feature**, completing the `--no-edit` workflow for the series. The patch adds the machinery to create a squashed commit from a resolved range without opening an editor, while handling autosquash markers (`fixup!`, `squash!`, `amend!`), preserving authorship and merge parents, and replaying descendants.

The patch introduces **~260 lines of new logic in `builtin/history.c`**, centered around the `cmd_history_squash()` function. When `--no-edit` is specified, the command:
- Resolves the revision range (via `resolve_squash_range()`, extended here to also return a message template).
- Validates autosquash markers: rejects any `fixup!`/`squash!`/`amend!` whose target is outside the range, unless the entire range consists of markers for a single target. **Strict case-sensitive matching is enforced** (rejecting uppercase OIDs).
- Builds the squashed commit using `commit_tree_ext()` with the oldest commit’s authorship, the tip’s tree, and the range’s parent list. The message is constructed from the oldest commit’s message, with `amend!` messages targeting it incorporated (and `squash!`/`fixup!` messages either appended or rejected if they would be discarded).
- Replays descendants using the existing history-rewrite machinery (`handle_reference_updates()`), respecting `--dry-run` and `--update-refs` flags.
- Records the full revision expression in the reflog (e.g., `squash: updating start..HEAD`).

Key helpers added:
- `squash_check_subject()`: Parses commit subjects to detect autosquash markers and validate their targets.
- `squash_check_autosquash_subject()`: Enforces strict case-sensitive matching and rejects markers whose targets are not in the range.
- `squash_amend_message()`/`squash_squash_message()`: Handle message construction for `amend!` and `squash!` markers, respectively.
- `subject_data` struct: Tracks subject strings and message templates during the range walk.

The **test suite (`t/t3455-history-squash.sh`)** expands by **~630 lines**, covering:
- Autosquash marker resolution: sequences like `fixup! fixup! <target>`, `squash!` into `fixup!`, and `amend!` message incorporation.
- Merge handling: folding ranges with interior merges, octopus merges, and nested merges, while rejecting merges with external parents.
- Ref protection: rejecting operations that would leave local branches dangling, with `--update-refs=head` as an escape hatch.
- Edge cases: `--dry-run` prediction accuracy, reflog message accuracy, and rev-list option sanitization.

The patch **completes the `--no-edit` workflow** for the series, leaving only the `--edit` path (which will open an editor with an autosquash-style template) unimplemented. The implementation is **well-decomposed**, with autosquash logic isolated in reusable helpers and merge/parent validation handled by earlier patches. The strict case-sensitive matching policy (resolved in v15) aligns with Git’s historical convention of emitting lowercase OIDs.
