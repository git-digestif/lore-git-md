This is the fourth patch in Christian Couder’s v3 series introducing `uploadpack.lazyFetchTrusted`, a server-side mechanism to mark repositories as safe for lazy fetching. This specific patch prevents infinite recursion when a repository is configured to lazy-fetch from itself or from another repository that in turn lazy-fetches back to it.

The problem is straightforward: if repository R is configured to lazy-fetch from promisor remote P, and P is configured to lazy-fetch from R, a request for a missing object triggers an infinite loop of nested `git-upload-pack` processes. In practice, the recursion fails only when the environment grows too large, producing a cryptic “Argument list too long” error. The fix introduces a new internal environment variable, `GIT_INTERNAL_LAZY_FETCH_DEPTH`, that counts how many levels deep the lazy-fetch stack is. When the depth exceeds `MAX_LAZY_FETCH_DEPTH` (set to 5), the code emits a clear warning (“too many nested lazy fetches; is a promisor remote pointing at the repository itself?”) and aborts the fetch.

The implementation touches `promisor-remote.c` to pass the depth counter through the call chain (`fetch_objects`, `try_promisor_remotes`, `lazy_fetch_objects`) and `environment.h` to define the new variable. A new test in `t/t0410-partial-clone.sh` verifies that the recursion is bounded: it creates two partial clones that point to each other as promisor remotes, then confirms that only five fetch subprocesses are spawned before the operation fails with the expected warning.

This patch directly addresses a security and correctness concern Junio raised in the v2 review—recursion risk when a repository is its own promisor remote—and does so with minimal overhead. The limit of five is chosen to allow legitimate nesting (e.g., `git fetch` invoking `index-pack` that lazy-fetches REF_DELTA bases) while still catching pathological cycles early. The warning message is clear and actionable, helping operators diagnose misconfigured remotes. No new configuration or user-facing behavior is introduced; the change is purely defensive plumbing.
