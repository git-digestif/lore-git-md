This is a v3 feature series introducing `uploadpack.lazyFetchTrusted`, a server-side protected configuration variable that lets operators explicitly mark repositories as trusted for lazy fetching. The series is now correctly threaded and addresses feedback from Junio C Hamano on the v2 iteration, including a new patch (4/5) that prevents infinite lazy-fetch recursion when a repository is configured as its own promisor remote.

The core goal remains the same: provide a server-side mechanism for operators to declare which repositories are safe to lazy-fetch from, addressing the security concern that untrusted repositories could trigger arbitrary code execution via lazy-fetch hooks or configuration. The new approach shifts trust decisions entirely to the server operator, modeled after Git’s `safe.directory` configuration. The v3 iteration refines the implementation by making repository identification more precise (using the git directory rather than worktree), adding a recursion depth limit via `GIT_INTERNAL_LAZY_FETCH_DEPTH`, and improving the API design of the path allowlist helper with a callback-based approach.

Patch 1/5 is a carry-over from earlier work, refactoring the `lazy_fetch_objects()` helper in `promisor-remote.c` to simplify control flow. Patch 2/5 extracts and generalizes the `safe.directory` allowlist machinery into reusable `path_allowlist_apply()` and `path_allowlist_config_apply()` helpers, now with a callback argument to let callers customize path validation. Patch 3/5 uses these helpers to implement `upload_pack_lazy_fetch_trusted()`, which checks whether the served repository is listed in the `uploadpack.lazyFetchTrusted` allowlist. Patch 4/5 is new in v3 and prevents infinite recursion by introducing a nesting depth limit via the `GIT_INTERNAL_LAZY_FETCH_DEPTH` environment variable. Patch 5/5 wires up the new functionality in `upload-pack`, setting `GIT_NO_LAZY_FETCH=0` when the served repository is trusted, and adds comprehensive tests covering edge cases like self-referential promisor remotes and worktree vs. git directory identification.

The series is well-motivated and addresses a real operational need in corporate environments where servers use promisor remotes. The implementation is careful and thorough, with clear documentation and test coverage for edge cases. The recursion prevention in patch 4/5 is a particularly important addition that directly responds to feedback on v2. The unresolved security objection from brian m. carlson remains relevant but is now mitigated by the server-side trust model; whether this satisfies the objection will likely be the central point of discussion. The series is ready for further review and looks like a solid contribution.
