This is the third patch in Christian Couder’s five-patch v3 series introducing `uploadpack.lazyFetchTrusted`, a server-side configuration to mark repositories as trusted for lazy fetching. The patch refactors the allowlist-checking logic from `safe.directory` into a reusable, callback-based helper, directly addressing Junio C Hamano’s v2 critique about API rigidity.

The new `path_allowlist_apply()` function now takes a callback and a `void *` context, letting callers define their own path-validation rules. This design future-proofs the helper for other protected configuration variables (e.g., future `safe.hookDirectory`) and preserves the original `safe.directory` behavior via a dedicated `allow_safe_dir()` callback. The patch also introduces `allow_trusted_path()`, a stricter callback for `uploadpack.lazyFetchTrusted` that enforces absolute paths and rejects `.` and relative paths, directly responding to Junio’s concern about caller-specific rules.

Files touched are `setup.c` and `setup.h`; the refactoring is clean and has no behavioral impact. The callback-based design is a clear improvement over the v2 hardcoded flags, and the patch is well-motivated by the series’ overall goal of shifting trust decisions to the server operator. If the series stalls, this refactoring could still be integrated early as a standalone improvement. No new reviews have been posted; the series remains under review.
