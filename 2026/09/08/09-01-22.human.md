This is a review exchange on the first patch of Patrick Steinhardt’s v2 series to standardize Git’s terminology for "ref storage format." The patch renames `--ref-format=` to `--ref-storage-format=` in `git init` while retaining the old option as a hidden backward-compatible alias.

Kaartic Sivaraam raises a procedural question: whether the old option (`--ref-format=`) should be formally deprecated (with warnings) to eventually retire it, or if it should be marked as an alias of the new option. He suggests updating the documentation and help text to clarify the deprecation status if the former approach is chosen, and proposes using `OPT_ALIAS` if the latter. The rest of the patch (renaming across documentation, code, and tests) is uncontroversial.

No technical objections or edge cases are identified; the discussion is purely about long-term maintenance strategy. The series’ overall goal—consistency ahead of the object storage extension—remains well-motivated, and this patch is a straightforward mechanical step toward that goal. The outcome of this exchange will likely apply uniformly to the other patches in the series that introduce the same rename.
