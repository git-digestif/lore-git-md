This is the fourth patch in the **v15 series** implementing `git history squash`, a new subcommand that folds a commit range into its oldest ancestor while preserving descendant history. The series is now technically complete and ready for integration, with this patch providing the **entry point and option parsing skeleton** for the squash command.

The patch adds the `git history squash` subcommand, defining its usage, option parsing, and revision range handling. It enforces the requirement for at least one *bottom* revision (e.g., `git history squash A..B`), ensuring the squashed commit has a valid base to reparent onto. The implementation passes remaining arguments through `setup_revisions()` to accept revision ranges and `rev-list` options, while explicitly restoring the walk-order and simplification settings required for the fold operation if they are altered by user-provided options. A warning is issued if any such options would change the default behavior.

Key details include:
- **Option parsing**: Supports `--dry-run`, `--update-refs=(branches|head)`, and `--[no-]edit` (defaulting to `--edit`).
- **Revision validation**: Rejects single-revision inputs (e.g., `git history squash A`) and ensures the range excludes a base commit.
- **Walk-order enforcement**: Explicitly sets `revs->reverse = 1`, `revs->topo_order = 1`, and other flags to ensure the range is walked in the correct order for squashing, warning if user-provided options would override these.
- **Placeholder error**: Currently returns "squashing commits is not implemented yet" to allow incremental review.
