This is a bug report about `git send-email`. The user encountered an SMTP rate-limiting error (`4.7.1 Error: too many recipients`) while sending a 13-patch series to the Linux kernel mailing list, causing `git send-email` to exit abruptly after the eighth mail. The user expected Git to handle the error gracefully—perhaps by pausing and prompting to continue—rather than failing outright. Instead, the abrupt exit led to a misthreaded follow-up attempt, creating an embarrassing situation.

The report includes clear reproduction steps: sending a series with many recipients (18 per mail) to a rate-limited SMTP server. The user’s workaround (`--batch-size=4 --relogin-delay=60`) suggests the issue could be mitigated with better defaults or built-in rate-limiting logic. The system info confirms this occurred on Git 2.34.1, a relatively old version, but the behavior is still worth noting for users on newer releases.

This isn’t a patch or a feature request—just a real-world pain point for contributors sending large patch series. The report is well-structured and actionable, though it’s unclear whether the Git project will prioritize a fix. For now, it serves as a cautionary tale for others hitting similar SMTP limits.
