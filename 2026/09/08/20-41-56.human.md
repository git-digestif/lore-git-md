This is the fifth patch in Harald Nordgren’s **v15 `git history squash` series**, which is now technically complete and ready for integration. This patch implements **input validation for squash revision ranges**, ensuring the selected commits form a well-defined, foldable history.

The patch walks the revision range in topological order, marking each commit as seen. It enforces several key constraints:
- **No root commits**: The oldest commit must have a parent (you cannot squash down to a root).
- **Single tip**: The range must resolve to exactly one tip commit (no ambiguous endpoints).
- **Contained merges only**: Merge parents must either be inside the range or already parents of the oldest commit (rejecting merges that introduce external history).
- **Non-empty, non-singleton ranges**: The range must contain at least two commits and not collapse to a single commit.

The implementation introduces two new object flags (`SQUASH_SEEN` and `SQUASH_TIP`) and a helper function `resolve_squash_range()` that replaces the earlier placeholder logic in `cmd_history_squash()`. The function returns the oldest commit (whose parents are preserved) and the single tip (whose tree is used for the rewrite). Test coverage in the new `t/t3455-history-squash.sh` script verifies all error conditions: empty ranges, single commits, root commits, multiple tips, and merges with external parents.
