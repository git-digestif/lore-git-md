This is a substantive review of the third patch in Beat Bolli’s `imap-send` TLS certificate verification series. Brian m. Carlson raises two technical concerns about the patch’s scope and approach.

First, he points out that the patch only handles DNS-type subject alternative names (SANs) but ignores IP addresses. Certificates for IP-based endpoints (e.g., `1.1.1.1`) use IP-type SANs, not DNS-type, so the current logic would incorrectly fall back to checking the common name (CN) even when an IP SAN exists. This violates RFC 6125 just as much as the DNS case the patch fixes.

Second, he questions why Git continues to implement certificate verification manually instead of delegating to OpenSSL’s built-in hostname verification (available since OpenSSL 1.0.2). Using OpenSSL’s native function would eliminate the risk of security-sensitive bugs, ensure ongoing compliance with evolving standards, and reduce maintenance burden. The review includes a link to OpenSSL’s hostname validation documentation as a reference.

The review is substantive: it identifies a standards-compliance gap (IP SANs) and proposes a higher-level architectural alternative (OpenSSL’s built-in verification). No tested feedback is provided, but the technical points are precise and actionable. The tone is constructive, framing the concerns as opportunities to improve correctness and maintainability rather than as flaws in the current patch.
