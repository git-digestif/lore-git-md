This is the third patch in the v15 series introducing `git history squash`, a new subcommand that folds a commit range into its oldest ancestor. The series is now technically complete and ready for integration, with this patch focusing on **refactoring to share squash-message helpers** between `git rebase -i` and the upcoming `git history squash`.

The patch extracts three static helpers from `sequencer.c`—`add_squash_combination_header()`, `add_squash_message_header()`, and `squash_subject_comment_len()`—and moves them to `sequencer.h` so they can be reused by `git history squash`. It also relocates the `todo_item_flags` enum to the header, allowing callers to distinguish between `amend!`, `fixup!`, and `squash!` markers when processing the rebase todo list. The changes are purely mechanical: no behavior is altered, and the existing `git rebase -i` squash template remains unchanged.

This refactoring is a prerequisite for patch 4/8, which implements the core squash logic in `builtin/history.c`. By centralizing these helpers, the patch ensures that `git history squash` will generate the same editor template as `git rebase -i --autosquash`, including the "This is a combination of N commits" banner and the per-commit headers. The `todo_item_flags` enum is similarly shared to maintain consistency in how autosquash markers are interpreted across commands.

The patch is well-structured and uncontroversial. It touches only `sequencer.c` and `sequencer.h`, with clear commit message documentation explaining the purpose of each helper. The changes are minimal and focused, making them easy to review. This is a **refactoring patch** that prepares the ground for the feature implementation in later patches, and it reflects the series' overall attention to code reuse and consistency.
