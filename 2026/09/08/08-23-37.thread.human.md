This thread is a bug report about `git bundle` omitting required tree objects when bitmaps are enabled, which breaks offline transport workflows. Peter Elmers originally reported the issue, confirming it only occurs with bitmaps and providing a reproduction script.

Taylor Blau has now proposed a fix that restricts pack "haves" to only those UNINTERESTING commits marked as BOUNDARY (prerequisites recorded in the bundle header). The patch updates `bundle.c` and adds a test case in `t/t6020-bundle-misc.sh` that directly verifies the reported issue is resolved. The fix addresses the root cause by aligning pack-objects traversal with the bundle's advertised prerequisites, ensuring all objects required by advertised refs are included. One existing test was updated to reflect correct object count expectations when bundles include tags but exclude branch tips.

The patch is signed off and includes Peter Elmers in the trailer, but hasn't received substantive review yet. Taylor notes it's "lightly tested" and flags potential test compatibility concerns, though the change appears well-scoped and targeted. No alternative solutions have been proposed, and the workaround of disabling bitmaps remains available for those needing immediate relief.
