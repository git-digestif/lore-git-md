This thread is a bug report from Peter Elmers about a subtle but serious issue in `git bundle` when bitmaps are enabled. When creating a bundle that includes one branch but excludes another that shares the same root tree, Git omits the shared tree object from the bundle—even though the bundle verification succeeds and the advertised commit is present. The result is a bundle that appears valid but fails when the recipient tries to access the tree of the advertised commit.

The problem is reproducible with a minimal test case: two sibling commits (one local, one remote-tracking) sharing the same parent and root tree. The bundle is created to include the local branch while excluding the remote-tracking ref. With bitmaps enabled, the bundle passes verification but is missing the shared tree object required by the advertised commit. Disabling bitmaps (`-c pack.useBitmaps=false`) works around the issue, confirming the bug lies in the bitmap traversal logic. The author also tested `pack.useBitmapBoundaryTraversal`, which did not resolve the omission.

No responses or reviews have appeared yet, so the thread is currently just the initial report. The issue is likely to affect users who rely on bundles for offline transport or backup, especially in workflows with divergent branches sharing history. If you use `git bundle` with bitmaps enabled, this is a thread to watch for potential fixes or workarounds.
