This thread is about a bugfix for the multi-pack-index (MIDX) subsystem, submitted by Pia Park. The patch addresses a regression where incremental MIDX writes could create an empty layer—either because the new packs were empty or contained only duplicate objects already indexed by earlier layers. This empty layer was published without a reverse index, causing subsequent incremental writes with `--bitmap` to fail when trying to load that missing reverse index.

The fix is straightforward: it adds an early exit in `midx-write.c` when `compute_sorted_entries()` finds no entries for a non-compacting incremental write, preventing the empty layer from being published. The patch includes a clear reproduction case and three new regression tests in `t/t5334-incremental-multi-pack-index.sh`, covering empty initial layers, empty packs, and packs with only duplicate objects. All tests pass with the patch, and the failing tests on the unpatched build confirm the bug's presence.

The change is minimal and targeted, avoiding unnecessary lock acquisition or temporary file creation when no entries are found. Given the MIDX subsystem's importance for large repositories and the role of incremental writes as a key optimization, this fix is likely to be uncontroversial and should attract attention from maintainers. So far, there are no replies or reviews, so the patch is still awaiting feedback.
