This thread is about a bugfix patch from Pia Park that prevents Git’s multi-pack-index (MIDX) subsystem from publishing empty layers, which can cause subsequent bitmap-enabled writes to fail. The issue affects all MIDX write modes—incremental, non-incremental, and compaction—and was introduced by a 2018 change that allowed empty MIDX layers to be published without a reverse index.

Pia’s latest version (v3) refines the patch based on Taylor Blau’s feedback, streamlining tests to remove filesystem state checks and clarifying edge-case coverage. The fix itself remains unchanged: an early exit in `write_midx_internal()` when no objects are found, preserving silent success (exit code 0) for compatibility with commands like `git repack -d`. Three new regression tests in `t/t5334` cover empty initial layers, empty packs, and packs with only duplicate objects, while updates to `t5326` ensure no MIDX or bitmap files are created when no objects exist.

Two questions remain open: whether the "no packs" case should also return success (aligning with `git repack -d`), and whether an empty non-incremental write should remove an existing MIDX. Derrick Stolee’s input on the former is still pending, and Junio’s earlier ping suggests the topic is being tracked for potential inclusion in a future "What’s cooking" report. Taylor Blau’s feedback has been addressed, and the patch is now procedurally unblocked after the v3 resubmission. No merge status has been reported, but the patch is well-motivated and ready for deeper review.
