This is a small but important follow-up in the ongoing effort to improve the advice subsystem’s configuration hints. Junio C Hamano, the maintainer, points out a minor oversight in Vsevolod Myalitsin’s planned v3 patch: the `advise()` function, which is not tied to any specific advice key in the `advice_setting[]` table, currently calls `vadvise()` without passing a proper `advice_setting` struct. To maintain consistency and future-proofing, Junio suggests creating an ad-hoc `advice_setting` instance on the stack for these cases, initializing it with default values (`key = ""`, `scope = CONFIG_SCOPE_UNKNOWN`, `level = 0`) and passing it to `vadvise()`.

The change is straightforward and low-risk, touching only the `advise()` function in `advice.c`. It ensures that the interface remains uniform across all advice-related code paths, avoiding special cases that could complicate future extensions. This aligns with the architectural direction already agreed upon in the thread—using a `scope_hint` field and passing the entire `advice_setting` struct to `vadvise()`—and should be incorporated into the upcoming v3 patch. No new behavior or user-facing changes are introduced; this is purely an internal cleanup. The patch remains under active review, with no objections to the core goal or design.
