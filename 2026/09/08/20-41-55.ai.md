This is **patch 4/8 of the `git history squash` series (v15)**, a feature that folds a commit range into its oldest ancestor while preserving descendant history. The patch adds the **skeleton for the `git history squash` subcommand**, including option parsing, revision range handling, and input validation. It is a **purely structural change** with no functional behavior yet—just the framework for the core logic that will follow in later patches.

The patch introduces the subcommand’s entry point (`cmd_history_squash`) and defines its usage string, which accepts a revision range (e.g., `HEAD~3..HEAD`) and flags like `--dry-run`, `--update-refs=(branches|head)`, and `--[no-]edit`. The `setup_squash_revisions()` helper configures the `rev_info` struct to walk the range in reverse topological order with ancestry-path simplification, while warning if user-supplied rev-list options would alter the walk (e.g., `--boundary`). It also enforces the requirement for at least one `BOTTOM` revision (e.g., `A..B` but not `B`), since the squashed commit needs a parent outside the range to serve as its base.
