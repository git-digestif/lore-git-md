This is the fifth patch in the v15 series implementing `git history squash`, a new subcommand that folds a commit range into its oldest ancestor while preserving descendant history. The patch introduces **shape-based validation** of the revision range, ensuring it forms a well-defined, squashable history.

The core logic is in `resolve_squash_range()`, which walks the selected commits in topological order (oldest to newest) and enforces these invariants:
- The range must contain at least two commits (rejecting empty or single-commit ranges).
- Exactly one tip commit must exist (rejecting multi-tip ranges).
- No commit in the range may be a root commit (to ensure a parent exists outside the range).
- Every parent of a commit in the range must either be in the range or a parent of the oldest commit (rejecting merges with external parents).

The validation uses two new object flags (`SQUASH_SEEN` and `SQUASH_TIP`) to track which commits are in the range and which is the tip. The walk rejects any commit whose parents violate the containment rule, producing clear error messages that cite the offending commit and parent OIDs. The patch also updates `cmd_history_squash()` to delegate range resolution to this helper, replacing its earlier placeholder logic.

Test coverage in the new `t/t3455-history-squash.sh` script verifies all error conditions: missing arguments, empty ranges, single commits, root commits, multi-tip ranges, and merges with external parents. The tests use `test_must_fail` with `test_grep` to confirm the correct error message is emitted for each case.

This is a **well-structured, safety-first validation layer** that prevents malformed histories from reaching the squash logic. The design reflects the series’ overall emphasis on robustness: by rejecting problematic ranges early, it avoids subtle bugs in later stages. The patch is purely mechanical (no behavior changes yet) and integrates cleanly with the preparatory refactoring in patches 1–4. The error messages are user-friendly and actionable, guiding contributors toward valid usage.
