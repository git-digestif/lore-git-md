This is the fourth patch in Christian Couder’s v3 series introducing `uploadpack.lazyFetchTrusted`, a server-side mechanism to mark repositories as trusted for lazy fetching. This patch specifically prevents infinite recursion when a repository is configured to lazy-fetch from itself or from another repository that in turn lazy-fetches back to it.

The problem is straightforward: if repository R is configured to lazy-fetch from promisor remote P, and P is configured to lazy-fetch from R, a request for a missing object triggers an infinite loop of nested `upload-pack` invocations. In practice, the recursion fails when the environment variable list grows too long, but the behavior is pathological and should be avoided. The fix introduces a new internal environment variable, `GIT_INTERNAL_LAZY_FETCH_DEPTH`, to track recursion depth and aborts when it exceeds `MAX_LAZY_FETCH_DEPTH` (set to 5). The limit is chosen to allow legitimate nesting (e.g., `git fetch` invoking `index-pack` to lazily fetch REF_DELTA bases) while preventing infinite loops.

The implementation touches `promisor-remote.c` and adds a new constant in `environment.h`. The `fetch_objects()` helper is modified to pass the incremented depth to child processes, and `lazy_fetch_objects()` checks the depth before proceeding. A new test in `t/t0410-partial-clone.sh` verifies that recursion is bounded: it sets up two partial clones that point to each other as promisor remotes, triggers a lazy fetch, and confirms that only five nested fetches occur before the operation fails with a clear warning.

This patch directly addresses Junio’s concern from v2 about recursion risks and is a prerequisite for the upcoming `uploadpack.lazyFetchTrusted` configuration, which will allow server operators to opt into lazy fetching for trusted repositories. The fix is minimal, well-tested, and does not change the default behavior (lazy fetching remains disabled unless explicitly enabled). The only open question is whether the depth limit of 5 is the right trade-off between safety and legitimate use cases, but the value can be adjusted later if needed.
