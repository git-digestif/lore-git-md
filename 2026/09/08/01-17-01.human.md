This is a review reply in the `git imap-send` OpenSSL compatibility series. Junio C Hamano spots a memory-management bug in Beat Bolli’s second patch: the code increments the `pattern` pointer after allocating it with `xmemdupz()`, then tries to `free()` the modified pointer, which would corrupt the heap. Junio suggests the standard Git pattern of keeping a separate `pattern_to_free` variable that is never modified and used only for cleanup. The fix is trivial but essential; the patch is otherwise a well-motivated correctness fix for unsafe ASN1_STRING handling. If you follow `git imap-send` or OpenSSL compatibility, this is a small but important correction to watch.
