This is the third patch in Christian Couder’s five-patch v3 series introducing `uploadpack.lazyFetchTrusted`, a server-side protected configuration variable to mark repositories as trusted for lazy fetching. The patch refactors the allowlist-checking logic from `safe.directory` into a reusable, callback-based helper, directly addressing Junio C Hamano’s v2 critique about API rigidity. The new design replaces the hardcoded `allow_dot` argument with a function pointer (`allow_path`) and a generic `void *cbdata` parameter, allowing callers to define their own path-validation rules. This change enables `uploadpack.lazyFetchTrusted` to enforce stricter requirements (e.g., rejecting relative paths) while preserving `safe.directory`’s existing behavior.

The patch touches `setup.c` and `setup.h`, introducing two new helpers: `path_allowlist_apply()` (the generic callback-based validator) and `path_allowlist_config_apply()` (a convenience wrapper for configuration callbacks). The original `safe.directory` logic is preserved as `allow_safe_dir()`, now implemented as a callback. The new `allow_trusted_path()` callback enforces the stricter rules for `uploadpack.lazyFetchTrusted`, rejecting `.` and relative paths outright. This refactoring is purely internal and has no user-visible behavior change, but it is critical for the series’ security model: it ensures that the server-side trust decision cannot be bypassed by maliciously crafted repository paths.

Christian’s implementation follows Junio’s suggested design closely, including the use of a `struct` to pass configuration keys and values to the callback.
