This is the fifth iteration of a feature patch extending `git var` to expose individual identity components (name, email, date for both author and committer), the resolved commit signing key, and support for multiple variable arguments with NUL-terminated output. The patch is part of the ongoing effort to provide a unified, scriptable interface for Git’s identity and signing configuration, replacing the earlier `git ident` proposal.

The v5 patch addresses all remaining **substantive review feedback** from Junio C Hamano and Phillip Wood, focusing on mechanical polish and edge-case handling. Key improvements include:

- **Signing key resolution**: now uses Git’s standard `get_signing_key()` (from `gpg-interface.c`) instead of a custom implementation, ensuring consistency with actual commit signing behavior.
- **Error handling**: when querying multiple variables, the command prints an empty record (blank line or NUL) for any unset variable and continues processing the remaining variables, rather than exiting prematurely. This is more script-friendly.
- **Multi-valued variables**: values are now stored internally with NUL delimiters, avoiding the need for temporary `string_list` allocations. When querying multiple variables, an extra delimiter (newline or NUL) is printed after multi-valued variables to disambiguate the output stream.
- **Code structure**: simplified the `show_config()` callback (always passes a non-NULL `nul_term` flag, uses `NUL` for clarity), removed redundant pre-validation of variable names, and renamed `null_term` to `nul_term` for consistency with Git’s style.
- **Documentation**: explicitly describes the `-z` output format for multi-valued variables and the behavior for unset variables.

The patch touches `builtin/var.c`, `Documentation/git-var.adoc`, and `t/t0007-git-var.sh`, with comprehensive test coverage for the new functionality, including edge cases like unset variables, multi-valued variables with newlines, and strict argument ordering. The implementation is backward-compatible with existing `git var` usage, though scripts relying on the current output format may need updates for `-z` mode.

This iteration is **ready for integration** and is likely to be merged soon, pending final review from Junio and Phillip Wood. The changes align with the design consensus reached in prior discussion and address all high-weight review feedback. The patch is technically sound, well-tested, and avoids controversial design choices.
