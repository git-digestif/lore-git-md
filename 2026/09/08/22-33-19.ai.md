This is a bugfix patch for the `git bundle` issue with bitmaps omitting required tree objects. Taylor Blau proposes a fix that restricts pack "haves" to only those UNINTERESTING commits marked as BOUNDARY (i.e., prerequisites recorded in the bundle header). The patch touches `bundle.c` and updates test expectations in `t/t6020-bundle-misc.sh`.

The core insight is that the current implementation overcounts UNINTERESTING objects by treating all excluded tips as pack "haves," whereas the bundle header only records boundary commits as prerequisites. This mismatch allows bitmap traversal to omit trees shared between included and excluded commits, breaking the bundle's self-containment. The fix aligns the pack-objects traversal with the bundle's advertised prerequisites, ensuring all objects required by advertised refs are included.

The patch includes a new test case (`bundle with bitmaps includes trees shared with an excluded sibling`) that directly verifies the reported issue is resolved. It also updates an existing test (`create bundle 4 - with tags`) to reflect the correct object count: when no prerequisites are recorded, the bundle must include the full history reachable from advertised tags, not just the tag objects themselves. This test fallout is a consequence of fixing the underlying logic rather than a regression.

Taylor notes the fix is "lightly tested" and flags potential concerns about test compatibility, particularly for cases where bundles include tags but exclude branch tips. The patch is signed off and includes the original reporter (Peter Elmers) in the trailer. No substantive review feedback has been incorporated yet, but the patch is clearly motivated by the earlier bug report and includes a technical rationale in the commit message. The change appears targeted and well-scoped, addressing the root cause without introducing broader behavioral changes.
