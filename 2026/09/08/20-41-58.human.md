This is the **seventh patch in the v15 series** introducing `git history squash`, a new subcommand that folds a commit range into its oldest ancestor while preserving descendant history. This patch implements the core logic for creating the squashed commit **without opening an editor** (`--no-edit` mode), handling autosquash markers (`fixup!`, `squash!`, `amend!`), and replaying descendants.

The patch adds **324 lines to `builtin/history.c`**, introducing the machinery to:
- **Resolve autosquash markers** while walking the commit range, rejecting operations that would discard a `squash!` or `amend!` message unless the target is also in the range (with strict case-sensitive matching, as finalized in v15).
- **Build the squashed commit** using the oldest commit’s authorship, the tip commit’s tree, and the full parent list of the oldest commit (preserving merge parents).
- **Replay descendants** through the existing history rewrite infrastructure, with `--dry-run` support and reflog messages recording the full revision expression.
- **Handle `amend!` messages** by incorporating them into the squashed commit’s message when targeting the oldest commit, or rejecting them if they would overwrite a `squash!` message.

Key behaviors:
- **Autosquash strictness**: Rejects `fixup!`/`squash!`/`amend!` commits whose targets are outside the range, unless the range consists entirely of markers for a single target (e.g., folding `fixup! fixup! A` into `A`).
- **Message handling**: With `--no-edit`, the last `amend!` message targeting the oldest commit is used; `squash!` messages are appended to the default message, and `fixup!` messages are discarded unless converted to `amend!` or `squash!`.
- **Merge preservation**: The squashed commit retains all parents of the original merge commit, allowing fully contained merges to be folded.
