This is the second patch in the v3 series (3/3) that defers auto maintenance until sequencer-driven operations (`git rebase`, `git cherry-pick`, `git revert`) complete. The patch moves the `run_auto_maintenance()` call from the sequencer to the built-in command entry points (`run_specific_rebase()` in `builtin/rebase.c` and `run_sequencer()` in `builtin/revert.c`), consolidating maintenance into a single exit path per command. This aligns with the apply backend’s design and addresses Patrick Steinhardt’s preference for a unified exit path.

The patch touches `builtin/rebase.c` and `builtin/revert.c`, adding logic to invoke `run_auto_maintenance()` only after the sequencer has successfully completed and removed its state directory (for rebase) or after any successful sequencer operation (for cherry-pick/revert). The changes are straightforward: for rebase, maintenance runs if the sequencer returns success and the state directory is gone; for cherry-pick/revert, it runs after any successful `sequencer_pick_revisions()`, `sequencer_continue()`, or `sequencer_skip()` call.
