This is a bugfix patch addressing the `git bundle` issue with bitmaps omitting required tree objects. Taylor Blau responds to Peter Elmers' bug report with a proposed fix and a clear explanation of the root cause.

The patch restricts pack "haves" to only those UNINTERESTING commits marked as BOUNDARY (i.e., prerequisites recorded in the bundle header). This prevents the bitmap traversal from incorrectly omitting trees shared between included and excluded commits. The fix is straightforward: in `bundle.c`, the code now skips UNINTERESTING objects that aren't also BOUNDARY when building the list of "haves" for pack generation.

Taylor notes that this change has test fallout in `t6020.13`, where a bundle previously omitted the history reachable from advertised tags (because the excluded branch tips suppressed it). The fix correctly includes that history, increasing the expected object count from 3 to 40. A new test (`bundle with bitmaps includes trees shared with an excluded sibling`) is added to verify the fix works for the reported scenario.

The patch is well-motivated and addresses the core issue: bitmap traversal was too aggressive in pruning objects, while the bundle header's prerequisites should be the sole determinant of what's excluded. The test adjustments are minimal and justified. This looks like a clean, targeted fix for a real bug affecting users who rely on bundles for offline transport.
