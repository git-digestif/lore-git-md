This is the maintainer's **substantive review** of the `git var` extension patch (v5), focusing on documentation clarity, output format compatibility, error handling, and code structure. The patch extends `git var` to support broken-down identity components, a resolved signing key, multiple variable arguments, and NUL-terminated output (`-z`), and is part of the unified identity/signing configuration effort.

Junio raises three key concerns. First, the **documentation for identity variables** (`GIT_AUTHOR_NAME`, `GIT_AUTHOR_EMAIL`, etc.) is too terse, offering no explanation of their purpose or relationship to `GIT_AUTHOR_IDENT`. In contrast, the `GIT_SIGNING_KEY` description is praised for clearly stating its significance. Second, the **output format changes** for multi-valued variables (e.g., `GIT_CONFIG_GLOBAL`) risk breaking existing scripts. The patch adds an extra newline/NUL after multi-valued variables when querying multiple variables, which Junio flags as a potential backward-incompatibility; he asks whether this affects non-`-z` output and requests clarification. Third, the **error handling in `ident_part()`** is overly permissive, masking programming errors (e.g., NULL pointers after successful `split_ident_line()`) that should trigger `BUG()` instead of returning NULL.

The review also critiques the **implementation of multi-valued variables**, noting that the current approach (NUL-delimited strings) could silently skip valid values if an empty string is present. Junio suggests a more robust design using a `string_list`-based `multiread` callback to avoid edge cases. Additionally, he objects to a **distracting whitespace cleanup** in `get_git_var()`, advising it be split into a separate patch.

The patch is **not yet ready for integration** despite addressing prior feedback. Junio’s concerns are technical and specific, targeting core design choices rather than polish. The author will need to revise the documentation, clarify output format behavior, tighten error handling, and reconsider the multi-valued variable implementation before the patch can proceed. The thread remains in active review, with no merge in sight.
