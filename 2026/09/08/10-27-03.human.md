This is the third patch in Karthik Nayak’s four-part series introducing the `receive-report` hook, now in its eighth iteration and queued in `next`. The patch refactors the status-report generation logic in `builtin/receive-pack.c` by extracting it into a reusable `generate_report()` helper, unifying the previously separate `report()` and `report_v2()` functions.

The motivation is straightforward: the next patch will add a second call site for generating the same report, so centralizing the logic avoids duplication. The new helper takes an `enum report_status_version` parameter to distinguish between the v0 and v2 protocols, with v2 adding per-ref details like `option refname` and `option old-oid`. The stale comment in the helper has been updated to reference the `version` parameter instead of the removed `detailed_report` boolean, addressing Junio’s latest surface-level nit.

The patch is purely internal and does not change user-visible behavior, but it is a necessary precursor to the hook implementation in patch 4/4. The refactoring is clean and well-motivated, with no obvious oversights. All prior substantive feedback—including Patrick Steinhardt’s suggestion to unify the two report functions—has been incorporated. The series as a whole remains on track for integration.
