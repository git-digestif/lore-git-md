This is the first patch in a three-part series (v3) that introduces a helper function for building `GIT_CONFIG_PARAMETERS` strings. The series aims to defer auto maintenance during sequencer operations (`git rebase`, `git cherry-pick`, `git revert`) until completion, aligning with the apply backend’s behavior.

The patch adds `git_config_append_parameter()`, a reusable helper in `config.c` that appends a properly quoted `key=value` pair to a `struct strbuf`. This replaces the inline formatting previously done in `git_config_push_split_parameter()`, making the logic available for other callers. The function handles shell quoting (via `sq_quote_buf()`) and documents the expected format in the header: a space-separated list of `'key'='value'` pairs, with `NULL` values treated as boolean `true`. The sequencer will use this helper in a later patch to pass `maintenance.auto=false` to spawned commands.

The change is mechanical and well-motivated, touching only `config.c` and `config.h`. The commit message clearly explains the purpose and usage, and the code follows Git’s conventions. No substantive objections remain; prior feedback about parameter naming (`env` vs. `buf`) and documentation was addressed in earlier iterations. This patch is ready for merging once the series’ commit messages are polished in v4.
