This is a review of the third patch in Beat Bolli’s three-patch series improving `git imap-send`’s TLS certificate verification. The patch enforces RFC 6125 by skipping the subject common name (CN) check if any DNS subject alternative names (SANs) are present. Brian m. carlson’s review raises two substantive concerns: the patch does not handle IP addresses in SANs, and it reinvents OpenSSL’s built-in hostname verification (available since OpenSSL 1.0.2), which would be more robust and standards-compliant.

The first point is a technical gap: the patch tracks only DNS SANs, so certificates with IP addresses (e.g., `1.1.1.1`) would incorrectly fall back to CN checks, violating RFC 6125. The second is architectural: OpenSSL’s native verification handles all SAN types (DNS, IP, URI, etc.) and is actively maintained, reducing the risk of Git introducing security bugs. Brian’s suggestion to delegate verification to OpenSSL is well-motivated, though it would require a larger refactor of `imap-send.c`. The review is substantive and highlights real limitations in the current approach.
