This is the second patch in Christian Couder’s v3 series introducing `uploadpack.lazyFetchTrusted`, a server-side protected configuration to mark repositories as trusted for lazy fetching. This patch is a pure refactoring of the `safe.directory` allowlist machinery in `setup.c`, extracting it into a generic, callback-based helper (`path_allowlist_apply()`) that can be reused for the new `uploadpack.lazyFetchTrusted` logic in later patches.

The refactoring moves the existing path-matching logic from `safe_directory_cb()` into a new `path_allowlist_apply()` function, which takes a caller-provided `allow_path` callback to validate paths. This lets different callers enforce their own rules—for example, `safe.directory` accepts `.` and absolute paths, while `uploadpack.lazyFetchTrusted` (introduced in patch 3) will reject relative paths entirely. The patch also adds a convenience wrapper, `path_allowlist_config_apply()`, to handle config-value expansion and simplify future callers. The `safe_directory_data` struct’s `is_safe` field is converted from `int` to `bool` for clarity, and the existing `safe.directory` logic is updated to use the new helpers.

The changes are observably equivalent to the current behavior, with no functional impact on `safe.directory`. The refactoring is motivated by the need to reuse the allowlist machinery for `uploadpack.lazyFetchTrusted` without duplicating code or config-value handling. The callback-based design directly addresses Junio’s API rigidity critique from v2, where he argued the original hardcoded logic was too inflexible for the new use case.
