This is the **v15 reroll of the `git history squash` feature**, a new standalone subcommand that folds a commit range into its oldest ancestor while preserving descendant history. The series is now **technically complete** and ready for integration, addressing the last remaining feedback from Junio C Hamano regarding autosquash marker resolution.

The core change in v15 is mechanical: replacing `istarts_with()` with `starts_with()` in `squash_check_autosquash_subject()` to enforce **strict case-sensitive matching** for autosquash markers (e.g., rejecting `fixup! ABCDEF` while accepting `fixup! abcdef`). This aligns with Git’s historical convention of emitting only lowercase hexadecimal OIDs, as established by `bc/restrict-hex-to-lowercase`. The reroll also fixes a typo in an adjacent comment (`squshed` → `squashed`). No other functional changes were made since v14, which already resolved all prior technical and structural concerns.

The series remains split into eight focused patches, with the core implementation (patches 4–8) touching `builtin/history.c` (720+ new lines), `sequencer.c`/`sequencer.h`, and adding a new test script (`t/t3455-history-squash.sh`, 886+ lines). Key behaviors finalized in v14 include:
- **Range validation**: Rejects root commits, multi-tip ranges, and merges with external parents via `resolve_squash_range()`.
- **Ref protection**: Blocks operations if any local branch descended from the squashed range would be left dangling, with an `advice()` message guiding users to `--update-refs[=head]`.
- **Merge handling**: Allows folding fully contained merges (single base, no external parents).
- **Autosquash template**: Generates an editor template matching `git rebase -i --autosquash`, grouping `fixup!`/`squash!`/`amend!` markers under their targets.
- **`amend!` message handling**: Incorporates `amend!` messages targeting the oldest folded commit into the default squashed message.
- **Rev-list option sanitization**: Preserves the `boundary` invariant and warns on forced walk-order changes.
