This is the final patch in Christian Couder’s v3 series introducing `uploadpack.lazyFetchTrusted`, a server-side protected configuration variable that lets operators explicitly mark repositories as trusted for lazy fetching. This patch activates the mechanism by implementing the actual behavior: when `upload-pack` serves a repository listed in `uploadpack.lazyFetchTrusted`, it sets `GIT_NO_LAZY_FETCH=0` in the environment, allowing the server and its child processes (notably `pack-objects`) to lazily fetch missing objects.

The patch touches `builtin/upload-pack.c` to check the allowlist and relax the default `GIT_NO_LAZY_FETCH=1` restriction, and adds extensive documentation in `Documentation/config/uploadpack.adoc`, `git-upload-pack.adoc`, and `git.adoc`. The new documentation explains the security model, clarifies that repositories are identified by their git directory (not worktree), warns against self-referential promisor remotes, and specifies that the configuration is multi-valued and interpolated (supporting `~` and `%(prefix)` expansions). It also cross-references the new variable from the existing `GIT_NO_LAZY_FETCH` documentation.

The test script `t/t5710-promisor-remote-capability.sh` is expanded with six new test cases covering: basic allowlisting, failure when the variable is unset, ignoring unprotected repository-local configuration, explicit `GIT_NO_LAZY_FETCH=1` overriding the allowlist, recursion safeguards when a repository is configured as its own promisor remote, and correct handling of non-bare repositories (requiring the `.git` directory path). These tests directly address Junio’s v2 concerns about recursion risks and API rigidity, and verify the server-side trust model’s security properties.

The patch is well-motivated and technically sound: it leverages the callback-based allowlist infrastructure introduced in patch 2/5, uses the recursion depth safeguard from patch 4/5, and completes the series by wiring the configuration to the actual lazy-fetching behavior. The documentation is thorough and unambiguous, and the tests cover the advertised edge cases. No new substantive concerns are introduced; the unresolved high-weight critiques from v2 (Junio’s scalability concern and conceptual doubt about using a configuration variable for this purpose, and brian m. carlson’s security objection) remain, but are mitigated by the server-side trust model. The series is rebased on a recent `master` and CI passes except for an unrelated Debian 11 environment issue.
