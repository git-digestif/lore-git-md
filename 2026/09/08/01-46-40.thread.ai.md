Subject: [PATCH v3] midx: avoid publishing empty incremental layers
Series version: standalone patch, v3 (v2 previously summarized)
Originating author: Pia Park <pia@pierre.co>
Thread type: bugfix patch

Core problem or goal
A regression in the multi-pack-index (MIDX) subsystem causes MIDX writes—regardless of mode (incremental, non-incremental, or compaction)—to publish empty layers (zero objects) without a reverse index. Subsequent writes with `--bitmap` fail when attempting to load the missing reverse index for the empty layer. The patch prevents publication of empty MIDX layers entirely by exiting early in `write_midx_internal()` when no objects are found, preserving the existing exit status (0) for compatibility.

- Behavior change: `write_midx_internal()` exits early for *any* MIDX write when no objects are found, avoiding lock acquisition, temporary file creation, and publication of invalid layers. The exit status for the "no objects" case remains silent success (0); the "no packs" case is now proposed to also return 0 for consistency with `git repack -d`, but this is deferred for future discussion.
- Subsystem: MIDX (multi-pack-index), performance-critical for large repositories.
- On-disk format: no changes; the fix prevents publication of invalid layers.
- Symbols/functions: `write_midx_internal()`, `compute_sorted_entries()`.
