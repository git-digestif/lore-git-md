Subject: [PATCH v2] midx: avoid publishing empty incremental layers
Series version: standalone patch, v2
Originating author: Pia Park <pia@pierre.co>
Thread type: bugfix patch

Core problem or goal
A regression in the multi-pack-index (MIDX) subsystem causes MIDX writes—regardless of mode (incremental, non-incremental, or compaction)—to publish empty layers (zero objects) without a reverse index. Subsequent writes with `--bitmap` fail when attempting to load the missing reverse index for the empty layer. The patch prevents publication of empty MIDX layers entirely by exiting early in `write_midx_internal()` when no objects are found.

Current status
Under review. This is the second version of the patch, addressing Taylor Blau’s feedback that the bug affects all MIDX write modes, not just incremental non-compacting writes. The exit status for empty MIDX writes (silent success vs. error) and test suite refinements are now under discussion. No merge status reported.

Key technical details
- Files touched: `midx-write.c`, `t/t5334-incremental-multi-pack-index.sh`, `t5326-multi-pack-bitmaps.sh`
- New test cases: three regression tests in `t/t5344` covering empty initial layers, empty packs, and packs with only duplicate objects. The existing test in `t5326` is updated to reflect the new behavior (no empty MIDX or bitmap).
- Behavior change: `write_midx_internal()` now exits early for *any* MIDX write when no objects are found, avoiding lock acquisition, temporary file creation, and publication of invalid layers. The exit status remains 0 for compatibility with callers, but this is now debated.
- Subsystem: MIDX (multi-pack-index), performance-critical for large repositories.
- On-disk format: no changes; the fix prevents publication of invalid layers.
- Symbols/functions: `compute_sorted_entries()`, `write_midx_internal()`.

Open questions and loose ends
1. **Exit status consistency**: Should empty MIDX writes return silent success (0) or an error? The patch preserves the existing exit status for compatibility, but Taylor Blau proposes extending this to the "no packs" case for consistency with commands like `git repack -d`. Derrick Stolee’s input is sought.
2. **Test suite refinements**: Taylor Blau recommends streamlining tests to focus on the core regression (empty MIDX writes do nothing) and avoid redundant assertions. Specific suggestions:
   - Drop filesystem state checks (e.g., `files.expect` comparisons) and stdout assertions.
   - Remove the "non-incremental MIDX with no objects" test from `t5319` (already covered in `t5334`).
   - Simplify the "no MIDX or .bitmap" test in `t5326` to omit filesystem state checks.
   - Fix a logic error in `t5334`’s "skip initial MIDX layer with no objects" test (no packs present, so the "no pack files" error should trigger).
   - Rename the "skip MIDX layer with empty pack" test for clarity.
