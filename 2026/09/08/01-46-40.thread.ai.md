Subject: [PATCH] midx: avoid publishing empty incremental layers

Core problem or goal
A regression in the multi-pack-index (MIDX) subsystem causes incremental MIDX writes to publish empty layers (zero objects) without a reverse index. Subsequent incremental writes with `--bitmap` fail when attempting to load the missing reverse index for the empty layer. The patch prevents empty layers from being published during non-compacting incremental writes.

Current status
Under review. No prior versions. No merge status reported.

Key technical details
- Files touched: `midx-write.c`, `t/t5334-incremental-multi-pack-index.sh`
- New test cases: three regression tests covering empty initial layers, empty packs, and packs with only duplicate objects
- Behavior change: early exit in `compute_sorted_entries()` when no entries are found for non-compacting incremental writes, avoiding lock acquisition and temporary file creation
- Subsystem: MIDX (multi-pack-index), performance-critical for large repositories
- On-disk format: no changes; the fix prevents publication of invalid layers
