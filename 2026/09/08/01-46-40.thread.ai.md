Subject: [PATCH v3] midx: avoid publishing empty incremental layers
Series version: standalone patch, v3 (v2 previously summarized)
Originating author: Pia Park <pia@pierre.co>
Thread type: bugfix patch

Core problem or goal
A regression in the multi-pack-index (MIDX) subsystem causes MIDX writes—regardless of mode (incremental, non-incremental, or compaction)—to publish empty layers (zero objects) without a reverse index. Subsequent writes with `--bitmap` fail when attempting to load the missing reverse index for the empty layer. The patch prevents publication of empty MIDX layers entirely by exiting early in `write_midx_internal()` when no objects are found, preserving the existing exit status (0) for compatibility.

Key technical details
- Files touched: `midx-write.c`, `t/t5319-multi-pack-index.sh`, `t/t5326-multi-pack-bitmaps.sh`, `t/t5334-incremental-multi-pack-index.sh`
- New test cases: three regression tests in `t/t5334` covering empty initial layers, empty packs, and packs with only duplicate objects. The existing test in `t5326` is updated to reflect the new behavior (no MIDX or bitmap files when no objects are present). The "no objects" test in `t5319` is renamed to "skip MIDX layer with empty pack" for clarity.
- Behavior change: `write_midx_internal()` exits early for *any* MIDX write when no objects are found, avoiding lock acquisition, temporary file creation, and publication of invalid layers. The exit status for the "no objects" case remains silent success (0); the "no packs" case is now proposed to also return 0 for consistency with `git repack -d`, pending Stolee’s input.
- Subsystem: MIDX (multi-pack-index), performance-critical for large repositories.
- On-disk format: no changes; the fix prevents publication of invalid layers.
- Symbols/functions: `write_midx_internal()`, `compute_sorted_entries()`.

Open questions and loose ends
1. **Exit status consistency**: Should empty MIDX writes (including the "no packs" case) return silent success (0) or an error? The patch preserves exit status 0 for "no objects" but the "no packs" case is now proposed to also return 0 for consistency with commands like `git repack -d`. Derrick Stolee’s input is explicitly sought and remains outstanding. Junio’s ping and Taylor’s follow-up imply the topic is being tracked for potential inclusion in a future "What's cooking" report, but no decision has been made.
2. **Empty non-incremental write behavior**: Whether an empty non-incremental write should remove an existing MIDX is left for future discussion, as noted by the author.
