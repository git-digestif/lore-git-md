This is the second patch in the v8 series introducing the `receive-report` hook, a feature now queued in `next`. The patch replaces two static boolean variables (`report_status` and `report_status_v2`) with a single `enum report_status_version` to track which protocol version the client requested. The enum makes the code more explicit and extensible, and the change is purely internal—no user-visible behavior is altered.

The patch drops the static variables in favor of passing the enum through the call chain, starting in `read_head_info()` where the client’s feature request is parsed. The `if/else` chain that previously checked the static booleans is now a `switch` statement, addressing Patrick Steinhardt’s subjective preference for clarity. A `REPORT_STATUS_UNKNOWN` sentinel value triggers a `BUG()` if neither v0 nor v2 is set, ensuring the code fails fast if the protocol version is uninitialized.

This refactoring is a prerequisite for the upcoming hook implementation: the unified `generate_report()` helper (introduced in patch 3) needs the enum to handle both protocol versions, and the hook itself must know which version to use when regenerating the error report. The patch is small, mechanical, and well-motivated; the commit message clearly explains the rationale and the `Helped-by` credit to Junio C Hamano acknowledges his suggestion to use an enum instead of a boolean. No test coverage is added because the change is purely internal, but the existing test suite will catch any regressions.
