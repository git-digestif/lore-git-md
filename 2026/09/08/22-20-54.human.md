This is a bugfix series targeting the `--force-if-includes` safety mechanism in `git push`. The v2 update clarifies that the current implementation incorrectly checks the reflog of the *local* branch matching the *remote* destination name (e.g., `main` when pushing to `origin/main`), rather than the branch actually being pushed (e.g., `src` when pushing `src:main`). This flaw can cause false rejections (e.g., when pushing from a differently named local branch or detached HEAD) or unintended data loss (e.g., pushing an unrelated branch that shares a name with a local branch containing the remote tip).

The series consists of two patches. The first fixes the core logic in `remote.c` to consult the reflog of the pushed ref (`ref->peer_ref->name`) instead of the destination ref (`ref->name`). It adds special handling for `HEAD`-based pushes (resolving the symref) and explicitly rejects detached HEAD pushes by default, as the reflog cannot reliably verify the remote tip in that state. The second patch adjusts the advice message for detached HEAD scenarios, introducing a new `advice.forceIfIncludesDetachedHead` config knob (documented as `advice.pushRefUnverifiable`) and a `ref->unverifiable` flag to distinguish these rejections from other cases. The advice now guides users to specify the expected remote tip with `--force-with-lease=<ref>:<expect>` or bypass the check entirely.

The v2 changes are minor but important: the commit message for the first patch now explicitly states that `--force-if-includes` already rejects detached HEAD pushes today (when the same-named local branch lacks the remote tip), and this patch makes that behavior intentional. The series includes eight new test cases in `t/t5533-push-cas.sh`, covering mismatched local/remote names, `HEAD`-based pushes, and detached HEAD states. All transport layers (direct pushes, transport helpers, and send-pack) are updated for consistency.

The patches address two previously reported false rejection cases (from 2023 and 2025) and prevent a potential data-loss scenario where an unrelated branch could clobber the remote. The implementation looks thorough, with clear test coverage and no on-disk format changes. The only open question—whether detached HEAD pushes should be rejected or allowed—was resolved in favor of rejection to avoid surprising behavior, with configurability via the new advice knob. The series is based on `maint` and appears ready for review.
