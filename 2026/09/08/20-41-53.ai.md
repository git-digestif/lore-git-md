This is the second patch in the **v15 `git history squash` series**, a well-scoped refactoring that prepares the ground for the core squash logic. The patch extends `commit_tree_ext()`—a helper used by `git history fixup` and `git history split`—to accept an optional `message_template` parameter. When provided, the template overrides the commit message body of the `commit_with_message` argument; when `NULL`, the original behavior (reusing the commit’s message) is preserved.

The change is **purely mechanical and backward-compatible**: the three existing callers (`commit_tree_with_edited_message`, `cmd_history_fixup`, and `split_commit`) pass `NULL`, so their behavior is unchanged. The new parameter is a straightforward string pointer, and the patch adds a single conditional to fall back to the original message body when the template is absent. No new dependencies or data structures are introduced.

This refactoring is **motivated by the upcoming squash logic** (patches 4–8), which will need to seed the squashed commit’s message from multiple source commits rather than a single one. By isolating the message-seeding logic here, the patch keeps the later squash implementation cleaner and avoids duplicating the commit-tree machinery.
