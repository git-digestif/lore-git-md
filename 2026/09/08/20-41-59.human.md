This is the final patch in Harald Nordgren’s **v15 `git history squash` series**, implementing the default interactive message-editing workflow. The patch enables users to combine commit messages in an editor when squashing, matching the behavior of `git rebase -i --autosquash` while preserving the series’ strict validation rules.

The implementation reuses Git’s existing sequencer machinery (`todo_list_rearrange_squash`) to rearrange commits by their autosquash markers (`fixup!`, `squash!`, `amend!`), then builds an editor template that mirrors `git rebase -i`: `fixup!` messages are commented out entirely, `squash!` bodies are retained (with the marker subject commented), and `amend!` replaces its target’s message unless a preceding `squash!` forces both to be kept. The patch also handles edge cases like empty commit messages (aborting the operation) and ensures the template accurately reflects the marker resolution logic used by the `--no-edit` path.

Key changes include:
- A new `build_squash_message()` helper that constructs the editor template from the rearranged todo list.
- Integration with `resolve_squash_range()` to pass the `edit_message` flag and generate the template during range validation.
- Updates to `cmd_history_squash()` to pass `COMMIT_TREE_EDIT_MESSAGE` when `--edit` is active (the default).
- Extensive test coverage (197+ lines) verifying template generation, marker handling, and editor behavior, including cases for `fixup!`, `squash!`, and `amend!` interactions.

The patch completes the feature’s design by providing a familiar, interactive workflow while maintaining consistency with the series’ strict autosquash validation. With this addition, the series is now **fully implemented** and ready for integration, having addressed all prior feedback on range validation, ref protection, and `--no-edit` behavior. The documentation updates clearly explain the template’s structure and how it aligns with `git rebase -i --autosquash`.
