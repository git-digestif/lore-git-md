This is the **core implementation patch** (4/4) of the `receive-report` hook series, now at v8. The patch introduces the new server-side hook that allows GitLab (and other server operators) to intercept and modify the status report sent to clients after ref updates are committed but before the report is transmitted.

The hook receives the complete pkt-line encoded status report on stdin, replaces it with its stdout, and forwards stderr to the client via the sideband channel. Exit code 0 uses the hook’s stdout as the report; non-zero exit discards stdout, rewrites all ref status lines to `"receive-report hook failed"`, and aborts the push from the client’s perspective—though server-side ref updates are *not* rolled back. This intentional decoupling between reported status and actual repository state is the hook’s defining (and controversial) feature, justified by GitLab’s MVCC use case where a "failed" push may still commit a candidate version that is later discarded.

The patch adds the hook’s plumbing in `builtin/receive-pack.c` (`run_receive_report_hook()`, `override_cmds_error()`), documents its behavior in `githooks.adoc` and `git-receive-pack.adoc`, and provides 224 lines of test coverage in `t/t5412-receive-report-hook.sh`. The tests exercise passthrough, failure modes, stdin/stdout handling, sideband relay, and the hook’s ability to modify the `unpack` status line. The commit message explicitly acknowledges the consistency trade-off: clients may see a "failed" push while the server has already applied the update, leaving remote-tracking branches inconsistent until the next fetch.

This patch is **feature-complete** and addresses all prior feedback, including the v7 error-handling fix (ensuring the regenerated error report uses the correct protocol version) and the v8 stale comment update. The hook’s design as a single-script filter (not integrated with the config-based hook infrastructure) and its exit semantics (aligned with `pre-receive`) are now settled. The series is queued in `next` and ready for integration.
