This thread is a bug report from Juha-Matti Tilli about `git send-email` failing to handle SMTP rate-limiting gracefully. When sending a 13-patch series to the Linux kernel mailing list, the tool encountered a "too many recipients" error from the SMTP server and exited immediately, leaving the remaining patches unsent. The user had to manually resume sending, which broke the threading of the patches and created an awkward situation.

The core issue is that `git send-email` currently lacks built-in error handling for rate-limiting scenarios. While options like `--batch-size` and `--relogin-delay` exist, they require manual configuration and don't address the problem automatically. The user suggests the tool should either pause and retry after a delay or prompt the user to confirm continuation when such errors occur. The report highlights a gap in robustness for users sending large patch series to busy mailing lists, where rate-limiting is common. No patches or prior discussion are mentioned, so this is the first time the issue has been raised in this thread.
