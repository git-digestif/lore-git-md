This is the **v3 resend of patch 5/5** in Christian Couder’s five-part series introducing `uploadpack.lazyFetchTrusted`, a server-side protected configuration variable that lets operators mark repositories as trusted for lazy fetching. The patch activates the mechanism by setting `GIT_NO_LAZY_FETCH=0` in `builtin/upload-pack.c` when serving a trusted repository and documents the feature in `git-upload-pack.adoc`, `git.adoc`, and `Documentation/config/uploadpack.adoc`.

The email is a **direct reply to Junio’s surface-level review** of the v2 documentation. Christian confirms that all of Junio’s editorial suggestions have been incorporated: the documentation now explicitly states that `uploadpack.lazyFetchTrusted` is a multi-valued variable (not a space-separated list), clarifies that repositories are identified by their `.git` directory or a parent directory, and fixes the “a uploadpack” typo. He also notes that the recursion issue Junio humorously flagged—trusting a repository to fetch from itself—has been addressed in v3 with a new patch (4/5) that adds a recursion depth limit via the `GIT_INTERNAL_LAZY_FETCH_DEPTH` environment variable.

The patch itself remains **unchanged in substance** from v2; the only modifications are the documentation tweaks and the threading fix (v3 was resent to correct a threading error in the original v3 submission). The series as a whole is **still under review**, with no new technical objections raised since v3. Junio’s earlier scalability and conceptual concerns about the design remain unresolved, but this specific patch is now **ready for integration** pending any further feedback. The documentation is now clear enough that readers should not misinterpret the syntax or purpose of the configuration variable.
