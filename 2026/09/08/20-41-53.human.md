This is the second patch in the **v15 `git history squash` series**, a feature that folds a commit range into its oldest ancestor while preserving descendant history. The series is now technically complete and ready for integration, with this patch introducing a preparatory refactoring to support the core functionality.

The patch extends `commit_tree_ext()`—a helper used by `git history`’s fixup and split operations—by adding an optional `message_template` parameter. When provided, this template seeds the commit message instead of reusing the original commit’s message. The change is purely mechanical: existing callers (fixup and split) pass `NULL`, preserving their current behavior, while future patches in the series will use the new parameter to construct the squashed commit’s message from multiple sources.

The implementation is straightforward: if `message_template` is `NULL`, the function falls back to the original commit’s message body (`original_body`). Otherwise, it uses the template for both interactive editing (`COMMIT_TREE_EDIT_MESSAGE`) and non-interactive commits. The patch touches only `builtin/history.c`, adding 10 lines and modifying 6, with no functional changes to existing commands.

This refactoring is a **clean, well-motivated step** toward the series’ goal. By isolating the message-seeding logic early, it keeps later patches focused on the squash-specific logic rather than plumbing details. The change aligns with Git’s pattern of incremental helper improvements (e.g., `commit_tree_ext()` itself was introduced in an earlier patch to consolidate commit creation).

The series as a whole addresses a longstanding workflow gap—efficiently collapsing a range of commits without the repeated conflict stops of `git rebase -i`—and this patch is a small but necessary part of that effort. It’s **uncontroversial and ready for review**, with no open questions or edge cases to resolve. The reroll (v15) has already addressed all prior feedback, including the final autosquash marker resolution policy, and Junio has signaled intent to queue the series for the next release.
