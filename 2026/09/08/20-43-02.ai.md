This is the fifth iteration of a **feature patch** extending `git var` to provide broken-down identity components (name, email, date), a resolved signing key, support for multiple variable arguments, and NUL-terminated output (`-z`). The patch is part of the ongoing effort to provide a unified, scriptable interface for Git’s identity and signing configuration, replacing the earlier `git ident` proposal.

The v5 patch addresses all remaining **mechanical and polish-level feedback** from Junio C Hamano and Phillip Wood on v4. Key improvements include: aligning `git_signing_key()` with Git’s standard `get_signing_key()` (from `gpg-interface.c`), simplifying the `show_config()` callback (using `nul_term` consistently, removing redundant checks), removing a pre-validation loop in `cmd_var()`, and adopting script-friendly error handling (printing empty records for unset variables instead of exiting). The `-z` output format now uses internal NUL delimiters for multi-valued variables (e.g., `GIT_CONFIG_GLOBAL`), and an extra delimiter is printed after multi-valued variables when querying multiple variables to disambiguate the stream. The documentation and test suite are updated to reflect these changes.

**Files touched**: `builtin/var.c`, `Documentation/git-var.adoc`, and `t/t0007-git-var.sh`. The patch introduces seven new variables: `GIT_AUTHOR_NAME`, `GIT_AUTHOR_EMAIL`, `GIT_AUTHOR_DATE`, `GIT_COMMITTER_NAME`, `GIT_COMMITTER_EMAIL`, `GIT_COMMITTER_DATE`, and `GIT_SIGNING_KEY`. It enforces strict argument ordering (options before variable names) via `parse_options()` with `PARSE_OPT_STOP_AT_NON_OPTION`, and maintains backwards compatibility with existing `git var` usage. The implementation is table-driven, uses `enum ident_part` for type safety, and integrates with Git’s standard argument parsing and GPG interfaces.

**Behavior changes**: `-z` mode now matches `git config -z` (variable name and value separated by newline, entries terminated by NUL), and multi-valued variables are delimited by NUL bytes. When querying multiple variables, an empty record (blank line or NUL) is printed for any unset variable, and the command continues processing remaining variables (exiting with code 1 if any variable was unset). The patch does not introduce new configuration options or on-disk format changes.

**Test coverage** is comprehensive, including `-z` output format, multi-valued variables, argument ordering, unset variables, and signing key resolution. The patch is **not yet merged** and remains in `seen`. Junio and Phillip Wood have not yet reviewed v5, but the changes align with their prior feedback and the design consensus reached in earlier threads. The series is approaching readiness for integration, pending final review.
