This is the second patch in Patrick Steinhardt’s 9-patch series refactoring ODB alternates handling, part of the ongoing ODB abstraction effort. The patch defers object database (ODB) initialization in `git clone` until after the clone source URI is resolved, addressing two key issues: forward compatibility with alternate ODB backends (which may require object hash information at creation time) and the need to resolve alternates paths before ODB setup. This reordering is purely structural and prepares for later patches that write alternates during ODB creation via `odb_create_on_disk_options`.

The change aligns with the series’ broader goal of simplifying repository initialization by eliminating skip flags and consolidating alternates logic into a single code path.
