This is a documentation-adjacent patch in the advice subsystem, part of an ongoing thread about how to instruct users to disable the `defaultBranchName` advice message. The author, Vsevolod Myalitsin, responds to Ben Knoble’s review by proposing a structural improvement: instead of adding an `is_global(key)` helper function, he extends the `advice_setting` struct with a `global_hint` boolean field. This field is set to `1` for `defaultBranchName` and `0` for all other advice keys, and the `vadvise()` helper uses it to conditionally substitute `--global` for the empty string when formatting the on-screen instructions.

The change is minimal and self-contained, touching only `advice.c`. It does not alter the on-disk format or introduce new functions, and it preserves the existing behavior for all advice keys except `defaultBranchName`, which now recommends a global config setting (`git config --global advice.defaultBranchName false`) instead of a repository-local one (`git config set advice.defaultBranchName false`). The patch does not address Ben Knoble’s syntax preference for `set --global` over `--global`, nor does it include test coverage, but the core goal -- ensuring the advice message recommends a global setting -- is now implemented in a way that is both clean and extensible.

Junio C Hamano’s earlier feedback suggested a more general `config_scope` field (e.g., `CONFIG_SCOPE_GLOBAL`, `CONFIG_SCOPE_SYSTEM`) and passing the entire `advice_setting` struct to `vadvise()` to narrow the interface. Vsevolod’s current proposal uses a simpler boolean, which is sufficient for the immediate use case but may need revisiting if future advice keys require non-global scopes. The thread remains open on both the architectural direction and the unresolved syntax debate, but there are no technical objections to the patch’s intent or the revised design.
