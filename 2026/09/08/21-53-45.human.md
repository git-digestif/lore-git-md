This is a **build system** and **platform compatibility** patch addressing a cross-compilation issue in Git's Rust build infrastructure. The v2 iteration expands the fix to cover both the Meson and `make`-based build systems, responding directly to Junio C Hamano's review questions about scope.

The patch ensures that `CARGO_BUILD_TARGET` is respected when locating the compiled Rust library (`libgitcore.a`), fixing a bug where the build scripts failed to find the library when cross-compiling. The issue arises because Cargo writes the library to `$BUILD_DIR/$CARGO_BUILD_TARGET/$BUILD_TYPE/`, while the scripts previously assumed `$BUILD_DIR/$BUILD_TYPE/`. The fix uses shell parameter expansion (`${CARGO_BUILD_TARGET-}`) in `src/cargo-meson.sh` and updates the `Makefile` to include the target tuple in `RUST_TARGET_DIR`.

The v2 changes are minimal but significant: the `Makefile` now mirrors the logic in `cargo-meson.sh`, ensuring consistency across build systems. Both native and cross-compilation cases have been tested, and the patch is well-motivated for cross-compilation workflows (e.g., Gentoo, embedded systems). This is part of the broader Rustification effort, though it stands alone as a targeted fix.
