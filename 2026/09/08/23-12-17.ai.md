This is the tenth patch in Patrick Steinhardt’s 13-patch series refactoring the object database (ODB) subsystem to remove ad-hoc source linking. The patch enforces a long-documented constraint in `git multi-pack-index --object-dir=`: the specified object directory must be an alternate of the current repository. Previously, Git would silently create an ad-hoc ODB source and link it to the main object database, contradicting the documentation and creating the last real-world caller of the ad-hoc source mechanism outside test helpers. Justin Tobler’s review confirms the patch aligns with the intended behavior and removes the unintended workaround introduced in commit `017db7bb14` (2025-08-11).

The change replaces the ad-hoc source creation with an explicit error message, updating one test chain in `t5319-multi-pack-index.sh` to retain a temporary repository (`repo64`) that provides the required alternate relationship. The patch is a breaking change in the strictest sense, but it aligns with documented behavior since 2021 and removes the only remaining non-test caller of the ad-hoc source API, clearing the way for its complete removal in patch 13/13. The commit message and test adaptation are thorough, and Justin Tobler’s review signals approval with no substantive concerns.

Files touched are `builtin/multi-pack-index.c` (3 lines changed) and `t/t5319-multi-pack-index.sh` (9 lines changed). The key symbol modified is `handle_object_dir_option()`, which now rejects non-alternate object directories with an error instead of creating an ad-hoc source. The test update ensures `repo64` is reused to maintain the alternate relationship required by the new enforcement. No new technical risks are introduced; the patch is a straightforward enforcement of an existing constraint.
