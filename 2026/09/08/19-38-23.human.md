This is a review comment in the thread about deferring auto maintenance during sequencer operations (`git rebase`, `git cherry-pick`, `git revert`). Kristoffer Haugsbakk responds to Junio C Hamano’s observation that commit messages are becoming longer and more formulaic, offering his perspective on why this might be happening.

Kristoffer notes that while thorough commit messages have always included problem descriptions, solution overviews, and sometimes alternatives considered, newer messages increasingly include details that were previously left implicit—such as explicit mentions of test additions, documentation updates, and even benchmarks. He observes that some recent commit messages read like they are filling out a checklist, with implied "checkmarks" for project conventions (e.g., "we added a test as required"). This contrasts with older messages that assumed such practices were understood and focused on the core technical narrative.

The comment is not a critique of the current patch series (which Junio has already signaled he will queue) but rather a reflection on a broader trend in Git’s commit message culture. It suggests that the perceived verbosity may stem from a shift toward more explicit, structured documentation of what was once considered routine development practice.
