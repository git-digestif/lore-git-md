This is a small but important build-system fix for the Rustification effort. The patch ensures that when Git is cross-compiled, the build script correctly locates the Rust library (`libgitcore.a`) by respecting the `CARGO_BUILD_TARGET` environment variable. Without this change, the script looks in the wrong directory (`$BUILD_DIR/$BUILD_TYPE`) and fails to copy the built artifact, breaking the build.

The fix is minimal: it updates the path in `src/cargo-meson.sh` to include `${CARGO_BUILD_TARGET-}` (with a fallback to an empty string if the variable is unset). This matches Cargo’s behavior of always writing output to a target-specific subdirectory, even when cross-compiling to the same architecture as the host.

The patch is well-motivated and addresses a real-world issue for cross-compilation workflows (e.g., Gentoo’s build system, where the author is a contributor). It’s part of the broader Rustification effort, though it doesn’t touch Rust code itself—just the build plumbing. The change is unlikely to be controversial, as it aligns with Cargo’s conventions and fixes a clear bug. If you work with cross-compilation or the Rust integration, this is worth a quick look.
