This thread is about a small but important fix to Git’s Rust build infrastructure, authored by James Le Cuirot. The issue is a cross-compilation bug: when `CARGO_BUILD_TARGET` is set, Cargo writes the compiled Rust library (`libgitcore.a`) to a target-specific subdirectory, but the build scripts weren’t looking in the right place. The patch—now in its third version—updates both the `Makefile` and `src/cargo-meson.sh` to include `CARGO_BUILD_TARGET` in the output path, matching Cargo’s behavior.

James sent v3 after addressing Junio’s feedback from the previous iteration. The new version rebases onto `master` to incorporate recent `RUST_TARGETS` logic (commit `924dfced6b`) and fixes a minor stylistic issue with double slashes in the shell script. The changes are mechanical and uncontroversial, touching just two files with three lines modified. No objections to the technical approach have been raised, and the patch is now ready for integration. It’s particularly relevant for cross-compilation workflows like Gentoo, embedded systems, and macOS universal builds. The thread has focused on implementation details, and the fix is now complete pending any final review comments.
