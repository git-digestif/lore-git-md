This is a documentation-adjacent patch in the advice subsystem, part of an ongoing thread to correct the on-screen instructions for disabling the `defaultBranchName` advice. The author, Vsevolod Myalitsin, has accepted Junio C Hamano’s architectural feedback and will revise the patch further in a v3.

The core goal remains unchanged: the advice message should recommend `git config --global` (or possibly `git config set --global`) instead of `git config set` so that the setting applies globally rather than just to the current repository. The current patch extends the `advice_setting` struct with a `scope_hint` field (renamed from `global_hint`) to allow future advice keys to specify their preferred configuration scope (e.g., `--global` or `--system`). The `vadvise()` helper will now receive a pointer to the entire `advice_setting` struct rather than individual fields, narrowing the interface and making it more extensible.

Junio’s feedback shifted the discussion from a simple boolean flag to a more general design that anticipates future needs. The author has agreed to both changes: using `scope_hint` instead of `global_hint` and passing the struct pointer to `vadvise()`. This makes the patch more future-proof but does not alter the immediate user-visible behavior. The unresolved syntax preference (`--global` vs `set --global`) from Ben Knoble’s earlier review is still pending, but the architectural questions are now settled.

The patch touches only `advice.c` and remains self-contained. No new tests have been added, but the change is low-risk and does not affect on-disk formats or core behavior. The thread is now waiting for v3, which should incorporate the agreed-upon design improvements. If the author follows through, this looks like a well-motivated, maintainable fix that addresses a real usability issue.
