This is a review reply in the ongoing thread about a small but user-facing documentation fix in the advice subsystem. The patch, originally from Vsevolod Myalitsin, updates the on-screen instructions for disabling the `defaultBranchName` advice message to recommend `--global` instead of `set`, ensuring the setting applies globally rather than just to the current repository.

Ben Knoble’s review is substantive but narrowly focused. He agrees with the goal but suggests a stylistic improvement: using `git config set --global` (the modern form) instead of `git config --global` (the older form). He also raises a forward-compatibility concern: the current implementation hardcodes the logic for `defaultBranchName` directly in the string formatting, which would make it awkward to extend later if other advice keys also need global-level recommendations. He proposes extracting a helper function (e.g., `is_global(key)`) to make the logic more maintainable.

The review does not question the patch’s correctness or motivation, nor does it identify any bugs or edge cases. It is a constructive, design-level suggestion aimed at improving the patch’s structure without changing its behavior. The discussion is now open on whether to adopt the more explicit `set --global` syntax and whether to refactor the logic for future extensibility.
