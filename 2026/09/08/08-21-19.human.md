This is a follow-up to a critical Windows-specific bug in `git worktree add` that deletes the `.git` directory when given an empty string (`""`) as the worktree path. The good news: the issue is already fixed and the fix is queued for merging into `master`.

Tuomas Ahola confirms the bug is real and provides two key links: a Git for Windows issue (#6346) and a lore.kernel.org thread showing the fix (a patch from Lukas Sandström, dated 2026-08-25). The fix is described as "queued to be merged to 'master'", meaning it has passed review and is awaiting integration into the next release. No further action is needed from the original reporter or other users—this is a resolved issue with a clear path to release.

The bug itself remains alarming: passing an empty string to `git worktree add` should never result in data loss, and the fact that it deletes the `.git` directory (not just the intended worktree) makes it especially severe. The fix likely addresses path validation or directory creation logic in `builtin/worktree.c`, though the exact details aren’t visible in this email. Windows users should watch for the fix in the next Git for Windows release or apply the patch manually if they’re at risk.
