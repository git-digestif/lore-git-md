This is the **v15 reroll of the `git history squash` feature**, a new subcommand that folds a range of commits into their oldest ancestor in a single tree operation, avoiding the repeated conflict stops of a rebase-based workflow. The series is now **functionally complete and ready for integration** after addressing the final technical blocker: enforcing **strict case-sensitive matching for autosquash markers** (e.g., rejecting `fixup! ABCDEF` while accepting `fixup! abcdef`).

The reroll makes two mechanical changes to Patch 7/8: replacing `istarts_with()` with `starts_with()` to reject uppercase OIDs, and fixing a typo in an adjacent comment. The rest of the series is unchanged from v14, which Junio C Hamano had already marked "Will replace" in his "What's cooking" report, signaling intent to queue it for the next release. The implementation is **decomposed into eight focused patches**, with the core logic split across five patches (4–8/8) covering range validation, ref protection, commit creation, and message editing. Test coverage is **extensive** (886 lines in `t/t3455-history-squash.sh`), and the documentation (`git-history.adoc`) and advice messages (`advice.c`) are fully updated.

The feature addresses a long-standing pain point: efficiently collapsing a linear or merge-commit-containing range while preserving descendant history. Key behaviors include:
- **Ref protection**: Rejects operations if any local branch descended from the squashed range would be left dangling, with an `advice()` message guiding users to `--update-refs=head`.
- **Merge commit handling**: Allows fully contained merges (single base) but rejects ranges with external parents or multiple bases.
- **Autosquash integration**: Groups `fixup!`/`squash!`/`amend!` markers under their targets in the default editor template, matching `git rebase -i --autosquash` behavior.
- **Strict marker resolution**: Enforces case-sensitive matching for OIDs, rejecting uppercase hex per Git’s historical convention.
