This is the first patch in Christian Couder’s v3 series introducing `uploadpack.lazyFetchTrusted`. It is a pure refactoring of the lazy-fetch logic in `promisor-remote.c` that extracts the scattered checks and control flow into a single, well-documented helper function, `lazy_fetch_objects()`.

The patch moves the `GIT_NO_LAZY_FETCH` environment-variable check from inside the per-remote loop to a single up-front call, eliminating redundant warnings and simplifying the code. It also converts the `try_promisor_remotes()` helper from an `int` to a `bool` return type, making its meaning clearer. The refactoring is mechanical and behavior-preserving: the same objects are fetched in the same order, and the same error messages are shown. The only observable difference is that `promisor_remote_init()` is now called only when lazy fetching is actually attempted, not when it is disabled.

This change is a preparatory step for the rest of the series. By isolating the lazy-fetch logic in one place, later patches can add recursion safeguards and server-side trust checks without cluttering the existing code paths. The commit message is clear and the diff is clean, making the patch easy to review. No new tests are added because the behavior is unchanged.
