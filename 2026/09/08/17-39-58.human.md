This is a review reply from Junio to the first patch in Christian Couder’s five-part series introducing `uploadpack.lazyFetchTrusted`. The patch is a pure refactoring of the promisor-remote subsystem, extracting lazy-fetching logic into a new helper function `lazy_fetch_objects()`.

Junio’s feedback is **surface-level**. His only substantive comment is on the clarity of the new function’s documentation: the phrase “from the (non-)accepted remotes” is confusing, and the description of `try_promisor_remotes()` should more precisely state that the function actually performs the fetch (not just checks whether it could be done) and document how the `remaining_oids` and `to_free` parameters are used. The rest of his reply is mechanical nitpicking about comment wording.

No technical objections are raised; the patch remains a clean, uncontroversial refactoring that sets the stage for the later patches in the series. Christian can address the documentation nits in a reroll without affecting the patch’s logic or integration readiness.
