Subject: [PATCH v3] refs/files-backend: skip packed transaction for root ref deletion
Series version: v3 (third iteration)

Thread type: bugfix patch series (single patch)

Core problem or goal
Fix an inefficiency in the refs files backend where deleting root refs (e.g., `AUTO_MERGE`, `CHERRY_PICK_HEAD`) unnecessarily attempts to lock the packed-refs file. Root refs are never packed, so the lock acquisition is redundant and causes `git update-ref --no-deref -d AUTO_MERGE` to fail when `.git/packed-refs.lock` is held. This also breaks post-commit cleanup in linked worktrees with read-only shared metadata.

- New/renamed symbols: none; uses existing `is_root_ref()` helper
- Behavior change: skips packed-ref transaction for root ref deletions only; preserves loose-ref locking and packed-ref deletion for non-root refs
- Flags involved: `REF_DELETING`, `REF_LOG_ONLY`, `REF_IS_PRUNING`
- Test coverage: adds tests for root ref deletion with `packed-refs.lock` held, mixed transactions (root + packed ref), and post-`pack-refs` loose ref verification
