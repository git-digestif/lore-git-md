Thread identity
Subject: [PATCH] ci: silence "missing tool" warnings on irrelevant platforms
Series version: v3 (two-patch series: preparatory cleanup + stricter behavior)
Originating author: Harald Nordgren
Thread type: patch (build system / CI)

Core problem or goal
Reduce noise in CI logs by ensuring warnings or failures for Perforce, Git LFS, and JGit occur only on platforms that require these tools. The thread has resolved the fundamental question in favor of strictness: tools required for a platform must be installed, causing the build to fail immediately if installation fails rather than allowing silent skips or warnings.

Current status
Under review; the v3 series is the active version. The preparatory cleanup (patch 1/2) is now unblocked: the GitLab CI pipeline Patrick Steinhardt linked to has passed, confirming the change—removing the macOS `xattr -d com.apple.quarantine` step for Perforce binaries—has no effect on GitLab CI runners, just as it had none on GitHub Actions. The patch is ready for a final positive review (Reviewed-by or Acked-by) from a contributor other than Junio C Hamano or Patrick Steinhardt. The stricter behavior patch (2/2) remains ready for final review as previously described.

Key technical details
- Files modified: `ci/install-dependencies.sh`
- New behavior (v3, patch 2): mandatory tool installation on platforms where Perforce, Git LFS, or JGit are required (ubuntu-* for all three, macos-* for Perforce), causing the build to fail immediately if installation fails. Version output is printed immediately after successful installation for confirmation.
- Preparatory change (v3, patch 1): removes the macOS `xattr -d com.apple.quarantine "$PERFORCE_TAR" || true` step, as it is a no-op (the attribute is never set by `wget` or `curl` on either GitHub Actions or GitLab CI runners).
- Old behavior (v1): warnings scoped to platform-specific `case` blocks, allowing tools to fail silently on other platforms.
- Simplification: v3 drops explicit `echo "error: ..." / exit 1` blocks for Perforce, Git LFS, and JGit, relying instead on `set -e` (already active via `ci/lib.sh`) to abort on the first failed install. This matches how every other install step in the file already works. The remaining `&&` chains are functionally redundant and acknowledged as such by Harald Nordgren, who intends to remove them in a future iteration.
- No functional change to Git itself; impact remains confined to CI behavior.
- Error-handling consistency: all install steps now rely on `set -e` for failure handling, eliminating redundancy.

Open questions and loose ends
- The v3 series still lacks an explicit positive review (Reviewed-by or Acked-by) from a contributor other than Junio C Hamano or Patrick Steinhardt.
- Minor stylistic question: whether to drop the redundant `&&` chains in the installation steps (acknowledged by Harald Nordgren as redundant but not yet addressed in a new patch version).
