Thread identity
Subject: [PATCH] ci: silence "missing tool" warnings on irrelevant platforms
Series version: standalone patch (v2 active, v3 proposed for preparatory cleanup)
Originating author: Harald Nordgren
Thread type: patch (build system / CI)

Core problem or goal
Reduce noise in GitHub Actions CI logs by ensuring warnings or failures for Perforce, Git LFS, and JGit occur only on platforms that require these tools. The thread has resolved the fundamental question in favor of strictness: tools required for a platform must be installed, causing the build to fail immediately if installation fails rather than allowing silent skips or warnings.

Current status
Under review; the v2 patch remains the active version, implementing Patrick Steinhardt’s proposal for mandatory tool installation. A v3 patch is now proposed to remove the macOS-specific `xattr` step for Perforce installation, as it is a no-op (the `com.apple.quarantine` attribute is never set by `wget` or `curl`). This change is preparatory, low-risk, and aligns with Patrick Steinhardt’s earlier suggestion, but it is not blocking the current patch’s progress. The v2 patch still awaits a formal positive review (Reviewed-by or Acked-by) from a contributor other than Junio C Hamano or Patrick Steinhardt.

Key technical details
- File modified: `ci/install-dependencies.sh`
- New behavior (v2): mandatory tool installation on platforms where Perforce, Git LFS, or JGit are required (ubuntu-* for all three tools, macos-* for Perforce), causing the build to fail immediately if installation fails. Version output (`p4d -V`, `git-lfs version`, `jgit version`) is printed immediately after successful installation for confirmation.
- Proposed preparatory change (v3): remove the macOS `xattr` step for Perforce (`xattr -d com.apple.quarantine "$PERFORCE_TAR" || true`), as it is a no-op and the `|| true` workaround is unnecessary.
- Old behavior (v1): warnings scoped to platform-specific `case` blocks, allowing tools to fail silently on other platforms.
- No functional change to Git itself; impact remains confined to CI behavior.
- Error-handling consistency:
  - `set -e` is already present in `ci/lib.sh`, making the patch’s explicit error checks redundant but harmless. The checks may still improve CI log clarity by surfacing immediate failure messages.
  - On macOS, the `tar` extraction for Perforce is mandatory, while the `xattr` step is proposed for removal.
  - Stylistic inconsistency in `rm` placement for Git LFS vs. Perforce on macOS (noted by Patrick Steinhardt, left as-is).

Open questions and loose ends
- The v2 patch still lacks an explicit positive review (Reviewed-by or Acked-by) from a contributor other than Junio (who has only confirmed the absence of objections) or Patrick Steinhardt (who has not provided a formal sign-off).
- Low-priority cleanup: remove the macOS `xattr` step for Perforce, as it is a no-op. This is now proposed as a preparatory change in a v3 patch, to be tested on GitLab CI before submission.
