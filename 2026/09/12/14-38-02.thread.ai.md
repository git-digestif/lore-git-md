Thread identity
Subject: [PATCH] ci: silence "missing tool" warnings on irrelevant platforms
Series version: v4 (two-patch series: preparatory cleanup + stricter behavior)
Originating author: Harald Nordgren
Thread type: patch (build system / CI)

Core problem or goal
Reduce CI log noise by ensuring warnings or failures for Perforce, Git LFS, and JGit occur only on platforms that require these tools. The thread has resolved the fundamental question in favor of strictness: tools required for a platform must be installed, causing the build to fail immediately if installation fails rather than allowing silent skips or warnings.

Current status
Under review; the v4 series is the active version. The preparatory cleanup (patch 1/2) is accepted in principle by Junio C Hamano and Patrick Steinhardt, with its commit message updated to explicitly state that the macOS `xattr` step has been a no-op since the 2022 switch from Homebrew to direct `wget`/`curl` downloads. The stricter behavior patch (2/2) is now technically complete, removing redundant `&&` chains and error-handling blocks, and has received Patrick Steinhardt’s informal approval ("this version looks good to me"). Neither patch has yet received an explicit positive review (Reviewed-by or Acked-by) from a contributor other than Junio C Hamano or Patrick Steinhardt, but the series is unblocked and appears uncontroversial.

Key technical details
- Files modified: `ci/install-dependencies.sh`
- New behavior (v4, patch 2): mandatory tool installation on platforms where Perforce, Git LFS, or JGit are required (ubuntu-* for all three, macos-* for Perforce), causing the build to fail immediately if installation fails. Version output is printed immediately after successful installation for confirmation. Redundant `&&` chains between `wget`, `tar`, and `chmod` steps removed, relying solely on `set -e` (already active via `ci/lib.sh`) for failure handling. The presence checks and warnings at the end of the script are removed because the script will have already exited if installation failed.
- Preparatory change (v4, patch 1): removes the macOS `xattr -d com.apple.quarantine "$PERFORCE_TAR" || true` step, as it has been a no-op since 2022 when the install method switched from Homebrew to direct `wget`/`curl` downloads; neither tool sets the attribute, and GitHub Actions and GitLab CI runners do not use Safari or Finder. Commit message now leads with this observation.
- Old behavior (v1): warnings scoped to platform-specific `case` blocks, allowing tools to fail silently on other platforms.
- Simplification: v4 drops all explicit `echo "error: ..." / exit 1` blocks and redundant `&&` chains for Perforce, Git LFS, and JGit, matching how every other install step in the file already works.
- No functional change to Git itself; impact remains confined to CI behavior.
- Error-handling consistency: all install steps now rely uniformly on `set -e` for failure handling.
