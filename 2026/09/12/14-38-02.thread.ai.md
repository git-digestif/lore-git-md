Thread identity
Subject: [PATCH] ci: silence "missing tool" warnings on irrelevant platforms
Series version: standalone patch (v2, implementing stricter approach)
Originating author: Harald Nordgren
Thread type: patch (build system / CI)

Core problem or goal
Reduce noise in GitHub Actions CI logs by ensuring warnings or failures for Perforce, Git LFS, and JGit occur only on platforms that require these tools. The fundamental question—whether CI should allow optional tools to be skipped with warnings or enforce mandatory installation—has been resolved in favor of strictness: tools required for a platform must be installed, causing the build to fail if installation fails.

Current status
Under review; the original patch has been superseded by a v2 patch that implements Patrick Steinhardt’s proposal: replace conditional tool installation with mandatory checks, eliminating warnings entirely by making failures explicit. The v2 patch is now the active version.

Key technical details
- File modified: `ci/install-dependencies.sh`
- New behavior (v2): mandatory tool installation on platforms where Perforce, Git LFS, or JGit are required (ubuntu-* for all three tools, macos-* for Perforce), causing the build to fail immediately if installation fails. Version output (p4d -V, git-lfs version, jgit version) is printed immediately after successful installation for confirmation.
- Old behavior (v1): warnings scoped to platform-specific `case` blocks, allowing tools to fail silently on other platforms.
- No functional change to Git itself; impact remains confined to CI behavior.
- Symbols: none (script-only change).

Open questions and loose ends
- Maintenance burden: future platform additions must update the installation logic to include required tools, or the build will fail. This is now an explicit requirement rather than a risk of silent skips.

Participant positions
- **Junio C Hamano**: reviewed the original patch, considered the trade-off (log noise vs. maintenance burden) reasonable, and invited a second review. Noted the risk of silent skips on new platforms but deemed it low. Position remains unchanged; no explicit agreement or disagreement with the stricter approach.
- **Patrick Steinhardt**: challenged the original patch’s premise, arguing that optional tools create a risk of silent test skips. Proposed a stricter approach: tools required for a platform should be mandatory, causing the build to fail if installation fails. This position is now the agreed direction and has been implemented in the v2 patch.
- **Harald Nordgren**: agreed in principle to Patrick’s critique, signaling no technical disagreement. The original patch was withdrawn in favor of the stricter approach, and the v2 patch implements it. No substantive objections remain.
