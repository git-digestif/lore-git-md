Thread identity
Subject: [PATCH] ci: silence "missing tool" warnings on irrelevant platforms
Series version: v3 (two-patch series: preparatory cleanup + stricter behavior)
Originating author: Harald Nordgren
Thread type: patch (build system / CI)

Core problem or goal
Reduce noise in GitHub Actions CI logs by ensuring warnings or failures for Perforce, Git LFS, and JGit occur only on platforms that require these tools. The thread has resolved the fundamental question in favor of strictness: tools required for a platform must be installed, causing the build to fail immediately if installation fails rather than allowing silent skips or warnings.

Current status
Under review; the v3 series is now the active version. It consists of two patches:
1. Preparatory cleanup: removes the macOS-specific `xattr -d com.apple.quarantine` step for Perforce binaries, which has been a silent no-op since Perforce installation moved off Homebrew in 2022. The commit message documents the historical context and confirms the step has had no effect on GitHub Actions runners for over four years.
2. Stricter behavior (just posted): implements the agreed consensus by failing the build immediately if Perforce, Git LFS, or JGit fail to install on platforms that require them (ubuntu-* for all three, macos-* for Perforce). The patch removes dead presence checks and warnings, moves version output (`p4d -V`, `git-lfs version`, `jgit version`) inline after successful installation, and relies on `set -e` (already active via `ci/lib.sh`) to abort on the first failed install, simplifying the code by 19 lines.

The v3 series is ready for final review and a formal positive sign-off (Reviewed-by or Acked-by) from a contributor other than Junio C Hamano or Patrick Steinhardt.

Key technical details
- Files modified: `ci/install-dependencies.sh`
- New behavior (v3, patch 2): mandatory tool installation on platforms where Perforce, Git LFS, or JGit are required (ubuntu-* for all three, macos-* for Perforce), causing the build to fail immediately if installation fails. Version output is printed immediately after successful installation for confirmation.
- Preparatory change (v3, patch 1): removes the macOS `xattr -d com.apple.quarantine "$PERFORCE_TAR" || true` step, as it is a no-op (the attribute is never set by `wget` or `curl`).
- Old behavior (v1): warnings scoped to platform-specific `case` blocks, allowing tools to fail silently on other platforms.
- Simplification: v3 drops explicit `echo "error: ..." / exit 1` blocks for Perforce, Git LFS, and JGit, relying instead on `set -e` (already active via `ci/lib.sh`) to abort on the first failed install. This matches how every other install step in the file already works.
- No functional change to Git itself; impact remains confined to CI behavior.
- Error-handling consistency: all install steps now rely on `set -e` for failure handling, eliminating redundancy.
