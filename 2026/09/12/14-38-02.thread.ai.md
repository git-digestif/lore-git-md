Subject: [PATCH] ci: silence "missing tool" warnings on irrelevant platforms
Series version: standalone patch (now superseded by new direction)
Originating author: Harald Nordgren
Thread type: patch (build system / CI)

Core problem or goal
Reduce noise in GitHub Actions CI logs by ensuring warnings or failures for Perforce, Git LFS, and JGit occur only on platforms that require these tools. The fundamental question—whether CI should allow optional tools to be skipped with warnings or enforce mandatory installation—has been resolved in favor of strictness: tools required for a platform must be installed, causing the build to fail if installation fails.

Current status
Under review; original patch is now superseded. The discussion has converged on Patrick Steinhardt’s proposal: replace conditional tool installation with mandatory checks, eliminating warnings entirely by making failures explicit. No follow-up patch has been posted yet, but the direction is agreed.

Key technical details
- File to be modified: `ci/install-dependencies.sh`
- New behavior (agreed direction): mandatory tool installation on platforms where Perforce, Git LFS, or JGit are required (ubuntu-* for all three tools, macos-* for Perforce), causing the build to fail if installation fails
- Alternative behavior (original patch): warnings scoped to platform-specific `case` blocks, allowing tools to fail silently on other platforms
- No functional change to Git itself; impact remains confined to CI behavior
- Symbols: none (script-only change)

Open questions and loose ends
- Mechanics of implementation: how to structure the mandatory installation checks in `ci/install-dependencies.sh` to ensure new platforms requiring these tools are explicitly listed, avoiding silent skips
- Maintenance burden: future platform additions must update the installation logic to include required tools, or the build will fail

Participant positions

Noted the risk of silent skips on new platforms but deemed it low. Position remains unchanged; no explicit agreement or disagreement with the stricter approach.
- **Patrick Steinhardt**: challenged the original patch’s premise, arguing that optional tools create a risk of silent test skips. - **Harald Nordgren**: agreed in principle to Patrick’s critique, signaling no technical disagreement. The original patch is effectively withdrawn in favor of the stricter approach. No code changes included in this reply.
