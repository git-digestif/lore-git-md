Thread identity
Subject: [PATCH] ci: silence "missing tool" warnings on irrelevant platforms
Series version: standalone patch (v2, implementing stricter approach)
Originating author: Harald Nordgren
Thread type: patch (build system / CI)

Core problem or goal
Reduce noise in GitHub Actions CI logs by ensuring warnings or failures for Perforce, Git LFS, and JGit occur only on platforms that require these tools. The thread has resolved the fundamental question in favor of strictness: tools required for a platform must be installed, causing the build to fail immediately if installation fails rather than allowing silent skips or warnings.

Current status
Under review; the v2 patch is the active version, implementing Patrick Steinhardt’s proposal for mandatory tool installation. Junio C Hamano’s review confirms the patch is a straightforward implementation of the agreed direction and raises no new objections. The patch is ready for final review and appears uncontroversial.

Key technical details
- File modified: `ci/install-dependencies.sh`
- New behavior (v2): mandatory tool installation on platforms where Perforce, Git LFS, or JGit are required (ubuntu-* for all three tools, macos-* for Perforce), causing the build to fail immediately if installation fails. Version output (`p4d -V`, `git-lfs version`, `jgit version`) is printed immediately after successful installation for confirmation.
- Old behavior (v1): warnings scoped to platform-specific `case` blocks, allowing tools to fail silently on other platforms.
- No functional change to Git itself; impact remains confined to CI behavior.
- Symbols: none (script-only change).
- Minor consistency note: on macOS, the `xattr` step for Perforce is allowed to fail silently (`|| true`), while the `tar` extraction is not. This is intentional and avoids complicating error handling for a non-critical step.

Open questions and loose ends
- Maintenance burden: future platform additions must update the installation logic to include required tools, or the build will fail. This is now an explicit requirement rather than a risk of silent skips.
- No unresolved technical questions or objections remain.

Participant positions
- **Junio C Hamano**: reviewed the original patch, considered the trade-off (log noise vs. maintenance burden) reasonable, and invited a second review. Reviewed the v2 patch, confirmed it implements the agreed stricter approach, and raised a minor consistency question about macOS Perforce installation (left as-is). Position: no objections; patch is ready for final review.
- **Patrick Steinhardt**: challenged the original patch’s premise, arguing that optional tools create a risk of silent test skips. Proposed a stricter approach: tools required for a platform should be mandatory, causing the build to fail if installation fails. This position is now the agreed direction and has been implemented in the v2 patch.
- **Harald Nordgren**: agreed in principle to Patrick’s critique, withdrew the original patch in favor of the stricter approach, and implemented the v2 patch. No substantive objections remain.
