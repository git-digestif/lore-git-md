Thread identity
Subject: [PATCH] ci: silence "missing tool" warnings on irrelevant platforms
Series version: standalone patch (v2, implementing stricter approach)
Originating author: Harald Nordgren
Thread type: patch (build system / CI)

Core problem or goal
Reduce noise in GitHub Actions CI logs by ensuring warnings or failures for Perforce, Git LFS, and JGit occur only on platforms that require these tools. The thread has resolved the fundamental question in favor of strictness: tools required for a platform must be installed, causing the build to fail immediately if installation fails rather than allowing silent skips or warnings.

Current status
Under review; the v2 patch remains the active version, implementing Patrick Steinhardt’s proposal for mandatory tool installation. Junio C Hamano’s feedback was clarified as not constituting a full endorsement, and the patch still requires a "real positive review" from another contributor. Patrick Steinhardt’s review confirmed the patch correctly implements the agreed behavior, has no technical blockers, and is ready for final review. The follow-up discussion confirmed that the patch’s error-handling logic, while redundant with `set -e` in `ci/lib.sh`, is harmless and may improve CI log clarity. No substantive changes are expected; the only remaining step is a formal positive review (Reviewed-by or Acked-by) from a contributor other than Junio or Patrick.

Key technical details
- File modified: `ci/install-dependencies.sh`
- New behavior (v2): mandatory tool installation on platforms where Perforce, Git LFS, or JGit are required (ubuntu-* for all three tools, macos-* for Perforce), causing the build to fail immediately if installation fails. Version output (`p4d -V`, `git-lfs version`, `jgit version`) is printed immediately after successful installation for confirmation.
- Old behavior (v1): warnings scoped to platform-specific `case` blocks, allowing tools to fail silently on other platforms.
- No functional change to Git itself; impact remains confined to CI behavior.
- Error-handling consistency:
  - `set -e` is already present in `ci/lib.sh`, making the patch’s explicit error checks redundant but harmless. The checks may still improve CI log clarity by surfacing immediate failure messages.
  - On macOS, the `xattr` step for Perforce is allowed to fail silently (`|| true`), while the `tar` extraction is not. This is intentional: the attribute is never set by `wget` or `curl`, so the step is a no-op. Patrick Steinhardt suggested removing the step entirely in a future preparatory patch.
  - Stylistic inconsistency in `rm` placement for Git LFS vs. Perforce on macOS (noted by Patrick Steinhardt, left as-is).

Open questions and loose ends
- The patch still lacks an explicit positive review (Reviewed-by or Acked-by) from a contributor other than Junio (who has only confirmed the absence of objections) or Patrick Steinhardt (who has not provided a formal sign-off).
- Low-priority cleanup: remove the macOS `xattr` step for Perforce, as it is a no-op. This is deferred to a separate patch.
