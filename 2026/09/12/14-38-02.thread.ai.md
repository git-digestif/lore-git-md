Thread identity
Subject: [PATCH] ci: silence "missing tool" warnings on irrelevant platforms
Series version: standalone patch
Originating author: Harald Nordgren
Thread type: patch (build system / CI)

Core problem or goal
Reduce noise in GitHub Actions CI logs by restricting "missing tool" warnings for Perforce, Git LFS, and JGit to only those platforms that actually attempt to install them. The fundamental question raised is whether these tools should be optional at all: Patrick Steinhardt argues that optional tools create a risk of silent test skips, and proposes that any tool required for a platform should be mandatory, causing the build to fail if it cannot be installed.

Current status
Under review; no prior versions. Junio considers the trade-off (reduced log noise vs. maintenance burden) reasonable and invites a second review. Patrick’s reply challenges the patch’s premise, suggesting a stricter approach that would eliminate warnings by making tool installation mandatory where expected.

Key technical details
- File touched: `ci/install-dependencies.sh`
- New behavior (proposed in patch): warnings are scoped to platform-specific `case` blocks (ubuntu-* for all three tools, macos-* additionally for Perforce)
- Alternative behavior (proposed in discussion): make tool installation mandatory on platforms where the tools are required, causing the build to fail if installation fails
- No functional change to Git itself; only CI behavior is affected
- Symbols: none (script-only change)

Open questions and loose ends
- Maintenance burden: future platform additions that require Perforce, Git LFS, or JGit must remember to update the `case` blocks in `ci/install-dependencies.sh` to avoid silent skips instead of warnings (applies to Harald’s patch).
- Fundamental design question: should CI enforce mandatory installation of tools required for a platform, or allow optional tools to be skipped with warnings? This determines whether the patch’s approach is acceptable or if a stricter policy is needed.

Participant positions
- **Junio C Hamano**: reviewed the patch, considers the trade-off (log noise vs. maintenance burden) reasonable, and invites a second review. Notes the risk of silent skips on new platforms but deems it low.
- **Patrick Steinhardt**: challenges the patch’s premise, arguing that optional tools create a risk of silent test skips. Proposes that tools required for a platform should be mandatory, causing the build to fail if installation fails. This would eliminate warnings entirely by making failures explicit. Position is substantive and engages with the patch’s underlying assumptions.
