This is the main feature patch (2/2) in Souma’s v3 series teaching `git history` to sign rewritten commits. It extends the `drop`, `fixup`, `reword`, and `split` subcommands to respect the `commit.gpgsign` configuration variable and the `-S/--gpg-sign` and `--no-gpg-sign` command-line options, with command-line options overriding configuration and the last option winning.

The patch touches `builtin/history.c`, threads a new `sign_commit` field through the replay machinery (`replay.c` plumbing was split out in patch 1/3), and adds GPG-gated regression tests in `t/t3451-history-reword.sh`, `t/t3452-history-split.sh`, `t/t3453-history-fixup.sh`, and `t/t3454-history-drop.sh`. The documentation in `git-history.txt` is updated to list the new options in the synopsis and describe their behavior. On-disk format is unchanged; only the commit object’s signature trailer is added when signing is enabled.

All substantive review feedback from Patrick Steinhardt (v1 and v2) has been addressed: the replay API plumbing remains split into a dedicated preparatory patch, the documentation and tests are folded into this patch, and the commit message is now trimmed. The series is under active review and looks close to ready, pending any remaining minor cleanups. The conceptual trade-off—whether signing rewritten commits that were originally authored by someone else is desirable or misleading—remains unresolved but is discussed in the commit message.
