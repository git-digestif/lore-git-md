This thread is about a simple but important bugfix to `git pull`: it currently segfaults if a merge head reference is corrupted (for example, by a concurrent fetch or garbage collection). Jiri Kuncar’s patch adds a NULL guard in `builtin/pull.c` so that the command fails gracefully instead of crashing, letting the normal merge machinery report the broken object.

Junio C Hamano has reviewed the patch and considers it a good, minimal improvement. He notes that while the fix might feel like a workaround—it doesn’t diagnose corruption at every lookup site—it’s a pragmatic choice that doesn’t block future refactoring. The only suggested change is a small tweak to the test: replacing the object file truncation with outright removal for better portability. The test itself is thorough, covering the edge case by forcing loose object storage and ensuring the object is reachable before corruption.

The patch is now effectively ready to merge, pending the minor test adjustment. No other objections or open questions have been raised.
