This thread is about a bugfix for `git pull` that prevents a segmentation fault when encountering an invalid merge head. The issue occurs when `lookup_commit_reference()` returns NULL due to a corrupted merge head reference—possibly caused by concurrent operations like parallel fetches or garbage collection. The fix, authored by Jiri Kuncar, adds NULL checks in `builtin/pull.c` to handle this gracefully, treating the failed lookup as "not up to date" and allowing the operation to fall back to a normal merge, which reports the broken object instead of crashing.

The patch includes a new test in `t/t5520-pull.sh` that simulates the scenario by corrupting an object in a cloned repository and verifying that `git pull` fails safely. The test uses `fetch.unpackLimit=1000` to force loose object storage and ensures the object is reachable before corruption. The fix is minimal, focused, and well-motivated, with clear commit messaging and thorough test coverage. There are no objections or requests for changes so far, and the patch appears ready for review and potential merging.
