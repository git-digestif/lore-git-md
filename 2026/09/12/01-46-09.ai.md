This is a bugfix patch targeting the refs subsystem, specifically the files backend. Ariel Keselman addresses a long-standing inefficiency where deleting root refs (like `AUTO_MERGE`, `CHERRY_PICK_HEAD`, etc.) unnecessarily attempts to lock the packed-refs file, even though root refs are never packed. The patch skips the packed-ref transaction for root ref deletions while preserving existing behavior for all other refs.

The motivation is clear and practical: holding `.git/packed-refs.lock` currently causes `git update-ref --no-deref -d AUTO_MERGE` to fail, which also breaks post-commit cleanup in linked worktrees with read-only shared metadata. The commit message provides concrete examples of affected workflows (commit cleanup, `CHERRY_PICK_HEAD`/`REVERT_HEAD` deletion) and explains the root cause (root refs cannot be packed, so the lock acquisition is redundant).

The implementation is minimal and surgical: a single condition is added to `files_transaction_prepare()` in `refs/files-backend.c` to check `!is_root_ref(update->refname)` before initiating a packed transaction. The change preserves loose-ref locking and packed-ref deletion for non-root refs, maintaining existing safety guarantees. The accompanying tests in `t/t0600-reffiles-backend.sh` are thorough, covering both the happy path (deleting a root ref with `packed-refs.lock` held) and the mixed case (a transaction deleting both a root ref and a packed branch, which should still fail if the lock is held).

The patch appears well-crafted and addresses a real annoyance. The v3 iteration incorporates feedback from Patrick Steinhardt, adding verification that `AUTO_MERGE` remains loose after `pack-refs` and testing mixed transactions more directly. The test suite passes fully, including SHA-256 compatibility. Key technical details for follow-up discussion include the `is_root_ref()` helper, the `REF_DELETING`/`REF_LOG_ONLY`/`REF_IS_PRUNING` flags, and the `refs list --include-root-refs` plumbing command used in tests. The patch is likely to be uncontroversial, as it fixes an obvious inefficiency without changing behavior for non-root refs.
