This thread is about a small but practical cleanup to Git’s macOS CI setup. Harald Nordgren sent a patch (v2) that removes a redundant `brew link --force gettext` command from the dependency installation script. The command was originally added to ensure gettext (a Homebrew package) was symlinked into the system path, but a 2020 Homebrew policy change made gettext no longer "keg-only," so it’s now linked by default on fresh installs. The patch’s goal is to eliminate spurious "Already linked" warnings in CI logs without breaking anything.

The patch was initially blocked because the CI pipeline Harald linked didn’t actually run the macOS job, leaving its safety unproven. In this latest email, Harald provided a new pipeline link showing the macOS job passing with the patch applied, confirming that gettext remains correctly exposed in the system path. Patrick Steinhardt had raised the original concern, and with this new evidence, the patch is now unblocked. No further technical objections or questions are open, and the patch is likely to be merged unless new concerns arise.

The change is minimal—just a one-line deletion in `ci/install-dependencies.sh`—and doesn’t touch any core Git functionality, test coverage, or on-disk formats. It’s a straightforward cleanup that reduces log noise in macOS CI runs.
