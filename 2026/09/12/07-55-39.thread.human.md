This thread is about a small but important cleanup to Git’s macOS CI setup: removing a redundant `brew link --force gettext` command that was added years ago when gettext was a keg-only Homebrew formula. The patch itself is trivial—one line deleted from `ci/install-dependencies.sh`—but its justification hinges on whether the command is truly unnecessary today.

Harald Nordgren posted v2 of the patch, which addressed all feedback from v1, including Patrick Steinhardt’s requests for empirical evidence (a passing CI pipeline) and historical context (the 2020 Homebrew policy change that made gettext no longer keg-only). At that point, the patch seemed ready for approval. However, Patrick’s latest reply reveals a critical flaw: the GitHub Actions pipeline Harald linked as proof *did not actually run the macOS job*, meaning there’s no evidence that removing the command won’t break gettext’s availability in the CI environment. The thread is now blocked until Harald provides a valid CI run or a convincing explanation for why the skipped jobs don’t matter.

The historical rationale for the change remains sound—gettext is no longer keg-only—but without empirical validation, the patch can’t move forward. No other reviewers have weighed in, and the ball is back in Harald’s court to either fix the CI evidence or clarify why it’s unnecessary.
