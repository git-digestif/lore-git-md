This thread is about a small but practical cleanup to Git’s macOS CI setup. Harald Nordgren sent a patch to remove a redundant `brew link --force gettext` command from the dependency installation script. The command was originally added to ensure the gettext Homebrew formula (which is keg-only) was symlinked into the system path, but it now emits a spurious “Already linked” warning in every macOS job log, cluttering the output.

The patch itself is trivial—just deleting one line—but Patrick Steinhardt initially asked for two things: empirical evidence that the change wouldn’t break anything, and an explanation of why the command was originally added and why it’s no longer needed. Harald provided the first in the initial version by linking to a passing GitHub Actions CI run, and in this update (v2) he’s addressed the second by revising the commit message to include the historical context. The new message explains that Homebrew changed its policy in 2020, making gettext no longer keg-only, so a fresh install now automatically links it into the prefix. That rationale, along with the CI validation, should satisfy Patrick’s concerns.

The patch is now ready for a final review. It’s a low-risk, platform-specific change that doesn’t touch any core Git functionality, and the updated commit message makes the motivation clear. Unless someone spots an edge case in the GitLab CI pipeline (which hasn’t been tested yet), this should be straightforward to merge.
