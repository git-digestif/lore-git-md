This is the first patch in a three-part documentation series that extends the AsciiDoc linting script to enforce backtick-quoting for commands (e.g., `command::`) in addition to options (e.g., `--option::`) in synopsis-style man pages. The change is mechanical and confined to `Documentation/lint-documentation-style.perl`, adjusting a regex to remove the requirement for a leading `-` and tightening the pattern to avoid false matches on `linkgit:` references. The patch is part of Todd Zullinger’s effort to fix inconsistent formatting in the `git-refs` and `git-pack-refs` man pages, aligning with Jean-Noël Avila’s broader synopsis-style conversion initiative.

The regex modification is straightforward: `[^:]*` replaces `.*` to exclude lines containing colons (like `linkgit:` references), and the `-` prefix is dropped to match both commands and options. The change is uncontroversial and follows established documentation conventions. No functional behavior changes to Git are introduced; the patch only affects the linting script’s enforcement rules. This patch sets the stage for the subsequent two patches, which will apply the corrected quoting to the affected man pages.
