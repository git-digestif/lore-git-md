This is the third iteration of Souma’s patch series teaching `git history` to sign rewritten commits. The series is now down to two patches after incorporating all feedback from v2: the replay API plumbing is consolidated into patch 1, and the feature implementation, documentation, and tests are in patch 2.

The core goal remains unchanged: `git history drop`, `fixup`, `reword`, and `split` now respect `commit.gpgsign` and the `-S/--gpg-sign` and `--no-gpg-sign` command-line options, with the same precedence rules as `git commit`. The implementation threads the signing key through the replay machinery and direct commit creation, preserving the original author identity while attesting the rewrite with the current committer’s signature.

Changes since v2 are purely cosmetic: commit messages are shorter, the implementation commit is now titled “history: sign rewritten commits” instead of “builtin/history: sign rewritten commits”, and a formatting nit in the `OPT_HISTORY_GPG_SIGN` macro is fixed. The range-diff shows that the substantive code changes are identical to v2, which already addressed Patrick Steinhardt’s earlier feedback.

The series looks ready: the code is clean, the tests cover all flag/config combinations, and the documentation is clear. The only open question is the conceptual trade-off around signing commits authored by someone else, but that discussion is now explicitly called out in the commit message and does not block merging.
