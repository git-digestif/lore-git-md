This thread is about a small but real bugfix in Git’s refs subsystem. Ariel Keselman identified that deleting root refs (like `AUTO_MERGE` or `CHERRY_PICK_HEAD`) unnecessarily tries to lock the packed-refs file, even though root refs are never packed. This inefficiency can cause `git update-ref --no-deref -d AUTO_MERGE` to fail when `.git/packed-refs.lock` is held, breaking post-commit cleanup in linked worktrees with read-only shared metadata.

The fix is a single patch that skips the packed-ref transaction entirely for root ref deletions. Ariel posted three versions, incorporating feedback from Patrick Steinhardt, who reviewed the changes substantively—focusing on correctness and test coverage rather than just style. The v3 patch adds thorough tests for root ref deletion with `packed-refs.lock` held, mixed transactions (root + packed ref), and verification that `AUTO_MERGE` remains loose after `pack-refs`. Patrick has now explicitly approved the patch, calling it “good to me,” so it’s ready for Junio to pick up in the next integration cycle unless another reviewer raises a late objection.

The patch is self-contained, touching only `refs/files-backend.c` and the test suite, and doesn’t change any on-disk formats or behavior for non-root refs. With Patrick’s approval, the thread is effectively closed from a technical standpoint.
