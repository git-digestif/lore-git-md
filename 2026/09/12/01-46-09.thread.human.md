This thread is about a small but important bugfix for Git's refs files backend. Ariel Keselman identified an inefficiency where deleting root refs (like `AUTO_MERGE` or `CHERRY_PICK_HEAD`) unnecessarily tried to lock the packed-refs file, even though root refs are never packed. This caused `git update-ref --no-deref -d AUTO_MERGE` to fail when `.git/packed-refs.lock` was held, breaking post-commit cleanup in linked worktrees with read-only shared metadata.

The fix, now in its third version, skips the packed-ref transaction entirely for root ref deletions while preserving all other locking behavior. Patrick Steinhardt reviewed and approved the patch, and Junio C Hamano has now queued it for the `next` integration branch. Since this is post-`rc1` for Git 2.56, it won't graduate to `master` until after the final release unless it's deemed an emergency fix. The patch is self-contained, touches only `refs/files-backend.c` and its test file, and carries no on-disk format changes. Unless a regression surfaces during integration testing, this thread is effectively closed.
