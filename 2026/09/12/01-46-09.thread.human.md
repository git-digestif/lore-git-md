This thread is about a targeted bugfix for Git’s refs subsystem, specifically the files backend. Ariel Keselman identified and fixed an inefficiency where deleting root-level refs (like `AUTO_MERGE` or `CHERRY_PICK_HEAD`) unnecessarily attempted to lock the `packed-refs` file, even though these refs are never packed. The issue caused failures in workflows like post-commit cleanup in linked worktrees with read-only shared metadata, particularly when `git update-ref --no-deref -d AUTO_MERGE` was called while `.git/packed-refs.lock` was held.

The patch is minimal and surgical: it adds a single condition in `files_transaction_prepare()` to skip packed-ref transactions for root ref deletions while preserving existing behavior for all other refs. The implementation includes thorough tests covering edge cases, such as mixed transactions deleting both root and non-root refs. Feedback from Patrick Steinhardt was incorporated in the v3 iteration, which added verification that `AUTO_MERGE` remains loose after `pack-refs` and improved test coverage for mixed transactions. The patch is uncontroversial, as it fixes a clear inefficiency without altering behavior for non-root refs, and the test suite passes fully, including SHA-256 compatibility. No objections or open questions remain, and the patch is likely ready for merging.
