# Thread deltas

## 2026/09/12

- [2026/09/12/14-38-02 by Harald Nordgren via GitGitGadget <gitgitgadget@gmail.com>] Harald Nordgren submitted a patch to `ci/install-dependencies.sh` scoping the perforce, git-lfs, and JGit presence checks to only the platforms that attempt to install them (ubuntu-* for all three, plus macos-* for perforce), because these tools test git's own interop code rather than platform-specific behavior and other platforms (debian, i386/ubuntu, alpine, fedora, almalinux) never install them yet were warning anyway; published as PR #2403.

## 2026/09/25

- [2026/09/25/19-02-13 by Junio C Hamano <gitster@pobox.com>] Junio C Hamano reviewed Harald Nordgren's patch to scope perforce/git-lfs/JGit warnings to the platforms that install them, calling it a "no brainer" to check correctness under the assumption nothing changes externally, and concluded it makes sense overall despite the higher maintenance cost of keeping the platform list in sync, noting that if p4 or jgit testing is later added to another platform the relevant tests (t98xx for p4, JGIT-prerequisite tests) silently skip when the tool is absent so a missing platform entry might go unnoticed for a while.
- [2026/09/25/19-02-13 by Junio C Hamano <gitster@pobox.com>] Junio C Hamano asked for volunteers to offer a second pair of eyes on the patch.

## 2026/09/28

- [2026/09/28/12-31-11 by Patrick Steinhardt <ps@pks.im>] Patrick Steinhardt suggests that instead of warning, the CI build should fail outright if perforce, git-lfs, or JGit fail to install, arguing that the current warnings give a false sense of confidence because such failures might go unnoticed while tests are skipped and the pipeline stays green.
- [2026/09/28/16-13-00 by Harald Nordgren <haraldnordgren@gmail.com>] Harald Nordgren agrees with Patrick Steinhardt's suggestion to fail the build outright on installation failures ("Fine by me!").
