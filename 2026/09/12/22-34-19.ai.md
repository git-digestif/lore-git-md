This is a bugfix patch for `git pull` that prevents a segmentation fault when an invalid merge head is encountered.

The patch adds NULL checks around calls to `lookup_commit_reference()` in `builtin/pull.c`. These guards prevent crashes when the function returns NULL, which can happen if a merge head reference is corrupted—possibly due to concurrent operations like parallel fetches or garbage collection racing on the same repository. Instead of crashing, the code now treats the failed lookup as "not up to date," allowing the caller to fall back to a normal merge, which will report the broken object rather than segfaulting.

The patch includes a new test in `t/t5520-pull.sh` that simulates the scenario: it creates a repository with two branches, clones it, corrupts an object by truncating its file, and verifies that `git pull` fails gracefully rather than crashing. The test uses `fetch.unpackLimit=1000` to force loose object storage and `git commit-graph write` to ensure the object is reachable before corruption.

The commit message is clear and concise, explaining both the problem (crashes due to invalid merge heads) and the solution (NULL guards). The test coverage is thorough, covering the edge case explicitly. The patch itself is minimal and focused, touching only the necessary code paths. This looks like a well-motivated and well-executed fix for a real-world issue.
