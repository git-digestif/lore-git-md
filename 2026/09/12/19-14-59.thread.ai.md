Subject: [PATCH 0/3] doc: lint and fix backtick quoting in git-refs and git-pack-refs
Series version: v3 (patches 1/2 and 2/2; patch 1/2 incorporates Junio’s requested correction to commit message and backtick-quoting scope in `pack-refs-options.adoc`)
Originating author: Todd Zullinger
Thread type: patch series (documentation-only)

Core problem or goal
Ensure consistent backtick-quoting of command, option, and subcommand references in the synopsis-style AsciiDoc source for the `git-refs` and `git-pack-refs` man pages. Inconsistent quoting causes visual formatting discrepancies in the rendered output (e.g., some commands or subcommands appear in bold while others do not).

Current status
Merged to `master`. Junio C Hamano accepted the v3 series, confirming the commit message wording and backtick-quoting scope correction (restricting backticks to configuration keys in `pack-refs-options.adoc` while leaving command-line options unquoted). The series was queued for integration and is now part of the mainline codebase. No functional changes to Git were introduced; the series is purely visual and aligns with the ongoing synopsis-style documentation effort.

Key technical details
- Files touched: `Documentation/git-refs.adoc`, `Documentation/git-pack-refs.adoc`, `Documentation/technical/pack-refs-options.adoc`.
- New or renamed symbols: none (documentation-only).
- Old-vs-new behavior: no functional change to Git; only affects rendered man page and HTML appearance. Patch 1/2 (v3) converts the SYNOPSIS block in `git-pack-refs.adoc` from `[verse]` to `[synopsis]`, removes single-quote formatting around the command name (`git pack-refs`), backtick-quotes all option terms (`--all`, `--no-prune`, `--auto`, `--include`, `--exclude`) in the OPTIONS section, and updates the included `pack-refs-options.adoc` to backtick-quote configuration keys (`core.packedRefsTimeout`, etc.) while leaving command-line options unquoted. Patch 2/2 (v3) mechanically backtick-quotes all subcommand entries in `git-refs.adoc` (`list`, `exists`, `optimize`, `create`, `delete`, `update`, and `rename`) and replaces a literal `<branch>` placeholder with an italicized version.
- Test coverage: none required; the changes are mechanical and align with the ongoing synopsis-style documentation effort.
