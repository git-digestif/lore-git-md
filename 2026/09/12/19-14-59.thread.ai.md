Core problem or goal
Ensure consistent backtick-quoting of command, option, and subcommand references in the synopsis-style AsciiDoc source for the `git-refs` and `git-pack-refs` man pages. Inconsistent quoting causes visual formatting discrepancies in the rendered output (e.g., some commands or subcommands appear in bold while others do not).

Current status
Ready for integration; v3 submitted with all requested corrections incorporated. Junio C Hamano’s requested correction—restricting backtick-quoting in `pack-refs-options.adoc` to configuration keys only—has been applied in patch 1/2, and patch 2/2 mechanically backtick-quotes all subcommand entries in `git-refs.adoc`. No substantive objections remain; the series is uncontested and awaits maintainer pickup.

Key technical details
- Files touched: `Documentation/git-refs.adoc`, `Documentation/git-pack-refs.adoc`, `Documentation/technical/pack-refs-options.adoc`.
- New or renamed symbols: none (documentation-only).
- Old-vs-new behavior: no functional change to Git; only affects rendered man page and HTML appearance. Patch 1/2 (v3) converts the SYNOPSIS block in `git-pack-refs.adoc` from `[verse]` to `[synopsis]`, removes single-quote formatting around the command name (`git pack-refs`), backtick-quotes all option terms (`--all`, `--no-prune`, `--auto`, `--include`, `--exclude`) in the OPTIONS section, and updates the included `pack-refs-options.adoc` to backtick-quote configuration keys (`core.packedRefsTimeout`, etc.) while leaving command-line options (`--all`, `--no-prune`) unquoted. Patch 2/2 (v3) mechanically backtick-quotes all subcommand entries in `git-refs.adoc` (`list`, `exists`, `optimize`, `create`, `delete`, `update`, and `rename`) and replaces a literal `<branch>` placeholder with an italicized version.
- Test coverage: none required; the changes are mechanical and align with the ongoing synopsis-style documentation effort.
