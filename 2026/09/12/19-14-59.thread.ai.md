Thread type: patch series (documentation-only)

Core problem or goal
Ensure consistent backtick-quoting of command and option references in the synopsis-style AsciiDoc source for the `git-refs` and `git-pack-refs` man pages. Inconsistent quoting causes visual formatting discrepancies in the rendered output (e.g., some commands appear in bold while others do not).

Current status
Under review; v2 submitted with only the uncontested mechanical backtick-quoting conversions (patches 1 and 2, corresponding to patches 2 and 3 from v1). Junio C Hamano identified a minor correction needed in patch 1/2 (v2): backtick-quoting in `pack-refs-options.adoc` should apply only to configuration keys, not to command-line options like `--all` or `--no-prune`. The substantive objection to the lint script change in v1's patch 1 has been resolved by its withdrawal. No further revisions are expected beyond the correction; the series remains ready for integration.

Key technical details
- Files touched: `Documentation/git-refs.adoc`, `Documentation/git-pack-refs.adoc`, `Documentation/technical/pack-refs-options.adoc`.
- New or renamed symbols: none (documentation-only).
- Old-vs-new behavior: no functional change to Git; only affects rendered man page and HTML appearance. Patch 1 (v2) converts the SYNOPSIS block in `git-pack-refs.adoc` from `[verse]` to `[synopsis]`, removes single-quote formatting around the command name (`git pack-refs`), backtick-quotes all option terms (`--all`, `--no-prune`, `--auto`, `--include`, `--exclude`) in the OPTIONS section, and updates the included `pack-refs-options.adoc` to backtick-quote configuration keys (but not command-line options, per Junio’s correction). Patch 2 (v2) mechanically backtick-quotes all subcommand entries in `git-refs.adoc` (`list`, `exists`, `optimize`, `create`, `delete`, `update`, and `rename`) and replaces a literal `<branch>` placeholder with an italicized version.
- Test coverage: none required; the changes are mechanical and align with the ongoing synopsis-style documentation effort.

Open questions and loose ends
A minor correction is needed in patch 1/2 (v2) to restrict backtick-quoting in `pack-refs-options.adoc` to configuration keys only. Once addressed, the series is uncontested and ready for integration.
