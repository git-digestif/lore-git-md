Subject: [PATCH 0/3] doc: lint and fix backtick quoting in git-refs and git-pack-refs
Series version: v1 (initial submission)
Originating author: Todd Zullinger
Thread type: patch series (documentation-only)

Core problem or goal
Ensure consistent backtick-quoting of command and option references in the synopsis-style AsciiDoc source for the `git-refs` and `git-pack-refs` man pages. Inconsistent quoting causes visual formatting discrepancies in the rendered output (e.g., some commands appear in bold while others do not).

Current status
Under review; no prior versions. The series is uncontroversial in its goal but has encountered a substantive technical objection to the lint script change in patch 1. The objection does not challenge the mechanical conversions in patches 2 and 3, which remain unopposed.

Key technical details
- Files touched: `Documentation/git-refs.adoc`, `Documentation/git-pack-refs.adoc`, `Documentation/technical/pack-refs-options.adoc`, and `Documentation/lint-documentation-style.perl`.
- New or renamed symbols: none (documentation-only).
- Old-vs-new behavior: no functional change to Git; only affects rendered man page and HTML appearance. The lint script now enforces backtick-quoting for both commands and options, excluding `linkgit:` references. Patch 2 converts the SYNOPSIS block from `[verse]` to `[synopsis]`, removes single-quote formatting around the command name, backtick-quotes all option terms in the OPTIONS section, and updates the included `pack-refs-options.adoc` to backtick-quote configuration keys. Patch 3 mechanically backtick-quotes all subcommand entries in `git-refs.adoc` (`list`, `exists`, `optimize`, `create`, `delete`, `update`, and `rename`). The only prose change replaces a literal `<branch>` with an italicized placeholder.
- Test coverage: the lint script checks for backtick-quoted commands and options in synopsis-style AsciiDoc. The proposed change in patch 1 would over-match in at least five other man pages (`git-add.adoc`, `git-push.adoc`, `git-difftool.adoc`, `git-daemon.adoc`, `git-fetch.adoc`), risking false positives that would freeze non-command terms for translators.

Open questions and loose ends
The lint script change in patch 1 must be revised to avoid false positives in unrelated man pages. Todd has not yet responded to Jean-Noël’s objection; the series cannot proceed until this is resolved.

Participant positions
- Todd Zullinger (author): identified the issue, implemented the fix, and posted the series. The first patch extends the lint script to enforce backtick-quoting for commands, the second patch applies the mechanical conversions to `git-pack-refs.adoc` and `pack-refs-options.adoc`, and the third patch completes the work by backtick-quoting all subcommand entries in `git-refs.adoc`.
- Jean-Noël Avila (ongoing documentation effort lead): supports the goal of consistent backtick-quoting but objects to the lint script change in patch 1. His review is substantive, listing specific files where the proposed regex would trigger false positives. The objection is narrow and does not extend to patches 2 or 3.

Related work
Part of the larger, multi-month effort to convert all Git man pages to a consistent synopsis style using AsciiDoc markup.
