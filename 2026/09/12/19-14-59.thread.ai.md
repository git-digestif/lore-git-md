Core problem or goal
Ensure consistent backtick-quoting of command and option references in the synopsis-style AsciiDoc source for the `git-refs` and `git-pack-refs` man pages. Inconsistent quoting causes visual formatting discrepancies in the rendered output (e.g., some commands appear in bold while others do not).

- New or renamed symbols: none (documentation-only).
- Old-vs-new behavior: no functional change to Git; only affects rendered man page and HTML appearance. Patch 2 converts the SYNOPSIS block from `[verse]` to `[synopsis]`, removes single-quote formatting around the command name, backtick-quotes all option terms in the OPTIONS section, and updates the included `pack-refs-options.adoc` to backtick-quote configuration keys. Patch 3 mechanically backtick-quotes all subcommand entries in `git-refs.adoc` (`list`, `exists`, `optimize`, `create`, `delete`, `update`, and `rename`). The only prose change replaces a literal `<branch>` with an italicized placeholder.
