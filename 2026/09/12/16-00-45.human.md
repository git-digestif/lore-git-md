This is the second patch in Souma’s v3 series teaching `git history` to sign rewritten commits. It is the main feature patch, adding GPG-signing support to the `drop`, `fixup`, `reword`, and `split` subcommands. The patch wires up the configuration (`commit.gpgsign`) and command-line options (`-S/--gpg-sign`, `--no-gpg-sign`) already used by `git commit`, threads the signing key through the replay machinery, and updates the documentation and tests.

The implementation is straightforward: a new `sign_commit` field in the `replay_revisions_options` struct is populated from either the config or the command line, then passed down through `pick_regular_commit`, `create_commit`, `commit_tree_ext`, and `split_commit` to the low-level commit-creation functions. Command-line options override configuration, and the last option wins. The on-disk format is unchanged; only the commit object’s signature trailer is added when signing is enabled.

Test coverage is thorough: each of the four subcommands (`t3451`–`t3454`) gets GPG-gated tests that verify config-driven signing, command-line overrides, explicit key selection, and the no-new-commit case for `drop`. The documentation patch adds a short section on signing options and cross-references the `git-commit` man page.

The patch is well-crafted, addresses all prior feedback, and looks ready for `next` once any remaining surface-level cleanups are done. The only open question is the conceptual trade-off noted in the commit message—whether signing rewritten commits that were originally authored by someone else is desirable or misleading—but that discussion is orthogonal to the implementation.
