This is a CI/build system patch discussion about a Coccinelle rule. René Scharfe replies to Junio C Hamano’s patch removing a risky Coccinelle rule that converted `if (!E) free(E);` into an unconditional `free(E)`. René agrees with the safety concern—freeing a pointer that wasn’t intended to be freed could cause real damage—but questions whether the rule ever provided value as a guardrail. He suggests that LeakSanitizer, with sufficient test coverage, might catch forgotten `free()` calls just as effectively. He also notes that Junio’s commit message led him to expect the rule would be replaced with *nothing* (removing the `free()` call entirely), which would be a safe no-op, rather than simply deleting the rule and leaving the original code unchanged.

The discussion is substantive but narrow, focusing on the trade-off between static analysis (Coccinelle) and runtime tools (LeakSanitizer) for catching memory leaks. René’s feedback doesn’t oppose the patch but raises a broader question: whether the rule was ever useful in practice, and whether its removal might miss opportunities to clean up genuinely redundant code. The thread remains under review, with no objections or alternative proposals yet.
