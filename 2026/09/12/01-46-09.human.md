This is a bugfix patch targeting the refs subsystem, specifically the files backend. Ariel Keselman addresses a long-standing inefficiency where deleting a root ref (like `AUTO_MERGE`, `CHERRY_PICK_HEAD`, or `REVERT_HEAD`) unnecessarily acquires the `packed-refs.lock`, even though root refs cannot be packed. The issue surfaces in linked worktrees with read-only shared metadata, where post-commit cleanup fails with a lock error despite the commit itself succeeding.

The fix is surgical: the files backend now skips the packed-ref transaction entirely when deleting a root ref, while preserving all other locking behavior. The patch includes two new tests in `t/t0600-reffiles-backend.sh` that verify the fix—one confirms that deleting a root ref succeeds even when `packed-refs.lock` is held, and the other ensures that mixed transactions (deleting both a root ref and a packed ref) still fail cleanly without altering any refs.

The commit message is clear and well-motivated, and the code change is minimal and focused. The tests are thorough and cover both the happy path and the edge case. This looks like a solid, uncontroversial fix that should be ready for `next`.
