This is the third patch in a three-part documentation series that ensures consistent backtick-quoting of commands and options in the `git-refs` man page. The series is part of the ongoing effort led by Jean-Noël Avila to standardize all Git man pages on the synopsis style.

The patch itself is mechanical and uncontroversial. It backtick-quotes the seven subcommand names (`verify`, `list`, `exists`, `optimize`, `create`, `delete`, `update`, and `rename`) in the `git-refs.adoc` file, fixing visual inconsistencies in the rendered man page where some commands appeared in bold and others in plain text. The commit message explains that the `git-refs` documentation was converted to synopsis style in February 2025, but subsequent additions missed the backtick-quoting convention, leaving the formatting uneven.

No functional changes to Git are introduced; this is purely about documentation appearance. The patch is well-scoped and aligns with established project conventions. Given the series has already touched the linting script and `git-pack-refs` in earlier patches, this final patch completes the cleanup for the refs-related documentation. The work looks ready for merging and should be a straightforward addition to the broader documentation standardization effort.
