This is a bugfix patch for the refs/files backend, now in its final polishing stage. The patch prevents Git from taking an unnecessary lock on `packed-refs` when deleting root refs (like `HEAD`, `AUTO_MERGE`, or `refs/heads/main`), which cannot be packed. The issue causes spurious failures in linked worktrees with read-only shared metadata, particularly during post-commit cleanup where `AUTO_MERGE` is deleted after updating `HEAD`.

Ariel Keselman posted v3 of the patch after accidentally sending it as a new thread. The core fix remains unchanged: `files_transaction_prepare()` in `refs/files-backend.c` now skips packed-ref transactions for root refs using the `is_root_ref()` helper. The v3 update incorporates Patrick Steinhardt’s latest test-coverage suggestions, including verifying that `AUTO_MERGE` is not packed after `git pack-refs --all` and strengthening the mixed-transaction test by capturing full ref state with `git refs list --include-root-refs`. Minor test-script cleanups (dropping redundant `start/prepare/commit` lines and inlining heredocs) are also included.

The patch is well-scoped, touching only `refs/files-backend.c` and adding two focused regression tests in `t/t0600-reffiles-backend.sh`. It resolves a real-world regression without changing on-disk format, CLI behavior, or configuration. All test suites pass, including SHA-256 validation, and the fix is uncontroversial. Patrick’s feedback has been constructive and fully addressed, so this patch looks ready for merging once v3 is formally submitted to the correct thread.
