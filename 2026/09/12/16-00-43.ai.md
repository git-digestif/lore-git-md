This is a feature patch series (2 patches) that teaches `git history` to sign rewritten commits, now at v3. The series has been streamlined from v2: the preparatory replay API plumbing (patch 1) and the main feature implementation (patch 2) remain, but the commit messages are shorter and the `OPT_HISTORY_GPG_SIGN` macro formatting is fixed. The core functionality is unchanged—`git history drop`, `fixup`, `reword`, and `split` now respect `commit.gpgsign` and the `-S/--gpg-sign`/`--no-gpg-sign` command-line options, with the same precedence rules as `git commit`.

The files touched are the same as in v2: `replay.c`, `replay.h`, `builtin/history.c`, the `git-history` documentation, and four test scripts (`t3451`–`t3454`). The new `sign_commit` field in `replay_revisions_options` and the plumbing through `pick_regular_commit` and `create_commit` are unchanged; only the commit-message trimming and macro formatting requested in the v2 review have been addressed. Test coverage still verifies config-driven signing, command-line overrides, explicit key selection, and the no-new-commit edge case for `drop`.

The conceptual question about signing rewritten commits authored by others remains unresolved but is now documented in the commit message. The series looks technically sound, with all prior review feedback incorporated; it is likely close to ready for merging once any remaining surface-level nits are addressed.
