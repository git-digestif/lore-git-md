This thread is about a two-patch series (v3) that tightens Git's CI behavior to reduce log noise by ensuring warnings or failures for Perforce, Git LFS, and JGit only appear on platforms that actually require these tools. The series is now fully unblocked after Harald Nordgren confirmed that the preparatory cleanup (patch 1/2) has no adverse effect on GitLab CI, matching earlier findings for GitHub Actions. This patch removes a macOS-specific `xattr` step for Perforce binaries, which had been a silent no-op since 2022.

The stricter behavior (patch 2/2) implements the agreed consensus: tools required for a platform (Perforce on macOS and Ubuntu, Git LFS and JGit on Ubuntu) must install successfully, or the build fails immediately. This replaces the previous approach of platform-scoped warnings and silent skips. The series relies on `set -e` (already active in `ci/lib.sh`) to handle failures, though some redundant `&&` chains remain for now—Harald has acknowledged these as stylistic cleanup for a future iteration.

Junio C Hamano and Patrick Steinhardt have both reviewed the series without raising blocking objections, but neither has provided a formal Reviewed-by or Acked-by. The series is now ready for a final positive review from another contributor. No technical questions remain open, and the changes are confined to CI behavior with no impact on Git's core functionality.
