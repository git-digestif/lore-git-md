This thread is about a two-patch series (v3) by Harald Nordgren that cleans up Git’s CI tool installation logic to reduce log noise. The goal is to ensure warnings or failures for Perforce, Git LFS, and JGit only appear on platforms that actually require these tools, with the build now failing immediately if installation fails on those platforms. The series has converged on a stricter approach—mandatory tool installation on relevant platforms—after Patrick Steinhardt argued that silent skips risked hiding test gaps.

The v3 series is under final review. The first patch removes a macOS-specific `xattr` step for Perforce binaries, which has been a no-op since 2022, while the second enforces stricter tool installation. Junio C Hamano and Patrick Steinhardt have both reviewed the changes without raising blocking objections, but neither has provided a formal *Reviewed-by* or *Acked-by*. Patrick’s latest review of the preparatory patch flags a potential platform-compatibility issue: whether the change affects GitLab CI, not just GitHub Actions. He linked to a GitLab CI pipeline to test this, leaving the patch in a holding state until those results arrive. The series is otherwise technically sound, with only minor stylistic questions (like redundant `&&` chains) remaining unresolved but non-blocking. Harald has addressed all prior feedback, and the patches are ready for a final sign-off once the GitLab CI outcome is confirmed.
