This thread is about a small but important cleanup to Git’s CI system. Harald Nordgren sent a patch to reduce log noise in GitHub Actions by making sure warnings or failures for tools like Perforce, Git LFS, and JGit only appear on platforms that actually need them. After some back-and-forth, the group agreed on a stricter approach: if a platform requires one of these tools, the build must fail immediately if installation fails, rather than allowing silent skips.

The patch is now in its second version and is ready for final review. Junio C Hamano looked it over and confirmed he has no objections, but he also made it clear that his feedback wasn’t a full endorsement—it still needs a formal “Reviewed-by” from someone else. Patrick Steinhardt, who originally pushed for the stricter approach, reviewed the patch thoroughly, tested it, and confirmed it does exactly what was agreed. The only loose end is that minor stylistic quirk (a small inconsistency in how `rm` is used for Git LFS versus Perforce on macOS), but everyone agreed to leave it as-is since it doesn’t affect functionality.

The latest email just clears up a small confusion: earlier, someone thought `ci/lib.sh` was missing `set -e`, but Harald pointed out it’s already there. No changes to the patch are needed—it’s just waiting for that final sign-off from another contributor before it can be merged.
