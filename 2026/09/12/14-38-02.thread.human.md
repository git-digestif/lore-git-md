This thread is about a small but practical improvement to Git's GitHub Actions CI setup. Harald Nordgren originally proposed a patch to reduce log noise by making warnings about missing optional tools (Perforce, Git LFS, JGit) appear only on platforms that actually need them. After discussion, the consensus shifted toward a stricter approach: if a tool is required for a platform, the build should fail immediately if installation fails, rather than warning or skipping silently.

The revised patch (v2) implements this stricter logic in `ci/install-dependencies.sh`. On Ubuntu runners (which need all three tools) and macOS runners (which need Perforce), the script now exits with an error if installation fails, ensuring broken tool downloads are caught early. Version output for each tool is printed right after installation, making it clear in the logs what succeeded. Junio reviewed the change and noted it as a clean implementation of the agreed direction, though he pointed out a minor inconsistency in macOS error handling (the `xattr` step is allowed to fail silently, but the `tar` extraction is not). No one has objected to leaving this as-is.

The patch is now under final review and looks uncontroversial. The only loose end is a small maintenance consideration: anyone adding a new platform in the future must remember to include the required tools in the installation logic, or the build will fail. This is now an explicit requirement, not a risk of silent skips. Key participants—Harald, Patrick Steinhardt, and Junio—have all signaled agreement with the current approach.
