This thread is about a bug in `git status --ignored` where a pathspec like `ba` incorrectly matches ignored directories whose names *contain* the pathspec as a substring (e.g., `bar/baz/`), rather than requiring an exact name match. The issue was reported by Sean Whitton (forwarding Lester Longley's Emacs issue) and has now been diagnosed and fixed by René Scharfe.

René traced the regression to commit `95c11ecc73` (2020) and submitted a minimal patch that removes an optimization in `dir.c` to restore the expected behavior. The fix is straightforward and directly addresses the bug, though René notes the optimization might be repairable in the future. The patch has been tested against the original reproduction case and in Git's own repository, where the issue manifests differently, suggesting context-dependent behavior. No test case accompanies the patch yet, but the original report's steps remain valid for verification.

The fix touches only the pathspec matching logic for ignored files in `treat_directory()`, with no broader implications for symbols or on-disk formats. While the patch is likely uncontroversial, follow-up discussion may explore whether the optimization can be safely reintroduced. No maintainer or reviewer feedback has been posted yet, but René's analysis and bisect results provide strong justification for the change.
