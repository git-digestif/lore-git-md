This thread is about a bug in `git status --ignored` where pathspec matching (e.g., `ba`) incorrectly includes ignored directories whose names *contain* the pathspec as a substring (e.g., `bar/baz/`), rather than requiring an exact match. The issue was introduced in 2020 by an optimization that skipped pathspec checks for excluded directories. René Scharfe posted a v1 patch to fix it by removing the problematic optimization, along with a regression test.

The patch is now under review, and Junio C Hamano has identified a critical safety issue: the new `dir_match()` helper could dereference a NULL `pathspec`, risking a crash during operations like `git checkout` when untracked nested repositories exist. Junio proposed a small fix (adding a NULL check) and a new test case to verify the edge case. The fix is straightforward and doesn’t change the patch’s core behavior—it just makes it safer. No maintainer decision has been made yet, but the patch is likely to be queued once the safety issue is resolved. The only open question remains whether the original optimization can be restored later without reintroducing the bug. Key participants are René (author) and Junio (reviewer).
