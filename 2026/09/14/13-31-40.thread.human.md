This thread is about a bug in `git status --ignored` where pathspecs like `ba` incorrectly match ignored directories whose names *contain* the pathspec as a substring (e.g., `bar/baz/`), rather than requiring an exact match. The issue was introduced in 2020 by an optimization that skipped pathspec matching for excluded directories.

René Scharfe posted a fix (v2) that removes the problematic optimization, restoring exact-match behavior. Junio C Hamano reviewed the patch and identified a NULL-dereference crash risk in the new `dir_match()` helper, which René addressed with a squash-in fix (a defensive NULL check and a test case). The patch now includes two test cases: one verifying the regression is fixed, and another ensuring `git checkout` doesn’t segfault with untracked nested repositories. All review feedback has been incorporated, and the patch is ready for maintainer integration. No open questions remain, though René noted the removed optimization could be revisited later. The fix is technically complete and targets the `dir.c` subsystem.
