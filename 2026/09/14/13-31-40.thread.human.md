This thread is a bug report from Sean Whitton about unexpected behavior in `git status --ignored` when a pathspec is used. The issue is that pathspec matching is treating the input as a substring rather than an exact match: searching for `ba` incorrectly includes ignored directories like `bar/baz/` and `bar/quux/`, even though `ba` isn’t an exact match for `bar`. The report includes a clear reproduction case involving nested Git repositories and a `.gitignore` entry, originally surfaced in an Emacs issue by Lester Longley.

No patch or proposed fix has been posted yet—this is just the initial report. The bug appears to be a regression or edge case in Git’s pathspec matching logic for ignored files, and the reproduction steps should make it straightforward for a maintainer to verify. So far, there’s been no discussion or review; the thread is just getting started.
