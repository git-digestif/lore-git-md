Thread identity
Subject: [PATCH 0/6] repack: fix concurrent-push race leading to data loss
Series version: v2 (five patches; patch 1/6 withdrawn, patches renumbered 1/5–5/5)
Originating author: qeesung (Qin ShiCheng via GitGitGadget)
Thread type: bugfix series

Core problem or goal
Fix a race condition in `git repack -d` where concurrent pushes can cause the repack machinery to delete packs whose objects were never copied elsewhere, resulting in data loss (dangling refs pointing to nonexistent commits). The series replaces the `--honor-pack-keep` mechanism with a snapshot-based approach to ensure `.keep` files are managed consistently. The latent cruft-pack walk bug, which would become critical once `--honor-pack-keep` is removed, is also fixed.

Current status
Under review; series at v2. Patches 1/5–5/5 merge cleanly into `next` and `seen`. The `.keep` file ownership logic is now handled by Justin Tobler's separate ODB-focused series, which will subsume the withdrawn patch 1/6 entirely. The final patch (5/5) eliminates the race by passing `pack-objects` a snapshot of `.keep` packs observed at repack startup via `--keep-pack-from-file`, replacing the mid-repack directory scan that could miss concurrent `.keep` file creation.

Key technical details
- **Files touched**: `builtin/pack-objects.c`, `builtin/repack.c`, `object-file.c`, `packfile.h`, `packfile.c`, `tempfile.h`, `tempfile.c`, `odb/source-packed.h`, `t/t5547-push-quarantine.sh`, `t/t5331-pack-objects-stdin.sh`, `t/t5329-pack-objects-cruft.sh`, `t7700-repack.sh`, `t7703-repack-geometric.sh`
- **New plumbing**:
  - `--stdin-packs=follow` now treats `--keep-pack` packs as traversal blockers only if explicitly marked as closed (`^`); otherwise, they are treated as "kept-open" (`!`), allowing traversal through their objects (patch 1/5). This fixes the long-standing behavioral inconsistency where `--keep-pack` packs were incorrectly treated as closed under reachability.
  - `--stdin-packs=follow` with `--keep-pack` now correctly includes objects reachable through kept packs but stored in other packs (patch 1/5).
  - `clear_kept_pack_cache()` helper (renamed from `packfile_store_invalidate_kept_pack_cache()` in this patch) exposed in `packfile.c`/`packfile.h` to invalidate the kept-pack cache for ODB sources (patch 2/5). This ensures the cruft-pack walk reflects the current kept-pack state after re-marking fresh packs as kept. **Junio C Hamano's review highlights a layering concern**: the patch assumes every ODB source is a `files`-backend source and calls `odb_source_files_downcast()` without checking the source type, which will trigger a `BUG()` if the source is from a different backend (e.g., a future pluggable ODB). Junio suggests either checking the source type before downcasting (a layering violation) or re-architecting the code to push packfile management details down to the files backend layer entirely. The latter aligns with recent design decisions but is beyond the scope of this patch.
  - **Performance optimization in `add_extra_kept_packs`** (patch 3/5): sorts the `--keep-pack` list once and replaces linear scans with binary search (`string_list_has_string`), yielding an 11× speed-up (11 s → 1 s) when matching 20,000 kept packs against 20,000 repository packs.
  - `--keep-pack-from-file=<file>` added to `git pack-objects` (patch 4/5): reads a file containing one pack name per line (empty lines ignored, relative paths resolved against working directory) and treats them as if passed via `--keep-pack`. The file format matches other Git tools (e.g., `git multi-pack-index write --refs-snapshot`).
  - `repack` now passes `pack-objects` the exact list of `.keep` packs observed at startup via `--keep-pack-from-file` (patch 5/5), replacing the `--honor-pack-keep` mechanism. The snapshot file is written next to the refs snapshot used for `multi-pack-index write` and contains one `<name>.pack` per line.
- **Behavior changes**:
  - `pack-objects --stdin-packs=follow` no longer incorrectly treats `--keep-pack` packs as closed under reachability (patch 1/5).
  - The cruft-pack walk now correctly traverses packs that were initially unknown to `pack-objects` but later marked as kept (patch 2/5).
  - Alternate ODB packs are no longer skipped; they are now packed (not deleted), trading disk space for safety (patch 5/5).
- **On-disk format**: no changes.
- **Test coverage**:
  - Patch 1/5 adds a test in `t/t5331-pack-objects-stdin.sh` to reproduce the traversal bug: a kept pack (`B_ONLY`) containing only a commit, with its tree and blob in an excluded pack (`B`). The test confirms the fix includes the tree and blob in the output pack.
  - Patch 2/5 adds a test in `t/t5329-pack-objects-cruft.sh` to verify the cruft-pack walk includes all reachable objects, even when the middle commit of an unreachable chain sits in an untold pack.
  - Patch 3/5 includes performance measurements in the commit message.
  - Patch 4/5 adds two tests in `t/t5331-pack-objects-stdin.sh` to verify `--keep-pack-from-file` behaves identically to `--keep-pack` (including ignoring empty lines and non-existent packs) and fails cleanly when the file is missing.
  - Patch 5/5 adds three tests:
    1. `t7700-repack.sh` verifies `--keep-pack` with `--pack-kept-objects` still excludes the kept pack’s objects.
    2. `t7703-repack-geometric.sh` reproduces the race (a `.keep` appearing mid-repack) and confirms objects are not lost.
    3. A second test in `t7703-repack-geometric.sh` ensures kept packs do not block traversal of objects reachable through them.

Open questions and loose ends
Patch 1/5’s traversal logic change may prompt discussion about edge cases in `pack-objects` reachability, particularly whether the mode check in `add_extra_kept_packs()` is sufficient to cover all callers. The test added in `t/t5331-pack-objects-stdin.sh` explicitly covers the corrected edge case, but reviewers may seek confirmation that no other callers rely on the old (incorrect) behavior. **Patch 2/5’s cruft-pack walk fix is now contested**: Junio C Hamano’s review raises a layering concern about the unchecked downcast in the ODB source loop, which could trigger a `BUG()` if a non-files ODB backend is used. The patch is minimal and correct for the current codebase, but the layering violation may need to be addressed before merging, either by adding a type check (a smaller violation) or by deferring the fix until a non-files ODB backend materializes. Patch 3/5’s performance optimization is unlikely to draw objections but may prompt verification that the sorted list does not interact poorly with future callers expecting insertion order. Patch 4/5’s `--keep-pack-from-file` is a scalability enabler for patch 5/5; reviewers may discuss whether the file format should be more structured (e.g., NUL-terminated) or whether error handling could be more graceful (e.g., skipping unreadable files). The current design is pragmatic and aligns with existing Git conventions. Patch 5/5’s removal of `--honor-pack-keep` and the snapshot-based approach may prompt discussion about the trade-off between safety and disk space (alternate ODB packs are now packed rather than skipped). Justin Tobler’s ODB-focused series will handle the `.keep` ownership logic, but reviewers may still discuss whether the repack-side changes (patches 1/5–5/5) are sufficient without it.
