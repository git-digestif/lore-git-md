Subject: [PATCH 0/6] repack: fix concurrent-push race leading to data loss

Thread type: bugfix series

Core problem or goal
Fix a race condition in `git repack -d` where concurrent pushes can cause the repack machinery to delete packs whose objects were never copied elsewhere, resulting in data loss (dangling refs pointing to nonexistent commits). The series addresses the root cause by ensuring `.keep` files are managed consistently and by replacing the `--honor-pack-keep` mechanism with a snapshot-based approach. The latent cruft-pack walk bug, which would become critical once `--honor-pack-keep` is removed, is also fixed.

Current status
Under review; series remains at v1 but patch 1/6 is withdrawn. Patches 2/6–6/6 are still active and merge cleanly into `next` and `seen`. The `.keep` file ownership logic will be handled by Justin Tobler's separate ODB-focused series, which will subsume patch 1/6 entirely.

Key technical details
- **Files touched**: `builtin/pack-objects.c`, `builtin/repack.c`, `object-file.c`, `packfile.h`, `packfile.c`, `tempfile.h`, `tempfile.c`, `odb/source-packed.h`, `t/t5547-push-quarantine.sh`, `t/t5331-pack-objects-stdin.sh`, `t/t5329-pack-objects-cruft.sh`, `t7700-repack.sh`, `t7703-repack-geometric.sh`
- **New plumbing**:
  - `--stdin-packs=follow` now treats `--keep-pack` packs as traversal blockers only if they are explicitly marked as closed (`^`); otherwise, they are treated as "kept-open" (`!`), allowing traversal through their objects (patch 2/6).
  - `--stdin-packs=follow` with `--keep-pack` now correctly includes objects reachable through kept packs but stored in other packs (patch 2/6).
  - `--keep-pack-from-file=<file>` added to `git pack-objects` (patch 5/6): reads a file containing one pack name per line (empty lines ignored, relative paths resolved against working directory) and treats them as if passed via `--keep-pack`. The `keep_pack_list` now owns its strings (`strdup_strings = 1`). Documented in `git-pack-objects.adoc` and tested in `t/t5331-pack-objects-stdin.sh` (two new tests: behavior identical to `--keep-pack`, including ignoring empty lines and non-existent packs; fails cleanly on missing file).
  - `clear_kept_pack_cache()` helper exposed in `packfile.c`/`packfile.h` to invalidate the kept-pack cache for ODB sources (patch 3/6).
  - **Performance optimization in `add_extra_kept_packs`** (patch 4/6): sorts the `--keep-pack` list once and replaces linear scans with binary search (`string_list_has_string`), yielding an 11× speed-up (11 s → 1 s) when matching 20,000 kept packs against 20,000 repository packs. The change is internal-only; the comparison function (`fspathcmp`) and matching semantics remain unchanged.
- **Behavior changes**:
  - `repack` now passes `pack-objects` the exact list of `.keep` packs observed at startup via `--keep-pack-from-file` (patch 6/6), replacing the `--honor-pack-keep` mechanism which rescanned the `.keep` directory mid-repack. The snapshot file is written next to the refs snapshot already used for `multi-pack-index write` and contains one `<name>.pack` per line, matching the exact set of kept packs `repack` observed when it began.
  - `pack-objects --stdin-packs=follow` no longer incorrectly treats `--keep-pack` packs as closed under reachability (patch 2/6).
  - The cruft-pack walk now correctly traverses packs that were initially unknown to `pack-objects` but later marked as kept, ensuring all reachable objects are included (patch 3/6).
  - Alternate ODB packs are no longer skipped; they are now packed (not deleted), trading disk space for safety (patch 6/6).
- **On-disk format**: no changes.
- **Test coverage**:
  - Patch 2/6 adds a test in `t/t5331-pack-objects-stdin.sh` to reproduce the traversal bug: a kept pack (`B_ONLY`) containing only a commit, with its tree and blob in an excluded pack (`B`). The test confirms the fix includes the tree and blob in the output pack.
  - Patch 3/6 adds a test in `t/t5329-pack-objects-cruft.sh` to verify the cruft-pack walk includes all reachable objects, even when the middle commit of an unreachable chain sits in an untold pack.
  - Patch 5/6 adds two tests in `t/t5331-pack-objects-stdin.sh` to verify `--keep-pack-from-file` behaves identically to `--keep-pack` (including ignoring empty lines and non-existent packs) and fails cleanly when the file is missing.
  - Patch 6/6 adds three tests:
    1. `t7700-repack.sh` verifies `--keep-pack` with `--pack-kept-objects` still excludes the kept pack’s objects.
    2. `t7703-repack-geometric.sh` reproduces the race (a `.keep` appearing mid-repack) and confirms objects are not lost.
    3. A second test in `t7703-repack-geometric.sh` ensures kept packs do not block traversal of objects reachable through them.

Open questions and loose ends
Patch 2/6’s traversal logic change is narrowly scoped but may prompt discussion about edge cases in `pack-objects` reachability. Patch 3/6’s cruft-pack walk fix is minimal but critical for the series’ correctness; reviewers may seek confirmation that the cache invalidation is sufficient and does not introduce performance regressions. Patch 4/6’s performance optimization is unlikely to draw objections but may prompt verification that the sorted list does not interact poorly with future callers expecting insertion order. Patch 5/6’s `--keep-pack-from-file` is a scalability enabler for patch 6/6 and is unlikely to be controversial, but reviewers may discuss whether the file format should be more structured (e.g., NUL-terminated); the one-per-line convention is consistent with other Git tools and sufficient for the use case. Patch 6/6’s removal of `--honor-pack-keep` and the snapshot-based approach may prompt discussion about the trade-off between safety and disk space (alternate ODB packs are now packed rather than skipped). Justin Tobler’s ODB-focused series will handle the `.keep` ownership logic, but reviewers may still discuss whether the repack-side changes (patches 2/6–6/6) are sufficient without it.
