Thread identity: Subject: [PATCH 0/3] repack: fix concurrent-push race leading to data loss. Series version: v5 (three patches; 1/3--3/3), rebased onto current `master` (base-commit 77904e546de3bd940621092ecec47a88d0cede5d). Originating author: qeesung (Qin ShiCheng via GitGitGadget). Thread type: bugfix series.

Core problem or goal: Fix a race condition in `git repack -d` where concurrent pushes can cause the repack machinery to delete packs whose objects were never copied elsewhere, resulting in data loss (dangling refs pointing to nonexistent commits). The v5 series replaces the `--honor-pack-keep` mechanism with a snapshot-based approach that explicitly tells `pack-objects` which packs it may delete via `--ignore-pack-keep-from`, eliminating the need for `--honor-pack-keep` entirely. The latent cruft-pack walk bug, which would become critical once `--honor-pack-keep` is removed, is also fixed.

Current status: Ready for integration; series at v5. v5 is v4 rebased onto current `master` to resolve a test conflict in `t/t7700-repack.sh` with the `ds/path-walk-tagged-tree-revisit` topic; the only code change in the range-diff is sorting the `keep_pack_list` before collection. Patches 1/3--3/3 merge cleanly into `master`. Junio C Hamano's prior ack for the cruft-walk fix remains valid, and the design addresses architectural concerns raised in earlier reviews. The series is production-ready and no longer blocked on external dependencies. Jeff King has provided a Reviewed-by for patch 1/3, and Taylor Blau has provided a Reviewed-by for patch 3/3, closing the review loop for the series.

Key technical details:
- Files touched: `builtin/pack-objects.c`, `builtin/repack.c`, `packfile.c`, `packfile.h`, `repack.c`, `repack.h`, `odb/source-packed.h`, `tempfile.h`, `Documentation/git-pack-objects.adoc`, `t/t5329-pack-objects-cruft.sh`, `t/t7700-repack.sh`, `t/t7703-repack-geometric.sh`
- New plumbing:
  - `repo_invalidate_kept_pack_caches()` exposed in `packfile.c`/`packfile.h` to invalidate the kept-pack cache for all ODB sources (patch 1/3), fixing a stale cache in the cruft walk where the cache was built while unlisted packs were still marked as kept, causing the reachability walk to stop at unlisted packs and miss expired objects beyond them.
  - `--ignore-pack-keep-from=<file>` added to `git pack-objects` (patch 2/3): implemented in `ignore_pack_keep_from_file()` in `builtin/pack-objects.c`, called early in `cmd_pack_objects()` before `add_extra_kept_packs()`. It opens the named file, reads pack basenames into a sorted string list using `fspathcmp`, then iterates `repo_for_each_pack()` clearing `pack_keep` on matching local packs (matched against `pack_basename(p)` for local packs only). The file-based interface avoids command-line length limits (notably the 32767-character limit on Windows and `ARG_MAX` elsewhere) and works where stdin is occupied. This clears the `pack_keep` flag before any object-walking code runs, covering every path that consults `pack_keep` including `--honor-pack-keep`, `--unpack-unreachable`, `--keep-unreachable`, and `--cruft`. Empty lines are ignored and relative paths are resolved against the working directory; the format matches existing Git tools (e.g., `git multi-pack-index write --refs-snapshot`). Patch 2/3 introduces no behavior change for existing callers.
  - `repack` now passes `pack-objects` the exact list of non-kept/cruft packs observed at startup via `--ignore-pack-keep-from` (patch 3/3), replacing the `--honor-pack-keep` mechanism. In `builtin/repack.c`, after collecting existing packs and sorting the keep list, the code checks `existing_packs_has_non_kept()` and, if true, creates a tempfile named `tmp_non_kept_packs_XXXXXX` in the object directory, writes the pack names via the new `existing_packs_write_non_kept()` helper in `repack.c`, and sets `po_args.ignore_pack_keep_from` to the tempfile path. The same path is also propagated to the cruft pack-objects invocation (`cruft_po_args.ignore_pack_keep_from`). In `repack.c`, `prepare_pack_objects()` appends `--ignore-pack-keep-from=%s` to the command line when the field is set, and `existing_packs_write_non_kept()` writes one `<name>.pack` per line for both non-kept and cruft packs. The v5 update sorts the `keep_pack_list` before collection. The implementation refuses pack names containing newlines (to prevent splitting) and ensures alternates are traversed (trading disk space for safety). The snapshot is only written when there are packs to delete.
- Behavior changes:
  - The cruft-pack walk now correctly traverses every pack except the explicitly fresh ones, including packs borrowed from alternates and packs specified via `--keep-pack` (patch 1/3). `--keep-pack` packs are marked as `pack_keep_in_core_open` (similar to `--stdin-packs=follow` "!" packs), so the walk passes through them to rescue reachable objects while still excluding the pack's own objects from the cruft pack.
  - Alternate ODB packs are now packed (not skipped), trading disk space for safety (patch 3/3).
  - `--ignore-pack-keep-from` avoids command-line length limits by reading pack names from a file.
- Performance impact: The cruft walk now traverses alternates, which can slow down `repack -d -l --cruft` in shared clones (e.g., 2ms -> 3.3s in a `clone --shared` of `git.git`). This is intentional (safety over speed) but may prompt discussion.
- On-disk format: no changes.
- Test coverage:
  - Patch 1/3 adds tests in `t/t5329-pack-objects-cruft.sh` to verify the cruft walk rescues objects through untold packs, `--keep-pack` packs (excluding the pack's own objects while rescuing others), and alternates (with/without `--local`), using `git repack --filter-to` scenarios to set up split object storage.
  - Patch 2/3 adds two tests in `t/t7700-repack.sh`: a functional test confirming that naming one of two kept packs in the ignore file causes its reachable objects to be packed while unreachable ones are loosened (and the other kept pack is left alone), and a negative test confirming that a missing file produces a `could not open ... for reading` error.
  - Patch 3/3 adds tests in `t/t7700-repack.sh` and `t/t7703-repack-geometric.sh` to reproduce the race (a `.keep` appearing mid-repack) using a `git` wrapper shim placed in `--exec-path` that creates a `.keep` file on the target pack at the moment `pack-objects` starts. The tests cover `-a -d`, `-A -d`, `-a -k -d`, `--cruft -d` (with and without expiration), `--pack-kept-objects`, `--filter`, and `--geometric` modes, verifying with `git fsck` and `cat-file` that no objects are lost even when the `.keep` appears mid-run.
