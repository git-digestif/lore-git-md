Core problem or goal
Fix a race condition in `git repack -d` where concurrent pushes can cause the repack machinery to delete packs whose objects were never copied elsewhere, resulting in data loss (dangling refs pointing to nonexistent commits). The series replaces the `--honor-pack-keep` mechanism with a snapshot-based approach to ensure `.keep` files are managed consistently. The latent cruft-pack walk bug, which would become critical once `--honor-pack-keep` is removed, is also fixed.

The fix ensures these packs are treated as "kept-open" (`!`), allowing traversal to continue through their objects to rescue dependencies that would otherwise be omitted. The optimization is purely internal to `builtin/pack-objects.c` and does not affect any other callers or on-disk formats. The commit message clearly states the problem, solution, and measured improvement, and the patch is necessary to make the snapshot-based approach (patch 5/5) viable for large repositories. **Patch 4/5 (`--keep-pack-from-file`) is now described in detail**: it adds a new `git pack-objects` option to read pack names from a file (one per line, empty lines ignored), treating them identically to `--keep-pack` arguments. The file format matches existing Git tools (e.g., `git multi-pack-index write --refs-snapshot`), and relative paths are resolved against the working directory. The implementation is minimal, reusing the existing `--keep-pack` logic and adding 28 lines of code to `builtin/pack-objects.c`. The change is a necessary enabler for patch 5/5, addressing scalability limitations of `--keep-pack` (e.g., `ARG_MAX` and Windows command-line length caps) in repositories with thousands of kept packs. **Patch 5/5 (final patch) is now described in detail**: it replaces the racy `--honor-pack-keep` mechanism with a snapshot-based approach, writing the list of `.keep` packs observed at repack startup to a temporary file and passing it to `pack-objects` via `--keep-pack-from-file`. The snapshot file is written next to the refs snapshot used for `multi-pack-index write` and contains one `<name>.pack` per line. The implementation adds 15 lines to `builtin/repack.c` and 34 lines to `repack.c`, while removing 3 redundant lines from `repack-filtered.c`. The patch handles edge cases: it refuses pack names containing newlines (to prevent splitting) and ensures kept packs from alternate object directories are packed (not skipped), trading disk space for safety. The patch is **production-ready** and includes three new tests: (1) `t7700-repack.sh` verifies `--keep-pack` with `--pack-kept-objects` still excludes kept pack objects, (2) `t7703-repack-geometric.sh` reproduces the race and confirms objects are not lost, and (3) a second test in `t7703-repack-geometric.sh` ensures kept packs do not block traversal of reachable objects.

- **New plumbing**:
  - `--stdin-packs=follow` now treats `--keep-pack` packs as traversal blockers only if explicitly marked as closed (`^`); otherwise, they are treated as "kept-open" (`!`), allowing traversal through their objects (patch 1/5). This fixes the long-standing behavioral inconsistency where `--keep-pack` packs were incorrectly treated as closed under reachability.
  - `--stdin-packs=follow` with `--keep-pack` now correctly includes objects reachable through kept packs but stored in other packs (patch 1/5).
  - `repo_invalidate_kept_pack_caches()` helper (renamed from `packfile_store_invalidate_kept_pack_cache()` in this patch) exposed in `packfile.c`/`packfile.h` to invalidate the kept-pack cache for all ODB sources (patch 2/5). The v3 revision moves the cache invalidation logic from `builtin/pack-objects.c` to `packfile.c`, eliminating the unchecked downcast in the ODB source loop. The downcast now sits alongside existing ones in `packfile.c`, which will need to move together when the files backend layering is reworked.
  - **Performance optimization in `add_extra_kept_packs`** (patch 3/5): sorts the `--keep-pack` list once and replaces linear scans with binary search (`string_list_has_string`), yielding an 11× speed-up (11 s → 1 s) when matching 20,000 kept packs against 20,000 repository packs. The comparison function remains `fspathcmp()`, so matching behavior is unchanged.
  - `--keep-pack-from-file=<file>` added to `git pack-objects` (patch 4/5): reads a file containing one pack name per line (empty lines ignored, relative paths resolved against working directory) and treats them as if passed via `--keep-pack`. The file format matches other Git tools (e.g., `git multi-pack-index write --refs-snapshot`). The implementation reads the file line-by-line, appends non-empty lines to the same `string_list` used by `--keep-pack`, and sets `strdup_strings = 1` to manage memory ownership. The list now holds entries from two sources (command-line and file), but the behavior remains identical to `--keep-pack` for all callers.
  - `repack` now passes `pack-objects` the exact list of `.keep` packs observed at startup via `--keep-pack-from-file` (patch 5/5), replacing the `--honor-pack-keep` mechanism. The snapshot file is written next to the refs snapshot used for `multi-pack-index write` and contains one `<name>.pack` per line. The snapshot is only written when there are kept packs, matching the behavior of `--honor-pack-keep` when no `.keep` files were found. The implementation refuses pack names containing newlines and ensures kept packs from alternate object directories are packed (not skipped).
- **Behavior changes**:
  - `pack-objects --stdin-packs=follow` no longer incorrectly treats `--keep-pack` packs as closed under reachability (patch 1/5).
  - The cruft-pack walk now correctly traverses packs that were initially unknown to `pack-objects` but later marked as kept (patch 2/5).
  - Alternate ODB packs are now packed (not deleted), trading disk space for safety (patch 5/5).
- **On-disk format**: no changes.

  - Patch 2/5 adds a test in `t/t5329-pack-objects-cruft.sh` to verify the cruft-pack walk includes all reachable objects, even when the middle commit of an unreachable chain sits in an untold pack. The test reproduces the bug and confirms the fix.
  - Patch 3/5 includes performance measurements in the commit message.

    2. An error-handling test confirming the command fails cleanly when the file is missing.

    2. `t7703-repack-geometric.sh` reproduces the race (a `.keep` appearing mid-repack) and confirms objects are not lost.
