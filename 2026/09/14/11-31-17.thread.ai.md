Thread type: bugfix series

Core problem or goal
Fix a race condition in `git repack -d` where concurrent pushes can cause the repack machinery to delete packs whose objects were never copied elsewhere, resulting in data loss (dangling refs pointing to nonexistent commits). The v4 series replaces the `--honor-pack-keep` mechanism with a snapshot-based approach that explicitly tells `pack-objects` which packs it may delete via `--ignore-pack-keep-from`, eliminating the need for `--honor-pack-keep` entirely. The latent cruft-pack walk bug, which would become critical once `--honor-pack-keep` is removed, is also fixed.

Key technical details
- **Files touched**: `builtin/pack-objects.c`, `builtin/repack.c`, `packfile.c`, `repack.c`, `odb/source-packed.h`, `packfile.h`, `repack.h`, `tempfile.h`, `Documentation/git-pack-objects.adoc`, `t/t5329-pack-objects-cruft.sh`, `t/t5331-pack-objects-stdin.sh`, `t/t7700-repack.sh`, `t/t7703-repack-geometric.sh`
- **New plumbing**:
  - `repo_invalidate_kept_pack_caches()` (carried over from v3 patch 2/5) exposed in `packfile.c`/`packfile.h` to invalidate the kept-pack cache for all ODB sources. The v4 revision retains the v3 fix’s layering (downcast grouped in `packfile.c`) and Junio’s ack.
  - `--ignore-pack-keep-from=<file>` added to `git pack-objects` (patch 2/3): reads a file containing one pack name per line (empty lines ignored, relative paths resolved against working directory) and treats them as if they had no `.keep` file. The file format matches existing Git tools (e.g., `git multi-pack-index write --refs-snapshot`), and the implementation reuses the existing `--keep-pack` logic (now repurposed for exclusion). The patch includes tests in `t/t7700-repack.sh` to verify functional equivalence with `--keep-pack` (packing reachable objects from the named pack while loosening unreachable ones) and proper error handling for missing files.
  - `repack` now passes `pack-objects` the exact list of non-kept/cruft packs observed at startup via `--ignore-pack-keep-from` (patch 3/3), replacing the `--honor-pack-keep` mechanism. The snapshot file is written next to the refs snapshot used for `multi-pack-index write` and contains one `<name>.pack` per line. The implementation refuses pack names containing newlines (to prevent splitting) and ensures alternates are traversed (trading disk space for safety). The snapshot is only written when there are packs to delete, matching the behavior of `--honor-pack-keep` when no `.keep` files were found.
- **Behavior changes**:
  - The cruft-pack walk now correctly traverses alternates and `--keep-pack` packs, even when their objects are excluded (patch 1/3). This fixes a latent bug exposed by removing `--honor-pack-keep` and ensures objects reachable through untold packs are not lost.
  - Alternate ODB packs are now packed (not skipped), trading disk space for safety (patch 3/3).
  - `--ignore-pack-keep-from` avoids command-line length limits (e.g., `ARG_MAX`, Windows) by reading pack names from a file.
- **Performance impact**: The cruft walk now traverses alternates, which can slow down `repack -d -l --cruft` in shared clones (e.g., 2ms → 3.3s in a `clone --shared` of `git.git`). This is intentional (safety over speed) but may prompt discussion.
- **On-disk format**: no changes.
- **Test coverage**:
  - Patch 1/3 adds tests in `t/t5329-pack-objects-cruft.sh` to verify the cruft walk rescues objects through untold packs, `--keep-pack` packs, and alternates (with/without `--local`).
  - Patch 2/3 adds two tests in `t/t7700-repack.sh` to verify:
    1. `--ignore-pack-keep-from` behaves identically to `--keep-pack` for exclusion.
    2. The command fails cleanly when the input file is missing.
  - Patch 3/3 adds tests in `t7703-repack-geometric.sh` to reproduce the race (a `.keep` appearing mid-repack) for `-a -d`, `-A -d`, `-k`, `--cruft`, `--geometric`, and `--filter`, ensuring no objects are lost. The tests use a `git` wrapper to create a `.keep` file on the pack about to be deleted as `pack-objects` starts, simulating the race condition.

Open questions and loose ends
- **Performance trade-off**: The cruft walk’s traversal of alternates may slow down `repack -d -l --cruft` in shared clones. This is intentional (safety over speed) but may prompt discussion about whether the trade-off is acceptable or if optimizations (e.g., parallel traversal) are needed.
- **Edge cases**: Pack names with newlines are refused to prevent splitting, but this is unlikely to affect real-world use. No other edge cases are known.
- **Architectural layering**: The downcast grouping in `packfile.c` (from v3 patch 2/5) remains a point of discussion for ODB backend experts (Patrick Steinhardt, Justin Tobler), though Junio has acked the patch for the current codebase.
- **Integration**: No new technical objections are expected. The series is ready for `next` and likely to graduate to `master` in the current cycle.
