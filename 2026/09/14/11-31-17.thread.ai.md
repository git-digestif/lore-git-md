Thread type: bugfix series

Core problem or goal
Fix a race condition in `git repack -d` where concurrent pushes can cause the repack machinery to delete packs whose objects were never copied elsewhere, resulting in data loss (dangling refs pointing to nonexistent commits). The bug reproduces on Git 2.43 and `master` and was observed in production. The series addresses the root cause by ensuring `.keep` files are only removed by the process that created them, preventing orphaned packs during concurrent operations.
