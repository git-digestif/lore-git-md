This is a bugfix series targeting Git's pathspec handling in directory traversal. The v4 iteration of Yannik Tausch's two-patch series is now rebased on Junio C Hamano's synthetic merge base `d66ac2af30` (which includes the preparatory `const`-correctness patch) and incorporates feedback from Elijah Newren. The series fixes two related bugs: a heap-buffer-overflow when exclude pathspecs are shorter than the common prefix derived from positive pathspecs, and a logical error where an exclude pathspec appearing first in the list prevents `common_prefix_len()` from finding the shared directory among subsequent positive pathspecs.

The patches are narrowly scoped to `dir.c` and add thorough test coverage—both a functional test in `t/t6132-pathspec-exclude.sh` (covering the deterministic incorrect match and the out-of-bounds access) and unit tests in `t/unit-tests/u-dir.c`. The commit messages now clearly explain the observable incorrect behavior (e.g., `git ls-files a/b ':!x/b' a/c` incorrectly excluding `a/b/m`) and the memory-safety issue, and use consistent "non-exclude/exclude" terminology. The series is explicitly acknowledged as ready for integration, with no further technical changes expected.

This iteration addresses all substantive review feedback: it includes Elijah's suggested deterministic regression test, clarifies the performance optimization being restored, and maintains the output-parameter design (`common_prefix_len(pathspec, &matched_prefix)`) agreed upon in earlier rounds. The series is well-motivated, thoroughly tested, and carries minimal risk of regression—it corrects long-standing edge cases without altering the core pathspec matching logic. The integration plan (queued as a three-patch sequence in Junio's tree) remains unchanged.
