This thread introduces an opt-in incremental connectivity check for Git fetches and pushes, aiming to reduce the performance cost of verifying object connectivity. The feature, proposed by Kristofer Karlsson, shifts the verification cost from repository size to the size of incoming changes by processing commits in topological order and skipping unchanged subtrees. The initial v1 patch series is under review, with Junio C Hamano raising two technical concerns about edge-case handling in the new `tree-verify.c` implementation: promisor object checks and potential NULL-dereference risks.

Kristofer has now addressed both concerns in his latest reply. For promisor objects, he confirms the current implementation is safe due to `rev-list`'s behavior but plans to add a more defensive approach and additional tests to cover blobs. For the NULL-dereference risk, he agrees to add explicit checks to handle corrupted commits, even after `parse_commit_or_die()` succeeds. These fixes appear uncontroversial and bring the series closer to resolution. The patch remains in early review, with no version updates or merge status yet, but the author’s proactive testing and safeguards suggest the technical hurdles are being cleared. The only remaining bottleneck is the commit boundary-finding step for repositories with many refs, which is noted as a future optimization.
