This thread introduces a new **incremental connectivity check** for Git, designed to speed up fetches and pushes in large repositories by avoiding the full object connectivity verification that currently scales poorly with repository size. The feature is opt-in via `transfer.connectivityCheck=incremental` and is implemented as a new `rev-list` flag (`--verify-trees-incremental`).

**Key details**: The incremental mode processes incoming commits in topological order, tracking "trusted" objects from parent commits to skip unchanged subtrees. Benchmarks show dramatic improvements for small pushes (up to 190x faster, with memory usage dropping from 3.4 GB to 14 MB in one test case), though it’s 1.5x slower for very long histories (10,000+ commits). The implementation is self-contained, adding a new `tree-verify.c` file and updating `rev-list` and connectivity-checking code, with thorough documentation and test coverage.

**Status**: This is the first version of the series (two patches), posted by Kristofer Karlsson via GitGitGadget. No reviews or maintainer decisions have been recorded yet. The design is conservative—falling back to the full check for edge cases like deepening fetches—and the benchmarks suggest it addresses a real pain point for large repositories. The next steps will likely involve review feedback on correctness, edge cases, and potential optimizations (e.g., the commit boundary-finding bottleneck).
