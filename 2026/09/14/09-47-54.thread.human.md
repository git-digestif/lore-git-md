This thread introduces an opt-in incremental connectivity check for Git fetches and pushes, now in its second version (v2). The feature, authored by Kristofer Karlsson, aims to reduce the performance cost of verifying object connectivity—particularly in large repositories—by processing incoming commits incrementally rather than performing a full repository scan. The new mode, enabled via `transfer.connectivityCheck=incremental`, shifts the cost from repository size to the size of incoming changes, offering dramatic speedups (up to 190x faster) for small pushes while introducing only a modest regression for very long histories.

The v2 update addresses the two technical concerns raised by Junio C Hamano in the initial review. First, it adds explicit NULL checks after `get_commit_tree_oid()` calls to prevent potential crashes, replacing them with clear error messages. Second, it hardens the lazy-fetch protection by explicitly setting `repo->fetch_if_missing = 0` early in the `rev-list` option parsing and adding a `BUG()` assertion to catch future regressions. The series also includes a new test verifying that promised blobs are not lazy-fetched during incremental checks, along with thorough test coverage for correctness and performance.

The implementation is self-contained, running inside the existing `rev-list` subprocess (triggered by the new `--verify-trees-incremental` flag) to avoid the fragility of the earlier in-process prototype. The design falls back to the full check for edge cases like deepening fetches, shallow boundaries, and promisor objects, ensuring robustness. While the commit boundary-finding step remains a bottleneck for repositories with many refs, the author considers this a future optimization target. The series is now ready for further review, with prior concerns resolved and no new issues apparent.
