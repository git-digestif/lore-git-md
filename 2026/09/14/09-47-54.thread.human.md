This thread introduces an opt-in incremental connectivity check for Git fetches and pushes, aiming to reduce the cost of verifying object connectivity. The feature, now in its fourth iteration, is structured as a four-patch series covering documentation, performance tests, config plumbing, and implementation. Kristofer Karlsson is the author, and the series has cleared substantive maintainer review from Junio C Hamano, who called it "exciting."

The latest update (v4) refines the design with a three-mode config (`full`/`incremental`/`auto`) and a 1,000-commit cutoff for dynamic fallback to the full check, based on new benchmark data showing strong performance gains for medium and large repositories. Patrick Steinhardt’s recent review endorses these changes but suggests making the cutoff configurable via `auto[=<cutoff>]` and reinforces the need to avoid new `die()` calls in library code. Kristofer has agreed to both, centralizing error handling at the subprocess boundary. The series is now nearly ready for integration, with only mechanical adjustments remaining. The unresolved stack overflow risk in recursive tree verification is acknowledged as a potential follow-up.
