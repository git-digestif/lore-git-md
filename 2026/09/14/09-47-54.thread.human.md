This thread introduces an opt-in incremental connectivity check for Git fetches and pushes, aimed at reducing the performance cost of verifying object connectivity in large repositories. The feature, proposed by Kristofer Karlsson, adds a new configuration option (`transfer.connectivityCheck=incremental`) that processes incoming commits in topological order, verifying trees against their parents rather than walking the entire object closure. This shifts the cost from repository size to the size of incoming changes, offering up to 190x speedups for small pushes to large repos while maintaining semantic equivalence with the existing full check.

The series is currently under review in its initial version (v1). The first patch laid the groundwork with documentation and configuration, while the second patch (just summarized) implements the core logic in a new `tree-verify.c` file and wires it up to `rev-list` and the connectivity check subsystem. The implementation is conservative, falling back to the full check for edge cases like deepening fetches or very long histories, and includes extensive test coverage and performance benchmarks. No design objections or change requests have been raised yet, though the author notes that future work could optimize the commit boundary-finding step. The feature remains opt-in, with the default behavior unchanged.
