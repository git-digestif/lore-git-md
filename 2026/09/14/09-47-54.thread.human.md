This thread is about a four-patch series by Kristofer Karlsson that introduces an opt-in incremental connectivity check for Git fetches and pushes, aiming to reduce the cost of verifying object connectivity in large repositories. The series is now at version 3, with all prior feedback addressed, and is split into documentation, baseline performance tests, config plumbing (this latest email), and the implementation.

The latest update is the plumbing patch (3/4), which adds the `transfer.connectivityCheck` configuration option (accepting `full` or `incremental`) and wires up the internal `--verify-trees-incremental` flag in `git rev-list`. This patch is purely preparatory—it sets up the config and flag but doesn’t yet change behavior. The config key is the user-facing toggle, while the `rev-list` flag is an internal hook for the incremental verifier, which will be introduced in the next patch. The patch also ensures the subprocess doesn’t trigger lazy fetches in partial clones, aligning with the connectivity check’s assumptions.

The series is under active review, with the author considering it production-ready behind its opt-in config. Key participants include Junio C Hamano, who raised initial concerns about edge cases (now resolved), and Patrick Steinhardt, who provided substantive feedback on documentation, trust boundary detection, and performance trade-offs—all of which have been addressed. The plumbing patch itself is minimal and focused, making it a low-risk prerequisite for the final implementation. The only remaining open question is the long-term viability of the subprocess architecture for server-side operations, though this is acknowledged as out of scope for the current series.
