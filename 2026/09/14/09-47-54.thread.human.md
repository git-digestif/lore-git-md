This thread introduces an opt-in incremental connectivity check for Git fetches and pushes, aiming to reduce the cost of verifying object connectivity. The feature, proposed by Kristofer Karlsson, is now in its third version and has gained strong interest from maintainer Junio C Hamano, who called it "exciting" and accepted its performance trade-offs as reasonable for an opt-in mode. The series is split into four patches covering documentation, baseline performance tests, config plumbing, and the core implementation, all of which have addressed prior feedback.

The implementation adds a new config key (`transfer.connectivityCheck=incremental`) and introduces an inductive trust algorithm in `tree-verify.c` that verifies only changed subtrees, shifting the cost from repository size to incoming change size. Benchmarks show up to 190x speedup for small pushes to large repositories, with modest regressions for very long histories. The feature falls back to the full check for edge cases like deepening fetches or promisor objects. All substantive review feedback—including concerns about NULL-dereference risks, lazy-fetch handling, and documentation clarity—has been resolved.

The only remaining open point is a refactoring suggestion from Junio to reduce reliance on the `the_repository` global variable by adding a `struct repository *repo` field to `check_connected_options`. Kristofer has acknowledged this and is preparing to address it in the next version. The series is effectively cleared from a maintainer perspective and appears headed for integration once this final technical point is resolved. No other objections or loose ends remain.
