This thread is about a patch series introducing an opt-in incremental connectivity check for Git fetches and pushes, aimed at reducing the cost of verifying object connectivity in large repositories. The series, now at version 3, is authored by Kristofer Karlsson and consists of four patches: documentation, baseline performance tests, config plumbing, and the core implementation.

The feature has gained strong interest from Junio C Hamano, who called it "exciting" and accepted its performance trade-offs (a 1.5x slowdown for very long incoming histories) as reasonable for an opt-in mechanism. All prior feedback—including concerns about NULL-dereference risks, lazy-fetch handling, and documentation clarity—has been addressed. The series is now effectively cleared from a maintainer perspective, though it remains under review pending further input from other contributors.

The latest exchange settled the scope of a refactoring in patch 3/4, with Junio deferring a broader cleanup of `the_repository` usage to avoid scope creep. A new open question remains: whether to add a dynamic fallback mechanism to disable incremental mode for very long incoming histories (e.g., 10,000+ commits). Kristofer framed this as a trade-off between safety and code simplicity, but no consensus has emerged yet.

Patrick Steinhardt’s recent review of the performance test suite (patch 2/4) identified two minor mechanical issues: missing the `PERL` prerequisite in the test script and a copy-paste error in the Perl script’s usage comment. Both are trivial to fix and will be addressed in the next reroll. His earlier review of the documentation (patch 1/4) also prompted two actionable changes: adding the new technical document to the build system and documenting the promisor fast path, both of which Kristofer accepted.

The implementation introduces a new config key (`transfer.connectivityCheck=incremental`), a `rev-list` flag (`--verify-trees-incremental`), and a new source file (`tree-verify.c`) that implements the incremental verification logic. Benchmarks show up to 190x speedups for small pushes to large repositories, with bounded regressions for very long histories. The series is now poised for integration once the remaining nits and the dynamic fallback question are resolved.
