This thread is about a six-patch series introducing an opt-in incremental connectivity check for Git fetches and pushes, aimed at reducing the performance cost of verifying object connectivity. The feature is now complete and ready for integration, with all prior feedback addressed in the latest v5 revision.

The series adds a new `transfer.connectivityCheck` configuration option with three modes: `full` (the default), `incremental` (which processes incoming commits in topological order, skipping unchanged subtrees), and `auto` (which dynamically switches between the two based on a configurable 1,000-commit cutoff). The core implementation in `tree-verify.c` uses an inductive trust model—parent trees are trusted, and new trees are verified only where they differ—avoiding lazy fetches and handling promisor objects correctly. Benchmarks show the incremental mode is up to 190x faster for small pushes to large repositories, with a modest slowdown for very long incoming histories, mitigated by the auto mode fallback.

Key participants include Kristofer Karlsson (the author), Junio C Hamano (the maintainer), and Patrick Steinhardt (a reviewer). Junio initially raised concerns about edge-case robustness and lazy-fetching assumptions, both resolved in v5. Patrick provided detailed feedback on trust boundary detection, error handling, and performance trade-offs, leading to the adoption of the three-mode config design and configurable cutoff. The latest exchange between Junio and Kristofer confirms the plan to remove a `BUG()` guard in v5, simplifying the code without introducing new blockers. The series is effectively cleared for integration pending final sign-off.
