This thread introduces an opt-in incremental connectivity check for Git fetches and pushes, aiming to reduce the cost of verifying object connectivity. The feature, now in its fourth iteration, is authored by Kristofer Karlsson and has gained strong interest from Junio C Hamano, who called it "exciting" and accepted its performance trade-offs—such as a 1.5x slowdown for very long incoming histories—as reasonable for an opt-in tool.

The series is split into four patches: documentation, baseline performance tests, config plumbing, and the core implementation. All prior feedback has been addressed, including Junio’s concerns about edge-case robustness and Patrick Steinhardt’s detailed reviews on documentation, error handling, and code structure. The latest update reorganizes the plumbing patch into three smaller, self-contained steps to improve reviewability, a change suggested by Patrick and accepted by Kristofer. The only remaining open question is whether to add a dynamic fallback mechanism for very long incoming histories, but this is now framed as a design trade-off rather than a blocker.

The implementation introduces a new config key (`transfer.connectivityCheck=incremental`), a `rev-list` flag (`--verify-trees-incremental`), and a dedicated verifier in `tree-verify.c`. It reuses Git’s existing boundary-detection mechanism and falls back to the full check for edge cases like deepening fetches or promisor objects. Benchmarks show up to 190x speedups for small pushes to large repositories, with the trade-off of modest regressions for very long histories. The series is now effectively cleared for integration, pending final feedback.
