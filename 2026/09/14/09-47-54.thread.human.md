This thread introduces an opt-in incremental connectivity check for Git fetches and pushes, aiming to reduce the cost of verifying object connectivity. The feature, now in its third version, is authored by Kristofer Karlsson and has gained strong interest from Junio C Hamano, who called it "exciting" and accepted its performance trade-offs. The series is effectively cleared from the maintainer's perspective, pending further feedback.

The latest exchange focuses on patch 3/4, which adds the configuration plumbing. Patrick Steinhardt suggests a cleaner three-step approach: first introduce the config option (accepting only the default "full"), then implement the `rev-list` flag, and finally enable the "incremental" config value. This would make each patch self-contained without changing functionality. The author has addressed all prior feedback, including Junio's concerns about edge cases and Patrick's documentation and implementation questions. The remaining open questions include whether to add a dynamic fallback for very long incoming histories and how to handle potential stack overflow in recursive tree verification.

The implementation introduces a new `transfer.connectivityCheck=incremental` config key and a `tree-verify.c` file with an inductive trust algorithm that verifies only new trees differing from parent commits. Benchmarks show up to 190x speedup for small pushes to large repositories, with a 1.5x slowdown for very long histories accepted as a trade-off. The series is now poised for integration once the remaining review points are addressed.
