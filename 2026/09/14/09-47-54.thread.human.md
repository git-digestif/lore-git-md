This thread introduces an opt-in incremental connectivity check for Git fetches and pushes, aiming to reduce the cost of verifying object connectivity by processing incoming commits in topological order. Kristofer Karlsson proposed the feature in a two-patch series (v1), adding a new `transfer.connectivityCheck=incremental` configuration, a `tree-verify.c` implementation, and extensive tests and documentation. Junio C Hamano initially acknowledged the series with enthusiasm for its benchmarks but had not yet provided detailed feedback.

Junio has now posted a substantive review of the implementation, raising two critical edge-case concerns in `tree-verify.c`. First, he notes that the `is_promisor_object()` check in `verify_blob()` occurs *after* `odb_read_object_info()`, which could trigger unintended lazy fetches from promisor remotes, undermining the incremental check’s goal of avoiding network round-trips. Second, he flags potential NULL-dereference risks in `verify_commit_tree()` if `get_commit_tree_oid()` returns NULL due to missing or corrupted trees, which the code currently passes unchecked to `tree_map_add()`. These issues focus on robustness rather than design or performance, and no other objections or requests for changes have been raised yet. The series remains under review, with these safety concerns now the primary open questions.
