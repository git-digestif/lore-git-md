This thread is about a patch series introducing an opt-in incremental connectivity check for Git fetches and pushes, aimed at reducing the performance cost of verifying object connectivity in large repositories. The feature, proposed by Kristofer Karlsson, adds a new configuration option (`transfer.connectivityCheck=incremental`) that processes incoming commits in topological order, verifying only the changes against trusted parent trees rather than scanning the entire repository.

The series is now at version 2, with a planned version 3 to address feedback. Junio C Hamano’s initial technical concerns—NULL checks and lazy-fetch protection—were resolved in v2, and Patrick Steinhardt has provided substantive review on both the documentation and implementation patches. The latest exchange between Patrick and Kristofer clarified a key technical point: the incremental mode still relies on `git rev-list --not --all` to establish the trust boundary (marking preexisting ref tips as uninteresting), but avoids the full tree walk of those boundary commits. This ensures correctness while preserving the performance gains—up to 190x faster for small pushes to large repositories. The subprocess architecture (using `die()` for errors) was also confirmed as safe for server-side operations like `git-receive-pack`.

The remaining work for v3 includes splitting the implementation patch into smaller commits for better reviewability and addressing Patrick’s documentation feedback (e.g., clarifying the connectivity invariant and removing code references to avoid staleness). No major objections remain, and the series is expected to proceed smoothly once the revisions are posted. The feature is positioned as a "first step" toward broader scalability improvements, though future directions like MIDX-based connectivity closure or parallel ref loading are explicitly out of scope for now.
