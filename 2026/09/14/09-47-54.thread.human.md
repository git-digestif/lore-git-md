This thread is about Kristofer Karlsson’s patch series introducing an opt-in incremental connectivity check (`transfer.connectivityCheck=incremental`) to speed up fetches and pushes in large repositories. The feature processes incoming commits in topological order, trusting objects from parent commits to skip unchanged subtrees, shifting the cost from repository size to the size of incoming changes. The series is now at v2, with two patches: one for documentation and one for implementation.

Kristofer has addressed Junio C Hamano’s initial technical concerns—adding NULL checks and hardening lazy-fetch protection—and is now responding to Patrick Steinhardt’s detailed review of the documentation. Patrick raised three points about precision, maintainability, and clarity, all of which Kristofer has accepted and plans to address in the next revision. The documentation patch explains the connectivity invariant, the existing full check, and exceptions like submodules and promisor objects, serving as a foundation for the implementation. Meanwhile, the implementation patch (which adds the new `tree-verify.c` file and integrates the verifier into `rev-list` and `connected.c`) is still under review, with Patrick raising questions about trust boundary detection, error handling, and performance trade-offs.

The series is still under active review, with no merge status yet. Kristofer has also clarified that while the current work is a "useful first step" toward broader scalability challenges, future directions like MIDX-based connectivity closure and parallel ref loading are explicitly out of scope for now. The next step is likely a v3 incorporating Patrick’s feedback on the documentation.
