This thread is about Kristofer Karlsson’s patch series introducing an opt-in incremental connectivity check for Git fetches and pushes, aimed at reducing the performance cost of verifying object connectivity in large repositories. The feature, now in its second version, allows users to set `transfer.connectivityCheck=incremental` to shift the verification cost from repository size to the size of incoming changes by processing commits in topological order and trusting objects from parent commits.

The series has two patches: one for documentation and one for implementation. Junio C Hamano’s initial review of the first version raised two technical concerns—NULL-dereference risks and lazy-fetch protection—which were addressed in v2. Patrick Steinhardt has since provided substantive feedback on both patches. His review of the documentation patch focused on precision and maintainability, while his latest review of the implementation patch raises deeper questions about the algorithm’s trust boundary detection, error-handling strategy, and performance trade-offs. Specifically, Patrick asks how the verifier identifies trusted trees without parsing all refs, suggests softer error handling for server-side operations, and notes that the incremental mode may verify more objects in scenarios with many refs or large boundary trees.

The series is still under review, with no merge status. Kristofer has addressed prior feedback but will likely need to respond to Patrick’s latest points before a third version is posted. The implementation is technically sound but may require adjustments to its boundary detection logic and error handling to better align with server-side expectations. No other reviewers have raised objections, and the feature remains a promising optimization for large repositories.
