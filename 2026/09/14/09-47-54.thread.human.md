This thread introduces an opt-in incremental connectivity check for Git fetches and pushes, aiming to reduce the performance cost of verifying object connectivity. The feature is now in its fourth iteration, structured as a six-patch series that includes documentation, baseline performance tests, refactoring, config plumbing, implementation, and an auto mode with a configurable cutoff. The core idea is to process incoming commits in topological order, tracking trusted objects from parent commits to skip unchanged subtrees, shifting the cost from repository size to incoming change size.

The series has cleared significant hurdles, with maintainer Junio C Hamano calling it "exciting" and all prior feedback addressed. Key participants include Kristofer Karlsson (the author), Junio, and Patrick Steinhardt, who provided thorough reviews. The latest update introduces a three-mode config design (`full`/`incremental`/`auto[=<n>]`) with a 1,000-commit cutoff for dynamic fallback to the full check, balancing performance and safety. Error handling has been refined to avoid new `die()` calls in library code, aligning with Git’s libification goals. The stack overflow risk in recursive tree verification remains unresolved but is acknowledged as a potential follow-up.

The series is now effectively ready for integration, pending final feedback. The new documentation patch in this update provides essential technical background, explaining Git’s connectivity invariant, the existing full check’s limitations, and edge cases like gitlinks and promisor objects. This documentation is aimed at developers and reviewers, not end users, and is confirmed for build system integration. No new blockers have been raised, and the series is rebased onto the latest master.
