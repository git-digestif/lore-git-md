This thread introduces an opt-in incremental connectivity check for Git fetches and pushes, allowing users to reduce verification overhead with `transfer.connectivityCheck=incremental` or `auto`. The feature is now complete in its v4 six-patch series, covering documentation, performance tests, refactoring, config plumbing, core implementation, and auto mode with a configurable 1,000-commit cutoff. Kristofer Karlsson is the author, and the series has received thorough review from Junio C Hamano and Patrick Steinhardt, addressing all prior feedback.

The implementation processes incoming commits in topological order, tracking trusted objects from parent commits to skip unchanged subtrees. This shifts the cost from repository size to incoming change size, with benchmarks showing up to 190x speedup for small pushes to large repos while maintaining correctness. The auto mode dynamically switches between incremental and full checks based on the incoming history size, preserving all existing fallback logic for deepening fetches, promisor objects, and other edge cases.

The latest discussion resolved the last technical concern about lazy-fetching behavior. Kristofer will submit a v5 revision that eliminates reliance on `repo->fetch_if_missing` by using `odb_read_object_info_extended()` with `OBJECT_INFO_SKIP_FETCH_OBJECT`, making the code more robust and maintainable. Junio and Patrick have both signaled the series is ready for integration pending this minor update. The only remaining open question is whether to document the reasoning behind this change in the commit message, though the code change itself makes the explanation largely redundant.
