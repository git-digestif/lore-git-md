This thread is about Kristofer Karlsson’s patch series introducing an opt-in incremental connectivity check for fetch and push operations, aimed at reducing the performance cost of verifying object connectivity in large repositories. The feature, now in its second version, has addressed initial feedback from Junio C Hamano and is under substantive review by Patrick Steinhardt.

The core idea is to shift the cost of connectivity checks from repository size to the size of incoming changes by processing commits in topological order and trusting objects from parent commits, skipping unchanged subtrees. The implementation adds a new config key (`transfer.connectivityCheck=incremental`), a `rev-list` flag (`--verify-trees-incremental`), and a new source file (`tree-verify.c`) that implements the inductive trust algorithm. Benchmarks show up to a 190x speedup for small pushes to large repos, though the mode falls back to a full check for deepening fetches or very long histories.

Patrick Steinhardt’s latest review pushes back on Junio’s tangential suggestion to expand connectivity checks to include non-ref roots like index entries. Patrick argues that the current scope—optimizing ref-based checks—is the right focus, as the performance bottleneck is primarily server-side (where index entries are absent) and adding more roots would likely worsen scalability in repos with many refs. The thread remains centered on the incremental mode, with open questions about trust boundary detection, error handling, and documentation clarity still under discussion. No merge decisions have been made, and a third version may be needed to address Patrick’s feedback.
