This thread introduces an opt-in incremental connectivity check for Git fetches and pushes, aimed at reducing the performance cost of verifying object connectivity. The feature is implemented as a six-patch series (v5) by Kristofer Karlsson, with all prior feedback addressed and the series now ready for integration. The core idea is to process incoming commits in topological order, tracking trusted objects from parent commits to skip unchanged subtrees, shifting the cost from repository size to incoming change size.

The series includes technical documentation (patch 1/6), baseline performance tests (2/6), refactoring to remove `the_repository` dependency (3/6), config plumbing (4/6), the core implementation (5/6), and an auto mode with a configurable 1,000-commit cutoff (6/6). The auto mode dynamically switches between incremental and full checks based on the size of the incoming history, balancing performance and safety. Benchmarks show the incremental mode is up to 190x faster for small pushes to large repositories, with a modest slowdown for very long incoming histories mitigated by the auto mode fallback.

Key participants include Kristofer Karlsson (author), Junio C Hamano (maintainer), and Patrick Steinhardt (reviewer). Junio has signaled strong interest ("This is exciting") and the series is effectively cleared for integration pending final sign-off. Patrick provided detailed reviews, suggesting improvements like the configurable cutoff and three-mode config design, which were adopted. The latest revision (v5) addresses Junio’s forward-compatibility concerns by eliminating reliance on `repo->fetch_if_missing` in the new code paths.

Open questions include a potential stack overflow risk for very deep trees (acknowledged as a follow-up) and the long-term viability of the subprocess architecture for server-side operations. The series is complete, well-tested, and ready for integration, with no new blockers introduced in the latest revision.
