The thread introduces an opt-in incremental connectivity check for Git fetches and pushes, aiming to reduce the cost of verifying object connectivity in large repositories. The feature, now in its third iteration (v3), is implemented as a four-patch series: documentation, baseline performance tests, config plumbing, and the core implementation. Kristofer Karlsson is the author, and the series has gained strong interest from Junio C Hamano, who called it "exciting" and accepted its performance trade-offs (a 1.5x slowdown for very long incoming histories) as reasonable for an opt-in feature.

The implementation adds a new config key, `transfer.connectivityCheck=incremental`, and a new internal `rev-list` flag, `--verify-trees-incremental`. It processes incoming commits in topological order, trusting parent trees to skip unchanged subtrees, which shifts the cost from repository size to the size of incoming changes. Benchmarks show up to 190x speedups for small pushes to large repos, with edge cases (deepening fetches, shallow boundaries, promisor objects) handled by falling back to the full check. The series has addressed all prior feedback, including Junio’s concerns about NULL-dereference risks and Patrick Steinhardt’s documentation and implementation suggestions.

The main open questions are whether to add a dynamic fallback mechanism for very long incoming histories (10,000+ commits) and how to mitigate potential stack overflow risks in recursive tree verification. Patrick Steinhardt’s latest review also suggests splitting the plumbing patch into three smaller, self-contained steps for easier review. The author has accepted these suggestions and is preparing a v4 reroll. The series is effectively cleared from a maintainer perspective but remains under review for final polish.
