This thread is about Kristofer Karlsson’s patch series introducing an opt-in incremental connectivity check for fetch and push operations, aiming to reduce the performance cost of verifying object connectivity in large repositories. The series is now at v2, addressing Junio C Hamano’s earlier technical concerns about edge-case robustness in the implementation.

The core idea is to shift the cost of connectivity checks from repository size to the size of incoming changes by processing commits in topological order and trusting objects already verified in parent commits. The implementation adds a new config key (`transfer.connectivityCheck=incremental`), a `rev-list` flag (`--verify-trees-incremental`), and a new source file (`tree-verify.c`) that implements the inductive trust algorithm. Benchmarks show up to 190x speedups for small pushes to large repos, though the mode falls back to the full check for deepening fetches, very long histories, or promisor objects.

Patrick Steinhardt has provided substantive feedback on both patches, raising questions about trust boundary detection, error handling, and performance trade-offs, as well as suggesting the implementation patch be split for better reviewability. Junio’s latest reply sidesteps the immediate documentation discussion and instead flags a tangential but broader question: whether connectivity checks should account for non-ref roots like index entries when running `fsck`. This is a speculative observation, not a request for changes, and the thread remains focused on the incremental mode’s review. No merge decisions have been made, and the series is still under active discussion.
