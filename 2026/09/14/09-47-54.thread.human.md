This thread introduces an opt-in incremental connectivity check for Git fetches and pushes, aiming to reduce the cost of verifying object connectivity. The feature, proposed by Kristofer Karlsson, is now at version 2 of the patch series and under active review. The core idea is to shift the verification cost from repository size to incoming change size by processing commits in topological order and tracking trusted objects from parent commits to skip unchanged subtrees.

Junio C Hamano and Patrick Steinhardt have provided substantive feedback, all of which has been addressed in the latest version. Junio’s concerns about edge-case robustness (NULL checks and lazy-fetch protection) were resolved in v2, while Patrick’s questions about trust boundary detection, error handling, and performance trade-offs were clarified in the latest exchange. The incremental mode reuses the same boundary-detection mechanism as the full check (`git rev-list --not --all`) and processes commits in reverse topological order, ensuring correctness without parsing all refs upfront. The implementation, housed in `tree-verify.c`, achieves up to 190x speedups for small pushes to large repositories while maintaining semantic equivalence with the full check.

The series is now poised for a v3 revision, which will split the implementation patch into smaller commits for better reviewability and address Patrick’s documentation feedback. Open questions include the long-term viability of the subprocess architecture (using `die()` for errors) and scalability of ref-parsing overhead, though these are acknowledged as out-of-scope for the current effort. The feature remains a focused first step toward broader scalability improvements, with future directions like MIDX-based connectivity closure and parallel ref loading left for later work.
