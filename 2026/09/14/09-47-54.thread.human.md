This thread introduces an **incremental connectivity check** for Git fetches and pushes, an opt-in performance feature that reduces the cost of verifying object connectivity. The existing full check scales poorly with repository size; the new mode processes incoming commits in topological order, tracking trusted objects from parent commits to skip unchanged subtrees. The feature is controlled by the `transfer.connectivityCheck` config key, which supports three modes: `full` (default), `incremental`, and `auto[=<n>]` (with a 1,000-commit cutoff). Benchmarks show up to a 190x speedup for small pushes to large repositories, with a modest slowdown for very long incoming histories (mitigated by the auto mode fallback).

The series, authored by Kristofer Karlsson, consists of six patches: documentation, baseline performance tests, refactoring to drop `the_repository` dependencies, config plumbing, the core implementation in `tree-verify.c`, and the auto mode. All prior feedback has been addressed, including concerns about promisor objects, lazy fetches, and stack overflow risks. Junio C Hamano has given his **final sign-off**, and the series is now **ready for integration into `next`**. The implementation is self-contained, thoroughly tested, and backward-compatible, with no on-disk format changes. Key contributors—Junio, Patrick Steinhardt, and Kristofer—have all reviewed and endorsed the design, including the configurable cutoff and three-mode config.

The only open technical question is a potential follow-up to mitigate stack overflow risk for very deep trees, but this is acknowledged in the documentation and not a blocker for merging. The feature is opt-in and conservative, falling back to full checks for edge cases like deepening fetches or shallow boundaries. Downstream users can expect the new config keys and `tree-verify.c` subsystem to be stable in the next release cycle.
