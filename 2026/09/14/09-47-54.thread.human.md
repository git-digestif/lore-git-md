The incremental connectivity check feature (`transfer.connectivityCheck=incremental` or `auto`) is now in its fourth iteration, with all six patches submitted and ready for integration. The series, authored by Kristofer Karlsson, introduces an opt-in mode to reduce the cost of verifying object connectivity during fetches and pushes by processing incoming commits incrementally, shifting the performance burden from repository size to the size of incoming changes.

The latest version addresses all prior feedback, including a refactoring to eliminate reliance on `the_repository`, a configurable three-mode design (`full`/`incremental`/`auto[=<n>]`) with a 1,000-commit cutoff for dynamic fallback, and thorough performance benchmarks. Junio C Hamano and Patrick Steinhardt have both reviewed the series substantively, with Junio calling it "exciting" and Patrick endorsing the design and heuristics. The only remaining open questions are forward-looking: a potential stack overflow risk in deep trees (acknowledged for follow-up) and long-term maintainability concerns about lazy-fetching assumptions and promisor-object handling, which Junio raised in the latest review. These do not block integration but may prompt minor adjustments in a future revision.

The implementation adds new config keys, a `rev-list` flag, and a dedicated `tree-verify.c` module that uses an inductive trust algorithm to skip unchanged subtrees. Performance tests show up to 190x speedups for small pushes to large repositories, with negligible overhead for small repos. The series is rebased onto master, includes comprehensive tests, and preserves backwards compatibility. No merge status has been reported yet, but the maintainer’s tone suggests it is likely to graduate soon.
