This is the v4 iteration of a two-patch bugfix series targeting Git’s pathspec handling in directory traversal. The series fixes two related issues: a heap-buffer-overflow when matching exclude pathspecs shorter than the common prefix derived from positive pathspecs, and a logical bug where an exclude pathspec appearing first in the list prevents `common_prefix_len()` from finding the common prefix among subsequent positive pathspecs, breaking an optimization that avoids scanning unrelated directories.

The v4 iteration returns to a two-patch structure (dropping the earlier v3 three-patch split) by basing the series on Junio C Hamano’s synthetic merge base `d66ac2af30`, which already includes his preparatory const-correctness patch. The core changes remain identical to v2, but the commit messages now use consistent "non-exclude/exclude" terminology and explicitly describe the observable incorrect match (e.g., `git ls-files a/b ':!x/b' a/c` incorrectly excluding `a/b/m`). The series also adds Elijah Newren’s suggested deterministic regression test for the heap-buffer-overflow, which uses an exclude pathspec whose length exactly matches the common prefix of positive pathspecs to reliably trigger the bug without AddressSanitizer.

Key technical details: the first patch ensures exclude pathspecs are matched against the full pathname (not the common prefix), preventing both the out-of-bounds read and false positives; the second patch refactors `common_prefix_len()` to use the first *non-exclude* pathspec as the comparison base, restoring the directory-walk optimization. Files touched are `dir.c`, `t/t6132-pathspec-exclude.sh` (functional test), and `t/unit-tests/u-dir.c` (unit test). The series is narrowly scoped to pathspec handling and directory traversal, with no broader subsystem changes. Junio’s integration plan remains unchanged: the series is queued for merging, and the author has confirmed no further action is required.
