This is Junio’s biweekly “What’s cooking in git.git” report for September 2026, summarizing the state of integration branches and in-flight topics.

Git 2.56-rc0 has been tagged, so the current cycle is in stabilization mode. About 80 topics are cooking in `next` (candidates for 2.56 final) and 228 are in `seen` (still under review). The report highlights which topics have graduated to `master`, which are newly proposed, and which are still cooking.

Notable graduations to `master` include:
- A documentation fix for `git cherry-pick --no-commit` clarifying that it skips setting `CHERRY_PICK_HEAD`.
- A safety improvement in `git commit` that refuses `--amend` or partial commits during conflict resolution, aligning it with `cherry-pick` and `merge`.
- A segfault fix in `git history` when a parent tree is missing.
- Memory leak fixes in submodule handling and CI documentation updates.

New topics worth watching:
- `hn/range-diff-matched-only` adds a `--matched-only` option to `git range-diff` to skip one-sided commits, making it easier to focus on retained changes.
- `js/rust-in-windows-ci` enables Rust builds in Windows CI, a step toward broader Rust support.
- `jt/object-file-batch-fsync-fix` fixes a bug in the ODB transaction logic when `core.fsyncMethod=batch`, preventing failures during packfile migration.
- `tb/rerere-wait-for-merge-rr-lock` makes `rerere` wait for the `MERGE_RR.lock` instead of failing immediately when `rerere gc` is running, improving robustness during concurrent operations.
- `ps/odb-pluggable-fsck` moves fsck checks into the ODB backend, making them pluggable for different storage formats. This is a significant refactoring that graduated to `next` and is likely to land in `master` soon.

Ongoing efforts:
- The `the_repository` removal and ODB abstraction efforts continue with patches like `ps/odb-stop-registering-in-memory-sources`, which removes ad-hoc alternate registration in favor of native submodule ODB access.
- `ps/ref-storage-format` standardizes terminology around reference storage formats, replacing `--ref-format` with `--ref-storage-format` across commands.
- `hn/history-squash` adds a new `git history squash` subcommand to fold a range of commits into one, with descendants replayed on top. This is part of the experimental `git history` command and looks well-structured.

The report also notes several topics needing review or rerolls, such as `tz/doc-pack-refs-and-refs-fixes` (doc updates) and `tb/midx-incremental-custom-base` (a midx bugfix). Overall, the integration branches are active but stabilizing for the upcoming 2.56 release.
