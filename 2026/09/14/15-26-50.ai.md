This is a **substantive review** from Junio C Hamano on the incremental connectivity check patch (2/2). The review raises two technical concerns about edge-case handling in the new `tree-verify.c` implementation.

First, Junio questions whether the `is_promisor_object()` check in `verify_blob()` happens too late: the function already calls `odb_read_object_info()` before checking for promisor objects, which could trigger a lazy fetch from the promisor remote. This might violate the intended semantics of the incremental check (avoiding network round-trips) and could lead to unexpected behavior if the fetch fails or is slow.

Second, Junio points out potential NULL-dereference risks in `verify_commit_tree()`: if `parse_commit_or_die()` succeeds but the commit's tree is missing or corrupted, `get_commit_tree_oid()` could return NULL, which would then be passed to `tree_map_add()`. The same issue exists for the incoming commit's tree outside the parent loop. The review does not suggest a specific fix but implies the code should either handle these cases gracefully or document why they are impossible.

The review is narrowly focused on these two low-level safety issues and does not engage with the broader design or performance claims of the series. Both points target the robustness of the implementation rather than its correctness or efficiency. No other feedback or objections are raised in this email.
