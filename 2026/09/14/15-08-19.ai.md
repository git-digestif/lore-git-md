This is the latest review feedback in Patrick Steinhardt’s 13-patch series to standardize Git’s ref-storage-format terminology. Kaartic Sivaraam acknowledges the v3 revision addresses all prior feedback but raises a new concern: the test suite now exclusively uses the new option names (`--ref-storage-format=`, `GIT_REF_STORAGE_FORMAT`, etc.) and environment variables, with no explicit test coverage for the deprecated backward-compatible aliases (`--ref-format=`, `GIT_REFERENCE_BACKEND`, etc.). While the aliases are implemented via `OPT_ALIAS_F()` and environment-variable fallbacks, Sivaraam suggests adding dedicated tests to verify they continue to work as expected, ensuring the backward-compatibility guarantees are actually met in practice.

The feedback is substantive but narrow: it targets test coverage rather than the core logic or design. The series already implements the aliases and fallbacks correctly (as confirmed by prior reviews), but Sivaraam’s point is that the absence of tests for the deprecated variants leaves a gap in regression protection. This is a common oversight in large refactoring series, where the focus shifts to the new names and the old ones are assumed to work by construction. The request is low-risk and aligns with Git’s testing philosophy—explicit tests for edge cases and backward compatibility—so it is likely to be addressed in a v4 or as a follow-up patch. No technical objections to the series remain; this is the sole open question.
