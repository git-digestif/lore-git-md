This is the first patch in a **bugfix series** addressing a data-loss race in `git repack -d` when concurrent pushes occur. The patch prevents `receive-pack` from removing `.keep` files it didn’t create, which is a prerequisite for the full race fix in patch 6/6.

The issue arises when two pushes of identical content produce identical thin packs, leading `index-pack` to target the same `.keep` file in the main object database. If the first push’s `.keep` is still present when the second push’s quarantine is migrated, `receive-pack` would previously remove it unconditionally—even if the push was rejected or the `.keep` belonged to another pack. This could orphan packs, leaving dangling refs.

The fix changes the timing of `.keep` file registration: instead of registering the destination path upfront (when the file doesn’t yet exist), the patch registers it just before migration and verifies its contents afterward. If the file contains a message other than the one `index-pack` wrote (e.g., from another push), the patch disowns it using a new `unregister_tempfile()` helper, leaving it untouched. This ensures only `.keep` files created by the current push are removed.

The patch touches `object-file.c` (adding logic to track and verify `.keep` files), `tempfile.c`/`tempfile.h` (introducing `unregister_tempfile()`), and adds two new tests in `t/t5547-push-quarantine.sh` to verify:
1. A rejected push doesn’t remove a foreign `.keep`.
2. A `.keep` installed during a failed migration is still cleaned up.

The implementation is careful to avoid introducing new race windows. By registering the `.keep` path before migration (but not tracking it as a tempfile until afterward), the patch maintains the existing guarantee that a signal during migration won’t leave behind a `.keep` with the current push’s message. The use of `string_list` to manage `.keep` files (replacing a raw array) is a clean refactor that simplifies ownership tracking.

This is a **well-scoped, low-risk fix** for a subtle edge case. The commit message clearly explains the problem and solution, and the tests cover both success and failure modes. The patch is part of a larger series but stands alone as a necessary first step. Reviewers familiar with the ODB and quarantine subsystems (e.g., Patrick Steinhardt) will likely focus on the tempfile ownership logic and signal-safety guarantees.
