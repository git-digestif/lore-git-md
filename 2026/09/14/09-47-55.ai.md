This is the **documentation patch** (1/2) in Kristofer Karlsson’s two-patch series introducing an incremental connectivity check for Git. It adds a new technical document, `Documentation/technical/connectivity-check.adoc`, that explains the connectivity invariant and the existing full connectivity check in detail.

The document is thorough and well-structured, breaking down the problem into clear sections: the connectivity invariant (what it means for a repository to be "connected"), exceptions (submodules, promisor objects), the mechanics of the full check (using `rev-list` to walk the object graph), and special cases like deepening fetches and non-commit tips. It includes a small example graph to illustrate the boundary between incoming and already-connected commits, which helps clarify how the check works in practice.

This patch is purely additive and does not change any code. It serves as foundational documentation for the incremental mode introduced in the second patch, so reviewers and future contributors can understand the context and design constraints. The writing is precise and technical, suitable for Git’s developer audience. No issues or controversies are apparent; this looks like a solid, uncontroversial contribution that supports the larger performance feature.
