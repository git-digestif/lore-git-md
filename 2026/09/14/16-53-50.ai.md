This is a **bugfix follow-up** to the first patch in Peff’s three-part series addressing resource cleanup in Git’s low-level merge driver infrastructure. The patch, which replaces manual buffer management with `strbuf` for reading external merge results, introduced a **latent type-safety bug** where file sizes exceeding `LONG_MAX` could silently truncate to negative values, risking buffer overreads. Elijah Newren identified the issue and proposed a targeted fix: a `die()` check before `strbuf_detach()` to fail fast on oversized files.

Peff **accepts the fix** and plans to incorporate it in a v3 of the series. He also notes that the truncation issue exists in the current code (e.g., wrapping beyond 4GB) and suggests extending the same check to `read_mmfile()`, another function with similar behavior. However, he acknowledges that the two functions (`mmfile_t` and `mmbuffer_t`) are artificially distinct despite holding identical data, which complicates a unified solution. For now, he will add the `die()` check to both functions and defer deeper refactoring to a separate effort.

The discussion confirms the series remains **uncontroversial and well-motivated**, but the type-safety fix is necessary before merging. Peff’s plan to split the file-read cleanup from the tempfile-deletion improvements (the original focus of the series) reflects a pragmatic approach to avoid blocking the core bugfix on unrelated refactoring. The fix itself is low-risk and aligns with Git’s defensive programming practices, as endorsed by Junio in earlier feedback.

**Key technical details**:
- **File**: `merge-ll.c` (only file touched).
- **Function**: `ll_ext_merge()` (reading external merge results).
- **Bug**: Silent truncation of file sizes > `LONG_MAX` to negative values, risking buffer overreads on LLP64 platforms (e.g., Windows).
- **Fix**: `if (result_buf.len > LONG_MAX) die(_("external merge result is too large"));` before `strbuf_detach()`.
- **Related function**: `read_mmfile()` (same truncation issue, will receive identical fix).
- **APIs**: `strbuf_read_file()`, `strbuf_detach()`, `xsize_t()` (mentioned but not used here).
- **Behavior change**: No functional impact on valid inputs; oversized files now fail explicitly instead of truncating.

**Next steps**: Peff will issue a v3 with the `die()` check, likely without further discussion. The series’ broader goal—replacing custom signal handling with Git’s `tempfile` API—remains unaffected. No new test coverage is required, as the fix addresses a theoretical edge case.
