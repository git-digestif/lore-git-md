This thread is about a v3 patch series from Qin ShiCheng (qeesung) that fixes a data-loss race in `git repack -d`. The race occurs when concurrent pushes create `.keep` files after `repack` has decided which packs to delete but before `pack-objects` finishes building the replacement pack. The series replaces the racy `--honor-pack-keep` mechanism with a snapshot-based approach: at startup, `repack` writes the list of `.keep` packs to a file and passes it to `pack-objects` via the new `--keep-pack-from-file` option, ensuring both processes work from the same snapshot.

The series is now complete at v3, with five patches (the original first patch was withdrawn in favor of Justin Tobler’s ODB-focused series). Junio C Hamano has acked patch 2/5, which fixes a latent cruft-pack walk bug that would become critical once `--honor-pack-keep` is removed. The final patch (5/5) implements the snapshot-based approach, adding thorough test coverage for the race condition and edge cases. The remaining patches (1/5, 3/5, 4/5) are well-motivated and unlikely to introduce regressions, addressing traversal logic, performance, and scalability, respectively.

Key participants include Justin Tobler, who proposed an alternative architectural direction for `.keep` file handling, and Junio, who acked the critical fix in patch 2/5. The series is production-ready, merges cleanly into `next` and `seen`, and represents a clear improvement over the current racy implementation. The only trade-off is a minor increase in disk space usage for alternate ODB packs, which are now packed rather than skipped. Review from repack/ODB maintainers like Patrick Steinhardt and Taylor Blau is still pending for the remaining patches.
