This thread is a six-patch series from Qin ShiCheng (qeesung) fixing a data-loss race in `git repack -d` where concurrent pushes could cause repack to delete packs whose objects were never copied elsewhere, leaving dangling refs. The series is production-tested, well-motivated, and all tests pass, with no prior versions.

The core issue is a race between `repack` scanning `.keep` files and `pack-objects` acting on that scan—if a push adds a `.keep` after the scan but before `pack-objects` runs, the pack could be deleted despite still being needed. The series addresses this by ensuring `.keep` files are only removed by the process that created them and by replacing the `--honor-pack-keep` mechanism with a snapshot file written at startup. This snapshot is passed to `pack-objects` via the new `--keep-pack-from-file` option (introduced in patch 5/6), guaranteeing both processes agree on which packs to leave untouched.

Key changes include performance optimizations (an 11× speed-up in kept-pack matching), fixes for latent bugs in cruft-pack traversal, and new plumbing like `unregister_tempfile()` and `clear_kept_pack_cache()`. The final patch (6/6) is the capstone, eliminating the race by ensuring `repack` and `pack-objects` work from a consistent snapshot. Tests cover the race, edge cases, and backward compatibility.
