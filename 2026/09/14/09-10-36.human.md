This is a reply in the ongoing discussion about Beat Bolli’s three-patch series fixing OpenSSL compatibility and correctness issues in `git imap-send`. The series targets TLS certificate verification logic, and this specific exchange addresses the first patch, which introduces a compatibility macro for OpenSSL 4.1’s renamed `ASN1_STRING_get_length()` function.

Beat responds to Patrick Steinhardt’s question about why the switch from `ASN1_STRING_length()` is necessary. He points to OpenSSL’s own documentation, which explicitly lists `ASN1_STRING_length()` as deprecated since OpenSSL 4.1 and states it can be hidden entirely by defining `OPENSSL_API_COMPAT`. Beat also notes that Git’s build fails under `DEVELOPER=1` because the deprecation warning is treated as an error, and Git currently lacks any OpenSSL compatibility macros. His response is factual and directly addresses Patrick’s concern: the change is not premature but required to avoid build failures with modern OpenSSL versions.

The exchange does not resolve the broader architectural question Patrick raised—whether Git should continue implementing certificate verification manually instead of using OpenSSL’s built-in hostname verification—but it clarifies the immediate motivation for the compatibility macro. The thread’s other unresolved issues (the memory-safety bug in patch 2, incomplete RFC 6125 compliance in patch 3, and the choice between allocation-based and length-bounded string handling) remain open. This reply suggests the first patch is well-justified and likely to proceed, but the series as a whole still faces significant technical hurdles before it can be merged.
