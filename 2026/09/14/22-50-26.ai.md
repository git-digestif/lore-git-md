This is the v8 iteration of Andrew Pleeter’s patch series extending `git var` to support broken-down identity components, commit signing keys, multiple variable arguments, and NUL-terminated output. The patch is part of the ongoing effort to provide a unified, scriptable interface for Git’s identity and signing configuration, replacing the earlier `git ident` proposal.

The v8 patch addresses all remaining feedback from Junio’s and Phillip Wood’s v7 reviews, resolving the two key documentation-implementation discrepancies that were blocking integration. Specifically:

- **Output format**: Multi-variable queries now print `VARIABLE=value` pairs (or `VARIABLE\nvalue\0` with `-z`), eliminating the ambiguity Junio highlighted in v7. Multi-valued variables are formatted as repeated `VARIABLE=value` entries, removing the need for extra trailing delimiters and ensuring scripts can parse the output without prior knowledge of which variables are multi-valued.
- **Exit code behavior**: The documentation now accurately reflects the implementation: multi-variable queries exit with code 1 if *any* requested variable is unset, while single-variable queries exit with code 1 only if that specific variable is unset. This aligns with Phillip Wood’s recommendation and resolves the discrepancy Junio noted in v7.

The patch touches `builtin/var.c`, `Documentation/git-var.adoc`, and `t/t0007-git-var.sh`, introducing new variables (`GIT_AUTHOR_NAME`, `GIT_AUTHOR_EMAIL`, `GIT_AUTHOR_DATE`, `GIT_COMMITTER_NAME`, `GIT_COMMITTER_EMAIL`, `GIT_COMMITTER_DATE`, and `GIT_SIGNING_KEY`) and supporting multiple variable arguments with strict argument ordering (options before variables). The `-z` option provides NUL-terminated output, matching `git config -z`’s behavior. The implementation uses `parse_options()` with `PARSE_OPT_STOP_AT_NON_OPTION` to enforce argument ordering and includes comprehensive test coverage for edge cases like unset variables, multi-valued variables, and `-z` mode.

Key technical details:
- **Files**: `builtin/var.c`, `Documentation/git-var.adoc`, `t/t0007-git-var.sh`.
- **New variables**: Identity components (name/email/date for author and committer) and `GIT_SIGNING_KEY` (resolves the key that would be used for a commit, regardless of `commit.gpgsign`).
- **Behavior**: Multi-variable queries print `VARIABLE=value` pairs (or `VARIABLE\nvalue\0` with `-z`), omitting unset variables and exiting with code 1 if any are unset. Single-variable queries retain backward compatibility by printing bare values.
- **Error handling**: Unset variables in multi-variable queries are omitted, and the command exits with code 1 if any requested variable is unset. Multi-valued variables are handled via `string_list`-based callbacks.
- **Argument parsing**: Strict ordering (options before variables) enforced via `parse_options()`.
- **Output format**: `-z` mode matches `git config -z` (`key\nvalue\0`), with multi-valued variables formatted as repeated entries.
- **Test coverage**: Tests cover `-z` output, multi-valued variables, argument ordering, unset variables, and signing key resolution.
