This is the final procedural note in the three-patch bugfix series that converts Git’s low-level merge driver infrastructure to use the `tempfile` API for signal-safe cleanup of temporary files. The series, authored by Michal Koutný and submitted as v2 by Jeff King (Peff), addresses a long-standing issue where `.merge_file_*` temporary files were left behind if the merge process was interrupted by SIGINT or SIGQUIT. The solution replaces custom signal handling with Git’s established `tempfile` subsystem, modernizes adjacent code (e.g., replacing manual buffer management with `strbuf`), and fixes latent robustness issues such as ignoring `close()` errors after successful `write()` calls.

This specific email is a brief exchange between Michal and Peff about commit-message attribution for the third patch, which introduced the `tempfile` API and a backward-compatibility helper (`temp_path_basename()`). Elijah Newren had suggested a custom phrasing to credit Michal, but Michal prefers a simple `Reported-by:` trailer. Peff agrees to use the trailer in the upcoming v3, which will also include a type-safety fix for a latent bug in the first patch (a `die()` check for file sizes exceeding `LONG_MAX`). The series is otherwise complete, uncontroversial, and ready for merging once v3 is submitted. No substantive changes are needed to the third patch, and Elijah’s approval ("Looks good to me") stands. The series has been lightly tested for interrupt scenarios but lacks automated test coverage, which Peff and Michal agree is acceptable.
