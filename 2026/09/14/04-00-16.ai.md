This is the v4 submission of a two-patch bugfix series targeting the `--force-if-includes` safety mechanism in `git push`. The core issue is that the feature incorrectly checks the reflog of the *local* branch whose name matches the *remote* destination branch (e.g., `refs/heads/main`) rather than the branch actually being pushed (e.g., `refs/heads/src` in `src:main`). This flaw can cause false rejections (e.g., when pushing from a differently named local branch or detached HEAD) or unintended data loss (e.g., pushing an unrelated branch that happens to share a name with a local branch containing the remote tip). The series also fixes misleading advice messages for detached HEAD and other non-branch pushes, replacing generic "pull" suggestions with actionable guidance.

Patch 1/2 (`push: check pushed ref for --force-if-includes`) fixes the core logic in `remote.c` to consult the reflog of the pushed ref (`ref->peer_ref->name`) instead of the destination ref (`ref->name`). It adds special handling for `HEAD`-based pushes (resolving symrefs with `RESOLVE_REF_READING` and rejecting non-branch revisions) and detached HEAD states (rejecting by default via the new `ref->unverifiable` flag). Deletions are explicitly allowed via `is_null_oid(&remote->peer_ref->new_oid)`. The patch includes 65 lines of new test coverage in `t/t5533-push-cas.sh`, covering mismatched local/remote names, `HEAD`-based pushes, detached HEAD scenarios, and non-branch revisions (e.g., tags, object IDs). Key changes since v3 include unconditionally resolving `peer_ref` with `RESOLVE_REF_READING` (rejecting all non-branch pushes), adding a test for tag pushes, clarifying the commit message, and refactoring `apply_push_cas` to narrow `check_if_includes_upstream`'s scope.

Patch 2/2 (`push: fix --force-if-includes non-branch advice`) adjusts the advice message for pushes lacking a reflog to consult (e.g., detached HEAD, tags, object IDs). It introduces a new `advice.forceIfIncludesDetachedHead` config knob (documented as `advice.pushRefUnverifiable`) and updates the advice message to instruct users to specify the expected remote tip with `--force-with-lease=<ref>:<expect>` or bypass the check with `--no-force-if-includes`. The patch updates all transport layers (direct pushes, transport helpers, send-pack) for consistency and expands test coverage to verify the new advice message. Changes since v3 include renaming the patch from "detached HEAD" to "non-branch" to reflect broader applicability, rewording the advice message for clarity, and fixing a line-length violation in `builtin/push.c`.

The series is technically complete and ready for merge, addressing all substantive feedback from v3. Junio C Hamano's feedback was surface-level (documentation wording, line-length nits), while Patrick Steinhardt's technical concerns (symbolic reference resolution, non-branch rejection, deletion rationale) are fully resolved in v4. The series is based on `maint` and includes clear test coverage for all edge cases, including deletions, `NULL` `peer_ref` paths, and non-branch revisions. Files touched include `remote.c` (core logic), `advice.c` (new advice message), and `t/t5533-push-cas.sh` (tests). The implementation is self-contained and avoids behavior changes for existing `--force-with-lease` cases.
