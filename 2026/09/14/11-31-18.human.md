This is the first patch in a **bugfix series** addressing a data-loss race in `git repack -d` when concurrent pushes occur. The patch prevents `receive-pack` from removing `.keep` files it didn’t create, which could otherwise delete packs still needed by other pushes.

The fix changes how `.keep` files are tracked during quarantine migration. Previously, `receive-pack` registered the final `.keep` path as a tempfile *before* migration, risking deletion of foreign `.keep` files (e.g., from identical pushes). Now, it registers tempfiles *after* migration and verifies their contents: only files containing the expected message (with the current process’s PID and hostname) are removed. This ensures foreign `.keep` files—even those linked to duplicate packs—are preserved.

The patch touches `object-file.c` (core ODB logic), `tempfile.c` (adding `unregister_tempfile()`), and adds two new tests in `t5547-push-quarantine.sh`. The tests validate that rejected pushes don’t remove foreign `.keep` files and that failed migrations clean up their own `.keep` files. The changes are **well-motivated and production-tested**, with clear commit messages and no behavior regressions.

This is a **subtle but critical fix** for a race that could corrupt repositories under concurrent load. The design avoids introducing new timing windows, and the tests cover edge cases like partial migrations.
