This is a bug report about `git status --ignored` with a pathspec. The issue is that when a pathspec is provided (e.g., `ba`), the command incorrectly matches ignored directories whose names *contain* the pathspec as a substring (e.g., `bar/baz/` and `bar/quux/` are matched when searching for `ba`). The expected behavior is that the pathspec should only match exact directory or file names, not partial substrings.

The report includes a minimal reproduction case: create a directory `bar`, add `bar/` to `.gitignore`, initialize two Git repositories inside `bar/` (`baz` and `quux`), then run `git status --porcelain --ignored --untracked-files -- ba`. The command incorrectly reports `bar/baz/` and `bar/quux/` as ignored, even though `ba` does not exactly match `bar`.

The bug was originally reported in an Emacs issue (bug#81625) by Lester Longley, and Sean Whitton is forwarding it to the Git mailing list. No patch or proposed fix is included in the email—this is purely a bug report. The reproduction steps are clear and should be easy for a maintainer to verify. The issue appears to be a regression or edge case in pathspec matching logic for ignored files.
