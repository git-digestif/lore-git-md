This is the second patch in a two-part **performance feature** introducing an opt-in incremental connectivity check for Git fetches and pushes. The patch wires up the core algorithm (added in `tree-verify.c`) to the existing `check_connected()` machinery, enabling the new mode when `transfer.connectivityCheck=incremental` is configured.

The incremental check processes incoming commits in topological order, comparing each commit’s tree against its parents’ trees to skip unchanged subtrees. This shifts the cost from being proportional to repository size to being proportional to the size of the incoming changes. The patch adds the internal `--verify-trees-incremental` flag to `git rev-list`, which is invoked automatically by `check_connected()` when the incremental mode is enabled. Deepening fetches and very long incoming histories (10,000+ commits) fall back to the full check, preserving correctness.

Test coverage is exhaustive: the new `t5412-connectivity-check.sh` script (655 lines) verifies semantic equivalence with the full check, corruption detection, partial clone handling, and integration with real fetch/push/clone operations. Performance benchmarks in `t/perf/p5412-connectivity-check.sh` show dramatic speedups for small pushes to large repositories (up to 190x faster) and memory reductions (14 MB vs. 3.4 GB in the same case), with a modest regression (1.5x slower) for very long incoming histories. The implementation is conservative, opt-in, and self-contained, touching only `builtin/rev-list.c`, `connected.c`, and the new `tree-verify.c`.

The patch is well-motivated, with clear benchmarks and thorough documentation in `Documentation/technical/connectivity-check.adoc`. The author has addressed prior feedback by moving the verifier into the `rev-list` subprocess, which simplified error handling and avoided issues with lazy fetches in partial clones. The series is under active review and looks like a strong candidate for merging, assuming no major objections surface.
