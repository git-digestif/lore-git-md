This is the second patch in a two-patch **performance feature** series introducing an incremental connectivity check for Git fetches and pushes. The patch wires up the new `transfer.connectivityCheck=incremental` configuration (added in patch 1/2) to the actual implementation, which lives in the new `tree-verify.c` file.

The core logic is a new internal `rev-list` mode (`--verify-trees-incremental`) that processes incoming commits in topological order, verifying each commit's tree against its parents' trees rather than walking the entire object closure of boundary commits. The implementation is careful to preserve existing semantics: it handles partial clones (skipping promisor objects), respects shallow boundaries, falls back to the full check for deepening fetches, and detects corruption (missing objects, malformed trees, type mismatches). The patch adds extensive test coverage (655 lines in `t5412-connectivity-check.sh`) that verifies semantic equivalence with the full check, corruption detection, and integration with real fetch/push/clone operations.

Key technical details include the new `tree-verify.c` file (306 lines), which implements the incremental verifier; updates to `builtin/rev-list.c` and `connected.c` to wire up the new mode; and trace2 instrumentation to measure trees loaded and blobs checked. The patch also adds a performance test script (`t/perf/p5412-connectivity-check.sh`) that benchmarks the incremental mode against the full check across three axes: repository size, incoming commit count, and files changed per commit. Benchmark results show dramatic speedups for small pushes to large repositories (up to 190x faster) and significant memory savings (14 MB vs. 3.4 GB in the largest case), with a modest regression (1.5x slower) for very long incoming histories (10,000+ commits).

The implementation is opt-in (default remains `full`), conservative (falls back to full check for edge cases), and well-documented (including a new technical document in `Documentation/technical/connectivity-check.adoc`). The patch is part of an ongoing effort to reduce the cost of connectivity checks in large repositories, and the author notes that future work could optimize the commit boundary-finding step. The series has no open design objections or change requests at this time.
