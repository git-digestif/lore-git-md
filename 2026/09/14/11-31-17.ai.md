This is a **bugfix series** targeting the `git repack` machinery, specifically a race condition where concurrent pushes can cause `git repack -d` to delete packs whose objects were never copied elsewhere, leading to data loss. The issue was observed in production on Git 2.43 and reproduces on `master`.

The root cause is a timing window between when `repack` scans for `.keep` files (to decide which packs to delete) and when `pack-objects` (spawned with `--honor-pack-keep`) does its own scan. If a concurrent push finishes migrating its quarantine during this window—dropping a duplicate pack but linking its `.keep` onto an older pack—`pack-objects` will skip the pack’s objects, but `repack` will still delete it based on its stale snapshot. The result is a dangling ref pointing to a nonexistent commit.

The series fixes two distinct problems:
1. **Patch 1/6** prevents `receive-pack` from removing `.keep` files it didn’t create (e.g., ones linked onto foreign packs or left behind after a rejected push).
2. **Patch 6/6** eliminates the race by passing `pack-objects` the exact list of `.keep` packs that `repack` observed at startup, rather than letting it rescan.

Patches 2–5 lay groundwork for patch 6:
- **2/6** makes `--stdin-packs=follow` treat `--keep-pack` packs as traversal blockers (like `^` packs), aligning behavior with on-disk `.keep` packs.
- **3/6** fixes a pre-existing bug where the cruft walk uses a stale kept-pack cache, masked by `--honor-pack-keep`.
- **4/6** optimizes `--keep-pack` name lookups by sorting the list.
- **5/6** adds `--keep-pack-from-file` to handle repositories with too many kept packs for command-line limits (e.g., 32K characters on Windows).

The series includes thorough tests: each fix is validated by a test that fails without it, and the race itself is reproduced in `t7703-repack-geometric.sh`. All tests pass, and the series merges cleanly into `next` and `seen`. Key files touched include `builtin/pack-objects.c`, `builtin/repack.c`, and `object-file.c`, with new plumbing in `packfile.h` and `tempfile.h`.

This is a **well-motivated, production-tested fix** for a subtle but serious data-loss bug. The commit messages are clear, the tests are comprehensive, and the design avoids introducing new races. The series is likely to attract attention from maintainers of the repack and ODB subsystems (e.g., Patrick Steinhardt, Taylor Blau).
