This is a **substantive review** from Junio C Hamano on the second patch of Kristofer Karlsson’s incremental connectivity check series. The review raises two technical concerns about edge-case handling in the new `tree-verify.c` implementation.

First, Junio questions whether the `is_promisor_object()` check in `verify_blob()` happens too late: the function already calls `odb_read_object_info()` before checking for promisor objects, which could trigger a lazy fetch from a promisor remote. This might undermine the intended behavior of skipping promisor objects entirely during connectivity checks.

Second, Junio points out potential NULL-dereference risks in `verify_commit_tree()`: if `parse_commit_or_die()` succeeds but the commit’s tree is missing or corrupt, `get_commit_tree_oid()` could return NULL, leading to undefined behavior when passed to `tree_map_add()`. The same issue exists for the incoming commit’s tree outside the parent loop. The review does not suggest fixes but flags these as robustness gaps that need addressing before the patch can be considered merge-ready.

The feedback is narrowly focused on correctness in corner cases rather than the overall design, which Junio previously described as "exciting" in his initial reaction to the series. No other aspects of the patch (performance, documentation, or test coverage) are questioned here. The author will likely need to address these points in a v2 before the series moves forward.
