This is a **performance feature** that introduces an opt-in incremental connectivity check for fetches and pushes, part of a two-patch series. The author, Kristofer Karlsson, responds to Junio C Hamano’s substantive review of the implementation’s edge-case handling.

Kristofer confirms that the promisor object check in `verify_blob()` is currently safe because `rev-list --exclude-promisor-objects` globally disables lazy fetching by setting `repo->fetch_if_missing = 0`. He demonstrates this with a targeted test that fails when lazy fetching is artificially re-enabled, though he acknowledges the test only covers trees, not blobs, and plans to add a matching blob test. He also proposes a belt-and-suspenders improvement: rewriting the code to use `odb_read_object_info_extended()` with explicit flags instead of relying on `odb_read_object_info()`.

On the NULL-dereference risk, Kristofer concedes the oversight and will add explicit NULL checks after `get_commit_tree_oid()` calls, exiting with a clear error message if the commit’s tree is missing or corrupted. These changes address both of Junio’s technical concerns without altering the feature’s core design or performance claims.

The series remains under active review, with no merge status yet. The incremental check is well-motivated (scaling cost with incoming change size rather than repository size) and thoroughly tested, but these edge-case fixes will likely be incorporated into a v2 before further discussion. If you care about large-repository performance or connectivity-check internals, this is worth tracking.
