This is the **documentation patch** in Kristofer Karlsson’s two-part series introducing an incremental connectivity check for Git fetches and pushes. It adds a new technical document (`Documentation/technical/connectivity-check.adoc`) that explains the connectivity invariant and how the existing full connectivity check works.

The document is thorough and well-structured, breaking down the problem into clear sections: the connectivity invariant (what it means for a repository to be "connected"), exceptions (submodules, promisor objects), the mechanics of the full check (using `rev-list` to walk the object graph), and edge cases like deepening fetches and non-commit tips. It includes a helpful ASCII-art commit graph to illustrate the boundary between trusted and incoming objects, making the algorithm easier to visualize. The writing is precise and assumes familiarity with Git internals, so it’s aimed at contributors rather than end users.

This patch is purely additive and doesn’t touch code, so it’s uncontroversial in itself. Its value lies in providing context for the second patch (the actual implementation), which introduces the incremental mode. If the series lands, this document will be a key reference for anyone working on connectivity checks in the future. The only thing missing is a forward reference to the incremental mode, but that’s likely intentional—this document describes the *current* state, while the incremental mode is an opt-in optimization added in the next patch.
