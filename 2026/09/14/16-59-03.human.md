This is a brief follow-up in the ongoing bugfix series for merge-driver temporary file cleanup. Jeff King (Peff) and Michal Koutný clarify a minor design point about whether Git should preserve temporary merge files when the merge process fails after the external tool completes. Peff raises the theoretical concern that a user might lose a complex merge result if Git deletes the file on read errors, but both agree this scenario is rare and not worth complicating the cleanup logic. The discussion reinforces the series' existing design: temporary files are deleted on any failure, including read errors, to avoid clutter. No technical changes or objections arise; the series remains on track for a v3 addressing the type-safety fix identified earlier, with no new test coverage planned. The exchange is purely about user experience trade-offs, not code correctness.
