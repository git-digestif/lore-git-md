This is a bug report about `git status --ignored` with a pathspec. The issue is that when you run `git status --ignored -- ba`, Git incorrectly matches ignored directories whose names *start with* "ba" (like "bar/baz" and "bar/quux") rather than requiring an exact match. The expected behavior is that the pathspec "ba" should not match "bar" at all, so no ignored directories should be listed.

The report includes a clear reproduction recipe: create a repository, add a `.gitignore` entry for "bar/", initialize two Git subdirectories inside "bar/", then run `git status --ignored -- ba`. The actual output shows the two subdirectories, while the expected output is nothing. The bug was originally reported in an Emacs issue tracker, and Sean is forwarding it to the Git list with credit to Lester Longley.

This looks like a genuine edge case in pathspec matching for ignored files. The report is concise, includes all necessary details, and provides a minimal reproduction case, making it easy for a developer to investigate. No patch is attached—this is just a bug report, not a fix. If you work on pathspec handling or the status command, this might be worth looking into.
