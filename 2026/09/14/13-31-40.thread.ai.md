Thread identity: Bug report about `git status --ignored` with pathspec substring matching; originating author Sean Whitton (forwarding Lester Longley's Emacs issue #81625). Series version: single patch (v2, incorporating Junio C Hamano's squash-in fix).

Core problem or goal: `git status --ignored` with a pathspec (e.g., `ba`) incorrectly matches ignored directories whose names *contain* the pathspec as a substring (e.g., `bar/baz/` and `bar/quux/`), rather than requiring an exact name match. The regression was introduced in commit `95c11ecc73` ("Fix error-prone fill_directory() API; make it only return matches", 2020-04-01), which removed pathspec matching for excluded directories as an optimization.

Current status: Bugfix patch (v2) posted by René Scharfe, incorporating Junio C Hamano’s squash-in fix for a NULL-dereference crash in the new `dir_match()` helper. The patch removes the optimization in `dir.c` that skipped pathspec matching for excluded directories, restoring exact-match behavior. It includes two test cases in `t/t7061-wtstatus-ignore.sh` (original regression test) and `t/t2021-checkout-overwrite.sh` (NULL safety test). The patch is technically complete, addresses all review feedback, and is ready for maintainer integration; no integration status yet.

Key technical details:
- **Subsystem**: `git status` (specifically `dir.c` and the `treat_directory()` function).
- **CLI options**: `--ignored`, `--untracked-files`, `--porcelain`.
- **Root cause**: Optimization in `95c11ecc73` that skipped pathspec matching for excluded directories, causing substring matching instead of exact matching.
- **Files touched**: `dir.c` (no new symbols or on-disk format changes; the squash-in adds a defensive NULL check in `dir_match()`).
- **Test coverage**: Two test cases:
  1. `t/t7061-wtstatus-ignore.sh`: Verifies `git status --porcelain --ignored -u` omits excluded directories with nested repositories when the pathspec is a prefix match.
  2. `t/t2021-checkout-overwrite.sh`: Verifies `git checkout` does not segfault when an untracked nested repository exists and `pathspec` is NULL.
- **Behavior change**: Restores exact-match pathspec behavior for ignored directories, eliminating unintended substring matching. The squash-in adds a defensive NULL check without altering the core fix.

Open questions and loose ends: None. The v2 patch resolves the NULL-dereference safety concern and includes all requested test coverage. René has left open the possibility of revisiting the removed optimization in a future follow-up, but this is not a blocker for the current fix.
