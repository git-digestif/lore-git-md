Thread identity: Bug report about `git status --ignored` with pathspec substring matching; originating author Sean Whitton (forwarding Lester Longley's Emacs issue #81625). Series version: single patch (v1, with proposed squash-in fix).

Core problem or goal: `git status --ignored` with a pathspec (e.g., `ba`) incorrectly matches ignored directories whose names *contain* the pathspec as a substring (e.g., `bar/baz/` and `bar/quux/`), rather than requiring an exact name match. The regression was introduced in commit `95c11ecc73` ("Fix error-prone fill_directory() API; make it only return matches", 2020-04-01), which removed pathspec matching for excluded directories as an optimization.

Current status: Bugfix patch (v1) posted by René Scharfe, with a proposed squash-in fix from Junio C Hamano addressing a NULL-dereference crash in the new `dir_match()` helper when `pathspec` is NULL. The patch removes the optimization in `dir.c` that skipped pathspec matching for excluded directories, restoring the expected exact-match behavior. It includes a new test case in `t/t7061-wtstatus-ignore.sh` to prevent regression, and Junio’s squash-in adds a second test case to verify the NULL pathspec safety fix. No maintainer integration status yet; the patch is under review with a pending safety fix.

Key technical details:
- **Subsystem**: `git status` (specifically `dir.c` and the `treat_directory()` function).
- **CLI options**: `--ignored`, `--untracked-files`, `--porcelain`.
- **Root cause**: Optimization in `95c11ecc73` that skipped pathspec matching for excluded directories, causing substring matching instead of exact matching.
- **Files touched**: `dir.c` (no new symbols or on-disk format changes; the squash-in adds a NULL check in `dir_match()`).
- **Test coverage**: Two test cases in `t/t7061-wtstatus-ignore.sh`:
  1. Original regression test verifying `git status --porcelain --ignored -u` omits excluded directories with nested repositories when the pathspec is a prefix match.
  2. New test case from Junio verifying that `git checkout` does not segfault when an untracked nested repository exists and `pathspec` is NULL.
- **Behavior change**: Restores exact-match pathspec behavior for ignored directories, eliminating unintended substring matching. The squash-in adds a defensive NULL check without altering the core fix.
