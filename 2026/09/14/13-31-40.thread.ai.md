Thread identity: Bug report about `git status --ignored` with pathspec substring matching; originating author Sean Whitton (forwarding Lester Longley's Emacs issue #81625). Series version: single patch (v1).

Core problem or goal: `git status --ignored` with a pathspec (e.g., `ba`) incorrectly matches ignored directories whose names *contain* the pathspec as a substring (e.g., `bar/baz/` and `bar/quux/`), rather than requiring an exact name match. The regression was introduced in commit `95c11ecc73` ("Fix error-prone fill_directory() API; make it only return matches", 2020-04-01), which removed pathspec matching for excluded directories as an optimization.

Current status: Bugfix patch (v1) posted by René Scharfe. The patch removes the optimization in `dir.c` that skipped pathspec matching for excluded directories, restoring the expected exact-match behavior. It includes a new test case in `t/t7061-wtstatus-ignore.sh` to prevent regression. René notes the optimization might be repairable in a future iteration, but the current patch prioritizes correctness. No maintainer response or integration status yet; the patch is under review.

Key technical details:
- **Subsystem**: `git status` (specifically `dir.c` and the `treat_directory()` function).
- **CLI options**: `--ignored`, `--untracked-files`, `--porcelain`.
- **Root cause**: Optimization in `95c11ecc73` that skipped pathspec matching for excluded directories, causing substring matching instead of exact matching.
- **Files touched**: `dir.c` (no new symbols or on-disk format changes).
- **Test coverage**: New test case in `t/t7061-wtstatus-ignore.sh` verifies that `git status --porcelain --ignored -u` omits excluded directories with nested repositories when the pathspec is a prefix match. The reproduction case from the original report remains valid.
- **Behavior change**: Restores exact-match pathspec behavior for ignored directories, eliminating unintended substring matching.
