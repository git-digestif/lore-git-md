This is the first patch in a two-patch bugfix series that is now queued for merging. It fixes a heap-buffer-overflow and a false-positive bug in Git’s pathspec handling during directory traversal.

The issue occurs when an exclude pathspec (e.g., `:(exclude)x/b`) is matched against a pathname (e.g., `a/b/m`) after stripping the common prefix derived from positive pathspecs (e.g., `a/` from `a/b` and `a/c`). The current code incorrectly applies the prefix to exclude pathspecs, which can lead to two problems: (1) if the exclude pathspec is shorter than the prefix, `match_pathspec_item()` advances beyond its allocation, causing an out-of-bounds read (reproducible with AddressSanitizer), and (2) if the exclude pathspec happens to match the stripped pathname, Git incorrectly excludes the file (e.g., `git ls-files a/b ':!x/b' a/c` wrongly excludes `a/b/m`).

The fix is simple: when matching exclude pathspecs, pass a zero prefix to `do_match_pathspec()` instead of the common prefix derived from positive pathspecs. The patch also adds two regression tests in `t/t6132-pathspec-exclude.sh`: one for the false-positive bug and one for the out-of-bounds access when the exclude pathspec is shorter than the prefix.

This is a well-scoped, memory-safety fix with clear test coverage. The commit message is thorough and explains both the bug and the fix in detail.
