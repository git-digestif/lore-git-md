This is the second patch in the v4 iteration of a two-patch bugfix series targeting Git’s pathspec handling in directory traversal. The patch restores an optimization that avoids scanning unrelated directories when all non-exclude pathspecs share a common prefix, even when an exclude pathspec appears first in the list.

The core change refactors `common_prefix_len()` to use the first *non-exclude* pathspec as the comparison base (instead of the first pathspec unconditionally), returning both the prefix length and the matched string via an output parameter. This ensures the directory-walk optimization works correctly while preserving the existing behavior that exclude pathspecs are matched against full paths. The patch also updates `common_prefix()` and `fill_directory()` to use the new output parameter, and adds a unit test in `t/unit-tests/u-dir.c` covering the edge case of an exclude pathspec followed by two non-exclude pathspecs sharing a directory.

The change is minimal and narrowly scoped to the pathspec subsystem, with no observable behavior change for end users beyond fixing the optimization. The series is queued for merging, and this patch completes the fix by addressing the logical bug in `common_prefix_len()` that the first patch (which prevented exclude pathspecs from being truncated to the common prefix) exposed. Key technical details: the output parameter in `common_prefix_len()` uses `const char **`, and the unit test verifies the correct prefix (`"foo/"`) is returned for pathspecs `':!unrelated/path' 'foo/bar' 'foo/baz'`.
