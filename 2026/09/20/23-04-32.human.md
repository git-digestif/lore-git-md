This is a bugfix patch for `git diff --no-index -R` that corrects how file/directory conflicts are handled when the `-R` (reverse diff) flag is used. The issue was that when comparing a file on one side with a directory on the other, the file was processed separately before the directory recursion, bypassing the normal reverse-diff logic. This caused incorrect output where paths were reported as deleted or added instead of being properly reversed.

The patch itself is minimal—just two lines in `diff-no-index.c`—and includes thorough regression tests in `t/t4053-diff-no-index.sh` covering both directions of the conflict (file→directory and directory→file). The fix swaps the filespecs of the early queue entry when `reverse_diff` is set, ensuring consistent behavior with the `-R` flag. René Scharfe and Jacob Keller have both reviewed and endorsed the patch, signaling it’s ready for integration.

This is a well-scoped fix for a clear edge case, with proper test coverage and a focused implementation. The issue would likely affect users comparing directory structures with mixed file/directory conflicts when using the reverse diff flag, so the fix addresses a real, if niche, problem. No open questions or loose ends remain, and the patch appears uncontroversial.
