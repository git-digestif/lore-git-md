This is a **surface-level review** of Harald Nordgren’s patch that adds advice for shallow history in `<ref>~N` and `<ref>^N` lookups. D. Ben Knoble’s reply flags a minor but important inconsistency in the patch’s messaging and documentation.

The review points out that the commit message and advice documentation use the terms “ref” and “commit-ish” interchangeably, which could confuse users. The commit message says the feature works when `<ref>` looks like `<remote>/<branch>`, implying it only triggers for refs, but the advice itself is documented as applying to `~N` and `^N` syntax, which works with any commit-ish (e.g., commit hashes, tags, or even reflog entries). The documentation also shows bare `~N`/`^N` syntax, which isn’t valid Git syntax—it should use `<rev>~<n>` and `<rev>^[<n>]` to match `gitrevisions(7)`.

The review doesn’t question the technical implementation or the advice’s usefulness, but it does highlight a potential source of user confusion. The patch’s core logic—detecting shallow boundaries and suggesting context-aware `git fetch --deepen` commands—remains uncontested. This is a nit-level observation about wording and documentation clarity, not a substantive critique of the patch’s design or correctness.
