This is a user-facing usability improvement for shallow clones. The patch adds a helpful error message when a user tries to reference an ancestor commit (e.g., `origin/main~3`) that doesn’t exist locally because the repository’s history was truncated at a shallow boundary. Instead of the current cryptic "is not a commit" error, Git now explains that the repository is shallow and suggests the exact `git fetch --deepen=...` command needed to fetch the missing history.

The implementation is careful: the hint only appears when the walk actually stops at a recorded shallow boundary, not just because the repository happens to be shallow elsewhere, so it won’t misfire on short but complete histories. It also accounts for the depth already present, so the suggested `--deepen` value is the minimal number of commits needed rather than a fixed guess. For merge parents (`^N`), it always suggests `--deepen=1` because a shallow boundary commit has no parents recorded locally, so fetching one generation retrieves the full parent list regardless of which parent index was requested.

The patch touches `object-name.c` to thread the advice through the revision-parsing machinery, adds a new `advice.shallowHistory` config knob, and includes thorough tests in `t1500-rev-parse.sh` that cover both `~N` and `^N` syntax, merge parents, partial deepening, and the ability to disable the advice. The commit message is clear and the code looks clean; this feels like a well-considered contribution that directly addresses a real pain point for users of shallow clones.
