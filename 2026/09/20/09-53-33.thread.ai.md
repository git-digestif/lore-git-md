Subject: [PATCH] rev-parse: add advice for shallow history in <rev>~N and <rev>^N
Series version: v3 (under review; scope narrowed to failing syntax only)
Originating author: Harald Nordgren
Thread type: bugfix / user-experience improvement

Core problem or goal
When a user in a shallow clone attempts to access an ancestor not present locally via explicit `<rev>~N`/`<rev>^N` syntax, Git emits a generic "is not a commit" error with no indication that the operation was limited by the shallow boundary. The patch adds a new advice (`advice.shallowHistory`) that explains the shallow boundary, why the operation failed, and suggests the exact `git fetch --deepen=<n>` command needed to resolve it. The v3 patch focuses solely on the failing-syntax case, addressing all prior review feedback.

Key technical details
- Files touched: `advice.c`, `advice.h`, `object-name.c`, `shallow.c`, `shallow.h`, `Documentation/config/advice.adoc`, plus new tests in `t/t1500-rev-parse.sh`.
- New enum value: `ADVICE_SHALLOW_HISTORY`.
- New CLI behavior: advice appears when a user explicitly uses `<rev>~N` or `<rev>^N` syntax in a command that fails to resolve (e.g., `git show HEAD~20`). The suggested `--deepen` value is context-aware:
  - `<rev>~N` → `--deepen=<N - current_depth>`
  - `<rev>^N` → `--deepen=1` (because a shallow boundary commit has no parents recorded locally).
- Remote and branch are auto-detected via `remote_find_tracking` instead of assuming `refs/remotes/<remote>/<branch>`.
- Advice is suppressed during internal re-resolution via `GET_OID_QUIETLY` and in non-shallow repos.
- Paging awareness: the advice waits for the pager to close so it isn’t wiped from the terminal.
- Bug fixed in v3: chained carets (e.g., `<rev>^^^`) no longer print the advice twice; the quiet flag is now threaded through the inner lookup in `get_parent()`.
- Test coverage: 8 new test cases verify the advice appears (or doesn’t) in all expected scenarios, including merge parents, partial depths, disabled advice, and non-shallow repos.

Open questions and loose ends
- **Scope of advice for `<rev>^N`**: The `--deepen=1` suggestion for merge parents may be less meaningful (all parents share the same depth). Junio’s v1 feedback questioned whether this case should be included; no explicit resolution yet, but the v3 patch retains it.
- **Implementation robustness for `<rev>~N`/`<rev>^N`**: Junio’s v1 review of the test case (`shallowHistory advice accounts for depth already present`) asked whether the advice would behave the same for `origin/main^^^^^` as it does for `origin/main~5`. This edge case remains unaddressed in the v3 commit message or tests.
- **Review bandwidth**: Junio’s latest email explicitly states the patch will be dropped from his integration branches unless a reviewer steps forward in the next few weeks. The latest process discussion (Harald’s reply to Kristoffer Haugsbakk and Patrick Steinhardt’s follow-up) does not resolve the bottleneck.
