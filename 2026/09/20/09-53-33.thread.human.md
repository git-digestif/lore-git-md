This thread is about a proposed improvement to Git’s error messages in shallow clones. When users try to access ancestors not present locally using `<rev>~N` or `<rev>^N` syntax, Git currently gives a generic "is not a commit" error. Harald Nordgren’s patch (now at v3) adds a new advice message that explains the shallow boundary, why the operation failed, and suggests the exact `git fetch --deepen=<n>` command needed to resolve it. The patch is technically ready—it addresses all prior feedback, includes thorough test coverage, and has no substantive objections—but it remains stalled due to a lack of reviewers.

Junio Hamano, the maintainer, has warned that unless a reviewer steps forward in the next few weeks, he will drop the patch from his integration branches. The thread has since shifted to a broader discussion about the review bottleneck. Harald proposed automating mechanical checks (like test-before-logic ordering in patch series) to free reviewers to focus on conceptual direction, but both Patrick Steinhardt and Kristoffer Haugsbakk rejected the idea, arguing that human review is irreplaceable for enforcing Git’s standards. The patch’s fate is still unresolved, and the discussion has not moved the needle on the core issue: the structural imbalance between contributor volume and reviewer bandwidth. For now, the patch remains in limbo, with no clear path forward.
