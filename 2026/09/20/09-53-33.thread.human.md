This thread is about a proposed improvement to Git’s error messages when users in shallow clones try to access ancestors that aren’t present locally. Harald Nordgren’s patch (now at v3) adds an advice message that explains the shallow boundary and suggests the exact `git fetch --deepen=<n>` command needed to resolve the issue. The patch is technically sound, addresses all prior feedback, and is ready for integration—but it’s stalled because no reviewer has stepped forward to formally approve it. Junio has warned that unless someone reviews it soon, he’ll drop it from his integration branches.

The core change is straightforward: when a user runs a command like `git show HEAD~20` in a shallow clone and the ancestor isn’t available, Git now prints a clear explanation and a context-aware fetch command (e.g., `--deepen=15` if the current depth is 5). The v3 patch narrowed the scope to only failing `<rev>~N`/`<rev>^N` syntax, fixing edge cases like chained carets and ensuring the advice doesn’t appear in non-shallow repos or during internal operations. Tests cover all the expected scenarios, and the implementation is robust, with auto-detection of the remote and branch to avoid hardcoding assumptions.

The thread’s main tension isn’t technical—it’s about the review bottleneck. Harald and others have discussed ways to reduce reviewer burden, like pre-review automation tools (e.g., Sashiko), but Patrick Steinhardt and Kristoffer Haugsbakk argue that human review is irreplaceable for assessing conceptual direction. Patrick’s latest reply acknowledges that tooling could help catch mechanical issues (like test ordering) but notes Git lacks the infrastructure to run such checks centrally. He’s open to contributors self-running scripts, but the project’s standards remain non-negotiable. Meanwhile, the patch’s fate hangs in the balance: Junio’s ultimatum still stands, and without a reviewer, it will likely be dropped. The only unresolved technical question is whether the `--deepen=1` suggestion for merge parents (`<rev>^N`) is meaningful enough to keep, but even that’s a minor detail compared to the larger review bottleneck.
