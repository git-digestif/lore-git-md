This thread is about a proposed improvement to Git’s error messages in shallow clones. When users try to access ancestors not present locally using `<rev>~N` or `<rev>^N` syntax, Git currently gives a generic "is not a commit" error. Harald Nordgren’s patch (now at v3) adds a new advice message that explains the shallow boundary and suggests the exact `git fetch --deepen=<n>` command needed to resolve it. The patch is technically sound, addresses all prior feedback, and is ready for integration—but it’s stalled for lack of a reviewer.

Junio Hamano, the maintainer, has warned that unless someone steps up to review it in the next few weeks, he’ll drop it from his integration branches. The patch has drawn only surface-level feedback so far; no one has raised substantive objections, but no one has offered a thorough review either. Harald has tried to address the bottleneck by proposing looser review standards for non-critical code and offering to trade reviews, but both Kristoffer Haugsbakk (who isn’t a C programmer) and Patrick Steinhardt (who insists human review is irreplaceable) declined. The latest email from Kristoffer reinforces this impasse, arguing that automation can’t solve the review bottleneck because it can’t enforce soft requirements like self-review or good commit messages.

The patch itself touches several files, adds a new advice enum, and includes thorough test coverage. It’s context-aware, auto-detects the remote and branch, and avoids double-printing advice for chained carets. The only lingering questions are whether the `<rev>^N` advice is useful (it suggests `--deepen=1`, which may not always be meaningful) and whether the implementation handles edge cases like `origin/main^^^^^` consistently. For now, the thread’s fate hinges on whether a reviewer emerges—or whether Junio follows through on his threat to drop it.
