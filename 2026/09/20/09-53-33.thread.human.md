This thread is about a usability improvement for shallow clones. When users try to access an ancestor not present locally—like `git show HEAD~20`—Git currently gives a generic error with no hint that the repository is shallow or how to fetch more history. Harald Nordgren’s patch adds a new advice (`advice.shallowHistory`) that explains the shallow boundary and suggests the exact `git fetch --deepen=<n>` command needed to resolve it.

The latest version (v3) focuses solely on the `<rev>~N` and `<rev>^N` syntax, which Junio’s review confirmed is the right scope. The advice is context-aware: for `~N`, it calculates the needed depth by subtracting the current shallow depth from `N`; for `^N`, it always suggests `--deepen=1` since shallow boundary commits have no recorded parents. The patch also fixes a bug where chained carets (e.g., `^^^`) would print the advice multiple times and improves remote/branch detection by using `remote_find_tracking` instead of hardcoded paths.

Harald has addressed all prior feedback, including Junio’s concerns about the flawed `git log` integration (now dropped) and documentation clarity. The implementation is robust, with thorough test coverage and careful handling of edge cases like paging and internal re-resolution. The advice is actionable and uncontroversial, and the patch looks ready for `next`. No open questions remain.
