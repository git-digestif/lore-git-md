This thread is about a small but user-friendly improvement to Git’s error messages in shallow clones. When a user tries to access an ancestor commit that isn’t available locally—like `HEAD~20` in a shallow clone with depth 10—Git currently just says “not a commit.” Harald Nordgren’s patch adds a helpful advice message that explains the shallow boundary and suggests the exact `git fetch --deepen=<n>` command needed to fix it.

The patch is under review and hasn’t been revised yet. Junio C Hamano, the maintainer, reviewed the initial version and liked the technical implementation—especially the way it auto-detects the remote and branch and calculates the right `--deepen` value. But he raised two questions: whether the advice should also cover merge parents (`<rev>^N`), since the suggested `--deepen` value is less meaningful for them, and whether the documentation should use `<rev>` instead of `<ref>` to be more precise. Harald has since clarified that the advice only appears when the user explicitly uses `<rev>~N` or `<rev>^N` in a command that fails, not during internal operations like `git log -20`, which just stops at the shallow boundary without erroring. This keeps the advice focused and avoids noise.

The patch touches a few files (`advice.c`, `sha1-name.c`, and a test script) and adds a new advice enum. It’s a straightforward fix, and the only remaining loose ends are the documentation wording and whether to include `<rev>^N` in the advice. A second version is likely, but the core idea seems to have broad support.
