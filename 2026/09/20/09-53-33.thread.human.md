This thread is about a small but user-facing improvement to Git’s error messages. When someone in a shallow clone tries to use `<ref>~N` or `<ref>^N` to reach a commit that isn’t available locally, Git currently just says “is not a commit.” Harald Nordgren’s patch adds a new advice message (`advice.shallowHistory`) that explains the repository is shallow, why the operation failed, and suggests the exact `git fetch --deepen=<n>` command needed to fix it.

The patch is under review and hasn’t seen any prior versions. It’s self-contained, touching just the advice subsystem and rev-parse logic, and includes thorough test coverage. The advice is context-aware: for `<ref>~N` it suggests `--deepen=<N - current_depth>`, while for `<ref>^N` it suggests `--deepen=1` because shallow boundary commits have no recorded parents. It also auto-detects the remote and branch if `<ref>` looks like `<remote>/<branch>`.

So far, the only feedback has come from D. Ben Knoble, who flagged a minor but important inconsistency in the patch’s messaging. The commit message and documentation use “ref” and “commit-ish” interchangeably, which could confuse users. The advice is documented as applying to `~N`/`^N` syntax, which works with any commit-ish (like commit hashes or tags), but the commit message implies it only triggers for refs. The documentation also shows bare `~N`/`^N` syntax, which isn’t valid—it should use `<rev>~<n>` and `<rev>^[<n>]` to match `gitrevisions(7)`. This is a nit about wording, not a critique of the patch’s design or correctness. No other concerns have been raised yet.
