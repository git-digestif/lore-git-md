This thread is about a small but user-facing improvement to Git’s error messages in shallow clones. When a user tries to access an ancestor commit that isn’t present locally using `<rev>~N` or `<rev>^N`, Git currently gives a generic “is not a commit” error. Harald Nordgren’s patch adds a new advice message (`advice.shallowHistory`) that explains the problem, why it happened, and suggests the exact `git fetch --deepen=<n>` command needed to fix it.

The patch is under review and hasn’t been revised yet. It touches `advice.c`, `advice.h`, `sha1-name.c`, and adds tests in `t/t1506-rev-parse-diagnosis.sh`. The advice is context-aware: for `<rev>~N` it calculates the needed `--deepen` value based on how far back the user is trying to go, and for `<rev>^N` it suggests `--deepen=1` since merge parents share the same depth. The patch also auto-detects the remote and branch if the reference looks like `<remote>/<branch>`, and suppresses the advice during internal operations.

Junio C Hamano reviewed the patch and praised the technical implementation but raised two substantive points. First, he questioned whether including `<rev>^N` (merge parents) in the advice might confuse users, since all parents of a commit share the same depth—if `<rev>^1` exists locally, `<rev>^2` is likely also available, making the advice less useful. Second, he flagged a documentation issue: the commit message and advice text use `<ref>` where `<rev>` would be more accurate, since the feature applies to any commit-ish, not just references. These refinements could make the advice more precise and less confusing. D. Ben Knoble had earlier noted similar documentation inconsistencies in a surface-level review.

The patch is well-motivated and well-tested, but these open questions mean a v2 is likely before it’s ready to merge. No one has objected to the core idea or implementation, and the changes are self-contained.
