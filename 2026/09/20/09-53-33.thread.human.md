This thread is about a proposed improvement to Git’s error messages when users in shallow clones try to access ancestors that aren’t present locally. Harald Nordgren’s patch, now at version 3, adds an advice message (`advice.shallowHistory`) that explains why `<rev>~N` or `<rev>^N` failed and suggests the exact `git fetch --deepen=<n>` command needed to resolve it. The patch is technically sound—it auto-detects the remote and branch, avoids double-printing advice for chained carets, and includes thorough test coverage—but it remains stuck in Junio’s `seen` branch because no one with C expertise has reviewed it.

Junio has repeatedly called for reviews, warning that the patch will be dropped unless someone steps forward soon. The discussion has shifted toward process: contributors have proposed automation, review quotas, and deferring nitpicking to ease the bottleneck, but Junio and others (notably Patrick Steinhardt and Phillip Wood) argue that human review is irreplaceable for assessing conceptual direction. Junio’s latest reply pushes back on review quotas, fearing they’d encourage superficial or AI-generated feedback rather than meaningful engagement. The patch itself is uncontroversial, but without a reviewer, it’s likely to be abandoned.
