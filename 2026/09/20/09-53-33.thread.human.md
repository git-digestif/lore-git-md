This thread is about a usability improvement for shallow clones. Harald Nordgren identified a common pain point: when users in shallow repositories try to access ancestors that aren’t present locally (e.g., `git show main~5`), Git currently gives a generic "not a commit" error with no hint that the repository is shallow or how to fetch more history. The patch adds a new advice message (`advice.shallowHistory`) that explains why the operation failed and suggests the exact `git fetch --deepen=<n>` command needed to resolve it.

The implementation is precise: the advice only triggers when the walk stops at a recorded shallow boundary, avoiding false positives on short histories that aren’t truncated. It handles both `~N` and `^N` syntax, calculating the exact `--deepen` value needed (e.g., if the repo is already `--depth=3`, asking for `~5` suggests `--deepen=3`). For `^N`, it always suggests `--deepen=1` because a shallow boundary commit has no parents recorded locally. The patch also smartly names the remote and branch in the suggested command if the reference looks like `<remote>/<branch>` and the remote is configured. The changes touch the rev-parse and object-name subsystems, adding a new `ADVICE_SHALLOW_HISTORY` enum value, updating `advice.c` and `advice.h`, and extending the test suite with six new cases covering edge cases like merge parents, partial depth, and disabled advice.

So far, this is a single-patch series from Harald, and the implementation looks solid: well-motivated, carefully tested, and designed to avoid false positives. No reviews or objections have appeared yet, so the patch is still under initial consideration. If it lands, it should make shallow clones significantly more user-friendly without adding noise for non-shallow repositories.
