This thread is about a small but user-friendly improvement to Git’s error messages in shallow clones. When a user tries to access a commit that isn’t present locally using `<rev>~N` or `<rev>^N` syntax (like `HEAD~20`), Git currently just says the commit doesn’t exist—no hint that the repository is shallow or how to fetch more history. Harald Nordgren’s patch adds an advice message that explains the shallow boundary and suggests the exact `git fetch --deepen=<n>` command needed to fix it.

The patch is now in its third version, narrowed to just the failing-syntax case after earlier feedback. Junio has reviewed it and called for additional reviewers, warning that it will be dropped from his integration branches unless someone steps in soon. The implementation is uncontroversial: it auto-detects the remote and branch, calculates the right `--deepen` value, and avoids printing the advice twice for chained carets. Tests cover all the expected scenarios. The only open questions are minor—whether the advice for merge parents (`<rev>^N`) is useful enough to keep, and whether the logic handles edge cases like `origin/main^^^^^` the same as `origin/main~5`.

Harald has addressed all prior feedback, and the patch is ready for `next`. The holdup isn’t technical—it’s that no one else has reviewed it yet. Kristoffer Haugsbakk recently replied to emphasize that this isn’t a process problem; it’s just that there aren’t enough reviewers to go around. Unless someone volunteers soon, Junio will likely drop the patch, and users will keep seeing the unhelpful error message.
