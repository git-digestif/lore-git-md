This thread is about a proposed improvement to Git’s shallow-clone user experience. When users in a shallow repository try to access history beyond the shallow boundary—such as with `git show HEAD~20`—Git currently emits a generic “is not a commit” error. Harald Nordgren’s patch adds a new advice message (`advice.shallowHistory`) that explains the shallow boundary, why the operation failed, and suggests the exact `git fetch --deepen=<n>` command needed to resolve it.

The patch is under review, with Junio C Hamano’s feedback shaping its evolution. While the technical implementation (auto-detection of remote/branch, context-aware `--deepen` values, and suppression of double-printing) has been praised, two substantive refinements remain open: whether `<rev>^N` (merge parents) should be included in the advice, given that all parents share the same depth, and whether the documentation should use `<rev>` instead of `<ref>` to accurately reflect the feature’s scope. Harald clarified that the advice is triggered only by explicit `<rev>~N` or `<rev>^N` syntax in commands that fail to resolve, not by internal resolution failures in commands like `git log -20` that stop gracefully at the shallow boundary.

The latest exchange reopens the design discussion. Junio argues that the current scope is too narrow, as commands like `git log -20 HEAD`—which silently truncate history at the shallow boundary—are *more* confusing to users than the failing case, because they provide no error message or hint. He suggests the advice should also appear in these silent-failure scenarios, even though they don’t use `<rev>~N` syntax directly. The challenge is where to inject the advice without disrupting normal output, as `git log -20` doesn’t error out. No specific implementation has been proposed, but Junio’s position implies the feature’s value would be significantly higher if it addressed silent truncation. This shifts the thread’s focus from a straightforward bugfix to a broader user-experience question about how aggressively Git should guide users in shallow repositories. A v2 is likely, but the scope of the advice message remains unresolved.
