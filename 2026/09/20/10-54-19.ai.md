This is a **bugfix series** targeting the refs subsystem, specifically restoring the correct behavior of the `reference-transaction` hook when branches, tags, or remote refs are deleted. The v2 series (three patches) addresses a regression introduced in Git 2.31 by commit `8198907795`, which optimized bulk deletions but inadvertently broke the hook by passing all-zero OIDs instead of the resolved old OID. The series now explicitly documents and tests the intentional trade-off: conditional deletion (compare-and-delete) restores the pre-regression safety check, preventing concurrent updates from being silently overwritten.

The core change is in the first patch, which modifies `refs_delete_refs()` to accept an optional `oid_array` of old OIDs, making deletions conditional if an OID is provided. The second and third patches update the callers (`git branch`, `git tag`, `git fetch --prune`, and `git remote prune`) to pass the resolved old OIDs, ensuring the hook receives meaningful values without additional ref reads. The series includes comprehensive test coverage for both files and reftable backends, SHA-1/SHA-256, broken/symbolic refs, and atomic fetch pruning, with new regression tests for concurrent updates and UI consistency (e.g., suppressing "[pruned]" output on failure).

Key technical details:
- **Commands affected**: `git branch -d`, `git tag -d`, `git remote prune`, `git fetch --prune` (all now fixed).
- **Commands unaffected**: `git update-ref -d` (already worked correctly).
- **Backends**: files and reftable.
- **New behavior**: Hook receives the resolved old OID followed by all-zeros on deletion; deletions are conditional (compare-and-delete) to prevent overwriting concurrent updates.
- **Performance**: No regression; bulk deletion of 10,000 packed tags remains at ~0.85 seconds.
- **Race condition trade-off**: The series frames conditional deletion as a deliberate choice to restore the pre-regression safety check, but this remains the **open technical question**—whether the project prefers this safety or unconditional deletion.

The v2 series addresses Karthik Nayak’s substantive review concern about the race condition by documenting the trade-off and adding tests to verify that concurrent updates are preserved. It also incorporates minor readability improvements (e.g., local loop variable) and fixes a UI inconsistency in `git remote prune`. The patches are well-motivated, with clear commit messages and thorough test coverage, making them a strong candidate for merging pending resolution of the race condition question.
