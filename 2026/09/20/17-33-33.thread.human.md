This thread is an RFC by Maciej Ciemborowicz proposing native Git hooks for worktree operations (`add`, `remove`, `move`, `lock`, `unlock`, `prune`). The goal is to replace indirect detection methods (like `post-checkout` or external wrappers) with direct hooks, enabling tools like `git-hooks-ext` to observe worktree changes more reliably. Maciej favors a unified `worktree-lifecycle` hook (similar to `reference-transaction`) over separate hooks for each operation, citing flexibility for multi-worktree operations like `prune`. Open questions include whether to expose a stable worktree identifier and how to handle backward compatibility with existing tools.

Kristoffer Haugsbakk recently chimed in with a surface-level observation, linking to a 2024 discussion where worktree hooks were briefly considered as part of Adrian Ratiu’s `git hook list` series. That earlier thread didn’t pursue the idea, but it may contain relevant arguments or constraints worth revisiting. No technical feedback has been offered yet—just a nudge to check the archives. The thread remains in the proposal stage, with no patches or deeper reviews addressing the design trade-offs. Key participants so far are limited to Maciej and Kristoffer, with no input from maintainers or domain experts.
