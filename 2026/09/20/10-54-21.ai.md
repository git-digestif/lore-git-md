This is the second patch in Maciej Ciemborowicz’s three-patch v2 series restoring the pre-regression behavior of the `reference-transaction` hook for batched branch and tag deletions. It updates the `git branch` and `git tag` built-ins to pass the resolved old OIDs to `refs_delete_refs()`, enabling conditional deletion (compare-and-delete) and ensuring the hook receives meaningful old OID values without additional ref reads. The patch also adds regression tests to `t/t1416-ref-transaction-hooks.sh` verifying that the hook receives the correct old OIDs and that concurrent updates are preserved (the safety check restored by the series).

The changes are straightforward: both commands now collect the old OIDs into an `oid_array` and pass it to `refs_delete_refs()`. The new tests cover the core functionality (hook receives old OIDs) and the race condition edge case (concurrent update prevents deletion). The patch is well-motivated, with clear commit messages and test coverage, and it directly addresses the regression introduced by `8198907795`. The only open question remains whether the project accepts the intentional trade-off of conditional deletion (safety) over unconditional deletion (simplicity), but this patch itself is uncontroversial and ready for review.
