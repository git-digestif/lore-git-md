This is a **bugfix and user-experience improvement** targeting the rev-parse and object-name subsystem. The patch adds a new advice message (`advice.shallowHistory`) that explains why `<ref>~N` or `<ref>^N` fails in a shallow clone, and suggests the exact `git fetch --deepen=<n>` command needed to resolve it.

The problem: when a user in a shallow clone tries to access an ancestor that isn’t present locally, Git currently emits a generic “is not a commit” error with no hint that the repository is shallow or how to fetch more history. The new advice fires only when the walk stops exactly at a recorded shallow boundary (not just because the repo happens to be shallow elsewhere), so it won’t misfire on short histories that aren’t truncated.

Key technical details:
- The advice is threaded through `GET_OID_QUIETLY` so it doesn’t double-print during internal re-resolution.
- For `<ref>~N` it suggests the exact `--deepen` value needed, accounting for any history already present (e.g., if the repo is already `--depth=3`, asking for `~5` suggests `--deepen=3`).
- For `<ref>^N` it always suggests `--deepen=1`, because a shallow boundary commit has no parents recorded locally, so deepening by one generation fetches its complete real parent list in one step.
- If `<ref>` looks like `<remote>/<branch>` and `<remote>` is configured, the suggested command names that remote and branch directly.
- The patch adds a new `ADVICE_SHALLOW_HISTORY` enum value, updates `advice.c` and `advice.h`, and extends the test suite with six new cases covering `~N`, `^N`, merge parents, partial depth, disabled advice, and non-shallow repos.

The implementation is careful to avoid false positives and provides actionable, context-specific suggestions. The test coverage is thorough, and the commit message clearly explains the rationale and edge cases. This looks like a well-motivated, well-tested fix that addresses a real usability pain point.
