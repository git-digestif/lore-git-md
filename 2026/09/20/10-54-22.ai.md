This is the third and final patch in Maciej Ciemborowicz’s v2 bugfix series restoring the correct behavior of the `reference-transaction` hook when pruning remote refs. It updates `git fetch --prune` and `git remote prune` to pass the resolved old OIDs to the deletion transaction, ensuring the hook receives meaningful values (the old OID followed by all-zeros) instead of all-zero OIDs. The patch also prevents a stale scan from deleting refs that were concurrently updated by another process, restoring the pre-regression safety check (conditional deletion) introduced in Git 2.28–2.30.

The changes touch `builtin/fetch.c` and `builtin/remote.c`, introducing a new `stale_ref` struct to carry the ref name and old OID, and modifying `get_stale_heads()` callers to pass the recorded OIDs to `refs_delete_refs()`. The patch includes no additional ref reads, preserving the performance gains of the original optimization (bulk deletion of 10,000 packed tags remains at ~0.85 seconds). It also fixes a UI inconsistency: `git remote prune` no longer prints "[pruned]" when a deletion fails due to a concurrent update.

Test coverage is thorough, adding two new tests to `t/t1416-ref-transaction-hooks.sh`:
1. A regression test verifying the hook receives the correct old OIDs for pruned remote refs across `git remote prune`, `git fetch --prune`, and `git fetch --atomic --prune`.
2. A test ensuring concurrent updates are preserved (the prune fails and the new value remains), with the UI fix (no "[pruned]" output on failure).

The patch is well-motivated and aligns with the series’ goal of restoring the pre-regression behavior while preserving performance. The core unresolved question—whether the project accepts the intentional race condition trade-off (safety via conditional deletion)—remains open, but this patch implements the chosen approach cleanly. The changes are minimal, focused, and backed by comprehensive tests, making it a strong candidate for merging pending resolution of the broader trade-off discussion. Key symbols introduced: `stale_ref` struct, `old_oids` parameter in `refs_delete_refs()` calls.
