This is a **bugfix** for `git diff --no-index -R` that corrects how file/directory conflicts are handled when the `-R` (reverse diff) flag is used. The patch, authored by Haokai Ding, has received a **substantive review** from René Scharfe, who confirmed the issue and endorsed the fix.

The bug occurs when comparing a file on one side with a directory on the other (e.g., `d/sub` as a file vs. `e/sub/file` as a file inside a directory). Without the fix, `git diff --no-index -R` incorrectly reports both paths as deleted or added, depending on the operand order. The fix is minimal—just two lines in `diff-no-index.c`—and swaps the filespecs of the early queue entry when `reverse_diff` is set, ensuring the `-R` flag works consistently. The patch also adds regression tests for both directions of the conflict.

René’s review is brief but substantive: he explicitly calls out the "good find" and approves the test design, particularly the use of `test_expect_code 1` to verify the expected non-zero exit status. The patch is self-contained, well-tested, and addresses a clear edge case without introducing new complexity. It looks ready for merging and should be uncontroversial. If you use `git diff --no-index -R` for comparing directory structures, this fix will resolve a subtle but real annoyance.
