This is a **bugfix series** targeting the reference-transaction hook regression introduced in Git 2.31. The v2 series (three patches) restores the old OID reporting for batched deletions in `git branch -d`, `git tag -d`, `git remote prune`, and `git fetch --prune`, while preserving the performance gains of the original optimization.

The core issue is that external tools (Gerrit, GitLab, CI systems) rely on the hook to monitor ref changes, but since Git 2.31, deleting branches or tags via high-level commands reports all-zero OIDs for both old and new fields, losing the previous object ID. The regression was caused by commit `8198907795`, which replaced `delete_ref()` with `delete_refs()` for bulk deletions but omitted the old OID for safety-checked deletions. The v2 series explicitly addresses the race condition concern raised in v1: the change from unconditional to conditional deletion is intentional, restoring the pre-regression safety check (from Git 2.28–2.30) where `delete_ref()` was passed the resolved OID to prevent deleting refs that were never examined by the caller.

Key improvements in v2 include documenting the conditional deletion behavior, adding tests for concurrent updates, fixing a UI inconsistency where `git remote prune` printed "[pruned]" even after a deletion failure, and incorporating Karthik Nayak’s readability suggestion. The series touches the refs subsystem and affected commands, with no performance regression (deleting 10,000 packed tags remains at ~0.85 seconds). Test coverage spans files/reftable backends, SHA-1/SHA-256, broken/symbolic refs, and atomic fetch pruning.

The **open question** remains whether the project accepts the intentional race condition trade-off (safety via conditional deletion) or prefers unconditional deletion (losing the safety check). The v2 series frames this as a deliberate choice to restore the pre-regression safety check, but the decision is still under discussion. The patches are well-motivated, thoroughly tested, and address a real-world regression affecting external integrations.
