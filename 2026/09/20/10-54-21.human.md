This is the second patch in Maciej Ciemborowicz’s three-patch v2 series fixing the regression in the `reference-transaction` hook. It updates the `git branch` and `git tag` commands to retain the resolved old OIDs when performing batched deletions, restoring the pre-regression safety check and ensuring the hook receives meaningful values.

The patch modifies `builtin/branch.c` and `builtin/tag.c` to collect the old OIDs during ref resolution and pass them to `refs_delete_refs()`, which was updated in the first patch to support conditional deletion. This change is mechanical and preserves the existing behavior of resolving OIDs before deletion—no additional ref reads are introduced. The commit message clearly explains the trade-off: conditional deletion prevents overwriting concurrent updates, which the author argues is a desirable failure mode.

Test coverage is thorough, adding two new tests to `t/t1416-ref-transaction-hooks.sh`. The first verifies that the hook receives the correct old OIDs for batched branch and tag deletions, while the second confirms that concurrent updates are preserved (the deletion fails if the ref changes between resolution and execution). The tests cover both the files and reftable backends implicitly, as the plumbing layer handles the backend-specific details.

The patch is well-crafted and directly addresses the regression without introducing new complexity. The only open question remains the project’s stance on the race condition trade-off (safety via conditional deletion vs. unconditional deletion), but this patch itself is uncontroversial and ready for review. If the series is accepted, this change will restore the hook’s usefulness for external tools like Gerrit and GitLab.
