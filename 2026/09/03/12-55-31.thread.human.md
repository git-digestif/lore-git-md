This thread is about a small but important documentation fix for Git’s partial clone feature. Aleksei Sviridkin identified and corrected a long-standing inaccuracy in `Documentation/technical/partial-clone.adoc`: the claim that dynamic object fetching always fetches objects one at a time was misleading, as it only applies to a single fallback path in `odb.c`. The other ten call sites batch objects efficiently. The patch updates the documentation to reflect this nuance and fixes a minor naming inconsistency (changing "fetch-pack" to "git fetch" to match the implementation).

The patch itself is uncontroversial and technically complete. It received a substantive Reviewed-by from Elijah Newren, who praised its clarity and accuracy, and all feedback—including a request to shorten the initially lengthy cover letter—has been addressed. The patch applies cleanly to both `maint` and `master` and passes basic checks. Despite this, it hasn’t been picked up by Junio or included in any integration branch. Aleksei is now asking whether he should resend the patch to draw attention to it, which seems reasonable given its readiness and the lack of any remaining open questions. A resend would be a low-effort way to ensure this small but useful improvement doesn’t get overlooked.
