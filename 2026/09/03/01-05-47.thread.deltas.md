## 2026/09/09

- [2026/09/09/06-56-39 by Aleksei Sviridkin <f@lex.la>] Clarified that the fallback is reached when the remote-tracking ref has no reflog, not because of gc or expiry: after "git clone --no-local" on the files backend, "git reflog exists refs/remotes/origin/main" returns 1 with core.logAllRefUpdates at its default and gc untouched, while the same source cloned with --ref-format=reftable gets one entry.
- [2026/09/09/06-56-39 by Aleksei Sviridkin <f@lex.la>] Explained that reflog entries do not expire on a calendar; they are removed only when "git reflog expire" runs or when "git gc --auto" decides by loose object count (gc.auto, 6700), so a quiet repository expires nothing.
- [2026/09/09/06-56-39 by Aleksei Sviridkin <f@lex.la>] Reported benchmark measurements (median of 7 runs with 20000 entries in the local branch reflog and a remote-tracking ref without reflog): with entries spread over 200 days, a zero cutoff took 0.325s versus 0.069s for a 90-day cutoff; after "git reflog expire --all" left 5 entries, both took about 0.070s; with 20000 entries inside 90 days both took about 0.320s; with no matching entry the zero cutoff added 0.26s of work for the same answer, concluding the extra cost lands only on repositories still holding entries older than 90 days where gc has not run.
