This thread is about a small but long-standing bug in the `git-contacts` contrib script, which Aleksei Sviridkin first posted about a month ago. The script misidentifies "boundary" commits—where `git blame` stops, like the initial commit or shallow clone cutoffs—as legitimate contributors, leading to false positives in reviewer suggestions. Aleksei’s fix is straightforward: it teaches the script to ignore these boundary commits by adding the `--root` flag to `git blame` and filtering them out. The patch is self-contained, applies cleanly to `maint`, and includes quantitative evidence showing it fixes 27 incorrect contact lists, empties 9 that should be empty, and improves 3 others.

No one has reviewed the patch yet, despite its age and the lack of controversy. Aleksei’s resend is a gentle nudge, noting the patch still applies and the issue has been present since the script was introduced in 2013. There’s no indication this is a contentious change—just a quiet, well-motivated fix that seems to have slipped through the cracks. If the project wants it, it’s ready to go.
