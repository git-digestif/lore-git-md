This thread is about a memory leak in `git history reword --dry-run` that was introduced when Patrick Steinhardt’s `ps/receive-pack-shallow-optim` branch was merged. The leak—283 bytes per invocation—only surfaces when the commit buffer isn’t cached in the commit slab, a condition tied to repository settings like `i18n.commitencoding` or packfile state. Kristoffer Haugsbakk reported the issue and bisected it to the merge commit; Patrick later proposed a one-line fix in `builtin/history.c` that adds a missing `repo_unuse_commit_buffer()` call.

The fix itself is uncontroversial and has been confirmed by both Patrick and Kaartic Sivaraam, who sent an identical patch in June 2026 but saw it stall due to a misleading commit message that claimed the leak was universal. Kaartic has now committed to resending the patch with a corrected message and may include a test case. The leak remains present in `master`, `next`, and `seen`; no merge has occurred yet. Once Kaartic’s reroll lands, the procedural hurdle will be cleared and the fix should proceed.
