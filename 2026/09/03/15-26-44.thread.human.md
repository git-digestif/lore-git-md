This thread is about a memory leak in `git history reword --dry-run` that was introduced when Patrick Steinhardt’s `ps/receive-pack-shallow-optim` branch was merged. The leak—283 bytes per invocation—only surfaces in certain repository conditions, specifically when commit buffers aren’t cached in the commit slab, which can depend on settings like `i18n.commitencoding` or the presence of a commit graph.

The fix is straightforward: a single line in `builtin/history.c` (`commit_tree_ext()`) to call `repo_unuse_commit_buffer()` and balance the allocation from `repo_get_commit_buffer()`. The patch itself is uncontested and ready, but Kaartic Sivaraam will resend it with a corrected commit message to clarify the leak’s environment-dependent nature. He may also add a test case to verify the fix under the right conditions. The leak remains in `master`, `next`, and `seen` as of early September 2026.

Kristoffer Haugsbakk originally reported the issue, confirmed the root cause via bisect, and provided reproduction steps. Patrick Steinhardt authored the fix but couldn’t reproduce the leak on his machine, while Kaartic had proposed the same fix earlier but delayed it due to an inaccurate commit message. Jeff King (Peff) had previously pointed out the message’s issues. The thread is now waiting on Kaartic’s reroll, with no new objections or technical concerns raised.
