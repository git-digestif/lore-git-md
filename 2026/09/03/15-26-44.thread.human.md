This thread is about a memory leak in `git history reword --dry-run` that was introduced when Patrick Steinhardt’s `ps/receive-pack-shallow-optim` branch was merged in March 2026. Kristoffer Haugsbakk reported the leak in early September, confirming it affects `master`, `next`, and `seen` and tracing it to the merge commit via bisect. The leak—283 bytes per invocation—occurs in the object database layer during commit buffer handling, specifically in `unpack_compressed_entry()` in `packfile.c`.

Patrick has now posted a fix: a single-line addition in `builtin/history.c` that calls `repo_unuse_commit_buffer()` to free the commit buffer after use in `commit_tree_ext()`. The patch targets the exact code path identified in the stack trace and aligns with prior discussion from June 2026, where Kaartic Sivaraam proposed the same fix but it was never merged. The leak’s visibility may depend on environment-specific conditions like `i18n.commitencoding`, which could explain why it went unnoticed until now. No broader investigation into whether other commands are affected has been proposed yet.

The fix is narrowly scoped and appears low-risk, though testing across diverse repository configurations would be wise. The thread is now focused on whether this patch resolves the leak and whether it should be merged as-is.
