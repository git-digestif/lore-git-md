This thread is about a memory leak in `git history reword --dry-run` that was introduced when Patrick Steinhardt’s `ps/receive-pack-shallow-optim` branch was merged. The leak, confirmed by Kristoffer Haugsbakk via bisect, occurs in the ODB layer when `repo_get_commit_buffer()` allocates memory that isn’t freed in `commit_tree_ext()`. Both Patrick and Kaartic Sivaraam have proposed the same fix—a single-line addition of `repo_unuse_commit_buffer()`—but it hasn’t been merged yet.

The core issue is straightforward: the leak surfaces only under specific conditions (e.g., certain `i18n.commitencoding` settings or packfile configurations), which is why it wasn’t caught earlier. Patrick’s fix is narrowly scoped and uncontroversial, but Kaartic’s earlier attempt stalled because his commit message didn’t accurately describe the leak’s trigger—it only occurs when the commit buffer isn’t cached in the commit slab. Kaartic plans to resend the patch with a corrected message and possibly a test case.

The leak remains present in `master`, `next`, and `seen` as of early September 2026. While the fix itself is simple, the thread underscores the need for precise commit messages and broader testing to ensure the fix works across all repository configurations. No regressions are expected, but the unresolved question is why some commits bypass the slab cache, which might warrant further investigation.
