Subject: Memory leak in `git history reword` introduced by `ps/receive-pack-shallow-optim` merge
Series version: N/A (bug report, now with proposed fix)
Originating author: Kristoffer Haugsbakk
Thread type: bug report with fix

Core problem or goal
Identify and fix a 283-byte memory leak in `git history reword --dry-run` that was introduced by the merge of Patrick Steinhardt’s `ps/receive-pack-shallow-optim` branch (commit `13763ecf`, 2026-03-02). The leak surfaces in the ODB layer during commit buffer handling, specifically in the path from `repo_get_commit_buffer()` to `unpack_compressed_entry()` in `packfile.c`. The goal is to plug the leak without introducing regressions.

Current status
Fix proposed by Patrick Steinhardt (single-line addition in `builtin/history.c`). The patch adds a missing `repo_unuse_commit_buffer()` call in `commit_tree_ext()` to balance the `repo_get_commit_buffer()` allocation. The fix is narrowly scoped to the leak’s immediate cause and does not address broader ODB or packfile-layer questions. The leak remains present in `master`, `next`, and `seen` as of 2026-09-02; no merge event has occurred.

Key technical details
- **Files/subsystems touched**: `builtin/history.c` (`commit_tree_ext()`), ODB layer (`repo_get_commit_buffer()`, `repo_unuse_commit_buffer()`).
- **Triggering command**: `git history reword --dry-run` (leak does not occur on the original `git history reword` commit `d205234c` or without `--dry-run`).
- **Repository conditions**: Leak requires a "real repo" with packfiles and/or commit graph; minimal test repos do not reproduce. May depend on `i18n.commitencoding` settings.
- **Stack trace**: Leak originates from `repo_get_commit_buffer()` -> `odb_read_object()` -> `packfile_store_read_object_info()` -> `unpack_compressed_entry()`.
- **Leak size**: 283 bytes per `git history reword --dry-run` invocation.
- **New symbol**: `repo_unuse_commit_buffer()` call added in `commit_tree_ext()` to free `original_message`.
- **Related prior work**: Kaartic Sivaraam proposed the same fix in June 2026 (unmerged, likely due to oversight or unresolved follow-ups).
