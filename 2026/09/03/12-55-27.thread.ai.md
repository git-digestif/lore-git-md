Subject: [PATCH] contrib/git-contacts: ignore boundary commits in blame output

Thread type: bugfix

Core problem or goal
The `git-contacts` contrib script misclassifies "boundary" commits (where `git blame` stops traversal, e.g., initial commit or shallow clone cut-off) as legitimate contributors. These commits often did not touch the file at all, causing false positives in reviewer suggestions and skewing relevance calculations.

- New behavior: boundary commits are explicitly tracked and excluded from the final contact list
- CLI change: adds `--root` flag to `git blame` to prevent initial commit from being marked as boundary
