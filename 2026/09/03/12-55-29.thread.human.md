This thread is about a bugfix for a performance regression in `git pack-objects` that affects partial clones. Aleksei Sviridkin identified a logic error in `prefetch_to_pack()` where the function incorrectly fetches missing objects one by one instead of batching them, leading to significant slowdowns. The patch, posted on September 3, includes a clear commit message, synthetic benchmarks, and test coverage for both SHA-1 and SHA-256 repositories.

The fix touches `builtin/pack-objects.c` and adds a test in `t/t5300-pack-object.sh`. It restores the intended batching behavior without changing the on-disk format. Despite the patch’s readiness, it hasn’t received any review feedback or been picked up for integration. Aleksei’s recent resend gently pings the list to check if the patch has been overlooked or if it’s no longer needed. No objections or open questions have been raised so far.
