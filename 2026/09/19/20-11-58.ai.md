This is the **third and final patch in a bugfix series** targeting the `reference-transaction` hook regression. The series restores the correct old-OID reporting for ref deletions while preserving the performance gains introduced in Git 2.31.

This patch updates `git fetch --prune` and `git remote prune` to pass the resolved old OIDs to the reference-transaction hook. The fix reuses the OIDs already collected by `get_stale_heads()` (stored in `ref->new_oid`), avoiding additional ref reads. The plumbing change (`refs_delete_refs()` accepting an optional `oid_array`) was introduced in the first patch, and the second patch addressed `git branch -d` and `git tag -d`.

The implementation touches `builtin/fetch.c` and `builtin/remote.c`, introducing a new `stale_ref` struct to carry both the ref name and its old OID through the pruning logic. The patch adds 42 lines of test coverage to `t/t1416-ref-transaction-hooks.sh`, verifying that the hook receives the correct old OID for pruned refs across `git remote prune`, `git fetch --prune`, and `git fetch --atomic --prune`, for both files and reftable backends.

This completes the series: all high-level commands that perform batched ref deletions now restore the pre-2.31 behavior of providing the old OID to the hook. The fix is narrowly scoped, does not affect the on-disk format, and maintains the performance optimization (deleting 10,000 packed tags remains at ~0.85 seconds). The test coverage is thorough, including atomic transactions and symbolic/broken refs. No controversy is evident—this appears to be a straightforward correction of an unintended behavioral change.
