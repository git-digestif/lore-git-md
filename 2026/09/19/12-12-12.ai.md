This is a CI/build system patch, the third in a four-patch series aimed at fixing GitLab CI breakage for Windows builds after Rust support was enabled. The series as a whole restores pipeline functionality for GitLab's MinGW-based Windows jobs, and this patch specifically addresses the Rust toolchain setup.

The patch fixes a "cargo: command not found" error in GitLab's MinGW job by ensuring the Rust toolchain is properly provisioned and accessible. The issue stems from commit `86909a4db5d` (ci(windows): build with Rust, 2026-09-13), which enabled Rust in the shared CI configuration but only added the necessary setup for GitHub Actions. The minimal SDK's login profile resets `PATH`, so simply installing the toolchain isn't enough—Cargo must be explicitly added back to `PATH` for the build to succeed.

The change modifies `.gitlab-ci.yml` to invoke `ci/install-dependencies.ps1` with a new `-Mingw` switch, which ensures the correct Rust toolchain (`gnu` target) is installed. The script then adjusts `PATH` to include `/c/Rust/bin` before running `ci/make-test-artifacts.sh`. This is a targeted fix for GitLab's MinGW environment and doesn't affect Git's core functionality or other CI platforms.

The patch is narrowly scoped to CI infrastructure and appears to be a straightforward mechanical adjustment. The commit message clearly identifies the problem (the "cargo: command not found" error) and the solution (ensuring Cargo is in `PATH` after the SDK's profile resets it). The `-Mingw` switch and `gnu` Rust target are key technical details for follow-up discussion, as they distinguish this setup from the existing MSVC-based Rust configuration.

No test coverage is included, as this is a CI infrastructure change whose validation relies on GitLab CI pipeline execution.
