This is a **platform compatibility / user experience discussion** about Git’s automatic `LESS=FRX` environment injection when using custom pagers like `delta`. Brian m. Carlson responds to Francisco Boni’s report with a defense of the current behavior, arguing that it is both necessary for cross-platform consistency and unlikely to change.

Carlson explains that Git’s logic—setting `LESS=FRX` only when the variable is *unset* (not when it is empty)—is intentional and aligns with how environment variables work. He highlights the difficulty of statically determining whether a custom `core.pager` (which can be an arbitrary shell command) will ultimately invoke `less`, especially across platforms where `more` may actually be `less` (e.g., FreeBSD). The example of Debian’s `sensible-pager` further illustrates the challenge: Git cannot reliably predict which pager will run, so it errs on the side of injecting defaults to ensure consistent behavior.

The response also provides workarounds, noting that users can override the behavior by explicitly setting `LESS` in their `GIT_PAGER` or `core.pager` configuration (e.g., `LESS="" delta`) or by using `env -i` to clear the environment entirely. Carlson acknowledges the surprise factor for users of pager wrappers but frames it as a consequence of an older design pattern (environment-based configuration) that modern tools now avoid in favor of config files.

Carlson’s conclusion is firm: the project is unlikely to change this behavior due to backward-compatibility concerns and the risk of breaking existing setups. The tone suggests this thread is more likely to document the rationale than to spark a patch series. For users of tools like `delta`, the takeaway is to adopt the provided workarounds rather than expect Git to adjust its defaults. The discussion remains open-ended, but the maintainer’s stance here is a strong signal that the status quo will persist.
