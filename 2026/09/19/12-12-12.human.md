This is a CI/build system patch, part of a four-patch series fixing GitLab CI breakage for Windows builds after Rust support was enabled. This specific patch (3/4) addresses the immediate cause of the MinGW job failure: `cargo` is not found in the build environment.

The fix is straightforward: the GitLab CI job now runs `ci/install-dependencies.ps1 -Mingw` in its `before_script` phase, ensuring the Rust toolchain is properly installed and configured for MinGW builds. The patch also adjusts the `PATH` in the build script to include `/c/Rust/bin`, compensating for the minimal SDK's profile resetting the environment. This matches the setup already in place for GitHub Actions, which was added in the earlier commit that enabled Rust for Windows.

The change is minimal and targeted, touching only `.gitlab-ci.yml`. It does not affect Git's core functionality or user-facing behavior, and the commit message clearly explains the motivation and the specific failure being addressed.
