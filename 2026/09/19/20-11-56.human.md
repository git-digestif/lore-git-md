This is the first patch in a three-part **bugfix** series that restores the correct old OID reporting in the `reference-transaction` hook when branches or tags are deleted. The regression, introduced in Git 2.31, causes the hook to receive all-zero OIDs instead of the resolved old OID, breaking external tools like Gerrit and GitLab that rely on this information.

The patch modifies `refs_delete_refs()` to accept an optional `oid_array` of old OIDs, which are then passed to `ref_transaction_delete()`. This allows callers to supply pre-resolved old OIDs (e.g., from `git branch -d` or `git tag -d`) without requiring additional ref reads, preserving the performance gains from the original optimization. The changes are mechanical: all existing callers pass `NULL` for the new parameter, maintaining backward compatibility.

The diff touches eight files, primarily updating function signatures and calls to `refs_delete_refs()`. The core logic in `refs.c` now checks for null OIDs and skips verification when none is provided, ensuring the hook receives the correct old OID when available. The patch is narrowly scoped and does not affect the on-disk format or other ref operations.
