This is a feature patch proposing a new warning in `git commit` when a new commit's date is earlier than its parent's. The motivation is clear: Git's history traversal (e.g., `git log --since`) assumes commit dates are non-decreasing, so an out-of-order date can silently hide commits. The patch adds a configurable warning via `advice.clockSkew`, triggered only during `git commit` (not merges or replays), and includes tests.

The commit message is unusually thorough, explaining the problem, the narrow scope of the fix, and even listing open questions (e.g., whether `fsck` should also warn about future dates). The implementation looks clean: it hooks into `builtin/commit.c`, checks parent dates, and uses Git's existing advice system. Tests cover the warning, its absence when dates are valid, and silencing via config.

This is a well-motivated, low-risk addition. The warning is opt-in (via advice) and narrowly targeted, so it won’t annoy users with legitimate use cases (e.g., replaying history). The RFC label suggests the author is more interested in feedback on the concept than the code, but the patch itself is already polished. Worth watching for discussion about whether `fsck` should grow a similar check.
