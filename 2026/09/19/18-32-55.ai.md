This is a **bugfix** identifying a regression in `git reflog expire` introduced in Git 2.50. The patch reports that the default expiry times for reachable and unreachable reflog entries were accidentally swapped in commit `85658275702b` ("builtin/reflog: stop storing default reflog expiry dates globally"). As a result, reachable entries (which should default to 90 days) are now expiring after 30 days, while unreachable entries (which should default to 30 days) are incorrectly kept for 90 days.

The email provides a clear reproduction case: a 60-day-old reachable reflog entry is pruned when it should be retained under the documented defaults (`gc.reflogExpire=90.days`, `gc.reflogExpireUnreachable=30.days`). The regression stems from a misordering of the `.default_expire_total` and `.default_expire_unreachable` fields in `reflog.h`, where the values are reversed compared to the pre-2.50 implementation.

The issue is well-documented with a minimal test case, commit references, and a comparison of the old vs. new code. It affects all platforms, as the bug is in core Git logic. The patch implicitly calls for a fix to restore the intended defaults, though no explicit patch is attached—this appears to be a bug report rather than a code submission. The regression is likely to be uncontroversial to fix, given the clear documentation mismatch and straightforward reproduction.
