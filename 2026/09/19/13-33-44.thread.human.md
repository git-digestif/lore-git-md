This thread is a well-documented bug report from Maciej Ciemborowicz about the `reference-transaction` hook’s incomplete reporting during branch renames (`git branch -m`). When a branch is renamed, the hook currently only reports the deletion of the old branch name, omitting the creation of the new one—a discrepancy that affects both the traditional files-based ref backend and the newer reftable backend (where the issue is more severe, as no usable rename payload is reported at all). The expected behavior, confirmed via `git update-ref --stdin`, is that both the deletion and creation should be included in the transaction.

The report includes a minimal reproducer script that works across Git versions 2.28 to 2.55, demonstrating the issue’s persistence. While no fix is proposed, the clarity of the report—focusing on observable behavior rather than root-cause speculation—makes it actionable for contributors working on ref backends (e.g., Patrick Steinhardt, Karthik Nayak) or hook infrastructure (e.g., Adrian Ratiu). The issue is straightforward to reproduce and affects a core Git operation, so it may see quick follow-up, though the discussion will likely center on whether the fix belongs in the branch-rename logic, the ref backend layer, or the hook invocation code.
