This thread is about a bug in Git’s `reference-transaction` hook, which fails to report the creation of a new branch when a branch is renamed (`git branch -m`) or copied (`git branch -c`). The hook currently only reports the deletion of the old branch name, omitting the new one entirely. Maciej Ciemborowicz posted a v2 patch to fix this, addressing earlier architectural concerns from Junio Hamano by confining the rename/copy state to per-ref updates rather than the transaction as a whole.

The patch has been under review, with Karthik Nayak supportive and Junio’s initial objections resolved. However, Patrick Steinhardt’s latest review is sharply critical, calling the patch "not reviewable" in its current form. He raises three major issues: the commit message is vague and unmotivated, the code mixes refactoring with core logic in a way that obscures review, and the implementation relies on non-idiomatic patterns (like excessive C block scopes) that suggest AI generation rather than careful authoring. Steinhardt proposes structural changes, such as splitting the patch into smaller commits and moving hook-skipping logic into `run_transaction_hook`. The thread’s future now depends on whether Maciej can address these concerns without breaking the fix’s correctness. No merge status has been reported, and the patch remains under active debate.
