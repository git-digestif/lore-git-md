This thread is about a patch series by Harald Nordgren that introduces a "matching-inspired" fetch mode for shallow repositories, aiming to speed up `git fetch` by dynamically fetching only branches tracked by local branches. The series, now at version 11, is queued in Junio’s `next` branch as of May 15, 2026, but its design is now contested.

The core idea is to use `remote.<name>.refmap` to define both namespace mappings and which refs are fetched when no explicit refspec is given. This avoids the slow negotiation of all remote branches in shallow repositories. The series is feature-complete, with all prior feedback addressed, and introduces a `--limited-fetch` flag for `git remote add`, making this mode the default in shallow repositories. However, Phillip Wood has raised a fundamental objection: overloading `refmap` to control both *what* to fetch and *where* to store it repeats the same inflexibility the series aims to fix. He proposes a cleaner alternative, `remote.<name>.fetchRefs`, to decouple these concerns, which would also resolve inconsistencies in refspec-matching order and enable per-branch overrides.

Junio has not yet responded to this objection, and the series remains in `next` pending resolution. The key open question is whether the current design will proceed or if a redesign is needed. Phillip’s critique is substantive and directly challenges the series’ core premise, making this a critical juncture for the thread. If the objection stands, the series may need significant rework before graduating to `master`.
