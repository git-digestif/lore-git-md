This thread introduces a new fetch mode for Git that addresses performance issues in shallow repositories by dynamically fetching only the branches tracked by local branches at the remote. The v4 patch series, authored by Harald Nordgren, is now technically complete and implements a consensus design using `remote.<name>.refmap` to separate namespace mappings from fetch selection logic.

The series has four patches. The first clarifies documentation and introduces the refmap configuration. The second, which this email discusses, implements the core dynamic branch enumeration logic—fetching only branches tracked by local branches at the remote—while removing the forced inclusion of the remote’s default branch, a change that resolved Junio Hamano’s earlier objection. The third patch adds a `--limited-fetch` flag to `git remote add` for explicit opt-in, and the fourth makes this mode the default in shallow repositories. All patches address prior feedback, and the series remains under active review with no merge status.

The only new input in this update is a minor edge case raised by Harald: when running a bare `git fetch` against a refmap-only remote, no branches are fetched, leaving no remote-tracking refs available for commands like `git branch --set-upstream-to`. While not a blocker, this is flagged for potential future discussion. Junio and Phillip Wood have provided substantive reviews on earlier versions, and the series is now stable, with no outstanding objections. The implementation preserves backward compatibility for non-shallow repositories but does not address migration of existing shallow setups, which may require follow-up.
