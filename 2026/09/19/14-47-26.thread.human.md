Harald Nordgren’s thirteen-patch series introducing `remote.<name>.fetchRefmap` for a matching-inspired fetch mode is now in the final stages of review, with the v13 implementation complete and targeted for merging to `master`. The series addresses a long-standing performance issue in shallow repositories, where a refspec-less `git fetch` negotiates history for all remote branches, causing slow or hanging operations. The design decouples the "what" (which refs to fetch) from the "where" (where to store them) using the new `remote.<name>.fetchRefmap` configuration key, resolving earlier objections to overloading `remote.<name>.refmap`.

The v13 revision is under active review, with two high-weight items converging toward resolution. First, the override semantics for command-line refspecs and colon-separated `remote.<name>.fetch` entries have narrowed to Phillip Wood’s preferred model, where such refspecs override `fetchRefmap` entirely rather than coexisting with it. This aligns with user expectations and preserves backwards compatibility, though the v13 revision still preserves the current dual-storage behavior in a regression test pending a v14 update. Second, Junio and Phillip have both critiqued the cover letter as inadequate for a complex series, blocking progress until it includes a patch-by-patch summary and design context. Junio’s email provided a template for Patches 1–3, and the urgency is heightened by the series’ blocking status for Collin’s `ch/fetch-followremotehead-lazy-validation` topic.

The series is otherwise ready for merging, with all major technical questions resolved. The v13 patches include seven key improvements: a mechanical fix for `@{push}` resolution (falling back to `remote->refmap` if `remote->fetch` doesn’t resolve the refname), a regression test for dual-storage behavior, core plumbing for `fetchRefmap`, an extracted helper for dynamic branch enumeration, a `--limited-fetch` flag for `git remote add`, a shallow-repository default for the flag, and comprehensive test coverage. The design is finalized, with precedence rules (`remote.<name>.fetch` > `remote.<name>.fetchRefmap` > dynamic branch enumeration) and forced-update placement (`+` on the refmap side) confirmed by Junio and Phillip. The only remaining low-priority edge cases—such as handling remotes with no default branch—require no action before graduation. Harald is expected to post a v14 revision addressing the override semantics and cover letter critiques, with the series likely to graduate in the current cycle.
