Harald Nordgren's v15 series continues to advance the matching-inspired fetch mode for shallow repositories, where `git fetch` would by default retrieve only locally tracked upstream branches rather than every remote ref. Junio C Hamano has now reviewed both the first and second patches, raising substantive technical concerns that need addressing before the series can graduate. On patch 1/7, he requested corrections to the commit message and documentation to clarify that `remote.<name>.fetchRefmap` arrives in patch 3/7, not 2/7, and to specify precisely which refspec forms bypass the refmap. His review of patch 2/7 identifies three edge cases: fetching from a URL with `--refmap` but no configured refspecs would silently ignore the refmap; automatic tag following could misbehave because `*autotags` is computed before destinations are dropped; and `git fetch --prune --refmap` might prune against the wrong ref hierarchy when no command-line refspecs are given.
