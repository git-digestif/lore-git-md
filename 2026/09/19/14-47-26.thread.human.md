This thread introduces a "matching-inspired" fetch mode for Git, designed to speed up `git fetch` operations in shallow repositories by dynamically fetching only the branches tracked by local branches at the remote. The v11 series (5 patches) is now complete and queued in `next` as of the 2026-05-15 "What's cooking" report, with all prior feedback addressed.

The core change adds a `remote.<name>.refmap` configuration that separates namespace mappings from fetch selection logic. When no explicit refspec is given and the remote has a refmap but no traditional `remote.<name>.fetch` refspec, Git now infers which branches to fetch based on local branches tracking the remote. The series also introduces a `--limited-fetch` flag for `git remote add` to explicitly opt into this mode, and makes it the default for shallow repositories. This default behavior is implemented in the final patch, which checks whether the repository is shallow and configures the remote accordingly unless explicitly overridden.
