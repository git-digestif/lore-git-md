This thread is about improving `git fetch` performance in shallow repositories (created with `git clone --depth`). When fetching from a remote with many branches, shallow repositories can experience slow or hanging operations because the default refspec-less fetch negotiates history for all remote branches. The discussion has settled on a "matching-inspired" fetch mode that dynamically fetches only the branches tracked by local branches at the remote, plus the remote’s default branch.

The initial proposal used a `+:` refspec syntax, but Junio C Hamano rejected this as too monolithic and instead proposed a more modular design using a new `remote.X.refmap` configuration. This refmap would define namespace mappings (e.g., `+refs/heads/*:refs/remotes/second/*`) without specifying what to fetch, allowing the fetch logic to dynamically select branches. The feature is now in the design refinement phase, with a v3 patch series expected to implement Junio’s four-part plan: introducing `remote.X.refmap`, dynamic branch enumeration, a `--limited-fetch` option for `git remote add`, and heuristics to enable this mode by default in shallow repositories.

D. Ben Knoble recently endorsed the `remote.X.refmap` approach, reinforcing the consensus and closing the discussion on refspec syntax. The design now focuses on implementation details, such as how to handle stale or missing `HEAD` information, whether `--limited-fetch` should be enabled by default for shallow repositories, and how to maintain backward compatibility with existing shallow repositories using wildcard refspecs. Harald Nordgren, the original author, is expected to implement the v3 series, with Junio and Phillip Wood likely to review it for technical correctness and edge cases. The feature remains under review, with no merge status yet.
