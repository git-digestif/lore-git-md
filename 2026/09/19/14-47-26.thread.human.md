Harald Nordgren’s twelve-iteration patch series introducing a matching-inspired fetch mode for shallow repositories is now effectively complete and awaiting final review before merging to `master`. The series addresses a long-standing pain point: shallow clones (`git clone --depth`) suffer slow or hanging fetches when the remote has many branches, because a refspec-less fetch negotiates history for all remote branches. The solution dynamically fetches only the branches tracked by local branches at the remote being fetched, using a new configuration key `remote.<name>.fetchRefmap` to separate the “what” (which refs to fetch) from the “where” (where to store them). This design, finalized in v12, resolves the maintainer’s and key reviewers’ objections to earlier versions that overloaded `remote.<name>.refmap`.

The v12 implementation is queued in `next` (as v11) but deprecated in favor of v12, which Junio C Hamano and Phillip Wood have endorsed. The precedence rule is settled: `remote.<name>.fetch` overrides `remote.<name>.fetchRefmap`, which in turn overrides dynamic branch enumeration; command-line refspecs override both. The only remaining open questions are minor—clarifying documentation around backwards-compatibility risks and edge cases, such as how to handle legacy configurations that mix colon-separated `fetch` entries with `refmap`. Phillip Wood and Junio are collaboratively working out whether such mixed configurations should error out or silently ignore the colon-separated entries, a decision that will be documented and tested but does not block graduation. Harald has addressed all substantive review feedback, and the series is expected to graduate in the current cycle once final nits are resolved.
