**Human summary**

This thread is about a 6-patch series (v13) by Harald Nordgren that introduces a new `remote.<name>.fetchRefmap` configuration to solve a long-standing problem: shallow repositories created with `git clone --depth` fetch all remote branches by default, which is slow and often unnecessary. The series implements a "matching-inspired" fetch mode that dynamically fetches only the branches tracked by local branches at the remote being fetched, using a new config key to separate which refs to fetch from where to store them. The design is finalized and endorsed by Junio Hamano and Phillip Wood, and the implementation is complete, with only one high-weight edge case still under discussion: how command-line refspecs should interact with the new `fetchRefmap` configuration (whether they should override it entirely or coexist with it).

The series is currently queued in `next` and expected to graduate to `master` in the current cycle once the override semantics are resolved and any remaining review feedback is addressed. The v13 revision includes several key improvements, such as a fix for `@{push}` resolution, a new `--limited-fetch` flag for `git remote add`, and a default to use this mode in shallow repositories. The patches are well-tested and touch core refspec logic in `remote.c`, `builtin/fetch.c`, and `builtin/remote.c`, along with updates to documentation and tests.
