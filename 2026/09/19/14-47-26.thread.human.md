This is the eleventh iteration of Harald Nordgren’s patch series introducing a “matching-inspired” fetch mode for shallow repositories.  The series is now ready to merge: all prior feedback—including Junio’s control-flow and NULL-check requirements and D. Ben Knoble’s clarity, efficiency, and documentation suggestions—has been incorporated.  The only change since v10 is the adoption of Knoble’s accepted improvements (strvec usage, const correctness, output parameters last, deduplication of followRemoteHEAD logic, and clearer commit messages).  The merge conflict with Junio’s ch/fetch-followremotehead-lazy-validation topic has been resolved, and the procedural request for a second reviewer’s Ack is satisfied by Knoble’s implicit endorsement.

The heart of the series is a new per-remote configuration key, remote.<name>.refmap, which supplies the default for --refmap when there is something explicit to fetch (command-line refspecs or remote.<name>.fetch).  When no explicit refspec is given and the remote has a refmap but no fetch refspec, git fetch dynamically enumerates only the branches tracked by local branches at that remote, eliminating the slow or hanging fetches that shallow users experience today.  The fallback logic in remote_find_tracking() now correctly treats refmap as a superset of fetch while preserving negative refspec exclusion.  A --limited-fetch flag for git remote add explicitly opts into this mode, and shallow repositories now default to it.  No on-disk format changes are introduced beyond the new configuration entries in .git/config.

The series touches remote.c/h, builtin/fetch.c, builtin/remote.c, and the relevant documentation and test files.  Sixteen new tests lock down edge cases, backward compatibility, and refmap tracking.  Open questions about edge-case handling (remotes with no default branch, migration of existing shallow repositories, and warnings for old-behavior users) remain, but they are not blockers for merging.  The series is uncontroversial, introduces no new technical debt, and reuses existing logic and configuration machinery.
