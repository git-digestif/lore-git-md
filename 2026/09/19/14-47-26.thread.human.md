This thread began with Harald Nordgren’s patch proposing a `fetch.shallow` configuration option to restrict refspec-less fetches in shallow repositories to the current branch, aiming to prevent slow or hanging fetches when the remote has many branches. The discussion quickly shifted after Phillip Wood identified the root cause: `git remote add` defaults to a wildcard fetch refspec even in shallow repositories, leading to unnecessary negotiation for all remote branches. Both now agree that modifying `git remote add` to avoid wildcard refspecs in shallow repositories is the cleaner solution, eliminating the need for `fetch.shallow`.

The thread is now focused on designing this alternative approach. Key questions remain about whether the new behavior should be automatic or configurable, how it should interact with existing remotes, and how to preserve backwards compatibility for non-shallow repositories. No code has been written yet for the alternative solution, and the original patch remains unmerged. The performance issue is confirmed to affect any shallow repository with many remote-tracking branches, not just sparse checkouts. The next steps will likely involve a new patch implementing the `git remote add` change.
