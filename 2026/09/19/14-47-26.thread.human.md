This thread covers Harald Nordgren's v16 patch series (7 patches) introducing a matching-inspired limited-fetch mode to speed up `git fetch` and `git pull` in shallow repositories with many remote branches. The series decouples which refs are fetched from where they are stored using new config keys `remote.<name>.fetchUpstreams` and `remote.<name>.fetchRefmap`, and culminates in patch 7/7, which makes `git remote add` default to this limited mode automatically inside shallow clones unless the user passes `-t`, `--mirror`, or `--no-limited-fetch`.

Version 16 directly addresses the three concerns Junio C Hamano raised during his review of v15: it restores the error when `--refmap` is used with a URL that has no configured fetch refspecs, fixes tag-following semantics when refs are stored through a refmap, and corrects `--prune` behavior so configured destinations are not incorrectly pruned when a refmap redirects storage. The series builds incrementally, starting with refmap application helpers in patches 1-3, extracting upstream-collection logic in patch 4, implementing the `fetchUpstreams` config and branch-tracking logic in patch 5, adding the `--limited-fetch` CLI flag to `git remote add` in patch 6, and finally defaulting to limited fetch in shallow repositories in patch 7/7.

The series remains under review; while v15 was queued in `next`, v16 has not yet graduated to `master` and awaits final maintainer sign-off. A proposal by Phillip Wood to partially merge the foundational patches 1-3 remains unacted upon, though it would unblock a dependent topic from Matt Hunter that currently conflicts textually in `seen`.
