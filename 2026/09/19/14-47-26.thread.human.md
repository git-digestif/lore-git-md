Here’s the **human-mode narrative** for the thread:

This thread implements a long-requested improvement to Git’s fetch behavior for shallow repositories. When users clone with `--depth`, a later `git fetch` without explicit refspecs can hang or slow to a crawl because Git negotiates history for *all* remote branches. Harald Nordgren’s eleven-iteration patch series introduces a “matching-inspired” mode that dynamically fetches only the branches tracked by local branches at the remote being fetched. The key innovation is `remote.<name>.refmap`, a new configuration knob that separates namespace mapping from fetch selection. If you configure `remote.cabal.refmap` to map `refs/heads/*` to `refs/remotes/cabal/*`, a refspec-less fetch against `cabal` will now fetch only the branches your local branches already track, not every branch on the remote.

The series is now feature-complete and queued in `next` as of mid-May 2026. Junio Hamano, the maintainer, proposed the refmap design and has queued the series after all review points were addressed. D. Ben Knoble provided detailed feedback on clarity, efficiency, and edge cases; his suggestions—ranging from `strvec` usage to commit-message precision—were all incorporated. The final patch adds a `--limited-fetch` flag to `git remote add` and makes it the default in shallow repositories, so new remotes in shallow clones automatically opt into the new behavior unless explicitly overridden with `--no-limited-fetch`. Four new tests lock down the shallow-repository default, the precedence rule (fetch refspecs override refmap), and the absence of interference with existing functionality.

The only open questions are edge-case handling—what to do about remotes with no default branch, whether to warn users about the behavior change, and whether to auto-migrate existing shallow repositories—but none are blockers. The series is uncontroversial, introduces no new technical debt, and reuses existing configuration machinery. If no flaws surface during the cooking period, it should graduate to `master` in the next release cycle.
