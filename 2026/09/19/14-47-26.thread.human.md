This thread is about a patch series by Harald Nordgren that introduces a "matching-inspired" fetch mode for shallow Git repositories, using a new `remote.<name>.refmap` configuration to dynamically fetch only the branches tracked by local branches at the remote. The series is now at version 6 and is technically complete but blocked on two issues raised by Junio C Hamano: a glitch where simultaneous `remote.<name>.fetch` and `remote.<name>.refmap` configuration triggers a fatal error, and an unresolved design question about how such simultaneous configuration should be handled.

The key participants are Harald (the author), Junio (the maintainer), Phillip Wood, and D. Ben Knoble. Junio previously endorsed the `refmap` design but identified the glitch and design ambiguity in his latest review, providing a test script to demonstrate the issues. Harald has now proposed that the `fetch` setting should take precedence when both configurations are present, which would resolve the fatal error by ignoring the `refmap` setting. This proposal is still under discussion, and no revised patches have been posted yet. The series remains under active review and is not queued for integration until these issues are resolved.

The technical implementation touches `remote.c`, `builtin/fetch.c`, and `builtin/remote.c`, adding the `refmap` configuration, dynamic branch enumeration logic, and a `--limited-fetch` flag for `git remote add`. The series is backward-compatible for non-shallow repositories but does not address migration of existing shallow repositories. Open questions include how to handle remotes with no default branch, whether to warn users about behavior changes, and the broader design policy for simultaneous `fetch` and `refmap` configuration. The thread is self-contained with no dependencies on other in-flight topics.
