This thread is about a patch series (v6) by Harald Nordgren that introduces a "matching-inspired" fetch mode to improve performance for shallow repositories. The series aims to solve the problem of slow or hanging `git fetch` operations when the remote has many branches, by dynamically fetching only the branches tracked by local branches at the remote.

The key idea is to use a new configuration option, `remote.<name>.refmap`, to separate namespace mappings from fetch selection logic. This allows `git fetch` to enumerate only the branches that local branches are tracking, rather than negotiating history for all remote branches. The series is technically identical to v5, with only a minor editorial fix in the commit message of Patch 3/4.

Junio C Hamano, the maintainer, has stated he will queue the series but has not yet performed his own re-review or queued it to any integration branch. The series remains under active review but is not yet in `seen`. All four patches are ready: Patch 1/4 adds the `remote.<name>.refmap` configuration, Patch 2/4 implements the dynamic branch enumeration logic, Patch 3/4 adds the `--limited-fetch` flag to `git remote add`, and Patch 4/4 makes `--limited-fetch` the default in shallow repositories.

No substantive objections remain, though some edge cases and backward compatibility questions are still open, such as whether the new mode should be available outside shallow repositories and how to handle remotes with no default branch. The series is self-contained and does not depend on other in-flight topics. Key participants include Harald Nordgren (author), Junio C Hamano (maintainer), Phillip Wood (design reviewer), and D. Ben Knoble (design discussion participant). The series is ready for integration once Junio completes his re-review.
