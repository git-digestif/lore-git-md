This thread is about Harald Nordgren’s patch series introducing a "matching-inspired" fetch mode for shallow repositories, now in its twelfth iteration (v12). The goal is to speed up `git fetch` in shallow clones by dynamically fetching only the branches tracked by local branches at the remote, rather than negotiating history for all remote branches. The series has undergone a major redesign since v11, splitting the "what to fetch" logic into a new configuration key, `remote.<name>.fetchRefmap`, to avoid overloading the existing `remote.<name>.refmap` (which now handles namespace mapping only). Junio C Hamano and Phillip Wood have endorsed the v12 design, and the series is now under final review for merging to `master`.

The v12 implementation is complete and addresses all prior design objections. The precedence rule is settled: `remote.<name>.fetch` takes priority over `remote.<name>.fetchRefmap`, which in turn overrides dynamic branch enumeration (if neither is configured). Command-line refspecs override both. A minor inconvenience remains: forced updates (`+`) must be specified on the refmap side (the "where"), requiring users who want to reject non-fast-forward updates for some branches to use two separate refspecs. This is not a blocker but may need clearer documentation. The series is backwards-compatible, as older Git versions will ignore `fetchRefmap` and fail cleanly rather than misinterpreting configuration.

The only remaining work is addressing final review feedback, such as clarifying the documentation around `fetchRefmap` and the forced-update behavior. The series is queued in `next` (as v11) but is deprecated in favor of v12, which is expected to graduate in the current cycle once reviews are complete. No open design or implementation questions remain.
