Here’s the **human-mode narrative** for the thread:

This thread is about a long-running patch series by Harald Nordgren that introduces a new `remote.<name>.fetchRefmap` configuration key to solve a performance problem in shallow repositories. When users clone with `--depth`, a plain `git fetch` can hang or slow to a crawl because it negotiates history for *all* remote branches. The series adds a "matching-inspired" mode that fetches only the branches tracked by local branches at the remote, controlled by the new `fetchRefmap` key. After eleven iterations and a major redesign (v12), the design is now finalized and endorsed by Junio Hamano and Phillip Wood. The series is queued in `next` as v11 but is deprecated in favor of v12, which is under active review for merging to `master`.

The core design separates the "what" (which refs to fetch) from the "where" (where to store them). `remote.<name>.fetchRefmap` specifies the source refs (e.g., `*@{upstream}`), while `remote.<name>.refmap` handles namespace mapping (e.g., `+refs/heads/*:refs/remotes/second/*`). Command-line refspecs override both, and the precedence is clear: explicit `remote.<name>.fetch` entries take priority, then `fetchRefmap`, then dynamic branch enumeration. The only remaining open questions are edge cases around how the new key interacts with older colon-separated `fetch` entries. Junio pointed out that the command-line already supports dual storage (e.g., `git fetch --refmap=... refs/heads/master:refs/remotes/origin/master`), and Harald’s latest email confirms that v12 implements the same behavior for the config-based case. Phillip Wood still prefers to reject such configurations outright, but the implementation already allows them, so the discussion is now about whether to document and support this behavior or to error out.

The series is otherwise complete and well-tested. All patches are ready for final review, and the only blockers are resolving the edge-case handling and addressing any remaining nits. The series is expected to graduate in the current cycle once these are settled. Key participants include Harald (the author), Junio (the maintainer), and Phillip Wood (the primary reviewer whose objections drove the v12 redesign). D.
