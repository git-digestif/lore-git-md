Harald Nordgren's v14 five-patch series introduces `remote.<name>.fetchRefmap` to let shallow repositories fetch only the branches they actually track, avoiding the slowdown caused by negotiating history for every remote branch. The core design is settled and endorsed by Junio C Hamano and Phillip Wood: the new config key selects which refs to fetch while `remote.<name>.refmap` handles only namespace mapping, with precedence running from `remote.<name>.fetch` to `fetchRefmap` to a dynamic fallback. The series is queued in `next` as an earlier version and is under final review, but three strategic questions remain open.

The most active disagreement concerns override semantics. Phillip Wood originally proposed that command-line refspecs with explicit destinations (`src:dst`) should cause both `--refmap` and `fetchRefmap` to be ignored entirely, preventing dual storage. Junio C Hamano objected, arguing this would be asymmetrical since command-line refspecs already override `remote.<name>.fetch` but not `--refmap` defaults, and instead proposed `--no-refmap` or `--refmap=""` as an explicit opt-out. In his latest reply, Phillip maintains that users expect command-line `src:dst` to override configuration rather than add to it, and questions whether the current `--refmap` interaction with explicit destinations matches the documentation, but he concedes that `--refmap=""` could serve as the dedicated opt-out mechanism. The two now appear close to a compromise around the explicit flag, though the implicit-override question is not fully resolved.

Separately, Phillip has endorsed a partial merge path: landing patches 1--3 now would resolve textual conflicts blocking Collin's dependent topic (`ch/remote-defer-follow-remote-head-validation`) while deferring the ergonomic patches 4--5. He also agrees with Junio that the implicit dynamic branch enumeration in patch 3 is problematic when explicit smart modes exist, preferring explicit `fetchRefmap` configuration, though removing patch 3 entirely would reintroduce the conflicts with the dependent topic. Harald Nordgren is expected to reconcile the override-semantics positions and decide whether to pursue the partial merge or wait for the full series.
