This thread is about a patch series (v5) by Harald Nordgren that introduces a "matching-inspired" fetch mode to improve performance for shallow repositories. The goal is to avoid slow or hanging `git fetch` operations when the remote has many branches by dynamically fetching only the branches tracked by local branches at the remote.

The series is now technically complete and ready for integration. Junio C Hamano, the maintainer, has indicated he will queue it ("Will replace") but hasn't yet performed his final review or added it to any integration branch. The key changes since v4 are purely mechanical—renumbering a test file to avoid conflicts with another in-flight topic. The core design, using `remote.<name>.refmap` to separate namespace mappings from fetch selection logic, has been approved by Junio and others. Patch 2/4, the focus of this latest update, implements the dynamic branch enumeration logic that makes the feature work, removing an earlier requirement to always fetch the remote's default branch.

The series is backward-compatible for non-shallow repositories, but a few edge cases remain open for future discussion, such as whether the new mode should be available outside shallow repositories or how to handle remotes with no default branch. Harald has noted one minor quirk—a bare `git fetch` against a refmap-only remote fetches no branches—but doesn't consider it a blocker. Phillip Wood and D. Ben Knoble have been involved in the design discussions, but no new objections have been raised in this iteration. The next step is likely Junio's final review before the series is queued for testing.
