This thread is about a patch series (now at v8) by Harald Nordgren that introduces a "matching-inspired" fetch mode to improve performance in shallow repositories. The problem it solves is that `git fetch` in shallow clones currently negotiates history for all remote branches, even when the user only cares about a few, leading to slow or hanging operations.

The core idea is to use a new `remote.<name>.refmap` configuration to define namespace mappings without specifying what to fetch. When no explicit refspec is given and the remote has a refmap but no `remote.<name>.fetch` refspec, Git dynamically fetches only the branches tracked by local branches at that remote (via `@{upstream}`). This avoids negotiating history for all remote branches, significantly speeding up fetches in shallow repositories. The series also introduces a `--limited-fetch` flag for `git remote add` and makes it the default for shallow repositories.

Junio Hamano, the maintainer, had previously raised several concerns in v7, all of which have now been addressed in v8. These include fixing hardcoded `the_repository` usage, renaming variables for clarity, refactoring to reduce code duplication, and resolving a regression where the current branch’s `@{upstream}` could be dropped. The test failures caused by a conflict with another topic in Junio’s `seen` branch have also been resolved. The precedence rule—where `remote.<name>.fetch` takes precedence when both it and `remote.<name>.refmap` are configured—is now uncontroversial and resolves a fatal error from earlier versions.

The series is technically sound and ready for final review. The design has broad consensus, and the remaining patches (adding the `--limited-fetch` flag and making it the default for shallow repositories) are uncontroversial. The only minor open question is whether the matching-inspired mode should be available outside of shallow repositories, but this can be addressed in follow-up work. The series is a strong candidate for merging.
