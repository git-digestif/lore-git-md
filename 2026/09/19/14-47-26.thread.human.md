This thread implements a "matching-inspired" fetch mode for shallow Git repositories, aiming to speed up `git fetch` operations by dynamically fetching only the branches tracked by local branches at the remote. Harald Nordgren's v4 patch series is now technically complete and addresses all prior feedback, including Junio C Hamano's key objection about the forced inclusion of the remote's default branch. The series introduces `remote.<name>.refmap` configuration to separate namespace mappings from fetch selection logic, adds a `--limited-fetch` flag to `git remote add`, and makes this mode the default for shallow repositories.

The implementation preserves backward compatibility for non-shallow repositories and introduces no on-disk format changes beyond the new configuration entry. A minor edge case was noted—where a bare `git fetch` against a refmap-only remote fetches no branches—but this is acknowledged as a small quibble and not a blocker. Open questions remain about whether the new mode should be available outside shallow repositories and how to handle migration of existing shallow repositories, but these are not holding up the current series.
