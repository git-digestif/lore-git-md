This thread introduces a new "matching-inspired" fetch mode for shallow Git repositories, designed to speed up `git fetch` operations by dynamically fetching only the branches tracked by local branches at the remote. The v4 series, authored by Harald Nordgren, is now technically complete and addresses all prior feedback, including Junio Hamano's key objection about forced inclusion of the remote's default branch.

The implementation centers on a new `remote.<name>.refmap` configuration that separates namespace mappings from fetch selection logic. When no explicit refspec is given and the remote has a refmap but no fetch refspec, `git fetch` now enumerates only the branches tracked by local branches at that remote. The series also adds a `--limited-fetch` flag to `git remote add` and makes it the default in shallow repositories, ensuring new remotes in shallow clones don’t trigger full fetches of all remote branches. Backward compatibility is preserved for non-shallow repositories.

Junio has indicated he will queue the series for wider review but hasn’t yet conducted his own re-review, leaving room for additional technical feedback. The only open quibble is a minor edge case where a bare `git fetch` against a refmap-only remote fetches no branches, which Harald acknowledges but doesn’t consider a blocker. The series remains under active review with no merge status yet.
