This thread is about a patch series by Harald Nordgren that introduces a new "matching-inspired" fetch mode to address performance issues in shallow repositories. The series, now at v3, implements Junio C Hamano's proposed `remote.<name>.refmap` design, which separates namespace mappings from fetch logic. The goal is to make `git fetch` faster in shallow clones by dynamically fetching only branches tracked by local branches at the remote, plus the remote’s default branch.

The series is complete with four patches covering the refmap configuration, dynamic branch enumeration, a `--limited-fetch` flag for `git remote add`, and a default to this mode in shallow repositories. Junio approved the code in the first patch but requested a documentation wording change to clarify that `--refmap` is always active. However, his recent review of the second patch raises a fundamental design concern: whether the remote’s default branch should always be fetched automatically. Junio argues this is overly presumptive and could be wasteful, suggesting it be removed to simplify the implementation. This question now hangs over the series, with a v4 iteration likely needed to resolve it.

Key participants include Harald Nordgren (the author), Junio (the maintainer, who proposed the refmap design but now questions the default branch inclusion), Phillip Wood (who contributed to earlier design discussions), and D. Ben Knoble (who endorsed the refmap approach). The series remains under active review, with no merge status yet. The earlier consensus on the refmap design is intact, but the core behavior of the matching-inspired mode is now in flux.
