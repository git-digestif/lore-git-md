This thread introduces a "matching-inspired" fetch mode to address performance issues in shallow repositories (`git clone --depth`), where `git fetch` can be slow or hang when the remote has many branches. The v5 patch series, authored by Harald Nordgren, is now complete and ready for integration, with Junio C Hamano indicating he will queue it.

The series implements a new `remote.<name>.refmap` configuration to separate namespace mappings from fetch selection logic. When no explicit refspec is given, `git fetch` dynamically fetches only the branches tracked by local branches at the remote, avoiding the negotiation of history for all remote branches. The `--limited-fetch` flag for `git remote add` explicitly opts into this mode, and this latest patch makes it the default in shallow repositories. Non-shallow repositories continue using wildcard refspecs by default, preserving backward compatibility.

Key participants include Harald Nordgren (author), who addressed Junio’s design concerns by removing the forced inclusion of the remote’s default branch and refining documentation wording. Junio C Hamano (maintainer) proposed the `remote.<name>.refmap` design and confirmed it resolves backward compatibility issues, though he deferred his own re-review. Phillip Wood and D. Ben Knoble contributed to design discussions, with no substantive objections remaining. The series is self-contained, with no external dependencies, and all four patches are technically ready. The only minor edge case—a bare `git fetch` against a refmap-only remote fetching no branches—was acknowledged by Harald but not considered a blocker.
