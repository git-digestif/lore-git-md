This thread introduces a matching-inspired fetch mode for shallow repositories, allowing `git fetch` to dynamically fetch only branches tracked by local branches at the remote. The v8 series (5 patches) by Harald Nordgren is under active review, with the core design—using `remote.<name>.refmap` to separate namespace mappings from fetch selection—now uncontroversial. Junio C Hamano, the maintainer, has reviewed most of the series and identified two issues in Patch 2/5 that require a respin, but all other concerns from prior versions are resolved.

The latest email covers Patch 4/5, which adds a `--limited-fetch` flag to `git remote add`. This flag configures the remote to use the new refmap-based fetch mode, avoiding the performance penalty of negotiating history for all remote branches in shallow repositories. Junio’s brief review acknowledges the patch as straightforward and well-executed, with no objections raised. The implementation is clean, integrates seamlessly with the rest of the series, and includes thorough test coverage. The patch is ready for review and has no known issues.

The series is a strong candidate for merging to `next` once Junio re-reviews the respun Patch 2/5. The remaining patches (4/5 and 5/5) are technically sound, with Patch 5/5 defaulting `--limited-fetch` for shallow repositories. Open questions include minor design choices (e.g., whether the mode should be available outside shallow repositories) and edge-case handling, but these are not blockers for merging. Key participants include Harald (author), Junio (maintainer), Phillip Wood (design reviewer), and D. Ben Knoble (design discussion).
