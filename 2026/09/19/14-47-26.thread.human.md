This thread is about Harald Nordgren’s twelve-version patch series introducing a “matching-inspired” fetch mode for shallow repositories. The goal is to stop `git fetch` from hanging or crawling when the remote has many branches: instead of negotiating history for every remote branch, the new mode dynamically fetches only the branches that local branches already track at that remote.

The design is now final. Version 12 splits the old `remote.<name>.refmap` into two keys: `remote.<name>.fetchRefmap` (what to fetch) and `remote.<name>.refmap` (where to store them). Precedence is clear: explicit `remote.<name>.fetch` beats `remote.<name>.fetchRefmap`, which beats dynamic branch enumeration. Command-line refspecs override both. Forced updates (`+`) stay on the refmap side. A new `--limited-fetch` flag for `git remote add` configures the fetchRefmap, and the final patch (5/5) makes that flag the default in shallow repositories.

Junio C Hamano and Phillip Wood have both endorsed the design. Phillip’s objection to overloading `refmap` in v11 was the catalyst for the v12 redesign, and Junio confirmed the precedence rules. The series is queued in `next` as v11 but is deprecated in favor of v12, which is under active review. No design or implementation questions remain open; the only blocker is final review feedback. The full v12 implementation is posted, and graduation to `master` is expected in the current cycle.
