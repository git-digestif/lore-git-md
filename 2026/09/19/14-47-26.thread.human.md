This thread introduces a new `fetch.shallow` configuration option, proposed by Harald Nordgren, to address performance issues in shallow repositories. When enabled, this setting restricts a refspec-less `git fetch` or `git pull` to only the current branch's upstream, avoiding the negotiation of history for all remote branches—a common source of slowdowns or hangs in large repositories with many branches. The feature is opt-in (defaulting to `false`) to prevent surprises for users who rely on the existing behavior of syncing all remote branches.

The implementation is clean and focused, modifying `builtin/fetch.c` to add the new config option and adjust refspec expansion logic. It includes thorough test coverage in `t/t5537-fetch-shallow.sh`, verifying the feature works as intended—narrowing fetches to the tracked branch, correctly updating `refs/remotes/<name>/HEAD`, and having no effect on non-shallow repositories or fetches of non-tracked remotes. The documentation in `Documentation/config/fetch.adoc` is complete, explaining the behavior, edge cases, and default value.

So far, the patch has not received any review feedback, but its design and execution appear solid. It addresses a real pain point for users of shallow repositories while maintaining backward compatibility. The next step will likely be review from maintainers or domain experts, particularly around the refspec handling and potential edge cases in the negotiation logic.
