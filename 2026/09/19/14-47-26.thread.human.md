This thread implements a "matching-inspired" fetch mode for Git, aimed at improving performance for shallow repositories by dynamically fetching only the branches tracked by local branches at the remote. The v10 series, authored by Harald Nordgren, is now ready for merging to Junio's `next` branch after addressing all prior feedback.

The core idea is to introduce a `remote.<name>.refmap` configuration that defines namespace mappings without specifying what to fetch, allowing `git fetch` to dynamically infer which branches to fetch based on local tracking branches. This avoids the slow or hanging operations users experience with shallow repositories when a refspec-less fetch negotiates history for all remote branches. The series also adds a `--limited-fetch` flag to `git remote add` and makes it the default for shallow repositories, ensuring new remotes in shallow clones use the optimized fetch mode.
