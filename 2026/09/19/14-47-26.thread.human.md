This thread began with Harald Nordgren’s proposal to add a `fetch.shallow` configuration option to restrict refspec-less fetches in shallow repositories to the current branch, addressing slow or hanging fetches when remotes have many branches. After substantive review from Phillip Wood, the discussion pivoted to a cleaner alternative: modifying `git remote add` to avoid wildcard refspecs in shallow repositories by defaulting to a narrower refspec (e.g., fetching only the remote’s default branch).

The current focus is on implementation details for this alternative. Harald’s latest email highlights a key challenge: constructing the narrower refspec without a network call. The local repository lacks information about the remote’s branches or default branch, making it difficult to determine the correct refspec (e.g., `+refs/heads/main:refs/remotes/origin/main`). The discussion now centers on whether to use the local repository’s current branch as a proxy, rely on the remote’s `HEAD` (which may be stale), or introduce a new configuration option to let users specify the branch explicitly. No code has been written yet, and the outcome of this design question will shape the eventual patch. The thread remains in the design phase, with consensus on the broader approach but open questions about the specifics.
