This thread is about a patch series by Harald Nordgren that introduces a new "matching-inspired" fetch mode to address performance issues in shallow repositories (created with `git clone --depth`). When fetching from a remote with many branches, shallow repositories can experience slow or hanging operations because a refspec-less fetch negotiates history for all remote branches. The proposed solution dynamically fetches only the branches tracked by local branches at the remote, plus the remote’s default branch, using a new `+:` refspec syntax.

The initial design, implemented in v2 of the patch, has been rejected by Junio C Hamano as too monolithic. Instead, Junio proposes a four-commit refactoring that replaces the `+:` refspec with a new `remote.X.refmap` configuration. This refmap would define the namespace mapping (e.g., `+refs/heads/*:refs/remotes/second/*`) without specifying what to fetch, while the fetch logic itself would dynamically determine which branches to fetch based on local tracking branches. The proposal also includes a new `--limited-fetch` option for `git remote add` and heuristics to enable this mode by default in shallow repositories. This approach avoids the ambiguity of the `+:` syntax and cleanly separates namespace mapping from branch selection, making the feature easier to review and test incrementally.

Key participants include Harald Nordgren (the author), Phillip Wood (who proposed the narrower refspec alternative and refined the matching-inspired approach), and Junio C Hamano (who provided the latest design feedback). The thread is now focused on refining the design rather than reviewing the v2 patch, and a v3 series will likely be needed to implement Junio’s proposal. Open questions include how to handle backward compatibility for existing shallow repositories, edge cases like stale `HEAD` or empty repositories, and whether the new mode should be opt-in or enabled by default for shallow repositories. The feature is not yet ready to merge and remains under active design discussion.
