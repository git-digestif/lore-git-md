This thread is about a patch series by Harald Nordgren that introduces a new "matching-inspired" fetch mode to solve performance issues in shallow repositories. When you clone with `--depth`, a plain `git fetch` can be slow or hang because it negotiates history for all remote branches. The series now implements Junio Hamano's proposed design using `remote.<name>.refmap` to dynamically fetch only the branches tracked by local branches at the remote, plus the remote’s default branch.

The v3 series is under active review and consists of four patches. The first patch added the `remote.<name>.refmap` configuration to define namespace mappings. The second patch, just posted, implements the core logic: when no explicit refspec is given and the remote has a refmap but no fetch refspec, Git now infers which branches to fetch by looking at the `@{upstream}` configuration of local branches and always includes the remote’s default branch. This ensures shallow repositories fetch only what they need without manual refspec management. The remaining patches will add a `--limited-fetch` flag to `git remote add` and default to this mode in shallow repositories.

The design discussion is settled, and the focus is now on implementation details like edge-case handling (e.g., remotes with no default branch) and whether the new mode should be available outside shallow repositories. Junio and Phillip Wood have been key voices in shaping the design, while Harald has been addressing feedback and refining the implementation. The series touches `remote.c`, `builtin/fetch.c`, and adds new tests to verify the dynamic branch selection works correctly. No merge decisions have been made yet, but the approach has broad agreement.
