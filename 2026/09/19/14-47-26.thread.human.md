Harald Nordgren's v15 series, which adds a matching-inspired fetch mode to speed up operations in shallow repositories, is now complete through patch 2/7 and under final review. The series introduces `remote.<name>.fetchUpstreams` to let users explicitly opt into fetching only the upstream branches of local branches on refspec-less fetches, alongside a new `remote.<name>.fetchRefmap` config key that decouples which refs are fetched from where they are stored. The latest two patches implement the confirmed override semantics: patch 1/7 ensures any refspec with an explicit destination (`src:dst`) ignores refmaps entirely, and patch 2/7 extends this so that `--refmap` on the command line now works even without command-line refspecs, applying to whatever `remote.<name>.fetch` selects by first stripping the configured destinations and then applying the supplied mapping.

Junio C Hamano and Phillip Wood have both endorsed this override behavior, resolving the main design debate from earlier versions where v14 relied on implicit dynamic enumeration. The architectural shift to explicit opt-in via `fetchUpstreams` also addresses the maintainer's earlier objection to implicit fallbacks. The series remains queued in `next` as of the latest "What's cooking" report, with v15 superseding earlier iterations, though it has not yet graduated to `master`. One remaining strategic question is Phillip Wood's earlier suggestion to partially merge the first few foundational patches now to unblock a dependent topic from Collin, a split that v15 has not implemented.
