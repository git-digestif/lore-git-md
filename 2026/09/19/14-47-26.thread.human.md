This thread is about a proposed `fetch.shallow` configuration option that would restrict refspec-less fetches (like `git fetch` or `git pull`) in shallow repositories to only the current branch’s upstream, avoiding the performance penalty of negotiating history for all remote branches. The patch was submitted by Harald Nordgren as an initial solution to a slowdown he experienced in shallow repositories with many remote-tracking branches.

The discussion has shifted after Phillip Wood questioned whether the performance issue is specific to sparse checkouts (as the documentation implied) or a more general problem for any shallow repository with many remote-tracking branches. Harald now agrees that the root cause is broader and suggests that improving `git remote add` behavior—by avoiding wildcard fetch refspecs in shallow repositories—might be a better solution than introducing a new config option. No code changes have been requested yet, and the thread is now exploring this alternative approach. The patch remains under review, with no merge status reported.
