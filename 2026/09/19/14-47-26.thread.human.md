This thread introduces a new `remote.<name>.refmap` configuration and a matching-inspired fetch mode to improve `git fetch` performance in shallow repositories by dynamically fetching only branches tracked by local branches. The v6 series, authored by Harald Nordgren, is technically complete and addresses all prior design objections, but Junio C Hamano has identified two remaining issues that block its integration.

The first is a glitch: when both `remote.<name>.fetch` and `remote.<name>.refmap` are set, the code currently fails with an unhelpful fatal error. The second is a design question: what *should* happen in that scenario? Junio’s test script demonstrates the ambiguity but leaves the policy decision open. Until these are resolved, the series remains under review despite Junio’s earlier intent to queue it.

Key participants include Harald Nordgren (author), Junio (maintainer), Phillip Wood (design reviewer), and D. Ben Knoble (design discussion). The series touches `remote.c`, `builtin/fetch.c`, and `builtin/remote.c`, adding the refmap configuration, dynamic branch enumeration logic, and a `--limited-fetch` flag for `git remote add` that defaults in shallow repositories. No substantive objections remain beyond the two open issues, and backward compatibility is preserved for non-shallow repositories. The next step is Harald’s proposal for handling the refmap/fetch coexistence.
