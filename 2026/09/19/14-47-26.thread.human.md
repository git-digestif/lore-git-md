This thread began with Harald Nordgren’s proposal to add a `fetch.shallow` configuration option to restrict refspec-less fetches in shallow repositories to the current branch, aiming to prevent slow or hanging fetches when the remote has many branches. That patch is now abandoned after Phillip Wood identified the root cause: shallow repositories default to wildcard fetch refspecs, which force negotiation for all remote branches. The discussion has since shifted to modifying `git remote add` to avoid wildcard refspecs in shallow repositories, but the exact implementation—particularly how to construct a narrower refspec without a network call—remained unresolved.

Junio C Hamano has now weighed in with a more ambitious alternative: a "matching-inspired" fetch mode for `git fetch` that dynamically determines which remote branches to fetch based on the local branches’ upstream settings. For example, if local branch `feature` tracks `origin/main`, a `git fetch origin` in this mode would fetch only `refs/heads/main` from `origin`. This approach avoids the need to guess the remote’s default branch and instead leverages existing tracking relationships. Junio suggests a special refspec syntax (e.g., `:` or `+:`) to trigger this mode, though key details—such as how it would integrate with `git remote add`, whether it would be the default for shallow repositories, and how to handle edge cases—are still open. The proposal is framed as a complementary addition rather than a direct replacement for the narrower refspec idea, leaving room for further discussion.

The thread is now at a design crossroads. The original `fetch.shallow` patch is dead, and the simpler `git remote add` fix is on hold while Junio’s dynamic fetch mode is explored. No code has been written for either alternative, and the conversation remains focused on conceptual trade-offs. The next steps will likely involve refining Junio’s proposal, addressing its integration with shallow repository workflows, and deciding whether it should supersede or coexist with the narrower refspec approach.
