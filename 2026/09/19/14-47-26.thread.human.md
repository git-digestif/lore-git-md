This thread began with Harald Nordgren’s patch proposing a new `fetch.shallow` configuration option to restrict refspec-less fetches in shallow repositories to the current branch, aiming to address slow or hanging `git fetch` operations when the remote has many branches. The discussion quickly pivoted when Phillip Wood suggested that the root cause might lie in `git remote add` defaulting to a wildcard fetch refspec in shallow repositories, which forces refspec-less fetches to negotiate history for all remote branches. Harald agreed this could be a more targeted solution, and the thread is now focused on exploring whether modifying `git remote add` to avoid wildcard refspecs in shallow repositories would eliminate the need for `fetch.shallow`.

The original patch touched `builtin/fetch.c`, added a new `fetch.shallow` config key (boolean, default `false`), and included test coverage for narrowing fetches to the tracked branch, but no code changes have been requested or implemented yet. The alternative solution under discussion would involve changing `git remote add` to default to a narrower refspec (e.g., fetching only the default branch) in shallow repositories, though questions remain about configurability, backwards compatibility, and interaction with existing remotes. The thread is still in the design phase, with no new patch proposed for the alternative approach. Key participants are Harald Nordgren (author) and Phillip Wood (design feedback), both of whom are driving the shift toward the `git remote add` solution.
