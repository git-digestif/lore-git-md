Harald Nordgren’s thread on introducing a matching-inspired fetch mode for shallow repositories is now in its fourteenth iteration and nearing completion. The series, which began as a response to slow fetches in shallow clones, has evolved into a well-reviewed implementation that decouples what to fetch from where to store it using a new `remote.<name>.fetchRefmap` configuration key. Junio C Hamano and Phillip Wood have endorsed the design, and the override semantics—where command-line refspecs override the new config key entirely—are now resolved. The series is currently queued in `next` as v11 but has been superseded by v14, which addresses all prior feedback.

The latest email covers the fourth patch in the series, adding a `--limited-fetch` flag to `git remote add`. This flag configures the remote to fetch only branches tracked by local branches, using `*@{upstream}` as the default `fetchRefmap`. While uncontroversial and well-tested, this patch is part of the ergonomic layer (along with Patch 5/5) and may be deferred if the maintainer opts for a partial merge of Patches 1–3. That proposal, now strengthened by Matt Hunter’s clarification that Patches 1–3 are sufficient to resolve conflicts with Collin’s dependent topic, aims to unblock other work while allowing the remaining patches to undergo further review. The key remaining decision is whether to merge the foundational plumbing now or hold out for the full series. Harald has signaled openness to splitting the series if it accelerates progress, but Junio’s preference for complete topics may weigh against it. The thread is otherwise ready for final review, with no technical blockers remaining.
