This thread introduces a "matching-inspired" fetch mode for shallow Git repositories, authored by Harald Nordgren. The goal is to speed up `git fetch` operations in shallow clones by dynamically fetching only the branches tracked by local branches at the remote, rather than negotiating history for all remote branches. The v7 series is now technically complete, addressing earlier design ambiguities by establishing that `remote.<name>.fetch` takes precedence when both it and the new `remote.<name>.refmap` are configured.

The series adds a new `remote.<name>.refmap` configuration to define namespace mappings without specifying what to fetch, and introduces a `--limited-fetch` flag for `git remote add` to opt into the new mode. Shallow repositories now default to this mode, ensuring faster fetches out of the box. The implementation touches `remote.c`, `builtin/fetch.c`, and `builtin/remote.c`, with tests verifying edge cases like remotes with no tracked branches. Junio Hamano, the maintainer, has reviewed earlier versions and identified design concerns that have since been resolved, but his response to the precedence rule in Patch 1/4 remains the sole blocker for merging. Phillip Wood and D. Ben Knoble have contributed to the design discussion, but their positions on the latest implementation are not yet stated. The series is otherwise uncontroversial and ready for queuing once Junio responds.
