Thread identity
Subject: `reference-transaction` hook omits new ref on branch rename (`git branch -m`)
Series version: v1 (standalone patch)
Originating author: Maciej Ciemborowicz
Thread type: bug report and fix

Core problem or goal
The `reference-transaction` hook must report every ref change in a transaction, but when a branch is renamed (`git branch -m`), the hook only receives the deletion of the old branch name, not the creation of the new one. Both the files-based and reftable backends are affected, with the reftable backend omitting any usable rename payload entirely. The expected behavior—confirmed via `git update-ref --stdin`—is that both deletion and creation events are included in the same transaction.

Current status
Patch v1 posted. The fix introduces a new transaction type (`REF_TRANSACTION_TYPE_RENAME`/`COPY`) and a `REF_TRANSACTION_FLAG_SKIP_HOOK` flag to ensure that branch rename and copy operations are reported as a single logical transaction to the hook. Both backends are updated to use the new mechanism, preserving backend-specific reflog handling while unifying hook visibility. The patch includes thorough test coverage for rename, copy, forced updates, D/F conflicts, concurrent updates, and hook-triggered rollback.
