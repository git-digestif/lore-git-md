Thread identity
Subject: `reference-transaction` hook omits new ref on branch rename (`git branch -m`)
Series version: standalone bug report (no patch series)
Originating author: Maciej Ciemborowicz
Thread type: bug report

Core problem or goal
The `reference-transaction` hook is expected to report every ref change in a transaction, but when a branch is renamed (`git branch -m`), the hook only receives the deletion of the old branch name, not the creation of the new one. This affects both the files-based and reftable backends, although the reftable backend exhibits a more severe failure by omitting any usable rename payload. The expected behavior—confirmed via `git update-ref --stdin`—is that both the deletion and creation events should be included in the same transaction.

Current status
Under review. No patch yet; the report is the first message in the thread. The reproducer script and compatibility test suite demonstrate the issue across Git versions 2.28 through 2.55.

- Commands: `git branch -m`, `git update-ref --stdin`

- Test coverage: minimal reproducer script provided; linked to `git-hooks-ext` compatibility test suite
- Backwards compatibility: issue present since at least Git 2.28; no on-disk format changes
