This is a **platform compatibility / user experience bug report** about Git's pager environment handling. The author describes a longstanding but surprising interaction where Git's automatic `LESS=FRX` environment variable injection affects not only direct invocations of `less` but also custom pagers (like `delta`) that internally chain to `less`. This leads to unintended behavior—such as broken terminal alternate-screen handling and disrupted keybindings—when users configure `core.pager` to a wrapper tool rather than `less` directly.

The issue arises because Git unconditionally sets `LESS=FRX` when `LESS` is unset, even if the user's `core.pager` is a third-party tool (e.g., `delta`) that later invokes `less`. The behavior differs subtly between `unset LESS` (Git injects `FRX`) and `LESS=""` (Git leaves the environment alone), which the author finds unintuitive. While the default is documented and historically justified for direct `less` usage, its application to arbitrary pager wrappers feels like an implementation leak, silently altering the behavior of tools Git doesn’t directly control.

The author isn’t proposing a specific patch yet but suggests reconsidering whether the automatic `LESS` default should be scoped more narrowly—perhaps limited to Git’s own default pager path or made suppressible via configuration. They note that the current behavior is difficult to diagnose and creates a sharp edge for users of pager wrappers. The workaround (explicitly setting `LESS` in the shell) is straightforward but doesn’t address the underlying design question.
