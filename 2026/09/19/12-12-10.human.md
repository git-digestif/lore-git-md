This is the first patch in a four-part CI/build system series from Johannes Schindelin that fixes GitLab CI breakage for Windows builds after Rust support was enabled. The series targets the GitLab CI pipeline's MinGW-based Windows jobs, which broke when Rust was introduced.

This patch adjusts the dependency installation script (`ci/install-dependencies.ps1`) to provision the GNU Rust toolchain for MinGW builds, rather than the default MSVC toolchain. The change is straightforward: it adds a `-Mingw` switch to the script, uses it to select the appropriate Rust target (`gnu` for MinGW, `msvc` otherwise), and skips the Git and Meson installations for MinGW builds since the Git for Windows SDK already provides them. The existing Rust installation logic for MSVC builds remains unchanged.

The patch is narrowly scoped to CI infrastructure and does not affect Git's core functionality. It looks like a clean, mechanical adjustment to environment setup, though the commit message could be clearer about why the GNU Rust toolchain is specifically needed for MinGW builds (e.g., linker compatibility). The change is well-explained in the context of the series' goal to restore CI functionality, and the code itself is easy to follow.

No review feedback has appeared yet, but this patch is likely uncontroversial given its limited scope. The series as a whole is still "lightly tested" due to GitLab CI build minute constraints, so expect follow-up discussion about validation in the full CI environment. For now, this patch appears to be a sensible step toward fixing the breakage.
