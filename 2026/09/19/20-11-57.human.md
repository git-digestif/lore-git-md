This is the second patch in Maciej Ciemborowicz’s three-patch bugfix series that restores the old OID reporting in the reference-transaction hook when branches or tags are deleted in bulk. The regression, introduced in Git 2.31 by commit `8198907795`, caused the hook to receive all-zero OIDs for both old and new values, breaking external tools like Gerrit and GitLab that rely on the hook to monitor ref changes.

The patch updates `` `git branch` `` and `` `git tag` `` to pass the already-resolved old OIDs to the new `old_oid` parameter in `refs_delete_refs()`, ensuring the hook receives the correct old OID without any additional ref reads. The changes are minimal and focused: both commands already resolve the old OIDs before deletion, so the patch simply collects and forwards them. Test coverage is thorough, adding a new test in `t/t1416-ref-transaction-hooks.sh` that verifies the hook receives the expected old OIDs for both branches and tags, including packed refs.

This looks like a clean, well-scoped fix. The patch preserves the performance gains of the original optimization (bulk tag deletion remains at ~0.85 seconds for 10,000 tags) while restoring the pre-regression behavior. The commit message and test coverage suggest the author has considered edge cases, and the changes are backward-compatible. No controversy is evident—this appears to be a straightforward correction of an unintended behavioral change. The final patch in the series will address `` `git fetch --prune` `` and `` `git remote prune` ``.
