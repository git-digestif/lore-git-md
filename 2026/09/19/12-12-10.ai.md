This is the first patch in a CI/build system series fixing GitLab CI breakage for Windows builds after Rust support was enabled. The patch adjusts the dependency installation script (`ci/install-dependencies.ps1`) to provision the GNU Rust toolchain for MinGW-based builds, which is required for the Git for Windows SDK environment.

The change introduces a new `-Mingw` switch parameter to the PowerShell script, allowing it to distinguish between MinGW and MSVC build configurations. When the switch is set, the script installs the `gnu` Rust target (instead of the default `msvc`) and skips the Git and Meson installations, which are already provided by the Git for Windows SDK. The existing Rust installation logic is preserved for MSVC builds.

The patch is narrowly scoped to CI infrastructure and does not affect Git's core functionality. It addresses a specific breakage in GitLab's Windows CI jobs by ensuring the correct Rust toolchain is available for MinGW builds. The commit message is clear about the motivation (avoiding redundant Git/Meson installations and providing GNU Rust support), though it does not detail the exact nature of the CI breakage (e.g., build errors or test failures).

Key technical details for follow-up discussion include the `-Mingw` switch, the `gnu` Rust target, and the `ci/install-dependencies.ps1` script.
