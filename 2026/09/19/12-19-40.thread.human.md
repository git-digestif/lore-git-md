This thread began when Francisco Boni reported that Git’s automatic injection of `LESS=FRX` into the environment—whenever the `LESS` variable is unset—creates sharp edges for users of third-party pager wrappers like `delta`. The behavior, while documented and historically justified for direct `less` usage, feels like an implementation leak when applied to tools Git does not directly control, causing unintended side effects such as broken alternate-screen handling and disrupted keybindings.

The discussion has now settled into a documentation-focused phase. **brian m. carlson** firmly rejected reconsidering the current behavior, citing cross-platform consistency (notably FreeBSD’s `more`, which is actually `less`) and the impracticality of statically detecting `less` usage in arbitrary shell commands specified via `core.pager`. Francisco Boni has accepted this rationale, conceding the compatibility constraints and expressing appreciation for the existing `LESS="" delta` workaround. With no further push for a code change, the thread’s remaining actionable item is **Todd Zullinger’s proposed documentation patch**, which aims to clarify the `LESS=""` workaround in `Documentation/config/core.adoc`. The patch is uncontroversial in principle but adds verbiage to an already lengthy document, leaving open the question of whether additional documentation venues (e.g., release notes or the `git-config` man page) might also benefit from emphasizing the behavior and workarounds.
