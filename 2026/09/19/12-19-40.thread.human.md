This thread is about a longstanding but subtle user-experience issue in Git’s pager handling. Francisco Boni reports that Git’s automatic injection of `LESS=FRX` into the environment—intended to improve the default `less` pager experience—unintentionally disrupts third-party pager tools like `delta` or `bat` that internally chain to `less`. The problem arises because Git sets this variable unconditionally when `LESS` is unset, even if the user’s `core.pager` is a wrapper script rather than `less` itself. This leads to broken terminal behavior (e.g., alternate-screen handling or keybindings) and is difficult to diagnose, as the behavior differs depending on whether `LESS` is unset or set to an empty string.

The report is well-documented, with clear reproduction steps and a thoughtful analysis of the trade-offs. While the current behavior is documented and historically justified for direct `less` usage, the author argues it feels like an implementation leak when applied to arbitrary pager wrappers. No specific patch has been proposed yet, but the discussion could lead to a small but meaningful UX improvement, such as scoping the `LESS=FRX` default more narrowly (e.g., only for Git’s default pager) or making it suppressible via configuration. The thread is likely to attract contributors interested in Git’s CLI ergonomics or environment handling. So far, no responses or decisions have been made.
