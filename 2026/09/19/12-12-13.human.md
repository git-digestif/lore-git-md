This is the fourth and final patch in a CI/build system series from Johannes Schindelin, fixing GitLab CI breakage for Windows builds after Rust support was enabled. The series targets GitLab’s MinGW-based Windows jobs, which broke due to missing Rust toolchain components (`cargo` and GNU Rust’s host-linker support) and a silent data loss issue in dependency setup.

This specific patch addresses the linker problem: GitLab’s MinGW job fails to find `x86_64-w64-mingw32-gcc` when Cargo attempts to link `build.rs` as a host executable. The fix adds the `Gcc` feature to the Rust MSI installer’s `ADDLOCAL` parameter when the `-Mingw` switch is active, ensuring the GNU Rust toolchain includes the necessary linker and platform libraries. The change is minimal—just one line in `ci/install-dependencies.ps1`—and preserves the existing behavior for MSVC builds.

The patch is well-motivated and narrowly scoped, addressing a clear technical gap in the Rust toolchain setup for MinGW. The commit message provides useful context, linking to the failing CI job and the Rust MSI installer’s source code to explain why the `Gcc` feature is needed. This is a practical fix rather than a speculative change, and it aligns with the series’ goal of restoring CI functionality without altering Git’s core behavior.

No review feedback has been posted yet, but the patch looks uncontroversial. The only open question is whether the series as a whole will receive enough CI validation—Johannes noted the patches are "lightly tested" due to limited GitLab CI build minutes. If the fix works as intended, it should be a straightforward merge to resolve the Windows CI breakage.
