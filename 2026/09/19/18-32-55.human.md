This is a bugfix patch reporting a regression in `git reflog expire` that swapped the default expiry times for reachable and unreachable reflog entries.

The author, r.norouzi, demonstrates that since Git 2.50, `git reflog expire` incorrectly prunes reachable reflog entries after 30 days instead of the documented 90 days. The commit message traces the issue to 85658275702b, which moved the default expiry values from `builtin/reflog.c` to `reflog.h` but swapped the assignments: `.default_expire_total` (for reachable entries) was set to 30 days, while `.default_expire_unreachable` was set to 90 days. The patch includes a minimal reproduction case showing the bug in action.

The fix is straightforward: the values in `reflog.h` need to be restored to their original order. The patch is well-motivated, includes a clear test case, and pinpoints the exact commit that introduced the regression. This looks like a genuine, user-visible bug that should be addressed promptly.
