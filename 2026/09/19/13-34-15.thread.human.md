This thread is about a regression in Git’s reference-transaction hook that broke external tools like Gerrit and GitLab by reporting all-zero object IDs when branches or tags were deleted. The issue, introduced in Git 2.31, affected commands like `git branch -d`, `git tag -d`, `git remote prune`, and `git fetch --prune`, though `git update-ref -d` remained unaffected. Maciej Ciemborowicz identified the root cause—a performance optimization that inadvertently dropped the old OID—and posted a three-patch series to restore the pre-regression behavior.

After five iterations, the series is now technically complete and ready for merging. Key feedback from Junio Hamano (the maintainer) and Karthik Nayak was addressed, including a critical design flaw that turned deletions into all-or-nothing operations and a build-breakage issue in v4. The fix uses `REF_TRANSACTION_ALLOW_FAILURE` to preserve unconditional deletion while enabling granular error reporting, resolving the core conflict. Junio’s latest email confirms the series builds cleanly at every step and is ready for integration into `next`. The regression, which persisted through Git 2.55, is now fully resolved with no loose ends.
