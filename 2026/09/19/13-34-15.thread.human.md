This thread is about a regression in Git’s reference-transaction hook that broke external tools like Gerrit and GitLab by reporting all-zero object IDs when branches or tags are deleted. The issue, introduced in Git 2.31, affects commands like `git branch -d`, `git tag -d`, `git remote prune`, and `git fetch --prune`, but not `git update-ref -d`. Maciej Ciemborowicz identified the root cause—a performance optimization that inadvertently dropped the old OID—and has posted a three-patch v5 series to restore the pre-regression behavior while preserving the original speedup.

The v5 series is now complete and ready for merging. All feedback from prior versions has been addressed, including Junio’s request for granular error reporting and Karthik Nayak’s concerns about API consistency and design conflicts. The final patch, just posted, ensures `git fetch --prune` and `git remote prune` correctly pass the old OID to the hook and maintain user-facing consistency when some refs fail due to concurrent updates. Tests cover both files and reftable backends, SHA-1/SHA-256, and edge cases like broken refs and atomic pruning. The series builds cleanly, passes all tests, and is rebased onto the latest `master`.
