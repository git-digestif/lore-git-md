This thread is about a regression in Git’s reference-transaction hook, where deleting branches or tags via commands like `git branch -d` or `git tag -d` causes the hook to receive all-zero object IDs instead of the correct old OID. This breaks external tools (Gerrit, GitLab, CI systems) that rely on the hook to monitor ref changes. The regression, introduced in Git 2.31, persists through Git 2.55 and affects both the files and reftable backends.

Maciej Ciemborowicz posted a v6 bugfix patch that moves the fix into the transaction hook layer, addressing architectural concerns raised by Patrick Steinhardt and Junio C Hamano. The patch is technically sound, well-documented, and includes thorough test coverage, but it has received no review activity for a month. Junio C Hamano has now warned that unless reviewers step up in the next few weeks, he will drop the topic from his integration branches (`seen`). This is a procedural heads-up rather than a technical critique—the patch remains a strong candidate for merging, but the lack of engagement risks it being discarded.

Key participants include Maciej (the author), Patrick Steinhardt (who endorsed the v6 approach as architecturally sound), and Junio (who merged earlier versions to `next` but now flags the lack of reviews). The patch resolves the regression for all ref-modifying commands while preserving the performance gains of the original optimization. If no reviews materialize, the topic will likely need a resend to regain visibility.
