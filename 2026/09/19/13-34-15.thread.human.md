This thread began when Maciej Ciemborowicz reported a regression in Git 2.31 where the reference-transaction hook started receiving all-zero object IDs when branches or tags were deleted via high-level commands like `git branch -d` or `git tag -d`. This broke external tools (Gerrit, GitLab, CI systems) that rely on the hook to monitor ref changes. The regression was introduced by a performance optimization that replaced `delete_ref()` with `delete_refs()` but omitted the old OID for safety-checked deletions.

Maciej posted a v6 patch that moved the fix into the transaction hook layer itself, resolving old OIDs on demand and storing them in separate fields that don’t influence transaction safety checks. This addressed architectural concerns raised by Patrick Steinhardt and Junio C Hamano, preserved the bulk-deletion performance gains, and fixed all ref-modifying commands—not just the ones addressed in earlier versions. The patch was well-documented, passed tests, and aligned with prior feedback, but it received no review activity for a full month. Junio warned that unless reviewers stepped up, he would drop the topic from his `seen` branch.

In the final email, Maciej acknowledged the lack of engagement and conceded the patch may not progress further. While the patch remains technically sound and ready for merging, the thread is now effectively closed due to inactivity. The regression persists in Git 2.55, and the patch would need to be resent to regain visibility if interest resumes. Maciej has shifted focus to a related issue (branch renaming), but the v6 patch remains a strong candidate for merging if the project revisits the topic.
