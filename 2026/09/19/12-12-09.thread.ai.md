Subject: [PATCH 0/4] Fix GitLab CI breakage after Rust enabled for Windows
Series version: v1 (initial submission)
Originating author: Johannes Schindelin (Dscho)
Thread type: patch series (CI/build system fix)

Core problem or goal
Restore GitLab CI pipeline functionality for Windows builds after Rust support was enabled. The breakage is specific to GitLab's MinGW-based Windows jobs and involves Rust toolchain provisioning (`cargo`) and GNU Rust host-linker support. The series targets CI infrastructure only, with no changes to Git's core behavior or user-facing features. The exact nature of the breakage includes: (1) build failures due to missing Rust toolchain (`cargo: command not found` error) after the minimal SDK's login profile resets `PATH`, (2) silent data loss in dependency setup (clobbering `.git/info/exclude` entries added by `install-sdk.ps1`), and (3) linker unavailability (`x86_64-w64-mingw32-gcc` not found) during linking of `gitcore`'s build script, caused by Cargo's requirement for the GNU MSI's `Gcc` feature.

Current status
Under review; v1 posted. No prior versions. Based on commit `d338352cd43ab9745686d697872408bc3249a153f`. Submitted via GitGitGadget as PR #2233. Karthik Nayak has set up an internal GitLab merge request (MR #671) and pipeline (#2863888081) to validate the series in the same CI environment where the breakage occurred. The `build:mingw64` job in the pipeline now succeeds, confirming the fix resolves the primary breakage. Johannes Schindelin notes the job name may be outdated (`ucrt64` would be more accurate) but this is cosmetic. An unrelated timeout in the `build:msvc-meson` job (stuck on credential handling) was observed but does not affect the series' core fix. No maintainer decision on integration status; no technical objections raised.

Key technical details
Files touched: `.gitlab-ci.yml`, `ci/install-dependencies.ps1`
Subsystems: GitLab CI, Windows MinGW build environment
New/renamed symbols: none (CI script adjustments only)
Behavior changes: none to Git itself; restores CI build pipeline for Windows jobs by:
1. Ensuring the correct Rust toolchain (`gnu` target) is provisioned for MinGW builds via a new `-Mingw` switch in `ci/install-dependencies.ps1`.
2. Preserving existing `.git/info/exclude` contents when creating the file, preventing silent data loss of `/git-sdk` entries added by `install-sdk.ps1`.
3. Explicitly adding `/c/Rust/bin` to `PATH` in `.gitlab-ci.yml` to ensure `cargo` is accessible after the minimal SDK's login profile resets it.
4. Including the `Gcc` feature (`ADDLOCAL=Rustc,Cargo,Std,Gcc`) in the Rust MSI installation when the `-Mingw` switch is used, ensuring the GNU linker (`x86_64-w64-mingw32-gcc`) is available for host executables like `build.rs`.
On-disk format: n/a
Test coverage: none (CI infrastructure change; testing relies on GitLab CI pipeline execution). Karthik Nayak's internal GitLab MR (#671) and pipeline (#2863888081) provide validation; the `build:mingw64` job now succeeds, confirming the fix.
