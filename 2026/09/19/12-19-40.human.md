This is a usability bug report about Git’s pager environment handling.

Francisco Boni describes a long-standing but surprising interaction: when the environment variable `LESS` is unset, Git automatically injects `LESS=FRX` into the environment of the pager process. This default is meant to provide sane behavior when Git directly invokes `less`, but it also affects custom pagers like `delta` that internally invoke `less` themselves. The result is that users who configure `core.pager = delta` and rely on delta’s own pager flags find their terminal behavior unexpectedly altered—alternate screen mode is disabled, and Page Up / Page Down keys stop working normally.

The report is clear and well-motivated. It identifies the root cause (Git’s automatic `LESS=FRX` injection), demonstrates the unintuitive distinction between `unset LESS` and `LESS=""`, and shows how the injected flags silently override the user’s intended pager configuration. While the behavior is documented and long-standing, the interaction with pager wrappers feels like a leaky abstraction. The author is not demanding an immediate change but suggests revisiting whether the default should apply only to Git’s own default pager path or be made suppressible via configuration.

This is a real, diagnosable issue that will resonate with users of custom pagers. It looks like a good candidate for discussion and eventual refinement.
