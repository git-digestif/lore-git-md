This is a bug report about the reference-transaction hook missing the destination ref when renaming a branch with `git branch -m`.

Maciej Ciemborowicz reports that when running `git branch -m old new`, the reference-transaction hook only shows the deletion of `refs/heads/old` (in the files backend) or nothing at all (in the reftable backend), but never the creation of `refs/heads/new`. The expected behavior would be for the hook to report both the deletion of the old ref and the creation of the new one, similar to how `git update-ref --stdin` correctly reports both updates.

The report includes a minimal reproducer script that demonstrates the issue across both ref backends (files and reftable) and confirms the behavior is consistent from Git 2.28 through 2.55. The script sets up a temporary repository, configures the hook, and shows that the hook log only contains the deletion event. The author also links to a compatibility test suite that verifies this behavior across versions.

This looks like a well-documented and reproducible issue affecting a core Git hook. The missing destination ref in the transaction could break tools that rely on the hook to track branch renames, making this a potentially impactful bug for users who depend on reference-transaction for automation or auditing. The fact that `update-ref` handles it correctly suggests the fix might be straightforward.
