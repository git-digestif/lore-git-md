This thread is about fixing GitLab CI breakage for Windows builds after Rust support was enabled. Johannes Schindelin (Dscho) sent a v2 patch series addressing the original issues, which included Rust toolchain provisioning problems, GNU Rust host-linker support, and a subtle data loss bug in `.git/info/exclude`. The series is narrowly focused on CI infrastructure and doesn’t change Git’s core behavior.

The second patch in the series fixes a silent data loss issue where `.git/info/exclude` was being truncated during dependency setup, discarding exclusions added by `install-sdk.ps1` (like `/git-sdk`). The fix is simple: it checks for the file’s existence before creating it, preserving any existing contents. This change is minimal and well-justified, preventing CI failures by ensuring SDK exclusions remain intact. No substantive review feedback has been raised against this patch, suggesting it’s uncontroversial.

The series as a whole is under review, with v2 improving commit message clarity but making no technical changes from v1. Karthik Nayak validated the fix in GitLab’s CI environment, confirming both `build:mingw64` and `build:msvc-meson` jobs now succeed. Patrick Steinhardt’s earlier questions about the "GNU Rust" toolchain and the `Gcc` feature in Rust’s MSI installer were resolved by Schindelin’s explanations. The series is ready for integration, though Junio hasn’t yet commented on its status. An unrelated GitLab Runner regression (credential-clearing timeout) remains unresolved but doesn’t affect the series’ validity.
