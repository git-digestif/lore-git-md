This thread is about fixing GitLab CI breakage for Windows builds after Rust support was enabled. Johannes Schindelin (Dscho) sent a four-patch series (now at v2) that restores the pipeline by addressing Rust toolchain provisioning, linker compatibility, and a silent data loss issue in `.git/info/exclude`. The series touches only CI scripts (`.gitlab-ci.yml` and `ci/install-dependencies.ps1`) and has no impact on Git’s core behavior.

The v2 iteration reworded commit messages for clarity but made no technical changes from v1. Karthik Nayak validated the fix in GitLab’s internal CI, confirming both MinGW and MSVC jobs now succeed. Patrick Steinhardt’s earlier questions about the "GNU Rust" toolchain and the `Gcc` feature in Rust’s MSI installer were resolved—these were about ensuring GCC-compatible output and linker availability, not redundant toolchains. The latest exchange with Patrick clarified minor script organization and shell syntax points, but no objections remain. The series is complete and ready for maintainer review, though Junio hasn’t yet weighed in on integration.

A separate GitLab Runner regression (credential-clearing timeouts) remains unresolved but doesn’t affect this fix. Dscho also noted the `build:mingw64` job name might be outdated, though this is cosmetic. The only open question is whether Rust might eventually be included in the Git for Windows SDK, but this is forward-looking and doesn’t block the current series.
