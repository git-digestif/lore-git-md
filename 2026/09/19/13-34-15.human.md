This is a bug report about the reference-transaction hook. Since Git 2.31, the hook receives all-zero object IDs when a branch or tag is deleted via high-level commands like `git branch -d` or `git tag -d`, instead of the previous behavior where the old object ID was provided. The regression affects both the files and reftable backends and persists through Git 2.55.

The report includes a minimal reproducer demonstrating the issue: deletions via `git branch -d` or `git tag -d` now emit zero OIDs for both old and new values, while direct deletions via `git update-ref -d` still correctly report the old OID followed by zeros. The author questions whether this change was intentional and suggests either restoring the old behavior or updating the documentation to clarify the current behavior.

The report is well-structured, with clear reproduction steps, expected vs. actual output, and a link to additional compatibility testing. The issue appears to be a real regression that could impact users relying on the hook for accurate ref deletion tracking. No prior discussion or replies are mentioned in the thread context.
