Thread identity
Subject: Git’s automatic LESS=FRX injection affects custom pagers (delta, etc.)
Series version: N/A (bug report / RFC discussion, now documentation-only)
Originating author: Francisco Boni
Thread type: platform-compatibility / user-experience bug report

Core problem or goal
Git unconditionally injects `LESS=FRX` into the environment whenever `LESS` is unset, even when the user’s `core.pager` is a third-party wrapper (e.g., delta) that internally chains to less. This causes unintended side effects—broken alternate-screen handling, disrupted keybindings, and inconsistent behavior between unset `LESS` (Git injects FRX) and `LESS=""` (Git leaves the environment alone). The report argues that this behavior, while documented and historically justified for direct less usage, feels like an implementation leak when applied to tools Git does not directly control.

The patch is uncontroversial and is expected to graduate to `master` after integration testing. No further discussion or objections are anticipated.

Key technical details
- Configuration key: `core.pager`
- Environment variable: `LESS` (defaults to `FRX` when *unset*, not when empty)
- Affected tools: any pager wrapper that internally invokes `less` (e.g., delta, bat)
- Cross-platform edge cases: FreeBSD’s `more` (which is actually `less`), Debian’s `sensible-pager`, and arbitrary shell commands in `core.pager` that may dynamically resolve to `less`
- Workarounds: users can override the default by setting `GIT_PAGER` or `core.pager` to explicitly clear `LESS` (e.g., `LESS="" delta` or `LESS="RX" delta`) or use `env -i` to sanitize the environment. The documentation patch clarifies these workarounds, including the distinction between `LESS=""` (clears all options) and `LESS="RX"` (selectively overrides), and provides examples for per-command pager configurations (e.g., `pager.blame`).
- On-disk or CLI changes: none; purely environment-handling logic and documentation
- Test coverage: none; reproduction steps provided in the original report
