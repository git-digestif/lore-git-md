This thread is about a regression in `git reflog expire` that was introduced in Git 2.50. The bug report, sent by r.norouzi, explains that the default expiry times for reachable and unreachable reflog entries were accidentally swapped in a recent commit. As a result, reachable entries (which should default to 90 days) are expiring after 30 days, while unreachable entries (which should default to 30 days) are being kept for 90 days.

The issue is well-documented, with a clear reproduction case showing that a 60-day-old reachable reflog entry is incorrectly pruned. The root cause is a misordering of fields in `reflog.h`, where `.default_expire_total` and `.default_expire_unreachable` were reversed compared to the pre-2.50 implementation. This affects all platforms, as the bug is in core Git logic.

No patch has been submitted yet—this is purely a bug report—but the regression is straightforward and likely uncontroversial to fix. The next step will be for a contributor to submit a patch restoring the intended defaults. Since the issue is a clear documentation mismatch with a minimal test case, it should be resolved quickly once addressed.
