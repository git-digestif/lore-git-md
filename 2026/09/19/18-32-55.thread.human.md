This thread is about a regression in Git 2.50 that swapped the default expiry times for reachable and unreachable reflog entries in `git reflog expire`. The bug, introduced by commit `85658275702b` in April 2025, caused reachable entries (documented to expire after 90 days) to expire after 30 days, while unreachable entries (documented to expire after 30 days) were incorrectly retained for 90 days.

Pushkar Singh posted a fix that restores the correct default expiry periods and adds a regression test. Junio C Hamano reviewed the patch and requested improvements to the commit message (to clarify when and why the regression was introduced) and to the test coverage (to verify both reachable and unreachable expiry behavior). Jeff King (Peff) chimed in to reinforce Junio’s feedback, confirming the regression’s origin and emphasizing the need for clearer context in the commit message. The fix itself remains uncontroversial and narrowly targeted, touching only the misordered defaults in `reflog.h` without altering other logic or on-disk formats.

The patch is still under review, awaiting a v2 from Pushkar Singh that incorporates the requested changes. One loose end remains: whether the regression affects `git gc` (which calls `reflog expire` internally) hasn’t been addressed in the thread. For now, the focus is on polishing the commit message and test coverage before the fix can be merged.
