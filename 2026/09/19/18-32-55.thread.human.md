This thread is about a regression in Git 2.50 that swapped the default expiry times for reachable and unreachable reflog entries in `git reflog expire`. The bug, introduced in April 2025, went unnoticed for over a year until reported by r.norouzi and fixed by Pushkar Singh. The fix, which restores the correct defaults (reachable entries expire after 90 days, unreachable after 30 days), was merged to `master` on June 12, 2025, with no further changes expected.

The regression was caused by a field-order swap in `reflog.h` during a refactoring commit, and the fix included expanded test coverage to verify both reachable and unreachable expiry behavior. While the bug affected `git reflog expire` and `git gc`, its real-world impact appears low, as no users reported issues during the year it was present. Reviewers—including Junio C Hamano, Jeff King, and Patrick Steinhardt—agreed the patch was minimal, targeted, and ready for merging, though Patrick initially suggested fast-tracking it for Git 2.56 before aligning with the consensus that it wasn’t urgent.

The only remaining discussion is a minor post-merge nitpick about test precision: Patrick suggested tightening the test thresholds to 89/90 days (reachable) and 29/30 days (unreachable) for boundary accuracy, but Junio countered that the current values (60/100 and 20/40 days) better avoid edge-case ambiguity in `approxidate()` while still verifying the core logic. This exchange is purely about test hygiene and doesn’t affect the fix itself. The thread is now resolved.
