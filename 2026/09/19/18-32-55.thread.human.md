This thread is about a regression in Git 2.50 that swapped the default expiry times for reachable and unreachable reflog entries in `git reflog expire`. Reachable entries, which should default to 90 days, were incorrectly expiring after 30 days, while unreachable entries (documented to default to 30 days) were being retained for 90 days. The bug was introduced in April 2025 by a commit that reversed the order of two fields in `reflog.h`.

Pushkar Singh posted a fix (now at v3) that restores the correct defaults and adds thorough test coverage. The patch is minimal, uncontroversial, and ready for merging. All review feedback—from Junio C Hamano, Jeff King (Peff), and Patrick Steinhardt—has been addressed, including requests for clearer commit messages and more symmetric test cases. Junio noted that the regression went unnoticed for over a year, suggesting low real-world impact, but does not object to merging the fix for Git 2.56. The only remaining question is whether Junio will include it in this cycle or defer it to the next one. The fix affects both `git reflog expire` and `git gc`, which calls it internally.
