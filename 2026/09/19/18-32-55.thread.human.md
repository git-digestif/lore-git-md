This thread is about a regression in Git 2.50 that swapped the default expiry times for reachable and unreachable reflog entries in `git reflog expire`. The bug, introduced in April 2025, went unnoticed for over a year, suggesting it had little real-world impact. Reachable entries (documented to default to 90 days) were incorrectly expiring after 30 days, while unreachable entries (documented to default to 30 days) were being retained for 90 days.

The fix, authored by Pushkar Singh and now in its third version, has been merged to `master` by Junio C Hamano. It restores the correct default expiry periods and adds comprehensive test coverage to prevent regression. The patch is minimal, uncontroversial, and addresses all prior review feedback, including clearer commit messaging and expanded test cases. Junio explicitly approved the patch as "looks very good" and ready for merging, with no further iteration expected. A minor post-merge cleanup suggestion was noted but deemed outside the scope of this patch.

Key participants include the original reporter (r.norouzi), the patch author (Pushkar Singh), and reviewers Junio C Hamano and Jeff King (Peff). All agreed the fix is low-risk and ready for integration. The regression affected both `git reflog expire` and `git gc`, but with no reported user complaints, the urgency was low. The fix is now complete and part of the upcoming Git release.
