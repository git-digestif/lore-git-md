This thread is about a regression in Git 2.50 that swapped the default expiry times for reachable and unreachable reflog entries in `git reflog expire`. The bug, introduced by commit `85658275702b` in April 2025, caused reachable entries (documented to expire after 90 days) to expire after 30 days, while unreachable entries (documented to expire after 30 days) were incorrectly retained for 90 days.

The fix, now in its second version by Pushkar Singh, has addressed all prior review feedback from Junio C Hamano and Jeff King. It restores the correct default expiry periods (reachable=90 days, unreachable=30 days) and includes comprehensive test coverage to verify both reachable and unreachable expiry behavior. The patch touches `reflog.h`, `builtin/reflog.c`, and adds tests in `t/t1410-reflog.sh`. The regression itself is purely logical—no on-disk format changes were involved.

The thread has seen no substantive objections, and the fix is considered ready for merging. The only remaining loose end is whether the regression affects `git gc`, which internally calls `reflog expire`, but this hasn’t been explored in the thread. Patrick Steinhardt’s recent reply was a surface-level acknowledgment, adding no new technical feedback. The fix remains uncontroversial and narrowly targeted.
