The `git reflog expire` regression introduced in Git 2.50 has been identified, fixed, and is now ready for merging. The bug swapped the default expiry times for reachable and unreachable reflog entries—reachable entries (documented to default to 90 days) were expiring after 30 days, while unreachable entries (documented to default to 30 days) were incorrectly retained for 90 days. The issue was traced to commit `85658275702b` (April 2025), which reversed the order of `.default_expire_total` and `.default_expire_unreachable` in `reflog.h`.

Pushkar Singh authored a targeted fix (v2) that restores the correct defaults and includes comprehensive test coverage in `t/t1410-reflog.sh`. The patch has been reviewed by Junio C Hamano, Jeff King (Peff), and Patrick Steinhardt, with all feedback addressed—including Junio’s earlier concern about test structure asymmetry. Peff called the fix "quite obvious and low-risk," and Patrick proposed fast-tracking it for Git 2.56 due to its urgency and user-visible impact (affecting both `git reflog expire` and `git gc`). Junio has now confirmed the intent to merge it promptly, resolving the only remaining question about timing. The fix is uncontroversial and narrowly scoped, touching only `reflog.h`, `builtin/reflog.c`, and the test suite. No further objections or loose ends remain.
