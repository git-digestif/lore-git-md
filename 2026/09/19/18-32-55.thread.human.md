**Human-readable summary**

This thread began with a bug report by r.norouzi: in Git 2.50, the default expiry times for `git reflog expire` were accidentally swapped, so reachable entries (meant to default to 90 days) were expiring after 30 days, while unreachable entries (meant to default to 30 days) were kept for 90 days. The root cause was a field-order mix-up in a cleanup commit from April 2025.

Pushkar Singh provided a fix that restored the correct defaults and added thorough test coverage. After three iterations—addressing review feedback on commit-message clarity and test structure—the patch was merged to `master` on 12 June 2025. Reviewers (Junio, Peff, and Patrick Steinhardt) agreed the regression had low real-world impact but was worth fixing for correctness. The merged version tests both reachable and unreachable reflog entries with 60/100-day and 20/40-day thresholds, respectively.

The only remaining discussion is post-merge: Patrick suggests tightening the test thresholds to 88/90 days for reachable entries to better reflect the intended 90-day policy, while Junio prefers the current looser values to avoid edge cases in Git’s date-parsing. Neither side sees this as a blocker, and no further code changes are planned.
