Thread identity
Subject: [PATCH 0/4] stash: fix autostash with staged index entries
Series version: v2 (posted, v3 expected)
Originating author: D. Ben Knoble
Thread type: patch series (bugfix)

Core problem or goal
Fix a bug in `git stash` where autostashing fails to correctly handle staged index entries when `stash.index=true` is set. The bug manifests during merge operations that trigger autostash, causing incorrect index state preservation due to a race condition in the subprocess-based logic (`git diff-tree` and `git apply`). The series replaces this with in-core merging via `merge-ort.c`, ensuring staged entries are properly preserved and eliminating the risk of SIGSEGV on conflicted index merges.

Current status
v2 posted and complete. Four patches: (1) cleanup (accepted by Junio C Hamano as a "no-brainer"), (2) refactor merge option initialization, (3) add test for conflicted index merges, (4) functional fix (refactor index merge logic in `builtin/stash.c` and `merge-ort.c`). Patch 1 is effectively merged to `master`. Patches 2-4 are under active review. Junio C Hamano identified a **critical correctness issue** in Patch 4: the order of tree arguments passed to `merge_incore_nonrecursive()` is likely backwards, causing the merge to apply the wrong change. A new test case (`t/t3903-stash.sh`) fails with the current patch but passes if the stash logic is reverted, confirming the issue. The fix is expected to be a one-line change swapping two arguments. Additionally, Phillip Wood’s prior feedback on Patch 4 (memory leak fix via `merge_finalize(&o, &result)` before returning on conflict) and Patch 3 (test robustness improvements: add `git diff-files -p` and `git diff-index --cached HEAD`) remains unresolved.

Key technical details
- Files touched: `builtin/stash.c`, `merge-ort.c`, `t/t3900-stash.sh`, `t/t3903-stash.sh`, `t/t7600-merge.sh`
- Subsystems: stash, merge-ort
- New/renamed symbols: None (internal refactoring only)
- Behavior change: Index state is now merged in-core during autostash, avoiding external process calls and eliminating a race condition that could corrupt the `MERGE_AUTOSTASH` ref. The patch standardizes on `init_ui_merge_options()` for both index and worktree merges, uses fixed ancestor/branch labels (e.g., `"stash"`, `"HEAD"`, `"Upstream index"`, `"Stashed index changes"`, `"Stash base"`), and employs `merge_finalize()` to ensure proper cleanup of the `merge_result` strmap. Verbosity is set to `0` to avoid minor overhead. The on-disk format is unchanged.
- Test coverage: Added test cases in `t/t3900-stash.sh` (conflicted index merges), `t/t3903-stash.sh` (graceful failure of `git stash apply --index` on conflicted index merges, preserving pre-merge state; now includes Junio’s new test case for unrelated staged changes), and `t/t7600-merge.sh` (bug scenario: staging a file before a fast-forward merge with `--autostash` and `stash.index=true`). Tests verify autostash application, stash list cleanup, and graceful failure (without SIGSEGV) if the index merge fails. Phillip Wood’s review identified gaps in the test’s verification logic: (1) `git diff-files` alone does not confirm that unstaged changes are identical before and after the failed stash apply, and (2) the test does not explicitly verify that the index state is preserved. Suggested improvements: add `git diff-files -p` and `git diff-index --cached HEAD`.

Open questions and loose ends
1. **Critical correctness issue**: The order of tree arguments in `merge_incore_nonrecursive()` in Patch 4 is likely backwards, causing the merge to apply the wrong change. Junio’s test case fails with the current patch, confirming the issue. The fix is a one-line change swapping two arguments.
2. **Memory leak**: Patch 4 must call `merge_finalize(&o, &result)` before returning on conflict to avoid unfreed allocations. The leak is isolated and does not affect correctness.
3. **Test robustness**: Patch 3 requires two improvements: (a) add `git diff-files -p` to compare the actual diff content of unstaged changes (not just filenames), and (b) add `git diff-index --cached HEAD` to explicitly verify index preservation.
4. **Cosmetic label naming**: Phillip Wood noted a minor quibble with the label `"Upstream index"` for the current index, but this is not worth a re-roll on its own.
