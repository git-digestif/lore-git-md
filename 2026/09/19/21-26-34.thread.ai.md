Subject: [PATCH 0/2] stash: fix autostash with staged index entries
Series version: v1 (initial submission)
Originating author: D. Ben Knoble
Thread type: patch series (bugfix)

Core problem or goal
Fix a bug in `git stash` where autostashing fails to correctly handle staged index entries when `stash.index=true` is set. The bug manifests during merge operations that trigger autostash, causing incorrect index state preservation due to a race condition in the subprocess-based logic (`git diff-tree` and `git apply`). The series replaces this with in-core merging via `merge-ort.c`, ensuring staged entries are properly preserved.

Current status
Under review (no prior versions). Two patches: (1) cleanup (remove unused `#include "oid-array.h"` from `builtin/stash.c`, uncontroversial), (2) functional fix (refactor index merge logic in `builtin/stash.c` and `merge-ort.c`, replacing 65 lines of subprocess calls with 23 lines of in-core merge logic; add test in `t/t7600-merge.sh`).

Key technical details
- Files touched: `builtin/stash.c`, `merge-ort.c`, `t/t7600-merge.sh`
- Subsystems: stash, merge-ort
- New/renamed symbols: None (internal refactoring only)
- Behavior change: Index state is now merged in-core during autostash, avoiding external process calls and eliminating a race condition that could corrupt the `MERGE_AUTOSTASH` ref. The patch uses the default diff algorithm for index merging, while the worktree merge uses the `_ui` variant, creating a potential behavioral mismatch.
- On-disk format: Unchanged
- Test coverage: Added test case in `t/t7600-merge.sh` covering the bug scenario (staging a file before a fast-forward merge with `--autostash` and `stash.index=true`), reported by Eli Barzilay. Test verifies autostash application and stash list cleanup but does not currently check for graceful failure on index merge errors.

Open questions and loose ends
- **Merge algorithm consistency**: Whether to standardize on the `_ui` variant for both index and worktree merges to avoid behavioral mismatches (raised by Phillip Wood).
- **Assertion safety**: The patch removes two `assert()` calls in `merge-ort.c` that guarded against NULL pointers (`opt->branch1`, `opt->branch2`, and `opt->ancestor`). These assertions were added in 2020 without explanatory context, and their removal risks crashes if the pointers are NULL (later dereferenced). Phillip Wood recommends adding fixed ancestor/branch names in `do_apply_stash()` to ensure safety and proposes a new test to verify graceful failure (without SIGSEGV) if the index merge fails.
- **Verbosity option**: The `verbosity` field in `merge_options` is unused by the ort strategy and could be dropped (raised by Phillip Wood).
- Bug impact not fully described in commit message (e.g., whether it causes data loss or merely incorrect behavior).
