Subject: [PATCH 0/4] stash: fix autostash with staged index entries
Series version: v2 (posted, v3 expected)
Originating author: D. Ben Knoble
Thread type: patch series (bugfix)

Core problem or goal
Fix a bug in `git stash` where autostashing fails to correctly handle staged index entries when `stash.index=true` is set. The bug manifests during merge operations that trigger autostash, causing incorrect index state preservation due to a race condition in the subprocess-based logic (`git diff-tree` and `git apply`). The series replaces this with in-core merging via `merge-ort.c`, ensuring staged entries are properly preserved and eliminating the risk of SIGSEGV on conflicted index merges.

Current status
v2 posted and complete. Four patches: (1) cleanup (remove unused `#include "oid-array.h"` from `builtin/stash.c`, accepted by Junio C Hamano as a "no-brainer"), (2) refactor merge option initialization to simplify later logic (moves `init_ui_merge_options()` call earlier in `do_apply_stash()` to prepare for in-core index merge; no behavior change), (3) add test for conflicted index merges, (4) functional fix (refactor index merge logic in `builtin/stash.c` and `merge-ort.c`, replacing 65 lines of subprocess calls with 23 lines of in-core merge logic). Patch 1 is effectively merged. Patches 2-4 are ready for integration but require two changes: (a) a trivial fix for a memory leak in Patch 4 (the `merge_result` struct must be finalized with `merge_finalize(&o, &result)` before returning on conflict to avoid unfreed allocations), and (b) test robustness improvements in Patch 3 (add `git diff-files -p` to compare unstaged change content and `git diff-index --cached HEAD` to explicitly verify index preservation). All other technical concerns raised by Phillip Wood—merge algorithm consistency, assertion safety, merge option lifecycle, verbosity settings, fixed labels, and graceful failure on conflicts—have been addressed.

Key technical details
- Files touched: `builtin/stash.c`, `merge-ort.c`, `t/t3900-stash.sh`, `t/t3903-stash.sh`, `t/t7600-merge.sh`
- Subsystems: stash, merge-ort
- New/renamed symbols: None (internal refactoring only)
- Behavior change: Index state is now merged in-core during autostash, avoiding external process calls and eliminating a race condition that could corrupt the `MERGE_AUTOSTASH` ref. The patch standardizes on `init_ui_merge_options()` for both index and worktree merges, uses fixed ancestor/branch labels (e.g., `"stash"`, `"HEAD"`, `"Upstream index"`, `"Stashed index changes"`, `"Stash base"`), and employs `merge_finalize()` to ensure proper cleanup of the `merge_result` strmap. Verbosity is set to `0` to avoid minor overhead. The on-disk format is unchanged.
- Test coverage: Added test cases in `t/t3900-stash.sh` (conflicted index merges), `t/t3903-stash.sh` (graceful failure of `git stash apply --index` on conflicted index merges, preserving pre-merge state), and `t/t7600-merge.sh` (bug scenario: staging a file before a fast-forward merge with `--autostash` and `stash.index=true`). Tests verify autostash application, stash list cleanup, and graceful failure (without SIGSEGV) if the index merge fails. Phillip Wood’s review identified two gaps in the test’s verification logic: (1) `git diff-files` alone does not confirm that unstaged changes are *identical* before and after the failed stash apply—only that the same files are modified—and (2) the test does not explicitly verify that the *index* state is preserved. Suggested improvements: add `git diff-files -p` to compare the actual diff content of unstaged changes, and add `git diff-index --cached HEAD` to explicitly check that the index is unchanged.

Open questions and loose ends
A memory leak in Patch 4 must be fixed before integration: `merge_finalize(&o, &result)` must be called before returning on conflict. The leak is isolated and does not affect correctness. Phillip Wood also noted a minor cosmetic label naming quibble (`"Upstream index"` for the current index), but this is not worth a re-roll on its own. The test robustness improvements (adding `git diff-files -p` and `git diff-index --cached HEAD`) are now the primary remaining action items. No other unresolved technical issues remain.
