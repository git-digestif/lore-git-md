Subject: [PATCH 0/4] stash: fix autostash with staged index entries
Series version: v2 (posted)
Originating author: D. Ben Knoble
Thread type: patch series (bugfix)

Core problem or goal
Fix a bug in `git stash` where autostashing fails to correctly handle staged index entries when `stash.index=true` is set. The bug manifests during merge operations that trigger autostash, causing incorrect index state preservation due to a race condition in the subprocess-based logic (`git diff-tree` and `git apply`). The series replaces this with in-core merging via `merge-ort.c`, ensuring staged entries are properly preserved and eliminating the risk of SIGSEGV on conflicted index merges.

All technical concerns raised by Phillip Wood—merge algorithm consistency, assertion safety, merge option lifecycle, verbosity settings, fixed labels, and graceful failure on conflicts—have been addressed. Key technical details
- Files touched: `builtin/stash.c`, `merge-ort.c`, `t/t3900-stash.sh`, `t/t7600-merge.sh`
- Subsystems: stash, merge-ort
- New/renamed symbols: None (internal refactoring only)
- Behavior change: Index state is now merged in-core during autostash, avoiding external process calls and eliminating a race condition that could corrupt the `MERGE_AUTOSTASH` ref. The patch standardizes on `init_ui_merge_options()` for both index and worktree merges, uses fixed ancestor/branch labels (e.g., `"stash"` and `"HEAD"`), and employs `merge_finalize()` to ensure proper cleanup of the `merge_result` strmap. Verbosity is set to `0` to avoid minor overhead. The on-disk format is unchanged.
- Test coverage: Added test cases in `t/t3900-stash.sh` (conflicted index merges) and `t/t7600-merge.sh` (bug scenario: staging a file before a fast-forward merge with `--autostash` and `stash.index=true`). Tests verify autostash application, stash list cleanup, and graceful failure (without SIGSEGV) if the index merge fails.
