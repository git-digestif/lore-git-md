Subject: [PATCH 0/4] stash: fix autostash with staged index entries
Series version: v3 (final, submitted)
Originating author: D. Ben Knoble
Thread type: patch series (bugfix)

Core problem or goal
Fix a bug in `git stash` where autostashing fails to correctly handle staged index entries when `stash.index=true` is set. The bug manifests during merge operations that trigger autostash, causing incorrect index state preservation due to a race condition in the subprocess-based logic (`git diff-tree` and `git apply`). The series replaces this with in-core merging via `merge-ort.c`, ensuring staged entries are properly preserved and eliminating the risk of SIGSEGV on conflicted index merges.

Current status
v3 has been submitted and is the final iteration. Four patches: (1) cleanup (merged to `master`), (2) refactor merge option initialization, (3) add test for conflicted index merges, (4) functional fix (refactor index merge logic in `builtin/stash.c` and `merge-ort.c`). The **critical correctness issue** identified by Junio C Hamano in Patch 4—backwards tree arguments in `merge_incore_nonrecursive()`—has been resolved by swapping `(head, merge, merge_base)` to `(merge_base, merge, head)`. Phillip Wood endorsed this fix, noting the error was masked in existing tests because "base" and "stage2" were identical, and recommended standardizing argument order across related merge functions (`merge_ort_nonrecursive` and `merge_incore_nonrecursive`) to avoid future confusion. The fix is confirmed by Junio’s test case, which the author included in the series as a preparatory patch with proper Signed-off-by attribution. The series is now technically sound and ready for integration. All follow-ups are resolved: (1) the memory leak in Patch 4 (add `merge_finalize(&o, &result)` before returning on conflict) has been confirmed and fixed in v3, (2) test robustness improvements in Patch 3 (add `git diff-files -p` and `git diff-index --cached HEAD` to verify unstaged changes and index preservation) are incorporated, and (3) inclusion of Junio’s test case with proper Signed-off-by is procedurally complete. The cosmetic label adjustment (`"Upstream index"` to a clearer alternative) is optional and not blocking.

Key technical details
- Files touched: `builtin/stash.c`, `merge-ort.c`, `t/t3900-stash.sh`, `t/t3903-stash.sh`, `t/t7600-merge.sh`
- Subsystems: stash, merge-ort
- New/renamed symbols: None (internal refactoring only)
- Behavior change: Index state is now merged in-core during autostash, avoiding external process calls and eliminating a race condition that could corrupt the `MERGE_AUTOSTASH` ref. The patch standardizes on `init_ui_merge_options()` for both index and worktree merges, uses fixed ancestor/branch labels (e.g., `"stash"`, `"HEAD"`, `"Upstream index"`, `"Stashed index changes"`, `"Stash base"`), and employs `merge_finalize()` to ensure proper cleanup of the `merge_result` strmap. Verbosity is set to `0` to avoid minor overhead. The on-disk format is unchanged. The tree argument order in `merge_incore_nonrecursive()` is now consistent with `merge_ort_nonrecursive()`, using `(merge_base, merge, head)`.
- Test coverage: Added test cases in `t/t3900-stash.sh` (conflicted index merges), `t/t3903-stash.sh` (graceful failure of `git stash apply --index` on conflicted index merges, preserving pre-merge state; includes Junio’s test case for unrelated staged changes), and `t/t7600-merge.sh` (bug scenario: staging a file before a fast-forward merge with `--autostash` and `stash.index=true`). Tests verify autostash application, stash list cleanup, and graceful failure (without SIGSEGV) if the index merge fails. Phillip Wood’s review confirmed the test’s verification logic is now robust: (1) `git diff-files -p` compares actual diff content of unstaged changes, and (2) `git diff-index --cached HEAD` explicitly verifies index preservation (with a `sed` filter to simplify patch output comparison).
