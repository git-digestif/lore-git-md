Core problem or goal
Fix a bug in `git stash` where autostashing fails to correctly handle staged index entries when `stash.index=true` is set. The bug manifests during merge operations that trigger autostash, causing incorrect index state preservation due to a race condition in the subprocess-based logic (`git diff-tree` and `git apply`). The series replaces this with in-core merging via `merge-ort.c`, ensuring staged entries are properly preserved and eliminating the risk of SIGSEGV on conflicted index merges. The root cause is a non-reentrant filesystem operation in `save_autostash()` that prematurely locks and deletes the MERGE_AUTOSTASH ref, corrupting the index state during concurrent merge operations.

- **Resolved issues**:
  - Breakage in `t5520-pull.sh` (pull/merge operations) when merged into `seen`, traced to commit `2d1fa0323f` in `tb/rerere-lock-grace`. The auto-maintenance step (`git maintenance run --auto`) triggered `git reflog expire` under the test’s fixed `GIT_COMMITTER_DATE`, expiring reflog entries critical for `git pull --rebase`’s fork-point detection. The stash series’ tests generated eight fewer reflog entries (from failed merges due to the elimination of `git reset --quiet --refresh` calls), shifting expiration timing. **Fix**: Thomas Bachem’s patch to pin `gc.reflogExpire` and `gc.reflogExpireUnreachable` to `never` in the test setup resolves the issue.
  - Verbosity regression in Patch 5/5: Fixed by preserving the original verbosity setting for the worktree merge.
  - Bisectability regression: The test in Patch 3/5 (v3) was squashed into Patch 5/5 and replaces an existing test, preserving bisectability. The test now uses `-U1` for `git stash push -p` to reduce context lines.
  - NULL-dereference risk: Fixed by checking `result.clean` before dereferencing `result.tree` in `do_apply_stash()`. Junio’s audit confirmed this pattern is used by all other callers of `merge_incore_nonrecursive()`.
  - **Patch 2/5 specifics**: Refactors `do_apply_stash()` to initialize the `merge_options` structure (`init_ui_merge_options()`) earlier, enabling reuse for the in-core index merge in later patches. The change is purely mechanical (10-line diff in `builtin/stash.c`) with no behavior change, but is a prerequisite for the index-merge logic.
- **Clarification on `git pull --rebase`**: The reflog dependency in `git pull --rebase` stems from its internal use of `git merge-base --fork-point` to compute the fork point from the reflog of `refs/remotes/me/copy`, even when an explicit `<upstream>` argument is provided. This behavior contradicts the documented expectation but does not affect the stash series’ logic.
- **Patch 1 specifics**: Removes unused `#include "oid-array.h"` from `builtin/stash.c`, addressing a Clang warning. The header is transitively covered by `hash.h`, and the change is purely mechanical with no functional impact.
