Thread identity
Subject: [PATCH 0/4] stash: fix autostash with staged index entries
Series version: v3 (final, submitted as five patches)
Originating author: D. Ben Knoble
Thread type: patch series (bugfix)

Core problem or goal
Fix a bug in `git stash` where autostashing fails to correctly handle staged index entries when `stash.index=true` is set. The bug manifests during merge operations that trigger autostash, causing incorrect index state preservation due to a race condition in the subprocess-based logic (`git diff-tree` and `git apply`). The series replaces this with in-core merging via `merge-ort.c`, ensuring staged entries are properly preserved and eliminating the risk of SIGSEGV on conflicted index merges.

Current status
v3 has been submitted as a five-patch series and is the final iteration. The series is technically complete and ready for integration. Patches: (1) cleanup (merged to `master`), (2) refactor merge option initialization, (3) add test for conflicted index merges (new in v3), (4) expanded test assertions for worktree and index state preservation, (5) functional fix (refactor index merge logic in `builtin/stash.c` and `merge-ort.c`). The **critical correctness issue** identified by Junio C Hamano in Patch 5—backwards tree arguments in `merge_incore_nonrecursive()`—has been resolved by swapping `(head, merge, merge_base)` to `(merge_base, merge, head)`. Junio explicitly endorsed the fix and confirmed the test case (included as Patch 3 with proper Signed-off-by attribution) is sufficient for verification. Phillip Wood endorsed this fix, noting the error was masked in existing tests because "base" and "stage2" were identical, and recommended standardizing argument order across related merge functions (`merge_ort_nonrecursive` and `merge_incore_nonrecursive`) to avoid future confusion. The author declined to include this standardization in the current series, treating it as a separate future cleanup, and Junio explicitly endorsed this decision as out of scope. All follow-ups are resolved: (1) the memory leak in Patch 5 (add `merge_finalize(&o, &result)` before returning on conflict) has been confirmed and fixed in v3, (2) test robustness improvements in Patch 4 (add `git diff-files -p` and `git diff-index --cached HEAD` to verify unstaged changes and index preservation) are incorporated, (3) inclusion of Junio’s test case with proper Signed-off-by is procedurally complete, and (4) the test’s diff comparison now uses raw diff output directly, as the existing `diff_cmp()` helper (which filters index lines) is unnecessary for comparing fixed content where blob IDs are stable.

**Test coverage enhancement**: The author has accepted Phillip Wood’s proposed expanded test case for Patch 4, which exercises content-level merge conflicts by staging a subset of changes, stashing, modifying the file again, committing, and popping the stash with `--index`. The test verifies that staged changes (`committed B staged`) are correctly merged into the index and unstaged changes (`committed B unstaged`) are preserved in the worktree. The author confirmed the test fails on the original (buggy) code and passes with the fix, addressing Junio’s concern about the original test being too trivial. Minor adjustments to avoid interfering with later tests are incorporated in v3.

Open questions and loose ends
None. The last open implementation detail—how to handle diff output comparison in the test—has been resolved by confirming that raw diff output can be used directly without filtering. The broader argument-order standardization between `merge_ort_nonrecursive()` and `merge_incore_nonrecursive()` remains a separate, future cleanup task and is explicitly out of scope.
