Subject: [PATCH 0/2] stash: fix autostash with staged index entries
Series version: v1 (initial submission, v2 pending)
Originating author: D. Ben Knoble
Thread type: patch series (bugfix)

Core problem or goal
Fix a bug in `git stash` where autostashing fails to correctly handle staged index entries when `stash.index=true` is set. The bug manifests during merge operations that trigger autostash, causing incorrect index state preservation due to a race condition in the subprocess-based logic (`git diff-tree` and `git apply`). The series replaces this with in-core merging via `merge-ort.c`, ensuring staged entries are properly preserved.

Current status
Under review (v1). Two patches: (1) cleanup (remove unused `#include "oid-array.h"` from `builtin/stash.c`, accepted by Junio C Hamano), (2) functional fix (refactor index merge logic in `builtin/stash.c` and `merge-ort.c`, replacing 65 lines of subprocess calls with 23 lines of in-core merge logic; add test in `t/t7600-merge.sh`). The author has agreed to address Phillip Wood’s technical concerns (merge algorithm consistency, assertion safety, verbosity handling) in a v2 submission, including a logic correction to conditionally reinitialize `merge_options` only when `!has_index`.

Key technical details
- Files touched: `builtin/stash.c`, `merge-ort.c`, `t/t7600-merge.sh`
- Subsystems: stash, merge-ort
- New/renamed symbols: None (internal refactoring only)
- Behavior change: Index state is now merged in-core during autostash, avoiding external process calls and eliminating a race condition that could corrupt the `MERGE_AUTOSTASH` ref. The patch standardizes on the `_ui` variant of the diff algorithm for both index and worktree merges to avoid behavioral mismatches.
- On-disk format: Unchanged
- Test coverage: Added test case in `t/t7600-merge.sh` covering the bug scenario (staging a file before a fast-forward merge with `--autostash` and `stash.index=true`), reported by Eli Barzilay. Test verifies autostash application and stash list cleanup. A new test will be added to verify graceful failure (without SIGSEGV) if the index merge fails.

Open questions and loose ends
- **Assertion safety**: The patch removes two `assert()` calls in `merge-ort.c` that guarded against NULL pointers (`opt->branch1`, `opt->branch2`, and `opt->ancestor`). These assertions were added in 2020 without explanatory context. The author plans to restore fixed ancestor/branch labels in `do_apply_stash()` to prevent crashes and add a test for graceful failure on index merge errors. Whether `merge_finalize()` should replace `clear_merge_options()` remains open (author leaning toward conditional reinitialization when `!has_index`).
- **Verbosity option**: The `verbosity` field in `merge_options` is unused by the ort strategy. The author has opted to retain it for now, citing potential future use and a desire to keep the merge quiet.
- Bug impact not fully described in commit message (e.g., whether it causes data loss or merely incorrect behavior).
