Thread identity
Subject: [PATCH 0/4] stash: fix autostash with staged index entries
Series version: v3 (final, submitted)
Originating author: D. Ben Knoble
Thread type: patch series (bugfix)

Core problem or goal
Fix a bug in `git stash` where autostashing fails to correctly handle staged index entries when `stash.index=true` is set. The bug manifests during merge operations that trigger autostash, causing incorrect index state preservation due to a race condition in the subprocess-based logic (`git diff-tree` and `git apply`). The series replaces this with in-core merging via `merge-ort.c`, ensuring staged entries are properly preserved and eliminating the risk of SIGSEGV on conflicted index merges.

Current status
v3 has been submitted and is the final iteration. The series is technically complete and ready for integration. Four patches: (1) cleanup (merged to `master`), (2) refactor merge option initialization, (3) add test for conflicted index merges, (4) functional fix (refactor index merge logic in `builtin/stash.c` and `merge-ort.c`). The **critical correctness issue** identified by Junio C Hamano in Patch 4—backwards tree arguments in `merge_incore_nonrecursive()`—has been resolved by swapping `(head, merge, merge_base)` to `(merge_base, merge, head)`. Junio explicitly endorsed the fix and confirmed the test case (included as a preparatory patch with proper Signed-off-by attribution) is sufficient for verification. Phillip Wood endorsed this fix, noting the error was masked in existing tests because "base" and "stage2" were identical, and recommended standardizing argument order across related merge functions (`merge_ort_nonrecursive` and `merge_incore_nonrecursive`) to avoid future confusion. The author declined to include this standardization in the current series, treating it as a separate future cleanup, and Junio explicitly endorsed this decision as out of scope. All follow-ups are resolved: (1) the memory leak in Patch 4 (add `merge_finalize(&o, &result)` before returning on conflict) has been confirmed and fixed in v3, (2) test robustness improvements in Patch 3 (add `git diff-files -p` and `git diff-index --cached HEAD` to verify unstaged changes and index preservation) are incorporated, (3) inclusion of Junio’s test case with proper Signed-off-by is procedurally complete, and (4) the test’s diff comparison now uses the existing `diff_cmp()` helper, eliminating the need for a `sed` filter as Phillip Wood confirmed. Phillip Wood has proposed an **expanded test case** for Patch 3 that exercises content-level merge conflicts (not just the trivial case of an added file), writing distinct lines to a file, staging a subset, stashing, modifying the file again, committing, and popping the stash with `--index`. The new test verifies that staged changes are correctly merged into the index and unstaged changes are preserved in the worktree. This proposal remains untested but aims to replace Junio’s minimal illustration with a more realistic scenario that better reflects real-world usage and provides stronger regression protection. The cosmetic label adjustment (`"Upstream index"` to a clearer alternative) is optional and not blocking.

Open questions and loose ends
The only remaining open item is whether to adopt Phillip Wood’s proposed expanded test case in place of Junio’s minimal illustration. Junio’s preference for a more realistic test scenario is now concretely addressed by Phillip’s proposal, but the author has not yet responded to confirm whether it will be incorporated into the series. The broader argument-order standardization between `merge_ort_nonrecursive()` and `merge_incore_nonrecursive()` remains a separate, future cleanup task and is explicitly out of scope.
