Thread identity
Subject: [PATCH 0/4] stash: fix autostash with staged index entries
Series version: v3 (final, submitted as five patches)
Originating author: D. Ben Knoble
Thread type: patch series (bugfix)

Core problem or goal
Fix a bug in `git stash` where autostashing fails to correctly handle staged index entries when `stash.index=true` is set. The bug manifests during merge operations that trigger autostash, causing incorrect index state preservation due to a race condition in the subprocess-based logic (`git diff-tree` and `git apply`). The series replaces this with in-core merging via `merge-ort.c`, ensuring staged entries are properly preserved and eliminating the risk of SIGSEGV on conflicted index merges. The root cause is a non-reentrant filesystem operation in `save_autostash()` that prematurely locks and deletes the MERGE_AUTOSTASH ref, corrupting the index state during concurrent merge operations.

Current status
v3 is the final iteration, submitted as a five-patch series. The series is technically complete and ready for integration. **Patch 1 (cleanup)** is merged to `master`. Patches 2–5 are ready for integration:
- **Patch 2**: Refactor merge option initialization in `do_apply_stash()` to enable reuse for both worktree and index merges (no behavior change).
- **Patch 3**: Add test `test_stash_apply_index_with_conflict` to `t/t3903-stash.sh`, verifying staged index entries are correctly merged during conflicted stash apply.
- **Patch 4**: Add test `stash apply --index leaves everything untouched on failure` to `t/t3903-stash.sh`, confirming worktree and index state are preserved on failed stash apply.
- **Patch 5**: Functional fix in `builtin/stash.c` and `merge-ort.c`, replacing subprocess-based index merging with in-core `merge_incore_nonrecursive()`. The tree argument order was corrected from `(head, merge, merge_base)` to `(merge_base, merge, head)` to resolve a critical correctness issue identified by Junio. The patch also adds a test in `t/t7600-merge.sh` to verify `--autostash` with `stash.index=true` works during fast-forward merges, ensuring the autostash is applied and the stash list is empty afterward.

All feedback is resolved:
- Memory leak in Patch 5 (missing `merge_finalize(&o, &result)`) fixed.
- Test robustness improved in Patch 4 (added `git diff-files -p` and `git diff-index --cached HEAD`).
- Tree argument order in `merge_incore_nonrecursive()` corrected.
- Junio’s test case included with proper Signed-off-by.
- Raw diff output used for test comparisons (blob IDs are stable for fixed content).
