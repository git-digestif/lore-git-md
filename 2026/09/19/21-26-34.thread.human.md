The `git stash` autostash bugfix series (v4) by D. Ben Knoble is now complete and ready for integration. The series fixes a long-standing bug where autostashing fails to correctly preserve staged index entries when `stash.index=true` is set, particularly during merge operations. The root cause—a race condition in subprocess-based logic (`git diff-tree` and `git apply`)—has been resolved by switching to in-core merging via `merge-ort.c`, eliminating the risk of SIGSEGV on conflicted index merges and ensuring staged entries are properly preserved.

All prior integration blockers have been addressed: the NULL-dereference risk in Patch 5/5 (fixed by checking `result.clean` before dereferencing `result.tree`), a verbosity regression (fixed by preserving the original verbosity setting for the worktree merge), and a bisectability regression (resolved by squashing the test from Patch 3/5 into Patch 5/5 and replacing an existing test). The interaction with `t5520-pull.sh`, caused by an unexpected reflog dependency in `git pull --rebase`, is fully resolved via Thomas Bachem’s test-environment fix, which pins `gc.reflogExpire` and `gc.reflogExpireUnreachable` to `never` in the test setup. Junio has already merged Patch 1 (a cleanup) to `master`, and Phillip Wood’s final review confirms the remaining patches are technically complete. The series is now awaiting Junio’s queueing, with no further changes expected. Knoble has offered to reroll the series with a synthetic base for cleaner integration, but this is optional.
