This thread is about a four-patch series from D. Ben Knoble that fixes a bug in `git stash` where autostashing fails to correctly handle staged index entries when `stash.index=true` is set. The bug occurs during merge operations that trigger autostash, leading to incorrect index state preservation due to a race condition in the subprocess-based logic. The series replaces this with in-core merging via `merge-ort.c`, ensuring staged entries are properly preserved and eliminating the risk of SIGSEGV on conflicted index merges.

The series is now in its final version (v3) and is technically complete. The first patch (a cleanup) has already been merged to `master`, while the remaining three patches—refactoring merge option initialization, adding a test for conflicted index merges, and the functional fix—are ready for integration. A critical correctness issue identified by Junio C Hamano in Patch 4 (backwards tree arguments in `merge_incore_nonrecursive()`) has been resolved, and Junio confirmed the fix with a test case included in the series. Phillip Wood endorsed the fix and recommended standardizing argument order across related merge functions, but this was deemed out of scope for the current series. All prior feedback, including a memory leak fix and test robustness improvements, has been incorporated.

The only remaining discussion is whether to adopt Phillip Wood’s proposed expanded test case, which exercises content-level merge conflicts to better reflect real-world usage. The author has not yet responded to this suggestion, but the series is otherwise ready for merging. Key participants include D. Ben Knoble (author), Junio C Hamano (maintainer), and Phillip Wood (reviewer), all of whom have endorsed the design and functional fixes. The series is on track for integration once the final v3 reroll is submitted.
