This thread fixes a bug in `git stash` where autostashing fails to preserve staged index entries when `stash.index=true` is set, particularly during merge operations. The issue stems from a race condition in the subprocess-based logic (`git diff-tree` and `git apply`), which the series replaces with in-core merging via `merge-ort.c`. The root cause is a non-reentrant filesystem operation in `save_autostash()` that corrupts the index state during concurrent merges, sometimes causing SIGSEGVs.

The series is now at v3, with five patches. Patch 1 (a cleanup) is already merged to `master`. Patches 2–5 were previously ready for integration but were ejected from Junio’s `seen` branch due to three issues, two of which are now resolved. The first was a test breakage in `t5520-pull.sh` caused by an interaction with the `tb/rerere-lock-grace` topic, where auto-maintenance steps prematurely expired reflog entries critical for `git pull --rebase`. This was fixed by pinning reflog expiration to `never` in the test setup. The second was a verbosity regression in Patch 5, where the index merge silenced the worktree merge; this was fixed by preserving the original verbosity setting. The third, a bisectability regression in Patch 3, was resolved by squashing its test into Patch 5 and replacing an existing test to avoid failures when bisecting.

The sole remaining blocker is a NULL-dereference risk in Patch 5, where `merge_incore_nonrecursive()` may return with `result.tree` uninitialized on catastrophic failure (e.g., missing objects). Junio’s audit confirmed this is a systemic omission in the patch’s error handling, and the author has agreed to check `result.clean` before dereferencing `result.tree`. Phillip Wood and Junio provided key feedback, with Phillip identifying the bisectability issue and proposing the test restructuring. The series is otherwise technically complete and ready for integration once the NULL-dereference fix is implemented.
