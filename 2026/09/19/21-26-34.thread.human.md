This thread fixes a bug in `git stash` where autostashing fails to correctly handle staged index entries when `stash.index=true` is set, particularly during merge operations. The issue, reported by Eli Barzilay, stems from a race condition in the subprocess-based logic (`git diff-tree` and `git apply`) that can corrupt the index state and even cause a SIGSEGV on conflicted merges.

D. Ben Knoble’s five-patch series (v3) is now complete and ready for integration. The first patch, a cleanup, has already been merged to `master`. The remaining four patches refactor merge option initialization, add robust test coverage (including conflicted index merges and fast-forward autostash scenarios), and replace the problematic subprocess logic with in-core merging via `merge-ort.c`. Key fixes since earlier versions include correcting the tree argument order in `merge_incore_nonrecursive()` (a critical correctness issue identified by Junio) and plugging a memory leak. Phillip Wood’s review helped tighten test assertions to verify both worktree and index state preservation on failure.

The series touches `builtin/stash.c`, `merge-ort.c`, and the test suite (`t/t3903-stash.sh` and `t/t7600-merge.sh`). Junio and Phillip Wood have both endorsed the changes, and the author has explicitly deferred broader argument-order standardization to a future cleanup. No further revisions are expected, and the patches are now awaiting integration into Junio’s queue.
