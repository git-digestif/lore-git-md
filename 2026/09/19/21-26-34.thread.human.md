This thread is about a bugfix series for `git stash` that addresses a race condition in autostashing when staged index entries are present and `stash.index=true` is set. The bug could corrupt the index state during merge operations that trigger autostash, and the fix replaces subprocess-based logic (`git diff-tree` and `git apply`) with in-core merging via `merge-ort.c`.

The series is now at version 2, with four patches: a cleanup (already accepted), a refactor of merge option initialization, a test for conflicted index merges, and the functional fix. The maintainer, Junio C Hamano, recently confirmed that the critical correctness issue in the final patch—where the order of tree arguments in `merge_incore_nonrecursive()` was backwards—has been resolved with a one-line change. This fix ensures the stash applies the correct changes and preserves unrelated staged entries. The series is now technically sound, with only two minor follow-ups remaining: a memory leak fix in the functional patch and test robustness improvements suggested by Phillip Wood.
