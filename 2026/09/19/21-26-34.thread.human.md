This thread fixes a bug in `git stash` where autostashing fails to correctly preserve staged index entries when `stash.index=true` is set, particularly during merge operations. The issue stemmed from a race condition in the subprocess-based logic (`git diff-tree` and `git apply`), which the series replaces with in-core merging via `merge-ort.c` to ensure staged entries are properly preserved and avoid potential SIGSEGV on conflicted index merges.

A critical correctness issue—backwards tree arguments in `merge_incore_nonrecursive()`—was identified by Junio C Hamano and resolved by swapping the order from `(head, merge, merge_base)` to `(merge_base, merge, head)`. Phillip Wood endorsed this fix, noting the error was masked in existing tests, and recommended standardizing argument order across related merge functions, though the author deferred this to a future cleanup. Junio later confirmed the series is technically sound and ready for integration, explicitly endorsing the decision to exclude the broader standardization from this series. All prior feedback, including memory leak fixes and test robustness improvements, has been incorporated. The series is now complete, with no open questions or blocking issues.
