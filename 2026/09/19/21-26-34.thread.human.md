This thread is about a four-patch series from D. Ben Knoble that fixes a bug in `git stash` where autostashing fails to correctly handle staged index entries when `stash.index=true` is set. The bug, which can cause incorrect index state preservation and even SIGSEGV during conflicted merges, is addressed by replacing subprocess-based logic with in-core merging via `merge-ort.c`.

The series is now at v2, with the first patch (a cleanup) already accepted by Junio C Hamano. Patches 2-4—covering refactoring, test additions, and the functional fix—were ready for integration pending minor adjustments: a memory leak fix in Patch 4 and test robustness improvements in Patch 3. Phillip Wood’s reviews have been thorough, focusing on correctness and test coverage, and all major technical concerns had been addressed.

However, Junio’s latest review identifies a critical logic error in Patch 4: the order of tree arguments passed to `merge_incore_nonrecursive()` appears to be backwards, which would cause the merge to apply changes in the wrong direction. He provides a failing test case to demonstrate the issue, confirming that the current patch breaks the expected behavior. The fix is straightforward—swapping two arguments—but this is a blocker for integration. The rest of the series remains sound, and the earlier feedback (memory leak, test improvements) still stands. The author will need to post a v3 to address this before the series can proceed.
