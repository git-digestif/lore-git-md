This thread fixes a long-standing bug in `git stash` where autostashing fails to correctly handle staged index entries when `stash.index=true` is set, particularly during merge operations. The issue could corrupt the index state and even cause a SIGSEGV on conflicted merges due to a race condition in the subprocess-based logic (`git diff-tree` and `git apply`).

D. Ben Knoble’s five-patch series (v3) is now complete and ready for integration. The first patch (a cleanup) is already merged to `master`. The remaining four patches refactor merge option initialization, add tests for conflicted index merges and failed stash apply scenarios, and implement the core fix: replacing subprocess-based merging with in-core merging via `merge-ort.c`. Junio C Hamano identified a critical correctness issue in the final patch—the backwards tree arguments in `merge_incore_nonrecursive()`—which the author fixed by swapping `(head, merge, merge_base)` to `(merge_base, merge, head)`. Junio and Phillip Wood both endorsed the fix, and Phillip confirmed the test case is sufficient. Phillip also helped tighten the test assertions to verify both worktree and index state preservation.

The series is technically complete, with all feedback incorporated. The broader argument-order standardization between `merge_ort_nonrecursive()` and `merge_incore_nonrecursive()` was deemed out of scope and left for a future cleanup. No further revisions are expected.
