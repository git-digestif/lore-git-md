This thread fixes a bug in `git stash` where autostashing fails to correctly preserve staged index entries when `stash.index=true` is set, particularly during merge operations. The issue stems from a race condition in the subprocess-based logic (`git diff-tree` and `git apply`), which the series replaces with in-core merging via `merge-ort.c`. The fix ensures staged entries are properly preserved and eliminates the risk of SIGSEGV on conflicted index merges.

The series is now in its third and final version (v3), with four patches: a cleanup (already merged to `master`), a refactor of merge option initialization, a test for conflicted index merges, and the functional fix. Junio C Hamano identified a critical correctness issue in the functional fix—a backwards tree argument order in `merge_incore_nonrecursive()`—which has been resolved. Phillip Wood’s reviews confirmed the design’s soundness but flagged a memory leak in the functional fix (now addressed) and minor test robustness improvements, which the author has agreed to include.
