This thread is about a four-patch bugfix series from D. Ben Knoble that fixes a race condition in `git stash` when `stash.index=true` is set and autostash is triggered during merge operations. The bug could corrupt the `MERGE_AUTOSTASH` ref and cause a SIGSEGV on conflicted index merges. The solution replaces the existing subprocess-based merge logic (`git diff-tree` and `git apply`) with an in-core merge using `merge-ort.c`, which is more reliable and eliminates the race condition.

The series is now complete with v2, which restructured the patches based on feedback from Phillip Wood. The first patch, a cleanup removing an unused include, has already been accepted by Junio C Hamano. The second patch refactored merge option initialization to prepare for the in-core merge, and the third added test coverage for conflicted index merges. The final patch (4/4), just posted, implements the core fix—replacing the subprocess calls with in-core merge logic in `builtin/stash.c`. All technical concerns, including merge algorithm consistency, assertion safety, and option lifecycle, have been addressed.

The fix is low-risk, as in-core merges are well-tested in `merge-ort.c`, and the series includes thorough test coverage. The code is now ready for integration, with no open questions or unresolved issues. Reviewers familiar with `merge-ort.c`, such as Elijah Newren, may still provide feedback, but the series is effectively complete and awaiting final review.
