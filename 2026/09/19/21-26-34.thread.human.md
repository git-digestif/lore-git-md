This thread is about a bugfix series for `git stash` that addresses a race condition in autostashing when `stash.index=true` is set. The bug causes staged index entries to be mishandled during merge operations, potentially corrupting the `MERGE_AUTOSTASH` ref. The original v1 series (two patches) has evolved into a four-patch v2, with D. Ben Knoble as the author.

The key change is replacing subprocess-based logic (`git diff-tree` and `git apply`) with in-core merging via `merge-ort.c`, ensuring staged entries are preserved correctly. The v2 series includes a cleanup patch (accepted by Junio), a refactoring patch to simplify merge option initialization, a new test for conflicted index merges, and the core fix. All feedback from Phillip Wood—covering merge algorithm consistency, assertion safety, and option lifecycle—has been addressed, including fixes for potential segfaults and improved error handling.

The series touches `builtin/stash.c`, `merge-ort.c`, and the test suite, with no changes to the on-disk format. Test coverage now includes scenarios for conflicted index merges and graceful failure. While the bug’s impact isn’t described as data loss, the refactoring and test additions suggest it’s a correctness issue with real-world consequences.
