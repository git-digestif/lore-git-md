Core problem or goal
A regression in Git 2.50 swapped the default expiry times for reachable and unreachable reflog entries in `git reflog expire`. Reachable entries (documented to default to 90 days) now expire after 30 days, while unreachable entries (documented to default to 30 days) are incorrectly retained for 90 days. The bug was introduced by commit `85658275702b` ("builtin/reflog: stop storing default reflog expiry dates globally", 2025-04-08), which reversed the order of `.default_expire_total` and `.default_expire_unreachable` in `reflog.h`.

Current status
The fix (v2) posted by Pushkar Singh has addressed all prior review feedback, including Junio C Hamano’s test-structure concern. The patch restores the correct default expiry periods (reachable=90d, unreachable=30d) and adds comprehensive test coverage in `t/t1410-reflog.sh` to verify both reachable and unreachable expiry behavior. Junio, Jeff King (Peff), and Patrick Steinhardt have all reviewed the patch; their feedback (commit message clarity, test coverage expansion, and test-structure consistency) has been fully satisfied. Patrick Steinhardt proposed **fast-tracking the fix for Git 2.56**, citing its urgency and the user-visible correctness issue affecting both `git reflog expire` and `git gc` (which calls it internally). Jeff King (Peff) has now weighed in, stating the patch is "quite obvious and low-risk" and expressing comfort with either merging it now or waiting for the next cycle. The fix remains uncontroversial, narrowly targeted, and ready for merging. No merge status has been reported; the series is still under review but considered complete by all reviewers.
