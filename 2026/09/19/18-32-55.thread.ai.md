Subject: regression in `git reflog expire` default expiry times (2.50)

Core problem or goal
A regression in Git 2.50 swapped the default expiry times for reachable and unreachable reflog entries in `git reflog expire`. Reachable entries (documented to default to 90 days) now expire after 30 days, while unreachable entries (documented to default to 30 days) are incorrectly retained for 90 days. The bug was introduced by commit `85658275702b` ("builtin/reflog: stop storing default reflog expiry dates globally", 2025-04-08), which reversed the order of `.default_expire_total` and `.default_expire_unreachable` in `reflog.h`.

Current status
The fix (v3) by Pushkar Singh has been **merged to `master`** by Junio C Hamano on 2025-06-12. The regression, introduced in Git 2.50.0 (April 2025), went unnoticed for over a year, indicating low real-world impact. The patch restores the correct default expiry periods (reachable=90d, unreachable=30d) and adds comprehensive test coverage in `t/t1410-reflog.sh` to verify both reachable and unreachable expiry behavior. The regression affected both `git reflog expire` and `git gc` (which calls it internally). Junio’s final approval explicitly stated the patch "looks very good" and is ready for merging, with no further iteration expected. A minor post-merge cleanup suggestion (consolidating timestamp conversion logic in the test file) was noted but deemed outside the scope of this patch.

Key technical details
- Files touched: `reflog.h` (field order in `REFLOG_EXPIRE_OPTIONS_INIT`), `t/t1410-reflog.sh` (regression test)
- Symbols: `.default_expire_total` (90 days), `.default_expire_unreachable` (30 days)
- Old behavior: reachable=90d, unreachable=30d (documented)
- New (buggy) behavior: reachable=30d, unreachable=90d
- Fixed behavior: reachable=90d, unreachable=30d (restored)
- On-disk format: unchanged; the bug was purely in the expiry logic
- Test coverage: expanded in v3 to verify four independent test cases:

  - 100-day-old reachable entries are expired

  - 40-day-old unreachable entries are expired
  - Uses `test-tool date` to simulate aged reflog entries
  - Test structure: split into four independent test cases for clarity, addressing Junio’s feedback about asymmetry in prior versions
