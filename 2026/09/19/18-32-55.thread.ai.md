Core problem or goal
A regression in Git 2.50 swapped the default expiry times for reachable and unreachable reflog entries in `git reflog expire`. Reachable entries (documented to default to 90 days) now expire after 30 days, while unreachable entries (documented to default to 30 days) are incorrectly retained for 90 days. The bug was introduced by commit `85658275702b` ("builtin/reflog: stop storing default reflog expiry dates globally", 2025-04-08), which reversed the order of `.default_expire_total` and `.default_expire_unreachable` in `reflog.h`.

Current status
The fix (v2) posted by Pushkar Singh has addressed all prior review feedback, including Junio C Hamano’s latest test-structure concern. The patch restores the correct default expiry periods (reachable=90d, unreachable=30d) and adds comprehensive test coverage in `t/t1410-reflog.sh` to verify both reachable and unreachable expiry behavior. Junio, Jeff King (Peff), and Patrick Steinhardt have all reviewed the patch; their feedback (commit message clarity, test coverage expansion, and test-structure consistency) has been satisfied. The fix remains uncontroversial, narrowly targeted, and ready for merging. No merge status has been reported; the series is still under review but considered complete by the author.

Key technical details
- Files touched: `reflog.h` (field order in `REFLOG_EXPIRE_OPTIONS_INIT`), `builtin/reflog.c` (usage of defaults), `t/t1410-reflog.sh` (regression test)
- Symbols: `.default_expire_total` (90 days), `.default_expire_unreachable` (30 days)
- Old behavior: reachable=90d, unreachable=30d (documented)
- New (buggy) behavior: reachable=30d, unreachable=90d
- Fixed behavior: reachable=90d, unreachable=30d (restored)
- On-disk format: unchanged; the bug is purely in the expiry logic
- Test coverage: expanded in v2 to verify:
  - 60-day-old reachable entries are retained (90-day default)
  - 100-day-old reachable entries are expired
  - 20-day-old unreachable entries are retained (30-day default)
  - 40-day-old unreachable entries are expired
  - Uses `test-tool date` to simulate aged reflog entries
  - Test structure: reachable entries tested in two separate repositories (retention and expiry); unreachable entries tested in a single repository with two expectations. Junio’s feedback questioned this asymmetry and suggested either consolidating all tests into one repository or splitting unreachable tests into two blocks for consistency.
