Subject: regression in `git reflog expire` default expiry times (2.50)
Series version: none (standalone bug report and fix)
Originating author: r.norouzi
Thread type: bug report and fix

Core problem or goal
A regression in Git 2.50 swapped the default expiry times for reachable and unreachable reflog entries in `git reflog expire`. Reachable entries (documented to default to 90 days) now expire after 30 days, while unreachable entries (documented to default to 30 days) are incorrectly retained for 90 days. The bug was introduced by commit `85658275702b` ("builtin/reflog: stop storing default reflog expiry dates globally", 2025-04-08), which reversed the order of `.default_expire_total` and `.default_expire_unreachable` in `reflog.h`.

Current status
A fix has been posted by Pushkar Singh and is under review. The patch restores the correct default expiry periods and adds a regression test in `t/t1410-reflog.sh`. Junio C Hamano and Jeff King (Peff) have both reviewed the patch, agreeing on the need for improvements to the commit message (to clarify when and how the regression was introduced) and to the test coverage (to verify both reachable and unreachable expiry behavior). The fix remains uncontroversial and well-motivated, targeting only the misordered defaults without altering other logic or on-disk formats. No merge status has been reported; the series is still under review pending a v2 patch.

Key technical details
- Files touched: `reflog.h` (field order in `REFLOG_EXPIRE_OPTIONS_INIT`), `builtin/reflog.c` (usage of defaults), `t/t1410-reflog.sh` (regression test)
- Symbols: `.default_expire_total`, `.default_expire_unreachable`
- Old behavior: reachable=90d, unreachable=30d (documented)
- New (buggy) behavior: reachable=30d, unreachable=90d
- Fixed behavior: reachable=90d, unreachable=30d (restored)
- On-disk format: unchanged; the bug is purely in the expiry logic
- Test coverage: reproduction case provided in the original report; current test verifies a 60-day-old reachable entry is retained after `git reflog expire --all`; Junio and Peff requested additional test cases to verify unreachable entries older than 30 days are *not* retained and reachable entries older than 90 days *are* expired
