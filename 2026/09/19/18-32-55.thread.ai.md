Subject: regression in `git reflog expire` default expiry times (2.50)
Series version: none (standalone bug report)
Originating author: r.norouzi
Thread type: bug report

Core problem or goal
A regression in Git 2.50 swapped the default expiry times for reachable and unreachable reflog entries in `git reflog expire`. Reachable entries (documented to default to 90 days) now expire after 30 days, while unreachable entries (documented to default to 30 days) are incorrectly retained for 90 days. The bug was introduced by commit `85658275702b` ("builtin/reflog: stop storing default reflog expiry dates globally"), which reversed the order of `.default_expire_total` and `.default_expire_unreachable` in `reflog.h`.

Current status
Under review. The report is recent and no fix has been posted or merged. The regression is confirmed by a reproduction case showing a 60-day-old reachable entry being pruned when it should be retained.

Key technical details
- Files touched: `reflog.h` (field order), `builtin/reflog.c` (usage of defaults)
- Symbols: `.default_expire_total`, `.default_expire_unreachable`
- Old behavior: reachable=90d, unreachable=30d
- New behavior: reachable=30d, unreachable=90d
- On-disk format: unchanged; the bug is purely in the expiry logic
- Test coverage: reproduction case provided in the report; no existing test failure noted
