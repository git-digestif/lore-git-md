Core problem or goal
A regression in Git 2.50 swapped the default expiry times for reachable and unreachable reflog entries in `git reflog expire`. Reachable entries (documented to default to 90 days) now expire after 30 days, while unreachable entries (documented to default to 30 days) are incorrectly retained for 90 days. The bug was introduced by commit `85658275702b` ("builtin/reflog: stop storing default reflog expiry dates globally", 2025-04-08), which reversed the order of `.default_expire_total` and `.default_expire_unreachable` in `reflog.h`.

Current status
The fix (v2) posted by Pushkar Singh has been reviewed and approved by Junio C Hamano, Jeff King (Peff), and Patrick Steinhardt. All prior review feedback—including Junio’s test-structure concern and Peff’s commit message clarity request—has been fully addressed. Junio C Hamano has now explicitly stated the intent to **merge the fix promptly for Git 2.56**, resolving the earlier scheduling uncertainty. The patch restores the correct default expiry periods (reachable=90d, unreachable=30d) and adds comprehensive test coverage in `t/t1410-reflog.sh` to verify both reachable and unreachable expiry behavior. The regression affects both `git reflog expire` and `git gc` (which calls it internally), making this a user-visible correctness issue with no risk of side effects beyond restoring documented behavior. The series is uncontroversial, narrowly targeted, and ready for merging to `master`.
