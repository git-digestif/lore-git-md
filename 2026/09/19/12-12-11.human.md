This is the second patch in a four-part CI/build system series aimed at fixing GitLab CI breakage for Windows builds after Rust support was enabled. The series as a whole addresses a regression in GitLab’s MinGW-based Windows jobs, and this patch specifically prevents the `ci/install-dependencies.ps1` script from clobbering the `.git/info/exclude` file when it runs after `install-sdk.ps1`.

The issue is straightforward: the script was using `New-Item -Force` to create the exclude file, which truncates any existing content. Since `install-sdk.ps1` already adds an exclusion for the Git SDK directory, this overwrite causes `ci/lib.sh` to flag SDK files as unignored build artifacts, breaking the CI pipeline. The fix is simple and surgical—check for the file’s existence before creating it, preserving any prior exclusions.

The patch is clearly motivated and well-explained in the commit message, which even credits GPT-6 for assistance (a detail that may draw curiosity but doesn’t affect the technical content). It’s a targeted fix with no behavior changes to Git itself, just a correction to the CI environment setup. Given the series’ goal of restoring CI functionality, this patch looks like a necessary and uncontroversial part of the solution. No review feedback has appeared yet, but the change is small and self-contained enough that it’s unlikely to spark debate.
