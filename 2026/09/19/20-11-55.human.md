This is a **bugfix** for the regression in the reference-transaction hook, where batched deletions (e.g., `git branch -d`, `git tag -d`, `git remote prune`) stopped reporting the old OID to the hook, breaking tools like Gerrit and GitLab that rely on it. The series directly addresses the issue identified in the earlier thread by modifying `refs_delete_refs()` to accept optional old OIDs and updating the callers to pass them through.

The patch is well-structured: the first commit adds the plumbing to support old OIDs in batched deletions, while the next two apply it to the high-level commands (`branch`, `tag`, `fetch`, and `remote`). Performance is preserved—deleting 10,000 tags remains just as fast (0.85s vs. 0.86s)—and the fix avoids adding any new ref reads. Test coverage is thorough, including both files and reftable backends, SHA-1/SHA-256, and edge cases like broken or symbolic refs.

The commit messages are clear and link back to the original bug report, making the motivation and scope unambiguous. The series looks like a clean, targeted fix for a real problem, with no obvious downsides. If the earlier discussion is any indication, this should be uncontroversial and ready for review. The only open question is whether the documentation for the reference-transaction hook needs updating to reflect the restored behavior, but that could easily be handled in a follow-up.
