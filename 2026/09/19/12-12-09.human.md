This is a CI/build system patch series targeting GitLab's Windows CI jobs. Johannes Schindelin addresses a breakage in GitLab CI that occurred after Rust support was enabled for Windows builds. The issue appears to stem from incorrect cargo/Rust setup in the MinGW environment used by GitLab's Windows runners.

The series consists of four patches that collectively fix the Rust toolchain invocation. Key changes include provisioning GNU Rust specifically for SDK-based MinGW builds, preserving exclusion rules during dependency setup, correcting the Rust setup for GitLab's MinGW environment, and ensuring GNU Rust's host-linker support is properly configured. The patches touch `.gitlab-ci.yml` and the PowerShell script `ci/install-dependencies.ps1`.

Schindelin notes this was lightly tested due to limited GitLab build minutes, but the motivation is clear: Junio C Hamano reported the CI was broken, and this series aims to restore functionality. Given Schindelin's role as Git for Windows maintainer and his deep familiarity with Windows CI infrastructure, this looks like a well-targeted fix rather than a speculative change.

The series is narrowly scoped to the CI machinery and doesn't affect Git's core functionality. If you're following Git's Windows CI or Rust integration efforts, this is worth watching to see if it resolves the reported breakage. The patches appear straightforward and focused, though the limited testing mentioned might warrant extra scrutiny from reviewers.
