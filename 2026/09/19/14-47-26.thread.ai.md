Core problem or goal
Users of shallow repositories (created with `git clone --depth`) experience slow or hanging `git fetch`/`git pull` operations when the remote has many branches, because a refspec-less fetch negotiates history for all remote branches. The thread implements a "matching-inspired" fetch mode that dynamically fetches only the branches tracked by local branches at the remote being fetched, using configuration to separate namespace mappings from fetch selection logic.

Key technical details
- **Current design**: `remote.<name>.refmap` defines namespace mappings (e.g., `+refs/heads/*:refs/remotes/second/*`) and, when no `remote.<name>.fetch` is configured, implicitly controls which refs are fetched by enumerating branches tracked by local branches at the remote. Precedence: `remote.<name>.fetch` > `remote.<name>.refmap`.
- **Proposed alternative**: `remote.<name>.fetchRefs` (Phillip Wood) would explicitly specify which refs to fetch (e.g., `*@{upstream}`), decoupling the "what" from the "where". This would resolve the refspec-matching order inconsistency and enable per-branch overrides.
- **Dynamic branch selection**: When no explicit refspec is given and the remote has a refmap but no fetch refspec, `git fetch` enumerates branches tracked by local branches at the remote via `@{upstream}`. The `branches_tracking_remote()` helper implements this logic; `get_ref_map()` integrates it.
- **`--limited-fetch` flag**: Added to `git remote add` (Patch 4/5), configures `remote.<name>.refmap` instead of the traditional wildcard `remote.<name>.fetch`. **Patch 5/5 makes it the default in shallow repositories** by checking `is_repository_shallow(the_repository)`.
- **Fallback logic**: `remote_find_tracking()` falls back to `remote->refmap` only when `remote->fetch` is empty or contains no matching refspec. Two new tests verify refmap tracking and negative refspec exclusion.
- **Files touched**:
  - `remote.c`/`remote.h`: `remote.<name>.refmap` parsing, `branches_tracking_remote()`, `collect_upstream_from_remote()` helper.
  - `builtin/fetch.c`: Integration with refmap configuration and dynamic branch enumeration.
  - `builtin/remote.c`: `--limited-fetch` flag and shallow-repository default.
  - Documentation: `remote.txt`, `git-fetch.adoc`, `git-remote.adoc`, `fetch-options.adoc`.
  - Tests: `t/t5510-fetch.sh`, `t/t5586-fetch-refmap.sh`, `t/t5505-remote.sh` (20 new tests).
- **Behavior**:
  - Remote’s default branch is no longer fetched by default.
  - Non-shallow repositories continue using wildcard refspecs by default.
  - New mode enabled when `remote.<name>.refmap` is configured without `remote.<name>.fetch`.
  - No on-disk format changes beyond new configuration entries.
- **New symbols**: `remote.<name>.refmap`, `remote->refmap`, `branches_tracking_remote()`, `collect_upstream_from_remote()`, `--limited-fetch`, `--no-limited-fetch`, `is_repository_shallow()`, `remote.<name>.fetchRefs` (proposed).
