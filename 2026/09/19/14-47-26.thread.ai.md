Core problem or goal
Users of shallow repositories (created with `git clone --depth`) experience slow or hanging `git fetch`/`git pull` operations when the remote has many branches, because a refspec-less fetch negotiates history for all remote branches. The series implements a "matching-inspired" fetch mode that dynamically fetches only the branches tracked by local branches at the remote being fetched, using configuration to separate namespace mappings from fetch selection logic. **The design is finalized: the series introduces `remote.<name>.fetchRefmap` (renamed from `remote.<name>.fetchRefs` in the v12 implementation) to decouple the "what" (which refs to fetch) from the "where" (where to store them), resolving the maintainer and key reviewer’s objection to overloading `remote.<name>.refmap`.**

Key technical details
- **Finalized design (v12)**:
  - **New config key**: `remote.<name>.fetchRefmap` explicitly specifies which refs to fetch (e.g., `*@{upstream}`), decoupling the "what" from the "where".
  - **Refmap role**: `remote.<name>.refmap` reverts to its original purpose: namespace mapping only (e.g., `+refs/heads/*:refs/remotes/second/*`).
  - **Precedence**: `remote.<name>.fetch` > `remote.<name>.fetchRefmap` > dynamic branch enumeration (if neither is configured). Command-line refspecs override both config keys.
  - **Forced updates (`+`)**: Belong on the refmap side (the "where"), not the fetchRefmap side (the "what").
  - **Refspec-matching order**: The new design resolves the inconsistency (first-match vs. last-one-wins) by decoupling the "what" and "where".
  - **Dynamic branch selection**: When no explicit refspec, `remote.<name>.fetch`, or `remote.<name>.fetchRefmap` is given, `git fetch` enumerates branches tracked by local branches at the remote via `@{upstream}`. The `branches_tracking_remote()` helper implements this logic; `get_ref_map()` integrates it. This logic now triggers only when neither `remote.<name>.fetch` nor `remote.<name>.fetchRefmap` is configured.
  - **`--limited-fetch` flag**: Added to `git remote add` (Patch 4/5), configures `remote.<name>.fetchRefmap` (e.g., `*@{upstream}`), while `remote.<name>.refmap` handles namespace mapping.
  - **Shallow-repository default**: Patch 5/5 makes `--limited-fetch` the default in shallow repositories by checking `is_repository_shallow(the_repository)`. The default uses `remote.<name>.fetchRefmap = *@{upstream}`.
  - **Fallback logic**: `remote_find_tracking()` falls back to `remote->fetchRefmap` (if configured) before dynamic branch enumeration.
  - **Files touched (v12)**:
    - `remote.c`/`remote.h`: Add `remote.<name>.fetchRefmap` parsing, adjust precedence rules, and rework `branches_tracking_remote()` to integrate with the new config key. **Patch 2/5 adds `collect_upstream_from_remote()` helper to `remote.c` and declares it in `remote.h` for reuse in dynamic branch enumeration.**
    - `builtin/fetch.c`: Update integration with refmap configuration and dynamic branch enumeration to use `fetchRefmap`.
    - `builtin/remote.c`: Update `--limited-fetch` flag and shallow-repository default to use `fetchRefmap`.
    - Documentation: Update `remote.txt`, `git-fetch.adoc`, `git-remote.adoc`, and `fetch-options.adoc` to reflect the new design.
    - Tests: Update `t/t5510-fetch.sh`, `t/t5586-fetch-refmap.sh`, and `t/t5505-remote.sh` to test the new `fetchRefmap` behavior.
  - **Behavior (v12)**:
    - New mode enabled when `remote.<name>.fetchRefmap` is configured (e.g., `*@{upstream}`).
    - `remote.<name>.refmap` handles namespace mapping only.
    - Precedence: `remote.<name>.fetch` > `remote.<name>.fetchRefmap` > dynamic branch enumeration.
    - Command-line refspecs override both config keys.
    - No on-disk format changes beyond new configuration entries.
  - **New symbols (v12)**:
    - `remote.<name>.fetchRefmap`, `remote->fetchRefmap`, **`collect_upstream_from_remote()`**.
