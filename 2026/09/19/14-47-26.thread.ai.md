Subject: [PATCH] fetch: introduce `fetch.shallow` config to restrict refspec-less fetches to current branch
Series version: v1 (initial submission)
Originating author: Harald Nordgren
Thread type: patch series (single patch)

Core problem or goal
Users of shallow repositories (created with `git clone --depth`) experience slow or hanging `git fetch`/`git pull` operations when the remote has many branches, because a refspec-less fetch negotiates history for all remote branches. The patch introduces a new `fetch.shallow` configuration option (default: `false`) that, when enabled, restricts such fetches to only the current branch’s upstream, avoiding the performance penalty.

- New config key: `fetch.shallow` (boolean, default `false`)
- Behavior: when `fetch.shallow=true` and the repository is shallow, a refspec-less fetch (e.g., `git fetch` or `git pull`) will only fetch the current branch’s upstream, ignoring other remote branches
