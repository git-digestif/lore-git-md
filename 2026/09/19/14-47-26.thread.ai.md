Subject: [PATCH] fetch: introduce `fetch.shallow` config to restrict refspec-less fetches to current branch
Series version: v1 (initial submission)
Originating author: Harald Nordgren
Thread type: patch series (single patch)

Core problem or goal
Users of shallow repositories (created with `git clone --depth`) experience slow or hanging `git fetch`/`git pull` operations when the remote has many branches, because a refspec-less fetch negotiates history for all remote branches. The patch introduces a new `fetch.shallow` configuration option (default: `false`) that, when enabled, restricts such fetches to only the current branch’s upstream, avoiding the performance penalty. The motivation and scope of the feature are now under discussion: whether the performance issue is specific to sparse checkouts (as implied by documentation) or more generally to any shallow repository with many remote-tracking branches.
