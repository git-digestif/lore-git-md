Thread identity: RFC patch series introducing a warning in `git commit` for commits with dates preceding their parents, authored by Yashwanth Sai via GitGitGadget. Thread type: design discussion / feature proposal.

Core problem or goal: Address the usability issue where Git accepts commit dates that violate the non-decreasing assumption, causing commands like `git log --since` to silently skip commits. The proposal adds a warning (via the advice system) when `git commit` creates a commit with a date earlier than its parent(s), alerting users to potential history traversal problems.

Current status: Under initial review as an RFC. No prior versions exist. The patch is not yet queued in any integration branch (status: under review).

Key technical details:
- **Files touched**: `advice.c`, `advice.h`, `builtin/commit.c`, `Documentation/config/advice.adoc`, `t7502-commit-porcelain.sh`.
- **New config key**: `advice.clockSkew` (boolean, default `true`).
- **New symbols**: None (internal logic only; no new public functions or structs).
- **Behavior**: Warning-only (no enforcement); triggers only for `git commit` (excludes merges/replays), compares new commit date against parents, handles timezones, skips unparseable commits.
- **On-disk format**: No changes.
- **Test coverage**: New tests in `t7502-commit-porcelain.sh` verify warning triggers and silencing via config.

Open questions and loose ends:
1. **Feature necessity**: Whether the warning is wanted at all (prior discussions were inconclusive).
2. **Output channel**: Whether advice is the right mechanism (stderr may get buried; alternatives like direct warning messages were not explored).
3. **Scope expansion**: Whether `git fsck` should also warn about dates far ahead of "now" (though it cannot compare parents, unlike `git commit`).

Participant positions: None recorded yet (initial RFC).

Related work: None mentioned in the thread. The issue (commit dates breaking history traversal) is a long-standing edge case but has not been addressed in prior series. The advice system is reused here, but no other subsystems (e.g., `fsck`) are modified.
