# Thread deltas

## 2026/09/07

- [2026/09/07/08-19-17 by AIKSXD ax <aiksxd@outlook.com>] AIKSXD ax reported that `git pull` silently replaces a local directory with a committed symlink of the same name when a `.gitignore` pattern like `dataset/` is used, causing irreversible data loss, and proposed that either the trailing-slash pattern should also ignore the symlink or Git should detect the conflict on pull and refuse to overwrite the directory without prompting.
- [2026/09/07/19-41-01 by brian m. carlson <sandals@crustytoothpaste.net>] brian m. carlson explained that `.gitignore` patterns with a trailing slash do not ignore symlinks because `dataset/` ignores everything under the directory rather than the entry itself, and the index tracks only regular files and symlinks, not directories.
- [2026/09/07/19-41-01 by brian m. carlson <sandals@crustytoothpaste.net>] brian m. carlson stated that testing with a non-symlink file showed Git also removes the local directory in that case, and that `git checkout` deletes ignored files and directories by default (`--overwrite-ignore`), noting that a `precious` attribute to preserve ignored files has been discussed but not implemented.
- [2026/09/07/19-41-01 by brian m. carlson <sandals@crustytoothpaste.net>] brian m. carlson argued that making `dataset/` ignore a symlink with that name would be a substantial behavior change, since a symlink need not point to a directory and on Unix need not point anywhere.
- [2026/09/07/19-41-01 by brian m. carlson <sandals@crustytoothpaste.net>] brian m. carlson argued that detecting the conflict and refusing to overwrite a real directory with a symlink during pull would also be a big behavior change and would probably break tooling that relies on the status quo.
- [2026/09/07/19-41-01 by brian m. carlson <sandals@crustytoothpaste.net>] brian m. carlson recommended not keeping valuable data in untracked or ignored files within the working tree.
