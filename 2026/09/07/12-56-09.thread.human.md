This thread is about a small but user-facing documentation fix in Git’s advice subsystem. The goal is to correct the on-screen instructions for disabling the `defaultBranchName` advice message, ensuring users are told to use `git config --global` (or possibly `git config set --global`) instead of just `git config set`, so the setting applies globally rather than just to the current repository. The patch was initially proposed by Vsevolod Myalitsin and revised in response to feedback from Ben Knoble, who supported the change but preferred the `set --global` syntax for clarity.

The current version of the patch adds a `global_hint` field to the `advice_setting` struct, set to `1` for `defaultBranchName` and `0` for all other advice keys. This makes the change extensible and cleaner than hardcoding the logic. However, Junio C Hamano has now raised deeper architectural questions: whether `global_hint` should instead be a more general `config_scope` field to accommodate future advice keys that might need `--system` scope, and whether the `vadvise()` helper should take the entire `advice_setting` struct rather than individual fields to keep the interface narrower and more self-contained. These suggestions aim to future-proof the design while keeping the code maintainable.

The thread is still under active review, with no objections to the core goal but open questions about the best way to structure the code. The earlier syntax debate (`--global` vs `set --global`) remains unresolved, but Junio’s feedback has shifted the discussion toward the underlying design rather than just the wording. The patch touches only `advice.c` and is considered low-risk, but the architectural feedback means it may see further revisions before being accepted.
