This thread is about a small but user-facing documentation fix in Git’s advice subsystem. Vsevolod Myalitsin noticed that the on-screen instructions for disabling the `defaultBranchName` advice message recommended a repository-local configuration command, when the setting should apply globally by default. The fix replaces the hard-coded hint with a configurable `scope_hint` field in the `advice_setting` struct, allowing future advice keys to specify their preferred scope (e.g., `--global` or `--system`).

The architectural direction is now settled: the `global_hint` boolean has been replaced with a `scope_hint` field, and the `vadvise()` helper now receives the entire `advice_setting` struct for better encapsulation. Junio C Hamano and Jeff King recently resolved the last major technical obstacle—how to maintain backward compatibility with the existing `advise()` function—by agreeing to pass `NULL` to `vadvise()` when no advice config is tied to the message. This avoids the need for a dummy struct and keeps the interface clean. The only remaining open question is a minor syntax preference (`--global` vs `set --global`) in the displayed command, which does not block the patch.

Vsevolod has accepted all architectural feedback and plans to send a v3 patch incorporating the `NULL` pointer approach. The patch is now effectively ready for merging, pending final polish. Reviewers—Ben Knoble, Junio, and Jeff—have all engaged substantively, with no technical objections to the core goal or design. Jeff also raised a broader question about the advice subsystem’s design (why turn-off instructions are only shown for `advise_if_enabled()` calls), but this is acknowledged as a separate discussion and not a blocker for this patch.
