This thread is about a small but user-facing documentation fix in Git’s advice subsystem. Vsevolod Myalitsin proposed correcting the on-screen instructions for disabling the `defaultBranchName` advice message to recommend a globally scoped configuration command (`--global` or `set --global`) instead of a repository-local `set`. The discussion has settled on the architectural approach: replacing a `global_hint` boolean with a more general `scope_hint` field in the `advice_setting` struct, which allows future advice keys to specify their preferred configuration scope (e.g., `--global`, `--system`).

The series is now in its final stages of review. Junio C Hamano, the maintainer, recently pointed out a minor but necessary adjustment to ensure the `vadvise()` interface remains backward-compatible with the existing `advise()` function, which isn’t tied to any specific `advice_setting[]` entry. The fix is straightforward: create an ad-hoc `advice_setting` struct on the stack for this case, initialized with default values, and pass it to `vadvise()`. This doesn’t change the core goal or the agreed-upon design but ensures the patch is complete before resubmission.

The only remaining loose end is a syntax preference raised by Ben Knoble—whether the displayed command should use `--global` or `set --global`—but this is a minor detail and doesn’t block progress. Vsevolod plans to send a v3 incorporating all feedback, and the thread appears on track for resolution. The change is low-risk, self-contained, and touches only `advice.c`. No test coverage has been added, but the scope is narrow enough that this isn’t a concern.
