This thread is about a small but user-facing documentation fix in Git’s advice subsystem. The goal is to correct the on-screen instructions for disabling the `defaultBranchName` advice message, changing the recommended command from `git config set advice.defaultBranchName false` (repository-local) to `git config --global advice.defaultBranchName false` (or `git config set --global ...` if Ben Knoble’s preferred syntax is adopted). The fix is part of a broader architectural cleanup: the patch replaces a boolean `global_hint` in the `advice_setting` struct with a more general `scope_hint` field, allowing future advice keys to specify their preferred configuration scope (e.g., `--global`, `--system`).

The design direction is now settled. Junio C Hamano, the maintainer, provided architectural feedback that the author accepted: the `vadvise()` helper now receives the entire `advice_setting` struct for better encapsulation, and an ad-hoc struct is created on the stack to maintain backward compatibility with the existing `advise()` function. The only remaining technical detail—how to handle the `advise()` case in the enum—was addressed in this latest email, where the author proposed adding an `ADVICE_LEVEL_UNKNOWN` value to avoid repurposing existing enum values. The unresolved debate between `--global` and `set --global` syntax in the displayed command remains, but it’s a minor preference and doesn’t block the patch.

The series is now ready for a v3, which the author plans to send shortly. The change is low-risk, self-contained to `advice.c`, and introduces no new behavior—just ensuring the existing interface continues to work after the refactor. No test coverage has been added, but the change is considered safe. Key participants include the author (Vsevolod Myalitsin), Junio (who provided architectural guidance), and Ben Knoble (who reviewed the patch and prefers the `set --global` syntax). The patch is under active review but has no outstanding technical objections.
