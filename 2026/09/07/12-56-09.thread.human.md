This thread is about a small but user-facing documentation fix in Git’s advice subsystem. Vsevolod Myalitsin proposed a patch to correct the on-screen instructions for disabling the `defaultBranchName` advice message, recommending `git config --global` instead of `git config set` so the setting applies globally rather than just to the current repository. The change is minimal, touching only the displayed command string in `advice.c`, and is considered low-risk.

Ben Knoble reviewed the patch and agreed with its goal but suggested two improvements. First, he prefers the more explicit `git config set --global` syntax (the modern form) over `git config --global` (the older form). Second, he raised a forward-compatibility concern: the current implementation hardcodes the logic for `defaultBranchName` directly in the string formatting, which could become awkward if other advice keys later need global-level recommendations. He proposed extracting a helper function (e.g., `is_global(key)`) to make the logic more maintainable. The discussion is now open on whether to adopt these refinements. No other objections or open questions have been raised, and the patch remains under review.
