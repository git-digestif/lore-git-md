This thread is about a small but user-facing documentation fix in Git’s advice subsystem. Vsevolod Myalitsin proposed correcting the on-screen instructions for disabling the `defaultBranchName` advice message to recommend a globally scoped configuration command (`--global` or `set --global`) instead of a repository-local `set`. The change also introduces a `scope_hint` field in the `advice_setting` struct to make the subsystem more extensible for future advice keys.

The architectural direction is now settled. Junio C Hamano and Jeff King agreed on a backward-compatibility mechanism—passing `NULL` to `vadvise()` when no advice config is associated—resolving the last major technical hurdle. The only remaining open question is a minor syntax preference: Ben Knoble prefers `set --global` for clarity, but this is not a blocker. Vsevolod plans to send a v3 patch shortly.

The broader advice subsystem design was also clarified in this exchange. Jeff King and Junio confirmed that the current pattern—checking `advice_enabled()` before expensive work and then calling `advise()`—is intentional. The `advise_if_enabled()` helper is reserved for cases where turn-off instructions are explicitly desired, and this inconsistency is not a blocker for the current patch. The discussion reinforces the existing design without requiring any changes to the patch.
