This thread is about a small but user-facing documentation fix in Git’s advice subsystem. Vsevolod Myalitsin has sent the third version of a patch that corrects the on-screen instructions for disabling the `defaultBranchName` advice message. Instead of recommending a repository-local `git config set` command, the new version suggests a globally scoped one (`git config --global advice.defaultBranchName false`), ensuring the setting applies everywhere by default.

The architectural direction is now settled. After feedback from Junio C Hamano and Jeff King, the patch replaces a simple boolean flag with a more extensible `scope_hint` field in the `advice_setting` struct, allowing future advice keys to specify their preferred configuration scope (e.g., `--global` or `--system`). The backward-compatibility requirement for the existing `advise()` function is handled by passing `NULL` to the helper when no advice config is associated, avoiding any disruption to the current codebase. The only unresolved point is a minor syntax preference—whether the displayed command should use `--global` or `set --global`—but this is not a blocker for merging.

The patch touches only `advice.c`, changes no on-disk formats, and adds no new tests, as the change is self-contained and low-risk. Junio and Peff have confirmed the intentional design distinction between `advise()` (used after checking if advice is enabled, to avoid unnecessary work) and `advise_if_enabled()` (used when turn-off instructions are explicitly desired), which remains unchanged. With all major feedback incorporated, the patch is effectively ready for Junio to pick up.
