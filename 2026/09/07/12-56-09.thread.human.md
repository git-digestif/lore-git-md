This thread is about a small but user-visible documentation fix for Git’s `defaultBranchName` advice message, paired with an internal refactoring of the advice subsystem. The core issue is that the on-screen instructions for disabling the `defaultBranchName` advice incorrectly suggested a repository-local configuration command (`git config set advice.defaultBranchName false`), when the setting should apply globally by default. Vsevolod Myalitsin’s patch (now at v3) fixes this by introducing a `scope_hint` field in the `advice_setting` struct, which lets the advice machinery recommend the correct scope (e.g., `--global`) in the displayed command. The design is future-proof, allowing other advice keys to specify their preferred scope, and it resolves backward-compatibility concerns by passing `NULL` to the `vadvise()` helper when no advice config is associated with the message.

Junio C Hamano and Jeff King reviewed the core patch and agreed on the architectural direction, including the `NULL` pointer approach for backward compatibility. The only remaining debate is a minor syntax preference—whether the displayed command should use `--global` or `set --global`—but this isn’t a blocker. Junio also posted a follow-up refactoring patch that mechanically converts existing `advice_enabled()` + `advise()` call sites to the newer `advise_if_enabled()` helper, reducing boilerplate across seven files. This cleanup is low-risk and doesn’t change behavior, but it unifies the codebase toward the newer helper, which is intended for cases where turn-off instructions are explicitly desired. The core patch is effectively ready for merging, while the refactoring patch is under review and awaits feedback on the mechanical conversion.
