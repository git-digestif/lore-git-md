This thread centers on a two-part patch series from Vsevolod Myalitsin that fixes a user-facing documentation issue in Git’s advice subsystem and refactors its internal code. The core patch corrects the on-screen instructions for disabling the `defaultBranchName` advice message, now recommending a globally scoped configuration command (`--global` or `set --global`) instead of a repository-local one. To make this extensible, the patch introduces a `scope_hint` field in the `advice_setting` struct, allowing future advice keys to specify their preferred configuration scope. This part of the series is effectively ready for merging, with architectural direction and backward-compatibility settled in version 3.

The second patch, posted by Junio C Hamano, mechanically refactors existing advice call sites to use the newer `advise_if_enabled()` helper, reducing boilerplate. Jeff King’s review identified a few missed call sites (notably in `commit.c`) and raised a design question about whether the turn-off instructions shown by `advise_if_enabled()` might be visually intrusive. Junio’s recent follow-up closes this discussion by reaffirming the existing design: advice messages should either be universally useful (shown unconditionally) or so rare that turn-off instructions aren’t needed—otherwise, `advise_if_enabled()` is the right tool. The only remaining open question is whether the refactoring patch needs a v2 to address the mechanical completeness issue, though this isn’t a blocker for the core fix. The series remains under review, with no substantive objections to the core patch.
