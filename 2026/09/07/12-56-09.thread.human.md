This thread is about a small but user-facing documentation fix in Git’s advice subsystem. Vsevolod Myalitsin proposed correcting the on-screen instructions for disabling the `defaultBranchName` advice message, which currently suggests a repository-local configuration command (`git config set advice.defaultBranchName false`) instead of a globally scoped one (`git config --global ...` or `git config set --global ...`). The architectural direction is now settled: the patch replaces a boolean `global_hint` in the `advice_setting` struct with a more general `scope_hint` field (e.g., `CONFIG_SCOPE_GLOBAL`), and passes the entire struct to the `vadvise()` helper for better encapsulation. Junio C Hamano’s feedback on backward compatibility—ensuring the existing `advise()` function continues to work—has been accepted, though the exact implementation remains under discussion.

Jeff King (Peff) recently weighed in with a substantive review, proposing a cleaner alternative for handling `advise()`’s backward compatibility. Instead of creating a dummy `advice_setting` struct on the stack, he suggests passing `NULL` to `vadvise()`, which would check for a missing config with `if (conf && !conf->level)`. This approach is more idiomatic in C and avoids the need for a placeholder struct. Peff also raised a broader question about the advice subsystem’s design: most `advise()` calls are wrapped in `if (advice_is_enabled(ADVICE_FOO))`, meaning they don’t show the turn-off instructions introduced in 2020. He wonders whether expanding these instructions to all advice messages might feel chatty to users, given that no one has complained about their absence so far. His proposal to extend `advise()` to accept an advice enum (e.g., `advise(ADVICE_FOO, "try %s", results)`) could address this while avoiding redundant checks, though it would require careful handling of cases where messages aren’t tied to a specific config value.

The core architectural changes—using `scope_hint` and passing the `advice_setting` struct to `vadvise()`—are uncontested, as is the goal of recommending a globally scoped configuration command. The unresolved details are now narrower: the syntax preference (`--global` vs `set --global`) and the implementation of `advise()`’s backward compatibility. Vsevolod plans to send a v3 incorporating Junio’s feedback, and Peff’s proposal offers a cleaner path forward for the compatibility issue. The thread is otherwise converging, with no major objections to the design or intent.
