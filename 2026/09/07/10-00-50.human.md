This is a brief follow-up in Patrick Steinhardt’s ongoing series to unify Git’s reference storage terminology. The series aims to standardize on `--ref-storage-format=` (and related environment variables/config keys) to avoid confusion with object hash formats, and this specific patch (9/11) renames environment variables like `GIT_REFERENCE_BACKEND` to `GIT_REF_STORAGE`.

Karthik Nayak’s review flagged a minor omission: the patch adds `GIT_REF_STORAGE_ENVIRONMENT` to `environment.h` but skips the analogous `GIT_DEFAULT_REF_STORAGE_ENVIRONMENT` macro, which would mirror the existing `GIT_DEFAULT_REF_FORMAT_ENVIRONMENT`. Patrick acknowledges the inconsistency and agrees to add the missing macro in the next version. The rest of the patch—renaming variables, updating documentation, and retaining backward-compatible aliases—is uncontroversial and mechanically sound.

The change is a small but necessary step in the broader refactoring effort, which is well-motivated (preparing for an upcoming object storage extension) and has already addressed Junio C Hamano’s design-level concerns about terminology ambiguity. This patch itself doesn’t introduce new functionality or edge cases; it’s purely about consistency. The missing macro is the only issue, and it’s a straightforward fix that won’t affect the series’ core goals. If you’re tracking the ref storage cleanup, this patch is worth noting for completeness, but it’s unlikely to spark debate.
