This is a review comment on the third patch of Thomas Bachem’s v2 series that defers auto maintenance until the end of sequencer-driven operations (`git rebase`, `git cherry-pick`, `git revert`). The series is otherwise complete and under review, with all prior feedback addressed.

Patrick Steinhardt points out a minor redundancy in the patch: it disables both `maintenance.auto` and `gc.auto` via `GIT_CONFIG_PARAMETERS`, but only `maintenance.auto` is strictly necessary. Modern Git uses `git maintenance` exclusively for auto maintenance, and disabling `maintenance.auto` prevents it from invoking `git gc` internally. The extra `gc.auto=0` is harmless but unnecessary, and removing it would simplify the code slightly. This is a surface-level observation about code clarity rather than a functional issue. The author will likely address it in the next revision.
