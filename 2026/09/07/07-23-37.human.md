This is a brief but substantive reply in the ongoing ODB alternates refactoring thread. Patrick Steinhardt responds to Justin Tobler’s design question about whether `git clone --shared` and similar options should be restricted to the "files" backend or left to backend discretion. Patrick clarifies that the behavior should indeed be backend-specific: while some alternative ODB backends may support alternates, others may not, and the interface is designed to accommodate both possibilities. This aligns with the broader ODB abstraction effort’s goal of making alternates an implementation detail rather than a core requirement.

The exchange leaves the patch’s technical implementation unchanged but provides useful context for future contributors working on pluggable ODB backends. It signals that the project expects backends to define their own semantics for options like `--shared`, which may influence how such features are documented or exposed to users. No further discussion is needed on this point unless other contributors raise objections.
