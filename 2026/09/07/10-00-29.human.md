This is a follow-up in the ongoing refactoring series to unify Git’s terminology for reference storage. Patrick Steinhardt responds to Junio C Hamano’s concern about the ambiguity of the proposed `--ref-storage` option by agreeing to rename it to `--ref-storage-format` (and the corresponding `--object-storage-format` for future object storage extensions). The goal remains the same: eliminate the current inconsistency where `--ref-format` clashes with `--object-format` (which controls the hash algorithm, not storage), and pave the way for a future object storage format extension.

The change is purely terminological; no new functionality is introduced in this reply. Patrick acknowledges that while neither "ref-format" nor "ref-storage" is perfectly clear, the new phrasing resolves the immediate scope conflict with `--object-format` and provides a consistent pattern for future extensions. He plans to send a v2 series with the updated option names (`--ref-storage-format` and `--object-storage-format`), while keeping `--object-format` for hash algorithm control (despite its own naming quirk).

This adjustment addresses Junio’s design-level objection without requiring deeper technical rework. The series’ other improvements—centralized URI parsing, immutability enforcement to prevent silent corruption, and backward-compatible aliases—remain unchanged. If the v2 patches are as clean as v1, this looks like a well-motivated cleanup that should proceed smoothly.
