This thread is about a three-patch series from Beat Bolli that fixes correctness and forward-compatibility issues in `git imap-send`'s TLS certificate verification. The series replaces deprecated OpenSSL API usage, fixes a latent bug where the code incorrectly assumed ASN1_STRINGs are NUL-terminated, and aligns certificate validation with RFC 6125 by prioritizing subject alternative names (SANs) over common names (CNs).

The series is currently under review, but Junio C Hamano identified a memory-safety bug in the second patch that must be fixed before it can proceed. Brian m. Carlson’s recent review raises two additional concerns about the third patch: it fails to handle IP-type SANs, which would incorrectly fall back to CN checks even when an IP SAN exists, and it questions why Git continues to implement certificate verification manually instead of using OpenSSL’s built-in hostname verification (available since OpenSSL 1.0.2). These points are substantive and suggest the series may need broader changes to fully comply with RFC 6125 and reduce maintenance burden.

No maintainer decisions or merge status have been reported yet, and the series remains at its initial v1 version. The only file touched is `imap-send.c`, and no new tests have been added to cover the edge cases these patches address. The open questions now include the memory-safety fix, the IP SAN handling gap, and whether to adopt OpenSSL’s native verification.
