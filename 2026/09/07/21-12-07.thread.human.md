This thread is about a three-patch series from Beat Bolli that fixes correctness and forward-compatibility issues in Git’s `imap-send` TLS certificate verification. The series addresses deprecated OpenSSL API usage, a latent memory-safety bug in ASN1_STRING handling, and stricter RFC 6125 compliance for certificate validation. It’s currently under review, with no prior versions, and faces several unresolved technical concerns.

The key sticking points are a memory-safety bug in the second patch (with two competing fixes proposed), incomplete RFC 6125 compliance in the third patch (missing IP SAN handling), and an architectural question about whether Git should continue implementing certificate verification manually or delegate to OpenSSL’s built-in functions. Beat’s latest reply clarifies the motivation for the first patch’s OpenSSL 4.1 compatibility macro: while the function isn’t deprecated yet, it will be hidden in future OpenSSL versions, and Git’s build configuration already treats deprecation warnings as errors, making this a preemptive fix.

Reviewers have weighed in with substantive feedback. Junio C Hamano identified the memory-safety bug and suggested a fix, brian m. carlson raised concerns about the third patch’s scope and the manual verification approach, and Patrick Steinhardt proposed an alternative fix for the second patch and questioned the necessity of the first patch’s compatibility shim. The series touches only `imap-send.c` and doesn’t change on-disk formats, but it lacks new test coverage for the edge cases it fixes. No maintainer decisions or merge status have been reported yet.
