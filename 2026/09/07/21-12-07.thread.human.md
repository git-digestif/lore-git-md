This thread is about a three-patch series from Beat Bolli that fixes correctness and forward-compatibility issues in Git’s `imap-send` TLS certificate verification. The series addresses a deprecated OpenSSL API usage, a latent memory-safety bug in ASN1_STRING handling, and stricter RFC 6125 compliance for certificate validation. All changes are confined to `imap-send.c`.

The series is still under review, with several unresolved technical concerns. The most pressing is a memory-safety bug in the second patch, where Junio C Hamano identified a heap corruption issue in the original allocation-based fix. Two competing solutions are on the table: Beat’s revised approach (using a separate variable to track the allocation) or Patrick Steinhardt’s alternative (avoiding dynamic allocation entirely with length-bounded string operations). The third patch’s RFC 6125 compliance is incomplete—it handles DNS-type subject alternative names (SANs) but ignores IP-type SANs, which brian m. carlson flagged as a compliance gap. There’s also an architectural question about whether Git should continue implementing certificate verification manually or delegate to OpenSSL’s built-in functions.

The first patch’s OpenSSL 4.1 compatibility macro is now better justified after Beat clarified that OpenSSL will hide the deprecated function when `OPENSSL_API_COMPAT` is set, causing build failures under Git’s `DEVELOPER=1` configuration. Patrick Steinhardt accepted this reasoning but suggested updating the commit message for clarity. The series has no maintainer decisions yet, and no new tests have been added to cover the edge cases these patches address. Key participants include Beat Bolli (author), Junio C Hamano (identified the memory-safety bug), brian m. carlson (raised compliance and architectural concerns), and Patrick Steinhardt (proposed an alternative fix and questioned the macro’s necessity). The thread remains open, with the next steps likely involving a revised version of the series to address the memory-safety bug and compliance gaps.
