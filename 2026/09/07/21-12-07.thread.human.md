This thread is about a three-patch series from Beat Bolli that fixes OpenSSL compatibility and correctness issues in `git imap-send`'s TLS certificate verification. The series addresses deprecated OpenSSL API usage, a latent bug in ASN1_STRING handling, and stricter RFC 6125 compliance for certificate validation. It’s currently under review, with several unresolved technical concerns blocking progress.

The most critical issue is a memory-safety bug in the second patch, where the code incorrectly frees a modified pointer after allocating a NUL-terminated copy of an ASN1_STRING. Junio C Hamano identified this as a showstopper, and Patrick Steinhardt has now proposed an alternative fix: replacing the dynamic allocation with length-bounded string operations (`memchr`, `strncasecmp`), which would eliminate the need for allocation entirely and sidestep the bug. This approach is technically sound but requires careful handling to avoid off-by-one errors in the comparison.

Other open questions remain: brian m. carlson pointed out that the third patch’s RFC 6125 compliance is incomplete (it handles DNS SANs but not IP SANs) and questioned why Git doesn’t use OpenSSL’s built-in hostname verification instead of manual checks. Patrick Steinhardt also challenged the necessity of the first patch’s OpenSSL 4.1 compatibility macro, arguing it may be premature. The series has no maintainer decisions yet, and no new tests have been added to cover these edge cases. The discussion is focused on correctness and maintainability, with no clear consensus on the best path forward.
