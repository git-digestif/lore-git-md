This thread is about a patch series from Beat Bolli that fixes OpenSSL compatibility and correctness issues in `git imap-send`. The series is now at version 2, splitting off uncontroversial parts from an earlier, more ambitious v1 series that remains blocked on unresolved technical concerns.

The key change in this patch (v2 2/2) replaces Git’s manual hostname verification with OpenSSL’s built-in `SSL_set1_host()` to achieve full RFC 6125 compliance, including support for IP-type Subject Alternative Names (SANs). While the principle was uncontroversial, Patrick Steinhardt’s recent review uncovered a critical security regression: the patch removes a check for the peer certificate’s presence, allowing an attacker to strip the certificate entirely and still have the connection accepted. This creates a trivial man-in-the-middle vulnerability that the old code explicitly prevented. The review also notes the lack of test coverage for this security-sensitive path, making the regression harder to catch.

Beat will need to address the security hole before the patch can proceed. The v1 series, which includes stricter RFC 6125 compliance and forward-compatibility fixes, is still stalled due to a memory-safety bug in one of its patches and an unresolved debate over an OpenSSL 4.1 compatibility macro. For now, the focus is on fixing the v2 patch’s security issue and adding test coverage to prevent similar regressions in the future.
