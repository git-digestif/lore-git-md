This thread is about a patch series improving OpenSSL compatibility and correctness in `git imap-send`. Beat Bolli has now sent a v3 series (three patches) to address issues raised during review of the earlier v2.

The first patch in v3 is a straightforward, uncontroversial change: it replaces the deprecated `SSLv23_method()` with the modern `TLS_method()` in `imap-send.c`. This is a purely mechanical update to avoid relying on APIs that OpenSSL has deprecated since 1.1.0 and may remove in future releases. The patch has already been reviewed and is not expected to change further.

The real action is in the other two patches. The second patch (carried over from v2) rewrites Git’s manual hostname verification logic to use OpenSSL’s built-in `SSL_set1_host()` API, achieving full RFC 6125 compliance. However, it introduced two regressions: a **security regression** (certificate stripping is now possible) and an **error reporting regression** (hostname-specific error messages are lost). The third patch is new in v3 and implements Xiangfei Ding’s proposed verification callback to restore the lost error context. The security regression is expected to be addressed in the second patch, but this remains to be seen in the full series.

Key participants include Beat Bolli (author), Patrick Steinhardt (who identified the security regression and lack of test coverage), Aniket Gupta (who spotted the error reporting regression), and Xiangfei Ding (who proposed the callback solution). The series is still under review and blocked on resolving the regressions. No tests exist for this security-sensitive code path, which Patrick Steinhardt has highlighted as a gap that should be addressed. If you care about `imap-send` or OpenSSL compatibility, the v3 series is where the discussion is now focused.
