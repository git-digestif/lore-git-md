This thread is about a patch series (`v2`) from Beat Bolli that aims to modernize and correct OpenSSL usage in `git imap-send`, specifically around TLS initialization and hostname verification. The series is currently blocked due to a **security regression** in the second patch: removing the `SSL_get_peer_certificate()` check creates a trivial man-in-the-middle (MITM) vulnerability by allowing certificate stripping. Additionally, the patch loses hostname-specific error messages when verification fails, a regression noted by Aniket Gupta.

The original `v1` series, which included broader OpenSSL compatibility fixes, remains unresolved due to a memory-safety bug (identified by Junio C Hamano) and a contested OpenSSL 4.1 compatibility macro. The `v2` series was split off to address uncontroversial parts, but the hostname verification rewrite now faces its own critical issues.

Xiangfei Ding has proposed a solution to the error reporting regression: installing a custom verification callback via `SSL_set_verify()` to capture and store the hostname mismatch, allowing the error path to print the specific failure. This would restore the lost context without altering the core verification logic or addressing the security regression. The proposal is substantive but leaves the MITM vulnerability unresolved. Key participants include Beat Bolli (author), Patrick Steinhardt (who identified the security regression), and Aniket Gupta (who flagged the error reporting issue). The thread lacks test coverage for these security-sensitive changes, a gap Patrick Steinhardt has highlighted.
