This thread is about a patch series from Beat Bolli that aims to modernize OpenSSL usage in `git imap-send`, specifically around TLS initialization and hostname verification. The series is now at v3, with the latest email adding OpenSSL 4.0 compatibility macros, but it remains blocked on several critical issues.

The core goals are twofold: first, replacing the deprecated `SSLv23_method()` with `TLS_method()` (uncontroversial and unchanged since v2), and second, replacing Git’s manual hostname verification with OpenSSL’s built-in `SSL_set1_host()` API for full RFC 6125 compliance. The latter effort, however, has introduced three regressions in v3: a **security regression** (certificate stripping via removal of `SSL_get_peer_certificate()`), an **error reporting regression** (lost hostname-specific error messages), and a **behavioral regression** (redundant `verify_peer()` call). A new patch in v3 (3/3) implements a custom verification callback to restore error reporting, but it does not address the security or behavioral issues.

Patrick Steinhardt’s latest review raises three sharp concerns about the OpenSSL 4.0 compatibility macros in the newest patch. First, the macros should have been introduced in the same commit as the `SSL_set1_host()` call, not as a separate patch. Second, the patch assumes `cfg->host` is always a DNS name, but OpenSSL 4.0 splits hostname verification into `SSL_set1_dnsname()` (for DNS names) and `SSL_set1_ipaddr()` (for IP addresses), creating a latent bug if `cfg->host` is ever an IP address. Third, the patch complicates error reporting by conditionally changing the function name in the error message, which adds no value. These issues, along with the unresolved security regression, mean the series will likely need another iteration before it can proceed. The lack of a cover letter and range-diff in the v3 submission further complicates review.

Key participants include Beat Bolli (author), Patrick Steinhardt (who has raised the most substantive technical and procedural concerns), Junio C Hamano (who identified a memory-safety bug in v1), brian m. carlson (who suggested using `SSL_set1_host()` in v1), Aniket Gupta (who spotted the error reporting regression in v2), and Xiangfei Ding (who proposed the verification callback now implemented in v3). The series touches only `imap-send.c` and introduces no on-disk format changes, but it lacks test coverage for the security-sensitive code path it modifies. Until the security regression and Patrick’s concerns are addressed, the series remains under active review with no clear path to merger.
