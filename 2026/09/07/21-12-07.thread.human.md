This thread began as a three-patch series from Beat Bolli aiming to fix OpenSSL compatibility and correctness issues in `git imap-send`'s TLS certificate verification. The original series addressed OpenSSL 4.1 deprecation warnings, a latent memory-safety bug in ASN1_STRING handling, and stricter RFC 6125 compliance for certificate validation. That version ran into several unresolved technical concerns: a memory-safety bug in the second patch (identified by Junio C Hamano), incomplete RFC 6125 compliance (missing IP SAN handling, noted by brian m. carlson), and an architectural question about whether Git should continue implementing certificate verification manually.

Beat has now split the series, sending a smaller v2 that focuses solely on replacing the deprecated `SSLv23_method()` with `TLS_method()`. This change is uncontroversial and purely mechanical, touching only `imap-send.c`. The patch is a straightforward forward-compatibility fix that keeps Git aligned with OpenSSL's recommended APIs. No maintainer decisions have been made on either version, and the remaining issues from the original series—particularly the memory-safety bug and RFC 6125 compliance—are still unresolved. If you're following the thread, the v2 patch is a safe incremental step, but the larger correctness questions remain open.
