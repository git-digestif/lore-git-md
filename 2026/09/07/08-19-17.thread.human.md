This thread reports a critical data-loss bug in `git pull` that can silently destroy local directories during a routine pull. The issue was discovered when a `.gitignore` pattern ending in a slash (`dir/`) failed to ignore a symlink of the same name, allowing the symlink to be committed. When another user pulls, Git overwrites their local directory with the symlink without warning, erasing all data inside it. The author, AIKSXD ax, reproduces the issue on both Linux (Git 2.43.0) and Windows (Git 2.53.0.windows.2) and provides a clear reproduction case.

The problem arises from two related behaviors: `.gitignore` patterns with trailing slashes don’t match symlinks, and `git pull` unconditionally overwrites local directories with symlinks. The author proposes two potential fixes: either extend `.gitignore` to ignore symlinks when the pattern ends with a slash, or detect the conflict during pull and refuse to overwrite without user confirmation. The impact is severe—hundreds of gigabytes of data could be lost silently during a normal workflow. No responses or reviews have appeared yet, so the thread is currently just the initial report. This is a high-priority issue that likely warrants immediate attention from maintainers.
