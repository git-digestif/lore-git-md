This is the third patch in Patrick Steinhardt’s v2 series to unify Git’s terminology for "ref storage format." It renames the `--ref-format=` option to `--ref-storage-format=` in the `git refs migrate` command, retaining the old name as a hidden backward-compatible alias.

The patch touches six files: the `git-refs` man page, `builtin/fetch.c` (updating an error message), `builtin/refs.c` (the core implementation), and three test scripts (`t/t1423-ref-backend.sh`, `t/t1460-refs-migrate.sh`, and `t/t7424-submodule-mixed-ref-formats.sh`). The changes are mechanical: every occurrence of `--ref-format=` is replaced with `--ref-storage-format=`, and the old option is kept as a hidden alias to avoid breaking scripts. The help text placeholder (`argh`) is already consistent with the series’ resolved convention (`"format"`), so no placeholder tweaks are needed here.

No functional changes are introduced; this is purely a rename for consistency. The test updates ensure that existing test cases continue to pass under the new option name. The patch is uncontroversial and aligns with the series’ goal of eliminating inconsistent terminology ahead of the upcoming object storage extension. It is a straightforward, well-scoped refactoring that should not introduce regressions.
