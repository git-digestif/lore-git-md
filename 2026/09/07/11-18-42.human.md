This is the eighth patch in Patrick Steinhardt’s v2 series unifying Git’s terminology for "ref storage format." It refactors the logic that determines and validates the ref storage format during repository (re)initialization, fixing a real bug in the process.

The patch addresses a critical edge case: when a repository is initialized with one ref storage format (e.g., "files") and then reinitialized with a different format (e.g., "reftable") via the `GIT_REFERENCE_BACKEND` environment variable, Git silently corrupts the repository. The new code enforces immutability of the existing format, preventing this corruption by dying with a clear error message if a reinitialization attempt changes the format.

The refactoring also reorders the precedence rules to match Git’s usual pattern: command-line arguments (`--ref-storage-format=`) now override environment variables, which in turn override config settings. This change is intentional and aligns with how other Git options work. The code is restructured to separate the logic for determining the desired format from the logic for validating it, eliminating repetitive validation checks and making the code easier to extend.

The patch touches `setup.c` and updates one test script (`t/t0001-init.sh`) to verify the new immutability enforcement. The changes are well-motivated and address a real-world issue, making this a substantive improvement rather than a purely mechanical refactoring. The series as a whole remains under review, but this patch in particular looks like a clear win.
