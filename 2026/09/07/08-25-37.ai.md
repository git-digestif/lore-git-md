This is the cover letter for v3 of Patrick Steinhardt’s 9-patch series refactoring how Git writes object database (ODB) alternates during repository creation. The series is part of the ongoing ODB abstraction effort, aiming to simplify the ODB interface by removing the ability to write alternates after repository creation.

The core change in v3 is a significant refactoring of `init_db()` into `create_repository()`, which now only creates the initial repository skeleton without setting up the reference or object databases. This eliminates the need for skip flags (e.g., `INIT_DB_SKIP_ODB`) and moves command-specific logic (like printing initialization messages) into the commands themselves, making the interface cleaner and more straightforward. The series also consolidates alternates handling into `odb_source_create_on_disk()`, ensuring alternates are written atomically during ODB creation using Git’s lockfile API, which resolves TOCTOU race and concurrent access concerns raised in earlier versions.

Key technical details include:
- **Files touched**: `builtin/clone.c` (refactored to defer ODB setup and consolidate alternates logic), `setup.c`/`setup.h` (split `init_db()` into `create_repository()` and updated `create_object_database()` to accept alternates), `odb/source-files.c` (added support for writing alternates during ODB creation), and other ODB source files (removed unused `write_alternates()` infrastructure).
- **New or renamed symbols**: `create_repository()` (replaces `init_db()` for skeleton creation), `collect_alternates()` (renamed from `setup_reference()`, now gathers alternates paths into a `strvec`), and `odb_create_on_disk_options` (carries alternates for ODB creation). The `write_alternates()` callback and related infrastructure are removed.
- **Subsystems**: ODB, repository creation, alternates handling, and worktree support.
- **Behavior changes**: No user-visible changes. The series defers ODB creation in `git clone` until after URI resolution, ensuring alternates are written with full context. It also fixes a latent bug in worktree alternates handling (unresolved common directory paths) and consolidates alternates logic into a single code path.
- **Test coverage**: Updated in `t/t5604-clone-reference.sh` to verify new behavior, including edge cases for worktree clones and relative path resolution.

The series is well-motivated and addresses feedback from v2, particularly around the lockfile API adoption and the refactoring of `init_db()`. The changes are mechanical but foundational, aligning with the broader ODB abstraction goal of making alternates an implementation detail of the backend. Reviewers will likely focus on ensuring the refactoring doesn’t introduce regressions in clone behavior or alternates handling, though the series appears uncontroversial given its incremental nature and clear technical rationale. The removal of the `write_alternates()` callback simplifies the ODB interface, and the lockfile API adoption ensures safety against partial writes or corruption.

The series is ready for review, with patches 1-2 introducing the `create_repository()` refactoring and patches 3-9 largely unchanged from v2 (except for minor typo fixes). The most significant discussion point may be the architectural shift in repository initialization, though Patrick’s approach—moving command-specific logic out of `init_db()`—seems reasonable and aligns with the goal of simplifying the interface.
