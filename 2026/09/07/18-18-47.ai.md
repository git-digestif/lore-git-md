This is a design counterproposal in the `post-worktree` hook thread. Kristoffer Haugsbakk suggests replacing the proposed unified `post-worktree` hook with a `--id=<string>` option for `git worktree add`. The ID would be stored in the worktree and used to enforce ownership: any `git worktree` command (remove, prune, move) would only act on worktrees that either lack an ID or match the provided `--id`. This would allow cooperating processes (IDEs, AI agents, devenv) to manage their own worktree pools without interference from uncontrolled callers, eliminating the need for lifecycle hooks entirely.

The proposal is lightweight: it requires no new hooks, no new config, and no changes to the on-disk format beyond storing the ID. Kristoffer sketches additional metadata (e.g., expiry timestamps) that tools could implement on top of the ID without further Git changes. The core idea is that ownership, not observability, is the real problem: if tools can mark worktrees as theirs, they can manage lifecycle events themselves without racing or relying on Git to notify them.

This is a substantive alternative to Domen Kožar’s compromise. It directly addresses the uncontrolled-caller scenario (the original motivation for hooks) by making it impossible for one tool to accidentally remove another’s worktree.
