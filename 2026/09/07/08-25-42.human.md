This is the fifth patch in Patrick Steinhardt’s nine-patch series refactoring how Git handles ODB alternates during repository creation, part of the ongoing ODB abstraction effort. The patch moves the logic for setting up alternates in shared local clones (`git clone --shared`) from `clone_local()` into `collect_alternates()`, consolidating alternates handling into a single code path.

The change is mechanical but meaningful: it unifies the setup of alternates for both `--reference` and `--shared` clones, preparing for the later patches that will write alternates during ODB creation rather than as a separate step. The patch updates `collect_alternates()` to accept `src_repo` and `is_local` parameters, allowing it to handle local clones directly. For shared local clones, it resolves the common directory of the source repository and adds its `objects` directory to the alternates list. Non-shared local clones continue to use the existing `clone_local()` logic, which will be addressed in the next patch.

The diff is clean and focused, touching only `builtin/clone.c`. The change reduces duplication and aligns with the series’ goal of simplifying the ODB interface by making alternates an implementation detail of the backend. No user-visible behavior changes are introduced, and the patch is uncontroversial—it’s a straightforward refactoring that sets the stage for the more substantial changes in patches 6-9. Reviewers may verify that the reordering doesn’t introduce regressions in edge cases (e.g., relative paths or worktree handling), but the patch itself looks solid and well-motivated.
