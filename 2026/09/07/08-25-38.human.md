This is the first patch in Patrick Steinhardt’s 9-patch series refactoring how Git initializes repositories, part of the ongoing ODB abstraction effort. The patch splits `init_db()` into a new `create_repository()` function that handles only the creation of the repository skeleton—directories, config files, and templates—without setting up the object or reference databases. This eliminates the need for the `SKIP_REFDB` flag (and a future `SKIP_ODB` flag) and moves command-specific logic, like printing initialization messages, into the commands themselves (`git init` and `git clone`).

The change is mechanical but foundational. `create_repository()` now takes a `reinit_ok` pointer to indicate whether reinitializing an existing repository is allowed, replacing the `EXIST_OK` flag. The `QUIET` flag is also removed, as the initialization message is now handled by `git init`. The patch updates both `builtin/clone.c` and `builtin/init-db.c` to use the new function and defer ODB/refdb setup until later in the command flow. This refactoring simplifies the interface and prepares for the series’ later patches, which will consolidate alternates handling into ODB creation.

The patch is well-motivated and addresses feedback from earlier versions, particularly Justin Tobler’s concern about the growing complexity of `init_db()`’s skip flags. The new design is cleaner and more flexible, though reviewers will likely focus on ensuring the refactoring doesn’t introduce regressions in repository initialization or command behavior. The changes are uncontroversial given their incremental nature and clear technical rationale.
