This is the fifth patch in brian m. carlson’s seven-patch RFC series proposing to restrict Git 3.0 to lowercase-only hex object IDs. The patch replaces an open-coded hex-parsing loop in `object-name.c` with the new `hexval()` helper introduced earlier in the series. The change is preparatory: it preserves the existing behavior (forcing hex digits to lowercase) while paving the way for the final patch’s enforcement of lowercase-only parsing.

The commit message explains the rationale clearly: the open-coded implementation is slower (not table-driven) and lacks constant-time guarantees, making it strictly inferior to the shared `hexval()` helper. The patch also adopts the defensive pattern (`val & ~0xff`) to safely check for invalid hex digits, addressing Elijah Newren’s correctness concern from the v1 review. One behavioral subtlety is noted: the new code continues to force hexadecimal values to lowercase, maintaining compatibility during the transition period.

The diff itself is minimal—11 lines removed, 4 added—touching only the `parse_oid_prefix()` function in `object-name.c`. The change is mechanical: replace the manual hex-digit checks with a call to `hexval(c, HEX_KIND_OID)` and adjust the error-checking logic to match the helper’s return type. The patch does not alter runtime behavior, but it does document the lowercase-forcing step explicitly, which will be important when the final patch activates enforcement.

This patch is uncontroversial on its own; the thread’s focus remains on whether the project will accept the breaking change in the seventh patch. Junio’s review of v2 flagged no issues here, and the implementation addresses all prior feedback. The only open question is whether the series as a whole will proceed, but this patch is ready for integration if the project decides to move forward.
