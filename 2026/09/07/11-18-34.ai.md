This is a refactoring series that standardizes Git's terminology for "ref storage format" across CLI options, environment variables, config keys, and documentation. The v2 iteration, authored by Patrick Steinhardt, addresses feedback from Junio C Hamano and Karthik Nayak by adopting `--ref-storage-format=` (and related names) to explicitly distinguish the ref storage format from the object hash format. The series also centralizes URI parsing for ref storage backends, enabling `--ref-storage-format=` to accept URIs like `files://path/to/repo`, and fixes a bug where reinitializing a repository with a different ref storage format silently corrupted it.

Key changes in v2:
- Renames `--ref-format=` to `--ref-storage-format=` across all commands (`init`, `clone`, `refs`, `submodule`, `rev-parse`).
- Updates environment variables (`GIT_REFERENCE_BACKEND` → `GIT_REF_STORAGE_FORMAT`, `GIT_DEFAULT_REF_FORMAT` → `GIT_DEFAULT_REF_STORAGE_FORMAT`) and config keys (`init.defaultRefFormat` → `init.defaultRefStorageFormat`), retaining backward-compatible aliases.
- Fixes the `argh` placeholder for `--ref-storage-format=` to use `"format"` (e.g., `--ref-storage-format=<format>`), resolving an inconsistency noted by Karthik Nayak.
- Adds the missing `GIT_DEFAULT_REF_STORAGE_ENVIRONMENT` macro to `environment.h` (addressing Karthik's feedback).
- Reorders precedence rules so `--ref-storage-format=` overrides environment variables, aligning with Git's usual precedence.
- Enforces immutability of the existing repository format to prevent silent corruption on reinitialization.

The motivation remains clear: resolving inconsistencies ahead of the upcoming "object storage" extension, which will use analogous `--object-storage-format=` options.
