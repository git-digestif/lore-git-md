This is a **bugfix discussion** about a serious data-loss scenario in `git pull`.

Brian M. Carlson responds to the original bug report, confirming the issue but pushing back on both proposed fixes. He explains that `.gitignore` patterns with trailing slashes (`dir/`) are designed to ignore *contents* of directories, not the directories or symlinks themselves, so the current behavior is intentional. He also notes that `git checkout` (and by extension `git pull`) already overwrites ignored files and directories by default, and that this behavior is documented.

Carlson argues that changing `.gitignore` to also ignore symlinks would be inconsistent and potentially confusing, since symlinks might point to files or non-existent targets. He also warns that making `git pull` refuse to overwrite directories with symlinks would break existing tooling. Instead, he recommends treating the root cause: users should not store valuable data in ignored or untracked files within the working tree. He links to a past proposal for a `precious` attribute that could protect such files, but notes it was never implemented.

The discussion is now at an impasse. The original report highlights a real and severe data-loss risk, but Carlson’s response suggests the project is unlikely to change core behavior without a more targeted solution. The thread is still open; no patch has been posted, and no maintainer has weighed in. If a fix emerges, it will likely need to address the `precious` attribute idea or introduce a new safety mechanism without breaking backwards compatibility.
