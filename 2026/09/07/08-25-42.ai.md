This is patch 5/9 in Patrick Steinhardt’s ODB alternates refactoring series, part of the ongoing ODB abstraction effort. The patch moves the setup of alternates for shared local clones (`git clone --shared`) from `clone_local()` into `collect_alternates()`, consolidating all alternates logic into a single code path. This prepares for the later patches (6-9) that will write alternates during ODB creation rather than as a separate step.

The change is mechanical: `collect_alternates()` gains two new parameters (`src_repo` and `is_local`) and now handles the `--shared` case by pushing the source repository’s objects directory into the alternates `strvec`. The manual call to `odb_add_to_alternates_file()` in `clone_local()` is removed, leaving only the non-shared clone logic (which will be addressed in the next patch). The patch also updates the call site in `cmd_clone()` to pass the new parameters.

This is a preparatory refactoring with no user-visible behavior change. The motivation is to unify alternates handling before the series switches to writing alternates during ODB creation, which requires all alternates paths to be known upfront. The patch is uncontroversial and aligns with the series’ goal of simplifying the ODB interface by making alternates an implementation detail of the backend.

The diff touches only `builtin/clone.c`, adding 14 lines and removing 9. The new logic in `collect_alternates()` mirrors the existing pattern for `--reference` and `--reference-if-able` alternates, using `get_common_dir()` to resolve the source repository’s objects directory. The patch does not yet handle the `--no-shared` case for local clones, which is deferred to the next commit.

Reviewers will likely focus on whether the refactoring introduces edge cases (e.g., path resolution for worktrees or relative paths), though the patch appears straightforward. The consolidation of alternates logic is a necessary step for the lockfile API adoption in patch 6, which resolves TOCTOU race and concurrent access concerns raised in earlier versions. No test failures are expected, as the patch preserves existing behavior.
