Subject: stash.index=true + --autostash during fast-forward merge leaves redundant stash entry and MERGE_AUTOSTASH ref
Series version: none (standalone bug report)
Originating author: Eli Barzilay
Thread type: bug report

Core problem or goal
A bug in Git 2.55.0 (and current master) causes `git merge --ff-only --autostash` (and by extension `git pull` with `rebase.autoStash` and `pull.rebase`) to leave behind a redundant stash entry and fail to clean up the `MERGE_AUTOSTASH` ref when `stash.index=true` is set and a staged change exists at merge time. The operation succeeds but emits an error message, and the stash list contains an extra entry.

Current status
Under review. The bug is confirmed, reproducible, and a fix has been implemented. D. Ben Knoble replaced the subprocess-heavy index-merge logic (`git diff-tree`, `git apply --cached`, `git reset`) with a direct call to `merge_incore_nonrecursive()`, resolving the root cause (premature `MERGE_AUTOSTASH` ref deletion) while improving performance and code clarity. Phillip Wood reviewed the patch, confirming it works and suggesting minor polish: silencing merge verbosity (since conflicts already trigger an abort), simplifying conflict-label setup, and using `oidcpy()` instead of direct OID assignment for robustness. The patch is now one cleanup pass away from formal submission as a series.

Key technical details
- Subsystems: stash, merge, ref management
- Files touched by the fix: `sequencer.c` (primary), with implications for `builtin/merge.c`, `builtin/stash.c`, and `branch.c`
- Symbols involved: `MERGE_AUTOSTASH` ref, `merge_incore_nonrecursive()`, `merge_ort_nonrecursive()`, `info->i_tree`, `info->w_tree`, `reset_head()`, `remove_merge_branch_state()`
- Old behavior: `MERGE_AUTOSTASH` ref was deleted prematurely during `stash apply --index` (via `reset_head()` → `remove_merge_branch_state()`), causing a duplicate stash entry and a later "ref not found" error
- New behavior: `merge_incore_nonrecursive()` is called directly to merge the index (`info->i_tree`), preserving `MERGE_AUTOSTASH` until autostash apply completes and eliminating three subprocess spawns
- Test coverage: reproduction script provided by Eli Barzilay; D. Ben Knoble and Phillip Wood confirm reproducibility and fix validation locally. No formal test in the suite yet.

Open questions and loose ends
