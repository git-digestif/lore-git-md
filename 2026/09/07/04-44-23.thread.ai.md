Subject: stash.index=true + --autostash during fast-forward merge leaves redundant stash entry and MERGE_AUTOSTASH ref
Series version: none (standalone bug report)
Originating author: Eli Barzilay
Thread type: bug report

Core problem or goal
A bug in Git 2.55.0 (and current master) causes `git merge --ff-only --autostash` (and by extension `git pull` with `rebase.autoStash` and `pull.rebase`) to leave behind a redundant stash entry and fail to clean up the `MERGE_AUTOSTASH` ref when `stash.index=true` is set and a staged change exists at merge time. The operation succeeds but emits an error message, and the stash list contains an extra entry.

Current status
Fix implemented and polished; ready for formal submission. D. Ben Knoble replaced the subprocess-heavy index-merge logic (`git diff-tree`, `git apply --cached`, `git reset`) with a direct call to `merge_incore_nonrecursive()`, resolving the root cause (premature `MERGE_AUTOSTASH` ref deletion) while improving performance and code clarity. Phillip Wood’s substantive review feedback has been incorporated: merge verbosity is now silenced (since conflicts already trigger an abort), conflict-label setup is simplified (passing `""` instead of full labels), and `oidcpy()` is used instead of direct OID assignment for robustness. The patch is now ready for submission as a formal series, likely targeting `master` and possibly `maint` for backport consideration.

Key technical details
- Subsystems: stash, merge, ref management
- Files touched by the fix: `sequencer.c` (primary), with implications for `builtin/merge.c`, `builtin/stash.c`, and `branch.c`
- Symbols involved: `MERGE_AUTOSTASH` ref, `merge_incore_nonrecursive()`, `merge_ort_nonrecursive()`, `info->i_tree`, `info->w_tree`, `reset_head()`, `remove_merge_branch_state()`, `refresh_index()`, `oidcpy()`
- Old behavior: `MERGE_AUTOSTASH` ref was deleted prematurely during `stash apply --index` (via `reset_head()` → `remove_merge_branch_state()`), causing a duplicate stash entry and a later "ref not found" error. The subprocess-based approach (`git diff-tree`, `git apply --cached`, `git reset`) left the index in a state where Git incorrectly believed the worktree had unstaged changes due to cleared stat data and `CE_UPTODATE` flags.
- New behavior: `merge_incore_nonrecursive()` is called directly to merge the index (`info->i_tree`), preserving `MERGE_AUTOSTASH` until autostash apply completes, eliminating three subprocess spawns, and avoiding index corruption. The fix also silences merge verbosity (via `verbosity=0`), simplifies conflict-label setup (passing `""`), and uses `oidcpy()` for OID assignment.
- Test coverage: reproduction script provided by Eli Barzilay; D. Ben Knoble and Phillip Wood confirm reproducibility and fix validation locally. No formal test in the suite yet.
