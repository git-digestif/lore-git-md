This is the fourth patch in Patrick Steinhardt’s nine-patch series refactoring how Git handles ODB alternates during repository creation. The series is part of the ongoing ODB abstraction effort, and this patch specifically prepares for consolidating alternates setup by refactoring the `--reference` and `--reference-if-able` logic in `git clone`.

The patch renames `setup_reference()` to `collect_alternates()` and changes its behavior to gather alternates paths into a `strvec` instead of immediately writing them to the object database. This is a mechanical but important step toward the series’ goal of deferring alternates writing until ODB creation, which will simplify the interface and resolve TOCTOU race concerns. The new `collect_alternates()` function loops through the required and optional reference paths, validates them, and stores their resolved object directories in the provided `strvec`. The patch also introduces a helper struct, `add_one_alternate_data`, to track whether an alternate is required and to hold the `strvec` of paths.

The changes are confined to `builtin/clone.c` and are straightforward: the logic is essentially the same, but the alternates are now collected for later use rather than written immediately. This refactoring enables subsequent patches (notably patch 6) to write alternates during ODB creation using Git’s lockfile API, ensuring atomic writes and resolving concurrency issues. The patch is well-motivated and aligns with the series’ broader design, though it doesn’t yet change user-visible behavior.

Reviewers may focus on whether the refactoring introduces any edge cases (e.g., error handling for invalid paths) or regressions in how alternates are resolved, but the patch appears uncontroversial. The commit message clearly explains the rationale, and the code changes are minimal and focused. This patch is a necessary stepping stone for the more substantial changes in later patches, particularly the lockfile API adoption and the removal of the `write_alternates()` callback.
