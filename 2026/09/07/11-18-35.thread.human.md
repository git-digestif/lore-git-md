This thread is about a cleanup series from Patrick Steinhardt that tackles a naming inconsistency in Git’s reference storage options. The current `--ref-format=` command-line flag doesn’t align with the repository extension `refStorage`, the environment variable `GIT_REFERENCE_BACKEND`, or the common documentation term “ref storage format.” The first patch in the 11-part series renames the flag to `--ref-storage-format=` in `git init`, updates man pages and test scripts, and retains the old flag as a hidden alias for backward compatibility. The change is mechanical, touching mostly documentation and tests, and sets the stage for a future `--object-storage-format=` option without creating further naming clashes.

The series is just getting started, so there’s no review feedback or decisions yet. If you’ve been following Git’s ref backend work, this is a small but important step toward clearer naming as the project continues to evolve its storage layer. Keep an eye out for the rest of the patches—this is the kind of cleanup that makes future changes easier to reason about.
