This is the final patch in Patrick Steinhardt’s 11-patch series standardizing Git’s ref-storage terminology. It enables the `--ref-storage-format=` option in `git init` and `git clone` to accept URIs with payloads (e.g., `files://path/to/alt-refs` or `reftable://path/to/db`), completing the series’ functional scope.

The patch updates the CLI option to parse URIs instead of plain format names, using the `ref_storage_format_by_uri()` helper introduced earlier. It documents the URI syntax for the "files" and "reftable" backends, which can now accept an alternate refs directory or database path via the payload. The implementation enforces immutability of the ref-storage payload during reinitialization, preventing silent corruption if a mismatched payload is specified. Two new tests in `t/t1423-ref-backend.sh` verify URI handling and reinitialization behavior.

Files touched include `builtin/init-db.c`, `builtin/clone.c`, `setup.c`, `setup.h`, and documentation. The changes are mechanical and well-tested, with no functional regressions expected. This patch is a logical capstone to the series, enabling the URI-based configuration that motivated the earlier refactoring.
