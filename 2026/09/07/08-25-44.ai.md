This is the seventh patch in Patrick Steinhardt’s 9-patch series refactoring ODB alternates handling during repository creation, part of the ongoing ODB abstraction effort. The patch implements the core design change: alternates are now written during ODB creation using Git’s lockfile API, replacing the previous append-mode approach that raised TOCTOU race and concurrent access concerns in earlier versions.

The patch extends `odb_source_files_create_on_disk()` to accept an `odb_create_on_disk_options` struct containing a `strvec` of alternates paths. When alternates are provided, the function writes them to `info/alternates` using a lockfile, ensuring atomic writes and avoiding partial corruption. It also handles preexisting alternates (e.g., from template directories) by reading and deduplicating them before writing the new entries. The lockfile is committed only after all writes succeed, and the object database is reprepared to activate the new alternates. The `odb_source_create_on_disk()` inline helper is updated to pass the options struct through to the backend.

Key technical details:
- **Files touched**: `odb/source-files.c` (implements alternates writing during ODB creation), `odb/source.h` (adds `odb_create_on_disk_options` struct and updates the `create_on_disk` callback signature), and `setup.c` (updates `create_object_database()` to pass an empty options struct).
- **New symbols**: `odb_create_on_disk_options` (carries alternates for ODB creation), and the updated `odb_source_files_create_on_disk()` callback.
- **Subsystems**: ODB (object database), alternates handling, lockfile API.
- **Behavior changes**: No user-visible changes. Alternates are now written atomically during ODB creation, resolving TOCTOU race and concurrent access concerns. The patch prepares for the removal of the `write_alternates()` callback in patch 9/9.
- **Safety**: The lockfile API ensures alternates are written safely, even in concurrent repository creation scenarios. The patch also handles preexisting alternates (e.g., from templates) by reading and deduplicating them before writing new entries.

The patch is well-motivated and addresses the primary security concern raised by Junio C Hamano in v1 (TOCTOU race with append-mode writes). The lockfile adoption is a clear improvement, and the implementation is thorough, handling edge cases like preexisting alternates and deduplication. The patch is uncontroversial and aligns with the series’ goal of simplifying the ODB interface by moving alternates handling into the backend. Reviewers may focus on the lockfile cleanup logic (e.g., rollback on error) and the reprepare step, but the implementation appears solid. The patch is a key step toward removing the `write_alternates()` callback and consolidating alternates logic into a single code path.
