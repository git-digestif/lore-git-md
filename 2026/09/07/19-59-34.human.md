This is the first patch in a seven-part RFC series proposing a breaking change for Git 3.0: restricting hex object IDs to lowercase only. The series aims to eliminate compatibility and security risks for external tools that assume hex uniqueness, and this patch lays the groundwork by introducing infrastructure for lowercase-only hex parsing.

The patch adds a new `hex_kind` enum (`HEX_KIND_MIXED`, `HEX_KIND_LOWER`) and a `hexval_lc_table` that rejects uppercase hex digits. The existing `hexval()` function is updated to accept an `enum hex_kind` parameter, allowing callers to choose between mixed-case and lowercase-only parsing. For now, all callers use `HEX_KIND_MIXED`, so runtime behavior remains unchanged. The patch touches four files: `hex-ll.c` (new table and updated `hex_to_bytes()`), `hex-ll.h` (enum and function signature changes), `color.c` (updated call to `hexval()`), and `pkt-line.c` (updated packet-length parsing).

This is a refactoring patch with no behavioral changes, but it’s clearly well-crafted. The commit message explains the motivation and the technical approach, and the implementation is clean: the new table is straightforward, the enum is self-documenting, and the changes to existing functions are minimal. The patch is part of a larger effort to enforce lowercase-only parsing in Git 3.0, and it’s the first step in a series that has already addressed all review feedback from the initial RFC. If the project decides to proceed with the breaking change, this patch will be uncontroversial. For now, it’s a quiet but necessary piece of infrastructure.
