This is the tenth patch in Patrick Steinhardt’s v2 series unifying Git’s terminology for "ref storage format." It renames the config key `init.defaultRefFormat` to `init.defaultRefStorageFormat` while retaining the old name as a backward-compatible alias.

The change is mechanical and aligns with the rest of the series, which has already renamed CLI options (`--ref-format=` → `--ref-storage-format=`), environment variables (`GIT_REFERENCE_BACKEND` → `GIT_REF_STORAGE_FORMAT`), and documentation. The patch updates `setup.c` to check both the new and old config keys, ensuring scripts or tools using the old name continue to work. Test scripts (`t/t0001-init.sh`) are updated to reflect the new config key name, and documentation (`BreakingChanges.adoc`, `config/feature.adoc`, `config/init.adoc`) is adjusted for consistency.

No functional changes are introduced; this is purely a terminology cleanup. The patch is well-motivated as part of the broader effort to standardize naming ahead of the upcoming `--object-storage-format=` extension. The backward-compatible alias minimizes disruption, and the test coverage ensures the rename doesn’t break existing workflows. The series as a whole looks ready for merging once any remaining edge cases (e.g., URI handling) are reviewed.
