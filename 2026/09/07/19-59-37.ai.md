This is the fourth patch in brian m. carlson’s seven-patch RFC series proposing a Git 3.0 breaking change: restricting hex object IDs to lowercase only. The series is in its second iteration and addresses all feedback from the initial RFC.

This patch is purely preparatory and introduces no behavioral changes. It labels hex-parsing calls that are specifically for object IDs by defining a new constant, `HEX_KIND_OID`, and updating the relevant call sites in `diagnose.c`, `hex.c`, `http-push.c`, `notes.c`, and `object-file.c` to use it instead of `HEX_KIND_MIXED`. The constant is currently defined as an alias for `HEX_KIND_MIXED`, so the runtime behavior remains unchanged. The change is mechanical and touches six files, all of which are core to object ID parsing from disk or network paths.

The patch directly addresses Junio C Hamano’s review feedback from v1, where he noted that `builtin/index-pack.c` and `notes.c` should use `HEX_KIND_OID` instead of `HEX_KIND_MIXED` to clearly distinguish object ID parsing from other hex-parsing contexts. This labeling sets the stage for the seventh patch, which will redefine `HEX_KIND_OID` as `HEX_KIND_LOWER` when `WITH_BREAKING_CHANGES` is enabled, enforcing the lowercase-only restriction.

The implementation is straightforward and uncontroversial: the new constant is added to `hex-ll.h`, and the call sites are updated with a simple search-and-replace. No new tests are introduced, as the patch does not alter behavior. The patch is technically sound and ready for integration, assuming the project proceeds with the series. The thread’s focus remains on whether the project will accept the breaking change, but this patch itself is a low-risk infrastructure step.
