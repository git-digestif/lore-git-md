This is a small refactoring patch in Patrick Steinhardt’s eleven-part series to unify Git’s terminology for "ref storage format." This specific patch updates the build-info output in `git version --build-options` to rename the `default-ref-format` field to `default-ref-storage-format`, aligning it with the rest of the series.

The change is mechanical: it updates one line in `help.c` and the corresponding test in `t/t0001-init.sh`. The motivation is consistency—this is the last remaining place where Git still refers to "ref-format" instead of "ref-storage-format," and the series aims to eliminate that inconsistency before Git 3.0 switches the default ref backend from "files" to "reftable."

No functional changes are introduced; the patch is purely about naming. The test adjustment ensures the build-info output continues to match the expected format. This is a well-justified cleanup that fits neatly into the larger effort.
