This is Patrick Steinhardt’s reply to Junio C Hamano’s design-level concern about the "ref-storage" vs. "ref-format" terminology in the v1 series unifying Git’s ref storage terminology. Patrick concedes the ambiguity and proposes adopting Junio’s suggestion to rename the CLI option to `--ref-storage-format=` (and the analogous `--object-storage-format=` for future object storage extensions), resolving the scope conflict with `--object-format=` (which controls the hash algorithm). The revised naming explicitly distinguishes storage format from object hash, clearing the way for the planned object storage extension. This change will ripple through the entire series, requiring updates to environment variables (`GIT_REF_STORAGE_FORMAT`), config keys (`init.defaultRefStorageFormat`), documentation, and tests. The series’ core goals—consistency, URI support, and immutability enforcement—remain unchanged, but the terminology shift addresses Junio’s objection and may reduce future confusion. Expect a v2 with these adjustments.
