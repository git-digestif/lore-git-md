This is patch 4/9 of Patrick Steinhardt’s ODB abstraction series, refactoring how `git clone` handles `--reference` and `--reference-if-able` options. The patch renames `setup_reference()` to `collect_alternates()` and changes its behavior to gather alternates paths into a `strvec` instead of immediately writing them to the object database. This prepares for later patches (6-7) that will consolidate alternates setup into `create_object_database()` and remove the manual `odb_add_to_alternates_file()` calls.

The change is mechanical and well-motivated: the new `collect_alternates()` function now iterates over both `option_required_reference` and `option_optional_reference`, using a `struct add_one_alternate_data` to track whether an alternate is required and to hold the `strvec` of paths. The `add_one_reference()` helper is renamed to `add_one_alternate()` and updated to push paths to the `strvec` rather than writing them directly. The `cmd_clone()` function now calls `collect_alternates()` before ODB creation and manually writes the gathered alternates afterward, though this manual step will be removed in patch 7.

The patch touches only `builtin/clone.c` and introduces no user-visible behavior changes. It is a straightforward refactoring that aligns with the series’ goal of consolidating alternates handling into a single code path during ODB creation. The new `struct add_one_alternate_data` and `strvec` usage are clear and maintain the existing logic for required vs. optional alternates. Reviewers may focus on whether the refactoring introduces any edge-case regressions (e.g., error handling for invalid alternates paths), though the patch appears uncontroversial given its incremental nature and clear technical rationale.

Key symbols introduced or modified: `collect_alternates()`, `add_one_alternate()`, `struct add_one_alternate_data`, and the `alternates` `strvec` in `cmd_clone()`. The patch retains `odb_add_to_alternates_file()` for now, but this will be removed in later patches. The refactoring is part of the broader effort to simplify the ODB interface by making alternates an implementation detail of the backend.
