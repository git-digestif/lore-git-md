This is the second patch in brian m. carlson’s seven-part RFC series proposing a Git 3.0 breaking change: restricting hex object IDs to lowercase only. This patch is purely preparatory and introduces no behavioral changes. It modifies the `hex2chr()` helper to accept an `enum hex_kind` parameter, allowing callers to specify whether they want to parse lowercase-only hex or mixed-case hex. The change touches seven files (`hex-ll.h`, `hex.c`, `mailinfo.c`, `ref-filter.c`, `strbuf.c`, `url.c`, `urlmatch.c`), all of which currently use `hex2chr()` for tasks like percent-encoding, quoted-printable decoding, and object ID parsing.

The patch is mechanical and straightforward: it adds the `kind` parameter to `hex2chr()`’s signature and propagates it to the two `hexval()` calls inside the function. All existing callers are updated to pass `HEX_KIND_MIXED`, preserving their current behavior. The motivation is to prepare for the later patch (7/7) that will enforce lowercase-only parsing for object IDs by setting `HEX_KIND_OID` to `HEX_KIND_LOWER` when `WITH_BREAKING_CHANGES` is enabled.

The implementation is clean and well-scoped, addressing only the plumbing needed for the eventual breaking change. The commit message clearly explains the purpose and the preparatory nature of the patch. No test failures or behavioral regressions are expected, and the patch does not alter any on-disk formats or user-visible behavior. This is a typical refactoring step in a larger series, and it looks ready for review if the project decides to proceed with the breaking change.
