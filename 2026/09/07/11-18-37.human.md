This is the third patch in Patrick Steinhardt’s v2 series to unify Git’s terminology for "ref storage format." It renames the `--ref-format=` option to `--ref-storage-format=` in the `git refs` command, keeping the old name as a hidden backward-compatible alias.

The patch touches six files: the `git-refs` man page, `builtin/refs.c` (the implementation), `builtin/fetch.c` (an error-message update), and three test scripts (`t1423-ref-backend.sh`, `t1460-refs-migrate.sh`, and `t7424-submodule-mixed-ref-formats.sh`). The changes are mechanical—replacing option names and updating help text—with no functional behavior change. The backward-compatible alias ensures scripts using the old option name continue to work.

This patch is part of the broader effort to standardize terminology ahead of the upcoming `--object-storage-format=` extension. The series is well-motivated, and this patch is uncontroversial: it aligns with the resolved design direction (using `--ref-storage-format=` to distinguish storage format from object hash) and addresses prior feedback about option naming. The test updates are thorough, covering both positive and negative cases (e.g., missing or unknown formats). No new edge cases or open questions are introduced here.
