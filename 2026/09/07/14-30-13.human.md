This is a design-discussion ping on Domen Kožar’s proposed compromise for worktree lifecycle hooks. The thread is part of an ongoing series that originally introduced three separate hooks (`post-worktree-add`, `post-worktree-remove`, `post-worktree-move`) but is now revisiting the design after Junio C Hamano objected to the necessity of any hooks at all.

Domen’s compromise narrows the interface to a single `post-worktree` hook with subcommands (`add`, `remove`, `move`). The hook would pass the worktree ID, absolute paths, and (for `move`) the old path, running in the appropriate worktree directory or the main worktree for removals. The core argument remains observability: external tools (IDEs, AI agents, environment managers) need a reliable way to detect worktree events even when those events are triggered by uncontrolled callers—users running `git worktree remove` directly, or IDEs invoking `git worktree prune`. Domen cites racing conditions, damaged entries, and the impracticality of requiring all callers to use a wrapper as reasons a Git-native hook is justified.

The email is a gentle ping asking Junio whether this unified interface meets his bar for acceptance. No updated patches are attached; this is purely a design checkpoint. Domen signals willingness to prepare a v3 if the direction is agreed upon, but the thread is stalled pending Junio’s response.
