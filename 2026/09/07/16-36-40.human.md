This is the latest exchange in the ongoing patch series that defers auto maintenance until the end of sequencer-driven operations (`git rebase`, `git cherry-pick`, `git revert`). The series is now in its third iteration (v3) and is technically complete, with all prior feedback addressed.

Thomas Bachem responds to Phillip Wood’s review of the second patch in the v2 series, which adds `run_auto_maintenance()` calls to key exit paths in the sequencer. The discussion centers on commit message clarity, test improvements, and a proposed design change for where maintenance is invoked. Thomas agrees to reword the commit message for clarity (e.g., replacing ambiguous phrasing with "The merge backend which is also used by 'git cherry-pick' and 'git revert' does not run it when it finishes") and to improve test coverage by asserting that auto maintenance does *not* run during intermediate steps (e.g., before `git rebase --continue`). He also plans to use `test_grep` instead of `grep` for better test failure output and to consolidate test coverage by extending existing tests rather than duplicating them.

The most significant development is Thomas’s proposal to move the maintenance call out of the sequencer entirely and delegate it to the callers (`run_specific_rebase()` for `rebase`, `run_sequencer()` for `cherry-pick`/`revert`). This would consolidate maintenance into a single exit path per command, aligning with the apply backend’s design and simplifying the rule to "the command runs maintenance once when done." This responds directly to Patrick Steinhardt’s preference for a unified exit path and addresses the structural issue of scattered `run_auto_maintenance()` calls. Phillip Wood has not objected to this approach, and it appears likely to be adopted in v3.

No substantive technical objections remain. The only open items are minor: documenting the format of `GIT_CONFIG_PARAMETERS` (noted by Patrick Steinhardt), monitoring real-world usage for edge cases (e.g., very long sequences where mid-sequence repacking might help), and test hygiene improvements. The series is on track for integration, pending the author’s incorporation of the latest feedback.
