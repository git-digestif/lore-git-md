This is the second patch in brian m. carlson’s seven-patch RFC series preparing Git 3.0 to enforce lowercase-only hex object IDs. It is a purely mechanical refactoring that adds an `enum hexkind` parameter to the `hex2chr()` helper, allowing callers to specify whether they want to accept mixed-case hex (`HEX_KIND_MIXED`) or lowercase-only (`HEX_KIND_LOWER`). The patch updates all existing call sites to pass `HEX_KIND_MIXED`, preserving the current runtime behavior. No new functionality is introduced; this is infrastructure for the later breaking change.

The patch touches seven files: `hex-ll.h` (the function declaration), `hex.c` (object ID parsing), `mailinfo.c` (quoted-printable decoding), `ref-filter.c` (ref formatting), `strbuf.c` (percent-encoding), and `url.c`/`urlmatch.c` (URL percent-decoding). All changes are one-line substitutions replacing the hard-coded `HEX_KIND_MIXED` with the new parameter. The commit message is minimal but sufficient: it states the purpose (future enforcement of lowercase-only parsing) and the immediate effect (no behavior change).

This patch is uncontroversial and technically sound. It addresses the feedback from v1 by adopting the defensive pattern (`val & ~0xf`) introduced in the first patch, ensuring correctness. The only unresolved technical question from the thread—whether `hexval()` table selection should be hoisted outside loops for micro-optimization—does not affect this patch, as `hex2chr()` is not used in hot loops. The patch is ready for integration if the series proceeds.
