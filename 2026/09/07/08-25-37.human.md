This is the third iteration of Patrick Steinhardt’s 9-patch series refactoring how Git handles object database (ODB) alternates during repository creation. The series is part of the ongoing ODB abstraction effort and builds on earlier work (`ps/odb-eagerly-load-alternates`).

The core goal remains unchanged: eliminate the ability to write alternates after repository creation, simplifying the ODB interface. The key change in v3 is a major refactoring of `init_db()` into `create_repository()`, which now only creates the repository skeleton (directories, config files) without initializing the refdb or ODB. This removes the need for skip flags (`INIT_DB_SKIP_REFDB`, `INIT_DB_SKIP_ODB`) and moves command-specific logic (e.g., printing messages, handling preexisting repos) into the commands themselves. The new design is cleaner and more intuitive, as `git clone` and `git init` now explicitly set up the refdb and ODB after repository creation.

Patches 1 and 2 implement this refactoring. Patch 1 splits `init_db()` into `create_repository()` (skeleton creation) and updates `git init` to call `create_reference_database()` and `create_object_database()` explicitly. Patch 2 updates `git clone` to defer ODB setup until after URI resolution and alternates collection, aligning with the series’ goal of consolidating alternates logic. The remaining patches (3-9) are largely unchanged from v2, with minor typo fixes and mechanical adjustments to accommodate the new `create_repository()` interface. Patch 7 (writing alternates during ODB creation) still uses the lockfile API to resolve TOCTOU races, and patch 9 removes the now-unused `write_alternates()` infrastructure.

The series touches `builtin/clone.c`, `builtin/init-db.c`, `setup.c`/`setup.h`, and several ODB source files. No user-visible behavior changes are expected, but the refactoring fixes a latent bug in worktree alternates handling (patch 6) and consolidates alternates logic into a single code path. The changes are well-motivated and align with the broader ODB abstraction effort, though the new `create_repository()` interface may prompt discussion about whether it strikes the right balance between simplicity and flexibility.

This iteration addresses the architectural concerns raised in v2 about `init_db()`’s growing complexity. The refactoring is a significant improvement, but reviewers may want to verify that the new interface doesn’t introduce regressions in edge cases (e.g., template directory handling, quiet mode). The series is now more focused and ready for deeper technical review, particularly from ODB-focused contributors like Karthik Nayak and Justin Tobler.
