This is the third patch in Beat Bolli’s three-part series improving `git imap-send`’s TLS certificate verification. It enforces RFC 6125 section 6.4.4: the subject common name (CN) must **not** be checked if the certificate contains any DNS subject alternative names (SANs). The patch adds a flag (`has_san_dns`) that tracks whether any SAN DNS entries were seen; if they were and none matched, the code now returns an error immediately instead of falling back to the CN. The change is minimal—only nine lines added—and the commit message cites both the RFC and a precedent in HAProxy, making the motivation clear. No new tests are introduced, but the logic is straightforward and the edge case it fixes is well-documented in the standard. This is a correctness fix that aligns Git’s behavior with modern security best practices.
