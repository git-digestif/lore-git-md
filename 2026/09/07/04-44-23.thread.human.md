The thread began when Eli Barzilay reported a bug in Git 2.55.0 where `git merge --ff-only --autostash` (and `git pull` with `rebase.autoStash` and `pull.rebase`) leaves behind a redundant stash entry and fails to clean up the `MERGE_AUTOSTASH` ref when `stash.index=true` is set and staged changes exist. The operation succeeds but emits an error, cluttering the stash list.

D. Ben Knoble confirmed the bug, reproduced it, and implemented a fix that replaces the original subprocess-heavy index-merge logic (`git diff-tree`, `git apply --cached`, `git reset`) with a direct call to `merge_incore_nonrecursive()`. This resolves the root cause—premature deletion of the `MERGE_AUTOSTASH` ref—while improving performance and code clarity. Phillip Wood provided substantive review, leading to further refinements: silencing merge verbosity, simplifying conflict-label setup, and using `oidcpy()` for robustness. The fix has been validated locally by both Knoble and Wood using Eli Barzilay’s reproduction script.

The patch series is now formally submitted and ready for review, targeting `sequencer.c` and affecting the stash, merge, and ref-management subsystems. It is expected to land in `master` and may be backported to the maintenance track. While the broader issue of `git reset` performing undocumented branch-state cleanups remains unaddressed, this fix is a focused, well-vetted solution to a real-world annoyance.
