This thread is about a bug in Git 2.55.0 where `git merge --ff-only --autostash` (and `git pull` with `rebase.autoStash` and `pull.rebase`) leaves behind a redundant stash entry and fails to clean up the `MERGE_AUTOSTASH` ref when `stash.index=true` is set and staged changes exist. The bug was confirmed and reproduced by Eli Barzilay, who also provided a reproduction script and traced the root cause to premature deletion of the `MERGE_AUTOSTASH` ref during `stash apply --index`.

D. Ben Knoble implemented a fix by replacing the subprocess-heavy index-merge logic (`git diff-tree`, `git apply --cached`, `git reset`) with a direct call to `merge_incore_nonrecursive()`, which preserves the `MERGE_AUTOSTASH` ref until the autostash apply completes. Phillip Wood reviewed the patch and suggested minor improvements: silencing merge verbosity (since conflicts already trigger an abort), simplifying conflict-label setup, and using `oidcpy()` for robustness. The patch is now one cleanup pass away from formal submission.

The fix touches `sequencer.c` and has implications for `builtin/merge.c`, `builtin/stash.c`, and `branch.c`. While the broader layering violation in `git reset` (which performs undocumented branch-state cleanups) was noted, it won’t be addressed in this bugfix thread. The discussion remains focused on finalizing the implementation, with no new edge cases or open questions introduced. The fix is under review and expected to be submitted soon.
