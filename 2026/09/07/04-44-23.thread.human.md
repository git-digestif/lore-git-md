This thread is about a bug in Git 2.55.0 where `git merge --ff-only --autostash` (and `git pull` with `rebase.autoStash`) leaves behind a redundant stash entry and fails to clean up the `MERGE_AUTOSTASH` ref when `stash.index=true` is set and staged changes exist. The bug is confirmed and well-analyzed, with Eli Barzilay providing a reproduction script and tracing the root cause to premature deletion of the `MERGE_AUTOSTASH` ref during `stash apply --index`.

The discussion is now focused on two proposed fixes by Phillip Wood: a surgical fix replacing `reset_head()` with `reset_tree(&c_tree, 0, 1)` to avoid branch-state cleanup, and a more ambitious refactoring using `merge_incore_nonrecursive()` for the index merge. D. Ben Knoble has committed to testing both approaches and may contribute implementation work. Eli Barzilay, while not a developer, has offered to test patches, signaling end-user interest in a resolution. The thread remains under review, with no formal test or patch posted yet, and the broader issue of `git reset` performing undocumented branch-state cleanups noted but not addressed in this context.
