This thread reports and fixes a bug in Git 2.55.0 where `git merge --ff-only --autostash` (and `git pull` with `rebase.autoStash` and `pull.rebase`) leaves behind a redundant stash entry and fails to clean up the `MERGE_AUTOSTASH` ref when `stash.index=true` is set and staged changes exist. The bug was confirmed and analyzed by Eli Barzilay, who provided a reproduction script, and has since drawn collaboration from D. Ben Knoble and Phillip Wood.

The agreed fix replaces the current subprocess-heavy logic (`git diff-tree`, `git apply --cached`, `git reset`) with a direct call to `merge_incore_nonrecursive()`, which preserves the ref until autostash apply completes and avoids spawning subprocesses. D. Ben Knoble has now implemented this refactoring in `sequencer.c`, confirming it resolves the bug and passes all tests.
