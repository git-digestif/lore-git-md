This is patch 9/11 in Patrick Steinhardt’s v2 series standardizing Git’s terminology for "ref storage format." The patch renames two environment variables—`GIT_REFERENCE_BACKEND` to `GIT_REF_STORAGE_FORMAT` and `GIT_DEFAULT_REF_FORMAT` to `GIT_DEFAULT_REF_STORAGE_FORMAT`—while retaining the old names as backward-compatible aliases. It also adds the missing `GIT_REF_STORAGE_FORMAT_ENVIRONMENT` macro to `environment.h` (addressing Karthik Nayak’s feedback from v1) and fixes indentation in the documentation.

The changes are mechanical and touch nine files: documentation (`Documentation/config/init.adoc`, `Documentation/git.adoc`), the environment variable header (`environment.h`), the setup code (`setup.c`), and five test scripts (`t/t0001-init.sh`, `t/t1419-exclude-refs.sh`, `t/t1423-ref-backend.sh`, `t/t7424-submodule-mixed-ref-formats.sh`, `t/test-lib.sh`). The test updates are thorough, replacing every occurrence of the old environment variable names and updating error messages and BUG assertions to use the new terminology. The setup code now checks both the new and old environment variable names, ensuring backward compatibility while enforcing the new precedence rules established in patch 8.

This patch is part of the series’ broader goal of resolving inconsistencies ahead of the upcoming `--object-storage-format=` extension. The renaming is uncontroversial and aligns with the design consensus reached in v1 (adopting `--ref-storage-format=` to distinguish storage format from object hash). No functional changes are introduced; the patch is purely a rename with backward-compatible aliases. The test coverage is comprehensive, and the changes are well-motivated by the series’ overall rationale. The patch is ready for review and likely to be merged as part of the series once any remaining edge cases (e.g., URI handling in patch 11) are addressed.
