This is the second patch in Patrick Steinhardt’s 9-patch series refactoring how Git handles ODB alternates during repository creation, part of the broader ODB abstraction effort. The patch defers initialization of the object database in `git clone` until after the clone source URI is resolved, ensuring alternates are written with full context.

The change is small but important: it moves the call to `create_object_database()` from immediately after repository skeleton creation to just before the transport is set up, and relocates the `setup_reference()` call (which handles alternates) to follow it. This ensures that alternates are written only after the URI is fully resolved, avoiding a latent issue where `.git/config` templates could rewrite the URI after the ODB was already set up. The patch also future-proofs the code by ensuring the ODB is created with knowledge of the object hash, which alternate backends may need.

The commit message clearly explains the motivation—both the immediate need to handle URI resolution correctly and the forward-looking benefit for alternate backends—and the diff is minimal and focused. This is a well-crafted refactoring that aligns with the series’ goal of simplifying the ODB interface. Reviewers will likely focus on whether the deferred ODB setup introduces any edge cases in clone behavior, but the change looks uncontroversial.
