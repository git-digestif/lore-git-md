This is the final patch in Patrick Steinhardt’s 11-part refactoring series that unifies Git’s terminology for "ref storage format." This patch enables the `--ref-storage-format=` option in `git init` and `git clone` to accept URIs with payloads, such as `files://path/to/alt-refs` or `reftable://path/to/reftable`. The payload allows backends like "files" and "reftable" to specify an alternate directory for storing references, which is then recorded in the repository’s config under `extensions.refStorage`.

The implementation is straightforward: the patch replaces the existing `ref_storage_format_by_name()` calls with `ref_storage_format_by_uri()`, which parses the URI and extracts the payload. The payload is then passed through the repository initialization logic and stored in the config. Documentation is updated to describe the URI syntax for both "files" and "reftable" backends, and two new tests verify that the payload is correctly handled and that reinitializing a repository with a mismatched payload is rejected.

This patch completes the series’ functional scope by enabling the URI payload feature, which was the primary motivation for the refactoring. The changes are well-contained and do not introduce new behavior beyond what was already planned. The test coverage is thorough, including edge cases like reinitialization with mismatched payloads. The patch is a natural extension of the earlier refactoring and should be uncontroversial, assuming the URI parsing logic is robust.
