This is the third and final patch in Beat Bolli’s three-part series fixing OpenSSL compatibility and correctness issues in `git imap-send`. It tightens TLS certificate validation to comply with RFC 6125: the code now only checks the subject’s common name (CN) if no DNS subject alternative names (SANs) are present. The change is small (nine lines added, four removed) and directly follows the RFC’s requirement that CN matching must not be attempted when DNS SANs exist. The commit message cites the relevant RFC section and references a similar fix in HAProxy, which adds credibility. If you care about secure IMAP connections or OpenSSL compliance, this patch is a straightforward, well-justified improvement.
