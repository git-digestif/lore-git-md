This is the first patch in Patrick Steinhardt’s 9-patch series refactoring how Git initializes repositories, part of the ongoing ODB abstraction effort. The patch splits `init_db()` into `create_repository()`, which now only creates the repository skeleton (directories, config files) without setting up the refdb or ODB. This eliminates the need for skip flags (`INIT_DB_SKIP_REFDB`, `INIT_DB_SKIP_ODB`) and moves command-specific logic (e.g., initialization messages) into the commands themselves, simplifying the interface.

The key change is the introduction of `create_repository()`, which takes a `reinit_ok` pointer to indicate whether reinitializing an existing repository is allowed. The caller (`git init` or `git clone`) is now responsible for explicitly creating the refdb and ODB via `create_reference_database()` and `create_object_database()`. This refactoring addresses Justin Tobler’s feedback about the growing complexity of `init_db()`’s skip flags and prepares the codebase for deferred ODB setup in `git clone` (where alternates handling requires full context).

The patch touches `builtin/clone.c`, `builtin/init-db.c`, `setup.c`, and `setup.h`, with mechanical changes to adapt callers to the new interface. No user-visible behavior changes are introduced, but the refactoring is foundational for the series’ goal of consolidating alternates handling during ODB creation. The changes are well-motivated and align with the broader ODB abstraction effort, though reviewers may focus on ensuring the new helpers are used consistently across the codebase. The patch is uncontroversial and appears ready for integration.
