This is the final patch in brian m. carlson’s seven-part RFC series proposing a breaking change for Git 3.0: restricting hex object IDs to lowercase only. It activates the enforcement mechanism introduced in the preparatory patches by defining `HEX_KIND_OID` as `HEX_KIND_LOWER` when `WITH_BREAKING_CHANGES` is enabled, documents the change in `Documentation/BreakingChanges.adoc`, and adds a test in `t1503-rev-parse-verify.sh` to verify that uppercase object IDs are rejected.

The patch is minimal and targeted, touching only three files. The core change is in `hex-ll.h`, where the `HEX_KIND_OID` macro is redefined to enforce lowercase-only parsing in breaking changes mode. The documentation update in `BreakingChanges.adoc` explains the rationale—citing security vulnerabilities and bugs in Git-adjacent software caused by Git’s historical case-insensitive parsing—and notes that most users are unlikely to notice the change. The new test in `t1503` ensures the enforcement works as intended by attempting to parse an uppercase version of a known object ID and verifying that `git rev-parse --verify` fails.

This patch is the culmination of the series’ infrastructure work. The first four patches introduced the `hex_kind` enum and refactored hex-parsing code to use it without altering behavior; the fifth patch preserved the existing lowercase-forcing behavior in `object-name.c` while adopting the new helpers; and the sixth patch adjusted an existing test to avoid false positives. With this patch, the breaking change is fully implemented and gated behind `WITH_BREAKING_CHANGES`, targeting Git 3.0. The series is technically complete, with all review feedback addressed, but the thread remains in RFC limbo pending a final decision on whether the project will accept the change.

The patch itself is straightforward and well-scoped, but the broader discussion around Phillip Wood’s adjacent proposal—whether Git should also forbid ref names that *look like* object IDs—could expand the scope if others engage with it. For now, this patch represents the enforcement mechanism for the lowercase-only hex policy, and its fate depends on the project’s appetite for breaking changes in Git 3.0.
