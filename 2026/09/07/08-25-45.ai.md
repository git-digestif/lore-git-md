This is patch 8/9 in Patrick Steinhardt’s 9-patch series refactoring ODB alternates handling during repository creation. The patch wires up the new `odb_create_on_disk_options` interface to pass alternates directly to `create_object_database()`, eliminating the need for a separate `odb_add_to_alternates_file()` call in `git clone`.

The change is mechanical and narrow: it removes the manual loop that writes alternates to the `info/alternates` file in `cmd_clone()` and instead passes the `strvec` of alternates paths to `create_object_database()`. The function signature is updated to accept the `strvec`, and the `odb_create_on_disk_options` struct is populated with the alternates. In `git init`, `create_object_database()` is called with `NULL` for alternates, preserving the existing behavior.

Files touched are `builtin/clone.c`, `builtin/init-db.c`, `setup.c`, and `setup.h`. The patch is uncontroversial and aligns with the series’ goal of consolidating alternates handling into ODB creation. It depends on the lockfile API adoption in patch 7, which ensures atomic writes and resolves the TOCTOU race concern raised in earlier versions. No user-visible behavior changes are introduced.

The patch is well-motivated and ready for review. Reviewers may focus on verifying that the alternates `strvec` is correctly passed through the call chain and that the `NULL` case in `git init` behaves as expected, though the changes are straightforward and unlikely to introduce regressions. The removal of the manual alternates loop simplifies the code and prepares for the final patch (9/9), which removes the now-unused `write_alternates()` infrastructure.
