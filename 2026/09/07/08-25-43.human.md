This is patch 6 of 9 in Patrick Steinhardt’s ODB alternates refactoring series, part of the ongoing ODB abstraction effort. The patch moves the setup of alternates for non-shared local clones (`git clone --local --no-shared`) into the `collect_alternates()` function, completing the consolidation of alternates logic that began in earlier patches.

The change is straightforward: previously, non-shared local clones manually read the source repository’s `objects/info/alternates` file in `copy_or_link_directory()`, but now this logic is handled by `collect_alternates()` alongside the existing `--shared` and `--reference` cases. The patch also fixes a latent bug where cloning from a worktree failed to resolve the source repository’s common directory, causing alternates paths to be incorrectly resolved. Two new tests in `t/t5604-clone-reference.sh` verify the fix and ensure relative alternates paths are properly handled.

The diff is clean and mechanical, with no user-visible behavior changes. The only functional improvement is the bug fix for worktree alternates, which is well-tested. The patch aligns with the series’ goal of simplifying the ODB interface by eliminating manual alternates setup and consolidating it into a single code path. Reviewers will likely focus on whether the refactoring introduces edge cases (e.g., error handling for invalid alternates paths), but the changes appear uncontroversial given their incremental nature and clear technical rationale.
