This is the sixth patch in brian m. carlson’s seven-patch RFC series proposing a Git 3.0 breaking change: restricting hex object IDs to lowercase only. The series is now in its second iteration, addressing all prior feedback, and this patch adjusts an existing test to avoid false positives once the enforcement lands.

The test in question, `t5324-split-commit-graph.sh`, corrupts the commit-graph chain file by replacing a hex character with an uppercase "A". Currently this works because Git accepts mixed-case object IDs, but after the breaking change the corruption would be rejected *before* the test’s intended error ("unable to find all commit-graph files") could trigger. To keep the test valid, the patch changes the corruption character from "A" to "b" at position 70 (ensuring the failure remains due to corruption, not uppercase rejection) and from "A" to "a" at position 30 (for consistency with the lowercase-only requirement). The commit message explains that "b" is safe for both SHA-1 and SHA-256, though future hash algorithms might require another adjustment.

This is a minimal, targeted change—just two line edits in a single test file—with no runtime behavior impact. It’s purely preparatory, ensuring the test suite remains robust when the final patch activates the breaking change. The patch is well-motivated and uncontroversial; the only discussion point in the thread is whether the broader series will be accepted, not this specific adjustment.
