Thread identity: patch series (single patch), originating author Vsevolod Myalitsin, thread type user-facing documentation fix in the advice subsystem.

Core problem or goal: correct the on-screen instructions for disabling the `defaultBranchName` advice message to recommend a globally scoped configuration command (`--global` or `set --global`) instead of a repository-local `set`, ensuring the setting applies globally by default. The design uses a configurable `scope_hint` field in the `advice_setting` struct to allow future advice keys to specify their preferred configuration scope (e.g., `--global`, `--system`), improving extensibility and maintainability.

Current status: under active review; architectural direction settled. The author has accepted Junio C Hamano’s feedback to replace the `global_hint` boolean with a more general `scope_hint` field (e.g., `CONFIG_SCOPE_GLOBAL`) and to pass the entire `advice_setting` struct to `vadvise()` for better encapsulation and future-proofing. Junio additionally identified a backward-compatibility requirement: the existing `advise()` function, which is not tied to any specific `advice_setting[]` entry, must continue to work after the refactoring. The solution is to create an ad-hoc `advice_setting` struct on the stack for this case, initialized with default values (`key = ""`, `scope_hint = CONFIG_SCOPE_UNKNOWN`, `level = ADVICE_LEVEL_UNKNOWN`). The author plans to post a v3 incorporating these changes, including the new `ADVICE_LEVEL_UNKNOWN` enum value. The unresolved syntax preference (`--global` vs `set --global`) from Ben Knoble remains pending, but the core architectural decisions are now resolved.
