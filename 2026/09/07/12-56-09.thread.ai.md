Thread identity: patch series (single patch), originating author Vsevolod Myalitsin, thread type user-facing documentation fix in the advice subsystem.

Core problem or goal: correct the on-screen instructions for disabling the `defaultBranchName` advice message to recommend a globally scoped configuration command (`--global` or `set --global`) instead of a repository-local `set`, ensuring the setting applies globally by default. The design uses a configurable `scope_hint` field in the `advice_setting` struct to allow future advice keys to specify their preferred configuration scope (e.g., `--global`, `--system`), improving extensibility and maintainability.

Current status: under active review; architectural direction settled but implementation details for backward compatibility remain under discussion. The author has accepted Junio C Hamano’s feedback to replace the `global_hint` boolean with a more general `scope_hint` field (e.g., `CONFIG_SCOPE_GLOBAL`) and to pass the entire `advice_setting` struct to `vadvise()` for better encapsulation and future-proofing. Junio additionally identified a backward-compatibility requirement: the existing `advise()` function, which is not tied to any specific `advice_setting[]` entry, must continue to work after the refactoring. Two competing proposals exist for this: (1) Junio’s suggestion to create an ad-hoc `advice_setting` struct on the stack with default values (`key = ""`, `scope_hint = CONFIG_SCOPE_UNKNOWN`, `level = ADVICE_LEVEL_UNKNOWN`), and (2) Jeff King’s proposal to pass `NULL` to `vadvise()` to indicate the absence of a matching advice config, with `vadvise()` checking `if (conf && !conf->level)` to decide whether to show turn-off instructions. Jeff’s approach is cleaner and more idiomatic in C, avoiding the need for a dummy struct. The unresolved syntax preference (`--global` vs `set --global`) from Ben Knoble remains pending, but the core architectural decisions are now resolved.

Key technical details:
- File touched: `advice.c`
- Subsystem: advice machinery
- Change: replaces the `global_hint` boolean in the `advice_setting` struct with a `scope_hint` field (e.g., `CONFIG_SCOPE_GLOBAL`, `CONFIG_SCOPE_SYSTEM`), set to `CONFIG_SCOPE_GLOBAL` for `defaultBranchName` and left as `CONFIG_SCOPE_UNKNOWN` (default) for other keys. The `vadvise()` helper now receives a pointer to the entire `advice_setting` struct, narrowing its interface and making it unaware of specific advice keys. To maintain backward compatibility with the existing `advise()` function, either an ad-hoc `advice_setting` struct (Junio’s proposal) or a `NULL` pointer (Jeff’s proposal) will be passed to `vadvise()`.
- Symbols: `advice_setting` struct extended with `scope_hint`; `advice_level` enum extended with `ADVICE_LEVEL_UNKNOWN` (if Junio’s proposal is adopted); no functions renamed or introduced.
- Behavior: old: `git config set advice.defaultBranchName false` (repository-local); new: `git config --global advice.defaultBranchName false` (or `git config set --global ...` if Ben Knoble’s syntax preference is adopted). The displayed command will use the scope hint to recommend the appropriate flag.
- On-disk format: unchanged.
- Test coverage: none added; change remains self-contained and low-risk.
- Broader subsystem implications: Jeff King notes that most `advise()` calls are wrapped in `if (advice_is_enabled(ADVICE_FOO))`, meaning they do not currently show turn-off instructions (introduced in 2020). Only `advise_if_enabled()` calls show these instructions. He questions whether expanding turn-off instructions to all advice messages would be overly chatty and suggests extending `advise()` to accept an advice enum (e.g., `advise(ADVICE_FOO, "try %s", results)`) to unify the interface and avoid redundant `advice_is_enabled()` checks. This could address the "NULL advice marker" case but might require broader subsystem changes.

Open questions and loose ends:
- Backward-compatibility mechanism: unresolved debate between Junio’s ad-hoc struct and Jeff’s `NULL` pointer approach for `advise()`.
- Syntax preference: unresolved debate between `--global` and `set --global` in the displayed command (Ben Knoble’s preference for the latter).
- Subsystem design: Jeff King’s observation about the inconsistency of turn-off instructions (only shown for `advise_if_enabled()`) and his proposal to extend `advise()` to accept an advice enum could spark further discussion about the subsystem’s design and user experience.
- No technical objections to the core goal or the revised design’s intent.
