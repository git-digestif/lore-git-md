Thread identity: patch series (single patch for the `defaultBranchName` advice documentation fix with configurable scope hints, plus a related mechanical refactoring in the advice subsystem), originating author Vsevolod Myalitsin, thread type user-facing documentation fix and internal refactoring in the advice subsystem.

Core problem or goal: correct the on-screen instructions for disabling the `defaultBranchName` advice message to recommend a globally scoped configuration command (`--global` or `set --global`) instead of a repository-local `set`, ensuring the setting applies globally by default. The design uses a configurable `scope_hint` field in the `advice_setting` struct to allow future advice keys to specify their preferred configuration scope (e.g., `--global`, `--system`), improving extensibility and maintainability. Additionally, Junio C Hamano posted a mechanical refactoring patch converting existing `advice_enabled()` + `advise()` call sites to the newer `advise_if_enabled()` helper, addressing the broader design question of whether the advice subsystem should consistently use the newer helper.

Current status: architectural direction and backward-compatibility mechanism for the `defaultBranchName` patch settled; patch v3 posted and effectively ready for merging. The refactoring patch is under review with substantive feedback from Jeff King identifying missed call sites (e.g., in `commit.c`) and reopening the design discussion about the user experience implications of `advise_if_enabled()`'s turn-off instructions. Both patches remain under review; the refactoring patch may require a v2 to address the mechanical completeness issue, though this is not a blocker for the core fix.

Key technical details:
- Files touched: `advice.c` (core patch and refactoring), `branch.c`, `builtin/am.c`, `builtin/checkout.c`, `builtin/commit.c`, `builtin/submodule--helper.c`, `sequencer.c` (refactoring only), and `tools/coccinelle/advice.cocci` (new Coccinelle rule).
- Subsystem: advice machinery.
- Core patch changes: replaces the `global_hint` boolean in the `advice_setting` struct with a `scope_hint` field (e.g., `CONFIG_SCOPE_GLOBAL`, `CONFIG_SCOPE_SYSTEM`), set to `CONFIG_SCOPE_GLOBAL` for `defaultBranchName` and left as `CONFIG_SCOPE_UNKNOWN` (default) for other keys. The `vadvise()` helper now receives a pointer to the entire `advice_setting` struct, narrowing its interface and making it unaware of specific advice keys. To maintain backward compatibility with the existing `advise()` function, `NULL` is passed to `vadvise()` when no advice config is associated with the message.
- Refactoring patch changes: mechanically converts 23 lines of conditional `advice_enabled()` + `advise()` logic to direct `advise_if_enabled()` calls across seven files, reducing boilerplate while preserving behavior. The Coccinelle rule automates the bulk of the work but missed call sites with more complex conditionals (e.g., in `commit.c`), requiring manual follow-up. The patch does not alter user-visible behavior but reopens the design question of whether `advise_if_enabled()`'s turn-off instructions are overly verbose or visually intrusive.
- Symbols: `advice_setting` struct extended with `scope_hint`; no functions renamed or introduced. The refactoring patch does not introduce or rename symbols.
- Behavior: core patch: old: `git config set advice.defaultBranchName false` (repository-local); new: `git config --global advice.defaultBranchName false` (or `git config set --global ...` if Ben Knoble’s syntax preference is adopted). The displayed command will use the scope hint to recommend the appropriate flag. Refactoring patch: no user-visible behavior changes; purely internal control flow cleanup, though the design discussion about turn-off instructions remains open.
- On-disk format: unchanged for both patches.
- Test coverage: none added for either patch; changes remain self-contained and low-risk.
- Broader subsystem implications: Jeff King and Junio C Hamano clarified the intentional design distinction between `advise()` (used after `advice_is_enabled()` checks to avoid expensive work when advice is disabled) and `advise_if_enabled()` (used when turn-off instructions are explicitly desired). The refactoring patch unifies the codebase toward `advise_if_enabled()` for existing callers, though the distinction remains intact for future use cases. Peff’s review reopens the question of whether the turn-off instructions are visually overwhelming, which may influence future subsystem design.
