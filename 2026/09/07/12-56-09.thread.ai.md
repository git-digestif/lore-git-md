Thread identity: patch series (single patch for the `defaultBranchName` advice documentation fix with configurable scope hints, plus a related mechanical refactoring in the advice subsystem), originating author Vsevolod Myalitsin, thread type user-facing documentation fix and internal refactoring in the advice subsystem.

Core problem or goal: correct the on-screen instructions for disabling the `defaultBranchName` advice message to recommend a globally scoped configuration command (`--global` or `set --global`) instead of a repository-local `set`, ensuring the setting applies globally by default. The design uses a configurable `scope_hint` field in the `advice_setting` struct to allow future advice keys to specify their preferred configuration scope (e.g., `--global`, `--system`), improving extensibility and maintainability. Additionally, Junio C Hamano posted a mechanical refactoring patch converting existing `advice_enabled()` + `advise()` call sites to the newer `advise_if_enabled()` helper, addressing the broader design question of whether the advice subsystem should consistently use the newer helper.

Current status: architectural direction and backward-compatibility mechanism for the `defaultBranchName` patch settled; patch v3 posted and effectively ready for merging. The refactoring patch is a separate, low-risk cleanup that does not block the core fix but unifies the codebase toward the newer helper. Both patches are under review. The author has incorporated all prior feedback on the core patch: replacing the `global_hint` boolean with a `scope_hint` field (e.g., `CONFIG_SCOPE_GLOBAL`), passing the entire `advice_setting` struct to `vadvise()` for better encapsulation, and resolving backward compatibility by passing `NULL` to `vadvise()` when no advice config is associated with the message. Junio C Hamano and Jeff King agreed on the `NULL` pointer approach, and the intentional design distinction between `advise()` and `advise_if_enabled()` remains unchanged. The only unresolved item is a minor syntax preference (`--global` vs `set --global`) in the displayed command, but this is not a blocker.

The refactoring patch unifies the codebase toward `advise_if_enabled()` for existing callers, though the distinction remains intact for future use cases.
