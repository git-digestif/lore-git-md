Thread identity: patch series (single patch), originating author Vsevolod Myalitsin, thread type user-facing documentation fix in the advice subsystem.

Core problem or goal: correct the on-screen instructions for disabling the `defaultBranchName` advice message to recommend a globally scoped configuration command (`--global` or `set --global`) instead of a repository-local `set`, ensuring the setting applies globally by default. The design uses a configurable `scope_hint` field in the `advice_setting` struct to allow future advice keys to specify their preferred configuration scope (e.g., `--global`, `--system`), improving extensibility and maintainability.

Current status: architectural direction and backward-compatibility mechanism settled; ready for v3 patch. The author has incorporated Junio C Hamano’s feedback to replace the `global_hint` boolean with a `scope_hint` field (e.g., `CONFIG_SCOPE_GLOBAL`) and to pass the entire `advice_setting` struct to `vadvise()` for better encapsulation. The backward-compatibility requirement for the existing `advise()` function is resolved: Junio and Jeff King agreed to pass `NULL` to `vadvise()` to indicate the absence of a matching advice config, avoiding the need for an ad-hoc struct. The unresolved syntax preference (`--global` vs `set --global`) from Ben Knoble remains pending but is not a blocker for merging.

Key technical details:
- File touched: `advice.c`
- Subsystem: advice machinery
- Change: replaces the `global_hint` boolean in the `advice_setting` struct with a `scope_hint` field (e.g., `CONFIG_SCOPE_GLOBAL`, `CONFIG_SCOPE_SYSTEM`), set to `CONFIG_SCOPE_GLOBAL` for `defaultBranchName` and left as `CONFIG_SCOPE_UNKNOWN` (default) for other keys. The `vadvise()` helper now receives a pointer to the entire `advice_setting` struct, narrowing its interface and making it unaware of specific advice keys. To maintain backward compatibility with the existing `advise()` function, `NULL` is passed to `vadvise()` when no advice config is associated with the message.
- Symbols: `advice_setting` struct extended with `scope_hint`; no functions renamed or introduced.
- Behavior: old: `git config set advice.defaultBranchName false` (repository-local); new: `git config --global advice.defaultBranchName false` (or `git config set --global ...` if Ben Knoble’s syntax preference is adopted). The displayed command will use the scope hint to recommend the appropriate flag.
- On-disk format: unchanged.
- Test coverage: none added; change remains self-contained and low-risk.
- Broader subsystem implications: Jeff King and Junio C Hamano clarified the intentional design distinction between `advise()` (used after `advice_is_enabled()` checks to avoid expensive work when advice is disabled) and `advise_if_enabled()` (used when turn-off instructions are explicitly desired). This pattern is consistent with `trace_want()` and is not altered by the current patch, though it remains an open design question for future work.

Open questions and loose ends:
- Syntax preference: unresolved debate between `--global` and `set --global` in the displayed command (Ben Knoble’s preference for the latter).
- Subsystem design: the intentional inconsistency of turn-off instructions (only shown for `advise_if_enabled()`) remains an open design question, but it is not a blocker for this patch.
