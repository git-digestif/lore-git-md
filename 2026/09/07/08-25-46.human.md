This is the final patch in Patrick Steinhardt’s 9-part series refactoring how Git handles ODB alternates during repository creation. The patch removes the now-unused `odb_source_write_alternates()` function and its supporting infrastructure across all ODB backends, completing the series’ goal of consolidating alternates handling into ODB creation.

The patch deletes 117 lines across seven files, removing the `write_alternate` callback from the `odb_source` struct and its implementations in `odb/source-files.c`, `odb/source-inmemory.c`, `odb/source-loose.c`, and `odb/source-packed.c`. It also removes the `odb_add_to_alternates_file()` helper from `odb.c` and `odb.h`, which was the last remaining user of the `write_alternate` callback. The changes are mechanical and uncontroversial, as the series’ earlier patches (7-8/9) already migrated all alternates handling to the new `odb_create_on_disk_options` interface, which writes alternates atomically during ODB creation using Git’s lockfile API.

This patch is a clean-up step with no user-visible behavior changes. It simplifies the ODB interface by eliminating redundant infrastructure, aligning with the broader ODB abstraction effort to make alternates an implementation detail of the backend. The removal is safe because the series’ earlier patches ensured all alternates are now written during ODB creation, and the lockfile API adoption in patch 7/9 resolved the TOCTOU race and concurrent access concerns raised in earlier reviews. The patch is ready for integration, assuming no further feedback on the series.
