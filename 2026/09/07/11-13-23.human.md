This is a bugfix patch addressing the memory leak in `git history reword` that Kristoffer Haugsbakk reported earlier in the thread. The leak, confirmed in `master`, `next`, and `seen`, was introduced by the merge of Patrick Steinhardt’s `ps/receive-pack-shallow-optim` branch and surfaces during commit buffer handling in the ODB layer.

Patrick’s patch adds a missing `repo_unuse_commit_buffer()` call in `builtin/history.c` to free the commit buffer allocated during `commit_tree_ext()`. The fix is small and targeted, touching only the `history` command’s internals. He notes this issue was previously discussed in June 2026 (linking to a thread with Kaartic Sivaraam) but apparently never merged, suggesting the leak has persisted for months.

The patch looks well-motivated and straightforward—it directly addresses the leak’s root cause as identified in the stack trace. Since the fix is localized to `git history` and doesn’t affect other commands, it’s unlikely to introduce regressions elsewhere. The fact that Patrick recalls a prior discussion about this exact issue adds confidence that this is the correct fix, not just a band-aid. If this lands, it should resolve the 283-byte leak Kristoffer observed.
