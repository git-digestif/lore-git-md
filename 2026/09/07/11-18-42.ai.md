This is patch 8/11 in Patrick Steinhardt’s v2 series standardizing Git’s terminology for "ref storage format." The patch refactors the logic that determines and validates the ref storage format during repository (re)initialization, fixing a bug where reinitializing a repository with a different format silently corrupted it.

The core change splits the previously intertwined logic for *determining* the desired format and *validating* the result. The new code clearly spells out the precedence order (command-line option overrides environment variables, which override existing repository format, etc.) and enforces immutability of the existing format once set. This prevents the silent corruption demonstrated in the commit message: reinitializing a repository with `GIT_REFERENCE_BACKEND=reftable` after it was created with the default "files" backend now fails with a clear error instead of leaving the repository in a broken state.

The patch also updates error messages to be more specific (e.g., "unknown ref storage format specified via GIT_DEFAULT_REF_FORMAT: 'garbage'") and adds a new test case to verify that reinitialization with a mismatched format is rejected. The refactoring is mechanical and does not change behavior except for the bug fix; it prepares the codebase for URI payload support in patch 11 by centralizing the format-determination logic.

Files touched: `setup.c` (primary refactoring) and `t/t0001-init.sh` (new test case). The patch is well-motivated, addresses a real bug, and aligns with the series’ goal of consistent terminology and robust configuration handling. No substantive review feedback has been incorporated yet, but the changes are narrowly scoped and unlikely to introduce regressions.
