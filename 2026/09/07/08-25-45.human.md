This is the eighth patch in Patrick Steinhardt’s nine-patch series refactoring how Git writes object database (ODB) alternates during repository creation. The patch wires up the new alternates-handling mechanism introduced in earlier patches, replacing the old two-step process (create ODB, then write alternates) with a single atomic operation during ODB creation.

The change is straightforward: `create_object_database()` now accepts an optional `strvec` of alternates paths, which it passes to the ODB backend via the `odb_create_on_disk_options` struct. In `builtin/clone.c`, this eliminates the manual loop that previously wrote alternates after ODB creation, consolidating all alternates logic into the ODB setup phase. The patch also updates `builtin/init-db.c` to pass `NULL` for alternates, preserving the existing behavior for `git init`.

This is a clean, mechanical change that aligns with the series’ goal of making alternates an ODB backend implementation detail. The lockfile API adoption in patch 7 ensures atomic writes, addressing the TOCTOU race concerns raised in earlier versions. The patch is uncontroversial and appears ready for integration, though reviewers may verify that the alternates `strvec` is correctly handled in edge cases (e.g., empty or invalid paths). No user-visible behavior changes are introduced.
