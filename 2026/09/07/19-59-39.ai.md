This is the sixth patch in brian m. carlson’s seven-patch RFC series proposing a Git 3.0 breaking change: restricting hex object IDs to lowercase only. The patch adjusts `t5324-split-commit-graph.sh` to avoid false positives when the upcoming enforcement is activated. The test currently corrupts the commit-graph chain file by replacing a character at positions 30 and 70 with "A", which would be rejected as an invalid (uppercase) object ID once the series’ final patch takes effect. This patch changes those corruption characters to "b", ensuring the test failure remains due to file corruption rather than uppercase rejection. The change is minimal—only two lines in a single test file—but necessary for correctness in both SHA-1 and SHA-256 modes, since one of the positions already contains a lowercase "a" in SHA-256.

The commit message clearly explains the rationale: the test must continue to validate the commit-graph corruption logic, not the new hex-parsing enforcement. By switching to "b", the patch guarantees the test remains valid regardless of the hash algorithm or the lowercase-only restriction. The message also notes that future hash algorithms may require further adjustments, but this change is sufficient for now. The patch is purely preparatory and introduces no behavioral changes; it simply future-proofs the test suite for the series’ final patch.

This patch directly addresses feedback from Elijah Newren’s review of v1, which flagged the ambiguity in the commit message about which "A" was being changed. The updated message now specifies the exact positions (30 and 70) and the new character ("b"), eliminating any confusion. The change is uncontroversial and aligns with the series’ overall goal of making Git’s hex-parsing behavior consistent and predictable. No further review issues are expected here, as the patch is narrowly scoped and well-motivated.

The patch touches only `t/t5324-split-commit-graph.sh`, making it easy to review in isolation. It is part of the series’ broader effort to enforce lowercase-only object IDs, but its role is purely to prevent test regressions rather than to implement the enforcement itself. The next (and final) patch in the series will activate the breaking change, at which point this test adjustment will become critical for avoiding false positives. For now, this patch is ready for integration once the project decides to proceed with the series.
