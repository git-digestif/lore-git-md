This is a bugfix patch addressing the memory leak in `git history reword` that Kristoffer Haugsbakk reported. The leak, introduced by the merge of Patrick Steinhardt’s `ps/receive-pack-shallow-optim` branch, occurs in the ODB layer during commit buffer handling and is triggered by `git history reword --dry-run`. Patrick’s patch adds a missing `repo_unuse_commit_buffer()` call in `builtin/history.c` to free the commit buffer allocated during the reword operation.

The fix is straightforward and targets the exact code path identified in the stack trace: `commit_tree_ext()` in `builtin/history.c`. The patch ensures the commit buffer (`original_message`) is properly released after use, which should resolve the 283-byte leak. Patrick notes this issue was previously discussed in a June 2026 thread (linked in the email) involving Kaartic Sivaraam, suggesting the fix was already proposed but not merged—likely due to oversight or unresolved follow-up questions.

This patch is narrowly scoped to the leak itself and does not attempt to address broader questions about whether other commands might be affected or whether the root cause lies deeper in the ODB or packfile code. The fix is well-motivated by the stack trace and aligns with the established pattern of using `repo_unuse_commit_buffer()` to balance `repo_get_commit_buffer()` calls. Given the leak’s reproducibility and the patch’s precision, it looks like a strong candidate for merging.

The email also clarifies that the leak does not reproduce on Patrick’s machine, hinting at environment-specific conditions (e.g., `i18n.commitencoding` settings) that might influence the bug’s visibility. This could explain why the issue persisted despite prior discussion. The patch itself is minimal and unlikely to introduce regressions, though testing in diverse repository configurations would be prudent.
