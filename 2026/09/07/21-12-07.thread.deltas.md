## 2026/09/08

- [2026/09/08/01-17-01 by Junio C Hamano <gitster@pobox.com>] Junio C Hamano pointed out a bug in the proposed fix for the NUL-termination issue in `host_matches()`: the code path that advances `pattern` by 2 would make `free(pattern)` invalid, and suggested keeping a separate `pattern_to_free` variable used only for the `free()` call.
- [2026/09/08/01-28-32 by brian m. carlson <sandals@crustytoothpaste.net>] brian m. carlson argued that TLS should not use the certificate CN at all these days (Go's implementation ignores it; subjectAltName should be used in all cases), noted that the proposed change handles DNS SANs but not IP addresses (e.g., it would not match certificates for 1.1.1.1), and asked why git still does hostname verification by hand instead of relying on OpenSSL's built-in verification available since 1.0.2, which would avoid security-sensitive mistakes and handle policy/standards compliance.
- [2026/09/08/04-17-01 by Junio C Hamano <gitster@pobox.com>] Junio C Hamano questioned the style of the `#define ASN1_STRING_get_length(s) ASN1_STRING_length(s)` compatibility mapping in the OpenSSL 4.1 preparation patch.
- [2026/09/08/08-26-36 by Patrick Steinhardt <ps@pks.im>] Patrick Steinhardt questioned the need to switch to the renamed `ASN1_STRING_get_length()` function, noting the old `ASN1_STRING_length()` still exists and is not deprecated.
- [2026/09/08/08-26-43 by Patrick Steinhardt <ps@pks.im>] Patrick Steinhardt questioned the need to `xmemdupz()` the ASN1_STRING in the NUL-termination fix, suggesting that `memchr`, `memchr`-based replacement for `strchr`, and `strncasecmp` in place of `strcasecmp` would bound all string inspections by the encoded length, avoiding the copy entirely.
