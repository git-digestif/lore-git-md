This is a brief follow-up in the ODB alternates refactoring series, specifically addressing Justin Tobler’s design question about the `odb_create_on_disk_options` interface and its `alternates` field.

Patrick Steinhardt clarifies that the behavior of `git clone --shared` and similar options should indeed be backend-specific. The ODB interface’s `alternates` field is intentionally flexible: while the "files" backend uses alternates, future backends may choose to ignore them or implement them differently. This aligns with the broader ODB abstraction goal of making alternates an implementation detail rather than a core requirement. The response leaves room for backends to define their own semantics while preserving the interface’s generality, though it may prompt further discussion about how to document or enforce consistency for user-facing options like `--shared`. No code changes are proposed; the clarification is purely architectural.
