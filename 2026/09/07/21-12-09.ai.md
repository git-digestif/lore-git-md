This is the second patch in Beat Bolli’s three-patch series fixing OpenSSL compatibility and correctness issues in `git imap-send`. It addresses a latent bug in the TLS certificate verification logic: the code incorrectly assumed that ASN1_STRINGs returned by OpenSSL are NUL-terminated, which the OpenSSL API never guaranteed. The patch replaces the unsafe direct use of ASN1_STRING data with a NUL-terminated copy, eliminating undefined behavior when the string contains embedded NUL bytes or lacks a terminator.

The change is confined to `imap-send.c` and touches only the `host_matches()` helper function. The fix is straightforward: allocate a copy of the ASN1_STRING data with `xmemdupz()`, use it for comparison, and free it before returning. The commit message cites a recent OpenSSL commit that explicitly documents this assumption as incorrect, providing clear upstream motivation.

This is a textbook example of a small, well-motivated correctness fix. The patch is minimal, self-contained, and removes a sharp edge before it causes problems. It does not introduce new behavior or dependencies, and the existing test suite should continue to pass since the fix only affects edge cases in the OpenSSL interaction layer. If you care about `git imap-send` or OpenSSL compatibility, this patch is worth noting for its proactive removal of undefined behavior.
