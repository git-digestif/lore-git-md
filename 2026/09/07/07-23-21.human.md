This is the first patch in Patrick Steinhardt’s 8-patch series refactoring how Git handles ODB alternates during repository creation. The patch defers object database (ODB) setup in `git clone` until after the clone source URI is resolved, ensuring alternates are written with full context, including any URI rewrites from template `.git/config` files. It introduces the `INIT_DB_SKIP_ODB` flag to `init_db()` and makes `create_object_database()` public, allowing ODB initialization to be deferred until after alternates collection.

The email is a reply to Justin Tobler’s substantive review of the patch, which questioned the growing complexity of `init_db()`’s "skip" flags and suggested requiring explicit setup of the refdb and ODB instead. Patrick agrees in principle, noting that the current interface has become awkward and proposing a future refactoring: lifting repository initialization messages out of `init_db()`, dropping the `QUIET` and `EXIST_OK` flags, and renaming the function to `create_repository()` to better reflect its new role. This would move command-specific logic to the commands themselves, simplifying the interface. The discussion is forward-looking and does not block the current patch, but it signals a likely follow-up effort to clean up the repository initialization API.

Patrick also clarifies a non-obvious detail: the deferred `setup_reference()` call is unrelated to refs themselves—it sets up alternates, which can only be done after the ODB exists. This explanation addresses Justin’s question about the timing of reference setup and will be added to the commit message for clarity.

The patch itself is well-motivated and technically sound, addressing a latent issue in worktree alternates handling and preparing for the broader ODB abstraction effort. The discussion here is about interface design rather than correctness, and Patrick’s responses are constructive. No changes to the patch are needed based on this exchange, but the thread highlights a potential future refactoring of `init_db()`. The series remains on track for integration, with this patch laying the groundwork for the alternates consolidation in later patches.
