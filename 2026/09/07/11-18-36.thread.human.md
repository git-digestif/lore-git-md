This thread is about a small but important cleanup in Git’s ref-storage terminology. Patrick Steinhardt is standardizing the option name used to specify the ref storage format across Git commands. This particular patch (2/11 in the v2 series) updates `git clone` to use `--ref-storage-format=` instead of the older `--ref-format=`, matching a change already made to `git init`. The old option name remains as a hidden alias for backward compatibility, so no existing scripts or workflows break. The patch touches the command implementation, its documentation, and seven test scripts to ensure everything works as expected—error messages, help text, and test assertions are all updated to reflect the new name.

The change is purely mechanical and doesn’t alter Git’s behavior, but it’s part of a broader effort to make the terminology consistent across the codebase. The patch is well-scoped, with clear commit messaging and thorough test coverage. So far, there’s no discussion or review feedback on this version, so the series is still in the early stages of the review cycle. If you’ve been following the ref-storage work, this is a straightforward follow-up; if not, it’s a minor but useful cleanup that won’t affect day-to-day usage.
