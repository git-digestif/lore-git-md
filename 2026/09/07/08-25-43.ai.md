This is patch 6/9 in Patrick Steinhardt’s ODB alternates refactoring series, part of the ongoing ODB abstraction effort. The patch moves the setup of alternates for non-shared local clones (`git clone --local --no-shared`) into the `collect_alternates()` function, completing the consolidation of all alternates logic into a single code path.

The change is mechanical but fixes a latent bug: previously, when cloning from a worktree, Git failed to resolve the source repository’s common directory, causing alternates setup to break. The patch reuses the already-resolved common directory path from `collect_alternates()` to handle this case correctly. Two new tests in `t/t5604-clone-reference.sh` verify the fix—one for cloning from a linked worktree and another for resolving relative alternates paths.

The diff renames `copy_alternates()` to `read_alternates()` and refactors it to gather alternates paths into a `strvec` instead of immediately writing them to the ODB. This aligns with the series’ goal of deferring alternates setup until ODB creation. The patch also removes the manual alternates handling in `copy_or_link_directory()`, since alternates are now processed earlier in `collect_alternates()`.

No user-visible behavior changes are introduced, but the bug fix and consolidation are foundational for later patches that adopt the lockfile API for writing alternates. The patch is uncontroversial and appears well-tested, with clear commit message rationale. Reviewers may focus on the error handling in `read_alternates()` (e.g., `fopen()` failure modes), though the changes are straightforward and consistent with the series’ design.
