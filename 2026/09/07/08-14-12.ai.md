This is a **substantive review** of the second patch in the v2 series that defers auto maintenance to sequence completion in the sequencer backend. Patrick Steinhardt raises two main concerns: the commit message is unclear about what behavior changes and why, and the patch adds `run_auto_maintenance()` calls in multiple places rather than consolidating them into a single exit path.

The review questions the patch’s clarity and structure but does not object to the core goal (deferring maintenance until sequence completion). Patrick asks for a clearer explanation of the new behavior—specifically, whether the patch introduces maintenance in cases where it did not run before, and what the consequences are. He also expresses a preference for a single exit path (like the apply backend’s `finish_rebase()`) to avoid scattering maintenance calls across multiple functions (`sequencer_finish()`, `continue_single_pick()`, `single_pick()`).

The feedback is technical and focused on code organization and documentation, not on the underlying design. The author will need to revise the commit message for clarity and may want to explore consolidating the maintenance calls, though the latter is a stylistic suggestion rather than a blocker. The review does not identify any functional issues or regressions.
