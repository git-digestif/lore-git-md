This is a refactoring and consistency cleanup series targeting Git's reference storage terminology. Patrick Steinhardt's v2 of the 11-patch series addresses long-standing inconsistencies in how Git refers to the "ref storage format" across command-line options, environment variables, configuration keys, and documentation. The series now standardizes on `--ref-storage-format=` (and analogous names for environment variables and config keys) to explicitly distinguish storage format from object hash, resolving Junio C Hamano's earlier ambiguity concern.

The v2 update renames all occurrences of "ref-format" to "ref-storage-format" throughout the codebase, including CLI options (`--ref-storage-format=`), environment variables (`GIT_REF_STORAGE_FORMAT`), and config keys (`init.defaultRefStorageFormat`). The old names are retained as backward-compatible aliases. The series also centralizes URI parsing for reference storage backends, enabling `--ref-storage-format=` to accept URIs like `files://path/to/repo` with payloads, and fixes a bug where reinitializing a repository with a different ref storage format silently corrupts the repository by enforcing immutability of the existing format.

Key changes in v2 include:
- Adoption of `--ref-storage-format=` (and related names) as the new standard terminology
- Consistent use of "format" as the placeholder in help text (e.g., `--ref-storage-format=<format>`)
- Backward-compatible aliases for all old names
- Updated documentation, tests, and shell completions across 39 files
- The missing `GIT_DEFAULT_REF_STORAGE_ENVIRONMENT` macro added to `environment.h`

The series is well-motivated and clearly structured, with detailed commit messages explaining each change. The refactoring is mechanical but thorough, touching built-in commands (`init`, `clone`, `refs`, `submodule`, `rev-parse`), documentation, and tests. The functional improvements (URI support and immutability enforcement) are valuable additions that address real problems. The backward-compatibility layer should mitigate most disruption, though third-party tools parsing help output or error messages may need updates. The series is ready for review, with no major open questions remaining.
