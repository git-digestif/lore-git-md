This is the second iteration of an RFC series proposing a breaking change for Git 3.0: restricting hex object IDs to lowercase only. The author, brian m. carlson, addresses feedback from the first version by fixing a comment typo, updating commit messages, separating test adjustments into their own patch, and restoring a lowercasing behavior in `parse_oid_prefix`.

The series remains focused on the same goal: enforcing lowercase-only parsing of object IDs to prevent compatibility and security issues in external tools that assume hex uniqueness. The first five patches introduce infrastructure (a new `hex_kind` enum, updated `hexval()`, `hex2chr()`, and `hex_to_bytes()` functions) and refactor existing hex-parsing code to use these helpers without changing runtime behavior. The sixth patch adjusts a test to avoid false positives, and the seventh activates the enforcement when `WITH_BREAKING_CHANGES` is enabled, documenting the change in `Documentation/BreakingChanges.adoc`.

Key improvements in this version include clearer commit messages, a dedicated patch for test adjustments in `t5324-split-commit-graph.sh`, and the restoration of lowercasing in `parse_oid_prefix` to preserve existing behavior during the transition. The series still targets Git 3.0 and remains gated behind the breaking changes flag, so it won’t affect current users until then. The changes are well-scoped, touching core hex-parsing utilities and their consumers (e.g., `object-name.c`, `pkt-line.c`, `ref-filter.c`).

The motivation—consistency and security—remains compelling, and the implementation looks solid after addressing feedback. However, the series is still an RFC, so the project hasn’t committed to merging it. Junio C Hamano’s earlier ambivalence ("my more principled side feels dirty") and the unresolved discussion about normalizing inputs internally (rather than rejecting them) suggest this may still face pushback. That said, the technical work is thorough, and the changes are minimal enough to be low-risk if accepted.

For a busy reader: this is a well-crafted, narrowly targeted breaking change that addresses a real problem. The patches are clean, the tests are adjusted appropriately, and the feedback from v1 has been incorporated. Whether it lands depends on whether the project is willing to accept a breaking change for this specific issue, but the series itself is ready for deeper review.
