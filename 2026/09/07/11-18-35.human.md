This is the first patch in an 11-part series that cleans up Git's inconsistent naming around reference storage formats. The patch renames the `--ref-format=` option in `git init` to `--ref-storage-format=` to align with the existing "ref storage format" terminology used in documentation and repository extensions. The old option remains as a hidden alias for backward compatibility.

The motivation is clear: the current naming is a mess, with `--ref-format=` clashing with the "object format" (hash algorithm) and the `GIT_REFERENCE_BACKEND` environment variable, while the repository extension is called `refStorage`. The new name (`--ref-storage-format=`) is consistent with the documentation and prepares the ground for an upcoming object storage extension, which would otherwise create even more naming collisions.

The patch touches documentation, the `init-db` builtin, and a dozen test scripts, updating all references to the old option. The changes are mechanical and well-tested; the commit message explains the rationale thoroughly. This is a refactoring patch that paves the way for future work rather than introducing new behavior. It looks uncontroversial and well-crafted.
