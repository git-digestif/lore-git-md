# Thread deltas

## 2026/11/15

- [2026/11/15/11-03-05 by Ewout ter Hoeven <ewoutterhoeven@live.nl>] Ewout ter Hoeven proposed stacked pull/merge requests as a concrete use case for a preserved change-id header, explaining that tools such as GitHub's gh-stack and GitLab's glab stack currently guess whether a rewritten commit is the same change by relying on branch names, recorded bases, and patch IDs, with documented failures including stranded stacks after a plain branch rename and mass replay of old commits when a lower layer is rewritten; he noted that GitLab Gitaly engineers have discussed moving toward change IDs for the same reason.
- [2026/11/15/16-24-24 by brian m. carlson <sandals@crustytoothpaste.net>] brian m. carlson objected that change-id headers cannot be trusted as a source of unmodified data because users can modify them, arguing that only a server performing the rebase can have confidence the content is unchanged, and warned that a malicious user could reuse change-ids to submit a different version under an existing review.
