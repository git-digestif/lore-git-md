This thread is about a proposed feature to preserve `change-id` headers during Git operations like rebase, cherry-pick, and amend—headers used by tools like Gerrit, GitHub’s `gh-stack`, and GitLab’s `glab stack` to track commits across rewrites. The discussion has evolved into a three-way debate between technical solutions, privacy/security concerns, and real-world workflow pain points.

Nico Williams initially proposed a policy/hook framework to preserve `change-id`s, arguing it would solve workflow issues for stacked PRs and multi-commit reviews. However, **brian m. carlson** has raised persistent security objections, most recently highlighting a critical flaw: `change-id`s can be manually edited, making them unreliable for automated review systems. His latest reply reframes the problem as a **security boundary issue**, insisting that only server-side rebases (where the server controls the `change-id`) can guarantee integrity. This directly challenges the assumption that client-side preservation (via hooks) is viable for security-sensitive workflows.

Meanwhile, **Ewout ter Hoeven** has countered utility objections with concrete examples of workflow failures—like 61-commit replays in `gh-stack` after branch renames—showing how the lack of `change-id` preservation forces fragile heuristics. Junio C Hamano remains skeptical of `change-id`-specific solutions, preferring trailer-based metadata, while **Phillip Wood** has yet to weigh in on how the proposal handles operational edge cases (e.g., cherry-picks, splits, squashes).

The thread now hinges on whether **brian’s security requirement** (server-side control) can coexist with **Ewout’s workflow needs** (client-side preservation). If not, the feature may be limited to opt-in use cases or abandoned entirely. The next steps likely involve evaluating whether Nico’s framework can incorporate safeguards (e.g., opt-in defaults, format validation) to address the security risks while preserving utility. For now, the proposal remains stalled between these competing priorities.
