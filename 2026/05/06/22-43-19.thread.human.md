This thread is about an RFC patch series from Johannes Schindelin (Dscho) that adds merge-commit support to `git history`, building on Elijah Newren’s merge-composition design. The series is still in the RFC stage, not yet queued for merging. The core idea is to handle merge commits by performing a three-way merge: given a merge commit O with parents B and D, the algorithm computes a remerge of the original parents (R), then a remerge of the rewritten parents (N), and finally layers O’s manual resolutions onto N using R as the base. Phillip Wood proposed an optimization for cases where only one parent is rebased, and this is now being integrated alongside the original approach.

The series includes patches for the merge logic in `replay.c`, conflict marker labeling, refactoring of `create_commit()` to handle multiple parents, a "reword" optimization (skipping remerge when only the commit message changes), explicit rejection of octopus merges, a new `test-tool historian` helper with a DSL for testing, and extensive test coverage in `t3454-history-merges.sh`. The DSL syntax questions have been resolved, but a regression in boundary commit handling—identified by Philippe Blain—initially raised concerns. Blain discovered that the pre-seeding logic (which maps negative revisions like `M^!` to the `--onto` target) is intentional and documented in Newren’s upstream branch, not a bug.
