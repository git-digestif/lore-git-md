This thread documents the `--follow` and `--no-follow` options for `git log`, a feature that has existed since 2012 but was only recently given proper documentation. Tamir Duberstein has been driving this effort, now in its fifth iteration (v5), refining the explanation of the feature's limitations after the v4 series was already merged into Junio Hamano's `next` branch.

The key update in v5 is a clearer distinction between *errors* (explicit `--follow` with zero or multiple paths) and *no-ops* (the same cases when `log.follow` is set). It also explicitly labels directory arguments and wildcard patterns as producing *unspecified* results, steering users toward `--no-follow` for predictable behavior. The documentation now lists `--follow` before `--no-follow` in the man page, aligning with Git's usual style. Junio Hamano's feedback on v4—requesting more precision about unsupported cases—has been addressed, though the documentation still avoids over-specifying undefined behavior.

The unusual aspect here is that v5 arrives *after* v4 was merged to `next`, indicating that both author and maintainer agreed the documentation could be improved further before graduating to `master`. The changes are minor but meaningful, ensuring users understand the constraints of `--follow` (single-file, linear history only) and the precedence rules between CLI options and configuration. The thread is effectively closed, with no open questions or objections—just a final polish before the feature's documentation is considered complete.
