Erik Cervin-Edin has posted v4 of his series teaching `git commit --fixup` (including the `amend:` and `reword:` variants) to accept `-m`, `-F`, `-c`, and `-C` for supplying the commit message non-interactively. The series is now split into three patches: the first restructures `prepare_to_commit()` in `builtin/commit.c` so the `fixup!`/`amend!` subject line is written up front, mirroring how `--squash` has always behaved, which removes the old guards that blocked `-m` from combining with fixups; the second enables `-m`/`-F` for all variants; the third enables `-c`/`-C`, reusing `prepare_amend_commit()` to strip `amend!` lines from the source commit. The change is confined to `builtin/commit.c`, the docs, and tests, with no on-disk format impact, and Erik notes he has been using the feature himself for months.

Review has largely converged. Phillip Wood's feedback across v1 through v3 -- on code reuse, terminology, and most recently test hygiene around editor invocation for `-c` and `-C` -- has been addressed in v4, with tests now using `GIT_EDITOR=false` and `GIT_EDITOR="echo edited >>"` as appropriate. Junio Hamano had explicitly asked for final review of the second patch after it sat unreviewed in v2, and has raised no new concerns since.

The series is production-ready and awaiting final review; there are no open design questions or technical objections, and backward compatibility is preserved since the editor still launches when no message option is given.
