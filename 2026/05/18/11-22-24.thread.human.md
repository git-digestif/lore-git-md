Erik Cervin-Edin's v4 patch series enhances `git commit --fixup` to accept non-interactive message options (`-m`, `-F`, `-c`, `-C`) across all fixup variants—plain, `--fixup=amend:`, and `--fixup=reword:`—restructured into three patches that refactor `prepare_to_commit()` in `builtin/commit.c` to handle fixup subjects up front, mirroring the existing `--squash` behavior. The series is production-ready and has addressed all feedback from earlier rounds, including Phillip Wood's test hygiene concerns about editor invocation in the test suite.

Phillip Wood has now given a substantive review of v4, approving the series overall and specifically praising the patch 1/3 restructuring that makes the subsequent changes cleaner. Junio Hamano had previously solicited final review for the second patch, and no technical objections remain from either reviewer. The only open question concerns the semantics of `-c` combined with plain `--fixup`: since plain `--fixup` never opens an editor, using `-c` currently behaves identically to `-C` (copying the message verbatim without editing). Phillip suggests it would be preferable for `-c` to actually launch an editor in this case, but acknowledges he has not investigated the implementation difficulty and is willing to accept the series as-is with this behavior marked as `#leftoverbits` if the fix proves tricky.
