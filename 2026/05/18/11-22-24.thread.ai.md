Git thread summary:

This thread covers Erik Cervin-Edin's patch series enhancing `git commit --fixup` to support non-interactive message specification via `-m`, `-F`, `-c`, and `-C` options for all `--fixup` variants (`--fixup`, `--fixup=amend:`, `--fixup=reword:`). The series is at v4, restructured into three patches, with all prior feedback addressed including Phillip Wood's test hygiene concerns.

Current status:
- v4 series (3/3) fully posted, completing the feature matrix by enabling all four message specification methods for all `--fixup` variants.
- v4 restructures the series into three patches: patch 1/3 refactors `prepare_to_commit()` in `builtin/commit.c` to write the `--fixup` subject line up front in a block before the message-source chain -- mirroring how `--squash` already behaves -- which eliminates the need for `!fixup_message` guards on the `-m` and `-F` arms; patch 2/3 enables `-m`/`-F` for all variants by removing the error that previously forbade combining `-m` with `--fixup=amend:` inside `prepare_to_commit()` and dropping `-F` from the `die_for_incompatible_opt` check that guarded `--fixup`, so that when `--fixup=amend:` or `--fixup=reword:` is used with `-m` or `-F`, the supplied message replaces the log message that would otherwise be copied from the target commit; patch 3/3 enables `-c`/`-C` for all fixup variants by modifying the `fixup_message` block in `prepare_to_commit()` to check for `use_message` (set by `-c`/`-C`) before falling back to `fixup_commit` for `--fixup=amend:`, and when `use_message` is present, looking up that commit and passing it to `prepare_amend_commit()` which copies the commit's message body while stripping any "amend!" lines, ensuring `git commit --fixup=amend:X -C X` produces the same message as opening an editor on `--fixup=amend:X`, and removing the `die_for_incompatible_opt3()` call in `parse_and_validate_options()` that previously rejected the combination of `--fixup` with `-C` or `-c`, leaving only the mutual exclusion between `-C`/`-c` and `-m`/`-F`.
- All substantive feedback from v1-v4 addressed: author identity consistency, terminology, code reuse, test robustness, redundant option-checking logic, the now-obsolete `die_for_incompatible_opt3()` function, and Phillip Wood's final test hygiene feedback from v3 (editor suppression for `-C` and editor execution for `-c`), which is now resolved in v4 with tests using `GIT_EDITOR=false` for the `-C` case and `GIT_EDITOR="echo edited >>"` for the `-c` case.
- Junio Hamano explicitly solicited final review for the second patch after it sat unreviewed in v2; no new comments from Junio in v3, v4, or since.
- Implementation remains production-ready with no remaining technical objections or design questions. The series awaits final review.

Key technical details:
- Unified message handling through `prepare_to_commit()` for all variants and message options, with special handling for amend-style messages (strips "amend!" lines) via `prepare_amend_commit()`.
- v4 patch 1/3 moves the `--fixup` subject line writing to occur up front in `prepare_to_commit()` before the if/else-if arms handling `-m`, `-F`, `-c`/`-C`, and the editor, matching the existing `--squash` behavior. The error for combining `-m` with `--fixup=amend:` is moved into this new subject block so it is still caught. The local variable previously named `commit` is renamed to `c` to match the style of the adjacent `--squash` block. This is purely structural with no user-visible behavior change yet; it removes the `!fixup_message` guards that previously prevented the `-m` arm from running when a fixup was requested. The commit message references original `--fixup` introduction (d71b8ba7c9), `--squash` introduction (89ac1223c0), and later `-m` support (30884c9afc).
- v4 patch 2/3 removes the fatal error for `-m` combined with `--fixup=amend:` and removes `-F` from `die_for_incompatible_opt`, allowing both options to supply replacement messages for amend/reword fixups instead of triggering errors.
- v4 patch 3/3 enables `-c`/`-C` by checking `use_message` in the `fixup_message` block and routing through `prepare_amend_commit()` when a source commit is provided, stripping "amend!" lines from the copied body; it also removes the `die_for_incompatible_opt3()` rejection of `--fixup` with `-C`/`-c`.
- Comprehensive test coverage in `t/t7500-commit-template-squash-signoff.sh` and `t/t7501-commit.sh`, including cases for `-C` with plain `--fixup`, `-c` with `--fixup=amend:`, `--fixup=amend:HEAD -C HEAD` matching the no-option editor result, `-C` on an "amend!" source commit correctly stripping the "amend!" line, nested squash/amend scenarios, `--fixup=reword:` and `--fixup=amend:` succeeding with `-m`, plain `--fixup` and `--fixup=reword:` succeeding with `-F`, and empty `-m ""` with `--fixup=amend:` still correctly failing. v4 tests address editor hygiene using `GIT_EDITOR=false` and `GIT_EDITOR="echo edited >>"`.
- Documentation updates (`git-commit.adoc`) reflect expanded capabilities, describing that `-m`, `-F`, `-c`, or `-C` may supply or supplement the replacement message for amend/reword fixups, bypassing the editor.
- Files touched: `builtin/commit.c`, `Documentation/git-commit.adoc`, and test suite only; no changes to core data structures or on-disk formats.
- Backward compatibility preserved (editor launches when no message options provided).
