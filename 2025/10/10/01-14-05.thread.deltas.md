## 2026/08/24

- [2026/08/24/01-32-51 by Junio C Hamano <gitster@pobox.com>] Junio C Hamano explained that reading per-user configuration from both ~/.gitconfig and the XDG layout was a deliberate design choice to help users migrate away from ~/.gitconfig while not disrupting those who choose not to migrate.
- [2026/08/24/01-32-51 by Junio C Hamano <gitster@pobox.com>] He stated that "git config --global --edit" should follow the same choice as the existing write-out code path for "git config --global set", and that Git should not open two files in users' editors.
- [2026/08/24/01-32-51 by Junio C Hamano <gitster@pobox.com>] He acknowledged that the "git config --global" read path was not designed as carefully as the write-out code path or the general "git config" sequence, and that any discrepancy between what "git config" reads from per-user files and what "git config --global" reads is very likely a bug caused by a slip of the mind rather than a deliberate design choice.

## 2026/08/26

- [2026/08/26/17-58-57 by Junio C Hamano <gitster@pobox.com>] Junio C Hamano questioned whether forcing forward slashes in `xdg_config_home_for()` on Windows is a required part of the XDG/HOME global fix, saying that if not it should be left out of the topic; he also asked where the backslashes in the returned path come from, noting that if they come from `XDG_CONFIG_HOME`/`HOME` environment variables that is the end user's preference and Git has no business forcing a slash form, and observed the patch's log message does not explain why the change must be part of this series.
- [2026/08/26/18-20-22 by Junio C Hamano <gitster@pobox.com>] Junio C Hamano corrected the claim that command output is "irrelevant" when no global config file exists — the output is how the user learns what caused the failure (e.g. "fatal: unable to read config file <path>"); the author only meant she cares about the exit code, not the exact message. He also suggested renaming `attempt_git_config_from_file_with_options()` to something shorter like `try_config()` to keep lines under ~70 columns, and argued `success_count` may be unnecessary, proposing the helper keep returning the error code so the caller accumulates it as before instead of returning void.
- [2026/08/26/18-38-03 by Junio C Hamano <gitster@pobox.com>] Junio C Hamano agreed it is sensible to make `config_options` the primary way to disable parts of the config sequence, but said to go further: either teach `git_config_system()` to take `config_options` and honor `.ignore_system`, or remove it and have callers check the struct, avoiding the ugly conditional. He noted the `if (!opts->ignore_global)` check is misleading because it is always taken (no caller skips per-user config), objected to 100-column-wide lines, and suggested adding a dedicated "else if" clause for the global case in `config_with_options()` instead of piggybacking on the existing sequence call, providing a fix-up diff that routes `CONFIG_SCOPE_GLOBAL` file sources to `do_git_config_sequence(..., 1)`.
