This thread is about Delilah Ashley Wu’s effort to fix a long-standing inconsistency in Git’s global configuration handling, where `git config list --global` only read from `$HOME/.gitconfig` despite Git actually reading both that file and `$XDG_CONFIG_HOME/git/config`. The series is now at v2, with three patches addressing feedback and design clarifications from the maintainer, Junio C Hamano.

The core of the fix involves modifying `config_sequence()` in `config.c` to properly handle the global scope by reading both config files, using new flags in `struct config_options` to restrict reads to the global scope. The series also introduces error-handling improvements, such as tracking successful config file reads and enforcing stricter error conditions for `--global` operations. While the technical implementation has received positive feedback—including a Reviewed-by from Johannes Schindelin—some aspects remain under discussion. The most contentious is the first patch, which normalizes Windows paths for XDG config files. Junio has questioned its necessity, and Delilah has now proposed dropping it entirely in favor of adjusting the tests to avoid the issue. The second patch’s helper function naming and the third patch’s structural refinements are also still being debated.

The series is functionally complete and aligns with Git’s design intent, as confirmed by Junio. The write path (`--global --edit` or `--global set`) remains unchanged, as it correctly writes to only one file (`$HOME/.gitconfig`). The remaining open questions are whether to include the Windows path normalization patch, how to name a helper function, and how to implement Junio’s suggested structural improvements for the final patch. The thread is nearing resolution, but these final points will determine whether a v3 is needed before the series can be merged.
