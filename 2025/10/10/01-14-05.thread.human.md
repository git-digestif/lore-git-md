This thread is about Delilah Ashley Wu’s two-patch v3 series that fixes a long-standing inconsistency in Git’s global config file handling. The issue was that `git config list --global` only showed `$HOME/.gitconfig` while Git actually reads both that file and `$XDG_CONFIG_HOME/git/config` for unscoped operations. The series is now complete and ready for integration.

The core fix modifies `config.c` to read both config files when `--global` is specified, using new ignore flags (`ignore_system`, `ignore_repo`, `ignore_worktree`, `ignore_cmdline`) to restrict reads to the global scope. A `global_had_success` flag ensures `git config list --global` fails if no global config file is readable, preserving existing error handling. The implementation consolidates scope-filtering logic into `config_options` and reuses existing infrastructure, avoiding duplication. Windows path normalization concerns were resolved at the test level, with no platform-agnostic code changes needed.

Key participants include Delilah (the author), Johannes Schindelin (who consistently reviewed the patches), and Junio C Hamano (the maintainer). Junio confirmed the series aligns with Git’s original design intent and addressed all structural concerns in v3. The series has progressed from a three-patch v1 (which included a Windows path normalization patch later dropped) to the current two-patch v3, which adds comprehensive test coverage and simplifies error handling. All feedback has been addressed, and the series is now technically complete. No on-disk format changes or new CLI options were introduced.
