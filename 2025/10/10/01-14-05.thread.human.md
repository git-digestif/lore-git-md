This thread is about Delilah Ashley Wu’s two-patch v3 series fixing a long-standing inconsistency in Git’s global config file handling. The issue is that `git config list --global` only reads from `$HOME/.gitconfig`, while unscoped operations read from both `$HOME/.gitconfig` and `$XDG_CONFIG_HOME/git/config`. The series ensures `--global` operations fail if no global config file is readable, aligning with Git’s original design intent.

The first patch (this email) adds test coverage for the edge case where no global config file exists, verifying that `git config list` succeeds while `git config list --global` fails. This is a preparatory change for the core fix in the second patch, which modifies `config_sequence()` to enforce the correct behavior. The tests focus on exit codes and use `test_must_fail` to confirm the expected failure mode for `--global` operations.

The series has evolved through three iterations, with v3 addressing all feedback, including structural refinements from Junio C Hamano and Windows path normalization concerns (resolved at the test level). Johannes Schindelin has consistently reviewed the patches, and Junio has confirmed the design intent and addressed his earlier concerns. The series is now technically complete and ready for integration, touching `config.c`, `builtin/config.c`, `config.h`, and `t1300-config.sh` without introducing on-disk format changes or new CLI options. The implementation reuses existing config-reading infrastructure while preserving backward compatibility.
