This thread is about Delilah Ashley Wu’s three-patch series fixing a long-standing inconsistency in Git’s global config handling: `git config list --global` only showed `$HOME/.gitconfig` while Git actually reads both that file and `$XDG_CONFIG_HOME/git/config`. The series is now on its second version, with all feedback addressed except for a few final details.

The core fix modifies `config_sequence()` in `config.c` to properly handle the global scope by reading both config files, using new ignore flags and a success counter to track reads and enforce error handling. The implementation reuses existing infrastructure and maintains backward compatibility. Junio C Hamano, the maintainer, confirmed the design intent and clarified that the write path (e.g., `--global --edit`) correctly writes to only one file, so no changes were needed there.

The latest update drops the Windows path normalization patch entirely, opting instead to adjust tests to export `XDG_CONFIG_HOME` with forward slashes. This keeps the series focused on the core fix without platform-specific code changes. Junio’s remaining concerns are structural refinements to the final patch (e.g., consolidating scope filtering logic) and the naming of a helper function in patch 2. Johannes Schindelin has reviewed the technical aspects of all patches, and the series is otherwise ready for integration. The thread is now just tidying up these last details before the fix can land.
