This thread is about Delilah Ashley Wu’s two-patch v3 series fixing a long-standing inconsistency in Git’s global config file handling. The issue was that `git config list --global` only read from `$HOME/.gitconfig`, even though Git’s unscoped operations read from both `$HOME/.gitconfig` and `$XDG_CONFIG_HOME/git/config`. The series is now complete, with all feedback addressed, including structural refinements, error handling simplifications, and test adjustments.

The core fix modifies `config_sequence()` in `config.c` to read both global config files when the global scope is requested, using ignore flags to restrict config reading. The implementation avoids duplicating logic by reusing `do_git_config_sequence()` and simplifies error handling with a boolean flag (`global_had_success`) to ensure `git config list --global` fails if no global config file is readable. Windows path normalization concerns were resolved at the test level, with no changes needed to platform-agnostic code. Junio C Hamano confirmed the series aligns with Git’s original design intent, and the write path behavior (which writes to only one file) remains correct.

The series has progressed through three iterations: v1 introduced a Windows path normalization patch (later dropped), v2 addressed most feedback but retained a `success_count` mechanism, and v3 simplified error handling, implemented all structural refinements, and added comprehensive test coverage. Junio’s recent email acknowledges the first patch (which adds tests for missing global config scenarios) with a simple "OK." and raises a minor test portability nit about hard-coded XDG paths.
