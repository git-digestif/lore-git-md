This thread is about Delilah Ashley Wu’s two-patch v3 series that fixes a long-standing inconsistency in Git’s global config handling: while Git reads both `$HOME/.gitconfig` and `$XDG_CONFIG_HOME/git/config` for unscoped operations, `git config list --global` only showed the former. The series is now effectively complete, with all feedback addressed and only a minor defensive programming tweak requested by Junio C Hamano before integration.

The core fix modifies `config_sequence()` in `config.c` to use `do_git_config_sequence()` with ignore flags, ensuring `--global` operations read both config files. The implementation avoids duplicating config-reading logic, consolidates scope-filtering into `struct config_options`, and simplifies error handling with a boolean flag (`global_had_success`) to ensure `git config list --global` fails if no global config file is readable. Windows path normalization concerns were resolved at the test level, and all structural refinements suggested by Junio—including improved line-wrapping and conditional logic—have been implemented. The first patch, which adds tests for missing global config scenarios, has already been accepted with a minor portability question about XDG paths in the test setup.

Junio’s latest feedback accepts the core approach but requests a small robustness improvement: adding a `BUG()` check in `git_config_system()` to guard against NULL `opts` pointers. With this tweak, the series will be ready for integration. Johannes Schindelin has consistently reviewed the patches favorably, and Delilah has addressed all prior feedback, including replacing an earlier `success_count` mechanism with the simpler boolean flag. The series maintains backward compatibility, preserves existing error handling, and reuses Git’s config-reading infrastructure without introducing new CLI options or on-disk format changes.
