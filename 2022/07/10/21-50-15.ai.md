This is a proposal to adopt an automatic code formatter for the Git project.

Brian m. carlson reopens the long-standing discussion about introducing an automatic code formatter to Git. The motivation is twofold: reducing the barrier for newcomers who often face repeated code-style nitpicks, and freeing up contributor time from manual formatting to focus on substantive work. Brian notes that even experienced contributors (including himself) spend significant effort on formatting during patch revisions, and that code-style comments frequently appear in review discussions.

The proposal suggests using `clang-format`, which is already available on all major platforms and is highly configurable. Git already has a `.clang-format` file, but it does not currently produce output fully conformant with Git's coding style. The key idea is to redefine Git's style in terms of the formatter's capabilities, accepting minor suboptimal outcomes in exchange for automation. Brian emphasizes that the specific style is less important than having a tool that eliminates manual formatting work.

This email does not include a concrete implementation plan or a patch, but it lays out the rationale and invites discussion toward a "productive resolution." The proposal is framed as a way to reduce friction in the contribution process and improve efficiency, particularly for large or complex patch series like the ongoing SHA-1/SHA-256 interop work. The thread context indicates this is a revival of a previous discussion that did not reach consensus.
