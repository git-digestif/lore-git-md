This is a platform-compatibility counterproposal to the `clang-format` RFC.

Randall S. Becker, the maintainer of Git's NonStop port, responds to brian m. carlson's proposal to adopt `clang-format` as an automatic code formatter. Randall points out that `clang-format` is not available on all platforms—specifically, it is not available on NonStop, which he maintains. Instead of adopting a tool that would exclude some platforms, he suggests building formatting infrastructure directly into Git itself.

The counterproposal is to implement a pluggable, language-specific clean filter system that runs automatically on `git add` or `git commit`. This system would be designed to be portable (e.g., written in Perl, which is already a dependency for Git) and could invoke platform-specific formatters like `clang-format` where available. Randall argues that this approach would be more inclusive, supporting not just C but other languages (Java, PHP, Perl, COBOL, TAL) and benefiting a broader community beyond Git contributors. The idea is to standardize the *mechanism* for formatting within Git, rather than mandating a specific tool like `clang-format`.

This email does not include a patch or technical implementation, but it introduces a new architectural direction for the discussion: building formatting support into Git's core workflow, rather than relying on an external tool with limited platform support. The proposal is framed as a more general and inclusive solution, though it would require significant new infrastructure. No other participants have yet responded to this specific idea.
