This is a platform-compatibility counterproposal in the ongoing discussion about adopting an automatic code formatter for Git.

Randall S. Becker, the maintainer of the NonStop port of Git, responds to Brian m. carlson’s proposal to use `clang-format` by pointing out that it would exclude platforms like NonStop, which lack Rust and therefore `clang-format` support. Instead of adopting a formatter that isn’t universally available, Randall suggests building formatting infrastructure directly into Git itself. His proposal is to use Git’s clean filter mechanism—language-specific filters that automatically format code on `git add` or `git commit`—as a pluggable, cross-platform alternative.

The key idea is to make the formatter a built-in Git feature rather than an external dependency. Randall envisions a helper script (possibly written in Perl for portability) that could invoke `clang-format` where available but would also support other language-specific formatters (Java, PHP, COBOL, etc.). This approach would standardize formatting across all contributions while remaining inclusive of platforms that don’t support `clang-format`. He argues that such infrastructure would benefit not just Git contributors but the broader Git user base, and that the Contributor’s Guide could simply mandate adherence to a standard (like `clang-format`) without requiring the tool itself to be present on all platforms.

This counterproposal shifts the discussion from *which formatter to use* to *how to integrate formatting into Git’s workflow in a platform-agnostic way*. It addresses Brian’s goal of reducing contributor friction but avoids the exclusionary implications of mandating `clang-format`. The trade-off is increased complexity in implementation—requiring Git to manage formatter plugins and ensuring they’re easy to install—compared to relying on an existing tool. No patches or concrete plans accompany the suggestion yet, but it introduces a new technical direction for the thread.
