The Git mailing list is discussing whether to adopt `clang-format` as an automatic code formatter to reduce manual style nitpicks in reviews. The conversation began with brian m. carlson proposing the idea, emphasizing efficiency gains and reduced contributor friction, while Junio C Hamano expressed cautious openness—provided `clang-format` can reformat the existing codebase without excessive disruption.

Now, Randall S. Becker, maintainer of Git’s NonStop port, has raised a significant compatibility concern: `clang-format` is unavailable on NonStop, making it an exclusionary choice. Instead, he proposes building formatting infrastructure directly into Git—a pluggable, language-specific clean filter system that would run automatically on `git add` or `git commit`. This system would be portable (e.g., written in Perl, an existing Git dependency) and could invoke platform-specific formatters like `clang-format` where available. Randall argues this approach would be more inclusive, supporting multiple languages and benefiting a broader community beyond Git contributors. The idea shifts the discussion toward standardizing a *mechanism* for formatting within Git itself, rather than mandating a specific external tool.

No decisions have been made, and the thread remains in the early design phase. Key open questions include whether `clang-format` can be configured to closely match Git’s style, how to handle edge cases where it diverges, and now—with Randall’s counterproposal—whether Git should build its own formatting infrastructure to avoid platform lock-in. The discussion is still exploratory, with no patches or implementation plans yet.
