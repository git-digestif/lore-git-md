This is a reply in the ongoing design discussion about adopting an automatic code formatter for Git. Randall S. Becker pushes back against brian m. carlson’s suggestion that NonStop developers use a VM or separate system to run `clang-format`, reiterating that GCC (and by extension, `clang`) will *never* be supported on NonStop for the foreseeable future—at least five years, due to undisclosed legal or technical constraints.

Randall’s core point is broader than Git contributions: he argues that code formatting to a standard is a general need across many projects and languages, not just Git. Instead of building a Git-specific solution around `clang-format`, he advocates for a more inclusive, pluggable infrastructure within Git itself—something that could handle C, Java, Perl, COBOL, and other languages, and could delegate to platform-specific formatters where available. This, he suggests, would serve a wider community and avoid excluding platforms like NonStop. His position remains unchanged from his earlier counterproposal, but this reply sharpens the urgency: NonStop’s limitations are not temporary, and Git should not adopt a toolchain that permanently excludes a supported platform.
