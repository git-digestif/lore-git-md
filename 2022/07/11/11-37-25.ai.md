This is the first patch in Ævar Arnfjörð Bjarmason’s RFC series aimed at refining Git’s `.clang-format` configuration and providing tooling to measure its impact. It introduces **Makefile targets for testing `.clang-format` across the entire codebase**, rather than just the files changed in a patch. The patch adds `style-all`, `style-all-diff`, `style-all-diff-ok`, and `style-all-diff-apply` targets, which generate formatted versions of all tracked `.c` and `.h` files, compare them to the current state, and optionally apply the changes. This infrastructure is designed to help the community assess how closely `.clang-format` output matches Git’s current style and to iteratively refine the configuration.

The patch also **tweaks one `.clang-format` rule**: it changes `AlignEscapedNewlines` from `Left` to `DontAlign`, which stops the formatter from aligning backslashes in multi-line macro definitions. This change reduces the formatting delta between `.clang-format` output and Git’s current style by ~126 lines (from ~32k to ~32k insertions/deletions), a small but measurable improvement. The commit message frames this as aligning the formatter with Git’s prevailing style, where backslashes in macros are typically not aligned.

The patch is **purely additive**—it does not enforce formatting or change any existing behavior. Instead, it provides a way to test and refine `.clang-format` rules before deciding whether to adopt them. The `style-all-diff-ok` target, for example, fails if any file would be reformatted, which could later be used in CI to enforce formatting. The `style-all-diff-apply` target applies the changes, but only if the working tree is clean (excluding the Makefile and `.clang-format` itself to avoid circular dependencies).

This patch is a **tangible step toward the `clang-format` proposal** but does not address Randall S. Becker’s counterproposal for a pluggable, language-agnostic formatter. It is explicitly RFC and part of a broader discussion about whether Git should adopt an automatic formatter at all. The tooling introduced here will help the community evaluate whether further `.clang-format` rule tweaks can close the remaining ~13k-line formatting gap, or whether the deviations are fundamental enough to require a different approach.
