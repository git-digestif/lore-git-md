Thread identity
Subject: [PATCH v3] advice: add scope hint for disabling advice messages
Series version: v4 (three patches)
Originating author: Vsevolod Myalitsin
Thread type: patch series

Core problem or goal
Add a scope hint to Git’s advice settings so that when users are told how to disable an advice message (e.g., `git config advice.detachedHead false`), the command includes the correct config scope (`--global`, `--local`, or `--system`). The series has converged on a simplified design using a single boolean `is_global_hint` to indicate whether the scope should be `--global` (true) or `--local` (false), eliminating build failures and focusing on the immediate goal of accurate scope hints for `--global` settings like `defaultBranchName`.

Current status
v4 is posted as a three-patch series: (1) refactor `vadvise()` to accept the full `advice_setting` struct, (2) introduce the scope-hint mechanism with the boolean `is_global_hint`, and (3) assign `is_global_hint = true` to the `defaultBranchName` advice. Junio’s mechanical feedback from v3 (commit-message motivation, `vadvise()` documentation, indentation) is addressed. Junio’s review of v4 identified a build failure under `DEVELOPER=YesPlease` mode due to unhandled `CONFIG_SCOPE` enum values in `vadvise()`; SZEDER Gábor’s review revealed an additional syntax error (unmatched opening brace). These issues are resolved by the boolean `is_global_hint` simplification, which replaces the `scope_hint` enum and removes all scopes except `--global` and `--local`. Jeff King has twice endorsed this boolean simplification, arguing that *all* advice settings should default to `--global` because advice messages are about silencing chatter for a *user* rather than a specific repository, making `--worktree` or `--system` unlikely to be useful in practice. Junio has acknowledged the merit of Peff’s position but countered that some users work across multiple projects with different workflows and may want to squelch advice *per project*, suggesting that `--local` (or even `--worktree`) could still be useful in rare cases. In his latest reply, Junio clarifies that the original 2009 design of the `advice.*` config system never intended the "use `git config advice.foo false`" instruction to be a literal cut-and-paste command; users were expected to adapt the command to their own needs (e.g., adding `--global` or `--local` as appropriate). This stance implies that the absence of a scope hint was intentional, and that adding scope hints now is a deliberate enhancement rather than a bugfix. The series remains under review with no evidence of Junio picking it up for integration. The second patch in v4 explicitly aligns with Peff’s argument, proposing that `advice.*` settings were originally intended to be disabled globally and treating all other scopes as local by default. A tangential documentation patch clarifying `<file-option>` in `git-config.txt` (posted by both Junio and Peff) may be resolved in parallel.

Key technical details
- Files touched: `advice.c`, `Documentation/git-config.txt` (tangential)
- New field: `is_global_hint` (boolean) in the `advice_setting` struct, replacing the `scope_hint` enum
- Enum: removal of `CONFIG_SCOPE` reuse; `is_global_hint` directly indicates whether the scope should be `--global` (true) or `--local` (false)
- Translatable string: rewritten to avoid string interpolation; no longer uses `"git config %s advice.%s false"`
- Symbols: `advice_setting`, `is_global_hint`, `advice_config[]`, `vadvise()` interface (now takes `const struct advice_setting *`), `ADVICE_DEFAULT_BRANCH_NAME` with `is_global_hint` set to true
- Helper function: `config_scope_name()` (existing) is no longer needed for scope flag construction
- Refactoring: `vadvise()` now accepts the entire `advice_setting` struct; call sites in `advise()` and `advise_if_enabled()` updated accordingly
- Build-failure resolutions: (1) the `switch` statement in `vadvise()` is eliminated by the boolean simplification, removing the `DEVELOPER=YesPlease` compilation error; (2) the unmatched opening brace in patch 1 is resolved by the structural change
- Tangential documentation: Junio’s patch adds a paragraph to `Documentation/git-config.txt` clarifying that `<file-option>` refers to `--system`, `--global`, `--local`, `--worktree`, or `--file <filename>`; Jeff King proposed a more concise alternative that groups these options under the same term and notes `--blob` as a special case

Open questions and loose ends
1. Maintainer decision on design direction: Junio has acknowledged the merit of Jeff King’s argument for `--global`-only scope hints but also noted that `--local` (or `--worktree`) could be useful for users working across multiple projects with different workflows. Peff’s latest reply reinforces his position with historical context, arguing that the per-project use case is effectively nonexistent and that the boolean `is_global_hint` simplification aligns with the original intent of the `advice.*` config system. Junio’s latest reply clarifies that the original design never intended the scope-less hint to be a literal command, leaving the door open for either the boolean simplification (which would default `defaultBranchName` to `--global` and others to `--local`) or a more flexible mechanism that could later support additional scopes if a use case emerges. The thread remains unresolved on this point.
2. Documentation patch resolution: Junio and Peff have both posted patches clarifying `<file-option>` in `git-config.txt`; it is unclear which version (or a hybrid) will be adopted. This is tangential to the series but may be resolved in parallel.
3. Future expansion: the boolean simplification leaves the door open for future expansion (e.g., `--worktree` or `--system` support) if a use case emerges, but no such use case has been identified.
