Subject: [PATCH v3] advice: add scope hint for disabling advice messages
Series version: v5 (single patch, replacing v4)
Originating author: Vsevolod Myalitsyn (original series), Junio C Hamano (v5 implementation)
Thread type: patch series

Core problem or goal
Add a scope hint to Git’s advice settings so that when users are told how to disable an advice message (e.g., `git config advice.detachedHead false`), the command includes the correct config scope. The series has converged on a uniform `--global` hint for all `advice.*` settings, eliminating per-setting scope tracking entirely after Junio and Jeff King explicitly endorsed this simplification.

Current status
v5 is posted as a single patch by Junio, replacing Vsevolod’s three-patch v4 series. The patch implements the now-consensus design: always recommending `--global` in the hint for *all* `advice.*` settings. It touches `advice.c` and updates twelve test scripts to expect the new `--global` wording. Vsevolod has reviewed v5 and endorsed the uniform `--global` approach, while reiterating his suggestion to refactor the `vadvise()` interface in a follow-up patch. The central design debate is resolved, and the implementation is minimal and mechanical. Jeff King has reviewed v4 patch 2/3 (the core logic) and endorsed it, also supporting Vsevolod’s suggestion to split the `vadvise()` interface cleanup into a follow-up patch. No evidence of Junio picking it up for integration yet; the series remains under review.

Key technical details
- Files touched: `advice.c`, twelve test scripts (`t/t*`)
- New field: none; the `is_global_hint` boolean proposed in v4 is eliminated
- Enum: none; no per-setting scope tracking remains
- Translatable string: rewritten to consistently recommend `--global` (e.g., `git config --global advice.detachedHead false`)
- Symbols: `advice_setting`, `advice_config[]`, `vadvise()`, `turn_off_instructions`
- Refactoring: `vadvise()` now directly embeds the `--global` hint without conditional logic. The interface cleanup (passing a pointer to `advice_setting` instead of individual fields) is deferred to a follow-up patch as suggested by Vsevolod and endorsed by Peff.
- Test updates: twelve test scripts updated to expect the new `--global` wording in advice messages
- Build-failure resolutions: the uniform `--global` approach eliminates the `DEVELOPER=YesPlease` compilation error and the unmatched opening brace from v4
- Documentation: the tangential `<file-option>` clarification in `Documentation/git-config.txt` remains unresolved but is independent of this series

Open questions and loose ends
