Subject: [PATCH v3] advice: add scope hint for disabling advice messages
Series version: v4 (in preparation)
Originating author: Vsevolod Myalitsin
Thread type: patch series

Core problem or goal
Add a `scope_hint` field to Git’s advice settings so that when users are told how to disable an advice message (e.g., `git config --global advice.detachedHead false`), the command includes the correct config scope (`--global`, `--local`, `--worktree`, or `--system`). The patch touches only `advice.c` and does not change any user-visible behavior beyond making the advice messages more accurate.

Under active revision. v4 is being prepared; it will address Junio’s mechanical feedback (commit-message motivation, `vadvise()` interface documentation, indentation) and adopt the three-part split he clarified: each patch must have its own distinct subject line and commit message explaining its specific purpose (API change, scope mechanism, default-branch-name scope assignment). The cover letter will describe the overall motivation and structure, while individual patches focus on their narrower scope. Threading guidance: v4 cover letter replies to the v3 patch email, and each v4 patch replies to the v4 cover letter. Peff’s review has removed the technical objection to reusing the `CONFIG_SCOPE` enum, but the semantic question of when to recommend `--global` versus `--local` remains unresolved. No new evidence of Junio picking up the series; it is still under review.

Key technical details
- File touched: `advice.c`
- New field: `scope_hint` in the `advice_setting` struct
- Enum: reuse of `CONFIG_SCOPE` (local, global, worktree, system, unknown) is now technically viable; `CONFIG_SCOPE_UNKNOWN` (value `0`) is interpreted as "use the default location for writing config" (currently local scope)
- Translatable string: rewritten to avoid string interpolation; no longer uses `"git config %s advice.%s false"`
- Symbols: `advice_setting`, `scope_hint`, `CONFIG_SCOPE_*`, `advice_config[]`, `vadvise()` interface narrowing, `ADVICE_DEFAULT_BRANCH_NAME` with `ADVICE_SCOPE_GLOBAL` hint
- Helper function: `config_scope_name()` (existing) constructs the scope flag programmatically
