Subject: [PATCH v3] advice: add scope hint for disabling advice messages
Series version: v3
Originating author: Vsevolod Myalitsin
Thread type: patch series

Core problem or goal
Add a `scope_hint` field to Git’s advice settings so that when users are told how to disable an advice message (e.g., `git config --global advice.detachedHead false`), the command includes the correct config scope (`--global`, `--local`, `--worktree`, or `--system`). The patch touches only `advice.c` and does not change any user-visible behavior beyond making the advice messages more accurate.

Current status
Under review. v3 is the latest posted version; it addresses feedback from v2 but has not been picked up by Junio. Junio’s review of v3 suggests splitting the patch into a three-part series (API change, scope mechanism, default-branch-name scope assignment) and notes three mechanical issues (commit-message clarity, indentation, and interface narrowing), but the substance of the patch remains unchanged.

Key technical details
- File touched: `advice.c`
- New field: `scope_hint` in the `advice_setting` struct
- New enum: `ADVICE_SCOPE` (local, global, worktree, system, none)
- Translatable string: `"git config %s advice.%s false"` with a `%s` placeholder for the scope flag
- Symbols: `advice_setting`, `scope_hint`, `ADVICE_SCOPE_*`, `advice_config[]`, `vadvise()` interface narrowing

Open questions and loose ends
1. Translation clarity: the `%s` placeholder in the translatable string may confuse translators; Peff suggests either a clarifying comment or an alternative implementation that avoids string interpolation.
2. Enum reuse: Peff proposes reusing Git’s existing `CONFIG_SCOPE` enum instead of defining a new `ADVICE_SCOPE` enum, and provides a code snippet showing how to construct the command string programmatically using `config_scope_name()` and `ADVICE_LEVEL_NONE` instead of a hardcoded `0`.
3. Junio’s suggested split: the patch could be restructured into three parts (API change, scope mechanism, default-branch-name scope assignment) for clarity, though this is a presentation suggestion rather than a technical blocker.
