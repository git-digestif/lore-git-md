Subject: [PATCH v3] advice: add scope hint for disabling advice messages
Series version: v4 (three patches)
Originating author: Vsevolod Myalitsin
Thread type: patch series

Core problem or goal
Add a scope hint to Git’s advice settings so that when users are told how to disable an advice message (e.g., `git config advice.detachedHead false`), the command includes the correct config scope (`--global`, `--local`, or `--system`). The patch now proposes replacing the `scope_hint` enum with a single boolean `is_global_hint` to simplify the design, addressing build failures and removing complexity for scopes that have no clear use case in advice settings.

Current status
v4 is posted as a three-patch series: (1) refactor `vadvise()` to accept the full `advice_setting` struct, (2) introduce the scope-hint mechanism, and (3) assign `ADVICE_SCOPE_GLOBAL` to the `defaultBranchName` advice. Junio’s mechanical feedback from v3 (commit-message motivation, `vadvise()` documentation, indentation) is addressed. Junio’s review of v4 identified a build failure under `DEVELOPER=YesPlease` mode: the `switch` statement in `vadvise()` does not handle all values of the `CONFIG_SCOPE` enum (`CONFIG_SCOPE_WORKTREE`, `CONFIG_SCOPE_COMMAND`, and `CONFIG_SCOPE_SUBMODULE`), causing a compilation error. Jeff King (Peff) proposed treating unhandled scopes as equivalent to the default (local) scope. SZEDER Gábor’s review of v4 patch 1 revealed an additional build-breaking syntax error: an unmatched opening brace in the `if (setting && setting->level == ADVICE_LEVEL_NONE)` block. Vsevolod now proposes replacing the `scope_hint` enum with a boolean `is_global_hint`, which would eliminate both build failures and simplify the design. The series remains under review; no evidence of Junio picking it up for integration.

Key technical details
- Files touched: `advice.c`
- New field: `is_global_hint` (boolean) in the `advice_setting` struct, replacing the `scope_hint` enum
- Enum: removal of `CONFIG_SCOPE` reuse; `is_global_hint` directly indicates whether the scope should be `--global` (true) or `--local` (false)
- Translatable string: rewritten to avoid string interpolation; no longer uses `"git config %s advice.%s false"`
- Symbols: `advice_setting`, `is_global_hint`, `advice_config[]`, `vadvise()` interface (now takes `const struct advice_setting *`), `ADVICE_DEFAULT_BRANCH_NAME` with `is_global_hint` set to true
- Helper function: `config_scope_name()` (existing) is no longer needed for scope flag construction
- Refactoring: `vadvise()` now accepts the entire `advice_setting` struct; call sites in `advise()` and `advise_if_enabled()` updated accordingly
- Build-failure resolutions: (1) the `switch` statement in `vadvise()` is eliminated by the boolean simplification, removing the `DEVELOPER=YesPlease` compilation error; (2) the unmatched opening brace in patch 1 is resolved by the structural change

Open questions and loose ends
1. Scope hint criteria for other advice settings: resolved only for `defaultBranchName` (now `is_global_hint = true`); whether other settings should default to `--global` or `--local` is left to future work or maintainer discretion.
2. Maintainer acceptance of the boolean simplification: Junio and Peff have not yet weighed in on Vsevolod’s proposal to replace the `scope_hint` enum with `is_global_hint`.
3. Practical need for `--system` scope: Peff previously questioned its relevance for advice settings; Vsevolod’s proposal removes this debate by eliminating the scope entirely, leaving the door open for future expansion if a use case emerges.
