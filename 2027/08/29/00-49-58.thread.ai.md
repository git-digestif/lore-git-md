Core problem or goal
Add a `scope_hint` field to Git’s advice settings so that when users are told how to disable an advice message (e.g., `git config --global advice.detachedHead false`), the command includes the correct config scope (`--global`, `--local`, `--worktree`, or `--system`). The patch touches only `advice.c` and does not change any user-visible behavior beyond making the advice messages more accurate.

Current status
Under active revision. v4 is being prepared; it will address Junio’s mechanical feedback (commit-message motivation, `vadvise()` interface documentation, indentation) and adopt the three-part split he clarified: each patch must have its own distinct subject line and commit message explaining its specific purpose (API change, scope mechanism, default-branch-name scope assignment). The cover letter will describe the overall motivation and structure, while individual patches focus on their narrower scope. Threading guidance: v4 cover letter replies to the v3 patch email, and each v4 patch replies to the v4 cover letter. The two open technical questions from Peff’s review (enum reuse and translation clarity) remain unresolved but are not blocking the reroll. No new evidence of Junio picking up the series; it is still under review.

Key technical details
- File touched: `advice.c`
- New field: `scope_hint` in the `advice_setting` struct
- Enum under discussion: reuse `CONFIG_SCOPE` (local, global, worktree, system, unknown) or define a new `ADVICE_SCOPE` (local, global, worktree, system, none)
- Translatable string: rewritten to avoid string interpolation; no longer uses `"git config %s advice.%s false"`
- Symbols: `advice_setting`, `scope_hint`, `ADVICE_SCOPE_*` / `CONFIG_SCOPE_*`, `advice_config[]`, `vadvise()` interface narrowing, `ADVICE_DEFAULT_BRANCH_NAME` with `ADVICE_SCOPE_GLOBAL` hint
- Helper function: `config_scope_name()` (existing) can be used to construct the scope flag programmatically

Open questions and loose ends
1. Enum reuse: `CONFIG_SCOPE_UNKNOWN` is `0`, so uninitialized `scope_hint` fields would default to `UNKNOWN` instead of the current local-scope behavior. Vsevolod notes this may not be the right semantic fit; Peff has not yet weighed in on this edge case.

3. Junio’s mechanical feedback: all three items (commit-message motivation, `vadvise()` documentation, indentation) will be addressed in v4.
