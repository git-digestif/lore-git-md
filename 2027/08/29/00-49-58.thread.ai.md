Subject: [PATCH v3] advice: add scope hint for disabling advice messages
Series version: v4 (three patches)
Originating author: Vsevolod Myalitsyn
Thread type: patch series

Core problem or goal
Add a scope hint to Git’s advice settings so that when users are told how to disable an advice message (e.g., `git config advice.detachedHead false`), the command includes the correct config scope (`--global`, `--local`, or `--system`). The series has converged on a uniform `--global` hint for all `advice.*` settings, eliminating per-setting scope tracking entirely after Junio and Jeff King explicitly endorsed this simplification.

Current status
v4 is posted as a three-patch series: (1) refactor `vadvise()` to accept the full `advice_setting` struct, (2) introduce the scope-hint mechanism, and (3) assign the hint to the `defaultBranchName` advice. Junio’s mechanical feedback from v3 (commit-message motivation, `vadvise()` documentation, indentation) and SZEDER Gábor’s syntax error (unmatched opening brace) are resolved. The series remains under review with no evidence of Junio picking it up for integration. The central design debate is now resolved: the hint will always recommend `--global` for *all* `advice.*` settings, eliminating the `is_global_hint` field entirely. Junio and Jeff King have both explicitly endorsed this approach, arguing that advice messages are about silencing chatter for a *user* rather than a specific repository, making `--worktree` or `--system` unlikely to be useful in practice. Vsevolod has not yet responded to confirm whether he will revise the series accordingly.

Key technical details
- Files touched: `advice.c`, `Documentation/git-config.txt` (tangential)
- New field: none; the `is_global_hint` boolean proposed in v4 is eliminated in favor of a uniform `--global` hint
- Enum: `CONFIG_SCOPE` reuse is avoided; no per-setting scope tracking remains
- Translatable string: rewritten to avoid string interpolation; the hint now consistently recommends `--global` (e.g., `git config --global advice.detachedHead false`)
- Symbols: `advice_setting`, `advice_config[]`, `vadvise()` interface (now takes `const struct advice_setting *`), `ADVICE_DEFAULT_BRANCH_NAME`
- Helper function: `config_scope_name()` (existing) is no longer needed for scope flag construction
- Refactoring: `vadvise()` now accepts the entire `advice_setting` struct; call sites in `advise()` and `advise_if_enabled()` updated accordingly
- Build-failure resolutions: (1) the `switch` statement in `vadvise()` is eliminated by the uniform `--global` approach, removing the `DEVELOPER=YesPlease` compilation error; (2) the unmatched opening brace in patch 1 is resolved by the structural change
- Tangential documentation: Junio’s patch adds a paragraph to `Documentation/git-config.txt` clarifying that `<file-option>` refers to `--system`, `--global`, `--local`, `--worktree`, or `--file <filename>`; Jeff King proposed a more concise alternative that groups these options under the same term and notes `--blob` as a special case

Open questions and loose ends

2. Documentation patch resolution: Junio and Peff have both posted patches clarifying `<file-option>` in `git-config.txt`; it is unclear which version (or a hybrid) will be adopted. This is tangential to the series but may be resolved in parallel.
3. Future expansion: the uniform `--global` approach closes the door to per-setting scope hints (e.g., `--worktree` or `--system`) unless a compelling use case emerges later. No such use case has been identified.
