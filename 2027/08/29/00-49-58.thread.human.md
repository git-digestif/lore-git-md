This thread is about adding a scope hint to Git’s advice messages so users know whether to disable them with `--global`, `--local`, or another config scope. The series, now at v4, started with an enum-based design but has evolved toward a simpler boolean flag (`is_global_hint`) after build failures and feedback revealed that only `--global` and `--local` are needed in practice. Vsevolod Myalitsin, the author, proposed the boolean simplification to eliminate compilation errors and focus on the immediate goal—accurate scope hints for settings like `defaultBranchName`, which should be `--global`.

Junio C Hamano, the maintainer, has reviewed the series but hasn’t yet responded to the boolean proposal, though he identified the build failures in v4. Jeff King (Peff) has been the most substantive reviewer, first suggesting workarounds for the enum-related build issues and now fully endorsing the boolean design, arguing that advice settings are inherently user-level preferences and thus unlikely to need `--system` or `--worktree` scopes. SZEDER Gábor caught a syntax error in an earlier version, but the boolean approach would resolve that as well. The series is still under review, with no indication yet of whether Junio will pick it up for integration.

The key technical change is replacing the `scope_hint` enum with `is_global_hint` in the `advice_setting` struct, simplifying the logic in `vadvise()` and the translatable string construction. The only remaining open question is whether Junio will accept this simplification, though Peff’s endorsement makes it likely. A tangential documentation patch from Junio and Peff about `<file-option>` in `git-config.txt` may be resolved separately.
