This thread is about a patch series by Vsevolod Myalitsin that adds a `scope_hint` field to Git’s advice system, so users see the correct config scope (e.g., `--global`, `--local`) when told how to disable an advice message. The series is now preparing its fourth iteration (v4) after Junio Hamano and Jeff King (Peff) reviewed v3.

The main technical question—whether to reuse Git’s existing `CONFIG_SCOPE` enum or define a new `ADVICE_SCOPE`—has moved forward: Peff removed the technical objection to reusing `CONFIG_SCOPE`, noting that `UNKNOWN` (value `0`) can simply mean "use the default config location" (currently local scope). However, the discussion now shifts to semantics: when should an advice setting recommend `--global` versus `--local`? Peff admits uncertainty about the criteria, leaving this as the remaining open question. Junio’s earlier feedback on mechanical issues (commit messages, documentation, indentation) and patch-series structure (three-part split) will be addressed in v4, which is expected to follow the clarified threading guidance. The series remains under review, with no indication of merger yet.
