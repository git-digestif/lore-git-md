This thread is about a patch series by Vsevolod Myalitsin that improves Git’s advice messages by adding a scope hint—telling users the correct config scope (`--global`, `--local`, etc.) when disabling an advice message. The series is now at v4, a three-patch set that refactors the advice subsystem to include this hint, with the `defaultBranchName` advice as the initial use case.

The latest development is a proposal from Vsevolod to simplify the design by replacing the `scope_hint` enum with a single boolean `is_global_hint`. This change would resolve two build failures identified in v4: an unhandled `switch` case in `vadvise()` under `DEVELOPER=YesPlease` mode and a syntax error in patch 1. The simplification also addresses Jeff King’s question about whether `--system` scope is ever needed for advice settings—Vsevolod argues it isn’t, at least for now. Junio Hamano and SZEDER Gábor have previously pointed out these technical issues, while Peff has suggested treating unhandled scopes as the default (local) rather than failing.

The series remains under review, with no evidence of Junio picking it up for integration yet. The open question is whether the maintainers will accept the simplified design or prefer to retain the full `scope_hint` enum for future flexibility. The only substantive review so far has come from Peff, with Junio and SZEDER Gábor focusing on mechanical correctness.
