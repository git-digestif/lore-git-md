This thread is about a patch series by Vsevolod Myalitsin that improves Git’s advice messages by adding a `scope_hint` field, ensuring users are told the correct config scope (e.g., `--global`) when disabling advice. The series is now at version 4, split into three patches: a refactor of `vadvise()`, the scope-hint mechanism, and an example assignment for the `defaultBranchName` advice.

The core idea—making advice-disablement messages more accurate—has been accepted, and earlier feedback on commit messages and documentation has been addressed. However, Junio’s review of v4 uncovered a build failure under `DEVELOPER=YesPlease` mode: the `switch` statement in `vadvise()` doesn’t handle all `CONFIG_SCOPE` enum values, causing a compilation error. Jeff King (Peff) has now weighed in, suggesting a simpler fix than Junio’s proposed `BUG()`: treat unhandled scopes (like `WORKTREE` or `COMMAND`) as equivalent to the default (unadorned `git config`), since they’re either irrelevant or never passed in practice. Peff also questions whether `--system` scope is ever needed for advice settings but concedes the series is already well-motivated.

The only remaining loose end is the build failure, which will likely be resolved in v5. The series remains under review, with no evidence of Junio picking it up for integration yet. Key participants—Vsevolod (author), Junio (maintainer), and Peff (reviewer)—have all engaged substantively, and the discussion is now focused on minor implementation details rather than the design itself.
