This thread is about adding a scope hint to Git’s advice messages, so users see the correct config scope (like `--global` or `--local`) when told how to disable a message. The series, now at v4, is authored by Vsevolod Myalitsin and consists of three patches that refactor the advice system to include a boolean `is_global_hint` instead of a more complex enum-based scope mechanism. This change simplifies the design, fixes build failures, and focuses on the immediate goal of accurate scope hints for global settings like `defaultBranchName`.

The key debate centers on whether all advice settings should default to `--global` (as Jeff King argues, citing historical precedent and the user-centric nature of advice messages) or whether `--local` (or even `--worktree`) should remain an option for users working across multiple projects with different workflows (as Junio has suggested). Junio’s latest reply clarifies that the original `advice.*` system was never intended to provide literal cut-and-paste commands, implying that the lack of scope hints was intentional. While this doesn’t resolve the design question, it reinforces that the current effort is an enhancement rather than a bugfix. The series remains under review, with no indication of when Junio might pick it up for integration.

The technical changes are confined to `advice.c`, where the `vadvise()` function now accepts the full `advice_setting` struct, and the new `is_global_hint` boolean replaces the earlier `scope_hint` enum. The build failures identified in v3 (under `DEVELOPER=YesPlease` mode and a syntax error) are resolved by this simplification. A tangential documentation patch to clarify `<file-option>` in `git-config.txt` is still unresolved, with both Junio and Peff proposing versions. The unresolved design question—whether to adopt the boolean simplification or retain flexibility for future scopes—remains the primary loose end.
