This thread is about adding scope hints to Git’s advice messages—telling users whether to use `--global` or `--local` when disabling an advice with `git config`. Vsevolod Myalitsin’s v4 series, now down to three patches, has converged on a simplified design using a boolean `is_global_hint` to indicate the scope. The series refactors `vadvise()` to accept the full `advice_setting` struct, introduces the scope-hint mechanism, and sets `is_global_hint = true` for the `defaultBranchName` advice, which is the only setting currently needing a `--global` hint.

The design debate is the main open question. Jeff King (Peff) has twice argued that *all* advice settings should default to `--global` because they’re about silencing chatter for a *user*, not a specific repository, making `--worktree` or `--system` unnecessary. Junio initially resisted, noting that some users might want per-project settings, but has since clarified that the original 2009 design never intended the scope-less hint to be a literal command—users were expected to adapt it themselves. Vsevolod’s latest patch aligns with Peff’s position, treating all scopes except `--global` as `--local` by default. The series is still under review, with no sign of Junio picking it up yet. A tangential documentation patch about `<file-option>` in `git-config.txt` may be resolved separately.
