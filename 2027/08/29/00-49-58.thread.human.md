This thread is about a small but user-facing improvement to Git’s advice system. When Git tells users how to disable an advice message (e.g., `git config --global advice.detachedHead false`), it will now include the correct config scope (`--global`, `--local`, etc.). The series is in its fourth iteration, with the author, Vsevolod Myalitsin, preparing v4 to address mechanical feedback from Junio Hamano and Jeff King (Peff).

The core change is a new `scope_hint` field in Git’s advice settings, used only for the `defaultBranchName` advice message at this stage. The rationale is straightforward: since this message appears only during `git init`, a local config setting would have no effect in future repositories, so `--global` is the logical choice. Peff had raised a broader question about whether other advice settings should also default to `--global`, but the author has kept this patch focused on `defaultBranchName`, leaving other settings for future work or maintainer discretion. The technical approach—reusing Git’s existing `CONFIG_SCOPE` enum and treating `UNKNOWN` as "use the default location"—is now uncontested.

The series is nearly ready. The remaining work is mechanical: polishing commit messages, documenting the `vadvise()` interface, and fixing indentation. Junio’s guidance on splitting the series into three distinct patches (API change, scope mechanism, and scope assignment) has been adopted, and the threading structure for v4 is settled. No objections remain, and the patch is still under review, with no indication yet that Junio has queued it for integration.
