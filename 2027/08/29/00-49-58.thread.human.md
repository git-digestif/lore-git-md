This thread is about adding a scope hint to Git’s advice messages—telling users how to disable them via `git config`. After several iterations, the series has settled on a simple, uniform approach: always recommending `--global` for *all* `advice.*` settings, rather than tracking per-setting scope. Junio C Hamano posted v5 as a single patch implementing this consensus, replacing Vsevolod Myalitsyn’s earlier three-patch v4 series.

The design debate is now resolved. Jeff King (Peff) and Junio both endorsed the uniform `--global` approach, arguing that advice settings are inherently user-level preferences, not repository-specific ones. The patch touches `advice.c` and updates twelve test scripts to expect the new wording. Vsevolod has just replied, endorsing Junio’s v5 patch and suggesting a follow-up refactor to clean up the `vadvise()` interface by passing a pointer to the `advice_setting` struct instead of its individual fields. This is a minor interface hygiene suggestion, not a design change, and the thread remains converged on the core approach.

No objections or open questions remain about the scope hint itself. The only loose ends are tangential: a separate documentation patch clarifying `<file-option>` in `git-config.txt` (posted by both Junio and Peff) and the proposed `vadvise()` interface cleanup. The series is now waiting for Junio to pick it up for integration.
