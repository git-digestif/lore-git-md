This thread is about adding a scope hint to Git’s advice messages, so users are told the correct way to disable them (e.g., `git config --global advice.detachedHead false`). After several iterations, the series has converged on a simple design: always recommending `--global` for *all* `advice.*` settings, eliminating the need to track per-setting scope. Junio C Hamano posted v5 as a single patch implementing this consensus, which touches `advice.c` and updates twelve test scripts to expect the new wording.

The key participants—Vsevolod Myalitsyn (original author), Jeff King (Peff), and Junio—have all endorsed the uniform `--global` approach. Vsevolod initially proposed simplifying the design with a boolean flag, but Junio’s v5 patch went further by removing scope tracking entirely, aligning with Peff’s argument that advice settings are inherently user-level preferences. The only remaining loose end is a follow-up patch to refactor the `vadvise()` interface, which Vsevolod and Peff agreed should be split out. Junio has now marked the topic (`jc/advice-config-set-global`) for the `next` branch, meaning it will undergo integration testing before graduating to `master`. The documentation clarification about `<file-option>` in `git-config.txt` remains unresolved but is independent of this series.
