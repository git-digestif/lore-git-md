This thread is about adding a scope hint to Git’s advice messages—telling users whether to use `--global` or `--local` when disabling an advice with `git config`. The series, now at v4, was introduced by Vsevolod Myalitsin and proposes a boolean `is_global_hint` to mark which advice settings should recommend `--global` (like `defaultBranchName`). Junio initially suggested mechanical improvements and later identified build failures tied to the original enum-based design, which the boolean simplification resolved.

The discussion has since shifted toward an even simpler approach: always recommending `--global` in the hint, eliminating the need for per-setting scope flags. Jeff King (Peff) has twice endorsed this idea, arguing that advice settings are inherently user-level preferences and rarely need repository-specific overrides. Junio, while acknowledging that some users might prefer `--local` for project-specific silencing, now leans toward the uniform `--global` hint as a deliberate enhancement rather than a strict bugfix—clarifying that the original 2009 design never intended the hint to be a literal cut-and-paste command. Peff’s latest reply reinforces this position, framing `--global` as the default and leaving room to handle exceptions later if they arise.

The series remains under review, with no evidence of Junio picking it up for integration. The main open question is whether Vsevolod will revise the patches to adopt the uniform `--global` hint or if the thread will stall on this design choice. A tangential documentation patch about `<file-option>` in `git-config.txt` (posted by both Junio and Peff) may be resolved separately. No substantive objections remain, and the boolean simplification has already addressed the build failures and syntax errors raised in earlier reviews.
