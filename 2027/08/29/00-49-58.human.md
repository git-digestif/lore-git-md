This is the third patch in Vsevolod Myalitsin’s four-part series that adds a `scope_hint` field to Git’s advice system. The series aims to make advice-disable instructions accurate by telling users the correct config scope (`--global`, `--local`, `--worktree`, or `--system`) when they are told how to turn off an advice message.

This patch assigns the `ADVICE_SCOPE_GLOBAL` hint to the `defaultBranchName` advice. The change is mechanical: it updates the `advice_setting` array entry for `ADVICE_DEFAULT_BRANCH_NAME` to include the new `scope_hint` field. No other advice settings are touched here, and the patch does not change any user-visible behavior beyond making the suggested config command (`git config --global advice.defaultBranchName false`) match the intended scope.

The patch is small (32 insertions, 11 deletions) and confined to `advice.c`. It follows the three-part split Junio requested: the first patch introduced the API and scope mechanism, this one assigns the scope for a single advice, and the next patch will handle the remaining advice settings. The commit message is minimal but sufficient for its narrow purpose.

The series is still under review; v4 is being prepared to address Junio’s mechanical feedback (commit-message motivation, `vadvise()` documentation, indentation) and the unresolved enum-reuse question raised by Peff. This patch itself is uncontroversial and looks ready to merge once the series lands.
